# 로그인과 학습 기록 동기화 설정

게스트 학습은 환경 변수 없이 동작합니다. Google 로그인과 계정별 학습 기록 동기화를 사용하려면 별도의 Supabase 프로젝트와 Google OAuth 설정이 필요합니다.

## 환경 변수

`.env.example`을 `.env.local`로 복사한 뒤 Supabase에서 발급한 공개 설정을 입력합니다.

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

브라우저에 전달되는 값이므로 서버 전용 비밀 키나 DB 비밀번호는 사용하지 않습니다.

## 연결 순서

1. Supabase 프로젝트를 생성합니다.
2. `supabase/migrations/`의 SQL 파일을 순서대로 적용합니다. 기존 DB에 적용할 때는 이미 반영된 마이그레이션인지 먼저 확인합니다.
3. Google OAuth 웹 클라이언트를 만들고 Supabase가 제공하는 인증 callback 주소를 등록합니다.
4. Supabase의 Google Provider에 OAuth 클라이언트 정보를 설정합니다.
5. Supabase의 Site URL과 Redirect URLs에 개발·배포 주소를 등록합니다. 로컬 개발 주소는 `http://127.0.0.1:4179/`입니다.
6. 개발 서버를 재시작하고 로그인·로그아웃·기록 가져오기·서버 저장을 확인합니다.

배포 환경에도 같은 공개 변수 이름을 등록합니다. 도메인이 달라지면 Supabase의 허용 복귀 주소와 Google OAuth 설정을 함께 확인합니다.

## 저장 구조

학습 진도·북마크·출퇴근 설정을 계정별로 저장합니다. 계정별 기기 캐시와 서버 revision을 사용하고, 업로드 전 요청 ID를 보관해 같은 변경의 재시도를 구분합니다. 서로 다른 카드의 변경을 병합하며 같은 카드의 평가는 최신 평가 시각을 기준으로 처리합니다.

퀴즈 기록과 진행 중인 학습 세션에는 기기별 저장 범위가 있습니다. 로그인만으로 모든 상태가 여러 기기에 동일하게 복제되지는 않습니다. 푸시 알림은 구현되지 않았습니다.

## 확인할 항목

- 로그인 취소·실패와 앱 복귀.
- 게스트 학습 기록 가져오기와 계정 전환.
- 저장 후 새로고침, 오프라인 변경 후 재접속.
- 서로 다른 기기의 동시 변경과 오래된 업로드.
- 다른 사용자의 데이터 접근 차단과 로그아웃 후 상태.

`npm run test:db`로 DB 테스트를 실행할 수 있습니다. 실제 서비스 설정과 여러 기기의 브라우저 동작은 별도 검증이 필요합니다.
