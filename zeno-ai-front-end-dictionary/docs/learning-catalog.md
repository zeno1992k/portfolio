# 프론트엔드 카드 구성

현재 카탈로그는 670개입니다. 기존 500개 카드의 ID와 설명을 유지하고, 네 학습 목차와 대조한 주요 빈틈을 채우는 170개를 추가했습니다. 면접 질문·답변 예시·꼬리질문은 기존 220개와 신규 170개, 총 390개 카드에서 제공합니다. 용어 카드와 퀴즈의 질문은 존댓말로 작성합니다. [콘텐츠 점검](content-coverage.md)에 추가 범위를 정리했습니다. 카드 콘텐츠는 `src/data`의 TypeScript 파일에 있으며 Supabase에는 개인 학습 기록을 저장한다. 콘텐츠와 선택적인 면접 설명 필드의 추가라 DB 테이블이나 마이그레이션을 추가할 필요는 없다.

언어와 웹의 기본기를 쌓고 면접에서 원리를 설명하거나 실무의 선택 조건을 판단하는 범위다. 출제 빈도를 수집한 순위나 특정 회사의 실제 면접 문항 모음은 아니다. 모든 프론트엔드 API·도구·자격증 시험 범위를 망라하지 않으며, 카드 학습과 직접 코드를 작성하는 연습을 함께 사용한다.

## 답변을 설명하는 연습

면접 정보가 있는 카드의 답변 아래에 **면접 답변 연습**을 표시한다. 질문에 먼저 말로 답한 뒤 **답변 예시 보기**를 펼쳐 원리와 선택의 이유를 비교하고, **이어서 생각하기**의 꼬리질문으로 상황을 바꿔 본다. 학습 카드와 용어 상세에서 같은 콘텐츠를 사용한다. 새 카드로 넘어가면 답변 예시는 다시 접힌 상태다.

용어 사전의 **면접 답변 연습 390** 필터를 켜면 면접 정보가 있는 카드만 볼 수 있다. 분야·난도·검색과 함께 좁힐 수 있고 다시 누르면 전체 콘텐츠로 돌아간다. 사전의 이 필터는 오늘의 학습 범위나 기존 복습 기록을 변경하지 않는다.

추가 범위에는 실행 컨텍스트·프로토타입·복사와 동등성·비동기 처리, TypeScript 타입 관계, CSS의 크기 계산, 브라우저 이벤트·탭 간 상태·스트림, HTTP 연결·캐시·재시도, React 정체성·동시 렌더링·최신 Hook, Next.js 캐시, 접근성, 테스트·성능·보안·운영 및 알고리즘이 포함된다. 예제를 외우는 대신 어떤 조건에서 쓰고 무엇을 해결하지 못하는지도 답한다.

## 난도와 종류

- **기초**: 처음 익히는 언어·웹·앱 개발의 기본.
- **실무**: 실제 앱에서 쓰는 메서드·API·개발 방식.
- **심화**: 동작 원리와 복잡한 상황을 다루는 개념.

난도는 이 앱의 편집 기준이며 개인별 숙련도를 측정한 점수가 아니다. 각 카드에는 **개념 / 문법·메서드 / API / 도구** 중 하나도 표시한다. 함수와 API마다 카테고리를 추가하지 않고 기존 26개 세부 분야 안에 배치한다.

홈의 **범위 선택**에서 여러 분야와 난도를 고른다. 기본 **기초부터**는 선택한 분야의 새 카드를 기초 → 실무 → 심화 순으로 준비하고 같은 난도 안에서는 섞는다. 이미 학습한 카드 중 복습할 날짜가 지난 카드를 먼저 배치하고, 나머지를 새 카드로 채워 최대 5장을 만든다. 다음 난도는 앞 난도의 모든 카드를 적어도 한 번 평가한 뒤 만나며, 앞 난도를 완전히 숙달했다고 판정하지 않는다. 특정 난도를 고르면 그 난도 안의 복습·새 카드만 오늘의 범위에 들어간다.

학습 범위 설정을 바꾸면 진행 중인 카드 세션만 초기화한다. 북마크·진도·평가 이력은 유지한다. 용어 사전의 난도 필터는 검색·대분류·세부분류와 함께 동작하며 오늘의 범위를 바꾸지 않는다. 저장 목록과 복습 일정은 전체 카탈로그를 다룬다. 전체 복습 세션은 `kind: review`를 기기 세션에 저장해, 중간에 나갔다가 현재 학습 난도와 관계없이 이어서 복습할 수 있다.

## 콘텐츠 파일과 추가 기준

- `terms.ts`, `foundation-terms.ts`, `quality-terms.ts`: 기존 52개 카드. `legacy-term-metadata.ts`에서 난도와 종류를 연결한다.
- `expanded-web-terms.ts`: 웹 기본기 82개 추가.
- `expanded-app-terms.ts`: 브라우저·통신 38개, React·앱 개발 56개 추가.
- `expanded-practice-terms.ts`: UI 21개, 품질 21개, 협업 16개, CS 14개 추가.
- `interview-web-terms.ts`: 웹 기본기 60개 추가.
- `interview-app-terms.ts`: 브라우저·통신 35개, React·앱 개발 45개 추가.
- `interview-practice-terms.ts`: UI 10개, 품질 20개, 협업 15개, CS 15개 추가.
- `core-interview-notes.ts`: 기존 핵심 20개에 면접 연습을 연결한다.
- `coverage-language-terms.ts`: JavaScript·TypeScript·코딩테스트의 주요 빈틈 50개를 보강한다.
- `coverage-react-terms.ts`: React·Next.js·서버/클라이언트 상태·폼·구조 50개를 보강한다.
- `coverage-platform-terms.ts`: 웹 컴포넌트·브라우저·접근성·품질·운영·CS 50개를 보강한다.
- `coverage-browser-apis.ts`: 파일·클립보드·위치·미디어·Canvas·알림·암호·환경 조건 API 20개를 보강한다.
- `term-levels.ts`: 난도·종류의 ID와 표시 이름.

카드는 질문, 짧은 정의, 사용 상황, 필요할 때 짧은 예제, 헷갈리기 쉬운 점, 연결 개념, 태그, 공식 문서 링크를 갖는다. 새 카드의 예제는 20줄 이하로 제한한다. 문서의 긴 원문을 복사하지 않고 앱에 맞는 설명과 예제를 작성한다. MDN·W3C·표준 문서와 각 기술의 공식 문서를 확인하며, 실행 환경이나 버전 조건은 주의점에 표시한다.

`npm test`는 수량·고유 ID/이름·분류·필수 콘텐츠·링크 형식, 신규 면접 필드의 완결성, 새 JS/TS/JSX/TSX 예제 구문, 기존 500개 용어 기록과 300개 퀴즈의 정답·중단 세션 복원, 난도 필터와 학습 순서·설정 호환성을 확인한다. 구문 검사는 브라우저 API·React Hooks·외부 도구 예제의 실제 실행을 보장하지 않는다. 모든 예제의 실행 결과와 iPhone 하드웨어를 자동 검증하는 테스트는 포함하지 않는다.
