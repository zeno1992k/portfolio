## 스트림 개념

스트림(stream)은 데이터를 한 번에 통째로 다루지 않고, 조각(chunk) 단위로 흘려보내며 처리하는 인터페이스입니다. 파일, 네트워크 연결, 압축처럼 크기가 크거나 끝이 정해지지 않은 데이터를 일정한 메모리로 다루기 위해 있습니다. `node:stream` 모듈은 Stable(안정성 지수 2)입니다.

```js
import { readFile } from 'node:fs/promises'
import { createReadStream } from 'node:fs'

const all = await readFile('big.log') // 파일 전체가 메모리에 올라감

const stream = createReadStream('big.log')
stream.on('data', (chunk) => {}) // 조각마다 호출, 메모리는 일정
```

- 모든 스트림은 `EventEmitter`입니다(기초 21편).
- 문자열과 `Buffer`(기초 19편), `TypedArray`, `DataView`를 조각으로 다룹니다. 그 밖의 JavaScript 값을 다루는 객체 모드는 2편에서 설명합니다.
- 스트림을 쓰기만 하는 코드는 `node:stream`을 import할 필요가 없습니다. 새 종류의 스트림을 만들 때 씁니다.

종류는 네 가지이고, Node.js 내장 객체 상당수가 스트림입니다.

| 종류 | 방향 | 내장 예 |
|------|------|---------|
| Readable | 읽기 | `fs.createReadStream()`, 서버의 `req`, `process.stdin` |
| Writable | 쓰기 | `fs.createWriteStream()`, 서버의 `res`, `process.stdout` |
| Duplex | 읽기와 쓰기 | `net.Socket` |
| Transform | 읽기와 쓰기, 출력이 입력에서 계산됨 | `zlib.createGzip()` |

자식 프로세스의 `stdout`·`stderr`는 Readable이고 `stdin`은 Writable입니다. `process.stdout`·`process.stderr`는 프로세스가 끝날 때까지 닫히지 않습니다.

**흔한 실수:** 작은 데이터에까지 스트림을 쓰는 것입니다. 한 번에 올려도 되는 크기라면 `readFile`이 단순합니다. 스트림은 크기를 모르거나 클 때, 또는 읽으면서 바로 다음 단계로 넘길 때 씁니다.

## Readable

Readable은 데이터를 읽어 가는 원천(source)입니다. 소비하는 쪽이 읽을 준비가 되면 스트림이 안에서 데이터를 만들어 내부 버퍼를 거쳐 내보냅니다. 소비하는 방법이 연결되기 전에는 데이터를 만들지 않습니다.

직접 만들 때는 `read()` 옵션 안에서 `this.push()`로 조각을 넣습니다(자세히는 아래 push 절).

```js
import { Readable } from 'node:stream'

let n = 0
const counter = new Readable({
  read() {
    n += 1
    this.push(n <= 3 ? String(n) : null) // null은 끝
  },
})
counter.on('data', (c) => console.log(c))
// <Buffer 31>, <Buffer 32>, <Buffer 33> 순서로 출력
```

- 문자열로 넣어도 소비하는 쪽은 `Buffer`를 받습니다. 문자열로 받으려면 `setEncoding('utf8')`을 호출합니다. 이 방식은 조각 경계에 걸친 여러 바이트 문자도 올바르게 디코딩합니다.
- 소비 방법은 `'data'` 이벤트, `'readable'` 이벤트와 `read()`, `pipe()`, 비동기 이터레이터 중 하나만 고르고 섞어 쓰지 않습니다. 섞으면 동작을 예측하기 어렵습니다.
- 자주 쓰는 읽기 쪽 속성: `readableFlowing`, `readableLength`(버퍼에 쌓인 크기), `readableHighWaterMark`, `readableEnded`, `destroyed`.

## Writable

Writable은 데이터를 쓰는 목적지(destination)입니다. `write(chunk)`로 조각을 넣고, 더 쓸 것이 없으면 `end()`를 호출합니다.

```js
import { Writable } from 'node:stream'

const sink = new Writable({
  write(chunk, encoding, callback) {
    console.log(chunk)  // <Buffer 61>
    callback()          // 이 조각 처리가 끝났다는 신호
  },
})
sink.write('a') // true
sink.end('b')   // 마지막 조각을 쓰고 닫기
```

- `write()`는 불리언을 돌려줍니다. 내부 버퍼가 `highWaterMark`보다 작으면 `true`이고, 이상이면 `false`입니다. `false`를 받으면 `'drain'` 이벤트가 올 때까지 쓰기를 멈춰야 합니다(자세히는 2편).
- 문자열은 기본적으로 `Buffer`로 바뀌어 `write` 구현에 전달됩니다(`decodeStrings` 기본값 `true`).
- `callback`은 조각 하나를 다 처리해야 호출합니다. 호출하지 않으면 다음 조각이 오지 않습니다. 에러는 `callback(err)`로 알립니다.
- `end()` 뒤의 `write()`는 `ERR_STREAM_WRITE_AFTER_END` 에러입니다.
- `destroy()`는 버퍼에 남은 쓰기를 기다리지 않고 즉시 닫습니다. 남은 데이터를 보내려면 `end()`를 씁니다.

**흔한 실수:** `write()`의 반환값을 무시하고 반복해서 쓰는 것입니다. 버퍼가 계속 커져 메모리가 늘어납니다.

## Duplex

Duplex는 Readable과 Writable을 모두 구현한 스트림입니다. 두 쪽은 버퍼를 따로 가지며 서로 독립적입니다. 한쪽에 쓴 것이 다른 쪽에서 나오지 않습니다. 가장 흔한 예는 TCP 연결인 `net.Socket`입니다. 받은 데이터는 읽기 쪽으로, 보낼 데이터는 쓰기 쪽으로 갑니다.

```js
import { Duplex } from 'node:stream'

const d = new Duplex({
  read() { this.push('out'); this.push(null) },
  write(chunk, enc, cb) { console.log('in', chunk); cb() },
})
d.on('data', (c) => console.log(c)) // <Buffer 6f 75 74>
d.end('x')                          // in <Buffer 78>
```

- 옵션 `readableHighWaterMark`와 `writableHighWaterMark`로 양쪽 버퍼를 따로 정합니다. `highWaterMark`를 주면 둘 다 같은 값이 됩니다.
- `allowHalfOpen`의 기본값은 `true`입니다. 읽기 쪽이 끝나도 쓰기 쪽은 열려 있습니다. `false`로 두면 읽기 쪽이 끝날 때 쓰기 쪽도 자동으로 끝납니다.
- `stream.duplexPair()`는 서로 연결된 Duplex 한 쌍을 만듭니다. 한쪽에 쓴 데이터가 다른 쪽에서 읽힙니다. 네트워크 연결을 흉내 내는 테스트에 씁니다(v22.6.0 추가).

## Transform

Transform은 Duplex의 한 종류로, 쓴 데이터를 변환해 읽는 쪽으로 내보냅니다. 입력과 출력의 크기·개수가 같을 필요는 없습니다. `zlib` 압축 스트림과 `crypto` 스트림이 Transform입니다.

구현하는 메서드는 `transform(chunk, encoding, callback)`이고, 마지막에 덧붙일 데이터가 있으면 `flush(callback)`을 씁니다.

```js
import { Transform } from 'node:stream'

const upper = new Transform({
  transform(chunk, encoding, callback) {
    callback(null, chunk.toString().toUpperCase())
  },
  flush(callback) {
    this.push('!') // 입력이 끝난 뒤 한 번 호출
    callback()
  },
})
upper.on('data', (c) => console.log(String(c)))
upper.write('ab')
upper.end('cd')
// AB, CD, ! 순서로 출력
```

- `callback(null, data)`는 `this.push(data); callback()`과 같습니다. 첫 번째 인수가 에러이면 두 번째 인수는 무시됩니다.
- `transform`은 병렬로 호출되지 않습니다. 다음 조각은 `callback`이 불린 뒤에 옵니다.
- 출력을 읽는 쪽이 소비하지 않으면 쓰기 쪽도 멈춥니다. Transform은 반드시 소비하는 쪽(`pipe`, `'data'` 리스너 등)과 함께 씁니다.
- 객체 모드 변환기와 `pipeline` 조합은 2편에서 다룹니다.

## PassThrough

PassThrough는 입력을 아무 변환 없이 그대로 출력하는 Transform입니다. 두 용도로 씁니다.

- 예제와 테스트에서 쓰는 단순한 스트림
- 새로운 형태의 스트림을 만들 때 쓰는 연결 부품

```js
import { PassThrough } from 'node:stream'

const pass = new PassThrough()
pass.on('data', (c) => console.log(c.toString())) // hello
pass.end('hello')
```

변환이 필요 없으니 `transform` 구현이 없습니다. 쓴 것이 그대로 읽는 쪽으로 나옵니다.

## flowing 모드

flowing 모드는 Readable이 데이터를 자동으로 읽어 이벤트로 계속 전달하는 상태입니다. 소비하는 쪽이 따로 요청하지 않아도 데이터가 가능한 한 빨리 나옵니다.

모든 Readable은 paused로 시작하고, 아래 세 가지 중 하나로 flowing이 됩니다.

- `'data'` 리스너를 붙임(명시적으로 멈추지 않은 스트림에서)
- `resume()` 호출
- `pipe()` 호출

내부 상태는 `readableFlowing`으로 확인하며 값이 세 가지입니다.

| 값 | 의미 | 데이터 |
|----|------|--------|
| `null` | 소비 방법이 아직 없음 | 만들지 않음 |
| `true` | flowing | 이벤트로 전달 |
| `false` | 명시적으로 멈춤 | 만들지만 전달하지 않고 버퍼에 쌓음 |

```js
const r = new Readable({ read() {} })
r.readableFlowing        // null
r.on('data', () => {})
r.readableFlowing        // true
r.pause()
r.readableFlowing        // false
r.resume()
r.readableFlowing        // true
```

- `false`일 때 `'data'` 리스너를 새로 붙여도 `true`로 바뀌지 않습니다. `resume()`을 호출해야 합니다.
- `'data'` 리스너를 제거해도 자동으로 멈추지 않습니다. 소비하는 쪽이 없는 flowing 상태에서 나온 데이터는 버려집니다. 확실히 멈추려면 `pause()`를 호출합니다.
- `resume()`만 호출하고 리스너가 없으면 데이터를 읽지 않고 끝까지 흘려보내 버립니다. 응답 본문을 읽지 않고 비우려는 용도로 씁니다.

## paused 모드

paused 모드는 소비하는 쪽이 `read()`를 직접 호출해 조각을 가져오는 상태입니다. 데이터는 내부 버퍼에 쌓이고, 요청하기 전에는 이벤트로 나오지 않습니다.

- `'readable'` 리스너를 붙이면 flowing이 멈추고 `read()` 방식이 됩니다(자세히는 아래 readable 이벤트 절).
- `pause()`는 flowing 스트림을 paused로 돌립니다. 데이터는 버퍼에 남습니다.
- `pipe()`로 연결된 대상이 있으면 `pause()`를 호출해도 대상이 데이터를 다시 요청하는 순간 흐름이 재개될 수 있습니다. 완전히 멈추려면 `unpipe()`로 연결을 끊습니다.
- `'readable'` 리스너가 붙어 있으면 `pause()`와 `resume()`은 효과가 없습니다.

```js
const r = new Readable({ read() {} })
r.on('data', (c) => console.log(c.toString()))
r.pause()
r.push('buffered')  // 출력 없음. 버퍼에 쌓임
r.resume()          // buffered
```

paused와 객체 모드는 별개 개념입니다. 객체 모드 스트림도 flowing일 수 있고, 바이트 스트림도 paused일 수 있습니다.

## data 이벤트

`'data'`는 스트림이 조각 하나의 소유권을 소비하는 쪽에 넘길 때 발생합니다. 인수는 조각이며, `setEncoding()`으로 인코딩을 정했으면 문자열이고 아니면 `Buffer`입니다. 객체 모드에서는 `null`을 뺀 아무 값입니다.

```js
const chunks = []
readable.on('data', (chunk) => chunks.push(chunk))
```

- `'data'` 리스너를 붙이면 flowing 모드로 바뀝니다. 리스너를 붙이는 즉시 호출되지 않고, 데이터가 준비되면 비동기로 발생합니다.
- 한 번에 오는 조각의 크기는 정해져 있지 않습니다. 한 메시지가 여러 조각으로 나뉘어 올 수 있으므로 조각 경계가 메시지 경계라고 가정하면 안 됩니다.
- `'readable'` 리스너가 함께 있으면 `read()`가 호출될 때만 `'data'`가 발생합니다. 데이터를 반환한 `read()` 호출 때도 `'data'`가 발생합니다.
- 조각을 `+=`로 문자열에 이어 붙이면 `Buffer`가 암묵적으로 문자열로 바뀝니다. 여러 바이트 문자가 조각 경계에 걸려 있으면 깨집니다. `setEncoding('utf8')`을 쓰거나 `Buffer`를 모아 `Buffer.concat()`으로 합칩니다(자세히는 4편).

## end 이벤트

`'end'`는 Readable에서 더 소비할 데이터가 없을 때 한 번 발생합니다. 데이터를 모두 소비해야 발생하므로, 소비 방법이 없으면 발생하지 않습니다.

```js
readable.on('data', (chunk) => {})
readable.on('end', () => {
  console.log('더 이상 데이터 없음')
})
```

- 오류로 끝난 스트림에서는 `'end'`가 나오지 않습니다. 오류는 `'error'`로 오고 이후 `'close'`가 옵니다.
- `'end'` 뒤에 `read()`를 호출하면 에러 없이 `null`을 돌려줍니다.
- `'end'`는 읽기가 끝났다는 뜻이고, 자원 정리가 끝났다는 뜻이 아닙니다. 파일 디스크립터 같은 자원이 닫힌 뒤에는 `'close'`가 발생합니다. 기본 `autoDestroy` 설정에서 스트림은 `'end'` 뒤에 자동으로 `destroy()`되어 `'close'`가 나옵니다.
- `readableEnded` 속성은 `'end'`가 발생한 뒤 `true`가 됩니다.
- Transform에서 `'end'`는 `flush`의 콜백이 호출되어 모든 출력이 나온 뒤에 발생합니다.

**흔한 실수:** `'end'`를 기다리는데 소비 방법을 붙이지 않아 영원히 오지 않는 경우입니다. 내용이 필요 없으면 `resume()`으로 비워 줍니다.

## finish 이벤트

`'finish'`는 Writable에서 `end()`가 호출되고 모든 데이터가 내부 시스템으로 전달된 뒤 한 번 발생합니다. 쓰기 쪽이 끝났다는 신호입니다.

```js
const w = createWriteStream('out.txt')
w.on('finish', () => console.log('모두 썼다'))
w.write('a')
w.end('b')
```

| 이벤트 | 대상 | 의미 |
|--------|------|------|
| `'end'` | Readable | 읽을 데이터를 모두 소비함 |
| `'finish'` | Writable | `end()` 후 쓰기를 모두 처리함 |
| `'close'` | 둘 다 | 스트림과 하위 자원이 닫힘 |

- `end()` 직후에 `'finish'`가 오는 것은 아닙니다. 쓰기 대기 중인 조각이 모두 처리되어야 합니다. `writableEnded`는 `end()`를 호출하면 바로 `true`이고, `writableFinished`는 `'finish'` 직전에 `true`가 됩니다.
- 파일 쓰기 스트림은 `'finish'` 뒤에 `'close'`가 오며, 그때 파일 디스크립터가 닫힙니다. 쓰기 완료 후 파일을 다시 읽는 코드는 `'finish'`면 충분하지만, 자원 해제가 필요하면 `'close'`를 봅니다.
- Duplex와 Transform은 읽기 쪽의 `'end'`와 쓰기 쪽의 `'finish'`를 모두 가집니다. 두 이벤트의 발생 순서에 의존하는 코드를 쓰지 않습니다.
- 에러가 나면 `'finish'`는 나오지 않습니다.
- `end()`의 콜백은 `'finish'` 이전 또는 에러 시에 호출됩니다. `stream.finished()`로 이벤트들을 한꺼번에 기다릴 수 있습니다(자세히는 2편).

## readable 이벤트

`'readable'`은 읽을 데이터가 버퍼에 있을 때, 그리고 스트림 끝에 도달했을 때 발생합니다. 이 이벤트를 받으면 `read()`로 데이터를 직접 꺼내야 합니다(v10.0.0부터 `'readable'` 사용 시 `read()` 호출이 필수).

```js
readable.on('readable', () => {
  let chunk
  while ((chunk = readable.read()) !== null) {
    console.log(chunk.length)
  }
})
readable.on('end', () => console.log('끝'))
```

- `'readable'` 리스너를 붙이면 `readableFlowing`이 `false`가 되어 flowing이 멈춥니다. `'data'` 리스너가 함께 있어도 `'readable'`이 우선하고, `'data'`는 `read()`가 데이터를 돌려줄 때만 발생합니다. `'readable'` 리스너를 제거하고 `'data'` 리스너가 남아 있으면 다시 flowing이 됩니다.
- 끝에 도달했을 때도 한 번 더 발생합니다. 이때 `read()`는 `null`을 돌려주고 `'end'`가 이어서 발생합니다. 빈 파일은 `read()`가 `null`인 `'readable'` 한 번 뒤에 `'end'`가 옵니다.
- 이벤트 한 번에 `read()`를 한 번만 호출하면 버퍼에 남은 데이터가 처리되지 않아 다음 이벤트가 오지 않을 수 있습니다. 위 코드처럼 `null`이 나올 때까지 반복해서 읽습니다.
- `'data'`나 `pipe()`보다 이해하기 어렵지만 처리량이 높아질 수 있다고 공식 문서가 설명합니다.

## read()

`readable.read([size])`는 내부 버퍼에서 데이터를 꺼내 돌려줍니다. 가져올 데이터가 없으면 `null`입니다. 기본적으로 `Buffer`를 돌려주고, `setEncoding()`을 호출했거나 객체 모드이면 문자열 또는 해당 값을 돌려줍니다.

```js
const r = new Readable({ read() {} })
r.push('abcdef')
r.once('readable', () => {
  r.read(4)  // <Buffer 61 62 63 64>
  r.read(4)  // null (2바이트뿐이고 끝나지 않았음)
})
```

- `size`를 생략하면 버퍼에 있는 전부를 돌려줍니다. 조각이 이어 붙은 채로 나옵니다.
- `size`를 주면 그만큼 모일 때까지 `null`입니다. 스트림이 끝났다면 남은 것을 전부 돌려줍니다. 최대 1 GiB입니다.
- 객체 모드에서는 `size`와 관계없이 항목 하나를 돌려줍니다.
- 한 번 호출로 파일 전체를 얻을 수 없습니다. 여러 번의 `'readable'`에 걸쳐 조각을 모아야 합니다.
- flowing 모드에서는 스트림이 버퍼가 빌 때까지 `read()`를 알아서 호출하므로 직접 호출하지 않습니다.
- `read()`가 `null`이 아닌 값을 돌려주면 `'data'`도 함께 발생합니다.

## push

`readable.push(chunk[, encoding])`는 Readable을 구현하는 쪽이 읽기 큐에 데이터를 넣는 메서드입니다. 소비하는 쪽이 부르는 메서드가 아닙니다.

```js
const r = new Readable({
  read() {
    this.push('a')
    this.push(null) // 끝 신호(EOF)
  },
})
```

- `chunk`는 문자열, `Buffer`, `TypedArray`, `DataView`입니다. 객체 모드에서는 `null`을 뺀 아무 값이 가능합니다. 다른 타입은 `ERR_INVALID_ARG_TYPE` 에러입니다.
- `null`을 넣으면 스트림이 끝납니다. 이미 넣은 데이터는 모두 소비된 뒤 `'end'`가 발생합니다. 그 뒤에 `push()`하면 `ERR_STREAM_PUSH_AFTER_EOF` 에러입니다.
- 반환값이 `false`이면 버퍼가 `highWaterMark`에 도달한 것이므로 소스에서 읽기를 멈춰야 합니다. 스트림이 다시 준비되면 `read()` 구현이 호출됩니다.
- 구현의 `read()`는 한 번 호출되면 `push()`가 일어나기 전에는 다시 호출되지 않습니다. 빈 문자열이나 빈 버퍼를 넣어서는 다시 호출되지 않습니다.
- 소비하는 쪽 모드에 따라 데이터가 전달되는 방식이 다릅니다. paused이면 `'readable'`과 `read()`로, flowing이면 `'data'` 이벤트로 나갑니다.
- `read()` 구현 안의 에러는 `throw`나 `'error'` 직접 발생이 아니라 `this.destroy(err)`로 알립니다.
- `unshift(chunk)`는 읽은 데이터를 큐의 앞에 되돌려 놓습니다. 헤더를 읽고 남은 본문을 돌려줄 때 쓰고, `'end'` 이후에는 호출할 수 없습니다.

## 핵심 정리

- 스트림은 데이터를 조각으로 흘려 처리하는 인터페이스이며 Readable, Writable, Duplex, Transform 네 종류가 있고 모두 `EventEmitter`입니다.
- Duplex는 읽기와 쓰기가 독립이고, Transform은 쓴 것을 변환해 읽는 쪽으로 내보내며, PassThrough는 변환 없이 그대로 통과시킵니다.
- Readable은 paused로 시작해 `'data'` 리스너, `resume()`, `pipe()`로 flowing이 되며, `readableFlowing`은 `null`·`true`·`false` 세 상태입니다.
- `'readable'`은 flowing을 멈추고 `read()` 호출을 요구하며, `read()`는 데이터가 없으면 `null`을 돌려줍니다.
- `'end'`는 Readable의 소비 완료, `'finish'`는 Writable의 쓰기 완료, `'close'`는 자원 해제이며 소비하지 않으면 `'end'`는 오지 않습니다.
- `push()`는 구현하는 쪽이 읽기 큐에 넣는 메서드이고 `null`이 끝 신호이며, `false`가 오면 소스 읽기를 멈춥니다.
