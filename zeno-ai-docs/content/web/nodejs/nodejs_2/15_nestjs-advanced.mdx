## Guard와 인증

Guard는 요청이 핸들러에 도달해도 되는지 결정하는 클래스입니다. `CanActivate`를 구현하고 `canActivate(context)`가 `true`면 통과, `false`면 거부합니다. 인증(누구인가)과 인가(무엇을 해도 되는가)의 개념은 10편입니다. 순서는 Middleware 다음, Interceptor와 Pipe 앞입니다(14편).

```ts
@Injectable()
export class AuthGuard implements CanActivate {
  canActivate(ctx: ExecutionContext): boolean {
    const req = ctx.switchToHttp().getRequest()
    return Boolean(req.headers.authorization)
  }
}

@UseGuards(AuthGuard) // 컨트롤러 또는 메서드에 적용
@Controller('cats')
export class CatsController {}
```

- `canActivate`는 `boolean`, `Promise<boolean>`, `Observable<boolean>`을 반환할 수 있습니다.
- `false`를 반환하면 Nest가 `ForbiddenException`(403)을 던집니다. 인증 실패를 401로 응답하려면 직접 `UnauthorizedException`을 던집니다. Guard가 던진 예외도 예외 필터가 처리합니다.
- `ExecutionContext`는 `ArgumentsHost`를 확장해 `getHandler()`(실행될 메서드)와 `getClass()`(컨트롤러)를 제공합니다. 미들웨어는 다음에 무엇이 실행될지 모르지만 Guard는 압니다.
- 전역 Guard는 `app.useGlobalGuards(new G())`(DI 불가) 또는 모듈의 `{ provide: APP_GUARD, useClass: G }`(DI 가능)로 등록합니다.

### 역할 기반 인가

메서드에 역할 메타데이터를 붙이고 `Reflector`로 읽어 Guard에서 비교합니다.

```ts
export const Roles = Reflector.createDecorator<string[]>()

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}
  canActivate(ctx: ExecutionContext): boolean {
    const roles = this.reflector.getAllAndOverride(Roles, [
      ctx.getHandler(), ctx.getClass(),
    ])
    if (!roles) return true // 역할 제한 없음
    const { user } = ctx.switchToHttp().getRequest()
    return roles.includes(user.role)
  }
}
// 사용: @Roles(['admin']) @Get('admin') admin() {}
```

- `getAllAndOverride`는 메서드 → 클래스 순으로 먼저 찾은 값을 씁니다.
- Guard는 `req.user`가 이미 채워져 있다고 가정합니다. 따라서 인증 Guard가 먼저 실행되어야 합니다(`@UseGuards(AuthGuard('jwt'), RolesGuard)`는 왼쪽부터 실행).

### JWT 발급과 Passport 검증

`@nestjs/jwt`의 `JwtModule`과 `JwtService`가 JWT 서명·검증을 맡습니다(JWT 구조와 검증 규칙은 10편). 비밀 키는 `ConfigService`에서 읽습니다.

```ts
JwtModule.registerAsync({
  global: true,
  inject: [ConfigService],
  useFactory: (c: ConfigService) => ({
    secret: c.getOrThrow<string>('JWT_SECRET'),
    signOptions: { expiresIn: '15m' },
  }),
})
// 발급: await jwt.signAsync({ sub: user.id })
// 검증: await jwt.verifyAsync(token) — 위조·만료 시 예외
```

Passport는 Node.js에서 가장 널리 쓰이는 인증 라이브러리이고, 인증 방식(strategy)을 플러그인으로 교체합니다. `@nestjs/passport`가 이를 Guard와 연결합니다. 설치: `npm i @nestjs/passport passport passport-jwt`와 타입 `@types/passport-jwt`.

```ts
@Injectable()
export class JwtStrategy
  extends PassportStrategy(Strategy) {
  constructor(config: ConfigService) {
    super({
      jwtFromRequest:
        ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: config.getOrThrow('JWT_SECRET'),
    })
  }
  validate(p: { sub: number; role: string }) {
    return { id: p.sub, role: p.role } // req.user가 됨
  }
}
```

- `Strategy`와 `ExtractJwt`는 `passport-jwt`에서 import합니다. 전략 클래스를 모듈의 `providers`에 등록하고 라우트에는 `@UseGuards(AuthGuard('jwt'))`를 붙입니다.
- Passport가 서명과 만료를 먼저 검증하고, 통과하면 `validate(payload)`가 호출됩니다. 반환값이 `req.user`가 됩니다. 검증 실패는 401입니다.
- 토큰이 없거나 위조되었거나 만료되면 401, 토큰은 유효하지만 역할이 부족하면 `RolesGuard`가 403으로 응답합니다.
- 로그인 엔드포인트는 사용자 확인(해시 비교는 10편) 후 `signAsync`로 토큰을 발급합니다. 로컬 로그인에는 `passport-local` 전략과 `AuthGuard('local')`을 같은 방식으로 씁니다.
- 모든 라우트를 기본 보호하고 공개 라우트만 예외로 두려면 `APP_GUARD`에 JWT Guard를 등록하고, `Reflector.createDecorator`로 만든 `@Public()` 메타데이터가 붙은 라우트는 통과시킵니다.
- 현재 Nest 인증 가이드는 Passport 대신 `@nestjs/authentication` 패키지(세션, Bearer JWT, OIDC 등)를 소개합니다. 이 패키지의 npm 버전은 0.0.1(2026-09 게시)이어서 아직 초기 단계입니다. Passport 방식은 공식 레시피로 계속 제공되고 `@nestjs/passport`는 12.0.0이 최신입니다. 이 문서는 널리 쓰이는 Passport·JWT를 기준으로 합니다.

**흔한 실수:** JWT 비밀 키를 코드에 쓰는 것입니다. 환경 변수에서 읽고 시작할 때 `getOrThrow`로 누락을 드러냅니다(14편).

## Interceptor

Interceptor는 핸들러 실행 앞뒤를 감싸는 클래스입니다. `NestInterceptor`의 `intercept(context, next)`를 구현하고, `next.handle()`이 핸들러를 실행해 응답을 Observable(RxJS)로 돌려줍니다. 로깅, 응답 변환, 예외 변환, 타임아웃, 캐시 같은 횡단 관심사에 씁니다.

```ts
@Injectable()
export class WrapInterceptor implements NestInterceptor {
  intercept(ctx: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(map((data) => ({ data })))
  }
}
// @UseInterceptors(WrapInterceptor) → { "data": 핸들러 반환값 }
```

- `next.handle()`을 호출하기 전 코드는 핸들러 전에, `pipe`로 이어 붙인 연산자는 핸들러가 끝난 뒤에 실행됩니다. `next.handle()`을 부르지 않으면 핸들러가 실행되지 않습니다(캐시 히트 시 `of(cached)`를 반환하는 방식).
- 자주 쓰는 RxJS 연산자는 `tap`(부수 효과, 소요 시간 측정), `map`(변환), `catchError`(예외 변환), `timeout`(시간 제한)입니다.
- 적용 범위는 메서드·컨트롤러(`@UseInterceptors`), 전역(`app.useGlobalInterceptors`, DI가 필요하면 `APP_INTERCEPTOR`)입니다.
- 복귀 순서는 진입의 역순입니다. 라우트 → 컨트롤러 → 전역입니다(14편).

```ts
return next.handle().pipe(
  timeout(5000),
  catchError((e) => {
    const timedOut = e instanceof TimeoutError
    return throwError(() =>
      timedOut ? new RequestTimeoutException() : e)
  }),
) // 5초를 넘기면 408
```

**흔한 실수:** 응답 변환 Interceptor에서 `@Res()`로 직접 응답하는 핸들러까지 감싸려는 것입니다. `@Res()`를 쓰면 Nest의 응답 처리가 꺼져 Interceptor의 변환이 적용되지 않습니다(14편). 값을 반환하는 방식을 씁니다.

## 커스텀 데코레이터

데코레이터는 직접 만들 수 있습니다. 매개변수 데코레이터는 `createParamDecorator`로, 여러 데코레이터를 하나로 묶는 조합은 `applyDecorators`로, 메타데이터 부착은 `Reflector.createDecorator`(또는 `SetMetadata`)로 만듭니다.

```ts
export const CurrentUser = createParamDecorator(
  (key: string | undefined, ctx: ExecutionContext) => {
    const user = ctx.switchToHttp().getRequest().user
    return key ? user?.[key] : user
  },
)
// @Get('me') me(@CurrentUser() user) {}
// @Get('id') id(@CurrentUser('id') id: number) {}
```

- 첫 인자(`data`)는 데코레이터 호출 시 넘긴 값(`'id'`)입니다. 두 번째 인자 `ExecutionContext`로 요청 객체에 접근합니다.
- 매개변수 데코레이터에도 파이프를 붙일 수 있고, ValidationPipe는 이 값을 검증할 수 있습니다.
- `applyDecorators`는 반복되는 조합을 한 이름으로 묶습니다.

```ts
export function Auth(...roles: string[]) {
  return applyDecorators(
    Roles(roles),
    UseGuards(AuthGuard('jwt'), RolesGuard),
    ApiBearerAuth(), // Swagger용(아래 절)
  )
}
// @Auth('admin') 하나로 인증·인가·문서 표시
```

- 메타데이터 데코레이터는 값을 저장만 하고 동작하지 않습니다. 읽는 쪽(Guard, Interceptor)이 `Reflector`로 꺼내 씁니다.

## 프로바이더 스코프

스코프는 프로바이더 인스턴스가 만들어지고 공유되는 범위입니다.

| 스코프 | 인스턴스 | 생성 시점 |
|--------|----------|-----------|
| `DEFAULT` | 앱 전체에서 하나(싱글턴) | 앱 시작 시 |
| `REQUEST` | 요청마다 새로 생성 | 요청 도착 시, 응답 후 GC |
| `TRANSIENT` | 주입받는 소비자마다 별개 | 주입 시 |

```ts
@Injectable({ scope: Scope.REQUEST })
export class TenantService {
  constructor(@Inject(REQUEST) private req: Request) {}
  tenantId() { return this.req.headers['x-tenant-id'] }
}
```

- 커스텀 프로바이더에는 `{ provide, useClass, scope: Scope.TRANSIENT }`로, 컨트롤러에는 `@Controller({ path, scope: Scope.REQUEST })`로 지정합니다.
- `@Inject(REQUEST)`(`@nestjs/core`)로 현재 요청을 주입받으려면 그 프로바이더가 요청 스코프여야 합니다.
- `REQUEST` 스코프는 의존 사슬을 타고 위로 번집니다. 요청 스코프 서비스를 쓰는 컨트롤러도 요청마다 새로 만들어집니다. `TRANSIENT`는 번지지 않습니다.
- 요청마다 객체 트리를 만들므로 성능 비용이 있습니다. 문서는 잘 설계된 앱에서 지연 증가가 약 5퍼센트 이내라고 설명하지만, 기본은 싱글턴입니다. 요청 단위 값이 필요하면 `AsyncLocalStorage`(23편)로 싱글턴 안에서 요청 컨텍스트를 읽는 방법도 있습니다.
- 멀티 테넌트처럼 같은 속성의 요청을 묶어 하위 트리를 재사용하려면 `ContextIdStrategy`와 `@Injectable({ scope: Scope.REQUEST, durable: true })`를 씁니다.
- `INQUIRER` 토큰으로 이 프로바이더를 주입받는 부모 클래스를 알 수 있습니다.

**흔한 실수:** 사용자 상태를 싱글턴 서비스의 필드에 저장하는 것입니다. 모든 요청이 같은 인스턴스를 공유하므로 요청 간 데이터가 섞입니다. 요청 데이터는 매개변수로 넘기거나 요청 스코프로 분리합니다.

## 동적 모듈

동적 모듈은 가져오는 쪽이 옵션을 넘겨 설정을 바꿀 수 있는 모듈입니다. 정적 메서드가 `DynamicModule` 객체(`module`, `providers`, `exports`, `imports`, `global`)를 반환합니다.

```ts
@Module({})
export class IdModule {
  static forRoot(opts: { prefix: string }): DynamicModule {
    return {
      module: IdModule,
      providers: [
        { provide: 'ID_OPTIONS', useValue: opts },
        IdService, // @Inject('ID_OPTIONS')로 옵션을 받음
      ],
      exports: [IdService],
    }
  }
}
// imports: [IdModule.forRoot({ prefix: 'u' })]
```

메서드 이름은 관례로 구분합니다(`ConfigModule.forRoot`, `JwtModule.register`가 이 관례를 따릅니다).

| 이름 | 의미 |
|------|------|
| `register()` | 가져오는 모듈마다 따로 설정한 인스턴스 |
| `forRoot()` | 앱 전체에서 한 번 설정(주로 루트 모듈) |
| `forFeature()` | `forRoot` 설정을 쓰되 모듈별로 일부만 조정 |

- 각각 비동기 버전(`registerAsync`, `forRootAsync`, `forFeatureAsync`)이 있고, 옵션을 `useFactory`와 `inject`로 만듭니다. `ConfigService`에서 값을 읽을 때 씁니다.
- `ConfigurableModuleBuilder`는 옵션 토큰과 `register`·`registerAsync`를 자동 생성합니다.

```ts
export const {
  ConfigurableModuleClass, MODULE_OPTIONS_TOKEN,
} = new ConfigurableModuleBuilder<IdOptions>()
  .setClassMethodName('forRoot') // 기본은 register
  .build()

@Module({ providers: [IdService], exports: [IdService] })
export class IdModule extends ConfigurableModuleClass {}
// IdService는 @Inject(MODULE_OPTIONS_TOKEN)으로 옵션을 받음
```

- `global: true`를 반환 객체에 넣으면 `imports` 없이 전역으로 씁니다.
- 동적 모듈의 메타데이터는 `@Module()`의 메타데이터를 덮어쓰지 않고 확장합니다.

## 순환 의존

순환 의존은 A가 B를 주입받고 B가 A를 주입받는 관계입니다. 클래스가 서로 아직 정의되기 전에 참조해 시작이 실패합니다. 양쪽 모두 `forwardRef()`로 감싸 해결합니다.

```ts
@Injectable()
export class CatsService {
  constructor(
    @Inject(forwardRef(() => CommonService))
    private commonService: CommonService,
  ) {}
} // CommonService 쪽에서도 CatsService를 같은 방식으로 주입
```

모듈 사이의 순환은 `imports`에 `forwardRef(() => OtherModule)`을 씁니다.

- 인스턴스 생성 순서는 보장되지 않으므로 생성자에서 상대 프로바이더를 호출하면 안 됩니다.
- `index.ts`로 여러 파일을 다시 내보내는 barrel 파일은 import 수준의 순환을 만들기 쉬워 피합니다.
- 요청 스코프 프로바이더가 순환에 끼면 의존성이 `undefined`가 될 수 있습니다.
- 대안은 `ModuleRef`로 필요한 시점에 상대 프로바이더를 가져오는 것입니다.
- 가능하면 순환을 없애도록 구조를 바꿉니다. 공통 부분을 제3의 서비스로 분리하거나 이벤트로 느슨하게 연결합니다.

**흔한 실수:** `forwardRef`를 한쪽에만 쓰는 것입니다. 양쪽 모두 필요합니다.

## 테스트 모듈

`@nestjs/testing`의 `Test.createTestingModule()`은 `@Module()`과 같은 메타데이터로 테스트용 모듈을 만듭니다. `.compile()`(비동기)이 모듈을 구성하고 `TestingModule`을 반환합니다.

```ts
const moduleRef = await Test.createTestingModule({
  controllers: [CatsController],
  providers: [CatsService],
})
  .overrideProvider(CatsService)
  .useValue({ findAll: () => ['mock'] })
  .compile()

const controller = moduleRef.get(CatsController)
```

- `get()`은 정적(싱글턴) 인스턴스를, `resolve()`는 요청·transient 스코프 인스턴스를 꺼냅니다.
- `overrideProvider(X)`는 `useValue`, `useClass`, `useFactory`로 구현을 바꾸고, `overrideGuard`, `overrideInterceptor`, `overridePipe`, `overrideFilter`도 같은 식으로 씁니다. 인증 Guard를 통과시키는 대역으로 바꿔 라우트 테스트를 단순화합니다.
- `useMocker((token) => ...)`는 모듈이 필요로 하는데 선언하지 않은 의존성을 자동으로 대역으로 채웁니다.
- 단위 테스트는 클래스 하나를 의존성 대역과 함께 시험하고 `.spec` 접미사로 소스 옆에 둡니다.
- e2e 테스트는 `moduleRef.createNestApplication()` 후 `app.init()`으로 앱을 띄우고 HTTP 요청으로 시험합니다(supertest와 함께 `request(app.getHttpServer()).get('/cats').expect(200)`). `test/` 폴더에 `.e2e-spec` 접미사로 둡니다.
- 12에서 새로 만든 ESM 프로젝트의 기본 테스트 도구는 Vitest이고(`vi.fn()`, `vi.spyOn()`), Jest도 쓸 수 있습니다. Node 내장 테스트 러너와 도구 비교는 24편입니다.
- 서비스가 DB 호출을 하면 단위 테스트에서는 저장소를 대역으로 바꾸고, e2e나 통합 테스트에서는 테스트 DB를 씁니다(24편).

## Swagger

Swagger 모듈(`@nestjs/swagger`)은 라우트와 DTO에서 OpenAPI 문서를 만들고 Swagger UI로 보여 줍니다. OpenAPI의 개념은 8편입니다. 이 패키지가 만드는 명세는 OpenAPI 3.0입니다.

```ts
const config = new DocumentBuilder()
  .setTitle('Cats')
  .setVersion('1.0')
  .addBearerAuth()
  .build()
SwaggerModule.setup('docs', app, () =>
  SwaggerModule.createDocument(app, config))
```

| 경로 | 내용 |
|------|------|
| `/docs` | Swagger UI |
| `/docs-json` | OpenAPI JSON |
| `/docs-yaml` | OpenAPI YAML |

- `setup`의 첫 인자가 UI 경로이고 JSON·YAML은 그 뒤에 `-json`, `-yaml`이 붙습니다. 네 번째 인자(`SwaggerCustomOptions`)로 `ui`, `raw`, 사용자 CSS 등을 바꿉니다.
- 문서 객체를 만드는 함수를 `setup`에 넘기면 첫 요청까지 생성을 미룹니다.
- 라우트와 DTO를 설명하는 데코레이터입니다.

| 데코레이터 | 대상 |
|------------|------|
| `@ApiTags('cats')` | 컨트롤러를 태그로 묶음 |
| `@ApiOperation({ summary })` | 엔드포인트 설명 |
| `@ApiResponse({ status, type })` | 응답 명세 |
| `@ApiProperty()` | DTO 속성 |
| `@ApiBearerAuth()` | Bearer 인증 필요 표시 |

- `nest-cli.json`의 `plugins`에 `@nestjs/swagger`를 넣으면 TypeScript 타입에서 `@ApiProperty`와 응답 타입을 추론해 반복을 줄입니다. 세밀한 제어가 필요하면 데코레이터를 직접 씁니다.
- 12는 Standard Schema(Zod 4.2 이상, Valibot)로 만든 스키마를 `@Body({ schema })`에 쓰면 요청 본문 명세를 자동 생성합니다. 지원하지 않는 라이브러리는 `SwaggerDocumentOptions`의 `standardSchemaConverter`로 변환합니다.
- Fastify 어댑터에서는 `@fastify/static`을 추가로 설치합니다.

## Fastify 어댑터

Nest는 HTTP 플랫폼을 어댑터로 추상화해 Express 대신 Fastify를 쓸 수 있습니다(Fastify는 12편에서 비교했습니다). 설치는 `npm i @nestjs/platform-fastify`입니다.

```ts
import {
  FastifyAdapter, NestFastifyApplication,
} from '@nestjs/platform-fastify'

const app = await NestFactory
  .create<NestFastifyApplication>(
    AppModule,
    new FastifyAdapter(),
  )
await app.listen(3000, '0.0.0.0') // 컨테이너는 호스트 지정 필요
```

- 컨트롤러·모듈·DI·Guard·Pipe 같은 Nest 계층은 그대로 쓰고 아래의 HTTP 플랫폼만 바뀝니다. 공식 문서는 Fastify가 Express보다 크게 빠르다고 설명합니다. 실제 서비스 성능은 병목(DB 등)에 따라 달라집니다.
- Fastify는 기본으로 `localhost`에만 바인딩합니다. 외부 접속(컨테이너 포함)을 받으려면 `'0.0.0.0'`을 지정합니다(25편).
- 미들웨어는 `@fastify/middie`를 통해 동작하며 Fastify 래퍼가 아니라 원시 `req`, `res`를 받습니다.
- `@Res()`로 받는 응답 객체는 Fastify 것이라 메서드가 다릅니다. 리다이렉트는 `res.status(302).redirect('/login')`처럼 상태를 먼저 지정합니다.
- `FastifyAdapter`에 옵션을 넘기고(`new FastifyAdapter({ logger: true })`), `@RouteConfig()`, `@RouteConstraints()`로 Fastify 라우트 기능을 씁니다.
- 플랫폼을 바꿀 가능성이 있으면 `@Req()`, `@Res()` 직접 사용을 줄이고 반환값 방식을 씁니다.

**흔한 실수:** Express용 `@Res()` 코드를 그대로 Fastify에서 쓰는 것입니다. 객체의 API가 달라 런타임 에러가 납니다.

## 마이크로서비스 전송 개요

Nest의 마이크로서비스는 HTTP 대신 전송 계층(transport)으로 메시지를 주고받는 애플리케이션입니다. 내장 전송은 TCP(기본), Redis, NATS, MQTT, RabbitMQ, Kafka, gRPC이고 직접 만들 수도 있습니다. 메시지 브로커 개념은 18편입니다.

| 패턴 | 데코레이터 | 용도 |
|------|-----------|------|
| 요청-응답 | `@MessagePattern()` | 응답이 필요한 호출 |
| 이벤트 | `@EventPattern()` | 응답이 필요 없는 알림 |

```ts
// 서버는 NestFactory.createMicroservice로 시작한다
// { transport: Transport.TCP, options: { port: 4321 } }
@Controller()
export class MathController {
  @MessagePattern({ cmd: 'sum' })
  sum(d: number[]) { return d.reduce((a, b) => a + b, 0) }

  @EventPattern('user_created')
  onUserCreated(data: { id: number }) {} // 응답 없음
}
```

- 호출하는 쪽은 `ClientsModule.register([{ name: 'MATH', transport: Transport.TCP, ... }])`로 클라이언트를 등록하고 `@Inject('MATH') client: ClientProxy`로 받습니다.
- `client.send(pattern, payload)`는 응답을 기다리는 요청이고 cold Observable이라 구독(`firstValueFrom`)해야 전송됩니다. `client.emit(pattern, payload)`는 이벤트를 발행합니다.
- 같은 이벤트 패턴에 핸들러가 여러 개이면 병렬로 모두 실행됩니다.
- 응답 시간 제한은 RxJS `timeout` 연산자로 겁니다.
- `app.connectMicroservice()`로 HTTP 서버에 전송 계층을 함께 붙이는 하이브리드 앱을 만들 수 있습니다.
- 12에서 NATS 전송은 v3로 올라 `nats` 패키지 대신 `@nats-io/transport-node`를 씁니다.
- 마이크로서비스는 서비스가 나뉘어 네트워크 실패, 중복 전달, 순서 문제가 생기므로 모듈러 모놀리스로 충분한지 먼저 따집니다. 보통은 단일 앱 안의 모듈 구조(14편)와 작업 큐(18편)로 시작합니다.

## 핵심 정리

- Guard는 핸들러 전에 통과 여부를 결정합니다. `false`는 403이고, 인증 실패는 `UnauthorizedException`(401)을 던집니다. 역할은 `Reflector`로 읽습니다.
- JWT는 `@nestjs/jwt`로 발급·검증하고, Passport는 `PassportStrategy`의 `validate()` 반환값을 `req.user`에 넣어 `AuthGuard('jwt')`로 보호합니다.
- Interceptor는 `next.handle()`의 Observable을 `pipe`로 가공해 핸들러 전후, 응답 변환, 타임아웃을 처리합니다.
- 프로바이더는 기본이 싱글턴이고 `REQUEST` 스코프는 사슬 위로 번지며 비용이 있습니다.
- 동적 모듈은 `forRoot`·`register`·`forFeature` 관례로 옵션을 받고, 순환 의존은 양쪽 `forwardRef` 또는 구조 변경으로 해결합니다.
- 테스트는 `Test.createTestingModule`과 `overrideProvider`로 대역을 주입하고, Swagger는 `DocumentBuilder`로 OpenAPI 3.0 문서를 만듭니다.
- Fastify 어댑터는 HTTP 플랫폼만 교체하고, 마이크로서비스는 `@MessagePattern`(요청-응답)과 `@EventPattern`(이벤트)을 씁니다.
