## os

`node:os`는 실행 중인 운영체제와 머신의 정보를 돌려주는 모듈입니다. 안정성 지수는 2(Stable)입니다. 함수는 모두 호출한 시점의 값을 반환하는 동기 함수입니다.

```js
import os from 'node:os'

os.hostname()   // 'my-pc'
os.platform()   // 'win32', 'linux', 'darwin'
```

아래 항목이 이 편에서 다루는 `os`의 핵심입니다.

### cpus

`os.cpus()`는 논리 CPU 코어마다 하나씩, 정보 객체의 배열을 돌려줍니다.

```js
const cores = os.cpus()
cores.length   // 논리 코어 수
cores[0]
// { model: '...', speed: 2400,
//   times: { user, nice, sys, idle, irq } }
```

- `model`은 모델명, `speed`는 MHz, `times`는 각 모드에서 CPU가 보낸 시간(밀리초)입니다.
- CPU 정보를 얻지 못하는 환경(예: `/proc`이 없을 때)에서는 빈 배열입니다.
- `times`는 부팅 이후 누적값이라서 CPU 사용률을 구하려면 두 시점의 차이를 계산해야 합니다.
- `nice`는 POSIX 전용 값이라서 Windows에서는 모든 코어가 항상 0입니다.

### totalmem과 freemem

`os.totalmem()`은 시스템 전체 메모리, `os.freemem()`은 남은 메모리를 바이트 정수로 돌려줍니다.

```js
const gb = (n) => (n / 1024 ** 3).toFixed(1)
console.log(gb(os.totalmem()))   // 예: '15.8'
console.log(gb(os.freemem()))    // 예: '6.2'
```

- 현재 프로세스의 메모리가 아니라 머신 전체 값입니다. 프로세스 메모리는 `process.memoryUsage()`로 봅니다.
- 단위는 바이트입니다. 사람이 읽을 때는 직접 나눕니다.

### hostname

`os.hostname()`은 운영체제의 호스트 이름 문자열입니다. 로그에 인스턴스를 구분하는 표식을 넣을 때 씁니다.
### tmpdir

`os.tmpdir()`은 운영체제의 기본 임시 디렉터리 경로를 돌려줍니다. 끝에 구분자가 붙지 않습니다.

```js
import { mkdtemp } from 'node:fs/promises'
import { join } from 'node:path'

const dir = await mkdtemp(join(os.tmpdir(), 'app-'))
// 예: /tmp/app-a1b2c3
// 예: C:\Users\me\AppData\Local\Temp\app-a1b2c3
```

- Windows는 `TEMP`, `TMP` 환경 변수가, 그 밖의 플랫폼은 `TMPDIR`, `TMP`, `TEMP` 환경 변수가 이 값을 덮어씁니다. 어느 변수도 없으면 Windows는 `%SystemRoot%\temp`, 그 밖에는 `/tmp`입니다.
- 임시 파일 이름은 `mkdtemp` 같은 함수로 고유하게 만들고, 쓴 뒤에 지웁니다. 고정 이름은 충돌과 보안 문제를 만듭니다.

### EOL

`os.EOL`은 플랫폼별 줄바꿈 문자열입니다. POSIX는 `\n`, Windows는 `\r\n`입니다.

```js
const lines = ['a', 'b'].join(os.EOL)
// POSIX: 'a\nb', Windows: 'a\r\nb'
```

- 텍스트 파일을 읽을 때는 `EOL`로 쪼개지 않고 `\r?\n`으로 쪼갭니다. 다른 플랫폼에서 만든 파일이 섞여 있기 때문입니다.
- 네트워크 프로토콜(HTTP 등)은 플랫폼과 무관하게 `\r\n`이 규격입니다. `os.EOL`을 쓰지 않습니다.

### availableParallelism

`os.availableParallelism()`은 프로그램이 기본으로 쓸 병렬도의 추정치를 돌려줍니다. 항상 0보다 큰 정수이고 v19.4.0, v18.14.0에 추가되었습니다. libuv의 `uv_available_parallelism()`을 감싼 함수입니다.

- 워커 수를 정할 때 `os.cpus().length`보다 이 함수를 씁니다. `cpus()`는 배열이 비어 있을 수 있지만 이 함수는 0을 돌려주지 않습니다.
- 워커와 클러스터는 이 과목의 범위가 아닙니다.

## util.promisify

`util.promisify(original)`은 마지막 인수로 에러 우선 콜백 `(err, value) => ...`을 받는 함수를 Promise를 반환하는 함수로 바꿉니다.

```js
import { promisify } from 'node:util'
import { stat } from 'node:fs'

const statAsync = promisify(stat)
const info = await statAsync('.')
// 콜백의 err는 reject, 두 번째 인수는 resolve 값
```

- 원본에 `original[util.promisify.custom]` 속성이 있으면 그 값을 돌려줍니다. 그래서 `promisify(setTimeout)`은 `(ms, value)`를 받는 Promise 버전입니다.
- 마지막 인수가 에러 우선 콜백이 아닌 함수에 쓰면 그 자리에 콜백이 억지로 전달되어 의도와 다르게 동작합니다.
- `this`를 쓰는 메서드는 그대로 넘기면 `this`를 잃습니다. 바인딩하거나 감싸서 씁니다.
- 이미 Promise를 반환하는 함수에 `promisify`를 쓰는 것은 v20.8.0부터 사용 중단(deprecated)입니다.
- 내장 모듈은 대부분 `node:fs/promises`처럼 Promise 버전을 따로 제공하므로 직접 `promisify`할 일은 콜백 API뿐입니다. 반대 방향은 `util.callbackify`입니다.

## util.types

`util.types`는 내장 객체의 종류를 검사하는 함수 모음이며 `node:util/types`로도 가져옵니다.

```js
import { types } from 'node:util'

types.isPromise(Promise.resolve())    // true
types.isAsyncFunction(async () => {}) // true
types.isProxy(new Proxy({}, {}))      // true
types.isNativeError(new TypeError())  // true
```

- `isDate`, `isRegExp`, `isMap`, `isSet`, `isTypedArray`, `isGeneratorFunction` 등이 있습니다.
- `instanceof`나 `Object.prototype.toString.call`과 달리 프로토타입처럼 JS에서 접근 가능한 속성을 보지 않고 엔진 내부의 종류를 검사하며, 보통 C++을 호출하는 비용이 듭니다.
- 공식 문서는 주로 애드온 개발자를 위한 용도라고 설명하고, 결과가 JS에서 어떤 속성이나 동작을 가졌는지는 보장하지 않는다고 적습니다. 일상 코드에서는 `Array.isArray`, `instanceof`로 충분합니다.
- JS 코드만으로 구분하기 어려운 `Proxy` 여부(`isProxy`)나 비동기 함수 여부(`isAsyncFunction`)를 확인할 때 씁니다.

## util.format

`util.format(format, ...args)`는 `printf` 스타일로 문자열을 만듭니다. `console.log`의 첫 인수 처리도 같은 규칙입니다.

```js
import { format } from 'node:util'

format('%s는 %d살', 'kim', '20')   // 'kim는 20살'
format('%j', { a: 1 })              // '{"a":1}'
format('%s:%s', 'foo')              // 'foo:%s'
format('a', 'b', { x: 1 })          // 'a b { x: 1 }'
```

| 지정자 | 변환 |
|--------|------|
| `%s` | 문자열. `toString`이 없는 객체는 `inspect`(depth 0) |
| `%d` | `Number`로 변환 |
| `%i` | `parseInt(값, 10)` |
| `%f` | `parseFloat(값)` |
| `%j` | JSON. 순환 참조는 `'[Circular]'` |
| `%o` | 객체. 열거 불가 프로퍼티·프록시까지 표시 |
| `%O` | 객체. 기본 `inspect` |
| `%c` | CSS. 무시되고 인수만 소모 |
| `%%` | 퍼센트 문자 하나. 인수를 소모하지 않음 |

- 지정자에 대응하는 인수가 없으면 치환하지 않고 그대로 둡니다.
- 지정자보다 인수가 많으면 남은 인수는 공백으로 이어 붙이고, 문자열이 아닌 값은 `inspect`로 바꿉니다.
- 첫 인수에 지정자가 없으면 모든 인수를 공백으로 이어 붙입니다(v12.0.0부터).

## inspect

`util.inspect(object, options)`는 객체를 사람이 읽을 문자열로 만듭니다. `console.log`가 객체를 출력할 때 쓰는 함수입니다.

```js
import { inspect } from 'node:util'

const o = { a: { b: { c: { d: 1 } } } }
inspect(o)          // '{ a: { b: { c: [Object] } } }'
inspect(o, { depth: null })    // 끝까지 펼침
inspect(o, { depth: 0 })       // '{ a: [Object] }'
```

주요 옵션입니다.

| 옵션 | 기본값 | 설명 |
|------|--------|------|
| `depth` | 2 | 재귀 깊이. `null`은 무제한 |
| `colors` | false | ANSI 색 적용 |
| `maxArrayLength` | 100 | 배열·Set·Map의 표시 개수 |
| `breakLength` | 80 | 줄을 나누는 폭 |
| `compact` | 3 | 안쪽 요소를 한 줄로 합치는 정도. `false`는 키마다 줄바꿈 |
| `showHidden` | false | 열거 불가 프로퍼티 표시 |

- `util.inspect.custom` 심벌 메서드를 객체에 두면 출력 형태를 바꿀 수 있습니다. 비밀 값 가리기에 씁니다.

```js
class Token {
  constructor(v) { this.v = v }
  [inspect.custom]() { return 'Token<***>' }
}
console.log(new Token('s3cr3t')) // Token<***>
```

- 한 줄로 길게 나온 로그가 `[Object]`로 잘려 보일 때는 `depth`를 올립니다. 로그용으로 `JSON.stringify`를 쓰면 순환 참조에서 에러가 나지만 `inspect`는 `[Circular]`로 표시합니다.
- `inspect` 결과는 디버깅용 출력입니다. 파싱하거나 저장 형식으로 쓰지 않습니다.

## util.parseEnv

`util.parseEnv(content)`는 `.env` 형식의 문자열을 객체로 파싱합니다. 파일을 읽거나 `process.env`를 바꾸지 않습니다. v21.7.0, v20.12.0에 추가되었고 v24.10.0부터 실험 단계를 벗어났습니다.

```js
import { parseEnv } from 'node:util'

parseEnv('A=1\nB="two words"\n# memo\nA=9')
// { A: '9', B: 'two words' }
```

- 같은 키가 반복되면 뒤의 값이 이깁니다. 주석 줄(`#`)은 무시되고 값은 모두 문자열입니다.
- 파일을 읽어 `process.env`에 넣는 기능은 `--env-file` 옵션과 `process.loadEnvFile()`가 맡습니다(자세히는 25편).

## querystring

`node:querystring`은 URL 쿼리 문자열을 파싱·직렬화하는 모듈입니다. 구분자(`&`, `=`)를 바꿀 수 있어서 쿼리 문자열 외 형식에도 쓸 수 있습니다.

```js
import { parse, stringify } from 'node:querystring'

parse('a=1&a=2&b=x')
// [Object: null prototype] { a: ['1', '2'], b: 'x' }
stringify({ a: [1, 2], b: 'x y' })  // 'a=1&a=2&b=x%20y'
```

- 공식 문서는 `querystring`이 `URLSearchParams`보다 빠르지만 표준 API가 아니라고 설명하고, 성능이 중요하지 않거나 브라우저 코드와 호환이 필요하면 `URLSearchParams`를 쓰라고 안내합니다. 이 편이 `querystring`을 레거시로 부르는 근거는 이 안내입니다.
- 공식 문서의 안정성 지수는 2(Stable)이고 사용 중단(deprecated)은 아닙니다. 기존 코드에서 만날 수 있지만 새 코드에서는 `URLSearchParams`가 기본입니다.
- `parse()`의 결과는 `Object.prototype`을 상속하지 않는 객체라서 `obj.hasOwnProperty`나 `obj.toString` 같은 메서드가 없습니다.
- 같은 키가 반복되면 값이 배열이 됩니다. 키가 하나뿐이면 문자열이라서 타입이 달라지는 점을 처리해야 합니다.
- 기본으로 최대 1000개의 키까지만 파싱합니다(`maxKeys`).

## URLSearchParams

`URLSearchParams`는 쿼리 문자열을 다루는 WHATWG 표준 클래스입니다. 전역에 있어서 `import`가 필요 없고 브라우저와 같은 API입니다.

```js
const sp = new URLSearchParams({ q: '한 글', page: '2' })
sp.append('tag', 'a')
sp.append('tag', 'b')
sp.toString()
// 'q=%ED%95%9C+%EA%B8%80&page=2&tag=a&tag=b'
```

| 메서드 | 동작 |
|--------|------|
| `get(name)` | 첫 값. 없으면 `null` |
| `getAll(name)` | 값의 배열 |
| `has(name[, value])` | 존재 여부. `value` 인수는 v20.2.0부터 |
| `append(name, value)` | 값 추가. 같은 키가 여러 개 가능 |
| `set(name, value)` | 같은 키를 모두 지우고 하나로 설정 |
| `delete(name[, value])` | 삭제. `value` 인수는 v20.2.0부터 |
| `sort()` | 키 기준 안정 정렬 |
| `size` | 항목 수(v19.8.0부터) |

- 생성자는 문자열(앞의 `?`는 무시), 객체, 이터러블(쌍의 배열), 다른 `URLSearchParams`를 받습니다.
- 공백을 `+`로 인코딩하고 한글 등은 퍼센트 인코딩합니다. `URL`의 `searchParams` 속성으로도 얻습니다(자세히는 5편).
- 반복하면 `[키, 값]` 쌍을 돌려줍니다. `Object.fromEntries(sp)`는 같은 키 중 마지막 값만 남깁니다. 중복 키를 보존하려면 `getAll`을 씁니다.
- 모든 값은 문자열입니다. 숫자는 `Number(sp.get('page'))`로 변환하고 검증합니다.

## readline

`node:readline`은 읽기 스트림(주로 `process.stdin`이나 파일 스트림)에서 한 줄씩 읽는 모듈입니다. 안정성 지수는 2(Stable)입니다. `readline.createInterface()`로 인터페이스를 만듭니다.

```js
import { createInterface } from 'node:readline'
import { createReadStream } from 'node:fs'

const rl = createInterface({
  input: createReadStream('input.txt'),
  crlfDelay: Infinity,
})
for await (const line of rl) console.log(line)
```

- `'line'` 이벤트는 줄 끝(`\n`, `\r`, `\r\n`)마다 발생합니다. 마지막에 줄바꿈이 없어도 입력이 끝나면 한 번 더 발생합니다. `rl.close()`를 호출하거나 입력 스트림이 끝나면 `'close'`가 발생합니다.
- `for await...of`로 줄을 순회할 수 있습니다. 공식 문서는 `'line'` 이벤트보다 느리다고 알려 줍니다. `break`하면 `rl.close()`가 호출되어 입력을 끝까지 소비한 것으로 취급됩니다.
- `crlfDelay: Infinity`를 주면 `\r\n`을 항상 줄바꿈 하나로 처리합니다. 기본값은 100ms이고 Windows에서 만든 파일을 읽을 때 쓰는 옵션입니다.
- 큰 파일을 한 줄씩 처리할 때 파일 전체를 메모리에 올리지 않아도 됩니다(스트림은 1편, 2편).
- `createInterface()`를 호출하면 바로 입력을 읽기 시작합니다. 만들고 `for await`에 들어가기 전에 비동기 작업(`await`)을 끼우면 그 사이 도착한 줄을 놓칠 수 있습니다.
- 콜백 API의 `rl.question(query, callback)`은 질문 출력 후 한 줄 입력을 받습니다. 인터페이스가 입력을 잡고 있어서 `rl.close()`를 호출하지 않으면 프로세스가 끝나지 않습니다.
- 대화형 CLI, 로그 파일 줄 단위 처리, 파이프 입력(`cat data | node app.js`) 처리에 씁니다.

## readline/promises

`node:readline/promises`는 `readline`의 Promise 버전입니다. v17.0.0에 추가되었고 v24.0.0에서 안정(Stable) 상태가 되었습니다.

```js
import { createInterface } from 'node:readline/promises'
import { stdin, stdout } from 'node:process'

const rl = createInterface({ input: stdin, output: stdout })
const name = await rl.question('이름? ')
console.log(`안녕 ${name}`)
rl.close()
```

- `rl.question(query[, options])`는 Promise를 반환하고 사용자가 입력한 줄로 이행합니다. `{ signal }` 옵션으로 `AbortSignal`을 줘서 취소하거나 시간제한(`AbortSignal.timeout(10_000)`)을 걸 수 있습니다.
- `rl.close()` 뒤에 `question`을 호출하면 거부(reject)된 Promise가 돌아옵니다.
- 끝난 입력(파이프로 줄을 다 읽은 뒤)에 `question`을 또 호출하면 Promise가 이행되지도 거부되지도 않을 수 있습니다. 이 환경(v24.15.0)에서 `printf 'x\n' | node app.mjs`로 질문을 두 번 하자 두 번째 `await`가 끝나지 않아 "unsettled top-level await" 경고와 함께 종료 코드 13으로 끝났습니다. 비대화형 입력은 `for await`로 줄을 읽습니다.
- 한 번에 한 질문을 `await`하는 흐름에 알맞고, 여러 줄을 연속으로 읽는 용도에는 `for await`가 낫습니다.

## zlib

`node:zlib`은 gzip, deflate, Brotli, Zstd로 데이터를 압축·해제하는 모듈입니다. 안정성 지수는 2(Stable)입니다(Zstd는 따로 실험 단계, 아래).

방식이 세 가지입니다.

| 방식 | 예 | 용도 |
|------|----|------|
| 콜백 | `gzip(buf, cb)` | 작은 데이터, 비동기 |
| 동기 | `gzipSync(buf)` | 스크립트, 시작 시 한 번 |
| 스트림 | `createGzip()` | 큰 데이터, 파일, HTTP 본문 |

- 동기가 아닌 모든 `zlib` API는 libuv 스레드 풀에서 실행됩니다. 공식 문서는 압축 객체를 동시에 많이(예: 3만 개) 만들면 메모리 단편화가 크게 생길 수 있다고 경고합니다. 요청마다 무제한으로 만들지 않습니다.
- 동기 함수(`Sync`)는 이벤트 루프를 막으므로 요청 처리 중에는 쓰지 않습니다.
- 압축 해제 입력이 신뢰할 수 없는 데이터라면 `maxOutputLength` 옵션으로 결과 크기 상한을 둡니다(편의 메서드 대상). 한도를 넘으면 `ERR_BUFFER_TOO_LARGE`가 납니다. 작은 입력이 아주 큰 출력으로 풀리는 압축 폭탄(zip bomb)을 막기 위해서입니다.
- 압축 수준은 `level` 옵션으로 정합니다. 높을수록 작아지지만 느립니다.

## gzip

gzip은 가장 널리 쓰이는 압축 형식이며 HTTP의 `Content-Encoding: gzip`과 `.gz` 파일이 이 형식입니다. 해제는 `gunzip`입니다.

```js
import { gzipSync, gunzipSync } from 'node:zlib'

const zipped = gzipSync('hello '.repeat(100))
zipped.length                       // 32 (원본 600바이트)
gunzipSync(zipped).toString().length // 600
zipped[0].toString(16)  // '1f' (매직 넘버 1f 8b)
```

파일은 스트림으로 `pipeline`에 연결해 압축합니다(자세히는 2편).

```js
import * as fs from 'node:fs'
import * as zlib from 'node:zlib'
import { pipeline } from 'node:stream/promises'

await pipeline(
  fs.createReadStream('app.log'),
  zlib.createGzip(),
  fs.createWriteStream('app.log.gz'),
)
```

- 해제는 `createGunzip()`을 `pipeline`의 가운데에 둡니다.
- gzip이 아닌 데이터를 `gunzip`하면 `Z_DATA_ERROR` 에러가 납니다. gzip 데이터는 앞 두 바이트가 `1f 8b`입니다.
- 이미 압축된 형식(이미지 JPEG·PNG, mp4, zip)을 다시 압축해도 크기가 거의 줄지 않아 낭비입니다. 텍스트·JSON·로그에 효과가 큽니다.
- `deflate`(zlib 형식)와 `deflateRaw`는 헤더가 다른 형제 형식이고, `createUnzip()`은 gzip과 deflate를 자동 판별합니다.

### brotli와 zstd

Brotli와 Zstd는 gzip과 같은 모양의 API를 가진 압축 형식입니다.

| 형식 | 함수 | 안정성 | HTTP 헤더 값 |
|------|------|--------|--------------|
| Brotli | `brotliCompress`, `createBrotliCompress` | Stable | `br` |
| Zstd | `zstdCompress`, `createZstdCompress` | 1 - Experimental | `zstd` |

```js
import zlib from 'node:zlib'

const src = 'hello '.repeat(100)   // 600바이트
const br = zlib.brotliCompressSync(src)
br.length   // 21 (같은 입력의 gzip은 32)
zlib.brotliDecompressSync(br).length // 600
```

- Brotli의 옵션은 `params` 객체에 `zlib.constants.BROTLI_PARAM_QUALITY` 같은 상수 키로 줍니다. 공식 문서는 zlib의 `level`이 이 `BROTLI_PARAM_QUALITY`에 해당한다고 설명합니다.
- Zstd는 v23.8.0과 v22.15.0에 추가되었고, 이 편이 확인한 v24 문서와 v26 문서 모두에서 안정성 지수가 1(Experimental)입니다. 서비스 코드에서 쓰기 전에 사용 중인 버전의 문서를 확인합니다.
- 브라우저가 지원하는 방식은 요청의 `Accept-Encoding` 헤더에 나옵니다. 서버는 그중 하나를 골라 `Content-Encoding`에 적고 해당 압축 스트림을 응답에 연결합니다.
## assert

`node:assert`는 조건이 참인지 검증하고 아니면 `AssertionError`를 던지는 모듈입니다. 테스트와 스크립트의 불변 조건 검사에 씁니다.

```js
import assert from 'node:assert'

assert.ok(user)                       // 참 같은 값
assert.strictEqual(1 + 1, 2)          // ===
assert.deepStrictEqual({ a: 1 }, { a: 1 })
assert.throws(() => JSON.parse('{'), SyntaxError)
await assert.rejects(Promise.reject(new Error('x')), /x/)
```

| 함수 | 검증 |
|------|------|
| `ok(value)` | 참 같은 값 |
| `strictEqual(a, b)` | `Object.is` 방식의 동일 |
| `deepStrictEqual(a, b)` | 구조와 값, 프로토타입까지 같음 |
| `partialDeepStrictEqual(a, b)` | `b`가 `a`의 부분집합 |
| `throws(fn, expected)` | 동기 함수가 던짐 |
| `rejects(promiseOrFn, expected)` | Promise가 거부됨. `await` 필수 |
| `match(str, regex)` | 정규식과 일치 |

- 두 번째 인수 `expected`에는 에러 생성자, 정규식, 속성을 가진 객체(`{ name, message }`)를 줄 수 있습니다.
- `partialDeepStrictEqual`은 v23.4.0, v22.13.0에 추가되었고 v24.0.0에서 안정 상태가 되었습니다.
- `assert.rejects`에 `await`을 빼면 실패가 보고되지 않고 지나갑니다.
- 마지막 인수 `message`에 문자열이나 `Error`를 주면 실패 메시지를 바꿉니다.

레거시 모드의 함수(`equal`, `deepEqual`, `notEqual`, `notDeepEqual`)는 `==` 비교를 쓰며, 공식 문서는 이들을 Legacy로 분류하고 `strictEqual`·`deepStrictEqual` 등을 쓰라고 안내합니다.

```js
assert.equal(1, '1')          // 통과 (== 비교)
assert.strictEqual(1, '1')    // AssertionError
```

## assert/strict

`node:assert/strict`는 엄격 모드(strict assertion mode)의 `assert`입니다. 비엄격 이름의 함수가 엄격 버전처럼 동작합니다. `assert.equal`이 `strictEqual`처럼, `assert.deepEqual`이 `deepStrictEqual`처럼 비교합니다.

```js
import assert from 'node:assert/strict'

assert.equal(1, '1')   // AssertionError (== 아님)
assert.deepEqual({ a: 1 }, { a: '1' }) // AssertionError
```

- 가져오는 방법은 세 가지이며 같은 결과입니다: `import assert from 'node:assert/strict'`, `import { strict as assert } from 'node:assert'`, `require('node:assert').strict`. `node:assert/strict`는 v15.0.0에 추가되었습니다.
- 엄격 모드는 객체 비교 실패 메시지에 diff(차이 표시)를 보여 줍니다. 레거시 모드는 객체를 잘라서 보여 줍니다. `NO_COLOR` 환경 변수로 색을 끕니다.
- 새 코드는 `node:assert/strict`로 시작해 `==` 비교가 섞이는 실수를 막습니다. 테스트 러너에서의 사용은 24편입니다.

## 핵심 정리

- `os`는 호출 시점의 시스템 값을 동기로 돌려줍니다. 병렬도는 `availableParallelism()`, 줄바꿈은 플랫폼별 `os.EOL`, 임시 경로는 `tmpdir()`이며 메모리 값은 머신 전체입니다.
- `util`은 콜백 API를 Promise로(`promisify`), 객체를 문자열로(`format`, `inspect`), `.env` 문자열을 객체로(`parseEnv`) 바꿉니다. `util.types`는 내장 객체 종류 검사용입니다.
- 쿼리 문자열은 표준인 전역 `URLSearchParams`를 쓰고, `querystring`은 표준이 아닌 기존 모듈로 읽을 줄만 알면 됩니다.
- `readline`은 스트림을 한 줄씩 읽고 `readline/promises`의 `rl.question()`은 Promise를 반환하며, 끝난 입력에 질문하면 영영 끝나지 않을 수 있습니다.
- `zlib`은 gzip, Brotli(Stable), Zstd(Experimental)를 콜백·동기·스트림으로 제공하고, 큰 데이터는 `pipeline`으로 압축하며 신뢰할 수 없는 입력에는 `maxOutputLength`를 둡니다.
- `assert/strict`는 `equal`과 `deepEqual`을 엄격 비교로 바꾸므로 새 코드의 기본입니다.
