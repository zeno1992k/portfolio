## EventEmitter

EventEmitter는 이름 붙은 이벤트를 발생시키고, 그 이벤트에 등록된 함수(리스너)를 호출하는 클래스입니다. `node:events` 모듈이 내보내며 안정성 지수는 Stable(2)입니다. 스트림, 서버, 소켓 같은 Node.js 핵심 객체 다수가 이 클래스를 상속합니다.

```js
import { EventEmitter } from 'node:events'

const emitter = new EventEmitter()
emitter.on('greet', (name) => console.log(`hi ${name}`))
emitter.emit('greet', 'Kim') // hi Kim
```

- 리스너를 등록하는 쪽은 `on`, 이벤트를 일으키는 쪽은 `emit`을 호출합니다.
- 리스너가 반환한 값은 버려집니다.
- 직접 쓰는 클래스에 이벤트 기능을 붙일 때는 `extends EventEmitter`로 상속합니다(아래 "커스텀 이벤트 설계").
- 이벤트 이름 `'newListener'`와 `'removeListener'`는 리스너가 추가되기 전과 제거된 뒤에 EventEmitter가 스스로 발생시킵니다.

## on

`emitter.on(eventName, listener)`는 리스너를 해당 이벤트의 목록 맨 끝에 추가합니다. `addListener`는 같은 메서드의 별칭입니다(v0.1.101부터).

```js
const e = new EventEmitter()
const f = () => console.log('f')
console.log(e.on('x', f) === e) // true (체이닝용으로 자신을 반환)
e.on('x', f)                    // 같은 함수를 또 등록
e.emit('x')                     // f
                                // f
```

- 같은 함수를 같은 이벤트에 두 번 등록해도 중복 검사를 하지 않습니다. 등록한 횟수만큼 호출됩니다.
- 반환값이 자기 자신이므로 `e.on('a', fa).on('b', fb)`처럼 이어 쓸 수 있습니다.

**흔한 실수:** 같은 `on` 호출이 반복 실행되는 코드(요청 처리 함수 안 등)에 두는 것입니다. 호출마다 리스너가 하나씩 쌓입니다(아래 "메모리 누수 경고").

## once

`emitter.once(eventName, listener)`는 최대 한 번만 호출되는 리스너를 등록합니다. 이벤트가 발생하면 먼저 목록에서 제거한 뒤 호출합니다.

```js
e.once('ready', () => console.log('ready'))
e.emit('ready') // ready
e.emit('ready') // (아무 일도 없음)
```

- 호출 전에 제거되므로, 리스너 안에서 같은 이벤트를 다시 `emit`해도 재귀하지 않습니다.
- `listeners()`는 원래 함수를 돌려주고, `rawListeners()`는 `once`가 감싼 래퍼 함수를 돌려줍니다.
- `once`로 등록한 리스너도 `off(eventName, 원래함수)`로 호출 전에 제거할 수 있습니다.
- 앞쪽에 넣는 `prependOnceListener`도 있습니다.

## emit

`emitter.emit(eventName, ...args)`는 해당 이벤트의 리스너를 등록한 순서대로 호출하고, 리스너가 하나라도 있었으면 `true`, 없었으면 `false`를 반환합니다.

```js
const e = new EventEmitter()
console.log(e.emit('x')) // false (리스너 없음)
e.on('x', () => {})
console.log(e.emit('x')) // true
```

- 리스너가 없는 이벤트를 `emit`해도 에러가 아닙니다. 단 이름이 `'error'`이면 예외입니다(아래 "error 이벤트를 안 들으면 죽음").
- 호출 중에 리스너가 추가되거나 제거되어도 진행 중인 `emit`은 시작 시점의 목록을 끝까지 호출합니다. 변경은 다음 `emit`부터 반영됩니다.

```js
const B = () => console.log('B')
e.on('e', () => { console.log('A'); e.off('e', B) })
e.on('e', B)
e.emit('e') // A, B (이번에는 B도 호출됨)
e.emit('e') // A
```

## off와 removeListener

`emitter.off(eventName, listener)`는 리스너를 제거합니다. `removeListener`와 같은 메서드이고 `off`는 v10.0.0에서 별칭으로 추가되었습니다.

```js
const onData = (x) => console.log(x)
e.on('data', onData)
e.off('data', onData) // 제거됨
e.on('data', () => {})
e.off('data', () => {}) // ❌ 다른 함수 객체라서 제거되지 않음
```

- 제거는 함수의 참조가 같아야 성립합니다. 인라인 화살표 함수는 나중에 제거할 수 없으므로 변수나 상수에 담아 둡니다.
- 한 번 호출에 하나만 제거합니다. 같은 함수가 두 번 등록되어 있으면 `off`도 두 번 불러야 합니다. 이때 가장 최근에 추가된 것이 먼저 제거됩니다.
- 제거하려는 리스너가 없으면 아무 일도 일어나지 않습니다.
- 리스너를 제거한 뒤 `'removeListener'` 이벤트가 발생합니다.

## removeAllListeners

`emitter.removeAllListeners([eventName])`는 지정한 이벤트의 모든 리스너를 제거합니다. 이름을 생략하면 그 emitter의 모든 이벤트에서 모든 리스너를 제거합니다.

```js
e.on('a', () => {})
e.on('b', () => {})
e.removeAllListeners('a')
console.log(e.eventNames()) // [ 'b' ]
e.removeAllListeners()
console.log(e.eventNames()) // []
```

- 다른 모듈이 만든 emitter(소켓, 스트림 등)에 쓰면 그 모듈이 등록한 내부 리스너까지 지워 버립니다. 공식 문서도 이를 나쁜 습관으로 규정합니다. 자기가 등록한 리스너만 `off`로 제거합니다.
- 남은 개수는 `listenerCount(eventName)`, 등록된 이름은 `eventNames()`로 확인합니다.

## prependListener

`emitter.prependListener(eventName, listener)`는 리스너를 목록의 맨 앞에 추가합니다(v6.0.0). 기본은 등록한 순서대로 호출되지만 이 메서드로 선두에 끼워 넣을 수 있습니다.

```js
e.on('foo', () => console.log('a'))
e.prependListener('foo', () => console.log('b'))
e.emit('foo')
// b
// a
```

- 중복 검사를 하지 않는 점은 `on`과 같습니다.
- 한 번만 호출하는 앞쪽 리스너는 `prependOnceListener`입니다.
- 앞쪽으로 끼워 넣는 일은 검증·로깅처럼 다른 리스너보다 먼저 실행되어야 할 때만 씁니다. 호출 순서에 의존하는 설계는 읽기 어렵습니다.

## 동기 호출이라는 점

`emit`은 리스너를 즉시, 동기적으로, 등록 순서대로 실행하고 모두 끝난 뒤에 반환합니다. 큐에 넣거나 다음 틱으로 미루지 않습니다.

```js
e.on('z', () => console.log('A'))
console.log('before')
e.emit('z')
console.log('after')
// before
// A
// after
```

- 리스너가 오래 걸리면 `emit`을 호출한 쪽이 그만큼 멈춥니다. 이벤트 루프를 막는 코드의 규칙은 04편과 같습니다.
- 리스너가 예외를 던지면 `emit` 호출 지점까지 예외가 전파되고, 같은 이벤트의 남은 리스너는 호출되지 않습니다.
- 비동기로 처리하고 싶은 리스너는 안에서 `setImmediate`나 `process.nextTick`으로 작업을 넘깁니다.
- 리스너가 `async` 함수이면 `emit`은 그 Promise를 기다리지 않고 지나갑니다. 거부된 Promise는 처리되지 않은 거부가 됩니다(아래 "captureRejections").

**흔한 실수:** 생성자 안에서 `this.emit('ready')`를 호출하는 것입니다. 생성자가 끝나기 전이라 호출하는 쪽이 아직 `on`을 등록하지 못해서 이벤트가 사라집니다. 비동기로 미뤄야 합니다.

```js
class Job extends EventEmitter {
  constructor() {
    super()
    this.emit('a') // ❌ 리스너가 없어 사라짐
    process.nextTick(() => this.emit('b')) // ✅
  }
}
```

## error 이벤트를 안 들으면 죽음

이름이 `'error'`인 이벤트는 특별 취급됩니다. 리스너가 하나도 없는 상태에서 `emit('error', err)`가 호출되면 `err`가 던져지고 처리되지 않은 예외로 프로세스가 종료됩니다.

```js
const e = new EventEmitter()
e.emit('error', new Error('boom')) // throw → 프로세스 종료

e.on('error', (err) => console.error(err.message))
e.emit('error', new Error('boom')) // boom (종료되지 않음)
```

- 인수가 `Error`가 아니면 `ERR_UNHANDLED_ERROR` 코드의 Error를 던집니다. 예를 들어 `emit('error', 'str')`은 메시지가 `Unhandled error. ('str')`인 Error가 됩니다. 인수를 생략해도 마찬가지입니다.
- 이벤트를 발생시키는 emitter(소켓, 스트림, 직접 만든 클래스)에는 항상 `'error'` 리스너를 붙입니다. 이것이 공식 문서의 권장입니다.
- 에러를 소비하지 않고 관찰만 하려면 `events.errorMonitor` 심벌(v13.6.0)로 리스너를 등록합니다. 일반 `'error'` 리스너보다 먼저 호출되고, 일반 리스너가 없으면 여전히 프로세스가 종료됩니다.

```js
import { EventEmitter, errorMonitor } from 'node:events'

const e = new EventEmitter()
e.on(errorMonitor, (err) => report(err)) // 관찰만 함
e.emit('error', new Error('x')) // 일반 리스너가 없어 여전히 throw
```

- 공식 문서는 `'error'` 핸들러를 `async` 함수로 만들지 말라고 권장합니다(아래 "captureRejections").

## 최대 리스너

한 emitter의 한 이벤트에 리스너가 11개 이상 쌓이면 경고가 출력됩니다. 기본 최대치는 10입니다. 하드 한계가 아니라 경고 기준이라서 리스너는 계속 추가되고 동작도 막히지 않습니다.

| 설정 | 범위 |
|------|------|
| `emitter.setMaxListeners(n)` | 그 emitter 하나 |
| `events.defaultMaxListeners` | 모든 emitter의 기본값 |
| `events.setMaxListeners(n, ...targets)` | 지정한 emitter·EventTarget, 대상을 생략하면 새로 만드는 모두의 기본값 |

```js
const e = new EventEmitter()
console.log(e.getMaxListeners()) // 10
e.setMaxListeners(20)
e.setMaxListeners(0)             // 0 또는 Infinity는 무제한
```

- `emitter.setMaxListeners(n)`이 `defaultMaxListeners`보다 우선합니다.
- `defaultMaxListeners`에 양수가 아닌 값을 넣으면 `RangeError`입니다. 이미 만든 emitter에도 영향을 주므로 조심해서 바꿉니다.
- `AbortSignal`은 기본으로 경고하지 않습니다.
- 정당한 이유로 리스너가 많은 경우(여러 소비자가 하나의 emitter를 구독)에만 값을 올립니다. 경고를 끄려고 0으로 두면 진짜 누수도 가려집니다.

## 메모리 누수 경고

최대 리스너를 넘으면 `MaxListenersExceededWarning`이 stderr에 출력됩니다. 리스너를 등록만 하고 해제하지 않는 누수의 신호입니다.

```text
MaxListenersExceededWarning: Possible EventEmitter memory
leak detected. 11 data listeners added to [EventEmitter].
MaxListeners is 10. Use emitter.setMaxListeners() ...
```

- 경고는 이벤트 이름마다 한 번만 출력됩니다. 12번째, 13번째 추가에는 다시 나오지 않습니다.
- 경고 위치를 알고 싶으면 `node --trace-warnings`로 스택을 봅니다.
- 코드에서는 `process.on('warning', (w) => ...)`로 받습니다. `w.name`은 `'MaxListenersExceededWarning'`이고 `w.emitter`, `w.type`, `w.count`가 붙습니다.
- 대부분의 원인은 오래 사는 emitter(싱글턴, 서버)에 수명이 짧은 코드가 리스너를 등록하고 해제하지 않는 것입니다. 리스너가 클로저로 잡고 있는 객체도 함께 해제되지 않습니다.

```js
// ❌ 호출될 때마다 리스너가 하나씩 늘어남
function handle(req) {
  bus.on('update', (data) => req.send(data))
}
// ✅ 한 번만 받거나, 끝나면 직접 제거
function handle2(req) {
  const send = (data) => req.send(data)
  bus.on('update', send)
  req.onClose(() => bus.off('update', send))
}
```

## 이벤트 이름

이벤트 이름은 문자열 또는 심벌입니다. 공식 문서는 일반적으로 camelCase 문자열을 쓰고 유효한 프로퍼티 키면 무엇이든 가능하다고 설명합니다.

```js
const kDone = Symbol('done')
e.on('dataReady', () => {})
e.on(kDone, () => {})
console.log(e.eventNames()) // [ 'dataReady', Symbol(done) ]
```

- 이름은 대소문자를 구분합니다. `'Data'`와 `'data'`는 다른 이벤트입니다.
- 숫자도 쓸 수 있지만 프로퍼티 키로 변환됩니다. `on(1, f)`로 등록하면 `emit('1')`로도 호출됩니다.
- 오타가 나도 에러가 나지 않고 리스너가 호출되지 않을 뿐입니다. 이름을 상수로 모으면 줄일 수 있습니다.
- 모듈 밖에 노출하고 싶지 않은 내부 이벤트에는 심벌을 쓰면 외부 코드와 충돌하지 않습니다.
- `'error'`, `'newListener'`, `'removeListener'`는 EventEmitter가 의미를 부여한 이름이라서 다른 용도로 쓰지 않습니다.

## 인자 전달

`emit`의 두 번째 인수부터가 그대로 리스너의 인수로 전달됩니다. 개수 제한이 없고, 리스너는 앞에서부터 필요한 만큼만 받으면 됩니다.

```js
e.on('evt', (a, b) => console.log(a, b))
e.on('evt', (...args) => console.log(args))
e.emit('evt', 1, 2, 3)
// 1 2
// [ 1, 2, 3 ]
```

- 이벤트마다 인수의 개수·순서·타입이 정해져 있지 않아서, 계약을 문서나 타입으로 따로 정해야 합니다.
- 같은 객체가 모든 리스너에게 전달됩니다. 한 리스너가 객체를 바꾸면 뒤의 리스너에게 영향을 줍니다.
- `events.once`의 Promise는 인수 전체를 배열로 받습니다(아래 "events.once와 events.on").

## this 바인딩

일반 함수 리스너가 호출될 때 `this`는 이벤트를 발생시킨 emitter 인스턴스입니다(공식 문서가 의도된 동작이라고 명시합니다). 화살표 함수는 자기 `this`가 없어서 바깥 스코프의 `this`를 씁니다.

```js
const e = new EventEmitter()
e.on('a', function () { console.log(this === e) })
e.on('a', () => console.log(this === e))
e.emit('a')
// true
// false (ESM 최상위의 this는 undefined)
```

- 클래스 안에서 메서드를 그대로 리스너로 넘기면 `this`가 클래스 인스턴스가 아니라 emitter가 됩니다. 같은 객체가 emitter 자신이면 우연히 맞지만 다른 객체의 메서드이면 어긋납니다.

```js
class Logger {
  constructor(bus) {
    this.prefix = '[app]'
    bus.on('log', this.print)              // ❌ this는 bus
    bus.on('log', (m) => this.print(m))    // ✅
    bus.on('log', this.print.bind(this))   // ✅
  }
  print(m) { console.log(this.prefix, m) }
}
```

- 리스너에서 emitter가 필요하면 `this`보다 바깥 변수를 참조하는 편이 읽기 쉽습니다.

## 커스텀 이벤트 설계

직접 이벤트를 내는 클래스는 `EventEmitter`를 상속하고, 상태가 바뀐 뒤에 이벤트를 발생시킵니다. 이벤트 이름과 인수가 그 클래스의 공개 계약입니다.

```js
class Downloader extends EventEmitter {
  start(url) {
    this.emit('progress', { url, percent: 50 })
    this.emit('done', { url, size: 1024 })
  }
}
const d = new Downloader()
d.on('progress', ({ percent }) => console.log(percent))
d.on('error', (err) => console.error(err.message))
d.start('a.txt') // 50
```

설계 기준은 다음과 같습니다.

- 이벤트 이름은 일어난 일을 알리는 과거형이나 상태 이름으로 짓습니다(`done`, `progress`, `closed`). 명령처럼 짓지 않습니다.
- 인수가 둘 이상이면 객체 하나로 묶습니다. 필드를 추가해도 기존 리스너가 깨지지 않습니다.
- 실패 가능성이 있는 클래스는 `'error'` 이벤트를 발생시키고, 사용 설명에 `'error'` 리스너가 필요하다고 적습니다.
- 이벤트를 한 번 발생시킨 뒤 구독하는 쪽이 놓치지 않으려면 생성 직후 `emit`하지 않고 `process.nextTick` 등으로 미룹니다(위 "동기 호출이라는 점").
- 한 번만 일어나는 일이면 이벤트보다 Promise가 맞습니다. 여러 번 반복되는 일에는 이벤트가 맞습니다(자세히는 23편).
- 상속 대신 EventEmitter 인스턴스를 필드로 갖고 필요한 메서드만 노출하는 방법도 있습니다. 상속하면 `emit`, `removeAllListeners` 같은 메서드가 모두 외부에 노출됩니다.

## EventTarget과 EventEmitter 차이

`EventTarget`은 웹 표준 이벤트 API의 Node.js 구현입니다. v14.5.0에 추가되었고 v15.0.0부터 전역 클래스이며 v15.4.0부터 실험 단계를 벗어났습니다. 브라우저와 같은 코드가 동작하며 `AbortSignal`도 `EventTarget`을 상속합니다.

| 항목 | EventEmitter | EventTarget |
|------|--------------|-------------|
| 출처 | Node.js 고유 | 웹 표준 |
| 등록 | `on`, `once`, `prependListener` | `addEventListener` |
| 해제 | `off`, `removeListener` | `removeEventListener` |
| 발생 | `emit(이름, ...인수)` | `dispatchEvent(Event 객체)` |
| 리스너의 인수 | 임의의 값 여러 개 | `Event` 객체 하나 |
| 같은 리스너 중복 등록 | 허용(여러 번 호출) | 무시(한 번만 등록) |
| `'error'` 이름 | 리스너가 없으면 프로세스 종료 | 특별 취급 없음 |
| 리스너의 예외 | `emit`으로 전파, 나머지 호출 안 됨 | 다른 리스너는 호출되고 예외는 처리되지 않은 예외가 됨 |
| `async` 리스너 거부 | 기본은 처리되지 않은 거부 | 동기 예외처럼 자동으로 잡힘 |
| 순서 | 등록 순, `prependListener`로 앞에 추가 가능 | 등록 순 |
| 옵션 | 없음 | `once`, `signal`, `capture`, `passive` |

```js
const t = new EventTarget()
t.addEventListener('ping', (e) => console.log(e.type))
t.dispatchEvent(new Event('ping')) // ping

t.addEventListener('d', (e) => console.log(e.detail))
t.dispatchEvent(new CustomEvent('d', { detail: { id: 1 } }))
// { id: 1 }
```

- DOM과 달리 계층과 전파가 없습니다. `bubbles`는 항상 `false`이고 `stopPropagation()`은 효과가 없습니다.
- 데이터를 실어 보내려면 `CustomEvent`를 만들고 `detail`에 담습니다. v23.0.0부터 실험 단계가 아닙니다.
- `EventTarget`에는 `on`, `emit`이 없습니다. 비슷한 인터페이스가 필요한 내부 구현체로 `NodeEventTarget`이 있지만 `EventEmitter`의 인스턴스는 아니고 `prependListener`, `rawListeners`, `errorMonitor` 등은 지원하지 않습니다.
- 서버 코드에서 새로 이벤트를 만들 때는 `EventEmitter`가 일반적입니다. 브라우저와 코드를 공유하거나 `AbortSignal`과 연동할 때 `EventTarget`을 씁니다.
- `EventTarget`의 리스너 목록과 개수는 `events.getEventListeners(target, name)`, `events.listenerCount(target, name)`로 확인합니다.

## events.once와 events.on

`events.once`와 `events.on`은 이벤트를 Promise와 비동기 이터레이터로 받는 함수입니다.

`events.once(emitter, name[, options])`는 이벤트가 발생하면 이행하는 Promise를 반환합니다(v11.13.0).

```js
import { once, EventEmitter } from 'node:events'

const e = new EventEmitter()
setTimeout(() => e.emit('ready', 42, 'x'), 10)
const args = await once(e, 'ready')
console.log(args) // [ 42, 'x' ] (인수 전체가 배열)
```

- 대기 중에 `'error'`가 발생하면 Promise가 그 에러로 거부됩니다. 단 `once(e, 'error')`처럼 `'error'` 자체를 기다릴 때는 일반 이벤트로 취급합니다.
- `signal` 옵션(v15.0.0)을 주면 대기를 취소할 수 있습니다. 취소되면 `AbortError`로 거부되고 등록했던 리스너는 제거됩니다.
- 여러 이벤트를 연속해서 `await once`하면 사이에 발생한 이벤트를 놓칠 수 있습니다. Promise 처리는 현재 실행이 끝난 뒤이기 때문입니다. 먼저 모든 Promise를 만들고 `Promise.all` 등으로 기다립니다(자세히는 24편).

`events.on(emitter, name[, options])`는 같은 이벤트가 반복되는 동안 값을 하나씩 꺼내는 비동기 이터레이터를 반환합니다(v13.6.0).

```js
import { on } from 'node:events'

const ac = new AbortController()
const { signal } = ac
setTimeout(() => ac.abort(), 100)
try {
  for await (const [msg] of on(e, 'msg', { signal })) {
    console.log(msg)
  }
} catch (err) {
  if (err.name !== 'AbortError') throw err
}
```

- 반복 값은 이벤트 인수의 배열입니다.
- 이벤트가 오지 않으면 `for await`는 영원히 대기합니다. 끝내려면 `signal`로 취소하거나 `close` 옵션(v20.0.0)에 끝내는 이벤트 이름 배열을 줍니다. 루프를 빠져나오면 등록한 리스너가 모두 제거됩니다.
- 대기 중에 `'error'`가 발생하면 루프가 그 에러를 던집니다.
- 루프 본문은 한 번에 하나의 이벤트만 처리합니다. 동시 처리가 필요한 곳에는 쓰지 않습니다.
- 안 읽힌 이벤트는 버퍼에 쌓입니다. `highWaterMark`, `lowWaterMark` 옵션은 `pause()`와 `resume()`을 가진 emitter에서만 동작합니다.

## captureRejections

`async` 함수를 리스너로 쓰면 그 안에서 던진 예외가 거부된 Promise가 되고, `emit`은 이를 기다리지 않아서 처리되지 않은 거부가 됩니다(처리되지 않은 거부의 기본 동작은 24편). EventEmitter의 `captureRejections` 옵션은 이를 `'error'` 이벤트로 돌립니다.

```js
const e = new EventEmitter({ captureRejections: true })
e.on('job', async () => { throw new Error('kaboom') })
e.on('error', (err) => console.log(err.message))
e.emit('job') // kaboom (비동기로 'error'에 전달됨)
```

- 옵션 이름은 `captureRejections`, 기본값은 `false`입니다(v13.4.0, v17.4.0부터 실험 단계 아님).
- `EventEmitter.captureRejections = true`로 새로 만드는 emitter의 기본값을 바꿀 수 있습니다.
- `Symbol.for('nodejs.rejection')` 메서드(또는 `events.captureRejectionSymbol`)를 정의하면 `'error'` 대신 그 메서드가 `(err, eventName, ...args)`로 호출됩니다.
- 이 경로로 전달되는 `'error'` 이벤트에는 거부 처리기가 붙지 않습니다. 무한 에러 루프를 막기 위해서이고, `'error'` 핸들러를 `async`로 만들지 말아야 하는 이유입니다.

## AbortSignal로 리스너 해제

`AbortSignal`을 쓰면 리스너 해제를 취소 신호 하나로 묶을 수 있습니다(AbortController의 자세한 설명은 22편). 이벤트 기반 API마다 방법이 다릅니다.

| 대상 | 방법 |
|------|------|
| `events.once`, `events.on` | `signal` 옵션 |
| `EventTarget` | `addEventListener`의 `signal` 옵션(v15.4.0) |
| `EventEmitter`의 `on`, `once` | `signal` 옵션 없음 |

`EventTarget`은 신호가 `abort()`되면 리스너를 자동으로 제거합니다.

```js
const t = new EventTarget()
const ac = new AbortController()
t.addEventListener('x', () => console.log('x'), {
  signal: ac.signal,
})
t.dispatchEvent(new Event('x')) // x
ac.abort()
t.dispatchEvent(new Event('x')) // (호출되지 않음)
```

`EventEmitter`에서는 신호의 `abort` 이벤트에 `off`를 연결합니다. `events.addAbortListener(signal, listener)`를 쓰면 됩니다(v20.5.0, v24.0.0에서 Stable).

```js
import { addAbortListener } from 'node:events'

const onData = (x) => console.log(x)
e.on('data', onData)
addAbortListener(ac.signal, () => e.off('data', onData))
ac.abort()
console.log(e.listenerCount('data')) // 0
```

- 신호의 `abort` 이벤트를 직접 `addEventListener`로 듣는 것은 안전하지 않습니다. 같은 신호를 가진 다른 코드가 `stopImmediatePropagation()`을 호출하면 리스너가 실행되지 않아서 누수가 생길 수 있습니다. `addAbortListener`는 이 호출의 영향을 받지 않습니다.
- `addAbortListener`는 정리용 `Disposable`을 반환하므로 `using` 선언과 함께 쓸 수 있습니다.
- 여러 emitter에 한꺼번에 붙인 리스너를 요청 단위로 정리해야 할 때 신호 하나로 묶으면 해제를 빠뜨리지 않습니다.

## 핵심 정리

- EventEmitter는 `on`으로 등록하고 `emit`으로 등록 순서대로 동기 호출하며, 리스너의 반환값은 버려지고 `emit`은 리스너 유무를 불리언으로 돌려줍니다.
- 일반 함수 리스너의 `this`는 emitter이고 화살표 함수는 바깥 `this`를 씁니다. 해제는 같은 함수 참조로 `off`를 호출해야 하며 인라인 함수는 제거할 수 없습니다.
- 리스너가 없는 `'error'` 이벤트는 던져져서 프로세스를 종료시키므로 emitter에는 항상 `'error'` 리스너를 붙입니다.
- 한 이벤트에 리스너가 10개를 넘으면 `MaxListenersExceededWarning`이 한 번 출력되며, 대개 해제하지 않는 누수의 신호입니다.
- EventTarget은 웹 표준 API로 중복 등록 무시, `Event` 객체 전달, `signal` 옵션, 계층 없음이 EventEmitter와 다릅니다.
- `events.once`와 `events.on`은 이벤트를 Promise·비동기 이터레이터로 받고 `signal`로 취소하며, `captureRejections`는 `async` 리스너의 거부를 `'error'`로 돌립니다.
