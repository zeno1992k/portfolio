## path 모듈

`node:path`는 파일과 디렉터리 경로 문자열을 다루는 내장 모듈입니다. 안정성 지수는 Stable(2)입니다.

```js
import path from 'node:path'
import { join, resolve } from 'node:path'

path.join('a', 'b') // 'a/b' (POSIX), 'a\\b' (Windows)
```

- 이 모듈의 함수는 문자열만 계산합니다. 파일이 실제로 있는지 확인하거나 파일 시스템을 읽지 않습니다. 예외는 `path.resolve`와 `path.relative`가 현재 작업 디렉터리(`process.cwd()`)를 읽는 것뿐입니다.
- 실행 중인 운영체제에 따라 동작이 달라집니다. Windows에서는 Windows 방식으로, 그 밖에서는 POSIX 방식으로 해석합니다(아래 "posix"와 "win32").
- 문자열이 아닌 인수를 주면 `TypeError`가 납니다. `path.join('a', 1)`은 `ERR_INVALID_ARG_TYPE`입니다.
- 이 편의 예제는 결과를 확정하려고 POSIX 방식을 기준으로 적고, Windows 결과는 따로 표시합니다.
- 파일 시스템을 읽고 쓰는 것은 16편 이후에서 다룹니다.

## path.join

`path.join(...조각)`은 조각들을 플랫폼의 구분자로 이어 붙인 뒤 정규화한 경로를 반환합니다.

```js
path.join('/foo', 'bar', 'baz/asdf', 'quux', '..')
// '/foo/bar/baz/asdf'
path.join('a', '', 'b')     // 'a/b' (빈 문자열은 무시)
path.join('')               // '.'
path.join('/a', '/b')       // '/a/b' (앞 조각을 버리지 않음)
path.join('a', '..', '..')  // '..'
```

- 빈 문자열 조각은 무시합니다. 결과가 빈 문자열이면 `'.'`을 반환합니다.
- 뒤 조각이 `/`로 시작해도 앞 조각을 버리지 않고 그냥 이어 붙입니다.
- 결과는 상대 경로일 수도 있습니다. 앞 조각 중 절대 경로가 없으면 절대 경로로 만들지 않습니다.
- 끝의 구분자는 유지됩니다. `path.join('/a/', '/b/')`는 `'/a/b/'`입니다.

**흔한 실수:** 구분자를 직접 이어 붙이는 것입니다. `dir + '/' + file`이나 템플릿 리터럴로 `/`를 직접 끼우는 방식은 한쪽 끝에 이미 `/`가 있으면 `//`가 되고 Windows에서는 구분자가 섞입니다. `path.join(dir, file)`을 씁니다.

## path.resolve

`path.resolve(...조각)`은 조각들을 절대 경로 하나로 만들어 반환합니다. 오른쪽 조각부터 왼쪽으로 보며 절대 경로가 만들어질 때까지 앞에 붙입니다. 끝까지 절대 경로가 안 되면 현재 작업 디렉터리를 앞에 붙입니다.

```js
path.resolve('/foo/bar', './baz')   // '/foo/bar/baz'
path.resolve('/foo/bar', '/tmp/file/') // '/tmp/file'
path.resolve('/a', '/b', 'c')       // '/b/c'
path.resolve('wwwroot', 'img')
// cwd가 /home/me면 '/home/me/wwwroot/img'
path.resolve()                      // cwd 자체
```

- 결과는 정규화되고 끝의 구분자는 루트가 아니면 제거됩니다.
- 빈 문자열 조각은 무시합니다. 조각이 하나도 없으면 현재 작업 디렉터리의 절대 경로를 반환합니다.
- 실행 위치(`process.cwd()`)에 따라 결과가 달라집니다. 작업 디렉터리는 `process.chdir`로 바뀔 수 있습니다(자세히는 05편).

## join과 resolve 차이

| 항목 | `path.join` | `path.resolve` |
|------|-------------|----------------|
| 결과 | 상대일 수도, 절대일 수도 있음 | 항상 절대 경로 |
| 절대 경로 조각을 만났을 때 | 그냥 이어 붙임 | 그 앞은 버리고 거기서 다시 시작 |
| 현재 작업 디렉터리 | 쓰지 않음 | 필요하면 앞에 붙임 |
| 끝의 구분자 | 유지 | 루트가 아니면 제거 |
| 빈 결과 | `'.'` | cwd |

```js
path.join('/a', '/b')    // '/a/b'
path.resolve('/a', '/b') // '/b'
path.join('a', 'b')      // 'a/b'
path.resolve('a', 'b')   // cwd + '/a/b'
```

- 사용자 입력을 기준 디렉터리 아래에 붙일 때 `path.resolve(base, input)`은 입력이 `/etc/passwd`처럼 절대 경로면 기준을 버립니다. `path.join(base, input)`은 `/srv/pub/etc/passwd`로 이어 붙이지만 입력의 `..`로는 기준 밖으로 나갈 수 있습니다(아래 "`..` 경로 탈출").
- 설정 파일이나 데이터 파일 위치처럼 코드 위치를 기준으로 하는 경로는 `path.join(import.meta.dirname, 'data', 'x.json')`처럼 쓰는 것이 흔합니다. `import.meta.dirname`은 07편에서 다룹니다.

## path.normalize

`path.normalize(경로)`는 `.`와 `..` 조각을 해석하고 연속된 구분자를 하나로 합칩니다.

```js
path.normalize('/a//b/../c/') // '/a/c/'
path.normalize('a/./b')       // 'a/b'
path.normalize('')            // '.'
path.normalize('../a/../../b') // '../../b'
```

- 끝의 구분자는 유지합니다. 빈 문자열은 `'.'`이 됩니다.
- 앞쪽에서 올라갈 곳이 없는 `..`는 상대 경로에서는 남깁니다.
- 파일 시스템을 확인하지 않고 문자열로만 계산합니다. 심볼릭 링크를 따라가지 않으므로 `..`를 지운 결과가 실제 시스템이 해석한 경로와 다를 수 있습니다(링크는 18편).
- `path.join`과 `path.resolve`는 내부에서 이 정규화를 합니다.

## path.relative

`path.relative(from, to)`는 `from`에서 `to`로 가는 상대 경로를 반환합니다. 두 인수를 각각 `path.resolve`로 절대 경로로 만든 뒤 비교합니다.

```js
path.relative('/data/a/x', '/data/b/y') // '../../b/y'
path.relative('/a/b', '/a')             // '..'
path.relative('/a', '/a/b/c')           // 'b/c'
path.relative('/a', '/a')               // ''
```

- 같은 경로면 빈 문자열을 반환합니다.
- 빈 문자열을 인수로 주면 현재 작업 디렉터리로 취급합니다.
- `to`가 `from`의 안쪽이면 `..`가 없는 경로를, 바깥이면 `..`로 시작하는 경로를 반환합니다. 이 성질이 "기준 안에 있는지" 검사에 쓰입니다.
- Windows에서 드라이브가 다르면 상대 경로를 만들 수 없어서 `to`의 절대 경로가 그대로 반환됩니다. `path.win32.relative('C:\\a', 'D:\\b')`는 `'D:\\b'`입니다.

## 경로 분해

### path.basename

경로의 마지막 조각(파일 이름)을 반환합니다. 끝의 구분자는 무시하고, 두 번째 인수로 접미사를 주면 그것을 뗍니다.

```js
path.basename('/a/b/c.txt')         // 'c.txt'
path.basename('/a/b/c.txt', '.txt') // 'c'
path.basename('/a/b/')              // 'b'
```

- 접미사 비교는 대소문자를 구분합니다. Windows가 파일 이름 대소문자를 구분하지 않더라도 `path.win32.basename('C:\\foo.HTML', '.html')`은 `'foo.HTML'`입니다.

### path.dirname

경로에서 마지막 조각을 뺀 디렉터리 부분을 반환합니다. 끝의 구분자는 무시합니다.

```js
path.dirname('/a/b/c.txt') // '/a/b'
path.dirname('/a')         // '/'
path.dirname('a')          // '.'
path.dirname('/')          // '/'
```

### path.extname

마지막 조각에서 마지막 `.`부터 끝까지를 확장자로 반환합니다.

```js
path.extname('a.tar.gz') // '.gz'
path.extname('a.')       // '.'
path.extname('a')        // ''
path.extname('.bashrc')  // ''
path.extname('.a.md')    // '.md'
```

- `.`이 없거나 조각의 첫 글자 `.`뿐이면 빈 문자열입니다.
- 마지막 점만 보므로 `.tar.gz` 같은 이중 확장자는 `.gz`만 나옵니다.

### path.parse

경로를 `root`, `dir`, `base`, `name`, `ext` 다섯 속성의 객체로 나눕니다.

```js
path.parse('/home/u/f.txt')
// { root: '/', dir: '/home/u',
//   base: 'f.txt', ext: '.txt', name: 'f' }
path.parse('f.txt')
// { root: '', dir: '', base: 'f.txt',
//   ext: '.txt', name: 'f' }
```

```text
 /     home/u   /  f   .txt
 root  dir         name ext
       (root+dir)   base = name + ext
```

- 끝의 구분자는 무시합니다. `path.parse('/a/b/')`의 `base`는 `'b'`입니다.
- `dir`은 `root`를 포함합니다. `'/home/u'`가 `dir`이고 `root`는 `'/'`입니다.

### path.format

`path.format(객체)`는 `path.parse`의 반대로, 객체에서 경로 문자열을 만듭니다. 속성 사이에 우선순위가 있습니다.

```js
path.format({ dir: '/a', base: 'f.txt' }) // '/a/f.txt'
path.format({ root: '/', name: 'f', ext: '.txt' })
// '/f.txt'
path.format({ name: 'f', ext: 'md' }) // 'f.md'
path.format({ root: '/x', dir: '/a', base: 'f' }) // '/a/f'
```

- `dir`이 있으면 `root`는 무시됩니다.
- `base`가 있으면 `name`과 `ext`는 무시됩니다. 없을 때 `name + ext`를 씁니다.
- `ext`에 점이 없으면 점을 붙입니다. 이 동작은 Node.js 19.0.0부터입니다.
- 확장자만 바꿀 때는 `parse`로 나눠 `ext`를 바꾸고 `base`를 지운 뒤 `format`으로 합칩니다.

```js
const { name, dir } = path.parse('/a/b.txt')
path.format({ dir, name, ext: '.md' }) // '/a/b.md'
```

## 구분자

### path.sep

경로 조각을 나누는 구분자입니다. POSIX는 슬래시(`/`), Windows는 역슬래시입니다.

```js
'foo/bar/baz'.split(path.sep)
// ['foo', 'bar', 'baz'] (POSIX)
```

- Windows는 슬래시와 역슬래시를 모두 구분자로 받아들이지만 `path`의 함수가 새로 넣는 구분자는 역슬래시입니다.
- 구분자로 직접 나누는 것보다 `path.parse`나 `path.basename`을 쓰는 편이 안전합니다. 문자열 비교에 `path.sep`를 붙일 때만 직접 씁니다.

### path.delimiter

`PATH` 같은 환경변수 안에서 경로 여러 개를 나누는 구분자입니다. POSIX는 `:`, Windows는 `;`입니다.

```js
process.env.PATH.split(path.delimiter)
// ['/usr/bin', '/bin', ...] (POSIX)
```

- 경로 하나 안의 구분자(`sep`)와 경로 목록의 구분자(`delimiter`)를 혼동하지 않습니다.
- Windows 경로의 드라이브 `C:`에도 `:`가 있으므로 `:`로 직접 나누면 Windows에서 깨집니다. `path.delimiter`를 씁니다.

## 플랫폼별 구현

### path.posix

`path.posix`는 운영체제와 관계없이 POSIX 규칙으로 동작하는 `path`입니다. `node:path/posix`로도 가져옵니다.

```js
import { posix } from 'node:path'
import posixPath from 'node:path/posix'

posix.basename('/tmp/f.html')       // 'f.html' (어디서나)
posix.join('a\\b', 'c')             // 'a\\b/c'
```

- POSIX에서는 역슬래시가 구분자가 아니고 이름의 일부입니다.
- Windows에서 URL 경로나 Docker·Linux 서버 경로처럼 항상 `/`를 쓰는 문자열을 다룰 때 씁니다.

### path.win32

`path.win32`는 운영체제와 관계없이 Windows 규칙으로 동작하는 `path`입니다. `node:path/win32`로도 가져옵니다.

```js
import { win32 } from 'node:path'

win32.basename('C:\\temp\\f.html') // 'f.html' (어디서나)
path.basename('C:\\temp\\f.html')
// POSIX에서는 'C:\\temp\\f.html' 전체
```

- Linux에서 Windows 경로가 들어 있는 로그나 설정을 파싱할 때 씁니다.
- `node:path/posix`와 `node:path/win32`로 가져오는 방식은 Node.js 15.3.0부터 가능합니다.
- 기본 `path`는 실행 중인 플랫폼에 해당하는 쪽(Windows에서는 `path.win32`와 같은 객체)입니다.

## 절대 경로

절대 경로는 루트부터 시작해 위치가 실행 위치와 관계없이 하나로 정해지는 경로입니다. `path.isAbsolute(경로)`로 판별합니다.

| 플랫폼 | 절대 경로 | 상대 경로 |
|--------|-----------|-----------|
| POSIX | `/foo/bar` | `qux/`, `.`, `''` |
| Windows | `C:\foo`, `C:/foo`, `\\server`, `\foo` | `bar\baz`, `.`, `C:foo` |

- 빈 문자열은 `false`입니다.
- Windows의 `C:foo`는 드라이브만 있고 루트가 없는 형태라서 절대 경로가 아닙니다(드라이브별 작업 디렉터리를 기준으로 합니다). `\foo`는 현재 드라이브의 루트부터라서 `true`로 판정됩니다.
- `path.resolve`는 절대 경로를 보장하고 `path.isAbsolute`는 문자열의 모양만 판정합니다. 파일이 있는지는 알려주지 않습니다.
- Node.js 문서는 `path.isAbsolute`가 경로 탈출 방어 수단으로 안전하지 않다고 명시합니다. 문자열 `'/baz/..'`도 `true`입니다.

## 상대 경로

상대 경로는 어떤 기준 디렉터리에서 시작하는 경로입니다. 기준이 바뀌면 가리키는 위치가 달라집니다.

- `./a`와 `a`는 같은 뜻이고 `../a`는 기준의 상위 디렉터리를 뜻합니다.
- 파일 시스템 함수(`fs`)에 상대 경로를 주면 기준은 현재 작업 디렉터리(`process.cwd()`)입니다. 소스 파일의 위치가 아닙니다.
- 같은 코드를 다른 폴더에서 실행하면 같은 상대 경로가 다른 파일을 가리킵니다.

```js
import { readFile } from 'node:fs/promises'

await readFile('data/x.json')
// 실행 위치가 어디냐에 따라 달라짐 (cwd 기준)
const file = path.join(import.meta.dirname, 'data/x.json')
await readFile(file)
// 소스 파일 위치 기준
```

- 모듈 안에서 소스 파일 옆의 자원을 가리킬 때는 `import.meta.dirname`(또는 `import.meta.url`)을 기준으로 삼습니다(자세히는 07편).
- `import`와 `require`의 상대 경로(`'./x.js'`)는 그 파일 위치를 기준으로 하므로 `fs`의 상대 경로와 규칙이 다릅니다.

**흔한 실수:** 상대 경로를 쓴 스크립트가 프로젝트 루트에서만 동작하는 것입니다. `npm run`으로 실행하면 루트에서 실행되어 동작하다가 다른 폴더에서 `node scripts/a.js`로 실행하면 파일을 찾지 못합니다.

## .. 경로 탈출

경로 탈출(path traversal)은 `..`를 이용해 허용된 디렉터리 밖의 파일에 접근하는 공격입니다. 사용자가 보낸 파일 이름을 기준 디렉터리 뒤에 붙일 때 `../../etc/passwd` 같은 값이 들어오면 일어납니다.

```js
const base = '/srv/pub'
path.join(base, '../secret')    // '/srv/secret' (밖으로 나감)
path.resolve(base, '../secret') // '/srv/secret'
path.resolve(base, '/etc/passwd') // '/etc/passwd'
```

`join`과 `resolve`는 `..`를 해석할 뿐 기준 안에 있는지 확인하지 않습니다. 직접 확인해야 합니다. 절대 경로로 만든 뒤 `path.relative`로 기준에서 본 상대 경로를 구하고, 그 경로가 `..`로 시작하거나 절대 경로이면 밖으로 나간 것입니다.

```js
function resolveInside(base, input) {
  const full = path.resolve(base, input)
  const rel = path.relative(base, full)
  const up = '..' + path.sep
  const out = rel === '..' || rel.startsWith(up)
  if (out || path.isAbsolute(rel)) {
    throw new Error('Path traversal')
  }
  return full
}
// ('/srv/pub', 'a/b.txt')  → '/srv/pub/a/b.txt'
// ('/srv/pub', '../secret') → 에러
// ('/srv/pub', '/etc/passwd') → 에러
```

- `rel.startsWith('..')`만 쓰면 `..hidden` 같은 정상 파일 이름도 막습니다. `'..'` 또는 `'..' + path.sep`로 시작하는지를 봅니다.
- Windows에서 드라이브가 다르면 `path.relative`가 절대 경로를 반환하므로 `path.isAbsolute(rel)`을 함께 검사합니다.
- 이 방법은 문자열만 검사합니다. 기준 안에 있는 심볼릭 링크가 밖을 가리키면 막지 못합니다. 링크까지 막으려면 `fs.realpath`로 실제 경로를 얻어 비교합니다(링크는 18편).
- `path.isAbsolute`나 `path.normalize` 한 번으로는 방어가 되지 않습니다. 파일 URL을 변환한 결과도 마찬가지입니다(아래 "URL과 파일 경로 변환").

## Windows 경로를 코드에서 다루기

Windows 경로는 구분자가 역슬래시이고 드라이브(`C:`)가 있어서 코드에서 몇 가지를 조심해야 합니다.

- 문자열 안의 역슬래시는 이스케이프 문자입니다. 경로의 역슬래시는 두 번 겹쳐 쓰거나 슬래시로 씁니다. `'C:\temp'`의 `\t`는 탭입니다.
- Windows는 `C:/temp/f.txt`처럼 `/`도 받아들입니다. 소스 코드에는 `/`나 `path.join`을 쓰는 편이 안전합니다.
- 구분자를 직접 이어 붙이지 않고 `path.join`을 씁니다. 결과는 역슬래시로 정규화됩니다.
- 다른 플랫폼의 경로를 파싱할 때는 `path.win32`나 `path.posix`를 명시합니다.
- 파일 이름의 대소문자는 구분하지 않는 것이 보통이지만 `path.win32.basename`의 접미사 비교는 대소문자를 구분합니다.

```js
path.win32.join('C:\\a', '..', 'b')     // 'C:\\b'
path.win32.normalize('C:/a//b/../c')    // 'C:\\a\\c'
path.win32.resolve('C:\\a', 'D:\\b')    // 'D:\\b'
path.win32.parse('\\\\srv\\share\\f.txt').root
// '\\\\srv\\share\\' (UNC 경로의 루트)
```

- UNC 경로(`\\서버\공유`)는 서버와 공유 이름까지가 루트입니다.
- Windows는 드라이브마다 작업 디렉터리를 따로 가진다는 개념이 있어서 `path.resolve('C:\\')`와 `path.resolve('C:')`의 결과가 다를 수 있습니다.
- 긴 경로나 특수한 이름에는 `path.toNamespacedPath`가 `\\?\C:\...` 형태의 접두사 경로를 만듭니다. Windows에서만 의미가 있고 POSIX에서는 입력을 그대로 반환합니다.

**흔한 실수:** 테스트를 Windows에서만 하고 서버(Linux)에서 깨지는 것입니다. 경로 문자열을 하드코딩한 비교(`'a\\b'`)나 `split('\\')`는 플랫폼이 바뀌면 동작하지 않습니다.

## path.matchesGlob

`path.matchesGlob(경로, 패턴)`은 경로가 글롭(glob) 패턴과 맞는지 `boolean`으로 반환합니다. Node.js 22.5.0과 20.17.0에서 추가되었고 24.8.0에서 Stable로 올라갔습니다(22.20.0에도 같은 변경이 반영되었습니다).

```js
path.matchesGlob('/foo/bar', '/foo/*')          // true
path.matchesGlob('src/a.ts', '*.ts')            // false
path.matchesGlob('src/a.ts', '**/*.ts')         // true
path.matchesGlob('a.ts', '*.{ts,js}')           // true
```

- 별표 하나는 한 조각 안의 문자와 맞고 구분자를 넘지 않습니다. 별표 두 개는 여러 디렉터리에 걸칩니다. 중괄호 안에 쉼표로 적은 `{ts,js}`는 선택지입니다.
- 인수가 문자열이 아니면 `TypeError`입니다.
- 파일 시스템을 읽지 않고 문자열만 비교합니다. 디렉터리를 순회하며 파일을 찾는 것은 `fs.glob`입니다(자세히는 18편).

## URL과 파일 경로 변환

ES Modules의 `import.meta.url`은 경로가 아니라 `file:///...` 형태의 URL 문자열입니다. 파일 경로와 파일 URL을 오가는 함수는 `node:url`에 있습니다.

```js
import { fileURLToPath, pathToFileURL } from 'node:url'

fileURLToPath('file:///tmp/a%20b.txt') // '/tmp/a b.txt'
pathToFileURL('/tmp/a b#1.txt').href
// 'file:///tmp/a%20b%231.txt'
```

| 함수 | 입력 | 반환 |
|------|------|------|
| `fileURLToPath(url)` | 파일 URL 문자열 또는 `URL` | 플랫폼에 맞는 경로 문자열 |
| `pathToFileURL(path)` | 경로 문자열 | `URL` 객체 |

- `fileURLToPath`는 `%20` 같은 퍼센트 인코딩을 풀고 Windows의 `/C:/path/`를 `C:\path`(끝에 역슬래시)로 바꿉니다. `new URL(...).pathname`은 이를 처리하지 않아서 경로로 쓰면 틀립니다.
- `pathToFileURL`은 경로를 절대 경로로 만들고 `#`, `%`, 공백 같은 URL 제어 문자를 인코딩합니다. `'file://' + 경로`로 직접 붙이면 `#`이 일부로 잘립니다.
- 둘 다 `{ windows: true | false }` 옵션으로 Windows·POSIX 해석을 강제할 수 있습니다. Node.js 22.1.0과 20.13.0에서 추가되었습니다.
- `import()`에 절대 경로를 줄 때는 Windows에서 `C:\...`가 URL이 아니라서 실패하므로 `pathToFileURL(경로).href`로 바꿔 줍니다.
- `fileURLToPath`는 인코딩된 `%2e%2e`(`..`)를 해석해 정규화합니다. Node.js 문서는 이 함수만으로 경로 탈출을 막을 수 없다고 경고하므로 결과 경로를 위의 방식으로 직접 검증합니다.

## 핵심 정리

- `node:path`는 문자열만 계산하는 Stable 모듈이며, 실행 플랫폼에 따라 POSIX와 Windows 규칙으로 동작하고 `path.posix`와 `path.win32`로 고정할 수 있습니다.
- `join`은 이어 붙이고 정규화하며, `resolve`는 항상 절대 경로를 만들고 절대 경로 조각을 만나면 앞을 버립니다.
- `basename`, `dirname`, `extname`, `parse`로 나누고 `format`으로 합칩니다. `relative`는 두 경로 사이의 상대 경로를 줍니다.
- `fs`의 상대 경로는 소스 파일이 아니라 현재 작업 디렉터리 기준입니다. 소스 파일 기준은 `import.meta.dirname`으로 만듭니다.
- 사용자 입력을 기준 디렉터리 아래에 붙일 때는 `resolve` 후 `relative`로 `..` 탈출과 절대 경로를 직접 검사합니다.
- `fileURLToPath`와 `pathToFileURL`로 파일 URL과 경로를 바꾸고, `matchesGlob`은 문자열을 글롭과 비교합니다.
