이 편의 코드는 `node:fs/promises`를 기준으로 합니다. 같은 이름의 콜백 형태와 동기 형태(`Sync` 접미사)가 있습니다(자세히는 16편).

## existsSync를 믿으면 안 되는 이유

`existsSync(path)`는 경로가 있으면 `true`, 그 외에는 `false`를 돌려주는 동기 함수입니다. 콜백 형태인 `fs.exists()`는 폐기(Deprecated)되었지만 `existsSync()`는 폐기되지 않았습니다. `node:fs/promises`에는 `exists`가 없습니다.

```js
import { existsSync, readFileSync } from 'node:fs'

if (existsSync('a.txt')) {
  // 이 사이에 다른 프로세스가 a.txt를 지울 수 있다
  const text = readFileSync('a.txt', 'utf8') // ENOENT 가능
}
```

- 확인과 사용 사이에 파일 상태가 바뀔 수 있습니다(경쟁 상태, TOCTOU). 확인이 통과해도 다음 줄은 실패할 수 있습니다.
- 공식 문서도 열기·읽기·쓰기 전에 존재를 확인하지 말라고 안내합니다. 곧바로 작업하고 던져진 에러를 처리하는 방식이 권장됩니다.
- 심볼릭 링크는 따라가므로, 링크는 있어도 가리키는 대상이 없으면 `false`입니다.
- `false`만으로는 없는 것인지, 확인할 수 없는 것인지 구분되지 않습니다. 에러의 `code`를 보려면 실제 작업을 시도해야 합니다.

```js
import { readFile } from 'node:fs/promises'

try {
  const text = await readFile('a.txt', 'utf8')
} catch (err) {
  if (err.code !== 'ENOENT') throw err
  // 없을 때의 처리
}
```

존재 여부 자체가 목적인 경우(설정 파일이 있으면 읽고 없으면 기본값 사용 등)에도 위처럼 `ENOENT`를 분기합니다. 파일을 새로 만들 때 이미 있는지 확인하려면 `'wx'` 플래그로 열어 `EEXIST`를 받습니다(자세히는 16편, 18편).

**흔한 실수:** `if (!existsSync(dir)) mkdirSync(dir)`로 폴더를 만드는 것입니다. 두 호출 사이에 다른 프로세스가 만들면 `EEXIST`가 납니다. `mkdir(dir, { recursive: true })`는 이미 있어도 에러를 내지 않습니다.

## access

`access(path, mode)`는 현재 프로세스가 그 경로에 접근할 수 있는지 확인합니다. 성공하면 `undefined`로 이행하고, 하나라도 실패하면 에러로 거부됩니다.

```js
import { access, constants } from 'node:fs/promises'

await access('a.txt') // 보이기만 하면 통과 (F_OK)
await access('a.txt', constants.R_OK | constants.W_OK)
// 읽기와 쓰기 모두 가능해야 통과. 아니면 reject
```

| 상수 | 뜻 |
|------|----|
| `F_OK` | 프로세스에서 보이는가(기본값). 읽기·쓰기·실행 권한은 보지 않음 |
| `R_OK` | 읽을 수 있는가 |
| `W_OK` | 쓸 수 있는가 |
| `X_OK` | 실행할 수 있는가. Windows에서는 `F_OK`처럼 동작 |

- 여러 검사는 `|`(비트 OR)로 합칩니다.
- `access`를 연 직후에 `open`하는 식의 사용은 앞 절과 같은 경쟁 상태를 만듭니다. 공식 문서도 권장하지 않습니다. 권한 점검 결과를 보여 주는 진단 용도에 알맞습니다.
- 실패한 에러의 `code`는 없으면 `ENOENT`, 권한이 없으면 `EACCES`입니다(자세히는 18편).

## stat

`stat(path)`는 경로의 메타데이터를 담은 `fs.Stats` 객체로 이행합니다. 심볼릭 링크는 따라가서 대상의 정보를 돌려줍니다. 경로가 없으면 `ENOENT`로 거부됩니다.

```js
import { stat } from 'node:fs/promises'

const info = await stat('a.txt')
info.size       // 5 (바이트 수)
info.isFile()   // true
info.mtime      // Date (마지막 수정 시각)
info.mtimeMs    // 숫자 (밀리초, Date와 별개 값)
```

| 속성 | 뜻 |
|------|----|
| `size` | 바이트 수. 파일 시스템이 크기를 알려 주지 않으면 `0` |
| `mode` | 파일 종류와 권한 비트(자세히는 18편) |
| `atime` | 마지막으로 데이터를 읽은 시각 |
| `mtime` | 마지막으로 데이터를 수정한 시각 |
| `ctime` | 파일 상태(inode)가 마지막으로 바뀐 시각. 생성 시각이 아님 |
| `birthtime` | 생성 시각. 지원하지 않는 파일 시스템에서는 `ctime`이나 1970-01-01일 수 있음 |

- `atimeMs`, `mtimeMs`, `ctimeMs`, `birthtimeMs`는 밀리초 숫자이고, `atime` 등은 `Date`입니다. 두 표현은 연결되어 있지 않아서 한쪽을 바꿔도 다른 쪽은 변하지 않습니다.
- 정밀도는 플랫폼마다 다릅니다.
- `{ bigint: true }`를 주면 숫자 값이 `bigint`가 되고 나노초 단위 `mtimeNs` 같은 속성이 추가됩니다.
- `Stats`를 `new`로 직접 만들지 않습니다.

경로가 없을 때 에러 대신 `undefined`를 받으려면 `throwIfNoEntry: false`를 줍니다.

```js
const info = await stat('maybe.txt', {
  throwIfNoEntry: false,
})
if (info === undefined) {
  // 없음. 그 밖의 에러(EACCES 등)는 그대로 던져짐
}
```

`fs/promises`의 `stat`에서 이 옵션은 Node.js 24.15.0과 25.7.0에서 추가되었습니다. 동기·콜백 형태의 `statSync`·`lstatSync`는 14.17.0부터 지원합니다. 이 옵션은 경로가 없는 경우만 처리합니다.

## lstat

`lstat(path)`는 `stat`과 같지만 경로가 심볼릭 링크일 때 링크를 따라가지 않고 링크 자체를 조사합니다. 링크가 아닌 경로에서는 `stat`과 결과가 같습니다.

```js
import { lstat, stat } from 'node:fs/promises'

// link는 real/ 디렉터리를 가리키는 링크라고 가정
const a = await lstat('link')
a.isSymbolicLink() // true
a.isDirectory()    // false (링크 자체를 본 것)
const b = await stat('link')
b.isSymbolicLink() // false
b.isDirectory()    // true (대상을 본 것)
```

- 끊어진 링크(대상이 없음)는 `stat`이 `ENOENT`로 실패하지만 `lstat`은 성공합니다.
- 링크 자체를 지우거나 이동할 때, 디렉터리를 순회하며 링크를 따라가고 싶지 않을 때 `lstat`을 씁니다.
- 링크의 개념과 `readlink`는 18편에서 다룹니다.

## 파일과 디렉터리 구분

`Stats`와 `Dirent`(디렉터리 항목)는 같은 이름의 판별 메서드를 가집니다. 결과는 불리언입니다.

| 메서드 | `true`인 경우 |
|--------|---------------|
| `isFile()` | 일반 파일 |
| `isDirectory()` | 디렉터리 |
| `isSymbolicLink()` | 심볼릭 링크 |
| `isFIFO()` | FIFO 파이프 |
| `isSocket()` | 소켓 |
| `isBlockDevice()`, `isCharacterDevice()` | 블록·문자 장치 |

```js
const info = await stat(path)
const kind = info.isDirectory()
  ? 'dir'
  : info.isFile() ? 'file' : 'other'
```

- 한 항목은 위 중 하나에만 해당합니다. 파일이 아니라고 해서 디렉터리인 것이 아니므로 둘을 각각 확인합니다.
- `stat`이 돌려준 `Stats`에서는 `isSymbolicLink()`가 `true`가 될 수 없습니다. 이 메서드는 `lstat`의 결과에서만 유효합니다.
- `lstat`한 링크의 `isDirectory()`는 대상이 디렉터리여도 `false`입니다.
- 잘못된 종류에 작업하면 에러 코드로 나타납니다. 디렉터리를 `readFile`하면 `EISDIR`, 파일을 `readdir`하면 `ENOTDIR`입니다(자세히는 18편).

## mkdir

`mkdir(path)`는 디렉터리 하나를 만듭니다. 이미 있으면 `EEXIST`, 부모 디렉터리가 없으면 `ENOENT`로 거부됩니다.

```js
import { mkdir } from 'node:fs/promises'

await mkdir('out')       // undefined
await mkdir('out')       // EEXIST
await mkdir('a/b/c')     // a가 없으면 ENOENT
```

두 번째 인수로 `{ mode }`를 줄 수 있습니다. 기본값은 `0o777`이고 Windows에서는 지원하지 않습니다. 권한 비트는 18편에서 다룹니다.

### recursive 옵션

`recursive: true`는 없는 부모 디렉터리를 함께 만들고, 대상이 이미 있어도 에러를 내지 않습니다.

```js
const first = await mkdir('a/b/c', { recursive: true })
// 새로 만든 가장 바깥 경로 (a의 절대 경로)
await mkdir('a/b/c', { recursive: true })
// undefined (이미 있어서 만든 것이 없음)
```

- 반환값이 다릅니다. `recursive`가 없으면 항상 `undefined`이고, 있으면 처음 만든 디렉터리 경로를 돌려줍니다. 새로 만든 것이 없으면 `undefined`입니다.
- 이미 있는 경로가 디렉터리가 아니라 파일이면 `recursive`여도 에러입니다.
- 폴더가 없으면 만들고 있으면 넘어가야 하는 상황에서는 존재 확인 없이 `recursive: true`를 씁니다.

## readdir

`readdir(path)`는 디렉터리 안 항목의 이름을 문자열 배열로 돌려줍니다. `.`과 `..`은 포함하지 않습니다. 하위 디렉터리의 내용은 들어 있지 않습니다.

```js
import { readdir } from 'node:fs/promises'

const names = await readdir('x')
// ['g.txt', 'y']  (파일과 디렉터리 이름이 섞여 있음)
```

- 이름만 돌려주므로 종류를 알려면 `stat`을 따로 불러야 합니다. 아래 `withFileTypes`가 이 호출을 줄입니다.
- 공식 문서는 반환 순서를 약속하지 않습니다. 순서가 필요하면 `sort()`합니다.
- 경로가 없으면 `ENOENT`, 디렉터리가 아니면 `ENOTDIR`입니다.
- `encoding: 'buffer'`를 주면 이름이 `Buffer`로 옵니다. 기본은 `'utf8'` 문자열입니다.

### withFileTypes

`withFileTypes: true`를 주면 이름 대신 `fs.Dirent` 객체의 배열을 돌려줍니다.

```js
const entries = await readdir('x', { withFileTypes: true })
for (const e of entries) {
  e.name           // 'g.txt'
  e.parentPath     // 'x' (부모 디렉터리 경로)
  e.isDirectory()  // false
}
const dirs = entries.filter((e) => e.isDirectory())
```

- `Dirent`는 이름과 종류를 함께 가지고 있어서 항목마다 `stat`을 부르지 않아도 됩니다. `Stats`와 같은 판별 메서드(`isFile()` 등)를 씁니다.
- 종류는 운영체제가 목록을 읽을 때 알려 준 값이며, 파일 시스템에 따라 `lstat` 결과와 다를 수 있습니다. 운영체제가 종류를 알려 주지 않을 때만 Node.js가 `lstat`을 부릅니다. 정확한 종류가 필요하면 `lstat`을 씁니다.
- `parentPath`는 Node.js 24에서 안정(Stable)이 되었습니다.

### recursive 옵션

`recursive: true`는 하위 디렉터리를 끝까지 내려가며 모든 항목을 한 배열에 담습니다. Node.js 18.17과 20.1에서 추가되었습니다.

```js
await readdir('x', { recursive: true })
// ['g.txt', 'y', 'y/f.txt', 'y/z', 'y/z/w']
```

- 이름은 시작 디렉터리 기준 상대 경로이고 구분자는 운영체제의 것입니다(Windows에서는 `y\f.txt`).
- 디렉터리 항목 자체도 목록에 들어갑니다. 파일만 필요하면 `withFileTypes`와 함께 써서 걸러냅니다.
- `withFileTypes`와 같이 쓰면 각 `Dirent`의 `parentPath`가 그 항목의 실제 부모 디렉터리를 가리킵니다. 경로가 필요하면 `join(e.parentPath, e.name)`으로 만듭니다.
- 패턴으로 파일을 찾을 때는 `glob`이 있습니다(자세히는 18편).

```js
import { join } from 'node:path'

const all = await readdir('x', {
  recursive: true,
  withFileTypes: true,
})
const files = all
  .filter((e) => e.isFile())
  .map((e) => join(e.parentPath, e.name))
```

## opendir

`opendir(path)`는 디렉터리를 열어 항목을 하나씩 읽을 수 있는 `fs.Dir` 객체로 이행합니다. 목록 전체를 배열로 만들지 않아서 항목이 아주 많은 디렉터리에 알맞습니다.

```js
import { opendir } from 'node:fs/promises'

const dir = await opendir('x')
for await (const entry of dir) {
  console.log(entry.name) // Dirent
}
// 반복이 끝나면 dir은 자동으로 닫힘
```

- 비동기 이터레이터로 순회하면 끝난 뒤 자동으로 닫힙니다.
- 직접 `await dir.read()`로 읽으면 `Dirent`나 끝을 뜻하는 `null`이 옵니다. 이 경우 `await dir.close()`를 직접 불러야 합니다.
- 읽기 순서는 운영체제가 주는 대로이며 정해져 있지 않습니다. 순회 도중 추가·삭제된 항목은 결과에 빠질 수 있습니다.
- `bufferSize`(기본 32)는 내부에서 미리 읽어 두는 항목 수입니다. 클수록 빠르지만 메모리를 더 씁니다.
- `recursive: true`로 하위 디렉터리까지 순회할 수 있습니다(18.17·20.1에서 추가).

## 삭제: rm, rmdir, unlink

세 함수는 대상과 옵션이 다릅니다.

| 함수 | 지우는 대상 | 비어 있지 않은 디렉터리 | 없는 경로 |
|------|-------------|------------------------|-----------|
| `rm` | 파일, 디렉터리 | `recursive: true`로 삭제 | `force: true`면 무시 |
| `rmdir` | 빈 디렉터리 | `ENOTEMPTY` | `ENOENT` |
| `unlink` | 파일, 심볼릭 링크 | 해당 없음 | `ENOENT` |

### rm

`rm(path, options)`는 `rm` 유틸리티를 본뜬 범용 삭제 함수입니다. Node.js 14.14에서 추가되었습니다.

```js
import { rm } from 'node:fs/promises'

await rm('a.txt')                    // 파일 삭제
await rm('x')                        // 디렉터리면 거부
await rm('x', { recursive: true })   // 하위까지 삭제
await rm('x', { recursive: true, force: true }) // rm -rf
```

- `recursive`의 기본값은 `false`라서 디렉터리를 주면 에러입니다(`ERR_FS_EISDIR`).
- `force: true`이면 경로가 없어도 에러를 내지 않습니다. 옵션 없이는 없는 경로가 `ENOENT`입니다.
- `recursive: true`일 때만 `EBUSY`, `EMFILE`, `ENFILE`, `ENOTEMPTY`, `EPERM`에서 재시도합니다. 횟수는 `maxRetries`(기본 0), 대기 간격은 `retryDelay`(기본 100ms)이고 시도마다 그만큼 길어집니다.

**흔한 실수:** 경로를 만드는 변수가 비거나 잘못되어 `rm(path, { recursive: true, force: true })`가 엉뚱한 곳을 지우는 것입니다. 삭제하기 전에 경로가 의도한 기준 디렉터리 아래에 있는지 확인합니다(자세히는 15편).

### rmdir

`rmdir(path)`는 빈 디렉터리 하나만 지웁니다. 안에 항목이 있으면 `ENOTEMPTY`입니다. 파일에 쓰면 POSIX에서 `ENOTDIR`, Windows에서 `ENOENT`입니다.

- `recursive` 옵션은 폐기(Deprecated)되었다가 Node.js 25.0.0에서 제거되었습니다. 24에서는 아직 받지만 쓰지 않습니다. 하위까지 지우려면 `rm`을 씁니다.
- Node.js 25 이후 문서에는 받는 옵션이 없으며, 옵션 인수는 호환성을 위해 받기만 하고 쓰지 않습니다.

### unlink

`unlink(path)`는 파일을 지웁니다. 경로가 심볼릭 링크이면 링크만 지워지고 대상은 그대로입니다.

```js
import { unlink } from 'node:fs/promises'

await unlink('a.txt')   // 파일 삭제
await unlink('link')    // 링크만 삭제, 대상 유지
await unlink('dir')     // 디렉터리는 에러 (EISDIR 또는 EPERM)
```

디렉터리에 쓰면 실패하는데 에러 코드는 운영체제마다 다릅니다. 이 환경(Windows)에서는 `EPERM`이었습니다. 코드로 분기하기보다 `rmdir`·`rm`을 쓰는 것이 낫습니다.

## rename

`rename(oldPath, newPath)`는 이름을 바꾸거나 다른 디렉터리로 옮깁니다. 결과는 `undefined`입니다.

```js
import { rename } from 'node:fs/promises'

await rename('a.txt', 'b.txt')      // 이름 변경
await rename('b.txt', 'out/b.txt')  // 이동 (out은 있어야 함)
```

- `newPath`가 이미 있는 파일이면 에러 없이 덮어씁니다. 덮어쓰기를 막는 옵션은 없습니다.
- `newPath`가 디렉터리이면 에러가 납니다.
- `oldPath`가 없으면 `ENOENT`입니다. `newPath`의 부모 디렉터리가 없어도 `ENOENT`이며 자동으로 만들어지지 않습니다.
- 서로 다른 파일 시스템(드라이브, 마운트 지점) 사이의 이동은 POSIX에서 `EXDEV`로 실패합니다. 이때는 `cp`나 `copyFile` 후 원본을 `rm`합니다.
- 같은 파일 시스템 안에서 POSIX `rename(2)`는 대상을 원자적으로 교체합니다. 이 성질을 이용한 안전한 쓰기는 18편에서 다룹니다.

## cp

`cp(src, dest, options)`는 파일이나 디렉터리 구조를 통째로 복사합니다. Node.js 16.7에서 추가되었고 22.3에서 실험적(Experimental) 표시가 풀렸습니다. 24와 26에서는 안정(Stable)입니다.

```js
import { cp } from 'node:fs/promises'

await cp('a.txt', 'b.txt') // 파일 복사
await cp('src', 'dst') // 에러 (ERR_FS_EISDIR)
await cp('src', 'dst', { recursive: true })
// 디렉터리 복사
```

- 디렉터리를 복사하려면 `recursive: true`가 필요합니다. 없으면 `ERR_FS_EISDIR`입니다.
- 디렉터리를 디렉터리로 복사하는 동작은 `cp dir1/ dir2/`와 비슷하며 글롭은 지원하지 않습니다.

옵션은 다음과 같습니다.

| 옵션 | 기본값 | 뜻 |
|------|--------|----|
| `recursive` | `false` | 디렉터리를 하위까지 복사 |
| `force` | `true` | 대상이 있으면 덮어씀. `false`이면 건너뜀 |
| `errorOnExist` | `false` | `force`가 `false`일 때 대상이 있으면 에러로 처리 |
| `filter` | 없음 | 항목마다 호출. `true`면 복사, `false`면 제외. 디렉터리를 제외하면 안의 내용도 제외 |
| `dereference` | `false` | 심볼릭 링크를 따라가서 대상을 복사 |
| `verbatimSymlinks` | `false` | `true`이면 링크의 경로 해석을 건너뛰고 링크 문자열을 그대로 복사 |
| `preserveTimestamps` | `false` | 원본의 시각 정보를 유지 |
| `mode` | `0` | `copyFile`의 `mode`와 같은 복사 동작 플래그 |

```js
await cp('src', 'dst', {
  recursive: true,
  filter: (src) => !src.endsWith('.log'),
})
// .log로 끝나는 항목은 복사하지 않음
```

- `filter`는 `(src, dest)`를 받으며 `Promise`를 돌려줘도 됩니다(동기 `cpSync`는 `Promise`를 지원하지 않음).
- `force: false`에 `errorOnExist: true`를 같이 주면 이미 있는 대상에서 `ERR_FS_CP_EEXIST`가 납니다. `errorOnExist`만 `true`로 주면 `force`가 기본값 `true`라서 덮어쓸 뿐 에러가 나지 않습니다.

## copyFile

`copyFile(src, dest, mode)`는 파일 하나를 복사합니다. 디렉터리에는 쓸 수 없고 `cp`를 씁니다. 기본 동작은 대상이 있으면 덮어쓰는 것입니다.

```js
import { copyFile, constants } from 'node:fs/promises'

await copyFile('a.txt', 'b.txt')  // b.txt가 있으면 덮어씀
await copyFile('a.txt', 'b.txt', constants.COPYFILE_EXCL)
// b.txt가 있으면 EEXIST
```

| 상수 | 동작 |
|------|------|
| `COPYFILE_EXCL` | 대상이 이미 있으면 실패 |
| `COPYFILE_FICLONE` | 복사 후 쓰기(reflink)를 시도하고, 지원하지 않으면 일반 복사로 대체 |
| `COPYFILE_FICLONE_FORCE` | reflink를 시도하고, 지원하지 않으면 실패 |

- 상수는 `|`로 합칠 수 있습니다.
- 심볼릭 링크는 따라갑니다. `src`가 링크이면 대상 파일이 복사되고, `dest`가 링크이면 `COPYFILE_EXCL`이 없는 한 링크가 가리키는 파일을 덮어씁니다.
- 복사의 원자성은 보장하지 않습니다. 대상을 연 뒤 에러가 나면 대상을 지우려고 시도합니다.

## 핵심 정리

- 존재를 확인한 뒤 사용하는 패턴은 경쟁 상태가 생기므로, 바로 작업하고 `ENOENT` 같은 에러 코드를 처리합니다. 폴더는 `mkdir(..., { recursive: true })`로 만듭니다.
- `access`는 권한 점검용, `stat`은 크기·시각·종류 확인용입니다. 링크 자체를 보려면 `lstat`을 씁니다.
- 파일과 디렉터리는 `isFile()`·`isDirectory()`로 각각 확인하고, `readdir`의 `withFileTypes`를 쓰면 항목마다 `stat`을 부르지 않아도 됩니다.
- 하위까지 내려가는 목록은 `readdir`의 `recursive`, 항목이 많으면 `opendir`로 하나씩 읽습니다.
- 삭제는 범용 `rm`, 빈 디렉터리 `rmdir`, 파일·링크 `unlink`로 나뉘며 `rm -rf`에 해당하는 것은 `rm`의 `recursive`와 `force`입니다.
- `rename`은 대상이 파일이면 덮어쓰며, `cp`는 디렉터리에 `recursive`가, `copyFile`은 덮어쓰기 방지에 `COPYFILE_EXCL`이 필요합니다.
