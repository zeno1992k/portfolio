## MediaStream과 MediaStreamTrack

`MediaStream`은 오디오·비디오 `MediaStreamTrack` 0개 이상을 묶은 실시간 미디어 흐름입니다. 카메라, 마이크, 화면 캡처, 캔버스, 원격 피어(자세히는 59편)가 모두 이 형태로 제공됩니다.

| 객체 | 멤버 | 내용 |
|------|------|------|
| `MediaStream` | `getTracks()`, `getAudioTracks()`, `getVideoTracks()` | 트랙 목록 |
| | `addTrack()`, `removeTrack()`, `clone()` | 트랙 추가·제거, 복제 |
| | `active`, `addtrack`·`removetrack` 이벤트 | 활성 여부, 트랙 변화 |
| `MediaStreamTrack` | `kind`, `label` | `audio`나 `video`, 장치 이름 |
| | `enabled` | `false`면 검은 화면이나 무음을 내보냄(트랙은 유지) |
| | `muted` | 소스가 데이터를 주지 않는 상태(읽기 전용) |
| | `readyState` | `live` 또는 `ended` |
| | `stop()`, `clone()` | 해제, 복제 |
| | `getSettings()`, `getCapabilities()`, `getConstraints()`, `applyConstraints()` | 설정 조회·변경(아래 "constraints") |
| | `ended`, `mute`, `unmute` 이벤트 | 끝남, 소스 데이터 중단·재개 |

- 스트림을 화면에 보이려면 `video.srcObject = stream`으로 연결합니다. `src`나 `createObjectURL`이 아닙니다(자세히는 50편).
- `enabled`는 사용자가 조작하는 켜기·끄기, `muted`는 소스 사정으로 데이터가 끊긴 상태입니다. 둘은 별개입니다.
- 마이크를 연 영상 미리보기에서 되울림을 막으려면 `video.muted = true`로 둡니다.

## getUserMedia

`navigator.mediaDevices.getUserMedia(constraints)`는 사용자에게 권한을 요청하고 카메라·마이크의 `MediaStream`을 Promise로 돌려줍니다.

```js
try {
  const stream = await navigator.mediaDevices.getUserMedia({
    audio: true,
    video: { width: 1280, height: 720 },
  })
  video.srcObject = stream
} catch (err) {
  console.log(err.name) // NotAllowedError 등
}
```

- 보안 컨텍스트(HTTPS, `localhost`, `file:`)에서만 쓸 수 있고, 아니면 `navigator.mediaDevices`가 `undefined`입니다.
- `audio`와 `video`는 `true`, `false`, 제약 객체 중 하나입니다. 둘 다 `false`이거나 비어 있으면 `TypeError`입니다.
- 사용 중에는 브라우저가 카메라·마이크 사용 표시를 보여 줍니다.
- 사용자가 프롬프트를 무시하면 Promise가 이행도 거부도 되지 않은 채 남을 수 있습니다. 호출 중에는 UI를 "대기 중" 상태로 두고 중복 호출을 막습니다.

예외 이름으로 원인을 구분합니다.

| 예외 | 원인 |
|------|------|
| `NotAllowedError` | 사용자가 거부, 보안 컨텍스트 아님, Permissions Policy가 차단 |
| `NotFoundError` | 조건에 맞는 장치가 없음 |
| `NotReadableError` | 하드웨어 오류, 다른 앱이 장치를 점유 |
| `OverconstrainedError` | 제약을 만족하는 장치가 없음. `constraint` 속성에 문제의 제약 이름 |
| `AbortError` | 권한이 있어도 장치를 쓸 수 없음 |
| `SecurityError` | 문서에서 사용자 미디어가 비활성화됨 |
| `InvalidStateError` | 문서가 완전히 활성 상태가 아님 |

## constraints와 applyConstraints()

제약(constraints)은 어떤 조건의 트랙을 원하는지 적는 객체입니다. 값에는 네 가지 형태가 있습니다.

| 형태 | 의미 |
|------|------|
| 값 그대로 (`width: 1280`) | `ideal`과 같은 선호값. 맞는 것이 없어도 실패하지 않음 |
| `ideal` | 가장 가까운 값을 선호. 실패하지 않음 |
| `min`, `max` | 범위 경계. 필수 조건 |
| `exact` | 정확히 그 값. 필수 조건 |

```js
const constraints = {
  video: {
    facingMode: 'environment',                // 후면 카메라
    width: { min: 640, ideal: 1280, max: 1920 },
    frameRate: { ideal: 30, max: 30 },
  },
}
```

- `facingMode`는 `user`(전면), `environment`(후면)이며 `{ exact: 'environment' }`로 쓰면 후면이 없을 때 `OverconstrainedError`입니다.
- `deviceId`로 특정 장치를 지정합니다(아래 "enumerateDevices()").
- 필수 조건(`exact`, `min`, `max`)이 하나라도 맞지 않으면 실패하므로 기본은 `ideal`로 씁니다.
- 어떤 제약 이름이 쓰이는지는 `navigator.mediaDevices.getSupportedConstraints()`로 확인합니다.

이미 얻은 트랙은 `applyConstraints()`로 다시 맞춥니다. 스트림을 새로 열지 않아도 됩니다.

```js
const [track] = stream.getVideoTracks()
console.log(track.getCapabilities().width) // { min, max }
await track.applyConstraints({ width: { ideal: 640 } })
console.log(track.getSettings().width)     // 실제 적용값
```

- 이전에 적용한 제약은 모두 교체됩니다. 이번 객체에 없는 속성은 기본 제약으로 돌아갑니다.
- 만족할 수 없으면 `OverconstrainedError`로 거부됩니다.
- 실제 값은 `getSettings()`, 장치가 지원하는 범위는 `getCapabilities()`, 적용 중인 제약은 `getConstraints()`로 읽습니다.

## 카메라 / 마이크 권한

카메라·마이크 접근은 두 계층의 허락을 거칩니다.

| 계층 | 내용 |
|------|------|
| 사용자 권한 | `getUserMedia()` 호출 때 브라우저가 프롬프트를 띄움 |
| Permissions Policy | 문서·`iframe`이 기능을 쓸 수 있는지 서버와 마크업이 정함 |

```http
Permissions-Policy: camera=(self); microphone=(self)
```

```html
<iframe src="https://widget.example"
        allow="camera; microphone"></iframe>
```

- 교차 출처 `iframe`은 `allow="camera; microphone"`이 있어야 합니다. 샌드박스된 `iframe`은 `allow-same-origin`이 필요합니다.
- 최상위 문서만 권한을 요청할 수 있으며, 하위 프레임은 정책으로 위임받아야 합니다.
- 현재 상태는 `navigator.permissions.query({ name: 'camera' })`로 조회합니다. 결과의 `state`는 `granted`, `denied`, `prompt`이고 `change` 이벤트가 있습니다. 지원하는 `name`은 브라우저마다 다를 수 있으므로 `try`/`catch`로 감쌉니다(자세히는 60편).
- 거부된 권한은 코드로 되돌릴 수 없습니다. 사용자가 주소창이나 설정에서 직접 허용해야 하므로 안내 문구를 보여 줍니다.
- 필요한 시점(예: "카메라 켜기" 버튼)에 요청합니다. 페이지 로드 직후 요청하면 거부당하기 쉽습니다.

**흔한 실수:** `NotAllowedError` 하나로 모든 실패를 "권한 거부"로 안내하는 것입니다. 보안 컨텍스트가 아니거나 정책이 막은 경우도 같은 이름입니다. `NotFoundError`(장치 없음)와 `NotReadableError`(다른 앱이 사용 중)는 문구가 달라야 합니다.

## enumerateDevices()와 devicechange

`navigator.mediaDevices.enumerateDevices()`는 입출력 장치 목록을 `MediaDeviceInfo` 배열로 돌려줍니다.

| 필드 | 내용 |
|------|------|
| `kind` | `audioinput`(마이크), `audiooutput`(스피커), `videoinput`(카메라) |
| `deviceId` | 장치 식별자 |
| `label` | 장치 이름 |
| `groupId` | 같은 물리 장치의 입출력을 묶는 ID |

```js
const md = navigator.mediaDevices
const devices = await md.enumerateDevices()
const cams = devices.filter((d) => d.kind === 'videoinput')
await md.getUserMedia({
  video: { deviceId: { exact: cams[1].deviceId } },
})
```

- `label`은 권한을 얻기 전에는 빈 문자열입니다. 활성 스트림이 있거나 영구 권한이 있을 때 채워집니다. 장치 선택 UI는 먼저 `getUserMedia()`로 권한을 받은 뒤 목록을 만듭니다.
- `kind`와 `groupId`는 권한 전에도 노출되어 핑거프린팅에 쓰일 수 있습니다. 정책으로 막힌 장치는 목록에서 빠집니다.
- 장치를 꽂거나 뽑으면 `navigator.mediaDevices`에서 `devicechange` 이벤트가 발생하므로 그때 목록을 다시 읽습니다.
- 사용 중인 장치가 뽑히면 해당 트랙은 `ended`가 되므로 대체 장치로 다시 열 수 있게 처리합니다.

## 트랙 stop()으로 장치 해제

`MediaStreamTrack.stop()`은 트랙을 소스에서 분리해 장치를 놓습니다. `readyState`는 즉시 `ended`가 되고 카메라·마이크 표시등이 꺼집니다.

```js
function release(stream) {
  stream.getTracks().forEach((track) => track.stop())
}
release(video.srcObject)
video.srcObject = null
```

- `MediaStream`에는 `stop()`이 없습니다. 모든 트랙을 하나씩 멈춰야 합니다.
- 같은 소스를 여러 트랙이 쓰고 있으면(예: 두 탭이 같은 마이크) 마지막 트랙이 멈출 때까지 소스는 유지됩니다. 복제한 트랙(`clone()`)도 각각 멈춥니다.
- 코드가 `stop()`을 호출하면 `ended` 이벤트는 발생하지 않습니다. `ended`는 장치가 뽑히거나 화면 공유를 사용자가 끝내는 것처럼 외부에서 끝났을 때 발생합니다.
- `video.srcObject = null`로 요소와의 연결도 끊어야 스트림이 정리됩니다.
- `enabled = false`는 해제가 아닙니다. 표시등이 켜진 채 장치를 계속 점유합니다.

**흔한 실수:** 화면에서 `video` 요소만 제거하는 것입니다. 스트림이 살아 있어 카메라가 계속 켜져 있습니다.

## getDisplayMedia() 화면 공유

`navigator.mediaDevices.getDisplayMedia()`는 사용자가 고른 화면, 창, 탭을 `MediaStream`으로 캡처합니다.

```js
shareBtn.onclick = async () => {
  const md = navigator.mediaDevices
  const stream = await md.getDisplayMedia({ video: true })
  const [track] = stream.getVideoTracks()
  track.addEventListener('ended', onShareStopped)
  video.srcObject = stream
}
```

- 일시적 사용자 활성화(버튼 클릭 등) 안에서만 호출할 수 있습니다. 보안 컨텍스트와 Permissions Policy의 `display-capture`가 필요합니다.
- 무엇을 공유할지는 브라우저의 선택 UI에서 사용자가 정합니다. 제약은 선택 이후에 적용됩니다. 허락은 영구 저장되지 않고 호출 때마다 받습니다.
- `video`는 필수이고 `video: false`는 `TypeError`입니다. `audio`의 기본값은 `false`이며 소리 캡처는 브라우저와 공유 대상에 따라 다릅니다.
- 선택 UI를 조정하는 옵션이 있습니다: `preferCurrentTab`, `selfBrowserSurface`(`include`·`exclude`), `surfaceSwitching`, `monitorTypeSurfaces`, `systemAudio`, `windowAudio`.
- 사용자가 브라우저의 "공유 중지"를 누르면 트랙에서 `ended`가 발생하므로 UI를 되돌립니다.
- 예외는 `NotAllowedError`(거부), `InvalidStateError`(사용자 활성화 없음), `NotFoundError`(공유할 대상 없음), `NotReadableError`(OS 차단)입니다.
- Baseline이 아닙니다. 모바일 브라우저에서는 대체로 지원되지 않습니다. 지원 여부는 `navigator.mediaDevices.getDisplayMedia`의 존재로 확인합니다.

## MediaRecorder

`MediaRecorder`는 `MediaStream`을 압축해 `Blob` 조각으로 내보내는 녹화 API입니다. Baseline 널리 지원(2021)입니다.

```js
const chunks = []
const rec = new MediaRecorder(stream, { mimeType })
rec.ondataavailable = (e) => chunks.push(e.data)
rec.onstop = () => {
  const blob = new Blob(chunks, { type: rec.mimeType })
  preview.src = URL.createObjectURL(blob)
}
rec.start()
// ... 나중에
rec.stop()
```

| 멤버 | 내용 |
|------|------|
| `start(timeslice)` | 녹화 시작. `timeslice`(ms)를 주면 그 간격으로 조각을 냄 |
| `stop()` | 종료. 마지막 `dataavailable`이 발생 |
| `pause()`, `resume()` | 일시정지, 재개 |
| `requestData()` | 녹화를 계속하면서 지금까지의 조각을 받음 |
| `state` | `inactive`, `recording`, `paused` |
| 이벤트 | `start`, `pause`, `resume`, `stop`, `dataavailable`, `error` |

- `dataavailable`의 `event.data`가 `Blob` 조각입니다. 조각을 모아 `new Blob(chunks)`로 합치면 재생·다운로드할 수 있습니다(자세히는 48편). 만든 URL은 사용 후 `revokeObjectURL()`로 해제합니다.
- `stop()` 후에 `onstop`이 발생하므로 합치는 일은 `onstop`에서 합니다. 그 직전에 마지막 `dataavailable`이 도착합니다.
- 비트레이트는 생성자 옵션 `audioBitsPerSecond`, `videoBitsPerSecond`로 정합니다. 실제 값은 같은 이름의 읽기 전용 속성으로 확인합니다.

### mimeType과 isTypeSupported()

녹화 형식은 브라우저마다 다릅니다. Chrome과 Firefox는 주로 `video/webm`·`audio/webm`을, Safari는 `video/mp4`·`audio/mp4`를 씁니다. 지원 여부는 반드시 `MediaRecorder.isTypeSupported(type)`으로 확인합니다.

```js
const candidates = [
  'video/webm;codecs=vp9,opus',
  'video/webm',
  'video/mp4',
]
const mimeType = candidates.find((t) =>
  MediaRecorder.isTypeSupported(t))
```

- 지원하지 않는 `mimeType`을 생성자에 넘기면 에러가 납니다. 후보 목록에서 첫 번째로 지원되는 값을 고릅니다.
- `mimeType`을 생략하면 브라우저가 기본 형식을 고르고, 실제 형식은 `recorder.mimeType`에서 읽습니다. 합친 `Blob`의 `type`에도 이 값을 씁니다.
- 컨테이너(`webm`, `mp4`)와 코덱(`vp9`, `opus` 등)이 `codecs=` 파라미터로 구분됩니다.

### timeslice

`start()`에 `timeslice`를 주지 않으면 `stop()`할 때 전체가 한 조각으로 나옵니다. 길게 녹화하면 모든 데이터가 메모리에 쌓입니다. `start(1000)`처럼 주면 1초마다 조각이 나와서 서버로 업로드하거나 저장소에 나눠 쓸 수 있습니다(자세히는 36편, 41편).

```js
rec.ondataavailable = (e) => upload(e.data) // 1초마다 호출
rec.start(1000)
```

- 조각은 순서대로 이어 붙여야 하나의 파일이 됩니다. 조각 하나만으로는 재생할 수 없다고 가정합니다.

## canvas captureStream()

`canvas.captureStream(frameRate)`는 캔버스의 그림을 비디오 트랙(`CanvasCaptureMediaStreamTrack`)이 담긴 `MediaStream`으로 만듭니다. 이 스트림을 `MediaRecorder`에 넣으면 캔버스 애니메이션을 녹화할 수 있습니다(자세히는 52편).

```js
const stream = canvas.captureStream(30)
const rec = new MediaRecorder(stream, { mimeType })
rec.start()
```

| `frameRate` | 동작 |
|-------------|------|
| 생략 | 캔버스가 바뀔 때마다 프레임을 캡처 |
| 양수 | 그 초당 프레임 수를 상한으로 캡처 |
| `0` | 자동 캡처 없음. 트랙의 `requestFrame()`을 호출할 때만 캡처 |

- 음수를 주면 `NotSupportedError`입니다. 다른 출처 이미지를 그려서 캔버스가 오염되었으면 `SecurityError`입니다(자세히는 52편).
- 소리는 들어 있지 않습니다. 오디오 트랙은 마이크 스트림에서 `addTrack()`으로 추가합니다.
- 캔버스의 `captureStream()`은 Baseline 널리 지원(2020)입니다. `video`·`audio` 요소용 `HTMLMediaElement.captureStream()`은 Baseline이 아니며 Firefox는 149부터 지원합니다(web-features 3.40.1).

## 미디어 컴포넌트 생명주기

카메라·녹화 컴포넌트에서 가장 중요한 규칙은 **요소가 사라질 때 장치를 반드시 놓는다**입니다. 트랙을 멈추지 않으면 장치가 계속 점유되어 표시등이 켜져 있습니다(자세히는 67편).

```js
const stopAll = (s) =>
  s.getTracks().forEach((track) => track.stop())
class CamView extends HTMLElement {
  #stream = null
  async connectedCallback() {
    const md = navigator.mediaDevices
    const s = await md.getUserMedia({ video: true })
    if (!this.isConnected) return stopAll(s) // 이미 제거됨
    this.#stream = s
  }
  disconnectedCallback() {
    if (this.#stream) stopAll(this.#stream)
    this.#stream = null
  }
}
```

- `getUserMedia()`는 사용자가 허용하기까지 오래 걸릴 수 있습니다. 그 사이 요소가 제거되면 Promise가 이행된 시점에 이미 `disconnectedCallback`이 지나갔으므로, 이행 후 `isConnected`를 확인해 즉시 멈춥니다(자세히는 18편).
- `disconnectedCallback()`에서 모든 트랙을 `stop()`하고 `srcObject`를 `null`로 만듭니다. `createObjectURL`로 만든 URL, `MediaRecorder` 리스너도 함께 정리합니다.
- 트랙의 `ended` 이벤트로 장치 분리와 외부 중단을 감지해 상태를 되돌립니다. `mute`·`unmute`는 소스가 일시적으로 데이터를 주지 않는 상태 변화입니다.
- 녹화 중이면 `rec.state`가 `inactive`가 아닐 때 `stop()`을 호출한 뒤 스트림을 해제합니다.
- 같은 요소를 다시 연결할 수 있으면(`connectedCallback`이 다시 호출) 이전 스트림을 새로 열어야 합니다. 멈춘 트랙은 되살릴 수 없습니다.
- 권한은 사용자 동작(버튼) 안에서 요청해 컴포넌트가 문서에 붙는 것만으로 프롬프트가 뜨지 않게 합니다.

**흔한 실수:** `disconnectedCallback`을 구현하지 않거나 `video.pause()`만 호출하는 것입니다. `pause()`는 재생만 멈출 뿐 스트림과 장치는 그대로입니다.

## WebCodecs와 MediaStreamTrack 처리 스트림

`MediaRecorder`는 브라우저가 압축·컨테이너를 알아서 처리하는 고수준 API입니다. 프레임 단위 제어가 필요하면 아래 두 API를 씁니다. 둘 다 Baseline이 아닙니다.

| API | 하는 일 |
|-----|---------|
| WebCodecs | `VideoEncoder`·`VideoDecoder`·`AudioEncoder`·`AudioDecoder`로 프레임과 인코딩된 조각(`EncodedVideoChunk`)을 변환. 프레임은 `VideoFrame`, `AudioData` |
| MediaStreamTrack 처리 스트림 | `MediaStreamTrackProcessor`가 트랙을 `VideoFrame`·`AudioData`의 `ReadableStream`으로 바꾸고, `MediaStreamTrackGenerator`·`VideoTrackGenerator`의 `WritableStream`이 다시 트랙으로 만듦 |

```js
// 워커 안: 트랙 → 프레임 → 변환 → 트랙
const proc = new MediaStreamTrackProcessor({ track })
const gen = new VideoTrackGenerator()
await proc.readable
  .pipeThrough(new TransformStream({ transform }))
  .pipeTo(gen.writable)
```

- WebCodecs는 압축·복호화 설정에 코덱 문자열 전체(예: `vp09.00.40.08.00`)가 필요하고, 컨테이너 muxing·demuxing은 포함하지 않아서 외부 라이브러리가 필요합니다.
- 처리 스트림은 배경 흐림 같은 실시간 프레임 처리에 쓰며, 성능을 위해 워커에서 쓰는 것이 기본입니다(자세히는 54편). `VideoTrackGenerator`는 워커 전용, `MediaStreamTrackGenerator`는 메인 스레드용입니다.
- web-features 3.40.1 기준 WebCodecs는 Chrome·Edge 94, Firefox 130, Safari 26에서 지원되지만 Android Firefox 지원이 없어 Baseline이 아닙니다. 처리 스트림은 Chromium 중심이며 Safari는 부분 지원입니다(MDN).
- 스트림 API의 `pipeThrough`는 38편을 참고합니다.

## Image Capture·Barcode Detection

두 API는 카메라 스트림에서 사진이나 바코드를 뽑습니다. 둘 다 Baseline이 아닙니다.

**Image Capture**: `new ImageCapture(videoTrack)`로 만들고 두 방법으로 정지 이미지를 얻습니다.

| 메서드 | 반환 | 내용 |
|--------|------|------|
| `takePhoto(settings)` | `Promise<Blob>` | 정지 사진을 `Blob`으로 촬영 |
| `grabFrame()` | `Promise<ImageBitmap>` | 현재 비디오 프레임을 가져옴 |
| `getPhotoCapabilities()` | `Promise` | 사진 설정이 가능한 범위 |
| `getPhotoSettings()` | `Promise` | 현재 사진 설정 |

```js
const [track] = stream.getVideoTracks()
const ic = new ImageCapture(track)
const blob = await ic.takePhoto()
```

**Barcode Detection**: `BarcodeDetector`가 이미지에서 바코드를 읽습니다.

```js
const formats = await BarcodeDetector.getSupportedFormats()
const detector = new BarcodeDetector({
  formats: ['qr_code'],
})
const codes = await detector.detect(video)
codes.forEach((c) => console.log(c.rawValue, c.format))
```

- `detect()`는 `img`, `video`, `canvas`, `ImageBitmap`, `Blob` 등을 받아 `rawValue`(해독 값), `format`, `boundingBox`, `cornerPoints`를 가진 배열을 반환합니다.
- 지원하는 형식은 `getSupportedFormats()`로 확인합니다. QR, EAN, Code 128 등이 있으며 기기마다 다릅니다.
- 보안 컨텍스트가 필요하고 워커에서도 쓸 수 있습니다. web-features 3.40.1 기준 Barcode Detection은 Android Chrome 83만 지원합니다.
- 지원하지 않는 환경에서는 `video`나 캔버스에서 프레임을 읽어 JavaScript 라이브러리나 WebAssembly 디코더로 대체합니다(자세히는 55편).

## Region Capture·Element Capture

두 API는 `getDisplayMedia()`로 현재 탭을 캡처한 트랙을 특정 요소 영역으로 제한합니다. Chromium 전용이며 Baseline이 아닙니다(web-features 3.40.1: Region Capture는 Chrome·Edge 104, Element Capture는 132부터).

| 항목 | Region Capture | Element Capture |
|------|----------------|-----------------|
| 대상 객체 | `CropTarget.fromElement(el)` | `RestrictionTarget.fromElement(el)` |
| 트랙 메서드 | `track.cropTo(target)` | `track.restrictTo(target)` |
| 동작 | 요소가 차지하는 사각 영역으로 잘라냄 | 요소와 자손의 내용만 캡처. 가리는 다른 콘텐츠는 제외 |

```js
const md = navigator.mediaDevices
const stream = await md.getDisplayMedia({
  preferCurrentTab: true,
})
const [track] = stream.getVideoTracks()
const target = await CropTarget.fromElement(panel)
await track.cropTo(target)
```

- 둘 다 현재 탭 캡처에만 적용됩니다. 두 API는 `getDisplayMedia()` 위에서 동작하므로 사용자 활성화와 공유 선택 UI가 필요합니다.
- `CropTarget`은 `postMessage()`로 다른 문서(예: `iframe`)에 전달할 수 있습니다.
- Region Capture는 잘라낸 영역 위에 다른 요소가 겹치면 그 모습까지 포함됩니다. 가리는 내용을 빼야 하면 Element Capture를 씁니다.
- 지원 환경이 한정되므로 기능이 없을 때는 전체 탭 공유로 대체하거나 기능을 숨깁니다.

## 핵심 정리

- `getUserMedia()`·`getDisplayMedia()`는 `MediaStream`을 Promise로 돌려주며, 보안 컨텍스트·사용자 권한·Permissions Policy를 거칩니다. 실패는 예외 이름으로 구분합니다.
- 제약은 `ideal`을 기본으로 쓰고 `exact`·`min`·`max`는 필수 조건이며, 열린 트랙은 `applyConstraints()`로 고칩니다.
- `enumerateDevices()`의 `label`은 권한 전에는 비어 있고, 장치 변화는 `devicechange`로 감지합니다.
- 장치는 `track.stop()`으로만 해제됩니다. `MediaStream`에는 `stop()`이 없고 `enabled = false`나 `pause()`는 해제가 아닙니다.
- `MediaRecorder`는 `isTypeSupported()`로 고른 `mimeType`과 `timeslice`로 조각을 모아 `Blob`을 만들고, 캔버스는 `captureStream()`으로 녹화합니다.
- 컴포넌트는 `disconnectedCallback`에서 트랙을 멈추고, 연결 전에 Promise가 늦게 끝난 경우도 처리합니다. WebCodecs·처리 스트림·Image Capture·Barcode Detection·Region/Element Capture는 Baseline이 아닙니다.
