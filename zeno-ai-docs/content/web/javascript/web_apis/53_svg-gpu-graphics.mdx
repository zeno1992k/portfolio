## SVG DOM 조작

인라인 SVG는 HTML 문서 안에서 일반 DOM 노드가 됩니다. SVG 요소는 `SVGElement`를 상속하므로 `querySelector`, 이벤트 리스너, 속성 메서드를 HTML 요소와 똑같이 씁니다(자세히는 03편, 07편). 다른 점은 요소를 만들 때 네임스페이스가 필요하다는 것, 좌표가 CSS 픽셀이 아니라 사용자 단위(user unit)라는 것입니다. 사용자 단위는 `viewBox`가 정하는 SVG 자체 좌표계의 단위입니다.

### SVG 네임스페이스와 createElementNS()

SVG 요소는 `http://www.w3.org/2000/svg` 네임스페이스에 속합니다. HTML 문서에서 `createElement('svg')`를 쓰면 `HTMLUnknownElement`가 만들어져 렌더링되지 않습니다. `createElementNS`에 네임스페이스를 함께 넘겨야 `SVGSVGElement` 같은 올바른 인터페이스가 만들어집니다. `createElementNS`는 2015년 7월부터 널리 지원됩니다.

```js
const NS = 'http://www.w3.org/2000/svg'
const svg = document.createElementNS(NS, 'svg')
svg.setAttribute('viewBox', '0 0 100 100')
const circle = document.createElementNS(NS, 'circle')
circle.setAttribute('cx', '50')
circle.setAttribute('cy', '50')
circle.setAttribute('r', '40')
svg.append(circle)
document.body.append(svg)
```

- `setAttribute`는 속성 이름의 대소문자를 보존합니다. SVG의 `viewBox`는 camelCase 그대로 씁니다.
- HTML 문서에 직접 쓴 `svg` 태그는 파서가 SVG 네임스페이스로 만들어 줍니다. 네임스페이스를 직접 지정해야 하는 경우는 스크립트로 요소를 만들 때입니다.
- `svg` 요소의 `innerHTML`에 문자열을 넣으면 자식이 SVG 네임스페이스로 해석됩니다. 문자열을 `svg` 밖에서 파싱하면 HTML로 해석됩니다.

**흔한 실수:** `createElement('circle')`처럼 HTML 방식으로 SVG 도형을 만드는 것입니다. 에러는 나지 않고 화면에 아무것도 그려지지 않아서 원인을 찾기 어렵습니다.

### 속성·클래스·스타일 다루기

SVG 요소의 프로퍼티는 HTML 요소와 다르게 동작하는 것이 있습니다.

| 항목 | SVG 요소에서의 동작 |
|------|---------------------|
| `className` | 문자열이 아니라 `SVGAnimatedString`이다. 읽기 전용 |
| `classList` | 그대로 쓸 수 있다. 클래스 조작은 이 방법이 안전하다 |
| `style` | `CSSStyleDeclaration`. 인라인 스타일을 쓴다 |
| `dataset` | `data-*` 속성에 접근한다 |
| 도형 속성(`cx`, `r`, `d` 등) | `setAttribute`로 쓴다. 프로퍼티는 `SVGAnimatedLength` 객체다 |

```js
circle.classList.add('active')
circle.style.fill = 'tomato'
circle.setAttribute('r', '30')
circle.r.baseVal.value // 30 (사용자 단위 숫자)
```

`fill`, `stroke`, `opacity` 같은 표현 속성은 속성으로도, CSS로도 지정할 수 있고 CSS가 우선합니다. 배경색은 `fill`이고 글자색을 따라가게 하려면 값에 `currentColor`를 씁니다.

### viewBox와 preserveAspectRatio

`viewBox`는 `min-x min-y width height` 네 숫자로, SVG 내용의 좌표계 범위를 정합니다. 이 범위가 `svg` 요소의 실제 크기(뷰포트)에 맞춰 늘어나고 줄어듭니다. 구분은 공백이나 쉼표입니다. 너비나 높이가 0 이하이면 렌더링되지 않습니다.

`preserveAspectRatio`는 viewBox와 뷰포트의 비율이 다를 때 어떻게 맞출지 정합니다. 형식은 `정렬 [meet|slice]`이고 기본값은 `xMidYMid meet`입니다.

| 값 | 의미 |
|----|------|
| `xMinYMin` … `xMaxYMax` | 가로(Min·Mid·Max)와 세로(Min·Mid·Max)의 정렬 기준. 아홉 가지 |
| `none` | 비율을 무시하고 가로세로를 따로 늘림 |
| `meet`(기본) | 비율을 유지하며 viewBox 전체가 보이도록 축소 |
| `slice` | 비율을 유지하며 뷰포트를 모두 덮도록 확대. 넘치는 부분은 잘림 |

```html
<svg viewBox="0 0 100 50" width="200" height="200"
     preserveAspectRatio="xMidYMid meet">
  <!-- 가로 200 기준으로 2배 확대, 세로는 가운데 정렬 -->
</svg>
```

- `preserveAspectRatio`는 `viewBox`가 있을 때만 효과가 있습니다. `viewBox`가 없으면 무시됩니다(`image` 요소는 예외).
- `svg`에 `width`·`height`를 주지 않고 CSS로 크기를 정하면 viewBox 비율이 그대로 유지되어 반응형 아이콘에 쓰기 좋습니다.

### getBBox()·getScreenCTM()과 좌표 변환

SVG에는 좌표계가 둘 이상 있어서 어느 좌표인지 구분해야 합니다.

| 메서드 | 반환 | 기준 좌표계 |
|--------|------|-------------|
| `getBBox()` | `DOMRect` | 요소 자신의 사용자 좌표계 |
| `getBoundingClientRect()` | `DOMRect` | 뷰포트의 CSS 픽셀(자세히는 06편) |
| `getCTM()` | `DOMMatrix` | 요소 좌표 → 가장 가까운 SVG 뷰포트 좌표 |
| `getScreenCTM()` | `DOMMatrix` | 요소 좌표 → 문서 뷰포트(client) 좌표 |

`getBBox()`는 요소 자신과 자손의 도형을 감싸는 가장 작은 사각형을 돌려줍니다. 렌더링되기 전에도 값을 얻을 수 있고, 자신과 부모에 걸린 변환(`transform`)은 반영하지 않습니다. 옵션 객체로 포함 범위를 바꿀 수 있습니다.

| 옵션 | 기본 | 포함 대상 |
|------|------|-----------|
| `fill` | `true` | 도형 자체 |
| `stroke` | `false` | 선, 선 끝 모양과 이음새 |
| `markers` | `false` | 마커 도형 |
| `clipped` | `false` | `clip-path`로 잘린 보이는 부분만 |

`getScreenCTM()`은 요소의 좌표를 화면(문서 뷰포트) 좌표로 옮기는 행렬입니다. 중간의 `viewBox`, `preserveAspectRatio`, `transform`과 SVG의 문서 안 위치가 모두 합쳐져 있습니다. 포인터 이벤트의 `clientX`·`clientY`를 SVG 좌표로 바꿀 때는 이 행렬의 역행렬을 씁니다.

```js
function toSvgPoint(svg, e) {
  const pt = new DOMPoint(e.clientX, e.clientY)
  return pt.matrixTransform(svg.getScreenCTM().inverse())
}
svg.addEventListener('pointermove', (e) => {
  const { x, y } = toSvgPoint(svg, e)
  // x, y는 viewBox 기준 사용자 단위
})
```

반대로 SVG 안의 요소가 화면의 어디에 있는지는 `element.getScreenCTM()`으로 점을 옮기면 얻습니다. `createSVGPoint()`는 `DOMPoint`를 만들어 주는 예전 API이고, 지금은 `new DOMPoint(x, y)`를 씁니다.

**흔한 실수:** `offsetX`·`clientX`를 viewBox 좌표로 그대로 쓰는 것입니다. viewBox가 뷰포트와 비율이 다르거나 스크롤·변환이 있으면 어긋납니다. `getBBox()`는 변환을 반영하지 않으므로 화면 위치가 필요하면 `getBoundingClientRect()`나 `getScreenCTM()`을 씁니다.

### SVG 접근성

보조 기술은 SVG를 기본적으로 그래픽 객체로 다루며, 이름이 없으면 무엇인지 알려 주지 못합니다. 의미 있는 그림은 이름을 주고, 장식은 숨깁니다.

```html
<svg role="img" aria-labelledby="t d" viewBox="0 0 20 10">
  <title id="t">월별 가입자</title>
  <desc id="d">1월부터 6월까지 꾸준히 증가</desc>
  <rect x="1" y="4" width="3" height="6" />
</svg>
```

- `role="img"`는 SVG 전체를 하나의 이미지로 다룹니다. 자손은 모두 프레젠테이션 역할이 되어 개별로 읽히지 않습니다. 이름은 `aria-label` 또는 `aria-labelledby`로 반드시 제공합니다.
- `title`은 접근 가능한 이름이자 툴팁이 됩니다. SVG 1.1 호환을 위해 부모의 첫 번째 자식으로 둡니다. 더 긴 설명은 `desc`를 씁니다.
- 화면에 보이는 글이 이미 있다면 `title`보다 `aria-labelledby`로 그 글을 가리키는 방식이 권장됩니다.
- 순수 장식 아이콘은 `aria-hidden="true"`로 숨깁니다.
- 도형 하나하나가 상호작용 대상이면 `img` 역할로 묶으면 안 됩니다. 각 도형에 역할·이름·`tabindex`를 주고 키보드 조작을 구현합니다(자세히는 27편, 28편).

## SVG를 컴포넌트로 감싸기

SVG 그래픽(아이콘, 차트, 게이지)은 속성으로 데이터를 받고 내부에서 SVG 노드를 만들거나 갱신하는 커스텀 요소로 감쌉니다. 바깥에는 HTML 요소의 인터페이스만 보이고 SVG 좌표계는 컴포넌트 안에 숨깁니다(속성 설계는 19편, Shadow DOM은 21편).

```js
const TEMPLATE = `
  <svg viewBox="0 0 100 10" role="img" aria-label="진행률">
    <rect width="100" height="10" fill="#ddd" />
    <rect id="bar" height="10" fill="currentColor" />
  </svg>`
```

```js
class MiniGauge extends HTMLElement {
  static observedAttributes = ['value']
  connectedCallback() {
    if (this.shadowRoot) return
    this.attachShadow({ mode: 'open' }).innerHTML = TEMPLATE
    this.render()
  }
  attributeChangedCallback() { this.render() }
  render() {
    const bar = this.shadowRoot?.getElementById('bar')
    const v = this.getAttribute('value') ?? 0
    bar?.setAttribute('width', v)
  }
}
customElements.define('mini-gauge', MiniGauge)
```

설계 규칙은 다음과 같습니다.

- 외부 API는 속성과 프로퍼티로 두고, 내부는 `viewBox` 고정 좌표로 그립니다. 컴포넌트 크기는 CSS(`width`, `height`, `aspect-ratio`)로 바깥에서 정합니다.
- 색은 `currentColor`와 CSS 사용자 정의 속성으로 열어 둡니다. Shadow DOM 안의 SVG는 바깥 선택자가 닿지 않지만 상속 속성과 사용자 정의 속성은 통과합니다(자세히는 23편).
- 정적인 틀은 `template`로 한 번 만들고 값이 바뀔 때는 `setAttribute`로 필요한 속성만 바꿉니다. 매번 `innerHTML`로 전체를 다시 만들면 포커스와 이벤트 리스너를 잃습니다.
- 접근성 이름은 컴포넌트가 책임집니다. 호스트의 `aria-label`을 내부 `svg`의 이름으로 전달하거나, 호스트에 `role="img"`를 부여합니다.
- 연결이 끊길 때 관찰자와 전역 리스너를 정리합니다(자세히는 18편).

**흔한 실수:** 조각 문자열을 `div`에 `innerHTML`로 넣어 SVG 자식만 만드는 것입니다. 바깥 `svg` 없이 파싱되어 HTML로 해석되므로 요소가 그려지지 않습니다. 항상 `svg` 요소를 포함한 문자열을 쓰거나 `createElementNS`로 만듭니다.

## ResizeObserver와 그래픽 리사이즈

`ResizeObserver`는 요소의 콘텐츠 박스나 보더 박스, SVG 요소의 경계 상자가 바뀔 때 콜백을 호출합니다. 윈도 `resize` 이벤트와 달리 컨테이너 단위로 변화를 감지합니다. 2020년 7월부터 널리 지원됩니다(Observer 일반은 43편).

| 그래픽 종류 | 리사이즈 처리 |
|-------------|----------------|
| SVG | viewBox 덕분에 대부분 CSS 크기만 바꾸면 자동으로 맞춰짐. 눈금·글자 크기를 다시 계산할 때만 관찰 |
| Canvas, WebGL | 그리기 버퍼 크기(`canvas.width`, `canvas.height`)를 직접 바꿔야 함. 바꾸면 내용이 지워지므로 다시 그림 |

캔버스는 CSS 크기와 그리기 버퍼 크기가 별개입니다. 선명하게 그리려면 버퍼를 물리 픽셀 수에 맞춥니다. `entry.devicePixelContentBoxSize`가 물리 픽셀 크기를 직접 알려 주고, 옵션 `box: 'device-pixel-content-box'`로 관찰합니다. 이 값은 Baseline이 아닙니다(MDN이 Safari 지원을 확인하라고 안내). 지원되지 않는 환경에서는 `contentBoxSize`에 `devicePixelRatio`를 곱해 근사합니다.

```js
const ro = new ResizeObserver(([entry]) => {
  const box = entry.devicePixelContentBoxSize?.[0]
  const cssBox = entry.contentBoxSize[0]
  canvas.width = box?.inlineSize
    ?? Math.round(cssBox.inlineSize * devicePixelRatio)
  canvas.height = box?.blockSize
    ?? Math.round(cssBox.blockSize * devicePixelRatio)
  draw() // 버퍼를 바꾸면 지워지므로 다시 그림
})
ro.observe(canvas, { box: 'device-pixel-content-box' })
```

- `devicePixelContentBoxSize`는 미지원 환경에서 비어 있을 수 있으므로 위 코드처럼 `?.`와 `??`로 대비합니다.
- 콜백은 렌더링 갱신 중 레이아웃 직후, 페인트 직전에 호출되므로 여기서 버퍼 크기를 바꾸고 바로 그려도 깜빡임이 없습니다(자세히는 08편).
- 콜백 안에서 관찰 중인 요소의 크기를 바꾸면 `ResizeObserver loop completed with undelivered notifications` 오류가 날 수 있습니다. 이 오류는 같은 렌더링 갱신에서 모든 알림을 전달하지 못했다는 뜻이며(깊이가 더 얕은 요소의 변화는 건너뜀), 크기를 바꾸는 작업을 `requestAnimationFrame`으로 미루면 피할 수 있습니다.
- 첫 `observe` 호출 직후에도 현재 크기로 콜백이 한 번 호출됩니다. 초기 렌더링을 겸해서 쓸 수 있습니다.
- 컴포넌트의 `disconnectedCallback`에서 `disconnect()`를 호출해 관찰을 끝냅니다.

**흔한 실수:** 버퍼 크기를 바꾸는 것을 잊고 CSS 크기만 키우는 것입니다. 그리기 버퍼가 늘어난 CSS 박스에 맞춰 확대되어 흐릿하게 보입니다. WebGL이라면 버퍼를 바꾼 뒤 `gl.viewport(0, 0, w, h)`도 다시 호출합니다.

## WebGL / WebGPU 개요

브라우저의 GPU 그래픽 API는 두 세대가 공존합니다. 둘 다 `canvas`에 그리고 Worker에서도 쓸 수 있으며(Worker는 54편), 2D 그리기용 Canvas 2D(52편)와 달리 셰이더 프로그램을 직접 작성합니다.

| 항목 | WebGL / WebGL2 | WebGPU |
|------|----------------|--------|
| 바탕 | OpenGL ES 2.0 / 3.0 | Metal·Vulkan·Direct3D 12 같은 현대 네이티브 API |
| 컨텍스트 | `getContext('webgl')`, `getContext('webgl2')` | `getContext('webgpu')`, `navigator.gpu` |
| 셰이더 언어 | GLSL ES | WGSL |
| 범용 계산 | 어려움 | 컴퓨트 파이프라인 지원 |
| 지원 | Baseline | 미Baseline |

한 `canvas`에는 컨텍스트 종류를 하나만 만들 수 있습니다. 같은 종류로 다시 `getContext`를 부르면 같은 객체를, 다른 종류로 부르면 `null`을 받습니다.

### WebGL2 컨텍스트

`WebGL2RenderingContext`는 OpenGL ES 3.0에 대응하고 WebGL 1의 모든 멤버를 구현합니다. 2021년 9월부터 Baseline입니다. 인스턴스 그리기, Vertex Array Object, Uniform Buffer, 3D 텍스처, 다중 렌더 타깃, Transform Feedback이 추가되었습니다.

```js
const gl = canvas.getContext('webgl2')
if (!gl) {
  // 지원하지 않으면 null. 대체 렌더러나 안내를 쓴다
}
gl.clearColor(0.1, 0.1, 0.2, 1)
gl.clear(gl.COLOR_BUFFER_BIT)
```

- GPU 컨텍스트는 시스템 사정으로 사라질 수 있습니다. 이때 캔버스에 `webglcontextlost` 이벤트가, 복구되면 `webglcontextrestored` 이벤트가 발생합니다. `gl.isContextLost()`로 상태를 확인합니다.
- 복구된 뒤에는 이전 텍스처와 버퍼가 모두 무효이므로 상태를 초기화하고 리소스를 다시 만들어야 합니다.
- 컨텍스트가 더 필요 없으면 `WEBGL_lose_context` 확장으로 명시적으로 해제할 수 있습니다. 페이지를 떠날 때 하려고 `unload` 핸들러를 달 필요는 없습니다.
- 캔버스 렌더링을 워커로 옮기려면 `OffscreenCanvas`를 씁니다(2023년 3월 Baseline).

### WebGPU

WebGPU는 WebGL의 후속 GPU API입니다. HTTPS 같은 보안 컨텍스트에서만 쓸 수 있고 지원 여부는 `navigator.gpu`로 확인합니다. 흐름은 어댑터(물리 GPU)를 요청하고, 그 어댑터에서 논리 장치를 요청하는 두 단계입니다.

```js
if (!navigator.gpu) throw new Error('WebGPU 미지원')
const adapter = await navigator.gpu.requestAdapter()
if (!adapter) throw new Error('어댑터 없음')
const device = await adapter.requestDevice()
const ctx = canvas.getContext('webgpu')
ctx.configure({
  device,
  format: navigator.gpu.getPreferredCanvasFormat(),
})
```

- **지원 상태: 미Baseline.** web-features 3.40.1 기준으로 Chrome·Edge 144, Safari 26에서 지원하고 Firefox는 지원 버전이 기록되어 있지 않습니다. 사용할 때는 `navigator.gpu`를 검사하고 WebGL2로 물러서는 점진적 향상으로 씁니다(자세히는 71편).
- 셰이더는 WGSL로 쓰고 `device.createShaderModule`로 만듭니다. 렌더링은 `GPURenderPipeline`, 범용 계산은 `GPUComputePipeline`입니다.
- 오류는 비동기로 보고됩니다. `pushErrorScope`와 `popErrorScope`로 구간별 오류를 받습니다. 유형은 `GPUValidationError`, `GPUOutOfMemoryError`, `GPUInternalError`입니다.
- `requestAdapter`에 `featureLevel: 'compatibility'`를 주면 OpenGL ES 3.1·Direct3D 11급의 구형 그래픽 API 환경도 대상으로 요청합니다.

### WebXR 개요(WebVR 폐기)

WebXR Device API는 VR·AR 장치에 3D 장면을 그리는 표준입니다. 진입점은 `navigator.xr`(`XRSystem`)이고 보안 컨텍스트에서만 쓸 수 있습니다. WebVR은 VR 전용이던 이전 API로 폐기되었고 WebXR이 대체합니다.

- 세션 모드는 `inline`(2D 화면 안), `immersive-vr`, `immersive-ar` 세 가지입니다. `navigator.xr.isSessionSupported(mode)`가 Promise로 지원 여부를 알려 줍니다.
- 세션 시작은 `requestSession(mode)`입니다. 사용자 클릭 같은 동작 안에서 호출하는 것이 일반적입니다.
- 렌더링은 `XRSession`의 프레임 루프에서 `XRFrame`마다 그립니다. 그리기 자체는 WebGL(`XRWebGLLayer`)로 합니다.
- **지원 상태: 미Baseline.** web-features 3.40.1 기준으로 `webxr-device`는 Chrome·Edge 79부터 지원하고 Firefox·Safari는 기록이 없습니다.

```js
if (navigator.xr) {
  const xr = navigator.xr
  const ok = await xr.isSessionSupported('immersive-vr')
  button.hidden = !ok // 지원할 때만 진입 버튼을 보임
}
```

## 핵심 정리

- SVG 요소는 `createElementNS`와 SVG 네임스페이스로 만들며, `createElement`로 만들면 `HTMLUnknownElement`가 되어 그려지지 않습니다.
- `viewBox`가 SVG 좌표계를 정하고 `preserveAspectRatio`(기본 `xMidYMid meet`)가 뷰포트 비율 차이를 처리합니다.
- 화면 좌표를 SVG 좌표로 바꿀 때는 `getScreenCTM().inverse()`를 쓰고, `getBBox()`는 요소 자신의 사용자 좌표계 값이라 변환을 반영하지 않습니다.
- 의미 있는 SVG는 `role="img"`와 `title`·`aria-labelledby`로 이름을 주고, 장식 SVG는 `aria-hidden`으로 숨깁니다.
- 캔버스·WebGL은 `ResizeObserver`로 그리기 버퍼 크기를 직접 맞춰야 선명하며, SVG는 viewBox 덕분에 대부분 CSS 크기만으로 해결됩니다.
- WebGL2는 Baseline 2021이고 WebGPU와 WebXR은 미Baseline이라 기능 검사와 대체 경로가 필요합니다. WebVR은 폐기되었습니다.
