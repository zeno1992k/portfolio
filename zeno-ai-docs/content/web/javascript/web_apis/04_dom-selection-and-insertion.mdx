## getElementById와 getElementsBy*

### getElementById

`document.getElementById(id)`는 id가 일치하는 요소를 하나 반환하고, 없으면 `null`을 반환합니다. 예외는 던지지 않습니다.

```js
document.getElementById('app')   // <div id="app"> 또는 null
document.getElementById('#app')  // null (# 는 id의 일부가 아님)
document.getElementById('App')   // null (대소문자 구분)
```

- 메서드는 `Document`와 `DocumentFragment`에만 있습니다. 요소에는 `getElementById`가 없으므로 범위를 좁히려면 `querySelector`를 씁니다.
- 문서에 연결된 트리만 검색합니다. `createElement`로 만들고 아직 넣지 않은 요소는 찾지 못합니다.
- id가 중복되면 트리 순서(문서 위에서 아래)로 첫 번째 요소를 반환합니다.
- 섀도 트리 안의 요소는 `document`로 찾지 못합니다(자세히는 21편).
- id가 있는 요소는 `window.id이름` 전역 프로퍼티로도 노출됩니다. 변수 선언 없이 값이 생기는 것처럼 보이므로 의존하지 않습니다.

### getElementsBy* (TagName, ClassName, Name)

| 메서드 | 기준 | 반환 | 호출 위치 |
|--------|------|------|-----------|
| `getElementsByTagName(name)` | 태그 이름 | live `HTMLCollection` | Document, Element |
| `getElementsByClassName(names)` | 클래스 | live `HTMLCollection` | Document, Element |
| `getElementsByName(name)` | `name` 속성 | live `NodeList` | Document만 |

```js
document.getElementsByTagName('li')     // 모든 li
document.getElementsByTagName('*')      // 모든 요소
document.getElementsByClassName('a b')  // a와 b를 모두 가진 요소
menu.getElementsByTagName('a')          // menu의 후손 a만
```

- `getElementsByClassName`에 공백으로 여러 클래스를 주면 AND 조건입니다. 하나라도 빠진 요소는 제외됩니다.
- HTML 문서에서 `getElementsByTagName`은 HTML 요소의 태그 이름을 대소문자 구분 없이 비교합니다. SVG 요소는 대소문자를 구분합니다.
- 요소에서 호출하면 그 요소의 후손만 대상이며 자기 자신은 포함하지 않습니다.
- 라디오·체크박스 그룹을 이름으로 모을 때 `getElementsByName`을 씁니다.

### 라이브 컬렉션과 정적 컬렉션

live 컬렉션은 DOM이 바뀌면 이미 받아 둔 컬렉션의 내용도 따라 바뀝니다. 정적 컬렉션은 호출 시점의 스냅샷입니다.

| 출처 | 타입 | live | `forEach` |
|------|------|------|-----------|
| `getElementsBy*`, `children`, `document.forms` 등 | `HTMLCollection` | O | 없음 |
| `childNodes`, `getElementsByName` | `NodeList` | O | 있음 |
| `querySelectorAll` | `NodeList` | X | 있음 |

- `HTMLCollection`에는 `namedItem(name)`이 있어 id나 `name` 속성으로 항목을 꺼냅니다. 배열 메서드(`map`, `filter`)는 없으므로 `Array.from`이나 전개 연산자로 변환합니다.
- `HTMLCollection`은 요소만 담고, `NodeList`는 텍스트·주석 노드도 담을 수 있습니다.

live 컬렉션을 순회하며 조건에서 벗어나는 변경을 하면 항목을 건너뜁니다.

```js
// class="on" 요소가 4개
const items = document.getElementsByClassName('on')
for (const el of items) el.classList.remove('on')
items.length // 2 — ❌ 지울 때마다 컬렉션이 줄어 하나씩 건너뜀

Array.from(items).forEach((el) => el.classList.remove('on'))
// ✅ 복사본을 순회하면 모두 제거
```

## querySelector와 querySelectorAll

`querySelector(selectors)`는 선택자와 일치하는 첫 요소를 반환하고, `querySelectorAll(selectors)`는 일치하는 모든 요소를 정적 `NodeList`로 반환합니다. 일치하는 요소가 없으면 각각 `null`과 빈 `NodeList`입니다.

```js
document.querySelector('#app .card')  // 첫 .card 또는 null
document.querySelectorAll('li.on')         // NodeList (정적)
card.querySelector('h2')                   // card 후손 중 첫 h2
document.querySelectorAll('h1, h2, h3')    // 선택자 목록 (문서 순서)
```

- `Document`, `DocumentFragment`, `Element`에서 호출할 수 있습니다.
- 결과는 항상 트리 순서(깊이 우선, 문서 위에서 아래)입니다. 선택자 목록에서 앞에 쓴 선택자의 결과가 먼저 나오지 않습니다.
- 요소에서 호출해도 선택자는 문서 전체를 기준으로 평가하고, 결과만 그 요소의 후손으로 제한합니다.

```js
// <div id="a"><section id="b"><p>x</p></section></div>
const b = document.getElementById('b')
b.querySelectorAll('div p').length // 1 (div는 b의 조상)
```

- `:hover`, `:checked` 같은 상태 선택자는 호출 시점의 상태로 평가합니다.
- 의사 요소(`p::before`)는 구문은 유효하지만 어떤 요소와도 일치하지 않아 `null`을 반환합니다.
- 반환된 노드는 실제 DOM 노드이므로 하나를 고쳐도 다른 곳에서 보이는 노드가 바뀝니다. 정적인 것은 목록뿐입니다.
- `NodeList`는 `forEach`, `entries`, 반복자를 지원하지만 `map`은 없습니다. 변환은 `Array.from(list, fn)`을 씁니다.

선택 API 선택 기준은 다음과 같습니다.

| 상황 | 선택 |
|------|------|
| id 하나를 안다 | `getElementById` |
| 복합 조건, 중첩 조건 | `querySelector(All)` |
| 지금 시점의 스냅샷을 순회하며 DOM을 바꾼다 | `querySelectorAll` |
| 이후 추가되는 요소까지 자동 반영되길 원한다 | `getElementsBy*` |

## 선택자 오류(SyntaxError)와 :scope

선택자 문자열이 문법에 맞지 않으면 `querySelector`, `querySelectorAll`, `matches`, `closest`는 이름이 `SyntaxError`인 `DOMException`을 던집니다. 값이 없는 경우처럼 반환값으로 알려 주지 않습니다.

```js
try {
  document.querySelector('#1a') // 숫자로 시작하는 id
} catch (e) {
  e instanceof DOMException     // true
  e.name                        // 'SyntaxError'
}
```

`SyntaxError`가 나는 대표 경우는 다음과 같습니다.

- 빈 문자열(`''`), 끝에 쉼표가 남은 목록(`'a,'`)
- 숫자로 시작하는 `#id`·`.class`(`'#1a'`, 이스케이프가 필요 — 아래 절)
- 알 수 없는 의사 클래스, 닫지 않은 괄호나 따옴표
- 선택자가 `>`, `+`, `~` 결합자로 시작하는 상대 선택자(`'> li'`)

선택자는 사용자 입력이나 서버 데이터로 조립하는 경우가 많습니다. 이때는 `try...catch`로 감싸거나 값을 이스케이프합니다.

`:scope`는 선택자 평가의 기준점입니다.

| 호출 위치 | `:scope`가 가리키는 것 |
|-----------|------------------------|
| `element.querySelector(All)` | 그 요소 |
| `document.querySelector(All)` | 루트 요소 `html` |
| `element.matches()`, `element.closest()` | 그 요소 |

```js
const ul = document.querySelector('ul.menu')
ul.querySelectorAll('li')           // 중첩된 목록의 li까지 전부
ul.querySelectorAll(':scope > li')  // ul의 직계 자식 li만
ul.querySelectorAll('> li')         // SyntaxError
ul.children                         // 직계 자식 요소 (선택자 불필요)
```

`'ul > li'`처럼 요소 이름으로 쓰면 중첩 목록 안의 `ul > li`도 일치하므로 직계 자식 제한이 되지 않습니다. 기준 요소에 한정하려면 `:scope`를 씁니다.

`:is()`와 `:where()`는 목록 안의 잘못된 항목을 무시하는 관대한 선택자 목록(forgiving selector list)을 받습니다. 그 바깥의 일반 선택자 목록은 하나만 틀려도 전체가 `SyntaxError`입니다.

## 특수문자 id와 CSS.escape()

`CSS.escape(value)`는 문자열을 CSS 식별자로 안전하게 바꿔 선택자에 끼워 넣을 수 있게 합니다. HTML5의 id는 공백을 뺀 거의 모든 문자를 허용하지만, CSS 식별자는 숫자 시작, `.`, `:` 등을 허용하지 않기 때문에 선택자에 넣으려면 이스케이프가 필요합니다.

```js
CSS.escape('a.b')   // 'a\\.b'  (문자열 값은 a\.b)
CSS.escape('1a')    // '\\31 a' (첫 숫자는 코드 포인트로 이스케이프)
CSS.escape('a b')   // 'a\\ b'
CSS.escape('--x')   // '--x'    (이스케이프 불필요)

document.querySelector(`#${CSS.escape(id)}`) // ✅
document.querySelector(`#${id}`)  // ❌ id가 '1a'면 SyntaxError
```

- 가장 단순한 회피책은 선택자를 아예 쓰지 않는 것입니다. `getElementById(id)`는 id를 문자열 그대로 비교하므로 이스케이프가 필요 없습니다.
- 속성 선택자 값에도 사용합니다: `` `a[href="#${CSS.escape(hash)}"]` ``.
- `CSS.escape`는 Baseline 널리 지원(2020년 1월부터)입니다. 널 문자(`'\0'`)는 U+FFFD로 바꿉니다.
- 이스케이프는 선택자 문법 오류를 막을 뿐, 사용자 입력을 신뢰할 수 있게 만들지는 않습니다.

## matches와 closest

`element.matches(selectors)`는 그 요소가 선택자와 일치하는지 불리언으로 반환하고, `element.closest(selectors)`는 자기 자신부터 조상 방향으로 올라가며 처음 일치하는 요소를 반환합니다. 일치하는 요소가 없으면 `null`입니다.

```js
el.matches('.card.active')   // true 또는 false
el.matches(':hover')         // 호출 시점의 상태
el.closest('.card')          // 자신 포함, 위로 탐색
el.parentElement?.closest('.card') // 자신 제외
```

- 두 메서드 모두 선택자 오류에는 `SyntaxError`를 던집니다. `closest`는 Baseline 널리 지원(2017년 4월부터)입니다.
- `closest`는 자기 자신이 일치하면 자기 자신을 반환합니다. 조상만 찾으려면 `parentElement`에서 호출합니다.
- 올라가는 경로는 일반 트리 조상이며 섀도 경계를 넘어 호스트로 이어지지 않습니다.
- 과거의 접두사 이름(`webkitMatchesSelector`, `msMatchesSelector`)은 현재 `matches`로 대체되었습니다.

이벤트 위임에서는 `closest`로 클릭된 위치에서 올라가 대상 요소를 찾습니다(이벤트는 07편).

```js
list.addEventListener('click', (e) => {
  const item = e.target.closest('li')
  if (!item || !list.contains(item)) return // ✅ 바깥 li 제외
  console.log(item.dataset.id)
})
```

`closest`는 `list` 바깥의 조상 `li`까지 올라가 일치시킬 수 있으므로 `list.contains(item)` 검사를 함께 둡니다.

## createElement

`document.createElement(localName)`은 해당 이름의 요소 노드를 만들어 반환합니다. 만들어진 요소는 문서 트리에 연결되지 않은 상태라 화면에 나타나지 않습니다.

```js
const card = document.createElement('div')
card.isConnected              // false
card.parentNode               // null
card.ownerDocument === document // true
document.body.append(card)    // 이제 화면에 나타난다
```

- HTML 문서에서 이름은 소문자로 바뀝니다. `createElement('DIV')`의 `localName`은 `'div'`이고 `tagName`은 `'DIV'`입니다.
- 알 수 없는 이름은 `HTMLUnknownElement`, 하이픈이 든 유효한 커스텀 요소 이름은 정의 전까지 `HTMLElement`입니다. 이미 정의된 커스텀 요소는 `createElement` 시점에 생성자가 실행됩니다(자세히는 17편).
- 이름에 공백이나 `1a`처럼 유효하지 않은 문자가 있으면 `InvalidCharacterError` `DOMException`이 발생합니다.
- 두 번째 인수 `{ is: 'x-name' }`은 기존 요소를 확장하는 커스터마이즈드 빌트인용입니다(자세히는 17편).
- SVG처럼 HTML이 아닌 네임스페이스의 요소는 `createElementNS(namespace, name)`으로 만듭니다(자세히는 53편).
- 텍스트와 주석 노드는 `createTextNode(text)`, `createComment(text)`로 만듭니다.
- 다른 문서(`createHTMLDocument`로 만든 문서 등)가 만든 노드를 현재 문서에 넣으면 자동으로 현재 문서로 이전(adopt)됩니다.

## append·prepend·before·after

네 메서드는 노드와 문자열을 여러 개 받아 지정한 위치에 삽입하고 `undefined`를 반환합니다.

| 메서드 | 정의된 곳 | 삽입 위치 |
|--------|-----------|-----------|
| `parent.append(...)` | `ParentNode` | 마지막 자식 뒤 |
| `parent.prepend(...)` | `ParentNode` | 첫 자식 앞 |
| `node.before(...)` | `ChildNode` | 바로 앞 형제 자리 |
| `node.after(...)` | `ChildNode` | 바로 뒤 형제 자리 |

- `ParentNode`는 `Document`, `DocumentFragment`, `Element`입니다. `ChildNode`는 `Element`, 텍스트·주석 같은 `CharacterData`, `DocumentType`입니다.
- `before`와 `after`는 대상의 부모가 없으면 아무것도 하지 않습니다. 예외도 없습니다.

```js
list.append(li1, 'text', li2)  // 한 번에 여러 개, 문자열 허용
list.prepend(li0)              // 맨 앞
li1.before(li0)                // li1 바로 앞
li1.after(li2)                 // li1 바로 뒤
```

문자열은 HTML이 아니라 텍스트 노드로 들어갑니다. 태그가 해석되지 않고 문자 그대로 보이며, 그래서 주입 위험이 없습니다(HTML 문자열은 05편).

```js
box.append('<b>x</b>') // 화면에 <b>x</b> 문자 그대로 표시
box.append(null)       // 텍스트 'null' 추가 — 문자열로 변환됨
box.append(5)          // 텍스트 '5'
```

구형 메서드와 비교하면 다음과 같습니다.

| 메서드 | 인수 | 반환 |
|--------|------|------|
| `append(...nodes)` | 노드·문자열 여러 개 | `undefined` |
| `appendChild(node)` | 노드 1개만 | 삽입한 노드 |
| `insertBefore(node, ref)` | 노드 1개, 기준 노드(`null`이면 끝) | 삽입한 노드 |

- 이미 트리에 있는 노드를 삽입하면 복사가 아니라 이동입니다. 원래 위치에서 제거된 뒤 새 위치에 들어갑니다. 같은 노드를 두 곳에 넣으려면 `cloneNode(true)`로 복제합니다.
- 제거 후 삽입이므로 이동한 요소는 상태를 잃습니다. iframe이 다시 로드되고, 포커스가 사라지고, CSS 애니메이션이 처음부터 다시 시작합니다. 이 문제를 피하는 방법이 아래의 `moveBefore`입니다.
- 노드를 자기 자신이나 자기 후손 안에 넣으면 `HierarchyRequestError`입니다.
- 여러 인수는 적은 순서대로 삽입됩니다.

## replaceWith와 remove

`node.replaceWith(...nodes)`는 노드를 인수로 받은 노드·문자열로 바꾸고, `node.remove()`는 노드를 부모에서 떼어 냅니다. 둘 다 `ChildNode`의 메서드이고 `undefined`를 반환합니다.

```js
old.replaceWith(a, b)   // old 자리에 a, b
old.replaceWith('text') // 텍스트로 교체
old.replaceWith()       // remove()와 같음
el.remove()             // 부모가 없으면 아무 일도 안 함
```

- 부모가 없는 노드에서 호출하면 예외 없이 아무것도 하지 않습니다.
- 구형 `parent.removeChild(child)`는 `child`가 자식이 아니면 `NotFoundError`를 던지고 제거한 노드를 반환합니다. `parent.replaceChild(newNode, oldNode)`는 교체된 `oldNode`를 반환합니다.
- 제거된 요소는 사라지지 않고 메모리에 남아 다시 삽입할 수 있습니다. 이벤트 리스너와 프로퍼티도 그대로이며, 어딘가에서 참조하는 한 가비지 컬렉션 대상이 되지 않습니다(자세히는 67편).
- 포커스를 가진 요소를 제거하면 포커스를 잃습니다.

## DocumentFragment와 replaceChildren

`DocumentFragment`는 문서 트리에 연결되지 않은 임시 노드 컨테이너입니다. `document.createDocumentFragment()` 또는 `new DocumentFragment()`로 만듭니다. 여기에 요소를 조립한 뒤 한 번에 삽입합니다.

```js
const frag = document.createDocumentFragment()
for (const name of names) {
  const li = document.createElement('li')
  li.textContent = name
  frag.append(li)
}
list.append(frag)       // frag의 자식들이 list로 이동
frag.childNodes.length  // 0 — 삽입 후 조각은 빈다
```

- 조각을 삽입하면 조각 자체는 들어가지 않고 그 자식들이 이동합니다.
- 조각 안에서의 변경은 화면에 영향이 없습니다. 연결된 부모에 삽입은 한 번만 일어나므로 MutationObserver 기록도 한 건입니다(옵저버는 43편).
- `append(...nodes)`처럼 노드를 여러 개 넘기면 내부적으로 조각을 만들어 한 번에 삽입합니다. 배열이 있다면 조각 없이 `list.append(...items)`로 충분합니다.
- `DocumentFragment`는 `getElementById`, `querySelector(All)`, `children`, `append` 등을 가집니다. `template` 요소의 `content`도 조각입니다(자세히는 22편).
- 삽입 사이에 `offsetHeight` 같은 레이아웃 값을 읽으면 강제 레이아웃이 반복됩니다(자세히는 06편). 읽기와 쓰기를 분리하는 것이 조각 사용보다 큰 영향을 줍니다.

`replaceChildren(...nodes)`는 모든 자식을 한 번에 인수의 노드·문자열로 교체합니다.

```js
list.replaceChildren()           // 자식 모두 제거
list.replaceChildren(a, b, 'x')  // 자식을 a, b, 텍스트 x로 교체

const rows = [...tbody.children]
rows.sort((p, q) =>
  p.textContent.localeCompare(q.textContent))
tbody.replaceChildren(...rows)   // 정렬 순서로 재배치
```

- `ParentNode`(Document, DocumentFragment, Element)에 있고 Baseline 널리 지원(2020년 10월부터)입니다.
- 인수를 먼저 하나의 조각으로 묶은 뒤 기존 자식을 지우므로, 기존 자식을 인수로 다시 넘겨 재배치할 수 있습니다.
- 삽입 가능 여부를 먼저 검사하므로 `HierarchyRequestError`가 나면 기존 자식은 그대로 남습니다.
- 인수 개수에는 엔진별 한도가 있어 매우 큰 배열을 전개하면 `RangeError`가 날 수 있습니다.
- 비우기만 할 때 `innerHTML = ''` 대신 `replaceChildren()`을 쓰면 HTML 문자열을 다루지 않는다는 의도가 분명합니다.

## insertAdjacentElement·insertAdjacentText

`insertAdjacentElement(where, element)`와 `insertAdjacentText(where, text)`는 기준 요소를 중심으로 네 위치 중 하나에 요소 또는 텍스트를 삽입합니다.

| `where` | 위치 | 같은 동작 |
|---------|------|-----------|
| `'beforebegin'` | 요소 바로 앞(형제) | `el.before(x)` |
| `'afterbegin'` | 요소 안, 첫 자식 앞 | `el.prepend(x)` |
| `'beforeend'` | 요소 안, 마지막 자식 뒤 | `el.append(x)` |
| `'afterend'` | 요소 바로 뒤(형제) | `el.after(x)` |

```js
p.insertAdjacentElement('beforeend', span) // span 반환
p.insertAdjacentText('afterbegin', 'Hi')   // 반환값 없음
p.insertAdjacentText('middle', 'x')        // SyntaxError
```

- `insertAdjacentElement`는 삽입한 요소를 반환합니다. `beforebegin`·`afterend`인데 기준 요소에 부모가 없으면 삽입하지 않고 `null`을 반환합니다. `insertAdjacentText`는 항상 `undefined`입니다.
- `where`는 ASCII 대소문자를 구분하지 않지만, 위 네 값이 아니면 `SyntaxError`입니다.
- `insertAdjacentText`는 HTML을 해석하지 않고 텍스트 노드를 만듭니다. HTML 문자열을 넣는 `insertAdjacentHTML`은 05편에서 다룹니다.
- 새 코드에서는 의도가 읽히는 `append`·`before` 계열이 간결합니다. `insertAdjacent*`는 위치를 문자열 하나로 바꿔 쓸 수 있을 때와 요소를 반환받고 싶을 때 쓸 만합니다.

## moveBefore로 상태 보존 이동

`parent.moveBefore(node, child)`는 노드를 제거했다 다시 넣지 않고 한 번의 연산으로 이동시킵니다. 이동하는 요소의 상태가 유지됩니다. 지원 상태는 미Baseline입니다.

| 엔진 | 지원 |
|------|------|
| Chrome·Edge | 133부터 |
| Firefox | 144부터 |
| Safari | 27까지 미지원 |

```js
// child 앞으로 node 이동. child가 null이면 맨 끝
parent.moveBefore(node, child)
parent.moveBefore(node, null) // 두 번째 인수 생략 불가(TypeError)
```

`insertBefore`나 `append`로 이동하면 잃는 다음 상태가 `moveBefore`에서는 유지됩니다.

- iframe의 로드 상태(다시 로드되지 않음)
- 포커스와 `:active` 같은 상호작용 상태
- 진행 중인 CSS 애니메이션·전환
- 전체 화면, 열린 popover, 모달 `dialog` 상태(자세히는 44편)

규칙과 예외는 다음과 같습니다.

- `ParentNode`(Element, Document, DocumentFragment)의 메서드이고, 이동할 수 있는 노드는 요소와 `CharacterData`입니다. 부모가 달라도 같은 트리 안이면 이동할 수 있습니다.
- 이동 전후가 같은 트리에 있어야 합니다. 문서에 연결된 노드와 연결되지 않은 노드 사이, 서로 다른 문서 사이의 이동은 `HierarchyRequestError`입니다. 그래서 문서에 연결된 부모에 새로 만든 노드를 넣는 용도로는 쓸 수 없습니다.
- 이동 대상이 새 부모의 조상이면 `HierarchyRequestError`, `child`가 새 부모의 자식이 아니면 `NotFoundError`입니다.
- 커스텀 요소는 `disconnectedCallback`·`connectedCallback` 대신 `connectedMoveCallback`을 받습니다(자세히는 18편).
- 미Baseline이므로 지원 여부를 검사하고 대체 경로를 둡니다.

```js
function move(parent, node, ref) {
  if ('moveBefore' in parent) parent.moveBefore(node, ref)
  else parent.insertBefore(node, ref) // 상태는 초기화된다
}
```

키가 있는 목록을 재정렬하는 렌더러가 주 사용처입니다(자세히는 80편).

## Document 속성

`document`가 문서 전체의 구조와 메타 정보를 노출하는 속성 중 자주 쓰는 것들입니다.

| 속성 | 반환 | 비고 |
|------|------|------|
| `documentElement` | 루트 요소(`html`) | 빈 문서면 `null` |
| `head` | `head` 요소 | |
| `body` | `body` 요소 | 프레임셋 문서면 `frameset` |
| `title` | 문자열 | 읽기·쓰기 |
| `referrer` | 이전 페이지 URL | 없으면 `''` |
| `URL` | 현재 문서 URL | 읽기 전용 문자열 |
| `characterSet` | 문서 인코딩 | 보통 `'UTF-8'` |
| `contentType` | MIME 타입 | HTML이면 `'text/html'` |
| `scrollingElement` | 문서를 스크롤하는 요소 | 모드에 따라 다름 |

```js
document.documentElement.tagName // 'HTML'
document.title = '새 제목'        // <title> 변경
document.URL  // 'https://example.com/a?x=1#top'
document.characterSet             // 'UTF-8'
document.contentType              // 'text/html'
```

- `body`는 파서가 `body`를 만나기 전에는 `null`입니다. `head`에서 지연 없는 스크립트가 `document.body`를 읽으면 `null`입니다(스크립트 로딩은 14편). `body`에 값을 대입할 때 `body`나 `frameset`이 아닌 요소를 넣으면 `HierarchyRequestError`입니다.
- `title` 읽기는 앞뒤 공백을 제거하고 연속 공백을 하나로 줄인 문자열을 반환합니다. `<title> a   b </title>`은 `'a b'`입니다. 쓰기는 `title` 요소가 없을 때 `head`에 새로 만들고, `head`도 없으면 아무 일도 일어나지 않습니다.
- `referrer`는 직접 입력해 들어오면 빈 문자열이고, 값이 있더라도 Referrer-Policy에 따라 출처만 남을 수 있습니다.
- `URL`은 `history.pushState` 이후의 URL을 반영합니다(자세히는 34편). 값을 바꾸려면 `location`을 써야 하며 `document.URL`에는 쓸 수 없습니다.
- `charset`, `inputEncoding`은 `characterSet`의 구형 별칭이므로 쓰지 않습니다.
- `scrollingElement`는 Baseline 널리 지원(2016년 8월부터)입니다. 표준 모드(`document.compatMode === 'CSS1Compat'`)에서는 `documentElement`를 반환합니다. 쿼크 모드(`'BackCompat'`)에서는 스크롤 가능하지 않은 `body`를 반환하고 그렇지 않으면 `null`입니다. 과거에 브라우저마다 `body.scrollTop`과 `documentElement.scrollTop` 중 다른 쪽이 동작하던 문제를 한 속성으로 해결합니다.

```js
document.scrollingElement.scrollTop = 0 // 모드와 무관하게 맨 위로
```

## 레거시 컬렉션

`document.forms`, `images`, `links`, `scripts`는 DOM 이전부터 있던 문서 단위 컬렉션입니다. 모두 live `HTMLCollection`입니다.

| 속성 | 담기는 요소 |
|------|-------------|
| `document.forms` | `form` |
| `document.images` | `img` |
| `document.links` | `href` 속성이 있는 `a`와 `area` |
| `document.scripts` | `script` |

```js
document.forms[0]            // 첫 form
document.forms.login         // id 또는 name이 'login'인 form
document.forms['login']      // 같은 결과
document.links.length        // href가 있는 링크 수
Array.from(document.scripts) // 배열로 변환
```

- 이름 접근(`forms.login`)은 id와 `name` 속성을 모두 대상으로 합니다.
- `getElementsByTagName('a')`와 `links`는 다릅니다. `links`는 `href`가 없는 `a`를 제외하고 `area`를 포함합니다.
- `document.anchors`는 `name` 속성이 있는 `a` 요소를 담지만 사용이 권장되지 않고, `document.applets`는 항상 빈 컬렉션입니다.
- `document['login-form']`처럼 문서 객체에 이름으로 바로 접근하는 방식은 현재나 미래의 `document` 프로퍼티와 충돌할 수 있으므로 `document.forms`를 씁니다.
- 폼의 컨트롤 접근(`form.elements`)은 11편에서 다룹니다.
- `document.all`은 옛 IE 시절의 전체 요소 컬렉션입니다. `typeof document.all`이 `'undefined'`이고 불리언으로 `false`가 되는 예외 객체이므로 새 코드에서 쓰지 않습니다.
- 새 코드에서는 `querySelectorAll('form')`처럼 선택자 기반 API가 일관됩니다. 레거시 컬렉션은 기존 코드를 읽을 때 알아 두면 충분합니다.

## DOMImplementation과 createHTMLDocument

`document.implementation`은 `DOMImplementation` 객체를 반환하며, 현재 문서와 별개의 새 문서를 만드는 데 씁니다.

| 메서드 | 반환 |
|--------|------|
| `createHTMLDocument(title)` | 빈 HTML `Document` |
| `createDocument(ns, qualifiedName, doctype)` | XML `Document` |
| `createDocumentType(name, publicId, systemId)` | `DocumentType` 노드 |
| `hasFeature()` | 항상 `true` (구형 호환) |

```js
const doc = document.implementation.createHTMLDocument('임시')
doc.documentElement.outerHTML
// <html><head><title>임시</title></head><body></body></html>
doc.URL          // 'about:blank'
doc.defaultView  // null (창이 없는 문서)
```

- `createHTMLDocument`는 doctype, `html`, `head`, `body`를 갖춘 문서를 만듭니다. `title` 인수를 주면 `title` 요소를 만들고, 인수를 생략하면 `title` 요소가 없습니다. Baseline 널리 지원(2015년 7월부터)입니다.
- 새 문서는 브라우징 컨텍스트가 없어 비활성(inert)입니다. 스크립트가 실행되지 않고 이미지 같은 리소스를 요청하지 않으며 화면에도 나타나지 않습니다.
- 용도는 문서에 영향을 주지 않는 작업 공간입니다. 문자열을 파싱해 내용을 검사·가공한 뒤 필요한 노드만 현재 문서로 옮깁니다(HTML 문자열 파싱은 05편).

```js
const tmp = document.implementation.createHTMLDocument('')
tmp.body.innerHTML = htmlText          // 파싱만 하고 실행 안 함
const nodes = tmp.querySelectorAll('li')
list.append(...nodes)                  // 현재 문서로 이전(adopt)
```

- 현재 문서에 노드를 옮기는 순간 노드는 활성 상태가 됩니다. 비활성 문서에 파싱했다는 이유만으로 안전해지지 않으며, 살균(sanitize)은 별개의 작업입니다(자세히는 63편).
- 이 문서의 origin은 만든 문서와 같습니다.

## 핵심 정리

- id 하나는 `getElementById`, 조건 검색은 `querySelector(All)`입니다. `getElementsBy*`는 live `HTMLCollection`, `querySelectorAll`은 정적 `NodeList`이며, live 컬렉션을 순회하며 바꾸면 항목을 건너뜁니다.
- 선택자 문법 오류는 `SyntaxError`로 던져집니다. 숫자로 시작하는 id는 `CSS.escape()`가 필요하고, 직계 자식은 `:scope > li`로 선택합니다.
- `matches`는 일치 여부, `closest`는 자신을 포함해 조상 방향으로 첫 일치 요소를 찾습니다.
- `append`·`prepend`·`before`·`after`·`replaceWith`·`remove`는 노드와 문자열을 받는 현대적 방법이고 문자열은 텍스트 노드가 됩니다. 이미 있는 노드를 삽입하면 이동이며 상태가 초기화됩니다.
- `replaceChildren`은 자식을 한 번에 교체하고, `moveBefore`는 상태를 보존하는 이동이지만 Safari는 27까지 미지원입니다.
- `document`는 `body`, `title`, `scrollingElement` 등의 속성과 `forms`·`links` 같은 live 컬렉션을 제공하고, `createHTMLDocument`는 비활성 작업 문서를 만듭니다.
