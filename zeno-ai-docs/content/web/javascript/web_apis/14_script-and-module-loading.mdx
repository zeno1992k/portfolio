## script / async / defer / module

`script` 요소는 HTML 문서에 JavaScript를 넣는 요소입니다. 외부 파일은 `src`로, 인라인 코드는 요소 안에 씁니다. 속성에 따라 파일을 내려받는 시점(fetch)과 실행하는 시점이 달라집니다.

| 형태 | 다운로드 | 실행 | 순서 | HTML 파싱 |
|------|----------|------|------|-----------|
| `<script src>` | 즉시, 파서를 멈춤 | 다운로드 직후 | 문서 순서 | 멈춤 |
| `<script async src>` | 파싱과 병렬 | 준비되는 즉시 | 보장 안 됨 | 실행 중에만 멈춤 |
| `<script defer src>` | 파싱과 병렬 | 파싱이 끝난 뒤 | 문서 순서 | 안 멈춤 |
| `<script type="module">` | 파싱과 병렬(의존 모듈 포함) | 파싱이 끝난 뒤 | 문서 순서 | 안 멈춤 |
| `<script type="module" async>` | 파싱과 병렬(의존 모듈 포함) | 준비되는 즉시 | 보장 안 됨 | 실행 중에만 멈춤 |

- 동기 스크립트(속성 없음)는 파서를 멈추고 그 자리에서 실행합니다. 그 위쪽 DOM만 존재하므로 아래 요소를 찾으면 `null`입니다. `head`에 두면 화면 표시가 지연됩니다.
- `defer`는 파싱이 끝난 뒤 문서에 나타난 순서대로 실행되고, 모두 실행된 뒤에 `DOMContentLoaded`가 발생합니다. 외부 파일(`src`)에만 효과가 있고, 인라인 스크립트에서는 의미가 없습니다.
- `async`는 도착하는 대로 실행해서 순서가 바뀔 수 있습니다. 다른 스크립트에 의존하지 않는 독립 스크립트(분석, 광고)에 맞습니다. `DOMContentLoaded`는 `async` 스크립트를 기다리지 않습니다.
- 모듈 스크립트는 기본이 `defer`처럼 동작합니다. 표준이 `defer` 속성은 모듈 스크립트에 효과가 없다고 적습니다. 인라인 모듈 스크립트도 지연되며, `async`는 외부와 인라인 모듈 모두에 쓸 수 있습니다.
- `async`와 `defer`를 함께 쓰면 `defer`만 아는 오래된 브라우저를 위한 대체로 동작합니다.
- 동적으로 만든 스크립트(`document.createElement('script')`)는 기본적으로 `async`처럼 동작합니다. 삽입 순서대로 실행하려면 삽입 전에 `script.async = false`로 설정합니다.

```html
<script src="a.js" defer></script>
<script src="b.js" defer></script>
<!-- a.js, b.js 순서로 실행, 둘 다 DOMContentLoaded 전 -->
<script src="ad.js" async></script>
<!-- 도착 즉시 실행 -->
```

`type` 속성의 값은 스크립트의 종류를 정합니다.

| 값 | 의미 |
|----|------|
| 생략 또는 JavaScript MIME 타입 | 클래식 스크립트 |
| `module` | ES 모듈 |
| `importmap` | Import Map(JSON, 아래 절) |
| `speculationrules` | Speculation Rules(자세히는 15편) |
| 그 밖의 값 | 실행하지 않는 데이터 블록(예: `application/json`) |

`nomodule` 속성이 있는 스크립트는 모듈을 지원하는 브라우저에서 실행되지 않습니다. 모듈을 모르던 오래된 브라우저에 대체 스크립트를 주는 패턴입니다.

```html
<script type="module" src="main.js"></script>
<script nomodule src="legacy.js"></script>
```

- 그 밖의 `script` 속성: `crossorigin`(CORS 방식 요청), `integrity`(서브리소스 무결성 해시 검사), `referrerpolicy`, `fetchpriority`, `blocking="render"`(렌더링을 막음, 지원 상태는 15편).
- 인라인 스크립트(`src` 없음)에는 `async`와 `defer`가 효과가 없고, 인라인 모듈 스크립트에만 `async`를 쓸 수 있습니다.

**흔한 실수:** `defer`를 인라인 스크립트에 붙이는 것입니다. 무시됩니다. 인라인 코드를 문서 파싱 뒤에 실행하려면 `type="module"`을 쓰거나 `DOMContentLoaded`에서 실행합니다.

## 문서 로딩 이벤트와 스크립트 실행 시점

`document.readyState`는 문서의 로딩 상태를 알려 주는 값이고, 바뀔 때 `readystatechange` 이벤트가 발생합니다.

| `readyState` | 뜻 | 대응 이벤트 |
|--------------|----|-------------|
| `loading` | HTML 파서가 작업 중 | - |
| `interactive` | 파싱이 끝남. `defer`·모듈 스크립트 실행, 이미지·스타일 등은 아직 로딩 중일 수 있음 | 이어서 `DOMContentLoaded` |
| `complete` | 문서와 하위 리소스 로딩이 끝남 | `load` |

- `DOMContentLoaded`는 HTML 파싱이 끝나고 `defer`와 모듈 스크립트 실행이 끝난 뒤에 발생합니다. 이미지, 서브프레임, `async` 스크립트, 스타일시트는 기다리지 않습니다.
- 동기 스크립트와 `defer`·모듈 스크립트는 앞서 파싱된 스타일시트가 로딩될 때까지 기다린 뒤 실행됩니다. 스타일시트가 느리면 스크립트와 `DOMContentLoaded`도 늦어집니다.
- `load`는 이미지와 `async` 스크립트까지 모든 하위 리소스가 끝난 뒤 `window`에서 발생합니다. 이미지 크기가 필요한 코드처럼 꼭 필요할 때만 씁니다.
- `readyState`와 `DOMContentLoaded`는 Baseline 널리 지원(2015년부터)입니다.

`async` 스크립트, 동적 삽입된 스크립트, `await` 이후의 코드는 `DOMContentLoaded`가 이미 지난 뒤 실행될 수 있습니다. 이벤트를 기다리기만 하면 영원히 실행되지 않으므로 상태를 먼저 확인합니다.

```js
function init() { /* DOM 접근 */ }
if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', init)
} else {
  init() // 이미 파싱 끝남
}
```

`document.currentScript`는 지금 실행 중인 `script` 요소를 돌려줍니다. 요소의 `src`나 `data-*` 설정값을 읽을 때 씁니다.

```html
<script src="widget.js" data-id="42"></script>
<!-- widget.js 안에서 -->
<!-- document.currentScript.dataset.id // '42' -->
```

- 모듈 스크립트에서는 `null`입니다. 모듈에서는 `import.meta`를 씁니다(아래).
- 콜백이나 이벤트 핸들러 안에서도 `null`입니다. 최초 실행 시점에만 값이 있으므로 최상위에서 변수에 저장해 둡니다.
- Baseline 널리 지원(2015년부터)입니다.

## ES Modules

ES Modules(ESM)는 JavaScript 파일을 모듈로 나누고 `import`와 `export`로 연결하는 언어 표준 모듈 시스템입니다. 모듈 문법 자체는 ECMAScript 과목에서 다루고, 이 편은 브라우저가 모듈을 불러오는 방식을 다룹니다. 모듈 지원은 Baseline 널리 지원(2018년부터)입니다.

```html
<script type="module" src="main.js"></script>
<script type="module">
  import { name } from './square.js'
</script>
```

클래식 스크립트와 모듈 스크립트의 차이는 다음과 같습니다.

| 항목 | 클래식 스크립트 | 모듈 스크립트 |
|------|-----------------|---------------|
| 스코프 | 최상위 `var`와 함수가 전역에 노출 | 모듈 스코프. 전역에 노출되지 않음 |
| 최상위 `this` | 전역 객체 | `undefined` |
| 엄격 모드 | 선택 | 항상 적용 |
| 실행 시점 | 동기(속성 없으면 즉시) | 기본 지연(defer처럼) |
| 같은 URL 여러 번 | 태그마다 실행 | 한 번만 실행 |
| `import`·`export` | 문법 오류 | 사용 가능 |
| CORS | 요구하지 않음 | 요구함 |

### CORS 요구와 MIME 타입

모듈 스크립트는 CORS 방식으로 요청합니다. 다른 출처의 모듈은 서버가 CORS 응답 헤더로 허용해야 로드됩니다. `file://`로 연 HTML에서 모듈을 불러오면 CORS 오류가 나므로 로컬 서버를 통해 열어야 합니다. 서버는 모듈을 JavaScript MIME 타입(`text/javascript`)으로 응답해야 하고, 다른 타입이면 로드가 거부됩니다(CORS 규칙은 62편).

**흔한 실수:** 모듈을 `file://`로 열었다가 CORS 오류로 안 되는 것입니다. 로컬 개발 서버로 확인합니다.

## import / export

모듈이 다른 모듈의 값을 가져오고 내보내는 문법입니다.

```js
// square.js
export const name = 'square'
export function area(n) { return n * n }
export default class Square {}
```

```js
// main.js
import Square, { name, area as sq } from './square.js'
import * as ns from './square.js'
import './setup.js' // 실행만(부수 효과)
```

- `export`는 이름 있는 내보내기와 `export default`(모듈당 하나)가 있습니다. `import`는 이름 있는 가져오기, 기본값 가져오기, 네임스페이스 가져오기(`* as`), 실행만 하는 가져오기가 있습니다.
- 가져온 값은 라이브 바인딩(live binding)입니다. 내보낸 모듈에서 값이 바뀌면 가져온 쪽에서도 바뀐 값이 보이고, 가져온 쪽에서는 대입할 수 없습니다(`TypeError`).
- `import` 선언은 호이스팅되고 모듈 최상위에만 쓸 수 있습니다. 함수나 블록 안에서는 쓸 수 없습니다.
- 정적 `import`의 지정자(specifier)는 문자열 리터럴만 허용합니다.

모듈 지정자는 세 종류입니다.

| 종류 | 예 | 처리 |
|------|----|------|
| 상대 | `./a.js`, `../b.js`, `/c.js` | 현재 모듈 URL 기준 |
| 절대 | `https://example.com/x.js` | 그대로 |
| 베어(bare) | `lodash` | 브라우저는 그대로 해석하지 못함. Import Map 필요 |

- 브라우저에서는 확장자(`.js`)까지 써야 합니다. 번들러와 달리 확장자를 보충해 주지 않습니다.
- 베어 지정자는 Node.js에서는 `node_modules`에서 찾지만 브라우저는 그런 규칙이 없습니다. 브라우저에서 베어 지정자를 쓰려면 Import Map을 선언합니다(아래).

## Dynamic import()

`import(specifier)`는 모듈을 실행 시점에 불러오는 표현식입니다. 모듈 네임스페이스 객체로 이행되는 Promise를 돌려줍니다. 함수처럼 보이지만 함수가 아니라 문법입니다. Baseline 널리 지원(2020년부터)입니다.

```js
button.addEventListener('click', async () => {
  const mod = await import('./chart.js')
  mod.render()
})
```

- 정적 `import`와 달리 클래식 스크립트에서도 쓸 수 있고 모듈 최상위가 아닌 어디서나 쓸 수 있습니다. 지정자를 변수나 템플릿 문자열로 만들 수 있습니다.
- 기본 내보내기는 네임스페이스 객체의 `default` 키입니다. `const { default: Chart } = await import('./chart.js')`로 받습니다.
- 로딩, 링크, 평가 중 하나라도 실패하면 Promise가 거부됩니다. 동기 예외는 던지지 않습니다.
- 같은 URL은 한 번만 평가되고 이후 호출은 같은 네임스페이스 객체를 돌려줍니다.
- 두 번째 인수로 가져오기 속성을 줍니다. `import('./data.json', { with: { type: 'json' } })`(아래 JSON 모듈).
- 사용자가 기능을 쓸 때만 불러오는 용도(코드 스플리팅, 자세히는 15편)와 조건부 로딩에 씁니다.

**흔한 실수:** 모듈이 `then`이라는 이름의 함수를 내보내는 것입니다. 동적 `import()`가 반환값을 Promise처럼 처리하여 그 `then`을 호출해 버립니다.

## Module graph

모듈 그래프(module graph)는 모듈이 `import`로 서로 의존하는 관계를 방향이 있는 그래프로 본 것입니다. 진입 모듈(`script type="module"`의 모듈)에서 시작해 의존 모듈이 연결됩니다.

로딩은 보통 세 단계로 진행됩니다. 먼저 진입 모듈을 내려받고 안의 `import`를 읽어 필요한 모듈을 모두 찾아 내려받습니다. 다음으로 모듈끼리 연결(link)해 바인딩을 맺고, 마지막으로 의존하는 모듈부터 실행(평가)합니다.

```js
// a.js: import './b.js'; console.log('a')
// b.js: import './c.js'; console.log('b')
// c.js: console.log('c')
// a.js를 진입 모듈로 실행하면 출력: c b a
```

- 같은 URL의 모듈은 모듈 맵에 한 번만 기록되어서 여러 곳에서 import해도 한 번만 실행됩니다. 모듈이 사실상 싱글턴처럼 동작하는 이유입니다.
- 순환 의존은 가능하지만 위험합니다. 라이브 바인딩 덕분에 나중에 값이 채워지면 접근할 수 있고, 초기화 전에 접근하면 `ReferenceError`가 납니다. 두 모듈을 합치거나 공통 코드를 제3의 모듈로 빼서 순환을 없앱니다.
- 최상위 `await`는 모듈 전체를 비동기 함수처럼 만듭니다. 그 모듈을 import한 모듈은 이행될 때까지 실행되지 않고, 관계없는 다른 모듈의 로딩은 막지 않습니다.
- 모듈 그래프가 깊으면 의존 모듈을 발견하는 요청이 연달아 일어나는 폭포(waterfall) 지연이 생깁니다. `modulepreload`로 미리 받아 줄입니다(자세히는 15편).

```js
// getColors.js
const res = await fetch('/colors.json')
export default await res.json()
// 이 모듈을 import한 모듈은 JSON을 받은 뒤 실행됨
```

## import.meta

`import.meta`는 현재 모듈의 메타데이터를 담은 객체입니다. 모듈 안에서만 쓸 수 있고, 모듈이 아닌 곳에서 쓰면 SyntaxError입니다. Baseline 널리 지원(2020년부터)입니다.

```js
console.log(import.meta.url)
// 외부 모듈 파일: 모듈 파일의 전체 URL
// 인라인 모듈: 문서의 URL
```

- `url`은 쿼리와 해시를 포함한 모듈의 전체 URL입니다. 모듈 파일 기준의 상대 경로를 만들 때 씁니다.
- 브라우저에서 파일 위치를 기준으로 자원을 가리킬 때는 `new URL('./a.png', import.meta.url)`로 씁니다. 상대 경로를 그대로 쓰면 문서 URL 기준이 되기 때문입니다.
- 호스트가 속성을 더할 수 있습니다. 브라우저에서 표준인 것은 `url`과 `resolve()`입니다.
- `document.currentScript`는 모듈에서 `null`이므로 `import.meta.url`로 대신합니다.

### import.meta.resolve()

`import.meta.resolve(specifier)`는 지정자가 가리키는 URL을 문자열로 동기적으로 돌려줍니다. 모듈을 불러오지 않고 해석만 하므로 파일이 없어도 오류가 없고, 해석할 수 없으면 예외를 던집니다. Import Map도 반영합니다. Baseline 2023입니다.

```js
const url = import.meta.resolve('./worker.js')
const worker = new Worker(url, { type: 'module' })
const lib = import.meta.resolve('lodash') // import map 반영
```

- `new URL(spec, import.meta.url)`은 베어 지정자와 Import Map을 모릅니다. `import.meta.resolve()`는 `import()`가 쓸 것과 같은 결과를 돌려줍니다.
- 이 메서드는 ECMAScript가 아니라 HTML 표준이 정의합니다.

## Import Maps

Import Map은 모듈 지정자를 실제 URL로 바꾸는 규칙표입니다. `type="importmap"` `script`에 JSON으로 씁니다. 베어 지정자를 브라우저에서 쓸 수 있게 하고, 해시가 붙은 파일명 같은 실제 URL을 코드에서 숨깁니다. Baseline 2023(Chrome 89, Firefox 108, Safari 16.4)입니다.

```html
<script type="importmap">
{
  "imports": {
    "lodash": "/vendor/lodash-es/lodash.js",
    "app/": "/js/app/"
  }
}
</script>
```

```js
import { debounce } from 'lodash'
// /vendor/lodash-es/lodash.js
import { Store } from 'app/store.js'
// /js/app/store.js
```

- `imports`는 지정자에서 URL로의 매핑입니다. 키와 값이 모두 `/`로 끝나면 접두사 매핑이 되어서 그 경로 아래 모든 모듈에 적용됩니다.
- `scopes`는 import하는 모듈의 위치에 따라 다른 매핑을 줍니다. 여러 범위가 맞으면 가장 구체적인(가장 긴) 경로가 적용됩니다.
- `integrity`는 모듈 URL과 서브리소스 무결성 해시(`sha384-...`)를 연결합니다.

```json
{
  "imports": { "sq": "/shapes/sq.js" },
  "scopes": {
    "/legacy/": { "sq": "/legacy/sq-v1.js" }
  },
  "integrity": { "/shapes/sq.js": "sha384-..." }
}
```

- Import Map은 모듈 로딩이 시작되기 전에 처리되어야 하므로 모듈을 가져오는 `script`보다 먼저 선언해야 합니다. 인라인 JSON만 가능하고 `src`, `async`, `defer`는 쓸 수 없습니다.
- `import`와 `import()`에만 적용되고 `<script src>`의 `src`에는 적용되지 않습니다.
- 다중 Import Map(여러 개의 `type="importmap"`을 합치기)은 Baseline이 아닙니다. web-features 데이터 기준으로 Chrome·Edge 133, Safari 18.4부터 지원하고 Firefox는 지원하지 않습니다. 합칠 때 이미 해석된 지정자의 매핑은 나중 맵이 바꾸지 못합니다.
- 오래된 브라우저는 `es-module-shims` 같은 폴리필로 대체할 수 있습니다.

## JSON 모듈

JSON 모듈은 JSON 파일을 `import`로 직접 가져오는 기능입니다. 가져오기 속성(import attributes)으로 `type: 'json'`을 명시해야 합니다. Baseline 2025(Chrome 123, Firefox 138, Safari 17.2)입니다.

```js
import config from './config.json' with { type: 'json' }
console.log(config.title)

const m = await import('./config.json', {
  with: { type: 'json' },
})
```

- JSON은 기본 내보내기(`default`)로 가져옵니다.
- 서버가 JSON MIME 타입(`application/json`)으로 응답해야 합니다. 브라우저는 모듈 형식을 검증하므로 `type: 'json'` 없이 가져오거나 JSON이 아닌 파일이면 실패합니다. 데이터만 가져오려다 코드가 실행되는 일을 막기 위해서입니다.
- 같은 URL의 모듈은 한 번만 평가되므로 객체가 공유됩니다. 한 곳에서 바꾸면 다른 곳에서도 바뀝니다.
- CSS 모듈(`with { type: 'css' }`)은 Baseline이 아닙니다(24편).

## 핵심 정리

- `async`는 도착 즉시 실행(순서 불확정), `defer`와 모듈은 파싱 후 문서 순서로 실행되고 `DOMContentLoaded` 전에 끝나며, 동기 스크립트는 파서를 멈춥니다.
- `readyState`는 `loading`, `interactive`, `complete`이고, `async` 스크립트와 동적 삽입 코드는 이벤트가 지난 뒤 실행될 수 있어 상태를 먼저 확인합니다.
- 모듈 스크립트는 모듈 스코프, 엄격 모드, 기본 지연, 같은 URL은 한 번만 실행, CORS 요구, JavaScript MIME 타입이 특징이고 `file://`에서는 로드되지 않습니다.
- 모듈 그래프는 의존 모듈부터 실행하고, 순환은 초기화 전 접근 시 `ReferenceError`이며, 동적 `import()`는 필요할 때 Promise로 불러옵니다.
- `import.meta.url`은 모듈의 URL, `import.meta.resolve()`는 Import Map까지 반영한 URL 문자열을 동기로 돌려줍니다.
- Import Map은 `imports`·`scopes`·`integrity`로 지정자를 바꾸며 모듈 로딩 전에 선언하고, 다중 Import Map은 미Baseline, JSON 모듈은 `with { type: 'json' }`가 필요하며 Baseline 2025입니다.
