## Canvas 2D

`canvas` 요소는 스크립트로 그림을 그리는 비트맵 영역이고, 2D 그리기는 `CanvasRenderingContext2D`가 맡습니다. 요소는 즉시 모드(immediate mode)입니다. 그린 도형이 객체로 남지 않고 픽셀로만 남아서, 수정하려면 지우고 다시 그립니다. 같은 용도로 객체가 남는 SVG와 비교는 53편에서 다룹니다.

```js
const canvas = document.querySelector('canvas')
const ctx = canvas.getContext('2d')
ctx.fillStyle = 'tomato'
ctx.fillRect(10, 10, 100, 50) // 가로 100, 세로 50 사각형
```

- 기본 크기는 300×150 픽셀입니다. `width`·`height` 속성이 비트맵 크기를 정하고, CSS 크기는 화면에 표시되는 크기입니다. 둘이 다르면 비트맵이 늘어나거나 줄어들어 표시됩니다.
- **`width`나 `height` 속성에 값을 쓰면 비트맵과 그리기 상태가 초기화됩니다.** 같은 값을 다시 써도 마찬가지입니다.
- 좌표계의 원점 `(0, 0)`은 왼쪽 위이고, 오른쪽이 x 증가, 아래쪽이 y 증가이며 기본 단위는 비트맵 픽셀 1개입니다.
- `getContext('2d')`는 같은 캔버스에서 항상 같은 컨텍스트를 반환합니다. 다른 종류(`webgl2` 등)를 이미 얻은 캔버스에 요청하면 `null`입니다(자세히는 53편).
- 두 번째 인수로 옵션을 줍니다.

| 옵션 | 내용 |
|------|------|
| `alpha: false` | 알파 채널을 쓰지 않음. 그리기가 빨라질 수 있음 |
| `willReadFrequently: true` | `getImageData()`를 자주 호출함을 알림(아래 "픽셀 조작") |
| `desynchronized: true` | 이벤트 루프와 그리기를 분리해 지연을 줄임 |
| `colorSpace` | `srgb`(기본) 또는 `display-p3` |

- 지원 상태는 Baseline 널리 지원(2015)입니다.

## 도형과 경로

캔버스가 직접 그리는 기본 도형은 사각형과 경로 두 가지입니다. 다른 도형은 모두 경로로 만듭니다.

| 메서드 | 내용 |
|--------|------|
| `fillRect(x, y, w, h)` | 채운 사각형 |
| `strokeRect(x, y, w, h)` | 윤곽선 사각형 |
| `clearRect(x, y, w, h)` | 영역을 투명하게 지움 |

경로는 `beginPath()`로 시작해 선·곡선을 이어 붙이고 `fill()`이나 `stroke()`로 그립니다.

```js
ctx.beginPath()
ctx.moveTo(20, 20)        // 펜 이동(그리지 않음)
ctx.lineTo(120, 20)
ctx.lineTo(70, 90)
ctx.closePath()           // 시작점으로 연결
ctx.fillStyle = 'skyblue'
ctx.fill()
ctx.lineWidth = 4
ctx.stroke()
```

| 경로 메서드 | 내용 |
|-------------|------|
| `moveTo`, `lineTo` | 점 이동, 직선 |
| `arc(x, y, r, start, end, ccw)` | 원호. 각도는 라디안(도 × π/180) |
| `arcTo(x1, y1, x2, y2, r)` | 두 접선으로 둥근 모서리 |
| `quadraticCurveTo` | 제어점 1개의 곡선 |
| `bezierCurveTo` | 제어점 2개의 곡선 |
| `rect(x, y, w, h)` | 사각형을 경로로 추가 |
| `closePath()` | 현재 하위 경로를 시작점으로 닫음 |

- `fillStyle`과 `strokeStyle`에는 색, 그라디언트, 패턴을 줄 수 있습니다. 선 모양은 `lineWidth`, `lineCap`, `lineJoin` 등으로 정합니다.
- `fill()`은 열린 경로를 자동으로 닫아 채우지만 `stroke()`는 닫지 않습니다. 윤곽을 닫으려면 `closePath()`를 호출합니다.
- `fill()`의 채움 규칙은 `nonzero`(기본)와 `evenodd`입니다. 경로가 겹치거나 구멍이 있을 때 결과가 달라집니다.
- 새 도형을 시작할 때 `beginPath()`를 빼먹으면 이전 경로가 남아서 다시 그려집니다.

**흔한 실수:** 반복문에서 `beginPath()` 없이 `arc()`를 계속 호출하고 매번 `stroke()`하는 것입니다. 이전 원이 그때마다 다시 그려져 선이 점점 두꺼워지고 느려집니다.

### roundRect()와 reset()

`roundRect(x, y, w, h, radii)`는 모서리가 둥근 사각형 하위 경로를 추가합니다. 반지름은 숫자 하나 또는 배열입니다.

```js
ctx.beginPath()
ctx.roundRect(10, 10, 120, 60, 12)
ctx.fill()
```

`ctx.reset()`은 비트맵을 지우고 그리기 상태를 기본값으로 되돌립니다. 크기를 다시 쓰지 않고도 초기화할 수 있습니다.

- 둘 다 Baseline 2023입니다. 시작 버전은 `roundRect()`가 Chrome 99, Firefox 112, Safari 16.4이고 `reset()`이 Chrome 99, Firefox 113, Safari 17.2입니다.

## Path2D와 isPointInPath() 히트 테스트

`Path2D`는 컨텍스트와 분리해 경로를 객체로 만들어 두고 재사용하는 클래스입니다.

```js
const star = new Path2D()
star.moveTo(50, 0)
star.lineTo(60, 35)
star.lineTo(95, 35)
ctx.fill(star)             // 필요할 때마다 그림
ctx.stroke(star)
const icon = new Path2D('M10 10 h 80 v 80 h -80 Z') // SVG
```

- 생성자는 인수 없음, 다른 `Path2D` 복사, SVG 경로 데이터 문자열을 받습니다. `addPath(path, transform)`으로 다른 경로를 이어 붙입니다.
- `ctx.fill(path)`, `ctx.stroke(path)`처럼 경로를 인수로 넘깁니다. 한 경로를 여러 번, 서로 다른 변환 아래서 그릴 수 있습니다.

캔버스에는 그려진 도형을 기억하는 구조가 없어서 클릭한 곳이 어느 도형인지 직접 판별해야 합니다. `isPointInPath()`와 `isPointInStroke()`가 점이 경로의 안쪽(채움)인지, 선 위인지 알려 줍니다.

```js
canvas.addEventListener('click', (e) => {
  const hit = ctx.isPointInPath(star, e.offsetX, e.offsetY)
  if (hit) console.log('별 클릭')
})
```

- 시그니처는 `isPointInPath(x, y, fillRule)`(현재 경로)와 `isPointInPath(path, x, y, fillRule)`입니다. 선 위의 점은 `isPointInStroke()`로 확인합니다.
- 점 좌표는 현재 변환 행렬의 영향을 받지 않는 캔버스 좌표입니다. CSS 픽셀의 `offsetX`·`offsetY`를 그대로 쓰면 비트맵 크기와 CSS 크기가 다른 캔버스에서 어긋나므로 `canvas.width / rect.width` 비율로 변환합니다.
- 여러 도형이 겹치면 그린 순서의 반대로 검사해 맨 위 도형을 찾습니다. 도형이 많으면 영역 분할 같은 별도 구조가 필요합니다.
- 포인터 이벤트 자체는 09편, 키보드로도 조작하게 하려면 캔버스 바깥에 대체 컨트롤이나 `aria` 설명을 둡니다(자세히는 27편).

## 상태 스택(save·restore)과 변환 행렬

컨텍스트는 현재 그리기 상태를 가지고 있습니다. `save()`는 상태 복사본을 스택에 쌓고, `restore()`는 가장 위의 상태를 꺼내 되돌립니다.

```js
ctx.fillStyle = 'black'
ctx.save()
ctx.fillStyle = 'red'
ctx.fillRect(0, 0, 50, 50)    // 빨강
ctx.restore()
ctx.fillRect(60, 0, 50, 50)   // 검정(복원됨)
```

- 저장되는 상태는 변환 행렬, 클리핑 영역, `fillStyle`·`strokeStyle`, `lineWidth`·`lineCap`·`lineJoin`·`miterLimit`·점선 설정, `globalAlpha`, `globalCompositeOperation`, 그림자, 글꼴과 정렬, 이미지 스무딩 설정 등입니다.
- **현재 경로는 저장되지 않습니다.** `restore()`해도 경로가 되돌아가지 않습니다.
- `save()`와 `restore()`는 쌍을 맞춥니다. 함수가 도형 하나를 그릴 때 `save()`로 시작해 `restore()`로 끝내면 호출한 쪽에 상태가 새지 않습니다.

변환은 이후에 그리는 모든 좌표에 적용되는 행렬입니다.

| 메서드 | 내용 |
|--------|------|
| `translate(x, y)` | 원점 이동 |
| `rotate(angle)` | 원점 기준 회전(라디안) |
| `scale(x, y)` | 확대·축소 |
| `transform(a, b, c, d, e, f)` | 현재 행렬에 곱함 |
| `setTransform(a, b, c, d, e, f)` | 현재 행렬을 교체 |
| `resetTransform()` | 항등 행렬로 |
| `getTransform()` | 현재 행렬을 `DOMMatrix`로 반환 |

```js
ctx.save()
ctx.translate(100, 100)   // 회전 중심으로 이동
ctx.rotate(Math.PI / 4)   // 45도
ctx.fillRect(-25, -25, 50, 50) // 중심이 (100, 100)인 사각형
ctx.restore()
```

- 변환은 호출한 순서대로 누적됩니다. `translate` 후 `rotate`와 `rotate` 후 `translate`의 결과가 다릅니다.
- 변환은 이미 그린 그림이 아니라 이후에 그리는 것에 적용됩니다.
- 도형 자체의 중심을 기준으로 회전하려면 그 중심으로 `translate`한 뒤 중심 기준 좌표로 그립니다.

## 합성과 globalAlpha

`globalAlpha`는 이후 그리는 모든 것의 불투명도(0.0–1.0, 기본 1.0)입니다. `globalCompositeOperation`은 새로 그리는 것이 이미 있는 픽셀과 어떻게 합쳐질지 정합니다. 기본값은 `source-over`(위에 덮어 그림)입니다.

| 값 | 결과 |
|----|------|
| `source-over` | 새 그림을 기존 위에 그림(기본) |
| `destination-over` | 새 그림을 기존 뒤에 그림 |
| `source-in` | 겹치는 곳에만 새 그림, 나머지는 투명 |
| `source-atop` | 기존 그림과 겹치는 곳에만 새 그림 |
| `destination-in` | 겹치는 곳의 기존 그림만 남김 |
| `destination-out` | 새 그림이 닿은 곳의 기존 그림을 지움 |
| `lighter` | 색을 더함 |
| `copy` | 새 그림만 남김 |
| `xor` | 겹치는 곳은 투명 |
| `multiply`, `screen`, `overlay` 등 | 블렌드 모드 |

```js
ctx.globalAlpha = 0.5
ctx.fillRect(0, 0, 80, 80)   // 반투명
ctx.globalAlpha = 1
ctx.globalCompositeOperation = 'destination-out'
ctx.beginPath()
ctx.arc(40, 40, 20, 0, Math.PI * 2)
ctx.fill()                    // 원 모양으로 지움(구멍)
```

- `destination-out`은 지우개처럼 쓰고, `destination-in`과 `source-in`은 마스크 효과에 씁니다.
- 합성 연산은 상태에 포함되어 다음 그리기에도 남습니다. 바꾸면 `save()`·`restore()`로 감싸거나 `source-over`로 되돌립니다.
- 색상 요소 연산으로 `hue`, `saturation`, `color`, `luminosity`도 있습니다.

## 텍스트 그리기와 measureText()

`fillText(text, x, y, maxWidth)`와 `strokeText()`가 텍스트를 그립니다. 글꼴은 CSS `font` 속기 문법 문자열로 지정합니다.

```js
ctx.font = 'bold 24px sans-serif'
ctx.textAlign = 'center'     // 기본 start
ctx.textBaseline = 'middle'  // 기본 alphabetic
ctx.fillText('안녕하세요', 150, 75)
```

- `textAlign`의 기본값은 `start`이고 `textBaseline`의 기본값은 `alphabetic`입니다. 정렬 기준점이 `(x, y)`입니다.
- 선택 인수 `maxWidth`를 주면 그 너비에 맞게 글자가 압축됩니다.
- 캔버스 텍스트는 자동으로 줄바꿈되지 않고, 선택하거나 검색할 수 없고 접근성 트리에도 나타나지 않습니다. 중요한 글은 DOM에도 둡니다.

`measureText(text)`는 현재 `font` 기준으로 크기를 잰 `TextMetrics`를 반환합니다. 단위는 CSS 픽셀입니다.

| 속성 | 내용 |
|------|------|
| `width` | 텍스트 폭 |
| `actualBoundingBoxLeft`, `actualBoundingBoxRight` | 기준점에서 실제 글자 상자의 좌·우 끝까지 |
| `actualBoundingBoxAscent`, `actualBoundingBoxDescent` | 기준선에서 실제 글자 상자의 위·아래 끝까지 |
| `fontBoundingBoxAscent`, `fontBoundingBoxDescent` | 기준선에서 글꼴 상자의 위·아래 끝까지 |

```js
const m = ctx.measureText('Hello')
const x = (canvas.width - m.width) / 2 // 가운데 정렬
```

- 글꼴을 바꾼 뒤에 측정합니다. `measureText()`는 호출 시점의 `ctx.font`를 씁니다.
- 줄바꿈은 단어를 이어 가며 `measureText().width`가 영역 폭을 넘는지 검사해 직접 구현합니다.
- 이탤릭처럼 기울어진 글자는 `width`보다 `actualBoundingBox` 값이 정확합니다.
- 웹폰트가 로드되기 전에 그리면 대체 글꼴로 그려지므로 로드 후에 그립니다.

## 이미지 렌더링

`drawImage()`는 이미지, 비디오, 다른 캔버스를 그립니다. 인수 개수에 따라 세 형태입니다.

| 형태 | 내용 |
|------|------|
| `drawImage(image, dx, dy)` | 원본 크기로 그림 |
| `drawImage(image, dx, dy, dw, dh)` | 대상 크기로 늘이거나 줄임 |
| `drawImage(image, sx, sy, sw, sh, dx, dy, dw, dh)` | 원본의 일부(`s…`)를 잘라 대상 영역(`d…`)에 그림 |

- 원본으로 쓸 수 있는 것은 `HTMLImageElement`, `SVGImageElement`, `HTMLVideoElement`, `HTMLCanvasElement`, `ImageBitmap`, `OffscreenCanvas`, `VideoFrame`입니다.
- 이미지는 로드가 끝난 뒤에 그려야 합니다. `load` 이벤트나 `decode()` Promise를 기다립니다.

```js
const img = new Image()
img.src = 'sprite.png'
await img.decode()
ctx.drawImage(img, 0, 0, 32, 32, 100, 100, 64, 64)
```

- 9인수 형태는 스프라이트 시트에서 한 칸을 잘라 그릴 때 씁니다.
- 비디오를 그리면 그 순간의 프레임이 그려집니다. 프레임마다 그릴 때는 `requestVideoFrameCallback()`이 적합합니다(자세히는 50편).
- 이미지 확대 시 스무딩은 `imageSmoothingEnabled`로 끄고 켭니다. 이 설정도 저장되는 상태입니다.
- 크기를 바꿔 그리는 비용이 크므로 자주 쓰는 크기를 미리 만들어 두는 것이 낫습니다.

### createImageBitmap()

`createImageBitmap(source, [sx, sy, sw, sh], [options])`은 소스를 디코딩해 `ImageBitmap`으로 만들어 주는 Promise 함수입니다. `ImageBitmap`은 `drawImage()`에 바로 쓸 수 있는 준비된 비트맵입니다.

```js
const opts = { resizeWidth: 200 }
const bmp = await createImageBitmap(blob, opts)
ctx.drawImage(bmp, 0, 0)
bmp.close() // 메모리 해제
```

- 소스로 `Blob`, `img`, `video`, `canvas`, `ImageData`, `ImageBitmap`, `OffscreenCanvas`, `VideoFrame`을 받습니다.
- 디코딩은 메인 스레드 밖에서 이뤄지고 워커에서도 쓸 수 있습니다. 파일을 읽은 `Blob`을 곧바로 `ImageBitmap`으로 만들면 `img`를 거치지 않아도 됩니다(자세히는 48편).
- 자르기 영역 인수와 `resizeWidth`·`resizeHeight`·`resizeQuality`, `imageOrientation`, `premultiplyAlpha`, `colorSpaceConversion` 옵션이 있습니다.
- `ImageBitmap`은 직접 수정할 수 없고 쓰고 나면 `close()`로 해제합니다.
- Baseline 2023입니다(Safari 17.2).

## 고해상도 Canvas

고밀도 화면(`devicePixelRatio`가 1보다 큰 화면)에서 캔버스를 CSS 크기와 같은 비트맵으로 만들면 늘어난 비트맵이 흐릿하게 보입니다. 비트맵을 `devicePixelRatio`배로 만들고 CSS 크기는 그대로 둡니다.

```js
const dpr = window.devicePixelRatio
const rect = canvas.getBoundingClientRect()
canvas.width = Math.round(rect.width * dpr)
canvas.height = Math.round(rect.height * dpr)
ctx.scale(dpr, dpr)         // 이후 좌표는 CSS 픽셀 기준
canvas.style.width = `${rect.width}px`
canvas.style.height = `${rect.height}px`
```

- `width`·`height`를 쓰면 상태가 초기화되므로 `scale()`은 그 뒤에 호출합니다. 크기를 다시 정할 때마다 `scale()`도 다시 합니다.
- 이렇게 하면 그리는 코드는 CSS 픽셀 좌표를 그대로 씁니다. 대신 `getImageData()` 같은 픽셀 접근과 `isPointInPath()`의 좌표는 비트맵 기준(`dpr`배)입니다.
- 확대·축소나 모니터 이동으로 `devicePixelRatio`가 바뀌면 다시 설정합니다. 요소 크기 변화는 `ResizeObserver`로 감지합니다(자세히는 43편).
- 비트맵이 커지는 만큼 메모리와 그리기 비용이 `dpr`의 제곱에 비례해 늘어납니다. 아주 큰 캔버스는 `dpr` 상한을 둡니다.
- 소수점 좌표는 가장자리가 흐려지고 비용이 늘 수 있어서 가능하면 정수 좌표로 그립니다.

## Animation Loop

캔버스 애니메이션은 매 프레임 지우고 다시 그리는 루프입니다. `requestAnimationFrame()`으로 화면 갱신 직전에 콜백을 실행합니다(자세히는 08편).

```js
let last = 0
let id
function frame(now) {
  const dt = last ? (now - last) / 1000 : 0 // 초
  last = now
  update(Math.min(dt, 0.1))
  ctx.clearRect(0, 0, w, h)
  draw()
  id = requestAnimationFrame(frame)
}
id = requestAnimationFrame(frame)
// 중지: cancelAnimationFrame(id)
```

- 콜백은 한 번만 실행되므로 안에서 다시 등록합니다. 콜백에는 `DOMHighResTimeStamp`가 전달됩니다.
- 이동은 프레임 수가 아니라 경과 시간(`dt`)으로 계산합니다. 프레임 수로 계산하면 주사율이 높은 화면에서 더 빠르게 움직입니다.
- 배경 탭에서는 `requestAnimationFrame()`이 멈춥니다. 돌아왔을 때 `dt`가 커지므로 상한(위 코드의 0.1초)을 둡니다.
- 갱신(`update`)과 그리기(`draw`)를 분리하면 로직을 테스트하고 일시정지하기 쉽습니다.
- 한 프레임 안에서 상태 변경을 줄이고, 그리기 호출을 묶고, `shadowBlur`를 피하고, 변하지 않는 배경은 별도 캔버스에 겹쳐 두면 빨라집니다. 반복해서 쓰는 그림은 다른 캔버스에 미리 그려 `drawImage()`로 복사합니다.
- `setInterval`은 화면 갱신과 맞지 않아서 쓰지 않습니다.
- 정적인 화면은 상태가 바뀔 때만 한 번 그리고 루프를 돌리지 않습니다.

## 픽셀 조작

`getImageData(sx, sy, sw, sh)`는 영역의 픽셀을 `ImageData`로 읽고, `putImageData(imageData, dx, dy)`는 `ImageData`를 캔버스에 씁니다.

```js
const img = ctx.getImageData(0, 0, w, h)
const d = img.data               // Uint8ClampedArray
for (let i = 0; i < d.length; i += 4) {
  d[i] = 255 - d[i]              // R
  d[i + 1] = 255 - d[i + 1]      // G
  d[i + 2] = 255 - d[i + 2]      // B
}                                // A는 그대로
ctx.putImageData(img, 0, 0)
```

- `data`는 픽셀 하나당 R, G, B, A 네 바이트(0–255)가 이어진 배열입니다. 좌표 `(x, y)`의 R 위치는 `(y * width + x) * 4`이고 G, B, A는 +1, +2, +3입니다.
- 배열 이름이 `Clamped`인 것은 0–255 밖의 값을 쓰면 가장자리 값으로 잘리기 때문입니다.
- 좌표와 크기는 비트맵 픽셀 기준이며 변환 행렬의 영향을 받지 않습니다. 캔버스 밖의 영역은 투명한 검정으로 읽힙니다. `getImageData()`는 `globalAlpha`와 합성 연산의 영향도 받지 않습니다.
- `sw`나 `sh`가 0이면 `IndexSizeError`이고, 오염된 캔버스면 `SecurityError`입니다.
- 지문 추적 방지 기능이 켜진 브라우저에서는 읽은 값에 미세한 노이즈가 섞일 수 있습니다.
- `putImageData()`는 픽셀을 그대로 덮어씁니다. `drawImage()`와 달리 합성하거나 변환하지 않습니다.

`getContext('2d', { willReadFrequently: true })`는 읽기를 자주 한다는 신호입니다. 하드웨어 가속 대신 소프트웨어 2D 캔버스를 쓰게 해서 `getImageData()`를 반복 호출할 때 속도와 메모리 사용을 개선합니다. Baseline 2024(Chrome 99, Firefox 28, Safari 18)입니다.

- 읽기가 한두 번이면 쓰지 않습니다. 쓰기가 주인 캔버스에서는 오히려 그리기가 느려질 수 있습니다.
- 큰 이미지의 픽셀 루프는 메인 스레드를 막습니다. 워커로 옮기거나(자세히는 54편) 영역을 나눠 처리합니다.

## toBlob()과 toDataURL()

캔버스 내용을 이미지 파일 형태로 내보냅니다.

| 메서드 | 반환 | 특징 |
|--------|------|------|
| `canvas.toBlob(callback, type, quality)` | 콜백으로 `Blob` | 비동기. 큰 이미지에 적합 |
| `canvas.toDataURL(type, quality)` | `data:` 문자열 | 동기. 문자열이 커짐 |
| `offscreen.convertToBlob(options)` | `Promise<Blob>` | `OffscreenCanvas`용 |

```js
canvas.toBlob((blob) => {
  const url = URL.createObjectURL(blob)
  link.href = url
  link.download = 'drawing.png'
}, 'image/png')
```

- `type`의 기본값은 `image/png`입니다. `image/jpeg`, `image/webp`처럼 손실 압축 형식은 `quality` 값을 받습니다.
- `toBlob()`은 결과가 콜백으로 오므로 Promise로 쓰려면 직접 감쌉니다. 이미지가 크면 `toDataURL()`이 메인 스레드를 길게 막습니다.
- `Blob`은 `URL.createObjectURL()`로 URL을 만들어 다운로드·미리보기에 쓰고 끝나면 `revokeObjectURL()`로 해제합니다(자세히는 48편).
- 투명 영역은 PNG에서는 투명으로 남고, JPEG에서는 검게 변합니다.
- 오염된 캔버스에서는 둘 다 `SecurityError`입니다(아래).

## 오염된 캔버스와 CORS

캔버스는 비트맵마다 origin-clean 플래그를 가집니다. 처음에는 참이고, 허락 없이 다른 출처의 콘텐츠를 그리면 거짓이 되어 캔버스가 "오염(tainted)"됩니다. 오염되면 픽셀을 읽어 내는 길이 막힙니다.

| 막히는 메서드 | 결과 |
|---------------|------|
| `getImageData()` | `SecurityError` |
| `toBlob()`, `toDataURL()` | `SecurityError` |
| `captureStream()` | `SecurityError`(자세히는 51편) |

- 그리는 것 자체는 오염되어도 가능합니다. 읽어 내는 것만 막힙니다.
- 오염되는 경우는 CORS 허가 없이 다른 출처 이미지를 그릴 때, 같은 출처 규칙을 만족하지 않는 `ImageBitmap`·캔버스를 그릴 때, 다른 출처 SVG를 그릴 때입니다.
- 해결은 서버가 `Access-Control-Allow-Origin` 헤더를 보내고, 클라이언트가 `crossorigin` 속성으로 CORS 요청을 하는 것입니다(자세히는 62편).

```js
const img = new Image()
img.crossOrigin = 'anonymous' // src보다 먼저
img.src = 'https://cdn.example.com/photo.jpg'
```

- `crossOrigin` 값은 `anonymous`(자격 증명 없음)와 `use-credentials`입니다. **`src`를 지정하기 전에** 설정해야 합니다.
- `crossOrigin`을 지정했는데 서버가 CORS 헤더를 보내지 않으면 이미지 로드 자체가 실패합니다.
- 오염된 캔버스를 풀려고 하지 말고, CORS가 허용된 이미지로 처음부터 다시 그립니다.

## OffscreenCanvas

`OffscreenCanvas`는 DOM에 붙지 않는 캔버스입니다. 메인 스레드와 워커 양쪽에서 쓸 수 있어서 무거운 그리기를 UI와 분리합니다. Baseline 2023입니다(Chrome 69, Firefox 105, Safari 16.4).

```js
const off = new OffscreenCanvas(200, 100)
const octx = off.getContext('2d')
octx.fillRect(0, 0, 200, 100)
const bitmap = off.transferToImageBitmap() // 효율적 전달
const blob = await off.convertToBlob()
```

- 생성자는 `new OffscreenCanvas(width, height)`이고 `width`·`height`는 읽고 쓸 수 있습니다.
- `transferToImageBitmap()`은 현재 내용을 `ImageBitmap`으로 만들어 줍니다. `HTMLCanvasElement`의 `drawImage()`나 `bitmaprenderer` 컨텍스트로 넘기는 데 씁니다.
- `convertToBlob()`은 Promise로 `Blob`을 만듭니다.
- 일반 캔버스에 미리 그려 두는 용도(스프라이트·배경 캐시)로도 씁니다. 화면에 안 보이는 `canvas` 요소를 만들어 쓰던 방식을 대체합니다.

### transferControlToOffscreen()과 워커 렌더링

`canvas.transferControlToOffscreen()`은 화면의 `canvas` 요소를 자리표시자로 두고 그리는 권한을 `OffscreenCanvas`로 넘깁니다. 이 객체를 워커에 전송해 워커가 그린 결과가 화면의 캔버스에 자동으로 나타납니다.

```js
// 메인 스레드
const off = canvas.transferControlToOffscreen()
const worker = new Worker('render.js')
worker.postMessage({ canvas: off }, [off]) // 소유권 이전
```

```js
// render.js (워커)
onmessage = (e) => {
  const ctx = e.data.canvas.getContext('2d')
  function frame(now) {
    ctx.clearRect(0, 0, 300, 150)
    // ... 그리기
    requestAnimationFrame(frame)
  }
  requestAnimationFrame(frame)
}
```

- 전송 목록(`[off]`)에 넣어야 소유권이 워커로 넘어갑니다(자세히는 54편).
- 워커에서도 `requestAnimationFrame()`을 쓸 수 있고, 워커가 그린 프레임은 자리표시자 캔버스에 자동으로 반영됩니다. 예전의 `commit()`은 제거되었습니다.
- 넘긴 뒤에는 자리표시자 캔버스의 `width`·`height`를 바꾸거나 컨텍스트를 얻을 수 없습니다. 크기를 바꾸려면 메시지로 알려 워커에서 `OffscreenCanvas`의 크기를 바꿉니다.
- 워커에는 DOM이 없으므로 이미지는 `createImageBitmap()`으로 만든 `ImageBitmap`을 전달해 그립니다. 포인터 입력은 메인 스레드에서 받아 메시지로 보냅니다.
- 워커에서 `contextlost`, `contextrestored` 이벤트로 컨텍스트 손실을 감지할 수 있습니다.
- 한 번 `transferControlToOffscreen()`한 캔버스에는 메인 스레드에서 `getContext()`를 호출할 수 없습니다.

## 핵심 정리

- 캔버스는 즉시 모드 비트맵이라 도형이 남지 않고, `width`·`height`를 쓰면 비트맵과 상태가 초기화됩니다.
- 도형은 사각형과 경로로 그리며 `beginPath()`로 새 경로를 시작하고, `Path2D`와 `isPointInPath()`로 재사용과 히트 테스트를 합니다.
- `save()`·`restore()`는 변환, 스타일, 합성 설정 등을 쌓고 되돌리지만 현재 경로는 저장하지 않습니다.
- 고해상도는 비트맵을 `devicePixelRatio`배로 만들고 `scale()`을 맞추며, 애니메이션은 경과 시간 기준의 `requestAnimationFrame()` 루프로 만듭니다.
- `getImageData()`는 RGBA 바이트 배열을 읽고, 오염된 캔버스에서는 읽기와 내보내기(`toBlob()`, `toDataURL()`)가 `SecurityError`가 됩니다. `crossOrigin`은 `src`보다 먼저 설정합니다.
- `OffscreenCanvas`와 `transferControlToOffscreen()`으로 워커에서 렌더링하고, `roundRect()`·`reset()`(2023)과 `willReadFrequently`(2024)는 Baseline입니다.
