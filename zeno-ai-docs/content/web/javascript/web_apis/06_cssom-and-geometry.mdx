## element.style과 CSSStyleDeclaration

`element.style`은 그 요소의 인라인 `style` 속성만 나타내는 `CSSStyleDeclaration` 객체입니다. 스타일시트나 상속으로 적용된 값은 들어 있지 않습니다. CSSOM(CSS Object Model)은 CSS를 JavaScript 객체로 표현한 API 전체를 가리키며, 이 편은 그중 스타일 선언·스타일시트와 요소 기하(CSSOM View)를 다룹니다.

```js
// <p style="color: red" class="note">  .note { margin: 8px }
p.style.color           // 'red'
p.style.margin          // ''  (스타일시트의 값은 보이지 않는다)
p.style.backgroundColor = 'blue' // 인라인에 background-color 추가
p.style.backgroundColor = ''     // 빈 문자열이면 그 속성을 제거
```

속성 이름과 메서드는 다음과 같습니다.

| 항목 | 규칙 |
|------|------|
| 속성 이름 | 하이픈 이름을 camelCase로 쓴다. `background-color`는 `backgroundColor` |
| 예외 | `float`는 `cssFloat`로도 접근할 수 있다 |
| `cssText` | 인라인 스타일 전체를 문자열로 읽고 통째로 교체한다 |
| `length`, `item(i)` | 설정된 속성의 개수와 i번째 속성 이름 |
| `getPropertyValue(name)` | 하이픈 이름으로 값을 읽는다. 없으면 `''` |
| `setProperty(name, value, priority)` | 값을 쓴다. 셋째 인수는 `'important'` 또는 생략 |
| `removeProperty(name)` | 속성을 제거하고 이전 값을 반환한다 |
| `getPropertyPriority(name)` | `'important'` 또는 `''` |

```js
el.style.cssText = 'color: RED; width: 10px'
el.style.cssText     // 'color: red; width: 10px;'  (정규화되어 나온다)
el.style.removeProperty('width') // '10px'
el.style.cssText     // 'color: red;'
```

값을 쓸 때의 규칙입니다.

- 파싱할 수 없는 값은 에러 없이 무시되고 이전 값이 남습니다. `el.style.width = 'banana'`는 아무 일도 하지 않습니다.
- 표준 모드에서 단위 없는 숫자는 `0`을 제외하고 무효입니다. `el.style.width = 100`은 무시되므로 `'100px'`로 씁니다.
- `!important`는 값 문자열이 아니라 `setProperty`의 셋째 인수로 지정합니다. `el.style.color = 'red !important'`는 무효입니다.
- 읽을 때 값은 정규화된 형태로 돌아옵니다. `'RED'`는 `'red'`로 나옵니다.
- 인라인 스타일은 스타일시트보다 우선하므로, 쓴 값은 `''`로 지우기 전까지 CSS 수정으로 바뀌지 않습니다.

실무 기준은 정해진 상태 변화에는 클래스를 바꾸고(자세히는 05편), 계산한 좌표나 색처럼 런타임에 정해지는 값에만 `style`을 쓰는 것입니다.

CSS 콘텐츠 보안 정책(CSP)의 `style-src`는 `style` 속성 문자열 삽입(`setAttribute('style', ...)`)을 막을 수 있지만, `element.style`을 통한 CSSOM 조작은 막지 않습니다(자세히는 63편).

## setProperty로 사용자 정의 속성 쓰기

사용자 정의 속성(`--name`)은 camelCase 속성으로 접근할 수 없으므로 `setProperty`·`getPropertyValue`·`removeProperty`로만 다룹니다.

```js
el.style['--gap'] = '4px'         // ❌ 그냥 자바스크립트 프로퍼티가 생길 뿐
el.style.setProperty('--gap', '4px') // ✅
el.style.getPropertyValue('--gap')   // '4px'
el.style.setProperty('--n', 5)       // 값은 문자열 '5'로 변환
document.documentElement.style.setProperty('--theme', 'dark')
```

- 이름은 대소문자를 구분합니다. `--Gap`과 `--gap`은 다른 속성입니다.
- 기본 규칙은 값 문자열을 그대로 보관하는 것입니다. 타입 검사 없이 어떤 토큰이든 들어갑니다. 타입을 지정하려면 `CSS.registerProperty`로 등록합니다(아래 절).
- `getPropertyValue('--gap')`은 인라인에 쓴 값만 돌려줍니다. 스타일시트에서 상속되어 실제 적용된 값은 `getComputedStyle`로 읽습니다.
- 요소에 쓴 사용자 정의 속성은 후손이 상속하므로, 한 요소에 쓰면 그 아래 전체의 CSS가 `var(--gap)`으로 받습니다. 테마 전환은 `documentElement`에 쓰는 방식이 대표적입니다(자세히는 74편).
- 레이아웃 값을 CSS에 넘길 때 변수를 한 번 쓰면 JavaScript가 여러 속성을 직접 고치지 않아도 됩니다.

```js
// 마우스 위치를 CSS에 전달
el.style.setProperty('--x', `${event.offsetX}px`)
// .glow { left: var(--x) }
```

## getComputedStyle과 계산값·사용값

`getComputedStyle(element)`는 요소에 최종 적용된 스타일을 읽기 전용 `CSSStyleDeclaration`으로 돌려줍니다. 인라인과 스타일시트, 상속, 기본 스타일이 모두 반영됩니다.

CSS 값은 단계를 거쳐 확정됩니다.

| 단계 | 의미 | 예 (`width: 50%`, 부모 400px) |
|------|------|-------------------------------|
| 지정값 | 선언에 쓴 값 (없으면 상속·초기값) | `50%` |
| 계산값 | 상대 단위를 풀어 둔 값 | `50%` (퍼센트는 레이아웃 전에는 모른다) |
| 사용값 | 레이아웃을 마친 뒤 확정된 값 | `200px` |

`getComputedStyle`이 돌려주는 것은 정확히는 해석값(resolved value)입니다. 대부분 속성은 계산값이고, `width`·`height`·`margin`·`padding` 등 일부 속성은 요소가 레이아웃에 참여하고 있으면 사용값입니다.

```js
// #w { width: 400px }  #b { width: 50%; margin: 0 1em; font-size: 20px }
const cs = getComputedStyle(b)
cs.width        // '200px'   (사용값)
cs.marginLeft   // '20px'    (em이 px로 풀림)
b.style.width   // '50%'     (인라인은 쓴 그대로)
```

- 색은 `rgb(...)` 형태로 직렬화됩니다. `'RED'`는 `'rgb(255, 0, 0)'`으로 나옵니다.
- `display: none`인 요소의 `width`는 사용값이 없으므로 `'auto'`로 나옵니다.
- 반환 객체는 살아 있습니다. 한 번 얻어 두고 스타일이 바뀐 뒤 다시 읽어도 최신 값이 나옵니다. 읽기 전용이라 값을 대입하면 `NoModificationAllowedError`가 납니다.
- 전환(transition) 중에는 그 순간의 보간된 값이 나옵니다(자세히는 46편).
- 두 번째 인수로 의사 요소를 지정합니다: `getComputedStyle(el, '::before').content`.
- 단축 속성(`margin`, `border`)은 브라우저에 따라 직렬화가 달라질 수 있으므로 `marginTop`처럼 개별 속성으로 읽는 편이 안전합니다.
- `getComputedStyle`로 레이아웃에 의존하는 값(`width`, `height` 등)을 읽으면 브라우저가 대기 중인 스타일·레이아웃 계산을 먼저 끝내야 합니다. 쓰기와 읽기를 번갈아 하면 반복 계산이 일어납니다(자세히는 02편).
- 방문한 링크의 `:visited` 스타일은 개인정보 보호를 위해 실제와 다르게 보고됩니다.

흔한 실수는 `el.style.color`로 스타일시트에서 정해진 색을 읽으려는 것입니다. 인라인에 없으면 `''`입니다.

## document.styleSheets·CSSStyleSheet·insertRule

`document.styleSheets`는 문서에 연결된 스타일시트(`link rel="stylesheet"`와 `style` 요소)를 문서 순서대로 담은 `StyleSheetList`이고, 각 항목이 `CSSStyleSheet`입니다.

```js
const sheet = document.styleSheets[0]
sheet.cssRules.length          // 규칙 개수
sheet.cssRules[0].selectorText // '.note'  (CSSStyleRule)
sheet.cssRules[0].style.color  // 'red'    (CSSStyleDeclaration)
sheet.cssRules[0].cssText      // '.note { color: red; }'
```

규칙은 종류별 객체입니다.

| 객체 | 규칙 |
|------|------|
| `CSSStyleRule` | 선택자와 선언. `selectorText`, `style` |
| `CSSMediaRule` | `@media`. 안쪽 규칙은 `cssRules` |
| `CSSImportRule` | `@import` |
| `CSSKeyframesRule` | `@keyframes` |
| `CSSLayerBlockRule` | `@layer` 블록 |

규칙 조작은 두 메서드로 합니다.

```js
const i = sheet.insertRule('.b { color: blue }', 0) // 0
sheet.insertRule('.c { margin: 0 }', sheet.cssRules.length) // 끝에
sheet.deleteRule(i)
```

- `insertRule(text, index)`는 규칙을 하나만 받습니다. `index`를 생략하면 0이고, 반환값은 삽입된 위치입니다.
- 위치는 곧 캐스케이드 순서이므로, 같은 우선순위에서는 나중 규칙이 이깁니다.
- 파싱할 수 없는 문자열은 `SyntaxError`, `index`가 규칙 수보다 크면 `IndexSizeError`, 규칙 순서가 맞지 않으면(다른 규칙 뒤에 `@import`) `HierarchyRequestError`가 납니다.
- 교차 출처 스타일시트의 `cssRules`를 읽으면 `SecurityError`가 납니다. `link`에 `crossorigin`을 주고 서버가 CORS를 허용해야 읽을 수 있습니다(자세히는 62편).
- `sheet.disabled = true`로 시트 전체를 끌 수 있고, `sheet.ownerNode`는 연결된 `link`·`style` 요소입니다.

`new CSSStyleSheet()`로 문서 밖에서 만드는 구성 가능 스타일시트(Baseline 2023, 널리 지원)는 `replaceSync(cssText)`로 내용을 채우고 `adoptedStyleSheets`로 문서나 Shadow Root에 붙입니다. 이렇게 붙인 시트는 `document.styleSheets`에 나타나지 않습니다(자세히는 24편).

## getBoundingClientRect와 DOMRect

`element.getBoundingClientRect()`는 요소의 테두리 상자(border box)를 뷰포트 기준 좌표로 돌려주는 `DOMRect`입니다.

```js
const r = el.getBoundingClientRect()
r.x; r.y             // 뷰포트 왼쪽 위 기준 좌표
r.width; r.height    // 테두리 상자 크기 (소수 가능)
r.top; r.right; r.bottom; r.left
```

- `x`·`y`는 `left`·`top`과 같고, `right = x + width`, `bottom = y + height`입니다.
- 좌표는 뷰포트 기준이므로 스크롤하면 값이 바뀝니다. 문서 기준 좌표는 `r.top + window.scrollY`, `r.left + window.scrollX`입니다.
- `transform`이 반영됩니다. `width: 100px`에 `scale(2)`를 걸면 `r.width`는 `200`입니다. 반대로 `offsetWidth`는 100입니다(다음 절).
- 값은 호출 시점의 스냅샷이며 살아 있지 않습니다.
- `display: none`이면 모든 값이 0입니다.
- 한 요소와 다른 요소의 상대 위치는 두 사각형의 차로 구합니다: `a.top - b.top`.
- `DOMRect`는 `width`가 음수일 수 있습니다. `new DOMRect(10, 20, -30, 40)`은 `left`가 `-20`, `right`가 `10`입니다. 읽기 전용 버전은 `DOMRectReadOnly`입니다.
- 호출은 레이아웃을 확정시킵니다. 변경과 읽기를 번갈아 쓰지 않습니다(자세히는 02편).

여러 줄로 나뉜 인라인 요소는 `getClientRects()`가 줄마다 `DOMRect` 하나씩 담은 목록을 돌려주고, `getBoundingClientRect()`는 그 전체를 감싸는 사각형입니다. 줄마다 위치가 필요한 텍스트 강조 같은 곳에 씁니다(Range에서도 같은 API를 쓴다. 자세히는 13편).

## offset·client·scroll 크기 속성

요소의 크기를 정수로 재는 세 속성군이 있고, 상자의 어디까지 포함하는지가 서로 다릅니다.

```text
┌ border ────────────────────────┐ offsetWidth: 테두리 상자 전체
│ ┌ padding ───────────────────┐ │ clientWidth: 패딩 상자
│ │  ┌ content ──────────────┐ │ │   (테두리와 스크롤바 제외)
│ │  │   scrollWidth: 넘친   │ │ │ scrollWidth: 패딩 + 내용 전체
│ │  └───────────────────────┘ │ │   (넘친 부분 포함)
│ └────────────────────────────┘ │
└────────────────────────────────┘
```

| 속성 | 기준 | 스크롤바 | 변환 |
|------|------|----------|------|
| `offsetWidth`·`offsetHeight` | 테두리 상자 | 포함 | 무시 |
| `clientWidth`·`clientHeight` | 패딩 상자 | 제외 | 무시 |
| `scrollWidth`·`scrollHeight` | 패딩 + 넘친 내용 | 해당 없음 | 무시 |

```js
// width:100px; padding:10px; border:5px; overflow:hidden
// 안쪽에 height:300px, width:50px 자식 (content-box)
el.offsetWidth    // 130  = 100 + 10*2 + 5*2
el.offsetHeight   // 80   (height:50px 기준)
el.clientWidth    // 120  = 100 + 10*2
el.clientTop      // 5    (위 테두리 두께)
el.scrollHeight   // 320  = 300 + 패딩 위아래 20
```

- 세 속성군 모두 정수로 반올림됩니다. 소수 크기가 필요하면 `getBoundingClientRect()`를 씁니다.
- `offsetLeft`·`offsetTop`은 `offsetParent` 기준 위치입니다. `offsetParent`는 가장 가까운 위치 지정(`position`이 `static`이 아닌) 조상이고, 없으면 `body`입니다. 요소가 `display: none`이거나 `position: fixed`이면 `null`입니다.
- `clientTop`·`clientLeft`는 위쪽·왼쪽 테두리 두께입니다.
- `document.documentElement.clientWidth`는 스크롤바를 뺀 뷰포트 너비입니다.
- 인라인 요소(한 줄 `span`)의 `clientWidth`는 0입니다.
- 클래식 스크롤바 두께는 `offsetWidth - clientWidth - 좌우 테두리`로 구합니다. 오버레이 스크롤바 환경에서는 0입니다.

스크롤 가능 여부와 끝 도달 판정에 씁니다.

```js
const overflows = el.scrollHeight > el.clientHeight
const atBottom =
  el.scrollHeight - el.scrollTop - el.clientHeight < 1
```

끝 판정에 `< 1`을 쓰는 이유는 확대/축소나 고해상도에서 `scrollTop`이 소수가 되기 때문입니다. `=== 0` 비교는 실패할 수 있습니다.

## scrollTo·scrollBy·scrollIntoView·scrollTop

스크롤 위치는 읽고 쓰는 속성과 이동 메서드로 제어합니다.

```js
window.scrollTo(0, 500)                 // 절대 위치
window.scrollTo({ top: 0, behavior: 'smooth' })
window.scrollBy({ top: 200 })           // 현재 위치에서 상대 이동
list.scrollTo({ left: 0 })              // 요소에도 같은 메서드
el.scrollTop                            // 읽기와 쓰기 모두 가능
```

| 항목 | 동작 |
|------|------|
| `scroll()` | `scrollTo()`와 같다 |
| `window.scrollY`·`scrollX` | 문서의 현재 스크롤 위치(소수 가능). `pageYOffset`은 옛 별칭 |
| 문서 스크롤 요소 | `document.scrollingElement`. 표준 모드에서 `<html>`이다 |
| `scrollTop`·`scrollLeft` | 요소의 스크롤 위치. 범위 밖 값은 0과 최댓값으로 잘린다 |
| `behavior` | `'smooth'`는 애니메이션, `'instant'`는 즉시, `'auto'`는 CSS `scroll-behavior` 값을 따른다 |

- 표준 모드에서 `document.body.scrollTop`은 항상 0입니다. 문서 스크롤은 `window.scrollY`나 `document.scrollingElement.scrollTop`을 씁니다.
- `scrollTop`에 대입하면 `behavior`가 `'auto'`로 취급됩니다. CSS에서 `scroll-behavior: smooth`를 주면 대입도 부드럽게 움직입니다.
- 범위를 벗어난 대입은 오류 없이 경계로 잘립니다. 스크롤할 내용이 없는 요소에서는 `scrollTop`이 항상 0입니다.

`element.scrollIntoView(options)`는 요소가 보이도록 **그 조상 스크롤 컨테이너 전부**를 스크롤합니다.

```js
el.scrollIntoView()                       // block: 'start'
el.scrollIntoView({ block: 'center', behavior: 'smooth' })
el.scrollIntoView(false)                  // 아래쪽 정렬과 같다
```

| 옵션 | 값 | 기본 |
|------|-----|------|
| `block` | `start`, `center`, `end`, `nearest` | `start` |
| `inline` | `start`, `center`, `end`, `nearest` | `nearest` |
| `behavior` | `auto`, `smooth`, `instant` | `auto` |

- `nearest`는 이미 보이면 움직이지 않고, 안 보이면 가장 가까운 쪽 가장자리에 맞춥니다.
- 고정 헤더가 요소를 가릴 때는 CSS의 `scroll-margin-top`(요소) 또는 `scroll-padding-top`(스크롤 컨테이너)으로 여백을 줍니다. JavaScript로 보정값을 빼지 않아도 됩니다.
- `smooth` 스크롤이 끝났는지는 스크롤 이벤트로 감지합니다(자세히는 09편).

## innerWidth·devicePixelRatio·visualViewport

뷰포트 크기를 나타내는 값이 여럿이라 무엇을 재는지 구분해야 합니다.

| 값 | 의미 |
|----|------|
| `window.innerWidth`·`innerHeight` | 레이아웃 뷰포트 크기(CSS 픽셀). 세로 스크롤바 두께를 포함 |
| `documentElement.clientWidth`·`clientHeight` | 스크롤바를 뺀 레이아웃 뷰포트 크기. `100vw`와 달리 스크롤바를 포함하지 않는다 |
| `window.outerWidth`·`outerHeight` | 브라우저 창 전체(툴바 포함) |
| `visualViewport.width`·`height` | 사용자가 실제로 보는 영역. 핀치 줌과 화상 키보드가 반영된다 |
| `screen.width`·`height` | 모니터 해상도 |

- 브라우저 확대(Ctrl +)를 하면 CSS 픽셀이 커지므로 `innerWidth`가 줄어듭니다. 미디어 쿼리 중단점이 확대로 발동하는 이유입니다.
- `100vw` 요소가 가로 스크롤바를 만드는 문제는 `100vw`에 스크롤바 두께가 들어 있기 때문입니다. 스크롤바를 뺀 너비가 필요하면 `clientWidth`를 씁니다.

`window.devicePixelRatio`는 물리 픽셀 수를 CSS 픽셀 수로 나눈 비율입니다.

```js
devicePixelRatio // 1 (일반), 2 (Retina), 3 (고밀도 휴대폰)
canvas.width = Math.round(cssWidth * devicePixelRatio)
canvas.style.width = `${cssWidth}px`
ctx.scale(devicePixelRatio, devicePixelRatio)
```

- 브라우저 확대를 하면 값이 커집니다(200퍼센트에서 2배). 핀치 줌은 CSS 픽셀 크기를 바꾸지 않으므로 값이 그대로입니다.
- `devicePixelRatio`에는 변경 이벤트가 없습니다. 값이 바뀌었는지는 `matchMedia`로 감시합니다.

```js
const mq = matchMedia(`(resolution: ${devicePixelRatio}dppx)`)
mq.addEventListener('change', onRatioChange, { once: true })
```

변경 이후에는 새 값으로 쿼리를 다시 만들어 등록해야 합니다. 쿼리 문자열이 옛 값에 고정되어 있기 때문입니다.

`window.visualViewport`(Baseline 2021, 널리 지원)는 레이아웃 뷰포트와 시각 뷰포트를 구분합니다. 레이아웃 뷰포트는 CSS가 요소를 배치하는 기준이고, 시각 뷰포트는 핀치 줌으로 확대했을 때 화면에 보이는 부분입니다.

| 속성 | 의미 |
|------|------|
| `width`·`height` | 시각 뷰포트 크기(CSS 픽셀). 핀치 줌하면 줄어든다 |
| `offsetLeft`·`offsetTop` | 레이아웃 뷰포트 왼쪽 위에서 시각 뷰포트 왼쪽 위까지의 거리 |
| `pageLeft`·`pageTop` | 문서 기준 시각 뷰포트 위치 |
| `scale` | 핀치 줌 배율. 줌하지 않으면 1 |

- `resize`와 `scroll` 이벤트(`scrollend`도 지원)가 시각 뷰포트 변화에 대해 발생합니다.
- 최상위 창에서만 별개의 시각 뷰포트가 있고, iframe에서는 레이아웃 뷰포트와 같은 값입니다.
- 화상 키보드가 올라올 때 `visualViewport.height`가 줄어드는 모바일 브라우저가 많습니다. 하단 고정 입력창을 키보드 위로 올리는 데 씁니다. 키보드가 레이아웃 뷰포트를 줄일지 시각 뷰포트만 줄일지는 브라우저와 viewport 메타의 `interactive-widget` 값에 따라 다릅니다.

```js
visualViewport.addEventListener('resize', () => {
  const v = visualViewport
  bar.style.bottom = `${innerHeight - v.height - v.offsetTop}px`
})
```

### matchMedia와 MediaQueryList

`matchMedia(query)`는 미디어 쿼리 문자열을 평가해 `MediaQueryList`를 돌려줍니다. `matches`는 현재 일치 여부, `media`는 정규화된 쿼리 문자열이고, 일치 여부가 바뀔 때 `change` 이벤트가 발생합니다.

```js
const mq = matchMedia('(min-width: 768px)')
mq.matches                       // true 또는 false
mq.addEventListener('change', (e) => render(e.matches))
matchMedia('(prefers-color-scheme: dark)').matches
```

`resize` 이벤트로 `innerWidth`를 매번 비교하는 방식보다, 일치 여부가 바뀔 때만 호출되는 `change`가 낫습니다.

## elementFromPoint·elementsFromPoint

`document.elementFromPoint(x, y)`는 뷰포트 좌표에서 가장 위에 그려진 요소를, `elementsFromPoint(x, y)`는 그 지점에 겹친 모든 요소를 위에서 아래 순서의 배열로 돌려줍니다.

```js
document.elementFromPoint(100, 50)   // <button>
document.elementsFromPoint(100, 50)  // [button, div.card, main, body, html]
document.elementFromPoint(-5, -5)    // null (뷰포트 밖)
```

- 좌표는 뷰포트 기준이므로 `getBoundingClientRect()`와 `clientX`·`clientY`와 같은 좌표계입니다.
- 뷰포트 밖 좌표는 `elementFromPoint`가 `null`, `elementsFromPoint`가 빈 배열을 돌려줍니다.
- `pointer-events: none`이거나 `visibility: hidden`인 요소는 결과에서 빠집니다. 클릭 가능한 대상만 나옵니다.
- Shadow DOM 안의 요소는 `document`에서 호스트로 대표되어 나옵니다. 내부 요소를 얻으려면 `shadowRoot.elementFromPoint`를 호출합니다(자세히는 21편).
- 드래그 중에 놓일 대상을 찾을 때 자주 씁니다. 끌고 있는 요소가 결과 맨 위에 오므로, 끌리는 요소에 `pointer-events: none`을 주거나 `elementsFromPoint`의 둘째 요소를 읽습니다(자세히는 49편).

## checkVisibility

`element.checkVisibility(options)`(Baseline 2024, 널리 지원)는 요소가 렌더링 상자를 가지고 있는지를 불리언으로 돌려줍니다. 스타일을 하나씩 확인하지 않아도 됩니다.

```js
el.checkVisibility()   // display:none 이면 false
```

| 조건 | 옵션 없이 | 옵션을 켜면 |
|------|-----------|-------------|
| `display: none` 또는 `display: contents` (상자 없음) | false | 기본 |
| 조상이 `display: none` | false | 기본 |
| `content-visibility: hidden` | false | 기본 |
| `opacity: 0` | true | `opacityProperty: true`면 false |
| `visibility: hidden`·`collapse` | true | `visibilityProperty: true`면 false |
| `content-visibility: auto`로 렌더링을 건너뜀 | true | `contentVisibilityAuto: true`면 false |

```js
el.style.opacity = '0'
el.checkVisibility()                        // true
el.checkVisibility({ opacityProperty: true }) // false
el.checkVisibility({ visibilityProperty: true,
                     contentVisibilityAuto: true })
```

- `checkOpacity`와 `checkVisibilityCSS`는 `opacityProperty`와 `visibilityProperty`의 옛 이름입니다. 새 코드에서는 새 이름을 씁니다.
- `true`는 "사용자에게 보인다"가 아닙니다. 뷰포트 밖에 있거나 다른 요소에 가려져도 `true`입니다. 화면 안에 들어왔는지는 `IntersectionObserver`로 확인합니다(자세히는 43편).
- 예전에는 `offsetParent === null`이나 `getClientRects().length`로 `display: none`을 판별했는데, `checkVisibility()`가 의도를 직접 표현합니다.

## Geometry 인터페이스: DOMMatrix·DOMPoint

Geometry Interfaces 표준은 점, 사각형, 사각형 네 꼭짓점, 변환 행렬을 표현하는 타입들을 정의합니다. `getBoundingClientRect()`가 돌려주는 `DOMRect`도 여기에 속합니다.

`DOMPoint`는 3차원 좌표 `x`, `y`, `z`와 원근용 `w`를 가진 점입니다. 기본값은 `0, 0, 0, 1`입니다.

```js
const p = new DOMPoint(1, 1)   // x:1 y:1 z:0 w:1
```

`DOMMatrix`는 4×4 변환 행렬입니다. 2차원 변환은 `a`·`b`·`c`·`d`·`e`·`f` 여섯 값이면 되고, 이 이름은 3차원 이름 `m11`·`m12`·`m21`·`m22`·`m41`·`m42`와 같은 값입니다.

```js
const m = new DOMMatrix().translate(10, 20).scale(2)
m.toString()  // 'matrix(2, 0, 0, 2, 10, 20)'
m.a; m.e; m.f // 2, 10, 20
m.is2D        // true
```

생성 방법은 네 가지입니다.

- 인수 없이: 단위 행렬.
- CSS 변환 문자열: `new DOMMatrix('translate(10px, 20px) scale(2)')`. `'none'`은 단위 행렬입니다. 문자열 생성자는 창(Window) 컨텍스트에서만 동작하고 워커에서는 쓸 수 없습니다(자세히는 54편).
- 숫자 배열: 6개(2D) 또는 16개(3D).
- 계산된 변환: `new DOMMatrix(getComputedStyle(el).transform)`.

주요 메서드입니다.

| 메서드 | 동작 |
|--------|------|
| `translate(x, y)`, `scale(s)`, `rotate(deg)` | 변환을 곱한 **새** 행렬을 반환 |
| `translateSelf`, `scaleSelf`, `rotateSelf` | 같은 변환을 **자기 자신**에 적용 |
| `multiply(other)` | 행렬 곱. `A.multiply(B)`는 `A × B`다 |
| `inverse()` | 역행렬. 역행렬이 없으면 모든 값이 `NaN`인 행렬이 된다 |
| `transformPoint(point)` | 점에 행렬을 적용해 새 `DOMPoint`를 반환 |

```js
const m = new DOMMatrix().translate(10, 20).scale(2)
const q = m.transformPoint(new DOMPoint(1, 1))
q.x; q.y                       // 12, 22  (먼저 2배, 그다음 이동)
m.inverse().toString()
// 'matrix(0.5, 0, 0, 0.5, -5, -10)'
```

- 곱셈 순서가 결과를 바꿉니다. `translate(10, 20).scale(2)`는 점에 크기 변환이 먼저 적용되고 이동이 나중에 적용됩니다.
- `DOMMatrixReadOnly`는 `…Self` 메서드가 없는 읽기 전용 부모 타입이고, `DOMMatrix`가 그 변경 가능한 버전입니다.
- 행렬 값이 `NaN`이면 `toString()`이 `InvalidStateError`를 던집니다.
- 사용처는 `transform`의 현재 값에서 이동량·배율 분해, 스크린 좌표와 요소 로컬 좌표의 변환(역행렬), Canvas의 `ctx.setTransform(matrix)`입니다(자세히는 52편).

## CSS Typed OM 개요

CSS Typed Object Model은 CSS 값을 문자열이 아니라 단위가 있는 타입 객체로 읽고 쓰는 API입니다. Baseline이 아니며 일부 브라우저에서만 지원되므로 MDN의 지원 표를 확인하고 점진적 향상으로 씁니다.

문자열 방식의 약점은 값마다 파싱이 필요하다는 점입니다.

```js
getComputedStyle(el).paddingTop       // '10px'  → parseFloat 필요
el.computedStyleMap().get('padding-top')
// CSSUnitValue { value: 10, unit: 'px' }
```

| API | 하는 일 |
|-----|---------|
| `el.attributeStyleMap` | 인라인 스타일의 타입 버전(`StylePropertyMap`). `set`, `get`, `append`, `delete`, `clear` |
| `el.computedStyleMap()` | 계산된 스타일의 읽기 전용 타입 버전 |
| `CSS.px(10)`, `CSS.em(2)`, `CSS.number(0.5)` | 값 객체를 만드는 팩토리 |
| `CSSStyleValue.parse(prop, text)` | 문자열을 타입 객체로 변환 |

값 타입은 다음과 같습니다.

| 타입 | 나오는 값 |
|------|-----------|
| `CSSUnitValue` | `10px`, `50%`, 단위 없는 숫자. `value`와 `unit` |
| `CSSKeywordValue` | `auto`, `none` 같은 키워드 |
| `CSSMathSum` 등 | `calc()` 식 |
| `CSSTransformValue` | `transform` 함수 목록 |
| `CSSUnparsedValue` | 등록되지 않은 사용자 정의 속성 |

```js
el.attributeStyleMap.set('width', CSS.px(10))
el.style.width  // '10px'
CSS.px(10).mul(2).toString() // '20px'
el.attributeStyleMap.set('width', 'banana') // TypeError
```

- 잘못된 값을 `set`하면 CSSOM 문자열 방식처럼 무시되지 않고 `TypeError`가 납니다.
- `computedStyleMap()`은 `getComputedStyle()`과 달리 계산값을 돌려줍니다. `width: auto`는 `'auto'` 키워드 객체로 나오고, 사용값(픽셀)이 필요하면 `getComputedStyle`이나 `getBoundingClientRect`를 씁니다.
- 숫자를 직접 넘기는 것도 허용됩니다(`attributeStyleMap.set('opacity', 0.5)`).

## CSS.registerProperty

`CSS.registerProperty(definition)`은 사용자 정의 속성에 타입·상속 여부·초기값을 등록하는 JavaScript API입니다(CSS Properties and Values API, Baseline 2024). CSS의 `@property` 규칙과 같은 역할이며 코드에서 등록할 때 씁니다.

```js
CSS.registerProperty({
  name: '--hue',
  syntax: '<number>',
  inherits: false,
  initialValue: '0',
})
```

| 필드 | 필수 | 의미 |
|------|------|------|
| `name` | 예 | `--`로 시작하는 이름 |
| `syntax` | 아니오 | 허용 문법. `'<length>'`, `'<color>'`, `'<number>'` 등. 기본 `'*'`(제한 없음) |
| `inherits` | 예 | 상속 여부 |
| `initialValue` | 조건부 | `syntax`가 `'*'`가 아니면 필수 |

- 필드가 빠지면 에러가 납니다. `inherits`가 없으면 `TypeError`, `syntax`가 `'*'`가 아닌데 `initialValue`가 없으면 `SyntaxError`입니다.
- `--` 없이 시작하는 이름은 `SyntaxError`, 같은 이름을 다시 등록하면 `InvalidModificationError`입니다. 등록은 해제할 수 없습니다.
- 등록하면 값이 타입에 맞게 검증됩니다. `<length>`로 등록한 속성에 `red`를 쓰면 무효로 처리되어 초기값으로 돌아갑니다.
- 계산값이 해석됩니다. `<length>`에 `2em`을 쓰면 `getComputedStyle`이 `'32px'`처럼 절대 길이로 돌려줍니다(글자 크기 16px일 때).
- 등록하지 않은 사용자 정의 속성은 문자열 토큰일 뿐이라 전환·애니메이션이 값을 보간하지 못합니다. 등록하면 `--hue` 같은 속성을 `transition`으로 부드럽게 바꿀 수 있습니다(자세히는 46편).
- 이 API는 `style` 규칙이 아니라 문서 전체에 적용되는 등록입니다.

## CSS Font Loading API

`document.fonts`는 문서의 웹 폰트 로딩을 다루는 `FontFaceSet`입니다(Baseline, 널리 지원). 웹 폰트는 텍스트가 실제로 그 글꼴을 쓸 때 비로소 내려받기 시작합니다. 이 API로 로딩 시점을 앞당기거나 끝을 기다릴 수 있습니다.

```js
await document.fonts.load('16px Inter')  // 로드해 둔다
document.fonts.check('16px Inter')       // true  (로드 완료)
await document.fonts.ready               // 사용 중인 폰트 전부 완료
document.fonts.status                    // 'loading' 또는 'loaded'
```

| 멤버 | 동작 |
|------|------|
| `load(font, text?)` | 해당 폰트를 로드하고 `FontFace` 배열로 이행하는 Promise |
| `check(font, text?)` | 해당 폰트가 이미 로드됐으면 `true`. 로드가 필요하면 `false` |
| `ready` | 현재 사용 중인 폰트의 로딩과 레이아웃이 끝나면 이행하는 Promise |
| `status` | `'loading'` 또는 `'loaded'` |
| 이벤트 | `loading`, `loadingdone`, `loadingerror` |

- `check()`는 문서에 선언되지 않은 글꼴 이름에도 `true`를 돌려줍니다. 로드할 것이 없다는 뜻이기 때문입니다. 존재 여부 확인이 아니라 "지금 렌더링에 쓸 수 있는가"를 확인하는 용도입니다.
- `ready`는 선언된 폰트가 아니라 **사용 중인** 폰트를 기다립니다. `font-display: optional`인 폰트는 늦으면 쓰이지 않으므로 기다리지 않습니다.

CSS 없이 JavaScript로 폰트를 등록하려면 `FontFace`를 만듭니다.

```js
const face = new FontFace('Brand', 'url(/brand.woff2)', {
  weight: '400',
})
await face.load()             // 다운로드
document.fonts.add(face)      // 이후 font-family: Brand 사용 가능
```

- `load()`가 실패하면 Promise가 거부됩니다. `face.status`는 `'unloaded'`, `'loading'`, `'loaded'`, `'error'` 중 하나입니다.
- 폰트가 늦게 도착하면 글자가 다시 그려지면서 레이아웃이 움직입니다(CLS). 첫 화면 폰트는 `link rel="preload"`로 앞당기는 편이 낫습니다(자세히는 15편).
- 캔버스는 로드되지 않은 폰트로 그리면 대체 글꼴로 그려지므로, 그리기 전에 `document.fonts.load`를 기다립니다(자세히는 52편).

## CSS Painting API와 Houdini

Houdini는 브라우저의 CSS 엔진 일부를 JavaScript에 개방하는 API 묶음입니다. 이 편에서 앞서 본 `CSS.registerProperty`(Properties and Values)와 Typed OM이 그 구성원이고, CSS Painting API는 JavaScript로 요소의 배경·테두리 같은 이미지를 직접 그립니다. Baseline이 아니며 Chromium 계열 중심이므로 장식 용도로 점진적 향상으로 씁니다.

그리는 코드는 **페인트 워크릿**이라는 DOM이 없는 전용 스코프에서 실행합니다(자세히는 55편).

```js
// boxbg.js (워크릿 파일)
registerPaint('boxbg', class {
  static get inputProperties() { return ['--box-color'] }
  paint(ctx, size, props) {
    ctx.fillStyle = props.get('--box-color').toString()
    ctx.fillRect(0, 0, size.width / 2, size.height)
  }
})
```

```js
// 메인 스크립트
CSS.paintWorklet.addModule('boxbg.js')
```

```css
li { background-image: paint(boxbg); --box-color: gold; }
```

- `registerPaint(name, class)`로 이름을 등록하고, CSS에서는 이미지가 들어가는 자리(`background-image`, `border-image`, `mask-image` 등)에 `paint(name)`으로 씁니다.
- `inputProperties`에 나열한 CSS 속성(사용자 정의 속성 포함)이 바뀌면 다시 그려집니다. 값은 `props.get(...)`으로 읽습니다.
- `paint(ctx, size, props)`의 `ctx`는 `PaintRenderingContext2D`로 Canvas 2D의 일부만 제공하며, 텍스트 그리기와 픽셀 읽기는 지원하지 않습니다. `size`는 `width`와 `height`를 가진 `PaintSize`입니다. Canvas 2D 자체는 52편에서 다룹니다.
- 미지원 브라우저에서는 `paint()` 선언이 무효가 됩니다. `@supports (background: paint(boxbg))`나 `'paintWorklet' in CSS`로 확인하고 기본 스타일을 먼저 둡니다.
- 워크릿 안에서는 DOM과 `window`에 접근할 수 없습니다. 필요한 값은 `inputProperties`로 받습니다.

## CSS.supports()

`CSS.supports()`는 브라우저가 특정 CSS 선언·조건·선택자를 지원하는지를 불리언으로 돌려줍니다. `@supports` 규칙의 JavaScript 버전입니다.

```js
CSS.supports('display', 'grid')            // true
CSS.supports('display: grid')              // true  (한 문자열 형태)
CSS.supports('display', 'banana')          // false (값이 무효)
CSS.supports('(display:grid) and (gap:1px)') // 조합
CSS.supports('selector(:has(a))')          // 선택자 지원 확인
```

| 호출 형태 | 용도 |
|-----------|------|
| `supports(property, value)` | 이름·값 쌍이 유효한지 |
| `supports(conditionText)` | `and`·`or`·`not` 조합, `selector(...)` 등 |

- 값이 지원 문법이어도 값 자체가 틀리면 `false`입니다. 속성 이름만 보는 것이 아니라 그 값이 파싱되는지를 봅니다.
- 한 문자열 형태는 바깥 괄호 없이 써도 되고, 여러 조건을 `and`로 묶을 때는 각 조건을 괄호로 감쌉니다.
- 기능 검사가 지원 여부를 보장하는 범위는 "파싱된다"까지입니다. 지원하는 브라우저에서의 렌더링 버그까지 걸러 주지는 않습니다.
- 스타일 규칙에서 분기하면 충분한 경우는 `@supports`를 쓰고, 로직 분기나 폴리필 로드에서만 `CSS.supports()`를 씁니다(자세히는 71편).

선택자에 JavaScript 값을 넣을 때는 `CSS.escape()`로 특수문자를 이스케이프합니다.

```js
CSS.escape('a.b#1')  // 'a\\.b\\#1'
document.querySelector(`#${CSS.escape(id)}`)
```

## 핵심 정리

- `el.style`은 인라인 스타일만 다루고, 사용자 정의 속성은 `setProperty`로만 씁니다. 실제 적용된 값은 `getComputedStyle`로 읽으며, 이 객체는 읽기 전용이고 `width` 같은 값은 사용값(픽셀)으로 나옵니다.
- 시트는 `document.styleSheets`와 `insertRule`·`deleteRule`로 조작하고, 교차 출처 시트는 CORS 없이는 규칙을 읽을 수 없습니다.
- `getBoundingClientRect`는 뷰포트 기준·변환 반영·소수 값, `offset`·`client`·`scroll` 크기는 정수·변환 무시이며 각각 테두리 상자·패딩 상자·넘친 내용 전체를 잽니다.
- 뷰포트는 `innerWidth`(스크롤바 포함)·`clientWidth`(제외)·`visualViewport`(핀치 줌·키보드 반영)로 나뉘고, `devicePixelRatio`는 확대하면 변합니다.
- `checkVisibility()`는 상자 유무를 확인하며 화면 안에 보이는지는 알려주지 않습니다. `DOMMatrix`는 행렬 곱 순서에 주의합니다.
- Typed OM·Painting API는 지원이 제한적이고, `CSS.registerProperty`·`document.fonts`·`CSS.supports`는 널리 지원됩니다.
