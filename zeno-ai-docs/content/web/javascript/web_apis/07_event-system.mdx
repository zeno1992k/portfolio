## EventTarget

`EventTarget`은 이벤트를 받고(리스너를 붙이고) 보낼 수 있는 객체의 인터페이스입니다. 이벤트는 "어떤 일이 일어났다"는 신호입니다. 노드, `Window`, `AbortSignal`, `XMLHttpRequest` 등 많은 객체가 `EventTarget`을 구현합니다.

| 멤버 | 하는 일 |
|------|---------|
| `addEventListener(type, callback, options)` | 리스너 등록 |
| `removeEventListener(type, callback, options)` | 리스너 제거 |
| `dispatchEvent(event)` | 이벤트를 이 객체에 보냄 |

- 각 `EventTarget`은 리스너 목록을 가지며 리스너는 이벤트의 `type` 문자열(`'click'`)로 구분합니다.
- 이벤트는 신호이지 동작이 아닙니다. 이벤트를 보낸다고 작업이 시작되지는 않으며, 이미 진행 중인 작업을 바꾸는 데 쓰입니다(예: `submit` 이벤트에서 `preventDefault()`로 전송 중단).

### new EventTarget()과 EventTarget 상속

`EventTarget`은 생성자를 가집니다(Baseline 2020). 직접 만들거나 상속해서 자기만의 이벤트 발행자를 만들 수 있습니다.

```js
class Store extends EventTarget {
  #count = 0
  increment() {
    this.#count++
    this.dispatchEvent(new CustomEvent('change', {
      detail: this.#count,
    }))
  }
}
const store = new Store()
store.addEventListener('change', (e) => {
  console.log(e.detail)
})
store.increment() // 1
```

- 직접 만든 `EventTarget`은 트리에 속하지 않습니다. 부모가 없어서 이벤트가 전파되지 않고 그 객체의 리스너만 호출됩니다.
- DOM 요소가 필요 없는 상태 저장소, 서비스 객체의 알림 수단으로 쓰입니다(자세히는 25편).

## addEventListener / removeEventListener

```js
button.addEventListener('click', onClick)
button.addEventListener('click', onClick, true)  // capture
button.addEventListener('click', onClick, { once: true })
button.removeEventListener('click', onClick)
```

- 세 번째 인수는 불리언(= `capture`)이거나 옵션 객체입니다(옵션은 아래 "리스너 옵션").
- 함수 리스너 안의 `this`는 `currentTarget`입니다. 화살표 함수는 `this`를 바꾸지 못합니다.
- 리스너의 예외는 `addEventListener`를 부른 쪽으로 전파되지 않고 보고됩니다(아래 "dispatchEvent").
- 이벤트 이름은 대소문자를 구분합니다. `'click'`이지 `'Click'`이 아닙니다.

### 같은 리스너 중복 등록 규칙

리스너의 동일성은 type, callback, capture 세 값으로 정해집니다. 같은 값으로 다시 등록하면 무시됩니다.

```js
el.addEventListener('click', f)
el.addEventListener('click', f)        // 무시(중복)
el.addEventListener('click', f, true)  // 등록(capture가 다름)
el.removeEventListener('click', f)     // 앞의 것만 제거
```

- `once`, `passive`, `signal`은 동일성 판단에 쓰이지 않습니다.
- `removeEventListener`는 type, callback, capture가 같은 리스너를 지웁니다. `capture`를 맞추지 않으면 지워지지 않습니다.
- 익명 함수와 화살표 함수는 등록할 때마다 새 함수라서 같은 것으로 제거할 수 없습니다. `bind()`도 새 함수를 만듭니다. 제거할 리스너는 변수에 담거나 `signal`을 씁니다.

**흔한 실수:** `addEventListener('click', handler())`처럼 함수를 호출하는 것입니다. 호출 결과가 등록되므로 `handler`만 넘깁니다.

### handleEvent 객체 리스너

콜백 자리에는 함수 대신 `handleEvent` 메서드를 가진 객체도 올 수 있습니다.

```js
class Menu {
  handleEvent(e) {
    if (e.type === 'click') this.onClick(e)
    if (e.type === 'keydown') this.onKey(e)
  }
  onClick(e) {}
  onKey(e) {}
}
const menu = new Menu()
el.addEventListener('click', menu)
el.addEventListener('keydown', menu)
```

- 객체의 `handleEvent`가 호출되고 `this`는 그 객체입니다. `bind()` 없이 인스턴스 메서드를 쓸 수 있습니다.
- 같은 객체를 한 번만 만들어서 제거도 쉽습니다. `removeEventListener('click', menu)`로 지웁니다.
- 컴포넌트 클래스 하나로 여러 이벤트를 처리하는 패턴에 쓰입니다.

### signal 옵션으로 리스너 제거

`signal`에 `AbortSignal`을 넘기면 그 신호가 중단될 때 리스너가 제거됩니다(Baseline 2021).

```js
const ac = new AbortController()
const opt = { signal: ac.signal }
window.addEventListener('resize', onResize, opt)
window.addEventListener('scroll', onScroll, opt)
ac.abort() // 두 리스너 모두 제거
```

- 한 컨트롤러로 여러 리스너를 한 번에 정리할 수 있어서 컴포넌트의 정리(cleanup)에 알맞습니다(자세히는 18편).
- 이미 중단된 신호로 등록하면 리스너가 추가되지 않습니다.
- `AbortController` 자체는 37편에서 다룹니다.

### on 이벤트 핸들러 속성과 addEventListener의 차이

`onclick` 같은 이벤트 핸들러(event handler) 속성도 리스너로 동작합니다. 표준은 핸들러를 해당 이벤트의 캡처 아닌 리스너로 정의합니다.

| 항목 | `on*` 핸들러 | `addEventListener` |
|------|--------------|--------------------|
| 개수 | 이벤트 종류마다 하나 | 제한 없음 |
| 다시 대입 | 이전 핸들러를 대체 | 추가 |
| 제거 | `null` 대입 | `removeEventListener` 또는 `signal` |
| 옵션(capture·once·passive) | 없음 | 있음 |
| 쓰는 곳 | 프로퍼티, HTML 속성(`onclick="..."`) | 코드 |
| 반환값 | `false`면 `preventDefault()` 효과 | 반환값 무시 |

```js
btn.onclick = () => console.log('A')
btn.onclick = () => console.log('B') // A는 사라짐
btn.addEventListener('click', () => console.log('C'))
// 클릭하면 B, C 출력
```

- HTML 속성 `onclick="..."`은 JavaScript 함수 본문으로 취급되며 `setAttribute('onclick', ...)`로도 설정됩니다. 콘텐츠 보안 정책(CSP)이 인라인 핸들러를 막을 수 있습니다(자세히는 63편).
- 핸들러는 처음 `null`이 아닌 값이 설정된 시점에 리스너 목록에 한 번 등록되고, 이후 값을 바꿔도 목록의 자리는 유지됩니다. 그래서 실행 순서는 핸들러가 활성화된 시점 기준입니다. `null`로 비활성화한 뒤 다시 설정하면 목록 맨 뒤로 갑니다.
- `window.onerror`는 특별해서 인수를 `(message, source, lineno, colno, error)` 순으로 받고, `true`를 반환하면 이벤트가 취소됩니다(아래 "전역 에러 이벤트").
- `body`와 `frameset` 요소의 일부 핸들러(`onload`, `onresize` 등)는 `Window`에 붙습니다.
- 새 코드에는 `addEventListener`를 씁니다. 여러 모듈이 같은 이벤트에 핸들러를 붙일 때 서로 덮어쓰지 않기 때문입니다.

## Event 객체

리스너는 `Event`(또는 그 하위) 객체를 인수로 받습니다. 직접 만들 때는 `new Event(type, init)`이며 `init`은 `bubbles`, `cancelable`, `composed`(모두 기본값 `false`)입니다.

| 프로퍼티 | 의미 |
|----------|------|
| `type` | 이벤트 이름 |
| `target` | 이벤트가 보내진 객체 |
| `currentTarget` | 지금 리스너를 실행 중인 객체 |
| `eventPhase` | 전파 단계(0–3) |
| `bubbles` | 버블링하는가 |
| `cancelable` | `preventDefault()`가 효과가 있는가 |
| `defaultPrevented` | `preventDefault()`가 성공했는가 |
| `composed` | 섀도 경계를 넘는가 |
| `isTrusted` | 브라우저가 만든 이벤트인가 |
| `timeStamp` | 발생 시각 |
| `composedPath()` | 전파 경로의 객체 목록 |

### isTrusted와 timeStamp

- `isTrusted`는 사용자 에이전트가 만든 이벤트일 때 `true`입니다. `dispatchEvent()`로 보낸 이벤트는 항상 `false`이고 스크립트가 바꿀 수 없습니다. 예외로 `element.click()`이 보내는 이벤트도 `false`입니다.
- 일부 API(전체 화면, 클립보드 등)는 `isTrusted`가 아닌 사용자 활성화를 요구합니다(자세히는 10편).
- `timeStamp`는 밀리초 단위의 `DOMHighResTimeStamp`입니다. `performance.now()`와 같은 시간축이라 이벤트가 만들어진 뒤 핸들러가 호출되기까지의 지연을 `performance.now() - e.timeStamp`로 잴 수 있습니다(자세히는 65편).

### eventPhase와 레거시 멤버

`eventPhase`는 `Event.NONE`(0, 보내지는 중이 아님), `CAPTURING_PHASE`(1), `AT_TARGET`(2), `BUBBLING_PHASE`(3) 중 하나입니다. 보내기가 끝나면 다시 0이 됩니다.

| 레거시 | 대체 |
|--------|------|
| `cancelBubble = true` | `stopPropagation()`. 읽으면 전파 중단 여부 |
| `returnValue = false` | `preventDefault()`. 읽으면 취소되지 않았는지 |
| `srcElement` | `target` |
| `window.event` | 리스너 인수 `e` |
| `initEvent()` | `new Event()` 생성자 |

`window.event`는 현재 처리 중인 이벤트를 가리키지만 워커에는 없고 섀도 트리 안의 이벤트에서는 부정확합니다. 이벤트는 리스너 인수로 받습니다.

### Event 하위 인터페이스 개관

이벤트마다 필요한 데이터가 달라 `Event`를 상속한 인터페이스를 씁니다. 리스너가 받는 객체의 실제 종류는 이벤트 이름이 정합니다.

| 인터페이스 | 추가 멤버 | 쓰이는 곳 |
|-----------|-----------|-----------|
| `CustomEvent` | `detail` | 사용자 정의 이벤트(아래 참조) |
| `UIEvent` | `view`, `detail` | 마우스·키보드·포커스·입력 이벤트의 부모(자세히는 09편, 10편) |
| `FocusEvent` | `relatedTarget` | `focus`, `blur`, `focusin`, `focusout`(자세히는 10편) |
| `ErrorEvent` | `message`, `filename`, `lineno`, `colno`, `error` | 전역 `error`(아래 참조) |
| `PromiseRejectionEvent` | `promise`, `reason` | `unhandledrejection`(아래 참조) |
| `ProgressEvent` | `lengthComputable`, `loaded`, `total` | `XMLHttpRequest`, 업로드·다운로드 진행(자세히는 36편) |

- `KeyboardEvent`, `InputEvent`, `CompositionEvent`는 `UIEvent`를 상속합니다.
- 각 하위 인터페이스의 생성자는 `new FocusEvent('focus', { relatedTarget })`처럼 해당 멤버를 초기화 객체로 받습니다.

## target vs currentTarget

`target`은 이벤트가 처음 보내진 객체이고, `currentTarget`은 지금 호출되는 리스너가 붙은 객체입니다. 전파되는 동안 `target`은 그대로고 `currentTarget`만 바뀝니다.

```html
<ul id="list"><li><b>A</b></li></ul>
```

```js
list.addEventListener('click', (e) => {
  e.target.localName       // 'b' (실제로 클릭된 요소)
  e.currentTarget.id       // 'list' (리스너가 붙은 요소)
  e.target === e.currentTarget // false
})
```

- 리스너가 대상 요소에 직접 붙어 있고 자식이 없으면 둘이 같습니다.
- `currentTarget`은 리스너 실행 중에만 값이 있습니다. 보내기가 끝나면 `null`이 되어서 `setTimeout`이나 `await` 뒤에서 `e.currentTarget`을 읽으면 `null`입니다. 필요하면 변수에 먼저 담습니다.
- 섀도 트리 안에서 시작한 이벤트는 바깥 리스너에게 `target`이 호스트 요소로 보입니다(리타깃팅). 보내기가 끝난 뒤에는 `target`이 `null`이 될 수 있습니다. 원래 경로는 `composedPath()`로 얻습니다(자세히는 21편).

## 캡처링 / 타깃 / 버블링

이벤트가 트리 안의 객체에 보내지면 전파 경로가 먼저 정해집니다. 경로는 대상에서 조상(문서, `Window`)까지입니다. 경로는 보내기 시작 때 한 번 정해지고, 리스너가 DOM을 바꿔도 이 경로는 바뀌지 않습니다.

| 단계 | `eventPhase` | 방향 | 실행되는 리스너 |
|------|--------------|------|-----------------|
| 캡처링 | 1 | 루트 → 대상의 부모 | `capture: true` |
| 타깃 | 2 | 대상 | capture 먼저, 그다음 non-capture |
| 버블링 | 3 | 대상의 부모 → 루트 | `capture: false`(`bubbles`가 참일 때만) |

```js
const log = (e) => {
  console.log(e.currentTarget.id, e.eventPhase)
}
outer.addEventListener('click', log, true)  // 캡처링
inner.addEventListener('click', log)         // 타깃
outer.addEventListener('click', log)         // 버블링
// inner를 클릭하면: outer 1, inner 2, outer 3
```

- 대상에서는 `capture` 값과 상관없이 리스너가 실행되며 capture 리스너가 먼저입니다.
- `bubbles`가 `false`이면 버블링 단계만 건너뜁니다. 캡처링과 타깃 단계는 그대로 일어납니다.
- 많은 이벤트가 버블링하지만 `focus`, `blur`, `mouseenter`, `mouseleave`, `load`는 버블링하지 않습니다. 포커스는 버블링하는 `focusin`·`focusout`을 대신 씁니다(자세히는 10편).
- 문서가 보내는 `load` 이벤트는 `Window`로 전파되지 않습니다.
- 캡처링은 하위에서 이벤트가 처리되기 전에 가로채거나 버블링하지 않는 이벤트를 상위에서 받을 때 씁니다.

## preventDefault / stopPropagation

두 메서드는 서로 다른 것을 막습니다.

| 메서드 | 막는 것 | 막지 않는 것 |
|--------|---------|--------------|
| `preventDefault()` | 브라우저의 기본 동작(링크 이동, 폼 전송, 체크박스 토글 등) | 전파 |
| `stopPropagation()` | 다음 객체로의 전파 | 같은 객체의 나머지 리스너, 기본 동작 |
| `stopImmediatePropagation()` | 다음 객체로의 전파와 같은 객체의 나머지 리스너 | 기본 동작 |

```js
link.addEventListener('click', (e) => {
  e.preventDefault()  // 이동 취소, 전파는 계속
  e.defaultPrevented  // true
})
```

- `preventDefault()`는 `cancelable`이 `true`이고 `passive` 리스너 안이 아닐 때만 효과가 있습니다. 아니면 조용히 무시됩니다(브라우저가 콘솔에 경고를 남길 수 있습니다).
- `defaultPrevented`로 다른 리스너가 이미 취소했는지 확인할 수 있습니다.
- `stopPropagation()`을 호출해도 같은 객체에 붙은 다른 리스너는 모두 실행됩니다. 그 리스너까지 막으려면 `stopImmediatePropagation()`입니다. 등록 순서가 곧 우선순위입니다.
- 이벤트 핸들러(`on*`)에서는 `false`를 반환해도 취소됩니다. `addEventListener`의 반환값은 무시됩니다.

**흔한 실수:**

- 기본 동작을 막으려고 `stopPropagation()`을 쓰는 것입니다. 둘은 독립입니다.
- `stopPropagation()`을 습관적으로 쓰는 것입니다. 상위의 위임 리스너, 분석 코드, "바깥 클릭" 감지가 이벤트를 받지 못합니다(자세히는 45편). 전파를 막는 대신 `defaultPrevented` 같은 상태로 소통합니다.
- `await`나 `setTimeout` 뒤에서 `preventDefault()`를 부르는 것입니다. 리스너가 끝나면 기본 동작이 진행되므로 동기로 실행되는 동안에만 효과가 있습니다.

## 리스너 옵션 once / passive / capture

옵션 객체의 세 가지 값입니다(`capture`·`once`·`passive` 옵션은 Baseline 2017).

| 옵션 | 기본값 | 의미 |
|------|--------|------|
| `capture` | `false` | 캡처링 단계에서 호출 |
| `once` | `false` | 한 번 호출한 뒤 자동 제거 |
| `passive` | 이벤트에 따라 다름 | `preventDefault()`를 호출하지 않겠다는 약속 |

```js
el.addEventListener('click', init, { once: true })
el.addEventListener('touchstart', onTouch, {
  passive: true,
})
```

- `once`: 콜백이 실행되기 직전에 제거되므로 콜백 안에서 같은 리스너를 다시 등록하면 새 리스너가 됩니다.
- `passive`: 이 리스너에서 `preventDefault()`를 불러도 무시됩니다. 브라우저는 스크롤을 막을 수 있는 리스너가 있는지 알아야 스크롤 시작을 기다릴지 정하는데, passive이면 기다리지 않고 스크롤을 진행합니다.
- 표준이 정한 기본값: `touchstart`, `touchmove`, `wheel`, `mousewheel`을 `Window`, `document`, `documentElement`, `body`에 붙이면 `passive`가 `true`입니다. 다른 요소에 붙인 리스너와 다른 이벤트는 `false`입니다. 이 기본값은 터치 이벤트는 Baseline 2020이고 `wheel`은 Safari가 적용하지 않아 Baseline이 아닙니다. 스크롤을 막아야 하면 `{ passive: false }`를 명시합니다.
- `signal`도 옵션입니다(위 참조).
- 스크롤·터치 이벤트와 `passive`의 관계는 09편에서 자세히 다룹니다.

## 이벤트 위임

이벤트 위임(event delegation)은 자식마다 리스너를 붙이는 대신 공통 조상에 리스너 하나를 두고, 버블링으로 올라온 이벤트에서 실제 대상을 가려내는 방식입니다.

```js
list.addEventListener('click', (e) => {
  const btn = e.target.closest('button[data-id]')
  if (!btn || !list.contains(btn)) return
  remove(btn.dataset.id)
})
```

- 리스너가 한 개라 메모리와 등록 비용이 줄고, 나중에 추가되는 자식에도 자동으로 적용됩니다.
- `e.target`은 클릭된 가장 깊은 요소(아이콘 `span` 등)일 수 있어서 `closest()`로 원하는 요소를 찾습니다(자세히는 04편). `list.contains(btn)`은 컨테이너 바깥의 같은 조건 요소를 거르기 위한 검사입니다.
- 위임이 안 되는 경우: 버블링하지 않는 이벤트(`focus`, `blur`, `mouseenter` 등), 중간에서 `stopPropagation()`이 호출된 경우입니다. 포커스는 `focusin`·`focusout`을 쓰거나 `capture: true`로 상위에서 받습니다.
- 섀도 DOM 안의 요소는 위임 대상의 `target`이 호스트로 바뀌어 보입니다. 실제 대상은 `e.composedPath()[0]`입니다(자세히는 21편).
- 컴포넌트에서는 호스트 요소나 섀도 루트에 위임 리스너를 붙이면 자식이 바뀌어도 리스너를 다시 달 필요가 없습니다.

## CustomEvent

`CustomEvent`는 임의의 데이터를 `detail`에 실어 보낼 수 있는 이벤트입니다. 컴포넌트가 바깥에 상태 변화를 알리는 표준 수단입니다.

```js
const e = new CustomEvent('item-select', {
  detail: { id: 7 },
  bubbles: true,
  composed: true,
})
card.dispatchEvent(e)
// 리스너: (ev) => ev.detail.id // 7
```

- `detail`의 기본값은 `null`이고 어떤 값이든 담을 수 있습니다. 복제되지 않고 같은 참조로 전달되므로 객체를 바꾸면 모든 리스너에게 보입니다.
- `bubbles`, `cancelable`, `composed`는 기본값이 `false`입니다. 바깥 조상이 받게 하려면 `bubbles: true`를, 섀도 경계를 넘게 하려면 `composed: true`를 함께 지정합니다.
- 이름은 내장 이벤트와 겹치지 않게 짓고 `detail`의 모양을 문서화합니다. 이름·`detail` 설계는 25편에서 다룹니다.
- 데이터가 없으면 `new Event(type)`으로 충분합니다. 필드가 여럿이면 `Event`를 상속한 클래스를 만들어 멤버를 두는 방법도 있습니다.

## dispatchEvent

`target.dispatchEvent(event)`는 이벤트를 대상에 보냅니다. 브라우저가 이벤트를 보내는 방식과 같은 전파 규칙이 적용됩니다.

```js
const ev = new Event('ping', { cancelable: true })
const ok = el.dispatchEvent(ev)
// ok는 취소되지 않았으면 true, preventDefault()가 불렸으면 false
```

- 동기로 실행됩니다. 모든 리스너가 끝난 뒤에야 `dispatchEvent`가 돌아오므로 리스너의 결과(`defaultPrevented`)를 바로 읽을 수 있습니다.
- 반환값은 `cancelable`이 `false`이거나 `preventDefault()`가 불리지 않았으면 `true`입니다. "취소되지 않았으니 기본 동작을 진행"하는 패턴에 씁니다.
- 이미 보내는 중인 이벤트를 다시 보내면 `InvalidStateError`입니다.
- 리스너가 던진 예외는 `dispatchEvent` 호출자에게 전달되지 않습니다. 예외는 전역 `error` 이벤트로 보고되고 나머지 리스너는 계속 실행됩니다.

```js
el.addEventListener('x', () => { throw new Error('a') })
el.addEventListener('x', () => console.log('b'))
el.dispatchEvent(new Event('x')) // 'b' 출력, 예외는 error로 보고
```

- 스크립트가 보낸 이벤트는 `isTrusted`가 `false`입니다.
- 링크·체크박스 같은 요소는 클릭 활성화 동작을 가집니다. `new MouseEvent('click')`을 `dispatchEvent`하면 실제 클릭처럼 이동·토글이 일어나지만 `new Event('click')`은 `MouseEvent`가 아니라서 일어나지 않습니다.
- 이벤트는 신호이므로 `dispatchEvent`로 "작업을 실행"시키려 하지 않습니다. 작업은 함수로 호출하고 알림이 필요할 때만 이벤트를 씁니다.

## composed / bubbles / cancelable

이벤트 생성 시 지정하는 세 가지 불리언입니다. 모두 기본값이 `false`이며 만든 뒤에는 바꿀 수 없습니다.

| 옵션 | 참이면 | 거짓이면 |
|------|--------|----------|
| `bubbles` | 대상에서 조상으로 버블링 | 버블링 단계 생략 |
| `cancelable` | `preventDefault()`가 취소를 일으킴 | `preventDefault()`가 효과 없음 |
| `composed` | 섀도 루트 경계를 넘어 호스트 바깥까지 전파 | 섀도 트리 안에서만 전파 |

- `composed`가 `false`인 이벤트는 섀도 루트에서 전파가 멈춥니다. 바깥에서는 그 이벤트를 받을 수 없습니다. 사용자 정의 이벤트를 섀도 컴포넌트 바깥으로 보내려면 `bubbles: true, composed: true`입니다.
- 브라우저가 만드는 `click`, `keydown` 같은 사용자 입력 이벤트는 `composed`입니다. 경계를 넘지 않는 이벤트의 목록은 21편에서 다룹니다.
- 읽기 전용 알림은 `cancelable`을 `false`로 두고, 외부가 막을 수 있는 동작 앞의 이벤트는 `true`로 둡니다(`submit` 이전의 `before-close` 같은 설계).
- `defaultPrevented`와 `dispatchEvent`의 반환값으로 취소 여부를 확인합니다.

## 전역 에러 이벤트

처리되지 않은 오류는 `Window`의 이벤트로도 전달됩니다. 두 종류가 있습니다.

### error

스크립트 실행 중 잡히지 않은 예외가 나면 `Window`에 `ErrorEvent`(`type`이 `'error'`)가 보내집니다. `cancelable`이며 버블링하지 않습니다.

```js
window.addEventListener('error', (e) => {
  console.log(e.message, e.filename, e.lineno, e.colno)
  console.log(e.error) // 던져진 값(Error 객체 등)
})
```

- `window.onerror`는 `(message, source, lineno, colno, error)` 인수를 받고, `true`를 반환하면 이벤트가 취소되어 기본 보고(콘솔 오류)를 막습니다.
- 교차 출처 스크립트의 오류는 정보가 가려져 `message`가 `'Script error.'`, `filename`이 빈 문자열, 줄 번호가 0이 됩니다. 세부 정보를 받으려면 스크립트에 `crossorigin`과 CORS 응답이 필요합니다(자세히는 62편).
- `img`, `script` 같은 리소스의 로드 실패도 그 요소에 `error` 이벤트를 보냅니다. 이 이벤트는 버블링하지 않으므로 `window.addEventListener('error', fn, true)`처럼 캡처링으로 받습니다.
- 리스너 안에서 던진 예외도 같은 방식으로 보고됩니다.
- 워커의 오류는 `Worker` 객체의 `error` 이벤트로 올라옵니다(자세히는 54편).

### unhandledrejection

처리기가 붙지 않은 상태로 거부된 프라미스는 `unhandledrejection` 이벤트(`PromiseRejectionEvent`)를 일으킵니다. `promise`와 `reason`을 가지며 `cancelable`입니다.

```js
window.addEventListener('unhandledrejection', (e) => {
  console.log(e.reason)  // 거부 사유
  e.preventDefault()     // 콘솔 오류 보고를 막음
})
```

- 거부 시점이 아니라 마이크로태스크 처리 뒤에 태스크로 알려집니다. 그 사이에 `.catch()`를 붙이면 이벤트는 발생하지 않습니다.
- 이미 `unhandledrejection`이 발생한 프라미스에 나중에 처리기를 붙이면 `rejectionhandled` 이벤트가 발생합니다.
- 프라미스 자체는 ECMAScript의 영역이고 이 이벤트만 호스트가 제공합니다(자세히는 08편).

### reportError

`self.reportError(e)`는 예외를 던지지 않고 처리되지 않은 예외와 같은 방식으로 `error` 이벤트를 `Window`(또는 워커 전역)에 보냅니다(Chrome 95·Firefox 93·Safari 15.4부터).

```js
for (const fn of callbacks) {
  try { fn() } catch (err) { reportError(err) }
}
// 한 콜백이 실패해도 나머지가 실행되고, 오류는 error로 보고
```

- 호출자의 실행 흐름을 끊지 않으면서 오류를 전역 에러 처리 경로에 올립니다. 사용자 콜백을 여럿 호출하는 라이브러리에서 쓰입니다.
- 실행 중단 없이 `error` 리스너와 콘솔 보고가 일어납니다.

## 핵심 정리

- `EventTarget`은 `addEventListener`·`removeEventListener`·`dispatchEvent`를 가지며, 리스너는 type·callback·capture가 같으면 중복 등록되지 않고 `once`·`passive`·`signal`은 동일성에 영향을 주지 않습니다.
- 이벤트는 캡처링(루트→부모) → 타깃 → 버블링(부모→루트) 순으로 전파되고, `target`은 고정이며 `currentTarget`은 리스너마다 바뀝니다.
- `preventDefault()`는 기본 동작을, `stopPropagation()`은 전파를, `stopImmediatePropagation()`은 같은 객체의 나머지 리스너까지 막으며, `passive` 리스너에서는 `preventDefault()`가 무시됩니다.
- 이벤트 위임은 조상에 리스너 하나를 두고 `closest()`로 대상을 찾는 방식이며 버블링하지 않는 이벤트에는 쓸 수 없습니다.
- `CustomEvent`는 `detail`로 데이터를 보내고, 섀도 경계 밖으로 보내려면 `bubbles`와 `composed`를 모두 켜야 하며, `dispatchEvent`는 동기로 실행됩니다.
- 처리되지 않은 오류는 `error`, 거부된 프라미스는 `unhandledrejection`으로 `Window`에 알려지고 `reportError`로 직접 보고할 수 있습니다.
