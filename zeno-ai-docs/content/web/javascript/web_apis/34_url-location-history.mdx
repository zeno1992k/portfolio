## URL을 애플리케이션 상태로 보기

URL은 주소창에 보이는 문자열이면서 북마크, 공유, 새로고침, 뒤로 가기가 모두 복원하는 유일한 상태입니다. 화면의 어떤 상태를 URL에 담을지가 SPA 설계의 첫 결정입니다.

| URL에 담는 상태 | URL에 담지 않는 상태 |
|-----------------|----------------------|
| 현재 화면(경로), 선택한 항목의 식별자 | 마우스 올림, 입력 중인 임시 값 |
| 검색어, 필터, 정렬, 페이지 번호 | 토큰, 비밀번호 같은 민감한 값 |
| 공유해도 같은 화면이 나와야 하는 값 | 크기가 큰 데이터, 직렬화되지 않는 객체 |

- 기준은 "이 주소를 다른 사람에게 보내면 같은 화면이 나와야 하는가"입니다.
- URL이 진실의 원천이면 흐름은 한 방향입니다. 사용자 조작이 URL을 바꾸고, URL의 변화가 화면 상태를 갱신합니다. 화면 상태를 바꾼 뒤 URL을 맞추는 양방향 동기화는 어긋나기 쉽습니다(자세히는 31편).
- URL에 담은 값은 모두 문자열입니다. 숫자와 불리언으로 쓰려면 읽을 때 변환하고 잘못된 값은 기본값으로 대체합니다.
- 비밀 값은 서버 로그, Referer 헤더, 브라우저 기록에 남으므로 URL에 넣지 않습니다.
- 어떤 값은 기록 항목에 붙이는 상태 객체(history.state)에 둡니다. 스크롤 위치처럼 공유할 필요는 없지만 뒤로 가기에서 복원해야 하는 값이 해당합니다(아래 절).

## URL 구성 요소와 상대 URL 해석

`URL` 객체는 문자열을 구성 요소로 분해하고, 속성을 바꾸면 전체 문자열을 다시 만듭니다.

```js
const u = new URL('https://me:pw@a.com:8080/x/y?q=1#top')
u.protocol // 'https:'
u.username // 'me'
u.host     // 'a.com:8080'
u.hostname // 'a.com'
u.port     // '8080'
u.pathname // '/x/y'
u.search   // '?q=1'
u.hash     // '#top'
u.origin   // 'https://a.com:8080'
```

- 읽기 전용은 `origin`과 `searchParams`입니다. 나머지는 대입하면 `href`가 갱신됩니다.
- `protocol`은 끝의 `:`를, `search`는 앞의 `?`를, `hash`는 앞의 `#`를 포함합니다. 값이 없으면 빈 문자열입니다.
- 스킴의 기본 포트(`https`의 443)는 `port`가 빈 문자열이 됩니다.
- 구문이 틀린 문자열을 `new URL()`에 넘기면 TypeError입니다. 상대 URL은 기준(base)이 없으면 틀린 URL입니다.

두 번째 인수 base를 주면 상대 URL을 그 기준으로 해석합니다.

```js
const base = 'https://a.com/x/y/z?k=1'
new URL('w', base).href      // https://a.com/x/y/w
new URL('../w', base).href   // https://a.com/x/w
new URL('/w', base).href     // https://a.com/w
new URL('?q=2', base).href   // https://a.com/x/y/z?q=2
new URL('#t', base).href     // https://a.com/x/y/z?k=1#t
new URL('//b.com/w', base).href // https://b.com/w
```

- 기준의 마지막 경로 조각(`z`)은 디렉터리가 아니라 파일로 보고 버립니다. 그래서 `w`는 `/x/y/w`가 됩니다.
- HTML에서 상대 URL의 기준은 문서의 `document.baseURI`입니다. 문서에 `base` 요소가 있으면 첫 번째 `base`의 `href`가 기준이 되어, 문서 주소가 아니라 그 값으로 모든 상대 링크가 해석됩니다.
- 사용자가 입력한 주소를 검증할 때는 예외 대신 검사나 `null` 반환을 씁니다.

```js
URL.canParse('/docs', 'https://a.com') // true
URL.canParse('/docs')                  // false
URL.parse('/docs', 'https://a.com')    // URL 객체
URL.parse('/docs')                     // null
```

- `URL.canParse()`는 파싱 가능 여부를 불리언으로 알려 줍니다. Baseline 2023입니다.
- `URL.parse()`는 성공하면 `URL` 객체를, 실패하면 `null`을 돌려주고 예외를 던지지 않습니다. Baseline 2024입니다.
- `canParse()`로 검사한 뒤 `new URL()`을 호출하면 파싱이 두 번 일어납니다. 객체가 필요하면 `URL.parse()` 한 번이 낫습니다.

## URL과 URLSearchParams

`URLSearchParams`는 쿼리 문자열을 이름과 값의 쌍 목록으로 다루는 객체입니다. `url.searchParams`는 그 URL의 쿼리와 연결된 `URLSearchParams`이고, 어느 쪽을 바꿔도 다른 쪽에 반영됩니다.

```js
const url = new URL('https://a.com/list?page=2&tag=a&tag=b')
const p = url.searchParams
p.get('page')     // '2' (문자열)
p.getAll('tag')   // ['a', 'b']
p.set('page', 3)
url.href          // https://a.com/list?page=3&tag=a&tag=b
```

만드는 방법은 네 가지입니다.

```js
new URLSearchParams('?a=1&b=2')          // 앞의 ? 는 무시
new URLSearchParams({ a: '1', b: '2' })  // 객체
new URLSearchParams([['a', '1'], ['a', '2']]) // 쌍의 배열
new URLSearchParams(location.search)     // 현재 주소
```

## URLSearchParams 메서드

| 메서드 | 동작 |
|--------|------|
| `append(name, value)` | 같은 이름이 있어도 끝에 쌍을 추가 |
| `set(name, value)` | 첫 쌍의 값을 바꾸고 같은 이름의 나머지는 삭제. 없으면 추가 |
| `get(name)` | 첫 값. 없으면 `null` |
| `getAll(name)` | 같은 이름의 모든 값 배열. 없으면 빈 배열 |
| `has(name)`, `has(name, value)` | 이름(또는 이름과 값)이 있는지 |
| `delete(name)`, `delete(name, value)` | 이름(또는 이름과 값이 맞는 쌍)을 삭제 |
| `sort()` | 이름 기준으로 정렬. 같은 이름의 순서는 유지 |
| `toString()` | 인코딩한 쿼리 문자열. 앞의 `?` 없음 |
| `entries()`, `keys()`, `values()`, `forEach()` | 순회. 객체 자체도 이터러블 |
| `size` | 쌍의 전체 개수. 같은 이름도 각각 센다 |

- `size`는 Baseline 2023입니다. `has()`와 `delete()`의 `value` 인수는 비교적 최근에 추가되어 오래된 브라우저에는 없습니다.
- 값은 항상 문자열로 저장됩니다. `set('n', 1)`은 `'1'`이 됩니다.
- `null`이나 `undefined`를 값으로 넣으면 각각 문자열 `'null'`, `'undefined'`가 됩니다. 값이 없으면 `delete()`로 지웁니다.
- 순회는 쌍 단위입니다. `Object.fromEntries(p)`는 같은 이름이 여럿이면 마지막 값만 남깁니다.
- 쌍 목록을 바꾸면 연결된 `url.search`가 다시 만들어집니다.

**흔한 실수:**

- `Number(p.get('page'))`: 값이 없으면 `null`이 0으로 변환됩니다. 있는지 먼저 확인하고 변환 결과가 `NaN`인지도 검사합니다.
- 필터를 지우려고 `set(name, '')`를 쓰는 것: `?tag=`가 남습니다. `delete()`를 씁니다.
- 쿼리를 문자열 이어 붙이기(`'?q=' + text`)로 만드는 것: `&`, `#`, 공백이 들어 있으면 주소가 깨집니다. `URLSearchParams`에 값을 넣습니다.

## 인코딩 규칙

`URLSearchParams`는 `application/x-www-form-urlencoded` 규칙으로 쓰고 읽습니다.

- 쓸 때: 영문자, 숫자, `*`, `-`, `.`, `_`만 그대로 두고 나머지는 UTF-8 바이트를 `%XX`로 바꿉니다. 공백은 `%20`이 아니라 `+`입니다.
- 읽을 때: `+`는 공백으로, `%XX`는 해당 바이트로 되돌립니다. 그래서 `a=b+c`와 `a=b%20c`는 모두 값이 `'b c'`입니다.
- `get()`에 넘기는 이름과 값은 디코딩된 형태입니다. 인코딩된 이름으로 찾으면 `null`입니다.
- `foo=`와 `foo`는 모두 `get()`이 빈 문자열을 돌려줍니다.

```js
const p = new URLSearchParams()
p.append('q', 'a b&c')
p.toString()              // 'q=a+b%26c'
new URLSearchParams('q=a+b%26c').get('q') // 'a b&c'
```

`encodeURIComponent()`는 다른 규칙입니다. 문자열 한 조각을 URI 구성 요소로 인코딩합니다.

| 항목 | `URLSearchParams` | `encodeURIComponent` |
|------|-------------------|----------------------|
| 공백 | `+` | `%20` |
| 그대로 두는 문자 | 영문자, 숫자, `* - . _` | 영문자, 숫자, `- _ . ! ~ * ' ( )` |
| `! ~ ' ( )` | `%21 %7E %27 %28 %29` | 그대로 |
| 쓰임 | 쿼리 쌍 목록 | 경로 조각, 단일 값 |

- 쿼리의 이름과 값에는 `URLSearchParams`를 쓰고, 경로의 한 조각(`/users/` 뒤의 이름)에는 `encodeURIComponent`를 씁니다.
- `decodeURIComponent`는 `+`를 공백으로 바꾸지 않습니다. 쿼리를 직접 디코딩하면 `+`가 남습니다.
- `encodeURIComponent`에 짝이 없는 서로게이트 문자를 넣으면 URIError입니다.
- `url.search`를 문자열로 직접 대입하면 쿼리용 인코딩 규칙으로 처리되어 공백이 `%20`이 됩니다. `searchParams`를 수정하면 다시 직렬화되어 `+`가 됩니다. 같은 주소의 표기가 달라질 수 있으므로 한쪽 방식으로 통일합니다.

## Location 객체

`location`(`window.location`)은 현재 문서의 URL을 담은 객체이고, `URL`과 같은 구성 요소 속성을 가집니다(`href`, `protocol`, `host`, `hostname`, `port`, `pathname`, `search`, `hash`). `origin`은 읽기 전용입니다.

| 멤버 | 동작 |
|------|------|
| `location.href = url`, `assign(url)` | 새 주소로 이동하고 기록 항목을 추가 |
| `replace(url)` | 이동하지만 현재 기록 항목을 대체. 뒤로 가기로 돌아올 수 없음 |
| `reload()` | 현재 문서를 다시 불러옴 |
| `toString()` | `href`와 같은 문자열 |

- `href`, `pathname`, `search`를 대입하면 문서 전체를 새로 불러옵니다. `hash`만 바꾸면 불러오지 않고 문서 안에서 이동하며, 기록 항목이 추가되고 `hashchange`가 발생합니다.
- `replace()`는 로그인 후 리다이렉트처럼 이전 화면으로 돌아오면 안 되는 이동에 씁니다. `assign()`을 쓰면 뒤로 가기를 누를 때마다 다시 리다이렉트되어 빠져나올 수 없습니다.
- 페이지 이동 없이 주소만 바꾸려면 `location`이 아니라 `history.pushState()`를 씁니다(아래 절).
- 같은 코드로 `location`과 `URL`을 다루기 쉽도록 `new URL(location.href)`로 객체를 만들어 쓰는 편이 안전합니다.

## History API

`history`는 현재 탭의 세션 기록(방문 목록)을 다루는 객체입니다. Baseline 2015입니다.

| 멤버 | 동작 |
|------|------|
| `length` | 현재 항목을 포함한 기록 항목 수(읽기 전용) |
| `state` | 현재 항목에 붙은 상태 객체(읽기 전용). 없으면 `null` |
| `back()`, `forward()` | 한 칸 이동. 끝에서는 아무 일도 없음 |
| `go(n)` | 상대 위치로 이동. 범위를 벗어나면 아무 일도 없음. `go(0)`은 다시 불러옴 |
| `scrollRestoration` | `'auto'`(기본) 또는 `'manual'` |

- 이동 메서드는 비동기입니다. 호출한 직후에는 `location`이 바뀌지 않았고, 이동이 끝나면 `popstate`가 발생합니다.
- `length`는 위치를 알려 주지 않습니다. 현재가 몇 번째 항목인지, 뒤로 갈 수 있는지는 알 수 없습니다(항목을 읽는 방법은 Navigation API로 35편).
- `history.state`는 `popstate`를 기다리지 않고 새로고침 직후에도 읽을 수 있습니다.
- `scrollRestoration`이 `'auto'`이면 브라우저가 뒤로 가기에서 스크롤 위치를 복원합니다. 화면이 비동기로 그려지는 SPA에서는 복원 시점에 내용이 아직 없을 수 있어 `'manual'`로 두고 직접 복원합니다.

```js
history.scrollRestoration = 'manual'
addEventListener('popstate', (e) => {
  render()
  scrollTo(0, e.state?.y ?? 0) // 렌더링 후 직접 복원
})
```

## pushState와 replaceState

`pushState()`는 새 기록 항목을 추가하고, `replaceState()`는 현재 항목을 바꿉니다. 둘 다 문서를 불러오지 않고 주소와 상태 객체만 바꿉니다.

```js
history.pushState({ id: 7 }, '', '/orders/7')
history.replaceState({ id: 7, y: 480 }, '')
```

인수는 `(state, unused, url)`입니다.

- `state`: 상태 객체입니다. 구조화 복제(structured clone)로 직렬화되므로 객체, 배열, 날짜, Map, Set 같은 복제 가능한 값만 담깁니다. 함수나 DOM 노드를 넣으면 DataCloneError입니다. 클래스 인스턴스는 일반 객체로 복제되어 메서드를 잃습니다.
- `unused`: 역사적 이유로 남은 자리입니다. 빈 문자열을 넘기고, 제목은 바뀌지 않으므로 `document.title`을 직접 바꿉니다.
- `url`: 생략하면 현재 주소를 씁니다. 상대 URL을 쓸 수 있고, 현재 문서와 같은 출처여야 합니다. 다른 출처이면 SecurityError입니다.
- 짧은 시간에 너무 자주 호출해도 SecurityError가 날 수 있습니다.

동작 규칙은 다음과 같습니다.

- 호출해도 `popstate`와 `hashchange`는 발생하지 않습니다. 화면 갱신은 호출한 쪽이 직접 합니다.
- 새 문서를 요청하지 않으므로 같은 주소를 직접 열면(새로고침, 링크 공유) 서버가 그 경로에도 앱을 내려 줘야 합니다.
- 상태 객체는 브라우저가 디스크에 저장할 수 있어 크기에 제한이 있고, 너무 크면 예외가 납니다. 식별자와 스크롤 위치 같은 작은 값만 두고 큰 데이터는 저장소에 둡니다(자세히는 40편, 41편).

`pushState`와 `replaceState`의 선택 기준은 뒤로 가기가 그 단계를 거쳐야 하는지입니다.

| 상황 | 선택 |
|------|------|
| 다른 화면으로 이동 | `pushState` |
| 필터·정렬을 바꾼 결과 | 보통 `pushState` |
| 입력할 때마다 갱신되는 검색어 | `replaceState` |
| 주소 정규화, 리다이렉트, 초기 상태 붙이기 | `replaceState` |

**흔한 실수:** 같은 주소를 반복해서 `pushState`하면 뒤로 가기를 눌러도 같은 화면이 계속 나옵니다. 현재 주소와 같으면 호출하지 않습니다. 그리고 타이핑마다 `pushState`하면 기록이 글자 수만큼 쌓입니다.

## popstate

`popstate`는 같은 문서 안에서 현재 기록 항목이 바뀌었을 때 `window`에서 발생하는 이벤트입니다. `PopStateEvent`의 `state`는 이동한 항목의 상태 객체이고 없으면 `null`입니다.

```js
addEventListener('popstate', (event) => {
  render(location.pathname, event.state)
})
```

- 발생하는 경우: 뒤로·앞으로 가기, `back()`, `forward()`, `go()`로 같은 문서의 항목으로 이동할 때.
- 발생하지 않는 경우: `pushState()`와 `replaceState()` 호출, 페이지 처음 로드.
- 핸들러가 실행될 때 `location`은 이미 새 주소입니다.
- 다른 문서의 항목으로 이동하는 경우는 문서가 바뀌므로 이 이벤트의 대상이 아닙니다(bfcache 복원은 아래 `pageshow`).
- 핸들러 안에서 `pushState()`를 호출하면 앞으로 갈 수 있던 항목이 사라집니다. 핸들러는 화면만 그립니다.

처음 로드 때는 `popstate`가 오지 않으므로 앱이 시작할 때 현재 주소로 한 번 화면을 그려야 합니다. 이 점이 `popstate`로 라우팅을 만들 때의 기본 구조입니다(자세히는 35편).

## hashchange

`hashchange`는 주소의 프래그먼트(`#` 뒤)가 바뀌었을 때 `window`에서 발생합니다. `HashChangeEvent`의 `oldURL`과 `newURL`이 전체 주소를 알려 줍니다.

```js
addEventListener('hashchange', (e) => {
  console.log(new URL(e.newURL).hash) // '#/orders/7'
})
```

- 발생하는 경우: `location.hash` 대입, `#` 링크 클릭, 프래그먼트만 다른 항목 사이의 뒤로·앞으로 가기.
- `pushState()`와 `replaceState()`로 해시를 바꾸면 발생하지 않습니다.
- 해시 라우팅(`#/orders/7`)은 서버가 경로를 몰라도 되고 서버 설정이 필요 없는 대신, 프래그먼트가 서버로 전송되지 않고 문서 안 이동 링크(건너뛰기 링크)와 충돌합니다(자세히는 33편). 요즘은 History API로 경로를 바꾸는 방식이 기본입니다.
- 프래그먼트는 문서 안 요소로 이동하는 용도가 본래 목적입니다. `id`가 같은 요소가 있으면 스크롤되고 `:target`이 적용됩니다.

## 텍스트 프래그먼트

텍스트 프래그먼트(text fragment)는 `id`가 없어도 페이지 안의 특정 문구로 이동하고 강조하는 URL 문법입니다. Baseline 2024입니다.

```text
https://a.com/doc#:~:text=start,end
https://a.com/doc#:~:text=before-,word,-after
https://a.com/doc#:~:text=one&text=two
```

- `#:~:`는 프래그먼트 지시자(fragment directive)이고, 뒤의 `text=`가 텍스트 지시자입니다. 형식은 `text=[prefix-,]textStart[,textEnd][,-suffix]`입니다.
- `textStart`만 쓰면 그 문구의 첫 번째 일치를, `textStart,textEnd`로 범위를, `prefix-`와 `-suffix`로 앞뒤 문맥을 지정해 동음 문구를 구별합니다. `&`로 여러 지시자를 잇습니다.
- 특수 문자(`-`, `,`, `&`)가 문구에 들어 있으면 퍼센트 인코딩합니다.
- 대소문자를 구별하지 않고, 한 블록 요소 안의 문구만 찾습니다.
- 사용자 활성화가 있는 이동에서만 동작하고, `iframe` 안에서는 적용되지 않습니다.
- 지시자는 `location.hash`에서 제거되어 스크립트가 읽을 수 없습니다. 지원 여부는 `document.fragmentDirective`로 확인합니다.
- 강조 모양은 `::target-text`로 바꿉니다. 사이트가 끄려면 `Document-Policy: force-load-at-top` 응답 헤더를 보냅니다.

## bfcache와 pageshow·pagehide

bfcache(back/forward cache)는 사용자가 페이지를 떠날 때 문서를 메모리에 통째로 보관했다가 뒤로·앞으로 가기에서 즉시 복원하는 브라우저 최적화입니다. 복원된 페이지는 JavaScript 실행이 멈췄던 자리에서 DOM과 변수 상태 그대로 다시 시작합니다.

```js
addEventListener('pageshow', (e) => {
  if (e.persisted) refreshStaleData() // bfcache에서 복원됨
})
addEventListener('pagehide', (e) => {
  if (e.persisted) pauseConnections() // 보관될 수 있음
})
```

- `pageshow`는 최초 로드(`load` 뒤)와 bfcache 복원 때 모두 발생하며, `persisted`가 `true`이면 복원입니다. 최초 로드에서는 `false`입니다.
- `pagehide`는 페이지를 떠날 때 발생하고, `persisted`가 `true`이면 브라우저가 보관을 시도한다는 뜻입니다. 실제로 보관된다는 보장은 아닙니다.
- 복원된 페이지는 `DOMContentLoaded`와 `load`를 다시 거치지 않으므로 초기화 코드가 다시 돌지 않습니다. 오래된 데이터 갱신, 끊어진 연결 복구는 `pageshow`에서 합니다.
- 보관을 막는 요인: `unload` 리스너(브라우저에 따라), `Cache-Control: no-store`, `window.opener` 참조, 진행 중인 IndexedDB 트랜잭션·fetch·WebSocket·WebRTC 연결.
- 연결은 `pagehide`에서 닫고 `pageshow`에서 다시 열면 보관 대상이 됩니다.
- 확인은 Chrome 개발자 도구의 Application 탭 Back/forward cache 항목에서 합니다.
- `freeze`와 `resume` 이벤트는 Chromium에서만 발생합니다.

## unload 폐기와 대안

`unload` 이벤트는 폐기되었고 쓰지 않아야 합니다. 이유는 두 가지입니다.

- 모바일에서 앱을 전환하거나 브라우저를 닫을 때 발생하지 않는 경우가 많아 믿을 수 없습니다.
- 리스너가 있으면 페이지가 파괴된다고 가정해야 하므로 bfcache 보관이 막힙니다.

Chrome은 기본적으로 `unload`를 발생시키지 않습니다. 계속 쓰려면 `Permissions-Policy` 응답 헤더의 `unload` 지시어로 다시 허용해야 합니다.

떠날 때 이벤트 순서는 `beforeunload`, `pagehide`, `unload`입니다. 대안은 다음과 같습니다.

| 하려는 일 | 대안 |
|-----------|------|
| 저장·로그 전송 | `visibilitychange`에서 `document.visibilityState`가 `'hidden'`일 때 실행 |
| 전송 보장 | `navigator.sendBeacon()`(자세히는 36편) |
| 연결 정리 | `pagehide` |

```js
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') {
    navigator.sendBeacon('/log', JSON.stringify(stats))
  }
})
```

- `visibilitychange`는 탭 전환, 최소화, 앱 전환, 페이지 닫기에서 발생하며 모바일에서도 가장 믿을 수 있는 마지막 신호입니다.
- `pagehide`는 모바일에서 항상 발생한다고 믿을 수 없어 저장 시점으로는 `visibilitychange`가 더 낫습니다.

## beforeunload

`beforeunload`는 문서가 닫히거나 다른 곳으로 이동하기 직전에 `window`에서 발생하며, 취소하면 브라우저가 이탈 확인 창을 띄웁니다.

```js
const guard = (event) => {
  event.preventDefault()
  event.returnValue = true // 오래된 Chrome·Edge(119 미만) 호환
}
addEventListener('beforeunload', guard)
removeEventListener('beforeunload', guard)
```

- 확인 창을 띄우는 표준 방법은 `event.preventDefault()`입니다. `returnValue`는 구형 호환용입니다.
- 사용자가 페이지와 상호작용(sticky 사용자 활성화)한 적이 없으면 확인 창이 뜨지 않습니다.
- 메시지는 브라우저가 정한 문구로 고정되고 코드가 바꿀 수 없습니다.
- 모바일에서는 앱을 전환한 뒤 브라우저를 닫는 경우처럼 발생하지 않을 수 있습니다.
- 리스너가 있으면 일부 브라우저(Firefox)가 bfcache 보관을 막습니다. 저장하지 않은 변경이 있을 때만 등록하고, 없어지면 해제합니다.

```js
input.addEventListener('input', () => {
  if (input.value) addEventListener('beforeunload', guard)
  else removeEventListener('beforeunload', guard)
})
```

- 앱 안에서 `pushState`로 하는 화면 전환은 문서가 사라지지 않으므로 `beforeunload`가 발생하지 않습니다. 앱 내부 이탈 확인은 링크 클릭을 가로채거나 Navigation API로 처리합니다(자세히는 35편).
- 자동 저장은 `beforeunload`가 아니라 `visibilitychange`에서 합니다.

## 핵심 정리

- 공유와 새로고침에서 복원돼야 하는 값은 URL에 담고, 임시 상태·민감한 값·큰 데이터는 담지 않습니다. 쿼리 값은 모두 문자열이라 읽을 때 변환하고 검증합니다.
- `URL`은 구성 요소로 분해하고 base로 상대 URL을 해석하며, 검증은 `URL.canParse()`(Baseline 2023)나 `URL.parse()`(Baseline 2024)로 합니다.
- `URLSearchParams`는 공백을 `+`로 쓰고, `encodeURIComponent`는 `%20`으로 씁니다. 쿼리는 `URLSearchParams`, 경로 조각은 `encodeURIComponent`입니다.
- `location`의 `href`, `assign()`은 문서를 새로 불러오고 `replace()`는 기록을 대체합니다. `pushState()`와 `replaceState()`는 불러오지 않고 주소와 상태만 바꾸며 `popstate`와 `hashchange`를 일으키지 않습니다.
- `popstate`는 뒤로·앞으로 가기에서만 발생하므로 처음 화면은 직접 그립니다.
- bfcache 복원은 `pageshow`의 `persisted`로 알아내고, 떠날 때의 저장과 전송은 `unload` 대신 `visibilitychange`로 하며, `beforeunload`는 변경이 있을 때만 등록합니다.
