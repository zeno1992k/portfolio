## Drag and Drop

HTML Drag and Drop은 요소나 데이터를 포인터로 끌어서 다른 요소 위에 놓는 브라우저 내장 기능입니다. 드래그하는 쪽(소스)과 놓이는 쪽(타깃)이 서로 다른 이벤트를 받고, 둘 사이의 데이터는 `DataTransfer` 객체로 전달됩니다.

- 소스 요소는 `draggable="true"` 속성으로 만듭니다. `draggable`의 기본값은 자동이며, `img`와 `href`가 있는 `a`, 텍스트 선택 영역은 속성 없이도 드래그됩니다. 그 밖의 요소는 `false`로 취급됩니다.
- 타깃은 별도 속성이 필요 없고 이벤트로 드롭을 받겠다고 선언합니다.
- 드래그 중의 데이터는 "드래그 데이터 저장소"에 있습니다. 이 저장소가 읽고 쓸 수 있는 시점은 이벤트마다 다릅니다(아래 "DataTransfer").
- 지원 상태는 Baseline 널리 지원(2015)입니다.

```html
<li draggable="true" data-id="7">할 일</li>
<ul id="drop-zone">여기에 놓기</ul>
```

## 드래그 이벤트 순서와 dragover의 preventDefault

드래그 이벤트는 소스에서 발생하는 것과 타깃에서 발생하는 것으로 나뉩니다.

| 이벤트 | 발생 위치 | 시점 |
|--------|-----------|------|
| `dragstart` | 소스 | 드래그 시작 |
| `drag` | 소스 | 드래그하는 동안 반복 |
| `dragenter` | 타깃 후보 | 포인터가 요소에 들어옴 |
| `dragover` | 타깃 후보 | 요소 위에 있는 동안 반복 |
| `dragleave` | 타깃 후보 | 포인터가 요소를 벗어남 |
| `drop` | 타깃 | 놓음 |
| `dragend` | 소스 | 드래그 종료(드롭 성공·취소 모두) |

핵심 규칙은 **`dragover`를 취소해야 드롭이 허용된다**는 것입니다. 취소하지 않으면 그 요소는 드롭 대상이 아니라서 `drop`이 발생하지 않고, 소스가 원래 자리로 돌아가는 애니메이션이 나타납니다. `dragenter`도 같은 방식으로 취소합니다.

```js
const allow = (e) => e.preventDefault()
zone.addEventListener('dragenter', allow)
zone.addEventListener('dragover', allow)
zone.addEventListener('drop', (e) => {
  e.preventDefault() // 브라우저의 기본 처리(링크 열기 등) 차단
  const text = e.dataTransfer.getData('text/plain')
})
```

- `drop`에서도 `preventDefault()`를 호출합니다. 호출하지 않으면 브라우저가 놓인 데이터를 기본 방식으로 처리합니다. 파일을 놓으면 페이지를 떠나 파일을 열고, 링크를 놓으면 그 주소로 이동합니다.
- `drag`는 일정 간격으로 반복 발생하고 `dragover`도 요소 위에 있는 동안 반복 발생합니다. 핸들러를 가볍게 유지해야 합니다.
- `dragend`는 소스에서 발생합니다. `dataTransfer.dropEffect`가 `none`이면 드롭이 일어나지 않은 것이고, 그 외 값이면 그 동작이 수행된 것입니다.
- 포인터가 타깃의 자식 요소로 들어가면 새 대상에 `dragenter`가, 이전 요소에 `dragleave`가 발생합니다. `dragleave`만으로 "타깃을 완전히 벗어났다"고 판단하면 자식 위를 지날 때마다 하이라이트가 깜박입니다. 진입 횟수를 세거나 `relatedTarget`으로 자식 요소 여부를 확인합니다.

**흔한 실수:** `dragover`에서 `preventDefault()`를 빼먹고 `drop`이 안 온다고 찾는 것입니다. `drop` 핸들러가 아무 문제 없어도 `dragover` 취소가 없으면 호출되지 않습니다.

## DataTransfer

`DataTransfer`는 드래그 이벤트(`DragEvent`)의 `dataTransfer` 속성으로 얻는 객체이며, 붙여넣기 이벤트(`ClipboardEvent`)의 `clipboardData`도 같은 타입입니다.

| 멤버 | 내용 |
|------|------|
| `setData(type, value)` | 형식별 문자열 데이터를 저장. 같은 형식이 있으면 교체 |
| `getData(type)` | 형식에 해당하는 문자열을 반환 |
| `clearData([type])` | 한 형식 또는 전부 제거 |
| `types` | 저장된 형식 문자열의 배열. 파일이 있으면 `Files`가 포함됨 |
| `items` | `DataTransferItem` 목록. 각 항목에 `kind`(`string` 또는 `file`)와 `type`이 있음 |
| `files` | 드래그 중인 로컬 파일의 `FileList`. 파일이 없으면 빈 목록 |
| `effectAllowed` | 소스가 허용하는 동작 |
| `dropEffect` | 타깃이 선택하는 동작 |

드래그 데이터 저장소는 이벤트에 따라 세 가지 모드가 됩니다.

| 모드 | 이벤트 | 가능한 일 |
|------|--------|-----------|
| 읽기·쓰기 | `dragstart` | 데이터 추가·수정 |
| 읽기 전용 | `drop` | 데이터 읽기 |
| 보호 | `drag`, `dragenter`, `dragover`, `dragleave`, `dragend` | 형식·종류 목록만 확인, 데이터는 읽을 수 없음 |

```js
item.addEventListener('dragstart', (e) => {
  e.dataTransfer.setData('text/plain', item.dataset.id)
  e.dataTransfer.effectAllowed = 'move'
})
// dragover 안에서: getData('text/plain') === '' (보호 모드)
// dragover 안에서: types.includes('text/plain') === true
```

- 보호 모드 때문에 `dragover`에서는 내용을 보고 허용 여부를 정할 수 없습니다. `types`, `items[i].kind`, `items[i].type`으로 형식만 확인합니다. 내용은 `drop`에서 읽습니다.
- 소스와 타깃이 서로 다른 앱이어도 같은 모델이 적용됩니다. 외부 앱에서 끌어온 파일은 `kind`가 `file`인 항목으로 나타납니다.

### effectAllowed와 dropEffect

`effectAllowed`는 소스가 `dragstart`에서 정하고, `dropEffect`는 타깃이 `dragover`에서 정합니다. 최종 동작은 둘이 겹치는 범위에서 결정되고, 겹치지 않으면 `none`이 되어 드롭이 거부됩니다.

| 속성 | 가능한 값 |
|------|-----------|
| `effectAllowed` | `none`, `copy`, `copyLink`, `copyMove`, `link`, `linkMove`, `move`, `all`, `uninitialized` |
| `dropEffect` | `none`, `copy`, `link`, `move` |

- `dragstart`에서 `effectAllowed`의 초기값은 `uninitialized`이고, 이 상태는 모든 동작을 허용하는 것으로 처리됩니다.
- `dropEffect`는 커서 모양(복사 `+` 표시 등)에도 반영됩니다. 파일 드롭 영역이라면 `dragover`에서 `e.dataTransfer.dropEffect = 'copy'`로 지정합니다.
- 이 값들은 드롭 동작을 안내할 뿐 실제 이동·복사는 직접 구현합니다. `move`를 선택해도 소스 요소가 저절로 옮겨지지 않습니다.

```js
zone.addEventListener('drop', (e) => {
  e.preventDefault()
  const id = e.dataTransfer.getData('text/plain')
  zone.append(document.querySelector(`[data-id="${id}"]`))
})
```

## setDragImage()

`setDragImage(element, x, y)`는 드래그 중 포인터를 따라다니는 이미지를 바꿉니다. 읽기·쓰기 모드인 `dragstart`에서만 동작합니다.

```js
item.addEventListener('dragstart', (e) => {
  const ghost = document.querySelector('#drag-ghost')
  e.dataTransfer.setDragImage(ghost, 10, 10)
})
```

- `x`, `y`는 이미지의 왼쪽 위 모서리에서 포인터까지의 오프셋(CSS 픽셀)입니다.
- `img` 요소는 원본 크기 그대로 쓰이고, 다른 요소는 렌더링된 모습으로 이미지가 만들어집니다.
- 지정하지 않으면 브라우저가 소스 요소로 이미지를 만듭니다.

## 파일·디렉터리 드롭과 webkitGetAsEntry()

운영체제에서 끌어 온 파일은 `drop`에서 `dataTransfer.items`로 읽습니다. 각 항목의 `kind`가 `file`이면 `getAsFile()`로 `File` 객체를 얻습니다(자세히는 48편).

```js
const hasFile = (e) =>
  [...e.dataTransfer.items].some((i) => i.kind === 'file')
zone.addEventListener('dragover', (e) => {
  if (hasFile(e)) {
    e.preventDefault()
    e.dataTransfer.dropEffect = 'copy'
  }
})
zone.addEventListener('drop', (e) => {
  e.preventDefault()
  const files = [...e.dataTransfer.items]
    .map((i) => i.getAsFile())
    .filter(Boolean)
})
```

- 파일 드롭을 받을 영역이 아닌 곳에 파일을 놓으면 브라우저가 파일을 열어 페이지를 떠납니다. 의도치 않은 이탈을 막으려면 `window`의 `drop`에서 파일 항목일 때 `preventDefault()`를 호출합니다.
- 같은 처리를 `input type="file"`의 `change` 이벤트(`e.target.files`)에도 연결해 두면 드롭을 쓸 수 없는 환경의 대안이 됩니다.
- `items`와 `files`는 모두 `drop`에서 읽습니다. `files`는 `dragover` 같은 이전 이벤트에서는 비어 있습니다.

폴더를 드롭하면 `getAsFile()`로는 디렉터리를 읽을 수 없습니다. `webkitGetAsEntry()`가 `FileSystemEntry` 계열 객체를 돌려줍니다.

| 항목의 종류 | 반환값 |
|-------------|--------|
| 파일 | `FileSystemFileEntry` |
| 디렉터리 | `FileSystemDirectoryEntry` |
| 파일이 아닌 항목, 읽을 수 없는 시점 | `null` |

```js
function walk(entry) {
  if (entry.isFile) {
    entry.file((file) => console.log(file.name))
  } else {
    const reader = entry.createReader()
    const read = () => reader.readEntries((list) => {
      if (list.length === 0) return // 끝
      list.forEach(walk)
      read() // 다음 묶음
    })
    read()
  }
}
// drop 안에서: walk(item.webkitGetAsEntry())
```

- `readEntries()`는 디렉터리 내용을 한 번에 주지 않고 묶음 단위로 돌려줍니다. Chromium 계열은 한 번에 최대 100개이며, 빈 배열이 올 때까지 반복 호출해야 전부 읽습니다.
- `webkitGetAsEntry()`는 드래그 데이터 저장소가 읽힐 때만 동작하므로 `dragstart`와 `drop`에서만 값을 얻습니다. 비동기 콜백 안에서 호출하면 이미 늦어서 `null`이 됩니다. `drop` 핸들러가 끝나기 전에 모든 항목의 엔트리를 먼저 꺼냅니다.
- 이름은 `webkit` 접두어가 붙어 있지만 Firefox를 포함한 비WebKit 브라우저에도 구현되어 있습니다. 나중에 `getAsEntry()`로 바뀔 수 있다는 MDN 안내가 있으므로 두 이름을 모두 확인하는 방어 코드를 둡니다.

```js
const entry =
  item.webkitGetAsEntry?.() ?? item.getAsEntry?.()
```

## 정렬 가능한 목록의 키보드 대안

HTML Drag and Drop은 포인터로 끄는 동작이라서 키보드로는 쓸 수 없고, 끌기 자체가 어려운 사용자도 있습니다. WCAG 2.2 성공 기준 2.5.7(드래그 동작, AA)은 드래그로 하는 모든 기능을 드래그 없이 단일 포인터로도 할 수 있게 요구합니다. 목록 정렬의 대안으로는 항목 옆의 위·아래 이동 버튼이 권장됩니다. 키보드 사용자는 이 버튼을 Tab으로 누를 수 있습니다.

드래그 정렬은 `dragover`에서 포인터 위치에 따라 소스를 대상의 앞이나 뒤에 끼워 넣습니다.

```js
let dragged = null
list.addEventListener('dragstart', (e) => {
  dragged = e.target.closest('li')
})
list.addEventListener('dragover', (e) => {
  e.preventDefault()
  const over = e.target.closest('li')
  if (!over || over === dragged) return
  const box = over.getBoundingClientRect()
  const after = e.clientY > box.top + box.height / 2
  over[after ? 'after' : 'before'](dragged)
})
```

같은 목록을 버튼으로 옮기는 함수는 한 개로 충분합니다.

```js
function move(item, dir) {
  const target = dir < 0
    ? item.previousElementSibling
    : item.nextElementSibling
  if (!target) return
  dir < 0 ? target.before(item) : target.after(item)
  item.querySelector('button').focus() // 포커스 유지
  status.textContent = `${item.textContent} 이동됨`
}
```

- 이동 후 포커스가 사라지지 않게 같은 항목의 버튼에 포커스를 돌려줍니다(자세히는 28편).
- 결과는 `aria-live` 영역(`role="status"`)에 문장으로 알려 스크린 리더 사용자도 변화를 알 수 있게 합니다.
- WAI-ARIA 실습 지침의 재배열 리스트박스 예제는 위·아래 버튼과 함께 `Alt`+위·아래 방향키 단축키를 제공하고, 단축키는 해당 위치에 포커스가 있을 때만 동작하게 하며 `aria-keyshortcuts`로 알립니다.

## Clipboard API

Clipboard API는 `navigator.clipboard`로 시스템 클립보드를 비동기(Promise)로 읽고 쓰는 API입니다. 기존의 `document.execCommand('copy')` 방식을 대체합니다.

| 메서드 | 하는 일 | 반환 |
|--------|---------|------|
| `writeText(text)` | 텍스트 쓰기 | `Promise<void>` |
| `readText()` | 텍스트 읽기 | `Promise<string>` |
| `write(items)` | `ClipboardItem` 배열 쓰기 | `Promise<void>` |
| `read()` | `ClipboardItem` 배열 읽기 | `Promise<ClipboardItem[]>` |

```js
btn.addEventListener('click', async () => {
  await navigator.clipboard.writeText('복사할 문장')
  const text = await navigator.clipboard.readText()
  // text: '복사할 문장'
})
```

- 보안 컨텍스트(HTTPS, localhost)에서만 쓸 수 있고 웹 워커에서는 쓸 수 없습니다.
- 쓰기는 일시적 사용자 활성화(클릭 같은 최근의 사용자 동작)가 있거나 `clipboard-write` 권한이 있으면 가능합니다.
- 읽기는 일시적 사용자 활성화가 필요하고, Chromium은 `clipboard-read` 권한 프롬프트를 띄웁니다. Firefox와 Safari는 권한 대신 붙여넣기 메뉴를 잠깐 보여 주고 사용자가 누르면 읽게 해 줍니다. 같은 출처에서 복사한 내용은 이 프롬프트가 생략됩니다.
- Chromium은 `Permissions-Policy` 헤더로 이 권한을 제한하며(자세히는 60편의 권한), 읽기에는 문서 포커스도 필요합니다.
- 클릭 같은 사용자 동작 안에서 호출하는 것이 모든 브라우저에서 안전한 방법입니다. 타이머나 페이지 로드 시점의 호출은 거부될 수 있어서 `try`/`catch`로 `NotAllowedError`를 처리합니다.

**흔한 실수:** 복사 실패를 처리하지 않는 것입니다. 사용자 동작 밖에서 호출하거나 HTTP 페이지에서 `navigator.clipboard`가 `undefined`일 때 아무 안내 없이 실패합니다. 실패 시 텍스트를 선택 상태로 보여 주는 식의 대안을 둡니다.

## 비동기 클립보드 지원 상태

비동기 Clipboard API는 Baseline 2024로, 2024년 6월 Firefox 127이 `read()`·`write()`를 지원하면서 핵심 브라우저 전체로 확대되었습니다. 시작 버전은 다음과 같습니다.

| 엔진 | 시작 버전 |
|------|-----------|
| Chrome·Edge | 76·79 |
| Firefox | 127 |
| Safari | 13.1 |

- 위 상태는 `writeText()`·`readText()`·`read()`·`write()` 기본 기능입니다. 형식별 세부는 다음과 같이 엔진별로 다릅니다.

| 기능 | 지원 상태 |
|------|-----------|
| `ClipboardItem.supports()` | Baseline 2025(Chrome 121, Firefox 127, Safari 18.4) |
| `image/svg+xml` 쓰기 | Chromium 124 이상만 |
| `web ` 접두어 사용자 지정 형식 | Chromium 104 이상만 |
| `clipboardchange` 이벤트 | Chromium 144 이상만 |

- 지원하지 않는 환경에서는 `copy` 이벤트 방식으로 대체합니다(아래 "copy·cut 이벤트와 clipboardData").
- 같은 클립보드를 다루지만 동기 이벤트 방식은 훨씬 오래전인 2017년부터 Baseline입니다.

## ClipboardItem과 MIME 형식

`ClipboardItem`은 클립보드의 항목 하나를 나타내며, 같은 내용을 여러 MIME 형식으로 담을 수 있습니다. 생성자에 형식을 키로, 데이터를 값으로 하는 객체를 넘깁니다. 값은 `Blob`이거나 `Blob`으로 이행되는 Promise입니다.

```js
const html = new Blob(['<b>굵게</b>'], { type: 'text/html' })
const text = new Blob(['굵게'], { type: 'text/plain' })
const item = new ClipboardItem({
  'text/html': html,
  'text/plain': text,
})
await navigator.clipboard.write([item])
```

- 표준이 필수로 정한 형식은 `text/plain`, `text/html`, `image/png` 세 가지입니다.
- 한 항목에 여러 형식을 담으면 붙여넣는 앱이 지원하는 가장 알맞은 형식을 골라 씁니다. 텍스트 편집기는 `text/plain`을, 리치 에디터는 `text/html`을 씁니다.
- `Blob` 대신 Promise를 넘기면 이미지 생성이나 `fetch`처럼 시간이 걸리는 데이터도 사용자 동작 안에서 `write()`를 호출하고 데이터는 나중에 채울 수 있습니다.
- 사용자 지정 형식은 `web ` 접두어를 붙입니다. 예를 들어 `'web text/csv'`입니다.
- `text/html`은 브라우저가 위험한 마크업을 걸러 낼 수 있고, `image/png`는 걸러 내지 않습니다. 붙여넣은 HTML은 항상 신뢰할 수 없는 입력으로 다룹니다(자세히는 63편).
- `presentationStyle`은 `unspecified`, `inline`, `attachment` 중 하나를 돌려줍니다.

`ClipboardItem.supports(type)`은 쓰기 전에 형식이 지원되는지 확인하는 정적 메서드입니다(Baseline 2025).

```js
ClipboardItem.supports('image/png')     // true
ClipboardItem.supports('image/svg+xml') // Chromium은 true
if (ClipboardItem.supports('image/svg+xml')) {
  // SVG를 쓰는 경로
} else {
  // PNG로 변환해 쓰는 경로
}
```

읽기는 `read()`로 항목을 받고 `types`로 형식을 확인한 뒤 `getType()`으로 `Blob`을 얻습니다.

```js
const items = await navigator.clipboard.read()
for (const item of items) {
  if (item.types.includes('image/png')) {
    const blob = await item.getType('image/png')
    img.src = URL.createObjectURL(blob)
  }
}
```

- `getType()`에 없는 형식을 넘기면 에러가 납니다. `types`를 먼저 확인합니다.
- `URL.createObjectURL()`로 만든 URL은 사용이 끝나면 `revokeObjectURL()`로 해제합니다(자세히는 48편).

## copy·cut 이벤트와 clipboardData

`copy`와 `cut`은 사용자가 복사·잘라내기를 할 때 발생하는 동기 이벤트입니다. 버블링되고 취소할 수 있으며, `ClipboardEvent`의 `clipboardData`(`DataTransfer`)에 클립보드에 들어갈 데이터를 넣을 수 있습니다.

```js
document.addEventListener('copy', (e) => {
  const sel = String(document.getSelection())
  const text = `${sel}\n출처: 예시 사이트`
  e.clipboardData.setData('text/plain', text)
  e.preventDefault() // 기본 복사 대신 위 데이터 사용
})
```

- 이벤트를 취소하지 않으면 현재 선택된 내용이 그대로 복사됩니다. 취소하면 `setData()`로 넣은 데이터로 대체됩니다.
- `cut`은 편집 가능한 영역에서 선택 내용이 삭제되기 전에 발생합니다. `preventDefault()`를 호출하면 삭제도 막힙니다. 지우는 동작은 직접 구현합니다.
- 사용자가 직접 복사한 동작 위에서 일어나므로 권한 프롬프트가 없고, 모든 브라우저에서 오래전부터 쓸 수 있습니다.
- 비동기 API는 코드로 복사 버튼을 만들 때, 이벤트는 사용자가 하는 복사 동작에 개입할 때 씁니다.
- `clipboardData`는 브라우저가 이벤트를 만들 때는 `null`이 아닙니다. 생성자로 직접 만든 `ClipboardEvent`는 `null`일 수 있습니다.

## 붙여넣기 이벤트

`paste`는 사용자가 붙여넣기를 할 때 클립보드의 내용이 삽입되기 직전에 발생합니다. 버블링되고 취소할 수 있으며, 이벤트의 대상은 포커스가 있는 요소입니다. 포커스가 없으면 `body`입니다. 읽기 전용 모드의 `clipboardData`로 내용을 읽습니다.

```js
input.addEventListener('paste', (e) => {
  const text = e.clipboardData.getData('text/plain')
  const files = e.clipboardData.files
  if (files.length > 0) {
    e.preventDefault() // 이미지 붙여넣기를 직접 처리
    upload(files[0])
  }
})
```

- `getData('text/plain')`, `getData('text/html')`로 형식별 문자열을, `files`로 붙여넣은 파일(스크린샷 같은 이미지 포함)을 읽습니다.
- 모드가 읽기 전용이라 `paste` 안에서 `setData()`를 호출해도 삽입될 내용이 바뀌지 않습니다. 바꾸려면 `preventDefault()`로 기본 삽입을 막고, 가공한 값을 직접 삽입합니다.
- 비동기 API의 `read()`와 달리 권한 프롬프트가 없습니다. 사용자의 붙여넣기 동작이 곧 허락이기 때문입니다.
- `paste`에서 읽은 `text/html`은 외부 앱이 만든 값이라 DOM에 `innerHTML`로 넣으면 XSS 위험이 있습니다. 텍스트로 넣거나 정제합니다.

| 항목 | 이벤트 방식 | 비동기 API |
|------|-------------|------------|
| 시작 계기 | 사용자의 복사·붙여넣기 동작 | 코드(버튼 클릭 등) |
| 권한 프롬프트 | 없음 | 있음(엔진별 방식 상이) |
| 읽는 곳 | `paste` 이벤트 안에서만 | 사용자 활성화 안에서 아무 때나 |
| 지원 | Baseline 널리 지원(2017) | Baseline 2024 |

## 핵심 정리

- 드롭이 되려면 `dragover`(와 `dragenter`)를 `preventDefault()`로 취소해야 하고, `drop`에서도 취소해 기본 동작을 막습니다.
- `DataTransfer`의 데이터는 `dragstart`에서 쓰고 `drop`에서 읽습니다. 그 사이 `dragover`는 형식 목록만 보입니다.
- 파일은 `drop`의 `items`(`kind`가 `file`)로 읽고, 폴더는 `webkitGetAsEntry()`와 `readEntries()` 반복 호출로 순회합니다.
- 드래그 정렬은 반드시 위·아래 버튼 같은 단일 포인터·키보드 대안을 함께 제공합니다(WCAG 2.2의 2.5.7).
- 비동기 Clipboard API(Baseline 2024)는 보안 컨텍스트와 사용자 동작이 필요하고, `ClipboardItem.supports()`(Baseline 2025)로 형식을 확인합니다.
- `copy`·`cut`·`paste` 이벤트는 `clipboardData`로 사용자 동작에 개입하며, 권한 프롬프트가 없습니다.
