## HTMLElement 상속

커스텀 요소(custom element)는 작성자가 생성자와 프로토타입을 직접 정의한 HTML 요소입니다. 클래스로 만들며, 자율형(autonomous) 커스텀 요소는 반드시 `HTMLElement`를 상속합니다.

```js
class UserCard extends HTMLElement {
  constructor() {
    super()
  }
}
```

- `HTMLElement`를 상속하면 `id`, `hidden`, `style`, `addEventListener`, `append` 같은 모든 내장 요소의 공통 API를 그대로 물려받습니다.
- 자율형 요소가 `HTMLParagraphElement` 같은 다른 내장 요소 클래스를 상속하면 인스턴스를 만들 때 TypeError입니다. 그런 상속은 확장형(customized built-in)에서만 허용됩니다(아래 "Customized Built-in Elements").
- `new HTMLElement()`처럼 정의에 등록되지 않은 생성자를 직접 호출해도 TypeError입니다. 생성자는 `define`으로 등록된 클래스를 통해서만 동작합니다.
- 자율형 커스텀 요소는 특별한 의미가 없고 자식 내용을 그대로 나타냅니다. 의미와 접근성은 작성자가 채웁니다(자세히는 27편).

## customElements.define

`customElements.define(name, constructor)`는 태그 이름과 클래스를 연결합니다. `customElements`는 `window`의 읽기 전용 프로퍼티이고 전역 `CustomElementRegistry`를 가리킵니다.

```js
customElements.define('user-card', UserCard)
const el = document.createElement('user-card')
el instanceof UserCard // true
```

정의 이후에는 같은 이름의 요소가 생성될 때마다 그 클래스의 인스턴스가 만들어집니다. 정의하기 전에 이미 문서에 있던 요소는 업그레이드됩니다(아래 "업그레이드 과정").

`define`은 클래스의 프로토타입에서 다음 이름을 읽어 정의에 저장합니다. 정의 시점에 한 번만 읽으므로 이후에 프로토타입을 바꿔도 반영되지 않습니다.

| 읽는 값 | 종류 | 용도 |
|---------|------|------|
| `connectedCallback` 등 생명주기 콜백 | 인스턴스 메서드 | 문서 연결·해제, 이동, 속성 변경 시 호출(자세히는 18편) |
| `observedAttributes` | 정적 프로퍼티 | `attributeChangedCallback`을 받을 속성 이름 목록 |
| `formAssociated` | 정적 프로퍼티 | 폼 연결 요소로 만들지 여부(자세히는 26편) |
| `disabledFeatures` | 정적 프로퍼티 | `internals`, `shadow` 기능 끄기(아래 "CustomElementRegistry") |

세 번째 인수 `{ extends: 'button' }`는 확장형 정의에 씁니다.

## 커스텀 엘리먼트 네이밍 규칙

유효한 커스텀 요소 이름은 다음을 모두 만족해야 합니다. 어기면 `define`이 SyntaxError를 던집니다.

| 조건 | 이유 |
|------|------|
| 첫 글자가 ASCII 소문자 | 파서가 태그 이름으로 인식 |
| ASCII 대문자를 포함하지 않음 | HTML 요소 이름은 대소문자를 구분하지 않고 다룸 |
| 하이픈(`-`)을 포함 | HTML·SVG·MathML에는 앞으로도 하이픈이 든 요소를 추가하지 않으므로 충돌하지 않음 |
| 예약된 이름이 아님 | 기존 SVG·MathML 요소와 겹침 |

예약된 이름은 `annotation-xml`, `color-profile`, `font-face`, `font-face-src`, `font-face-uri`, `font-face-format`, `font-face-name`, `missing-glyph`입니다.

```js
customElements.define('user-card', A)   // ✅
customElements.define('UserCard', A)    // ❌ SyntaxError
customElements.define('card', A)        // ❌ SyntaxError
customElements.define('font-face', A)   // ❌ SyntaxError
```

- 위 조건 밖에서는 넓은 범위의 이름이 허용됩니다. 숫자와 비ASCII 글자도 쓸 수 있지만 관례는 소문자와 하이픈입니다.
- 이름에 팀이나 제품 접두사(`acme-button`)를 붙여 다른 라이브러리와의 충돌을 줄입니다. 전역 레지스트리에서는 이름이 하나뿐이기 때문입니다.
- 태그는 `<user-card />`처럼 자기 닫기를 쓸 수 없고 `<user-card></user-card>`로 닫아야 합니다. HTML 파서는 자기 닫기 문법을 무시하므로 뒤따르는 형제가 자식이 됩니다.

## customElements.get·getName·whenDefined

레지스트리는 정의를 조회하는 메서드를 제공합니다.

| 메서드 | 반환 |
|--------|------|
| `get(name)` | 해당 이름의 생성자, 없으면 `undefined` |
| `getName(constructor)` | 해당 생성자의 이름, 없으면 `null` |
| `whenDefined(name)` | 정의되면 생성자로 이행하는 Promise |

```js
customElements.get('user-card')    // class UserCard
customElements.get('nope-x')       // undefined
customElements.getName(UserCard)   // 'user-card'
```

- `get`은 이름이 유효하든 아니든 예외 없이 `undefined`를 돌려줍니다. 이름이 유효한지는 `define`과 `whenDefined`만 검사합니다.
- `getName`은 Chrome 117, Firefox 116부터 지원하지만 Safari는 아직 정식 지원 전이라 Baseline이 아닙니다.
- `whenDefined`는 이미 정의되어 있으면 즉시 이행된 Promise를 돌려주고, 유효하지 않은 이름이면 SyntaxError로 거부된 Promise를 돌려줍니다. 같은 이름을 여러 번 호출해도 정의될 때 한꺼번에 이행됩니다.

```js
await customElements.whenDefined('user-card')
document.querySelector('user-card').render() // 업그레이드 완료
```

`whenDefined`는 정의를 비동기로 불러오는 페이지에서 "정의가 끝난 뒤 메서드를 호출"하는 순서를 보장합니다. 정의 전에는 요소가 `HTMLElement` 인스턴스일 뿐이라 `render` 같은 메서드가 없습니다.

## 업그레이드 과정

업그레이드(upgrade)는 이미 만들어진 일반 요소를 커스텀 요소로 바꾸는 과정입니다. 문서에 `<user-card>`가 먼저 있고 `define`이 나중에 실행되는 경우에 일어납니다.

```html
<user-card name="Kim"></user-card>
<script src="user-card.js" async></script>
```

정의 전의 `user-card`는 이름이 유효한 "정의되지 않은 요소(undefined)"입니다. `HTMLElement` 인스턴스로서 `span`처럼 동작하다가, `define`이 호출되면 업그레이드됩니다. 업그레이드는 다음 순서로 진행됩니다.

1. `define`이 문서에서 해당 이름의 요소를 문서 순서대로 찾아 업그레이드를 예약합니다.
2. 그 요소에 대해 정의한 클래스의 생성자가 실행됩니다.
3. 생성자가 끝난 뒤, 이미 붙어 있던 속성마다 `attributeChangedCallback`이 호출됩니다(`observedAttributes`에 든 속성만).
4. 요소가 문서에 연결되어 있으면 `connectedCallback`이 호출됩니다.

- 같은 요소는 한 번만 업그레이드됩니다. 생성자가 예외를 던지면 요소는 "실패(failed)" 상태가 되어 다시 시도되지 않고, 예외는 콘솔에 보고됩니다.
- 업그레이드 시점에는 속성과 자식이 이미 있습니다. 파서나 `createElement`로 만들 때는 없다는 점이 다르므로, 생성자가 이를 가정하면 안 됩니다(아래 "생성자 제약").
- 자동 업그레이드는 문서 트리에 연결된 요소만 대상입니다. `createElement`로 만들어 붙이지 않은 요소는 정의 후에도 그대로이고, 문서에 삽입되는 순간 업그레이드됩니다.
- 연결 전에 업그레이드해야 하면 `customElements.upgrade(root)`를 씁니다. `root`의 모든 하위 요소(shadow를 포함)를 연결 여부와 무관하게 업그레이드합니다.

```js
const el = document.createElement('user-card')
customElements.define('user-card', UserCard)
el instanceof UserCard    // false (연결 전이라 그대로)
customElements.upgrade(el)
el instanceof UserCard    // true
```

### :defined 의사 클래스

`:defined`는 정의가 끝난 요소에 일치합니다. 내장 요소는 항상 일치하고, 커스텀 요소는 `define` 이후(업그레이드 성공 후)에만 일치합니다. 정의 전의 깜빡임(FOUC)을 막는 데 씁니다.

```css
user-card:not(:defined) {
  visibility: hidden;
}
```

`:not(:defined)`와 `whenDefined`를 함께 쓰면 필요한 요소가 모두 정의된 뒤에 영역을 보여 줄 수 있습니다.

```js
const undef = root.querySelectorAll(':not(:defined)')
const tags = new Set([...undef].map((el) => el.localName))
await Promise.all(
  [...tags].map((t) => customElements.whenDefined(t)),
)
root.hidden = false
```

## document.createElement과 Custom Element

`document.createElement('user-card')`는 정의되어 있으면 생성자를 즉시 실행해 그 클래스의 인스턴스를 돌려줍니다. `new UserCard()`도 같은 결과입니다.

```js
const a = document.createElement('user-card')
const b = new UserCard()
a instanceof UserCard // true (정의되어 있을 때)
a.isConnected         // false (아직 문서에 없음)
```

- 생성된 요소는 속성도 자식도 없는 상태입니다. 생성자가 속성이나 자식을 추가하면 `createElement`는 예외를 던지지 않고 `HTMLUnknownElement`를 반환하며, 원인 예외는 콘솔에 보고됩니다.
- 정의가 없는 이름이면 `HTMLElement`가 만들어지고, 나중에 `define`을 호출해도 연결되기 전까지 업그레이드되지 않습니다. `customElements.upgrade`나 문서 삽입으로 업그레이드합니다.
- 생성자가 `super()`가 만든 요소가 아닌 다른 객체를 반환하면 업그레이드는 TypeError로 실패합니다.
- 확장형은 두 번째 인수로 만듭니다: `document.createElement('button', { is: 'fancy-btn' })`.

| 만드는 경로 | 생성자 실행 시점 | 생성자 시점의 속성·자식 |
|-------------|------------------|-------------------------|
| 파서(정의가 먼저 있을 때) | 시작 태그를 만날 때 | 없음 |
| `createElement` / `new` | 호출하는 즉시 | 없음 |
| 업그레이드 | `define` 시점 또는 문서에 삽입되는 시점 | 있음 |

## Autonomous Custom Elements 구현

자율형 커스텀 요소(autonomous custom element)는 `extends` 없이 정의하고 태그 이름으로 직접 쓰는 요소입니다. 기본 구현은 클래스 → `define` → 마크업의 세 부분입니다.

```js
class UserCard extends HTMLElement {
  connectedCallback() {
    this.textContent = `Hello, ${this.getAttribute('name')}`
  }
}
customElements.define('user-card', UserCard)
```

```html
<user-card name="Kim"></user-card>
<!-- Hello, Kim -->
```

- 자율형 요소는 로컬 이름이 정의한 이름과 같습니다. `localName`이 `'user-card'`이고 `is` 속성은 쓰지 않습니다. 쓰더라도 효과가 없습니다.
- 속성은 소문자 이름으로 자유롭게 쓸 수 있습니다. 대문자가 든 이름은 HTML에서 소문자로 바뀝니다(자세히는 19편).
- 속성이나 자식을 읽어야 하는 작업은 생성자가 아닌 `connectedCallback`으로 옮깁니다. 렌더링의 전체 설계는 30편, 생명주기는 18편입니다.

### 생성자 제약

커스텀 요소의 생성자는 파서, `createElement`, 업그레이드 세 경로에서 모두 호출되므로 다음 규칙을 지켜야 합니다.

| 규칙 | 이유 |
|------|------|
| 인수 없는 `super()`를 첫 문장으로 호출 | 프로토타입 체인과 `this`를 먼저 만들어야 함 |
| `return`을 쓰지 않음(단순 조기 `return` 제외) | 다른 객체를 반환하면 TypeError |
| 속성과 자식을 읽지 않음 | 파서·`createElement` 경로에는 없음 |
| 속성과 자식을 추가하지 않음 | 위반하면 `createElement` 결과가 `HTMLUnknownElement` |
| `document.write`, `document.open` 사용 금지 | 파싱 도중의 문서를 깨뜨림 |

```js
constructor() {
  super()
  this.#count = 0                  // ✅ 초기 상태
  this.addEventListener('click', this.#onClick) // ✅ 리스너
  this.setAttribute('role', 'button')           // ❌ 속성 추가
  this.append(document.createElement('b'))      // ❌ 자식 추가
}
```

- 생성자에서는 초기 상태와 기본값, 이벤트 리스너, shadow root(자세히는 21편)만 준비합니다.
- 리소스 요청이나 렌더링은 `connectedCallback`으로 미룹니다. 이 콜백은 여러 번 호출될 수 있으므로 한 번만 해야 하는 작업에는 가드가 필요합니다(자세히는 18편).
- 생성자 안에서 이벤트를 발생시키지 않습니다. 아직 어떤 리스너도 붙기 전이라 받는 쪽이 없습니다.

## Customized Built-in Elements

확장형(customized built-in element)은 `button`, `p` 같은 기존 내장 요소를 상속해 기능을 더하는 요소입니다. 내장 요소의 의미와 기본 동작을 그대로 물려받는 것이 장점입니다.

```js
class FancyButton extends HTMLButtonElement {
  connectedCallback() { this.classList.add('fancy') }
}
customElements.define('fancy-button', FancyButton, {
  extends: 'button',
})
```

```html
<button is="fancy-button">Save</button>
```

- 정의할 때 `extends`에 내장 요소의 태그 이름을, 마크업에서는 `is` 속성에 정의한 이름을 씁니다. 로컬 이름은 `button`으로 유지됩니다.
- 상속하는 클래스는 그 태그가 쓰는 인터페이스와 맞아야 합니다. `extends: 'p'`에 `HTMLButtonElement`를 상속하면 TypeError입니다.
- `is` 값은 요소를 만들 때 저장됩니다. 나중에 `is` 속성을 바꿔도 동작이 바뀌지 않습니다.
- `extends`로 지정할 수 있는 것은 알려진 내장 요소뿐입니다. 이름이 커스텀 요소이거나 정의에 없는 태그이면 NotSupportedError입니다.
- 폼 요소를 확장하면 제출, 검증, 포커스 같은 내장 동작을 공짜로 얻습니다. 자율형으로 만드려면 직접 구현해야 합니다(자세히는 26편).
- 일부 내장 요소에는 shadow root를 붙일 수 없습니다(자세히는 21편).
- Chrome 67, Firefox 63부터 지원하지만 Safari는 지원 계획이 없습니다. Baseline이 아니므로 모든 브라우저를 대상으로 하는 컴포넌트는 자율형으로 만들고, 필요하면 내부에 내장 요소를 감싸는 방식을 씁니다.

## CustomElementRegistry

`CustomElementRegistry`는 이름·생성자·정의를 보관하는 저장소입니다. 문서마다 하나가 `window.customElements`로 주어지며, 앞서 본 `define`, `get`, `getName`, `whenDefined`, `upgrade`와 범위 지정용 `initialize`를 가집니다.

한 레지스트리 안에서는 이름과 생성자가 모두 일대일입니다.

```js
customElements.define('user-card', UserCard)
customElements.define('user-card', Other)
// ❌ NotSupportedError (이미 쓰인 이름)
customElements.define('other-card', UserCard)
// ❌ NotSupportedError (이미 등록한 생성자)
```

| 호출 | 예외 |
|------|------|
| 생성자가 아닌 값(화살표 함수 포함) | TypeError |
| 유효하지 않은 이름 | SyntaxError |
| 이미 쓰인 이름 | NotSupportedError |
| 이미 등록한 생성자 | NotSupportedError |
| `extends`가 커스텀 요소 이름이거나 알 수 없는 태그 | NotSupportedError |

- 정의는 취소하거나 바꿀 수 없습니다. 같은 이름을 다시 쓰려면 새 페이지(또는 아래의 별도 레지스트리)가 필요합니다.
- 번들이 두 번 로드되는 상황을 막으려면 정의 전에 `if (!customElements.get('user-card'))`로 확인합니다(자세히는 72편).
- `define`을 호출하는 동안 `define`을 다시 호출하면(생성자·`observedAttributes` getter 안에서의 재귀) NotSupportedError입니다.

### disabledFeatures

정적 프로퍼티 `disabledFeatures`는 문자열 배열이며 `internals`와 `shadow`를 지정할 수 있습니다. 해당 기능을 이 요소에서 막겠다는 선언입니다.

```js
class PlainBox extends HTMLElement {
  static disabledFeatures = ['internals', 'shadow']
}
```

- `internals`가 있으면 `attachInternals()`가, `shadow`가 있으면 `attachShadow()`가 NotSupportedError를 던집니다(자세히는 20편, 21편).
- 요소가 해당 기능을 쓰지 않음을 선언해, 사용하는 쪽이 shadow root나 internals를 붙이지 못하게 합니다.
- 이 값이 `shadow`일 때 이미 shadow root가 있는 요소를 업그레이드하면 업그레이드가 실패합니다.
- Chrome 77, Firefox 92부터 지원하고 Safari는 지원하지 않아서 Baseline이 아닙니다.

## Scoped Custom Element Registries

범위 지정 레지스트리(scoped custom element registry)는 전역이 아니라 특정 shadow root나 요소 하위에만 적용되는 별도의 레지스트리입니다. 서로 다른 라이브러리가 같은 이름을 다른 클래스로 쓰는 충돌을 피하려고 도입되었습니다.

`new CustomElementRegistry()`로 만들고 `define`으로 정의합니다.

```js
const scoped = new CustomElementRegistry()
scoped.define('user-card', LibUserCard)

const host = document.createElement('div')
const root = host.attachShadow({
  mode: 'open',
  customElementRegistry: scoped,
})
root.innerHTML = '<user-card></user-card>'
```

레지스트리를 연결하는 방법은 세 가지입니다.

| 방법 | 설명 |
|------|------|
| `attachShadow({ customElementRegistry })` | 그 shadow root 안의 요소가 해당 레지스트리를 사용 |
| `document.createElement(name, { customElementRegistry })` | 만들 요소가 해당 레지스트리를 사용 |
| `registry.initialize(root)` | 아직 레지스트리가 없는(null) 하위 노드에 지정하고 업그레이드 |

- 요소와 shadow root에는 `customElementRegistry` 프로퍼티가 있고 어떤 레지스트리를 쓰는지 읽을 수 있습니다. 일단 정해진 레지스트리는 바꿀 수 없습니다.
- 같은 이름을 레지스트리마다 다른 클래스에 연결할 수 있습니다.
- 범위 지정 레지스트리는 `extends`(확장형)를 지원하지 않습니다. 쓰면 NotSupportedError입니다.
- 전역 레지스트리의 `initialize`는 `Document`를 넘기거나 노드 문서의 레지스트리가 자신이 아니면 NotSupportedError입니다.
- Chrome 146, Edge 146, Safari 26부터 지원하고 Firefox는 지원하지 않아서 Baseline이 아닙니다. 지원 여부를 확인하고 쓰거나, 지원하지 않는 환경에서는 이름에 접두사를 붙이는 방식으로 충돌을 피합니다.

## 핵심 정리

- 자율형 커스텀 요소는 `HTMLElement`를 상속한 클래스를 `customElements.define`으로 등록해서 만들며, 이름은 소문자로 시작하고 하이픈을 포함해야 합니다.
- 생성자는 `super()`를 먼저 호출하고, 속성과 자식을 읽거나 추가하지 않고 초기 상태와 리스너만 준비합니다. 나머지는 `connectedCallback`에서 처리합니다.
- 정의 전에 있던 요소는 정의 시점에 업그레이드되며 순서는 생성자, 속성 콜백, `connectedCallback`입니다. 연결되지 않은 요소는 삽입되거나 `customElements.upgrade`를 부를 때 업그레이드됩니다.
- `get`·`getName`·`whenDefined`는 정의를 조회하고, 이름과 생성자는 한 레지스트리에서 한 번만 등록할 수 있어 중복 정의는 NotSupportedError입니다.
- 확장형(`extends`와 `is`)은 Safari가 지원하지 않고, 범위 지정 레지스트리는 Chrome 146과 Safari 26부터 지원하며 둘 다 Baseline이 아닙니다.
