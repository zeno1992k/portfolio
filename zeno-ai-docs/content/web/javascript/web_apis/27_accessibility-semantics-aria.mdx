## 접근성 트리와 보조 기술

접근성 트리(accessibility tree)는 브라우저가 DOM에서 만들어 보조 기술에 넘기는 구조입니다. 화면 낭독기 같은 보조 기술은 DOM이나 화면 픽셀이 아니라 이 트리를 읽습니다.

```text
HTML → DOM → 접근성 트리 → 플랫폼 접근성 API → 보조 기술
```

트리의 각 노드는 다음 정보를 가집니다.

| 항목 | 뜻 | 예 |
|------|-----|----|
| 역할(role) | 요소의 종류 | button, checkbox, heading |
| 이름(name) | 요소를 부르는 이름 | "저장" |
| 설명(description) | 이름을 보충하는 설명 | "변경 내용을 서버에 저장합니다" |
| 상태·속성 | 현재 조건 | 체크됨, 펼쳐짐, 비활성 |

- `display: none`인 요소와 `aria-hidden="true"`인 요소는 트리에서 빠집니다.
- 커스텀 요소는 기본적으로 특별한 역할이 없는 일반 요소입니다. 이름과 상태도 없으므로 구현자가 채워야 합니다.
- Shadow DOM 안의 내용은 접근성 트리에서 숨겨지지 않습니다. 슬롯에 들어간 내용은 슬롯 자리에 이어 붙은 구조(평탄화된 트리)로 보조 기술에 전달됩니다(슬롯은 22편).
- 브라우저 개발자 도구의 접근성 패널에서 요소별 역할, 이름, 상태를 확인할 수 있습니다.

## Semantic HTML 우선

시맨틱 HTML은 내용의 의미에 맞는 네이티브 요소를 쓰는 것입니다. 네이티브 요소는 역할, 이름 계산, 키보드 조작, 포커스, 폼 참여를 브라우저가 한꺼번에 제공합니다. 커스텀 컴포넌트를 만들 때도 이것이 먼저입니다.

```html
<!-- ❌ 역할도 키보드도 없다 -->
<div class="btn" onclick="save()">저장</div>

<!-- ✅ 역할, 포커스, Enter·Space 모두 제공 -->
<button type="button" onclick="save()">저장</button>
```

- `div`와 `span`에는 역할이 없습니다. `role="button"`을 붙여도 역할만 바뀌고 포커스와 키 조작은 생기지 않습니다.
- 컴포넌트는 안에 네이티브 요소를 두고 그것을 감싸는 방식이 가장 안전합니다.

```js
this.attachShadow({ mode: 'open' }).innerHTML =
  '<button part="button"><slot></slot></button>'
```

- 제목은 `h1`–`h6`, 목록은 `ul`·`ol`, 내비게이션은 `nav`, 표는 `table`을 씁니다. 컴포넌트 템플릿 안에서도 같습니다.
- 네이티브로 표현할 수 없는 위젯(탭, 트리, 콤보박스)만 ARIA로 의미를 더합니다.
- 컴포넌트 호스트 자체를 의미 있는 요소로 만들어야 할 때는 호스트에 역할을 부여하고 키보드·포커스를 직접 구현합니다(28편).

**흔한 실수:** 호스트를 `role="button"`으로 바꾸고 내부에 `button`을 또 두는 것입니다. 보조 기술에 버튼 안의 버튼이 전달됩니다. 역할은 한 곳에만 둡니다.

## ARIA 역할과 상태

ARIA(WAI-ARIA)는 보조 기술에 요소의 역할, 상태, 관계를 알리는 속성 모음입니다. 접근성 트리에만 영향을 줍니다. 모양, 동작, 포커스, 키보드는 바꾸지 않습니다.

| 구분 | 속성 | 예 |
|------|------|----|
| 역할 | `role` | `button`, `checkbox`, `tab`, `dialog`, `status` |
| 상태 | 자주 바뀌는 값 | `aria-checked`, `aria-expanded`, `aria-pressed`, `aria-selected`, `aria-disabled`, `aria-current` |
| 속성 | 잘 안 바뀌는 값 | `aria-label`, `aria-labelledby`, `aria-describedby`, `aria-controls`, `aria-haspopup` |

```html
<button aria-expanded="false"
        aria-controls="menu">메뉴</button>
<ul id="menu" hidden>...</ul>
```

- 상태는 바뀔 때마다 갱신해야 합니다. 시각 표시만 바꾸고 `aria-expanded`를 그대로 두면 보조 기술은 이전 상태를 읽습니다.
- 값은 문자열입니다. `aria-checked="true"`처럼 씁니다. 불리언 어트리뷰트처럼 존재 여부로 표현하지 않습니다.
- `aria-disabled="true"`는 비활성이라고 알리기만 합니다. 클릭과 포커스를 막지는 않습니다. 실제로 막으려면 `disabled`나 이벤트 처리가 필요합니다.
- `aria-hidden="true"`를 포커스 가능한 요소에 붙이면 보조 기술에서는 사라지는데 키보드로는 도달하는 상태가 됩니다. 붙이지 않습니다.
- 역할마다 필요한 상태와 자식 구조가 정해져 있습니다. 위젯별 패턴은 WAI-ARIA Authoring Practices에 정리되어 있습니다.
- 네이티브 요소의 역할을 `role`로 바꾸는 일은 피합니다. 헤딩을 `role="button"`으로 바꾸면 제목 구조가 사라집니다.

### ARIA 속성 반영

요소의 ARIA 어트리뷰트는 같은 이름의 프로퍼티로 읽고 쓸 수 있습니다(ARIA 반영, Baseline 2023: Chrome 103, Firefox 119, Safari 16.4). `aria-` 뒤를 이어 붙여 대문자로 시작하는 이름입니다.

```js
const btn = document.querySelector('button')
btn.ariaExpanded = 'true'   // aria-expanded="true"
btn.ariaLabel                // 어트리뷰트가 없으면 null
btn.ariaLabel = null         // 어트리뷰트 제거
```

| 어트리뷰트 | 프로퍼티 |
|------------|----------|
| `aria-label` | `ariaLabel` |
| `aria-expanded` | `ariaExpanded` |
| `aria-checked` | `ariaChecked` |
| `aria-live` | `ariaLive` |
| `role` | `role` |

- 프로퍼티는 어트리뷰트를 반영하므로 같은 값을 가리킵니다. 값은 문자열 또는 `null`입니다.
- `setAttribute('aria-expanded', ...)`를 쓰는 것과 결과가 같습니다. 어트리뷰트가 없는 상태가 `null`입니다.
- 프로퍼티가 `ElementInternals`에도 같은 이름으로 있습니다(아래 "ElementInternals와 접근성").

## Accessible Name

접근 가능한 이름(accessible name)은 보조 기술이 요소를 부르는 이름입니다. 버튼이면 "저장", 입력이면 "이메일 주소"처럼 읽힙니다. 이름이 없으면 낭독기는 역할만 말하고 무엇인지 알려 주지 못합니다. 브라우저는 다음 순서로 이름을 정합니다.

| 순서 | 출처 | 예 |
|------|------|----|
| 1 | `aria-labelledby`가 가리키는 요소의 텍스트 | `aria-labelledby="title"` |
| 2 | `aria-label` | `aria-label="닫기"` |
| 3 | 네이티브 레이블 | `label`, `img`의 `alt`, `fieldset`의 `legend`, `table`의 `caption` |
| 4 | 내용(해당 역할일 때) | `button`, `link`, `heading`의 텍스트 |
| 5 | `title` 어트리뷰트(마지막 대안) | `title="닫기"` |

```html
<button aria-label="닫기">✕</button>
<!-- 이름: 닫기 (✕ 글자 대신) -->

<h2 id="t">주문 내역</h2>
<section aria-labelledby="t">...</section>
<!-- 이름: 주문 내역 -->
```

- 위의 앞 순서가 뒤 순서를 덮어씁니다. `aria-label`이 있으면 버튼의 내용 텍스트는 이름이 되지 않습니다.
- 화면에 보이는 텍스트를 이름으로 쓰는 편이 좋습니다. `aria-labelledby`로 보이는 제목을 가리키거나 버튼 안 텍스트를 그대로 둡니다. 보이는 글자와 이름이 다르면 음성 제어 사용자가 보이는 글자로 부르지 못합니다.
- 아이콘만 있는 버튼은 `aria-label`이나 숨은 텍스트가 필요합니다. 아이콘 이미지에는 `alt`를 줍니다. 장식용이면 `alt=""`로 비웁니다.
- 설명(description)은 `aria-describedby`로 연결합니다. 이름은 짧게, 부가 설명은 설명으로 둡니다.
- 슬롯에 들어간 텍스트도 내용으로 계산됩니다. 호스트에 `role="button"`을 주면 슬롯의 텍스트가 이름이 됩니다.

**흔한 실수:** 이름을 `title`에만 두는 것입니다. 모바일과 키보드 사용자는 툴팁을 볼 수 없고, 다른 출처가 있을 때 뒤로 밀립니다.

### Shadow 경계를 넘는 ID 참조 문제

`aria-labelledby`, `aria-describedby`, `aria-controls`, `label`의 `for` 같은 ID 참조는 같은 트리 안에서만 요소를 찾습니다. Shadow 경계를 넘지 못합니다.

```html
<label for="field">이메일</label>
<my-input id="field"></my-input>
<!-- my-input의 shadow 안 input에는 label이 연결되지 않는다 -->
```

| 참조하는 쪽 | 참조되는 쪽 | 동작 |
|-------------|-------------|------|
| 라이트 DOM | 라이트 DOM | 정상 |
| shadow 안 | 같은 shadow 안 | 정상 |
| 라이트 DOM | shadow 안 | 연결되지 않음 |
| shadow 안 | 라이트 DOM(호스트 바깥) | 연결되지 않음 |

우회 방법은 다음과 같습니다.

- 레이블과 컨트롤을 같은 트리에 둡니다. 컴포넌트가 레이블 텍스트를 슬롯이나 어트리뷰트로 받아 shadow 안에서 `label`과 `input`을 함께 그립니다.
- 호스트의 `aria-label` 값을 읽어 내부 요소에 복사합니다. 다만 값이 바뀔 때 동기화 코드가 필요합니다.
- 폼 연관 요소는 `internals.labels`로 바깥 `label`을 읽을 수 있습니다(26편).
- 요소 참조 프로퍼티를 씁니다(아래 절).

#### referenceTarget

`referenceTarget`은 이 문제를 해결하려고 WICG가 제안한 기능입니다. shadow 루트가 내부의 한 요소를 외부 참조의 대상으로 지정하면, 호스트를 ID로 가리킨 참조가 그 내부 요소로 이어집니다.

```js
host.attachShadow({
  mode: 'open',
  referenceTarget: 'inner', // shadow 안 요소의 id
})
// 선언형: template의 shadowrootreferencetarget
// 읽기: host.shadowRoot.referenceTarget
```

- 미Baseline입니다. web-features 3.40.1 기준으로 Chrome·Edge 152만 지원하고 Firefox와 Safari는 지원 데이터가 없습니다. 점진적 향상으로만 쓰고 위의 우회 방법을 함께 둡니다.
- 외부에서는 `label for="field"`로 호스트를 가리키기만 하면 되고 shadow 내부 구조는 노출되지 않는다는 점이 목적입니다.

### ARIA 요소 참조 반영

ID 대신 요소 객체로 관계를 지정하는 프로퍼티가 있습니다. `ariaLabelledByElements`, `ariaDescribedByElements`, `ariaControlsElements` 등입니다. `ariaLabelledByElements`는 Baseline 2025(Chrome·Edge 135, Firefox 136, Safari 16.4)입니다.

```js
input.ariaLabelledByElements = [title, hint]
input.ariaLabelledByElements // [title, hint]
```

| 항목 | `aria-labelledby` | `ariaLabelledByElements` |
|------|-------------------|--------------------------|
| 지정 방식 | 공백으로 구분한 ID 문자열 | 요소의 배열 |
| ID 필요 | 필요 | 불필요 |
| 대상 위치 | 같은 트리 | 같은 범위 또는 조상 범위 |

- 대상은 참조하는 요소와 같은 트리이거나 그 조상 트리에 있어야 합니다. shadow 안의 요소가 호스트가 속한 라이트 DOM의 요소를 가리킬 수 있지만, 라이트 DOM의 요소가 shadow 안의 요소를 가리킬 수는 없습니다.
- 읽으면 정적인 읽기 전용 배열이 반환되고, 값을 쓸 때는 배열이 복사됩니다. 원본 배열을 나중에 바꿔도 반영되지 않습니다.
- MDN은 이 프로퍼티가 다른 레이블 지정 방법보다 우선한다고 설명합니다. 읽을 때는 `aria-labelledby` 어트리뷰트를 반영하되 범위 안의 유효한 요소만 돌려줍니다.
- 사용 전에 기능을 확인합니다: `'ariaLabelledByElements' in Element.prototype`.

## ElementInternals와 접근성

`ElementInternals`는 호스트 요소의 기본(default) 접근성 의미를 정합니다. 호스트에 어트리뷰트를 직접 쓰지 않고 내부에서 설정하므로, 컴포넌트 사용자가 마크업에 쓴 값과 충돌하지 않습니다. `internals.role`과 `internals.aria*` 프로퍼티(예: `ariaChecked`, `ariaLabel`)를 씁니다. 모두 Baseline 2023입니다.

```js
class MyCheckbox extends HTMLElement {
  #internals = this.attachInternals()
  constructor() {
    super()
    this.#internals.role = 'checkbox'
    this.#internals.ariaChecked = 'false'
  }
  set checked(v) {
    this.#internals.ariaChecked = String(!!v)
  }
}
```

- 이 값은 어트리뷰트가 아니라 요소의 내부 속성 맵에 들어갑니다. DOM에서 보이지 않고 `getAttribute`로 읽히지 않으며, CSS 어트리뷰트 선택자(`[role]`)에도 걸리지 않습니다.
- `attachInternals()`는 폼 연관 여부와 관계없이 쓸 수 있고, 한 요소에 한 번만 호출할 수 있습니다(자세히는 26편).
- 상태가 바뀔 때마다 `ariaChecked` 같은 값을 갱신하는 일은 구현자의 몫입니다.

### 기본 ARIA와 호스트 속성의 덮어쓰기

`internals`로 설정한 값은 기본값일 뿐입니다. 호스트에 같은 의미의 `role`·`aria-*` 어트리뷰트가 있으면 어트리뷰트가 이깁니다. 네이티브 요소의 기본 의미를 페이지 작성자가 덮을 수 있는 것과 같은 규칙입니다.

```html
<!-- internals는 role=checkbox, 어트리뷰트가 button으로 덮어씀 -->
<my-checkbox role="button"></my-checkbox>
```

- 사용자가 `aria-label`을 호스트에 쓰면 컴포넌트가 `internals.ariaLabel`로 정한 기본 이름보다 우선합니다. 이름은 사용자가 정하게 두는 것이 자연스러우므로 컴포넌트는 이름의 기본값을 정하지 않거나 보조로만 둡니다.
- 표준은 컴포넌트 작성자가 덮어쓰지 말아야 할 의미(강한 네이티브 의미)를 문서에 밝히라고 권합니다. 체크박스의 `role`과 `aria-checked`가 그 예입니다. 호스트에서 이를 바꾸면 의도와 다른 결과가 됩니다.
- 상태에 맞는 값은 컴포넌트가 계속 갱신하고, 사용자가 덮어쓰도록 열어 둘 값(이름, 설명)과 구분해 문서화합니다.
- 시각 상태를 CSS에 알리는 커스텀 상태(`internals.states`, `:state()`)는 접근성 의미와 별개입니다(20편).

## aria-live

라이브 영역(live region)은 내용이 바뀌면 보조 기술이 포커스 이동 없이 그 변경을 알려 주는 영역입니다. `aria-live`로 지정합니다.

| 값 | 동작 |
|----|------|
| `off`(기본) | 변경을 알리지 않음 |
| `polite` | 현재 읽는 것이 끝난 뒤 알림 |
| `assertive` | 즉시 알림. 읽던 것을 끊을 수 있다 |

```html
<div id="status" aria-live="polite"></div>
```

```js
status.textContent = '3개 항목이 저장되었습니다.'
// 낭독기가 변경을 읽는다
```

- 라이브 영역은 내용이 바뀌기 전에 DOM에 이미 있어야 합니다. 영역을 내용과 함께 새로 추가하면 알려지지 않을 수 있습니다. 빈 영역을 미리 두고 내용만 바꿉니다.
- `role="status"`는 `aria-live="polite"`, `role="alert"`는 `aria-live="assertive"`를 내포합니다.
- 보조 속성은 `aria-atomic`(영역 전체를 다시 읽을지, 바뀐 부분만 읽을지), `aria-relevant`(추가·삭제·텍스트 변경 중 알릴 변경), `aria-busy`(갱신 중에는 알림을 미룸)입니다.
- `assertive`는 사용자의 작업을 끊으므로 시간 제한 경고 같은 급한 알림에만 씁니다. 저장 완료, 검색 결과 수는 `polite`입니다.
- 같은 문자열로 다시 바꾸면 변경이 없어 읽히지 않을 수 있습니다. 내용이 달라져야 알림이 됩니다.
- 컴포넌트가 상태 메시지를 낼 때는 컴포넌트 내부에 라이브 영역을 하나 두고 텍스트만 바꾸는 구조가 안정적입니다.

### ariaNotify()

`element.ariaNotify(text, options)`는 DOM을 바꾸지 않고 낭독기에 텍스트를 읽도록 대기열에 넣습니다(Baseline 2026: Chrome·Edge 141, Firefox 150, Safari 27). 라이브 영역의 대안입니다.

```js
button.ariaNotify('저장되었습니다.')
button.ariaNotify('연결이 끊어졌습니다.', {
  priority: 'high',
})
```

| `priority` | 동작 |
|------------|------|
| `normal`(기본) | 현재 읽는 것 뒤에 읽음. `aria-live="polite"`와 비슷 |
| `high` | 즉시 읽음. `aria-live="assertive"`와 비슷 |

- 요소를 영역으로 만들 필요가 없고 알리고 싶은 시점에 호출하면 됩니다. 알림용 요소를 DOM에 미리 두지 않아도 됩니다.
- 언어는 요소의 `lang`, 없으면 가장 가까운 조상의 언어를 따릅니다.
- `html`, `body`처럼 접근성 트리에서 무시되는 요소에서는 동작하지 않습니다.
- 라이브 영역의 알림이 `ariaNotify()`보다 앞서 처리됩니다. 알림이 여러 개면 하나로 합쳐서 호출하는 편이 안정적입니다.
- 새 API라서 이전 브라우저에는 없습니다. `'ariaNotify' in Element.prototype`로 확인하고, 없으면 라이브 영역으로 대체합니다.

## prefers-reduced-motion

`prefers-reduced-motion`은 사용자가 운영체제에서 모션 줄이기를 켰는지 알려 주는 미디어 기능입니다(Baseline 2020, 널리 지원). 값은 `no-preference`와 `reduce`입니다. 화면 움직임이 어지럼증을 일으키는 사용자(전정 장애)를 위한 설정입니다.

```css
.panel { transition: transform 300ms; }

@media (prefers-reduced-motion: reduce) {
  .panel { transition: none; }
}
```

- `reduce`일 때 움직임을 없애거나 약하게 바꿉니다. 큰 이동, 확대·축소, 회전, 시차 스크롤, 자동 재생 애니메이션이 대상입니다. 위치 이동을 페이드(투명도 변화)로 바꾸는 방식이 흔합니다.
- 상태 변화 자체는 그대로 전달해야 합니다. 애니메이션을 끄더라도 요소는 열리고 닫혀야 합니다.
- 자바스크립트로 움직이는 애니메이션은 CSS 미디어 쿼리가 막아 주지 않으므로 값을 직접 읽습니다.

```js
const mq = matchMedia('(prefers-reduced-motion: reduce)')
const reduce = mq.matches
mq.addEventListener('change', (e) => { /* e.matches */ })
```

- 컴포넌트의 shadow 안 스타일시트에서도 같은 미디어 쿼리를 쓸 수 있습니다. 스타일이 컴포넌트마다 흩어지지 않게 전역 정책으로 두는 것이 좋습니다(애니메이션 API는 46편).
- 설정은 실행 중에도 바뀔 수 있으므로 `change` 이벤트로 반영합니다.

## 핵심 정리

- 보조 기술은 DOM이 아니라 접근성 트리를 읽고, 커스텀 요소는 기본적으로 역할·이름·상태가 없어서 구현자가 채워야 합니다.
- 네이티브 요소를 먼저 쓰고, ARIA는 역할·상태·관계만 바꿀 뿐 동작과 키보드는 만들어 주지 않으므로 상태를 직접 갱신해야 합니다.
- 이름은 `aria-labelledby`, `aria-label`, 네이티브 레이블, 내용, `title` 순으로 정해지고, ID 참조는 Shadow 경계를 넘지 못해 같은 트리에 두거나 요소 참조 프로퍼티를 씁니다.
- `ElementInternals`의 `role`·`aria*`는 호스트의 기본 의미이며 호스트 어트리뷰트가 덮어씁니다.
- 변경을 알릴 때는 미리 있는 `aria-live` 영역을 쓰거나 새 API인 `ariaNotify()`를 지원 여부 확인 후 씁니다.
- `prefers-reduced-motion: reduce`에서는 움직임을 줄이되 상태 변화는 그대로 전달합니다.
