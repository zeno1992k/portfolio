## :host

`:host`는 shadow tree 안의 스타일시트에서 그 shadow tree의 host 요소를 선택하는 의사 클래스입니다. shadow root 밖(문서의 스타일시트 등)에서 쓰면 아무것도 선택하지 못합니다. Baseline 2020, 널리 지원됩니다.

```css
/* 컴포넌트의 shadow tree 안 스타일시트 */
:host {
  display: block;
  border: 1px solid #ccc;
}
:host([hidden]) { display: none }
```

- 사용자 정의 요소의 기본 `display`는 `inline`입니다. `:host { display: block }`처럼 컴포넌트가 기본값을 직접 정합니다.
- `:host`에 `display`를 지정하면 UA 스타일시트의 `[hidden] { display: none }`을 덮어씁니다. 작성자 선언이 UA 선언보다 우선하기 때문입니다. `:host([hidden]) { display: none }`을 함께 씁니다.
- shadow tree 안에서 host는 featureless입니다. 클래스·ID·태그 선택자(`.foo:host`, `x-card`)로는 선택되지 않고 `:host`, `:host()`, `:host-context()`로만 선택됩니다. 바깥 마크업의 클래스 이름이 컴포넌트 내부 스타일에 우연히 걸리는 것을 막는 규칙입니다.
- `:host`의 명시도는 의사 클래스 하나(0-1-0)입니다.
- host는 문서 쪽 요소이므로 바깥 스타일도 받습니다. 둘이 충돌할 때의 규칙은 아래 "외부 스타일과 :host 규칙의 cascade 우선순위"에서 다룹니다.

## :host()

`:host(선택자)`는 host가 괄호 안의 선택자와 일치할 때만 선택합니다. 속성이나 클래스로 바뀌는 변형 스타일에 씁니다.

```css
:host([variant="primary"]) { --_bg: royalblue }
:host(.compact) { padding: 4px }
:host(:hover) { background: #f4f4f4 }
:host(:focus-within) { outline: 2px solid }
:host(:not([disabled])) { cursor: pointer }
```

- 인수는 복합 선택자(compound selector) 하나입니다. `:host(.a .b)`처럼 결합자가 있는 선택자는 쓸 수 없습니다.
- 명시도는 의사 클래스에 인수의 명시도를 더합니다. `:host(.compact)`는 0-2-0이므로 같은 스타일시트의 `:host`보다 우선합니다. 인수의 명시도만 취하는 `:is()`·`:not()`과 다릅니다.
- 상태를 속성으로 반영하는 방법은 19편, `:state()`로 노출하는 방법은 20편에서 다룹니다.
- 인수는 host가 문서에서 가지는 속성·클래스·상태를 기준으로 판정합니다. host의 조상 조건은 인수로 쓸 수 없고 `:host-context()`가 따로 있습니다(아래).

## 외부 스타일과 :host 규칙의 cascade 우선순위

같은 요소에 대해 바깥 문서의 선언과 shadow tree 안의 선언이 충돌하면, 출처(origin)와 중요도 다음에 **컨텍스트**(어느 트리의 스타일시트인가)로 승부합니다. 명시도와 소스 순서는 그 뒤입니다.

| 선언 종류 | 우선하는 쪽 |
|-----------|--------------|
| 일반 선언 | 바깥(문서) 컨텍스트 |
| `!important` 선언 | 안쪽(shadow tree) 컨텍스트 |

```css
/* 문서 */
x-card { display: inline-block; color: red }
```

```css
/* x-card 의 shadow tree */
:host { display: block !important; color: blue }
/* 결과: display 는 block, color 는 red */
```

- 컨텍스트 비교는 명시도보다 먼저 이뤄집니다. 바깥의 `x-card { }`(0-0-1)가 안쪽 `:host`(0-1-0)보다 명시도가 낮아도 일반 선언에서는 바깥이 이깁니다. 소스 순서와 `@layer` 순서도 컨텍스트 사이에서는 비교되지 않습니다.
- 그래서 `:host` 규칙은 "컴포넌트의 기본값"이고 문서가 덮어쓰기 쉽습니다. 사용자가 덮어쓰면 안 되는 값만 `!important`로 고정합니다.
- 같은 규칙이 `::slotted()`와 `::part()`에도 적용됩니다. 슬롯된 요소는 문서의 스타일을, part는 문서의 `::part()` 규칙을 일반 선언에서 우선 받습니다.
- host의 `style` 속성과 문서의 규칙도 바깥 컨텍스트입니다.
- 이 규칙은 CSS Cascade 명세가 정한 것입니다. 판정 기준은 명시도가 아니라 컨텍스트입니다.

**흔한 실수:** 컴포넌트의 `:host { color: blue }`를 문서가 `x-card { color: red }`로 덮어쓰지 못한다고 생각하는 것입니다. 반대로 문서가 이깁니다. 컴포넌트가 선언을 보호하려면 `!important`가 필요하고, 그만큼 사용자의 커스터마이징을 막게 됩니다.

## ::slotted()

`::slotted(선택자)`는 shadow tree의 슬롯에 배정된 요소를 선택하는 의사 요소입니다. 슬롯 요소에 붙여서 씁니다. Baseline 2020, 널리 지원됩니다.

```css
::slotted(*) { margin: 0 }
::slotted(h2) { font-size: 1.25rem }
slot[name="actions"]::slotted(button) { margin-left: 8px }
slot[name="title"] { color: #333 }
```

- 인수는 복합 선택자 하나입니다. `::slotted(p span)`은 쓸 수 없습니다.
- 슬롯에 직접 배정된 요소만 선택합니다. 그 요소의 자손은 선택하지 못합니다. 자손은 문서의 스타일시트로 다루는 요소입니다.
- 중첩 슬롯으로 전달된 요소도 최종 배정(flatten) 기준으로 최종 슬롯의 `::slotted()`에 선택됩니다(슬롯 전달은 22편).
- 텍스트 노드는 선택하지 못합니다. 슬롯 요소에 스타일을 주면 슬롯된 노드가 flat tree에서 슬롯의 자식이므로 상속되는 속성(`color`, `font` 등)이 텍스트에 전달됩니다.
- `::slotted(p)::before`처럼 뒤에 `::before`·`::after`를 붙일 수 있습니다.
- 명시도는 의사 요소에 인수의 명시도를 더합니다.
- 슬롯된 요소는 문서의 규칙도 받습니다. 일반 선언에서는 문서가 이기므로(위 우선순위) `::slotted()`는 기본값을 정하는 용도입니다.
- 슬롯된 요소의 `display`, `margin`, `flex` 같은 박스 속성은 `::slotted()`로 정할 수 있습니다. 슬롯 자체는 `display: contents`라서 박스가 없으므로 슬롯 요소에 `padding`이나 `border`를 주려면 `display`를 지정하거나 감싸는 요소를 둡니다.
- 배정된 노드가 없을 때 슬롯 상태로 스타일을 바꾸는 `:has-slotted`는 22편에서 다룹니다.

## ::part

`::part(이름)`은 shadow tree 안에서 `part` 속성으로 이름을 붙인 요소를 바깥에서 선택하는 의사 요소입니다. 컴포넌트가 스타일링을 허용한 지점을 명시하는 통로입니다. Baseline 2020, 널리 지원됩니다.

```html
<!-- x-tabs 의 shadow tree -->
<div part="tab">A</div>
<div part="tab active">B</div>
```

```css
/* 문서 */
x-tabs::part(tab) { padding: 8px }
x-tabs::part(tab active) { border-bottom: 2px solid }
x-tabs::part(tab):hover { background: #eee }
x-tabs::part(tab)::after { content: "" }
```

- 선택의 출발점은 shadow host여야 합니다. `x-tabs::part(tab)`처럼 host를 앞에 씁니다.
- part 이름은 클래스처럼 쓰입니다. 한 요소에 여러 이름을 줄 수 있고 여러 요소가 같은 이름을 쓸 수 있으며, `::part(tab active)`는 두 이름을 모두 가진 요소만 선택합니다. 이름 순서는 무관합니다.
- 이 통로는 shadow root의 `mode`와 관계없이 동작합니다. 선택은 CSS 안에서만 처리되고 DOM으로는 노출되지 않습니다.
- 안쪽 요소와 문서의 규칙이 충돌하면 위의 컨텍스트 규칙에 따라 일반 선언은 문서의 `::part()`가 이깁니다.
- `::part()`로 선택된 요소는 원래의 shadow tree 위치를 기준으로 상속받습니다.
- 슬롯된 요소는 Light DOM이므로 part가 아니라 일반 선택자로 다룹니다.

선택에는 제한이 있습니다.

| 가능 | 불가능 |
|------|--------|
| `::part(a)`, `::part(a b)` | `::part(a):first-child` 같은 구조 의사 클래스 |
| `::part(a):hover`, `::part(a):focus` 같은 사용자 동작 의사 클래스 | `::part(a) span` 같은 자손 선택(part 안쪽 구조를 노출하지 않음) |
| `::part(a)::before`, `::after` 같은 의사 요소 | `::part(a)::part(b)` 연쇄 |
| host가 직접 소유한 shadow tree의 part | 안쪽 컴포넌트의 part(`exportparts`로 내보내지 않으면) |

- 구조 의사 클래스와 자손 선택을 막는 이유는 컴포넌트의 내부 구조를 바깥에 노출하지 않기 위해서입니다. 필요한 상태는 part 이름(`tab active`)이나 `:state()`로 노출합니다.
- 외부에서 `::part()`로 바꿀 수 있는 요소의 목록과 이름은 컴포넌트의 공개 API입니다(자세히는 75편).

## part와 exportparts

`part` 속성은 요소를 공개 표면으로 만들고, `exportparts` 속성은 중첩된 shadow tree의 part를 바깥으로 전달합니다. 둘 다 Baseline 2020입니다.

- `part`: 공백으로 구분한 이름 목록입니다. 속성이 붙은 요소 하나만 노출되고 자손은 노출되지 않습니다.
- 한 번의 `::part()`는 한 개의 shadow tree만 통과합니다. 문서에서 `x-field`의 `::part()`로는 `x-field`의 shadow tree 안 요소까지만 선택하고, 그 안의 `x-input`이 가진 shadow tree 내부는 선택하지 못합니다.
- 중간 컴포넌트가 `exportparts`로 안쪽 part를 자기 이름으로 내보내면 바깥에서 선택할 수 있습니다.

```html
<!-- x-field 의 shadow tree -->
<x-input exportparts="control, label:field-label"></x-input>
```

```css
/* 문서 */
x-field::part(control) { border-radius: 4px }
x-field::part(field-label) { font-weight: 600 }
```

- `exportparts`는 쉼표로 구분한 목록이고, 항목은 `이름`이거나 `안쪽이름:바깥이름`입니다. 이름만 쓰면 같은 이름으로 내보냅니다.
- 내보내진 이름은 `x-field`의 part처럼 선택됩니다. 같은 안쪽 part를 여러 이름으로 내보낼 수도 있습니다.
- 내보내지 않은 안쪽 part는 바깥에서 선택되지 않습니다. 이것이 중첩 컴포넌트를 조합하는 컴포넌트가 의도적으로 열어 둔 표면만 보이게 하는 방법입니다.
- 이름 충돌을 피하려면 내보낼 때 컴포넌트 접두사를 붙입니다(`card__header`).

### Element.part

`Element.part`는 `part` 속성을 `DOMTokenList`로 다루는 프로퍼티입니다. `classList`와 같은 방법으로 part 이름을 추가·제거합니다.

```js
const tab = root.querySelector('.tab')
tab.part.add('active')          // part="tab active"
tab.part.toggle('selected', on) // 조건에 따라 추가/제거
tab.part.contains('active')     // true
tab.part.value = 'tab'          // 속성 문자열을 통째로 교체
```

- 상태를 외부에 스타일 가능하게 보여 줄 때 씁니다. `active`, `selected`, `disabled`처럼 상태를 part 이름으로 붙입니다.
- 값이 바뀌면 `::part(tab active)` 규칙의 일치 여부가 즉시 달라집니다.
- 내보낸 이름은 `exportparts`가 정하므로, 안쪽 컴포넌트가 part 이름을 추가해도 중간 컴포넌트가 내보내지 않으면 바깥에서 볼 수 없습니다.

## CSS Custom Properties

CSS 커스텀 속성(`--name`)은 사용자가 이름을 붙이는 속성으로, `var(--name, 대체값)`으로 읽습니다. 기본적으로 상속되므로 shadow 경계를 통과합니다. 컴포넌트에 값을 넘기는 가장 단순한 스타일 통로입니다.

```css
/* 문서: host 또는 조상 어디서든 정의 */
x-card { --x-card-bg: #fffbe6 }
```

```css
/* x-card 의 shadow tree */
.card { background: var(--x-card-bg, #fff) }
```

- host에서 shadow tree 안 요소로 상속되어 읽힙니다. 선택자와 달리 경계를 넘지 못하는 문제가 없습니다.
- `var()`의 두 번째 인수가 기본값입니다. 컴포넌트가 `:host { --x-card-bg: #fff }`처럼 자기 host에 기본값을 선언하면 조상에서 상속된 값이 가려집니다. host 자체의 선언이 상속값보다 우선하기 때문입니다. 기본값은 `var(--x-card-bg, #fff)`의 대체값으로 둡니다.
- 모든 값이 문자열 취급이며 타입 검증이 없습니다. 타입과 상속 여부를 정하려면 `@property`로 등록합니다(자세히는 74편).
- 컴포넌트가 읽는 커스텀 속성의 이름과 용도는 공개 API로 문서화합니다(자세히는 19편).
- 호출하는 쪽은 `x-card { --x-card-bg: ... }`로 개별 인스턴스에, `:root`나 조상 클래스로 전체에 값을 줄 수 있습니다.

## 디자인 토큰

디자인 토큰은 색, 간격, 글꼴처럼 디자인 결정을 이름 붙은 값으로 정리한 것입니다. 웹 컴포넌트에서는 커스텀 속성이 토큰의 전달 수단입니다.

| 계층 | 예 | 역할 |
|------|----|------|
| primitive | `--blue-500: #2a5cff` | 원시 값 |
| semantic | `--color-primary: var(--blue-500)` | 용도를 나타내는 의미 이름 |
| component | `--x-button-bg: var(--color-primary)` | 컴포넌트가 읽는 이름 |

```css
/* 전역(테마) */
:root { --color-primary: #2a5cff }
/* 컴포넌트의 shadow tree */
button {
  background: var(--x-button-bg, var(--color-primary));
}
```

- 컴포넌트는 자기 이름의 토큰(`--x-button-bg`)을 먼저 읽고, 없으면 전역 의미 토큰으로, 마지막에는 고정값으로 내려가는 체인을 둡니다. 개별 컴포넌트만 바꾸는 것과 테마 전체를 바꾸는 것이 모두 가능합니다.
- 토큰 이름 규칙, 계층 설계, `@property` 등록은 74편에서 자세히 다룹니다.

## Shadow DOM 테마 주입

테마 주입은 컴포넌트를 수정하지 않고 바깥에서 외형을 바꾸는 것입니다. 통로별 특징은 다음과 같습니다.

| 방법 | 바꿀 수 있는 것 | 비고 |
|------|------------------|------|
| 상속되는 커스텀 속성 | 컴포넌트가 읽도록 열어 둔 값 | 가장 안정적인 계약. 조상 한 곳에서 전체 적용 |
| host 속성(`:host([theme])`) | 컴포넌트가 정의한 변형 | 선택지가 컴포넌트 안에 고정 |
| `::part()` | part로 노출된 요소의 임의 속성 | 표면이 넓을수록 호환성 부담 |
| 스타일시트 주입 | shadow root에 규칙 추가 | `adoptedStyleSheets`로 공유(24편) |
| `:host-context()` | 조상 조건에 따른 변형 | Chromium 전용(아래) |

```css
/* 문서 */
:root { --x-card-bg: #fff; --x-card-fg: #222 }
.dark { --x-card-bg: #1b1b1f; --x-card-fg: #eee }
```

- `.dark` 아래의 모든 컴포넌트가 상속으로 새 값을 받으므로 컴포넌트마다 코드를 바꿀 필요가 없습니다.
- 값은 커스텀 속성, 구조·세부 외형은 `::part()`, 통째로 교체할 때는 스타일시트 주입으로 역할을 나눕니다.
- 다크 모드와 `prefers-color-scheme`, `color-scheme`, `light-dark()`는 24편에서 다룹니다.

### :host-context()

`:host-context(선택자)`는 host나 그 조상 중 하나가 선택자와 일치하면 host를 선택합니다. 경계를 넘어 조상을 검사합니다.

```css
:host-context(.dark) .card { background: #1b1b1f }
```

- Chromium 계열(Chrome 54, Edge 79 이후)에서만 지원되고 Firefox와 Safari는 지원하지 않습니다. 미Baseline입니다.
- MDN은 이 기능을 deprecated로 분류하고 새 코드에서 쓰지 말라고 안내합니다.
- 대체 수단은 host 속성(`:host([theme="dark"])`), 상속되는 커스텀 속성, 컨테이너 스타일 쿼리입니다. 스타일 쿼리는 flat tree의 조상 컨테이너를 질의하므로 shadow 경계 바깥의 값도 읽습니다.

```css
@container style(--theme: dark) {
  .card { background: #1b1b1f }
}
```

- 커스텀 속성에 대한 컨테이너 스타일 쿼리는 Baseline 2026(Firefox 151 이후 핵심 브라우저 전체 지원)입니다.

## 상속과 all: initial

shadow 경계는 선택자와 규칙을 막지만, 상속은 막지 않습니다. host에서 shadow tree 안의 요소로 상속 속성의 값이 흘러갑니다.

| 구분 | 경계를 통과하는가 | 예 |
|------|--------------------|----|
| 상속 속성 | 통과 | `color`, `font-*`, `line-height`, `text-align`, `visibility`, `cursor`, `direction` |
| 커스텀 속성 | 통과(기본 상속) | `--x-card-bg` |
| 비상속 속성 | 통과 안 함 | `background`, `border`, `margin`, `padding`, `display`, `width` |

- 바깥에서 `body { font-family: serif }`를 지정하면 컴포넌트 안의 글자도 serif입니다. 컴포넌트가 자기 글꼴을 쓰려면 `:host`에 지정합니다.
- 슬롯된 노드는 flat tree에서 슬롯의 자식이므로 원래 부모가 아니라 슬롯(그리고 shadow tree의 조상)에서 상속받습니다.

바깥 환경과 무관하게 컴포넌트가 일정한 외형을 가져야 하면 `:host`에서 상속을 끊습니다.

```css
:host {
  all: initial;   /* 모든 속성을 초기값으로 */
  display: block; /* all 뒤에 필요한 값을 다시 지정 */
  font: 16px/1.4 system-ui, sans-serif;
  color: #222;
}
```

- `all: initial`은 host 요소의 모든 속성을 초기값으로 돌립니다. host가 상속받던 값이 끊기고 안쪽 요소는 host의 새 값을 상속받습니다.
- `all`은 `direction`, `unicode-bidi`, 커스텀 속성은 초기화하지 않습니다(MDN). 그래서 테마용 커스텀 속성은 `all: initial` 뒤에도 그대로 통과합니다.
- `all: initial`은 `display`도 `inline`으로 되돌리므로 뒤에 `display`를 다시 지정합니다.
- 일반 선언이므로 문서의 `x-card { color: red }` 같은 규칙이 이깁니다. 외부 영향을 완전히 막는 장치가 아니라 상속을 끊는 장치입니다.

## 핵심 정리

- `:host`와 `:host()`는 shadow tree 안에서 host를 선택하고, host는 그 외 선택자에는 보이지 않습니다. `:host()`의 명시도는 의사 클래스에 인수를 더합니다.
- 바깥과 안쪽 선언이 충돌하면 명시도보다 먼저 컨텍스트로 가려 일반 선언은 바깥이, `!important`는 안쪽이 이깁니다. `:host`, `::slotted()`, `::part()`의 안쪽 규칙은 기본값 역할입니다.
- `::slotted()`는 슬롯에 직접 배정된 요소만 선택하고 텍스트와 자손은 선택하지 못하며, `::part()`는 `part`로 열린 요소만 선택하고 구조 의사 클래스와 자손 선택은 쓸 수 없습니다.
- 중첩 컴포넌트의 part는 `exportparts`로 내보내야 하고, 상태 노출은 `Element.part`로 이름을 바꿔서 합니다.
- 커스텀 속성은 상속으로 경계를 통과하는 안정적인 스타일 계약이며, 기본값은 `var()`의 대체값에 두어야 조상의 값이 가려지지 않습니다.
- `:host-context()`는 Chromium 전용이며 deprecated입니다. 상속 속성은 경계를 넘고, 끊으려면 `:host`에 `all: initial`을 씁니다.
