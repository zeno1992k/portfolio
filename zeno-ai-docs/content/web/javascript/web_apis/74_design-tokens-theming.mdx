## Design Token

디자인 토큰(design token)은 색, 간격, 글꼴 크기처럼 디자인 결정을 이름 붙은 값으로 저장한 것입니다. 소스 코드에 `#2a5cff`를 직접 쓰지 않고 `--color-action-bg`라는 이름으로 참조하면, 값이 바뀔 때 이름을 쓴 모든 곳이 함께 바뀝니다.

웹에서 토큰은 CSS 커스텀 속성(custom property)으로 전달합니다. `--` 로 시작하는 이름을 선언하고 `var()`로 읽습니다. Baseline 2017입니다.

```css
:root { --color-action-bg: #2a5cff }
button { background: var(--color-action-bg) }
```

- 커스텀 속성은 상속되므로 조상에서 선언한 값이 shadow 경계 안의 컴포넌트에도 전달됩니다(자세히는 23편).
- 이름은 대소문자를 구분합니다. `--Color`와 `--color`는 다른 속성입니다.
- `var(--name, 대체값)`의 두 번째 인수는 그 속성이 정의되어 있지 않을 때(순환 참조도 포함) 쓰는 대체값입니다. 쉼표가 들어 있어도 첫 쉼표 뒤 전체가 대체값입니다. 대체값 안에 `var()`를 중첩할 수 있습니다.
- 토큰의 목적은 값의 재사용이 아니라 결정을 한곳에 두는 것입니다. 값이 한 번만 쓰이더라도 의미가 있으면 토큰입니다.
- 토큰의 원본은 코드가 아니라 도구에서 관리하는 데이터일 수 있고, 거기서 CSS, JavaScript, 네이티브 플랫폼용 값을 생성합니다(아래 "디자인 토큰 교환 형식").

## Primitive / Semantic Token

토큰은 값 자체를 담은 primitive와, 용도를 이름으로 나타낸 semantic으로 나눕니다.

| 계층 | 예 | 담는 것 |
|------|----|---------|
| primitive | `--color-blue-500: #2a5cff` | 원시 값. 용도가 없고 스케일 위치만 있음 |
| semantic | `--color-action-bg: var(--color-blue-500)` | 용도. 어떤 primitive를 쓸지 결정 |

```css
:root {
  --color-blue-500: #2a5cff;
  --color-blue-700: #1a3fb8;
  --color-action-bg: var(--color-blue-500);
  --color-action-bg-hover: var(--color-blue-700);
}
```

- 컴포넌트는 semantic 토큰만 읽습니다. primitive를 직접 읽으면 테마나 다크 모드에서 값을 바꿀 때 컴포넌트마다 고쳐야 합니다.
- 테마 전환은 semantic 토큰이 가리키는 primitive를 바꾸는 일입니다. primitive 값은 그대로 두고 연결만 바꿉니다.
- 이름에 값을 넣지 않습니다. `--color-blue-button`처럼 semantic에 색 이름을 넣으면 색이 바뀔 때 이름이 거짓이 됩니다. semantic 이름은 `action`, `danger`, `surface`, `text-muted`처럼 역할을 씁니다.
- semantic은 기존 primitive를 가리키기만 합니다. 새 값이 필요하면 semantic에 직접 적지 않고 primitive를 먼저 추가합니다.

## 컴포넌트 토큰 계층

컴포넌트 토큰은 컴포넌트 하나가 읽는 이름으로, 컴포넌트가 외부에 여는 스타일 훅입니다. 기본값은 semantic 토큰으로 이어 둡니다.

| 계층 | 선언하는 곳 | 읽는 곳 |
|------|-------------|---------|
| primitive | 문서 `:root` | semantic 선언 |
| semantic | 문서 `:root`, 테마 선택자 | 컴포넌트 토큰의 대체값 |
| component | 사용자가 조상이나 요소에 선언 (선택) | 컴포넌트의 shadow tree |

```css
/* x-button 의 shadow tree */
button {
  background: var(--x-button-bg, var(--color-action-bg));
  color: var(--x-button-fg, var(--color-action-fg));
}
```

- 읽는 순서는 컴포넌트 토큰, semantic 토큰, 고정 기본값입니다. 한 컴포넌트만 바꾸려면 `--x-button-bg`를, 전체 테마를 바꾸려면 semantic을 바꿉니다.
- `:host { --x-button-bg: ... }`로 기본값을 선언하면 조상이 준 값이 가려집니다. host 자신의 선언이 상속값보다 우선하기 때문입니다. 기본값은 `var()`의 대체값 체인으로 둡니다(자세히는 23편).
- shadow 안에서 같은 값을 여러 곳에서 쓸 때는 내부용 별칭을 한 번 만들고 `--_bg` 같은 접두사로 비공개임을 표시합니다.

```css
.btn {
  --_bg: var(--x-button-bg, var(--color-action-bg));
  background: var(--_bg);
  border-color: var(--_bg);
}
```

- 별칭은 관례일 뿐 브라우저가 비공개를 강제하지는 않습니다. 사용자가 읽거나 덮어쓸 수 있는 이름은 문서에 있는 것만 공개로 보장합니다.
- 컴포넌트 토큰은 필요한 곳에만 둡니다. 모든 속성에 만들면 공개 API 범위가 커지고 변경 비용이 늘어납니다(자세히는 73편).

## 토큰 이름 규칙

이름은 역할이 드러나고 알파벳 순으로 정렬해도 묶이도록 일반에서 구체로 씁니다.

```text
--{접두사}-{카테고리}-{요소·역할}-{변형}-{상태}
--color-action-bg-hover
--space-4
--font-size-lg
--x-button-radius
```

| 규칙 | 이유 |
|------|------|
| 소문자와 하이픈만 사용 | 대소문자를 구분하므로 철자 실수를 막음 |
| 카테고리를 앞에 (`color`, `space`, `font`, `radius`, `shadow`) | 같은 종류가 이름순으로 모이고 자동완성이 쉬움 |
| 상태(`hover`, `disabled`)는 맨 뒤 | 같은 요소의 상태 토큰이 이어짐 |
| 컴포넌트 토큰은 컴포넌트 접두사 (`--x-button-`) | 다른 컴포넌트와 이름 충돌 방지 |
| 값이 아니라 역할을 이름에 (`danger`, `surface`) | 값이 바뀌어도 이름이 유효 |
| 스케일은 숫자 단계 (`100`–`900`, `1`–`8`) | 중간 단계를 끼워 넣을 여지를 둠 |

- 접두사 없는 전역 토큰(`--color-`)은 다른 시스템과 한 페이지에서 만나면 충돌합니다. 조직이나 시스템 이름 접두사(`--acme-color-`)를 붙이면 피할 수 있습니다.
- 한 번 공개한 토큰 이름의 변경은 breaking 변경입니다. 이름을 바꿀 때는 옛 이름을 새 이름의 별칭으로 남기고 폐기 예고를 거칩니다(자세히는 73편).

```css
:root {
  --color-primary: var(--color-action-bg); /* 폐기 예정 별칭 */
}
```

## CSS Custom Properties 계약

컴포넌트가 읽는 커스텀 속성은 사용자와의 계약입니다. 이름, 기대하는 값의 종류, 기본값, 상속 여부를 문서에 적고, 계약을 바꿀 때는 호환 규칙을 따릅니다.

| 항목 | 정할 것 | 예 |
|------|---------|----|
| 이름 | 접두사와 규칙에 맞는 공개 이름 | `--x-card-bg` |
| 값의 종류 | 색, 길이, 숫자 등 | `<color>` |
| 기본값 | 대체값 체인의 끝 | `var(--color-surface)` |
| 설정 위치 | 조상, 요소 인라인, 둘 다 | 어디서든 |
| 변경 규칙 | 이름·종류 변경은 MAJOR | 73편 |

- 계약에 없는 값은 읽지 않습니다. `--x-card-pad`를 문서에 적지 않았다면 사용자가 정의해도 효과가 없어야 합니다.
- 커스텀 속성은 등록하지 않으면 모든 값을 받으므로 `--x-card-bg: 12px` 같은 잘못된 값도 선언 단계에서는 오류가 없습니다. 이 값을 `background`가 읽는 시점에 유효하지 않으면(invalid at computed-value time) 그 속성은 `unset`처럼 처리되어 상속되는 속성이면 상속값, 아니면 초깃값이 됩니다. 이때 `var()`의 대체값은 쓰이지 않습니다. 대체값은 속성이 정의되지 않았을 때만 쓰입니다.
- `var()`는 미디어 쿼리나 컨테이너 쿼리의 조건 안에서 쓸 수 없습니다. 중단점 값은 토큰이 아니라 별도 상수로 관리합니다.
- JavaScript에서는 `el.style.setProperty('--x-card-bg', 'red')`로 쓰고 `getComputedStyle(el).getPropertyValue('--x-card-bg')`로 읽습니다.
- 계약은 JSDoc의 `@cssprop` 태그로 적어 Custom Elements Manifest에 담을 수 있습니다(자세히는 75편).
- 상속되는 토큰은 중첩에 주의합니다. 바깥 컴포넌트에 준 `--x-card-bg`가 안쪽의 같은 컴포넌트에도 상속됩니다. 이런 누수는 `@property`의 `inherits: false`로 막을 수 있습니다(아래).

## @property로 토큰 타입 지정

`@property`는 커스텀 속성의 값 종류(`syntax`), 상속 여부(`inherits`), 초깃값(`initial-value`)을 등록하는 규칙입니다. 등록한 속성은 값을 타입으로 검증하고 전환·애니메이션도 할 수 있습니다. Baseline 2024입니다.

```css
@property --acme-gap {
  syntax: '<length>';
  inherits: true;
  initial-value: 8px;
}
```

- `syntax`와 `inherits`는 필수입니다. 둘 중 하나라도 없으면 규칙 전체가 무시됩니다.
- `initial-value`는 `syntax`가 `*`가 아니면 필수이며, 다른 값에 의존하지 않아야 합니다. `10px`은 되지만 `3em`은 부모의 글꼴 크기에 의존해서 규칙이 무효입니다.
- `syntax`에는 `<color>`, `<length>`, `<number>`, `<percentage>` 같은 형식 이름, 여러 형식을 고르는 `|`, 공백 목록 `+`, 쉼표 목록 `#`를 쓸 수 있고 `*`는 모든 값을 받습니다.
- 등록된 속성에 형식에 맞지 않는 값을 선언하면 그 선언은 무효가 되어 적용되지 않습니다. 다른 선언이 없으면 상속값이나 `initial-value`가 쓰이므로 결과를 예측할 수 있습니다.
- 등록하지 않은 커스텀 속성은 값이 토큰 열이라 보간할 수 없어서 `transition`이 즉시 바뀝니다. 등록하면 형식을 알기 때문에 부드럽게 전환됩니다.

```css
@property --x-bar-pct {
  syntax: '<percentage>';
  inherits: false;
  initial-value: 0%;
}
.bar { transition: --x-bar-pct 0.3s }
```

- `inherits: false`로 등록하면 자식에게 값이 전해지지 않아 중첩 컴포넌트로의 누수를 막습니다.
- 등록은 `@property` 규칙이나 `CSS.registerProperty()` 중 하나로 합니다. 같은 이름의 규칙이 여럿이면 마지막 규칙이 적용되고 `CSS.registerProperty()`가 `@property`보다 우선합니다.
- 속성 등록은 shadow tree 범위가 아니라 문서 전체에서 하나의 맵을 공유한다고 CSS Properties and Values 명세가 정의합니다. 컴포넌트 라이브러리가 등록하는 이름에는 접두사를 붙여 다른 코드와 충돌하지 않게 합니다.

## Typography / Spacing / Color 시스템

세 가지는 토큰 대부분을 차지하는 기본 축입니다. 각각 한정된 단계의 스케일을 정하고 컴포넌트는 그 단계만 씁니다.

### Color

색은 primitive 스케일(예: 50부터 900까지)과 semantic 역할 두 층으로 나눕니다.

| semantic 역할 | 예 |
|---------------|----|
| 표면 | `--color-surface`, `--color-surface-raised` |
| 텍스트 | `--color-text`, `--color-text-muted` |
| 경계 | `--color-border` |
| 동작 | `--color-action-bg`, `--color-action-fg` |
| 상태 | `--color-danger`, `--color-success` |

- 대비 기준은 텍스트가 일반 크기면 4.5:1, 큰 텍스트(18pt 이상, 굵으면 14pt 이상)면 3:1입니다(WCAG 1.4.3, AA). 컨트롤 경계, 포커스 표시, 상태를 나타내는 아이콘은 인접 색과 3:1입니다(WCAG 1.4.11). 조합마다 대비를 확인할 수 있게 `*-bg`와 `*-fg`를 짝으로 정의합니다.
- 상태 색(hover, active)은 새 값을 만들기보다 기준색에서 파생합니다. `color-mix()`는 두 색을 지정한 색 공간에서 섞습니다(Baseline 2023, 기본 색 공간은 `oklab`).

```css
:root {
  --color-action-bg-hover:
    color-mix(in oklab, var(--color-action-bg) 85%, black);
}
```

### Spacing

간격은 일정한 기준 단위의 배수 스케일로 정하고 컴포넌트 안의 모든 여백, 틈, 크기에 씁니다.

```css
:root {
  --space-1: 0.25rem;
  --space-2: 0.5rem;
  --space-3: 0.75rem;
  --space-4: 1rem;
}
```

- `rem`으로 쓰면 사용자가 브라우저의 글꼴 크기를 바꿨을 때 간격도 따라갑니다. 픽셀 고정이면 글자만 커지고 간격은 그대로입니다.
- 터치 대상의 크기는 포인터 입력에서 24 x 24 CSS 픽셀 이상이어야 합니다. 대상 사이 간격이 충분하거나 같은 기능의 큰 컨트롤이 있거나 문장 안의 링크이면 예외입니다(WCAG 2.5.8, AA). 크기 토큰의 최솟값을 이에 맞춥니다.

### Typography

글꼴 관련 토큰은 한 속성 값이 아니라 묶음으로 정합니다.

| 토큰 종류 | 예 |
|-----------|----|
| 글꼴 모음 | `--font-family-sans`, `--font-family-mono` |
| 크기 스케일 | `--font-size-sm`, `--font-size-md`, `--font-size-lg` |
| 굵기 | `--font-weight-regular`, `--font-weight-bold` |
| 줄 높이 | `--line-height-tight`, `--line-height-body` |

- 크기도 `rem`으로 정해 사용자의 글꼴 크기 설정을 따릅니다.
- 화면 폭에 맞춰 부드럽게 변하는 크기는 `clamp(최솟값, 선호값, 최댓값)`으로 한 토큰에 담습니다.

```css
:root {
  --font-size-lg: clamp(1.125rem, 1rem + 0.5vw, 1.375rem);
}
```

- 글꼴 모음 토큰의 끝에는 `sans-serif`나 `monospace` 같은 일반 계열을 둡니다. 웹 폰트가 늦게 도착할 때의 대체 글꼴이 됩니다.
- 글꼴 파일의 로딩과 글꼴 교체로 인한 레이아웃 이동은 76편의 "FOUC / Layout Shift 방지"와 66편에서 다룹니다.

## Theme

테마(theme)는 semantic 토큰 한 벌의 값입니다. 같은 컴포넌트가 테마에 따라 다른 외형을 갖는 것은 컴포넌트가 아니라 semantic 토큰의 값이 바뀌기 때문입니다.

```css
:root, [data-theme='brand-a'] {
  --color-action-bg: var(--color-blue-500);
}
[data-theme='brand-b'] {
  --color-action-bg: var(--color-green-500);
}
```

```js
document.documentElement.dataset.theme = 'brand-b'
```

- 테마를 선택자로 구분하면 한 문서 안에서 영역마다 다른 테마를 적용할 수 있습니다. 조상에 `data-theme`을 두면 그 아래의 컴포넌트가 상속으로 값을 받습니다. shadow 경계도 통과합니다.
- 컴포넌트가 `theme` 속성을 받아 `:host([theme])`로 외형을 고르는 방식은 선택지가 컴포넌트 안에 고정되어 확장이 어렵습니다. 토큰 값으로 테마를 주는 방식이 확장성이 좋습니다(자세히는 24편).
- 테마별 값은 `<link>`나 `adoptedStyleSheets`로 문서에 한 번만 싣습니다. 컴포넌트가 shadow root마다 테마 스타일을 복제하지 않습니다.
- 커스텀 속성을 바꾸면 그 속성을 쓰는 요소의 스타일이 다시 계산됩니다. 문서 루트에서 바꾸면 영향 범위가 넓으므로 필요한 영역의 조상에서 바꿉니다.
- 사용자가 고른 테마는 저장해야 다음 방문에 적용됩니다. `localStorage`에 저장하면 서버가 모르므로 서버 렌더링 HTML은 기본 테마로 나갑니다. 서버가 알아야 하면 쿠키에 저장합니다(자세히는 40편, 76편).

## Dark Mode

다크 모드는 테마의 한 종류로 다룹니다. 별도 컴포넌트 스타일이 아니라 같은 semantic 토큰에 어두운 값을 연결합니다. 시스템 설정을 읽는 `prefers-color-scheme`, 구성표를 선언하는 `color-scheme`, `light-dark()` 함수의 동작은 24편에서 다룹니다.

```css
:root {
  color-scheme: light dark;
  --color-surface: #ffffff;
  --color-text: #1b1b1f;
}
@media (prefers-color-scheme: dark) {
  :root {
    --color-surface: #1b1b1f;
    --color-text: #f2f2f5;
  }
}
```

- 사용자가 앱 안에서 직접 모드를 고를 수 있게 하려면 상태가 세 가지입니다. 시스템 따름, 밝게, 어둡게. 시스템 따름일 때는 미디어 쿼리가, 직접 선택일 때는 `data-theme` 속성이 값을 정합니다.

```css
:root[data-theme='dark'] {
  color-scheme: dark;
  --color-surface: #1b1b1f;
  --color-text: #f2f2f5;
}
```

- 미디어 쿼리 안의 값과 속성 선택자 안의 값이 같은 내용이면 중복입니다. 도구로 한 곳에서 생성하거나, 색에는 `light-dark()`를 써서 중복을 줄입니다. `light-dark()`는 색 값만 받으므로 그림자 같은 색 이외의 토큰은 선택자로 재정의해야 합니다.
- `color-scheme`을 선언하지 않으면 다크 모드에서 폼 컨트롤, 스크롤바, 기본 배경이 밝은 채 남습니다. 문서 루트에 `light dark`를 선언합니다.
- 밝은 값을 단순 반전해서 어두운 값을 만들지 않습니다. 두 모드 모두에서 텍스트와 표면, 경계, 포커스 표시의 대비 기준(4.5:1, 3:1)을 다시 확인합니다.
- 저장된 모드가 있으면 첫 페인트 전에 `data-theme`을 `html`에 지정해야 밝은 화면이 먼저 보이는 깜빡임이 없습니다. `head`의 인라인 스크립트가 이 일을 하며, CSP를 쓰면 nonce나 해시를 붙여야 합니다(자세히는 63편).
- 이미지, 일러스트, 그림자는 색 토큰만으로 바뀌지 않습니다. 이미지 값에는 `light-dark()`가 쓰이는 형태가 있고(Baseline 2026), 아니면 `picture`의 `prefers-color-scheme` 미디어 조건이나 별도 이미지 토큰을 둡니다.

## forced-colors 고대비 대응

강제 색상 모드(forced colors mode)는 사용자가 고른 제한된 팔레트를 브라우저가 페이지에 강제로 적용하는 모드입니다. Windows 고대비 모드가 대표적입니다. `@media (forced-colors: active)`로 감지합니다. Baseline 2022입니다.

- 이 모드에서는 `color`, `background-color`, `border-color`, `outline-color`, `text-decoration-color`와 SVG의 `fill`, `stroke` 같은 색 속성이 페인트 시점에 브라우저가 고른 값으로 바뀝니다. 토큰으로 준 색은 무시됩니다.
- `box-shadow`와 `text-shadow`는 `none`이 되고, `background-image`는 `url()` 이미지만 남고 `none`이 되며, `color-scheme`은 `light dark`가 됩니다.
- 색은 요소의 의미에 따라 시스템 색 키워드에서 골라집니다. 키워드는 어느 `<color>` 자리에서든 쓸 수 있습니다.

| 키워드 | 의미 |
|--------|------|
| `Canvas`, `CanvasText` | 문서 배경과 본문 텍스트 |
| `LinkText`, `VisitedText`, `ActiveText` | 링크 |
| `ButtonFace`, `ButtonText`, `ButtonBorder` | 버튼 배경, 글자, 경계 |
| `Field`, `FieldText` | 입력 필드 배경과 글자 |
| `Highlight`, `HighlightText` | 선택 영역 |
| `GrayText` | 비활성 |
| `AccentColor`, `AccentColorText` | 강조 컨트롤 |

문제는 색이 아닌 그림자나 배경색만으로 경계나 상태를 표현한 컴포넌트가 이 모드에서 사라진다는 것입니다.

```css
.btn { box-shadow: 0 0 0 1px var(--color-border) }

@media (forced-colors: active) {
  .btn { border: 2px solid ButtonBorder }
}
```

- 경계, 포커스 링, 선택 표시는 `box-shadow` 대신 `border`나 `outline`으로 만듭니다. 이 둘은 강제 색상 모드에서도 남고 색만 바뀝니다. 투명 테두리(`border: 2px solid transparent`)를 평소에 두면 이 모드에서 색이 채워져 보입니다.
- 아이콘은 `fill: currentColor`로 두어 글자색을 따르게 합니다.
- 색만으로 구분한 상태(선택됨, 오류)는 모양이나 텍스트, 아이콘으로도 구분합니다.
- 미디어 쿼리는 작은 조정에만 씁니다. 별도 디자인을 만들면 사용자의 선택을 거스르게 됩니다.
- `forced-color-adjust: none`은 해당 요소를 자동 조정에서 빼는 속성입니다. 브라우저의 조정 결과가 나쁠 때만 최소 범위로 쓰며, 사용자의 선택을 무시하는 용도로 쓰지 않습니다. 이 속성은 일부 엔진에서만 지원해 Baseline이 아닙니다.
- 비슷한 사용자 설정으로 `prefers-contrast`(`more`, `less`, `custom`, `no-preference`)가 있습니다. Baseline 2022이며, `custom`은 `forced-colors: active`와 짝을 이룹니다. 대비를 높이는 `more`에서 경계를 진하게 하는 정도의 조정에 씁니다.

## 디자인 토큰 교환 형식

디자인 토큰 교환 형식은 디자인 도구, 토큰 관리 도구, 코드 변환 도구가 같은 토큰 파일을 주고받기 위한 JSON 형식입니다. W3C 디자인 토큰 커뮤니티 그룹(DTCG)이 Design Tokens Format Module을 정의합니다. 2025.10 버전은 Final Community Group Report로, W3C 표준이나 표준 트랙 문서는 아닙니다.

```json
{
  "color": {
    "blue-500": {
      "$type": "color",
      "$value": {
        "colorSpace": "srgb",
        "components": [0.16, 0.36, 1]
      }
    },
    "action-bg": { "$value": "{color.blue-500}" }
  }
}
```

| 키 | 의미 |
|----|------|
| `$value` | 토큰의 값. 필수 |
| `$type` | 값의 종류. 그룹에 두면 아래 토큰이 상속 |
| `$description` | 용도 설명 |
| `$deprecated` | 폐기 표시(불리언 또는 사유 문자열) |
| `$extensions` | 도구별 추가 정보. 역방향 도메인 표기 |

- 파일 확장자는 `.tokens` 또는 `.tokens.json`, 미디어 타입은 `application/design-tokens+json`입니다. `application/json`도 허용합니다.
- 토큰의 묶음인 그룹을 중첩할 수 있고, `{group.token}` 형태의 중괄호 참조로 다른 토큰을 가리킵니다(별칭). 이 참조가 primitive와 semantic의 연결을 표현합니다.
- 값의 종류는 `color`, `dimension`, `fontFamily`, `fontWeight`, `duration`, `cubicBezier`, `number`와, 여러 값을 묶는 복합 형식 `shadow`, `border`, `transition`, `gradient`, `typography`, `strokeStyle`입니다.
- 이 파일을 읽어 CSS 커스텀 속성(`--color-action-bg`)으로 변환하는 일은 도구가 합니다. 변환 도구와 스펙 수정은 별개이므로 사용하는 도구가 지원하는 버전을 확인합니다.
- 브라우저가 이 형식을 직접 읽지는 않습니다. 빌드 단계의 입력 형식이며, 런타임 계약은 여전히 CSS 커스텀 속성입니다.

## 핵심 정리

- 토큰은 디자인 결정에 붙인 이름이며 웹에서는 상속되는 CSS 커스텀 속성으로 전달하고, 이름은 대소문자를 구분하며 `var()`의 대체값 체인으로 기본값을 둡니다.
- primitive는 원시 값, semantic은 용도, component는 컴포넌트가 여는 훅이며 컴포넌트는 component, semantic 순으로 읽고 primitive를 직접 읽지 않습니다.
- 이름은 접두사, 카테고리, 역할, 변형, 상태 순의 소문자 하이픈 형식으로 쓰고, 공개한 이름을 바꾸는 것은 breaking 변경입니다.
- `@property`는 값의 종류, 상속, 초깃값을 등록해 잘못된 값을 걸러 내고 전환을 가능하게 하며, 등록은 문서 전역이라 이름에 접두사를 붙입니다.
- 테마는 semantic 토큰 한 벌이고 다크 모드는 그 한 종류이며, `color-scheme`을 선언하고 두 모드 모두에서 대비를 확인합니다.
- forced-colors 모드에서는 그림자와 배경 이미지가 사라지고 색이 시스템 색으로 대체되므로 경계와 포커스는 `border`나 `outline`으로 만들고, DTCG는 도구 사이에서 토큰을 주고받는 JSON 형식입니다.
