## constructor

생성자는 요소 인스턴스가 만들어질 때 요소당 한 번 호출됩니다. 호출 경로는 파서, `createElement`·`new`, 업그레이드 세 가지입니다(자세히는 17편).

- 생성자가 실행되는 시점에는 요소가 문서에 연결되어 있지 않고, 경로에 따라 속성과 자식이 있거나 없습니다. 속성과 자식을 읽거나 추가하지 않는 이유입니다.
- 생성자는 요소의 수명 동안 한 번뿐이므로, 연결과 해제를 반복하는 요소에서도 한 번만 해도 되는 작업만 둡니다(아래 "초기화와 연결 로직 분리").
- 이후의 모든 콜백은 인스턴스 메서드로 호출되며, 인수 없는 콜백이 대부분입니다.

| 콜백 | 호출 조건 | 인수 |
|------|-----------|------|
| `connectedCallback` | 연결된 트리에 들어갈 때 | 없음 |
| `disconnectedCallback` | 연결된 트리에서 빠질 때 | 없음 |
| `connectedMoveCallback` | `moveBefore`로 이동할 때 | 없음 |
| `adoptedCallback` | 다른 문서로 입양될 때 | 이전 문서, 새 문서 |
| `attributeChangedCallback` | 관찰 대상 속성이 바뀔 때 | 이름, 이전 값, 새 값, 네임스페이스 |

모두 선택 사항입니다. 정의한 것만 호출됩니다.

## connectedCallback

`connectedCallback`은 요소가 문서(shadow 트리를 포함한 연결된 트리)에 삽입될 때마다 호출됩니다. 부모가 아직 문서에 붙지 않은 상태에서 요소를 넣는 경우에는 호출되지 않고, 그 부모가 문서에 붙을 때 호출됩니다.

```js
class UserCard extends HTMLElement {
  connectedCallback() {
    this.textContent = this.getAttribute('name') ?? ''
  }
}
```

- 같은 요소에서 여러 번 호출될 수 있습니다. 요소를 제거했다가 다시 붙일 때마다 호출됩니다.
- 요소를 포함한 서브트리가 삽입되면 그 안의 모든 커스텀 요소가 문서 순서(부모 먼저)로 호출됩니다.
- 보통 `this.isConnected`가 `true`입니다. 다만 호출이 예약된 뒤 다른 콜백이 요소를 제거하면 연결이 끊긴 상태로 호출될 수 있어서, 비동기로 이어지는 작업에서는 다시 확인합니다.
- 렌더링, 속성과 자식 읽기, 바깥 대상에 대한 리스너·옵저버·타이머 시작, 데이터 요청이 이 콜백의 일입니다.

## disconnectedCallback

`disconnectedCallback`은 요소가 연결된 트리에서 빠질 때 호출됩니다. `remove()`로 직접 제거되든, 조상이 제거되든 같습니다. 호출 순서는 문서 순서입니다.

```js
disconnectedCallback() {
  clearInterval(this.#timer)
  window.removeEventListener('resize', this.#onResize)
}
```

- 요소는 파괴되지 않고 메모리에 남아 있으며 다시 붙일 수 있습니다. 이 콜백은 연결 시점에 시작한 일을 정리하는 곳입니다.
- 연결되지 않은 트리 안에서의 제거에는 호출되지 않습니다.
- 정리하지 않은 외부 리스너·옵저버·타이머는 요소가 문서에서 사라진 뒤에도 요소를 붙잡아 둡니다(아래 "이벤트 리스너 등록 / 해제").

## attributeChangedCallback

`attributeChangedCallback(name, oldValue, newValue)`는 관찰 대상 속성이 추가·변경·제거·교체될 때 호출됩니다. 네 번째 인수로 네임스페이스도 받습니다.

```js
class UserCard extends HTMLElement {
  static observedAttributes = ['name']
  attributeChangedCallback(name, oldV, newV) {
    console.log(name, oldV, newV)
  }
}
// el.setAttribute('name', 'Kim')  // name null Kim
// el.setAttribute('name', 'Kim')  // name Kim Kim (같은 값)
// el.removeAttribute('name')      // name Kim null
```

- 속성이 추가되면 `oldValue`가 `null`, 제거되면 `newValue`가 `null`입니다.
- 값이 그대로여도 `setAttribute`를 부르면 호출됩니다. 변경 여부는 직접 비교합니다.
- `setAttribute`, `removeAttribute`, `toggleAttribute`, `id`·`className` 같은 반영 프로퍼티 설정 모두 이 콜백을 부릅니다.
- 업그레이드와 파서 생성에서는 이미 있던 속성마다 최초로 호출됩니다. 이때 요소가 아직 연결되기 전일 수 있으므로, 이 콜백의 로직은 연결 여부와 무관하게 안전해야 합니다.
- 콜백은 생성자가 끝난 뒤에 호출되므로 생성자에서 만든 비공개 필드를 쓸 수 있습니다.

## observedAttributes

`observedAttributes`는 `attributeChangedCallback`을 받을 속성 이름을 나열한 정적 프로퍼티입니다. 정적 필드나 정적 getter로 씁니다.

```js
static observedAttributes = ['name', 'size']
// 또는
static get observedAttributes() {
  return ['name', 'size']
}
```

- `define` 시점에 한 번만 읽습니다. 이후에 배열을 바꿔도 반영되지 않습니다.
- `attributeChangedCallback`이 정의되어 있을 때만 읽습니다. 목록에 없는 속성은 바뀌어도 콜백이 호출되지 않지만 `getAttribute`로는 읽을 수 있습니다.
- 이름은 소문자로 씁니다. HTML 문서에서 `setAttribute`와 파서는 속성 이름을 소문자로 바꾸므로 대문자가 든 이름은 어떤 속성과도 일치하지 않습니다.

```js
static observedAttributes = ['maxValue']  // ❌ 호출되지 않음
static observedAttributes = ['max-value'] // ✅
```

- 여러 단어는 하이픈으로 잇습니다(자세히는 19편).

## adoptedCallback

`adoptedCallback(oldDocument, newDocument)`는 요소가 다른 문서로 입양(adopt)될 때 호출됩니다. `document.adoptNode()`로 직접 입양하거나, 다른 문서(`iframe`의 문서 등)의 트리에 요소를 삽입하면 자동으로 입양됩니다.

```js
const doc = frame.contentDocument
doc.body.append(el)
// disconnectedCallback (연결되어 있었다면)
// adoptedCallback(oldDoc, doc)
// connectedCallback
```

- 같은 문서 안에서의 이동에는 호출되지 않습니다.
- 입양은 먼저 요소를 이전 위치에서 제거하므로 `disconnectedCallback`이 앞서 호출되고, 새 문서에 삽입된 뒤 `connectedCallback`이 호출됩니다.
- 쓸 일이 드뭅니다. 문서에 묶인 자원(`document` 참조, 스타일시트)을 새 문서 기준으로 바꿔야 할 때 씁니다.

## connectedMoveCallback

`connectedMoveCallback`은 연결된 요소를 `moveBefore()`로 옮길 때 호출됩니다. `moveBefore`는 요소를 제거하지 않고 새 위치로 옮겨서, 포커스, CSS 애니메이션, `iframe` 로딩 상태, 열린 popover와 modal 같은 상태를 유지합니다.

```js
parent.moveBefore(el, referenceNode)
// el에 connectedMoveCallback이 있으면 그것만 호출
```

```js
connectedMoveCallback() {
  this.#updateParentInfo() // 정리·재시작 없이 필요한 갱신만
}
```

- 이 콜백이 있으면 `disconnectedCallback`과 `connectedCallback` 대신 호출됩니다. 없으면 이동 시 두 콜백이 차례로 호출됩니다(안전한 대체 동작).
- 옮겨진 요소의 모든 커스텀 후손에도 호출됩니다.
- 연결된 트리 안에서의 이동만 대상입니다. 연결되지 않은 노드를 연결된 부모로 옮기거나 문서 사이를 옮기면 `HierarchyRequestError`입니다.
- 정리와 시작이 비싼 컴포넌트(옵저버, 연결 구독)는 이 콜백을 구현해 이동 때마다 재시작하지 않게 합니다.
- Chrome·Edge 133, Firefox 144부터 지원하고 Safari는 지원하지 않아서 Baseline이 아닙니다. 지원하지 않는 브라우저에서는 `moveBefore`가 없으므로 `insertBefore`로 대체합니다.

## 생성 경로별 콜백 순서

같은 요소라도 만들어지는 경로에 따라 콜백 순서와 생성자 시점의 상태가 다릅니다.

| 경로 | 호출 순서 | 생성자 시점의 속성·자식 |
|------|-----------|-------------------------|
| 파서, 정의가 먼저 있을 때 | 생성자 → `attributeChangedCallback`(관찰 속성마다) → `connectedCallback` | 없음 |
| 업그레이드(정의가 나중) | 생성자 → `attributeChangedCallback`(관찰 속성마다) → `connectedCallback`(연결되어 있을 때) | 있음 |
| `createElement` 또는 `new` | 생성자 | 없음 |

- 파서 경로에서는 시작 태그를 만난 시점에 요소가 만들어지고, 속성이 붙은 뒤 문서에 삽입됩니다. 속성 콜백은 삽입 전이라 `isConnected`가 `false`일 때 호출됩니다.
- `createElement` 경로에서는 생성자 이후의 콜백이 모두 이후 동작에 의해 호출됩니다. `setAttribute`를 부르면 속성 콜백이, 문서에 삽입하면 `connectedCallback`이 호출됩니다.
- 업그레이드에서는 속성 콜백과 `connectedCallback`이 생성자 호출 이전에 예약되지만, 생성자가 끝난 뒤에 실행됩니다.
- 생성자가 어느 경로에서든 먼저 실행되므로 콜백 안에서 생성자가 준비한 필드가 항상 있습니다.

## 커스텀 요소 반응 큐와 호출 시점

콜백은 DOM 작업 도중에 끼어들지 않고, DOM 메서드가 끝난 직후 사용자 코드로 돌아가기 직전에 호출됩니다. 이를 커스텀 요소 반응(custom element reaction)이라 합니다.

- 요소마다 반응 큐가 있고, 업그레이드와 콜백 호출이 순서대로 쌓입니다.
- `append`, `setAttribute`, `innerHTML` 설정 같은 DOM API는 호출될 때 새 큐를 열고, 작업이 모두 끝나면 그 큐의 반응을 실행합니다. 그래서 겉으로는 동기처럼 보입니다.
- 한 호출에서 여러 노드를 다루면 모든 변경이 끝난 뒤에 콜백이 일괄 호출됩니다.

```js
class XA extends HTMLElement {
  connectedCallback() {
    console.log(this.nextElementSibling?.localName)
  }
}
customElements.define('x-a', XA)
box.append(new XA(), document.createElement('b'))
// b (두 노드가 모두 삽입된 뒤 호출되므로 형제가 이미 있음)
```

- 같은 요소에 대한 반응은 원인이 된 동작의 순서대로 호출됩니다. 서로 다른 요소 사이의 전역 순서는 보장되지 않습니다. 콜백 안의 변경이 다시 콜백을 부르기 때문입니다.
- 콜백 안에서 예외가 나면 호출한 DOM 메서드로 전파되지 않고 전역 오류로 보고됩니다.
- 콜백 안에서 트리를 바꾸면 결과를 예측하기 어렵습니다. 예약된 `connectedCallback`이 실행되기 전에 다른 콜백이 요소를 제거하면 `isConnected`가 `false`인 채로 호출됩니다.
- DOM API를 거치지 않는 변경(사용자가 편집 가능한 영역을 직접 고치는 경우 등)은 마이크로태스크 시점에 반응을 실행합니다.

## 파서 생성 시 자식이 아직 없는 문제

HTML 파서는 시작 태그를 읽는 즉시 요소를 만들고 삽입하므로, 정의가 먼저 있을 때 `connectedCallback`은 자식이 파싱되기 전에 호출됩니다.

```html
<script src="user-card.js"></script>
<user-card><b>Kim</b></user-card>
<!-- connectedCallback 시점: this.children.length는 0 -->
```

이 상태에서 자식을 읽는 컴포넌트는 빈 값을 보게 됩니다. 해결 방법은 다음과 같습니다.

| 방법 | 설명 |
|------|------|
| 모듈 스크립트나 `defer`로 정의 | 문서 파싱이 끝난 뒤 정의되어 업그레이드 경로를 타므로 자식이 이미 있음 |
| 자식에 의존하지 않음 | 속성으로 받거나 slot으로 자식을 표시(자세히는 22편) |
| 자식 변화를 관찰 | `MutationObserver`로 `childList`를 감시(자세히는 43편) |
| 파싱 종료를 기다림 | `document.readyState`가 `loading`이면 `DOMContentLoaded` 후 처리 |

- 정의를 `async` 스크립트로 불러오면 요소가 먼저 만들어졌는지 나중에 업그레이드되는지 실행 때마다 달라질 수 있습니다. 어느 경로든 같은 결과가 나오도록 만드는 것이 목표입니다.
- 정의가 나중인 업그레이드에서는 자식이 이미 있으므로 위 문제가 없습니다. 같은 컴포넌트가 두 경로를 모두 견뎌야 하는 이유입니다.

## remove 후 append로 옮길 때의 콜백 쌍

연결된 요소를 `append`, `insertBefore`, `replaceWith`, `before`, `after` 등으로 다른 위치에 넣으면 DOM은 요소를 먼저 제거한 뒤 삽입합니다. 그래서 이동 한 번에 `disconnectedCallback`과 `connectedCallback`이 한 쌍으로 호출됩니다.

```js
list.append(el)           // 이미 연결된 el을 옮김
// disconnectedCallback → connectedCallback
el.remove()               // disconnectedCallback
document.body.append(el)  // connectedCallback
```

- 새 부모가 같은 문서에 있어도 쌍이 호출됩니다. 서브트리의 모든 커스텀 후손에게도 같은 쌍이 호출됩니다.
- 목록을 재정렬하며 항목을 `append`하면 항목마다 쌍이 호출되어 정리와 시작이 반복됩니다. 상태 보존이 필요하면 `moveBefore`를 쓰고 `connectedMoveCallback`을 구현합니다.
- 연결되지 않은 트리 안에서의 이동에는 콜백이 호출되지 않습니다.
- 그러므로 `connectedCallback`에는 "다시 호출되어도 안전한가"를 항상 점검해야 합니다.

## 초기화와 연결 로직 분리

초기화(한 번)와 연결 로직(연결마다)을 나누는 것이 생명주기 설계의 출발점입니다.

| 위치 | 하는 일 | 호출 횟수 |
|------|---------|-----------|
| `constructor` | 비공개 필드와 기본값, shadow root, 자기 자신에게 붙이는 리스너 | 요소당 1회 |
| `connectedCallback` | 최초 렌더, 속성·자식 읽기, 바깥 리스너·옵저버·타이머 시작 | 연결마다 |
| `disconnectedCallback` | `connectedCallback`에서 시작한 것을 모두 정리 | 해제마다 |

```js
class UserCard extends HTMLElement {
  #ready = false
  connectedCallback() {
    if (!this.#ready) {
      this.#ready = true
      this.#renderOnce()  // 최초 1회만
    }
    this.#start()         // 연결마다 시작
  }
  disconnectedCallback() {
    this.#stop()          // start가 한 일을 모두 되돌림
  }
}
```

- 한 번만 해야 하는 일(템플릿 복제, 초기 렌더)에는 가드 필드를 둡니다.
- 시작과 정리는 쌍으로 만듭니다. 시작한 것의 목록이 곧 정리할 것의 목록입니다.
- 비공개 필드(`#`)는 생성자 이후부터 쓸 수 있습니다(자세히는 20편).

## 재연결 가능한 컴포넌트 설계

재연결 가능한 컴포넌트는 붙였다 떼었다 다시 붙여도 처음과 같게 동작하고 자원이 쌓이지 않는 컴포넌트입니다. 목록 재정렬, 탭 전환, 라우터가 뷰를 떼었다 붙이는 경우에 필요합니다.

- 시작 작업은 반복 호출되어도 중복되지 않게 만듭니다. 같은 함수 참조를 같은 이벤트에 다시 `addEventListener`하는 것은 무시되지만, 익명 함수는 매번 새 리스너로 쌓입니다.
- 상태는 인스턴스에 두고, 연결할 때 DOM을 상태에서 다시 그릴 수 있게 합니다.
- 정리는 연결마다 `AbortController` 하나로 묶는 방식이 간단합니다.

```js
#ac = null
connectedCallback() {
  this.#ac = new AbortController()
  const opt = { signal: this.#ac.signal }
  window.addEventListener('resize', this.#onResize, opt)
  document.addEventListener('keydown', this.#onKey, opt)
}
disconnectedCallback() {
  this.#ac.abort() // signal로 등록한 리스너를 한꺼번에 제거
}
```

- `await` 뒤에는 요소가 아직 연결되어 있는지 확인하고, `fetch`에도 같은 `signal`을 넘겨 취소합니다(자세히는 37편).
- 확인 방법: 같은 요소를 `remove()` 후 다시 `append`하기를 여러 번 반복해도 리스너와 타이머가 하나만 동작해야 합니다.

## 이벤트 리스너 등록 / 해제

이벤트 리스너는 붙인 대상에 따라 정리가 필요한지가 갈립니다.

| 붙이는 대상 | 해제 | 이유 |
|-------------|------|------|
| `this`, 자신의 shadow root, 자신의 자식 | 불필요 | 요소와 수명이 같아 함께 사라짐 |
| `window`, `document`, `body`, 다른 요소 | 필요 | 대상이 리스너와 그 안의 요소 참조를 계속 붙잡음 |

- 요소 자신에게 붙이는 리스너는 생성자에서 한 번만 붙이면 재연결에도 유지됩니다. `connectedCallback`에서 다시 붙이면 익명 함수의 경우 중복됩니다.
- 해제하려면 등록할 때와 같은 함수 참조가 필요합니다. 클래스 필드의 화살표 함수나 `bind`한 함수를 필드에 저장합니다.
- 해제는 `removeEventListener`나 `AbortController`의 `signal` 옵션으로 합니다(자세히는 07편).

```js
#onResize = () => this.#layout()
connectedCallback() {
  window.addEventListener('resize', this.#onResize)
}
disconnectedCallback() {
  window.removeEventListener('resize', this.#onResize)
}
```

## Observer 등록 / 해제

`MutationObserver`, `ResizeObserver`, `IntersectionObserver`는 `observe()`를 호출한 뒤 끝내지 않으면 계속 동작하며 콜백이 계속 호출됩니다. 연결 시 시작하고 해제 시 `disconnect()`로 끝냅니다(자세히는 43편).

```js
connectedCallback() {
  this.#io = new IntersectionObserver(this.#onSeen)
  this.#io.observe(this)
}
disconnectedCallback() {
  this.#io.disconnect() // 모든 대상의 관찰을 중단
  this.#io = null
}
```

- `disconnect()`는 관찰 대상 전부를 한꺼번에 중단합니다. 특정 대상만 중단하려면 `unobserve()`입니다.
- `MutationObserver`는 `disconnect()`로 이미 감지했지만 아직 전달하지 않은 기록을 버립니다. 필요하면 먼저 `takeRecords()`로 꺼냅니다. 같은 옵저버에 `observe()`를 다시 호출해 재사용할 수도 있습니다.
- 가장 안전한 방법은 연결마다 새로 만들고 해제 때 `disconnect()` 후 버리는 것입니다.
- `document`나 다른 요소를 관찰하는 옵저버는 반드시 해제합니다. 자기 자신만 관찰하더라도 해제 규칙을 하나로 통일하면 빠뜨리지 않습니다.

## 타이머와 비동기 작업 정리

타이머와 진행 중인 비동기 작업은 요소가 문서에서 빠져도 계속 실행됩니다. 연결 때 시작하고 해제 때 취소합니다.

| 시작 | 취소 |
|------|------|
| `setTimeout` | `clearTimeout(id)` |
| `setInterval` | `clearInterval(id)` |
| `requestAnimationFrame` | `cancelAnimationFrame(id)` |
| `fetch(url, { signal })` | `AbortController.abort()` |

```js
connectedCallback() {
  this.#timer = setInterval(() => this.#tick(), 1000)
}
disconnectedCallback() {
  clearInterval(this.#timer)
}
```

- 유효하지 않은 id로 `clear...`를 호출해도 에러가 없으므로 방어 코드 없이 호출해도 됩니다. `setTimeout`과 `setInterval`의 id 풀은 같지만 짝을 맞춰 씁니다.
- `await` 뒤의 코드는 요소가 이미 떼어진 뒤에 실행될 수 있습니다. 결과를 반영하기 전에 `this.isConnected`나 `signal.aborted`를 확인합니다.
- 같은 요소가 다시 연결될 때를 위해 정리한 뒤 필드를 비우고(`null`), 연결 때 새로 시작합니다.
- 일반 메모리 관리는 67편, 비동기 경쟁 상태는 39편에서 다룹니다.

## 핵심 정리

- `connectedCallback`과 `disconnectedCallback`은 연결과 해제마다 여러 번 호출되고, 생성자는 요소당 한 번뿐이라서 초기화와 연결 로직을 나눕니다.
- `attributeChangedCallback`은 `observedAttributes`에 든 소문자 이름에만 호출되며, 같은 값을 다시 설정해도 호출됩니다.
- 파서와 업그레이드는 생성자 → 속성 콜백 → `connectedCallback` 순서이고, 파서 경로는 자식이 아직 없고 업그레이드 경로는 이미 있습니다.
- 콜백은 DOM 메서드가 끝난 직후 반응 큐에서 호출되며, 요소를 `append`로 옮기면 해제와 연결이 한 쌍으로 호출되고 `moveBefore`는 `connectedMoveCallback`을 부릅니다(Baseline이 아님).
- `window`·`document` 같은 바깥 대상의 리스너, 옵저버, 타이머, 요청은 `disconnectedCallback`에서 정리해야 하며, `AbortController` 하나로 묶으면 재연결에도 안전합니다.
