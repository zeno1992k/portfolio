## 연동이 갈리는 지점

프레임워크는 커스텀 요소를 "이름에 대시가 있는 일반 요소"로 취급합니다. 연동은 네 가지 접점에서 갈립니다.

| 접점 | 질문 |
|------|------|
| 값 전달 | 템플릿의 값을 HTML 어트리뷰트로 넘기는가, DOM 프로퍼티로 넘기는가 |
| 이벤트 | `CustomEvent`를 어떤 문법으로 받는가. 이름의 대소문자·대시를 구분하는가 |
| 자식 | 프레임워크가 만든 노드가 슬롯에 들어가는가 |
| 폼·스타일 | 폼 값과 테마가 프레임워크 경계를 넘는가 |

어트리뷰트는 문자열만 담고, 프로퍼티는 객체·배열·함수도 담습니다(자세히는 19편). 프레임워크마다 기본값이 다릅니다.

## Web Component를 React에서 사용

React에서 커스텀 요소는 JSX 태그로 씁니다. 태그 이름에 대시가 있거나 `is` 어트리뷰트가 있으면 커스텀 요소로 인식됩니다.

```jsx
function App() {
  const pick = (e) => log(e.detail)
  return <user-card name="Kim" onselect={pick} />
}
```

- React 18까지는 인식하지 못하는 prop을 전부 어트리뷰트로 넘겨서 객체를 전달할 수 없었습니다. 객체는 문자열로 변환되고, 이벤트는 직접 `addEventListener`로 달아야 했습니다.
- React 19는 커스텀 요소를 완전히 지원합니다(아래 "React 19의 커스텀 요소 지원 범위").

### React 19의 커스텀 요소 지원 범위

React 19의 처리 규칙은 렌더링 환경에 따라 다릅니다.

| 환경 | prop이 어트리뷰트가 되는 경우 | prop이 프로퍼티가 되는 경우 | 생략되는 경우 |
|------|-------------------------------|-----------------------------|---------------|
| 클라이언트 렌더링 | 요소 인스턴스에 같은 이름의 프로퍼티가 없을 때 | 요소 인스턴스에 같은 이름의 프로퍼티가 있을 때 | 없음 |
| 서버 렌더링 | 문자열, 숫자 같은 원시 값, `true` | 해당 없음 | 객체, 심벌, 함수, `false` |

```jsx
<my-list items={[1, 2, 3]} />
// 클라이언트: my-list에 items 프로퍼티가 있으면 배열 그대로 전달
// 클라이언트: 없으면 items="1,2,3" 어트리뷰트
// 서버 렌더링: 객체라서 HTML에서 생략
```

- 프로퍼티 존재 여부는 요소가 만들어진 뒤 확인합니다. 정의가 로드되기 전에 렌더링되면 요소가 아직 업그레이드되지 않아 프로퍼티가 없고, 값이 어트리뷰트로 나갑니다. 요소를 렌더링하기 전에 `customElements.define()`을 끝내 두는 편이 안전합니다(업그레이드는 17편).
- 이벤트는 `on` 접두사로 받습니다. 이름은 대소문자와 대시를 구분합니다. `onsay-hi`는 `say-hi` 이벤트를, `onsayHi`는 `sayHi` 이벤트를 듣습니다.
- 표준 이벤트 이름은 소문자이므로 `change`를 들으려면 `onchange`입니다. `onChange`는 `Change` 이벤트를 듣습니다.

```jsx
<my-switch onchange={(e) => setOn(e.target.checked)} />
<my-chip onsay-hi={handleHi} />
```

**흔한 실수:** 서버 렌더링된 HTML에서 객체 prop이 빠진다는 사실을 놓치는 것입니다. 객체를 받는 요소는 클라이언트에서 프로퍼티가 설정되기 전까지 빈 상태로 보입니다.

## Web Component를 Vue에서 사용

Vue는 템플릿의 비표준 태그를 Vue 컴포넌트로 찾으려 합니다. 컴파일러에 커스텀 요소 판별 함수를 알려 주어야 경고 없이 일반 요소로 처리됩니다.

```js
// vite.config.js
vue({
  template: {
    compilerOptions: {
      isCustomElement: (tag) => tag.includes('-'),
    },
  },
})
```

Vue 3는 템플릿 바인딩을 값마다 `in` 연산자로 DOM 프로퍼티 존재를 확인해 프로퍼티면 프로퍼티로, 아니면 어트리뷰트로 넘깁니다. 확실히 프로퍼티로 보내야 하면 `.prop` 수식어를 씁니다.

```vue
<user-card :user.prop="{ name: 'Kim' }" />
<user-card .user="{ name: 'Kim' }" />
```

- 두 번째 줄은 `.prop`의 단축 표기입니다.
- 이벤트는 `@` 로 받고 이름을 있는 그대로 씁니다. `@say-hi="onHi"`는 `say-hi` 이벤트를 듣습니다.
- Vue 컴포넌트 자체를 커스텀 요소로 내보내는 `defineCustomElement`도 있습니다. 선언한 props가 요소의 프로퍼티가 되고(Boolean·Number는 자동 형 변환), `emit`한 이벤트는 `detail`에 인수를 담은 `CustomEvent`가 됩니다. 슬롯은 네이티브 슬롯 문법을 쓰며 스코프드 슬롯은 지원하지 않습니다.

## Web Component를 Svelte에서 사용

Svelte 템플릿에서도 커스텀 요소는 일반 요소처럼 씁니다. 이벤트는 `on` 으로 시작하는 어트리뷰트로 달고, 이름의 대소문자를 구분합니다. `onclick`은 `click`을, `onClick`은 `Click`을 듣습니다. 따라서 대문자가 섞인 커스텀 이벤트 이름도 그대로 받을 수 있습니다.

```svelte
<user-card name="Kim" onselect={(e) => pick(e.detail)} />
```

객체는 `bind:this`로 요소를 잡아 프로퍼티로 직접 대입하면 어트리뷰트 변환 규칙과 무관하게 전달됩니다(아래 "ref / imperative API").

반대로 Svelte 컴포넌트를 커스텀 요소로 컴파일할 수도 있습니다. `customElement` 컴파일러 옵션을 켜고 `svelte:options`로 태그 이름을 지정합니다.

```svelte
<svelte:options customElement="my-counter" />
<script>
  let { count = 0 } = $props()
</script>
```

- 컴파일된 요소에 노출하려면 props를 하나씩 선언해야 합니다. `let props = $props()`로 통째로 받으면 개별 props를 알 수 없어 요소의 프로퍼티로 내보내지 못합니다.
- `customElement`는 객체로 줄 수도 있습니다. `tag`, `shadow`(`"none"`, `"open"`, `ShadowRootInit`), `props`(`attribute`, `reflect`, `type`), `extend`를 지정합니다.
- 호스트 요소는 `$host` 룬으로 접근합니다.
- 컴파일된 요소 안에서 이름이 `on`으로 시작하는 prop은 이벤트 리스너로 해석되므로 쓰지 않습니다.
- 슬롯 내용은 DOM에서는 즉시 만들어지지만 Svelte는 지연 렌더링으로 다룹니다. `{#if}` 블록 안에 있어도 항상 생성됩니다.
- 스타일은 기본으로 섀도 DOM에 캡슐화되어 외부 스타일시트와 `:global()` 규칙이 닿지 않습니다. 컨텍스트는 커스텀 요소 경계를 넘지 못합니다.

## Angular의 CUSTOM_ELEMENTS_SCHEMA와 Angular Elements

Angular는 템플릿 컴파일 때 모르는 요소를 오류로 처리합니다. `CUSTOM_ELEMENTS_SCHEMA`를 선언하면 이름에 대시가 있는 비Angular 요소와 대시가 있는 요소 프로퍼티가 허용됩니다.

```ts
@Component({
  selector: 'app-root',
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
  template: `
    <user-card [user]="user" (select)="pick($event)" />
  `,
})
export class AppComponent {}
```

- 프로퍼티 바인딩 `[user]`는 DOM 프로퍼티에 대입하고, 어트리뷰트로 보내려면 `[attr.user]`로 씁니다. 값이 `null`이면 `removeAttribute`가 호출됩니다.
- 이벤트는 `(event-name)` 구문으로 받습니다.
- 스키마 선언은 오타 난 태그 이름도 통과시키므로 사용 범위를 해당 컴포넌트로 좁힙니다.

Angular Elements(`@angular/elements`)는 반대 방향으로 Angular 컴포넌트를 커스텀 요소로 내보냅니다.

```ts
import { createCustomElement } from '@angular/elements'

const el = createCustomElement(Popup, { injector })
customElements.define('popup-element', el)
```

- 컴포넌트 입력(`inputProp`)은 소문자 대시 어트리뷰트(`input-prop`)와 같은 이름의 프로퍼티가 됩니다.
- 컴포넌트 출력은 출력 이름과 같은 이름의 `CustomEvent`로 디스패치됩니다.
- 커스텀 요소의 태그 이름을 컴포넌트의 selector와 같게 하면 한 DOM 요소에 컴포넌트 인스턴스가 두 개 생겨 예기치 못한 동작이 나므로 피합니다.
- 타입은 `NgElement`와 `WithProperties`로 붙입니다.

## Property 전달 차이

연동 문제의 대부분은 값이 프로퍼티로 가는지 어트리뷰트로 가는지에서 나옵니다.

| 프레임워크 | 기본 동작 | 프로퍼티로 강제하는 방법 |
|------------|-----------|--------------------------|
| React 19 (클라이언트) | 같은 이름의 프로퍼티가 있으면 프로퍼티, 없으면 어트리뷰트 | `ref`로 요소를 잡아 대입 |
| Vue 3 | 같은 이름의 DOM 프로퍼티가 있으면 프로퍼티(`in` 검사) | `.prop` 수식어 |
| Svelte | 공식 문서에서 규칙을 확인하지 못함 | `bind:this`로 요소를 잡아 대입 |
| Angular | `[name]`은 프로퍼티, `[attr.name]`은 어트리뷰트 | 프로퍼티 바인딩 |

- 어트리뷰트는 문자열이라서 객체를 `JSON.stringify`로 보내면 요소가 파싱해야 합니다. 공개 계약에서 객체는 프로퍼티로만 받게 정하고 어트리뷰트는 원시 값 전용으로 둡니다(자세히는 19편).
- 요소 정의가 늦게 로드되면 프로퍼티가 인스턴스에 없는 시점이 생깁니다. 요소 쪽에서 업그레이드 전에 대입된 프로퍼티를 constructor나 `connectedCallback`에서 다시 읽어 흡수하면 프레임워크와 로딩 순서에 덜 의존합니다.

```js
connectedCallback() {
  if (Object.hasOwn(this, 'items')) {
    const v = this.items  // 업그레이드 전에 대입된 값
    delete this.items     // 자기 프로퍼티를 지우고
    this.items = v        // 클래스의 setter로 다시 대입
  }
}
```

## CustomEvent 연동

커스텀 요소는 `CustomEvent`를 디스패치하고 프레임워크는 그 이벤트를 리스너로 듣습니다. 요소 쪽에서 지켜야 할 것은 이벤트 이름과 데이터 위치뿐입니다(자세히는 25편).

```js
this.dispatchEvent(new CustomEvent('item-select', {
  detail: { id },
  bubbles: true,
  composed: true,
}))
```

| 프레임워크 | 받는 문법 | 이름 규칙 |
|------------|-----------|-----------|
| React 19 | `onitem-select={fn}` | 대소문자·대시 구분 |
| Vue | `@item-select="fn"` | 있는 그대로 |
| Svelte | `onitem-select={fn}` | 대소문자 구분 |
| Angular | `(item-select)="fn($event)"` | 있는 그대로 |

- 이벤트 이름은 소문자와 대시(kebab-case)로 짓는 것이 어느 프레임워크에서도 같은 표기로 받는 가장 안전한 선택입니다. 대소문자가 섞인 이름은 문법별 변환 규칙에 걸립니다.
- React 18 이하에서는 `on*` prop이 합성 이벤트 시스템에 걸려 커스텀 이벤트를 받지 못해서 `ref`와 `addEventListener`가 필요합니다.
- 데이터는 `event.detail`에 담습니다. 프레임워크가 `event.target` 이 가리키는 값을 쓰도록 `value` 같은 프로퍼티도 함께 갱신해 두면 편합니다.
- 섀도 경계를 넘어 상위에서 듣게 하려면 `composed: true`와 `bubbles: true`가 모두 필요합니다(자세히는 21편).

## ref / imperative API

프레임워크의 ref로 요소 인스턴스를 얻으면 공개 메서드와 프로퍼티를 직접 호출할 수 있습니다. 선언형 값 전달로 풀 수 없는 일(포커스 이동, `open()`·`show()` 호출, 객체 대입)은 이 경로로 합니다.

```jsx
const ref = useRef(null)
const openDialog = () => ref.current.showModal()
return <my-dialog ref={ref} />
```

```vue
<script setup>
import { useTemplateRef } from 'vue'
const dlg = useTemplateRef('dlg')
const open = () => dlg.value.showModal()
</script>
<template><my-dialog ref="dlg" /></template>
```

```svelte
<script>
  let el
  const open = () => el.showModal()
</script>
<my-dialog bind:this={el} />
```

- ref는 요소가 마운트된 뒤에만 채워지고, Vue의 `useTemplateRef`는 3.5 이상에서 쓰며 이전에는 같은 이름의 `ref` 변수를 선언합니다.
- 요소의 정의가 아직 로드되지 않았다면 메서드가 없습니다. `customElements.whenDefined('my-dialog')`로 정의를 기다린 뒤 호출합니다.
- React 19는 함수 컴포넌트에서 `ref`를 일반 prop으로 받습니다. 커스텀 요소 래퍼 컴포넌트를 만들 때 `forwardRef` 없이 `ref`를 전달할 수 있습니다.

## Slot과 Framework Children

프레임워크가 렌더링한 자식은 커스텀 요소의 light DOM 자식이 되고, `slot` 어트리뷰트로 이름 있는 슬롯에 배정됩니다(자세히는 22편).

```jsx
<user-card>
  <h3 slot="title">{name}</h3>
  <p>{bio}</p>
</user-card>
```

- 자식 노드는 프레임워크가 만들고 갱신하며 슬롯 배정은 브라우저가 합니다. 둘은 독립이라서 프레임워크의 상태 변화가 슬롯 안 노드에 그대로 반영됩니다.
- 슬롯에는 DOM 노드만 들어갑니다. 프레임워크의 "컴포넌트를 prop으로 넘기는" 패턴(렌더 prop, 스코프드 슬롯)은 요소 경계를 넘지 못합니다. Vue의 `defineCustomElement`가 스코프드 슬롯을 지원하지 않는 것도 같은 이유입니다.
- 슬롯에 넣을 텍스트가 자식 하나라면 `slot` 어트리뷰트를 붙일 요소가 필요하므로 래퍼 `span`을 씁니다. 텍스트 노드는 `slot` 어트리뷰트를 가질 수 없습니다.

## 폼 컴포넌트 연동

폼 연관 커스텀 요소(자세히는 26편)는 `ElementInternals.setFormValue()`로 값을 폼에 등록합니다. 이 요소가 `formAssociated`이면 프레임워크와 무관하게 `FormData`, 제출, `reset`, 제약 검증에 참여합니다.

```js
class MyInput extends HTMLElement {
  static formAssociated = true
  #internals = this.attachInternals()
  set value(v) { this.#internals.setFormValue(v) }
}
```

- 프레임워크의 폼 라이브러리가 `form.elements`나 `FormData`로 값을 읽는 경우 동작하지만, 프레임워크 상태에 값을 두는 제어 컴포넌트 방식(양방향 바인딩)은 요소가 프로퍼티 `value`와 `input`·`change` 이벤트를 제공해야 연결됩니다.
- 연결 방법은 같습니다. 값은 프로퍼티로 내려 주고(Vue의 `.prop`, Angular의 프로퍼티 바인딩, `ref` 대입) 변경은 이벤트로 올려 받습니다.
- `setFormValue`는 `formAssociated`가 `true`가 아니면 `NotSupportedError`를 던집니다. Baseline 널리 지원(2023).
- 폼 제출 시점에 값을 읽는 방식이면 값 전달 동기화 문제가 사라집니다. 제어 방식이 꼭 필요하지 않다면 비제어 방식으로 `name`, `value`, 폼 제출에 맡깁니다.

**흔한 실수:** 양방향 바인딩 문법(`v-model`, `bind:value`)이 임의의 커스텀 요소에 그대로 동작한다고 가정하는 것입니다. 요소가 프로퍼티와 이벤트 이름을 어떻게 공개했는지에 맞춰 값과 이벤트를 따로 연결해야 합니다.

## CSS / Theme 연동

섀도 DOM 안의 스타일은 프레임워크의 스타일(CSS 모듈, 스코프 스타일, 유틸리티 클래스)이 닿지 않습니다. 연동 창구는 섀도 경계를 통과하는 세 가지입니다(자세히는 23편, 24편, 74편).

| 창구 | 쓰는 방법 |
|------|-----------|
| CSS 사용자 정의 속성 | 프레임워크 쪽 `:root`나 부모 요소에서 값 설정. 상속되어 경계를 통과 |
| `::part()` | 요소가 `part`로 공개한 부분만 외부에서 꾸밈 |
| 호스트 요소의 클래스·어트리뷰트 | 프레임워크가 `class`나 `data-*`를 붙이면 `:host(.dark)`로 요소 안에서 분기 |

```css
user-card { --card-bg: #fff; }
.dark user-card { --card-bg: #222; }
user-card::part(title) { font-weight: 700; }
```

- 테마는 사용자 정의 속성(디자인 토큰)으로 주입하는 편이 프레임워크에 독립적입니다.
- 외부 스타일시트를 요소 안에서 쓰려면 `adoptedStyleSheets`로 공유하거나 `link`를 섀도 루트에 넣습니다.
- Svelte 컴파일 요소처럼 `shadow: "none"`으로 섀도 DOM을 끄면 전역 스타일이 닿지만 캡슐화가 사라집니다.

## Custom Elements Everywhere 호환성 표

Custom Elements Everywhere는 프레임워크가 커스텀 요소를 얼마나 올바르게 쓰는지를 테스트 모음으로 측정해 공개하는 사이트입니다. 기본 테스트는 요소 표시, 어트리뷰트 설정, DOM 이벤트 수신을 확인하고 고급 테스트는 데이터 처리(프로퍼티와 어트리뷰트)와 이벤트 처리(이름 형식별 선언적 수신)를 확인합니다.

| 프레임워크 | 측정 버전 | 기본 | 고급 |
|------------|-----------|------|------|
| React | 19 이상 | 16/16 | 16/16 |
| Vue | 3.2.38 이상 | 16/16 | 16/16 |
| Svelte | 4.2.19 | 16/16 | 16/16 |
| Angular | 16.2.10 | 16/16 | 16/16 |

- 표는 사이트가 마지막으로 측정한 버전 기준이며 Svelte 5와 최신 Angular는 이 표의 측정 대상이 아닙니다. 점수가 낮은 프레임워크는 대부분 이벤트 이름의 대소문자 지원 문제입니다.
- 만점이어도 프레임워크마다 문법이 다르다는 사실은 남습니다. 표는 "동작한다"를 확인하는 자료이지 "같은 코드로 동작한다"를 보장하지 않습니다.

## JSX 타입 선언(IntrinsicElements)

TypeScript에서 JSX로 커스텀 요소를 쓰면 정의되지 않은 태그라서 오류가 납니다. `IntrinsicElements`에 태그와 prop 타입을 선언합니다. React 19는 전역 `JSX` 네임스페이스를 없앴으므로 모듈 선언으로 감쌉니다.

```ts
// global.d.ts  (tsconfig의 jsx가 react-jsx인 경우)
declare module 'react/jsx-runtime' {
  namespace JSX {
    interface IntrinsicElements {
      'user-card': {
        name?: string
        onselect?: (e: Event) => void
      }
    }
  }
}
```

| tsconfig의 `jsx` 값 | 선언할 모듈 이름 |
|---------------------|------------------|
| `react-jsx` | `react/jsx-runtime` |
| `react-jsxdev` | `react/jsx-dev-runtime` |
| `react`, `preserve` | `react` |

- Vue는 `GlobalComponents`를 확장하고 `DefineCustomElement` 도우미로 요소 클래스, 이벤트, 어트리뷰트 이름을 지정합니다.
- Angular는 `HTMLElementTagNameMap`을 확장하거나 `NgElement`와 `WithProperties`로 타입을 붙입니다.
- 프로퍼티 이름을 하나씩 손으로 적는 방식은 요소가 늘수록 누락이 생기므로 Custom Elements Manifest 같은 메타데이터에서 생성하는 편이 낫습니다.

## 프레임워크 SSR과 DSD 연동

서버에서 프레임워크로 HTML을 렌더링하면 커스텀 요소는 태그와 어트리뷰트만 나옵니다. 섀도 DOM의 내용은 JavaScript가 `attachShadow()`를 호출해야 생기므로 서버 HTML에 없고, 정의가 로드되기 전까지 내용이 비어 보입니다(자세히는 76편).

해법은 Declarative Shadow DOM(DSD)입니다. `template`에 `shadowrootmode`를 지정하면 HTML 파서가 파싱 시점에 섀도 루트를 만듭니다.

```html
<user-card>
  <template shadowrootmode="open">
    <style>p { margin: 0 }</style>
    <p>Kim</p>
  </template>
</user-card>
```

- `shadowrootmode`는 `open`과 `closed`만 유효합니다. 값이 없거나 잘못되면 일반 `template`이 됩니다. 부모 안의 첫 번째 선언적 섀도 루트만 변환됩니다.
- 처음 HTML 파싱 중에만 동작합니다. `innerHTML`에 문자열로 넣으면 섀도 루트가 만들어지지 않고, `setHTMLUnsafe()`·`parseHTMLUnsafe()`는 DSD를 처리합니다.
- React 19의 서버 렌더링은 객체와 함수 prop을 생략합니다. 섀도 내용은 커스텀 요소 쪽 SSR(Lit SSR 같은 도구)이 DSD로 출력해야 하며, 프레임워크는 그 요소를 일반 태그로 감쌉니다.
- Lit SSR은 Lit 컴포넌트를 Node에서 정적 HTML로 렌더링하며 Next.js(`@lit-labs/nextjs`), Nuxt 3(`nuxt-ssr-lit`), Astro 통합을 제공합니다. 섀도 DOM을 쓰는 Lit 컴포넌트만 지원하고 비동기 컴포넌트 작업은 지원하지 않습니다.
- 클라이언트에서 요소 정의가 로드되면 업그레이드가 일어납니다. DSD로 만든 섀도 루트가 이미 있는 요소에 `attachShadow()`를 부르면, `mode`가 같을 때는 기존 `ShadowRoot`를 비우고 돌려주고 `mode`가 다르면 `NotSupportedError`를 던집니다. 서버가 그린 내용을 살리려면 비우기 전에 `ElementInternals.shadowRoot`로 기존 루트가 있는지 확인합니다.

```js
constructor() {
  super()
  this.#internals = this.attachInternals()
  this.#root = this.#internals.shadowRoot
    ?? this.attachShadow({ mode: 'open' })
}
```

- 서버 출력의 `mode`와 클라이언트의 `attachShadow({ mode })`를 맞춥니다.

## 프레임워크 독립 UI 라이브러리 설계

한 번 만든 Web Component를 모든 프레임워크에서 쓰게 하려면 공개 계약을 플랫폼 표준만으로 정합니다.

| 계약 | 설계 기준 |
|------|-----------|
| 값 입력 | 원시 값은 어트리뷰트와 프로퍼티 양쪽, 객체는 프로퍼티 전용 |
| 값 출력 | `CustomEvent`. 이름은 kebab-case, 데이터는 `detail` |
| 명령 | 공개 메서드(`open()`, `focus()`). 문서에 목록으로 명시 |
| 구성 | 슬롯. 렌더 prop이나 스코프드 슬롯을 요구하지 않음 |
| 폼 | `formAssociated`와 `ElementInternals`. 프레임워크 폼 상태에 의존하지 않음 |
| 스타일 | 사용자 정의 속성과 `::part()`. 프레임워크의 CSS 기능 의존 금지 |
| 등록 | 정의와 등록을 분리하고 `define` 호출은 소비자가 선택 |
| 타입 | 요소 클래스와 이벤트 맵을 타입으로 내보냄 |

- 기능을 프레임워크 어댑터로 보강하는 방식이 흔합니다. 얇은 래퍼(React의 `ref`와 이벤트 연결, Vue의 `.prop`)만 두고 로직은 요소에 둡니다. 어댑터는 다음 일만 합니다: 프로퍼티 대입, 이벤트 연결, 타입 제공.
- 요소를 등록하는 부수 효과를 `import`할 때 일어나게 하면 번들러의 트리 셰이킹과 SSR에서 문제가 됩니다. 클래스를 내보내고 `defineElements()` 같은 등록 함수를 따로 제공합니다(자세히는 72편).
- 패키지 구조·버전 관리는 72편, 73편에서 다룹니다.

## 핵심 정리

- 연동의 핵심은 값이 DOM 프로퍼티로 가는지 HTML 어트리뷰트로 가는지입니다. 객체는 프로퍼티로만 안전합니다.
- React 19는 클라이언트에서 같은 이름의 프로퍼티가 있으면 프로퍼티로, 없으면 어트리뷰트로 넘기고, 서버 렌더링에서는 원시 값과 `true`만 어트리뷰트로 내보냅니다. Vue는 `.prop`, Angular는 `[prop]`, Svelte는 `bind:this` 대입으로 프로퍼티를 강제합니다.
- 이벤트는 프레임워크마다 문법이 다르며 React 19와 Svelte는 이름의 대소문자를 구분하므로 kebab-case 소문자 이름이 가장 이식성이 높습니다.
- 슬롯은 DOM 노드만 받고, 폼은 `formAssociated`와 `setFormValue`로, 스타일은 사용자 정의 속성과 `::part()`로 경계를 넘깁니다.
- 서버 렌더링에서 섀도 내용은 Declarative Shadow DOM으로 출력해야 하며, 클라이언트 요소는 이미 있는 섀도 루트를 재사용해야 합니다.
