## 공통 규칙

장치 API 대부분은 보안 컨텍스트(HTTPS)에서만 노출되고, 사용자 권한이나 사용자 활성화(클릭 같은 입력)를 요구합니다. 권한 모델은 60편, 보안 컨텍스트는 62편에서 다룹니다.

- 지원 여부는 객체나 메서드 존재로 확인합니다(`'geolocation' in navigator`).
- 지원하지 않거나 거부돼도 핵심 기능이 동작해야 합니다. 장치 API는 점진적 향상으로 씁니다.
- iframe에서는 Permissions-Policy가 허용해야 하고, 상위 문서는 `allow` 속성으로 위임합니다.

## Geolocation

`navigator.geolocation`은 기기의 위치를 읽는 API입니다. Baseline 널리 지원, 보안 컨텍스트 필수, 호출하면 권한 프롬프트가 뜹니다.

```js
navigator.geolocation.getCurrentPosition(
  (pos) => {
    const { latitude, longitude, accuracy } = pos.coords
    // 37.56, 126.97, 25 (accuracy는 미터)
  },
  (err) => console.log(err.code, err.message),
)
```

`GeolocationPosition`은 `coords`와 `timestamp`를 가집니다. `coords`의 필드는 다음과 같습니다.

| 필드 | 단위 | null 가능 |
|------|------|-----------|
| `latitude`, `longitude` | 도(WGS84) | 아니오 |
| `accuracy` | 미터(95% 신뢰 수준) | 아니오 |
| `altitude`, `altitudeAccuracy` | 미터 | 예 |
| `heading` | 진북 기준 시계 방향 도 | 예 |
| `speed` | 초당 미터 | 예 |

### 옵션

세 번째 인수 `PositionOptions`의 기본값은 표준에 다음과 같이 정의돼 있습니다.

| 옵션 | 기본값 | 뜻 |
|------|--------|----|
| `enableHighAccuracy` | `false` | `true`면 GPS 같은 정밀 수단을 요청(배터리 소모 증가) |
| `timeout` | 제한 없음 | 위치를 얻기까지 허용할 밀리초 |
| `maximumAge` | `0` | 이 시간(밀리초) 안의 캐시된 위치는 재사용 허용. `0`이면 항상 새로 측정 |

`timeout`에는 권한 프롬프트 응답을 기다린 시간과 문서가 보이지 않던 시간이 포함되지 않습니다. 사용자가 프롬프트를 방치하면 오류 콜백이 호출되지 않을 수 있으므로 UI에 대기 상태를 따로 둡니다.

### watchPosition과 clearWatch

`watchPosition()`은 `getCurrentPosition()`과 같은 인수를 받고, 위치가 바뀔 때마다 성공 콜백을 호출합니다. 반환하는 숫자 ID를 `clearWatch()`에 넘겨 중단합니다.

```js
const geo = navigator.geolocation
const id = geo.watchPosition(onMove, onFail)
// 화면을 떠날 때
geo.clearWatch(id)
```

중단하지 않으면 배터리를 계속 쓰고 콜백이 남습니다. 컴포넌트는 `disconnectedCallback`에서 정리합니다(자세히는 18편).

### 오류 코드

오류 콜백은 `GeolocationPositionError`를 받고, `code`는 다음 셋 중 하나입니다.

| 상수 | 값 | 원인 |
|------|----|------|
| `PERMISSION_DENIED` | 1 | 사용자 거부, 또는 정책이 차단 |
| `POSITION_UNAVAILABLE` | 2 | 위치를 얻지 못함(신호 없음 등) |
| `TIMEOUT` | 3 | `timeout` 안에 얻지 못함 |

**흔한 실수:** HTTP 페이지에서 호출하는 것입니다. 보안 컨텍스트가 아니면 API가 노출되지 않습니다. `timeout`을 지정하지 않으면 응답이 오래 오지 않을 수 있습니다.

## Device Orientation과 Motion 이벤트

기기의 기울기와 움직임을 `window` 이벤트로 받습니다. Baseline 2023입니다.

| 이벤트 | 이벤트 객체 | 담는 값 |
|--------|-------------|---------|
| `deviceorientation` | `DeviceOrientationEvent` | `alpha`(z축 0–360), `beta`(x축 –180–180), `gamma`(y축 –90–90), `absolute` |
| `deviceorientationabsolute` | `DeviceOrientationEvent` | 지구 자기장 기준 방향 |
| `devicemotion` | `DeviceMotionEvent` | `acceleration`, `accelerationIncludingGravity`(m/s²), `rotationRate`(도/초), `interval`(ms) |

```js
window.addEventListener('deviceorientation', (e) => {
  console.log(e.alpha, e.beta, e.gamma) // 90 12.5 -3
})
```

iOS Safari(13 이상)는 이벤트를 받기 전에 사용자 활성화 안에서 권한을 요청해야 합니다. `DeviceOrientationEvent.requestPermission()`과 `DeviceMotionEvent.requestPermission()`이 `'granted'` 또는 `'denied'`로 이행하는 프라미스를 돌려줍니다. 활성화 없이 호출하면 `NotAllowedError`입니다.

```js
button.addEventListener('click', async () => {
  const api = DeviceOrientationEvent
  if (typeof api.requestPermission === 'function') {
    const state = await api.requestPermission()
    if (state !== 'granted') return
  }
  window.addEventListener('deviceorientation', onTilt)
})
```

`requestPermission`이 없는 브라우저는 함수 존재 검사로 건너뜁니다. 센서 접근은 Permissions-Policy의 `accelerometer`, `gyroscope`, `magnetometer`가 제어합니다. 데스크톱처럼 센서가 없는 기기에서는 이벤트가 오지 않거나 값이 `null`입니다.

## Screen Orientation

`screen.orientation`은 화면 방향을 읽고 잠그는 API입니다. 읽기(`type`, `angle`, `change` 이벤트)는 Baseline 2023, `lock()`과 `unlock()`은 미Baseline입니다.

```js
const o = screen.orientation
console.log(o.type, o.angle) // 'portrait-primary' 0
o.addEventListener('change', () => console.log(o.type))
```

- `type`: `portrait-primary`, `portrait-secondary`, `landscape-primary`, `landscape-secondary` 중 하나.
- `angle`: 기기의 자연 방향에서 반시계 방향으로 돌아간 각도(0, 90, 180, 270).
- CSS에서 방향만 필요하면 `(orientation: landscape)` 미디어 쿼리가 더 단순합니다.

### 잠금 지원 상태

`lock(type)`은 방향을 고정하는 프라미스를 돌려줍니다. 허용 값은 `any`, `natural`, `landscape`, `portrait`, `portrait-primary`, `portrait-secondary`, `landscape-primary`, `landscape-secondary`입니다. MDN은 일반적으로 모바일 기기에서, 전체 화면일 때만 잠금이 켜진다고 설명합니다.

```js
await document.documentElement.requestFullscreen()
await screen.orientation.lock('landscape')
screen.orientation.unlock() // 반환값 없음(undefined)
```

| 예외 | 조건 |
|------|------|
| `NotSupportedError` | 요청한 방향을 지원하지 않음 |
| `SecurityError` | 문서가 보이지 않거나, sandbox에 `allow-orientation-lock`이 없음 |
| `AbortError` | 대기 중에 다른 `lock()`이나 `unlock()`이 호출됨 |
| `InvalidStateError` | 문서가 완전히 활성 상태가 아님 |

지원은 Android Chrome과 Firefox 144 이상으로 한정됩니다(2026-10 기준 데이터). 데스크톱 Chrome과 Safari에서는 기대하면 안 됩니다. 잠금이 안 돼도 레이아웃이 깨지지 않게 설계합니다.

## Wake Lock

Screen Wake Lock API는 화면이 꺼지거나 어두워지는 것을 막습니다. Baseline 2025이고 보안 컨텍스트가 필요합니다. 지원하는 유형은 `'screen'` 하나뿐입니다.

```js
let lock = null
lock = await navigator.wakeLock.request('screen')
lock.addEventListener('release', () => {
  console.log(lock.released) // true
})
await lock.release() // 직접 해제
```

`request()`는 `WakeLockSentinel`을 돌려주고, 시스템 사유(절전 모드, 배터리 부족 등)로 거부될 수 있어 `try`·`catch`로 감싸고 `err.name`과 `err.message`로 사유를 확인합니다.

### 해제 시점과 재요청

잠금은 다음 경우 자동으로 풀리고 `release` 이벤트가 발생합니다. 센티널은 한 번 풀리면 재사용되지 않습니다.

- 문서가 숨겨지거나 비활성이 됨(탭 전환, 화면 잠금)
- 절전 모드나 낮은 배터리 같은 시스템 설정
- 플랫폼이 회수

화면이 다시 보일 때 새로 요청합니다.

```js
document.addEventListener('visibilitychange', async () => {
  const visible = document.visibilityState === 'visible'
  if (lock !== null && visible) {
    lock = await navigator.wakeLock.request('screen')
  }
})
```

iframe에는 Permissions-Policy `screen-wake-lock`(기본 허용 범위는 `self`)이 적용됩니다. 문서 가시성은 60편에서 다룹니다.

## Web Share API

`navigator.share()`는 운영체제의 공유 시트를 열어 URL·텍스트·파일을 다른 앱으로 보냅니다. 미Baseline입니다. 이 API가 있는 환경은 Chrome 128 이상 데스크톱, Android의 Chrome과 Firefox, Safari로 데이터상 Firefox 데스크톱은 지원하지 않습니다.

```js
shareBtn.addEventListener('click', async () => {
  try {
    const data = { title: 'MDN', url: location.href }
    await navigator.share(data)
  } catch (e) {
    if (e.name !== 'AbortError') throw e // 취소는 정상
  }
})
```

- 데이터 필드는 `url`, `text`, `title`, `files`이고, 알려진 필드가 하나 이상 있어야 합니다. `title`은 대상 앱이 무시할 수 있습니다.
- 요건: 보안 컨텍스트, 일시적 활성화(클릭 등), Permissions-Policy `web-share`.
- `NotAllowedError`: 정책 차단, 활성화 없음. `TypeError`: 잘못된 데이터나 URL. `AbortError`: 사용자가 취소하거나 공유 대상 없음.

### canShare와 파일 공유

`navigator.canShare(data)`는 같은 데이터를 `share()`가 받아들일지 동기적으로 알려 주는 불리언입니다. 사용자 활성화가 필요 없습니다. 파일 공유는 지원이 환경마다 달라서 `canShare({ files })`로 먼저 확인합니다.

```js
if (navigator.canShare?.({ files })) {
  await navigator.share({ files, title: 'Photos' })
} else {
  // 대체: 링크 복사 버튼 같은 폴백
}
```

`canShare`가 `false`가 되는 경우는 알려진 필드가 없을 때, URL 형식 오류, 파일 공유 미지원, 정책 차단입니다. `navigator.share` 자체가 없는 환경이 있으므로 폴백 UI는 항상 둡니다.

## Gamepad API

게임 컨트롤러 입력을 읽는 API입니다. Baseline 2017입니다. 이벤트로 알려 주는 것은 연결과 해제뿐이고, 버튼·축 상태는 폴링으로 읽습니다.

```js
window.addEventListener('gamepadconnected', (e) => {
  console.log(e.gamepad.id, e.gamepad.index) // 'Xbox ...' 0
})
function loop() {
  const gp = navigator.getGamepads()[0]
  if (gp?.buttons[0].pressed) jump()
  requestAnimationFrame(loop)
}
```

- `navigator.getGamepads()`는 호출 시점의 스냅샷 배열을 돌려주고, 없는 슬롯은 `null`입니다. 한 번 얻은 객체를 계속 쓰지 말고 매 프레임 다시 호출합니다.
- `Gamepad` 필드: `id`, `index`, `connected`, `mapping`, `buttons`, `axes`, `timestamp`.
- `buttons[i]`는 `pressed`(불리언)와 `value`(0–1, 트리거 같은 아날로그 버튼)를 가집니다. `axes`는 –1에서 1 사이 값입니다.
- `mapping`이 `'standard'`면 표준 배치입니다. 아니면 빈 문자열이므로 배치를 가정하지 않습니다.
- Firefox는 이미 연결된 게임패드를 페이지 로드 뒤 버튼을 누르거나 축을 움직여야 `gamepadconnected`로 알립니다.
- 진동 피드백은 `GamepadHapticActuator`(`gamepad.vibrationActuator`)가 맡지만 지원이 제한적입니다.

## Generic Sensor API

가속도계·자이로스코프 같은 센서를 공통 인터페이스로 읽는 API입니다. 미Baseline이며 Chromium 계열이 지원합니다. 자기 센서(`Magnetometer`)와 `AmbientLightSensor`는 데이터상 기본으로 켜진 브라우저가 없습니다.

| 인터페이스 | 값 | 권한 이름 |
|------------|----|-----------|
| `Accelerometer` | 3축 가속도 | `accelerometer` |
| `Gyroscope` | 3축 각속도 | `gyroscope` |
| `Magnetometer` | 자기장 | `magnetometer` |
| `AmbientLightSensor` | 조도 | `ambient-light-sensor` |
| `AbsoluteOrientationSensor` | 지구 기준 방향 | 가속도·자이로·자기 |
| `RelativeOrientationSensor` | 기기 기준 방향 | 가속도·자이로 |
| `GravitySensor`, `LinearAccelerationSensor` | 중력, 중력 제외 가속도 | 가속도계 |

모든 센서는 `Sensor`를 상속하고 같은 사용법을 따릅니다.

```js
const sensor = new Accelerometer({ frequency: 60 })
sensor.addEventListener('reading', () => {
  console.log(sensor.x, sensor.y, sensor.z) // 0.1 9.8 0.3
})
sensor.addEventListener('error', (e) => {
  console.log(e.error.name) // 'NotAllowedError'
})
sensor.start()
```

- 멤버: `start()`, `stop()`, `activated`, `hasReading`, `timestamp`, `reading`·`error` 이벤트.
- `frequency` 옵션은 초당 읽기 횟수입니다. 요청한 값과 실제 값은 다를 수 있습니다.
- 생성자는 차단되면 `SecurityError`(정책), 미지원이면 `ReferenceError`를 던집니다. 비동기 오류는 `error` 이벤트로 오고, `NotAllowedError`(권한)와 `NotReadableError`(센서에 연결 못 함)가 대표적입니다.
- Baseline인 Device Orientation·Motion 이벤트가 같은 정보를 주므로, 교차 브라우저 코드는 그쪽을 씁니다.

## Vibration, Battery Status, Network Information

세 API 모두 미Baseline이고 Chromium 위주입니다. 반드시 기능 검사를 하고 없어도 동작해야 합니다.

| API | 진입점 | 지원 |
|-----|--------|------|
| Vibration | `navigator.vibrate()` | Chromium. Safari·Firefox 미지원 |
| Battery Status | `navigator.getBattery()` | Chromium. Firefox·Safari는 핑거프린팅 우려로 제거 |
| Network Information | `navigator.connection` | Chromium |

### Vibration

```js
navigator.vibrate(200)                  // 200ms 진동
navigator.vibrate([100, 30, 100])       // 진동, 쉼, 진동
navigator.vibrate(0)                    // 취소 (빈 배열도 취소)
```

패턴은 진동과 쉼의 밀리초를 번갈아 적은 배열입니다. 반환값은 불리언이며 잘못된 인수면 `false`입니다. 지속적 사용자 활성화(문서에 이전 입력이 있었음)가 있어야 합니다. 무음·방해 금지 모드에서는 울리지 않을 수 있습니다.

### Battery Status

`getBattery()`는 `BatteryManager`로 이행하는 프라미스를 돌려줍니다. 보안 컨텍스트에서만 쓰고 워커에서는 쓸 수 없습니다.

```js
const b = await navigator.getBattery()
console.log(b.level, b.charging) // 0.82 false
b.addEventListener('levelchange', () => {
  if (b.level < 0.2) pauseAnimations()
})
```

필드는 `charging`, `level`(0–1), `chargingTime`·`dischargingTime`(초)이고 이벤트는 `chargingchange`, `levelchange`, `chargingtimechange`, `dischargingtimechange`입니다.

### Network Information

```js
const c = navigator.connection
if (c && c.effectiveType === 'slow-2g') skipVideoPreload()
c?.addEventListener('change', () => console.log(c.downlink))
```

필드는 `effectiveType`(`slow-2g`, `2g`, `3g`, `4g`), `downlink`(추정 대역폭 Mbps), `rtt`(추정 왕복 시간 ms), `saveData`(데이터 절약 요청), `type`(wifi, cellular 등)입니다. 워커에서도 쓸 수 있습니다. 값은 추정치이므로 로딩 전략의 힌트로만 씁니다(자세히는 66편).

## UA Client Hints와 navigator 속성

`navigator.userAgentData`는 User-Agent 문자열을 대체하려는 구조화된 API입니다. 미Baseline이며 Chromium 계열만 지원합니다.

```js
const u = navigator.userAgentData
console.log(u.brands, u.mobile, u.platform)
// [{ brand: 'Chromium', version: '154' }] false 'Windows'
const hi = await u.getHighEntropyValues(['platformVersion'])
```

- 낮은 엔트로피(`brands`, `mobile`, `platform`)는 바로 읽습니다.
- 높은 엔트로피(`architecture`, `model`, `platformVersion`, `fullVersionList`)는 `getHighEntropyValues()`로 명시 요청합니다. Permissions-Policy `ch-ua-high-entropy-values`로 막히면 낮은 엔트로피 값만 옵니다.
- 서버는 요청 헤더 `Sec-CH-UA`와 `Accept-CH`로 같은 정보를 주고받습니다.
- 브라우저 이름으로 분기하지 말고 기능 검사를 우선합니다(자세히는 71편).

기기 성능을 어림하는 속성도 있습니다.

| 속성 | 뜻 | 지원 |
|------|----|------|
| `navigator.hardwareConcurrency` | 논리 프로세서 수 | Baseline 2022 |
| `navigator.deviceMemory` | 메모리 GB의 대략값(2의 거듭제곱으로 올림·내림, 구현이 범위를 제한) | Chromium, 보안 컨텍스트 |

둘 다 핑거프린팅 방지를 위해 값이 거칠게 가려집니다. 정확한 사양 판정이 아니라 부하를 줄일지 정하는 힌트로 씁니다.

## Pointer Lock과 Keyboard Lock

### Pointer Lock

`element.requestPointerLock()`은 포인터를 요소에 고정해 커서를 숨기고, 화면 경계에 막히지 않는 상대 이동량을 줍니다. 3D 게임 시점 조작에 씁니다. 미Baseline입니다.

```js
canvas.addEventListener('click', async () => {
  await canvas.requestPointerLock({
    unadjustedMovement: true,
  })
})
document.addEventListener('mousemove', (e) => {
  if (document.pointerLockElement === canvas) {
    yaw += e.movementX // 이전 이벤트 대비 이동량
  }
})
```

- 잠긴 동안 `clientX`·`screenX`는 고정되고 `movementX`·`movementY`만 변합니다.
- 사용자 활성화가 필요하고, 사용자가 Esc로 해제할 수 있습니다. 해제는 `document.exitPointerLock()`입니다.
- 상태 변화는 `pointerlockchange`, 실패는 `pointerlockerror` 이벤트입니다. `document.pointerLockElement`가 현재 잠근 요소입니다.
- `unadjustedMovement: true`는 운영체제의 포인터 가속을 끄고 원시 입력을 요청합니다.
- 한 번에 iframe 하나만 잠글 수 있고, sandbox된 iframe에는 `allow-pointer-lock`이 필요합니다.

### Keyboard Lock

`navigator.keyboard.lock()`은 브라우저나 운영체제가 가로채는 키(예: Esc, 단축키)를 페이지가 받게 합니다. 미Baseline이고 Chromium 계열만 지원하며, 보안 컨텍스트와 일시적 활성화가 필요합니다.

```js
const keys = ['KeyW', 'KeyA', 'KeyS', 'KeyD']
await navigator.keyboard.lock(keys)
// 인수를 생략하면 모든 키
navigator.keyboard.unlock()
```

`code` 값은 키 배치와 무관한 물리 키 이름입니다(자세히는 10편). 최상위 브라우징 컨텍스트에서만 호출할 수 있고(아니면 `InvalidStateError`), 잘못된 코드는 `InvalidAccessError`, 호출이 겹치면 `AbortError`입니다.

## 하드웨어 API 개요

주변 장치에 직접 연결하는 API들은 모두 미Baseline이고 Chromium 위주입니다. 보안 컨텍스트가 필요하고, 사용자가 브라우저의 장치 선택 창에서 장치를 고르는 방식이 공통입니다. 선택은 `requestDevice()` 계열 호출에서 일어나며 일시적 활성화 안에서 호출해야 합니다.

| API | 진입점 | 대상 | 지원(데이터 기준) |
|-----|--------|------|-------------------|
| Web Bluetooth | `navigator.bluetooth.requestDevice()` | BLE 장치(GATT) | Chromium |
| WebUSB | `navigator.usb.requestDevice()` | USB 장치 | Chromium |
| Web Serial | `navigator.serial.requestPort()` | 시리얼 포트 | Chromium, Firefox 151 이상 |
| WebHID | `navigator.hid.requestDevice()` | HID 장치 | Chromium |
| Web MIDI | `navigator.requestMIDIAccess()` | MIDI 입출력 | Chromium, Firefox 108 이상 |
| Web NFC | `NDEFReader` | NFC 태그 읽기·쓰기 | Android Chrome |

- 권한은 장치 단위로 저장되고, Bluetooth는 `getDevices()`로 이미 허용한 장치를 다시 얻습니다. Permissions-Policy 지시어 `bluetooth`, `usb`, `serial`, `midi`가 iframe을 제어합니다.
- Bluetooth는 GATT 계층(서버, 서비스, 특성, 디스크립터)으로 데이터를 읽고 씁니다.
- Web MIDI는 `sysex` 옵션을 요청해야 시스템 전용 메시지를 보낼 수 있습니다.
- USB와 Serial은 워커에서도 쓸 수 있습니다. Bluetooth는 워커에서 쓸 수 없습니다.
- 선택 창이 필수라서 페이지가 장치를 몰래 훑을 수 없습니다. 장치가 없는 환경의 폴백(수동 입력 등)을 둡니다.

## 기타 장치 API 개요

모두 미Baseline이며 다음은 지원이 Chromium 계열에 한정됩니다(Contact Picker는 Android Chrome).

| API | 진입점 | 하는 일 |
|-----|--------|---------|
| Idle Detection | `IdleDetector` | 사용자의 유휴와 화면 잠금 감지 |
| EyeDropper | `new EyeDropper().open()` | 화면의 색을 골라 `sRGBHex` 반환 |
| Contact Picker | `navigator.contacts.select()` | 연락처 선택 |
| Local Font Access | `window.queryLocalFonts()` | 설치된 글꼴 목록 |
| Window Management | `window.getScreenDetails()` | 다중 모니터 정보와 창 배치 |
| Compute Pressure | `PressureObserver` | CPU 부하 상태 관찰 |

- Idle Detection은 `IdleDetector.requestPermission()`을 활성화 안에서 호출해 허용받은 뒤 `start({ threshold, signal })`로 시작합니다. `userState`는 `active` 또는 `idle`, `screenState`는 화면 잠금 여부이며 변하면 `change` 이벤트입니다.
- EyeDropper는 사용자 활성화가 필요하고, 사용자가 색을 클릭해야 프라미스가 이행되며 Esc로 취소합니다. `AbortSignal`도 받습니다.
- Contact Picker는 `getProperties()`로 지원 필드(`name`, `email`, `tel`, `address`, `icon`)를 확인하고 `{ multiple: true }` 옵션으로 여러 명을 고릅니다. 호출마다 사용자 선택이 필요하고 워커에서는 쓸 수 없습니다.
- Local Font Access는 `local-fonts` 권한이 필요하며 각 `FontData`는 `family`, `fullName`, `postscriptName`, `style`과 글꼴 바이트를 주는 `blob()`을 가집니다.
- Window Management는 `window-management` 권한이 필요합니다. 거부되면 `getScreenDetails()`는 `NotAllowedError`로 거부되고 `screen.isExtended`는 `false`입니다.
- Compute Pressure는 `observe('cpu', { sampleInterval })`로 시작하고 상태는 `nominal`, `fair`, `serious`, `critical` 네 단계입니다. 서비스 워커에서는 쓸 수 없습니다.

## 폴더블 화면

접히는 기기의 화면 분할과 접힘 상태를 다룹니다. 두 API 모두 미Baseline이며 Chromium 계열이 지원합니다.

| API | 진입점 | 값 |
|-----|--------|----|
| Viewport Segments | `window.viewport.segments`, 미디어 쿼리 `horizontal-viewport-segments`·`vertical-viewport-segments`, `env(viewport-segment-*)` | 각 분할 영역의 사각형 |
| Device Posture | `navigator.devicePosture.type`, 미디어 쿼리 `device-posture` | `continuous`(펼침·단일 화면), `folded`(접힘) |

```css
@media (horizontal-viewport-segments: 2) {
  .layout { display: grid; grid-template-columns: 1fr 1fr; }
}
@media (device-posture: folded) {
  .player { height: 50vh; }
}
```

`navigator.devicePosture`는 접힘 상태가 바뀔 때 `change` 이벤트를 냅니다. 일반 기기에서는 분할이 하나이고 자세가 `continuous`이므로 기본 레이아웃은 그대로 동작하게 두고, 폴더블에서만 보강합니다.

## 언어와 환경 속성

`navigator`에서 읽는 사용자 환경 값입니다.

| 속성·이벤트 | 뜻 |
|-------------|----|
| `navigator.language` | 선호 언어 하나(브라우저 UI 언어). 알 수 없으면 `null` |
| `navigator.languages` | 선호 언어 배열(우선순위 순) |
| `languagechange` 이벤트 | 선호 언어가 바뀌면 전역 객체에서 발생. Baseline 널리 지원 |
| `navigator.cookieEnabled` | 쿠키 설정이 무시되면 `false`. Baseline 2024 |
| `navigator.pdfViewerEnabled` | 브라우저가 PDF를 인라인으로 보여 주면 `true`. Baseline 2023 |

```js
console.log(navigator.languages) // ['ko-KR', 'ko', 'en-US']
addEventListener('languagechange', () => {
  console.log(navigator.language) // 'en-US'
})
```

- 언어 값은 `Intl` 로케일 선택의 입력으로 쓰고, 바뀌면 `languagechange`에서 다시 포맷합니다.
- `cookieEnabled`가 `true`여도 서드파티 쿠키 제한이나 저장소 정책으로 쿠키가 실제로 저장되지 않을 수 있습니다. 쿠키 자체는 40편에서 다룹니다.
- `pdfViewerEnabled`가 `false`면 PDF를 `iframe`·`embed`로 보여 주지 말고 다운로드 링크를 줍니다.

## 핵심 정리

- 장치 API는 보안 컨텍스트, 권한, 사용자 활성화를 요구하고 기능 검사 뒤 점진적 향상으로 씁니다.
- Baseline인 것은 Geolocation, Device Orientation·Motion(2023), Screen Orientation 읽기(2023), Wake Lock(2025), Gamepad(2017)이며, 나머지 대부분은 Chromium 위주입니다.
- 위치 오류는 코드 1(거부), 2(얻지 못함), 3(시간 초과)이고, `watchPosition`은 `clearWatch`로 반드시 중단합니다.
- Wake Lock 센티널은 문서가 숨겨지면 풀리므로 `visibilitychange`에서 새로 요청합니다. iOS는 방향·모션 이벤트에 `requestPermission()`이 필요합니다.
- `share()`는 활성화 안에서 호출하고 취소(`AbortError`)를 정상 흐름으로 다루며, 파일은 `canShare()`로 먼저 확인합니다.
- 블루투스·USB·시리얼·HID 같은 하드웨어 API는 장치 선택 창을 거치며 지원이 제한적입니다.
