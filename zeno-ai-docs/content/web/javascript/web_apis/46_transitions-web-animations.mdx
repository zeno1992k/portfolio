## CSS Transition

CSS Transition은 속성 값이 바뀔 때 새 값으로 즉시 바꾸지 않고 정해진 시간 동안 중간 값을 채워 넣는 기능입니다. 시작과 끝 두 값만 있고, 시작은 스타일이 바뀌는 사건이 계기입니다.

```css
.btn {
  opacity: 1;
  transition: opacity 0.3s ease 0s;
}
.btn:hover { opacity: 0.6; }
```

| 속성 | 기본값 | 역할 |
|------|--------|------|
| `transition-property` | `all` | 전환할 속성 |
| `transition-duration` | `0s` | 걸리는 시간 |
| `transition-timing-function` | `ease` | 시간에 따른 진행 곡선 |
| `transition-delay` | `0s` | 시작 전 대기 |
| `transition-behavior` | `normal` | `allow-discrete`면 이산 속성도 전환 |

단축형 `transition`에서 시간 값이 두 개면 첫째가 duration, 둘째가 delay입니다. 쉼표로 속성마다 다른 값을 줍니다.

- 전환은 한 요소의 계산된 값이 이전과 달라질 때 시작합니다. 처음 렌더링되는 요소에는 이전 값이 없어 전환이 일어나지 않습니다(아래 `@starting-style` 절).
- duration과 delay를 더한 값이 0 이하이면 전환은 시작되지 않고 이벤트도 없습니다(CSS Transitions 표준).
- 값 목록의 길이가 `transition-property`보다 짧으면 반복해서 맞추고, 길면 잘라냅니다.
- 진행 중에 원래 값으로 되돌리면 현재 값에서 원래 값으로 가는 새 전환이 시작됩니다. 되돌릴 때는 남은 거리에 비례해 시간이 줄어듭니다(reversing shortening).
- `height: auto` 같은 키워드와 길이 사이는 보간되지 않습니다. `interpolate-size: allow-keywords`가 이를 허용하지만 Chrome·Edge 129에서만 지원합니다(Baseline 아님).
- `transform`과 `opacity`는 레이아웃을 일으키지 않아 비용이 낮습니다(자세히는 66편).
- Baseline 2018부터 널리 지원됩니다.

**흔한 실수:** `transition: all`로 의도하지 않은 속성까지 전환하는 것, 그리고 DOM에 넣은 직후 클래스를 바꿔 전환이 시작되지 않는 것입니다(아래 "Enter / Leave Transition").

## CSS Animation

CSS Animation은 `@keyframes`로 중간 단계를 정의하고 `animation` 속성으로 요소에 적용하는 기능입니다. 전환과 달리 속성 변화 없이 시작할 수 있고 단계가 여럿이며 반복할 수 있습니다.

```css
@keyframes fade-in {
  from { opacity: 0; }
  to { opacity: 1; }
}
.toast {
  animation: fade-in 0.3s ease-out both;
}
```

| 속성 | 의미 |
|------|------|
| `animation-name` | 적용할 `@keyframes` 이름 |
| `animation-duration`, `animation-delay` | 한 번의 길이, 시작 전 대기 |
| `animation-timing-function` | 진행 곡선 |
| `animation-iteration-count` | 반복 횟수, `infinite` 가능 |
| `animation-direction` | `normal`, `reverse`, `alternate`, `alternate-reverse` |
| `animation-fill-mode` | `none`(기본), `forwards`, `backwards`, `both` |
| `animation-play-state` | `running`, `paused` |
| `animation-composition` | 같은 속성의 다른 값과 합치는 방식(Baseline 2023) |
| `animation-timeline` | 진행도를 정하는 타임라인(스크롤 기반 절) |

- `fill-mode`가 `none`이면 애니메이션 전후에 요소는 원래 스타일로 돌아갑니다. `forwards`는 마지막 키프레임을 유지하고 `backwards`는 delay 동안 첫 키프레임을 적용합니다.
- `forwards`로 유지되는 속성은 `will-change`가 걸린 것처럼 동작해 스태킹 컨텍스트가 계속 남을 수 있습니다.
- 애니메이션 값은 일반 스타일 선언보다 우선합니다. 끝난 뒤에도 `forwards`가 값을 쥐고 있으면 다른 스타일로 덮어쓸 수 없습니다.
- 속성이 여러 개일 때 값 목록이 모자라면 반복해서 맞춥니다. 쉼표로 여러 애니메이션을 한 요소에 겁니다.
- `from`과 `to`는 `0%`와 `100%`의 별칭이고 중간은 퍼센트로 씁니다.

| 비교 | Transition | Animation |
|------|-----------|-----------|
| 시작 | 속성 값 변화 | 적용되는 순간부터 |
| 단계 | 시작과 끝 | 키프레임 여러 개 |
| 반복 | 없음 | `animation-iteration-count` |
| 중간 정지·되감기 | CSS만으로는 어려움 | `animation-play-state`, WAAPI |

Baseline 2018부터 널리 지원됩니다.

## 전환·애니메이션 이벤트

전환과 애니메이션은 진행 단계를 이벤트로 알립니다. 둘 다 버블링합니다.

| 전환 이벤트 | 애니메이션 이벤트 | 발생 시점 |
|-------------|-------------------|-----------|
| `transitionrun` | (없음) | 전환이 생성될 때, delay 이전 |
| `transitionstart` | `animationstart` | delay가 끝나고 실제로 시작될 때 |
| (없음) | `animationiteration` | 반복 한 번이 끝나고 다음 반복이 시작될 때 |
| `transitionend` | `animationend` | 끝났을 때 |
| `transitioncancel` | `animationcancel` | 중단됐을 때 |

- `transitionend`는 속성 하나마다 발생합니다. 여러 속성이 전환되면 여러 번 오므로 `e.propertyName`으로 거른 속성이 맞는지 확인합니다. 애니메이션 이벤트는 `e.animationName`으로 구분합니다.
- 이벤트가 버블링하므로 자식의 이벤트가 부모의 리스너에도 도착합니다. `e.target === el`을 확인합니다.
- `elapsedTime`은 초 단위이고 delay는 포함하지 않습니다.
- 값이 이미 목표와 같거나 duration이 0이면 전환이 생기지 않아 `transitionend`가 오지 않습니다. 요소에 `display: none`이 적용되거나 전환 도중 속성 값이 바뀌면 `transitionend` 대신 `transitioncancel`이 옵니다. 요소가 문서에서 제거되어도 진행 중인 전환은 취소됩니다.
- `animation-iteration-count: infinite`는 `animationend`가 오지 않습니다.

```js
el.addEventListener('transitionend', (e) => {
  if (e.target !== el) return
  if (e.propertyName === 'opacity') el.remove()
})
```

**흔한 실수:** 이벤트가 반드시 온다고 믿고 `remove()`나 다음 단계를 이벤트에만 맡기는 것입니다. 위의 중단·무전환 경로에서는 이벤트가 오지 않아 요소가 영영 남습니다. 대기 방법으로는 Animation 객체의 `finished`가 더 안전합니다(아래 "Enter / Leave Transition").

## requestAnimationFrame

`requestAnimationFrame(callback)`은 다음 화면 갱신 직전에 콜백을 한 번 호출해 달라고 브라우저에 요청합니다. 매 프레임 값을 JS로 계산해야 하는 경우(캔버스 그리기, 물리 시뮬레이션, 스크롤 연동 수치)에 씁니다. 콜백은 이벤트 루프의 렌더링 갱신 단계에서 스타일·레이아웃 계산 전에 실행됩니다(자세히는 8편).

```js
let start, id
function step(now) {
  start ??= now
  const t = Math.min((now - start) / 300, 1)
  box.style.transform = `translateX(${t * 200}px)`
  if (t < 1) id = requestAnimationFrame(step)
}
id = requestAnimationFrame(step)
```

- 콜백의 인수 `now`는 `DOMHighResTimeStamp`이고 같은 프레임의 모든 콜백이 같은 값을 받습니다.
- 한 번만 호출됩니다. 이어 가려면 콜백 안에서 다시 요청합니다.
- 요청의 반환값(숫자 ID)으로 `cancelAnimationFrame(id)`를 호출해 취소합니다.
- 호출 빈도는 화면 주사율을 따르고(60Hz, 120Hz 등) 백그라운드 탭과 숨겨진 `iframe`에서는 멈춥니다.
- 진행도는 반드시 `now`로 계산합니다. 프레임 수를 세면 주사율이 높은 화면에서 더 빨라집니다.
- 워커 안에서도 쓸 수 있습니다(Baseline 2023, 자세히는 54편). Baseline 2015부터 널리 지원됩니다.

DOM 읽기와 쓰기가 한 콜백에서 섞이면 매번 레이아웃이 강제됩니다. 읽기를 먼저 모으고 쓰기를 나중에 합니다(자세히는 6편).

**흔한 실수:** 선언만으로 되는 효과(색·불투명도 전환)를 rAF로 구현하는 것, 컴포넌트가 제거된 뒤에도 루프가 계속 도는 것입니다. 루프는 정리 시점에 `cancelAnimationFrame`으로 끊습니다.

## Web Animations API

Web Animations API(WAAPI)는 CSS 애니메이션과 같은 엔진을 JS로 만들고 제어하는 API입니다. `element.animate(keyframes, options)`가 `Animation` 객체를 돌려주고 호출 즉시 재생을 시작합니다. Baseline 2020, 널리 지원됩니다.

```js
const anim = box.animate(
  [
    { opacity: 0, transform: 'translateY(8px)' },
    { opacity: 1, transform: 'none' },
  ],
  { duration: 200, easing: 'ease-out', fill: 'both' },
)
```

키프레임은 두 형식이 있습니다.

```js
// 배열: 키프레임 객체의 목록
[{ opacity: 0 }, { opacity: 1 }]
// 객체: 속성별 값의 배열
{ opacity: [0, 1], transform: ['none', 'scale(1.1)'] }
```

| 옵션 | 기본값 | 의미 |
|------|--------|------|
| `duration` | `0` | 길이(ms). 숫자 하나만 주면 duration |
| `delay`, `endDelay` | `0` | 시작 전, 종료 후 대기 |
| `iterations` | `1` | 반복 횟수 |
| `direction` | `normal` | 진행 방향 |
| `easing` | `linear` | 진행 곡선 |
| `fill` | `none` | 전후 상태 유지 |
| `composite` | `replace` | 기존 값과 합치는 방식 |
| `id` | 없음 | 식별용 이름 |
| `timeline` | 문서 타임라인 | 진행도를 정하는 타임라인 |

- 옵션 이름은 CSS 속성과 비슷하지만 접두사가 없고 camelCase입니다. 값의 단위는 밀리초입니다.
- WAAPI의 기본 `easing`은 `linear`입니다. CSS 전환의 기본 `ease`와 다르므로 같은 느낌을 내려면 명시합니다.
- 기본 `fill`이 `none`이라 끝나면 원래 스타일로 되돌아갑니다. 최종 상태를 남기려면 `fill: 'forwards'`를 쓰거나 `commitStyles()`로 확정합니다(아래 절).
- 기본 `duration`이 `0`이라서 지정하지 않으면 즉시 끝납니다.
- CSS보다 나은 점: 값을 JS로 동적으로 계산할 수 있고, 일시정지·되감기·속도 조절이 되며, 완료를 Promise로 기다릴 수 있습니다.

## Animation 객체

`animate()`가 돌려주는 `Animation` 객체는 재생 상태를 읽고 제어하는 핸들입니다.

| 멤버 | 설명 |
|------|------|
| `playState` | `idle`, `running`, `paused`, `finished` |
| `pending` | 재생·일시정지가 아직 시작되지 않았으면 `true` |
| `ready` | 재생 준비가 끝나면 이행되는 Promise |
| `finished` | 끝나면 이행되는 Promise |
| `playbackRate` | 재생 속도. 음수면 거꾸로 |
| `currentTime`, `startTime` | 현재 재생 위치(ms), 시작 시각 |
| `effect`, `timeline` | 효과(대개 `KeyframeEffect`), 연결된 타임라인 |
| `id` | 식별용 이름 |

| 메서드 | 동작 |
|--------|------|
| `play()` | 재생·재개. 끝났으면 처음부터 |
| `pause()` | 일시정지 |
| `reverse()` | 방향을 뒤집어 재생. 끝났거나 시작 전이면 끝에서 시작으로 |
| `finish()` | 진행 방향의 끝으로 이동 |
| `cancel()` | 효과를 모두 제거하고 중단 |
| `updatePlaybackRate(n)` | 재생 위치를 맞춘 뒤 속도 변경 |
| `commitStyles()`, `persist()` | 스타일 확정, 자동 제거 방지(아래 절) |

이벤트는 `finish`, `cancel`, `remove`가 있습니다.

```js
const a = el.animate({ opacity: [0, 1] }, 300)
await a.ready        // 재생이 실제로 시작됨
a.playbackRate = 2   // 2배속
a.reverse()          // 방향 뒤집기
try { await a.finished } catch { /* AbortError: cancel됨 */ }
```

- `ready`는 비동기로 예약된 재생·일시정지가 실제로 시작될 때 이행됩니다.
- `finished`는 현재 상태에 대한 Promise라서 다시 `play()`하면 새 Promise가 만들어집니다.
- `cancel()`을 호출하면 `finished`가 `AbortError`로 거부됩니다. `await`한 코드는 예외를 받습니다.
- `reverse()`는 진행 중에도 현재 위치에서 방향만 바꿔 되돌아갑니다. 열고 닫기 토글에 알맞습니다.
- `playbackRate`를 바로 바꾸면 위치가 어긋날 수 있어 속도 변화가 부드러워야 하면 `updatePlaybackRate()`를 씁니다.

**흔한 실수:** `await anim.finished`만 쓰고 `cancel()` 경로를 처리하지 않아 예외가 위로 번지는 것입니다. 취소가 정상 흐름이면 `try`/`catch`나 `Promise.allSettled`로 받습니다.

## KeyframeEffect와 composite

`KeyframeEffect`는 대상 요소, 키프레임, 타이밍을 묶은 효과 객체입니다. `animate()`는 내부에서 이를 만들어 `Animation`에 연결합니다. 직접 만들면 효과를 따로 보관하고 갱신할 수 있습니다.

```js
const effect = new KeyframeEffect(
  box,
  { transform: ['translateX(0)', 'translateX(200px)'] },
  { duration: 1000, iterations: Infinity },
)
const anim = new Animation(effect, document.timeline)
anim.play()
```

- `new KeyframeEffect(source)`로 기존 효과를 복사합니다.
- 속성: `target`, `pseudoElement`, `composite`. 메서드: `getKeyframes()`, `setKeyframes()`, `getTiming()`, `updateTiming()`, `getComputedTiming()`. 재생 중에도 키프레임과 타이밍을 바꿀 수 있습니다.

`composite`는 애니메이션 값을 요소의 원래 값(underlying value) 위에 어떻게 합칠지 정합니다. 예로 효과의 값이 `blur(2)`, 원래 값이 `blur(3)`일 때 결과는 다음과 같습니다.

| 값 | 의미 | 결과 |
|----|------|------|
| `replace` (기본) | 원래 값을 덮어씀 | `blur(2)` |
| `add` | 원래 값 뒤에 덧붙임 | `blur(2) blur(3)` |
| `accumulate` | 같은 종류의 값을 합산 | `blur(5)` |

```js
// el의 transform이 translateX(100px)일 때
el.animate(
  { transform: ['translateX(0)', 'translateX(50px)'] },
  { duration: 300, composite: 'add' },
) // 100px에서 150px까지 (원래 위치 기준으로 이동)
```

- 기본 `replace`는 원래 위치를 덮어써 애니메이션이 원래 위치를 무시하고 시작합니다. 기존 값에서 상대적으로 움직이려면 `add`를 씁니다.
- 한 요소에 여러 애니메이션이 같은 속성을 건드릴 때 우선순위와 합성은 이 값이 정합니다. CSS의 `animation-composition`이 같은 역할을 합니다.
- `iterationComposite`(반복마다 값을 누적)는 Baseline이 아닙니다(Firefox 80, Safari 16.4).

## document.getAnimations()와 commitStyles()

`getAnimations()`는 지금 영향을 주고 있거나 곧 영향을 줄 애니메이션의 목록을 돌려줍니다. CSS 애니메이션, CSS 전환, WAAPI 애니메이션이 모두 `Animation` 객체로 포함됩니다.

```js
document.getAnimations()                 // 문서 전체
el.getAnimations()                       // 이 요소
el.getAnimations({ subtree: true })      // 후손과 의사 요소까지
el.getAnimations({ pseudoElement: '::after' })
```

- 호출하면 보류 중인 스타일 변경을 먼저 반영하므로 방금 클래스를 바꿔 시작된 전환도 목록에 들어갑니다(Web Animations 표준).
- 목록은 효과 스택의 합성 순서로 정렬됩니다. 끝났고 `fill`도 없는 애니메이션은 포함되지 않습니다.
- 용도: 모든 애니메이션 일시정지·취소, 끝날 때까지 대기, 디버깅.

```js
const all = el.getAnimations({ subtree: true })
await Promise.allSettled(all.map((a) => a.finished))
el.remove()
```

`commitStyles()`는 애니메이션이 지금 만들어 내는 값을 요소의 인라인 `style`에 기록합니다. 애니메이션이 끝나거나 취소된 뒤에도 최종 상태를 유지하고 싶을 때 씁니다.

```js
const a = el.animate({ transform: 'translateX(100px)' },
  { duration: 500, fill: 'forwards' })
await a.finished
a.commitStyles() // 인라인 style에 확정
a.cancel()       // 애니메이션 제거. 값은 인라인으로 남음
```

- `fill: 'forwards'`를 그대로 두면 애니메이션이 일반 스타일보다 우선해 이후의 스타일 변경이 먹지 않습니다. 확정한 뒤 `cancel()`로 애니메이션을 걷어 냅니다.
- 새 브라우저는 `fill` 없이도 끝난 애니메이션을 자동으로 제거하고 `commitStyles()`가 동작하지만 이를 감지할 방법이 없어 `fill`을 함께 쓰는 편이 호환됩니다.
- 확정된 값은 평범한 인라인 스타일이므로 이후 다른 스타일로 바꿀 수 있습니다.

## @starting-style과 display 전환

`@starting-style`은 요소가 처음 스타일을 받을 때의 시작 값을 정해 전환을 가능하게 합니다. 전환은 이전 값이 있어야 시작되는데 새로 DOM에 들어온 요소나 `display: none`에서 보이게 된 요소에는 이전 값이 없기 때문입니다. Baseline 2024입니다.

```css
.panel {
  opacity: 1;
  transition: opacity 0.3s;
  @starting-style { opacity: 0; }
}
```

- 시작 스타일이 쓰이는 때: 처음 렌더링, `display: none`에서 보이는 값으로 변경, DOM에 새로 추가. 시작 스타일은 한 번만 쓰이고 이후에는 일반 스타일로 오갑니다.
- 특이도는 일반 규칙과 같아서 같은 선택자의 일반 규칙 뒤에 놓아야 이깁니다. 위처럼 규칙 안에 중첩해도 되고 최상위 `@starting-style { 선택자 { ... } }`로 써도 됩니다.

`display`와 `content-visibility`는 중간 값이 없는 이산 속성이라 기본적으로는 전환되지 않습니다(전환 중간 지점에서 값이 바뀝니다). `transition-behavior: allow-discrete`를 주면 전환 대상이 되고, `none`으로 가거나 `none`에서 오는 경우는 보이는 구간 내내 유지되도록 처리됩니다(Baseline 2024).

```css
.panel {
  transition: opacity 0.3s, display 0.3s allow-discrete;
}
.panel.closed { opacity: 0; display: none; }
```

- 위 코드는 닫힐 때 불투명도가 0이 되는 동안 `display`가 마지막에 `none`으로 바뀌어 퇴장 전환이 보입니다.
- top layer 요소(popover, 모달 `dialog`)의 퇴장에는 `overlay`도 이산 전환 대상에 넣어야 전환이 끝날 때까지 top layer에 남습니다. `overlay`는 Chrome·Edge 117에서만 지원합니다.
- `display` 값 자체의 애니메이션은 Baseline이 아닙니다(Chrome·Edge 117, Safari 18. web-features 기준).

## Enter / Leave Transition

진입(enter)은 요소가 DOM에 들어올 때, 퇴장(leave)은 DOM에서 나갈 때 주는 효과입니다. 진입에는 "이전 스타일이 없다", 퇴장에는 "요소가 즉시 사라진다"는 어려움이 있습니다.

진입 방법은 세 가지입니다.

```js
// 1. @starting-style: CSS만으로 진입 (가장 단순)
// 2. WAAPI: 이전 스타일이 필요 없음
list.append(item)
item.animate({ opacity: [0, 1] }, 200)
// 3. 클래스: 삽입 후 스타일 계산이 한 번 끝나야 전환이 시작됨
list.append(item)
item.getBoundingClientRect() // 강제 스타일 계산
item.classList.add('entered')
```

퇴장은 효과가 끝난 뒤에 제거합니다. 이벤트 대신 Animation의 `finished`를 기다리면 전환·애니메이션·WAAPI에 모두 통합니다.

```js
async function leave(el) {
  el.classList.add('leaving')
  await Promise.allSettled(
    el.getAnimations().map((a) => a.finished),
  )
  el.remove()
}
```

- 애니메이션이 하나도 없으면 목록이 비어 즉시 이행되어 바로 제거합니다. `transitionend`에 의존하면 이 경우 영영 오지 않습니다.
- `allSettled`는 취소로 거부된 애니메이션도 기다림을 끝내 줍니다.
- 퇴장 도중 같은 요소가 다시 필요해지면(재진입) 제거를 막아야 합니다. 퇴장 중임을 표시하는 플래그를 두거나, 진행 중 애니메이션을 `cancel()`하고 상태를 되돌립니다.
- 목록에서 항목이 빠질 때 남은 항목이 위치를 옮기는 효과(레이아웃 애니메이션)는 47편에서 다룹니다.

## 상태 기반 Animation

상태 기반 애니메이션은 "어떻게 움직이라"를 JS가 지시하지 않고 컴포넌트의 상태(`open`, `closed`, `loading`)에 따른 모습을 정의해 두고 상태가 바뀌면 그 사이를 전환하게 하는 설계입니다. 상태가 중간에 바뀌어도 현재 위치에서 새 상태로 이어지므로 중단 처리가 따로 필요 없습니다.

```css
.panel { opacity: 0; translate: 0 8px; }
.panel[data-state='open'] { opacity: 1; translate: 0 0; }
.panel { transition: opacity 0.2s, translate 0.2s; }
```

```js
panel.dataset.state = open ? 'open' : 'closed'
```

- JS는 상태 속성만 바꾸고 모양과 시간은 CSS가 정합니다. 상태를 외부 속성(`data-state`, `aria-expanded`, `hidden`)에 두면 스타일링과 접근성이 같은 신호를 씁니다(상태 설계는 31편).
- 열림 중에 닫기가 오면 전환이 현재 값에서 되돌아갑니다. JS로 제어해야 하면 WAAPI의 `reverse()`가 같은 성질을 줍니다.

```js
let anim
function toggle() {
  if (!anim) {
    anim = panel.animate({ opacity: [0, 1] },
      { duration: 200, fill: 'both' })
  } else {
    anim.reverse() // 진행 중이어도 현재 위치에서 방향 전환
  }
}
```

- 상태가 둘 이상일 때는 상태별 최종 모습만 정의하고 전환 사이를 일일이 쓰지 않습니다.
- 애니메이션이 끝나기 전에 상태를 읽는 코드가 있다면 "상태"와 "화면이 그 상태에 도달함"을 구분합니다. 후자는 `finished`로 압니다.

## Animation 취소 / 정리

애니메이션은 시작보다 끝낼 때의 처리가 어렵습니다. 취소, 완료 후 스타일 처리, 컴포넌트 제거 시 정리 세 가지를 챙깁니다.

- `cancel()`은 효과를 제거하고 요소를 원래 스타일로 즉시 돌립니다. `playState`가 `idle`이 되고 `cancel` 이벤트가 발생하며 `finished`는 `AbortError`로 거부됩니다.
- `finish()`는 끝 상태로 건너뜁니다. 사용자가 애니메이션을 건너뛰게 할 때 쓰고, `cancel()`처럼 처음 상태로 돌리지 않습니다.
- 끝난 `fill` 애니메이션은 스타일을 계속 쥡니다. `commitStyles()` 후 `cancel()`하거나 `fill`을 쓰지 않고 최종 값을 CSS로 직접 적용합니다.
- 같은 속성을 더 늦게 만든 애니메이션이 가리는 끝난 애니메이션은 브라우저가 자동으로 제거하고 `remove` 이벤트를 발생시킵니다. 유지하려면 `persist()`를 부릅니다(`replaceState`로 상태를 읽습니다).
- 연속 트리거에서는 새 애니메이션을 만들기 전에 이전 것을 `cancel()`하거나 `reverse()`로 재사용합니다. 그렇지 않으면 같은 속성을 두고 애니메이션이 쌓입니다.

```js
class Panel extends HTMLElement {
  #anim
  #raf
  disconnectedCallback() {
    this.#anim?.cancel()
    cancelAnimationFrame(this.#raf)
  }
}
```

- 요소가 문서에서 빠지면 CSS 전환은 자동으로 취소되지만 WAAPI에서 만든 `finished` 대기와 rAF 루프, 타이머는 직접 정리해야 합니다(자세히는 18편, 67편).
- `AbortSignal`과 묶으면 일괄 정리가 쉽습니다.

```js
signal.addEventListener(
  'abort', () => anim.cancel(), { once: true },
)
```

**흔한 실수:** `finished`를 `await`하는 함수가 취소 후 다음 단계(`remove()`, 상태 갱신)를 계속 실행하는 것입니다. 취소된 경로에서는 그 단계를 건너뛰어야 하는지 따져 봅니다.

## 스크롤 기반 애니메이션

스크롤 기반 애니메이션은 시간 대신 스크롤 위치를 진행도로 삼는 애니메이션입니다. 타임라인이 두 종류입니다.

| 타임라인 | 진행도의 기준 | 용도 |
|----------|---------------|------|
| `ScrollTimeline` | 스크롤 컨테이너의 스크롤 위치 | 읽기 진행 막대, 시차 효과 |
| `ViewTimeline` | 요소가 스크롤 영역에 보이는 정도 | 화면에 들어올 때 나타나는 효과 |

CSS에서는 `animation-timeline`에 `scroll()` 또는 `view()`를 줍니다. `animation-range`로 구간을 정합니다(`entry`, `cover`, `exit`).

```css
.bar {
  animation: grow linear both;
  animation-timeline: scroll(root block);
}
.card {
  animation: reveal linear both;
  animation-timeline: view();
  animation-range: entry 0% cover 40%;
}
```

JS에서는 타임라인 객체를 만들어 `animate()`의 `timeline` 옵션에 줍니다.

```js
const tl = new ViewTimeline({
  subject: card, axis: 'block',
})
card.animate({ opacity: [0, 1] }, {
  timeline: tl, fill: 'both', duration: 1, // 자리 표시 값
  rangeStart: 'entry 0%', rangeEnd: 'cover 40%',
})
```

- `ScrollTimeline`은 `source`(스크롤 컨테이너)와 `axis`를, `ViewTimeline`은 `subject`(관찰할 요소)와 `axis`를 받습니다.
- Baseline이 아닙니다. Chrome·Edge 115, Safari 26에서 지원하고 Firefox는 지원 목록에 없습니다(web-features 3.40.1 기준).
- 점진적 향상으로 씁니다. `@supports (animation-timeline: scroll())`로 분기하고, 미지원 환경에서도 내용이 보이도록 기본 상태가 가려진 모습이면 안 됩니다. 효과는 장식에 쓰고 필수 정보를 숨기는 데 쓰지 않습니다.
- 스크롤 이벤트에서 위치를 읽어 스타일을 바꾸던 코드를 선언으로 대체합니다(스크롤 이벤트는 9편).
- 이동·확대가 큰 시차 효과는 모션 줄이기 설정에서 끕니다(아래 절).

## prefers-reduced-motion

`prefers-reduced-motion`은 사용자가 OS에서 불필요한 움직임을 줄이도록 설정했는지 알려 주는 미디어 기능입니다. 확대·이동 같은 움직임은 전정 기관 장애가 있는 사용자에게 불편이나 증상을 일으킬 수 있습니다. 값은 `no-preference`와 `reduce` 두 가지이고 Baseline 2020부터 널리 지원됩니다.

```css
.card { animation: pop 0.4s both; }
@media (prefers-reduced-motion: reduce) {
  .card { animation: fade 0.4s both; }
}
```

- 움직임을 없애기보다 불투명도 전환 같은 덜 자극적인 표현으로 바꿉니다. 애니메이션이 없어도 기능이 동작해야 합니다.
- 이 미디어 쿼리는 CSS 규칙에만 적용됩니다. JS로 만든 WAAPI·rAF 애니메이션에는 자동 적용되지 않으므로 직접 확인합니다.

```js
const q = '(prefers-reduced-motion: reduce)'
const reduce = matchMedia(q)
const from = reduce.matches ? 'none' : 'translateY(16px)'
el.animate({
  opacity: [0, 1],
  transform: [from, 'none'],
}, 200)
reduce.addEventListener('change', (e) => { /* 설정 변경 반영 */ })
```

- 설정은 사용 중에도 바뀔 수 있으므로 `change` 이벤트로 반영합니다.
- 모션 줄이기에서 duration을 0으로 만들면 전환은 시작되지 않아 `transitionend`가 오지 않습니다. 앞 절의 `finished` 기반 대기는 이 경우에도 동작합니다.
- 설정 위치는 OS마다 다릅니다(Windows는 접근성의 표시, macOS·iOS는 손쉬운 사용의 동작, Android 9 이상은 애니메이션 제거).

## 핵심 정리

- 전환은 값 변화 사이를 채우고 애니메이션은 키프레임으로 단계를 정의하며, 둘의 끝은 이벤트보다 Animation의 `finished`로 기다리는 편이 안전합니다.
- `requestAnimationFrame`은 매 프레임 JS 계산이 필요할 때만 쓰고 진행도는 콜백의 시각으로 계산하며 정리 시 `cancelAnimationFrame`을 부릅니다.
- WAAPI의 `animate()`는 `Animation`을 돌려주고 `play`·`pause`·`reverse`·`cancel`·`playbackRate`와 `ready`·`finished`로 제어하며 기본 `fill`은 `none`이라 최종 상태는 `commitStyles()`로 확정합니다.
- 진입은 `@starting-style` 또는 WAAPI로, 퇴장은 `getAnimations()`의 `finished`를 기다린 뒤 제거하며, `display` 전환에는 `allow-discrete`가 필요합니다.
- 상태 기반 설계는 상태 속성에 모양을 연결해 중단·되돌림이 자연스럽고, 취소 경로(`AbortError`, 컴포넌트 제거)를 항상 처리합니다.
- 스크롤 기반 애니메이션은 미Baseline이라 점진적 향상으로 쓰고, 모든 모션은 `prefers-reduced-motion`을 지킵니다.
