## textContent와 innerHTML

`textContent`는 노드의 자손 텍스트를 이어 붙인 문자열이고, `innerHTML`은 요소의 자식을 HTML 문자열로 읽고 쓰는 프로퍼티입니다.

```js
// <p id="p">Hi <b>there</b><!-- c --></p>
p.textContent              // 'Hi there'  (주석 제외)
p.innerHTML                // 'Hi <b>there</b><!-- c -->'
p.textContent = '<b>x</b>' // 태그가 아니라 글자로 들어간다
p.innerHTML                // '&lt;b&gt;x&lt;/b&gt;'
```

`textContent` 규칙은 다음과 같습니다.

- 읽을 때 자손 텍스트 노드를 모두 이어 붙입니다. `script`·`style` 안의 글자와 CSS로 숨겨진 글자도 포함하고, 주석은 제외합니다.
- 대입하면 모든 자식을 지우고 텍스트 노드 하나로 바꿉니다. 빈 문자열이나 `null`을 대입하면 텍스트 노드 없이 자식만 지워집니다.
- 텍스트·주석 노드에서는 그 노드의 데이터를 그대로 돌려줍니다. `document`와 문서 타입 노드에서는 `null`이며 대입은 무시됩니다.
- 레이아웃 계산이 필요 없어 빠릅니다.

`innerHTML` 규칙은 다음과 같습니다.

- 읽을 때는 원본 소스가 아니라 현재 DOM을 직렬화합니다. 속성 따옴표는 정규화되고, 파서가 보충한 요소도 나옵니다.
- 대입하면 문자열을 그 요소를 문맥으로 파싱해 기존 자식 전부를 교체합니다. 이전 자식에 붙은 리스너, 입력값, 포커스는 사라집니다.
- `null`은 빈 문자열로 처리됩니다. 대입은 `innerHTML = ''`로 비우는 용도로도 씁니다.
- 대입한 문자열 안의 `script` 요소는 실행되지 않습니다. 그러나 이미지의 `onerror` 같은 이벤트 핸들러 속성은 동작하므로 XSS 경로가 됩니다(자세히는 63편).
- 호스트 요소의 `innerHTML`에는 Shadow DOM 내용이 포함되지 않습니다(자세히는 21편).

```js
const box = document.createElement('div')
box.innerHTML = '<table><tr><td>1'
box.innerHTML
// '<table><tbody><tr><td>1</td></tr></tbody></table>'
```

파싱 문맥에 따라 허용되는 구조가 달라집니다. `tr` 요소의 `innerHTML`에는 `td`를 넣을 수 있지만, `div`의 `innerHTML`에 `td`만 넣으면 태그가 무시되고 글자만 남습니다. 문맥이 필요한 조각은 `template`로 만듭니다(자세히는 22편).

흔한 실수는 `+=`입니다.

```js
list.innerHTML += '<li>C</li>'  // ❌ 전체를 직렬화·재파싱
// 기존 li는 새 요소로 교체되어 리스너와 입력 상태가 사라진다
list.insertAdjacentHTML('beforeend', '<li>C</li>') // ✅
```

## innerText와 outerHTML

`innerText`는 화면에 렌더링된 모습 기준의 텍스트이고, `outerHTML`은 요소 자신을 포함한 HTML입니다. `innerText`는 `HTMLElement` 전용이라 SVG 요소에는 없습니다.

| 프로퍼티 | 읽는 값 | `display:none` 안의 글자 | 레이아웃 계산 |
|----------|---------|---------------------------|---------------|
| `textContent` | 모든 텍스트 노드 | 포함 | 하지 않음 |
| `innerText` | 렌더링된 텍스트 | 제외 | 함 |
| `innerHTML` | 자식 직렬화 | 마크업으로 포함 | 하지 않음 |
| `outerHTML` | 자신 + 자식 직렬화 | 마크업으로 포함 | 하지 않음 |

```html
<div id="d">a<span style="display:none">b</span><br>c</div>
<p id="p" style="text-transform:uppercase">hi</p>
```

```js
d.textContent  // 'abc'
d.innerText    // 'a\nc'  (숨겨진 b 제외, br은 줄바꿈)
p.textContent  // 'hi'
p.innerText    // 'HI'    (CSS text-transform 반영)
```

`innerText` 규칙은 다음과 같습니다.

- CSS를 반영합니다. 숨겨진 글자를 빼고, `text-transform`을 적용하고, `br`과 블록 요소 경계에 줄바꿈을 넣습니다. `p`는 앞뒤에 빈 줄이 들어갑니다.
- 값을 읽을 때 최신 레이아웃이 필요하므로 강제 리플로가 일어납니다(자세히는 06편). 반복문 안에서 읽으면 느려집니다.
- 요소 자신이 렌더링되지 않으면(`display:none` 등) `textContent`와 같은 값을 돌려줍니다.
- 대입하면 `\n`이 `br` 요소로 바뀝니다. `textContent` 대입은 `\n`을 텍스트 노드의 줄바꿈 문자로 두므로, `white-space`를 바꾸지 않으면 화면에서 한 줄로 이어집니다.

```js
el.innerText = 'a\nb'
el.innerHTML     // 'a<br>b'
el.textContent = 'a\nb'
el.innerHTML     // 'a\nb'  (br 없음)
```

`outerHTML` 규칙은 다음과 같습니다.

- 읽으면 요소 자신을 포함한 HTML 문자열입니다.
- 대입하면 요소가 파싱 결과로 교체됩니다. 변수는 여전히 분리된 옛 요소를 가리킵니다.
- 부모가 없는 요소에 대입하면 아무 일도 일어나지 않고, 부모가 `document`이면(`document.documentElement`) `NoModificationAllowedError`가 발생합니다.

```js
// <div id="box"></div>
box.outerHTML = '<p id="box">x</p>'
box.tagName                              // 'DIV'  (옛 요소)
document.getElementById('box').tagName   // 'P'
```

요소 교체는 `replaceWith()`가 대체로 더 명확합니다(자세히는 04편).

## insertAdjacentHTML

`insertAdjacentHTML(position, text)`는 HTML 문자열을 파싱해 요소를 기준으로 네 위치 중 한 곳에 삽입하는 메서드입니다. 기존 자식을 건드리지 않습니다.

| position | 삽입 위치 |
|----------|-----------|
| `beforebegin` | 요소 바로 앞(형제) |
| `afterbegin` | 요소 안, 첫 자식 앞 |
| `beforeend` | 요소 안, 마지막 자식 뒤 |
| `afterend` | 요소 바로 뒤(형제) |

```html
<!-- beforebegin --><ul>
  <!-- afterbegin --><li>A</li><!-- beforeend -->
</ul><!-- afterend -->
```

```js
ul.insertAdjacentHTML('beforeend', '<li>B</li>')
ul.children.length   // 2
ul.children[0]       // 기존 li 그대로 (리스너 유지)
```

- `position`은 대소문자를 구분하지 않습니다. 네 값이 아니면 `SyntaxError`입니다.
- `beforebegin`과 `afterend`는 부모가 필요합니다. 부모가 없거나 `document`이면 `NoModificationAllowedError`입니다.
- 반환값이 없으므로 삽입한 노드를 바로 얻지 못합니다. 노드가 필요하면 `createElement`로 만들어 넣습니다.
- 문자열을 HTML로 해석하므로 `innerHTML`과 같은 XSS 위험이 있습니다.

같은 위치 규칙을 쓰는 형제 메서드가 둘 있습니다.

| 메서드 | 받는 값 | 반환 |
|--------|---------|------|
| `insertAdjacentElement(position, el)` | 요소 | 삽입한 요소, 삽입 위치가 없으면 `null` |
| `insertAdjacentText(position, text)` | 문자열(마크업 해석 없음) | 없음 |

사용자 입력은 `insertAdjacentText`나 `textContent`로 넣습니다. 현대적 대안인 `append`·`before`·`after`는 04편에서 다룹니다.

## 안전한 DOM 생성 패턴

안전한 DOM 생성의 원칙은 사용자 데이터를 마크업 문자열에 섞지 않는 것입니다. 구조는 `createElement`로 만들고, 데이터는 텍스트 노드나 속성값으로 넣습니다.

```js
function renderComment(user, url) {
  const li = document.createElement('li')
  const a = document.createElement('a')
  a.textContent = user.name            // 마크업으로 해석 안 됨
  if (new URL(url, location.href).protocol === 'https:') {
    a.href = url                       // javascript: 차단
  }
  li.append(a, ': ', user.text)        // 문자열은 텍스트 노드
  return li
}
```

피해야 할 형태는 템플릿 리터럴로 HTML을 조립하는 것입니다.

```js
li.innerHTML = `<b>${user.name}</b>` // ❌
// name이 '<img src=x onerror=alert(1)>'이면 코드가 실행된다
```

규칙은 다음과 같습니다.

- 텍스트는 `textContent`·`createTextNode`·`append('문자열')`로 넣습니다. 셋 다 마크업으로 해석하지 않습니다.
- 속성값은 프로퍼티나 `setAttribute`로 넣습니다. 문자열 조립으로 속성을 만들면 따옴표를 닫고 새 속성을 주입당할 수 있습니다.
- `href`·`src`·`action` 같은 URL 속성은 값이 `javascript:` 스킴일 수 있습니다. `new URL()`로 파싱해 스킴을 검사합니다.
- 속성 이름을 사용자 입력으로 정하지 않습니다. `setAttribute('onclick', 문자열)`은 문자열이 곧 코드입니다.
- 반복되는 구조는 `template`을 복제해 채웁니다(자세히는 22편).
- 사용자가 쓴 HTML을 그대로 보여 줘야 하면 살균기를 거칩니다. 브라우저 내장 방식은 `setHTML()`이고(아래 setHTMLUnsafe 절), 서드파티로는 DOMPurify가 쓰입니다.

이스케이프는 마지막 수단입니다.

```js
const escapeHtml = s => s.replace(/[&<>"']/g, c => ({
  '&': '&amp;', '<': '&lt;', '>': '&gt;',
  '"': '&quot;', "'": '&#39;'
})[c])

escapeHtml('<b a="1">')  // '&lt;b a=&quot;1&quot;&gt;'
```

이 함수는 요소 안의 텍스트와 따옴표로 감싼 속성값 문맥에서만 유효합니다. URL 속성, 이벤트 핸들러 속성, `script`·`style` 안에서는 막지 못합니다. 이스케이프보다 DOM API를 쓰는 편이 규칙이 단순합니다. 정책으로 문자열 대입 자체를 막는 방법은 Trusted Types입니다(자세히는 63편).

## 속성 메서드와 attributes

속성(attribute)은 HTML 마크업에 적힌 이름과 문자열 값의 쌍이고, 요소에는 이를 다루는 메서드 다섯 개가 있습니다.

| 메서드 | 반환 | 동작 |
|--------|------|------|
| `getAttribute(name)` | 문자열 또는 `null` | 값을 읽는다. 속성이 없으면 `null` |
| `setAttribute(name, value)` | 없음 | 값을 문자열로 바꿔 설정한다. 있으면 덮어쓴다 |
| `removeAttribute(name)` | 없음 | 제거한다. 없어도 오류가 없다 |
| `hasAttribute(name)` | `boolean` | 존재 여부. 값이 빈 문자열이어도 `true` |
| `toggleAttribute(name, force?)` | `boolean` | 없으면 값 `''`으로 추가, 있으면 제거. 반환은 호출 뒤 존재 여부 |

```js
const btn = document.querySelector('button')
btn.getAttribute('type')         // null  (속성 없음)
btn.setAttribute('disabled', 'false')
btn.disabled                     // true  (존재만으로 켜진다)
btn.toggleAttribute('disabled')  // false (제거됨)
btn.setAttribute('data-n', 5)
btn.getAttribute('data-n')       // '5'   (항상 문자열)
```

- 불리언 속성(`disabled`·`hidden`·`checked`·`required`·`readonly`)은 값이 아니라 존재 여부가 의미입니다. 끄려면 `removeAttribute`나 `toggleAttribute(name, false)`를 씁니다.
- HTML 문서의 HTML 요소에서는 이름이 소문자로 바뀌어 처리됩니다. SVG 요소는 대소문자를 구분하므로 `viewBox`는 그대로 써야 합니다.
- 이름이 XML 이름 규칙을 어기면(숫자로 시작, 공백 포함 등) `setAttribute`가 `InvalidCharacterError`를 던집니다.
- 네임스페이스가 있는 속성은 `getAttributeNS`·`setAttributeNS`를 씁니다.
- `getAttributeNames()`는 속성 이름 배열을, `hasAttributes()`는 속성이 하나라도 있는지를 돌려줍니다.

`attributes`는 요소의 속성 전체를 담은 `NamedNodeMap`입니다. 각 항목은 `name`·`value`·`ownerElement`를 가진 `Attr` 객체이고, 속성이 바뀌면 즉시 반영되는 라이브 컬렉션입니다.

```js
// <a id="x" class="y" href="/z">
for (const { name, value } of a.attributes) {
  console.log(name, value) // 'id' 'x' → 'class' 'y' → 'href' '/z'
}
a.attributes.length            // 3
a.attributes.getNamedItem('id').value // 'x'
```

항목 순서는 소스에 적은 순서이고, 새로 추가한 속성은 뒤에 붙습니다. 같은 속성을 두 번 적으면 파서가 첫 번째만 남깁니다.

### 프로퍼티와 속성의 차이

많은 속성은 같은 이름의 프로퍼티에 반영(reflect)되지만, 두 값이 항상 같지는 않습니다.

| 차이 | 예 |
|------|----|
| 이름이 다르다 | `class` ↔ `className`, `for` ↔ `htmlFor` |
| 프로퍼티가 값을 가공한다 | `a.href`는 절대 URL, 속성은 적은 그대로 |
| 타입이 다르다 | `tabIndex`는 숫자, 속성은 문자열 |
| 속성이 없어도 프로퍼티는 기본값이 있다 | `div.tabIndex`는 `-1`, `getAttribute('tabindex')`는 `null` |
| 현재 상태와 초기값이 갈린다 | `input.value`와 `value` 속성 |

```js
// <a href="/docs">, 페이지 주소 https://ex.com/
a.getAttribute('href')  // '/docs'
a.href                  // 'https://ex.com/docs'
```

```js
// <input value="a">, 사용자가 b로 고친 뒤
input.value                     // 'b'  (현재 값)
input.getAttribute('value')     // 'a'  (초기 기본값)
input.setAttribute('value','c') // 화면은 'b' 그대로
```

사용자가 값을 바꾸거나 `input.value`를 대입하면 입력 요소는 값이 "변경됨" 상태가 되어 `value` 속성 변화를 더 이상 화면에 반영하지 않습니다(자세히는 11편).

- 상태를 다루려면 프로퍼티를 씁니다.
- 마크업 그대로 보존해야 하는 값은 속성을 씁니다. `data-*`, `aria-*`, 커스텀 속성이 해당합니다.
- 커스텀 요소의 `attributeChangedCallback`은 속성 변화만 감지합니다. 프로퍼티 대입은 감지하지 못합니다(자세히는 18편).
- 임의 이름의 프로퍼티(`el.foo = 1`)는 속성이 아니라 JavaScript 객체의 프로퍼티일 뿐이며 마크업에 나타나지 않습니다.
- ARIA 속성의 프로퍼티 반영(`ariaLabel` 등)은 27편에서 다룹니다.

## classList와 DOMTokenList

`classList`는 `class` 속성을 공백으로 구분된 토큰 집합으로 다루는 `DOMTokenList`입니다. `class` 속성의 라이브 뷰라서 어느 쪽을 바꿔도 다른 쪽에 반영됩니다.

| 멤버 | 동작 |
|------|------|
| `add(...tokens)` | 토큰을 추가한다. 이미 있으면 무시 |
| `remove(...tokens)` | 토큰을 제거한다. 없어도 오류 없음 |
| `toggle(token, force?)` | 있으면 제거, 없으면 추가. 반환은 호출 뒤 존재 여부 |
| `contains(token)` | 존재 여부 `boolean` |
| `replace(old, new)` | 바꾸면 `true`, `old`가 없으면 `false`(변화 없음) |
| `item(i)`, `length`, `value` | 인덱스 접근, 개수, 속성 문자열 전체 |
| `supports(token)` | 지원 토큰 목록이 있는 속성에서만 사용 |

```js
// <div class="card">
el.classList.add('on', 'big')        // class="card on big"
el.classList.add('on')               // 중복 무시
el.classList.toggle('on')            // false (제거됨)
el.classList.toggle('on', true)      // true  (강제 추가)
el.classList.replace('big', 'small') // true
el.classList.contains('card')        // true
Array.from(el.classList)             // ['card', 'small', 'on']
```

- 빈 문자열 토큰은 `SyntaxError`, 공백이 들어간 토큰(`add('a b')`)은 `InvalidCharacterError`입니다. 여러 개는 인수로 나눠 넘깁니다.
- `toggle`의 두 번째 인수 `force`는 조건부 토글에 씁니다. `el.classList.toggle('open', isOpen)`은 `if`·`else` 두 갈래를 한 줄로 줄입니다.
- 마지막 토큰을 지워도 `class=""` 속성은 남습니다.
- `value`에 대입하면 `class` 속성 문자열 전체가 교체됩니다.
- `relList`·`sandbox`·`part`처럼 같은 `DOMTokenList`를 쓰는 속성이 있습니다. `supports()`는 `rel`·`sandbox` 같이 지원 토큰이 정의된 속성에서만 동작하고, `classList.supports()`는 `TypeError`입니다.

`className`은 문자열 전체를 다루므로 부분 문자열 비교에 쓰면 안 됩니다.

```js
el.className = 'card on'             // ❌ 다른 클래스까지 덮어씀
el.className.includes('on')          // ❌ 'button'에도 true
el.classList.contains('on')          // ✅ 토큰 단위 비교
```

스타일 값을 직접 대입하는 대신 클래스를 토글하면 스타일 규칙이 CSS에 남습니다(자세히는 06편).

## dataset과 data-* 이름 변환

`dataset`은 요소의 `data-*` 속성을 객체처럼 읽고 쓰는 `DOMStringMap`입니다. HTML 요소와 SVG 요소에서 모두 쓸 수 있습니다.

```html
<li id="u" data-user-id="42" data-role="admin"></li>
```

```js
u.dataset.userId       // '42'
u.dataset.role         // 'admin'
u.dataset.count = 3    // data-count="3"
u.dataset.fooBar = 'x' // data-foo-bar="x"
'role' in u.dataset    // true
delete u.dataset.role  // data-role 속성 제거
u.dataset.missing      // undefined (getAttribute는 null)
```

이름 변환 규칙은 방향별로 다릅니다.

| 방향 | 규칙 | 예 |
|------|------|----|
| 속성 → 키 | `data-`를 떼고, 하이픈 뒤 소문자를 대문자로 바꾸며 하이픈 제거 | `data-user-id` → `userId` |
| 키 → 속성 | 대문자를 하이픈 + 소문자로 바꾸고 `data-`를 붙임 | `fooBar` → `data-foo-bar` |

- 하이픈 뒤가 소문자가 아니면 하이픈이 남습니다. `data-1st`의 키는 `'1st'`라서 `dataset['1st']`로 접근합니다.
- 키에 "하이픈 + 소문자"가 들어 있으면 대입할 때 `SyntaxError`입니다. `dataset['foo-bar'] = 1`이 해당합니다.
- 값은 항상 문자열입니다. `5`는 `'5'`, `true`는 `'true'`, `null`은 `'null'`로 저장됩니다. 숫자는 `Number()`, 객체는 `JSON.parse()`로 되돌립니다.
- HTML 파서가 속성 이름을 소문자로 바꾸므로 마크업에 `data-userId`로 적으면 키는 `userid`입니다. 마크업에서는 하이픈 표기만 씁니다.
- `Object.keys(el.dataset)`로 열거할 수 있고, 순서는 속성 순서입니다.
- CSS에서 `[data-role="admin"]` 선택자로 쓸 수 있으므로 상태 표현에 자주 쓰입니다.
- 마크업에 그대로 노출되므로 비밀 값이나 큰 데이터를 저장하지 않습니다.

## HTMLElement 공통 속성

다음 속성들은 `HTMLElement`에 정의되어 모든 HTML 요소에서 쓸 수 있고, 프로퍼티로 읽고 쓸 수 있습니다.

| 속성 | 타입 | 역할 |
|------|------|------|
| `title` | 문자열 | 마우스를 올리면 보이는 보조 설명 |
| `lang` | 문자열 | 요소의 언어(BCP 47 태그) |
| `dir` | `ltr`·`rtl`·`auto` | 텍스트 방향 |
| `translate` | `boolean` | 번역 도구의 번역 대상 여부 |
| `spellcheck` | `boolean` | 맞춤법 검사 대상 여부 |
| `draggable` | `boolean` | 드래그 가능 여부 |
| `tabIndex` | 숫자 | 포커스 가능 여부와 탭 순서 |
| `accessKey` | 문자열 | 포커스·활성화용 단축키 문자 |
| `autocapitalize` | 문자열 | 가상 키보드의 자동 대문자 방식 |

```js
el.title = '저장'          // title="저장"
el.lang = 'ko'             // lang="ko"
el.translate = false       // translate="no"
el.spellcheck = false      // spellcheck="false"
el.draggable = true        // draggable="true"
el.tabIndex = -1           // tabindex="-1"
```

개별 규칙은 다음과 같습니다.

- `title`은 요소에 없으면 가장 가까운 조상의 `title`이 적용됩니다. 터치와 키보드 사용자에게는 보이지 않으므로 필수 정보를 담지 않습니다.
- `lang`은 하위 요소가 상속합니다. 스크린 리더의 발음, 하이픈 처리, CSS `:lang()` 선택자, 번역 판단에 쓰입니다. 프로퍼티는 속성값 그대로를 돌려주고 상속값을 반영하지 않습니다.
- `dir="auto"`는 내용의 첫 강한 방향 글자로 방향을 정합니다. 사용자가 쓴 글을 보여 줄 때 씁니다.
- `translate` 속성값은 `yes`와 `no`이며 하위 요소가 상속합니다. 코드 조각, 고유명사, 브랜드명에 `translate="no"`를 지정합니다.
- `spellcheck` 속성값은 `true`와 `false`입니다. 편집 가능한 요소(입력창, `contenteditable`)에만 의미가 있고, 기본값은 브라우저가 정합니다.
- `draggable`은 속성이 없으면 `img`와 `href`가 있는 `a`만 `true`입니다. 드래그 동작 전체는 49편에서 다룹니다.
- `tabIndex`는 `-1`이면 탭 키 순서에서 빠지지만 스크립트의 `focus()`와 클릭으로는 포커스를 받습니다. `0`이면 문서 순서대로 탭 순서에 들어가고, 양수는 그 값이 먼저 오므로 쓰지 않습니다. `div`의 기본값은 `-1`이고 `button`·`a[href]`·`input`은 `0`입니다(자세히는 28편).
- `accessKey`는 누르는 조합 키가 브라우저와 OS마다 다르고 스크린 리더 단축키와 충돌하기 쉬워 권장되지 않습니다.
- `autocapitalize`는 `off`(`none`), `on`(`sentences`), `words`, `characters`를 받습니다. 가상 키보드에만 영향을 주고 물리 키보드 입력은 바꾸지 않습니다. 편집 가능한 요소에서만 의미가 있습니다.

## DOMParser와 XMLSerializer

`DOMParser`는 문자열을 파싱해 새 `Document`를 만들고, `XMLSerializer`는 노드를 XML 문자열로 직렬화합니다.

```js
const doc = new DOMParser()
  .parseFromString('<p>Hi</p>', 'text/html')
doc.body.firstChild.textContent  // 'Hi'
doc.documentElement.tagName      // 'HTML' (html·head·body 보충)

list.append(doc.body.firstElementChild) // 현재 문서로 이동
```

`parseFromString(string, type)`의 `type`은 다섯 값만 받고, 그 밖의 값은 `TypeError`입니다.

| type | 파서 | 오류 처리 |
|------|------|-----------|
| `text/html` | HTML 파서 | 오류 없음. 항상 html·head·body를 채워 줌 |
| `text/xml`, `application/xml`, `application/xhtml+xml`, `image/svg+xml` | XML 파서 | 잘못된 XML이면 `parsererror` 요소를 담은 문서 |

XML은 예외를 던지지 않으므로 직접 확인해야 합니다.

```js
const xml = new DOMParser()
  .parseFromString('<a><b></a>', 'application/xml')
xml.querySelector('parsererror') !== null  // true (오류 문서)
```

- 결과 문서는 활성 문서가 아니라서 스크립트가 실행되지 않고 외부 리소스도 불러오지 않습니다. 이 문서의 `script` 요소는 현재 문서로 옮겨도 실행되지 않습니다.
- 그러나 살균은 아닙니다. `onerror` 같은 이벤트 핸들러 속성은 그대로 남아 있어 현재 문서에 옮기면 동작합니다.
- 문맥 없이 `body` 기준으로 파싱하므로 `<tr>`·`<td>` 조각은 버려집니다. 이런 조각에는 `template`을 씁니다(자세히는 22편).
- 선언적 Shadow DOM(`template`의 `shadowrootmode`)은 처리하지 않습니다. 그 용도는 `parseHTMLUnsafe`입니다.

`XMLSerializer`는 노드 하나를 받아 XML 문법의 문자열로 돌려줍니다.

```js
const s = new XMLSerializer()
s.serializeToString(document.createElement('br'))
// '<br xmlns="http://www.w3.org/1999/xhtml" />'
```

`outerHTML`과의 차이는 다음과 같습니다.

- XML 문법을 지킵니다. 빈 요소는 `<br />`처럼 스스로 닫고, 필요한 네임스페이스 선언(`xmlns`)을 붙입니다.
- `Element`뿐 아니라 `Document`를 포함한 어떤 노드도 받습니다.
- HTML 문서 안의 인라인 SVG는 `outerHTML`에 `xmlns`가 붙지 않지만 `XMLSerializer`는 붙입니다. 따라서 SVG를 독립 파일이나 `Blob`으로 저장할 때는 `XMLSerializer`를 씁니다(자세히는 48편).

```js
const svg = document.querySelector('svg')
new XMLSerializer().serializeToString(svg)
// '<svg xmlns="http://www.w3.org/2000/svg" ...>...</svg>'
```

## setHTMLUnsafe와 parseHTMLUnsafe

`setHTMLUnsafe()`는 `innerHTML`처럼 요소의 자식을 HTML 문자열로 교체하되 선언적 Shadow DOM을 해석하고 살균기 옵션을 받는 메서드이고, `Document.parseHTMLUnsafe()`는 같은 파서로 새 `Document`를 만드는 정적 메서드입니다. 둘 다 Baseline 2025(2025년 9월부터 핵심 브라우저 전체 지원)입니다.

```js
host.setHTMLUnsafe(`
  <template shadowrootmode="open">
    <p>in shadow</p>
  </template>`)
host.shadowRoot !== null   // true  (host에 shadow root 생성)
```

```js
const doc = Document.parseHTMLUnsafe('<p>Hi</p>')
doc.body.firstChild.textContent  // 'Hi'
doc.URL                          // 'about:blank'
```

- `innerHTML`과 `DOMParser`는 `template`의 `shadowrootmode`를 해석하지 않고 일반 `template` 요소로 남깁니다. 이 두 메서드는 해석해서 shadow root를 만듭니다.
- 이름의 `Unsafe`는 기본으로 살균하지 않는다는 뜻입니다. `onerror` 같은 이벤트 핸들러 속성이 남으므로 `innerHTML`과 같은 위험을 가집니다.
- 두 번째 인수로 `{ sanitizer: 'default' }`나 `Sanitizer` 객체를 주면 요소·속성을 필터링합니다.
- 입력으로 문자열 대신 `TrustedHTML`을 받아 Trusted Types 정책과 함께 쓸 수 있습니다. Trusted Types를 강제하는 페이지에서는 문자열을 넘기면 `TypeError`입니다(자세히는 63편).
- `ShadowRoot`에도 `setHTMLUnsafe()`가 있습니다.
- `Document.parseHTMLUnsafe()`가 돌려주는 문서의 URL은 `about:blank`, 문자셋은 UTF-8입니다.

살균이 기본인 짝은 `Element.setHTML()`과 `Document.parseHTML()`입니다. Sanitizer API 기반이라 `script`·`iframe`·이벤트 핸들러 속성을 항상 제거합니다. 확인 시점(2026-10) MDN에서는 아직 Baseline이 아닌 것으로 표시되므로 지원 여부를 확인하고 씁니다.

```js
box.setHTML(userHtml)   // script·onclick 제거 (지원 브라우저에서)
```

살균한 결과를 `innerHTML`로 다시 읽어 다른 요소에 대입하면 안 됩니다. 직렬화 후 재파싱하면 DOM 구조가 달라져 살균이 무력화될 수 있습니다(mXSS). 다시 넣을 때도 `setHTML()`을 씁니다. 살균기와 정책은 63편에서 다룹니다.

## hidden 속성과 hidden="until-found"

`hidden`은 요소를 렌더링하지 않게 하는 전역 속성이며, 값에 따라 두 상태가 있습니다.

| 값 | 상태 | 렌더링 | 찾기·앵커 이동 |
|----|------|--------|----------------|
| 빈 값, `hidden`, 그 밖의 값 | hidden | `display: none` | 걸리지 않음 |
| `until-found` | hidden until found | `content-visibility: hidden` | 걸림 |

```html
<p hidden>안 보임</p>
<div id="faq" hidden="until-found">긴 답변</div>
```

```js
p.hidden = false                  // hidden 속성 제거
faq.hidden = 'until-found'        // hidden="until-found"
faq.addEventListener('beforematch', () => {
  console.log('찾기로 열림')       // hidden이 제거되기 직전
})
```

기본 `hidden` 규칙은 다음과 같습니다.

- 자리를 차지하지 않고 접근성 트리에서도 빠집니다. 화면 표시만 숨기고 스크린 리더에는 읽히게 하는 용도로 쓰지 않습니다.
- UA 스타일시트의 `display: none`일 뿐이므로 작성자 CSS의 `display`가 이깁니다. `.card { display: flex }`가 있으면 `hidden` 요소가 보입니다.
- 숨겨진 요소 안에서도 스크립트는 실행되고 폼 컨트롤 값은 제출됩니다.

```css
.card[hidden] { display: none }   /* 해결 */
```

`until-found` 규칙은 다음과 같습니다.

- 박스는 만들어지고 내용만 렌더링을 건너뜁니다. 그래서 브라우저의 페이지 내 찾기와 URL 조각(`#id`) 이동이 내용을 찾을 수 있습니다.
- 찾기나 조각 이동으로 걸리면 브라우저가 `beforematch` 이벤트를 발생시키고, `hidden` 속성을 제거하고, 그 위치로 스크롤합니다. 핸들러에서 `aria-expanded` 같은 관련 상태를 맞춥니다.
- 요소가 `display: none`·`contents`·`inline`이면 찾기에 걸리지 않습니다. 앞의 `.card[hidden] { display: none }` 같은 규칙을 `until-found` 요소에도 적용하면 기능이 막히므로 `.card[hidden]:not([hidden="until-found"])`처럼 값을 가려 씁니다.
- 프로퍼티 `hidden`은 `true`·`false`와 문자열 `'until-found'`를 모두 다룹니다.
- 지원: Chrome·Edge 102 이상, Firefox 148 이상이고 Safari는 지원하지 않아 Baseline이 아닙니다(web-features 기준). 미지원 브라우저는 `until-found`를 잘못된 값으로 보고 일반 `hidden`으로 처리합니다. 내용은 숨겨지지만 찾기로는 열리지 않으므로 열기 버튼을 따로 둡니다. 점진적 향상 방식으로 적용합니다(자세히는 71편).

`dialog`와 Popover 같은 표시 제어는 44편에서 다룹니다.

## document.write를 쓰지 않는 이유

`document.write(markup)`는 문자열을 HTML로 파싱해 문서 스트림의 현재 위치에 끼워 넣는 메서드이고, `writeln`은 줄바꿈을 덧붙입니다. 쓰지 않는 것이 원칙입니다.

```js
// 파싱 중 실행되는 인라인 스크립트
document.write('<p>한 줄</p>')   // 이 스크립트 자리에 삽입

// 파싱이 끝난 뒤(load 이후, 클릭 핸들러 등)
document.write('<p>한 줄</p>')   // 문서 전체가 지워지고 이 내용만 남음
```

이유는 다음과 같습니다.

- 파싱이 끝난 문서에서 호출하면 `document.open()`이 암묵적으로 호출되어 기존 문서가 통째로 사라집니다.
- 파서의 진행 상태를 바꾸기 때문에 결과 DOM이 소스와 다를 수 있고, 삽입한 `script`가 파서를 막고 실행되어 렌더링이 지연됩니다.
- `async`·`defer` 속성의 스크립트처럼 비동기로 불러온 외부 스크립트에서 호출하면 무시되고 콘솔에 경고가 남습니다.
- XML 문서(XHTML)와 커스텀 요소 생성자 안에서 호출하면 `InvalidStateError`입니다.
- 네트워크 지연에 따라 동작이 달라져 재현하기 어려운 오류가 생깁니다.
- 문자열을 살균 없이 HTML로 해석하는 XSS 싱크입니다. Trusted Types를 강제하면 문자열 인수는 `TypeError`입니다(자세히는 63편).

대체 수단은 목적별로 정해져 있습니다.

| 하려는 일 | 대신 쓸 것 |
|-----------|------------|
| 요소를 현재 위치에 추가 | `createElement` + `append`(04편) |
| 정적 HTML 조각 삽입 | `insertAdjacentHTML`, `template` |
| 스크립트를 동적으로 불러옴 | `createElement('script')`(14편) |

## 핵심 정리

- 사용자 입력은 `textContent`나 `createElement`로 넣고, `innerHTML`·`insertAdjacentHTML`·`document.write`에는 마크업 문자열만 넣습니다. `innerHTML +=`는 기존 자식을 모두 다시 만듭니다.
- `innerText`는 CSS 렌더링 결과 기준이고 레이아웃을 강제하며, `textContent`는 모든 텍스트 노드를 이어 붙입니다. `outerHTML` 대입은 요소를 교체하지만 변수는 옛 요소를 가리킵니다.
- 속성은 문자열이고 불리언 속성은 존재 여부가 의미입니다. 상태는 프로퍼티, 마크업 보존이 필요한 값은 속성으로 다룹니다.
- `classList.toggle(token, force)`는 조건부 토글이고, `dataset`은 `data-user-id`를 `userId`로 변환하며 값은 항상 문자열입니다.
- `DOMParser`는 살균하지 않고 `setHTMLUnsafe`·`parseHTMLUnsafe`(Baseline 2025)는 선언적 Shadow DOM을 해석합니다. `hidden="until-found"`는 미Baseline입니다.
