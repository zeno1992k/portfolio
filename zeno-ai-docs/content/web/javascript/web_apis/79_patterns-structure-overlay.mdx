## 패턴을 고르는 기준

같은 "숨겼다 보였다" 컴포넌트도 의미에 따라 요소와 역할이 다릅니다. 먼저 의미로 고릅니다.

| 컴포넌트 | 열리는 곳 | 포커스 | 네이티브 기반 |
|----------|-----------|--------|---------------|
| Disclosure | 제자리 | 버튼에 유지 | `details`와 `summary` |
| Accordion | 제자리 | 버튼에 유지 | `details`의 `name` 그룹 |
| Tabs | 제자리(한 패널만 표시) | 탭 목록에 유지 | 없음(ARIA로 구현) |
| Modal Dialog | 위(Top Layer) | 안으로 이동, 배경 비활성 | `dialog`와 `showModal()` |
| Popover·Tooltip | 위 | 열린 뒤 다음 Tab으로 진입 또는 이동 없음 | `popover` 속성 |
| Dropdown Menu | 위 | 첫 항목으로 이동 | `popover`에 `role="menu"` |
| Toast | 위 | 이동 없음 | `popover="manual"`과 live region |

- 오버레이의 포커스·닫기·스택 규칙은 45편, 네이티브 요소 자체는 44편에서 다뤘습니다.
- 위젯별 역할·상태·키보드 규칙은 W3C APG(Authoring Practices Guide)를 기준으로 합니다. 키보드 포커스 일반 규칙은 28편입니다.
- shadow DOM 안에서 `aria-controls`, `aria-labelledby` 같은 id 참조는 같은 트리 안에서만 연결됩니다. 탭 버튼과 패널처럼 서로를 참조하는 요소는 둘 다 light DOM 슬롯 자식으로 받으면 같은 트리에 있어 참조가 유지됩니다(자세히는 21편, 22편).

## Disclosure와 details name

디스클로저(disclosure)는 버튼 하나가 내용 하나를 보였다 숨기는 가장 단순한 패턴입니다. 네이티브는 `details`와 `summary`입니다.

```html
<details>
  <summary>환불 규정</summary>
  <p>수령 후 7일 이내…</p>
</details>
```

- `details`의 암묵 역할은 `group`이고 `summary`가 토글 컨트롤입니다. Baseline 널리 지원(2020)입니다.
- 열림 상태는 `open` 속성이 나타내고 상태 변화는 `toggle` 이벤트로 받습니다. 속성을 읽거나 쓰면 같은 상태가 동기화됩니다.
- 같은 `name` 값을 가진 `details` 여러 개는 한 번에 하나만 열립니다(아래 Accordion). Baseline 2024입니다.
- `::details-content` 의사 요소로 펼쳐지는 영역을 꾸밉니다. Baseline 2025입니다.

직접 만들 때는 APG 규칙을 따릅니다.

```html
<button aria-expanded="false" aria-controls="more">
  더 보기
</button>
<div id="more" hidden>…</div>
```

| 항목 | 규칙 |
|------|------|
| 컨트롤 | `button` 역할 |
| 상태 | `aria-expanded`가 열리면 `true`, 닫히면 `false` |
| 연결 | `aria-controls`로 내용 요소 id 참조(선택) |
| 키보드 | Enter와 Space로 토글 |

- 상태가 바뀌어도 버튼의 레이블은 그대로 둡니다. 상태는 `aria-expanded`가 전달합니다.
- 내비게이션 메뉴를 만들 때도 사이트 이동 링크의 펼침은 `role="menu"`가 아니라 디스클로저로 만듭니다. `menu` 역할은 응용 프로그램 메뉴용입니다(아래 Menubar).

## Accordion

아코디언은 디스클로저를 세로로 여러 개 쌓은 것입니다. 각 헤더는 버튼이고 제목 요소(heading)로 감쌉니다.

```html
<h3>
  <button id="b1" aria-expanded="true" aria-controls="s1">
    배송
  </button>
</h3>
<div id="s1" role="region" aria-labelledby="b1">…</div>
```

| 항목 | 규칙 |
|------|------|
| 헤더 | 제목 요소 안의 `button`. 제목 수준은 문서 구조에 맞춤 |
| 상태 | 버튼의 `aria-expanded`와 `aria-controls` |
| 패널 | `role="region"`과 `aria-labelledby`로 버튼 참조(선택) |
| 키보드 | Enter·Space로 토글, Tab으로 포커스 이동 |
| 항상 열린 패널 | 닫을 수 없으면 버튼에 `aria-disabled="true"` |

```js
btn.addEventListener('click', () => {
  const open = btn.getAttribute('aria-expanded') === 'true'
  btn.setAttribute('aria-expanded', String(!open))
  panel.hidden = open
})
```

- 한 번에 하나만 열게 할지는 선택입니다. 네이티브는 같은 `name`의 `details` 그룹이 이를 처리합니다.
- 동시에 열릴 수 있는 패널이 대략 6개를 넘으면 `region` 역할을 쓰지 않습니다. 랜드마크가 너무 많아져 스크린 리더 사용자가 혼란스럽습니다.
- 위아래 방향키와 Home·End로 헤더 사이를 이동하는 것은 선택 사항입니다.
- 접힌 패널의 내용은 `hidden`이나 `display: none`으로 접근성 트리에서 빼야 합니다. 높이만 0으로 줄이면 숨은 링크에 Tab 포커스가 갑니다.

**흔한 실수:** 헤더를 `div`나 `h3` 자체에 클릭 리스너를 달아 만드는 것입니다. 제목 요소 안에 `button`을 넣어야 제목 탐색과 키보드 조작이 모두 됩니다.

## Tabs

탭은 겹쳐진 패널 중 하나만 보이고 탭 목록으로 전환하는 구조입니다. 네이티브 요소가 없어 ARIA로 구현합니다.

```html
<div role="tablist" aria-label="설정">
  <button role="tab" id="t1" aria-selected="true"
          aria-controls="p1">일반</button>
  <button role="tab" id="t2" aria-selected="false"
          aria-controls="p2" tabindex="-1">보안</button>
</div>
<div role="tabpanel" id="p1" aria-labelledby="t1">…</div>
<div role="tabpanel" id="p2" aria-labelledby="t2"
     hidden>…</div>
```

| 항목 | 규칙 |
|------|------|
| 역할 | `tablist`, `tab`, `tabpanel` |
| 선택 | 활성 탭만 `aria-selected="true"` |
| 연결 | 탭의 `aria-controls`로 패널, 패널의 `aria-labelledby`로 탭 |
| Tab 키 | 활성 탭에 들어가고 다음 Tab은 탭 목록을 벗어나 패널로 이동 |
| 방향키 | 좌우(세로형은 상하)로 탭 사이 이동. 끝에서 순환 |
| Home·End | 첫·마지막 탭 |
| 세로 탭 | `aria-orientation="vertical"` |

```js
list.addEventListener('keydown', (e) => {
  const tabs = [...list.querySelectorAll('[role=tab]')]
  const i = tabs.indexOf(e.target)
  const to = { ArrowRight: i + 1, ArrowLeft: i - 1,
    Home: 0, End: tabs.length - 1 }[e.key]
  if (to === undefined) return
  e.preventDefault()
  tabs.at(to % tabs.length).focus()
})
```

- 활성 탭만 `tabindex="0"`이고 나머지는 `-1`인 roving tabindex 구조입니다(자세히는 28편).
- 활성화 방식은 둘입니다. 자동 활성화는 포커스를 받으면 바로 패널을 바꿉니다. 패널 내용이 미리 로드되어 있을 때 권장됩니다. 수동 활성화는 방향키로 포커스만 옮기고 Space나 Enter로 활성화합니다. 패널을 불러오는 데 시간이 걸릴 때 씁니다.
- 패널 안에 포커스 가능한 요소가 없으면 패널에 `tabindex="0"`을 줘서 Tab 순서에 포함합니다.
- 비활성 패널은 `hidden`으로 접근성 트리에서 뺍니다.
- 선택된 탭을 URL의 해시나 쿼리와 동기화하면 링크로 공유할 수 있습니다(자세히는 34편).

## Modal Dialog

모달 다이얼로그는 배경 조작을 막고 사용자의 응답을 받는 오버레이입니다. 네이티브 `dialog`의 `showModal()`을 씁니다. Baseline 널리 지원(2022)입니다.

```html
<dialog id="dlg" aria-labelledby="t">
  <h2 id="t">삭제할까요?</h2>
  <form method="dialog">
    <button value="cancel">취소</button>
    <button value="ok">삭제</button>
  </form>
</dialog>
```

```js
opener.addEventListener('click', () => dlg.showModal())
dlg.addEventListener('close', () => {
  if (dlg.returnValue === 'ok') removeItem()
})
```

| 항목 | 규칙 |
|------|------|
| 역할·이름 | `dialog` 역할. `aria-labelledby`(보이는 제목) 또는 `aria-label` 필요 |
| 설명 | `aria-describedby`는 선택. 표나 목록처럼 구조를 탐색해야 하는 내용이면 생략 |
| 열 때 | 안의 적절한 요소로 포커스 이동. 첫 상호작용 요소가 기본이고, 내용이 길면 `tabindex="-1"`인 정적 요소가 나음 |
| Tab | 안에서만 순환 |
| Escape | 닫기 |
| 닫을 때 | 열기 전 요소로 포커스 복귀(요소가 사라졌다면 가까운 안정된 요소) |

- `showModal()`은 Top Layer 승격, 배경 비활성(inert), `::backdrop`, Escape 처리, 포커스 복귀를 대신합니다(자세히는 44편, 45편).
- `form method="dialog"`로 닫으면 누른 버튼의 `value`가 `returnValue`가 됩니다.
- 직접 만든 모달이면 `role="dialog"`와 `aria-modal="true"`를 쓰되, `aria-modal`은 코드가 실제로 배경 조작을 막고 시각적으로도 배경을 가릴 때만 붙입니다. 조건이 하나라도 빠지면 보조 기술 사용자에게 큰 장벽이 됩니다.
- 배경 클릭으로 닫기는 `dialog`의 `click`에서 `e.target === dlg`를 확인하면 됩니다. `dialog` 자체에 패딩을 주면 패딩 영역 클릭도 `dialog`가 대상이 되므로, 패딩은 안쪽 래퍼에 줍니다. `closedby` 속성은 미Baseline입니다.
- 모달 위에 다른 모달을 열 때는 스택으로 관리합니다(45편).

**흔한 실수:** 모달이 열릴 때 포커스를 옮기지 않거나 닫을 때 복귀시키지 않는 것입니다. 키보드 사용자는 모달 뒤의 페이지 어딘가에서 포커스를 잃습니다.

## Alert·Alert Dialog

알림에는 두 패턴이 있고 차이는 작업을 중단시키느냐입니다.

| 항목 | Alert | Alert Dialog |
|------|-------|--------------|
| 역할 | `alert` | `alertdialog` |
| 작업 중단 | 아니오 | 예(모달) |
| 포커스 이동 | 하지 않음 | 안으로 이동 |
| 키보드 | 해당 없음 | 모달 다이얼로그와 같음 |
| 용도 | 저장 실패, 유효성 오류 같은 알림 | 삭제 확인, 오류 확인 같은 응답 요구 |

```html
<div id="live" role="alert"></div>
```

```js
live.textContent = '저장하지 못했습니다.'  // 스크린 리더가 읽음
```

- `alert`는 동적으로 렌더링되면 대부분의 스크린 리더가 자동으로 읽어 줍니다. 포커스를 옮기면 안 됩니다. 사용자가 하던 작업이 끊깁니다.
- 알림 영역은 내용이 들어가기 전에 DOM에 존재하게 둡니다. 영역과 내용을 동시에 삽입하면 일부 보조 기술이 읽지 못할 수 있어 빈 컨테이너를 먼저 두고 내용을 채웁니다(자세히는 27편의 `aria-live`).
- 알림이 너무 빨리 사라지면 읽을 시간이 부족합니다. 자주 띄워도 방해가 됩니다. 중단이 필요한 경우에만 Alert Dialog를 씁니다.
- Alert Dialog는 `role="alertdialog"`, `aria-modal="true"`, 메시지를 가리키는 `aria-describedby`, 제목(`aria-labelledby` 또는 `aria-label`)을 갖춥니다. 네이티브는 `dialog`에 `role="alertdialog"`를 붙여 `showModal()`로 엽니다.
- 열 때 포커스를 안쪽 적절한 요소로 옮기고 닫을 때 복귀시키는 규칙은 모달 다이얼로그와 같습니다.

## Tooltip / Popover

툴팁은 요소가 키보드 포커스를 받거나 마우스가 올라갔을 때 보조 정보를 보이는 팝업입니다. 팝업 안에 포커스 가능한 요소가 있으면 툴팁이 아니라 팝오버(비모달 다이얼로그)로 만듭니다.

| 항목 | Tooltip | Popover |
|------|---------|---------|
| 안의 상호작용 요소 | 없음 | 있음 |
| 역할 | `tooltip` | 내용에 맞는 역할(`dialog` 등) |
| 연결 | 트리거의 `aria-describedby` | 트리거의 `popovertarget` |
| 포커스 | 트리거에 유지, 툴팁은 포커스를 받지 않음 | 열린 뒤 다음 Tab으로 진입 |
| 닫기 | Escape, blur, 마우스가 트리거와 툴팁을 모두 벗어남 | light dismiss, Escape |

```html
<button aria-describedby="tip">삭제</button>
<div id="tip" role="tooltip" popover="manual">
  되돌릴 수 없습니다
</div>
```

```js
const show = () => tip.showPopover()
const hide = () => tip.hidePopover()
btn.addEventListener('pointerenter', show)
btn.addEventListener('focus', show)
btn.addEventListener('pointerleave', hide)
btn.addEventListener('blur', hide)
document.addEventListener('keydown', (e) => {
  if (e.key === 'Escape') hide()
})
```

- 마우스로 연 툴팁은 포인터가 트리거나 툴팁 위에 있는 동안 유지합니다. 이동 중에 사라지면 내용을 읽을 수 없습니다.
- APG의 툴팁 패턴은 팀 합의가 아직 없다고 명시한 진행 중 패턴입니다. 핵심 정보를 툴팁에만 두지 않습니다. 터치 기기에는 호버가 없습니다.
- `popover` 속성은 요소를 Top Layer에 올리고 `popovertarget`으로 트리거와 선언적으로 연결합니다. 연결된 트리거에는 `aria-expanded`와 `aria-details`가 암묵적으로 적용되고, 팝오버는 모달이 아니라서 페이지의 다른 곳을 계속 조작할 수 있습니다.
- 팝오버 유형은 셋입니다. `auto`는 light dismiss와 Escape가 되고 한 번에 하나만 열립니다(중첩 제외). `manual`은 light dismiss가 없고 여러 개가 동시에 열립니다. `hint`는 `auto` 팝오버를 닫지 않아 툴팁에 맞지만 미Baseline이므로 `manual`로 대체될 수 있게 둡니다.
- 위치 지정에 쓰는 CSS 앵커 포지셔닝은 미Baseline입니다. 지원하지 않는 브라우저를 위해 `getBoundingClientRect()` 계산을 대비합니다(자세히는 6편, 45편).
- 호버 지연, 호버로 여는 `interestfor`는 미Baseline입니다(자세히는 45편).

## Dropdown Menu

드롭다운 메뉴는 버튼을 눌러 동작 목록을 여는 메뉴 버튼 패턴입니다. 사이트 이동 링크가 아니라 응용 프로그램의 동작 목록(복사, 이름 바꾸기, 삭제 같은 명령)에 씁니다.

```html
<button id="mb" popovertarget="m" aria-haspopup="menu">
  편집
</button>
<div id="m" popover role="menu" aria-labelledby="mb">
  <button role="menuitem" tabindex="-1">복사</button>
  <button role="menuitem" tabindex="-1">삭제</button>
</div>
```

| 위치 | 키 | 동작 |
|------|----|------|
| 메뉴 버튼 | Enter·Space | 메뉴를 열고 첫 항목으로 포커스 이동 |
| 메뉴 버튼 | Down·Up Arrow | (선택) 메뉴를 열고 첫·마지막 항목으로 이동 |
| 메뉴 | Down·Up Arrow | 다음·이전 항목(끝에서 순환 가능) |
| 메뉴 | Home·End | 첫·마지막 항목 |
| 메뉴 | Enter·Space | 항목 실행. 대개 메뉴를 닫고 포커스를 버튼으로 복귀 |
| 메뉴 | Escape | 닫고 포커스를 버튼으로 복귀 |
| 메뉴 | Tab | 메뉴를 벗어남 |

```js
const items = [...m.querySelectorAll('[role=menuitem]')]
m.addEventListener('toggle', (e) => {
  if (e.newState === 'open') items[0].focus()
})
m.addEventListener('keydown', (e) => {
  const i = items.indexOf(e.target)
  const n = items.length
  if (e.key === 'ArrowDown') items[(i + 1) % n].focus()
  if (e.key === 'ArrowUp') items[(i + n - 1) % n].focus()
})
```

- 버튼에 `aria-haspopup`을 `menu`로 주고 `aria-expanded`로 열림을 알립니다. `popovertarget`을 쓰면 `aria-expanded`는 암묵적으로 적용됩니다.
- 메뉴 컨테이너는 `role="menu"`, 항목은 `menuitem`(체크 상태가 있으면 `menuitemcheckbox`, 하나만 선택되는 그룹이면 `menuitemradio`)입니다.
- 항목 포커스는 roving tabindex 또는 컨테이너의 `aria-activedescendant`로 관리합니다(28편).
- `popover="auto"`면 바깥 클릭과 Escape로 닫히고, Escape로 닫으면 포커스가 트리거로 돌아옵니다. 중첩 `auto` 팝오버로 하위 메뉴를 만들 수 있습니다.
- `menu` 역할은 응용 프로그램 메뉴용입니다. 링크 목록인 사이트 내비게이션에 `role="menu"`를 쓰면 방향키 규칙을 약속하게 되어 오히려 혼란스럽습니다. 그 경우는 디스클로저와 `nav`로 만듭니다.

## Menubar

메뉴바는 데스크톱 응용 프로그램의 상단 메뉴줄처럼 가로로 늘어선 최상위 메뉴 항목과 드롭다운 하위 메뉴입니다. 웹 응용 프로그램(편집기, 대시보드)의 명령 모음에 씁니다.

```html
<ul role="menubar" aria-label="편집기">
  <li role="none">
    <button role="menuitem" aria-haspopup="menu"
            aria-expanded="false" tabindex="0">파일</button>
    <ul role="menu">…</ul>
  </li>
</ul>
```

| 키 | 동작 |
|----|------|
| Left·Right Arrow | 메뉴바에서 이전·다음 최상위 항목으로 이동 |
| Down Arrow | 메뉴바 항목에서는 하위 메뉴를 열고, 메뉴 안에서는 다음 항목으로 이동 |
| Up Arrow | 메뉴 안에서 이전 항목으로 이동 |
| Enter·Space | 항목 실행 또는 하위 메뉴 열기 |
| Escape | 메뉴를 닫고 호출한 요소로 포커스 복귀 |
| Home·End | 첫·마지막 항목(순환하지 않는 구현에서) |
| Tab | 메뉴 전체를 벗어남 |

- 구조는 roving tabindex입니다. 메뉴바 전체가 탭 정류장 한 칸이며 항목은 `tabindex="0"` 하나, 나머지는 `-1`입니다.
- 하위 메뉴가 있는 항목은 `aria-haspopup`과 `aria-expanded`를 갖습니다.
- 위 메뉴 버튼 패턴과 구분은 규모입니다. 버튼 하나의 단일 메뉴는 Dropdown Menu, 여러 메뉴가 줄지어 있고 좌우 이동이 필요하면 Menubar입니다.
- 키 규칙이 많고 오류가 잦으므로 메뉴바가 정말 필요한지 먼저 판단합니다. 대부분의 웹 사이트 내비게이션은 링크 목록입니다.

## Toast

토스트는 작업 결과를 잠시 보이고 사라지는 비모달 알림입니다. 사용자 작업을 가로막지 않습니다. 구조는 세 요소의 조합입니다.

| 요소 | 담당 |
|------|------|
| Top Layer | `popover="manual"`로 `z-index`와 클리핑 문제 해결. 여러 개 동시 표시 가능 |
| live region | 보조 기술에 알림. 성공·정보는 `role="status"`, 오류는 `role="alert"` |
| 타이머 | 자동 닫기. 포커스·호버 중에는 일시 정지 |

```html
<div id="toasts" role="status"></div>
```

```js
function toast(msg, ms = 5000) {
  const el = document.createElement('div')
  el.popover = 'manual'
  el.textContent = msg
  toasts.append(el)
  el.showPopover()
  setTimeout(() => el.remove(), ms)
}
```

- 알림 영역(`toasts`)은 처음부터 DOM에 두고 토스트를 자식으로 추가합니다. 영역과 내용을 동시에 삽입하면 읽히지 않을 수 있습니다(자세히는 27편).
- 토스트는 포커스를 가져오지 않습니다. 가져오면 작업이 끊깁니다.
- 닫기 버튼이 있어야 하고, 되돌리기 같은 동작 버튼이 있는 토스트와 오류 토스트는 자동으로 사라지지 않게 합니다. 읽고 반응할 시간이 필요합니다.
- 여러 토스트가 쌓이면 위치와 순서, 최대 개수를 관리하는 매니저가 필요합니다(45편).
- 움직임은 `prefers-reduced-motion`을 확인해 줄입니다(자세히는 27편).

**흔한 실수:** 토스트를 `alert`로 남발하는 것입니다. 모든 메시지가 스크린 리더의 진행 중인 낭독을 끊어 방해가 됩니다. 긴급하지 않은 알림은 `status`를 씁니다.

## Carousel

캐러셀은 슬라이드를 한 번에 일부만 보이고 순서대로 넘기는 구조입니다. 자동 회전이 접근성 문제의 중심입니다.

| 구성 | 규칙 |
|------|------|
| 컨테이너 | `role="region"`(또는 `group`)과 `aria-roledescription="carousel"`, 이름 필요 |
| 슬라이드 | `role="group"`과 `aria-roledescription="slide"`, 이름은 "3 중 1" 같은 위치 |
| 이전·다음 버튼 | 수동으로 이동 |
| 회전 제어 | 자동 회전 시작·정지 버튼. 버튼 레이블은 상태에 따라 달라짐 |
| 슬라이드 선택(선택) | 탭 패턴 또는 버튼 그룹 |
| 슬라이드 래퍼 | 회전 중 `aria-live="off"`, 멈춘 뒤 `aria-live="polite"` |

- 자동 회전은 키보드 포커스가 캐러셀에 들어오면 멈추고, 사용자가 직접 시작하지 않는 한 재시작하지 않습니다. 마우스가 올라가도 멈춥니다.
- `prefers-reduced-motion`이 켜져 있으면 자동 회전을 시작하지 않습니다.
- 회전 제어 버튼은 레이블이 바뀌는 예외입니다(시작과 정지가 서로 다른 동작이므로). 토글 버튼의 "레이블 고정" 규칙과 헷갈리지 않게 구분합니다.

슬라이드 이동은 CSS 스크롤 스냅(Baseline 널리 지원, 2020)에 맡기면 터치 스와이프와 키보드 스크롤이 네이티브로 동작합니다.

```css
.track {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
}
.slide { flex: 0 0 100%; scroll-snap-align: start; }
```

```js
const io = new IntersectionObserver((entries) => {
  for (const en of entries) {
    en.target.inert = !en.isIntersecting
  }
}, { root: track })
slides.forEach((s) => io.observe(s))
```

- 화면에 전혀 보이지 않는 슬라이드는 `inert`로 접근성 트리와 Tab 순서에서 뺍니다. 일부라도 보이는 슬라이드는 상호작용을 막지 않도록 `isIntersecting` 기준을 씁니다(`inert`는 Baseline 2023, `IntersectionObserver`는 2019).
- 이전·다음 버튼은 `track.scrollBy`나 `scrollTo`로 슬라이드 폭만큼 이동합니다. 스크롤 끝 감지는 `scrollend`(Baseline 2025)를 쓸 수 있습니다.
- CSS만으로 스크롤 마커와 버튼을 만드는 CSS Carousel 기능(`scroll-markers`, `scroll-buttons`)은 미Baseline입니다.
- 현재 슬라이드 번호를 알리는 레이블("3 중 1")은 슬라이드가 바뀔 때 갱신합니다.

## 핵심 정리

- 의미로 고릅니다. 제자리에서 펼치면 Disclosure·Accordion·Tabs, 배경을 막으면 Modal Dialog, 비모달이면 Popover, 동작 목록이면 Menu, 알림이면 Toast·Alert입니다.
- 네이티브가 있으면 먼저 씁니다. `details`(`name`으로 아코디언), `dialog`와 `showModal()`, `popover` 속성이 포커스·Escape·Top Layer를 대신 처리합니다.
- Tabs·Menubar·Menu는 roving tabindex와 방향키·Home·End 규칙을 직접 구현하고, 모달은 열 때 포커스 이동과 닫을 때 복귀가 필수입니다.
- `alert`와 `status`는 포커스를 옮기지 않고 live region으로 알리며, 중단이 필요하면 `alertdialog`를 씁니다. 툴팁은 포커스 가능한 내용을 가질 수 없고 그런 경우는 팝오버입니다.
- 캐러셀은 자동 회전을 포커스·호버 시 멈추고, 스크롤 스냅과 `inert`로 이동과 숨김을 처리합니다.
