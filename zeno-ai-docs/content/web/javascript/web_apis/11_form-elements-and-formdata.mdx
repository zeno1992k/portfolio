## HTMLFormElement

`HTMLFormElement`는 `form` 요소의 DOM 인터페이스입니다. 폼에 속한 컨트롤 목록과 제출 방식을 속성으로 노출하고, 제출·초기화 메서드를 제공합니다.

| 속성 | 읽을 때 얻는 값 | 정규화 규칙 |
|------|-----------------|-------------|
| `action` | 절대 URL 문자열 | 속성이 없으면 문서의 URL |
| `method` | `get`, `post`, `dialog` | 대소문자 무시, 그 밖의 값은 `get` |
| `enctype` | 인코딩 MIME 타입 | 세 값 이외는 `application/x-www-form-urlencoded` |
| `target` | 탐색 대상 이름 | 속성 값 그대로 |
| `noValidate` | 검증 생략 여부(불리언) | 제약 검증은 12편 |

```js
// <form action="/save" method="POST" enctype="foo">
form.action  // 'https://example.com/save' (절대 URL로 해석)
form.method  // 'post'
form.enctype // 'application/x-www-form-urlencoded'
form.method = 'PUT'
form.method  // 'get' (잘못된 값은 get으로 정규화)
```

- `enctype` 세 값은 `application/x-www-form-urlencoded`(기본), `multipart/form-data`(파일 업로드), `text/plain`(디버깅용, 파싱이 모호해 실무에서 쓰지 않음)입니다.
- `method="get"`이면 `enctype`과 무관하게 데이터가 URL 쿼리 문자열에 붙습니다.
- `method="dialog"`는 서버로 보내지 않고 가장 가까운 `dialog`를 닫습니다(자세히는 44편).
- 제출 버튼의 `formaction`, `formmethod`, `formenctype`, `formtarget`, `formnovalidate`는 폼의 같은 속성보다 우선합니다.

### elements와 컨트롤 접근

`form.elements`는 폼에 속한 컨트롤의 살아 있는 컬렉션(`HTMLFormControlsCollection`)입니다. `form.length`는 이 컬렉션의 길이입니다.

- 포함되는 요소: `button`, `fieldset`, `input`, `output`, `select`, `textarea`, `object`, 폼 연관 커스텀 요소(26편).
- 제외되는 요소: `input type="image"`. `label`, `datalist`, `progress`, `meter`는 애초에 폼 연관 컨트롤이 아닙니다.
- 폼 밖에 있어도 `form` 속성으로 연결된 컨트롤은 포함됩니다.
- 이름이 같은 컨트롤이 여럿이면 `RadioNodeList`가 반환되고, 라디오 묶음에서는 `.value`가 체크된 항목의 값입니다.

```js
form.elements.q          // name이 q인 컨트롤 하나
form.elements.namedItem('q') // 같은 결과
form.elements[0]         // 인덱스 접근
form.elements.r.value    // 'y' (name=r 라디오 중 체크된 값)
form.q                   // 단축 접근. 같은 컨트롤
```

흔한 실수: 컨트롤의 `name`이 폼의 내장 속성 이름과 같으면 컨트롤이 내장 속성을 가립니다. `name="action"`인 입력이 있으면 `form.action`은 URL 문자열이 아니라 그 `input` 요소를 반환합니다. `name="submit"`이면 `form.submit()`이 함수가 아니게 되어 호출이 실패합니다. 속성 값은 `form.getAttribute('action')`으로 읽고, 컨트롤은 `form.elements`로 접근하면 충돌이 없습니다.

## submit 이벤트와 submitter

`submit` 이벤트는 폼 제출이 시작될 때 폼에서 발생합니다. 버블링하고 취소할 수 있으며, `preventDefault()`를 호출하면 제출이 중단됩니다.

```js
form.addEventListener('submit', (event) => {
  event.preventDefault()          // 페이지 이동 취소
  event.submitter                 // 제출을 일으킨 버튼 또는 null
  event.submitter?.name           // 'go'
})
```

`event.submitter`는 제출을 일으킨 제출 버튼(`SubmitEvent` 인터페이스의 속성)입니다.

| 제출 경로 | submitter |
|-----------|-----------|
| 제출 버튼 클릭 | 그 버튼 |
| 텍스트 입력에서 Enter(암묵적 제출) | 폼의 기본 버튼. 제출 버튼이 없으면 `null` |
| `requestSubmit()` | `null` |
| `requestSubmit(button)` | 인수로 준 버튼 |
| `submit()` | 이벤트가 발생하지 않는다 |

- 기본 버튼은 폼 안에서 트리 순서가 가장 앞인 제출 버튼입니다. 제출 버튼은 `type="submit"`(기본값)인 `button`과 `input type="submit"`·`type="image"`입니다.
- `type="button"` 버튼은 제출을 일으키지 않습니다. `button`의 `type`을 생략하면 `submit`이라서 폼 안의 일반 버튼이 제출해 버리는 것이 흔한 실수입니다.
- 제출 버튼의 `formaction` 등 override 속성을 읽을 때 `event.submitter`를 씁니다. 같은 폼에 "저장"과 "임시 저장" 버튼을 두는 경우가 대표적입니다.
- 키보드 Enter가 `click` 이벤트를 기본 버튼에 보내는 방식이라 암묵적 제출에서도 버튼의 `click` 리스너가 실행됩니다(키 입력 이벤트는 10편).

## submit()과 requestSubmit()의 차이

둘 다 스크립트로 폼을 제출하지만 제출 전 과정이 다릅니다.

| 비교 | `form.submit()` | `form.requestSubmit(submitter?)` |
|------|-----------------|----------------------------------|
| submit 이벤트 | 발생하지 않음 | 발생함, 취소 가능 |
| 제약 검증 | 건너뜀 | 수행함 (실패 시 제출 중단) |
| formdata 이벤트 | 발생함 | 검증 통과 후 발생함 |
| submitter | 없음 | 인수로 지정 가능 |
| 사용자 클릭과의 동등성 | 다름 | 버튼 클릭과 같은 경로 |

```js
form.submit()                 // 검증·submit 이벤트 없이 바로 제출
form.requestSubmit()          // 클릭한 것과 같은 절차
form.requestSubmit(saveButton) // saveButton을 submitter로 제출
```

- `requestSubmit(submitter)`의 인수가 제출 버튼이 아니면 `TypeError`, 이 폼에 속하지 않으면 `NotFoundError`입니다.
- JavaScript로 제출을 가로채 `fetch`를 쓰는 폼은 `submit` 리스너에서 `preventDefault()`를 호출합니다. 다른 코드가 폼을 제출하게 하려면 `submit()`이 아니라 `requestSubmit()`을 써야 그 리스너가 실행됩니다.
- 제출 이벤트와 검증 순서: 제출 시도 → 검증(실패하면 `invalid` 이벤트 후 중단, 12편) → `submit` 이벤트 → `formdata` 이벤트 → 탐색.

## reset 이벤트

`reset` 이벤트는 폼이 초기화되기 직전에 발생하며 취소할 수 있습니다. 초기화 버튼(`type="reset"`) 클릭이나 `form.reset()`이 발생시킵니다. `form.submit()`과 달리 `form.reset()`은 이벤트를 발생시킵니다.

```js
form.addEventListener('reset', (event) => {
  if (!confirm('입력을 지울까요?')) event.preventDefault()
})
form.reset() // 이벤트 발생 → 취소되지 않으면 초기값 복원
```

- 컨트롤은 HTML 속성에 적힌 기본값으로 돌아갑니다. `value` 속성이 `defaultValue`, `checked` 속성이 `defaultChecked`, `option`의 `selected` 속성이 `defaultSelected`입니다.
- 스크립트로 바꾼 현재 값은 사라지고, 스크립트로 바꾼 `defaultValue`는 유지됩니다.
- `reset`이 일으키는 값 변경은 `input`·`change` 이벤트를 발생시키지 않습니다. 화면 상태를 값에서 계산하는 컴포넌트는 `reset`을 따로 들어야 합니다.
- `output` 요소도 `defaultValue`로 복원됩니다.

## formdata 이벤트

`formdata` 이벤트는 폼의 제출용 데이터 목록(엔트리 리스트)이 만들어진 직후 폼에서 발생합니다. 리스너가 `event.formData`를 수정하면 그 변경이 실제 제출 데이터에 반영됩니다. 취소할 수 없습니다.

```js
form.addEventListener('formdata', (event) => {
  event.formData.append('clientTime', Date.now())
  event.formData.delete('draft')
})
```

발생 시점은 두 가지입니다.

- 제출 중: `submit()`을 포함해 어떤 경로로 제출하든 탐색 직전에 발생합니다(`submit` 이벤트보다 뒤).
- `new FormData(form)`을 호출할 때마다. 이때 리스너가 붙인 값도 새 `FormData`에 들어갑니다.

흔한 실수: `formdata` 리스너에서 `new FormData(form)`을 호출하면 이벤트가 다시 발생해 무한 재귀가 됩니다. 이벤트 객체의 `event.formData`를 쓰십시오.

## FormData

`FormData`는 이름–값 쌍의 목록을 담는 객체입니다. 값은 문자열 또는 `File`입니다. 폼 제출 데이터를 표현하고, `fetch`의 요청 본문으로 바로 쓸 수 있습니다(자세히는 36편).

### 생성자

```js
new FormData()                   // 빈 목록
new FormData(form)               // 폼의 현재 값으로 채움
new FormData(form, submitter)    // 제출 버튼의 이름·값도 포함
```

`form` 인수로 채울 때의 규칙은 실제 제출과 같습니다.

| 컨트롤 | 목록에 들어가는가 |
|--------|-------------------|
| `name`이 없거나 빈 문자열 | 아니오 |
| `disabled` 컨트롤, 비활성 `fieldset` 안의 컨트롤 | 아니오 |
| 체크되지 않은 체크박스·라디오 | 아니오 |
| 체크된 체크박스(`value` 속성 없음) | 예, 값 `on` |
| `select` | 선택된 옵션마다 한 쌍 |
| 파일을 고르지 않은 `input type="file"` | 예, 이름이 빈 문자열인 빈 `File` 하나 |
| 제출 버튼 | `submitter`로 지정한 것만 |
| `input type="image"`가 submitter | `이름.x`, `이름.y` 두 쌍 |

- 폼 밖에서 `form` 속성으로 연결된 컨트롤도 포함됩니다.
- 비어 있어도 이름이 있으면 들어갑니다. 체크박스 `value=""`는 빈 문자열 값으로 들어갑니다.
- `submitter`가 제출 버튼이 아니면 `TypeError`, 폼 소속이 아니면 `NotFoundError`입니다.
- 생성자의 두 번째 인수(`submitter`)는 `formaction` 같은 override에는 영향을 주지 않고, 버튼의 이름과 값을 목록에 넣는 용도입니다.

### 메서드

| 메서드 | 동작 |
|--------|------|
| `append(name, value, filename?)` | 끝에 추가. 같은 이름이 있어도 덮지 않음 |
| `set(name, value, filename?)` | 같은 이름 항목 전체를 하나로 교체. 없으면 끝에 추가 |
| `get(name)` | 첫 번째 값. 없으면 `null` |
| `getAll(name)` | 같은 이름의 모든 값 배열. 없으면 `[]` |
| `has(name)` | 존재 여부 |
| `delete(name)` | 같은 이름의 모든 항목 삭제 |
| `entries()`, `keys()`, `values()`, `forEach()` | 순회. `for...of`는 `entries()`와 같음 |

```js
const fd = new FormData()
fd.append('k', 1)     // 숫자는 문자열 '1'로 변환
fd.append('k', '2')
fd.append('z', 'z')
fd.set('k', '3')      // k가 첫 위치에서 하나로 교체
Array.from(fd)        // [['k','3'], ['z','z']]
fd.get('none')        // null
fd.getAll('none')     // []
```

- `set`은 교체된 항목이 처음 등장한 위치를 유지합니다. 같은 이름이 여러 개면 첫 항목만 값을 바꾸고 나머지는 제거합니다.
- 값이 `Blob`이면 `File`로 변환되어 저장되고, 파일 이름은 세 번째 인수가 없을 때 `blob`입니다. `File`이면 원래 이름이 유지되며 세 번째 인수로 바꿀 수 있습니다.
- 문자열·`Blob` 이외의 값은 문자열로 변환됩니다. `null`은 `'null'`이 됩니다.
- 같은 이름이 여럿이라는 점이 객체 변환에서 문제가 됩니다. `Object.fromEntries(fd)`는 같은 이름 중 마지막 값만 남기고, 파일 값은 `File` 객체 그대로입니다. 다중 선택·체크박스 묶음은 `getAll`로 읽어야 합니다.

```js
// name=a 입력 둘, 값 '1'과 '2'
Object.fromEntries(new FormData(form)) // { a: '2' }  ← 1이 사라짐
new FormData(form).getAll('a')         // ['1', '2']
```

## FormData와 URLSearchParams·multipart 인코딩

`FormData`는 값 목록일 뿐이고, 전송할 때 본문 형식으로 인코딩됩니다. 형식은 폼의 `enctype`, 또는 `fetch` 본문에 넘긴 객체의 종류가 정합니다.

| 본문 | Content-Type | 파일 전송 |
|------|--------------|-----------|
| `URLSearchParams` | `application/x-www-form-urlencoded;charset=UTF-8` | 불가 |
| `FormData` | `multipart/form-data; boundary=...` | 가능 |
| 폼 제출(`enctype` 기본) | `application/x-www-form-urlencoded` | 불가(파일 이름만 전송) |

```js
fetch('/save', { method: 'POST', body: new FormData(form) })
fetch('/save', { method: 'POST', body: new URLSearchParams(
  new FormData(form)) }) // 문자열 값만 있을 때
```

- `FormData`를 `fetch` 본문으로 줄 때 `Content-Type` 헤더를 직접 쓰면 안 됩니다. 브라우저가 경계 문자열(boundary)을 포함해 자동으로 붙이며, 직접 지정하면 경계가 어긋나 서버가 파싱하지 못합니다.
- `new URLSearchParams(formData)`는 파일 값을 `[object File]` 문자열로 바꿔 버립니다. 파일이 있으면 `FormData` 그대로 보내십시오.
- JSON으로 보내려면 `JSON.stringify(Object.fromEntries(fd))`를 쓰되 같은 이름 중복과 파일을 직접 처리해야 합니다.

### urlencoded 형식

`이름=값`을 `&`로 잇고 공백은 `+`, 영문자·숫자·`*-._` 이외는 `%XX`(UTF-8 바이트)로 바꿉니다.

```text
a+b=x%26y*&t=l1%0Al2
```

### multipart 형식

항목마다 경계선으로 구분된 부분(part)이 되고, 파일 부분에는 `filename`과 `Content-Type`이 붙습니다. 줄바꿈은 CRLF입니다.

```text
--경계
Content-Disposition: form-data; name="t"

l1
l2
--경계
Content-Disposition: form-data; name="f"; filename="a.txt"
Content-Type: text/plain

hi
--경계--
```

- 문자열 값의 줄바꿈은 인코딩 때 CRLF로 정규화됩니다. `textarea`의 `\n`이 서버에는 `\r\n`으로 도착하는 이유입니다. `URLSearchParams`는 정규화하지 않아 `%0A`로 나갑니다.
- 파일 업로드는 `enctype="multipart/form-data"`가 필요합니다. 기본 `enctype`으로 파일 입력을 제출하면 파일 내용 없이 파일 이름만 전송됩니다.
- 파일 객체와 `Blob` 자체는 48편에서 다룹니다.

## 컨트롤 값 API

컨트롤의 현재 값은 속성이 아니라 DOM 속성(프로퍼티)으로 읽고 씁니다. 같은 이름의 HTML 속성은 초기값(`defaultValue`)만 나타냅니다.

| 속성 | 대상 | 타입 |
|------|------|------|
| `value` | 대부분의 `input`, `textarea`, `select` | 문자열 |
| `valueAsNumber` | 숫자·날짜·시간·`range` 입력 | 숫자, 변환 불가 시 `NaN` |
| `valueAsDate` | `date`, `month`, `week`, `time` | `Date` 또는 `null` |
| `checked` | `checkbox`, `radio` | 불리언 |
| `indeterminate` | `checkbox`(라디오는 표시만) | 불리언 |
| `files` | `input type="file"` | `FileList` |

### value

- 항상 문자열입니다. `type="number"`도 `'12.5'`를 반환합니다.
- 체크박스와 라디오의 `value`는 제출될 값이며 기본값은 `'on'`입니다. 체크 상태와 무관합니다.
- 값을 `value`에 대입하면 해당 입력 유형에서 유효하지 않은 문자열은 정규화되어 `''`가 됩니다. 예를 들어 `type="date"`에 `'abc'`를 넣으면 빈 문자열이 됩니다.
- `value`를 스크립트로 바꿔도 `input`·`change` 이벤트는 발생하지 않습니다(이벤트는 10편).
- `type="file"`의 `value`는 `C:\fakepath\이름` 형태로, 경로를 숨기기 위해 가짜 경로를 반환합니다. 대입은 빈 문자열만 허용하고 그 밖의 값은 `InvalidStateError`입니다.

### valueAsNumber와 valueAsDate

```js
// 입력 type="number" value="12.5"
n.valueAsNumber        // 12.5
// type="date" value="2026-10-05"
d.valueAsNumber        // 1791158400000 (UTC 자정의 밀리초)
d.valueAsDate          // Date: 2026-10-05T00:00:00Z
// type="time" value="09:30"
t.valueAsNumber        // 34200000 (자정 이후 밀리초)
// type="month" value="2026-10"
m.valueAsNumber        // 681 (1970-01부터 지난 개월 수)
```

| 유형 | valueAsNumber 단위 | valueAsDate |
|------|--------------------|-------------|
| `number`, `range` | 그 숫자 | `null` |
| `date` | 1970-01-01T00:00Z부터의 밀리초 | UTC 자정의 `Date` |
| `time` | 자정부터의 밀리초 | 1970-01-01의 해당 시각(UTC) `Date` |
| `month` | 1970-01부터의 개월 수 | 그 달 1일 UTC 자정 `Date` |
| `week` | 1970년 첫 주 월요일부터의 밀리초 | 그 주 월요일 UTC 자정 `Date` |
| `datetime-local` | 입력 값을 UTC로 간주한 밀리초 | 항상 `null` |
| `text` 등 기타 | `NaN` | `null` |

- 값이 비었거나 유효하지 않으면 `valueAsNumber`는 `NaN`입니다.
- `valueAsDate`는 UTC 기준입니다. 지역 시간대로 출력하면 하루가 어긋나 보일 수 있습니다. 한국(UTC+9)에서 `2026-10-05`의 `valueAsDate.toString()`은 9시로 나옵니다.
- 대입도 됩니다. `n.valueAsNumber = 3`은 `value`를 `'3'`으로, `d.valueAsDate = new Date(Date.UTC(2027, 0, 31))`은 `value`를 `'2027-01-31'`로 만듭니다.
- 지원하지 않는 유형에 `valueAsDate`를 대입하면 `InvalidStateError`입니다.
- `datetime-local`은 `valueAsDate`가 `null`이므로 값 문자열을 직접 파싱하거나 `valueAsNumber`를 UTC 기준으로 해석해야 합니다.

### checked와 indeterminate

- `checked`는 현재 체크 상태이고, HTML 속성 `checked`는 초기 상태(`defaultChecked`)입니다.
- 같은 `name`의 라디오는 한 그룹이며 하나를 체크하면 나머지가 해제됩니다. 같은 폼(또는 폼 없는 같은 트리) 안에서만 묶입니다.
- `indeterminate`는 체크박스를 "일부 선택" 모양으로 표시하는 값입니다. HTML 속성이 없어 스크립트로만 설정합니다.
- 체크박스는 `indeterminate`여도 `checked`는 그대로이고 제출에도 영향이 없습니다. 값은 `checked`만 봅니다. 사용자가 클릭하면 `checked`가 토글되고 `indeterminate`는 `false`가 됩니다.

```js
box.indeterminate = true // 반쯤 선택 표시
box.checked              // false (변함 없음)
box.click()         // 사용자 클릭과 같음
box.checked         // true
box.indeterminate   // false (클릭으로 해제)
```

흔한 실수: "전체 선택" 체크박스를 자식 상태에 맞추려고 `indeterminate`를 `checked`와 같은 의미로 쓰는 경우입니다. 자식 일부만 체크되면 `checked=false`, `indeterminate=true`로 두고, 제출 값은 자식에서 가져옵니다.

### files

`files`는 선택한 파일의 읽기 전용 `FileList`입니다. 선택을 바꾸는 방법은 사용자가 고르는 것과 `input.files = dataTransfer.files`(`FileList` 대입)뿐입니다. 선택을 지우려면 `input.value = ''`입니다. 파일 읽기와 `File`·`Blob`은 48편, 드롭으로 받는 `DataTransfer`는 49편에서 다룹니다.

## select와 option API

`select` 요소는 `option`(과 `optgroup`) 목록에서 하나 이상을 고르는 컨트롤입니다. `multiple` 속성이 있으면 복수 선택입니다.

| 속성·메서드 | 설명 |
|-------------|------|
| `value` | 선택된 첫 옵션의 값. 선택이 없으면 `''` |
| `selectedIndex` | 선택된 첫 옵션의 인덱스. 없으면 `-1` |
| `selectedOptions` | 선택된 옵션의 살아 있는 `HTMLCollection` |
| `options` | 모든 옵션의 `HTMLOptionsCollection` |
| `length` | 옵션 수. 대입으로 개수를 줄이거나 늘림 |
| `add(option, before?)` | 옵션 추가. `before`는 요소 또는 인덱스 |
| `remove(index)` | 인덱스의 옵션 제거 |

```js
sel.value = 'b'          // 값이 'b'인 첫 옵션 선택
sel.selectedIndex = 2    // 세 번째 옵션 선택
sel.selectedIndex = -1   // 모두 해제 → value는 ''
sel.value = 'zzz'        // 일치하는 값이 없으면 해제됨
sel.add(new Option('D', 'd', false, true)) // 끝에 추가·선택
sel.add(new Option('Z', 'z'), 0)           // 맨 앞에 추가
sel.remove(0)                              // 첫 옵션 삭제
```

- `new Option(text, value, defaultSelected, selected)`로 옵션을 만듭니다. `value`를 생략하면 옵션의 `value`는 텍스트와 같습니다.
- `option`의 `selected`는 현재 선택 상태, `defaultSelected`는 HTML 속성입니다. `text`는 공백이 정리된 텍스트, `label`은 표시용 문자열, `index`는 위치입니다.
- 복수 선택(`multiple`)에서 `value`는 첫 선택 옵션의 값만 줍니다. 모두 읽으려면 `selectedOptions`를 씁니다.

```js
// <select multiple> A(선택) B C(선택)
sel.value  // 'A'
Array.from(sel.selectedOptions, (o) => o.value) // ['A', 'C']
```

- 한 줄짜리 단일 선택 `select`에서 선택된 옵션이 없으면 브라우저가 첫 옵션을 선택 상태로 만듭니다. 그래서 처음부터 `selectedIndex`는 `0`입니다. 선택 해제는 `selectedIndex = -1`을 대입해야만 가능하고, `multiple`이거나 `size`가 2 이상이면 처음부터 선택이 없을 수 있습니다.
- `remove`가 둘로 겹칩니다. `select.remove(index)`는 인덱스를 받는 옵션 제거이고, 인수 없이 `select.remove()`는 `ChildNode.remove()`로 `select` 요소 자체를 지웁니다.
- `select.showPicker()`로 옵션 목록 팝업을 열 수 있습니다(조건은 `showPicker` 절 참고).
- 옵션을 많이 바꿀 때는 `select.replaceChildren(...options)`가 한 번에 바꿔 효율적입니다.

## 텍스트 컨트롤 선택 API

텍스트 입력 안에서 선택 영역과 커서 위치를 다루는 API입니다. 문서 전체의 선택과 `Range`는 별개이며 13편에서 다룹니다.

| 속성·메서드 | 설명 |
|-------------|------|
| `selectionStart`, `selectionEnd` | 선택 구간의 시작·끝 위치. 같으면 커서 |
| `selectionDirection` | `'forward'`, `'backward'`, `'none'` |
| `select()` | 전체 선택 |
| `setSelectionRange(start, end, dir?)` | 구간 지정 |
| `setRangeText(text, start?, end?, mode?)` | 구간의 텍스트 교체 |

- 위치는 문자 수가 아니라 UTF-16 코드 단위 오프셋입니다. 이모지 하나가 2로 셉니다.
- 지원 대상은 `textarea`와 `input`의 `text`, `search`, `url`, `tel`, `password` 유형입니다.
- `email`, `number`, `date` 등 다른 유형은 `selectionStart`가 `null`이고 `setSelectionRange`는 `InvalidStateError`를 던집니다. `email` 입력의 커서 위치가 필요하면 `type="text"`와 `inputmode` 조합을 쓰는 방법이 있습니다.

```js
input.value = 'Hello World'
input.setSelectionRange(0, 5)
input.selectionEnd // 5
input.setRangeText('Bye', 0, 5, 'select')
input.value        // 'Bye World'
input.selectionEnd // 3 (새 텍스트 Bye가 선택됨)
```

`setRangeText`의 네 번째 인수 `mode`는 교체 뒤 선택을 어떻게 둘지 정합니다.

| mode | 교체 후 선택 |
|------|--------------|
| `select` | 새 텍스트 전체를 선택 |
| `start` | 새 텍스트 앞에 커서 |
| `end` | 새 텍스트 뒤에 커서 |
| `preserve`(기본) | 기존 선택을 최대한 유지 |

- 구간 인수 `start`·`end`를 생략하면 현재 선택 구간을 교체합니다. 구간이 커서(시작과 끝이 같음)이면 그 위치에 삽입합니다.
- `value`를 대입하면 커서가 끝으로 이동합니다(`'abcdef'` 대입 직후 `[6, 6]`).
- `select`·`selectionStart` 대입 모두 포커스를 옮기지 않습니다. 화면에서 선택을 보이려면 컨트롤이 포커스를 가진 상태여야 합니다.
- 이 값은 사용자가 입력 중에도 계속 변하므로, 서식 적용(전화번호 하이픈 등)에서는 값 변경 전에 커서를 저장하고 변경 후에 복원합니다.

## label과 control·labels

`label` 요소는 폼 컨트롤에 이름(텍스트)을 붙입니다. 라벨을 클릭하면 연결된 컨트롤에 클릭이 전달되어 포커스·체크가 일어납니다. 접근성 이름의 소스가 되기도 합니다(27편).

연결 방법은 두 가지입니다.

```html
<label for="email">Email</label> <input id="email">
<label>Name <input name="n"></label>
```

- `for` 속성: 같은 트리의 `id`를 가리킵니다.
- 감싸기: `for`가 없으면 라벨 안의 첫 번째 라벨 가능 후손이 컨트롤입니다.
- 라벨 가능한 요소: `button`, `input`(`hidden` 제외), `meter`, `output`, `progress`, `select`, `textarea`, 폼 연관 커스텀 요소.

| API | 설명 |
|-----|------|
| `label.control` | 연결된 컨트롤 요소 또는 `null` |
| `label.htmlFor` | `for` 속성 값 (문자열) |
| `label.form` | 컨트롤의 폼 |
| `control.labels` | 컨트롤에 연결된 모든 라벨의 `NodeList` |

```js
label.control      // <input id="email">
input.labels.length // 1
label.htmlFor = 'form1' // 라벨 가능한 요소가 아니면
label.control      // null
```

- 컨트롤 하나에 라벨 여러 개가 연결될 수 있고, `labels`가 모두 반환합니다. 가리키는 대상이 라벨 불가 요소(`form`, `div` 등)이면 `control`은 `null`입니다.
- 라벨 안에 버튼·링크 같은 인터랙티브 요소가 있으면 그 요소를 클릭했을 때는 컨트롤로 전달되지 않습니다.
- `for`에 걸린 id가 중복되면 트리 순서상 첫 요소가 대상입니다.

## form 속성으로 바깥 컨트롤 연결

폼 연관 요소의 `form` 속성에 폼의 `id`를 쓰면, 그 요소가 폼의 후손이 아니어도 그 폼에 속합니다. 같은 컨트롤이 `form.elements`와 제출 데이터에 포함됩니다.

```html
<form id="search"> ... </form>
<input name="q" form="search">
<button form="search">검색</button>
```

- 폼 소유자(form owner) 규칙: `form` 속성이 있으면 그 `id`의 `form` 요소가 소유자이고, 없으면 가장 가까운 조상 `form`입니다.
- `form` 속성의 id가 존재하지 않거나 `form` 요소가 아니면 소유자는 없습니다. 조상이 `form`이어도 무시됩니다.
- 컨트롤의 `form` 프로퍼티는 이 소유자(또는 `null`)를 읽기 전용으로 반환합니다. 소유자를 바꾸려면 속성을 바꿔야 합니다.
- 대상 요소: `button`, `fieldset`, `input`, `object`, `output`, `select`, `textarea`, 폼 연관 커스텀 요소.
- 쓰임: 표 셀이나 레이아웃 때문에 컨트롤이 폼 밖에 있어야 할 때, 폼 중첩이 금지되어 있어 한 영역에서 두 폼을 써야 할 때입니다. `form` 요소를 다른 `form` 안에 넣을 수는 없습니다.

## autocomplete 속성과 브라우저 자동 완성

`autocomplete` 속성은 입력 칸의 자동 완성 방식을 브라우저에 알립니다. `form`, `input`, `select`, `textarea`에서 쓰고, DOM 프로퍼티 `autocomplete`로 읽고 씁니다.

- `on`(기본): 브라우저가 이전 입력이나 저장된 정보를 제안해도 됩니다.
- `off`: 자동 완성을 원하지 않음을 알립니다. 강제가 아닙니다. 비밀번호 관리자나 로그인 칸은 이 값을 무시하는 경우가 많습니다.
- 토큰: 칸의 의미를 구체적으로 알려 주어 정확히 채우게 합니다.

| 토큰 | 의미 |
|------|------|
| `username`, `current-password` | 로그인 |
| `new-password` | 새 비밀번호(관리자가 생성 제안) |
| `one-time-code` | 일회용 인증 코드 |
| `email`, `tel` | 이메일, 전화번호 |
| `given-name`, `family-name`, `name` | 이름 |
| `street-address`, `postal-code`, `country` | 주소 |
| `cc-number`, `cc-exp`, `cc-csc` | 카드 번호·만료·보안 코드 |

```html
<input name="id" autocomplete="username">
<input type="password" autocomplete="current-password">
<input autocomplete="shipping postal-code">
```

- 여러 토큰을 공백으로 이을 수 있습니다. 구역을 나누는 `shipping`·`billing`, `section-이름`을 앞에 붙여 한 페이지의 배송지와 청구지를 구분합니다.
- 폼의 `autocomplete`는 아래 컨트롤의 기본값이 됩니다. 컨트롤의 값이 우선합니다. `form.autocomplete`는 속성이 없으면 `'on'`을 반환합니다.
- 채워진 값은 스크립트가 `value`를 대입한 경우와 달리 사용자 입력처럼 `input`·`change` 이벤트를 일으키는 것이 일반적입니다. 프레임워크의 상태가 값을 놓치지 않게 이벤트를 들어야 합니다.
- 토큰을 정확히 쓰면 접근성과 입력 속도, 비밀번호 관리자 연동이 좋아집니다. 자동 완성 완전 차단 목적으로 `off`에 의존하지 않습니다.

## customizable select

customizable select는 CSS만으로 `select` 요소의 버튼과 목록(picker), 옵션 내용을 자유롭게 꾸미는 기능입니다. Baseline이 아닙니다(web-features 3.40.1 기준 Chrome·Edge 135, Safari 27, Firefox는 미지원).

```css
select, ::picker(select) {
  appearance: base-select;
}
```

- `appearance: base-select`를 `select`와 `::picker(select)`에 주면 켜집니다. 값이 미지원인 브라우저는 선언을 무시하고 기존 `select`로 동작합니다.
- 켜면 목록이 `popover`처럼 최상위 레이어(top layer)에 그려지고, CSS 앵커 위치 지정으로 배치할 수 있습니다. 모바일 OS의 기본 선택기도 쓰지 않습니다.
- `option` 안에 이미지나 `span` 같은 비인터랙티브 마크업을 넣을 수 있습니다. 제출 값은 `option`의 `value`이고, 없으면 `textContent`를 정리한 값입니다.
- `selectedcontent` 요소를 `select`의 첫 번째 자식 `button` 안에 넣으면 선택된 옵션 내용의 복제본이 그 버튼에 표시됩니다.
- 스타일 대상 의사 요소: `::picker(select)`(목록), `::picker-icon`(버튼의 화살표), `::checkmark`(선택된 옵션의 체크 표시).

```html
<select>
  <button><selectedcontent></selectedcontent></button>
  <option value="cat"><span>🐱</span> Cat</option>
</select>
```

- 미지원 브라우저에서도 안전하게 쓰려면 `@supports (appearance: base-select)` 안에 스타일을 두는 점진적 향상으로 접근합니다(자세히는 71편).
- 옵션 안에 `a`, `button` 등 인터랙티브 요소는 허용되지 않습니다.

## input.showPicker()로 선택기 열기

`showPicker()`는 `input`의 브라우저 기본 선택기(날짜 달력, 색상 팝업, 파일 대화상자, 입력 후보 목록)를 스크립트로 엽니다. 입력 칸에 포커스를 두지 않고 별도 버튼에서 열 때 씁니다. `select.showPicker()`도 있습니다.

```js
pickBtn.addEventListener('click', () => {
  try {
    dateInput.showPicker()
  } catch (e) {
    dateInput.focus() // 폴백
  }
})
```

| 예외 | 조건 |
|------|------|
| `NotAllowedError` | 사용자 활성화(클릭·키 입력 직후)가 없을 때 |
| `InvalidStateError` | 입력이 읽기 전용이거나 비활성 등으로 변경 불가일 때 |
| `SecurityError` | 다른 출처 iframe 안에서 호출했을 때 (파일·색상 선택기는 예외) |

- 대상은 `date`, `month`, `week`, `time`, `datetime-local`, `color`, `file`, 그리고 `datalist` 후보가 있거나 `autocomplete`가 걸린 입력입니다. 지원 입력 유형에 따라 브라우저마다 차이가 있어 기능 감지(`'showPicker' in HTMLInputElement.prototype`)와 `try...catch`를 함께 둡니다.
- `NotAllowedError`는 `setTimeout`이나 응답 콜백처럼 사용자 입력과 떨어진 곳에서 호출하면 발생합니다. 클릭 핸들러 안에서 직접 호출해야 합니다.
- MDN은 Baseline 널리 지원(2022년 9월부터)으로 표시하지만, 유형별 지원에 편차가 있습니다.

## datalist와 list 속성

`datalist`는 입력 칸에 제안할 후보 목록입니다. `input`의 `list` 속성에 `datalist`의 `id`를 쓰면 연결됩니다. 후보에 없는 값도 자유롭게 입력할 수 있습니다. 목록에서 고르도록 강제하는 `select`와 다릅니다.

```html
<input name="fruit" list="fruits">
<datalist id="fruits">
  <option value="Apple">
  <option value="Banana" label="바나나">
</datalist>
```

```js
input.list                // <datalist id="fruits">
input.list.options.length // 2
hiddenInput.list          // null (list 속성이 무시되는 유형)
```

- `option`의 `value`가 입력되는 값이고, `label`이 있으면 브라우저가 함께 또는 대신 보여 줍니다. 표시 방식은 브라우저마다 다릅니다.
- `list`는 `text`, `search`, `url`, `tel`, `email`, `number`, `range`, `date` 계열, `color` 유형에서 동작합니다. `hidden`, `password`, `checkbox`, `radio`, `file` 등에서는 무시됩니다.
- 브라우저가 입력한 글자에 맞춰 후보를 걸러 보입니다. 걸러 내는 기준(앞부분 일치·부분 일치)은 브라우저 구현입니다.
- `datalist.options`는 `option` 요소의 컬렉션이며, 스크립트로 `option`을 추가·삭제해 후보를 동적으로 바꿀 수 있습니다.
- `datalist`는 Baseline이 아닙니다. web-features는 Chrome 69, Firefox 110, Safari 12.1부터 지원으로 적지만, Firefox가 일부 `input` 유형에서 동작하지 않아 부분 지원으로 봅니다.
- 접근성이 높은 자동 완성이 필요하면 직접 만든 콤보박스를 씁니다(78편).

## output·progress·meter 요소 API

세 요소는 값을 표시하는 요소입니다. 모두 라벨 가능(`labels`)이며, `output`만 폼 컨트롤입니다.

### output

`output`은 계산 결과나 동작의 결과를 표시합니다. 폼 연관 요소이며 `form.elements`에 들어가지만 제출 데이터에는 포함되지 않습니다.

| 속성 | 설명 |
|------|------|
| `value` | 표시 값. 대입은 `textContent`를 바꿈 |
| `defaultValue` | 기본 값. `reset` 때 복원됨 |
| `htmlFor` | `for` 속성의 `DOMTokenList`. 계산에 쓰인 컨트롤의 id 목록 |
| `name`, `form`, `labels`, `type`(`'output'`) | 일반 컨트롤 속성 |

```js
out.value = '9'
[out.textContent, out.defaultValue] // ['9', '5']
out.htmlFor.value                   // 'n rg'
```

- 암묵적 `role="status"`를 가져 값이 바뀌면 보조 기술이 읽습니다.
- 폼의 `input` 이벤트를 들어 합계를 계산해 쓰는 방식이 대표적입니다.

### progress

`progress`는 작업의 진행도를 표시합니다.

| 속성 | 설명 |
|------|------|
| `value` | 현재 값. 속성이 없으면 진행도 불확정 상태 |
| `max` | 최댓값, 기본 `1`. 0 이하는 무시됨 |
| `position` | `value / max` 비율. 불확정이면 `-1` |

```js
// <progress> (value 속성 없음)
[p.value, p.max, p.position]  // [0, 1, -1]
// <progress value="30" max="120">
[p2.value, p2.max, p2.position] // [30, 120, 0.25]
p2.value = 500
p2.value                        // 120 (max로 제한)
```

- `value` 속성을 빼면 로딩 중임만 알리는 불확정 상태이고, `position`이 `-1`입니다. 진행도가 정해지면 `value` 속성을 추가합니다.
- `max`에 0 이하를 대입해도 값이 바뀌지 않습니다.
- 접근성 이름은 `labels`나 `aria-label`로 줍니다.

### meter

`meter`는 정해진 범위 안의 측정값(디스크 사용량, 점수)을 표시합니다. 진행도가 아닙니다. 진행도에는 `progress`를 씁니다.

| 속성 | 설명 |
|------|------|
| `min`, `max` | 범위. 기본 `0`, `1` |
| `value` | 현재 값. 범위 안으로 제한됨 |
| `low`, `high` | 낮음·높음 구간의 경계 |
| `optimum` | 가장 좋은 값. 좋음·나쁨 방향을 정함 |

```js
// <meter value="5" min="0" max="10" low="3" high="8" optimum="9">
m.value = 99
m.value  // 10 (max로 제한)
m.low = -5
m.low    // 0 (min으로 제한)
```

- `optimum`이 `high`보다 크면 값이 높을수록 좋은 것이고, `low`보다 작으면 낮을수록 좋은 것입니다. 브라우저가 구간별로 색을 달리해 그립니다.
- `low`, `high`, `optimum`이 범위를 벗어나면 `min`~`max` 안으로 제한됩니다.

## 핵심 정리

- `form.submit()`은 `submit` 이벤트와 검증 없이 제출하고, `requestSubmit()`은 클릭과 같은 절차(검증, `submit` 이벤트)를 거칩니다. 둘 다 `formdata` 이벤트를 발생시킵니다.
- `FormData(form)`에는 `name`이 있고 비활성이 아닌 컨트롤의 값만 들어갑니다. 체크 안 된 항목은 빠지고, 파일 미선택은 빈 `File`로 들어갑니다.
- `set`은 같은 이름을 하나로 교체하고, `append`는 쌓습니다. `Object.fromEntries`는 중복 이름을 잃습니다.
- 파일이 있으면 `multipart/form-data`(`FormData` 본문, Content-Type은 직접 쓰지 않음), 문자열뿐이면 `URLSearchParams`도 가능합니다.
- 값은 `value`(문자열), `valueAsNumber`, `valueAsDate`(UTC 기준)로 읽고, 텍스트 선택 API는 `text`·`search`·`url`·`tel`·`password`와 `textarea`에서만 동작합니다.
- `label.control`, `control.labels`, `form` 속성으로 컨트롤을 라벨·폼에 연결하고, customizable select는 Baseline이 아니므로 점진적 향상으로 씁니다.
