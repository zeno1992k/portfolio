## 설계 원칙

입력 컨트롤은 네이티브 HTML 요소가 키보드, 포커스, 접근성, 폼 참여를 이미 해 줍니다. 커스텀 요소는 네이티브로 되지 않는 모양이나 동작이 필요할 때만 만듭니다.

| 순서 | 방법 | 쓰는 경우 |
|------|------|-----------|
| 1 | 네이티브 요소와 CSS | 모양만 바꾸면 되는 경우 |
| 2 | 네이티브 요소를 slot으로 받는 래퍼 | 공통 스타일·동작을 입히되 폼과 접근성은 네이티브에 맡길 때 |
| 3 | 폼 연관 커스텀 요소(`formAssociated`) | 네이티브에 없는 위젯(슬라이더 변형, 콤보박스 등) |

- 3번은 `ElementInternals`로 역할(`internals.role`), 상태(`internals.ariaChecked` 등), 폼 값을 직접 선언합니다(자세히는 20편, 26편).
- ARIA 패턴은 W3C APG(Authoring Practices Guide)의 위젯별 역할·상태·키보드 규칙을 따릅니다. 본문의 키보드 표는 APG 기준입니다(키보드·포커스 일반 규칙은 28편).
- 포커스가 가는 곳은 두 방식입니다. 항목이 여러 개면 roving tabindex 또는 `aria-activedescendant`를 씁니다.

## Button Component

버튼은 클릭하면 동작을 일으키는 컨트롤입니다. 가장 먼저 `button` 요소를 씁니다. 활성화는 Space와 Enter가 모두 되고, 포커스와 `disabled`도 네이티브가 처리합니다.

```html
<ui-button>
  <button type="button">저장</button>
</ui-button>
```

- 공통 모양·로딩 표시는 호스트가 맡고 실제 `button`은 light DOM 자식으로 둡니다. 폼 제출과 접근성은 네이티브가 그대로 처리합니다.
- `button`의 `type` 기본값은 `submit`입니다. 폼 안에서 제출이 아닌 버튼은 `type="button"`을 명시합니다.
- shadow 트리 안의 `button`은 바깥 폼의 소유가 아니라서 제출 버튼이 될 수 없습니다(26편).
- 선언형으로 다른 요소를 조작하려면 `commandfor`, `command`(Invoker Commands, Baseline 2025)나 `popovertarget`을 씁니다(자세히는 44편).

`button`을 쓸 수 없어 호스트 자체를 버튼으로 만들어야 하면 다음을 모두 직접 채워야 합니다.

```js
class UiButton extends HTMLElement {
  static formAssociated = true
  #i = this.attachInternals()
  connectedCallback() {
    this.#i.role = 'button'
    this.tabIndex = 0
    this.addEventListener('keydown', (e) => {
      if (e.key === 'Enter' || e.key === ' ') {
        e.preventDefault()
        this.click()
      }
    })
  }
}
```

| 항목 | 규칙 |
|------|------|
| 역할 | `role="button"` |
| 키보드 | Space와 Enter가 활성화 |
| 이름 | 내용 텍스트, `aria-label`, `aria-labelledby` 중 하나 |
| 비활성 | `aria-disabled="true"`. 포커스를 유지하려면 `disabled` 대신 사용 |
| 토글 버튼 | `aria-pressed`로 눌림 여부 표시 |
| 메뉴 버튼 | `aria-haspopup`을 `menu` 또는 `true`로 지정 |

- 토글 버튼의 레이블은 상태가 바뀌어도 그대로 두어야 합니다. 레이블을 "켜기"에서 "끄기"로 바꾸면서 `aria-pressed`까지 바꾸면 중복 안내가 됩니다.
- 비동기 동작 중에는 클릭을 무시하고 `aria-busy`나 `aria-disabled`로 상태를 알립니다. 버튼을 DOM에서 지우거나 `disabled`로 만들면 포커스가 사라집니다.
- 폼을 제출해야 하는 커스텀 버튼은 `internals.form?.requestSubmit()`을 호출합니다.

**흔한 실수:** `div`에 `click` 리스너만 달고 `role`, `tabindex`, 키보드 처리를 빼먹는 것입니다. 마우스로만 동작하고 키보드·스크린 리더에서는 존재하지 않는 버튼이 됩니다.

## Input Component

입력 컴포넌트는 `input` 요소에 레이블, 오류 메시지, 도움말 같은 공통 구조를 입히는 래퍼입니다. 입력 동작은 네이티브 `input`에 맡기고 호스트는 폼 참여를 대신합니다(26편의 "내부 input을 감싸는 방식"과 같은 구조).

```js
class UiInput extends HTMLElement {
  static formAssociated = true
  #i = this.attachInternals()
  #in = document.createElement('input')
  constructor() {
    super()
    const init = { mode: 'open', delegatesFocus: true }
    this.attachShadow(init).append(this.#in)
    this.#in.oninput = () => this.#sync()
  }
  #sync(n = this.#in) {
    this.#i.setFormValue(n.value)
    this.#i.setValidity(n.validity, n.validationMessage, n)
  }
}
```

설계에서 판단할 것은 네 가지입니다.

- 값 전달: `value`는 프로퍼티와 어트리뷰트 양쪽으로 열고, `type`, `placeholder`, `required`, `pattern`, `minlength`, `autocomplete` 같은 어트리뷰트는 내부 `input`으로 전달합니다. `observedAttributes`로 감시하고 변경을 반영합니다(자세히는 19편).
- 이벤트: 네이티브 `input` 이벤트는 shadow 경계를 넘지만 `change`는 넘지 못합니다. 호스트에서 `change`를 다시 디스패치해야 외부가 받습니다(자세히는 21편, 25편).
- 레이블: `for`와 `id` 연결은 shadow 경계를 넘지 못합니다. 바깥의 `label`을 `internals.labels`로 읽어 내부 `input`의 `aria-label`로 복사하거나 `label`을 호스트 안에 slot으로 받습니다.
- 포커스: `delegatesFocus: true`면 호스트에 포커스를 줄 때 내부 첫 포커스 가능 요소가 받고, 바깥 `label`을 눌러도 입력창으로 갑니다(자세히는 28편).

오류 메시지는 `aria-describedby`로 입력에 연결하고, 유효하지 않을 때 `aria-invalid="true"`를 겁니다. 오류를 표시하는 시점은 `invalid` 이벤트나 `blur`가 안전하고, 입력하는 동안 매 글자마다 띄우지 않습니다(자세히는 12편).

**흔한 실수:**

- IME 입력 중(`isComposing`)에 `input` 이벤트로 값을 가공하면 한글 조합이 깨집니다. 조합 중에는 가공을 미룹니다(자세히는 10편).
- 래퍼가 `type`, `inputmode`, `autocomplete`를 전달하지 않으면 모바일 키보드와 자동 완성이 동작하지 않습니다.
- `value`를 어트리뷰트로만 받으면 사용자가 입력한 뒤에는 어트리뷰트 변경이 현재 값에 반영되지 않는 네이티브 규칙과 어긋납니다. 어트리뷰트는 기본값, 프로퍼티는 현재 값으로 구분합니다.

## Checkbox·Switch

체크박스는 `input type="checkbox"`가 네이티브입니다. 스위치는 on/off 의미가 더 잘 맞는 이진 컨트롤이며, 네이티브 체크박스에 `role="switch"`를 붙여 쓸 수 있습니다.

```html
<label>
  <input type="checkbox" role="switch" name="push">
  알림 받기
</label>
```

| 항목 | 체크박스 | 스위치 |
|------|----------|--------|
| 역할 | `checkbox` | `switch` |
| 상태 | `aria-checked`가 `true`, `false`, `mixed` | `aria-checked`가 `true`, `false`만 가능 |
| 키보드 | Space로 상태 변경 | Space로 변경(필수), Enter(선택) |
| 선택 기준 | 선택 여부, 다중 선택 | 즉시 적용되는 켜기·끄기 |

- 스위치는 중간 상태가 없다는 점이 체크박스와 토글 버튼과 다릅니다.
- 스위치와 토글 버튼은 상태가 바뀌어도 레이블을 바꾸지 않습니다. "알림 받기"는 켜져도 꺼져도 "알림 받기"입니다.
- 제출 값은 체크되지 않으면 없어야 하므로 `setFormValue(null)`을, 체크되면 `value` 어트리뷰트(없으면 `'on'`)를 씁니다. 상태는 `internals.ariaChecked = 'true'`처럼 문자열로 반영합니다. 구현은 26편의 `ToggleBox`와 같습니다.
- 3상태(`mixed`) 체크박스는 자식 체크박스들의 요약 상태를 나타내는 "모두 선택" 용도입니다. 사용자가 누르면 `mixed`는 보통 `true`로 바뀝니다. 같은 `name`의 체크박스 묶음은 `role="group"`과 `aria-labelledby`로 레이블을 붙입니다.
- `indeterminate`는 네이티브 `input`의 JavaScript 프로퍼티이고 어트리뷰트가 없으며 `checked`와 별개입니다.

**흔한 실수:** 체크박스 그룹을 하나의 커스텀 요소에서 `name` 하나로 모아 값 배열을 만들려는 것입니다. 폼 제출에 여러 항목이 들어가야 하면 `setFormValue(FormData)`로 같은 이름의 항목을 여러 개 넣거나 체크박스마다 폼 연관 요소로 둡니다.

## Radio Group

라디오 그룹은 하나만 선택되는 상호 배타적 선택입니다. 네이티브는 같은 `name`의 `input type="radio"`가 하나의 그룹이 되고 방향키와 포커스 규칙까지 처리합니다. 커스텀은 이 규칙을 전부 직접 구현해야 해서 네이티브로 되는 한 네이티브를 씁니다.

```html
<div role="radiogroup" aria-labelledby="size-label">
  <span id="size-label">크기</span>
  <div role="radio" aria-checked="true" tabindex="0">S</div>
  <div role="radio" aria-checked="false"
       tabindex="-1">M</div>
</div>
```

| 항목 | 규칙 |
|------|------|
| 역할 | 컨테이너 `radiogroup`, 항목 `radio` |
| 상태 | 항목마다 `aria-checked`가 `true` 또는 `false` |
| Tab | 그룹에 들어갈 때 체크된 항목에, 없으면 첫 항목에 포커스. 그룹 전체가 탭 정류장 한 칸 |
| 방향키 | 다음·이전 항목으로 이동하면서 곧바로 체크(이전 항목은 해제). 끝에서 처음으로 순환 |
| Space | 포커스된 항목을 체크 |

- 포커스를 하나만 `tabindex="0"`으로 두고 방향키로 옮기는 roving tabindex로 구현합니다(자세히는 28편).
- 이동과 선택이 함께 일어나는 것이 일반 규칙입니다. 툴바 안의 라디오 그룹은 방향키가 포커스만 옮기고 Space나 Enter로 선택하는 변형을 씁니다.
- 폼 참여는 그룹 호스트 하나가 `setFormValue`로 선택된 항목의 값을 내보내는 방식이 단순합니다. 항목마다 폼 연관 요소로 만들면 같은 `name`끼리 하나만 체크되는 규칙을 직접 구현해야 합니다.
- `required`, 비활성 항목(건너뛰며 이동), `reset` 시 기본 선택 복원도 정해야 합니다.

## Slider

슬라이더는 범위 안의 값을 선택하는 컨트롤입니다. 네이티브는 `input type="range"`이며 값이 하나일 때는 거의 이것으로 충분합니다. 두 값(구간 선택)이나 눈금 표시가 필요하면 커스텀입니다.

```html
<div role="slider" tabindex="0"
     aria-label="볼륨"
     aria-valuemin="0" aria-valuemax="100"
     aria-valuenow="40" aria-valuetext="40퍼센트"></div>
```

| 항목 | 규칙 |
|------|------|
| 역할 | `slider`. 포커스는 조절 손잡이(thumb) 자체에 둠 |
| 필수 속성 | `aria-valuemin`, `aria-valuemax`, `aria-valuenow` |
| 선택 속성 | `aria-valuetext`(사람이 읽는 값), 세로형은 `aria-orientation="vertical"` |
| 키보드 | 오른쪽·위쪽 화살표는 증가, 왼쪽·아래쪽은 감소 |
| | Home은 최솟값, End는 최댓값 |
| | Page Up·Page Down은 큰 단위 증감(선택) |
| 이름 | `aria-label` 또는 `aria-labelledby` |

- 포인터 조작은 Pointer Events와 `setPointerCapture`로 구현합니다. 손잡이를 벗어나도 `pointermove`를 계속 받습니다(자세히는 9편).
- 터치 기반 보조 기술은 슬라이더 제스처를 지원하지 않는 경우가 있다는 한계가 APG에 명시되어 있습니다. 중요한 값은 숫자 입력을 함께 제공합니다.
- 값은 `step` 단위로 반올림하고 `min`, `max`로 제한합니다. 값 표시와 폼 제출 값(`setFormValue`)을 같은 곳에서 갱신합니다.
- 범위 슬라이더는 손잡이마다 `slider` 역할을 따로 두고, 최소 손잡이의 최대 범위가 최대 손잡이 값이 되도록 `aria-valuemax`와 `aria-valuemin`을 동적으로 갱신합니다.
- 스타일은 `aria-valuenow` 값에서 계산한 비율을 사용자 정의 속성(`--ratio`)으로 노출하면 트랙 채움을 CSS로 처리할 수 있습니다.

## Listbox

리스트박스는 목록에서 하나 또는 여러 옵션을 고르는 위젯입니다. 네이티브는 `select multiple`이나 `select size`입니다. 커스텀 리스트박스는 콤보박스의 팝업과 선택 목록의 기반이 됩니다.

```html
<ul role="listbox" tabindex="0" aria-label="과일"
    aria-activedescendant="o1">
  <li role="option" id="o1" aria-selected="true">사과</li>
  <li role="option" id="o2" aria-selected="false">배</li>
</ul>
```

| 항목 | 규칙 |
|------|------|
| 역할 | 컨테이너 `listbox`, 항목 `option` |
| 상태 | 선택은 `aria-selected`(또는 `aria-checked`). 다중 선택은 컨테이너에 `aria-multiselectable="true"` |
| 방향키 | 항목 사이 이동 |
| Home·End | 처음·끝 항목(항목 5개 이상이면 권장) |
| Space | 다중 선택에서 현재 항목 선택 토글 |
| 타입어헤드 | 입력한 글자로 시작하는 항목으로 이동(항목 7개 이상이면 권장) |

- DOM 포커스(현재 항목)와 선택 상태(`aria-selected`)는 별개입니다. 단일 선택에서 이동하면 곧바로 선택되는 방식(follows focus)도 있고 Enter나 Space로 확정하는 방식도 있어 둘 중 하나를 정합니다.
- 항목 이동은 roving tabindex나 `aria-activedescendant` 중 하나입니다. 콤보박스 팝업처럼 입력창이 포커스를 유지해야 하면 후자입니다(28편).
- 옵션 이름은 짧게 하고 같은 단어로 시작하는 이름을 피합니다. 스크린 리더가 이름 전체를 한 덩어리로 읽습니다. 긴 목록은 계층 구조로 나눕니다.
- 링크나 버튼, 체크박스 같은 상호작용 요소 목록에는 리스트박스를 쓰지 않습니다. 이 경우는 Grid 패턴입니다(80편).
- 항목이 많으면 가시 영역만 렌더링하는 가상 목록을 씁니다(80편). 이때 `aria-setsize`와 `aria-posinset`로 전체 크기와 위치를 알립니다.

## Select / Combobox

선택 입력은 두 갈래입니다. 네이티브 `select`로 되는 범위를 먼저 확인합니다.

| 요구 | 선택 |
|------|------|
| 고정된 목록에서 하나 선택, 모양은 기본 | 네이티브 `select` |
| 목록을 CSS로 꾸미고 싶음 | customizable select(`appearance: base-select`, 미Baseline) |
| 입력창에서 검색하며 선택 | 편집 가능한 콤보박스 |
| 옵션에 아이콘·복합 내용 | 커스텀 select-only 콤보박스 |

- customizable select는 `select`와 `::picker(select)`에 `appearance: base-select`를 주면 켜지며 미지원 브라우저는 기존 `select`로 동작합니다(자세히는 11편, 71편).
- 모바일에서는 네이티브 `select`가 OS의 선택 UI를 쓰기 때문에 커스텀보다 조작이 낫습니다.

콤보박스는 팝업과 연결된 입력 위젯입니다. 팝업은 `listbox`, `grid`, `tree`, `dialog`가 될 수 있고, 여기서는 가장 흔한 `listbox`를 다룹니다.

```html
<div id="cb" role="combobox" tabindex="0"
     aria-controls="lb" aria-expanded="false"
     aria-haspopup="listbox">과일 선택</div>
<ul id="lb" role="listbox" popover="manual">
  <li role="option" id="o1">사과</li>
</ul>
```

| 항목 | 규칙 |
|------|------|
| 콤보박스 요소 | `role="combobox"`, `aria-controls`로 팝업 id, `aria-expanded`로 열림 표시 |
| 팝업이 listbox가 아닐 때 | `aria-haspopup`에 `grid`, `tree`, `dialog` 지정 |
| 활성 항목 | 팝업 안에서도 포커스는 콤보박스에 두고 `aria-activedescendant`가 활성 옵션을 가리킴 |
| Down Arrow | 팝업을 열거나 팝업 안으로 이동 |
| Enter | 현재 옵션을 확정 |
| Escape | 팝업 닫기 |
| Alt + Down Arrow | 포커스를 옮기지 않고 팝업 열기(선택) |

- 팝업은 `popover` 속성으로 Top Layer에 올리면 `z-index`와 클리핑 문제를 피합니다. 위치는 CSS 앵커 포지셔닝 또는 직접 계산합니다(자세히는 44편, 45편).
- 선택 확정 후에는 팝업을 닫고 콤보박스에 값을 표시하며 `aria-expanded`를 `false`로 되돌립니다. 포커스는 이동하지 않았으므로 되돌릴 곳이 없습니다.
- 폼 참여가 필요하면 `setFormValue`로 선택된 옵션의 값을 내보냅니다(26편).
- 바깥 클릭과 `blur`로 닫는 것을 `popover="auto"`의 light dismiss에 맡길 수 있으나 콤보박스처럼 입력창이 포커스를 유지해야 하면 `manual`과 직접 제어가 안전합니다(45편).

## Autocomplete Search

자동 완성 검색은 사용자가 입력하는 동안 서버나 목록에서 후보를 찾아 보여주는 편집 가능한 콤보박스입니다. `aria-autocomplete`로 후보 동작을 알립니다.

| `aria-autocomplete` | 동작 |
|---------------------|------|
| `none` | 입력과 무관하게 같은 후보를 보여줌 |
| `list` | 입력과 일치하는 후보 목록을 보여주고 선택은 사용자가 함 |
| `both` | 목록과 함께 입력창에 인라인 완성 문자열도 표시 |

입력창에 `role="combobox"`, `aria-controls`, `aria-expanded`, `aria-autocomplete`를 두고 팝업 목록은 위의 리스트박스 패턴을 따릅니다. 핵심은 입력과 비동기 응답의 순서 문제입니다.

```js
#ctrl = null
async #search(q) {
  this.#ctrl?.abort()
  this.#ctrl = new AbortController()
  const url = `/api/search?q=${encodeURIComponent(q)}`
  try {
    const signal = this.#ctrl.signal
    const res = await fetch(url, { signal })
    this.#render(await res.json())
  } catch (e) {
    if (e.name !== 'AbortError') this.#showError()
  }
}
```

- 새 요청을 보낼 때 이전 요청을 `AbortController`로 취소합니다. 응답이 요청 순서와 다르게 도착해도 마지막 입력의 결과만 남습니다(자세히는 37편, 39편).
- 입력마다 요청하지 않도록 debounce를 둡니다. 입력이 일정 시간 멈춘 뒤에 요청합니다(자세히는 8편).
- IME 조합 중(`isComposing`)에는 검색하지 않고 `compositionend` 뒤에 요청합니다. 한글은 조합 중 글자가 계속 바뀝니다(10편).
- 입력이 비었거나 너무 짧으면 요청하지 않고 팝업을 닫습니다.
- 후보 텍스트는 `textContent`로 넣고 일치 부분은 DOM으로 `mark`를 만들어 감쌉니다. 서버가 준 문자열을 `innerHTML`에 넣으면 XSS 경로가 됩니다(자세히는 5편, 63편).
- 상태는 네 가지(대기, 로딩, 결과, 오류)를 구분해 빈 결과도 "결과 없음"으로 알립니다.
- 결과 개수 변화는 `role="status"`(암묵적 `aria-live="polite"`)인 영역에 "3개의 결과"처럼 알립니다(27편).
- 입력 중에는 활성 옵션을 비워 두고(`aria-activedescendant` 제거) 사용자가 아래 방향키를 누를 때 첫 옵션으로 이동합니다. 입력창의 커서 이동 키(좌우, Home, End)는 가로채지 않습니다.

**흔한 실수:** 응답 도착 순서를 보장하지 않는 것입니다. 느린 이전 응답이 늦게 와 현재 입력과 다른 결과를 덮어씁니다. 취소와 입력값 비교 중 하나는 반드시 있어야 합니다.

## Theme Switcher

테마 스위처는 라이트, 다크, 시스템 설정 중 하나를 고르게 하는 컨트롤입니다. 상태는 세 가지(`light`, `dark`, `system`)이고, 선택지가 셋이면 라디오 그룹이나 `select`, 둘이면 토글 버튼이나 스위치가 맞습니다.

핵심은 `color-scheme` 속성입니다. 이 속성은 기본 캔버스 색, 스크롤바, 폼 컨트롤의 기본 색을 바꾸고 Baseline 널리 지원(2022)입니다. 상속되므로 루트에 설정하면 shadow 안의 컴포넌트에도 전달됩니다.

```css
:root { color-scheme: light dark; }
.card {
  background: light-dark(#fff, #1b1b1f);
  color: light-dark(#111, #eee);
}
```

- `light-dark()`는 `color-scheme`이 있을 때 현재 스킴에 맞는 색을 고릅니다. Baseline 2024입니다.
- `color-scheme: light dark`는 OS의 설정을 따르는 시스템 모드입니다. 사용자가 라이트나 다크를 직접 고르면 루트의 `color-scheme`을 해당 값 하나로 바꿉니다.

```js
function applyTheme(pref) {   // 'light' | 'dark' | 'system'
  const root = document.documentElement
  root.style.colorScheme =
    pref === 'system' ? 'light dark' : pref
  try { localStorage.setItem('theme', pref) } catch {}
}
```

- 이 방식은 `prefers-color-scheme` 변화를 JavaScript로 감시할 필요가 없습니다. 시스템 모드의 전환은 CSS가 처리합니다.
- 선택은 `localStorage`에 저장합니다. 접근이 막힐 수 있으므로 `try`로 감쌉니다(40편).
- 저장한 값은 첫 페인트 전에 적용해야 깜빡임이 없습니다. `head`의 동기 인라인 스크립트에서 읽어 루트에 적용합니다. `defer`와 모듈 스크립트는 문서 파싱이 끝난 뒤 실행되므로 첫 페인트 이후에 적용될 수 있습니다(14편).
- `meta name="color-scheme" content="light dark"`를 CSS보다 앞에 두면 스타일이 로드되기 전 화면의 색 번쩍임을 막습니다.
- 토글 버튼이라면 `aria-pressed`로 상태를 알리고 레이블은 "다크 모드"로 고정합니다. 시스템 설정 변화에 따라 UI 표시(아이콘)를 갱신해야 하면 `matchMedia('(prefers-color-scheme: dark)')`의 `change` 이벤트를 듣습니다(자세히는 74편).
- 디자인 토큰은 사용자 정의 속성으로 정의하고 `light-dark()`로 두 값을 담아 컴포넌트가 스킴을 몰라도 되게 합니다(24편, 74편).

**흔한 실수:** 저장된 값을 DOM이 로드된 뒤에 적용해서 라이트 화면이 먼저 나타났다가 다크로 바뀌는 깜빡임입니다.

## 핵심 정리

- 입력 컨트롤은 네이티브 요소, 네이티브를 감싼 래퍼, 폼 연관 커스텀 요소의 순서로 고르고, 직접 만들 때는 역할·상태·키보드·폼 값을 모두 채웁니다.
- 버튼은 Space와 Enter로 활성화되고, 스위치와 토글 버튼은 상태가 바뀌어도 레이블을 바꾸지 않으며, 체크박스만 `mixed` 상태를 가집니다.
- 라디오 그룹과 리스트박스는 roving tabindex나 `aria-activedescendant`로 포커스를 관리하고, 슬라이더는 `aria-valuemin`, `aria-valuemax`, `aria-valuenow`와 화살표·Home·End를 지원합니다.
- 콤보박스는 `role="combobox"`, `aria-controls`, `aria-expanded`, `aria-activedescendant`로 입력 포커스를 유지한 채 팝업 옵션을 가리킵니다.
- 자동 완성은 취소·debounce·IME 조합 처리로 응답 순서를 보장하고, 테마 스위처는 `color-scheme`과 `light-dark()`를 루트에서 바꿔 컴포넌트 전체에 전달합니다.
