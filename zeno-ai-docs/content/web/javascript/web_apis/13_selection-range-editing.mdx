## Range

**Range**는 문서 안의 연속된 구간을 나타내는 객체입니다. 시작점과 끝점, 두 경계점(boundary point)으로 정해지며, 경계점은 컨테이너 노드와 오프셋의 쌍입니다. 노드를 고르는 방법(자세히는 04편)과 달리, 노드 안쪽의 글자 단위 위치까지 가리킬 수 있습니다.

### 경계점과 오프셋

오프셋의 단위는 컨테이너 종류에 따라 다릅니다.

| 컨테이너 | 오프셋의 뜻 | 유효 범위 |
|----------|-------------|-----------|
| Text·Comment 등 문자 데이터 노드 | 글자 위치 (UTF-16 코드 유닛) | 0–length |
| Element·DocumentFragment·Document | 자식 노드 사이의 위치 (인덱스) | 0–자식 수 |

```html
<p id="p">Hello <b>big</b> world</p>
```

```js
const p = document.getElementById('p')
const r = new Range()
r.setStart(p.firstChild, 2)       // "Hello " 의 2번 글자 앞
r.setEnd(p.lastChild, 3)          // " world" 의 3번 글자 앞
r.toString()                      // "llo big wo"
r.startOffset                     // 2
r.commonAncestorContainer.nodeName // 'P'
```

- `new Range()`는 문서 맨 앞 `(document, 0)`에서 시작하는 접힌 Range를 만듭니다. `document.createRange()`도 같은 결과입니다.
- 오프셋이 컨테이너 길이(또는 자식 수)를 넘으면 `IndexSizeError`가 발생합니다.
- 끝점을 시작점보다 앞으로 옮기거나 시작점을 끝점보다 뒤로 옮기면 에러 없이 Range가 접히고, 다른 쪽 경계가 같은 위치로 따라옵니다. 시작이 끝보다 뒤인 Range는 존재할 수 없습니다.
- 시작과 끝이 같은 위치이면 `collapsed`가 `true`입니다. 접힌 Range는 구간이 아니라 삽입 위치를 뜻합니다.
- Range는 살아 있습니다(live). DOM이 바뀌면 경계점이 자동으로 보정됩니다.

```js
// <p>abcdef</p> 의 Text 노드 tn
const r = new Range()
r.setStart(tn, 2)
r.setEnd(tn, 4)
tn.insertData(0, 'XX')            // 앞에 두 글자 삽입
r.startOffset                     // 4  (함께 밀려남)
r.toString()                      // "cd"
```

노드가 제거되면 그 노드 안에 있던 경계점은 부모 노드의 해당 인덱스로 옮겨집니다.

### 위치를 지정하는 메서드

| 메서드 | 동작 |
|--------|------|
| `setStart(node, offset)` · `setEnd(node, offset)` | 경계점을 직접 지정 |
| `setStartBefore(node)` · `setStartAfter(node)` | 노드 앞·뒤를 시작점으로 (끝점은 `setEndBefore`·`setEndAfter`) |
| `selectNode(node)` | 노드 자신을 포함해 구간으로 지정 |
| `selectNodeContents(node)` | 노드의 자식 전체를 구간으로 지정 |
| `collapse(toStart)` | 시작점(`true`) 또는 끝점으로 접음. 인자 생략 시 `false` |
| `cloneRange()` | 같은 경계를 가진 새 Range |

```js
// <p id="p">Hello <b>big</b> world</p>
const b = p.querySelector('b')
r.selectNodeContents(p)  // 시작 (P, 0) · 끝 (P, 3)
r.selectNode(b)          // 시작 (P, 1) · 끝 (P, 2)
```

`selectNode`는 부모 기준의 위치로 경계를 잡으므로 컨테이너가 노드 자신이 아니라 부모입니다. `selectNodeContents(node)`의 컨테이너는 `node`입니다. 문서 전체 선택은 `selectNodeContents(document.body)`입니다.

### 내용을 복사·추출·감싸기

| 메서드 | 원본 DOM | 반환 |
|--------|----------|------|
| `cloneContents()` | 그대로 | 구간의 복제본이 든 DocumentFragment |
| `extractContents()` | 구간이 제거됨 | 제거된 내용이 든 DocumentFragment |
| `deleteContents()` | 구간이 제거됨 | 없음 |
| `insertNode(node)` | 시작점에 노드 삽입 | 없음 |
| `surroundContents(newParent)` | 구간이 `newParent` 안으로 이동 | 없음 |

구간이 요소를 일부만 걸치면 그 요소는 쪼개집니다.

```js
// <p id="p">Hello <b>big</b> world</p>
// 시작 ("Hello ", 2) · 끝 ("big", 1)
const frag = r.cloneContents()
// frag: "llo " + <b>b</b>   (원본 p는 그대로)
const out = r.extractContents()
// out은 위와 같고, p는 He<b>ig</b> world 로 바뀐다
```

- `extractContents` 뒤 Range는 접힙니다.
- 일부만 걸쳐진 요소는 원본에 남은 부분과 추출된 부분으로 나뉘며, 추출된 쪽은 껍데기만 복제된 요소입니다. `id` 같은 속성도 복제되므로 중복 `id`가 생길 수 있습니다.

`surroundContents`는 `extractContents`로 꺼낸 내용을 `newParent`의 자식으로 넣고, `newParent`를 구간 자리에 삽입합니다. 이후 Range는 `newParent` 전체를 선택합니다.

```js
// 텍스트 노드 하나 안의 구간: 성공
const mark = document.createElement('mark')
r.surroundContents(mark)   // He<mark>llo</mark> <b>big</b> world
```

**흔한 실수:** 구간이 Text가 아닌 노드를 일부만 걸치면 `surroundContents`가 `InvalidStateError`를 던집니다. 요소를 완전히 포함하거나 아예 포함하지 않는 구간, 또는 텍스트 노드 한 곳 안의 구간만 허용됩니다. 일부만 걸치는 경우에는 직접 추출해 감쌉니다.

```js
const wrap = document.createElement('mark')
wrap.append(range.extractContents())
range.insertNode(wrap)
// He<mark>llo <b>b</b></mark><b>ig</b> world
```

### 위치 비교와 기하

- `compareBoundaryPoints(how, other)`는 두 Range의 경계를 비교해 -1, 0, 1을 돌려줍니다.
- `comparePoint(node, offset)`은 점이 Range 앞(-1)·안(0)·뒤(1)인지, `isPointInRange`는 안에 있는지만 불리언으로 돌려줍니다.
- `getBoundingClientRect()`와 `getClientRects()`는 Range가 화면에서 차지하는 사각형을 돌려줍니다(자세히는 06편). 선택 영역 옆에 툴바를 띄울 때 씁니다.

## AbstractRange와 StaticRange

**AbstractRange**는 Range와 StaticRange의 공통 부모 인터페이스입니다. `startContainer`, `startOffset`, `endContainer`, `endOffset`, `collapsed` 다섯 읽기 전용 속성만 가집니다.

**StaticRange**는 경계점을 그대로 저장하는 스냅샷입니다. DOM이 바뀌어도 보정되지 않고, 그래서 구간 내용을 다루는 메서드(`cloneContents`, `toString` 등)가 없습니다.

```js
const s = new StaticRange({
  startContainer: tn, startOffset: 2,
  endContainer: tn, endOffset: 4,
})
tn.insertData(0, 'YY')
s.startOffset   // 2  (Range였다면 4)
```

| 구분 | Range | StaticRange |
|------|-------|-------------|
| 상위 인터페이스 | AbstractRange | AbstractRange |
| DOM 변경 시 | 경계 자동 보정 | 변하지 않음 |
| 내용 조작 메서드 | 있음 | 없음 |
| 생성 | `new Range()` 후 `setStart`·`setEnd` | 생성자에 네 값을 한꺼번에 전달 |

- 생성자 인자에 `startContainer`·`startOffset`·`endContainer`·`endOffset` 네 값이 모두 필요합니다. 하나라도 빠지면 `TypeError`입니다.
- 컨테이너가 DocumentType이나 Attr이면 `InvalidNodeTypeError`입니다.
- 오프셋이 노드 길이를 넘어도 생성 시점에는 검증하지 않습니다. 검증은 Range로 변환할 때 일어납니다.
- 쓰이는 곳: `InputEvent.getTargetRanges()`(이 편의 beforeinput 절), `Selection.getComposedRanges()`(Shadow DOM 절)의 반환값. Highlight(CSS Custom Highlight API 절)도 AbstractRange를 받습니다.
- StaticRange를 편집에 쓰려면 새 Range를 만들어 같은 경계를 지정합니다.

```js
const [sr] = event.getTargetRanges()
const r = new Range()
r.setStart(sr.startContainer, sr.startOffset)
r.setEnd(sr.endContainer, sr.endOffset)
```

## Selection API

**Selection**은 사용자가 화면에서 선택한 구간(또는 캐럿 위치)을 나타내는 객체이고 문서마다 하나입니다. `window.getSelection()` 또는 `document.getSelection()`으로 얻으며, 같은 객체를 돌려줍니다. 선택 자체를 Range로 표현하므로 Range가 Selection의 구성 요소입니다.

### 상태 읽기

```js
const sel = getSelection()
sel.type          // 'None' | 'Caret' | 'Range'
sel.rangeCount    // 0 또는 1 (Firefox는 여러 개 가능)
sel.isCollapsed   // 캐럿이면 true
sel.toString()    // 선택된 텍스트
sel.getRangeAt(0) // Range. rangeCount가 0이면 IndexSizeError
```

- `type`은 선택 없음 `'None'`, 접힌 선택(캐럿) `'Caret'`, 구간 선택 `'Range'`입니다.
- `getRangeAt`이 돌려주는 Range는 Selection과 연결되어 있어서, 그 Range를 고치면 화면의 선택도 바뀝니다. 복사본이 필요하면 `cloneRange()`를 씁니다.

### 앵커와 포커스

| 속성 | 뜻 |
|------|----|
| `anchorNode`·`anchorOffset` | 선택을 시작한 쪽 경계 |
| `focusNode`·`focusOffset` | 선택이 끝난 쪽(사용자가 드래그를 마친 쪽, 캐럿이 있는 쪽) 경계 |

Range의 시작·끝은 문서 순서로 정해지지만 앵커·포커스는 선택 방향으로 정해집니다. 오른쪽에서 왼쪽으로 드래그하면 앵커가 뒤에, 포커스가 앞에 옵니다.

```js
// "Hello world" 의 Text 노드 t
sel.setBaseAndExtent(t, 5, t, 1)  // 앵커 5, 포커스 1
sel.anchorOffset                  // 5
sel.focusOffset                   // 1
sel.getRangeAt(0).startOffset     // 1  (Range는 문서 순서)
sel.getRangeAt(0).endOffset       // 5
```

### 선택을 바꾸는 메서드

| 메서드 | 동작 |
|--------|------|
| `addRange(range)` | Range를 선택에 추가 |
| `removeRange(range)` · `removeAllRanges()` | 하나 또는 전부 제거 (`empty()`는 `removeAllRanges`의 별칭) |
| `collapse(node, offset)` | 해당 위치에 캐럿 (`setPosition`은 별칭) |
| `collapseToStart()` · `collapseToEnd()` | 선택을 시작점·끝점으로 접음 |
| `extend(node, offset)` | 앵커는 두고 포커스만 이동 |
| `setBaseAndExtent(aNode, aOff, fNode, fOff)` | 앵커와 포커스를 한 번에 지정 (방향 유지) |
| `selectAllChildren(node)` | 노드의 자식 전체 선택 |
| `containsNode(node, allowPartial)` | 노드가 선택에 포함되는지 |
| `deleteFromDocument()` | 선택된 내용을 DOM에서 삭제 |

```js
sel.collapse(t, 3)       // 3번 글자 앞에 캐럿
sel.extend(t, 8)         // 3 ~ 8 선택
sel.toString()           // "lo wo" ("Hello world" 기준)
sel.collapseToEnd()      // 8 위치의 캐럿. isCollapsed === true
```

- 표준 알고리즘에서 `addRange`는 이미 Range가 있으면(rangeCount가 0이 아니면) 아무 일도 하지 않습니다. 선택을 교체하려면 `removeAllRanges()` 뒤에 `addRange`를 하거나 `setBaseAndExtent`를 씁니다.
- `<input>`·`<textarea>` 안의 선택은 이 API가 아니라 요소의 `selectionStart`, `selectionEnd`, `setSelectionRange()`로 다룹니다(자세히는 11편).

### Selection.modify

`modify(alter, direction, granularity)`는 방향키·Shift+방향키와 같은 규칙으로 선택을 움직이는 비표준 메서드입니다. Baseline 널리 지원(2020년 1월부터)이지만 표준 문서에는 없습니다.

```js
sel.modify('move', 'forward', 'character')   // 캐럿을 한 글자 앞으로
sel.modify('extend', 'forward', 'word')      // 선택을 한 단어 확장
sel.modify('extend', 'backward', 'lineboundary') // 줄 시작까지 확장
```

- `alter`: `'move'`(캐럿 이동) 또는 `'extend'`(선택 확장).
- `direction`: `'forward'`·`'backward'`는 글쓰기 방향 기준, `'left'`·`'right'`는 화면 방향 기준.
- `granularity`: `'character'`, `'word'`, `'line'`, `'sentence'`, `'paragraph'`, `'lineboundary'`, `'sentenceboundary'`, `'paragraphboundary'`, `'documentboundary'`.
- Firefox는 `sentence`, `paragraph`, `sentenceboundary`, `paragraphboundary`, `documentboundary`를 지원하지 않습니다.
- 단어·문장 경계는 브라우저의 텍스트 분할 규칙을 따르므로 엔진마다 결과가 다를 수 있습니다.

## selectionchange와 selectstart

### selectionchange

`selectionchange`는 문서의 선택이 바뀔 때 `document`에서 발생하는 이벤트입니다. 버블링하지 않고 취소할 수 없으며, 이벤트 객체에는 선택 정보가 없으므로 리스너에서 `getSelection()`을 호출합니다. Baseline 널리 지원(2017년 3월부터)입니다.

```js
document.addEventListener('selectionchange', () => {
  const sel = getSelection()
  if (sel.rangeCount === 0 || sel.isCollapsed) return
  console.log(sel.toString())   // 선택된 텍스트
})
```

발생하는 경우: 선택이 생기거나 지워질 때, 경계가 이동할 때, 구간이 통째로 바뀔 때, 캐럿으로 접힐 때(캐럿 이동 포함).

- 프로그램에서 `collapse` 등으로 선택을 바꾸면 선택은 즉시 바뀌지만 이벤트는 태스크로 예약되어 현재 스크립트가 끝난 뒤 호출됩니다. `focus`·`click`처럼 동기로 호출되지 않습니다(자세히는 08편). 한 스크립트 안에서 여러 번 바꿔도 이벤트는 한 번 예약됩니다.
- 드래그로 선택을 넓히는 동안 계속 발생하므로 무거운 작업은 `requestAnimationFrame` 또는 디바운스로 제한합니다.
- `<input>`·`<textarea>`의 선택은 `document`가 아니라 그 요소에서 발생하며 버블링합니다. 이때 `document.getSelection()`이 아니라 `selectionStart`·`selectionEnd`·`selectionDirection`을 읽습니다.

### selectstart

`selectstart`는 사용자가 새 선택을 시작하려 할 때 선택이 시작되는 노드에서 발생하는 이벤트입니다. 버블링하고 취소할 수 있으며, 취소하면 선택이 시작되지 않습니다.

```js
article.addEventListener('selectstart', (e) => {
  if (e.target.closest('.no-select')) e.preventDefault()
})
```

- 선택 방지는 CSS `user-select: none`이 일반적입니다. `selectstart` 취소는 조건에 따라 막거나 풀어야 할 때 씁니다.
- 선택 막기는 접근성(보조 기술의 읽기)과 사용성을 해칩니다. 복사 방지 수단으로 신뢰할 수 없으므로 보안 용도로 쓰지 않습니다.

| 이벤트 | 발생 대상 | 버블링 | 취소 | 시점 |
|--------|-----------|--------|------|------|
| `selectstart` | 선택이 시작되는 노드 | 예 | 가능 | 선택이 바뀌기 전 |
| `selectionchange` | `document` (입력 요소는 그 요소) | 문서: 아니오, 입력 요소: 예 | 불가 | 선택이 바뀐 뒤 |

## Shadow DOM 안의 선택과 getComposedRanges

Shadow DOM(자세히는 21편)은 DOM 트리를 캡슐화하므로, 선택의 끝점이 shadow 트리 안에 있거나 경계를 가로지르면 기존 `getRangeAt()`으로는 정확한 위치를 얻을 수 없습니다. `getRangeAt()`은 shadow 경계를 모르며, 경계를 가로지르는 선택에서는 엔진마다 다른 Range를 돌려줍니다. 닫힌(closed) shadow root 안의 노드는 노출하지 않습니다.

**getComposedRanges**는 이 문제를 풀기 위해 만들어진 메서드로, 합성(composed) 트리 기준의 StaticRange 배열을 돌려줍니다. Baseline 2025입니다.

```js
const sel = getSelection()
const [range] = sel.getComposedRanges({
  shadowRoots: [openRoot, closedRoot],
})
range.startContainer   // 전달한 shadow root 안의 노드일 수 있다
```

| `shadowRoots`에 | 끝점이 그 root 안일 때 |
|------------------|------------------------|
| 포함한 root | 그 root 안의 실제 노드를 돌려줌 |
| 포함하지 않은 root | 끝점이 shadow host 요소 기준으로 올려짐(리타깃팅) |

- 인자 없이 호출하면 shadow 안쪽 끝점은 모두 host로 올려져 문서 트리 기준의 범위가 됩니다.
- 닫힌 shadow root는 호출한 쪽이 root 참조를 가지고 있어야 인자로 넘길 수 있습니다. 내부 구현이 root를 숨기면 외부에서는 내부 노드를 얻을 수 없습니다.
- 반환값은 StaticRange이므로 DOM이 바뀌면 낡습니다. 필요하면 MutationObserver(자세히는 43편)로 변화를 추적하고, 선택을 복원하려면 `setBaseAndExtent`를 씁니다.
- 경계를 가로지를 수 있는 선택은 `getRangeAt()` 대신 `getComposedRanges()`를 기본으로 합니다.

## contenteditable과 편집 호스트

**contenteditable**은 요소 내용을 사용자가 직접 편집하게 만드는 전역 속성입니다.

| 값 | 의미 |
|----|------|
| `true` 또는 빈 문자열 | 편집 가능 |
| `false` | 편집 불가 (편집 영역 안의 비편집 영역) |
| `plaintext-only` | 텍스트만 편집, 서식 입력과 붙여넣기 서식 제거 |
| 없음·잘못된 값 | 부모에게서 상속 |

```html
<div contenteditable="true">
  편집 영역 <span contenteditable="false">고정 칩</span>
</div>
```

```js
div.isContentEditable    // true (상속 포함 현재 상태)
div.contentEditable      // 'true' (속성값 문자열)
```

- `plaintext-only`는 엔진별 도입 시기가 달라 MDN 지원표에서 대상 브라우저를 확인합니다.
- `document.designMode = 'on'`은 문서 전체를 편집 가능하게 만듭니다. iframe 안 문서를 편집기로 쓰던 옛 방식에서 쓰입니다.
- 편집 가능한 요소는 포커스를 받고 탭 순서에 들어갑니다. 중첩된 편집 영역은 기본적으로 탭 순서에 들어가지 않습니다.
- 캐럿 색은 `caret-color`로 바꿉니다.

### 편집 호스트

**편집 호스트**(editing host)는 편집 가능한 영역의 최상위 요소입니다. `contenteditable`이 켜져 있고 부모가 편집 가능하지 않은 요소가 호스트이며, `designMode`가 켜져 있으면 문서 루트가 호스트입니다.

- 호스트 안의 자손은 상속으로 편집 가능해집니다. 호스트에는 포커스와 `beforeinput`·`input` 이벤트가 걸리고, 이벤트는 호스트로 버블링합니다.
- 중첩된 `contenteditable="false"` 요소는 편집되지 않는 섬이 됩니다. 캐럿이 안으로 들어가지 않고, Backspace는 섬 전체를 한 번에 지웁니다. 멘션 칩, 태그 같은 원자적 요소에 씁니다.
- 중첩된 `contenteditable="true"`는 별도의 편집 호스트가 되지 않고 부모 호스트에 포함된 상태로 남습니다(상위가 이미 편집 가능하므로).
- `value` 속성이 없으므로 내용은 `innerText`·`textContent`·`innerHTML`로 읽습니다. 사용자 입력 HTML을 `innerHTML`에 넣으면 XSS 위험이 있습니다(자세히는 63편).

### 브라우저 기본 동작의 한계

- 엔터를 누를 때 새로 만들어지는 마크업(`div`, `p`, `br`)을 엔진이 정하고, 서식·붙여넣기·삭제 결과도 엔진마다 다릅니다.
- 서식 적용은 `b`와 `strong`, 인라인 `style`을 섞어 생성할 수 있어 결과 DOM이 일정하지 않습니다.
- 붙여넣은 HTML은 외부 서식을 그대로 가져옵니다.
- 이 편차를 줄이려면 `beforeinput`을 가로채 직접 처리합니다.

## beforeinput 기반 편집기 설계

`beforeinput`은 편집 호스트(또는 `input`·`textarea`)의 내용이 바뀌기 직전에 발생하는 `InputEvent`입니다. 버블링하고 대부분 취소할 수 있으며, 기본 동작을 막고 앱이 직접 문서를 갱신하는 설계의 진입점입니다. Baseline 널리 지원(2021년 3월부터)입니다. 키 이벤트의 한계와 composition 이벤트는 10편에서 다룹니다.

### 이벤트가 담는 정보

| 속성·메서드 | 내용 |
|-------------|------|
| `inputType` | 편집 동작의 종류 |
| `data` | 삽입될 텍스트 (입력 요소의 일반 삽입) |
| `dataTransfer` | contenteditable의 붙여넣기·드롭 내용 (자세히는 49편) |
| `isComposing` | IME 조합 중인지 |
| `getTargetRanges()` | 변경이 일어날 위치의 StaticRange 배열 |

| 대표 `inputType` | 의미 |
|------------------|------|
| `insertText` | 글자 입력 |
| `insertParagraph` · `insertLineBreak` | Enter · Shift+Enter |
| `insertFromPaste` · `insertFromDrop` | 붙여넣기 · 드롭 |
| `insertCompositionText` | IME 조합 중 입력 |
| `deleteContentBackward` · `deleteContentForward` | Backspace · Delete |
| `deleteByCut` | 잘라내기 |
| `historyUndo` · `historyRedo` | 실행 취소·다시 실행 |
| `formatBold` 등 `format*` | 서식 명령 |

`getTargetRanges()`는 contenteditable에서만 위치를 돌려줍니다. `<input>`·`<textarea>`에서는 빈 배열이고, 어디서든 `historyUndo`·`historyRedo`에서도 빈 배열입니다. Backspace처럼 선택이 접힌 상태에서도 지워질 글자를 가리키는 범위를 계산해 줍니다.

### 설계 흐름

기본 동작을 취소하고, 앱의 모델을 갱신한 뒤, 화면을 다시 그리는 구조입니다.

```js
editor.addEventListener('beforeinput', (e) => {
  if (e.isComposing) return          // IME 조합은 건드리지 않음
  e.preventDefault()
  const [range] = e.getTargetRanges()
  switch (e.inputType) {
    case 'insertText':
      model.replace(range, e.data); break
    case 'deleteContentBackward':
      model.replace(range, ''); break
    case 'historyUndo':
      model.undo(); break
  }
  render(model)                      // 렌더 후 선택 복원 필요
})
```

- 기본 동작을 취소하면 브라우저의 undo 스택에 기록되지 않습니다. 실행 취소는 앱이 `historyUndo`·`historyRedo`를 받아 직접 구현해야 합니다.
- 렌더링이 DOM을 교체하면 선택이 사라집니다. 렌더 뒤에 모델의 선택 위치를 `setBaseAndExtent`로 복원합니다.
- 모든 변경에 `beforeinput`이 오지는 않습니다. 자동완성, 맞춤법 교정, 비밀번호 관리자의 채움, 일부 IME 입력은 이벤트가 오지 않거나 취소할 수 없습니다. 이런 변경은 `input` 이벤트에서 모델과 DOM을 비교해 보정합니다.
- IME 조합 중(`insertCompositionText`) 입력은 취소할 수 없고, 취소하려 하면 조합이 깨집니다. 조합이 끝난 뒤에 모델에 반영합니다.
- `execCommand`가 일으킨 변경은 `beforeinput`·`input`이 발생할 수도, 안 할 수도 있습니다(다음 절).

**흔한 실수:** `keydown`에서 키 값을 보고 글자를 직접 넣는 방식입니다. IME, 붙여넣기, 드롭, 음성 입력, 모바일 키보드는 `keydown`에 의미 있는 값이 오지 않습니다. 편집 의도는 `beforeinput`의 `inputType`으로 판단합니다.

## execCommand의 폐기 상태

`document.execCommand(name, showUI, value)`는 contenteditable에서 서식·삽입·삭제·실행 취소 등의 편집 명령을 실행하는 옛 API입니다. MDN은 이 메서드를 폐기(deprecated) 대상으로 표시하며, 브라우저가 일관되거나 완전하게 구현하지 않는다고 설명합니다. 표준에서 제거될 수 있지만 현재 브라우저는 모두 동작합니다.

```js
document.execCommand('bold')                  // 선택 영역 굵게
document.execCommand('insertText', false, 'x')
document.execCommand('undo')
```

| 명령 예 | 용도 |
|---------|------|
| `bold` · `italic` · `underline` | 서식 |
| `insertText` · `insertHTML` · `insertImage` · `createLink` | 삽입 |
| `undo` · `redo` | 편집 기록 |
| `selectAll` · `delete` | 선택·삭제 |
| `copy` · `cut` · `paste` | 클립보드(Clipboard API로 대체, 자세히는 49편) |

- 반환값은 불리언이며 명령이 지원되지 않거나 비활성이면 `false`입니다. 사용자 상호작용 중에만 `true`를 돌려주는 명령이 있습니다.
- `showUI`는 Firefox에서 구현되지 않습니다. Firefox 82 이후 중첩 호출은 항상 실패합니다.
- 결과 마크업이 엔진마다 다르고(`b`와 `strong`, `style` span 등), 변경이 `beforeinput`·`input`을 일으키는지도 일정하지 않습니다.
- `insertHTML`은 주입 싱크(injection sink)이므로 신뢰할 수 없는 문자열을 넣으면 XSS가 됩니다. Trusted Types의 `TrustedHTML` 사용을 권장합니다(자세히는 63편).
- 장점은 하나입니다. 이 API를 거친 변경은 브라우저 undo 스택에 기록됩니다. DOM을 직접 바꾸면 undo 기록이 깨집니다.

| 목적 | 대체 수단 |
|------|-----------|
| 서식·구조를 일관되게 편집 | 자체 문서 모델 + `beforeinput` |
| 클립보드 | Clipboard API |
| 간단한 편집 | `contenteditable` 기본 동작 |
| undo가 필요한데 대체 수단 없음 | `execCommand` (지원 확인 후) |

`document.queryCommandSupported(name)`으로 명령 지원 여부를 확인합니다. 새 코드의 기본 선택지는 `execCommand`가 아닙니다.

## EditContext API

**EditContext**는 DOM 편집 호스트 없이 텍스트 입력 서비스(IME, 이모지 선택기, OS 입력 UI)를 연결하는 API입니다. 캔버스나 자체 렌더링 편집기처럼 DOM으로 텍스트를 그리지 않는 곳에서, 브라우저의 입력 처리만 빌려 쓰게 해 줍니다. Chromium(Chrome·Edge 121 이상)에서만 지원하고 Firefox·Safari는 지원하지 않으며 Baseline이 아닙니다. 점진적 향상으로만 사용합니다.

contenteditable과의 차이는 책임입니다. contenteditable은 브라우저가 DOM을 바꾸지만 EditContext는 브라우저가 텍스트·선택 변경을 이벤트로 알려 주기만 하고, 앱이 렌더링한다는 점입니다.

```js
const ctx = new EditContext({
  text: '', selectionStart: 0, selectionEnd: 0,
})
canvas.editContext = ctx          // 요소에 연결
ctx.addEventListener('textupdate', (e) => {
  // e.text 가 e.updateRangeStart ~ e.updateRangeEnd 를 대체
  model.splice(e.updateRangeStart, e.updateRangeEnd, e.text)
  draw()
})
```

| 구성 | 역할 |
|------|------|
| `HTMLElement.editContext` | 요소에 EditContext를 연결하는 속성 |
| `textupdate` | 사용자가 텍스트·선택을 바꿈 (`text`, `updateRangeStart`, `updateRangeEnd`, `selectionStart`, `selectionEnd`) |
| `textformatupdate` | IME 조합 중 서식(밑줄 등)을 적용해 달라는 요청 |
| `characterboundsupdate` | IME 창 위치를 정하려고 글자 사각형을 요청 |
| `compositionstart` · `compositionend` | 조합 시작·종료 |
| `updateText` · `updateSelection` | 앱의 변경을 EditContext의 상태에 반영 |
| `updateControlBounds` · `updateSelectionBounds` · `updateCharacterBounds` | 편집 영역·선택·글자의 화면 위치를 OS에 알림 |

앱이 해야 할 일: 텍스트 렌더링, 선택과 캐럿 렌더링, 선택 변경을 OS에 통지, IME 후보 창이 뜰 위치 제공, 조합 중 서식 적용.

- 캔버스에 연결할 때는 스크린 리더가 읽을 수 있도록 화면 밖 DOM에 같은 텍스트를 두어 접근성을 확보해야 합니다(자세히는 27편).
- 앱이 모델을 직접 바꾸면 `updateText`·`updateSelection`으로 EditContext의 상태도 맞춰 줍니다.
- DOM 기반 편집기는 contenteditable과 `beforeinput`으로 충분하며, EditContext는 캔버스·WebGL·WASM 기반 편집기에서 의미가 큽니다.

## CSS Custom Highlight API

**CSS Custom Highlight API**는 DOM을 바꾸지 않고 임의의 텍스트 Range에 스타일을 입히는 API입니다. 검색 결과 표시, 맞춤법 오류 밑줄, 협업 편집의 상대 선택 표시에 씁니다. web-features 데이터는 Baseline 2026(Firefox 149가 마지막 엔진, 2026-03-24)으로 기록합니다. MDN의 일부 페이지에는 2025로 표기되어 있어 날짜가 다를 수 있습니다.

네 단계로 사용합니다.

```js
const r = new Range()
r.setStart(textNode, 6)
r.setEnd(textNode, 11)
CSS.highlights.set('hit', new Highlight(r))   // 이름 'hit'으로 등록
```

```css
::highlight(hit) {
  background-color: gold;
  color: black;
}
```

| 구성 | 역할 |
|------|------|
| `Highlight` | Range(AbstractRange) 모음. Set처럼 `add`·`delete`·`clear`·`has`·`size` 사용 |
| `CSS.highlights` | 이름 대 Highlight를 저장하는 Map 같은 레지스트리 (`HighlightRegistry`) |
| `::highlight(이름)` | 해당 이름의 Highlight 구간에 스타일을 적용하는 CSS 의사 요소 |
| `Highlight.priority` | 겹칠 때 우선순위. 큰 값이 이김 |
| `Highlight.type` | 의미 표시: `'highlight'`, `'spelling-error'`, `'grammar-error'` |

- `::highlight()`에는 색 관련 속성만 쓸 수 있습니다. `color`, `background-color`, `text-decoration` 계열, `text-shadow` 등이며 `font-size`·`padding`처럼 레이아웃에 영향을 주는 속성은 적용되지 않습니다.
- 한 Highlight에 여러 Range를 넣을 수 있고, 여러 Highlight가 겹칠 수 있습니다. 같은 속성이 겹치면 `priority`가 높은 쪽이 이기고, 우선순위가 같으면 나중에 등록한 Highlight가 이깁니다.
- 일반 Range를 넣으면 DOM 변경에 따라 보정되지만 StaticRange는 보정되지 않습니다.
- Highlight 자체는 의미를 전달하지 않습니다. 중요한 강조에는 `mark` 같은 시맨틱 요소를 함께 쓰고, `type`으로 오류 표시의 의미를 알립니다.
- 선택 영역 자체의 스타일은 `::selection`이며 Highlight와 별개입니다.

```js
// 검색 결과 갱신: 이름만 교체하면 기존 표시가 바뀐다
CSS.highlights.set('hit', new Highlight(...ranges))
CSS.highlights.delete('hit')                 // 표시 제거
```

**흔한 실수:** 검색어가 바뀔 때 이전 이름의 Highlight를 지우지 않아 옛 결과가 화면에 남는 것입니다. 갱신 시 `CSS.highlights.set`으로 교체하거나 `delete`로 지웁니다.

## caretPositionFromPoint

**`document.caretPositionFromPoint(x, y)`**는 화면 좌표에 해당하는 텍스트 삽입 위치를 `CaretPosition`으로 돌려줍니다. 클릭한 지점의 캐럿 위치를 계산하거나 드롭 위치를 정할 때 씁니다. Baseline 2025입니다(2025년 12월부터 핵심 브라우저 전부 지원).

```js
document.addEventListener('click', (e) => {
  const pos = document.caretPositionFromPoint(e.clientX, e.clientY)
  if (!pos) return                 // 뷰포트 밖 등: null
  const r = new Range()
  r.setStart(pos.offsetNode, pos.offset)
  r.collapse(true)                 // 접힌 Range = 캐럿 위치
  getSelection().removeAllRanges()
  getSelection().addRange(r)
})
```

| 항목 | 내용 |
|------|------|
| 좌표 | 뷰포트 기준(clientX·clientY) |
| 반환 | `CaretPosition`의 `offsetNode`(노드), `offset`(글자 오프셋) 또는 `null` |
| `null`인 경우 | 문서에 뷰포트가 없음, 좌표가 음수이거나 뷰포트 밖, 삽입 위치가 없음 |
| 세 번째 인자 | `{ shadowRoots: [...] }` 옵션 |

- Shadow DOM 안쪽 위치를 얻으려면 `shadowRoots` 옵션에 해당 root를 넘깁니다. 넘기지 않으면 host 요소가 `offsetNode`로 돌아옵니다. getComposedRanges와 같은 리타깃팅 규칙입니다.
- 비표준인 `document.caretRangeFromPoint(x, y)`는 WebKit에서 시작한 같은 목적의 함수이고 Range를 돌려줍니다. 옛 브라우저 대응용 폴백으로만 씁니다.
- 스크롤된 문서에서는 `pageX`가 아니라 `clientX`를 넘깁니다.

## 핵심 정리

- Range는 문서 구간을 (컨테이너, 오프셋) 두 경계로 나타내며 살아 있습니다. StaticRange는 스냅샷이고 `beforeinput`·`getComposedRanges`가 이를 돌려줍니다.
- Selection은 문서당 하나이고 앵커·포커스(선택 방향)와 Range(문서 순서)가 다릅니다. `selectionchange`는 비동기로 `document`에서 발생합니다.
- Shadow DOM을 가로지르는 선택은 `getComposedRanges({ shadowRoots })`로, 화면 좌표의 캐럿 위치는 `caretPositionFromPoint`로 얻습니다.
- 편집은 contenteditable과 편집 호스트가 기본이고, 일관된 결과가 필요하면 `beforeinput`을 취소하고 자체 모델로 처리합니다. `execCommand`는 폐기 대상이며 장점은 undo 스택뿐입니다.
- EditContext는 Chromium 전용으로 캔버스형 편집기에 쓰고, Custom Highlight API는 DOM 변경 없이 Range에 색을 입힙니다.
