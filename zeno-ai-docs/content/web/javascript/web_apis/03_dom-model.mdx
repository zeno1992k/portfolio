## Node와 Element

DOM(Document Object Model)은 문서를 노드(node)의 트리로 표현하는 표준입니다. 모든 노드는 `Node` 인터페이스를 구현합니다. `Node` 자체는 추상이라 직접 만들 수 없고, 실제 객체는 아래 중 하나의 하위 인터페이스입니다.

| 인터페이스 | 노드 | 상속 |
|------------|------|------|
| `Document` | 문서 루트 | `Node` |
| `DocumentType` | `doctype` 선언 | `Node` |
| `DocumentFragment` | 가벼운 임시 컨테이너(`ShadowRoot`도 해당) | `Node` |
| `Element` | 요소 | `Node` |
| `Attr` | 속성 | `Node` |
| `CharacterData` | 문자 데이터(추상) | `Node` |
| `Text`, `Comment`, `ProcessingInstruction` | 텍스트, 주석, 처리 명령 | `CharacterData` |

`Node`는 `EventTarget`을 상속하므로 모든 노드에 이벤트 리스너를 붙일 수 있습니다(자세히는 07편). `Element`는 요소 전용 기능(속성, 선택자, 섀도 루트)을 더합니다(자세히는 04편, 05편).

### 노드 타입(nodeType)과 Text·Comment·Attr 노드

`nodeType`은 노드 종류를 숫자로 알려 줍니다. `Node`의 상수와 비교합니다.

| 상수 | 값 | `nodeName` |
|------|-----|------------|
| `Node.ELEMENT_NODE` | 1 | 대문자 태그 이름(`'DIV'`) |
| `Node.ATTRIBUTE_NODE` | 2 | 속성 이름 |
| `Node.TEXT_NODE` | 3 | `'#text'` |
| `Node.CDATA_SECTION_NODE` | 4 | `'#cdata-section'` |
| `Node.PROCESSING_INSTRUCTION_NODE` | 7 | 대상(target) |
| `Node.COMMENT_NODE` | 8 | `'#comment'` |
| `Node.DOCUMENT_NODE` | 9 | `'#document'` |
| `Node.DOCUMENT_TYPE_NODE` | 10 | doctype 이름 |
| `Node.DOCUMENT_FRAGMENT_NODE` | 11 | `'#document-fragment'` |

```js
const div = document.createElement('div')
div.nodeType === Node.ELEMENT_NODE // true
div.nodeName                       // 'DIV'
div.nodeValue                      // null (요소는 값이 없음)
document.createTextNode('a').nodeName // '#text'
```

- HTML 문서의 요소는 `nodeName`이 대문자이고 `localName`과 `tagName`도 같은 규칙을 따릅니다. 비교는 `localName`(소문자)이 편합니다.
- `nodeValue`는 `Attr`와 `CharacterData`에서만 값이 있고 나머지는 `null`입니다. 쓰기는 이 두 종류에서만 동작하고 요소에서는 무시됩니다.
- `Text` 노드는 요소 사이의 공백과 줄바꿈도 포함합니다. 마크업의 들여쓰기가 그대로 텍스트 노드가 됩니다.
- `Attr`는 노드지만 트리에 참여하지 않습니다. 부모와 자식이 없고 `parentNode`는 항상 `null`입니다. 요소의 `attributes`(`NamedNodeMap`)로 접근합니다(자세히는 05편).
- `Comment`는 `<!-- -->`에 해당하며 렌더링되지 않습니다. `CDATASection`은 XML 문서에서만 쓰입니다. HTML 파서는 만들지 않습니다.

### CharacterData

`CharacterData`는 `Text`와 `Comment`의 공통 부모이며 문자열 `data`를 가진 노드의 인터페이스입니다.

| 멤버 | 하는 일 |
|------|---------|
| `data` | 전체 문자열 읽기·쓰기 |
| `length` | 길이 |
| `substringData(offset, count)` | 일부 문자열 반환 |
| `appendData(s)` | 끝에 추가 |
| `insertData(offset, s)` | 위치에 삽입 |
| `deleteData(offset, count)` | 일부 삭제 |
| `replaceData(offset, count, s)` | 일부 교체 |

`Text`는 `splitText(offset)`과 `wholeText`를 더합니다.

```js
const t = new Text('Hello World')
t.replaceData(0, 5, 'Bye')   // 'Bye World'
const rest = t.splitText(3)  // t는 'Bye', rest는 ' World'
t.wholeText                  // 'Bye' (부모가 있으면 인접 텍스트 합)
```

- `offset`과 `count`는 UTF-16 코드 유닛 단위입니다. 이모지처럼 코드 유닛 둘짜리 문자를 가운데서 자를 수 있습니다.
- `offset`이 길이를 넘으면 `IndexSizeError`(`DOMException`)가 납니다.
- `splitText`는 부모가 있으면 새 노드를 바로 뒤에 삽입합니다.
- `textContent`와 `nodeValue`는 `CharacterData`에서 `data`와 같은 값입니다. 요소에서의 `textContent`는 자손 텍스트 전체입니다(자세히는 05편).

### HTML 인터페이스 상속 계층

HTML 요소의 객체는 요소마다 구체적인 인터페이스를 가집니다.

```
EventTarget → Node → Element → HTMLElement
  → HTMLInputElement, HTMLTableElement ...
```

```js
const input = document.createElement('input')
Object.getPrototypeOf(input) === HTMLInputElement.prototype
// true
input instanceof HTMLElement // true
input instanceof Element     // true
input instanceof Node        // true
```

- `HTMLElement`는 모든 HTML 요소의 공통 부모이며 `title`, `lang`, `dir`, `hidden`, `inert`, `click()`, `accessKey`, `draggable`, `spellcheck`, `innerText`, `popover` 같은 멤버가 있습니다(자세히는 05편).
- SVG 요소는 `SVGElement`를 쓰며 `HTMLElement`가 아닙니다. 둘 다 `Element`를 상속합니다(자세히는 53편).
- 표준에 없는 이름의 요소(`createElement('foo')`)는 `HTMLUnknownElement`입니다. 유효한 커스텀 요소 이름(`my-card`)은 정의 전이라도 `HTMLElement`입니다. 나중에 정의로 업그레이드할 때 인터페이스가 바뀌지 않게 하기 위해서입니다(자세히는 17편).
- 요소를 판별할 때는 `instanceof`보다 `nodeType`이나 `localName`이 안전한 경우가 있습니다. iframe 같은 다른 문서의 요소는 이 문서의 `HTMLElement`로 `instanceof`가 거짓이 됩니다.

## DOM Tree

문서는 `Document`를 루트로 한 노드 트리입니다. 표준이 정한 부모-자식 제약은 다음과 같습니다.

| 부모 | 가질 수 있는 자식 |
|------|-------------------|
| `Document` | 주석·처리 명령, `DocumentType` 최대 1개, `Element` 최대 1개(문서 요소) |
| `DocumentFragment`, `Element` | `Element`, `Text`, `Comment`, `ProcessingInstruction` |
| `DocumentType`, `CharacterData`, `Attr` | 자식 없음 |

- 문서 요소(document element)는 부모가 문서인 유일한 요소이며 HTML에서는 `html`입니다(`document.documentElement`, 자세히는 04편).
- 제약을 어기는 삽입은 `HierarchyRequestError`입니다. 텍스트 노드에 자식을 붙이거나 문서에 요소를 두 개 넣는 경우입니다.
- 노드는 한 곳에만 있을 수 있습니다. 이미 트리에 있는 노드를 다른 곳에 삽입하면 복사되지 않고 이동합니다.

```js
const a = document.createElement('ul')
const b = document.createElement('ul')
const li = document.createElement('li')
a.append(li)
b.append(li)   // 이동: a는 비고 b에 li가 있음
```

- 트리 순서(tree order)는 전위 깊이 우선입니다. 부모가 먼저, 자식이 문서 순서대로 옵니다. 컬렉션과 선택자 결과의 정렬 기준입니다.
- 섀도 DOM은 별도의 트리입니다. 섀도 루트를 루트로 하는 섀도 트리가 호스트 요소에 붙으며, 호스트가 속한 쪽을 라이트 트리라고 합니다(자세히는 21편).

## Document / DocumentFragment

### Document

`Document`는 문서 트리의 루트이자 노드를 만드는 팩토리입니다.

| 메서드 | 만드는 것 |
|--------|-----------|
| `createElement(name)` | 요소 |
| `createTextNode(data)` | 텍스트 노드 |
| `createComment(data)` | 주석 |
| `createDocumentFragment()` | 빈 프래그먼트 |
| `createAttribute(name)` | 속성 노드 |
| `createTreeWalker()`, `createNodeIterator()` | 순회 객체(아래 참조) |
| `createRange()` | 범위(자세히는 13편) |

- 생성자 `new Document()`로 새 빈 문서도 만들 수 있습니다. 브라우징 컨텍스트와는 무관한 문서입니다.
- 문서는 HTML 문서와 XML 문서로 나뉩니다. HTML 문서에서 `createElement('DIV')`는 이름을 소문자로 바꿔 만듭니다. XML 문서는 대소문자를 구분합니다.
- `compatMode`는 쿼크 모드이면 `'BackCompat'`, 아니면 `'CSS1Compat'`입니다. 쿼크 모드는 `doctype`이 없거나 오래된 형식일 때 파서가 정합니다.
- 문서의 `ownerDocument`는 `null`이고 다른 모든 노드는 자신이 속한 문서(node document)를 가집니다.
- 문서의 속성과 조회 메서드는 04편에서 다룹니다.

### DocumentFragment

`DocumentFragment`는 부모가 없는 가벼운 컨테이너입니다. 문서 트리에 속하지 않아서 그 안의 변경은 렌더링을 일으키지 않습니다.

```js
const frag = new DocumentFragment()
for (const name of ['a', 'b', 'c']) {
  const li = document.createElement('li')
  li.textContent = name
  frag.append(li)
}
list.append(frag)  // 세 li가 list로 이동
frag.childNodes.length // 0 (프래그먼트는 비워짐)
```

- 삽입하면 프래그먼트 자신이 아니라 자식들이 이동하고 프래그먼트는 빕니다. 같은 프래그먼트를 다시 쓰려면 복제해야 합니다.
- `ParentNode` 멤버(`append`, `children`, `querySelector` 등)와 `getElementById`를 가집니다. 요소 전용 멤버(속성, `innerHTML`)는 없습니다.
- `ShadowRoot`는 `DocumentFragment`의 하위 인터페이스입니다(자세히는 21편).
- 여러 노드를 한 번에 붙이는 용도는 04편에서 다룹니다.

## HTMLCollection vs NodeList

둘 다 노드 목록을 나타내는 옛 방식의 컬렉션입니다.

| 항목 | `NodeList` | `HTMLCollection` |
|------|-----------|------------------|
| 담는 것 | 모든 종류의 노드 | 요소만 |
| 길이·인덱스 | `length`, `item(i)`, `list[i]` | 같음 |
| 이름으로 접근 | 없음 | `namedItem(name)`, `list[name]`(`id` 또는 HTML 요소의 `name`) |
| 순회 | `for...of`, `forEach`, `keys`, `values`, `entries` | `for...of`만 |
| 배열 메서드 | 없음 | 없음 |

```js
const items = document.querySelectorAll('li') // NodeList
items.forEach((li) => li.classList.add('x'))
const kids = list.children              // HTMLCollection
kids.map                                // undefined
Array.from(kids).map((el) => el.id)     // 변환 후 사용
```

- 둘 다 배열이 아니므로 `map`, `filter`, `reduce`가 없습니다. `Array.from()`이나 `[...list]`로 변환합니다.
- 반환하는 API는 정해져 있습니다. 같은 요소 선택이라도 반환형이 다릅니다.

| 반환형 | API |
|--------|-----|
| `HTMLCollection` | `getElementsByTagName`, `getElementsByClassName`, `children`, `document.forms`·`images`·`links`, `table.rows` |
| `NodeList` | `childNodes`, `querySelectorAll`, `getElementsByName` |

- 표준은 `HTMLCollection`을 "웹에서 없앨 수 없는 역사적 유물"이라 부르며 새 API에는 쓰지 말라고 합니다. 새 API는 배열(`sequence`)을 반환합니다.
- 선택 API 자체는 04편에서 다룹니다.

## Live vs Static 컬렉션

라이브(live) 컬렉션은 호출 시점의 스냅숏이 아니라 실제 DOM을 계속 반영합니다. DOM이 바뀌면 이미 받아 둔 컬렉션의 내용도 바뀝니다. 정적(static) 컬렉션은 만들어진 순간의 목록이 고정됩니다. 표준은 달리 정하지 않으면 컬렉션을 라이브로 둡니다.

| 구분 | API |
|------|-----|
| 라이브 | `getElementsBy*`, `children`, `childNodes`, `document.forms` 등 |
| 정적 | `querySelectorAll` |

```js
// <li class="a"> 3개가 있을 때
const live = document.getElementsByClassName('a')
live.length              // 3
for (const el of live) {
  el.classList.remove('a') // 지우는 순간 live에서 빠짐
}
live.length              // 1 (하나를 건너뜀)
```

- 순회 중에 지우면 인덱스가 밀려서 요소를 건너뜁니다. `childNodes`에서 `remove()`를 반복하는 경우도 같습니다.
- 해결은 정적 목록으로 바꾸는 것입니다: `Array.from(live)`, `[...live]`, 또는 `querySelectorAll`.
- 반대로 정적 목록은 이후 추가된 요소를 반영하지 않습니다. 목록 객체가 얼려진 것이지 그 안의 요소가 얼려진 것은 아니어서, 요소 자체의 속성 변경은 그대로 보입니다.
- 라이브 컬렉션은 접근할 때마다 최신 상태를 보장해야 하므로 변경이 잦은 DOM에서 쓰기 전에 배열로 바꾸는 편이 안전합니다.
- 내용이 바뀌는 시점을 알고 싶으면 컬렉션이 아니라 `MutationObserver`를 씁니다(자세히는 43편).

**흔한 실수:** 라이브 컬렉션을 순회하면서 같은 컬렉션의 조건을 바꾸는 것, 그리고 `querySelectorAll` 결과를 보관해 두고 나중에 추가된 요소가 들어 있으리라 기대하는 것입니다.

## 부모 / 자식 / 형제 탐색

노드 사이를 이동하는 속성은 모든 노드를 대상으로 하는 것과 요소만 대상으로 하는 것으로 나뉩니다.

| 이동 | 모든 노드 | 요소만 |
|------|-----------|--------|
| 부모 | `parentNode` | `parentElement` |
| 자식 목록 | `childNodes`(`NodeList`) | `children`(`HTMLCollection`) |
| 첫 자식 | `firstChild` | `firstElementChild` |
| 마지막 자식 | `lastChild` | `lastElementChild` |
| 이전 형제 | `previousSibling` | `previousElementSibling` |
| 다음 형제 | `nextSibling` | `nextElementSibling` |
| 자식 유무·수 | `hasChildNodes()` | `childElementCount` |

```html
<ul id="menu">
  <li>A</li>
  <li>B</li>
</ul>
```

```js
menu.childNodes.length     // 5 (텍스트 3개 + li 2개)
menu.children.length       // 2
menu.firstChild.nodeType   // 3 (첫 줄바꿈 텍스트)
menu.firstElementChild.textContent // 'A'
```

- 마크업의 줄바꿈과 들여쓰기가 텍스트 노드로 들어가서 `firstChild`나 `nextSibling`이 의외로 공백 텍스트일 수 있습니다. 요소를 찾을 때는 요소만 탐색하는 속성을 씁니다.
- 문서 요소 `html`의 `parentNode`는 `document`이지만 `parentElement`는 `null`입니다. 부모가 요소가 아니면 `parentElement`는 `null`입니다. 섀도 루트와 프래그먼트의 직계 자식도 같습니다.
- 요소 전용 속성은 `ParentNode`(`Document`, `DocumentFragment`, `Element`)와 `NonDocumentTypeChildNode`(`Element`, `CharacterData`) 믹스인에 있습니다. 텍스트 노드에는 `children`이 없지만 `previousElementSibling`은 있습니다.
- 탐색 속성은 현재 트리 기준이며 섀도 트리의 경계를 넘지 않습니다(자세히는 21편). 선택자로 올라가는 `closest()`는 04편에서 다룹니다.
- 형제와 부모 탐색은 매번 직접 호출하는 값이라 라이브입니다. 캐시하지 않습니다.

### contains와 compareDocumentPosition

`node.contains(other)`는 `other`가 `node`의 자손이거나 `node` 자신이면 `true`입니다(포함적). `contains(null)`은 `false`입니다.

`compareDocumentPosition(other)`는 `other`가 기준 노드에 대해 어디에 있는지를 비트마스크로 반환합니다.

| 상수 | 값 | 의미 |
|------|-----|------|
| `DOCUMENT_POSITION_DISCONNECTED` | 1 | 서로 다른 트리 |
| `DOCUMENT_POSITION_PRECEDING` | 2 | `other`가 앞에 있음 |
| `DOCUMENT_POSITION_FOLLOWING` | 4 | `other`가 뒤에 있음 |
| `DOCUMENT_POSITION_CONTAINS` | 8 | `other`가 조상 |
| `DOCUMENT_POSITION_CONTAINED_BY` | 16 | `other`가 자손 |
| `DOCUMENT_POSITION_IMPLEMENTATION_SPECIFIC` | 32 | 구현이 정한 순서 |

```js
const pos = a.compareDocumentPosition(b)
pos & Node.DOCUMENT_POSITION_FOLLOWING // b가 a 뒤인가
// b가 a의 자손이면 pos는 20 (CONTAINED_BY 16 + FOLLOWING 4)
// b가 a의 조상이면 pos는 10 (CONTAINS 8 + PRECEDING 2)
```

- 값이 비트 조합이라 `===`가 아니라 `&`로 검사합니다.
- 서로 다른 트리의 노드이면 `DISCONNECTED`와 `IMPLEMENTATION_SPECIFIC`에 앞뒤 중 하나가 더해집니다. 앞뒤는 일관되지만 어느 쪽인지는 구현마다 다릅니다.

### getRootNode

`getRootNode()`는 노드가 속한 트리의 루트를 반환합니다.

| 노드의 위치 | 반환 |
|-------------|------|
| 문서에 연결됨 | `document` |
| 섀도 트리 안 | `ShadowRoot` |
| 어디에도 연결 안 된 서브트리 | 그 서브트리의 최상위 노드 |

- `getRootNode({ composed: true })`는 섀도 경계를 넘어 섀도 포함 루트를 반환합니다. 섀도 트리 안의 노드도 `document`에 도달합니다(자세히는 21편).

## DOM 연결 상태와 isConnected

노드의 섀도 포함 루트가 문서이면 연결된(connected) 상태이고, `isConnected`가 `true`입니다. 연결된다는 것은 화면에 그려질 수 있는 문서에 속했다는 뜻입니다.

```js
const el = document.createElement('div')
el.isConnected                 // false (만들기만 함)
document.body.append(el)
el.isConnected                 // true
el.remove()
el.isConnected                 // false (다시 분리)
```

- 부모가 연결되면 자손 전체가 함께 연결되고, 부모가 분리되면 자손 전체가 분리됩니다. 분리된 서브트리 안에서 `isConnected`는 모두 `false`입니다.
- 분리된 노드는 `document.getElementById()`로 찾을 수 없고 렌더 트리에 없어서 크기가 0입니다(자세히는 02편, 06편).
- 섀도 호스트가 문서에 연결돼 있으면 섀도 트리 안의 노드도 `isConnected`가 `true`입니다. 반면 `document.contains(shadowChild)`는 섀도 경계를 넘지 않아서 `false`입니다. 연결 여부는 `isConnected`로 판단합니다.
- 커스텀 요소의 `connectedCallback`과 `disconnectedCallback`은 연결 상태가 바뀔 때 호출됩니다(자세히는 18편).
- 비동기 콜백에서 요소를 쓰기 전에 `isConnected`를 확인하면 이미 제거된 요소를 건드리는 실수를 막을 수 있습니다.

## cloneNode와 importNode

### cloneNode

`node.cloneNode(deep)`는 노드의 복사본을 만듭니다. `deep`의 기본값은 `false`입니다.

```js
const li = document.querySelector('li')
const shallow = li.cloneNode()      // li와 속성만, 자식 없음
const deep = li.cloneNode(true)     // 자손까지 복사
deep.parentNode                      // null (복사본은 부모가 없음)
```

- 복사본은 부모가 없고 문서에 삽입되지 않은 상태입니다.
- 복사되는 것은 노드의 종류, 속성, 텍스트 데이터입니다. 요소에 `addEventListener`로 붙인 리스너와 스크립트로 직접 붙인 프로퍼티(`el.foo = 1`)는 복사되지 않습니다.
- `input`, `script`, `template`은 HTML 표준이 복제 단계를 따로 정의합니다. `input`은 현재 값 상태를, `template`은 깊은 복사일 때 `content`를 함께 복사합니다.
- `id`도 그대로 복사되므로 삽입하면 같은 `id`가 둘이 됩니다. 복사한 뒤 바꿉니다.
- 섀도 호스트는 섀도 루트가 `clonable: true`로 만들어졌을 때만 섀도 트리까지 복사됩니다(자세히는 21편).
- 복사본과 원본이 같은지는 `isEqualNode()`로 구조를 비교합니다. 같은 노드인지는 `===`입니다.

### importNode

`document.importNode(node, deep)`는 다른 문서의 노드를 이 문서의 노드로 복사합니다. `deep` 기본값은 `false`로 `cloneNode`와 같습니다. 두 번째 인수에 옵션 객체도 받으며 `selfOnly`(기본 `false`, 참이면 자손 제외)와 `customElementRegistry`(자세히는 17편)가 있습니다.

```js
const frameDoc = iframe.contentDocument
const src = frameDoc.querySelector('p')
const copy = document.importNode(src, true) // 이 문서 소속의 복사본
document.body.append(copy)
```

- 복사하지 않고 같은 노드를 쓰는 것은 `adoptNode`입니다(아래 참조).
- 문서와 섀도 루트는 가져올 수 없고 `NotSupportedError`입니다.
- 복제한 노드는 어느 문서가 소유하느냐에 따라 커스텀 요소의 정의를 찾는 레지스트리가 달라집니다. `template.content`를 복제할 때 중요합니다(아래 "template.content").

### adoptNode와 ownerDocument

`ownerDocument`는 노드가 속한 문서(node document)입니다. 문서 자신은 `null`입니다.

`document.adoptNode(node)`는 노드를 원래 부모에서 떼어 이 문서 소속으로 옮기고 같은 노드를 반환합니다. 복사하지 않습니다.

```js
const p = otherDoc.querySelector('p')
const moved = document.adoptNode(p)
moved === p                      // true
moved.ownerDocument === document // true
moved.parentNode                 // null (원래 자리에서 제거됨)
```

- 문서는 `NotSupportedError`, 섀도 루트는 `HierarchyRequestError`입니다.
- 커스텀 요소가 문서를 옮기면 `adoptedCallback`이 호출됩니다(자세히는 18편).
- 다른 문서의 노드를 `append` 같은 삽입 메서드로 붙이면 자동으로 이전(adopt)되므로 명시적인 `adoptNode`가 필요한 경우는 드뭅니다. `importNode`와 `adoptNode`의 차이는 복사 여부입니다.

## template.content

`template` 요소는 화면에 그려지지 않는 마크업 조각을 담습니다. 담긴 내용은 요소의 자식이 아니라 `content` 프로퍼티의 `DocumentFragment`에 있습니다.

```html
<template id="row">
  <li class="item"></li>
</template>
```

```js
const tpl = document.getElementById('row')
tpl.childNodes.length        // 0 (자식이 아님)
tpl.content.children.length  // 1
const node = tpl.content.cloneNode(true)
list.append(node)
```

- `content`는 일반 문서가 아니라 템플릿 전용의 비활성(inert) 문서에 속합니다. 브라우징 컨텍스트가 없어서 그 안의 스크립트는 실행되지 않습니다.
- `content`를 그대로 삽입하면 프래그먼트의 자식이 이동해서 템플릿이 비어 버립니다. 항상 복제해서 씁니다.
- 복제 방법은 두 가지입니다.

| 방법 | 복사본의 소속 문서 |
|------|--------------------|
| `tpl.content.cloneNode(true)` | 템플릿 전용 문서. 문서에 삽입할 때 이전됨 |
| `document.importNode(tpl.content, true)` | 현재 문서. 복제 시점에 이 문서의 커스텀 요소 정의를 따름 |

- 커스텀 요소가 들어 있는 템플릿은 `importNode`로 복제하면 복제 시점에 정의가 적용됩니다. `cloneNode`로 만든 복사본은 문서에 삽입된 뒤에 업그레이드됩니다. 어느 쪽이든 삽입 후에는 같은 요소가 되지만, 삽입 전에 복사본의 메서드를 호출하려면 `importNode`가 안전합니다.
- `template` 요소를 `cloneNode(true)`하면 `content`도 함께 복사됩니다.
- 섀도 DOM과 슬롯에 템플릿을 쓰는 방법은 22편에서 다룹니다.

## 노드 정규화: normalize와 인접 텍스트 노드

`splitText`나 `appendChild`로 텍스트 노드를 이어 붙이면 인접한 `Text` 노드가 여러 개 생깁니다. 화면에는 한 문장으로 보여도 노드는 여럿입니다.

```js
const p = document.createElement('p')
p.append('Hello, ', 'World', '!') // 문자열마다 텍스트 노드
p.childNodes.length               // 3
p.textContent                     // 'Hello, World!'
p.normalize()
p.childNodes.length               // 1
```

- `normalize()`는 자손의 빈 텍스트 노드를 지우고, 이웃한 텍스트 노드를 첫 노드로 합칩니다.
- `wholeText`는 이웃한 텍스트 노드 전체의 데이터를 합쳐 읽을 뿐 노드를 바꾸지 않습니다.
- `textContent`에 쓰면 모든 자식이 하나의 텍스트 노드로 교체됩니다.
- 텍스트 노드를 개수로 세거나 첫 텍스트 노드의 `data`만 읽는 코드는 노드가 쪼개져 있을 때 틀립니다. 필요하면 `normalize()`를 먼저 부릅니다.

## TreeWalker · NodeIterator · NodeFilter

트리를 순서대로 훑을 때 쓰는 API입니다. `document.createTreeWalker(root, whatToShow, filter)`와 `createNodeIterator(root, whatToShow, filter)`로 만듭니다.

| 항목 | `NodeIterator` | `TreeWalker` |
|------|----------------|---------------|
| 이동 | `nextNode()`, `previousNode()` | `nextNode()`, `previousNode()`, `parentNode()`, `firstChild()`, `lastChild()`, `previousSibling()`, `nextSibling()` |
| 위치 | `referenceNode`(읽기 전용) | `currentNode`(대입 가능) |
| 필터가 `FILTER_REJECT` | `FILTER_SKIP`과 같음(그 노드만 제외) | 그 노드의 서브트리까지 제외 |
| 성격 | 평평한 문서 순서 목록 | 트리 구조를 따라 이동 |

- `whatToShow`는 보여 줄 노드 종류의 비트마스크입니다: `NodeFilter.SHOW_ELEMENT`(1), `SHOW_TEXT`(4), `SHOW_COMMENT`(128), `SHOW_ALL`(모두, 기본값). `SHOW_ELEMENT | SHOW_TEXT`처럼 합칩니다.
- `filter`는 `NodeFilter` 콜백입니다. 함수이거나 `acceptNode`를 가진 객체이며 `FILTER_ACCEPT`(1), `FILTER_REJECT`(2), `FILTER_SKIP`(3)을 반환합니다.
- 필터가 `null`이면 `whatToShow`에 맞는 노드를 모두 받아들입니다.

```js
const walker = document.createTreeWalker(
  root,
  NodeFilter.SHOW_TEXT,
  (n) => n.data.trim()
    ? NodeFilter.FILTER_ACCEPT
    : NodeFilter.FILTER_SKIP,
)
const texts = []
while (walker.nextNode()) {
  texts.push(walker.currentNode.data)
}
```

- `TreeWalker`의 `currentNode`는 처음에 `root`이고 `nextNode()`는 그 다음 노드부터 반환합니다. `NodeIterator`는 첫 `nextNode()`에서 `root`도 후보입니다.
- 필터 안에서 순회 객체를 다시 부르면 `InvalidStateError`입니다.
- `NodeIterator`는 순회 중 노드가 제거돼도 기준 위치를 스스로 갱신합니다. `detach()`는 아무 일도 하지 않으며 호출할 필요가 없습니다.
- 반환하는 정적 목록(`querySelectorAll`)과 달리 둘 다 호출하는 시점마다 현재 트리를 읽습니다.
- 용도는 선택자로 표현하기 어려운 조건(텍스트 노드, 주석 노드)과 조건이 복잡한 전체 탐색입니다.

## XPath 개요

XPath는 문서에서 노드를 고르는 질의 언어이며 DOM에는 XPath 1.0을 평가하는 API가 있습니다. DOM 표준은 널리 구현됐지만 더 이상 발전시키지 않는 API라고 밝힙니다. `document.evaluate()`가 진입점입니다.

```js
const result = document.evaluate(
  '//a[@href]',                   // XPath 식
  document,                        // 컨텍스트 노드
  null,                            // 네임스페이스 리졸버
  XPathResult.ORDERED_NODE_SNAPSHOT_TYPE,
  null,
)
result.snapshotLength              // 일치한 노드 수
result.snapshotItem(0)             // 첫 노드
```

| 결과 유형 | 얻는 방법 |
|-----------|-----------|
| 숫자·문자열·불리언 | `numberValue`, `stringValue`, `booleanValue` |
| 첫 노드 하나 | `FIRST_ORDERED_NODE_TYPE`, `singleNodeValue` |
| 노드 스냅숏 | `ORDERED_NODE_SNAPSHOT_TYPE`, `snapshotItem(i)`, `snapshotLength` |
| 노드 이터레이터 | `ORDERED_NODE_ITERATOR_TYPE`, `iterateNext()` |

- 이터레이터 유형은 순회 중 문서가 바뀌면 무효가 되어(`invalidIteratorState`) 예외가 납니다. 안전하게 쓰려면 스냅숏 유형을 고릅니다.
- CSS 선택자와 달리 텍스트 내용으로 고르거나(`//button[text()="OK"]`) 조상·형제 방향으로 질의할 수 있습니다. 그러나 대부분의 경우 `querySelector`로 충분합니다.
- 이 API는 `Document`에 있고 `new XPathEvaluator()`로도 같은 메서드를 씁니다. 모든 주요 브라우저가 지원합니다(Baseline 2015).

## 요소별 편의 API

일부 HTML 요소는 DOM의 일반 메서드 대신 구조를 이해하는 전용 API를 제공합니다. 표 요소가 대표적입니다.

| 요소 | 멤버 |
|------|------|
| `HTMLTableElement` | `rows`, `tBodies`, `tHead`, `tFoot`, `caption`, `insertRow()`, `deleteRow()`, `createTHead()`, `createTFoot()`, `createTBody()`, `createCaption()` |
| `HTMLTableRowElement` | `cells`, `rowIndex`, `sectionRowIndex`, `insertCell()`, `deleteCell()` |

```js
const table = document.createElement('table')
const row = table.insertRow()  // 맨 끝(-1)에 추가, tbody 자동 생성
const cell = row.insertCell()  // 맨 끝에 td 추가
cell.textContent = 'A1'
table.rows.length              // 1
table.tBodies.length           // 1
```

- `insertRow(index)`의 `index` 기본값은 -1(끝)이며 범위를 벗어나면 `IndexSizeError`입니다. 행이 없고 `tbody`도 없는 표에서는 `tbody`를 만들어 그 안에 행을 넣습니다.
- `rows`는 `thead`, `tbody`, `tfoot` 안의 행을 문서 순서로 모두 포함합니다. 라이브 `HTMLCollection`입니다.
- 이런 전용 API는 구조 규칙을 알아서 지켜 주므로 `createElement('tr')`과 `append`를 직접 조합하는 것보다 안전합니다.
- 폼의 `elements`, `select`의 `options` 같은 다른 요소 API는 11편에서, `img`의 `decode()`와 `complete`는 15편에서 다룹니다.

## 핵심 정리

- DOM은 `Node`를 루트로 하는 노드 트리이며 `nodeType`으로 요소·텍스트·주석·문서·프래그먼트를 구분하고, HTML 요소는 `Node → Element → HTMLElement → 구체 인터페이스`로 상속합니다.
- `childNodes`와 `firstChild` 계열은 공백 텍스트를 포함한 모든 노드를, `children`과 `firstElementChild` 계열은 요소만 다룹니다.
- `NodeList`와 `HTMLCollection`은 배열이 아니며, `getElementsBy*`·`children`·`childNodes`는 라이브라서 순회 중 변경하면 요소를 건너뛰고 `querySelectorAll`은 정적입니다.
- 연결 상태는 `isConnected`로 판단하고, 이미 트리에 있는 노드를 삽입하면 복사가 아니라 이동합니다.
- `cloneNode`는 리스너와 스크립트 프로퍼티를 복사하지 않고, `importNode`는 다른 문서에서 복사하며, `adoptNode`는 복사 없이 이전합니다.
- `template.content`는 비활성 프래그먼트라서 복제해 쓰고, 텍스트 노드 분리는 `normalize()`로, 조건부 순회는 `TreeWalker`로 처리합니다.
