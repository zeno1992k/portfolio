## 패턴을 고르는 기준

데이터 컴포넌트는 의미 구조와 성능 전략을 따로 정합니다. 둘은 독립이라서 조합합니다.

| 질문 | 선택지 |
|------|--------|
| 읽기만 하는 표인가 | 네이티브 `table` |
| 셀을 편집하거나 셀 안에 위젯이 많은가 | `grid` 패턴 |
| 계층 구조인가 | `tree` 패턴 |
| 끝없이 이어지는 기사·게시물인가 | `feed` 패턴 |
| 항목이 수천 개 이상인가 | 윈도잉(Virtual List) |
| 스크롤하며 이어서 불러오나 | 센티널 관찰(Infinite Scroll) |

- 위젯별 역할·키보드 규칙은 W3C APG(Authoring Practices Guide)를 기준으로 합니다(키보드·포커스 일반 규칙은 28편).
- 관찰자 API는 43편, 파일·Blob은 48편, 성능 최적화는 66편에서 다룹니다.

## Data Table

데이터 테이블은 행과 열로 표현되는 읽기 중심의 데이터 목록입니다. 네이티브 `table`을 씁니다. APG도 가능한 한 네이티브 `table`을 쓰라고 강하게 권합니다. `div`와 `span`으로 만든 표보다 보조 기술 지원이 확실합니다.

```html
<table>
  <caption>주문 목록</caption>
  <thead>
    <tr>
      <th scope="col" aria-sort="ascending">
        <button type="button">주문일</button>
      </th>
      <th scope="col">금액</th>
    </tr>
  </thead>
  <tbody id="rows"></tbody>
</table>
```

| 요소·속성 | 역할 |
|-----------|------|
| `caption` | 표의 이름. 보조 기술이 표 진입 시 읽음 |
| `th scope="col"`, `th scope="row"` | 열·행 머리글 지정 |
| `aria-sort` | 정렬 중인 열 머리글에만 `ascending`, `descending`. 한 번에 하나의 열 |
| `aria-rowcount`, `aria-colcount` | 일부만 렌더링할 때 전체 행·열 수 |
| `aria-rowindex`, `aria-colindex` | 렌더링된 행·열의 실제 위치 |

- 정렬 컨트롤은 머리글 안의 `button`입니다. 클릭하면 `aria-sort`를 바꾸고 데이터를 다시 그립니다.

```js
th.querySelector('button').onclick = () => {
  const asc = th.ariaSort === 'ascending'
  const dir = asc ? 'descending' : 'ascending'
  headers.forEach((h) => h.removeAttribute('aria-sort'))
  th.ariaSort = dir
  render(sortBy(col, dir))
}
```

- 행 렌더링은 `template`을 복제하고 `replaceChildren`으로 한 번에 교체합니다. 행마다 이벤트 리스너를 달지 않고 `tbody`에 위임합니다(자세히는 4편, 7편).
- 정렬·필터·페이지는 서버에서 하는지 클라이언트에서 하는지를 먼저 정합니다. 행이 많으면 서버 쪽 정렬과 페이지네이션이 단순하고 안정적입니다.
- 일부만 렌더링하는 경우(가상화, 페이지네이션 일부) `aria-rowcount`로 전체 크기를, 각 행의 `aria-rowindex`로 위치를 알려 줍니다.
- 헤더 고정은 `position: sticky`(Baseline 널리 지원, 2019)로 처리합니다.
- 좁은 화면에서는 표를 가로 스크롤 컨테이너로 감싸고 컨테이너에 `tabindex="0"`과 이름을 주어 키보드로 스크롤할 수 있게 합니다.
- 셀 안에 버튼·입력이 많아 Tab 이동이 길어지면 grid 패턴으로 바꾸는 편이 낫습니다. 그리드는 하나의 복합 위젯이라 Tab 정류장이 하나입니다.

**흔한 실수:** 레이아웃용으로 `table`을 쓰거나 반대로 데이터 표를 `div` 그리드로 만드는 것입니다. 머리글과 셀의 관계가 사라져 스크린 리더가 셀을 읽을 때 열 이름을 알려 주지 못합니다.

## Grid 키보드 모델

그리드(grid)는 방향키로 셀 사이를 이동하는 2차원 복합 위젯입니다. 스프레드시트나 편집 가능한 데이터 표에 씁니다. 읽기 전용 표는 table이고, 그리드는 키보드로 셀을 조작할 때 씁니다.

```html
<div role="grid" aria-label="재고" aria-rowcount="500">
  <div role="row" aria-rowindex="1">
    <div role="columnheader">상품</div>
    <div role="columnheader">수량</div>
  </div>
  <div role="row" aria-rowindex="2">
    <div role="gridcell" tabindex="0">연필</div>
    <div role="gridcell" tabindex="-1">120</div>
  </div>
</div>
```

| 키 | 동작 |
|----|------|
| 방향키 | 인접 셀로 이동 |
| Home·End | 행의 처음·끝 셀 |
| Ctrl+Home·Ctrl+End | 그리드의 첫·마지막 셀 |
| Page Up·Page Down | 여러 행 이동(스크롤) |
| Enter·F2 | 편집 모드 진입. 편집 중에는 그리드 방향키 이동이 꺼짐 |
| Escape | 편집 모드 종료, 탐색 모드 복귀(편집을 취소하기도 함) |

- 역할은 컨테이너 `grid`, 행 `row`, 셀 `gridcell`·`columnheader`·`rowheader`입니다.
- 포커스는 roving tabindex나 `aria-activedescendant`로 관리합니다(28편). 한 셀만 `tabindex="0"`이라 그리드 전체가 Tab 정류장 하나입니다.
- 포커스를 줄 대상이 둘입니다. 셀 안에 방향키를 쓰지 않는 위젯(버튼, 링크, 체크박스)이 하나뿐이면 그 위젯에, 텍스트나 그림만 있으면 셀에 포커스를 둡니다.
- 편집 모드가 필요한 이유는 셀 안의 텍스트 입력이 방향키를 쓰기 때문입니다. 탐색 모드와 편집 모드를 분리해 키 충돌을 막습니다. 영숫자 키를 누르면 바로 편집을 시작하는 구현도 있습니다.
- 선택 상태는 `aria-selected`(셀 또는 행), 정렬은 `aria-sort`, 가상화된 그리드의 전체 크기는 `aria-rowcount`, `aria-colcount`, 위치는 `aria-rowindex`, `aria-colindex`로 알립니다.
- 레이아웃 그리드(카드 목록처럼 데이터가 아닌 배치용)는 같은 방향키 이동에 끝에서 감싸 이어지게 하는 선택 규칙이 있습니다.

```js
grid.addEventListener('keydown', (e) => {
  const d = { ArrowRight: [0, 1], ArrowLeft: [0, -1],
    ArrowDown: [1, 0], ArrowUp: [-1, 0] }[e.key]
  if (!d || editing) return
  e.preventDefault()
  moveFocus(row + d[0], col + d[1])
})
```

## Tree View

트리 뷰는 접고 펼 수 있는 계층 목록입니다. 파일 탐색기, 카테고리 목록에 씁니다.

```html
<ul role="tree" aria-label="폴더">
  <li role="treeitem" aria-expanded="true" tabindex="0">
    src
    <ul role="group">
      <li role="treeitem" tabindex="-1">index.js</li>
    </ul>
  </li>
</ul>
```

| 항목 | 규칙 |
|------|------|
| 역할 | 컨테이너 `tree`, 노드 `treeitem`, 자식 묶음 `group` |
| 펼침 | 자식이 있는 노드에 `aria-expanded`(`true` 또는 `false`). 잎 노드에는 쓰지 않음 |
| 선택 | `aria-selected` 또는 `aria-checked` 중 하나로 일관되게. 다중 선택이면 컨테이너에 `aria-multiselectable="true"` |
| 위치 | 동적으로 불러오는 트리는 `aria-level`, `aria-setsize`, `aria-posinset` 필요 |

| 키 | 동작 |
|----|------|
| Down·Up Arrow | 보이는 노드 사이 이동 |
| Right Arrow | 닫힌 노드는 열기, 열린 노드는 첫 자식으로 이동 |
| Left Arrow | 열린 노드는 닫기, 닫힌 노드는 부모로 이동 |
| Home·End | 첫·마지막 보이는 노드 |
| Enter | 노드 활성화(선택 또는 펼침 토글) |
| Space | 다중 선택에서 선택 토글 |
| 글자 입력 | 이름이 일치하는 노드로 이동(타입어헤드) |

- 포커스(DOM 포커스)와 선택 상태는 별개입니다. 시각적으로도 둘을 구분해야 합니다. 특히 다중 선택에서 중요합니다.
- 포커스 관리는 roving tabindex나 `aria-activedescendant`입니다(28편).
- 자식을 지연 로딩하면 DOM에 없는 노드가 생깁니다. `aria-expanded`는 로딩 전에도 달고, 전체 개수를 알면 `aria-setsize`로 알립니다.
- 노드 수가 많으면 보이는 노드만 렌더링하는 가상화를 적용합니다(아래 Virtual List). 이때 평탄화한 목록에 `aria-level`로 깊이를 알립니다.
- 트리는 탐색용이고 데이터 열이 여러 개이면 treegrid가 맞습니다. 이 문서의 범위는 단일 열 트리입니다.

## Virtual List

가상 목록(windowing)은 전체 항목 중 화면에 보이는 범위와 앞뒤 여유분(overscan)만 DOM에 만드는 기법입니다. 항목이 수천 개를 넘으면 DOM 노드 수가 스타일 계산, 레이아웃, 메모리 비용을 키우기 때문에 씁니다(자세히는 66편, 67편).

구조는 세 층입니다.

| 요소 | 역할 |
|------|------|
| 스크롤 컨테이너 | 고정 높이에 `overflow: auto`. `scroll` 이벤트의 출처 |
| 전체 높이 스페이서 | 높이가 항목 수 × 항목 높이. 스크롤바 길이를 만듦 |
| 항목 창(window) | 보이는 범위만 담고 `transform: translateY`로 위치 이동 |

```js
const H = 40, OVER = 5   // 항목 높이, 여유분
function visibleRange(scrollTop, viewH, total) {
  const first = Math.floor(scrollTop / H)
  const last = Math.ceil((scrollTop + viewH) / H)
  return [Math.max(0, first - OVER),
    Math.min(total, last + OVER)]
}
```

```js
let queued = false
box.addEventListener('scroll', () => {
  if (queued) return
  queued = true
  requestAnimationFrame(() => {
    queued = false
    draw(visibleRange(box.scrollTop, box.clientHeight, n))
  })
}, { passive: true })
```

- 스크롤 처리는 `requestAnimationFrame`으로 프레임당 한 번만 합니다(자세히는 8편).
- 항목 높이가 모두 같으면 위의 계산이 정확합니다. 높이가 제각각이면 렌더링된 항목을 `ResizeObserver`로 측정해 높이를 캐시하고, 측정 전 항목은 추정 높이를 씁니다. 추정이 틀리면 스크롤 위치가 튀므로 보정이 필요합니다(자세히는 43편).
- 접근성: 일부만 렌더링되므로 항목에 `aria-setsize`(전체 개수)와 `aria-posinset`(위치)을 줍니다. 표라면 `aria-rowcount`와 `aria-rowindex`입니다.
- 화면 밖으로 나간 항목은 DOM에서 사라집니다. 포커스된 항목이 사라지면 키보드 포커스를 잃으므로 포커스 중인 항목은 범위 밖이어도 유지합니다.
- 브라우저의 페이지 내 검색은 DOM에 없는 항목을 찾지 못합니다. 검색이 중요하면 가상화를 피하거나 자체 검색을 제공합니다.
- 중간 규모(수백–수천 개)는 가상화 없이 `content-visibility: auto`와 `contain-intrinsic-size`로 화면 밖 렌더링을 건너뛸 수 있습니다. 화면 밖 내용도 DOM, 접근성 트리, 페이지 내 검색, Tab 순서에 남습니다. `content-visibility`는 Baseline 2025입니다(web-features 3.40.1 기준).

```css
.row {
  content-visibility: auto;
  contain-intrinsic-size: auto 40px;
}
```

**흔한 실수:** 스크롤 이벤트에서 `scrollTop`을 읽고 DOM을 바로 갱신해 강제 레이아웃을 일으키는 것입니다. 읽기와 쓰기를 한 프레임 안에서 분리합니다(자세히는 2편).

## Infinite Scroll List

무한 스크롤은 스크롤이 끝에 가까워지면 다음 데이터를 불러와 이어 붙이는 목록입니다. `scroll` 이벤트로 위치를 계산하지 않고 목록 끝의 센티널(sentinel) 요소를 `IntersectionObserver`로 관찰합니다. Baseline 널리 지원(2019)입니다.

```js
const io = new IntersectionObserver(([entry]) => {
  if (entry.isIntersecting) loadMore()
}, { rootMargin: '0px 0px 400px 0px' })
io.observe(sentinel)
```

- `rootMargin`으로 센티널이 화면에 닿기 전에 미리 불러옵니다. 이 값이 크면 일찍 불러오고 작으면 빈 화면이 보일 수 있습니다.
- 센티널은 목록의 마지막 요소 뒤에 둡니다. 새 항목을 추가하면 센티널이 아래로 밀려나가므로 다시 교차하기 전까지 추가 호출이 없습니다.

```js
async function loadMore() {
  if (loading || done) return
  loading = true
  list.setAttribute('aria-busy', 'true')
  const { items, next } = await fetchPage(cursor)
  list.append(...items.map(toNode))
  cursor = next
  done = next == null
  loading = false
  list.setAttribute('aria-busy', 'false')
}
```

| 상태 | 처리 |
|------|------|
| 로딩 중 | 중복 호출 방지 플래그, `aria-busy="true"`, 스켈레톤 또는 스피너 |
| 오류 | 센티널 자리에 "다시 시도" 버튼. 자동 재시도 루프는 피함 |
| 끝 | 센티널 관찰 해제(`io.disconnect()`)와 "마지막입니다" 표시 |
| 빈 결과 | 빈 상태 메시지 |

- 페이지는 오프셋보다 커서(마지막 항목의 ID나 토큰)로 요청하는 편이 안전합니다. 불러오는 사이 항목이 추가·삭제되면 오프셋은 중복이나 누락을 만듭니다.
- 요청은 `AbortController`로 취소하고, 필터가 바뀌면 이전 요청의 응답을 버립니다(자세히는 37편, 39편).
- 항목이 쌓이면 DOM이 계속 커집니다. 수백 개를 넘으면 가상화(앞 절)를 함께 씁니다.
- 푸터에 닿지 못하는 문제가 있습니다. 무한 스크롤에서는 푸터가 계속 밀려납니다. "더 보기" 버튼으로 불러오는 방식이나 푸터 고정으로 완화합니다.
- 뒤로 가기 시 스크롤 위치와 불러온 목록을 복원하려면 History 상태에 커서와 위치를 저장하거나 목록을 캐시합니다(자세히는 34편).
- 접근성은 다음 절의 feed 패턴을 따릅니다.

## Feed 패턴

피드(feed)는 스크롤에 따라 기사가 계속 추가되는 구조입니다. `feed` 역할은 위젯이 아니라 구조라서 보조 기술이 읽기 모드를 유지하고, 위젯 모드로 바꾸지 않습니다.

```html
<div role="feed" aria-labelledby="h" aria-busy="false">
  <article aria-labelledby="t1" aria-posinset="1"
           aria-setsize="-1" tabindex="0">
    <h3 id="t1">제목</h3>
    <p>내용…</p>
  </article>
</div>
```

| 항목 | 규칙 |
|------|------|
| 컨테이너 | `role="feed"`와 `aria-labelledby` 또는 `aria-label` |
| 항목 | `article`. `aria-labelledby`로 제목 요소를 가리키고 `aria-describedby`로 본문(권장) |
| 위치 | `aria-posinset`으로 순번, `aria-setsize`로 전체 개수. 전체를 모르면 `-1` |
| 로딩 | DOM을 갱신하는 동안 `aria-busy="true"`, 끝나면 `false` |
| 키보드 | Page Down·Page Up으로 이전·다음 기사 이동, Ctrl+End·Ctrl+Home으로 피드 밖 이동 |

- 역할 분담이 계약입니다. 웹 페이지는 시각적 스크롤과 콘텐츠 로딩을 포커스 위치에 맞춰 처리하고, 보조 기술은 읽기 커서와 탐색 키를 맡습니다. 기사에 포커스가 가면 페이지는 그 기사 주변이 로드되어 있도록 보장합니다.
- 피드는 널리 알려진 키보드 규칙이 없으므로 조작법을 눈에 띄게 문서화합니다.
- 항목 수가 끝없이 늘 때 앞쪽 항목을 DOM에서 지우면(가상화) `aria-posinset`으로 위치를 유지합니다.

## File Uploader

파일 업로더는 파일을 고르거나 끌어다 놓아 서버로 보내는 컴포넌트입니다. 선택, 검증, 미리 보기, 전송, 상태 표시, 취소·재시도로 나눠 설계합니다.

```html
<input type="file" id="f" multiple
       accept="image/*,.pdf" hidden>
<button type="button" id="pick">파일 선택</button>
```

```js
pick.addEventListener('click', () => f.click())
f.addEventListener('change', () => add([...f.files]))
```

### 선택과 검증

- `accept`는 확장자(`.pdf`), MIME 타입(`image/png`), 와일드카드(`image/*`)를 쉼표로 나열한 힌트일 뿐입니다. 사용자는 우회할 수 있어서 검증은 JavaScript와 서버에서 모두 합니다.
- `multiple`은 여러 파일, `webkitdirectory`는 폴더 선택(Baseline 2025)입니다. 모바일에서 `capture`(`user`, `environment`)는 카메라를 지정합니다.
- 선택 결과는 `files`(FileList)이고 각 `File`에서 `name`, `size`, `type`, `lastModified`를 읽습니다(자세히는 48편).
- 선택창을 닫기만 하면 `cancel` 이벤트가 발생합니다.
- 클라이언트 검증은 개수, 크기(`file.size`), 확장자·MIME(`file.type`은 확장자에서 추정되어 정확하지 않음)입니다. 오류는 파일마다 이유와 함께 보여 줍니다.
- 숨긴 `input`은 `hidden`이므로 버튼이 `click()`을 대신 호출합니다. 버튼이 키보드와 접근성을 담당합니다.

### 끌어다 놓기

- 드롭 영역은 `dragover`에서 `preventDefault()`를 호출해야 드롭이 허용됩니다. `drop`에서 `e.dataTransfer.files`를 읽습니다(자세히는 49편).
- 끌어다 놓기는 마우스 전용 보조 수단이므로 반드시 버튼으로 선택하는 경로도 둡니다.
- 영역을 벗어난 드롭이 브라우저의 기본 동작(파일 열기)으로 이어지지 않게 문서 단위 `dragover`·`drop`도 처리합니다.

### 미리 보기

- 이미지 미리 보기는 `URL.createObjectURL(file)`로 만들고 쓰고 나서 `URL.revokeObjectURL()`을 호출해 메모리를 해제합니다(자세히는 48편, 67편).
- 큰 파일을 `FileReader`로 통째로 읽어 `data:` URL로 만드는 방식은 메모리를 많이 씁니다.

### 전송과 진행률

`fetch`는 업로드 진행률 이벤트가 없습니다. 진행률이 필요하면 `XMLHttpRequest`의 `upload` 객체를 씁니다.

```js
const xhr = new XMLHttpRequest()
xhr.upload.addEventListener('progress', (e) => {
  if (e.lengthComputable) bar.value = e.loaded / e.total
})
xhr.addEventListener('load', () => done(xhr.status))
xhr.addEventListener('error', fail)
xhr.open('POST', '/upload')
xhr.send(formData)   // 취소는 xhr.abort()
```

- `progress` 이벤트의 `loaded`, `total`, `lengthComputable`로 진행률을 계산합니다. 진행률 표시는 `progress` 요소가 네이티브입니다.
- 취소는 `xhr.abort()`이고 `abort` 이벤트가 발생합니다. 진행률이 필요 없으면 `fetch`와 `AbortController`로 충분합니다.
- 여러 파일은 동시 전송 수를 제한하는 큐로 처리합니다. 한 번에 전부 보내면 연결과 메모리가 압박됩니다.
- 큰 파일은 `Blob.slice()`로 조각을 나눠 순서대로 보내고 서버가 받은 위치부터 이어 보내는 청크 업로드로 재시도 비용을 줄입니다(자세히는 48편, 37편).

### 상태와 접근성

| 상태 | 표시 |
|------|------|
| 대기 | 파일 이름과 크기, 제거 버튼 |
| 업로드 중 | `progress` 요소와 취소 버튼 |
| 성공 | 완료 표시 |
| 실패 | 이유와 "다시 시도" 버튼 |

- 파일마다 하나의 목록 항목으로 상태를 보이고, 상태 변화는 `role="status"`인 영역에 "report.pdf 업로드 완료"처럼 알립니다(자세히는 27편). 진행률을 퍼센트마다 알리면 스크린 리더가 끊임없이 읽으므로 시작과 끝만 알립니다.
- 폼에 포함해 제출하는 구조라면 `formAssociated` 요소로 `setFormValue(FormData)`를 써서 선택한 파일을 폼 값으로 내보냅니다(자세히는 26편).
- 보안: 파일 이름과 MIME 타입을 믿지 않고 서버에서 내용을 검증합니다. 미리 보기에 사용자 파일 이름을 `innerHTML`로 넣지 않습니다(자세히는 63편).

## 핵심 정리

- 읽기 전용 표는 네이티브 `table`(`caption`, `th scope`, `aria-sort`)이고, 셀 단위 키보드 조작과 편집이 필요하면 grid 패턴입니다. 부분 렌더링은 `aria-rowcount`와 `aria-rowindex`로 알립니다.
- 그리드는 방향키, Home·End, Ctrl+Home·End로 셀을 이동하고 Enter·F2로 편집 모드에 들어가며 Tab 정류장은 하나입니다. 트리는 Right·Left로 펼침과 부모·자식 이동을 합니다.
- 가상 목록은 보이는 범위와 여유분만 렌더링하고 `aria-setsize`·`aria-posinset`으로 전체 크기를 알리며, 중간 규모는 `content-visibility: auto`로 충분할 수 있습니다.
- 무한 스크롤은 센티널을 `IntersectionObserver`로 관찰하고 커서 기반 요청, 중복 방지, 취소, 오류·끝 상태를 처리하며, 접근성은 `feed` 역할과 `aria-busy`로 알립니다.
- 파일 업로더는 `accept`를 힌트로만 쓰고 클라이언트·서버에서 검증하며, 진행률은 `fetch`가 아닌 `XMLHttpRequest.upload`로 얻고 상태 변화는 live region으로 알립니다.
