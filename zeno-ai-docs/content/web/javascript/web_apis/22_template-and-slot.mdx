## template 요소

`template`은 렌더링하지 않고 보관만 하는 HTML 조각을 담는 요소입니다. 문서에 있어도 화면에 나타나지 않고, 안의 스크립트는 실행되지 않습니다. 필요할 때 복제해서 쓰는 틀입니다. Baseline 2015, 널리 지원됩니다.

```html
<template id="row-tpl">
  <li><slot></slot></li>
</template>
```

- 콘텐츠 모델이 "없음"입니다. 파서는 `template` 안의 마크업을 요소의 자식이 아니라 별도의 조각(template contents)에 넣습니다.
- 그래서 `row-tpl.children.length`는 `0`이고, `document.querySelector('#row-tpl li')`도 `null`입니다.
- `innerHTML`로 읽고 쓰면 요소 자식이 아니라 이 조각이 대상입니다.
- `template`은 Declarative Shadow DOM에도 쓰입니다. `shadowrootmode` 속성이 붙으면 파서가 이 요소를 shadow root로 바꿉니다(자세히는 21편).

```js
const tpl = document.createElement('template')
tpl.innerHTML = '<p>Hello</p>'
tpl.children.length     // 0
tpl.content.children.length // 1
```

## template.content

`content`는 template contents를 가리키는 읽기 전용 `DocumentFragment`입니다. 자식 요소와 달리 문서와 분리된 상태로 존재합니다.

- 이 조각의 소유 문서는 현재 문서가 아니라 브라우징 컨텍스트가 없는 별도의 문서(inert template document)입니다. 문서마다 하나이며 모든 `template`이 공유합니다. 그래서 내용이 활성화되지 않습니다.
- 조각은 문서에 삽입될 때에야 현재 문서로 옮겨집니다(adopt).
- 안의 요소를 선택하려면 `content.querySelector()`를 씁니다.

```js
const tpl = document.getElementById('row-tpl')
tpl.content instanceof DocumentFragment // true
tpl.content.ownerDocument === document  // false
tpl.content.querySelector('li')         // <li>
```

`HTMLTemplateElement`에는 `content` 외에 선언적 shadow root 속성에 대응하는 `shadowRootMode`, `shadowRootDelegatesFocus`, `shadowRootClonable`, `shadowRootSerializable`, `shadowRootSlotAssignment` 프로퍼티가 있습니다.

**흔한 실수:** `content`를 복제하지 않고 그대로 삽입하는 것입니다. `DocumentFragment`는 삽입하면 자식이 대상으로 이동하고 조각은 비게 됩니다. 두 번째 인스턴스부터는 아무것도 나타나지 않습니다.

```js
shadow.append(tpl.content)             // ❌ 한 번만 동작
shadow.append(tpl.content.cloneNode(true)) // ✅ 매번 복제
```

## 템플릿 Clone

템플릿을 쓸 때마다 `content`를 깊은 복제해서 삽입합니다. 복제 방법은 두 가지입니다.

| 방법 | 복제본의 소유 문서 |
|------|--------------------|
| `tpl.content.cloneNode(true)` | 템플릿의 inert 문서. 문서에 삽입될 때 옮겨짐 |
| `document.importNode(tpl.content, true)` | 현재 문서. 사용자 정의 요소가 복제 시점에 업그레이드됨 |

- 둘 다 `true`가 깊은 복제를 뜻합니다. 생략하면 조각 자체만 복제되어 빈 조각이 됩니다.
- 사용자 정의 요소가 들어 있는 템플릿은 `importNode()`로 복제하면 삽입 전에 이미 업그레이드되어 있습니다(자세히는 18편).
- `template` 요소 자체를 `cloneNode(true)`로 복제하면 template contents도 함께 복제됩니다.

컴포넌트에서의 표준 형태는 모듈 범위에서 `template`을 한 번 만들고 인스턴스마다 복제하는 것입니다. 문자열 파싱이 인스턴스 수만큼 반복되지 않습니다.

```js
const tpl = document.createElement('template')
tpl.innerHTML = '<style>:host{display:block}</style>' +
  '<slot></slot>'

class Box extends HTMLElement {
  constructor() {
    super()
    this.attachShadow({ mode: 'open' })
      .append(tpl.content.cloneNode(true))
  }
}
customElements.define('x-box', Box)
```

- `addEventListener()`로 단 리스너는 복제되지 않습니다. 복제한 뒤에 연결합니다.
- 복제본은 `id`를 그대로 가지므로 shadow tree 안에서는 충돌하지 않지만 light DOM에 직접 넣으면 문서 안에서 중복됩니다(자세히는 21편).

## slot 요소

`slot`은 shadow tree 안에 두는 자리표시자로, host의 Light DOM 자식을 그 자리에 보여 줍니다. Baseline 2020, 널리 지원됩니다. shadow tree 밖에 쓴 `slot`은 아무것도 받지 못합니다.

```html
<!-- x-card 의 shadow tree -->
<slot name="title"></slot>
<slot></slot>
```

```html
<!-- 사용하는 쪽 (Light DOM) -->
<x-card>
  <h2 slot="title">제목</h2>
  <p>본문</p>
</x-card>
```

- 배정 대상(slottable)은 host의 직계 자식 중 `Element`와 `Text` 노드입니다. 손자 요소는 배정되지 않습니다.
- 배정은 호스트 자식의 `slot` 속성 값과 `slot` 요소의 `name` 값을 문자열로 비교해서 정해집니다. `Element.slot`과 `HTMLSlotElement.name`이 각각 이 속성을 반영합니다.
- UA 스타일에서 `slot`은 `display: contents`로 취급되어 자체 박스를 만들지 않습니다. `display`를 지정하면 박스를 만들 수 있습니다.
- 배정되지 않은 자식은 DOM에는 남아 있지만 렌더링되지 않습니다.

## 기본 Slot

`name`이 없는(빈 문자열인) 슬롯이 기본 슬롯(default slot)입니다. `slot` 속성이 없는 자식과 모든 텍스트 노드가 여기에 배정됩니다.

```html
<x-card>
  <h2 slot="title">제목</h2>
  텍스트 노드
  <p>이름 없는 요소</p>
</x-card>
<!-- 기본 슬롯 배정: 텍스트 노드, p, 그리고 공백 텍스트들 -->
```

- 같은 이름의 슬롯이 shadow tree에 여러 개 있으면 트리 순서상 첫 번째만 노드를 받습니다. 나머지는 항상 비어 있습니다.
- 기본 슬롯이 없으면 `slot` 속성이 없는 자식은 렌더링되지 않습니다.
- 줄바꿈과 들여쓰기로 생긴 공백 텍스트 노드도 배정 대상입니다. `assignedNodes()`의 결과에는 이 공백이 섞입니다(아래 "assignedNodes와 assignedElements").

## Named Slot

`name`이 있는 슬롯은 같은 값의 `slot` 속성을 가진 자식만 받습니다. 한 슬롯에 여러 자식을 배정할 수 있고, 요소를 배정해도 원래 DOM 위치는 변하지 않습니다.

```html
<x-card>
  <span slot="tag">New</span>
  <span slot="tag">Hot</span>
  <h2 slot="title">제목</h2>
</x-card>
<!-- tag 슬롯에 span 두 개가 문서 순서대로 들어감 -->
```

- `slot="title"`이 가리키는 `name="title"` 슬롯이 없으면 그 자식은 어디에도 배정되지 않아 렌더링되지 않습니다.
- 슬롯 안에서의 순서는 host 자식의 DOM 순서입니다. 순서를 바꾸려면 DOM을 바꾸거나 수동 배정을 씁니다.
- 속성 값은 대소문자를 구분합니다.

## Fallback Content

슬롯 요소의 자식은 배정된 노드가 없을 때만 보이는 대체 내용(fallback content)입니다.

```html
<slot name="title">제목 없음</slot>
```

- 렌더링을 정하는 flat tree 알고리즘은 슬롯에 배정된 노드가 하나도 없을 때에만 슬롯의 자식을 씁니다.
- 공백 텍스트도 배정 대상이므로 기본 슬롯에는 공백뿐인 자식이 있어도 배정 목록이 비지 않습니다.
- fallback 안의 내용도 shadow tree의 일부입니다. shadow tree의 스타일이 그대로 적용되고, 배정된 노드가 생기면 렌더링에서 빠집니다.
- 배정이 없는 슬롯에 fallback 자식이 추가·제거될 때도 `slotchange`가 발생합니다(아래).
- `assignedNodes({ flatten: true })`는 배정이 없을 때 fallback 내용을 돌려줍니다.

## slotchange 이벤트

`slotchange`는 슬롯에 배정된 노드 목록이 바뀔 때 해당 슬롯에서 발생하는 이벤트입니다. Baseline 2020, 널리 지원됩니다.

```js
const slot = root.querySelector('slot[name="item"]')
slot.addEventListener('slotchange', () => {
  const items = slot.assignedElements()
  this.count = items.length
})
```

- 노드가 배정되거나 배정에서 빠질 때, 자식의 `slot` 속성이 바뀔 때, 슬롯의 `name`이 바뀔 때, 배정이 없는 슬롯의 fallback 자식이 바뀔 때 발생합니다.
- 배정된 노드 안쪽의 변화(텍스트 수정, 손자 추가)에는 발생하지 않습니다. 이것은 `MutationObserver`로 감시합니다(자세히는 43편).
- `bubbles: true`이고 `composed`는 아니므로 shadow root까지만 버블링됩니다. root에 리스너 하나를 두고 `e.target`으로 어느 슬롯인지 구분할 수 있습니다(자세히는 21편).
- 같은 슬롯의 변경은 마이크로태스크 시점에 모아서 한 번만 발생합니다. 연속으로 여러 자식을 추가해도 이벤트는 한 번입니다.
- 표준은 배정 목록이 이전과 달라지면 신호를 보내도록 정합니다. 첫 배정도 목록이 달라지는 것이지만, MDN은 초기 배정에서는 발생하지 않는다고 적고 있습니다. 초기 상태는 이벤트에 의존하지 말고 컴포넌트가 준비되었을 때 `assignedNodes()`로 직접 읽습니다.

## assignedNodes와 assignedElements

슬롯에 배정된 노드를 `HTMLSlotElement`의 메서드로 읽습니다.

```js
slot.assignedNodes()                  // Text 와 Element
slot.assignedElements()               // Element 만
slot.assignedNodes({ flatten: true }) // 중첩 슬롯과 fallback 반영
```

| 메서드 | 반환 | `flatten: true`일 때 |
|--------|------|-----------------------|
| `assignedNodes()` | 배정된 `Element`와 `Text` 배열 | 배정된 슬롯을 그 슬롯의 배정 노드로 펼치고, 배정이 없으면 fallback 자식 반환 |
| `assignedElements()` | `Element`만 | 위와 같되 요소만 |

- 기본값은 `flatten: false`이고, 배정이 없으면 빈 배열입니다.
- 공백 텍스트 노드까지 `assignedNodes()`에 들어오므로 "자식이 있는가"를 판단하려면 `assignedElements().length`를 씁니다.
- 반환값은 호출 시점의 정적 배열입니다. 이후 변경은 반영되지 않습니다.

반대 방향은 `assignedSlot`입니다. 슬롯된 `Element`나 `Text`에서 자신이 배정된 슬롯을 읽습니다.

```js
const title = host.querySelector('[slot="title"]')
title.assignedSlot // shadow tree 안의 <slot name="title">
title.parentNode   // host (DOM 부모는 그대로)
```

- 배정되지 않았거나 shadow root가 closed이면 `null`입니다(자세히는 21편).
- `assignedSlot`은 직접 배정된 슬롯 하나를 돌려줍니다. 슬롯이 다시 다른 슬롯에 배정되어 있어도 가장 바깥 슬롯까지 올라가지 않습니다.

## 슬롯 재배정

배정은 자동으로 다시 계산됩니다. 아래 변경이 일어나면 영향받는 슬롯에서 `slotchange`가 발생합니다.

| 변경 | 결과 |
|------|------|
| host에 자식 추가·제거·이동 | 해당 노드가 배정되거나 해제됨 |
| 자식의 `slot` 속성 변경(`el.slot = 'x'`, `removeAttribute('slot')`) | 새 이름의 슬롯으로 이동. 속성을 지우면 기본 슬롯 |
| 슬롯의 `name` 변경 | shadow tree 전체의 배정을 다시 계산 |
| 이름이 같은 앞선 슬롯 추가·제거 | 첫 번째 슬롯이 바뀌며 노드가 이동 |
| shadow tree의 슬롯 추가·제거 | 대응하는 자식이 배정되거나 해제됨 |

```js
const h2 = card.querySelector('h2')
h2.slot = 'header'         // title → header 슬롯으로 이동
h2.removeAttribute('slot') // 기본 슬롯으로 이동
```

- 자식이 이동해도 같은 DOM 노드가 그대로 유지됩니다. 복제나 재생성이 일어나지 않습니다.
- 이 규칙은 `slotAssignment`가 `'named'`일 때의 규칙입니다. `'manual'`이면 `slot` 속성이 무시됩니다(아래).

## 중첩 slot과 flatten

슬롯 요소도 `slot` 속성을 가질 수 있어서 다른 컴포넌트의 슬롯에 배정될 수 있습니다. 바깥 컴포넌트가 받은 내용을 안쪽 컴포넌트의 슬롯으로 전달하는 방식입니다(slot forwarding).

```html
<!-- x-panel 의 shadow tree -->
<x-frame>
  <slot name="title" slot="header"></slot>
</x-frame>
```

- 사용자는 `x-panel`의 `title` 슬롯에 요소를 넣습니다. `x-frame`의 `header` 슬롯에는 `slot` 요소 자체가 배정됩니다.
- `x-frame`의 `header` 슬롯에서 `assignedNodes()`를 읽으면 사용자가 넣은 요소가 아니라 `slot` 요소가 나옵니다.
- `assignedNodes({ flatten: true })`는 배정된 `slot`을 그 슬롯이 가진 노드로 펼쳐서 최종적으로 렌더링되는 노드를 돌려줍니다. 안쪽 슬롯이 배정을 못 받으면 그 슬롯의 fallback이 펼쳐집니다.
- `slot` 요소를 직접 `slot` 속성으로 전달하는 방식은 `x-panel` 내부에 `x-frame`을 두는 합성에서 필요합니다(자세히는 29편).
- 렌더링 결과, CSS 상속, 이벤트 경로는 모두 이 펼쳐진 flat tree를 따릅니다.

## 슬롯된 노드는 Light DOM에 남는다

슬롯에 배정된 노드는 어디로도 옮겨지지 않습니다. DOM상 위치는 host의 자식 그대로이고 화면에서만 슬롯 자리에 나타납니다. 이 사실에서 다음 규칙이 나옵니다.

| 영역 | 규칙 |
|------|------|
| 탐색 | `document.querySelector()`, `host.querySelector()`, `host.children`이 그대로 찾음. `parentNode`는 슬롯이 아니라 host |
| 스타일 | 문서의 스타일시트가 일반 요소처럼 적용됨. shadow tree에서는 `::slotted()`로만 최상위 배정 요소를 선택(자세히는 23편). `slot`은 `display: contents`라서 flat tree에서는 슬롯의 자식으로 상속받음 |
| 이벤트 | 이벤트 경로가 flat tree를 따라 슬롯과 shadow tree의 조상을 지남. `target`은 항상 슬롯된 노드 그대로(retargeting 없음) |
| 접근성 | 보조 기술은 flat tree를 순회하므로 슬롯된 내용이 슬롯 자리에서 읽힘 |
| 소유 | 사용자가 만든 마크업이므로 사용자의 CSS, 클래스, `id`, `label for`가 그대로 동작 |

- 이벤트: 슬롯된 버튼을 클릭하면 `button`, 슬롯, shadow tree의 조상, shadow root, host, 문서 순서로 경로가 이어집니다. shadow tree 안의 조상에서 리스너가 받는 `target`도 그 버튼입니다. 이벤트의 경계 규칙은 21편에서 다룹니다.
- 접근성: WICG의 Shadow DOM 초안은 보조 기술이 flat tree를 순회해 shadow tree 안에서도 WAI-ARIA 의미론을 쓸 수 있다고 적고 있습니다. 슬롯된 네이티브 요소(`button`, `a`, `input`)는 Light DOM에 있으므로 폼 제출, 레이블 연결, 기본 키보드 동작을 그대로 유지합니다.
- 스타일: 슬롯된 텍스트 노드는 `::slotted()`로 선택할 수 없습니다. 슬롯 요소에 스타일을 주고 상속에 의존하거나, 텍스트를 요소로 감싸서 받게 합니다.
- 컴포넌트가 슬롯 안의 내용을 직접 수정하면 사용자의 DOM을 바꾸는 것이 됩니다. 읽기와 배정 제어까지만 하는 것이 원칙입니다.

## 수동 슬롯 할당

기본 배정은 `slot` 속성으로 정해집니다. **수동 슬롯 할당**(manual slot assignment)은 컴포넌트가 JavaScript로 어떤 자식을 어떤 슬롯에 넣을지 직접 정하는 방식입니다. Baseline 2023, 널리 지원됩니다.

```js
const root = host.attachShadow({
  mode: 'open',
  slotAssignment: 'manual',
})
root.slotAssignment // 'manual'
slot.assign(host.children[0], host.children[2])
slot.assignedNodes() // [children[0], children[2]]
```

- `attachShadow()`에 `slotAssignment: 'manual'`을 주거나 Declarative Shadow DOM에서 `shadowrootslotassignment="manual"`을 지정한 root에서만 동작합니다.
- 이 모드에서는 `slot` 속성과 `name` 값이 배정에 쓰이지 않습니다. `assign()`으로 넘긴 노드만 배정됩니다.
- 인수는 `Element`와 `Text` 노드입니다. 인수를 주지 않고 `assign()`을 호출하면 그 슬롯의 배정이 모두 지워지고 fallback이 나타납니다.
- `assign()`은 그 슬롯의 이전 배정을 새 목록으로 교체합니다. 이미 다른 슬롯에 배정된 노드를 넘기면 그쪽에서 빠집니다.
- host의 직계 자식이 아닌 노드를 넘겨도 예외는 없지만 배정되지 않습니다. 자식이 host에서 제거되면 배정에서 빠지고, 같은 host에 다시 삽입하면 이전 `assign()` 기록으로 복원됩니다(MDN).
- `assign()`이 목록을 바꾸면 `slotchange`가 발생합니다. 배정은 자동으로 다시 계산되지 않으므로, 자식 목록이 바뀔 때마다 컴포넌트가 `assign()`을 다시 호출해야 합니다.

```js
const slot = root.querySelector('slot')
const sync = () => {
  const visible = [...host.children]
    .filter((c) => c.matches('[data-tab]'))
  slot.assign(...visible)
}
new MutationObserver(sync)
  .observe(host, { childList: true })
sync()
```

수동 할당이 맞는 경우는 자식에 `slot` 속성을 붙이게 하고 싶지 않을 때, DOM 순서와 다르게 표시할 때, 일부 자식만 골라 보여 줄 때(탭 패널, 가상 목록의 현재 구간)입니다.

## :has-slotted

`:has-slotted`는 배정된 노드가 하나라도 있는 슬롯을 선택하는 의사 클래스입니다. 슬롯의 flat 배정 목록이 비어 있지 않을 때 일치합니다.

```css
slot[name="footer"]:not(:has-slotted) { display: none }
slot[name="footer"]:has-slotted { border-top: 1px solid }
```

- 지원은 Firefox 136부터이며 미Baseline입니다. Chrome, Edge, Safari에서는 동작하지 않으므로 이것에 의존하면 안 됩니다.
- 공백 텍스트 노드 하나만 있어도 일치합니다. `assignedNodes()`와 일관되게 설계된 동작입니다.
- fallback이 있는 슬롯에서 일치하면 fallback은 렌더링되지 않는다는 뜻입니다.
- 모든 브라우저에서 쓰는 방법은 `slotchange`에서 상태를 계산해 host 속성이나 클래스로 반영하고 `:host([has-footer])`로 선택하는 것입니다.

```js
footerSlot.addEventListener('slotchange', () => {
  const has = footerSlot.assignedElements().length > 0
  this.toggleAttribute('has-footer', has)
})
```

## 컴포넌트 합성을 위한 Slot API

슬롯 합성에 관여하는 API를 역할별로 정리하면 다음과 같습니다.

| 역할 | API |
|------|-----|
| 사용자가 자리를 지정 | `slot` 속성(`Element.slot`) |
| 컴포넌트가 자리를 선언 | `slot` 요소와 `name`(`HTMLSlotElement.name`) |
| 배정 모드 선택 | `attachShadow({ slotAssignment })`, `ShadowRoot.slotAssignment` |
| 수동으로 배정 | `HTMLSlotElement.assign()` |
| 배정 결과 읽기 | `assignedNodes()`, `assignedElements()`, `Element.assignedSlot` |
| 배정 변화 감지 | `slotchange` 이벤트, `onslotchange` |
| 스타일 | `::slotted()`, `:has-slotted`(Firefox 전용) |
| 슬롯 전달 | `slot` 요소의 `slot` 속성, `flatten` 옵션 |

슬롯 이름은 컴포넌트의 공개 API입니다. 이름을 바꾸면 사용하는 쪽의 마크업이 깨지는 호환성 변경이므로 속성·메서드와 같은 수준으로 문서화하고 관리합니다(자세히는 19편).

## Wrapper 컴포넌트 설계

Wrapper 컴포넌트는 사용자가 넣은 내용을 소유하지 않고 감싸서 구조, 스타일, 동작만 더하는 컴포넌트입니다. 카드, 패널, 툴바, 레이아웃 래퍼가 해당합니다. 슬롯이 이 설계의 중심입니다.

```js
const tpl = document.createElement('template')
tpl.innerHTML = `
  <header><slot name="title">제목 없음</slot></header>
  <div class="body"><slot></slot></div>
  <footer><slot name="footer"></slot></footer>`
```

설계 규칙은 다음과 같습니다.

- 내용은 슬롯으로 받고, 값은 속성으로 받습니다. 긴 마크업이나 네이티브 요소(`button`, `a`, `input`)는 슬롯으로 받아야 폼, 레이블, 접근성 동작이 유지됩니다.
- 영역마다 이름 있는 슬롯을 두고, 자주 쓰는 영역 하나를 기본 슬롯으로 둡니다. 모든 슬롯의 의미와 기대하는 요소를 문서화합니다.
- 비어 있어도 의미가 통하는 슬롯에는 fallback을 둡니다. 비어 있을 때 영역 자체를 숨겨야 하면 `slotchange`로 상태를 만들어 반영합니다.
- 슬롯된 노드의 수·종류에 따라 바뀌는 상태는 `slotchange` 핸들러에서 `assignedElements()`로 계산합니다. 생성자에서 한 번 읽지 않습니다.
- 사용자의 자식 DOM은 수정하지 않습니다. 컴포넌트가 필요로 하는 표식(예: 항목 번호)은 슬롯 쪽 shadow tree에 만들거나 `::slotted()`, `part`, 속성 반영으로 처리합니다.
- 내용에 따라 레이아웃이 달라지는 컴포넌트는 슬롯이 `display: contents`라는 점을 고려해 박스가 필요한 곳에 감싸는 요소를 둡니다.
- 합성이 깊어지면 슬롯 전달(`slot` 속성이 붙은 `slot`)로 안쪽 컴포넌트에 내용을 넘기고, 최종 내용은 `flatten` 옵션으로 읽습니다(합성 패턴은 29편, 실전 구조는 79편).

**흔한 실수:** 슬롯 안의 사용자 요소에 컴포넌트가 직접 `classList`를 바꾸거나 `innerHTML`로 교체하는 것입니다. 사용자 프레임워크의 렌더링 결과와 충돌합니다. 필요하면 사용자 요소에 속성을 요구하거나 내부 shadow tree에서 대신 표현합니다.

## 핵심 정리

- `template`은 렌더링되지 않는 틀이고, 내용은 `content`(`DocumentFragment`)에 inert한 별도 문서 소유로 들어갑니다. 쓸 때마다 `cloneNode(true)`나 `importNode(..., true)`로 복제합니다.
- 슬롯은 host의 직계 자식(`Element`·`Text`)만 `slot` 속성과 `name`의 문자열 일치로 받고, 이름이 겹치면 첫 슬롯이 받으며, 빈 이름의 기본 슬롯이 나머지를 받습니다.
- 배정이 없을 때만 fallback이 쓰이고, 공백 텍스트도 배정되므로 판단은 `assignedElements()`로 합니다.
- `slotchange`는 배정 목록이 바뀔 때 슬롯에서 발생하고(내부 변화는 제외), 배정 결과는 `assignedNodes`·`assignedElements`·`assignedSlot`으로 읽으며 `flatten`이 중첩 슬롯과 fallback을 펼칩니다.
- 슬롯된 노드는 Light DOM에 그대로 남아 사용자의 CSS와 `label for`, 폼 동작을 유지하고, 이벤트와 접근성은 flat tree를 따릅니다.
- `slotAssignment: 'manual'`과 `assign()`은 컴포넌트가 배정을 직접 정하는 방식이고, `:has-slotted`는 Firefox에서만 지원되므로 `slotchange` 기반 상태로 대체합니다.
