## formAssociated 정적 속성

폼 연관 커스텀 요소(form-associated custom element)는 `static formAssociated = true`를 선언한 자율 커스텀 요소입니다. 이 선언이 있으면 요소는 가장 가까운 조상 `form`을 폼 소유자로 삼고, 네이티브 폼 컨트롤처럼 폼에 참여합니다.

```js
class RatingInput extends HTMLElement {
  static formAssociated = true
}
customElements.define('rating-input', RatingInput)
```

| 폼에서 일어나는 일 | formAssociated 선언 후 |
|--------------------|-------------------------|
| `form.elements`에 포함 | 포함됨 |
| 제출 시 값 전송 | `setFormValue`로 정한 값이 `name`으로 전송됨 |
| `form.checkValidity()`의 대상 | 포함됨 |
| `form.reset()`의 대상 | `formResetCallback` 호출 |
| `fieldset disabled` 영향 | 비활성화 상태가 됨 |

- 선언만으로는 값이 전송되지 않습니다. 값은 `setFormValue`로 직접 알려야 합니다.
- 커스텀 요소에는 `name`, `value`, `disabled` 같은 IDL 프로퍼티가 자동으로 생기지 않습니다. 필요한 프로퍼티는 클래스가 정의합니다(아래 "name / value / disabled 상태").
- 기본 제공 요소를 확장하는 커스터마이즈드 빌트인(`is` 문법)은 이미 폼 컨트롤을 상속하므로 이 선언이 필요 없습니다. 자율 요소(`HTMLElement`를 상속)만 대상입니다.
- 기능 감지는 `'setFormValue' in ElementInternals.prototype`으로 합니다. `ElementInternals`의 폼 관련 멤버는 Baseline 2023(널리 지원)이고 Chrome 77, Firefox 98, Safari 16.4부터 지원합니다.

## attachInternals

`attachInternals()`는 요소에 `ElementInternals` 객체를 붙여 반환하는 메서드입니다. 폼 참여, 검증, ARIA, 커스텀 상태 같은 요소의 내부 기능은 이 객체를 통해서만 접근합니다.

```js
class RatingInput extends HTMLElement {
  static formAssociated = true
  #internals = this.attachInternals()
}
```

- 요소 하나에 한 번만 호출할 수 있습니다. 두 번째 호출은 예외입니다.
- 객체를 비공개 필드에 보관합니다. 공개 프로퍼티로 두면 바깥에서 `setFormValue` 등을 마음대로 호출할 수 있습니다.
- `formAssociated`가 참이 아닌 요소에서 `setFormValue`·`setValidity`를 호출하면 `NotSupportedError`입니다.
- 생성자나 필드 초기화에서 호출할 수 있습니다. 호스트의 속성을 읽거나 자식을 만드는 일은 생성자에서 하지 않습니다(자세히는 17편, 18편).

## ElementInternals.form

`internals.form`은 요소의 폼 소유자인 `HTMLFormElement`를 돌려주고, 폼 안에 없으면 `null`입니다. 이 값은 읽기 전용입니다.

```js
const form = this.#internals.form
form?.addEventListener('submit', () => { /* ... */ })
```

폼 소유자는 다음 순서로 정해집니다.

- 요소에 `form` 어트리뷰트가 있으면 그 `id`의 폼이 소유자입니다. 폼이 조상이 아니어도 됩니다.
- 없으면 가장 가까운 조상 `form`입니다.
- 둘 다 없으면 `null`입니다.

### formAssociatedCallback

`formAssociatedCallback(form)`은 폼 소유자가 바뀔 때 호출됩니다. 폼에 들어가거나 나가면 인수로 새 폼 또는 `null`이 옵니다.

```js
formAssociatedCallback(form) {
  // form: 새 폼 소유자 또는 null
}
```

- 요소를 폼 안으로 옮기거나 `form` 어트리뷰트를 바꾸면 호출됩니다.
- 폼을 이벤트 대상으로 쓰고 있다면 이 시점에 이전 폼의 리스너를 제거하고 새 폼에 달아야 합니다.

## ElementInternals.labels

`internals.labels`는 이 요소를 가리키는 `label`들의 `NodeList`입니다(`for`로 연결되었거나 요소를 감싼 경우). 폼 연관 커스텀 요소는 레이블 가능 요소라서 `label`과 연결됩니다.

```html
<label for="r">평점</label>
<rating-input id="r"></rating-input>
```

```js
this.#internals.labels[0].textContent // '평점'
```

- 레이블 텍스트를 접근 가능한 이름으로 쓸 때 읽습니다(자세히는 27편).
- 연결된 레이블이 없으면 빈 `NodeList`입니다. 읽은 시점의 레이블만 반영되므로, 레이블이 나중에 붙을 수 있다면 `connectedCallback` 이후에 읽습니다.

## name / value / disabled 상태

폼 연관 커스텀 요소가 폼과 맞물려 쓰는 어트리뷰트는 `name`, `disabled`, `form`, `readonly`입니다. 이 어트리뷰트에 대응하는 프로퍼티는 클래스가 정의해야 합니다.

| 항목 | 브라우저가 처리하는 것 | 클래스가 할 일 |
|------|-----------------------|-----------------|
| `name` | 제출 시 이름으로 사용 | 프로퍼티가 필요하면 `getAttribute`로 반영 |
| `disabled` | 비활성 상태 판정, 제출 제외, `:disabled` 매칭 | 프로퍼티를 정의하고 어트리뷰트에 반영 |
| `readonly` | 제약 검증에서 제외(`willValidate`가 `false`) | 편집 동작은 직접 막기 |
| `value` | 없음. 예약된 의미가 없다 | 프로퍼티와 `setFormValue` 호출 |

```js
get name() { return this.getAttribute('name') }
set name(v) { this.setAttribute('name', v) }
get disabled() { return this.hasAttribute('disabled') }
set disabled(v) { this.toggleAttribute('disabled', !!v) }
```

- 제출되려면 `name`이 있어야 합니다. 이름이 없으면 값이 있어도 폼 데이터에 들어가지 않습니다.
- 비활성(`disabled`)은 `disabled` 어트리뷰트가 있거나 `disabled`인 `fieldset`의 자손일 때 성립합니다. 비활성 요소의 값은 제출되지 않습니다.
- `disabled` 요소가 사용자 입력을 받지 않게 하는 일은 브라우저가 해 주지 않습니다. 이벤트 처리와 포커스(`tabindex`)를 직접 끕니다.
- `value`는 규약이 없는 이름이라서 설계 자유도가 있습니다. 네이티브 컨트롤처럼 `value` 프로퍼티를 제공하면 사용하는 쪽이 익숙한 방식으로 쓸 수 있습니다.

## setFormValue

`internals.setFormValue(value)`는 요소의 제출 값을 브라우저에 알립니다. 폼이 제출될 때 이 값이 `name`과 짝지어 전송됩니다. 값을 바꿀 때마다 호출합니다.

```js
set value(v) {
  this.#value = String(v)
  this.#internals.setFormValue(this.#value)
}
// 제출: ?rating=4  (name="rating"일 때)
```

| value | 제출되는 것 |
|-------|-------------|
| 문자열 | 그 문자열 |
| `File` | 파일 하나 |
| `FormData` | 그 안의 각 이름·값 쌍. 요소의 `name`은 쓰이지 않는다 |
| `null` | 아무것도 제출되지 않음 |

```js
// 하나의 컨트롤이 여러 필드를 제출
const entries = new FormData()
entries.append('start', this.start)
entries.append('end', this.end)
this.#internals.setFormValue(entries)
```

- `null`은 체크되지 않은 체크박스처럼 "값 없음"을 표현합니다.
- 호출하지 않은 상태에서는 제출 값이 없습니다. 초기값이 있다면 `connectedCallback`이나 값 설정 시점에 한 번 호출합니다.
- 값을 바꾸고 `setFormValue`를 부르지 않으면 화면과 제출 값이 어긋납니다. 값이 바뀌는 경로가 여럿이면 한 곳(`#commit`)에서 호출합니다.

### state 인수와 복원

두 번째 인수 `state`는 사용자가 입력한 원래 형태를 담습니다. 제출 값(`value`)과 복원용 상태(`state`)가 다를 때 구분해서 씁니다.

```js
// 사용자는 '3/15/2019'를 입력, 서버는 '2019-03-15'를 기대
this.#internals.setFormValue('2019-03-15', '3/15/2019')
```

- `value`는 서버에 보낼 정규화된 값, `state`는 같은 화면을 복원하는 데 필요한 입력입니다. `state`를 생략하면 `value`가 `state`로 쓰입니다.
- `state`는 `File`, 문자열, `FormData` 중 하나이고, 브라우저가 폼 상태를 복원할 때 `formStateRestoreCallback`으로 되돌려 줍니다(다음 절).

## formStateRestoreCallback

`formStateRestoreCallback(state, mode)`는 브라우저가 사용자를 대신해 요소의 값을 갱신할 때 호출됩니다. `state`는 앞서 `setFormValue`에 넘긴 값이고, `mode`는 호출 이유를 나타내는 문자열입니다.

| mode | 의미 |
|------|------|
| `'restore'` | 뒤로 가기·새로고침 같은 내비게이션에서 폼 상태를 복원 |
| `'autocomplete'` | 브라우저의 자동 완성이 값을 채움 |

```js
formStateRestoreCallback(state, mode) {
  this.value = state
  // mode === 'restore' 또는 'autocomplete'
}
```

- 콜백에서 받은 `state`로 화면과 내부 값을 되돌리고, 필요하면 다시 `setFormValue`를 호출합니다.
- `restore` 때는 이전에 사용자가 입력한 상태를, `autocomplete` 때는 브라우저가 제안한 값을 받습니다. 두 경우 모두 사용자가 입력한 것과 같은 방식으로 처리하는 것이 일반적입니다.
- 복원할 값이 있으려면 `setFormValue`가 사용자 입력에 맞게 호출되어 있어야 합니다. 상태가 비어 있으면 복원되지 않습니다.

## formResetCallback

`formResetCallback()`은 폼 소유자가 초기화(`form.reset()` 또는 `reset` 버튼)될 때 호출됩니다. 요소를 초기 상태로 되돌리는 코드를 여기에 둡니다.

```js
formResetCallback() {
  this.value = this.getAttribute('value') ?? ''
}
```

- 초기값은 보통 마크업의 `value` 어트리뷰트(기본값)입니다. 사용자가 바꾼 현재 값과 기본값을 구분해서 보관합니다.
- 값을 되돌린 뒤에는 `setFormValue`로 제출 값도 갱신하고, 검증 상태와 화면(표시)도 함께 되돌립니다.
- 폼 안에 없는 요소에는 호출되지 않습니다.

## formDisabledCallback

`formDisabledCallback(disabled)`는 요소의 비활성 상태가 바뀔 때 호출되고 새 상태를 불리언으로 받습니다. 요소 자신의 `disabled` 어트리뷰트가 바뀌어도, 조상 `fieldset`이 비활성이 되거나 풀려도 호출됩니다.

```js
formDisabledCallback(disabled) {
  this.#button.disabled = disabled
  this.tabIndex = disabled ? -1 : 0
}
```

- `attributeChangedCallback`으로 `disabled` 어트리뷰트만 지켜보면 `fieldset`을 통한 비활성화를 놓칩니다. 비활성 상태에 반응하는 코드는 이 콜백에 둡니다.
- 비활성 상태에서 조작을 막는 일(포커스, 클릭, 키 입력)과 시각 표시는 구현자의 몫입니다.
- 선택자에서는 `:disabled`로 비활성 요소를 고를 수 있습니다(아래 "폼 관련 의사 클래스").

## setValidity

`internals.setValidity(flags, message, anchor)`는 요소의 유효성 상태를 정합니다. `flags`는 `ValidityState`의 플래그 이름을 키로 갖는 객체입니다(`valueMissing`, `typeMismatch`, `patternMismatch`, `tooLong`, `tooShort`, `rangeUnderflow`, `rangeOverflow`, `stepMismatch`, `badInput`, `customError`).

```js
// 값이 비었을 때 invalid로
this.#internals.setValidity(
  { valueMissing: true },
  '평점을 선택하세요.',
)

// 통과
this.#internals.setValidity({})
```

- 플래그 중 하나라도 `true`이면 `message`가 필수입니다. 없으면 `TypeError`입니다.
- 빈 객체 `{}`를 넘기면 유효 상태가 됩니다. 값이 바뀔 때마다 한 번 호출해서 현재 상태를 반영합니다.
- 플래그를 여러 개 켤 수 있고, 메시지는 하나입니다.
- 이 메서드는 상태를 기록할 뿐입니다. `required`나 `min` 같은 어트리뷰트를 자동으로 검사해 주지 않으므로 값을 검사하는 로직은 직접 작성합니다.
- `formAssociated`가 아니면 `NotSupportedError`입니다.

### anchor 인수

세 번째 인수 `anchor`는 브라우저가 오류 메시지를 띄우고 포커스를 줄 때 기준으로 삼을 요소입니다. 호스트 대신 내부의 포커스 가능한 요소(예: 내부 `input`)를 지정합니다.

```js
this.#internals.setValidity(
  { valueMissing: true },
  '값을 입력하세요.',
  this.#input, // shadow 트리 안의 요소
)
```

- `anchor`는 호스트 자신이거나 호스트의 shadow-including 자손이어야 하고, 아니면 `NotFoundError`입니다. 호스트의 shadow 트리 안 요소를 가리킬 때 씁니다.
- 표준은 브라우저가 `anchor`를 오류 표시에 사용할 수 있다고만 규정하므로 표시 방식은 브라우저마다 다를 수 있습니다.
- 생략하면 호스트가 기준이 됩니다. 호스트가 포커스 가능하지 않으면 제출 시 오류 위치로 이동하지 못할 수 있으므로, 호스트에 `tabindex`를 두거나 `anchor`를 내부 요소로 지정합니다.

## checkValidity / reportValidity

`internals.checkValidity()`와 `internals.reportValidity()`는 요소가 유효한지 검사합니다. 둘 다 유효하면 `true`, 아니면 `false`를 반환합니다.

| 메서드 | 유효하지 않을 때 하는 일 |
|--------|--------------------------|
| `checkValidity()` | 호스트에 `invalid` 이벤트를 발생시키고 `false` 반환 |
| `reportValidity()` | `invalid` 이벤트를 발생시키고, 취소되지 않았다면 사용자에게 오류 메시지를 보여 준다 |

```js
const ok = this.#internals.reportValidity()
// ok: false이면 메시지 표시와 포커스 이동이 일어날 수 있다
```

- 폼이 제출될 때 브라우저가 폼 안의 모든 컨트롤에 대해 이 검사를 수행합니다. 하나라도 유효하지 않으면 제출이 중단되고 `invalid` 이벤트가 발생합니다(자세히는 12편).
- `invalid` 이벤트에서 `preventDefault()`로 기본 메시지를 막고 자체 오류 UI를 보여 주는 흐름도 네이티브 컨트롤과 같습니다.
- 호스트 요소 자체의 `checkValidity()` 메서드는 자동으로 생기지 않습니다. 호스트에서 호출하게 하려면 `internals`로 위임하는 메서드를 정의합니다.

```js
checkValidity() {
  return this.#internals.checkValidity()
}
reportValidity() {
  return this.#internals.reportValidity()
}
```

## Constraint Validation 연동

제약 검증(Constraint Validation, 12편)에 참여하는 상태 값은 `internals`에서 읽습니다. 읽기 전용입니다.

| 멤버 | 값 |
|------|-----|
| `willValidate` | 검증 대상이면 `true`. 비활성(`disabled`)이거나 `readonly`이면 `false` |
| `validity` | `ValidityState` 객체. `setValidity`로 켠 플래그가 반영된다 |
| `validationMessage` | 오류 메시지 문자열. 유효하거나 검증 대상이 아니면 빈 문자열 |

```js
this.#internals.setValidity({ tooShort: true }, '너무 짧습니다.')
this.#internals.validity.tooShort     // true
this.#internals.validationMessage     // '너무 짧습니다.'
this.#internals.willValidate          // true
```

- 검증 대상이 아닌 요소(`willValidate`가 `false`)는 유효성 플래그가 있어도 제출을 막지 않습니다.
- 호스트의 `validity`·`willValidate`·`validationMessage`도 자동으로 생기지 않습니다. 네이티브 컨트롤과 같은 인터페이스가 필요하면 `internals`의 값을 돌려주는 getter를 정의합니다.

### 폼 관련 의사 클래스

브라우저는 `setValidity`와 비활성 상태를 보고 호스트에 의사 클래스를 맞춥니다.

| 선택자 | 매칭 조건 |
|--------|-----------|
| `:invalid` | 유효성 플래그가 켜져 있다 |
| `:valid` | 검증 대상이면서 플래그가 없다 |
| `:disabled` | 비활성 상태(`disabled` 어트리뷰트 또는 비활성 `fieldset`) |

```css
rating-input:invalid { outline: 2px solid crimson; }
rating-input:disabled { opacity: 0.5; }
```

- 입력 전에도 `:invalid`가 매칭되므로 처음부터 빨갛게 보일 수 있습니다. 사용자가 조작한 뒤에만 보이게 하려면 조작 여부를 자체 상태(클래스나 커스텀 상태)로 기록해 함께 조건에 씁니다. 네이티브 컨트롤의 `:user-invalid`는 12편에서 다룹니다.
- 의사 클래스는 호스트에 적용됩니다. shadow 트리 안의 요소를 꾸미려면 `:host(:invalid)`를 씁니다(23편).
- 직접 정의하는 상태(체크됨, 열림 등)는 `internals.states`와 `:state()`로 노출합니다(20편).

## 커스텀 input / checkbox 만들기

### 텍스트 값 컨트롤

값을 갖고 검증하는 최소 구조입니다.

```js
class NameInput extends HTMLElement {
  static formAssociated = true
  #internals = this.attachInternals()
  #value = ''
  get value() { return this.#value }
  set value(v) {
    this.#value = String(v)
    this.#internals.setFormValue(this.#value)
    const short = this.#value.length < 2
    this.#internals.setValidity(
      short ? { tooShort: true } : {},
      short ? '두 글자 이상 입력하세요.' : '',
    )
  }
}
```

### 체크박스

체크박스는 체크되지 않으면 제출 값이 없어야 하므로 `setFormValue(null)`을 씁니다. `checked` 어트리뷰트는 기본값이고 현재 상태는 따로 보관합니다.

```js
class ToggleBox extends HTMLElement {
  static formAssociated = true
  static observedAttributes = ['checked']
  #internals = this.attachInternals()
  #checked = false
  #dirty = false
  attributeChangedCallback() {
    if (this.#dirty) return
    this.#set(this.hasAttribute('checked'))
  }
  formResetCallback() {
    this.#dirty = false
    this.#set(this.hasAttribute('checked'))
  }
}
```

```js
  // ToggleBox 이어서
  toggle() {
    this.#dirty = true
    this.#set(!this.#checked)
  }
  #set(checked) {
    this.#checked = checked
    this.#internals.setFormValue(
      checked ? this.getAttribute('value') ?? 'on' : null,
    )
    this.#internals.ariaChecked = String(checked)
  }
```

- 체크됨의 제출 값은 `value` 어트리뷰트이고 없으면 `'on'`입니다. 네이티브 체크박스와 같은 규칙입니다.
- `#dirty`는 사용자가 한 번이라도 바꿨는지를 나타냅니다. 바꾼 뒤에는 `checked` 어트리뷰트가 바뀌어도 현재 상태를 덮어쓰지 않고, 초기화하면 다시 기본값을 따릅니다.
- `role="checkbox"`(`internals.role`), 키보드(스페이스), `tabindex`는 별도로 구현해야 합니다(27편, 28편).
- 같은 구조로 라디오 그룹, 스위치, 별점 등을 만듭니다. 라디오는 같은 `name`끼리 하나만 선택되는 규칙을 직접 구현해야 합니다.

## 내부 input을 감싸는 방식과의 비교

shadow 트리 안에 네이티브 `input`을 두고 그것을 감싸는 방식도 있습니다. 가장 큰 제약은 shadow 안의 `input`이 바깥 폼의 구성원이 아니라는 점입니다. 폼 소유자는 같은 트리 안에서 찾으므로 제출 값에도 들어가지 않습니다.

| 항목 | 내부 input 래핑만 | formAssociated + internals |
|------|-------------------|-----------------------------|
| 폼 제출에 값 포함 | 안 됨 | 됨 |
| `form.elements`·`form.checkValidity()` | 포함되지 않음 | 포함됨 |
| `form.reset()` 반응 | 없음 | `formResetCallback` |
| `fieldset disabled` 반응 | 없음 | `formDisabledCallback` |
| 키보드·IME·자동 완성·텍스트 선택 | 네이티브가 처리 | 직접 구현해야 함 |
| 접근성 | 네이티브 `input`이 제공 | `role`과 ARIA를 직접 설정 |

현실적인 방식은 둘을 합치는 것입니다. 입력 동작은 내부 `input`에 맡기고, 폼 참여는 호스트가 `internals`로 대신합니다.

```js
#input.addEventListener('input', () => {
  this.#internals.setFormValue(this.#input.value)
  this.#internals.setValidity(
    this.#input.validity,
    this.#input.validationMessage,
    this.#input,
  )
})
```

- 내부 `input`의 값과 유효성을 호스트의 `internals`에 복사합니다. 이렇게 하면 `required`, `minlength` 같은 네이티브 검증 규칙을 다시 만들지 않아도 됩니다.
- 내부 `input`을 `anchor`로 지정해 오류 위치와 포커스가 입력창으로 가게 합니다.
- 호스트의 포커스를 내부 `input`으로 넘기려면 `delegatesFocus`를 씁니다(28편).
- 폼 참여가 필요 없는 장식적 래퍼라면 formAssociated를 쓰지 않는 것이 단순합니다.

## 핵심 정리

- `static formAssociated = true`와 `attachInternals()`가 폼 참여의 출발점이며, `internals`는 비공개 필드에 보관합니다.
- 제출 값은 `setFormValue`로, 유효성은 `setValidity`로 직접 알려야 하고, `name`, `value`, `disabled` 프로퍼티는 클래스가 정의해야 합니다.
- 폼 콜백은 폼 소유자 변경(`formAssociatedCallback`), 초기화(`formResetCallback`), 비활성(`formDisabledCallback`), 복원·자동 완성(`formStateRestoreCallback`)에 반응합니다.
- `setFormValue`의 `state`는 복원용 입력이고, `setValidity`의 `anchor`는 오류 위치가 될 내부 요소입니다.
- 호스트에서는 `:invalid`, `:valid`, `:disabled`가 매칭되고 `willValidate`, `validity`, `validationMessage`는 `internals`에서 읽습니다.
- 내부 `input`만 감싸면 폼에 참여하지 못하므로, 입력은 내부 `input`에 맡기고 폼 참여는 `internals`로 연결하는 구성이 흔합니다.
