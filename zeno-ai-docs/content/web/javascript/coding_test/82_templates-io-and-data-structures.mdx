## 템플릿을 쓰는 방법

이 편의 코드는 동작 원리가 아니라 붙여 쓰는 형태를 모은 것입니다. 원리는 각 자료구조 편에서 다룹니다.

- 모든 템플릿은 Node.js 24에서 실행해 동작을 확인한 코드입니다. 외워 두지 말고 구조를 이해한 뒤 문제에 맞게 고칩니다.
- 번호는 문제마다 다릅니다. 노드 번호가 1부터이면 배열 크기를 `n + 1`로 잡습니다(템플릿에 표시).
- 수가 2^53을 넘을 수 있으면 `Number` 템플릿을 그대로 쓰지 않습니다(자세히는 85편).
- 알고리즘 템플릿은 83편에서 모읍니다.

## 빠른 입력 템플릿

입력 전체를 한 번 읽어 줄 배열로 만들고, 줄 포인터로 꺼내 쓰는 형태입니다(자세히는 08편).

```js
const fs = require('fs')
const lines = fs.readFileSync(0, 'utf8')
  .trim()
  .split(/\r?\n/)
let li = 0
const readLine = () => lines[li++]
const readNums = () => readLine().split(' ').map(Number)
```

```js
const [n, m] = readNums()   // "3 5" → n = 3, m = 5
const a = readNums()        // "1 2 3" → [1, 2, 3]
const word = readLine()     // 문자열 한 줄
```

- `\r\n`과 끝 줄바꿈은 `trim().split(/\r?\n/)`가 처리합니다.
- 숫자 사이가 한 칸이 아닐 수 있으면 `split(/\s+/)`로 바꿉니다. 빈 줄이 데이터인 문제에서는 `trim()`이 마지막 빈 줄을 지우므로 확인합니다.
- 줄 구조가 불규칙하면 아래 토큰 파서가 더 안전합니다.
- 출력은 배열에 모아 한 번에 냅니다.

```js
const out = []
out.push(a.length)
out.push(a.join(' '))
console.log(out.join('\n'))
```

## 숫자 Token Parser

공백과 줄바꿈을 구분 없이 건너뛰며 정수나 단어를 하나씩 꺼내는 파서입니다. 입력을 문자열 배열로 쪼개지 않고 바이트를 직접 읽어서 메모리를 적게 씁니다.

```js
const buf = require('fs').readFileSync(0)
let pos = 0
const skip = () => {
  while (buf[pos] <= 32) pos++
}
function nextInt() {
  skip()
  let sign = 1
  if (buf[pos] === 45) { sign = -1; pos++ }
  let x = 0
  while (buf[pos] >= 48 && buf[pos] <= 57) {
    x = x * 10 + buf[pos++] - 48
  }
  return sign * x
}
```

```js
function nextWord() {
  skip()
  const start = pos
  while (buf[pos] > 32) pos++
  return buf.toString('utf8', start, pos)
}
const n = nextInt()
const a = Array.from({ length: n }, nextInt)
```

- 바이트 값 32 이하는 공백·탭·줄바꿈(`\r`, `\n`)이고, 45가 `-`, 48–57이 숫자입니다.
- 정수만 읽습니다. 소수점은 처리하지 않으므로 소수는 `nextWord()`로 받아 `Number`로 바꿉니다.
- 2^53을 넘는 정수는 누적 계산 중 정밀도를 잃습니다. 그런 입력은 `nextWord()`로 받아 `BigInt(word)`로 바꿉니다(자세히는 85편).
- 입력이 끝난 뒤에 호출하면 에러 없이 `nextInt()`는 `0`, `nextWord()`는 빈 문자열을 반환합니다. 개수를 정확히 맞춰 읽습니다.
- `nextInt`는 호출 때마다 인자를 무시하므로 `Array.from({ length: n }, nextInt)`로 바로 쓸 수 있습니다.

## Queue 템플릿

배열 앞에서 꺼내는 `shift`는 배열 길이에 비례해 느려서 큐로 쓰지 않습니다(자세히는 86편). 앞쪽 위치를 가리키는 head 인덱스를 두는 형태가 기본입니다(자세히는 20편).

```js
class Queue {
  constructor() { this.a = []; this.h = 0 }
  push(x) { this.a.push(x) }
  shift() { return this.a[this.h++] }
  get size() { return this.a.length - this.h }
}
const q = new Queue()
q.push(1); q.push(2)
q.shift() // 1
q.size    // 1
```

- 모든 연산이 O(1)입니다. 꺼낸 자리는 비우지 않아서 넣은 총량만큼 메모리를 씁니다. BFS에서는 각 상태를 한 번씩만 넣으므로 문제되지 않습니다.
- 비어 있을 때 `shift()`는 `undefined`를 줍니다. 사용 전에 `size`를 확인합니다.
- 넣을 총 개수의 상한을 알고 값이 정수이면 고정 크기 TypedArray가 더 가볍습니다.

```js
class IntQueue {
  constructor(cap) {
    this.a = new Int32Array(cap)
    this.h = 0
    this.t = 0
  }
  push(x) { this.a[this.t++] = x }
  shift() { return this.a[this.h++] }
  get size() { return this.t - this.h }
}
```

- `cap`은 넣는 횟수의 총합 이상이어야 합니다. 넘기면 범위 밖 쓰기가 조용히 무시되어 값이 사라집니다(TypedArray는 범위 밖 인덱스에 쓰면 아무 일도 하지 않습니다).
- `Int32Array`는 32비트 정수만 담습니다. 격자 좌표를 `r * W + c`로 합친 값이 이 범위를 넘지 않는지 확인합니다.

## Deque 템플릿

양쪽 끝에서 넣고 빼는 자료구조입니다. 배열 가운데를 시작점으로 잡고 앞쪽은 인덱스를 줄이고 뒤쪽은 늘립니다(자세히는 20편).

```js
class Deque {
  constructor(cap) {
    this.a = new Array(2 * cap + 1)
    this.h = cap
    this.t = cap
  }
  pushBack(x) { this.a[this.t++] = x }
  pushFront(x) { this.a[--this.h] = x }
  popFront() { return this.a[this.h++] }
  popBack() { return this.a[--this.t] }
  get size() { return this.t - this.h }
}
```

- 구간은 `[h, t)`입니다. 모든 연산이 O(1)입니다.
- `cap`은 앞쪽으로 넣는 횟수의 총합과 뒤쪽으로 넣는 횟수의 총합 중 큰 값 이상이어야 합니다. 0-1 BFS처럼 한 노드가 여러 번 들어가면 간선 수를 기준으로 잡습니다(자세히는 39편).
- 슬라이딩 윈도우 최댓값 같은 단조 덱은 인덱스를 담아 앞에서 만료된 것을 빼고 뒤에서 작은 값을 뺍니다(자세히는 32편).

## Min Heap / Priority Queue 템플릿

가장 작은 값을 O(log N)에 꺼내는 힙입니다. JavaScript에는 내장 힙이 없어서 직접 만듭니다(자세히는 46편, 47편). 비교 함수 `less(a, b)`를 인자로 받아 숫자와 쌍 모두에 씁니다.

```js
function heapPush(h, x, less) {
  let i = h.push(x) - 1
  while (i > 0) {
    const p = (i - 1) >> 1
    if (!less(x, h[p])) break
    h[i] = h[p]
    i = p
  }
  h[i] = x
}
```

```js
function heapPop(h, less) {
  const top = h[0]
  const last = h.pop()
  if (h.length === 0) return top
  let i = 0
  for (let c = 1; c < h.length; c = 2 * i + 1) {
    if (c + 1 < h.length && less(h[c + 1], h[c])) c++
    if (!less(h[c], last)) break
    h[i] = h[c]
    i = c
  }
  h[i] = last
  return top
}
```

사용은 힙 배열 `h`와 `less`를 함께 넘깁니다.

```js
const less = (a, b) => a < b          // 숫자 최소 힙
const h = []
heapPush(h, 5, less)
heapPush(h, 2, less)
heapPop(h, less)                      // 2
const byDist = (a, b) => a[0] < b[0]  // [거리, 노드] 쌍
```

- 힙이 비면 `heapPop`은 `undefined`를 줍니다. `h.length`로 확인한 뒤 꺼냅니다.
- 비교는 `<`(엄격)로 씁니다. `less`가 두 값을 같다고 보면 순서는 정해지지 않습니다. 같은 키의 처리 순서가 중요하면 비교에 보조 키를 더합니다.
- 쌍 `[거리, 노드]`를 매번 배열로 만들면 객체 생성 비용이 듭니다. 거리와 노드를 수 하나로 합치면 기본 `<`로 비교할 수 있습니다. `key = dist * 2 ** 20 + node`처럼 노드 수를 담을 만큼의 자리를 정하고, 합친 수가 2^53을 넘지 않는지 확인합니다.
- `h`를 `sort`로 정렬한 배열처럼 읽으면 안 됩니다. 힙 배열은 정렬되어 있지 않고 `h[0]`만 최솟값입니다.

## Max Heap 템플릿

가장 큰 값을 꺼내는 힙은 같은 코드에서 `less`만 뒤집으면 됩니다.

```js
const greater = (a, b) => a > b   // 숫자 최대 힙
const h = []
heapPush(h, 5, greater)
heapPush(h, 9, greater)
heapPop(h, greater)               // 9
const byScore = (a, b) => a[1] > b[1] // 쌍의 둘째 값 기준
```

- 숫자만 담는다면 부호를 바꿔 넣고 꺼낼 때 다시 바꾸는 방법도 있습니다. `heapPush(h, -x, less)`로 넣고 `-heapPop(h, less)`로 꺼냅니다. 값이 0이면 `-0`이 되는데 비교는 정상이고 출력할 때 `String(-0)`은 `'0'`이라 문제없습니다.
- 비교 함수가 둘 이상의 기준을 가질 때는 앞 기준이 같을 때만 다음 기준을 봅니다. `(a, b) => a[0] !== b[0] ? a[0] > b[0] : a[1] < b[1]`처럼 씁니다.
- K번째로 큰 수는 크기 K의 최소 힙을 유지하며 작은 것을 버립니다. 최대 힙을 N개 모두 담는 것보다 메모리가 적습니다(자세히는 47편).

## Union-Find 템플릿

원소를 서로소 집합으로 나누고, 같은 집합인지 확인하고, 두 집합을 합치는 자료구조입니다(자세히는 51편). 경로 압축과 크기 기준 합치기를 함께 써서 연산이 사실상 상수 시간에 가깝습니다.

```js
const parent = new Int32Array(n + 1)
for (let i = 0; i <= n; i++) parent[i] = i
const size = new Int32Array(n + 1).fill(1)
function find(x) {
  while (parent[x] !== x) {
    parent[x] = parent[parent[x]]
    x = parent[x]
  }
  return x
}
```

```js
function union(a, b) {
  a = find(a)
  b = find(b)
  if (a === b) return false
  if (size[a] < size[b]) [a, b] = [b, a]
  parent[b] = a
  size[a] += size[b]
  return true
}
```

- `find`는 반복문이라 재귀 깊이 문제가 없습니다. 부모를 한 칸씩 건너뛰며 줄이는 경로 반감 방식입니다.
- `union`은 합쳐졌으면 `true`, 이미 같은 집합이면 `false`를 반환합니다. 크루스칼의 사이클 판정이나 연결 요소 수 세기에 그대로 씁니다. 집합 수는 처음 `n`에서 `true`가 나올 때마다 1씩 줄입니다.
- 집합의 크기는 `size[find(x)]`입니다.
- 노드 번호가 0부터이면 길이를 `n`으로 해도 되지만, 1부터이면 `n + 1`이어야 합니다.

## Segment Tree 템플릿

배열의 한 값을 바꾸고 구간의 합(또는 최솟값 등)을 묻는 질의를 둘 다 O(log N)에 처리합니다(자세히는 62편). 아래는 반복문으로 만드는 방식이고, 질의 구간은 반열린 구간 `[l, r)`입니다.

```js
const n = a.length
const t = new Float64Array(2 * n)
for (let i = 0; i < n; i++) t[n + i] = a[i]
for (let i = n - 1; i > 0; i--) {
  t[i] = t[2 * i] + t[2 * i + 1]
}

function update(i, v) {          // a[i] = v
  for (t[i += n] = v; i > 1; i >>= 1) {
    t[i >> 1] = t[i] + t[i ^ 1]
  }
}
```

```js
function query(l, r) {           // a[l] + ... + a[r - 1]
  let sum = 0
  for (l += n, r += n; l < r; l >>= 1, r >>= 1) {
    if (l & 1) sum += t[l++]
    if (r & 1) sum += t[--r]
  }
  return sum
}
```

- 잎이 `t[n]`부터 `t[2n - 1]`까지이고, 부모는 두 자식의 합입니다. `n`이 2의 거듭제곱이 아니어도 동작합니다.
- 합은 `Float64Array`에 담아서 2^53까지 정확합니다. `Int32Array`에 담으면 합이 2^31을 넘는 순간 에러 없이 음수로 되돌아갑니다(자세히는 85편).
- 최솟값 트리로 바꾸려면 합 대신 `Math.min`을 쓰고, 합칠 때와 질의의 시작값을 `Infinity`로 둡니다. 배열 `t`도 `Infinity`로 채웁니다.
- 이 방식은 합·최솟값·최댓값·GCD처럼 순서를 바꿔도 결과가 같은 연산에 맞습니다. 순서가 중요한 연산이나 구간 갱신(Lazy Propagation)에는 재귀 방식이 필요합니다(자세히는 63편).

## Fenwick Tree 템플릿

한 값에 더하고 앞부분의 합을 묻는 질의를 O(log N)에 처리하는 자료구조입니다(자세히는 64편). 세그먼트 트리보다 코드가 짧습니다. 위치는 0부터이고 합 구간은 `[0, i)`입니다.

```js
const tree = new Float64Array(n + 1)
function add(i, d) {             // a[i] += d
  for (i++; i <= n; i += i & -i) tree[i] += d
}
function sum(i) {                // a[0] + ... + a[i - 1]
  let s = 0
  for (; i > 0; i -= i & -i) s += tree[i]
  return s
}
// 구간 [l, r)의 합: sum(r) - sum(l)
```

- `i & -i`는 `i`의 가장 낮은 켜진 비트입니다(자세히는 24편). 내부는 1부터 번호를 매기므로 `add`에서 `i++`를 합니다.
- 처음 배열로 채울 때는 `add(i, a[i])`를 n번 부르면 O(N log N)입니다.
- 값을 바꾸려면 차이를 더합니다. `a[i]`를 `v`로 바꿀 때는 `add(i, v - a[i])` 뒤에 `a[i] = v`로 맞춥니다.
- 합처럼 되돌릴 수 있는 연산에만 씁니다. 구간 최솟값은 세그먼트 트리가 필요합니다.
- 비트 연산은 32비트 정수에서 이뤄지므로 `n`이 2^31 미만이어야 합니다. 합은 `Float64Array`에 담아 오버플로를 피합니다.

## 핵심 정리

- 입력은 `readFileSync(0)`으로 한 번 읽어 줄 포인터나 바이트 토큰 파서로 꺼내고, 출력은 배열에 모아 한 번에 냅니다.
- 큐는 `shift` 대신 head 인덱스를 쓰고, 덱은 배열 가운데에서 시작해 양쪽 인덱스를 움직입니다. 둘 다 고정 크기 TypedArray로 바꿀 수 있습니다.
- 힙은 `less` 함수를 받는 `heapPush`·`heapPop` 한 벌로 최소 힙과 최대 힙을 모두 만들고, 쌍은 비교 함수로 키를 지정합니다.
- Union-Find는 반복문 `find`(경로 반감)와 크기 기준 `union`이 기본이고, 합쳐졌는지를 `true`와 `false`로 돌려줍니다.
- 세그먼트 트리와 펜윅 트리는 합을 `Float64Array`에 담아 오버플로를 피하고, 구간은 반열린 `[l, r)`로 다룹니다.
- 템플릿은 노드 번호의 시작(0 또는 1), 용량 `cap`, 값의 범위를 문제에 맞게 고쳐서 씁니다.
