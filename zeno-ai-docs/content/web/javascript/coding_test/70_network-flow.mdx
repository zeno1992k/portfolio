## 최대 유량 (Maximum Flow)

유량 네트워크(flow network)는 간선마다 용량(capacity)이 붙은 방향 그래프에 출발점 s(source)와 도착점 t(sink)를 지정한 것입니다. 파이프에 물을 흘리는 상황처럼 s에서 t로 얼마나 많이 보낼 수 있는지를 묻습니다(방향 그래프와 가중치는 35편).

유량(flow)은 간선마다 정한 흘리는 양 `f`이고 두 조건을 지켜야 합니다.

- 용량 제한: 모든 간선에서 `0 <= f <= 용량`입니다.
- 유량 보존: s와 t를 제외한 모든 정점에서 들어오는 양과 나가는 양이 같습니다.

유량의 값(value)은 s에서 나가는 순유량이고, 유량 보존 때문에 t로 들어오는 순유량과 같습니다. 최대 유량(maximum flow)은 값이 가장 큰 유량입니다.

이 문서의 예제 네트워크입니다. 0이 s, 5가 t이고 원소는 `[출발, 도착, 용량]`입니다.

```js
const E = [
  [0, 1, 10], [0, 2, 10], [1, 2, 2], [1, 3, 4], [1, 4, 8],
  [2, 4, 9], [3, 5, 10], [4, 3, 6], [4, 5, 10],
]
```

- 이 네트워크의 최대 유량은 19입니다. 근거는 아래 "최소 컷"에서 나옵니다.
- 용량이 모두 정수이면 정수 유량인 최대 유량이 반드시 있습니다. 알고리즘이 간선마다 정수만 흘려도 최적에 도달합니다.
- 간선의 용량이 없는 쪽으로는 흘릴 수 없습니다. 같은 두 정점 사이에 간선이 여러 개여도 되고, 각각 따로 추가합니다.

**문제의 단서:** "동시에 최대 몇 개를 보낼 수 있는가", "용량이 있는 도로·회선·파이프", "서로 겹치지 않는 경로의 최대 개수", "최소 비용으로 끊기"가 나옵니다. 이분 매칭(71편), 작업 배정, 격자 위 경로 분리도 최대 유량으로 모델링합니다.

문제를 유량으로 바꿀 때 자주 쓰는 변형입니다.

| 상황 | 모델링 |
|------|--------|
| 무방향 간선 용량 c | 간선 한 쌍의 두 방향 용량을 모두 c로 둠 |
| 정점에 용량 c | 정점을 입구와 출구로 쪼개고 입구→출구 간선에 용량 c |
| 출발점이 여럿 | 가상 출발점에서 각 출발점으로 용량 무한 간선 |
| 도착점이 여럿 | 각 도착점에서 가상 도착점으로 용량 무한 간선 |
| 간선이 서로 겹치지 않는 경로 | 모든 간선 용량 1 |

- 용량 무한은 `Infinity`로 둘 수 있습니다. 유량의 합이 `Number.MAX_SAFE_INTEGER` 이하면 Number로 충분합니다(자세히는 02편).

**흔한 실수:** 간선 용량이 방향마다 다른데 무방향으로 합쳐 버리거나, 정점 용량을 간선 용량으로 착각하는 것입니다. 정점에 한도가 있으면 정점을 쪼갭니다.

## 잔여 그래프 (Residual Graph)

잔여 그래프(residual graph)는 현재 유량이 정해진 뒤 더 흘릴 수 있는 양을 간선으로 나타낸 그래프입니다. 간선 `u→v`의 용량이 c이고 지금 f를 흘리고 있으면 두 간선이 생깁니다.

| 간선 | 잔여 용량 | 뜻 |
|------|-----------|----|
| `u→v` | `c - f` | 더 흘릴 수 있는 양 |
| `v→u` | `f` | 흘린 양을 되돌릴(취소할) 수 있는 양 |

- 잔여 용량이 0보다 큰 간선만 잔여 그래프의 간선입니다.
- 역방향 간선은 원래 그래프에 없어도 생깁니다. 이미 흘린 유량을 거두고 다른 길로 돌리는 선택지를 주기 때문에 증가 경로 탐색이 틀린 선택을 만회할 수 있습니다.

구현은 간선 하나를 정방향과 역방향 한 쌍으로 넣고, 잔여 용량을 `cap` 배열에 직접 저장하는 방식이 가장 단순합니다. 간선 번호 `e`의 반대 방향은 `e ^ 1`입니다(`^`는 XOR이고 짝수 번호와 그다음 홀수 번호가 한 쌍).

```js
function makeGraph(n) {
  const adj = Array.from({ length: n }, () => [])
  return { adj, to: [], cap: [] }
}
function addEdge(g, u, v, c) {      // u→v 용량 c, 역간선 용량 0
  g.adj[u].push(g.to.length); g.to.push(v); g.cap.push(c)
  g.adj[v].push(g.to.length); g.to.push(u); g.cap.push(0)
}
// 간선 e에 증가 f: g.cap[e] -= f; g.cap[e ^ 1] += f
// 정방향 간선(짝수 e)의 현재 유량: g.cap[e ^ 1]
```

- `adj[u]`에는 u에서 나가는 간선 번호가 들어갑니다. 도착 정점은 `to[e]`, 출발 정점은 `to[e ^ 1]`입니다.
- 간선을 항상 이 함수로만 추가해야 짝수 번호가 원래 간선이라는 규칙이 유지됩니다. 무방향 간선은 `addEdge(g, u, v, c)` 뒤에 `g.cap[g.cap.length - 1] = c`로 역간선 용량도 c로 바꿉니다.

역간선이 왜 필요한지 작은 네트워크로 봅니다. 정점 0=s, 1=a, 2=b, 3=t이고 간선 `s→a`, `s→b`, `a→b`, `a→t`, `b→t`의 용량이 모두 1입니다. 최대 유량은 2입니다(`s→a→t`와 `s→b→t`).

| 단계 | 증가 경로 | 잔여 그래프에서 일어난 일 |
|------|-----------|----------------------------|
| 1 | `s→a→b→t` | 이 경로의 세 간선이 잔여 0, 역간선 `a→s`, `b→a`, `t→b`가 잔여 1 |
| 2 | `s→b→a→t` | 역간선 `b→a`로 `a→b`의 유량을 취소하고 `b→a→t`로 돌림 |
| 끝 | | `a→b`의 유량이 0으로 돌아감. 총 유량 2 |

첫 경로 `s→a→b→t`는 가운데 간선을 써서 두 번째 경로를 막는 좋지 않은 선택입니다. 역간선이 없다면 여기서 멈춰 유량 1이 최대라고 틀리게 답합니다.

**흔한 실수:**

- 역간선을 만들지 않거나 용량을 0이 아닌 값으로 넣는 것입니다. 유향 간선의 역간선은 용량 0으로 시작합니다.
- 간선 번호가 한 쌍으로 붙어 있지 않게 추가하고 `e ^ 1`을 쓰는 것입니다. 짝수에서 시작해 두 개씩 붙여야 합니다.
- 증가 때 정방향만 줄이고 역방향 `cap[e ^ 1]`을 늘리지 않는 것입니다.

## Ford-Fulkerson

Ford-Fulkerson 방법은 잔여 그래프에서 s에서 t로 가는 경로(증가 경로, augmenting path)를 찾아 그 경로의 최소 잔여 용량(병목)만큼 유량을 늘리는 일을 경로가 없을 때까지 반복하는 방법입니다. 경로를 어떻게 찾는지는 정하지 않았고, DFS로 찾으면 흔히 말하는 Ford-Fulkerson입니다(자세히는 36편).

1. 모든 유량을 0으로 시작한다(잔여 그래프는 원래 그래프와 같다).
2. 잔여 그래프에서 s→t 경로를 찾는다. 없으면 끝이다.
3. 경로의 간선 중 잔여 용량의 최솟값 f를 구해 경로의 각 간선 `e`에서 `cap[e] -= f`, `cap[e ^ 1] += f`를 한다.
4. 총 유량에 f를 더하고 2로 돌아간다.

종료했을 때 최대 유량이라는 것은 다음 절의 최대 유량 최소 컷 정리가 보장합니다. 정수 용량이면 증가할 때마다 총 유량이 1 이상 늘어서 반드시 끝납니다.

DFS로 구현한 증가 경로 탐색입니다. 한 번 호출에 경로 하나를 찾아 그 유량을 반환합니다. `seen`은 길이 n 배열이고, 호출 전마다 `fill(false)`로 초기화합니다.

```js
function dfs(u, f) {                  // u에서 t까지 보낼 수 있는 양
  if (u === t) return f
  seen[u] = true
  for (const e of g.adj[u]) {
    const v = g.to[e]
    if (g.cap[e] === 0 || seen[v]) continue
    const pushed = dfs(v, Math.min(f, g.cap[e]))
    if (pushed > 0) {
      g.cap[e] -= pushed
      g.cap[e ^ 1] += pushed
      return pushed
    }
  }
  return 0
}
```

```js
function fordFulkerson(g, s, t) {     // dfs를 이 안에 둔다
  const seen = new Array(g.adj.length)
  // function dfs(u, f) { ... }  위 코드
  let total = 0
  for (;;) {
    seen.fill(false)
    const f = dfs(s, Infinity)
    if (f === 0) return total
    total += f
  }
}
```

- 앞의 4정점 예제에서 간선을 추가한 순서대로 DFS하면 첫 경로는 `0→1→2→3`, 둘째는 `0→2→1→3`이고 총 유량은 2입니다. 둘째 경로가 역간선 `2→1`을 지납니다.
- 시간은 O(E · F)입니다. F는 최대 유량의 값이고, 증가 한 번에 DFS가 O(E)입니다. 증가가 최소 1씩 늘어나므로 증가 횟수가 F를 넘지 않습니다.
- 용량이 큰 문제에서는 위험합니다. `s→a`, `s→b`, `a→t`, `b→t`의 용량이 모두 10억이고 `a→b`의 용량이 1일 때, DFS가 `s→a→b→t`와 `s→b→a→t`를 번갈아 고르면 증가가 1씩 일어나 20억 번 반복합니다. 이 방법은 경로를 고르는 순서에 시간이 달려 있습니다.
- 용량이 정수일 때만 종료와 시간 한계가 보장됩니다. 실수 용량이면 끝나지 않는 경우가 있습니다.

**흔한 실수:**

- 반복마다 `seen`을 초기화하지 않는 것입니다. 두 번째 증가부터 경로를 못 찾습니다.
- 병목 `f`를 구하지 않고 1만 흘리는 것입니다. 느려지거나 틀립니다.
- 용량이 큰 문제를 Ford-Fulkerson으로 푸는 것입니다. 용량이 작거나 최대 유량 F가 작을 때만 씁니다.

## Edmonds-Karp

Edmonds-Karp 알고리즘은 증가 경로를 BFS로 찾는, 즉 간선 수가 가장 적은 경로를 고르는 Ford-Fulkerson입니다(자세히는 38편). 용량의 크기와 상관없이 시간이 O(V · E²)로 정해집니다.

- BFS가 항상 가장 짧은 증가 경로를 고르면 증가가 있을 때마다 경로의 길이가 줄어들지 않고, 같은 길이의 경로는 간선이 포화되는 만큼만 있어서 증가 횟수가 O(V · E)로 묶입니다. 증가마다 BFS가 O(E)라서 전체가 O(V · E²)입니다.
- 이 한계는 용량이 정수가 아니어도 성립합니다.

잔여 용량이 있는 간선만 따라가는 BFS가 각 정점에 들어온 간선 번호를 기록하고, 그것으로 경로를 거슬러 복원합니다.

```js
function bfs(g, s) {            // prev[v]: v로 들어온 간선 번호
  const prev = new Array(g.adj.length).fill(-1)
  prev[s] = -2
  const q = [s]
  for (let h = 0; h < q.length; h++) {
    const u = q[h]
    for (const e of g.adj[u]) {
      const v = g.to[e]
      if (g.cap[e] === 0 || prev[v] !== -1) continue
      prev[v] = e
      q.push(v)
    }
  }
  return prev
}
```

```js
function pathOf(g, prev, s, t) {  // s에서 t까지 간선 번호 배열
  const path = []
  for (let v = t; v !== s; v = g.to[prev[v] ^ 1])
    path.push(prev[v])
  return path
}
```

```js
function edmondsKarp(g, s, t) {
  let total = 0
  for (;;) {
    const prev = bfs(g, s)
    if (prev[t] === -1) return total
    const path = pathOf(g, prev, s, t)
    const f = Math.min(...path.map((e) => g.cap[e]))
    for (const e of path) {
      g.cap[e] -= f
      g.cap[e ^ 1] += f
    }
    total += f
  }
}
```

- 큐는 `shift`를 쓰지 않고 head 인덱스로 돌립니다(자세히는 20편).
- `prev[s] = -2`는 s를 방문 처리하고 경로 복원 반복이 s에서 멈추게 하는 표시입니다.
- 앞의 6정점 예제를 풀면 증가 경로가 다음 순서로 나옵니다. 처음 세 경로는 간선 3개짜리, 마지막은 4개짜리로 길이가 줄지 않습니다.

| 증가 | 경로 | 병목 | 총 유량 |
|------|------|------|---------|
| 1 | `0→1→3→5` | 4 (`1→3`) | 4 |
| 2 | `0→1→4→5` | 6 (`0→1`의 남은 용량) | 10 |
| 3 | `0→2→4→5` | 4 (`4→5`의 남은 용량) | 14 |
| 4 | `0→2→4→3→5` | 5 (`2→4`의 남은 용량) | 19 |

더 증가시킬 경로가 없으니 최대 유량은 19입니다.

- 실제로는 이론 한계보다 훨씬 빨리 끝나는 경우가 많지만, 정점과 간선이 많으면 Dinic을 씁니다.
- 이분 매칭처럼 정점이 많고 용량이 1인 그래프에서는 Ford-Fulkerson(DFS)이 단순하고 빠릅니다(자세히는 71편).

**흔한 실수:**

- 무방향 간선의 역방향 용량을 0으로 두는 것입니다. 반대 방향으로도 흘릴 수 있어야 하므로 두 방향 모두 c입니다.
- BFS 결과 `prev`를 반복마다 새로 만들지 않고 재사용해 이전 방문 기록이 남는 것입니다.
- `prev[t]`를 확인하지 않고 경로 복원에 들어가 무한 반복하는 것입니다.

## 최소 컷 (Minimum Cut)

s-t 컷(cut)은 정점을 s를 포함하는 집합 S와 t를 포함하는 집합 T로 나누는 것입니다. 컷의 용량은 S에서 T로 가는 간선의 용량의 합입니다. T에서 S로 가는 간선은 더하지 않습니다. 컷은 s에서 t로 가는 모든 길을 끊는 간선 집합이고, 용량이 가장 작은 컷이 최소 컷(minimum cut)입니다.

**최대 유량 최소 컷 정리(max-flow min-cut theorem):** 최대 유량의 값은 최소 컷의 용량과 같습니다.

- 어떤 유량이든 모든 컷의 용량을 넘을 수 없습니다(유량은 컷을 지나 s에서 t로 가야 하기 때문). 증가 경로가 더 없는 상태에서 컷을 하나 만들 수 있고 그 용량이 현재 유량과 같음이 보이면 정리가 성립합니다.
- 예제 네트워크에서 `S = {0, 2}`, `T = {1, 3, 4, 5}`로 나누면 S에서 T로 가는 간선은 `0→1`(10)과 `2→4`(9)뿐이고 용량 합은 19입니다. 최대 유량이 19이므로 이 컷이 최소 컷입니다. `2→1`처럼 반대 방향 간선은 용량이 있어도 더하지 않습니다.

최대 유량을 구한 뒤 최소 컷을 얻는 방법입니다. 잔여 그래프에서 s에서 도달할 수 있는 정점의 집합을 S로 두고 나머지를 T로 둡니다.

- S에서 T로 가는 원래 간선은 모두 포화(유량 = 용량)되어 있습니다. 포화되지 않았다면 잔여 용량이 있어서 도달할 수 있어야 하기 때문입니다.
- T에서 S로 가는 원래 간선의 유량은 0입니다. 0이 아니면 역간선으로 S에서 T로 도달할 수 있어야 합니다.
- 그래서 컷의 용량이 유량의 값과 같습니다.

```js
function minCut(g, s) {          // 최대 유량을 흘린 뒤 호출
  const inS = bfs(g, s).map((e) => e !== -1)
  const cut = []
  for (let e = 0; e < g.to.length; e += 2) {
    const u = g.to[e ^ 1], v = g.to[e]
    if (inS[u] && !inS[v]) cut.push([u, v])
  }
  return cut                     // 예제: [[0, 1], [2, 4]]
}
```

- 최소 컷은 여러 개일 수 있습니다. 위 방법은 그중 S가 가장 작은 컷을 줍니다. t 쪽에서 거슬러 도달할 수 있는 정점을 T로 하면 S가 가장 큰 컷이 나옵니다.
- 모든 간선의 용량이 1이면 최소 컷은 s에서 t로 가는 길을 끊는 데 필요한 최소 간선 수이고, 이는 서로 간선을 공유하지 않는 경로의 최대 개수와 같습니다.
- 최소 컷은 "가장 적은 비용으로 연결을 끊기", "두 집단 중 하나로 나누기(분리 비용 최소)" 유형에 쓰입니다.

**문제의 단서:** "s와 t를 끊으려면 최소 몇 개(얼마)를 없애야 하는가"가 나오면 최대 유량의 값을 구하면 됩니다.

**흔한 실수:**

- 컷의 용량에 T에서 S로 가는 간선까지 더하는 것입니다.
- 최대 유량을 구하기 전의 잔여 그래프에서 도달 가능 집합을 구하는 것입니다. 유량을 다 흘린 뒤에 BFS해야 합니다.
- 무방향 그래프의 간선을 한 방향으로만 컷에 세는 것입니다. 무방향 간선은 S에서 T로 걸치면 용량을 한 번 더합니다.

## Dinic 개요

Dinic 알고리즘(1970)은 증가 경로를 하나씩 찾는 대신, 한 단계(phase)에서 최단 경로 길이가 같은 경로들을 한꺼번에 포화시키는 최대 유량 알고리즘입니다. 한 단계는 다음과 같습니다.

1. 잔여 그래프를 BFS해 정점마다 s로부터의 거리(레벨)를 구한다. t에 도달하지 못하면 끝난다.
2. 레벨이 정확히 1 큰 정점으로 가는 간선만 써서 DFS로 증가를 반복한다. 어떤 s→t 경로에도 포화 간선이 하나 이상 있게 될 때(블로킹 플로우)까지 한다.
3. 각 정점에서 이미 살펴본 간선을 가리키는 포인터 `it[u]`를 두어, 막혔거나 포화된 간선을 다시 보지 않는다.

한 단계가 끝나면 s에서 t까지의 최단 거리가 반드시 늘어나므로 단계는 V번 미만입니다.

```js
function levels(g, s) {             // BFS 레벨. 도달 불가는 -1
  const level = new Array(g.adj.length).fill(-1)
  level[s] = 0
  const q = [s]
  for (let h = 0; h < q.length; h++) {
    const u = q[h]
    for (const e of g.adj[u]) {
      const v = g.to[e]
      if (g.cap[e] === 0 || level[v] !== -1) continue
      level[v] = level[u] + 1
      q.push(v)
    }
  }
  return level
}
```

```js
function dfs(g, u, t, f) {           // 레벨이 1 큰 간선만 따라감
  if (u === t) return f
  const { adj, to, cap, level, it } = g
  for (; it[u] < adj[u].length; it[u]++) {
    const e = adj[u][it[u]], v = to[e]
    if (cap[e] === 0 || level[v] !== level[u] + 1) continue
    const d = dfs(g, v, t, Math.min(f, cap[e]))
    if (d > 0) {
      cap[e] -= d
      cap[e ^ 1] += d
      return d
    }
  }
  return 0
}
```

```js
function dinic(g, s, t) {
  let total = 0
  while ((g.level = levels(g, s))[t] !== -1) {
    g.it = new Array(g.adj.length).fill(0)
    let f
    while ((f = dfs(g, s, t, Infinity)) > 0) total += f
  }
  return total
}
```

- 일반 네트워크에서 시간은 O(V² · E)이고, 실제로는 이보다 훨씬 빠릅니다.
- 모든 용량이 1인 네트워크에서는 O(E · √E)이고, 이분 매칭처럼 각 정점의 들어오는 또는 나가는 용량이 1인 단위 네트워크에서는 O(E · √V)입니다.
- DFS 깊이는 레벨이 1씩 커지므로 V를 넘지 않습니다.
- `levels`로 구한 `level`과 포인터 `it`는 `g.level`, `g.it`에 저장해 `dfs`가 읽습니다.
- `it[u]`를 올리는 위치가 핵심입니다. 증가에 성공하면 `return`으로 빠져나와 `it[u]`가 그대로여서 같은 간선을 다시 쓸 수 있고, 막혀서 `continue`나 반복이 끝나면 `it[u]`가 올라갑니다.

**흔한 실수:**

- `it`를 단계마다 0으로 초기화하지 않는 것입니다. 앞 단계에서 막힌 간선이 새 단계에서는 뚫릴 수 있습니다.
- `it` 없이 `for...of`로 간선을 매번 처음부터 보는 것입니다. 막힌 곳을 반복해서 탐색해 시간 초과가 납니다.
- 레벨 조건 `level[v] === level[u] + 1`을 빼는 것입니다. 단계 구조가 깨져서 느려집니다.

## 최소 비용 최대 유량 개요

최소 비용 최대 유량(min-cost max-flow)은 간선마다 용량과 단위 유량당 비용이 있을 때, 최대 유량을 흘리면서 총 비용을 최소로 하는 문제입니다. 유량의 양 K가 정해진 변형은 K만큼만 보내는 최소 비용을 구합니다. 비용은 `유량 × 단위 비용`의 합입니다.

풀이는 최소 비용 증가 경로(successive shortest path)입니다. 잔여 그래프에서 비용이 가장 작은 s→t 경로(간선 수가 아니라 비용 합이 최소)를 찾아 병목만큼 흘리는 일을 경로가 없을 때까지 반복합니다.

- 역간선의 비용은 정방향 비용에 마이너스를 붙입니다. 유량을 되돌리면 그 비용도 돌려받는 것입니다. 그래서 잔여 그래프에 음수 간선이 생깁니다.
- 음수 간선이 있으므로 최단 경로는 Bellman-Ford 계열인 SPFA(49편)로 구합니다. Dijkstra를 쓰려면 정점 포텐셜로 간선 비용을 0 이상으로 바꿔야 하고, 그 아이디어가 Johnson 알고리즘입니다(49편).
- 증가 한 번에 최단 경로 탐색이 한 번 드니 시간은 증가 횟수 × 최단 경로 시간이고, 증가 횟수는 최대 유량 F 이하입니다.
- 원래 그래프에 음수 사이클이 없어야 하고, 이 방법은 그런 입력을 가정합니다.

```js
function addEdgeC(g, u, v, cap, cost) {   // g.cost 배열도 필요
  g.adj[u].push(g.to.length)
  g.to.push(v); g.cap.push(cap); g.cost.push(cost)
  g.adj[v].push(g.to.length)
  g.to.push(u); g.cap.push(0); g.cost.push(-cost)
}
```

```js
function spfa(g, s) {             // 비용 기준 최단 경로
  const dist = new Array(g.adj.length).fill(Infinity)
  const prev = dist.map(() => -1)
  const q = [s], inQ = new Set([s]); dist[s] = 0
  for (let h = 0; h < q.length; h++) {
    const u = q[h]; inQ.delete(u)
    for (const e of g.adj[u]) {
      const v = g.to[e], nd = dist[u] + g.cost[e]
      if (g.cap[e] === 0 || nd >= dist[v]) continue
      dist[v] = nd; prev[v] = e
      if (!inQ.has(v)) { inQ.add(v); q.push(v) }
    }
  }
  return { dist, prev }
}
```

```js
function minCostFlow(g, s, t) {   // pathOf는 위와 같다
  let flow = 0, cost = 0
  for (;;) {
    const { dist, prev } = spfa(g, s)
    if (prev[t] === -1) return { flow, cost }
    const path = pathOf(g, prev, s, t)
    const f = Math.min(...path.map((e) => g.cap[e]))
    for (const e of path) {
      g.cap[e] -= f
      g.cap[e ^ 1] += f
    }
    flow += f
    cost += f * dist[t]
  }
}
```

작은 예로 따라갑니다. 정점 0=s, 1=a, 2=b, 3=t이고 `[출발, 도착, 용량, 비용]`이 `[0,1,2,1]`, `[0,2,1,2]`, `[1,2,1,1]`, `[1,3,1,3]`, `[2,3,2,1]`입니다.

| 증가 | 경로 | 비용 | 유량 |
|------|------|------|------|
| 1 | `0→2→3` | 2 + 1 = 3 | 1 |
| 2 | `0→1→2→3` | 1 + 1 + 1 = 3 | 1 |
| 3 | `0→1→3` | 1 + 3 = 4 | 1 |

최대 유량은 3이고 총 비용은 3 + 3 + 4 = 10입니다. 증가 경로의 비용은 단계마다 같거나 커집니다.

- 쓰임: 작업과 사람의 비용이 정해진 할당 문제(가중치 이분 매칭), 비용이 다른 여러 경로로 물건을 최소 비용에 나르는 문제입니다. 가중치 이분 매칭을 전용으로 푸는 헝가리안 알고리즘은 71편에서 개요로 다룹니다.
- 정점 쪼개기와 가상 출발·도착점 모델링은 최대 유량과 같고, 간선 비용만 더 붙습니다.

**흔한 실수:**

- 역간선 비용을 정방향과 같은 양수로 넣는 것입니다. 음수여야 합니다.
- 증가 때 경로의 비용에 병목 유량을 곱하지 않고 `dist[t]`만 더하는 것입니다. 비용은 `f * dist[t]`입니다.
- 음수 간선 때문에 Dijkstra를 그대로 쓰는 것입니다. 포텐셜 없이는 틀립니다.
- "최대 유량"과 "유량 K에서의 최소 비용"을 구분하지 않는 것입니다. K가 정해진 문제는 누적 유량이 K에 도달하면 마지막 증가를 `K - flow`까지만 하고 멈춥니다.

## 핵심 정리

- 유량 네트워크 문제는 용량 제한과 유량 보존을 지키면서 s에서 t로 보내는 최대량을 구하며, 잔여 그래프는 남은 용량 `c - f`와 되돌릴 수 있는 양 `f`(역간선)로 이루어집니다.
- Ford-Fulkerson은 증가 경로를 반복해서 찾으며 O(E · F)이고, 정수 용량에서만 종료가 보장되고 용량이 크면 느립니다. BFS로 최단 경로를 고르는 Edmonds-Karp는 용량과 무관하게 O(V · E²)입니다.
- 최대 유량의 값은 최소 컷의 용량과 같고, 최대 유량을 흘린 뒤 잔여 그래프에서 s에서 도달 가능한 정점 집합이 S입니다.
- Dinic은 BFS 레벨 그래프와 현재 간선 포인터를 쓰는 DFS로 단계마다 블로킹 플로우를 구해 O(V² · E)이며 단위 용량 그래프에서 훨씬 빠릅니다.
- 최소 비용 최대 유량은 비용이 최소인 증가 경로를 반복해 구하며, 역간선 비용은 음수라서 SPFA나 포텐셜을 쓴 Dijkstra가 필요합니다.
