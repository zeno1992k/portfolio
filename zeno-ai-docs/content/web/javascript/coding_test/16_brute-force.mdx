## Brute Force

완전탐색(brute force)은 답이 될 수 있는 후보를 빠짐없이 모두 만들어 조건을 검사하고 최적의 것을 고르는 방법입니다. 모든 경우를 보므로 틀릴 수 없다는 점이 장점이고, 후보가 많으면 시간 초과가 나는 점이 한계입니다.

- 전체 시간은 후보 수 × 후보 하나를 검사하는 비용입니다.
- 가능 여부는 후보 수를 세어 허용 연산 횟수(1초에 약 10^8 어림, 14편)와 비교해 판단합니다.
- 최적 풀이를 못 찾을 때 일단 완전탐색으로 정답을 내는 용도로도 씁니다. 이 정답은 더 빠른 풀이를 검증하는 기준이 됩니다(15편, 80편).

| 후보의 모양 | 후보 수 | 반복 방식 |
|-------------|---------|-----------|
| 값 하나의 범위 | N | 반복문 한 겹 |
| 서로 다른 두 개 | 약 N²/2 | 이중 반복문 |
| 서로 다른 세 개 | 약 N³/6 | 삼중 반복문 |
| 선택 횟수가 입력으로 정해짐 | 방법에 따라 다름 | 재귀 |
| 각 원소를 넣거나 뺌 | 2^N | 비트마스크 또는 재귀 |

## 단순 반복 완전탐색

단순 반복 완전탐색은 하나의 변수가 가질 수 있는 값을 범위 끝까지 차례로 모두 시험하는 방법입니다.

```js
function countSpecial(n, k) {
  let count = 0
  for (let x = 1; x <= n; x++) {
    let digitSum = 0
    for (let t = x; t > 0; t = Math.floor(t / 10)) {
      digitSum += t % 10
    }
    if (digitSum % k === 0) count++
  }
  return count
}
countSpecial(30, 3) // 10 (3, 6, 9, ..., 27, 30)
```

- 후보는 1부터 n까지 n개이고, 각 후보의 검사는 자릿수만큼(log N)이어서 전체 O(N log N)입니다.
- 범위의 양 끝을 포함하는지(`<=`)를 문제 조건과 맞춥니다. 끝 하나를 빠뜨리는 off-by-one이 가장 흔합니다(15편).
- 약수를 구할 때처럼 범위를 √N까지만 보면 되는 경우가 있습니다(12편).

## 이중 반복문

이중 반복문은 서로 다른 두 원소를 고르는 모든 쌍을 검사하는 방법입니다. 안쪽 반복을 `j = i + 1`부터 시작하면 같은 쌍을 두 번 세지 않고 자기 자신과의 쌍도 빠집니다.

```js
function minGap(arr) {
  let best = Infinity
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      best = Math.min(best, Math.abs(arr[i] - arr[j]))
    }
  }
  return best
}
minGap([8, 1, 5, 3]) // 2
```

- 쌍의 수는 N(N−1)/2이고 복잡도는 O(N²)입니다. N이 5000 안팎까지 가능합니다(14편).
- 순서가 있는 쌍이면 `j`를 0부터 돌며 `i !== j`를 확인합니다. 쌍의 수는 N(N−1)입니다.
- 같은 원소를 두 번 써도 된다면 `j = i`부터 시작합니다. 문제의 허용 여부를 먼저 읽습니다.
- 격자에서는 모든 칸이 후보인 R × C 이중 반복을 씁니다(17편).

**흔한 실수:** 안쪽 반복을 `j = 0`으로 쓰고 쌍을 `/ 2`로 보정하는 것입니다. 자기 자신 쌍(i === j)이 섞여 값이 틀립니다.

## 삼중 반복문

삼중 반복문은 서로 다른 세 원소를 고르는 모든 조합을 검사합니다. `j = i + 1`, `k = j + 1`로 시작해 `i < j < k`인 조합만 한 번씩 봅니다.

```js
function countTriples(arr, target) {
  const n = arr.length
  let count = 0
  for (let i = 0; i < n; i++) {
    for (let j = i + 1; j < n; j++) {
      for (let k = j + 1; k < n; k++) {
        if (arr[i] + arr[j] + arr[k] === target) count++
      }
    }
  }
  return count
}
countTriples([1, 2, 3, 4, 5], 9) // 2 (1+3+5, 2+3+4)
```

- 조합 수는 N(N−1)(N−2)/6이고 복잡도는 O(N³)입니다. N이 500 안팎까지 가능합니다.
- 정렬하고 투 포인터로 안쪽 두 반복을 하나로 합치면 O(N²)이 됩니다(30편).
- 네 겹 이상이 필요하다고 느껴지면 반복문을 중첩하지 말고 재귀나 비트마스크로 바꿉니다.

## 모든 경우의 수

중첩 반복문은 겹 수가 코드에 고정돼 있어서, 선택 횟수가 입력으로 정해지면 쓸 수 없습니다. 이럴 때는 한 번에 하나씩 고르는 재귀로 모든 경우를 만듭니다.

문제 예: 주사위를 k번 던져 눈의 합이 target인 경우의 수입니다.

```js
function countDice(k, sum, target) {
  if (k === 0) return sum === target ? 1 : 0
  let total = 0
  for (let face = 1; face <= 6; face++) {
    total += countDice(k - 1, sum + face, target)
  }
  return total
}
countDice(2, 0, 7) // 6 (1+6, 2+5, 3+4, 4+3, 5+2, 6+1)
```

- 재귀는 종료 조건(k가 0이면 값을 판정), 선택(눈 하나 고르기), 다음 호출 순서로 짭니다(22편).
- 경우의 수는 6^k입니다. 호출 깊이는 k이고 호출 수는 6^k에 비례합니다.
- 종류에 따라 경우의 수가 다릅니다.

| 종류 | 설명 | 경우의 수 |
|------|------|-----------|
| 중복 순열 | N가지에서 K번 고름, 같은 것 반복 허용, 순서 중요 | N^K |
| 순열 | N개 중 K개를 순서 있게 | N × (N−1) × … × (N−K+1) |
| 조합 | N개 중 K개를 순서 없이 | 순열 수 / K! |
| 부분집합 | 각 원소를 넣거나 뺌 | 2^N |

- 순열·조합·부분집합을 생성하는 표준 구조는 백트래킹(23편)이고 조합의 개수 공식은 56편에서 다룹니다.
- 경우의 수가 허용 연산 횟수보다 많으면 모든 경우를 보는 방법은 버리고 가지치기(23편)나 다른 알고리즘을 찾습니다.

## 부분집합 탐색

부분집합 탐색은 원소 N개 각각을 "넣는다/넣지 않는다"로 정해 가능한 2^N개 조합을 모두 보는 방법입니다. 비트마스크로 반복문 하나에 담을 수 있습니다. 0부터 2^N − 1까지의 정수 `mask`를 쓰고, 이진수의 i번째 비트가 1이면 i번째 원소를 포함합니다.

```js
function countSubsets(arr, target) {
  const n = arr.length
  let count = 0
  for (let mask = 0; mask < (1 << n); mask++) {
    let sum = 0
    for (let i = 0; i < n; i++) {
      if (mask & (1 << i)) sum += arr[i]
    }
    if (sum === target) count++
  }
  return count
}
countSubsets([1, 2, 3, 4], 5) // 2 ({1, 4}, {2, 3})
```

재귀로 쓰면 원소마다 두 갈래로 나뉩니다.

```js
function dfs(i, sum) {
  if (i === arr.length) return sum === target ? 1 : 0
  return dfs(i + 1, sum) + dfs(i + 1, sum + arr[i])
}
dfs(0, 0)  // 같은 결과 (arr, target은 바깥 변수)
```

- 비트마스크 방식의 복잡도는 O(2^N × N)입니다(부분집합 2^N개, 합 계산 N). N이 20 안팎까지 가능합니다(2^20 × 20 = 약 2 × 10^7).
- `mask = 0`은 공집합입니다. 합이 0이어서 target이 0이면 공집합이 한 번 세어집니다. 문제에서 공집합을 허용하는지 확인합니다.
- JavaScript의 비트 연산은 피연산자를 32비트 정수로 바꾸고 시프트 양은 32로 나눈 나머지를 씁니다. `1 << n`이 안전한 범위는 n이 30 이하입니다. 31이면 음수가 되고 32 이상은 `1 << 0`과 같아져 틀립니다(자세히는 24편).
- 재귀 방식은 합을 인수로 누적해 넘기므로 합 계산이 O(1)이고 전체가 O(2^N)입니다. 비트마스크 방식은 매번 합을 새로 구해서 O(2^N × N)입니다(아래 "완전탐색 최적화").

## 완전탐색 최적화

완전탐색의 최적화는 후보의 수를 줄이거나 후보 하나를 검사하는 비용을 줄이는 일입니다. 다음 방법이 있습니다.

| 방법 | 설명 | 예 |
|------|------|----|
| 범위 줄이기 | 볼 필요 없는 구간을 시작·끝에서 제외 | `j = i + 1`, 약수는 √N까지 |
| 중복 계산 제거 | 이어지는 계산을 이어서 갱신 | 구간 합을 `sum +=`로 누적 |
| 일찍 중단 | 정답이 확정되거나 불가능하면 즉시 빠져나옴 | `break`, `return`, 가지치기(23편) |
| 안쪽 반복을 자료구조로 대체 | 탐색을 O(1)·O(log N)으로 | `Set` 조회, 이분 탐색(28편) |
| 전처리 | 정렬·누적합을 먼저 한 번 만들어 둠 | 누적합(29편) |
| 절반씩 나눠 탐색 | 2^N을 두 개의 2^(N/2)로 쪼갬 | Meet In The Middle(72편) |

구간 합 최대 문제로 중복 계산 제거를 봅니다. 구간 [i, j] 모든 쌍에서 합을 매번 처음부터 구하면 O(N³)이고, 시작 i를 고정하고 j를 늘리며 합을 이어서 구하면 O(N²)입니다.

```js
let best = -Infinity
for (let i = 0; i < n; i++) {
  let sum = 0
  for (let j = i; j < n; j++) {
    sum += arr[j]                // 이전 합에 하나만 더함
    best = Math.max(best, sum)
  }
}
```

- 최적화를 해도 모양이 완전탐색이면 후보 수의 한계 안에서만 쓸 수 있습니다. 여전히 허용치를 넘으면 알고리즘을 바꿔야 합니다.
- 최적화를 적용하기 전과 후의 결과를 같은 테스트로 비교해서 틀리지 않았는지 확인합니다(15편).

## 곱의 법칙과 합의 법칙

곱의 법칙과 합의 법칙은 경우의 수를 세는 두 기본 규칙입니다. 후보 수를 코드를 짜기 전에 어림하는 데 씁니다.

| 법칙 | 상황 | 계산 |
|------|------|------|
| 합의 법칙 | 서로 겹치지 않는 두 경우 중 하나를 고름 (A 또는 B) | m + n |
| 곱의 법칙 | 앞 선택과 상관없이 단계마다 고름 (A 그리고 B) | m × n |

- 합의 법칙 예: 버스 3가지, 지하철 2가지 중 하나로 가면 3 + 2 = 5가지입니다. 두 경우에 겹치는 방법이 있으면 겹친 만큼 빼야 합니다.
- 곱의 법칙 예: 셔츠 3가지에 바지 4가지를 고르면 3 × 4 = 12가지입니다.
- 두 법칙을 섞으면 곱한 뒤 더합니다. 셔츠 3 × 바지 4에 원피스 2가지를 더 고를 수 있으면 3 × 4 + 2 = 14가지입니다.

곱의 법칙에서 앞 선택 때문에 다음 선택지가 줄면 줄어든 수를 곱합니다. 이것이 순열입니다.

| 경우 (N = 10, K = 3) | 식 | 경우의 수 |
|----------------------|----|-----------|
| 중복 순열 | N^K | 1000 |
| 순열 | 10 × 9 × 8 | 720 |
| 조합 | 720 / 3! | 120 |
| 부분집합 (전체) | 2^N | 1024 |
| 전체 순열 | 10! | 3628800 |

- 부분집합 2^N은 원소마다 두 가지(넣음, 안 넣음)를 곱한 2 × 2 × … × 2입니다.
- 조합은 같은 K개 묶음이 순서만 다르게 K!번 세어진 것이므로 순열 수를 K!로 나눕니다.
- 어림한 경우의 수에 검사 비용을 곱해 허용 연산과 비교하면 완전탐색 가능 여부가 바로 나옵니다. 예: N = 20 부분집합이면 2^20 × 20 = 약 2 × 10^7이어서 가능합니다.

## 핵심 정리

- 완전탐색은 모든 후보를 만들어 검사하는 방법이고, 시간은 후보 수 × 검사 비용입니다. 후보 수를 먼저 세어 가능 여부를 판단합니다.
- 쌍은 `j = i + 1`로 시작하는 이중 반복(O(N²)), 세 개는 삼중 반복(O(N³))입니다. 선택 횟수가 입력으로 정해지면 재귀를 씁니다.
- 부분집합은 2^N개이고 비트마스크 반복문이나 포함·제외 재귀로 모두 봅니다. 복잡도는 O(2^N × N)입니다.
- 최적화는 범위 줄이기, 중복 계산 제거, 일찍 중단, 안쪽 반복의 자료구조 대체로 합니다.
- 합의 법칙은 더하고 곱의 법칙은 곱합니다. 순열은 줄어드는 선택지의 곱이고 조합은 순열을 K!로 나눈 값입니다.
