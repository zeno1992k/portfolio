## Queue 개념

큐(queue)는 먼저 넣은 원소를 먼저 꺼내는 선입선출(FIFO, First In First Out) 자료구조입니다. 줄을 서는 것과 같습니다. 원소를 넣는 쪽을 뒤(rear, back), 꺼내는 쪽을 앞(front)이라고 합니다.

| 연산 | 동작 |
|------|------|
| enqueue | 뒤에 원소를 넣음 |
| dequeue | 앞의 원소를 꺼내 반환하고 제거 |
| peek(front) | 앞의 원소를 제거하지 않고 봄 |
| isEmpty, size | 비었는지, 원소 수 |

- 스택(19편)은 한쪽 끝에서 넣고 빼지만 큐는 반대쪽에서 넣고 뺍니다. 그래서 들어온 순서가 보존됩니다.
- 모든 연산이 O(1)이어야 쓸모가 있습니다. 이 편의 구현 방법은 이 조건을 얼마나 만족하는지로 갈립니다.
- 큐가 필요한 문제의 단서는 "들어온 순서대로 처리", "가까운 것부터 차례로", "한 단계씩 퍼져 나가는" 표현입니다. 대표 용도는 BFS(자세히는 38편)와 순서대로 처리하는 시뮬레이션입니다.

## JavaScript Queue 구현

JavaScript에는 큐 클래스가 없어서 배열을 씁니다. 뒤에 넣는 것은 `push`, 앞에서 꺼내는 것은 `shift`입니다. 가장 짧은 구현입니다.

```js
const q = []
q.push(1)    // enqueue
q.push(2)
q.shift()    // 1 (dequeue)
q[0]         // 2 (peek)
q.length     // 1 (size)
q.shift()    // 2
q.shift()    // undefined (빈 큐, 에러 아님)
```

- `shift`는 맨 앞 원소를 제거해 반환하고, 배열이 비어 있으면 `undefined`를 반환합니다. 스택의 `pop`처럼 빈 큐에서도 에러가 없으므로 길이를 먼저 확인합니다.
- `push` 반환값은 새 길이입니다.
- 입력이 작을 때(원소가 수만 개 이하)는 이 구현으로 충분합니다. 큰 입력에서는 다음 절의 이유로 느려집니다.

## Array.shift를 Queue로 쓰면 느린 이유

`shift`는 첫 원소를 제거한 뒤 나머지 원소를 모두 한 칸 앞으로 당기고 `length`를 1 줄입니다(MDN). 명세상 동작이 그렇기 때문에 한 번에 걸리는 시간이 원소 수에 비례하는 O(N)이라고 보고 설계해야 합니다. 원소 N개를 `shift`로 모두 꺼내면 합계가 O(N²)입니다.

| 방식 | 한 번의 dequeue | N개를 모두 꺼내는 합 |
|------|-----------------|----------------------|
| `shift` | O(N) | O(N²) |
| head index(다음 절) | O(1) | O(N) |

Node.js 24.15.0에서 길이 N인 배열을 `shift`로 끝까지 비운 시간을 한 번씩 직접 재 본 값입니다.

| N | 시간 |
|---|------|
| 10,000 | 약 1ms |
| 30,000 | 약 41ms |
| 50,000 | 약 113ms |
| 100,000 | 약 500ms |
| 200,000 | 약 9.5초 |
| 400,000 | 약 41.8초 |

- 작은 N에서는 빠르다가 크기가 커지면 N이 두 배일 때 시간이 두 배보다 훨씬 늘어납니다. 같은 N개를 head index로 차례로 꺼내는 데는 N이 100만이어도 0ms가 나왔습니다.
- 위 수치는 한 번의 측정이고 기기, Node.js 버전, 배열 안의 값에 따라 달라집니다. 기준값이 아니라 증가 양상을 보는 자료입니다.
- 원소가 10만 개를 넘을 수 있는 BFS 같은 문제에서 `shift`는 시간 초과의 원인이 됩니다. 입력 크기로 판단하는 법은 14편에 있습니다.
- 반대쪽 끝에 넣는 `unshift`도 같은 이유로 O(N)입니다.

## head index Queue

head index 큐는 원소를 실제로 지우지 않고 "앞이 어디인지"를 가리키는 정수 `head`만 옮기는 큐입니다. dequeue는 `arr[head++]`이고, 꺼낸 자리는 그대로 둡니다.

```js
const q = [10, 20, 30]
let head = 0
q.push(40)                  // enqueue
const x = q[head++]         // dequeue -> 10
const front = q[head]       // peek -> 20
const size = q.length - head // 3
const empty = head === q.length // false
```

- 원소를 이동하지 않으므로 enqueue와 dequeue가 모두 O(1)입니다.
- 큐에 남은 원소 수는 `q.length - head`이고, 비었는지는 `head === q.length`(또는 `head >= q.length`)입니다. `q.length === 0`으로 검사하면 이미 꺼낸 원소가 남아 있어서 영영 비지 않습니다.
- 꺼낸 자리는 메모리에 남습니다. 배열의 길이가 지금까지 넣은 총 개수가 됩니다. BFS처럼 각 상태를 한 번씩만 넣는 문제는 그 총 개수가 상태 수이므로 문제가 없습니다.
- 넣고 빼는 횟수가 상태 수보다 훨씬 커지는 문제(같은 원소를 계속 되돌려 넣는 경우)에서는 메모리가 문제입니다. `head`가 배열 길이의 절반을 넘으면 `q.splice(0, head); head = 0`으로 앞부분을 정리하거나 원형 큐를 씁니다.
- `while (head < q.length)` 반복 안에서 `q.push`를 해도 반복 조건이 길이를 다시 읽으므로 새로 넣은 원소가 처리됩니다. BFS가 이 성질을 씁니다.
- `for...of`로 큐를 순회하면 도중에 넣은 원소도 순회될 수 있지만 `head`를 쓸 수 없으니 `while`을 씁니다.

**흔한 실수:** 검사에 `q.length`를 쓰는 것과 `head`를 올리지 않고 `q[head]`만 읽는 것입니다. 꺼낼 때는 반드시 `head++`로 올립니다.

## BFS Queue

BFS(너비 우선 탐색)는 시작점에서 가까운 칸부터 차례로 퍼져 나가는 탐색이고, 큐가 그 순서를 만듭니다. 시작점을 넣고, 꺼낸 노드의 이웃 중 처음 보는 것을 큐 뒤에 넣는 과정을 반복합니다(자세히는 38편).

```js
function bfs(graph, start) {
  const dist = Array(graph.length).fill(-1)
  const q = [start]; let head = 0
  dist[start] = 0
  while (head < q.length) {
    const v = q[head++]
    for (const w of graph[v]) {
      if (dist[w] !== -1) continue // 이미 방문
      dist[w] = dist[v] + 1
      q.push(w)
    }
  }
  return dist
}
bfs([[1, 2], [3], [3], [4], []], 0) // [0, 1, 1, 2, 3]
```

- 큐에는 가까운 노드(거리 d)가 모두 나간 뒤에야 먼 노드(거리 d + 1)가 나갑니다. 그래서 처음 도착한 거리가 최단입니다.
- `dist`가 방문 배열을 겸합니다. 처음 보는 노드(`-1`)를 만나면 넣을 때 바로 거리를 적습니다. 꺼낼 때 방문을 확인하면 같은 노드가 큐에 여러 번 들어갑니다.
- 도달할 수 없는 노드의 `dist`는 `-1`로 남습니다.
- 시간은 노드 수 V, 간선 수 E에 대해 O(V + E)입니다. 큐에는 노드가 한 번씩만 들어갑니다.
- 격자 BFS는 큐에 `(r, c)`를 넣고 방향 배열로 이웃을 계산합니다. 좌표를 정수 하나로 바꾸면 큐에 숫자만 넣을 수 있습니다(자세히는 17편).
- 거리별로 끊어서 처리해야 하면 반복마다 현재 큐 크기를 `size`로 저장하고 그만큼만 꺼냅니다.

## Circular Queue

원형 큐(circular queue)는 크기가 고정된 배열의 끝과 처음을 이어 붙여, 꺼낸 자리를 다시 쓰는 큐입니다. 인덱스를 `% cap`(cap은 용량)으로 돌려서 배열이 원처럼 이어집니다.

```js
class RingQueue {
  constructor(cap) {
    this.buf = new Int32Array(cap)
    this.cap = cap; this.head = 0; this.size = 0
  }
  push(x) { // size가 cap보다 작을 때만 호출
    this.buf[(this.head + this.size++) % this.cap] = x
  }
  shift() { // size가 0보다 클 때만 호출
    const x = this.buf[this.head]
    this.head = (this.head + 1) % this.cap
    this.size--
    return x
  }
}
```

- 뒤에 넣는 위치는 `(head + size) % cap`입니다. `head`와 `size` 두 값으로 비었는지(`size === 0`)와 찼는지(`size === cap`)를 구별합니다. `head`와 `tail`만 쓰면 비었을 때와 찼을 때 둘 다 `head === tail`이 되어 구별이 안 되므로, 한 칸을 비워 두는 규칙이 필요합니다.
- 용량은 동시에 큐에 있는 원소의 최대 수입니다. 용량을 넘겨 넣으면 아직 꺼내지 않은 원소를 덮어쓰므로 `size < cap`일 때만 `push`하고, 빈 큐에서는 `shift`하지 않도록 호출하는 쪽에서 검사합니다. 문제의 제한으로 최대 동시 개수를 알 때만 씁니다.
- 메모리가 `cap`으로 고정되고 모든 연산이 O(1)입니다. head index 큐처럼 총 넣은 개수만큼 늘지 않습니다.
- `Int32Array`는 정수만 담을 수 있고 32비트 범위가 한계입니다(자세히는 05편). 객체를 담으려면 일반 `Array`를 씁니다.
- 큐를 번갈아 넣고 빼는 시뮬레이션처럼 총 연산 수가 많고 동시 개수가 작을 때 유용합니다.

**흔한 실수:** `% cap`을 빼먹고 `head++`만 하는 것입니다. 인덱스가 배열 끝을 넘어가 `undefined`를 읽거나 쓰기가 무시됩니다.

## Deque

덱(deque, double-ended queue)은 앞과 뒤 양쪽에서 넣고 뺄 수 있는 자료구조입니다. 스택과 큐를 합친 것입니다.

| 연산 | 동작 | 배열 메서드 | 비용 |
|------|------|-------------|------|
| pushBack | 뒤에 넣음 | `push` | O(1) |
| popBack | 뒤에서 뺌 | `pop` | O(1) |
| pushFront | 앞에 넣음 | `unshift` | O(N) |
| popFront | 앞에서 뺌 | `shift` | O(N) |

- 배열로는 뒤쪽 연산만 빠르고 앞쪽 연산은 느립니다. 앞쪽 연산이 잦으면 직접 구현해야 합니다(다음 절).
- 덱이 필요한 문제의 단서는 두 가지입니다. 양쪽 끝에서 원소를 꺼내야 하는 경우(회문 검사, 양 끝에서 줄이기), 가중치가 0과 1인 최단 경로에서 가중치 0인 이동은 앞에, 1인 이동은 뒤에 넣는 0-1 BFS(자세히는 39편)입니다.
- 슬라이딩 윈도우의 최댓값처럼 앞에서는 범위를 벗어난 원소를 빼고 뒤에서는 작은 원소를 빼는 문제에도 덱이 쓰입니다(자세히는 32편).
- 스택, 큐, 덱은 서로의 특수한 경우입니다. 덱에서 한쪽 끝만 쓰면 스택이 되고, 넣는 끝과 빼는 끝을 반대로 하면 큐가 됩니다.

## Deque 직접 구현

앞쪽에도 O(1)로 넣으려면 배열의 중간에서 시작해 양쪽으로 자라게 하면 됩니다. 앞에 넣는 횟수와 뒤에 넣는 횟수가 각각 N을 넘지 않는다는 것을 아는 경우의 가장 간단한 구현입니다.

```js
class Deque {
  constructor(n) {
    this.buf = new Array(2 * n + 1)
    this.head = n; this.tail = n // [head, tail)이 내용
  }
  get size() { return this.tail - this.head }
  pushBack(x) { this.buf[this.tail++] = x }
  pushFront(x) { this.buf[--this.head] = x }
  popBack() {
    return this.size ? this.buf[--this.tail] : undefined
  }
  popFront() {
    return this.size ? this.buf[this.head++] : undefined
  }
}
```

`pushBack(1)`, `pushFront(2)`, `pushBack(3)` 뒤의 내용은 앞에서부터 `2, 1, 3`입니다. `popFront()`는 `2`, `popBack()`은 `3`을 돌려줍니다.

- 내용은 `buf[head]`부터 `buf[tail - 1]`까지입니다. 앞에 넣으면 `head`가 줄고, 뒤에 넣으면 `tail`이 늘어서 배열 중앙에서 양쪽으로 퍼집니다.
- 모든 연산이 O(1)이고 공간은 O(N)입니다. 앞과 뒤에 각각 넣을 수 있는 횟수의 상한이 `n`이므로, 전체 `pushFront`와 `pushBack` 횟수를 기준으로 `n`을 정합니다. 안전하게는 총 넣는 횟수를 `n`으로 합니다.
- 넣고 빼는 횟수가 상한을 넘을 수 있으면 원형 큐처럼 인덱스를 `% cap`으로 돌리는 원형 버퍼 덱을 씁니다. 앞에 넣을 때 `head = (head - 1 + cap) % cap`으로 음수를 피합니다(자세히는 11편).
- 빈 덱에서 꺼내면 `undefined`를 돌려주도록 길이를 확인합니다.
- 코딩테스트에서 한 번에 외우기 어렵다면 `head`, `tail` 두 정수와 `new Array(2 * n + 1)`이라는 구조만 기억하면 됩니다.

## 양방향 BFS와 Deque

양방향 BFS는 시작점과 도착점에서 동시에 탐색을 시작해 두 탐색이 만나는 곳에서 끝내는 방법입니다. 한쪽에서만 퍼지면 탐색 범위가 거리의 거듭제곱으로 커지는 그래프에서 양쪽의 탐색 범위가 훨씬 작아집니다(자세히는 39편). 이 구현에서는 큐가 둘 필요합니다. 시작 쪽 큐와 도착 쪽 큐입니다. 한 번에 한 층을 통째로 확장하므로 층마다 새 배열을 만드는 방식이 간단합니다. 한 층의 확장은 `expand`가 맡습니다.

```js
function expand(g, q, mine, other) {
  const next = []; let best = Infinity
  for (const v of q) {
    for (const w of g[v]) {
      if (other.has(w)) {
        const len = mine.get(v) + 1 + other.get(w)
        best = Math.min(best, len)
      }
      if (mine.has(w)) continue
      mine.set(w, mine.get(v) + 1)
      next.push(w)
    }
  }
  return [next, best] // 다음 층, 만난 곳을 지나는 최단 거리
}
```

```js
function biBfs(g, s, t) {
  if (s === t) return 0
  const dS = new Map([[s, 0]]), dT = new Map([[t, 0]])
  let qS = [s], qT = [t]
  while (qS.length && qT.length) {
    let best
    if (qS.length <= qT.length) { // 작은 쪽을 확장
      [qS, best] = expand(g, qS, dS, dT)
    } else {
      [qT, best] = expand(g, qT, dT, dS)
    }
    if (best < Infinity) return best
  }
  return -1
}
```

- 각 방향의 `Map`은 방문 표시와 시작점까지의 거리를 겸합니다. 상대편이 방문한 노드를 만나면 두 탐색이 이어진 것입니다.
- 만났다고 바로 반환하지 않고 그 층을 끝까지 훑어 최솟값을 구해야 합니다. 먼저 찾은 연결이 최단이 아닐 수 있습니다.
- 작은 쪽 층을 확장하면 두 큐의 크기가 비슷하게 유지되어 탐색량이 줄어듭니다.
- 덱은 이 구조에서는 필수가 아닙니다. 덱이 필요한 BFS는 0-1 BFS입니다. 간선 가중치가 0이면 `pushFront`, 1이면 `pushBack`을 해서 거리가 작은 노드가 항상 앞에 오게 합니다(자세히는 39편). 위의 `Deque` 클래스가 그 앞쪽 삽입을 O(1)로 해 줍니다.
- 도착점이 시작점에서 도달할 수 없으면 한쪽 큐가 먼저 비어 `-1`을 반환합니다.

## 스택 두 개로 만드는 큐

스택 두 개로 큐를 만들 수 있습니다. 하나는 넣는 용도(`inStack`), 다른 하나는 꺼내는 용도(`outStack`)입니다. 넣을 때는 `inStack`에 `push`하고, 꺼낼 때는 `outStack`이 비었을 때만 `inStack`의 모든 원소를 하나씩 `pop`해 `outStack`에 `push`합니다. 옮기면 순서가 뒤집혀 가장 먼저 들어온 원소가 `outStack`의 맨 위에 옵니다.

```js
class TwoStackQueue {
  constructor() { this.inS = []; this.outS = [] }
  push(x) { this.inS.push(x) }
  shift() {
    if (this.outS.length === 0) {
      while (this.inS.length) this.outS.push(this.inS.pop())
    }
    return this.outS.pop() // 둘 다 비면 undefined
  }
}
```

`1, 2, 3`을 넣으면 `inS`는 `[1, 2, 3]`입니다. 첫 `shift`에서 `outS`가 `[3, 2, 1]`이 되고 `1`이 나옵니다. 이어서 `4`를 넣으면 `inS`는 `[4]`이고, 다음 `shift`는 `outS`가 비지 않았으므로 옮기지 않고 `2`를 꺼냅니다.

- 옮기는 일은 `outStack`이 비었을 때만 합니다. 비지 않았는데 옮기면 순서가 뒤섞입니다.
- 한 번의 `shift`는 O(N)일 수 있지만 모든 원소는 `inS`에서 `outS`로 딱 한 번만 옮겨집니다. 따라서 연산 M번의 전체 시간은 O(M)이고 연산당 평균은 O(1)입니다(분할 상환, 자세히는 14편).
- 이 구조는 두 스택으로 큐를 만드는 문제 자체가 출제되기도 하고, 스택만 쓸 수 있는 환경에서 큐가 필요할 때 씁니다. 일반적인 풀이에서는 head index 큐가 더 단순합니다.
- 반대로 큐 두 개로 스택을 만들 수도 있지만 한 번의 `pop`이 O(N)이라서 실용성은 떨어집니다.

## 요세푸스 문제

요세푸스 문제는 N명이 원으로 둘러앉아 있을 때, 한 명부터 시작해 K번째 사람을 제거하고 그다음 사람부터 다시 세는 일을 반복하며 제거되는 순서를 구하는 문제입니다. 원형으로 도는 구조라서 큐로 풀립니다. 앞의 K - 1명은 꺼내서 뒤로 보내고, K번째 사람은 꺼내서 제거합니다.

```js
function josephus(N, K) {
  const q = Array.from({ length: N }, (_, i) => i + 1)
  let head = 0
  const out = []
  while (head < q.length) {
    for (let i = 0; i < K - 1; i++) q.push(q[head++])
    out.push(q[head++]) // K번째 제거
  }
  return out
}
josephus(7, 3) // [3, 6, 2, 7, 5, 1, 4]
```

`N = 7`, `K = 3`의 추적입니다. 큐 `1 2 3 4 5 6 7`에서 `1`, `2`를 뒤로 보내고 `3`을 제거합니다. 큐는 `4 5 6 7 1 2`입니다. 다시 `4`, `5`를 보내고 `6`을 제거하며 이어가면 제거 순서는 `3, 6, 2, 7, 5, 1, 4`입니다.

- 한 명을 제거하는 데 K - 1번 옮기므로 전체 시간은 O(N · K)입니다. head index 큐라서 `shift`의 비용은 없습니다. 다만 배열이 N · K까지 길어지므로 둘의 곱이 크면 메모리가 문제입니다. 그때는 원형 큐를 쓰거나 아래 점화식을 씁니다.
- 마지막에 남는 사람의 번호만 구하면 되면 O(N)의 점화식이 있습니다. `n`명일 때 생존자(0부터 센 위치)를 `f(n)`이라 하면 `f(1) = 0`, `f(n) = (f(n - 1) + K) % n`입니다. 1부터 센 번호는 `f(N) + 1`입니다.

```js
function lastSurvivor(N, K) {
  let pos = 0 // f(1)
  for (let n = 2; n <= N; n++) pos = (pos + K) % n
  return pos + 1
}
lastSurvivor(7, 3) // 4 (josephus(7, 3)의 마지막 값)
```

- `K = 1`이면 앞에서부터 한 명씩 제거되어 순서는 `1, 2, …, N`입니다. K가 N 이상이어도 위 코드는 그대로 동작합니다.
- 시작 위치나 제거 방향이 문제마다 다르므로 첫 사람을 누구로 보는지 예제로 확인합니다.
- 제거된 순서가 필요하면 큐 시뮬레이션이 필요하고, 마지막 한 명만 필요하면 점화식이 훨씬 빠릅니다.

## 핵심 정리

- 큐는 선입선출이고 앞에서 꺼내는 연산이 핵심입니다. `Array.shift`는 나머지 원소를 모두 당기므로 큰 입력에서 O(N)씩 걸려 시간 초과가 날 수 있습니다.
- head index 큐는 `arr[head++]`로 꺼내서 O(1)이고, 남은 원소 수는 `length - head`이며 BFS에서는 그대로 쓰입니다.
- 원형 큐는 고정 크기 배열에서 `% cap`으로 인덱스를 돌려 메모리를 일정하게 유지합니다. 비었는지와 찼는지는 `size`로 구별합니다.
- 덱은 양쪽 끝에서 넣고 뺍니다. 배열의 `unshift`와 `shift`는 느리므로 중앙에서 시작하는 `head`, `tail` 배열이나 원형 버퍼로 직접 구현합니다.
- 양방향 BFS는 큐 두 개를 층 단위로 확장하며 만난 층의 최솟값을 반환하고, 0-1 BFS는 덱의 앞뒤 삽입을 씁니다.
- 스택 두 개로 만든 큐는 분할 상환 O(1)이고, 요세푸스는 큐 회전으로 순서를, 점화식으로 생존자를 O(N)에 구합니다.
