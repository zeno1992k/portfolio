## 행과 열

격자(grid)는 같은 길이의 행을 쌓아 만든 사각형 칸 판이며, JavaScript에서는 2차원 배열로 표현합니다. 가로줄이 행(row), 세로줄이 열(column)입니다. `grid[r][c]`는 r번째 행의 c번째 열 칸입니다.

```js
const grid = [
  [1, 2, 3],
  [4, 5, 6],
]
const H = grid.length    // 2 (행 수)
const W = grid[0].length // 3 (열 수)
grid[1][2]               // 6 (r=1, c=2)
```

- 첫 번째 인덱스가 행, 두 번째가 열입니다. 이 문서는 행 수를 `H`, 열 수를 `W`라고 씁니다.
- 행이 하나도 없으면 `grid[0]`이 `undefined`라서 `grid[0].length`가 TypeError입니다. 빈 격자가 가능한 문제에서는 `grid[0]?.length ?? 0`으로 씁니다.
- 입력 줄을 격자로 바꾸는 방법은 칸이 문자인지 숫자인지에 따라 다릅니다(자세히는 08편).

```js
const lines = ['#.#', '..#']
const chars = lines.map((line) => line.split(''))
// [['#', '.', '#'], ['.', '.', '#']]
const nums = '1 0 1'.split(' ').map(Number) // [1, 0, 1]
```

- 문자열도 `line[c]`로 칸을 읽을 수 있지만 문자열은 바꿀 수 없습니다. 칸을 수정해야 하면 `split('')`으로 배열로 바꿉니다.
- 새 격자를 만들 때는 행마다 새 배열이어야 합니다. `Array(H).fill(Array(W).fill(0))`은 모든 행이 같은 배열이 됩니다(자세히는 05편).

```js
const H = 2, W = 3
const board = Array.from(
  { length: H },
  () => Array(W).fill(0),
)
// [[0, 0, 0], [0, 0, 0]] (행마다 독립된 배열)
```

격자 전체를 한 번 훑는 비용은 칸 수 `H × W`에 비례합니다. 시간복잡도는 O(HW)입니다.

## 좌표 표현

칸의 위치는 `(r, c)` 쌍으로 나타냅니다. 위쪽이 0행이고 아래로 갈수록 r이 커집니다. 왼쪽이 0열이고 오른쪽으로 갈수록 c가 커집니다.

| 표기 | 첫 값 | 둘째 값 | 아래로 이동 |
|------|-------|---------|-------------|
| 행렬 좌표 `(r, c)` | 행 | 열 | r 증가 |
| 수학 좌표 `(x, y)` | 가로 위치 | 세로 위치 | 보통 y 감소 |

- 배열 인덱스는 행렬 좌표입니다. 수학 좌표의 `(x, y)`를 그대로 쓰면 `grid[y][x]`가 되어 순서가 뒤집힙니다.
- 문제가 `(x, y)`로 좌표를 줄 때 x가 행인지 열인지는 문제마다 다릅니다. 예제 입력으로 어느 쪽인지 확인한 뒤 코드의 `r`, `c`에 대응시킵니다.
- 문제가 1번부터 센다면 읽는 즉시 1을 빼서 0부터 세는 인덱스로 바꿉니다. 코드 곳곳에서 `-1`을 붙이는 것보다 입력 직후 한 번만 바꾸는 편이 안전합니다.

```js
const [r1, c1] = [3, 2]           // 문제의 좌표 (1부터)
const r = r1 - 1, c = c1 - 1      // 인덱스 (0부터)
grid[r][c]
```

좌표 하나를 저장할 때는 `[r, c]` 배열이나 `{ r, c }` 객체를 씁니다. 큐에 많이 넣을 때의 부담은 20편과 38편에서 다룹니다.

## 상하좌우 이동

한 칸 이동은 현재 좌표에 변화량 `(dr, dc)`를 더하는 것입니다.

| 방향 | dr | dc |
|------|----|----|
| 상 | −1 | 0 |
| 하 | +1 | 0 |
| 좌 | 0 | −1 |
| 우 | 0 | +1 |

```js
const r = 2, c = 3
const up = [r - 1, c]    // [1, 3]
const down = [r + 1, c]  // [3, 3]
const left = [r, c - 1]  // [2, 2]
const right = [r, c + 1] // [2, 4]
```

- 위는 r이 줄어드는 쪽입니다. 수학 좌표의 직관(위가 y 증가)과 반대라서 가장 많이 틀리는 곳입니다.
- 이동 결과가 격자 밖일 수 있습니다. 읽거나 쓰기 전에 범위 검사를 해야 합니다(아래 "범위 검사").
- `k`칸 이동은 변화량에 k를 곱합니다. `[r + dr * k, c + dc * k]`입니다.

## 대각선 이동

대각선은 행과 열이 동시에 ±1 변합니다. 네 방향이 있습니다.

| 방향 | dr | dc |
|------|----|----|
| 좌상 | −1 | −1 |
| 우상 | −1 | +1 |
| 좌하 | +1 | −1 |
| 우하 | +1 | +1 |

상하좌우 4개와 대각선 4개를 합치면 한 칸 주변을 모두 보는 8방향이 됩니다.

- 두 칸의 `dr`, `dc`가 모두 0이 아니면 대각선 이웃입니다.
- 같은 대각선 위의 칸은 `r - c`가 같거나(좌상–우하 방향) `r + c`가 같습니다(우상–좌하 방향). 체스의 비숍이나 퀸이 서로 공격하는지 검사할 때 이 값을 비교합니다.
- 장애물이 없을 때 한 칸에서 다른 칸까지 최소 이동 횟수는 방향 수에 따라 다릅니다.

| 허용 이동 | 거리 | 이름 |
|-----------|------|------|
| 상하좌우 | `Math.abs(dr) + Math.abs(dc)` | 맨해튼 거리 |
| 8방향 | `Math.max(Math.abs(dr), Math.abs(dc))` | 체비쇼프 거리 |

- 장애물이 있으면 이 공식이 맞지 않으므로 BFS로 구합니다(자세히는 38편).
- 체스의 나이트는 `(±1, ±2)`와 `(±2, ±1)`의 8가지로 한 번에 뜁니다. 같은 방식으로 방향 배열만 바꿔 처리합니다.

## 방향 배열

방향별 변화량을 배열 두 개로 모아 두고 인덱스 `d`로 방향을 고르는 방식이 방향 배열입니다. 방향마다 `if`를 쓰지 않고 반복문 하나로 모든 이웃을 처리합니다.

```js
const dr = [-1, 0, 1, 0] // 상 우 하 좌
const dc = [0, 1, 0, -1]
for (let d = 0; d < 4; d++) {
  const nr = r + dr[d]
  const nc = c + dc[d]
  // (nr, nc)가 d 방향 이웃
}
```

8방향은 배열 길이를 8로 늘립니다.

```js
const dr8 = [-1, -1, -1, 0, 0, 1, 1, 1]
const dc8 = [-1, 0, 1, -1, 1, -1, 0, 1]
// (0, 0)인 쌍은 넣지 않는다
```

- 두 배열은 같은 인덱스끼리 한 쌍입니다. 위 순서(상, 우, 하, 좌)는 시계 방향입니다.
- 시계 방향으로 놓으면 인덱스 연산으로 방향을 바꿀 수 있습니다. 오른쪽으로 90도는 `(d + 1) % 4`, 왼쪽으로 90도는 `(d + 3) % 4`, 반대 방향은 `(d + 2) % 4`입니다. 왼쪽 회전에 `d - 1`을 쓰면 `d`가 0일 때 `-1`이 되어 `dr[-1]`이 `undefined`가 됩니다. `+ 3`으로 음수를 피합니다(자세히는 18편).
- 명령 문자를 방향으로 바꾸는 표를 따로 둘 수 있습니다.

```js
const dir = { U: 0, R: 1, D: 2, L: 3 }
const d = dir['R']        // 1
const nr = r + dr[d], nc = c + dc[d]
```

- 문제에 따라 방향 번호가 `0 = 북, 1 = 동, 2 = 남, 3 = 서`로 정해져 있기도 합니다. 문제의 번호에 맞춰 배열 순서를 정하면 변환 표가 필요 없습니다.

**흔한 실수:**

- `dr`과 `dc`의 순서가 서로 어긋나는 것입니다. 한 배열만 순서를 바꾸면 이동이 엉뚱한 방향으로 갑니다.
- 8방향에 `(0, 0)`을 넣으면 제자리 칸을 이웃으로 셉니다.
- 방향 반복 안에서 `r`, `c` 자체를 갱신하는 것입니다. 이웃은 `nr`, `nc`라는 새 변수로 계산합니다.

## 범위 검사

이웃 좌표가 격자 안에 있는지 확인하는 것이 범위 검사입니다. 행은 `0 <= nr < H`, 열은 `0 <= nc < W`입니다. 행은 `H`로, 열은 `W`로 비교합니다.

```js
function inRange(nr, nc) {
  return nr >= 0 && nr < H && nc >= 0 && nc < W
}
for (let d = 0; d < 4; d++) {
  const nr = r + dr[d], nc = c + dc[d]
  if (!inRange(nr, nc)) continue
  // 안전하게 grid[nr][nc] 사용
}
```

범위를 벗어난 칸을 읽으면 결과가 조용히 틀리거나 에러가 납니다.

| 접근 | 결과 |
|------|------|
| `grid[nr][nc]`에서 행만 범위 안, 열이 밖 | `undefined` (에러 없음) |
| 행이 밖(`-1` 또는 `H`) | `grid[nr]`이 `undefined`라서 `grid[nr][nc]`는 TypeError |
| 범위 밖 칸에 쓰기, 행이 안 | 행 배열이 늘어나서 열이 어긋남 (에러 없음) |

- 열이 밖일 때 에러가 나지 않는 점이 위험합니다. `grid[nr][nc] === '#'`가 `false`가 되어 "벽이 아님"으로 처리되고 틀린 답이 나옵니다.
- 옵셔널 체이닝 `grid[nr]?.[nc]`는 행이 밖이어도 `undefined`를 줍니다. 칸 값으로 `undefined`가 나올 수 없는 격자에서만 범위 검사를 대신할 수 있고, 값이 아니라 위치를 계산해야 하는 쪽에서는 명시적인 검사가 안전합니다.
- 조건은 `&&`로 이어서 행을 먼저 검사합니다. 행이 밖이면 뒤의 `grid[nr][nc]`를 평가하지 않아야 합니다.
- 정사각형이 아닌 격자에서 `H`와 `W`를 바꿔 쓰는 실수가 많습니다. 정사각형 예제로만 시험하면 드러나지 않습니다.

## 격자 순회

격자의 모든 칸을 방문하는 기본 형태는 행 우선 이중 반복문입니다. 바깥이 행, 안쪽이 열이라서 `(0,0), (0,1), …, (1,0), …` 순서로 읽습니다.

```js
let count = 0
for (let r = 0; r < H; r++) {
  for (let c = 0; c < W; c++) {
    if (grid[r][c] === '#') count++
  }
}
```

- 행·열의 인덱스가 필요 없으면 `for...of`로 씁니다.

```js
for (const row of grid) {
  for (const cell of row) {
    // cell은 칸의 값
  }
}
```

- 열 우선(위에서 아래로 한 열씩)은 두 반복문의 순서를 바꿉니다. 바깥이 `c`, 안쪽이 `r`입니다.
- 역순은 `for (let r = H - 1; r >= 0; r--)`처럼 쓰고, 중력이 작용하는 문제(아래에서 위로 채우기)에서 쓰입니다.
- 모든 칸을 보는 반복은 한 번에 O(HW)입니다. 칸마다 4방향 이웃을 보면 O(4HW)이며 상수는 복잡도에 영향을 주지 않습니다(자세히는 13편).
- 대각선 줄을 따라 순회하려면 같은 `r + c` 또는 같은 `r - c` 값을 가진 칸을 모읍니다.

```js
const diag = new Map() // r + c가 같은 칸끼리 묶기
for (let r = 0; r < H; r++) {
  for (let c = 0; c < W; c++) {
    if (!diag.has(r + c)) diag.set(r + c, [])
    diag.get(r + c).push(grid[r][c])
  }
}
```

격자 문제의 단서는 "N × M 크기의 판", "상하좌우로 인접한", "칸"이라는 표현입니다. 모든 칸을 한 번씩 보는 문제는 이중 반복문이고, 연결된 칸을 따라가는 문제는 DFS·BFS입니다(자세히는 36편, 38편).

**흔한 실수:** 안쪽 반복문의 상한을 `H`로 쓰는 것입니다. 안쪽은 열이므로 `W`입니다. 정사각형에서는 우연히 통과합니다.

## 격자 방문 처리

같은 칸을 두 번 처리하지 않으려고 방문 여부를 표시하는 배열이 `visited`입니다. 격자와 같은 크기의 2차원 불리언 배열을 씁니다.

```js
const visited = Array.from(
  { length: H },
  () => Array(W).fill(false),
)
visited[r][c] = true
if (visited[nr][nc]) continue // 이미 방문한 칸
```

방문 표시의 방식은 세 가지입니다.

| 방식 | 장점 | 주의 |
|------|------|------|
| 별도 `visited` 배열 | 원본이 그대로 | 메모리가 칸 수만큼 더 듦 |
| 원본 격자 수정(`grid[r][c] = '#'`) | 배열이 하나 | 원래 값을 잃음. 같은 격자를 다시 써야 하면 불가 |
| 거리 배열을 `-1`로 초기화하고 `-1`이면 미방문 | 방문과 거리를 함께 기록 | 초기값을 `-1`로 채우는 것을 잊으면 `0`이 방문으로 오해됨 |

- 방문 배열은 테스트 케이스마다 새로 만듭니다. 이전 케이스의 값이 남으면 틀립니다(자세히는 08편).
- 칸 수가 많으면 `new Uint8Array(H * W)`처럼 1차원 TypedArray가 메모리를 적게 씁니다(자세히는 05편, 아래 "좌표를 정수 하나로 바꾸기").
- 탐색 중 방문 표시를 언제 하는지(큐에 넣을 때인지 꺼낼 때인지)는 탐색 알고리즘의 규칙입니다(자세히는 36편, 38편).

**흔한 실수:** `visited`를 `Array(H).fill(Array(W).fill(false))`로 만드는 것입니다. 한 칸을 방문 처리하면 같은 열의 모든 행이 방문으로 바뀝니다.

## 격자 시뮬레이션

격자 시뮬레이션은 규칙에 따라 칸의 상태를 단계마다 바꾸며 K단계 뒤의 모습을 구하는 유형입니다. 핵심 규칙은 한 단계의 모든 변화가 같은 시각에 일어난다는 점입니다. 그러므로 현재 격자를 읽으면서 같은 격자를 수정하면 안 되고, 다음 격자를 따로 만들어 거기에 씁니다.

직접 만든 문제입니다. `#`는 켜진 칸이고, 1초마다 켜진 칸의 상하좌우 이웃이 켜집니다. 1초 뒤 격자를 구합니다. `dr`, `dc`는 앞에서 만든 상 우 하 좌 방향 배열입니다.

```js
function step(grid) {
  const H = grid.length, W = grid[0].length
  const next = grid.map((row) => [...row]) // 복사
  for (let r = 0; r < H; r++) {
    for (let c = 0; c < W; c++) {
      if (grid[r][c] !== '#') continue     // 읽기는 현재 격자
      for (let d = 0; d < 4; d++) {
        const nr = r + dr[d], nc = c + dc[d]
        if (nr < 0 || nr >= H || nc < 0 || nc >= W) continue
        next[nr][nc] = '#'                 // 쓰기는 다음 격자
      }
    }
  }
  return next
}
```

작은 입력을 추적하면 다음과 같습니다.

| 시각 | 격자 (행을 `/`로 구분) |
|------|-------------------------|
| 0초 | `.../.#./...` |
| 1초 | `.#./###/.#.` |
| 2초 | `###/###/###` |

- 읽기는 현재 격자, 쓰기는 다음 격자로 나누는 이유는 같은 단계에서 새로 켜진 칸이 또 이웃을 켜는 연쇄를 막기 위해서입니다.
- 규칙이 "이웃 칸의 값을 세어 결정"하는 형태라면 칸마다 이웃을 세는 방식으로 `next[r][c]`를 정하고, 규칙이 "이 칸이 이웃에 영향을 준다"는 형태라면 위 코드처럼 퍼뜨립니다.
- 단계 수 K가 크면 O(K · H · W)가 너무 커질 수 있습니다. 상태가 반복되는지(주기) 확인하거나 다른 알고리즘이 필요한지 제한 조건으로 판단합니다(자세히는 14편, 18편).
- 로봇이 한 칸씩 움직이는 시뮬레이션처럼 격자 전체가 아니라 객체 하나의 상태가 변하는 유형은 18편에서 다룹니다.

**흔한 실수:** 현재 격자를 읽으면서 그 격자에 바로 쓰는 것입니다. 위 문제를 제자리에서 처리하면 순회 순서상 뒤에 있는 칸이 같은 단계에서 이미 켜진 칸으로 보여서 한 단계에 여러 칸이 퍼집니다.

## 좌표를 정수 하나로 바꾸기

`(r, c)`를 정수 하나 `id = r * W + c`로 바꾸면 좌표를 다루기 쉬워집니다. 행 길이인 `W`를 곱한다는 점이 핵심입니다. 되돌릴 때는 몫과 나머지를 씁니다.

```js
const W = 4
const id = 2 * W + 1             // (2, 1) -> 9
const r = Math.floor(id / W)     // 2
const c = id % W                 // 1
```

| `(r, c)` | `id` (W = 4) |
|----------|--------------|
| (0, 0) | 0 |
| (0, 3) | 3 |
| (1, 0) | 4 |
| (2, 1) | 9 |

- `id`는 행 우선 순서로 칸에 붙인 번호입니다. 격자를 한 줄로 펼친 1차원 배열의 인덱스와 같아서 `flat[id]`로 읽을 수 있습니다.
- `Set`이나 `Map`의 키로 `id`를 쓰면 문자열 `` `${r},${c}` ``를 만들지 않아도 됩니다. `visited[id]`처럼 1차원 배열 하나로 방문을 기록할 수 있습니다.
- 큐에 `[r, c]` 배열 대신 숫자 하나를 넣으면 객체를 만드는 부담이 줄어듭니다(자세히는 38편).
- 이웃의 `id`는 위아래가 `id - W`, `id + W`이고 좌우가 `id - 1`, `id + 1`입니다. 위아래는 `0 <= nid < H * W`로 범위를 검사합니다. 좌우는 그것만으로는 부족합니다. `id + 1`이 다음 행의 첫 칸으로 넘어갈 수 있어서 `c`를 구해 `c + 1 < W`인지 따로 검사해야 합니다.

```js
const flat = new Uint8Array(H * W)
const at = (r, c) => flat[r * W + c]
flat[2 * W + 1] = 1
at(2, 1) // 1
```

- 나눗셈으로 `r`을 복원할 때 `id`는 0 이상의 정수여야 합니다. 음수 `id`에는 `Math.floor`와 `%`의 결과가 서로 어긋납니다(자세히는 02편).
- `id`의 최댓값은 `H * W - 1`입니다. 이 값이 32비트 정수 범위 안이면 `Int32Array`에 담을 수 있습니다.

**흔한 실수:** `r * H + c`로 쓰는 것입니다. 곱하는 수는 열 수 `W`입니다. 정사각형이면 같아서 놓치기 쉽습니다. `H = 3, W = 4`에서 `(2, 3)`은 `11`이어야 하는데 `r * H + c`로 계산하면 `9`가 되어 `(2, 1)`과 겹칩니다.

## 테두리 패딩으로 범위 검사 줄이기

격자 바깥에 한 칸 두께의 테두리를 덧대 `(H + 2) × (W + 2)` 격자를 만드는 방법이 테두리 패딩(padding)입니다. 테두리에는 "이동할 수 없는 값"을 넣어 두면 이웃을 읽을 때 격자 밖으로 나가는 일이 없어서 범위 검사를 생략할 수 있습니다.

```js
const WALL = '#'
const pad = Array.from({ length: H + 2 }, () =>
  Array(W + 2).fill(WALL),
)
for (let r = 0; r < H; r++) {
  for (let c = 0; c < W; c++) {
    pad[r + 1][c + 1] = grid[r][c] // 한 칸씩 안쪽으로
  }
}
```

원래 칸은 `1 ≤ r ≤ H`, `1 ≤ c ≤ W`에 놓입니다. 이 안에서 4방향 또는 8방향 이웃은 항상 `0 ≤ r ≤ H + 1`, `0 ≤ c ≤ W + 1` 안에 있으므로 `pad[nr][nc]`가 에러 없이 읽힙니다.

```js
for (let r = 1; r <= H; r++) {
  for (let c = 1; c <= W; c++) {
    for (let d = 0; d < 4; d++) {
      if (pad[r + dr[d]][c + dc[d]] === WALL) continue
      // 칸 안쪽 이웃만 남음
    }
  }
}
```

- 테두리 값이 원래 칸의 값과 구분되어야 합니다. 벽과 길이 나뉜 문제라면 벽 표시를 그대로 테두리에 쓰고, 칸 값이 숫자 전체인 문제라면 `-1`이나 `Infinity`처럼 나올 수 없는 값을 고릅니다.
- 이동할 수 없는 칸으로 검사하는 문제에서 가장 잘 맞습니다. 벽 검사 하나가 범위 검사를 겸합니다.
- 인덱스가 1씩 밀리므로 입력은 `[r + 1][c + 1]`에 넣고, 답을 낼 때는 1을 뺍니다. 1부터 세는 문제 좌표를 쓴다면 오히려 변환 없이 그대로 쓸 수 있습니다.
- 테두리를 넘는 것이 의미 있는 문제(격자 밖으로 나가면 탈출, 종료)에서는 쓰지 않습니다. 테두리 칸에 닿았는지로 탈출을 판정하는 식으로 바꿀 수는 있습니다.
- 메모리는 `(H + 2)(W + 2)`로 약간 늘어납니다. 격자가 크면 1차원 `Uint8Array`에 같은 방식으로 패딩할 수 있습니다.

## 핵심 정리

- `grid[r][c]`의 첫 인덱스는 행, 둘째는 열이고, 위로 가면 r이 줄어듭니다. 행 수는 `H`, 열 수는 `W`이며 서로 바꿔 쓰면 정사각형이 아닐 때 틀립니다.
- 방향은 `dr`, `dc` 배열로 두고 반복문으로 이웃을 계산합니다. 시계 방향으로 놓으면 `(d + 1) % 4`, `(d + 3) % 4`로 회전합니다.
- 이웃은 읽기 전에 `0 <= nr < H`, `0 <= nc < W`를 검사하고, 행을 먼저 봅니다. 열이 밖이면 에러 없이 `undefined`가 나와 조용히 틀립니다.
- 방문 배열과 새 격자는 행마다 독립된 배열로 만들고, 단계별 갱신은 현재 격자를 읽어 다음 격자에 씁니다.
- `id = r * W + c`로 좌표를 숫자 하나로 바꿀 수 있고, 테두리 한 칸을 덧대면 범위 검사를 벽 검사로 대신할 수 있습니다.
