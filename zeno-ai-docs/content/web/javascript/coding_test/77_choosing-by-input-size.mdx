## 상한에서 후보를 좁히는 순서

입력 크기 상한 N은 문제를 읽자마자 얻는 가장 빠른 단서입니다. 풀이를 떠올리기 전에 상한부터 보면 가능한 복잡도의 천장이 정해지고, 그 천장 아래에 들어오는 알고리즘만 후보로 남습니다.

- 어림 기준은 14편과 같이 "1초에 단순 연산 약 10^8번"입니다. 채점 환경의 실제 처리량은 공식 자료로 확인하지 못했으므로 판정 기준이 아니라 감각용 가정입니다.
- 순서는 세 단계입니다. 상한을 읽는다, 떠오른 후보의 복잡도에 상한을 대입한다, 10^8과 비교한다.
- 상한은 후보를 거르는 데만 쓰고 정답을 보장하지 않습니다. 같은 N이라도 허용 복잡도 안에 드는 알고리즘이 여럿이면 문제 문장의 단서(78편)로 하나를 고릅니다.

| N 상한 | 연산 수가 맞는 복잡도 | 떠올릴 후보 |
|--------|----------------------|-------------|
| 10 이하 | O(N!) | 순열 전수 탐색 |
| 20 이하 | O(2^N × N) | 부분집합 완전탐색, 비트마스크 |
| 40 이하 | O(2^(N/2) × N) | Meet In The Middle |
| 500 이하 | O(N³) | 삼중 반복문, Floyd-Warshall |
| 1000 – 5000 | O(N²) | 이중 반복문, 2차원 DP |
| 10^5 – 2 × 10^5 | O(N log N) | 정렬, 이분 탐색, 힙, 세그먼트 트리 |
| 10^6 이상 | O(N), O(log N) | 한 번 훑기, 누적합, 투 포인터, 공식 |

- 14편의 표가 "이 상한에서 허용되는 복잡도"라면, 이 표는 거꾸로 "그 복잡도에서 나오는 알고리즘"입니다.
- 위 수치는 경계가 아니라 구간입니다. 상수가 큰 코드(안쪽에 `Map`, 정렬, 문자열 연산)는 한 단계 보수적으로 봅니다.

## N ≤ 10: O(N!) 순열 탐색

N이 10 이하이면 모든 순열을 만들어 보는 풀이가 가능합니다. N!을 대입해 봅니다.

| N | N! |
|---|----|
| 8 | 40320 |
| 10 | 3628800 |
| 11 | 39916800 |
| 12 | 479001600 |

- 10!은 약 3.6 × 10^6이라 순열마다 O(N)을 검사해도 4 × 10^7 안팎입니다. 12!부터는 10^8을 넘기 시작해서 순열 탐색이 위험합니다.
- 순서가 결과에 영향을 주는 문제(배치, 방문 순서, 작업 순서)가 N ≤ 10이면 순열 전수 탐색을 먼저 의심합니다.
- 구현은 방문 배열을 쓰는 재귀입니다(자세히는 23편).

```js
function permute(n, visit) {
  const used = new Array(n).fill(false)
  const pick = []
  const dfs = () => {
    if (pick.length === n) return visit(pick)
    for (let i = 0; i < n; i++) {
      if (used[i]) continue
      used[i] = true; pick.push(i)
      dfs()
      pick.pop(); used[i] = false
    }
  }
  dfs()
}
```

- `visit`가 N! 번 호출됩니다. 같은 원소가 있으면 서로 다른 순열만 세도록 중복 처리를 따로 해야 합니다.
- 가지치기(조건에 어긋나면 그 가지를 버림)를 넣으면 실제 탐색량은 N!보다 훨씬 줄 수 있습니다. 다만 상한 판단은 가지치기 없는 최악 기준으로 합니다.

## N ≤ 20: 완전탐색과 비트마스크 의심

N이 20 이하이면 모든 부분집합(2^N 가지)을 보는 풀이를 의심합니다. 2^20은 1,048,576이고, 부분집합마다 O(N)으로 검사해도 약 2 × 10^7입니다.

- "각 원소를 고르거나 고르지 않는다"는 구조이면 부분집합입니다. N ≤ 20은 이 구조에 대한 대표적인 신호입니다.
- 부분집합을 N비트 정수 하나로 표현하는 것이 비트마스크입니다. `mask`의 i번째 비트가 1이면 i번째 원소를 고른 것입니다(자세히는 24편).

```js
let best = 0
for (let mask = 0; mask < (1 << n); mask++) {
  let sum = 0
  for (let i = 0; i < n; i++) {
    if (mask & (1 << i)) sum += a[i]
  }
  if (sum <= limit && sum > best) best = sum
}
// limit 이하인 부분집합 합의 최댓값
```

- `1 << n`은 32비트 정수 연산이라 n이 30 이하일 때만 안전합니다. `1 << 31`은 음수 −2147483648이고, 시프트 양은 32로 나눈 나머지만 쓰이므로 `1 << 32`는 1입니다. N ≤ 20 문제에서는 문제가 되지 않습니다.
- 재귀로 포함·미포함을 나누는 방식도 같은 2^N입니다. 순열은 N!, 부분집합은 2^N이라서 N ≤ 10이면 순열이, N ≤ 20이면 부분집합만 가능합니다.
- 최적 경로나 상태 압축 DP로 가면 2^N × N 또는 2^N × N²가 됩니다(아래 "상태 수가 작은 문제").

**흔한 실수:** N ≤ 20이라서 N!으로 접근하는 것입니다. 20!은 약 2.4 × 10^18입니다. 순서를 구분하는지 선택만 하는지를 먼저 확인합니다.

## N ≤ 40: Meet In The Middle 의심

N이 40 안팎이면 2^N은 불가능한데(2^40 ≈ 1.1 × 10^12) N ≤ 20 풀이는 통하지 않는 어중간한 구간입니다. 입력을 절반씩 둘로 나눠 각각 완전탐색하고 결과를 합치는 Meet In The Middle(MITM)을 의심합니다.

- 반쪽의 경우의 수는 2^20 ≈ 10^6입니다. 두 반쪽을 따로 열거한 뒤 합치는 단계를 정렬·해시·이분 탐색으로 처리하면 전체가 약 2^(N/2) × N입니다.
- 신호는 N이 30–40이고, 선택·미선택 구조이며, 값의 범위가 커서 DP로 풀 수 없는 경우입니다(배낭 용량이 10^9 등).
- 원리와 합치는 방법은 72편에서 다룹니다.

```js
function sums(arr) {            // 모든 부분집합 합 (2^k개)
  let list = [0]
  for (const x of arr) {
    list = list.concat(list.map((s) => s + x))
  }
  return list
}
const half = n >> 1
const rightSet = new Set(sums(a.slice(half)))
const found = sums(a.slice(0, half))
  .some((s) => rightSet.has(target - s))
// 합이 정확히 target인 부분집합이 있는가
```

- 왼쪽 합 s마다 오른쪽에 `target - s`가 있는지 찾습니다. 전체 2^(N/2)번의 조회입니다.
- 합이 Number 안전 범위(약 9.0 × 10^15)를 넘을 수 있으면 BigInt가 필요합니다(02편).
- "이하인 부분집합 개수"처럼 조건이 부등호이면 한쪽을 정렬한 뒤 이분 탐색으로 개수를 셉니다.

## N ≤ 500: O(N³)

N이 500 이하이면 삼중 반복문이 가능합니다. 500³ = 1.25 × 10^8이라서 10^8 감각의 한계선이고, 안쪽 연산이 단순해야 합니다.

- 가장 대표적인 후보는 모든 쌍의 최단거리를 구하는 Floyd-Warshall입니다(자세히는 49편). 정점 수 N ≤ 500이라는 상한이 그 신호입니다.
- 행렬 곱셈, 3중 DP(구간 DP의 분할점 선택 등)도 O(N³)입니다(자세히는 73편).

```js
for (let k = 0; k < n; k++) {
  for (let i = 0; i < n; i++) {
    for (let j = 0; j < n; j++) {
      const via = dist[i][k] + dist[k][j]
      if (via < dist[i][j]) dist[i][j] = via
    }
  }
}
```

- N이 400이면 6.4 × 10^7로 여유가 있고, 1000이면 10^9라서 불가능합니다. 상한이 500 근처이면 반복문 안쪽을 줄이는 방법(가능한 구간만 돌기)을 같이 고려합니다.
- N ≤ 500에서 정점이 아닌 간선 수가 큰 그래프(N² 근처)는 인접 행렬로 둡니다(자세히는 35편).

## N ≤ 1000: O(N²) 가능성

N이 1000 이하이면 이중 반복문이 가능합니다. N²은 10^6이고, N이 5000이어도 2.5 × 10^7이라서 여유가 있습니다.

| 상한 | N² | 판정 |
|------|-----|------|
| 1000 | 10^6 | 여유 |
| 5000 | 2.5 × 10^7 | 여유 |
| 10000 | 10^8 | 한계선 |
| 10^5 | 10^10 | 불가 |

- 모든 쌍을 비교하는 완전탐색, N × N 2차원 DP(41편, 42편), 모든 정점 쌍 처리, 인접 행렬 기반 풀이가 해당합니다.
- N ≤ 1000이라는 숫자는 의도적으로 O(N²)을 허용하는 상한인 경우가 많습니다. O(N log N)이 따로 있어도 O(N²)이 정답으로 의도된 것일 수 있어서, 복잡한 풀이를 찾기 전에 이중 반복문으로 충분한지 계산합니다.
- 상한이 10^4이면 한계선이므로 안쪽 연산이 가벼운지 봅니다. 안쪽에 `Map`·`sort`가 있으면 불가로 봅니다.
- N × N 2차원 배열의 메모리도 계산합니다. 5000 × 5000은 2.5 × 10^7칸이라서 `Int32Array`로도 100MB입니다(자세히는 14편).

**흔한 실수:** N²을 계산하지 않고 "이중 반복문은 느리다"고 단정하는 것입니다. 느리다는 판단은 상한을 대입한 결과여야 합니다.

## N ≤ 10^5: O(N log N) 우선 검토

N이 10^5 안팎(2 × 10^5까지)이면 O(N²)은 불가능합니다(10^10). O(N log N)이나 O(N)을 먼저 찾습니다. N log N은 10^5 × 17 ≈ 1.7 × 10^6이라 여유가 큽니다.

- 이 상한에서 나오는 O(N log N) 도구는 다음과 같습니다.

| 도구 | 쓰임 | 편 |
|------|------|-----|
| 정렬 | 정렬 후 인접 비교, 정렬 후 투 포인터·그리디 | 26편 |
| 이분 탐색 | 정렬된 배열 탐색, 답을 이분 탐색 | 28편 |
| 힙·우선순위 큐 | 최솟값 반복 추출, Dijkstra | 46편, 47편 |
| 세그먼트 트리·펜윅 트리 | 구간 질의와 갱신 | 62편, 64편 |
| 해시 | 평균 O(1) 조회로 N번 | 10편 |

- N × N의 이중 반복문을 쓰고 있다면 안쪽 반복을 "정렬한 뒤 이분 탐색" 또는 "해시 조회"로 바꿀 수 있는지 먼저 봅니다.
- O(N √N)도 10^5 × 316 ≈ 3 × 10^7이라서 허용됩니다. 제곱근 분할 같은 풀이가 이 상한에서 의도되는 경우가 있습니다.
- 상수가 큰 O(N log N)(정렬 기준으로 객체 비교, 안쪽 `Map` 조작)은 10^5에서도 느릴 수 있으니 한 단계 보수적으로 봅니다.

## N ≥ 10^6: O(N)과 O(log N) 검토

N이 10^6 이상이면 입력을 한 번 읽는 것도 비용입니다. O(N)이나 O(N log N)에 상수가 작은 풀이를 찾고, N이 10^9 이상이면 입력을 훑을 수 없으니 O(log N)이나 공식을 찾습니다.

| N 상한 | 가능한 복잡도 | 대표 풀이 |
|--------|---------------|-----------|
| 10^6 | O(N log N)까지(상수 작게) | 정렬 한 번, 누적합 |
| 10^7 | O(N) | 한 번 훑기, 투 포인터, 슬라이딩 윈도우, 에라토스테네스의 체 |
| 10^9 이상 | O(log N), O(1) | 이분 탐색, 빠른 거듭제곱, 수학 공식 |

- O(N)이 요구되는 구조는 순서를 가진 배열에서의 "누적하며 한 번 훑기"입니다. 누적합(29편), 투 포인터(30편), 슬라이딩 윈도우(31편), Monotonic Stack(32편)이 모두 반복 한 번으로 끝나서 분할 상환 O(N)입니다.
- N이 10^9 이상이면 값 자체가 입력입니다. 값의 크기에 대해 로그 시간인 풀이(이분 탐색, 거듭제곱 분할)나 닫힌 식을 찾습니다. 10^18이면 Number 안전 범위를 넘으므로 BigInt를 씁니다(02편).
- 입출력도 병목이 됩니다. 10^6줄을 읽고 쓸 때는 한 번에 읽고 `join`으로 모아 한 번에 출력합니다(자세히는 08편).
- 메모리도 상한이 됩니다. 10^7개의 `Int32Array`는 40MB, 일반 배열은 그보다 큽니다(자세히는 14편).

**흔한 실수:** N ≤ 10^6에서 O(N log N)이 된다는 이유로 객체 배열을 정렬하는 것입니다. 비교 함수 호출 비용이 커서 숫자 배열보다 훨씬 느립니다(자세히는 86편).

## 상태 수가 작은 문제는 Bitmask

문제의 상태를 "무엇을 이미 골랐는가"로 표현할 수 있고 대상이 20개 안팎이면, 상태를 비트마스크로 줄여 DP의 인덱스로 씁니다. 상태 수가 2^N으로 정해지기 때문입니다.

- 신호는 세 가지입니다. 대상이 N ≤ 20 안팎이고, 방문·사용 여부 같은 집합이 상태에 들어가며, 단순 완전탐색이 N!이라 불가능한 경우입니다.
- 예는 모든 도시를 한 번씩 방문하는 최소 비용(외판원 문제), 작업 배정, 집합 덮기입니다.
- 순열 N!을 부분집합 2^N으로 줄이는 것이 핵심입니다. 순서 대신 "어디까지 방문했는가"만 상태로 기억합니다.

| N | N! | 2^N × N² |
|---|-----|----------|
| 10 | 약 3.6 × 10^6 | 약 10^5 |
| 16 | 약 2.1 × 10^13 | 약 1.7 × 10^7 |
| 20 | 약 2.4 × 10^18 | 약 4.2 × 10^8 |

- 상태가 `dp[mask][last]`이면 상태 수가 2^N × N, 전이가 N이라서 시간은 2^N × N²입니다. N = 20은 한계선을 넘으므로 N ≤ 16–18이 현실적입니다.
- 메모리는 상태 수 × 값 크기입니다. 2^20 × 20개의 `Int32Array`는 약 80MB입니다.
- 구현과 비트 연산은 24편, 비트마스크 DP는 73편에서 다룹니다.

## 질의 수 Q와 값의 범위를 함께 보기

입력 크기는 N 하나가 아닙니다. 질의 수 Q, 값의 범위 V(원소가 가질 수 있는 최댓값)가 있으면 각각 대입해서 본 뒤 가장 비싼 것을 기준으로 삼습니다.

### 질의 수 Q

질의마다 O(N)이면 전체는 O(N × Q)입니다. N과 Q가 모두 10^5이면 10^10이라서 불가능합니다. 전처리를 한 번 하고 질의를 O(1) 또는 O(log N)으로 줄입니다.

```js
// ❌ 질의마다 훑기: O(N × Q)
const slow = (l, r) => {
  let s = 0
  for (let i = l; i <= r; i++) s += a[i]
  return s
}
// ✅ 누적합으로 전처리 O(N), 질의 O(1)
const pre = new Array(n + 1).fill(0)
for (let i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i]
const fast = (l, r) => pre[r + 1] - pre[l]
```

| 질의 | 갱신 | 후보 |
|------|------|------|
| 구간 합·개수 | 없음 | 누적합 |
| 구간 합·최솟값 | 있음 | 세그먼트 트리, 펜윅 트리 |
| 정렬된 값 조회 | 없음 | 이분 탐색 |
| 같은 값 개수 | 있음 | 해시 |

- 갱신(수정)이 끼면 누적합이 깨지므로 O(log N) 자료구조(62편, 64편)로 올라갑니다.
- 총 시간은 전처리 + Q × 질의 비용입니다. (N + Q) log N ≈ 2 × 10^5 × 17 ≈ 3.4 × 10^6입니다.

### 값의 범위 V

값의 범위는 값을 배열의 인덱스로 쓸 수 있는지, 합과 곱이 안전 범위를 넘는지를 결정합니다.

| V의 크기 | 쓸 수 있는 것 |
|----------|---------------|
| 10^6 이하 | 값을 인덱스로 하는 배열(빈도수 배열, 체), 값에 대한 DP |
| 10^9 | 배열 인덱스로 불가. 해시(`Map`)나 좌표 압축(54편) |
| 10^18 | Number 안전 범위 초과. BigInt |

- 배낭 문제는 DP 크기가 N × (용량)입니다. 용량이 10^5이면 가능하지만 10^9이면 불가능합니다. 이때 N이 40이면 MITM으로 갑니다. 값이 아니라 개수로 상한이 주어지는 경우를 구분합니다.
- 합이 안전 범위를 넘는지는 최댓값 × 개수로 계산합니다. 10^9 × 10^5 = 10^14는 안전하지만 10^9 × 10^7 = 10^16은 `Number.MAX_SAFE_INTEGER`(9007199254740991, 약 9.0 × 10^15)를 넘습니다. 넘으면 BigInt나 나머지 연산이 필요합니다(02편, 57편).
- 값의 범위가 작으면(예: 0–100) N이 커도 값의 종류가 적다는 구조를 쓸 수 있습니다. 빈도수 배열을 만들어 정렬 없이 O(N + V)로 처리합니다(자세히는 10편).

## 핵심 정리

- 입력 크기 상한을 대입해 허용 복잡도를 구하고(1초에 약 10^8 연산 가정), 그 안에 드는 알고리즘만 후보로 남깁니다.
- N ≤ 10이면 순열 전수 탐색(N!), N ≤ 20이면 부분집합 완전탐색·비트마스크(2^N), N ≤ 40이면 Meet In The Middle(2^(N/2))을 의심합니다.
- N ≤ 500은 O(N³)(Floyd-Warshall), N ≤ 1000–5000은 O(N²), N ≤ 10^5는 O(N log N), N ≥ 10^6은 O(N)이나 O(log N)입니다.
- 상태를 집합으로 표현할 수 있고 대상이 20개 안팎이면 N!을 2^N 상태의 비트마스크 DP로 줄입니다.
- 입력에 질의 수 Q와 값의 범위 V가 있으면 각각 대입해서 가장 비싼 항을 기준으로 삼고, V가 크면 배열 대신 해시·좌표 압축·BigInt를 검토합니다.
- 상한은 후보를 거르는 용도이고, 허용 구간 안의 알고리즘 중 하나를 고르는 일은 문제 문장의 단서(78편)로 합니다.
