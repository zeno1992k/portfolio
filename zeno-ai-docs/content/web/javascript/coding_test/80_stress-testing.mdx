## Brute Force 기준답 (Oracle)

기준답(oracle)은 정답을 확실히 내는 풀이입니다. 속도는 상관없습니다. 제출할 풀이가 맞는지 판정하는 심판 역할을 하며, 보통 완전탐색(16편)으로 만듭니다.

- 좋은 기준답은 풀이와 다른 방법으로, 가능한 한 단순하게 만듭니다. 같은 아이디어로 만들면 같은 곳에서 같이 틀려서 비교가 의미 없습니다.
- 복잡도는 신경 쓰지 않고 모든 경우를 열거합니다. 모든 부분 배열, 모든 부분집합, 모든 순열을 직접 확인하는 식입니다.
- 기준답이 틀리면 거짓 경보가 납니다. 작은 입력 몇 개는 손으로 계산해서 기준답이 맞는지 먼저 확인합니다.
- 기준답은 큰 입력에서 느려도 됩니다. 비교는 작은 입력에서만 하므로 O(N²)이나 O(N!)도 괜찮습니다.

```js
// 최대 부분 배열 합의 기준답: 모든 구간을 직접 더한다
const oracle = (a) => {
  let best = a[0]
  for (let i = 0; i < a.length; i++) {
    let s = 0
    for (let j = i; j < a.length; j++) {
      s += a[j]
      if (s > best) best = s
    }
  }
  return best
}
```

- 제출용 풀이(Kadane 등 O(N))와 이 기준답이 모든 입력에서 같은 값을 내면 풀이가 맞다고 믿을 수 있습니다. 모든 입력을 시험할 수는 없어서 증명은 아니지만, 반례를 찾는 데는 가장 효과적입니다.

## 작은 입력 완전탐색과 정답 비교 (Naive Solution)

작은 입력에서 기준답과 제출용 풀이의 답을 비교하는 것이 스트레스 테스트의 핵심입니다. 기준답이 O(2^N)이어도 N이 8 이하이면 순식간에 끝납니다(77편).

- 틀린 풀이의 반례는 대부분 작은 입력에도 있습니다. 원소가 5개 이하, 값이 −5 이상 5 이하 같은 작은 범위에서도 중복값·음수·경계가 모두 나타납니다. 작은 입력이 좋은 이유는 한 번에 많이 돌릴 수 있고, 틀렸을 때 사람이 읽고 원인을 추적할 수 있기 때문입니다.
- 비교 방식은 결과의 형태에 따라 다릅니다.

| 결과 | 비교 방법 |
|------|----------|
| 숫자, 문자열 | `===` |
| 배열, 객체 | `JSON.stringify` 비교 또는 `assert.deepStrictEqual` |
| 정답이 여러 개 가능(경로, 순서) | 값 비교가 아니라 검사 함수로 유효성과 값(길이, 비용)을 확인 |

- 정답이 하나가 아닌 문제(아무 최단 경로를 출력, 가능한 순서 하나를 출력)는 두 풀이의 출력이 달라도 둘 다 맞을 수 있습니다. 출력이 규칙을 지키는지 확인하는 검사 함수를 따로 만들고, 비용처럼 유일한 값만 비교합니다.
- `assert.deepStrictEqual`은 Node.js `node:assert` 모듈의 함수입니다. 두 값이 깊이 같지 않으면 `AssertionError`를 던지고 차이를 보여 줍니다.
- 입력을 풀이에 넘기기 전에 복사합니다. 풀이가 입력 배열을 정렬하거나 수정하면 같은 입력을 기준답에 넘겼을 때 달라져 있습니다(`structuredClone`, 자세히는 01편).

## Random Test (랜덤 테스트 생성)

랜덤 테스트는 규칙에 맞는 입력을 난수로 만들어 풀이를 시험하는 것입니다. 사람이 떠올린 경계 입력(79편)이 놓치는 조합을 기계가 만들어 줍니다.

- 입력은 문제의 제약 안에서 만듭니다. 제약을 벗어난 입력(범위 밖 값, 연결되지 않은 그래프를 연결이라 약속한 문제에 주는 것)은 풀이를 틀리게 만들지만 버그가 아닙니다.
- 크기와 값의 범위를 작게 잡습니다. 값의 범위를 좁히면 중복값, 같은 합, 동점 같은 흔한 경계가 자주 나옵니다. 값이 10^9까지 퍼지면 우연한 충돌이 거의 없어서 이런 경계가 안 나옵니다.
- 크기도 작은 것부터 늘립니다. N = 1, 2, 3에서 먼저 틀리면 가장 읽기 쉬운 반례가 나옵니다.
- 랜덤 테스트는 반례를 찾는 도구입니다. 오래 돌려도 반례가 없다고 맞다는 증명이 아니므로 경계 테스트(79편)와 함께 씁니다.
- 테스트 입력이 한쪽으로 치우치면 약합니다. 값의 범위 몇 가지(−5–5, 0–1, 1–100)와 크기 몇 가지로 나눠 돌려서 다양한 입력 분포를 만듭니다.

## 시드를 고정한 난수 생성기

스트레스 테스트가 틀린 입력을 찾으면 같은 입력을 다시 만들어야 디버깅할 수 있습니다. 시드(seed)로 시작 상태를 정하면 같은 시드가 같은 난수 수열을 만들어 입력을 재현할 수 있습니다.

- `Math.random()`은 [0, 1) 범위의 의사 난수를 주지만, 시드는 구현이 정하며 사용자가 고르거나 재설정할 수 없습니다(MDN). 그래서 재현이 필요한 테스트에는 직접 난수 생성기를 만듭니다.
- 아래는 xorshift32입니다. 32비트 상태 하나에 시프트와 XOR 세 번을 적용하는 아주 작은 생성기로, 주기가 2^32 − 1이고 상태가 0이면 안 됩니다. 통계적 품질이 약해서 보안이나 정밀 시뮬레이션에는 맞지 않지만, 테스트 입력을 만드는 데는 충분합니다.

```js
function makeRng(seed) {
  let x = (seed | 0) || 1     // 시드 0은 상태 0이라 1로 대체
  return () => {
    x ^= x << 13
    x ^= x >>> 17
    x ^= x << 5
    return (x >>> 0) / 4294967296   // [0, 1)
  }
}
const rng = makeRng(42)
rng()  // 같은 시드는 항상 같은 값 (매 실행 동일)
```

- `^`, `<<`는 32비트 정수 연산이라 곱셈이 안전 범위를 넘는 문제가 없습니다(자세히는 02편). 곱셈을 쓰는 선형 합동 생성기를 직접 만들면 곱이 2^53을 넘어 정확도를 잃기 쉬워서, 이 형태가 JavaScript에서 안전합니다.
- 범위를 정해 정수를 뽑는 함수를 함께 만듭니다. 양 끝을 포함하는 구간 [lo, hi]입니다.

```js
const randInt = (rng, lo, hi) =>
  lo + Math.floor(rng() * (hi - lo + 1))
randInt(rng, 1, 6)  // 1 이상 6 이하의 정수
```

- 생성기를 함수로 만들어 상태를 클로저에 가두면 테스트마다 독립된 수열을 쓸 수 있습니다. 시드는 반복 번호(1, 2, 3, …)를 그대로 쓰면 틀린 반복 번호가 곧 재현용 시드입니다.
- `Math.random`에는 시드를 넘기는 자리가 없으므로, 재현이 필요하면 이처럼 상태를 직접 가진 생성기를 따로 만듭니다.

## 배열 셔플 (Fisher-Yates)

무작위 순열이 필요할 때(입력 순서 섞기, 정점 번호 섞기) 쓰는 표준 방법이 Fisher-Yates 셔플입니다. 뒤에서부터 한 칸씩, 아직 섞지 않은 앞부분에서 무작위 원소를 골라 현재 칸과 바꿉니다. O(N)에 모든 순열이 같은 확률로 나옵니다.

```js
function shuffle(a, rng) {
  for (let i = a.length - 1; i > 0; i--) {
    const j = Math.floor(rng() * (i + 1))   // 0 이상 i 이하
    ;[a[i], a[j]] = [a[j], a[i]]
  }
  return a
}
shuffle([1, 2, 3, 4], makeRng(1))
```

- 핵심은 `j`의 범위가 `0`부터 `i`까지(현재 칸 포함)라는 점입니다. 이미 확정한 뒤쪽 칸은 건드리지 않습니다.
- 흔한 잘못된 방법 두 가지가 있습니다.

| 방법 | 문제 |
|------|------|
| 매번 `j`를 배열 전체에서 고름 | 경우의 수가 n^n이라 n!로 나누어떨어지지 않아 치우친다 |
| `sort(() => rng() - 0.5)` | 정렬 알고리즘에 따라 크게 치우치고 비교 함수의 일관성도 깨진다 |

- 원소 3개를 6만 번 섞어 보면 올바른 셔플은 여섯 순열이 각각 약 1만 번씩 나옵니다. 매번 전체에서 고르는 방법은 27가지 경우를 6개 순열에 나누므로 어떤 순열은 4번, 어떤 순열은 5번 나와서 약 8900번과 약 11100번으로 갈립니다. 랜덤 비교 함수 정렬은 더 심하게 치우칩니다.
- 시험 입력을 섞을 때 편향이 있으면 일부 입력이 거의 나오지 않아서 테스트가 약해집니다.
- 이 편의 시드 난수를 넘겨서 셔플하면 같은 시드에서 같은 순열이 나옵니다.

## 랜덤 배열·그래프·트리 생성

문제의 입력 구조에 맞춰 규칙을 지키는 랜덤 입력을 만드는 방법입니다.

### 배열

길이, 값의 범위를 정해 `randInt`로 채웁니다.

```js
const randomArray = (rng, n, lo, hi) =>
  Array.from({ length: n }, () => randInt(rng, lo, hi))
randomArray(makeRng(3), 5, -5, 5)
// 길이 5, 값은 -5 이상 5 이하
```

- 값이 서로 다른 배열(순열)이 필요하면 1부터 N까지를 만들어 셔플합니다.
- 정렬된 배열이 필요하면 만든 뒤 `sort((x, y) => x - y)`합니다(자세히는 26편).
- 값의 범위를 좁게 잡으면 중복값이 자주 나오고, 넓게 잡으면 거의 안 나옵니다.

### 트리

정점 번호를 0부터 정하고, i번째 정점(1부터)마다 이미 만든 정점 중 하나를 부모로 골라 간선을 추가하면 항상 연결된 트리가 됩니다. 정점 번호를 셔플해서 번호 순서에 구조가 드러나지 않게 합니다.

```js
function randomTree(n, rng) {
  const label = shuffle(
    Array.from({ length: n }, (_, i) => i + 1), rng)
  const edges = []
  for (let i = 1; i < n; i++) {
    const p = randInt(rng, 0, i - 1)    // 앞 정점 중 하나
    edges.push([label[p], label[i]])
  }
  return edges   // n - 1개의 간선
}
```

- 부모를 `i - 1`로 고정하면 일직선(경로)이 되어 DFS 깊이가 N인 최악 입력이 됩니다(86편). 부모를 항상 0으로 고정하면 별 모양이 됩니다. 이 두 극단을 함께 시험합니다.
- 위 방식은 모든 트리가 같은 확률로 나오지는 않습니다. 반례를 찾는 용도로는 충분합니다.

### 그래프

연결된 그래프는 먼저 트리를 만들고 남은 간선을 무작위로 더합니다. 자기 루프와 중복 간선을 허용할지는 문제 제약에 따릅니다(79편).

```js
const key = (u, v, n) =>
  Math.min(u, v) * (n + 1) + Math.max(u, v)
function randomGraph(n, m, rng) {
  const edges = randomTree(n, rng)   // 연결 보장
  const seen = new Set(edges.map(([u, v]) => key(u, v, n)))
  while (edges.length < m) {
    const u = randInt(rng, 1, n)
    const v = randInt(rng, 1, n)
    if (u === v || seen.has(key(u, v, n))) continue
    seen.add(key(u, v, n))
    edges.push([u, v])
  }
  return edges   // 단순 무방향 연결 그래프
}
```

- `m`은 `n - 1` 이상 `n(n - 1) / 2` 이하여야 합니다. 그 이상이면 반복이 끝나지 않습니다.
- 방향 그래프, 가중치, 비연결 그래프는 위 구조를 바꿔서 만듭니다. 가중치는 간선마다 `randInt`로 붙이고, 비연결은 트리를 생략하고 간선만 무작위로 뽑습니다.
- DAG가 필요하면 정점에 순서를 정하고 앞 번호에서 뒤 번호로만 간선을 만듭니다.

## Stress Testing 자동화

스트레스 테스트 자동화는 입력 생성, 두 풀이 실행, 비교를 수천 번 반복하고 처음 틀린 입력에서 멈추는 것입니다. 파일 하나에 모든 요소를 넣고 `node`로 실행합니다(제출용이 아니라 로컬 확인용입니다).

```js
function stress(solve, oracle, gen, rounds) {
  for (let seed = 1; seed <= rounds; seed++) {
    const input = gen(makeRng(seed))
    const got = solve(structuredClone(input))
    const want = oracle(structuredClone(input))
    if (JSON.stringify(got) !== JSON.stringify(want)) {
      console.log('FAIL seed', seed)
      console.log(JSON.stringify(input), got, want)
      return false
    }
  }
  console.log('OK')
  return true
}
```

- 반복 번호가 곧 시드이므로 틀린 번호만 알면 `gen(makeRng(seed))`로 같은 입력을 다시 만들어 디버깅할 수 있습니다.
- `gen`은 시드로 만든 난수 생성기를 받아 입력 하나를 만드는 함수입니다.

```js
const gen = (rng) =>
  randomArray(rng, randInt(rng, 1, 5), -5, 5)

const fast = (a) => {       // 일부러 넣은 버그: 0으로 초기화
  let best = 0, cur = 0
  for (const x of a) {
    cur = Math.max(0, cur + x)
    best = Math.max(best, cur)
  }
  return best
}
stress(fast, oracle, gen, 1000)
// FAIL seed 1 [-5] 0 -5  (모두 음수인 입력에서 틀림)
```

- 반례가 길면 읽기 어렵습니다. 크기를 1부터 시작해서 점점 키우거나, 틀린 입력에서 원소를 하나씩 빼 보며 계속 틀리는 가장 작은 입력을 찾아 디버깅합니다.
- 비교 결과가 맞더라도 풀이가 시간 안에 도는지는 별개입니다. 스트레스 테스트는 정답을 비교하고, 시간은 최대 입력(79편)에서 따로 잽니다.
- 테스트가 모두 통과하면 반복 횟수를 늘리고, 값의 범위와 크기를 바꿔 다시 돌립니다. 한 가지 분포만 돌리면 그 분포에 없는 반례는 못 찾습니다.
- 풀이가 출력 대신 `solution` 함수(08편)로 감싸져 있으면 그 함수를 `solve`로 바로 넘깁니다. 표준 입력을 읽는 풀이는 핵심 로직을 함수로 분리해야 부를 수 있습니다.

**흔한 실수:** 기준답과 풀이가 입력 배열을 공유해서 한쪽의 수정이 다른 쪽에 영향을 주는 것입니다. 복사본을 넘겨야 합니다.

## 핵심 정리

- 기준답(oracle)은 느려도 확실한 완전탐색이고, 풀이와 다른 방법으로 단순하게 만듭니다.
- 작은 입력(원소 5개 이하, 값 −5–5)에서 두 풀이를 비교하면 반례를 찾기 쉽고 읽기 쉽습니다. 정답이 여러 개 가능한 문제는 값이 아니라 검사 함수로 비교합니다.
- `Math.random`은 시드를 정할 수 없으므로 재현이 필요한 테스트에는 xorshift32 같은 직접 만든 생성기를 쓰고, 반복 번호를 시드로 삼습니다.
- Fisher-Yates 셔플은 뒤에서부터 `0`부터 `i`까지에서 `j`를 골라 바꾸고, 전체에서 고르는 방법과 랜덤 비교 정렬은 치우칩니다.
- 트리는 이전 정점 중 하나를 부모로 골라 만들고, 연결 그래프는 트리에 간선을 더해 만들며, 일직선과 별 모양 극단도 함께 시험합니다.
- 스트레스 테스트는 생성, 두 풀이 실행, 비교를 반복하다 처음 틀린 시드에서 멈추는 루프입니다.
