## Euler Tour

Euler Tour는 **트리를 DFS로 한 바퀴 돌며 정점을 방문 순서대로 배열에 적어, 트리 문제를 배열 문제로 바꾸는** 기법입니다. 기록 방식은 두 가지이고, 이 문서에서 각각 쓰입니다.

| 방식 | 기록 | 길이 | 용도 |
|------|------|------|------|
| DFS 진입 순서 | 정점에 처음 들어갈 때만 | N | 서브트리 질의(아래 세 절) |
| 방문마다 기록 | 들어갈 때와 자식에서 돌아올 때마다 | 2N - 1 | LCA(뒤의 절) |

핵심 성질은 **서브트리가 배열의 연속 구간**이라는 것입니다. DFS는 한 정점에 들어가면 그 서브트리를 모두 방문한 뒤에야 나오기 때문입니다. 정점마다 진입 시각 `tin[v]`와 서브트리의 끝 `tout[v]`를 기록합니다. `tout[v]`는 서브트리를 모두 끝낸 시점의 시각으로, 서브트리는 반열린 구간 `[tin[v], tout[v])`입니다.

```js
function dfs(v, p) {                     // 재귀 정의 (개념 확인용)
  tin[v] = timer++
  for (const w of adj[v]) if (w !== p) dfs(w, v)
  tout[v] = timer                        // 서브트리가 끝난 시각
}
```

재귀는 깊은 트리에서 호출 스택이 넘칩니다(자세히는 86편). 스택으로 반복하는 방식을 씁니다. 정점을 꺼내 방문 순서에 적고 자식을 스택에 쌓습니다. 마지막에 쌓은 자식이 먼저 나오지만 서브트리가 연속이라는 성질은 그대로입니다.

```js
function dfsOrder(n, adj, root) {
  const parent = new Int32Array(n).fill(-1)
  const order = [], stack = [root]
  parent[root] = root
  while (stack.length) {
    const v = stack.pop()
    order.push(v)                        // 방문 순서에 적는다
    for (const w of adj[v]) {
      if (parent[w] !== -1) continue
      parent[w] = v
      stack.push(w)
    }
  }
  return { parent, order }
}
```

`tin`과 서브트리 크기 `size`는 `order`에서 얻습니다. 반대 방향으로(`order`의 뒤에서 앞으로) 훑으면 자식이 부모보다 먼저 처리되므로 크기가 누적됩니다. `tout[v]`는 `tin[v] + size[v]`입니다.

```js
const tin = new Int32Array(n)
const size = new Int32Array(n).fill(1)
order.forEach((v, i) => { tin[v] = i })
for (let i = n - 1; i > 0; i--) {        // 자식부터 부모로 누적
  size[parent[order[i]]] += size[order[i]]
}
// v의 서브트리 = order[tin[v] .. tin[v] + size[v] - 1]
```

66편의 트리(간선 `0-1, 0-2, 1-3, 1-4, 2-5, 4-6, 4-7`, 루트 0)를 넣으면 다음과 같습니다.

| 항목 | 값 |
|------|----|
| `order` | 0 2 5 1 4 7 6 3 |
| `tin` (정점 0부터) | 0 3 1 7 4 2 6 5 |
| `size` (정점 0부터) | 8 5 2 1 3 1 1 1 |

- 정점 1의 서브트리는 `order[3 .. 7]`, 즉 `1 4 7 6 3`입니다. 실제 서브트리 `{1, 3, 4, 6, 7}`과 같습니다.
- 자식을 방문하는 순서는 인접 리스트와 스택 때문에 달라질 수 있지만, 어떤 순서든 서브트리가 연속이라는 점은 같습니다.
- `parent`는 BFS가 아니라 이 DFS에서 구한 값으로도 충분합니다. 깊이가 필요하면 `depth[w] = depth[v] + 1`을 함께 기록합니다.
- 시간과 공간은 O(N)입니다.

**흔한 실수:**

- `tout`을 닫힌 끝(마지막 정점의 `tin`)으로 정의해 놓고 `tin + size`로 계산하는 것입니다. 이 문서는 반열린 구간이라 `tout = tin + size`이고, 닫힌 끝은 `tin + size - 1`입니다.
- 재귀 DFS로 `tin`을 구하다가 체인형 트리에서 `RangeError`가 나는 것입니다.
- 방문 순서를 다른 함수의 순서와 섞는 것입니다. 한 번 만든 `order`와 `tin`을 모든 질의에서 일관되게 씁니다.

## Subtree Query

서브트리 질의는 **"정점 `v`의 서브트리에 대한 합·최솟값·개수"를 묻는 질의**입니다. Euler Tour로 서브트리가 구간 `[tin[v], tin[v] + size[v])`가 되므로 구간 질의 도구를 그대로 씁니다.

값이 바뀌지 않으면 누적합(29편)이 O(1)입니다.

```js
const pre = new Float64Array(n + 1)    // order 앞 i개의 합
for (let i = 0; i < n; i++) {
  pre[i + 1] = pre[i] + val[order[i]]
}
const subtreeSum = (v) =>
  pre[tin[v] + size[v]] - pre[tin[v]]
```

- 서브트리의 최솟값·최댓값은 `order` 순서의 값 배열에 Sparse Table(65편)을 만들면 O(1)입니다.
- 서브트리 크기는 `size[v]`, 리프 개수는 `order` 순서로 리프 여부를 1로 둔 배열의 구간 합으로 구합니다.
- 서브트리에서 서로 다른 값의 개수처럼 합칠 수 없는 질의는 구간 질의의 오프라인 기법(Mo 알고리즘 등, 65편)이나 Small to Large(아래)로 풉니다.

조상 관계도 O(1)에 판정됩니다. `u`가 `v`의 조상이라는 것은 `v`가 `u`의 서브트리 안에 있다는 뜻이고, 이는 `tin[v]`가 `u`의 구간에 들어 있다는 말입니다.

```js
const isAncestor = (u, v) =>
  tin[u] <= tin[v] && tin[v] < tin[u] + size[u]
// u === v 이면 true (자기 자신도 조상으로 친다)
```

- 66편의 LCA에서 조상 판정을 이 식으로 대신할 수 있습니다.
- 간선 `(a, b)`가 `a`가 부모인 간선일 때, 간선을 끊으면 `b`의 서브트리만 떨어져 나가므로 "간선을 끊었을 때 두 부분의 크기"는 `size[b]`와 `n - size[b]`입니다.

**문제의 단서:** "정점 v를 루트로 하는 서브트리의 합", "v의 서브트리에 속한 정점 중", "v가 u의 조상인가", 트리와 질의가 많습니다.

## Euler Tour + Segment Tree

트리의 값이 **바뀌는** 문제는 Euler Tour 배열 위에 Fenwick Tree(64편)나 Segment Tree(62편)를 올립니다. 정점 `v`는 위치 `tin[v]`에 있고 서브트리는 구간입니다. 아래의 `makeBit`는 64편의 Fenwick Tree를 객체로 묶은 것입니다.

```js
function makeBit(n) {
  const t = new Float64Array(n + 1)
  return {
    add(i, d) { for (i++; i <= n; i += i & -i) t[i] += d },
    prefix(i) {                          // [0, i]의 합
      let s = 0
      for (i++; i > 0; i -= i & -i) s += t[i]
      return s
    },
  }
}
```

**점 갱신과 서브트리 합:** 정점의 값을 바꾸면 위치 한 칸이 바뀌고, 서브트리 합은 구간 합입니다.

```js
const sum = makeBit(n)
order.forEach((v, i) => sum.add(i, val[v]))
const addValue = (v, d) => sum.add(tin[v], d) // val[v] += d
const subtreeSum = (v) =>
  sum.prefix(tin[v] + size[v] - 1) - sum.prefix(tin[v] - 1)
```

**서브트리 덧셈과 점 질의:** 서브트리 전체에 `d`를 더하는 일은 구간 덧셈이고, Fenwick Tree에서는 차분으로 기록합니다(64편). 정점 하나의 값은 위치의 누적값입니다.

```js
const diff = makeBit(n)
const addSubtree = (v, d) => {
  diff.add(tin[v], d)
  diff.add(tin[v] + size[v], -d)         // 끝 다음 칸에서 되돌린다
}
const pointValue = (v) => diff.prefix(tin[v])
```

- `diff.add(tin[v] + size[v], -d)`에서 위치가 `n`이면 `add`의 반복이 돌지 않아 아무 일도 하지 않습니다. 범위 밖 쓰기가 일어나지 않습니다.
- 두 용도는 의미가 다르므로 Fenwick Tree를 **따로** 둡니다.
- 간선의 가중치를 바꾸고 "루트에서 정점 `x`까지의 거리"를 묻는 문제가 이 방식입니다. 간선 `(부모 p, 자식 c)`의 가중치가 `d`만큼 변하면 `c`의 서브트리 모든 정점의 거리가 `d`만큼 변하므로 `addSubtree(c, d)`이고, 질의는 `pointValue(x)`입니다.
- 서브트리 덧셈과 서브트리 **합**을 함께 묻거나 최솟값·최댓값이 필요하면 Lazy Propagation(63편)이 달린 Segment Tree를 씁니다.
- 갱신과 질의 모두 O(log N)이고 준비는 O(N)입니다.

**흔한 실수:**

- 정점 번호로 Fenwick Tree를 바로 인덱싱하는 것입니다. 위치는 항상 `tin[v]`입니다.
- 정점 값을 `order` 순서가 아니라 정점 번호 순서로 Segment Tree에 넣는 것입니다. 서브트리가 구간이 되지 않아 틀립니다.

**문제의 단서:** "정점 값이 바뀌고 서브트리의 합을 묻는다", "서브트리 전체에 값을 더하고 정점 하나를 묻는다".

## Tree DP

Tree DP는 **서브트리에 대한 답을 자식에서 부모로 모아 가며 구하는** DP입니다. 정점 `v`의 상태 `dp[v]`를 "v의 서브트리만 보았을 때의 답"으로 정의하고, 자식의 `dp`로 `dp[v]`를 계산합니다(40편). 자식이 부모보다 먼저 계산돼야 하므로, 위의 `order`를 **뒤에서부터** 훑으면 됩니다. 재귀를 쓰지 않아 깊은 트리에서도 안전합니다.

대표 예는 **최대 가중치 독립 집합**입니다. 서로 이웃하지 않는 정점을 골라 값의 합을 최대로 합니다. 정점 `v`를 고르는지에 따라 상태가 둘입니다.

- `take[v]`: `v`를 고를 때 서브트리의 최대 합. 자식은 고를 수 없으므로 `val[v]` + 자식들의 `skip` 합.
- `skip[v]`: `v`를 고르지 않을 때의 최대 합. 자식은 고르든 말든 자유이므로 자식마다 `max(take, skip)`의 합.

```js
const take = new Float64Array(n), skip = new Float64Array(n)
for (let i = n - 1; i >= 0; i--) {       // 자식 → 부모 순서
  const v = order[i]
  take[v] += val[v]            // 자식들의 skip 합에 자기 값
  if (i === 0) break                     // 루트는 부모가 없다
  const p = parent[v]
  take[p] += skip[v]
  skip[p] += Math.max(take[v], skip[v])
}
// 답: Math.max(take[root], skip[root])
```

- `v`를 처리하는 시점에 `v`의 모든 자식이 이미 `take[v]`, `skip[v]`에 자기 기여를 더해 둔 상태입니다. 그래서 `v`를 꺼낼 때 `val[v]`만 더하면 `take[v]`가 완성됩니다.
- 66편의 트리에 `val = [3, 1, 4, 1, 5, 9, 2, 6]`을 넣으면 `take[0] = 21`, `skip[0] = 18`이라 답은 21입니다. 정점 `{0, 3, 5, 6, 7}`을 고른 경우(3 + 1 + 9 + 2 + 6)입니다.
- 시간은 정점과 간선을 한 번씩 보는 O(N)입니다.

| 문제 | 상태 | 점화식의 모양 |
|------|------|----------------|
| 서브트리 크기·높이 | `size[v]`, `height[v]` | 자식의 합, 자식의 최댓값 + 1 |
| 최대 독립 집합 | `take`, `skip` | 위 코드 |
| 최소 정점 덮개 | 선택 여부 | 선택하면 자식은 자유, 안 하면 자식은 모두 선택 |
| 트리 지름 | 아래로 가장 긴 길이 | 정점마다 상위 두 자식 길이의 합으로 갱신(44편) |
| 서브트리에서 k개 고르기 | `dp[v][j]` | 자식을 하나씩 합치며 배낭 형태로 합성 |
| 색칠 경우의 수 | `dp[v][색]` | 자식 색이 다른 경우의 곱(모듈러 곱, 57편) |

- 상태에 **부모와의 관계**(부모를 골랐는가, 부모와 같은 색인가)가 필요하면 `dp[v][상태]`로 차원을 하나 늘립니다.
- "서브트리에서 k개 고르기"는 자식을 합칠 때 두 쪽의 크기만큼만 반복하면 전체가 O(N²)에 끝납니다. 크기를 제한하지 않고 `k` 전체를 돌면 느려집니다.
- 간선에 가중치가 있으면 `dp[p] += dp[v] + 간선 가중치` 형태로 바뀝니다. 가중치의 위치를 점화식에 정확히 써 둡니다.
- DAG 위의 DP(53편)와 같은 구조입니다. 트리는 부모가 하나라서 위상 순서가 곧 `order`의 역순입니다.

**흔한 실수:**

- 재귀로 풀다가 정점 수가 크면 호출 스택이 넘치는 것입니다. `order` 역순 반복이 안전합니다.
- 루트의 `parent`가 자기 자신이라 `parent[root]`에 값을 더해 루트의 값이 두 번 쌓이는 것입니다. `i === 0`에서 멈추거나 `v === root`를 검사합니다.
- 상태를 초기화하지 않고 여러 테스트에서 배열을 재사용하는 것입니다.

**문제의 단서:** "트리에서 인접한 정점을 동시에 고를 수 없다", "서브트리에서 ~를 최대로", 입력이 트리이고 정점 수가 10^5 안팎입니다.

## Rerooting DP

Rerooting DP는 **모든 정점을 루트로 삼았을 때의 답을 한 번에 구하는** 기법입니다. 정점마다 새로 Tree DP를 돌리면 O(N²)이므로, 루트를 인접 정점으로 옮길 때 답이 어떻게 바뀌는지를 식으로 구해 O(N)에 끝냅니다. 두 번의 패스로 이뤄집니다.

1. **아래 방향(자식 → 부모):** 루트를 하나 고정하고 Tree DP로 서브트리 값을 구합니다.
2. **위 방향(부모 → 자식):** 부모를 루트로 한 답에서 자식을 루트로 한 답으로 옮기는 식을 `order` 순서로 적용합니다.

예로 **모든 정점에 대해 다른 모든 정점까지의 거리 합**을 구합니다. 아래 방향에서 서브트리 크기 `sz[v]`와, `v`에서 서브트리 안의 정점들까지의 거리 합 `down[v]`를 구합니다.

```js
const sz = new Int32Array(n).fill(1)
const down = new Float64Array(n)
for (let i = n - 1; i > 0; i--) {        // 자식 → 부모
  const v = order[i], p = parent[v]
  sz[p] += sz[v]
  down[p] += down[v] + sz[v]   // 자식 쪽 정점마다 간선 1개 추가
}
```

루트의 답은 `down[루트]`입니다. 루트를 부모 `p`에서 자식 `v`로 옮기면 `v`의 서브트리에 있는 `sz[v]`개 정점은 거리가 1씩 줄고, 나머지 `n - sz[v]`개 정점은 1씩 늘어납니다.

```js
const ans = new Float64Array(n)   // ans[v]: v가 루트일 때
ans[order[0]] = down[order[0]]
for (let i = 1; i < n; i++) {            // 부모 → 자식
  const v = order[i], p = parent[v]
  ans[v] = ans[p] - sz[v] + (n - sz[v])
}
```

66편의 트리에서 `down = [14, 6, 1, 0, 2, 0, 0, 0]`이고 `ans = [14, 12, 18, 18, 14, 24, 20, 20]`입니다. 정점 0에서 나머지까지 거리 합이 14, 정점 1은 `14 - 5 + 3 = 12`입니다.

- 두 반복 모두 `order`의 순서만 바꿔 쓰므로 재귀가 없고 O(N)입니다.
- 위 방향의 식은 "부모의 답에서 자식 서브트리의 기여를 빼고 반대편의 기여를 더한다"입니다. 일반 문제에서도 이 틀을 씁니다.
- 합처럼 **뺄 수 있는** 값이면 위 식처럼 간단히 빼서 옮깁니다. 최댓값처럼 뺄 수 없는 값(예: 각 정점에서 가장 먼 정점까지의 거리)은 자식 중 **가장 큰 값과 두 번째로 큰 값**(또는 접두 최대와 접미 최대)을 저장해 두고, "자기 자신의 기여를 제외한 나머지"를 구해서 옮깁니다.
- 거리 합 문제는 간선 가중치가 있으면 `down[p] += down[v] + sz[v] * 가중치`, `ans[v] = ans[p] + (n - 2 * sz[v]) * 가중치`로 바뀝니다.

**문제의 단서:** "모든 정점에 대해", "각 정점을 루트로 했을 때"의 값을 구하고 정점 수가 10^5 이상입니다.

## Euler Tour와 RMQ로 구하는 LCA

길이 `2N - 1`의 Euler Tour(방문마다 기록)를 만들면 **LCA 문제가 RMQ 문제로 바뀝니다**. 두 정점 `u`, `v`의 첫 등장 위치 사이 구간에서 **깊이가 가장 작은 정점**이 LCA입니다. 두 정점 사이를 오가는 경로가 LCA까지 올라갔다 내려오기 때문입니다.

```js
function eulerTour(n, adj, root) {
  const euler = [root], depth = new Int32Array(n)
  const ptr = new Int32Array(n), stack = [root]
  while (stack.length) {
    const v = stack[stack.length - 1]
    const w = adj[v][ptr[v]++]     // 다음 이웃, 없으면 undefined
    if (w === undefined) {         // 다 끝냄: 부모로 복귀
      stack.pop()
      if (stack.length) euler.push(stack[stack.length - 1])
    } else if (w !== stack[stack.length - 2]) {   // 부모가 아니면
      depth[w] = stack.length; euler.push(w); stack.push(w)
    }
  }
  return { euler, depth }
}
```

- 정점에 처음 들어갈 때, 그리고 자식 하나에서 돌아올 때마다 `euler`에 적습니다. 정점 `N`개, 간선 `N - 1`개를 왕복하므로 길이는 `2N - 1`입니다.
- `depth[w] = stack.length`는 `w`를 넣기 직전 스택이 루트에서 `v`까지의 경로이므로 `w`의 깊이와 같습니다.
- 부모는 스택의 아래에서 두 번째 정점으로 알 수 있어서 `parent` 배열이 필요 없습니다.

첫 등장 위치 `first[v]`는 한 번 훑어서 구합니다.

```js
const first = new Int32Array(n).fill(-1)
euler.forEach((v, i) => { if (first[v] < 0) first[v] = i })
```

66편의 트리에서 `euler = [0, 1, 3, 1, 4, 6, 4, 7, 4, 1, 0, 2, 5, 2, 0]`(인접 리스트 순서)이고, 15개입니다. `first[6] = 5`, `first[5] = 12`이므로 `LCA(6, 5)`는 `euler[5 .. 12] = 6 4 7 4 1 0 2 5`에서 깊이가 가장 작은 정점인 0입니다. `LCA(6, 7)`은 `euler[5 .. 7] = 6 4 7`에서 깊이가 가장 작은 정점 4입니다.

구간에서 **깊이가 가장 작은 정점**을 구하는 RMQ에 Sparse Table(65편)을 씁니다. 깊이 값이 아니라 **정점 번호**를 표에 담고 비교는 깊이로 합니다.

```js
function buildTable(euler, depth) {
  const m = euler.length, K = 32 - Math.clz32(m)
  const st = [Int32Array.from(euler)]
  for (let k = 1; k < K; k++) {
    const prev = st[k - 1]
    const cur = new Int32Array(m - (1 << k) + 1)
    for (let i = 0; i < cur.length; i++) {
      const a = prev[i], b = prev[i + (1 << (k - 1))]
      cur[i] = depth[a] <= depth[b] ? a : b
    }
    st.push(cur)
  }
  return st
}
```

```js
function lcaRmq(st, first, depth, u, v) {
  let l = first[u], r = first[v]
  if (l > r) [l, r] = [r, l]             // 왼쪽 첫 등장이 앞에 오게
  const k = 31 - Math.clz32(r - l + 1)
  const a = st[k][l], b = st[k][r - (1 << k) + 1]
  return depth[a] <= depth[b] ? a : b    // 깊이가 작은 정점
}
```

- 준비는 O(N log N), 질의는 O(1)입니다. Binary Lifting(66편)의 질의 O(log N)보다 빠르고, 질의가 매우 많을 때 유리합니다.
- 표 크기는 `2N × log(2N)`이라 Binary Lifting보다 약 두 배 큽니다. 메모리가 빠듯하면 Binary Lifting이 낫습니다.
- 비교를 깊이로 하므로 `u === v`이면 `l === r`이 되어 자기 자신을 반환합니다. `u`가 `v`의 조상일 때도 구간 안에서 `u`의 깊이가 가장 작아 `u`가 나옵니다.

**흔한 실수:**

- 표에 깊이 값만 담아 "LCA의 깊이"는 구했지만 "LCA가 어느 정점인가"를 잃는 것입니다.
- 길이를 `N`으로 착각해 배열이나 표를 작게 만드는 것입니다. 방문마다 기록하면 길이가 `2N - 1`입니다.

## Heavy-Light Decomposition 개요

HLD(Heavy-Light Decomposition, 무거운-가벼운 분해)는 **트리를 서로 겹치지 않는 경로(체인)들로 나눠, 임의의 정점에서 루트까지가 O(log N)개의 체인만 지나게 만드는** 기법입니다. 체인마다 번호를 연속으로 매기면 경로 질의를 구간 질의 O(log N)번으로 바꿀 수 있습니다.

- 정점 `v`의 자식 중 **서브트리가 가장 큰 자식**으로 가는 간선이 무거운(heavy) 간선이고 나머지는 가벼운(light) 간선입니다. 정점마다 무거운 간선은 많아야 하나입니다.
- 무거운 간선으로 이어진 정점들이 한 체인이고, 체인의 맨 위 정점이 `head`입니다.
- 가벼운 간선을 한 번 내려가면 서브트리 크기가 절반 이하로 줄기 때문에, 루트에서 어떤 정점까지 가벼운 간선은 O(log N)개입니다. 그래서 지나는 체인도 O(log N)개입니다.
- 위치는 무거운 자식을 **먼저** 방문하는 DFS 순서로 매깁니다. 그러면 체인이 연속된 위치를 차지하고, 서브트리도 연속이라 서브트리 질의도 됩니다.

```js
const heavy = new Int32Array(n).fill(-1)  // 무거운 자식
for (let i = n - 1; i > 0; i--) {         // size는 위에서 구한 값
  const v = order[i], p = parent[v]
  const h = heavy[p]
  if (h === -1 || size[v] > size[h]) heavy[p] = v
}
```

```js
const head = new Int32Array(n), pos = new Int32Array(n)
const stack = [root]; let cur = 0
head[root] = root
while (stack.length) {
  const v = stack.pop()
  pos[v] = cur++
  for (const w of adj[v]) {         // 가벼운 자식: 새 체인
    if (w === parent[v] || w === heavy[v]) continue
    head[w] = w; stack.push(w)
  }
  if (heavy[v] !== -1) {         // 무거운 자식을 마지막에 넣어
    head[heavy[v]] = head[v]     // 가장 먼저 꺼내 체인을 잇는다
    stack.push(heavy[v])
  }
}
```

두 정점 사이의 경로 질의는 `head`가 서로 다른 동안 **head가 더 깊은 쪽을 체인 위로** 올리며, 올릴 때마다 그 체인 구간 `[pos[head], pos[v]]`를 Segment Tree로 질의합니다. 같은 체인에 도달하면 남은 구간을 한 번 더 질의합니다. 이 반복이 곧 LCA 알고리즘입니다.

```js
while (head[u] !== head[v]) {
  if (depth[head[u]] < depth[head[v]]) [u, v] = [v, u]
  // 여기서 구간 [pos[head[u]], pos[u]]를 질의한다
  u = parent[head[u]]                    // 체인 위로 올라간다
}
// 같은 체인: 구간 [pos[낮은 쪽], pos[깊은 쪽]]을 질의하고
// LCA는 depth가 작은 쪽
return depth[u] < depth[v] ? u : v
```

- 경로 질의는 체인 O(log N)개에 Segment Tree 질의 O(log N)이라 O(log² N)입니다.
- 정점 값이 바뀌는 경로 합·최댓값 질의(Binary Lifting으로는 풀 수 없는 경우)에 씁니다.
- 구현이 길어서, 코딩테스트에서는 경로 질의에 값 변경이 섞일 때만 꺼냅니다. LCA만 필요하면 Binary Lifting이나 Euler Tour가 간단합니다.

## Centroid Decomposition 개요

센트로이드(centroid)는 **제거했을 때 남는 모든 연결 요소의 크기가 `N / 2` 이하가 되는 정점**입니다. 모든 트리에는 센트로이드가 하나 또는 두 개(두 개이면 서로 인접)가 있습니다.

Centroid Decomposition은 다음 과정을 반복해 트리를 계층으로 나눕니다.

1. 현재 트리의 센트로이드 `c`를 찾는다. 서브트리 크기를 구한 뒤 크기가 큰 자식 쪽으로 이동해, 어느 자식 서브트리도 절반 이하가 되는 곳에서 멈춥니다.
2. `c`를 지나는 경로를 모두 처리한다.
3. `c`를 제거하고 남은 각 연결 요소에서 1부터 반복한다.

- 한 단계마다 연결 요소의 크기가 절반 이하로 줄어서 분해의 깊이는 O(log N)이고, 한 층의 총 작업량이 O(N)이라 전체가 O(N log N)입니다.
- 트리의 임의의 경로 `u–v`는 **센트로이드 분해 트리에서 `u`와 `v`의 LCA에 해당하는 센트로이드를 지납니다**. 그래서 "경로를 세는" 문제를 "센트로이드 `c`를 지나는 경로를 세는" 문제로 바꿀 수 있습니다.
- 대표 문제는 "길이가 정확히 K인 경로의 수", "가까운 표시된 정점까지의 거리 질의"입니다. 센트로이드 `c`에서 각 정점까지의 거리를 모으고, 서로 다른 자식 서브트리에 속한 정점끼리만 짝을 짓습니다(같은 서브트리끼리 짝지으면 `c`를 지나지 않는 경로가 섞이기 때문입니다).
- 이 기법은 경로 문제에서 Euler Tour(서브트리 문제)와 역할이 다릅니다. 서브트리가 아니라 **임의의 두 정점 사이 경로**가 핵심일 때 씁니다.
- 구현은 길고 재귀를 반복으로 바꿔야 하므로 이 문서에서는 원리만 정리합니다.

## Small to Large (DSU on Tree) 개요

Small to Large(작은 것을 큰 것에 합치기, DSU on Tree)는 **서브트리마다 집합이나 맵을 만들 때, 자식의 집합들을 합치되 항상 작은 쪽을 큰 쪽에 넣는** 기법입니다. 합치는 방향만 신경 써도 전체 비용이 O(N log N)으로 줄어듭니다.

이유는 한 원소가 옮겨질 때마다 그 원소가 속한 집합의 크기가 **최소 두 배**가 되기 때문입니다. 작은 쪽의 원소를 큰 쪽(크기가 같거나 큼)에 넣으면 합친 집합의 크기는 작은 쪽의 두 배 이상입니다. 크기는 N을 넘을 수 없으므로 한 원소는 최대 `log2 N`번 옮겨집니다. 원소 N개이므로 이동의 총합은 O(N log N)입니다.

예로 **각 정점의 서브트리에 서로 다른 색이 몇 가지인지**를 구합니다. `order`의 역순으로 정점을 처리하면 서브트리가 모두 합쳐진 뒤에 답을 읽을 수 있습니다.

```js
const sets = colors.map((c) => new Set([c]))
const answer = new Array(n)
for (let i = n - 1; i >= 0; i--) {
  const v = order[i]
  answer[v] = sets[v].size               // v의 서브트리가 완성됨
  if (i === 0) continue
  const p = parent[v]
  if (sets[p].size < sets[v].size) {     // 큰 쪽을 부모에 남긴다
    [sets[p], sets[v]] = [sets[v], sets[p]]
  }
  for (const x of sets[v]) sets[p].add(x)
}
```

- 합치기 전에 두 집합을 **교환**해서 항상 큰 집합이 `sets[p]`에 남게 합니다. 교환은 참조만 바꾸므로 O(1)입니다.
- `Set`은 명세상 평균 O(N)보다 빠른 접근 시간만 요구하고, 엔진은 보통 해시로 구현해 삽입을 상수 시간으로 볼 수 있습니다(자세히는 09편). 이 문서의 O(N log N)은 삽입을 상수로 본 값입니다.
- 서브트리마다 "값별 개수"가 필요하면 `Map`을 같은 방식으로 합칩니다. 이때 합치는 쪽의 `(값, 개수)`를 큰 쪽에 더합니다.
- `v`의 서브트리 질의를 `order`의 구간으로 바꾸고 오프라인 구조(Mo 알고리즘 등, 65편)로 푸는 방법도 있습니다. 서브트리마다 완전한 집합이 필요하면 Small to Large가 단순합니다.
- 집합을 직접 다루는 대신 "가장 큰 자식의 정보를 남기고 작은 자식들만 다시 더하는" 형태(sack)로 구현하는 방법도 있고, 시간복잡도는 같습니다.

**흔한 실수:**

- 교환 없이 항상 자식을 부모에 합치는 것입니다. 체인형 트리에서 합치는 비용이 O(N²)이 됩니다.
- 합친 뒤 `sets[v]`를 비우지 않아도 답에는 영향이 없지만, 메모리를 아끼려면 합친 자식의 집합을 `null`로 놓아 가비지 컬렉션이 되게 합니다.

**문제의 단서:** "각 서브트리에서 서로 다른 값의 개수", "서브트리 안에서 가장 많이 나온 값", 모든 정점에 대한 답이 필요하고 서브트리 정보를 합칠 수 있습니다.

## 핵심 정리

- Euler Tour(DFS 진입 순서)는 서브트리를 연속 구간 `[tin[v], tin[v] + size[v])`로 만들고, 조상 판정과 서브트리 질의를 O(1)로 줄입니다. 값이 바뀌면 그 배열 위에 Fenwick Tree나 Segment Tree를 올립니다.
- Tree DP는 서브트리의 답을 자식에서 부모로 모으며, 방문 순서 배열을 뒤에서부터 훑으면 재귀 없이 O(N)입니다. 부모와의 관계가 필요하면 상태를 늘립니다.
- Rerooting DP는 아래 방향 DP로 한 정점의 답을 구하고, 위 방향으로 루트를 옮기는 식(예: 거리 합 `ans[v] = ans[p] - sz[v] + (n - sz[v])`)을 적용해 모든 정점의 답을 O(N)에 구합니다.
- 방문마다 기록한 길이 `2N - 1`의 Euler Tour에서 첫 등장 위치 구간의 최소 깊이 정점이 LCA이고, Sparse Table로 질의가 O(1)입니다.
- HLD는 무거운 간선으로 체인을 만들어 경로를 O(log N)개의 구간으로 바꾸고(O(log² N)), 센트로이드 분해는 깊이 O(log N)의 계층으로 경로 문제를 풀며, Small to Large는 작은 집합을 큰 집합에 합쳐 O(N log N)에 서브트리 집합 문제를 풉니다.
