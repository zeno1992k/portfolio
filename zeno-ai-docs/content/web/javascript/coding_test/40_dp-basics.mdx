## DP 개념

동적 계획법(Dynamic Programming, DP)은 큰 문제를 작은 부분 문제로 나누어 풀고, **한 번 푼 부분 문제의 답을 저장해 다시 쓰는** 방법입니다. 같은 계산을 반복하지 않아서 지수 시간이 걸리던 완전탐색이 다항 시간으로 줄어듭니다.

DP는 문제가 다음 두 성질을 가질 때 쓸 수 있습니다.

| 성질 | 뜻 |
|------|----|
| 최적 부분 구조 | 큰 문제의 답을 작은 부분 문제의 답으로 만들 수 있다 |
| 중복되는 부분 문제 | 같은 부분 문제가 여러 번 나타난다 |

부분 문제가 겹치지 않으면 분할 정복(25편)이고, 매 순간 하나를 골라 되돌아보지 않으면 그리디(33편)입니다. DP는 모든 선택지의 답을 저장해 두고 그중에서 고릅니다.

풀이는 다섯 가지를 정하는 일입니다.

1. **상태 정의:** `dp[...]`가 무엇을 뜻하는지 한 문장으로 쓴다.
2. **점화식:** 큰 상태의 값을 작은 상태의 값으로 나타낸다.
3. **초기값:** 점화식이 시작할 수 있게 가장 작은 상태의 값을 직접 정한다.
4. **계산 순서:** 의존하는 상태를 먼저 계산하도록 정한다.
5. **답의 위치:** 어느 상태의 값이 답인지 정한다.

- 시간복잡도는 **상태 수 × 상태 하나를 계산하는 데 드는 전이 수**입니다. 상태가 N개이고 전이가 상수이면 O(N)입니다.
- 공간복잡도는 저장하는 상태 수입니다.
- 구현 방식은 재귀로 위에서부터 푸는 Memoization(top-down)과 반복문으로 아래에서부터 채우는 Tabulation(bottom-up)입니다. 둘은 상태와 점화식이 같고 계산 순서만 다릅니다.

**문제의 단서:** "경우의 수를 구하라", "최솟값·최댓값을 구하라", 그리고 완전탐색으로는 N이 너무 커서 시간 초과일 때입니다. 앞의 선택이 뒤의 선택에 영향을 주면서 같은 상황이 반복되면 DP를 의심합니다.

## 상태 정의

상태(state)는 부분 문제 하나를 구별하는 값(들)이고, `dp[상태]`는 그 부분 문제의 답입니다. DP의 대부분은 **상태를 어떻게 정의하느냐**로 정해집니다. 정의가 분명하면 점화식은 따라 나오고, 정의가 흐리면 점화식을 쓸 수 없습니다.

`dp[i]`의 뜻을 말로 정확히 씁니다.

| 문제 | `dp[i]`의 정의 |
|------|----------------|
| N번째 피보나치 수 | `i`번째 피보나치 수 |
| 인접한 원소를 못 고르는 최대 합 | 앞의 `i + 1`개 원소 중에서 고른 합의 최댓값 |
| 계단 `i`번째 칸에 오르는 방법 | `i`번째 계단에 오르는 경우의 수 |
| 정수 `i`를 만드는 최소 묶음 | 정확히 `i`개를 만드는 데 필요한 최소 묶음 수 |

- 정의에는 **"몇 번째까지"인지, "정확히"인지 "이하"인지, 마지막 칸을 반드시 밟는지**를 구분해서 씁니다. 이것이 흐리면 초기값과 답의 위치를 잘못 잡습니다.
- 답에 영향을 주는 정보는 상태에 넣고, 영향이 없는 정보는 넣지 않습니다. 넣을 정보가 모자라면 점화식을 세울 수 없고, 넘치면 상태 수가 늘어서 비용이 커집니다(같은 사고가 39편의 상태 BFS입니다).
- 상태가 둘 이상의 값이면 `dp[i][j]`처럼 차원이 늘어납니다(자세히는 41편).
- 정의를 세우는 방법은 두 가지가 흔합니다. 앞에서부터 "i번째까지의 답"으로 두거나, 뒤에서부터 "i번째에서 시작할 때의 답"으로 둡니다.

**흔한 실수:** `dp[i]`의 뜻을 정하지 않은 채 값을 채우다가, 어떤 칸은 "i까지의 최대"이고 어떤 칸은 "i를 반드시 고른 최대"가 되어 점화식이 섞이는 것입니다.

## 점화식

점화식(recurrence relation)은 `dp[i]`를 그보다 작은 상태의 값으로 나타낸 식입니다. 세우는 방법은 **마지막 선택으로 경우를 나누는 것**입니다. `i`번째 상태에 어떻게 도착했는지, 마지막에 무엇을 골랐는지를 모든 경우로 나누고, 경우마다 작은 상태의 값을 가져옵니다.

| 구하는 것 | 경우를 합치는 방법 | 모양 |
|-----------|---------------------|------|
| 경우의 수 | 더한다 | `dp[i] = dp[i - 1] + dp[i - 2]` |
| 최솟값 | 가장 작은 것을 고른다 | `dp[i] = min(dp[i - 1], dp[i - 2]) + 비용` |
| 최댓값 | 가장 큰 것을 고른다 | `dp[i] = max(dp[i - 1], dp[i - 2] + 값)` |

- 경우들은 **겹치지 않고 빠짐없이** 나뉘어야 합니다. 경우의 수에서 겹치면 중복해서 세고, 빠지면 모자랍니다.
- 최소·최대에서는 경우가 겹쳐도 답에는 영향이 없습니다. 그래도 빠뜨리면 답이 틀립니다.
- 점화식이 참조하는 인덱스는 `i`보다 작아야 합니다. 같거나 크면 계산 순서를 정할 수 없습니다.
- 한 상태가 의존하는 상태의 수가 전이 수입니다. `dp[i - 1]`과 `dp[i - 2]`만 쓰면 전이가 2개입니다.

**흔한 실수:** 마지막 선택을 나누는 기준이 빠져서 경우가 중복되는 것입니다. 예를 들어 "마지막에 1을 더한다 / 2를 더한다"로 나누면 서로 다른 경우지만, "1을 한 번 이상 쓴다 / 2를 한 번 이상 쓴다"로 나누면 겹칩니다.

## 초기값

초기값은 점화식이 참조할 수 없는 가장 작은 상태의 값을 **직접** 정해 주는 것입니다. 점화식이 `dp[i - 1]`과 `dp[i - 2]`를 쓰면 `dp[0]`과 `dp[1]`이 필요합니다. 점화식이 `i - k`까지 거슬러 올라가면 초기값이 k개 필요합니다.

- 경우의 수에서 아무것도 하지 않는 상태 `dp[0]`은 보통 `1`입니다. "빈 선택 한 가지"가 있다고 세는 것입니다.
- 최댓값에서 `dp[0]`은 보통 `0`(아무것도 고르지 않은 합)이고, 최솟값에서 도달할 수 없는 상태는 큰 값으로 둡니다(아래 "불가능 상태 표현").
- `i - 2` 같은 인덱스가 음수가 될 수 있으면 `if (i >= 2)`로 막습니다.
- 입력이 아주 작을 때(`n = 0`, `n = 1`)도 점화식이 맞는지 따로 확인합니다. 배열 길이가 모자라서 초기값을 쓰는 코드에서 인덱스 오류가 납니다.

**흔한 실수:**

- 초기값 하나를 빼먹거나, 정의와 다른 값으로 넣는 것입니다. 점화식이 맞아도 모든 값이 틀어집니다.
- `dp[1]`을 쓰는 코드에서 `n = 0`일 때 배열 길이가 1이라 `dp[1]` 대입이 범위 밖이 되는 것입니다. 이 경우 JavaScript는 에러 없이 배열을 늘려서 조용히 지나갑니다.

## Memoization

Memoization(메모이제이션)은 **재귀로 문제를 풀되, 계산한 결과를 저장해 두었다가 같은 호출이 오면 저장한 값을 돌려주는** 방법입니다. 위에서부터(top-down) 필요한 상태만 계산합니다. 재귀 점화식을 그대로 코드로 옮기고 캐시만 붙이면 됩니다.

```js
function fib(n, memo = new Array(n + 1).fill(-1)) {
  if (n < 2) return n                 // 초기값
  if (memo[n] !== -1) return memo[n]  // 이미 계산함
  memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
  return memo[n]
}
```

- 캐시는 배열(`memo[n]`)이나 `Map`입니다. 상태가 정수 범위 안이면 배열이 빠르고, 상태가 문자열이나 큰 범위이면 `Map`입니다(자세히는 9편).
- 캐시가 비어 있음을 나타내는 값(`-1` 등)은 **정답이 될 수 없는 값**이어야 합니다. 정답이 `0`일 수 있으면 `if (memo[n])`처럼 거짓 값으로 검사하면 안 되고 `!== -1`로 비교합니다.
- 캐시가 없으면 같은 호출을 반복하고, 있으면 상태마다 한 번씩만 계산합니다. 시간복잡도는 상태 수 × 전이 수입니다.
- 필요한 상태만 계산하므로, 상태 공간은 크지만 답에 닿는 상태는 일부일 때 유리합니다.
- 재귀라서 깊이가 깊으면 호출 스택이 넘칩니다. 위 함수에 `n = 100000`을 넣으면 Node.js 24 기본 설정에서 RangeError가 났습니다. 깊이가 수만 이상이 될 수 있으면 Tabulation으로 바꿉니다(자세히는 22편, 86편).
- 함수의 기본 매개변수 `memo = new Array(...)`는 호출마다 새로 만들어집니다. 재귀 호출에서는 `memo`를 직접 넘겨서 하나를 공유해야 합니다.

**흔한 실수:**

- 재귀 호출에 `memo`를 넘기지 않아서 호출마다 새 배열이 생겨 캐시가 무용지물이 되는 것입니다. 시간은 그대로 지수입니다.
- 결과를 `memo`에 저장하지 않고 반환만 하는 것입니다.

## Tabulation

Tabulation(타뷸레이션)은 **작은 상태부터 반복문으로 표(배열)를 채워서** 큰 상태를 얻는 방법입니다. 아래에서부터(bottom-up) 모든 상태를 계산합니다.

```js
function fib(n) {
  if (n < 2) return n
  const dp = new Array(n + 1).fill(0)
  dp[1] = 1                              // 초기값 dp[0] = 0
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2]        // 점화식
  }
  return dp[n]
}
```

- 반복문의 순서가 계산 순서입니다. `dp[i]`가 `dp[i - 1]`, `dp[i - 2]`에 의존하면 `i`를 작은 쪽에서 큰 쪽으로 돌립니다. 의존하는 상태가 항상 먼저 계산돼 있어야 합니다.
- 재귀가 없어서 호출 스택이 넘치지 않고, 함수 호출 비용이 없어서 일반적으로 빠릅니다.
- 모든 상태를 계산하므로 불필요한 상태까지 채웁니다.
- 표의 일부만 참조하면 이전 값 몇 개만 남겨 공간을 줄일 수 있습니다(자세히는 41편).

두 방식을 비교하면 다음과 같습니다.

| 항목 | Memoization | Tabulation |
|------|-------------|------------|
| 방향 | 위에서 아래(재귀) | 아래에서 위(반복문) |
| 계산하는 상태 | 필요한 것만 | 전부 |
| 순서 | 호출이 알아서 정함 | 직접 정해야 함 |
| 호출 스택 | 깊이만큼 사용 | 쓰지 않음 |
| 코드 | 점화식을 그대로 옮김 | 순서를 신경 써야 함 |

**문제의 단서:** 점화식은 쉽게 세워지는데 계산 순서가 복잡하면(격자의 경로, 트리) Memoization이 편하고, N이 크거나 상태 전체를 어차피 계산해야 하면 Tabulation이 안전합니다.

## 피보나치

피보나치 수는 `F(0) = 0`, `F(1) = 1`, `F(n) = F(n - 1) + F(n - 2)`로 정의된 수열입니다. 가장 단순한 DP 예제이고, 재귀가 왜 느린지 보여 줍니다.

```js
function fib(n) {
  return n < 2 ? n : fib(n - 1) + fib(n - 2)
}
```

- 이 코드는 `fib(3)` 같은 값을 여러 번 다시 계산합니다. `fib(5)`는 `fib(4)`와 `fib(3)`을 부르고, `fib(4)`도 다시 `fib(3)`을 부릅니다.
- 호출 횟수는 `n`이 1 늘 때마다 약 1.6배가 되어 시간복잡도가 지수입니다. 직접 세어 보면 `fib(30)`은 2,692,537번, `fib(40)`은 331,160,281번 호출됩니다.
- 앞의 두 절의 Memoization과 Tabulation은 상태 `F(0)`부터 `F(n)`까지 `n + 1`개를 한 번씩만 계산하므로 O(n)입니다.

| 방법 | 시간 | 공간 |
|------|------|------|
| 순수 재귀 | 지수 | O(n) 호출 스택 |
| Memoization | O(n) | O(n) |
| Tabulation | O(n) | O(n) |
| 변수 두 개 | O(n) | O(1) |

`dp[i]`가 바로 앞 두 값만 쓰므로 변수 두 개로 줄일 수 있습니다.

```js
function fib(n) {
  let a = 0, b = 1                // F(0), F(1)
  for (let i = 0; i < n; i++) {
    const next = a + b
    a = b
    b = next
  }
  return a                        // F(n)
}
```

- `Number`는 정수를 `2^53 - 1`(9007199254740991)까지만 정확히 표현합니다. 피보나치 수는 `F(78) = 8944394323791464`까지 정확하고, `F(79)`부터는 부정확합니다. 실제로 `F(79)`의 참값은 14472334024676221인데 `Number`로 계산하면 14472334024676220입니다.
- 그보다 큰 수가 필요하면 `BigInt`를 쓰거나(2편), 문제가 "나머지를 출력하라"고 하면 계산할 때마다 나머지를 취합니다(57편). 이때 더하기는 안전하지만 곱하기는 `Number` 범위를 넘을 수 있습니다.

**흔한 실수:** 순수 재귀로 `n = 40` 근처를 계산하는 것입니다. 입력이 작아 보여도 호출이 수억 번 일어나 시간 초과입니다.

## 1차원 DP

1차원 DP는 **상태가 정수 하나**(`dp[i]`)이고, `dp[i]`가 `i`보다 작은 몇 개의 상태에 의존하는 DP입니다. 계산 순서는 `i`를 0에서 N 방향으로 늘리면 됩니다. 입력이 수열이면 `i`는 원소의 위치, 입력이 하나의 수 N이면 `i`는 만들려는 값입니다.

대표 문제로 "수열에서 인접한 두 원소를 함께 고를 수 없을 때 합의 최댓값"을 풉니다. `dp[i]`를 앞의 `i + 1`개 원소 중에서 고른 합의 최댓값으로 정의하면 마지막 원소 `a[i]`를 고르는지로 경우가 나뉩니다.

- 고르지 않는다: 앞의 `i`개에서 최대이므로 `dp[i - 1]`.
- 고른다: 바로 앞 `a[i - 1]`은 고를 수 없으므로 `dp[i - 2] + a[i]`.

```js
function maxNoAdjacent(a) {
  const n = a.length
  if (n === 0) return 0
  const dp = new Array(n).fill(0)
  dp[0] = a[0]
  if (n > 1) dp[1] = Math.max(a[0], a[1])
  for (let i = 2; i < n; i++) {
    dp[i] = Math.max(dp[i - 1], dp[i - 2] + a[i])
  }
  return dp[n - 1]
}
// [2, 7, 9, 3, 1] → 12
```

`[2, 7, 9, 3, 1]`을 추적합니다.

| i | `a[i]` | 고르지 않음 `dp[i-1]` | 고름 `dp[i-2] + a[i]` | `dp[i]` |
|---|--------|------------------------|-----------------------|---------|
| 0 | 2 | - | - | 2 |
| 1 | 7 | - | - | 7 |
| 2 | 9 | 7 | 2 + 9 = 11 | 11 |
| 3 | 3 | 11 | 7 + 3 = 10 | 11 |
| 4 | 1 | 11 | 11 + 1 = 12 | 12 |

- 답은 `dp[n - 1]`이고 12(2, 9, 1을 고름)입니다.
- 초기값 `dp[0]`, `dp[1]`은 점화식이 `i - 2`까지 보기 때문에 필요합니다. 원소가 하나나 없는 경우를 따로 처리합니다.
- 원소가 음수일 수 있으면 `dp[0]`을 `Math.max(0, a[0])`로 둘지, 최소 하나를 반드시 골라야 하는지를 문제에서 확인합니다.
- 같은 모양의 문제: 연속된 집을 털 수 없는 최대 금액, 연속 N개 이하만 고를 수 있는 최대 합, 원소를 지우며 얻는 점수의 최댓값입니다.

**문제의 단서:** "인접한 것은 선택할 수 없다", "i번째까지 고려했을 때"처럼 앞에서부터 하나씩 결정이 이어지는 수열입니다.

## 계단 DP

계단 DP는 계단을 한 번에 1칸 또는 2칸씩 올라 꼭대기에 도착하는 문제 유형입니다. 마지막 걸음이 1칸이었는지 2칸이었는지로 점화식이 나뉩니다. 경우의 수, 최소 비용, 최대 점수 세 가지 변형이 있습니다.

**경우의 수:** `dp[i]`는 `i`번째 계단에 오르는 방법의 수입니다. 마지막 걸음이 1칸이면 `i - 1`에서, 2칸이면 `i - 2`에서 왔으므로 `dp[i] = dp[i - 1] + dp[i - 2]`입니다. 땅(0번째)에 서 있는 한 가지 방법이 `dp[0] = 1`입니다.

```js
function stairWays(n) {
  const dp = new Array(n + 1).fill(0)
  dp[0] = 1
  for (let i = 1; i <= n; i++) {
    dp[i] = dp[i - 1]
    if (i >= 2) dp[i] += dp[i - 2]
  }
  return dp[n]
}
// n = 0, 1, 2, 3, 4, 5 → 1, 1, 2, 3, 5, 8
```

피보나치 수열과 같은 모양입니다(`stairWays(n)`은 `F(n + 1)`). 한 번에 오를 수 있는 칸이 `{1, 2, 3}`이면 `dp[i] = dp[i - 1] + dp[i - 2] + dp[i - 3]`으로 늘어납니다.

**최소 비용:** 계단마다 밟을 때 비용이 있고, 1칸 또는 2칸씩 올라 꼭대기까지 갈 때 비용의 최솟값을 구합니다. `dp[i]`는 `i`번째 계단을 밟았을 때의 최소 비용이고 `dp[i] = min(dp[i - 1], dp[i - 2]) + cost[i]`입니다.

**최대 점수:** 계단마다 점수가 있고, **연속된 세 계단을 모두 밟을 수 없을** 때 마지막 계단을 밟아 얻는 점수의 최댓값을 구합니다. `dp[i]`를 `i`번째 계단을 밟았을 때의 최대 점수로 두고 마지막 걸음으로 나눕니다.

- 2칸 점프로 왔다: 그전은 제한이 없어 `dp[i - 2] + s[i]`.
- 1칸으로 왔다: 연속 세 칸이 되지 않으려면 `i - 1`은 점프로 왔어야 하므로 `dp[i - 3] + s[i - 1] + s[i]`.

```js
function maxScore(s) {              // s[0]이 1번째 계단
  const n = s.length
  const dp = new Array(n + 1).fill(0)
  dp[1] = s[0]
  if (n > 1) dp[2] = s[0] + s[1]
  for (let i = 3; i <= n; i++) {
    const jump = dp[i - 2]
    const step = dp[i - 3] + s[i - 2]
    dp[i] = Math.max(jump, step) + s[i - 1]
  }
  return dp[n]
}
// [10, 20, 15, 25, 10, 20] → 75
```

- 점수 배열 `s`가 0부터 시작하고 계단은 1부터 세기 때문에 `s[i - 1]`이 `i`번째 계단의 점수입니다. 인덱스가 한 칸 어긋나는 실수가 잦아서 `dp`를 `n + 1`칸으로 만들어 계단 번호와 맞춥니다.
- 연속 제한처럼 "직전에 어떻게 왔는가"가 중요한 문제는 상태에 연속 횟수를 넣어서 `dp[i][연속 횟수]`로 풀 수도 있습니다.

**흔한 실수:** 계단이 1개나 2개뿐일 때 `dp[2]`나 `dp[i - 3]`이 범위를 벗어나는 것입니다. `n`이 작은 입력을 따로 검사합니다.

## 불가능 상태 표현

DP에서 어떤 상태는 **만들 수 없는** 경우가 있습니다. 예를 들어 "3개짜리와 5개짜리 묶음으로 정확히 `n`개를 포장하는 최소 묶음 수"에서 `n = 4`는 만들 수 없습니다. 이런 상태를 값으로 표현해야 하고, 그 값이 다른 계산에 섞여도 답을 망치지 않아야 합니다.

- 최솟값 DP에서는 불가능을 **아주 큰 값**(INF)으로 둡니다. `min`을 취할 때 자연스럽게 무시됩니다.
- 최댓값 DP에서는 불가능을 **아주 작은 값**(-INF)으로 둡니다.
- 최종 답이 INF이면 문제가 정한 출력(`-1` 등)으로 바꿔 냅니다.

```js
const INF = 1e9
function minBundles(n) {
  const dp = new Array(n + 1).fill(INF)
  dp[0] = 0
  for (let i = 1; i <= n; i++) {
    if (i >= 3) dp[i] = Math.min(dp[i], dp[i - 3] + 1)
    if (i >= 5) dp[i] = Math.min(dp[i], dp[i - 5] + 1)
  }
  return dp[n] >= INF ? -1 : dp[n]
}
// n = 3, 4, 5, 6, 8 → 1, -1, 1, 2, 2
```

- `dp[i - 3]`이 INF이면 `dp[i - 3] + 1`은 INF보다 커서 `Math.min`이 기존의 INF를 그대로 둡니다. 불가능이 유지되고, 마지막에 `>= INF`로 불가능을 판단합니다.
- INF는 **정상 답보다 훨씬 크고, 더해도 넘치지 않는 값**으로 잡습니다. 정상 답의 최댓값이 1억이라면 INF는 1e9가 적당합니다.
- 두 INF를 더하면 값이 2배가 됩니다. 1e9의 두 배(2,000,000,000)는 32비트 정수의 최댓값 2,147,483,647 안이지만 세 배는 밖입니다.
- `Infinity`는 일반 배열에서는 가장 간단합니다. `Infinity + 1`은 `Infinity`이고 `Math.min`에서도 문제없습니다.

타입 배열에서는 주의가 필요합니다. `Int32Array`는 32비트 정수만 담아서 `Infinity`를 넣으면 `0`이 됩니다.

```js
const t = new Int32Array(3).fill(Infinity)
console.log(t[0])             // 0 (불가능이 0으로 바뀜)
const u = new Int32Array(1)
u[0] = 3e9                    // 32비트 범위를 넘음
console.log(u[0])             // -1294967296 (다른 수로 바뀜)
```

- 타입 배열을 쓸 때는 `Infinity` 대신 1e9 같은 유한한 정수를 INF로 씁니다.
- 불가능을 `-1`로 표시하면 최솟값 DP에서 `Math.min`이 `-1`을 고르는 사고가 납니다. `-1`은 `Math.min`에서 가장 작은 값이므로 불가능이 제일 좋은 값으로 뽑힙니다. `-1`은 최종 출력에서만 씁니다.
- 불가능한 상태를 `dp` 값 대신 `if (dp[i - 3] !== INF)`로 걸러서 쓸 수도 있습니다.
- 0도 정상 값일 수 있는 문제에서는 "아직 계산하지 않음"과 "불가능"을 서로 다른 값(`-1`과 INF 등)으로 구분합니다.

**흔한 실수:** 초기값을 `0`으로 채우고 최솟값을 구하는 것입니다. 아무 계산도 안 한 상태가 최솟값 0으로 선택됩니다.

## 최소 / 최대 DP

최소·최대 DP는 점화식이 `min` 또는 `max`로 후보를 고르는 DP입니다. 후보마다 "작은 상태의 값 + 이번 선택의 비용(또는 이득)"을 계산합니다.

| 구하는 것 | 점화식 | `dp` 초기값 | 불가능 |
|-----------|--------|--------------|---------|
| 최솟값 | `min(후보)` | 큰 값 INF | INF |
| 최댓값 | `max(후보)` | 작은 값 -INF 또는 0 | -INF |

예제는 "정수 N에서 시작해 연산을 몇 번 해서 1로 만들 때의 최소 횟수"입니다. 연산은 3으로 나누기(나누어떨어질 때), 2로 나누기(나누어떨어질 때), 1 빼기입니다. `dp[i]`를 `i`를 1로 만드는 최소 연산 횟수로 두고, 마지막으로 `i`에 적용하는 연산으로 경우를 나눕니다.

```js
function toOne(n) {
  const dp = new Array(n + 1).fill(0)    // dp[1] = 0
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + 1                // 1 빼기
    if (i % 2 === 0) dp[i] = Math.min(dp[i], dp[i / 2] + 1)
    if (i % 3 === 0) dp[i] = Math.min(dp[i], dp[i / 3] + 1)
  }
  return dp[n]
}
// toOne(10) → 3 (10 → 9 → 3 → 1)
```

- 이 문제는 항상 `1 빼기`가 가능하므로 불가능 상태가 없고, 초기값은 `dp[1] = 0`뿐입니다.
- 나누어떨어지면 무조건 나누는 그리디로는 틀립니다. 10은 `10 → 5 → 4 → 2 → 1`(4번)이 되지만 최소는 `10 → 9 → 3 → 1`(3번)입니다. 모든 후보를 비교하는 것이 DP입니다.
- 값이 같은 경로 중 어느 것인지를 출력해야 하면, 각 상태에서 어느 후보를 골랐는지(이전 상태)를 따로 저장해 두었다가 거슬러 올라가며 복원합니다(경로 복원은 38편과 같은 방식).
- 최대 DP는 `Math.max`로 바뀌고, 초기값은 "아직 만들 수 없음"을 `-INF`로 둡니다. 모든 값이 0 이상이면 `0`으로 시작할 수 있습니다.
- 동전·배낭처럼 여러 항목 중에서 고르는 최소·최대 DP는 41편에서 다룹니다.

**문제의 단서:** "최소 몇 번", "최대 얼마"이면서 한 번의 선택이 다음 상태를 바꾸는 문제입니다.

## 경우의 수 DP

경우의 수 DP는 점화식이 **합**이고, 서로 다른 경우를 빠짐없이 세는 DP입니다. 각 경우가 겹치지 않도록 나누는 것이 핵심입니다. 초기값 `dp[0] = 1`이 "아무것도 하지 않는 방법 한 가지"를 뜻합니다.

예제는 "1, 2, 3의 합으로 `n`을 만드는 방법의 수(순서가 다르면 다른 방법)"입니다. 마지막에 더한 수가 1, 2, 3 중 무엇인지로 나누면 `dp[i] = dp[i - 1] + dp[i - 2] + dp[i - 3]`입니다. 방법이 매우 많아져서 문제가 보통 `1,000,000,007`로 나눈 나머지를 요구합니다.

```js
function ways(n) {
  const MOD = 1000000007
  const dp = new Array(n + 1).fill(0)
  dp[0] = 1
  for (let i = 1; i <= n; i++) {
    for (let k = 1; k <= 3; k++) {
      if (i >= k) dp[i] = (dp[i] + dp[i - k]) % MOD
    }
  }
  return dp[n]
}
// n = 1, 2, 3, 4, 5 → 1, 2, 4, 7, 13
```

- 나머지는 **더할 때마다** 취합니다. 값이 `MOD`보다 작게 유지되어 합이 약 2 × 10^9로 `Number`의 안전한 범위 안에 있습니다.
- 곱하기가 들어가면 두 값의 곱이 최대 약 10^18이 되어 `2^53`을 넘고 정밀도를 잃습니다. 그때는 `BigInt`로 곱하거나 곱셈을 쪼개는 방법을 씁니다(자세히는 57편).
- 점화식의 합산 순서가 결과를 바꿉니다. 위처럼 마지막에 더한 수로 나누면 순서가 다른 조합을 서로 다른 방법으로 세고, 같은 수의 집합이면 하나로 세는 문제는 동전 DP처럼 반복문 순서가 달라집니다(자세히는 41편).
- 같은 모양의 문제: 타일 채우기(2 × n 칸을 2 × 1 타일로 채우는 방법, 점화식은 피보나치와 같음), 격자의 경로 수, 계단 경우의 수입니다.
- 정답이 너무 커서 `Number`를 넘을 수 있는데 나머지를 요구하지 않으면 `BigInt`를 씁니다.

**흔한 실수:**

- 마지막에만 `% MOD`를 하는 것입니다. 중간에 수가 `Number`의 정밀도를 넘어서 틀린 값이 나옵니다.
- 초기값 `dp[0]`을 `0`으로 두는 것입니다. 모든 값이 0이 됩니다.

## DFS + Memoization

DFS에 Memoization을 붙이는 방식은 **재귀 DFS가 같은 정점·칸을 여러 경로로 반복 방문할 때** 그 답을 저장해서 한 번만 계산하게 하는 DP입니다. 정점마다 "여기서부터의 답"을 상태로 정의하고, 점화식은 이웃 정점의 답을 합치는 DFS의 재귀 구조 그대로입니다(DFS는 36편).

예제는 "높이 격자에서 높이가 **strictly 줄어드는** 칸으로만 상하좌우 이동할 때, `(0, 0)`에서 `(H - 1, W - 1)`까지 가는 경로의 수"입니다. 정의는 `memo[r][c]` = `(r, c)`에서 도착점까지 가는 경로 수입니다. 내려가기만 하므로 같은 칸을 두 번 지나는 일이 없고 사이클이 없습니다.

아래에서 `h`는 높이 격자, `H`와 `W`는 행·열 수, `memo`는 같은 크기에 `-1`을 채운 배열, `DR`·`DC`는 방향 배열(38편)입니다.

```js
function dfs(r, c) {
  if (r === H - 1 && c === W - 1) return 1
  if (memo[r][c] !== -1) return memo[r][c]
  let sum = 0
  for (let d = 0; d < 4; d++) {
    const nr = r + DR[d], nc = c + DC[d]
    if (h[nr]?.[nc] < h[r][c]) sum += dfs(nr, nc)
  }
  return (memo[r][c] = sum)
}
// [[5,4,3],[4,3,2],[3,2,1]] → dfs(0, 0)은 6
```

- `memo`가 `-1`인 칸만 계산하고, 계산한 값은 저장합니다. 경로가 없는 칸의 값은 `0`이므로 `-1`과 구분되어 `0`도 다시 계산하지 않습니다.
- 시간복잡도는 상태 수 × 이웃 수, 즉 `O(H × W)`입니다. 메모 없이 하면 경로 수만큼 호출되어 지수입니다.
- `h[nr]?.[nc]`는 범위 밖이면 `undefined`이고 `undefined < 숫자`는 `false`라서 범위 검사를 겸합니다.
- 반환값으로 값을 합치는 재귀 구조는 22편의 "재귀 반환값"과 같습니다.
- DAG(사이클 없는 방향 그래프)에서 "정점 `u`에서 시작하는 가장 긴 경로의 길이"도 같은 방식입니다. `memo[u] = max(memo[v] + 1)`이고, 정점 번호를 위상 순서의 반대로 돌리면 Tabulation으로도 풉니다.
- **사이클이 있으면 쓸 수 없습니다.** 계산 중인 상태를 다시 만나면 값을 구할 수 없어 무한 재귀가 됩니다. 사이클이 가능한 그래프라면 37편의 방법(탐색 중 상태를 표시)으로 사이클을 먼저 걸러야 합니다.
- 재귀 깊이는 경로의 길이만큼입니다. 격자가 크면 호출 스택이 넘칠 수 있어 위상 순서 Tabulation이나 반복 DFS로 바꿉니다(자세히는 22편).

**문제의 단서:** "경로의 수", "가장 긴 경로", 방향이 정해진 이동(내리막, 한 방향 이동)이 나오면 DFS + Memoization을 의심합니다.

**흔한 실수:**

- 메모 확인을 반환값 계산 뒤에 하는 것입니다. 그러면 메모가 있어도 호출이 계속 일어납니다.
- 방문 처리(`visited`)와 메모를 혼동하는 것입니다. 일반 DFS의 `visited`는 정점을 한 번만 방문하게 막고, 메모이제이션은 같은 정점을 여러 경로로 다시 방문하면서도 계산을 한 번만 하게 합니다.

## 핵심 정리

- DP는 부분 문제의 답을 저장해 재사용하는 방법이며, 최적 부분 구조와 중복되는 부분 문제가 있을 때 쓰고 시간은 상태 수 × 전이 수입니다.
- 풀이는 상태 정의, 점화식, 초기값, 계산 순서, 답의 위치를 정하는 일이며, 점화식은 마지막 선택으로 경우를 나누어 세웁니다.
- Memoization은 재귀 + 캐시(필요한 상태만, 스택 사용)이고, Tabulation은 반복문으로 표를 채웁니다(전부 계산, 스택 없음).
- 불가능 상태는 최소 DP에서 큰 값, 최대 DP에서 작은 값으로 두고, `Int32Array`에는 `Infinity`를 넣지 말며 `-1`로 두면 `Math.min`이 망가집니다.
- 경우의 수 DP는 `dp[0] = 1`로 시작해 합하고 나머지는 더할 때마다 취하며, 곱하기에서는 `Number`가 정밀도를 잃을 수 있습니다.
- DFS + Memoization은 방향이 정해진 DAG에서 정점별 답을 한 번만 계산하게 하며, 사이클이 있으면 쓸 수 없습니다.
