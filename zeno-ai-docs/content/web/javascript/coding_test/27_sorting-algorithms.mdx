정렬 문제는 대부분 내장 `sort`(26편)로 풉니다. 정렬 알고리즘을 직접 구현하는 이유는 두 가지입니다. 원리를 알면 정렬이 끼어 있는 문제를 변형할 수 있고, 병합 정렬·퀵 정렬의 뼈대를 고쳐 쓰는 유형(역순쌍, K번째 수)이 있기 때문입니다. 아래 구현은 모두 숫자 배열을 오름차순으로 정렬하며, 작은 입력으로 동작을 따라갑니다.

공통 도구로 두 값을 바꾸는 함수를 씁니다.

```js
function swap(a, i, j) {
  const t = a[i]; a[i] = a[j]; a[j] = t
}
```

## 버블 정렬

버블 정렬(bubble sort)은 이웃한 두 요소를 비교해 순서가 틀리면 바꾸는 과정을 배열 끝까지 반복합니다. 한 번 훑을 때마다 가장 큰 값이 맨 뒤로 떠오릅니다.

```js
function bubbleSort(a) {
  for (let i = 0; i < a.length - 1; i++) {
    let swapped = false
    for (let j = 0; j < a.length - 1 - i; j++) {
      if (a[j] > a[j + 1]) {
        swap(a, j, j + 1)
        swapped = true
      }
    }
    if (!swapped) break   // 교환이 없으면 이미 정렬됨
  }
  return a
}
```

`[5, 2, 4, 1]`의 훑기 결과입니다.

| 훑기 | 배열 | 확정된 값 |
|------|------|-----------|
| 시작 | 5, 2, 4, 1 | |
| 1회 | 2, 4, 1, 5 | 5 |
| 2회 | 2, 1, 4, 5 | 4 |
| 3회 | 1, 2, 4, 5 | 2 |

- 안쪽 반복은 `a.length - 1 - i`까지만 돕니다. 뒤쪽 `i`개는 이미 확정되었기 때문입니다.
- 시간은 최악·평균 O(N²), `swapped` 검사를 넣으면 이미 정렬된 입력에서 O(N)입니다. 공간은 O(1)이고 안정 정렬입니다(`>`일 때만 바꾸므로 같은 값은 순서가 유지됨).
- N이 커지면 시간 안에 끝나지 않습니다. 개념 문제와 N이 매우 작은 경우에만 의미가 있습니다.

**시험에서 묻는 방식:** k회 훑은 뒤의 배열 상태나 교환 횟수를 묻습니다. 교환 횟수는 역순쌍 개수(아래)와 같습니다.

## 선택 정렬

선택 정렬(selection sort)은 아직 정렬되지 않은 구간에서 가장 작은 값을 찾아 구간의 맨 앞과 바꿉니다.

```js
function selectionSort(a) {
  for (let i = 0; i < a.length - 1; i++) {
    let min = i
    for (let j = i + 1; j < a.length; j++) {
      if (a[j] < a[min]) min = j
    }
    swap(a, i, min)
  }
  return a
}
```

`[5, 2, 4, 1, 3]`의 결과입니다.

| i | 최솟값 위치 | 교환 후 배열 |
|---|-------------|--------------|
| 0 | 3 (값 1) | 1, 2, 4, 5, 3 |
| 1 | 1 (값 2) | 1, 2, 4, 5, 3 |
| 2 | 4 (값 3) | 1, 2, 3, 5, 4 |
| 3 | 4 (값 4) | 1, 2, 3, 4, 5 |

- 비교 횟수는 입력과 상관없이 N(N-1)/2번이라 최선·평균·최악이 모두 O(N²)입니다. 교환은 최대 N-1번뿐입니다.
- 공간은 O(1)입니다. 안정 정렬이 아닙니다. `[2a, 2b, 1]`에서 `1`이 `2a`와 자리를 바꾸면 `[1, 2b, 2a]`가 되어 같은 값의 순서가 뒤집힙니다.
- 교환 횟수가 중요한 상황(쓰기 비용이 큰 경우)에서만 장점이 있습니다.

## 삽입 정렬

삽입 정렬(insertion sort)은 앞쪽을 정렬된 구간으로 보고, 다음 요소를 그 구간의 알맞은 자리에 끼워 넣습니다. 카드를 한 장씩 뽑아 손에 든 정렬된 카드 사이에 넣는 방식입니다.

```js
function insertionSort(a) {
  for (let i = 1; i < a.length; i++) {
    const x = a[i]
    let j = i - 1
    while (j >= 0 && a[j] > x) {
      a[j + 1] = a[j]    // 큰 값을 한 칸 뒤로 민다
      j--
    }
    a[j + 1] = x
  }
  return a
}
```

`[5, 2, 4, 1, 3]`의 결과입니다. 매번 앞쪽이 정렬된 상태를 유지합니다.

| i | 끼워 넣는 값 | 결과 배열 |
|---|--------------|-----------|
| 1 | 2 | 2, 5, 4, 1, 3 |
| 2 | 4 | 2, 4, 5, 1, 3 |
| 3 | 1 | 1, 2, 4, 5, 3 |
| 4 | 3 | 1, 2, 3, 4, 5 |

- 시간은 최악·평균 O(N²), 이미 정렬된 입력은 O(N)입니다. 밀어야 할 칸 수가 역순쌍 개수와 같아서 시간은 O(N + 역순쌍 수)입니다.
- 공간은 O(1)이고 안정 정렬입니다(`>`일 때만 밀므로 같은 값은 지나치지 않음).
- 거의 정렬된 입력이나 아주 작은 입력에서 빠릅니다. 역순쌍이 적을수록 밀 칸이 적기 때문입니다.

## 병합 정렬

병합 정렬(merge sort)은 배열을 반으로 나눠 각각 정렬한 뒤, 정렬된 두 절반을 하나로 병합합니다. 분할 정복의 대표 예입니다(25편).

```js
function merge(a, tmp, lo, mid, hi) { // [lo,mid) [mid,hi)
  let i = lo, j = mid, k = lo
  while (i < mid && j < hi) {
    tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++]
  }
  while (i < mid) tmp[k++] = a[i++]     // 왼쪽 남은 것
  for (let t = lo; t < k; t++) a[t] = tmp[t]
}
```

```js
function mergeSort(a) {
  const tmp = new Array(a.length)
  function sort(lo, hi) {               // 구간 [lo, hi)
    if (hi - lo <= 1) return
    const mid = (lo + hi) >> 1
    sort(lo, mid)
    sort(mid, hi)
    merge(a, tmp, lo, mid, hi)
  }
  sort(0, a.length)
  return a
}
```

- 병합은 왼쪽 앞과 오른쪽 앞 중 작은 쪽을 `tmp`에 옮기는 일을 반복합니다. 한쪽이 바닥나면 남은 쪽을 붙입니다. 오른쪽이 남으면 이미 제자리에 있어서 복사할 필요가 없습니다.
- `a[i] <= a[j]`에서 같은 값일 때 왼쪽을 먼저 꺼내므로 안정 정렬입니다. `<`로 쓰면 안정성이 깨집니다.
- 깊이가 log N이고 각 깊이에서 전체 N개를 한 번씩 병합하므로 시간은 항상 O(N log N)입니다. 공간은 `tmp` 때문에 O(N)입니다.
- `slice`로 새 배열을 만드는 구현은 짧지만 호출마다 배열을 할당해 느립니다. 큰 N에서는 위처럼 `tmp` 하나를 재사용합니다.
- 재귀 깊이는 log N이라 호출 스택 걱정이 없습니다.

**병합 과정의 예:** `[3, 1, 4, 2]`는 `[3, 1]`, `[4, 2]`로 나뉘고 각각 `[1, 3]`, `[2, 4]`가 된 뒤 병합되어 `[1, 2, 3, 4]`가 됩니다.

## 퀵 정렬

퀵 정렬(quick sort)은 피벗(pivot) 하나를 고르고, 피벗보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 가른(partition) 뒤 양쪽을 각각 정렬합니다. 병합 정렬과 달리 결합 단계가 없습니다. 가르는 순간 피벗이 최종 위치에 놓이기 때문입니다.

피벗과 같은 값이 많아도 느려지지 않도록 세 구간(작은 값, 같은 값, 큰 값)으로 가르는 방식을 씁니다. 세 구간 분할은 네덜란드 국기 문제(30편)와 같은 기법입니다.

```js
function partition3(a, lo, hi) {      // 닫힌 구간 [lo, hi]
  const n = hi - lo + 1
  const p = a[lo + Math.floor(Math.random() * n)]
  let lt = lo, i = lo, gt = hi
  while (i <= gt) {
    if (a[i] < p) swap(a, lt++, i++)
    else if (a[i] > p) swap(a, i, gt--)
    else i++
  }
  return [lt, gt]   // a[lt..gt]는 모두 피벗과 같다
}
```

```js
function quickSort(a, lo = 0, hi = a.length - 1) {
  if (lo >= hi) return a
  const [lt, gt] = partition3(a, lo, hi)
  quickSort(a, lo, lt - 1)
  quickSort(a, gt + 1, hi)
  return a
}
```

`[3, 1, 4, 1, 5]`에서 피벗 3을 고르면 가른 뒤 `[1, 1, 3, 4, 5]`가 됩니다. 가르는 과정의 상태입니다.

| 단계 | 보는 값 | 배열 | lt, i, gt |
|------|---------|------|-----------|
| 시작 | | 3, 1, 4, 1, 5 | 0, 0, 4 |
| 1 | 3 (같음) | 3, 1, 4, 1, 5 | 0, 1, 4 |
| 2 | 1 (작음) | 1, 3, 4, 1, 5 | 1, 2, 4 |
| 3 | 4 (큼) | 1, 3, 5, 1, 4 | 1, 2, 3 |
| 4 | 5 (큼) | 1, 3, 1, 5, 4 | 1, 2, 2 |
| 5 | 1 (작음) | 1, 1, 3, 5, 4 | 2, 3, 2 |

마지막에 `lt = 2`, `gt = 2`이므로 인덱스 2의 3이 확정이고, 왼쪽 `[1, 1]`과 오른쪽 `[5, 4]`를 재귀로 정렬합니다.

- 평균 O(N log N)이고 최악은 O(N²)입니다. 최악은 피벗이 매번 최솟값이나 최댓값이어서 한쪽이 비는 경우입니다. 피벗을 `Math.random`으로 고르면 입력 순서에 의존한 최악을 피합니다.
- 이미 정렬된 입력에서 첫 값이나 마지막 값을 피벗으로 쓰면 최악이 되고 재귀 깊이도 N까지 늘어 호출 스택이 넘칩니다(자세히는 86편). 무작위 피벗이 이를 막습니다.
- 공간은 재귀 깊이만큼 평균 O(log N)이고, 제자리 정렬입니다. 안정 정렬이 아닙니다. 가르는 과정에서 같은 값의 순서가 바뀝니다.
- 대표적인 분할 방식으로 Lomuto와 Hoare가 있습니다. 두 방식 모두 같은 값이 많으면 한쪽으로 쏠릴 수 있어 위의 세 구간 분할이 안전합니다.

**흔한 실수:** 두 구간 분할에 같은 값을 한쪽에만 몰아넣어 모든 값이 같은 입력에서 O(N²)이 되는 것입니다.

## 계수 정렬 (Counting Sort)

계수 정렬(counting sort)은 값끼리 비교하지 않고, 각 값이 몇 번 나왔는지 센 뒤 작은 값부터 그 횟수만큼 출력합니다. 값의 범위가 0부터 K까지로 작을 때 씁니다.

```js
function countingSort(a, K) {          // 값은 0 이상 K 이하 정수
  const cnt = new Array(K + 1).fill(0)
  for (const x of a) cnt[x]++
  const out = []
  for (let v = 0; v <= K; v++) {
    for (let c = 0; c < cnt[v]; c++) out.push(v)
  }
  return out
}
countingSort([2, 5, 3, 0, 2, 3, 0, 3], 5)
// cnt는 [2, 0, 2, 3, 0, 1] → [0, 0, 2, 2, 3, 3, 3, 5]
```

- 시간 O(N + K), 공간 O(K)(출력 배열 제외)입니다. 비교를 하지 않아서 아래의 N log N 하한을 받지 않습니다.
- K가 N에 비해 아주 크면 `cnt` 배열이 커져 오히려 느리고 메모리를 많이 씁니다. 값 범위가 100만 정도까지이거나 N과 비슷한 경우에 알맞습니다.
- 음수가 있으면 최솟값을 빼서 0부터 시작하게 맞춥니다(`cnt[x - min]`).
- 값만 정렬하면 되는 위 방식은 안정성이 의미가 없습니다. 레코드(값에 딸린 데이터)를 정렬하려면 누적 개수로 각 값의 출력 위치를 정하고 입력을 앞에서부터 놓는 안정 버전을 씁니다.

```js
function countingSortBy(recs, K, key) { // key는 0 이상 K 이하
  const pos = new Array(K + 2).fill(0)
  for (const r of recs) pos[key(r) + 1]++
  for (let v = 1; v <= K + 1; v++) pos[v] += pos[v - 1]
  const out = new Array(recs.length)
  for (const r of recs) out[pos[key(r)]++] = r   // 앞에서부터
  return out
}
```

- `pos[v]`는 값 `v`의 첫 출력 위치입니다. 같은 값은 입력 순서대로 놓이므로 안정 정렬입니다. 이 안정성이 아래 기수 정렬의 전제입니다.
- 값 범위가 큰 경우(예: 최대 10^9)에는 계수 정렬을 쓸 수 없고 일반 정렬을 씁니다.

## 정렬 시간복잡도

지금까지의 알고리즘을 비교합니다. N은 요소 수, K는 값의 범위, d는 자릿수입니다.

| 알고리즘 | 최선 | 평균 | 최악 | 추가 공간 | 안정 |
|----------|------|------|------|-----------|------|
| 버블 (조기 종료) | O(N) | O(N²) | O(N²) | O(1) | 예 |
| 선택 | O(N²) | O(N²) | O(N²) | O(1) | 아니오 |
| 삽입 | O(N) | O(N²) | O(N²) | O(1) | 예 |
| 병합 | O(N log N) | O(N log N) | O(N log N) | O(N) | 예 |
| 퀵 (무작위 피벗) | O(N log N) | O(N log N) | O(N²) | O(log N) | 아니오 |
| 계수 | O(N + K) | O(N + K) | O(N + K) | O(K) | 안정 버전은 예 |
| 기수 (LSD) | O(d(N + 10)) | O(d(N + 10)) | O(d(N + 10)) | O(N) | 예 |

- 버블·선택·삽입은 O(N²)이라 N이 커지면 쓰지 않습니다.
- 병합 정렬은 입력과 무관하게 O(N log N)이 보장되고 안정적이지만 추가 공간이 듭니다.
- 퀵 정렬은 상수가 작아 빠르지만 최악이 있습니다. 무작위 피벗으로 확률적으로 피합니다.
- 입력 크기별 허용 복잡도는 14편에서 다룹니다.
- 코딩테스트의 JavaScript에서는 내장 `sort`가 최악 O(N log N)에 안정적이므로(26편) 일반 정렬은 이것을 씁니다. 정수 배열이 크면 `Int32Array`·`Float64Array`의 `sort()`를 쓰는 방법도 있습니다(05편).

## 기수 정렬

기수 정렬(radix sort)은 자릿수 단위로 정렬하는 방법입니다. 가장 낮은 자릿수(LSD, least significant digit)부터 높은 자릿수까지, 각 자릿수를 기준으로 안정 정렬을 반복합니다. 자릿수별 정렬에는 계수 정렬을 씁니다.

```js
function countingByDigit(arr, exp) {
  const cnt = new Array(10).fill(0)
  const digit = (x) => Math.floor(x / exp) % 10
  for (const x of arr) cnt[digit(x)]++
  for (let d = 1; d < 10; d++) cnt[d] += cnt[d - 1]
  const out = new Array(arr.length)
  for (let i = arr.length - 1; i >= 0; i--) {
    out[--cnt[digit(arr[i])]] = arr[i]   // 뒤에서부터 안정
  }
  return out
}
```

```js
function radixSort(a) {                  // 0 이상의 정수
  let max = 0
  for (const x of a) max = Math.max(max, x)
  let out = a
  for (let exp = 1; exp <= max; exp *= 10) {
    out = countingByDigit(out, exp)
  }
  return out
}
```

`[170, 45, 75, 90, 802, 24, 2, 66]`의 자릿수별 결과입니다.

| 기준 자릿수 | 정렬 후 배열 |
|-------------|--------------|
| 1의 자리 | 170, 90, 802, 2, 24, 45, 75, 66 |
| 10의 자리 | 802, 2, 24, 45, 66, 170, 75, 90 |
| 100의 자리 | 2, 24, 45, 66, 75, 90, 170, 802 |

- 낮은 자릿수부터 처리해도 맞는 이유는 각 단계가 안정 정렬이라서, 높은 자릿수가 같은 값끼리는 앞 단계의 순서(낮은 자릿수 순)가 유지되기 때문입니다.
- 시간은 O(d(N + B))이고 B는 진법의 밑(위 코드는 10)입니다. 값이 정수이고 자릿수 d가 작을 때 O(N)에 가깝습니다.
- 한 자릿수 정렬이 안정적이지 않으면 결과가 틀립니다. 그래서 위 코드는 뒤에서부터 위치를 채웁니다.
- 음수는 부호를 따로 처리하거나 최솟값을 더해 0 이상으로 맞춥니다.
- 밑을 256이나 65536으로 키우면 패스 수가 줄어듭니다. 비트 연산을 쓸 때는 32비트 정수 제한에 주의합니다(24편).

## 비교 정렬의 하한 Ω(N log N)

비교 정렬은 요소끼리 비교(`<` 등)한 결과로만 순서를 정하는 정렬이고, 어떤 비교 정렬도 최악에 Ω(N log N)번의 비교가 필요합니다. 버블·선택·삽입·병합·퀵은 모두 비교 정렬입니다.

이유는 결정 트리 논증입니다.

- N개 요소의 가능한 순열은 N!가지입니다. 정렬 알고리즘은 입력이 이 중 어느 순열인지 가려내야 합니다.
- 비교 한 번은 결과가 둘(참, 거짓)이라서 비교를 k번 하면 최대 2^k가지 경우만 가려낼 수 있습니다.
- 따라서 2^k ≥ N!, 곧 k ≥ log2(N!)이 필요합니다.
- N!은 (N/2)^(N/2) 이상이므로 log2(N!)은 (N/2) log2(N/2) 이상이고 Θ(N log N)입니다.

| N | 순열 수 N! | 필요한 최소 비교 수 (올림 log2 N!) |
|---|------------|-----------------------------------|
| 3 | 6 | 3 |
| 4 | 24 | 5 |
| 5 | 120 | 7 |

- 병합 정렬은 이 하한과 같은 O(N log N)이라서 비교 정렬 중 점근적으로 최적입니다.
- 계수 정렬과 기수 정렬이 O(N)에 가까운 것은 요소를 비교하지 않고 값 자체를 인덱스로 쓰기 때문입니다. 하한은 비교 정렬에만 적용됩니다. 대신 값의 범위나 자릿수에 제약이 붙습니다.

## 퀵 선택 (K번째 수)

퀵 선택(quickselect)은 퀵 정렬의 가르기를 이용해 정렬하지 않고 K번째로 작은 수를 찾는 방법입니다. 가른 뒤 K번째가 있는 쪽 한 구간만 이어서 처리합니다. 평균 O(N)입니다.

```js
function kthSmallest(a, k) {          // k는 0부터. a를 재배열한다
  let lo = 0, hi = a.length - 1
  while (lo < hi) {
    const [lt, gt] = partition3(a, lo, hi)
    if (k < lt) hi = lt - 1           // 왼쪽 구간에 있다
    else if (k > gt) lo = gt + 1      // 오른쪽 구간에 있다
    else return a[k]                  // 피벗과 같은 값 구간
  }
  return a[lo]
}
kthSmallest([7, 2, 9, 4, 1], 2) // 4 (정렬하면 1, 2, 4, 7, 9)
```

- 가를 때마다 구간이 줄어서 비용이 N + N/2 + N/4 + ... = 약 2N이 되므로 평균 O(N)입니다. 최악은 O(N²)이고 무작위 피벗으로 확률적으로 피합니다.
- 정렬은 O(N log N)이므로 N이 크고 K번째 하나만 필요할 때 이득입니다. 여러 번 질의하거나 K개 전부 필요하면 한 번 정렬하는 편이 낫습니다.
- 큰 쪽 K번째는 `k = a.length - 1 - k`로 바꿔 부릅니다.
- 입력 배열이 가르기 과정에서 재배열됩니다. 원본이 필요하면 복사해서 넘깁니다.
- 힙으로도 K번째 수를 구할 수 있습니다(46편).

**흔한 실수:** `k`를 1부터 세는 문제에서 0부터 세는 코드에 그대로 넘겨 한 칸 어긋나는 것입니다.

## 병합 정렬로 역순쌍 세기

역순쌍(inversion)은 `i < j`이면서 `a[i] > a[j]`인 쌍입니다. 정렬된 정도를 재는 값이고, 버블 정렬의 교환 횟수와 같습니다. 모든 쌍을 비교하면 O(N²)이지만 병합 정렬 중에 세면 O(N log N)입니다.

병합할 때 오른쪽 값을 먼저 꺼내는 순간, 왼쪽에 남은 모든 값이 그 오른쪽 값보다 큽니다. 그 개수 `mid - i`가 새로 확인된 역순쌍입니다.

```js
function mergeCount(a, tmp, lo, mid, hi) {
  let i = lo, j = mid, k = lo, cnt = 0
  while (i < mid && j < hi) {
    if (a[i] <= a[j]) tmp[k++] = a[i++]
    else { tmp[k++] = a[j++]; cnt += mid - i }  // 역순쌍
  }
  while (i < mid) tmp[k++] = a[i++]
  for (let t = lo; t < k; t++) a[t] = tmp[t]
  return cnt
}
```

```js
function countInv(a) {
  const tmp = new Array(a.length)
  const go = (lo, hi) => {
    if (hi - lo <= 1) return 0
    const mid = (lo + hi) >> 1
    const left = go(lo, mid), right = go(mid, hi)
    return left + right + mergeCount(a, tmp, lo, mid, hi)
  }
  return go(0, a.length)
}
countInv([2, 4, 1, 3, 5]) // 3 (2,1) (4,1) (4,3)
```

`[2, 4, 1, 3, 5]`는 `[2, 4]`와 `[1, 3, 5]`로 나뉩니다. 병합할 때의 흐름입니다.

| 병합 단계 | 비교 | 꺼낸 값 | 더해진 역순쌍 |
|-----------|------|---------|---------------|
| 1 | 2 대 1 | 1 (오른쪽) | 왼쪽에 남은 2, 4 → 2 |
| 2 | 2 대 3 | 2 (왼쪽) | 0 |
| 3 | 4 대 3 | 3 (오른쪽) | 왼쪽에 남은 4 → 1 |
| 4 | 4 대 5 | 4 (왼쪽) | 0 |

- 두 절반 안의 역순쌍은 재귀가 세고, 병합이 절반 사이에 걸친 쌍을 셉니다. 합이 전체 역순쌍입니다.
- 같은 값은 역순쌍이 아니므로 `a[i] <= a[j]`일 때 왼쪽을 먼저 꺼내 셈에 넣지 않습니다. 부등호를 `<`로 쓰면 같은 값이 중복으로 세어집니다.
- 역순쌍은 최대 N(N-1)/2입니다. N이 10^6이면 약 5 × 10^11이라 32비트 정수를 넘습니다. JavaScript의 `Number`는 2^53 근처까지 정확하므로 `cnt`는 그대로 `Number`로 둬도 되지만, 비트 연산(`| 0`, `>> 0`)으로 합치면 안 됩니다(자세히는 02편).
- 같은 병합 구조로 "각 요소의 오른쪽에 있는 더 작은 값의 개수"도 셀 수 있습니다. 왼쪽 값을 꺼내는 순간 이미 꺼낸 오른쪽 값의 개수가 그 요소의 답입니다. 이런 질의는 펜윅 트리로도 풉니다(64편).
- 문제 문장의 단서는 "교환 횟수의 최솟값", "순서가 뒤바뀐 쌍의 개수", "N이 10^5 이상인데 쌍을 센다"입니다.

## 핵심 정리

- 버블·선택·삽입은 O(N²)이고 삽입·버블(조기 종료)은 정렬된 입력에서 O(N)이며, 선택 정렬만 안정적이지 않습니다.
- 병합 정렬은 항상 O(N log N)에 안정적이고 추가 공간 O(N)이 들며, 퀵 정렬은 평균 O(N log N)에 최악 O(N²)이고 무작위 피벗과 세 구간 분할로 대비합니다.
- 계수 정렬은 O(N + K), 기수 정렬은 자릿수별 안정 계수 정렬을 반복해 O(d(N + B))이며 둘 다 값의 범위나 자릿수 제약이 있습니다.
- 비교 정렬은 결정 트리 논증에 따라 최악 Ω(N log N)번 비교가 필요하고, 비교를 쓰지 않는 계수·기수 정렬은 이 하한을 받지 않습니다.
- 퀵 선택은 가르기 후 한 쪽만 이어 평균 O(N)에 K번째 수를 구하고, 병합 정렬은 오른쪽 값을 먼저 꺼낼 때 왼쪽 남은 개수를 더해 역순쌍을 O(N log N)에 셉니다.
