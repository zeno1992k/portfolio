## Number와 BigInt

JavaScript의 숫자 자료형은 둘입니다. `number`는 64비트 부동소수점(IEEE 754 배정밀도)이고, `bigint`는 크기 제한이 없는 정수입니다. BigInt는 ES2020에 추가되었습니다.

| 항목 | `number` | `bigint` |
|------|----------|----------|
| 값 | 정수와 실수 모두 | 정수만 |
| 범위 | 정확한 정수는 ±(2^53 − 1)까지 | 제한 없음(메모리 한도) |
| 리터럴 | `10`, `1.5`, `1e9` | `10n` |
| 특수 값 | `NaN`, `Infinity` | 없음 |
| 나눗셈 | 실수 결과 | 0 방향으로 버린 정수 |
| `typeof` | `'number'` | `'bigint'` |

```js
const a = 9007199254740993n   // 정확히 저장됨
const b = BigInt('123456789012345678901234567890')
const c = BigInt(10)          // 10n (new 없이 호출)
typeof a                      // 'bigint'
5n / 2n                       // 2n
2n ** 100n   // 1267650600228229401496703205376n
```

- 대부분의 문제는 `number`로 충분합니다. 값이 약 9 × 10^15(2^53)를 넘을 수 있을 때만 BigInt를 씁니다.
- `BigInt(x)`에 정수가 아닌 값을 넘기면 RangeError, 문자열이 정수 형식이 아니면 SyntaxError입니다. `new BigInt(1)`은 TypeError입니다.
- `0n`만 거짓이고 나머지 BigInt는 참입니다.
- `BigInt`에는 `Math` 함수를 쓸 수 없고 단항 `+`(`+1n`)도 TypeError입니다.
- 배열의 기본 `sort()`는 값을 문자열로 바꿔 비교하므로 BigInt 배열도 `[1n, 10n, 9n]` 순서가 됩니다. 비교 함수는 `(a, b) => (a < b ? -1 : a > b ? 1 : 0)`처럼 씁니다. `(a, b) => a - b`는 BigInt를 반환하는데 `sort`가 이를 숫자로 바꾸지 못해 TypeError입니다(자세히는 26편).

BigInt는 JSON으로 직렬화할 수 없습니다.

```js
JSON.stringify({ a: 1n })  // TypeError
```

**흔한 실수:** BigInt를 `console.log(10n)`으로 출력하는 것입니다. Node.js는 `10n`처럼 `n`을 붙여 보여 줍니다. 제출용 출력에서는 `String(x)`, `x.toString()`, 템플릿 리터럴로 문자열로 바꿉니다(자세히는 08편).

## Number.MAX_SAFE_INTEGER

`Number.MAX_SAFE_INTEGER`는 `number`가 정수를 오차 없이 나타내는 가장 큰 값 2^53 − 1 = 9007199254740991입니다. 반대쪽 한계는 `Number.MIN_SAFE_INTEGER`(−9007199254740991)입니다.

```js
Number.MAX_SAFE_INTEGER       // 9007199254740991
2 ** 53                       // 9007199254740992
2 ** 53 + 1                   // 9007199254740992 (틀림)
9007199254740993              // 9007199254740992 (리터럴도 틀림)
```

- 이 범위를 넘으면 서로 다른 정수가 같은 값으로 합쳐지고, 숫자 사이의 간격이 2 이상으로 벌어집니다.
- 덧셈·뺄셈·곱셈은 입력과 결과가 모두 안전 범위 안이면 정확합니다. 중간 계산이 한 번이라도 범위를 넘으면 그 뒤 결과는 믿을 수 없습니다.
- `Number.isSafeInteger(x)`는 `x`가 정수이면서 안전 범위 안일 때 `true`입니다.
- 입력 문자열의 정수가 안전 범위를 넘을 수 있으면 `Number()`로 바꾸기 전에 BigInt로 읽습니다. 이미 `Number`로 바꾼 뒤에는 복구할 수 없습니다.

```js
Number('9007199254740993')   // 9007199254740992
BigInt('9007199254740993')   // 9007199254740993n
```

**흔한 실수:** 나머지를 구하기 전에 곱셈이 넘치는 것입니다. 모듈러 연산 문제에서 `a * b % M`의 `a * b`가 2^53을 넘으면 틀립니다. `M = 1e9 + 7`일 때 `a`, `b`가 `M` 가까운 값이면 곱이 약 10^18이라서 이 경우에 해당합니다. `(1e9 + 6) * (1e9 + 6) % (1e9 + 7)`은 정답 1이 아니라 `999999972`가 나옵니다. 이때는 BigInt로 곱합니다.

```js
const M = 1_000_000_007n
const r = (BigInt(a) * BigInt(b)) % M   // BigInt 곱셈
Number(r)                               // 다시 number로
```

## 부동소수점 오차와 Number.EPSILON

`number`는 2진수로 저장하기 때문에 `0.1`처럼 2진수로 딱 떨어지지 않는 소수는 근삿값이고, 계산하면 오차가 쌓입니다.

```js
0.1 + 0.2          // 0.30000000000000004
0.1 + 0.2 === 0.3  // false
1.1 * 3            // 3.3000000000000003
0.57 * 100         // 56.99999999999999
```

- 실수를 `===`로 비교하지 않습니다. 두 값의 차이가 허용 오차보다 작은지로 비교합니다.
- `Number.EPSILON`은 1과 그다음으로 큰 표현 가능한 수의 차이 2^−52(약 2.22 × 10^−16)입니다. 크기가 1 근처인 값끼리 비교할 때만 허용 오차로 적절합니다.

```js
const eq = (x, y) => Math.abs(x - y) < Number.EPSILON
eq(0.1 + 0.2, 0.3)       // true
eq(1000.1 + 1000.2, 2000.3) // false (값이 커서 오차도 커짐)
```

- 값이 크면 오차도 커지므로 `Number.EPSILON`에 값의 크기를 곱하거나, 문제가 허용하는 오차(예: `1e-9`)를 직접 씁니다.
- 가능하면 소수를 쓰지 않고 정수로 바꿔 계산합니다. 금액은 최소 단위(전, 센트)의 정수로, 소수점 둘째 자리까지의 값은 100배한 정수로 다루면 오차가 없습니다.
- 소수를 정수로 바꿀 때 `0.57 * 100`처럼 곱하면 오차가 생기므로 `Math.round(x * 100)`으로 반올림합니다(`56.99999999999999`가 `57`이 됨).

## 정수 판별

`Number.isInteger(x)`는 `x`가 `number`이고 소수 부분이 없을 때 `true`입니다. 문자열은 변환하지 않고 바로 `false`입니다.

```js
Number.isInteger(5)        // true
Number.isInteger(5.0)      // true (같은 값)
Number.isInteger(5.5)      // false
Number.isInteger('5')      // false
Number.isInteger(NaN)      // false
Number.isInteger(Infinity) // false
```

- `5.0`과 `5`는 같은 값이라서 `true`입니다.
- `Number.isInteger(2 ** 53)`은 `true`입니다. 안전한 정수인지는 `Number.isSafeInteger`로 따로 확인합니다.
- 비슷한 전역 함수 `isNaN('abc')`는 인수를 숫자로 바꾼 뒤 검사해서 `true`가 되고, `Number.isNaN('abc')`는 `false`입니다. 전역 `isFinite('5')`도 문자열을 변환해 `true`이지만 `Number.isFinite('5')`는 `false`입니다. `Number.` 쪽을 씁니다.
- `x % 1 === 0`으로도 판별할 수 있지만 `'5' % 1 === 0`이 `true`여서 문자열을 걸러 내지 못합니다. `Number.isInteger`를 씁니다.
- 부동소수점 오차 때문에 계산한 결과가 정수여야 하는데 `3.0000000000000004`가 되는 경우가 있습니다. 이때 `Number.isInteger`는 `false`입니다. 정수 연산은 처음부터 정수로 합니다.

## parseInt와 Number 변환의 차이

둘 다 문자열을 숫자로 바꾸지만 규칙이 다릅니다. `Number(s)`는 문자열 전체가 숫자 형식이어야 하고, `parseInt(s, radix)`는 앞에서부터 읽을 수 있는 만큼 읽고 멈춥니다.

| 입력 | `Number(s)` | `parseInt(s, 10)` |
|------|-------------|-------------------|
| `'42'` | 42 | 42 |
| `'  42  '` | 42 | 42 |
| `'12px'` | NaN | 12 |
| `''` | 0 | NaN |
| `'3.9'` | 3.9 | 3 |
| `'1e3'` | 1000 | 1 |
| `'0x1f'` | 31 | 0 |
| `'1_000'` | NaN | 1 |
| `null` | 0 | NaN |

- `Number('')`가 `0`이고 `parseInt('')`가 `NaN`입니다. 입력이 빈 줄일 수 있는 경우를 구분해야 합니다.
- `parseInt`는 정수 부분만 읽어서 `'3.9'`가 `3`입니다. 소수까지 읽으려면 `parseFloat`를 씁니다.
- 둘 다 앞쪽 공백을 건너뜁니다. `Number`는 뒤쪽 공백도 허용하지만 그 밖의 문자가 끼면 `NaN`이고, `parseInt`는 읽을 수 없는 문자에서 멈추고 앞부분을 돌려줍니다.
- `parseInt`의 두 번째 인수는 진법(2–36)입니다. 생략하면 `0x`로 시작할 때만 16진수로 읽고 나머지는 10진수로 읽습니다. 2–36 밖의 값은 `NaN`입니다. 진법을 항상 적는 것이 안전합니다.
- 진법을 지정해 읽을 때는 `parseInt(s, 2)`처럼 씁니다. 접두사 `0b`, `0o`는 `Number('0b101')`만 해석하고 `parseInt('0b101', 2)`는 `0`입니다(자세히는 11편).
- `parseInt`에 숫자를 넘기면 먼저 문자열로 바꾸므로 `1e21`이나 `0.0000005`는 지수 표기 문자열이 되어 `1`과 `5`처럼 엉뚱한 값이 나옵니다. 숫자를 내림하려면 `Math.trunc`를 씁니다.

**흔한 실수:** `map(parseInt)`입니다. `map`이 `(값, 인덱스, 배열)`을 넘겨서 인덱스가 진법이 됩니다.

```js
['1', '2', '3'].map(parseInt)  // [1, NaN, NaN]
['1', '2', '3'].map(Number)    // [1, 2, 3]
['1', '2', '3'].map((s) => parseInt(s, 10)) // [1, 2, 3]
```

## Math 객체

`Math`는 수학 함수와 상수를 담은 객체이고 `new`로 만들지 않습니다. 모든 메서드는 인수를 숫자로 바꿔서 계산하며, BigInt는 받지 못합니다.

| 메서드 | 동작 | 예 |
|--------|------|----|
| `Math.abs(x)` | 절댓값 | `Math.abs(-5)` → 5 |
| `Math.floor(x)` | 내림(−∞ 방향) | `Math.floor(-3.5)` → −4 |
| `Math.ceil(x)` | 올림(+∞ 방향) | `Math.ceil(-3.5)` → −3 |
| `Math.round(x)` | 반올림. 정확히 .5이면 +∞ 방향 | `Math.round(-2.5)` → −2 |
| `Math.trunc(x)` | 소수 부분 버림(0 방향) | `Math.trunc(-3.5)` → −3 |
| `Math.sign(x)` | 부호: 1, −1, 0, −0, NaN | `Math.sign(-5)` → −1 |
| `Math.max(...)`, `Math.min(...)` | 최댓값, 최솟값 | `Math.max(1, 3)` → 3 |
| `Math.pow(x, y)` | 거듭제곱(`x ** y`와 같음) | `Math.pow(2, 10)` → 1024 |
| `Math.sqrt(x)` | 제곱근. 음수는 NaN | `Math.sqrt(16)` → 4 |
| `Math.cbrt(x)` | 세제곱근 | `Math.cbrt(27)` → 3 |
| `Math.hypot(...)` | 제곱합의 제곱근 | `Math.hypot(3, 4)` → 5 |
| `Math.log2(x)` | 밑이 2인 로그 | `Math.log2(8)` → 3 |
| `Math.log10(x)` | 밑이 10인 로그 | `Math.log10(1000)` → 3 |
| `Math.random()` | 0 이상 1 미만 난수 | 0.37... |

- `Math.max()`는 인수가 없으면 `-Infinity`, `Math.min()`은 `Infinity`입니다. 인수 중 하나라도 `NaN`이면 결과는 `NaN`입니다.
- `Math.max(...arr)`는 배열이 매우 크면 RangeError가 납니다(자세히는 01편).
- `Math.round`는 `.5`일 때 항상 +∞ 쪽으로 가서 `Math.round(2.5)`는 `3`, `Math.round(-2.5)`는 `-2`입니다. 0에서 멀어지는 쪽으로 반올림하는 언어와 다릅니다.
- 같은 범위의 정수 난수는 `Math.floor(Math.random() * (max - min + 1)) + min`입니다.
- `Math.sqrt`, `Math.log` 등의 정밀도는 구현에 따라 다를 수 있다고 MDN이 밝히고 있습니다. 결과를 정수로 쓸 때는 정확한 값으로 보정합니다.
- 로그로 자릿수나 지수를 구하면 오차가 생길 수 있습니다. `Math.log(1000) / Math.log(10)`은 `2.9999999999999996`입니다. 자릿수는 `String(n).length`로 구하고, 지수는 곱셈 반복으로 구합니다.
- `Math.PI`, `Math.E`는 상수입니다. 제곱수 `x * x`는 `Math.pow`보다 `**`를 씁니다.

## Math.floor·Math.trunc와 음수 나눗셈

JavaScript의 `/`는 실수 나눗셈이라서 정수 몫은 직접 만들어야 합니다. 양수에서는 `Math.floor`와 `Math.trunc`가 같지만 음수에서는 다릅니다.

| 식 | 값 |
|----|----|
| `Math.floor(7 / 2)` | 3 |
| `Math.trunc(7 / 2)` | 3 |
| `Math.floor(-7 / 2)` | −4 |
| `Math.trunc(-7 / 2)` | −3 |

- `Math.floor`는 −∞ 방향으로 내리므로 음수는 절댓값이 커집니다. `Math.trunc`는 0 방향으로 소수 부분을 버립니다.
- `%`는 `trunc` 방식 몫과 짝입니다. `-7 % 2`는 `-1`이고, `-7 = 2 × (-3) + (-1)`이 성립합니다.
- 다른 언어의 풀이를 옮길 때는 그 언어의 나눗셈이 `floor` 방식인지 `trunc` 방식인지 먼저 확인하고 맞는 쪽을 고릅니다.
- 올림 나눗셈(`ceil`)은 양수에서 `Math.ceil(a / b)` 또는 `Math.floor((a + b - 1) / b)`입니다. 후자는 `a`, `b`가 양의 정수일 때만 맞습니다.

```js
Math.floor(-7 / 2)   // -4
Math.trunc(-7 / 2)   // -3
-7 % 2               // -1
((-7 % 2) + 2) % 2   // 1 (항상 0 이상으로 보정)
Math.ceil(7 / 2)     // 4
```

- 음수 나머지를 0 이상으로 만드는 `((a % m) + m) % m`은 11편에서 자세히 다룹니다.
- 값이 안전 정수 범위를 넘으면 `a / b`의 소수 연산 자체가 부정확해서 `Math.floor(a / b)`도 틀릴 수 있습니다. 그때는 BigInt의 `/`(0 방향 정수 나눗셈)를 씁니다.

## 정수 몫 구하기: Math.floor와 비트 연산 절삭

몫을 구하는 방법은 세 가지입니다.

```js
const a = -7, b = 2
Math.floor(a / b)  // -4 (floor)
Math.trunc(a / b)  // -3 (trunc)
(a / b) | 0        // -3 (비트 OR, trunc와 같은 결과)
~~(a / b)          // -3 (비트 NOT 두 번)
```

| 방법 | 음수 | 큰 수 | 비고 |
|------|------|-------|------|
| `Math.floor` | −∞ 방향 | 안전 범위까지 | 양수 전용으로 쓰기 좋음 |
| `Math.trunc` | 0 방향 | 안전 범위까지 | 의도가 가장 분명 |
| 비트 절삭(0과 OR, `~~`) | 0 방향 | 32비트 정수 범위만 | 범위를 넘으면 값이 깨짐 |

- `x | 0`과 `~~x`는 피연산자를 32비트 정수로 바꿔 소수 부분을 버리므로 `-2147483648`부터 `2147483647` 범위 밖에서는 값이 틀립니다.

```js
5e9 | 0              // 705032704 (틀림)
Math.trunc(5e9)      // 5000000000
2 ** 31 | 0          // -2147483648 (틀림)
```

- MDN도 `~~`보다 `Math.trunc`를 권장합니다. 몫이 32비트 안에 확실히 들어오는 경우가 아니면 비트 연산으로 절삭하지 않습니다.
- 몫과 나머지를 모두 구하고 값이 클 수 있으면 `(a - a % b) / b`로 구합니다. `a % b`는 정확하고 뺀 값은 `b`로 나누어떨어져서 오차 없이 몫이 나옵니다.

```js
const a = 100, b = 7
const r = a % b             // 2
const q = (a - r) / b       // 14 (정확한 정수 몫)
```

- 이 식의 몫은 `trunc` 방식입니다. 음수를 `floor` 방식으로 맞추려면 나머지를 보정한 뒤 같은 식에 넣습니다(자세히는 11편).

## BigInt와 Number 혼합 연산 주의

BigInt와 Number를 산술·비트 연산자로 섞으면 TypeError입니다. 비교는 섞어도 됩니다.

```js
1n + 2          // TypeError
1n + BigInt(2)  // 3n
Number(1n) + 2  // 3
1n < 2          // true (비교는 허용)
1n == 1         // true
1n === 1        // false (타입이 다름)
```

- 섞어야 하면 한쪽으로 명시적으로 변환합니다. `BigInt(n)`은 정수만 받고, `Number(b)`는 안전 범위를 넘는 값에서 정밀도를 잃습니다.
- `Number(2n ** 64n)`은 `18446744073709552000`으로 근삿값입니다. 큰 BigInt를 Number로 바꾸면 되돌릴 수 없습니다.
- `Math.sqrt`, `Math.max` 등 `Math` 함수는 BigInt를 받지 못해 TypeError입니다. 최댓값은 직접 비교하거나 `a > b ? a : b`로 씁니다.
- `+1n`(단항 `+`)과 `>>>`는 BigInt에서 TypeError입니다. BigInt는 항상 부호가 있기 때문입니다.
- BigInt의 `/`는 소수 없이 0 방향으로 버립니다: `-5n / 2n`은 `-2n`, `-5n % 2n`은 `-1n`입니다.
- `BigInt.asUintN(64, x)`와 `BigInt.asIntN(64, x)`는 x를 64비트 부호 없는/있는 정수 범위로 잘라 냅니다. 해시 계산에서 64비트 오버플로를 흉내 낼 때 씁니다.
- 한 식에서 BigInt를 쓰기로 했으면 모든 피연산자를 BigInt로 맞추고, 최종 결과를 출력할 때만 문자열로 바꿉니다.

```js
let acc = 1n
for (let i = 1n; i <= 25n; i++) acc *= i  // 25!
String(acc)   // '15511210043330985984000000'
```

## 비트 연산의 32비트 정수 변환

비트 연산자(`&`, `|`, `^`, `~`, `<<`, `>>`, `>>>`)는 피연산자를 32비트 정수로 바꿔서 계산합니다. 큰 수는 상위 비트가 버려지고, 결과는 부호 있는 32비트 정수입니다(`>>>`만 부호 없는 값).

```js
1 << 31             // -2147483648 (부호 비트가 켜짐)
2 ** 32 | 0         // 0 (상위 비트가 버려짐)
(2 ** 32 + 5) | 0   // 5
-1 >>> 0            // 4294967295 (부호 없는 값으로)
-1 >> 1             // -1 (산술 시프트: 부호 유지)
-1 >>> 1            // 2147483647 (논리 시프트: 0 채움)
```

- 시프트 양은 32로 나눈 나머지만 쓰입니다. `1 << 32`는 `1 << 0`이라서 `1`이고 `1 << 33`은 `2`입니다.
- 비트 연산 결과가 음수가 될 수 있습니다. 부호 없는 32비트 값이 필요하면 `>>> 0`을 붙입니다.
- `x >> 1`은 `Math.floor(x / 2)`와 같고 `x | 0`은 `trunc`와 같습니다. 단, 값이 `-2^31` 이상 `2^31 − 1` 이하일 때만 그렇습니다.
- 2^31 이상이거나 안전 정수 범위의 큰 수에는 비트 연산을 쓸 수 없습니다. 이 범위는 BigInt의 비트 연산(`&`, `|`, `<<`, `>>` 등)으로 처리합니다. BigInt는 상위 비트를 버리지 않습니다.
- `1 << n`은 `n`이 30 이하일 때 양수이고, 31이면 음수, 32 이상이면 값이 순환합니다. 부분집합 비트마스크는 원소가 최대 30개 정도일 때까지 Number로 안전합니다(자세히는 24편).
- `Math.imul(a, b)`는 두 수를 32비트 정수로 곱한 하위 32비트를 부호 있는 정수로 돌려줍니다. 해시 계산에서 32비트 곱셈 오버플로를 흉내 낼 때 씁니다.

**흔한 실수:** 큰 값에 `| 0`이나 `>> 0`을 써서 조용히 값이 깨지는 것입니다. 에러가 나지 않으므로 발견이 늦습니다.

## 소수점 자릿수 출력: toFixed

`x.toFixed(d)`는 `x`를 소수점 아래 `d`자리로 반올림한 문자열을 돌려줍니다. `d`는 0–100이고 밖이면 RangeError입니다.

```js
(3.14159).toFixed(2)   // '3.14'
(3).toFixed(2)         // '3.00' (0으로 자릿수 채움)
typeof (3).toFixed(2)  // 'string'
Number((3.14159).toFixed(2)) // 3.14 (숫자로)
```

- 반환값은 문자열입니다. 계산에 다시 쓰려면 `Number()`로 바꾸지만, 출력용이면 그대로 씁니다.
- 반올림은 2진수 근삿값 기준이라 우리가 기대한 결과와 다를 수 있습니다. `(1.005).toFixed(2)`는 `'1.00'`이고 `(2.55).toFixed(1)`은 `'2.5'`입니다. `1.005`가 실제로는 `1.00499999999999989...`에 가깝게 저장되기 때문입니다.
- 정확히 표현되는 값의 중간(`2.5`, `0.125` 등)은 0에서 멀어지는 쪽으로 반올림됩니다. `(2.5).toFixed(0)`은 `'3'`, `(-2.5).toFixed(0)`은 `'-3'`입니다. `Math.round(-2.5)`는 `-2`라서 다릅니다.
- `1e21` 이상인 수는 지수 표기 문자열이 됩니다. `(1e21).toFixed(2)`는 `'1e+21'`입니다.
- `NaN`, `Infinity`는 `'NaN'`, `'Infinity'` 문자열입니다.
- 음수에는 괄호가 필요합니다. `-2.34.toFixed(1)`은 `-(2.34.toFixed(1))`로 해석되어 숫자 `-2.3`이 됩니다. `(-2.34).toFixed(1)`이 문자열 `'-2.3'`입니다.
- 소수점 아래를 정확히 반올림해야 하는 문제에서는 정수로 바꿔 계산합니다: `Math.round(x * 100) / 100`은 값에 따라 오차가 남으므로, 처음부터 정수 단위로 계산하고 마지막에만 문자열로 바꿉니다.
- 문제가 "오차 1e-6 이내"처럼 허용 오차를 주면 `toFixed(9)`처럼 넉넉하게 출력합니다.
- `(-0.0001).toFixed(2)`처럼 반올림 결과가 0이 되는 음수는 `'-0.00'`이 됩니다. 출력 형식에 맞는지 확인합니다.

## 진법 문자열: toString(radix)

`n.toString(radix)`는 숫자를 `radix`진법 문자열로, `parseInt(s, radix)`는 그 반대로 바꿉니다. 진법은 2–36이고 밖이면 RangeError입니다.

```js
(255).toString(2)       // '11111111'
(255).toString(16)      // 'ff' (소문자)
(35).toString(36)       // 'z'
parseInt('ff', 16)      // 255
parseInt('11111111', 2) // 255
(10).toString(2).padStart(8, '0') // '00001010'
```

- 10을 넘는 자릿수는 소문자 `a`–`z`를 씁니다. 대문자가 필요하면 `.toUpperCase()`를 붙입니다.
- 음수는 부호를 붙여서 `(-10).toString(2)`가 `'-1010'`입니다. 2의 보수가 아닙니다. 32비트 2의 보수 표현이 필요하면 `(x >>> 0).toString(2)`입니다.
- 앞에 0을 채우는 자릿수 고정은 `padStart`로 합니다(자세히는 06편).
- 안전 정수 범위를 넘는 값은 `BigInt(x).toString(radix)`로 바꿉니다. BigInt의 `toString`도 진법을 받습니다.
- 반대 방향의 `parseInt(s, radix)`는 안전 범위를 넘으면 정밀도를 잃으므로 큰 값은 직접 자릿수를 곱해 누적합니다(자세히는 11편).
- 숫자 리터럴에 바로 메서드를 쓰려면 `5..toString(2)`처럼 점 두 개나 `(5).toString(2)`입니다. `5.toString()`은 SyntaxError입니다.

**흔한 실수:** `toString(2)`의 결과를 숫자처럼 더하는 것입니다. 결과는 문자열이라서 `+`가 이어 붙이기가 됩니다.

## 정수 제곱근과 완전제곱수 판별

`Math.floor(Math.sqrt(n))`은 `n`의 정수 제곱근(제곱해서 `n` 이하인 가장 큰 정수)을 구합니다. `Math.sqrt`는 정밀도가 구현에 따라 다를 수 있어서, 결과를 `r`이라 할 때 `r * r`과 `(r + 1) * (r + 1)`로 한 번 보정합니다.

```js
function isqrt(n) {
  let r = Math.floor(Math.sqrt(n))
  while (r * r > n) r--        // 너무 크게 나온 경우
  while ((r + 1) * (r + 1) <= n) r++  // 너무 작게 나온 경우
  return r
}
isqrt(99)   // 9
isqrt(100)  // 10
```

완전제곱수는 정수 제곱근을 제곱해서 `n`이 되는 수입니다.

```js
const isSquare = (n) => {
  const r = isqrt(n)
  return r * r === n
}
isSquare(144)  // true
isSquare(145)  // false
```

- `Number.isInteger(Math.sqrt(n))`으로도 판별할 수 있지만 `Math.sqrt`의 정밀도가 구현에 따라 다르므로, 정수 비교로 한 번 더 확인하는 위 방식이 안전합니다.
- 음수의 `Math.sqrt`는 `NaN`입니다. 완전제곱수 판별은 `n >= 0`을 먼저 확인합니다.
- `r * r`이 2^53을 넘으면 보정 비교가 부정확해지므로, `n`이 10^15 정도까지일 때 이 방식을 씁니다. 그보다 큰 수는 BigInt로 같은 논리를 구현합니다.

```js
function isqrtBig(n) {      // n은 BigInt
  let r = BigInt(Math.floor(Math.sqrt(Number(n))))
  while (r * r > n) r--
  while ((r + 1n) * (r + 1n) <= n) r++
  return r
}
isqrtBig(10n ** 30n)  // 1000000000000000n
```

- 제곱근 후보가 필요할 때(소수 판별의 `i * i <= n`)는 `Math.sqrt`를 쓰지 않고 `i * i <= n` 조건을 그대로 쓰면 오차 걱정이 없습니다(자세히는 12편).
- 세제곱근은 `Math.cbrt`지만 같은 이유로 결과를 정수로 쓸 때는 보정합니다.

## 핵심 정리

- `number`는 안전 정수 범위(±(2^53 − 1))까지만 정수를 정확히 저장하므로, 그 범위를 넘는 값과 곱셈 후 나머지 연산에는 BigInt를 씁니다.
- BigInt와 Number를 산술·비트 연산자로 섞으면 TypeError이고, 출력은 문자열로 바꿔서 합니다.
- 실수는 `===`로 비교하지 말고 허용 오차로 비교하며, 가능하면 정수로 바꿔 계산합니다.
- `Math.floor`는 −∞ 방향, `Math.trunc`는 0 방향이고, `%`의 부호는 왼쪽 값을 따릅니다.
- `Number('')`는 0이고 `parseInt('')`는 NaN이며, `map(parseInt)`는 인덱스가 진법이 되어 틀립니다.
- 비트 연산은 32비트 정수로 바꾸므로 2^31 이상 값에서는 쓰지 않고, 제곱근은 `Math.sqrt` 결과를 정수 비교로 보정합니다.
