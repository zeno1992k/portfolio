## 정점과 간선

그래프(graph)는 정점(vertex, 노드)의 집합 V와 간선(edge)의 집합 E로 이뤄진 구조입니다. 정점은 대상(도시, 사람, 칸, 상태)이고 간선은 두 정점 사이의 관계(도로, 친구, 이동 가능)입니다. 간선 하나는 두 끝점을 가집니다.

그래프로 모델링하면 문제가 "정점 사이를 어떻게 이동하는가"로 바뀝니다. 격자 문제도 칸을 정점으로, 이동 가능한 인접 칸 사이를 간선으로 보면 그래프입니다(격자는 17편).

용어를 정리합니다.

| 용어 | 뜻 |
|------|----|
| 경로(path) | 간선으로 이어진 정점의 나열. 같은 정점을 반복하지 않는 것을 단순 경로라 한다 |
| 인접(adjacent) | 두 정점이 간선 하나로 직접 이어진 상태 |
| 자기 루프(self-loop) | 양 끝이 같은 정점인 간선 |
| 다중 간선 | 같은 두 정점 사이에 둘 이상 있는 간선 |
| 단순 그래프 | 자기 루프와 다중 간선이 없는 그래프 |

- 정점 수를 V, 간선 수를 E로 적고 복잡도는 이 둘로 씁니다. 대부분의 문제는 정점 번호가 1부터 V입니다.
- 입력은 흔히 첫 줄에 정점 수와 간선 수, 다음 E줄에 간선의 두 끝점을 줍니다(입력 처리는 08편).
- 문제가 자기 루프나 다중 간선을 허용하는지 먼저 읽습니다. 허용하면 코드에서 별도 처리가 필요합니다.

**흔한 실수:** 정점 번호가 1부터인데 배열을 `V`개만 만들어 인덱스를 벗어나는 것입니다. 1부터 쓰면 `V + 1`개를 만들거나 입력에서 1을 뺍니다.

## 방향 그래프

방향 그래프(directed graph)는 간선에 방향이 있는 그래프입니다. 간선 `u → v`는 u에서 v로만 갈 수 있고 반대로는 갈 수 없습니다. 선후 관계, 일방통행, 팔로우처럼 한쪽 방향 관계를 표현합니다.

- 간선 `u → v`와 `v → u`는 서로 다른 간선입니다. 둘 다 있을 수 있습니다.
- `u → v`에서 u를 시작점(꼬리), v를 도착점(머리)이라 하고 v는 u의 이웃으로 저장합니다.
- 입력 한 줄 `u v`는 문제에 따라 `u → v` 한 방향만 뜻합니다. 방향이 있다고 문장에 쓰여 있는지 확인합니다.

```js
const edges = [[1, 2], [1, 3], [2, 3]] // 1→2, 1→3, 2→3
// 2에서 1로는 갈 수 없다. 1에서 3으로는 직접, 또는 2를 거쳐 간다.
```

**흔한 실수:** 방향 그래프를 양쪽으로 저장하는 것입니다. 두 방향을 모두 저장하면 일방통행이 양방향이 되어 탐색 결과가 달라집니다.

## 무방향 그래프

무방향 그래프(undirected graph)는 간선에 방향이 없는 그래프입니다. 간선 `{u, v}`는 양쪽으로 이동할 수 있습니다. 친구 관계, 양방향 도로를 표현합니다.

- 저장할 때는 방향 그래프의 간선 두 개로 바꿔 `u → v`와 `v → u`를 모두 넣는 것이 일반적입니다.
- 간선 수 E는 `{u, v}` 하나를 하나로 셉니다. 저장되는 항목은 2E개입니다.
- 방향 그래프와 달리 `u`와 `v`의 순서를 바꿔 입력해도 같은 간선입니다.

| 구분 | 방향 그래프 | 무방향 그래프 |
|------|-------------|----------------|
| 간선 | `u → v`, 한 방향 | `{u, v}`, 양방향 |
| 저장 | `adj[u]`에 v만 | `adj[u]`에 v, `adj[v]`에 u |
| 대칭성 | 없다 | 인접 행렬이 대각선 기준으로 대칭 |

**흔한 실수:** 무방향 그래프의 한 방향만 저장하는 것입니다. 한쪽 정점에서는 이웃이 보이는데 반대쪽에서는 보이지 않아 탐색 결과가 정점마다 달라집니다.

## 가중치 그래프

가중치 그래프(weighted graph)는 간선에 값(가중치, 비용, 거리)이 붙은 그래프입니다. 최단 거리와 최소 비용 문제의 대상입니다. 방향 여부와는 독립입니다.

- 이웃과 가중치를 함께 저장합니다. 인접 리스트에서는 `[이웃, 가중치]` 쌍을 넣습니다.
- 가중치는 음수일 수 있고, 음수 간선이 있으면 쓸 수 있는 최단 경로 알고리즘이 달라집니다(자세히는 48편, 49편).
- 가중치의 합이 2^53을 넘을 수 있으면 `Number` 대신 `BigInt`를 고려합니다(자세히는 02편).

```js
const adj = Array.from({ length: 4 }, () => [])
adj[1].push([2, 5])  // 1 → 2, 가중치 5
adj[1].push([3, 2])  // 1 → 3, 가중치 2
adj[3].push([2, 1])  // 3 → 2, 가중치 1
// 1에서 2로 직접 5, 3을 거치면 2 + 1 = 3
```

**흔한 실수:** 가중치가 있는 문제인데 간선 수가 적은 경로가 최단이라고 가정하는 것입니다. 가중치가 모두 같을 때만 BFS의 단계 수가 곧 거리입니다(자세히는 38편).

## 인접 행렬

인접 행렬(adjacency matrix)은 `V × V` 2차원 배열로 간선을 저장하는 표현입니다. `m[u][v]`가 1이면 u에서 v로 가는 간선이 있습니다. 가중치 그래프면 1 대신 가중치를 넣고 간선이 없는 칸은 `0`이나 `Infinity`로 둡니다.

```js
function buildMatrix(n, edges, directed) {
  const m = Array.from({ length: n + 1 },
    () => Array(n + 1).fill(0))
  for (const [u, v] of edges) {
    m[u][v] = 1
    if (!directed) m[v][u] = 1
  }
  return m
}
buildMatrix(3, [[1, 2], [1, 3]], false)
// [[0,0,0,0],[0,0,1,1],[0,1,0,0],[0,1,0,0]]
```

- 두 정점이 인접한지 `m[u][v]` 한 번으로 O(1)에 확인합니다. 간선 추가와 삭제도 O(1)입니다.
- u의 모든 이웃을 찾으려면 행 전체를 훑어야 해서 O(V)입니다. 이웃이 몇 개 없어도 V번을 봅니다.
- 공간은 O(V²)입니다. V가 10만이면 칸이 100억 개라서 만들 수 없습니다. 인접 행렬은 V가 작을 때(대략 천 단위까지)만 씁니다.
- 격자 문제의 2차원 배열은 칸의 값을 담고, 인접 행렬은 정점 쌍을 인덱스로 씁니다. 둘은 다른 배열입니다.
- 모든 쌍 최단 거리처럼 정점 쌍을 전부 다루는 알고리즘(플로이드-워셜, 49편)은 인접 행렬이 자연스럽습니다.

**흔한 실수:** `Array(n + 1).fill(Array(n + 1).fill(0))`처럼 행을 같은 배열 하나로 채우는 것입니다. 모든 행이 한 배열을 가리켜 한 칸을 바꾸면 전체가 바뀝니다(자세히는 05편).

## 인접 리스트

인접 리스트(adjacency list)는 정점마다 이웃 목록을 저장하는 표현입니다. `adj[u]`가 u의 이웃 배열입니다.

```js
function buildList(n, edges, directed) {
  const adj = Array.from({ length: n + 1 }, () => [])
  for (const [u, v] of edges) {
    adj[u].push(v)
    if (!directed) adj[v].push(u)
  }
  return adj
}
const edges = [[1, 2], [1, 3], [2, 4], [3, 4], [5, 6]]
buildList(7, edges, false)
// [[], [2,3], [1,4], [1,4], [2,3], [6], [5], []]
```

- 공간은 O(V + E)이고 이웃을 순회하는 시간은 이웃 수(차수)에 비례합니다. 간선이 적은(희소한) 그래프에서 효율적입니다.
- 간선 추가는 `push`라서 O(1)입니다. 간선 존재 확인은 이웃 배열을 훑어야 해서 O(차수)입니다. 확인이 자주 필요하면 `Set`을 함께 씁니다(자세히는 09편).
- 대부분의 그래프 문제에서 기본 선택입니다. 탐색 전체가 O(V + E)가 됩니다.
- 입력은 보통 간선 수만큼 줄을 읽어 한 번에 채웁니다.

| 항목 | 인접 행렬 | 인접 리스트 |
|------|-----------|-------------|
| 공간 | O(V²) | O(V + E) |
| 간선 존재 확인 | O(1) | O(차수) |
| 이웃 순회 | O(V) | O(차수) |
| 전체 간선 순회 | O(V²) | O(V + E) |
| 적합한 경우 | 정점이 적거나 간선이 촘촘함 | 간선이 적은 대부분의 경우 |

**흔한 실수:** `Array(n + 1).fill([])`로 만드는 것입니다. 모든 정점이 같은 배열을 이웃 목록으로 공유해 한 정점에 `push`하면 전부에 들어갑니다. `Array.from({ length: n + 1 }, () => [])`로 정점마다 새 배열을 만듭니다.

## 간선 리스트

간선 리스트(edge list)는 간선을 `[u, v]`(가중치가 있으면 `[u, v, w]`)로 한 줄에 하나씩 저장한 배열입니다. 입력 그대로의 모양이라 별도 변환이 필요 없습니다.

```js
// 간선마다 [u, v, 가중치]
const edges = [[1, 2, 5], [1, 3, 2], [3, 2, 1]]
const sorted = [...edges].sort((a, b) => a[2] - b[2])
// 가중치 오름차순: [3,2,1], [1,3,2], [1,2,5]
```

- 공간은 O(E)입니다. 이웃 조회가 빠르지 않아서 탐색에는 쓰지 않습니다.
- 간선을 통째로 다루는 알고리즘에 맞습니다. 간선을 가중치로 정렬해 쓰는 크루스칼 최소 신장 트리(52편), 모든 간선을 반복해서 완화하는 벨만-포드(49편)가 대표입니다.
- 인접 리스트가 필요하면 간선 리스트에서 `buildList`로 한 번 변환합니다.

**흔한 실수:** 간선 리스트로 이웃을 찾으려고 매번 전체를 훑는 것입니다. 정점마다 O(E)가 되어 전체 O(V × E)입니다.

## JavaScript 인접 리스트 구현 방식

JavaScript에서 인접 리스트를 만드는 방법은 둘입니다. 정점 수와 간선 수가 큰 문제에서는 둘의 비용 차이가 시간 초과와 메모리 초과를 가릅니다.

### 배열의 배열

위에서 쓴 `adj[u]`가 배열인 방식입니다. 쓰기 쉽고 순회가 `for (const v of adj[u])`로 간결합니다.

- 정점마다 배열 객체가 하나씩 생겨 정점이 수십만 개이면 객체 수가 많아지고 메모리와 생성 시간이 늘어납니다.
- 간선을 `push`할 때 배열이 동적으로 늘어나는 비용이 붙습니다.
- 일반적인 크기(정점 10만, 간선 수십만)에서는 충분히 빠르고 기본 선택입니다.

### TypedArray 기반 간선 배열

간선을 `to`(도착점), `nxt`(같은 정점의 다음 간선 번호) 두 배열에 담고 `head[u]`에 정점 u의 첫 간선 번호를 두는 방식입니다. 연결 리스트(21편)를 배열로 구현한 것과 같습니다. `Int32Array`는 원소당 4바이트이고 길이가 고정되며 0으로 초기화됩니다. 간선 수를 미리 알 때 씁니다.

```js
function buildFS(n, edges) {
  const head = new Int32Array(n + 1).fill(-1) // -1은 간선 없음
  const nxt = new Int32Array(edges.length * 2)
  const to = new Int32Array(edges.length * 2)
  let cnt = 0
  const add = (u, v) => {
    to[cnt] = v
    nxt[cnt] = head[u]  // 이전 첫 간선을 뒤로 밀고
    head[u] = cnt++     // 새 간선이 첫 간선이 된다
  }
  for (const [u, v] of edges) { add(u, v); add(v, u) }
  return { head, nxt, to }
}
```

정점 u의 이웃은 `head[u]`에서 시작해 `nxt`를 따라 `-1`이 나올 때까지 순회합니다.

```js
for (let e = head[u]; e !== -1; e = nxt[e]) {
  const v = to[e]   // u의 이웃
}
```

위 `edges`로 만들면 정점 1의 순회 결과는 `3, 2`입니다. 간선을 앞에 끼워 넣어서 나중에 추가한 간선이 먼저 나옵니다. 순서에 의존하는 문제에서는 주의합니다.

| 항목 | 배열의 배열 | TypedArray 간선 배열 |
|------|-------------|----------------------|
| 생성 | 정점마다 배열 | 배열 3개 |
| 메모리 | 객체 오버헤드가 있다 | 정수 4바이트씩, 고정 크기 |
| 간선 수 | 몰라도 된다 | 미리 알아야 한다 |
| 순회 코드 | `for...of` | 인덱스 반복문 |
| 무방향 간선 | `push` 두 번 | 간선 번호 슬롯 2개 필요 |

- 무방향 그래프는 간선당 슬롯이 둘이라 배열 길이는 `2E`입니다. 방향 그래프는 `E`입니다.
- 입력이 매우 큰 문제에서 메모리와 시간을 아끼려는 선택입니다. 처음에는 배열의 배열로 풀고, 시간이나 메모리가 부족할 때 바꿉니다(자세히는 86편).

**흔한 실수:** `Int32Array`의 `nxt` 초기값이 0이라서 0번 간선과 "간선 없음"을 혼동하는 것입니다. 간선 번호를 0부터 쓰면 끝 표시는 `-1`로 `fill`해야 합니다.

## 차수

차수(degree)는 정점에 붙은 간선의 수입니다. 방향 그래프에서는 진입 차수와 진출 차수를 구분합니다.

| 용어 | 뜻 | 인접 리스트에서 |
|------|----|-----------------|
| 차수 | 무방향에서 그 정점에 붙은 간선 수 | `adj[u].length` |
| 진출 차수(outdegree) | 정점에서 나가는 간선 수 | `adj[u].length` |
| 진입 차수(indegree) | 정점으로 들어오는 간선 수 | 간선을 읽으며 따로 센다 |

```js
const edges = [[1, 2], [1, 3], [2, 3], [3, 4]] // 방향 그래프
const inDeg = new Int32Array(5)
const outDeg = new Int32Array(5)
for (const [u, v] of edges) {
  outDeg[u]++
  inDeg[v]++
}
// inDeg  [0, 0, 1, 2, 1], outDeg [0, 2, 1, 1, 0]
```

- 진입 차수는 인접 리스트로는 바로 알 수 없어서 간선을 읽을 때 `v`의 카운트를 올립니다.
- 무방향 그래프에서 모든 정점의 차수 합은 간선 수의 2배입니다(악수 보조정리). 모든 간선이 두 정점에 한 번씩 기여하기 때문입니다.
- 방향 그래프에서 진입 차수의 합과 진출 차수의 합은 모두 E입니다.
- 진입 차수가 0인 정점은 선행 조건이 없는 시작 후보입니다. 위상 정렬이 이 값을 씁니다(자세히는 53편).
- 자기 루프는 무방향 그래프에서 차수에 2로 세는 것이 일반적입니다.

**흔한 실수:** 무방향 그래프에서 진입·진출을 구분하는 것입니다. 무방향은 간선 방향이 없으므로 차수 하나만 있습니다.

## 그래프 탐색

그래프 탐색은 시작 정점에서 간선을 따라 도달할 수 있는 모든 정점을 방문하는 일입니다. 어떤 정점에서 어떤 정점으로 갈 수 있는가, 연결되어 있는가를 묻는 문제의 기본 도구입니다.

탐색의 뼈대는 "방문한 정점을 표시해서 같은 정점을 두 번 처리하지 않는다"입니다. 그래프에는 사이클이 있을 수 있어서 표시가 없으면 같은 정점을 무한히 반복합니다.

```js
function explore(adj, start, visited, parent) {
  const stack = [start]
  visited[start] = 1
  while (stack.length) {
    const u = stack.pop()
    for (const v of adj[u]) {
      if (visited[v]) continue
      visited[v] = 1      // 넣을 때 표시해서 한 번만 들어간다
      parent[v] = u       // v를 처음 발견한 정점
      stack.push(v)
    }
  }
}
```

호출하는 쪽에서 `visited`(`Uint8Array`)와 `parent`(`Int32Array`)를 정점 수 + 1 길이로 만들어 넘깁니다. 초기값 0은 "미방문"과 "부모 없음"을 뜻합니다.

- 스택 대신 큐를 쓰면 가까운 정점부터 방문합니다. 정점을 꺼낼 때 표시하는 방식과 넣을 때 표시하는 방식이 있고, 순서가 달라집니다. 순서가 중요한 DFS는 36편, BFS는 38편에서 다룹니다.
- 각 정점은 한 번 처리되고 각 간선은 한 번(무방향은 양쪽에서 각각) 검사되므로 인접 리스트에서 O(V + E), 인접 행렬에서 O(V²)입니다.
- `visited`는 정점 번호를 인덱스로 하는 `Uint8Array`나 `boolean` 배열입니다. 정점이 문자열이면 `Set`이나 `Map`을 씁니다(자세히는 09편).
- 탐색이 끝난 `visited`로 "시작점에서 도달 가능한가", `parent`로 "어떤 경로로 갔는가"를 답합니다.

**흔한 실수:** 방문 표시를 빼먹는 것입니다. 사이클이 있는 그래프에서는 무한 루프가 되고, 무방향 그래프는 간선이 양방향이라서 사이클이 없는 그래프에서도 직전 정점으로 되돌아가 무한 루프가 됩니다.

## 연결 요소

연결 요소(connected component)는 무방향 그래프에서 서로 경로로 닿을 수 있는 정점들의 최대 묶음입니다. 서로 다른 연결 요소의 정점 사이에는 경로가 없습니다. 연결 요소가 하나이면 연결 그래프입니다.

연결 요소의 수는 방문하지 않은 정점마다 새로 탐색을 시작하고, 시작한 횟수를 세어 구합니다.

```js
function countComponents(n, adj) {
  const visited = new Uint8Array(n + 1)
  const parent = new Int32Array(n + 1)
  let count = 0
  for (let s = 1; s <= n; s++) {
    if (visited[s]) continue
    count++                  // 새 연결 요소의 시작
    explore(adj, s, visited, parent)
  }
  return count
}
```

`explore`가 `visited`를 정점 전체에서 공유하므로 이미 방문한 요소는 다시 탐색하지 않습니다.

위의 `edges`(간선 `1-2, 1-3, 2-4, 3-4, 5-6`)로 정점 7개 그래프를 만들면 요소는 `{1, 2, 3, 4}`, `{5, 6}`, `{7}`로 3개입니다. 간선이 없는 정점 `7`도 하나의 연결 요소입니다.

- 시간은 정점과 간선을 한 번씩만 보므로 O(V + E)입니다.
- 방향 그래프에서는 "서로 도달 가능한 최대 묶음"인 강연결 요소(SCC)를 쓰며 구하는 방법이 다릅니다(자세히는 68편). 간선의 방향을 무시한 연결 요소는 약연결 요소라 부릅니다.
- 연결 요소 수는 Union-Find로도 셀 수 있습니다(자세히는 51편). 간선이 하나씩 추가되며 요소를 묻는 문제에 적합합니다.
- DFS로 연결 요소와 영역 개수를 세는 구현은 36편에서 다룹니다.

**흔한 실수:** 정점 1에서만 탐색을 시작해서 연결 요소가 하나라고 가정하는 것입니다. 정점마다 방문 여부를 확인하며 돌아야 고립된 정점까지 셉니다.

## 사이클

사이클(cycle)은 한 정점에서 출발해 간선을 따라 다시 그 정점으로 돌아오는 경로입니다. 단순 사이클은 시작과 끝 정점을 제외하고 정점을 반복하지 않습니다. 사이클이 없는 무방향 그래프는 숲(forest)이고, 연결된 숲이 트리입니다(자세히는 43편).

무방향 그래프와 방향 그래프의 사이클 개념은 다릅니다.

| 항목 | 무방향 | 방향 |
|------|--------|------|
| 사이클의 뜻 | 같은 간선을 되돌아가는 것은 제외하고 정점으로 돌아오는 경로 | 간선 방향을 따라 출발점으로 돌아오는 경로 |
| 길이가 가능한 최소 | 3(단순 그래프). 자기 루프 1, 다중 간선 2도 사이클 | 1(자기 루프), 2(`u → v → u`) |
| 판별 | 탐색 중 이미 방문한 정점이 부모가 아니면 사이클 | 탐색 중 현재 경로 위에 있는 정점을 다시 만나면 사이클 |

- 무방향 그래프에서 `u-v` 간선 하나는 양쪽에서 보이므로 `v`에서 부모 `u`를 다시 만나는 것은 사이클이 아닙니다.
- 무방향 그래프에서는 간선 수로도 판별합니다. 정점 V개, 연결 요소 C개일 때 사이클이 없으면 `E = V - C`이고, 사이클이 있으면 `E > V - C`입니다. 위의 예는 `V = 7`, `C = 3`, `E = 5`라서 `5 > 4`이므로 사이클이 있고 `1-2-4-3-1`이 그 사이클입니다.
- 방향 그래프의 사이클은 진입 차수로 제거하는 위상 정렬로도 찾습니다(자세히는 53편).
- 사이클 판별 구현은 37편에서 다룹니다.

**흔한 실수:** 방향 그래프에 무방향 그래프의 "부모가 아닌 방문 정점" 규칙을 쓰는 것입니다. 방향 그래프에서는 방문했더라도 현재 경로 위에 있지 않으면 사이클이 아닙니다(`1 → 2`, `1 → 3`, `2 → 3`에서 3을 두 번 만나도 사이클이 아님).

## DAG

DAG(Directed Acyclic Graph)는 사이클이 없는 방향 그래프입니다. 선후 관계(선수 과목, 작업 순서, 의존성)를 표현합니다.

- 방향 그래프가 DAG인 것은 위상 순서가 존재하는 것과 필요충분입니다. 위상 순서는 모든 간선 `u → v`에서 u가 v보다 앞에 오도록 정점을 한 줄로 세운 것입니다.
- 사이클이 있으면 그 사이클의 첫 정점에 들어오는 간선이 위상 순서를 어기므로 위상 순서가 없습니다.
- 모든 DAG에는 진입 차수가 0인 정점이 하나 이상 있고, 위상 순서는 하나 이상 존재합니다.
- DAG는 방향을 무시해도 사이클이 없다는 뜻이 아닙니다. `1 → 2`, `1 → 3`, `2 → 4`, `3 → 4`는 DAG지만 방향을 무시하면 `1-2-4-3-1` 사이클이 있습니다.
- DAG 위에서는 위상 순서대로 한 번 훑으며 DP를 할 수 있습니다. 최장 경로, 경로의 수가 이에 해당합니다(자세히는 53편).

**흔한 실수:** 무방향 그래프의 트리와 DAG를 같은 것으로 보는 것입니다. 트리는 무방향에서 사이클이 없는 연결 그래프이고, DAG는 방향이 있으며 무방향으로 보면 사이클이 있을 수 있습니다.

## 경로 복원용 Parent 배열

Parent 배열은 `parent[v]`에 탐색에서 v를 처음 발견한 정점(v의 직전 정점)을 저장한 배열입니다. 도착점에서 `parent`를 따라 시작점까지 거슬러 올라가면 경로를 복원할 수 있습니다.

```js
function pathTo(parent, visited, s, t) {
  if (!visited[t]) return []   // 도달 불가
  const path = []
  for (let v = t; v !== s; v = parent[v]) path.push(v)
  path.push(s)
  return path.reverse()        // 시작점에서 도착점 순서로
}
```

정점 7개와 앞의 `edges`로 만든 그래프에서 정점 1에서 `explore`를 실행한 결과입니다.

| 정점 | 2 | 3 | 4 | 5 |
|------|---|---|---|---|
| `parent` | 1 | 1 | 3 | 0 (미방문) |

```js
const adj = buildList(7, edges, false)
const visited = new Uint8Array(8)
const parent = new Int32Array(8)
explore(adj, 1, visited, parent)
pathTo(parent, visited, 1, 4) // [1, 3, 4]
pathTo(parent, visited, 1, 6) // [] (6은 도달 불가)
```

- 4는 3에서 발견되었고 3은 1에서 발견되었으므로 거슬러 올라가면 `4 → 3 → 1`이고 뒤집으면 `[1, 3, 4]`입니다.
- 거슬러 올라가며 쌓았으므로 마지막에 `reverse()`가 필요합니다. 길이가 L인 경로를 복원하는 데 O(L)입니다.
- 시작점은 부모가 없으므로 `parent[s]`를 0(또는 -1)로 둡니다. 정점 번호가 0부터면 -1을 씁니다.
- 어떤 탐색으로 채웠는지에 따라 복원된 경로의 성질이 다릅니다. BFS로 채우면 간선 수가 가장 적은 경로이고, DFS로 채우면 임의의 경로입니다(자세히는 36편, 38편).
- 가중치 그래프의 최단 경로도 같은 방식으로 `parent`를 갱신하며 복원합니다(자세히는 48편).
- 격자에서는 `parent`에 이전 칸의 좌표를 정수 하나로 넣어 복원합니다(자세히는 17편).

**흔한 실수:**

- 도달할 수 없는 정점의 경로를 요청하고 `parent`를 따라가는 것입니다. `visited[t]`를 먼저 확인하지 않으면 반복이 끝나지 않거나 잘못된 값이 나옵니다.
- 경로를 복원하면서 `reverse()`를 잊어 도착점에서 시작점 순서로 출력하는 것입니다.

## 핵심 정리

- 그래프는 정점과 간선의 집합이며 방향 여부와 가중치 여부로 구분합니다. 무방향 간선은 인접 리스트에 양쪽으로 저장합니다.
- 인접 행렬은 O(V²) 공간에 간선 확인이 O(1)이고, 인접 리스트는 O(V + E) 공간에 이웃 순회가 차수에 비례합니다. 대부분의 문제는 인접 리스트가 기본입니다.
- 간선 리스트는 간선을 정렬하거나 모두 훑는 알고리즘에 씁니다. 인접 리스트를 만들 때 `Array(n).fill([])`로 배열 하나를 공유하면 안 됩니다.
- JavaScript에서는 배열의 배열이 기본이고, 규모가 크면 `Int32Array` 3개(`head`, `nxt`, `to`)로 연결 리스트를 구현합니다.
- 연결 요소는 방문하지 않은 정점마다 탐색을 시작한 횟수이고, 무방향 그래프의 사이클은 `E > V - C`로도 판별합니다.
- DAG는 사이클 없는 방향 그래프이고 위상 순서가 있는 그래프와 같습니다. Parent 배열은 발견한 직전 정점을 저장해 경로를 복원하며 `reverse()`가 필요합니다.
