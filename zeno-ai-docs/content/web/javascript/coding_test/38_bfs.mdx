## BFS 개념

BFS(Breadth-First Search, 너비 우선 탐색)는 시작점에서 **가까운 정점부터 차례로** 방문하는 탐색입니다. 간선 1개로 닿는 정점을 모두 방문하고, 그다음 간선 2개로 닿는 정점, 그다음 3개로 닿는 정점 순으로 퍼져 나갑니다. 물에 돌을 던졌을 때 파문이 번지는 모양입니다.

이 순서는 **큐(queue)** 가 만듭니다. 먼저 넣은 정점을 먼저 꺼내므로, 거리가 d인 정점이 모두 거리가 d + 1인 정점보다 먼저 처리됩니다. DFS는 스택(또는 재귀)을 써서 한 갈래를 끝까지 파고듭니다(자세히는 36편).

| 항목 | BFS | DFS |
|------|-----|-----|
| 자료구조 | 큐 | 스택 또는 재귀 |
| 방문 순서 | 시작점에서 가까운 순 | 한 갈래를 끝까지 간 뒤 되돌아옴 |
| 가중치 없는 최단거리 | 구함 | 구하지 못함 |
| 시간복잡도 | O(V + E) | O(V + E) |
| 메모리 | 한 레벨의 폭만큼 | 경로의 깊이만큼 |

- V는 정점 수, E는 간선 수입니다. 정점은 한 번씩, 간선은 한 번씩(무방향이면 양쪽에서 두 번) 확인합니다.
- BFS는 재귀를 쓰지 않아서 깊이가 깊어도 호출 스택이 넘치지 않습니다.
- 한 시작점에서 닿는 정점만 방문합니다. 닿지 않는 정점은 방문하지 않고, 연결 요소를 모두 구하려면 시작점을 바꿔 가며 반복합니다.

**문제의 단서:** "최소 이동 횟수", "가장 빨리 도착하는 시간", "가장 가까운", 가중치가 없거나 모두 같은 이동 비용이면 BFS입니다.

## Queue BFS

BFS의 틀은 항상 같습니다. 시작점을 큐에 넣고 방문 표시를 한 뒤, 큐가 빌 때까지 하나씩 꺼내 이웃을 확인하고 새 이웃을 큐에 넣습니다.

1. 시작점을 큐에 넣고 방문 처리한다.
2. 큐에서 정점 `u`를 꺼낸다.
3. `u`의 이웃 중 방문하지 않은 정점을 **방문 처리하고 큐에 넣는다**.
4. 큐가 빌 때까지 2–3을 반복한다.

자바스크립트에서는 큐를 배열로 만들되 `shift()`로 꺼내지 않고 **꺼낼 위치를 가리키는 인덱스** `head`를 하나 둡니다. `shift()`는 남은 원소를 앞으로 당겨서 원소가 많으면 한 번에 O(N)이 들 수 있습니다(자세히는 20편).

```js
const queue = [start]
for (let head = 0; head < queue.length; head++) {
  const u = queue[head]        // 꺼내기: head만 움직임
  // u의 이웃을 확인하고 새 정점은 queue.push(v)
}
// 반복 중에 push가 일어나서 queue.length가 늘어난다
```

- 배열은 줄어들지 않고 넣은 정점이 모두 남아 있으므로, 메모리는 방문한 정점 수만큼 듭니다. 정점은 한 번씩만 넣기 때문에 길이는 V를 넘지 않습니다.
- `for` 조건의 `queue.length`는 매번 다시 읽어서 중간에 push된 정점도 이어서 처리합니다.
- **방문 처리는 큐에 넣을 때** 합니다. 꺼낼 때 처리하면 같은 정점이 큐에 여러 번 들어가서 시간이 늘고, 거리 계산도 틀어질 수 있습니다.

**흔한 실수:**

- 큐에서 꺼낼 때 방문 표시를 하는 것입니다. 정점 3이 정점 1과 2에서 모두 발견되면 큐에 두 번 들어갑니다.
- 시작점의 방문 표시를 빼먹는 것입니다. 이웃에서 시작점으로 되돌아와 다시 큐에 들어갑니다.

## 그래프 BFS

인접 리스트 `adj`로 표현한 그래프에서 시작점 `s`로부터의 BFS입니다. 방문 표시와 거리 기록을 같은 배열 하나로 합칩니다(아래 "거리 배열"). 인접 리스트는 35편입니다.

```js
function bfs(n, adj, s) {
  const dist = new Array(n).fill(-1)
  const queue = [s]
  dist[s] = 0
  for (let head = 0; head < queue.length; head++) {
    const u = queue[head]
    for (const v of adj[u]) {
      if (dist[v] !== -1) continue
      dist[v] = dist[u] + 1
      queue.push(v)
    }
  }
  return dist
}
```

간선 `0-1, 0-2, 1-3, 2-3, 3-4`인 무방향 그래프에서 `bfs(5, adj, 0)`을 추적합니다.

| 꺼낸 정점 | 새로 넣은 정점 | 큐에 남은 정점 | dist |
|-----------|----------------|----------------|------|
| 0 | 1, 2 | 1, 2 | 0 1 1 -1 -1 |
| 1 | 3 | 2, 3 | 0 1 1 2 -1 |
| 2 | 없음(3은 이미 방문) | 3 | 변화 없음 |
| 3 | 4 | 4 | 0 1 1 2 3 |
| 4 | 없음 | 비어 있음 | 변화 없음 |

- 결과는 `[0, 1, 1, 2, 3]`입니다. 방문 순서는 `0, 1, 2, 3, 4`입니다.
- 이웃을 보는 순서(`adj[u]`의 순서)가 바뀌면 방문 순서는 달라지지만, 각 정점의 거리는 그대로입니다.
- 시간복잡도는 O(V + E), 공간은 O(V)입니다. 인접 행렬로 만들면 정점마다 V개를 훑어서 O(V²)입니다.

## 격자 BFS

격자(2차원 배열)에서는 칸이 정점이고, 상하좌우로 이웃한 칸이 간선입니다. 방향 배열과 범위 검사는 17편의 방식을 그대로 씁니다. 아래에서 `'0'`은 갈 수 있는 칸, `'1'`은 벽입니다.

```js
const DR = [-1, 1, 0, 0]
const DC = [0, 0, -1, 1]
function canGo(grid, dist, r, c) {
  if (r < 0 || r >= grid.length) return false
  if (c < 0 || c >= grid[0].length) return false
  return grid[r][c] !== '1' && dist[r][c] === -1
}
```

`canGo`는 범위 안이고, 벽이 아니며, 아직 방문하지 않은 칸일 때만 `true`입니다. 범위 검사를 가장 먼저 해야 `grid[r][c]`가 범위 밖을 읽지 않습니다.

```js
function bfsGrid(grid, sr, sc) {
  const dist = grid.map((row) => Array(row.length).fill(-1))
  const queue = [[sr, sc]]
  dist[sr][sc] = 0
  for (let head = 0; head < queue.length; head++) {
    const [r, c] = queue[head]
    for (let d = 0; d < 4; d++) {
      const nr = r + DR[d], nc = c + DC[d]
      if (!canGo(grid, dist, nr, nc)) continue
      dist[nr][nc] = dist[r][c] + 1
      queue.push([nr, nc])
    }
  }
  return dist
}
```

`['0110', '0010', '0000']`에서 `bfsGrid(grid, 0, 0)`의 결과입니다. `-1`은 벽이거나 닿지 못한 칸입니다.

```text
0 -1 -1  7
1  2 -1  6
2  3  4  5
```

- 오른쪽 위 칸은 위쪽 길이 벽으로 막혀 있어서 아래로 돌아가는 7칸 거리입니다.
- 큐에 `[r, c]` 배열을 넣으면 코드가 읽기 쉽습니다. 정점이 수십만 개이면 좌표를 정수 하나(`r * W + c`)로 넣는 쪽이 객체 생성이 없어서 가볍습니다(자세히는 17편).
- 시간복잡도는 O(H × W)입니다(H는 행 수, W는 열 수). 칸마다 이웃 4개만 확인합니다.
- 이동이 8방향이거나 말의 이동처럼 정해진 규칙이면 방향 배열만 바꿉니다.

**흔한 실수:**

- `dist[nr][nc]`를 범위 검사보다 먼저 읽는 것입니다. 행이 범위를 벗어나면 `undefined[nc]`에서 TypeError입니다.
- 행을 `new Array(H).fill(new Array(W).fill(-1))`로 만드는 것입니다. 모든 행이 같은 배열을 가리켜서 한 칸을 바꾸면 모든 행이 바뀝니다(자세히는 5편).

## 최단거리 BFS

BFS는 **간선에 가중치가 없는(또는 모두 같은) 그래프에서 시작점으로부터의 최단 거리**를 구합니다. 거리는 지나는 간선의 최소 개수입니다.

왜 맞는지는 큐의 성질에서 나옵니다. 큐에는 항상 거리가 d인 정점들 다음에 거리가 d + 1인 정점들이 이 순서로만 놓입니다. 거리 d인 정점에서 새로 발견한 정점은 거리 d + 1이고 큐의 뒤에 붙기 때문입니다. 그래서 어떤 정점이 처음 발견되는 순간은 그 정점까지 가장 적은 간선으로 오는 경로를 통해서이고, 이후 더 짧은 경로는 없습니다.

- 처음 발견된 순간의 거리가 곧 최단 거리라서, 한 번 정해진 `dist`는 다시 고치지 않습니다.
- 가중치가 1과 2처럼 섞이면 BFS는 틀립니다. 가중치가 0 또는 1이면 0-1 BFS(39편), 일반 양수이면 Dijkstra(48편)를 씁니다.
- 격자에서 "시작 칸도 센다"는 문제는 `dist[도착] + 1`을 출력합니다. 거리(이동 횟수)와 지난 칸 수는 1 차이가 납니다.
- 도착점에 닿지 못하면 `dist`가 `-1`로 남습니다. 문제가 정한 출력(`-1` 등)과 맞는지 확인합니다.

**문제의 단서:** "최소 몇 번 만에", "가장 짧은 경로의 칸 수", "몇 초 후"입니다. 이동 한 번의 비용이 같으면 최단거리는 BFS 한 번입니다.

## 거리 배열

거리 배열(`dist`)은 시작점에서 각 정점까지의 최단 거리를 담는 배열입니다. `-1`로 초기화해서 **방문 여부와 거리를 한 배열로** 나타냅니다.

| `dist[v]` 값 | 뜻 |
|--------------|----|
| `-1` | 아직 방문하지 않음(최종적으로는 도달 불가) |
| 0 이상 | 시작점에서 `v`까지의 최소 간선 수 |

- `dist[v] !== -1` 검사가 방문 검사를 대신하므로 `visited` 배열이 따로 필요 없습니다.
- 격자에서는 `dist[r][c]`가 2차원 배열입니다. 좌표를 정수 하나로 바꾸면 1차원 배열 하나로 둘 수 있습니다.
- 모든 정점에서 `dist`는 0 이상 V − 1 이하입니다. 가장 먼 정점까지의 거리는 BFS가 끝난 뒤 `dist`의 최댓값으로 구합니다. 원소가 많으면 `Math.max(...dist)`는 인수 개수 한계에 걸리므로 `reduce`를 씁니다(자세히는 86편).
- 거리 `-1`을 그대로 합계나 최댓값에 넣으면 틀립니다. 닿지 못한 정점을 걸러서 처리합니다.
- 거리 배열은 시작점이 하나일 때의 값입니다. 시작점이 달라지면 BFS를 다시 합니다.

## 다중 시작점 BFS

다중 시작점 BFS(multi-source BFS)는 **시작점이 여러 개**일 때, 모든 시작점을 거리 0으로 먼저 큐에 넣고 한 번만 BFS하는 방법입니다. 각 정점의 `dist`가 **가장 가까운 시작점까지의 거리**가 됩니다.

시작점마다 BFS를 따로 돌려서 최솟값을 구하면 O(시작점 수 × (V + E))입니다. 한 번에 합치면 O(V + E)입니다. 모든 시작점이 한 겹씩 동시에 퍼져 나가는 모양이어서 불이 번지는 것, 바이러스·토마토가 익는 것, "가장 가까운 ○○까지의 거리"를 구하는 문제에 맞습니다.

초기화만 다르고 나머지 반복문은 `bfsGrid`와 같습니다.

```js
const queue = []
for (const [r, c] of starts) {
  dist[r][c] = 0
  queue.push([r, c])
}
// 이후 for (let head ...) 반복문은 bfsGrid와 같다
```

열린 3 × 4 격자에서 시작점이 `(0, 0)`과 `(2, 3)`이면 결과는 다음과 같습니다.

```text
0 1 2 2
1 2 2 1
2 2 1 0
```

- 칸 `(0, 3)`은 `(0, 0)`에서 3, `(2, 3)`에서 2라서 `2`입니다.
- "모두 번지는 데 걸리는 시간"은 BFS 뒤의 `dist` 최댓값입니다. 닿지 못한 칸(`-1`)이 남아 있으면 불가능으로 처리하는 문제가 많습니다.
- 시작점이 아닌 쪽, 즉 "어떤 칸에서 가장 가까운 시작점"을 구하는 문제도 시작점들을 모두 큐에 넣는 한 번의 BFS면 됩니다.
- 시작점을 넣는 순서는 결과에 영향을 주지 않습니다. 모두 거리 0이기 때문입니다.
- 서로 다른 두 종류의 시작점이 있고 한쪽이 먼저 움직이는 문제(불과 사람)는 두 번 BFS하거나, 큐에 종류를 함께 담습니다(자세히는 39편).

**흔한 실수:** 시작점을 하나씩 BFS하고 `dist`를 덮어쓰는 것입니다. 마지막 시작점의 거리만 남고 O(시작점 수 × (V + E))로 느려집니다.

## BFS 레벨 단위 탐색

레벨 단위 탐색은 BFS를 **거리가 같은 정점들을 한 묶음(레벨)씩** 처리하는 방식입니다. 레벨 번호가 곧 시작점까지의 거리입니다. 레벨마다 무언가를 세거나, 레벨이 몇 개인지가 답인 문제(최소 몇 번 만에 끝나는가)에 씁니다.

현재 레벨의 배열과 다음 레벨의 배열 두 개로 나누면 코드가 단순합니다.

```js
function levels(n, adj, s) {
  const seen = new Array(n).fill(false)
  let cur = [s]
  seen[s] = true
  const result = []
  while (cur.length > 0) {
    result.push(cur)
    const next = []
    for (const u of cur)
      for (const v of adj[u])
        if (!seen[v]) { seen[v] = true; next.push(v) }
    cur = next
  }
  return result
}
```

- 위 예제 그래프에서 `levels(5, adj, 0)`은 `[[0], [1, 2], [3], [4]]`입니다.
- `result.length - 1`이 시작점에서 가장 먼 정점까지의 거리이고, `result[k]`는 거리가 k인 정점들입니다.
- 큐 하나로 하려면 레벨을 시작할 때 `const size = queue.length`로 이번 레벨의 개수를 고정하고 그 수만큼만 꺼냅니다. 레벨 수는 `size`를 꺼낼 때마다 1씩 늘립니다.
- 거리 배열이 있으면 레벨 단위 탐색 없이도 `dist`를 값별로 묶어 같은 결과를 얻습니다. 레벨 경계에서 하는 일이 있을 때(한 턴이 끝날 때마다 상태 변경)에만 레벨 단위로 씁니다.
- 레벨 하나를 처리하는 중에 큐에 들어온 정점은 다음 레벨입니다. 이번 레벨의 `size`를 미리 고정하지 않으면 레벨이 섞입니다.

**흔한 실수:** 반복문 조건을 `i < queue.length`로 두고 레벨을 센다면, 이번 레벨 도중에 push된 정점까지 이번 레벨로 처리해서 레벨 수가 틀립니다.

## BFS 경로 복원

BFS는 최단거리 값뿐 아니라 **최단 경로 자체**도 복원합니다. 정점을 큐에 넣을 때 "어느 정점에서 왔는지"를 `parent[v]`에 기록하고, 도착점에서 `parent`를 따라 시작점까지 거슬러 올라간 뒤 뒤집습니다.

`parent`는 `-2`(방문 전), `-1`(시작점, 부모 없음), 그 외(부모 정점 번호)로 씁니다. 방문 표시를 겸하므로 `seen`이 따로 필요 없습니다.

```js
function bfsParent(n, adj, s) {
  const parent = new Array(n).fill(-2)
  const queue = [s]
  parent[s] = -1
  for (let head = 0; head < queue.length; head++) {
    const u = queue[head]
    for (const v of adj[u]) {
      if (parent[v] !== -2) continue
      parent[v] = u
      queue.push(v)
    }
  }
  return parent
}
```

```js
function restore(parent, t) {
  if (parent[t] === -2) return []
  const path = []
  for (let v = t; v !== -1; v = parent[v]) path.push(v)
  return path.reverse()
}
// 예제 그래프, s = 0 → parent [-1, 0, 0, 1, 3]
// restore(parent, 4) → [0, 1, 3, 4]
```

- 도착점부터 거슬러 올라가므로 `reverse()`가 필요합니다. 시작점에서 도착점 순으로 얻으려면 마지막에 뒤집습니다.
- 닿지 못한 도착점은 `parent[t] === -2`라서 빈 배열을 돌려줍니다.
- 최단 경로가 여러 개일 수 있고, `parent`는 그중 하나만 가리킵니다. 사전순으로 가장 빠른 경로처럼 조건이 붙으면 이웃을 보는 순서를 맞춥니다.
- 격자에서는 `parent`를 정수 `r * W + c`로 저장하고, 복원할 때 `r = Math.floor(v / W)`, `c = v % W`로 되돌립니다.
- 이동 방향을 출력해야 하면 부모와의 차이로 방향을 구하거나, 이동할 때 방향 번호(`d`)를 따로 저장합니다.
- 최단거리와 `parent`는 한 번의 BFS로 같이 얻습니다. 거리가 필요하면 `dist`를 함께 둡니다.

**흔한 실수:**

- `parent`를 `0`으로 초기화해서 정점 0과 "방문 전"을 구분하지 못하는 것입니다. 방문 전은 `-1`이나 `-2` 같은 정점 번호가 될 수 없는 값으로 둡니다.
- 시작점의 `parent`를 지정하지 않아 복원 반복이 끝나지 않는 것입니다.

## 핵심 정리

- BFS는 큐로 시작점에서 가까운 정점부터 방문하고, 시간복잡도는 O(V + E)입니다. 격자에서는 O(H × W)입니다.
- 방문 처리는 큐에서 꺼낼 때가 아니라 넣을 때 합니다. `shift()` 대신 `head` 인덱스로 꺼냅니다.
- 가중치가 없는 그래프에서 처음 발견된 거리가 최단 거리이며, 거리 배열은 `-1`로 초기화해 방문 표시를 겸합니다.
- 시작점이 여러 개이면 모두 거리 0으로 큐에 넣고 한 번만 BFS하면 가장 가까운 시작점까지의 거리가 나옵니다.
- 레벨 단위 탐색은 레벨 크기를 고정해 한 묶음씩 처리하고, 경로 복원은 `parent` 배열을 도착점에서 따라가 뒤집습니다.
