## 패턴을 고르는 단서

패턴은 알고리즘 이름이 아니라 코드가 반복되는 모양입니다. 문제를 읽고 아래 표처럼 단서에서 후보를 고릅니다(자세히는 77편, 78편).

| 문제 문장의 단서 | 후보 패턴 |
|------------------|-----------|
| 몇 번 나왔는지, 가장 많이 나온 것 | 빈도수 세기 |
| 이미 본 것인지, 중복 | 방문 체크 |
| 가장 큰 값, 가장 작은 값을 한 번 훑으며 | 최소·최대 갱신 |
| 바로 앞 값과 비교, 연속 | 이전 상태 저장 |
| 모든 경우를 나열 | 선택 → 재귀 → 복구 |
| 짝, 가장 가까운 값, 순서와 무관 | 정렬 후 탐색, 해시 |
| 최소 횟수, 최소 이동 | BFS 거리 관리 |
| 경우의 수, 최댓값, 앞의 결과를 재사용 | DP 상태 설계 |
| 관계, 연결, 이동 규칙 | 그래프·상태 공간 모델링 |

## 빈도수 세기

원소가 몇 번 나왔는지 세어 두고 그 수로 답을 구하는 패턴입니다(자세히는 10편). 값의 종류가 작고 정해져 있으면 배열의 인덱스로, 아니면 `Map`에 셉니다.

```js
const freq = new Map()
for (const ch of s) freq.set(ch, (freq.get(ch) ?? 0) + 1)

const cnt = new Int32Array(26)   // 알파벳 소문자만
for (const ch of s) cnt[ch.charCodeAt(0) - 97]++
```

- `Map`의 처음 값은 `undefined`이므로 `?? 0`으로 기본값을 줍니다. 이 기본값을 빼면 `NaN`이 됩니다.
- 객체에 `freq[x]++`로 세면 처음에 `undefined + 1`이라 `NaN`이 됩니다. 객체를 쓰려면 `freq[x] = (freq[x] ?? 0) + 1`입니다.
- 가장 많은 것을 찾을 때 동률 규칙(사전순, 먼저 나온 것)을 문제에서 확인합니다. 배열 인덱스로 세면 작은 인덱스부터 훑어 `>`로 갱신해서 사전순 앞이 남습니다.
- 비교 대상을 "개수가 같은가"로 바꾸면 애너그램·같은 구성 판별이 됩니다(자세히는 07편).

## 방문 체크

이미 처리한 것을 다시 처리하지 않도록 표시하는 패턴입니다. 탐색의 종료를 보장하고 중복 계산을 막습니다.

```js
const seen = new Set()
for (const x of nums) {
  if (seen.has(x)) return x   // 처음 중복된 값
  seen.add(x)
}
```

- 키가 작은 정수이면 `Uint8Array`와 같은 배열 표시가 `Set`보다 가볍고 빠릅니다. 객체나 문자열이면 `Set`입니다.
- 표시 시점은 "넣을 때"입니다. 큐에서 꺼낼 때 표시하면 같은 것이 여러 번 들어갑니다(자세히는 38편).
- 표시를 되돌려야 하는 문제가 있습니다. 한 경로 안에서만 쓰는 방문 표시는 경로를 벗어나면 지웁니다(아래 "선택 → 재귀 → 복구"). 전체에서 한 번만 방문하는 표시는 지우지 않습니다.
- 방문 표시에 쓰는 키가 상태 전체를 구분해야 합니다. 위치만 표시하면 같은 위치에 다른 상태로 오는 경우를 놓칩니다(아래 "문제를 상태 공간으로 바꾸기").

## 최소 / 최대 갱신

배열을 한 번 훑으며 지금까지의 최솟값(또는 최댓값)을 변수 하나로 유지하고, 각 원소에서 그 변수를 써서 답을 갱신하는 패턴입니다. 한 번 훑어서 O(N)입니다.

```js
// 한 번 사고팔아 얻는 최대 이익
let minPrice = Infinity
let best = 0
for (const p of prices) {
  best = Math.max(best, p - minPrice)
  minPrice = Math.min(minPrice, p)
}
// prices = [7, 1, 5, 3, 6, 4] → 5
```

- 초기값은 비교에서 반드시 지는 값입니다. 최솟값은 `Infinity`, 최댓값은 `-Infinity`입니다. 최댓값의 초기값을 `0`으로 두면 모든 값이 음수일 때 `0`이 답으로 남아 틀립니다.
- 첫 원소를 초기값으로 쓰고 둘째부터 훑어도 됩니다. 빈 배열이면 읽을 원소가 없으므로 입력 최소 크기를 확인합니다.
- 최솟값 갱신과 답 갱신의 순서가 결과를 정합니다. 위 코드는 현재 값 `p`를 팔고(답 갱신) 그다음에 `p`를 사는 날로 반영합니다. 순서를 바꾸면 같은 날 사고파는 것을 허용합니다.
- 큰 배열에서 `Math.max(...arr)`로 최댓값을 구하면 인수 개수 한계에 걸릴 수 있습니다. 반복문으로 갱신합니다(자세히는 86편).

## 이전 상태 저장

앞 원소나 앞 단계의 값을 변수에 보관하고 현재와 비교하거나 이어서 계산하는 패턴입니다. 연속 구간, 변화 횟수, 공간을 줄인 DP에 쓰입니다.

```js
// 가장 긴 증가 연속 구간의 길이
let prev = a[0]
let run = 1
let best = 1
for (let i = 1; i < a.length; i++) {
  run = a[i] > prev ? run + 1 : 1
  best = Math.max(best, run)
  prev = a[i]
}
// a = [1, 2, 2, 3, 4, 5, 0] → 4
```

- `prev`는 비교가 끝난 뒤에 갱신합니다. 먼저 갱신하면 자기 자신과 비교합니다.
- 증가가 끊기는 순간 `run`을 1로 되돌립니다. 0으로 되돌리면 한 칸이 모자랍니다.
- 이전 단계의 값만 필요한 DP는 배열 대신 변수 둘로 줄입니다. `[a, b] = [b, a + b]`가 그 예입니다(자세히는 41편의 공간 최적화).
- 마지막 구간은 반복이 끝나도 갱신되도록 `best`를 매 반복에서 갱신합니다. 구간이 끊길 때만 갱신하면 끝에서 끝나는 구간을 놓칩니다.

## 선택 → 재귀 → 복구

모든 경우를 나열할 때 "하나 고르고, 다음 선택으로 재귀하고, 고른 것을 되돌리는" 세 줄로 이루어진 패턴입니다(자세히는 23편).

```js
const result = []
const path = []
function dfs(start) {
  result.push([...path])       // 지금 상태 기록
  for (let i = start; i < nums.length; i++) {
    path.push(nums[i])         // 선택
    dfs(i + 1)                 // 재귀
    path.pop()                 // 복구
  }
}
// nums = [1, 2, 3] → 부분집합 8개
```

- 복구는 선택의 정반대입니다. `push`에는 `pop`, 방문 표시에는 표시 해제, 합 누적에는 빼기입니다.
- 결과에 `path` 자체를 넣으면 같은 배열의 참조가 계속 들어가서 모든 결과가 마지막 상태(빈 배열)가 됩니다. `[...path]`로 복사해서 넣습니다.
- 순열은 `start` 대신 `visited` 배열로 쓴 원소를 표시하고 복구합니다. 조합과 부분집합은 `start`를 `i + 1`로 올려 순서를 고정합니다.
- 불가능한 선택을 앞에서 걸러 호출 수를 줄이는 것이 가지치기입니다. 깊이가 입력 크기에 비례하면 호출 스택을 확인합니다(자세히는 86편).

## 정렬 후 탐색

순서가 답과 무관할 때 먼저 정렬하면 비슷한 값이 이웃에 모여서 탐색이 단순해지는 패턴입니다(자세히는 26편, 30편).

```js
const s = [...a].sort((x, y) => x - y)   // 원본은 복사
let best = Infinity
for (let i = 1; i < s.length; i++) {
  best = Math.min(best, s[i] - s[i - 1])
}
// a = [9, 4, 1, 7] → 정렬 [1, 4, 7, 9] → 가장 가까운 차이 2
```

- 정렬하면 가장 가까운 두 값은 이웃합니다. 모든 쌍을 비교하는 O(N²)이 정렬 O(N log N)과 이웃 비교로 줄어듭니다.
- 정렬한 뒤에는 이분 탐색, 양끝 포인터, 이웃 비교, 구간 병합을 쓸 수 있습니다.
- 숫자 정렬은 비교 함수 `(x, y) => x - y`가 필요합니다. 없으면 사전순입니다(자세히는 26편).
- `sort`는 원본을 바꿉니다. 원래 순서가 필요하면 먼저 복사하거나 `toSorted`(ES2023)를 씁니다.
- 원래 인덱스가 답에 필요하면 값 대신 인덱스를 정렬합니다.

## Hash로 탐색 최적화

"이 값을 가진 원소가 이전에 있었는가"를 `Map`이나 `Set`으로 O(1)에 확인해 안쪽 반복을 없애는 패턴입니다(자세히는 10편).

```js
function twoSum(a, target) {
  const seen = new Map()        // 값 → 인덱스
  for (let i = 0; i < a.length; i++) {
    const j = seen.get(target - a[i])
    if (j !== undefined) return [j, i]
    seen.set(a[i], i)
  }
  return null
}
// twoSum([3, 5, 2, 8], 10) → [2, 3]
```

- 합이 `target`이 되는 짝을 찾는 이중 반복 O(N²)이 한 번의 반복 O(N)이 됩니다.
- 찾았는지는 `j !== undefined`로 판단합니다. 인덱스 0이 `if (j)`에서 거짓이 되어 놓칩니다.
- 현재 원소를 넣기 전에 찾으면 자기 자신과 짝이 되는 일이 없습니다. 같은 값이 두 번 필요한 경우(`5 + 5`)도 앞의 것과 맞춰집니다.
- 해시와 정렬 중 선택 기준은 순서가 필요하면 정렬, 존재 여부와 개수만 필요하면 해시입니다.
- 키가 객체나 배열이면 참조로 비교됩니다. 복합 키는 문자열이나 정수로 바꿔 넣습니다(자세히는 85편).

## BFS 거리 관리

가중치 없는 최소 이동 횟수를 `dist` 배열로 기록하거나 층(레벨) 단위로 세는 패턴입니다(자세히는 38편). 거리 배열은 시작점에서 각 노드까지의 거리를 저장합니다. 층별 반복은 "지금 큐에 있는 만큼"을 한 층으로 처리합니다.

```js
let level = 0
let head = 0
while (head < queue.length) {
  const end = queue.length        // 이번 층의 끝
  while (head < end) {
    const u = queue[head++]
    for (const v of adj[u]) {
      if (dist[v] !== -1) continue
      dist[v] = level + 1
      queue.push(v)
    }
  }
  level++
}
```

- `end`를 층 시작에서 고정해 둬야 이번 층에서 새로 넣은 노드가 같은 층에 섞이지 않습니다.
- 거리 배열이 있으면 층 반복이 필요 없습니다. 층 단위 처리가 필요한 문제(한 번에 모두 동시에 퍼지는 것)에만 씁니다.
- `-1`은 미방문입니다. 시작점은 거리 0으로 두고 큐에 넣습니다.
- 도착점의 `dist`가 `-1`이면 도달할 수 없다는 뜻이므로 문제의 요구(`-1` 출력 등)를 확인합니다.

## DP 상태 설계

DP는 "무엇을 상태로 삼고(무엇을 기억할지), 상태 사이에 어떤 관계가 있는지"를 정하는 일입니다(자세히는 40편). 세 가지를 순서대로 정합니다.

| 단계 | 정할 것 | 예: n계단을 1칸 또는 2칸씩 오르는 방법의 수 |
|------|---------|----------------------------------------------|
| 상태 | `dp[i]`가 무엇을 뜻하는가 | `i`번째 계단에 도착하는 방법의 수 |
| 점화식 | 앞 상태에서 어떻게 구하는가 | `dp[i] = dp[i-1] + dp[i-2]` |
| 초기값·순서 | 시작과 계산 순서 | `dp[0] = 1`, `dp[1] = 1`, `i`를 작은 쪽부터 |

```js
const MOD = 1000000007
const dp = new Array(n + 1).fill(0)
dp[0] = 1
dp[1] = 1
for (let i = 2; i <= n; i++) {
  dp[i] = (dp[i - 1] + dp[i - 2]) % MOD
}
// n = 5 → 8
```

- 상태에 필요한 정보가 모자라면 점화식이 안 세워집니다. 입력 조건이 두 개(인덱스와 남은 용량, 위치와 방향)이면 상태도 두 차원입니다.
- 한 상태가 한 번만 계산되도록 순서를 정합니다. 표를 채우는 방식(Tabulation)과 재귀에 캐시를 두는 방식(Memoization)이 있습니다.
- 값이 클 수 있으면 나머지를 매번 취합니다. 위의 합은 `MOD` 미만 두 수의 합이라 안전하지만, 곱은 2^53을 넘을 수 있습니다(자세히는 85편).
- 단서는 "경우의 수", "최댓값·최솟값", "같은 부분 문제가 반복"입니다. 탐욕이 맞는지 확신이 없을 때 DP가 안전한 선택인 경우가 많습니다(자세히는 33편).

## 그래프 모델링

문제를 노드와 간선으로 옮겨 이미 아는 그래프 알고리즘으로 푸는 패턴입니다(자세히는 35편). 무엇을 노드로, 무엇을 간선으로 삼을지가 핵심입니다.

| 문제의 말 | 노드 | 간선 | 알고리즘 |
|-----------|------|------|----------|
| 한 번에 한 글자만 바꿔 단어 변환 | 단어 | 한 글자 차이 | BFS |
| 같은 그룹인지, 연결 여부 | 원소 | 같은 그룹 관계 | Union-Find |
| 선행 관계가 있는 작업 순서 | 작업 | 선행 → 후행 | 위상 정렬 |
| 도로 길이가 있는 최단 경로 | 지점 | 도로(길이) | 다익스트라 |
| 모든 지점을 최소 비용으로 연결 | 지점 | 연결 비용 | 최소 신장 트리 |

```js
const oneDiff = (a, b) => {
  let diff = 0
  for (let i = 0; i < a.length; i++) {
    if (a[i] !== b[i]) diff++
  }
  return diff === 1
}
for (let i = 0; i < words.length; i++) {
  for (let j = i + 1; j < words.length; j++) {
    if (oneDiff(words[i], words[j])) {   // 간선 i - j
      adj[i].push(j)
      adj[j].push(i)
    }
  }
}
```

- 위 코드는 단어 길이가 모두 같다고 가정합니다. 길이가 다를 수 있으면 먼저 길이를 비교합니다.
- 간선이 방향을 가지는지(한쪽으로만 이동), 가중치가 있는지, 같은지를 먼저 정합니다. 방향 그래프이면 한쪽만 `push`합니다.
- 간선을 직접 만드는 비용도 계산합니다. 위 이중 반복은 O(N² × 단어 길이)입니다. 노드가 많으면 간선 생성 방법을 바꿔야 합니다.
- 노드를 정수로 번호 매겨 `Map`(이름 → 번호)으로 오가게 하면 배열 기반 그래프를 쓸 수 있습니다.
- 모델링이 맞는지는 작은 예제에서 노드와 간선을 손으로 그려 확인합니다(자세히는 15편).

## 문제를 상태 공간으로 바꾸기

한 위치만으로는 앞으로의 선택을 정할 수 없을 때, 필요한 정보 전체를 상태로 묶어 그 상태들 사이의 이동으로 문제를 바꾸는 패턴입니다(자세히는 39편). 예를 들어 "벽을 최대 한 번 부술 수 있는 격자 최단 거리"는 위치만으로 부술 수 있는 횟수가 남았는지 알 수 없어서, 상태가 위치와 부순 횟수의 쌍입니다.

| 문제 | 상태 | 상태 수 |
|------|------|---------|
| 벽을 한 번 부수고 도착 | (행, 열, 부순 횟수 0 또는 1) | R × C × 2 |
| 열쇠를 모으며 이동 | (행, 열, 열쇠 비트마스크) | R × C × 2의 K제곱(K는 열쇠 수) |
| 방향이 중요한 이동 | (행, 열, 방향) | R × C × 4 |

상태를 정수 하나로 인코딩해서 `dist` 배열 하나로 관리합니다.

```js
// 상태 = (r * C + c) * 2 + k   (k: 부순 횟수)
const dist = new Int32Array(R * C * 2).fill(-1)
const queue = [0]
dist[0] = 1
for (let head = 0; head < queue.length; head++) {
  const cur = queue[head]
  const k = cur & 1
  const pos = cur >> 1
  const r = Math.floor(pos / C), c = pos % C
  // 네 방향에 대해: nk = k + (벽이면 1 : 0)
  // nk > 1이면 건너뜀, next = (nr * C + nc) * 2 + nk
  // dist[next] === -1이면 dist[next] = dist[cur] + 1, push
}
```

- 상태 수가 시간과 메모리를 정합니다. 상태가 R × C × 2이면 배열이 2배입니다. 열쇠처럼 상태가 지수로 늘면 입력 크기 한계를 먼저 확인합니다(자세히는 14편).
- 방문 배열도 같은 상태 차원을 가져야 합니다. 위치만으로 표시하면 같은 칸에 다른 상태로 도착한 경우를 버려 틀립니다.
- 같은 위치라도 상태가 다르면 서로 다른 노드입니다. 거리는 상태 노드마다 따로 쌓입니다.
- 도착 판정은 위치만 보고 하고, 모든 상태 중 가장 먼저 도착한 값이 최단입니다. BFS는 가까운 상태부터 나오므로 처음 도착한 거리가 답입니다.

## 완전탐색 → 최적화하기

느려도 정답이 확실한 완전탐색을 먼저 쓰고, 병목이 되는 안쪽 반복을 자료구조로 바꿔 줄이는 패턴입니다(자세히는 16편, 80편). 최적화한 코드가 완전탐색과 같은 답을 내는지 대조할 수 있다는 것이 장점입니다.

순서는 다음과 같습니다.

1. 완전탐색을 쓰고 작은 입력에서 정답을 확인합니다.
2. 입력 최댓값에서 연산 횟수를 어림해 얼마나 줄여야 하는지 압니다(자세히는 13편).
3. 가장 안쪽에서 반복되는 일이 무엇인지 찾고, 아래 표의 대체를 고릅니다.
4. 최적화 풀이와 완전탐색의 출력을 무작위 입력으로 비교합니다.

| 안쪽에서 반복하는 일 | 대체 |
|----------------------|------|
| 값이 있는지 찾기 | `Set`, `Map` |
| 정렬된 곳에서 위치 찾기 | 이분 탐색 |
| 구간의 합 구하기 | 누적합 |
| 조건에 맞는 구간 찾기 | 투 포인터, 슬라이딩 윈도우 |
| 같은 부분 문제 다시 풀기 | DP, 메모이제이션 |

합이 `k`인 연속 부분 배열의 개수를 구하는 예입니다. 먼저 완전탐색입니다.

```js
let cnt = 0
for (let i = 0; i < n; i++) {
  let sum = 0
  for (let j = i; j < n; j++) {
    sum += a[j]
    if (sum === k) cnt++
  }
}
```

구간 합이 `접두 합[j] - 접두 합[i]`라는 점에서, 현재까지의 합에서 `k`를 뺀 값이 앞에 몇 번 나왔는지 `Map`으로 세면 안쪽 반복이 사라집니다(자세히는 29편).

```js
const seen = new Map([[0, 1]])   // 접두 합 0이 한 번
let sum = 0
let cnt = 0
for (const x of a) {
  sum += x
  cnt += seen.get(sum - k) ?? 0
  seen.set(sum, (seen.get(sum) ?? 0) + 1)
}
```

- 완전탐색은 O(N²), 최적화는 O(N)입니다. 두 코드의 `cnt`를 무작위 입력으로 비교합니다.
- 접두 합 0을 `seen`의 처음에 넣어 두어야 맨 앞에서 시작하는 구간을 셉니다. 빼먹으면 그 구간이 사라집니다.
- 음수가 섞인 배열에서는 투 포인터가 성립하지 않아 이 방식을 씁니다.
- 최적화 코드가 틀렸을 때 줄여 가며 원인을 찾으려면 완전탐색이 기준입니다. 완전탐색을 버리지 말고 보관합니다.

## 핵심 정리

- 패턴은 문제의 단서에서 고릅니다. 개수는 빈도수, 중복은 방문 체크, 훑으며 최댓값은 갱신, 연속은 이전 상태, 모든 경우는 선택·재귀·복구입니다.
- 초기값은 비교에서 지는 값(`Infinity`, `-Infinity`)으로 두고, `prev`는 비교가 끝난 뒤에 갱신하며, 결과에 `path`를 넣을 때는 `[...path]`로 복사합니다.
- 정렬 후 탐색은 `sort`에 숫자 비교 함수를 쓰고 원본은 복사하며, 해시 탐색은 `!== undefined`로 존재를 판단합니다.
- BFS는 큐에 넣을 때 거리를 정하고, 층 단위가 필요하면 `end`를 고정합니다. DP는 상태·점화식·초기값 세 가지를 정합니다.
- 그래프 모델링은 노드와 간선의 의미를 먼저 정하고, 위치만으로 부족하면 필요한 정보 전체를 상태로 묶어 방문 배열도 같은 차원으로 둡니다.
- 완전탐색을 먼저 써서 기준으로 삼고, 안쪽 반복을 해시·이분 탐색·누적합으로 바꿔 대조합니다.
