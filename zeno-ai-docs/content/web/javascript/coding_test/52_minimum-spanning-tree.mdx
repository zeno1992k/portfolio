## MST 개념

**신장 트리**(spanning tree)는 연결된 무방향 그래프의 모든 정점을 포함하면서 **사이클이 없는** 부분 그래프입니다. 정점이 V개이면 간선은 정확히 V - 1개입니다. **최소 신장 트리**(MST, Minimum Spanning Tree)는 가중치가 있는 그래프에서 간선 가중치의 합이 가장 작은 신장 트리입니다.

- 모든 정점을 연결하는 최소 비용(도로, 통신선, 배관 공사)을 구하는 문제의 모델입니다.
- 그래프가 연결되어 있어야 신장 트리가 존재합니다. 연결되어 있지 않으면 연결 요소마다 MST를 만든 **최소 신장 숲**을 구합니다.
- MST는 하나가 아닐 수 있습니다. 간선 가중치가 **모두 다르면 유일**하고, 같은 가중치가 있으면 비용이 같은 MST가 여럿일 수 있습니다. 비용은 항상 같습니다.
- 무방향 그래프의 개념입니다. 방향 그래프의 MST(최소 아크 분기)는 다른 문제입니다.

두 알고리즘의 정당성은 같은 성질에서 나옵니다.

- **컷 성질:** 정점을 두 그룹으로 나눌 때 두 그룹을 잇는 간선 중 가장 가벼운 간선을 포함하는 MST가 존재합니다.
- **사이클 성질:** 사이클에서 가장 무거운 간선(유일한 최대)은 어떤 MST에도 들어가지 않습니다.

**MST는 최단경로 트리가 아닙니다.** 정점 A, B, C와 간선 A–B(2), B–C(2), A–C(3)이 있을 때 MST는 A–B, B–C이고 합은 4입니다. A에서의 최단경로 트리는 A–B(2), A–C(3)이고 합이 5입니다. MST는 간선 합을 최소로 하고, 최단경로 트리는 시작점에서 각 정점까지의 거리를 최소로 합니다(자세히는 48편).

| 비교 | MST | 최단경로 |
|------|-----|----------|
| 목표 | 전체 간선 합 최소 | 시작점에서 각 정점까지 거리 최소 |
| 시작점 | 필요 없음 | 필요 |
| 결과 | V - 1개 간선의 트리 | 거리 배열 |

**문제의 단서:** "모든 정점(도시, 컴퓨터)을 연결하는 최소 비용", "N - 1개의 도로만 남기고 나머지를 제거"입니다.

이 편의 코드는 예시 그래프를 공유합니다. 정점은 0–4, 간선은 `[u, v, w]` 형식입니다.

```js
const edges = [
  [0, 1, 4], [0, 2, 3], [1, 2, 1],
  [1, 3, 2], [2, 3, 2], [3, 4, 2],
]
// MST 비용: 8 (간선 1–2, 1–3, 3–4, 0–2)
```

## Kruskal

Kruskal은 **가벼운 간선부터 보며, 사이클을 만들지 않으면 채택**하는 알고리즘입니다. 간선을 가중치 오름차순으로 정렬하고 차례로 확인합니다. V - 1개를 채택하면 끝납니다.

- 정렬된 순서로 보는 간선은 컷 성질에 의해 "지금까지 고른 간선과 이어도 안전한" 가장 싼 간선입니다. 이미 연결된 두 정점을 잇는 간선은 사이클을 만들므로 건너뜁니다.
- 사이클 검사가 핵심이고, 간선을 고를 때마다 DFS로 확인하면 O(E · V)입니다. 이 검사를 Union-Find로 바꾸면 거의 O(1)이 됩니다.

예시 그래프의 추적입니다(가중치가 같은 간선은 입력 순서).

| 순서 | 간선 | 가중치 | 판정 | 누적 |
|------|------|--------|------|------|
| 1 | 1–2 | 1 | 채택 | 1 |
| 2 | 1–3 | 2 | 채택 | 3 |
| 3 | 2–3 | 2 | 건너뜀(2와 3이 이미 연결) | 3 |
| 4 | 3–4 | 2 | 채택 | 5 |
| 5 | 0–2 | 3 | 채택, 4개를 채택해 종료 | 8 |

- 0–1(4)은 확인하지 않고 끝납니다. 같은 가중치의 간선은 어느 순서든 합이 같습니다.

## Union-Find와 Kruskal

사이클 검사를 Union-Find(51편)의 `union`으로 합니다. `union`이 `false`를 반환하면 양 끝점이 이미 같은 집합이라 사이클이 생기는 간선입니다.

```js
function kruskal(n, edges) {
  const sorted = [...edges].sort((a, b) => a[2] - b[2])
  const dsu = new DSU(n)           // 51편의 템플릿
  let total = 0, used = 0
  for (const [u, v, w] of sorted) {
    if (!dsu.union(u, v)) continue // 사이클이면 건너뜀
    total += w
    if (++used === n - 1) break    // V - 1개를 채택하면 종료
  }
  return used === n - 1 ? total : -1   // -1: 연결되지 않음
}
```

- `[...edges]`로 복사하면 원본 순서를 보존합니다. 정렬은 가중치 `a[2] - b[2]`의 숫자 비교입니다(자세히는 26편).
- 시간복잡도는 정렬이 O(E log E), Union-Find가 간선당 거의 상수라서 합쳐 O(E log E)입니다. `E ≤ V²`라서 O(E log V)와 같습니다.
- 간선 목록이 입력 형태일 때 인접 리스트를 만들 필요가 없어서 가장 짧게 구현됩니다.
- 그래프가 연결되어 있지 않으면 `used`가 V - 1에 못 미치므로 그것으로 판단합니다. 연결 요소마다 MST를 만든 숲의 비용이 필요하면 `used` 확인 없이 `total`을 반환합니다.

**흔한 실수:**

- 간선 목록을 `n - 1`개만 읽는 것입니다. 모든 간선을 정렬해서 봐야 합니다.
- 정렬 비교 함수를 `a[2] > b[2]`처럼 불리언으로 쓰는 것입니다. 음수, 0, 양수 중 하나인 숫자를 반환해야 합니다(자세히는 26편).

## Prim

Prim은 **한 정점에서 시작해 트리를 키워 가는** 알고리즘입니다. 트리 안의 정점과 트리 밖의 정점을 잇는 간선 중 **가장 가벼운 것**을 고르는 일을 모든 정점이 트리에 들어올 때까지 반복합니다. 컷 성질의 "트리 안과 밖"이 그 컷입니다.

우선순위 큐에 `[가중치, 정점]`을 넣는 구현입니다.

```js
function prim(n, adj) {            // adj[u] = [[v, w], ...]
  const seen = new Array(n).fill(false)
  const pq = new Heap((a, b) => a[0] - b[0])  // 47편
  pq.push([0, 0])                  // 시작 정점 0, 비용 0
  let total = 0, cnt = 0
  while (pq.size && cnt < n) {
    const [w, u] = pq.pop()
    if (seen[u]) continue          // 이미 트리 안
    seen[u] = true; total += w; cnt++
    for (const [v, c] of adj[u])
      if (!seen[v]) pq.push([c, v])
  }
  return cnt === n ? total : -1    // -1: 연결되지 않음
}
```

인접 리스트는 무방향이라서 양쪽에 넣습니다.

```js
const adj = Array.from({ length: n }, () => [])
for (const [u, v, w] of edges) {
  adj[u].push([v, w])
  adj[v].push([u, w])
}
```

- 정점은 **큐에서 꺼낼 때** 트리에 넣습니다(`seen`). 간선을 넣을 때 표시하면 더 싼 간선이 뒤에 나오는 경우를 놓칩니다.
- Dijkstra(48편)와 모양이 거의 같습니다. 차이는 큐에 넣는 값입니다. Dijkstra는 시작점에서의 누적 거리 `d + w`, Prim은 **간선 하나의 가중치 `w`** 입니다.
- 시간복잡도는 간선마다 최대 한 번 큐에 들어가서 O(E log E) = O(E log V)입니다.
- 시작 정점은 어디든 결과의 합이 같습니다. 연결되어 있지 않으면 시작 정점이 속한 연결 요소만 구합니다.

예시 그래프를 0에서 시작한 추적입니다.

| 순서 | 트리에 넣은 정점 | 사용한 간선 | 누적 |
|------|------------------|-------------|------|
| 1 | 0 | 시작 | 0 |
| 2 | 2 | 0–2 (3) | 3 |
| 3 | 1 | 2–1 (1) | 4 |
| 4 | 3 | 1–3 (2) | 6 |
| 5 | 4 | 3–4 (2) | 8 |

- 4단계에서 2–3(2)도 가중치가 같아 어느 쪽을 고르든 합은 같습니다.

**Kruskal과 Prim의 선택:**

| 항목 | Kruskal | Prim |
|------|---------|------|
| 핵심 도구 | 정렬 + Union-Find | 우선순위 큐 |
| 입력 형태 | 간선 목록 | 인접 리스트(또는 행렬) |
| 시간복잡도 | O(E log E) | O(E log V), 밀집이면 O(V²) |
| 유리한 경우 | 간선이 적은 희소 그래프, 간선 목록 입력 | 간선이 많은 밀집 그래프 |

**흔한 실수:** Prim에서 Dijkstra처럼 `d + w`를 큐에 넣는 것입니다. 누적 거리가 아니라 간선 하나의 가중치로 비교해야 합니다.

## MST 비용 계산

MST 문제의 답은 대부분 **선택한 V - 1개 간선의 가중치 합**입니다. 합을 구할 때 확인할 것은 다음과 같습니다.

- **연결 여부.** 채택한 간선이 V - 1개가 아니면 MST가 없습니다. 문제가 지정한 값(`-1` 등)을 출력합니다.
- **값의 범위.** 합은 `(V - 1) × 최대 가중치` 이하입니다. 이 값이 `Number.MAX_SAFE_INTEGER`를 넘을 수 있으면 BigInt를 씁니다(자세히는 50편).
- **이미 있는 연결.** 일부 정점이 이미 연결되어 있으면 그 간선을 비용 0으로 먼저 `union`한 뒤 Kruskal을 돌립니다.
- **전체에서 뺀 비용.** "모든 간선의 합에서 MST를 뺀 만큼 절약한다" 유형은 `전체 합 - MST 합`이 답입니다. 같은 값의 MST가 여럿이어도 합은 같으므로 결과는 하나입니다.
- **가장 큰 간선을 최소화.** MST에서 가장 큰 간선은 모든 신장 트리 중 가장 큰 간선의 최솟값입니다. 그래서 "경로 중 가장 무거운 간선을 최소화"하는 문제도 MST로 풉니다.
- **점들의 좌표가 주어질 때.** 모든 점 쌍이 간선인 완전 그래프라서 간선이 V(V - 1) / 2개입니다. 점이 많지 않으면(수천 이하) 간선을 모두 만들어 Kruskal을 쓰거나 다음 절의 Prim O(V²)를 씁니다. 제곱 거리로 비교해도 같은 트리가 나오며, 비용은 선택한 간선마다 제곱근을 취해 합합니다(자세히는 60편).
- 간선이 정확히 V - 1개이면 이미 트리이므로 그 합이 답입니다.

**흔한 실수:** 정점 번호가 1부터인데 0부터로 가정해 `DSU(n)`을 만드는 것, 무방향 간선을 인접 리스트에 한쪽만 넣는 것입니다.

## 밀집 그래프의 O(V²) Prim

간선이 많아서 E가 V²에 가까우면 힙을 쓰는 O(E log V)는 O(V² log V)로 오히려 느립니다. 힙 없이 **배열을 선형 탐색**하는 Prim은 O(V²)입니다. 트리 밖 정점마다 트리와 이어지는 최소 가중치 `best[v]`를 유지합니다.

```js
function primDense(n, w) {        // w[u][v]: 없으면 Infinity
  const best = new Array(n).fill(Infinity)
  const used = new Array(n).fill(false)
  let total = 0
  best[0] = 0
  for (let i = 0; i < n; i++) {
    let u = -1                    // 트리 밖에서 best가 가장 작은 정점
    for (let v = 0; v < n; v++)
      if (!used[v] && (u < 0 || best[v] < best[u])) u = v
    if (best[u] === Infinity) return -1   // 연결되지 않음
```

```js
    used[u] = true
    total += best[u]
    for (let v = 0; v < n; v++)   // u를 통해 best 갱신
      if (w[u][v] < best[v]) best[v] = w[u][v]
  }
  return total
}   // 위 코드와 이어지는 한 함수
```

- 매번 최소를 O(V)로 찾고 갱신도 O(V)라서 전체 O(V²)이고, 인접 행렬 `w`가 입력일 때 자연스럽습니다. 공간은 O(V²)입니다.
- 자기 자신과 간선이 없는 쌍은 `Infinity`로 둡니다.
- 이미 선택한 정점의 `best`가 갱신되어도 다시 선택하지 않으므로 합에는 영향이 없습니다.
- 어느 쪽이 빠른지는 E로 정합니다. 힙 방식은 E log V, 배열 방식은 V²이므로 E가 V² / log V보다 크면 배열이 유리합니다.

## 최대 신장 트리

최대 신장 트리는 간선 가중치의 합이 **가장 큰** 신장 트리입니다. 가중치 부호를 뒤집어 MST를 구하는 것과 같고, 구현은 Kruskal의 정렬을 **내림차순**으로 바꾸는 한 줄이면 됩니다.

```js
const sorted = [...edges].sort((a, b) => b[2] - a[2])
// 나머지는 kruskal과 같다. 예시 그래프의 결과: 11
```

- Prim이면 큐를 최대 힙으로 바꿉니다. 최소 힙에 `-w`를 넣어 부호를 뒤집는 방법도 있습니다(46편).
- 예시 그래프에서는 0–1(4), 0–2(3), 1–3(2), 3–4(2)를 채택해 합이 11입니다.
- 음수 가중치가 있어도 MST와 최대 신장 트리는 그대로 구할 수 있습니다. 최단거리와 달리 음수가 문제가 되지 않습니다.

## 두 번째 최소 신장 트리 개요

두 번째 최소 신장 트리는 MST 다음으로 합이 작은 신장 트리입니다. **MST에서 간선을 정확히 하나만 바꾼** 트리 중에 반드시 하나가 있다는 성질을 씁니다.

- MST에 들어가지 않은 간선 `(u, v, w)`를 추가하면 MST 안의 u–v 경로와 합쳐 사이클이 생깁니다. 그 경로에서 가장 무거운 간선을 빼면 새 신장 트리입니다. 합은 `MST 합 + w - (경로의 최대 간선)`입니다.
- 모든 비 MST 간선에 대해 이 값을 구해 **가장 작은 것**이 두 번째 MST의 합입니다.

예시 그래프에서는 다음과 같습니다.

| 추가하는 간선 | MST 안의 경로 | 경로 최대 간선 | 새 합 |
|---------------|----------------|----------------|-------|
| 0–1 (4) | 0–2–1 | 3 | 8 + 4 - 3 = 9 |
| 2–3 (2) | 2–1–3 | 2 | 8 + 2 - 2 = 8 |

- 2–3은 가중치가 같은 간선으로 교체해서 합이 8로 MST와 같습니다. 문제가 "합이 MST보다 **엄격히 큰** 트리"를 요구하면 경로의 최대 간선과 가중치가 같은 후보를 건너뛰어야 하고, 그러면 답은 9입니다. 이때는 경로의 최대 간선과 함께 **그보다 작은 가장 큰 간선**(두 번째 최대)까지 관리합니다.
- 단순한 방법은 MST의 간선을 하나씩 빼고 MST를 다시 구하는 것으로 O(VE)입니다.
- 빠른 방법은 MST를 루트 트리로 만들고 Binary Lifting으로 두 정점 사이 경로의 최대 간선을 O(log V)에 구해서 전체 O(E log V)입니다(자세히는 66편). V가 작으면 모든 정점 쌍의 경로 최대 간선을 DFS로 미리 구하는 O(V²) 방법도 있습니다.

**문제의 단서:** "두 번째로 싼 연결 방법", "MST가 유일한가"입니다. MST가 유일한지는 위의 교체 비용이 0인 후보가 있는지로도 판단할 수 있습니다.

## 핵심 정리

- 신장 트리는 모든 정점을 잇는 V - 1개 간선의 트리이고, MST는 가중치 합이 최소인 신장 트리입니다. 가중치가 모두 다르면 유일하고, 같으면 비용이 같은 MST가 여럿일 수 있습니다.
- Kruskal은 간선을 오름차순으로 정렬해 사이클을 만들지 않으면 채택하며, Union-Find로 사이클을 검사하면 O(E log E)입니다. V - 1개를 채택하지 못하면 연결되지 않은 그래프입니다.
- Prim은 시작 정점에서 트리를 키우며, 큐에 넣는 값이 누적 거리가 아니라 간선 하나의 가중치인 점이 Dijkstra와 다릅니다. 힙으로 O(E log V), 배열로 O(V²)입니다.
- MST 비용은 V - 1개 간선의 합이고, 연결 여부와 합의 범위를 확인합니다. 밀집 그래프나 완전 그래프는 O(V²) Prim이 유리합니다.
- 최대 신장 트리는 Kruskal의 정렬만 내림차순으로 바꾸고, 두 번째 MST는 비 MST 간선 하나를 넣고 경로의 최대 간선을 빼는 교체 중 최소입니다.
