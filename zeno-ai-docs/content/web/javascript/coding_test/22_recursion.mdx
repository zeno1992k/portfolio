## 재귀 개념

재귀(recursion)는 함수가 자기 자신을 호출해서, 문제를 같은 모양의 더 작은 문제로 줄여 푸는 방법입니다. 재귀 함수는 두 부분으로 이루어집니다.

- 종료 조건(base case): 더 줄이지 않고 답을 바로 돌려주는 경우
- 재귀 호출(recursive case): 더 작은 입력으로 자기 자신을 부르고, 그 결과로 답을 만드는 경우

```js
function factorial(n) {
  if (n <= 1) return 1            // 종료 조건
  return n * factorial(n - 1)     // 재귀 호출
}
console.log(factorial(5)) // 120
```

`factorial(5)`는 `5 * factorial(4)`로, `factorial(4)`는 `4 * factorial(3)`으로 줄어들다가 `factorial(1)`에서 멈추고, 돌아오면서 곱이 완성됩니다.

- 재귀로 풀 수 있는 문제는 반복문으로도 풀 수 있습니다. 재귀는 구조가 스스로를 닮은 문제(트리, 경우의 수, 절반으로 나누기)를 짧게 쓰게 해 줍니다.
- 완전탐색, 백트래킹, DFS, 분할 정복, 동적 계획법의 바탕이 되는 기법입니다.
- 재귀 설계는 세 질문으로 정리됩니다. 어떤 입력이 가장 작은가(종료 조건), 한 단계 줄인 입력은 무엇인가(재귀 호출), 줄인 문제의 답으로 지금 답을 어떻게 만드는가(결합)입니다.

## 종료 조건

종료 조건은 재귀가 멈추는 지점입니다. 모든 호출 경로가 결국 종료 조건에 도달해야 합니다. 도달하지 못하면 호출이 끝없이 쌓여 RangeError가 납니다(아래 "재귀 깊이 한계").

```js
function countDown(n) {
  if (n === 0) return        // 종료 조건
  console.log(n)
  countDown(n - 1)           // 입력이 종료 조건에 가까워진다
}
countDown(3) // 3 2 1
```

종료 조건이 맞으려면 두 가지가 성립해야 합니다.

- 재귀 호출마다 입력이 종료 조건 쪽으로 줄어듭니다. 인자가 `n - 1`이면 줄어들고 `n + 1`이면 멀어집니다.
- 입력이 될 수 있는 모든 값이 종료 조건에 걸리거나 줄어든 끝에 걸립니다.

자주 쓰는 종료 조건의 모양입니다.

| 대상 | 종료 조건 |
|------|-----------|
| 정수 n을 1씩 줄임 | `n === 0` 또는 `n <= 1` |
| 배열을 인덱스 i로 훑음 | `i === arr.length` |
| 구간 `[l, r]`을 줄임 | `l > r` 또는 `l === r` |
| 트리 | 노드가 `null` |
| 선택 횟수를 채움 | 깊이 `=== k` |

- 종료 조건이 여러 개일 수 있습니다. 피보나치는 `fib(n - 1)`과 `fib(n - 2)`를 모두 부르므로 `n < 2`로 0과 1을 함께 처리해야 합니다.
- 종료 조건은 재귀 호출보다 앞에 둡니다. 뒤에 두면 호출이 먼저 일어나 멈추지 못합니다.

**흔한 실수:**

- `n === 0`만 검사했는데 입력이 음수일 수 있는 경우입니다. `factorial(-1)`은 `-2`, `-3`, …으로 줄어들며 종료 조건에 닿지 못합니다. 입력 범위를 확인하거나 `n <= 1`처럼 부등호로 씁니다.
- 재귀 호출 결과를 `return`하지 않는 것입니다. 호출은 되지만 반환값이 `undefined`로 끊깁니다.

## 호출 스택

호출 스택(call stack)은 실행 중인 함수들을 쌓아 두는 후입선출 구조입니다. 함수를 호출하면 매개변수, 지역 변수, 돌아갈 위치를 담은 스택 프레임이 쌓이고, 함수가 반환되면 그 프레임이 제거됩니다. 재귀 호출은 같은 함수의 프레임이 호출마다 따로 쌓입니다.

```js
function show(n) {
  if (n === 0) return
  console.log('in', n)
  show(n - 1)
  console.log('out', n)
}
show(3) // in 3, in 2, in 1, out 1, out 2, out 3
```

- 호출하며 내려갈 때 `in`이 3, 2, 1 순서로 찍히고, 반환하며 올라올 때 `out`이 1, 2, 3 순서로 찍힙니다. 재귀 호출 앞에 쓴 코드는 내려가는 길에서, 뒤에 쓴 코드는 올라오는 길에서 실행됩니다.
- `sum(n) = n + sum(n - 1)`로 `sum(2)`를 호출하면 스택은 이렇게 변합니다.

| 시점 | 스택(아래 → 위) | 일어나는 일 |
|------|-----------------|-------------|
| 호출 | sum(2) | |
| 호출 | sum(2), sum(1) | |
| 호출 | sum(2), sum(1), sum(0) | sum(0)이 0 반환 |
| 반환 | sum(2), sum(1) | sum(1)이 1 + 0 = 1 반환 |
| 반환 | sum(2) | sum(2)가 2 + 1 = 3 반환 |

- 스택에 동시에 쌓이는 프레임의 최대 개수가 재귀 깊이입니다. 재귀의 공간 복잡도는 O(깊이)입니다. `sum(n)`은 깊이가 n이라 O(n)입니다.
- 프레임이 사라지면 그 호출의 지역 변수도 사라집니다. 호출마다 지역 변수는 독립적이어서, 같은 이름의 변수가 호출마다 다른 값을 가질 수 있습니다.

## 재귀 상태 전달

재귀 호출 사이에 상태(지금까지의 선택, 합, 방문 정보)를 넘기는 방법은 세 가지입니다.

1. 매개변수로 넘기기: 호출마다 독립된 값이라 안전합니다. 숫자·문자열 같은 원시 값은 복사됩니다.
2. 객체·배열을 공유하기: 참조가 넘어가서 모든 호출이 같은 객체를 봅니다. 한 호출에서 바꾸면 다른 호출에도 보입니다.
3. 바깥 함수의 변수(클로저)로 두기: 매개변수 목록이 짧아집니다. 결과를 모으는 배열이나 방문 배열에 씁니다.

인덱스와 누적값을 매개변수로 넘기는 형태가 가장 기본입니다.

```js
function sumArr(arr, i, acc) {
  if (i === arr.length) return acc
  return sumArr(arr, i + 1, acc + arr[i])
}
console.log(sumArr([4, 1, 5], 0, 0)) // 10
```

- 배열을 줄이려고 `arr.slice(1)`을 넘기면 호출마다 복사가 일어나 전체가 O(n²)이 됩니다. 인덱스나 구간 `(l, r)`만 넘깁니다.
- 결과를 모으는 문제는 공유 배열과 현재 경로를 바깥에 두고, 안쪽 함수에는 바뀌는 값만 넘깁니다.

```js
function subsets(arr) {
  const out = []
  const cur = []
  function go(i) {
    if (i === arr.length) { out.push([...cur]); return }
    go(i + 1)          // arr[i]를 선택하지 않음
    cur.push(arr[i])   // 선택
    go(i + 1)
    cur.pop()          // 선택을 되돌림
  }
  go(0)
  return out
}
console.log(subsets([1, 2])) // [[], [2], [1], [1, 2]]
```

- 공유 상태를 바꿨으면 호출이 끝나기 전에 되돌려야 다음 경로가 깨끗한 상태로 시작합니다. 이 패턴이 백트래킹입니다(자세히는 23편).

**흔한 실수:**

- 결과에 `out.push(cur)`로 공유 배열 자체를 넣는 것입니다. 이후 `cur`가 바뀌면 이미 넣은 결과도 바뀝니다. `[...cur]`로 복사해서 넣습니다.
- 바깥 변수를 초기화하지 않아서 테스트 케이스를 여러 개 돌릴 때 이전 값이 남는 것입니다. 상태는 케이스마다 새로 만듭니다.

## 재귀 반환값

재귀 호출이 돌려준 값을 위로 합쳐서 답을 만드는 방식입니다. 반환값의 쓰임은 세 가지입니다.

- 값을 합치기: 하위 문제의 답을 더하거나 최댓값을 취해 지금 답을 만듭니다.
- 참 거짓으로 일찍 끝내기: 하나라도 찾으면 `true`를 위로 전파해 나머지 탐색을 건너뜁니다.
- 반환값 없이 바깥 변수에 누적하기: 개수 세기, 결과 모으기에 씁니다.

```js
function height(node) {
  if (node === null) return 0
  const l = height(node.left)
  const r = height(node.right)
  return 1 + Math.max(l, r)
}
// 노드 1(왼쪽 2, 오른쪽 3), 3의 왼쪽이 4이면 높이 3
```

참 거짓 반환은 단락 평가(`||`)로 일찍 끝냅니다. 배열에서 일부를 골라 합이 목표가 되는지 확인합니다.

```js
function hasSum(arr, i, target) {
  if (i === arr.length) return target === 0
  return hasSum(arr, i + 1, target - arr[i])
      || hasSum(arr, i + 1, target)
}
console.log(hasSum([3, 5, 7], 0, 12)) // true (5 + 7)
console.log(hasSum([3, 5, 7], 0, 11)) // false
```

- `||` 앞쪽이 `true`이면 뒤쪽 호출은 실행되지 않습니다.
- 같은 하위 호출 결과를 두 번 쓸 때는 변수에 담아 한 번만 계산합니다. 거듭제곱을 절반으로 나눠 구하는 코드가 대표입니다.

```js
function pow(base, exp) {
  if (exp === 0) return 1
  const half = pow(base, Math.floor(exp / 2)) // 한 번만 호출
  return exp % 2 === 1 ? half * half * base : half * half
}
console.log(pow(2, 10)) // 1024
```

- `pow(base, exp / 2) * pow(base, exp / 2)`처럼 두 번 부르면 호출이 두 배씩 늘어 O(exp)가 됩니다. 한 번만 부르면 깊이 O(log exp)입니다.

**흔한 실수:** 재귀 호출의 결과를 `return`하지 않거나, 반환값을 쓰는 자리에서 `undefined`를 합치는 것입니다. `1 + undefined`는 `NaN`입니다. 모든 경로가 값을 돌려주는지 확인합니다.

## 재귀 트리

재귀 트리(recursion tree)는 호출 하나를 노드로, 호출이 부른 호출을 자식으로 그린 트리입니다. 호출 횟수는 트리의 노드 수이고, 재귀 깊이는 트리의 높이입니다. 그래서 시간 복잡도는 대략 노드 수에 노드당 작업을 곱한 값이고, 공간은 높이에 비례합니다.

`fib(4)`의 호출을 들여쓰기로 보이면 이렇습니다.

```text
fib(4)
 fib(3)
  fib(2)
   fib(1)
   fib(0)
  fib(1)
 fib(2)
  fib(1)
  fib(0)
```

- `fib(2)`가 두 번 계산됩니다. 같은 입력의 중복 호출이 노드를 지수적으로 늘립니다. 호출 수는 `fib(5)`가 15, `fib(10)`이 177, `fib(30)`이 2,692,537입니다(직접 센 값).
- 호출 수 `C(n)`은 `C(n) = C(n - 1) + C(n - 2) + 1`을 만족하고, 대략 1.618의 n제곱으로 커집니다. 2의 n제곱으로 어림하면 안전한 상한입니다.
- 중복 호출은 한 번 계산한 결과를 저장해 재사용하면 없앨 수 있습니다(메모이제이션, 자세히는 40편).

```js
const memo = new Map()
function fib(n) {
  if (n < 2) return n
  if (memo.has(n)) return memo.get(n)
  const v = fib(n - 1) + fib(n - 2)
  memo.set(n, v)
  return v
}
// 서로 다른 입력은 n개뿐이라 호출이 O(n)
```

재귀 구조별 비용 읽는 법입니다.

| 구조 | 노드 수 | 예 |
|------|---------|-----|
| 호출 1개, 입력 1 감소 | n | `sum(n)`, 팩토리얼 |
| 호출 1개, 입력 절반 | log n | 이진 탐색, `pow` |
| 호출 2개, 입력 1 감소 | 2의 n제곱 | 부분집합 |
| 호출 2개, 입력 1과 2 감소 | 약 1.618의 n제곱 | 메모 없는 피보나치 |
| 호출 b개, 깊이 d | b의 d제곱 | 완전탐색 |
| 호출 2개, 입력 절반, 노드당 O(n) 작업 | 레벨당 O(n), 레벨 log n | 병합 정렬(자세히는 25편) |

## 재귀 디버깅

재귀 코드는 호출이 쌓여서 눈으로 추적하기 어렵습니다. 아래 순서로 좁힙니다.

1. 가장 작은 입력(0, 1, 빈 배열)으로 먼저 실행합니다. 종료 조건이 틀리면 여기서 드러납니다.
2. 입력을 작게 줄이고 호출마다 인자와 반환값을 들여쓰기로 찍습니다. 들여쓴 칸 수가 재귀 깊이입니다.

```js
function sum(n, depth = 0) {
  const pad = ' '.repeat(depth)
  console.log(pad + 'sum(' + n + ')')
  if (n === 0) { console.log(pad + '-> 0'); return 0 }
  const r = n + sum(n - 1, depth + 1)
  console.log(pad + '-> ' + r)
  return r
}
sum(2)
```

```text
sum(2)
 sum(1)
  sum(0)
  -> 0
 -> 1
-> 3
```

- 호출 횟수를 세는 카운터를 바깥에 두고 입력을 키워 보면, 호출이 입력에 비례해 늘어나는지 지수로 늘어나는지 확인할 수 있습니다.
- `RangeError: Maximum call stack size exceeded`가 나면 스택 트레이스에 같은 함수가 반복됩니다. 종료 조건에 닿지 못하는지(인자가 줄지 않음), 깊이가 정말 큰 입력인지를 구분합니다.
- 공유 배열을 쓰는 코드는 호출 전후의 배열을 찍어 되돌리기를 빠뜨렸는지 확인합니다.
- 큰 입력에서는 로그를 찍으면 매우 느려집니다. 제출 전에 로그를 모두 지웁니다.

## 재귀 깊이 한계

호출 스택은 크기가 정해져 있습니다. 초과하면 V8(Node.js)은 `RangeError: Maximum call stack size exceeded`를 던집니다. 종료 조건이 없는 무한 재귀뿐 아니라, 종료 조건은 맞아도 깊이가 너무 큰 정상 입력에서도 발생합니다.

```js
function sum(n) {
  if (n === 0) return 0
  return n + sum(n - 1)
}
sum(1000)    // 500500
sum(200000)  // RangeError (호출 스택 초과)
```

- 허용 깊이는 고정된 수가 아닙니다. 프레임 하나의 크기(인자와 지역 변수의 수)와 실행 상태에 따라 달라집니다. Node.js 24.15 기본 설정에서 직접 측정한 대략의 최대 깊이입니다.

| 함수 | 최대 깊이(대략) |
|------|-----------------|
| 인자·지역 변수가 없는 함수 | 12,500 |
| `sum(n)` | 10,900 |
| 인자 5개와 지역 변수 3개 | 5,400 |
| 인접 리스트 DFS(재귀) | 4,900 |

- 위 값은 기준으로 쓰면 안 됩니다. 같은 코드도 환경과 호출 이력에 따라 달라집니다. 채점 사이트의 한계는 공식 자료로 확인하지 못해서 수치로 쓰지 않습니다.
- 안전하게는 깊이가 수천을 넘을 수 있는 입력(길이 10만의 배열, 한 줄로 늘어선 그래프, 편향된 트리)에는 재귀를 쓰지 않는다고 판단합니다. 최악의 입력에서 깊이가 얼마인지가 기준입니다.
- 대처 방법은 세 가지입니다.
  - 반복문으로 바꿉니다. 꼬리 재귀 형태이면 `while`로 직접 바뀝니다.
  - 명시적 스택으로 바꿉니다. DFS가 대표입니다(아래 절).
  - 문제를 절반으로 나눠 깊이를 로그로 줄입니다. 병합 정렬과 `pow`가 그렇습니다.
- `try`/`catch`로 RangeError를 잡을 수는 있지만 이미 한계에 닿았다는 뜻이라 해결책이 아닙니다.
- 입력 크기로 알고리즘을 판별할 때의 호출 스택 주의는 86편에서도 다룹니다.

## 재귀 DFS를 반복 DFS로 변환

재귀 호출이 하던 일, 즉 호출 스택에 노드를 쌓는 일을 직접 만든 배열 스택이 대신하게 하면 깊이 제한이 사라집니다. 배열의 `push`와 `pop`을 스택으로 씁니다(자세히는 19편).

```js
// 인접 리스트: 1 → 2, 3 / 2 → 4 / 3 → 4
const adj = [[], [2, 3], [4], [4], []]
function dfs(u, seen, order) {
  seen[u] = 1
  order.push(u)
  for (const v of adj[u]) if (!seen[v]) dfs(v, seen, order)
}
// 방문 순서: 1 2 4 3
```

반복 버전은 스택에서 꺼낸 노드를 방문하고 자식을 넣습니다.

```js
function dfsIter(start) {
  const seen = new Uint8Array(adj.length)
  const order = []
  const stack = [start]
  while (stack.length > 0) {
    const u = stack.pop()
    if (seen[u]) continue
    seen[u] = 1
    order.push(u)
    for (const v of [...adj[u]].reverse()) stack.push(v)
  }
  return order // [1, 2, 4, 3]
}
```

- 방문 확인은 꺼낼 때 합니다. 같은 노드가 스택에 여러 번 들어갈 수 있기 때문입니다.
- 자식을 역순으로 넣어야 재귀와 같은 순서(앞 자식 먼저)로 방문합니다. 순서가 중요하지 않으면 정방향으로 넣어도 됩니다.
- 재귀의 "올라올 때 하는 일"(후위 처리, 자식 결과 합치기)이 필요하면 노드마다 다음에 볼 자식 위치를 따로 기억하고, 자식을 모두 본 노드를 꺼낼 때 처리합니다.

```js
function dfsPost(start) {
  const seen = new Uint8Array(adj.length)
  const pos = new Int32Array(adj.length) // 다음에 볼 자식 위치
  const stack = [start]
  const post = []
  seen[start] = 1
  while (stack.length > 0) {
    const u = stack[stack.length - 1]
    if (pos[u] < adj[u].length) {
      const v = adj[u][pos[u]++]
      if (!seen[v]) { seen[v] = 1; stack.push(v) }
    } else post.push(stack.pop()) // 올라올 때 하던 일
  }
  return post // [4, 2, 3, 1]
}
```

- 스택 위 노드를 꺼내지 않고 들여다보다가, 자식을 다 본 뒤에야 꺼냅니다. 꺼내는 시점이 재귀 함수가 반환하는 시점입니다.
- DFS의 성질과 그래프 문제는 36편에서 다룹니다.

## 하노이 탑

하노이 탑(Tower of Hanoi)은 기둥 세 개 중 첫 기둥에 쌓인 원판 n개를, 한 번에 하나씩, 작은 원판 위에 큰 원판을 올리지 않으면서 셋째 기둥으로 옮기는 문제입니다. 재귀의 대표 예입니다.

옮기는 규칙은 세 단계입니다. n-1개를 보조 기둥으로 옮기고, 가장 큰 원판을 목적지로 옮기고, n-1개를 보조 기둥에서 목적지로 옮깁니다. 원판이 0개이면 아무것도 하지 않습니다.

```js
function hanoi(n, from, to, via, moves) {
  if (n === 0) return
  hanoi(n - 1, from, via, to, moves)
  moves.push(from + '->' + to)
  hanoi(n - 1, via, to, from, moves)
}
const moves = []
hanoi(3, 'A', 'C', 'B', moves)
console.log(moves.join(' '))
// A->C A->B C->B A->C B->A B->C A->C
```

- 이동 횟수를 `T(n)`이라 하면 `T(n) = 2T(n - 1) + 1`이고 `T(0) = 0`입니다. 풀면 `T(n) = 2의 n제곱 − 1`이며, 이것이 최소 이동 횟수입니다. 원판 3개는 7번입니다.
- 재귀 깊이는 n이고 호출 수는 약 2의 n제곱입니다. n이 20이면 이동이 1,048,575번이라 이동 목록을 모두 저장하면 메모리를 많이 씁니다. 횟수만 필요하면 `2 ** n - 1`로 계산합니다.
- 횟수가 `Number`의 정확한 정수 범위를 넘는 n이면 `2n ** BigInt(n) - 1n`으로 계산합니다(자세히는 02편).
- 인자의 역할(`from`, `to`, `via`)이 호출마다 바뀝니다. 두 번째 재귀 호출에서는 출발이 `via`가 됩니다.

**흔한 실수:** 두 재귀 호출에서 `to`와 `via`를 바꿔 쓰지 않는 것입니다. 첫 호출은 `via`로 옮기고 둘째 호출은 `via`에서 옮겨야 합니다.

## 꼬리 재귀와 반복문 변환

꼬리 호출(tail call)은 함수의 마지막 동작이 다른 함수 호출의 결과를 그대로 반환하는 호출입니다. 자기 자신을 이렇게 부르면 꼬리 재귀입니다. 호출 뒤에 할 일이 남으면 꼬리가 아닙니다.

```js
function sum(n) {
  if (n === 0) return 0
  return n + sum(n - 1)       // ❌ 호출 뒤에 더하기가 남음
}
function sumTail(n, acc) {
  if (n === 0) return acc
  return sumTail(n - 1, acc + n) // ✅ 꼬리 호출
}
```

- 꼬리 재귀는 돌아와서 할 일이 없으므로 호출 스택을 쌓지 않아도 됩니다. 이를 이용해 스택 프레임을 재사용하는 최적화를 꼬리 호출 최적화라고 합니다.
- ES2015 명세는 strict mode의 꼬리 호출에 이 동작을 요구했고, Safari의 WebKit이 이를 구현했습니다. Node.js(V8)에서는 `'use strict'`를 붙이고 `sumTail(1e6, 0)`을 실행해도 RangeError가 납니다(Node.js 24.15에서 직접 확인). 코딩테스트에서 꼬리 호출 최적화를 기대하면 안 됩니다.
- 그래서 꼬리 재귀는 반복문으로 직접 바꿉니다. 변환은 기계적입니다. 매개변수를 지역 변수로 두고, 재귀 호출을 매개변수 대입으로 바꾸고, 종료 조건에서 값을 반환합니다.

```js
function sumLoop(n) {
  let acc = 0
  while (n !== 0) {
    acc += n   // acc = acc + n
    n -= 1     // n = n - 1
  }
  return acc
}
console.log(sumLoop(1000000)) // 500000500000
```

- 유클리드 호제법의 `gcd`도 꼬리 재귀입니다.

```js
const gcd = (a, b) => (b === 0 ? a : gcd(b, a % b)) // 재귀
function gcdLoop(a, b) {
  while (b !== 0) [a, b] = [b, a % b]
  return a
}
console.log(gcdLoop(48, 18)) // 6
```

- 꼬리가 아닌 재귀(피보나치처럼 호출이 둘이거나, 호출 뒤에 계산이 남는 재귀)는 이렇게 바뀌지 않습니다. 명시적 스택을 쓰거나, 작은 입력부터 채우는 반복 DP로 바꿉니다(자세히는 40편).

## 핵심 정리

- 재귀는 종료 조건과 한 단계 줄인 재귀 호출로 이루어지며, 모든 입력이 종료 조건에 닿도록 입력이 줄어야 합니다.
- 호출마다 스택 프레임이 쌓이므로 공간 복잡도는 재귀 깊이이고, 재귀 호출 앞의 코드는 내려갈 때, 뒤의 코드는 올라올 때 실행됩니다.
- 상태는 매개변수로 넘기고, 공유 배열을 바꿨으면 되돌리며, 결과로 저장할 때는 복사합니다. 반환값으로 하위 결과를 합치거나 참 거짓으로 일찍 끝냅니다.
- 재귀 트리의 노드 수가 호출 횟수입니다. 같은 입력의 중복 호출은 지수 비용을 만들고 메모로 줄입니다.
- 호출 스택 한계는 고정값이 아니며(Node.js 24.15 기본 설정에서 수천에서 만 단위), 깊은 입력에는 반복문이나 명시적 스택을 씁니다. Node.js는 꼬리 호출 최적화를 하지 않습니다.
- 재귀 DFS는 배열 스택으로 바꾸고, 하노이 탑은 `2의 n제곱 − 1`번 이동합니다.
