## 부모 찾기

부모 찾기는 루트가 정해진 무방향 트리(간선 목록)에서 루트가 아닌 모든 정점의 부모를 구하는 문제입니다. 간선 `a b`가 부모와 자식 중 누구인지 입력에 없으므로 루트에서 순회하며 정합니다. 어느 정점을 처음 방문하는 간선이 그 정점의 부모 간선입니다.

```js
function rootTree(adj, root) {
  const parent = new Array(adj.length).fill(0)
  const order = [], stack = [root]
  parent[root] = -1
  while (stack.length) {
    const v = stack.pop()
    order.push(v)
    for (const u of adj[v]) {
      if (u !== parent[v]) { parent[u] = v; stack.push(u) }
    }
  }
  return { order, parent }
}
```

- 43편의 `dfsOrder`와 같은 함수입니다. 이후 절은 이 함수의 `order`(전위 방문 순서)와 `parent`를 씁니다.
- 트리에는 사이클이 없어서 부모만 건너뛰면 모든 정점을 한 번씩 방문합니다. 반복문 DFS라서 깊이가 큰 트리에서도 호출 스택이 넘치지 않습니다(자세히는 86편).
- `parent[루트]`는 -1로 둡니다. 정점 번호는 1부터라서 0은 쓰이지 않는 칸입니다.
- BFS로 써도 같은 부모 배열이 나옵니다. 트리에서 루트까지 경로는 하나뿐이기 때문입니다.

solution 함수와 표준 입력 형식은 이렇게 감쌉니다(입출력은 08편).

```js
function solution(n, edges) {          // 프로그래머스식
  const adj = Array.from({ length: n + 1 }, () => [])
  for (const [a, b] of edges) {
    adj[a].push(b); adj[b].push(a)
  }
  return rootTree(adj, 1).parent.slice(2)   // 2번~n번의 부모
}
```

```js
// 표준 입력식: 첫 줄 N, 다음 N-1줄에 a b
const fs = require('fs')
const lines = fs.readFileSync(0, 'utf8').trim().split('\n')
const n = Number(lines[0])
const edges = lines.slice(1)
  .map((l) => l.split(' ').map(Number))
console.log(solution(n, edges).join('\n'))
```

예제 트리라면 2번부터 순서대로 `1 1 2 2 3 5 5`가 나옵니다.

**흔한 실수:** 입력된 `a b`를 부모 `a`, 자식 `b`로 가정하는 것입니다. 입력 순서와 방향은 문제가 보장할 때만 믿습니다. 또 `parent`를 `slice(1)`로 잘라 루트의 -1까지 출력하는 실수가 자주 나옵니다.

## Rooting

Rooting은 무방향 트리에서 루트를 하나 골라 모든 간선에 부모 → 자식 방향을 주는 일입니다. 앞 절의 `rootTree`가 하는 일이 그것입니다. 방향이 생기면 `children` 리스트를 만들 수 있고 이후 계산이 단순해집니다.

```js
const { order, parent } = rootTree(adj, root)
const children = Array.from({ length: n + 1 }, () => [])
for (const v of order) {
  if (parent[v] > 0) children[parent[v]].push(v)
}
// 예제: children[5] = [8, 7], children[1] = [3, 2]
```

- `order`가 전위라서 부모가 항상 자식보다 앞에 있습니다. 이 성질이 다음 절들의 핵심입니다. `order`를 앞에서부터 읽으면 위에서 아래로, 뒤에서부터 읽으면 아래에서 위로 계산할 수 있습니다.
- `children`의 순서는 스택에서 꺼낸 순서라서 입력의 역순으로 쌓이는 정점이 있습니다. 자식 순서가 답에 영향을 주는 문제(예: 사전순 출력)에서는 정렬합니다.
- 루트는 문제가 정하지만, 풀이 편의로 임의의 루트(보통 1)를 정해도 되는 문제가 많습니다. 거리·지름처럼 루트와 무관한 값만 구한다면 그렇습니다.

루트를 바꾸고 싶을 때(rerooting) 전체를 다시 순회하지 않아도 부모 배열을 고칠 수 있습니다. 새 루트 `r`이 정해지면 바뀌는 것은 옛 루트에서 `r`까지의 경로 위의 간선 방향뿐입니다. 이 경로의 부모 관계만 뒤집습니다.

```js
function reroot(parent, newRoot) {
  let prev = -1, v = newRoot
  while (v !== -1) {
    const next = parent[v]    // 옛 부모
    parent[v] = prev          // 경로를 따라 방향을 뒤집는다
    prev = v; v = next
  }
}
```

- 예제에서 `reroot(parent, 5)`를 부르면 5의 부모는 -1, 2의 부모는 5, 1의 부모는 2가 됩니다. 나머지 정점의 부모는 그대로입니다. 시간은 경로 길이만큼입니다.
- 루트를 바꾸면 깊이·높이·서브트리 크기는 다시 계산해야 합니다. 모든 정점을 루트로 삼아 본 값을 한 번에 구하는 기법을 리루팅 DP라 부릅니다(자세히는 67편).

**흔한 실수:** 루트를 정한 뒤 `adj`에서 부모를 지우지 않고 `adj[v]`를 곧바로 자식 목록으로 쓰는 것입니다. `adj[v]`에는 부모가 섞여 있습니다. `children`을 따로 만들거나 순회 때 부모를 건너뜁니다.

## Subtree Size

서브트리 크기는 정점 v를 루트로 하는 서브트리에 속한 정점의 수입니다(서브트리 정의는 43편). 자식들의 크기 합에 자기 자신 1을 더합니다.

$$
size(v) = 1 + \sum_{c \in \text{children}(v)} size(c)
$$

`order`를 뒤에서부터 읽으면 자식이 항상 부모보다 먼저 나오므로, 각 정점의 크기가 확정된 순간 부모에게 더하면 됩니다.

```js
function subtreeSizes(order, parent) {
  const size = new Array(parent.length).fill(1)
  for (let i = order.length - 1; i > 0; i--) {
    const v = order[i]
    size[parent[v]] += size[v]
  }
  return size
}
```

예제의 크기는 정점 1부터 `8, 5, 2, 1, 3, 1, 1, 1`입니다. 5의 크기는 7과 8의 1씩에 자기 1을 더한 3이고, 2는 4(1)와 5(3)에 자기 1을 더한 5입니다.

- 시간과 공간은 O(N)입니다.
- `i > 0`으로 루트(`order[0]`)를 건너뜁니다. 루트의 부모 -1에 더하면 안 됩니다.
- 크기를 한 번 구해 두면 "정점 v의 서브트리에 정점이 몇 개인가"가 O(1)이고, 간선 `(p, v)`를 끊었을 때 갈라지는 두 컴포넌트의 크기는 `size[v]`와 `N - size[v]`입니다.
- 서브트리가 `order`에서 연속한 구간이 되는 전위 순서의 성질로 서브트리 질의를 구간 질의로 바꾸는 기법이 있습니다(자세히는 67편).

**흔한 실수:** 크기를 전위(앞에서부터) 순서로 더하는 것입니다. 부모를 먼저 만나서 자식 값이 아직 1인 채 쓰입니다. 반드시 뒤에서부터 읽거나 재귀의 후위에서 더합니다.

## Leaf Count

리프 수는 트리 전체의 리프 개수와, 각 정점의 서브트리 안 리프 개수 두 가지로 묻습니다. 전체 개수는 자식이 없는 정점을 세면 되고, 서브트리별 개수는 서브트리 크기와 같은 방식으로 구합니다.

$$
leaf(v) = \begin{cases} 1 & v \text{가 리프} \\ \sum_{c \in \text{children}(v)} leaf(c) & \text{그 외} \end{cases}
$$

```js
function leafCounts(order, parent) {
  const cnt = new Array(parent.length).fill(0)
  for (let i = order.length - 1; i >= 0; i--) {
    const v = order[i]
    if (cnt[v] === 0) cnt[v] = 1      // 자식이 없으면 리프
    if (parent[v] > 0) cnt[parent[v]] += cnt[v]
  }
  return cnt
}
```

예제는 정점 1부터 `4, 3, 1, 1, 2, 1, 1, 1`입니다. 5의 서브트리에는 리프 7과 8이 있어 2이고, 루트의 값 4가 트리 전체의 리프 수입니다.

- 정점 `v`를 처리하는 시점에는 모든 자식이 이미 더해졌습니다. `cnt[v]`가 0이면 자식이 없는 것이고 리프입니다. 자식이 있으면 합이 1 이상이기 때문입니다.
- 정점이 하나뿐인 트리에서는 루트가 리프이고 답은 1입니다. `parent[v] > 0` 조건은 루트의 부모 -1에 더하지 않으려는 것입니다.
- 서브트리 크기와 리프 수를 한 번의 역순 읽기에서 동시에 구할 수 있습니다. 같은 `order`를 쓰기 때문입니다.
- 단순히 전체 리프 수만 필요하면 루트 기준의 `children` 개수가 0인 정점을 세거나, 무방향 인접 리스트에서 차수가 1인 정점을 셉니다(루트의 이웃이 하나뿐일 때는 루트를 제외하고 세는지 확인합니다).

**흔한 실수:** 리프 판정(`cnt[v] === 0`)을 자식이 더해지기 전에 하는 것입니다. 전위 순서로 읽으면 모든 정점의 값이 아직 0이라서 전부 리프로 셉니다. 역순으로 읽어야 이 판정이 맞습니다.

## Weighted Tree

가중치 트리(weighted tree)는 간선마다 가중치(길이, 비용)가 붙은 트리입니다. 경로의 길이는 경로에 놓인 간선 가중치의 합이고, 가중치가 없는 트리는 모든 가중치가 1인 트리로 볼 수 있습니다.

- 간선 `a b w`를 인접 리스트에 `[이웃, 가중치]` 쌍으로 저장합니다.

```js
const adj = Array.from({ length: n + 1 }, () => [])
for (const [a, b, w] of edges) {
  adj[a].push([b, w])
  adj[b].push([a, w])
}
```

- 예제 가중치는 `1-2: 3`, `1-3: 2`, `2-4: 4`, `2-5: 1`, `3-6: 5`, `5-7: 2`, `5-8: 6`으로 둡니다.
- 가중치가 붙으면 깊이는 간선 수 대신 루트까지의 가중치 합(거리)이 됩니다. 아래 `dist`가 그것이고, 간선 수로 센 깊이가 필요하면 가중치를 1로 둔 순회를 따로 돌립니다.
- 값의 범위를 먼저 봅니다. 가중치가 최대 W이면 한 경로의 길이는 최대 (N - 1) × W입니다. 이 값이 `Number.MAX_SAFE_INTEGER`를 넘지 않는지 확인합니다(자세히는 02편). 넘으면 `BigInt`를 씁니다.
- 가중치가 음수일 수 있는지 확인합니다. 음수가 있으면 아래의 지름 두 번 탐색 방법이 성립하지 않습니다.

한 정점 `src`에서 모든 정점까지의 거리와 부모를 구하는 함수입니다. 이 문서의 나머지 절이 이 함수를 씁니다.

```js
function distFrom(adj, src) {
  const dist = new Array(adj.length).fill(-1)
  const parent = new Array(adj.length).fill(0)
  dist[src] = 0; parent[src] = -1
  const stack = [src]
  while (stack.length) {
    const v = stack.pop()
    for (const [u, w] of adj[v]) {
      if (u === parent[v]) continue
      dist[u] = dist[v] + w; parent[u] = v; stack.push(u)
    }
  }
  return { dist, parent }
}
```

루트 1에서의 거리는 정점 1부터 `0, 3, 2, 7, 4, 7, 6, 10`입니다. 8까지는 `1-2-5-8`이라 3 + 1 + 6 = 10입니다.

- 트리에는 경로가 하나뿐이라서 다익스트라가 필요 없습니다. 순회 한 번에 O(N)으로 모든 거리가 나옵니다(일반 그래프의 최단거리는 48편).
- `dist`를 `-1`로 초기화하는 것은 방문 표시를 겸합니다. 이 코드는 가중치가 0 이상일 때 맞습니다.

**흔한 실수:** 간선 목록의 가중치를 인접 리스트에 넣을 때 한쪽에만 넣는 것입니다. 무방향이라서 `adj[a]`와 `adj[b]` 양쪽에 모두 넣어야 합니다.

## Tree 거리

트리 거리는 두 정점 사이 경로의 길이(간선 수 또는 가중치 합)입니다. 경로가 하나뿐이라서 그 경로가 곧 최단 경로입니다.

한 쌍의 거리나 한 출발점에서의 거리들만 필요하면 출발점에서 순회 한 번이면 끝납니다. 앞의 `distFrom(adj, u).dist[v]`가 u와 v의 거리입니다.

질의가 많으면 루트를 하나 정해 두고 최소 공통 조상(LCA, Lowest Common Ancestor)을 이용합니다. 두 정점 u, v의 경로는 LCA를 지나가므로 거리는 다음과 같습니다.

$$
dist(u, v) = d(u) + d(v) - 2 \cdot d(\text{lca}(u, v))
$$

- `d(x)`는 루트에서 x까지의 거리(간선 수 또는 가중치 합)입니다.
- LCA의 위쪽 구간 `d(lca)`는 두 경로가 모두 지나므로 두 번 더해진 것을 빼는 식입니다.

LCA는 깊이가 더 깊은 쪽을 한 칸씩 올려 두 정점이 만나는 곳을 찾으면 구해집니다.

```js
function lca(u, v, parent, depth) {
  while (u !== v) {
    if (depth[u] < depth[v]) [u, v] = [v, u]   // 더 깊은 쪽
    u = parent[u]                               // 한 칸 올린다
  }
  return u
}
```

예제에서 `lca(7, 6)`은 1입니다. 가중치 트리라면 `dist[7] + dist[6] - 2 * dist[1] = 6 + 7 - 0 = 13`이고, 간선 수로는 3 + 2 = 5입니다. `lca(4, 8)`은 2입니다.

- `depth`는 간선 수 깊이(루트 0)여야 올리는 순서가 맞고, 가중치 거리와는 별도로 구합니다.
- 이 방법은 질의 하나에 O(깊이)입니다. 일직선에 가까운 트리에서 질의가 많으면 느려서, 질의가 많은 문제는 이진 승계(binary lifting)로 O(log N)에 풉니다(자세히는 66편).

**흔한 실수:** 가중치 트리에서 `depth`(간선 수)로 거리를 계산하는 것입니다. 거리에는 가중치 합 `dist`를 쓰고, LCA를 찾는 데에만 간선 수 깊이를 씁니다.

## Tree Diameter

트리의 지름(diameter)은 트리에서 가장 먼 두 정점 사이의 거리입니다. 그 두 정점이 지름의 끝점입니다. 지름은 루트와 무관한 값입니다.

### 순회 두 번으로 구하기

가중치가 모두 0 이상일 때 다음 두 단계로 구합니다.

1. 아무 정점(예: 1)에서 가장 먼 정점 `a`를 찾는다.
2. `a`에서 가장 먼 정점 `b`를 찾는다. `a`와 `b` 사이의 거리가 지름이다.

```js
function farthest(dist) {
  let best = 1
  for (let v = 2; v < dist.length; v++) {
    if (dist[v] > dist[best]) best = v
  }
  return best
}
function diameter(adj) {
  const a = farthest(distFrom(adj, 1).dist)
  const { dist, parent } = distFrom(adj, a)
  const b = farthest(dist)
  return { length: dist[b], ends: [a, b], parent }
}
```

- 예제(가중치 있음)는 1에서 가장 먼 정점 8(거리 10)을 찾고, 8에서 가장 먼 정점 6(거리 17)을 얻어 지름 17, 끝점 `[8, 6]`입니다. 경로는 `8-5-2-1-3-6`이고 6 + 1 + 3 + 2 + 5 = 17입니다.
- 가중치를 모두 1로 보면 지름은 5(간선 수)이고 끝점은 7과 6입니다.
- 시간은 O(N)입니다. 순회가 두 번이고 각각 O(N)입니다.
- 이 방법은 임의의 정점에서 가장 먼 정점이 어떤 지름의 끝점이 된다는 성질에 기댑니다. 가중치가 음수이면 이 성질이 깨집니다.
- 가장 먼 정점이 여러 개이면 아무 쪽이나 골라도 지름의 값은 같습니다. 끝점과 경로는 달라질 수 있습니다.
- `farthest`에서 `Math.max(...dist)`를 쓰지 않은 이유는 큰 배열의 스프레드가 인수 개수 한계에 걸리기 때문입니다(자세히는 86편).

### 트리 DP로 구하기

모든 정점 v에서 "v를 가장 높은 지점으로 하는 경로 중 최장"을 보는 방법입니다. 그 경로는 v 아래의 가장 긴 하강 경로 두 개를 이어 만듭니다. 간선 수 지름이면 다음과 같습니다.

```js
function diameterDP(order, parent) {
  const down = new Array(parent.length).fill(0)
  let best = 0
  for (let i = order.length - 1; i > 0; i--) {
    const v = order[i], p = parent[v]
    best = Math.max(best, down[p] + down[v] + 1)
    down[p] = Math.max(down[p], down[v] + 1)
  }
  return best
}
```

- `down[x]`는 x에서 아래로 내려가는 가장 긴 경로의 간선 수입니다.
- `p`의 자식 `v`를 처리할 때 `down[p]`에는 앞서 처리한 자식들의 최대가 들어 있습니다. 새 자식과 이어 `down[p] + down[v] + 1`이 `p`를 꼭대기로 하는 경로 후보입니다.
- 가중치가 있으면 `+ 1` 대신 부모 간선의 가중치를 더합니다.
- 지름 경로 자체를 복원하기에는 두 번 순회하는 방법이 쉽습니다. DP는 지름의 값만 구할 때, 또는 지름을 만든 정점에서 다른 계산을 이어 갈 때 쓰입니다(자세히는 67편).

두 방법을 같은 입력에서 비교하면 이렇습니다.

| 항목 | 순회 두 번 | 트리 DP |
|------|------------|---------|
| 시간 | O(N) | O(N) |
| 경로 복원 | 쉬움(`parent`) | 별도 기록 필요 |
| 가중치 | 0 이상일 때 | 0 이상일 때 |
| 코드 | 순회 함수 재사용 | `order` 역순 읽기 |

- 두 방법 모두 가중치가 0 이상일 때 성립합니다. DP는 `down`의 초기값 0이 빈 경로를 뜻해서 음수 가중치에서는 맞지 않습니다.

**흔한 실수:** 1번 정점에서 가장 먼 정점을 지름의 끝점이라고 단정해 한 번만 순회하는 것입니다. 한 번 순회한 결과는 지름의 한쪽 끝점일 뿐입니다. 그 끝점에서 한 번 더 순회해야 반대쪽 끝점과 지름이 나옵니다.

## Tree 중심 개념

트리의 중심(center)은 가장 먼 정점까지의 거리(이심률, eccentricity)가 최소인 정점입니다. 트리의 중심은 정점 하나이거나 서로 인접한 정점 둘입니다.

- 지름 경로의 가운데가 중심입니다. 지름 경로의 정점이 홀수 개이면 가운데 정점 하나가, 짝수 개이면 가운데 두 정점이 중심입니다. 지름이 간선 수 D이면 중심의 이심률은 D를 2로 나눈 값의 올림입니다.
- 예제(가중치 없음)의 지름 경로는 `7-5-2-1-3-6`으로 정점이 6개라서 가운데 두 정점 2와 1이 중심이고, 이심률은 3입니다.
- 중심을 루트로 삼으면 트리의 높이가 최소가 됩니다. 높이가 최소인 루트를 찾는 문제가 이 성질에 해당합니다.
- 가중치 트리의 중심은 가운데 점이 간선 위에 놓일 수 있어서, 정점으로 한정하는지 정의를 문제에서 확인합니다. 아래 두 방법은 가중치 없는 트리를 전제로 합니다.

지름 경로를 복원해 가운데를 고르는 방법입니다. `parent`를 따라 끝점에서 시작점으로 거슬러 경로를 만듭니다(다음 절).

```js
// diameter가 돌려준 parent로 끝점 b에서 a까지의 경로를 만든다
const path = pathTo(parent, b)  // [7, 5, 2, 1, 3, 6] 형태
const L = path.length
const centers = L % 2 === 1
  ? [path[(L - 1) / 2]]
  : [path[L / 2 - 1], path[L / 2]]
// 예제: [2, 1]
```

리프를 바깥에서부터 한 겹씩 벗겨 내는 방법도 있습니다. 정점이 1개나 2개 남을 때까지 현재 리프를 모두 제거합니다. 남은 것이 중심입니다.

```js
function centersByPeeling(adj) {      // 간선에 가중치 없음
  const deg = adj.map((l) => l.length)
  let left = adj.length - 1, leaves = []
  for (let v = 1; v < adj.length; v++)
    if (deg[v] <= 1) leaves.push(v)
  while (left > 2) {
    left -= leaves.length
    const next = []
    for (const v of leaves) for (const u of adj[v])
      if (--deg[u] === 1) next.push(u)
    leaves = next
  }
  return leaves
}
```

- 예제에서 첫 겹은 리프 4, 6, 7, 8이고, 다음 겹은 2의 이웃 5와 3이 리프가 되어 제거됩니다. 정점 1과 2가 남아 중심은 `[1, 2]`입니다.
- 매 겹마다 현재 리프를 한꺼번에 제거합니다. 하나씩 제거하면 중심이 아닌 정점이 남을 수 있습니다.
- 정점이 하나뿐이면 `left`가 1이라서 루프에 들어가지 않고 그 정점이 중심입니다.
- 두 방법 모두 O(N)입니다. 무작위 트리 수천 개에서 두 방법의 결과가 정의대로 계산한 중심과 같음을 직접 확인했습니다.

**흔한 실수:** 중심을 항상 하나라고 가정하는 것입니다. 지름 경로의 정점 수가 짝수이면 중심이 둘입니다. 하나만 필요한 문제라면 둘 중 어느 쪽을 고르는지 문제 조건을 확인합니다.

## Tree 경로 복원

경로 복원은 트리에서 두 정점 사이의 실제 경로(정점 순서)를 구하는 일입니다. 거리만이 아니라 지나는 정점이 필요할 때 씁니다. 순회가 만든 `parent`를 도착 정점에서 출발 정점까지 거슬러 올라가면 됩니다(일반 그래프의 경로 복원은 36편, 38편).

방법은 출발점 `s`를 루트로 순회해 `parent`를 만들고, 도착점 `t`에서 부모를 따라가는 것입니다.

```js
function pathTo(parent, v) {
  const path = []
  for (; v !== -1; v = parent[v]) path.push(v)
  return path.reverse()
}
const { parent } = distFrom(adj, s)
pathTo(parent, t)
// 예제 s = 8, t = 6: [8, 5, 2, 1, 3, 6]
```

- `parent[s]`는 -1이라서 반복이 `s`에서 멈춥니다. 거슬러 올라가면 도착점부터 나오므로 마지막에 `reverse`로 뒤집습니다.
- 시간은 순회 O(N)에 경로 길이를 더한 값입니다.
- 한 번 구한 `parent`로 같은 출발점의 여러 도착점 경로를 모두 복원할 수 있습니다.
- 경로의 정점 수는 최대 N이라서 `path`가 길어질 수 있습니다. 출력할 때는 한 줄로 합쳐 한 번에 냅니다(자세히는 08편).

루트가 정해져 있고 질의가 많으면 순회를 매번 돌리지 않고 LCA로 구합니다. u에서 LCA까지 올라가는 구간과 v에서 LCA까지 올라가는 구간을 이어 붙입니다(앞의 `lca` 함수).

```js
function pathBetween(u, v, parent, depth) {
  const top = lca(u, v, parent, depth)
  const left = [], right = []
  for (let x = u; x !== top; x = parent[x]) left.push(x)
  for (let x = v; x !== top; x = parent[x]) right.push(x)
  return [...left, top, ...right.reverse()]
}
// 예제 pathBetween(7, 6): [7, 5, 2, 1, 3, 6]
```

- 위쪽 구간(`u`에서 LCA)은 그대로, 아래쪽 구간(`v`에서 LCA)은 거꾸로 올라가므로 뒤집어 붙입니다.
- 이 방법은 O(경로 길이)입니다. 지름 경로를 복원할 때도 두 번째 순회의 `parent`를 `pathTo`로 따라가면 됩니다.

**흔한 실수:** 첫 번째 순회의 `parent`를 지름 경로 복원에 쓰는 것입니다. 지름의 끝점 `a`에서 시작한 두 번째 순회가 만든 `parent`여야 `a`와 `b`를 잇는 경로가 나옵니다.

## 핵심 정리

- 부모는 루트에서 순회하며 처음 방문하는 간선으로 정해지고, 입력 `a b`의 방향을 믿지 않습니다.
- `order`를 앞에서 읽으면 위에서 아래로(깊이), 뒤에서 읽으면 아래에서 위로(서브트리 크기, 리프 수) 재귀 없이 계산합니다.
- 가중치 트리는 거리를 가중치 합으로 구하며, 간선 수 깊이와 구분하고 합이 안전 범위를 넘는지 확인합니다.
- 두 정점의 거리는 `d(u) + d(v) - 2 d(lca)`이고, 질의가 적으면 한 점에서의 순회로 구합니다.
- 지름은 임의의 정점에서 가장 먼 정점 `a`, `a`에서 가장 먼 정점 `b` 순으로 두 번 순회해 구하며, 가중치가 0 이상일 때 성립합니다.
- 중심은 지름 경로의 가운데 한두 정점이고, 경로는 순회가 만든 `parent`를 도착점에서 거슬러 올라가 복원합니다.
