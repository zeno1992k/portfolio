## Binary Tree

이진 트리(binary tree)는 모든 노드의 자식이 최대 두 개이고, 두 자식을 왼쪽 자식과 오른쪽 자식으로 구분하는 트리입니다. 자식이 하나뿐일 때도 왼쪽인지 오른쪽인지가 구별되므로 같은 값이라도 모양이 다르면 다른 트리입니다(일반 트리의 용어는 43편).

JavaScript에서는 값과 두 자식 참조를 가진 객체로 노드를 만듭니다. 이 문서의 모든 코드는 아래 노드를 씁니다.

```js
const n = (v, l = null, r = null) => ({ v, l, r })
//        1
//       / \
//      2   3
//     / \   \
//    4   5   6
const T = n(1, n(2, n(4), n(5)), n(3, null, n(6)))
```

코딩테스트 입력은 객체 대신 번호로 주어지는 경우가 많습니다. "노드 i의 왼쪽·오른쪽 자식 번호"를 받으면 `left[i]`, `right[i]` 배열에 담고, 자식이 없으면 0이나 -1 같은 표식을 둡니다.

모양에 따른 이름은 다음과 같습니다.

| 이름 | 조건 |
|------|------|
| 정 이진 트리(full) | 모든 노드의 자식이 0개 또는 2개 |
| 포화 이진 트리(perfect) | 모든 내부 노드의 자식이 2개이고 모든 잎의 깊이가 같다 |
| 완전 이진 트리(complete) | 마지막 층을 뺀 모든 층이 꽉 차 있고, 마지막 층은 왼쪽부터 채워졌다 |
| 편향 트리(skewed) | 모든 노드의 자식이 한쪽에만 있어 연결 리스트 모양이다 |

- 높이가 h(간선 수 기준)인 포화 이진 트리의 노드 수는 2^(h+1) - 1개이고 잎은 2^h개입니다.
- 노드가 N개인 이진 트리의 높이는 최소 floor(log2 N), 최대 N - 1입니다. 최소는 완전 이진 트리, 최대는 편향 트리일 때입니다.
- 노드 N개의 이진 트리에서 간선은 N - 1개입니다.

## 전위 순회

전위 순회(preorder)는 노드 자신, 왼쪽 서브트리, 오른쪽 서브트리 순서로 방문합니다. 부모가 자식보다 먼저 나옵니다.

```js
function pre(t, out = []) {
  if (!t) return out
  out.push(t.v)       // 방문
  pre(t.l, out)
  pre(t.r, out)
  return out
}
pre(T) // [1, 2, 4, 5, 3, 6]
```

- 트리를 복사하거나 직렬화할 때, 루트부터 정보를 아래로 내려보낼 때 씁니다.
- 반복문으로 쓰려면 스택에 오른쪽 자식을 먼저 넣습니다. 스택은 나중에 넣은 것이 먼저 나오기 때문입니다.

```js
function preIter(root) {
  const out = [], st = root ? [root] : []
  while (st.length) {
    const t = st.pop()
    out.push(t.v)
    if (t.r) st.push(t.r)   // 오른쪽을 먼저 넣어야
    if (t.l) st.push(t.l)   // 왼쪽이 먼저 나온다
  }
  return out
}
```

재귀 깊이가 트리 높이만큼 쌓이므로 편향 트리에서 JavaScript 호출 스택이 넘칠 수 있습니다. 노드가 수만 개 이상이면 반복문 버전을 씁니다(자세히는 22편).

## 중위 순회

중위 순회(inorder)는 왼쪽 서브트리, 노드 자신, 오른쪽 서브트리 순서입니다. 왼쪽에서 오른쪽으로 읽는 순서와 같습니다.

```js
function ino(t, out = []) {
  if (!t) return out
  ino(t.l, out)
  out.push(t.v)       // 왼쪽을 다 본 뒤 방문
  ino(t.r, out)
  return out
}
ino(T) // [4, 2, 5, 1, 3, 6]
```

반복문 버전은 왼쪽 끝까지 내려가며 스택에 쌓고, 꺼내 방문한 뒤 오른쪽으로 갑니다.

```js
function inIter(root) {
  const out = [], st = []
  let cur = root
  while (cur || st.length) {
    while (cur) { st.push(cur); cur = cur.l }
    cur = st.pop()
    out.push(cur.v)
    cur = cur.r
  }
  return out
}
```

이진 탐색 트리를 중위 순회하면 값이 오름차순으로 나옵니다(아래 BST 절).

## 후위 순회

후위 순회(postorder)는 왼쪽 서브트리, 오른쪽 서브트리, 노드 자신 순서입니다. 자식을 모두 끝낸 뒤에 부모를 처리합니다.

```js
function post(t, out = []) {
  if (!t) return out
  post(t.l, out)
  post(t.r, out)
  out.push(t.v)       // 자식을 다 본 뒤 방문
  return out
}
post(T) // [4, 5, 2, 6, 3, 1]
```

- 자식의 결과로 부모의 값을 계산할 때 씁니다. 서브트리 크기·높이 구하기, 트리 DP, 수식 트리 계산, 트리 삭제가 해당합니다.
- 반복문으로는 "루트, 오른쪽, 왼쪽" 순서로 방문한 결과를 뒤집으면 후위 순서가 됩니다.

```js
function postIter(root) {
  const out = [], st = root ? [root] : []
  while (st.length) {
    const t = st.pop()
    out.push(t.v)
    if (t.l) st.push(t.l)   // 전위와 반대로 왼쪽을 먼저 넣는다
    if (t.r) st.push(t.r)
  }
  return out.reverse()
}
```

세 순회는 모두 노드마다 한 번씩 방문하므로 O(N), 재귀 깊이(보조 공간)는 O(높이)입니다. 세 순회의 차이는 노드를 방문하는 시점뿐입니다.

| 순회 | 방문 시점 | 예의 결과 |
|------|-----------|-----------|
| 전위 | 자식보다 먼저 | 1 2 4 5 3 6 |
| 중위 | 왼쪽 서브트리 뒤, 오른쪽 서브트리 앞 | 4 2 5 1 3 6 |
| 후위 | 자식보다 나중 | 4 5 2 6 3 1 |

**흔한 실수:** 방문 코드(`out.push`)의 위치를 잘못 두는 것입니다. 재귀 호출 세 줄의 순서는 그대로이고, 방문 줄이 앞·가운데·뒤 중 어디에 있는지가 전위·중위·후위를 정합니다.

## Level Order

레벨 순서 순회(level order)는 깊이가 같은 노드를 왼쪽에서 오른쪽으로 읽고, 얕은 층부터 깊은 층으로 내려갑니다. 큐를 쓰는 BFS입니다(자세히는 38편).

```js
function levels(root) {
  const res = []
  let q = root ? [root] : []
  while (q.length) {
    res.push(q.map((t) => t.v))     // 현재 층의 값
    const next = []
    for (const t of q) {
      if (t.l) next.push(t.l)
      if (t.r) next.push(t.r)
    }
    q = next
  }
  return res
}
levels(T) // [[1], [2, 3], [4, 5, 6]]
```

- 층마다 배열을 새로 만들어 넘기므로 `shift`를 쓰지 않아 O(N)입니다. 층을 구분할 필요가 없으면 head 인덱스 큐로 한 줄로 이어 읽어도 됩니다(자세히는 20편).
- 층별 값이 필요한 문제에 씁니다. 너비 구하기, 각 층의 최댓값, 오른쪽에서 본 모습, 지그재그 순회(짝수 층만 뒤집기)가 대표입니다.
- 한 층이 가진 노드 수는 최대 2^(깊이)개이므로 큐가 가장 넓은 층만큼 메모리를 씁니다.

## BST 개념

이진 탐색 트리(binary search tree, BST)는 모든 노드에서 왼쪽 서브트리의 값이 노드보다 작고 오른쪽 서브트리의 값이 노드보다 큰 이진 트리입니다. 비교 한 번으로 한쪽 서브트리를 통째로 버리는 이분 탐색(28편)을 트리 모양으로 만든 것입니다.

```js
//        5
//       / \
//      3   8
//     / \ / \
//    1  4 7  9
```

- 중위 순회하면 값이 오름차순으로 나옵니다. 위 트리는 `1 3 4 5 7 8 9`입니다. 이 성질로 BST가 정렬된 집합을 표현합니다.
- 서브트리 전체가 조건을 만족해야 합니다. 노드를 자식 하나와만 비교해서는 BST인지 알 수 없습니다.
- 같은 값(중복)을 허용할지는 문제가 정합니다. 이 문서의 구현은 중복을 무시합니다. 허용하려면 한쪽 서브트리(예: 오른쪽)에 같은 값을 넣는 규칙을 정하거나, 노드에 개수를 저장합니다.
- 복잡도는 트리 높이 h에 비례해서 탐색·삽입·삭제 모두 O(h)입니다. 값이 무작위로 들어오면 높이가 평균 O(log N)이지만, 정렬된 순서로 들어오면 편향되어 O(N)이 됩니다(아래 편향 트리 절).

BST인지 검사할 때는 각 노드가 지켜야 할 값의 범위를 내려보냅니다.

```js
function isBST(t, lo = -Infinity, hi = Infinity) {
  if (!t) return true
  if (t.v <= lo || t.v >= hi) return false
  return isBST(t.l, lo, t.v) && isBST(t.r, t.v, hi)
}
isBST(n(5, n(3, null, n(6)), n(8))) // false
```

- 마지막 예에서 6은 부모 3보다 크므로 오른쪽 자식으로는 맞지만, 조상 5보다 작아야 하는 왼쪽 서브트리에 있어서 BST가 아닙니다.
- 중위 순회 결과가 순증가(앞 값보다 항상 큼)인지 확인해도 같은 판정입니다.

**흔한 실수:** 노드를 직접 연결된 자식과만 비교하는 것입니다. 위 예가 그 검사를 통과합니다. 조상이 만든 범위까지 함께 확인해야 합니다.

## 삽입

BST에 값을 넣으려면 루트에서 시작해 값이 더 작으면 왼쪽, 크면 오른쪽으로 내려가다가 빈 자리에 새 노드를 답니다. 새 노드는 항상 잎이 됩니다.

```js
function insert(t, v) {
  if (!t) return n(v)             // 빈 자리에 새 노드
  if (v < t.v) t.l = insert(t.l, v)
  else if (v > t.v) t.r = insert(t.r, v)
  return t                        // 같은 값이면 무시
}
let root = null
for (const v of [5, 3, 8, 1, 4, 7, 9]) {
  root = insert(root, v)
}
```

- 함수가 서브트리의 루트를 반환하고 호출한 쪽이 `t.l = ...`로 다시 연결합니다. 루트가 비어 있던 경우도 같은 방식으로 처리됩니다.
- 입력 순서가 모양을 정합니다. 위 입력 순서는 값이 중간부터 섞여 있어 균형 잡힌 모양이 됩니다.
- 시간은 내려간 깊이, 곧 O(h)입니다.

## 탐색

값을 찾을 때도 같은 규칙으로 내려갑니다. 반복문으로 쓰면 재귀 깊이 걱정이 없습니다.

```js
function search(t, v) {
  while (t && t.v !== v) t = v < t.v ? t.l : t.r
  return t                        // 없으면 null
}
search(root, 4)?.v // 4
search(root, 6)    // null
```

- 한 번 비교할 때마다 한쪽 서브트리 전체를 버리므로 O(h)입니다.
- 최솟값은 왼쪽 끝 노드, 최댓값은 오른쪽 끝 노드입니다.
- 어떤 값 이상 중 가장 작은 값(lower bound)도 내려가는 도중에 기억해 두면 구할 수 있습니다. 찾는 값이 현재 노드 값 이하라서 왼쪽으로 갈 때마다 현재 노드를 후보로 기록하는 방식입니다.

## 삭제

삭제는 삭제할 노드의 자식 수에 따라 세 경우로 나뉩니다.

| 자식 수 | 처리 |
|---------|------|
| 0개(잎) | 그 노드를 떼어 낸다 |
| 1개 | 그 자식으로 노드를 대체한다 |
| 2개 | 중위 후계자(오른쪽 서브트리의 최솟값)의 값을 가져오고, 후계자 노드를 오른쪽 서브트리에서 삭제한다 |

```js
function remove(t, v) {
  if (!t) return null
  if (v < t.v) t.l = remove(t.l, v)
  else if (v > t.v) t.r = remove(t.r, v)
  else {
    if (!t.l) return t.r          // 0개 또는 오른쪽만
    if (!t.r) return t.l          // 왼쪽만
    let s = t.r
    while (s.l) s = s.l           // 중위 후계자
    t.v = s.v
    t.r = remove(t.r, s.v)
  }
  return t
}
```

앞의 트리(`5 3 8 1 4 7 9`를 삽입한 것)에서 차례로 지워 봅니다. 모양은 전위 순회로 적었습니다.

| 삭제 | 경우 | 전위 순회 결과 |
|------|------|----------------|
| (처음) | - | 5 3 1 4 8 7 9 |
| 1 | 잎, 그냥 제거 | 5 3 4 8 7 9 |
| 3 | 자식 1개(4), 4가 자리를 이어받음 | 5 4 8 7 9 |
| 5 | 자식 2개, 후계자 7의 값을 가져오고 7 노드 제거 | 7 4 8 9 |

- 중위 후계자는 중위 순서에서 바로 다음 값이므로, 그 값을 올려도 BST 조건이 깨지지 않습니다. 왼쪽 서브트리의 최댓값(중위 선행자)을 써도 됩니다.
- 후계자는 왼쪽 자식이 없으므로 두 번째 `remove`는 0개 또는 1개 경우에 걸려 바로 끝납니다.
- 시간은 O(h)입니다. 없는 값을 지우면 아무 일도 일어나지 않습니다.

**흔한 실수:**

- 자식이 둘인 경우에 후계자를 올리고 원래 후계자 노드를 지우지 않는 것입니다. 같은 값이 두 번 남습니다.
- 삭제 후 반환값을 부모에 다시 연결하지 않는 것입니다(`t.l = remove(...)`). 루트를 지울 때는 `root = remove(root, v)`로 받아야 합니다.

## 배열로 표현한 완전 이진 트리

완전 이진 트리는 노드를 위에서 아래, 왼쪽에서 오른쪽 순서(레벨 순서)로 번호를 매겨 배열 하나에 담을 수 있습니다. 빈 칸이 없어서 자식 참조가 필요 없고, 위치만으로 부모와 자식을 계산합니다.

| 관계 | 0부터 시작하는 인덱스 | 1부터 시작하는 인덱스 |
|------|-----------------------|-----------------------|
| 왼쪽 자식 | `2i + 1` | `2i` |
| 오른쪽 자식 | `2i + 2` | `2i + 1` |
| 부모 | `Math.floor((i - 1) / 2)` | `Math.floor(i / 2)` |

```js
const a = [1, 2, 3, 4, 5, 6]     // 0부터 시작
const left = (i) => 2 * i + 1
const right = (i) => 2 * i + 2
a[left(1)]  // 4 (2의 왼쪽 자식)
a[right(1)] // 5 (2의 오른쪽 자식)
a[left(2)]  // 6 (3의 왼쪽 자식)
```

- 인덱스가 배열 길이(N)보다 작은 동안만 노드가 있습니다. `left(i) >= N`이면 왼쪽 자식이 없습니다.
- 완전하지 않은 트리를 이 방식으로 담으면 빈 칸이 생겨서, 깊이가 d인 편향 트리는 배열 길이가 2^d 규모로 커집니다. 그래서 완전 이진 트리(힙, 세그먼트 트리)에만 씁니다(자세히는 46편, 62편).
- 노드 참조를 담지 않아 메모리가 적고 캐시에 유리합니다.

## 순회 결과로 트리 복원

노드 값이 모두 다르다면 두 순회 결과로 이진 트리를 하나로 복원할 수 있는 조합이 있습니다.

| 주어진 순회 | 복원 가능 여부 |
|-------------|----------------|
| 전위 + 중위 | 유일하게 복원된다 |
| 후위 + 중위 | 유일하게 복원된다 |
| 전위 + 후위 | 자식이 하나인 노드의 방향을 알 수 없어서 유일하지 않다 |
| 레벨 순서 + 중위 | 유일하게 복원된다 |
| 중위만 | 모양이 여러 가지다 |

전위+중위로 복원하는 원리는 이렇습니다.

1. 전위 순회의 첫 값이 루트다.
2. 중위 순회에서 루트의 위치를 찾으면 그 왼쪽이 왼쪽 서브트리, 오른쪽이 오른쪽 서브트리다.
3. 왼쪽 서브트리의 노드 수만큼 전위 순회에서 이어 읽으면 왼쪽, 나머지가 오른쪽이다.

```js
function build(pre, ino) {
  const pos = new Map(ino.map((v, i) => [v, i]))
  let p = 0                         // 전위에서 읽을 위치
  function go(lo, hi) {             // 중위 구간 [lo, hi)
    if (lo >= hi) return null
    const v = pre[p++]
    const m = pos.get(v)            // 중위에서 루트 위치
    const node = n(v)
    node.l = go(lo, m)
    node.r = go(m + 1, hi)
    return node
  }
  return go(0, ino.length)
}
// build([1,2,4,5,3,6], [4,2,5,1,3,6])은 앞의 T와 같은 트리
```

- 중위 위치를 `Map`에 미리 모으면 루트 찾기가 O(1)이라서 전체 O(N)입니다. 구간마다 `indexOf`로 찾으면 편향 트리에서 O(N²)입니다.
- 전위를 앞에서 읽는 대신 후위를 뒤에서부터 읽으면 후위+중위 복원이 됩니다. 후위의 뒤쪽이 루트, 그다음이 오른쪽 서브트리의 루트이므로 `node.r`을 먼저 만들고 `node.l`을 나중에 만듭니다.
- 전위+후위가 유일하지 않은 예: 전위 `[1, 2]`, 후위 `[2, 1]`이면 2가 1의 왼쪽 자식인지 오른쪽 자식인지 알 수 없습니다.
- BST는 중위 순서가 정렬된 값이라서 전위(또는 후위) 하나만 있어도 복원됩니다. 값을 순서대로 `insert`하거나 범위를 내려보내며 만듭니다.

시험이나 문제에서는 복원한 트리를 다시 순회하는 형태(전위+중위가 주어지고 후위를 출력)로 묻습니다. 트리를 실제로 만들지 않고도 같은 분할을 재귀로 따라가며 바로 후위를 출력할 수 있습니다.

**흔한 실수:** 값에 중복이 있는데 이 방법을 쓰는 것입니다. 중위에서 루트 위치가 하나로 정해지지 않아 복원이 유일하지 않습니다.

## 편향 트리와 균형 BST의 대안

BST의 높이는 값이 들어오는 순서에 달려 있습니다. 정렬된 값을 순서대로 넣으면 노드마다 오른쪽 자식만 생기는 편향 트리가 되어, 높이가 N이고 모든 연산이 O(N)입니다.

```js
let r = null
for (let i = 1; i <= 100000; i++) r = insert(r, i)
// RangeError: 재귀 깊이가 넘친다 (Node.js 24 실험)
// 넘치지 않더라도 삽입 N번의 합계가 O(N²)
```

- 입력이 이미 정렬돼 있거나 거의 정렬돼 있는 문제에서 BST를 그대로 쓰면 시간 초과나 호출 스택 초과가 납니다.
- JavaScript 표준 라이브러리에는 정렬된 상태를 유지하는 집합·맵(균형 BST)이 없습니다. `Map`과 `Set`은 삽입 순서를 유지할 뿐 값 순서로 정렬하지 않습니다(자세히는 09편).

균형 BST가 필요해 보일 때 코딩테스트에서 고르는 대안입니다.

| 필요한 연산 | 대안 |
|-------------|------|
| 정렬된 값에서 탐색만 한다 | 정렬 배열과 이분 탐색(28편) |
| 정렬 상태에서 삽입이 드물다 | 정렬 배열에 이분 탐색으로 위치를 찾아 `splice`로 삽입. 한 번에 O(N)이라 횟수가 많으면 느리다 |
| 최솟값·최댓값만 계속 꺼낸다 | 힙(46편, 47편) |
| 값의 범위가 작거나 오프라인으로 알 수 있다 | 좌표 압축(54편)과 Fenwick Tree(64편) 또는 Segment Tree(62편)로 개수·순위 질의 |
| 정말 BST 연산이 필요하다 | AVL·Treap 같은 균형 BST를 직접 구현 |

직접 구현은 코드가 길어서 대부분의 문제는 위 대안 중 하나로 풀립니다. 기본 BST를 쓰려면 입력이 무작위로 섞여 있다는 보장이 있어야 합니다.

## AVL·레드블랙·Treap 개요

삽입·삭제 뒤 트리를 회전(rotation, 부모와 자식의 위치를 바꾸되 BST 조건은 유지하는 국소 변환)으로 고쳐 높이를 O(log N)으로 유지하는 BST를 자가 균형 BST라고 합니다. 모든 연산이 O(log N)입니다.

| 트리 | 균형을 유지하는 규칙 | 높이 | 특징 |
|------|----------------------|------|------|
| AVL | 모든 노드에서 두 서브트리의 높이 차가 1 이하 | 최적의 약 1.44배 이하 | 가장 엄격하게 균형을 잡아 탐색이 빠르다. 삽입은 회전이 최대 1회(단일 또는 이중) |
| 레드블랙 | 노드에 색을 칠하고, 빨간 노드의 자식은 검은색이며, 모든 경로의 검은 노드 수가 같다 | 2 log2(N + 1) 이하 | 삽입·삭제의 회전 횟수가 적다. C++의 `std::map`, Java의 `TreeMap`이 쓴다 |
| Treap | 키는 BST 순서, 무작위 우선순위는 힙 순서로 동시에 만족 | 높은 확률로 O(log N) | 구현이 짧다. 분할(split)과 병합(merge)으로 구간 연산이 쉽다 |

- AVL의 불균형은 네 경우로 나뉩니다. 왼쪽 자식의 왼쪽(LL)과 오른쪽 자식의 오른쪽(RR)은 회전 한 번, 왼쪽 자식의 오른쪽(LR)과 오른쪽 자식의 왼쪽(RL)은 회전 두 번으로 고칩니다.
- 레드블랙 트리는 한 경로가 가장 짧은 경로의 두 배를 넘지 않는다는 성질로 높이를 제한합니다. AVL보다 느슨한 대신 갱신 비용이 낮습니다.
- Treap은 노드마다 난수 우선순위를 붙이고, 삽입하면 BST처럼 잎에 달았다가 우선순위가 부모보다 크면 회전해 올립니다. 키와 우선순위가 정해지면 모양이 유일해서, 입력 순서와 무관하게 무작위 BST와 같은 기대 높이를 가집니다.
- 코딩테스트에서 이 중 하나를 직접 구현해야 하는 경우는 드뭅니다. 정렬된 집합의 순위·구간 질의는 앞 절의 대안으로 풀고, 어느 균형 BST인지는 "연산이 O(log N)로 보장된다"는 사실만 알면 됩니다.

**흔한 실수:** 최악의 경우를 확인하지 않고 BST를 쓰는 것입니다. 정렬된 입력이 테스트에 하나만 있어도 편향 트리가 되어 시간 초과가 납니다.

## 핵심 정리

- 이진 트리는 노드마다 왼쪽·오른쪽 자식이 최대 하나씩이고, 전위·중위·후위 순회는 방문 시점만 다르며 레벨 순서 순회는 큐로 층별로 읽습니다.
- 재귀 순회는 깊이가 높이만큼 쌓이므로 노드가 많으면 스택을 쓰는 반복문으로 바꿉니다.
- BST는 왼쪽이 작고 오른쪽이 크며 중위 순회가 오름차순입니다. 검사할 때는 조상이 만든 값의 범위까지 확인합니다.
- 삽입은 잎에 달고, 삭제는 자식 0개·1개·2개(중위 후계자로 대체)로 나눠 처리하며 탐색·삽입·삭제는 모두 O(h)입니다.
- 완전 이진 트리는 배열에 담아 인덱스로 부모·자식을 계산하고, 값이 모두 다를 때 전위+중위나 후위+중위로 트리를 복원할 수 있습니다.
- 정렬된 입력은 BST를 편향시켜 O(N)이 되며, JavaScript에는 균형 BST가 없어서 정렬 배열·힙·좌표 압축 같은 대안을 쓰고, AVL·레드블랙·Treap은 O(log N)을 보장하는 자가 균형 BST입니다.
