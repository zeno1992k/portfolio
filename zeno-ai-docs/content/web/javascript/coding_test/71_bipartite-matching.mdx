## 이분 그래프 (Bipartite Graph)

이분 그래프(bipartite graph)는 정점을 두 집합으로 나눠 모든 간선이 서로 다른 집합의 정점을 잇는 그래프입니다. 같은 집합 안의 정점끼리는 간선이 없습니다. 길이가 홀수인 사이클이 없는 것과 같은 조건이고, DFS나 BFS로 정점에 두 색을 번갈아 칠해 판별합니다(자세히는 37편).

문제 문장에서 이분 그래프를 알아보는 단서는 두 종류의 대상 사이의 관계라는 구조입니다.

| 두 집단 | 간선의 뜻 |
|---------|-----------|
| 사람과 일 | 사람이 그 일을 할 수 있다 |
| 학생과 자리 | 학생이 그 자리를 원한다 |
| 행과 열 | 격자의 그 칸에 표시가 있다 |
| 격자의 `(r + c)`가 짝수인 칸과 홀수인 칸 | 상하좌우로 맞닿은 두 칸 |

- 격자에서 `(r + c) % 2`로 칸을 둘로 나누면 상하좌우 이웃은 항상 다른 쪽입니다. 도미노(두 칸짜리 조각)를 놓는 문제가 이 그래프의 매칭입니다(자세히는 17편).
- 매칭 코드에서는 왼쪽 정점 번호를 `0`부터 `n - 1`, 오른쪽을 `0`부터 `m - 1`로 따로 매기고 `adj[u]`에 왼쪽 u와 이어진 오른쪽 정점 번호를 담습니다. 오른쪽 정점은 번호가 겹쳐도 배열이 다르므로 구분됩니다.
- 이분 그래프라는 보장이 문제에 없으면 먼저 37편의 방법으로 판별합니다. 이분 그래프가 아니면 이 문서의 알고리즘은 쓰지 못합니다.

이 문서의 예제 그래프입니다. 왼쪽 4개, 오른쪽 4개이고 `adj[u]`는 u와 이어진 오른쪽 정점입니다.

```js
// 왼쪽 0: 오른쪽 0, 1   왼쪽 1: 오른쪽 0
// 왼쪽 2: 오른쪽 0      왼쪽 3: 오른쪽 2, 3
const n = 4, m = 4
const adj = [[0, 1], [0], [0], [2, 3]]
```

**흔한 실수:** 오른쪽에서 왼쪽으로 가는 간선까지 `adj`에 넣는 것입니다. 이 문서의 코드는 왼쪽에서 출발하는 간선만 담는다고 가정하고, 오른쪽에서 왼쪽으로는 매칭 간선(`matchR`)으로만 갑니다.

## 이분 매칭 (Bipartite Matching)

매칭(matching)은 어떤 정점도 두 번 이상 쓰이지 않게 고른 간선의 집합입니다. 이분 매칭은 이분 그래프에서 매칭을 구하는 문제이고, 보통은 개수가 최대인 매칭을 구합니다. 양쪽 정점이 모두 짝을 찾은 매칭은 완전 매칭(perfect matching)입니다.

예제에서 간선 `0-1`(왼쪽 0과 오른쪽 1), `1-0`, `3-2`를 고르면 크기 3인 매칭입니다. 왼쪽 2는 오른쪽 0밖에 갈 수 없는데 그 자리를 이미 왼쪽 1이 쓰고 있어서 짝이 없습니다.

핵심 도구는 증가 경로입니다.

- 교대 경로(alternating path)는 매칭에 속하지 않는 간선과 속하는 간선이 번갈아 나오는 경로입니다.
- 증가 경로(augmenting path)는 양 끝 정점이 아직 매칭되지 않은 교대 경로입니다. 시작은 짝이 없는 왼쪽 정점, 끝은 짝이 없는 오른쪽 정점입니다.
- 증가 경로의 간선을 매칭 여부를 뒤집으면(매칭 간선은 빼고 비매칭 간선은 넣으면) 매칭의 크기가 정확히 1 늘어납니다.
- 베르주의 보조정리(Berge's lemma): 매칭이 최대일 필요충분조건은 증가 경로가 없는 것입니다.

그래서 빈 매칭에서 시작해 증가 경로를 찾아 뒤집기를 더 못 찾을 때까지 반복하면 최대 매칭이 됩니다. 어떻게 증가 경로를 찾느냐에 따라 알고리즘이 갈립니다. DFS로 찾으면 Kuhn 알고리즘, 층을 나눠 한꺼번에 찾으면 Hopcroft-Karp입니다.

유량으로 풀 수도 있습니다. 가상 출발점 S에서 모든 왼쪽 정점으로, 왼쪽에서 오른쪽으로(이분 그래프의 간선), 모든 오른쪽 정점에서 가상 도착점 T로 용량 1짜리 간선을 놓으면 S에서 T로의 최대 유량이 최대 매칭의 크기입니다(자세히는 70편). 용량이 1이라서 한 정점에 한 번만 흐릅니다.

```js
function matchByFlow(n, m, adj) {   // 70편의 함수 사용
  const g = makeGraph(n + m + 2)
  const S = n + m, T = n + m + 1
  for (let u = 0; u < n; u++) {
    addEdge(g, S, u, 1)
    for (const v of adj[u]) addEdge(g, u, n + v, 1)
  }
  for (let v = 0; v < m; v++) addEdge(g, n + v, T, 1)
  return dinic(g, S, T)             // 최대 매칭의 크기
}
```

- 이 방법은 매칭의 크기만 알려 주고 짝은 따로 복원해야 합니다. 짝이 필요하거나 구현이 간단해야 하면 아래의 DFS 매칭을 씁니다.
- 용량이 모두 1인 이 유량 그래프에서 Dinic은 O(E · √V)에 끝납니다(자세히는 70편).

**문제의 단서:** "각각 하나씩 짝을 지어 줄 때 최대 몇 쌍", "한 사람에게 일 하나, 한 일에 한 사람", "서로 다른 둘을 연결해 배치"가 나오면 이분 매칭입니다.

## DFS Matching

DFS 매칭(Kuhn 알고리즘)은 왼쪽 정점을 하나씩 골라 그 정점에서 시작하는 증가 경로를 DFS로 찾고, 찾으면 매칭을 뒤집는 방법입니다. 오른쪽 정점의 짝을 `matchR[v]`(없으면 -1)로 둡니다.

왼쪽 정점 u에서 증가 경로를 찾는 DFS(`tryKuhn`)의 동작입니다.

1. u와 이어진 오른쪽 정점 v를 하나씩 본다. 이번 시도에서 이미 본 v는 건너뛴다.
2. v에 짝이 없으면 u와 v를 짝지어 성공이다.
3. v에 짝 `matchR[v]`가 있으면, 그 짝이 다른 오른쪽 정점으로 옮겨 갈 수 있는지(`tryKuhn(matchR[v])`가 성공하는지) 재귀로 묻는다. 성공하면 v를 u에게 넘기고 성공이다.
4. 모든 v를 보고도 안 되면 실패다.

```js
function tryKuhn(u) {   // adj, matchR, seen, stamp는 바깥 변수
  for (const v of adj[u]) {
    if (seen[v] === stamp) continue // 이번 시도에서 이미 본 정점
    seen[v] = stamp
    if (matchR[v] === -1 || tryKuhn(matchR[v])) {
      matchR[v] = u
      return true
    }
  }
  return false
}
```

예제를 따라갑니다. 왼쪽 정점 0, 1, 2, 3 순서로 시도합니다.

| 시도 | 일어난 일 | `matchR` (오른쪽 0–3의 짝) |
|------|-----------|-----------------------------|
| 0 | 오른쪽 0에 짝이 없어 짝지음 | `[0, -1, -1, -1]` |
| 1 | 오른쪽 0의 짝이 왼쪽 0이므로 왼쪽 0에게 다른 자리를 묻는다. 왼쪽 0이 오른쪽 1로 옮기고 오른쪽 0은 왼쪽 1이 차지 | `[1, 0, -1, -1]` |
| 2 | 오른쪽 0의 짝인 왼쪽 1은 오른쪽 0밖에 갈 곳이 없어 실패 | 그대로 |
| 3 | 오른쪽 2에 짝이 없어 짝지음 | `[1, 0, 3, -1]` |

시도 1에서 이미 있던 짝을 다른 곳으로 옮겨 자리를 만든 것이 증가 경로를 뒤집은 것입니다. 경로는 왼쪽 1, 오른쪽 0, 왼쪽 0, 오른쪽 1입니다.

- `seen`은 이번 시도에서 방문한 오른쪽 정점의 표시입니다. 같은 오른쪽 정점을 한 시도 안에서 두 번 보면 같은 결과가 나오고 사이클을 돕니다.
- 왼쪽 정점마다 시도를 새로 시작하므로 `seen`도 새로 시작해야 합니다. 배열을 매번 `fill`하면 시도마다 O(m)이 듭니다. 시도마다 바뀌는 번호 `stamp`를 값으로 쓰면 초기화가 필요 없습니다(코드의 `seen[v] === stamp`).
- 한 시도의 시간은 O(E)이고 전체는 왼쪽 정점 수만큼 반복해 O(V · E)입니다. 왼쪽을 정점 수가 적은 쪽으로 정하면 반복이 줄어듭니다.
- 먼저 짝이 없는 정점끼리 탐욕으로 매칭해 두고 시작하면 대개 더 빨리 끝납니다.

**흔한 실수:**

- `seen`을 시도마다 새로 하지 않는 것입니다. 이전 시도에서 본 정점은 건너뛰어 증가 경로를 놓치고 매칭이 작게 나옵니다.
- 반대로 `tryKuhn` 안의 재귀 호출 사이에서 `seen`을 초기화하는 것입니다. 한 시도 안에서는 유지해야 합니다.
- 왼쪽에서만 시도하면 되는데 양쪽을 번갈아 돌리는 것입니다. 한쪽 정점만 시작점으로 합니다.
- 재귀 깊이가 증가 경로의 길이만큼 깊어질 수 있어서 큰 입력에서는 호출 스택이 넘칠 수 있습니다(자세히는 86편).

## 최대 이분 매칭 (Maximum Bipartite Matching)

최대 이분 매칭은 위 시도를 왼쪽 정점 전부에 대해 반복해 얻는 가장 큰 매칭입니다. 성공한 시도의 수가 매칭의 크기이고, 짝은 `matchR`에 남습니다.

```js
function maxMatching(n, m, adj) {
  const matchR = new Array(m).fill(-1)
  const seen = new Array(m).fill(0)
  let stamp = 0, size = 0
  // function tryKuhn(u) { ... }  위 코드를 이 안에 둔다
  for (let u = 0; u < n; u++) {
    stamp++
    if (tryKuhn(u)) size++
  }
  return { size, matchR }
}
// 예제: size 3, matchR [1, 0, 3, -1]
```

- 시간은 O(V · E)이고 공간은 O(V + E)입니다.
- `matchR`에서 쌍을 복원합니다. `matchR[v]`가 -1이 아니면 `(matchR[v], v)`가 짝입니다. 완전 매칭인지는 `size === n`(왼쪽 기준 모두 짝이 있음)으로 확인합니다.
- 결과는 한 가지 매칭이고, 최대 매칭이 여러 개일 수 있습니다. 문제가 특정 매칭을 요구하면 조건을 확인합니다.

대표 유형입니다.

| 유형 | 모델링 |
|------|--------|
| 작업 배정 | 사람(왼쪽)과 일(오른쪽), 할 수 있는 조합이 간선 |
| 도미노 최대 개수 | 격자의 빈 칸을 `(r + c) % 2`로 나누고 인접한 빈 칸 사이가 간선, 최대 매칭 크기 = 놓을 수 있는 조각 수 |
| 최소 경로 덮개(DAG) | 정점 u마다 왼쪽 u와 오른쪽 u를 두고 간선 `u→v`를 왼쪽 u와 오른쪽 v로 연결. 정점 수 − 최대 매칭 = 정점이 겹치지 않는 경로의 최소 개수 |
| 배치 충돌 | 서로 겹치는 쌍을 간선으로 하는 이분 그래프 |

**시험에서 묻는 방식:** 작은 이분 그래프를 주고 최대 매칭의 크기를 묻거나, 증가 경로를 하나 찾아 매칭이 어떻게 바뀌는지 묻습니다. 그리디로 먼저 오는 대로 짝지으면 최대가 되지 않는 예(위 예제의 시도 1)를 섞습니다.

**흔한 실수:** 입력 순서대로 먼저 가능한 곳에 짝지어 버리는 탐욕 풀이입니다. 앞에서 짝지은 선택을 되돌릴 수 있어야 해서 증가 경로로 재배치해야 합니다.

## 쾨니그 정리

정점 덮개(vertex cover)는 모든 간선에서 적어도 한 끝점이 속하는 정점의 집합이고, 크기가 최소인 것이 최소 정점 덮개입니다. 독립 집합(independent set)은 서로 이웃하지 않는 정점의 집합입니다. 일반 그래프에서는 둘 다 어려운 문제지만 이분 그래프에서는 매칭으로 풀립니다.

**쾨니그 정리(Kőnig's theorem):** 이분 그래프에서 최대 매칭의 크기는 최소 정점 덮개의 크기와 같습니다.

- 정점 덮개의 여집합은 독립 집합이라서, 최대 독립 집합의 크기는 `전체 정점 수 − 최대 매칭 크기`입니다.
- 예제는 정점이 8개이고 최대 매칭이 3이므로 최소 정점 덮개는 3개, 최대 독립 집합은 5개입니다.
- 덮개는 매칭의 간선마다 정점을 하나 이상 가져야 해서 덮개의 크기는 언제나 매칭의 크기 이상입니다. 정리는 이분 그래프에서 이 둘이 같아진다는 것을 보장합니다.

최소 정점 덮개를 실제로 구하는 방법은 최대 매칭을 구한 뒤 교대 경로를 따라가는 것입니다.

1. 짝이 없는 왼쪽 정점을 모두 시작점으로 한다.
2. 왼쪽에서는 모든 간선을 따라 오른쪽으로, 오른쪽에서는 매칭 간선을 따라 왼쪽으로만 간다(교대 경로). 닿은 정점의 집합을 Z라 한다.
3. 덮개는 `(왼쪽 − Z) ∪ (오른쪽 ∩ Z)`이다. 방문하지 못한 왼쪽 정점과 방문한 오른쪽 정점이다.

```js
// matched[u]: 왼쪽 u에 짝이 있는가, visL, visR: 방문 표시
function walk(u) {                  // 교대 경로를 따라 방문
  visL[u] = true
  for (const v of adj[u]) {
    if (visR[v]) continue
    visR[v] = true
    if (!visL[matchR[v]]) walk(matchR[v])
  }
}
```

```js
for (let u = 0; u < n; u++) if (!matched[u]) walk(u)
const coverL = [], coverR = []
for (let u = 0; u < n; u++) if (!visL[u]) coverL.push(u)
for (let v = 0; v < m; v++) if (visR[v]) coverR.push(v)
// 예제: coverL [0, 3], coverR [0] → 3개
```

- 최대 매칭 뒤에는 방문한 오른쪽 정점 `v`에 반드시 짝이 있습니다. 짝이 없다면 증가 경로가 있다는 뜻이어서 매칭이 최대가 아닙니다. 그래서 `matchR[v]`가 -1인 경우는 생기지 않습니다.
- 예제에서 짝이 없는 왼쪽은 2뿐입니다. 2에서 오른쪽 0으로 가고 그 짝 왼쪽 1로 가서 `Z`는 왼쪽 2, 1과 오른쪽 0입니다. 덮개는 왼쪽 0, 3과 오른쪽 0이고 모든 간선이 덮입니다.
- 독립 집합이 필요하면 덮개의 여집합을 씁니다.

대표 유형입니다. 격자에서 표시된 칸을 모두 지우려고 행 전체 또는 열 전체를 한 줄씩 지울 때 최소 몇 줄인지는 행(왼쪽)과 열(오른쪽)을 정점으로, 표시된 칸을 간선으로 둔 최소 정점 덮개입니다. 답은 최대 매칭의 크기입니다. 서로 충돌하지 않는 대상을 최대한 많이 고르는 문제는 최대 독립 집합이고 `정점 수 − 최대 매칭`입니다.

**흔한 실수:**

- 일반 그래프(이분이 아닌)에 같은 공식을 쓰는 것입니다. 쾨니그 정리는 이분 그래프에서만 성립합니다.
- 덮개를 만들 때 교대 경로가 아니라 아무 간선이나 따라가는 것입니다. 오른쪽에서는 매칭 간선만 따라가야 합니다.
- 최대 독립 집합을 `정점 수 − 최대 매칭`이 아니라 `정점 수 / 2`로 계산하는 것입니다.

## Hopcroft-Karp 개요

Hopcroft-Karp 알고리즘은 한 번에 증가 경로 하나가 아니라, 길이가 같은 최단 증가 경로를 정점이 겹치지 않게 가능한 한 많이 찾아 한꺼번에 반영하는 최대 이분 매칭 알고리즘입니다. 한 단계(phase)는 두 부분입니다.

1. BFS: 짝이 없는 왼쪽 정점들에서 출발해 비매칭 간선(왼쪽에서 오른쪽)과 매칭 간선(오른쪽에서 왼쪽)을 번갈아 따라 층을 만든다. 짝이 없는 오른쪽 정점이 처음 나타나는 층에서 멈춘다. 이 층까지의 길이가 최단 증가 경로의 길이다.
2. DFS: 층이 하나씩 깊어지는 간선만 따라, 서로 정점을 공유하지 않는 최단 증가 경로를 찾을 수 있는 만큼 찾아 매칭을 뒤집는다. 한 번 지난 정점은 이 단계에서 다시 쓰지 않는다.

더 이상 증가 경로가 없으면 끝납니다. 단계가 O(√V)번이어서 전체 시간이 O(E · √V)입니다. Kuhn이 O(V · E)이므로 정점이 많을 때 차이가 큽니다. 같은 O(E · √V)가 이분 매칭용 유량 그래프에서 Dinic의 시간이기도 합니다(자세히는 70편). 두 알고리즘은 사실상 같은 일을 합니다.

- 쓰는 때: 정점과 간선이 많아 Kuhn이 시간 초과가 날 때입니다. Kuhn에 탐욕 초기 매칭을 더하면 무작위에 가까운 입력에서 빨라지고, 그래도 느릴 때 Hopcroft-Karp나 Dinic으로 바꿉니다.
- 구현은 층 배열 `dist`로 BFS한 뒤, DFS가 `dist[다음 짝] === dist[현재] + 1`인 경우만 따라가는 형태입니다. 이 문서에서는 전체 구현을 생략합니다.

## 헝가리안 알고리즘 개요

헝가리안 알고리즘(Hungarian algorithm)은 가중치가 있는 이분 매칭, 즉 할당 문제(assignment problem)를 푸는 알고리즘입니다. n명과 n개의 일 사이의 비용 행렬이 주어질 때, 한 사람에 일 하나씩 모두 배정하면서 총 비용을 최소로 하는 완전 매칭을 O(n³)에 구합니다.

- 1955년 쿤(Harold Kuhn)이 발표했고, 쾨니그와 에게르바리가 이전에 한 연구에 바탕을 두어 '헝가리안'이라 불렀습니다. 1957년 먼크레스(Munkres)가 분석해서 먼크레스 알고리즘이라고도 합니다.
- 원리: 정점마다 포텐셜을 두고, 비용이 포텐셜의 합과 같아 여유가 없는 간선(tight edge)만으로 매칭을 만들고 증가 경로로 키웁니다. 완전 매칭이 안 되면 포텐셜을 조정해 새 tight edge를 만듭니다. 전부 매칭되면 그 매칭의 비용이 최소입니다.
- 최댓값을 구하는 문제는 비용을 `(전체 최댓값 − 비용)`으로 바꿔 최소화합니다. 사람과 일의 수가 다르면 비용이 0인 가짜 행이나 열을 채워 정사각 행렬로 맞춥니다.
- 최소 비용 최대 유량(70편)으로도 같은 문제를 풉니다. 출발점에서 사람으로 용량 1·비용 0, 사람에서 일로 용량 1·비용 `c`, 일에서 도착점으로 용량 1·비용 0 간선을 놓습니다.

```js
// c[i][j]: 사람 i가 일 j를 할 때의 비용, 사람과 일이 k개씩
const S = 2 * k, T = 2 * k + 1   // g: 정점 2k+2개
for (let i = 0; i < k; i++) {
  addEdgeC(g, S, i, 1, 0)
  addEdgeC(g, k + i, T, 1, 0)
  for (let j = 0; j < k; j++)
    addEdgeC(g, i, k + j, 1, c[i][j])
}
// minCostFlow(g, S, T).cost 가 최소 총 비용
```

- k가 작으면(수십–수백) 이 유량 모델링이 구현이 쉽고 충분합니다. 비용 행렬이 꽉 차 있고 k가 크면 O(n³)인 헝가리안이 맞고, 선택은 문제의 제한으로 판단합니다.
- 가중치가 없는 문제(간선이 있느냐 없느냐)에는 위의 DFS 매칭이 훨씬 가볍습니다.

## 핵심 정리

- 이분 그래프는 두 집합 사이에만 간선이 있는 그래프이고, 두 집단의 짝짓기 문제는 왼쪽·오른쪽 정점과 가능한 쌍을 간선으로 모델링한 이분 매칭입니다.
- 증가 경로(양 끝이 짝이 없는 교대 경로)를 뒤집으면 매칭이 1 늘고, 증가 경로가 없을 때 최대입니다(베르주의 보조정리).
- DFS 매칭(Kuhn)은 왼쪽 정점마다 증가 경로를 DFS로 찾으며 O(V · E)이고, 시도마다 `seen`을 새로 시작해야 합니다. 용량 1짜리 유량 그래프로도 풉니다.
- 쾨니그 정리에 따라 이분 그래프에서 최소 정점 덮개의 크기는 최대 매칭의 크기와 같고, 최대 독립 집합은 `정점 수 − 최대 매칭`입니다.
- Hopcroft-Karp는 단계마다 최단 증가 경로를 겹치지 않게 모아서 O(E · √V)에 풀고, 헝가리안 알고리즘은 비용이 있는 완전 매칭을 O(n³)에 구합니다.
