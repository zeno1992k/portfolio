## map

`map`은 모든 요소에 콜백을 적용한 결과를 모아 같은 길이의 새 배열로 반환합니다. 원본은 바뀌지 않습니다.

```js
const nums = [1, 2, 3]
const doubled = nums.map((x) => x * 2) // [2, 4, 6]
const idx = nums.map((x, i) => x * i)  // [0, 2, 6]
```

- 콜백은 요소, 인덱스, 배열 순서로 세 인수를 받습니다.
- `return`이 없으면 그 자리는 `undefined`가 됩니다. 중괄호 본문 화살표 함수에서 자주 생기는 실수입니다.
- 빈 슬롯은 콜백을 건너뛰고 빈 슬롯으로 남습니다(자세히는 04편).

**흔한 실수:** 함수를 그대로 넘기는 것입니다. `parseInt`는 두 번째 인수를 진법으로 읽어서 인덱스가 진법이 됩니다.

```js
['1', '2', '3'].map(parseInt)             // ❌ [1, NaN, NaN]
['1', '2', '3'].map(Number)               // ✅ [1, 2, 3]
['1', '2', '3'].map((s) => parseInt(s, 10)) // ✅ [1, 2, 3]
```

## filter

`filter`는 콜백이 참 값을 반환한 요소만 모아 새 배열로 반환합니다. 결과 길이는 0 이상 원본 이하이고, 원본은 바뀌지 않습니다.

```js
const nums = [5, 12, 8, 130, 44]
nums.filter((x) => x > 10) // [12, 130, 44]
nums.filter((x) => x > 999) // [] (빈 배열)
```

- 조건에 맞는 요소가 없으면 `undefined`가 아니라 빈 배열입니다. `if (result)`는 빈 배열도 참이므로 `result.length`로 검사합니다.
- 거짓 값을 걸러내는 `arr.filter(Boolean)`은 `0`, `''`, `null`, `undefined`, `NaN`을 함께 지웁니다. `0`이 유효한 값이면 쓰지 않습니다.

## reduce

`reduce`는 요소를 하나씩 누적값에 합쳐 값 하나로 줄입니다. 콜백은 누적값, 현재 요소, 인덱스, 배열을 받습니다.

```js
const nums = [1, 2, 3, 4]
const sum = nums.reduce((acc, x) => acc + x, 0) // 10
const max = nums.reduce((a, b) => (a > b ? a : b)) // 4
```

| 호출 | 첫 콜백의 acc | 콜백 호출 횟수 |
|------|---------------|----------------|
| 초깃값 있음 | 초깃값 | 요소 수만큼 |
| 초깃값 없음 | 첫 요소 | 요소 수 − 1 |

- 초깃값이 없는 빈 배열은 TypeError입니다. 초깃값이 있으면 그 값을 그대로 반환합니다.
- 요소가 하나이고 초깃값이 없으면 콜백 없이 그 요소를 반환합니다.
- 코딩테스트에서는 항상 초깃값을 씁니다. 빈 입력과 한 개짜리 입력에서 안전합니다.
- 누적값은 숫자뿐 아니라 배열·객체·Map도 됩니다.

**흔한 실수:**

- 콜백이 `acc`를 반환하지 않으면 다음 반복의 `acc`가 `undefined`가 됩니다.
- `reduce` 안에서 `[...acc, x]`나 `{ ...acc }`로 누적하면 반복마다 전체를 복사해서 전체 비용이 요소 수의 제곱에 비례합니다. `acc.push(x)` 후 `acc`를 반환합니다.

## find와 findIndex

`find`는 조건을 만족하는 첫 요소를, `findIndex`는 그 인덱스를 반환하고 첫 일치에서 순회를 멈춥니다.

```js
const nums = [5, 12, 8, 130, 44]
nums.find((x) => x > 10)      // 12
nums.findIndex((x) => x > 10) // 1
nums.find((x) => x > 999)     // undefined
nums.findIndex((x) => x > 999) // -1
```

- 못 찾으면 `find`는 `undefined`, `findIndex`는 `-1`입니다.
- 요소 자체가 `undefined`나 `0`일 수 있으면 `find`의 결과로는 "찾음"을 구별하지 못합니다. 이때는 `findIndex`가 `-1`이 아닌지 검사합니다.
- 값이 같은지만 보려면 `indexOf`나 `includes`가 더 간단합니다(자세히는 04편). 조건으로 찾을 때만 `find`를 씁니다.

## some과 every

`some`은 하나라도 조건을 만족하면 `true`, `every`는 모두 만족해야 `true`를 반환하는 불리언 메서드입니다. 결과가 정해지는 순간 순회를 멈춥니다.

```js
const nums = [1, 3, 5, 6]
nums.some((x) => x % 2 === 0)  // true (6에서 확정)
nums.every((x) => x % 2 === 1) // false (6에서 확정)
const empty = []
empty.some((x) => true)        // false
empty.every((x) => false)      // true
```

- 빈 배열에서 `some`은 `false`, `every`는 `true`입니다. "모든 요소가 ~이다"를 `every`로 검사할 때 빈 입력이 통과한다는 뜻입니다.
- 둘 다 빈 슬롯은 건너뜁니다.
- `some`은 존재 여부, `every`는 전체 검증입니다. 반복문에서 `flag`를 두고 `break`하던 코드를 대체합니다.

## forEach

`forEach`는 각 요소에 콜백을 실행하고 항상 `undefined`를 반환합니다. 결과를 만들지 않고 부수 효과(출력, 외부 변수 갱신)만 일으킬 때 씁니다.

```js
let total = 0
;[1, 2, 3].forEach((x) => { total += x })
console.log(total) // 6
```

- `break`와 `continue`가 없습니다. 중간에 멈추려면 예외를 던지는 방법뿐이라서 `for...of`나 `some`·`every`를 씁니다. 콜백의 `return`은 그 호출만 끝냅니다(`continue`처럼 동작).
- 비동기 콜백을 기다리지 않습니다. 코딩테스트에는 거의 나오지 않습니다.
- 값을 만들어 내는 용도는 `map`·`filter`·`reduce`입니다.

## flat과 flatMap

`flat`은 중첩 배열을 지정한 깊이만큼 펼친 새 배열을 반환합니다. 기본 깊이는 1이고, `Infinity`는 끝까지 펼칩니다. 빈 슬롯은 제거됩니다.

```js
const nested = [1, [2, [3, [4]]]]
nested.flat()         // [1, 2, [3, [4]]]
nested.flat(2)        // [1, 2, 3, [4]]
nested.flat(Infinity) // [1, 2, 3, 4]
```

`flatMap`은 `map` 뒤에 `flat(1)`을 한 번에 합니다. 한 단계만 펼치고, 콜백이 배열이 아닌 값을 반환하면 그대로 넣습니다.

```js
const words = ['ab', 'c']
words.map((w) => [...w])     // [['a', 'b'], ['c']]
words.flatMap((w) => [...w]) // ['a', 'b', 'c']
```

- 콜백이 빈 배열 `[]`을 반환하면 그 요소가 사라져서 `filter`와 `map`을 한 번에 하는 용도로 씁니다.
- 2차원 배열을 1차원으로 만들 때는 `grid.flat()`, 모든 칸 값의 합 같은 계산은 `grid.flat().reduce(...)`입니다.

## findLast와 findLastIndex

`findLast`는 뒤에서부터 순회해 조건을 만족하는 첫 요소를, `findLastIndex`는 그 인덱스를 반환합니다. ES2023에 추가되었습니다. 못 찾으면 `findLast`는 `undefined`, `findLastIndex`는 `-1`입니다.

```js
const nums = [5, 12, 8, 130, 44]
nums.findLast((x) => x > 10)      // 44
nums.findLastIndex((x) => x > 10) // 4
```

구형 대체는 `[...arr].reverse().find(...)`입니다. 복사 비용이 들고 인덱스를 뒤집어서 계산해야 하므로 뒤에서부터 순회하는 `for` 문이 더 낫습니다. Node.js 24에서는 그대로 쓸 수 있습니다.

## sort

`sort`는 배열을 제자리에서 정렬하고 같은 배열의 참조를 반환합니다. 원본이 바뀝니다.

```js
const nums = [10, 9, 1, 30]
nums.sort()               // [1, 10, 30, 9] (문자열 순서)
nums.sort((a, b) => a - b) // [1, 9, 10, 30]
nums.sort((a, b) => b - a) // [30, 10, 9, 1]
```

- 비교 함수가 없으면 요소를 문자열로 바꿔 UTF-16 코드 유닛 순으로 비교합니다. 숫자 배열에서 `[1, 10, 30, 9]`처럼 나오는 이유입니다. 숫자는 항상 비교 함수를 넘깁니다.
- 비교 함수의 반환값이 음수이면 `a`가 앞, 양수이면 `a`가 뒤, 0이면 순서 유지입니다.
- ES2019부터 안정 정렬입니다. 비교 결과가 같은 요소는 원래 순서를 지킵니다.
- `undefined`는 맨 뒤로 가고, 빈 슬롯은 `undefined`보다도 뒤에 놓입니다.
- 복잡도는 명세가 정하지 않고 구현에 따릅니다(자세히는 26편).

**흔한 실수:**

- 비교 함수가 불리언을 반환하는 것입니다. `(a, b) => a > b`는 `1` 또는 `0`만 나오고 음수가 없어서 올바른 정렬이 되지 않을 수 있습니다. 숫자 차이나 `-1`·`0`·`1`을 반환합니다.
- `const sorted = arr.sort()`로 "새 배열"을 얻었다고 믿는 것입니다. `sorted`와 `arr`는 같은 배열입니다.
- 문자열 기준 정렬과 다중 기준 정렬의 비교 함수는 26편에서 다룹니다.

## 원본을 바꾸지 않는 toSorted, toReversed, with

ES2023에 `sort`, `reverse`, 인덱스 대입에 대응하는 비변형 메서드가 추가되었습니다. 모두 새 배열을 반환하고 원본은 그대로입니다.

| 변형 방식 | 비변형 방식 | 하는 일 |
|-----------|-------------|---------|
| `arr.sort(f)` | `arr.toSorted(f)` | 정렬한 새 배열 |
| `arr.reverse()` | `arr.toReversed()` | 뒤집은 새 배열 |
| `arr[i] = v` | `arr.with(i, v)` | i번 요소만 바꾼 새 배열 |

```js
const a = [3, 1, 2]
a.toSorted((x, y) => x - y) // [1, 2, 3]
a.toReversed()              // [2, 1, 3]
a.with(0, 9)                // [9, 1, 2]
// a는 계속 [3, 1, 2]
```

- `with`는 음수 인덱스를 받고, 범위를 벗어나면 RangeError입니다. 빈 슬롯은 `undefined`로 채워진 새 배열이 됩니다.
- `toSorted`도 비교 함수가 없으면 문자열 순서입니다.
- 구형 대체 코드는 `[...a].sort(f)`, `[...a].reverse()`, `Object.assign([...a], { [i]: v })` 같은 복사 후 변형입니다. 세 메서드 모두 복사가 일어나서 O(n)입니다.
- 원본을 보존해야 하는 상태 탐색에서 쓸모가 있지만, 반복마다 복사하므로 큰 입력의 반복문 안에서는 피합니다.

## 2차원 배열

2차원 배열은 배열을 요소로 가진 배열입니다. `grid[r][c]`는 r행 c열이고, 행 수는 `grid.length`, 열 수는 `grid[0].length`입니다.

```js
const grid = [
  [1, 2, 3],
  [4, 5, 6],
]
grid[1][2]         // 6
grid.length        // 2 (행)
grid[0].length     // 3 (열)
```

크기가 정해진 빈 격자는 행마다 새 배열을 만들어야 합니다.

```js
const n = 3, m = 4
const g = Array.from({ length: n }, () => Array(m).fill(0))
// 3행 4열, 모두 0
```

전체 순회는 중첩 반복문입니다. 행 인덱스를 바깥에 둡니다.

```js
for (let r = 0; r < n; r++) {
  for (let c = 0; c < m; c++) {
    g[r][c] = r * m + c
  }
}
```

- 범위를 벗어난 행에 접근하면 `g[-1]`이 `undefined`라서 `g[-1][0]`은 TypeError입니다. 범위 검사를 먼저 합니다.
- 행을 복사하려면 `row.slice()`나 `[...row]`, 전체를 복사하려면 `grid.map((row) => [...row])`입니다. `[...grid]`는 행 배열을 공유하는 얕은 복사입니다(자세히는 01편).
- 격자 탐색, 방향 배열, 회전은 17편에서 다룹니다.

## 2차원 배열 fill의 참조 공유 문제

`fill`은 같은 값을 모든 칸에 넣는데, 값이 배열이나 객체이면 참조 하나가 모든 칸에 들어갑니다. 행이 전부 같은 배열이 됩니다.

```js
const bad = Array(3).fill(Array(3).fill(0))
bad[0][0] = 1
console.log(bad) // [[1,0,0],[1,0,0],[1,0,0]] ❌
```

```js
const good = Array.from({ length: 3 }, () =>
  Array(3).fill(0),
)
good[0][0] = 1
console.log(good) // [[1,0,0],[0,0,0],[0,0,0]] ✅
```

- `Array(3).fill(0)`의 `0`은 원시 값이라 값이 복사되어 안전합니다. 문제는 `fill`의 인수가 객체·배열일 때만 생깁니다.
- `Array.from`의 두 번째 인수(콜백)는 칸마다 실행되므로 칸마다 새 배열이 만들어집니다. `Array(n).fill().map(() => Array(m).fill(0))`도 같은 결과를 냅니다.
- `fill` 대신 `Array(n).map(...)`을 쓰면 빈 슬롯은 콜백을 건너뛰어서 아무것도 채워지지 않습니다(자세히는 04편).
- 객체를 칸마다 따로 만들 때도 `Array.from({ length: n }, () => ({}))`입니다.

## 배열 빈도수 계산

값의 범위가 작은 정수라면 값 자체를 인덱스로 쓰는 카운트 배열이 가장 간단합니다.

```js
const nums = [3, 1, 3, 0, 1, 3]
const cnt = Array(4).fill(0) // 값 범위 0–3
for (const x of nums) cnt[x]++
console.log(cnt) // [1, 2, 0, 3]
```

- `cnt[v]`는 값 `v`가 나온 횟수입니다. 배열 크기는 최댓값 + 1입니다.
- 가장 많이 나온 값은 `cnt`에서 최댓값의 인덱스를 찾습니다. 동률이면 어느 값을 고를지 문제 조건을 확인합니다.
- 값이 음수이거나 범위가 크면 인덱스로 쓸 수 없어서 `Map`이나 `Object`를 씁니다(자세히는 10편). 알파벳이면 `charCodeAt`으로 `'a'`와의 차이를 인덱스로 씁니다(자세히는 06편).
- `Array(n).fill(0)`의 `n`을 몰라서 `Math.max(...nums)`로 구하면 대용량에서 인수 개수 한계로 RangeError가 날 수 있습니다. 반복문으로 최댓값을 구합니다.

## TypedArray

TypedArray는 한 가지 숫자 형식만 담는 고정 길이 배열입니다. `Int32Array`, `Float64Array` 등 종류마다 요소의 바이트 크기와 값 범위가 정해져 있고, 생성하면 모든 요소가 0입니다.

| 종류 | 값 범위 | 요소 바이트 |
|------|---------|-------------|
| `Int8Array` | –128–127 | 1 |
| `Uint8Array` | 0–255 | 1 |
| `Int16Array` | –32768–32767 | 2 |
| `Uint16Array` | 0–65535 | 2 |
| `Int32Array` | –2147483648–2147483647 | 4 |
| `Uint32Array` | 0–4294967295 | 4 |
| `Float32Array` | 약 ±3.4e38 | 4 |
| `Float64Array` | 약 ±1.8e308 | 8 |
| `BigInt64Array` | –2^63–2^63−1 | 8 |

```js
const dp = new Int32Array(5)     // [0, 0, 0, 0, 0]
const seen = new Uint8Array(100) // 방문 표시용
dp.fill(-1)                      // [-1, -1, -1, -1, -1]
dp[2] = 7
```

- 길이는 고정입니다. `push`, `pop`, `shift`, `splice`가 없습니다.
- 범위를 벗어난 값은 에러 없이 잘려서 바뀝니다. 정수 배열은 소수점을 버리고 아래 비트만 남겨서 값이 순환합니다.

```js
const a = new Int8Array(1)
a[0] = 200
console.log(a[0]) // -56 (200 − 256)
const b = new Int32Array([2147483647])
b[0]++
console.log(b[0]) // -2147483648
```

- `Uint8ClampedArray`만은 0–255로 잘라 맞춥니다. 나머지 정수 배열은 순환합니다.
- `sort()`의 기본 비교가 숫자 순입니다. 일반 배열과 달리 문자열 순서가 아닙니다.
- `map`, `filter`, `slice`, `reduce`, `fill`, `find`, `includes`, `toSorted`, `with` 등 읽기·변환 메서드는 대부분 있습니다. 결과 `map`·`filter`·`slice`는 같은 종류의 TypedArray입니다.
- 일반 배열로 바꾸려면 `Array.from(t)` 또는 `[...t]`입니다. `console.log`로 확인하거나 `join`으로 출력할 때 씁니다.
- 용도는 큰 `dp`·방문 표시·카운트 배열처럼 크기가 크고 값 범위를 아는 숫자 배열입니다. 메모리가 요소 바이트 수만큼만 듭니다.
- 2차원 격자는 한 줄 배열에 `r * m + c`로 접근해서 만들 수 있습니다.
- 합이 `Int32Array`의 범위를 넘을 수 있으면 `Float64Array`를 쓰거나 합을 별도의 `Number` 변수에 누적합니다. `Float64Array`의 정확한 정수 범위는 `Number.MAX_SAFE_INTEGER`까지입니다(자세히는 02편).
- `BigInt64Array`에는 BigInt만 넣을 수 있습니다. `Number`를 넣으면 TypeError입니다.

## 고차 함수와 for 문의 비용 차이

`map`, `filter`, `reduce`와 `for` 문은 둘 다 요소 수에 비례하는 O(n)입니다. 차이는 상수 배에서 나옵니다.

| 항목 | 고차 함수 | for 문 |
|------|-----------|--------|
| 요소마다 | 콜백 호출 | 호출 없음 |
| 중간 결과 | 체이닝마다 새 배열 | 만들지 않아도 됨 |
| 중간 탈출 | `some`·`every`·`find`만 가능 | `break`·`return` 자유 |
| 가독성 | 의도가 드러남 | 코드가 길어짐 |

```js
// 순회 두 번 + 중간 배열 하나
const a = nums.filter((x) => x > 0).map((x) => x * 2)
// 순회 한 번, 중간 배열 없음
const b = []
for (const x of nums) if (x > 0) b.push(x * 2)
```

- 체이닝은 단계마다 순회와 새 배열이 하나씩 생깁니다. 입력이 크면 `for` 문 하나로 합칩니다.
- 이 상수 배 차이가 시간 제한을 넘기는지는 입력 크기와 엔진에 따라 다릅니다. 이 문서는 측정 수치를 제시하지 않습니다. 기본은 읽기 쉬운 고차 함수로 쓰고, 제한이 빠듯한 반복문에서 `for` 문으로 바꿉니다(자세히는 13편).
- `reduce`로 객체나 배열을 누적할 때는 위에서 본 대로 복사 누적을 피합니다.

## 핵심 정리

- `map`·`filter`·`reduce`·`flat`·`flatMap`·`toSorted`·`toReversed`·`with`는 새 값을 반환하고, `sort`·`reverse`·`fill`은 원본을 바꿉니다.
- `reduce`에는 항상 초깃값을 줍니다. 초깃값 없는 빈 배열은 TypeError입니다.
- `sort`의 기본 비교는 문자열 순서이므로 숫자는 `(a, b) => a - b`를 넘기고, `find`는 못 찾으면 `undefined`, `findIndex`는 `-1`을 반환합니다.
- `Array(n).fill([])`는 모든 칸이 같은 배열이므로 2차원 배열은 `Array.from`의 콜백으로 행마다 새로 만듭니다.
- 값 범위가 작은 정수의 빈도수는 카운트 배열로 셉니다. 크기가 큰 숫자 배열은 TypedArray를 쓰되 범위를 넘으면 값이 순환합니다.
- 고차 함수와 `for` 문은 모두 O(n)이고 차이는 상수 배입니다. 체이닝은 중간 배열을 만듭니다.
