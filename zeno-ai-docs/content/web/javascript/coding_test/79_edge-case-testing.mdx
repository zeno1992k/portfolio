## 경계 테스트 (Boundary Test)

경계 테스트는 입력이 허용되는 범위의 끝과 그 바로 안팎의 값으로 풀이를 시험하는 것입니다. 버그는 값의 한가운데보다 경계에서 훨씬 자주 나옵니다. 조건식의 부등호, 반복의 시작과 끝, 배열의 첫·마지막 인덱스가 모두 경계에서 달라지기 때문입니다.

- 출발점은 문제의 제약입니다. 제약에 적힌 최솟값과 최댓값이 경계의 후보입니다(자세히는 15편).
- 예제 입력은 대개 경계를 피한 평범한 값이라서 예제를 통과해도 경계에서 틀릴 수 있습니다.
- 풀이를 제출하기 전에 아래 표에서 해당하는 입력을 골라 손으로 따라가거나(Dry Run) 직접 돌려 봅니다.

| 입력 종류 | 시험할 경계 | 이 편의 절 |
|-----------|-------------|-----------|
| 크기 | 최소, 최대 | 최소 입력, 최대 입력 |
| 비어 있음·하나뿐 | 길이 0, 1 | 빈 입력과 단일 원소 |
| 값의 분포 | 중복, 정렬, 역정렬, 모두 같음 | 중복값부터 모든 값이 같은 입력까지 |
| 값의 크기 | 합·곱이 안전 범위를 넘는 경계 | Overflow 경계 |
| 인덱스·구간 | 포함·제외, 처음과 끝 | Off-by-one 경계 |
| 그래프 | 정점 1개, 간선 0개, 자기 루프, 중복 간선 | 그래프 특수 입력 |
| 격자 | 1 × 1, 한 줄 | 격자 특수 입력 |

- 경계 테스트는 정답을 알고 있어야 합니다. 작은 입력은 손으로 정답을 구하고, 큰 입력은 느리더라도 확실히 맞는 풀이와 비교합니다(80편).
- 같은 입력으로 여러 번 틀리는 것을 막으려면 틀린 입력을 목록으로 모아 두고 수정할 때마다 전부 다시 돌립니다.

## 최소 입력

최소 입력은 제약이 허용하는 가장 작은 크기와 가장 작은 값입니다. N이 1부터 허용되면 N = 1이고, 값이 0 이상이면 0입니다.

- 첫 원소와 마지막 원소가 같은 칸이거나, 이웃이 아예 없는 경우가 생깁니다. 비교 대상이 없는 풀이가 `undefined`와 비교하게 됩니다.
- 구간이나 쌍을 다루는 풀이는 원소가 하나뿐이면 구간이 없습니다. 정답이 0인지, -1인지, 원소 자체인지 문제를 다시 읽어 정합니다.
- 값이 0이면 곱이 0이 되고, 나눗셈이 0으로 나뉘고(`1 / 0`은 에러 없이 `Infinity`), 로그와 최댓값 초기화가 어긋납니다.
- 최솟값 초기화는 입력에 나올 수 있는 값보다 작거나 큰 값이어야 합니다. 값이 음수일 수 있는데 최댓값을 `0`으로 초기화하면 모두 음수인 입력에서 틀립니다. `-Infinity`나 첫 원소로 초기화합니다.

```js
// ❌ 모두 음수이면 0이 답으로 남는다
let best = 0
for (const x of a) if (x > best) best = x
// ✅ 첫 원소로 초기화
let best2 = a[0]
for (const x of a) if (x > best2) best2 = x
```

## 최대 입력

최대 입력은 제약의 상한 크기와 상한 값입니다. 정답이 아니라 시간, 메모리, 재귀 깊이, 값의 크기가 한계를 넘지 않는지 보는 시험입니다.

- 시간: 상한에서 77편의 계산이 실제로 맞는지 직접 돌려 봅니다. 평균적인 입력이 아니라 풀이에 가장 불리한 구조(모두 정렬, 모두 같음, 일직선 그래프)로 만듭니다.
- 메모리: 배열·객체를 상한 크기로 만들었을 때 감당되는지 봅니다(자세히는 14편).
- 재귀 깊이: 입력 크기만큼 깊어지는 재귀(일직선 트리의 DFS 등)는 스택 한계를 넘을 수 있습니다. 한계는 환경에 따라 다릅니다(자세히는 22편, 86편).
- 출력 크기: 줄이 10^6개이면 한 번에 모아 출력해야 합니다(자세히는 08편).
- 값: 합과 곱이 Number 안전 범위를 넘는지 계산합니다(아래 "Overflow 경계").

```js
const n = 100000
const sorted = Array.from({ length: n }, (_, i) => i)
const reversed = sorted.slice().reverse()
const same = new Array(n).fill(7)
// 최대 크기의 정렬·역정렬·동일값 입력을 만들어 시간을 잰다
```

- 입력 파일이 아니라 코드로 만들면 크기를 바꿔 가며 시험하기 쉽습니다. 무작위 입력으로 확장하는 방법은 80편입니다.
- 상한 입력에서 문제가 되는 것은 속도만이 아닙니다. 통과하던 코드가 크기만 키웠을 때 RangeError(호출 스택 초과)나 메모리 초과를 내기도 합니다.

## 빈 입력과 단일 원소

빈 입력은 원소가 0개이고, 단일 원소는 1개입니다. 문제가 허용하면 반드시 시험합니다.

- 배열의 빈 입력은 JavaScript에서 에러 없이 조용히 넘어가는 경우와 에러가 나는 경우가 갈립니다.

| 코드 | 빈 배열 `[]`일 때 |
|------|------------------|
| `a[0]`, `a.at(-1)` | `undefined` |
| `Math.max(...a)` | `-Infinity` |
| `Math.min(...a)` | `Infinity` |
| `a.reduce(f)` (초기값 없음) | TypeError |
| `a.reduce(f, 0)` | `0` |

- 단일 원소 배열에 초기값 없는 `reduce`를 쓰면 콜백이 한 번도 호출되지 않고 그 원소가 그대로 반환됩니다. 빈 배열은 TypeError이고 단일 원소는 통과하므로, 소량 테스트에서 놓치기 쉽습니다.
- `Math.max()`에 인수가 없으면 `-Infinity`입니다. 이 값이 그대로 출력되거나 계산에 섞이지 않는지 봅니다.
- 문자열의 빈 입력도 다릅니다. 빈 문자열을 구분자로 나누면 빈 배열이 아니라 빈 문자열 하나가 든 배열이 됩니다.

```js
''.split(' ')   // [''] (길이 1)
''.split('')    // [] (길이 0)
'5'.split(' ')  // ['5'] (단일 원소)
```

- 입력의 한 줄이 비어 있으면 `split(' ').map(Number)`가 `[0]`이 됩니다(`Number('')`는 0). 원소가 0개인 줄을 읽는 코드는 빈 문자열을 먼저 검사합니다(자세히는 08편).
- 문제가 "N ≥ 1"을 보장하면 빈 입력은 나오지 않습니다. 보장이 없는데 풀이가 첫 원소를 가정하면 틀립니다.

```js
const maxOf = (a) => a.reduce((m, v) => (v > m ? v : m))
maxOf([5])  // 5 (콜백 호출 없이 5)
maxOf([])   // TypeError
```

## 중복값

중복값은 같은 값이 여러 개 있는 입력입니다. 값이 모두 다르다는 암묵적 가정이 깨지는 곳에서 틀립니다.

- 부등호가 `<`인지 `<=`인지에 따라 같은 값을 처리하는 방식이 갈립니다. 정렬의 비교 함수, 이분 탐색의 하한·상한, 단조 스택의 pop 조건이 모두 해당합니다.
- 최댓값·최솟값이 여러 개일 수 있습니다. 위치를 구한다면 첫 번째, 마지막, 모두 중 무엇인지 문제를 확인합니다. `indexOf`는 첫 번째만 줍니다.
- `Set`으로 중복을 제거하면 원소 수가 줄어듭니다. 줄어든 길이를 N으로 쓰는지 원래 N을 쓰는지 확인합니다.
- 투 포인터에서 같은 값을 건너뛰는 처리를 안 하면 같은 쌍을 중복으로 세거나 빠뜨립니다.
- 같은 키를 가진 항목의 순서가 중요하면 안정 정렬 여부를 확인합니다. 배열 `sort`는 ES2019부터 안정 정렬입니다(자세히는 26편).
- 객체나 `Map`의 키로 쓸 값이 겹치는지도 봅니다. 중복 키는 앞의 값을 덮어씁니다(자세히는 09편).

```js
const a = [3, 1, 3, 3, 2]
a.indexOf(3)         // 0 (첫 번째만)
new Set(a).size      // 3 (길이는 5)
a.lastIndexOf(3)     // 3
```

**흔한 실수:** 모든 값이 서로 다르다고 가정한 풀이입니다. 예제가 우연히 중복 없는 값이면 통과합니다.

## 정렬된 입력과 역정렬 입력

이미 정렬되어 있거나 거꾸로 정렬된 입력은 구조가 단순해서 평균 입력에서는 드러나지 않는 최악의 동작을 끌어냅니다.

| 풀이 | 정렬·역정렬 입력에서 생기는 일 |
|------|------------------------------|
| 첫·마지막 원소를 기준으로 삼는 퀵 정렬 | 분할이 한쪽으로 치우쳐 O(N²) |
| 삽입 정렬 | 정렬 입력은 O(N), 역정렬은 O(N²) |
| 균형 잡지 않는 이진 탐색 트리에 순서대로 삽입 | 일직선이 되어 높이가 N, 연산이 O(N) |
| Monotonic Stack | 스택에 모든 원소가 쌓이거나 매번 모두 pop |
| 정렬되었다고 가정한 이분 탐색 | 정렬이 아닌 입력에서는 틀린 답 |

- 정렬 알고리즘과 트리의 최악 동작은 27편과 45편에서 다룹니다. 직접 구현한 정렬이나 트리가 있다면 이 입력으로 시간을 잽니다.
- 반대로 정렬이 보장되지 않는 입력에 정렬을 가정한 풀이를 쓰면 틀립니다. 정렬 여부가 문제에 적혀 있는지 확인합니다.
- `sort`의 기본 비교는 문자열 순서라서 숫자는 비교 함수가 필요합니다(자세히는 26편).
- 최대 크기의 정렬·역정렬 배열을 만드는 방법은 앞의 "최대 입력"의 코드와 같습니다.

## 모든 값이 같은 입력

모든 원소가 같은 입력은 중복값의 극단입니다. 값이 달라야 의미 있는 연산이 전부 퇴화합니다.

- 최댓값과 최솟값이 같아서 `max - min`이 0입니다. 이 값으로 나누면 `Infinity`나 `NaN`이 나옵니다(정규화, 비율 계산).
- 정렬 후 인접한 원소의 차이가 모두 0이고, 중복 제거 후에는 원소가 하나뿐입니다.
- 단조 스택에서 같은 값에 대한 처리 조건(`<`와 `<=`)이 갈립니다. 같은 값이 연속으로 N개이면 어느 쪽이든 O(N)이어야 합니다.
- 분할 정복이나 퀵 정렬에서 한쪽만 채워지는 분할이 일어납니다. 같은 값을 세 구간(작은 값, 같은 값, 큰 값)으로 가르는 구현이 이를 피합니다.
- 합이 K인 구간을 세는 문제에서 모든 값이 같으면 가능한 구간의 개수가 최대가 되고, 정답 값이 커집니다(오버플로를 함께 봅니다).
- 모든 값이 같은 문자열(`'aaaa'`)은 팰린드롬, 접두사·접미사 비교, KMP의 실패 함수 같은 문자열 풀이의 최악 입력입니다(자세히는 58편).

```js
const same = [4, 4, 4, 4]
const range = Math.max(...same) - Math.min(...same) // 0
1 / range   // Infinity
0 / range   // NaN
```

## Overflow 경계

JavaScript의 `Number`는 정수 오버플로로 값이 순환하지 않습니다. 대신 안전 범위를 넘으면 정확도를 잃고, 비트 연산과 TypedArray에서는 32비트로 순환합니다. 어떤 연산이 어느 경계를 갖는지 아는 것이 핵심입니다.

| 연산·자료형 | 경계 | 넘으면 |
|-------------|------|--------|
| 일반 산술(`+`, `*`) | 정수 정확도 2^53 − 1 | 정확하지 않은 값(오류 없음) |
| 비트 연산(AND, OR, 시프트) | 32비트 부호 있는 정수 | 하위 32비트만 남아 순환 |
| `Int32Array` 등 정수 TypedArray | 요소 자료형의 범위 | 하위 비트만 남아 순환 |
| BigInt | 없음(메모리까지) | 해당 없음 |

- 안전 범위는 `Number.MAX_SAFE_INTEGER`, 즉 9007199254740991(약 9.0 × 10^15)입니다. 이 값을 넘으면 서로 다른 정수가 같은 값으로 합쳐집니다.

```js
999999999 * 999999999    // 999999998000000000 (1이 사라짐)
999999999n * 999999999n  // 999999998000000001n (정확)
2 ** 53 + 1 === 2 ** 53  // true
```

- 비트 연산은 피연산자를 32비트 정수로 바꿉니다. `2 ** 31 | 0`은 −2147483648이고, `1 << 31`도 음수입니다. 정수 나눗셈을 `| 0`으로 하는 습관은 값이 2^31 미만일 때만 안전합니다(자세히는 02편).
- `Int32Array`에 범위 밖의 값을 넣으면 하위 32비트만 남습니다. `2 ** 32`를 넣으면 0이 되고 에러는 나지 않습니다.
- 경계를 미리 계산합니다. 합이면 최댓값 × 개수, 곱이면 최댓값의 거듭제곱, 누적합이면 N × 최댓값입니다. 10^9 × 10^5 = 10^14는 안전하고, 10^9 × 10^7 = 10^16은 안전하지 않습니다(77편).
- 곱셈이 한 번이라도 2^53을 넘으면 나머지 연산 전에 이미 값이 틀립니다. `(a * b) % M`에서 a, b가 10^9 수준이면 곱이 10^18이라 안전하지 않습니다. BigInt나 곱셈 분할을 씁니다(자세히는 57편).
- BigInt는 Number와 섞어서 산술하면 TypeError입니다. 대소 비교는 섞어도 됩니다. 한 쪽으로 통일합니다(자세히는 02편).

**흔한 실수:** 예제에서 정답이 작아서 오버플로를 못 보는 것입니다. 상한 값(전부 10^9 등)으로 합과 곱을 직접 계산해 확인합니다.

## Off-by-one 경계

Off-by-one은 반복 횟수, 인덱스, 구간의 끝이 하나 모자라거나 하나 넘치는 오류입니다. 경계 값에서만 틀리고 중간 값에서는 맞아서 소량 예제로 놓치기 쉽습니다.

- 포함·제외를 구분합니다. 구간이 `[l, r]`(양 끝 포함)인지 `[l, r)`(끝 제외)인지에 따라 길이와 반복 조건이 바뀝니다. `slice(start, end)`의 `end`는 제외입니다.
- 길이 N인 배열의 인덱스는 0부터 N − 1까지입니다. `arr[arr.length]`는 `undefined`입니다.
- 반복의 `<`와 `<=`: 인덱스로 도는 반복은 `i < n`이고, 값(1부터 N까지)으로 도는 반복은 `i <= n`입니다.
- N개의 점 사이 구간은 N − 1개이고, N개 구간에 필요한 울타리 기둥은 N + 1개입니다(fencepost).
- 0부터 세는 인덱스와 1부터 세는 번호를 섞으면 하나씩 어긋납니다. 입력이 1부터 번호를 매기면 배열을 `n + 1`칸으로 만들어 그대로 쓰는 편이 안전합니다.

```js
const a = [1, 2, 3]
const pre = [0, 1, 3, 6]          // pre[i] = a[0..i-1]의 합
const sum = (l, r) => pre[r + 1] - pre[l]
sum(0, 2)  // 6 (✅ r 포함)
// ❌ pre[r] - pre[l]은 3: 마지막 원소가 빠짐
```

- 이분 탐색은 경계가 가장 자주 틀리는 곳입니다. 구간을 닫힌 구간으로 쓰면 `while (lo <= hi)`와 `hi = mid - 1`이, 반닫힌 구간이면 `while (lo < hi)`와 `hi = mid`가 짝입니다. 짝이 섞이면 무한 루프가 되거나 답을 놓칩니다(자세히는 28편).
- 안쪽 `while`이나 반복의 조건이 `i + 1`을 읽는다면 마지막 인덱스에서 범위 밖을 읽습니다.
- 확인 방법은 가장 작은 입력(N = 1, 2)에서 손으로 따라가 보는 것입니다. 하나가 어긋나면 N이 작을수록 눈에 띕니다.

## 그래프 특수 입력

그래프 문제의 경계 입력입니다. 일반적인 그래프(여러 정점, 연결됨, 간선이 단순함)를 가정한 코드가 깨집니다.

- 정점 1개: 정점이 하나뿐인 그래프입니다. 출발과 도착이 같고, 연결 요소 수는 1이며, 트리 문제의 루트가 곧 리프입니다. 최단 거리는 0입니다.
- 간선 0개: 모든 정점이 고립입니다. 인접 리스트의 모든 칸이 빈 배열이어야 하고, 연결 요소 수는 정점 수와 같습니다. 간선 목록 입력의 줄이 0개이면 읽는 코드가 빈 줄이나 `undefined`를 만나지 않는지 봅니다.
- 자기 루프(`u → u`): 방향 그래프에서는 사이클이고 위상 정렬을 막습니다. 무방향 그래프에서는 차수를 2 늘리고, Union-Find에서는 같은 집합을 합치려는 간선이 됩니다. 최단 경로에서는 거리를 줄이지 못해서 문제없지만, 음수 가중치 자기 루프는 음수 사이클입니다.
- 중복 간선(같은 정점 쌍이 여러 번): 인접 리스트에 같은 이웃이 여러 번 들어갑니다. 최단 경로는 문제없지만 진입차수나 차수를 세는 풀이, 간선 수를 세는 풀이는 결과가 달라집니다. 가중치가 다르면 최솟값만 남기는 처리가 필요한지 확인합니다.
- 연결되지 않은 그래프: 도달할 수 없는 정점의 거리는 무한대입니다. 이를 출력할 때 `Infinity`가 그대로 나가지 않도록 문제의 형식(예: `-1`)을 따릅니다.

```js
// 정점 번호 1..n, 간선 0개
const adj = Array.from({ length: n + 1 }, () => [])
for (const [u, v] of edges) {       // edges가 []이면 건너뜀
  adj[u].push(v)
  adj[v].push(u)                    // u === v이면 같은 칸에 두 번
}
```

- 위상 정렬에서 인접 리스트는 중복을 허용해 두고 진입차수도 간선 수만큼 세어야 일관됩니다. 한쪽만 중복을 제거하면 진입차수가 0이 되지 않아 사이클로 잘못 판정합니다(자세히는 53편).
- DFS와 BFS에서 방문 체크를 하지 않으면 자기 루프와 중복 간선에서 무한 반복에 빠집니다(자세히는 36편, 38편).
- 문제 제약이 "단순 그래프"(자기 루프와 중복 간선 없음)를 보장하면 시험할 필요가 없습니다. 보장이 없으면 포함해서 시험합니다.

## 격자 특수 입력

격자 문제의 경계 입력입니다.

- 1 × 1 격자: 이동할 칸이 없습니다. 출발과 도착이 같은 칸이고, 최단 거리는 0입니다. 그 칸이 벽이면 도달 불가능입니다.
- 한 줄 격자(1 × M 또는 N × 1): 한 방향으로만 이동이 가능합니다. 네 방향을 시도하다가 범위를 벗어나는 경우가 대부분입니다.
- 출발이 곧 도착이거나, 출발·도착이 벽으로 막혀 있거나, 도착이 도달 불가능한 경우입니다.
- JavaScript에서는 범위 검사를 빠뜨렸을 때 증상이 조용합니다.

| 접근 | 결과 |
|------|------|
| `grid[-1][c]` (행이 범위 밖) | `grid[-1]`이 `undefined`라서 TypeError |
| `grid[r][-1]`, `grid[r][M]` (열이 범위 밖) | 에러 없이 `undefined` |

- 열이 범위 밖일 때 `undefined`는 벽(`1`)이 아니라서 `grid[r][c] === 1`이 거짓이 되고, 범위 밖 칸이 빈 칸으로 취급되어 틀린 답이 나옵니다. 이동 전에 행과 열을 모두 검사합니다.

```js
const dr = [1, -1, 0, 0]
const dc = [0, 0, 1, -1]
for (let d = 0; d < 4; d++) {
  const nr = r + dr[d]
  const nc = c + dc[d]
  if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue
  if (grid[nr][nc] === 1 || visited[nr][nc]) continue
  // 이동
}
```

- `R`은 `grid.length`이고 `C`는 `grid[0].length`입니다. 한 줄 격자에서도 `grid[0]`이 있는지는 입력 파싱에서 확인합니다(자세히는 17편).
- 입력의 행과 열 순서(N × M인지 M × N인지)를 헷갈리면 정사각이 아닌 격자에서만 틀립니다. 정사각 예제만으로는 드러나지 않으므로 N ≠ M인 입력을 반드시 시험합니다.

## 핵심 정리

- 경계 테스트는 제약의 최솟값과 최댓값, 그 바로 안팎에서 풀이를 시험하는 것이고, 예제를 통과해도 경계에서 틀릴 수 있습니다.
- 최소·빈·단일 입력은 비교 대상이 없는 경우를 만듭니다. `[].reduce(f)`는 TypeError, `Math.max()`는 `-Infinity`, `''.split(' ')`는 `['']`입니다.
- 중복·정렬·역정렬·모두 같은 값은 암묵적 가정(값이 서로 다름, 무작위 분포)을 깨서 부등호 처리, 최악 시간, 0으로 나누기 오류를 드러냅니다.
- Number는 2^53 − 1을 넘으면 오류 없이 부정확해지고, 비트 연산과 정수 TypedArray는 32비트로 순환합니다. 합과 곱의 상한을 미리 계산합니다.
- Off-by-one은 포함·제외, 0-index와 1-index, 반복 조건을 정하고 N = 1, 2에서 손으로 따라가 확인합니다.
- 그래프(정점 1개, 간선 0개, 자기 루프, 중복 간선)와 격자(1 × 1, 한 줄, N ≠ M)에는 전용 경계 입력이 있고, 격자는 열 범위 검사 누락이 조용히 틀립니다.
