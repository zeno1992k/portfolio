## 최단거리 개념

최단거리 문제는 그래프에서 두 정점을 잇는 경로 가운데 간선 가중치의 합이 가장 작은 경로를 찾는 문제입니다. 그 합이 거리이고, 간선에 가중치가 없으면 간선 수가 거리입니다. 정점과 간선, 가중치 그래프의 표현은 35편입니다.

문제의 종류는 세 가지입니다.

| 종류 | 구하는 것 | 해당 알고리즘 |
|------|-----------|---------------|
| 단일 쌍 | 정점 s에서 정점 t까지 | 단일 시작점 알고리즘을 쓰고 t에서 멈춘다 |
| 단일 시작점 | 정점 s에서 모든 정점까지 | BFS, Dijkstra, Bellman-Ford |
| 모든 쌍 | 모든 정점 쌍 사이 | Floyd-Warshall(49편) |

가중치의 조건에 따라 알고리즘을 고릅니다.

| 간선 가중치 | 알고리즘 | 시간 |
|-------------|----------|------|
| 모두 같거나 없음 | BFS | O(V + E) |
| 0 또는 1 | 0-1 BFS | O(V + E) |
| 0 이상 | Dijkstra | O((V + E) log V) |
| 음수 포함 | Bellman-Ford(49편) | O(VE) |
| 모든 쌍, 정점 수가 작다 | Floyd-Warshall(49편) | O(V³) |

- 이 문서의 예제는 모두 정점이 0부터 번호가 매겨진 다음 그래프(방향 그래프)를 씁니다. 형식은 `[출발, 도착, 가중치]`입니다.

```js
// 0→1(4)  0→2(1)  2→1(2)  1→3(1)  2→3(5)  3→4(3)
const edges = [
  [0, 1, 4], [0, 2, 1], [2, 1, 2],
  [1, 3, 1], [2, 3, 5], [3, 4, 3],
]
const adj = Array.from({ length: 5 }, () => [])
for (const [u, v, w] of edges) adj[u].push([v, w])
// 무방향이면 adj[v].push([u, w])도 추가
```

- 0번에서 각 정점까지의 최단거리는 `[0, 3, 1, 4, 7]`입니다.
- 도달할 수 없는 정점의 거리는 무한대로 둡니다. JavaScript에서는 `Infinity`를 쓰면 `Infinity + w`도 `Infinity`이고 어떤 유한한 값과 비교해도 더 크므로 별도 처리가 필요 없습니다(INF 값 설계는 50편).
- 최단 경로는 하나가 아닐 수 있습니다. 거리는 유일하지만 경로는 여럿일 수 있어서, 경로를 출력하는 문제는 어느 경로를 낼지 조건이 따로 붙습니다.
- 음수 사이클(합이 음수인 순환)이 있으면 같은 순환을 돌수록 거리가 줄어서 최단거리가 정의되지 않습니다(49편).

**시험에서 묻는 방식:** 간선 조건(가중치 유무, 음수 여부)을 주고 쓸 알고리즘과 시간복잡도를 묻거나, 작은 그래프에서 정점을 확정하는 순서와 최종 거리를 묻습니다.

## BFS 최단거리

간선에 가중치가 없는 그래프(또는 모든 가중치가 같은 그래프)에서는 BFS가 최단거리를 구합니다. 시작점에서 가까운 정점부터 큐에 넣고 꺼내므로 정점이 처음 발견되는 순간의 거리가 최단거리입니다(자세히는 38편).

```js
function bfsDist(n, adj, src) {      // adj[u]: 이웃 번호들
  const dist = new Array(n).fill(-1)     // -1: 아직 방문 안 함
  const q = [src]
  dist[src] = 0
  for (let h = 0; h < q.length; h++) {   // head 인덱스 큐
    const u = q[h]
    for (const v of adj[u]) {
      if (dist[v] !== -1) continue
      dist[v] = dist[u] + 1
      q.push(v)
    }
  }
  return dist
}
```

- 정점마다 한 번만 큐에 들어가므로 시간은 O(V + E)입니다. 큐에서 `shift`를 쓰지 않고 head 인덱스를 움직입니다(자세히는 20편).
- 처음 발견할 때 거리가 확정되는 이유는 큐 안의 정점이 항상 거리 순서로 정렬되어 있기 때문입니다.
- 가중치가 모두 같은 값 c면 BFS 결과에 c를 곱하면 됩니다.

가중치가 서로 다르면 BFS는 틀립니다. 앞의 그래프에서 0번에서 3번까지 간선 수가 가장 적은 경로는 `0→2→3`(간선 2개)이지만 가중치 합은 6이고, `0→2→1→3`은 간선 3개에 합이 4입니다. BFS는 간선 수가 적은 앞의 경로를 먼저 찾아 거리 6을 답으로 냅니다.

**흔한 실수:** 가중치가 있는 문제에 BFS를 쓰는 것입니다. 간선 수가 아니라 가중치 합이 거리일 때는 Dijkstra를 씁니다.

## Dijkstra

Dijkstra 알고리즘은 시작점에서 가장 가까운 정점부터 거리를 하나씩 확정해 나가는 단일 시작점 최단거리 알고리즘입니다. 모든 간선 가중치가 0 이상이어야 합니다. 방법은 다음과 같습니다.

1. 시작점의 거리는 0, 나머지는 무한대로 둔다.
2. 아직 확정하지 않은 정점 가운데 거리가 가장 작은 정점 u를 고른다. 이 거리가 u의 최단거리로 확정된다.
3. u에서 나가는 간선으로 이웃 정점의 거리를 줄일 수 있는지 본다(거리 갱신).
4. 확정하지 않은 정점이 없거나 남은 정점이 모두 무한대일 때까지 2–3을 반복한다.

정당성은 이렇습니다. 가장 작은 거리를 가진 미확정 정점 u에 이르는 다른 경로가 있다면, 그 경로는 어떤 미확정 정점을 거쳐 오는데 그 정점의 거리가 이미 u 이상이고 이후 간선은 0 이상을 더하므로 u의 현재 거리보다 짧아질 수 없습니다. 음수 간선이 있으면 이 논리가 깨집니다.

음수 간선 예: 간선 `0→1(2)`, `0→2(3)`, `2→1(-2)`에서 0번에서 출발하면 가장 가까운 1번이 거리 2로 먼저 확정됩니다. 실제 최단거리는 `0→2→1`의 3 + (-2) = 1인데 이미 확정된 값은 고치지 않아 틀립니다.

가장 단순한 구현은 매번 미확정 정점을 전부 훑어 최솟값을 찾는 방식입니다.

```js
function dijkstraArr(n, adj, src) {
  const dist = new Array(n).fill(Infinity)
  const done = new Array(n).fill(false)
  dist[src] = 0
  for (let it = 0; it < n; it++) {
    let u = -1
    for (let i = 0; i < n; i++)          // 미확정 중 최소 거리
      if (!done[i] && (u < 0 || dist[i] < dist[u])) u = i
    if (dist[u] === Infinity) break      // 남은 정점은 도달 불가
    done[u] = true
    for (const [v, w] of adj[u])
      if (dist[u] + w < dist[v]) dist[v] = dist[u] + w
  }
  return dist
}
```

앞의 그래프에서 0번을 시작점으로 한 진행입니다. 열은 정점 0, 1, 2, 3, 4의 현재 거리입니다.

| 확정한 정점 | 거리 배열 | 처리 |
|-------------|-----------|------|
| (시작) | `[0, ∞, ∞, ∞, ∞]` | - |
| 0 (거리 0) | `[0, 4, 1, ∞, ∞]` | 1과 2를 갱신 |
| 2 (거리 1) | `[0, 3, 1, 6, ∞]` | 1을 4에서 3으로 줄이고 3을 6으로 갱신 |
| 1 (거리 3) | `[0, 3, 1, 4, ∞]` | 3을 6에서 4로 줄임 |
| 3 (거리 4) | `[0, 3, 1, 4, 7]` | 4를 7로 갱신 |
| 4 (거리 7) | `[0, 3, 1, 4, 7]` | 나가는 간선 없음 |

- 정점 n개를 확정하는 반복이 n번이고 매번 O(n)으로 최솟값을 찾아서 O(V²)입니다(간선 처리 O(E)는 V² 안에 들어갑니다).
- 정점이 수천 개 이하이고 간선이 많은 밀집 그래프에서는 이 방식이 힙 방식보다 단순하고 빠를 수 있습니다.
- 정점이 많고 간선이 적은 희소 그래프는 아래의 우선순위 큐 방식을 씁니다.

**흔한 실수:** 음수 간선이 하나라도 있는데 Dijkstra를 쓰는 것입니다. 간선 가중치의 범위를 먼저 확인합니다.

## 거리 갱신

거리 갱신(relaxation, 완화)은 정점 u를 거쳐 v로 가는 경로가 지금까지 알려진 v의 거리보다 짧으면 v의 거리를 고치는 연산입니다.

```js
if (dist[u] + w < dist[v]) {
  dist[v] = dist[u] + w
}
```

- 이 연산이 최단거리 알고리즘의 공통 핵심입니다. Dijkstra, Bellman-Ford, Floyd-Warshall(49편)은 갱신하는 순서와 횟수만 다릅니다.
- `dist[v]`는 시작점에서 v까지 지금까지 찾은 가장 짧은 경로의 길이, 곧 최단거리의 상한입니다. 갱신할 때마다 줄어들기만 하고 실제 최단거리 아래로는 내려가지 않습니다.
- Dijkstra는 정점 u를 확정하는 순간 u의 거리가 이미 최단거리이므로, u에서 나가는 간선을 한 번씩만 갱신하면 충분합니다.
- 부등호는 `<`입니다. 같은 거리일 때는 갱신하지 않아서 처음 찾은 경로를 유지하고 불필요한 큐 삽입도 막습니다.
- 병렬 간선(같은 두 정점 사이 간선이 여러 개)과 자기 자신으로 가는 간선은 별도 처리 없이 갱신 조건이 알아서 걸러 냅니다.
- 시작점에서 도달하지 못한 정점 u의 `dist[u]`는 `Infinity`이므로 `Infinity + w < dist[v]`는 항상 거짓이 되어 갱신되지 않습니다. 정수형 배열(`Int32Array`)에 큰 수로 INF를 두면 `INF + w`가 넘칠 수 있어서 `Infinity`가 안전합니다(자세히는 50편).

**흔한 실수:**

- 갱신 조건을 `dist[u] + w <= dist[v]`로 쓰는 것입니다. 같은 값에서도 다시 큐에 넣어 불필요한 작업이 늘고, 경로 복원에서는 마지막으로 본 경로가 덮어씁니다.
- `dist[u]`가 `Infinity`인 정점에서 간선을 갱신하는 것입니다. 위 이유로 값은 안전하지만 불필요한 반복입니다.

## Priority Queue Dijkstra

매번 최솟값을 찾는 O(V) 반복을 우선순위 큐(힙)로 바꾸면 O(log V)가 됩니다. 큐에는 `[거리, 정점]` 쌍을 넣고 거리가 작은 쌍부터 꺼냅니다. 47편의 `Heap` 클래스에 거리 기준 비교 함수를 씁니다.

```js
function dijkstra(n, adj, src) {
  const dist = new Array(n).fill(Infinity)
  const pq = new Heap((a, b) => a[0] - b[0])   // [거리, 정점]
  dist[src] = 0; pq.push([0, src])
  while (pq.size) {
    const [d, u] = pq.pop()
    if (d > dist[u]) continue          // 낡은 항목은 건너뜀
    for (const [v, w] of adj[u]) {
      if (d + w >= dist[v]) continue   // 줄지 않으면 무시
      dist[v] = d + w
      pq.push([dist[v], v])            // 줄어든 거리로 새로 넣음
    }
  }
  return dist
}
```

- 힙에는 거리를 줄이는 연산(decrease-key)이 없어서, 거리가 줄어들 때마다 새 쌍을 넣고 옛 쌍은 그대로 둡니다. 한 정점이 큐에 여러 번 들어 있을 수 있습니다.
- 꺼낸 쌍의 `d`가 `dist[u]`보다 크면 이미 더 짧은 거리로 처리한 정점의 옛 항목이라서 버립니다(지연 삭제, 47편). 이 검사가 없으면 같은 정점의 간선을 여러 번 처리해 느려집니다.
- 진행은 앞의 표와 같고, 큐에서는 `[4,1]`(옛 항목)과 `[6,3]`(옛 항목)이 나올 때 건너뜁니다.
- 갱신에 성공할 때만 push하고 성공은 간선당 최대 한 번이라서 큐에 들어가는 쌍은 최대 E개, 시간은 O((V + E) log V)입니다. 희소 그래프에서는 배열 방식(O(V²))보다 훨씬 빠릅니다.
- 시작점에서 목적지 하나까지만 필요하면 목적지를 꺼내는 순간 `return`합니다. 그 시점에 목적지의 거리가 확정되기 때문입니다.
- 풀이 형식에 맞춰 감쌉니다. 정점이 1부터 번호 매겨지면 `adj`를 `n + 1`개로 만들거나 입력에서 1을 뺍니다.

```js
// 백준식: 첫 줄 N M, 다음 M줄 u v w (1부터), 마지막 줄 시작점
const fs = require('fs')
const t = fs.readFileSync(0, 'utf8').trim().split(/\s+/)
let p = 0
const n = +t[p++], m = +t[p++]
const adj = Array.from({ length: n + 1 }, () => [])
for (let i = 0; i < m; i++) {
  const u = +t[p++], v = +t[p++], w = +t[p++]
  adj[u].push([v, w])
}
const dist = dijkstra(n + 1, adj, +t[p]).slice(1)
const r = dist.map((d) => d < Infinity ? d : 'INF')
console.log(r.join('
'))
```

- 입력을 한 번에 읽고 출력을 모아서 한 번에 내보냅니다(자세히는 08편). 도달 불가를 어떻게 출력할지는 문제가 정합니다.

**흔한 실수:**

- 큐에서 꺼낸 정점이 이미 처리됐는지 검사하지 않는 것입니다. 정답은 나오지만 정점이 여러 번 처리되어 시간 초과가 날 수 있습니다.
- 비교 함수에서 `a[0] - b[0]`을 `a[1] - b[1]`로 잘못 쓰는 것입니다. 정점 번호 기준으로 꺼내면 힙이 최단거리 순서를 보장하지 못합니다.
- 큐에 정점만 넣고 거리를 `dist`에서 읽는 것입니다. 큐 안에 있는 동안 `dist`가 바뀌어 정렬 기준이 달라지므로 힙 성질이 깨집니다. 넣는 시점의 거리를 쌍으로 함께 넣습니다.

## 경로 복원

최단거리뿐 아니라 실제 경로가 필요하면 각 정점이 어느 정점에서 와서 거리가 정해졌는지 `prev` 배열에 기록합니다. 거리 갱신에 성공할 때 `prev[v] = u`를 함께 적습니다.

```js
// dijkstra에 prev만 추가 (나머지는 앞의 코드와 같음)
const prev = new Array(n).fill(-1)     // -1: 이전 정점 없음
// ...
if (d + w < dist[v]) {
  dist[v] = d + w
  prev[v] = u                          // v는 u에서 왔다
  pq.push([dist[v], v])
}
```

목적지에서 `prev`를 따라 시작점까지 거슬러 올라간 뒤 뒤집습니다.

```js
function pathTo(prev, src, t) {
  const path = []
  for (let v = t; v !== -1; v = prev[v]) path.push(v)
  path.reverse()
  return path[0] === src ? path : []   // 도달 불가면 빈 배열
}
// 앞의 그래프: prev는 [-1, 2, 0, 1, 3]
pathTo(prev, 0, 4) // [0, 2, 1, 3, 4]
```

- `prev`는 정점마다 하나씩이라서 경로가 트리를 이룹니다(최단 경로 트리). 모든 정점까지의 경로가 한 배열에 담깁니다.
- 거슬러 올라가는 데는 경로 길이만큼, 최대 V번 걸립니다.
- 도달할 수 없는 정점은 `prev`를 따라가도 시작점에 닿지 않으므로 `path[0] === src` 검사로 가려냅니다. 시작점 자신은 `[src]`입니다.
- 갱신 조건이 `<`라서 거리가 같은 경로가 여럿이면 먼저 발견한 경로가 남습니다. "사전순으로 가장 앞선 경로" 같은 조건이 있으면 같은 거리일 때 비교 규칙을 따로 넣어야 합니다.
- 거리가 같은 최단 경로의 개수는 `cnt[v]`를 두고, 더 짧은 경로를 찾으면 `cnt[v] = cnt[u]`, 같은 거리면 `cnt[v] += cnt[u]`로 셉니다. 개수가 크면 나머지를 취합니다(자세히는 57편).
- 경로 대신 "그 경로에 포함된 간선이나 정점"만 필요하면 도착점에서 `prev`를 따라가며 표시합니다.

**흔한 실수:**

- `prev`를 거리가 같을 때도 갱신해서 경로가 마지막 후보로 덮이는 것입니다. 갱신 조건과 같은 시점에만 기록합니다.
- 경로를 시작점에서 목적지 방향으로 만들 수 있다고 생각하는 것입니다. `prev`는 거슬러 올라가는 방향이라서 뒤집어야 합니다.

## 다중 시작점 Dijkstra

시작점이 여러 개이고 "가장 가까운 시작점까지의 거리"가 필요하면, 모든 시작점의 거리를 0으로 놓고 한꺼번에 큐에 넣고 시작합니다. 한 번의 실행으로 모든 정점의 가장 가까운 시작점까지의 거리가 나옵니다. 가상의 정점을 만들어 모든 시작점으로 가는 가중치 0 간선을 두는 것과 같습니다.

```js
// dijkstra와 다른 부분은 초기화뿐이다
const pq = new Heap((a, b) => a[0] - b[0])
for (const s of sources) {
  dist[s] = 0
  pq.push([0, s])                    // 모든 시작점을 넣고 출발
}
// 이후 while (pq.size) 반복은 단일 시작점과 같다
```

- 앞의 그래프에서 시작점이 0과 3이면 거리 배열은 `[0, 3, 1, 0, 3]`입니다. 4번은 3번에서 가는 거리 3입니다.
- 시간은 단일 시작점과 같은 O((V + E) log V)입니다. 시작점마다 따로 실행하면 시작점 수만큼 곱해져서 느립니다.
- 어느 시작점에서 왔는지 알고 싶으면 큐 항목에 `origin`을 함께 담거나, 거리 갱신 때 `origin[v] = origin[u]`로 전달합니다.
- "모든 정점에서 목적지 하나까지의 최단거리"는 방향을 뒤집은 그래프에서 목적지를 시작점으로 한 번 실행하면 됩니다(역방향 그래프는 37편).
- BFS도 같은 방식으로 여러 시작점을 큐에 넣고 시작합니다(다중 시작점 BFS는 38편).

**흔한 실수:** 시작점마다 Dijkstra를 따로 돌린 뒤 최솟값을 취하는 것입니다. 시작점이 많으면 시간 초과가 납니다. 한 번에 합쳐서 돌립니다.

## 특정 정점 경유 최단거리

"시작점 s에서 출발해 정점 a와 b를 모두 지나 t에 도착하는 최단거리"는 경유 순서마다 구간으로 나눠서 구간별 최단거리를 더합니다. 순서가 정해져 있으면 `s→a→b→t`이고, 순서가 자유면 `s→b→a→t`도 구해 더 작은 쪽을 고릅니다.

- 필요한 구간 거리는 s, a, b를 시작점으로 한 세 번의 Dijkstra에서 모두 나옵니다.

```js
function viaTwo(n, adj, s, a, b, t) {
  const ds = dijkstra(n, adj, s)
  const da = dijkstra(n, adj, a)
  const db = dijkstra(n, adj, b)
  const ab = ds[a] + da[b] + db[t]     // s → a → b → t
  const ba = ds[b] + db[a] + da[t]     // s → b → a → t
  const ans = Math.min(ab, ba)
  return ans === Infinity ? -1 : ans
}
```

앞의 그래프를 무방향으로 보고 `s = 1`, `t = 2`, 반드시 지나야 하는 정점이 4와 0일 때의 구간 거리입니다.

| 구간 | 거리 |
|------|------|
| 1 → 4 | 4 |
| 4 → 0 | 7 |
| 0 → 2 | 1 |
| 1 → 0 | 3 |
| 0 → 4 | 7 |
| 4 → 2 | 6 |

- 4를 먼저 지나는 경로는 4 + 7 + 1 = 12, 0을 먼저 지나는 경로는 3 + 7 + 6 = 16이라서 답은 12입니다.
- 경유 정점이 k개이고 순서가 자유이면 순서가 k!가지라서 k가 작을 때만 전부 시도할 수 있습니다. 더 크면 방문 집합을 비트마스크로 표현하는 상태 확장을 씁니다(자세히는 50편).
- 같은 정점이나 간선을 두 번 지나는 경로도 허용되는 문제라면 위 방식이 맞습니다. 각 구간이 서로 겹쳐도 괜찮기 때문입니다. 정점을 한 번씩만 지나야 하는 조건이면 최단 경로 문제가 아니라 훨씬 어려운 문제가 됩니다.
- 무방향 그래프에서는 `da[b]`와 `db[a]`가 같습니다. 방향 그래프에서는 구간 방향별로 따로 구한 거리를 씁니다.
- 어느 구간이든 도달할 수 없으면 합이 `Infinity`가 되어 -1로 바꿔 줍니다.

**흔한 실수:**

- `ds[a] + da[b] + db[t]`에서 한 번 구한 `ds`로 `a`에서 `b`까지의 거리를 대신하는 것입니다. 구간의 시작점이 다르면 그 정점을 시작점으로 다시 실행해야 합니다.
- 두 경유 순서 가운데 한쪽만 계산하는 것입니다. 순서가 자유라면 둘 다 구해 최솟값을 취합니다.

## 0-1 BFS vs Dijkstra

간선 가중치가 0 또는 1뿐일 때는 우선순위 큐 없이 덱(deque)으로 O(V + E)에 풀 수 있습니다. 이를 0-1 BFS라고 합니다. 가중치 0 간선으로 이웃을 찾으면 같은 거리이므로 덱의 앞에, 가중치 1 간선이면 거리가 1 늘어나므로 덱의 뒤에 넣습니다. 덱은 항상 거리 순서를 유지합니다(덱은 20편).

덱을 배열 두 개로 흉내 내면 `shift` 비용 없이 쓸 수 있습니다. 앞쪽은 스택(`push`와 `pop`), 뒤쪽은 head 인덱스 큐로 만듭니다.

```js
function bfs01(n, adj, src) {
  const dist = new Array(n).fill(Infinity)
  const front = [src], back = []     // front: 스택, back: 큐
  let head = 0; dist[src] = 0
  while (front.length || head < back.length) {
    const u = front.length ? front.pop() : back[head++]
    for (const [v, w] of adj[u]) {
      if (dist[u] + w >= dist[v]) continue
      dist[v] = dist[u] + w
      if (w === 0) front.push(v)     // 거리 같음: 앞에
      else back.push(v)              // 거리 1 증가: 뒤에
    }
  }
  return dist
}
```

- 격자에서 "벽을 부수면 비용 1, 빈 칸은 0"처럼 이동 비용이 0과 1로 나뉘는 문제가 대표적입니다(격자와 상태 BFS는 39편).
- 정점이 큐에 최대 두 번 들어가고(처음에 1 늘어난 거리로, 이후 0 간선으로 줄어든 거리로) 꺼낼 때 현재 `dist`로 처리하므로 시간은 O(V + E)입니다.

| 항목 | 0-1 BFS | Dijkstra |
|------|---------|----------|
| 간선 가중치 | 0 또는 1 | 0 이상의 임의 값 |
| 자료구조 | 덱 | 우선순위 큐 |
| 시간 | O(V + E) | O((V + E) log V) |
| 구현 | 짧다 | 힙 클래스가 필요하다 |

- 가중치가 0 이상의 작은 정수(최대 k)이면 0-1 BFS를 일반화한 Dial 알고리즘(거리별 k + 1개의 버킷)을 쓸 수 있습니다. 코딩테스트에서는 보통 Dijkstra를 씁니다.
- 가중치가 1과 2처럼 작은 값이어도 0-1 BFS는 못 씁니다. 간선을 쪼개 가중치 1짜리 간선으로 바꾸거나 Dijkstra를 씁니다.
- 가중치가 모두 1이면 일반 BFS(앞 절)가 가장 단순합니다. 1이 아닌 같은 값이어도 마찬가지입니다.
- 0-1 BFS를 쓸 수 있는 문제에 Dijkstra를 써도 정답은 같습니다. 시간 제한이 빠듯하거나 구현을 줄일 때 0-1 BFS가 유리합니다.

**흔한 실수:**

- 가중치 0 간선에도 `back.push`를 해서 거리 순서가 깨지는 것입니다. 0 간선은 반드시 앞에 넣습니다.
- 한 정점의 거리가 두 번 줄어드는 경우를 놓치고 방문 표시를 하는 것입니다. Dijkstra처럼 거리가 줄어들 때만 갱신하고, 방문 여부 배열로 처음 도착을 막지 않습니다.

## 핵심 정리

- 최단거리는 간선 가중치 조건으로 알고리즘을 고릅니다. 가중치가 없으면 BFS, 0 또는 1이면 0-1 BFS, 0 이상이면 Dijkstra, 음수가 있으면 Bellman-Ford입니다.
- Dijkstra는 확정하지 않은 정점 중 거리가 가장 작은 정점을 확정하고 그 정점에서 이웃의 거리를 갱신하며, 음수 간선이 있으면 정당성이 깨집니다.
- 거리 갱신은 `dist[u] + w < dist[v]`일 때 `dist[v]`를 고치는 연산이며, 미도달 거리는 `Infinity`로 둡니다.
- 우선순위 큐 구현은 `[거리, 정점]`을 넣고 꺼낸 거리가 `dist`보다 크면 건너뛰어 O((V + E) log V)에 동작하고, 배열 구현은 O(V²)입니다.
- 경로는 갱신 때 `prev[v] = u`를 기록하고 목적지에서 거슬러 올라가 뒤집어 복원합니다.
- 시작점이 여럿이면 모두 거리 0으로 넣고 한 번에 실행하고, 경유 정점은 시작점·경유점마다 Dijkstra를 돌려 구간 거리를 더하며, 가중치가 0과 1뿐이면 덱을 쓰는 0-1 BFS가 O(V + E)입니다.
