## Bitmask DP

Bitmask DP는 DP의 상태로 "원소의 부분집합"을 쓰고, 그 부분집합을 정수 하나(비트마스크)로 표현하는 방법입니다. 원소가 n개이면 상태가 2^n개라서 n이 20 안팎일 때 씁니다. 비트 연산 규칙은 24편, DP의 기본 틀은 40편에서 다룹니다.

대표 유형은 작업 배정입니다. 사람 n명에게 일 n개를 하나씩 맡길 때 비용 합을 최소로 만듭니다. 사람을 0번부터 차례로 배정한다고 정하면, 지금까지 쓴 일의 집합만 알아도 다음에 배정할 사람은 `popcount(mask)`번으로 정해집니다.

- 상태: `dp[mask]` = 일 집합 `mask`를 앞사람들이 맡았을 때의 최소 비용
- 전이: 아직 안 쓴 일 `t`를 다음 사람 `w`가 맡는다. `dp[mask | (1 << t)] = min(그 값, dp[mask] + cost[w][t])`
- 시작: `dp[0] = 0`, 답: `dp[전체 집합]`

켜진 비트 개수 `pop`은 24편의 방법을 씁니다.

```js
function pop(x) { // 켜진 비트 개수
  let c = 0
  for (; x; x &= x - 1) c++
  return c
}
```

```js
function minAssign(cost) {
  const n = cost.length
  const dp = new Array(1 << n).fill(Infinity)
  dp[0] = 0
  for (let mask = 0; mask < (1 << n) - 1; mask++) {
    const w = pop(mask) // 다음에 배정할 사람
    for (let t = 0; t < n; t++) {
      if ((mask >> t) & 1) continue
      const nm = mask | (1 << t)
      dp[nm] = Math.min(dp[nm], dp[mask] + cost[w][t])
    }
  }
  return dp[(1 << n) - 1]
}
```

`cost = [[9,2,7],[6,4,3],[5,8,1]]`이면 답은 9입니다(사람 0이 일 1에 2, 사람 1이 일 0에 6, 사람 2가 일 2에 1). 마스크 오름차순으로 채운 `dp`는 다음과 같습니다.

| mask(2진) | 000 | 001 | 010 | 011 | 100 | 101 | 110 | 111 |
|-----------|-----|-----|-----|-----|-----|-----|-----|-----|
| `dp[mask]` | 0 | 9 | 2 | 8 | 7 | 12 | 5 | 9 |

- `dp[011]`은 일 0과 일 1을 사람 0과 1이 나눠 맡은 경우입니다. 사람 0이 일 1(2), 사람 1이 일 0(6)이면 8이고, 사람 0이 일 0(9), 사람 1이 일 1(4)이면 13이라서 8이 남습니다.
- 마스크 오름차순으로 돌려도 되는 이유: 전이는 항상 비트를 하나 켜므로 `nm > mask`입니다. `dp[mask]`를 읽는 시점에는 그보다 작은 마스크에서 오는 전이가 모두 끝나 있습니다.
- 시간은 O(2^n · n), 공간은 O(2^n)입니다. 브루트포스 n!보다 훨씬 작습니다(n = 20이면 약 2 × 10^7 대 2 × 10^18).
- 값 배열이 클 때는 `Int32Array`가 메모리를 덜 씁니다. 다만 `Infinity`를 담을 수 없어서 `1e9` 같은 큰 값으로 대신하고, 더할 때 32비트를 넘지 않는지 확인합니다.
- 비트 연산은 32비트 정수에서만 정확하므로 n이 30을 넘는 문제에는 쓸 수 없습니다(자세히는 24편).

**문제의 단서:** n ≤ 20 안팎, "모든 ~를 정확히 한 번씩", "부분집합마다 최적값". 상태가 "무엇을 이미 썼는가"로 요약될 때입니다.

**흔한 실수:** `1 << n`을 n이 31 이상일 때 쓰는 것, `mask & (1 << t) === 0`처럼 비교를 괄호 없이 쓰는 것입니다. `===`가 `&`보다 먼저 계산되어 의도와 다른 값이 나옵니다. 비트 검사는 `((mask >> t) & 1) === 0`처럼 괄호로 묶습니다.

## 외판원 순회(TSP)

외판원 순회(TSP, traveling salesman problem)는 모든 도시를 한 번씩 방문하고 출발 도시로 돌아오는 최소 비용 경로를 구하는 문제입니다. 모든 순서를 시도하면 n!이고, Bitmask DP로 풀면 O(n^2 · 2^n)입니다. 이 방법을 Held-Karp 알고리즘이라 하며 1962년에 Bellman과 Held·Karp가 각각 제안했습니다.

경로는 출발 도시를 고정해도 일반성을 잃지 않으므로 0번에서 시작합니다. 같은 집합을 방문했어도 마지막 도시에 따라 이어갈 비용이 달라서, 상태에 마지막 도시가 하나 더 필요합니다.

- 상태: `dp[mask][last]` = 0번에서 출발해 `mask`의 도시를 모두 방문하고 `last`에 있는 최소 비용
- 전이: 아직 안 간 도시 `k`로 이동한다. `dp[mask | (1 << k)][k] = min(그 값, dp[mask][last] + d[last][k])`
- 시작: `dp[{0}][0] = 0`, 답: `min(dp[전체][last] + d[last][0])`

```js
function tsp(d) {
  const n = d.length, INF = 1e9
  const dp = new Int32Array((1 << n) * n).fill(INF)
  dp[1 * n + 0] = 0 // mask = {0}, last = 0
  for (let m = 1; m < 1 << n; m += 2) { // 0번 포함 마스크만
    for (let l = 0; l < n; l++) {
      const cur = dp[m * n + l]
      if (cur >= INF) continue
      for (let k = 1; k < n; k++) {
        if ((m >> k) & 1) continue
        const i = (m | (1 << k)) * n + k
        dp[i] = Math.min(dp[i], cur + d[l][k])
      }
    }
  }
```

위 블록 다음에 돌아오는 비용을 더해 답을 고릅니다.

```js
  const full = (1 << n) - 1
  let ans = INF
  for (let l = 1; l < n; l++)
    ans = Math.min(ans, dp[full * n + l] + d[l][0])
  return ans
}
// 아래 예제의 d로 tsp(d)는 80
```

`d = [[0,10,15,20],[10,0,35,25],[15,35,0,30],[20,25,30,0]]`이면 최적 경로는 0 → 1 → 3 → 2 → 0이고 비용은 10 + 25 + 30 + 15 = 80입니다. 상태가 이렇게 자랍니다.

| 상태 | 의미 | 값 |
|------|------|----|
| `dp[{0,1}][1]` | 0 → 1 | 10 |
| `dp[{0,1,3}][3]` | 0 → 1 → 3 | 35 |
| `dp[{0,1,2,3}][2]` | 0 → 1 → 3 → 2 | 65 |
| 닫기 | 65 + `d[2][0]` | 80 |

- 시간은 상태 2^n · n개에 전이 n개를 곱한 O(n^2 · 2^n)입니다. 공간은 O(n · 2^n)입니다.
- n = 20이면 `Int32Array`가 2^20 × 20 × 4바이트로 약 84MB입니다. 메모리 제한이 빠듯하면 0번을 빼고 n − 1개로 마스크를 만들어 절반으로 줄입니다.
- 간선이 없는 쌍은 `d`에 큰 값을 넣어 두고, 합이 32비트를 넘지 않게 `INF`를 정합니다. 위 코드는 `cur >= INF`로 도달 불가 상태를 건너뜁니다.
- 출발 도시로 돌아오지 않는 경로(해밀턴 경로)는 마지막 닫기 단계만 빼고 `min(dp[전체][last])`를 답으로 합니다.
- 방문 순서를 구하려면 각 상태에 직전 도시를 저장해 거꾸로 따라갑니다.

**문제의 단서:** "모든 도시(정점)를 정확히 한 번씩 방문", n ≤ 16–20. 모든 정점을 방문하는 최단 거리를 BFS로 푸는 방식은 간선 가중치가 같을 때만 됩니다(자세히는 39편).

**흔한 실수:** 상태에서 마지막 도시를 빼는 것입니다. 집합만으로는 다음 이동 비용을 알 수 없어서 값이 틀립니다. 시작 상태를 `dp[0][0]`으로 잡아 0번이 마스크에 포함되지 않는 것도 자주 합니다.

## Profile DP 개요

Profile DP는 격자를 칸 단위로 채워 가면서, "처리한 부분과 처리하지 않은 부분의 경계"를 비트마스크로 기억하는 DP입니다. 격자 한 변이 작을 때(보통 열 수 M이 10 안팎, 많아야 20 정도) 도미노 타일링 같은 "겹치지 않게 빈틈없이 채우는 경우의 수"를 셉니다. 개요만 다루며 변형은 많습니다.

도미노 타일링은 N × M 격자를 2 × 1 도미노로 빈틈없이 덮는 방법의 수입니다. 칸을 행 우선 순서로 보며 비트마스크 M비트를 경계로 씁니다.

- 현재 칸이 `(r, c)`일 때, 비트 `c` 미만은 다음 행의 칸이 이미 채워졌는지, 비트 `c` 이상은 현재 행의 칸이 이미 채워졌는지를 나타낸다.
- 현재 칸이 이미 채워져 있으면 비트를 끄고 넘어간다.
- 비어 있으면 아래로 세워 넣거나(다음 행 비트 켜기), 오른쪽 칸이 비어 있을 때 가로로 넣는다(오른쪽 비트 켜기).

```js
function step(cur, r, c, N, M) {
  const nxt = new Array(1 << M).fill(0)
  for (let m = 0; m < 1 << M; m++) {
    if (!cur[m]) continue
    if ((m >> c) & 1) nxt[m ^ (1 << c)] += cur[m]
    else {
      if (r + 1 < N) nxt[m | (1 << c)] += cur[m]
      if (c + 1 < M && !((m >> (c + 1)) & 1))
        nxt[m | (1 << (c + 1))] += cur[m]
    }
  }
  return nxt
}
```

```js
function domino(N, M) {
  let cur = new Array(1 << M).fill(0)
  cur[0] = 1
  for (let r = 0; r < N; r++)
    for (let c = 0; c < M; c++) cur = step(cur, r, c, N, M)
  return cur[0] // 모든 칸을 채우고 경계가 비어 있는 상태
}
domino(2, 3) // 3
domino(4, 4) // 36
domino(8, 8) // 12988816
```

- 상태는 (칸 번호, 마스크)이고 칸이 N · M개, 마스크가 2^M개이므로 시간은 O(N · M · 2^M)입니다. 한 칸의 상태만 필요해서 배열 두 개를 번갈아 쓰면 공간은 O(2^M)입니다.
- 행과 열 중 작은 쪽을 M으로 잡도록 전치하면 상태 수가 크게 줄어듭니다.
- 홀수 × 홀수 격자는 칸 수가 홀수라서 도미노로 덮을 수 없고 답은 0입니다(`domino(3, 3)`은 0).
- 경우의 수가 2^53을 넘으면 매 단계 mod를 취합니다. 점화식이 덧셈뿐이라 mod 덧셈이면 충분합니다(자세히는 57편).
- 같은 방식으로 "한 행씩" 채우는 행 단위 전이도 가능하지만, 칸 단위가 전이 수를 줄여 줍니다.

**문제의 단서:** 한 변이 작은 격자(N × M에서 M ≤ 10 안팎), "빈틈없이 채우는 방법의 수", 이웃 칸과의 배치 제약(인접한 칸에 놓지 못함). 위 칸의 영향이 한 행 너비로 요약될 때 씁니다.

**흔한 실수:** 비트가 "현재 행 칸"인지 "다음 행 칸"인지 섞는 것입니다. `c` 미만과 `c` 이상의 의미가 칸을 지나며 바뀐다는 점을 기준으로 전이를 설계합니다.

## Digit DP

Digit DP는 수를 자릿수 단위로 만들어 가며 "0부터 N까지 조건을 만족하는 수의 개수"를 세는 DP입니다. N이 10^18처럼 커서 하나씩 검사할 수 없을 때 씁니다. 상태는 다음과 같습니다.

- `pos`: 지금 정하는 자릿수 (맨 앞자리부터)
- `tight`: 지금까지 정한 앞자리가 N의 앞자리와 같으면 1, 이미 작으면 0. `tight`가 1이면 이번 자릿수는 N의 해당 자릿수까지만 고를 수 있고, 0이면 0부터 9까지 자유롭다.
- 문제별 값: 자릿수 합, 나머지, 마지막 숫자 등 조건을 판정하는 데 필요한 정보

`tight`가 1인 상태에서 N의 자릿수와 같은 숫자를 고르면 `tight`가 유지되고, 더 작은 숫자를 고르면 0이 되어 끝까지 0입니다.

예제는 "0 이상 N 이하 정수 중 자릿수 합이 S인 수의 개수"입니다. 개수가 10^18까지 커질 수 있어서 Number의 안전 범위(2^53)를 넘으므로 BigInt로 셉니다(자세히는 02편). N은 문자열로 받습니다.

```js
function countSum(nStr, S) { // 0..N 중 자릿수 합이 S
  const d = [...nStr].map(Number), memo = new Map()
  function go(pos, sum, tight) {
    if (sum > S) return 0n
    if (pos === d.length) return sum === S ? 1n : 0n
    const key = (pos * 200 + sum) * 2 + tight
    if (memo.has(key)) return memo.get(key)
    let res = 0n
    for (let x = 0; x <= (tight ? d[pos] : 9); x++)
      res += go(pos + 1, sum + x, +(tight && x === d[pos]))
    memo.set(key, res)
    return res
  }
  return go(0, 0, 1)
}
```

`countSum('25', 7)`은 3(7, 16, 25)입니다. 십의 자리로 나눠 따라가면 다음과 같습니다.

| 십의 자리 | `tight` | 일의 자리 조건 | 개수 |
|-----------|---------|----------------|------|
| 0 | 0 | 합이 7이 되려면 7 | 1 |
| 1 | 0 | 합이 7이 되려면 6 | 1 |
| 2 | 1 | 0–5 중 합이 7이 되려면 5 | 1 |

- 상태 수는 자릿수 L, 합 S, `tight` 2가지이고 각 상태에서 숫자 10개를 시도하므로 시간은 O(L · S · 10)입니다. `tight`가 1인 상태는 한 줄기뿐이라 실제로는 더 적습니다.
- 메모에 `key`를 만들 때 `sum`의 최댓값(9 × 자릿수)보다 큰 수를 곱해야 키가 겹치지 않습니다. 위 코드는 합이 200 미만인 범위(19자리 이하)에서 안전합니다.
- 구간 `[L, R]`은 `f(R) - f(L - 1)`로 구합니다. 두 값 모두 BigInt이고 `L - 1`은 `(BigInt(L) - 1n).toString()`으로 만듭니다. 10부터 99 중 자릿수 합이 10인 수는 `countSum('99', 10) - countSum('9', 10)`으로 9개입니다.
- 앞자리 0이 의미가 있는 조건(0의 개수 세기, 서로 다른 숫자만 쓰는 수)은 "아직 수가 시작되지 않았다"를 뜻하는 `started` 상태를 하나 더 둡니다. 앞의 0을 숫자 0으로 세면 틀립니다.
- 반복 구조로 `dp[pos][sum][tight]`를 채워도 같은 결과입니다. 재귀 깊이는 자릿수(최대 19)라서 호출 스택 걱정이 없습니다.

**문제의 단서:** "1부터 N까지의 수 중 ~인 수의 개수"에서 N이 10^9를 넘는 경우, 조건이 자릿수 구성(합, 포함하는 숫자, 인접한 자릿수 관계, 나머지)으로 정해질 때입니다.

**흔한 실수:** `tight` 전이를 틀리는 것입니다. 다음 `tight`는 "현재 `tight`가 1이고 고른 숫자가 상한과 같을 때만" 1입니다. 개수를 Number로 합산해 큰 입력에서 조용히 틀리는 것도 흔합니다.

## Interval DP

Interval DP는 구간 `[l, r]`을 상태로 두고, 구간을 둘로 나누는 지점 `k`를 시도해 큰 구간의 값을 작은 구간으로부터 구하는 DP입니다. 구간의 길이가 짧은 것부터 채웁니다.

대표 유형은 파일 합치기입니다. 일렬로 놓인 파일 n개를 인접한 두 개씩 합칠 때, 합치는 비용이 두 파일 크기의 합이면 전체를 하나로 합치는 최소 비용을 구합니다.

- 상태: `dp[l][r]` = 파일 `l`부터 `r`까지를 하나로 합치는 최소 비용
- 전이: 마지막으로 합치는 지점을 `k`(`l ≤ k < r`)로 놓는다. `dp[l][r] = min(dp[l][k] + dp[k+1][r]) + sum(l..r)`
- 시작: `dp[i][i] = 0`, 답: `dp[0][n-1]`

마지막 합치기는 `[l, k]`로 합친 파일과 `[k+1, r]`로 합친 파일을 합치는 것이라서 비용 `sum(l..r)`이 들어갑니다. 구간 합은 누적합으로 O(1)에 구합니다(자세히는 29편).

```js
function merge(a) {
  const n = a.length, pre = [0]
  for (const x of a) pre.push(pre[pre.length - 1] + x)
  const dp = [...Array(n)].map(() => Array(n).fill(0))
  for (let len = 2; len <= n; len++) {
    for (let l = 0; l + len <= n; l++) {
      const r = l + len - 1
      let best = Infinity
      for (let k = l; k < r; k++)
        best = Math.min(best, dp[l][k] + dp[k + 1][r])
      dp[l][r] = best + pre[r + 1] - pre[l]
    }
  }
  return dp[0][n - 1]
}
```

`merge([40, 30, 30, 50])`은 300입니다. 길이순으로 채우면 이렇습니다.

| 구간 | 길이 | 계산 | `dp` |
|------|------|------|------|
| `[0,1]` | 2 | 40 + 30 | 70 |
| `[1,2]` | 2 | 30 + 30 | 60 |
| `[2,3]` | 2 | 30 + 50 | 80 |
| `[0,2]` | 3 | min(0 + 60, 70 + 0) + 100 | 160 |
| `[1,3]` | 3 | min(0 + 80, 60 + 0) + 110 | 170 |
| `[0,3]` | 4 | min(170, 70 + 80, 160) + 150 | 300 |

- 바깥 반복이 길이여야 합니다. `dp[l][r]`을 계산할 때 필요한 `dp[l][k]`, `dp[k+1][r]`은 모두 더 짧은 구간이라서 이미 채워져 있어야 하기 때문입니다.
- 시간은 구간 O(n^2)개에 분할 지점 O(n)개를 곱한 O(n^3), 공간은 O(n^2)입니다. n이 500 안팎까지 가능합니다.
- 분할 지점이 단조로운 일부 점화식은 Knuth 최적화로 O(n^2)까지 줄입니다(자세히는 74편).
- 같은 틀의 문제: 행렬 곱셈 순서(비용이 `p[l] · p[k+1] · p[r+1]`), 괄호·문자열의 최소 삽입, 풍선 터뜨리기(마지막에 터뜨릴 풍선을 `k`로 놓음). 가운데를 먼저 정하는 "마지막에 무엇을 하는가"로 생각하면 전이가 나옵니다.
- 구간을 하나 줄이는 형태(`dp[l+1][r]`, `dp[l][r-1]`만 보는 전이)도 Interval DP입니다. 분할 지점을 시도하지 않으면 O(n^2)입니다.

**문제의 단서:** 일렬 배열에서 인접한 것끼리 합치거나 제거하고, 합치는 순서에 따라 비용이 달라질 때. n이 수백 이하.

**흔한 실수:** 반복 순서를 `l`부터 바깥에 두어 아직 안 채운 칸을 읽는 것입니다. 길이를 바깥, 시작 위치를 안쪽으로 둡니다. `dp[l][r]`의 초깃값을 0으로 두고 `min`을 취해 전이가 항상 0으로 남는 것도 잦은 실수라서 `Infinity`로 시작합니다.

## 승패 상태 DP와 미니맥스

두 사람이 번갈아 움직이는 게임에서 "현재 차례인 사람이 이기는 상태(승)인가, 지는 상태(패)인가"를 상태마다 구하는 DP입니다. 둘 다 최선을 다한다고 가정하고 마지막으로 움직인 쪽이 이기는 규칙을 기준으로 합니다.

- 어디로 움직여도 상대가 이기는 상태로 가게 되면(또는 움직일 수 없으면) 패입니다.
- 상대가 지는 상태로 갈 수 있는 이동이 하나라도 있으면 승입니다.

예: 돌 n개 더미에서 한 번에 `moves` 중 하나만큼 가져가고, 마지막 돌을 가져가는 쪽이 이깁니다.

```js
function winTable(n, moves) {
  const win = new Array(n + 1).fill(false) // win[0]: 패
  for (let s = 1; s <= n; s++)
    win[s] = moves.some((m) => s >= m && !win[s - m])
  return win
}
winTable(8, [1, 2, 3]) // 0, 4, 8에서 false
```

`moves = [1, 2, 3]`이면 4의 배수에서 패입니다. 어떤 수를 가져가도 상대가 4의 배수를 맞춰 줄 수 있기 때문입니다. `moves = [1, 3, 4]`이면 패인 상태는 0, 2, 7, 9입니다.

- 시간은 O(n · 이동 종류 수)입니다. 상태가 더 복잡하면(남은 돌 두 더미 등) 상태를 키로 한 메모이제이션으로 같은 틀을 씁니다.
- 이동할 때마다 상태가 바뀌어 이전 상태로 돌아오지 않아야 합니다(상태 전이가 방향 있는 비순환 그래프). 같은 상태로 돌아올 수 있는 게임에는 이 DP를 쓸 수 없습니다.

점수가 걸린 게임은 미니맥스(minimax)입니다. 내 차례에는 내 점수를 최대로, 상대 차례에는 내 점수를 최소로 만드는 선택을 합니다. 두 사람 게임에서 상태값을 "현재 차례 사람의 점수에서 상대 점수를 뺀 값"으로 정의하면 네가맥스(negamax) 형태로 한 식이 됩니다. `max(a, b) = -min(-a, -b)`이기 때문입니다.

예: 양 끝에서만 가져갈 수 있는 수열 `a`에서 번갈아 한 개씩 가져갈 때, 선공의 점수 − 후공의 점수의 최댓값.

- 상태: `dp[l][r]` = 구간 `[l, r]`이 남았을 때 현재 차례 사람이 낼 수 있는 점수 차이의 최댓값
- 전이: `dp[l][r] = max(a[l] - dp[l+1][r], a[r] - dp[l][r-1])`

```js
function bestDiff(a) {
  const n = a.length
  const dp = [...Array(n)].map(() => Array(n).fill(0))
  for (let i = 0; i < n; i++) dp[i][i] = a[i]
  for (let len = 2; len <= n; len++)
    for (let l = 0; l + len <= n; l++) {
      const r = l + len - 1
      const take = a[l] - dp[l + 1][r]
      dp[l][r] = Math.max(take, a[r] - dp[l][r - 1])
    }
  return dp[0][n - 1]
}
bestDiff([3, 9, 1, 2]) // 7 (선공 11점, 후공 4점)
```

- 내가 `a[l]`을 가져가면 상대가 남은 `[l+1, r]`에서 낼 수 있는 차이만큼 내 차이가 줄어서 빼고, 상대가 `a[r]`을 가져가는 쪽도 같습니다.
- 선공이 이기는지만 알고 싶으면 `dp[0][n-1] > 0`인지 봅니다.
- 시간은 O(n^2), 구간을 쪼개는 모양이라 Interval DP의 한 종류입니다.
- 상태가 수만 개를 넘어 계산이 막히면 알파-베타 가지치기 같은 탐색 기법이 따로 있지만, 코딩테스트에서는 위처럼 메모이제이션이 가능한 크기로 주어집니다.

**문제의 단서:** "두 사람이 번갈아", "둘 다 최선", "이기는 사람 / 점수 차". 최선이라는 말이 나오면 상대의 응수까지 상태에 포함해 계산합니다.

**흔한 실수:** 상대 차례의 값을 더하는 것입니다. 상대가 얻는 점수는 내 차이에서 빠지므로 빼야 합니다. 승패 DP에서 `win` 초깃값(움직일 수 없는 상태)을 승으로 두는 것도 틀린 방향입니다. 규칙(마지막에 움직이면 승/패)에 맞춰 초깃값을 정합니다.

## 님 게임과 스프라그-그런디 정리 개요

님(Nim) 게임은 돌 더미 여러 개에서 한 번에 한 더미를 골라 1개 이상 가져가고, 마지막 돌을 가져가는 쪽이 이기는 게임입니다. 승패는 더미 크기의 XOR로 정해집니다.

- 모든 더미 크기의 XOR이 0이 아니면 선공이 이깁니다. 0이면 후공이 이깁니다.
- 이유: XOR이 0인 상태에서는 어떤 이동을 해도 XOR이 0이 아니게 되고, XOR이 0이 아닌 상태에서는 XOR을 0으로 만드는 이동이 항상 있습니다. 마지막 상태(전부 0)의 XOR이 0이므로 XOR이 0인 상태가 패입니다.

```js
const nimWin = (p) => p.reduce((x, v) => x ^ v, 0) !== 0
nimWin([3, 4, 5]) // true (3 ^ 4 ^ 5 = 2)
nimWin([1, 2, 3]) // false (1 ^ 2 ^ 3 = 0)
```

`[3, 4, 5]`는 XOR이 2입니다. 3인 더미를 1로 줄이면(`3 ^ 2 = 1`) `1 ^ 4 ^ 5 = 0`이 되어 상대를 패 상태에 넣습니다.

스프라그-그런디 정리(Sprague-Grundy theorem)는 이 결과를 일반화합니다. 두 사람이 번갈아 움직이고, 두 사람이 할 수 있는 이동이 같으며(공정 게임), 마지막에 움직이면 이기고 같은 상태로 돌아오지 않는 모든 게임은 크기가 정해진 님 더미 하나와 같습니다. 그 크기가 그런디 값입니다.

- 그런디 값은 `mex`로 정의합니다. 상태의 그런디 값 = 이동해서 갈 수 있는 상태들의 그런디 값 집합에 없는 가장 작은 음이 아닌 정수입니다. 갈 곳이 없으면 0입니다.
- 그런디 값이 0이면 패, 0이 아니면 승입니다.
- 서로 독립인 게임 여러 개를 동시에 하면(한 번에 한 게임에서만 이동) 전체의 그런디 값은 각 게임 그런디 값의 XOR입니다.

```js
function grundy(n, moves) {
  const g = new Array(n + 1).fill(0)
  for (let s = 1; s <= n; s++) {
    const seen = new Set()
    for (const m of moves) if (s >= m) seen.add(g[s - m])
    let x = 0
    while (seen.has(x)) x++ // mex
    g[s] = x
  }
  return g
}
grundy(12, [1, 3, 4])
// [0, 1, 0, 1, 2, 3, 2, 0, 1, 0, 1, 2, 3]
```

`moves = [1, 3, 4]`일 때 돌 5개의 그런디 값은 3이고 돌 7개는 0입니다. 이 게임 두 판을 동시에 하는데 더미가 5개와 7개이면 `3 ^ 0 = 3`이 0이 아니므로 선공이 이깁니다.

- 한 더미의 이동이 "1개 이상 아무거나"인 게임의 그런디 값은 더미 크기 자체이고, 이것이 님의 승패 규칙입니다.
- 더미 하나를 쪼개는 게임, 격자 위 말 이동처럼 서로 독립인 부분으로 나뉘는 게임에서 쓰입니다. 부분 게임마다 `grundy`를 구하고 XOR합니다.
- 시간은 O(n · 이동 종류 수)(집합 구성 포함)입니다.
- 정리는 마지막에 움직이는 쪽이 이기는 규칙에서 성립합니다. 마지막에 움직이는 쪽이 지는 규칙(misère)은 따로 다뤄야 합니다.

**문제의 단서:** 여러 더미·여러 칸에서 독립적으로 움직이는 게임, "선공이 이기는가", 이동 규칙이 상태에 관계없이 같을 때.

**흔한 실수:** 그런디 값을 이긴다 / 진다로만 합치는 것입니다. 독립 게임의 승패를 OR나 AND로 합치면 틀리고, 그런디 값을 XOR해야 합니다. mex에서 0을 빼먹고 1부터 찾는 것도 잦은 실수입니다.

## 핵심 정리

- Bitmask DP는 집합을 비트마스크로 표현하며 상태가 2^n개이고, n ≤ 20 안팎에서 O(2^n · n)으로 모든 순열·부분집합 문제를 줄입니다.
- TSP는 `dp[mask][last]`로 푸는 Held-Karp 알고리즘이고 시간 O(n^2 · 2^n), 공간 O(n · 2^n)입니다.
- Profile DP는 격자 경계를 마스크로 기억하며 O(N · M · 2^M)이라서 한 변이 작을 때만 가능합니다.
- Digit DP는 `(자릿수, tight, 조건 값)`으로 0부터 N까지의 개수를 세고 구간은 `f(R) - f(L-1)`입니다. 개수가 2^53을 넘으면 BigInt를 씁니다.
- Interval DP는 구간 길이 순으로 `dp[l][r]`를 채우며 O(n^3), 승패 DP는 승 상태를 이동 후 패 상태가 있는 것으로 정의합니다.
- 님 게임은 더미 XOR이 0이 아니면 선공 승이고, 스프라그-그런디 정리는 일반 게임을 mex로 구한 그런디 값의 XOR로 풉니다.
