## SCC

SCC(Strongly Connected Component, 강한 연결 요소)는 방향 그래프에서 **서로 도달할 수 있는 정점끼리 묶은 최대 집합**입니다. 집합 안의 모든 정점 쌍 `u`, `v`에 대해 `u`에서 `v`로, `v`에서 `u`로 가는 방향 경로가 모두 있고, 더 넣을 수 있는 정점이 없습니다.

간선이 `0→1, 1→2, 2→0, 2→3, 3→4, 4→5, 5→3, 5→6`인 7개 정점의 예입니다.

```text
0 → 1 → 2 → 0        {0, 1, 2}: 사이클 하나
        ↓
        3 → 4 → 5 → 3   {3, 4, 5}: 사이클 하나
                ↓
                6          {6}: 혼자
```

- 정점은 정확히 하나의 SCC에 속합니다. SCC는 정점을 분할합니다.
- **방향 사이클 위의 정점은 모두 같은 SCC**입니다. 사이클에 속하지 않는 정점은 혼자서 SCC가 됩니다. 위의 정점 6이 그렇습니다.
- SCC의 개수가 1이면 그래프 전체가 강하게 연결된 그래프입니다.
- 무방향 그래프의 연결 요소와 다릅니다. 방향이 있어서 `u`에서 `v`로 갈 수 있어도 `v`에서 `u`로 못 가면 다른 SCC입니다. 무방향 그래프에서 끊어지는 부분을 찾는 문제는 69편입니다.
- SCC끼리의 간선은 한 방향으로만 이어집니다. 두 방향이 모두 있으면 두 SCC가 합쳐지기 때문입니다. SCC를 한 점으로 줄이면 사이클이 없는 그래프(DAG)가 됩니다(아래 "SCC 압축 그래프").

대표 알고리즘은 둘이고, 모두 O(V + E)입니다(V는 정점 수, E는 간선 수).

| 항목 | Tarjan | Kosaraju |
|------|--------|----------|
| DFS 횟수 | 1번 | 2번(원래 그래프, 뒤집은 그래프) |
| 추가 자료 | 스택, `idx`, `low` | 뒤집은 그래프, 종료 순서 |
| SCC 번호의 방향 | 위상 순서의 역(싱크가 0번) | 위상 순서(소스가 0번) |
| 메모리 | 적음 | 간선을 하나 더 저장 |

**문제의 단서:** "서로 오갈 수 있는 정점끼리 묶는다", "사이클에 속한 정점", "한 정점에서 시작해 모두에 닿으려면 최소 몇 개를 골라야 하는가", "A를 하면 B도 해야 한다"는 형태의 조건이 있는 방향 그래프입니다. 방향 그래프의 사이클 판정은 37편, 사이클이 없는 그래프의 순서는 53편에서 다룹니다.

**흔한 실수:** 무방향 그래프에 SCC 알고리즘을 쓰는 것입니다. 무방향 간선은 양방향 간선과 같아서 모든 연결 요소가 그대로 SCC가 되어 버려, 의미 있는 결과가 아닙니다.

## Tarjan

Tarjan 알고리즘은 **DFS 한 번으로 SCC를 구하는** 방법입니다(Robert Tarjan, 1972). 정점마다 두 값을 기록합니다.

- `idx[v]`: DFS에서 `v`를 처음 방문한 순서(0, 1, 2, ...).
- `low[v]`: `v`에서 DFS 서브트리를 따라가며, 아직 SCC가 정해지지 않은 정점(스택에 있는 정점)으로 향하는 간선을 한 번 쓸 때 닿을 수 있는 **가장 작은 `idx`**.

방문한 정점은 스택에 쌓아 두고, SCC가 확정되면 꺼냅니다. `low[v] === idx[v]`이면 `v`가 자기 서브트리 밖의(더 먼저 방문한) 정점으로 올라갈 수 없다는 뜻이므로 **`v`가 SCC의 루트**입니다. 스택에서 `v`가 나올 때까지 꺼낸 정점들이 하나의 SCC입니다.

간선 `v → w`를 볼 때의 규칙은 셋입니다.

| 간선의 `w` | 의미 | 처리 |
|-----------|------|------|
| 아직 방문하지 않음 | DFS 트리 간선 | `dfs(w)` 후 `low[v] = min(low[v], low[w])` |
| 방문했고 SCC가 미확정(스택에 있음) | `v`와 같은 SCC로 되돌아오는 간선 | `low[v] = min(low[v], idx[w])` |
| 이미 SCC가 확정됨 | 다른 SCC로 가는 간선 | 무시 |

먼저 이해하기 쉬운 재귀 형태입니다. 상태 배열은 다음과 같습니다.

```js
const idx = new Int32Array(n).fill(-1)   // 방문 순서
const low = new Int32Array(n)            // lowlink
const comp = new Int32Array(n).fill(-1)  // SCC 번호
const stack = []                         // SCC가 미확정인 정점
let time = 0, cnt = 0                    // 방문 시각, SCC 개수
```

```js
function dfs(v) {
  idx[v] = low[v] = time++
  stack.push(v)
  for (const w of adj[v]) {
    if (idx[w] === -1) {                 // 트리 간선
      dfs(w); low[v] = Math.min(low[v], low[w])
    } else if (comp[w] === -1) {         // 스택에 있는 정점
      low[v] = Math.min(low[v], idx[w])
    }
  }
  if (low[v] !== idx[v]) return          // 루트가 아님
  let w
  do { w = stack.pop(); comp[w] = cnt } while (w !== v)
  cnt++                        // v까지 꺼낸 것이 하나의 SCC
}
```

`comp[w] === -1`이 "아직 스택에 있다"는 뜻입니다. 방문했지만 `comp`가 정해지지 않았다는 말은 스택에 남아 있다는 말이기 때문입니다.

위의 7개 정점 예를 추적합니다. 방문 순서는 0, 1, 2, 3, 4, 5, 6입니다.

| 정점 | idx | low | 이유 | comp |
|------|-----|-----|------|------|
| 0 | 0 | 0 | 루트 | 2 |
| 1 | 1 | 0 | 2에서 올라온 low | 2 |
| 2 | 2 | 0 | 간선 `2→0`이 스택의 0을 가리킴 | 2 |
| 3 | 3 | 3 | 간선 `5→3`을 거쳐 3 | 1 |
| 4 | 4 | 3 | 5에서 올라온 low | 1 |
| 5 | 5 | 3 | 간선 `5→3`이 스택의 3을 가리킴 | 1 |
| 6 | 6 | 6 | 자기 서브트리 밖으로 못 감 | 0 |

- 정점 6이 먼저 끝나서 `low[6] === idx[6]`이므로 `{6}`이 가장 먼저 SCC 0번이 됩니다. 다음에 3이 끝나며 `{3, 4, 5}`(1번), 마지막에 0이 끝나며 `{0, 1, 2}`(2번)입니다.
- **SCC는 후속 SCC보다 먼저 확정됩니다.** 그래서 SCC 번호는 위상 순서의 역입니다. 간선이 SCC `a`에서 `b`로 가면 `a`의 번호가 더 큽니다.
- 정점마다 한 번씩 방문하고 간선마다 한 번씩 보므로 O(V + E)입니다.

JavaScript에서는 재귀 깊이가 문제입니다. 정점이 수만 개인 체인형 그래프에서 `dfs`는 호출 스택이 넘칩니다(자세히는 86편). 호출 스택을 직접 관리하는 반복형으로 씁니다. 하나의 함수를 네 조각으로 나눠 보이니, 위에서 아래로 이어 붙여 읽습니다.

```js
function tarjan(n, adj) {
  const idx = new Int32Array(n).fill(-1)
  const low = new Int32Array(n)
  const comp = new Int32Array(n).fill(-1)
  const ptr = new Int32Array(n)          // 다음에 볼 간선 위치
  const stack = [], call = []      // SCC 스택, 호출 스택
  let time = 0, cnt = 0
  const lower = (v, x) => { if (x < low[v]) low[v] = x }
  const visit = (v) => {
    idx[v] = low[v] = time++
    stack.push(v); call.push(v)
  }
```

```js
  const popScc = (v) => {          // v가 루트: SCC를 꺼낸다
    let w
    do { w = stack.pop(); comp[w] = cnt } while (w !== v)
    cnt++
  }
```

```js
  const step = (v) => {                  // v의 간선 하나를 처리
    if (ptr[v] < adj[v].length) {
      const w = adj[v][ptr[v]++]
      if (idx[w] === -1) visit(w)
      else if (comp[w] === -1) lower(v, idx[w])
      return
    }
    call.pop()                           // 간선을 모두 봄: dfs의 끝
    if (call.length) lower(call[call.length - 1], low[v])
    if (low[v] === idx[v]) popScc(v)
  }
```

```js
  for (let s = 0; s < n; s++) {
    if (idx[s] !== -1) continue
    visit(s)
    while (call.length) step(call[call.length - 1])
  }
  return { comp, cnt }
}
```

- `step`은 재귀의 "간선 하나 처리"와 "함수 끝"을 나눈 것입니다. `ptr[v]`가 `v`의 인접 리스트에서 어디까지 봤는지를 기억해서, 자식 정점으로 내려갔다가 돌아와도 이어서 봅니다.
- 함수가 끝나는 지점(`call.pop()` 이후)에서 부모의 `low`를 자식의 `low`로 갱신하는 일이 재귀 코드의 `low[v] = min(low[v], low[w])`입니다.
- 반환값 `comp[v]`는 정점 `v`의 SCC 번호이고 `cnt`는 SCC 개수입니다.

백준식 입력(정점 번호는 1부터, 간선은 `u v`로 방향 `u → v`)의 감싸는 코드입니다.

```js
const fs = require('fs')
const data = fs.readFileSync(0, 'utf8').split(/\s+/)
let p = 0
const n = Number(data[p++]), m = Number(data[p++])
const adj = Array.from({ length: n }, () => [])
for (let i = 0; i < m; i++) {
  const u = Number(data[p++]) - 1, v = Number(data[p++]) - 1
  adj[u].push(v)                         // 방향 간선은 한쪽만
}
const { comp, cnt } = tarjan(n, adj)
console.log(cnt)
```

**흔한 실수:**

- 스택에 없는(이미 SCC가 확정된) 정점으로 가는 간선으로 `low`를 낮추는 것입니다. 그 간선은 다른 SCC로 가는 간선이라 무시해야 합니다. `comp[w] === -1` 검사가 그 역할입니다.
- 방향 간선을 양쪽에 넣는 것입니다. `adj[u].push(v)`만 합니다.
- SCC 번호가 `0`부터 위상 순서의 역이라는 사실을 모르고 번호 순서를 순방향으로 가정하는 것입니다.

## Kosaraju

Kosaraju 알고리즘은 **DFS를 두 번 하는** 방법입니다. 원래 그래프에서 DFS의 종료 순서를 구한 뒤, 간선을 뒤집은 그래프에서 종료가 늦은 정점부터 DFS를 돌립니다. 각 DFS가 한 번에 닿는 정점이 하나의 SCC입니다.

1. 원래 그래프에서 DFS를 돌며 정점이 **끝나는(모든 이웃을 처리한) 순서**를 기록한다.
2. 모든 간선의 방향을 뒤집은 그래프를 만든다.
3. 종료 순서가 **늦은 정점부터** 뒤집은 그래프에서 DFS를 시작한다. 아직 SCC가 없는 정점에서 시작해 닿는 정점이 한 SCC다.

왜 맞는지는 종료 시각의 성질에서 나옵니다. SCC `A`에서 SCC `B`로 가는 간선이 있으면 `A`의 정점 중 가장 늦게 끝나는 정점이 `B`의 어떤 정점보다 늦게 끝납니다. 그래서 종료가 가장 늦은 정점은 SCC 압축 그래프의 **소스**(들어오는 간선이 없는 SCC)에 있습니다. 뒤집은 그래프에서 소스 SCC로 들어오는 간선은 원래의 나가는 간선이라 소스 SCC를 벗어나지 못합니다. 그래서 그 DFS는 정확히 그 SCC만 방문하고, 방문한 정점을 빼고 같은 과정을 반복합니다.

1단계의 종료 순서입니다. 재귀를 쓰지 않는 반복형입니다.

```js
function finishOrder(n, adj) {
  const seen = new Uint8Array(n), order = []
  const ptr = new Int32Array(n)
  for (let s = 0; s < n; s++) {
    if (seen[s]) continue
    const st = [s]; seen[s] = 1
    while (st.length) {
      const v = st[st.length - 1]
      const w = adj[v][ptr[v]++]         // 없으면 undefined
      if (w === undefined) { order.push(v); st.pop() }
      else if (!seen[w]) { seen[w] = 1; st.push(w) }
    }
  }
  return order
}
```

2, 3단계입니다. 두 번째 DFS는 정점이 끝나는 순서가 필요 없어서 스택에 넣고 꺼내는 단순한 탐색이면 됩니다.

```js
function reverseGraph(n, adj) {
  const radj = Array.from({ length: n }, () => [])
  for (let u = 0; u < n; u++) {
    for (const v of adj[u]) radj[v].push(u)
  }
  return radj
}
```

```js
function kosaraju(n, adj) {
  const radj = reverseGraph(n, adj)
  const comp = new Int32Array(n).fill(-1)
  let cnt = 0
  for (const s of finishOrder(n, adj).reverse()) {  // 늦은 순
    if (comp[s] !== -1) continue
    const st = [s]; comp[s] = cnt
    while (st.length) for (const w of radj[st.pop()]) {
      if (comp[w] === -1) { comp[w] = cnt; st.push(w) }
    }
    cnt++
  }
  return { comp, cnt }
}
```

7개 정점 예입니다. 정점 0에서 시작하는 첫 DFS의 종료 순서는 `6, 5, 4, 3, 2, 1, 0`입니다. 뒤집은 그래프에서 늦게 끝난 0부터 시작하면 `{0, 1, 2}`(0번), 다음 미배정 정점 3에서 `{3, 4, 5}`(1번), 6에서 `{6}`(2번)이 나옵니다.

- Kosaraju의 SCC 번호는 **위상 순서**입니다. 간선이 SCC `a`에서 `b`로 가면 `a`의 번호가 더 작습니다. Tarjan과 반대입니다.
- 시간은 O(V + E)이고, 뒤집은 그래프를 따로 저장해서 메모리가 간선 수만큼 더 듭니다.
- 문제에서 SCC의 위상 순서가 필요하면 Kosaraju가, 메모리와 코드 길이가 중요하면 Tarjan이 편합니다.

**흔한 실수:**

- 두 번째 DFS를 **종료가 이른 순서**로 돌리는 것입니다. 반드시 늦게 끝난 정점부터입니다. 위 코드는 `.reverse()`로 뒤집습니다.
- 두 번째 DFS를 원래 그래프에서 돌리는 것입니다. 뒤집은 그래프가 아니면 SCC 밖으로 새어 나갑니다.
- 종료 순서를 정점이 **처음 방문된 순서**로 착각하는 것입니다. 이웃을 모두 처리한 뒤에 기록해야 합니다.

## SCC 압축 그래프

SCC 압축 그래프(condensation graph)는 **SCC 하나를 정점 하나로 보고, SCC 사이의 간선만 남긴 그래프**입니다. SCC끼리의 간선은 한 방향으로만 이어지므로 압축 그래프에는 사이클이 없는 DAG가 됩니다. 사이클이 있는 방향 그래프를 사이클 없는 그래프로 바꿔서 DP나 위상 정렬(53편)을 쓸 수 있게 하는 것이 목적입니다.

```js
function condense(n, adj, comp, cnt) {
  const dag = Array.from({ length: cnt }, () => new Set())
  for (let u = 0; u < n; u++) {
    for (const v of adj[u]) {
      if (comp[u] !== comp[v]) dag[comp[u]].add(comp[v])
    }
  }
  return dag.map((s) => [...s])   // dag[c]: c에서 나가는 SCC들
}
```

- 같은 SCC 안의 간선(`comp[u] === comp[v]`)은 버립니다.
- `Set`으로 같은 SCC 사이의 중복 간선을 한 번만 남깁니다. 경로의 개수를 세는 문제는 중복 간선이 개수에 영향을 주므로 문제 조건에 맞춰 처리합니다.
- 위 7개 정점 예의 Tarjan 번호로는 `dag = [[], [0], [1]]`입니다. `{0, 1, 2}` → `{3, 4, 5}` → `{6}`의 한 줄입니다.

**DAG 위의 DP로 풀기.** 정점마다 값이 있을 때 "한 정점에서 출발해 간선을 따라가며 모을 수 있는 값의 합의 최댓값"을 구하는 문제입니다. SCC 안에서는 모든 정점을 돌아 다닐 수 있으므로 SCC의 값을 합쳐 한 정점으로 보고 DAG DP를 돌립니다. Tarjan의 번호는 위상 순서의 역이라 **번호가 작은 SCC부터** 처리하면 나가는 SCC가 항상 먼저 계산돼 있습니다.

```js
const wsum = new Float64Array(cnt)       // SCC별 정점 값의 합
for (let v = 0; v < n; v++) wsum[comp[v]] += val[v]
const best = new Float64Array(cnt)       // best[c]: c에서 출발
for (let c = 0; c < cnt; c++) {          // Tarjan 번호: 싱크부터
  let next = 0
  for (const d of dag[c]) next = Math.max(next, best[d])
  best[c] = wsum[c] + next
}
```

- `next`를 0에서 시작해서 값이 음수인 SCC를 일부러 거치지 않는 선택을 허용합니다. 반드시 끝까지 가야 하는 문제이면 초기값과 싱크 처리를 조건에 맞춥니다.
- Kosaraju의 번호를 쓰면 `c`를 `cnt - 1`부터 0까지 거꾸로 돕니다.

**압축 그래프로 구하는 값들:**

| 질문 | 답 |
|------|----|
| 모든 정점에 닿으려면 필요한 최소 시작 정점 수 | 들어오는 간선이 없는 SCC(소스)의 수 |
| 그래프를 강연결로 만드는 데 필요한 최소 추가 간선 수 | SCC가 하나이면 0, 아니면 소스 수와 싱크 수 중 큰 값 |
| 두 정점 `u`, `v`가 서로 도달 가능한가 | `comp[u] === comp[v]` |
| 한 정점에서 다른 정점으로 도달 가능한가 | 압축 그래프에서의 도달 가능성 |

- 싱크는 나가는 간선이 없는 SCC입니다.
- 소스 수는 `dag`를 만든 뒤 들어오는 간선 수를 세어 구합니다.

**문제의 단서:** "사이클이 있는 방향 그래프에서 DP", "서로 영향을 주는 묶음을 한 단위로 보고 싶다".

## 2-SAT 개요

2-SAT은 **절마다 리터럴이 정확히 두 개인 논리식을 참으로 만드는 불리언 변수의 배정이 있는지 판정하고, 있으면 하나 구하는** 문제입니다. 변수 `x_1 ... x_m`이 참 또는 거짓이고, 리터럴은 `x_i` 또는 `¬x_i`(부정)입니다. 식은 `(a ∨ b)` 형태 절을 `∧`로 이은 것입니다. 절이 세 리터럴 이상이면 효율적인 풀이가 알려져 있지 않지만, 둘이면 SCC로 O(m + 절의 수)에 풀립니다.

`(a ∨ b)`는 "`a`가 거짓이면 `b`가 참이어야 하고, `b`가 거짓이면 `a`가 참이어야 한다"와 같습니다. 이 함의를 간선으로 만든 것이 **함의 그래프**입니다.

- 정점은 `2m`개입니다. 변수 `i`마다 `2i`(참인 리터럴 `x_i`)와 `2i + 1`(거짓인 리터럴 `¬x_i`)입니다.
- 어떤 리터럴 `a`의 부정은 `a ^ 1`(XOR)입니다. 짝수와 홀수 짝을 비트 하나로 뒤집습니다.
- 절 `(a ∨ b)`마다 간선 `(a ^ 1) → b`와 `(b ^ 1) → a`를 넣습니다.

```js
const lit = (i, val) => 2 * i + (val ? 0 : 1)  // 변수 i가 val
function addClause(adj, a, b) {          // 절 (a ∨ b)
  adj[a ^ 1].push(b)                     // a가 거짓이면 b는 참
  adj[b ^ 1].push(a)                     // b가 거짓이면 a는 참
}
```

자주 나오는 조건을 절로 바꾸는 방법입니다.

| 조건 | 절 |
|------|-----|
| `x`는 반드시 참 | `(x ∨ x)` |
| `x`가 참이면 `y`도 참 (`x ⇒ y`) | `(¬x ∨ y)` |
| `x`와 `y` 중 적어도 하나는 참 | `(x ∨ y)` |
| `x`와 `y`를 동시에 참으로 할 수 없음 | `(¬x ∨ ¬y)` |
| `x`와 `y`는 정확히 하나만 참 | `(x ∨ y)`와 `(¬x ∨ ¬y)` |
| `x`와 `y`는 같다 | `(¬x ∨ y)`와 `(x ∨ ¬y)` |

**판정:** 함의 그래프를 SCC로 나눴을 때 어떤 변수에 대해 `x_i`와 `¬x_i`가 **같은 SCC에 있으면** 식을 참으로 만들 수 없습니다. 둘이 서로를 함의하므로 `x_i`가 참이어도 거짓이어도 모순이 생깁니다. 모든 변수에서 두 리터럴이 다른 SCC에 있으면 만족하는 배정이 존재합니다.

**배정 구하기:** 압축 그래프의 위상 순서에서 `x_i`와 `¬x_i` 중 **뒤쪽(싱크에 가까운 쪽)에 있는 리터럴을 참**으로 합니다. 뒤쪽 리터럴을 참으로 하면 그 리터럴이 함의하는 리터럴은 모두 더 뒤쪽에 있어서 이미 참이 됩니다. Tarjan의 번호는 위상 순서의 역이라 **번호가 작은 쪽이 뒤쪽**입니다.

```js
function solve2sat(m, clauses) {   // clauses: [[a, b], ...]
  const adj = Array.from({ length: 2 * m }, () => [])
  for (const [a, b] of clauses) addClause(adj, a, b)
  const { comp } = tarjan(2 * m, adj)
  const value = new Array(m)
  for (let i = 0; i < m; i++) {
    const x = comp[2 * i], y = comp[2 * i + 1]
    if (x === y) return null            // 불가능
    value[i] = x < y                    // 번호가 작은 쪽이 참
  }
  return value                          // value[i]: 변수 i의 값
}
```

예 1. 변수 3개, 절 `(x0 ∨ x1)`, `(¬x0 ∨ x1)`, `(¬x1 ∨ x2)`입니다. 정점은 `0 = x0, 1 = ¬x0, 2 = x1, 3 = ¬x1, 4 = x2, 5 = ¬x2`이고, 간선은 다음과 같습니다.

| 절 | 간선 |
|----|------|
| `(x0 ∨ x1)` | `¬x0 → x1`, `¬x1 → x0` |
| `(¬x0 ∨ x1)` | `x0 → x1`, `¬x1 → ¬x0` |
| `(¬x1 ∨ x2)` | `x1 → x2`, `¬x2 → ¬x1` |

Tarjan의 SCC 번호는 정점 0부터 5까지 `2, 3, 1, 4, 0, 5`입니다. 모든 변수에서 두 리터럴의 번호가 다르고, 번호가 작은 쪽을 참으로 하면 `x0`은 2 < 3이라 참, `x1`은 1 < 4라 참, `x2`는 0 < 5라 참입니다. 세 절 모두 참이 됩니다.

예 2. 절 `(x ∨ x)`와 `(¬x ∨ ¬x)`는 `¬x → x`와 `x → ¬x` 간선을 만들어 `x`와 `¬x`가 같은 SCC에 속하므로 `null`(불가능)을 반환합니다.

- 시간은 간선 수가 절의 두 배라서 O(m + 절의 수)입니다.
- SCC 번호의 방향은 알고리즘마다 반대입니다. Kosaraju의 번호(위상 순서)를 쓰면 부등호가 반대여서 `comp[2 * i] > comp[2 * i + 1]`일 때 참입니다. 코드를 바꿔 쓸 때 가장 많이 틀리는 곳입니다.
- 값이 정해진 변수가 일부 있으면 `(x ∨ x)`나 `(¬x ∨ ¬x)` 절로 넣습니다.
- 변수가 두 선택지 중 하나를 고르는 상황(예: 각 항목을 A쪽 또는 B쪽에 배치)은 항목마다 변수 하나로 모델링하고, 충돌하는 조합을 금지하는 절로 표현합니다.
- 주어진 문제에서 "정확히 k개 선택", "세 가지 중 하나"처럼 두 리터럴만으로 표현되지 않는 조건이 있으면 2-SAT이 아닙니다.

**흔한 실수:**

- 절 하나당 간선을 하나만 넣는 것입니다. `(a ∨ b)`는 `¬a → b`와 `¬b → a` 두 개를 모두 넣어야 합니다.
- 번호 규칙과 부정 연산이 어긋나는 것입니다. 변수마다 `2i`, `2i + 1`을 쓰면 부정은 `^ 1`이고, `i`, `i + m`을 쓰면 부정은 `(x + m) % (2 * m)`입니다. 한 가지로 통일합니다.
- 두 리터럴이 같은 SCC인 변수가 있는지 확인하지 않고 배정을 출력하는 것입니다.

**문제의 단서:** "각 항목에 두 가지 중 하나를 고른다", "A와 B를 동시에 고를 수 없다", "A를 고르면 B도 골라야 한다"가 이어진 조건이고, 만족하는 배치가 있는지 묻습니다.

## 핵심 정리

- SCC는 방향 그래프에서 서로 도달할 수 있는 정점의 최대 집합이며, 정점을 분할하고, SCC끼리의 간선은 한 방향뿐이라 압축하면 DAG가 됩니다.
- Tarjan은 DFS 한 번으로 `idx`와 `low`, 스택을 써서 `low[v] === idx[v]`인 정점을 루트로 SCC를 꺼냅니다. SCC 번호는 위상 순서의 역이고, JavaScript에서는 반복형으로 구현합니다.
- Kosaraju는 원래 그래프에서 종료 순서를 구한 뒤 뒤집은 그래프에서 늦게 끝난 정점부터 DFS하며, SCC 번호가 위상 순서입니다. 둘 다 O(V + E)입니다.
- 압축 그래프는 같은 SCC 안의 간선을 버리고 SCC 사이 간선만 남긴 DAG로, DAG DP, 소스·싱크 개수 계산에 씁니다.
- 2-SAT은 `(a ∨ b)`를 `¬a → b`, `¬b → a` 간선으로 바꾼 함의 그래프에서 `x`와 `¬x`가 같은 SCC이면 불가능하고, 아니면 위상 순서에서 뒤쪽 리터럴(Tarjan은 번호가 작은 쪽)을 참으로 배정합니다.
