## Heap 개념

힙(heap)은 부모와 자식 사이에 크기 순서가 정해진 완전 이진 트리입니다. 가장 작은(또는 가장 큰) 값을 항상 루트에 두어서, 그 값을 O(1)에 확인하고 O(log N)에 꺼낼 수 있습니다. 이진 트리와 완전 이진 트리, 배열 표현은 45편에서 다뤘고, 이 문서의 힙은 모두 이진 힙입니다.

힙이 지켜야 할 조건은 두 가지입니다.

- **모양 성질**: 완전 이진 트리다. 마지막 층을 뺀 모든 층이 차 있고, 마지막 층은 왼쪽부터 채워진다.
- **힙 성질**: 모든 노드가 자식과 정해진 방향으로 크기 순서를 지킨다(최소 힙은 부모가 자식보다 작거나 같다).

모양이 완전 이진 트리라서 노드 참조 없이 배열 하나에 담고, 인덱스로 부모와 자식을 계산합니다(0부터 시작).

| 관계 | 인덱스 |
|------|--------|
| 왼쪽 자식 | `2i + 1` |
| 오른쪽 자식 | `2i + 2` |
| 부모 | `(i - 1) >> 1` (또는 `Math.floor((i - 1) / 2)`) |

```js
//        1          배열: [1, 3, 2, 7, 4, 5, 6]
//      /   \
//     3     2
//    / \   / \
//   7   4 5   6
```

- 순서가 정해진 것은 부모와 자식 사이뿐입니다. 형제나 사촌 사이에는 순서가 없어서 위 트리의 3과 2는 어느 쪽이 커도 됩니다. 그래서 힙은 정렬된 상태가 아니고 배열을 앞에서부터 읽어도 정렬 순서가 아닙니다.
- 루트가 최솟값(또는 최댓값)인 것만 보장됩니다. 임의의 값을 찾거나 K번째 값을 바로 꺼내는 것은 지원하지 않습니다.

| 연산 | 시간 |
|------|------|
| 루트 확인(peek) | O(1) |
| 삽입 | O(log N) |
| 루트 삭제(꺼내기) | O(log N) |
| 임의 값 탐색 | O(N) |
| 배열을 힙으로 만들기 | O(N) |

BST(45편)와 헷갈리지 않아야 합니다. BST는 왼쪽이 작고 오른쪽이 크게 정렬되어 값 탐색이 O(h)이고, 힙은 부모와 자식만 순서가 있어서 최솟값·최댓값에만 빠릅니다. 힙은 항상 완전 이진 트리라서 높이가 floor(log2 N)로 고정이고 편향되지 않습니다.

JavaScript에는 표준 힙이 없어서 배열과 함수로 직접 만듭니다. 이 문서의 코드는 값을 `<`와 `>`로 비교하므로 숫자·문자열·BigInt에 바로 쓸 수 있습니다. 객체를 다루는 비교 함수는 47편에서 다룹니다.

**시험에서 묻는 방식:** 배열이 최소 힙인지 판별하게 하거나, 값을 차례로 삽입·삭제한 뒤의 배열 상태를 묻습니다. 정렬된 배열은 항상 힙이지만 힙이 항상 정렬된 것은 아닙니다.

## Min Heap

최소 힙(min heap)은 모든 부모가 자식보다 작거나 같은 힙입니다. 루트가 전체의 최솟값입니다.

```js
const isMinHeap = (a) =>
  a.every((v, i) => i === 0 || a[(i - 1) >> 1] <= v)
isMinHeap([1, 3, 2, 7, 4, 5, 6]) // true
isMinHeap([1, 3, 2, 7, 4, 5, 0]) // false (0의 부모 2가 더 큼)
```

- 모든 원소가 자신의 부모보다 크거나 같은지 확인하면 됩니다.
- 이 문서의 삽입·삭제 코드(아래 절)는 최소 힙 기준입니다. 가장 작은 값을 반복해서 꺼내야 하는 문제(가장 가까운 정점 선택, 작은 값 두 개 합치기)에 씁니다.

## Max Heap

최대 힙(max heap)은 모든 부모가 자식보다 크거나 같은 힙입니다. 루트가 전체의 최댓값입니다.

최소 힙 코드에서 비교 방향만 뒤집으면 최대 힙이 됩니다. 이 방향은 두 곳에 있습니다. 삽입의 부모 비교(`a[p] <= a[i]`가 `a[p] >= a[i]`로)와 삭제의 자식 비교(`<`가 `>`로)입니다. 삭제 쪽을 최대 힙으로 쓴 함수는 이렇습니다.

```js
function siftDownMax(a, i, n) {
  while (true) {
    let m = i
    const l = 2 * i + 1, r = l + 1
    if (l < n && a[l] > a[m]) m = l   // < 가 > 로 바뀜
    if (r < n && a[r] > a[m]) m = r
    if (m === i) break
    ;[a[i], a[m]] = [a[m], a[i]]
    i = m
  }
}
```

숫자만 다룬다면 값에 -1을 곱해 최소 힙에 넣고, 꺼낼 때 다시 -1을 곱하는 방법도 있습니다.

```js
push(h, -v)       // 넣을 때 부호를 뒤집는다
-pop(h)           // 꺼낼 때 다시 뒤집는다
```

- 이 방법은 숫자에서만 됩니다. 문자열이나 `[거리, 정점]` 같은 쌍에는 비교 함수를 받는 형태로 일반화합니다(자세히는 47편).
- 값 0은 `-0`이 됩니다. `-0 === 0`은 `true`라서 비교에는 문제가 없고 `String(-0)`도 `'0'`이지만, `console.log(-0)`은 `-0`으로 찍힙니다.

| 구분 | 최소 힙 | 최대 힙 |
|------|---------|---------|
| 루트 | 최솟값 | 최댓값 |
| 부모와 자식 | 부모 ≤ 자식 | 부모 ≥ 자식 |
| 쓰이는 곳 | 가장 작은 값을 반복해서 꺼낼 때 | 가장 큰 값을 반복해서 꺼낼 때, 힙 정렬(오름차순) |

## Heap 삽입

힙에 값을 넣는 순서는 세 단계입니다.

1. 값을 배열의 맨 끝에 붙인다. 모양 성질(완전 이진 트리)이 유지된다.
2. 그 값이 부모보다 작으면(최소 힙) 부모와 자리를 바꾼다.
3. 부모보다 작지 않거나 루트에 닿을 때까지 2를 반복한다.

```js
function swap(a, i, j) {
  const t = a[i]; a[i] = a[j]; a[j] = t
}
function push(a, v) {
  a.push(v)                  // 1. 끝에 붙인다
  siftUp(a, a.length - 1)    // 2–3. 위로 올린다
}
```

`[5, 3, 8, 1, 4]`를 차례로 삽입하는 과정입니다.

| 삽입 | 처리 | 배열 |
|------|------|------|
| 5 | 루트 | `[5]` |
| 3 | 끝에 붙임, 부모 5보다 작아서 교환 | `[3, 5]` |
| 8 | 끝에 붙임, 부모 3보다 커서 그대로 | `[3, 5, 8]` |
| 1 | 부모 5와 교환, 다시 부모 3과 교환 | `[1, 3, 8, 5]` |
| 4 | 부모 3보다 커서 그대로 | `[1, 3, 8, 5, 4]` |

- 삽입 한 번의 시간은 올라간 층 수에 비례해서 O(log N)입니다. 무작위 값을 넣으면 평균적으로 몇 층 못 올라가서 평균 O(1)에 가깝지만, 최악은 O(log N)입니다.
- 값 N개를 하나씩 넣어 힙을 만들면 O(N log N)입니다. 한꺼번에 만드는 방법은 아래 heapify 절에 있습니다.

## Bubble Up

버블 업(bubble up, sift-up이라고도 부릅니다)은 새 값을 부모와 비교하며 제자리로 올려 보내는 동작입니다. 삽입이 깨뜨릴 수 있는 힙 성질은 새 값과 그 부모 사이뿐이라서 위쪽으로만 고치면 됩니다.

```js
function siftUp(a, i) {
  while (i > 0) {
    const p = (i - 1) >> 1       // 부모 인덱스
    if (a[p] <= a[i]) break      // 이미 조건 만족
    swap(a, p, i)
    i = p                        // 부모 자리에서 다시 비교
  }
}
```

- 교환할 때마다 값이 한 층 올라가므로 최대 층 수, 곧 floor(log2 N)번 반복합니다.
- 교환으로 내려온 옛 부모는 원래 그 아래 모든 값보다 작았으므로 아래쪽은 다시 확인할 필요가 없습니다.
- `a[p] <= a[i]`에서 같은 값이면 멈춥니다. `<`로 쓰면 같은 값끼리 불필요하게 교환해서 올라갑니다.

**흔한 실수:**

- 부모 인덱스를 `i / 2`로 쓰는 것입니다. 0부터 시작하는 배열에서는 `(i - 1) >> 1`입니다. 1부터 시작하는 배열(인덱스 0을 비워 두는 방식)에서는 `i >> 1`이고 자식은 `2i`, `2i + 1`입니다. 한 풀이 안에서 두 방식을 섞으면 안 됩니다.
- `while (i > 0)` 조건 없이 `p`를 계산하면 루트에서 `p`가 `-1 >> 1 = -1`이 되어 `a[-1]`을 읽습니다.

## Heap 삭제

힙에서 삭제는 루트(최솟값)를 꺼내는 것입니다. 중간 노드를 지우는 것이 아닙니다. 순서는 이렇습니다.

1. 루트 값을 기억해 둔다.
2. 배열의 마지막 값을 꺼내 루트 자리에 둔다. 모양 성질(마지막 층 왼쪽부터 채움)이 유지된다.
3. 루트에 올라온 값을 자식과 비교하며 아래로 내려 힙 성질을 복구한다.
4. 기억해 둔 값을 반환한다.

```js
function pop(a) {
  const top = a[0]
  const last = a.pop()                // 마지막 값을 꺼냄
  if (a.length) {
    a[0] = last                       // 루트 자리에 둠
    siftDown(a, 0, a.length)          // 아래로 내림
  }
  return top                          // 빈 힙이면 undefined
}
```

`[1, 3, 8, 5, 4]`에서 루트를 두 번 꺼내는 과정입니다.

| 꺼냄 | 처리 | 배열 |
|------|------|------|
| 1 | 마지막 4가 루트로, 자식 3과 8 중 작은 3과 교환 | `[3, 4, 8, 5]` |
| 3 | 마지막 5가 루트로, 자식 4와 8 중 작은 4와 교환 | `[4, 5, 8]` |

- 마지막 값을 쓰는 이유는 배열의 앞쪽을 건드리지 않고 길이만 하나 줄이기 위해서입니다. 루트 칸을 지우고 `shift`로 당기면 O(N)이 들고 힙 구조도 깨집니다.
- 꺼낸 값을 연속해서 읽으면 오름차순이 됩니다. 이 성질이 힙 정렬의 바탕입니다.
- 값이 하나뿐일 때는 `pop`이 그 값을 꺼낸 뒤 `a.length`가 0이라 아무것도 하지 않습니다.

**흔한 실수:** 빈 힙에서 꺼내는 것입니다. 위 코드는 `undefined`를 반환하므로 호출하는 쪽에서 `size`를 먼저 확인합니다. `if (!top)` 같은 검사는 값 0과 빈 힙을 구분하지 못하므로 길이로 판단합니다.

## Bubble Down

버블 다운(bubble down, sift-down이라고도 부릅니다)은 위에 올라온 값을 자식과 비교하며 제자리로 내려 보내는 동작입니다. 두 자식 중 더 작은 쪽과 비교해서, 그 자식이 더 작으면 교환합니다.

```js
function siftDown(a, i, n) {         // n: 힙의 크기
  while (true) {
    let m = i                        // 부모·자식 셋 중 최소의 인덱스
    const l = 2 * i + 1, r = l + 1
    if (l < n && a[l] < a[m]) m = l
    if (r < n && a[r] < a[m]) m = r
    if (m === i) break               // 이미 조건 만족
    swap(a, i, m)
    i = m                            // 내려간 자리에서 반복
  }
}
```

- 자식이 둘이면 반드시 둘 중 작은 쪽과 바꿉니다. 큰 쪽과 바꾸면 새 부모가 다른 자식보다 커져서 힙 성질이 깨집니다.
- `l < n`, `r < n` 검사가 없으면 존재하지 않는 자식(`undefined`)과 비교합니다. `undefined`와의 비교는 항상 `false`라서 우연히 동작하기도 하지만, 힙 크기를 따로 두는 경우(힙 정렬)에는 범위 밖의 값을 읽어 틀립니다.
- 값이 내려갈 수 있는 층은 최대 floor(log2 N)이므로 O(log N)입니다.
- 크기 n을 인자로 받는 이유는 힙 정렬처럼 배열 일부만 힙으로 보는 경우를 처리하기 위해서입니다.

**흔한 실수:**

- 왼쪽 자식만 확인하고 오른쪽 자식을 빼먹는 것입니다. 두 자식을 모두 비교해야 합니다.
- 같은 값일 때 교환해서 불필요하게 내려가는 것입니다. `<`로 비교하면 같은 값에서는 멈춥니다.
- 삽입은 위로, 삭제는 아래로 고친다는 방향을 바꿔 쓰는 것입니다. 루트에 다른 값을 올린 삭제에서 `siftUp`을 부르면 아무 일도 일어나지 않습니다.

## 배열을 한 번에 힙으로 만들기

이미 가진 배열 N개를 힙으로 바꾸려고 `push`를 N번 하면 O(N log N)입니다. 마지막 부모부터 거꾸로 올라가며 `siftDown`을 한 번씩 부르면 O(N)에 만들 수 있습니다. 이를 heapify(Floyd의 방법)라고 합니다.

```js
function heapify(a) {
  for (let i = (a.length >> 1) - 1; i >= 0; i--) {
    siftDown(a, i, a.length)
  }
  return a
}
heapify([9, 4, 7, 1, 3, 2]) // [1, 3, 2, 4, 9, 7]
```

- 잎은 이미 크기 1의 힙이므로 건드리지 않습니다. 마지막 부모의 인덱스는 `(N >> 1) - 1`입니다. 길이가 6이면 2부터 시작합니다.
- 아래쪽 부모부터 위로 올라가며 처리하므로, `siftDown`을 부르는 시점에 그 노드의 두 서브트리는 이미 힙입니다. 그래서 루트의 값 하나만 내려 보내면 서브트리 전체가 힙이 됩니다.

`[9, 4, 7, 1, 3, 2]`의 진행입니다.

| 시작 인덱스 | 처리 | 배열 |
|-------------|------|------|
| 2 (값 7) | 자식 2와 교환 | `[9, 4, 2, 1, 3, 7]` |
| 1 (값 4) | 자식 1, 3 중 1과 교환 | `[9, 1, 2, 4, 3, 7]` |
| 0 (값 9) | 자식 1, 2 중 1과 교환, 이어서 자식 4, 3 중 3과 교환 | `[1, 3, 2, 4, 9, 7]` |

O(N)인 이유는 노드가 내려가는 최대 거리가 층마다 다르기 때문입니다. 높이가 h인 노드는 최대 N / 2^(h+1)개 정도이고 각각 최대 h번 내려가므로 총합은 다음과 같습니다.

$$
\sum_{h=0}^{\log N} \frac{N}{2^{h+1}} \cdot h = N \sum_{h=0}^{\log N} \frac{h}{2^{h+1}} \le N
$$

- h: 노드의 높이(가장 깊은 잎까지의 거리). 잎은 0.
- N / 2^(h+1): 높이가 h인 노드 수의 상한. 절반 가까이가 높이 0이라 비용이 들지 않는다.
- 합 `h / 2^(h+1)`은 h를 무한히 더해도 1에 수렴하므로 총합은 O(N)입니다.

반면 `push`를 N번 하면 대부분의 노드(아래층)가 가장 많이 올라갈 수 있어서 O(N log N)입니다.

**흔한 실수:** 앞에서부터(루트부터) `siftDown`을 부르는 것입니다. 서브트리가 아직 힙이 아니어서 결과가 힙이 되지 않습니다. 반드시 마지막 부모에서 루트 방향으로 처리합니다.

## 힙 정렬

힙 정렬(heap sort)은 배열을 최대 힙으로 만든 뒤, 루트(최댓값)를 배열의 맨 뒤로 보내고 힙 크기를 하나 줄이는 일을 반복하는 정렬입니다. 결과는 오름차순입니다.

```js
function heapSort(a) {
  const n = a.length
  for (let i = (n >> 1) - 1; i >= 0; i--) {
    siftDownMax(a, i, n)           // 1. 최대 힙으로 heapify
  }
  for (let end = n - 1; end > 0; end--) {
    swap(a, 0, end)                // 2. 최댓값을 뒤로
    siftDownMax(a, 0, end)         // 3. 힙 크기를 end로 줄여 복구
  }
  return a
}
heapSort([4, 1, 3, 2]) // [1, 2, 3, 4]
```

`[4, 1, 3, 2]`의 진행입니다. 대괄호가 둘로 나뉜 오른쪽 배열은 이미 확정된 부분입니다.

| 단계 | 배열 |
|------|------|
| 최대 힙으로 만들기 | `[4, 2, 3, 1]` |
| 4를 뒤로 보내고 복구 | `[3, 2, 1] [4]` |
| 3을 뒤로 보내고 복구 | `[2, 1] [3, 4]` |
| 2를 뒤로 보내고 끝 | `[1] [2, 3, 4]` |

- 시간은 항상 O(N log N)입니다. heapify가 O(N), 꺼내기 N번이 각각 O(log N)이라서 최선·평균·최악이 같습니다.
- 추가 배열이 필요 없어서 보조 공간은 O(1)입니다(제자리 정렬). 병합 정렬은 O(N)의 보조 공간이 듭니다.
- 같은 값의 원래 순서를 보장하지 않는 불안정 정렬입니다. 안정성이 필요하면 인덱스를 함께 비교하거나 `sort`를 씁니다(자세히는 26편).
- 최대 힙을 쓰는 이유는 뒤에서부터 확정하기 때문입니다. 최소 힙으로도 정렬할 수 있지만 별도의 결과 배열이 필요합니다.
- 실제로는 퀵 정렬이 보통 더 빠르고(캐시 효율), 코딩테스트에서는 내장 `sort`를 씁니다. 힙 정렬은 최악이 O(N log N)으로 보장된다는 점과, 부분만 정렬하는 문제(가장 큰 K개)에 힙을 응용한다는 점이 중요합니다(자세히는 27편, 47편).

**흔한 실수:** 루프 안에서 `siftDownMax(a, 0, a.length)`처럼 전체 길이를 넘기는 것입니다. 뒤쪽에 확정된 값까지 힙으로 보고 다시 올려 버려서 정렬이 깨집니다. 힙 크기는 `end`입니다.

## 핵심 정리

- 힙은 완전 이진 트리이면서 부모와 자식 사이에 순서(최소 힙은 부모 ≤ 자식)가 있는 구조이며, 배열에 담고 `2i + 1`, `2i + 2`, `(i - 1) >> 1`로 이동합니다.
- 루트 확인은 O(1), 삽입과 루트 삭제는 O(log N)이고, 임의 값 탐색은 O(N)입니다. 형제 사이에는 순서가 없습니다.
- 삽입은 끝에 붙인 뒤 bubble up으로 올리고, 삭제는 마지막 값을 루트에 올린 뒤 더 작은 자식과 교환하는 bubble down으로 내립니다.
- 최대 힙은 비교 방향만 뒤집은 것이고, 숫자라면 부호를 바꿔 최소 힙으로 대신할 수 있습니다.
- 배열을 힙으로 만드는 heapify는 마지막 부모부터 루트까지 `siftDown`을 부르면 O(N)입니다(`push` 반복은 O(N log N)).
- 힙 정렬은 최대 힙의 루트를 뒤로 보내며 정렬하고, 항상 O(N log N)에 보조 공간 O(1)인 불안정 정렬입니다.
