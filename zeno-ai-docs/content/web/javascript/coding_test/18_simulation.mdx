## 시뮬레이션

시뮬레이션(simulation)은 문제에 적힌 규칙을 순서대로 실행해 최종 상태를 구하는 유형입니다. 영리한 알고리즘보다 규칙을 빠짐없이 정확히 옮기는 것이 관건이라서 구현 문제라고도 부릅니다. 기본 틀은 같습니다.

```js
let state = initialState        // 1. 입력으로 초기 상태 만들기
for (let t = 0; t < K; t++) {   // 2. 단계 수만큼 반복
  state = applyRule(state)      //    규칙 한 단계 적용
}
// 종료 조건형이면: while (!isDone(state)) state = applyRule(state)
console.log(result(state))      // 3. 최종 상태에서 답 뽑기
```

| 형태 | 반복 기준 | 단서 |
|------|-----------|------|
| 단계 수형 | 정해진 K번 | "K초 뒤", "K번 수행한 후" |
| 종료 조건형 | 조건이 될 때까지 | "더 이상 할 수 없을 때까지" |
| 명령 목록형 | 입력된 명령을 차례로 | "주어진 명령을 순서대로" |

- 전체 비용은 단계 수 × 한 단계의 비용입니다. 제한 조건을 보고 시뮬레이션을 그대로 돌려도 되는지 먼저 계산합니다(자세히는 14편).
- 단계 수 K가 매우 크면(예: 10억) 상태가 반복되는 주기를 찾거나 수식으로 바꿔야 합니다. 주기 감지는 아래 "상태 관리"에서 다룹니다.
- 격자 위에서 한 단계씩 칸을 갱신하는 방식은 17편의 "격자 시뮬레이션"을 따릅니다.
- 작성 순서는 상태 정의, 한 단계 함수, 반복, 출력입니다. 한 단계 함수를 작게 만들어 작은 입력으로 손 추적한 뒤 반복에 붙입니다(자세히는 15편).

## 상태 관리

상태(state)는 시간에 따라 바뀌는 값을 모은 것이고, 상태 관리는 무엇을 상태로 둘지 정하고 일관되게 갱신하는 일입니다. 위치, 방향, 남은 개수 같은 값이 상태입니다.

```js
const robot = { r: 0, c: 0, d: 1 } // 행, 열, 방향 인덱스
robot.r += dr[robot.d]
robot.c += dc[robot.d]
```

- 상태는 최소한으로 둡니다. 다른 값에서 계산할 수 있는 값(예: 남은 칸 수)을 따로 저장하면 갱신을 빠뜨렸을 때 서로 어긋납니다. 자주 읽고 계산이 비싼 값만 저장합니다.
- 변수가 서너 개를 넘으면 객체 하나로 묶어 함수에 넘깁니다. 갱신할 값을 한곳에서 관리하게 됩니다.
- 한 단계에서 여러 값이 서로의 이전 값을 쓰면 갱신 순서가 결과를 바꿉니다. 이전 값을 임시 변수에 두거나 구조 분해로 동시에 대입합니다.

```js
let [a, b] = [1, 1]
for (let i = 0; i < 3; i++) {
  [a, b] = [b, a + b] // 오른쪽을 모두 계산한 뒤 대입
}
// a는 3, b는 5
```

- 앞 단계의 상태가 나중에 다시 나오는지 알려면 상태를 문자열 키로 만들어 `Map`이나 `Set`에 넣습니다. 이미 있는 키가 나오면 주기가 시작된 것이고, 그 뒤는 같은 과정이 반복됩니다.

```js
const seen = new Map() // 상태 키 -> 그때의 시각
for (let t = 0; t < K; t++) {
  const key = `${r},${c},${d}`
  if (seen.has(key)) { /* 주기 = t - seen.get(key) */ break }
  seen.set(key, t)
  // 한 단계 진행
}
```

- 주기를 찾으면 남은 단계를 `(K - t) % 주기`로 줄입니다. 상태의 모든 요소(위치, 방향, 남은 명령 위치 등)가 키에 들어가야 합니다. 하나라도 빠지면 다른 상태를 같다고 착각합니다.

**흔한 실수:** 객체 상태를 복사한다고 `const prev = state`로 쓰는 것입니다. 같은 객체를 가리키므로 갱신하면 이전 값도 바뀝니다. 이전 값이 필요하면 `{ ...state }`로 복사합니다(자세히는 01편).

## 방향 전환

방향을 인덱스로 두면 방향 전환은 인덱스 계산입니다. 17편의 방향 배열(상 우 하 좌, 시계 방향)을 그대로 씁니다.

| 동작 | 새 방향 |
|------|---------|
| 오른쪽으로 90도 | `(d + 1) % 4` |
| 왼쪽으로 90도 | `(d + 3) % 4` |
| 뒤로 돌기(180도) | `(d + 2) % 4` |
| 오른쪽으로 90도를 k번 | `(d + k) % 4` |

```js
const turn = (d, cmd) =>
  cmd === 'R' ? (d + 1) % 4 : (d + 3) % 4
let d = 0           // 상
d = turn(d, 'L')    // 3 (좌)
d = turn(d, 'L')    // 2 (하)
```

- JavaScript의 `%`는 피제수의 부호를 따릅니다. `(-1) % 4`는 `-1`이라서 왼쪽 회전을 `d - 1`로 쓰면 `d`가 0일 때 인덱스가 음수가 됩니다. `+ 3`을 쓰거나 `(d - 1 + 4) % 4`로 씁니다.
- 벽이나 경계에서 튕기는 반사는 방향을 뒤집는 것입니다. 인덱스 방식은 `(d + 2) % 4`이고, 속도를 `(vr, vc)`로 들고 있는 방식은 부딪힌 축의 부호를 바꿉니다(`vr = -vr`).
- 문제가 방향을 숫자로 정해 주면(예: 0 북, 1 동, 2 남, 3 서) 그 번호에 맞춰 방향 배열의 순서를 정하면 변환이 필요 없습니다.
- 회전 후에 이동하는지, 이동 후에 회전하는지는 문제마다 다릅니다. 순서를 문장 그대로 따릅니다.

## 회전

격자(행렬) 전체를 90도 돌린 새 격자를 만드는 것이 회전입니다. H × W 격자를 90도 돌리면 W × H 격자가 되므로 새 배열의 행 수와 열 수가 바뀝니다.

| 회전 | 원래 `(r, c)`가 가는 곳 | 새 크기 |
|------|-------------------------|---------|
| 시계 90도 | `(c, H - 1 - r)` | W × H |
| 반시계 90도 | `(W - 1 - c, r)` | W × H |
| 180도 | `(H - 1 - r, W - 1 - c)` | H × W |

```js
function rotateCW(g) {
  const H = g.length, W = g[0].length
  const res = Array.from({ length: W }, () =>
    Array(H).fill(0),
  )
  for (let r = 0; r < H; r++) {
    for (let c = 0; c < W; c++) {
      res[c][H - 1 - r] = g[r][c]
    }
  }
  return res
}
rotateCW([[1, 2, 3], [4, 5, 6]])
// [[4, 1], [5, 2], [6, 3]]
```

- 원본의 첫 행이 결과의 마지막 열이 됩니다. 위 결과의 마지막 열 `1, 2, 3`이 원본의 첫 행입니다.
- k번 회전하라는 문제는 `k % 4`번만 돌립니다. 네 번 돌면 원래대로입니다.
- 회전 대신 좌표만 변환해도 됩니다. 시계 방향 90도로 돌린 뒤의 `(r, c)` 칸 값은 원본의 `(H - 1 - c, r)`에 있습니다. 격자를 다시 만들지 않고 읽을 때만 변환할 수 있습니다.
- 비용은 칸 수에 비례하는 O(HW)입니다. 회전을 매 단계 반복하면 K배가 됩니다.

**흔한 실수:** 정사각형만 생각하고 새 배열을 `H × W`로 만드는 것입니다. 정사각형이 아니면 인덱스가 범위를 벗어나거나 칸이 잘립니다.

## 이동

이동은 현재 좌표에 방향의 변화량을 더해 새 좌표를 만드는 일입니다. 새 좌표가 이동 가능한지 확인한 뒤에만 상태에 반영합니다(범위 검사는 17편).

```js
const nr = r + dr[d]
const nc = c + dc[d]
if (inRange(nr, nc) && grid[nr][nc] !== '#') {
  r = nr
  c = nc
}
```

- 이동하지 못하면 제자리에 있을지, 방향을 바꿀지, 종료할지는 문제의 규칙입니다.
- 한 번에 `k`칸 가는 이동은 변화량에 `k`를 곱합니다. 중간 칸에 장애물이 있는지 보는 문제는 한 칸씩 `k`번 반복해야 하고, 도착 칸만 중요하면 한 번에 계산합니다.
- 격자의 한쪽 끝에서 나가면 반대쪽 끝으로 나오는 경우(순환)는 나머지 연산을 씁니다. 음수가 나올 수 있으므로 보정합니다.

```js
const nr = (r + dr[d] + H) % H     // 한 칸
const nk = ((r + dr[d] * k) % H + H) % H // k칸 (k는 음수 가능)
// H = 5, r = 0, 위로 1칸: (0 - 1 + 5) % 5 = 4
```

- 보정 식 `((x % n) + n) % n`은 `x`가 음수여도 `0` 이상 `n` 미만을 줍니다(자세히는 11편).
- 한 칸씩 움직이는 이동의 총 비용은 이동 횟수에 비례합니다. 이동 거리가 크고 장애물이 없다면 반복하지 않고 한 번에 계산합니다.

## 충돌 처리

충돌 처리는 이동한 결과가 규칙에 어긋나는 상황을 판정하고 그에 맞게 바꾸는 일입니다. 종류가 셋 있습니다.

| 종류 | 판정 | 처리 예 |
|------|------|---------|
| 벽·장애물·경계 | 이동할 칸이 막혀 있음 | 이동 취소, 방향 전환, 종료 |
| 객체끼리 같은 칸 | 이동 후 같은 좌표에 둘 이상 | 모두 제거, 하나만 남김 |
| 서로 교차 | 두 객체가 자리를 맞바꿈 | 충돌로 처리하는지 문제에서 확인 |

같은 칸에 모인 객체는 모두 이동한 뒤에 한꺼번에 판정합니다. 이동하는 도중에 바로 판정하면 아직 움직이지 않은 객체와 잘못 비교합니다. 칸별 개수를 `Map`으로 세고, 정수 id(17편)를 키로 씁니다.

```js
const cnt = new Map()
for (const { r, c } of balls) {
  const key = r * W + c
  cnt.set(key, (cnt.get(key) ?? 0) + 1)
}
const alive = balls.filter(
  ({ r, c }) => cnt.get(r * W + c) === 1,
)
```

- 위 코드는 같은 칸에 둘 이상 모이면 그 칸의 객체를 모두 제거합니다. 하나만 남기는 규칙이면 키별로 한 객체만 보관합니다.
- 두 객체가 한 칸씩 움직이며 서로 자리를 바꾸면 단계가 끝난 뒤에는 같은 칸에 없어서 위 방식으로는 잡히지 않습니다. 이런 충돌이 규칙에 있다면 이동 전후의 좌표 쌍을 비교하거나, 좌표와 시간을 2배로 늘려 반 칸 단위로 쪼개서 판정합니다.
- 충돌한 객체를 제거하는 시점도 규칙입니다. 한 단계가 끝난 뒤에 제거해야 하는지, 즉시 제거해야 하는지 문장 그대로 따릅니다.

**흔한 실수:** 객체를 하나씩 이동하면서 곧바로 충돌을 검사하는 것입니다. 객체가 움직이는 순서에 따라 결과가 달라집니다.

## 객체 상태 변경

시뮬레이션에서 칸 위의 개체(병사, 공, 로봇)는 객체로 두고 속성을 직접 바꿉니다.

```js
const units = [
  { id: 1, hp: 10, alive: true },
  { id: 2, hp: 3, alive: true },
]
units[1].hp -= 4
if (units[1].hp <= 0) units[1].alive = false
```

- 변수에 객체를 담으면 복사가 아니라 같은 객체를 가리킵니다. `const u = units[0]; u.hp = 0`은 `units[0]`을 바꿉니다(자세히는 01편).
- 여러 객체를 한 번에 만들 때 `Array(n).fill({ hp: 0 })`으로 만들면 모두 같은 객체입니다. `Array.from({ length: n }, () => ({ hp: 0 }))`로 만듭니다(자세히는 05편).
- 객체를 빠르게 찾아야 하면 `id`를 키로 하는 `Map`이나 배열 인덱스로 접근합니다. 배열에서 `find`로 찾으면 매번 O(N)입니다.
- 객체를 지울 때는 두 방법이 있습니다. `alive` 같은 플래그를 두고 건너뛰는 방법, 단계가 끝난 뒤 `filter`로 새 배열을 만드는 방법입니다.

```js
const a = [{ hp: 0 }, { hp: 0 }, { hp: 3 }]
for (let i = 0; i < a.length; i++) {
  if (a[i].hp <= 0) a.splice(i, 1)  // ❌ 다음 요소를 건너뜀
}
// a는 [{ hp: 0 }, { hp: 3 }] (둘째 요소가 남음)
const rest = a.filter((u) => u.hp > 0) // ✅
```

- 반복 중에 `splice`로 지우면 뒤 요소가 앞으로 당겨져 다음 요소를 건너뜁니다. 지우려면 뒤에서부터 순회하거나 `filter`를 씁니다.
- 한 단계에서 객체끼리 영향을 주고받으면 갱신 순서가 결과를 바꿉니다. 모든 객체의 변화량을 먼저 계산한 뒤 한꺼번에 적용합니다.

## 명령어 처리

명령어 처리는 입력으로 주어진 명령을 차례로 읽어 상태를 바꾸는 유형입니다. 명령 한 줄을 이름과 인수로 나눈 뒤 이름에 맞는 동작을 실행합니다.

```js
const ops = {
  move: (s, a) => {
    s.r += dr[s.d] * Number(a)
    s.c += dc[s.d] * Number(a)
  },
  turn: (s, a) => {
    s.d = a === 'R' ? (s.d + 1) % 4 : (s.d + 3) % 4
  },
}
const s = { r: 0, c: 0, d: 1 }
for (const line of ['move 3', 'turn R', 'move 2']) {
  const [name, arg] = line.split(' ')
  ops[name](s, arg)
}
// s는 { r: 2, c: 3, d: 2 }
```

- `split(' ')`의 결과는 문자열입니다. 숫자 인수는 `Number`로 바꿉니다.
- 명령마다 `if`나 `switch`를 쓰는 것과 위처럼 이름을 키로 하는 객체에 함수를 모으는 것 중 하나를 고릅니다. 명령 종류가 많으면 표가 읽기 쉽습니다.
- 객체로 이름을 찾을 때 `ops['toString']`처럼 상속된 키가 걸립니다. 입력에 임의의 이름이 올 수 있으면 `Object.hasOwn(ops, name)`으로 확인하거나 `Map`을 씁니다(자세히는 10편).
- 줄 끝의 `\r`이나 끝 공백이 이름에 붙어 매칭이 실패할 수 있습니다. 입력을 읽을 때 `trim`합니다(자세히는 08편).
- 명령이 상태에 맞지 않을 때(빈 스택에서 `pop` 등)의 처리는 문제가 정합니다. 무시하는지, `-1`을 출력하는지 확인합니다.
- 비용은 명령 수 Q에 각 명령의 비용을 곱한 것입니다. 한 명령이 O(N)이면 전체가 O(QN)이 되므로 제한 조건과 비교합니다.

## 복잡한 조건 구현

조건이 여러 겹인 문제는 문장을 코드 구조로 옮기는 순서를 정해 두면 실수가 줄어듭니다.

1. 규칙을 한 문장씩 나누고 번호를 붙입니다.
2. 번호 순서가 우선순위인지, 모든 규칙이 동시에 적용되는지 구분합니다.
3. 우선순위가 있으면 위에서 아래로 `if`, `else if`를 쓰고 "그 외"는 `else`로 둡니다. 동시에 적용되면 각각 독립된 `if`로 씁니다.
4. 복잡한 판정은 이름 있는 함수(`canMove`, `isBlocked`)로 빼서 조건식을 짧게 합니다.

직접 만든 문제입니다. 로봇이 `(0, 0)`에서 오른쪽을 보고 시작합니다. 앞 칸이 빈 칸(`.`)이면 전진하고 그 칸을 `x`로 표시합니다. 아니면 오른쪽으로 90도 돕니다. 연속으로 4번 돌아도 못 가면 멈춥니다. 전진 횟수를 구합니다.

```js
let r = 0, c = 0, d = 1, turns = 0, steps = 0
grid[0][0] = 'x'
while (turns < 4) {
  const nr = r + dr[d], nc = c + dc[d]
  if (inRange(nr, nc) && grid[nr][nc] === '.') {
    r = nr; c = nc; grid[r][c] = 'x'
    turns = 0; steps++
  } else {
    d = (d + 1) % 4; turns++
  }
}
```

격자가 `.../.#./...`이면 `steps`는 7입니다. 가운데 벽을 제외한 8칸을 시계 방향으로 돌며 7번 전진하고 `(1, 0)`에서 멈춥니다.

- 위 코드의 종료는 `turns`와 `x` 표시로 보장됩니다. 방문 표시가 없으면 같은 칸을 영원히 도는 무한 루프가 됩니다. 반복문마다 "언제 끝나는가"를 확인합니다.
- `!(A && B)`는 `!A || !B`와 같고, `!(A || B)`는 `!A && !B`와 같습니다(드모르간 법칙). "~이 아니면서 ~이 아닌"을 옮길 때 씁니다.
- 문제에서 "먼저", "동시에", "그 다음"이라는 말은 순서 규칙입니다. 이 말을 코드 주석으로 옮겨 두면 구현이 어긋나지 않습니다.
- 시간이 0초부터인지 1초부터인지, 경계 값이 포함되는지(이상·초과)를 예제의 숫자로 확인합니다(자세히는 15편).
- 막히면 가장 작은 입력을 손으로 추적한 값과 코드의 중간 출력을 비교해 처음 어긋나는 단계를 찾습니다.

## 행렬 전치

전치(transpose)는 행과 열을 맞바꾸는 것입니다. 원래 `(r, c)`의 값이 `(c, r)`로 갑니다. H × W 행렬은 W × H가 됩니다.

```js
const m = [[1, 2, 3], [4, 5, 6]]
const t = Array.from({ length: m[0].length }, (_, c) =>
  m.map((row) => row[c]),
)
// [[1, 4], [2, 5], [3, 6]]
```

정사각 행렬은 새 배열 없이 제자리에서 바꿀 수 있습니다. 대각선(`r === c`)은 그대로이고, 대각선 위쪽 칸만 아래쪽 칸과 맞바꿉니다.

```js
const n = m.length // 정사각 행렬일 때
for (let r = 0; r < n; r++) {
  for (let c = r + 1; c < n; c++) {
    ;[m[r][c], m[c][r]] = [m[c][r], m[r][c]]
  }
}
```

- 안쪽 반복을 `c = r + 1`부터 시작하는 것이 핵심입니다. `c = 0`부터 전체를 돌면 맞바꾼 칸을 한 번 더 바꿔서 원래대로 돌아갑니다.
- 전치한 뒤 각 행을 뒤집으면 시계 90도 회전입니다. 위의 `rotateCW`와 같은 결과를 냅니다.
- 문장에서 "행과 열을 바꾼다"는 말이 나오면 전치입니다. 시간은 O(HW)입니다.

## 나선 순회

나선(달팽이) 순회는 바깥에서 안쪽으로 시계 방향으로 돌며 칸을 방문하는 순서입니다. 방향 배열을 써서 한 방향으로 가다가 경계에 닿거나 이미 지난 칸이면 오른쪽으로 방향을 바꾸는 방식이 가장 단순합니다(방향 전환은 위에서 다룸). 1부터 `N × N`까지 나선으로 채우는 코드입니다.

```js
function spiral(N) {
  const g = Array.from({ length: N }, () =>
    Array(N).fill(0),
  )
  const blocked = (r, c) =>
    r < 0 || r >= N || c < 0 || c >= N || g[r][c] !== 0
  let r = 0, c = 0, d = 1 // 오른쪽에서 시작
  for (let v = 1; v <= N * N; v++) {
    g[r][c] = v
    if (blocked(r + dr[d], c + dc[d])) d = (d + 1) % 4
    r += dr[d]; c += dc[d]
  }
  return g
}
// spiral(4): 1 2 3 4 / 12 13 14 5 / 11 16 15 6 / 10 9 8 7
```

- 칸을 채운 뒤 다음 칸이 막혔으면 방향을 한 번 돌리고 이동합니다. 마지막 칸에서는 이동한 좌표를 더 쓰지 않고 반복이 끝납니다.
- 읽는 문제(주어진 `H × W` 격자를 나선 순서로 출력)는 채우는 대신 방문 배열(17편)을 두고 같은 구조로 씁니다. 총 `H × W`번 반복합니다.
- 다른 방식은 위·아래·왼쪽·오른쪽 경계 네 개를 두고 한 변을 읽을 때마다 경계를 한 칸씩 줄이는 것입니다. 행이나 열이 하나만 남았을 때 같은 칸을 두 번 읽지 않도록 경계가 교차했는지 검사해야 합니다.
- 방향 방식은 정사각형이 아닌 격자와 막힌 칸이 섞인 격자에서도 코드를 바꾸지 않고 쓸 수 있습니다.
- 시간은 O(HW)입니다.

## 시각·날짜 계산

시각은 시와 분을 따로 다루지 않고 하루의 분 단위 정수 하나로 바꿔 계산합니다. `시 × 60 + 분`입니다. 더하고 빼는 연산이 정수 연산이 되고 하루를 넘는 경우는 `1440`(24 × 60)으로 나눈 나머지로 처리합니다.

```js
const toMin = (h, m) => h * 60 + m
const fmt = (t) => {
  const x = ((t % 1440) + 1440) % 1440 // 0 이상으로 보정
  const h = String(Math.floor(x / 60)).padStart(2, '0')
  return `${h}:${String(x % 60).padStart(2, '0')}`
}
fmt(toMin(23, 50) + 30) // '00:20'
fmt(toMin(0, 10) - 30)  // '23:40'
```

- 두 시각의 차이는 분 단위 정수의 뺄셈입니다. 끝 시각이 다음 날로 넘어갈 수 있으면 `(end - start + 1440) % 1440`으로 구합니다.
- 자릿수를 맞춘 출력은 `padStart`를 씁니다(자세히는 06편).
- 날짜는 `Date`를 쓰는 방법과 직접 계산하는 방법이 있습니다. `Date.UTC(년, 월 - 1, 일)`은 UTC 기준 1970년 1월 1일 0시부터 지난 밀리초를 줍니다. 월은 0부터 시작하고 일은 1부터 시작합니다. UTC 기준이라 실행 환경의 시간대에 영향을 받지 않습니다.

```js
const day = (y, m, d) => Date.UTC(y, m - 1, d)
const MS = 86400000 // 하루의 밀리초
const diff = day(2026, 10, 6) - day(2026, 1, 1)
diff / MS                              // 278 (일수 차이)
new Date(day(2026, 10, 6)).getUTCDay() // 2 (0이 일요일)
const next = new Date(day(2024, 2, 28) + 2 * MS)
next.toISOString().slice(0, 10)        // '2024-03-01'
```

- `getUTCDay()`는 요일을 일요일 0, 월요일 1, … 토요일 6으로 줍니다.
- 각 값이 범위를 넘으면 `Date.UTC`가 자동으로 올립니다. `day: 32`는 다음 달로 넘어갑니다. 날짜에 며칠을 더할 때는 밀리초에 더해서 새 `Date`를 만들거나 일 인수에 더합니다.
- 윤년은 4로 나누어떨어지고 100으로 나누어떨어지지 않거나, 400으로 나누어떨어지는 해입니다. `(y % 4 === 0 && y % 100 !== 0) || y % 400 === 0`이고 1900년은 윤년이 아니며 2000년은 윤년입니다.
- 달마다 일수를 더하는 계산은 배열 `[31, 28, 31, …]`을 두고 윤년이면 2월을 29로 바꿔서 누적합니다. `Date` 없이 풀어야 하는 문제는 이 방식을 씁니다.
- 날짜에서 월을 0부터 세는 점과 요일 번호의 시작이 일요일 0인 점이 가장 흔한 실수입니다.

## 행렬 곱셈

행렬 곱셈은 `n × m` 행렬 `A`와 `m × p` 행렬 `B`로 `n × p` 행렬 `C`를 만드는 연산입니다. `C[i][j]`는 `A`의 i행과 `B`의 j열의 대응하는 원소끼리 곱해 모두 더한 값입니다.

$$
C[i][j] = \sum_{k=0}^{m-1} A[i][k] \times B[k][j]
$$

- `A[i][k]`: `A`의 i행 k열 값
- `B[k][j]`: `B`의 k행 j열 값
- `m`: `A`의 열 수이자 `B`의 행 수. 둘이 같아야 곱할 수 있습니다.

```js
function mul(A, B) {
  const n = A.length, m = B.length, p = B[0].length
  const C = Array.from({ length: n }, () =>
    Array(p).fill(0),
  )
  for (let i = 0; i < n; i++) {
    for (let j = 0; j < p; j++) {
      for (let k = 0; k < m; k++) {
        C[i][j] += A[i][k] * B[k][j]
      }
    }
  }
  return C
}
// mul([[1,2],[3,4]], [[5,6],[7,8]]) = [[19,22],[43,50]]
```

- 반복문은 `i`, `j`, `k` 순서의 삼중 반복이고 시간은 O(n · m · p)입니다. 정사각 `N × N`이면 O(N³)입니다.
- 결과 배열 `C`는 0으로 채워 만들어야 합니다. 누적하는 `+=`가 시작할 값이 필요합니다.
- 교환법칙이 성립하지 않아서 `A × B`와 `B × A`는 일반적으로 다릅니다. 결합법칙은 성립합니다.
- 곱해도 변하지 않는 단위 행렬(대각선이 1, 나머지가 0)이 있습니다. 행렬의 거듭제곱에서 시작 값으로 씁니다(자세히는 76편).
- 값이 커지면 `Number`의 안전한 정수 범위(약 9 × 10의 15제곱)를 넘을 수 있습니다. 문제가 나머지를 요구하면 곱한 뒤 매번 나머지를 취하고, 한 번의 곱이 범위를 넘으면 `BigInt`를 씁니다(자세히는 02편, 57편).

## 배열 회전

배열 회전은 요소의 순서를 유지한 채 앞이나 뒤의 일부를 반대쪽으로 옮기는 것입니다. 길이 `n`인 배열을 오른쪽으로 `k`칸 돌리면 마지막 `k`개가 앞으로 옵니다.

```js
function reverse(a, l, r) {
  while (l < r) {
    ;[a[l], a[r]] = [a[r], a[l]]
    l++; r--
  }
}
function rotateRight(a, k) {
  const n = a.length
  k %= n                  // k가 n 이상이어도 같은 결과
  reverse(a, 0, n - 1)    // 1. 전체 뒤집기
  reverse(a, 0, k - 1)    // 2. 앞 k개 뒤집기
  reverse(a, k, n - 1)    // 3. 나머지 뒤집기
  return a
}
rotateRight([1, 2, 3, 4, 5], 2) // [4, 5, 1, 2, 3]
```

- 정당성은 이렇습니다. 배열을 앞부분 `A`와 뒷부분 `B`가 이어진 `AB`로 보면, 전체를 뒤집은 `BᴿAᴿ`에서 `B`와 `A`를 각각 다시 뒤집으면 `BA`입니다. 오른쪽 회전은 뒤의 `k`개 `B`가 앞으로 오는 것이므로 `BA`와 같습니다(`ᴿ`는 뒤집은 것).
- 왼쪽으로 `k`칸은 순서만 바꿉니다. 앞 `k`개 뒤집기, 나머지 뒤집기, 전체 뒤집기를 차례로 합니다.
- 시간은 O(n)이고 추가 공간은 O(1)입니다.
- `k %= n`을 빼먹으면 `k`가 `n`보다 클 때 범위를 벗어납니다. `k`가 `0`이거나 `n`의 배수면 아무것도 하지 않아도 됩니다.
- 새 배열을 만들어도 된다면 `slice`와 스프레드로 한 줄에 쓸 수 있습니다. 이때도 `k %= n`이 먼저입니다.

```js
const a = [1, 2, 3, 4, 5]
const k = 7 % a.length                    // 2
const cut = a.length - k
const next = [...a.slice(cut), ...a.slice(0, cut)]
// [4, 5, 1, 2, 3]
const wrong = [...a.slice(-7), ...a.slice(0, -7)]
// ❌ [1, 2, 3, 4, 5] (음수 인덱스가 시작을 넘으면 전체)
```

- `slice`의 음수 인덱스는 길이를 더한 값이며 0보다 작아지면 0으로 취급합니다. `k`가 `n`보다 큰 채로 `slice(-k)`를 쓰면 전체가 돌아옵니다.
- 격자의 한 행을 돌리는 문제는 같은 방법을 그 행에 적용합니다. 한 칸만 돌리면 되는 경우에는 `a.unshift(a.pop())`로 충분합니다.

## 핵심 정리

- 시뮬레이션은 규칙을 순서대로 옮기는 유형이고 전체 비용은 단계 수 × 한 단계의 비용입니다. 단계 수가 크면 상태 반복(주기)을 찾습니다.
- 상태는 최소한으로 두고 객체로 묶습니다. 이전 값이 필요하면 복사해 두고, 객체는 대입이 복사가 아님을 기억합니다.
- 방향은 시계 방향 인덱스로 두고 `(d + 1) % 4`, `(d + 3) % 4`로 돌립니다. 모든 객체가 이동한 뒤에 충돌을 판정하고, 교차 충돌은 따로 처리합니다.
- 명령어는 이름과 인수로 나눠 처리하고 공백·`\r`·상속된 키를 조심합니다. 복잡한 조건은 문장을 번호로 나눠 우선순위를 구조로 옮깁니다.
- 전치는 `(r, c)`와 `(c, r)`을 맞바꾸고, 90도 회전은 `(c, H - 1 - r)`로 가며, 나선 순회는 방향 배열과 방문 표시로 구현합니다.
- 시각은 분 단위 정수와 `1440`의 나머지로, 날짜는 `Date.UTC`(월은 0부터)로 계산합니다. 배열 회전은 뒤집기 세 번으로 O(n)에 처리합니다.
