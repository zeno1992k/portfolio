## DFS 개념

DFS(Depth-First Search, 깊이 우선 탐색)는 한 갈래로 갈 수 있는 데까지 깊이 들어가고, 더 갈 곳이 없으면 직전 갈림길로 되돌아와 다음 갈래를 탐색하는 방법입니다. 되돌아오는 지점을 기억하는 구조가 스택이라서 재귀 호출이나 명시적 스택으로 구현합니다.

예제 그래프(정점 6개, 무방향)로 흐름을 따라가 봅니다. 정점 1에서 시작하고 이웃은 입력에 나온 순서대로 봅니다.

```js
const edges = [
  [1, 2], [1, 3], [2, 4], [2, 5], [4, 5], [3, 6],
]
// 1: [2, 3]   2: [1, 4, 5]   3: [1, 6]
// 4: [2, 5]   5: [2, 4]      6: [3]
```

| 단계 | 현재 정점 | 동작 | 방문 순서 |
|------|-----------|------|-----------|
| 1 | 1 | 방문, 첫 이웃 2로 | 1 |
| 2 | 2 | 방문, 이웃 1은 방문함, 4로 | 1, 2 |
| 3 | 4 | 방문, 이웃 2는 방문함, 5로 | 1, 2, 4 |
| 4 | 5 | 방문, 이웃 2·4 모두 방문함, 되돌아감 | 1, 2, 4, 5 |
| 5 | 2 | 마지막 이웃 5는 방문함, 되돌아감 | |
| 6 | 1 | 다음 이웃 3으로 | |
| 7 | 3 | 방문, 이웃 6으로 | 1, 2, 4, 5, 3 |
| 8 | 6 | 방문 | 1, 2, 4, 5, 3, 6 |

- 시간은 인접 리스트에서 O(V + E)입니다. 모든 정점을 한 번 방문하고 모든 간선을 한 번(무방향은 양쪽에서) 확인하기 때문입니다. 인접 행렬이면 이웃을 찾는 데 O(V)가 들어 O(V²)입니다(그래프 표현은 35편).
- 공간은 호출 스택(또는 명시적 스택)의 깊이로, 최악 O(V)입니다.
- DFS가 쓰이는 곳은 도달 가능 여부, 연결 요소, 사이클 판별(37편), 위상 정렬(53편), 격자의 영역 탐색, 완전탐색의 뼈대인 백트래킹(23편)입니다.
- 가장 가까운 정점부터 방문하는 BFS와 달리 DFS는 최단 거리를 보장하지 않습니다(자세히는 38편).

**흔한 실수:** DFS의 방문 순서가 하나라고 생각하는 것입니다. 이웃을 보는 순서(`adj`에 넣은 순서)가 바뀌면 방문 순서도 바뀝니다. 방문 순서를 출력하는 문제에서는 "번호가 작은 이웃부터"처럼 순서 조건이 주어지므로 정렬해서 넣습니다.

## 재귀 DFS

재귀 DFS는 정점 `u`를 방문하고, 방문하지 않은 이웃마다 같은 함수를 다시 호출하는 구현입니다. 함수 호출 스택이 곧 되돌아갈 지점을 기억하므로 코드가 가장 짧습니다(재귀는 22편).

```js
function dfs(adj, u, visited, order) {
  visited[u] = 1        // 진입 시 방문 표시
  order.push(u)
  for (const v of adj[u]) {
    if (!visited[v]) dfs(adj, v, visited, order)
  }
}
const order = []
dfs(adj, 1, new Uint8Array(7), order)
// order는 [1, 2, 4, 5, 3, 6]
```

- 호출은 "진입 → 이웃 호출들 → 반환" 순서입니다. 반환이 곧 되돌아감입니다.
- 반환 후에 하는 일(자식의 결과를 합치기, 종료 시각 기록)은 `for` 반복문 뒤에 씁니다.
- 방문 표시는 반복문 안의 호출 직전이 아니라 함수 맨 앞에서 해야 합니다. 한 정점이 이웃 여러 곳에서 호출되어도 처음 하나만 실행됩니다.
- 재귀 깊이는 한 갈래의 길이만큼입니다. 정점이 한 줄로 이어진 사슬 그래프에서는 깊이가 V입니다.

### 재귀 깊이 한계

JavaScript 엔진은 호출 스택 크기가 제한되어 있어서 깊이가 크면 `RangeError: Maximum call stack size exceeded`가 발생합니다. 명세는 한계를 정하지 않고 엔진마다 다릅니다.

Node.js 24에서 인자 없는 단순 재귀 함수를 직접 실험하면 약 1만 번째 호출에서 RangeError가 났습니다. 인자와 지역 변수가 많은 DFS 함수는 프레임이 커서 그보다 얕은 곳에서도 났습니다. 호출 위치와 실행 상태에 따라 달라지므로 기준값으로 쓰면 안 됩니다.

- 정점이 수만 개이고 사슬 모양이 가능하면 재귀 DFS는 위험합니다. 스택 DFS로 바꿉니다.
- 격자 문제에서 100만 칸이 뱀처럼 이어지면 깊이가 100만에 이를 수 있습니다.
- 재귀를 반복으로 바꾸는 일반 방법은 22편, 호출 스택 한계는 86편에서 다룹니다.

**흔한 실수:** 예제가 작다고 재귀로 제출하는 것입니다. 입력 크기 제한을 보고 최악 깊이를 따져서 재귀와 스택 중 고릅니다.

## Stack DFS

스택 DFS는 호출 스택 대신 배열을 스택으로 써서 되돌아갈 지점을 직접 관리하는 구현입니다(스택은 19편). 재귀 한계가 없고 `RangeError`가 나지 않습니다. 두 방식이 있습니다.

### 이웃을 모두 넣는 방식

현재 정점의 방문하지 않은 이웃을 전부 스택에 넣고, 꺼낼 때 방문 여부를 확인합니다.

```js
function dfsIter(adj, start) {
  const visited = new Uint8Array(adj.length)
  const order = []
  const stack = [start]
  while (stack.length) {
    const u = stack.pop()
    if (visited[u]) continue   // 이미 방문한 정점은 건너뜀
    visited[u] = 1
    order.push(u)
    for (let i = adj[u].length - 1; i >= 0; i--) {
      if (!visited[adj[u][i]]) stack.push(adj[u][i])
    }
  }
  return order
}
```

- 이웃을 뒤에서부터 넣어야 스택에서 첫 이웃이 먼저 나와 재귀 DFS와 같은 순서(`[1, 2, 4, 5, 3, 6]`)가 됩니다. 앞에서부터 넣으면 이웃 순서가 반대로 방문됩니다.
- 한 정점이 여러 번 스택에 들어갈 수 있으므로 꺼낼 때 `visited`를 확인해야 합니다. 스택에 최대 O(E)개가 쌓입니다.
- 정점을 스택에 넣을 때 방문 표시를 하는 방식(35편의 `explore`)은 각 정점이 한 번만 들어가 빠르지만 방문 순서가 재귀 DFS와 다릅니다. 같은 예제에서 `[1, 2, 3, 6, 4, 5]`가 됩니다. 순서가 상관없는 도달 가능 여부, 연결 요소에는 충분합니다.

### 이웃 위치를 기억하는 방식

스택의 각 정점이 "다음에 볼 이웃의 위치"를 따로 기억하는 방식입니다. 재귀 호출의 진행 상태를 그대로 옮긴 것이라 방문 순서와 반환 시점이 재귀와 정확히 같습니다. 반환 시점이 필요한 종료 시각, 후위 순서, 사이클 판별은 이 방식으로 구현합니다.

```js
function dfsExact(adj, start, visited) {
  const idx = new Int32Array(adj.length) // 다음에 볼 이웃의 위치
  const stack = [start]
  visited[start] = 1
  while (stack.length) {
    const u = stack[stack.length - 1]    // 꺼내지 않고 본다
    if (idx[u] < adj[u].length) {
      const v = adj[u][idx[u]++]
      if (!visited[v]) { visited[v] = 1; stack.push(v) }
    } else {
      stack.pop()                        // 이웃을 다 봄: 반환
    }
  }
}
```

- 스택에는 현재 경로의 정점만 쌓여서 크기가 O(V)입니다.
- `stack.pop()` 자리가 재귀 함수의 `return` 직전과 같습니다. 여기서 종료 시각을 기록합니다(아래 "방문 순서와 진입·종료 시각").
- 방문 순서를 맞출 필요가 없고 단순하면 첫 번째 방식, 반환 시점이 필요하면 두 번째 방식을 씁니다.

**흔한 실수:** `stack.shift()`로 꺼내는 것입니다. 앞에서 꺼내면 큐가 되어 BFS가 되고 배열 `shift`는 느립니다(자세히는 20편).

## visited

visited는 이미 방문한 정점을 표시해서 같은 정점을 다시 처리하지 않게 하는 배열입니다. 그래프에는 사이클이 있을 수 있어서 이 표시가 없으면 무한히 반복합니다. 무방향 그래프는 간선이 양방향이라서 사이클이 없어도 방금 온 정점으로 되돌아가 무한 루프가 됩니다.

| 대상 | 자료구조 | 인덱스 |
|------|----------|--------|
| 정점 번호가 정수 | `Uint8Array(n + 1)` | 정점 번호 |
| 격자 | `Array.from`으로 만든 행별 `Uint8Array(w)` | `visited[r][c]` |
| 격자(1차원) | `Uint8Array(h * w)` | `r * w + c` |
| 문자열·객체 정점 | `Set` 또는 `Map` | 키(자세히는 09편) |

- 방문 표시는 정점을 처음 만났을 때(진입 시) 합니다. 재귀는 함수 맨 앞, 이웃 확인 방식에서는 호출 직전에 합니다.
- 그래프 DFS의 `visited`는 한 번 켜면 끄지 않습니다. 각 정점이 한 번만 처리되어 O(V + E)입니다. 백트래킹처럼 되돌아올 때 끄면 같은 정점을 여러 경로로 다시 방문해서 지수 시간이 됩니다(자세히는 23편).
- 격자에서 원본 칸의 값을 바꿔서 방문을 표시(예: `'1'`을 `'0'`으로)하면 `visited` 배열이 필요 없습니다. 대신 원본이 망가지므로 다시 써야 하면 복사해서 씁니다.
- 테스트 케이스가 여러 개이거나 시작점이 여러 번 바뀌면 `visited`를 초기화합니다. 매번 `new Uint8Array(n + 1)`로 새로 만들거나 `fill(0)`을 호출합니다. 두 방법 모두 O(V)입니다.
- `Uint8Array`는 0으로 초기화됩니다. 일반 배열은 `new Array(n + 1).fill(false)`로 채웁니다(자세히는 04편, 05편).

**흔한 실수:**

- 방문 표시를 이웃 호출 뒤에 하는 것입니다. 그러면 호출이 돌아오기 전까지 같은 정점이 다시 호출되어 무한 재귀가 됩니다.
- `visited`를 함수 안에서 매번 새로 만드는 것입니다. 재귀 호출마다 새 배열이 생겨서 방문 기록이 이어지지 않습니다. 바깥에서 한 번 만들어 인자로 넘기거나 클로저로 공유합니다.

## 그래프 DFS

그래프 DFS는 인접 리스트로 표현한 방향·무방향 그래프에서 시작 정점에서 도달 가능한 정점을 모두 방문하는 DFS입니다. 앞의 `dfs`와 `dfsIter`가 그대로 그래프 DFS입니다. 방향 그래프는 간선을 한 방향만 저장해서 같은 코드로 풉니다.

문제 입력에서 `N`개 정점과 `M`개 간선을 읽어 인접 리스트를 만들고 탐색합니다.

```js
function reachable(n, edges, s, t) {  // s에서 t로 갈 수 있는가
  const adj = Array.from({ length: n + 1 }, () => [])
  for (const [u, v] of edges) {
    adj[u].push(v)
    adj[v].push(u)                    // 무방향
  }
  const visited = new Uint8Array(n + 1)
  dfsExact(adj, s, visited)
  return visited[t] === 1
}
reachable(6, [[1, 2], [2, 3], [4, 5]], 1, 3) // true
reachable(6, [[1, 2], [2, 3], [4, 5]], 1, 5) // false
```

- 시작점에서 도달 가능한 정점만 방문합니다. 그래프가 여러 조각이면 나머지는 방문되지 않습니다. 모든 정점을 방문하려면 방문하지 않은 정점마다 DFS를 다시 시작합니다(아래 "연결 요소").
- 인접 행렬로 구현하면 이웃 순회가 `for (let v = 1; v <= n; v++) if (m[u][v] && !visited[v])`가 되고 전체 O(V²)입니다.
- 정점마다 이웃을 보는 순서를 고정해야 하는 문제는 `adj[u].sort((a, b) => a - b)`를 한 번 한 뒤 탐색합니다(비교 함수는 26편).
- DFS 한 번의 방문 집합이 시작 정점이 속한 연결 요소와 같습니다(무방향일 때).

**흔한 실수:** 무방향 그래프에서 간선을 한쪽만 저장하는 것입니다. 입력 순서에 따라 한쪽에서만 닿아서 도달 여부가 틀립니다(자세히는 35편).

## 격자 DFS

격자 DFS는 2차원 격자의 칸을 정점으로, 상하좌우로 이웃한 칸을 간선으로 보고 하는 DFS입니다. 별도의 인접 리스트를 만들지 않고 방향 배열로 이웃을 계산합니다(방향 배열과 범위 검사는 17편).

```js
const dr = [-1, 1, 0, 0]   // 상, 하, 좌, 우
const dc = [0, 0, -1, 1]

function walk(grid, r, c, seen) {      // 칸 값이 '1'인 칸만 이동
  const h = grid.length, w = grid[0].length
  seen[r][c] = 1
  for (let d = 0; d < 4; d++) {
    const nr = r + dr[d], nc = c + dc[d]
    if (nr < 0 || nr >= h || nc < 0 || nc >= w) continue
    if (grid[nr][nc] === '1' && !seen[nr][nc]) {
      walk(grid, nr, nc, seen)
    }
  }
}
```

- 이웃 칸 조건 세 가지(범위 안, 이동 가능한 칸, 미방문)를 모두 확인해야 합니다. 범위 검사를 먼저 해야 `grid[nr]`이 `undefined`가 되는 일을 막습니다.
- 대각선을 포함한 8방향 문제는 방향 배열을 8개로 늘립니다. 문제가 4방향인지 8방향인지 먼저 읽습니다.
- 칸 수가 `H × W`이고 한 칸에서 4방향을 보므로 시간은 O(HW)입니다.
- 칸 수가 크면 재귀 깊이가 최대 `H × W`이므로 스택 방식으로 씁니다(아래 "Flood Fill").
- 칸 좌표를 `[r, c]` 배열 대신 정수 `r * w + c` 하나로 쓰면 스택과 `visited`가 가벼워집니다. 되돌릴 때는 `Math.floor(x / w)`와 `x % w`입니다(자세히는 17편).

**흔한 실수:** 범위 검사를 `nr > h`처럼 쓰는 것입니다. 유효한 행은 `0`부터 `h - 1`이므로 `nr >= h`가 범위 밖입니다.

## Flood Fill

Flood Fill은 시작 칸과 같은 색(값)으로 연결된 모든 칸을 새로운 색으로 바꾸는 알고리즘입니다. 그림판의 페인트통 도구가 이 동작입니다. 격자 DFS에 "방문 표시 = 색 바꾸기"를 결합한 것입니다.

> 2차원 배열 `img`, 시작 위치 `(sr, sc)`, 새 색 `color`가 주어진다. 시작 칸과 상하좌우로 이어진 같은 색 칸을 모두 `color`로 바꾼다.

```js
function floodFill(img, sr, sc, color) {
  const old = img[sr][sc]
  if (old === color) return      // 같은 색이면 할 일이 없다
  const stack = [[sr, sc]]
  img[sr][sc] = color
  while (stack.length) {
    const [r, c] = stack.pop()
    for (let d = 0; d < 4; d++) {
      const nr = r + dr[d], nc = c + dc[d]
      if (img[nr]?.[nc] !== old) continue // 범위 밖도 걸러진다
      img[nr][nc] = color
      stack.push([nr, nc])
    }
  }
}
```

```js
const img = [[1, 1, 1], [1, 1, 0], [1, 0, 1]]
floodFill(img, 1, 1, 2)
// img는 [[2, 2, 2], [2, 2, 0], [2, 0, 1]]
```

- `img[nr]?.[nc]`는 행이나 열이 범위를 벗어나면 `undefined`가 되어 `old`와 달라서 걸러집니다. 범위 검사와 색 확인을 한 번에 합니다.
- 칸의 색이 `old`인지 확인하는 것이 방문 확인을 겸합니다. 칸을 `color`로 바꾸면 더 이상 `old`가 아니라서 다시 들어가지 않습니다. 별도 `visited`가 필요 없습니다.
- 칸을 스택에 넣을 때 바로 색을 바꿉니다. 꺼낼 때 바꾸면 같은 칸이 여러 번 스택에 들어갑니다.
- 결과에서 오른쪽 아래 `1`은 상하좌우로 이어지지 않아 그대로입니다. 대각선(8방향)으로 이어지는 문제면 바뀝니다.
- 시간은 바뀌는 칸 수에 비례해서 O(HW), 스택이 한 번에 최대 칸 수만큼 쌓일 수 있습니다.

**흔한 실수:** `old === color`를 검사하지 않는 것입니다. 새 색이 원래 색과 같으면 칸을 바꿔도 `old`로 보여서 계속 스택에 넣어 무한 루프가 됩니다.

## 연결 요소

연결 요소는 DFS로 한 번에 방문되는 정점 묶음과 같습니다. 방문하지 않은 정점마다 DFS를 새로 시작하고, 그 시작 횟수가 연결 요소의 수입니다(개념은 35편).

정점마다 속한 요소의 번호를 `comp` 배열에 적어 두면 "두 정점이 같은 요소인가", "요소의 크기는 얼마인가"를 바로 답합니다.

```js
function components(n, adj) {
  const comp = new Int32Array(n + 1)   // 0이면 미방문
  let id = 0
  for (let s = 1; s <= n; s++) {
    if (comp[s]) continue
    comp[s] = ++id                     // 새 요소 번호
    const stack = [s]
    while (stack.length) {
      for (const v of adj[stack.pop()]) {
        if (!comp[v]) { comp[v] = id; stack.push(v) }
      }
    }
  }
  return comp
}
```

요소의 크기는 `comp`를 한 번 훑어 셉니다. 아래에서 `adj7`은 정점 7개, 간선 `1-2, 1-3, 2-4, 3-4, 5-6`으로 만든 인접 리스트입니다.

```js
const comp = components(7, adj7)  // 요소 3개
const size = Array(4).fill(0)    // 0번 칸은 비워 둔다
for (let v = 1; v <= 7; v++) size[comp[v]]++
// size는 [0, 4, 2, 1]
```

- `comp[v]`가 0이 아닌 것이 `visited`를 대신합니다. 요소 번호는 1부터 붙입니다.
- 위 코드는 순서가 필요 없는 용도라 넣을 때 표시하는 스택 방식을 썼습니다. 재귀로 써도 같습니다.
- 정점 7개, 간선 `1-2, 1-3, 2-4, 3-4, 5-6`이면 요소는 `{1, 2, 3, 4}`, `{5, 6}`, `{7}`로 3개입니다.
- 전체 시간은 O(V + E)입니다. 정점마다 DFS를 다시 돌리는 것처럼 보이지만 방문한 정점은 건너뛰므로 각 정점과 간선을 한 번씩만 처리합니다.
- 간선이 계속 추가되며 요소를 묻는 문제는 Union-Find가 낫습니다(자세히는 51편).

**흔한 실수:** 정점 1에서 한 번만 DFS를 하고 연결 요소가 하나라고 가정하는 것입니다. 고립된 정점은 간선이 없어도 연결 요소 하나입니다.

## 영역 개수 구하기

영역 개수는 격자에서 같은 종류의 칸이 상하좌우로 이어진 덩어리가 몇 개인지 세는 문제입니다. 격자 DFS에 연결 요소의 시작 횟수 세기를 결합합니다. 섬의 개수, 단지의 개수 같은 이름으로 나옵니다.

> `'1'`은 땅, `'0'`은 바다인 격자 문자열 배열이 주어진다. 상하좌우로 이어진 땅의 덩어리 수와 가장 큰 덩어리의 칸 수를 구한다.

먼저 한 영역의 칸 수를 세는 DFS입니다. 앞의 `walk`가 칸 수를 반환하게 바꾼 것입니다.

```js
function areaSize(grid, r, c, seen) {
  seen[r][c] = 1
  let size = 1
  for (let d = 0; d < 4; d++) {
    const nr = r + dr[d], nc = c + dc[d]
    if (nr < 0 || nr >= grid.length) continue
    if (nc < 0 || nc >= grid[0].length) continue
    if (grid[nr][nc] === '1' && !seen[nr][nc]) {
      size += areaSize(grid, nr, nc, seen)
    }
  }
  return size
}
```

모든 칸을 훑다가 방문하지 않은 땅을 만나면 영역이 하나 늘고, 그 칸에서 `areaSize`를 호출합니다.

```js
function countAreas(grid) {
  const h = grid.length, w = grid[0].length
  const seen = Array.from({ length: h },
    () => new Uint8Array(w))
  let count = 0, best = 0
  for (let r = 0; r < h; r++) {
    for (let c = 0; c < w; c++) {
      if (grid[r][c] !== '1' || seen[r][c]) continue
      count++                      // 새 영역의 시작
      best = Math.max(best, areaSize(grid, r, c, seen))
    }
  }
  return [count, best]
}
```

`['11000', '11010', '00100', '00011']`로 흐름을 봅니다.

| 시작 칸 | 이어진 땅 | 칸 수 | 누적 영역 수 |
|---------|-----------|-------|--------------|
| (0, 0) | (0,0) (0,1) (1,0) (1,1) | 4 | 1 |
| (1, 3) | (1,3) | 1 | 2 |
| (2, 2) | (2,2) | 1 | 3 |
| (3, 3) | (3,3) (3,4) | 2 | 4 |

영역은 4개이고 가장 큰 영역은 4칸입니다. `(1, 1)`과 `(2, 2)`는 대각선이라 서로 다른 영역입니다.

- 모든 칸을 한 번씩 보고, DFS는 각 땅 칸을 한 번씩만 방문하므로 O(HW)입니다.
- 8방향 연결이면 `(1, 1)`과 `(2, 2)`가 이어져 영역이 3개가 됩니다. 방향 배열만 바꿉니다.
- 영역의 개수 대신 크기들의 목록이 필요하면 `areaSize`의 반환값을 배열에 모아서 정렬합니다.
- 격자가 클 때는 `areaSize`를 스택 방식으로 바꿉니다. 이때 칸 수는 스택에서 꺼낼 때마다 센다.

**흔한 실수:** DFS 안에서 `count`를 올리는 것입니다. 영역 수는 DFS를 새로 시작한 횟수이고 DFS가 방문하는 칸마다 올리면 칸 수가 됩니다.

## DFS 경로 복원

DFS로 시작점에서 도착점까지의 경로를 구하려면 탐색 중 각 정점을 처음 발견한 이전 정점을 `parent`에 저장하고, 도착점에서 거슬러 올라갑니다(Parent 배열은 35편).

```js
function dfsParent(adj, u, visited, parent) {
  visited[u] = 1
  for (const v of adj[u]) {
    if (!visited[v]) {
      parent[v] = u            // v를 u에서 처음 발견
      dfsParent(adj, v, visited, parent)
    }
  }
}
```

앞의 예제 그래프(정점 1에서 시작)로 실행하면 `parent`는 다음과 같습니다.

| 정점 | 2 | 3 | 4 | 5 | 6 |
|------|---|---|---|---|---|
| `parent` | 1 | 1 | 2 | 4 | 3 |

```js
pathTo(parent, visited, 1, 5) // [1, 2, 4, 5]
pathTo(parent, visited, 1, 6) // [1, 3, 6]
```

`pathTo`는 `visited[t]`를 확인한 뒤 `t`에서 `parent`를 따라 `s`까지 모아 뒤집는 35편의 함수입니다.

- 5의 부모가 4이고 4의 부모가 2이며 2의 부모가 1이라서 `[1, 2, 4, 5]`입니다.
- DFS가 찾은 경로는 가장 짧다고 보장되지 않습니다. 정점 2에서 5로는 직접 이어져 있지만(`2-5`) 이웃 순서상 4를 거치는 경로가 먼저 발견되었습니다. 최단 경로는 BFS로 구합니다(자세히는 38편).
- 경로 위의 정점만 따로 관리하는 방법도 있습니다. 재귀 호출 전에 `path.push(v)`, 반환 후에 `path.pop()`을 하면 현재 경로가 `path`에 유지되고 도착점에 닿는 순간 `path`가 곧 경로입니다. `visited`를 끄지 않아야 전체가 O(V + E)입니다.
- 격자에서는 `parent`에 이전 칸을 `r * w + c` 정수로 저장합니다. 복원하면서 `Math.floor(x / w)`, `x % w`로 좌표를 되돌립니다.
- 시작점의 `parent`는 0(또는 -1)로 둡니다. 정점 번호가 0부터면 -1을 씁니다.

**흔한 실수:** 도달할 수 없는 도착점에 대해 `parent`를 따라가는 것입니다. 먼저 `visited[t]`를 확인합니다.

## 방문 순서와 진입·종료 시각

DFS의 방문 순서는 정점을 처음 방문한 순서(선행 순서, preorder)이고, 정점의 모든 이웃을 처리하고 반환한 순서가 후행 순서(postorder)입니다. 시각으로 기록하면 정점마다 진입 시각 `tin`과 종료 시각 `tout`이 생깁니다. 시간 한 칸씩 흐르는 카운터를 정점에 들어갈 때와 나올 때 모두 올립니다.

```js
function dfsTimes(adj, start, tin, tout) {
  const idx = new Int32Array(adj.length) // 다음에 볼 이웃 위치
  const stack = [start]
  let timer = 0
  tin[start] = timer++
  while (stack.length) {
    const u = stack[stack.length - 1]
    if (idx[u] < adj[u].length) {
      const v = adj[u][idx[u]++]
      if (tin[v] === -1) { tin[v] = timer++; stack.push(v) }
    } else {                         // 이웃을 모두 처리: 종료
      tout[u] = timer++; stack.pop()
    }
  }
}
```

`tin`은 `-1`로 채운 `Int32Array`, `tout`은 0으로 둔 `Int32Array`이고 둘 다 정점 수 + 1 길이로 만들어 넘깁니다. `-1`은 미방문을 뜻합니다.

예제 그래프에서 정점 1부터 실행한 결과입니다.

| 정점 | 1 | 2 | 3 | 4 | 5 | 6 |
|------|---|---|---|---|---|---|
| `tin` | 0 | 1 | 7 | 2 | 3 | 8 |
| `tout` | 11 | 6 | 10 | 5 | 4 | 9 |

- 진입 시각 순으로 정점을 나열한 `1, 2, 4, 5, 3, 6`이 선행 순서이고, 종료 시각 순으로 나열한 `5, 4, 2, 6, 3, 1`이 후행 순서입니다.
- 정점마다 구간 `[tin, tout]`을 만들면 두 정점의 구간은 서로 겹치지 않거나 한쪽이 다른 쪽을 완전히 포함합니다. 정점 `u`가 `v`의 조상(DFS 트리에서 위쪽)이면 `tin[u] < tin[v]`이고 `tout[v] < tout[u]`입니다.
- 조상·자손 관계를 상수 시간에 판별할 수 있어서 트리의 서브트리 질의에 씁니다(자세히는 67편). 이 카운터 방식에서 서브트리의 정점 수는 `(tout - tin + 1) / 2`입니다. 정점 2의 서브트리 `{2, 4, 5}`는 `(6 - 1 + 1) / 2 = 3`입니다.
- 진입 시각만 올리는 카운터를 쓰는 변형도 있습니다. 이때 `tout[u]`는 서브트리에서 마지막으로 진입한 정점의 `tin`이고 서브트리는 `tin[u]`부터 `tout[u]`까지의 연속 구간입니다. 문제와 코드의 정의를 맞춥니다.
- 간선의 종류도 시각으로 구분합니다. 이미 방문한 정점 `v`로 가는 간선 `u → v`는, `v`가 아직 종료되지 않았으면 조상으로 올라가는 역방향 간선(사이클의 증거)이고, 종료되었으면 순방향 간선이나 교차 간선입니다. 무방향 그래프에는 트리 간선과 역방향 간선만 있습니다(자세히는 37편).
- 후행 순서를 거꾸로 하면 DAG의 위상 순서입니다(자세히는 53편).

**흔한 실수:** 종료 시각을 정점을 스택에 넣을 때 기록하는 것입니다. 종료 시각은 모든 이웃을 처리하고 `pop`하는 순간이므로 이웃 위치를 기억하는 방식에서만 정확히 기록됩니다.

## 핵심 정리

- DFS는 갈 수 있는 데까지 깊이 들어갔다가 되돌아오는 탐색이며 인접 리스트에서 O(V + E), 인접 행렬에서 O(V²)입니다. 최단 거리는 보장하지 않습니다.
- 재귀 DFS는 코드가 짧지만 깊이가 큰 입력에서 `RangeError`가 나므로, 최악 깊이를 따져 스택 DFS로 바꿉니다. 이웃을 뒤에서부터 넣어야 재귀와 같은 순서가 되고, 반환 시점이 필요하면 이웃 위치를 기억하는 방식을 씁니다.
- `visited`는 정점에 처음 들어갈 때 표시하고 그래프 DFS에서는 끄지 않습니다. 격자는 방향 배열과 범위 검사로 이웃을 계산합니다.
- Flood Fill은 칸의 색 바꾸기가 방문 표시를 겸하며, 새 색이 원래 색과 같으면 먼저 반환해야 합니다.
- 연결 요소와 영역 개수는 방문하지 않은 정점(칸)마다 DFS를 시작한 횟수이고 전체 시간은 한 번 훑는 비용입니다.
- 경로는 `parent`를 도착점에서 거슬러 올라가 복원하고 DFS 경로는 최단이 아닙니다. 진입·종료 시각 구간은 서로 겹치지 않거나 포함하며 조상·자손 판별에 씁니다.
