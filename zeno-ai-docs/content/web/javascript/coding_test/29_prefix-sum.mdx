## 누적합 만들기

누적합(prefix sum)은 배열의 앞에서부터 원소를 더해 가며 각 위치까지의 합을 저장한 배열입니다. 구간 합 질의가 여러 번 들어올 때 매번 더하지 않으려고 미리 한 번 계산해 둡니다.

`p[i]`를 "원본의 앞 i개의 합"으로 정의하고 길이를 N + 1로 만듭니다. `p[0]`은 원소가 하나도 없는 합이므로 0입니다.

```js
function buildPrefix(a) {
  const p = new Array(a.length + 1).fill(0)
  for (let i = 0; i < a.length; i++) p[i + 1] = p[i] + a[i]
  return p
}
buildPrefix([3, 1, 4, 1, 5]) // [0, 3, 4, 8, 9, 14]
```

| i | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 원본 `a[i-1]` | - | 3 | 1 | 4 | 1 | 5 |
| `p[i]` | 0 | 3 | 4 | 8 | 9 | 14 |

- 점화식은 `p[i + 1] = p[i] + a[i]`입니다. 시간 O(N), 공간 O(N)입니다.
- 맨 앞의 0 덕분에 구간이 배열 맨 앞에서 시작해도 `p[-1]` 같은 경계 처리가 필요 없습니다.
- 쓰는 단서: 배열이 바뀌지 않고, 구간 합을 묻는 질의가 많습니다. 원소가 중간에 바뀌면 뒤의 값을 모두 고쳐야 해서 O(N)이 듭니다. 갱신과 질의가 섞이면 Fenwick Tree(64편)나 Segment Tree(62편)를 씁니다.

### 합이 커질 때

합이 `Number.MAX_SAFE_INTEGER`(2^53 − 1, 약 9.007 × 10^15)를 넘으면 정수가 정확하지 않습니다. 원소 최댓값 × 개수로 합의 상한을 먼저 계산합니다.

| 원소 최댓값 | 개수 | 합의 상한 | 안전한가 |
|-------------|------|-----------|----------|
| 10^9 | 10^5 | 10^14 | 안전 |
| 10^9 | 10^6 | 10^15 | 안전 |
| 10^9 | 10^7 | 10^16 | 넘침, BigInt 필요 |

- 합이 2^31 − 1을 넘을 수 있는데 `Int32Array`에 저장하면 비트가 잘려 값이 감깁니다(자세히는 05편).
- 숫자와 BigInt는 섞어 연산할 수 없어서 BigInt를 쓰려면 원소도 BigInt로 바꿔야 합니다(자세히는 02편).

```js
const p = new Int32Array(2)
p[1] = 2147483647 + 1
p[1] // -2147483648 (범위를 넘어 감김)
```

## 구간 합

구간 합 질의는 두 누적값의 차입니다. 앞에서 i개의 합에서 앞에서 j개의 합을 빼면 그 사이의 원소만 남습니다.

| 구간 표기 | 합 |
|-----------|----|
| 0부터 세는 닫힌 구간 `[l, r]` | `p[r + 1] - p[l]` |
| 반열린 구간 `[l, r)` | `p[r] - p[l]` |
| 1부터 세는 닫힌 구간 `[i, j]` | `p[j] - p[i - 1]` |

```js
function solution(a, queries) {
  const p = [0]
  for (const x of a) p.push(p[p.length - 1] + x)
  return queries.map(([l, r]) => p[r + 1] - p[l])
}
solution([3, 1, 4, 1, 5], [[1, 3], [0, 4]]) // [6, 14]
```

- `[1, 3]`은 `a[1] + a[2] + a[3] = 1 + 4 + 1`이고 `p[4] - p[1] = 9 - 3 = 6`입니다.
- 질의마다 반복문으로 더하면 O(NQ)입니다. 누적합은 준비에 O(N), 질의 하나에 O(1)이라서 전체 O(N + Q)입니다.
- 표준 입력 형식에서는 질의가 많으므로 결과를 모아 한 번에 출력합니다(자세히는 08편).

**흔한 실수:** 닫힌 구간에서 `p[r] - p[l]`을 쓰는 것입니다. 오른쪽 끝 원소가 빠집니다. 구간 표기(닫힌지, 0부터인지 1부터인지)를 먼저 정하고 표의 식을 그대로 씁니다.

```js
p[r] - p[l]         // ❌ [l, r) 합이다. a[r]이 빠진다
p[r + 1] - p[l]     // ✅ [l, r] 합
```

## 2차원 누적합

2차원 누적합은 격자의 왼쪽 위 모서리부터 `(r, c)`까지의 직사각형 합을 저장한 배열입니다(격자 표현은 17편). 행과 열 앞에 0을 한 줄씩 붙여 `(H + 1) × (W + 1)` 크기로 만듭니다.

`P[r][c]`는 "위쪽 r개 행, 왼쪽 c개 열로 이루어진 직사각형의 합"입니다.

```js
function build2D(g) {
  const H = g.length, W = g[0].length
  const P = Array.from({ length: H + 1 }, () =>
    Array(W + 1).fill(0))
  for (let r = 0; r < H; r++)
    for (let c = 0; c < W; c++)
      P[r + 1][c + 1] =
        g[r][c] + P[r][c + 1] + P[r + 1][c] - P[r][c]
  return P
}
```

점화식 `P[r+1][c+1] = g[r][c] + P[r][c+1] + P[r+1][c] - P[r][c]`의 각 항입니다.

- `g[r][c]`: 새로 추가되는 칸
- `P[r][c+1]`: 바로 위까지의 직사각형
- `P[r+1][c]`: 바로 왼쪽까지의 직사각형
- `P[r][c]`: 위와 왼쪽에 모두 포함되어 두 번 더해진 겹침 영역이라 한 번 뺀다

3 × 3 격자 `[[1,2,3],[4,5,6],[7,8,9]]`의 결과입니다.

| P | c=0 | c=1 | c=2 | c=3 |
|---|-----|-----|-----|-----|
| r=0 | 0 | 0 | 0 | 0 |
| r=1 | 0 | 1 | 3 | 6 |
| r=2 | 0 | 5 | 12 | 21 |
| r=3 | 0 | 12 | 27 | 45 |

`P[2][2] = 5 + P[1][2] + P[2][1] - P[1][1] = 5 + 3 + 5 - 1 = 12`입니다. 이 값은 왼쪽 위 2 × 2 칸의 합 `1 + 2 + 4 + 5 = 12`와 같습니다.

- 시간 O(HW), 공간 O((H + 1)(W + 1))입니다.
- 칸 수가 아주 크면 행마다 배열을 만드는 대신 `Float64Array` 하나에 `r * (W + 1) + c`로 저장합니다(자세히는 17편).
- 쓰는 단서: 격자에서 직사각형 영역의 합을 여러 번 묻습니다.

## 2차원 누적합 질의

직사각형 `(r1, c1)`부터 `(r2, c2)`까지(0부터 세는 닫힌 범위)의 합은 큰 직사각형에서 위쪽과 왼쪽을 빼고, 두 번 빠진 모서리를 한 번 되돌려 구합니다.

```js
function rectSum(P, r1, c1, r2, c2) {
  return P[r2 + 1][c2 + 1] - P[r1][c2 + 1]
       - P[r2 + 1][c1] + P[r1][c1]
}
// 위 3x3 격자에서
rectSum(P, 1, 1, 2, 2) // 28 (5 + 6 + 8 + 9)
rectSum(P, 0, 1, 1, 2) // 16 (2 + 3 + 5 + 6)
```

`rectSum(P, 1, 1, 2, 2)`는 `45 - 6 - 12 + 1 = 28`입니다.

| 항 | 뜻 |
|----|----|
| `P[r2+1][c2+1]` | 왼쪽 위 모서리부터 `(r2, c2)`까지 전체 |
| `P[r1][c2+1]` | 구간 위쪽에 있는 행들 (뺀다) |
| `P[r2+1][c1]` | 구간 왼쪽에 있는 열들 (뺀다) |
| `P[r1][c1]` | 위쪽과 왼쪽에서 두 번 빠진 모서리 (더한다) |

- 질의 하나가 O(1)이고, 질의 Q개는 O(Q)입니다. 직접 더하면 질의마다 O(HW)입니다.
- 질의 범위가 0행 또는 0열에서 시작해도 패딩 덕분에 `P[0][...]`, `P[...][0]`이 0이라 그대로 동작합니다.

**흔한 실수:** 질의 인덱스에 `+ 1`을 빠뜨리는 것입니다. `P[r2][c2]`로 쓰면 마지막 행과 열이 빠집니다. 1부터 세는 문제는 입력 직후 모두 1을 빼서 0부터 세는 인덱스로 바꾼 뒤 위 식을 씁니다.

## 차이 배열

차이 배열(difference array)은 구간 전체에 같은 값을 더하는 갱신을 O(1)에 처리하려고, 인접한 값의 차이만 저장하는 배열입니다. 누적합의 반대 방향입니다. 차이 배열의 누적합이 원래 배열입니다.

구간 `[l, r]`에 `v`를 더하려면 시작에서 `+v`, 끝 바로 다음에서 `-v`만 기록합니다.

```js
const d = new Array(6).fill(0) // 길이 N + 1 (N = 5)
function add(l, r, v) {
  d[l] += v
  d[r + 1] -= v
}
add(1, 3, 2)
add(2, 4, 1)
// d: [0, 2, 1, 0, -2, -1]
```

모든 갱신을 끝낸 뒤 한 번 누적하면 값이 복원됩니다.

```js
let run = 0
const a = []
for (let i = 0; i < 5; i++) {
  run += d[i]
  a.push(run)
}
// a: [0, 2, 3, 3, 1]
```

- `d[l]`의 `+v`가 누적되어 l 이후 모든 위치에 v가 더해지고, `d[r + 1]`의 `-v`가 r 다음 위치부터 그 효과를 지웁니다.
- 길이를 N + 1로 두면 `r`이 마지막 인덱스일 때 `d[r + 1]`이 범위를 벗어나지 않습니다.
- 갱신 M번과 복원이 합쳐 O(N + M)입니다. 갱신마다 구간을 훑으면 O(NM)입니다.
- 이미 값이 있는 배열 `b`의 차이 배열은 `d[0] = b[0]`, `d[i] = b[i] - b[i - 1]`입니다.

**제약:** 갱신을 모두 마친 뒤에야 값을 읽을 수 있습니다(오프라인 처리). 갱신과 조회가 번갈아 오면 Fenwick Tree(64편)를 씁니다.

## Imos 기법

Imos 기법(이모스법)은 차이 배열의 생각을 일반화해서, 구간마다 "시작에서 더하고 끝 다음에서 빼는" 기록을 모아 두었다가 마지막에 한 번 누적하는 방법입니다. 개념만 정리합니다.

1차원은 위의 차이 배열과 같습니다. 시간 구간 `[s, e)`에 사용자가 접속했다면 `d[s] += 1`, `d[e] -= 1`을 기록하고 누적하면 각 시각의 동시 접속자 수가 나옵니다(자세히는 55편).

2차원에서는 직사각형 하나에 네 모서리를 기록합니다.

```js
function addRect(d, r1, c1, r2, c2, v) {
  d[r1][c1] += v
  d[r1][c2 + 1] -= v
  d[r2 + 1][c1] -= v
  d[r2 + 1][c2 + 1] += v
}
```

- `d`는 `(H + 1) × (W + 1)` 크기입니다. 모서리 `(r2 + 1, c2 + 1)`이 범위를 넘지 않게 하려는 것입니다.
- 모든 갱신 뒤에 `d`에 2차원 누적합을 적용하면 칸별 값이 나옵니다. 위 `build2D(d)`를 호출하면 `P[r + 1][c + 1]`이 `(r, c)` 칸의 값입니다.
- 3 × 3 격자에서 `(0,0)–(1,1)`과 `(1,1)–(2,2)`에 각각 1을 더하면 복원 결과는 `[[1,1,0],[1,2,1],[0,1,1]]`입니다. 두 사각형이 겹치는 `(1,1)`만 2입니다.
- 좌표 범위가 10^9처럼 크면 배열을 만들 수 없어서 좌표 압축(54편)을 하거나 이벤트 정렬 방식인 Sweep Line(55편)을 씁니다.
- 쓰는 단서: 구간·직사각형에 값을 더하는 갱신이 매우 많고, 조회는 모두 끝난 뒤 한 번입니다.

## 누적 카운트

값의 합 대신 "조건을 만족하는 원소의 개수"를 누적하면 구간 안의 개수를 O(1)에 구할 수 있습니다. 조건에 맞으면 1, 아니면 0을 더하는 누적합입니다.

```js
const a = [2, 7, 4, 9, 5, 3]
const isOdd = [0]
for (const x of a) isOdd.push(isOdd.at(-1) + (x % 2))
// isOdd: [0, 0, 1, 1, 2, 3, 4]
isOdd[5] - isOdd[1] // 3 (구간 [1, 4]의 홀수 개수)
```

`at(-1)`은 ES2022 메서드이고, 구형 환경에서는 `isOdd[isOdd.length - 1]`로 씁니다.

종류가 여러 개이면 종류별로 누적 배열을 둡니다. 문자열에서 알파벳 26개 각각의 개수를 한 배열에 모아 둔 예입니다.

```js
const s = 'abaca'
const n = s.length
const cnt = new Int32Array((n + 1) * 26)
for (let i = 0; i < n; i++) {
  for (let k = 0; k < 26; k++)
    cnt[(i + 1) * 26 + k] = cnt[i * 26 + k]
  cnt[(i + 1) * 26 + s.charCodeAt(i) - 97]++
}
const count = (l, r, k) =>
  cnt[(r + 1) * 26 + k] - cnt[l * 26 + k]
count(0, 4, 0) // 3 ('a'는 코드 97 → k = 0)
count(1, 2, 0) // 1
```

- `cnt[i * 26 + k]`는 "앞 i글자에서 k번째 알파벳의 개수"입니다. `TypedArray`는 0으로 초기화되므로 `cnt[0..25]`가 0인 상태로 시작합니다.
- 메모리는 `(N + 1) × 종류 수`입니다. 종류가 많으면 질의에 나오는 값만 따로 모읍니다(자세히는 14편).
- 쓰는 단서: 구간 안의 특정 값(또는 문자) 개수를 여러 번 묻습니다. 구간의 서로 다른 값 개수는 이 방법으로 안 풀립니다(자세히는 31편, 65편).

## 누적합과 해시

누적합과 해시(Prefix Sum + Hash)는 구간 합이 정확히 K인 부분 배열의 개수를 한 번의 순회로 세는 방법입니다. 원소에 음수가 있어도 됩니다.

구간 `(i, j]`의 합이 K라는 말은 `p[j] - p[i] = K`, 즉 `p[i] = p[j] - K`라는 뜻입니다. 현재까지의 합 `sum`을 `p[j]`로 보고, 앞에서 본 누적값 중 `sum - K`가 몇 번 나왔는지 해시에 물어봅니다(해시는 10편).

```js
function countSubarrays(a, K) {
  const seen = new Map([[0, 1]]) // 빈 접두의 합 0
  let sum = 0, ans = 0
  for (const x of a) {
    sum += x
    ans += seen.get(sum - K) ?? 0
    seen.set(sum, (seen.get(sum) ?? 0) + 1)
  }
  return ans
}
countSubarrays([1, 2, -1, 3], 3) // 2
```

| x | sum | `sum - K` | `seen`에서 찾은 횟수 | ans |
|---|-----|-----------|---------------------|-----|
| 1 | 1 | -2 | 0 | 0 |
| 2 | 3 | 0 | 1 | 1 |
| -1 | 2 | -1 | 0 | 1 |
| 3 | 5 | 2 | 1 | 2 |

찾은 두 구간은 `[1, 2]`(합 3)와 `[3]`(합 3)입니다.

- 시간 O(N), 공간 O(N)입니다. 모든 시작점마다 끝점을 훑는 O(N²)보다 빠릅니다.
- `seen`에 `[0, 1]`을 먼저 넣어야 맨 앞에서 시작하는 구간을 셉니다.
- 조회를 먼저 하고 현재 값을 나중에 넣습니다. 순서를 바꾸면 K가 0일 때 빈 구간(자기 자신)을 셉니다.
- 키가 숫자라서 Object 대신 Map을 씁니다(Object는 키를 문자열로 바꿉니다. 자세히는 09편). 없는 키는 `undefined`이므로 `?? 0`으로 받습니다.
- 원소가 모두 양수일 때만 투 포인터(30편)로 같은 문제를 O(N)에 풀 수 있습니다. 음수가 있으면 구간을 늘려도 합이 단조롭지 않아서 누적합과 해시를 씁니다.

변형은 해시에 저장하는 값만 바꿉니다.

| 문제 | 해시 키 | 값 |
|------|---------|----|
| 합이 K인 구간 개수 | 누적합 | 나온 횟수 |
| 합이 K의 배수인 구간 개수 | 누적합을 K로 나눈 나머지 | 나온 횟수 |
| 합이 K인 가장 긴 구간 | 누적합 | 처음 나온 인덱스 |

배수 개수는 나머지가 같은 두 접두의 차가 K의 배수라는 성질을 씁니다. 음수 나머지는 보정합니다(자세히는 11편).

```js
function divCount(a, K) {
  const seen = new Map([[0, 1]])
  let sum = 0, ans = 0
  for (const x of a) {
    sum = (((sum + x) % K) + K) % K
    ans += seen.get(sum) ?? 0
    seen.set(sum, (seen.get(sum) ?? 0) + 1)
  }
  return ans
}
divCount([4, 5, 0, -2, -3, 1], 5) // 7
```

0과 1로 이루어진 배열에서 0과 1의 개수가 같은 가장 긴 구간은, 0을 -1로 바꿔 합이 0인 가장 긴 구간을 찾는 문제가 됩니다. 처음 나온 인덱스를 저장해 `현재 인덱스 - 처음 인덱스`의 최댓값을 구합니다.

## 역연산이 있는 연산의 누적

누적하는 방식이 통하는 조건은 연산에 역연산이 있는 것입니다. `p[r + 1] ⊕ p[l]`에서 앞부분을 "지울" 수 있어야 구간 값이 나옵니다.

| 연산 | 역연산 | 구간 값 | 가능한가 |
|------|--------|---------|----------|
| 덧셈 | 뺄셈 | `p[r+1] - p[l]` | 가능 |
| XOR | XOR 자기 자신 | `p[r+1] ^ p[l]` | 가능 |
| 곱셈 | 나눗셈 | `p[r+1] / p[l]` | 0이 없을 때, 나머지 연산에서는 모듈러 역원(57편) |
| 최솟값·최댓값, AND, OR, GCD | 없음 | - | 불가 |

기준은 "이미 들어간 값을 되돌릴 수 있는가"입니다. 최솟값은 앞부분을 빼도 남은 구간의 최솟값을 알 수 없어서 누적으로 구간 값을 만들 수 없습니다(Sparse Table은 65편, Segment Tree는 62편).

### XOR 누적

같은 값을 두 번 XOR하면 0이 되고(`x ^ x === 0`), 0과 XOR해도 값이 변하지 않습니다(`x ^ 0 === x`). 그래서 XOR은 자기 자신이 역연산입니다.

```js
const a = [1, 2, 3, 4]
const px = [0]
for (const x of a) px.push(px.at(-1) ^ x)
// px: [0, 1, 3, 0, 4]
const rangeXor = (l, r) => px[r + 1] ^ px[l]
rangeXor(1, 2) // 1 (2 ^ 3)
```

- 숫자의 `^`는 피연산자를 32비트 정수로 바꾸고 결과도 부호 있는 32비트 정수입니다. 2^31 이상인 값이 있으면 쓸 수 없고, 값이 BigInt이면 BigInt끼리 XOR합니다(`14n ^ 9n`은 `7n`). 숫자와 BigInt를 섞으면 TypeError입니다(자세히는 24편).
- 두 접두의 XOR이 같다면 그 사이 구간의 XOR은 0입니다. 합이 K인 구간을 세던 방식 그대로 XOR이 K인 구간을 해시로 셀 수 있습니다.

### 곱 누적

- 정수 곱의 누적은 값이 매우 빨리 커져서 Number의 정확한 범위(2^53 − 1)를 금방 넘습니다. 그래서 곱은 나머지를 취하며 다루는 문제가 많습니다(자세히는 57편).
- 0이 하나라도 있으면 그 뒤의 누적곱은 모두 0이라서 나눗셈으로 구간 곱을 구할 수 없습니다. 0의 개수를 따로 세거나 아래의 접두·접미 방식을 씁니다.

## 접두 누적과 접미 누적

접두 누적(prefix)은 왼쪽 끝에서 `i`까지, 접미 누적(suffix)은 `i`부터 오른쪽 끝까지의 결과를 저장합니다. 역연산이 없어도 쓸 수 있는 이유는 구간을 만들지 않고, 각 위치의 왼쪽 전체와 오른쪽 전체를 따로 합쳐 쓰기 때문입니다.

접미 합은 뒤에서부터 만듭니다. 길이 N + 1에 끝을 0으로 둡니다.

```js
const a = [3, 1, 4, 1, 5]
const suf = new Array(a.length + 1).fill(0)
for (let i = a.length - 1; i >= 0; i--)
  suf[i] = suf[i + 1] + a[i]
// suf: [14, 11, 10, 6, 5, 0] (suf[i] = a[i..N-1]의 합)
```

### 자기 자신을 제외한 곱

나눗셈 없이 `a[i]`를 뺀 나머지의 곱을 모두 구합니다. 왼쪽 곱과 오른쪽 곱을 곱합니다. 0이 있어도 맞습니다.

```js
function exceptSelf(a) {
  const n = a.length, res = new Array(n).fill(1)
  let left = 1, right = 1
  for (let i = 0; i < n; i++) {
    res[i] = left
    left *= a[i]
  }
  for (let i = n - 1; i >= 0; i--) {
    res[i] *= right
    right *= a[i]
  }
  return res
}
exceptSelf([1, 2, 3, 4]) // [24, 12, 8, 6]
exceptSelf([1, 0, 3])    // [0, 3, 0]
```

- 첫 순회에서 `res[i]`에 `a[i]` 왼쪽 원소의 곱을, 둘째 순회에서 오른쪽 원소의 곱을 곱합니다. 추가 배열 없이 O(N) 시간, 결과 배열 외 O(1) 공간입니다.

### 접두 최댓값과 접미 최댓값

최댓값은 역연산이 없어서 구간 값은 못 구하지만, 접두 최댓값과 접미 최댓값은 만들 수 있습니다. 각 칸이 담을 수 있는 물의 양은 왼쪽 최댓값과 오른쪽 최댓값 중 작은 쪽에서 자기 높이를 뺀 값입니다(빗물 담기 유형).

```js
function trap(h) {
  const n = h.length, L = [h[0]], R = []
  for (let i = 1; i < n; i++)
    L[i] = Math.max(L[i - 1], h[i])
  R[n - 1] = h[n - 1]
  for (let i = n - 2; i >= 0; i--)
    R[i] = Math.max(R[i + 1], h[i])
  let water = 0
  for (let i = 0; i < n; i++)
    water += Math.min(L[i], R[i]) - h[i]
  return water
}
trap([3, 0, 2, 0, 4]) // 7
```

| i | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| `h` | 3 | 0 | 2 | 0 | 4 |
| `L` | 3 | 3 | 3 | 3 | 4 |
| `R` | 4 | 4 | 4 | 4 | 4 |
| 물 | 0 | 3 | 1 | 3 | 0 |

- 시간 O(N), 공간 O(N)입니다.
- 쓰는 단서: "자기 자신을 제외한", "왼쪽 전체와 오른쪽 전체를 함께 본다" 같은 표현입니다.

## 핵심 정리

- 누적합 `p[i + 1] = p[i] + a[i]`를 앞에 0을 두고 만들면 닫힌 구간 `[l, r]`의 합은 `p[r + 1] - p[l]`이고 질의가 O(1)입니다.
- 2차원은 `(H + 1) × (W + 1)` 배열로 만들고, 직사각형 합은 큰 직사각형에서 위·왼쪽을 빼고 겹친 모서리를 더합니다.
- 구간 갱신은 차이 배열(`d[l] += v`, `d[r + 1] -= v`)로 기록한 뒤 한 번 누적해 복원하며, 2차원 확장이 Imos 기법입니다.
- 누적 카운트는 조건에 맞으면 1을 더해 구간 안의 개수를 구하고, 누적합과 해시는 `p[i] = p[j] - K`를 해시로 찾아 음수가 있어도 합이 K인 구간을 O(N)에 셉니다.
- 누적이 통하는 연산은 역연산이 있는 덧셈·XOR이며, 최솟값·최댓값·GCD는 안 됩니다.
- 합은 2^53 − 1을 넘는지, `Int32Array`에서 감기지 않는지 상한을 먼저 계산합니다.
