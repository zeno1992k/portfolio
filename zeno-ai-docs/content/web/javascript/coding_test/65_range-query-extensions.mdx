## Range Minimum Query

RMQ(Range Minimum Query)는 배열 `a`에서 구간 `[l, r]`의 최솟값을 묻는 질의입니다. 최댓값 질의(RMaxQ)도 부호만 다를 뿐 같은 문제입니다.

최솟값은 합과 달리 **되돌릴 수 없는 연산**입니다. 누적합(29편)은 `prefix[r] - prefix[l - 1]`로 구간 합을 구하지만, 최솟값에는 "빼기"에 해당하는 연산이 없어서 같은 방식을 쓸 수 없습니다.

| 방법 | 준비 | 질의 | 값 변경 |
|------|------|------|---------|
| 반복문으로 직접 | 없음 | O(N) | O(1) |
| Segment Tree(62편) | O(N) | O(log N) | O(log N) |
| Sparse Table | O(N log N) | O(1) | 불가 |
| Sqrt Decomposition | O(N) | O(√N) | O(√N) |

- 배열이 질의 중에 바뀌지 않고 질의가 많으면 Sparse Table이 가장 빠릅니다.
- 값이 바뀌면 Segment Tree를 씁니다.
- 직접 반복하는 방법은 `N × Q`번 계산합니다. N과 Q가 10^5이면 10^10번이라 시간 초과입니다.

**문제의 단서:** "배열이 주어지고", "구간의 최솟값(최댓값)을 Q번 묻는다", 값 변경이 없으면 정적 RMQ입니다.

## Sparse Table

Sparse Table은 **길이가 2의 거듭제곱인 모든 구간의 답을 미리 계산해 두는** 표입니다. 임의의 구간은 길이가 같은 두 개의 2의 거듭제곱 구간으로 덮을 수 있어서, 최솟값 질의가 O(1)입니다.

`st[k][i]`를 구간 `[i, i + 2^k - 1]`의 최솟값으로 정의합니다. 길이 `2^k`인 구간은 앞쪽 절반과 뒤쪽 절반으로 나뉘므로 점화식은 다음과 같습니다.

- `st[0][i] = a[i]`
- `st[k][i] = min(st[k-1][i], st[k-1][i + 2^(k-1)])`

```js
function buildSparse(a) {
  const n = a.length
  const K = 32 - Math.clz32(n)          // floor(log2 n) + 1
  const st = [Int32Array.from(a)]
  for (let k = 1; k < K; k++) {
    const prev = st[k - 1]
    const len = n - (1 << k) + 1        // 시작점이 될 수 있는 칸 수
    const cur = new Int32Array(len)
    for (let i = 0; i < len; i++) {
      cur[i] = Math.min(prev[i], prev[i + (1 << (k - 1))])
    }
    st.push(cur)
  }
  return st
}
```

질의는 구간 길이 `len = r - l + 1`에서 `2^k <= len`인 가장 큰 k를 구해, 왼쪽 끝에서 시작하는 구간과 오른쪽 끝에서 끝나는 구간을 합칩니다. 두 구간은 겹쳐도 됩니다.

```js
function queryMin(st, l, r) {            // [l, r] 닫힌 구간
  const k = 31 - Math.clz32(r - l + 1)   // floor(log2(길이))
  return Math.min(st[k][l], st[k][r - (1 << k) + 1])
}
```

`a = [5, 2, 4, 7, 1, 3, 6, 8]`의 표입니다.

| k | st[k] (시작점 0부터) |
|---|----------------------|
| 0 | 5 2 4 7 1 3 6 8 |
| 1 | 2 2 4 1 1 3 6 |
| 2 | 2 1 1 1 1 |
| 3 | 1 |

- `queryMin(st, 1, 5)`: 길이 5이므로 `k = 2`. `min(st[2][1], st[2][2]) = min(1, 1) = 1`입니다. 각각 `[1, 4]`와 `[2, 5]`를 덮고 `2, 4, 7, 1, 3`의 최솟값이 1입니다.
- `queryMin(st, 0, 2)`: 길이 3이므로 `k = 1`. `min(st[1][0], st[1][1]) = min(2, 2) = 2`입니다.

구현 규칙입니다.

- `Math.clz32(x)`는 32비트 정수 `x`의 앞쪽 0의 개수를 돌려줍니다. 그래서 `31 - Math.clz32(x)`가 `floor(log2 x)`이고, 로그 표를 따로 만들 필요가 없습니다.
- 준비는 O(N log N), 질의는 O(1)이고 메모리는 O(N log N)입니다. N이 10^6이면 표는 약 2×10^7칸이므로 `Int32Array`로 만들어 메모리를 줄입니다(자세히는 14편).
- 값이 바뀌면 표 전체를 다시 만들어야 합니다. 값 변경이 있으면 쓰지 않습니다.
- 구간의 위치(인덱스)를 구해야 하면 값이 아니라 인덱스를 담고, 비교를 `a[인덱스]`로 합니다.

**흔한 실수:**

- `K`를 너무 작게 잡아서 가장 긴 구간의 층이 빠지는 것입니다. `n = 8`이면 `k = 3`까지 필요하고 위 식의 `K`는 4입니다.
- `len`을 `n - (1 << k)`로 쓰면 마지막 시작점이 하나 빠집니다. 시작점은 `0`부터 `n - 2^k`까지 `n - 2^k + 1`개입니다.
- 질의 구간을 반열린 구간 `[l, r)`로 받으면서 위 식을 그대로 쓰는 것입니다. 위 식은 닫힌 구간 기준이라 길이가 `r - l + 1`입니다.

## Idempotent Operation

멱등 연산(idempotent operation)은 **같은 값에 두 번 적용해도 결과가 같은 연산**입니다. `f(x, x) = x`가 성립하면 멱등입니다.

| 멱등 연산 | 멱등이 아닌 연산 |
|-----------|------------------|
| 최솟값, 최댓값 | 합 |
| 최대공약수(gcd) | 곱 |
| 비트 AND, 비트 OR | 비트 XOR |

Sparse Table의 O(1) 질의가 가능한 이유가 여기에 있습니다. 두 구간이 겹쳐도 겹친 원소가 두 번 계산될 뿐이고, 멱등이면 결과가 달라지지 않습니다. `[1, 4]`와 `[2, 5]`를 합친 최솟값이 `[1, 5]`의 최솟값과 같은 이유입니다.

멱등이 아닌 연산은 겹치면 틀립니다. 합은 겹친 원소가 두 번 더해집니다. 이때는 구간을 겹치지 않게 큰 조각부터 이어 붙여서 질의가 O(log N)입니다.

```js
function querySum(st, l, r) {            // st는 합으로 만든 표
  let sum = 0
  for (let k = st.length - 1; k >= 0; k--) {
    if (l + (1 << k) - 1 <= r) {         // 길이 2^k 조각이 들어가면
      sum += st[k][l]
      l += 1 << k
    }
  }
  return sum
}
```

- 구간 길이를 이진수로 쓴 것과 같습니다. 길이 13이면 8 + 4 + 1로 세 조각입니다.
- 합은 누적합이 O(1)이라서 Sparse Table을 쓸 이유가 없습니다. 멱등이 아니면서 되돌릴 수도 없는 연산(예: 행렬 곱)에서 이 방식이 의미를 가집니다.
- gcd 구간 질의는 멱등이라 Sparse Table로 O(1)에 풀립니다. 비교 대신 `gcd(x, y)`로 합칩니다.

**문제의 단서:** 구간 연산이 최솟값·최댓값·gcd·AND·OR이고 값 변경이 없으면 Sparse Table입니다.

## Sqrt Decomposition

Sqrt Decomposition(제곱근 분할)은 **배열을 크기 `B = √N` 정도의 블록으로 나눠 블록마다 답을 저장**하는 기법입니다. 구간 질의는 양 끝의 잘린 조각을 원소 단위로, 가운데의 온전한 블록을 블록 단위로 처리합니다. 질의와 갱신이 모두 O(√N)입니다.

```js
const B = Math.ceil(Math.sqrt(n))
const block = new Array(Math.ceil(n / B)).fill(0)
for (let i = 0; i < n; i++) block[(i / B) | 0] += a[i]

function update(i, v) {                  // a[i]를 v로 바꾸기
  block[(i / B) | 0] += v - a[i]
  a[i] = v
}
```

```js
function query(l, r) {                   // [l, r] 닫힌 구간의 합
  let sum = 0
  while (l <= r) {
    if (l % B === 0 && l + B - 1 <= r) { // 온전한 블록
      sum += block[l / B]
      l += B
    } else {                             // 잘린 조각
      sum += a[l]
      l++
    }
  }
  return sum
}
```

- 잘린 조각은 양쪽에 각각 B개 미만이고, 온전한 블록은 N / B개 이하입니다. B가 √N일 때 둘의 합이 가장 작아집니다.
- 블록에 저장하는 값을 바꾸면 다른 연산도 됩니다. 블록의 최솟값을 저장하면 구간 최솟값이 됩니다. 이때 값 변경은 해당 블록을 처음부터 다시 계산해서 O(B)입니다.
- **구간 갱신**도 됩니다. 블록마다 "이 블록 전체에 더할 값" `lazy[b]`를 두고, 온전한 블록은 `lazy`만 바꾸고 잘린 조각은 원소를 직접 바꿉니다. 구간 덧셈은 O(√N)입니다. Lazy Propagation(63편)과 같은 발상을 블록 단위로 한 것입니다.
- 코딩테스트에서는 Segment Tree가 더 빠르지만, 합칠 수 없는 정보(블록 안 값의 개수 분포 등)를 블록이 직접 들고 있어야 하는 문제에서 쓰입니다.

**흔한 실수:**

- 블록 번호를 `i / B`로 쓰는 것입니다. JavaScript의 나눗셈은 실수라서 `(i / B) | 0` 또는 `Math.floor`가 필요합니다.
- 마지막 블록이 B보다 짧을 수 있는데 `l + B - 1 <= r`을 확인하지 않고 블록을 통째로 쓰는 것입니다.

## Mo's Algorithm 개요

Mo 알고리즘은 **질의를 정해진 순서로 재배열해, 구간의 양 끝을 한 칸씩 움직이며 답을 갱신하는** 기법입니다. 갱신 없는 구간 질의에서 "구간에 원소 하나를 추가하거나 빼는" 연산이 O(1)이면 전체 O((N + Q)√N)에 풀립니다.

핵심은 질의 `[l, r]`의 답에서 다음 질의 `[l', r']`의 답으로 넘어갈 때 **구간을 처음부터 다시 세지 않고 양 끝만 옮긴다**는 것입니다. 옮기는 거리의 합이 작아지도록 질의 순서를 정합니다.

- `l`을 크기 `B = √N`의 블록으로 나눕니다.
- 같은 블록의 질의끼리 모아 `r` 오름차순으로 정렬합니다.
- 한 블록 안에서 `l`은 B 안에서만 움직여서 질의당 O(B), `r`은 한 블록에서 N 이하로 움직이고 블록이 √N개라서 전체 O(N√N)입니다.
- 블록 번호가 홀수인 블록은 `r`을 내림차순으로 정렬하면 포인터가 되돌아가는 낭비가 줄어듭니다(홀짝 정렬).

구간 `[l, r]`의 서로 다른 값의 개수를 묻는 예입니다. 값은 `0`부터 `N`까지로 압축돼 있다고 합니다(54편).

```js
function mo(a, queries) {  // queries[i] = [l, r]
  const B = Math.max(1, Math.floor(Math.sqrt(a.length)))
  const ord = queries.map((_, i) => i)
  ord.sort((x, y) => {
    const bx = (queries[x][0] / B) | 0
    const by = (queries[y][0] / B) | 0
    if (bx !== by) return bx - by
    return bx % 2 ? queries[y][1] - queries[x][1]
                  : queries[x][1] - queries[y][1]
  })
  // 이어서 포인터를 움직이며 답을 구한다
}
```

```js
let curL = 0, curR = -1, distinct = 0   // 현재 구간은 비어 있음
const cnt = new Int32Array(a.length + 1)
const ans = new Array(queries.length)
const add = (i) => { if (cnt[a[i]]++ === 0) distinct++ }
const del = (i) => { if (--cnt[a[i]] === 0) distinct-- }
for (const qi of ord) {
  const [l, r] = queries[qi]
  while (curL > l) add(--curL)           // 먼저 넓히고
  while (curR < r) add(++curR)
  while (curL < l) del(curL++)           // 그다음 좁힌다
  while (curR > r) del(curR--)
  ans[qi] = distinct
}
```

- 반드시 **넓히는 이동을 먼저, 좁히는 이동을 나중에** 합니다. 반대로 하면 구간이 비거나 `curL > curR`가 되어 `cnt`가 음수가 될 수 있습니다.
- 답은 원래 질의 번호 `qi`에 저장하고 마지막에 그 순서로 출력합니다.
- 시간은 `add`·`del`이 O(1)일 때 O((N + Q)√N)입니다. N과 Q가 10^5이면 약 6×10^7번의 포인터 이동으로, 계산이 가벼우면 통과 가능한 크기입니다.
- 값 변경이 있으면 쓸 수 없습니다. 값 변경까지 넣은 변형(시간 축을 더하는 방식)은 있지만 이 문서에서는 다루지 않습니다.
- 구간의 답을 `add`와 `del`로 O(1)에 관리할 수 없으면(예: 구간 최솟값) 쓸 수 없습니다.
- 정렬 비교 함수에 `queries[x][0] / B`를 그대로 쓰면 실수 비교가 되어 블록이 어긋나므로 `| 0`으로 정수화합니다(자세히는 26편).

**문제의 단서:** "구간 안에서 서로 다른 값의 개수", "구간의 빈도 제곱합", 질의는 오프라인이고 값 변경이 없으며 N, Q가 10^5 정도입니다.

## Offline Query

오프라인 쿼리는 **질의를 전부 읽은 뒤, 풀기 편한 순서로 재배열해 답하고 원래 순서로 되돌리는** 방식입니다. 질의가 하나씩 들어와 바로 답해야 하는 온라인 방식과 구별합니다. 입력이 한 번에 주어지는 코딩테스트는 거의 모두 오프라인으로 풀 수 있습니다.

| 재배열 기준 | 이용하는 성질 | 예 |
|-------------|---------------|----|
| 오른쪽 끝 `r` 오름차순 | `r`까지의 원소만 반영한 상태로 답한다 | 구간 내 서로 다른 값의 개수 |
| 값(임계값) 오름차순 | 임계값 이하의 원소만 켠 상태로 답한다 | 구간에서 x 이하의 개수 |
| 블록과 `r`(Mo) | 구간 끝을 조금씩 이동한다 | 구간 빈도 질의 |
| 시간 역순 | 삭제를 추가로 바꾼다(51편) | 간선 삭제 후 연결 여부 |

`r` 기준 정렬로 서로 다른 값의 개수를 구하는 방법입니다. 왼쪽부터 원소를 하나씩 보면서, 각 값의 **가장 최근 위치에만 1을 놓습니다**. 같은 값이 다시 나오면 이전 위치의 1을 지우고 새 위치에 놓습니다. 그러면 `[l, r]`의 서로 다른 값의 개수는 현재까지 놓인 1 중 위치가 `l` 이상인 것의 개수이고, Fenwick Tree(64편)의 구간 합입니다.

```js
const bit = new Int32Array(n + 1)
const add = (i, v) => {                  // i번째에 v 더하기
  for (i++; i <= n; i += i & -i) bit[i] += v
}
const sum = (i) => {                     // [0, i]의 합
  let s = 0
  for (i++; i > 0; i -= i & -i) s += bit[i]
  return s
}
```

```js
const byR = Array.from({ length: n }, () => [])
// r별로 질의 번호를 묶는다
queries.forEach(([, r], qi) => byR[r].push(qi))
const last = new Int32Array(n + 1).fill(-1)  // 값의 마지막 위치
const ans = new Array(queries.length)
for (let i = 0; i < n; i++) {
  if (last[a[i]] !== -1) add(last[a[i]], -1)
  add(i, 1)
  last[a[i]] = i
  for (const qi of byR[i]) {
    ans[qi] = sum(i) - sum(queries[qi][0] - 1)
  }
}
```

- 정렬 대신 `r`별로 질의를 묶어 두면 정렬 없이 순서대로 처리됩니다.
- 시간은 O((N + Q) log N)이고 Mo보다 빠르지만, "가장 최근 위치에만 놓는" 성질을 만들 수 있는 문제에서만 가능합니다.
- 질의 번호를 들고 다니지 않으면 답의 순서가 뒤섞입니다. 모든 오프라인 풀이는 질의 번호를 함께 저장합니다.

**문제의 단서:** 질의가 한꺼번에 주어지고, 값 변경 없이 "구간에서 ~의 개수"를 묻습니다.

## Difference Array + Range Update

차분 배열(difference array)은 **구간 덧셈을 양 끝의 두 칸 수정으로 바꾸는** 배열입니다. 구간 `[l, r]`에 `v`를 더하는 일을 `d[l] += v`, `d[r + 1] -= v` 두 번으로 기록하고, 모든 갱신이 끝난 뒤 누적합을 한 번 구하면 최종 배열이 나옵니다.

```js
const d = new Array(n + 1).fill(0)   // r + 1 접근 때문에 n + 1칸
for (const [l, r, v] of updates) {
  d[l] += v
  d[r + 1] -= v
}
for (let i = 1; i < n; i++) d[i] += d[i - 1]
// d[i]가 최종 값. 갱신 하나당 O(1), 전체 O(N + U)
```

- 누적합(29편)의 역연산입니다. 누적합 배열을 만들면 차분 배열이 계산됩니다.
- **갱신이 모두 끝난 뒤에 질의**할 수 있을 때만 씁니다. 갱신과 질의가 섞이면 질의할 때마다 누적합이 필요해서 O(N)입니다.
- 갱신과 질의가 섞여 있으면 Fenwick Tree(64편)의 "구간 갱신, 점 질의" 또는 Lazy Propagation(63편)을 씁니다.

2차원 격자에서 직사각형 `(r1, c1)–(r2, c2)`에 `v`를 더하는 일은 모서리 네 칸으로 기록합니다.

```js
d[r1][c1] += v
d[r1][c2 + 1] -= v
d[r2 + 1][c1] -= v
d[r2 + 1][c2 + 1] += v
// 마지막에 2차원 누적합을 구한다(29편)
```

- 배열은 `(R + 1) × (C + 1)`칸으로 만들어 `r2 + 1`, `c2 + 1` 접근이 범위 밖이 되지 않게 합니다.
- 2차원 누적합 식은 위쪽과 왼쪽을 더하고 겹친 왼쪽 위를 한 번 뺍니다(17편, 29편).

**흔한 실수:**

- `d`를 `n`칸으로 만드는 것입니다. `r`이 마지막 인덱스이면 `d[r + 1]`이 범위 밖인데, `Int32Array`는 범위 밖 쓰기를 에러 없이 무시해서 결과가 조용히 틀립니다.
- 구간이 닫힌 구간인지 반열린 구간인지 헷갈려 `r` 대신 `r + 1`을 빼는 것입니다.

## 2D Fenwick Tree 개요

2차원 Fenwick Tree는 **Fenwick Tree를 행과 열 양쪽에 겹쳐 만든 구조**입니다. 칸 하나의 값 변경과 `(0, 0)`부터 `(r, c)`까지의 직사각형 합이 모두 O(log N × log M)이고 메모리는 O(N × M)입니다(N, M은 행과 열의 수).

```js
const t = Array.from({ length: n + 1 },
  () => new Float64Array(m + 1))
function add(r, c, v) {                  // 칸 (r, c)에 v를 더한다
  for (let i = r + 1; i <= n; i += i & -i)
    for (let j = c + 1; j <= m; j += j & -j) t[i][j] += v
}
function prefix(r, c) {          // (0,0)–(r,c) 직사각형 합
  let s = 0
  for (let i = r + 1; i > 0; i -= i & -i)
    for (let j = c + 1; j > 0; j -= j & -j) s += t[i][j]
  return s
}
```

임의의 직사각형 `(r1, c1)–(r2, c2)`의 합은 포함-배제로 구합니다.

```js
const rect = (r1, c1, r2, c2) =>
  prefix(r2, c2) - prefix(r1 - 1, c2)
  - prefix(r2, c1 - 1) + prefix(r1 - 1, c1 - 1)
// prefix(-1, c)와 prefix(r, -1)은 반복문이 돌지 않아 0
```

- 1차원 Fenwick의 `i += i & -i`, `i -= i & -i` 반복을 바깥과 안쪽에 한 번씩 쓴 것이 전부입니다.
- 값 변경이 없으면 2차원 누적합(29편)이 O(1)이라 더 간단합니다. 값이 바뀔 때만 2D Fenwick을 씁니다.
- 합처럼 되돌릴 수 있는 연산에만 쓸 수 있습니다. 최솟값은 포함-배제가 안 되므로 2D Segment Tree가 필요합니다.
- N × M이 크면(10^6칸 이상) 메모리가 부담이므로 `Float64Array` 대신 값 범위가 맞으면 `Int32Array`를 씁니다.

## 2D Segment Tree 개요

2차원 Segment Tree는 **행 방향 Segment Tree의 각 노드가 열 방향 Segment Tree를 하나씩 갖는** 구조입니다. 직사각형 질의는 행 트리를 내려가며 걸리는 O(log N)개 노드마다 열 트리에 질의해서 O(log N × log M)입니다. 메모리는 O(N × M)이 필요합니다.

- 바깥 트리의 노드는 **그 노드가 맡은 행 구간 전체**의 정보를 열 방향 트리로 담습니다. 안쪽 트리의 칸 `c`는 그 행 구간에서 열 `c`에 있는 모든 칸의 합(또는 최솟값)입니다.
- 한 칸을 바꾸면 바깥 트리에서 그 행을 포함하는 노드들(O(log N)개)의 안쪽 트리를 각각 한 칸씩 갱신합니다. 바깥이 리프이면 칸의 값을 그대로 쓰고, 바깥이 내부 노드이면 두 자식의 안쪽 트리 같은 칸을 결합해서 다시 계산합니다.
- 합뿐 아니라 최솟값, 최댓값, gcd 등 결합할 수 있는 연산이면 모두 됩니다. 2D Fenwick이 못 하는 부분입니다.
- 구현이 길고 상수가 커서, 코딩테스트에서는 격자의 크기가 작거나(예: 1000 × 1000 이하) 연산이 합이 아닐 때만 고려합니다.
- 질의에 맞춰 안쪽 트리를 필요한 좌표만 저장하는 압축 방식은 메모리를 O(N log N)으로 줄이지만, 새 점을 넣는 갱신을 효율적으로 하지 못합니다.

**문제의 단서:** 격자의 칸 값이 바뀌고 직사각형의 합·최솟값을 묻습니다. 합이면 2D Fenwick, 최솟값이면 2D Segment Tree입니다.

## Merge Sort Tree 개요

Merge Sort Tree는 **Segment Tree의 각 노드에 그 구간의 원소를 정렬해 저장한** 구조입니다. 합병 정렬의 합치기 과정을 트리로 남겨 둔 모양입니다. "구간 `[l, r]`에서 x 이하(또는 초과)인 원소의 개수"를 O(log² N)에 답합니다. 메모리는 O(N log N)입니다.

```js
function build(node, lo, hi) {   // tree[node]는 정렬된 배열
  if (lo === hi) { tree[node] = [a[lo]]; return }
  const mid = (lo + hi) >> 1
  build(node * 2, lo, mid)
  build(node * 2 + 1, mid + 1, hi)
  tree[node] = merge(tree[node * 2], tree[node * 2 + 1])
}
```

```js
function countLE(node, lo, hi, l, r, x) {  // x 이하의 개수
  if (r < lo || hi < l) return 0
  if (l <= lo && hi <= r) return upperBound(tree[node], x)
  const mid = (lo + hi) >> 1
  return countLE(node * 2, lo, mid, l, r, x)
       + countLE(node * 2 + 1, mid + 1, hi, l, r, x)
}
```

- `merge`는 정렬된 두 배열을 합치는 함수(27편), `upperBound`는 x보다 큰 첫 위치를 찾는 이분 탐색(28편)입니다.
- 질의가 걸치는 노드는 O(log N)개이고, 각 노드에서 이분 탐색이 O(log N)입니다.
- 준비는 각 층의 총 원소 수가 N이고 층이 log N개라서 O(N log N)입니다.
- 값 변경에는 약합니다. 원소 하나가 바뀌면 그 원소를 담은 O(log N)개 노드의 정렬 배열을 고쳐야 하는데 각각 O(길이)입니다.
- 구간의 k번째로 작은 값은 이 구조로는 효율적으로 구하기 어렵습니다. 그 문제는 아래 Persistent Segment Tree가 맡습니다.

## Persistent Segment Tree 개요

Persistent Segment Tree는 **값을 바꿀 때 기존 노드를 고치지 않고 바뀐 경로의 노드만 새로 만들어, 이전 버전을 모두 보존하는** Segment Tree입니다. 한 번의 갱신에 새 노드가 O(log N)개만 생겨서 N번의 갱신 뒤에도 메모리는 O(N log N)입니다. 안 바뀐 부분은 이전 버전의 노드를 그대로 가리킵니다.

대표 활용은 **구간의 K번째 수**입니다. 값을 `0`부터 `m - 1`로 압축하고, 버전 `i`를 "`a[0]`부터 `a[i-1]`까지의 값을 센 트리"로 만듭니다. 구간 `[l, r]`의 값 분포는 버전 `r + 1`에서 버전 `l`의 개수를 뺀 것입니다.

```js
const L = [0], R = [0], C = [0]          // 노드 0은 빈 트리
function insert(prev, lo, hi, x) {       // 값 x를 하나 넣은 새 버전
  const cur = L.length
  L.push(L[prev]); R.push(R[prev]); C.push(C[prev] + 1)
  if (lo < hi) {
    const mid = (lo + hi) >> 1
    if (x <= mid) L[cur] = insert(L[prev], lo, mid, x)
    else R[cur] = insert(R[prev], mid + 1, hi, x)
  }
  return cur                             // 새 루트 번호
}
```

```js
function kth(u, v, lo, hi, k) {  // 버전 v에서 u를 뺀 분포
  while (lo < hi) {
    const mid = (lo + hi) >> 1
    const left = C[L[v]] - C[L[u]]       // 왼쪽 값 범위의 개수
    if (k <= left) { u = L[u]; v = L[v]; hi = mid }
    else { k -= left; u = R[u]; v = R[v]; lo = mid + 1 }
  }
  return lo                              // 압축된 값
}
// roots[0] = 0
// roots[i + 1] = insert(roots[i], 0, m - 1, a[i])
// a[l..r]의 k번째 = kth(roots[l], roots[r + 1], 0, m - 1, k)
```

- `L`, `R`, `C`는 노드의 왼쪽 자식, 오른쪽 자식, 담긴 개수입니다. 객체를 노드마다 만들지 않고 배열 세 개로 두면 메모리와 속도에서 유리합니다.
- 질의는 트리를 한 번 내려가서 O(log N)입니다. 오프라인으로 풀 수도 있지만 질의가 온라인으로 와도 되는 것이 장점입니다.
- `insert` 한 번에 노드가 `log m + 1`개 안팎으로 생겨서 N번이면 `N × (log m + 1)`개입니다. N이 10^5이면 수백만 개이므로, 크기를 미리 잡은 `Int32Array`를 쓰는 편이 안전합니다.
- 압축한 값은 질의 결과를 원래 값으로 되돌리는 배열이 필요합니다(54편).

**문제의 단서:** "구간에서 K번째로 작은 수"를 온라인으로 묻거나, "과거 버전의 상태"를 질의합니다.

## 자료구조 선택 기준

먼저 값이 바뀌는지, 질의가 한꺼번에 주어지는지, 연산이 합처럼 되돌릴 수 있는지를 묻습니다. 그다음 N과 Q의 크기로 시간을 계산합니다.

| 상황 | 선택 | 질의 시간 |
|------|------|-----------|
| 값 변경 없음, 구간 합 | 누적합(29편) | O(1) |
| 값 변경 없음, 최솟값·최댓값·gcd | Sparse Table | O(1) |
| 값 변경 없음, 구간 내 서로 다른 값 | 오프라인 + Fenwick 또는 Mo | O(log N) 또는 O(√N) |
| 점 변경, 구간 합 | Fenwick Tree(64편) | O(log N) |
| 점 변경, 구간 최솟값 등 | Segment Tree(62편) | O(log N) |
| 구간 변경, 구간 질의 | Lazy Propagation(63편) | O(log N) |
| 구간 변경이 모두 질의 앞에 | 차분 배열 | O(1) (준비 후) |
| 질의가 한꺼번에 주어지고 add·del이 O(1) | Mo 알고리즘 | O(√N) |
| 격자에서 점 변경, 직사각형 합 | 2D Fenwick | O(log N × log M) |
| 격자에서 점 변경, 직사각형 최솟값 | 2D Segment Tree | O(log N × log M) |
| 구간에서 x 이하의 개수 | Merge Sort Tree | O(log² N) |
| 구간 K번째 수, 과거 버전 | Persistent Segment Tree | O(log N) |

선택 순서는 다음과 같습니다.

- 값이 바뀌지 않으면 정적 구조(누적합, Sparse Table)부터 봅니다. 가장 빠르고 구현이 짧습니다.
- 값이 바뀌고 연산이 합이면 Fenwick Tree가 Segment Tree보다 짧고 빠릅니다.
- 연산이 합이 아니거나 구간 갱신이 있으면 Segment Tree(Lazy 포함)입니다.
- 정보를 합칠 수 없고 add·del로만 관리되면 Mo입니다. 그것도 안 되면 Sqrt Decomposition을 의심합니다.
- 질의를 모아서 풀 수 있으면 오프라인 처리로 구조를 단순하게 만들 수 있는지 먼저 따져 봅니다.

**제한 조건으로 판단하기:**

- N, Q가 10^5이면 O(log N)이나 O(√N)이 모두 통과합니다. O(N)은 `N × Q`로 10^10이라 안 됩니다.
- N, Q가 10^6이면 O(√N) 풀이는 10^9 근처라 위험하고 O(log N)이 필요합니다.
- JavaScript에서는 숫자 배열을 `Int32Array`나 `Float64Array`로 만들면 메모리와 속도 모두 이득입니다(자세히는 14편).

## 핵심 정리

- RMQ는 최솟값이 되돌릴 수 없는 연산이라 누적합이 안 통합니다. 값 변경이 없으면 Sparse Table(준비 O(N log N), 질의 O(1))이고, `Math.clz32`로 로그를 구합니다.
- Sparse Table의 O(1)은 두 구간이 겹쳐도 되는 멱등 연산(min, max, gcd, AND, OR)에서만 성립합니다. 합 같은 연산은 O(log N)입니다.
- Sqrt Decomposition은 블록 크기 √N으로 질의와 갱신을 O(√N)에 처리하고, Mo 알고리즘은 질의를 블록 순으로 정렬해 O((N + Q)√N)에 처리합니다.
- 오프라인 쿼리는 질의를 모아 정렬하고 질의 번호로 답을 되돌립니다. 차분 배열은 구간 덧셈을 두 칸 수정으로 바꾸지만 질의가 갱신 뒤에 있을 때만 씁니다.
- 2D Fenwick은 합에, 2D Segment Tree는 합·최솟값 등 결합 가능한 연산에 쓰이고 질의가 O(log N × log M)입니다. Merge Sort Tree는 구간 내 개수를, Persistent Segment Tree는 구간 K번째 수와 과거 버전을 맡습니다.
