## 문제 문장에서 알고리즘 단서 찾기

문제 문장에는 구하는 것(최소, 최대, 개수, 가능 여부), 대상의 구조(배열, 격자, 그래프, 구간), 허용된 동작(이동, 선택, 질의)이 들어 있습니다. 이 세 가지가 알고리즘 후보를 정합니다. 77편의 입력 크기가 후보의 복잡도 천장을 정한다면, 이 편의 단서는 후보의 종류를 정합니다.

| 문장의 단서 | 후보 | 이 편의 절 |
|-------------|------|-----------|
| 연속한 구간의 합·길이·개수 | 누적합, 투 포인터, 슬라이딩 윈도우 | 연속 구간 |
| 최소 몇 번·몇 칸 만에 도달 | BFS | 최단 횟수 |
| 이동마다 비용이 다름 | 0-1 BFS, Dijkstra | 가중치 최단거리 |
| 모든 쌍 사이의 거리 | Floyd-Warshall | 모든 쌍 최단거리 |
| 같은 집합인가, 연결되는가 | Union-Find | 연결 여부 |
| A를 한 뒤에 B를 해야 한다 | 위상 정렬 | 선수 관계 |
| 구간 질의가 많고 값이 바뀐다 | 세그먼트 트리, 펜윅 트리 | 구간 Query |
| 최댓값을 최소로, 최솟값을 최대로 | 답에 대한 이분 탐색 | 최솟값의 최댓값 |
| 각 항목을 고른다·고르지 않는다 | DP, 백트래킹 | 선택과 미선택 |
| 같은 부분 문제가 반복된다 | DP | 중복 부분문제 |
| 지금 가장 좋은 것을 고르면 전체가 최적 | Greedy | Greedy가 가능한 구조 |

- 단서는 후보를 줄이는 용도입니다. 하나로 확정하려면 입력 크기, 가중치, 갱신 여부 같은 조건으로 후보를 가릅니다.
- 문장의 표현만으로 판단하면 틀립니다. 같은 "최소"라도 최소 횟수, 최소 비용, 최소화한 최댓값은 서로 다른 알고리즘입니다.
- 읽는 순서는 구하는 것 → 구조 → 가중치와 제약 → 77편의 입력 크기입니다. 후보가 둘 이상이면 아래 각 절의 구분 기준을 적용합니다.
- 어떤 후보도 맞지 않으면 문제를 그래프나 상태 공간으로 바꿔 봅니다(84편).

## 연속 구간: Prefix Sum, Two Pointer, Sliding Window

"연속한 부분 배열", "구간의 합", "연속한 K개"라는 표현은 배열을 구간으로 다루는 세 후보를 부릅니다. 가르는 기준은 구간 길이가 고정인지, 값에 음수가 있는지, 질의가 여러 번인지입니다.

| 조건 | 후보 | 편 |
|------|------|-----|
| 구간 합을 여러 번 묻는다(갱신 없음) | 누적합 | 29편 |
| 길이가 정확히 K인 모든 구간 | 슬라이딩 윈도우 | 31편 |
| 원소가 모두 양수이고 합이 K 이상·이하인 구간, 최소·최대 길이 | 투 포인터 | 30편 |
| 음수가 섞인 배열에서 합이 정확히 K인 구간 | 누적합과 `Map` | 29편 |

- 투 포인터는 구간을 늘리면 합이 커지고 줄이면 작아진다는 단조성이 필요합니다. 음수가 있으면 단조성이 깨져서 쓸 수 없습니다.
- 음수가 있으면 구간 합을 "누적합의 차"로 바꿉니다. 현재까지의 누적합이 `sum`이면 합이 k인 구간의 개수는 이전에 `sum - k`가 나온 횟수입니다.

```js
const seen = new Map([[0, 1]])
let sum = 0, count = 0
for (const x of a) {
  sum += x
  count += seen.get(sum - k) ?? 0
  seen.set(sum, (seen.get(sum) ?? 0) + 1)
}
// a = [1, 2, -1, 1, 1, -2], k = 2 이면 count는 5
```

- 세 방법의 시간은 전처리와 한 번 훑는 O(N)입니다. 모든 구간을 직접 보는 O(N²)이 N ≤ 10^5에서 막힐 때 바꿉니다.
- 구간이 "연속"이 아니라 "부분 수열"이면 순서만 지키고 건너뛸 수 있으므로 이 세 후보가 아니라 DP를 봅니다(42편).

**흔한 실수:** 음수가 있는 배열에 투 포인터를 쓰는 것입니다. 구간을 늘려도 합이 줄 수 있어서 포인터를 한쪽으로만 움직이는 논리가 성립하지 않습니다.

## 최단 횟수: BFS

"최소 몇 번 만에", "가장 적은 이동으로", "몇 단계 만에"는 모든 이동의 비용이 같은 그래프에서의 최단 경로입니다. BFS는 시작점에서 가까운 칸부터 단계별로 퍼져 나가므로 처음 도착한 시점이 곧 최소 횟수입니다(자세히는 38편).

- 신호는 격자 이동, 한 번에 한 단계 바꾸기(문자 하나 바꾸기, 숫자에 연산 하나 적용), 간선 가중치가 모두 같은 그래프입니다.
- 이동 횟수가 최소라는 표현이 있으면 DFS가 아니라 BFS입니다. DFS는 먼저 찾은 경로가 최단이라는 보장이 없습니다.
- 대상이 격자나 그래프처럼 보이지 않아도 "상태"를 정점으로, "한 번의 동작"을 간선으로 보면 BFS가 됩니다. 상태에 위치 외의 정보(열쇠, 벽 부순 횟수)가 들어가는 경우입니다(자세히는 39편).
- 복잡도는 정점 수 V와 간선 수 E에 대해 O(V + E)입니다.

**흔한 실수:** 이동 비용이 서로 다른 그래프에 BFS를 쓰는 것입니다. BFS는 간선 개수가 최소인 경로를 주지 비용이 최소인 경로를 주지 않습니다. 다음 절의 기준으로 가릅니다.

## 가중치 최단거리: 0-1 BFS와 Dijkstra

이동마다 비용이 있는 그래프의 최단 거리입니다. 가중치의 종류가 후보를 가릅니다.

| 간선 가중치 | 후보 | 시간 | 편 |
|-------------|------|------|-----|
| 모두 같음 | BFS | O(V + E) | 38편 |
| 0 또는 1만 있음 | 0-1 BFS | O(V + E) | 48편 |
| 0 이상 일반 값 | Dijkstra | O((V + E) log V) | 48편 |
| 음수 간선이 있음 | Bellman-Ford | O(V × E) | 49편 |

- 0-1 BFS는 덱을 씁니다. 비용 0 간선으로 이동하면 앞에, 비용 1 간선이면 뒤에 넣어서 거리 순서를 유지합니다. 같은 문제를 Dijkstra로도 풀 수 있지만 0-1 BFS가 더 빠르고 짧습니다.
- 비용이 "벽을 부수면 1, 아니면 0"처럼 두 종류일 때 0-1 BFS가 자연스럽습니다.
- Dijkstra는 음수 간선이 있으면 틀립니다. 한 번 확정한 거리를 나중에 더 줄일 수 있기 때문입니다.
- 음수 사이클이 있으면 최단 거리가 정의되지 않으므로 사이클 탐지가 문제의 일부일 수 있습니다(자세히는 49편).
- 비용이 클 때 합이 Number 안전 범위를 넘는지도 확인합니다(77편).

## 모든 쌍 최단거리: Floyd-Warshall

"모든 도시 쌍 사이의 최단 거리", "모든 정점에서 모든 정점으로"는 단일 출발이 아니라 모든 쌍입니다.

- 정점 수 N이 500 이하이면 O(N³)의 Floyd-Warshall이 가장 단순합니다(77편, 자세히는 49편). 점화식 하나와 삼중 반복문으로 끝납니다.
- N이 커서 N³이 불가능하면 출발점마다 Dijkstra를 돌립니다. 시간은 N × (V + E) log V입니다. 간선이 적은 희소 그래프에서만 현실적입니다.
- 출발점이 하나이거나 질의 몇 개로 주어지면 모든 쌍을 구할 필요가 없습니다. 출발점 수만큼 Dijkstra를 돌립니다.
- 음수 간선이 있어도 음수 사이클이 없으면 Floyd-Warshall은 동작합니다. 정점 쌍 사이에 경로가 없는 경우를 무한대 값으로 표현해야 합니다.

**흔한 실수:** 질의가 한두 개인데 N³을 돌리는 것입니다. 출발점이 정해져 있으면 단일 출발 최단 경로를 씁니다.

## 연결 여부: Union-Find

"A와 B가 같은 그룹인가", "연결되어 있는가", "그룹의 개수는"은 집합을 합치고 같은 집합인지 묻는 구조입니다. Union-Find는 합치기(union)와 찾기(find)를 거의 상수 시간에 처리합니다(자세히는 51편).

- 신호는 간선이 하나씩 추가되며 그때마다 연결 여부를 묻는 문제, 친구 관계의 그룹 수, 같은 집합 여부 질의입니다.
- 간선이 처음부터 모두 주어지고 한 번만 묻는다면 DFS나 BFS로 연결 요소를 세어도 같은 답입니다(자세히는 35편). 합치기와 질의가 번갈아 나올 때 Union-Find가 유리합니다.
- 간선 가중치를 정렬해 합치면 최소 신장 트리(52편)가 됩니다. "모든 정점을 최소 비용으로 연결"이라는 문장이 신호입니다.
- 간선이 삭제되는 문제는 Union-Find가 직접 지원하지 않습니다. 질의를 거꾸로 읽어 삭제를 추가로 바꾸는 방법을 씁니다.

## 선수 관계: Topological Sort

"A를 먼저 해야 B를 할 수 있다", "선행 과목", "작업 순서"는 방향 그래프의 순서 제약입니다. 간선 A → B를 "A가 B보다 먼저"로 읽고 위상 정렬로 순서를 구합니다(자세히는 53편).

- 신호는 선후 관계가 쌍으로 주어지고, 가능한 순서 하나를 출력하거나 모든 일을 끝낼 수 있는지 묻는 경우입니다.
- 순서를 만들 수 없으면(사이클이 있으면) 불가능이라고 답합니다. 위상 정렬은 사이클 판별도 겸합니다.
- 선후 관계 위에서 최소 소요 시간, 최대 경로 길이를 묻는 문제는 위상 순서대로 DP를 합니다. DAG에서는 순서대로 한 번 훑으면 되어서 O(V + E)입니다.
- 순서를 묻지 않고 "각 정점에서 도달 가능한가"만 묻는다면 DFS·BFS로 충분합니다.

## 구간 Query: Segment Tree와 Fenwick Tree

"구간의 합·최솟값·최댓값을 구하라"와 "값을 바꿔라"가 섞여서 N, Q가 각각 10^5 안팎일 때입니다. 질의마다 O(N)으로 구간을 훑으면 O(N × Q)라서 불가능합니다(77편).

| 조건 | 후보 | 편 |
|------|------|-----|
| 갱신 없음, 구간 합 | 누적합 | 29편 |
| 갱신 없음, 구간 최솟값·최댓값 | Sparse Table 등 | 65편 |
| 점 갱신 + 구간 합 | 펜윅 트리(짧고 빠름) | 64편 |
| 점 갱신 + 구간 최솟값·최댓값 등 | 세그먼트 트리 | 62편 |
| 구간 전체에 더하기 + 구간 질의 | Lazy Propagation | 63편 |

- 펜윅 트리는 합처럼 뒤집을 수 있는(빼서 되돌릴 수 있는) 연산에 쓰이고, 세그먼트 트리는 합, 최솟값, 최댓값 등 결합 법칙만 성립하는 연산에도 쓸 수 있습니다.
- 두 자료구조 모두 질의와 갱신이 각각 O(log N)입니다.
- 갱신이 없다면 이 자료구조는 과합니다. 가장 단순한 도구(누적합)부터 확인합니다.

## 최솟값의 최댓값, 최댓값의 최솟값: Parametric Search

"최댓값을 최소로 만들어라", "가장 짧은 간격을 최대로 하라"처럼 어떤 값의 극단을 다시 극단으로 만드는 문장은 답을 이분 탐색하는 신호입니다(자세히는 28편).

- 핵심은 답 x에 대한 판정 문제로 바꾸는 것입니다. "최댓값이 x 이하가 되도록 만들 수 있는가"의 답은 x가 커질수록 거짓에서 참으로 한 번만 바뀝니다. 이 단조성이 있으면 경계를 이분 탐색으로 찾습니다.
- 판정은 보통 그리디나 단순 반복으로 O(N)에 합니다. 전체는 O(N log(답의 범위))입니다.

```js
// 구간 K개 이하로 나눌 때 구간 합의 최댓값을 최소로
function canSplit(a, K, x) {
  let parts = 1, cur = 0
  for (const v of a) {
    if (v > x) return false
    if (cur + v > x) { parts++; cur = 0 }
    cur += v
  }
  return parts <= K
}
```

```js
let lo = 0, hi = 32     // 답의 범위 (a의 합 이상)
while (lo < hi) {
  const mid = lo + Math.floor((hi - lo) / 2)
  if (canSplit([7, 2, 5, 10, 8], 2, mid)) hi = mid
  else lo = mid + 1
}
// lo는 18
```

- 최솟값을 최대로(예: 인접한 두 점 사이의 최소 거리를 최대화)이면 참인 x 중 가장 큰 값을 찾습니다. 이때는 `mid`를 올림해야 무한 루프를 피합니다.
- 반복 횟수는 답의 범위가 10^9이면 약 30번입니다. 한 번의 판정이 O(N)이면 30 × N이라서 N이 10^5여도 여유롭습니다.

**흔한 실수:** 판정이 단조가 아닌데 이분 탐색을 쓰는 것입니다. x가 커졌는데 "가능"이 "불가능"으로 돌아가는 구간이 있으면 경계가 하나로 정해지지 않습니다.

## 선택과 미선택: DP와 Backtracking

"각 항목을 고르거나 고르지 않는다"는 부분집합 구조입니다. 두 후보를 가르는 기준은 구하는 것이 값인지 해 자체인지, 그리고 상태가 겹치는지입니다.

| 조건 | 후보 | 편 |
|------|------|-----|
| 최적값·경우의 수·가능 여부만 묻는다, 상태가 겹친다 | DP | 40편, 41편 |
| 해(조합, 순열) 자체를 모두 출력하거나 조건을 만족하는 해를 찾는다 | 백트래킹 | 23편 |
| N이 20 이하이고 상태가 단순하다 | 완전탐색, 비트마스크 | 24편 |
| N이 40 안팎이다 | Meet In The Middle | 72편 |

- 2^N 가지를 일일이 만들어야 하는 문제는 백트래킹입니다. 값(최대 가치, 경우의 수)만 필요하고 "지금까지 고른 것 중 중요한 정보만" 상태로 줄일 수 있으면 DP입니다.
- 배낭 문제(무게 제한 안에서 가치 최대)는 선택·미선택 구조지만 상태를 (몇 번째 물건, 남은 무게)로 줄여 DP로 풉니다(자세히는 41편).
- 값의 범위가 커서 DP 상태 수를 만들 수 없고 N이 작으면 완전탐색이나 MITM으로 갑니다(77편).

## 중복 부분문제와 최적 부분구조 찾기

DP를 쓸 수 있는 문제는 두 가지 구조를 가집니다.

- 중복 부분문제(overlapping subproblems): 큰 문제를 쪼갠 작은 문제가 같은 인자로 반복해서 나타납니다.
- 최적 부분구조(optimal substructure): 전체의 최적해가 부분 문제의 최적해로 만들어집니다.

재귀 풀이를 쓰고 호출 트리에 같은 인자가 반복되는지 보면 첫 번째 구조를 확인할 수 있습니다.

```js
let calls = 0
function fib(n) {
  calls++
  return n < 2 ? n : fib(n - 1) + fib(n - 2)
}
fib(5)   // calls는 15
fib(30)  // calls는 2692537 (fib(30)은 한 값인데 호출은 수백만 번)
```

- `fib(5)`의 호출 트리에서 `fib(3)`이 두 번 이상 나옵니다. 결과를 저장해 두고 재사용하면 호출 수가 N에 비례합니다(메모이제이션, 40편).
- 두 구조가 모두 있으면 DP입니다. 부분 문제의 답을 합쳐도 전체 답이 안 되면(최적 부분구조가 없으면) DP가 아닙니다. 예를 들어 두 정점 사이의 가장 긴 단순 경로는 부분 경로의 최적해를 이어도 단순 경로가 아닐 수 있어서 이 구조를 갖지 않습니다.
- 상태가 겹치지 않는다면(분할한 부분이 서로 독립이면) DP가 아니라 분할 정복입니다(25편).
- DP로 확정하려면 상태 정의를 쓰고(`dp[i]`가 무엇인지), 점화식을 쓰고, 상태 수 × 전이 비용이 77편의 허용 범위인지 계산합니다.

## Greedy가 가능한 구조 찾기

Greedy는 매 단계에서 지금 가장 좋은 선택을 하고 되돌리지 않는 방법입니다. 빠르지만 항상 맞지는 않아서 구조가 맞는지 확인하는 것이 핵심입니다(자세히는 33편).

- 탐욕 선택 속성: 지금의 최선 선택을 포함하는 최적해가 항상 존재합니다. 최선 선택으로 바꿔도 전체가 나빠지지 않는다는 교환 논증으로 확인합니다.
- 최적 부분구조: 선택한 뒤 남은 문제가 같은 형태의 작은 문제입니다.
- 신호는 정렬 기준이 하나 떠오르는 문제입니다. 회의실 배정(끝나는 시각 순), 단위가 배수 관계인 거스름돈, 가장 작은 것부터 합치기가 대표입니다.
- 확신이 없으면 작은 입력으로 완전탐색과 비교합니다(80편). 반례를 직접 만드는 것이 가장 빠른 검증입니다(15편).

```js
// 큰 동전부터 쓰는 Greedy
function greedy(coins, target) {
  let count = 0
  for (const c of [...coins].sort((x, y) => y - x)) {
    count += Math.floor(target / c)
    target %= c
  }
  return count
}
greedy([1, 5, 10, 50], 63) // 5 (50 + 10 + 1 + 1 + 1, 최적)
greedy([1, 3, 4], 6)       // 3 (4 + 1 + 1, 최적은 3 + 3으로 2)
```

- 같은 코드가 동전 단위에 따라 맞기도 틀리기도 합니다. 단위가 서로 배수가 아니면 반례가 생기므로 이 경우는 DP(41편)로 풉니다.
- Greedy와 DP의 구분: 선택을 되돌릴 필요가 없다는 증명이 있으면 Greedy, 증명할 수 없거나 반례가 있으면 DP입니다.

**흔한 실수:** 예제 몇 개에서 맞았다는 이유로 Greedy를 확정하는 것입니다. 예제는 반례가 나오지 않게 고른 입력일 수 있어서 증명이나 완전탐색 비교가 필요합니다.

## 핵심 정리

- 문제 문장에서 구하는 것, 구조, 허용된 동작을 읽어 후보를 정하고 입력 크기(77편)로 거릅니다.
- 연속 구간은 누적합·투 포인터(양수만)·슬라이딩 윈도우(길이 고정)이고, 음수가 섞인 구간 합은 누적합과 `Map`입니다.
- 최소 횟수는 BFS, 비용이 0 또는 1이면 0-1 BFS, 비음수 일반 비용이면 Dijkstra, 모든 쌍이면 Floyd-Warshall(N ≤ 500)입니다.
- 연결 여부와 그룹은 Union-Find, 선후 관계와 순서는 위상 정렬, 갱신이 있는 구간 질의는 펜윅 트리·세그먼트 트리입니다.
- 극단값의 극단값은 답에 대한 이분 탐색(단조인 판정 필요)이고, 선택·미선택 구조는 상태가 겹치면 DP, 해를 열거하면 백트래킹입니다.
- DP는 중복 부분문제와 최적 부분구조가, Greedy는 탐욕 선택 속성이 있어야 하고 반례를 만들어 검증합니다.
