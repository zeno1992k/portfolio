## Bellman-Ford

Bellman-Ford는 **한 시작점에서 모든 정점까지의 최단거리**를 구하는 알고리즘입니다. 음수 간선이 있어도 동작합니다. 모든 간선을 한 바퀴씩 훑으며 거리를 줄이는 일을 V - 1번 반복합니다(V는 정점 수, E는 간선 수).

간선 `(u, v, w)`를 보고 `dist[u] + w < dist[v]`이면 `dist[v]`를 줄이는 동작을 **이완**(relaxation)이라고 합니다. Dijkstra(48편)도 같은 이완을 쓰지만 이완할 간선을 우선순위 큐로 고릅니다. Bellman-Ford는 고르지 않고 전부 시도합니다.

```js
function bellmanFord(n, edges, src) {
  const dist = new Array(n).fill(Infinity)
  dist[src] = 0
  for (let i = 0; i < n - 1; i++) {
    let changed = false
    for (const [u, v, w] of edges) {
      if (dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w
        changed = true
      }
    }
    if (!changed) break          // 한 바퀴 동안 변화가 없으면 끝
  }
  return dist
}
```

- `edges`는 `[출발, 도착, 가중치]` 배열의 목록입니다(간선 리스트, 35편). 무방향 간선은 양방향으로 두 번 넣습니다.
- 도달하지 못한 정점은 `Infinity`로 남습니다. JavaScript에서 `Infinity + w`는 `Infinity`이므로 `Infinity < Infinity`가 거짓이 되어 별도 검사 없이도 안전합니다. 유한한 큰 수를 INF로 쓰면 이 검사가 필요합니다(자세히는 50편).
- 시간복잡도는 O(VE), 공간복잡도는 O(V + E)입니다.

### 왜 V - 1번이면 충분한가

음수 사이클이 없으면 최단 경로는 같은 정점을 두 번 지나지 않으므로 **간선이 최대 V - 1개**입니다. k번째 바퀴가 끝나면 간선 k개 이하로 닿는 최단 경로가 모두 확정됩니다. 간선을 훑는 순서가 나빠도 한 바퀴에 최소한 경로 한 칸은 전진합니다.

간선 순서를 일부러 거꾸로 둔 예입니다. 시작점은 0입니다.

| 바퀴 | 처리하는 간선 (순서대로) | dist 결과 |
|------|--------------------------|-----------|
| 시작 | - | 0, ∞, ∞, ∞ |
| 1 | 2→3(4), 1→2(-3), 0→1(4), 0→2(5) | 0, 4, 5, ∞ |
| 2 | 같은 순서 | 0, 4, 1, 9 |
| 3 | 같은 순서 | 0, 4, 1, 5 |

- 1바퀴에서는 2→3과 1→2가 앞에 있어서 아직 닿지 못한 정점이라 이완이 일어나지 않습니다.
- 경로 0→1→2→3은 간선이 3개라서 정확히 3바퀴가 걸렸습니다. 4번째 바퀴는 변화가 없습니다.
- 간선을 경로 순서대로 놓으면 한 바퀴에 끝나기도 합니다. 최악은 V - 1바퀴입니다.

**언제 쓰는가:** 음수 간선이 있는 단일 시작점 최단거리, 음수 사이클 판정. 단서는 "비용이 음수일 수 있다", "무한히 줄어드는지 판단하라", "시간을 되돌린다"입니다.

**흔한 실수:**

- 반복 횟수를 정점 수가 아니라 간선 수로 잡아서 시간이 늘어나는 것입니다. 바퀴 수는 V - 1이고, 한 바퀴의 비용이 E입니다.
- 간선 목록을 `[u, v, w]` 순서가 아닌 `[u, w, v]`로 넣어서 가중치와 도착 정점이 바뀌는 것입니다.

## 음수 간선

음수 간선은 이동하면 거리가 **줄어드는** 간선입니다. 보상, 환급, 시간 되돌리기, 이익이 있는 거래가 해당합니다.

Dijkstra는 **우선순위 큐에서 꺼낸 정점의 거리는 확정이다**라는 가정에 기대는데, 이 가정은 이후에 더하는 간선이 모두 0 이상일 때만 성립합니다. 음수 간선이 있으면 이미 확정한 정점을 나중에 줄일 수 있습니다.

```js
// 0→1 (2), 0→2 (3), 2→1 (-4)
// 0에서 1까지 실제 최단거리: 0→2→1 = -1
// 정점을 확정(visited)하는 Dijkstra: 1을 먼저 확정해 2를 반환
// Bellman-Ford: 0, -1, 3
```

- 확정 표시를 하는 Dijkstra는 틀린 값을 냅니다. 확정 표시 없이 `d > dist[u]`일 때만 건너뛰는 구현은 갱신될 때마다 정점을 다시 처리해서 값은 맞을 수 있지만, 같은 정점을 여러 번 처리하므로 시간복잡도 보장이 사라집니다.
- 모든 가중치에 상수를 더해 음수를 없애는 방법은 쓸 수 없습니다. 예를 들어 경로 A는 가중치 1인 간선 1개이고 경로 B는 간선 3개 `-1, 1, 0`(합 0)이면 B가 더 짧습니다. 전부 1을 더하면 A는 2, B는 3이 되어 순위가 뒤집힙니다. 간선 수가 다른 경로에는 더해지는 횟수가 다르기 때문입니다.
- 무방향 그래프에 음수 간선이 하나라도 있으면 그 간선을 왔다 갔다 하는 음수 사이클이 생깁니다. 무방향 그래프의 음수 간선은 최단거리가 정의되지 않습니다.

방향 그래프에서 음수 간선이 있어도 **음수 사이클이 없으면** 최단거리는 정상적으로 정의됩니다. 이때는 Bellman-Ford가 정답을 줍니다.

## 음수 사이클

음수 사이클은 한 바퀴 돌면 가중치 합이 음수인 사이클입니다. 돌 때마다 거리가 줄어서 그 사이클을 지나갈 수 있는 정점의 최단거리는 **-∞**입니다(정의되지 않음).

### 판정

음수 사이클이 없으면 V - 1바퀴 안에 모든 거리가 확정되므로 **V번째 바퀴에서도 이완이 일어나면** 시작점에서 닿을 수 있는 음수 사이클이 있습니다.

```js
function hasNegativeCycle(n, edges, src) {
  const dist = new Array(n).fill(Infinity)
  dist[src] = 0
  for (let i = 0; i < n - 1; i++)
    for (const [u, v, w] of edges)
      if (dist[u] + w < dist[v]) dist[v] = dist[u] + w
  for (const [u, v, w] of edges)
    if (dist[u] + w < dist[v]) return true   // V번째 바퀴
  return false
}
```

- 시작점에서 **닿지 못하는** 음수 사이클은 잡히지 않습니다. 그 정점의 `dist`가 `Infinity`라서 이완이 일어나지 않기 때문입니다. 이것이 올바른 동작인 문제가 많습니다("1번에서 출발해서").
- 그래프 **전체**에 음수 사이클이 있는지 보려면 모든 `dist`를 0으로 시작합니다(가상의 시작점을 모든 정점에 0으로 이은 것과 같습니다).

### 영향받는 정점 찾기

음수 사이클에서 닿을 수 있는 정점은 모두 -∞입니다. V - 1바퀴 뒤에 V번 더 훑으면서 이완이 가능한 정점과 그 정점에서 퍼지는 정점에 `-Infinity`를 표시합니다.

```js
// dist는 V - 1바퀴가 끝난 상태
for (let i = 0; i < n; i++) {
  for (const [u, v, w] of edges) {
    if (dist[u] === Infinity) continue
    if (dist[u] === -Infinity || dist[u] + w < dist[v])
      dist[v] = -Infinity
  }
}
// 결과: -Infinity는 "무한히 작아짐", Infinity는 "도달 불가"
```

- 첫 바퀴에서 사이클에 속한 정점이 표시되고, 이후 바퀴마다 간선 하나씩 퍼지므로 V바퀴면 모두 퍼집니다.
- 출력 형식은 문제마다 다릅니다. 한 정점이라도 -∞면 `-1`을 출력하는 문제, 정점마다 `-INF`를 따로 출력하는 문제가 있습니다.

### 사이클 자체 복원

이완할 때 `parent[v] = u`를 기록합니다. V번째 바퀴에서 마지막으로 이완된 정점 x에서 `parent`를 V번 따라가면 사이클 위의 정점에 도달합니다. 거기서 `parent`를 따라 같은 정점으로 돌아올 때까지 모으면 사이클입니다.

**흔한 실수:**

- V - 1바퀴만 돌고 끝내서 음수 사이클이 있는데도 값을 그대로 출력하는 것입니다.
- 유한한 INF(예: 1e9)를 쓰면서 `dist[u]`가 INF인 정점의 간선까지 이완해, 도달 불가한 정점에 INF - 1 같은 값이 쓰이고 도달 불가 음수 사이클이 잘못 잡히는 것입니다. `Infinity`를 쓰거나 `dist[u]`가 INF이면 건너뜁니다.

## Floyd-Warshall

Floyd-Warshall은 **모든 정점 쌍의 최단거리**를 한 번에 구하는 알고리즘입니다. `d[i][j]`를 i에서 j까지의 최단거리로 두고, **정점 k를 경유지로 허용했을 때** 더 짧아지는지 검사합니다.

```js
function floyd(n, edges) {
  const row = () => new Array(n).fill(Infinity)
  const d = Array.from({ length: n }, row)
  for (let i = 0; i < n; i++) d[i][i] = 0
  for (const [u, v, w] of edges)
    d[u][v] = Math.min(d[u][v], w)
  for (let k = 0; k < n; k++)
    for (let i = 0; i < n; i++)
      for (let j = 0; j < n; j++)
        if (d[i][k] + d[k][j] < d[i][j])
          d[i][j] = d[i][k] + d[k][j]
  return d
}
```

- `d[i][i] = 0`으로 시작합니다. 간선이 없는 쌍은 `Infinity`입니다.
- 같은 두 정점 사이에 간선이 여러 개면 `Math.min`으로 가장 작은 값만 남깁니다. 입력을 그냥 대입하면 마지막 간선이 이겨서 틀립니다.
- 2차원 배열은 `Array.from`으로 행마다 새 배열을 만듭니다. `new Array(n).fill(new Array(n))`은 모든 행이 같은 배열을 가리킵니다(자세히는 05편).
- 시간복잡도는 O(V³), 공간복잡도는 O(V²)입니다. V가 수백 이하일 때 씁니다.

### 왜 k가 가장 바깥 반복문인가

k번째 단계가 시작되기 전의 `d[i][j]`는 **경유지로 0번부터 k - 1번 정점만 허용했을 때의 최단거리**입니다. k번째 단계에서 경유지에 k를 추가하면 새 최단거리는 "k를 지나지 않는 기존 값"과 "i에서 k까지 + k에서 j까지"(둘 다 k를 경유지로 쓰지 않는 값) 중 작은 쪽입니다. 이 정의는 k를 바깥에 둘 때만 유지됩니다.

```js
// ❌ k가 안쪽: 경유지를 다 허용하기 전의 값을 섞어 쓴다
for (let i = 0; i < n; i++)
  for (let j = 0; j < n; j++)
    for (let k = 0; k < n; k++) { /* ... */ }
// ✅ k가 가장 바깥
```

작은 그래프의 추적입니다. 간선은 0→1(4), 0→2(11), 1→2(2)입니다.

| 단계 | 의미 | d[0][2] |
|------|------|---------|
| 시작 | 직접 간선만 | 11 |
| k = 0 | 0을 경유지로 허용 | 11 (0→0→2는 이득 없음) |
| k = 1 | 1을 경유지로 허용 | 6 (0→1→2 = 4 + 2) |
| k = 2 | 2를 경유지로 허용 | 6 |

### 음수 간선과 음수 사이클

- 음수 간선은 그대로 처리합니다. 음수 사이클만 없으면 정답입니다.
- 모든 계산이 끝난 뒤 `d[i][i] < 0`인 정점 i가 있으면 i를 지나는 음수 사이클이 있습니다.
- 음수 사이클이 있으면 그 사이클을 거치는 쌍의 값은 의미가 없어지고, 단계가 반복되면서 매우 작은 값으로 퍼집니다.
- 유한한 INF를 쓰면 `d[i][k]`와 `d[k][j]`가 INF인지 먼저 확인해야 합니다. 음수 간선이 있으면 `INF + (-1)`이 INF보다 작아져 도달 불가 쌍이 도달 가능으로 바뀝니다.

### 반복 비용 줄이기

안쪽 반복문에서 `d[i][k]`와 `d[k]`는 j와 무관하므로 바깥에서 한 번만 읽습니다. 인덱싱 횟수를 줄이고, `d[i][k]`가 도달 불가이면 그 행을 통째로 건너뜁니다.

```js
for (let k = 0; k < n; k++) {
  const dk = d[k]
  for (let i = 0; i < n; i++) {
    const di = d[i], dik = di[k]
    if (dik === Infinity) continue
    for (let j = 0; j < n; j++)
      if (dik + dk[j] < di[j]) di[j] = dik + dk[j]
  }
}
```

- 같은 시간복잡도 O(V³)이고 상수만 줄입니다. 정점 수가 큰 문제에서 쓸 만합니다.

**언제 쓰는가:** 모든 쌍의 최단거리가 필요하거나, 질의가 많고 V가 작을 때("N ≤ 100", "모든 도시 쌍"). 한 번 계산해 두고 `d[a][b]`를 질의마다 O(1)로 읽습니다.

## Floyd-Warshall 경로 복원

`d`만으로는 경로를 알 수 없으므로 `next[i][j]`를 함께 둡니다. `next[i][j]`는 **i에서 j로 가는 최단 경로에서 i 다음에 오는 정점**입니다. 거리가 줄어들 때 `next[i][j] = next[i][k]`로 갱신합니다.

```js
const next = Array.from({ length: n }, () =>
  new Array(n).fill(-1))
for (let i = 0; i < n; i++) next[i][i] = i
// 간선 (u, v)를 읽을 때: d[u][v] 갱신과 함께 next[u][v] = v
// 삼중 반복문 안에서 d[i][j]를 줄일 때:
//   d[i][j] = d[i][k] + d[k][j]
//   next[i][j] = next[i][k]
```

복원은 `next`를 따라가며 정점을 모으면 됩니다.

```js
function path(next, s, e) {
  if (next[s][e] === -1) return null   // 경로 없음
  const res = [s]
  while (s !== e) {
    s = next[s][e]
    res.push(s)
  }
  return res
}
// 위 예제: path(next, 0, 2) → [0, 1, 2]
```

- 경로 길이는 정점 수를 넘지 않으므로 복원은 O(V)입니다. 메모리는 `d`와 같은 O(V²)가 하나 더 듭니다.
- 다른 방식으로 `mid[i][j] = k`(마지막으로 줄인 경유지)를 저장하고 `path(i, k) + path(k, j)`로 재귀 복원할 수 있습니다. 재귀 깊이는 V 이하이지만 `next` 방식이 반복문이라 더 단순합니다.
- 같은 거리의 경로가 여러 개면 `<`로 갱신할 때 먼저 찾은 경로가 남습니다. 문제가 사전순 경로 같은 규칙을 요구하면 같은 값일 때의 선택 규칙을 따로 넣어야 합니다.

**흔한 실수:** `next[i][i]`를 초기화하지 않아서 `path(next, s, s)`가 `null`을 돌려주는 것, 간선 입력에서 `next[u][v] = v`를 빼먹는 것입니다.

## 최단거리 알고리즘 선택 기준

고르는 순서는 **가중치의 성격 → 시작점의 수 → 입력 크기**입니다.

| 상황 | 알고리즘 | 시간복잡도 |
|------|----------|------------|
| 가중치가 없거나 모두 같음 | BFS(38편) | O(V + E) |
| 가중치가 0 또는 1 | 0-1 BFS(39편) | O(V + E) |
| 음수 없음, 단일 시작점 | Dijkstra(48편) | O((V + E) log V) |
| 음수 있음, 단일 시작점 | Bellman-Ford, SPFA | O(VE) |
| 모든 쌍, V 작음 | Floyd-Warshall | O(V³) |
| 모든 쌍, 간선 적고 음수 있음 | Johnson | 아래 참고 |
| 방향 비순환 그래프(DAG) | 위상 정렬 + DP(53편) | O(V + E) |

- 정점이 V = 500이고 간선이 E = 6000이면 Bellman-Ford는 약 3,000,000번, Floyd-Warshall은 125,000,000번 이완합니다. 시작점이 하나뿐인데 Floyd를 쓰면 낭비입니다.
- 모든 쌍이 필요해도 음수가 없고 간선이 적으면 Dijkstra를 V번 돌리는 편이 O(V(V + E) log V)로 빠를 수 있습니다.
- 시작점이 여러 개이고 모두 같은 도착점이면 간선 방향을 뒤집어 도착점 하나에서 한 번 돌립니다.
- 문제의 단서로 거르면 대부분 정해집니다. "음수 비용"이면 Dijkstra는 제외, "모든 쌍"이나 "N ≤ 100"이면 Floyd, "무한히 줄어든다"이면 Bellman-Ford입니다.

## SPFA

SPFA(Shortest Path Faster Algorithm)는 Bellman-Ford를 **큐**로 바꾼 것입니다. 모든 간선을 매번 훑지 않고, **거리가 줄어든 정점의 이웃만** 다시 확인합니다.

```js
function spfa(n, adj, src) {       // adj[u] = [[v, w], ...]
  const dist = new Array(n).fill(Infinity)
  const inQ = new Array(n).fill(false)   // 큐에 있는가
  const cnt = new Array(n).fill(0)       // 큐에 들어간 횟수
  const q = [src]
  dist[src] = 0; inQ[src] = true; cnt[src] = 1
  // (이어서 아래 반복문)
```

```js
  for (let h = 0; h < q.length; h++) {
    const u = q[h]
    inQ[u] = false
    for (const [v, w] of adj[u]) {
      if (dist[u] + w >= dist[v]) continue
      dist[v] = dist[u] + w
      if (inQ[v]) continue
      if (++cnt[v] >= n) return null   // 음수 사이클
      q.push(v); inQ[v] = true
    }
  }
  return dist
}
```

- `inQ`는 이미 큐에 있는 정점을 중복해서 넣지 않기 위한 표시입니다. `cnt[v]`는 정점이 큐에 들어간 횟수이고, 한 정점이 V번 이상 들어가면 음수 사이클이 있다는 뜻입니다.
- 큐는 `head` 인덱스 방식(20편)이라 배열이 계속 길어집니다. 정점이 여러 번 들어가면 길이가 V를 넘을 수 있습니다.
- 평균적으로 Bellman-Ford보다 빠르지만 **최악의 시간복잡도는 O(VE)로 같습니다**. 일부러 만든 입력에서는 느려질 수 있어서 시간 제한이 빡빡한 문제에서는 단정할 수 없습니다.
- 한 정점이 큐에 들어가는 횟수를 세는 방식이어서 시작점에서 닿는 음수 사이클만 잡습니다.

## Johnson 알고리즘

Johnson은 **음수 간선이 있고 간선이 적은 그래프의 모든 쌍 최단거리**를 Floyd보다 빠르게 구하는 알고리즘입니다(개요). 음수 간선을 **0 이상으로 바꾼 뒤** 각 정점에서 Dijkstra를 돌립니다.

1. 새 정점 q를 만들고 모든 정점에 가중치 0인 간선을 잇는다.
2. q에서 Bellman-Ford를 돌려 각 정점의 거리 `h(v)`를 구한다. 음수 사이클이 있으면 여기서 중단한다.
3. 모든 간선을 `w'(u, v) = w(u, v) + h(u) - h(v)`로 바꾼다. 최단거리 조건 `h(v) ≤ h(u) + w`에 의해 `w'`는 항상 0 이상이다.
4. 각 정점에서 Dijkstra를 돌린다.
5. 결과를 `d(u, v) = d'(u, v) - h(u) + h(v)`로 되돌린다.

경로의 중간 정점 항이 서로 상쇄되어 **경로 하나의 가중치가 `h(시작) - h(끝)`만큼만 달라지므로** 어떤 경로가 최단인지는 바뀌지 않습니다. 앞 절에서 본 "모든 가중치에 상수를 더하는" 방법과 달리 간선 수와 무관합니다.

간선 0→1(3), 1→2(-2), 0→2(2)의 예입니다.

| 정점 | h | 바꾼 간선 | w' |
|------|---|-----------|----|
| 0 | 0 | 0→1: 3 + 0 - 0 | 3 |
| 1 | 0 | 1→2: -2 + 0 - (-2) | 0 |
| 2 | -2 | 0→2: 2 + 0 - (-2) | 4 |

0에서 Dijkstra를 돌리면 `d'(0, 2) = min(3 + 0, 4) = 3`이고, 되돌리면 `3 - 0 + (-2) = 1`입니다. 실제 최단 경로 0→1→2의 길이 1과 같습니다.

- Bellman-Ford 한 번 O(VE)에 Dijkstra V번을 더합니다. 이진 힙이면 O(V(V + E) log V), 피보나치 힙이면 O(V² log V + VE)입니다.
- 간선이 적은 희소 그래프에서 O(V³)인 Floyd보다 유리하고, 밀집 그래프나 V가 작으면 Floyd가 더 짧고 간단합니다.
- 코딩테스트에서는 드물고, 필요하면 Floyd로 대부분 해결됩니다.

## 핵심 정리

- Bellman-Ford는 모든 간선을 V - 1바퀴 이완해서 음수 간선이 있어도 단일 시작점 최단거리를 구하며 O(VE)입니다. 한 바퀴에 변화가 없으면 일찍 끝냅니다.
- Dijkstra는 확정한 정점이 나중에 줄어들 수 있는 음수 간선에서 틀립니다. 모든 가중치에 상수를 더하는 방법으로는 해결되지 않습니다.
- V번째 바퀴에서도 이완이 일어나면 시작점에서 닿는 음수 사이클이 있습니다. 그 사이클에서 닿는 정점의 거리는 -∞입니다.
- Floyd-Warshall은 경유지 k를 가장 바깥 반복문에 두는 O(V³) 모든 쌍 최단거리입니다. `d[i][i] < 0`이면 음수 사이클이 있고, `next[i][j]`로 경로를 복원합니다.
- 음수가 없으면 Dijkstra, 있으면 Bellman-Ford, 모든 쌍이고 V가 작으면 Floyd를 고릅니다. SPFA는 평균은 빠르지만 최악이 O(VE)이고, Johnson은 h(v)로 간선을 0 이상으로 바꿔 Dijkstra를 V번 돌립니다.
