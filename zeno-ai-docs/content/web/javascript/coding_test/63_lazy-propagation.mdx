## Lazy Propagation

지연 전파(lazy propagation)는 구간 갱신을 세그먼트 트리에서 미루어 처리하는 기법입니다. 구간 `[ql, qr]`의 모든 원소에 같은 연산(예: x를 더한다)을 하는 갱신을 점 갱신 N번으로 하면 O(N log N)이 듭니다. 이를 O(log N)으로 줄입니다. 세그먼트 트리의 구조는 62편에서 다뤘습니다.

- 갱신 구간에 노드 구간이 완전히 들어가면 그 노드의 값만 바로 고치고, 자식에게는 "아직 반영하지 않은 연산"을 태그(lazy tag)로 적어 둡니다. 자식 이하의 모든 노드를 고치지 않습니다.
- 나중에 그 노드의 자식으로 내려가야 할 때(갱신이든 질의든) 태그를 자식에게 넘기고(push down) 노드의 태그를 지웁니다.
- 노드 `v`에 대해 항상 성립하는 약속은 하나입니다. `t[v]`는 `v`가 받은 모든 갱신이 반영된 값이고, `lz[v]`는 자식에게 아직 전달하지 않은 갱신입니다. 이 약속 덕분에 `v`를 읽을 때는 태그를 신경 쓰지 않고, `v`의 자식으로 내려갈 때만 push합니다.

연산은 세 가지로 나뉩니다.

| 연산 | 하는 일 | 쓰이는 때 |
|------|---------|-----------|
| apply | 노드 하나에 갱신을 적용: 값을 고치고 태그에 합성 | 갱신 구간에 노드가 완전히 들어갈 때, push할 때 |
| push | 노드의 태그를 두 자식에 apply하고 노드의 태그를 지운다 | 자식으로 내려가기 직전 |
| pull | 두 자식의 값으로 노드의 값을 다시 계산한다 | 자식 갱신이 끝나고 올라올 때 |

구간 덧셈과 구간 합의 `apply`와 `push`는 다음과 같습니다.

```js
let t = new Float64Array(4 * N)    // 노드 값(구간 합)
let lz = new Float64Array(4 * N)   // 자식에게 미룬 덧셈
function apply(v, l, r, x) {
  t[v] += x * (r - l + 1)          // 구간 길이만큼 합이 늘어난다
  lz[v] += x
}
function push(v, l, r) {
  if (lz[v] === 0) return
  const m = (l + r) >> 1
  apply(2 * v, l, m, lz[v])
  apply(2 * v + 1, m + 1, r, lz[v])
  lz[v] = 0
}
```

- 합 트리에서는 구간의 모든 원소에 x를 더하면 합이 `x × 구간 길이`만큼 늘어납니다. 그래서 `apply`가 구간 길이 `r - l + 1`을 알아야 합니다.
- `push`는 태그를 자식의 값에 반영하고 자식의 태그에 쌓습니다. 자식이 이미 태그를 갖고 있으면 덧셈은 단순히 더해집니다.
- 리프는 자식이 없으므로 push할 일이 없습니다. 갱신과 질의에서 `push`가 호출되는 노드는 구간이 일부만 겹치는 내부 노드라서 항상 자식이 있습니다.
- 갱신과 질의 모두 O(log N)이고, 생성은 O(N), 공간은 `t`와 `lz`를 합쳐 `8N`칸입니다.

lazy를 쓸 수 있는 조건은 세 가지입니다.

- 노드의 요약 값(합, 최대 등)에 갱신을 구간 길이 정보만으로 O(1)에 적용할 수 있다.
- 두 갱신을 O(1)에 하나의 태그로 합성할 수 있고, 그 합성이 결합법칙을 만족한다.
- 아무 일도 하지 않는 태그(위 코드의 `0`)가 있다.

노드 요약만으로 갱신 결과를 구할 수 없으면 쓸 수 없습니다. 구간의 각 원소를 제곱근으로 바꾸는 갱신이 예입니다. 합의 제곱근은 제곱근의 합과 다르기 때문입니다.

**흔한 실수:** 자식으로 내려가기 전에 push를 빼먹는 것입니다. 내려가는 모든 곳(갱신과 질의 모두)에서 push가 필요합니다. 질의에서 빼먹으면 이전 갱신이 반영되지 않은 값을 읽습니다.

## Range Update / Point Query

구간 갱신과 점 질의는 구간의 모든 원소에 x를 더하는 갱신 뒤 한 원소의 값을 묻는 문제입니다. 구간 합이 필요 없으므로 push 없이 푸는 가장 간단한 방법이 있습니다.

- 갱신 구간에 완전히 들어가는 노드 O(log N)개의 `tag`에 x를 더합니다. 자식으로 전달하지 않고 그 자리에 둡니다.
- 한 점의 값은 원래 값에 루트에서 그 리프까지 지나는 노드의 태그를 모두 더한 값입니다. 리프를 덮는 모든 구간의 갱신이 그 경로에 있는 노드에 쌓여 있기 때문입니다.

```js
let tag = new Float64Array(4 * N)
function add(v, l, r, ql, qr, x) {
  if (qr < l || r < ql) return
  if (ql <= l && r <= qr) { tag[v] += x; return }
  const m = (l + r) >> 1
  add(2 * v, l, m, ql, qr, x)
  add(2 * v + 1, m + 1, r, ql, qr, x)
}
```

```js
function point(i) {
  let v = 1, l = 0, r = N - 1, s = a[i]
  while (true) {
    s += tag[v]
    if (l === r) return s
    const m = (l + r) >> 1
    if (i <= m) { v = 2 * v; r = m }
    else { v = 2 * v + 1; l = m + 1 }
  }
}
```

`a = [2, 5, 1, 4, 3, 6]`에서 `add(1, 0, 5, 0, 2, 10)` 뒤에 `point(1)`을 구하면 15입니다. 갱신으로 노드 2(`[0,2]`)의 `tag`가 10이 되고, `point(1)`은 경로 1, 2, 4, 9의 태그를 더하므로 `5 + 10`입니다.

- `build`가 필요 없습니다. `tag`는 0으로 시작하고 원래 값은 `a`에서 읽습니다.
- 두 연산 모두 O(log N)입니다.
- 덧셈은 순서에 상관없이 더해지므로 이 방식이 맞습니다. 구간 대입은 나중에 한 갱신이 먼저 한 갱신을 덮어야 해서, 태그에 갱신 순서(시각)를 같이 저장하고 경로에서 가장 최근 것을 골라야 합니다.
- 구간 덧셈과 점 질의는 차이 배열로도 풉니다. `l`에 x를 더하고 `r + 1`에서 x를 빼 두면 점 `i`의 값은 `i`까지의 접두사 합입니다. Fenwick Tree가 이 구조를 가장 짧게 구현합니다(자세히는 64편).

**문제의 단서:** "구간에 모두 더한다"와 "한 원소의 값을 묻는다"만 있으면 이 방식이면 충분합니다. 구간 합이나 구간 최댓값을 묻는 순간 아래 절의 push 방식이 필요합니다.

**흔한 실수:** 점 질의에서 `a[i]`를 빼먹거나, 경로의 리프 노드 태그(`l === r`인 노드)를 더하지 않는 것입니다. 리프만 덮는 갱신이 그 태그에 쌓입니다.

## Range Update / Range Query

구간 갱신과 구간 질의는 구간 덧셈과 구간 합을 함께 처리하는 가장 기본적인 lazy 문제입니다. 앞 절의 `apply`와 `push`를 쓰고, 갱신과 질의에서 내려가기 전에 push합니다.

```js
function update(v, l, r, ql, qr, x) {
  if (qr < l || r < ql) return
  if (ql <= l && r <= qr) { apply(v, l, r, x); return }
  push(v, l, r)
  const m = (l + r) >> 1
  update(2 * v, l, m, ql, qr, x)
  update(2 * v + 1, m + 1, r, ql, qr, x)
  t[v] = t[2 * v] + t[2 * v + 1]       // pull
}
```

```js
function query(v, l, r, ql, qr) {
  if (qr < l || r < ql) return 0
  if (ql <= l && r <= qr) return t[v]
  push(v, l, r)
  const m = (l + r) >> 1
  const left = query(2 * v, l, m, ql, qr)
  return left + query(2 * v + 1, m + 1, r, ql, qr)
}
```

`a = [2, 5, 1, 4, 3, 6]`에서 `update(1, 0, 5, 0, 2, 10)`을 한 뒤 `query(1, 0, 5, 1, 1)`을 따라가면 다음과 같습니다. 트리의 노드 번호와 구간은 62편의 표와 같습니다.

| 단계 | 일어나는 일 | 상태 |
|------|-------------|------|
| update: 노드 1 | 구간이 일부만 겹침, push(태그 0이라 아무 일 없음) | |
| update: 노드 2 `[0,2]` | 완전히 포함, apply | `t[2]` = 8 + 30 = 38, `lz[2]` = 10 |
| update: 노드 3 | 겹치지 않음 | |
| update: 올라오며 pull | 노드 1 다시 계산 | `t[1]` = 38 + 13 = 51 |
| query: 노드 1 | 일부 겹침, push(태그 0) | |
| query: 노드 2 | 일부 겹침, push | 노드 4, 5에 apply, `lz[2]` = 0 |
| query: 노드 4 `[0,1]` | 일부 겹침, push | 노드 8, 9에 apply, 노드 9는 5 + 10 = 15 |
| query: 노드 9 `[1,1]` | 완전히 포함 | 15 반환 |

push를 거치면서 갱신이 아래로 한 층씩 내려가고, 질의가 지나간 경로의 노드가 정확한 값을 갖게 됩니다. 질의가 지나지 않은 곳은 태그를 쥔 채 그대로 두었다가, 나중에 내려갈 때 전달합니다.

- 갱신과 질의가 모두 O(log N)입니다. push는 방문한 노드마다 상수 시간이라 전체 시간이 방문 노드 수에 비례합니다.
- 트리를 만드는 `build`는 62편과 같고, `lz`는 0으로 시작합니다.
- 합의 크기를 먼저 계산합니다. 원소가 N개이고 한 번에 더하는 값이 최대 X, 갱신이 Q번이면 합의 상한은 N × Q × X입니다. 이 값이 2^53 − 1(약 9 × 10^15)을 넘을 수 있으면 `Float64Array`의 값이 조용히 부정확해지므로 BigInt를 써야 합니다. N, Q, X가 10^5, 10^5, 10^9이면 상한이 10^19라 BigInt가 필요합니다(자세히는 02편).
- BigInt로 바꿀 때는 `t`, `lz`를 `new Array(4 * N).fill(0n)`으로 만들고, 구간 길이도 `BigInt(r - l + 1)`로 바꿔 곱합니다. 숫자와 BigInt를 섞으면 TypeError입니다.

백준식 입력으로 감싼 코드입니다. 첫 줄은 N과 질의 수 Q, 둘째 줄은 배열이고, 이어지는 줄은 `1 l r x`(구간에 x를 더한다) 또는 `2 l r`(구간 합)입니다. 번호는 1부터입니다.

```js
const fs = require('fs')
const tk = fs.readFileSync(0, 'utf8').split(/\s+/)
let p = 0
const N = +tk[p++], Q = +tk[p++]
const a = Array.from({ length: N }, () => +tk[p++])
// t, lz를 4 * N으로 만들고 62편의 build(1, 0, N - 1)를 호출
const out = []
for (let k = 0; k < Q; k++) {
  const c = +tk[p++], l = +tk[p++] - 1, r = +tk[p++] - 1
  if (c === 1) update(1, 0, N - 1, l, r, +tk[p++])
  else out.push(query(1, 0, N - 1, l, r))
}
console.log(out.join('\n'))
```

**흔한 실수:**

- 갱신에서 자식을 갱신한 뒤 `pull`(부모 값 재계산)을 빼먹는 것입니다. 부모가 자식의 새 값을 반영하지 못합니다.
- `apply`에서 구간 길이를 곱하지 않는 것입니다. 점 값이면 `x`만 더해도 되지만 합 트리에서는 `x × 길이`입니다.
- 질의에서 push를 빼먹는 것입니다. 갱신 직후의 질의가 오래된 값을 돌려줍니다.

## Lazy Propagation 응용

같은 틀에서 `apply`와 태그의 의미만 바꾸면 여러 문제를 풉니다. 바꿔야 하는 곳은 노드 값을 고치는 식, 태그에 쌓는 식, 태그가 없다는 표시(항등 태그)뿐입니다.

| 문제 | 노드 값 | `apply(v, l, r, x)` | 항등 태그 |
|------|---------|----------------------|-----------|
| 구간 덧셈, 구간 합 | 합 | `t[v] += x * len`, `lz[v] += x` | 0 |
| 구간 덧셈, 구간 최대 | 최대 | `t[v] += x`, `lz[v] += x` | 0 |
| 구간 토글, 켜진 개수 | 1의 개수 | `t[v] = len - t[v]`, `lz[v] ^= 1` | 0 |
| 구간 대입, 구간 합 | 합 | `t[v] = x * len`, 태그를 x로 | 없음 표시 |

`len`은 구간 길이 `r - l + 1`입니다.

- 구간 덧셈과 구간 최대는 구간 전체가 x만큼 올라가면 최댓값도 x만큼 올라가므로 길이를 곱하지 않습니다. 질의의 합치는 연산은 `Math.max`, 겹치지 않을 때의 반환값은 `-Infinity`입니다(62편).
- 토글(0과 1을 뒤집는 연산)은 구간 안의 1의 개수가 `len - 개수`가 됩니다. 두 번 뒤집으면 원래대로이므로 태그는 XOR로 합성합니다.

```js
function apply(v, l, r, flip) {
  if (!flip) return
  t[v] = (r - l + 1) - t[v]   // 켜진 개수 ↔ 꺼진 개수
  lz[v] ^= 1                   // 두 번이면 취소
}
// [0,0,0,0]에서 [0,2] 토글 → [1,1,1,0] 개수 3
// 이어서 [1,3] 토글 → [1,0,0,1] 개수 2
```

- 구간 곱과 구간 덧셈을 함께 하면 태그를 한 쌍 `(mul, add)`로 둡니다. 값 `s`에 `(mul, add)`를 적용하면 `s × mul + add`이고, 합 트리에서는 노드 합 `S`가 `S × mul + add × len`이 됩니다. 이미 `(m1, a1)`인 태그에 `(m2, a2)`를 겹치면 결과는 `(m1 × m2, a1 × m2 + a2)`입니다. 소수로 나눈 나머지를 구하는 문제에서는 곱이 2^53을 넘으므로 곱셈마다 BigInt나 분할 곱셈이 필요합니다(자세히는 57편).
- 점 갱신(한 원소의 값을 바꾸기)도 같은 트리에서 섞여 나올 수 있습니다. 리프로 내려가는 길의 push가 모두 끝나야 리프 값이 정확하므로, 점 갱신도 내려가며 push하고 올라오며 pull합니다.
- 문제 문장의 단서는 "구간의 모든 원소에 ~한다"와 "구간의 합·최댓값·개수를 묻는다"가 한 문제에 같이 나오는 것입니다. 구간 갱신이 없으면 62편의 일반 세그먼트 트리면 충분합니다.

**흔한 실수:** 태그가 없다는 표시로 0을 쓰는 방식을 모든 연산에 적용하는 것입니다. 대입 태그는 0도 값이므로 별도 표시(플래그)가 필요합니다(아래 절).

## 구간 대입과 구간 덧셈의 lazy 합성

한 트리에 구간 대입(`[l, r]` 전체를 x로)과 구간 덧셈이 함께 있으면 태그 하나로 둘을 합성해야 합니다. 이때 "먼저 한 연산이 무엇이었나"가 결과에 영향을 주기 때문에 합성 규칙이 필요합니다.

태그를 "먼저 값을 `y`로 바꾸고 나서 `z`를 더한다"라는 한 쌍(대입 `y`가 있는지 여부, 덧셈 `z`)으로 둡니다. 새 연산이 들어올 때 합성은 다음과 같습니다.

| 현재 태그 | 새 연산 | 합성 결과 |
|-----------|---------|-----------|
| 없음 | 대입 `x` | 대입 `x`, 덧셈 0 |
| 없음 | 덧셈 `x` | 덧셈 `x` |
| 대입 `y`, 덧셈 `z` | 대입 `x` | 대입 `x`, 덧셈 0 (이전 덧셈 `z`는 버린다) |
| 대입 `y`, 덧셈 `z` | 덧셈 `x` | 대입 `y`, 덧셈 `z + x` |
| 덧셈 `z` | 대입 `x` | 대입 `x`, 덧셈 0 |
| 덧셈 `z` | 덧셈 `x` | 덧셈 `z + x` |

- 새 대입은 이전의 대입과 덧셈을 모두 지웁니다. 어차피 값을 덮어쓰기 때문입니다.
- 새 덧셈은 대입이 있으면 대입 뒤에 붙고, 없으면 기존 덧셈에 더해집니다.
- 이 규칙은 결합법칙을 만족하므로 두 태그를 나중에 합쳐도, 하나씩 순서대로 적용한 것과 결과가 같습니다.

```js
const st = new Float64Array(4 * N)   // 대입 값
const has = new Uint8Array(4 * N)    // 대입 태그가 있는가
const ad = new Float64Array(4 * N)   // 덧셈 값
function applySet(v, l, r, x) {
  t[v] = x * (r - l + 1)
  st[v] = x; has[v] = 1; ad[v] = 0   // 이전 태그를 모두 지운다
}
function applyAdd(v, l, r, x) {
  t[v] += x * (r - l + 1)
  ad[v] += x                         // 대입이 있으면 그 뒤에 붙는다
}
```

```js
function push(v, l, r) {
  const m = (l + r) >> 1
  if (has[v]) {                      // 대입을 먼저
    applySet(2 * v, l, m, st[v])
    applySet(2 * v + 1, m + 1, r, st[v])
    has[v] = 0
  }
  if (ad[v] !== 0) {                 // 그다음 덧셈
    applyAdd(2 * v, l, m, ad[v])
    applyAdd(2 * v + 1, m + 1, r, ad[v])
    ad[v] = 0
  }
}
```

- `has` 표시를 따로 두는 이유는 0을 대입하는 갱신이 있기 때문입니다. `st[v] === 0`을 "없음"으로 쓰면 0 대입이 사라집니다.
- `push`가 대입을 먼저, 덧셈을 나중에 자식에게 적용하는 순서가 태그의 의미("대입 후 덧셈")와 맞아야 합니다. 순서를 바꾸면 덧셈이 대입에 덮여 사라집니다.
- 갱신 함수는 `update`와 같고 완전히 포함될 때 `applySet`이나 `applyAdd` 중 연산에 맞는 쪽을 호출하는 것만 다릅니다. 질의 함수는 앞 절의 `query`를 그대로 씁니다. `push`가 이 절의 것으로 바뀌어 있습니다.
- 시간은 갱신과 질의 모두 O(log N)입니다.

`a = [2, 5, 1, 4, 3, 6]`에서 `[1, 3]`을 7로 대입하면 `[2, 7, 7, 7, 3, 6]`이고, 이어서 `[0, 4]`에 1을 더하면 `[3, 8, 8, 8, 4, 6]`입니다. 이때 `[0, 5]`의 합은 37입니다.

**흔한 실수:**

- 새 대입 때 이전 덧셈 태그를 지우지 않는 것입니다. 이전 덧셈이 대입 뒤에 다시 더해져 값이 틀립니다.
- push에서 덧셈을 먼저 적용하고 대입을 나중에 하는 것입니다. 대입이 덧셈 결과를 덮어씁니다.
- 대입 값이 0일 수 있는데 `st[v] !== 0`으로 태그 유무를 판정하는 것입니다.

## 핵심 정리

- 지연 전파는 갱신 구간에 완전히 들어가는 노드에만 갱신을 반영하고 자식에게는 태그로 미뤘다가, 자식으로 내려갈 때 push합니다. 구간 갱신과 질의가 모두 O(log N)입니다.
- 노드의 값 `t[v]`는 `v`가 받은 갱신이 모두 반영된 값이고, 태그는 자식에게 전하지 않은 갱신입니다. 갱신과 질의에서 자식으로 내려가기 전에는 반드시 push하고, 갱신에서 올라올 때는 pull합니다.
- 구간 덧셈과 점 질의는 push 없이 완전히 포함된 노드에 태그를 쌓고, 점 질의에서 루트에서 리프까지의 태그를 더합니다.
- 구간 덧셈과 구간 합에서는 `apply`가 `x × 구간 길이`를 합에 더하고, 합이 2^53을 넘을 수 있으면 BigInt를 씁니다. 구간 최대는 길이를 곱하지 않습니다.
- 태그는 노드 요약에 O(1)에 적용되고 결합법칙을 만족하는 합성이 있어야 합니다. 토글은 XOR, 곱과 덧셈은 `(mul, add)` 쌍으로 합성합니다.
- 대입과 덧셈이 함께 있으면 새 대입은 이전 태그를 모두 지우고, 새 덧셈은 대입 뒤에 붙으며, push는 대입을 먼저 덧셈을 나중에 적용합니다.
