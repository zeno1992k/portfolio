이 문서의 코드는 57편의 `mulmod(a, b, m)`(곱이 2^53을 넘지 않게 나눠 곱하는 모듈러 곱셈, `m ≤ 2^31`)을 씁니다. 모듈러가 더 크면 BigInt로 바꿉니다.

## Extended Euclidean

확장 유클리드 알고리즘은 `a · x + b · y = gcd(a, b)`를 만족하는 정수 `x`, `y`를 gcd와 함께 구합니다. 유클리드 호제법(12편)을 돌며 거슬러 올라올 때 계수를 갱신합니다. `(b, a mod b)`에서 구한 계수가 `(x1, y1)`이면 `(a, b)`의 계수는 다음과 같습니다.

- `x = y1`
- `y = x1 − ⌊a / b⌋ · y1`

```js
function egcd(a, b) { // a, b ≥ 0. [g, x, y]: a*x + b*y = g
  if (b === 0) return [a, 1, 0]
  const [g, x1, y1] = egcd(b, a % b)
  return [g, y1, x1 - Math.floor(a / b) * y1]
}
egcd(240, 46) // [2, -9, 47]
```

`240 · (−9) + 46 · 47 = 2`입니다. 호출을 따라가면 이렇습니다. 맨 아래(`b = 0`)가 시작이고 위로 올라오며 계수가 만들어집니다.

| 호출 | 몫 `⌊a/b⌋` | `(x, y)` |
|------|------------|----------|
| `(240, 46)` | 5 | (−9, 47) |
| `(46, 10)` | 4 | (2, −9) |
| `(10, 6)` | 1 | (−1, 2) |
| `(6, 4)` | 1 | (1, −1) |
| `(4, 2)` | 2 | (0, 1) |
| `(2, 0)` | - | (1, 0) |

- 시간은 유클리드 호제법과 같은 O(log min(a, b))이고, 재귀 깊이도 그만큼이라 호출 스택 걱정이 없습니다.
- 해는 하나가 아니라서 위 `(x, y)`는 그중 하나입니다. 이 코드가 돌려주는 값은 `|x| ≤ b / g`, `|y| ≤ a / g`입니다. 그래서 `a`, `b`가 2^53 이하이면 중간 곱 `⌊a/b⌋ · y1`도 정확한 정수입니다.
- 음수 입력은 `%`의 부호 때문에 틀립니다. 먼저 0 이상으로 만듭니다(57편).
- BigInt 판은 `Math.floor(a / b)`를 `a / b`로 바꾸고 상수에 `n`을 붙입니다. BigInt의 나눗셈은 0 방향 절삭이라 0 이상에서는 내림과 같습니다.

일차 부정 방정식 `a · x + b · y = c`도 이 결과로 풉니다. 해가 있을 조건은 `gcd(a, b)`가 `c`를 나누는 것입니다. 그때 `egcd`의 계수에 `c / g`를 곱하면 한 해이고, 나머지 해는 `t`를 정수로 해서 `x0 + (b/g) · t`, `y0 − (a/g) · t`입니다.

```js
function diophantine(a, b, c) { // 해 [x0, y0, b/g, a/g]
  const [g, x, y] = egcd(a, b)
  if (c % g !== 0) return null
  return [x * (c / g), y * (c / g), b / g, a / g]
}
diophantine(30, 18, 12) // [-2, 4, 3, 5]
```

`30 · (−2) + 18 · 4 = 12`이고 일반해는 `x = −2 + 3t`, `y = 4 − 5t`입니다. `c / g`를 곱할 때 값이 2^53을 넘지 않는지 확인합니다.

**문제의 단서:** "`a·x + b·y = c`의 정수 해", "역원을 구하라(모듈러가 소수가 아님)", 물통 문제, 두 주기의 만남 시점.

**흔한 실수:** `gcd`가 `c`를 나누는지 확인하지 않고 해를 구하는 것, `x`가 음수인 채로 쓰는 것(역원이면 mod로 보정), `a`, `b`가 음수일 때 `%`로 틀리는 것입니다.

## 모듈러 나눗셈

모듈러 나눗셈 `a / b mod m`은 `b`의 역원을 곱하는 것입니다. 역원은 `gcd(b, m) = 1`일 때만 있고, 확장 유클리드로 `b · x + m · y = 1`의 `x`를 구해 mod로 보정한 값이 역원입니다. 모듈러가 소수가 아니어도 되므로 페르마의 소정리(57편)보다 범용입니다.

```js
function modInv(a, m) { // 역원, 없으면 -1
  const [g, x] = egcd(((a % m) + m) % m, m)
  return g === 1 ? ((x % m) + m) % m : -1
}
modInv(3, 11)  // 4 (3 × 4 = 12 ≡ 1)
modInv(10, 17) // 12
modInv(6, 9)   // -1 (gcd(6, 9) = 3)
```

| 방법 | 조건 | 시간 |
|------|------|------|
| 페르마의 소정리 `a^(m−2)` | m이 소수 | O(log m) |
| 오일러의 정리 `a^(φ(m)−1)` | `gcd(a, m) = 1`, φ(m)을 알아야 함 | O(log m) |
| 확장 유클리드 | `gcd(a, m) = 1` | O(log m) |

역원이 없는 경우의 나눗셈은 합동 방정식 `b · x ≡ a (mod m)`으로 봅니다. `g = gcd(b, m)`일 때 `g`가 `a`를 나눠야 해가 있습니다. 양변과 모듈러를 `g`로 나누면 `(b/g) · x ≡ a/g (mod m/g)`이 되고 이는 역원이 있어서 `x`는 `m/g`를 법으로 하나로 정해집니다.

```js
function divMod(a, b, m) { // b*x ≡ a (mod m), 없으면 null
  const [g, x] = egcd(((b % m) + m) % m, m)
  if (a % g !== 0) return null
  const m2 = m / g
  const inv = ((x % m2) + m2) % m2
  return mulmod(inv, ((a / g) % m2 + m2) % m2, m2)
}
divMod(10, 4, 6) // 1 (4 × 1 = 4 ≡ 10 mod 6)
divMod(3, 4, 6)  // null (gcd(4, 6) = 2가 3을 나누지 못함)
divMod(7, 3, 11) // 6 (3 × 6 = 18 ≡ 7)
```

- `divMod(10, 4, 6)`은 `x = 1`이고 `x = 4`도 해입니다(`m/g = 3`마다 반복되므로 모듈러 6에서 해가 2개).
- `(a / b) % m`처럼 먼저 나누면 안 됩니다. 나눗셈은 mod에서 역원 곱으로만 정의됩니다.
- `a`가 크면 `a % m`으로 줄인 뒤 곱합니다.

**문제의 단서:** "분수의 값을 1,000,000,007 대신 임의의 M으로 나눈 나머지", 모듈러가 합성수, `ax ≡ b (mod m)`의 해.

**흔한 실수:** 역원이 없는데도 `-1`이나 `0`을 그대로 곱하는 것, `m`이 소수라고 가정하고 페르마를 쓰는 것입니다.

## 조합 전처리 (factorial / inverse factorial)

팩토리얼 배열 `fact`와 팩토리얼의 역원 배열 `inv`를 미리 만들어 두면 `C(n, r)`, `P(n, r)`을 쿼리마다 O(1)에 구합니다. 57편은 소수 모듈러에서 페르마로 `inv[n]`을 구했습니다. 여기서는 확장 유클리드로 구하므로 `n!`과 서로소인 모듈러(모든 소인수가 n보다 큰 합성수도 포함)에서도 동작합니다.

```js
function buildFact(n, m) { // n!과 m이 서로소여야 한다
  const fact = new Int32Array(n + 1)
  const inv = new Int32Array(n + 1)
  fact[0] = 1
  for (let i = 1; i <= n; i++)
    fact[i] = mulmod(fact[i - 1], i, m)
  inv[n] = modInv(fact[n], m)
  for (let i = n; i >= 1; i--)
    inv[i - 1] = mulmod(inv[i], i, m)
  return { fact, inv }
}
```

- `inv[n]`만 역원을 구하고, `inv[i−1] = inv[i] · i`로 내려오며 나머지를 채웁니다. 전체 O(n + log m)입니다.
- 값이 모듈러보다 작으면 `Int32Array`에 들어갑니다(1,000,000,007은 2^31 − 1보다 작음). 일반 배열보다 메모리를 덜 씁니다(자세히는 14편).

```js
const MOD = 1000000007
const { fact, inv } = buildFact(2000, MOD)
const C = (n, r) => r < 0 || r > n ? 0
  : mulmod(mulmod(fact[n], inv[r], MOD), inv[n - r], MOD)
const P = (n, r) => r < 0 || r > n ? 0
  : mulmod(fact[n], inv[n - r], MOD)
C(5, 2)         // 10
P(5, 2)         // 20
C(3 + 2 - 1, 2) // 6 (3종류 중 2개를 고르는 중복 조합)
```

| 구하려는 값 | 식 |
|-------------|----|
| 조합 `C(n, r)` | `fact[n] · inv[r] · inv[n−r]` |
| 순열 `P(n, r)` | `fact[n] · inv[n−r]` |
| 중복 조합 `H(n, r)` | `C(n + r − 1, r)` |
| 같은 것이 있는 순열 | `fact[n] · ∏ inv[개수]` |

- 표의 크기는 쿼리에 나오는 가장 큰 인자까지 필요합니다. 중복 조합은 `n + r − 1`까지 필요합니다.
- 모듈러가 소수이고 `n ≥ p`이면 `n!`이 p의 배수라서 이 방법이 성립하지 않습니다. 그때는 뤼카 정리(아래 절)를 씁니다.
- 합성수 모듈러에서 `n!`과 서로소가 아니면, 모듈러를 소수의 거듭제곱들로 쪼개 각각 구하고 CRT(다음 절)로 합칩니다.
- 조합의 정의와 파스칼 삼각형은 56편에서 다룹니다.

**문제의 단서:** "N개 중 R개를 고르는 방법의 수를 M으로 나눈 나머지"가 쿼리 많음, N이 10^6 안팎. 모듈러가 소수가 아닌 M일 때는 `n!`과 서로소인지 확인합니다.

**흔한 실수:** 표의 최대 인덱스를 입력 범위보다 작게 잡아 `undefined`가 `NaN`으로 번지는 것, `C(n, r)`에서 `r > n`을 막지 않는 것입니다.

## Chinese Remainder Theorem

중국인의 나머지 정리(CRT)는 서로소인 모듈러들의 합동식 연립 `x ≡ a_i (mod m_i)`이 `m_i`의 곱을 법으로 해를 하나만 가진다는 정리입니다. 모듈러가 서로소가 아니어도 풀 수 있습니다. 해가 있을 조건은 모든 쌍에서 `a_i`와 `a_j`가 `gcd(m_i, m_j)`를 법으로 같은 것이고, 해는 모듈러들의 최소공배수를 법으로 하나입니다.

두 식씩 합치는 방법이 모든 경우를 다룹니다. `x ≡ a1 (mod m1)`, `x ≡ a2 (mod m2)`에서 `x = a1 + m1 · t`로 놓고 `m1 · t ≡ a2 − a1 (mod m2)`를 풉니다. `g = gcd(m1, m2)`이고 `m1 · p + m2 · q = g`이면 `t = ((a2 − a1) / g) · p mod (m2 / g)`입니다. 합친 모듈러는 `lcm(m1, m2)`입니다. 모듈러의 곱이 2^53을 넘기 쉬우므로 BigInt로 씁니다.

```js
function egcdB(a, b) { // BigInt 판. [g, x, y]
  if (b === 0n) return [a, 1n, 0n]
  const [g, x1, y1] = egcdB(b, a % b)
  return [g, y1, x1 - (a / b) * y1]
}
function crt2(a1, m1, a2, m2) { // 모두 BigInt, 0 ≤ a < m
  const [g, p] = egcdB(m1, m2)
  const diff = a2 - a1
  if (diff % g !== 0n) return null // 해 없음
  const l = (m1 / g) * m2          // lcm
  const m = m2 / g
  const t = (((diff / g) * p) % m + m) % m
  return [(a1 + m1 * t) % l, l]
}
```

```js
function crt(rs, ms) { // 나머지 배열, 모듈러 배열 (BigInt)
  let x = rs[0], l = ms[0]
  for (let i = 1; i < rs.length; i++) {
    const r = crt2(x, l, rs[i], ms[i])
    if (r === null) return null
    x = r[0]; l = r[1]
  }
  return [x, l]
}
crt([2n, 3n, 2n], [3n, 5n, 7n]) // [23n, 105n]
crt([1n, 3n], [4n, 6n])         // [9n, 12n]
crt([1n, 2n], [4n, 6n])         // null
```

`x ≡ 2 (mod 3)`, `x ≡ 3 (mod 5)`, `x ≡ 2 (mod 7)`은 23입니다. 앞의 둘을 합치는 과정입니다.

| 단계 | 식 | 결과 |
|------|----|------|
| 시작 | `x ≡ 2 (mod 3)` | `x = 2`, 법 3 |
| 합치기 1 | `x ≡ 3 (mod 5)`와 합침 | `x = 8`, 법 15 |
| 합치기 2 | `x ≡ 2 (mod 7)`와 합침 | `x = 23`, 법 105 |

- `crt([1n, 3n], [4n, 6n])`은 `gcd(4, 6) = 2`에서 두 나머지가 홀수로 같아서 해가 있고 법은 `lcm = 12`입니다. `crt([1n, 2n], [4n, 6n])`은 1과 2가 2를 법으로 달라서 해가 없습니다.
- 시간은 합칠 때마다 확장 유클리드 O(log M)이라서 식이 k개이면 O(k log M)입니다.
- 서로소인 모듈러만 있으면 `M`을 모든 모듈러의 곱, `M_i = M / m_i`, `N_i`를 `M_i`의 mod `m_i` 역원이라 할 때 `Σ a_i · M_i · N_i`를 `M`으로 나눈 나머지가 해라는 직접 공식도 있습니다.
- 쓰임: "N으로 나누면 a, M으로 나누면 b가 남는 수", 합성수 모듈러를 소인수분해해 문제를 쪼개 풀고 합치기(조합을 합성수로 나눈 나머지), 주기가 다른 신호의 만남.

**문제의 단서:** "x를 3으로 나누면 2, 5로 나누면 3, 7로 나누면 2인 가장 작은 x", 모듈러가 합성수인 조합.

**흔한 실수:** 서로소라고 가정하고 역원 공식을 쓰는 것, 해의 존재 조건(`a2 − a1`이 `gcd`로 나누어떨어지는지)을 확인하지 않는 것, Number로 `m1 * t`를 계산해 2^53을 넘기는 것입니다.

## Matrix Exponentiation

행렬 거듭제곱은 선형 점화식의 n번째 항을 행렬의 n제곱으로 바꿔 O(log n)번의 행렬 곱으로 구하는 방법입니다. 거듭제곱의 분할 정복(57편)은 결합 법칙이 성립하는 모든 곱에 쓸 수 있어서 행렬에도 적용됩니다.

피보나치 `F(n) = F(n−1) + F(n−2)`는 이렇게 쓸 수 있습니다.

`[[1, 1], [1, 0]]^n = [[F(n+1), F(n)], [F(n), F(n−1)]]`

행렬 곱은 k × k에서 O(k^3)이고 곱하는 횟수가 O(log n)이므로 전체 O(k^3 log n)입니다.

```js
function matMul(A, B, m) {
  const n = A.length
  const C = [...Array(n)].map(() => Array(n).fill(0))
  for (let i = 0; i < n; i++)
    for (let k = 0; k < n; k++) {
      if (A[i][k] === 0) continue
      for (let j = 0; j < n; j++) {
        const v = mulmod(A[i][k], B[k][j], m)
        C[i][j] = (C[i][j] + v) % m
      }
    }
  return C
}
```

```js
function matPow(A, e, m) { // e: 2^53 미만의 Number
  let R = A.map((_, i) => A.map((_, j) => +(i === j)))
  for (; e > 0; e = Math.floor(e / 2)) {
    if (e % 2 === 1) R = matMul(R, A, m)
    A = matMul(A, A, m)
  }
  return R
}
const fib = (n, m) => matPow([[1, 1], [1, 0]], n, m)[0][1]
fib(10, 1000000007) // 55
```

`e = 10`(이진수 1010)의 진행은 `A^1`, `A^2`, `A^4`, `A^8`을 만들고 비트가 1인 `A^2`와 `A^8`을 곱합니다.

| 단계 | 제곱한 행렬 | 비트 | 결과 `R` |
|------|-------------|------|----------|
| 0 | `A^1 = [[1,1],[1,0]]` | 0 | 단위행렬 |
| 1 | `A^2 = [[2,1],[1,1]]` | 1 | `A^2` |
| 2 | `A^4 = [[5,3],[3,2]]` | 0 | `A^2` |
| 3 | `A^8 = [[34,21],[21,13]]` | 1 | `A^2 · A^8 = [[89,55],[55,34]]` |

`R[0][1] = 55 = F(10)`입니다.

- 일반 점화식 `f(n) = c1 · f(n−1) + … + ck · f(n−k)`는 첫 행이 `c1 … ck`이고 그 아래가 한 칸씩 내려가는 단위 행렬 모양의 k × k 행렬로 바꿉니다. 상태 벡터는 `(f(n−1), …, f(n−k))`입니다.
- 그래프의 인접 행렬을 k제곱하면 `[i][j]`가 길이가 정확히 k인 `i → j` 걷기의 수입니다. 정점 3개짜리 삼각형 그래프에서 길이 3인 걷기는 대각선이 2, 나머지가 3입니다.
- 곱셈을 덧셈으로, 덧셈을 `min`으로 바꾸면 최단 경로의 거듭제곱이 됩니다. 항등원은 대각선 0, 나머지 무한대입니다.
- 행렬 크기 k가 50 정도를 넘으면 O(k^3 log n)이 부담입니다. 점화식 항이 많으면 다른 방법을 찾습니다.
- 지수 `e`가 2^53을 넘으면 BigInt로 받아 `e % 2n`, `e /= 2n`으로 바꿉니다.
- 내부 합 `C[i][j] + mulmod(...)`은 `m` 미만 두 값의 합이라서 안전하지만, 합을 많이 모은 뒤에 `%`를 한 번만 하면 2^53을 넘을 수 있어서 매번 `% m`을 합니다.

**문제의 단서:** "N번째 항을 mod로 구하라"에서 N이 10^18, 점화식이 상수 계수의 선형식, 항 수 k가 작음, "길이가 정확히 K인 경로의 수".

**흔한 실수:** 단위행렬 대신 0 행렬로 결과를 시작하는 것, 모든 `A[i][k] · B[k][j]`에 2^53을 넘는 곱을 Number로 하는 것, 초기 상태 벡터와 행렬의 방향을 거꾸로 곱하는 것입니다.

## 피보나치 수 빠르게 구하기

피보나치의 fast doubling은 `F(n)`을 행렬 없이 두 항등식으로 지수를 절반씩 줄여 O(log n)에 구하는 방법입니다.

- `F(2k) = F(k) · (2 · F(k+1) − F(k))`
- `F(2k+1) = F(k+1)² + F(k)²`

`(F(k), F(k+1))` 쌍에서 `(F(2k), F(2k+1))`을 얻고, n이 홀수이면 한 칸 더 나아갑니다(`F(2k+2) = F(2k) + F(2k+1)`).

```js
function fibPair(n, m) { // [F(n), F(n+1)] mod m
  if (n === 0) return [0, 1]
  const [a, b] = fibPair(Math.floor(n / 2), m)
  // c = F(2k), d = F(2k+1)
  const c = mulmod(a, (2 * b - a + m) % m, m)
  const d = (mulmod(a, a, m) + mulmod(b, b, m)) % m
  return n % 2 === 0 ? [c, d] : [d, (c + d) % m]
}
fibPair(10, 1000000007)[0] // 55
fibPair(1e15, 1000000007)[0] // 648325137
```

`F(10)`을 구하는 호출은 `n = 10 → 5 → 2 → 1 → 0`으로 내려가고, 올라오며 쌍이 이렇게 됩니다.

| n | `(F(n), F(n+1))` |
|---|------------------|
| 0 | (0, 1) |
| 1 | (1, 1) |
| 2 | (1, 2) |
| 5 | (5, 8) |
| 10 | (55, 89) |

- 재귀 깊이가 log n이고 곱셈이 한 단계에 세 번이라서, 같은 O(log n)이어도 2 × 2 행렬 거듭제곱(한 단계에 8번 곱함)보다 상수가 작습니다.
- `(2 * b - a + m) % m`은 음수가 되지 않게 보정한 `2b − a`입니다.
- 나머지 수열 `F(n) mod m`은 같은 쌍이 반복되어 주기를 가집니다(피사노 주기). `n`이 아주 크면 주기로 줄일 수 있지만, fast doubling은 `n`이 10^18이어도 약 60단계라서 보통 필요 없습니다.
- `n`이 2^53을 넘으면 BigInt로 `n / 2n`, `n % 2n`을 씁니다.
- 피보나치의 합, `gcd(F(a), F(b)) = F(gcd(a, b))` 같은 성질도 쓰이지만 이 문서의 범위 밖입니다.

**문제의 단서:** "N번째 피보나치 수를 mod로", N ≥ 10^12.

**흔한 실수:** `F(0) = 0`과 `F(1) = 1`의 기준을 문제와 어긋나게 쓰는 것(1부터 시작하는 변형), `2 * b - a`가 음수가 되는 것을 보정하지 않는 것입니다.

## 뤼카 정리 개요

뤼카 정리(Lucas' theorem)는 소수 p에 대해 `C(n, r) mod p`를 n과 r의 p진법 자릿수별 조합의 곱으로 바꾸는 정리입니다. `n ≥ p`이면 `n!`이 p의 배수라서 팩토리얼 역원 방식이 막히는데, 이때 씁니다.

n과 r을 p진법으로 쓴 자릿수가 `n_i`, `r_i`일 때 다음이 성립합니다.

`C(n, r) ≡ ∏ C(n_i, r_i) (mod p)`

자릿수에서 `r_i > n_i`이면 `C`는 0이고 전체가 0입니다. 각 `C(n_i, r_i)`는 p 미만이라서 작은 표로 구합니다.

```js
function lucas(n, r, p, fact, inv) { // fact, inv: p 미만 표
  let res = 1
  while (n > 0 || r > 0) {
    const a = n % p, b = r % p
    if (b > a) return 0
    const c = mulmod(fact[a], inv[b], p)
    res = mulmod(res, mulmod(c, inv[a - b], p), p)
    n = Math.floor(n / p)
    r = Math.floor(r / p)
  }
  return res
}
const p = 7, t = buildFact(p - 1, p)
lucas(10, 3, p, t.fact, t.inv) // 1
```

`C(10, 3) = 120`이고 `120 mod 7 = 1`입니다. 7진법으로 `10 = (1, 3)`, `3 = (0, 3)`이라서 `C(1, 0) · C(3, 3) = 1 · 1 = 1`입니다.

- 표는 `p − 1`까지만 만들면 되어 O(p)이고, 쿼리는 자릿수 개수 `log_p n`입니다. p가 10^6 안팎이어도 n이 10^18까지 가능합니다.
- p는 소수여야 합니다. 합성수 모듈러는 소수의 거듭제곱으로 쪼개 CRT로 합치는 방법이 따로 있어서 여기서는 다루지 않습니다.
- n이 2^53을 넘으면 `Math.floor(n / p)`가 틀리므로 BigInt로 `n / p`, `n % p`를 씁니다.

**문제의 단서:** "C(n, r) mod p"에서 n이 p보다 크거나 같음(n이 10^18, p가 10^6 이하의 소수).

**흔한 실수:** `b > a`일 때 0을 돌려주는 조건을 빼먹는 것, `n`이 `p`보다 작은데도 뤼카를 쓰며 표 크기를 `n`까지 만드는 것입니다.

## 가우스 소거 개요

가우스 소거(Gauss elimination)는 연립일차방정식을 행 연산으로 풀어 해가 없는지, 하나인지, 무수히 많은지를 판별하고 해를 구하는 방법입니다. n개의 식과 n개의 미지수일 때 O(n^3)입니다. 코딩테스트에서는 모듈러 p(소수) 위의 연립방정식, 전구 켜고 끄기 같은 mod 2 연립방정식, 확률·기댓값 점화식이 연립방정식이 되는 문제에서 쓰입니다.

1. 열을 왼쪽부터 보며 그 열에서 0이 아닌 피벗 행을 찾아 위로 올린다.
2. 피벗 행으로 다른 모든 행의 그 열을 0으로 만든다(역원을 곱해 뺀다).
3. 피벗이 없는 열이 있으면 유일해가 아니다. 모든 열에 피벗이 있으면 각 행에서 해를 읽는다.

```js
function eliminate(M, c, p) { // 열 c의 다른 행을 0으로
  const n = M.length
  const iv = modInv(M[c][c], p)
  for (let r = 0; r < n; r++) {
    if (r === c || M[r][c] === 0) continue
    const f = mulmod(M[r][c], iv, p)
    for (let k = c; k <= n; k++)
      M[r][k] = (M[r][k] - mulmod(f, M[c][k], p) + p) % p
  }
}
```

```js
function solveMod(A, b, p) { // p는 소수. 유일해면 배열, 아니면 null
  const n = A.length
  const M = A.map((row, i) => [...row, b[i]])
  for (let c = 0; c < n; c++) {
    let piv = c
    while (piv < n && M[piv][c] === 0) piv++
    if (piv === n) return null
    const t = M[c]; M[c] = M[piv]; M[piv] = t
    eliminate(M, c, p)
  }
  return M.map((r, i) => mulmod(r[n], modInv(r[i], p), p))
}
solveMod([[2, 1], [1, 3]], [5, 5], 7) // [2, 1]
```

`2x + y = 5`, `x + 3y = 5` (mod 7)의 확대 행렬 진행입니다.

| 단계 | 확대 행렬 |
|------|-----------|
| 시작 | `[2 1 / 5]`, `[1 3 / 5]` |
| 열 0 소거 | `[2 1 / 5]`, `[0 6 / 6]` |
| 열 1 소거 | `[2 0 / 4]`, `[0 6 / 6]` |

`x = 4 / 2 = 2`, `y = 6 / 6 = 1`입니다(mod 7의 나눗셈은 역원 곱).

- 실수 계수에서는 피벗으로 그 열에서 절댓값이 가장 큰 행을 고릅니다. 작은 수로 나눠 오차가 커지는 것을 줄이기 위해서이고, 0 판정은 정확히 0이 아니라 `1e-9` 같은 허용 오차로 합니다. 그래도 크기가 50–100 정도의 행렬에서 오차가 쌓일 수 있습니다.
- 모듈러가 소수가 아니면 0이 아닌 값에도 역원이 없을 수 있어서 위 코드를 그대로 쓸 수 없습니다.
- mod 2 연립방정식은 비트 묶음으로 행 연산을 하면 비트 연산 한 번에 여러 열을 처리해 약 32배 빠릅니다. JavaScript의 비트 연산이 32비트라서 32열씩 `Int32Array`에 묶습니다(자세히는 24편).
- 피벗이 없는 열(자유 변수)이 있으면 그 변수는 아무 값이나 가질 수 있고 해가 무수히 많습니다. 식 쪽이 `0 = c`(c는 0이 아님)로 끝나면 해가 없습니다. 위 코드는 둘을 구분하지 않고 `null`을 돌려줍니다.

**문제의 단서:** 변수 n개가 식 n개로 얽힌 문제(n ≤ 수백), "각 스위치를 누르면 주변이 바뀐다"(mod 2), 기댓값이 서로 순환하는 점화식.

**흔한 실수:** 피벗 행을 교환하지 않고 `M[c][c]`가 0인 채로 진행하는 것, 확대 행렬의 마지막 열(우변)까지 연산하지 않는 것, 실수에서 `=== 0`으로 비교하는 것입니다.

## FFT·NTT 개요

FFT(고속 푸리에 변환)는 다항식(또는 수열)의 곱, 즉 합성곱 `c[k] = Σ a[i] · b[k − i]`를 O(n log n)에 구하는 알고리즘이고, NTT는 같은 구조를 모듈러 정수에서 하는 정확한 버전입니다. 개요만 다룹니다.

합성곱을 정의대로 구하면 O(n · m)입니다.

```js
function convolve(a, b) { // c[k] = Σ a[i] * b[k - i]
  const c = new Array(a.length + b.length - 1).fill(0)
  for (let i = 0; i < a.length; i++)
    for (let j = 0; j < b.length; j++)
      c[i + j] += a[i] * b[j]
  return c
}
convolve([1, 2], [3, 1]) // [3, 7, 2]
```

`(1 + 2x)(3 + x) = 3 + 7x + 2x²`이고 계수가 곧 합성곱입니다. 길이가 10^5인 두 수열은 이 방식으로 10^10번이 필요합니다.

FFT의 아이디어는 점 값 표현입니다. 다항식은 계수로도, 충분히 많은 점에서의 값으로도 정해지는데, 점 값에서는 곱이 같은 점의 값끼리의 곱으로 단순합니다.

1. 두 수열을 결과 길이(`a.length + b.length − 1`) 이상의 2의 거듭제곱 길이로 0을 채운다.
2. 각각을 n제곱근(1의 n제곱근)들에서의 값으로 변환한다(DFT). 분할 정복으로 O(n log n)이다.
3. 같은 점끼리 곱한다.
4. 역변환해 계수로 되돌린다.

| 방식 | 계산 | 장점 | 한계 |
|------|------|------|------|
| FFT | 복소수 | 실수 계수 가능 | 부동소수점 오차로 계수가 크면 틀림 |
| NTT | 소수 p를 법으로 하는 정수 | 오차 없이 정확 | p가 `c · 2^k + 1` 꼴이고 길이가 2^k 이하 |

- NTT에서 1의 n제곱근 대신 mod p의 원시근에서 얻은 값을 씁니다. `p = c · 2^k + 1`이고 g가 p의 원시근이면 `g^c`가 mod p의 원시 2^k제곱근입니다. 널리 쓰이는 `p = 998244353`은 `119 · 2^23 + 1`이고 원시근 3을 가져서 길이 2^23까지 변환할 수 있습니다.
- 곱셈마다 모듈러 곱이 필요합니다. 998244353은 곱이 2^53을 넘으므로 `mulmod`(57편)나 BigInt가 들어가서 JavaScript에서는 상수가 큽니다.
- 쓰임: 큰 수의 곱셈(자릿수를 계수로 해 합성곱 후 올림 처리), 두 집합의 원소 합이 k가 되는 쌍의 수, 경우의 수 DP를 합성곱으로 합치기, 문자열의 일치 위치 세기.
- 결과 계수를 mod p로만 구하는 문제는 NTT, 계수가 작은 정수로 정확해야 하고 mod가 정해져 있지 않으면 계수 크기를 따져 FFT나 NTT 여러 개를 고릅니다.
- 이 문서에서는 구현을 생략합니다. 구현은 비트 반전 순서 정렬과 나비 연산(butterfly)으로 이루어진 반복문입니다.

**문제의 단서:** 수열 두 개를 "합해서 k가 되는" 모든 쌍으로 세기, 길이가 10^5 이상인 합성곱, 아주 큰 자릿수의 곱셈.

**흔한 실수:** 결과 길이보다 작은 크기로 변환해 앞쪽 계수와 뒤쪽 계수가 겹치는 것(순환 합성곱이 됨), FFT의 부동소수점 결과를 반올림하지 않는 것, NTT 모듈러가 길이 조건을 만족하는지 확인하지 않는 것입니다.

## 핵심 정리

- 확장 유클리드는 `a·x + b·y = gcd`의 `x`, `y`를 O(log)에 구하고, 이것으로 합성수 모듈러의 역원, `b·x ≡ a (mod m)`의 해, 부정 방정식을 풉니다.
- 모듈러 나눗셈은 `gcd(b, m) = 1`일 때 역원을 곱하는 것이고, 1이 아니면 `gcd`가 `a`를 나눌 때만 `m/gcd`를 법으로 해가 있습니다.
- 조합 전처리는 `fact`와 `inv`(마지막만 역원, 나머지는 `· i`로 내려감)로 쿼리당 O(1)이고, `n!`과 모듈러가 서로소여야 하며 `n ≥ p`이면 뤼카 정리를 씁니다.
- CRT는 합동식을 두 개씩 합쳐 해를 `lcm` 법으로 구하며, 쌍마다 `gcd` 조건이 필요하고 모듈러의 곱이 커서 BigInt를 씁니다.
- 선형 점화식은 행렬 거듭제곱으로 O(k^3 log n)에 풀고, 피보나치는 fast doubling이 상수가 더 작습니다.
- 가우스 소거는 O(n^3)이며 mod p에서는 역원을 쓰고 실수에서는 최대 절댓값 피벗과 허용 오차를 씁니다. FFT·NTT는 합성곱을 O(n log n)에 구하고 NTT는 모듈러 소수 `c · 2^k + 1`이 필요합니다.
