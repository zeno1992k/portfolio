## 상태 BFS

상태 BFS는 BFS의 정점을 **위치가 아니라 상태**로 두는 방식입니다. 상태는 위치와 "문제의 답에 영향을 주는 추가 정보"를 묶은 것입니다. 같은 칸이라도 추가 정보가 다르면 다른 정점입니다. 가능한 모든 상태가 이루는 집합을 상태 공간(state space)이라고 하고, 상태 BFS는 시작 상태에서 목표 상태까지 가장 적은 이동으로 가는 길을 상태 공간에서 찾습니다. BFS 자체는 38편과 같습니다.

위치만으로 방문을 표시하면 틀리는 이유는 다음과 같습니다. 벽을 한 번 부수고 칸 `P`에 먼저 도착했더라도, 나중에 벽을 부수지 않고 `P`에 도착하는 경로가 있으면 그쪽이 앞으로 더 많은 선택지를 가집니다. 위치로만 방문을 막으면 이 경로가 버려집니다.

| 문제 | 추가 정보 | 값의 개수 |
|------|-----------|-----------|
| 벽을 최대 K번 부술 수 있다 | 지금까지 부순 횟수 | K + 1 |
| 열쇠 K종을 모아 문을 연다 | 가진 열쇠의 집합 | 2의 K제곱 |
| 낮과 밤이 번갈아 바뀐다 | 시간을 2로 나눈 나머지 | 2 |
| 같은 방향으로 이어서 움직여야 한다 | 마지막 이동 방향 | 4 |
| 이동 방식이 M가지이고 전환할 수 있다 | 현재 방식(모드) | M |

상태가 정수 하나로 표현돼 있다면(아래 "상태를 정수 하나로 인코딩") BFS는 상태에만 의존하는 하나의 틀로 쓸 수 있습니다. 이웃 상태를 돌려주는 함수와 목표 판정 함수만 문제마다 바꿉니다.

```js
function bfsState(start, size, nextStates, isGoal) {
  const dist = new Int32Array(size).fill(-1)
  const queue = [start]
  dist[start] = 0
  for (let head = 0; head < queue.length; head++) {
    const s = queue[head]
    if (isGoal(s)) return dist[s]
    for (const t of nextStates(s)) {
      if (dist[t] !== -1) continue
      dist[t] = dist[s] + 1
      queue.push(t)
    }
  }
  return -1
}
```

- `size`는 전체 상태 수입니다. 상태는 한 번씩만 큐에 들어가므로 시간은 O(상태 수 × 상태당 이동 수)입니다.
- 목표에 닿지 못하면 `-1`입니다.
- 목표 상태가 하나가 아니라 "특정 칸에 어떤 상태로든 도착"이면 `isGoal`이 그 조건을 검사합니다. 가장 먼저 꺼낸 상태가 최단입니다.

**문제의 단서:** 같은 칸을 여러 번 지나야 할 수 있는 최단거리, "최대 K번", "열쇠", "상태에 따라 이동 규칙이 달라진다"입니다.

**흔한 실수:** 상태에 필요한 정보를 빼먹고 위치로만 방문 처리하는 것입니다. 반대로 답에 영향이 없는 정보까지 넣으면 상태 수만 늘어서 시간과 메모리가 낭비됩니다.

## visited[row][col][state]

격자 문제에서는 방문 배열에 **상태 차원을 하나 더 붙입니다**. `visited[row][col][state]`는 "이 칸에 이 상태로 이미 온 적이 있는가"입니다. 같은 칸이라도 `state`가 다르면 별개로 다룹니다.

```js
const visited = Array.from({ length: H }, () =>
  Array.from({ length: W }, () => new Array(S).fill(false)))
```

- `S`는 한 칸에서 가질 수 있는 상태의 개수입니다(벽 부수기 K번이면 K + 1).
- 마지막 차원은 `new Array(S).fill(false)`로 만들어도 됩니다. `false`는 원시 값이라 모든 원소가 독립입니다. 반면 2차원 이상의 배열을 `fill`에 직접 넣으면 같은 배열이 공유됩니다(자세히는 5편).
- 거리도 같은 모양의 `dist[row][col][state]`로 둡니다. 방문 배열과 합쳐 `-1`을 방문 전으로 쓰면 하나로 충분합니다(자세히는 38편).

이동할 때 새 상태를 계산한 뒤, 새 상태의 방문 여부를 확인합니다.

```js
// (r, c, s)에서 (nr, nc)로 이동하고 상태가 ns가 될 때
if (visited[nr][nc][ns]) continue   // 이 칸에 이 상태로 이미 옴
visited[nr][nc][ns] = true
queue.push([nr, nc, ns, d + 1])
```

- 방문 표시는 38편과 같이 **큐에 넣을 때** 합니다.
- 상태가 많으면 3차원 배열은 배열 객체가 너무 많아져서 느리고 메모리를 많이 씁니다. 그때는 상태를 정수 하나로 만들어 1차원 `Int32Array`를 씁니다(다음 절).

**흔한 실수:** `visited[r][c]`만 쓰고 상태 차원을 빼는 것입니다. 같은 칸에 도착한 두 번째 경로(다른 상태)가 방문한 칸으로 취급돼 버려지고 답이 `-1`이나 너무 큰 값이 됩니다.

## 상태를 정수 하나로 인코딩

위치와 추가 정보를 정수 하나로 묶으면 `dist`와 큐를 1차원 배열로 둘 수 있습니다. 칸마다 상태가 S개라면 칸 번호 `r * W + c`에 S를 곱하고 추가 정보 `x`(0부터 S − 1까지)를 더합니다. 숫자를 자릿수 단위로 묶는 것과 같습니다.

```js
let W, S                        // 열 수, 칸당 상태 수
const encode = (r, c, x) => (r * W + c) * S + x
function decode(s) {
  const x = s % S
  const cell = (s - x) / S
  return [Math.floor(cell / W), cell % W, x]
}
```

- 상태 번호는 0부터 `H * W * S - 1`까지의 서로 다른 정수입니다. 이 값이 `dist`의 크기가 됩니다.
- `x`를 먼저 빼면 `(s - x) / S`는 나누어떨어져서 정확히 정수입니다.
- 칸 번호를 정수 하나로 바꾸는 방법은 17편입니다.
- 추가 정보가 비트마스크이고 S가 2의 거듭제곱이면 곱셈 대신 시프트(`(cell << K) | mask`)를 쓸 수 있습니다. 비트 연산은 32비트 정수로 계산되므로 상태 번호가 2의 31제곱 미만일 때만 안전합니다(자세히는 24편).
- 칸이 아니라 정점인 문제는 `cell` 자리에 정점 번호를 넣습니다. 예를 들어 정점 n개와 방문 집합 mask는 `node * (1 << n) + mask`입니다.

상태가 많을 때는 큐도 `Int32Array`로 두면 메모리가 예측됩니다. 상태는 한 번씩만 들어가므로 크기가 상태 수면 충분합니다.

```js
const queue = new Int32Array(size)
let head = 0, tail = 0
queue[tail++] = start
while (head < tail) {
  const s = queue[head++]
  // 이웃 상태 t를 만들어 dist[t] = dist[s] + 1; queue[tail++] = t
}
```

**흔한 실수:** `encode`와 `decode`의 `W`나 `S`가 서로 다른 값인 것입니다. 문제를 풀 때마다 `W`, `S`를 맞춰 둔 뒤 사용합니다. 칸 번호에 곱하는 수가 `S`이고, `x`는 반드시 `S`보다 작아야 합니다.

## 상태 수로 메모리 계산하기

상태 BFS의 비용은 **상태 수**로 정해집니다. 코드를 쓰기 전에 상태 수와 배열 크기를 계산해서 메모리 제한 안에 들어가는지 확인합니다.

- 상태 수 = 칸 수(또는 정점 수) × 칸당 추가 상태 수입니다.
- 메모리 = 상태 수 × 원소 한 개의 바이트 수 × 배열 개수입니다.
- 시간 = 상태 수 × 상태당 이동 수입니다. 이동이 상하좌우 4가지이면 상태 수의 4배 정도입니다.

타입 배열의 원소 크기는 `Uint8Array` 1바이트, `Int16Array` 2바이트, `Int32Array` 4바이트, `Float64Array` 8바이트입니다. 타입 배열은 만들 때 0으로 채워집니다. 그래서 `-1`로 쓰려면 `.fill(-1)`이 필요합니다.

| 문제 | 상태 수 | `Int32Array` 하나 | `Uint8Array` 하나 |
|------|---------|-------------------|-------------------|
| 1000 × 1000 격자, 벽 10번(S = 11) | 11,000,000 | 약 44MB | 약 11MB |
| 50 × 50 격자, 열쇠 6종(S = 64) | 160,000 | 약 640KB | 약 160KB |
| 정점 20개, 방문 집합(20 × 2의 20제곱) | 20,971,520 | 약 84MB | 약 21MB |

- 방문 여부만 알면 되면 `Uint8Array`, 거리도 필요하면 `Int32Array`입니다. 거리가 255 이하로 보장되면 `Uint8Array`로 거리까지 담을 수 있습니다.
- `dist`와 큐를 모두 상태 수 크기로 두면 메모리가 두 배입니다. 위 표의 정점 20개 문제는 둘을 합쳐 약 168MB입니다.
- 큐에 `[r, c, s]` 배열을 넣으면 상태마다 작은 배열 객체가 만들어져서 숫자만 담는 타입 배열보다 훨씬 많이 씁니다. 상태가 수백만이면 정수 하나로 인코딩해 넣습니다.
- 메모리와 시간 제한은 문제마다 다르므로, 계산한 값을 문제의 제한과 비교합니다(입력 크기와 공간복잡도는 14편).

**흔한 실수:** 상태 수를 계산하지 않고 3차원 배열로 시작하는 것입니다. 상태가 천만 개를 넘는 문제에서 메모리 초과나 시간 초과가 납니다. 상태를 줄일 수 있는지(예를 들어 부순 횟수 중 필요한 것만) 먼저 생각합니다.

## 벽 부수기 / 열쇠 / 모드 상태 BFS

### 벽 부수기

벽을 최대 K번 부술 수 있을 때 `(0, 0)`에서 `(H - 1, W - 1)`까지의 최소 이동 횟수를 구합니다. 추가 상태는 부순 횟수 `b`(0부터 K까지)이고, 벽 칸으로 들어가면 `b`가 1 늘며 `b`가 K를 넘으면 이동할 수 없습니다. 아래 코드에서 `'1'`은 벽, `'0'`은 길입니다.

```js
function wallStates(grid, K) {
  return (s) => {
    const [r, c, b] = decode(s)
    const out = []
    for (let d = 0; d < 4; d++) {
      const nr = r + DR[d], nc = c + DC[d]
      const ch = grid[nr]?.[nc]
      if (ch === undefined) continue
      const nb = b + (ch === '1' ? 1 : 0)
      if (nb <= K) out.push(encode(nr, nc, nb))
    }
    return out
  }
}
```

`grid[nr]?.[nc]`는 범위 밖이면 `undefined`입니다(옵셔널 체이닝). `DR`, `DC`는 38편의 방향 배열입니다. 이 함수와 `bfsState`를 연결합니다.

```js
function minWallBreak(grid, K) {
  const H = grid.length
  W = grid[0].length
  S = K + 1
  const goal = (s) => {
    const [r, c] = decode(s)
    return r === H - 1 && c === W - 1
  }
  const next = wallStates(grid, K)
  return bfsState(encode(0, 0, 0), H * W * S, next, goal)
}
```

`['010', '010', '010']`에서 `K = 0`이면 `-1`이고, `K = 1`이면 중간 벽을 하나 부수고 지나서 `4`입니다.

### 열쇠

문과 열쇠가 있는 미로는 추가 상태가 가진 열쇠의 집합이고, 비트마스크로 표현합니다(다음 절).

### 모드

모드는 "지금 어떤 규칙으로 움직이는가"를 상태로 둔 것입니다. 이동 규칙이 모드에 따라 달라지므로 `nextStates`가 모드에 맞는 이동만 만듭니다.

- 말 이동: 일반 이동 4방향은 횟수를 그대로 두고, 체스 나이트처럼 두 칸 건너 한 칸 가는 이동 8방향은 횟수를 1 늘립니다(K번까지만). 상태는 `(r, c, 말처럼 움직인 횟수)`입니다.
- 시간대: 벽이 짝수 초에만 열리면 상태는 `(r, c, 시간 % 2)`이고, 한 칸 이동할 때 시간대가 뒤집힙니다.
- 방향 유지: "꺾을 때 비용"이나 "같은 방향으로 최대 3칸" 같은 조건은 `(r, c, 마지막 방향)`을 상태로 둡니다. 비용이 0과 1로 나뉘면 0-1 BFS를 함께 씁니다(아래).

**흔한 실수:** 벽을 부수는 횟수 `b`를 큐의 값으로만 들고 방문 배열에서 빼먹는 것입니다. `b`가 다른 상태는 서로 다른 정점이어야 합니다.

## BFS + 비트마스크 상태

열쇠를 집합으로 모으는 문제는 가진 열쇠를 **비트마스크**(각 비트가 열쇠 하나의 보유 여부)로 상태에 담습니다. 비트 `i`가 1이면 `i`번째 열쇠를 가진 것입니다. 열쇠를 줍는 일은 `mask | (1 << i)`, 문을 열 수 있는지는 `(mask >> i) & 1`로 확인합니다(자세히는 24편). 상태 수는 칸 수 × 2의 K제곱이라서 K가 20을 넘으면 어렵고, 열쇠 종류가 6 정도인 문제가 대표적입니다.

소문자 `a`–`f`는 열쇠, 대문자 `A`–`F`는 같은 알파벳 열쇠가 있어야 지나는 문, `#`은 벽, `X`는 출구라고 하겠습니다. 칸에 들어갈 때 새 마스크를 구합니다. 들어갈 수 없으면 `-1`입니다.

```js
function enter(ch, m) {
  if (ch === undefined || ch === '#') return -1
  if (ch >= 'a' && ch <= 'f')
    return m | (1 << (ch.charCodeAt(0) - 97))
  if (ch >= 'A' && ch <= 'F')
    return (m >> (ch.charCodeAt(0) - 65)) & 1 ? m : -1
  return m
}
```

```js
function keyStates(grid) {
  return (s) => {
    const [r, c, m] = decode(s)
    const out = []
    for (let d = 0; d < 4; d++) {
      const nr = r + DR[d], nc = c + DC[d]
      const nm = enter(grid[nr]?.[nc], m)
      if (nm !== -1) out.push(encode(nr, nc, nm))
    }
    return out
  }
}
```

`S = 1 << K`로 두고 `bfsState`에 `keyStates`를 연결하면 됩니다. 목표 판정은 `grid[r][c] === 'X'`입니다.

- 한 줄짜리 `.aA.X`(왼쪽에서 시작)는 열쇠 `a`를 먼저 줍고 문 `A`를 지나서 `4`입니다.
- `.A.aX`는 열쇠가 문 뒤에 있어서 문을 열 수 없으므로 `-1`입니다. 같은 칸을 열쇠 없이 방문한 상태와 열쇠를 가진 상태가 다른 정점이기 때문에 구분됩니다.
- 열쇠를 이미 가진 칸에 다시 와도 마스크가 그대로이므로 새 상태가 생기지 않습니다. 열쇠를 가진 상태는 마스크가 커질수록 이동이 자유로워지는 단조 증가입니다.

같은 틀로 **모든 정점을 방문하는 최단 경로**도 풉니다. 상태는 `(현재 정점, 방문한 정점 집합)`이고, 모든 정점을 시작 상태로 넣은 뒤 마스크가 `(1 << n) - 1`이 되는 첫 상태가 답입니다. 정점이 15–20개 이하일 때 쓰며, 간선에 가중치가 있으면 비트마스크 DP(73편)를 씁니다.

**흔한 실수:**

- 열쇠를 주운 뒤 마스크를 갱신하지 않고 큐에 넣는 것입니다.
- `1 << i`의 `i`를 32 이상으로 두는 것입니다. 시프트 양은 32로 나눈 나머지로 적용돼 엉뚱한 비트가 켜집니다(자세히는 24편).

## 양방향 BFS

양방향 BFS(bidirectional BFS)는 **시작 상태와 목표 상태에서 동시에** BFS를 시작해서 중간에서 만나면 끝내는 방법입니다. 한 방향으로만 깊이 d까지 탐색하면 이웃 수(분기 수)를 b라고 할 때 약 b의 d제곱 개를 보지만, 양쪽에서 d의 절반씩 가면 약 2 × b의 (d/2)제곱 개만 봅니다. 상태가 폭발적으로 늘어나는 문제(퍼즐, 단어 변환 등)에서 탐색 범위를 크게 줄입니다.

조건은 두 가지입니다. 목표 상태가 **하나로 정해져 있어야** 하고, 한 이동을 거꾸로 되짚을 수 있어야 합니다. 방향 그래프라면 목표 쪽 탐색은 간선을 뒤집은 역방향 그래프에서 합니다(자세히는 37편). 아래 코드는 무방향 그래프를 가정합니다.

```js
function expand(adj, front, mine, other) {
  const next = []
  for (const u of front)
    for (const v of adj[u]) {
      if (other[v] !== -1)
        return { next, ans: mine[u] + 1 + other[v] }
      if (mine[v] !== -1) continue
      mine[v] = mine[u] + 1
      next.push(v)
    }
  return { next, ans: -1 }
}
```

```js
function biBfs(n, adj, s, t) {
  if (s === t) return 0
  const ds = new Array(n).fill(-1), dt = ds.slice()
  ds[s] = 0; dt[t] = 0
  let [fa, da, fb, db] = [[s], ds, [t], dt]
  while (fa.length > 0 && fb.length > 0) {
    if (fa.length > fb.length)
      [fa, da, fb, db] = [fb, db, fa, da]
    const r = expand(adj, fa, da, db)
    if (r.ans !== -1) return r.ans
    fa = r.next
  }
  return -1
}
```

- `ds`, `dt`는 시작점과 목표점에서의 거리 배열이고, `fa`, `fb`는 각 쪽의 현재 레벨입니다. `fa`가 더 크면 두 쪽의 역할을 맞바꿔서 항상 `fa`를 확장합니다.
- 매번 **더 작은 쪽의 레벨을 통째로** 확장합니다. 작은 쪽을 늘려야 탐색하는 상태 수가 적습니다.
- 한 쪽 탐색이 반대쪽이 이미 방문한 정점을 발견하면 `mine[u] + 1 + other[v]`가 답입니다. 레벨 단위로 확장하는 한, 처음 만났을 때의 값이 최단입니다. 만나기 전까지는 두 쪽이 닿은 깊이의 합 이하인 경로가 없다는 것이 확인된 상태이고, 이번 확장으로 이어진 경로의 길이는 그 합보다 정확히 1 큰 값이기 때문입니다.
- 한쪽 큐가 비면 닿지 못하는 것이므로 `-1`입니다.
- 시작점과 목표가 같으면(`s === t`) 거리는 0입니다.
- 상태가 정수로 인코딩돼 있으면 `ds`, `dt`를 `Int32Array`로, 상태가 문자열이나 배열이면 `Map`으로 둡니다(키 설계는 9편).

**흔한 실수:**

- 두 쪽을 번갈아 한 칸(정점 하나)씩만 확장하며 처음 만난 즉시 `ds + dt`를 답으로 쓰는 것입니다. 레벨 단위로 확장하지 않으면 최단이 아닌 길에서 먼저 만날 수 있습니다.
- 목표가 여러 개이거나 불분명한 문제에 쓰는 것입니다. 목표가 여러 개이면 모두를 시작점으로 둔 다중 시작점 BFS(38편)로 바꿔야 합니다.

## 0-1 BFS

0-1 BFS는 **간선 가중치가 0 또는 1뿐인 그래프**에서 단일 시작점 최단거리를 O(V + E)에 구합니다. 일반 BFS는 모든 이동 비용이 같을 때만 맞고, 가중치가 섞이면 Dijkstra(48편)가 필요하지만 가중치가 0과 1뿐이면 우선순위 큐 없이 풀 수 있습니다.

핵심은 **데크(deque)** 입니다. 가중치 0인 간선으로 닿은 정점은 거리가 그대로이므로 **큐의 앞**에 넣어 바로 처리하고, 가중치 1인 간선으로 닿은 정점은 **뒤**에 넣습니다. 그러면 큐에는 항상 거리가 d인 정점들과 d + 1인 정점들만 이 순서로 놓입니다(데크는 20편).

자바스크립트에는 내장 데크가 없으므로, 아래 코드는 같은 동작을 두 목록으로 구현합니다. `processLevel`은 거리 `d`의 목록 `cur`를 처리합니다. 0 간선으로 닿는 정점은 `cur`에 계속 덧붙여 같은 거리에서 이어서 처리하고, 1 간선으로 닿는 정점은 `next`에 모았다가 다음 거리에서 처리합니다.

```js
function processLevel(adj, dist, cur, d) {
  const next = []
  for (let i = 0; i < cur.length; i++) {
    const u = cur[i]
    if (dist[u] !== d) continue     // 더 일찍 처리된 정점
    for (const [v, w] of adj[u]) {
      if (dist[v] <= d + w) continue
      dist[v] = d + w
      if (w === 0) cur.push(v)
      else next.push(v)
    }
  }
  return next
}
```

```js
function bfs01(n, adj, s) {   // adj[u] = [[v, w], ...]
  const dist = new Array(n).fill(Infinity)
  let cur = [s]
  dist[s] = 0
  for (let d = 0; cur.length > 0; d++)
    cur = processLevel(adj, dist, cur, d)
  return dist
}
```

- 정점이 `next`에 들어간 뒤 0 간선으로 더 짧게 닿을 수 있습니다. 그때 `dist[v]`가 `d`로 줄고 `cur`에도 들어가서, 나중에 `next`에서 꺼낼 때는 `dist[u] !== d`라서 건너뜁니다.
- 각 정점의 거리는 많아야 두 번만 갱신돼서 전체가 O(V + E)입니다.
- 닿지 못한 정점은 `Infinity`로 남습니다.
- 격자에서는 길로 들어가면 0, 벽으로 들어가면 1로 두면 **부순 벽의 최소 개수**를 구합니다. 횟수 제한 K가 없으면 상태를 늘리지 않고 0-1 BFS 한 번으로 충분합니다. 제한 K가 있으면 위의 벽 부수기 상태 BFS를 씁니다.
- 방향 상태와 함께 "꺾을 때마다 비용 1"인 문제는 `(r, c, 방향)` 상태에서 직진은 0, 꺾기는 1로 둔 0-1 BFS입니다.

**흔한 실수:**

- 가중치가 0과 1이 아닌데(2나 3이 섞임) 0-1 BFS를 쓰는 것입니다. 틀린 답이 나옵니다. 일반 양수 가중치는 Dijkstra입니다.
- 정점을 한 번 꺼내 처리했다고 해서 `dist`를 더 줄이지 않는다고 가정하는 것입니다. 0 간선으로 같은 거리의 다른 정점을 통해 갱신될 수 있으므로 `dist[v] <= d + w` 검사로 거릅니다.

## A* 탐색 개요

A*(A-star)는 목표까지의 **남은 거리 추정값**을 이용해서 목표 쪽으로 먼저 탐색하는 최단 경로 알고리즘입니다. 각 상태 `n`의 우선순위는 `f(n) = g(n) + h(n)`입니다. `g(n)`은 시작에서 `n`까지 실제로 온 비용이고, `h(n)`은 `n`에서 목표까지 남은 비용의 추정값(휴리스틱)입니다. 우선순위 큐(47편)에서 `f`가 가장 작은 상태부터 꺼냅니다. BFS나 Dijkstra는 `h(n) = 0`인 특수한 경우라서 목표와 반대 방향으로도 퍼지는데, A*는 좋은 추정이 있으면 훨씬 적은 상태만 봅니다.

최적성은 추정값의 조건이 정합니다.

- 허용 가능(admissible): `h`가 실제 남은 비용을 절대 넘지 않는다. 이러면 A*가 최적 경로를 찾습니다.
- 일관적(consistent): 모든 간선 `(x, y)`에 대해 `h(x)`가 `비용(x, y) + h(y)` 이하이다. 이러면 상태를 한 번씩만 확장해도 최적이어서 방문 배열을 쓸 수 있습니다.

격자에서 상하좌우로만 움직이고 칸마다 비용이 1이면 맨해튼 거리 `abs(r - tr) + abs(c - tc)`가 허용 가능하고 일관적인 `h`입니다. 벽이 있어도 실제 거리가 맨해튼 거리보다 짧아질 수 없기 때문입니다. 8방향 이동이면 맨해튼 거리는 실제보다 클 수 있으므로 체비쇼프 거리(가로·세로 차이의 큰 값)를 씁니다.

```text
open ← 우선순위 큐 (f 기준)
g[시작] = 0, open에 시작 넣기
open이 빌 때까지:
  n ← f가 가장 작은 상태를 꺼냄
  n이 목표이면 g[n] 반환
  n의 이웃 y마다:
    새 g = g[n] + 비용(n, y)
    새 g < g[y] 이면 g[y] 갱신, f = g[y] + h(y)로 open에 넣기
```

- 코딩테스트에서는 BFS, 0-1 BFS, Dijkstra로 대부분 풀려서 A*가 꼭 필요한 일은 드뭅니다. 슬라이딩 퍼즐처럼 상태가 매우 많고 좋은 추정값이 있는 문제에서 가끔 쓰입니다.
- `h`가 실제 비용을 넘는(허용 불가) 추정이면 빨라질 수는 있지만 최단이 아닐 수 있습니다.
- 일관적이지 않은 `h`는 이미 확장한 상태를 다시 열어야 해서 방문 배열 방식이 틀립니다.

## 핵심 정리

- 상태 BFS는 정점을 (위치, 추가 정보)로 두며, 방문 배열에 상태 차원(`visited[row][col][state]`)을 더해서 같은 칸의 서로 다른 상태를 구분합니다.
- 상태를 정수 하나로 인코딩하면 `Int32Array`로 `dist`와 큐를 만들 수 있고, 메모리는 상태 수 × 원소 바이트 수로 미리 계산합니다.
- 벽 부수기는 부순 횟수, 열쇠는 비트마스크, 모드는 현재 규칙을 상태로 두며 전이 함수만 문제마다 바꿉니다.
- 양방향 BFS는 시작과 목표에서 작은 쪽 레벨을 통째로 번갈아 확장해 탐색 범위를 줄이고, 목표가 하나로 정해져 있을 때 씁니다.
- 0-1 BFS는 가중치가 0 또는 1일 때 데크(0은 앞, 1은 뒤)로 O(V + E)에 풀며, 가중치가 더 다양하면 Dijkstra입니다.
- A*는 `f = g + h`로 목표 쪽을 먼저 탐색하며, `h`가 실제 비용을 넘지 않을 때 최적입니다.
