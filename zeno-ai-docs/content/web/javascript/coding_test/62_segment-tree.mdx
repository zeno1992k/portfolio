## Segment Tree 개념

세그먼트 트리(segment tree)는 배열의 구간을 이진 트리로 쪼개고, 각 노드에 그 구간의 요약 값(합, 최솟값, 최댓값 등)을 저장하는 자료구조입니다. 값이 바뀌는 배열에서 구간 질의를 여러 번 받을 때 질의와 갱신을 모두 O(log N)에 처리합니다.

- 루트는 전체 구간 `[0, N-1]`을 맡습니다. 한 노드의 구간 `[l, r]`을 가운데 `mid = (l + r) >> 1`에서 `[l, mid]`와 `[mid+1, r]`로 나눠 두 자식에게 줍니다. 구간 길이가 1인 노드(리프)가 원소 하나입니다.
- 노드의 값은 두 자식의 값을 합쳐서 만듭니다. 합 트리에서는 두 자식의 합, 최소 트리에서는 두 자식 중 작은 값입니다.
- 다른 방법과 비교하면 다음과 같습니다.

| 방법 | 구간 질의 | 점 갱신 | 쓰는 때 |
|------|-----------|---------|---------|
| 배열을 그대로 순회 | O(N) | O(1) | 질의가 적다 |
| 누적합(29편) | O(1) | O(N) | 값이 바뀌지 않는다 |
| 세그먼트 트리 | O(log N) | O(log N) | 값이 바뀌고 질의도 많다 |

노드는 힙(46편)처럼 배열 하나에 담습니다. 루트를 1번으로 두고 노드 `v`의 왼쪽 자식은 `2v`, 오른쪽 자식은 `2v + 1`입니다(힙의 0부터 시작하는 번호와 달리 1부터 시작합니다).

- 트리 높이는 `ceil(log2 N) + 1`이고, 배열 크기를 `4N`으로 잡으면 N이 2의 거듭제곱이 아니어도 항상 충분합니다.
- 시간은 생성 O(N), 질의·갱신 각 O(log N)이고 공간은 O(N)입니다.
- 질의 구간이 비어 있을 때를 대비해 합치는 연산의 항등원이 필요합니다. 합은 0, 최솟값은 `Infinity`입니다(아래 "구간 최소" 절).
- 합치는 연산은 결합법칙을 만족해야 합니다. 합, 최소, 최대, 최대공약수, XOR이 해당합니다.

문제 문장의 단서는 "값이 바뀐다", "구간의 합·최솟값·최댓값을 구한다", "질의가 10^5 이상"입니다. 값이 바뀌지 않으면 누적합이 더 간단합니다.

## Tree 생성

배열 `a`로 트리 `t`를 만드는 `build`는 재귀로 구간을 쪼개며 내려가 리프에 값을 넣고, 올라오며 부모를 계산합니다.

```js
const merge = (x, y) => x + y    // 합치는 연산
const ID = 0                     // 항등원
let a = [2, 5, 1, 4, 3, 6]
let t = new Float64Array(4 * a.length)
function build(v, l, r) {
  if (l === r) { t[v] = a[l]; return }
  const m = (l + r) >> 1
  build(2 * v, l, m)
  build(2 * v + 1, m + 1, r)
  t[v] = merge(t[2 * v], t[2 * v + 1])
}
build(1, 0, a.length - 1)        // t[1]은 21 (전체 합)
```

위 배열의 트리는 다음과 같습니다. 노드 번호는 배열 `t`의 인덱스입니다.

| 노드 | 구간 | 값 |
|------|------|----|
| 1 | `[0,5]` | 21 |
| 2 | `[0,2]` | 8 |
| 3 | `[3,5]` | 13 |
| 4 | `[0,1]` | 7 |
| 5 | `[2,2]` | 1 |
| 6 | `[3,4]` | 7 |
| 7 | `[5,5]` | 6 |
| 8, 9 | `[0,0]`, `[1,1]` | 2, 5 |
| 12, 13 | `[3,3]`, `[4,4]` | 4, 3 |

- 노드 10, 11, 14 이상은 비어 있습니다. N이 2의 거듭제곱이 아니면 트리가 한쪽으로 기울어서 빈 칸이 생기고, 그래서 배열을 넉넉히 잡습니다.
- 모든 노드를 한 번씩 방문하므로 생성은 O(N)입니다. 재귀 깊이는 트리 높이인 O(log N)이라 호출 스택은 문제가 되지 않습니다.
- 합 배열은 `Float64Array`로 잡습니다. 합이 2^31을 넘어도 2^53 미만이면 정확하고, 0으로 초기화되며 `Infinity`도 담을 수 있습니다. `Int32Array`는 합이 범위를 넘으면 값이 감깁니다(자세히는 05편).
- 원소 합이 2^53 − 1을 넘을 수 있으면 BigInt를 써야 하는데, 이때는 `t`를 일반 배열(`new Array(4 * N).fill(0n)`)로 만들고 `ID`도 `0n`으로 둡니다(자세히는 02편).

**흔한 실수:** 트리 크기를 `2 * N`으로 잡고 재귀형을 쓰는 것입니다. N이 2의 거듭제곱이 아니면 번호가 배열 밖으로 나갑니다. 재귀형은 `4 * N`, 비재귀형은 `2 * N`입니다(아래 "비재귀 Segment Tree" 절).

## 구간 합

구간 `[ql, qr]`의 합은 트리를 위에서 내려가며 세 경우로 나눠 구합니다.

| 노드 구간과 질의 구간의 관계 | 처리 |
|------------------------------|------|
| 겹치지 않는다 | 항등원 반환 |
| 노드 구간이 질의 구간에 완전히 들어간다 | 저장된 값 반환 |
| 일부만 겹친다 | 두 자식에게 내려가 결과를 합친다 |

```js
function query(v, l, r, ql, qr) {
  if (qr < l || r < ql) return ID
  if (ql <= l && r <= qr) return t[v]
  const m = (l + r) >> 1
  const left = query(2 * v, l, m, ql, qr)
  const right = query(2 * v + 1, m + 1, r, ql, qr)
  return merge(left, right)
}
query(1, 0, a.length - 1, 1, 4) // 13 (5 + 1 + 4 + 3)
```

`query(1, 0, 5, 1, 4)`를 따라가면 다음과 같습니다.

| 방문 | 구간 | 판정 | 반환 |
|------|------|------|------|
| 1 | `[0,5]` | 일부 겹침 | 아래 합 |
| 2 | `[0,2]` | 일부 겹침 | 아래 합 |
| 4 | `[0,1]` | 일부 겹침 | 아래 합 |
| 8 | `[0,0]` | 겹치지 않음 | 0 |
| 9 | `[1,1]` | 완전히 포함 | 5 |
| 5 | `[2,2]` | 완전히 포함 | 1 |
| 3 | `[3,5]` | 일부 겹침 | 아래 합 |
| 6 | `[3,4]` | 완전히 포함 | 7 |
| 7 | `[5,5]` | 겹치지 않음 | 0 |

최종 값은 5 + 1 + 7 = 13입니다. 질의 구간 `[1,4]`가 노드 9, 5, 6의 세 구간으로 쪼개졌습니다.

- 구간은 양 끝을 포함하는 닫힌 구간 `[ql, qr]`입니다. 이 문서의 재귀형은 모두 닫힌 구간을 씁니다(반열린 구간은 아래 "비재귀 Segment Tree" 절).
- 한 질의는 O(log N)입니다(이유는 아래 "Range Query" 절).

백준식 입력으로 감싼 전체 흐름입니다. 첫 줄은 N과 질의 수 Q, 둘째 줄은 배열이고, 이어지는 줄은 `1 i x`(i번째를 x로 바꾼다) 또는 `2 l r`(l부터 r까지의 합)입니다. 번호는 1부터 시작합니다.

```js
const fs = require('fs')
const tk = fs.readFileSync(0, 'utf8').split(/\s+/)
let p = 0
const n = +tk[p++], q = +tk[p++]
a = Array.from({ length: n }, () => +tk[p++])
t = new Float64Array(4 * n)
build(1, 0, n - 1)
const out = []
for (let k = 0; k < q; k++) {
  const c = +tk[p++], x = +tk[p++], y = +tk[p++]
  if (c === 1) update(1, 0, n - 1, x - 1, y)
  else out.push(query(1, 0, n - 1, x - 1, y - 1))
}
console.log(out.join('\n'))
```

입력을 한 번에 읽고 출력을 모아서 한 번에 내는 이유는 08편에서 다룹니다. `update`는 아래 "Point Update" 절에 있습니다.

**흔한 실수:**

- 번호가 1부터인 문제의 입력을 0부터 쓰는 배열에 그대로 넣는 것입니다. `x - 1`로 바꿔 넣습니다.
- 겹치지 않을 때 `0`이 아니라 `undefined`나 `null`을 반환하는 것입니다. 합이 `NaN`이 됩니다.

## 구간 최소

구간 최솟값을 구하려면 `merge`와 `ID`만 바꾸면 됩니다. 나머지 코드(`build`, `query`, `update`)는 그대로입니다.

| 질의 | `merge` | `ID` |
|------|---------|------|
| 합 | `x + y` | `0` |
| 최소 | `Math.min(x, y)` | `Infinity` |
| 최대 | `Math.max(x, y)` | `-Infinity` |
| 최대공약수 | `gcd(x, y)` | `0` |
| XOR | `x ^ y` | `0` |

```js
const merge = (x, y) => Math.min(x, y)
const ID = Infinity
// a = [2, 5, 1, 4, 3, 6]
// query(1, 0, 5, 1, 4) → 1
// query(1, 0, 5, 3, 5) → 3
```

- 항등원은 어떤 값과 합쳐도 그 값이 되는 값입니다. 최솟값에서는 모든 값보다 큰 `Infinity`가 그 역할을 합니다. 겹치지 않는 노드가 결과에 영향을 주지 않으려면 이 값이어야 합니다.
- `Float64Array`는 `Infinity`를 담을 수 있습니다. `Int32Array`에 담으려면 `Infinity` 대신 입력 최댓값보다 큰 정수(예: 2147483647)를 항등원으로 씁니다.
- 질의와 갱신의 시간은 합 트리와 같은 O(log N)입니다.
- XOR은 `^`가 32비트 정수로 변환하므로 값이 2^31 이상이면 맞지 않습니다(자세히는 24편).

최솟값의 위치도 필요하면 값 대신 인덱스를 저장합니다.

```js
const better = (i, j) => (a[i] <= a[j] ? i : j)
// 노드에 인덱스를 저장하고 merge = better
// 리프에는 t[v] = l, 갱신은 a[i]를 바꾼 뒤 update(..., i)
```

**흔한 실수:** 최소 트리에서 겹치지 않을 때 `0`을 반환하는 것입니다. 모든 값이 양수인데 구간 밖의 `0`이 결과로 섞여 최솟값이 0이 됩니다.

## 구간 최대

최댓값은 `merge = Math.max`, `ID = -Infinity`로 바꾸면 됩니다.

```js
const merge = (x, y) => Math.max(x, y)
const ID = -Infinity
// a = [2, 5, 1, 4, 3, 6]
// query(1, 0, 5, 0, 3) → 5
// query(1, 0, 5, 4, 5) → 6
```

- 값에 음수가 있을 수 있으므로 항등원은 `0`이 아니라 `-Infinity`입니다.
- 최대와 최소가 모두 필요하면 트리 두 개를 만들거나, 노드에 두 값을 한 쌍으로 저장합니다(쌍으로 저장하면 `merge`가 쌍을 받아 쌍을 돌려줍니다).
- 최솟값을 구하는 문제를 `-1`을 곱한 값의 최댓값으로 바꿔 푸는 방법도 있지만, `merge`만 바꾸는 쪽이 간단하고 실수가 적습니다.

세 질의(합, 최소, 최대)에 공통인 점은 합치는 연산이 결합법칙을 따르고 항등원이 있다는 것입니다. 이 두 조건이 맞는 연산이면 같은 코드로 풀 수 있습니다.

## Point Update

점 갱신은 리프 하나의 값을 바꾸고, 그 리프에서 루트까지 올라가며 조상 노드를 다시 계산합니다. 갱신할 인덱스 `i`가 속한 자식 쪽으로만 내려가므로 경로가 하나입니다.

```js
function update(v, l, r, i, x) {
  if (l === r) { t[v] = x; return }
  const m = (l + r) >> 1
  if (i <= m) update(2 * v, l, m, i, x)
  else update(2 * v + 1, m + 1, r, i, x)
  t[v] = merge(t[2 * v], t[2 * v + 1])
}
update(1, 0, 5, 2, 9)   // a[2]를 1에서 9로 (합 트리)
```

합 트리에서 `a[2] = 9`로 바꾸면 노드 1, 2, 5만 바뀝니다.

| 노드 | 구간 | 이전 | 이후 |
|------|------|------|------|
| 5 | `[2,2]` | 1 | 9 |
| 2 | `[0,2]` | 8 | 16 |
| 1 | `[0,5]` | 21 | 29 |

- 한 번의 갱신은 높이만큼의 노드를 고치므로 O(log N)입니다.
- 이 방식은 부모를 자식 두 개로부터 다시 계산하므로 합, 최소, 최대 어느 트리에도 맞습니다. 합 트리에서 값을 더하는 갱신(`a[i] += d`)이면 지나는 노드마다 `t[v] += d`로 쓸 수도 있지만 최소·최대에는 쓸 수 없습니다.
- 갱신 후 `a[i]`도 함께 바꿔 두어야 나중에 `a`를 쓰는 코드(위치 저장 등)와 어긋나지 않습니다.
- 구간의 값을 한꺼번에 바꾸는 구간 갱신을 점 갱신 반복으로 하면 O(N log N)입니다. 63편의 Lazy Propagation으로 O(log N)에 처리합니다.

**흔한 실수:** 값을 더하는 문제에서 대입 코드를 쓰는 것입니다. "i번째에 x를 더한다"이면 `update(..., a[i] + x)`로 새 값을 계산해 넘기고 `a[i]`도 함께 고칩니다.

## Range Query

구간 질의의 원리는 질의 구간 `[ql, qr]`을 서로 겹치지 않는 O(log N)개의 노드 구간으로 쪼개고, 그 노드 값을 순서대로 합치는 것입니다. 앞의 예에서 `[1,4]`는 노드 9, 5, 6으로 쪼개졌습니다.

- 일부만 겹치는 노드에서만 자식으로 내려갑니다. 한 층에서 일부만 겹치는 노드는 최대 2개(질의 구간의 양 끝이 걸치는 노드)이므로 한 층에서 방문하는 노드는 최대 4개입니다. 층이 O(log N)개라서 한 질의는 O(log N)입니다.
- 쪼개진 노드를 왼쪽에서 오른쪽 순서로 합칩니다(`merge(left, right)`). 그래서 교환법칙이 성립하지 않는 연산(구간 행렬 곱, 문자열 이어 붙이기)도 위 재귀형으로 풀 수 있습니다. 결합법칙만 있으면 됩니다.
- 노드에 저장하는 값은 요약이 합쳐질 수 있는 형태여야 합니다. 평균은 합치기 어려우므로 합과 개수를 같이 저장하고 질의 끝에서 나눕니다. 부분 배열의 최대 합은 노드마다 구간 합, 접두사 최대, 접미사 최대, 구간 최대 합 네 값을 저장해서 합칩니다.
- `ql > qr`인 질의는 호출 전에 걸러냅니다. 구간이 비어 있는 입력이라 의도한 질의인지 확인해야 합니다.

| 항목 | 값 |
|------|----|
| 질의 | O(log N) |
| 점 갱신 | O(log N) |
| 생성 | O(N) |
| 공간 | O(N) |

질의와 갱신 Q개를 처리하는 전체 시간은 O(N + Q log N)입니다. N과 Q가 모두 10^5 수준이면 연산이 약 170만 번이라 여유가 있습니다(자세히는 14편).

**흔한 실수:** 질의 구간 경계를 `ql < l`처럼 등호를 빼고 쓰는 것입니다. 완전히 포함되는 판정은 `ql <= l && r <= qr`이고 겹치지 않는 판정은 `qr < l || r < ql`입니다.

## 좌표 압축 + Segment Tree

인덱스가 될 값의 범위가 너무 크거나(10^9) 정수가 아닐 때, 값을 크기 순위로 바꿔 순위 위에 세그먼트 트리를 만듭니다. 사용하는 값만 순위를 매기므로 트리 크기가 서로 다른 값의 개수 M으로 줄어듭니다(좌표 압축은 54편).

- 질의를 미리 모두 알 수 있는 오프라인 문제에 씁니다. 값을 모으고, 정렬하고, 중복을 없애 순위 표를 만든 뒤 트리를 만듭니다.
- 노드에는 보통 "그 순위 범위에 값이 몇 개 들어 있는지"를 저장합니다. 값 하나를 넣으면 해당 순위의 개수에 1을 더합니다.

```js
const vals = [100, 5, 100, 70]
const sorted = [...new Set(vals)].sort((x, y) => x - y)
const rank = new Map(sorted.map((v, i) => [v, i]))
// 5 → 0, 70 → 1, 100 → 2 (M = 3)
const M = sorted.length
a = new Array(M).fill(0)         // 순위별 개수
t = new Float64Array(4 * M)
for (const v of vals) {
  const r = rank.get(v)
  update(1, 0, M - 1, r, ++a[r]) // 개수를 1 늘린다
}
query(1, 0, M - 1, 0, rank.get(70)) // 2 (70 이하의 개수)
```

- 위 코드는 합 트리(`merge = x + y`, `ID = 0`)를 쓴 것입니다.
- "x보다 작은 값의 개수"는 순위 `0`부터 `rank(x) - 1`까지의 합, "x 이하의 개수"는 `rank(x)`까지의 합입니다.
- 압축 후 순위는 서로 다른 값마다 하나이므로 같은 값이 여러 번 나오면 `a[r]`가 그 개수를 셉니다.
- 값을 지우는 것은 `--a[r]`로 갱신하면 됩니다.
- 질의에 들어오는 값이 압축표에 없을 수 있으면 `Map.get`이 `undefined`를 돌려주므로, 정렬된 표에서 이분 탐색(28편)으로 위치를 찾아야 합니다.
- 질의를 미리 알 수 없는 온라인 문제에서는 노드를 필요할 때 만드는 동적 세그먼트 트리를 쓰는데, 이 문서의 범위를 넘으므로 개요만 알아 두면 됩니다.

**흔한 실수:** 압축 순위를 0부터 만들고 트리는 1부터 쓰는 것처럼 기준을 섞는 것입니다. 이 문서는 순위와 트리 인덱스를 모두 0부터 씁니다. 문제의 번호를 쓰는 곳에서만 한 번 변환합니다.

## 비재귀 Segment Tree

비재귀(bottom-up) 세그먼트 트리는 리프를 배열의 뒤쪽 `[size, 2*size)`에 두고, 노드 `i`의 부모를 `i >> 1`로 계산해 반복문만으로 올라갑니다. 재귀 호출이 없어서 상수가 작고 코드가 짧으며, 배열 크기가 `2 * size`면 충분합니다. 리프 개수가 2의 거듭제곱이 아니어도 질의가 맞게 동작합니다.

```js
const size = 6
const t2 = new Float64Array(2 * size)
const base = [2, 5, 1, 4, 3, 6]
for (let i = 0; i < size; i++) t2[size + i] = base[i]
for (let i = size - 1; i >= 1; i--) {
  t2[i] = merge(t2[2 * i], t2[2 * i + 1])   // 아래에서 위로
}
```

```js
function query2(l, r) {              // 반열린 구간 [l, r)
  let res = ID
  for (l += size, r += size; l < r; l >>= 1, r >>= 1) {
    if (l & 1) res = merge(res, t2[l++])
    if (r & 1) res = merge(res, t2[--r])
  }
  return res
}
function update2(i, x) {
  i += size
  t2[i] = x
  for (i >>= 1; i >= 1; i >>= 1) {
    t2[i] = merge(t2[2 * i], t2[2 * i + 1])
  }
}
```

- 질의는 반열린 구간 `[l, r)`입니다. `l`이 오른쪽 자식이면(홀수) 그 노드는 질의에 들어가므로 합치고 오른쪽 이웃으로 넘어갑니다. `r`이 오른쪽 자식이면 바로 왼쪽 노드를 합치고 한 칸 내립니다. 그다음 두 인덱스가 부모로 올라갑니다.
- 닫힌 구간 `[ql, qr]`을 받는 문제는 `query2(ql, qr + 1)`로 호출합니다.
- 시간은 질의와 갱신 모두 O(log N), 공간은 `2 * size`입니다.
- `merge`가 교환법칙을 만족해야 위 코드가 맞습니다(합, 최소, 최대, 최대공약수, XOR). 교환법칙이 없으면 왼쪽에서 모은 값과 오른쪽에서 모은 값을 따로 두고, 왼쪽은 `resL = merge(resL, t2[l++])`, 오른쪽은 `resR = merge(t2[--r], resR)`로 쌓은 뒤 마지막에 `merge(resL, resR)`로 합쳐야 합니다.

재귀형과 비교하면 다음과 같습니다.

| 항목 | 재귀(top-down) | 비재귀(bottom-up) |
|------|----------------|-------------------|
| 배열 크기 | `4N` | `2N` |
| 구간 표기 | 닫힌 `[ql, qr]` | 반열린 `[l, r)` |
| 속도 | 호출 비용이 든다 | 반복문이라 빠르다 |
| 구간 갱신(Lazy) | 쉽다 | 구현이 까다롭다 |
| 트리 위 이분 탐색 | 쉽다 | 2의 거듭제곱 크기에서 쉽다 |

점 갱신과 구간 질의만 필요하면 비재귀형이 간결합니다. 구간 갱신이 나올 가능성이 있으면 재귀형을 익혀 둡니다.

**흔한 실수:** 반열린 구간과 닫힌 구간을 섞는 것입니다. 닫힌 구간을 그대로 넘기면 끝 원소가 빠집니다.

## Segment Tree 위 이분 탐색 (K번째 원소)

개수를 저장한 트리에서는 값 구간을 이분 탐색하지 않고 트리를 위에서 내려가며 K번째 값을 O(log N)에 찾을 수 있습니다. 질의마다 이분 탐색(28편)과 구간 합을 함께 쓰면 O(log² N)이지만, 트리 안에서 한 번에 내려가면 O(log N)입니다.

내려가는 규칙은 하나입니다. 현재 노드의 왼쪽 자식에 든 개수가 K 이상이면 왼쪽으로 가고, 아니면 K에서 그 개수를 빼고 오른쪽으로 갑니다. 리프에 닿으면 그 순위가 답입니다.

```js
function kth(k) {                // 1부터 세는 k번째로 작은 값
  let v = 1, l = 0, r = M - 1
  while (l < r) {
    const m = (l + r) >> 1
    if (t[2 * v] >= k) { v = 2 * v; r = m }
    else { k -= t[2 * v]; v = 2 * v + 1; l = m + 1 }
  }
  return sorted[l]               // 순위를 원래 값으로
}
```

앞 절의 개수 트리(`5`가 1개, `70`이 1개, `100`이 2개)에서 `kth`를 호출한 결과입니다.

| k | 처리 | 결과 |
|---|------|------|
| 1 | 루트의 왼쪽 합 2는 1 이상이라 왼쪽, 다음 왼쪽 합 1도 1 이상이라 왼쪽 | 5 |
| 2 | 왼쪽 합 2는 2 이상이라 왼쪽, 다음 왼쪽 합 1은 2 미만이라 `k = 1`로 오른쪽 | 70 |
| 3 | 루트의 왼쪽 합 2는 3 미만이라 `k = 1`로 오른쪽 | 100 |
| 4 | 루트의 왼쪽 합 2는 4 미만이라 `k = 2`로 오른쪽 | 100 |

- 전제는 `1 <= k <= 전체 개수`입니다. 범위를 벗어나는 k는 미리 걸러냅니다.
- 같은 방식으로 "접두사 합이 처음 X 이상이 되는 위치"를 찾을 수 있습니다. 리프 값이 모두 0 이상이어야 접두사 합이 늘기만 해서 맞습니다.
- 값을 넣고 빼는 `update`와 함께 쓰면 동적으로 변하는 집합의 K번째 값(중앙값 유지 포함)을 질의마다 O(log N)에 구합니다.
- 비재귀 트리에서도 리프 수가 2의 거듭제곱이면 인덱스를 `v = 2 * v`, `v = 2 * v + 1`로 내려가는 같은 방식이 됩니다.

**흔한 실수:** 왼쪽으로 내려갈 때도 `k`를 빼는 것입니다. `k`에서 빼는 것은 오른쪽으로 갈 때뿐입니다.

## 핵심 정리

- 세그먼트 트리는 구간을 이분해 각 노드에 구간 요약 값을 저장하고, 질의와 점 갱신을 모두 O(log N), 생성을 O(N)에 처리합니다. 재귀형은 노드 번호가 `2v`, `2v + 1`이고 배열 크기는 `4N`입니다.
- 합, 최소, 최대는 `merge`와 항등원(`0`, `Infinity`, `-Infinity`)만 바꾸면 같은 코드입니다. 결합법칙과 항등원이 있는 연산이면 쓸 수 있습니다.
- 질의는 구간을 O(log N)개 노드로 쪼개 합치고, 점 갱신은 리프에서 루트까지의 경로를 다시 계산합니다.
- 값의 범위가 크면 좌표 압축으로 순위를 만들고 순위별 개수를 저장한 트리를 씁니다. 질의를 미리 알 수 있는 오프라인에서 쓰는 방법입니다.
- 비재귀형은 리프를 `[size, 2*size)`에 두고 반열린 구간으로 반복문만 써서 빠르며, 교환법칙이 성립하는 연산에서 위 코드가 그대로 맞습니다.
- 개수 트리에서는 왼쪽 합과 K를 비교하며 내려가 K번째 원소를 O(log N)에 찾습니다.
