## 몫과 나머지

정수 a를 양의 정수 b로 나누면 `a = b × 몫 + 나머지`가 성립합니다. JavaScript에서 `/`는 소수점까지 계산하는 나눗셈이므로 정수 몫은 따로 구합니다.

```js
const a = 17
const b = 5
const q = Math.floor(a / b) // 3 (몫)
const r = a % b             // 2 (나머지)
console.log(b * q + r)      // 17
```

- 몫과 나머지는 `Math.floor(a / b)`와 `a % b`로 구합니다. `a`와 `b`가 0 이상이면 이 둘로 충분합니다.
- `%`는 나머지(remainder) 연산자이고 결과의 부호가 나뉘는 수(a)의 부호를 따릅니다. 수학의 mod와 음수에서 다릅니다(아래 "음수 나머지 보정").
- `a % 0`은 `NaN`이고 BigInt의 `5n % 0n`은 RangeError입니다.
- `a`가 음수이면 `Math.floor`는 음의 무한대 쪽으로 내려서 `Math.floor(-7 / 2)`가 `-4`입니다. 0 쪽으로 자르는 몫이 필요하면 `Math.trunc(-7 / 2)`(`-3`)를 씁니다(자세히는 02편).

| a | b | `Math.floor(a / b)` | `Math.trunc(a / b)` | `a % b` |
|---|---|---------------------|---------------------|---------|
| 7 | 2 | 3 | 3 | 1 |
| -7 | 2 | -4 | -3 | -1 |
| 7 | -2 | -4 | -3 | 1 |

- 몫과 나머지를 함께 쓰는 곳은 시간 변환(초를 분과 초로), 자리 분해, 2차원 격자의 인덱스 변환입니다.

```js
const sec = 3725
const h = Math.floor(sec / 3600)       // 1
const m = Math.floor((sec % 3600) / 60) // 2
const s = sec % 60                      // 5
```

**흔한 실수:** 정수 나눗셈을 `/`만으로 하는 것입니다. `7 / 2`는 `3.5`이고, 정수 몫이 필요한 자리에서 이 값을 인덱스로 쓰면 `undefined`를 읽습니다.

## 절댓값

절댓값은 0에서의 거리로, 부호를 없앤 값입니다. `Math.abs`를 씁니다.

```js
Math.abs(-5)   // 5
Math.abs(5)    // 5
Math.abs(-0)   // 0
Math.abs('-3') // 3 (문자열은 숫자로 변환됨)
Math.abs()     // NaN
Math.abs(null) // 0
```

- 두 수의 차이(거리)는 `Math.abs(a - b)`입니다. 맨해튼 거리는 `Math.abs(x1 - x2) + Math.abs(y1 - y2)`입니다.
- 인수를 숫자로 바꿔 계산하므로 변환할 수 없는 값은 `NaN`입니다.
- `Math.abs`는 BigInt를 받지 못해서 `Math.abs(-5n)`은 TypeError입니다. BigInt는 직접 비교합니다.

```js
const absBig = (x) => (x < 0n ? -x : x)
absBig(-5n) // 5n
```

**흔한 실수:** `Math.abs(a - b)`를 `Math.abs(a) - Math.abs(b)`로 쓰는 것입니다. `a = 3`, `b = -4`이면 앞은 `7`, 뒤는 `-1`입니다. 부호만 필요하면 `Math.sign(x)`(`-1`, `0`, `1`)가 있습니다.

## 올림, 내림, 반올림

네 함수는 소수를 정수로 바꾸는 방향이 다릅니다.

| 함수 | 방향 | 2.5 | -2.5 | 2.4 | -2.4 |
|------|------|-----|------|-----|------|
| `Math.floor` | 음의 무한대(내림) | 2 | -3 | 2 | -3 |
| `Math.ceil` | 양의 무한대(올림) | 3 | -2 | 3 | -2 |
| `Math.trunc` | 0 쪽(소수부 버림) | 2 | -2 | 2 | -2 |
| `Math.round` | 가장 가까운 정수 | 3 | -2 | 2 | -2 |

- `Math.round`는 소수부가 정확히 0.5이면 양의 무한대 쪽으로 올립니다. `Math.round(2.5)`는 `3`이고 `Math.round(-2.5)`는 `-2`입니다. 0.5를 0에서 먼 쪽으로 올리는 언어와 음수에서 다릅니다.
- 음수를 반올림하면 `-0`이 나올 수 있습니다. `Math.round(-0.4)`는 `-0`입니다. 출력할 때 `0`으로 보이지만(`console.log(-0)`은 `-0`으로 보임) 비교는 `0 === -0`이 참입니다.

### 정수 올림 나눗셈

`ceil(a / b)`가 필요하면 `Math.ceil(a / b)`를 쓰거나, 부동소수점을 피해 정수만으로 계산합니다.

```js
Math.ceil(7 / 2)           // 4
Math.floor((7 + 2 - 1) / 2) // 4 ((a + b - 1) / b의 내림)
```

- 작은 정수에서는 두 식이 같습니다. `a`, `b`가 양의 정수이고 몫이 안전한 범위일 때 둘 다 맞습니다.
- 올림 나눗셈은 "물건 a개를 b개씩 담을 때 필요한 상자 수", "페이지 수 계산"에 쓰입니다.
- `a`가 0이면 `Math.ceil(0 / 5)`는 `0`입니다.

### 소수점 아래 반올림

특정 자리에서 반올림하려면 10의 거듭제곱을 곱해 `Math.round`한 뒤 나눕니다.

```js
const round2 = (x) => Math.round(x * 100) / 100
round2(3.14159) // 3.14
round2(2.675)   // 2.68
;(2.675).toFixed(2) // '2.67' (문자열, 다른 결과)
```

- 소수는 2진수로 정확히 표현되지 않습니다. `2.675`의 실제 저장값은 2.67499999…로 2.675보다 약간 작습니다. 곱하기를 거치는 `round2`와 `toFixed`는 이 오차를 다르게 처리해서 결과가 갈릴 수 있습니다(자세히는 02편).
- 돈이나 비율처럼 정확해야 하는 값은 소수 대신 정수(원, 퍼센트×100)로 바꿔 계산하고, 마지막에만 나눕니다.
- `toFixed`는 문자열을 돌려줘서 이후 계산에는 `Number()`로 되돌립니다.

**흔한 실수:** 음수에서 `Math.round`가 0에서 먼 쪽으로 올림하는 것으로 가정하는 것입니다. `Math.round(-1.5)`는 `-1`입니다. 또 `Math.floor(x)`를 소수부 버림으로 쓰면 음수에서 값이 하나 작아집니다.

## 최소값, 최대값

`Math.min`과 `Math.max`는 인수 중 가장 작은 값과 큰 값을 돌려줍니다.

```js
Math.max(3, 9, 4)    // 9
Math.min(3, 9, 4)    // 3
Math.max(...[3, 9, 4]) // 9 (배열은 스프레드로 펼침)
```

- 인수가 하나도 없으면 `Math.max()`는 `-Infinity`, `Math.min()`은 `Infinity`입니다. 빈 배열에 `Math.max(...[])`를 쓰면 `-Infinity`입니다.
- 인수 중 `NaN`이거나 `NaN`으로 변환되는 값이 있으면 결과가 `NaN`입니다. `Math.max(1, NaN)`은 `NaN`입니다.
- 배열 전체를 인수로 펼치므로 원소가 아주 많으면 호출이 실패할 수 있습니다. 큰 배열에는 반복문이나 `reduce`를 씁니다(자세히는 86편).

```js
const arr = [3, 9, 4]
let best = -Infinity       // 어떤 값보다도 작은 초기값
for (const v of arr) if (v > best) best = v
const best2 = arr.reduce(
  (a, b) => Math.max(a, b), -Infinity,
)
// 둘 다 9
```

- 초기값은 입력 범위를 모두 덮는 값으로 정합니다. 최댓값 찾기는 `-Infinity`, 최솟값 찾기는 `Infinity`입니다. 정수만 다루면 `Number.MIN_SAFE_INTEGER`, `Number.MAX_SAFE_INTEGER`도 쓸 수 있지만, 입력이 그 범위를 넘으면 틀립니다.
- 최댓값의 위치가 필요하면 값을 먼저 구하고 `indexOf`로 찾거나, 반복문에서 인덱스를 함께 갱신합니다. 같은 값이 여럿이면 `indexOf`는 처음 위치를 줍니다.
- 문자열 인수도 숫자로 바뀌어 `Math.max('3', 2)`는 `3`입니다. 문자열 배열에서는 비교가 사전순이 아니라 수치 기준으로 일어나는 점을 기억합니다.

**흔한 실수:** 초기값을 `0`으로 두는 것입니다. 모든 값이 음수이면 최댓값이 0이 되어 틀립니다.

## 팩토리얼

n! 은 1부터 n까지의 곱이고, 0! 은 1로 정의합니다. 반복문으로 구현합니다.

```js
function factorial(n) {
  let result = 1
  for (let i = 2; i <= n; i++) result *= i
  return result
}
factorial(5)  // 120
factorial(0)  // 1
```

- 시간은 O(n)입니다. 재귀로 쓰는 방법은 22편에서 다룹니다.
- 값이 매우 빠르게 커집니다. Number는 정확한 정수를 2^53 − 1(9007199254740991)까지만 표현해서 20!(2432902008176640000)은 그 범위를 넘습니다.

| n | n! | 상태 |
|---|----|------|
| 18 | 6402373705728000 | 안전한 정수 범위 안 |
| 19 이상 | 121645100408832000부터 | 안전 범위를 넘어 정확성 미보장 |
| 170 | 약 7.26e306 | Number로 표현 가능 |
| 171 이상 | `Infinity` | 표현 범위 초과 |

- 18!까지가 안전 정수 범위 안이고 19!부터는 정확성이 보장되지 않습니다. 팩토리얼은 2의 인수를 많이 가져서 22!까지는 우연히 정확히 표현되지만(Node.js 24에서 확인), 23!부터는 BigInt와 값이 달라집니다. 정확한 큰 값이 필요하면 BigInt로 계산합니다.

```js
function factorialBig(n) {
  let result = 1n
  for (let i = 2n; i <= BigInt(n); i++) result *= i
  return result
}
factorialBig(21).toString() // '51090942171709440000'
```

- BigInt 결과는 `toString()`이나 템플릿 문자열로 출력합니다(Number와 섞어 쓰면 TypeError, 자세히는 02편).
- 나머지를 구하는 문제는 팩토리얼 자체를 만들지 않고, 곱할 때마다 나머지를 취합니다(자세히는 57편).

**흔한 실수:** 19! 이상을 Number로 계산하고 정확한 값처럼 쓰는 것입니다. 에러가 나지 않고, 23!부터는 마지막 자리가 틀린 값이 나옵니다.

## 거듭제곱

거듭제곱은 `**` 연산자(또는 `Math.pow`)로 구합니다.

```js
2 ** 10        // 1024
Math.pow(2, 10) // 1024
2 ** 0.5       // 1.4142135623730951 (정수 아닌 지수도 가능)
2 ** -1        // 0.5
0 ** 0         // 1
```

- `**`는 오른쪽 결합입니다. `2 ** 3 ** 2`는 `2 ** 9`로 512입니다.
- `-2 ** 2`처럼 단항 마이너스를 바로 붙이면 SyntaxError입니다. `(-2) ** 2`처럼 괄호를 씁니다.
- Number의 결과가 2^53을 넘으면 정확하지 않습니다. `3 ** 40`은 `12157665459056929000`이지만 실제 값은 `12157665459056928801`입니다. 정확한 값은 BigInt `3n ** 40n`으로 구합니다. BigInt의 지수는 0 이상이어야 하고, 음수이면 RangeError입니다.
- 지수가 정수일 때만 정확한 정수 거듭제곱을 기대합니다. 제곱근 `x ** 0.5`는 `Math.sqrt(x)`로 씁니다.

### 빠른 거듭제곱

지수 e가 크면 e번 곱하는 O(e) 대신, 지수를 절반씩 줄이며 곱하는 O(log e) 방법을 씁니다. `b^e = (b²)^(e/2)`이고 e가 홀수이면 결과에 b를 한 번 더 곱합니다.

```js
function power(base, exp) {
  let result = 1
  while (exp > 0) {
    if (exp % 2 === 1) result *= base  // 홀수면 하나 더 곱함
    base *= base
    exp = Math.floor(exp / 2)
  }
  return result
}
power(3, 13) // 1594323
```

- `3^13`의 지수 13은 이진수로 1101이므로 `3^1 × 3^4 × 3^8`을 곱한 것과 같습니다. 곱셈 횟수는 지수의 이진 자릿수에 비례합니다.
- 홀짝 판별에 `exp & 1`, 절반 나누기에 `exp >>= 1`을 쓰면 `exp`가 2^31 이상일 때 32비트 변환으로 틀립니다(자세히는 24편). 위처럼 `%`와 `Math.floor`가 안전합니다.
- 결과가 크면 나머지를 취하는 빠른 거듭제곱을 씁니다. 곱셈이 2^53을 넘으면 BigInt가 필요합니다(자세히는 57편).

**흔한 실수:** 큰 정수 거듭제곱을 `**`로 계산하고 정확하다고 믿는 것입니다. `3 ** 40`처럼 결과가 2^53을 넘으면 에러 없이 어긋난 값이 나옵니다.

## 진법 변환

진법 변환은 같은 수를 다른 기수(2진수, 8진수, 16진수 등)의 문자열로 바꾸는 일입니다. 내장 함수로 2에서 36진법까지 변환할 수 있습니다.

```js
const b2 = (255).toString(2)    // '11111111' (정수 -> 문자열)
const b16 = (255).toString(16)  // 'ff' (소문자)
const b36 = (255).toString(36)  // '73'
const n2 = parseInt('11111111', 2) // 255 (문자열 -> 정수)
const n16 = parseInt('ff', 16)     // 255
const n36 = parseInt('zz', 36)     // 1295
```

- `toString(radix)`의 `radix`는 2부터 36입니다. 범위 밖이면 RangeError입니다. 10을 넘는 자릿수는 소문자 `a`–`z`입니다. 대문자가 필요하면 `.toUpperCase()`를 붙입니다.
- 음수는 부호를 앞에 붙입니다. `(-255).toString(2)`는 `'-11111111'`이고 2의 보수 표현이 아닙니다.
- `parseInt(문자열, radix)`는 유효하지 않은 자리에서 파싱을 멈춥니다. `parseInt('102', 2)`는 `'10'`까지만 읽어 `2`를 돌려줍니다(`'2'`는 이진수에 없는 자리). 첫 글자부터 유효하지 않으면 `NaN`입니다.
- `parseInt`에는 반드시 `radix`를 줍니다. 생략하면 `0x`로 시작하는 문자열을 16진수로 읽습니다.
- 2진 문자열을 고정 길이로 맞출 때는 `padStart`를 씁니다. `(5).toString(2).padStart(8, '0')`은 `'00000101'`입니다.

직접 구현은 나머지를 모으고 몫으로 내려가는 방식입니다. 가장 낮은 자리부터 나오므로 뒤집어 붙입니다.

```js
const DIGITS = '0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ'
function toBase(n, base) {      // n >= 0인 정수
  if (n === 0) return '0'
  let s = ''
  while (n > 0) {
    s = DIGITS[n % base] + s    // 나머지가 한 자리
    n = Math.floor(n / base)
  }
  return s
}
toBase(255, 16) // 'FF'
```

반대 방향은 자리를 하나씩 읽으며 `기수`를 곱해 올립니다.

```js
function fromBase(str, base) {
  let n = 0
  for (const ch of str) n = n * base + parseInt(ch, 36)
  return n
}
fromBase('FF', 16) // 255
fromBase('1010', 2) // 10
```

- 255를 16으로 나누면 몫 15, 나머지 15이고, 15를 다시 나누면 몫 0, 나머지 15라서 `FF`입니다.
- 2^53 이상의 큰 수는 Number로 변환하면 부정확합니다. BigInt에도 `toString(radix)`가 있고, 문자열에서 만들 때는 접두사를 쓸 수 있습니다.

```js
const x = BigInt('0b1010')   // 10n
const y = BigInt('0xff')     // 255n
const z = (2n ** 64n).toString(16)
// '10000000000000000'
```

- `Number('0b11')`처럼 접두사가 있는 문자열은 `Number()`로도 읽히지만, 접두사가 없는 `Number('ff')`는 `NaN`입니다.

**흔한 실수:** 2^53을 넘는 긴 이진·16진 문자열을 `parseInt(s, 2)`로 읽는 것입니다. 에러 없이 정밀도를 잃은 값이 나옵니다. 이런 입력은 `BigInt`로 읽습니다.

## 자리수 계산

자연수의 자릿수 개수, 각 자리의 값, 자리의 합을 구하는 방법은 두 가지입니다. 문자열로 바꾸는 방법과 `% 10`, `/ 10` 연산으로 하는 방법입니다.

```js
const n = 12345
const len = String(n).length           // 5 (자릿수)
const digits = [...String(n)].map(Number)
// [1, 2, 3, 4, 5]
const sum = digits.reduce((a, c) => a + c, 0) // 15
```

- 문자열 방식은 짧고, 자리 단위로 뒤집거나 비교하기 쉽습니다. 음수는 `-` 부호가 길이에 들어가므로 `Math.abs` 뒤에 변환합니다.
- 연산 방식은 가장 낮은 자리 `n % 10`을 꺼내고 `Math.floor(n / 10)`으로 한 자리 줄입니다.

```js
function digitSum(n) {
  let sum = 0
  while (n > 0) {
    sum += n % 10          // 일의 자리
    n = Math.floor(n / 10) // 일의 자리를 버림
  }
  return sum
}
digitSum(12345) // 15
```

| 하고 싶은 일 | 식 |
|--------------|----|
| 일의 자리 | `n % 10` |
| 일의 자리 제거 | `Math.floor(n / 10)` |
| i번째 자리(0부터, 오른쪽에서) | `Math.floor(n / 10 ** i) % 10` |
| 자릿수 | 0이 될 때까지 10으로 나눈 횟수, 또는 `String(n).length` |
| 숫자 뒤집기 | `r = r * 10 + n % 10`을 반복 |

숫자를 뒤집는 반복은 다음과 같습니다.

```js
function reverseNumber(n) {
  let r = 0
  while (n > 0) {
    r = r * 10 + (n % 10)
    n = Math.floor(n / 10)
  }
  return r
}
reverseNumber(1200) // 21 (끝의 0이 사라짐)
reverseNumber(12345) // 54321
```

- 팰린드롬 수 판별은 뒤집은 값과 비교하거나, 문자열로 바꿔 뒤집은 것과 비교합니다.
- 자릿수를 `Math.floor(Math.log10(n)) + 1`로 구하는 방법도 있지만, 부동소수점 오차로 경계(10의 거듭제곱 근처)에서 틀릴 수 있어서 코딩테스트에서는 문자열 길이나 반복을 씁니다.
- 0은 `while (n > 0)` 반복을 한 번도 돌지 않으므로 자릿수 계산에서 0을 따로 처리합니다. 0의 자릿수는 `String(0).length`로 1입니다.
- 2^53을 넘는 수는 Number로 읽는 순간 자리가 바뀝니다. 입력이 매우 크면 문자열 그대로 자리별로 처리합니다.

**흔한 실수:** `n / 10`을 그대로 쓰는 것입니다. 정수 나눗셈이 아니라서 `12345 / 10`은 `1234.5`이고, `% 10`이 소수가 됩니다. 반드시 `Math.floor`로 감쌉니다.

## 음수 나머지 보정

`%`는 부호가 나뉘는 수를 따르므로 음수에서 음수 나머지가 나옵니다.

```js
-7 % 3     // -1 (수학의 mod는 2)
7 % -3     // 1
-6 % 3     // -0
```

- 나머지를 0에서 `m - 1` 사이 값으로 맞추려면 `m`을 더한 뒤 한 번 더 나눕니다.

```js
const mod = (a, m) => ((a % m) + m) % m
mod(-7, 3) // 2
mod(7, 3)  // 1
mod(-3, 3) // 0
```

- `a % m`은 `-(m - 1)`에서 `m - 1` 사이입니다. `m`을 더하면 0 이상 `2m - 1` 이하가 되고, 다시 `% m`으로 범위를 맞춥니다. `-6 % 3`이 `-0`이어도 이 보정을 거치면 `0`입니다.
- 쓰이는 곳은 환형(원형) 배열 인덱스, 시계 방향 이동, 요일·시간 계산, 해시 인덱스입니다.

```js
const n = 7                // 원형 배열 크기
let i = 0
i = (i - 1 + n) % n        // 6 (0에서 한 칸 뒤로)
i = mod(i - 10, n)         // 이동 거리가 클 때는 mod로 보정
```

- 이동 거리가 `n`보다 작을 때만 `(i + d + n) % n`으로 충분합니다. 거리가 `-n`보다 더 음수가 될 수 있으면 `mod`를 씁니다.
- 몫도 음수 나눗셈에서는 맞춰야 합니다. 나머지가 `mod`이면 몫은 `Math.floor(a / m)`이어야 `a = m × 몫 + 나머지`가 성립합니다.

```js
const divmod = (a, b) => [Math.floor(a / b), mod(a, b)]
divmod(-7, 2) // [-4, 1] (-7 = 2 * (-4) + 1)
```

**흔한 실수:** `(i - 1) % n`으로 한 칸 뒤로 이동하는 것입니다. `i`가 0이면 `-1`이 되어 인덱스 -1을 읽습니다. 괄호 안에서 `n`을 더하거나 `mod`를 씁니다.

## 등차, 등비수열의 합

규칙이 있는 수열의 합은 반복문 없이 공식으로 O(1)에 구합니다.

### 등차수열

이웃한 항의 차이가 일정한 수열입니다. 첫째 항 a, 공차 d, 항의 개수 n이면 다음과 같습니다.

$$
S = \frac{n(2a + (n-1)d)}{2}
$$

- `S`는 n개 항의 합, `a`는 첫째 항, `d`는 공차, `n`은 항의 개수입니다.
- 마지막 항은 `a + (n - 1) * d`이고 합은 (첫 항 + 끝 항) × 개수 / 2와 같습니다.
- 1부터 n까지의 합은 `a = 1`, `d = 1`인 특수한 경우로 `n(n + 1) / 2`입니다.

```js
const sumTo = (n) => (n * (n + 1)) / 2
sumTo(100) // 5050
const arith = (a, d, n) => (n * (2 * a + (n - 1) * d)) / 2
arith(3, 4, 5) // 55 (3 + 7 + 11 + 15 + 19)
```

- `n(n + 1)`은 연속한 두 정수의 곱이라 항상 짝수여서 2로 나눠 떨어집니다. 곱을 먼저 하고 나눠도 정수입니다.
- 곱이 `Number.MAX_SAFE_INTEGER`(2^53 − 1)를 넘으면 틀립니다. `n = 10^8`이면 `n(n + 1)`이 약 10^16이라 안전 범위를 넘어 정확하지 않을 수 있습니다. 이 경우 BigInt를 씁니다.

```js
const N = 10 ** 9
const total = (BigInt(N) * BigInt(N + 1)) / 2n
// 500000000500000000n
```

### 등비수열

이웃한 항의 비가 일정한 수열입니다. 첫째 항 a, 공비 r, 항의 개수 n이면 `r ≠ 1`일 때 다음과 같습니다.

$$
S = \frac{a(r^n - 1)}{r - 1}
$$

- `S`는 n개 항의 합, `a`는 첫째 항, `r`은 공비, `n`은 항의 개수입니다.
- `r = 1`이면 모든 항이 `a`이므로 합은 `a * n`입니다. 이 경우를 따로 처리해야 0으로 나누지 않습니다.

```js
const geo = (a, r, n) =>
  r === 1 ? a * n : (a * (r ** n - 1)) / (r - 1)
geo(1, 2, 10) // 1023 (1 + 2 + 4 + ... + 512)
geo(3, 2, 5)  // 93 (3 + 6 + 12 + 24 + 48)
```

- `r ** n`이 크게 자라므로 안전 정수 범위를 쉽게 넘습니다. 큰 값은 BigInt로 계산하거나, 나머지를 구하는 문제에서는 모듈러 역원을 써야 합니다(자세히는 57편).
- 항의 개수가 작으면 반복문으로 더하는 편이 안전하고, 개수가 크면(10^9 이상) 공식이 필요합니다.

**흔한 실수:** 공비가 1인 경우를 빼먹는 것입니다. 공식에 `r = 1`을 넣으면 `0 / 0`이 되어 `NaN`입니다. 또 공식으로 풀 수 있는 `10^9`개의 합을 반복문으로 더하면 시간 초과가 납니다.

## 핵심 정리

- 정수 몫은 `Math.floor(a / b)`, 나머지는 `a % b`이며, `%`의 부호는 나뉘는 수를 따르고 몫은 음수에서 `Math.trunc`와 `Math.floor`가 다릅니다.
- `Math.round`는 .5를 양의 무한대 쪽으로 올리고, 소수 반올림은 부동소수점 오차 때문에 정수로 환산해 계산하는 편이 안전합니다.
- `Math.min`, `Math.max`는 빈 입력에서 `Infinity`, `-Infinity`를 주고, 초기값은 입력 범위를 덮게 잡습니다.
- 팩토리얼과 거듭제곱은 2^53을 넘으면 Number가 부정확하므로 BigInt를 쓰고, 큰 지수는 빠른 거듭제곱으로 O(log e)에 계산합니다.
- 진법은 `toString(radix)`와 `parseInt(s, radix)`로 바꾸고, 자릿수는 `% 10`과 `Math.floor(n / 10)` 또는 문자열로 다룹니다.
- 음수 나머지는 `((a % m) + m) % m`으로 보정하고, 등차·등비수열의 합은 공식으로 구하되 곱이 2^53을 넘는지 확인합니다.
