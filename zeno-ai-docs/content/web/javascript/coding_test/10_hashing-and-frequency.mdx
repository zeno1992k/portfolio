## 중복 제거

중복 제거는 Set에 넣는 것으로 끝납니다. Set은 같은 값을 하나만 보관하고 삽입 순서를 유지합니다(자세히는 09편).

```js
const arr = [3, 1, 3, 2, 1]
const uniq = [...new Set(arr)]
console.log(uniq) // [3, 1, 2] (처음 나온 순서 유지)
```

- 시간 복잡도는 O(n)입니다. 원소마다 Set의 `add`를 평균 O(1)로 한 번 부릅니다.
- 같은 결과를 내는 `arr.filter((v, i) => arr.indexOf(v) === i)`는 `indexOf`가 O(n)이라 전체가 O(n²)입니다. 입력이 10만 개이면 시간 초과가 날 수 있습니다.
- 중복이 있는지만 알면 될 때는 크기를 비교합니다. 하나라도 겹치면 Set이 더 작습니다.

```js
const hasDup = new Set(arr).size !== arr.length // true
```

- 처음 중복이 나오는 자리에서 멈추려면 보면서 넣습니다.

```js
const seen = new Set()
for (const x of arr) {
  if (seen.has(x)) { console.log('중복', x); break }
  seen.add(x)
}
// 중복 3
```

- 객체의 배열은 객체 자체가 아니라 기준이 되는 필드로 중복을 판단합니다.

```js
const users = [{ id: 1 }, { id: 2 }, { id: 1 }]
const ids = new Set()
const uniqUsers = users.filter((u) => {
  if (ids.has(u.id)) return false
  ids.add(u.id)
  return true
}) // id가 1, 2인 두 객체
```

**흔한 실수:** 객체 배열에 `new Set(users)`를 쓰는 것입니다. 객체는 참조로 비교되어 내용이 같아도 전부 남습니다.

## Hash 개념

해시(hash)는 키를 해시 함수에 넣어 정수로 바꾸고, 그 정수로 저장 칸(버킷)의 위치를 정해 키로 값을 바로 찾는 방식입니다. 배열이 인덱스로 한 번에 접근하듯, 해시는 키로 한 번에 접근합니다.

키가 정수이고 칸이 5개인 단순한 모델을 보면 이렇습니다. 해시 함수는 `키 % 5`로 가정합니다.

| 키 | 해시값(키 % 5) | 들어가는 칸 |
|----|----------------|-------------|
| 12 | 2 | 2번 |
| 7 | 2 | 2번 (12와 같은 칸) |
| 9 | 4 | 4번 |

- 조회할 때도 같은 계산으로 칸을 찾고, 그 칸 안만 확인합니다. 전체를 훑지 않아서 평균 O(1)입니다.
- 선형 탐색(배열 `find`, `includes`)은 O(n), 해시 조회는 평균 O(1)입니다. 해시의 이득은 "찾기"를 반복할 때 나타납니다.
- JavaScript에서 해시 구조는 Map, Set, Object입니다. 엔진 내부의 해시 함수와 테이블 구조는 명세가 정하지 않고, 명세는 Map과 Set의 접근 시간이 평균 준선형이어야 한다는 것만 요구합니다. 코딩테스트에서는 평균 O(1)로 계산합니다.
- 해시는 순서가 아니라 존재 여부와 값 조회를 위한 구조입니다. 키들을 크기순으로 꺼내거나 범위로 찾는 데는 맞지 않습니다.

## 해시 충돌과 평균, 최악 복잡도

서로 다른 키가 같은 칸에 배정되는 것을 충돌(collision)이라고 합니다. 위 표의 12와 7이 그 예입니다. 칸 수보다 키가 많으면 충돌은 피할 수 없습니다.

- 흔한 해결법은 칸마다 후보 목록을 두는 체이닝입니다. 같은 칸에 들어온 키들을 목록으로 이어 두고, 조회하면 칸을 찾은 뒤 목록 안에서 실제 키와 비교합니다.
- 충돌이 적으면 목록이 짧아서 조회가 평균 O(1)입니다. 키들이 한 칸에 몰리면 목록이 길어져 조회가 O(n)까지 느려집니다. 그래서 일반적인 해시 테이블의 이론은 평균 O(1), 최악 O(n)입니다.
- 칸 수를 키 개수에 맞춰 늘려 충돌을 줄이는 재해시(rehash)가 있고, 이 때문에 원소 하나를 추가하는 일이 가끔 크게 느려질 수 있습니다. 평균으로는 상수입니다.
- JavaScript 코딩테스트에서 충돌이 문제가 될 만큼 몰리는 입력을 만나는 일은 드뭅니다. 평균 O(1)로 설계하되, 해시 연산이 O(1)이 아니라 평균이라는 점은 알아 둡니다.
- 키 하나를 해시하는 비용은 키의 크기에 비례합니다. 긴 문자열 키를 반복해 넣으면 연산 하나가 O(1)이 아니라 O(문자열 길이)입니다.

| 연산 | 평균 | 최악(이론) |
|------|------|------------|
| 조회, 삽입, 삭제 | O(1) | O(n) |
| 전체 순회 | O(n) | O(n) |

## 빈도수 Hash

빈도수 세기는 원소를 키로, 등장 횟수를 값으로 저장하는 가장 흔한 해시 패턴입니다.

```js
const words = ['a', 'b', 'a', 'c', 'a', 'b']
const freq = new Map()
for (const w of words) {
  freq.set(w, (freq.get(w) ?? 0) + 1)
}
console.log(freq) // Map(3) { 'a' => 3, 'b' => 2, 'c' => 1 }
```

- 한 번 훑어서 O(n)입니다. 결과 Map에서 최빈값, 등장 횟수 비교, 한 번만 나온 값 찾기를 모두 할 수 있습니다.
- 최빈값은 Map을 한 번 더 순회해 최댓값을 찾습니다. 횟수가 같으면 어느 쪽을 고를지 문제 조건대로 정합니다.

```js
let best = null
let bestCount = 0
for (const [key, count] of freq) {
  if (count > bestCount) { best = key; bestCount = count }
}
console.log(best, bestCount) // 'a' 3
```

- 횟수 내림차순, 같으면 키 오름차순처럼 정렬이 필요하면 쌍으로 펼쳐 정렬합니다.

```js
const sorted = [...freq].sort(
  (x, y) => y[1] - x[1] || (x[0] < y[0] ? -1 : 1),
)
```

키가 문자열이면 위처럼 비교 연산자로 사전순을 정하고, 숫자이면 `x[0] - y[0]`으로 뺍니다(자세히는 26편).

키가 작은 정수나 소문자 같은 고정된 범위이면 배열이 해시보다 단순하고 빠릅니다. 키를 인덱스로 씁니다.

```js
const cnt = new Array(26).fill(0)
for (const ch of 'banana') {
  cnt[ch.charCodeAt(0) - 97]++   // 'a'는 코드 97
}
// cnt[0]=3 ('a'), cnt[1]=1 ('b'), cnt[13]=2 ('n')
```

| 키의 성질 | 쓸 구조 |
|-----------|---------|
| 작은 정수 범위(0부터 N까지), 소문자 26개 | 배열 |
| 범위가 크거나 모름, 문자열, 음수, 큰 수 | Map |
| 키가 문자열이고 프로토타입 키가 없을 것이 확실 | Object도 가능 |

**흔한 실수:**

- 값이 없을 때 `undefined + 1`이 되어 `NaN`이 저장되는 것입니다. `?? 0`으로 기본값을 줍니다.
- 빈도 배열의 크기를 모자라게 잡거나, 대문자·숫자가 섞인 입력에 소문자 기준 인덱스를 쓰면 `-` 인덱스나 범위 밖에 쓰게 됩니다. 입력 범위를 먼저 확인합니다.

## Key-Value 탐색

"이 값에 대응하는 짝이 있는가"를 찾을 때, 지금까지 본 값을 Map에 키로 저장해 두면 짝을 O(1)에 조회합니다. 이중 반복문 O(n²)이 O(n)으로 줄어듭니다.

대표 유형은 두 수의 합입니다. 합이 `target`인 두 원소의 인덱스를 구하는 문제입니다.

```js
function twoSum(nums, target) {
  const seen = new Map()              // 값 -> 인덱스
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i]
    if (seen.has(need)) return [seen.get(need), i]
    seen.set(nums[i], i)
  }
  return []
}
twoSum([2, 7, 11, 15], 9) // [0, 1]
twoSum([3, 3], 6)         // [0, 1]
```

- 현재 값의 짝을 먼저 조회하고, 그다음에 현재 값을 저장합니다. 저장을 먼저 하면 `[3]`, `6`에서 자기 자신과 짝지어져 틀립니다.
- 값을 키로, 인덱스(또는 필요한 정보)를 값으로 둡니다. 키는 찾는 기준, 값은 찾은 뒤에 필요한 것입니다.
- 같은 값이 여러 번 나와 마지막 인덱스가 필요하면 덮어쓰고, 처음 인덱스가 필요하면 `has`로 검사해 덮어쓰지 않습니다.

이 패턴은 다음처럼 확장됩니다.

| 문제 유형 | 키 | 값 |
|-----------|-----|-----|
| 두 수의 합 | 지금까지 본 숫자 | 인덱스 |
| 이름으로 점수 조회 | 이름 | 점수 |
| 특정 문자가 처음 나온 위치 | 문자 | 인덱스 |
| 누적합이 같은 구간 찾기 | 누적합 | 처음 등장한 인덱스(자세히는 29편) |

**흔한 실수:** 짝이 되는 값이 자기 자신인 경우를 놓치는 것입니다. 저장 전에 조회하는 순서로 쓰면 같은 원소를 두 번 쓰지 않아서 자연스럽게 막힙니다.

## 그룹화

그룹화는 원소를 기준에 따라 묶는 일입니다. 기준 값을 키로, 해당 원소들의 배열을 값으로 하는 해시를 만듭니다. ES2024에서 `Object.groupBy`와 `Map.groupBy`가 추가되었습니다.

```js
const words = ['apple', 'avocado', 'bean']
const byObj = Object.groupBy(words, (w) => w[0])
// { a: ['apple', 'avocado'], b: ['bean'] }
const byMap = Map.groupBy([1, 2, 3, 4, 5], (x) => x % 2)
// Map { 1 => [1, 3, 5], 0 => [2, 4] }
```

| 항목 | `Object.groupBy` | `Map.groupBy` |
|------|------------------|---------------|
| 반환 | 프로토타입이 없는 객체 | Map |
| 키 | 문자열, 심벌(다른 값은 문자열로 변환) | 아무 값 |
| 콜백 인수 | `(원소, 인덱스)` | `(원소, 인덱스)` |

- 반환 객체는 `Object.prototype`을 상속하지 않아서 `constructor` 같은 키가 충돌하지 않습니다.
- 결과 배열 안의 원소는 입력 순서를 유지합니다. 키의 순서는 `Object`이면 정수 키가 먼저이고, `Map`이면 처음 나온 순서입니다.
- 키가 숫자였다면 `Object.groupBy`에서는 `'1'`, `'0'` 같은 문자열이 됩니다. 숫자 키를 유지하려면 `Map.groupBy`를 씁니다.

ES2024 이전이나 지원이 불확실한 환경에서는 직접 만듭니다.

```js
const groups = new Map()
for (const w of words) {
  const key = w[0]
  if (!groups.has(key)) groups.set(key, [])
  groups.get(key).push(w)
}
```

그룹화의 대표 유형은 애너그램 묶기입니다. 글자를 정렬한 문자열이 같으면 같은 그룹입니다(애너그램은 07편).

```js
const list = ['eat', 'tea', 'tan', 'ate', 'nat', 'bat']
const groups = Map.groupBy(
  list, (w) => [...w].sort().join(''),
)
console.log([...groups.values()])
// [['eat','tea','ate'], ['tan','nat'], ['bat']]
```

- 정렬한 문자열이 키입니다. 키 하나를 만드는 비용이 정렬 때문에 O(k log k)라서, 전체는 단어 수 n에 대해 O(n · k log k)입니다(k는 단어 길이).
- 구형 환경에서는 `Object.groupBy`를 쓸 수 없으니 위 직접 구현을 씁니다.

**흔한 실수:** 그룹 키가 객체인데 `Object.groupBy`를 쓰는 것입니다. 모든 객체가 `'[object Object]'` 키 하나로 합쳐집니다(자세히는 09편).

## 해시와 정렬 중 선택 기준

같은 문제를 해시로도 정렬로도 풀 수 있는 경우가 많습니다. 어느 쪽이 맞는지는 필요한 결과의 모양과 입력의 성질로 정합니다.

| 상황 | 고르는 쪽 | 이유 |
|------|-----------|------|
| 있는지 확인, 개수 세기, 짝 찾기 | 해시 | 평균 O(1) 조회, 전체 O(n) |
| 결과가 크기순·사전순이어야 함 | 정렬 | 해시는 순서를 만들지 않음 |
| 이웃한 원소끼리 비교(최소 차이, 겹침) | 정렬 | 정렬 후 인접 원소만 보면 됨 |
| 정렬된 상태에서 범위 탐색(이분 탐색) | 정렬 | 해시는 범위 조회 불가 |
| 키 범위가 작은 정수 | 배열 카운팅 | 해시보다 단순하고 빠름 |
| 메모리가 빠듯함 | 정렬 | 해시는 키 수만큼 추가 공간 |

- 중복 판정을 정렬로 하면 O(n log n)이고, 해시로 하면 평균 O(n)입니다. 순서를 따로 쓰지 않는다면 해시가 낫습니다.
- 해시로 센 결과를 정렬해서 내는 조합이 흔합니다. 빈도수를 Map으로 O(n)에 세고, 서로 다른 키 m개만 정렬하면 O(n + m log m)입니다. 원소 전체를 정렬하는 O(n log n)보다 보통 작습니다.
- 정렬은 입력을 그대로 쓰므로 해시의 충돌과 평균 가정에 기대지 않습니다. 시간이 최악 기준으로 보장되어야 하면 정렬이 안전한 선택이 되기도 합니다.

## Object를 해시로 쓸 때의 함정

Object로 빈도수를 세면 코드는 짧지만, 다음 함정이 있습니다. 입력이 영어 소문자만이라고 보장되지 않으면 Map이 안전합니다.

### 정수형 키의 순회 순서

정수 형태의 키가 오름차순으로 먼저 순회되고, 문자열 키는 삽입 순서로 그다음에 옵니다.

```js
const o = {}
o.b = 1; o[10] = 1; o[2] = 1; o.a = 1
console.log(Object.keys(o)) // ['2', '10', 'b', 'a']
```

처음 나온 순서가 필요한 문제(예: 가장 먼저 나온 최빈값)에서 `Object`는 입력 순서를 보존하지 않습니다. Map을 씁니다.

### 프로토타입 키

객체 리터럴은 `Object.prototype`의 `constructor`, `toString` 같은 프로퍼티를 물려받습니다. 입력에 이 문자열이 나오면 카운트가 오염됩니다.

```js
const cnt = {}
cnt['constructor'] = (cnt['constructor'] || 0) + 1
console.log(cnt.constructor)
// 'function Object() { [native code] }1' (숫자가 아니라 문자열)
```

- 원인은 `cnt['constructor']`가 값을 넣기 전에도 `Object` 함수를 읽어 오기 때문입니다. `||`가 그 함수를 그대로 써서 문자열 덧셈이 됩니다.
- `'__proto__'` 키는 값 설정이 무시됩니다. `o['__proto__'] = 1`을 해도 키가 생기지 않습니다.
- `key in obj`도 상속된 키에 `true`를 돌려줍니다. 자기 키만 확인하려면 `Object.hasOwn(obj, key)`(ES2022)를 씁니다.

해결 방법은 세 가지입니다.

| 방법 | 코드 | 특징 |
|------|------|------|
| Map 사용 | `new Map()` | 가장 단순하고 안전 |
| 프로토타입 없는 객체 | `Object.create(null)` | 키 충돌 없음, 문자열 키만 |
| 자기 키 확인 | `Object.hasOwn(o, k) ? o[k] : 0` | 읽을 때마다 검사 |

```js
const safe = Object.create(null)
safe['constructor'] = (safe['constructor'] || 0) + 1 // 1
console.log(safe.constructor) // 1 (숫자)
```

### 키의 문자열 변환

숫자 1과 문자열 `'1'`이 합쳐지고, 객체 키가 모두 `'[object Object]'`가 됩니다(자세히는 09편). 숫자 키로 빈도수를 세고 `Object.keys`로 돌려받으면 문자열이라 `Number()` 변환이 필요합니다.

## 다수결 투표

다수결 투표(Boyer-Moore voting)는 배열에서 절반을 넘는 원소(다수 원소)를 시간 O(n), 추가 공간 O(1)로 찾는 알고리즘입니다. Map 없이 후보 하나와 카운터 하나만 씁니다.

규칙은 이렇습니다. 후보와 같은 값이 나오면 카운터를 올리고, 다른 값이면 내립니다. 카운터가 0이면 현재 값을 새 후보로 삼습니다.

```js
function majority(arr) {
  let cand = null
  let count = 0
  for (const x of arr) {
    if (count === 0) { cand = x; count = 1 }
    else if (x === cand) count++
    else count--
  }
  return cand
}
majority([2, 2, 1, 1, 2, 2, 3, 2]) // 2
```

`[2, 2, 1, 1, 2, 2, 3, 2]`를 따라가면 다음과 같습니다.

| 읽은 값 | 2 | 2 | 1 | 1 | 2 | 2 | 3 | 2 |
|---------|---|---|---|---|---|---|---|---|
| 후보 | 2 | 2 | 2 | 2 | 2 | 2 | 2 | 2 |
| 카운터 | 1 | 2 | 1 | 0 | 1 | 2 | 1 | 2 |

네 번째 값 뒤에 카운터가 0이 되고, 다섯 번째 값에서 후보가 새로 정해집니다(같은 2라서 표는 같습니다).

왜 맞는가: 서로 다른 두 값을 한 쌍으로 묶어 지운다고 생각합니다. 카운터를 내리는 것이 그 쌍을 지우는 것입니다. 다수 원소는 절반을 넘으므로 다른 모든 원소와 한 쌍씩 지워도 최소 하나가 남습니다. 그래서 마지막까지 남는 후보는 다수 원소입니다.

- 다수 원소가 반드시 존재한다고 보장될 때만 위 반환값을 믿을 수 있습니다. 보장이 없으면 후보가 다수가 아닐 수 있습니다(`[1, 2, 3]`은 후보가 3).
- 존재 보장이 없으면 한 번 더 훑어 후보의 개수를 세어 확인합니다.

```js
function verified(arr) {
  const cand = majority(arr)
  let k = 0
  for (const x of arr) if (x === cand) k++
  return k > arr.length / 2 ? cand : -1
}
verified([1, 2, 3])    // -1
verified([2, 2, 1, 1, 2]) // 2
```

- 절반을 넘는(`> n/2`) 조건이 핵심입니다. 정확히 절반이거나 그 이하인 경우, 그리고 n/3을 넘는 원소 두 개를 찾는 문제는 이 규칙을 그대로 쓸 수 없습니다.
- 해시로도 풀 수 있고(빈도수 Map, O(n) 시간 O(n) 공간), 정렬 후 가운데 원소를 읽어도 됩니다(O(n log n)). 공간이 O(1)이어야 하는 조건이 보이면 다수결 투표를 씁니다.

**흔한 실수:** 카운터가 0일 때 후보를 바꾸는 것을 빼먹거나, `else`가 아니라 `if` 체인으로 써서 새 후보가 정해진 같은 반복에서 `count++`가 한 번 더 실행되는 것입니다.

## 핵심 정리

- 중복 제거는 `[...new Set(arr)]`로 O(n)이고, 처음 나온 순서가 유지됩니다. 객체는 참조로 비교되어 필드 기준으로 직접 걸러야 합니다.
- 해시는 키로 칸을 정해 평균 O(1)에 조회합니다. 충돌이 몰리면 최악 O(n)이고, JavaScript 명세는 Map과 Set에 평균 준선형 접근만 요구합니다.
- 빈도수는 `map.set(k, (map.get(k) ?? 0) + 1)`로 세고, 키가 작은 정수 범위면 배열 카운팅이 더 빠릅니다.
- 짝 찾기는 현재 값의 짝을 먼저 조회한 뒤 현재 값을 저장합니다. 그룹화는 `Object.groupBy`, `Map.groupBy`(ES2024)나 직접 만든 Map으로 합니다.
- 존재 확인, 개수, 짝 찾기는 해시, 크기순이나 이웃 비교는 정렬이 맞습니다. Object 해시는 정수 키 순서와 프로토타입 키 때문에 Map이 안전합니다.
- 다수결 투표는 후보와 카운터로 절반 초과 원소를 O(n) 시간, O(1) 공간에 찾고, 존재 보장이 없으면 개수를 다시 확인합니다.
