## Pattern Matching

패턴 매칭(pattern matching)은 텍스트 `t`에서 패턴 `p`와 같은 부분 문자열이 시작하는 위치를 모두 찾는 문제입니다. 텍스트 길이를 N, 패턴 길이를 M이라 합니다.

가장 단순한 방법은 모든 시작 위치에서 패턴을 비교하는 것입니다.

```js
function naive(t, p) {
  const res = []
  for (let i = 0; i + p.length <= t.length; i++)
    if (t.startsWith(p, i)) res.push(i)
  return res
}
naive('aaaaa', 'aa') // [0, 1, 2, 3]
```

- 시작 위치가 N − M + 1개이고 각 위치에서 최대 M글자를 비교하므로 최악이 O(N · M)입니다. `t = 'aaaa…a'`, `p = 'aaa…ab'`가 최악의 입력입니다.
- N과 M이 10^5이면 10^10번 비교라서 시간 초과입니다.
- 문자열 하나에서 첫 위치만 찾는다면 `indexOf`로 충분합니다. 모든 위치가 필요하고 N이 클 때 아래 알고리즘이 필요합니다. `indexOf`의 내부 복잡도는 엔진 구현에 따르므로 최악 입력에서 선형이라고 가정하지 않습니다.
- 겹치는 위치도 모두 세는 것이 기본입니다. 위 예에서 `'aa'`는 0, 1, 2, 3에서 시작합니다. 겹치지 않게 세려면 일치할 때마다 `i`를 M만큼 건너뜁니다.

**문제의 단서:** "텍스트에서 패턴이 몇 번, 어디에 나타나는가", N이 10^5 이상, 같은 접두사를 계속 다시 비교해서 느려지는 풀이.

핵심 아이디어는 하나입니다. 일치하지 않을 때 이미 비교한 정보를 버리지 않는 것입니다. KMP와 Z는 패턴 자신의 구조를 이용하고, Rabin-Karp는 해시로 비교를 O(1)로 줄입니다.

## Prefix Function

접두사 함수(prefix function) `pi[i]`는 `s[0..i]`의 진접두사(자기 자신을 제외한 접두사) 중에서 그 부분 문자열의 접미사이기도 한 것의 최대 길이입니다. 접두사와 접미사가 같아지는 가장 긴 경계(border)의 길이입니다.

`'abcabcd'`의 접두사 함수는 `[0, 0, 0, 1, 2, 3, 0]`입니다. 인덱스 5에서 `'abcabc'`의 접두사 `'abc'`와 접미사 `'abc'`가 같아 3입니다.

계산은 이전 값을 이용해 앞에서부터 합니다. `s[0..i−1]`의 경계 길이 j가 있을 때, `s[j]`가 `s[i]`와 같으면 경계가 `j + 1`로 늘어납니다. 다르면 더 짧은 경계로 후퇴해서 다시 비교합니다.

```js
function prefixFunction(s) {
  const pi = new Array(s.length).fill(0)
  for (let i = 1; i < s.length; i++) {
    let j = pi[i - 1]
    while (j > 0 && s[i] !== s[j]) j = pi[j - 1]
    if (s[i] === s[j]) j++
    pi[i] = j
  }
  return pi
}
prefixFunction('ababaca') // [0, 0, 1, 2, 3, 0, 1]
```

`'ababaca'`를 추적합니다.

| i | s[i] | 시작 j | 과정 | pi[i] |
|---|------|--------|------|-------|
| 1 | b | 0 | s[0]은 a라서 불일치, j는 0 | 0 |
| 2 | a | 0 | s[0]과 일치 | 1 |
| 3 | b | 1 | s[1]과 일치 | 2 |
| 4 | a | 2 | s[2]와 일치 | 3 |
| 5 | c | 3 | s[3]=b 불일치, j=pi[2]=1, s[1]=b 불일치, j=pi[0]=0, s[0]=a 불일치 | 0 |
| 6 | a | 0 | s[0]과 일치 | 1 |

- `j = pi[j - 1]`은 현재 경계보다 짧은 다음으로 긴 경계로 후퇴하는 것입니다.
- 시간은 O(M)입니다. `j`는 반복마다 많아야 1 늘고, `while`의 후퇴 한 번은 `j`를 줄이므로 후퇴 횟수의 합이 증가량의 합을 넘지 못합니다(분할 상환).
- 빈 문자열이면 `pi`도 비어 있습니다.

**흔한 실수:** `pi[i]`를 접두사의 "길이"가 아니라 "인덱스"로 착각하는 것입니다. 값 j는 다음에 비교할 패턴의 위치이기도 해서 `s[j]`와 비교합니다. 인덱스 off-by-one에 주의합니다.

## KMP

KMP(Knuth-Morris-Pratt)는 텍스트를 앞에서 한 번만 훑으면서, 불일치가 났을 때 패턴의 접두사 함수로 패턴만 후퇴시키는 알고리즘입니다. 텍스트 위치는 되돌아가지 않습니다.

`j`는 현재 텍스트 위치 `i`에서 끝나는, 패턴의 접두사와 일치한 길이입니다.

```js
function kmp(t, p) {
  const pi = prefixFunction(p), res = []
  let j = 0
  for (let i = 0; i < t.length; i++) {
    while (j > 0 && t[i] !== p[j]) j = pi[j - 1]
    if (t[i] === p[j]) j++
    if (j === p.length) {
      res.push(i - j + 1)
      j = pi[j - 1]
    }
  }
  return res
}
```

`t = 'abababc'`, `p = 'ababc'`(`pi = [0, 0, 1, 2, 0]`)를 추적합니다.

| i | t[i] | 시작 j | 과정 | 끝 j |
|---|------|--------|------|------|
| 0 | a | 0 | p[0]과 일치 | 1 |
| 1 | b | 1 | p[1]과 일치 | 2 |
| 2 | a | 2 | p[2]와 일치 | 3 |
| 3 | b | 3 | p[3]과 일치 | 4 |
| 4 | a | 4 | p[4]=c 불일치, j=pi[3]=2, p[2]=a 일치 | 3 |
| 5 | b | 3 | p[3]과 일치 | 4 |
| 6 | c | 4 | p[4]와 일치, j=5=M이라 시작 위치 2를 기록 | 5 |

- 시간은 접두사 함수 O(M) + 매칭 O(N)이고, 공간은 O(M)입니다.
- 일치를 찾은 뒤 `j = pi[j - 1]`로 후퇴하므로 겹치는 일치도 모두 찾습니다. `kmp('aaaaa', 'aa')`는 `[0, 1, 2, 3]`입니다.
- 패턴이 비어 있으면 `p[0]`이 `undefined`라서 이상 동작합니다. M = 0은 먼저 걸러냅니다.
- 패턴이 여러 개이면 패턴마다 O(N)이 따로 듭니다. 패턴이 아주 많으면 Aho-Corasick을 씁니다(자세히는 59편).

**흔한 실수:** 일치를 기록한 뒤 `j = 0`으로 초기화하는 것입니다. 겹치는 일치를 놓칩니다. `j = pi[j - 1]`을 씁니다. 또 `if (j === p.length)`를 `while` 앞에 두면 `p[j]`가 `undefined`가 되어 틀립니다.

## Z Algorithm

Z 배열 `z[i]`는 `s[i..]`와 `s` 전체의 가장 긴 공통 접두사 길이입니다. `z[0]`은 정의가 모호해서 보통 0으로 둡니다(이 문서도 0).

`'aabcaabxaaaz'`의 Z 배열은 `[0, 1, 0, 0, 3, 1, 0, 0, 2, 2, 1, 0]`입니다. `z[4] = 3`은 `'aab'`가 접두사와 같다는 뜻입니다.

계산은 이미 구한 가장 오른쪽 구간 `[l, r)`(접두사와 일치하는 구간)을 재사용합니다. `i`가 이 구간 안에 있으면 `s[i-l..]`의 값을 복사해 출발점으로 삼습니다.

```js
function zFunction(s) {
  const n = s.length, z = new Array(n).fill(0)
  let l = 0, r = 0
  for (let i = 1; i < n; i++) {
    if (i < r) z[i] = Math.min(r - i, z[i - l])
    while (i + z[i] < n && s[z[i]] === s[i + z[i]]) z[i]++
    if (i + z[i] > r) { l = i; r = i + z[i] }
  }
  return z
}
```

- 시간은 O(n)입니다. `r`은 줄어들지 않고 n을 넘지 못하며, `while`은 `r` 너머를 비교할 때만 성공을 이어 가서 성공 횟수의 합이 O(n)입니다.
- 구간 밖(`i ≥ r`)이면 처음부터 비교하고, 안이면 `min(r - i, z[i - l])`을 출발값으로 삼습니다. 이 값이 `r - i`보다 작으면 이미 확정이라 `while`이 바로 끝납니다.

텍스트에서 패턴 찾기는 `p + 구분자 + t`를 이어 붙여 Z 배열을 구하고, `z[i] === p.length`인 위치를 모읍니다.

```js
function zFind(t, p) {
  const z = zFunction(p + '#' + t), res = []
  for (let i = p.length + 1; i < z.length; i++)
    if (z[i] === p.length) res.push(i - p.length - 1)
  return res
}
zFind('abababc', 'ababc') // [2]
```

- 구분자는 `p`와 `t`에 나오지 않는 문자여야 합니다. 구분자가 없거나 겹치면 `z`가 `p.length`를 넘어 잘못된 위치가 잡힙니다.
- KMP와 능력은 같습니다(둘 다 O(N + M)). 접두사 함수는 "각 위치까지의 최장 경계"를, Z는 "각 위치에서 시작하는 접두사 일치 길이"를 줍니다. 문제가 "모든 접미사와 전체 문자열의 공통 접두사"를 묻는다면 Z가 바로 답이고, 경계·주기를 묻는다면 접두사 함수가 바로 답입니다.
- 접두사 함수와 Z 배열은 서로 변환할 수 있지만, 한 가지만 능숙하게 쓰는 것으로도 충분합니다.

## 문자열 Hash

문자열 해시(string hash)는 문자열을 정수 하나로 바꾸는 함수입니다. 두 문자열이 같으면 해시도 같으므로, 해시가 다르면 문자열도 다릅니다. 해시가 같다고 문자열이 같은 것은 아닙니다(충돌, 아래 절). 문자열 비교를 정수 비교 한 번으로 줄이는 것이 목적입니다.

가장 널리 쓰는 것은 다항 해시(polynomial hash)입니다. 문자열을 B진수의 수로 보고 M으로 나눈 나머지를 취합니다.

```text
H(s) = s[0]·B^(n-1) + s[1]·B^(n-2) + … + s[n-1]  (mod M)
```

- B는 밑(base), M은 소수인 모듈러, `s[i]`는 문자 코드입니다. 문자 코드가 0인 문자는 쓰지 않습니다. 0이면 앞에 붙은 0과 구별이 안 되어 `'a'`와 `'aa'`가 충돌할 수 있습니다. `charCodeAt`은 보통 1 이상이라 괜찮습니다.
- 차수의 방향은 책마다 다릅니다(첫 글자가 가장 높은 차수 또는 가장 낮은 차수). 한 코드 안에서만 일관되면 됩니다.

곱셈이 2^53을 넘으면 정확하지 않습니다(자세히는 57편). 모듈러를 9천만 미만의 소수로 잡으면 `h * B + c`가 2^53 − 1 아래에 머물러 `%`를 그대로 쓸 수 있습니다.

```js
const M1 = 89999999, M2 = 89999983 // 9천만 미만의 소수
const B1 = 256 + Math.floor(Math.random() * (M1 - 256))
const B2 = 256 + Math.floor(Math.random() * (M2 - 256))
```

- `h`, `B`는 M 미만이고 문자 코드는 65,535 이하이므로 `h * B + c`는 약 8.1 × 10^15 이하입니다.
- 밑 B는 실행마다 무작위로 정하면 입력을 미리 만들어 충돌시키는 공격을 피할 수 있습니다. 문자 코드(26자 소문자는 97–122)보다 크게 잡습니다.

접두사 해시 배열을 만들면 임의의 부분 문자열 해시를 O(1)에 구합니다.

```js
function buildHash(s, B, M) {
  const h = new Array(s.length + 1).fill(0)
  const pw = new Array(s.length + 1).fill(1)
  for (let i = 0; i < s.length; i++) {
    h[i + 1] = (h[i] * B + s.charCodeAt(i)) % M
    pw[i + 1] = pw[i] * B % M
  }
  return { h, pw }
}
const get = ({ h, pw }, l, r, M) => // s[l, r)의 해시
  ((h[r] - h[l] * pw[r - l]) % M + M) % M
```

- `h[i]`는 앞 i글자의 해시이고, `pw[i]`는 `B^i mod M`입니다.
- `s[l, r)`의 해시는 `h[r]`에서 앞쪽 l글자가 기여한 `h[l] · B^(r−l)`을 뺀 값입니다. 음수가 될 수 있어서 M을 더해 보정합니다(자세히는 57편).
- 전처리는 O(n), 부분 문자열 해시 질의는 O(1)입니다.

```js
const A = buildHash('abcabc', B1, M1)
get(A, 0, 3, M1) === get(A, 3, 6, M1) // true ('abc' 두 개)
```

**흔한 실수:** 뺄셈 결과가 음수인데 보정하지 않는 것, 그리고 곱셈이 2^53을 넘는 모듈러(10^9 규모)를 `%`로만 처리하는 것입니다. 에러 없이 틀린 해시가 나와서 같은 문자열도 다르게 보입니다.

## Rolling Hash

롤링 해시(rolling hash)는 길이가 고정된 윈도우를 한 칸씩 밀면서, 해시를 처음부터 다시 계산하지 않고 O(1)에 갱신하는 방법입니다. 빠지는 문자의 기여를 빼고, 나머지를 B배 하고, 새 문자를 더합니다.

윈도우 길이가 m이고 현재 해시가 `s[i..i+m−1]`의 것일 때:

```text
다음 = (현재 − s[i]·B^(m−1)) · B + s[i+m]  (mod M)
```

- `B^(m−1) mod M`은 한 번 계산해 둡니다.
- 앞 절의 접두사 해시 배열을 쓰면 윈도우를 직접 갱신하지 않아도 모든 길이의 윈도우 해시를 `get`으로 구할 수 있습니다. 한 길이로만 밀 때는 롤링이 메모리를 아낍니다.
- 롤링 갱신도 곱셈이 포함되므로 모듈러 크기 제한이 같습니다.

롤링 해시는 윈도우를 미는 슬라이딩 윈도우(31편)와 같은 틀입니다. 윈도우에 들어오고 나가는 값이 문자 하나라는 점만 다릅니다.

## Rabin-Karp

라빈-카프(Rabin-Karp)는 롤링 해시로 모든 윈도우의 해시를 구하고, 패턴의 해시와 같을 때만 실제로 비교하는 매칭 알고리즘입니다.

```js
function rabinKarp(t, p, B, M) {
  const n = t.length, m = p.length, res = []
  if (m === 0 || m > n) return res
  const P = buildHash(p, B, M)
  const hp = P.h[m], top = P.pw[m - 1] // top은 B^(m-1)
  let ht = buildHash(t.slice(0, m), B, M).h[m]
  for (let i = 0; ; i++) {
    if (hp === ht && t.startsWith(p, i)) res.push(i)
    if (i + m >= n) break
    const out = t.charCodeAt(i) * top % M
    ht = ((ht - out + M) % M * B + t.charCodeAt(i + m)) % M
  }
  return res
}
rabinKarp('abababc', 'ababc', B1, M1) // [2]
```

- 해시가 같으면 `startsWith`로 한 번 더 확인합니다. 해시 충돌이 만든 가짜 일치를 걸러 내서 결과는 항상 정확합니다.
- 평균은 O(N + M)입니다. 가짜 일치가 드물기 때문입니다. 최악은 해시가 계속 충돌하는 O(N · M)이지만 무작위 밑과 큰 모듈러로 사실상 일어나지 않습니다.
- 확인을 생략하고 해시만 믿는 경우(이중 해싱)는 아래 절에서 다룹니다.
- KMP·Z는 확정적으로 O(N + M)이라서 단일 패턴 매칭에는 보통 이들이 안전합니다. Rabin-Karp는 여러 길이의 후보를 해시 집합으로 비교하거나(여러 패턴), 이분 탐색과 결합하는 문제(아래 절)에서 강합니다.

**문제의 단서:** "같은 부분 문자열이 두 번 이상 나오는가", "길이 L의 부분 문자열 중 서로 다른 것의 수", 이분 탐색할 수 있는 길이 변수.

**흔한 실수:** 윈도우를 갱신할 때 빠지는 문자의 `top`을 `B^m`으로 쓰는 것(정답은 `B^(m−1)`), 그리고 음수 보정(`+ M`)을 빠뜨리는 것입니다.

## 해시 충돌과 이중 해싱

해시 충돌(collision)은 서로 다른 두 문자열이 같은 해시값을 갖는 일입니다. 해시값이 M가지뿐이라 문자열이 M가지를 넘으면 반드시 일어나고, 그보다 훨씬 적은 개수에서도 일어납니다.

- 두 문자열을 한 번 비교할 때 충돌 확률은 대략 `1/M`입니다.
- K개의 서로 다른 문자열 중 어떤 둘이 충돌할 확률은 대략 `K² / (2M)`입니다(생일 문제). M이 약 9 × 10^7이면 K가 약 10^4개만 돼도 충돌이 한 쌍쯤 나올 정도입니다.

이중 해싱(double hashing)은 서로 다른 모듈러(또는 밑)로 해시를 두 개 만들고, 두 값이 모두 같을 때만 같다고 보는 방법입니다. 충돌 확률이 대략 `1/(M1 · M2)`로 줄어, M1과 M2가 9천만 근처이면 약 8 × 10^15분의 1입니다. K가 10^5개여도 충돌 확률은 약 10^-6 규모입니다.

두 해시를 하나의 정수 키로 묶으면 `Set`과 `Map`에 바로 넣을 수 있습니다.

```js
const key = (h1, h2) => h1 * M2 + h2
// h1 < M1, h2 < M2 이므로 key < M1 * M2 ≈ 8.1e15 < 2^53
```

- 안전한 정수 범위 안에서 두 값이 겹치지 않게 하나로 합치는 방법입니다. 문자열로 `h1 + ',' + h2`를 만드는 것보다 훨씬 빠릅니다.
- 이 합치기가 성립하려면 `M1 * M2`가 2^53 − 1 이하여야 합니다. 두 모듈러가 각각 9천만 미만이면 8.1 × 10^15로 만족합니다.
- 충돌 방어 순서: 소수 모듈러 사용, 무작위 밑, 이중 해싱, 마지막으로 실제 문자열 확인입니다. 확인이 가능한 곳(Rabin-Karp)에서는 확인을 넣는 것이 가장 확실합니다.
- 모듈러를 2의 거듭제곱으로 잡거나 밑을 고정하면 이를 노린 입력에 깨질 수 있다고 알려져 있습니다. 소수 모듈러와 무작위 밑을 씁니다.

**흔한 실수:** 해시가 같으면 문자열이 같다고 단정하는 것입니다. 확률적으로 맞을 뿐이며, 모듈러가 작은데 비교 횟수가 크면 실제로 틀립니다. 두 해시를 쓰는 이유가 이것입니다.

## 문자열의 최소 주기

문자열 `s`의 최소 주기는 `s`를 어떤 문자열 `u`의 반복으로 만들 수 있을 때 가장 짧은 `u`의 길이입니다. 접두사 함수의 마지막 값으로 구합니다.

`k = n − pi[n − 1]`로 두면, `n`이 `k`로 나누어떨어질 때 최소 주기가 `k`입니다. 나누어떨어지지 않으면 `s` 전체가 한 주기입니다(주기 n).

```js
function minPeriod(s) {
  const n = s.length
  const k = n - prefixFunction(s)[n - 1]
  return n % k === 0 ? k : n
}
minPeriod('abcabcabc') // 3
minPeriod('abab')      // 2
minPeriod('abcab')     // 5 (k=3이지만 5가 3으로 안 나뉨)
minPeriod('aaaa')      // 1
```

- 이유: 접두사 함수의 마지막 값은 문자열의 가장 긴 경계(접두사이면서 접미사인 것)입니다. 경계를 뺀 `k`만큼 밀어도 문자열이 자기 자신과 겹치므로 `k`가 "겹쳐 이동하는" 최소 거리입니다. 이 `k`가 `n`의 약수일 때 `s`는 길이 k 조각의 반복으로 정확히 나뉩니다.
- `n − pi[n − 1]`은 약수가 아니어도 `s[i] = s[i + k]`가 성립하는 최소 간격(주기의 다른 정의)입니다. 문제가 "반복 단위"를 묻는지 "가장 짧은 간격"을 묻는지 확인합니다.
- 반복 횟수는 `n / k`입니다. `'abcabcabc'`는 3번 반복입니다.
- Z 배열로도 구할 수 있습니다. `z[i] === n - i`(접미사 전체가 접두사와 일치)이고 `n % i === 0`인 가장 작은 `i`가 최소 주기입니다.
- `n = 1`이면 `pi = [0]`이라 `k = 1`, 결과는 1입니다. 빈 문자열은 따로 처리합니다.

**문제의 단서:** "문자열이 어떤 문자열의 반복인가", "반복 단위의 최소 길이", "문자열을 몇 번 반복한 것인가".

## 해시와 이분 탐색으로 최장 반복 부분 문자열

최장 반복 부분 문자열(longest repeated substring)은 문자열에서 두 번 이상 나타나는 가장 긴 부분 문자열입니다. 해시와 이분 탐색을 합치면 O(n log n)입니다.

이분 탐색이 가능한 이유는 단조성입니다. 길이 L의 반복 부분 문자열이 있으면, 그 앞 L−1글자도 같은 위치에서 두 번 나타나므로 길이 L−1의 반복도 있습니다. 반복 여부는 길이가 작은 쪽에서 참, 큰 쪽에서 거짓으로 나뉩니다(자세히는 28편).

길이 `len` 검사는 모든 윈도우의 이중 해시 키를 `Set`에 넣다가 이미 있으면 반복이 있는 것입니다.

```js
function findRepeat(n, len, A, C) {
  const seen = new Set()
  for (let i = 0; i + len <= n; i++) {
    const h1 = get(A, i, i + len, M1)
    const k = h1 * M2 + get(C, i, i + len, M2)
    if (seen.has(k)) return i // 반복의 시작 위치
    seen.add(k)
  }
  return -1
}
```

길이는 이분 탐색으로 찾습니다. 상한은 `n − 1`이고, 성공하면 길이를 늘립니다.

```js
function longestRepeat(s) {
  const n = s.length
  const A = buildHash(s, B1, M1), C = buildHash(s, B2, M2)
  let lo = 0, hi = n - 1, start = 0
  while (lo < hi) {
    const mid = (lo + hi + 1) >> 1
    const pos = findRepeat(n, mid, A, C)
    if (pos >= 0) { lo = mid; start = pos }
    else hi = mid - 1
  }
  return s.slice(start, start + lo)
}
longestRepeat('banana') // 'ana'
longestRepeat('aaaa')   // 'aaa' (겹침 허용)
```

- 시간은 `findRepeat` 한 번이 O(n), 이분 탐색 약 log n번이라 O(n log n)이고, 공간은 O(n)입니다.
- `(lo + hi + 1) >> 1`은 올림 중간값입니다. 성공하면 `lo = mid`로 올라가므로 `+ 1`이 없으면 무한 반복합니다.
- 위 코드는 두 출현이 겹쳐도 인정합니다. 겹치면 안 되는 문제라면 `Set` 대신 `Map`에 처음 위치를 저장하고 `i - 처음위치 >= len`일 때만 성공으로 처리합니다. 이때도 길이에 대한 단조성은 유지됩니다.
- 해시가 충돌하면 거짓 성공이 나옵니다. 이중 해싱을 쓰고, 정확한 답이 필수이면 찾은 두 위치의 문자열을 직접 비교해 확인합니다.
- 접미사 배열과 LCP 배열을 쓰면 해시 없이 확정적으로 풀 수 있습니다(자세히는 59편).

**문제의 단서:** "두 번 이상 나타나는 가장 긴 부분 문자열", "같은 부분 문자열이 겹치지 않고 두 번", 길이 변수에 단조성이 있는 문자열 문제.

**흔한 실수:** 이분 탐색을 하지 않고 길이를 1부터 하나씩 늘려 가며 검사하는 것입니다. 최악 O(n²)입니다. 또 `lo`와 `hi`의 갱신 방식이 틀려 무한 반복이 되는 것(올림 중간값)입니다.

## 핵심 정리

- 완전탐색 매칭은 O(N · M)이라서 N이 10^5 이상이면 KMP·Z·Rabin-Karp로 줄입니다.
- 접두사 함수 `pi[i]`는 `s[0..i]`의 가장 긴 경계 길이이고, KMP는 불일치마다 `j = pi[j - 1]`로 패턴만 후퇴해 텍스트를 한 번만 훑습니다. 겹치는 일치도 찾으려면 일치 후에도 `pi`로 후퇴합니다.
- Z 배열은 각 위치에서 시작하는 접두사 일치 길이이며, `p + 구분자 + t`에서 `z[i] === p.length`인 위치가 일치입니다.
- 다항 해시는 접두사 해시로 부분 문자열 해시를 O(1)에 구하고, 롤링 해시는 윈도우를 밀며 O(1)에 갱신합니다. JavaScript에서는 모듈러를 9천만 미만으로 잡으면 곱이 2^53 안에 있습니다.
- 충돌은 확률적으로 일어나므로 소수 모듈러, 무작위 밑, 이중 해싱을 쓰고, 가능하면 실제 비교로 확인합니다.
- 최소 주기는 `k = n − pi[n − 1]`이 n의 약수일 때 k이고 아니면 n이며, 최장 반복 부분 문자열은 길이에 대한 이분 탐색과 해시 집합으로 O(n log n)에 구합니다.
