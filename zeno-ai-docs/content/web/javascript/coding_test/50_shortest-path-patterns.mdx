## 상태 확장 Dijkstra

상태 확장 Dijkstra는 **정점 하나가 아니라 (정점, 상태) 한 쌍을 노드로 보고** Dijkstra를 돌리는 방법입니다. 같은 정점이라도 도착할 때의 상태에 따라 앞으로 할 수 있는 일이 다르면, 정점별 최단거리 하나로는 부족합니다.

- 예: 도로를 최대 K번 무료로 지날 수 있는 문제에서 정점 v에 무료를 0번 쓰고 도착한 거리가 10, 1번 쓰고 도착한 거리가 4일 수 있습니다. 4가 더 짧지만 무료 기회를 소모한 상태라서 10을 버릴 수 없습니다.
- 상태를 붙이면 정점이 V개에서 V × S개(S는 상태 수)로 늘어납니다. 간선은 상태가 바뀌는 전이까지 포함합니다. 가중치가 모두 0 이상이면 확장한 그래프에서도 Dijkstra가 그대로 성립합니다.

| 문제 유형 | 추가하는 상태 | 전이 |
|-----------|---------------|------|
| 도로를 K개까지 무료로 이용 | 쓴 횟수 k | 이용하면 k + 1, 비용 0 |
| 홀수 번·짝수 번째 이동만 허용 | 이동 횟수의 홀짝 | 이동할 때마다 뒤집기 |
| 같은 방향으로 연속 이동 제한 | 마지막 방향, 연속 횟수 | 방향이 같으면 연속 횟수 + 1 |
| 연료·체력 | 남은 양 | 이동하면 감소, 충전소에서 증가 |
| 열쇠·아이템 | 가진 목록(다음 절) | 칸에 들어갈 때 갱신 |

### 구현

상태를 정수 하나로 인코딩해서 평평한 `dist` 배열을 씁니다. 상태 id는 `정점 × S + 상태`입니다(자세히는 39편).

```js
function solve(n, adj, K, src, dst) {
  const S = K + 1                 // 쓴 횟수 0 ... K
  const dist = new Array(n * S).fill(Infinity)
  const pq = new Heap((a, b) => a[0] - b[0])
  const go = (v, k, d) => {       // 상태 (v, k)로 거리 d에 도착
    if (d >= dist[v * S + k]) return
    dist[v * S + k] = d
    pq.push([d, v * S + k])
  }
  go(src, 0, 0)
```

```js
  while (pq.size) {
    const [d, id] = pq.pop()
    if (d > dist[id]) continue   // 오래된 항목은 버림
    const u = Math.floor(id / S), k = id % S
    for (const [v, w] of adj[u]) {
      go(v, k, d + w)            // 그냥 지나감
      if (k < K) go(v, k + 1, d) // 무료 이용: 비용 0
    }
  }
  const best = Math.min(...dist.slice(dst * S, dst * S + S))
  return best === Infinity ? -1 : best
}   // 위 코드와 이어지는 한 함수
```

- 도착점의 답은 **모든 상태 중 최솟값**입니다. 도착 정점에 어떤 상태로 닿아도 되는지 문제에서 확인합니다.
- 오래된 항목 걸러내기(`d > dist[id]`)와 `go`의 이완 조건은 48편의 Dijkstra와 같습니다.
- 정점 id는 `Math.floor(id / S)`로 구합니다. `(id / S) | 0`은 id가 2³¹ 이상이면 틀립니다(자세히는 24편).
- 시간복잡도는 노드 V × S개, 간선 E × S개 정도이므로 O(S · E · log(S · E))입니다. 메모리는 O(V × S)입니다. S가 크면 V × S가 메모리 한도를 넘는지 먼저 계산합니다(자세히는 39편).

**문제의 단서:** "최대 K번까지", "한 번만 ~할 수 있다", "~를 가진 상태에서만", "연속으로 ~번 이상 금지"입니다. 입력 조건의 K가 작다(수십 이하)는 것이 이 방법을 쓴다는 신호입니다.

**흔한 실수:**

- 상태별로 거리를 따로 저장하지 않고 `dist[v]` 하나만 쓰는 것입니다. 값이 큰 상태가 더 유리한 미래를 가질 수 있어서 틀립니다.
- 전이 순서 때문에 `k`가 `K`를 넘는 상태를 만드는 것입니다. `k < K` 조건을 빼먹으면 배열 범위를 벗어난 다른 정점의 상태로 들어갑니다.

## 최단거리와 비트마스크

상태가 **어떤 항목들을 가졌는가의 집합**이면 비트마스크로 인코딩합니다(24편). 항목이 K개이면 상태는 2^K가지입니다. 모든 열쇠를 모으는 최단거리, 필수 정점을 모두 거치는 최단거리가 대표 유형입니다.

정점 v에 열쇠가 있으면 `keyBit[v]`가 그 열쇠의 비트이고, 없으면 0입니다. 상태 id는 `mask × n + v`입니다.

```js
function collectAll(n, adj, keyBit, K, src) {
  const full = (1 << K) - 1       // 열쇠를 모두 모은 상태
  const dist = new Array((full + 1) * n).fill(Infinity)
  const start = keyBit[src] * n + src
  const pq = new Heap((a, b) => a[0] - b[0])
  dist[start] = 0
  pq.push([0, start])
```

```js
  while (pq.size) {
    const [d, id] = pq.pop()
    if (d > dist[id]) continue
    const u = id % n, mask = (id - u) / n
    if (mask === full) return d  // 처음 꺼낸 완성 상태가 최단
    for (const [v, w] of adj[u]) {
      const nid = (mask | keyBit[v]) * n + v
      if (d + w >= dist[nid]) continue
      dist[nid] = d + w
      pq.push([d + w, nid])
    }
  }
  return -1                       // 모두 모을 수 없음
}   // 위 코드와 이어지는 한 함수
```

- 정점을 지나는 것만으로 열쇠를 줍는 경우입니다. 이동에 열쇠가 필요한 문(조건부 간선)이면 간선을 건널 때 `(mask & need) === need`를 확인합니다.
- 우선순위 큐에서 처음 꺼낸 완성 상태(`mask === full`)의 거리가 최단입니다. Dijkstra는 꺼낸 순서가 거리 순서입니다.
- 같은 정점을 여러 번 지나도 됩니다. 상태에 마스크가 들어 있어서 이미 방문한 정점에도 다시 갈 수 있습니다.
- 시간복잡도는 O(2^K · E · log(2^K · E)), 메모리는 O(2^K · V)입니다. K는 보통 10 안팎이어야 합니다.
- `1 << K`는 K가 31 이상이면 32비트 정수 한계 때문에 틀립니다(자세히는 24편).

모든 정점을 한 번씩 방문하는 최단 경로(외판원 유형)는 다른 방식도 있습니다. 먼저 Floyd-Warshall(49편)로 모든 쌍의 거리를 구하고, 거리 `d[i][j]`로 `dp[mask][v] = 마스크 mask를 방문하고 v에서 끝나는 최소 거리`를 채우는 비트마스크 DP입니다. 점화식은 `dp[mask | (1 << j)][j] = min(dp[mask][i] + d[i][j])`이고 O(2^N · N²)입니다(자세히는 73편).

## 최단거리와 시간·비용 상태

가중치가 둘일 때(시간과 비용, 거리와 연료) 하나는 `dist` 값으로 최소화하고 **다른 하나는 상태로 올립니다**. 상태로 올린 값은 범위가 작아야 합니다.

- 예: 간선마다 시간 t와 요금 c가 있고 **요금 합계가 M 이하인 경로 중 최소 시간**을 구하는 문제입니다. 상태는 지금까지 쓴 요금 c(0–M)이고 `dist`는 시간입니다.
- 상태 확장 구현과 틀은 같고, 전이 부분만 달라집니다.

```js
// 노드: (정점 v, 쓴 요금 c) → id = v * (M + 1) + c
// dist[id] = 그 상태에 도착하는 최소 시간
for (const [v, t, c] of adj[u]) {
  if (cost + c <= M) go(v, cost + c, d + t)   // 요금 한도 확인
}
// 답: 도착점의 모든 요금 상태 중 dist 최솟값
```

- 어느 쪽을 상태로 올릴지는 값의 범위로 정합니다. 요금이 최대 M = 10^3 정도로 작으면 요금을 상태로, 시간이 수십 이하이면 시간을 상태로 올립니다. 둘 다 크면 이 방법으로는 풀 수 없습니다.
- 요금을 상태로 올렸다면 `go`가 항상 더 작은 시간만 받으므로 같은 상태가 여러 번 갱신될 수 있고, 오래된 항목은 `d > dist[id]`로 버립니다.
- 노드 수가 V × (M + 1)이므로 O(M · E · log(M · E))입니다.

시간 자체가 제약인 유형은 상태를 늘리지 않고 이완 식만 바꿉니다. 예를 들어 간선이 시각 `open` 이후에만 열려 있고 **기다릴 수 있으면** 도착 시각을 `Math.max(d, open) + w`로 계산합니다. 기다릴 수 있으면 일찍 도착하는 것이 항상 이득이라서 정점별 최단 도착 시각 하나로 충분합니다. 기다릴 수 없으면 일찍 도착해서 오히려 막힐 수 있으므로 시각을 상태로 두어야 합니다.

**흔한 실수:**

- 시간을 `dist`에 넣고 요금을 상태로 올려야 하는 문제에서 요금까지 `dist` 하나로 합치는 것입니다. 서로 단위가 달라서 합쳐서 최소화하면 의미가 없습니다.
- 요금이 0인 간선과 시간이 0인 간선을 구분하지 않는 것입니다. 비용 0 전이도 상태 id가 달라지므로 반드시 `go`로 처리해야 합니다.

## K번째 최단거리

K번째 최단거리는 시작점에서 도착점까지 **K번째로 짧은 경로의 길이**입니다. 같은 정점을 여러 번 지나도 되는 경우(정점 반복을 허용하는 경로)와 허용하지 않는 경우로 나뉘며, 허용하지 않는 쪽이 훨씬 어렵습니다.

정점 반복을 허용할 때는 Dijkstra를 조금 바꿉니다. 정점마다 **큐에서 꺼내는 것을 K번까지 허용**합니다.

```js
function kthShortest(n, adj, src, dst, K) {
  const cnt = new Array(n).fill(0)   // 정점별로 꺼낸 횟수
  const pq = new Heap((a, b) => a[0] - b[0])
  pq.push([0, src])
  while (pq.size) {
    const [d, u] = pq.pop()
    if (cnt[u] >= K) continue
    cnt[u]++
    if (u === dst && cnt[u] === K) return d   // K번째로 짧은 길이
    for (const [v, w] of adj[u]) {
      if (cnt[v] < K) pq.push([d + w, v])
    }
  }
  return -1                          // K번째 경로가 없음
}
```

- 정점 u를 j번째로 꺼낼 때의 거리가 시작점에서 u까지 j번째로 짧은 경로의 길이입니다. 도착점을 K번째로 꺼낼 때 답이 나옵니다.
- 길이가 같은 서로 다른 경로는 각각 한 번으로 셉니다. 시작점과 도착점이 같으면 길이 0인 빈 경로가 1번째입니다.
- 한 정점에서 K번까지만 꺼내므로 간선은 각각 최대 K번 처리됩니다. 시간복잡도는 O(K · E · log(K · E))입니다.
- 가중치가 0 이상이어야 합니다. 큐에 항목이 모자라 끝나면 경로가 K개 미만입니다.

정점을 한 번만 지나야 하는 K번째 경로(loopless)는 Yen 알고리즘이 대표적이고 O(K · V · (E + V log V))입니다. 코딩테스트에서는 위의 방식이나 "K개 이하의 경로" 같은 제한이 걸린 문제가 주로 나옵니다. 정점 반복을 허용하는 K번째 경로를 훨씬 빠르게(O(E + V log V + K)) 구하는 Eppstein 알고리즘도 있으나 구현이 복잡해 개요로만 알아 둡니다.

**문제의 단서:** "두 번째로 짧은 경로", "K번째 최단 시간", "최단거리와 다른 길이 중 가장 짧은 것"입니다. 경로를 하나만 구하는 문제로 착각하지 않는 것이 첫 단계입니다.

## 경로가 없는 경우 처리

도달할 수 없는 정점의 거리는 `Infinity`로 남습니다. 이 값을 출력하거나 계산에 섞으면 틀리므로 **출력 직전과 집계 직전에** 걸러냅니다.

```js
const ans = dist[dst]
console.log(ans === Infinity ? -1 : ans)   // -1은 문제 지정 값
dist.map((d) => (d === Infinity ? 'INF' : d)).join(' ')
// 가장 먼 도달 가능 정점까지의 거리
Math.max(...dist.filter(Number.isFinite))
```

- 문제가 요구하는 출력 형식(`-1`, `INF`, `0`, 공백)을 먼저 확인합니다. `Infinity`를 그대로 출력하면 문자열 `Infinity`가 나옵니다.
- 거리 0은 정상 값입니다. `if (dist[t])`처럼 참 거짓으로 검사하면 시작점과 같은 정점이나 0 가중치 간선의 결과가 "없음"으로 처리됩니다. `=== Infinity`로 비교합니다.
- 시작점과 도착점이 같으면 거리 0입니다.
- 도착점에 닿을 수 있어도 **조건이 불가능하면** 경로가 없습니다. K번 무료인데 전부 쓰고도 요금 조건을 못 맞추거나, 열쇠를 모두 모을 수 없는 경우입니다. 상태 확장에서는 도착점의 모든 상태가 `Infinity`인지로 판단합니다.
- 큐가 비어 반복이 끝나는 것이 도달 불가의 신호입니다. 조기 종료(`return`)가 없었다면 마지막에 `-1`을 반환합니다.
- 최대나 합을 집계할 때(`Math.max`, `reduce`) 도달 불가 값을 제외합니다. `Infinity`가 섞이면 최댓값이 `Infinity`가 됩니다.

**흔한 실수:** `dist` 초기값과 같은 값으로 비교해서 거르는데, 유한한 INF를 쓰면서 `INF + w`가 저장되어 `=== INF`가 거짓이 되는 것입니다. `Infinity`를 쓰면 이 문제가 생기지 않습니다(아래 절).

## 무한대(INF) 값 설계

INF는 "아직 도달하지 못함"을 표현하는 큰 수입니다. JavaScript에서는 `Infinity`가 가장 안전하고, 유한한 수를 쓰려면 조건이 있습니다.

| 선택 | 장점 | 주의 |
|------|------|------|
| `Infinity` | `Infinity + w`가 `Infinity`, 모든 수보다 큼 | 32비트 정수용 `Int32Array`에는 맞지 않아 정수 INF가 필요 |
| 10^9 | 정수라 TypedArray에 담기 쉬움 | 실제 거리가 10^9 이상이면 틀림 |
| 2^31 - 1 | `Int32Array`의 최댓값 | `INF + w`가 2^31 이상이면 부호가 뒤집힘 |
| `Number.MAX_SAFE_INTEGER` | 큰 값 | 더하면 안전 정수 범위를 넘어 정밀도 손실 |
| 10^15 | 안전 정수 안에서 INF + INF까지 가능 | 거리 상한이 이보다 작을 때만 |

INF가 갖춰야 할 조건은 세 가지입니다.

1. 실제로 나올 수 있는 **가장 큰 거리보다 커야** 합니다. 경로의 간선은 최대 V - 1개이므로 `(V - 1) × (최대 가중치)`가 거리의 상한입니다.
2. `INF + INF`가 계산될 수 있으면(Floyd-Warshall의 `d[i][k] + d[k][j]`) 그 합도 안전 정수 이하여야 합니다. 즉 INF는 `Number.MAX_SAFE_INTEGER`의 절반 이하입니다.
3. 값을 담는 배열의 타입이 그 수를 담을 수 있어야 합니다. `Int32Array`는 32비트 정수만 담고, 범위를 넘으면 최하위 비트만 남습니다(MDN의 고정폭 변환 규칙).

계산 예입니다. V = 10^5이고 가중치가 최대 10^9이면 거리 상한은 약 10^14입니다. INF = 10^15면 상한보다 크고 `2 × 10^15`가 `9.007 × 10^15`(`MAX_SAFE_INTEGER`) 이하라서 모두 만족합니다.

```js
const INF = 1e15               // 상한 1e14보다 크고, 2 * INF가 안전
Number.isSafeInteger(2 * INF)  // true
const BAD = 1e18               // 안전 정수 범위 밖
BAD + 1 === BAD                // true (정밀도 손실)
```

- 유한한 INF를 쓰면 **이완 전에** `dist[u] === INF`이면 건너뜁니다. 건너뛰지 않으면 도달 불가 정점에 `INF + w`가 저장되고, 이후 `=== INF` 비교가 틀립니다. 음수 간선이 있으면 도달 불가인데 `INF - 1`이 INF보다 작아지는 문제가 생깁니다(자세히는 49편).
- 음수 간선이 없다면 도달 가능한지의 판정을 `dist[v] === INF` 대신 `dist[v] >= INF`로 해서 `INF + w`가 저장되어도 안전하게 만들 수 있습니다.
- 입력 가중치가 크지 않고 TypedArray가 필요 없으면 `Infinity`가 가장 단순하고 틀릴 일이 없습니다.

**흔한 실수:** INF를 10^9로 두었는데 가중치가 10^9, 정점 수가 10^5라 실제 거리가 INF보다 커져서 도달 불가로 처리되는 것입니다. 입력 제한으로 거리 상한을 계산한 뒤 INF를 정합니다.

## Overflow를 피하는 거리 계산

JavaScript의 Number는 정수 overflow로 값이 뒤집히지 않지만, **2^53 - 1(`Number.MAX_SAFE_INTEGER`, 9,007,199,254,740,991)을 넘으면 정수를 정확히 표현하지 못합니다**. 값이 조용히 틀립니다.

```js
const a = 2 ** 53
Number.isSafeInteger(a)   // false
a + 1 === a               // true (1을 더해도 안 변함)
```

거리를 더할 때 확인할 것입니다.

- **상한 확인.** `(V - 1) × (최대 가중치)`가 `MAX_SAFE_INTEGER` 이하이면 Number로 충분합니다. V = 10^5이고 가중치 10^9이면 10^14라서 안전하지만, 가중치가 10^12까지면 10^17이라 안전하지 않습니다.
- **입력을 읽는 순간.** 입력 문자열이 2^53을 넘으면 `Number("...")`로 읽는 순간 이미 값이 바뀝니다. 정확해야 하면 처음부터 `BigInt("...")`로 읽습니다.
- **비트 연산과 정수 TypedArray.** `(a + b) | 0`이나 `Int32Array`에 저장하면 2^31 이상이 32비트로 잘려서 음수로 뒤집힙니다. 올림 용도의 `| 0`을 거리 계산에 쓰면 안 됩니다(자세히는 24편).
- **Floyd의 INF + INF.** INF가 안전 정수의 절반을 넘으면 합이 정밀도를 잃습니다. 앞 절의 조건 2입니다.

안전 범위를 넘는 거리가 정말 나올 때는 BigInt로 거리를 계산합니다(자세히는 02편). 모든 값이 BigInt여야 합니다.

```js
const INF = 1n << 100n           // BigInt용 INF
const dist = new Array(n).fill(INF)
dist[src] = 0n
// dist[u] + w  → w도 BigInt여야 한다. 입력은 BigInt(token)
// dist[u] + 5  // TypeError: BigInt와 Number는 섞을 수 없음
// Math.min(a, b)  // TypeError: Math는 BigInt를 받지 않음
```

- 대소 비교(`<`, `>`)는 BigInt와 Number를 섞어도 되지만 덧셈 같은 산술은 TypeError입니다(MDN). 혼동을 피하려고 거리, 가중치, INF를 모두 BigInt로 통일합니다.
- 힙의 비교는 `a[0] < b[0]`처럼 불리언 비교로 쓰면 BigInt에서도 동작합니다. `a[0] - b[0]`의 BigInt 결과를 `sort` 비교 함수가 반환하면 TypeError입니다.
- 거리를 `mod`로 줄이는 방법은 쓰지 않습니다. 최단거리 값의 비교가 mod 값으로는 틀립니다. 모듈러는 경로의 개수를 셀 때만 씁니다(57편).
- 결과는 `String(dist[t])` 또는 문자열 합치기로 출력합니다. BigInt에 `JSON.stringify`를 쓰면 에러입니다.

**흔한 실수:** BigInt가 필요한 문제에서 Number로 풀어 앞쪽 몇 개 테스트만 통과하는 것입니다. 거리 상한을 먼저 계산해서 2^53을 넘을 가능성이 있으면 처음부터 BigInt로 설계합니다.

## 핵심 정리

- 같은 정점이라도 상태에 따라 앞날이 다르면 (정점, 상태)를 노드로 하는 확장 그래프에서 Dijkstra를 돌리고, 답은 도착 정점의 모든 상태 중 최솟값입니다.
- 집합 상태는 비트마스크(`mask × n + v`)로 인코딩하며 상태 수 2^K가 메모리와 시간의 한도를 정합니다.
- 가중치가 둘이면 범위가 작은 쪽을 상태로 올리고 다른 쪽을 `dist`로 최소화합니다.
- 정점 반복을 허용하는 K번째 최단거리는 정점마다 큐에서 K번까지 꺼내는 Dijkstra로 구하고, 정점 반복을 금지하면 Yen 알고리즘이 필요합니다.
- 경로가 없으면 `dist === Infinity`이고, 출력과 집계 전에 걸러냅니다. 거리 0은 정상 값입니다.
- INF는 거리 상한보다 크고 INF + INF가 안전 정수 이하여야 합니다. 거리 합이 2^53 - 1을 넘으면 BigInt로 통일해서 계산합니다.
