## 배열 생성

배열은 순서가 있는 값의 목록입니다. 만드는 방법은 다섯 가지입니다.

```js
const a = [1, 2, 3]                  // 배열 리터럴
const b = new Array(3)               // 길이 3, 빈 슬롯 3개
const c = Array.of(3)                // [3]
const d = Array.from({ length: 3 }, (_, i) => i) // 0 1 2
const e = new Array(3).fill(0)       // [0, 0, 0]
```

- 값을 알고 있으면 리터럴 `[ ]`을 씁니다.
- `new Array(n)`처럼 숫자 하나를 넘기면 그 숫자가 원소가 아니라 길이가 됩니다. `new Array(1, 2)`는 `[1, 2]`이고 `new Array(3)`은 길이 3의 빈 배열입니다. 원소 하나짜리 배열은 `Array.of(3)`이나 `[3]`입니다.
- 길이는 0 이상 2^32 − 1 이하의 정수여야 합니다. `Array(3.5)`나 `Array(-1)`은 RangeError입니다.
- 길이가 정해진 초기화 배열은 `Array(n).fill(값)`이나 `Array.from({ length: n }, 함수)`로 만듭니다(아래 각 절).
- 입력 문자열을 배열로 만드는 방법은 `split`, 이터러블을 배열로 바꾸는 방법은 `[...x]`나 `Array.from(x)`입니다(자세히는 06편).
- `Array.isArray(x)`로 배열인지 확인합니다. `typeof []`는 `'object'`입니다.

## 빈 슬롯이 있는 배열

`Array(n)`으로 만든 배열은 원소가 `undefined`로 채워진 것이 아니라 값이 없는 칸(빈 슬롯, hole)이 n개 있는 희소 배열(sparse array)입니다.

```js
const a = Array(3)     // [ <3 empty items> ]
a[0]                   // undefined (읽으면 undefined)
0 in a                 // false (칸 자체가 없음)
const b = [1, , 3]     // 리터럴에서도 만들어짐
```

빈 슬롯은 메서드마다 다르게 취급됩니다(MDN 기준).

| 취급 | 메서드 |
|------|--------|
| 콜백·검색에서 건너뜀 | `forEach`, `map`, `filter`, `reduce`, `some`, `every`, `indexOf` |
| 빈 슬롯을 유지한 채 처리 | `slice`, `splice`, `concat`, `reverse` |
| `undefined`로 취급 | `for...of`, 스프레드, `includes`, `join`, `find`, `keys`, `entries`, `Array.from` |

```js
Array(3).map((_, i) => i)      // 빈 슬롯 3개 그대로
[...Array(3)].map((_, i) => i) // [0, 1, 2]
Array.from({ length: 3 }, (_, i) => i) // [0, 1, 2]
```

- `Array(3).map(...)`은 콜백을 한 번도 실행하지 않습니다. 인덱스로 채우려면 `Array.from`이나 `[...Array(n)]`, `[...Array(n).keys()]`를 씁니다.
- `Array.from`은 빈 슬롯을 만들지 않고 `undefined`로 채웁니다.
- `fill`은 빈 슬롯도 채웁니다. `Array(3).fill(0)`은 `[0, 0, 0]`입니다.
- `join`은 빈 슬롯을 빈 문자열로 바꿔서 `Array(3).join('-')`은 `'--'`입니다.
- `[1, , 3]`과 `[1, undefined, 3]`은 출력에서 다르게 보이고(`<1 empty item>`) `1 in a`도 다릅니다. 코딩테스트에서는 빈 슬롯을 의도해서 만들 일이 없으므로, 초기화하지 않은 배열이 빈 슬롯이라는 점을 기억하고 항상 `fill`이나 `Array.from`으로 초기화합니다.

**흔한 실수:** `new Array(n).map(...)`으로 배열을 채우려는 것입니다. 빈 슬롯은 `map`이 건너뛰므로 원하는 값이 만들어지지 않습니다.

## 인덱스와 length

원소는 0부터 시작하는 인덱스로 접근합니다. `length`는 마지막 인덱스 + 1입니다.

```js
const a = [10, 20, 30]
a[0]            // 10
a[a.length - 1] // 30 (마지막)
a[3]            // undefined (범위 밖은 에러가 아님)
a[-1]           // undefined (음수는 원소가 아님)
```

- 범위 밖 인덱스를 읽으면 `undefined`가 나오고 에러는 나지 않습니다. 이 때문에 범위 검사를 빠뜨리면 오류 없이 `undefined`가 계산에 섞입니다(`NaN`으로 번짐).
- 인덱스는 내부적으로 문자열 키입니다. `a['1']`은 `a[1]`과 같습니다. `a[-1] = 7`은 원소가 아니라 `'-1'`이라는 일반 프로퍼티를 만들며 `length`는 그대로입니다.
- `length`에 대입하면 배열이 바뀝니다. 줄이면 뒤쪽 원소가 잘리고, 늘리면 빈 슬롯이 생깁니다.
- 현재 길이보다 큰 인덱스에 대입하면 `length`가 늘고 사이는 빈 슬롯이 됩니다.

```js
const a = [1, 2, 3]
a.length = 2          // [1, 2] (잘림)
a.length = 0          // [] (비우기)
const b = []
b[2] = 'x'            // [ <2 empty items>, 'x' ], length 3
```

- 배열을 비우는 가장 짧은 방법이 `a.length = 0`입니다. 같은 배열을 다른 곳에서 참조하고 있으면 그쪽도 비워집니다.
- `delete a[1]`은 원소를 지우지 않고 빈 슬롯을 만듭니다. `length`는 그대로이고 뒤 원소는 당겨지지 않습니다. 원소를 없애려면 `splice`를 씁니다.
- `length`와 인덱스 프로퍼티만 가진 유사 배열 객체는 `Array.from`으로 배열로 바꿔서 씁니다.

## 마지막 원소와 음수 인덱스: at

`a.at(i)`는 `i`가 음수이면 뒤에서부터 센 원소를 돌려줍니다. `at`은 ES2022에 추가되었습니다.

```js
const a = [1, 2, 3]
a.at(0)       // 1
a.at(-1)      // 3 (마지막)
a.at(-2)      // 2
a.at(5)       // undefined (범위 밖은 에러 없음)
a[-1]         // undefined (대괄호는 음수를 뒤에서 세지 않음)
```

- 음수 `i`는 `i + length` 위치와 같습니다. `-length`보다 작거나 `length` 이상이면 `undefined`입니다.
- ES2022 이전 환경이나 호환이 걱정되면 `a[a.length - 1]`로 씁니다. Node.js 24에서는 `at`을 그대로 쓸 수 있습니다.
- 문자열에도 `at`이 있어서 `'abc'.at(-1)`은 `'c'`입니다.
- 빈 배열의 `a.at(-1)`과 `a[a.length - 1]` 모두 `undefined`입니다. 스택의 맨 위 확인(`top`)에 `stack.at(-1)`을 자주 씁니다(자세히는 19편).

## 배열 순회

세 가지 방법이 기본입니다.

```js
const a = ['x', 'y', 'z']
for (let i = 0; i < a.length; i++) { /* a[i] */ }
for (const v of a) { /* v */ }
for (const [i, v] of a.entries()) { /* i, v */ }
```

- 인덱스가 필요하면 `for`, 값만 필요하면 `for...of`입니다(선택 기준은 03편).
- `forEach`, `map`, `filter` 등 고차 함수는 05편에서 다룹니다. `forEach`는 `break`할 수 없습니다.
- `for...in`은 키를 문자열로 돌려주고 상속된 열거 가능 프로퍼티까지 돌 수 있어서 배열에는 쓰지 않습니다.
- `for (let i = 0; i < a.length; i++)`에서 `a.length`는 매 회차 다시 읽힙니다. 반복 중에 `push`나 `splice`로 길이를 바꾸면 반복 횟수가 달라집니다.
- 역순 순회는 `for (let i = a.length - 1; i >= 0; i--)`입니다. 원본을 바꾸는 `reverse()` 후 순회하는 것보다 안전합니다.
- 빈 슬롯이 있으면 `for`는 `undefined`를 읽고, `forEach`는 건너뜁니다(앞 절 표).

## push와 pop

`push`는 끝에 원소를 추가하고, `pop`은 끝의 원소를 꺼냅니다. 둘 다 원본을 바꿉니다.

```js
const a = [1]
a.push(2, 3)   // 3 (반환값은 새 길이), a는 [1, 2, 3]
a.pop()        // 3 (반환값은 꺼낸 원소), a는 [1, 2]
[].pop()       // undefined (빈 배열)
```

- `push`는 여러 값을 한 번에 넣을 수 있고 반환값은 새 `length`입니다. `pop`의 반환값은 꺼낸 원소이고, 빈 배열이면 `undefined`이며 배열은 그대로입니다.
- 둘 다 배열 끝만 건드리므로 원소 수에 상관없이 일정한 비용입니다. 스택은 `push`와 `pop`으로 만듭니다(자세히는 19편).
- 다른 배열의 원소를 모두 추가할 때 `a.push(...b)`는 `b`가 매우 크면 인수 개수 한계로 RangeError가 납니다. MDN도 큰 배열에는 `concat`이나 반복 `push`를 권합니다(자세히는 01편).
- 반환값이 길이이므로 `const b = a.push(x)`로 새 배열을 얻는 것은 틀린 사용입니다. 새 배열이 필요하면 `[...a, x]`나 `a.concat(x)`입니다.
- 스택에서 비었는지 확인하지 않고 `pop()`하면 `undefined`가 나와서 오류 없이 값이 섞입니다. `stack.length`를 먼저 확인합니다.

## shift와 unshift

`shift`는 맨 앞의 원소를 꺼내고, `unshift`는 맨 앞에 원소를 추가합니다. 둘 다 원본을 바꿉니다.

```js
const a = [2, 3]
a.unshift(1)   // 3 (새 길이), a는 [1, 2, 3]
a.shift()      // 1 (꺼낸 원소), a는 [2, 3]
[].shift()     // undefined
```

- `shift`의 반환값은 꺼낸 원소(빈 배열이면 `undefined`), `unshift`의 반환값은 새 길이입니다.
- `unshift`에 여러 값을 한 번에 주면 준 순서 그대로 앞에 들어갑니다. `unshift(1, 2)`는 `[1, 2, ...]`이고, `unshift(1)` 뒤 `unshift(2)`는 `[2, 1, ...]`입니다.
- 앞쪽을 바꾸면 나머지 원소의 인덱스가 모두 한 칸씩 이동해야 해서 원소 수에 비례하는 비용으로 계산합니다. MDN도 `shift`가 남은 원소를 앞으로 당기며 재인덱싱한다고 설명합니다. 반복문 안에서 `shift`로 큐를 구현하면 전체가 N²이 될 수 있습니다(자세히는 14편, 20편).
- 큐가 필요하면 `shift` 대신 시작 위치를 가리키는 인덱스를 두고 앞으로 옮깁니다(자세히는 20편).

**흔한 실수:** 큐처럼 쓰려고 `while (q.length) { const x = q.shift() ... }`를 쓰는 것입니다. 입력이 수십만이면 시간 초과가 날 수 있습니다.

## slice와 splice

`slice`는 일부를 잘라 새 배열로 돌려주고 원본을 바꾸지 않습니다. `splice`는 원본을 직접 바꿔서 지우고, 넣고, 바꿉니다.

```js
const a = [0, 1, 2, 3, 4]
a.slice(1, 3)    // [1, 2] (끝 인덱스는 포함 안 함)
a.slice(-2)      // [3, 4] (뒤에서 2개)
a.slice()        // [0, 1, 2, 3, 4] (얕은 복사)
a.slice(3, 1)    // [] (끝이 시작보다 앞)
```

- `slice(start, end)`는 `start`부터 `end` 직전까지입니다. 음수는 뒤에서 센 위치이고, 범위를 벗어난 값은 알아서 맞춰집니다. 원본은 그대로입니다.
- `[start, end)`로 생각하면 결과의 길이가 `end - start`입니다.

`splice(start, deleteCount, ...items)`는 `start`부터 `deleteCount`개를 지우고 그 자리에 `items`를 넣으며, 지워진 원소의 배열을 돌려줍니다.

```js
const a = [0, 1, 2, 3, 4]
a.splice(1, 2)         // [1, 2] 반환, a는 [0, 3, 4]
a.splice(1, 0, 'x')    // [] 반환, a는 [0, 'x', 3, 4] (삽입)
a.splice(2, 1, 'y')    // [3] 반환, a는 [0, 'x', 'y', 4] (교체)
a.splice(-1)           // [4] 반환, a는 [0, 'x', 'y']
```

- `deleteCount`를 생략하면 `start`부터 끝까지 지웁니다. `0`이면 아무것도 지우지 않고 삽입만 합니다.
- `start`가 음수이면 뒤에서 센 위치입니다.
- `splice()`에 아무 인수도 안 주면 아무 일도 하지 않고 빈 배열을 돌려줍니다.
- 가운데에서 지우거나 넣으면 뒤쪽 원소가 모두 이동하므로 원소 수에 비례하는 비용입니다.
- 원본을 바꾸지 않는 `toSpliced`가 ES2023에 추가되었습니다. 이전 환경에서는 `slice`와 스프레드로 새 배열을 만듭니다(`[...a.slice(0, i), x, ...a.slice(i)]`).
- 반복하면서 `splice`로 지우면 뒤 원소가 앞으로 당겨져 다음 원소를 건너뜁니다. `[2, 2, 3]`에서 값이 2인 원소를 `for`로 지우면 `[2, 3]`이 남습니다. 지울 대상은 새 배열에 걸러 담거나 뒤에서부터 돕니다.

**흔한 실수:** `slice`와 `splice`를 혼동하는 것입니다. `slice`는 새 배열을 반환하고 원본을 바꾸지 않으며, `splice`는 원본을 바꿉니다. 이름이 비슷해서 틀리기 쉽습니다.

## includes와 indexOf

`indexOf(x)`는 `x`가 처음 나오는 인덱스를, 없으면 `-1`을 돌려줍니다. `includes(x)`는 있는지만 `true`·`false`로 돌려줍니다. 둘 다 앞에서부터 순서대로 찾으므로 원소 수에 비례하는 비용입니다.

```js
const a = [5, 6, 5]
a.indexOf(5)        // 0
a.indexOf(9)        // -1
a.indexOf(5, 1)     // 2 (인덱스 1부터 찾기)
a.lastIndexOf(5)    // 2 (뒤에서부터)
a.includes(6)       // true
```

- 두 번째 인수 `fromIndex`로 검색 시작 위치를 정합니다.
- 값이 있는지만 필요하면 `includes`, 위치가 필요하면 `indexOf`입니다. `indexOf`의 결과는 `!== -1`로 검사합니다. `if (a.indexOf(x))`는 인덱스 0을 놓칩니다.
- 비교 방식이 다릅니다. `indexOf`는 `===`이라 `NaN`을 찾지 못하고, `includes`는 SameValueZero라서 `NaN`을 찾습니다.

```js
[NaN].indexOf(NaN)   // -1
[NaN].includes(NaN)  // true
[1, 2].includes('2') // false (타입이 다름)
```

- 객체·배열 원소는 참조로 비교합니다. `[[1]].includes([1])`은 `false`입니다. 값으로 찾으려면 `some`이나 `find`를 씁니다(자세히는 05편).
- 빈 슬롯은 `includes(undefined)`가 `true`로 찾고, `indexOf(undefined)`는 `-1`입니다.
- 같은 배열에서 검색을 수없이 반복하면 `includes`의 비용이 쌓이므로 Set을 씁니다(자세히는 09편).

## reverse

`reverse()`는 원소 순서를 뒤집고 원본을 바꿉니다. 반환값은 새 배열이 아니라 같은 배열입니다.

```js
const a = [1, 2, 3]
const b = a.reverse()
b === a      // true (같은 배열)
a            // [3, 2, 1]
```

- 원본을 유지하려면 복사한 뒤 뒤집거나 `toReversed()`(ES2023)를 씁니다.

```js
const a = [1, 2, 3]
const r1 = [...a].reverse()   // [3, 2, 1], a는 그대로
const r2 = a.toReversed()     // [3, 2, 1], a는 그대로
```

- 문자열 뒤집기는 `[...s].reverse().join('')`입니다. 문자열에는 `reverse`가 없습니다(자세히는 07편).
- `const b = a.reverse()`로 사본을 얻었다고 착각하는 실수가 흔합니다. `a`도 같이 뒤집힙니다.
- 빈 슬롯은 뒤집힌 위치로 옮겨져 유지됩니다.

## concat

`concat`은 배열을 이어 붙인 새 배열을 돌려주고 원본을 바꾸지 않습니다.

```js
const a = [1, 2]
a.concat([3, 4])        // [1, 2, 3, 4]
a.concat(3, [4, [5]])   // [1, 2, 3, 4, [5]] (한 단계만 펼침)
a.concat()              // [1, 2] (복사)
a                       // [1, 2] (그대로)
```

- 인수가 배열이면 한 단계 펼쳐서 붙이고, 배열이 아닌 값은 그대로 하나의 원소로 붙입니다. 중첩된 안쪽 배열은 그대로 남습니다.
- 얕은 복사라서 객체 원소는 참조를 공유합니다.
- 두 배열을 합칠 때 `[...a, ...b]`와 같은 결과입니다. 합칠 대상이 이터러블인 문자열이면 두 방식이 달라집니다(자세히는 ECMAscript 과목의 스프레드 문법 편).
- 반복문 안에서 `acc = acc.concat(x)`로 계속 이어 붙이면 매번 전체를 복사해서 N²입니다. 누적할 때는 `push`를 씁니다.

## join

`join(sep)`은 원소를 문자열로 바꿔 `sep`로 이어 붙인 문자열을 돌려줍니다. `sep`를 생략하면 쉼표입니다.

```js
[1, 2, 3].join()       // '1,2,3'
[1, 2, 3].join('')     // '123'
[1, 2, 3].join(' ')    // '1 2 3'
['a'].join('-')        // 'a'
[].join('-')           // ''
```

- 원소가 하나이면 구분자가 붙지 않고, 빈 배열은 빈 문자열입니다.
- `undefined`, `null`, 빈 슬롯은 빈 문자열이 됩니다. `[1, null, 3].join('-')`은 `'1--3'`입니다.
- 중첩 배열은 안쪽을 `toString()`(쉼표 구분)으로 바꿉니다. `[[1, 2], [3]].join(';')`은 `'1,2;3'`입니다. 2차원 배열을 출력하려면 행마다 `join`한 뒤 다시 `join('\n')`합니다(자세히는 08편).
- 결과는 문자열이라서 `[1, 2, 3].join('') + 1`은 `'1231'`입니다. 숫자로 쓰려면 `Number()`로 바꿉니다.
- 출력할 값을 모아 `join('\n')`으로 한 번에 내보내면 출력 횟수를 줄일 수 있습니다(자세히는 08편).

## 배열 복사

대입(`b = a`)은 복사가 아니라 같은 배열을 가리키게 합니다. 복사본이 필요하면 새 배열을 만듭니다.

```js
const a = [1, 2, 3]
const b = a             // 같은 배열 (참조 공유)
const c = [...a]        // 새 배열
const d = a.slice()     // 새 배열
const e = Array.from(a) // 새 배열
const f = a.concat()    // 새 배열
b.push(4)               // a도 [1, 2, 3, 4]
c.push(5)               // a는 그대로
```

- 위 네 방법(`[...a]`, `slice()`, `Array.from`, `concat()`)은 모두 최상위 한 단계만 새로 만드는 얕은 복사입니다. 원소가 객체나 배열이면 안쪽은 공유합니다.
- 2차원 배열은 행마다 복사합니다: `grid.map((row) => [...row])`. `[...grid]`는 행을 공유합니다(자세히는 05편, 17편).
- 깊은 복사는 `structuredClone`입니다(자세히는 01편).
- 복사는 원소 수에 비례하는 비용입니다. 재귀나 반복 안에서 매번 복사하면 전체 비용이 크게 늘어납니다.
- 함수에 배열을 넘기면 참조가 전달됩니다. 함수 안에서 `push`, `sort`, `reverse`, `splice`로 바꾸면 호출한 쪽 배열도 바뀝니다.

원본을 바꾸는 메서드와 바꾸지 않는 메서드를 구분해 둡니다.

| 구분 | 메서드 |
|------|--------|
| 원본을 바꿈 | `push`, `pop`, `shift`, `unshift`, `splice`, `reverse`, `sort`, `fill`, `length` 대입 |
| 새 배열·값을 반환 | `slice`, `concat`, `map`, `filter`, `join`, `indexOf`, `includes`, `at` |
| ES2023 복사본 반환형 | `toReversed`, `toSorted`, `toSpliced`, `with` (자세히는 05편) |

## Array.from

`Array.from(items, mapFn)`은 이터러블이나 유사 배열 객체(`length`와 인덱스를 가진 객체)로 새 배열을 만듭니다. 두 번째 인수 `mapFn`은 `(값, 인덱스)`를 받는 변환 함수입니다.

```js
Array.from('abc')                    // ['a', 'b', 'c']
Array.from(new Set([1, 1, 2]))       // [1, 2]
Array.from({ length: 3 })   // undefined가 3개
Array.from({ length: 3 }, (_, i) => i * i)  // [0, 1, 4]
Array.from([1, 2, 3], (x) => x * 2)  // [2, 4, 6]
```

- `Array.from({ length: n }, 함수)`는 길이 n의 배열을 함수가 만든 값으로 초기화하는 표준 패턴입니다. 빈 슬롯이 아니라 실제 값이 들어갑니다.
- 칸마다 함수가 새로 실행되므로, 칸마다 독립된 배열이 필요한 2차원 배열 초기화에 맞습니다.

```js
const grid = Array.from(
  { length: 3 }, () => Array(3).fill(0),
)
grid[0][0] = 1
grid[1][0]   // 0 (행이 서로 독립)
```

- 이터러블(문자열, Set, Map, 제너레이터)은 `[...x]`와 같은 결과이고, `Array.from`은 유사 배열도 받으며 변환 함수를 넣을 수 있다는 점이 다릅니다.
- 문자열은 코드 포인트 단위로 쪼개져 `Array.from('😀a')`는 두 원소입니다.
- 변환 함수 없이 `Array.from(x).map(f)`로 쓰면 중간 배열이 하나 더 생기므로 변환은 두 번째 인수로 넘기는 편이 낫습니다.
- 인덱스 배열이 필요하면 `Array.from({ length: n }, (_, i) => i)` 또는 `[...Array(n).keys()]`입니다.

## Array.fill

`a.fill(value, start, end)`는 `start`부터 `end` 직전까지를 `value`로 채우고, 원본을 바꾸며 같은 배열을 돌려줍니다. `start`와 `end`를 생략하면 전체입니다.

```js
Array(3).fill(0)         // [0, 0, 0]
[1, 2, 3, 4].fill(0, 1, 3)  // [1, 0, 0, 4]
[1, 2, 3].fill(9, -1)    // [1, 2, 9] (음수는 뒤에서)
new Array(5).fill(Infinity)  // 거리 배열 초기화
```

- 빈 슬롯도 채우므로 `Array(n).fill(값)`이 길이 n의 초기화 배열을 만드는 가장 짧은 방법입니다.
- `fill`에 객체나 배열을 넘기면 모든 칸이 같은 객체 하나를 가리킵니다.

```js
const bad = Array(3).fill([])
bad[0].push(1)   // [[1], [1], [1]] (세 칸이 같은 배열)
const ok = Array.from({ length: 3 }, () => [])
ok[0].push(1)    // [[1], [], []]
```

- 원시 값(숫자, 문자열, 불리언, `null`)으로 채울 때만 안전합니다. 2차원 배열 초기화에서 `Array(n).fill(Array(m).fill(0))`이 행을 공유하는 대표적인 함정입니다(자세히는 05편).
- 길이가 큰 배열을 만들 때 `fill`은 `new Array(n)`과 함께 쓰는 것이 일반적입니다. `new Array(n)`의 n이 크면(2^32 이상) RangeError입니다.

## 핵심 정리

- `Array(n)`은 값이 `undefined`인 칸이 아니라 빈 슬롯 n개이며 `map`이 건너뛰므로, `fill`이나 `Array.from({ length: n }, 함수)`로 초기화합니다.
- 범위 밖 인덱스 읽기는 `undefined`이고 에러가 아닙니다. `at(-1)`(ES2022)은 뒤에서 센 원소를 돌려주고 `a[-1]`은 `undefined`입니다.
- `push`와 `pop`은 끝만 바꾸고, `shift`와 `unshift`는 앞쪽을 바꾸어 모든 원소를 옮기므로 큐로 쓰지 않습니다.
- `slice`는 원본을 바꾸지 않고 `splice`와 `reverse`는 원본을 바꾸며, `reverse`의 반환값은 같은 배열입니다.
- `indexOf`는 `NaN`을 찾지 못하고 `-1`을 반환하며, `includes`는 `NaN`을 찾습니다. 객체는 참조로 비교합니다.
- `[...a]`, `slice()`, `Array.from`, `concat()`은 모두 얕은 복사이고, `fill`에 배열을 넘기면 모든 칸이 같은 배열을 공유합니다.
