## Cycle Detection (방향 그래프)

방향 그래프에서 사이클(cycle)은 한 정점에서 출발해 간선 방향을 따라 다시 그 정점으로 돌아오는 경로입니다. 사이클이 없는 방향 그래프는 DAG입니다. 방향 그래프의 사이클은 DFS 중에 **지금 탐색 중인 정점으로 되돌아오는 간선**으로 찾습니다.

정점마다 세 가지 상태를 둡니다.

| 상태 | 값 | 뜻 |
|------|----|----|
| 미방문(white) | 0 | 아직 닿지 않음 |
| 탐색 중(gray) | 1 | 지금 재귀 스택 위에 있음 |
| 완료(black) | 2 | 이 정점에서 갈 수 있는 곳을 모두 확인함 |

탐색 중인 정점으로 가는 간선은 자기 조상으로 되돌아가는 간선이라서 사이클이 됩니다. 완료된 정점으로 가는 간선은 사이클이 아닙니다. 완료된 정점에서는 현재 정점으로 돌아올 수 없다는 것을 이미 확인했기 때문입니다.

```js
function hasCycle(n, adj) {
  const color = new Array(n).fill(0)
  function dfs(u) {
    color[u] = 1
    for (const v of adj[u]) {
      if (color[v] === 1) return true
      if (color[v] === 0 && dfs(v)) return true
    }
    color[u] = 2
    return false
  }
  for (let s = 0; s < n; s++)
    if (color[s] === 0 && dfs(s)) return true
  return false
}
```

- `0→1`, `1→2`, `2→0`이면 `dfs(0)`이 `1`, `2`를 거쳐 `2→0`에서 `color[0] === 1`을 만나 `true`입니다.
- `0→1`, `1→2`, `0→2`이면 `2`가 완료된 뒤 `0→2`를 볼 때 `color[2] === 2`라서 사이클이 아닙니다. 방문했다는 사실만으로 사이클이라 하면 이 경우를 틀립니다.
- 자기 자신으로 가는 간선(`u→u`)은 `color[u] === 1`이므로 사이클로 잡힙니다.
- 시작 정점을 모든 정점으로 돌려야 합니다. 한 정점에서 닿지 않는 사이클이 있을 수 있습니다.
- 시간복잡도는 O(V + E)입니다.

정점이 많을 때의 반복 버전입니다. 스택에 정점을 쌓고 `idx[u]`로 다음에 볼 간선 위치를 기억합니다. 간선을 모두 본 정점은 완료로 바꾸고 스택에서 뺍니다.

```js
function dfsIter(s, adj, color, idx) {
  const st = [s]
  color[s] = 1
  while (st.length > 0) {
    const u = st[st.length - 1]
    if (idx[u] === adj[u].length) { color[u] = 2; st.pop() }
    else {
      const v = adj[u][idx[u]++]
      if (color[v] === 1) return true
      if (color[v] === 0) { color[v] = 1; st.push(v) }
    }
  }
  return false
}
```

바깥에서는 정점마다 이 함수를 부릅니다. `color`와 `idx`는 모든 시작 정점이 공유하는 배열입니다.

```js
const color = new Array(n).fill(0)
const idx = new Array(n).fill(0)
let found = false
for (let s = 0; s < n && !found; s++) {
  if (color[s] === 0) found = dfsIter(s, adj, color, idx)
}
```

위상 정렬(53편)에서 진입 차수가 0인 정점부터 지울 때 정점이 남으면 사이클이 있다는 것을 이용해도 판정할 수 있습니다.

**문제의 단서:** 작업의 선후 관계에 순환이 있는지, 상태 전이가 무한히 돌 수 있는지, 서로 의존하는 모듈이 있는지를 묻습니다.

**흔한 실수:**

- 방문 여부(`true`/`false`) 하나로만 사이클을 판단하는 것입니다. 방향 그래프에서는 완료된 정점으로 가는 간선이 사이클이 아니라서 세 상태가 필요합니다.
- 재귀가 끝날 때 `color[u] = 2`로 바꾸는 것을 빼먹는 것입니다. 탐색 중 상태가 남아서 사이클이 없는데도 `true`가 나옵니다.

## Cycle Detection (무방향 그래프)

무방향 그래프에서는 방문한 정점을 다시 만났을 때, 그것이 **방금 내가 온 간선**이 아니면 사이클입니다. 무방향 간선은 양쪽 인접 리스트에 모두 들어 있어서 `u→v`로 내려간 뒤 `v`에서 `u`를 다시 보는데, 이것은 사이클이 아닙니다. 그래서 부모로 돌아가는 그 간선 하나만 건너뜁니다.

색 세 가지는 필요 없고 방문 여부만 있으면 됩니다. 무방향 그래프에서는 완료된 정점을 다시 만나는 일이 DFS 트리에서 조상이나 자손으로 이어진 간선뿐이기 때문입니다.

정점이 아니라 **간선 번호**로 부모 간선을 건너뛰면 같은 두 정점 사이의 중복 간선(다중 간선)도 사이클로 잡습니다. 인접 리스트에 `[이웃, 간선 번호]` 쌍을 담습니다.

```js
const adj = Array.from({ length: n }, () => [])
edges.forEach(([u, v], id) => {
  adj[u].push([v, id])
  adj[v].push([u, id])
})
```

```js
function hasCycleUndirected(n, adj) {
  const seen = new Array(n).fill(false)
  function dfs(u, parentEdge) {
    seen[u] = true
    for (const [v, id] of adj[u]) {
      if (id === parentEdge) continue
      if (seen[v] || dfs(v, id)) return true
    }
    return false
  }
  for (let s = 0; s < n; s++)
    if (!seen[s] && dfs(s, -1)) return true
  return false
}
```

- `[[0,1],[1,2],[2,0]]`은 `true`, `[[0,1],[1,2],[1,3]]`은 `false`입니다.
- `[[0,1],[0,1]]`처럼 같은 간선이 두 번 있으면 `true`입니다. 문제가 다중 간선이 없다고 보장하면 부모 정점을 `parent`로 넘겨 `v === parent`일 때 건너뛰어도 됩니다.
- 자기 자신으로 가는 간선(`0→0`)은 `seen[0]`이 이미 `true`라서 `true`입니다.

간선 수만으로도 판정합니다. 연결 요소가 C개인 무방향 그래프에서 사이클이 없는 것(포레스트)은 **간선 수 E가 V − C일 때**뿐입니다. E가 V − C보다 크면 사이클이 있습니다. 연결 요소 수는 DFS를 시작한 횟수로 셉니다(자세히는 36편). 사이클이 있는지만 알면 되고 서로소 집합이 이미 준비돼 있다면 Union-Find(51편)로 간선을 하나씩 합치며, 이미 같은 집합인 두 정점을 잇는 간선이 나오는 순간을 사이클로 보는 방법이 더 짧습니다.

**흔한 실수:**

- 부모 정점을 건너뛰지 않아서 간선 하나만 있어도 `true`가 되는 것입니다.
- 방향 그래프의 세 상태 방식을 무방향에 그대로 쓰는 것입니다. 간선 `0-1`에서 `1`이 `0`을 탐색 중으로 보고 사이클이라 판정합니다.

## Graph Coloring

그래프 색칠(graph coloring)은 이웃한 두 정점이 서로 다른 색이 되도록 정점마다 색을 하나씩 정하는 문제입니다. 색이 k개 이하이면 k-색칠이 가능하다고 하고, 가능한 최소 색 수를 색칠수(chromatic number)라고 합니다. 한 정점에 인접한 정점이 이미 칠한 색만 피하면 되므로 DFS나 백트래킹(23편)이 자연스럽게 맞습니다.

| 색 수 | 판별 난이도 |
|-------|-------------|
| 1색 | 간선이 하나도 없으면 가능 |
| 2색 | 이분 그래프 판별과 같고 선형 시간에 풀림 |
| 3색 이상 | 일반 그래프에서는 NP-완전. 정점이 적을 때 백트래킹으로 풂 |

- 차수(이웃 수)가 가장 큰 정점의 차수를 Δ라고 하면, 정점을 차례로 보며 이웃이 쓰지 않은 가장 작은 색을 붙이는 탐욕 색칠은 항상 Δ + 1색 이하로 끝납니다. 이웃이 최대 Δ개이므로 쓸 수 없는 색이 Δ개를 넘지 않기 때문입니다.
- 평면에 그려지는 그래프(지도)는 4색이면 충분합니다(4색 정리).
- 탐욕 색칠이 최소 색 수를 보장하지는 않습니다. 정점을 보는 순서에 따라 결과가 달라집니다.

```js
function greedyColor(n, adj) {
  const color = new Array(n).fill(-1)
  for (let u = 0; u < n; u++) {
    const used = new Set()
    for (const v of adj[u])
      if (color[v] >= 0) used.add(color[v])
    let c = 0
    while (used.has(c)) c++
    color[u] = c
  }
  return color
}
// 간선 0-1, 1-2, 2-0, 2-3 → [0, 1, 2, 0]
```

**문제의 단서:** "인접한 것끼리 서로 다른 그룹·색·시간대에 넣어야 한다", "충돌하는 쌍이 주어진다"가 나오면 그래프 색칠로 모델링합니다. 그룹이 둘이면 이분 그래프 판별이고, 셋 이상이면 N이 작아야 정답이 되는 완전탐색 문제입니다.

## 이분 그래프 판별

이분 그래프(bipartite graph)는 정점을 두 집합으로 나눠서 모든 간선이 서로 다른 집합의 정점을 잇는 그래프입니다. 같은 말로 2색 칠하기가 가능한 그래프입니다. 간선이 같은 집합 안에 있는 일이 없습니다.

판별은 DFS로 정점에 색(0 또는 1)을 칠하며 합니다. 정점의 이웃에는 반대 색을 칠하고, 이미 칠해진 이웃이 같은 색이면 이분 그래프가 아닙니다.

```js
function isBipartite(n, adj) {
  const color = new Array(n).fill(-1)
  function dfs(u, c) {
    color[u] = c
    for (const v of adj[u]) {
      if (color[v] === -1) {
        if (!dfs(v, 1 - c)) return false
      } else if (color[v] === c) return false
    }
    return true
  }
  for (let s = 0; s < n; s++)
    if (color[s] === -1 && !dfs(s, 0)) return false
  return true
}
```

작은 입력으로 추적합니다. 사각형 `0-1-2-3-0`과 삼각형 `0-1-2-0`을 비교합니다.

| 그래프 | 칠하는 과정 | 결과 |
|--------|-------------|------|
| 사각형 | 0은 0, 1은 1, 2는 0, 3은 1. 3의 이웃 0은 0이고 3은 1이라 충돌 없음 | 이분 |
| 삼각형 | 0은 0, 1은 1, 2는 0. 2의 이웃 0이 이미 0이라 같은 색 | 이분 아님 |

- 이분 그래프의 필요충분조건은 **길이가 홀수인 사이클이 없는 것**입니다. 삼각형은 길이 3의 홀수 사이클이라 실패하고, 사각형은 짝수 사이클이라 통과합니다. 트리는 사이클이 없으므로 항상 이분 그래프입니다.
- 그래프가 여러 덩어리로 나뉘어 있으면 덩어리마다 따로 칠해야 합니다. 바깥 `for` 루프가 그 일을 합니다. 덩어리마다 시작 색은 아무거나 괜찮습니다.
- 자기 자신으로 가는 간선은 `color[u] === c`이므로 이분 그래프가 아닙니다.
- 시간복잡도는 O(V + E)입니다. BFS로 같은 색칠을 해도 결과는 같습니다(자세히는 38편).
- 이분 그래프임을 알면 이분 매칭(71편)을 쓸 수 있습니다.

**문제의 단서:** 사람들을 두 팀으로 나누되 싫어하는 쌍은 같은 팀에 두지 않기, 서로 대립하는 쌍이 주어지는 문제, 두 종류가 번갈아 이어지는 구조입니다.

**흔한 실수:** 연결 요소가 여러 개일 때 정점 0에서만 시작해서 나머지 덩어리를 검사하지 않는 것입니다.

## Functional Graph

Functional graph는 **모든 정점에서 나가는 간선이 정확히 하나**인 방향 그래프입니다. 배열 `next[i]`(정점 `i`가 가리키는 정점)로 표현하고, 함수 `f(i) = next[i]`를 반복 적용하는 상황과 같습니다.

구조는 항상 같은 모양입니다. 어느 정점에서 출발해도 간선을 따라가면 결국 어떤 사이클에 닿고, 각 연결 덩어리에는 사이클이 정확히 하나 있으며 나머지 정점은 그 사이클로 흘러드는 나무 모양입니다.

```text
next = [1, 2, 3, 1, 5, 4, 6]
0 → 1 → 2 → 3 → 1   (사이클 1,2,3 / 0은 꼬리)
4 ⇄ 5               (사이클 4,5)
6 → 6               (자기 자신, 길이 1 사이클)
```

- 정점 수와 간선 수가 같습니다(N개 정점, N개 간선).
- 사이클 길이 1(자기 자신을 가리킴)도 사이클입니다.
- 사이클에 속한 정점만 "다시 돌아오는" 정점입니다. 꼬리의 정점은 사이클에 들어간 뒤 나오지 못합니다.

사이클들을 모두 찾는 코드입니다. 정점 `s`에서 출발해 상태가 0인 동안 따라가고, 만난 정점이 이번 경로에서 방문 중(상태 1)이면 새 사이클을 발견한 것입니다. 경로를 모두 완료(상태 2)로 바꾸면 각 정점을 한 번씩만 처리합니다. 시간복잡도는 O(N)입니다.

```js
function cycleFrom(u, next) {
  const cyc = [u]
  for (let v = next[u]; v !== u; v = next[v])
    cyc.push(v)
  return cyc
}
```

```js
function findCycles(next) {
  const state = new Array(next.length).fill(0)
  const cycles = []
  for (let s = 0; s < next.length; s++) {
    let u = s
    while (state[u] === 0) { state[u] = 1; u = next[u] }
    if (state[u] === 1) cycles.push(cycleFrom(u, next))
    for (let v = s; state[v] === 1; v = next[v])
      state[v] = 2
  }
  return cycles
}
// [1,2,3,1,5,4,6] → [[1,2,3],[4,5],[6]]
```

- `state[u] === 1`이면 이번 출발에서 다시 만난 것이므로 사이클이고, `state[u] === 2`이면 앞선 출발에서 이미 처리한 경로에 합류한 것이라 새 사이클이 없습니다.
- 재귀를 쓰지 않아서 N이 커도 호출 스택이 넘치지 않습니다.
- 한 정점에서 K번 이동한 위치는 K가 크면 사이클 안에서 돌기 때문에 `K - (꼬리 길이)`를 사이클 길이로 나눈 나머지로 구합니다. K가 아주 크면 이진 점프(66편)를 씁니다.

**문제의 단서:** "각자 다른 한 명을 지목한다", "i번 칸에 적힌 번호로 이동한다", "함수를 반복 적용한다"처럼 정점마다 다음 위치가 하나로 정해지면 functional graph입니다.

**흔한 실수:** 사이클이 아닌 꼬리의 정점까지 사이클에 넣는 것입니다. 사이클은 다시 만난 정점 `u`에서 `u`로 돌아올 때까지 따라간 정점만입니다.

## Transitive Closure 개념

전이적 폐쇄(transitive closure)는 정점 쌍 `(a, b)`마다 `a`에서 `b`로 가는 경로가 있는지를 모두 모아 둔 결과입니다. 간선이 `a→b`, `b→c`이면 `a→c`도 닿으므로 전이적으로 간선을 채우는 것입니다. 보통 `reach[a][b]`를 불리언 2차원 배열로 저장하고, 한 번 만들면 "a에서 b로 갈 수 있는가"를 O(1)에 답합니다.

DFS로 만들려면 모든 정점을 시작점으로 DFS를 한 번씩 돌립니다. 아래 코드는 자기 자신도 도달 가능(`reach[s][s]`가 `true`)으로 둡니다.

```js
function closure(n, adj) {
  const row = () => new Array(n).fill(false)
  const reach = Array.from({ length: n }, row)
  for (let s = 0; s < n; s++) {
    const st = [s]
    reach[s][s] = true
    while (st.length > 0) {
      const u = st.pop()
      for (const v of adj[u])
        if (!reach[s][v]) { reach[s][v] = true; st.push(v) }
    }
  }
  return reach
}
// 간선 0→1, 1→2 이면 reach[0][2]는 true, reach[2][0]은 false
```

- 시간복잡도는 O(V × (V + E)), 공간은 O(V²)입니다. 정점이 수백 개 이하일 때 씁니다.
- Floyd-Warshall 방식으로도 만들 수 있고 O(V³)입니다(자세히는 49편). 그래프가 촘촘하고 V가 작으면 코드가 더 짧습니다.
- 사이클이 있으면 사이클 안의 모든 정점이 서로 도달 가능입니다. 이런 덩어리를 SCC로 묶으면 그래프가 DAG로 줄어듭니다(자세히는 68편).
- 질의가 많고 정점이 많으면 쌍을 전부 저장하지 못합니다. 그때는 질의마다 탐색하거나 SCC를 이용합니다.

**문제의 단서:** "A가 B보다 크다는 관계들이 주어질 때 비교 가능한 쌍", "누가 누구에게 영향을 줄 수 있는가", 정점 수가 작은 도달 가능성 질의입니다.

## 트리 판별

트리(tree)는 사이클이 없는 연결된 무방향 그래프입니다. 정점이 N개인 트리는 간선이 정확히 N − 1개입니다. 이 사실로 판별은 두 조건으로 줄어듭니다.

- 간선 수가 N − 1이다.
- 한 정점에서 DFS를 했을 때 N개 정점을 모두 방문한다(연결되어 있다).

두 조건 중 하나만으로는 부족합니다. 간선이 N − 1개여도 연결 안 된 덩어리에 사이클이 숨어 있을 수 있고, 연결돼 있어도 간선이 많으면 사이클이 있습니다. 간선이 N − 1개이면서 연결이면 사이클이 없다는 것이 증명되므로 사이클 탐지를 따로 하지 않습니다.

```js
function isTree(n, m, adj) {   // m은 간선 수
  if (m !== n - 1) return false
  const seen = new Array(n).fill(false)
  const st = [0]
  seen[0] = true
  let cnt = 1
  while (st.length > 0) {
    const u = st.pop()
    for (const v of adj[u])
      if (!seen[v]) { seen[v] = true; cnt++; st.push(v) }
  }
  return cnt === n
}
```

`adj`는 양쪽 방향으로 담은 인접 리스트입니다.

- 간선 `[[0,1],[1,2],[1,3]]`(N = 4)은 `true`입니다.
- 간선 `[[0,1],[1,2],[2,0]]`(N = 4)은 간선이 3개라 N − 1과 같지만 정점 3에 닿지 않아 `cnt`가 3이므로 `false`입니다.
- 정점이 하나(`n = 1`)이고 간선이 없으면 `true`입니다.

방향 그래프에서 루트가 있는 트리(루트 트리)는 조건이 다릅니다. 진입 차수가 0인 정점이 정확히 하나(루트)이고, 나머지 정점의 진입 차수는 모두 1이며, 루트에서 모든 정점에 닿아야 합니다.

**흔한 실수:** 간선 수만 확인하고 연결성을 확인하지 않는 것입니다. 숲(트리 여러 개)에도 간선 수가 N − C로 N − 1보다 작아서 걸러지지만, 사이클을 가진 덩어리와 고립된 정점이 섞이면 N − 1개가 될 수 있습니다.

## 역방향 그래프

역방향 그래프(reversed graph)는 모든 간선의 방향을 뒤집은 그래프입니다. 원래 그래프에 `u→v`가 있으면 역방향 그래프에는 `v→u`가 있습니다.

```js
const radj = Array.from({ length: n }, () => [])
for (const [u, v] of edges) {
  adj[u].push(v)
  radj[v].push(u)   // 방향만 뒤집어 저장
}
```

DFS는 나가는 간선만 따라가므로 "어디로 갈 수 있는가"는 쉬워도 "어디서 올 수 있는가"는 어렵습니다. 역방향 그래프에서 DFS를 하면 그 답이 나옵니다.

- 정점 `t`에 도달할 수 있는 모든 정점은 `t`에서 `radj`로 DFS해서 방문한 정점들입니다. 모든 정점마다 `t`까지 탐색하면 O(V × (V + E))이지만 역방향으로 한 번만 하면 O(V + E)입니다.
- 정점 `s`가 모든 정점과 서로 오갈 수 있는지(강한 연결인지)는 `adj`에서 `s`로부터 모든 정점에 닿고, `radj`에서도 `s`로부터 모든 정점에 닿는지 확인하면 됩니다. 두 번의 DFS입니다.
- 도착점이 정해진 문제(모든 길이 도착점으로 모이는 문제)는 도착점에서 역방향으로 시작하는 쪽이 단순합니다.
- 간선 방향의 의미를 바꾸는 방식이라 가중치가 있으면 가중치도 그대로 가져갑니다.
- SCC를 구하는 알고리즘(68편)도 역방향 그래프를 사용합니다.

**문제의 단서:** "목적지로 갈 수 있는 출발지는 몇 개인가", "이 정점을 지나야만 닿는 곳", 여러 출발점과 하나의 도착점이 주어지는 경우입니다.

## 순열 사이클 분해

순열(permutation)은 0부터 N − 1까지의 수를 한 번씩 쓴 배열입니다. 순열 `p`를 `i → p[i]`로 이은 그래프는 functional graph이면서 **모든 정점의 진입 차수도 1**입니다. 그래서 꼬리가 없고 모든 정점이 어떤 사이클에 속하며, 사이클끼리는 겹치지 않습니다. 순열 사이클 분해(cycle decomposition)는 이 사이클들을 모두 구하는 일입니다.

```js
function decompose(p) {
  const seen = new Array(p.length).fill(false)
  const cycles = []
  for (let i = 0; i < p.length; i++) {
    if (seen[i]) continue
    const cyc = []
    for (let j = i; !seen[j]; j = p[j]) {
      seen[j] = true
      cyc.push(j)
    }
    cycles.push(cyc)
  }
  return cycles
}
// [1, 2, 0, 4, 3] → [[0, 1, 2], [3, 4]]
```

- 시간복잡도는 O(N)입니다. 각 정점이 한 번만 방문됩니다.
- 순열을 정렬된 상태(`p[i] === i`)로 만드는 **최소 교환 횟수는 N − (사이클 수)** 입니다. 길이 L인 사이클은 L − 1번 교환으로 풀리고, 길이 1 사이클은 이미 제자리입니다. `[1, 2, 0, 4, 3]`은 5 − 2 = 3번입니다.
- 순열을 K번 적용한 결과는 사이클마다 독립입니다. 길이 L인 사이클에서 K번 이동한 위치는 `K % L`칸 이동한 위치입니다.
- 순열을 몇 번 반복하면 처음으로 돌아오는지는 사이클 길이들의 최소공배수입니다(자세히는 12편).
- 입력이 1부터 시작하는 순열이면 인덱스를 하나 줄여서 0부터 시작하는 순열로 바꿔 씁니다.

**문제의 단서:** "원소를 맞바꿔 정렬할 때 최소 횟수", "카드를 섞은 뒤 K번 반복한 위치", "자리를 바꾸는 규칙이 주어졌을 때 원래대로 돌아오는 횟수"입니다.

**흔한 실수:** 순열이 아닌데 사이클 분해를 쓰는 것입니다. 값이 중복돼 진입 차수가 2인 정점이 있으면 `seen` 방식의 순회가 꼬리를 사이클로 오인하거나 건너뜁니다. 그때는 functional graph 방식을 씁니다.

## 핵심 정리

- 방향 그래프의 사이클은 DFS에서 탐색 중(gray)인 정점으로 되돌아오는 간선이고, 완료된 정점으로 가는 간선은 사이클이 아닙니다.
- 무방향 그래프의 사이클은 방문한 정점을 만났을 때, 방금 온 간선이 아니면 성립합니다. 간선 수가 V − C를 넘어도 사이클입니다.
- 이분 그래프는 DFS로 이웃에 반대 색을 칠해서 판별하며, 홀수 길이 사이클이 없다는 것과 같습니다. 3색 이상 색칠은 일반적으로 어려워서 정점이 적을 때 백트래킹을 씁니다.
- 정점마다 나가는 간선이 하나인 functional graph는 덩어리마다 사이클이 정확히 하나이고, 순열은 모든 정점이 사이클에 속하며 최소 교환 횟수는 N − 사이클 수입니다.
- 도달 가능성은 정점마다 DFS를 하면 O(V × (V + E))에 구하고, 어디서 올 수 있는지는 역방향 그래프로 한 번에 구합니다.
- 트리는 간선 수가 N − 1이고 연결된 무방향 그래프입니다.
