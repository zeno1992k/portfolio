## 템플릿 약속

- 모든 템플릿은 Node.js 24에서 실행해 동작을 확인한 코드입니다. 무작위 입력을 단순한 구현과 대조한 것이 많습니다.
- 노드 번호는 1부터이고 `n`은 노드 수입니다. 0부터이면 배열 크기를 `n`으로 바꿉니다.
- `adj[u]`는 `u`에서 갈 수 있는 노드의 목록입니다. 가중치가 있으면 `[도착, 가중치]` 쌍을 담습니다.
- 힙은 82편의 `heapPush`·`heapPop`을 그대로 씁니다.
- 원리와 변형은 각 알고리즘 편에서 다룹니다.

```js
const adj = Array.from({ length: n + 1 }, () => [])
for (const [a, b] of edges) {
  adj[a].push(b)   // 간선 a → b
  adj[b].push(a)   // 무방향이면 반대 방향도
}
```

## DFS 템플릿

한 갈래를 끝까지 파고든 뒤 돌아와 다음 갈래를 보는 탐색입니다(자세히는 36편). 방문 배열은 노드마다 한 칸입니다.

```js
const visited = new Uint8Array(n + 1)
function dfs(u) {
  visited[u] = 1
  for (const v of adj[u]) {
    if (!visited[v]) dfs(v)
  }
}
dfs(1)
```

- 방문 표시는 호출에 들어오자마자 합니다. 나중에 하면 같은 노드를 여러 번 들어갑니다.
- 재귀 DFS는 일직선 그래프에서 깊이가 노드 수와 같아집니다. Node.js 24에서 인자 없는 단순한 함수가 약 12,500번째 호출에서 `RangeError`가 났습니다(실측, 환경과 함수에 따라 다릅니다). 노드가 수만 개이면 반복문으로 바꿉니다(자세히는 86편).

호출 스택 대신 직접 스택을 쓰는 반복 DFS입니다. 노드마다 다음에 볼 이웃의 위치를 기억해서 재귀와 같은 방문 순서가 나옵니다.

```js
const visited = new Uint8Array(n + 1)
const next = new Int32Array(n + 1)
const stack = [1]
visited[1] = 1
while (stack.length) {
  const u = stack[stack.length - 1]
  if (next[u] === adj[u].length) { stack.pop(); continue }
  const v = adj[u][next[u]++]
  if (visited[v]) continue
  visited[v] = 1
  stack.push(v)
}
```

- 이웃을 한꺼번에 스택에 넣는 간단한 방식은 방문 순서가 재귀와 다릅니다. 순서가 상관없는 연결 요소·도달 가능성 문제에는 그 방식으로 충분합니다.
- 노드를 처음 방문하는 시점이 `visited[v] = 1` 다음 줄입니다. 진입 순서를 기록하려면 거기서 `order.push(v)` 합니다. 종료 시점은 `stack.pop()` 자리입니다.

## BFS 템플릿

시작점에서 가까운 노드부터 층별로 방문하는 탐색으로, 가중치 없는 그래프의 최단 거리를 구합니다(자세히는 38편). 큐는 `shift` 대신 head 인덱스를 씁니다.

```js
const dist = new Int32Array(n + 1).fill(-1)
const queue = [start]
dist[start] = 0
for (let head = 0; head < queue.length; head++) {
  const u = queue[head]
  for (const v of adj[u]) {
    if (dist[v] !== -1) continue
    dist[v] = dist[u] + 1
    queue.push(v)
  }
}
```

- `dist[v] === -1`이 방문 여부를 겸합니다. 도달하지 못한 노드는 `-1`로 남습니다.
- 큐에 넣는 시점에 거리를 정하고 방문 처리를 합니다. 꺼낼 때 처리하면 같은 노드가 여러 번 들어갑니다.
- 가중치가 모두 같을 때만 최단 거리입니다. 가중치가 다르면 다익스트라입니다.

격자 BFS는 좌표를 `r * C + c` 정수 하나로 합쳐 큐에 담습니다(자세히는 17편). 벽은 `'#'`, 빈 칸은 `'.'`인 문자열 배열 `grid`를 가정합니다.

```js
const DR = [-1, 1, 0, 0]
const DC = [0, 0, -1, 1]
const dist = new Int32Array(R * C).fill(-1)
const queue = [sr * C + sc]
dist[sr * C + sc] = 0
```

```js
for (let head = 0; head < queue.length; head++) {
  const cur = queue[head]
  const r = Math.floor(cur / C)
  const c = cur % C
  for (let d = 0; d < 4; d++) {
    const nr = r + DR[d], nc = c + DC[d]
    if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue
    const next = nr * C + nc
    if (grid[nr][nc] === '#' || dist[next] !== -1) continue
    dist[next] = dist[cur] + 1
    queue.push(next)
  }
}
```

- 범위 검사를 `grid[nr][nc]` 읽기보다 먼저 합니다. 범위 밖 행을 읽고 다시 접근하면 `TypeError`입니다(자세히는 81편).
- `(r, c)`의 거리는 `dist[r * C + c]`입니다.

## Dijkstra 템플릿

음수가 없는 가중치 그래프에서 시작점으로부터 모든 노드까지의 최단 거리를 구합니다(자세히는 48편). `adj[u]`에 `[v, w]` 쌍이 들어 있습니다.

```js
const dist = new Array(n + 1).fill(Infinity)
const heap = []
const less = (a, b) => a[0] < b[0]
dist[src] = 0
heapPush(heap, [0, src], less)
while (heap.length) {
  const [d, u] = heapPop(heap, less)
  if (d > dist[u]) continue
  for (const [v, w] of adj[u]) {
    if (d + w >= dist[v]) continue
    dist[v] = d + w
    heapPush(heap, [dist[v], v], less)
  }
}
```

- 힙에는 `[거리, 노드]`를 담고 거리가 작은 쪽이 먼저 나옵니다.
- `d > dist[u]`는 이미 더 짧은 거리로 처리된 노드의 낡은 항목을 건너뜁니다. 이 줄이 없으면 정답은 같지만 느려집니다.
- 도달하지 못한 노드는 `Infinity`로 남습니다. 출력 요구에 맞게 `-1` 등으로 바꿉니다.
- 간선 수가 E이면 O(E log E)입니다. 거리의 합이 2^53 미만이어야 정확합니다(자세히는 85편).
- 가중치가 음수이면 틀립니다. 그때는 벨만-포드를 씁니다(자세히는 49편).
- 경로가 필요하면 거리를 갱신할 때 `parent[v] = u`를 함께 기록합니다.

## Topological Sort 템플릿

방향 그래프의 노드를 모든 간선이 앞에서 뒤로 향하도록 줄 세웁니다(자세히는 53편). 진입 차수가 0인 노드부터 꺼내는 방식입니다.

```js
const adj = Array.from({ length: n + 1 }, () => [])
const indeg = new Int32Array(n + 1)
for (const [a, b] of edges) {   // 간선 a → b
  adj[a].push(b)
  indeg[b]++
}
const order = []
for (let v = 1; v <= n; v++) if (!indeg[v]) order.push(v)
for (let head = 0; head < order.length; head++) {
  for (const v of adj[order[head]]) {
    if (--indeg[v] === 0) order.push(v)
  }
}
const ok = order.length === n   // false이면 사이클
```

- 줄 세운 결과는 `order`입니다. 길이가 `n`보다 작으면 사이클 때문에 일부 노드가 끝까지 진입 차수 0이 되지 못한 것입니다.
- 정답이 여러 개일 수 있습니다. 사전순으로 가장 앞선 순서를 요구하면 `order` 대신 최소 힙에서 꺼냅니다.
- 같은 배열 `order`가 큐 역할을 겸해서 별도의 큐가 필요 없습니다.

## Binary Search 템플릿

정렬된 배열에서 값을 찾는 기본형입니다(자세히는 28편). 구간을 닫힌 `[lo, hi]`로 두고, 찾으면 인덱스, 없으면 `-1`을 반환합니다.

```js
function binarySearch(a, target) {
  let lo = 0, hi = a.length - 1
  while (lo <= hi) {
    const mid = (lo + hi) >> 1
    if (a[mid] === target) return mid
    if (a[mid] < target) lo = mid + 1
    else hi = mid - 1
  }
  return -1
}
```

답의 범위를 이분 탐색하는 매개변수 탐색에서는 조건이 처음 참이 되는 값을 찾는 형태가 더 많이 쓰입니다. 조건 `ok(x)`가 거짓에서 참으로 한 번만 바뀐다고 가정합니다.

```js
function firstTrue(lo, hi, ok) {   // [lo, hi]에서 처음 참인 x
  while (lo < hi) {
    const mid = Math.floor((lo + hi) / 2)
    if (ok(mid)) hi = mid
    else lo = mid + 1
  }
  return lo   // 모두 거짓이면 hi
}
```

- 범위를 `[lo, hi]`로 보면 모두 거짓일 때 `hi`가 반환됩니다. 범위를 `hi = 정답 최댓값 + 1`로 잡아 "없음"을 `hi`로 구분합니다.
- 갱신은 반드시 `lo = mid + 1`과 `hi = mid`입니다. `lo = mid`로 쓰면 무한루프가 납니다(자세히는 81편).
- `mid`는 `Math.floor((lo + hi) / 2)`로 계산합니다. `>> 1`은 32비트 정수로 바꿔서 값이 2^31을 넘으면 틀립니다. 예를 들어 `(2 ** 31 + 10) >> 1`은 `-1073741819`입니다. 배열 인덱스처럼 범위가 작을 때만 `>> 1`을 씁니다.
- 최댓값의 최솟값은 `ok`를 "이 값으로 가능한가"로 두고 `firstTrue`로 구합니다. 최솟값의 최댓값은 조건이 참에서 거짓으로 바뀌므로 `ok`를 뒤집거나 마지막 참을 찾는 형태로 바꿉니다.

## Lower / Upper Bound 템플릿

정렬된 배열에서 기준 `x`가 들어갈 위치를 찾습니다(자세히는 28편). 둘 다 `[0, a.length]`를 반환하는 반열린 구간 방식입니다.

```js
function lowerBound(a, x) {      // x 이상이 처음 나오는 위치
  let lo = 0, hi = a.length
  while (lo < hi) {
    const mid = (lo + hi) >> 1
    if (a[mid] < x) lo = mid + 1
    else hi = mid
  }
  return lo
}
```

```js
function upperBound(a, x) {      // x 초과가 처음 나오는 위치
  let lo = 0, hi = a.length
  while (lo < hi) {
    const mid = (lo + hi) >> 1
    if (a[mid] <= x) lo = mid + 1
    else hi = mid
  }
  return lo
}
```

| 구하려는 것 | 식 |
|-------------|----|
| `x`의 개수 | `upperBound(a, x) - lowerBound(a, x)` |
| `x`가 있는지 | `lowerBound(a, x) < a.length && a[lowerBound(a, x)] === x` |
| `x` 미만의 개수 | `lowerBound(a, x)` |
| `x` 이하의 개수 | `upperBound(a, x)` |
| 구간 `[x, y]`에 있는 개수 | `upperBound(a, y) - lowerBound(a, x)` |

- 둘의 차이는 비교 한 곳(`<`와 `<=`)뿐입니다.
- 배열은 오름차순이어야 합니다. 정렬할 때 숫자 비교 함수를 씁니다(자세히는 26편).
- 반환값이 `a.length`일 수 있으므로 `a[반환값]`을 읽기 전에 범위를 확인합니다.

## Prefix Sum 템플릿

앞에서부터의 합을 미리 계산해 구간 합을 O(1)에 구합니다(자세히는 29편). 길이를 하나 늘려 `p[0] = 0`을 둡니다.

```js
const p = new Array(a.length + 1).fill(0)
for (let i = 0; i < a.length; i++) p[i + 1] = p[i] + a[i]
// a[l] + ... + a[r - 1] = p[r] - p[l]
```

2차원은 사각형의 합을 포함·배제로 계산합니다. `g`는 R행 C열의 숫자 배열이고, `p[r][c]`는 위쪽 r행, 왼쪽 c열까지의 합입니다.

```js
const p = []
for (let r = 0; r <= R; r++) {
  p.push(new Array(C + 1).fill(0))
}
for (let r = 0; r < R; r++) {
  for (let c = 0; c < C; c++) {
    const up = p[r][c + 1]
    const left = p[r + 1][c]
    p[r + 1][c + 1] = g[r][c] + up + left - p[r][c]
  }
}
// (r1, c1)–(r2, c2) 사각형(양 끝 포함)의 합
const rect = (r1, c1, r2, c2) =>
  p[r2 + 1][c2 + 1] - p[r1][c2 + 1]
  - p[r2 + 1][c1] + p[r1][c1]
```

- 구간 질의가 많을수록 효과가 큽니다. 질의 한 번이 O(1)이고 준비는 한 번 O(N)입니다.
- 합이 2^53을 넘으면 정밀도를 잃습니다. 그러면 BigInt로 누적합니다(자세히는 85편).
- 값 갱신이 섞이면 누적합이 아니라 펜윅 트리나 세그먼트 트리입니다(82편).

## KMP 템플릿

문자열 `s`에서 패턴 `p`가 나타나는 모든 위치를 O(N + M)에 찾습니다(자세히는 58편). 먼저 패턴의 실패 함수를 만듭니다. `fail[i]`는 `p[0..i]`의 접두사이면서 접미사인 부분 중 가장 긴 것의 길이입니다.

```js
function failure(p) {
  const fail = new Int32Array(p.length)
  for (let i = 1, k = 0; i < p.length; i++) {
    while (k > 0 && p[i] !== p[k]) k = fail[k - 1]
    if (p[i] === p[k]) k++
    fail[i] = k
  }
  return fail
}
// failure('abacaba') → [0, 0, 1, 0, 1, 2, 3]
```

```js
function kmpSearch(s, p) {
  const fail = failure(p)
  const found = []
  for (let i = 0, k = 0; i < s.length; i++) {
    while (k > 0 && s[i] !== p[k]) k = fail[k - 1]
    if (s[i] === p[k]) k++
    if (k === p.length) {
      found.push(i - p.length + 1)   // 시작 위치
      k = fail[k - 1]
    }
  }
  return found
}
```

- 반환값은 겹치는 경우를 포함한 모든 시작 인덱스입니다. `kmpSearch('aaaa', 'aa')`는 `[0, 1, 2]`입니다.
- `p`가 빈 문자열이면 `fail[k - 1]`이 잘못된 인덱스를 읽습니다. 패턴이 비어 있지 않다고 가정합니다.
- 한 번만 찾는다면 `s.indexOf(p)`나 `includes`가 더 간단합니다. 짧은 패턴과 짧은 문자열이면 그것으로 충분하고, 입력이 크고 최악의 반복 패턴이 가능할 때 KMP를 씁니다.
- 접두사 함수의 값은 반복 주기(문자열이 몇 번 반복되는가)를 구하는 데도 쓰입니다(자세히는 58편).

## GCD / LCM 템플릿

최대공약수는 유클리드 호제법으로, 최소공배수는 곱을 최대공약수로 나눠 구합니다(자세히는 12편).

```js
function gcd(a, b) {
  while (b) [a, b] = [b, a % b]
  return a
}
const lcm = (a, b) => (a / gcd(a, b)) * b
// gcd(12, 18) → 6, lcm(4, 6) → 12
// 여러 수: nums.reduce(gcd), nums.reduce(lcm)
```

- `lcm`은 먼저 나누고 곱합니다. `a * b / gcd(a, b)`로 쓰면 중간 값 `a * b`가 2^53을 넘을 수 있습니다. 결과가 2^53을 넘을 수 있으면 BigInt로 계산합니다(자세히는 85편).
- `gcd(a, 0)`은 `a`이고 `gcd(0, b)`는 `b`입니다.
- 음수가 들어가면 결과의 부호가 음수일 수 있습니다. 예를 들어 `gcd(12, -18)`은 `-6`입니다. 입력이 음수일 수 있으면 `Math.abs`를 먼저 적용합니다.
- 반복문이라 재귀 깊이 문제가 없습니다.

## 빠른 거듭제곱 템플릿

지수를 이진수로 보고 제곱을 반복해 `base ** exp`를 O(log exp)번의 곱셈으로 구합니다(자세히는 57편). 나머지를 구할 때는 곱할 때마다 나눈 나머지를 취합니다.

```js
function powMod(base, exp, mod) {
  let result = 1
  base %= mod
  while (exp > 0) {
    if (exp % 2 === 1) result = (result * base) % mod
    base = (base * base) % mod
    exp = Math.floor(exp / 2)
  }
  return result
}
```

이 `Number` 버전은 곱 `result * base`가 2^53 미만일 때만 정확합니다. 두 수가 `mod` 미만이므로 `mod`가 94,906,266 이하일 때 안전합니다. 흔한 `1_000_000_007`은 이 범위를 넘습니다. 그때는 BigInt로 계산합니다.

```js
function powModBig(base, exp, mod) {   // 모두 BigInt
  let result = 1n
  base %= mod
  while (exp > 0n) {
    if (exp & 1n) result = (result * base) % mod
    base = (base * base) % mod
    exp >>= 1n
  }
  return result
}
powModBig(2n, 100n, 1000000007n)   // 976371285n
```

같은 입력을 `Number` 버전에 넣으면 값이 달라집니다.

```js
powMod(2, 100, 1e9 + 7)            // 976371253 (❌ 틀린 값)
Number(powModBig(2n, 100n, 1000000007n)) // 976371285 (✅)
```

나머지 없이 큰 수 자체가 필요하면 BigInt로 곱합니다.

```js
function powBig(base, exp) { // BigInt, Number
  let result = 1n
  while (exp > 0) {
    if (exp & 1) result *= base
    base *= base
    exp >>= 1
  }
  return result
}
// powBig(2n, 100) === 2n ** 100n
```

- `Number` 버전의 지수 처리는 `exp % 2`와 `Math.floor(exp / 2)`라서 2^53까지 쓸 수 있습니다. `exp & 1`과 `exp >>= 1`은 32비트 정수만 다룹니다.
- BigInt는 Number와 섞어 연산하면 `TypeError`입니다. 모든 인자를 `n` 접미사 값으로 넘깁니다.
- BigInt 곱셈은 Number보다 느립니다. 질의가 많을 때는 입력 크기와 시간 제한을 확인합니다.
- `**` 연산자는 `Number`로도 BigInt로도 쓸 수 있지만, 큰 수에서는 정밀도(Number)나 메모리(BigInt)가 문제가 되어 나머지 연산이 필요한 문제에는 직접 쓰지 않습니다.

## 핵심 정리

- DFS와 BFS는 방문 배열과 큐(head 인덱스)로 쓰고, 방문 표시는 넣는 시점에 합니다. 깊은 그래프의 DFS는 반복문으로 바꿉니다.
- 다익스트라는 `[거리, 노드]`를 최소 힙에 담고 낡은 항목을 건너뛰며, 음수 가중치에는 쓰지 못합니다.
- 위상 정렬은 진입 차수 0인 노드부터 꺼내고, 결과 길이가 `n`보다 작으면 사이클입니다.
- 이분 탐색은 갱신을 `mid + 1`과 `mid`로 하고, 큰 범위에서는 `mid`를 `Math.floor((lo + hi) / 2)`로 계산합니다. 하한과 상한은 비교 기호 한 곳만 다릅니다.
- 누적합은 길이 `n + 1`로 `p[0] = 0`을 두고, KMP는 실패 함수와 탐색 두 단계입니다.
- `lcm`은 나눈 뒤 곱하고, 모듈러 거듭제곱의 곱이 2^53을 넘을 수 있으면 BigInt 버전을 씁니다.
