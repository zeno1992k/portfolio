## LIS

최장 증가 부분 수열(LIS, Longest Increasing Subsequence)은 수열에서 원소를 일부 골라 원래 순서를 유지한 채 값이 증가하게 만들 때 가장 긴 길이를 구하는 문제입니다. 고른 원소가 붙어 있을 필요는 없습니다.

상태 `dp[i]`는 `a[i]`로 끝나는 증가 부분 수열의 최대 길이입니다. `a[i]` 앞의 원소 `a[j]`(j < i) 중 `a[j] < a[i]`인 것 뒤에 `a[i]`를 붙일 수 있으므로 점화식은 다음과 같습니다.

$$
dp[i] = 1 + \max_{j < i,\ a[j] < a[i]} dp[j]
$$

- 붙일 수 있는 `j`가 없으면 `dp[i] = 1`입니다. 모든 `dp[i]`의 초기값이 1인 이유입니다.
- 답은 `dp[N-1]`이 아니라 모든 `dp[i]` 중 최댓값입니다. 마지막 원소로 끝난다는 보장이 없습니다.

```js
function lis(a) {
  const dp = new Array(a.length).fill(1)
  for (let i = 1; i < a.length; i++) {
    for (let j = 0; j < i; j++) {
      if (a[j] < a[i]) dp[i] = Math.max(dp[i], dp[j] + 1)
    }
  }
  return Math.max(...dp)
}
lis([10, 20, 10, 30, 20, 50]) // 4 (10, 20, 30, 50)
```

| i | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| a[i] | 10 | 20 | 10 | 30 | 20 | 50 |
| dp[i] | 1 | 2 | 1 | 3 | 2 | 4 |

- 시간 O(N²), 공간 O(N)입니다. N이 수천 정도까지 쓸 수 있습니다.
- 증가의 기준이 문제마다 다릅니다. 값이 같아도 되면(감소하지 않는 수열) 조건을 `a[j] <= a[i]`로 바꿉니다. 감소 수열은 부등호를 뒤집습니다.
- `Math.max(...dp)`는 인수 개수 한계가 있어서 N이 매우 크면 반복문으로 최댓값을 구합니다(자세히는 86편).

**문제의 단서:** 문제 문장에 "부분 수열", "순서를 바꾸지 않고", "가장 길게"가 나옵니다. 부분 수열(subsequence)은 떨어져 있어도 되고, 부분 배열(subarray)은 연속이어야 합니다. 이 둘을 헷갈리지 않는 것이 첫 관문입니다.

## 이분 탐색을 쓰는 O(N log N) LIS

N이 10만 이상이면 O(N²)은 통하지 않습니다. 이 경우 길이별로 "그 길이의 증가 부분 수열이 끝날 수 있는 가장 작은 값"을 배열 `tails`에 유지하는 방법을 씁니다.

- `tails[k]`는 길이 `k + 1`인 증가 부분 수열의 마지막 값 중 최솟값입니다.
- 끝값이 작을수록 뒤에 더 많은 원소를 붙일 수 있어서 최솟값만 남겨도 손해가 없습니다.
- `tails`는 항상 오름차순입니다. 길이가 긴 수열의 끝값이 짧은 수열의 끝값보다 작을 수 없기 때문입니다.

새 원소 `x`를 만나면 `tails`에서 `x` 이상인 첫 위치(lower bound)를 이분 탐색으로 찾습니다(자세히는 28편).

- 그런 위치가 없으면 `x`가 가장 긴 수열의 뒤에 붙으므로 `tails` 끝에 추가합니다. 길이가 1 늘어납니다.
- 있으면 그 자리의 값을 `x`로 바꿉니다. 같은 길이의 수열 중 끝값이 더 작은 것이 생긴 것입니다.

```js
function lisFast(a) {
  const tails = []
  for (const x of a) {
    let lo = 0, hi = tails.length
    while (lo < hi) {                 // x 이상인 첫 위치
      const mid = (lo + hi) >> 1
      if (tails[mid] < x) lo = mid + 1
      else hi = mid
    }
    tails[lo] = x     // lo === tails.length이면 추가
  }
  return tails.length
}
```

`a = [4, 1, 5, 2, 3, 6]`을 처리하는 과정입니다.

| x | 위치 | 동작 | tails |
|---|------|------|-------|
| 4 | 0 | 추가 | [4] |
| 1 | 0 | 4를 1로 교체 | [1] |
| 5 | 1 | 추가 | [1, 5] |
| 2 | 1 | 5를 2로 교체 | [1, 2] |
| 3 | 2 | 추가 | [1, 2, 3] |
| 6 | 3 | 추가 | [1, 2, 3, 6] |

답은 `tails`의 길이 4입니다.

- 시간 O(N log N), 공간 O(N)입니다.
- `tails`는 길이만 정확하고 실제 LIS 수열은 아닐 수 있습니다. `[2, 5, 3, 1]`을 처리하면 `tails`가 `[1, 3]`이 되지만 1은 3보다 뒤에 있어서 `[1, 3]`은 부분 수열이 아닙니다(길이 2는 맞습니다). 수열이 필요하면 역추적 절의 방법을 씁니다.
- 값이 같아도 되는 경우(감소하지 않는 수열)는 `x` 이상이 아니라 `x` 초과인 첫 위치(upper bound)를 찾습니다. 비교를 `tails[mid] <= x`로 바꿉니다. `[1, 2, 2, 3, 1]`은 증가 수열이면 3, 감소하지 않는 수열이면 4입니다.

**흔한 실수:** 값이 같은 원소를 만났을 때 lower bound와 upper bound를 바꿔 쓰는 것입니다. 엄격한 증가는 lower bound, 비감소는 upper bound입니다. 값이 같은 두 원소가 들어 있는 작은 입력으로 확인합니다.

## 문자열 DP

문자열 DP는 문자열의 접두사나 구간을 상태로 삼는 DP입니다. 두 문자열 `a`, `b`를 비교하는 문제는 대부분 같은 틀입니다.

- 상태 `dp[i][j]`는 `a`의 앞 `i`글자와 `b`의 앞 `j`글자에 대한 답입니다.
- 표 크기는 `(n + 1) × (m + 1)`입니다. 0번 행과 0번 열은 빈 문자열을 뜻해서 경계 처리가 필요 없어집니다.
- 점화식은 마지막 글자 `a[i-1]`과 `b[j-1]`이 같은지 다른지로 갈립니다. 인덱스는 문자열 쪽이 0부터라서 표의 `i`는 문자열의 `i - 1`번째 글자에 대응합니다.
- 채우는 순서는 `i`와 `j`를 증가시키는 방향입니다. 모든 점화식이 위·왼쪽·왼쪽 위에 의존하기 때문입니다.

한 문자열 안의 구간을 보는 문제는 `dp[i][j]`가 구간 `s[i..j]`에 대한 답이 됩니다. 이 형태는 팰린드롬 절에서 다룹니다.

```js
const n = a.length, m = b.length
const dp = Array.from({ length: n + 1 },
  () => new Array(m + 1).fill(0))
// i = 1..n, j = 1..m 으로 채운다. a[i - 1], b[j - 1]이 마지막 글자
```

JavaScript에서 문자열 `a[i]`는 UTF-16 코드 유닛이라서 이모지 같은 글자가 둘로 나뉠 수 있습니다. 코딩테스트 입력은 대개 영문이라 문제가 없지만, 서로게이트 쌍이 있는 문자열은 `[...a]`로 코드 포인트 배열을 만든 뒤 처리합니다(자세히는 06편).

## LCS

최장 공통 부분 수열(LCS, Longest Common Subsequence)은 두 문자열의 공통 부분 수열 중 가장 긴 것의 길이를 구하는 문제입니다. 부분 수열은 떨어져 있어도 되므로 `ABCD`와 `ACBAD`의 공통 부분 수열에 `AB`와 `AC`가 모두 들어갑니다.

상태 `dp[i][j]`는 `a`의 앞 `i`글자와 `b`의 앞 `j`글자의 LCS 길이입니다.

$$
dp[i][j] = \begin{cases} dp[i-1][j-1] + 1 & a[i-1] = b[j-1] \\ \max(dp[i-1][j],\ dp[i][j-1]) & \text{그 외} \end{cases}
$$

- 마지막 글자가 같으면 그 글자를 LCS의 끝에 쓰는 것이 항상 이득이라서 양쪽에서 한 글자씩 지운 문제에 1을 더합니다.
- 다르면 둘 중 한 문자열의 마지막 글자는 LCS에 쓰이지 않으므로 하나를 지운 두 경우 중 큰 쪽을 고릅니다.
- 한쪽이 빈 문자열이면 0이라서 0번 행과 0번 열이 0입니다.

```js
function lcs(a, b) {
  const n = a.length, m = b.length
  const dp = Array.from({ length: n + 1 },
    () => new Array(m + 1).fill(0))
  for (let i = 1; i <= n; i++) {
    for (let j = 1; j <= m; j++) {
      dp[i][j] = a[i - 1] === b[j - 1]
        ? dp[i - 1][j - 1] + 1
        : Math.max(dp[i - 1][j], dp[i][j - 1])
    }
  }
  return dp
}
```

`a = 'ACAYKP'`, `b = 'CAPCAK'`일 때 반환된 표입니다. 답은 오른쪽 아래 값 4입니다.

| | 빈 | C | A | P | C | A | K |
|---|---|---|---|---|---|---|---|
| 빈 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| A | 0 | 0 | 1 | 1 | 1 | 1 | 1 |
| C | 0 | 1 | 1 | 1 | 2 | 2 | 2 |
| A | 0 | 1 | 2 | 2 | 2 | 3 | 3 |
| Y | 0 | 1 | 2 | 2 | 2 | 3 | 3 |
| K | 0 | 1 | 2 | 2 | 2 | 3 | 4 |
| P | 0 | 1 | 2 | 3 | 3 | 3 | 4 |

- 시간과 공간은 O(NM)입니다. 길이만 필요하면 행 두 개만 남겨 공간을 O(M)으로 줄입니다(자세히는 41편의 롤링 배열).
- 표에서 값이 왼쪽 위 칸보다 1 커진 칸이 글자가 일치한 칸입니다.
- LIS는 원래 수열과 중복을 제거해 정렬한 수열의 LCS로도 구할 수 있습니다. 다만 O(NM)이라 앞의 O(N log N) 풀이가 낫습니다.

**흔한 실수:** LCS(subsequence)와 최장 공통 부분 문자열(substring)을 섞는 것입니다. 앞의 것은 불일치에서 값을 이어 가고, 뒤의 것은 0으로 끊습니다(최장 공통 부분 문자열 절).

## DP 역추적

DP 역추적은 DP 표의 값이 아니라 그 값을 만든 선택(수열, 경로, 편집 과정)을 복원하는 기법입니다. 표를 끝에서부터 거꾸로 따라가며 어느 선택에서 이 값이 나왔는지 찾습니다. 두 가지 방법이 있습니다.

| 방법 | 내용 | 특징 |
|------|------|------|
| 선택 기록 | 값을 정할 때 고른 이전 상태를 `prev` 배열에 저장 | 복원 코드가 단순하다. 메모리가 더 든다 |
| 표에서 재계산 | 저장된 표의 값으로 어느 점화식 분기에서 나왔는지 다시 판정 | 추가 메모리가 필요 없다. 조건 판정을 정확히 써야 한다 |

### LIS 복원

O(N²) 풀이에서 `dp[i]`를 갱신할 때 어느 `j`를 골랐는지 `prev[i]`에 남깁니다.

```js
function lisSeq(a) {
  const dp = a.map(() => 1), prev = a.map(() => -1)
  for (let i = 0; i < a.length; i++) {
    for (let j = 0; j < i; j++) {
      if (a[j] < a[i] && dp[j] + 1 > dp[i]) {
        dp[i] = dp[j] + 1; prev[i] = j
      }
    }
  }
  let k = dp.indexOf(Math.max(...dp)), res = []
  while (k !== -1) { res.push(a[k]); k = prev[k] }
  return res.reverse()
}
lisSeq([10, 20, 10, 30, 20, 50]) // [10, 20, 30, 50]
```

- `prev[i]`가 -1이면 `a[i]`에서 시작한다는 뜻이고 거슬러 가는 반복이 멈춥니다.
- 거슬러 오르면 마지막 원소부터 나오므로 마지막에 `reverse`로 뒤집습니다.
- 길이가 같은 LIS가 여러 개일 수 있습니다. 어느 것을 출력할지 정해져 있으면 `>`와 `>=`, 선택 순서를 문제에 맞게 고릅니다.

O(N log N) 풀이에서는 `tails`에 값 대신 인덱스를 저장하고, 원소를 놓을 때 바로 앞 길이의 끝 인덱스를 `prev`에 적습니다.

```js
const tailIdx = [], prev = new Array(a.length).fill(-1)
for (let i = 0; i < a.length; i++) {
  let lo = 0, hi = tailIdx.length
  while (lo < hi) {
    const mid = (lo + hi) >> 1
    if (a[tailIdx[mid]] < a[i]) lo = mid + 1
    else hi = mid
  }
  tailIdx[lo] = i
  prev[i] = lo > 0 ? tailIdx[lo - 1] : -1
}
// 복원은 k = tailIdx[tailIdx.length - 1] 에서 prev를 따라간다
```

### LCS 복원

표 `dp`의 오른쪽 아래 칸에서 출발해 점화식의 분기를 거꾸로 판정합니다.

```js
function lcsString(a, b, dp) {
  let i = a.length, j = b.length
  const out = []
  while (i > 0 && j > 0) {
    if (a[i - 1] === b[j - 1]) {      // 일치한 글자
      out.push(a[i - 1]); i--; j--
    } else if (dp[i - 1][j] >= dp[i][j - 1]) {
      i--                              // 위에서 온 값
    } else {
      j--                              // 왼쪽에서 온 값
    }
  }
  return out.reverse().join('')
}
// lcsString('ACAYKP', 'CAPCAK', dp) // 'ACAK'
```

- 일치한 칸이면 대각선으로 이동하며 그 글자를 모읍니다.
- 일치하지 않으면 값이 더 큰 쪽(위 또는 왼쪽)으로 이동합니다. 같으면 어느 쪽을 골라도 LCS 길이는 같지만 결과 문자열이 달라질 수 있습니다.
- 경로를 거꾸로 따라가므로 마지막에 뒤집습니다.
- 복원에는 중간 행들이 모두 필요해서 롤링 배열로 줄인 표로는 복원할 수 없습니다(41편).

**흔한 실수:** 복원 때 `dp[i][j] === dp[i-1][j-1] + 1`만으로 일치를 판정하는 것입니다. 글자가 다른데도 우연히 값이 맞는 경우가 있습니다. 반드시 `a[i-1] === b[j-1]`로 글자를 직접 비교합니다.

## 편집 거리

편집 거리(edit distance, Levenshtein distance)는 한 문자열을 다른 문자열로 바꾸는 데 필요한 최소 연산 횟수입니다. 연산은 문자 삽입, 삭제, 교체 세 가지이며 각각 비용이 1입니다.

상태 `dp[i][j]`는 `a`의 앞 `i`글자를 `b`의 앞 `j`글자로 바꾸는 최소 연산 수입니다. 마지막 글자를 맞추는 방법이 셋입니다.

$$
dp[i][j] = \min \begin{cases} dp[i-1][j] + 1 & \text{a의 글자 삭제} \\ dp[i][j-1] + 1 & \text{b의 글자 삽입} \\ dp[i-1][j-1] + c & \text{교체 또는 일치} \end{cases}
$$

- `c`는 `a[i-1] === b[j-1]`이면 0, 아니면 1입니다.
- 경계는 `dp[i][0] = i`(i글자를 모두 삭제), `dp[0][j] = j`(j글자를 모두 삽입)입니다.

```js
function editDistance(a, b) {
  const n = a.length, m = b.length
  const dp = Array.from({ length: n + 1 },
    () => new Array(m + 1).fill(0))
  for (let i = 0; i <= n; i++) dp[i][0] = i
  for (let j = 0; j <= m; j++) dp[0][j] = j
  for (let i = 1; i <= n; i++) {
    for (let j = 1; j <= m; j++) {
      const c = a[i - 1] === b[j - 1] ? 0 : 1
      dp[i][j] = Math.min(dp[i - 1][j] + 1,
        dp[i][j - 1] + 1, dp[i - 1][j - 1] + c)
    }
  }
  return dp
}
```

`flaw`를 `lawn`으로 바꾸는 표입니다. 답은 오른쪽 아래 값 2입니다.

| | 빈 | l | a | w | n |
|---|---|---|---|---|---|
| 빈 | 0 | 1 | 2 | 3 | 4 |
| f | 1 | 1 | 2 | 3 | 4 |
| l | 2 | 1 | 2 | 3 | 4 |
| a | 3 | 2 | 1 | 2 | 3 |
| w | 4 | 3 | 2 | 1 | 2 |

- 시간 O(NM), 공간 O(NM)입니다. 거리만 필요하면 행 두 개로 줄여 O(min(N, M))까지 낮출 수 있습니다.
- 연산 과정을 복원하려면 표를 끝에서부터 따라갑니다. 일치하면 대각선으로, 아니면 값이 `dp[i-1][j-1] + 1`(교체), `dp[i-1][j] + 1`(삭제), `dp[i][j-1] + 1`(삽입)인 쪽으로 이동하며 연산을 기록하고 마지막에 뒤집습니다. `flaw`에서 `lawn`은 f를 삭제하고 n을 삽입하는 두 연산입니다.
- 삽입과 삭제만 허용하면 편집 거리는 `n + m - 2 × LCS`입니다. 교체를 허용하는 편집 거리와 다른 값이므로 문제의 연산 정의를 확인합니다.

**흔한 실수:** 0번 행·열 경계 초기화를 빼먹는 것입니다. `dp`를 0으로만 채우고 시작하면 빈 문자열과의 거리가 모두 0이 되어 정답이 작게 나옵니다. LCS의 경계는 0이지만 편집 거리의 경계는 `i`와 `j`입니다.

## 최장 공통 부분 문자열

최장 공통 부분 문자열(longest common substring)은 두 문자열에 모두 연속해서 나타나는 가장 긴 부분 문자열을 구하는 문제입니다. LCS와 달리 글자들이 붙어 있어야 합니다.

상태 `dp[i][j]`는 `a[i-1]`과 `b[j-1]`에서 끝나는 공통 부분 문자열의 최대 길이입니다. 글자가 일치하면 이어 붙이고, 다르면 끊깁니다.

$$
dp[i][j] = \begin{cases} dp[i-1][j-1] + 1 & a[i-1] = b[j-1] \\ 0 & \text{그 외} \end{cases}
$$

- 마지막 글자에서 끝나는 값만 담으므로 답은 오른쪽 아래 칸이 아니라 표 전체의 최댓값입니다.
- 최댓값을 만든 끝 위치를 기록해 두면 부분 문자열도 잘라낼 수 있습니다.

```js
function longestCommonSubstring(a, b) {
  const n = a.length, m = b.length
  const dp = Array.from({ length: n + 1 },
    () => new Array(m + 1).fill(0))
  let best = 0, end = 0               // end: a에서의 끝 위치(제외)
  for (let i = 1; i <= n; i++) {
    for (let j = 1; j <= m; j++) {
      if (a[i - 1] !== b[j - 1]) continue
      dp[i][j] = dp[i - 1][j - 1] + 1
      if (dp[i][j] > best) { best = dp[i][j]; end = i }
    }
  }
  return a.slice(end - best, end)
}
longestCommonSubstring('ABABC', 'BABCA') // 'BABC'
```

- 시간과 공간은 O(NM)이고, `dp[i][j]`가 `dp[i-1][j-1]`에만 의존하므로 행 두 개로 줄일 수 있습니다.
- 표를 0으로 초기화했으므로 불일치 칸은 건너뛰기만 하면 0이 유지됩니다.
- 공통 부분 문자열이 없으면 `best`는 0이고 빈 문자열을 반환합니다.
- 입력이 매우 크면(문자열 길이가 수십만) 접미사 배열 같은 자료구조를 씁니다(자세히는 59편).

| 항목 | LCS | 최장 공통 부분 문자열 |
|------|-----|-----------------------|
| 연속 조건 | 없음 | 있음 |
| 글자가 다를 때 | `max(위, 왼쪽)` | 0 |
| 답의 위치 | 오른쪽 아래 칸 | 표 전체의 최댓값 |

**흔한 실수:** 답을 `dp[n][m]`으로 반환하는 것입니다. 공통 부분 문자열이 중간에서 끝나면 마지막 칸은 0입니다.

## 팰린드롬 부분 문자열 DP

팰린드롬(회문)은 앞에서 읽으나 뒤에서 읽으나 같은 문자열입니다. 팰린드롬 DP는 문자열의 모든 구간 `s[i..j]`가 팰린드롬인지 표로 만들어 두고, 팰린드롬 부분 문자열의 개수나 가장 긴 것을 구하는 문제를 푸는 방법입니다.

상태 `is[i][j]`는 `s[i..j]`가 팰린드롬이면 참입니다. 양끝 글자가 같고 안쪽도 팰린드롬이면 참입니다.

$$
is[i][j] = (s[i] = s[j]) \land (j - i < 2 \ \lor\ is[i+1][j-1])
$$

- 길이가 1(`i === j`)이면 항상 참이고 길이가 2(`j - i === 1`)이면 두 글자가 같을 때 참입니다. 안쪽 구간이 비어서 `is[i+1][j-1]`을 읽지 않고 `j - i < 2`로 처리합니다.
- `is[i][j]`는 `is[i+1][j-1]`(한 행 아래, 한 열 왼쪽)에 의존하므로 `i`를 큰 쪽에서 작은 쪽으로, `j`를 `i`부터 증가시키며 채웁니다. 구간 길이가 짧은 것부터 채우는 순서입니다.

```js
function palindromes(s) {
  const n = s.length
  const is = Array.from({ length: n },
    () => new Array(n).fill(false))
  let count = 0, start = 0, len = 1
  for (let i = n - 1; i >= 0; i--) {
    for (let j = i; j < n; j++) {
      if (s[i] !== s[j]) continue
      if (j - i >= 2 && !is[i + 1][j - 1]) continue
      is[i][j] = true; count++
      if (j - i + 1 > len) { len = j - i + 1; start = i }
    }
  }
  return { count, longest: s.slice(start, start + len), is }
}
```

`'abacd'`로 호출하면 `count`는 6(`a`, `b`, `a`, `c`, `d`, `aba`)이고 `longest`는 `'aba'`입니다.

- 시간과 공간은 O(N²)입니다.
- 표 `is`를 한 번 만들어 두면 "구간 `[l, r]`이 팰린드롬인가"를 O(1)에 답할 수 있습니다. 질의가 여러 개인 문제에 쓰입니다.
- 문자열을 팰린드롬 여러 조각으로 나눌 때 필요한 최소 조각 수는 `is`를 이용해 `cut[j] = min(cut[i] + 1)` (`is[i][j-1]`이 참인 `i`)로 구합니다. `cut[0] = 0`이고 `'aab'`는 조각이 2개(`aa`, `b`)입니다.
- 가장 긴 팰린드롬 하나만 구한다면 표 없이 O(N²) 시간·O(1) 공간으로 풀 수 있습니다. 모든 위치를 중심으로 양쪽으로 확장하며, 홀수 길이와 짝수 길이 중심을 모두 봅니다. 더 빠른 O(N) 방법으로 마나커(Manacher) 알고리즘이 있습니다.
- LCS로도 풀립니다. 문자열 `s`와 `s`를 뒤집은 문자열의 LCS 길이가 가장 긴 팰린드롬 부분 수열(떨어져 있어도 되는 것)의 길이입니다.

**흔한 실수:** `j - i < 2`일 때의 조건을 빼먹고 항상 `is[i+1][j-1]`을 읽는 것입니다. 길이 2인 구간에서 `is[i+1][j-1]`은 안쪽이 비어 있는 칸이라 `false`이므로 `'aa'` 같은 구간이 팰린드롬에서 빠집니다. `j - i >= 2`를 먼저 검사해야 `is[i + 1]`이 없는 마지막 행에서 TypeError가 나지 않습니다. 또 `i`를 증가시키는 순서로 채우면 아직 채우지 않은 칸을 읽습니다.

## Prefix Sum과 DP

누적합(prefix sum)과 DP를 함께 쓰는 방법은 두 가지입니다(누적합은 29편).

### 입력의 누적합으로 비용을 O(1)에 구하기

점화식에 구간 합이 들어가면 입력 배열의 누적합 `P`로 구간 합을 O(1)에 얻습니다. `P[i]`는 앞 `i`개의 합이고 `a[j..i-1]`의 합은 `P[i] - P[j]`입니다.

예로 배열을 연속한 M개 구간으로 나눠 각 구간 합의 제곱의 합을 최소화합니다. 상태 `dp[k][i]`는 앞 `i`개를 `k`개 구간으로 나눈 최솟값입니다.

$$
dp[k][i] = \min_{j < i}\ (dp[k-1][j] + (P[i] - P[j])^2)
$$

```js
const P = [0]
for (const x of a) P.push(P[P.length - 1] + x)
```

이 `P`로 점화식을 계산합니다.

```js
function splitCost(P, M) {  // P: 길이 N + 1인 누적합
  const n = P.length - 1
  let prev = [0, ...new Array(n).fill(Infinity)]
  for (let k = 1; k <= M; k++) {
    const cur = new Array(n + 1).fill(Infinity)
    for (let i = k; i <= n; i++) {
      for (let j = k - 1; j < i; j++) {
        const s = P[i] - P[j]
        cur[i] = Math.min(cur[i], prev[j] + s * s)
      }
    }
    prev = cur
  }
  return prev[n]
}
```

`a = [1, 2, 3, 4]`이면 `P = [0, 1, 3, 6, 10]`이고 `splitCost(P, 2)`는 52입니다(`[1, 2, 3]`, `[4]`로 나눌 때).

- 구간 합을 매번 반복문으로 더하면 O(N³M)인데 누적합으로 O(N²M)이 됩니다.
- `prev`, `cur` 두 배열만 유지하는 롤링 배열입니다(41편).
- 이 O(N²M) 점화식이 너무 느린 경우의 가속은 74편에서 다룹니다.

### DP 값의 누적합으로 구간 합 점화식을 O(1)에 구하기

점화식이 `dp[i - K .. i - 1]` 같은 연속 구간의 합이면, DP 배열 자체의 누적합 `S`를 같이 갱신해 합을 O(1)에 얻습니다. 한 번에 1칸에서 K칸까지 오를 수 있는 계단 오르기의 방법 수를 나머지로 구합니다.

$$
dp[i] = \sum_{t=1}^{K} dp[i-t] = S[i-1] - S[i-K-1]
$$

- `S[i]`는 `dp[0]`부터 `dp[i]`까지의 합입니다.
- `i - K - 1`이 음수이면 뺄 값이 없습니다.

```js
function stairs(n, K) {
  const MOD = 1000000007
  const dp = new Array(n + 1).fill(0)
  const S = new Array(n + 1).fill(0)
  dp[0] = 1; S[0] = 1
  for (let i = 1; i <= n; i++) {
    const low = i - K - 1 >= 0 ? S[i - K - 1] : 0
    dp[i] = (S[i - 1] - low + MOD) % MOD   // 음수 방지
    S[i] = (S[i - 1] + dp[i]) % MOD
  }
  return dp[n]
}
stairs(5, 3) // 13
```

- 합을 매번 K개 더하면 O(NK)이고 누적합으로 O(N)입니다.
- 나머지 연산에서는 뺄셈이 음수가 될 수 있어서 `MOD`를 더한 뒤 다시 나머지를 취합니다. JavaScript의 `%`는 부호가 피제수를 따릅니다(자세히는 57편).
- 이 두 방법은 대상이 다릅니다. 앞의 것은 입력 배열의 누적합이고 뒤의 것은 계산 중인 `dp`의 누적합입니다.

**흔한 실수:** 누적합 배열의 인덱스를 한 칸 어긋나게 쓰는 것입니다. `P`를 길이 N + 1로 만들고 `P[0] = 0`을 두면 `a[j..i-1]`의 합이 `P[i] - P[j]`로 경계 없이 통일됩니다.

## 핵심 정리

- LIS는 `dp[i] = 1 + max dp[j]`(a[j] < a[i])로 O(N²), `tails` 배열과 lower bound 이분 탐색으로 O(N log N)입니다. `tails`는 길이만 맞고 실제 수열이 아닐 수 있습니다.
- 두 문자열 DP는 `dp[i][j]`를 앞 `i`글자와 앞 `j`글자의 답으로 두고 0번 행·열을 빈 문자열로 둡니다.
- LCS는 불일치에서 `max(위, 왼쪽)`이고 최장 공통 부분 문자열은 0으로 끊으며 후자의 답은 표 전체의 최댓값입니다.
- 편집 거리는 삭제·삽입·교체의 최솟값이고 경계는 `dp[i][0] = i`, `dp[0][j] = j`입니다.
- DP 역추적은 `prev` 배열이나 표의 값을 끝에서부터 따라가 수열·편집 과정을 복원하며, 롤링 배열로 줄인 표로는 못 합니다.
- 팰린드롬 DP는 `is[i][j] = (s[i] = s[j]) 그리고 안쪽이 팰린드롬`이고, 입력이나 dp의 누적합은 점화식의 구간 합을 O(1)로 만듭니다.
