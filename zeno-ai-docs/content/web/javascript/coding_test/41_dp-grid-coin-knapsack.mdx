## 2차원 DP

2차원 DP는 상태를 인덱스 두 개로 정의하는 DP입니다. `dp[i][j]`가 가리키는 대상은 문제마다 정합니다. 격자의 칸 `(i, j)`일 수도 있고, 앞에서 `i`개 물건을 보고 용량이 `j`인 경우일 수도 있습니다(DP의 정의와 점화식은 40편).

예로 격자의 왼쪽 위에서 오른쪽 아래까지 오른쪽·아래로만 이동할 때 지나는 칸 값의 합이 최소인 경로를 구합니다. 상태 `dp[i][j]`는 칸 `(i, j)`에 도착했을 때의 최소 합입니다. 칸에는 위나 왼쪽에서만 올 수 있으므로 점화식은 다음과 같습니다.

$$
dp[i][j] = g[i][j] + \min(dp[i-1][j],\ dp[i][j-1])
$$

- `g[i][j]`는 칸의 값입니다.
- 첫 행과 첫 열은 한쪽 이웃이 없으므로 없는 쪽을 `Infinity`로 보고, 시작 칸 `(0, 0)`은 앞선 비용이 0이라서 `best`를 0으로 둡니다.

```js
function minPath(g) {
  const n = g.length, m = g[0].length
  const dp = Array.from({ length: n },
    () => new Array(m).fill(0))
  for (let i = 0; i < n; i++) {
    for (let j = 0; j < m; j++) {
      const up = i > 0 ? dp[i - 1][j] : Infinity
      const left = j > 0 ? dp[i][j - 1] : Infinity
      const best = i + j === 0 ? 0 : Math.min(up, left)
      dp[i][j] = g[i][j] + best
    }
  }
  return dp[n - 1][m - 1]
}
```

`g = [[1,3,1],[1,5,1],[4,2,1]]`이면 dp 표는 아래와 같고 답은 7입니다.

| | j=0 | j=1 | j=2 |
|---|---|---|---|
| i=0 | 1 | 4 | 5 |
| i=1 | 2 | 7 | 6 |
| i=2 | 6 | 8 | 7 |

- 채우는 순서가 곧 의존 방향입니다. `dp[i][j]`가 위와 왼쪽에 의존하므로 `i`와 `j`를 모두 증가하는 방향으로 돌면 필요한 값이 이미 채워져 있습니다.
- 시간과 공간은 모두 O(NM)입니다.
- 격자 자체를 다루는 방법은 17편에서 다룹니다.

**흔한 실수:** 2차원 배열을 `new Array(n).fill(new Array(m).fill(0))`로 만드는 것입니다. 모든 행이 같은 배열을 가리켜 한 칸을 바꾸면 모든 행이 바뀝니다(자세히는 05편). `Array.from`으로 행마다 새로 만듭니다.

## 경로 DP

경로 DP는 출발점에서 어떤 칸·정점까지 가는 방법의 수나 최적값을 구하는 DP입니다. 앞 절의 최소 합도 경로 DP입니다. 대표 유형은 경로의 개수를 세는 문제입니다.

격자에 장애물(1)이 있을 때 오른쪽·아래로만 가는 경로의 수는, 칸에 도착하는 방법이 위에서 오는 방법과 왼쪽에서 오는 방법의 합이라는 점에서 나옵니다. 장애물 칸은 0입니다.

$$
dp[i][j] = \begin{cases} 0 & g[i][j] = 1 \\ dp[i-1][j] + dp[i][j-1] & \text{그 외} \end{cases}
$$

```js
function countPaths(g) {
  const n = g.length, m = g[0].length, MOD = 1000000007
  const dp = Array.from({ length: n },
    () => new Array(m).fill(0))
  for (let i = 0; i < n; i++) {
    for (let j = 0; j < m; j++) {
      if (g[i][j] === 1) continue       // 장애물은 0
      if (i + j === 0) { dp[0][0] = 1; continue }
      const up = i > 0 ? dp[i - 1][j] : 0
      const left = j > 0 ? dp[i][j - 1] : 0
      dp[i][j] = (up + left) % MOD
    }
  }
  return dp[n - 1][m - 1]
}
```

`g = [[0,0,0],[0,1,0],[0,0,0]]`이면 `dp = [[1,1,1],[1,0,1],[1,1,2]]`이고 답은 2입니다.

- 시작 칸 값을 직접 정해 둔 뒤 나머지를 더해 갑니다. 시작이 장애물이면 경로가 0개입니다.
- 경로 수는 격자가 커지면 빠르게 커집니다. 문제가 나머지로 출력하라고 하면 더할 때마다 나머지를 취합니다. 두 수를 더하는 것은 `Number`의 안전 범위 안이라 `BigInt` 없이 됩니다(자세히는 57편).
- 이동 규칙이 바뀌면 점화식의 이웃만 바뀝니다. 대각선도 허용하면 `dp[i-1][j-1]`을 더합니다.
- 최적 경로 자체를 출력해야 하면 각 칸에서 어느 이웃을 골랐는지 함께 저장해 거꾸로 따라갑니다(자세히는 42편).

**흔한 실수:** 첫 행·첫 열에서 `dp[-1][j]`를 읽는 것입니다. JavaScript 배열은 범위를 벗어난 인덱스를 읽어도 에러 없이 `undefined`가 되는데, `undefined`와 더하면 `NaN`이 되어 정답이 `NaN`으로 나옵니다. 경계를 검사하거나 배열 크기를 `(n + 1) × (m + 1)`로 잡아 0번 행·열을 비워 둡니다.

## 동전 DP

동전 DP는 주어진 동전으로 금액을 만드는 문제입니다. 가장 흔한 질문은 "금액 `a`를 만드는 최소 동전 개수"입니다. 상태 `dp[a]`는 금액 `a`를 만드는 데 필요한 최소 동전 개수입니다. 동전 `c`를 마지막으로 쓴다고 보면 점화식이 나옵니다.

$$
dp[a] = \min_{c \le a}\ (dp[a - c] + 1)
$$

- `dp[0] = 0`입니다. 금액 0은 동전 없이 만듭니다.
- 나머지는 `Infinity`로 시작합니다. 만들 수 없는 금액을 표현하는 값입니다.

```js
function coinMin(coins, amount) {
  const dp = new Array(amount + 1).fill(Infinity)
  dp[0] = 0
  for (let a = 1; a <= amount; a++) {
    for (const c of coins) {
      if (a >= c) dp[a] = Math.min(dp[a], dp[a - c] + 1)
    }
  }
  return dp[amount] === Infinity ? -1 : dp[amount]
}
coinMin([1, 3, 4], 6) // 2 (3 + 3)
coinMin([2], 3)       // -1
```

동전 `[1, 3, 4]`, 금액 6일 때 dp 값은 다음과 같습니다.

| a | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| dp[a] | 0 | 1 | 2 | 1 | 1 | 2 | 2 |

- 시간은 O(금액 × 동전 종류 수), 공간은 O(금액)입니다.
- `Infinity + 1`은 `Infinity`라서 도달 불가능한 상태에서 더해도 값이 망가지지 않습니다. 이 점이 `Infinity`를 쓰는 이유입니다.
- 가장 큰 동전부터 쓰는 그리디는 `[1, 3, 4]`로 6을 만들 때 `4 + 1 + 1`(3개)이 되어 틀립니다. 동전이 서로 배수 관계일 때만 그리디가 성립합니다(자세히는 33편).

**흔한 실수:** `Int32Array`로 dp를 만들면서 `Infinity`를 넣는 것입니다. 정수 타입 배열은 값을 정수로 변환해 저장하므로 `Infinity`가 0이 됩니다(자세히는 05편). 정수 배열을 쓸 때는 정답이 될 수 없는 큰 정수(예: `1e9`)를 센티널로 쓰고, 더해도 넘치지 않는지 확인합니다.

## 순서를 구분하는 경우의 수와 구분하지 않는 경우의 수

금액을 만드는 방법의 수를 셀 때는 `1 + 2`와 `2 + 1`을 같은 방법으로 볼지 다른 방법으로 볼지에 따라 풀이가 갈립니다. 점화식은 거의 같고 반복문의 중첩 순서만 다릅니다.

| 구분 | 의미 | 반복문 순서 |
|------|------|-------------|
| 조합(순서 구분 안 함) | `1+2`와 `2+1`은 한 가지 | 바깥이 동전, 안쪽이 금액 |
| 순열(순서 구분함) | `1+2`와 `2+1`은 두 가지 | 바깥이 금액, 안쪽이 동전 |

```js
function combos(coins, target) {   // 순서 구분 안 함
  const dp = new Array(target + 1).fill(0)
  dp[0] = 1
  for (const c of coins) {
    for (let a = c; a <= target; a++) dp[a] += dp[a - c]
  }
  return dp[target]
}
```

금액을 바깥에 두면 순열이 됩니다.

```js
function perms(coins, target) {    // 순서 구분함
  const dp = new Array(target + 1).fill(0)
  dp[0] = 1
  for (let a = 1; a <= target; a++) {
    for (const c of coins) if (a >= c) dp[a] += dp[a - c]
  }
  return dp[target]
}
```

동전 `[1, 2, 3]`, 금액 4로 두 함수를 돌리면 결과가 다릅니다.

| 함수 | 결과 | 세어지는 것 |
|------|------|-------------|
| `combos` | 4 | `1+1+1+1`, `1+1+2`, `2+2`, `1+3` |
| `perms` | 7 | 위 넷에서 `1+1+2`가 세 가지 배열(`1+1+2`, `1+2+1`, `2+1+1`), `1+3`이 두 가지(`1+3`, `3+1`)로 늘어남 |

왜 순서가 이렇게 갈리는지는 dp가 채워지는 방식에서 나옵니다.

- 동전이 바깥이면 한 동전씩 차례로 허용 목록에 추가합니다. 동전 `c`를 처리하는 시점에는 앞서 처리한 동전 뒤에 `c`를 붙이는 경우만 세어서, 사용 순서가 항상 동전 목록 순서로 고정됩니다. 따라서 같은 집합이 한 번만 셉니다.
- 금액이 바깥이면 금액 `a`의 마지막 동전이 무엇인지로 나눠 셉니다. 마지막 동전이 `1`인 경우, `2`인 경우를 모두 합하므로 사용 순서가 다르면 다른 방법이 됩니다.

문제 문장의 단서는 보통 "순서가 다른 것은 다른 방법으로 센다"나 "구성이 같으면 한 가지로 센다"입니다. 계단을 1칸·2칸으로 오르는 방법의 수는 순서를 구분하는 경우이고 피보나치가 됩니다(자세히는 40편).

**흔한 실수:** 순서를 구분하지 않는 문제를 금액을 바깥에 두고 풀어 값이 부풀어 오르는 것입니다. 예제 하나만 손으로 세어 보면 둘을 구분할 수 있습니다.

## 최대 부분합

최대 부분합은 배열에서 연속한 구간의 합 중 최댓값을 구하는 문제입니다. 상태 `dp[i]`는 인덱스 `i`에서 끝나는 구간의 최대 합입니다. 구간은 `a[i]` 하나로 시작하거나 앞 구간에 이어 붙이는 두 경우뿐입니다.

$$
dp[i] = \max(a[i],\ dp[i-1] + a[i])
$$

- 답은 모든 `dp[i]` 중 최댓값입니다. 마지막 인덱스에서 끝난다는 보장이 없습니다.
- 이 방법을 카데인 알고리즘(Kadane)이라 부릅니다. `dp[i]`가 `dp[i-1]`에만 의존하므로 변수 하나로 줄어듭니다.

```js
function maxSubarray(a) {
  let cur = a[0], best = a[0]
  for (let i = 1; i < a.length; i++) {
    cur = Math.max(a[i], cur + a[i]) // 시작 vs 이어 붙이기
    best = Math.max(best, cur)
  }
  return best
}
maxSubarray([-2, 1, -3, 4, -1, 2, 1, -5, 4]) // 6
maxSubarray([-3, -1, -2])                     // -1
```

| i | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| a[i] | -2 | 1 | -3 | 4 | -1 | 2 | 1 | -5 | 4 |
| dp[i] | -2 | 1 | -2 | 4 | 3 | 5 | 6 | 1 | 5 |

- 시간 O(N), 공간 O(1)입니다. 같은 문제를 분할 정복으로 풀면 O(N log N)입니다(자세히는 25편).
- 빈 구간을 허용하는 문제라면 `cur = Math.max(0, cur + a[i])`로 바꾸고 `best`를 0으로 시작합니다.
- 구간 합을 누적합으로 구해 `prefix[j] - prefix[i]`의 최댓값을 보는 풀이도 있습니다(자세히는 29편).
- 앞 구간의 합이 음수이면 이어 붙일수록 손해이므로 버리고 새로 시작합니다. `Math.max(a[i], cur + a[i])`가 하는 일이 그것입니다.

**흔한 실수:** `cur`과 `best`를 0으로 시작하는 것입니다. 원소가 모두 음수인 배열에서 빈 구간의 합 0이 답으로 나옵니다. 첫 원소로 시작하거나 `-Infinity`로 시작합니다. 문제가 빈 구간을 허용하는지도 확인합니다.

## 배낭 문제

배낭 문제는 물건마다 무게와 가치가 있을 때, 무게 합이 용량 이하가 되도록 고른 물건의 가치 합을 최대로 하는 문제입니다. 각 물건을 한 번만 쓸 수 있는 형태가 0/1 배낭입니다. 물건마다 담거나(1) 담지 않는(0) 두 선택뿐이라서 0/1이라 부릅니다.

상태 `dp[i][w]`는 앞에서 `i`개 물건만 고려하고 용량이 `w`일 때의 최대 가치입니다. `i`번째 물건을 담지 않거나(`dp[i-1][w]`) 담는(`dp[i-1][w - 무게] + 가치`) 두 경우의 최댓값입니다.

$$
dp[i][w] = \max(dp[i-1][w],\ dp[i-1][w - w_i] + v_i)
$$

- `w_i`는 `i`번째 물건의 무게, `v_i`는 가치입니다.
- `w < w_i`이면 담을 수 없으므로 `dp[i-1][w]`입니다.
- 모든 `dp[0][w]`는 0입니다.
- 시간과 공간은 O(N × W)입니다. W는 용량이고 입력 길이가 아니라 값의 크기에 비례하므로, W가 매우 크면(예: 10^9) 쓸 수 없습니다.

2차원 표를 그대로 구현하면 다음과 같습니다. 항상 앞 행만 읽으므로 다음 절에서 줄입니다.

```js
function knapsack2d(items, cap) {
  const dp = Array.from({ length: items.length + 1 },
    () => new Array(cap + 1).fill(0))
  for (let i = 1; i <= items.length; i++) {
    const [w, v] = items[i - 1]
    for (let j = 0; j <= cap; j++) {
      dp[i][j] = dp[i - 1][j]
      if (j >= w) {
        dp[i][j] = Math.max(dp[i][j], dp[i - 1][j - w] + v)
      }
    }
  }
  return dp[items.length][cap]
}
```

물건 `[무게, 가치]`가 `[2,3]`, `[3,4]`, `[4,5]`, `[5,6]`이고 용량 5일 때, 물건을 하나씩 추가할 때마다 `dp[0..5]`가 이렇게 바뀝니다.

| 고려한 물건 | w=0 | w=1 | w=2 | w=3 | w=4 | w=5 |
|-------------|-----|-----|-----|-----|-----|-----|
| 없음 | 0 | 0 | 0 | 0 | 0 | 0 |
| (2, 3) | 0 | 0 | 3 | 3 | 3 | 3 |
| (3, 4) | 0 | 0 | 3 | 4 | 4 | 7 |
| (4, 5) | 0 | 0 | 3 | 4 | 5 | 7 |
| (5, 6) | 0 | 0 | 3 | 4 | 5 | 7 |

답은 7이며 물건 `(2,3)`과 `(3,4)`를 담은 경우입니다.

**흔한 실수:** 가치당 무게 비율이 좋은 물건부터 채우는 그리디로 푸는 것입니다. 물건을 쪼갤 수 있을 때만 그리디가 맞고, 쪼갤 수 없는 0/1 배낭에서는 틀릴 수 있습니다.

## 0/1 배낭과 무한 배낭의 반복 방향

물건 종류마다 개수 제한이 없는 형태를 무한 배낭(unbounded knapsack)이라 부릅니다. 2차원 표를 1차원으로 줄이면 두 배낭의 코드는 안쪽 반복문의 방향 하나만 다릅니다.

| 구분 | 물건 사용 | 안쪽 용량 반복 방향 |
|------|-----------|---------------------|
| 0/1 배낭 | 물건당 최대 한 번 | 큰 용량에서 작은 용량으로(내림차순) |
| 무한 배낭 | 제한 없음 | 작은 용량에서 큰 용량으로(오름차순) |

```js
function knap01(items, cap) {
  const dp = new Array(cap + 1).fill(0)
  for (const [w, v] of items) {
    for (let j = cap; j >= w; j--) {    // 내림차순
      dp[j] = Math.max(dp[j], dp[j - w] + v)
    }
  }
  return dp[cap]
}
```

무한 배낭은 안쪽 반복문의 방향만 오름차순으로 바꿉니다.

```js
function knapInf(items, cap) {
  const dp = new Array(cap + 1).fill(0)
  for (const [w, v] of items) {
    for (let j = w; j <= cap; j++) {    // 오름차순
      dp[j] = Math.max(dp[j], dp[j - w] + v)
    }
  }
  return dp[cap]
}
```

방향이 결과를 바꾸는 이유는 `dp[j - w]`가 무엇을 가리키는지에 있습니다.

- 내림차순이면 `dp[j]`를 갱신할 때 `dp[j - w]`는 아직 이번 물건으로 갱신되지 않은 값, 즉 이전 행의 값입니다. 2차원의 `dp[i-1][j - w]`와 같아서 물건을 한 번만 씁니다.
- 오름차순이면 `dp[j - w]`가 이미 이번 물건을 반영한 값, 즉 현재 행의 값입니다. 같은 물건이 계속 추가될 수 있어서 무한 배낭이 됩니다. 2차원으로 쓰면 `dp[i][j - w]`에 해당합니다.

물건 하나 `(무게 2, 가치 3)`, 용량 5로 두 방향을 비교하면 차이가 보입니다.

| 방향 | dp[0..5] | dp[5] |
|------|----------|-------|
| 내림차순(0/1) | 0 0 3 3 3 3 | 3 |
| 오름차순 | 0 0 3 3 6 6 | 6 |

- 무한 배낭의 오름차순은 물건 `(2,3)`을 두 번 써서 `dp[4] = 6`이 됩니다. 0/1 문제에 오름차순을 쓰면 이 값이 답에 섞입니다.
- 앞의 동전 DP는 무한 배낭입니다. 동전은 개수 제한이 없고 안쪽 금액이 오름차순입니다.
- 물건마다 개수 제한이 있는 형태는 개수만큼 물건을 복제해 0/1로 바꿀 수 있습니다. 개수가 크면 2의 거듭제곱 개씩 묶어 복제하는 이진 분할로 줄입니다.

**흔한 실수:** 0/1 배낭 코드를 쓰다가 안쪽 반복문을 습관적으로 오름차순으로 쓰는 것입니다. 작은 입력에서는 답이 맞아 보이기도 해서 놓치기 쉽습니다. 용량이 물건 무게의 두 배 이상인 반례를 하나 손으로 돌려 봅니다.

## 부분집합 합 DP

부분집합 합(subset sum)은 주어진 수들 중 일부를 골라 합이 정확히 목표 `T`가 되게 할 수 있는지 판단하는 문제입니다. 0/1 배낭에서 무게와 가치가 같고 "정확히 `T`"만 따지는 특수한 경우입니다.

상태 `dp[s]`는 합 `s`를 만들 수 있는지(불리언)입니다. `dp[0] = true`이고, 수 `x`를 쓸 때 `dp[s - x]`가 참이면 `dp[s]`도 참입니다. 각 수를 한 번만 쓰므로 `s`는 내림차순입니다.

```js
function subsetSum(nums, target) {
  const dp = new Array(target + 1).fill(false)
  dp[0] = true
  for (const x of nums) {
    for (let s = target; s >= x; s--) {
      if (dp[s - x]) dp[s] = true
    }
  }
  return dp[target]
}
subsetSum([3, 34, 4, 12, 5, 2], 9) // true (4 + 5)
```

- 시간은 O(N × T), 공간은 O(T)입니다. T의 크기에 비례하는 의사 다항 시간입니다.
- 부분집합 합 문제 자체는 NP-완전 문제로 알려져 있습니다. T가 작을 때만 이 DP가 통합니다.
- 합이 `T`가 되는 부분집합의 개수를 세려면 불리언 대신 개수를 더합니다. 점화식은 `dp[s] += dp[s - x]`이고 내림차순을 지킵니다.

```js
const dp = new Array(7).fill(0)
dp[0] = 1
for (const x of [1, 2, 3, 3]) {
  for (let s = 6; s >= x; s--) dp[s] += dp[s - x]
}
// dp: [1, 1, 1, 3, 2, 2, 3] (합 6은 3개)
```

- 같은 값이 둘인 `3`은 서로 다른 원소로 셉니다. 값이 같은 집합을 한 번만 세려면 다른 방법이 필요합니다.
- 목표가 전체 합의 절반이면 "두 그룹으로 나눠 합을 같게 하는가"가 됩니다. 두 그룹의 합 차이를 최소로 하는 문제는 가능한 합을 모두 구한 뒤 전체 합의 절반에 가장 가까운 값을 고릅니다.
- 가능한 합의 집합을 `BigInt` 비트마스크 하나로 들고 다닐 수 있습니다. `mask |= mask << BigInt(x)`로 갱신하고 `(mask >> BigInt(t)) & 1n`으로 확인합니다. 시프트마다 비트 전체를 처리하므로 T가 크면 불리언 배열보다 빠를 수 있습니다(자세히는 24편).

**흔한 실수:** 합 0의 처리입니다. `dp[0] = true`를 빼면 모든 칸이 거짓이 됩니다. 또 수가 음수이면 `s - x`가 배열 범위를 벗어나므로 이 형태로는 풀리지 않고, 합의 범위를 평행 이동해야 합니다.

## Rolling Array

롤링 배열(rolling array)은 `dp[i]`가 바로 앞 행 `dp[i-1]`에만 의존할 때 모든 행을 저장하지 않고 필요한 행만 번갈아 쓰는 기법입니다. 2차원 표의 메모리가 O(NM)에서 O(M)으로 줄어듭니다.

앞의 최소 경로 합은 위 행과 왼쪽 칸만 읽습니다. 행 두 개를 번갈아 씁니다.

```js
function minPathRolling(g) {
  const m = g[0].length
  let prev = new Array(m).fill(Infinity)
  for (let i = 0; i < g.length; i++) {
    const cur = new Array(m).fill(0)
    for (let j = 0; j < m; j++) {
      if (i === 0 && j === 0) { cur[0] = g[0][0]; continue }
      const up = i > 0 ? prev[j] : Infinity
      const left = j > 0 ? cur[j - 1] : Infinity
      cur[j] = g[i][j] + Math.min(up, left)
    }
    prev = cur
  }
  return prev[m - 1]
}
```

- `prev`는 위 행, `cur`는 지금 채우는 행입니다. 한 행이 끝나면 `prev = cur`로 바꿉니다.
- 행마다 새 배열을 만드는 대신 `dp[i % 2]`로 두 배열을 재사용하는 방식도 있습니다. 배열을 새로 만들지 않아 할당이 줄어듭니다.
- 롤링 배열이 쓸 수 있는 조건은 `dp[i]`가 앞의 일정한 개수의 행에만 의존하는 것입니다. 앞 두 행에 의존하면 세 행을 돌립니다.
- 시간복잡도는 그대로고 공간만 줄어듭니다. 행 수가 수천이고 열 수가 수천이면 표 전체의 메모리가 한계를 넘을 수 있어서 쓰입니다(자세히는 14편).
- 중간 행들이 필요한 문제에는 쓸 수 없습니다. 경로 복원이 그렇습니다(다음 절과 42편).

**흔한 실수:** `prev = cur`로 같은 배열을 가리키게 한 뒤 다음 행에서 `cur`를 재사용하는 것입니다. `cur`가 `prev`와 같은 배열이 되어 읽을 값이 덮어씌워집니다. 새 배열을 만들거나 두 배열을 교환(`[prev, cur] = [cur, prev]`)해서 서로 다른 배열이 되게 합니다.

## 공간 최적화 DP

공간 최적화 DP는 점화식이 읽는 이전 상태만 남기고 나머지를 버려 메모리를 줄이는 방법의 통칭입니다. 롤링 배열은 그중 한 모양입니다. 줄이는 모양은 의존하는 범위로 정합니다.

| 의존하는 범위 | 줄이는 방법 | 예 |
|---------------|-------------|----|
| 바로 앞 한두 값 | 변수 몇 개 | 피보나치, 최대 부분합 |
| 앞 행 전체 | 행 두 개 번갈아 쓰기 | 격자 경로, 문자열 DP |
| 앞 행의 같은 열과 이전 열 | 행 하나를 제자리 갱신 | 0/1·무한 배낭 |

제자리 갱신으로 줄일 때는 읽는 값이 아직 덮어쓰이지 않았거나 이미 덮어쓰였는지가 점화식과 맞아야 합니다. 앞의 배낭에서 본 방향 규칙이 그것입니다. 최소 경로 합은 행 하나로 줄일 수 있습니다. 위 칸은 갱신 전 값이고, 왼쪽 칸은 갱신 후 값이라서 오름차순으로 한 번에 처리됩니다.

```js
function minPathOneRow(g) {
  const m = g[0].length
  const row = new Array(m).fill(Infinity)
  row[0] = 0
  for (let i = 0; i < g.length; i++) {
    for (let j = 0; j < m; j++) {
      const left = j > 0 ? row[j - 1] : Infinity
      row[j] = g[i][j] + Math.min(row[j], left)
    }
  }
  return row[m - 1]
}
```

- `row[j]`를 갱신하기 전의 값이 위 칸(`dp[i-1][j]`)이고 `row[j-1]`은 이미 갱신된 값이 왼쪽 칸(`dp[i][j-1]`)입니다. 첫 행에서는 `row[0] = 0`에서 출발해 `row[j]`가 `Infinity`이므로 왼쪽만 이어집니다.
- 공간은 O(M)이고 표 전체를 저장하던 O(NM)보다 작습니다.
- 최적화 전에 정답이 맞는 풀이를 먼저 만들고, 최적화 결과를 원래 풀이와 비교합니다.

줄이면 잃는 것도 있습니다.

- 최적 선택의 경로를 복원해야 하면 줄이기 전의 표나 선택 기록이 필요합니다(자세히는 42편).
- 한 행을 제자리로 갱신하면 점화식의 의존 방향이 코드 순서에 숨어서 틀리기 쉽습니다. 방향을 바꾸거나 의존 범위가 달라지면 결과가 조용히 틀립니다.

**흔한 실수:** 메모리 한계가 넉넉한데 처음부터 최적화하는 것입니다. 2차원 표가 한계 안에 들어가면 표 그대로 쓰는 편이 디버깅이 쉽습니다. 최적화는 메모리 초과가 실제로 날 때 합니다.

## 핵심 정리

- 2차원 DP는 상태가 인덱스 두 개이고, 의존하는 방향에 맞춰 채우는 순서를 정합니다. 격자 경로는 위·왼쪽에 의존하므로 모두 증가 방향으로 돕니다.
- 동전 최소 개수는 `Infinity`로 시작해 불가능을 표현하고, 경우의 수는 동전을 바깥에 두면 조합, 금액을 바깥에 두면 순열을 셉니다.
- 최대 부분합은 `dp[i] = max(a[i], dp[i-1] + a[i])`이며 답은 모든 `dp[i]`의 최댓값입니다.
- 1차원 배낭에서 용량을 내림차순으로 돌면 0/1(물건당 한 번), 오름차순이면 무한 배낭입니다.
- 부분집합 합은 `dp[0] = true`에서 내림차순으로 `dp[s]`를 채우고, 시간은 O(N × T)입니다.
- 롤링 배열과 제자리 갱신은 필요한 이전 상태만 남겨 메모리를 줄이지만, 경로 복원에는 쓸 수 없습니다.
