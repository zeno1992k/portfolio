## Binary Search

이분 탐색(binary search)은 정렬된 배열에서 찾는 값을 후보 구간의 가운데와 비교해, 매번 후보를 절반으로 줄이는 탐색입니다. 후보가 N개면 비교는 최대 log2(N)을 내림한 값에 1을 더한 횟수이고 시간은 O(log N)입니다. 배열이 정렬되어 있어야 하고, 정렬되어 있지 않으면 결과가 틀립니다.

```js
function binarySearch(a, x) {      // a는 오름차순
  let lo = 0, hi = a.length - 1    // 후보 구간 [lo, hi]
  while (lo <= hi) {
    const mid = Math.floor((lo + hi) / 2)
    if (a[mid] === x) return mid
    if (a[mid] < x) lo = mid + 1   // 오른쪽 절반
    else hi = mid - 1              // 왼쪽 절반
  }
  return -1                        // 없음
}
binarySearch([1, 3, 5, 7, 9, 11], 7) // 3
```

`[1, 3, 5, 7, 9, 11]`에서 7을 찾는 과정입니다.

| 단계 | lo | hi | mid | a[mid] | 판정 |
|------|----|----|-----|--------|------|
| 1 | 0 | 5 | 2 | 5 | 5는 7보다 작아 lo = 3 |
| 2 | 3 | 5 | 4 | 9 | 9는 7보다 커서 hi = 3 |
| 3 | 3 | 3 | 3 | 7 | 찾음, 3 반환 |

- 배열 메서드 `indexOf`·`includes`는 앞에서부터 훑어 O(N)입니다. 정렬된 큰 배열을 여러 번 탐색하면 이분 탐색이 이깁니다.
- 이분 탐색의 본질은 "구간을 절반으로 버려도 답이 남아 있는가"입니다. 그래서 정렬 말고도 한쪽으로만 바뀌는 성질(단조성)이 있으면 적용됩니다(아래 "결정 문제").
- 정렬하는 데 O(N log N)이 들므로 한 번만 찾는 질의에는 O(N) 탐색이 낫습니다. 같은 배열에 질의가 많을 때 정렬 후 이분 탐색을 씁니다(정렬은 26편).

**흔한 실수:** 정렬하지 않은 배열에 이분 탐색을 쓰는 것, 그리고 `[lo, hi]`와 `[lo, hi)` 규칙을 섞어 쓰는 것입니다(다음 절).

## left / right / mid

이분 탐색 버그의 대부분은 구간 규칙이 일관되지 않아서 생깁니다. 두 가지 규칙 중 하나를 골라 끝까지 지킵니다.

| 항목 | 닫힌 구간 `[lo, hi]` | 반열린 구간 `[lo, hi)` |
|------|----------------------|------------------------|
| 초기값 | lo = 0, hi = N - 1 | lo = 0, hi = N |
| 반복 조건 | `lo <= hi` | `lo < hi` |
| 왼쪽을 버릴 때 | `lo = mid + 1` | `lo = mid + 1` |
| 오른쪽을 버릴 때 | `hi = mid - 1` | `hi = mid` |
| 종료 시 | 구간이 비어 `lo > hi` | `lo === hi`가 경계 위치 |
| 잘 맞는 용도 | 값이 있는지 찾기 | 경계(Lower·Upper Bound) 찾기 |

- 닫힌 구간은 `mid`를 검사했으니 양쪽에서 `mid`를 제외합니다(`mid + 1`, `mid - 1`).
- 반열린 구간은 `hi`를 후보에 포함하지 않으므로 `hi = mid`로 둡니다. 경계 문제에서는 `lo`가 마지막에 경계 위치를 가리켜서 따로 `-1` 같은 보정이 필요 없습니다.
- 반복마다 구간이 반드시 줄어야 끝납니다. 위 표의 갱신은 항상 구간을 줄입니다.

`mid`는 `Math.floor((lo + hi) / 2)`로 구합니다. C++·Java의 `int`는 `lo + hi`가 넘칠 수 있어 `lo + (hi - lo) / 2`로 쓰지만, JavaScript의 `Number`는 2^53 근처까지 정확해서 `(lo + hi) / 2`가 안전합니다(자세히는 02편).

- 배열 인덱스처럼 값이 2^31 미만이면 `(lo + hi) >> 1`도 됩니다. 비트 연산이 32비트 정수로 바뀌기 때문입니다(24편). 정답 범위가 2^31 이상이면 `>> 1`은 틀립니다.
- 범위가 10^18 같은 값이면 `lo + hi`가 2^53을 넘어 정밀도를 잃습니다. 이때는 `BigInt`를 써서 `(lo + hi) / 2n`으로 구합니다. BigInt 나눗셈은 0 방향으로 버려서 양수에서 내림과 같습니다.
- 닫힌 구간에서 `lo = mid`처럼 `mid`를 그대로 두는 갱신을 쓰면 `mid`가 `lo`와 같아질 때 무한 반복합니다. 그런 갱신이 필요한 경우(최댓값을 찾을 때)는 `mid`를 올림으로 구합니다(아래 "최솟값의 최댓값").

**시험에서 묻는 방식:** 갱신식을 `hi = mid`나 `mid - 1` 중 무엇으로 쓰는지, 반복 조건이 `<`인지 `<=`인지를 구간 규칙과 맞춰 고르게 합니다.

## Lower Bound

Lower Bound는 정렬된 배열에서 값 `x` 이상인 첫 번째 위치입니다. `x`를 넣어도 순서가 유지되는 가장 왼쪽 위치와 같고, 그런 값이 없으면 `a.length`입니다.

```js
function lowerBound(a, x) {   // 첫 a[i] >= x, 없으면 a.length
  let lo = 0, hi = a.length   // [lo, hi)
  while (lo < hi) {
    const mid = (lo + hi) >> 1
    if (a[mid] < x) lo = mid + 1   // x 미만은 버린다
    else hi = mid                  // x 이상은 후보로 남긴다
  }
  return lo
}
```

`[1, 2, 2, 2, 5]`에서 `lowerBound(a, 2)`의 과정입니다.

| 단계 | lo | hi | mid | a[mid] | 판정 |
|------|----|----|-----|--------|------|
| 1 | 0 | 5 | 2 | 2 | 2 미만 아님, hi = 2 |
| 2 | 0 | 2 | 1 | 2 | 2 미만 아님, hi = 1 |
| 3 | 0 | 1 | 0 | 1 | 2 미만, lo = 1 |
| 종료 | 1 | 1 | | | 1 반환 |

- 조건 `a[mid] < x`가 참인 칸은 모두 `x` 미만이라는 점이 핵심입니다. 배열은 `x` 미만 구간 다음에 `x` 이상 구간이 이어지므로 경계가 하나뿐입니다.
- 같은 값이 여러 개여도 가장 왼쪽 위치를 줍니다. 찾는 값이 없으면 그 값이 들어갈 위치를 줍니다. `lowerBound([1, 2, 2, 2, 5], 3)`은 4이고, `lowerBound(a, 0)`은 0, `lowerBound(a, 9)`는 5입니다.
- Python의 `bisect_left`, C++의 `lower_bound`와 같은 함수입니다. JavaScript에는 내장이 없어서 직접 만듭니다.
- 값이 있는지는 `i < a.length && a[i] === x`로 확인합니다. 인덱스가 범위를 벗어날 수 있으므로 길이 검사를 먼저 합니다.

**흔한 실수:** 결과가 `a.length`일 수 있다는 것을 잊고 `a[result]`를 바로 읽어 `undefined`를 얻는 것입니다.

## Upper Bound

Upper Bound는 정렬된 배열에서 값 `x`보다 큰 첫 번째 위치입니다. Lower Bound와 비교 연산 하나만 다릅니다(`<`가 `<=`).

```js
function upperBound(a, x) {   // 첫 a[i] > x, 없으면 a.length
  let lo = 0, hi = a.length
  while (lo < hi) {
    const mid = (lo + hi) >> 1
    if (a[mid] <= x) lo = mid + 1  // x 이하는 버린다
    else hi = mid                  // x 초과는 후보로 남긴다
  }
  return lo
}
```

`[1, 2, 2, 2, 5]`에서 `upperBound(a, 2)`의 과정입니다.

| 단계 | lo | hi | mid | a[mid] | 판정 |
|------|----|----|-----|--------|------|
| 1 | 0 | 5 | 2 | 2 | 2 이하, lo = 3 |
| 2 | 3 | 5 | 4 | 5 | 2 이하 아님, hi = 4 |
| 3 | 3 | 4 | 3 | 2 | 2 이하, lo = 4 |
| 종료 | 4 | 4 | | | 4 반환 |

| 함수 | 반환하는 위치 | 앞쪽 구간의 조건 |
|------|---------------|------------------|
| Lower Bound | 첫 `a[i] >= x` | 앞은 모두 `x`보다 작다 |
| Upper Bound | 첫 `a[i] > x` | 앞은 모두 `x` 이하이다 |

- 두 함수 모두 `x`를 넣어도 정렬이 유지되는 위치입니다. Lower Bound는 같은 값의 왼쪽, Upper Bound는 오른쪽에 넣습니다.
- 정수 배열에서는 `upperBound(a, x)`가 `lowerBound(a, x + 1)`과 같습니다.
- 공식 문서의 정의도 같습니다. Python `bisect_left`는 반환 위치의 왼쪽이 모두 `x`보다 작고, `bisect_right`는 왼쪽이 모두 `x` 이하입니다. C++ `lower_bound`는 `x`보다 앞서지 않는 첫 원소를 줍니다.

## 중복값 탐색

Lower Bound와 Upper Bound를 함께 쓰면 중복값의 처리가 한 줄로 끝납니다.

| 구하려는 것 | 식 |
|-------------|----|
| 첫 등장 위치 | `lowerBound(a, x)` (값이 있을 때) |
| 마지막 등장 위치 | `upperBound(a, x) - 1` (값이 있을 때) |
| 개수 | `upperBound(a, x) - lowerBound(a, x)` |
| 존재 여부 | 개수가 1 이상 |
| 구간 `[x, y]`에 속하는 값의 개수 | `upperBound(a, y) - lowerBound(a, x)` |
| `x`보다 작은 값의 개수 | `lowerBound(a, x)` |
| `x` 이하인 값의 개수 | `upperBound(a, x)` |

```js
const a = [1, 2, 2, 2, 5]
const count = upperBound(a, 2) - lowerBound(a, 2) // 3
const first = lowerBound(a, 2)                    // 1
const last = upperBound(a, 2) - 1                 // 3
const inRange = upperBound(a, 5) - lowerBound(a, 2)
// 4 (2 이상 5 이하)
```

- 값이 없으면 개수가 0이라 첫·마지막 위치는 의미가 없습니다. 개수를 먼저 확인합니다.
- 일반 이분 탐색은 같은 값이 여럿일 때 그중 어느 위치를 줄지 정해져 있지 않습니다. 위치가 필요하면 Lower·Upper Bound를 씁니다.
- 질의가 Q번이면 O(Q log N)입니다. 같은 일을 해시(10편)로 하면 개수는 O(1)이지만, 구간 개수나 "x보다 작은 값의 개수" 같은 순서 질의는 이분 탐색이 필요합니다.
- 정렬된 두 배열에서 공통 값의 개수를 셀 때는 한쪽을 이분 탐색하거나 투 포인터(30편)를 씁니다.

## 결정 문제

결정 문제(decision problem)는 후보 값 `x`가 조건을 만족하는지 참·거짓으로 답하는 문제입니다. 이분 탐색은 `x`를 키워 가며 결과가 `거짓, 거짓, ..., 참, 참`처럼 한 번만 바뀌는 단조성이 있을 때 쓸 수 있습니다.

```
x:      1  2  3  4  5  6  7  8
참거짓: F  F  F  T  T  T  T  T   ← 첫 T의 위치를 찾는다
```

이 "첫 참의 위치 찾기"가 이분 탐색의 일반형이고, Lower Bound도 그 한 경우입니다(`a[i] >= x`가 참거짓). 정수 범위에서 처음으로 조건이 참이 되는 값을 구하는 함수를 한 번 만들어 두면 이후 모든 문제에 씁니다.

```js
function firstTrue(lo, hi, pred) {  // [lo, hi]에서 첫 true
  hi++                              // 반열린 구간 [lo, hi)
  while (lo < hi) {
    const mid = Math.floor((lo + hi) / 2)
    if (pred(mid)) hi = mid         // 참이면 왼쪽도 확인
    else lo = mid + 1
  }
  return lo                         // 참이 없으면 원래 hi + 1
}
```

- 같은 함수로 Lower Bound를 쓰면 `firstTrue(0, a.length - 1, (i) => a[i] >= x)`입니다. 참이 없으면 `a.length`를 돌려줍니다.
- 참거짓이 `참, 참, ..., 거짓, 거짓`이면 마지막 참의 위치를 구합니다. 조건을 뒤집어 첫 거짓을 찾고 1을 뺍니다: `firstTrue(lo, hi, (x) => !pred(x)) - 1`.
- 단조성이 성립하는지 확인하는 것이 먼저입니다. "x가 커질수록 조건을 만족하기 쉬워지는가(또는 어려워지는가)"를 묻습니다. 성립하지 않으면 이분 탐색을 쓸 수 없습니다.
- 정렬된 배열은 단조성의 특수한 경우입니다. `a[i] >= x`가 인덱스에 대해 단조이기 때문입니다.

**시험에서 묻는 방식:** 조건이 단조인지 판단하게 하거나, 첫 참과 마지막 참 중 무엇을 구하는지에 따라 갱신식을 고르게 합니다.

## Parametric Search

파라메트릭 서치(parametric search)는 "조건을 만족하는 값 중 최소(또는 최대)를 구하라"는 최적화 문제를 "값 `x`가 가능한가"라는 결정 문제로 바꿔 이분 탐색으로 푸는 방법입니다. 답을 직접 만드는 대신 답을 추측하고 검증합니다.

풀이 틀은 세 단계입니다.

1. 답의 후보 범위 `[lo, hi]`를 정한다.
2. 후보 `x`가 가능한지 검사하는 함수 `can(x)`를 만든다. 이 검사는 보통 그리디나 단순 반복문이다.
3. `can`이 단조인 것을 이용해 경계를 이분 탐색한다.

- 전체 시간은 O(검사 비용 × log(범위 크기))입니다. 범위가 10^9이면 반복이 약 30번, 10^18이면 약 60번입니다.
- 검사 함수를 O(N)에 만들 수 있으면 전체가 O(N log 범위)가 되어 N이 10^5–10^6이어도 풀립니다.
- 문제의 단서는 "최댓값을 최소화", "최솟값을 최대화", "N이 크고 답의 범위도 크다", 그리고 답이 하나의 정수나 실수로 나온다는 점입니다.
- 답을 직접 구하는 완전탐색은 범위 전체를 보지만, 파라메트릭 서치는 범위의 로그만 봅니다.

## 정답 범위 설정

이분 탐색 전에 `lo`와 `hi`를 정확히 정해야 합니다. 범위가 틀리면 정답이 범위 밖에 있거나, 검사 함수가 정의되지 않는 값(0 나눗셈 등)에 걸립니다.

| 문제 유형 | lo | hi |
|-----------|----|----|
| 거리·길이를 최대화 | 1 (가능한 최소 단위) | 좌표 최댓값 - 최솟값 |
| 구간 합의 최댓값을 최소화 | 요소 중 최댓값 | 전체 합 |
| 시간·횟수를 최소화 | 0 또는 1 | 모두 하나씩 처리하는 시간 |
| 자르는 길이를 최대화 | 1 | 가장 긴 막대의 길이 |

- `lo`는 "정답이 이보다 작을 수 없는 값", `hi`는 "정답이 이보다 클 수 없는 값"입니다. 둘 다 정답 후보에 포함되는 경계로 잡습니다.
- 정답이 존재하지 않을 수 있는 문제는 `hi` 뒤에 한 칸을 더 둡니다. 위 `firstTrue`가 참이 없으면 `hi + 1`을 돌려주므로 그 값으로 불가능을 구별합니다.
- `lo`가 너무 작으면 검사에서 문제가 생깁니다. 길이 0으로 나누는 검사는 `lo`를 1부터 시작합니다.
- `hi`는 넉넉히 잡아도 반복 횟수가 로그로만 늘어서 시간 영향이 작습니다. 다만 검사 함수 안의 곱셈이 `Number`의 정확한 정수 범위(2^53 - 1)를 넘지 않는지 확인합니다. 넘으면 `BigInt`로 바꿉니다(자세히는 02편).
- 범위 계산은 입력 제한에서 구합니다. 제한을 모르면 `hi`를 임의로 잡지 않습니다.

```js
// 범위가 10^18이면 BigInt로 mid를 구한다
function bigFirstTrue(lo, hi, pred) {   // 모두 BigInt
  hi++
  while (lo < hi) {
    const mid = (lo + hi) / 2n          // 양수에서 내림
    if (pred(mid)) hi = mid
    else lo = mid + 1n
  }
  return lo
}
bigFirstTrue(0n, 10n ** 18n, (x) => x * x >= 10n ** 30n)
// 1000000000000000n
```

## 최솟값의 최댓값

"최솟값을 가능한 한 크게 만든다"(maximize the minimum)는 유형입니다. 답 `d`를 정하면 "모든 값이 `d` 이상이 되도록 할 수 있는가"를 검사합니다. `d`가 작을수록 만족하기 쉽습니다.

직접 만든 문제입니다.

> 일직선 위의 집 좌표가 오름차순으로 주어진다. 집 중 `c`곳에 장비를 놓을 때, 이웃한 장비 사이 거리의 최솟값을 가능한 한 크게 한다. 그 최댓값을 구하라.

`can(d)`는 "이웃 거리가 모두 `d` 이상이게 `c`곳 이상 놓을 수 있는가"입니다. 앞에서부터 그리디하게 놓으면 됩니다. 거리 `d`는 클수록 어려워서 결과가 `참, 참, ..., 거짓`이므로 마지막 참을 구합니다.

```js
function maxMinDistance(houses, c) {   // houses 오름차순
  const can = (d) => {
    let count = 1, last = houses[0]    // 첫 집에 놓는다
    for (const h of houses) {
      if (h - last >= d) { count++; last = h }
    }
    return count >= c
  }
  const span = houses[houses.length - 1] - houses[0]
  return firstTrue(1, span + 1, (d) => !can(d)) - 1
}
maxMinDistance([1, 2, 4, 8, 9], 3) // 3
```

| d | 놓는 위치 | 개수 | can(d) |
|---|-----------|------|--------|
| 3 | 1, 4, 8 | 3 | 참 |
| 4 | 1, 8 | 2 | 거짓 |

- 거리 3은 가능하고 4는 불가능하므로 답은 3입니다. 이분 탐색은 `d`를 1부터 8까지 중 참에서 거짓으로 바뀌는 경계를 찾습니다.
- 검사는 O(N)이고 `d`의 범위는 최대 좌표 차이이므로 전체 O(N log(좌표 차이))입니다. 집을 정렬하는 O(N log N)이 앞에 필요합니다.
- 닫힌 구간 `[lo, hi]`로 직접 쓰면 최댓값을 찾는 갱신이 `lo = mid`가 되어 `mid`를 올림해야 합니다.

```js
let lo = 1, hi = span
while (lo < hi) {
  const mid = Math.floor((lo + hi + 1) / 2)  // 올림
  if (can(mid)) lo = mid
  else hi = mid - 1
}
// lo가 답. mid를 내림으로 쓰면 lo = mid가 제자리라 무한 반복
```

**흔한 실수:** 마지막 참을 찾는데 `mid`를 내림으로 구해 `lo = mid`에서 무한 반복하는 것입니다. 첫 참을 찾는 형태(`firstTrue`)로 쓰면 이 문제가 없어서 안전합니다.

## 최댓값의 최솟값

"최댓값을 가능한 한 작게 만든다"(minimize the maximum)는 유형입니다. 답 `L`을 정하면 "모든 값이 `L` 이하가 되도록 할 수 있는가"를 검사합니다. `L`이 클수록 만족하기 쉬워서 결과가 `거짓, ..., 참, 참`입니다. 첫 참을 구합니다.

직접 만든 문제입니다.

> 양의 정수 배열을 순서를 바꾸지 않고 정확히 `m`개 이하의 연속 구간으로 나눈다. 구간 합의 최댓값을 가능한 한 작게 할 때 그 값을 구하라.

`can(L)`은 "구간 합이 모두 `L` 이하가 되게 `m`개 이하로 나눌 수 있는가"입니다. 앞에서부터 합이 `L`을 넘기 직전까지 한 구간으로 묶는 그리디로 필요한 구간 수를 셉니다.

```js
function minMaxSum(a, m) {
  const groups = (limit) => {          // 필요한 구간 수
    let count = 1, sum = 0
    for (const x of a) {
      if (sum + x > limit) { count++; sum = 0 }
      sum += x
    }
    return count
  }
  let lo = 0, hi = 0
  for (const x of a) { lo = Math.max(lo, x); hi += x }
  return firstTrue(lo, hi, (L) => groups(L) <= m)
}
minMaxSum([7, 2, 5, 10, 8], 2) // 18
```

| L | 나눈 결과 | 구간 수 | m이 2일 때 |
|---|-----------|---------|------------|
| 17 | 7 2 5 / 10 / 8 | 3 | 불가 |
| 18 | 7 2 5 / 10 8 | 2 | 가능 |

- `lo`는 가장 큰 요소입니다. `L`이 그보다 작으면 그 요소가 어떤 구간에도 들어가지 못합니다. `hi`는 전체 합이고 이때 구간 수는 1입니다(정답 범위 설정).
- `m`을 늘릴수록 답이 작아집니다. `[7, 2, 5, 10, 8]`에서 `m`이 3이면 14, `m`이 5이면 10입니다.
- 유형 구분: 두 유형 모두 `can` 안에서 그리디로 개수를 셉니다. 최솟값의 최댓값은 "개수가 충분한가", 최댓값의 최솟값은 "구간 수가 한도 이내인가"입니다.
- 비슷한 문제로 작업 시간 합계의 최대를 줄이는 기계 배정, 짐을 `D`일에 나눠 싣는 최소 용량 문제가 있습니다.

## 실수 이분 탐색 개념

실수 이분 탐색은 값이 정수가 아닌 구간에서 경계를 찾는 방법입니다. 정수 이분 탐색의 `mid + 1`, `mid - 1`이 없고 `lo = mid` 또는 `hi = mid`로 그대로 둡니다. 연속인 실수는 한 칸 단위가 없기 때문입니다.

```js
function sqrtBinary(x) {              // x는 0 이상
  let lo = 0, hi = Math.max(1, x)
  for (let it = 0; it < 100; it++) {  // 횟수를 고정
    const mid = (lo + hi) / 2
    if (mid * mid < x) lo = mid
    else hi = mid
  }
  return lo
}
sqrtBinary(2).toFixed(6) // '1.414214'
```

- 종료 조건은 반복 횟수를 고정하는 방식을 권합니다. 구간이 반으로 줄므로 `R`을 `ε`까지 줄이려면 log2(R/ε)번이면 됩니다. 100번이면 일반적인 범위에서 `Number`의 정밀도 한계까지 갑니다.
- `while (hi - lo > eps)`로 쓰면 값이 크거나 `eps`가 너무 작을 때 끝나지 않습니다. `Number`는 값이 클수록 인접한 수 사이의 간격이 커집니다. 10^18 근처에서는 간격이 128이라 `hi - lo`가 `1e-9` 아래로 줄지 않아서 무한 반복합니다.
- 결과를 `lo`와 `hi` 중 무엇으로 쓸지는 거의 차이가 없지만, 출력할 때는 문제가 요구하는 자릿수로 `toFixed`로 맞춥니다. `lo` 값 자체는 `0.49999999999999994`처럼 정확한 값에서 미세하게 어긋날 수 있습니다(`sqrtBinary(0.25)`).
- 결정 문제의 단조성은 정수와 같이 필요합니다. 예를 들어 "속도가 `v`일 때 시간 안에 도착하는가"는 `v`가 클수록 참입니다.
- 정답을 정수로 낼 수 있는 문제(최소 정수 `x`)는 정수 이분 탐색이 정확해서 더 안전합니다. 실수 이분 탐색은 연속 값(거리, 속도, 시간, 방정식의 해)에만 씁니다.
- 문제의 단서는 "오차 10^-6 이내", "소수점 아래 몇 자리까지 출력"입니다.

**흔한 실수:** 실수 비교 `===`로 정답을 판정하는 것입니다. 부동소수점 오차 때문에 정확히 같아지지 않아서 항상 범위(`<`, `>=`)와 횟수 기준으로 판정합니다(부동소수점 오차는 02편).

## Binary Search on Answer

Binary Search on Answer는 정답이 될 값의 범위를 놓고 이분 탐색하며, 각 후보를 검사 함수로 확인하는 풀이 방식입니다. 앞의 파라메트릭 서치와 같은 뜻으로 쓰이고, 정답이 배열의 원소가 아니라 직접 정하는 수인 점이 일반 이분 탐색과 다릅니다.

적용 절차는 다음과 같습니다.

| 순서 | 할 일 | 점검할 것 |
|------|-------|-----------|
| 1 | 구하는 값을 하나의 수 `x`로 잡는다 | 정답이 정수인가, 실수인가 |
| 2 | 범위 `[lo, hi]`를 정한다 | 정답이 반드시 포함되는가 |
| 3 | `can(x)`를 만든다 | 계산량이 O(N) 안팎인가 |
| 4 | 단조성을 확인한다 | `x`가 커질 때 결과가 한 번만 바뀌는가 |
| 5 | 최소면 첫 참, 최대면 마지막 참을 구한다 | 갱신식이 구간 규칙과 맞는가 |

직접 만든 문제로 전체를 한 번 거칩니다.

> 길이가 정수인 막대 N개가 있다. 막대를 정수 길이 `L`로 잘라 길이 `L` 조각을 `k`개 이상 얻으려 한다. 가능한 `L`의 최댓값을 구하라(조각 하나는 한 막대에서만 나온다).

1. 구하는 값은 `L`이고 정수입니다.
2. `lo`는 1, `hi`는 가장 긴 막대 길이입니다.
3. `pieces(L)`은 `L`로 자른 조각의 합이며 각 막대마다 `Math.floor(x / L)`입니다.
4. `L`이 클수록 조각이 줄어드므로 `pieces(L) >= k`는 `참, ..., 참, 거짓`입니다.
5. 마지막 참을 구하므로 첫 거짓에서 1을 뺍니다.

```js
function maxCutLength(sticks, k) {
  const pieces = (L) => {
    let sum = 0
    for (const x of sticks) sum += Math.floor(x / L)
    return sum
  }
  const top = Math.max(...sticks)       // 막대 수가 작을 때
  return firstTrue(1, top, (L) => pieces(L) < k) - 1
}
maxCutLength([9, 7, 5], 5) // 3
```

- `L`이 3이면 3 + 2 + 1 = 6조각이라 가능하고, 4이면 2 + 1 + 1 = 4조각이라 5개에 못 미칩니다. 그래서 답은 3입니다.
- 모든 `L`에서 조건 `pieces(L) < k`가 거짓이면 `firstTrue`는 `top + 1`을 돌려주고 결과는 `top`입니다. 가장 긴 막대 길이 그대로 `k`개 이상 얻는 경우입니다.
- `L = 1`에서도 `k`개를 얻을 수 없으면 `firstTrue`가 1을 돌려주어 결과가 0입니다. 0을 "불가능"으로 해석합니다.
- 막대 수가 매우 많으면 `Math.max(...sticks)`가 인수 개수 한계에 걸릴 수 있어 반복문으로 최댓값을 구합니다(자세히는 86편).
- 같은 구조로 "나무를 높이 `H`로 자를 때 얻는 양", "시간 `t`에 처리할 수 있는 일의 양", "용량 `C`로 실을 수 있는 짐"이 모두 풀립니다.

**흔한 실수:** 단조성을 확인하지 않는 것입니다. 조건이 `참, 거짓, 참`처럼 여러 번 바뀌면 이분 탐색이 틀린 답을 냅니다. 작은 입력으로 `can`을 모든 `x`에 대해 출력해 한 번만 바뀌는지 봅니다.

## 삼분 탐색

삼분 탐색(ternary search)은 값이 한 번 내려갔다가 올라가는(아래로 볼록한) 함수의 최솟값, 또는 올라갔다 내려가는 함수의 최댓값을 찾는 탐색입니다. 이분 탐색이 단조 조건의 경계를 찾는다면, 삼분 탐색은 봉우리나 골짜기의 위치를 찾습니다.

구간 `[lo, hi]`에서 두 점 `m1 < m2`를 잡고 함수값을 비교합니다. 최솟값을 찾는 경우입니다.

- `f(m1) < f(m2)`이면 최솟값이 `m2` 왼쪽에 있으므로 오른쪽을 버립니다.
- `f(m1) > f(m2)`이면 최솟값이 `m1` 오른쪽에 있으므로 왼쪽을 버립니다.
- 구간이 충분히 작아지면 남은 후보를 하나씩 비교합니다.

```js
function ternaryMin(f, lo, hi) {      // 정수 구간의 최솟값 위치
  while (hi - lo > 2) {
    const d = Math.floor((hi - lo) / 3)
    const m1 = lo + d, m2 = hi - d
    if (f(m1) < f(m2)) hi = m2 - 1    // 최솟값은 m2 왼쪽
    else lo = m1 + 1                  // 최솟값은 m1 오른쪽
  }
  let best = lo
  for (let x = lo + 1; x <= hi; x++) {
    if (f(x) < f(best)) best = x
  }
  return best
}
ternaryMin((x) => (x - 13) ** 2 + 3, 0, 99) // 13
```

- 매번 구간의 약 1/3이 줄어서 반복은 약 log_{3/2}(범위)번이고, 한 번에 `f`를 두 번 계산해 O(log 범위 × f 비용)입니다.
- 함수는 엄격하게 한 번만 꺾여야 합니다(최솟값 앞은 감소, 뒤는 증가). 같은 값이 이어지는 평평한 구간이 최솟값이 아닌 곳에 있으면 어느 쪽을 버릴지 알 수 없어 틀립니다.
- 실수 구간에서는 같은 구조로 `lo`와 `hi`를 `(2 * lo + hi) / 3`, `(lo + 2 * hi) / 3`으로 줄이고 반복 횟수를 고정합니다.
- 대안: 정수에서는 인접한 두 값의 차를 단조 조건으로 바꿔 이분 탐색할 수 있습니다. 아래로 볼록한 함수는 `f(x) <= f(x + 1)`이 `거짓, ..., 참`이므로 `firstTrue(lo, hi - 1, (x) => f(x) <= f(x + 1))`이 최솟값 위치입니다. 최솟값 자리의 평평한 구간은 허용하지만, 최솟값 앞에 평평한 구간이 있으면 틀립니다.

```js
const f = (x) => (x - 13) ** 2
firstTrue(0, 98, (x) => f(x) <= f(x + 1)) // 13
```

- 함수값 계산이 비싸고 `f`의 도함수를 구할 수 있으면 도함수의 부호로 이분 탐색하는 방법도 있습니다.
- 문제의 단서는 "비용이 한 번 줄었다 늘어난다", "거리의 합이 최소인 지점", "볼록 함수의 최소"입니다.

## 핵심 정리

- 이분 탐색은 단조성이 있는 후보를 절반씩 버리는 O(log N) 탐색이고, 구간 규칙(`[lo, hi]` 또는 `[lo, hi)`)과 갱신식을 일관되게 씁니다. 큰 범위는 `Math.floor`나 `BigInt`로 `mid`를 구합니다.
- Lower Bound는 첫 `a[i] >= x`, Upper Bound는 첫 `a[i] > x`이며, 두 값의 차가 중복값 개수입니다.
- 결정 문제는 `거짓, ..., 참`으로 한 번만 바뀌는 조건이고, 최적화 문제를 이 형태로 바꿔 경계를 찾는 것이 파라메트릭 서치와 Binary Search on Answer입니다.
- 정답 범위는 정답이 반드시 포함되도록 잡고, 최솟값의 최댓값은 마지막 참(올림 `mid` 또는 첫 거짓 빼기 1), 최댓값의 최솟값은 첫 참을 구합니다.
- 실수 이분 탐색은 반복 횟수를 고정하고 `eps` 비교를 피하며, 삼분 탐색은 엄격하게 한 번 꺾이는 함수의 최솟값·최댓값 위치를 찾습니다.
