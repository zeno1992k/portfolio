## Trie

트라이(trie)는 문자열 집합을 글자 단위의 트리로 저장하는 자료구조입니다. 뿌리(root)에서 한 글자씩 간선을 따라 내려가면 접두사가 되고, 단어가 끝나는 노드에 표시를 해 둡니다. 같은 접두사를 공유하는 단어는 같은 경로를 씁니다.

`app`, `apple`, `apt`, `bat`을 넣은 트라이입니다(`*`는 단어의 끝).

```text
root
├─ a ─ p ─┬─ p* ─ l ─ e*
│         └─ t*
└─ b ─ a ─ t*
```

- 노드 하나는 자식 간선(글자 → 자식 노드)과 "여기서 끝나는 단어가 있는가"를 가집니다.
- 단어 길이를 L이라 하면 삽입·검색·접두사 확인이 모두 O(L)입니다. 저장된 단어 수 N과 무관합니다.
- 해시 집합(10편)은 단어 전체가 있는지만 O(L)에 확인할 수 있고, 접두사 질의는 지원하지 못합니다. 트라이는 접두사 질의와 사전순 순회가 필요할 때 씁니다.
- 노드 수는 모든 단어 길이의 합을 넘지 않습니다. 접두사를 많이 공유할수록 노드가 줄어듭니다.

**문제의 단서:** "접두사로 시작하는 단어가 있는가", "어떤 단어가 다른 단어의 접두사인가", 자동 완성, 사전에서 단어 찾기, 단어 수가 많고 길이가 짧은 문제.

## Trie 삽입 / 검색

Map으로 자식을 저장하는 가장 단순한 구현입니다. 노드는 자식 `Map`, 끝 표시, 이 노드를 지나는 단어 수를 가진 객체입니다.

```js
const makeNode = () =>
  ({ next: new Map(), end: false, cnt: 0 })
const root = makeNode()

function insert(word) {
  let node = root
  for (const ch of word) {
    if (!node.next.has(ch)) node.next.set(ch, makeNode())
    node = node.next.get(ch)
    node.cnt++
  }
  node.end = true
}
```

- 글자마다 자식이 있으면 따라가고 없으면 새 노드를 만듭니다.
- `cnt`는 이 노드를 지나간 삽입 횟수입니다. 같은 단어를 두 번 넣으면 두 번 셉니다. 중복을 한 번만 세려면 삽입 전에 `search`로 확인합니다.
- 모든 테스트 케이스마다 `root = makeNode()`로 다시 만들어야 합니다(`const` 대신 `let`).

검색은 문자열을 따라 내려간 마지막 노드를 돌려주는 `find`를 두고, 그 위에서 단어 검색과 접두사 확인을 만듭니다.

```js
function find(s) {
  let node = root
  for (const ch of s) {
    node = node.next.get(ch)
    if (!node) return null
  }
  return node
}
const search = (w) => find(w)?.end === true
const startsWith = (p) => find(p) !== null
```

```js
search('app')     // true
search('ap')      // false (접두사일 뿐 단어가 아님)
startsWith('ap')  // true
```

- `search`와 `startsWith`의 차이는 끝 표시(`end`)입니다. `end`를 빼먹으면 접두사도 단어로 판정됩니다.
- `Map.get`은 없는 키에 `undefined`를 돌려줘서 `!node`로 끊을 수 있습니다.
- 자식을 일반 객체 `{}`로 저장하면 `'constructor'` 같은 상속 키와 충돌할 수 있습니다. `Map`이나 `Object.create(null)`을 씁니다(자세히는 09편).
- `for...of`는 코드 포인트 단위로 문자열을 돕니다. 영문자와 숫자에서는 글자 하나입니다.

**흔한 실수:** 삽입 때 마지막 노드에 `end = true`를 빼먹는 것, 단어 삭제를 구현하지 않고 `end`만 내리면 노드가 남아 접두사 질의가 틀리는 것(삭제가 필요하면 `cnt`를 줄여 0이 된 노드를 끊습니다)입니다.

## Trie 노드 구현 방식

자식을 저장하는 방식은 크게 두 가지입니다.

| 항목 | Map 노드 | 고정 크기 배열 |
|------|----------|----------------|
| 자식 저장 | 노드마다 `Map` | 전체를 평탄한 배열 하나, 크기 노드 수 × 알파벳 |
| 알파벳 | 제한 없음(유니코드, 숫자, 임의 문자) | 작고 고정된 알파벳(소문자 26자 등) |
| 메모리 | 실제 존재하는 간선만큼 | 노드마다 알파벳 크기만큼 항상 차지 |
| 속도 | 해시 조회, 노드 객체 생성 비용 | 인덱스 계산 한 번, 객체 생성 없음 |
| 사전순 순회 | 삽입 순서라서 정렬 필요 | 알파벳 순서대로 돌면 사전순 |

고정 크기 배열 구현은 노드에 번호를 매기고 `next[노드 * 26 + 글자]`에 자식 번호를 저장합니다. 0번이 루트이므로 값 0을 "자식 없음"으로 쓸 수 있습니다.

```js
class ArrayTrie {
  constructor(maxNodes) {
    this.next = new Int32Array(maxNodes * 26) // 0 = 없음
    this.end = new Uint8Array(maxNodes)
    this.size = 1 // 루트가 0번
  }
  insert(word) {
    let node = 0
    for (let i = 0; i < word.length; i++) {
      const e = node * 26 + word.charCodeAt(i) - 97
      node = this.next[e] || (this.next[e] = this.size++)
    }
    this.end[node] = 1
  }
}
```

- `e`는 노드와 글자로 정한 간선의 칸입니다. 그 칸이 0이면 `size++`로 새 노드 번호를 배정합니다.
- `maxNodes`는 모든 단어 길이의 합 + 1입니다. 입력 크기로 미리 정해야 합니다.
- 타입 배열은 길이만 주면 0으로 채워진 채 생성됩니다. `Int32Array`는 요소당 4바이트이므로 노드당 `26 × 4 = 104`바이트이고, 노드 100만 개면 약 104MB입니다. 메모리 제한을 먼저 계산합니다(자세히는 14편).
- 알파벳이 26자인데 대문자나 숫자가 섞이면 인덱스가 범위를 벗어납니다. 알파벳 크기를 문제 조건으로 확인합니다.
- 알파벳이 크거나 입력 단어가 적으면 Map 노드가 낫고, 알파벳이 작고 단어가 많으면 배열이 빠릅니다. 코딩테스트 입력이 작으면 Map 노드가 구현 실수가 적습니다.

**흔한 실수:** 배열 트라이에서 `maxNodes`를 단어 수로 잡는 것입니다. 글자 수의 합이 필요합니다. 부족하면 `next`의 범위를 넘는 쓰기가 에러 없이 무시되어 조용히 틀립니다.

## Prefix Search

접두사 탐색(prefix search)은 접두사 `p`로 시작하는 단어를 세거나 나열하는 질의입니다. `p`를 따라 내려간 노드가 그 접두사의 모든 단어를 대표합니다.

개수는 `cnt`로 O(L)에 구합니다.

```js
const countPrefix = (p) => find(p)?.cnt ?? 0
countPrefix('ap')  // 3 (app, apple, apt)
countPrefix('app') // 2
countPrefix('z')   // 0
```

나열은 그 노드에서 하위 트리를 DFS로 돕니다(자세히는 36편).

```js
function collect(node, path, out) {
  if (node.end) out.push(path)
  for (const [ch, child] of node.next)
    collect(child, path + ch, out)
}
function withPrefix(prefix) {
  const node = find(prefix), out = []
  if (node) collect(node, prefix, out)
  return out
}
withPrefix('ap') // ['app', 'apple', 'apt']
```

- 결과 수가 K이고 총 글자 수가 S이면 나열은 O(L + S)입니다.
- `Map`은 삽입 순서로 돌아서 결과가 사전순이 아닙니다. 사전순이 필요하면 자식 키를 정렬하거나 고정 크기 배열의 알파벳 순회를 씁니다.
- 단어가 매우 길면 재귀 깊이가 단어 길이만큼 늘어납니다. 깊이 한계가 걱정되면 스택으로 바꿉니다(자세히는 86편).
- 접두사 질의에서 `p`가 빈 문자열이면 `find`가 루트를 돌려주어 모든 단어가 나옵니다.

**문제의 단서:** "접두사가 같은 단어의 수", "가장 긴 공통 접두사", 자동 완성 후보, 한 단어가 다른 단어의 접두사인 쌍이 있는지 판별하는 문제(전화번호 목록 유형).

## Aho-Corasick 개요

아호-코라식(Aho-Corasick)은 패턴 여러 개를 텍스트에서 한 번에 찾는 알고리즘입니다. 패턴들로 트라이를 만들고, KMP의 접두사 함수처럼 불일치가 났을 때 돌아갈 곳(실패 링크, suffix link)을 노드마다 붙입니다. 텍스트를 앞에서 한 번만 훑으면 모든 패턴의 모든 출현을 찾습니다.

- 실패 링크는 "이 노드가 나타내는 문자열의 가장 긴 진접미사이면서 트라이에 노드로 있는 것"으로 향하는 링크입니다. 트라이 전체를 BFS(38편)로 돌며 부모의 실패 링크를 이용해 구합니다.
- 없는 자식은 실패 링크 쪽 노드의 전이로 채우면 오토마톤이 되어 텍스트 한 글자당 O(1)에 상태가 바뀝니다.
- 시간은 구축 O(패턴 길이 합 × 알파벳 크기), 탐색 O(텍스트 길이 + 출현 수)입니다.
- 패턴이 하나면 KMP(58편)와 같은 역할입니다. 패턴이 많을 때 패턴마다 KMP를 돌리면 패턴 수만큼 텍스트를 훑게 되는데, 아호-코라식은 한 번이면 됩니다.

핵심 구현 골격입니다. 먼저 트라이를 만들고(`addWord`), BFS로 실패 링크와 전이를 채웁니다(`link`). `out[u]`는 노드 u에서 끝나는 패턴 수입니다.

```js
const next = [new Array(26).fill(-1)], out = [0]
function addWord(w) {
  let u = 0
  for (const ch of w) {
    const c = ch.charCodeAt(0) - 97
    if (next[u][c] < 0) {
      next[u][c] = next.length
      next.push(new Array(26).fill(-1)), out.push(0)
    }
    u = next[u][c]
  }
  out[u]++
}
```

```js
function link() {
  const fail = new Array(next.length).fill(0), queue = []
  for (let c = 0; c < 26; c++)
    if (next[0][c] < 0) next[0][c] = 0
    else queue.push(next[0][c])
  for (let qi = 0; qi < queue.length; qi++) {
    const u = queue[qi]
    out[u] += out[fail[u]] // 접미사로 끝나는 패턴 수도 합침
    for (let c = 0; c < 26; c++) {
      const v = next[u][c]
      if (v < 0) next[u][c] = next[fail[u]][c]
      else { fail[v] = next[fail[u]][c]; queue.push(v) }
    }
  }
}
```

탐색은 상태를 따라가며 `out`을 더합니다.

```js
function countAll(text) {
  let u = 0, total = 0
  for (const ch of text) {
    u = next[u][ch.charCodeAt(0) - 97]
    total += out[u]
  }
  return total
}
['he', 'she', 'his', 'hers'].forEach(addWord)
link()
countAll('ushers') // 3
```

- `'ushers'` 안에 `she`, `he`, `hers`가 한 번씩 있어 3입니다. 같은 패턴을 두 번 넣으면 두 번 셉니다.
- 어느 패턴이 어디서 나왔는지 필요하면 `out`에 패턴 번호 목록을 두고 접미사 링크를 따라 모읍니다.
- 이 문서의 코드는 소문자 26자로 고정했습니다. 알파벳이 다르면 `26`과 `- 97`을 바꿉니다.

**문제의 단서:** "금지 단어 사전", "텍스트에서 사전 단어가 몇 번 나오는가", 패턴 수가 많고 텍스트가 긴 문제, 특정 단어들을 피해 문자열을 만드는 DP.

## Suffix Array 개요

접미사 배열(suffix array)은 문자열의 모든 접미사를 사전순으로 정렬하고, 각 접미사의 시작 인덱스를 순서대로 담은 배열입니다.

`'banana'`의 접미사와 정렬 결과입니다.

| 시작 인덱스 | 접미사 | 사전순 순위 |
|-------------|--------|-------------|
| 0 | banana | 3 |
| 1 | anana | 2 |
| 2 | nana | 5 |
| 3 | ana | 1 |
| 4 | na | 4 |
| 5 | a | 0 |

순위 순서대로 인덱스를 나열하면 접미사 배열 `[5, 3, 1, 0, 4, 2]`입니다.

가장 짧은 구현은 접미사를 직접 정렬하는 것입니다.

```js
const sa = Array.from({ length: s.length }, (_, i) => i)
sa.sort((a, b) => (s.slice(a) < s.slice(b) ? -1 : 1))
// 'banana' -> [5, 3, 1, 0, 4, 2]
```

- 비교 하나가 O(n)이라 최악 O(n² log n)입니다. n이 수천 이하일 때만 씁니다.
- 빠른 방법은 접두사 배가(prefix doubling)입니다. 길이 1, 2, 4, …로 접미사의 앞부분을 정렬하고, 길이 2k의 순위는 `(길이 k의 순위, 뒤쪽 k글자의 순위)` 쌍으로 정합니다. 라운드가 log n번이고, 라운드마다 기수 정렬을 쓰면 O(n log n), 일반 정렬이면 O(n log² n)입니다.
- n이 10^5 이상이면 접두사 배가 같은 빠른 구현이 필요합니다. 이 문서는 원리와 쓰임을 다루고 전체 구현은 생략합니다.

접미사 배열이 해결하는 문제는 다음과 같습니다.

- 부분 문자열 검색: 패턴 `p`를 접미사 배열에서 이분 탐색(28편)으로 찾아 O(|p| log n)에 존재 여부를 확인합니다.
- 서로 다른 부분 문자열의 수: 아래 LCP 배열과 합쳐서 구합니다.
- 가장 긴 반복 부분 문자열, 두 문자열의 가장 긴 공통 부분 문자열(구분자로 이어 붙여서 구합니다).
- 사전순으로 가장 작은 회전(문자열을 두 번 이어 붙이고 구한 접미사 배열의 첫 항목).

**흔한 실수:** 접미사 배열을 `slice`로 만들어 정렬하는 코드를 n이 10^5인 입력에 그대로 쓰는 것입니다. 접미사 문자열을 실제로 만드는 비용이 O(n²)여서 시간과 메모리가 폭발합니다.

## LCP Array 개요

LCP 배열(longest common prefix array)은 접미사 배열에서 이웃한 두 접미사의 가장 긴 공통 접두사 길이를 담은 배열입니다. `lcp[i]`는 `sa[i - 1]`과 `sa[i]`의 접미사 사이 값이고, `lcp[0]`은 0으로 둡니다.

`'banana'`에서 `sa = [5, 3, 1, 0, 4, 2]`일 때 `lcp = [0, 1, 3, 0, 0, 2]`입니다. `a`와 `ana`는 1, `ana`와 `anana`는 3, `na`와 `nana`는 2입니다.

카사이(Kasai) 알고리즘은 이 배열을 O(n)에 만듭니다. 문자열의 접미사를 길이 순이 아니라 원래 위치 순서(i = 0, 1, 2, …)로 돌면서, 앞 접미사의 LCP에서 1을 뺀 값 이상은 이어진다는 사실을 이용합니다.

```js
function lcpArray(s, sa) {
  const n = s.length, rank = [], lcp = Array(n).fill(0)
  for (let i = 0; i < n; i++) rank[sa[i]] = i
  let h = 0
  for (let i = 0; i < n; i++) {
    if (rank[i] > 0) {
      const j = sa[rank[i] - 1]
      while (s[i + h] && s[i + h] === s[j + h]) h++
      lcp[rank[i]] = h
      if (h > 0) h--
    } else h = 0
  }
  return lcp
}
```

- `rank`는 접미사 배열의 역함수(`rank[sa[i]] = i`)입니다.
- `h`는 한 번에 최대 1씩 줄고 n을 넘지 못하므로 `while`의 총 반복이 O(n)입니다.
- 인접한 접미사만 비교해도 충분한 이유는 사전순에서 접두사가 같은 접미사들이 연속해서 모이기 때문입니다. 임의의 두 접미사의 LCP는 두 순위 사이 `lcp` 값의 최솟값입니다(구간 최솟값 질의, 자세히는 65편).

응용입니다.

- 서로 다른 부분 문자열의 수 = `n(n + 1) / 2 − (lcp 합)`. `'banana'`는 `21 − 6 = 15`입니다.
- 가장 긴 반복 부분 문자열의 길이 = `lcp`의 최댓값. `'banana'`는 3(`'ana'`)입니다. 해시와 이분 탐색으로 같은 문제를 푸는 방법은 58편입니다.
- 가장 긴 반복 부분 문자열은 겹침을 허용합니다. 겹치지 않는 조건이 있으면 이웃 쌍만 보는 방식으로는 부족하고 다른 처리가 필요합니다.

**흔한 실수:** `lcp[i]`의 정의(어느 두 접미사 사이인가)를 구현마다 다르게 쓰는 것입니다. `lcp[i]`를 `sa[i]`와 `sa[i + 1]` 사이로 정의하는 코드도 있으니 한 코드 안에서 하나만 씁니다.

## Manacher Algorithm 개요

마나커(Manacher) 알고리즘은 문자열의 모든 위치를 중심으로 하는 가장 긴 팰린드롬을 O(n)에 구합니다. 중심마다 양쪽으로 넓히는 방식(07편)은 O(n²)입니다.

짝수 길이 팰린드롬과 홀수 길이 팰린드롬을 따로 처리하지 않도록 글자 사이와 양 끝에 구분자를 끼웁니다. `'abaab'`는 `'#a#b#a#a#b#'`가 되고, 원래의 짝수·홀수 팰린드롬이 모두 이 문자열에서 홀수 길이(구분자 중심 포함)가 됩니다.

```js
function manacher(s) {
  const t = '#' + s.split('').join('#') + '#'
  const n = t.length, p = new Array(n).fill(0)
  let c = 0, r = 0
  for (let i = 0; i < n; i++) {
    if (i < r) p[i] = Math.min(r - i, p[2 * c - i])
    while (i - p[i] - 1 >= 0 && i + p[i] + 1 < n &&
           t[i - p[i] - 1] === t[i + p[i] + 1]) p[i]++
    if (i + p[i] > r) { c = i; r = i + p[i] }
  }
  return p
}
manacher('abaab') // [0,1,0,3,0,1,4,1,0,1,0]
```

- `p[i]`는 `t`에서 `i`를 중심으로 하는 가장 긴 팰린드롬의 반지름이고, 구분자를 끼웠으므로 원래 문자열에서의 팰린드롬 길이와 같습니다. 위 결과의 `p[6] = 4`는 `'baab'`입니다.
- `c`와 `r`은 지금까지 찾은 팰린드롬 중 오른쪽 끝(`r`)이 가장 먼 것의 중심과 오른쪽 끝입니다. 새 중심 `i`가 그 안에 있으면 대칭 위치 `2c − i`의 값을 이용해 비교를 건너뜁니다.
- 확장은 `r`을 넘어서는 구간에서만 실제로 일어나서 전체가 O(n)입니다(`r`은 줄지 않습니다).

결과를 읽는 방법입니다.

- 가장 긴 팰린드롬 부분 문자열의 길이는 `p`의 최댓값입니다(`Math.max(...p)`는 n이 크면 인수 개수 한계에 걸리므로 반복문으로 구합니다, 자세히는 86편). 시작 위치는 최댓값의 중심 인덱스를 `i`, 값을 `m`이라 할 때 `(i - m) / 2`이고, 길이는 `m`입니다.
- 팰린드롬 부분 문자열의 총 개수(위치가 다르면 다른 것으로 셈)는 모든 `p[i]`에 대해 `⌈p[i] / 2⌉`를 더한 값입니다.
- 어떤 구간 `s[l..r]`이 팰린드롬인지는 중심 `l + r + 1`(`t` 인덱스)의 `p`가 구간 길이 이상인지로 O(1)에 확인합니다.
- `s.split('')`은 UTF-16 코드 유닛 단위로 쪼갭니다. 영문자와 숫자에서는 글자 하나입니다. 이모지처럼 두 개의 코드 유닛으로 이뤄지는 글자는 `Array.from(s)`를 씁니다(자세히는 06편).

**문제의 단서:** "가장 긴 팰린드롬 부분 문자열", "팰린드롬 부분 문자열의 개수", n이 10^5 이상이라 O(n²) 중심 확장이 안 되는 팰린드롬 문제.

**흔한 실수:** 구분자가 입력에 등장하는 글자이면 틀립니다. 입력에 없는 문자를 쓰고, 값이 `p`의 반지름인지 원래 길이인지 헷갈려 시작 위치 계산이 틀리는 실수도 많습니다.

## 핵심 정리

- Trie는 접두사를 공유하는 트리이며 삽입·검색·접두사 확인이 O(L)입니다. 단어 끝 표시(`end`)가 있어야 접두사와 단어를 구별합니다.
- 노드는 Map(알파벳이 크거나 입력이 작을 때)이나 고정 크기 배열(알파벳이 작고 단어가 많을 때, 노드당 알파벳 크기만큼 메모리 사용)로 구현합니다.
- 접두사 개수는 노드의 `cnt`로, 나열은 그 노드 아래를 DFS로 구합니다.
- Aho-Corasick은 패턴들의 트라이에 실패 링크를 붙여 여러 패턴을 텍스트 한 번 훑기로 찾으며, 구축 O(패턴 길이 합 × 알파벳), 탐색 O(텍스트 길이 + 출현 수)입니다.
- Suffix Array는 정렬된 접미사의 시작 인덱스 배열이고, LCP 배열(카사이, O(n))과 합쳐서 서로 다른 부분 문자열 수(`n(n + 1) / 2 − lcp 합`)와 가장 긴 반복 부분 문자열(`lcp` 최댓값)을 구합니다.
- Manacher는 구분자를 끼운 문자열에서 모든 중심의 팰린드롬 반지름을 O(n)에 구하며, 반지름이 곧 원래 팰린드롬의 길이입니다.
