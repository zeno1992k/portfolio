## solution 함수 형식

solution 함수 형식은 채점기가 정해진 이름의 함수를 호출하고 반환값을 정답과 비교하는 방식입니다. 입력은 매개변수로 들어오고, 출력은 `return`입니다. 입출력 코드를 쓰지 않습니다.

```js
function solution(nums, k) {
  const answer = nums.filter((x) => x > k)
  return answer
}
// solution([1, 5, 9], 4) → [5, 9]
```

- 매개변수의 개수·순서·자료형(숫자, 문자열, 배열, 2차원 배열)은 문제가 정합니다. 입력 문자열을 파싱하지 않습니다.
- 반환 자료형도 문제가 정합니다. 배열을 요구하는데 문자열을 `return`하면 오답입니다. 값이 없을 때 빈 배열, `-1`, `0` 중 무엇을 반환할지도 문제에 적혀 있습니다.
- `console.log`로 찍은 값은 채점되지 않습니다(디버깅 출력일 뿐이고 정답 비교에는 반환값만 씁니다). 제출 전에 지우는 것이 안전합니다.
- 함수 이름을 바꾸면 채점기가 호출하지 못합니다. 함수 밖에 보조 함수와 상수를 선언해도 됩니다.
- 매개변수로 받은 배열을 바꾸면 채점기가 가진 원본이 바뀝니다. 다음 테스트 케이스에 영향을 줄 수 있어서 정렬하거나 수정하기 전에 복사합니다(자세히는 05편).
- 프로그래머스가 이 형식입니다. 반환 자료형과 제한 조건은 각 문제 페이지를 따릅니다.

## 표준 입력 형식

표준 입력 형식(백준식)은 프로그램이 표준 입력(stdin)에서 직접 읽고 표준 출력(stdout)에 쓰는 방식입니다. 채점기는 입력 파일을 프로그램에 연결하고 출력된 텍스트를 정답 파일과 비교합니다. 백준 사이트는 2026-04-28 서비스를 종료하고 "채점 서비스 준비 중"을 안내하고 있어서, 이 과목에서 "백준식"은 이 형식을 가리키는 이름으로만 씁니다.

| 항목 | solution 함수 | 표준 입출력 |
|------|---------------|-------------|
| 입력 | 매개변수 | stdin 텍스트를 직접 파싱 |
| 출력 | `return` 값 | stdout 텍스트 |
| 자료형 | 이미 파싱된 값 | 모두 문자열로 들어옴 |
| 출력 형식 오류 | 없음 | 공백·줄바꿈·소수점이 틀려도 오답 |

입력은 대개 세 모양입니다.

```text
한 줄:     3 5
여러 줄:   첫 줄 N, 둘째 줄에 N개의 수
N개 줄:    첫 줄 N, 이어서 N개의 줄에 값 하나씩
```

- 첫 줄에 개수나 크기를 주고 뒤에 본 데이터가 오는 모양이 가장 흔합니다.
- 모든 값이 텍스트라서 숫자는 직접 `Number`로 바꿔야 합니다. `'10' + '5'`는 `'105'`입니다.
- 형식 설명에 나온 줄 구분과 공백 구분(한 칸, 여러 칸)을 확인한 뒤 파싱 방법을 정합니다.

## fs.readFileSync(0)과 utf8 인코딩

Node.js에서 표준 입력을 한 번에 읽는 기본 코드입니다.

```js
const fs = require('fs')
const input = fs.readFileSync(0, 'utf8')
// input은 stdin 전체가 담긴 문자열
```

- `fs.readFileSync(path, options)`의 `path`는 파일 이름뿐 아니라 파일 디스크립터(정수)도 받습니다(v5.0.0부터). 표준 입력의 디스크립터가 `0`입니다(`process.stdin.fd`가 보통 0).
- `options`에 인코딩(`'utf8'`)을 주면 문자열을, 생략하면 `Buffer`를 반환합니다. 한글이 들어올 수 있으므로 문자열이 필요하면 `'utf8'`을 명시합니다.
- 디스크립터로 읽으면 현재 위치부터 읽고 디스크립터를 자동으로 닫지 않습니다.
- 동기 함수라서 입력이 끝날 때까지 기다린 뒤 전체를 반환합니다. 채점 환경처럼 입력이 파일이나 파이프로 연결될 때 쓰는 방식입니다.
- 한 번 읽으면 입력이 소비되어 다시 읽을 수 없습니다. 한 번만 읽어 변수에 보관합니다.
- 입력 끝 줄바꿈 때문에 `split('\n')` 결과의 마지막에 빈 문자열이 생깁니다(아래 "줄바꿈과 공백 처리").

## 빠른 입력

입력 줄이 많을 때 줄마다 읽는 것보다 전체를 한 번에 읽어 나누는 것이 빠르고 간단합니다. 읽기는 한 번, 나누기도 한 번입니다.

```js
const fs = require('fs')
const lines = fs.readFileSync(0, 'utf8').trim().split('\n')
const n = Number(lines[0])
const nums = lines[1].split(' ').map(Number)
// 입력 "3\n1 2 3" → n = 3, nums = [1, 2, 3]
```

- 수십만 줄에서도 읽기 호출은 한 번입니다. 구체적인 시간은 환경에 따라 달라서 이 문서는 수치를 제시하지 않습니다.
- 줄 수가 N인 입력은 `lines.slice(1, 1 + n)`처럼 범위로 꺼내 `map`합니다.
- 2차원 입력은 줄마다 `split`한 뒤 `Number`로 바꿉니다.

```js
const grid = lines.slice(1, 1 + n)
  .map((line) => line.split(' ').map(Number))
```

- `map(Number)`는 안전하지만 `map(parseInt)`는 인덱스가 진법으로 들어가서 틀립니다(자세히는 05편).
- 공백 없이 붙은 숫자 줄(`'10110'`)은 `[...line].map(Number)`로 한 글자씩 숫자로 바꿉니다.

## 줄바꿈과 공백 처리

윈도우에서 만든 입력 파일의 줄 끝은 `\r\n`입니다. `split('\n')`만 하면 각 줄 끝에 `\r`이 남습니다.

```js
const text = '3\r\nabc\r\n'
text.split('\n')      // ['3\r', 'abc\r', '']
text.split(/\r?\n/)   // ['3', 'abc', '']
text.trim().split(/\r?\n/) // ['3', 'abc']
```

- `Number('3\r')`은 `3`이라서 숫자만 읽을 때는 티가 나지 않습니다. 문자열은 `'abc\r' === 'abc'`가 `false`가 되어 비교와 `Map` 키에서 틀립니다.
- 안전한 기본형은 `.trim().split(/\r?\n/)`입니다. 양끝 공백·줄바꿈을 제거해서 끝 줄바꿈이 만드는 빈 줄도 없앱니다.
- `trim()`은 문자열의 양끝만 처리합니다. 입력 줄 안에 공백이 중요한 문제(문자열 안의 공백 포함)는 `trim()`을 줄 단위로 쓰지 말고 `\r`만 제거합니다.

```js
const raw = fs.readFileSync(0, 'utf8').split('\n')
const lines = raw.map((l) => l.replace(/\r$/, ''))
```

- 줄 중간에 빈 줄이 있는 입력(테스트 케이스 사이 공백 줄)은 `trim()`으로 사라지지 않습니다. 빈 줄을 건너뛰려면 `filter((l) => l !== '')`를 쓰되, 빈 문자열 자체가 데이터인 문제에서는 쓰면 안 됩니다.
- 값 사이가 여러 칸 공백이거나 줄 끝에 공백이 붙었을 수 있으면 `split(' ')`은 빈 문자열을 만듭니다. `trim().split(/\s+/)`를 씁니다.
- 숫자 줄의 끝 공백은 `Number`가 제거하지만, `split(' ')` 뒤 마지막 요소가 `''`이면 `Number('')`가 `0`이 되어 값이 하나 늘어납니다.

## Tokenizer와 Pointer Parser

줄 구조에 상관없이 공백과 줄바꿈으로 입력 전체를 토큰으로 나눈 뒤 포인터로 하나씩 꺼내는 방식입니다. 줄 단위 파싱보다 형식 변화에 강합니다.

```js
const fs = require('fs')
const text = fs.readFileSync(0, 'utf8')
const tokens = text.trim().split(/\s+/)
let pos = 0
const next = () => tokens[pos++]
const nextInt = () => Number(tokens[pos++])

const n = nextInt()
const nums = Array.from({ length: n }, nextInt)
```

- `/\s+/`는 공백, 탭, `\r`, `\n`을 모두 구분자로 취급하므로 줄바꿈 형식에 영향을 받지 않습니다. 앞에 공백이 있으면 첫 요소가 `''`이라서 `trim()`을 먼저 합니다.
- `pos`가 다음에 읽을 위치입니다. `next()`를 부를 때마다 앞으로만 움직입니다.
- 값 사이 구조(줄이 몇 줄인지)가 필요 없어서 N개의 줄, 한 줄에 몇 개씩 같은 모양을 모두 같은 코드로 읽습니다. 문자열이 공백을 포함하는 문제에는 맞지 않습니다.
- 토큰이 많으면 문자열 배열이 입력 크기에 비례하는 메모리를 씁니다(자세히는 14편).
- 더 줄이려면 `Buffer`를 직접 훑어 숫자를 파싱합니다. 인코딩을 생략하면 바이트 배열이 오고, 아스키 코드 48–57이 숫자, 45가 `-`입니다.

```js
const buf = fs.readFileSync(0)
let p = 0
function nextInt() {
  while (buf[p] !== 45 && (buf[p] < 48 || buf[p] > 57)) p++
  let neg = false
  if (buf[p] === 45) { neg = true; p++ }
  let x = 0
  while (buf[p] >= 48 && buf[p] <= 57) {
    x = x * 10 + buf[p++] - 48
  }
  return neg ? -x : x
}
```

- 입력이 끝난 뒤에도 호출하면 에러 없이 `0`을 반환합니다. 입력 개수를 정확히 지켜서 읽습니다.
- 정수만 읽는 파서입니다. 소수점이나 문자열 토큰에는 쓰지 못합니다.

## readline 모듈 방식과의 차이

`readline` 모듈은 입력을 한 줄씩 이벤트로 받는 방식입니다.

```js
const rl = require('readline').createInterface({
  input: process.stdin,
  crlfDelay: Infinity,
})
const lines = []
rl.on('line', (line) => lines.push(line))
rl.on('close', () => solve(lines))
```

- `'line'` 이벤트는 줄이 끝날 때마다, `'close'` 이벤트는 입력 스트림이 끝났을 때 발생합니다. 마지막 줄 끝에 줄바꿈이 없어도 `'line'`이 한 번 더 발생합니다.
- 풀이는 `'close'` 안에서 호출합니다. `'line'` 안에서 바로 풀면 입력이 다 오기 전에 실행됩니다.
- `crlfDelay`는 `\r`과 `\n` 사이가 이 시간(기본 100ms, 최솟값 100)을 넘으면 줄바꿈을 두 번으로 세는 옵션입니다. `Infinity`로 두면 `\r\n`을 항상 한 번으로 취급합니다.
- `for await (const line of rl)`로도 읽을 수 있지만, 공식 문서는 `'line'` 이벤트 방식보다 성능이 낮다고 밝히고 있습니다.

| 항목 | `fs.readFileSync(0)` | `readline` |
|------|----------------------|------------|
| 읽는 방식 | 동기, 전체를 한 번에 | 비동기, 줄 단위 이벤트 |
| 코드 | 한 줄 | 이벤트 핸들러 필요 |
| 풀이 시작 시점 | 읽은 직후 | `'close'` 이벤트 안 |
| `\r\n` 처리 | 직접 처리 | 줄 단위로 분리해서 제공 |
| 메모리 | 입력 전체를 한 번에 보관 | 줄을 모으면 같음 |

- 채점 입력이 파일로 주어지는 코딩테스트에서는 `fs.readFileSync(0)`가 코드가 짧고 실수가 적습니다. 대화형 입력을 줄 단위로 처리해야 하는 문제에서만 `readline`이 필요합니다.
- 입력이 끝나지 않으면(표준 입력에 EOF가 없으면) 두 방식 모두 끝나지 않고 기다립니다.

## 빠른 출력

출력할 줄이 많으면 줄마다 `console.log`를 부르지 않고 결과를 배열에 모아 한 번에 출력합니다.

```js
const out = []
for (let i = 1; i <= n; i++) out.push(i * i)
console.log(out.join('\n'))
```

- `console.log`는 `process.stdout`에 쓰고 줄바꿈을 붙입니다. 호출 횟수를 줄이면 출력 작업도 줄어듭니다.
- 문자열을 `+=`로 이어 붙이는 대신 배열에 `push`하고 마지막에 `join`합니다(자세히는 06편).
- 줄바꿈 하나로 끝내려면 `join('\n')` 뒤에 `console.log`가 붙이는 줄바꿈 하나가 끝에 옵니다. `process.stdout.write`는 줄바꿈을 붙이지 않아서 `+ '\n'`을 직접 씁니다.
- 출력할 것이 없는 경우(`out`이 빈 배열)에는 `console.log('')`가 빈 줄 하나를 출력합니다. 아무것도 출력하지 않아야 하면 호출하지 않습니다.

## 대량 출력 버퍼링

출력이 매우 클 때는 한 번에 만든 하나의 문자열이 문제가 될 수 있습니다. 문자열에는 최대 길이가 있고, 이를 넘기는 연산은 `RangeError`를 던집니다. 일정 개수가 쌓일 때마다 비웁니다.

```js
const out = []
function flush() {
  if (out.length === 0) return
  process.stdout.write(out.join('\n') + '\n')
  out.length = 0
}
// 반복문 안에서
out.push(value)
if (out.length >= 100000) flush()
// 반복이 끝난 뒤 flush()
```

- `process.stdout.write`는 데이터를 쓰고, 내부 버퍼가 가득 차면 `false`를 반환합니다. 코딩테스트 규모의 출력에서는 대개 신경 쓰지 않아도 됩니다.
- 표준 출력 쓰기가 동기인지는 연결 대상에 따라 다릅니다(파일: 동기, 터미널: 윈도우는 비동기·POSIX는 동기, 파이프: 윈도우는 동기·POSIX는 비동기).
- 비동기 쓰기가 남은 상태에서 `process.exit()`를 호출하면 출력이 잘릴 수 있다고 공식 문서가 경고합니다. 종료는 프로세스가 스스로 끝나게 두고 `exit`를 부르지 않습니다.
- 동기 쓰기가 필요하면 `fs.writeFileSync(1, text)`입니다. 디스크립터 1이 표준 출력입니다.
- 일반적인 크기(수십만 줄)에서는 하나의 `join`으로 충분하고, 위 방식은 출력 문자열이 매우 클 때의 대비책입니다.

## 출력 형식

출력은 공백 하나, 줄바꿈 하나까지 정답과 비교됩니다. 문제의 출력 설명을 그대로 따릅니다.

| 요구 | 코드 |
|------|------|
| 공백으로 구분해 한 줄 | `arr.join(' ')` |
| 한 줄에 하나씩 | `arr.join('\n')` |
| 여러 값을 한 줄에 | ``console.log(`${a} ${b}`)`` |
| 소수점 아래 k자리 | `x.toFixed(k)` |
| 빈 결과 | 문제의 지시(`-1`, 빈 줄, 출력 없음) |

- `join`은 끝에 구분자를 남기지 않아서 끝 공백 문제를 피합니다. 끝 공백을 허용하는지는 채점기와 문제마다 다르므로 만들지 않는 편이 안전합니다.
- `console.log(a, b)`는 값 사이에 공백 하나를 넣어 출력합니다. 형식이 단순하면 그대로 씁니다.
- `toFixed(k)`는 문자열을 반환하고 모자라는 자리를 `0`으로 채웁니다. 부동소수점 표현 때문에 `(1.005).toFixed(2)`는 `'1.00'`입니다. 소수점 아래 자리가 정해진 문제는 반올림 규칙을 확인합니다(자세히는 02편).
- `toFixed`는 음의 0에 가까운 값에서 `'-0.00'`을 만들 수 있습니다. `(-0.001).toFixed(2)`가 그렇습니다.
- 정수 나눗셈 결과는 `Math.floor`나 `Math.trunc`로 정수로 만든 뒤 출력합니다. `7 / 2`는 `3.5`입니다.
- `Number`는 `1e21` 이상에서 지수 표기(`'1e+21'`)로 출력합니다. 큰 정수는 BigInt로 계산합니다.
- `console.log(10n)`은 `10n`으로 찍힙니다. 문자열로 바꿔 쓰거나(`String(x)`, `join`) 템플릿 문자열을 씁니다. `join`에서는 `n` 접미사 없이 숫자만 나옵니다.
- `console.log(-0)`은 `-0`으로 찍힙니다. `String(-0)`은 `'0'`입니다.
- 디버깅용 `console.log`를 남기면 표준 출력이 오염되어 오답이 됩니다. 디버깅은 `console.error`로 하면 표준 오류로 가서 채점에 영향을 주지 않지만, 제출 전에 지우는 것이 안전합니다.

## 같은 풀이를 두 형식으로 감싸기

풀이 로직은 입출력과 분리된 순수 함수로 쓰고, 형식에 맞게 얇은 껍데기만 바꿉니다.

```js
// 핵심 풀이 (입출력 없음)
function maxOf(nums) {
  return nums.reduce((a, b) => (a > b ? a : b), -Infinity)
}
```

```js
// 형식 1: solution 함수
function solution(nums) {
  return maxOf(nums)
}
```

```js
// 형식 2: 표준 입출력
const fs = require('fs')
const text = fs.readFileSync(0, 'utf8')
const lines = text.trim().split(/\r?\n/)
const nums = lines[1].split(' ').map(Number)
console.log(maxOf(nums))
```

- 입력 `3\n1 5 2`에서 형식 2는 `5`를 출력하고, 형식 1은 `solution([1, 5, 2])`가 `5`를 반환합니다.
- 두 형식의 차이는 껍데기에만 있습니다. 입력을 파싱해 같은 자료형으로 만들고, 결과를 반환하거나 출력합니다.
- 풀이 함수는 입력 배열을 바꾸지 않도록 씁니다. 표준 입출력에서는 문제없어 보이다가 solution 함수 형식에서 원본이 바뀌어 여러 테스트가 서로 영향을 주는 일이 있습니다.
- 이 과목의 알고리즘 편은 핵심 함수를 먼저 보이고 필요한 껍데기만 덧붙입니다. 템플릿은 82편에서 모읍니다.

## 여러 테스트 케이스(T개) 입력 처리

첫 줄에 테스트 케이스 수 T를 주고 이어서 T개의 케이스가 오는 형식입니다. 케이스마다 결과를 모아 한 번에 출력합니다.

```text
2
3
1 2 3
2
5 7
```

줄 단위로 읽는 방법은 줄 번호 포인터 `li`를 둡니다.

```js
const text = fs.readFileSync(0, 'utf8')
const lines = text.trim().split(/\r?\n/)
let li = 0
const t = Number(lines[li++])
const out = []
for (let tc = 0; tc < t; tc++) {
  const n = Number(lines[li++])
  const nums = lines[li++].split(' ').map(Number)
  out.push(maxOf(nums))
}
console.log(out.join('\n')) // 3 (줄바꿈) 7
```

토큰으로 읽는 방법은 포인터가 줄 구조를 신경 쓰지 않아서 더 단순합니다.

```js
const t = nextInt()
const out = []
for (let tc = 0; tc < t; tc++) {
  const n = nextInt()
  const nums = Array.from({ length: n }, nextInt)
  out.push(maxOf(nums))
}
console.log(out.join('\n'))
```

- 케이스마다 변수를 새로 만듭니다. 바깥에 선언한 배열이나 `Map`을 재사용하면 이전 케이스의 값이 남아 틀립니다. 초기화를 빼먹는 것이 가장 흔한 실수입니다.
- 케이스마다 `console.log`를 부르지 않고 `out`에 모아 마지막에 한 번 출력합니다. 케이스 출력 형식(`Case #1: 3` 같은 접두사)이 있으면 템플릿 문자열로 만들어 `out`에 넣습니다.
- 입력 줄이 비어 있을 수 있는 케이스(`n`이 0이어서 둘째 줄이 빈 줄)는 줄 단위 파싱이 `lines[li++]`가 `''`이거나 줄 하나가 사라져서 어긋납니다. 이런 입력에서는 토큰 파서가 안전합니다.
- 전체 입력 크기는 모든 케이스의 합 기준입니다. 케이스가 많을 때는 케이스마다 큰 배열을 새로 할당하는 비용도 합쳐집니다(자세히는 14편).
- 입력이 `T`로 시작하지 않고 `0 0`으로 끝나는 형식도 있습니다. 반복 안에서 종료 조건을 검사하고 `break`합니다.

## 핵심 정리

- solution 함수 형식은 매개변수와 `return`만 쓰고, 표준 입출력 형식은 stdin을 직접 파싱해 stdout에 출력하며 모든 입력이 문자열입니다.
- 입력은 `fs.readFileSync(0, 'utf8')`로 한 번에 읽어 `.trim().split(/\r?\n/)`로 줄을 나누거나 `/\s+/`로 토큰을 나눕니다. `\r`이 남으면 문자열 비교가 틀립니다.
- 줄 구조에 얽매이기 싫으면 토큰 배열과 포인터(`nextInt`)로 읽고, `readline`은 이벤트 방식이라 `'close'`에서 풀이를 시작합니다.
- 출력은 배열에 모아 `join`하여 한 번에 내고, 매우 크면 일정 개수마다 `process.stdout.write`로 비웁니다. `process.exit()`는 부르지 않습니다.
- 출력 형식은 한 글자까지 비교되므로 `join`, `toFixed`, BigInt의 `n` 접미사, 디버깅 출력을 확인합니다.
- 풀이는 입출력과 분리된 함수로 쓰고 형식별 껍데기만 바꾸며, T개 케이스는 케이스마다 변수를 초기화합니다.
