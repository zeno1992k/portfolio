## 시간복잡도 개념

시간복잡도(time complexity)는 입력 크기 N이 커질 때 알고리즘이 실행하는 기본 연산 횟수가 얼마나 빠르게 늘어나는지를 나타내는 척도입니다. 초 단위 실행 시간이 아니라 연산 횟수의 증가 형태를 봅니다. 기계·언어·채점 서버가 달라도 같은 증가 형태는 변하지 않기 때문입니다.

- 기본 연산은 대입, 산술, 비교, 배열 인덱스 접근처럼 입력 크기와 무관하게 한 번에 끝나는 동작입니다.
- N은 문제가 정하는 입력 크기입니다. 배열 길이, 문자열 길이, 정점 수 등입니다.
- 표기는 Big-O입니다. 연산 횟수를 식으로 세고, 가장 빨리 커지는 항만 남기고, 계수를 버립니다(아래 "연산 횟수 세는 규칙").

작은 쪽에서 큰 쪽으로 정리하면 다음 순서입니다.

| N | O(log N) | O(N log N) | O(N²) | O(N³) | O(2^N) | O(N!) |
|---|----------|------------|-------|-------|--------|-------|
| 10 | 약 3 | 약 33 | 100 | 1000 | 1024 | 3628800 |
| 20 | 약 4 | 약 86 | 400 | 8000 | 약 10^6 | 약 2.4 × 10^18 |
| 100 | 약 7 | 약 664 | 10^4 | 10^6 | 약 1.3 × 10^30 | 약 9.3 × 10^157 |
| 1000 | 약 10 | 약 9970 | 10^6 | 10^9 | 약 1.1 × 10^301 | 천문학적 |

- 로그는 밑이 2입니다(이유는 O(log N) 절).
- N이 10배가 될 때 O(N)은 10배, O(N²)은 100배, O(N³)은 1000배가 됩니다. 지수·팩토리얼은 N이 조금만 늘어도 감당할 수 없게 됩니다.
- 입력 크기별로 어떤 복잡도까지 허용되는지는 14편에서 다룹니다.

## O(1)

O(1)(상수 시간)은 N이 아무리 커져도 연산 횟수가 일정한 경우입니다.

```js
const first = arr[0]                // 인덱스 접근
const last = arr[arr.length - 1]    // length 읽기 + 접근
const total = n * (n + 1) / 2       // 1부터 n까지 합: 공식
stack.push(x)                       // 끝에 추가 (분할 상환, 14편)
```

- 반복문이 없어도 O(1)이 아닐 수 있고, 반복문이 있어도 반복 횟수가 상수(예: 항상 4방향)이면 O(1)입니다.
- `Map`의 `get`·`set`·`has`는 해시 테이블로 구현되면 평균 O(1)입니다. 명세는 평균 접근 시간이 요소 수에 대해 준선형(sublinear)일 것만 요구합니다(자세히는 14편).

## O(log N)

O(log N)(로그 시간)은 한 단계마다 남은 일의 크기가 일정한 비율(보통 절반)로 줄어드는 경우입니다.

```js
function countHalving(n) {
  let steps = 0
  while (n > 1) {
    n = Math.floor(n / 2)   // 매번 절반
    steps++
  }
  return steps
}
countHalving(1000) // 9
```

- N을 1이 될 때까지 절반으로 나누는 횟수가 약 log₂N입니다. 1000은 9번, 10^9는 30번 안팎입니다. N이 두 배가 되어도 연산이 한 번만 늘어납니다.
- 밑이 다른 로그는 상수배(`log₁₀N = log₂N / log₂10`)이므로 Big-O에서는 밑을 쓰지 않습니다.
- 대표 사례는 이분 탐색(28편)이고, `i *= 2`로 커지는 반복문, 자릿수 세기(N의 자릿수는 약 log₁₀N)도 같습니다.

```js
for (let i = 1; i < n; i *= 2) {} // log N번 반복
```

## O(N)

O(N)(선형 시간)은 입력을 한 번씩 훑는 경우입니다. 연산 횟수가 N에 비례합니다.

```js
function maxOf(arr) {
  let best = -Infinity
  for (const x of arr) {   // N번
    if (x > best) best = x
  }
  return best
}
```

- 반복문이 한 겹이어도 안에서 O(N) 메서드를 부르면 O(N)이 아닙니다(아래 "연산 횟수 세는 규칙").
- 입력을 읽는 것 자체가 O(N)이므로 N개를 전부 봐야 하는 문제의 하한은 O(N)입니다.
- 반복문이 두 개 이어져 있어도(한 번 돌고, 이어서 또 한 번) O(N + N) = O(N)입니다.

## O(N log N)

O(N log N)은 N개 각각에 대해 log N짜리 일을 하거나, 로그 단계로 나눈 뒤 매 단계에서 N을 처리하는 경우입니다.

```js
function hasDuplicate(arr) {
  const sorted = [...arr].sort((a, b) => a - b) // N log N
  for (let i = 1; i < sorted.length; i++) {      // N
    if (sorted[i] === sorted[i - 1]) return true
  }
  return false
}
```

- 전체는 N log N + N이고, 낮은 항 N을 버려서 O(N log N)입니다.
- 대표 사례는 비교 기반 정렬(26·27편)과 병합 정렬 같은 분할 정복(25편), 힙을 N번 쓰는 알고리즘(46편)입니다.
- `sort`의 복잡도는 명세가 보장하지 않고 구현에 따릅니다. 코딩테스트에서는 O(N log N)으로 가정하고 씁니다.

## O(N²)

O(N²)(이차 시간)은 모든 쌍을 보는 이중 반복문에서 나옵니다.

```js
function countPairs(arr, target) {
  let count = 0
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[i] + arr[j] === target) count++
    }
  }
  return count
}
```

- 안쪽이 `j = i + 1`로 시작하면 비교 횟수는 (N−1) + (N−2) + … + 1 = N(N−1)/2입니다. 절반이지만 계수를 버리므로 O(N²)입니다.
- 배열을 도는 반복문 안에서 `includes`, `indexOf`, `slice`, `splice`, 스프레드를 부르는 경우도 O(N²)입니다.
- N이 10배가 되면 시간이 100배가 됩니다.

## O(N³)

O(N³)(삼차 시간)은 삼중 반복문이거나 모든 세 개 조합을 보는 경우입니다.

```js
for (let i = 0; i < n; i++) {
  for (let j = i + 1; j < n; j++) {
    for (let k = j + 1; k < n; k++) {
      // 세 개 조합마다 O(1) 작업: 약 N³/6번
    }
  }
}
```

- N × N 행렬 두 개를 곱하는 기본 방법도 O(N³)입니다(18편).
- 플로이드-워셜도 세 겹이어서 O(V³)입니다(49편).

## O(2^N)

O(2^N)(지수 시간)은 원소마다 "넣는다/넣지 않는다" 두 가지를 고르는 경우, 즉 부분집합을 모두 보는 경우에 나옵니다.

- 원소 N개의 부분집합은 2^N개입니다(곱의 법칙, 16편).
- 한 번 호출이 두 번 이상 자기 자신을 부르는데 문제 크기가 조금씩만 줄면 호출 수가 지수로 늘어납니다.

```js
function fib(n) {
  if (n <= 1) return n
  return fib(n - 1) + fib(n - 2)
}
fib(5) // 5 (함수 호출 15번)
```

- 호출 수는 n=2에서 3번, 3에서 5번, 4에서 9번, 5에서 15번으로 늘어 N이 1 늘 때마다 약 1.6배가 됩니다. 정확한 증가율은 2보다 작지만 2^N이 상한이므로 O(2^N)으로 쓸 수 있습니다.
- 같은 인자로 반복 호출하는 낭비는 메모이제이션으로 없앱니다(40편).
- N이 20 안팎이면 2^N은 약 10^6이어서 가능하고, 30을 넘으면 10^9로 어렵습니다.

## O(N!)

O(N!)(팩토리얼 시간)은 N개를 늘어놓는 모든 순서, 즉 순열을 모두 보는 경우입니다.

```js
function perms(rest, picked, out) {
  if (rest.length === 0) { out.push(picked); return }
  for (let i = 0; i < rest.length; i++) {
    const next = rest.filter((_, k) => k !== i)
    perms(next, [...picked, rest[i]], out)
  }
}
const out = []
perms([1, 2, 3], [], out) // out.length === 6
```

- 첫 자리 N가지, 둘째 자리 N−1가지, … 이므로 N × (N−1) × … × 1 = N!개입니다.
- 결과가 N!개이므로 모두 만들어 내는 것만으로 N! 이상의 연산이 듭니다.
- N이 10이면 약 3.6 × 10^6이어서 가능하고, 12가 넘으면 10^8을 넘습니다. 순서를 모두 시도하는 외판원 문제 완전탐색이 대표 사례입니다(백트래킹은 23편).

## Big-O·Big-Ω·Big-Θ

세 표기는 연산 횟수 함수 f(N)이 기준 함수 g(N)과 어떤 관계인지를 나타냅니다. 아래 "충분히 큰 N"은 어떤 N0 이상의 모든 N을 뜻합니다.

| 표기 | 의미 | 조건 (양의 상수 c, N0) |
|------|------|------------------------|
| Big-O, O(g) | 점근적 상한 | 충분히 큰 N에서 f(N) ≤ c × g(N) |
| Big-Ω, Ω(g) | 점근적 하한 | 충분히 큰 N에서 f(N) ≥ c × g(N) |
| Big-Θ, Θ(g) | 상한이자 하한 (정확한 증가율) | O(g)이면서 Ω(g) |

- f(N) = 3N + 5는 Θ(N)이고 O(N)이며 Ω(N)입니다. 상한이므로 O(N²)도 참이지만 느슨한 말입니다. 보통은 가장 딱 맞는 상한을 씁니다.
- 코딩테스트에서 "O(N log N)"이라고 쓰면 대개 Big-O의 최악 상한을 뜻합니다. 정확한 증가율을 말하고 싶을 때만 Θ를 씁니다.
- 반복문 두 겹(N × N)처럼 입력과 상관없이 항상 같은 횟수를 도는 코드는 Θ(N²)입니다.

## 최선·평균·최악

같은 N이라도 입력의 내용에 따라 연산 횟수가 달라질 수 있습니다. 어떤 입력을 가정하느냐가 최선(best), 평균(average), 최악(worst)입니다.

```js
function find(arr, target) {
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === target) return i
  }
  return -1
}
```

| 경우 | 입력 | 비교 횟수 | 복잡도 |
|------|------|-----------|--------|
| 최선 | 첫 원소가 target | 1 | O(1) |
| 평균 | target이 어느 위치든 같은 확률 | 약 N/2 | O(N) |
| 최악 | target이 없거나 마지막 | N | O(N) |

- 최선·평균·최악은 입력 경우를 고르는 말이고, Big-O·Ω·Θ는 증가율을 표현하는 말입니다. 최악의 경우에 대해 O를 붙이거나 최선의 경우에 대해 Ω를 붙이는 식으로 서로 독립입니다. "Big-O는 최악"이라는 말은 흔히 쓰이지만 정확하지 않습니다.
- 코딩테스트 채점 데이터에는 최악 입력이 들어 있다고 가정해야 하므로 최악 복잡도를 기준으로 합니다.
- 평균과 최악이 크게 다른 사례: 퀵 정렬(평균 O(N log N), 최악 O(N²), 27편), 해시 조회(평균 O(1), 최악 O(N), 10편).
- 분할 상환(14편)은 평균과 다릅니다. 입력의 확률 가정 없이 연산을 이어서 했을 때의 총 비용을 평균 낸 것입니다.

## 연산 횟수 세는 규칙

코드를 보고 Big-O를 구하는 절차는 세는 규칙 몇 가지로 정리됩니다.

| 규칙 | 설명 | 예 |
|------|------|----|
| 순차는 합 | 위에서 아래로 이어진 부분은 더한 뒤 가장 큰 것만 남김 | O(N) 다음 O(N²) → O(N²) |
| 중첩은 곱 | 안에 든 반복문은 바깥 반복 횟수와 곱함 | N번 안에 M번 → O(N × M) |
| 상수 계수 무시 | 앞의 상수 배는 버림 | 3N → O(N) |
| 낮은 차수 무시 | 가장 빨리 커지는 항만 남김 | N² + 5N + 7 → O(N²) |
| 상수 반복 | 반복 횟수가 N과 무관하면 O(1) | 4방향 탐색 |

```js
for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) count++   // N × N
}
for (let k = 0; k < n; k++) count++     // N
// N² + N → O(N²)
```

바깥 변수에 따라 안쪽 반복 횟수가 달라지면 곱하지 말고 합을 구합니다.

```js
for (let i = 0; i < n; i++) {
  for (let j = i; j < n; j++) count++   // N, N-1, ..., 1
}
// 1 + 2 + ... + N = N(N+1)/2 → O(N²)
```

```js
for (let i = 1; i < n; i *= 2) {        // log N번
  for (let j = 0; j < n; j++) count++   // N번
}
// log N × N → O(N log N)
```

```js
for (const x of a) {            // N번
  if (b.includes(x)) count++    // includes는 O(M)
}
// N × M → O(N × M)
```

**흔한 실수:**

- 내장 메서드를 O(1)로 착각합니다. `includes`, `indexOf`, `slice`, `concat`, `splice`, `shift`, `unshift`, 스프레드, `join`, 정렬은 모두 요소 수에 비례하는 이상의 비용이 듭니다. 반복문 안에 있으면 곱해서 셉니다.
- 문자열을 반복문에서 `slice`로 자르거나 `[...arr]`로 복사하면 겉보기 한 줄이 O(N)입니다.
- 입력 변수가 둘인데 N 하나로 합칩니다. 배열 두 개의 길이가 N, M이면 O(N × M)이지 O(N²)이 아닙니다(자세히는 14편).

## 핵심 정리

- 시간복잡도는 N에 대한 기본 연산 횟수의 증가 속도이고, 가장 큰 항만 남기고 계수를 버려 Big-O로 씁니다.
- 증가 속도 순서는 O(1), O(log N), O(N), O(N log N), O(N²), O(N³), O(2^N), O(N!)입니다.
- 순차는 합, 중첩은 곱입니다. 안쪽 반복 횟수가 바깥 변수에 따라 달라지면 합을 계산합니다.
- Big-O는 상한, Big-Ω는 하한, Big-Θ는 둘 다입니다. 최선·평균·최악은 입력 경우의 구분이어서 이들과 별개입니다.
- 코딩테스트에서는 최악 입력을 기준으로 하고, 반복문 안의 내장 메서드 비용을 곱해서 셉니다.
