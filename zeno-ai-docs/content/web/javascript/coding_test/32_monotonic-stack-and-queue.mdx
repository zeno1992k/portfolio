## Monotonic Stack

단조 스택(monotonic stack)은 스택 안의 값이 위에서 아래로 항상 한 방향(증가 또는 감소)으로 정렬되도록 유지하는 스택입니다. 새 원소를 넣기 전에, 정렬 상태를 깨는 원소를 위에서부터 꺼냅니다.

```js
// 값이 아래에서 위로 감소하는 스택(큰 값이 아래)
const st = []
for (let i = 0; i < a.length; i++) {
  while (st.length && a[st.at(-1)] < a[i]) {
    st.pop() // a[i]가 이 원소의 "오른쪽 첫 더 큰 값"
  }
  st.push(i)
}
```

- 원소는 한 번 들어가고 한 번 나옵니다. `while`이 안에 있어도 전체 pop은 N번 이하라서 시간 O(N)입니다(자세히는 14편).
- 스택에는 값이 아니라 인덱스를 넣습니다. 값은 `a[인덱스]`로 읽을 수 있고, 인덱스가 있어야 거리나 위치를 구할 수 있습니다.
- 꺼내는 시점이 중요합니다. 원소 `j`가 pop되는 순간 현재 원소 `i`가 `j`의 오른쪽에서 처음으로 조건을 깬 원소입니다. 이 정보를 기록하는 것이 단조 스택 문제의 풀이입니다.
- 스택 자체(`push`·`pop`·`at(-1)`)는 19편에서 다룹니다. `at`은 ES2022 메서드이고 구형 환경에서는 `st[st.length - 1]`로 씁니다.

| 스택 유지 방향 | pop 조건 | 구하는 것 |
|----------------|----------|-----------|
| 감소(큰 값이 아래) | `a[top] < a[i]` | 오른쪽 첫 더 큰 값 |
| 증가(작은 값이 아래) | `a[top] > a[i]` | 오른쪽 첫 더 작은 값 |

- 쓰는 단서: "오른쪽(또는 왼쪽)에서 처음으로 더 크거나 작은", "자기보다 큰 값을 만날 때까지", "각 원소를 최솟값(최댓값)으로 하는 구간"입니다. 이중 반복문이면 O(N²)이라 N이 10^5 이상이면 이 기법을 의심합니다.

## 다음 큰 수

다음 큰 수(next greater element)는 각 원소의 오른쪽에서 처음 나오는 더 큰 값입니다. 없으면 -1입니다. 감소 스택을 쓰고, `a[i]`가 스택 위 원소들보다 크면 그 원소들의 답이 `a[i]`입니다.

```js
function nextGreater(a) {
  const res = new Array(a.length).fill(-1)
  const st = []
  for (let i = 0; i < a.length; i++) {
    while (st.length && a[st.at(-1)] < a[i]) {
      res[st.pop()] = a[i]
    }
    st.push(i)
  }
  return res
}
nextGreater([2, 1, 5, 3, 4]) // [5, 5, -1, 4, -1]
```

`a = [2, 1, 5, 3, 4]`의 추적입니다.

| i | `a[i]` | pop되는 원소(답 기록) | push 후 스택(값) |
|---|--------|-----------------------|------------------|
| 0 | 2 | 없음 | [2] |
| 1 | 1 | 없음 | [2, 1] |
| 2 | 5 | 1과 2 (둘 다 답 5) | [5] |
| 3 | 3 | 없음 | [5, 3] |
| 4 | 4 | 3 (답 4) | [5, 4] |

끝까지 남은 원소(5, 4)는 오른쪽에 더 큰 값이 없어서 초기값 -1이 그대로 답입니다.

- 값이 같을 때는 조건이 `<`이라 같은 값은 "더 크다"가 아니어서 pop되지 않습니다. `[3, 3, 3]`의 답은 모두 -1입니다. "크거나 같은"을 구하려면 `<=`로 바꿉니다.
- 값 대신 위치가 필요하면 `res[st.pop()] = i`로 기록합니다. 거리가 필요하면 `i - j`입니다.
- 오른쪽에서 왼쪽으로 순회하며, 현재 원소를 넣기 직전의 스택 위를 답으로 읽는 방식도 같은 O(N)입니다. 이때 pop 조건은 `a[top] <= a[i]`입니다.

**흔한 실수:** 스택에 값을 넣고 인덱스가 필요해지는 것입니다. 값이 중복될 수 있어서 값으로는 위치를 되찾지 못합니다. 처음부터 인덱스를 넣습니다.

## 다음 작은 수

다음 작은 수(next smaller element)는 오른쪽에서 처음 나오는 더 작은 값이며, 다음 큰 수의 부등호를 뒤집은 것입니다. 스택은 증가 상태를 유지합니다.

```js
function nextSmaller(a) {
  const res = new Array(a.length).fill(-1)
  const st = []
  for (let i = 0; i < a.length; i++) {
    while (st.length && a[st.at(-1)] > a[i]) {
      res[st.pop()] = a[i]
    }
    st.push(i)
  }
  return res
}
nextSmaller([4, 5, 2, 10, 8]) // [2, 2, -1, 8, -1]
```

- 다음 큰 수 코드와 다른 곳은 `<`가 `>`로 바뀐 한 글자뿐입니다. 문제를 읽고 "큰가 작은가, 같은 값을 포함하는가"만 정하면 됩니다.
- 큰 쪽과 작은 쪽 중 어느 쪽 스택이냐를 헷갈리면 "pop되는 원소가 어떤 조건을 만족하는가"를 생각합니다. 다음 작은 수에서는 새 값이 pop되는 원소보다 작아야 하므로 스택 위가 새 값보다 크면 pop합니다.
- 다음 작은 수까지의 거리나 그 위치를 구하는 문제는 "주식 가격" 절에서 다룹니다.

## 이전 큰 수

이전 큰 수(previous greater element)는 왼쪽 방향에서 처음 나오는 더 큰 값입니다. 왼쪽에서 오른쪽으로 순회하면서 현재 원소를 넣기 직전에 스택에 남은 맨 위 원소가 답입니다. 그 앞에서 `a[i]` 이하인 원소는 모두 버립니다.

```js
function prevGreater(a) {
  const res = []
  const st = []
  for (let i = 0; i < a.length; i++) {
    while (st.length && a[st.at(-1)] <= a[i]) st.pop()
    res.push(st.length ? a[st.at(-1)] : -1)
    st.push(i)
  }
  return res
}
prevGreater([2, 1, 5, 3, 4]) // [-1, 2, -1, 5, 5]
```

- pop 조건이 `<=`입니다. "더 큰"이 엄격한 비교이므로 같은 값은 답이 될 수 없어서 버립니다. 다음 큰 수에서는 pop될 때 답을 기록했지만, 여기서는 pop 후 남은 위 원소가 답입니다.
- 한 번의 순회로 두 정보를 동시에 얻을 수 있습니다. 원소가 pop되는 순간은 오른쪽 첫 조건 위반 원소를, 원소를 push하기 직전의 스택 위는 왼쪽 첫 조건 위반 원소를 알려 줍니다. 히스토그램은 이 두 정보를 모두 씁니다.
- 방향 정리입니다.

| 구하는 것 | 순회 방향 | 답을 읽는 시점 |
|-----------|-----------|----------------|
| 다음 큰·작은 수 | 왼쪽 → 오른쪽 | pop될 때 |
| 이전 큰·작은 수 | 왼쪽 → 오른쪽 | push 직전 스택 위 |
| 다음 큰·작은 수(다른 방식) | 오른쪽 → 왼쪽 | push 직전 스택 위 |

## 히스토그램

히스토그램에서 가장 큰 직사각형은 너비 1인 막대들이 일렬로 놓였을 때, 연속한 막대로 만들 수 있는 가장 넓은 직사각형의 넓이입니다. 직사각형의 높이는 포함한 막대 중 가장 낮은 막대이므로, 각 막대를 "가장 낮은 막대"로 보고 왼쪽·오른쪽으로 얼마나 뻗을 수 있는지 구합니다.

막대 `j`가 높이를 정하는 직사각형의 범위는 왼쪽으로 처음 `h[j]`보다 낮은 막대 다음부터, 오른쪽으로 처음 `h[j]`보다 낮은 막대 앞까지입니다. 그 두 위치가 단조 스택으로 한 번에 나옵니다. 증가 스택을 쓰고, 막대가 pop되는 순간 그 막대의 오른쪽 경계가 확정됩니다.

```js
function largestRect(h) {
  const st = [] // 인덱스, 높이가 증가
  let best = 0
  for (let i = 0; i <= h.length; i++) {
    const cur = i === h.length ? 0 : h[i]
    while (st.length && h[st.at(-1)] >= cur) {
      const height = h[st.pop()]
      const left = st.length ? st.at(-1) + 1 : 0
      best = Math.max(best, height * (i - left))
    }
    st.push(i)
  }
  return best
}
largestRect([2, 1, 5, 6, 2, 3]) // 10 (높이 5, 너비 2)
```

- 끝에 높이 0인 가상의 막대(`i === h.length`일 때 `cur = 0`)를 하나 더 놓아서 스택에 남은 막대를 모두 pop해 계산합니다. 이 막대를 보초(sentinel)라고 합니다.
- 막대 `j`가 pop될 때 오른쪽 경계는 `i`(처음으로 낮거나 같은 막대의 위치)입니다. 왼쪽 경계는 pop 후 스택 위 원소의 다음 칸이며, 스택이 비었으면 0입니다. 너비는 `i - left`입니다.
- 같은 높이의 막대가 연속하면 앞 막대는 pop되지만 그 너비가 줄어든 채 계산됩니다. 뒤 막대가 같은 `left`를 쓰고 더 오른쪽까지 가므로 최대 넓이는 놓치지 않습니다.

`h = [2, 1, 5, 6, 2, 3]`에서 넓이를 계산하는 시점입니다.

| i | `cur` | pop되는 막대(높이) | left | 넓이 |
|---|-------|--------------------|------|------|
| 1 | 1 | 인덱스 0(2) | 0 | 2 × 1 = 2 |
| 4 | 2 | 인덱스 3(6) | 3 | 6 × 1 = 6 |
| 4 | 2 | 인덱스 2(5) | 2 | 5 × 2 = 10 |
| 6 | 0 | 인덱스 5(3) | 5 | 3 × 1 = 3 |
| 6 | 0 | 인덱스 4(2) | 2 | 2 × 4 = 8 |
| 6 | 0 | 인덱스 1(1) | 0 | 1 × 6 = 6 |

- 시간 O(N), 공간 O(N)입니다. 모든 막대 쌍을 보는 O(N²)보다 빠릅니다.
- 넓이가 `Number.MAX_SAFE_INTEGER`(2^53 − 1)를 넘을 수 있는지 높이 최댓값 × N으로 확인합니다.
- 0과 1로 이루어진 격자에서 가장 큰 직사각형 문제는 행마다 "위로 연속한 1의 개수"를 막대 높이로 보고 이 함수를 행 수만큼 호출해 O(HW)에 풉니다(격자는 17편).

## 주식 가격

주식 가격 유형은 날짜별 가격 배열에서, 각 날짜 기준으로 앞이나 뒤의 첫 가격 변화까지의 일수를 구하는 문제입니다. 다음 작은 수와 이전 큰 수의 위치를 쓰는 응용입니다. 위치 차이를 구하므로 인덱스를 저장한 스택이 필요합니다.

가격이 처음으로 떨어지는 날까지 며칠 걸리는지 구합니다. 끝까지 떨어지지 않으면 마지막 날까지의 일수입니다.

```js
function daysUntilDrop(p) {
  const n = p.length
  const res = new Array(n).fill(0)
  const st = []
  for (let i = 0; i < n; i++) {
    while (st.length && p[st.at(-1)] > p[i]) {
      const j = st.pop()
      res[j] = i - j // j일의 가격이 i일에 처음 떨어짐
    }
    st.push(i)
  }
  for (const j of st) res[j] = n - 1 - j // 끝까지 안 떨어짐
  return res
}
daysUntilDrop([3, 1, 2, 4, 2]) // [1, 3, 2, 1, 0]
```

- `p[j]`보다 `p[i]`가 엄격하게 낮을 때 pop하므로 같은 가격은 떨어진 것으로 보지 않습니다.
- 스택에 남은 날은 끝까지 떨어지지 않은 날입니다. 이 날들의 답은 마지막 날까지의 일수 `n - 1 - j`입니다. 문제마다 "끝까지 안 떨어지면 0"인지 "마지막 날까지의 일수"인지 다르므로 조건을 읽고 고릅니다.
- 시간 O(N)입니다. 날짜마다 뒤를 훑는 O(N²)보다 빠릅니다.

반대 방향 유형은 주가 스팬(stock span)입니다. 오늘 가격 이하였던 연속된 날이 며칠인지, 즉 오늘을 포함해 왼쪽으로 처음 오늘보다 큰 가격이 나오기 전까지의 날 수입니다.

```js
function stockSpan(p) {
  const res = []
  const st = []
  for (let i = 0; i < p.length; i++) {
    while (st.length && p[st.at(-1)] <= p[i]) st.pop()
    res.push(st.length ? i - st.at(-1) : i + 1)
    st.push(i)
  }
  return res
}
stockSpan([100, 80, 60, 70, 60, 75, 85])
// [1, 1, 1, 2, 1, 4, 6]
```

- 이전 큰 수의 위치 `st.at(-1)`와 현재 위치의 거리가 스팬입니다. 이전 큰 값이 없으면 처음부터 오늘까지라서 `i + 1`입니다.

## Monotonic Queue

단조 큐(monotonic queue)는 큐의 값이 한 방향으로 정렬되도록 유지하는 덱(deque)입니다. 고정 길이 윈도우의 최댓값을 O(N)에 구할 때 씁니다. 윈도우가 밀리면 앞에서는 윈도우 밖으로 나간 원소를 빼고, 뒤에서는 새 원소보다 작은 후보를 빼는 구조입니다.

왜 맞는가: 새 원소 `x`가 들어올 때, 뒤쪽에 있던 `x`보다 작거나 같은 원소 `y`는 `x`보다 먼저 윈도우를 떠나고 항상 `x` 이하이므로 앞으로 최댓값이 될 수 없습니다. 그래서 버려도 됩니다. 남은 후보는 값이 앞에서 뒤로 감소하고, 맨 앞이 현재 윈도우의 최댓값입니다.

| 연산 | 위치 | 하는 일 |
|------|------|---------|
| 만료 제거 | 앞 | 인덱스가 윈도우를 벗어난 후보를 뺌 |
| 후보 정리 | 뒤 | 새 원소 이하인 후보를 뺌 |
| 삽입 | 뒤 | 새 원소의 인덱스를 넣음 |
| 최댓값 읽기 | 앞 | 맨 앞 후보의 값 |

- 인덱스를 저장해야 만료 여부를 알 수 있습니다. 값만 들고 있으면 어느 원소가 윈도우를 떠났는지 알 수 없습니다.
- 단조 스택과 같은 구조에 앞쪽 만료가 더해진 것입니다. 스택은 한쪽만 쓰고, 큐는 양쪽을 씁니다(자세히는 20편).
- 덱 구현은 20편을 따릅니다. `Array.prototype.shift`는 나머지 원소를 한 칸씩 당기는 연산이라 길이에 비례하는 비용이 들 수 있으므로 큐의 앞은 `head` 인덱스로 처리합니다.
- 최솟값은 감소를 증가로, 비교를 반대로 바꿔 구합니다.

## Sliding Window Maximum

슬라이딩 윈도우 최댓값은 길이 K 윈도우를 한 칸씩 밀며 각 윈도우의 최댓값을 모으는 문제입니다. 31편에서 O(NK)로 푼 문제를 단조 큐로 O(N)에 풉니다.

```js
function windowMax(a, K) {
  const dq = [], res = [] // dq: 인덱스, 값이 감소
  let head = 0            // 앞의 위치(shift 대신)
  for (let i = 0; i < a.length; i++) {
    while (dq.length > head && a[dq.at(-1)] <= a[i]) {
      dq.pop()
    }
    dq.push(i)
    if (dq[head] <= i - K) head++
    if (i >= K - 1) res.push(a[dq[head]])
  }
  return res
}
windowMax([1, 3, -1, -3, 5, 3, 6, 7], 3)
// [3, 3, 5, 5, 6, 7]
```

`a = [1, 3, -1, -3, 5, 3, 6, 7]`, `K = 3`의 일부 추적입니다. 덱에는 인덱스가 있고 괄호는 그 값입니다.

| i | `a[i]` | 덱 (앞 → 뒤) | 윈도우 최댓값 |
|---|--------|--------------|---------------|
| 0 | 1 | 0(1) | - |
| 1 | 3 | 1(3) | - |
| 2 | -1 | 1(3), 2(-1) | 3 |
| 3 | -3 | 1(3), 2(-1), 3(-3) | 3 |
| 4 | 5 | 4(5) (앞의 세 후보가 모두 5 이하라 뒤에서 제거) | 5 |

- 시간 O(N)입니다. 각 인덱스는 한 번 들어가고 한 번만 나갑니다. 윈도우마다 훑는 O(NK)나 힙의 O(N log N)보다 빠릅니다(자세히는 31편, 47편).
- 앞 만료 검사는 `if`면 충분합니다. 윈도우는 한 칸씩 밀려서 한 번에 최대 한 원소만 만료되기 때문입니다.
- `dq.length > head` 조건은 앞에서 제거해 비어 있는 상태에서 `a[dq.at(-1)]`를 읽는 일을 막습니다.
- `head`를 쓰면 배열이 앞쪽으로 줄지 않아 메모리가 최대 N까지 늘어납니다. 보통은 허용되지만 제한이 빠듯하면 원형 버퍼 덱을 씁니다(자세히는 20편).
- 같은 값을 `<=`로 pop했습니다. 같은 값이면 더 늦게 윈도우를 떠나는 쪽이 나으므로 앞의 것을 버립니다. `<`로 쓰면 같은 값이 쌓여 덱이 길어질 뿐 결과는 같습니다.
- 윈도우 최솟값을 이용한 DP 최적화는 74편에서 다룹니다.

**흔한 실수:** `i - K + 1` 대신 `i - K`로 만료를 검사하는 데서 오는 off-by-one입니다. 윈도우가 `[i - K + 1, i]`이므로 인덱스가 `i - K` 이하이면 만료입니다(`dq[head] <= i - K`).

## 원형 배열 처리

원형 배열은 끝 다음이 처음으로 이어지는 배열입니다. 다음 큰 수를 구할 때 배열을 두 번 이어 붙인 것으로 보고 2N번 순회하면 됩니다. 인덱스는 `i % n`으로 감쌉니다.

```js
function nextGreaterCircular(a) {
  const n = a.length
  const res = new Array(n).fill(-1)
  const st = []
  for (let i = 0; i < 2 * n; i++) {
    const x = a[i % n]
    while (st.length && a[st.at(-1)] < x) {
      res[st.pop()] = x
    }
    if (i < n) st.push(i)
  }
  return res
}
nextGreaterCircular([1, 2, 1]) // [2, -1, 2]
nextGreaterCircular([5, 4, 3, 4, 5]) // [-1, 5, 4, 5, -1]
```

- 첫 N번 순회에서만 push합니다. 둘째 순회는 첫 순회에서 답을 못 찾은 원소가 왼쪽 방향으로 이어지는 값을 찾게 하는 용도라서, 다시 push하면 같은 원소를 두 번 넣게 됩니다.
- 둘째 순회의 `x`가 이미 답이 정해진 원소를 pop하는 일은 없습니다. 답이 정해진 원소는 스택에서 이미 빠졌기 때문입니다.
- 시간 O(N)입니다. 순회는 2N번이지만 각 원소는 한 번 push되고 한 번 pop됩니다.
- 이전 큰 수나 다른 단조 스택 문제도 같은 방법으로 원형으로 확장합니다.
- 원형에서 가장 큰 값 자신은 자기 자신보다 큰 값이 없으므로 -1이 그대로 남습니다. 최댓값이 여러 개일 때도 서로를 "더 크다"고 보지 않아 모두 -1입니다.

## 핵심 정리

- 단조 스택은 스택 안을 한 방향 정렬로 유지하며 조건을 깨는 원소를 pop하고, 각 원소가 한 번씩 들어가고 나와서 O(N)입니다. 값 대신 인덱스를 저장합니다.
- 다음 큰 수는 감소 스택에서 새 값이 위 원소보다 클 때 pop하며 답을 기록하고, 다음 작은 수는 부등호만 뒤집습니다. 이전 큰 수는 push 직전의 스택 위가 답입니다.
- 히스토그램은 증가 스택에서 막대가 pop될 때 `i - left`를 너비로 넓이를 계산하고, 끝에 높이 0의 보초를 둡니다.
- 주식 가격 유형은 pop될 때 `i - j`를 기록하거나 push 직전 스택 위와의 거리를 구하며, 끝까지 남은 원소의 처리 조건을 문제에서 확인합니다.
- 단조 큐는 앞에서 윈도우 밖 인덱스를 빼고 뒤에서 새 원소 이하인 후보를 빼서 윈도우 최댓값을 O(N)에 구하며, 앞 제거는 `shift` 대신 `head` 인덱스를 씁니다.
- 원형 배열은 2N번 순회하며 첫 N번에만 push해 처리합니다.
