## Interval 기본

구간(interval)은 수직선 위의 시작점과 끝점으로 정해지는 범위입니다. 코딩테스트에서는 회의 시간, 작업 기간, 선분, 좌표 범위 같은 모양으로 나옵니다. JavaScript에서는 `[start, end]` 배열 하나로 표현하고, 구간 목록은 배열의 배열입니다.

```js
const list = [[1, 3], [2, 6], [8, 10]]
const [start, end] = list[0]   // 1, 3
const length = end - start     // 2 (반열린 구간의 길이)
```

구간 문제를 푸는 첫 단계는 정렬입니다. 정렬하면 겹침 확인이 인접한 구간끼리의 비교로 줄어듭니다(비교 함수는 26편).

| 문제 유형 | 정렬 기준 |
|-----------|-----------|
| 병합, 삽입, 교집합, 덮기 | 시작점 오름차순 |
| 겹치지 않는 최대 개수, 점으로 덮기 | 끝점 오름차순(자세히는 33편) |
| 최소 회의실 | 시작점 목록과 끝점 목록을 따로 정렬 |

- 두 구간 사이의 관계는 세 가지입니다. 떨어져 있음, 일부가 겹침, 한쪽이 다른 쪽을 포함함. 포함 관계를 놓치는 것이 흔한 실수의 원인입니다.
- 구간 문제의 입력 크기가 N이면 정렬 O(N log N)이 대부분의 시간입니다(자세히는 13편).
- 구간 정렬은 `a[0] - b[0]`처럼 숫자 뺄셈 비교 함수가 필요합니다. 기본 `sort`는 문자열 순서라서 `[10, 12]`가 `[2, 3]`보다 앞에 옵니다.

## 닫힌 구간과 반열린 구간

구간의 끝점이 포함되는지에 따라 표기와 겹침 조건이 달라집니다. 문제를 읽으면 가장 먼저 경계를 확인합니다.

| 표기 | 이름 | 포함 범위 | 정수 구간의 길이 |
|------|------|-----------|------------------|
| `[a, b]` | 닫힌 구간 | a 이상 b 이하 | b - a + 1 |
| `[a, b)` | 반열린 구간 | a 이상 b 미만 | b - a |

- 반열린 구간은 `[1, 3)`과 `[3, 5)`를 이어 붙여 `[1, 5)`가 되고, 겹치는 점이 없습니다. 길이가 곧 `end - start`라서 계산이 단순합니다.
- 닫힌 구간 `[1, 3]`과 `[3, 5]`는 점 3을 공유하므로 겹칩니다.
- 정수 구간이면 닫힌 `[a, b]`는 반열린 `[a, b + 1)`과 같습니다. 문제의 구간을 반열린으로 바꿔 두면 이후 코드가 단순해집니다.
- 문제 문장이 "끝나는 시각에 다른 회의가 시작할 수 있다"라고 하면 반열린 구간입니다. "같은 시각에 걸치면 겹친다"라고 하면 닫힌 구간입니다.

**흔한 실수:** 겹침 조건의 등호입니다.

| 경계 | 겹침 조건 | `[1, 3]`과 `[3, 5]` |
|------|-----------|---------------------|
| 닫힌 | `a[0] <= b[1] && b[0] <= a[1]` | 겹침 |
| 반열린 | `a[0] < b[1] && b[0] < a[1]` | 겹치지 않음 |

문제의 경계 조건과 코드의 등호를 일치시키지 않으면 경계가 닿는 입력에서만 틀립니다. 샘플이 통과해도 놓치기 쉽습니다.

## 겹치는 구간 판별

두 구간이 겹치려면 한 구간의 시작이 다른 구간의 끝보다 앞서야 하고, 반대도 성립해야 합니다. 떨어져 있는 경우를 부정하는 식입니다. 구간 `a`가 `b`의 완전히 왼쪽 또는 완전히 오른쪽에 있지 않으면 겹칩니다.

```js
const overlapsClosed = (a, b) =>
  a[0] <= b[1] && b[0] <= a[1]
const overlapsHalf = (a, b) =>
  a[0] < b[1] && b[0] < a[1]
overlapsClosed([1, 3], [3, 5]) // true
overlapsHalf([1, 3], [3, 5])   // false
overlapsHalf([1, 5], [2, 3])   // true (포함도 겹침)
```

- 이 식은 부분 겹침과 포함 모두 한 번에 처리합니다. 시작 순서를 따로 나눠 경우를 세지 않아도 됩니다.
- 겹친 부분의 시작은 `Math.max(a[0], b[0])`, 끝은 `Math.min(a[1], b[1])`입니다. 시작이 끝보다 작으면(닫힌은 이하) 실제로 겹친 것입니다.

목록 안에 겹치는 구간이 하나라도 있는지 확인하려면 시작점으로 정렬한 뒤 인접한 쌍만 확인합니다.

```js
function anyOverlap(list) {  // 반열린 구간
  const s = [...list].sort((a, b) => a[0] - b[0])
  for (let i = 1; i < s.length; i++) {
    if (s[i][0] < s[i - 1][1]) return true
  }
  return false
}
anyOverlap([[1, 3], [3, 5], [6, 8]]) // false
anyOverlap([[1, 4], [2, 3]])         // true
```

- 모든 쌍을 비교하면 O(N²)이지만 정렬 후 인접 비교는 정렬 포함 O(N log N)입니다.
- 겹침이 하나라도 있다면 인접한 쌍 중에도 반드시 있습니다. `s[i]`가 앞의 `s[k]`와 겹치면 `s[k + 1]`의 시작이 `s[i]`의 시작 이하이므로 `s[k + 1]`도 `s[k]`와 겹치기 때문입니다.
- 겹침의 존재 여부가 아니라 어떤 구간들이 겹치는지 구하려면 직전 구간이 아니라 지금까지의 최대 끝점과 비교해야 합니다(아래 "Interval Merge").

**흔한 실수:** 겹침 관계를 직전 구간의 끝만으로 판단하는 것입니다. `[1, 10]`, `[2, 3]`, `[4, 5]`를 시작점으로 정렬하면 `[4, 5]`는 직전 구간 `[2, 3]`과 떨어져 있지만 `[1, 10]`에 포함됩니다.

## Interval Merge

구간 병합은 겹치는 구간을 하나로 합쳐 서로 겹치지 않는 구간 목록을 만드는 문제입니다. 시작점으로 정렬하고, 결과의 마지막 구간과 겹치면 끝을 늘리고, 아니면 새 구간으로 추가합니다.

```js
function merge(list) {  // 닫힌 구간: 끝이 닿으면 병합
  const s = [...list].sort((a, b) => a[0] - b[0])
  const res = []
  for (const [st, en] of s) {
    const last = res.at(-1)
    if (last && st <= last[1]) {
      last[1] = Math.max(last[1], en) // 끝점은 큰 쪽
    } else {
      res.push([st, en])
    }
  }
  return res
}
merge([[8, 10], [1, 3], [2, 6], [15, 18], [17, 20]])
// [[1, 6], [8, 10], [15, 20]]
```

정렬 후 `[[1,3],[2,6],[8,10],[15,18],[17,20]]`의 흐름입니다.

| 구간 | 결과의 마지막 | 판단 | 결과 |
|------|----------------|------|------|
| [1, 3] | 없음 | 새 구간 | [1, 3] |
| [2, 6] | [1, 3] | 2 ≤ 3, 끝을 6으로 | [1, 6] |
| [8, 10] | [1, 6] | 8 > 6, 새 구간 | [1, 6], [8, 10] |
| [15, 18] | [8, 10] | 새 구간 | …, [15, 18] |
| [17, 20] | [15, 18] | 17 ≤ 18, 끝을 20으로 | …, [15, 20] |

- `Math.max(last[1], en)`이 핵심입니다. 포함된 구간(`[1, 10]` 뒤의 `[2, 3]`)이 오면 끝점이 줄어들지 않아야 합니다. `last[1] = en`으로 쓰면 `[1, 10]`이 `[1, 3]`으로 줄어듭니다.
- 반열린 구간 문제면 병합 조건이 `st < last[1]`입니다. 끝이 닿는 `[1, 3)`, `[3, 5)`는 병합하지 않는 문제도 있고, 합쳐서 연속된 구간으로 보는 문제도 있으니 문제 문장을 확인합니다.
- 정수 닫힌 구간에서 `[1, 3]`과 `[4, 5]`처럼 인접한 구간(끝 + 1 = 시작)을 합칠지는 문제마다 다릅니다. 합치려면 조건을 `st <= last[1] + 1`로 씁니다.
- 정렬이 O(N log N), 병합이 O(N)입니다. `res`에는 `[st, en]` 새 배열을 넣으므로 `last[1]`을 고쳐도 입력 구간은 바뀌지 않습니다.
- 병합은 구간 문제의 기본 도구입니다. 합집합의 전체 길이(겹침을 한 번만 센 총 길이)는 병합 후 길이를 더하면 됩니다.

**흔한 실수:** 정렬하지 않고 병합하는 것, 그리고 끝점을 `max`로 갱신하지 않고 대입하는 것입니다.

## Interval Insert

구간 삽입은 겹치지 않고 시작점 순으로 정렬된 구간 목록에 새 구간을 넣고, 겹치는 구간을 병합한 결과를 구하는 문제입니다. 목록이 이미 정렬되어 있으므로 다시 정렬하지 않고 세 단계로 한 번 훑습니다.

1. 새 구간보다 완전히 왼쪽에 있는 구간(`끝 < 새 시작`)을 그대로 옮긴다.
2. 새 구간과 겹치는 구간(`시작 <= 새 끝`)을 새 구간에 합친다.
3. 나머지 오른쪽 구간을 그대로 옮긴다.

```js
function insert(list, add) {  // 닫힌 구간, list는 정렬·비겹침
  let [st, en] = add
  const res = []
  let i = 0, n = list.length
  while (i < n && list[i][1] < st) res.push(list[i++])
  while (i < n && list[i][0] <= en) {
    st = Math.min(st, list[i][0])
    en = Math.max(en, list[i][1])
    i++
  }
  res.push([st, en])
  while (i < n) res.push(list[i++])
  return res
}
```

```js
const list = [[1, 2], [3, 5], [6, 7], [8, 10], [12, 16]]
insert(list, [4, 8]) // [[1, 2], [3, 10], [12, 16]]
```

| 단계 | 대상 | 동작 |
|------|------|------|
| 왼쪽 복사 | [1, 2] | 끝 2가 새 시작 4보다 작아 그대로 |
| 병합 | [3, 5], [6, 7], [8, 10] | 시작이 8 이하라서 합쳐 [3, 10] |
| 오른쪽 복사 | [12, 16] | 그대로 |

- 시간은 O(N)이고 정렬이 필요 없습니다. 새 구간 하나를 정렬된 목록에 넣을 때 전체를 다시 정렬하면 O(N log N)이라 비효율입니다.
- 두 번째 반복의 조건 `list[i][0] <= en`은 `en`이 갱신되면서 함께 커지므로, 여러 구간을 연달아 흡수합니다.
- 반열린 구간이면 첫 반복은 `list[i][1] <= st`, 둘째 반복은 `list[i][0] < en`입니다.
- 간단한 대안은 새 구간을 목록에 추가하고 Interval Merge를 호출하는 것입니다. 구현이 짧고 정렬 비용(O(N log N))만 더 듭니다.

**흔한 실수:** 두 번째 반복에서 `en`을 갱신하지 않는 것입니다. 병합한 구간의 끝이 새 구간의 끝보다 길면 뒤의 구간을 놓칩니다.

## Interval Intersection

구간 교집합은 정렬된 두 구간 목록(각각 안에서는 서로 겹치지 않음)에서 두 목록의 구간이 겹치는 부분을 모두 구하는 문제입니다. 두 목록에 포인터를 하나씩 두고, 겹침을 계산한 뒤 끝이 더 빠른 쪽의 포인터를 앞으로 옮깁니다(포인터는 30편).

```js
function intersect(a, b) {  // 닫힌 구간
  const res = []
  let i = 0, j = 0
  while (i < a.length && j < b.length) {
    const lo = Math.max(a[i][0], b[j][0])
    const hi = Math.min(a[i][1], b[j][1])
    if (lo <= hi) res.push([lo, hi])
    if (a[i][1] < b[j][1]) i++
    else j++
  }
  return res
}
const a = [[0, 2], [5, 10], [13, 23]]
const b = [[1, 5], [8, 12], [15, 24]]
intersect(a, b) // [[1, 2], [5, 5], [8, 10], [15, 23]]
```

| a의 구간 | b의 구간 | lo | hi | 결과 | 옮기는 쪽 |
|----------|----------|----|----|------|-----------|
| [0, 2] | [1, 5] | 1 | 2 | [1, 2] | a (끝 2 &lt; 5) |
| [5, 10] | [1, 5] | 5 | 5 | [5, 5] | b (a의 끝 10이 5보다 큼) |
| [5, 10] | [8, 12] | 8 | 10 | [8, 10] | a |
| [13, 23] | [8, 12] | 13 | 12 | 없음 | b |
| [13, 23] | [15, 24] | 15 | 23 | [15, 23] | a |

- 끝이 더 빠른 구간은 상대 목록의 다음 구간과는 더 이상 겹칠 수 없으므로 버립니다. 끝이 같으면 어느 쪽을 옮겨도 정답입니다.
- 시간은 O(A + B)입니다. 모든 쌍을 비교하는 O(A × B)보다 훨씬 빠릅니다.
- 반열린 구간이면 조건이 `lo < hi`입니다. 닫힌 구간에서 `[5, 5]`는 점 하나로 이뤄진 유효한 구간이지만, 문제에 따라 길이 0을 제외할 수 있으니 확인합니다.
- 입력이 정렬되어 있지 않으면 각각을 병합한 뒤 이 방식을 씁니다.

**흔한 실수:** 포인터를 `lo`나 시작점이 작은 쪽으로 옮기는 것입니다. 옮기는 기준은 끝점입니다.

## 최소 회의실

최소 회의실은 모든 회의를 진행하려면 회의실이 최소 몇 개 필요한지 구하는 문제입니다. 답은 어느 한 시점에 동시에 진행되는 회의의 최대 수입니다(33편의 회의실 배정은 회의실이 하나일 때 최대 회의 수를 묻는 다른 문제입니다).

시작 시각들과 끝 시각들을 따로 정렬하고, 시작 시각을 오름차순으로 보면서 가장 이른 끝 시각과 비교합니다. 새 회의가 가장 먼저 끝나는 회의보다 먼저 시작하면 방이 하나 더 필요하고, 아니면 그 방을 재사용합니다.

```js
function minRooms(list) {  // 반열린 구간
  const starts = list.map((x) => x[0]).sort((a, b) => a - b)
  const ends = list.map((x) => x[1]).sort((a, b) => a - b)
  let rooms = 0, j = 0
  for (const s of starts) {
    if (s < ends[j]) rooms++ // 비는 방이 없음
    else j++                 // 끝난 방을 재사용
  }
  return rooms
}
minRooms([[0, 30], [5, 10], [15, 20]]) // 2
```

| 새 회의 시작 | 가장 이른 끝 | 판단 | 방 수 |
|--------------|--------------|------|-------|
| 0 | 10 | 0 &lt; 10, 새 방 | 1 |
| 5 | 10 | 5 &lt; 10, 새 방 | 2 |
| 15 | 10 | 15 이상, 끝난 방 재사용 | 2 |

- 정렬이 O(N log N)이고 훑기가 O(N)입니다.
- 비교 `s < ends[j]`의 등호는 반열린 구간 기준입니다. 끝나는 시각에 시작할 수 있으면 `[1, 2]`, `[2, 3]`은 방 하나로 충분하고 위 코드는 1을 반환합니다. 닫힌 구간이라면 `s <= ends[j]`로 바꿔 2가 되게 합니다.
- 끝 시각 목록을 따로 정렬해도 되는 이유는 "방이 몇 개 필요한가"는 어느 방에 어느 회의가 배정되는지가 아니라 동시에 진행되는 수만 필요하기 때문입니다.
- 회의를 실제 방에 배정한 결과까지 필요하면 시작점 순으로 보면서 가장 일찍 끝나는 방을 힙으로 관리합니다(자세히는 47편).
- 시점별 겹침 수를 이벤트로 다루는 일반화가 Sweep Line입니다(자세히는 55편).

**흔한 실수:** 시작점과 끝점을 한 정렬 안에서 `[시각, 종류]`로 섞을 때 같은 시각의 순서를 잘못 두는 것입니다. 끝 이벤트를 시작 이벤트보다 먼저 처리해야 반열린 구간의 재사용이 맞습니다.

## 구간 Scheduling

구간 스케줄링은 구간(작업)들 중 일부를 서로 겹치지 않게 골라 목표를 최적화하는 문제군입니다. 목표에 따라 풀이가 갈립니다.

| 목표 | 방법 | 시간 |
|------|------|------|
| 겹치지 않는 구간 수 최대 | 끝점 정렬 그리디(33편) | O(N log N) |
| 선택한 구간의 가중치 합 최대 | DP와 이분 탐색 | O(N log N) |
| 모든 구간을 처리할 방의 수 최소 | 최소 회의실(위) | O(N log N) |
| 모든 구간에 닿는 점의 수 최소 | 끝점 정렬 그리디(33편) | O(N log N) |

가중치가 있으면 그리디가 틀립니다. 짧은 구간 여러 개보다 긴 구간 하나의 가중치가 클 수 있기 때문입니다. 끝점으로 정렬하고, `dp[i]`를 앞의 `i`개 구간만 썼을 때의 최대 가중치로 둡니다(DP는 40편).

- `i`번째 구간을 고르지 않으면 `dp[i - 1]`입니다.
- 고르면 가중치 `w`에 `i`번째 구간과 겹치지 않는 마지막 구간까지의 최댓값 `dp[p]`를 더합니다. `p`는 끝이 `i`번째 시작 이하인 구간의 수이고 끝점으로 정렬했으므로 이분 탐색으로 찾습니다(자세히는 28편).

```js
function bestWeight(list) {  // [시작, 끝, 가중치], 반열린
  const s = [...list].sort((a, b) => a[1] - b[1])
  const dp = Array(s.length + 1).fill(0)
  for (let i = 1; i <= s.length; i++) {
    const [st, , w] = s[i - 1]
    let lo = 0, hi = i - 1   // 끝이 st 이하인 구간 수를 찾는다
    while (lo < hi) {
      const mid = (lo + hi + 1) >> 1
      if (s[mid - 1][1] <= st) lo = mid
      else hi = mid - 1
    }
    dp[i] = Math.max(dp[i - 1], dp[lo] + w)
  }
  return dp[s.length]
}
```

구간 `[[1,3,5],[2,5,6],[4,6,5],[6,7,4],[5,8,11],[7,9,2]]`(시작, 끝, 가중치)는 이미 끝점 순입니다.

| i | 구간 | 앞에서 겹치지 않는 구간 수 p | dp[i] |
|---|------|------------------------------|-------|
| 1 | [1, 3] 가중치 5 | 0 | 5 |
| 2 | [2, 5] 가중치 6 | 0 | 6 |
| 3 | [4, 6] 가중치 5 | 1 | 10 |
| 4 | [6, 7] 가중치 4 | 3 | 14 |
| 5 | [5, 8] 가중치 11 | 2 | 17 |
| 6 | [7, 9] 가중치 2 | 4 | 17 |

답은 17이고 구간 `[2, 5]`와 `[5, 8]`을 고른 경우입니다(반열린이라 끝 5와 시작 5가 겹치지 않습니다).

- 가중치가 모두 1이면 이 DP의 답은 그리디의 선택 수와 같습니다.
- 구간 수가 작으면 이분 탐색 없이 이중 반복으로 `p`를 찾아도 되지만 N이 크면 O(N²)입니다.

**흔한 실수:** 가중치가 있는 문제에 끝점 정렬 그리디를 쓰는 것입니다. 구간 수를 최대로 만드는 것과 가중치 합을 최대로 만드는 것은 다른 문제입니다.

## 최소 개수의 구간으로 범위 덮기

구간 덮기는 구간 여러 개를 골라 `[0, L)` 전체를 빈틈없이 덮는 데 필요한 최소 구간 수를 구하는 문제입니다. 지금까지 덮은 오른쪽 끝(`reach`)을 기준으로, 시작이 `reach` 이하인 구간 중 끝이 가장 먼 구간을 고르는 그리디입니다. 시작점으로 정렬합니다.

```js
function cover(segs, L) {  // 반열린, [0, L)을 덮는다
  const s = [...segs].sort((a, b) => a[0] - b[0])
  let reach = 0, i = 0, count = 0
  while (reach < L) {
    let far = reach
    while (i < s.length && s[i][0] <= reach) {
      far = Math.max(far, s[i++][1]) // 이어 붙일 수 있는 최대 끝
    }
    if (far === reach) return -1     // 틈이 있어서 덮을 수 없다
    reach = far
    count++
  }
  return count
}
```

```js
const segs = [
  [0, 3], [2, 5], [1, 4], [4, 8], [6, 10], [9, 12],
]
cover(segs, 10) // 4
```

| 단계 | reach | 시작이 reach 이하인 후보 | 고른 구간 | 새 reach |
|------|-------|--------------------------|-----------|----------|
| 1 | 0 | [0, 3] | [0, 3] | 3 |
| 2 | 3 | [1, 4], [2, 5] | [2, 5] | 5 |
| 3 | 5 | [4, 8] | [4, 8] | 8 |
| 4 | 8 | [6, 10] | [6, 10] | 10 |

`reach`가 10에 닿았으므로 구간 4개가 답입니다.

- 정당성은 교환 논증입니다. 같은 `reach`에서 이어 붙일 수 있는 구간 중 끝이 가장 먼 것을 고르면, 다른 어떤 선택으로 만든 해도 그 구간으로 바꿔 구간 수가 늘지 않습니다.
- 정렬 후 인덱스 `i`는 한 방향으로만 가므로 훑기는 O(N)이고 전체는 O(N log N)입니다.
- 시작이 `reach` 이하인 구간이 없거나 있어도 끝이 `reach`를 넘지 못하면 틈이 있는 것이라 `-1`입니다.
- 닫힌 정수 구간 `[a, b]`는 반열린 `[a, b + 1)`로 바꿔 같은 코드를 씁니다.

**흔한 실수:** 끝이 가장 먼 구간이 아니라 시작이 가장 이른 구간을 고르는 것입니다. 시작은 이미 `reach` 이하라는 조건을 만족하면 충분하고, 고를 기준은 끝점입니다.

## 핵심 정리

- 구간은 `[start, end]` 배열로 표현하고, 푸는 첫 단계는 정렬입니다. 병합·삽입·교집합·덮기는 시작점, 최대 개수·점 덮기는 끝점으로 정렬합니다.
- 닫힌 구간의 겹침 조건은 `a[0] <= b[1] && b[0] <= a[1]`이고, 반열린 구간은 등호가 빠집니다. 문제의 경계 조건과 등호를 맞춥니다.
- 병합은 결과의 마지막 구간과 겹치면 끝을 `max`로 늘리고, 삽입은 정렬된 목록을 왼쪽 복사, 병합, 오른쪽 복사로 O(N)에 처리합니다.
- 교집합은 두 목록에 포인터를 두고 끝이 빠른 쪽을 옮깁니다. 최소 회의실은 시작·끝을 따로 정렬해 동시에 진행되는 수의 최댓값을 구합니다.
- 가중치가 있는 구간 스케줄링은 그리디가 틀려서 끝점 정렬 DP와 이분 탐색을 씁니다.
- 범위 덮기는 지금까지 덮은 끝 이하에서 시작하는 구간 중 끝이 가장 먼 것을 고르는 그리디입니다.
