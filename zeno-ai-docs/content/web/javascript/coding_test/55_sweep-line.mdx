## Sweep Line 개념

스위핑(Sweep Line)은 수직선 위의 가상의 선을 왼쪽에서 오른쪽으로 쓸고 지나가며, 값이 바뀌는 지점(이벤트)만 차례로 처리하는 기법입니다. 모든 위치를 보지 않고 변화가 일어나는 점만 보므로 좌표가 아무리 커도 이벤트 개수에 비례하는 시간에 끝납니다.

구성은 세 가지입니다.

| 요소 | 내용 |
|------|------|
| 이벤트 | 상태가 바뀌는 좌표와 변화의 종류. 구간의 시작과 끝 |
| 정렬 | 이벤트를 좌표 오름차순으로 나열 |
| 상태 | 선이 지나는 동안 유지하는 값. 겹친 구간 수, 활성 구간의 집합 등 |

- 선이 이벤트를 하나 지날 때마다 상태를 갱신하고, 필요한 답을 그 자리에서 기록합니다.
- 구간 N개는 이벤트 2N개가 되고, 정렬이 O(N log N), 훑기가 O(N)입니다.
- 같은 방식이 2차원에서도 쓰입니다. 평면의 도형을 x 방향으로 쓸며 선과 만나는 y 구간을 상태로 둡니다(아래 "선분 합집합의 길이").
- 적합한 문제의 단서: 구간·선분·사각형이 여러 개 주어지고, 동시에 몇 개가 겹치는지, 겹친 길이가 얼마인지, 어떤 순간에 최댓값이 얼마인지를 묻는 경우.

## 시작과 종료 이벤트 정렬

구간 `[s, e]` 하나를 이벤트 두 개로 바꿉니다. 시작은 `[s, +1]`, 종료는 `[e, -1]`입니다. 두 번째 값(변화량)이 활성 구간 수에 더해집니다. 이 편의 구간은 별도 언급이 없으면 반열린 구간 `[s, e)`입니다(표기는 34편).

```js
function makeEvents(iv) {
  const ev = []
  for (const [s, e] of iv) ev.push([s, 1], [e, -1])
  return ev.sort((a, b) => a[0] - b[0] || a[1] - b[1])
}
makeEvents([[1, 4], [2, 6], [5, 8]])
// [[1,1],[2,1],[4,-1],[5,1],[6,-1],[8,-1]]
```

- 정렬 기준은 좌표가 첫째이고, 좌표가 같으면 둘째 값입니다. `a[0] - b[0] || a[1] - b[1]`은 첫째 차이가 0일 때만 둘째를 봅니다(비교 함수는 26편).
- 이벤트를 `[좌표, 변화량]` 배열로 만들면 변화량 부호가 곧 종류라서 별도 필드가 필요 없습니다.
- 입력의 구간이 이미 시작점으로 정렬돼 있어도 종료 이벤트는 순서가 섞이므로 합쳐서 다시 정렬합니다.
- 변화량 대신 시작과 종료 좌표를 각각 정렬한 두 배열로 두 포인터를 쓰는 방법도 있습니다(최소 회의실은 34편). 이벤트가 두 종류일 때만 가능하고, 이벤트마다 값이 달라지면 이벤트 배열이 일반적입니다.

**흔한 실수:** 기본 `sort()`로 이벤트 배열을 정렬하는 것입니다. 배열을 문자열로 바꿔 비교하므로 `[10, 1]`이 `[2, 1]`보다 앞에 옵니다.

## 이벤트 정렬 우선순위

같은 좌표에 시작과 종료 이벤트가 겹치면 어느 것을 먼저 처리할지가 결과를 바꿉니다. 문제의 경계 규칙으로 정합니다.

| 경계 | 같은 좌표에서 먼저 처리 | 이유 |
|------|--------------------------|------|
| 반열린 `[s, e)` | 종료 | 끝 좌표는 구간에 포함되지 않아서 거기서 시작하는 구간과 겹치지 않음 |
| 닫힌 `[s, e]` | 시작 | 끝 좌표도 포함해서 거기서 시작하는 구간과 겹침 |

```js
// [1, 3]과 [3, 5]의 최대 동시 개수
// 반열린: ... [3,-1], [3,1] ... 종료 먼저, 최대 1
// 닫힌:   ... [3,1], [3,-1] ... 시작 먼저, 최대 2
```

- 변화량이 -1(종료), +1(시작)이므로 반열린은 변화량 오름차순(`a[1] - b[1]`), 닫힌은 내림차순(`b[1] - a[1]`)입니다.
- 정수 구간이 닫힌이면 끝에 1을 더해 반열린으로 바꾸고(`[s, e + 1)`) 반열린 규칙으로 처리해도 같습니다.
- 값이 있는 이벤트(스카이라인의 높이 등)는 같은 좌표의 이벤트를 모두 처리한 뒤에 답을 기록하는 편이 순서 규칙을 따로 외우는 것보다 안전합니다(아래 "스카이라인 문제").
- 문제 문장에서 확인할 표현은 "맞닿아 있으면 겹친다", "끝나는 순간 다른 것이 시작할 수 있다"입니다.

**흔한 실수:** 우선순위를 정하지 않고 좌표만으로 정렬하는 것입니다. 정렬은 안정 정렬이라서 입력에 먼저 나온 이벤트가 앞에 오고, 샘플은 통과해도 경계가 닿는 입력에서만 틀립니다(안정 정렬은 26편).

## 구간 겹침

구간 목록에 서로 겹치는 쌍이 있는지, 몇 쌍인지를 이벤트로 구합니다. 시작 이벤트를 만나는 순간 활성 구간은 모두 새 구간과 겹칩니다.

```js
function overlapPairs(iv) {
  let cur = 0, pairs = 0
  for (const [, d] of makeEvents(iv)) {
    if (d === 1) pairs += cur   // 활성 구간 전부와 겹침
    cur += d
  }
  return pairs
}
overlapPairs([[1, 4], [2, 6], [5, 8]]) // 2
```

- 쌍은 `[1,4]`와 `[2,6]`, `[2,6]`과 `[5,8]`입니다. `[1,4]`와 `[5,8]`은 떨어져 있습니다.
- 겹침이 있는지만 묻는다면 시작 이벤트 처리 직후 `cur > 1`인지 확인하면 됩니다. 처음 발견한 곳에서 멈출 수 있습니다.
- 모든 쌍을 비교하는 방법은 O(N²)이고 이벤트 방식은 O(N log N)입니다. 쌍의 수는 최대 N(N - 1) / 2라서 N이 100만이어도 Number로 충분합니다. 쌍의 목록을 출력하는 문제라면 출력 크기가 O(N²)입니다.
- 어떤 구간들이 겹치는지 알아야 하면 개수 대신 활성 구간 집합을 유지합니다(아래 "활성 구간 관리").

## 동시 발생 개수

동시 발생 개수는 같은 순간에 활성인 구간의 수입니다. 이벤트를 훑으며 변화량을 누적하면 그 값이 곧 동시 개수이고, 최댓값이 필요한 최소 자원 수(회의실, 서버, 작업자)입니다.

```js
function maxConcurrent(iv) {
  let cur = 0, best = 0
  for (const [, d] of makeEvents(iv)) {
    cur += d
    best = Math.max(best, cur)
  }
  return best
}
maxConcurrent([[1, 4], [2, 6], [5, 8]]) // 2
```

| 이벤트 | 변화량 | 누적 `cur` |
|--------|--------|------------|
| 1 | +1 | 1 |
| 2 | +1 | 2 |
| 4 | -1 | 1 |
| 5 | +1 | 2 |
| 6 | -1 | 1 |
| 8 | -1 | 0 |

- 최대 동시 개수는 2입니다. 최댓값은 시작 이벤트 직후에만 갱신되므로 `best`를 갱신하는 위치가 어디든 같은 결과입니다.
- 최댓값이 처음 나타나는 좌표는 `cur > best`일 때 좌표를 함께 저장합니다.
- 변화량이 +1이 아니라 구간마다 다른 가중치(필요한 인원 수, 사용 대역폭)이면 `[s, w]`, `[e, -w]`로 쌓고 같은 코드를 씁니다.
- 마지막 `cur`는 항상 0입니다. 아니라면 시작과 종료의 짝이 맞지 않는 입력입니다.

## Interval과 Sweep Line

34편의 구간 문제 대부분을 스위핑으로 다시 풀 수 있습니다. 구간이 몇 개 겹치든 상태 하나(`cur`)로 처리됩니다.

| 문제 | 스위핑의 읽는 방법 |
|------|--------------------|
| 병합 | `cur`이 0에서 양수로 바뀔 때 시작, 양수에서 0으로 바뀔 때 끝 |
| 겹치는 구간 판별 | 시작 이벤트 직후 `cur > 1` |
| 최소 회의실 | `cur`의 최댓값 |
| 합집합 길이 | `cur > 0`인 동안의 길이 합 |
| 점이 덮인 횟수 | 그 점까지의 `cur` |

병합은 이렇게 됩니다.

```js
function mergeSweep(iv) {
  const res = []
  let cur = 0, from = 0
  for (const [x, d] of makeEvents(iv)) {
    if (cur === 0) from = x       // 빈 곳에서 시작
    cur += d
    if (cur === 0) res.push([from, x])
  }
  return res
}
mergeSweep([[1, 3], [2, 6], [8, 10], [10, 12]])
// [[1, 6], [8, 10], [10, 12]]
```

- 반열린 규칙이라 `[8, 10)`과 `[10, 12)`는 맞닿아도 병합되지 않습니다. 맞닿는 구간을 합치려면 같은 좌표에서 시작을 먼저 처리하는 닫힌 규칙의 정렬을 씁니다.
- 병합 자체는 정렬 후 최대 끝점을 갱신하는 방법(34편)이 코드가 짧습니다. 이벤트 방식은 병합과 동시 개수를 한 번의 훑기로 함께 구해야 할 때 유리합니다.

## 좌표 압축과 Sweep Line

좌표가 크지만 이벤트가 적을 때 이벤트 좌표를 압축하면 배열 위의 차이 배열로 스위핑을 할 수 있습니다. 압축한 좌표 사이의 구간 하나가 한 칸이고, 그 칸의 겹침 수를 한 번에 구합니다(압축은 54편, 차이 배열은 29편).

```js
const { list, idx } = compress(iv.flat())   // 54편의 compress
const diff = new Array(list.length + 1).fill(0)
for (const [s, e] of iv) {
  diff[idx.get(s)]++        // 시작 칸에서 +1
  diff[idx.get(e)]--        // 끝 칸에서 -1
}
let cur = 0
for (let i = 0; i < list.length; i++) {
  cur += diff[i]            // [list[i], list[i + 1])의 겹침 수
}
```

- `iv`가 `[[1, 4], [2, 6], [8, 10]]`이면 칸별 겹침 수는 `[1,2)`가 1, `[2,4)`가 2, `[4,6)`이 1, `[6,8)`이 0, `[8,10)`이 1입니다.
- 칸의 실제 길이는 `list[i + 1] - list[i]`입니다. 순위 차이가 아니라 원래 좌표로 계산합니다.
- 같은 좌표의 시작과 종료는 `diff`의 한 칸에 합쳐져서 우선순위 문제가 생기지 않습니다. 반열린 구간에서는 `diff[idx.get(e)]--`가 `e`에서 시작하는 구간과 같은 칸에서 상쇄됩니다.
- 압축 없이 이벤트를 정렬하는 방법과 결과는 같습니다. 칸 단위의 값을 배열로 쓸 일이 있을 때(질의를 여럿 받거나 2차원으로 확장할 때) 압축이 편합니다.

질의 지점이 여러 개라면 이벤트 없이 시작 좌표와 종료 좌표를 각각 정렬해 이분 탐색으로도 셀 수 있습니다.

```js
const starts = iv.map((v) => v[0]).sort((a, b) => a - b)
const ends = iv.map((v) => v[1]).sort((a, b) => a - b)
// 점 p가 덮인 횟수: s <= p인 구간 수 - e <= p인 구간 수
const cover = (p) =>
  upperBound(starts, p) - upperBound(ends, p)
cover(5) // 1  (28편의 upperBound: x보다 큰 첫 위치)
```

- `s <= p < e`인 구간만 세는 식입니다. `e <= p`인 구간은 `s <= p`에도 포함되어 있어 한 번 뺍니다.
- 질의 하나가 O(log N)이라서 질의가 Q개면 O((N + Q) log N)입니다.

**흔한 실수:** 닫힌 구간 `[s, e]`를 그대로 `diff[e]--`로 처리하는 것입니다. 닫힌 구간은 끝 칸까지 포함하므로 정수 구간이면 `e + 1`에서 -1을 하고, `e + 1`도 압축 대상에 넣어야 합니다.

## 활성 구간 관리

활성 구간은 선이 지나는 지금 걸쳐 있는 구간입니다. 개수만이 아니라 어떤 구간인지, 그중 최댓값이나 최솟값이 필요하면 집합을 유지합니다. 시작 이벤트에서 넣고 종료 이벤트에서 뺍니다.

- 어떤 구간이 활성인지만 알면 되면 `Set`에 구간 번호를 넣고 뺍니다. 넣기·빼기·확인이 평균 O(1)입니다(자세히는 09편).
- 활성 구간 중 최댓값(또는 최솟값)이 필요하면 힙을 씁니다. 다만 JavaScript에는 임의의 원소를 지우는 힙이 없어서 지연 삭제(lazy deletion)를 씁니다. 종료 이벤트에서는 바로 지우지 않고 지울 값으로 표시해 두고, 꼭대기를 읽을 때 표시된 값이면 그때 꺼냅니다(힙은 46편, 활용은 47편).

```js
function activeMax(heap, gone) {    // 최대 힙: -값을 저장
  while (heap.length) {
    const h = -heap[0]
    if (!(gone.get(h) > 0)) return h
    gone.set(h, gone.get(h) - 1)    // 지울 표시를 하나 소진
    pop(heap)                       // 46편의 pop
  }
  return 0                          // 활성 구간 없음
}
```

- `heap`에는 시작 이벤트에서 `push(heap, -값)`을 합니다. 46편의 힙은 최소 힙이므로 부호를 바꿔 넣으면 최댓값이 꼭대기에 옵니다.
- `gone`은 값 → 지워야 할 개수를 저장한 `Map`입니다. 종료 이벤트에서 `gone.set(h, (gone.get(h) ?? 0) + 1)`로 올립니다.
- 같은 값이 여러 구간에 있어도 개수로 구분하므로 한 구간의 종료가 다른 구간의 같은 값을 지우는 일이 없습니다.
- 꼭대기가 아닌 곳의 지울 값은 그대로 남아 있다가 꼭대기에 올라오면 정리됩니다. 값 하나는 한 번 들어가고 한 번 나오므로 전체 O(N log N)입니다.

## 선분 합집합의 길이

선분 합집합의 길이는 수직선 위의 선분 여러 개가 덮는 전체 길이로, 겹친 부분은 한 번만 셉니다. `cur > 0`인 동안의 길이를 더합니다.

```js
function coveredLength(iv) {         // 반열린 [s, e)
  let cur = 0, prev = 0, len = 0
  for (const [x, d] of makeEvents(iv)) {
    if (cur > 0) len += x - prev     // 직전 이벤트부터 이번까지
    cur += d
    prev = x
  }
  return len
}
coveredLength([[1, 4], [2, 6], [8, 10]]) // 7
```

- `[1,4]`와 `[2,6]`이 합쳐 `[1,6]`(길이 5)이고 `[8,10]`이 2라서 합은 7입니다. 사이 `[6,8]`은 `cur`이 0이라 더하지 않습니다.
- 이 값을 "이벤트 사이의 길이를 활성 구간이 있을 때만 더한다"로 읽으면 됩니다. 구간 병합 결과의 길이를 더해도 같습니다.
- 값이 최대 10억이어도 합은 선분 수 × 10억 이하이므로 Number로 충분한지 입력 크기와 함께 확인합니다. 넘으면 BigInt를 씁니다(자세히는 02편).
- 닫힌 정수 구간 `[s, e]`는 `[s, e + 1)`로 바꿔 같은 코드를 쓰면 덮인 정수 점의 개수가 나옵니다.

2차원으로 확장하면 사각형 여러 개의 합집합 넓이가 됩니다. x 방향으로 쓸며 사각형의 왼쪽·오른쪽 변을 이벤트로 두고, 선과 만나는 y 구간의 덮인 길이를 상태로 유지합니다. y 구간의 덮인 길이는 세그먼트 트리에 구간의 덮임 횟수와 덮인 길이를 저장해 갱신합니다(자세히는 62편). 이벤트 사이의 x 간격에 현재 덮인 y 길이를 곱해 더하면 O(N log N)입니다. 격자가 작을 때는 54편의 압축 격자 방식이 더 단순합니다.

## 스카이라인 문제

스카이라인 문제는 건물 `[왼쪽 x, 오른쪽 x, 높이]` 여러 개를 멀리서 본 윤곽선을 구하는 문제입니다. 윤곽선은 높이가 바뀌는 지점 `[x, 높이]`의 목록입니다. x를 따라 훑으며 활성 건물 중 최대 높이를 상태로 두고, 그 값이 바뀔 때만 기록합니다.

```js
function skyEvents(buildings) {
  const ev = []
  for (const [l, r, h] of buildings) {
    ev.push([l, 1, h], [r, -1, h])
  }
  return ev.sort((a, b) => a[0] - b[0])
}
```

`skyEvents`가 만든 이벤트를 훑으며 같은 x의 이벤트를 모두 처리한 뒤 한 번만 높이를 읽습니다. 앞에서 만든 `activeMax`를 씁니다.

```js
function buildSkyline(ev) {
  const heap = [], gone = new Map(), res = []
  let prev = 0
  for (let i = 0; i < ev.length; i++) {
    const [x, t, h] = ev[i]
    if (t === 1) push(heap, -h)
    else gone.set(h, (gone.get(h) ?? 0) + 1)
    if (i + 1 < ev.length && ev[i + 1][0] === x) continue
    const cur = activeMax(heap, gone)   // 같은 x를 다 처리한 뒤
    if (cur !== prev) res.push([x, cur])
    prev = cur
  }
  return res
}
```

`buildSkyline(skyEvents([[2,9,10],[3,7,15],[5,12,12],[15,20,10],[19,24,8]]))`의 결과는 `[[2,10],[3,15],[7,12],[12,0],[15,10],[20,8],[24,0]]`입니다.

| x | 처리 | 활성 건물의 최대 높이 | 기록 |
|---|------|------------------------|------|
| 2 | 높이 10 시작 | 10 | [2, 10] |
| 3 | 높이 15 시작 | 15 | [3, 15] |
| 5 | 높이 12 시작 | 15 | 변화 없음 |
| 7 | 높이 15 종료 | 12 | [7, 12] |
| 9 | 높이 10 종료 | 12 | 변화 없음 |
| 12 | 높이 12 종료 | 0 | [12, 0] |
| 15 | 높이 10 시작 | 10 | [15, 10] |
| 19 | 높이 8 시작 | 10 | 변화 없음 |
| 20 | 높이 10 종료 | 8 | [20, 8] |
| 24 | 높이 8 종료 | 0 | [24, 0] |

- 높이가 바뀌는 지점만 기록하므로 같은 높이가 이어지는 구간은 점 하나로 합쳐집니다.
- 같은 x를 한꺼번에 처리하는 이유는 맞닿은 두 건물 `[0, 2, 3]`, `[2, 5, 3]`을 올바르게 다루기 위해서입니다. 종료를 먼저 처리해 높이를 읽으면 x = 2에서 `[2, 0]`, `[2, 3]`이 잘못 기록됩니다. 모두 처리한 뒤 읽으면 높이가 3으로 변하지 않아 기록하지 않습니다.
- 높이가 같은 건물이 둘 이상 같은 구간에 있어도 `gone`이 개수로 센 덕분에 한 건물의 종료가 다른 건물의 높이를 지우지 않습니다.
- 시간 O(N log N), 공간 O(N)입니다.
- 높이가 0인 건물은 없다고 가정합니다. 높이 0은 활성 건물이 없음을 나타내는 값으로 씁니다.

**흔한 실수:** 같은 x에서 이벤트 하나를 처리할 때마다 높이를 기록하는 것입니다. 맞닿은 건물 사이에 높이가 떨어졌다 올라오는 가짜 점이 생깁니다.

## 핵심 정리

- 스위핑은 시작·종료 이벤트를 좌표순으로 정렬해 한 번 훑으며 상태(겹친 수, 활성 구간)를 갱신하는 기법이고 O(N log N)입니다.
- 이벤트는 `[좌표, +1]`과 `[좌표, -1]`이며, 같은 좌표에서 반열린 구간은 종료를 먼저, 닫힌 구간은 시작을 먼저 처리합니다.
- 누적한 변화량의 최댓값이 최대 동시 개수이고, 시작 이벤트마다 활성 개수를 더하면 겹치는 쌍의 수입니다.
- 좌표가 크면 압축해 차이 배열로 칸별 겹침 수를 구하고, 칸의 길이는 원래 좌표의 차이로 계산합니다.
- 활성 구간의 최댓값은 힙과 지연 삭제로 관리하고, 선분 합집합 길이는 `cur > 0`인 동안의 길이를 더하며, 스카이라인은 같은 x의 이벤트를 모두 처리한 뒤 최대 높이가 바뀔 때만 기록합니다.
