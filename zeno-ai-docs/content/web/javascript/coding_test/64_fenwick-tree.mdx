## Binary Indexed Tree

Fenwick Tree(Binary Indexed Tree, BIT)는 배열 하나로 접두사 합 질의와 점 갱신을 모두 O(log N)에 처리하는 자료구조입니다. 세그먼트 트리(62편)보다 코드가 짧고 빠르지만, 합처럼 되돌릴 수 있는 연산에만 쓸 수 있습니다.

배열 `bit`의 `i`번 칸은 구간 `(i - lowbit(i), i]`의 합을 저장합니다. 번호는 1부터 씁니다.

- `lowbit(i)`는 `i`의 이진 표현에서 가장 낮은 1 비트가 만드는 값이고, `i & -i`로 구합니다. 12(이진수 1100)의 lowbit는 4입니다.
- 한 칸이 맡는 구간의 길이가 그 칸 번호의 lowbit입니다. 홀수 번호는 원소 하나, 4의 배수는 4개 이상을 맡습니다.

```js
12 & -12   // 4
10 & -10   // 2
7 & -7     // 1
```

`a = [3, 1, 4, 1, 5, 9, 2, 6]`(1번부터)에 대한 `bit`는 다음과 같습니다.

| `i` | 이진수 | lowbit | 맡는 구간 | `bit[i]` |
|-----|--------|--------|-----------|----------|
| 1 | 0001 | 1 | `(0, 1]` | 3 |
| 2 | 0010 | 2 | `(0, 2]` | 4 |
| 3 | 0011 | 1 | `(2, 3]` | 4 |
| 4 | 0100 | 4 | `(0, 4]` | 9 |
| 5 | 0101 | 1 | `(4, 5]` | 5 |
| 6 | 0110 | 2 | `(4, 6]` | 14 |
| 7 | 0111 | 1 | `(6, 7]` | 2 |
| 8 | 1000 | 8 | `(0, 8]` | 31 |

두 연산은 모두 lowbit로 인덱스를 움직입니다.

- 접두사 합은 `i`에서 lowbit를 빼며 내려갑니다. `i`가 이진수로 몇 개의 1을 가졌는지만큼 칸을 더하면 `[1, i]`가 서로 겹치지 않는 구간들로 정확히 덮입니다.
- 갱신은 `i`에서 lowbit를 더하며 올라갑니다. `i`를 포함하는 구간을 맡은 칸을 모두 고칩니다.
- 두 연산 모두 이진수 자릿수만큼만 반복하므로 O(log N)이고, 공간은 O(N)입니다.

```js
let N = 8
let bit = new Float64Array(N + 1)   // 0번 칸은 쓰지 않는다
function add(i, d) {                // a[i]에 d를 더한다
  for (; i <= N; i += i & -i) bit[i] += d
}
function sum(i) {                   // a[1..i]의 합
  let s = 0
  for (; i > 0; i -= i & -i) s += bit[i]
  return s
}
```

배열에서 한 번에 만들 때는 점 갱신을 N번 하는 대신 O(N)에 만듭니다. 각 칸을 자신의 부모 칸(`i + lowbit(i)`)에 한 번만 더해 올립니다.

```js
function build(a) {                 // a[1..N], a[0]은 쓰지 않는다
  for (let i = 1; i <= N; i++) {
    bit[i] += a[i]
    const j = i + (i & -i)
    if (j <= N) bit[j] += bit[i]
  }
}
```

- 인덱스를 0부터 쓰면 `i & -i`가 0이 되어 `i += 0`으로 무한 루프에 빠집니다. 문제의 인덱스가 0부터이면 `+ 1`로 옮겨서 씁니다.
- `i & -i`는 32비트 정수 연산이라 `i`가 2^31 미만일 때만 맞습니다. 코딩테스트의 N은 이보다 훨씬 작습니다(자세히는 24편).
- 값이 정수이고 합이 2^53 − 1 이하이면 `Float64Array`로 오차가 없습니다. 개수만 세면 `Int32Array`로도 충분합니다.

세그먼트 트리와 비교하면 다음과 같습니다.

| 항목 | Fenwick Tree | Segment Tree |
|------|--------------|--------------|
| 코드 길이 | 짧다(반복문 두 개) | 길다 |
| 상수 | 작다 | 크다 |
| 공간 | N + 1 | 4N 또는 2N |
| 되돌릴 수 없는 연산(최소·최대) | 구간 질의가 어렵다 | 가능 |
| 구간 대입 | 어렵다 | Lazy로 가능(63편) |

합, 개수, XOR처럼 역연산이 있는 값의 접두사 질의가 문제의 중심이면 Fenwick Tree가 간단합니다.

**흔한 실수:** 인덱스를 0부터 쓰는 것입니다. 앞에서 말한 무한 루프 외에도 `bit` 배열 크기를 `N`으로 잡으면 마지막 칸이 범위 밖입니다. 크기는 `N + 1`입니다.

## Prefix Sum Query

접두사 합 질의 `sum(i)`는 `a[1] + ... + a[i]`를 구합니다. `i`에서 시작해 lowbit를 빼며 `bit`의 칸을 더하고 0이 되면 멈춥니다.

`sum(7)`을 따라가면 다음과 같습니다.

| 단계 | `i` | 더하는 칸 | 누적 | 다음 `i` |
|------|-----|-----------|------|----------|
| 1 | 7 (0111) | `bit[7]` = 2 | 2 | 6 |
| 2 | 6 (0110) | `bit[6]` = 14 | 16 | 4 |
| 3 | 4 (0100) | `bit[4]` = 9 | 25 | 0 |

결과는 25이고, `3 + 1 + 4 + 1 + 5 + 9 + 2`와 같습니다. 세 칸이 `(6, 7]`, `(4, 6]`, `(0, 4]`로 `[1, 7]`을 빈틈과 겹침 없이 덮었습니다.

- 반복 횟수는 `i`의 이진수에서 1의 개수와 같으므로 이진수 자릿수를 넘지 않습니다.
- `sum(0)`은 반복이 한 번도 돌지 않아 0입니다. 구간 합에서 `l = 1`일 때 `sum(l - 1)`이 0이 되어 따로 처리가 필요 없습니다.
- 접두사 합의 일반 개념은 29편에서 다뤘습니다. 누적합 배열은 질의가 O(1)이지만 값이 바뀌면 O(N)을 다시 계산합니다. Fenwick Tree는 둘 다 O(log N)입니다.

**흔한 실수:** `i`를 0이 될 때까지 빼지 않고 `i >= 0`으로 반복하는 것입니다. `i = 0`에서 `i & -i`가 0이라 `i -= 0`으로 무한 루프가 됩니다. 조건은 `i > 0`입니다.

## Point Update

점 갱신 `add(i, d)`는 `a[i]`에 `d`를 더하고, `i`를 맡은 칸을 모두 고칩니다. `i`에서 시작해 lowbit를 더하며 올라가고 `N`을 넘으면 멈춥니다.

`add(3, 5)`를 따라가면 다음과 같습니다.

| 단계 | `i` | 고치는 칸 | 이전 → 이후 | 다음 `i` |
|------|-----|-----------|-------------|----------|
| 1 | 3 (0011) | `bit[3]` | 4 → 9 | 4 |
| 2 | 4 (0100) | `bit[4]` | 9 → 14 | 8 |
| 3 | 8 (1000) | `bit[8]` | 31 → 36 | 16 |

16은 `N = 8`을 넘어서 멈춥니다. 이후 `sum(7)`은 `bit[7] + bit[6] + bit[4] = 2 + 14 + 14 = 30`으로 이전의 25보다 5 큽니다.

- 원소 하나에 더하는 연산(가산)이 기본입니다. 값을 바꾸는 갱신(대입)은 차이를 더하면 됩니다. 원본 `a`를 따로 갖고 있다가 `add(i, x - a[i])`를 호출하고 `a[i] = x`로 고칩니다.
- 고치는 칸의 수는 이진수 자릿수를 넘지 않아 O(log N)입니다.
- 되돌릴 수 있는 연산이어야 하는 이유가 여기에 있습니다. 값을 더하는 것은 역연산(빼기)으로 취소할 수 있지만, 최솟값은 한 원소가 커졌을 때 칸의 최솟값을 다시 구할 수 없습니다.

**흔한 실수:** 대입 갱신에서 새 값을 그대로 `add(i, x)`로 넣는 것입니다. 이전 값이 남아 `a[i]`가 `이전 + x`가 됩니다. 차이 `x - a[i]`를 넘겨야 합니다.

## Range Sum

구간 `[l, r]`의 합은 두 접두사 합의 차입니다. `r`까지의 합에서 `l - 1`까지의 합을 뺍니다.

```js
const rangeSum = (l, r) => sum(r) - sum(l - 1)
rangeSum(3, 6) // 19 (4 + 1 + 5 + 9)
```

`sum(6) = 3 + 1 + 4 + 1 + 5 + 9 = 23`이고 `sum(2) = 4`이므로 23 − 4 = 19입니다. 질의 하나가 `sum`을 두 번 부르므로 O(log N)입니다.

백준식 입력으로 감싼 전체 흐름입니다. 첫 줄은 N과 질의 수 Q, 둘째 줄은 배열이고, 이어지는 줄은 `1 i x`(i번째를 x로 바꾼다) 또는 `2 l r`(구간 합)입니다. 번호는 1부터입니다.

```js
const fs = require('fs')
const tk = fs.readFileSync(0, 'utf8').split(/\s+/)
let p = 0
N = +tk[p++]
const Q = +tk[p++], a = [0]
bit = new Float64Array(N + 1)
for (let i = 1; i <= N; i++) a.push(+tk[p++])
for (let i = 1; i <= N; i++) add(i, a[i])
const out = []
for (let k = 0; k < Q; k++) {
  const c = +tk[p++], x = +tk[p++], y = +tk[p++]
  if (c === 1) { add(x, y - a[x]); a[x] = y }
  else out.push(sum(y) - sum(x - 1))
}
console.log(out.join('\n'))
```

- 배열을 채울 때 `add`를 N번 부르면 O(N log N)이고, 앞의 `build`를 쓰면 O(N)입니다. 입력 크기가 10^5 정도면 어느 쪽이든 충분합니다.
- 입력을 한 번에 읽고 출력을 모아서 한 번에 내는 이유는 08편에서 다룹니다.

**흔한 실수:** 구간 합을 `sum(r) - sum(l)`로 쓰는 것입니다. `l` 번째 원소가 빠집니다. 빼는 것은 `sum(l - 1)`입니다.

## Range Update / Point Query

구간 갱신과 점 질의는 `[l, r]`의 모든 원소에 x를 더하는 갱신 뒤 한 원소의 값을 묻는 문제입니다. 차이 배열(29편)을 `bit`에 저장하면 풀립니다.

- 차이 배열 `d[i]`는 `a[i] - a[i - 1]`입니다. 원소 `i`가 지금까지 받은 값은 `d[1] + ... + d[i]`, 곧 접두사 합입니다.
- `[l, r]`에 x를 더하는 것은 차이 배열에서 `d[l]`에 x를 더하고 `d[r + 1]`에서 x를 빼는 두 번의 점 갱신입니다.

```js
function rangeAdd(l, r, x) {
  add(l, x)          // l부터 끝까지 x가 더해진 것으로 본다
  add(r + 1, -x)     // r 다음부터 취소한다
}
const pointValue = (i) => a[i] + sum(i)   // 원래 값 + 받은 값
```

`a = [3, 1, 4, 1, 5, 9, 2, 6]`에서 `rangeAdd(2, 4, 10)`을 하면 `d[2]`에 10, `d[5]`에 −10이 더해집니다. 그 뒤 `pointValue(3)`은 `a[3] + sum(3) = 4 + 10 = 14`이고, `pointValue(5)`는 `5 + (10 − 10) = 5`입니다.

- `r + 1 > N`이면 `add`의 반복이 한 번도 돌지 않아 아무 일도 하지 않으므로 따로 처리하지 않습니다.
- 갱신과 질의가 모두 O(log N)입니다.
- 세그먼트 트리의 Range Update / Point Query(63편)와 같은 문제를 더 짧은 코드로 풉니다. 단, 이 방식은 덧셈처럼 되돌릴 수 있는 연산에서만 쓸 수 있습니다.
- 이때 `bit`에는 원래 배열이 아니라 차이 배열이 들어 있으므로, 같은 `bit`로 원래 배열의 구간 합은 구할 수 없습니다(다음 절).

**흔한 실수:** 점 질의에서 `a[i]`를 더하지 않는 것입니다. `sum(i)`는 갱신으로 받은 값의 합일 뿐 원래 값을 포함하지 않습니다.

## Range Update / Range Sum

구간 갱신과 구간 합은 `[l, r]`에 x를 더하는 갱신과 `[l, r]`의 합 질의를 모두 O(log N)에 처리하는 문제입니다. 차이 배열 `d`로 `a`의 접두사 합을 쓰면 계산이 보입니다.

$$
P(i) = \sum_{j=1}^{i} a_j = pre_i + \sum_{k=1}^{i} d_k \,(i - k + 1)
$$

$$
P(i) = pre_i + (i + 1) \sum_{k=1}^{i} d_k - \sum_{k=1}^{i} k \, d_k
$$

- `P(i)`는 갱신이 반영된 `a[1..i]`의 합입니다.
- `pre_i`는 갱신 전 원래 배열의 접두사 합입니다.
- `d_k`는 갱신이 만든 차이 배열입니다. `[l, r]`에 x를 더하면 `d_l`이 x만큼 늘고 `d_{r+1}`이 x만큼 줄어듭니다.

두 합 `Σ d_k`와 `Σ k × d_k`를 각각 Fenwick Tree(`b1`, `b2`)로 관리합니다.

```js
const b1 = new Float64Array(N + 2)   // d[k]
const b2 = new Float64Array(N + 2)   // k * d[k]
function addTo(b, i, v) {
  for (; i <= N; i += i & -i) b[i] += v
}
function sumOf(b, i) {
  let s = 0
  for (; i > 0; i -= i & -i) s += b[i]
  return s
}
```

```js
function rangeAdd(l, r, x) {
  addTo(b1, l, x)
  addTo(b1, r + 1, -x)
  addTo(b2, l, x * l)
  addTo(b2, r + 1, -x * (r + 1))
}
const prefix = (i) =>
  pre[i] + (i + 1) * sumOf(b1, i) - sumOf(b2, i)
const rangeSum = (l, r) => prefix(r) - prefix(l - 1)
```

- `pre`는 원래 배열의 접두사 합 배열입니다(`pre[0] = 0`). 원래 값이 모두 0이면 `pre`가 필요 없습니다.
- `a = [3, 1, 4, 1, 5, 9, 2, 6]`에서 `rangeAdd(2, 4, 10)` 뒤 `rangeSum(3, 6)`은 `(14 + 11 + 5 + 9) = 39`입니다. 구간 `[3, 4]`가 10씩 올라 원래 19에서 20이 늘어난 값입니다.
- 갱신 하나가 `addTo` 네 번, 질의 하나가 `sumOf` 네 번이라 모두 O(log N)이고, 공간은 `b1`, `b2`, `pre`의 3N입니다.
- 두 번째 합에서 `x * l`처럼 인덱스와 값을 곱하므로 값이 커집니다. `Σ k × d_k`와 `(i + 1) × Σ d_k`의 크기를 미리 계산해서 2^53 − 1을 넘으면 BigInt를 씁니다(자세히는 02편).
- 값 대입이나 최대·최소를 함께 요구하면 이 방식은 쓸 수 없고 Lazy Propagation(63편)이 필요합니다.

**흔한 실수:**

- `b2`에 `x * l`이 아니라 `x`만 넣는 것입니다. 곱하는 것이 `Σ k × d_k`의 정의입니다.
- `(i + 1)`을 `i`로 쓰는 것입니다. 항 `d_k (i - k + 1)`에서 나오는 계수는 `i + 1`과 `k`입니다.
- `r + 1`에서 빼는 값이 `x * (r + 1)`인데 `x * r`로 쓰는 것입니다.

## 좌표 압축 + Fenwick Tree

인덱스가 될 값의 범위가 크거나(10^9) 정수가 아니면 값을 크기 순위로 바꾼 뒤 순위 위에 Fenwick Tree를 만듭니다(좌표 압축은 54편). 순위를 1부터 매기면 Fenwick Tree의 인덱스로 바로 쓸 수 있습니다.

값의 크기 순위 위에서 쓰는 개수 Fenwick Tree를 함수로 묶어 두면 이후 절에서 재사용할 수 있습니다.

```js
function makeBit(n) {
  const b = new Int32Array(n + 1)    // 개수는 Int32로 충분
  return {
    b,
    add(i, d) { for (; i <= n; i += i & -i) b[i] += d },
    sum(i) {
      let s = 0
      for (; i > 0; i -= i & -i) s += b[i]
      return s
    },
  }
}
```

```js
const vals = [100, 5, 100, 70]
const sorted = [...new Set(vals)].sort((x, y) => x - y)
const rank = new Map(sorted.map((v, i) => [v, i + 1]))
// 5 → 1, 70 → 2, 100 → 3
const f = makeBit(sorted.length)
for (const v of vals) f.add(rank.get(v), 1)
f.sum(rank.get(70))        // 2 (70 이하의 값의 개수)
f.sum(rank.get(70) - 1)    // 1 (70 미만의 값의 개수)
```

- `Set`으로 중복을 없애 정렬하면 순위표가 됩니다. 같은 값이 여러 번 나오면 같은 순위의 칸에 개수가 쌓입니다.
- "x 이하의 개수"는 `sum(rank(x))`, "x 미만의 개수"는 `sum(rank(x) - 1)`, "x 초과의 개수"는 `전체 개수 - sum(rank(x))`입니다.
- 질의에 들어오는 값이 순위표에 없을 수 있으면 `Map.get`이 `undefined`를 돌려주므로 정렬된 표에서 이분 탐색(28편)으로 위치를 찾아야 합니다.
- 질의를 미리 알 수 있는 오프라인 문제에서 씁니다. 모든 값을 읽어 순위표를 만든 뒤 처리를 시작합니다.
- 세그먼트 트리(62편)에서도 같은 압축을 쓰며, 순위가 0부터인지 1부터인지만 다릅니다. Fenwick Tree는 1부터입니다.

**흔한 실수:** 순위를 0부터 매겨 Fenwick Tree에 넣는 것입니다. 0번 칸은 쓰지 않으므로 값이 사라지거나 무한 루프가 됩니다.

## Fenwick Tree로 역순쌍 세기

역순쌍(inversion)은 `i < j`인데 `a[i] > a[j]`인 쌍입니다. 배열을 앞에서부터 읽으며, 각 원소 앞에 이미 나온 원소 중 자기보다 큰 것의 개수를 더하면 전체 역순쌍 수가 됩니다. 병합 정렬로 세는 방법은 27편에서 다뤘고, Fenwick Tree로는 O(N log N)에 셉니다.

1. 값을 압축해 순위를 만든다.
2. 왼쪽에서 오른쪽으로 읽는다. 원소의 순위 `r`에 대해 지금까지 넣은 개수 `i`에서 `r` 이하의 개수 `sum(r)`을 뺀 값이 앞의 더 큰 원소의 수다.
3. 그 뒤 `add(r, 1)`로 이 원소를 넣는다.

```js
function countInversions(a) {
  const sorted = [...new Set(a)].sort((x, y) => x - y)
  const rank = new Map(sorted.map((v, i) => [v, i + 1]))
  const f = makeBit(sorted.length)
  let inv = 0
  for (let i = 0; i < a.length; i++) {
    const r = rank.get(a[i])
    inv += i - f.sum(r)    // 앞에 있는 원소 중 a[i]보다 큰 것
    f.add(r, 1)
  }
  return inv
}
countInversions([3, 1, 2, 3, 1]) // 5
```

`[3, 1, 2, 3, 1]`을 처리하는 과정입니다. 순위는 1 → 1, 2 → 2, 3 → 3입니다.

| `i` | 값 | 앞에 있는 원소 | `r` 이하의 개수 | 더하는 수 `i - sum(r)` |
|-----|----|----------------|-----------------|-------------------------|
| 0 | 3 | 없음 | 0 | 0 |
| 1 | 1 | 3 | 0 | 1 |
| 2 | 2 | 3, 1 | 1 | 1 |
| 3 | 3 | 3, 1, 2 | 3 | 0 |
| 4 | 1 | 3, 1, 2, 3 | 1 | 3 |

합은 5이고, 쌍으로 쓰면 (3,1), (3,2), (3,1), (2,1), (3,1)입니다.

- 같은 값은 역순쌍이 아닙니다. `sum(r)`에 `r` 자신이 포함되므로 같은 값은 "큰 값"에서 빠집니다. `a[i] >= a[j]`로 세는 문제라면 `sum(r - 1)`을 씁니다.
- 시간은 압축의 정렬 O(N log N), 원소마다 `sum`과 `add` 한 번씩 O(N log N)입니다.
- 역순쌍 수는 최대 N(N − 1) / 2입니다. N이 10^5이면 약 5 × 10^9로 32비트 정수(약 21억)를 넘으므로, 답 `inv`는 보통 Number로 둡니다. `| 0`이나 `Int32Array`에 담으면 안 됩니다. 개수 배열 `b`는 각 칸이 N을 넘지 않아 `Int32Array`로 충분합니다.
- 같은 방식으로 "각 원소의 왼쪽에 자기보다 작은 원소가 몇 개인가", "i < j이고 `a[i] < a[j]`인 쌍의 수"를 셉니다. 비교 방향만 바꿉니다.

**흔한 실수:** 답을 `Int32Array`나 비트 연산으로 다루는 것입니다. 큰 입력에서 값이 감겨 틀리지만 작은 입력에서는 맞아서 놓치기 쉽습니다.

## Fenwick Tree 위 K번째 원소 탐색

개수를 저장한 Fenwick Tree에서는 이분 탐색과 `sum`을 함께 쓰지 않고, 트리 위에서 한 번에 내려가며 K번째로 작은 값의 순위를 O(log N)에 찾습니다. 이분 탐색(28편)과 `sum`을 함께 쓰면 O(log² N)입니다.

`pos`를 지금까지 건너뛴 위치로 두고, 가장 큰 2의 거듭제곱부터 줄여 가며 한 칸씩 시도합니다.

```js
function kth(f, n, k) {            // 개수 BIT에서 k번째 원소의 순위
  let pos = 0
  let pw = 1 << (31 - Math.clz32(n))   // n 이하의 최대 2의 거듭제곱
  for (; pw > 0; pw >>= 1) {
    if (pos + pw <= n && f.b[pos + pw] < k) {
      pos += pw
      k -= f.b[pos]
    }
  }
  return pos + 1
}
```

- `f.b[pos + pw]`는 구간 `(pos, pos + pw]`의 개수입니다. `pos`가 `pw`의 두 배수이므로 그 칸이 맡는 구간이 정확히 이 길이이기 때문입니다.
- 그 개수가 `k`보다 작으면 K번째는 이 구간 뒤에 있으므로 `pos`를 옮기고 `k`에서 개수를 뺍니다. 아니면 구간 안에 있으므로 옮기지 않고 더 작은 `pw`로 좁힙니다.
- 끝나면 `pos`는 접두사 합이 `k`보다 작은 마지막 위치이고, `pos + 1`이 접두사 합이 처음 `k` 이상이 되는 순위입니다.
- 전제는 모든 칸의 값이 0 이상이고 `1 <= k <= 전체 개수`입니다.
- `Math.clz32(n)`은 32비트로 봤을 때 앞쪽 0의 개수입니다. `31 - clz32(n)`이 `floor(log2 n)`이므로 `1 << (31 - Math.clz32(n))`이 n 이하의 최대 2의 거듭제곱입니다.

앞 절의 `vals = [100, 5, 100, 70]`(`5` 하나, `70` 하나, `100` 두 개)에서 순위로 호출한 결과입니다. 순위 1, 2, 3은 각각 5, 70, 100입니다.

| `k` | 반환(순위) | 값 |
|-----|-----------|----|
| 1 | 1 | 5 |
| 2 | 2 | 70 |
| 3 | 3 | 100 |
| 4 | 3 | 100 |

`kth(f, 3, 3)`을 따라가면 `pw`는 2에서 시작합니다. `bit[2]`(순위 1–2의 개수) = 2가 3보다 작아서 `pos = 2`, `k = 1`이 됩니다. 다음 `pw = 1`에서 `bit[3]` = 2가 1 이상이라 그대로 두고, 반환값은 `2 + 1 = 3`입니다.

- 값을 넣고 빼는 갱신(`add`)과 함께 쓰면, 집합이 바뀌는 동안 K번째 값이나 중앙값을 질의마다 O(log N)에 구합니다.
- 접두사 합이 처음 `x` 이상이 되는 위치를 찾는 일반 문제에도 같은 코드를 씁니다. 값이 모두 0 이상이어야 합니다.
- 값의 상한이 정해진 정수(예: 1부터 10^6)이면 압축 없이 값 자체를 순위로 쓰는 것이 간단합니다. 크기가 큰 `Int32Array` 하나로 충분합니다.

**흔한 실수:** `pos + pw <= n` 확인을 빼먹는 것입니다. `n`이 2의 거듭제곱이 아니면 `bit` 배열 밖의 칸을 읽어 `undefined`가 되고 비교가 거짓이 되어 결과가 틀립니다.

## 핵심 정리

- Fenwick Tree는 `bit[i]`가 구간 `(i - lowbit(i), i]`의 합을 저장하는 1부터 시작하는 배열이고, `lowbit(i)`는 `i & -i`입니다. 접두사 합은 lowbit를 빼며, 갱신은 lowbit를 더하며 O(log N)에 처리합니다.
- 구간 합은 `sum(r) - sum(l - 1)`입니다. 대입 갱신은 차이 `x - a[i]`를 더합니다. 0부터 시작하는 인덱스는 무한 루프를 만들기 때문에 1부터 씁니다.
- 구간 덧셈과 점 질의는 차이 배열을 `bit`에 두고 `add(l, x)`, `add(r + 1, -x)`로 갱신하며 점의 값은 `a[i] + sum(i)`입니다.
- 구간 덧셈과 구간 합은 `Σ d`와 `Σ k × d`를 두 개의 Fenwick Tree로 관리하고 `prefix(i) = pre[i] + (i + 1) × Σd − Σ(k × d)`로 구합니다.
- 값이 크거나 정수가 아니면 좌표 압축한 순위(1부터)를 인덱스로 쓰고, 역순쌍은 앞에 넣은 개수에서 `sum(r)`을 빼며 센 합이며 답은 32비트를 넘을 수 있습니다.
- 개수를 저장한 트리에서 `pw`를 큰 2의 거듭제곱부터 줄여 가며 내려가면 K번째 원소의 순위를 O(log N)에 찾습니다.
