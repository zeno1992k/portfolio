## Object

Object는 문자열(또는 심벌) 키에 값을 연결하는 자료구조입니다. 코딩테스트에서는 사전(dictionary)으로 씁니다.

```js
const score = { kim: 90, lee: 80 }
score.park = 70          // 추가
score['kim'] = 95        // 수정
delete score.lee         // 삭제
console.log(score)       // { kim: 95, park: 70 }
console.log(score.choi)  // undefined (없는 키는 에러가 아님)
console.log(Object.keys(score).length) // 2 (크기)
```

- 점 표기 `obj.key`는 키가 식별자 모양일 때만 쓰고, 변수에 든 키는 대괄호 `obj[key]`로 읽습니다.
- 없는 키를 읽으면 `undefined`입니다. 키가 있는지는 `key in obj`(상속된 키 포함) 또는 `Object.hasOwn(obj, key)`(ES2022, 자기 키만)로 확인합니다.
- 값이 `undefined`인 키도 존재합니다. `{ a: undefined }`에서 `'a' in obj`는 `true`입니다.
- 크기를 알려 주는 속성이 없어서 `Object.keys(obj).length`로 셉니다. 호출할 때마다 키 배열을 새로 만듭니다.

**흔한 실수:** 상속된 키입니다. 객체 리터럴은 `Object.prototype`을 물려받아서 `obj['constructor']`나 `'toString' in obj`가 키를 넣은 적 없어도 참입니다(자세히는 10편).

## Object.keys, values, entries

세 메서드는 객체의 자기 열거 가능 문자열 키 프로퍼티를 배열로 돌려줍니다. 심벌 키와 상속된 프로퍼티는 빠집니다.

| 메서드 | 반환 | 예: `{ a: 1, b: 2 }` |
|--------|------|----------------------|
| `Object.keys(obj)` | 키 배열 | `['a', 'b']` |
| `Object.values(obj)` | 값 배열 | `[1, 2]` |
| `Object.entries(obj)` | `[키, 값]` 쌍의 배열 | `[['a', 1], ['b', 2]]` |

세 메서드의 반환 순서는 같습니다. 정수 형태의 키가 오름차순으로 먼저 오고, 그다음 문자열 키가 만들어진 순서로 옵니다.

```js
const o = { b: 1, 100: 'x', a: 2, 7: 'y' }
console.log(Object.keys(o)) // ['7', '100', 'b', 'a']
```

### Object.keys

키는 항상 문자열입니다. 숫자를 키로 넣었어도 `'7'`로 나옵니다. 숫자가 필요하면 `Number(k)`로 바꿉니다.

```js
const count = { 3: 'c', 1: 'a' }
const ids = Object.keys(count).map(Number) // [1, 3]
```

### Object.values

값 배열에 `reduce`나 `Math.max`를 적용할 때 씁니다.

```js
const stock = { apple: 3, pear: 5 }
const total = Object.values(stock)
  .reduce((a, b) => a + b, 0) // 8
const most = Math.max(...Object.values(stock)) // 5
```

빈 객체에 `Math.max(...[])`를 쓰면 `-Infinity`입니다(자세히는 11편의 최대값 절).

### Object.entries

`[키, 값]` 쌍을 구조 분해로 받으면 키와 값을 함께 순회하거나 정렬할 수 있습니다. 반대 방향의 `Object.fromEntries`(ES2019)는 쌍의 이터러블에서 객체를 만듭니다.

```js
const cnt = { a: 2, b: 5, c: 1 }
const top = Object.entries(cnt)
  .sort((x, y) => y[1] - x[1])   // 값 내림차순
console.log(top[0])              // ['b', 5]
const back = Object.fromEntries(top) // { b: 5, a: 2, c: 1 }
```

**흔한 실수:** `for...in`을 쓰는 것입니다. `for...in`은 상속된 열거 가능 키까지 순회합니다. 자기 키만 필요하면 위 세 메서드를 씁니다.

## Map

Map은 어떤 값이든 키로 쓸 수 있는 키-값 자료구조입니다. 전용 메서드로만 다룹니다.

```js
const m = new Map()
m.set('a', 1)          // 추가 또는 수정, Map을 반환
m.set('b', 2).set('c', 3) // 체이닝 가능
m.get('a')             // 1
m.get('z')             // undefined
m.has('b')             // true
m.delete('b')          // true (지웠으면 true)
m.size                 // 2 (속성, 메서드가 아님)
m.clear()              // 전부 삭제
```

- 생성자에 `[키, 값]` 쌍의 이터러블을 주면 한 번에 채웁니다. `new Map([['a', 1], ['b', 2]])`.
- `Object`와 달리 기본 키가 없습니다. `'constructor'`나 `'__proto__'` 같은 문자열도 평범한 키입니다.
- 크기는 `size`로 바로 얻습니다.
- 명세는 접근 시간이 요소 수보다 느리게 늘어날 것(평균 준선형)만 요구합니다. 코딩테스트에서는 `get`, `set`, `has`, `delete`를 평균 O(1)로 계산합니다(자세히는 10편).

값이 없을 때 기본값을 주는 패턴입니다. `get`이 `undefined`를 돌려주는 것을 이용합니다.

```js
const cnt = new Map()
for (const w of ['a', 'b', 'a']) {
  cnt.set(w, (cnt.get(w) ?? 0) + 1)
}
console.log(cnt) // Map(2) { 'a' => 2, 'b' => 1 }
```

값으로 `0`이나 `''`을 쓸 수 있으면 `||` 대신 `??`를 씁니다. `0 || 5`는 5가 되기 때문입니다.

**흔한 실수:** 대괄호로 접근하는 것입니다. `m['a'] = 1`은 Map의 데이터가 아니라 일반 프로퍼티를 만들어서 `m.has('a')`가 `false`입니다.

| 비교 | Object | Map |
|------|--------|-----|
| 키 타입 | 문자열, 심벌 | 모든 값 |
| 기본 키 | 상속된 키가 있음 | 없음 |
| 크기 | `Object.keys(o).length` | `m.size` |
| 순회 | 직접 순회 불가, `entries` 등 필요 | 바로 `for...of` |
| 순서 | 정수 키 오름차순 후 삽입 순서 | 삽입 순서 |
| JSON | `JSON.stringify` 가능 | 불가(`{}`가 됨) |

기준은 단순합니다. 키가 문자열이고 정해진 필드 몇 개면 Object, 키를 마음대로 넣고 빼는 사전이면 Map을 씁니다.

## Set

Set은 중복 없는 값의 모음입니다. 같은 값을 다시 넣어도 하나만 남습니다.

```js
const s = new Set([3, 1, 3, 2])
s.add(5)       // Set 반환, 체이닝 가능
s.add(1)       // 이미 있어서 변화 없음
s.has(2)       // true
s.delete(3)    // true
s.size         // 3
console.log(s) // Set(3) { 1, 2, 5 }
```

- 생성자에 이터러블을 주면 중복을 걷어내며 채웁니다. 문자열도 이터러블이라 `new Set('hello')`는 `h, e, l, o` 네 글자입니다.
- 값 비교는 Map의 키와 같은 규칙입니다(아래 "Map에서 숫자, 객체 Key").
- 존재 확인 `has`는 평균 O(1)이라, 배열의 `includes`(O(n))를 반복 호출하는 자리를 Set으로 바꾸면 빨라집니다.

```js
const banned = new Set(['x', 'y'])
const ok = ['a', 'x', 'b'].filter((c) => !banned.has(c))
// ['a', 'b']
```

배열에서 중복을 없애는 `[...new Set(arr)]`는 10편에서 다룹니다.

**흔한 실수:** 객체나 배열 값을 넣고 내용으로 중복이 제거되기를 기대하는 것입니다. `new Set([[1], [1]]).size`는 2입니다. 참조가 다르기 때문입니다.

## Map 순회

Map은 이터러블이고, 한 번 순회하면 `[키, 값]` 쌍을 삽입 순서대로 돌려줍니다.

```js
const m = new Map([['a', 1], ['b', 2]])
for (const [k, v] of m) console.log(k, v)   // a 1, b 2
for (const k of m.keys()) console.log(k)    // a, b
for (const v of m.values()) console.log(v)  // 1, 2
m.forEach((v, k) => console.log(k, v))      // 인수 순서 (값, 키)
```

- `for...of m`은 `m.entries()`와 같습니다.
- `keys()`, `values()`, `entries()`는 배열이 아니라 이터레이터를 돌려줍니다. 배열 메서드가 필요하면 `[...m.keys()]`나 `Array.from(m.values())`로 바꿉니다(자세히는 1편의 Spread 절).
- `forEach` 콜백의 인수는 `(값, 키, Map)` 순서입니다. `for...of`의 `[키, 값]`과 반대라서 헷갈립니다.
- Map에는 `map`, `filter`, `sort`가 없습니다. 배열로 펼친 뒤에 적용합니다.

```js
const sorted = [...m].sort((x, y) => y[1] - x[1])
// 값 내림차순 [['b', 2], ['a', 1]]
```

순회 중에 수정할 수 있습니다. 순회 중 삭제한 항목은 아직 방문하지 않았다면 건너뛰고, 순회 중 추가한 항목은 순회가 끝나기 전에 방문합니다. 순회하며 계속 추가하면 끝나지 않을 수 있으니, 단계마다 새 Map을 만드는 편이 안전합니다.

**흔한 실수:** `m.keys().length`나 `m.keys()[0]`처럼 이터레이터를 배열처럼 쓰는 것입니다. 이터레이터에는 `length`와 인덱스가 없어서 `undefined`가 됩니다. 크기는 `m.size`, 첫 키는 `[...m.keys()][0]`으로 얻습니다.

## Set 순회

Set도 이터러블이고 삽입 순서대로 값을 돌려줍니다.

```js
const s = new Set([3, 1, 2])
for (const x of s) console.log(x)   // 3, 1, 2
s.forEach((v, k) => console.log(v, k)) // 값과 키가 같음
console.log([...s].sort((a, b) => a - b)) // [1, 2, 3]
```

- `values()`가 기본 순회이고 `keys()`는 `values()`와 같은 함수입니다. `entries()`는 `[값, 값]` 쌍을 돌려줍니다. Map과 인터페이스를 맞추려는 설계입니다.
- `forEach` 콜백은 `(값, 값, Set)`을 받습니다.
- Set에는 인덱스가 없어서 `s[0]`은 `undefined`입니다. 첫 값은 `s.values().next().value`, 일반 접근은 `[...s]`로 배열로 바꿉니다.
- Set은 정렬하지 않습니다. 정렬된 순서가 필요하면 배열로 바꿔 `sort`합니다.

순회 중 수정 규칙은 Map과 같습니다. 순회 중 삭제한 항목은 건너뛰고 순회 중 추가한 항목은 방문합니다.

**흔한 실수:** 크기를 `s.length`로 읽는 것입니다. Set은 `size`입니다. `s.length`는 `undefined`라서 반복문이 한 번도 안 돌아갑니다.

## Object Key의 문자열 변환

Object의 키는 문자열이나 심벌이고, 그 외의 값은 문자열로 변환되어 키가 됩니다. 서로 다른 값이 같은 키로 합쳐지는 것이 문제입니다.

```js
const o = {}
o[1] = 'num'
o['1'] = 'str'         // 숫자 1과 같은 키
o[[1, 2]] = 'arr'      // 키는 '1,2'
o[{}] = 'obj'          // 키는 '[object Object]'
o[null] = 'nul'        // 키는 'null'
console.log(Object.keys(o))
// ['1', '1,2', '[object Object]', 'null']
console.log(o[1] === o['1']) // true
```

| 넣은 키 | 실제 키 |
|---------|---------|
| `1`, `'1'` | `'1'` |
| `true` | `'true'` |
| `null`, `undefined` | `'null'`, `'undefined'` |
| 배열 `[1, 2]` | `'1,2'` |
| 객체 | `'[object Object]'` (모든 객체가 같은 키) |

- 객체를 키로 쓰면 서로 다른 객체가 전부 같은 키 하나로 뭉칩니다. 에러가 나지 않아서 조용히 틀립니다.
- 배열 키는 `join(',')`한 문자열이 됩니다. `[1, 23]`과 `[12, 3]`은 각각 `'1,23'`과 `'12,3'`이라 구분되지만, 문자열 구분자 없이 직접 이어 붙이면 충돌합니다(아래 "복합 키 설계").
- `Object.keys`가 돌려주는 키는 숫자였어도 문자열이므로, 값 비교는 `Number(k)`로 바꾼 뒤에 합니다. `'10' < '9'`는 `true`입니다(문자열은 사전순 비교).

숫자와 문자열을 구별해야 하는 문제에서는 Object 대신 Map을 씁니다.

## Map에서 숫자, 객체 Key

Map과 Set은 키를 문자열로 바꾸지 않고, SameValueZero 규칙으로 비교합니다. `===`와 거의 같지만 `NaN`을 같은 값으로 봅니다.

```js
const m = new Map()
m.set(1, 'num')
m.set('1', 'str')
console.log(m.size)     // 2 (숫자 1과 문자열 '1'은 다른 키)
m.set(NaN, 'nan')
console.log(m.get(NaN)) // 'nan' (NaN === NaN은 false인데도)
m.set(0, 'zero')
console.log(m.get(-0))  // 'zero' (0과 -0은 같은 키)
```

- 숫자 키는 숫자 그대로 꺼냅니다. `for (const k of m.keys())`의 `k`는 `Number` 타입이어서 `Number()` 변환이 필요 없습니다.
- 객체와 배열 키는 참조로 비교합니다. 내용이 같아도 다른 객체이면 다른 키입니다.

```js
const key = [1, 2]
const m2 = new Map([[key, 'v']])
console.log(m2.get(key))    // 'v'
console.log(m2.get([1, 2])) // undefined (다른 배열)
```

- 같은 참조를 보관해 두고 쓰는 경우(노드 객체에 메타 정보를 붙이는 용도)에만 객체 키가 유용합니다.
- 좌표나 상태처럼 값으로 같음을 판단해야 하는 키는 문자열이나 정수로 인코딩합니다(아래 "복합 키 설계").

**흔한 실수:** `set(1, ...)`으로 넣고 `get('1')`로 읽는 것입니다. 입력을 `split`으로 읽으면 문자열이 되므로, 키를 넣을 때와 읽을 때 타입이 같은지 확인합니다.

## Map, Set의 삽입 순서

Map과 Set은 항목을 처음 넣은 순서를 기억하고, 모든 순회가 그 순서를 따릅니다.

```js
const m = new Map()
m.set('b', 1).set('a', 2).set(1, 3)
console.log([...m.keys()]) // ['b', 'a', 1] (숫자 키도 그대로)
```

- Object는 정수 형태 키를 앞으로 보내 오름차순으로 정렬하므로 삽입 순서를 믿을 수 없습니다. 삽입 순서가 필요하면 Map을 씁니다.
- 이미 있는 키에 `set`하면 값만 바뀌고 순서는 그대로입니다.
- 지운 뒤 다시 넣으면 맨 뒤로 갑니다.

```js
const m = new Map([['a', 1], ['b', 2]])
m.set('a', 9)           // 값만 변경
console.log([...m])     // [['a', 9], ['b', 2]]
m.delete('a')
m.set('a', 9)           // 새로 삽입된 것으로 취급
console.log([...m])     // [['b', 2], ['a', 9]]
```

- 가장 오래된 항목은 `m.keys().next().value`, 가장 최근 항목은 마지막까지 순회하거나 `[...m.keys()].at(-1)`(ES2022)로 얻습니다.
- 이 성질이 "지웠다가 다시 넣어 최신으로 만들기" 기법의 바탕이고, LRU 캐시에 그대로 쓰입니다(아래 "삽입 순서를 이용한 LRU 캐시").

## Set 집합 연산 메서드

Set에는 합집합, 교집합 같은 집합 연산 메서드가 ES2025에서 추가되었습니다. 원본은 바꾸지 않고 새 Set을 돌려줍니다.

| 메서드 | 의미 | 반환 |
|--------|------|------|
| `a.union(b)` | 합집합 | Set |
| `a.intersection(b)` | 교집합 | Set |
| `a.difference(b)` | a에서 b를 뺀 차집합 | Set |
| `a.symmetricDifference(b)` | 한쪽에만 있는 값 | Set |
| `a.isSubsetOf(b)` | a가 b의 부분집합인가 | 불리언 |
| `a.isSupersetOf(b)` | a가 b를 포함하는가 | 불리언 |
| `a.isDisjointFrom(b)` | 공통 원소가 없는가 | 불리언 |

```js
const a = new Set([1, 2, 3])
const b = new Set([2, 3, 4])
a.union(b)               // Set { 1, 2, 3, 4 }
a.intersection(b)        // Set { 2, 3 }
a.difference(b)          // Set { 1 }
a.symmetricDifference(b) // Set { 1, 4 }
a.isSubsetOf(b)          // false
```

- 인수는 Set과 같은 모양의 객체(set-like)여야 합니다. `size`, `has()`, `keys()`를 가지면 되어서 Map도 받습니다. 배열은 `size`가 없어서 TypeError이므로 `new Set(arr)`로 감쌉니다.
- Node.js 24에서 동작을 확인했습니다. 채점 환경의 지원 여부는 확인하지 못했으므로, 지원하지 않는 환경에서는 구형 코드를 씁니다.

```js
const union = new Set([...a, ...b])
const inter = new Set([...a].filter((x) => b.has(x)))
const diff = new Set([...a].filter((x) => !b.has(x)))
```

- 구형 코드의 교집합과 차집합은 `a`를 순회하며 `b.has`로 확인하므로 O(a의 크기)입니다. `b`를 `Set`으로 만들어 두는 것이 핵심입니다. 배열의 `includes`를 쓰면 O(n²)이 됩니다.

## 복합 키 설계

값 두 개 이상으로 이뤄진 키(좌표 `(r, c)`, 상태 `(위치, 열쇠)`)를 Map이나 Set의 키로 쓰려면 하나의 원시 값으로 만들어야 합니다. 배열을 그대로 키로 쓰면 참조 비교라서 같은 좌표도 서로 다른 키가 됩니다.

### 문자열 결합 키

구분자를 넣어 문자열로 이어 붙입니다.

```js
const visited = new Set()
visited.add(`${3},${4}`)      // '3,4'
visited.has(`${3},${4}`)      // true
const [r, c] = '3,4'.split(',').map(Number) // 복원
```

- 반드시 구분자를 넣습니다. 구분자 없이 이으면 `(1, 23)`과 `(12, 3)`이 둘 다 `'123'`이 되어 충돌합니다.
- 키마다 문자열을 만들고 비교하므로 정수 키보다 무겁습니다. 값 범위가 작으면 정수 인코딩을 씁니다.
- 음수도 `'-1,2'`처럼 그대로 들어가 문제가 없습니다.

### 정수 인코딩

각 성분의 범위를 알면 한 정수에 담을 수 있습니다. `0 <= c < W`일 때 `r * W + c`는 쌍마다 서로 다른 정수입니다.

```js
const W = 1000                 // c의 상한(미포함)보다 크게
const key = 3 * W + 45         // 3045
const r = Math.floor(key / W)  // 3
const c = key % W              // 45
```

- 곱하는 수 `W`는 뒤 성분의 가능한 값 개수 이상이어야 합니다. 작으면 서로 다른 쌍이 같은 정수가 됩니다.
- 음수 성분이 있으면 최솟값만큼 더해 0 이상으로 옮깁니다. `(r + 100) * W + (c + 100)`처럼 쓰고, 복원할 때 다시 뺍니다.
- 결과가 `Number.MAX_SAFE_INTEGER`(2^53 − 1) 이하여야 정확합니다. 성분이 셋 이상이면 `((a * B + b) * C + c)`로 이어 갑니다.
- 정수 키는 문자열을 만들지 않아서 보통 더 가볍습니다.

| 방법 | 장점 | 주의 |
|------|------|------|
| 문자열 결합 | 범위를 몰라도 됨, 성분 수 자유 | 구분자 필수, 느림 |
| 정수 인코딩 | 가볍고 빠름 | 범위 확정, 안전 정수 이내, 음수 보정 |

**흔한 실수:** `visited.add([r, c])`입니다. 에러 없이 들어가지만 `visited.has([r, c])`는 항상 `false`라서, 방문 체크가 작동하지 않고 탐색이 무한히 돕니다.

## 삽입 순서를 이용한 LRU 캐시

LRU(Least Recently Used) 캐시는 용량이 가득 차면 가장 오래 쓰지 않은 항목을 버리는 캐시입니다. `get`과 `put`을 평균 O(1)로 만들어야 하는 문제로 자주 나옵니다. Map은 삽입 순서를 기억하므로 맨 앞이 가장 오래된 항목이고, 쓸 때마다 지웠다가 다시 넣어 맨 뒤로 보내면 됩니다.

```js
class LRUCache {
  constructor(cap) { this.cap = cap; this.map = new Map() }
  get(key) {
    if (!this.map.has(key)) return -1
    const v = this.map.get(key)
    this.map.delete(key)
    this.map.set(key, v)       // 맨 뒤 = 가장 최근
    return v
  }
}
```

`put`은 같은 클래스에 추가합니다.

```js
  put(key, value) {
    this.map.delete(key)        // 있으면 지우고
    this.map.set(key, value)    // 맨 뒤에 새로 삽입
    if (this.map.size > this.cap) {
      this.map.delete(this.map.keys().next().value)
      // 맨 앞 = 가장 오래된 항목 제거
    }
  }
```

용량 2에서의 동작입니다.

| 연산 | Map 내용(앞이 오래됨) | 결과 |
|------|----------------------|------|
| `put(1, 'a')` | 1 | |
| `put(2, 'b')` | 1, 2 | |
| `get(1)` | 2, 1 | `'a'` |
| `put(3, 'c')` | 1, 3 (2가 가장 오래돼서 제거) | |
| `get(2)` | 1, 3 | `-1` |

- `get`, `put` 모두 `has`, `get`, `delete`, `set`을 상수 번 부르므로 평균 O(1)입니다. 이중 연결 리스트와 해시 맵을 직접 엮는 고전 구현과 시간 복잡도는 같고, 코드는 훨씬 짧습니다(연결 리스트는 21편).
- `get(key)`로 값이 `undefined`인 항목을 구분해야 하면 반환 규칙을 문제에 맞게 정합니다. `-1`은 값이 음수가 아닐 때만 안전합니다.

**흔한 실수:**

- `get`에서 최근 사용 처리를 빼먹는 것입니다. 읽기만 하고 순서를 갱신하지 않으면 FIFO 캐시가 됩니다.
- `put`에서 이미 있는 키를 지우지 않고 `set`만 하는 것입니다. 값은 바뀌어도 위치가 안 바뀌어 최신으로 취급되지 않습니다.
- 용량을 넘기기 전에 제거하거나, 같은 키 갱신인데도 크기 검사를 먼저 해서 항목을 잘못 버리는 것입니다. 삽입한 뒤에 `size > cap`을 검사하면 순서 문제가 없습니다.

## 핵심 정리

- Object는 문자열 키 사전이고 키 순서가 정수 우선입니다. `keys`, `values`, `entries`로 배열을 만들어 순회합니다.
- Object는 키를 문자열로 바꾸므로 `1`과 `'1'`이 합쳐지고, 객체 키는 전부 같은 키가 됩니다. 구분이 필요하면 Map을 씁니다.
- Map과 Set은 SameValueZero로 키를 비교하고(`NaN`은 같은 값, 객체는 참조), 삽입 순서로 순회하며, `size`로 크기를 얻습니다.
- Set 집합 메서드(ES2025)는 새 Set을 돌려주고 지원 환경이 불확실하면 `filter`와 `has`로 대체합니다.
- 좌표 같은 복합 키는 구분자를 넣은 문자열이나 `r * W + c` 정수로 인코딩하며, 배열을 그대로 키로 쓰면 안 됩니다.
- 지웠다가 다시 넣으면 맨 뒤로 가는 성질로 LRU 캐시를 Map 하나로 구현합니다.
