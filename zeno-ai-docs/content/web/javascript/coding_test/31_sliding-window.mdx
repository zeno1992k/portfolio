## 슬라이딩 윈도우 개념

슬라이딩 윈도우(sliding window)는 배열이나 문자열의 연속 구간(윈도우)을 한 칸씩 밀면서, 구간의 상태를 처음부터 다시 계산하지 않고 바뀐 부분만 고쳐 답을 구하는 기법입니다. 윈도우가 오른쪽으로 한 칸 가면 새 원소 하나가 들어오고 원소 하나가 나갑니다.

```js
// 윈도우 [2, 4]를 오른쪽으로 한 칸 민다
// a = [a0, a1, a2, a3, a4, a5]
// [2, 4] → [3, 5]: a2가 나가고 a5가 들어온다
```

- 모든 윈도우를 처음부터 계산하면 윈도우 길이가 K일 때 O(NK)입니다. 상태를 갱신하면 윈도우마다 O(1)이라서 전체 O(N)입니다.
- 쓰려면 윈도우의 상태(합, 빈도수, 서로 다른 값의 개수 등)를 원소 하나를 넣고 빼는 데 O(1)에 갱신할 수 있어야 합니다.
- 윈도우는 항상 연속 구간입니다. 연속이 아닌 부분 수열에는 쓰지 못합니다.

| 종류 | 윈도우 길이 | 두 끝 | 대표 질문 |
|------|-------------|-------|-----------|
| 고정 길이 | K로 일정 | 함께 한 칸씩 | 길이 K 구간의 합·최댓값·빈도 |
| 가변 길이 | 조건에 따라 늘고 줆 | 끝은 늘리고 시작은 조건이 깨지면 | 조건을 만족하는 가장 긴·가장 짧은 구간 |

가변 길이 윈도우는 같은 방향 포인터(자세히는 30편)와 같은 구조입니다. 차이는 포인터 사이 구간의 상태를 자료구조로 들고 다닌다는 점입니다.

- 쓰는 단서: "연속된 K개", "연속 부분 배열·부분 문자열", "가장 긴·가장 짧은", "서로 다른 문자 K개 이하" 같은 표현입니다.

## 고정 길이 Window

고정 길이 윈도우는 길이 K를 유지한 채로 밀립니다. 첫 윈도우의 상태를 직접 만들고, 이후 인덱스 `i`마다 `a[i]`를 넣고 `a[i - K]`를 뺍니다.

길이 K 구간 합의 최댓값입니다.

```js
function maxWindowSum(a, K) {
  if (a.length < K) return null
  let sum = 0
  for (let i = 0; i < K; i++) sum += a[i]
  let best = sum
  for (let i = K; i < a.length; i++) {
    sum += a[i] - a[i - K]
    if (sum > best) best = sum
  }
  return best
}
maxWindowSum([2, 1, 5, 1, 3, 2], 3) // 9
```

| i | 들어옴 `a[i]` | 나감 `a[i-K]` | 윈도우 | 합 |
|---|---------------|---------------|--------|----|
| 2 | - | - | [2, 1, 5] | 8 |
| 3 | 1 | 2 | [1, 5, 1] | 7 |
| 4 | 3 | 1 | [5, 1, 3] | 9 |
| 5 | 2 | 5 | [1, 3, 2] | 6 |

- 윈도우 `[i - K + 1, i]`에서 `i`가 들어오면 `i - K`가 나갑니다. `a[i - K + 1]`을 빼는 실수가 가장 흔합니다.
- 윈도우의 개수는 `N - K + 1`입니다. `a.length < K`이면 윈도우가 없으므로 먼저 걸러야 합니다.
- 시간 O(N), 공간 O(1)입니다.
- 합이 `Number.MAX_SAFE_INTEGER`를 넘을 수 있는지 확인합니다(자세히는 29편). 소수를 더하고 빼는 갱신은 오차가 쌓이므로 정수로 바꿔 계산하거나 윈도우마다 다시 합산합니다(자세히는 02편).

**흔한 실수:** 첫 윈도우를 별도로 만들지 않고 `i = 0`부터 `a[i - K]`를 읽는 것입니다. `a[-1]`은 `undefined`라서 합이 `NaN`이 됩니다.

## 가변 길이 Window

가변 길이 윈도우는 끝 `end`를 하나씩 늘려 새 원소를 넣고, 조건이 깨지면 시작 `start`를 늘려 조건이 맞을 때까지 줄입니다. 가장 긴 구간을 구하는 템플릿입니다.

```js
function longestAtMost(a, K) { // 양수 배열, 합이 K 이하
  let start = 0, sum = 0, best = 0
  for (let end = 0; end < a.length; end++) {
    sum += a[end]
    while (sum > K) sum -= a[start++]
    best = Math.max(best, end - start + 1)
  }
  return best
}
longestAtMost([2, 1, 3, 1, 1], 4) // 2
```

- 반복의 구조는 항상 같습니다. 넣는다, 조건이 깨졌으면 줄인다, 이 시점의 윈도우가 올바른 구간이므로 답을 갱신한다.
- `start`와 `end`는 줄어들지 않고 각각 최대 N번 움직이므로 안쪽 `while`이 있어도 시간 O(N)입니다(자세히는 14편).
- 가장 긴 구간은 "조건을 만족하는 상태를 유지하며 키우고", 가장 짧은 구간은 "조건을 만족하는 동안 줄이며" 갱신한다는 점이 다릅니다(아래 "최소 길이 Window").
- 조건이 단조여야 합니다. 구간을 줄이면 조건이 더 쉽게 맞고, 늘리면 더 어렵게 맞아야 합니다. 음수가 섞인 합 조건은 단조가 아니므로 누적합과 해시(29편)를 씁니다.
- "정확히 K"는 직접 만들기 어렵고, 보통 "K 이하의 개수에서 K − 1 이하의 개수를 뺀" 값으로 구합니다(아래 "Distinct Count Window").

## 구간 합

구간 합 문제에서 슬라이딩 윈도우와 누적합(29편) 중 무엇을 쓸지는 질의 방식으로 정합니다.

| 상황 | 알맞은 방법 | 이유 |
|------|-------------|------|
| 길이 K 구간만 모두 훑는다 | 슬라이딩 윈도우 | 추가 배열 없이 O(1) 공간 |
| 임의 구간 `[l, r]`을 여러 번 묻는다 | 누적합 | 윈도우 모양이 정해져 있지 않음 |
| 조건을 만족하는 가장 긴·짧은 구간 | 가변 슬라이딩 윈도우 | 구간의 양 끝을 조건에 맞춰 이동 |

고정 길이 구간 합의 응용은 "합이 기준 이상인 윈도우의 개수"입니다. 배열이 원형이면 인덱스를 `N`으로 나눈 나머지로 감쌉니다.

```js
function countCircular(a, K, T) {
  const n = a.length
  let sum = 0
  for (let i = 0; i < K; i++) sum += a[i]
  let count = sum >= T ? 1 : 0
  for (let i = 1; i < n; i++) {
    sum += a[(i + K - 1) % n] - a[i - 1]
    if (sum >= T) count++
  }
  return count
}
countCircular([1, 5, 2, 4], 3, 8) // 3
```

- 시작 위치 `i`의 윈도우는 `a[i]`부터 K개입니다. 시작이 `i - 1`에서 `i`로 가면 `a[i - 1]`이 나가고 `a[(i + K - 1) % n]`이 들어옵니다.
- 윈도우가 원형으로 이어지므로 시작 위치가 N개이고 모두 확인합니다. `K <= n`이어야 합니다.
- 윈도우 평균은 합을 K로 나눈 값이므로, 합으로 비교하고 마지막에 나눕니다.

## 구간 최대와 최소

고정 길이 K 윈도우마다 최댓값을 구하는 문제입니다. 합과 달리 최댓값은 "나간 원소를 되돌려 빼는" 방법이 없습니다. 나간 원소가 최댓값이었다면 남은 원소 중 새 최댓값이 무엇인지 알려면 윈도우를 다시 봐야 합니다(역연산이 없는 연산은 29편).

가장 단순한 방법은 윈도우마다 훑는 것입니다.

```js
const a = [1, 3, -1, -3, 5, 3, 6, 7], K = 3
const res = []
for (let i = 0; i + K <= a.length; i++) {
  res.push(Math.max(...a.slice(i, i + K)))
}
// [3, 3, 5, 5, 6, 7]
```

- 윈도우마다 K개를 보므로 O(NK)입니다. K가 작을 때만 허용됩니다.
- `Math.max(...)`는 인수 개수에 한계가 있어서 K가 아주 크면 에러가 날 수 있습니다. 엔진마다 한계가 다릅니다(MDN은 JavaScriptCore의 65536개를 명시). 큰 K에는 `for` 반복으로 최댓값을 구합니다(자세히는 86편).
- 윈도우마다 `slice`로 새 배열을 만드는 비용(O(K))도 듭니다.

O(N)에 푸는 방법은 윈도우 안에서 최댓값 후보만 단조롭게 남기는 모노톤 큐입니다(자세히는 32편). 힙에 넣고 윈도우 밖 원소를 나중에 지우는 방법도 있지만 O(N log N)입니다(자세히는 47편).

| 방법 | 시간 | 쓰는 경우 |
|------|------|-----------|
| 윈도우마다 훑기 | O(NK) | K가 작을 때 |
| 모노톤 큐 | O(N) | 일반적인 정답 |
| 힙과 지연 삭제 | O(N log N) | 윈도우가 불규칙할 때 |

## 문자열 Window

문자열 윈도우는 배열 윈도우와 같습니다. 윈도우를 `s.slice(start, end + 1)`로 매번 만들면 길이만큼의 복사 비용이 들어서 O(NK)가 되므로, 인덱스 `start`, `end`만 유지하고 상태는 따로 둡니다(문자열은 변경할 수 없어서 글자를 빼고 넣는 개념이 없습니다. 자세히는 06편).

반복 문자가 없는 가장 긴 부분 문자열의 길이입니다. 각 문자의 마지막 위치를 Map에 저장하고, 반복이 나오면 `start`를 그 위치 다음으로 점프합니다.

```js
function lengthOfLongest(s) {
  const last = new Map()
  let start = 0, best = 0
  for (let end = 0; end < s.length; end++) {
    const p = last.get(s[end])
    if (p !== undefined && p >= start) start = p + 1
    last.set(s[end], end)
    best = Math.max(best, end - start + 1)
  }
  return best
}
lengthOfLongest('abcabcbb') // 3 (abc)
lengthOfLongest('abba')     // 2 (ab 또는 ba)
```

- `p >= start` 검사가 필요합니다. 마지막 위치가 윈도우 밖이면 반복이 아닙니다. `'abba'`의 마지막 `a`에서 `p = 0`이지만 이미 `start = 2`이므로 무시해야 합니다.
- 시작을 한 칸씩 올리며 해당 문자를 `Set`에서 지우는 방식도 가능하고 시간은 같은 O(N)입니다. 점프 방식은 `start` 이동이 한 번에 끝납니다.
- `s[end]`는 UTF-16 코드 유닛 단위입니다. 이모지처럼 코드 유닛이 둘인 글자는 하나로 보이지 않습니다. 문제의 문자가 소문자 알파벳이면 `charCodeAt(i) - 97`로 0–25 인덱스를 만들어 배열에 쓸 수 있습니다(자세히는 06편).
- 쓰는 단서: "중복 없는", "같은 문자 K개까지", "서로 다른 문자 K개 이하"입니다.

## 빈도수 Map Window

윈도우 안의 값별 개수를 Map이나 배열로 유지하고, 들어오는 원소는 개수를 올리고 나가는 원소는 내립니다. 두 빈도 분포를 비교하는 문제에 쓰입니다.

문자열 `s`에서 `p`의 애너그램(글자 구성이 같은 문자열)이 시작하는 위치를 모두 찾습니다. 윈도우 길이는 `p.length`로 고정입니다. 소문자만 나오므로 알파벳 26개짜리 배열을 씁니다(애너그램은 07편, 빈도수는 10편).

```js
function findAnagrams(s, p) {
  const need = Array(26).fill(0), win = Array(26).fill(0)
  const code = (i) => s.charCodeAt(i) - 97
  for (const ch of p) need[ch.charCodeAt(0) - 97]++
  const same = () => need.every((v, k) => v === win[k])
  const res = [], m = p.length
  for (let i = 0; i < s.length; i++) {
    win[code(i)]++
    if (i >= m) win[code(i - m)]--
    if (i >= m - 1 && same()) res.push(i - m + 1)
  }
  return res
}
findAnagrams('cbaebabacd', 'abc') // [0, 6]
```

- 윈도우가 `p.length`를 넘으면 맨 왼쪽 글자를 빼고, 윈도우가 찼으면 비교합니다. 비교는 26칸이라 O(26)이고 전체 O(26N)입니다.
- 비교를 O(1)로 줄이려면 "필요한 개수와 같아진 문자 종류의 수"를 변수로 유지합니다. 개수를 바꿀 때마다 그 문자가 같아졌는지, 같았다가 달라졌는지만 확인해 변수를 고칩니다.
- 값의 범위가 작은 정수나 소문자 문자는 배열이 Map보다 빠르고 코드가 짧습니다. 범위가 크거나 문자열 키라면 Map을 씁니다(자세히는 09편).

## 최소 길이 Window

최소 길이 윈도우는 조건을 만족하는 가장 짧은 구간을 구합니다. 가장 긴 구간과 반대로 "조건이 만족되는 동안 시작을 줄여 가며" 매번 길이를 갱신합니다.

양수 배열에서 합이 S 이상인 가장 짧은 구간의 길이입니다.

```js
function shortestAtLeast(a, S) {
  let start = 0, sum = 0, best = Infinity
  for (let end = 0; end < a.length; end++) {
    sum += a[end]
    while (sum >= S) {
      best = Math.min(best, end - start + 1)
      sum -= a[start++]
    }
  }
  return best === Infinity ? 0 : best
}
shortestAtLeast([2, 3, 1, 2, 4, 3], 7) // 2 ([4, 3])
```

- 갱신 위치가 `while` 안입니다. 조건을 만족하는 동안만 구간이 후보이고, 줄이면 더 짧은 후보가 됩니다. 가장 긴 구간의 템플릿과 비교하면 `while` 조건이 반대입니다.
- 답이 없을 수 있어서 `Infinity`로 시작하고 마지막에 처리합니다.
- 양수일 때만 맞고, 음수가 있으면 단조성이 깨집니다(자세히는 29편).

문자열에서 `t`의 모든 글자를 포함하는 가장 짧은 부분 문자열을 찾는 문제도 같은 구조입니다. 윈도우에 부족한 글자 수를 `missing`으로 유지하고, `missing`이 0인 동안 줄입니다.

```js
function minWindowLen(s, t) { // ASCII 문자열 가정
  const need = new Array(128).fill(0)
  for (const ch of t) need[ch.charCodeAt(0)]++
  let missing = t.length, start = 0, best = Infinity
  for (let end = 0; end < s.length; end++) {
    if (need[s.charCodeAt(end)]-- > 0) missing--
    while (missing === 0) {
      best = Math.min(best, end - start + 1)
      if (++need[s.charCodeAt(start++)] > 0) missing++
    }
  }
  return best === Infinity ? 0 : best
}
minWindowLen('ADOBECODEBANC', 'ABC') // 4 (BANC)
```

- `need[c]`가 양수이면 아직 필요한 글자, 0 이하이면 충분하거나 남는 글자입니다. 필요한 글자가 들어올 때만 `missing`이 줄고, 필요한 글자가 나갈 때만 늘어납니다.
- 시작 위치까지 필요하면 `best`를 갱신할 때 `start`도 함께 저장합니다.

## Distinct Count Window

윈도우 안의 서로 다른 값의 개수를 유지합니다. 값별 개수를 Map에 두고, 개수가 0이 되면 키를 지웁니다. 그러면 `Map.size`가 서로 다른 값의 개수입니다.

길이 K 윈도우마다 서로 다른 값의 개수를 구합니다.

```js
function distinctPerWindow(a, K) {
  const cnt = new Map()
  const res = []
  for (let i = 0; i < a.length; i++) {
    cnt.set(a[i], (cnt.get(a[i]) ?? 0) + 1)
    if (i >= K) {
      const x = a[i - K]
      if (cnt.get(x) === 1) cnt.delete(x)
      else cnt.set(x, cnt.get(x) - 1)
    }
    if (i >= K - 1) res.push(cnt.size)
  }
  return res
}
distinctPerWindow([1, 2, 1, 3, 2, 2], 3) // [2, 3, 3, 2]
```

- 개수가 0인 키를 지우지 않으면 `size`가 윈도우를 벗어난 값까지 세어 틀립니다. 지우는 코드가 이 문제의 핵심입니다.
- Map은 키를 `SameValueZero`로 비교해서 숫자 `1`과 문자열 `'1'`을 구분합니다. 없는 키는 `undefined`라서 `?? 0`으로 받습니다(자세히는 09편).
- 값이 작은 정수라면 배열과 변수 `distinct`로 같은 일을 할 수 있습니다. 개수가 0에서 1이 될 때 `distinct`를 올리고, 1에서 0이 될 때 내립니다.

서로 다른 값이 K개 이하인 가장 긴 구간은 가변 길이 템플릿에 같은 Map을 씁니다.

```js
function longestKDistinct(a, K) {
  const cnt = new Map()
  let start = 0, best = 0
  for (let end = 0; end < a.length; end++) {
    cnt.set(a[end], (cnt.get(a[end]) ?? 0) + 1)
    while (cnt.size > K) {
      const x = a[start++]
      if (cnt.get(x) === 1) cnt.delete(x)
      else cnt.set(x, cnt.get(x) - 1)
    }
    best = Math.max(best, end - start + 1)
  }
  return best
}
longestKDistinct([1, 2, 1, 2, 3], 2) // 4
```

- 시간 O(N)입니다. 안쪽 `while`의 총 반복은 `start` 이동 횟수인 N 이하입니다.
- "서로 다른 값이 정확히 K개인 구간의 개수"는 직접 세기 어렵습니다. "K개 이하인 구간의 개수"를 세는 함수를 만들어 `atMost(K) - atMost(K - 1)`로 구합니다. `[1, 2, 1, 2, 3]`에서 정확히 2종류인 구간은 `atMost(2) - atMost(1) = 7`개입니다.
- "K개 이하" 개수는 각 `end`마다 `end - start + 1`을 더합니다. `end`로 끝나는 올바른 구간이 그만큼이기 때문입니다.

## 핵심 정리

- 슬라이딩 윈도우는 연속 구간을 밀면서 들어오는 원소와 나가는 원소만으로 상태를 갱신해 O(NK)를 O(N)으로 줄이며, 상태 갱신이 O(1)이어야 합니다.
- 고정 길이는 첫 윈도우를 직접 만든 뒤 `a[i]`를 넣고 `a[i - K]`를 뺍니다. 윈도우 개수는 `N - K + 1`입니다.
- 가변 길이는 끝을 늘려 넣고, 조건이 깨지면 시작을 줄이며, 가장 긴 구간은 줄인 뒤에 갱신하고 가장 짧은 구간은 줄이는 동안 갱신합니다.
- 합은 빼서 되돌릴 수 있지만 최댓값·최솟값은 되돌릴 수 없어서 모노톤 큐(32편)가 필요합니다.
- 문자열은 `slice`를 만들지 않고 인덱스와 빈도 배열·Map으로 상태를 유지하며, 서로 다른 값의 개수는 개수가 0인 키를 지워야 `Map.size`로 알 수 있습니다.
- "정확히 K개"는 "K개 이하" 개수의 차로 구하고, 음수가 섞인 합 조건은 단조가 아니라서 슬라이딩 윈도우를 쓰지 못합니다.
