## JavaScript sort

`Array.prototype.sort`는 배열을 제자리(in-place)에서 정렬하고 같은 배열 참조를 반환합니다. 비교 함수(comparator)를 생략하면 요소를 문자열로 바꿔 UTF-16 코드 유닛 순서로 비교합니다.

```js
const a = [1, 30, 4, 21, 100000]
const r = a.sort()
r === a // true (같은 배열, 원본이 바뀜)
a       // [1, 100000, 21, 30, 4]
```

- `undefined`는 비교 함수를 호출하지 않고 항상 맨 뒤로 가고, 빈 칸(hole)은 `undefined`보다도 뒤로 갑니다.
- 원본을 유지하려면 복사본을 정렬하거나(`[...a].sort(...)`) `toSorted`를 씁니다. `toSorted`는 ES2023에 추가되었고 새 배열을 반환합니다. 비교 함수 규칙은 `sort`와 같습니다.
- 비교 함수는 `(a, b)`를 받아 숫자를 반환합니다. 음수면 a가 앞, 양수면 a가 뒤, 0이면 같은 값으로 취급합니다.

| 반환값 | 의미 |
|--------|------|
| 음수 | a를 b보다 앞에 둔다 |
| 0 | 같다. 원래 순서를 유지한다(안정 정렬) |
| 양수 | a를 b보다 뒤에 둔다 |

- 정렬의 시간복잡도는 명세가 정하지 않습니다. V8은 7.0(Chrome 70)부터 TimSort(안정적인 병합 정렬 계열)를 쓰며 최악 O(N log N), 이미 정렬된 입력은 O(N)입니다. 코딩테스트에서는 O(N log N)으로 계산합니다.
- 비교 함수는 순수해야 합니다. 배열을 바꾸거나 바깥 상태를 건드리면 결과가 불확실합니다.

## 숫자 정렬

숫자 배열은 기본 정렬 대신 `(a, b) => a - b`로 오름차순, `(a, b) => b - a`로 내림차순 정렬합니다.

```js
const n = [10, 9, 1]
n.toSorted()                // [1, 10, 9] ❌ 문자열 순
n.toSorted((a, b) => a - b) // [1, 9, 10] ✅ 오름차순
n.toSorted((a, b) => b - a) // [10, 9, 1] ✅ 내림차순
const neg = [-1, -10, 5, 0]
neg.toSorted()              // [-1, -10, 0, 5] ❌
```

- 기본 정렬은 숫자를 `'10'`, `'9'` 같은 문자열로 바꿔 비교하므로 `'10'`이 `'9'`보다 앞입니다. 음수의 부호 `-`도 문자 하나로 비교됩니다.
- TypedArray의 `sort()`는 비교 함수 없이도 숫자 순으로 정렬합니다. `Int32Array.from(arr).sort()`가 오름차순입니다.

```js
new Int32Array([10, 9, 1, 100]).sort()
// Int32Array [1, 9, 10, 100]
```

- Node 24에서 난수 정수 100만 개를 직접 쟀을 때 비교 함수가 있는 일반 배열은 약 190ms, `Int32Array`는 약 50ms가 걸렸습니다. 환경에 따라 달라지는 값이므로 경향만 참고합니다(TypedArray는 05편).

**시험에서 묻는 방식:** `[10, 9, 1].sort()`의 결과를 묻습니다. 오름차순으로 착각하기 쉽습니다.

**흔한 실수:** 숫자 배열에 비교 함수를 빼먹는 것입니다. 한 자리 수만 있는 작은 예제에서는 맞게 나와서 놓치고, 두 자리 수가 섞이면 틀립니다.

## 문자열 정렬

문자열 배열의 기본 정렬은 UTF-16 코드 유닛 값 순서이며 영어 사전 순과 다릅니다.

```js
const w1 = ['b', 'B', 'a', 'A']
w1.toSorted() // ['A', 'B', 'a', 'b'] 대문자가 모두 앞
const w2 = ['apple', 'Banana', 'cherry']
w2.toSorted() // ['Banana', 'apple', 'cherry']
const w3 = ['가', 'ㄱ', 'a', 'A', '나']
w3.toSorted() // ['A', 'a', 'ㄱ', '가', '나']
```

- 코드 값 기준이라 대문자(65–90)가 소문자(97–122)보다 앞이고, 한글 자모와 완성형 음절은 영문자보다 뒤입니다.
- 숫자로 된 문자열은 사전 순이라 `['10', '9', '2', '1'].sort()`는 `['1', '10', '2', '9']`입니다.
- 코딩테스트의 "사전 순"은 대부분 이 코드 값 순서입니다. 대소문자를 구분하지 않는 사전 순이 필요하면 비교 전에 `toLowerCase()`로 맞춥니다.
- `localeCompare`는 로캘(지역 언어 규칙)을 반영해 순서가 달라집니다(아래 "문자열 Comparator").

## Comparator에서 a - b

`a - b`는 두 수의 부호가 곧 비교 결과이기 때문에 숫자 Comparator로 쓸 수 있습니다. a가 작으면 음수, 같으면 0, 크면 양수입니다.

```js
const asc = (a, b) => a - b   // a가 작을수록 앞
const desc = (a, b) => b - a  // a가 클수록 앞
```

조건이 안전한 경우와 아닌 경우를 구분해야 합니다.

| 상황 | `a - b`의 결과 |
|------|----------------|
| 일반 정수·실수 | 정상 |
| 값이 `NaN` | 결과가 `NaN`이 되고 `sort`는 0(같음)으로 취급해 순서가 깨진다 |
| `Infinity`와 `Infinity` | `Infinity - Infinity`가 `NaN` |
| BigInt 배열 | 차가 BigInt라서 숫자로 변환할 수 없어 TypeError |
| 객체나 문자열 | 숫자로 바뀌지 않으면 `NaN` |

```js
const f = [3, NaN, 1, 2]
f.toSorted((a, b) => a - b)
// [3, NaN, 1, 2] ❌ 정렬되지 않음
const big = [3n, 1n, 2n]
big.toSorted((a, b) => a - b)
// TypeError: Cannot convert a BigInt value to a number
big.toSorted((a, b) => (a < b ? -1 : a > b ? 1 : 0))
// [1n, 2n, 3n] ✅
```

- `NaN`이 들어올 수 있으면 먼저 걸러 내거나 별도로 처리합니다.
- BigInt는 부호만 맞추는 Comparator `a < b ? -1 : a > b ? 1 : 0`을 씁니다(BigInt는 02편).
- JavaScript의 Number는 부동소수점이라 C++의 `int` 같은 오버플로가 없습니다. 값이 2^53 이하의 정수이거나 일반 실수이면 `a - b`가 안전합니다. 정밀도를 넘는 값은 BigInt로 다룹니다.
- `a - b`의 반환값은 숫자여야 합니다. 불리언을 반환하면 안 됩니다(아래 "일관성 없는 Comparator의 결과").

**흔한 실수:** 오름차순과 내림차순을 헷갈려 `a - b`를 내림차순에 쓰는 것입니다. 결과를 뒤집으려고 `reverse()`를 붙여도 되지만, 비교 함수의 순서만 바꾸는 편이 안정 정렬의 순서까지 의도대로 둡니다.

## 문자열 Comparator

문자열은 `<`, `>`로 코드 값 순서를 비교해 `-1`, `0`, `1`을 반환하는 Comparator를 씁니다. 문자열에는 `-`를 쓸 수 없습니다.

```js
const cmp = (a, b) => (a < b ? -1 : a > b ? 1 : 0)
const ch = ['b', 'a', 'C']
ch.toSorted(cmp)                  // ['C', 'a', 'b']
ch.toSorted((a, b) => cmp(b, a))  // ['b', 'a', 'C']
```

- 오름차순에서 대문자가 앞서는 이유는 코드 값 순서이기 때문입니다.

길이를 먼저 비교하고 같을 때 사전 순으로 정렬하는 식이 자주 나옵니다.

```js
const ws = ['abc', 'b', 'aa', 'a']
ws.sort((a, b) => a.length - b.length || cmp(a, b))
// ['a', 'b', 'aa', 'abc']
```

붙여서 비교하는 Comparator도 있습니다. 숫자를 이어 붙여 가장 큰 수를 만드는 문제에서는 `a + b`와 `b + a`를 문자열로 비교합니다.

```js
const words = ['5', '25', '100', '1']
words.sort((a, b) => {
  const x = a + b, y = b + a
  return x < y ? 1 : x > y ? -1 : 0   // 큰 이어 붙임이 앞
})
words.join('') // '5251100'
```

`localeCompare`는 로캘 규칙으로 비교합니다.

```js
const ab = ['b', 'B', 'a', 'A']
ab.sort((x, y) => x.localeCompare(y))
// ['a', 'A', 'b', 'B'] 소문자가 같은 글자의 대문자보다 앞
const opt = { numeric: true }
const files = ['item10', 'item9', 'item2']
files.sort((x, y) => x.localeCompare(y, undefined, opt))
// ['item2', 'item9', 'item10']
```

- 반환값의 부호만 믿습니다. `-1`, `1`이 아닌 다른 숫자가 나올 수 있습니다.
- 결과가 로캘과 구현에 따라 달라집니다. 로캘를 생략하면 실행 환경의 기본 로캘이 쓰입니다.
- `numeric: true` 옵션을 주면 숫자 부분을 수로 비교합니다(자연 정렬).
- 많은 문자열을 정렬할 때는 `Intl.Collator`를 한 번 만들어 `collator.compare`를 넘기는 편이 빠릅니다.
- 코딩테스트의 사전 순은 코드 값 순서이므로 `<`, `>` 비교를 기본으로 하고, 문제가 로캘 정렬을 요구할 때만 `localeCompare`를 씁니다.

**흔한 실수:** 문자열 Comparator를 `(a, b) => a > b`처럼 불리언으로 쓰는 것입니다.

## 다중 조건 정렬

여러 기준으로 정렬할 때는 Comparator에서 `||`로 기준을 잇습니다. 앞 기준의 결과가 0일 때만 다음 기준으로 넘어갑니다.

```js
const pts = [[2, 1], [1, 5], [2, 0], [1, 2]]
pts.sort((a, b) => a[0] - b[0] || a[1] - b[1])
// [[1, 2], [1, 5], [2, 0], [2, 1]]
```

- `a[0] - b[0]`이 0이면 거짓으로 취급되어 `||` 뒤의 `a[1] - b[1]`을 평가합니다. 0이 아닌 숫자는 참이라 그 값이 반환됩니다.
- 기준마다 오름차순과 내림차순을 따로 정합니다. 내림차순 기준은 인자의 순서를 바꿉니다.

```js
// 첫째 값 내림차순, 같으면 둘째 값 오름차순
pts.sort((a, b) => b[0] - a[0] || a[1] - b[1])
// [[2, 0], [2, 1], [1, 2], [1, 5]]
```

- 기준이 숫자이면 `-`로, 문자열이면 `cmp`로 씁니다. 섞을 때도 같은 방식입니다.
- 모든 기준이 같은 요소는 0이 되어 원래 순서가 유지됩니다(안정 정렬, 아래).
- 기준이 많아지면 한 줄이 길어집니다. 휴대폰 폭에서는 줄을 나눠 씁니다.

**흔한 실수:** `||` 대신 `&&`나 삼항 연산자로 이으려다 결과가 틀리는 것입니다. 기준 하나의 결과가 항상 숫자여야 `||`가 동작합니다. 불리언을 반환하는 기준이 하나라도 있으면 안 됩니다.

## 객체 다중 기준 Comparator

객체 배열은 프로퍼티를 꺼내 같은 방식으로 이습니다. 점수 내림차순, 나이 오름차순, 이름 사전 순의 세 기준입니다.

```js
const rows = [
  { name: 'kim', score: 90, age: 20 },
  { name: 'lee', score: 85, age: 19 },
  { name: 'an', score: 90, age: 20 },
  { name: 'park', score: 85, age: 21 },
]
rows.sort((a, b) =>
  b.score - a.score || a.age - b.age || cmp(a.name, b.name))
rows.map((r) => r.name) // ['an', 'kim', 'lee', 'park']
```

- `an`과 `kim`은 점수·나이가 같아 이름 `an < kim`으로 정해집니다. `lee`와 `park`는 점수가 같고 나이가 19, 21로 달라서 `lee`가 앞입니다.
- 기준 함수를 배열로 정의해 순서대로 적용하는 방식으로 일반화할 수 있습니다.

```js
const by = (...keys) => (a, b) => {
  for (const [f, dir] of keys) {
    const x = f(a), y = f(b)
    if (x !== y) return (x < y ? -1 : 1) * dir
  }
  return 0
}
rows.sort(by([(r) => r.score, -1], [(r) => r.age, 1]))
```

- `dir`이 1이면 오름차순, -1이면 내림차순입니다. 이 방식은 숫자와 문자열 모두 `<`로 비교하므로 `NaN`이 없는 값에 씁니다.
- 비교할 값을 매번 계산하는 비용이 크면, 먼저 `[키, 원본]` 쌍으로 만든 뒤 정렬하고 원본만 꺼냅니다.

## 안정 정렬 (Stable Sort)

안정 정렬은 비교 결과가 같은 요소들의 원래 순서를 유지하는 정렬입니다. `Array.prototype.sort`는 ES2019부터 안정 정렬이 보장됩니다. 그 전에는 보장되지 않았습니다.

```js
const people = [
  { n: 'a', s: 90 }, { n: 'b', s: 80 },
  { n: 'c', s: 90 }, { n: 'd', s: 80 },
]
people.sort((x, y) => y.s - x.s)
people.map((p) => p.n).join('') // 'acbd'
```

점수가 같은 `a`와 `c`는 원래 순서(`a`가 먼저)대로, `b`와 `d`도 원래 순서대로 남습니다.

안정성을 이용해 기준을 여러 번에 나눠 정렬할 수 있습니다. 덜 중요한 기준으로 먼저 정렬하고, 더 중요한 기준으로 나중에 정렬합니다.

```js
const d = [
  { n: 'a', g: 2, s: 1 }, { n: 'b', g: 1, s: 2 },
  { n: 'c', g: 2, s: 2 }, { n: 'd', g: 1, s: 1 },
]
d.sort((x, y) => x.s - y.s)  // 보조 기준 s 먼저
d.sort((x, y) => x.g - y.g)  // 주 기준 g 나중
d.map((x) => x.n).join('')   // 'dbac'
```

- 마지막에 정렬한 기준이 우선순위가 가장 높습니다. 같은 g 안에서는 앞선 정렬의 s 순서가 유지되어 `d, b`(g가 1, s 순)와 `a, c`(g가 2, s 순)가 됩니다.
- 한 번에 `||`로 잇는 방식이 더 짧고 빠릅니다. 여러 번 정렬하는 방식은 기준이 번갈아 바뀌는 경우나 키 비교 함수가 독립적일 때 씁니다.
- 안정 정렬 덕분에 "같으면 입력 순서 유지" 조건의 문제를 마지막에 `i - j` 같은 보조 기준 없이 풀 수 있습니다.
- 퀵 정렬은 일반적으로 안정적이지 않습니다(27편). 안정성을 전제로 쓴 풀이를 안정성이 없는 정렬로 옮기면 결과가 달라집니다.

## 정렬 후 Sweep / Greedy 연결

정렬은 그 자체로 답이 아니라 뒤의 스캔(sweep)이나 탐욕(greedy) 선택을 가능하게 하는 전처리인 경우가 많습니다. 정렬하면 "이웃끼리만 비교하면 된다"가 성립해 O(N²) 비교가 O(N)으로 줄기 때문입니다.

대표 패턴은 두 가지입니다. 직접 만든 입력으로 봅니다.

**종료 시각 순 탐욕:** 구간을 끝 시각이 빠른 순으로 정렬하고, 앞의 선택과 겹치지 않는 구간을 차례로 고릅니다(자세히는 33편).

```js
const m = [[1, 3], [2, 4], [3, 6], [5, 7], [6, 8], [8, 10]]
m.sort((a, b) => a[1] - b[1] || a[0] - b[0])
let end = -Infinity, count = 0
for (const [s, e] of m) {
  if (s >= end) { count++; end = e }  // 겹치지 않으면 선택
}
count // 4 (선택: [1,3] [3,6] [6,8] [8,10])
```

**시작 시각 순 병합:** 구간을 시작 시각 순으로 정렬하고, 겹치면 끝을 늘리며 한 번 훑습니다(자세히는 34편).

```js
const iv = [[5, 8], [1, 3], [2, 4], [9, 10], [8, 9]]
iv.sort((a, b) => a[0] - b[0])
const out = [iv[0].slice()]
for (const [s, e] of iv.slice(1)) {
  const last = out[out.length - 1]
  if (s <= last[1]) last[1] = Math.max(last[1], e)
  else out.push([s, e])
}
out // [[1, 4], [5, 10]]
```

- 정렬 기준 선택이 풀이의 핵심입니다. 같은 구간 문제라도 끝 시각 순이냐 시작 시각 순이냐에 따라 맞는 풀이가 갈립니다.
- 두 점이나 배열 요소의 합·차를 이웃에서 찾는 문제(투 포인터, 30편), 사건의 시작과 끝을 점으로 바꿔 훑는 문제(스위프 라인, 55편)도 같은 정렬 후 스캔 구조입니다.
- 문제 문장의 단서는 "최대/최소 개수를 고른다", "겹치는 것을 합친다", "가까운 것끼리 짝짓는다"입니다.

## 인덱스 정렬

인덱스 정렬은 값 배열은 그대로 두고 인덱스 배열을 값 기준으로 정렬해 원래 위치를 보존하는 방법입니다. 정렬 결과와 원래 위치를 함께 알아야 할 때 씁니다(순위, 원래 번호 출력).

```js
const v = [30, 10, 20, 10]
const idx = v.map((_, i) => i)
idx.sort((i, j) => v[i] - v[j] || i - j)
idx // [1, 3, 2, 0] (작은 값부터의 원래 인덱스)
```

- `i - j`는 값이 같을 때 원래 순서를 정하는 보조 기준입니다. 안정 정렬이라 없어도 같은 결과지만 의도를 드러냅니다.
- 각 요소의 정렬 후 순위(rank)는 인덱스 배열을 뒤집어 구합니다.

```js
const rank = new Array(v.length)
idx.forEach((original, k) => { rank[original] = k })
rank // [3, 0, 2, 1]
```

- `rank[i]`는 `v[i]`가 정렬 후 몇 번째인지(0부터)입니다. 같은 값(10)이 둘이면 원래 순서대로 0, 1이 붙습니다.
- 값을 `[값, 인덱스]` 쌍으로 묶어 정렬해도 같은 결과입니다. 쌍 방식은 메모리를 더 쓰고, 인덱스 방식은 값을 읽을 때 간접 접근이 필요합니다.
- 좌표를 정수 순위로 바꾸는 좌표 압축(54편)이 이 방식의 응용입니다.

## 일관성 없는 Comparator의 결과

일관성 없는 Comparator는 같은 두 값에 대해 호출 순서에 따라 결과가 달라지거나 모순되는 값을 반환하는 비교 함수입니다. 올바른 Comparator는 다음 성질을 지켜야 합니다.

- 반사성: `cmp(a, a)`가 0
- 반대칭: `cmp(a, b)`와 `cmp(b, a)`의 부호가 반대(또는 모두 0)
- 추이성: a가 b보다 앞서고 b가 c보다 앞서면 a가 c보다 앞선다

이를 어기면 결과는 엔진마다 다르고, 정렬이 틀리거나 예측할 수 없습니다. 명세는 이 경우 정렬 순서를 구현에 맡깁니다.

**불리언 반환:**

```js
const p = [3, 1, 2]
p.toSorted((a, b) => a > b)
// [3, 1, 2] ❌ Node 24(V8)에서는 정렬되지 않음
const q = [5, 4, 3, 2, 1]
q.toSorted((a, b) => (a > b ? 1 : 0))
// [5, 4, 3, 2, 1] ❌ 음수가 없어서 정렬되지 않음
```

- `a > b`는 `true`가 1, `false`가 0이 되어 음수가 나오지 않습니다. 반대칭이 깨져서 엔진마다 결과가 다릅니다. MDN은 비슷한 식 `(a > b ? 1 : 0)`이 V8과 Safari에서는 배열이 그대로이고 Firefox에서는 오름차순이 되는 사례를 듭니다.
- 항상 `-1`, `0`, `1`(또는 부호가 맞는 숫자)을 반환합니다.

**랜덤 Comparator로 섞기:**

```js
arr.sort(() => Math.random() - 0.5) // ❌ 편향된 셔플
```

- 같은 쌍을 비교할 때마다 결과가 달라 일관성이 없습니다. 1부터 10까지 배열을 20000번 섞어 첫 원소를 세어 보면 균등하지 않고 특정 값에 크게 치우칩니다(Node 24에서 1이 약 20퍼센트).
- 섞으려면 Fisher-Yates를 씁니다.

```js
for (let i = arr.length - 1; i > 0; i--) {
  const j = Math.floor(Math.random() * (i + 1))
  ;[arr[i], arr[j]] = [arr[j], arr[i]]
}
```

**NaN과 undefined:**

- 비교 결과가 `NaN`이면 0으로 취급되어 정렬이 깨질 수 있습니다(숫자 Comparator 절).
- `undefined` 요소는 비교 함수를 거치지 않고 맨 뒤로 갑니다.

**부수 효과가 있는 Comparator:**

- 비교 함수 안에서 정렬 중인 배열을 바꾸거나 카운터를 올리는 코드는 호출 횟수·순서가 엔진마다 달라서 결과를 믿을 수 없습니다.

**시험에서 묻는 방식:** `[3, 1, 2].sort((a, b) => a > b)`의 결과나, 문제 코드에 숨은 `Math.random() - 0.5`의 문제를 지적하게 합니다.

## 핵심 정리

- `sort`는 원본을 제자리에서 바꾸고 같은 배열을 반환하며, 비교 함수가 없으면 문자열 UTF-16 코드 유닛 순서라서 숫자 배열이 틀립니다.
- 숫자 오름차순은 `(a, b) => a - b`이고 내림차순은 `b - a`입니다. `NaN`이나 BigInt가 섞이면 부호만 반환하는 Comparator를 씁니다.
- 문자열은 `<`, `>`로 `-1`, `0`, `1`을 반환하고, `localeCompare`는 로캘에 따라 달라지므로 필요할 때만 씁니다.
- 다중 조건은 `||`로 잇고, 내림차순 기준은 인자 순서를 바꿉니다. `sort`는 ES2019부터 안정 정렬이라 같은 값은 원래 순서를 유지합니다.
- 정렬은 구간 선택·병합 같은 스캔의 전처리이고, 원래 위치가 필요하면 인덱스 배열을 정렬합니다.
- 불리언을 반환하거나 `Math.random() - 0.5`를 쓰는 일관성 없는 Comparator는 결과를 보장할 수 없습니다.
