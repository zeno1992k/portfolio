## Mod 연산

mod 연산은 정수를 m으로 나눈 나머지를 구하는 연산입니다. 답이 너무 커서 정확한 값을 출력할 수 없는 문제는 "1,000,000,007로 나눈 나머지"를 요구합니다. 이때 중간 계산마다 나머지를 취해 값의 크기를 m 아래로 묶어 둡니다.

`a mod m`은 `0 ≤ r < m`이고 `a = m·q + r`인 r입니다. 나머지는 항상 0 이상입니다. 그런데 JavaScript의 `%`는 나머지의 부호가 피제수(앞의 수)를 따릅니다.

```js
7 % 5    // 2
-7 % 5   // -2 (수학의 mod 값은 3)
-5 % 5   // -0
```

음수가 나올 수 있는 식은 한 번 더 보정해서 0 이상으로 만듭니다.

```js
const MOD = 1000000007
const mod = (a, m = MOD) => ((a % m) + m) % m
mod(-7, 5)   // 3
mod(-1)      // 1000000006
```

- `-0`은 `Object.is`로 비교하지 않으면 `0`과 구별되지 않지만, 출력은 `0`으로 나옵니다. 문자열로 만들 때 `String(-0)`은 `'0'`입니다.
- BigInt의 `%`도 같은 규칙(피제수의 부호)이고, `0n`으로 나누면 RangeError입니다(숫자는 `NaN`).
- 소수 부분이 있는 값에는 쓰지 않습니다. mod 계산은 정수만 대상으로 합니다.

아래 표가 mod에서 쓰는 성질입니다.

| 연산 | 성립 여부 | 식 |
|------|-----------|----|
| 덧셈 | 성립 | `(a + b) mod m = ((a mod m) + (b mod m)) mod m` |
| 뺄셈 | 성립 | 결과를 보정해서 0 이상으로 만든다 |
| 곱셈 | 성립 | `(a · b) mod m = ((a mod m) · (b mod m)) mod m` |
| 거듭제곱 | 성립 | 곱셈을 반복한 것 |
| 나눗셈 | 성립하지 않음 | 역원을 곱한다(아래 Modular Inverse) |
| 대소 비교 | 의미 없음 | 나머지끼리 비교한 결과는 원래 값의 대소와 무관 |

**문제의 단서:** "답을 1,000,000,007로 나눈 나머지", "998,244,353으로 나눈 값", 경우의 수가 지수적으로 커지는 세기 문제.

**흔한 실수:** 중간에 `Math.max`나 `<`로 mod 값을 비교하는 것입니다. 최댓값·최솟값을 구해야 하면 mod를 취하기 전의 값으로 비교합니다. 정확한 값이 Number 범위를 넘으면 BigInt를 씁니다(자세히는 02편).

## Mod 덧셈

mod 덧셈은 두 수를 더한 뒤 m으로 나눈 나머지를 구합니다. 두 값이 이미 `0 ≤ x < m`이면 합은 `2m`보다 작고, 한 번의 빼기로도 줄일 수 있습니다.

```js
const add = (a, b) => (a + b) % MOD
const sub = (a, b) => (a - b + MOD) % MOD
add(1000000006, 5)  // 4
sub(3, 10)          // 1000000000
```

- `a`, `b`가 `[0, MOD)`에 있으면 `a + b < 2e9 + 14`이고 이는 안전한 정수 범위(2^53 − 1) 안입니다.
- 뺄셈은 `a - b`가 음수일 수 있어서 `MOD`를 더한 뒤 `%`를 취합니다.
- 누적합은 한 번 더할 때마다 mod를 취합니다.

```js
let sum = 0
for (const x of arr) sum = (sum + x) % MOD
```

- 각 값이 10^9 미만이면 mod 없이도 약 900만 개까지는 정확하게 더할 수 있습니다(2^53 ÷ 10^9 ≈ 9.0 × 10^6). 그 이상이면 매번 mod를 취합니다.
- 입력값 `x`가 `MOD`보다 크거나 음수일 수 있으면 먼저 `mod(x)`로 줄인 뒤 더합니다.

**흔한 실수:** 마지막에 한 번만 mod를 취하면 되는 줄 알고 중간 결과를 그대로 쌓는 것입니다. 누적 값이 2^53을 넘는 순간부터 하위 자릿수가 조용히 틀립니다. 오류 없이 틀린 값이 나옵니다.

## Mod 곱셈

mod 곱셈은 두 수를 곱한 뒤 m으로 나눈 나머지를 구합니다. JavaScript에서는 곱의 크기가 문제입니다. Number는 2^53 − 1(약 9.007 × 10^15)까지만 정수를 정확히 담습니다(자세히는 02편).

```js
const MOD = 1000000007
const a = MOD - 1                   // 1000000006
const wrong = (a * a) % MOD         // 999999972 (틀림)
const right = Number(BigInt(a) * BigInt(a) % BigInt(MOD))
// 1 (맞음. (-1) × (-1) = 1)
```

`a * a`는 약 10^18이라서 이미 반올림된 값이 `%`로 들어갑니다. 에러 없이 틀린 값이 나옵니다.

곱이 안전한 범위에 들어가는 한계는 `(m - 1)^2 ≤ 2^53 − 1`입니다.

| 모듈러 | 곱 `a * b`와 `%`를 그대로 써도 되는가 |
|--------|---------------------------------------|
| `m ≤ 94,906,266` | 된다 (`(m−1)^2 ≤ 2^53 − 1`) |
| `m = 998,244,353` | 안 된다 |
| `m = 1,000,000,007` | 안 된다 |

소수 모듈러 997이나 10,007처럼 작은 모듈러는 그대로 곱해도 됩니다. 10^9 규모의 모듈러는 다음 절의 방법을 씁니다.

**흔한 실수:** 작은 입력으로 테스트해서 통과한 뒤 큰 입력에서 틀리는 것입니다. 값이 2^53을 넘기 전까지는 정상으로 보입니다.

## 2^53을 넘는 모듈러 곱셈 처리

곱이 2^53을 넘으면 두 가지로 처리합니다. BigInt로 계산하거나, 한쪽 수를 쪼개서 모든 중간 곱을 2^53 안에 두는 곱셈 분할입니다.

### BigInt로 곱하기

```js
const mulBig = (a, b, m) =>
  Number(BigInt(a) * BigInt(b) % BigInt(m))
mulBig(1000000006, 1000000006, 1000000007) // 1
```

- BigInt는 정밀도 제한이 없어서 m이 10^18이어도 정확합니다.
- BigInt와 Number를 섞어 연산하면 TypeError이므로 양쪽을 모두 `BigInt()`로 변환합니다. 변환 없이 `a * 2n`을 쓰는 실수가 많습니다.
- 변환과 BigInt 연산은 Number 연산보다 느립니다. 곱셈을 수백만 번 반복하는 코드에서 시간 초과의 원인이 될 수 있어서, `m < 2^31`이면 아래 곱셈 분할이 안전한 선택입니다.
- 모듈러 `m` 자체가 2^53을 넘는 문제는 값을 처음부터 BigInt로 들고 있어야 합니다(`BigInt(x)`에 Number를 줄 때 이미 반올림된 값은 복구되지 않습니다. 문자열로 읽어 `BigInt('...')`로 변환합니다).

### 곱셈 분할

한쪽 수를 15비트 단위로 쪼개서, 곱할 때마다 값이 2^47 아래에 머물게 합니다. `b = hi · 2^15 + lo`로 놓으면 `a · b = (a · hi) · 2^15 + a · lo`입니다.

```js
function mulmod(a, b, m) { // 0 ≤ a, b < m ≤ 2^31
  const hi = Math.floor(b / 32768)
  const lo = b % 32768
  return ((a * hi % m) * 32768 + a * lo) % m
}
mulmod(1000000006, 1000000006, 1000000007) // 1
```

- `a < 2^31`, `hi < 2^16`, `lo < 2^15`이므로 `a * hi < 2^47`, `a * lo < 2^46`입니다.
- `(a * hi % m)`은 m보다 작아서 `* 32768`을 해도 `2^46` 아래이고, 두 항의 합은 `2^47` 아래입니다. 모두 안전한 정수입니다.
- 조건은 `a`, `b`가 0 이상이고 m 미만이며 `m ≤ 2^31`인 것입니다. `1,000,000,007`과 `998,244,353`이 이 범위에 들어갑니다.
- `m`이 2^31을 넘으면 조각 수를 늘리거나 BigInt를 씁니다.
- `b / 32768` 대신 `b >> 15`를 쓰면 b가 2^31 이상일 때 부호가 바뀌므로 `Math.floor`를 씁니다(`>>>`는 2^32 미만에서 가능). 비트 연산이 32비트 정수로 변환하는 규칙은 02편에서 다룹니다.

이 문서의 이후 코드는 모두 위의 `mulmod`를 씁니다. 모듈러가 작으면 `(a * b) % m`으로 바꿔도 됩니다.

**흔한 실수:** `a * b % m`에서 곱이 먼저 계산되므로 `%`를 곱 바깥에서만 취하는 것입니다. 곱하기 전에 줄이는 것이 아니라, 곱이 2^53 안에 있게 만드는 것이 핵심입니다.

## 빠른 거듭제곱

빠른 거듭제곱(binary exponentiation)은 a^e를 O(log e)번의 곱셈으로 계산하는 방법입니다. 지수를 반으로 쪼개는 분할 정복의 일종입니다(자세히는 25편).

- `e`가 짝수이면 `a^e = (a^(e/2))^2`입니다.
- `e`가 홀수이면 `a^e = a · a^(e−1)`입니다.

반복문으로 쓰면 지수를 이진수로 보고, 비트가 1인 자리마다 결과에 밑을 곱합니다.

```js
function powmod(base, e, m) {
  let result = 1 % m
  base %= m
  while (e > 0) {
    if (e % 2 === 1) result = mulmod(result, base, m)
    base = mulmod(base, base, m)
    e = Math.floor(e / 2)
  }
  return result
}
powmod(3, 13, 1000) // 323
```

`3^13 mod 1000`을 추적하면 13은 이진수 1101입니다.

| 단계 | e | base | result(곱하기 전) | e가 홀수 |
|------|---|------|------------------|----------|
| 1 | 13 | 3 | 1 | 예, result = 3 |
| 2 | 6 | 9 | 3 | 아니오 |
| 3 | 3 | 81 | 3 | 예, result = 243 |
| 4 | 1 | 561 | 243 | 예, result = 323 |

각 단계에서 `base`는 3, 3^2, 3^4, 3^8을 1000으로 줄인 값이고, 비트가 1인 자리(3, 3^4, 3^8)만 결과에 곱해집니다. 3^8 = 6561이므로 단계 4의 base는 561입니다.

- 곱셈 횟수는 `2 · log2(e)` 이하이고, 시간은 O(log e)입니다. e가 10^18이어도 약 60회입니다.
- `result = 1 % m`으로 시작해 `m = 1`일 때 결과가 0이 되게 합니다.
- `e % 2`와 `Math.floor(e / 2)`는 2^53 미만의 e에서 정확합니다. `e >> 1`은 2^31 이상에서 틀립니다.
- 지수가 10^18처럼 2^53을 넘으면 `e`를 BigInt로 받아 `e % 2n === 1n`, `e /= 2n`으로 바꿉니다. 지수의 `/`는 BigInt에서 0 방향으로 잘립니다.
- 모듈러 m이 소수 p이고 a가 p의 배수가 아니면 `a^(p−1) ≡ 1`(페르마의 소정리)이라서 지수를 `e mod (p − 1)`로 줄일 수 있습니다. 소수가 아니거나 a가 p의 배수이면 줄이면 안 됩니다.
- 재귀로도 쓸 수 있고, 깊이는 log e이므로 호출 스택 걱정은 없습니다.

```js
const pw = (b, e, m) => {
  if (e === 0) return 1 % m
  const h = pw(b, Math.floor(e / 2), m)
  const sq = mulmod(h, h, m)
  return e % 2 === 1 ? mulmod(sq, b % m, m) : sq
}
```

**문제의 단서:** "N이 10^18", 경우의 수가 `k^n` 꼴, 분수의 거듭제곱, 역원을 구해야 하는 모든 문제의 부품입니다. 곱셈을 e번 반복하는 반복문은 e가 크면 시간 초과입니다.

**흔한 실수:** `Math.pow(a, e) % m`과 `a ** e % m`입니다. 거듭제곱 결과가 먼저 Number로 계산되어 2^53을 넘으면 반올림되고, `e`가 크면 `Infinity`가 됩니다. 반드시 매 단계 mod를 취합니다.

## Modular Inverse

모듈러 역원(modular inverse)은 `a · x ≡ 1 (mod m)`을 만족하는 x입니다. mod에서 나눗셈을 대신합니다. `a / b mod m`은 `a · b^(−1) mod m`입니다. `(a / b) % m`으로 먼저 나누면 안 됩니다. 정수 나눗셈이 아니라 소수가 나오고, mod의 나눗셈은 이 방식으로만 정의됩니다.

- 역원은 `gcd(a, m) = 1`일 때만 존재합니다. 소수 m이면 `a`가 m의 배수가 아닌 모든 수가 가능합니다.
- 역원은 `0 ≤ x < m`에서 유일합니다.

### 페르마의 소정리

m이 소수 p이면 `a^(p−1) ≡ 1`이므로 역원은 `a^(p−2)`입니다.

```js
const inv = (a) => powmod(mod(a), MOD - 2, MOD)
inv(2)                  // 500000004 (곱하면 1000000008 ≡ 1)
mulmod(inv(3), 3, MOD)  // 1
```

- 시간은 O(log MOD)입니다. 역원이 몇 개 필요한 문제에서 가장 간단한 방법입니다.
- 모듈러가 소수가 아니면 쓰지 못합니다.
- `a`가 0이거나 MOD의 배수이면 역원이 없습니다. 이때 `inv`는 0을 돌려주고, 에러가 나지 않으므로 호출 전에 확인합니다.

### 확장 유클리드

`gcd(a, m) = 1`이면 `a·x + m·y = 1`의 x를 구해 mod로 보정한 값이 역원입니다. 모듈러가 소수가 아닐 때 이 방법을 씁니다(자세히는 76편).

### 1부터 n까지의 역원을 한 번에

모듈러가 소수이고 n이 MOD보다 작을 때, 점화식으로 모든 역원을 O(n)에 구합니다.

```js
const invs = new Array(n + 1).fill(0)
invs[1] = 1
for (let i = 2; i <= n; i++) {
  const q = Math.floor(MOD / i)
  invs[i] = mulmod(MOD - q, invs[MOD % i], MOD)
}
```

- 식은 `inv[i] = −⌊m/i⌋ · inv[m mod i] (mod m)`이고, `m mod i < i`라서 이미 구한 값을 씁니다.
- 역원이 n개 필요하면 각각 `powmod`를 부르는 O(n log MOD)보다 빠릅니다.

**흔한 실수:** 모듈러가 소수인지 확인하지 않고 페르마를 쓰는 것입니다. 998,244,353과 1,000,000,007은 소수이지만 1,000,000,000이나 10^9 + 6은 아닙니다. 문제에 "소수"로 적혀 있지 않으면 소수라고 가정하지 않습니다.

## 큰 수 조합

조합 `C(n, r) = n! / (r! (n−r)!)`을 mod로 구하려면 나눗셈이 필요합니다. 팩토리얼과 팩토리얼의 역원을 미리 계산해 두면 쿼리마다 곱셈 두 번으로 답이 나옵니다(조합의 정의와 파스칼 삼각형은 56편).

```js
function build(n) {
  const fact = [1]
  const invFact = new Array(n + 1)
  for (let i = 1; i <= n; i++)
    fact[i] = mulmod(fact[i - 1], i, MOD)
  invFact[n] = powmod(fact[n], MOD - 2, MOD)
  for (let i = n; i >= 1; i--)
    invFact[i - 1] = mulmod(invFact[i], i, MOD)
  return { fact, invFact }
}
```

- `invFact[n]`만 거듭제곱으로 구하고, 나머지는 `inv((i−1)!) = inv(i!) · i`로 내려가며 채웁니다. 전체가 O(n + log MOD)입니다.
- 이 방법은 `n < MOD`일 때만 성립합니다. n이 MOD 이상이면 `n!`이 MOD의 배수가 되어 역원이 없습니다. 그런 입력은 뤼카 정리 같은 다른 방법이 필요합니다.

```js
const { fact, invFact } = build(1000)
function C(n, r) {
  if (r < 0 || r > n) return 0
  const t = mulmod(fact[n], invFact[r], MOD)
  return mulmod(t, invFact[n - r], MOD)
}
C(5, 2)      // 10
C(1000, 500) // 159835829
```

- `r < 0` 또는 `r > n`이면 0을 돌려줍니다. 배열 범위를 벗어나면 `undefined`가 되어 `NaN`이 번집니다.
- 한 번만 구하는 `C(n, r)`이고 `r`이 작으면 `fact` 전체 대신 `n·(n−1)···(n−r+1)`과 `r!`의 역원만 써도 됩니다.
- 입력 n이 작고(수천 이하) 쿼리가 많을 때는 파스칼 삼각형 `C[i][j] = C[i−1][j−1] + C[i−1][j]`에 mod 덧셈만 쓰는 방식이 더 간단하고, 역원도 필요하지 않습니다. n이 10^5–10^6이면 팩토리얼 방식을 씁니다.

**문제의 단서:** "N개 중 R개를 고르는 경우의 수를 1,000,000,007로 나눈 나머지", 쿼리가 최대 10^5개이고 N이 10^6.

**흔한 실수:** `fact[n] / (fact[r] * fact[n - r])`처럼 Number 나눗셈을 쓰는 것입니다. `fact` 값은 이미 mod가 적용된 값이라서 나눗셈 결과가 실수이거나 틀립니다. 반드시 역원을 곱합니다. 역원 배열을 만들 최대 N을 입력 범위로 정확히 잡지 않아서 인덱스를 벗어나는 오류도 자주 납니다.

## 핵심 정리

- JavaScript의 `%`는 피제수의 부호를 따르므로 음수가 나올 수 있는 식은 `((a % m) + m) % m`으로 보정합니다.
- mod는 덧셈·뺄셈·곱셈·거듭제곱에서 성립하고, 나눗셈은 역원을 곱해서 구하며, 나머지끼리의 대소 비교는 의미가 없습니다.
- 곱이 2^53 − 1을 넘으면 에러 없이 틀립니다. `m ≤ 2^31`이면 15비트 곱셈 분할로, 그 이상이면 BigInt로 곱합니다.
- 빠른 거듭제곱은 지수를 이진수로 보며 O(log e)번 곱하고, 모든 곱셈에 mod를 적용합니다.
- 소수 모듈러의 역원은 `a^(m−2)`이고, 소수가 아니면 확장 유클리드를 씁니다.
- 큰 조합은 팩토리얼과 팩토리얼 역원 배열을 미리 만들어 `fact[n] · invFact[r] · invFact[n−r]`로 구하며 `n < MOD`가 조건입니다.
