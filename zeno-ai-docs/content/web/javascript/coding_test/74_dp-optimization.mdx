## DP 최적화

DP 최적화는 DP의 풀이 시간을 줄이는 방법의 총칭이고, 대부분 "각 상태에서 시도하는 전이 후보의 수"를 줄입니다. DP의 시간은 상태 수 × 상태당 전이 수입니다. 상태 수가 10^5인데 전이를 모두 보면 O(n^2)이라서 시간 초과이고, 이때 전이를 O(1)이나 O(log n)로 줄입니다.

점화식의 모양에 따라 쓸 수 있는 방법이 정해집니다.

| 기법 | 점화식의 모양 | 필요한 조건 | 시간 |
|------|----------------|-------------|------|
| 롤링 배열 | 한 층이 바로 앞 층만 참조 | 없음 | 공간만 줄어듦 |
| 누적합 | 전이 비용이 구간 합 | 합을 O(1)에 구함 | 전이 O(1) |
| 단조 큐 | 후보 창 안에서 j만의 값의 최솟값 | 창이 한 방향으로 밀림 | O(n) |
| Convex Hull Trick | 비용에 j의 값과 i의 값의 곱이 있음 | 직선으로 바꿀 수 있음 | O(n) 또는 O(n log n) |
| Divide and Conquer | 층마다 `dp[i][j]`가 `dp[i-1][k]`와 `C(k, j)`로 결정 | 최적 k가 j에 따라 단조 증가 | O(K · n log n) |
| Knuth | 구간 `dp[i][j]`를 분할 지점 k로 결정 | 사각 부등식 등 | O(n^2) |

- 롤링 배열은 시간이 아니라 메모리를 줄입니다. 2차원 `dp[i][j]`에서 `i`번 줄이 `i-1`번 줄만 쓰면 배열 두 줄이나 한 줄로 충분합니다(자세히는 41편).
- 누적합으로 전이 비용을 O(1)에 구하는 방법은 42편에서 다뤘습니다.
- 위 조건은 점화식의 모양만 보고 판단하지 않고, 비용 함수의 성질(단조성, 볼록성)을 확인해야 합니다. 조건이 틀리면 에러 없이 틀린 답이 나옵니다.
- 최적화한 풀이는 먼저 느린 풀이를 구현해 두고 무작위 입력으로 결과를 비교합니다(자세히는 80편).

**문제의 단서:** N이 10^5 이상인데 "구간으로 나눈다", "그룹 K개로 나눈다", "이전 K칸 중에서 고른다"처럼 전이 후보가 많은 점화식. 최적화 이전의 O(n^2) 점화식을 먼저 쓰는 것이 출발점입니다.

**흔한 실수:** 모양이 비슷해 보인다고 최적화를 적용하는 것입니다. 각 기법은 조건(단조성, 사각 부등식)이 성립해야 정확합니다.

## 단조 큐를 이용한 최적화

단조 큐 최적화는 전이 후보가 "i 바로 앞 K개"처럼 한 방향으로 밀리는 창이고, 후보의 값이 j만으로 정해질 때 창의 최솟값(최댓값)을 단조 큐로 O(1)에 구하는 방법입니다. 단조 큐의 원리는 32편, 슬라이딩 윈도우는 31편에서 다룹니다.

점화식이 이런 모양이면 쓸 수 있습니다.

`dp[i] = min(dp[j]) + cost(i)`, j는 `i - K`부터 `i - 1`까지

`min` 안은 j만의 값이고 `cost(i)`는 i만의 값이라서 분리됩니다. 예: 0번 칸에서 시작해 한 번에 1칸부터 K칸까지 앞으로 가며, 칸 i에 도착할 때 `a[i]`를 내는 최소 비용 경로.

```js
function minJump(a, K) {
  const n = a.length, dp = new Array(n).fill(0)
  const q = [0] // 인덱스, dp 값이 증가
  let h = 0
  dp[0] = a[0]
  for (let i = 1; i < n; i++) {
    while (q[h] < i - K) h++ // 창 밖 제거
    dp[i] = dp[q[h]] + a[i]  // 앞이 창의 최솟값
    while (q.length > h && dp[q.at(-1)] >= dp[i]) q.pop()
    q.push(i)
  }
  return dp[n - 1]
}
minJump([2, 9, 1, 4, 3, 8, 1], 3) // 7
```

`a = [2, 9, 1, 4, 3, 8, 1]`, `K = 3`의 진행입니다. 덱에는 인덱스가 있습니다.

| i | `dp[i]` | 덱 (앞 → 뒤) |
|---|---------|--------------|
| 0 | 2 | 0 |
| 1 | 11 | 0, 1 |
| 2 | 3 | 0, 2 (11은 3보다 커서 제거) |
| 3 | 6 | 0, 2, 3 |
| 4 | 6 | 2, 4 (0은 창 밖, 3은 6 이상이라 제거) |
| 5 | 11 | 2, 4, 5 |
| 6 | 7 | 4, 6 (2는 창 밖) |

- 앞을 `h`로 옮겨 제거하므로 `shift`를 쓰지 않습니다(자세히는 20편, 86편). 덱이 비는 일이 없는 이유는 방금 넣은 `i - 1`이 항상 창 안에 있기 때문입니다(`K ≥ 1`).
- 정당성: 뒤쪽 후보 `j2`가 앞쪽 후보 `j1`보다 `dp` 값이 작거나 같으면 `j1`은 `j2`보다 먼저 창을 떠나므로 다시는 최솟값이 될 수 없습니다. 그래서 `dp` 값이 증가하는 순서로 덱을 유지합니다.
- 각 인덱스는 한 번 들어가고 한 번 나가서 전체 O(n)입니다. 모든 후보를 보면 O(nK)입니다.
- 최댓값이면 비교 방향을 반대로 합니다.
- 후보의 값이 `dp[j] + c[j]`처럼 j만의 식이면, 그 합을 덱에 올려 같은 방식으로 씁니다.
- 비용이 j와 i를 함께 쓰는 식(`(i - j)^2` 등)이면 j만의 값이 아니라서 쓸 수 없습니다. 그런 점화식은 CHT 등을 봅니다.

**문제의 단서:** "최대 K칸 점프", "연속된 K개 이내에서 고른다", 창의 최솟값이 점화식에 직접 나올 때.

**흔한 실수:** 창 경계의 off-by-one입니다. 후보가 `[i - K, i - 1]`이면 `i - K`보다 작은 인덱스를 제거합니다(`dq[h] < i - K`). 값 대신 인덱스를 저장하지 않으면 만료 여부를 알 수 없습니다.

## Convex Hull Trick 개요

Convex Hull Trick(CHT)은 `dp[i] = min over j (dp[j] + b[j] · a[i])`처럼 비용에 j와 i의 곱이 들어간 점화식을 직선 모음의 최솟값 질의로 바꿔 푸는 방법입니다. 각 j를 직선 `y = b[j] · x + dp[j]`로 보면 `dp[i]`는 `x = a[i]`에서 모든 직선 중 가장 낮은 값입니다. 가장 낮은 값을 이은 아래쪽 경계(lower envelope)만 있으면 되고, 경계에 못 드는 직선은 버립니다.

예: 수열을 연속한 구간으로 나눌 때 구간마다 `(구간 합)^2 + C`의 비용이 들면, 전체 비용의 최솟값. `S`는 누적합이라 구간 `(j, i]`의 합은 `S[i] - S[j]`입니다.

`dp[i] = min over j (dp[j] + (S[i] - S[j])^2 + C)`

식을 펼치면 j만 있는 항, i만 있는 항, 곱 항으로 나뉩니다.

`dp[i] = S[i]^2 + C + min over j (-2 · S[j] · S[i] + dp[j] + S[j]^2)`

- 직선 j: 기울기 `-2 · S[j]`, 절편 `dp[j] + S[j]^2`
- 질의: `x = S[i]`에서의 최솟값

`S`는 늘어나므로 직선을 추가하는 순서대로 기울기가 감소하고 질의 x는 증가합니다. 이 경우 직선을 덱에 담고 앞에서부터 쓸모없어진 직선을 버리면 전체가 O(n)입니다.

```js
const f = (l, x) => l.m * x + l.b // 직선 l의 x에서의 값
function bad(ln, l3) { // 마지막 직선 l2가 쓸모없으면 true
  const l1 = ln.at(-2), l2 = ln.at(-1)
  return (l3.b - l1.b) * (l1.m - l2.m) <=
         (l2.b - l1.b) * (l1.m - l3.m)
}
function advance(ln, h, x) { // 앞 직선이 더 낮은 동안 이동
  while (h + 1 < ln.length &&
         f(ln[h + 1], x) <= f(ln[h], x)) h++
  return h
}
```

`bad`는 새 직선 `l3`이 들어오면 `l1`과 `l3`의 교점이 `l1`과 `l2`의 교점보다 왼쪽이거나 같을 때 `l2`가 어떤 x에서도 최솟값이 못 된다는 것을 곱셈으로 비교합니다. 기울기가 모두 다르고 `l1.m > l2.m > l3.m`일 때 분모가 양수라서 부등호가 유지됩니다.

```js
function chtDp(a, C) {
  const S = [0]
  for (const x of a) S.push(S[S.length - 1] + x)
  const dp = [0], ln = [{ m: 0, b: 0 }]
  let h = 0
  for (let i = 1; i <= a.length; i++) {
    const x = S[i]
    h = advance(ln, h, x)
    dp[i] = f(ln[h], x) + x * x + C
    const nl = { m: -2 * x, b: dp[i] + x * x }
    while (ln.length - h > 1 && bad(ln, nl)) ln.pop()
    ln.push(nl)
  }
  return dp
}
```

`chtDp([3, 2, 4, 1], 5)`는 `[0, 14, 23, 44, 50]`입니다.

`a = [3, 2, 4, 1]`, `C = 5`이면 `S = [0, 3, 5, 9, 10]`입니다.

| i | x | 앞의 직선 | 값 | `dp[i]` |
|---|---|-----------|----|---------|
| 1 | 3 | j=0 (0, 0) | 0 | 0 + 9 + 5 = 14 |
| 2 | 5 | j=1 (-6, 23) | -7 | -7 + 25 + 5 = 23 |
| 3 | 9 | j=2 (-10, 48) | -42 | -42 + 81 + 5 = 44 |
| 4 | 10 | j=3 (-18, 125) | -55 | -55 + 100 + 5 = 50 |

괄호는 (기울기, 절편)입니다. 앞의 직선은 질의 x가 커질수록 기울기가 더 작은 직선으로 넘어가며, 한 번 앞에서 버린 직선은 다시 쓰이지 않습니다.

- 위 코드는 최솟값, 기울기 감소, 질의 x 증가인 경우입니다. 최댓값은 부호를 바꿔 같은 형태로 만듭니다.
- 기울기나 질의 순서가 한쪽으로만 정해지지 않으면 덱 앞의 포인터 이동이 성립하지 않습니다. 직선은 스택에 두고 질의를 이분 탐색으로 찾으면 O(n log n)입니다.
- 순서가 임의이거나 온라인 질의(입력을 읽으며 곧바로 답해야 함)이면 Li Chao tree를 씁니다. 구간 트리의 각 노드에 직선 하나를 두고, 새 직선과 저장된 직선을 구간의 중점에서 비교해 낮은 쪽을 노드에 남기고 교점이 있는 반쪽으로 내려갑니다. 직선 추가와 질의가 각각 O(log C)(C는 x 범위의 크기)이고, 두 함수가 최대 한 번 교차하기만 하면 직선이 아니어도 됩니다.
- `bad`의 곱은 절편 차이와 기울기 차이를 곱하므로 값이 커서 2^53을 넘을 수 있습니다. 그러면 에러 없이 틀리므로 BigInt로 비교하거나 Li Chao tree를 씁니다(자세히는 02편).
- 같은 기울기가 들어올 수 있으면 절편이 작은 쪽만 남기는 처리를 따로 해야 합니다.
- 구현이 복잡해 개요 수준으로 아는 것이 목적이며, 이 문서의 코드는 단조 조건을 만족하는 기본형입니다.

**문제의 단서:** 점화식을 펼쳤을 때 `dp[j]`와 `a[i] · b[j]` 형태의 곱 항이 보이는 경우, 구간 합의 제곱이나 `(i - j)`에 비례하는 비용, N이 10^5 이상.

**흔한 실수:** 기울기와 질의 순서의 단조성을 확인하지 않고 덱 방식을 쓰는 것입니다. 곱셈 비교에서 부호와 부등호 방향을 틀리는 것도 많아, 작은 입력에서 O(n^2) 풀이와 결과를 비교합니다.

## Divide and Conquer DP Optimization 개요

Divide and Conquer(D&C) 최적화는 층별 DP에서 "최적의 분할 지점이 j가 커질수록 줄지 않는" 성질을 이용해, 전이 후보를 재귀로 좁혀 계산하는 방법입니다. 다음 점화식을 대상으로 합니다.

`dp[g][j] = min over k (dp[g-1][k-1] + C(k, j))`, k는 1 이상 j 이하

`g`는 그룹 수(층), `C(k, j)`는 k부터 j까지를 한 그룹으로 묶는 비용이고 O(1)에 계산됩니다. 조건은 `opt(g, j)`(최적의 k)가 `opt(g, j) ≤ opt(g, j + 1)`을 만족하는 것입니다. 충분조건은 비용 함수의 사각 부등식(quadrangle inequality)입니다.

`C(a, c) + C(b, d) ≤ C(a, d) + C(b, c)`, `a ≤ b ≤ c ≤ d`

그룹 합의 제곱처럼 구간이 길수록 비용이 볼록하게 커지는 비용이 이 성질을 가집니다.

한 층을 계산하는 방법은 이렇습니다. 가운데 `mid`의 최적 지점 `bk`를 후보 `[optl, optr]` 전체에서 찾고, 왼쪽 절반 `[l, mid-1]`은 `[optl, bk]`에서, 오른쪽 절반 `[mid+1, r]`은 `[bk, optr]`에서만 찾습니다.

```js
function layer(prev, cur, g, n, cost) {
  const solve = (l, r, optl, optr) => {
    if (l > r) return
    const mid = (l + r) >> 1
    let best = Infinity, bk = optl
    for (let k = optl; k <= Math.min(mid, optr); k++) {
      const v = prev[k - 1] + cost(k, mid)
      if (v < best) { best = v; bk = k }
    }
    cur[mid] = best
    solve(l, mid - 1, optl, bk)
    solve(mid + 1, r, bk, optr)
  }
  solve(g, n, g, n)
}
```

예: 수열을 연속한 K개 그룹으로 나눠 그룹 합의 제곱의 합을 최소로 합니다. `cost(k, j)`는 k번부터 j번까지(1부터 센 번호)를 한 그룹으로 한 비용입니다. `dp[1][j]`는 처음부터 j까지를 한 그룹으로 한 비용이고, 이후 층마다 `layer`를 부릅니다.

```js
function splitSquares(a, K) {
  const n = a.length, P = [0]
  for (const x of a) P.push(P[P.length - 1] + x)
  const cost = (k, j) => (P[j] - P[k - 1]) ** 2
  let prev = new Array(n + 1).fill(Infinity)
  for (let j = 1; j <= n; j++) prev[j] = cost(1, j)
  for (let g = 2; g <= K; g++) {
    const cur = new Array(n + 1).fill(Infinity)
    layer(prev, cur, g, n, cost)
    prev = cur
  }
  return prev[n]
}
```

`splitSquares([4, 1, 3, 2, 5], 2)`는 113입니다.

`[4, 1, 3, 2, 5]`를 2그룹으로 나눈 둘째 층에서 j마다 최적 k는 다음과 같고, k는 줄지 않습니다.

| j | 2 | 3 | 4 | 5 |
|---|---|---|---|---|
| 최적 k | 2 | 2 | 3 | 4 |
| `dp[2][j]` | 17 | 32 | 50 | 113 |

`j = 5`의 최적 k = 4는 `[4, 1, 3]`과 `[2, 5]`로 나눈 64 + 49 = 113입니다.

- 한 층을 `O(n log n)`에 계산합니다. 재귀가 약 log n 단계이고 각 단계에서 후보 범위가 겹치는 부분의 합이 O(n)이기 때문입니다. 전체 O(K · n log n)이고, 모든 후보를 보면 O(K · n^2)입니다.
- 재귀 깊이가 log n이라서 호출 스택 걱정이 없습니다.
- 층이 이전 층만 참조해야 합니다. 같은 층의 앞 값을 쓰면(1차원 점화식) 이 방법은 적용되지 않습니다.
- 값이 클 때 `cost`가 2^53을 넘는지 확인합니다. 합이 10^9 규모이면 제곱이 10^18이라 BigInt가 필요합니다.
- 최적 지점의 단조성을 검증하기 어려우면 느린 풀이와 비교해 확인합니다.

**문제의 단서:** "K개 그룹으로 나눈다"에서 K와 N이 모두 클 때(`K · N^2`이 너무 큼), 그룹 비용이 합의 제곱이나 거리의 제곱 같은 볼록 함수.

**흔한 실수:** 탐색 범위를 `k ≤ mid`로 자르지 않아 k가 mid보다 큰 잘못된 구간을 계산하는 것, 층 시작 j의 하한을 그룹 수(g)보다 작게 두는 것입니다. 한 그룹이 비어 있는 상태가 섞이지 않게 `j ≥ g`부터 계산합니다.

## Knuth 최적화 개요

Knuth 최적화는 구간 DP의 분할 지점 탐색 범위를 좁혀 O(n^3)을 O(n^2)으로 줄이는 방법입니다. 다음 점화식에 적용합니다.

`dp[i][j] = min over k (dp[i][k] + dp[k+1][j]) + C(i, j)`, k는 i 이상 j 미만

조건은 비용 `C`에 대한 두 가지이고, 둘이 성립하면 세 번째 성질이 따라옵니다.

- 사각 부등식: `a ≤ b ≤ c ≤ d`에서 `C(a, c) + C(b, d) ≤ C(a, d) + C(b, c)`
- 단조성: `a ≤ b ≤ c ≤ d`에서 `C(b, c) ≤ C(a, d)`
- 결과: 최적 분할 지점 `opt[i][j]`가 `opt[i][j-1] ≤ opt[i][j] ≤ opt[i+1][j]`

그래서 `k`를 `i`부터 `j - 1`까지 모두 보지 않고 `opt[i][j-1]`부터 `opt[i+1][j]`까지만 봅니다. 73편의 파일 합치기(`C(i, j)` = 구간 합)가 이 조건을 만족합니다.

```js
function bestSplit(dp, opt, i, j) {
  const lo = opt[i][j - 1]
  const hi = Math.min(j - 1, opt[i + 1][j])
  let best = Infinity, bk = lo
  for (let k = lo; k <= hi; k++) {
    const v = dp[i][k] + dp[k + 1][j]
    if (v < best) { best = v; bk = k }
  }
  return [best, bk]
}
```

```js
function mergeKnuth(a) {
  const n = a.length, pre = [0]
  for (const x of a) pre.push(pre[pre.length - 1] + x)
  const dp = [...Array(n)].map(() => Array(n).fill(0))
  const opt = [...Array(n)].map((_, i) => Array(n).fill(i))
  for (let len = 2; len <= n; len++) {
    for (let i = 0; i + len <= n; i++) {
      const j = i + len - 1
      const [best, bk] = bestSplit(dp, opt, i, j)
      dp[i][j] = best + pre[j + 1] - pre[i]
      opt[i][j] = bk
    }
  }
  return dp[0][n - 1]
}
```

`mergeKnuth([40, 30, 30, 50])`은 73편의 `merge`와 같은 300이고, `[40, 30, 30, 50]`에서 시도하는 k의 범위는 이렇습니다.

| 구간 | 시도하는 k | 최적 k | `dp` |
|------|------------|--------|------|
| `[0,1]` | 0 | 0 | 70 |
| `[1,2]` | 1 | 1 | 60 |
| `[2,3]` | 2 | 2 | 80 |
| `[0,2]` | 0–1 | 0 | 160 |
| `[1,3]` | 1–2 | 2 | 170 |
| `[0,3]` | 0–2 | 1 | 300 |

- 길이가 같은 구간들에서 각 구간이 보는 후보 수는 `opt[i+1][j] - opt[i][j-1] + 1`이고, i에 대해 더하면 대부분의 항이 서로 지워져(telescoping) O(n)입니다. 길이가 n가지이므로 전체 O(n^2)입니다.
- 초깃값은 `opt[i][i] = i`입니다. `i + 1`번 줄을 읽어야 해서 구간 길이순으로 채웁니다.
- 위 `hi`에 `j - 1`로 상한을 두어야 `dp[k+1][j]`에서 `k + 1 > j`인 칸을 읽지 않습니다.
- 모든 구간 DP에 적용되는 것은 아닙니다. 사각 부등식이 성립하는지 증명하거나 느린 풀이와 비교해 확인해야 합니다.
- n이 수천인 문제에서 O(n^2)이 필요할 때 씁니다. `dp`와 `opt`가 n × n 표라서 메모리가 크므로 `Int32Array` 한 덩어리로 두는 것을 고려합니다(자세히는 14편).

**문제의 단서:** 구간을 합치거나 쪼개는 DP이고 n이 수천(O(n^3)은 불가능, O(n^2)은 가능), 합치는 비용이 구간 합 같은 단조 함수.

**흔한 실수:** 점화식이 같은 구간 DP여도 비용이 `C(i, j)`가 아닌 다른 꼴이면 조건이 성립하지 않는데 적용하는 것입니다. 후보 범위의 상한 `j - 1`을 빼먹는 것도 자주 합니다.

## 핵심 정리

- DP 최적화는 상태 수와 전이 수 중 전이 수를 줄이는 방법이고, 점화식의 모양과 비용 함수의 성질에 따라 기법이 정해집니다.
- 후보가 밀리는 창이고 j만의 값이면 단조 큐로 O(n)이며 인덱스를 저장해 만료를 검사합니다.
- 비용에 j와 i의 곱이 있으면 직선의 최솟값 질의로 바꾸는 CHT를 쓰고, 기울기와 질의가 단조이면 덱으로 O(n), 아니면 O(n log n)이나 Li Chao tree입니다. 곱셈 비교는 2^53을 넘기 쉽습니다.
- D&C 최적화는 `opt(g, j)`가 단조일 때 재귀로 후보를 좁혀 층마다 O(n log n)이고 전체 O(K · n log n)입니다.
- Knuth 최적화는 사각 부등식과 단조성이 성립하는 구간 DP에서 k의 범위를 `opt[i][j-1]`부터 `opt[i+1][j]`로 좁혀 O(n^2)입니다.
- 어떤 최적화든 조건이 틀리면 에러 없이 틀린 답이 나오므로 O(n^2) 풀이와 비교합니다.
