## Priority Queue 구현

우선순위 큐(priority queue)는 원소마다 우선순위가 있고, 넣은 순서가 아니라 우선순위가 가장 높은 원소부터 꺼내는 자료구조입니다. 필요한 연산은 세 가지입니다.

| 연산 | 하는 일 |
|------|---------|
| 삽입(push) | 원소를 넣는다 |
| 확인(peek) | 우선순위가 가장 높은 원소를 보기만 한다 |
| 추출(pop) | 우선순위가 가장 높은 원소를 꺼내 반환한다 |

내부를 어떻게 만드느냐에 따라 비용이 달라집니다.

| 구현 | 삽입 | 추출 |
|------|------|------|
| 정렬하지 않은 배열 | O(1) | O(N) (전체를 훑어 최솟값 탐색) |
| 정렬된 배열 | O(N) (끼워 넣기) | O(1) (끝에서 꺼내기) |
| 이진 힙 | O(log N) | O(log N) |

- 삽입과 추출이 번갈아 N번씩 일어나면 배열 방식은 O(N²), 힙은 O(N log N)입니다.
- 코딩테스트의 우선순위 큐는 거의 항상 이진 힙입니다(힙은 46편).
- JavaScript의 표준 내장 객체에는 힙이나 우선순위 큐가 없습니다(MDN 표준 내장 객체 목록 기준). 배열과 함수로 직접 구현해서 풀이 코드에 붙입니다.

46편의 `push`, `pop` 함수(최소 힙, 배열 `a`를 받음)를 클래스로 묶으면 다음과 같습니다.

```js
class PQ {
  constructor() { this.a = [] }
  get size() { return this.a.length }
  peek() { return this.a[0] }
  push(v) { push(this.a, v) }
  pop() { return pop(this.a) }
}
const q = new PQ()
q.push(5); q.push(2); q.push(8)
q.pop() // 2 (가장 작은 값이 먼저)
q.pop() // 5
```

숫자만 비교하는 최소 힙이라서 "가장 작은 숫자부터"만 처리합니다. 쌍이나 객체를 담거나 큰 값부터 꺼내려면 비교 기준을 바꿔야 합니다.

**흔한 실수:** 우선순위 큐를 "넣은 순서대로 나오는 큐"로 착각하는 것입니다. 우선순위가 같은 원소끼리의 꺼내는 순서는 힙이 보장하지 않습니다(아래 비교 함수 절).

## Priority Queue Comparator

비교 함수(comparator)는 두 원소 `a`, `b`를 받아 누가 먼저 나와야 하는지 숫자로 알려 주는 함수입니다. `Array.prototype.sort`의 비교 함수와 같은 약속을 씁니다. 음수면 `a`가 먼저, 양수면 `b`가 먼저, 0이면 같은 순위입니다(정렬 비교 함수는 26편).

```js
const minFirst = (a, b) => a - b        // 작은 값이 먼저 (최소 힙)
const maxFirst = (a, b) => b - a        // 큰 값이 먼저 (최대 힙)
const byDist = (a, b) => a[0] - b[0]    // [거리, 정점] 쌍
const byAge = (a, b) => a.age - b.age   // 객체의 age 기준
```

- 힙은 "`cmp(a, b)`가 음수인 쪽이 루트에 가깝다"는 규칙으로 동작합니다. 같은 클래스에 비교 함수만 바꿔 끼우면 최소 힙, 최대 힙, 쌍 기준 힙이 모두 만들어집니다.
- 기준이 여럿이면 앞 기준이 같을 때 다음 기준으로 넘어갑니다.

```js
// 비용 오름차순, 같으면 번호 오름차순
const cmp = (a, b) => a.cost - b.cost || a.id - b.id
```

- `a.cost - b.cost`가 0이면 `||` 뒤의 식이 결과가 됩니다.
- 입력 순서(FIFO)를 지켜야 하는 우선순위 큐는 push할 때 증가하는 번호를 함께 담고, 우선순위가 같을 때 그 번호로 비교합니다.

**흔한 실수:**

- 뺄셈 비교 함수에 `Infinity`가 섞이는 것입니다. `Infinity - Infinity`는 `NaN`이라서 비교 결과가 틀어집니다. 값에 `Infinity`가 있을 수 있으면 `a < b ? -1 : a > b ? 1 : 0`으로 씁니다.
- 힙에 들어 있는 객체의 우선순위 필드를 바꾸는 것입니다. 힙은 push·pop 때만 자리를 정리하므로 바깥에서 값을 바꾸면 힙 성질이 조용히 깨집니다. 우선순위를 바꾸고 싶으면 새 값으로 다시 push하고 옛 항목은 나중에 걸러 냅니다(지연 삭제 절).
- 비교 함수가 일관되지 않은 것입니다. `cmp(a, b)`와 `cmp(b, a)`의 부호가 반대여야 합니다. `(a, b) => a > b`처럼 불리언을 반환하면 `true`는 1, `false`는 0이라서 음수가 나오지 않고 순서가 틀립니다.

## Heap Class 템플릿

앞의 내용을 합친, 비교 함수를 받는 힙 클래스입니다. 풀이 코드에 그대로 복사해 씁니다. 뼈대(생성자, push, pop)입니다.

```js
class Heap {
  constructor(cmp = (a, b) => a - b) {
    this.a = []; this.cmp = cmp   // 음수면 a가 루트에 가까움
  }
  get size() { return this.a.length }
  peek() { return this.a[0] }
  push(v) {
    this.a.push(v)
    this._up(this.a.length - 1)
  }
  pop() {
    const a = this.a, top = a[0], last = a.pop()
    if (a.length) { a[0] = last; this._down(0) }
    return top
  }
```

클래스 안에 이어지는 `_up`(위로 올리기, 46편의 Bubble Up)입니다.

```js
  _up(i) {
    const a = this.a, c = this.cmp
    while (i > 0) {
      const p = (i - 1) >> 1
      if (c(a[i], a[p]) >= 0) break
      ;[a[i], a[p]] = [a[p], a[i]]
      i = p
    }
  }
```

이어서 `_down`(아래로 내리기, Bubble Down)과 배열에서 한 번에 만드는 정적 메서드입니다.

```js
  _down(i) {
    const a = this.a, c = this.cmp, n = a.length
    for (;;) {
      let m = i
      const l = 2 * i + 1, r = l + 1
      if (l < n && c(a[l], a[m]) < 0) m = l
      if (r < n && c(a[r], a[m]) < 0) m = r
      if (m === i) break
      ;[a[i], a[m]] = [a[m], a[i]]
      i = m
    }
  }
```

```js
  static from(arr, cmp) {     // heapify O(N)
    const h = new Heap(cmp)
    h.a = arr.slice()
    const n = h.a.length
    for (let i = (n >> 1) - 1; i >= 0; i--) h._down(i)
    return h
  }
}                              // class 끝
```

사용 예입니다.

```js
const minH = new Heap()                       // 최소 힙
const maxH = new Heap((a, b) => b - a)        // 최대 힙
const pairH = new Heap((a, b) => a[0] - b[0]) // 쌍 기준
const h = Heap.from([4, 1, 3, 2])             // O(N) 생성
h.pop() // 1
```

- 기본 비교 함수는 숫자용(`a - b`)입니다. 문자열은 `(a, b) => (a < b ? -1 : a > b ? 1 : 0)`으로 바꿉니다.
- `pop`은 빈 힙에서 `undefined`를 반환합니다. 꺼내기 전에 `size`를 확인합니다.

## Heap 활용 문제

문장에서 아래 단서가 보이면 우선순위 큐를 떠올립니다.

| 문제의 단서 | 힙에 담는 것 |
|-------------|--------------|
| "가장 작은(큰) 것을 반복해서 꺼낸다", 꺼낸 뒤 새 값이 들어온다 | 값 |
| 현재 가능한 것 중 최선을 매번 고른다(그리디) | 후보 |
| K번째로 큰·작은 값, 상위 K개 | 크기 K의 힙 |
| 데이터가 계속 들어오는 중에 중앙값 | 두 개의 힙 |
| 가장 가까운 정점을 확정하며 퍼진다 | `[거리, 정점]` 쌍(Dijkstra, 48편) |
| 시간 순으로 자원을 쓰고 반납한다 | 반납 시각 |

직접 만든 문제 둘로 패턴을 익힙니다.

**회의실 수.** 회의가 `[시작, 끝)` 구간으로 주어질 때 필요한 최소 회의실 수를 구합니다. 시작 시각 순으로 보면서, 사용 중인 회의실 가운데 가장 먼저 끝나는 방이 새 회의 시작 전에 끝났다면 그 방을 재사용합니다. 가장 먼저 끝나는 값만 필요하므로 끝 시각의 최소 힙입니다(구간은 34편, 이벤트 정렬 방식은 55편).

```js
function minRooms(meetings) {
  const sorted = [...meetings].sort((x, y) => x[0] - y[0])
  const ends = new Heap()               // 사용 중인 방의 끝 시각
  for (const [s, e] of sorted) {
    if (ends.size && ends.peek() <= s) ends.pop() // 방 재사용
    ends.push(e)
  }
  return ends.size                      // 동시에 쓰이는 방의 수
}
minRooms([[0, 30], [5, 10], [15, 20]]) // 2
minRooms([[0, 5], [5, 10]])            // 1 (끝=시작이면 재사용)
```

**마감이 있는 작업.** 작업마다 `[마감일, 보상]`이 있고 하루에 하나만 처리할 때 얻을 수 있는 보상의 최대 합입니다. 마감일 순으로 보면서 보상을 힙에 넣고, 처리할 수 있는 개수(마감일)를 넘으면 가장 작은 보상을 버립니다(그리디는 33편).

```js
function maxReward(jobs) {
  const h = new Heap()                  // 고른 작업의 보상
  const byDeadline = [...jobs].sort((x, y) => x[0] - y[0])
  for (const [d, p] of byDeadline) {
    h.push(p)
    if (h.size > d) h.pop()             // 가장 작은 보상을 버림
  }
  let sum = 0
  while (h.size) sum += h.pop()
  return sum
}
maxReward([[2, 10], [1, 5], [2, 7], [3, 4]]) // 21
```

마감일이 2 이하인 작업은 셋(보상 5, 10, 7)인데 하루 두 개까지만 처리할 수 있어서 가장 작은 보상 5가 버려지고, 마감일 3인 작업(4)이 더해져 10 + 7 + 4 = 21이 됩니다.

- 두 풀이 모두 정렬 O(N log N)에 힙 연산 N번(O(log N))이 더해져 전체 O(N log N)입니다.
- 힙은 "지금까지 본 것 중 가장 불리한 것을 버리고, 남긴 것의 합을 유지"하는 도구로 자주 쓰입니다.

**흔한 실수:** 힙이 정렬된 배열이라고 착각해 `h.a`를 앞에서부터 읽는 것입니다. 힙의 내부 배열은 정렬 순서가 아닙니다. 순서대로 얻으려면 `pop`으로 꺼냅니다.

## K개 최댓값 / 최솟값

K번째로 큰 값이나 상위 K개를 구할 때는 크기가 K로 제한된 힙을 씁니다. 큰 쪽 K개를 구하려면 **최소 힙**을 쓰고, 크기가 K를 넘으면 루트(가장 작은 값)를 버립니다. 끝나면 힙에 가장 큰 K개가 남고, 루트가 K번째로 큰 값입니다.

```js
function kthLargest(arr, k) {
  const h = new Heap()                  // 최소 힙, 크기 k 유지
  for (const v of arr) {
    h.push(v)
    if (h.size > k) h.pop()             // 가장 작은 값을 버림
  }
  return h.peek()
}
kthLargest([3, 9, 4, 1, 7], 2) // 7
```

진행 과정입니다(`k = 2`).

| 읽은 값 | 힙(작은 값이 루트) | 처리 |
|---------|--------------------|------|
| 3 | 3 | - |
| 9 | 3, 9 | - |
| 4 | 4, 9 | 크기 3이 되어 가장 작은 3을 버림 |
| 1 | 4, 9 | 1을 넣고 바로 1을 버림 |
| 7 | 7, 9 | 4를 버림, 루트 7이 두 번째로 큰 값 |

- 반대로 작은 쪽 K개(K번째로 작은 값)는 **최대 힙**을 쓰고 크기가 K를 넘으면 가장 큰 값을 버립니다. 버려야 하는 쪽이 루트에 오도록 반대 힙을 고른다고 기억하면 됩니다.
- 시간은 O(N log K)이고 보조 공간은 O(K)입니다. 전체를 정렬하는 O(N log N)보다 K가 작을 때 유리하고, 데이터가 한 번에 다 메모리에 없는 스트림에서도 쓸 수 있습니다.
- 한 번에 배열이 있다면 O(N) 평균의 퀵 선택(27편)도 있습니다. K가 N에 가까우면 정렬이 간단합니다.
- 힙의 내용을 전부 얻으면 상위 K개입니다. `pop`으로 꺼내면 작은 것부터 나오므로 뒤집어서 큰 순서로 만듭니다.
- 빈도 기준 상위 K개는 값별 개수를 `Map`으로 센 뒤(10편) `[개수, 값]` 쌍을 같은 방식으로 힙에 넣습니다.

| 구하려는 것 | 힙 종류 | 크기 K 초과 시 버리는 값 |
|-------------|---------|--------------------------|
| K번째로 큰 값, 큰 K개 | 최소 힙 | 가장 작은 값 |
| K번째로 작은 값, 작은 K개 | 최대 힙 | 가장 큰 값 |

**흔한 실수:** 큰 K개를 구하면서 크기를 제한한 힙을 최대 힙으로 만드는 것입니다. 최대 힙에서 루트(큰 값)를 버리면 큰 K개가 아니라 작은 K개가 남습니다.

## 두 Heap을 이용한 중앙값

값이 하나씩 들어올 때마다 중앙값을 구하려면 값을 작은 절반과 큰 절반으로 나눠 두 힙에 담습니다. 중앙값은 두 절반의 경계에 있는 값입니다. 중앙값의 정의는 값 개수가 홀수면 가운데 값, 짝수면 가운데 두 값의 평균입니다.

- `lo`: 작은 절반을 담은 **최대 힙**. 루트가 작은 절반의 최댓값
- `hi`: 큰 절반을 담은 **최소 힙**. 루트가 큰 절반의 최솟값
- 불변 조건: `lo`의 모든 값은 `hi`의 모든 값 이하이고, `lo.size`는 `hi.size`와 같거나 하나 더 많다

```js
class MedianFinder {
  constructor() {
    this.lo = new Heap((a, b) => b - a)   // 최대 힙
    this.hi = new Heap()                  // 최소 힙
  }
  add(v) {
    this.lo.push(v)
    this.hi.push(this.lo.pop())  // 작은 쪽 최댓값을 큰 쪽으로
    if (this.hi.size > this.lo.size) {
      this.lo.push(this.hi.pop()) // 크기 균형 복구
    }
  }
```

클래스 안에 이어지는 `median`입니다.

```js
  median() {
    const { lo, hi } = this
    if (lo.size > hi.size) return lo.peek()
    return (lo.peek() + hi.peek()) / 2
  }
}
```

`5, 2, 9, 1`을 차례로 넣는 과정입니다.

| 넣은 값 | lo (작은 절반) | hi (큰 절반) | 중앙값 |
|---------|----------------|--------------|--------|
| 5 | 5 | - | 5 |
| 2 | 2 | 5 | (2 + 5) / 2 = 3.5 |
| 9 | 2, 5 | 9 | 5 |
| 1 | 1, 2 | 5, 9 | (2 + 5) / 2 = 3.5 |

- `add`는 먼저 `lo`에 넣고 그 최댓값을 `hi`로 옮깁니다. 이 두 단계로 새 값이 어느 쪽에 속하든 `lo`의 모든 값이 `hi`의 모든 값 이하라는 조건이 유지됩니다.
- 시간은 `add`가 O(log N), `median`이 O(1)입니다.
- 문제가 "가운데 두 값 중 작은 값"을 요구하면 짝수일 때도 `lo.peek()`을 반환합니다.
- 구간(슬라이딩 윈도우)의 중앙값은 오래된 값을 지워야 해서 한 힙에서 임의 값을 빼는 연산이 필요합니다. 아래 지연 삭제로 해결합니다.

**흔한 실수:**

- 새 값을 크기만 보고 한쪽에 바로 넣는 것입니다. 값의 크기 관계가 깨져서 경계 값이 중앙값이 아니게 됩니다.
- 짝수일 때 `/ 2`를 빼먹거나, 정수 나눗셈이 필요한 문제에서 소수가 나오는 것입니다. 문제의 요구 형식을 확인합니다.

## 지연 삭제

힙은 루트만 빠르게 꺼낼 수 있고, 중간에 있는 값을 지우려면 위치를 찾는 데 O(N)이 듭니다. 지연 삭제(lazy deletion)는 지울 값을 지금 지우지 않고 "삭제 예약"만 해 두었다가, 그 값이 루트에 올라왔을 때 버리는 방법입니다. 예약은 `Map`으로 값별 개수를 셉니다.

```js
class LazyHeap {
  constructor(cmp) {
    this.h = new Heap(cmp)
    this.del = new Map()      // 값 -> 삭제 예약 개수
    this.size = 0             // 실제 살아 있는 원소 수
  }
  push(v) { this.h.push(v); this.size++ }
  remove(v) {
    this.del.set(v, (this.del.get(v) ?? 0) + 1)
    this.size--
  }
```

이어지는 부분입니다. 루트에 예약된 값이 있으면 그 값을 버린 뒤 비로소 읽거나 꺼냅니다.

```js
  _clean() {
    const { h, del } = this
    while (h.size && del.get(h.peek())) {
      del.set(h.peek(), del.get(h.peek()) - 1)
      h.pop()                 // 예약된 값을 이제 버린다
    }
  }
  peek() { this._clean(); return this.h.peek() }
  pop() { this._clean(); this.size--; return this.h.pop() }
}
```

```js
const q = new LazyHeap((a, b) => b - a)   // 최대 힙
;[5, 3, 5, 1].forEach((v) => q.push(v))
q.remove(5)    // 5 하나를 삭제 예약, q.size는 3
q.peek()       // 5 (두 개 중 하나가 버려지고 하나가 남음)
```

- 예약만 하는 `remove`는 O(1)이고, 실제로 버리는 비용은 `_clean`이 `pop`할 때 한 번씩 치릅니다. 원소가 한 번만 버려지므로 전체는 O(N log N)입니다.
- `size`를 따로 세는 이유는 힙 안에 예약된 원소가 남아 있어서 `h.size`가 실제 개수와 다르기 때문입니다.
- 이 방식은 값이 힙에 실제로 들어 있다는 전제가 필요합니다. 없는 값을 `remove`하면 `size`가 틀립니다. 두 힙을 쓸 때는 지울 값이 어느 쪽 힙에 있는지 구분해서 그 힙에서 지웁니다.
- 같은 값이 여럿일 수 있어서 `Set`이 아니라 개수를 세는 `Map`을 씁니다. 객체를 담는다면 고유 번호(id)를 예약 키로 씁니다.
- 우선순위가 바뀐 항목은 옛 항목을 예약해 버리고 새 우선순위로 다시 `push`하면 됩니다. 힙에는 값의 우선순위를 줄이는 연산이 없으므로 이 방식으로 대신합니다. 최단거리 알고리즘이 같은 원리를 씁니다(Dijkstra는 48편).

**흔한 실수:** 예약만 하고 `size`나 `peek`에서 `_clean`을 부르지 않는 것입니다. 이미 지운 값을 최댓값으로 읽게 됩니다.

## 이중 우선순위 큐

이중 우선순위 큐(double-ended priority queue)는 최솟값과 최댓값을 모두 꺼낼 수 있는 큐입니다. 힙 하나로는 한쪽 끝만 빠르게 꺼낼 수 있어서, 최소 힙과 최대 힙을 하나씩 두고 같은 원소를 양쪽에 넣습니다. 한쪽에서 꺼낸 원소는 다른 쪽 힙에 남아 있으므로 지연 삭제로 처리합니다.

원소마다 고유 번호(id)를 붙이고, 이미 꺼낸 원소는 `dead[id]`로 표시합니다.

```js
class DEPQ {
  constructor() {
    this.mn = new Heap((x, y) => x[0] - y[0])   // [값, id]
    this.mx = new Heap((x, y) => y[0] - x[0])
    this.dead = []      // dead[id]가 true면 이미 꺼낸 원소
    this.size = 0
  }
  push(v) {
    const id = this.dead.length
    this.dead.push(false)
    this.mn.push([v, id])
    this.mx.push([v, id])
    this.size++
  }
```

```js
  _pop(h) {
    while (h.size && this.dead[h.peek()[1]]) h.pop()
    if (!h.size) return undefined
    const [v, id] = h.pop()
    this.dead[id] = true         // 반대쪽 힙에서도 무효 표시
    this.size--
    return v
  }
  popMin() { return this._pop(this.mn) }
  popMax() { return this._pop(this.mx) }
}
```

```js
const d = new DEPQ()
;[4, 1, 9, 7].forEach((v) => d.push(v))
d.popMax() // 9
d.popMin() // 1
d.popMax() // 7
```

- 각 연산은 상환 O(log N)입니다. 원소는 두 힙에서 각각 한 번씩만 버려집니다.
- 값이 같은 원소가 있어도 id가 다르므로 정확히 하나만 꺼냅니다. 값 기준 `Map` 예약 방식(앞 절)보다 중복 처리가 단순합니다.
- 최솟값과 최댓값 외의 순서 질의(K번째 등)가 필요하거나 값 개수가 작은 범위라면 BST(45편)나 좌표 압축 후 Fenwick Tree(64편)를 씁니다.
- 문제에서 "최댓값 삭제, 최솟값 삭제, 삽입" 명령을 섞어 주는 형태가 대표적입니다. 빈 큐에 삭제 명령이 오면 무시해야 하는지 문제 조건을 확인합니다.

**흔한 실수:** 한쪽 힙에서만 꺼내고 `dead` 표시를 하지 않는 것입니다. 반대쪽 힙에 남은 같은 원소가 나중에 다시 꺼내집니다.

## 허프만 부호화

허프만 부호화(Huffman coding)는 글자마다 길이가 다른 이진 부호를 붙여 전체 비트 수를 가장 작게 만드는 방법입니다. 자주 나오는 글자에 짧은 부호를 줍니다. 어떤 부호도 다른 부호의 앞부분이 아닌 접두 부호(prefix code)라서 이어 붙인 비트열을 모호함 없이 해독할 수 있습니다.

만드는 순서는 다음과 같습니다.

1. 글자마다 빈도를 무게로 갖는 잎 노드를 만들어 최소 힙에 넣는다.
2. 무게가 가장 작은 두 노드를 꺼내 합친 부모 노드(무게는 두 무게의 합)를 만들어 다시 넣는다.
3. 노드가 하나 남을 때까지 2를 반복한다. 남은 노드가 루트다.
4. 루트에서 왼쪽 간선을 `0`, 오른쪽 간선을 `1`로 읽은 경로가 각 글자의 부호다.

```js
function huffTree(freq) {          // freq: Map 글자 -> 빈도
  const h = new Heap((a, b) => a.w - b.w)
  for (const [ch, w] of freq) h.push({ w, ch })
  while (h.size > 1) {
    const a = h.pop(), b = h.pop()   // 최소 둘
    h.push({ w: a.w + b.w, l: a, r: b })
  }
  return h.pop()
}
```

```js
function codes(root) {
  const res = new Map()
  const walk = (t, code) => {
    if (t.ch !== undefined) {   // 잎: 글자 하나
      res.set(t.ch, code || '0')
      return
    }
    walk(t.l, code + '0')
    walk(t.r, code + '1')
  }
  walk(root, '')                   // 글자가 하나뿐이면 '0'
  return res
}
const f = new Map([['a', 5], ['b', 2], ['c', 1], ['d', 1]])
codes(huffTree(f)) // a: 1, b: 00, c: 010, d: 011
```

`a 5, b 2, c 1, d 1`의 진행입니다.

| 단계 | 합치는 두 노드 | 새 노드 무게 | 남은 노드 |
|------|----------------|--------------|-----------|
| 1 | c(1), d(1) | 2 | a5, b2, cd2 |
| 2 | b(2), cd(2) | 4 | a5, bcd4 |
| 3 | a(5), bcd(4) | 9 | 루트 9 |

- 부호 길이는 a 1비트, b 2비트, c·d 3비트이고 총 비트 수는 5×1 + 2×2 + 1×3 + 1×3 = 15입니다. 모든 글자에 2비트를 쓰는 고정 길이 부호는 9 × 2 = 18비트입니다.
- 총 비트 수는 합치는 과정에서 만든 부모 노드 무게의 합과 같습니다(2 + 4 + 9 = 15). 부호를 실제로 만들 필요 없이 이 합만 구하는 문제가 많습니다.
- 힙 연산이 N번씩이므로 O(N log N)입니다. 빈도가 이미 정렬되어 있으면 두 개의 큐로 O(N)에 만들 수 있습니다(Wikipedia 기준).
- 무게가 같은 노드가 있을 때 어느 쪽을 먼저 합치느냐에 따라 부호는 달라질 수 있지만 총 비트 수는 같습니다. 부호 자체를 출력하는 문제라면 동률 규칙을 문제에서 확인합니다.

가장 작은 둘을 합치는 이 방식은 허프만 외에도 쓰입니다. "여러 묶음을 둘씩 합치되 합칠 때 두 크기의 합만큼 비용이 드는데, 하나로 만드는 최소 총비용"이 같은 구조입니다.

```js
function mergeCost(sizes) {
  const h = Heap.from(sizes)
  let cost = 0
  while (h.size > 1) {
    const s = h.pop() + h.pop()    // 가장 작은 둘을 합침
    cost += s
    h.push(s)
  }
  return cost
}
mergeCost([4, 1, 3, 2]) // 19 (3 + 6 + 10)
```

- 작은 것끼리 먼저 합쳐야 큰 값이 여러 번 더해지는 횟수가 줄어듭니다. 합치는 순서를 바꾸면 `[4, 1, 3, 2]`를 앞에서부터 합친 5 + 8 + 10 = 23처럼 더 커집니다.
- 정당성은 교환 논증(33편)으로 보입니다. 가장 작은 두 노드는 최적 트리에서 가장 깊은 곳의 형제로 둘 수 있습니다.

**흔한 실수:** 원소가 하나뿐인 경우를 놓치는 것입니다. `mergeCost`는 0이고, 글자가 하나뿐인 `huffTree`는 루트가 잎이라서 부호가 빈 문자열이 되므로 `'0'`으로 보정합니다.

## 핵심 정리

- 우선순위 큐는 우선순위가 가장 높은 원소부터 꺼내는 자료구조이며, 코딩테스트에서는 이진 힙으로 구현해 삽입·추출을 O(log N)에 처리합니다. JavaScript에는 내장이 없어 직접 구현합니다.
- 비교 함수가 음수를 반환하는 쪽이 먼저 나옵니다. 하나의 Heap 클래스에 비교 함수를 바꿔 끼워 최소·최대·쌍·객체 기준을 만들고, 힙 안의 우선순위를 바깥에서 바꾸면 안 됩니다.
- 큰 K개는 크기 K의 최소 힙, 작은 K개는 크기 K의 최대 힙으로 O(N log K)에 구합니다.
- 중앙값은 작은 절반의 최대 힙과 큰 절반의 최소 힙을 크기 차이 1 이하로 유지해 구합니다.
- 힙 중간의 값은 지연 삭제(예약해 두었다가 루트에 오면 버림)로 지우고, 최솟값·최댓값을 모두 꺼내는 이중 우선순위 큐는 두 힙과 id 표시로 만듭니다.
- 허프만 부호화는 가장 작은 두 노드를 반복해서 합쳐 최적의 접두 부호를 만들며 O(N log N)입니다.
