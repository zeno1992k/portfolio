## DAG

DAG(Directed Acyclic Graph)는 방향이 있고 사이클이 없는 그래프입니다. 간선 `u → v`는 "u가 v보다 먼저"라는 선후 관계를 뜻하고, 사이클이 없으면 이 관계가 모순 없이 한 줄로 펼쳐집니다(그래프 용어는 35편, 사이클 판별은 37편).

위상 정렬(topological sort)은 모든 간선 `u → v`에서 u가 v보다 앞에 오도록 정점을 한 줄로 나열하는 것입니다.

```js
// 1 → 2, 1 → 3, 2 → 4, 3 → 4, 4 → 5
// 위상 순서: 1 2 3 4 5 (또는 1 3 2 4 5)
```

- 위상 순서는 그래프가 DAG일 때만 존재합니다. 사이클이 있으면 사이클 안의 정점끼리 서로 먼저여야 해서 나열할 수 없습니다.
- 순서는 여러 개일 수 있습니다. 선후 관계가 없는 정점은 서로 어느 쪽이 앞에 와도 됩니다.
- 위상 순서가 하나만 있는 조건은 아래 "위상 정렬 결과의 유일성"에서 다룹니다.
- 시간은 O(V + E)입니다. V는 정점 수, E는 간선 수입니다.

시험(코딩테스트)에서 묻는 방식: "A를 하려면 B가 먼저 끝나야 한다"는 문장이 그래프 문제임을 알아채는 것이 첫 관문입니다. B → A 간선으로 바꿔 놓는 방향 실수가 가장 흔합니다.

## 진입 차수

진입 차수(indegree)는 한 정점으로 들어오는 간선의 수입니다. 위상 정렬에서는 "아직 끝나지 않은 선행 작업의 수"로 읽습니다. 진입 차수가 0이면 먼저 할 일이 없으니 지금 시작할 수 있습니다.

```js
function build(n, edges) {   // 정점 번호 1..n
  const adj = Array.from({ length: n + 1 }, () => [])
  const indeg = new Array(n + 1).fill(0)
  for (const [u, v] of edges) {
    adj[u].push(v)           // u → v
    indeg[v]++               // v로 들어오는 간선 +1
  }
  return { adj, indeg }
}
```

- 같은 간선이 두 번 주어지면 `adj[u]`에 v가 두 번 들어가고 `indeg[v]`도 2가 됩니다. 나중에 간선을 따라가며 두 번 빼므로 결과가 맞습니다.
- 인접 리스트는 `Array.from`으로 만듭니다. `fill([])`은 모든 정점이 같은 배열을 공유합니다(자세히는 35편).

## Queue 위상 정렬

Queue 위상 정렬(Kahn 알고리즘, 1962)은 진입 차수가 0인 정점을 큐에 넣고, 꺼낸 정점에서 나가는 간선을 지우며 새로 0이 된 정점을 큐에 넣는 방법입니다.

1. 진입 차수가 0인 정점을 모두 큐에 넣는다.
2. 큐에서 u를 꺼내 순서에 추가한다.
3. u의 이웃 v마다 `indeg[v]`를 1 줄인다. 0이 되면 큐에 넣는다.
4. 큐가 빌 때까지 2–3을 반복한다.

```js
function topoSort(n, edges) {
  const { adj, indeg } = build(n, edges)
  const queue = []
  for (let i = 1; i <= n; i++) {
    if (indeg[i] === 0) queue.push(i)
  }
  for (let head = 0; head < queue.length; head++) {
    for (const v of adj[queue[head]]) {
      if (--indeg[v] === 0) queue.push(v)
    }
  }
  return queue.length === n ? queue : null
}
topoSort(5, [[1,2],[1,3],[3,4],[2,4],[4,5]])
// [1, 2, 3, 4, 5]
```

- 큐는 `shift` 대신 `head` 인덱스로 읽습니다. 큐에 들어간 순서가 곧 위상 순서라서 별도 결과 배열이 필요 없습니다(자세히는 20편).
- 마지막 줄은 아래 "Cycle 존재 여부 판정"의 검사입니다. 사이클이 없으면 순서를, 있으면 `null`을 돌려줍니다.

위 예제의 진행입니다. 표기는 처리 후의 진입 차수입니다.

| 꺼냄 | 간선 처리 | 큐에 새로 들어감 | 큐 전체 |
|------|-----------|------------------|---------|
| 시작 | 진입 차수 0인 정점 | 1 | 1 |
| 1 | 2는 0, 3은 0 | 2, 3 | 1, 2, 3 |
| 2 | 4는 2에서 1 | 없음 | 1, 2, 3 |
| 3 | 4는 1에서 0 | 4 | 1, 2, 3, 4 |
| 4 | 5는 0 | 5 | 1, 2, 3, 4, 5 |

- 정점은 한 번만 큐에 들어가고, 간선은 한 번만 지워집니다. 시간 O(V + E), 공간 O(V + E)입니다.
- 정점 5의 진입 차수가 0이 되는 시점은 4가 끝난 직후입니다. 이 시점이 "선행 작업이 전부 끝난 시점"입니다.
- 큐 대신 스택을 써도 올바른 위상 순서가 나옵니다. 순서만 달라집니다.

**흔한 실수:**

- 진입 차수를 줄이기 전에 큐에 넣거나, `--indeg[v] === 0` 대신 `indeg[v]-- === 0`으로 써서 한 박자 늦게 넣는 것입니다. 앞은 줄인 값, 뒤는 줄이기 전 값을 비교합니다.
- 정점 번호가 0부터인 입력에 1부터 쓰는 배열을 쓰는 것입니다. 번호 체계를 먼저 맞춥니다.

## 작업 순서

작업 순서 문제는 작업마다 먼저 끝나야 하는 작업이 있을 때 모든 작업을 끝내는 순서를 하나 구하는 문제입니다. 작업을 정점으로, "A 다음 B"를 `A → B` 간선으로 바꾸고 위상 정렬을 하면 그 순서가 답입니다.

```js
// 기초 → 응용 → 실전, 기초 → 실전
const edges = [[1, 2], [2, 3], [1, 3]]
topoSort(3, edges) // [1, 2, 3]
```

- 순서가 여럿이면 문제는 보통 "아무거나 하나" 또는 "사전순으로 가장 앞선 것"을 요구합니다. 후자는 아래 "우선순위 큐로 사전순 위상 정렬"입니다.
- 불가능한 입력(사이클)이 있는 문제는 `null`을 보고 "불가능"을 출력합니다.
- 작업마다 걸리는 시간이 있고 동시에 진행할 수 있다면 순서가 아니라 최소 완료 시간을 묻습니다. 아래 "위상 정렬과 최장경로"에서 다룹니다.

## 선수 조건 문제

선수 조건 문제는 과목마다 먼저 들어야 하는 과목이 있을 때 전부 이수할 수 있는지, 어떤 순서가 가능한지 묻는 대표 유형입니다. 입력이 `[a, b]`이면 "a를 들으려면 b가 먼저"라는 뜻이므로 간선은 `b → a`입니다.

```js
function findOrder(num, pre) {          // 과목 0..num-1
  const edges = pre.map(([a, b]) => [b + 1, a + 1])
  const order = topoSort(num, edges)    // 1부터 쓰는 함수 재사용
  return order ? order.map((x) => x - 1) : []
}
findOrder(4, [[1,0],[2,0],[3,1],[3,2]]) // [0, 1, 2, 3]
findOrder(2, [[1,0],[0,1]])                 // []
```

- 이수 가능 여부만 묻는다면 `topoSort`가 `null`인지만 확인하면 됩니다.
- 최소 학기 수를 묻는 변형은 한 학기에 수강 수 제한이 없을 때 "선수 과목들이 끝난 다음 학기"가 최소입니다. 큐를 돌며 학기를 갱신합니다.

```js
const sem = new Array(n + 1).fill(1)   // 모두 1학기에서 시작
// 큐를 돌리는 안쪽 반복에서, u → v 간선을 지울 때마다
sem[v] = Math.max(sem[v], sem[u] + 1)
```

- v의 학기는 선수 과목 중 가장 늦은 학기 + 1입니다. 선행이 여럿이므로 대입이 아니라 `max`로 갱신해야 합니다.
- 위 예제(1→2, 1→3, 3→4, 2→4, 4→5)의 학기는 1, 2, 2, 3, 4이므로 최소 4학기입니다. 정점 4는 2와 3이 모두 끝난 다음에 해당하는 3학기입니다.
- 이 값은 DAG에서 가장 긴 경로의 정점 수와 같습니다. 같은 학기에 듣는 과목들은 서로 선후 관계가 없습니다.

**흔한 실수:** 간선 방향을 입력 그대로 `a → b`로 만드는 것입니다. 샘플이 우연히 통과하는 경우가 많아서 방향을 먼저 문장으로 확인합니다.

## 위상 정렬 결과의 유일성

위상 순서가 하나뿐인지는 큐에서 꺼내는 시점마다 큐에 정확히 한 정점만 있는지로 판단합니다. 큐에 둘 이상 있다는 것은 지금 시작할 수 있는 작업이 둘 이상이라는 뜻이고, 둘의 선후는 자유입니다.

```js
// topoSort의 for 반복 맨 위에 한 줄 추가
if (queue.length - head > 1) unique = false
```

- 앞의 예제에서 1을 처리한 직후 큐에 2와 3이 함께 있으므로 순서가 둘 이상입니다(`1 2 3 4 5`와 `1 3 2 4 5`).
- 모든 시점에 대기 정점이 하나이면 순서가 유일하고, 그때 연속한 두 정점 사이에는 모두 간선이 있습니다. 즉 위상 순서가 유일한 것과 그 순서가 한 줄짜리 경로(해밀턴 경로)인 것은 동치입니다.
- 유일 여부는 사이클이 없을 때만 의미가 있습니다. 사이클이 있으면 먼저 `queue.length === n`을 확인합니다.
- 비교 결과로 순위를 복원하는 문제(예: 키 비교 정보로 줄 세우기)에서는 간선이 충분해 순서가 유일해야 전체 순위를 확정할 수 있습니다.

```js
// 1 → 2 → 3: 대기 정점이 항상 1개, 유일
// 1 → 2, 1 → 3: 1 뒤에 2, 3이 함께 대기, 유일하지 않음
```

## Cycle 존재 여부 판정

위상 정렬 결과에 n개 정점이 모두 들어가지 못하면 사이클이 있습니다. 사이클 안의 정점은 서로 선행이라서 진입 차수가 끝까지 0이 되지 못하고, 그 뒤에 이어진 정점도 큐에 들어가지 못합니다.

```js
topoSort(3, [[1, 2], [2, 3], [3, 2]]) // null
// 1은 시작. 2는 진입 차수 2에서 1로 줄 뿐 0이 안 된다.
// 3은 2가 끝나야 줄어든다. 결과 길이 1 < 3
```

- 처리하지 못한 정점은 사이클에 속한 정점과 사이클 뒤에서 이어지는 정점입니다. 사이클에 속한 정점만 구분하려면 DFS(37편)를 씁니다.
- 자기 간선 `u → u`는 `indeg[u]`가 줄지 않아 사이클로 잡힙니다.
- 방향 그래프의 사이클 판정을 위상 정렬로 하면 DFS 상태 배열 없이 반복문만으로 끝납니다. 재귀 깊이 걱정도 없습니다(자세히는 86편).
- 무방향 그래프의 사이클에는 쓰지 못합니다. 무방향 간선은 양쪽 모두 진입 차수에 들어가 해당 없는 정점이 생깁니다.

**흔한 실수:** 결과 길이를 확인하지 않고 큐에 들어간 정점만 출력하는 것입니다. 사이클이 있는데도 일부만 출력하고 끝납니다.

## DAG DP

DAG에서는 위상 순서대로 정점을 처리하면 DP의 점화식을 맞는 순서로 계산할 수 있습니다. 정점 v의 값이 v로 들어오는 정점들의 값에서 정해지는데, 위상 순서에서는 들어오는 정점이 전부 v보다 앞에 있기 때문입니다(DP는 40편).

정점 1에서 정점 n까지 가는 경로의 수를 세는 예입니다. `ways[v]`는 1에서 v까지의 경로 수입니다.

```js
function countPaths(n, edges) {
  const order = topoSort(n, edges)
  const adj = Array.from({ length: n + 1 }, () => [])
  for (const [u, v] of edges) adj[u].push(v)
  const ways = new Array(n + 1).fill(0)
  ways[1] = 1                          // 출발점
  for (const u of order) {
    for (const v of adj[u]) ways[v] += ways[u]
  }
  return ways[n]
}
// 예제(1→2, 1→3, 3→4, 2→4, 4→5)에서 2
```

- 순서대로 `u`를 처리하는 시점에 `ways[u]`는 이미 완성되어 있습니다. 선행 정점이 모두 앞에서 처리됐기 때문입니다.
- 계산 방식은 두 가지입니다. 위처럼 정점에서 이웃으로 밀어 넣는 방식(push)과, 정점마다 들어오는 정점의 값을 모으는 방식(pull)이며 둘 다 O(V + E)입니다.
- 사이클이 있으면 DP가 성립하지 않으므로 `order`가 `null`인 경우를 먼저 처리합니다.
- 경로 수는 빠르게 커집니다. 합이 `Number.MAX_SAFE_INTEGER`(2^53 - 1)를 넘으면 정확하지 않으므로 문제가 나머지를 요구하면 매번 mod를 취하고, 아니면 BigInt를 씁니다(자세히는 57편, 02편).
- 같은 DP를 DFS와 메모이제이션으로 쓰면 위상 순서가 재귀의 호출 순서에 숨어 있는 방식이 됩니다(40편). 깊이가 깊으면 위상 정렬 쪽이 안전합니다.

## 위상 정렬과 최장경로

DAG의 최장경로는 위상 순서대로 이웃의 값을 `max`로 갱신해서 O(V + E)에 구합니다. 일반 그래프에서는 최장경로가 어려운 문제지만 DAG에서는 사이클이 없어서 같은 정점을 두 번 지나는 일이 없기 때문에 쉽습니다.

```js
function longest(n, wedges, s) {       // wedges: [u, v, w]
  const order = topoSort(n, wedges.map(([u, v]) => [u, v]))
  const adj = Array.from({ length: n + 1 }, () => [])
  for (const [u, v, w] of wedges) adj[u].push([v, w])
  const dist = new Array(n + 1).fill(-Infinity)
  dist[s] = 0
  for (const u of order) {
    if (dist[u] === -Infinity) continue   // s에서 못 닿음
    for (const [v, w] of adj[u]) {
      dist[v] = Math.max(dist[v], dist[u] + w)
    }
  }
  return dist
}
```

- 입력 `[[1,2,3],[1,3,2],[3,4,4],[2,4,1],[4,5,2]]`, 시작 1이면 `dist`는 정점 1부터 `0, 3, 2, 6, 8`입니다. 가장 긴 경로는 1 → 3 → 4 → 5이고 길이는 2 + 4 + 2 = 8입니다.
- `-Infinity`로 시작해야 "닿지 못함"과 "길이 0"이 구분됩니다. `0`으로 채우면 닿지 못한 정점이 길이 0인 출발점처럼 작동합니다.
- 최소값(`min`)으로 바꾸고 `Infinity`로 초기화하면 DAG의 최단경로입니다. 음수 가중치가 있어도 쓸 수 있습니다(Dijkstra는 음수 불가, 48편, 49편).
- 작업마다 소요 시간이 있는 작업 스케줄링의 최소 완료 시간(임계 경로)도 같은 틀입니다. `finish[v] = max(finish[u]) + time[v]`로 선행 작업이 모두 끝난 시점에 자기 시간을 더합니다.
- 최장경로의 길이가 곧 모든 작업을 동시에 진행할 수 있을 때의 최소 완료 시간입니다.

```js
// finish[v]를 소요 시간 time[v]로 시작. 간선 u → v를 지날 때
finish[v] = Math.max(finish[v], finish[u] + time[v])
// 전체 완료 시간은 Math.max(...finish)
```

- 마지막 줄의 `Math.max(...finish)`는 인수 개수 한계가 있어서 정점이 수십만이면 `reduce`를 씁니다(자세히는 86편).

## DFS 위상 정렬

DFS 위상 정렬은 DFS로 정점의 탐색이 끝나는 순서를 기록하고 그 역순을 위상 순서로 쓰는 방법입니다. 정점 u는 자기 뒤에 올 모든 정점의 탐색이 끝난 뒤에 끝나므로 종료 순서에서는 후행 정점이 앞에 오고, 뒤집으면 선행 정점이 앞에 옵니다(DFS 종료 시각은 36편).

```js
function topoDfs(n, adj) {
  const state = new Array(n + 1).fill(0) // 0 미방문 1 진행 2 끝
  const post = []; let cyclic = false
  const dfs = (u) => {
    state[u] = 1
    for (const v of adj[u]) {
      if (state[v] === 1) cyclic = true  // 진행 중인 정점으로
      else if (state[v] === 0) dfs(v)
    }
    state[u] = 2
    post.push(u)                         // 종료 순서 기록
  }
  for (let i = 1; i <= n; i++) if (state[i] === 0) dfs(i)
  return cyclic ? null : post.reverse()
}
```

예제(1→2, 1→3, 3→4, 2→4, 4→5)에서 `adj[1]`은 2, 3 순서입니다.

| 단계 | 상태 |
|------|------|
| 1에서 2로, 2에서 4로, 4에서 5로 내려감 | 5가 끝남, 이어서 4, 2 |
| 1로 돌아와 3을 탐색 | 4는 이미 끝났으므로 3이 끝남, 이어서 1 |
| 종료 순서 | 5, 4, 2, 3, 1 |
| 뒤집음 | 1, 3, 2, 4, 5 |

- Queue 방식의 결과 `1 2 3 4 5`와 다르지만 모든 간선에서 선행이 앞에 있으므로 올바른 위상 순서입니다. 순서가 여러 개일 때 어느 쪽이 나오는지는 방식과 이웃의 순서에 달렸습니다.
- 진행 중(1)인 정점으로 되돌아가는 간선이 있으면 사이클입니다(자세히는 37편).
- 시간 O(V + E)입니다. 재귀 깊이가 V까지 갈 수 있어서 정점이 많으면 스택으로 바꿉니다(22편, 86편).
- 어느 쪽을 쓸지: 진입 차수 방식은 반복문이라 안전하고 사이클을 길이로 판정하며 사전순 변형이 쉽습니다. DFS 방식은 종료 시각이 필요한 다른 알고리즘(SCC 등)과 같은 틀로 쓸 때 편합니다(SCC는 68편).

**흔한 실수:** 종료 순서를 뒤집지 않고 그대로 출력하는 것입니다. 그 순서는 후행이 앞에 오는 역위상 순서입니다.

## 우선순위 큐로 사전순 위상 정렬

큐 대신 최소 힙(우선순위 큐)을 쓰면 시작할 수 있는 정점 중 번호가 가장 작은 것을 항상 먼저 꺼냅니다. 이렇게 하면 결과가 사전순으로 가장 앞선 위상 순서가 됩니다. 아래 코드의 `push`, `pop`은 46편의 최소 힙 함수입니다(활용은 47편).

```js
function lexTopo(n, edges) {
  const { adj, indeg } = build(n, edges)
  const heap = [], order = []
  for (let i = 1; i <= n; i++) {
    if (indeg[i] === 0) push(heap, i)
  }
  while (heap.length) {
    const u = pop(heap)                // 가장 작은 번호
    order.push(u)
    for (const v of adj[u]) {
      if (--indeg[v] === 0) push(heap, v)
    }
  }
  return order.length === n ? order : null
}
```

- `lexTopo(4, [[4, 2], [3, 1]])`은 `[3, 1, 4, 2]`입니다. 같은 입력에 일반 큐는 시작 정점 3, 4를 넣은 순서대로 `3 4 1 2`를 냅니다. 힙은 3을 꺼낸 직후 새로 시작 가능해진 1을 4보다 먼저 꺼냅니다.
- 매 단계에서 가능한 선택지 중 가장 작은 값을 고르는 그리디이고, 앞자리가 작을수록 사전순으로 앞서므로 맞습니다(자세히는 33편).
- 정점이 한 번씩 힙에 들어가고 나오므로 시간은 O(E + V log V)입니다.
- 문제에 "사전순으로 가장 앞선"이라고 쓰였는지, "번호가 작은 정점을 가능한 한 앞에"라고 쓰였는지 구분해야 합니다. 앞의 것은 위 코드입니다.

뒤의 것은 다릅니다. 예를 들어 `3 → 1` 하나뿐인 3개 정점에서 위 코드는 `2 3 1`을 내지만, 1을 가능한 한 앞에 두는 순서는 `3 1 2`입니다. 이 경우 간선을 모두 뒤집고 최대 힙으로 꺼낸 뒤 결과를 뒤집습니다.

```js
// 최대 힙은 최소 힙에 부호를 바꿔 넣는다 (46편)
// 1. 간선 [u, v]를 [v, u]로 뒤집어 build
// 2. push(heap, -i), 꺼낼 때 u = -pop(heap)
// 3. 최종 order.reverse()
// 3 → 1 이면 [3, 1, 2]
```

- 역방향에서 큰 번호를 먼저 놓으면 뒤집었을 때 큰 번호가 뒤로 가고, 작은 번호는 선행이 허락하는 한 앞에 놓입니다.
- 힙에 한꺼번에 들어 있는 정점이 하나라도 있으면 일반 큐와 다른 결과가 나옵니다. 난이도 순서처럼 "쉬운 문제부터" 푸는 문제가 이 유형입니다.

**흔한 실수:** 위상 정렬 뒤에 정렬(`sort`)로 사전순을 맞추려는 것입니다. 정렬하면 선후 관계가 깨집니다.

## 핵심 정리

- 위상 정렬은 모든 간선에서 시작 정점이 앞에 오도록 DAG의 정점을 나열하는 것이며, 사이클이 있으면 존재하지 않습니다.
- Queue 방식은 진입 차수가 0인 정점을 큐에 넣고 간선을 지우며 O(V + E)에 순서를 만들고, 큐에 들어간 개수가 n보다 작으면 사이클입니다.
- 큐에 항상 한 정점뿐이면 순서가 유일합니다. 선수 조건 입력 `[a, b]`는 `b → a` 간선입니다.
- DAG 위에서는 위상 순서대로 DP를 돌려 경로 수와 최장경로를 O(V + E)에 구합니다. 최장경로는 `-Infinity`로 초기화합니다.
- DFS 방식은 종료 순서를 뒤집고, 사전순이 필요하면 큐 대신 최소 힙을 씁니다.
