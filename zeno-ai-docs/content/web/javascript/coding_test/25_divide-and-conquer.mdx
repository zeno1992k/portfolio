## 분할 정복 개념

분할 정복(divide and conquer)은 문제를 같은 형태의 더 작은 문제로 나눠 풀고, 그 답을 합쳐 원래 문제의 답을 만드는 방법입니다. 작은 문제가 원래 문제와 같은 형태라서 재귀로 쓰는 것이 자연스럽습니다(재귀는 22편).

분할 정복이 성립하는 조건은 세 가지입니다.

- 문제를 같은 형태의 작은 문제로 나눌 수 있다.
- 나눈 부분 문제가 서로 독립이다. 한 부분 문제의 답이 다른 부분 문제의 풀이에 영향을 주지 않는다.
- 부분 문제의 답에서 전체 답을 만드는 방법이 있다.

대표 예는 배열의 최댓값입니다. 구간을 반으로 나눠 각각의 최댓값을 구하고 둘 중 큰 쪽을 고릅니다.

```js
function maxOf(arr, lo, hi) {   // 구간 [lo, hi)
  if (hi - lo === 1) return arr[lo]
  const mid = (lo + hi) >> 1
  return Math.max(maxOf(arr, lo, mid), maxOf(arr, mid, hi))
}
maxOf([3, 9, 4, 1, 7], 0, 5) // 9
```

최댓값은 반복문 한 번이면 끝나므로 분할 정복이 이득이 없습니다. 분할 정복이 빛나는 경우는 결합이 싸고 분할로 비용이 줄어드는 문제입니다. 정렬(병합 정렬), 거듭제곱, 격자 분할이 그렇습니다.

## 분할 → 정복 → 결합

분할 정복 풀이는 세 단계로 이뤄집니다.

| 단계 | 하는 일 |
|------|---------|
| 분할(divide) | 문제를 같은 형태의 작은 문제 a개로 나눈다. 크기는 보통 1/b로 줄어든다 |
| 정복(conquer) | 작은 문제를 재귀로 푼다. 충분히 작아지면(기저 조건) 바로 답을 낸다 |
| 결합(combine) | 부분 문제의 답을 합쳐 원래 문제의 답을 만든다 |

코드의 뼈대는 다음과 같습니다.

```js
function solve(lo, hi) {            // 구간 [lo, hi)
  if (hi - lo === 1) return base(lo) // 기저: 크기 1
  const mid = (lo + hi) >> 1         // 분할
  const left = solve(lo, mid)        // 정복
  const right = solve(mid, hi)       // 정복
  return combine(left, right, lo, mid, hi) // 결합
}
```

- 구간은 `[lo, hi)`(왼쪽 포함, 오른쪽 제외)로 잡으면 `mid`로 나눈 두 구간이 `[lo, mid)`, `[mid, hi)`가 되어 겹치거나 빠지는 곳이 없습니다.
- 기저 조건은 크기 1(또는 0)입니다. 기저 조건이 없거나 구간이 줄어들지 않으면 무한 재귀가 됩니다.
- 구간 길이가 1 이상이면 `mid`는 항상 `lo`보다 크고 `hi`보다 작아서, 두 부분 구간이 모두 원래보다 짧아집니다.

### 결합이 핵심인 예: 최대 부분 배열 합

연속한 구간의 합이 가장 큰 값을 구합니다. 답은 왼쪽 절반 안, 오른쪽 절반 안, 가운데 경계를 걸치는 구간 중 하나입니다. 앞의 둘은 재귀가 구하고, 결합 단계가 경계를 걸치는 경우를 직접 계산합니다.

```js
function maxSub(a, lo, hi) {
  if (hi - lo === 1) return a[lo]
  const mid = (lo + hi) >> 1
  let left = -Infinity, right = -Infinity, sum = 0
  for (let i = mid - 1; i >= lo; i--) {
    sum += a[i]; left = Math.max(left, sum)   // mid 왼쪽 끝 합
  }
  sum = 0
  for (let i = mid; i < hi; i++) {
    sum += a[i]; right = Math.max(right, sum) // mid 오른쪽 끝 합
  }
  const l = maxSub(a, lo, mid), r = maxSub(a, mid, hi)
  return Math.max(l, r, left + right)
}
maxSub([-2, 1, -3, 4, -1, 2, 1, -5, 4], 0, 9) // 6
```

결합이 O(N)이고 부분 문제가 둘이므로 시간은 O(N log N)입니다(마스터 정리 절). 같은 문제는 DP로 O(N)에 풀립니다(자세히는 41편).

### 결합이 사실상 없는 예: 거듭제곱

x의 n제곱을 `n`을 반으로 줄여 구합니다. 반으로 줄인 문제를 한 번만 풀고 그 결과를 제곱합니다.

```js
function power(x, n) {
  if (n === 0) return 1
  const half = power(x, Math.floor(n / 2))
  return n % 2 === 0 ? half * half : half * half * x
}
power(2, 10) // 1024
```

`power(2, 10)`의 호출 흐름입니다.

| 호출 | n | half | 결과 |
|------|---|------|------|
| power(2, 10) | 10 | power(2, 5) | 32 × 32 = 1024 |
| power(2, 5) | 5 | power(2, 2) | 4 × 4 × 2 = 32 |
| power(2, 2) | 2 | power(2, 1) | 2 × 2 = 4 |
| power(2, 1) | 1 | power(2, 0) | 1 × 1 × 2 = 2 |
| power(2, 0) | 0 | 기저 | 1 |

- `n`이 매번 절반이 되므로 호출은 약 log N번이고 시간은 O(log N)입니다.
- 값이 커지는 문제는 결합 단계에서 나머지를 취합니다. JavaScript에서는 `Number`는 `Number.MAX_SAFE_INTEGER`(2^53 - 1)를 넘으면 정밀도를 잃으므로 곱셈 결과가 그 범위를 넘을 수 있으면 `BigInt`를 씁니다(자세히는 02편, 57편).

```js
function powMod(b, e, m) {      // 모두 BigInt
  if (e === 0n) return 1n
  const h = powMod(b, e / 2n, m)
  const hh = (h * h) % m
  return e % 2n === 0n ? hh : (hh * b) % m
}
powMod(2n, 100n, 1000000007n) // 976371285n
```

**흔한 실수:** 반으로 줄인 문제를 두 번 호출하는 것입니다.

```js
// ❌ 같은 부분 문제를 두 번 풀어 O(N)
power(x, k) * power(x, k)
// ✅ 한 번 풀어 변수에 담고 제곱 O(log N)
const half = power(x, k); half * half
```

`n`이 16일 때 호출이 ❌는 63번, ✅는 6번입니다. 부분 문제의 결과는 변수에 담아 재사용합니다.

## 정렬과 분할 정복

병합 정렬과 퀵 정렬은 분할 정복의 대표 예입니다. 둘의 차이는 어느 단계에 일을 몰아 두느냐입니다(구현은 27편).

| 항목 | 병합 정렬 | 퀵 정렬 |
|------|-----------|---------|
| 분할 | 가운데 인덱스로 반으로 자른다. 비용 O(1) | 피벗을 골라 작은 쪽과 큰 쪽으로 가른다. 비용 O(N) |
| 정복 | 두 절반을 각각 정렬한다 | 두 쪽을 각각 정렬한다 |
| 결합 | 정렬된 두 배열을 병합한다. 비용 O(N) | 없음. 이미 제자리에 있다 |
| 분할 크기 | 항상 N/2 | 피벗에 따라 다르다. 한쪽으로 쏠리면 최악 |
| 점화식 | T(N) = 2T(N/2) + O(N) | 평균 T(N) = 2T(N/2) + O(N) |

병합 정렬의 뼈대는 이렇습니다.

```js
function mergeSort(arr) {
  if (arr.length <= 1) return arr
  const mid = arr.length >> 1
  const left = mergeSort(arr.slice(0, mid))   // 분할 + 정복
  const right = mergeSort(arr.slice(mid))
  return merge(left, right) // 결합: 정렬된 두 배열을 하나로
}
```

- 정렬된 두 배열을 합치는 `merge`는 앞에서부터 작은 쪽을 꺼내는 O(N) 작업입니다. 구현은 27편에 있습니다.
- 병합 정렬은 깊이가 log N이고 각 깊이에서 전체 N개를 한 번씩 병합하므로 O(N log N)입니다.
- 정렬 말고도 정렬된 상태를 이용하는 병합 단계를 변형하면 역순쌍 개수를 셀 수 있습니다(자세히는 27편).

## 격자 분할 (쿼드 트리)

쿼드 트리(quad tree) 압축은 정사각형 격자를 같은 값으로만 채워졌는지 검사하고, 아니면 네 개의 정사각형으로 나눠 같은 방식으로 압축하는 분할 정복입니다. 격자 변의 길이는 2의 거듭제곱입니다. 직접 만든 유형 문제로 풉니다.

> 한 변이 N인 정사각형 격자(N은 2의 거듭제곱, 칸 값은 0 또는 1)를 압축한다. 영역이 모두 같은 값 v면 문자 v 하나로, 아니면 왼쪽 위, 오른쪽 위, 왼쪽 아래, 오른쪽 아래 순서로 압축한 결과를 괄호로 묶는다.

```js
function compress(g, r, c, size) {
  const v = g[r][c]
  let same = true
  for (let i = r; i < r + size && same; i++)
    for (let j = c; j < c + size; j++)
      if (g[i][j] !== v) { same = false; break }
  if (same) return String(v)         // 기저: 모두 같은 값
  const h = size / 2                 // 분할: 네 사분면
  const tl = compress(g, r, c, h)
  const tr = compress(g, r, c + h, h)
  const bl = compress(g, r + h, c, h)
  const br = compress(g, r + h, c + h, h)
  return '(' + tl + tr + bl + br + ')'
}
```

네 칸 격자로 흐름을 따라가 봅니다.

```js
const g = [[1,1,0,0],[1,1,0,0],[0,0,1,1],[0,0,1,0]]
compress(g, 0, 0, 4) // '(100(1110))'
```

| 영역 | 내용 | 결과 |
|------|------|------|
| 전체 4×4 | 섞여 있음 | 네 사분면으로 분할 |
| 왼쪽 위 2×2 | 모두 1 | `1` |
| 오른쪽 위 2×2 | 모두 0 | `0` |
| 왼쪽 아래 2×2 | 모두 0 | `0` |
| 오른쪽 아래 2×2 | 1, 1, 1, 0 | 칸 단위로 분할해 `(1110)` |

- 영역은 좌상단 좌표 `(r, c)`와 한 변의 길이 `size`로 표현합니다. 사분면의 좌상단은 `(r, c)`, `(r, c+h)`, `(r+h, c)`, `(r+h, c+h)`입니다(격자 좌표는 17편).
- 같은 값 검사가 영역 넓이 `size * size`만큼 걸립니다. 한 깊이에서 영역들의 넓이 합은 N²이고 깊이가 log N이라서 최악 O(N² log N)입니다. 점화식으로는 T(N) = 4T(N/2) + O(N²)입니다.
- 결합은 문자열 이어 붙이기뿐입니다. 부분 문제가 서로 겹치지 않는 영역이라 독립입니다.
- 같은 틀로 세 갈래·아홉 갈래로 나누는 문제도 풉니다. 3×3으로 나눠 영역 값 종류별 개수를 세는 문제가 대표적입니다. 나누는 개수 a와 줄어드는 비율 b만 바뀝니다.
- 값이 모두 같다는 검사를 빠르게 하고 싶으면 2차원 누적합으로 영역 합을 O(1)에 구합니다(자세히는 29편).

**흔한 실수:**

- 기저 조건을 크기 1로만 두면 이미 같은 값인 큰 영역도 끝까지 쪼개집니다. 같은 값이면 바로 반환하는 검사를 먼저 둡니다.
- 사분면의 순서를 문제 조건과 다르게 합치는 것입니다. 결합 순서는 문제가 정합니다.
- 좌표 대신 `slice`로 격자를 복사해 넘기면 호출마다 복사 비용이 붙어 느려집니다. 좌표와 크기만 넘깁니다.

## 분할 정복 vs DP

둘 다 큰 문제를 작은 문제로 쪼개 푸는 방법이지만, 부분 문제가 겹치는지가 다릅니다.

| 항목 | 분할 정복 | DP |
|------|-----------|-----|
| 부분 문제 | 서로 독립이고 겹치지 않는다 | 같은 부분 문제가 여러 번 나온다 |
| 풀이 방식 | 위에서 아래로 재귀 | 결과를 저장해 재사용(메모이제이션 또는 표 채우기) |
| 저장 | 하지 않는다 | 부분 문제의 답을 저장한다 |
| 대표 예 | 병합 정렬, 거듭제곱, 쿼드 트리 | 피보나치, 배낭, 최장 공통 부분 수열 |

피보나치 수를 분할 정복 형태로 쓰면 부분 문제가 겹쳐 호출 수가 폭발합니다.

```js
function fib(n) {
  return n < 2 ? n : fib(n - 1) + fib(n - 2)
}
// fib(5) 호출 15번, fib(10) 177번, fib(20) 21891번
```

`fib(5)`는 `fib(3)`을 두 번 계산합니다. 부분 문제가 겹치므로 한 번 푼 답을 저장하면 O(N)이 됩니다(자세히는 40편).

- 구분 방법: 부분 문제의 호출 트리에 같은 인자가 반복해서 나오면 DP, 모든 인자가 다르면 분할 정복입니다.
- 분할 정복 풀이에 같은 인자가 반복되는 호출이 있으면 저장을 붙여 DP로 바꿉니다.
- 최대 부분 배열 합처럼 두 방법 모두 풀 수 있는 문제도 있습니다. 시간은 DP가 더 낫지만 분할 정복은 구간 질의를 합치는 구조(세그먼트 트리, 62편)로 이어집니다.

## 마스터 정리로 복잡도 구하기

분할 정복의 시간은 점화식으로 표현됩니다. 마스터 정리(master theorem)는 `T(n) = a T(n/b) + f(n)` 꼴 점화식을 점화식 풀이 없이 바로 푸는 공식입니다.

- `a`: 부분 문제의 개수(a ≥ 1)
- `b`: 부분 문제 크기가 줄어드는 비율(b > 1). 부분 문제의 크기는 n/b
- `f(n)`: 분할과 결합에 드는 비용

`f(n)`을 `n`의 `log_b(a)`제곱과 비교합니다. `n^(log_b a)`는 재귀 트리의 잎 개수, 곧 가장 작은 부분 문제들의 총 비용입니다.

| 경우 | 조건 | 결과 |
|------|------|------|
| 1 | 분할·결합 비용이 잎 비용보다 다항식 차이로 작다. f(n) = O(n^c)이고 c가 log_b a보다 작다 | T(n) = Θ(n^(log_b a)) |
| 2 | 두 비용이 같은 속도다. f(n) = Θ(n^(log_b a)) | T(n) = Θ(n^(log_b a) log n) |
| 3 | 분할·결합 비용이 다항식 차이로 크다. f(n) = Ω(n^c)이고 c가 log_b a보다 크며 정칙 조건을 만족한다 | T(n) = Θ(f(n)) |

- 경우 1은 잎(작은 문제)의 비용이 지배합니다. 경우 3은 맨 위(분할·결합)의 비용이 지배합니다. 경우 2는 모든 깊이의 비용이 비슷해서 깊이 수 log n이 곱해집니다.
- 경우 3의 정칙 조건은 어떤 상수 k(k는 1 미만)에 대해 a f(n/b) ≤ k f(n)입니다. `f(n)`이 다항식이면 보통 만족합니다.
- 경우 2는 `f(n) = Θ(n^(log_b a) (log n)^k)`로 확장하면 k ≥ 0일 때 T(n) = Θ(n^(log_b a) (log n)^(k+1))입니다.

### 풀이 순서

1. 점화식에서 a, b, f(n)을 읽는다.
2. `log_b(a)`를 계산한다.
3. f(n)의 차수와 비교해 경우 1, 2, 3을 고른다.

### 대표 예

| 알고리즘 | 점화식 | a, b, f | log_b a | 경우 | 결과 |
|----------|--------|---------|---------|------|------|
| 이분 탐색, 거듭제곱 | T(n) = T(n/2) + 1 | 1, 2, 1 | 0 | 2 | O(log n) |
| 배열 최댓값(분할 정복) | T(n) = 2T(n/2) + 1 | 2, 2, 1 | 1 | 1 | O(n) |
| 병합 정렬, 최대 부분 배열 합 | T(n) = 2T(n/2) + n | 2, 2, n | 1 | 2 | O(n log n) |
| 쿼드 트리 압축(변 길이 n) | T(n) = 4T(n/2) + n² | 4, 2, n² | 2 | 2 | O(n² log n) |
| 결합이 이차인 가상의 분할 정복 | T(n) = 2T(n/2) + n² | 2, 2, n² | 1 | 3 | O(n²) |
| 부분 문제가 셋인 가상의 분할 정복 | T(n) = 3T(n/2) + n | 3, 2, n | 약 1.585 | 1 | O(n^1.585) |

- 배열 최댓값의 점화식은 경우 1입니다. 분할 정복으로 써도 선형 시간이라 반복문보다 낫지 않습니다.
- 경우 3 예의 정칙 조건은 2 (n/2)² = n²/2 ≤ k n²이므로 k = 1/2로 만족합니다.
- 쿼드 트리는 변 길이 n을 기준으로 한 식입니다. 전체 칸 수 M = n²을 기준으로 쓰면 T(M) = 4T(M/4) + O(M)이고 O(M log M)으로 같은 결과입니다.

### 쓸 수 없는 경우

- 부분 문제가 줄어드는 비율이 일정하지 않을 때: 한쪽으로 쏠리는 퀵 정렬의 최악 T(n) = T(n-1) + n은 `n/b` 꼴이 아니라 마스터 정리를 쓸 수 없습니다. 풀어 쓰면 n + (n-1) + … + 1이므로 O(n²)입니다.
- 부분 문제 크기가 서로 다를 때: T(n) = T(n/3) + T(2n/3) + n 같은 식은 재귀 트리를 그려 깊이별 비용을 더합니다. 이 식은 깊이가 log n이고 깊이마다 비용이 n 이하라서 O(n log n)입니다.
- 경우 사이의 틈: f(n)이 n^(log_b a)와 다항식 차이가 나지 않지만 같은 속도도 아닌 경우(예: T(n) = 2T(n/2) + n/log n)는 위 세 경우 밖입니다.
- 재귀가 `T(n) = 2T(n-1) + 1`처럼 n을 빼는 꼴이면 부분 문제 크기가 곱 비율로 줄지 않아 마스터 정리를 쓸 수 없습니다. 이 식은 O(2^n)입니다.

**흔한 실수:**

- 부분 문제가 둘이라고 무조건 O(n log n)으로 쓰는 것입니다. 결합 비용 f(n)에 따라 결과가 달라집니다(위 표의 O(n), O(n²) 예).
- `a`를 호출 코드의 재귀 호출 줄 수로 잘못 읽는 것입니다. 한 줄이 반복문 안에 있으면 실제 호출 수는 다릅니다.
- 결합 비용을 빼먹는 것입니다. `slice`로 배열을 복사하면 분할에도 O(n)이 듭니다. 앞의 `mergeSort`는 `slice` 때문에 분할이 O(n)이지만 병합도 O(n)이라 총합은 O(n log n)으로 같습니다.

## 핵심 정리

- 분할 정복은 문제를 같은 형태의 독립된 작은 문제로 나눠 재귀로 풀고 답을 합칩니다.
- 풀이는 분할, 정복(기저 조건 포함), 결합 세 단계이며 구간은 `[lo, hi)`로 잡고 `mid`로 나눕니다.
- 병합 정렬은 결합에, 퀵 정렬은 분할에 비용 O(N)이 들고, 쿼드 트리는 영역을 네 사분면으로 나눠 같은 값이면 즉시 반환합니다.
- 부분 문제가 겹치면 DP, 겹치지 않고 독립이면 분할 정복입니다. 반으로 줄인 문제는 한 번만 풀어 변수에 담습니다.
- 마스터 정리는 `T(n) = a T(n/b) + f(n)`에서 f(n)을 n의 log_b(a) 제곱과 비교해 세 경우로 O(n^(log_b a)), O(n^(log_b a) log n), O(f(n))을 구합니다.
