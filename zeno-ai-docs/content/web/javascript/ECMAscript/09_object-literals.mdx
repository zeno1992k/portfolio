## 객체의 개념

객체(object)는 프로퍼티(property)의 모음입니다. ECMA-262는 객체를 프로퍼티의 모음이며 프로토타입 객체를 하나 가지는 값으로 정의합니다. 프로토타입은 `null`일 수도 있습니다(자세히는 17편).

- 원시 값 7종(string, number, bigint, boolean, undefined, null, symbol)을 뺀 모든 값이 객체입니다.
- 배열, 함수, 정규 표현식, 날짜, `Map`, `Set`, `Promise`, 에러 인스턴스는 모두 객체입니다.
- 함수는 호출할 수 있는 객체이며, `typeof` 결과만 `'function'`입니다.
- `typeof null`은 `'object'`이지만 `null`은 객체가 아닙니다(자세히는 05편).

값이 객체인지는 `Object(v) === v`로 판별할 수 있습니다. `Object(v)`는 객체이면 그대로 돌려주고, 원시 값이면 새 객체를 만들어 돌려주므로 `===`가 `false`가 됩니다.

```js
const isObject = (v) => Object(v) === v
isObject({})        // true
isObject([])        // true
isObject(() => {})  // true
isObject(null)      // false
isObject('text')    // false
```

객체는 만든 뒤에도 프로퍼티를 추가·변경·삭제할 수 있는 변경 가능한 값입니다. 원시 값은 바꿀 수 없는 값입니다(자세히는 10편).

객체 지향 프로그래밍은 프로그램을 객체의 모음으로 구성하는 방식입니다. 객체는 상태를 나타내는 데이터와 그 데이터를 다루는 동작을 하나로 묶습니다. 대상에서 프로그램에 필요한 속성만 추려 표현하는 것을 추상화(abstraction)라고 합니다. 사람을 이름과 나이만으로 표현하면 나머지 특성을 버린 추상화입니다.

객체를 만드는 방법은 여러 가지입니다.

| 방법 | 예 | 자세히 |
|------|----|--------|
| 객체 리터럴 | `{ a: 1 }` | 이 편 |
| Object 생성자, 생성자 함수 | `new Object()`, `new Foo()` | 15편 |
| `Object.create` | `Object.create(proto)` | 17편 |
| 클래스 | `class Foo {}` 후 `new Foo()` | 24편 |

## 프로퍼티와 메서드

프로퍼티는 키(key)와 값(value)의 쌍입니다. 메서드(method)는 값이 함수인 프로퍼티입니다. 프로퍼티는 객체의 상태를, 메서드는 객체의 동작을 나타냅니다.

```js
const rect = {
  width: 4,     // 프로퍼티
  height: 3,
  area() {      // 메서드
    return this.width * this.height
  },
}
rect.area() // 12
```

- 메서드 안의 `this`는 호출에 쓴 객체(`rect`)를 가리킵니다(자세히는 21편).
- 프로퍼티 값에는 원시 값, 배열, 함수, 다른 객체 등 무엇이든 올 수 있습니다. 객체 안에 객체를 넣으면 중첩 구조가 됩니다.
- 프로퍼티는 값을 직접 가지는 데이터 프로퍼티와, 읽기·쓰기 때 함수를 호출하는 접근자 프로퍼티로 나뉩니다. 접근자 프로퍼티는 이 편의 getter·setter 절에서 다룹니다.
- 모든 프로퍼티는 `writable`, `enumerable`, `configurable` 어트리뷰트를 가집니다. 리터럴로 만든 데이터 프로퍼티는 세 값이 모두 `true`입니다(자세히는 14편).

## 객체 리터럴

객체 리터럴(object literal)은 중괄호 안에 프로퍼티를 쉼표로 나열해 객체를 만드는 표기입니다. 중괄호만 쓰면 빈 객체가 됩니다.

```js
const empty = {}
const user = { name: 'Kim', age: 30 }
```

- 마지막 프로퍼티 뒤의 쉼표(trailing comma)도 허용됩니다(ES5).
- 리터럴을 평가할 때마다 새 객체가 만들어집니다. 내용이 같아도 서로 다른 객체이므로 `{} === {}`는 `false`입니다(자세히는 10편).
- 리터럴로 만든 뒤에도 프로퍼티를 추가하고 삭제할 수 있습니다.
- 리터럴 안에는 값 프로퍼티, 축약 프로퍼티, 계산된 이름, 메서드, getter·setter, `__proto__` 지정을 쓸 수 있습니다. 스프레드(`...obj`, ES2018)도 쓸 수 있지만 36편이 다룹니다.
- 중괄호는 문이 시작되는 자리에서는 블록으로, 표현식 자리에서는 객체 리터럴로 해석됩니다(자세히는 04편).
- JSON은 객체 리터럴과 모양이 비슷한 별도의 데이터 포맷입니다. 키를 큰따옴표 문자열로만 쓰는 등 규칙이 더 엄격합니다(자세히는 39편).

화살표 함수 본문의 `{`는 블록으로 해석됩니다. 객체를 반환하려면 괄호로 감쌉니다.

```js
const bad = () => { a: 1 }     // undefined (블록 + 레이블)
const good = () => ({ a: 1 })  // { a: 1 }
```

`bad`에서 `a:`는 레이블이고 `1`은 표현식 문이므로 반환값이 없습니다(자세히는 27편).

## 프로퍼티 키와 값

키는 문자열 또는 심벌이고, 값에는 제한이 없습니다. 값이 `undefined`여도 프로퍼티는 존재합니다. 리터럴에서 키를 쓰는 방식은 네 가지입니다.

| 형태 | 예 | 만들어지는 키 |
|------|----|---------------|
| 식별자 이름 | `name: 1` | `'name'` |
| 문자열 리터럴 | `'first-name': 1` | `'first-name'` |
| 숫자 리터럴 | `42: 1`, `0x10: 1` | `'42'`, `'16'` |
| 계산된 이름 | `[expr]: 1` | 평가 결과(아래 절) |

```js
const o = {
  name: 'Kim',          // 식별자 이름
  'first-name': 'Ann',  // 규칙 위반 → 따옴표 필수
  42: 'answer',         // 숫자 리터럴 → 키 '42'
  class: 'A',           // 예약어도 가능
  '': 'empty',          // 빈 문자열 키
  address: { city: 'Seoul' },  // 값이 객체
}
```

- 식별자 이름은 변수 이름과 같은 규칙을 따릅니다. 문자, `$`, `_`로 시작하고 이후에 숫자를 쓸 수 있으며 한글 같은 유니코드 문자도 가능합니다.
- 변수 이름과 달리 예약어(`class`, `if`, `new`)도 키로 쓸 수 있습니다(ES5).
- 식별자 규칙을 어기는 키(`first-name`, `a b`, `2nd`)와 빈 문자열 키는 따옴표를 붙인 문자열 리터럴로 써야 합니다. 작은따옴표와 큰따옴표는 같습니다.
- 키는 대소문자를 구분합니다. `name`과 `Name`은 다른 키입니다.
- 따옴표 없는 숫자 키는 문자열로 변환됩니다(키의 문자열 변환 절).
- 심벌 키는 계산된 이름으로만 리터럴에 쓸 수 있습니다(자세히는 34편).

## 마침표·대괄호 표기법

프로퍼티에 접근하는 표기는 두 가지입니다. 마침표 표기법은 `obj.key`, 대괄호 표기법은 `obj['key']`입니다. 읽을 때와 쓸 때 같은 표기를 씁니다.

```js
const user = {
  name: 'Kim',
  'first-name': 'Ann',
  1: 'one',
}
user.name           // 'Kim'
user['name']        // 'Kim'
user['first-name']  // 'Ann'
user[1]             // 'one'
```

| 상황 | 쓸 수 있는 표기 |
|------|-----------------|
| 식별자 이름인 고정 키 | 마침표, 대괄호 |
| 식별자 규칙을 어기는 키(`first-name`, `2nd`) | 대괄호만 |
| 변수나 표현식의 결과를 키로 쓸 때 | 대괄호만 |
| 숫자 키 | 대괄호만 |

- 대괄호 안은 표현식입니다. 문자열 키는 따옴표로 감싸야 하고, 따옴표 없이 쓴 이름은 변수로 평가됩니다.
- 마침표 뒤에는 식별자 이름만 올 수 있습니다. 예약어와 한글은 가능합니다(`obj.class`, `obj.이름`). 숫자로 시작하는 `obj.1`은 구문 오류입니다.
- 존재하지 않는 키를 읽으면 에러 없이 `undefined`입니다. 프로토타입 체인에 같은 이름이 있으면 그 값이 나옵니다. `({}).toString`은 `undefined`가 아니라 `Object.prototype`의 함수입니다(자세히는 17편).
- `null`이나 `undefined`의 프로퍼티를 읽거나 쓰면 TypeError입니다. 중첩 접근에서 중간 값이 없을 때 이 에러가 납니다.
- 옵셔널 체이닝 `?.`(ES2020)은 중간 값이 `null`이나 `undefined`이면 에러 대신 `undefined`로 끝냅니다(자세히는 08편).

```js
const key = 'name'
user[key]     // 'Kim'       (변수 key의 값이 키)
user['key']   // undefined   (문자열 'key'가 키)
user[title]   // title 미선언이면 ReferenceError

const u = {}
u.address.city   // TypeError
u.address?.city  // undefined
```

흔한 실수는 하이픈이 든 키에 마침표를 쓰는 것입니다. `h.first-name`은 뺄셈으로 해석되어 ReferenceError나 `NaN`이 됩니다.

```js
const h = { 'first-name': 'Ann' }
h.first-name     // ❌ h.first - name (뺄셈)
h['first-name']  // ✅ 'Ann'
```

## 프로퍼티 갱신·동적 생성·삭제

### 갱신과 동적 생성

할당문의 왼쪽이 이미 있는 프로퍼티이면 값이 바뀌고(갱신), 없으면 새 프로퍼티가 만들어집니다(동적 생성).

```js
const user = { name: 'Kim' }
user.name = 'Lee'     // 갱신
user.age = 30         // 동적 생성
user['job'] = 'dev'   // 대괄호로도 생성
user  // { name: 'Lee', age: 30, job: 'dev' }
```

- 새 프로퍼티 생성은 에러가 아닙니다. `user.nmae = 'x'` 같은 오타가 새 프로퍼티로 조용히 만들어집니다. strict mode에서도 같습니다.
- `const`로 선언한 객체의 프로퍼티도 바꿀 수 있습니다. `const`가 막는 것은 변수에 다른 값을 다시 할당하는 것뿐입니다(자세히는 03편, 10편).
- 쓰기가 허용되지 않는 경우가 있습니다: 읽기 전용 프로퍼티, getter만 있는 접근자 프로퍼티, 동결된 객체, 확장이 금지된 객체에 새 프로퍼티 추가. 비엄격 모드에서는 에러 없이 무시되고 strict mode에서는 TypeError입니다(자세히는 14편, 19편).

### 삭제

`delete`는 프로퍼티를 객체에서 완전히 제거하고 불리언을 반환합니다(연산자 자체는 06편).

```js
const user = { name: 'Kim', age: 30 }
delete user.age     // true
user.age            // undefined
'age' in user       // false
```

| 대상 | 비엄격 모드 | strict mode |
|------|-------------|-------------|
| 삭제할 수 있는 자신의 프로퍼티 | `true` | `true` |
| 존재하지 않는 프로퍼티 | `true` | `true` |
| 상속받은 프로퍼티 | `true`(삭제되지 않음) | `true`(삭제되지 않음) |
| `configurable`이 `false`인 프로퍼티 | `false` | TypeError |

- `delete`는 객체 자신의 프로퍼티만 지웁니다. 프로토타입에 같은 이름이 있으면 삭제 뒤에는 그 값이 읽힙니다.
- 삭제할 수 없는 프로퍼티의 예는 `Object.prototype`, 배열의 `length`입니다. 비엄격 모드에서 `delete Object.prototype`은 `false`입니다.
- `obj.a = undefined`와 `delete obj.a`는 다릅니다. 앞의 것은 키를 남기고 값만 `undefined`로 바꿉니다.

```js
const u = { a: 1 }
u.a = undefined
'a' in u         // true
Object.keys(u)   // ['a']
delete u.a
'a' in u         // false
Object.keys(u)   // []
```

`in`은 06편, 프로퍼티 존재 확인과 열거는 18편에서 다룹니다.

## 프로퍼티 축약

프로퍼티 축약(shorthand property)은 ES2015 문법입니다. 값이 변수이고 키가 그 변수 이름과 같으면 `: 값`을 생략할 수 있습니다.

```js
const x = 1
const y = 2
const p1 = { x: x, y: y }
const p2 = { x, y }      // p1과 같다. { x: 1, y: 2 }
const p3 = { x, z: 3 }   // 일반 프로퍼티와 섞어 쓸 수 있다
```

- 축약할 수 있는 값은 식별자 하나뿐입니다. `{ a.b }`처럼 점 접근이나 표현식은 구문 오류입니다.
- 변수 이름이 곧 키가 되므로, 변수 이름을 바꾸면 객체의 키도 바뀝니다.
- 예약어는 변수 이름이 될 수 없으므로 축약할 수 없습니다. `{ class }`는 구문 오류입니다.
- 선언되지 않은 변수를 축약하면 ReferenceError입니다.
- 함수가 여러 값을 객체로 묶어 반환할 때 `return { x, y }`로 자주 씁니다. 반대 방향인 구조 분해는 37편에서 다룹니다.

## 계산된 프로퍼티 이름

계산된 프로퍼티 이름(computed property name)은 키 자리에 `[표현식]`을 써서 평가 결과를 키로 쓰는 ES2015 문법입니다. ES5까지는 리터럴 안에서 계산된 키를 쓸 수 없어서, 객체를 만든 뒤 `obj[expr] = value`로 추가해야 했습니다.

```js
const field = 'age'
const user = {
  name: 'Kim',
  [field]: 30,               // 키 'age'
  [field + 'Group']: '30s',  // 키 'ageGroup'
  [`id_${1 + 1}`]: 'x',      // 키 'id_2'
}
```

- 대괄호 안에는 문자열 연결, 템플릿 리터럴, 함수 호출 등 어떤 표현식이든 쓸 수 있습니다.
- 평가 결과가 문자열이나 심벌이 아니면 문자열로 변환됩니다(다음 절).
- 평가 순서는 프로퍼티를 위에서 아래로 처리하되, 한 프로퍼티 안에서는 키 표현식 다음에 값 표현식입니다.
- 메서드와 접근자에도 쓸 수 있습니다: `[name]() {}`, `get [name]() {}`, `*[Symbol.iterator]() {}`.
- 심벌을 키로 쓰는 유일한 리터럴 문법입니다(자세히는 34편).
- 익명 함수를 값으로 쓰면 함수의 `name`이 계산된 키 값으로 정해집니다(자세히는 11편).
- 같은 키로 평가되는 계산된 이름이 둘 이상이면 뒤의 값이 앞의 값을 덮어씁니다. 실행 중에만 알 수 있으므로 에러가 아닙니다.
- 계산된 키가 `'__proto__'`여도 프로토타입을 지정하지 않고 일반 프로퍼티를 만듭니다.

```js
const log = []
const k = (n) => { log.push('k' + n); return 'key' + n }
const v = (n) => { log.push('v' + n); return n }
const o = { [k(1)]: v(1), [k(2)]: v(2) }
log  // ['k1', 'v1', 'k2', 'v2']
```

흔한 실수는 대괄호를 빠뜨리는 것입니다. 대괄호가 없으면 변수 이름이 문자열 그대로 키가 됩니다.

```js
const field = 'age'
const a = { field: 30 }    // { field: 30 }
const b = { [field]: 30 }  // { age: 30 }
```

## 키의 문자열 변환

프로퍼티 키는 문자열 또는 심벌입니다. 대괄호 표기법과 계산된 이름의 결과가 그 외 타입이면 ToPropertyKey 연산으로 변환합니다. 값을 먼저 원시 값으로 바꾸고(문자열 힌트의 ToPrimitive), 심벌이면 그대로 두고, 아니면 문자열로 바꿉니다. 따옴표 없는 숫자 리터럴 키도 문자열이 됩니다.

| 키로 쓴 값 | 변환된 키 | 이유 |
|------------|-----------|------|
| `1`, `1.0`, `1n`, `'1'` | `'1'` | 같은 숫자는 같은 문자열 |
| `0x10`, `1e3`, `.5` | `'16'`, `'1000'`, `'0.5'` | 값을 10진 표기로 변환 |
| `-0` | `'0'` | 음의 0도 `'0'` |
| `null`, `undefined`, `true` | `'null'`, `'undefined'`, `'true'` | 값의 문자열 표기 |
| `[1, 2]` | `'1,2'` | 배열의 `toString` |
| `{}` | `'[object Object]'` | 객체의 기본 `toString` |

- `obj[1]`과 `obj['1']`은 같은 프로퍼티입니다. 배열의 `arr[0]`도 키가 `'0'`인 프로퍼티입니다(자세히는 28편).
- 객체가 `toString`을 직접 정의하면 그 반환값이 키가 됩니다.
- 심벌은 변환되지 않고 그대로 키가 됩니다.

객체를 키로 쓰면 일반 객체는 모두 같은 문자열 `'[object Object]'`가 되어 키가 충돌합니다. 객체 자체를 키로 쓰려면 `Map`이나 `WeakMap`을 씁니다(자세히는 38편).

```js
const a = {}
const b = {}
const cache = {}
cache[a] = 'A'
cache[b] = 'B'
Object.keys(cache)  // ['[object Object]']
cache[a]            // 'B'
```

키가 항상 문자열이므로 `Object.keys`와 `for...in`이 돌려주는 키도 문자열입니다.

```js
const o = { 1: 'a' }
Object.keys(o)           // ['1']
Object.keys(o)[0] === 1  // false (문자열 '1')
```

## 메서드 축약

메서드 축약(method shorthand)은 함수를 값으로 가지는 프로퍼티를 `이름() { ... }`으로 쓰는 ES2015 문법입니다.

```js
const counter = {
  count: 0,
  inc: function () { this.count++ },  // ES5 방식
  dec() { this.count-- },             // 메서드 축약
}
```

문법만 짧아진 것이 아니라 만들어지는 함수의 성질이 다릅니다.

| 항목 | `f: function () {}` | `f() {}` |
|------|---------------------|----------|
| `new`로 생성자 호출 | 가능 | TypeError (not a constructor) |
| `prototype` 프로퍼티 | 있음 | 없음 |
| `super` 참조 | 불가(구문 오류) | 가능 |

- `super`는 메서드가 가진 내부 슬롯 [[HomeObject]]로 프로토타입의 프로퍼티를 찾습니다(자세히는 27편).
- 함수 표현식에 이름을 붙이면(`f: function g() {}`) `g`가 함수 안에서 보여 재귀 호출에 쓸 수 있습니다(자세히는 11편). 메서드 축약은 이름을 따로 붙일 수 없고 `f`도 스코프에 만들어지지 않으므로, 재귀 호출은 `this.f()`처럼 객체를 거쳐야 합니다.
- 종류는 일반 `m() {}`, 비동기 `async m() {}`, 제너레이터 `*m() {}`, 비동기 제너레이터 `async *m() {}`, 계산된 이름 `[k]() {}`가 있습니다(자세히는 42편, 43편). getter와 setter는 별도 절에서 다룹니다.
- 리터럴로 만든 메서드는 열거 가능한 일반 데이터 프로퍼티입니다. 클래스 메서드는 열거되지 않습니다(자세히는 24편).

```js
const math = {
  fact(n) {
    // ❌ fact(n - 1): ReferenceError, 메서드 이름은 스코프에 없다
    return n <= 1 ? 1 : n * this.fact(n - 1)  // ✅
  },
}
math.fact(3) // 6
```

흔한 실수는 객체 메서드를 화살표 함수로 쓰는 것입니다. 화살표 함수는 자체 `this`가 없어서 바깥 스코프의 `this`를 씁니다(자세히는 21편).

```js
const user = {
  name: 'Kim',
  hi() { return this.name },  // ✅ this는 user
  bye: () => this.name,       // ❌ 바깥 스코프의 this
}
```

## 프로퍼티 열거 순서 규칙

객체의 프로퍼티는 키의 종류와 생성 순서에 따라 정해진 순서로 나열됩니다. ECMA-262는 객체 자신의 키 순서를 다음과 같이 정합니다.

1. 배열 인덱스인 키를 숫자 오름차순으로
2. 그 밖의 문자열 키를 생성된 순서대로
3. 심벌 키를 생성된 순서대로

```js
const s = Symbol('s')
const o = { b: 1, 2: 'x', [s]: 0, a: 2, 1: 'y' }
Object.keys(o)      // ['1', '2', 'b', 'a']
Reflect.ownKeys(o)  // ['1', '2', 'b', 'a', Symbol(s)]
```

- 배열 인덱스는 `0 ≤ i ≤ 2^32 - 2`인 정수를 10진수로 쓴 문자열입니다. `'01'`, `'-1'`, `'1.5'`와 `'4294967295'`는 인덱스가 아니므로 일반 문자열 키처럼 생성 순서를 따릅니다.
- 이미 있는 프로퍼티의 값을 바꿔도 위치는 그대로입니다. 삭제한 뒤 다시 추가하면 해당 종류의 맨 뒤로 갑니다.
- 이 순서를 따르는 API는 `Object.keys`, `Object.values`, `Object.entries`, `Object.getOwnPropertyNames`, `Reflect.ownKeys`, `JSON.stringify`, `for...in`입니다. 심벌은 `Reflect.ownKeys`와 `Object.getOwnPropertySymbols`에만 나옵니다.
- `for...in`은 객체 자신의 프로퍼티를 이 순서로 방문한 뒤 프로토타입의 프로퍼티를 방문합니다. 이 순서가 명세에 들어온 것은 ES2020입니다.
- 모든 키를 삽입 순서로 유지해야 하면 `Map`을 씁니다(자세히는 38편). 열거 API의 비교는 18편에서 다룹니다.

흔한 실수는 정수처럼 생긴 키가 삽입 순서를 따른다고 믿는 것입니다.

```js
const ranking = { 30: 'C', 10: 'A', 20: 'B', name: 'x' }
Object.keys(ranking) // ['10', '20', '30', 'name']
```

## 리터럴의 getter·setter

getter와 setter는 `get 이름() {}`과 `set 이름(값) {}`으로 접근자 프로퍼티를 만드는 문법입니다(ES5). 접근자 프로퍼티는 값을 저장하지 않고, 읽을 때 getter를 호출하고 쓸 때 setter를 호출합니다. 값을 직접 가지는 일반 프로퍼티는 데이터 프로퍼티라고 합니다(자세히는 14편).

```js
const person = {
  first: 'Ada',
  last: 'Lovelace',
  get full() {
    return `${this.first} ${this.last}`
  },
  set full(v) {
    const parts = v.split(' ')
    this.first = parts[0]
    this.last = parts[1]
  },
}
```

```js
person.full                   // 'Ada Lovelace' (getter 호출)
person.full = 'Grace Hopper'  // setter 호출
person.first                  // 'Grace'
```

- getter는 매개변수가 없어야 하고 setter는 정확히 하나여야 합니다. 어기면 구문 오류입니다.
- 둘 중 하나만 정의해도 됩니다. getter만 있는 프로퍼티에 쓰면 비엄격 모드에서는 무시되고 strict mode에서는 TypeError입니다. setter만 있는 프로퍼티를 읽으면 `undefined`입니다.
- 같은 이름의 `get`과 `set`은 하나의 접근자 프로퍼티로 합쳐집니다.
- getter와 setter 안의 `this`는 접근에 쓴 객체입니다. 프로토타입에서 상속받은 접근자도 마찬가지입니다.
- 접근자 프로퍼티는 열거 가능한 소유 프로퍼티입니다. `Object.keys`에 나오고, `JSON.stringify`는 getter를 호출해 결과 값을 직렬화합니다.
- 계산된 이름과 함께 쓸 수 있습니다: `get [k]() {}`.
- `get`과 `set` 뒤에 이름이 오지 않으면 평범한 키입니다. `{ get: 1 }`, `{ get() {} }`, 축약 `{ get }`은 모두 일반 프로퍼티입니다.
- 접근자 프로퍼티는 `Object.defineProperty`로도 만들 수 있습니다(자세히는 14편).
- 용도는 다른 프로퍼티에서 계산되는 값 제공과 쓰기 때의 검증·가공입니다.

흔한 실수는 getter나 setter 안에서 같은 이름의 프로퍼티에 접근하는 것입니다. 자기 자신을 다시 호출해 무한 재귀가 되고 RangeError로 끝납니다.

```js
const bad = {
  get a() { return this.a },        // ❌ RangeError
  set a(v) { this.a = v },          // ❌ RangeError
}
```

값을 따로 보관할 프로퍼티를 두고 그쪽을 읽고 씁니다.

## 리터럴의 `__proto__` 키

객체 리터럴에서 `__proto__: 값` 형태의 프로퍼티는 프로퍼티를 만들지 않고 새 객체의 프로토타입을 그 값으로 지정합니다(ES2015). 프로토타입은 프로퍼티를 찾지 못했을 때 이어서 찾는 상위 객체입니다(자세히는 17편).

```js
const base = { hi() { return 'hi' } }
const obj = { __proto__: base, own: 1 }
obj.hi()                            // 'hi' (base에서 상속)
Object.keys(obj)                    // ['own']
Object.getPrototypeOf(obj) === base // true
```

- 값이 객체나 `null`일 때만 프로토타입이 지정됩니다. 다른 값(원시 값)이면 에러도 프로퍼티도 없이 무시됩니다.
- `'__proto__': 값`처럼 문자열 리터럴로 써도 같습니다.
- 콜론 없는 형태는 프로토타입을 지정하지 않고 `__proto__`라는 이름의 일반 프로퍼티를 만듭니다: 축약 `{ __proto__ }`, 메서드 `{ __proto__() {} }`, 계산된 이름 `{ ['__proto__']: v }`.
- 콜론 형태의 `__proto__`를 한 리터럴에 두 번 쓰면 구문 오류입니다.
- `{ __proto__: null }`은 프로토타입이 없는 객체를 만듭니다. `toString` 같은 `Object.prototype`의 메서드를 상속받지 않아 키 충돌이 없는 사전처럼 쓸 수 있습니다. 대신 `String(obj)`나 템플릿 리터럴 변환은 TypeError가 됩니다.
- 이미 만든 객체의 `obj.__proto__`로 읽고 쓰는 접근자는 `Object.prototype`이 상속해 주는 호환용 기능입니다. 표준 방법은 `Object.getPrototypeOf`와 `Object.setPrototypeOf`입니다(자세히는 17편). 리터럴 문법과는 별개입니다.

흔한 실수는 외부에서 받은 키로 프로퍼티를 만드는 코드입니다. `obj[key] = value`에서 `key`가 `'__proto__'`이면 프로퍼티가 생기지 않고 상속받은 setter가 실행되어 프로토타입이 바뀝니다(프로토타입 오염은 17편). 프로토타입이 없는 객체(`Object.create(null)`)에서는 평범한 키가 되고, `Map`을 쓰면 이 문제가 없습니다.

```js
const e = {}
e['__proto__'] = base
Object.keys(e)                    // []
Object.getPrototypeOf(e) === base // true
```

## 중복 키

한 리터럴에서 같은 키를 여러 번 쓰면 마지막 값이 앞의 값을 덮어씁니다. 에러가 아닙니다.

```js
const o = { a: 1, b: 2, a: 3 }
o               // { a: 3, b: 2 }
Object.keys(o)  // ['a', 'b'] (위치는 처음 쓴 자리)
```

- 같은 문자열로 환산되면 중복입니다: `{ 1: 'a', '1': 'b', 0x1: 'c' }`는 `{ '1': 'c' }`입니다.
- ES5의 strict mode에서는 중복 키가 구문 오류였습니다. 계산된 이름 때문에 중복을 실행 중에만 알 수 있게 되어 ES2015에서 이 제한이 없어졌고, 지금은 모드와 관계없이 허용됩니다.
- 예외는 콜론 형태의 `__proto__` 중복으로, 구문 오류입니다.
- 데이터 프로퍼티와 접근자 프로퍼티가 같은 이름이면 나중에 쓴 쪽이 이깁니다. `{ get a() {...}, a: 2 }`는 데이터 프로퍼티 `a: 2`가 되고, `{ a: 2, get a() {...} }`는 getter만 있는 접근자 프로퍼티가 됩니다.
- 같은 이름의 `get`과 `set` 한 쌍은 중복이 아니라 하나로 합쳐집니다.
- 스프레드로 합칠 때도 같은 원리입니다. `{ ...a, ...b }`에서 같은 키는 뒤쪽 값이 남습니다(자세히는 36편).

흔한 실수는 긴 리터럴에서 같은 키를 실수로 두 번 쓰는 것입니다. 앞의 값이 에러 없이 사라지므로 린터의 `no-dupe-keys` 규칙으로 잡습니다.

## 핵심 정리

- 객체는 프로퍼티(키와 값의 쌍)의 모음이고, 값이 함수인 프로퍼티를 메서드라고 합니다. 원시 값 7종을 뺀 모든 값이 객체입니다.
- 키는 문자열이나 심벌이며, 다른 값은 문자열로 변환됩니다. 식별자 규칙을 어기는 키와 변수로 정한 키는 대괄호 표기법으로 접근합니다.
- 없는 키에 할당하면 새 프로퍼티가 생기고, `delete`는 자신의 프로퍼티만 제거합니다. `const`는 프로퍼티 변경을 막지 못합니다.
- 프로퍼티 축약, 계산된 이름, 메서드 축약은 ES2015 문법입니다. 메서드 축약으로 만든 함수는 생성자로 호출할 수 없습니다.
- 열거 순서는 배열 인덱스 오름차순, 그 밖의 문자열 키의 생성 순서, 심벌 키의 생성 순서입니다.
- 리터럴의 `__proto__: 객체`는 프로토타입을 지정하고, 같은 키를 여러 번 쓰면 마지막 값이 남습니다.
