## 이터레이션 프로토콜

이터레이션 프로토콜(iteration protocol)은 값을 하나씩 꺼내는 방법을 정한 ES2015의 규약입니다. 값을 내놓는 쪽(배열, `Set`, 직접 만든 객체)과 꺼내 쓰는 쪽(`for...of`, 스프레드, 구조 분해)이 이 규약만 지키면 서로를 몰라도 연결됩니다.

```mermaid
graph LR
  A["배열, Set, Map, 문자열, 사용자 객체"] --> P(("이터레이션 프로토콜"))
  P --> B["for...of, 스프레드, 구조 분해, Array.from"]
```

ES5까지는 자료구조마다 순회 방법이 달랐습니다(배열은 인덱스 for 문, 객체는 `for...in`). 규약이 생긴 뒤로는 공급자와 소비자가 각자 규약 하나만 구현하면 모든 조합이 동작합니다.

규약은 두 개입니다.

| 프로토콜 | 요구 사항 |
|----------|-----------|
| 이터러블 프로토콜 | `Symbol.iterator` 키의 메서드가 이터레이터를 반환한다 |
| 이터레이터 프로토콜 | `next()` 메서드가 `{ value, done }` 객체를 반환한다 |

- 규약은 인터페이스입니다. 특정 클래스를 상속할 필요 없이 조건을 만족하는 객체이면 됩니다.
- 비동기 값을 꺼내는 별도 규약은 `Symbol.asyncIterator`와 프로미스를 반환하는 `next()`를 씁니다(자세히는 43편).

## 이터러블

이터러블(iterable)은 `Symbol.iterator` 키로 이터레이터를 반환하는 메서드를 가진 객체입니다. `for...of`가 순회할 수 있는 대상이 이터러블입니다. `Symbol.iterator`는 언어가 정의한 잘 알려진 심벌입니다(자세히는 34편).

```js
const arr = [10, 20]
typeof arr[Symbol.iterator]   // 'function'
const iter = arr[Symbol.iterator]()
iter.next()                   // { value: 10, done: false }
```

이터러블인지 확인하는 코드입니다.

```js
const isIterable = v =>
  v != null && typeof v[Symbol.iterator] === 'function'

isIterable('abc')     // true
isIterable(new Map()) // true
isIterable(123)       // false
isIterable({ a: 1 })  // false
```

- `Symbol.iterator` 메서드는 인수 없이 호출되고, 이터레이터 객체를 반환해야 합니다. 객체가 아닌 값을 반환하면 소비하는 시점에 TypeError입니다.
- 프로퍼티 조회는 원시 값을 래퍼 객체로 바꾸므로 문자열은 이터러블입니다. 숫자, 불리언, `null`, `undefined`는 아닙니다.
- 메서드가 객체 자신에 있든 프로토타입에 있든 상관없습니다. 배열의 `Symbol.iterator`는 `Array.prototype`에 있습니다.

흔한 실수는 일반 객체를 이터러블로 착각하는 것입니다.

```js
const user = { name: 'kim', age: 30 }
for (const x of user) {}   // ❌ TypeError (not iterable)
const copy = [...user]     // ❌ TypeError
const obj = { ...user }    // ✅ 객체 스프레드는 별개 문법
```

객체 스프레드 `{ ...obj }`는 이터레이션 프로토콜을 쓰지 않습니다(자세히는 36편). 일반 객체의 키와 값은 `Object.entries`로 배열을 만들어 순회합니다(자세히는 18편).

## 이터레이터와 next

이터레이터(iterator)는 `next()` 메서드를 가진 객체이고, `next()`를 호출할 때마다 이터레이터 결과 객체를 반환합니다.

| 프로퍼티 | 의미 |
|----------|------|
| `value` | 이번에 꺼낸 값. `done`이 `true`일 때는 반환값(보통 `undefined`) |
| `done` | 순회가 끝났으면 `true`, 아직 값이 있으면 `false` |

```js
const it = ['a', 'b'][Symbol.iterator]()
it.next()   // { value: 'a', done: false }
it.next()   // { value: 'b', done: false }
it.next()   // { value: undefined, done: true }
it.next()   // { value: undefined, done: true }
```

- 이터레이터는 상태를 가진 일방향 커서입니다. 되돌리거나 복제할 수 없고, `next()`를 호출한 만큼 앞으로 갑니다.
- 끝난 뒤에도 `next()`가 계속 `done: true`를 반환하는 것이 관례입니다.
- `done`을 생략하면 `undefined`이므로 거짓으로 취급됩니다. `done: true`일 때 `value`도 생략할 수 있습니다.
- `done: true`와 함께 온 `value`는 `for...of`, 스프레드, `Array.from`이 버립니다. 제너레이터의 `return x`가 이 자리로 나옵니다(자세히는 42편).
- `next()`가 객체가 아닌 값을 반환하면 TypeError(`Iterator result 1 is not an object`)입니다.
- `for...of`는 시작할 때 `next` 메서드를 한 번 읽어 저장합니다. 순회 도중 `it.next`를 다른 함수로 바꿔도 반영되지 않습니다.
- `next(arg)`는 인수를 받을 수 있지만 `for...of`는 항상 인수 없이 호출합니다. 인수는 제너레이터가 씁니다(자세히는 42편).
- 선택 메서드로 `return()`(아래 이터레이터 종료 절)과 `throw()`가 있습니다. `throw()`는 `yield*`가 위임할 때 쓰입니다(자세히는 42편).

흔한 실수는 두 가지입니다.

- `done: true`를 반환하는 조건을 빠뜨려 순회가 끝나지 않습니다.
- `next()`만 가진 객체는 이터레이터일 뿐 이터러블이 아닙니다. `for (const x of { next() {} })`는 TypeError입니다. `Symbol.iterator` 메서드가 있어야 소비자가 받습니다.

## 빌트인 이터러블

| 값 | 꺼내는 값 | 비고 |
|----|-----------|------|
| `Array` | 요소(구멍은 `undefined`) | 기본 이터레이터는 `values()`와 같은 함수 |
| `String` | 코드 포인트 하나씩 | `'😀'`는 한 번에 나온다(자세히는 33편) |
| `Map` | `[키, 값]` 배열 | 기본 이터레이터는 `entries()`와 같은 함수 |
| `Set` | 값 | `keys()`와 `values()`는 같은 함수 |
| `TypedArray` | 요소 | 자세히는 48편 |
| `arguments` | 인수 | 유사 배열이기도 하다 |
| 제너레이터 객체 | `yield`한 값 | 자세히는 42편 |
| `matchAll()` 결과 | 매치 배열 | 자세히는 32편 |

일반 객체, `WeakMap`, `WeakSet`, 숫자·불리언 같은 원시 값은 이터러블이 아닙니다(`WeakMap`·`WeakSet`은 38편).

`Array`, `Map`, `Set`, `TypedArray`에는 `keys()`, `values()`, `entries()`가 있고, 셋 모두 배열이 아니라 이터레이터를 반환합니다.

```js
const m = new Map([['a', 1], ['b', 2]])
const keys = [...m.keys()]    // ['a', 'b']
const pairs = [...m]          // [['a', 1], ['b', 2]]
const s = new Set([1])
const sp = [...s.entries()]   // [[1, 1]] (값, 값 쌍)
```

- 순회는 실시간 상태를 봅니다. 순회 중에 추가한 요소는 뒤에서 방문하고, 방문 전에 삭제한 요소는 방문하지 않습니다.

```js
const s = new Set([1, 2, 3])
for (const x of s) {
  console.log(x)          // 1, 3
  if (x === 1) s.delete(2)
}
```

- 배열에 조건 없이 `push`하며 `for...of`를 돌리면 새 요소까지 계속 방문해서 끝나지 않습니다.
- 구멍 난 배열 `[, 1]`을 펼치면 `[undefined, 1]`입니다. 구멍도 `undefined` 값으로 꺼냅니다.
- ES2025부터 모든 빌트인 이터레이터가 `Iterator.prototype`을 상속하므로 `[].values().map(...)`처럼 헬퍼 메서드를 씁니다(아래 Iterator Helpers 절).
- DOM의 `NodeList`와 `URLSearchParams` 같은 호스트 객체도 이터러블로 정의되어 있지만 ECMAScript가 아니라 웹 표준의 몫입니다.

## for...of

`for...of`는 이터러블이 내놓는 값을 하나씩 변수에 꺼내 본문을 실행하는 반복문입니다.

```js
for (const ch of 'a😀') console.log(ch)   // 'a', '😀'
for (const [k, v] of new Map([['x', 1]])) {
  console.log(k, v)                       // 'x' 1
}
for (const [i, v] of ['a', 'b'].entries()) {
  console.log(i, v)                       // 0 'a', 1 'b'
}
```

동작 순서는 다음과 같습니다.

1. 오른쪽 식을 한 번 평가하고 `[Symbol.iterator]()`를 호출해 이터레이터를 얻습니다.
2. `next()`를 호출합니다. `done`이 `true`이면 종료합니다.
3. `value`를 변수에 바인딩하고 본문을 실행합니다.
4. 2번으로 돌아갑니다. `break`, `return`, `throw`로 빠져나가면 `return()`을 호출합니다(아래 이터레이터 종료 절).

```js
const it = iterable[Symbol.iterator]()
let r = it.next()
while (!r.done) {
  const x = r.value
  // 본문
  r = it.next()
}
```

- 이터러블이 아니면 첫 반복 전에 TypeError(`x is not iterable`)입니다.
- `const`와 `let`은 반복마다 새 바인딩을 만들어 `const`로 선언할 수 있고, 본문의 클로저가 각 값을 따로 붙잡습니다(자세히는 12편, 13편). `var`는 하나를 공유합니다.
- 머리에는 기존 변수 `for (x of list)`와 구조 분해 패턴 `for (const [a, b] of pairs)`를 쓸 수 있습니다.
- `break`, `continue`, 레이블, `return`, `throw`를 모두 쓸 수 있습니다. `forEach`와 달리 중간에 끝낼 수 있고, 본문의 `await`가 반복을 기다립니다(자세히는 43편).
- 비동기 이터러블은 `for await...of`로 순회합니다(자세히는 43편).
- `for...in`은 열거 가능한 문자열 키를 상속까지 포함해 돕니다. 비교는 07편, 열거 규칙은 18편에서 다룹니다.

흔한 실수입니다.

```js
for (const x of ['a', 'b']) {}   // x는 값 (인덱스가 아님)
for (const [k, v] of { a: 1 }) {}   // ❌ TypeError
const o = Object.entries({ a: 1 })
for (const [k, v] of o) {}          // ✅
```

## 이터러블과 유사 배열 객체

유사 배열 객체(array-like)는 음이 아닌 정수 `length`와 `0`, `1`, ... 인덱스 키를 가진 객체입니다. 인덱스로 읽을 수 있을 뿐 배열 메서드는 없고, 이터러블과는 별개 개념입니다.

| 값 | 유사 배열 | 이터러블 |
|----|-----------|----------|
| 배열, 문자열, `arguments`, `TypedArray` | O | O |
| `{ length: 2, 0: 'a', 1: 'b' }` | O | X |
| `Set`, `Map`, 제너레이터 객체 | X | O |
| `{ a: 1 }` | X | X |

`Set`과 `Map`은 `length`가 아니라 `size`를 가져서 유사 배열이 아닙니다. `new Set([1])[0]`과 `new Set([1]).length`는 모두 `undefined`입니다.

```js
const al = { length: 2, 0: 'a', 1: 'b' }
Array.from(al)                 // ['a', 'b']
Array.from({ length: 2 })      // [undefined, undefined]
Array.from({ length: 3 }, (_, i) => i)   // [0, 1, 2]
const copy = [...al]        // ❌ TypeError (not iterable)
```

- 이터레이션 프로토콜을 쓰는 문법(스프레드, 구조 분해, `for...of`, `new Set()`, `Promise.all`)은 유사 배열을 받지 못합니다.
- `Array.from`은 둘 다 받습니다. `Symbol.iterator`가 있으면 프로토콜로, 없으면 `length`만큼 인덱스를 읽어 배열을 만듭니다. 둘 다 있으면 이터러블이 우선입니다.
- `Function.prototype.apply`의 인수 목록과 `Array.prototype.slice.call(obj)` 같은 범용 배열 메서드 호출은 이터레이터가 아니라 `length`와 인덱스를 씁니다(자세히는 28편).
- 문자열은 양쪽 모두에 속하지만 단위가 다릅니다. 유사 배열로는 UTF-16 코드 유닛, 이터러블로는 코드 포인트입니다.

```js
Array.from('😀')   // ['😀']
Array.prototype.map.call('😀', c => c)
// ['\ud83d', '\ude00']
```

- 이터러블은 `length`를 모를 수 있고 무한할 수도 있어서 인덱스 접근이 없습니다. 인덱스가 필요하면 `Array.from(iterable)`로 배열을 만든 뒤 씁니다.
- `arguments`나 오래된 DOM 컬렉션 같은 유사 배열은 `Array.from(arrayLike)`로 배열을 만든 뒤 배열 메서드를 씁니다.

## 사용자 정의 이터러블

사용자 정의 이터러블은 `Symbol.iterator` 메서드를 직접 구현한 객체입니다. 구현하면 스프레드, 구조 분해, `Array.from`, `Set` 생성자 같은 소비자를 따로 고치지 않고 그대로 쓸 수 있습니다.

```js
const range = {
  from: 1,
  to: 3,
  [Symbol.iterator]() {
    let current = this.from
    const last = this.to
    return {
      next: () => current <= last
        ? { value: current++, done: false }
        : { value: undefined, done: true },
    }
  },
}
```

```js
const nums = [...range]         // [1, 2, 3]
const max = Math.max(...range)  // 3
const set = new Set(range)      // Set(3) { 1, 2, 3 }
const [first, second] = range   // 1, 2
```

- `[Symbol.iterator]()`는 호출마다 새 이터레이터와 새 상태(`current`)를 만들어야 합니다. 그래야 같은 이터러블을 여러 번, 중첩해서 순회할 수 있습니다.
- `[Symbol.iterator]()`는 메서드로 호출되므로 `this`가 이터러블입니다. `next`는 화살표 함수로 두고 클로저 변수만 씁니다(자세히는 21편).
- 클래스에서는 제너레이터 메서드가 가장 짧은 구현입니다(자세히는 42편).

```js
class Countdown {
  constructor(n) { this.n = n }
  *[Symbol.iterator]() {
    for (let i = this.n; i > 0; i--) yield i
  }
}
const list = [...new Countdown(3)]   // [3, 2, 1]
```

흔한 실수는 상태를 이터러블 객체에 두는 것입니다. 첫 순회가 상태를 소진해서 두 번째부터 빈 결과가 나옵니다.

```js
const bad = {
  to: 3, current: 1,            // ❌ 상태가 이터러블에 있다
  [Symbol.iterator]() {
    return {
      next: () => this.current <= this.to
        ? { value: this.current++, done: false }
        : { value: undefined, done: true },
    }
  },
}
const a = [...bad]   // [1, 2, 3]
const b = [...bad]   // []
```

## 이터러블이면서 이터레이터인 객체

이터러블이면서 이터레이터인 객체는 `next()`를 가지고, `Symbol.iterator` 메서드가 자기 자신(`this`)을 반환하는 객체입니다. 이터레이터를 이터러블을 요구하는 자리에 그대로 넣기 위한 형태입니다.

```js
const it = [1, 2, 3].values()
it[Symbol.iterator]() === it   // true: 자기 자신을 반환
for (const x of it) {}         // 바로 넣을 수 있다
```

모든 빌트인 이터레이터(배열, `Map`, `Set`, 문자열 이터레이터)와 제너레이터 객체가 이 형태입니다. 같은 이유로 `new Set(map.keys())`처럼 이터레이터를 이터러블 자리에 넘길 수 있습니다. `Iterator.prototype`이 `[Symbol.iterator]() { return this }`를 정의하므로 `Iterator`를 상속하는 이터레이터는 이 메서드를 물려받습니다.

직접 만들 때는 두 메서드를 모두 둡니다.

```js
function countTo(max) {
  let n = 0
  return {
    next: () => n < max
      ? { value: ++n, done: false }
      : { value: undefined, done: true },
    [Symbol.iterator]() { return this },
  }
}
```

`Iterator`를 상속하면 `Symbol.iterator`와 헬퍼 메서드(ES2025)를 함께 얻습니다. `new Iterator()`로 직접 만들 수는 없고(추상 클래스, TypeError) 상속만 가능합니다.

```js
class Counter extends Iterator {
  n = 0
  next() {
    return this.n < 3
      ? { value: this.n++, done: false }
      : { value: undefined, done: true }
  }
}
new Counter().map(x => x * 2).toArray()   // [0, 2, 4]
```

이터러블과의 차이는 순회 횟수에서 드러납니다.

| 구분 | 이터러블 (배열, `Map`, `Set`, 문자열) | 이터러블이면서 이터레이터 (제너레이터 객체, 빌트인 이터레이터) |
|------|----------------------------------------|------------------------------------------------------------------|
| `[Symbol.iterator]()` | 호출마다 새 이터레이터 | `this` 반환 |
| 순회 횟수 | 몇 번이든 | 한 번 |
| 중간에 멈춘 뒤 | 다음 순회는 처음부터 | 같은 객체로 이어서 순회 |

```js
const it = [1, 2, 3].values()
const a = [...it]   // [1, 2, 3]
const b = [...it]   // []  (이미 소진)
```

- 중간에 멈춘 뒤 이어 쓸 수 있는지는 `return()`에 달려 있습니다. 배열 이터레이터에는 `return()`이 없어서 `break` 뒤에도 이어서 꺼낼 수 있고, 제너레이터 객체는 `break`로 닫혀서 이어 쓸 수 없습니다.

```js
const it = [1, 2, 3, 4].values()
for (const x of it) { if (x === 2) break }
const rest = [...it]   // [3, 4]
```

- 흔한 실수: 제너레이터 객체를 변수에 담아 두 번 순회하면 두 번째는 비어 있습니다. 제너레이터 함수를 다시 호출하거나 `toArray()`로 배열에 저장해서 씁니다.

## 이터레이터 종료: return

이터레이터 종료는 소비자가 끝까지 가지 않고 순회를 멈출 때 이터레이터의 `return()` 메서드를 호출해 정리할 기회를 주는 규칙입니다. 순회 중에 잡아 둔 파일 핸들이나 연결을 푸는 데 씁니다. `return()`은 선택 사항입니다.

```js
const source = {
  [Symbol.iterator]() {
    let i = 0
    return {
      next: () => ({ value: i++, done: false }),
      return() {
        console.log('closed')
        return { done: true }
      },
    }
  },
}
for (const x of source) { if (x === 1) break }   // 'closed'
```

`return()`이 호출되는 경우와 아닌 경우입니다.

| 상황 | `return()` |
|------|------------|
| `for...of`의 `break`, `return`, `throw`, 레이블로 바깥 반복문 탈출 | 호출 |
| 구조 분해가 필요한 개수만 꺼내고 멈춤 (`const [a] = it`) | 호출 |
| `Array.from(it, fn)` 중 `fn`이 예외를 던짐 | 호출 |
| `find`, `some`, `every`, `take`가 중간에 멈춤 | 호출 |
| `continue`, 끝까지 순회해 `done: true`를 받음 | 호출 안 함 |
| 스프레드, `Array.from`, `new Set(it)`로 끝까지 소비 | 호출 안 함 |
| 구조 분해의 rest (`[a, ...rest]`) | 호출 안 함 |
| `next()` 자체가 예외를 던짐 | 호출 안 함 |

- 구조 분해는 필요한 개수만 꺼내고 그 뒤를 확인하지 않습니다. 이터레이터에 값이 정확히 3개라도 `const [a, b, c] = it`은 `done`을 보지 못해서 `return()`을 호출합니다. 4개를 요구하면 `done`을 만나므로 호출하지 않습니다.
- `break` 같은 정상 종료에서 `return()`이 객체가 아닌 값을 반환하면 TypeError입니다. 반환값 자체는 소비자가 쓰지 않습니다.
- `throw`로 빠져나갈 때는 `return()`의 반환값과 예외를 무시하고 원래 예외를 전달합니다. `break`일 때는 `return()`이 던진 예외가 전파됩니다.
- 제너레이터는 `return()`을 자동으로 구현해서, `break`하면 `finally` 블록이 실행됩니다(자세히는 42편).

```js
function* open() {
  try { yield 1; yield 2 }
  finally { console.log('cleanup') }
}
for (const x of open()) break   // 'cleanup'
```

- 흔한 실수: 정리를 `done: true`를 반환할 때만 구현하고 `return()`을 빠뜨리면, `break`로 중단했을 때 자원이 정리되지 않습니다.

## 프로토콜을 쓰는 문법 목록

| 분류 | 문법·API | 소비 방식 |
|------|----------|-----------|
| 반복문 | `for...of` | 끝까지 또는 `break`까지 |
| 스프레드 | `[...x]`, `f(...x)` | 끝까지 (자세히는 36편) |
| 구조 분해 | `const [a, b] = x` | 필요한 개수만 (자세히는 37편) |
| 제너레이터 | `yield*` | 안쪽 이터러블에 위임 (자세히는 42편) |
| 배열 | `Array.from(x)` | 끝까지. 유사 배열도 받는다 |
| 컬렉션 | `new Map(x)`, `new Set(x)`, `new WeakMap(x)`, `new WeakSet(x)` | 끝까지 (자세히는 38편) |
| 객체 | `Object.fromEntries(x)`, `Object.groupBy(x, fn)`, `Map.groupBy(x, fn)` | 끝까지 |
| 프로미스 | `Promise.all`, `allSettled`, `race`, `any` | 끝까지 (자세히는 41편) |
| 기타 | `new Int8Array(x)`, `Int8Array.from(x)`, `new AggregateError(x)`, `Intl.ListFormat`의 `format(x)` | 끝까지 |
| 이터레이터 | `Iterator.from`, `Iterator.concat`, `Iterator.zip` | 이 편 아래 절 |
| 비동기 | `for await...of`, `Array.fromAsync` | `Symbol.asyncIterator`를 먼저 보고 없으면 `Symbol.iterator` (자세히는 43편) |

이터레이션 프로토콜을 쓰지 않는 것들입니다.

- `for...in`, `Object.keys`, `Object.values`, `Object.entries`: 프로퍼티 키를 열거합니다(자세히는 18편).
- 객체 스프레드 `{ ...x }`: 자기 열거 가능 프로퍼티를 복사합니다.
- 배열 메서드(`forEach`, `map` 등)와 `apply`의 인수 목록: `length`와 인덱스를 씁니다.
- `Array.prototype.concat`: 배열만 펼치고 `Set` 같은 이터러블은 요소 하나로 넣습니다.
- `Set`의 집합 메서드(`union` 등)의 인수: 이터러블이 아니라 `size`, `has`, `keys`를 가진 객체를 받습니다(자세히는 38편).

이터러블이 아닌 값을 넘기면 TypeError(`x is not iterable`)이고, 메시지 문구는 엔진마다 다릅니다.

## 무한 이터러블과 지연 평가

지연 평가(lazy evaluation)는 값이 필요해지는 순간, 즉 `next()`가 호출될 때 하나씩 계산하는 방식입니다. 배열처럼 값을 미리 모두 만들어 두는 즉시 평가(eager)의 반대입니다. 이터레이터는 값을 저장하지 않고 다음 값을 계산하는 규칙과 현재 위치만 가지므로 끝이 없는 수열도 표현합니다.

```js
const naturals = {
  [Symbol.iterator]() {
    let n = 0
    return { next: () => ({ value: ++n, done: false }) }
  },
}
const [a, b, c] = naturals   // 1, 2, 3 (필요한 만큼만 계산)
for (const n of naturals) {
  if (n > 3) break           // break가 없으면 끝나지 않는다
}
```

- 값이 모두 필요한 소비자는 무한 이터러블에서 끝나지 않습니다. `[...x]`, `Array.from(x)`, `new Set(x)`, `Math.max(...x)`, `toArray()`, `break` 없는 `for...of`가 해당하며, 끝나지 않거나 메모리 한도에서 실패합니다.
- 필요한 만큼만 꺼내는 소비자는 안전합니다. 구조 분해, `break`, `take`, `find`, `some`이 해당합니다.
- 이터레이터를 만드는 시점에는 코드가 실행되지 않습니다. 소비할 때 실행되므로 부수 효과가 일어나는 시점도 소비 시점입니다. 제너레이터 함수를 호출해도 본문은 첫 `next()`까지 실행되지 않습니다(자세히는 42편).
- 지연 이터레이터는 한 번 소비하면 값이 사라집니다. 같은 값을 다시 쓰려면 `toArray()`로 저장하거나 이터러블에서 새 이터레이터를 만듭니다.
- 배열의 `map().filter()`는 단계마다 전체 새 배열을 즉시 만듭니다. 첫 몇 개만 필요해도 전체를 계산하는 점이 다르고, 아래 Iterator Helpers 절에서 실행 순서로 비교합니다.
- 쓰임새는 무한 수열, 큰 파일의 줄 단위 읽기, 페이지 단위로 가져오는 데이터처럼 전체를 메모리에 올리고 싶지 않은 경우입니다.

## Iterator Helpers

Iterator Helpers(ES2025)는 `Iterator.prototype`에 추가된 메서드 모음입니다. 이터레이터에 배열 메서드처럼 `map`, `filter`를 체인으로 쓰되 중간 배열을 만들지 않고 값을 지연 처리합니다.

```js
const result = [1, 2, 3, 4, 5, 6].values()
  .filter(n => n % 2 === 0)
  .map(n => n * 10)
  .take(2)
  .toArray()
// [20, 40]
```

- 전역 `Iterator`는 추상 클래스입니다. 배열·`Map`·`Set`·문자열 이터레이터와 제너레이터 객체가 모두 `Iterator.prototype`을 상속하므로 헬퍼를 씁니다.
- 헬퍼는 이터레이터에만 있고 이터러블에는 없습니다. `new Set([1]).map`은 `undefined`이고 `new Set([1]).values().map`은 함수입니다. 배열은 `values()`를 먼저 호출해야 이터레이터 헬퍼가 됩니다(배열 자체의 `map`은 `Array.prototype.map`).
- 지원: Chrome·Edge 122, Firefox 131, Safari 18.4, Node.js 22 이상입니다(MDN 호환성 데이터).

| 메서드 | 평가 | 동작 |
|--------|------|------|
| `map(fn)` | 지연 | 각 값을 `fn(값, 카운터)`의 결과로 바꾼다 |
| `filter(fn)` | 지연 | `fn`이 참인 값만 통과시킨다 |
| `take(n)` | 지연 | 처음 `n`개만 내놓고 원본을 닫는다 |
| `drop(n)` | 지연 | 처음 `n`개를 버린다 |
| `flatMap(fn)` | 지연 | `fn`이 반환한 이터러블·이터레이터의 값을 한 단계 펼친다 |
| `toArray()` | 즉시 | 남은 값을 배열로 모은다 |
| `forEach(fn)` | 즉시 | 각 값에 `fn`을 호출하고 `undefined`를 반환한다 |
| `reduce(fn, init)` | 즉시 | 값을 하나로 누적한다 |
| `some(fn)`, `every(fn)` | 즉시 | 결과가 정해지는 순간 멈춘다 |
| `find(fn)` | 즉시 | 처음 일치하는 값을 반환하고, 없으면 `undefined` |

지연 메서드는 새 이터레이터를 반환하고, 즉시 메서드는 이터레이터를 소비해 값을 반환합니다. 지연 파이프라인은 값 하나가 모든 단계를 거친 뒤 다음 값으로 넘어갑니다.

```js
const log = (tag, n) => { console.log(tag, n); return n }
const out = [1, 2, 3].values()
  .map(n => log('map', n))
  .filter(n => log('filter', n) > 1)
  .take(1)
  .toArray()
// map 1, filter 1, map 2, filter 2   (3은 처리되지 않는다)
// out: [2]
```

같은 작업을 배열 메서드로 하면 `map`이 세 값을 모두 처리한 뒤에야 `filter`가 시작합니다.

| 항목 | 배열 메서드 | 이터레이터 헬퍼 |
|------|-------------|-----------------|
| 평가 | 메서드마다 즉시, 새 배열 생성 | 값 하나씩 지연 |
| 콜백 인수 | `(요소, 인덱스, 배열)` | `(값, 카운터)` |
| 재사용 | 몇 번이든 | 한 번만 |
| 무한 데이터 | 불가 | `take` 등으로 가능 |
| 정렬, `slice`, 인덱스 접근 | 있음 | 없음 |

규칙입니다.

- 인수 검증은 호출 즉시 일어납니다. `iter.map(123)`은 TypeError, `iter.take(-1)`은 RangeError를 첫 `next()`를 기다리지 않고 던집니다.
- `take(n)`과 `drop(n)`의 `n`이 `NaN`이거나 음수이면 RangeError입니다. 소수는 버리고(`take(1.5)`는 1개), `Infinity`는 허용합니다.
- `flatMap`은 한 단계만 펼칩니다. 콜백이 문자열이나 이터러블이 아닌 값을 반환하면 TypeError입니다.
- `reduce`에 초기값이 없으면 첫 값이 누적값이 되고 콜백의 카운터는 1부터 시작합니다. 빈 이터레이터에 초기값이 없으면 TypeError입니다.
- 헬퍼가 반환한 이터레이터는 원본과 같은 데이터 원천을 공유합니다. 복제본이 아니므로 한쪽에서 `next()`하면 다른 쪽도 앞으로 갑니다.
- 헬퍼 이터레이터의 `return()`은 원본의 `return()`을 호출합니다. `take`, `find`, `some`, `every`가 중간에 멈추면 원본을 닫습니다.
- 흔한 실수: `console.log([1, 2].values().map(x => x))`는 값이 아니라 `Iterator Helper` 객체를 출력합니다. 결과를 보려면 `toArray()`로 소비합니다. 소비하지 않으면 콜백도 실행되지 않습니다.

## Iterator.from

`Iterator.from(obj)`는 이터러블이나 이터레이터 비슷한 객체를 `Iterator.prototype`을 상속하는 이터레이터로 바꾸는 정적 메서드입니다(ES2025). 직접 만든 이터레이터나 이터러블에 헬퍼를 붙이는 용도입니다.

```js
const raw = { next() { return { value: 1, done: false } } }
Iterator.from(raw).take(2).toArray()   // [1, 1]
Iterator.from(new Set([1, 2]))
  .map(x => x * 2).toArray()           // [2, 4]
```

- `obj`에 `Symbol.iterator`가 있으면 그 메서드로 이터레이터를 얻고, 없으면 `obj` 자신을 이터레이터로 씁니다(`next` 메서드가 필요).
- 얻은 이터레이터가 이미 `Iterator.prototype`을 상속하면 그대로 반환합니다. 아니면 상속하는 래퍼로 감싸고, 래퍼의 `next()`와 `return()`은 원본에 위임합니다.
- 문자열은 이터러블이므로 받습니다(`Iterator.from('ab😀').toArray()`는 `['a', 'b', '😀']`). 숫자 같은 다른 원시 값과 `null`은 TypeError입니다.
- `Iterator.from(arr)`는 배열이 아니라 배열 이터레이터를 반환해서 `Iterator.from(arr) !== arr`입니다.
- 무한 이터러블에 헬퍼를 붙이는 전형적인 형태입니다.

```js
const naturals = {
  [Symbol.iterator]() {
    let n = 0
    return { next: () => ({ value: ++n, done: false }) }
  },
}
Iterator.from(naturals)
  .filter(n => n % 2 === 0)
  .map(n => n * n)
  .take(3)
  .toArray()   // [4, 16, 36]
```

- 흔한 실수: `next`가 없는 객체(`Iterator.from({})`)는 `from` 호출이 아니라 첫 `next()`에서 TypeError가 납니다.

## Iterator.concat (ES2026)

`Iterator.concat(...iterables)`는 여러 이터러블을 순서대로 이어 하나의 이터레이터로 만드는 정적 메서드입니다(Iterator Sequencing, ES2026).

```js
const it = Iterator.concat([1, 2], new Set([3]), [4])
it.toArray()   // [1, 2, 3, 4]
```

- 인수는 객체이고 `Symbol.iterator` 메서드가 있어야 합니다. 문자열 같은 원시 값, `next`만 있는 이터레이터 객체는 호출 즉시 TypeError입니다. 후자는 `Iterator.from`으로 감싸서 넘깁니다.
- 지연 평가라서 호출 시점에는 아무것도 순회하지 않습니다. 각 인수의 `[Symbol.iterator]()`는 그 차례가 왔을 때 호출하고, 앞 인수를 다 소비한 뒤에야 다음 인수로 넘어갑니다.
- 무한 이터러블 뒤에 오는 인수에는 도달하지 못합니다. `Iterator.concat(a, infinite, b).take(10)`의 `b`는 처리되지 않습니다.
- 중간에 멈추면 지금 열려 있는 이터레이터의 `return()`을 호출하고, 아직 열지 않은 인수는 건드리지 않습니다.
- 인수가 없으면 빈 이터레이터입니다. 반환값은 이터레이터 헬퍼라서 `map`, `take` 등을 이어 쓸 수 있습니다.
- `Array.prototype.concat`과 다릅니다. 배열 `concat`은 배열을 반환하고 배열만 펼치지만, `Iterator.concat`은 어떤 이터러블이든 받고 값을 미리 만들지 않습니다.
- `Map`을 이어 붙이면 뒤의 키가 앞의 값을 덮어씁니다: `new Map(Iterator.concat(m1, m2))`.
- 지원: Chrome·Edge 146, Firefox 147, Safari 26.4, Node.js 26 이상입니다(MDN 호환성 데이터). Node.js 24에는 없습니다.

## ES2027 예정 헬퍼

### Iterator.zip

`Iterator.zip(iterables, options)`는 여러 이터러블을 같은 위치끼리 묶은 배열을 내놓는 이터레이터를 만듭니다. 인수는 이터러블 여러 개가 아니라 이터러블들을 담은 이터러블 하나입니다.

```js
const names = ['kim', 'lee', 'park']
const ages = [30, 25]
Iterator.zip([names, ages]).toArray()
// [['kim', 30], ['lee', 25]]
```

`options.mode`가 길이가 다를 때의 동작을 정합니다.

| mode | 동작 |
|------|------|
| `'shortest'` (기본) | 가장 짧은 쪽이 끝나면 종료하고 나머지는 닫는다 |
| `'longest'` | 가장 긴 쪽까지 진행한다. 빈 자리는 `undefined` 또는 `padding` |
| `'strict'` | 길이가 다르면 TypeError |

```js
const opts = { mode: 'longest', padding: [0, '-'] }
Iterator.zip([[1, 2], ['a']], opts).toArray()
// [[1, 'a'], [2, '-']]
```

- `padding`은 `'longest'`에서만 쓰고, 위치 순서대로 빈 자리를 채울 값의 이터러블입니다.
- `Iterator.zipKeyed(obj, options)`는 객체의 값들을 묶어 키가 있는 객체를 내놓습니다. 결과 객체는 프로토타입이 `null`이고, `padding`은 키를 가진 객체입니다.

```js
const cols = { id: [1, 2], name: ['a', 'b'] }
Iterator.zipKeyed(cols).toArray()
// [{ id: 1, name: 'a' }, { id: 2, name: 'b' }]
```

- 흔한 실수: `Iterator.zip([1, 2], [3, 4])`처럼 인수를 나열하면 TypeError입니다. 배열 하나로 감싸야 합니다. 목록의 원소가 문자열 같은 원시 값이어도 TypeError입니다.

### chunks와 windows

`chunks(size)`는 값을 `size`개씩 끊어 배열로, `windows(size)`는 한 칸씩 이동하는 겹치는 구간을 배열로 내놓습니다.

```js
const nums = () => [1, 2, 3, 4, 5].values()
nums().chunks(2).toArray()    // [[1, 2], [3, 4], [5]]
nums().windows(2).toArray()
// [[1, 2], [2, 3], [3, 4], [4, 5]]
```

- `chunks`의 마지막 묶음은 `size`보다 짧을 수 있습니다.
- `windows`는 요소가 창 크기보다 적으면 아무것도 내놓지 않는 것이 기본이고, 두 번째 인수 `'allow-partial'`로 부분 창을 허용합니다(명세 초안 기준).
- `size`가 1 미만이면 RangeError, 정수가 아니면 TypeError입니다. 각 항목은 새 배열입니다.
- 쓰임새는 배치 처리, 페이지 나누기, 이동 평균, 인접 쌍 비교입니다.

### join

`join(separator)`는 이터레이터의 값을 문자열로 이어 붙입니다. 동작은 `Array.prototype.join`과 같습니다.

```js
const it = [1, null, 3].values()
it.join('-')   // '1--3'
```

- 구분자를 생략하면 `,`입니다. `null`과 `undefined`는 빈 문자열, 나머지는 문자열로 바꿉니다(`Symbol`은 TypeError). 빈 이터레이터는 `''`입니다.
- 이터레이터를 끝까지 소비하는 즉시 메서드입니다. 지금까지는 `Array.from(it).join(sep)`처럼 배열을 거쳐야 했습니다.

### includes

`includes(value)`는 이터레이터가 그 값을 내놓는지 `true`·`false`로 알려 줍니다.

```js
function* gen() { yield 1; yield 3 }
gen().includes(3)           // true
gen().includes(2)           // false
gen().drop(1).includes(1)   // false
```

- 비교는 `Array.prototype.includes`와 같은 SameValueZero입니다. `NaN`을 찾고 `0`과 `-0`을 같게 봅니다.
- 찾으면 즉시 `true`를 반환하고 원본의 `return()`을 호출합니다. 찾지 못하면 끝까지 소비하므로 무한 이터레이터에서는 끝나지 않습니다.
- 두 번째 인수는 앞에서 건너뛸 개수입니다(명세 초안에서는 `skippedElements`). 배열 `includes`의 `fromIndex`와 달리 음수는 RangeError입니다. 건너뛰려면 `drop`이 더 명확합니다.

## 핵심 정리

- 이터러블은 `Symbol.iterator` 메서드로 이터레이터를 반환하고, 이터레이터는 `next()`로 `{ value, done }`을 반환합니다.
- `for...of`, 스프레드, 구조 분해, `Array.from`, `Set`·`Map` 생성자가 이 프로토콜을 쓰며, 일반 객체와 유사 배열은 이터러블이 아닙니다.
- 이터러블은 호출마다 새 이터레이터를 만들어 여러 번 순회할 수 있고, 이터러블이면서 이터레이터인 객체(제너레이터 객체, 빌트인 이터레이터)는 한 번만 순회됩니다.
- 순회를 중간에 멈추면(`break`, 필요한 개수만의 구조 분해) `return()`이 호출되고, 끝까지 소비하는 문법은 호출하지 않습니다.
- 이터레이터는 값을 지연 계산해 무한 수열을 표현합니다. ES2025 Iterator Helpers와 `Iterator.from`으로 배열 없이 지연 파이프라인을 만듭니다.
- `Iterator.concat`은 ES2026, `zip`·`chunks`·`windows`·`join`·`includes`는 ES2027 예정이며 엔진 지원을 확인해야 합니다.
