## 핵심 먼저 보기

- 이터러블은 `Symbol.iterator` 메서드로 이터레이터를 반환하고, 이터레이터는 `next()`로 `{ value, done }`을 반환합니다.
- `for...of`, 스프레드, 구조 분해, `Array.from`, `Set`·`Map` 생성자가 이 프로토콜을 쓰며, 일반 객체와 유사 배열은 이터러블이 아닙니다.
- 이터러블은 호출마다 새 이터레이터를 만들어 여러 번 순회할 수 있고, 이터러블이면서 이터레이터인 객체(제너레이터 객체, 빌트인 이터레이터)는 한 번만 순회됩니다.
- 순회를 중간에 멈추면(`break`, 필요한 개수만의 구조 분해) `return()`이 호출되고, 끝까지 소비하는 문법은 호출하지 않습니다.
- 이터레이터는 값을 지연 계산해 무한 수열을 표현합니다. ES2025 Iterator Helpers와 `Iterator.from`으로 배열 없이 지연 파이프라인을 만듭니다.
- `Iterator.concat`은 ES2026, `zip`·`chunks`·`windows`·`join`·`includes`는 ES2027 예정이며 엔진 지원을 확인해야 합니다.

## 이터레이션 프로토콜

이터레이션 프로토콜(iteration protocol)은 값을 하나씩 꺼내는 방법을 정한 ES2015의 규약입니다. 값을 내놓는 쪽(배열, `Set`, 직접 만든 객체)과 꺼내 쓰는 쪽(`for...of`, 스프레드, 구조 분해)이 이 규약만 지키면 서로를 몰라도 연결됩니다.

| 프로토콜 | 요구 사항 |
|----------|-----------|
| 이터러블 프로토콜 | `Symbol.iterator` 키의 메서드가 이터레이터를 반환한다 |
| 이터레이터 프로토콜 | `next()` 메서드가 `{ value, done }` 객체를 반환한다 |

## 이터러블

이터러블(iterable)은 `Symbol.iterator` 키로 이터레이터를 반환하는 메서드를 가진 객체입니다. `for...of`가 순회할 수 있는 대상이 이터러블입니다. `Symbol.iterator`는 언어가 정의한 잘 알려진 심벌입니다(자세히는 34편).

```js
const arr = [10, 20]
typeof arr[Symbol.iterator]   // 'function'
const iter = arr[Symbol.iterator]()
iter.next()                   // { value: 10, done: false }
```

## 이터레이터와 next

이터레이터(iterator)는 `next()` 메서드를 가진 객체이고, `next()`를 호출할 때마다 이터레이터 결과 객체를 반환합니다.

| 프로퍼티 | 의미 |
|----------|------|
| `value` | 이번에 꺼낸 값. `done`이 `true`일 때는 반환값(보통 `undefined`) |
| `done` | 순회가 끝났으면 `true`, 아직 값이 있으면 `false` |

```js
const it = ['a', 'b'][Symbol.iterator]()
it.next()   // { value: 'a', done: false }
it.next()   // { value: 'b', done: false }
it.next()   // { value: undefined, done: true }
it.next()   // { value: undefined, done: true }
```

## 빌트인 이터러블

| 값 | 꺼내는 값 | 비고 |
|----|-----------|------|
| `Array` | 요소(구멍은 `undefined`) | 기본 이터레이터는 `values()`와 같은 함수 |
| `String` | 코드 포인트 하나씩 | `'😀'`는 한 번에 나온다(자세히는 33편) |
| `Map` | `[키, 값]` 배열 | 기본 이터레이터는 `entries()`와 같은 함수 |
| `Set` | 값 | `keys()`와 `values()`는 같은 함수 |
| `TypedArray` | 요소 | 자세히는 48편 |
| `arguments` | 인수 | 유사 배열이기도 하다 |
| 제너레이터 객체 | `yield`한 값 | 자세히는 42편 |
| `matchAll()` 결과 | 매치 배열 | 자세히는 32편 |

일반 객체, `WeakMap`, `WeakSet`, 숫자·불리언 같은 원시 값은 이터러블이 아닙니다(`WeakMap`·`WeakSet`은 38편).

## for...of

`for...of`는 이터러블이 내놓는 값을 하나씩 변수에 꺼내 본문을 실행하는 반복문입니다.

## 이터러블과 유사 배열 객체

유사 배열 객체(array-like)는 음이 아닌 정수 `length`와 `0`, `1`, ... 인덱스 키를 가진 객체입니다. 인덱스로 읽을 수 있을 뿐 배열 메서드는 없고, 이터러블과는 별개 개념입니다.

| 값 | 유사 배열 | 이터러블 |
|----|-----------|----------|
| 배열, 문자열, `arguments`, `TypedArray` | O | O |
| `{ length: 2, 0: 'a', 1: 'b' }` | O | X |
| `Set`, `Map`, 제너레이터 객체 | X | O |
| `{ a: 1 }` | X | X |

## 사용자 정의 이터러블

사용자 정의 이터러블은 `Symbol.iterator` 메서드를 직접 구현한 객체입니다. 구현하면 스프레드, 구조 분해, `Array.from`, `Set` 생성자 같은 소비자를 따로 고치지 않고 그대로 쓸 수 있습니다.

## 이터러블이면서 이터레이터인 객체

이터러블이면서 이터레이터인 객체는 `next()`를 가지고, `Symbol.iterator` 메서드가 자기 자신(`this`)을 반환하는 객체입니다. 이터레이터를 이터러블을 요구하는 자리에 그대로 넣기 위한 형태입니다.

| 구분 | 이터러블 (배열, `Map`, `Set`, 문자열) | 이터러블이면서 이터레이터 (제너레이터 객체, 빌트인 이터레이터) |
|------|----------------------------------------|------------------------------------------------------------------|
| `[Symbol.iterator]()` | 호출마다 새 이터레이터 | `this` 반환 |
| 순회 횟수 | 몇 번이든 | 한 번 |
| 중간에 멈춘 뒤 | 다음 순회는 처음부터 | 같은 객체로 이어서 순회 |

## 이터레이터 종료: return

`for...of`를 `break`·예외 등으로 일찍 끝내면 이터레이터의 `return()`을 호출해 정리를 시도합니다. 제너레이터의 `finally`가 자원 정리에 쓰이는 이유입니다. 직접 `next()`로 소비할 때는 종료 관리도 직접 해야 합니다.

## 무한 이터러블과 지연 평가

지연 평가(lazy evaluation)는 값이 필요해지는 순간, 즉 `next()`가 호출될 때 하나씩 계산하는 방식입니다. 배열처럼 값을 미리 모두 만들어 두는 즉시 평가(eager)의 반대입니다. 이터레이터는 값을 저장하지 않고 다음 값을 계산하는 규칙과 현재 위치만 가지므로 끝이 없는 수열도 표현합니다.

- 값이 모두 필요한 소비자는 무한 이터러블에서 끝나지 않습니다. `[...x]`, `Array.from(x)`, `new Set(x)`, `Math.max(...x)`, `toArray()`, `break` 없는 `for...of`가 해당하며, 끝나지 않거나 메모리 한도에서 실패합니다.
- 필요한 만큼만 꺼내는 소비자는 안전합니다. 구조 분해, `break`, `take`, `find`, `some`이 해당합니다.
- 이터레이터를 만드는 시점에는 코드가 실행되지 않습니다. 소비할 때 실행되므로 부수 효과가 일어나는 시점도 소비 시점입니다. 제너레이터 함수를 호출해도 본문은 첫 `next()`까지 실행되지 않습니다(자세히는 42편).
- 지연 이터레이터는 한 번 소비하면 값이 사라집니다. 같은 값을 다시 쓰려면 `toArray()`로 저장하거나 이터러블에서 새 이터레이터를 만듭니다.
- 배열의 `map().filter()`는 단계마다 전체 새 배열을 즉시 만듭니다. 첫 몇 개만 필요해도 전체를 계산하는 점이 다르고, 아래 Iterator Helpers 절에서 실행 순서로 비교합니다.
- 쓰임새는 무한 수열, 큰 파일의 줄 단위 읽기, 페이지 단위로 가져오는 데이터처럼 전체를 메모리에 올리고 싶지 않은 경우입니다.

## Iterator Helpers

Iterator Helpers(ES2025)는 `Iterator.prototype`에 추가된 메서드 모음입니다. 이터레이터에 배열 메서드처럼 `map`, `filter`를 체인으로 쓰되 중간 배열을 만들지 않고 값을 지연 처리합니다.

<details>
<summary>전체 비교표 펼치기</summary>

| 메서드 | 평가 | 동작 |
|--------|------|------|
| `map(fn)` | 지연 | 각 값을 `fn(값, 카운터)`의 결과로 바꾼다 |
| `filter(fn)` | 지연 | `fn`이 참인 값만 통과시킨다 |
| `take(n)` | 지연 | 처음 `n`개만 내놓고 원본을 닫는다 |
| `drop(n)` | 지연 | 처음 `n`개를 버린다 |
| `flatMap(fn)` | 지연 | `fn`이 반환한 이터러블·이터레이터의 값을 한 단계 펼친다 |
| `toArray()` | 즉시 | 남은 값을 배열로 모은다 |
| `forEach(fn)` | 즉시 | 각 값에 `fn`을 호출하고 `undefined`를 반환한다 |
| `reduce(fn, init)` | 즉시 | 값을 하나로 누적한다 |
| `some(fn)`, `every(fn)` | 즉시 | 결과가 정해지는 순간 멈춘다 |
| `find(fn)` | 즉시 | 처음 일치하는 값을 반환하고, 없으면 `undefined` |

</details>

## Iterator.from

`Iterator.from(obj)`는 이터러블이나 이터레이터 비슷한 객체를 `Iterator.prototype`을 상속하는 이터레이터로 바꾸는 정적 메서드입니다(ES2025). 직접 만든 이터레이터나 이터러블에 헬퍼를 붙이는 용도입니다.

## Iterator.concat (ES2026)

`Iterator.concat(...iterables)`는 여러 이터러블을 순서대로 이어 하나의 이터레이터로 만드는 정적 메서드입니다(Iterator Sequencing, ES2026).

- 인수는 객체이고 `Symbol.iterator` 메서드가 있어야 합니다. 문자열 같은 원시 값, `next`만 있는 이터레이터 객체는 호출 즉시 TypeError입니다. 후자는 `Iterator.from`으로 감싸서 넘깁니다.
- 지연 평가라서 호출 시점에는 아무것도 순회하지 않습니다. 각 인수의 `[Symbol.iterator]()`는 그 차례가 왔을 때 호출하고, 앞 인수를 다 소비한 뒤에야 다음 인수로 넘어갑니다.
- 무한 이터러블 뒤에 오는 인수에는 도달하지 못합니다. `Iterator.concat(a, infinite, b).take(10)`의 `b`는 처리되지 않습니다.
- 중간에 멈추면 지금 열려 있는 이터레이터의 `return()`을 호출하고, 아직 열지 않은 인수는 건드리지 않습니다.
- 인수가 없으면 빈 이터레이터입니다. 반환값은 이터레이터 헬퍼라서 `map`, `take` 등을 이어 쓸 수 있습니다.
- `Array.prototype.concat`과 다릅니다. 배열 `concat`은 배열을 반환하고 배열만 펼치지만, `Iterator.concat`은 어떤 이터러블이든 받고 값을 미리 만들지 않습니다.
- `Map`을 이어 붙이면 뒤의 키가 앞의 값을 덮어씁니다: `new Map(Iterator.concat(m1, m2))`.
- 지원: Chrome·Edge 146, Firefox 147, Safari 26.4, Node.js 26 이상입니다(MDN 호환성 데이터). Node.js 24에는 없습니다.
