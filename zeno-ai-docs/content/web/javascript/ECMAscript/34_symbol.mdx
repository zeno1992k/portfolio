## 심벌의 개념

심벌(Symbol)은 ES2015에서 추가된 원시 타입으로, 만들 때마다 다른 값이 되는 고유한 값입니다. 프로퍼티 키로 쓸 수 있는 값은 문자열과 심벌 두 가지뿐입니다(자세히는 09편).

```js
const a = Symbol('id')
const b = Symbol('id')
a === b      // false
typeof a     // 'symbol'
```

- 불변이고 고유합니다. 한 번 만들어진 심벌은 바뀌지 않으며 다른 어떤 심벌과도 같아지지 않습니다.
- 리터럴이 없습니다. 함수 호출로만 만듭니다.
- 설명(description)은 디버깅용 꼬리표입니다. 값의 동일성에는 영향을 주지 않습니다.
- 문자열처럼 보여도 문자열이 아닙니다. 문자열·숫자로 자동 변환되지 않습니다(아래 "심벌의 형 변환 제약").

문자열 키는 이름이 같으면 같은 프로퍼티입니다. 서로 모르는 코드가 한 객체에 같은 이름의 키를 붙이면 덮어씁니다. 심벌 키는 설명이 같아도 심벌 값이 다르면 다른 프로퍼티입니다.

심벌은 세 종류로 나뉩니다.

| 종류 | 만드는 법 | 같은 값이 되는 조건 |
|------|-----------|---------------------|
| 일반 심벌 | `Symbol(desc)` | 같은 심벌을 참조할 때뿐 |
| 등록 심벌 | `Symbol.for(key)` | key가 같을 때 |
| Well-known Symbol | `Symbol.iterator` 등 | 어느 realm에서나 항상 같은 값 |

realm은 전역 객체와 내장 객체 한 벌을 가진 실행 영역입니다. 페이지의 iframe마다 realm이 따로 있습니다.

## Symbol 함수와 값 생성

`Symbol([description])`은 호출할 때마다 새 심벌을 반환하는 함수입니다.

```js
const s1 = Symbol()
const s2 = Symbol('login')
console.log(s2)   // Symbol(login)
new Symbol()      // TypeError
```

- `new`로 호출하면 TypeError입니다. 생성자 함수처럼 보이지만 `new` 없이 호출하는 함수입니다(자세히는 15편).
- 설명 인수는 문자열로 변환됩니다. 인수가 심벌이면 TypeError입니다.
- 인수를 생략하거나 `undefined`를 주면 설명이 없는 심벌이 됩니다.

```js
Symbol(123).description        // '123'
Symbol(null).description       // 'null'
Symbol(undefined).description  // undefined
Symbol(Symbol())               // TypeError
```

- 심벌은 원시 값이라 프로퍼티를 붙일 수 없습니다. `sym.foo = 1`은 엄격 모드에서 TypeError이고 비엄격 모드에서는 조용히 무시됩니다.
- `sym.toString()`이나 `sym.description` 같은 접근은 임시 래퍼 객체를 거칩니다(자세히는 10편).

### 래퍼 객체와 Symbol.prototype

`Object(sym)`은 심벌을 감싼 래퍼 객체를 만듭니다.

```js
const s = Symbol('w')
const w = Object(s)
typeof w         // 'object'
w == s           // true
w === s          // false
const o = { [s]: 1 }
o[w]             // 1  (키로 쓰면 감싼 심벌로 바뀐다)
```

- `Symbol.keyFor(Object(sym))`은 TypeError입니다. 래퍼 객체는 심벌이 아닙니다.
- `instanceof Symbol`은 원시 심벌에는 `false`, 래퍼 객체에는 `true`입니다.

래퍼가 상속하는 `Symbol.prototype`의 멤버는 다음과 같습니다.

| 멤버 | 반환값 |
|------|--------|
| `toString()` | `'Symbol(설명)'` 문자열 |
| `valueOf()` | 심벌 자신 |
| `description` (getter) | 설명 문자열 또는 `undefined` |
| `[Symbol.toPrimitive]()` | 심벌 자신 (힌트와 무관) |
| `[Symbol.toStringTag]` | `'Symbol'` |

## description과 toString

`description`은 심벌을 만들 때 준 설명을 읽는 접근자 프로퍼티입니다(ES2019).

```js
Symbol('login').description    // 'login'
Symbol().description           // undefined
Symbol('').description         // ''
Symbol.for('app').description  // 'app'
Symbol.iterator.description    // 'Symbol.iterator'
```

- 읽기 전용입니다. 대입하면 엄격 모드에서 TypeError입니다.
- 설명 없음(`undefined`)과 빈 문자열 설명(`''`)은 구분됩니다. 그러나 `toString()`은 둘 다 `'Symbol()'`을 반환합니다.
- ES2019 이전에는 `sym.toString().slice(7, -1)`로 설명을 꺼냈습니다. 이 방식은 위 두 경우를 구분하지 못합니다.
- 설명은 식별자가 아닙니다. 설명이 같은 심벌을 여러 개 만들 수 있고, 설명으로 심벌을 찾을 수 없습니다. 찾아야 하면 `Symbol.for`를 씁니다.
- `toString()`의 결과 `'Symbol(login)'`은 출력용 문자열입니다. 이 문자열을 키로 쓰면 심벌 키 프로퍼티에 접근하지 못합니다.

## Symbol.for와 Symbol.keyFor

`Symbol.for(key)`는 전역 심벌 레지스트리에서 key에 해당하는 심벌을 찾아 반환하고, 없으면 만들어 등록한 뒤 반환합니다. `Symbol.keyFor(sym)`은 등록 심벌의 key를 돌려줍니다.

```js
const a = Symbol.for('app.id')
const b = Symbol.for('app.id')
a === b                         // true
Symbol.keyFor(a)                // 'app.id'
Symbol.keyFor(Symbol('x'))      // undefined
Symbol.keyFor(Symbol.iterator)  // undefined
```

- 레지스트리는 모든 realm이 공유합니다. 다른 realm에서 `Symbol.for('app.id')`로 얻은 심벌도 같은 값입니다. 일반 심벌은 설명이 같아도 realm마다 다른 값입니다.
- key는 문자열로 변환됩니다. `Symbol.for(1) === Symbol.for('1')`이고, `Symbol.for()`는 key가 `'undefined'`인 심벌을 돌려줍니다. key가 심벌이면 TypeError입니다.
- 등록 심벌의 `description`은 key와 같습니다.
- `keyFor`는 등록되지 않은 심벌(일반 심벌, Well-known Symbol)에 `undefined`를 반환합니다. 심벌이 아닌 값을 주면 TypeError입니다.
- 레지스트리는 전역 이름 공간입니다. 충돌을 피하려면 `'라이브러리명.이름'`처럼 접두어를 붙입니다.

| 구분 | `Symbol()` | `Symbol.for()` |
|------|------------|----------------|
| 새 값이 만들어지는 때 | 호출할 때마다 | key마다 처음 한 번 |
| 같은 설명 | 서로 다른 값 | 같은 값 |
| realm 사이 | 서로 다른 값 | 같은 값 |
| WeakMap 키·WeakRef 대상 | 가능 | TypeError |

- ES2023부터 일반 심벌과 Well-known Symbol은 WeakMap의 키와 WeakSet·WeakRef의 대상이 될 수 있습니다. 등록 심벌은 TypeError입니다(자세히는 38편).
- 흔한 실수: `Symbol.for('a') === Symbol('a')`는 `false`입니다. 같은 코드베이스 안에서만 공유한다면 `Symbol()`을 `const`로 선언해 내보내는 쪽이 전역 충돌이 없어 안전합니다.

## 심벌과 상수

값이 서로 겹치면 안 되는 상수(열거형 값)에 심벌을 쓸 수 있습니다. 심벌 상수는 상수 객체를 거쳐야만 얻을 수 있고, 다른 상수와 값이 우연히 같아질 수 없습니다.

```js
const Direction = Object.freeze({
  UP: Symbol('up'),
  DOWN: Symbol('down'),
})

function move(dir) {
  switch (dir) {
    case Direction.UP: return 'up'
    case Direction.DOWN: return 'down'
    default: throw new Error('unknown direction')
  }
}
move(Direction.UP)  // 'up'
move('up')          // Error: unknown direction
```

- 문자열·숫자 상수는 리터럴(`'up'`, `0`)을 직접 써도 통과합니다. 서로 다른 상수에 같은 값을 실수로 주어도 에러가 없습니다.
- `Object.freeze`로 상수 객체를 동결하면 상수를 바꿔 끼우는 것을 막습니다(자세히는 14편).
- 디버깅 출력은 `Symbol(up)`이고, `Direction.UP.description`은 `'up'`입니다.
- 한계: 심벌은 JSON으로 직렬화되지 않고, localStorage·네트워크로 보낼 수 없습니다. 저장하거나 전송하는 값에는 문자열·숫자 상수를 씁니다.
- 흔한 실수: `dir === Symbol('up')`은 항상 `false`입니다. 상수는 반드시 `Direction.UP`으로 참조합니다.

## 심벌과 프로퍼티 키

심벌 키 프로퍼티는 계산된 이름(`[sym]`)이나 대괄호 표기법으로 만들고 읽습니다.

```js
const id = Symbol('id')
const user = { name: 'Kim', [id]: 123 }
user[id]    // 123
user.id     // undefined  ('id' 문자열 키는 없다)
user[id] = 456
```

심벌 키를 만드는 방법은 다음과 같습니다.

- 객체 리터럴의 계산된 이름 `[id]: value` (리터럴에서 심벌 키를 쓰는 유일한 문법)
- 대괄호 대입 `obj[id] = value`
- `Object.defineProperty(obj, id, descriptor)`
- 클래스의 `[id]() {}` 메서드와 `static [id] = value` 필드

규칙은 다음과 같습니다.

- 점 표기법 `obj.id`는 항상 문자열 키 `'id'`를 뜻합니다. 심벌 키는 대괄호로만 접근합니다.
- 설명이 같은 심벌은 서로 다른 키입니다. `{ [Symbol('k')]: 1, [Symbol('k')]: 2 }`에는 프로퍼티가 두 개 있습니다.
- `in`, `Object.hasOwn`, `delete`, `Object.getOwnPropertyDescriptor`, `propertyIsEnumerable`은 심벌 키를 그대로 받습니다.
- 프로토타입 체인 탐색은 문자열 키와 같습니다. 상속된 심벌 키는 `in`으로 확인되고 `Object.hasOwn`으로는 확인되지 않습니다.
- 열거 순서에서 심벌 키는 문자열 키 뒤에 생성 순서로 옵니다(자세히는 09편).
- 대입으로 만든 심벌 키 프로퍼티의 어트리뷰트는 문자열 키와 같습니다. `writable`, `enumerable`, `configurable`이 모두 `true`입니다. `Object.defineProperty`로 만들면 지정하지 않은 어트리뷰트가 `false`입니다(자세히는 14편).
- 심벌 키가 순회에서 빠지는 이유는 열거 불가여서가 아닙니다. 문자열 키만 다루는 API가 심벌 키를 건너뛰기 때문입니다.

| API | 심벌 키 |
|-----|---------|
| `Object.keys`, `values`, `entries`, `for...in`, `getOwnPropertyNames` | 포함하지 않음 |
| `Object.getOwnPropertySymbols` | 심벌 키만 반환 (열거 불가 포함) |
| `Reflect.ownKeys`, `Object.getOwnPropertyDescriptors` | 포함 (열거 불가 포함) |
| `Object.assign`, 객체 스프레드 | 열거 가능한 것만 복사 |
| `JSON.stringify` | 무시 |

열거 API 전체 비교는 18편에서 다룹니다.

## 프로퍼티 은닉

심벌 키 프로퍼티는 문자열 키를 순회하는 API에 나타나지 않으므로 실수로 건드리거나 직렬화될 일이 줄어듭니다. 그러나 접근을 막지는 못합니다.

```js
const secret = Symbol('secret')
const user = { name: 'Kim', [secret]: 'pw' }

Object.keys(user)       // ['name']
JSON.stringify(user)    // '{"name":"Kim"}'
Reflect.ownKeys(user)   // ['name', Symbol(secret)]
const [leaked] = Object.getOwnPropertySymbols(user)
user[leaked]            // 'pw'
```

- 숨겨지는 것: 문자열 키 열거(`for...in`, `Object.keys`), 직렬화, 이름 충돌.
- 숨겨지지 않는 것: `Object.getOwnPropertySymbols`와 `Reflect.ownKeys`로 누구나 키를 얻어 값을 읽고 쓸 수 있습니다. 심벌 변수를 모듈 밖으로 내보내지 않아도 마찬가지입니다.
- 접근 자체를 막으려면 `#private` 필드(24편), 클로저(23편), WeakMap(38편)을 씁니다.

| 방식 | 키 열거에서 | 외부 접근 |
|------|-------------|-----------|
| `_name` 관례 | 그대로 노출 | 막지 못함 |
| 심벌 키 | 문자열 API에서는 숨음 | 막지 못함 |
| `#name` 필드 | 키가 아니므로 나타나지 않음 | 클래스 밖에서 쓰면 SyntaxError |
| 클로저·WeakMap | 해당 없음 | 막음 |

## 표준 빌트인 객체 확장

빌트인 객체(`Array.prototype` 등)에 프로퍼티를 붙이면 그 환경의 모든 코드에 영향을 줍니다. 문자열 키로 붙이면 두 가지 문제가 생깁니다.

- 나중에 표준에 같은 이름이 추가되면 충돌합니다. MooTools가 `Array.prototype.flatten`을 직접 정의해 두었는데, 브라우저가 같은 이름의 표준 메서드를 구현하자 일부 사이트가 깨졌고, 표준 이름이 `flat`으로 바뀌었습니다(2018년 5월).
- 대입으로 붙인 프로퍼티는 열거 가능이라 `for...in`에 끼어듭니다.

```js
Array.prototype.sum = function () {
  return this.reduce((a, b) => a + b, 0)
}
const keys = []
for (const k in [10, 20]) keys.push(k)
keys   // ['0', '1', 'sum']  ← sum이 끼어든다
```

심벌 키로 붙이면 두 문제가 모두 사라집니다.

```js
const sum = Symbol('sum')
Array.prototype[sum] = function () {
  return this.reduce((a, b) => a + b, 0)
}
const nums = [10, 20]
nums[sum]()   // 30
const keys = []
for (const k in nums) keys.push(k)
keys          // ['0', '1']
```

- 표준이 나중에 추가하는 이름은 문자열이거나 Well-known Symbol이므로, 직접 만든 심벌과 값이 겹칠 수 없습니다.
- 그 심벌을 가진 코드에서만 메서드에 접근할 수 있습니다. 여러 파일이나 패키지가 공유하려면 심벌을 내보내거나 `Symbol.for('mylib.sum')`을 씁니다. 후자는 전역 이름이므로 접두어를 붙입니다.
- 전역 상태를 바꾼다는 점은 같습니다. 같은 심벌을 쓰는 다른 코드와 덮어쓸 수 있고, 모든 배열에 프로퍼티가 생깁니다. 구형 환경에 표준 메서드를 채우는 폴리필(51편)이 아니라면 `sum(arr)` 같은 일반 함수가 더 안전합니다.
- 문자열 키를 꼭 써야 한다면 `Object.defineProperty`로 `enumerable: false`를 지정해 `for...in` 노출을 막습니다(자세히는 14편).
- 빌트인 생성자를 상속해 확장하는 방법은 25편에서 다룹니다.

## Well-known Symbol

Well-known Symbol은 명세가 미리 만들어 `Symbol`의 정적 프로퍼티로 제공하는 심벌입니다. 엔진의 내부 알고리즘이 객체의 동작을 확인할 때 이 심벌을 키로 프로퍼티를 찾습니다. 객체에 그 키로 메서드를 정의하면 `for...of`, `instanceof`, 형 변환 같은 언어 기능의 동작을 바꿀 수 있습니다.

```js
const range = {
  from: 1, to: 3,
  *[Symbol.iterator]() {
    for (let i = this.from; i <= this.to; i++) yield i
  },
}
const nums = [...range]   // [1, 2, 3]
```

- 명세는 `@@iterator` 또는 `%Symbol.iterator%`로 표기합니다.
- `Symbol`의 프로퍼티는 `writable`, `enumerable`, `configurable`이 모두 `false`입니다. 대입은 엄격 모드에서 TypeError이고 비엄격 모드에서는 무시됩니다.
- 설명은 `'Symbol.iterator'`처럼 이름 전체이고, `Symbol.keyFor`는 `undefined`를 반환합니다. 등록 심벌이 아닙니다.
- 어느 realm에서 읽어도 같은 값입니다.
- 이 메서드는 엔진이 호출하는 훅입니다. 배열·문자열·Map·Set은 `[Symbol.iterator]`를, 정규식은 `[Symbol.match]` 등을 이미 가지고 있고, 사용자 정의 객체에도 직접 정의할 수 있습니다.
- 전체 목록은 아래 "Well-known Symbol 전체 표"에 있습니다.

## toPrimitive

`Symbol.toPrimitive`는 객체를 원시 값으로 바꾸는 방법을 직접 정하는 메서드의 키입니다. 엔진은 객체가 문자열이나 숫자 자리에 쓰이면 이 메서드를 힌트(hint)와 함께 호출합니다.

```js
const price = {
  amount: 1500,
  [Symbol.toPrimitive](hint) {
    if (hint === 'number') return this.amount
    if (hint === 'string') return `${this.amount}원`
    return this.amount   // 'default'
  },
}
+price       // 1500
`${price}`   // '1500원'
price + 1    // 1501
```

힌트는 `'number'`, `'string'`, `'default'` 중 하나이고, 어떤 문맥이 어떤 힌트를 만드는지는 정해져 있습니다.

| 힌트 | 발생하는 문맥 |
|------|---------------|
| `'number'` | 단항 `+`·`-`, `*` 같은 산술, 대소 비교, `Number()`, `Math.max()` |
| `'string'` | 템플릿 리터럴 삽입, `String()`, 계산된 프로퍼티 키, `join`, `parseInt` |
| `'default'` | 이항 `+`, `==`, `new Date(obj)` |

- 반환값은 원시 값이어야 합니다. 객체를 반환하면 TypeError입니다. 심벌은 원시 값이라 반환할 수 있지만, 그 뒤에 문자열이나 숫자로 바뀔 때 TypeError가 납니다.
- 이 메서드가 있으면 `valueOf`와 `toString`은 호출되지 않습니다.
- 프로퍼티 값이 `null`이나 `undefined`이면 메서드가 없는 것으로 보고 `valueOf`·`toString` 순서로 넘어갑니다. 함수가 아닌 다른 값이면 TypeError입니다.
- 메서드가 없는 객체의 기본 변환 순서는 08편에서 다룹니다.
- 표준 내장 객체 중 이 메서드를 가진 것은 `Date.prototype`과 `Symbol.prototype`뿐입니다.
- `Date`는 `'default'` 힌트를 `'string'`으로 취급하고, 세 힌트가 아닌 값을 받으면 TypeError입니다. 그래서 `new Date(0) + 1`은 문자열 연결입니다.
- `Symbol.prototype`의 구현은 힌트와 관계없이 심벌을 반환합니다. `Object(sym) + ''`가 TypeError인 이유입니다.

## toStringTag

`Symbol.toStringTag`는 `Object.prototype.toString()`이 만드는 `'[object 태그]'` 문자열에서 태그를 정하는 프로퍼티의 키입니다.

```js
class Temp {
  get [Symbol.toStringTag]() { return 'Temp' }
}
const toStr = Object.prototype.toString
toStr.call(new Temp())   // '[object Temp]'
String(new Temp())       // '[object Temp]'

const o = { [Symbol.toStringTag]: 'X' }
String(o)                // '[object X]'
```

- 프로퍼티 값이 문자열이면 그 문자열이 태그가 되고, 문자열이 아니면 무시하고 내장 태그를 씁니다.
- `null`은 `'Null'`, `undefined`는 `'Undefined'`입니다.
- `Array`, `Function`, `Error`, `Boolean`, `Number`, `String`, `Date`, `RegExp`, `arguments`에는 `toStringTag` 프로퍼티가 없고 내부 슬롯으로 태그를 정합니다. `Map`, `Set`, `WeakMap`, `Promise`, `Symbol`, `BigInt`, `JSON`, `Math`, `Reflect`, `ArrayBuffer`, 제너레이터 등은 자신의 프로토타입이나 객체에 `toStringTag`를 가집니다.
- 내장 객체의 `toStringTag` 프로퍼티는 `writable`, `enumerable`이 `false`이고 `configurable`이 `true`입니다.
- 문자열 태그가 내장 태그보다 우선합니다. 배열에 `toStringTag`를 붙이면 `'[object Array]'`가 아니라 붙인 태그가 나옵니다. 따라서 이 방식의 타입 판별은 위조할 수 있습니다.

타입을 구분하는 관용구는 다음과 같습니다.

```js
const toStr = Object.prototype.toString
const typeOf = v => toStr.call(v).slice(8, -1)
typeOf(null)         // 'Null'
typeOf([])           // 'Array'
typeOf(new Date())   // 'Date'
typeOf(new Map())    // 'Map'
typeOf(1n)           // 'BigInt'
```

- `typeof`는 `null`, 배열, `Date`를 모두 `'object'`로 돌려주므로 이 관용구로 구분합니다. 배열 판별은 `Array.isArray`가 더 직접적입니다.
- `obj.toString()`이 아니라 `.call`을 쓰는 이유는 대부분의 타입이 자기 `toString`으로 오버라이드하기 때문입니다. `[1, 2].toString()`은 `'1,2'`입니다.

## Well-known Symbol 전체 표

ES2026까지 명세에 있는 Well-known Symbol은 13개입니다.

| 심벌 | 사용하는 쪽 | 정의하는 값 | 자세히 |
|------|-------------|-------------|--------|
| `Symbol.iterator` | `for...of`, 스프레드, 구조 분해 | 이터레이터를 반환하는 메서드 | 35편 |
| `Symbol.asyncIterator` | `for await...of` | 비동기 이터레이터를 반환하는 메서드 | 43편 |
| `Symbol.hasInstance` | `instanceof` | 인스턴스 판정 메서드 (보통 `static`) | 17편 |
| `Symbol.toPrimitive` | 형 변환 | 원시 값으로 바꾸는 메서드 | 위 절 |
| `Symbol.toStringTag` | `Object.prototype.toString` | 태그 문자열 | 위 절 |
| `Symbol.isConcatSpreadable` | `Array.prototype.concat` | 펼칠지 정하는 불리언 | 아래 |
| `Symbol.species` | `map`, `slice` 등 파생 객체를 만드는 메서드 | 파생 객체에 쓸 생성자 (정적 getter) | 25편 |
| `Symbol.match` | `String.prototype.match`, 정규식 판별 | 일치 검사 메서드 | 32편 |
| `Symbol.matchAll` | `String.prototype.matchAll` | 모든 일치를 돌려주는 메서드 | 32편 |
| `Symbol.replace` | `String.prototype.replace`, `replaceAll` | 치환 메서드 | 32편 |
| `Symbol.search` | `String.prototype.search` | 위치 검색 메서드 | 32편 |
| `Symbol.split` | `String.prototype.split` | 분할 메서드 | 32편 |
| `Symbol.unscopables` | `with` 문 | with 스코프에서 뺄 이름의 객체 | 아래 |

- ES2015에서 11개가 도입되었고, `asyncIterator`는 ES2018, `matchAll`은 ES2020에 추가되었습니다.
- `Symbol.dispose`와 `Symbol.asyncDispose`는 `using`·`await using` 선언이 호출하는 메서드의 키입니다(자세히는 03편). 명시적 자원 관리 제안이 추가했고 4단계에 올라 ES2027 판에 들어갈 예정이라 위 13개에는 포함하지 않았습니다.
- 데코레이터 메타데이터 제안은 `Symbol.metadata`를 추가하려 하지만 아직 표준이 아닙니다.

### Symbol.isConcatSpreadable

`concat`은 배열 인수를 펼쳐서 이어 붙이고 그 외 값은 통째로 붙입니다. 이 심벌 프로퍼티가 `true`이면 배열이 아닌 객체도 펼치고, `false`이면 배열도 펼치지 않습니다.

```js
const pair = { length: 2, 0: 'a', 1: 'b' }
pair[Symbol.isConcatSpreadable] = true
const r1 = [1].concat(pair)   // [1, 'a', 'b']

const arr = [3, 4]
arr[Symbol.isConcatSpreadable] = false
const r2 = [1].concat(arr)    // [1, [3, 4]]
```

- 펼칠 때는 `length`와 인덱스 프로퍼티를 읽으므로 유사 배열 객체여야 합니다.
- `pair`에 이 심벌이 없으면 `[1].concat(pair)`는 `pair`를 한 요소로 붙입니다.

### Symbol.match·replace·search·split·matchAll

`String.prototype`의 `match`, `matchAll`, `replace`, `replaceAll`, `search`, `split`은 인수에 해당 심벌 메서드가 있으면 문자열 처리 대신 그 메서드를 호출합니다. 정규식이 동작하는 것은 `RegExp.prototype`이 이 메서드들을 가지고 있기 때문이고, 같은 이름의 메서드를 가진 객체라면 정규식이 아니어도 인수로 쓸 수 있습니다.

```js
const upper = {
  [Symbol.replace](str, replacement) {
    return str.toUpperCase() + replacement
  },
}
'abc'.replace(upper, '!')   // 'ABC!'
```

- 호출은 `인수[Symbol.replace](문자열, 치환값)` 형태입니다.
- `Symbol.match`는 `startsWith`, `endsWith`, `includes`가 "정규식인지" 판별할 때도 읽힙니다. 정규식을 넘기면 TypeError인데, `re[Symbol.match] = false`로 바꾸면 정규식이 아닌 값으로 취급해 문자열로 바꿔 사용합니다.

```js
const re = /a/
'/a/'.startsWith(re)    // TypeError
re[Symbol.match] = false
'/a/'.startsWith(re)    // true  (문자열 '/a/'로 취급)
```

### Symbol.species

`map`, `filter`, `slice`, `concat` 같은 메서드는 결과 배열을 만들 때 `this.constructor[Symbol.species]`를 생성자로 씁니다. 서브클래스가 이 정적 getter를 재정의하면 파생 객체의 클래스를 바꿀 수 있습니다.

```js
class MyArray extends Array {
  static get [Symbol.species]() { return Array }
}
const m = new MyArray(1, 2, 3)
m instanceof MyArray               // true
m.map(x => x) instanceof MyArray   // false (일반 Array)
```

- `Array`, `Map`, `Set`, `RegExp`, `ArrayBuffer`, `Promise`, 타입드 어레이의 생성자는 `this`를 반환하는 정적 getter를 가집니다. 서브클래스가 재정의하지 않으면 서브클래스 자신이 species가 되어 파생 객체도 서브클래스 인스턴스입니다.

### Symbol.unscopables

`with` 문은 객체의 프로퍼티를 변수처럼 쓰게 하는 문법이며 엄격 모드에서는 SyntaxError입니다(자세히는 19편). `Symbol.unscopables` 객체에 `true`로 적힌 이름은 `with` 스코프에서 빠지고 바깥 변수로 해석됩니다.

```js
// 비엄격 모드 스크립트에서만 가능
var keys = 'outer'
with ([]) {
  keys   // 'outer'  (Array.prototype.keys가 아니다)
}
```

- `Array.prototype[Symbol.unscopables]`는 프로토타입이 `null`인 객체이고 `at`, `flat`, `includes`, `keys`, `values`, `toSorted` 등 16개 이름이 들어 있습니다.
- 새 배열 메서드가 추가될 때 오래된 `with` 코드가 같은 이름의 바깥 변수를 쓰고 있으면 깨지므로 이 목록이 만들어졌습니다. ES2015에서 `Array.prototype.values`가 추가되었을 때 Firefox에서 일부 사이트가 깨진 사례가 있습니다.
- 엄격 모드와 모듈에서는 `with`를 쓸 수 없어 일반 코드에서 다룰 일이 거의 없습니다.

## 심벌의 형 변환 제약

심벌은 문자열이나 숫자로 암묵적 변환되지 않습니다. 명시적 변환도 일부만 허용됩니다. 전체 변환 규칙은 08편이고 여기서는 심벌 기준으로 모았습니다.

| 연산 | 결과 |
|------|------|
| `String(sym)`, `sym.toString()` | `'Symbol(설명)'` |
| `sym.description` | 설명 문자열 또는 `undefined` |
| `Boolean(sym)`, `!sym`, `if (sym)` | `true` (심벌은 항상 truthy) |
| `sym + ''`, 템플릿 리터럴에 삽입 | TypeError |
| `Number(sym)`, `+sym`, `sym * 2` | TypeError |
| `[sym].join()`, `parseInt(sym)` | TypeError |
| `sym == 'a'`, `sym === 'a'` | `false` (에러 아님) |

```js
const sym = Symbol('a')
sym + ''      // TypeError (문자열로 변환 불가)
`${sym}`      // TypeError
+sym          // TypeError (숫자로 변환 불가)
String(sym)   // 'Symbol(a)'
sym == 'a'    // false
```

- 대소 비교(`sym < 1`), `Math.max(sym)`, `BigInt(sym)`도 숫자 변환을 거치므로 TypeError입니다.
- `==`와 `===`는 변환 없이 비교하므로 에러가 나지 않습니다. `Object(sym) == sym`은 래퍼 객체를 원시 값으로 바꿔 비교해 `true`입니다.
- `console.log(sym)`은 변환이 아니라서 출력됩니다. `console.log('id: ' + sym)`은 TypeError이고 `console.log('id:', sym)`은 정상입니다.
- 기본 `sort()`는 요소를 문자열로 비교하므로 심벌 배열에서 TypeError입니다. 비교 함수를 넘기고 `description`으로 비교합니다.
- 프로퍼티 키로 쓰는 것은 변환이 아닙니다. `obj[sym]`은 심벌을 그대로 키로 씁니다.
- `Object(sym) + ''`, `new String(sym)`, `String(Object(sym))`는 모두 TypeError입니다. `String(sym)`이 허용되는 것은 원시 심벌일 때뿐입니다.
- 문자열로 바꾸면 고유성이 사라집니다. 아래 두 문자열은 같지만 원래의 두 심벌은 다른 값입니다.

```js
const k1 = String(Symbol('a'))
const k2 = String(Symbol('a'))
k1 === k2   // true
```

## JSON·for...in에서 제외

`JSON.stringify`와 `for...in`은 문자열 키만 다룹니다. 심벌 키 프로퍼티는 열거 가능이어도 둘 다에서 빠집니다(자세히는 39편, 18편).

```js
const id = Symbol('id')
const user = { name: 'Kim', [id]: 1 }

JSON.stringify(user)   // '{"name":"Kim"}'
Object.keys(user)      // ['name']
const keys = []
for (const k in user) keys.push(k)
keys                   // ['name']
```

JSON에서의 규칙은 다음과 같습니다.

- 심벌 키 프로퍼티는 무시됩니다. replacer 함수도 심벌 키에는 호출되지 않아서 replacer로 포함시킬 수 없습니다.
- 심벌이 값이면 위치에 따라 다르게 처리됩니다.

```js
JSON.stringify({ a: Symbol('x') })  // '{}' (프로퍼티 생략)
JSON.stringify([Symbol('x')])       // '[null]'
JSON.stringify(Symbol('x'))         // undefined
```

- replacer로 값을 바꾸면 심벌 값은 포함시킬 수 있습니다. `(k, v) => typeof v === 'symbol' ? v.description : v`를 쓰면 `{ a: Symbol('x') }`가 `'{"a":"x"}'`가 됩니다.
- 심벌 키를 직렬화하려면 먼저 문자열 키 객체로 옮깁니다. 설명이 없는 심벌은 키가 `'undefined'`가 되고, 설명이 같은 심벌은 서로 덮어쓰므로 주의합니다.

```js
const o = { a: 1, [Symbol('b')]: 2 }
const flat = {}
for (const k of Reflect.ownKeys(o)) {
  flat[typeof k === 'symbol' ? k.description : k] = o[k]
}
flat   // { a: 1, b: 2 }
```

- `JSON.parse`는 심벌을 만들 수 없으므로 왕복할 수 없습니다.
- 호스트 API인 `structuredClone`도 심벌 키 프로퍼티를 에러 없이 버리고, 심벌 값을 만나면 `DataCloneError`를 던집니다(자세히는 10편).

`for...in`에서의 규칙은 다음과 같습니다.

- 자신과 프로토타입 체인의 열거 가능한 문자열 키만 순회합니다. 상속된 심벌 키도 나오지 않습니다.
- `Object.keys`, `values`, `entries`, `getOwnPropertyNames`도 같습니다. 심벌 키를 포함하는 API는 `Object.getOwnPropertySymbols`, `Reflect.ownKeys`입니다.

| API | 문자열 키 | 심벌 키 |
|-----|-----------|---------|
| `for...in` | 열거 가능 (상속 포함) | 제외 |
| `Object.keys` / `values` / `entries` | 열거 가능 | 제외 |
| `JSON.stringify` | 열거 가능 | 제외 |
| `Object.assign` / 객체 스프레드 | 열거 가능 | 열거 가능한 것만 복사 |
| `getOwnPropertyNames` | 전부 | 제외 |
| `getOwnPropertySymbols` | 제외 | 전부 |
| `Reflect.ownKeys` | 전부 | 전부 |

- 흔한 실수: `JSON.parse(JSON.stringify(obj))`로 복사하면 심벌 키 프로퍼티와 심벌 값이 사라집니다.
- 흔한 실수: `Object.keys(obj).length === 0`으로 빈 객체를 판정하면 심벌 키만 가진 객체도 비었다고 판정합니다. 심벌까지 보려면 `Reflect.ownKeys(obj).length`를 씁니다.

## 핵심 정리

- 심벌은 호출마다 고유한 원시 값입니다. `Symbol()`은 `new` 없이 호출하고, 설명이 같아도 서로 다릅니다. `Symbol.for(key)`만 key가 같으면 같은 심벌을 모든 realm에서 공유합니다.
- 심벌 키는 대괄호로만 접근합니다. `for...in`, `Object.keys`, `JSON.stringify`에서는 빠지지만 `Object.getOwnPropertySymbols`와 `Reflect.ownKeys`로 드러나므로 진짜 private이 아닙니다.
- 심벌 키로 빌트인 객체를 확장하면 이름 충돌과 `for...in` 노출이 없습니다. 전역 상태를 바꾼다는 점은 그대로입니다.
- Well-known Symbol 13개는 `for...of`, `instanceof`, 형 변환, 문자열 메서드 등 언어 동작을 객체가 바꾸는 훅입니다. `Symbol.dispose` 계열은 ES2027 예정입니다.
- 심벌은 문자열·숫자로 암묵 변환되지 않습니다. `+ ''`, 템플릿 삽입, 산술은 TypeError이고 `String(sym)`, `description`, 불리언 변환, `==` 비교만 에러 없이 동작합니다.
