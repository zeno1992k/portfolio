## 제어문의 분류

제어문은 위에서 아래로 한 문씩 실행되는 기본 흐름을 바꾸는 문입니다. 문은 값으로 쓸 수 없는 실행 단위입니다(자세히는 04편). 값이 필요한 자리에서 분기할 때는 식인 조건 연산자와 단축 평가를 씁니다(자세히는 06편, 08편).

| 분류 | 문 | 다루는 곳 |
|------|----|-----------|
| 분기 | `if...else`, `switch` | 이 편 |
| 반복 | `for`, `while`, `do...while` | 이 편 |
| 반복 | `for...in`, `for...of` | 개요는 이 편, 자세히는 18편·35편 |
| 점프 | `break`, `continue`, 레이블 | 이 편 |
| 점프 | `return` | 11편 |
| 예외 | `throw`, `try...catch` | 44편 |

## 블록문

블록문은 중괄호로 문 0개 이상을 묶어 문 하나처럼 다루게 하는 문입니다. `if`, `for` 같은 문은 본문으로 문 하나만 받으므로, 여러 문을 넣으려면 블록으로 묶습니다.

```js
const score = 70
if (score >= 60) {
  const label = 'pass'
  console.log(label) // 'pass'
}
```

- 블록 끝에는 세미콜론을 붙이지 않습니다. 붙이면 블록 뒤에 빈 문이 따로 생깁니다(아래 빈 문 절).
- 블록은 `let`, `const`, `class` 선언의 스코프를 만듭니다. `var`는 블록을 무시하고 함수 스코프에 속합니다(자세히는 12편).
- 블록 안의 `let`·`const`는 선언 줄 앞에서 접근하면 `ReferenceError`입니다(자세히는 03편).
- 함수 선언은 strict mode에서 블록 스코프입니다. sloppy mode에서는 블록 밖에서도 보이는 호환 동작이 있어 일관되지 않으므로 블록 안에 함수 선언을 쓰지 않습니다(자세히는 12편, 19편).
- 바깥 변수와 같은 이름을 블록 안에서 선언하면 그 블록 안에서는 안쪽 변수가 바깥 변수를 가립니다.

```js
let n = 1
{
  let n = 2      // 바깥 n을 가린다
  console.log(n) // 2
}
console.log(n)   // 1
```

단독 블록은 임시 변수의 수명을 그 블록으로 한정하고 싶을 때 씁니다.

문이 와야 하는 자리에서 `{`는 항상 블록의 시작입니다. 객체 리터럴이 아닙니다.

```js
{ a: 1 }       // 블록 안의 레이블 a와 식 1 (객체 아님)
{ a: 1, b: 2 } // SyntaxError
({ a: 1 })     // 소괄호 안은 식 자리이므로 객체
```

화살표 함수 본문의 `{`도 블록입니다. `() => { a: 1 }`은 `undefined`를 반환하고, 객체를 반환하려면 `() => ({ a: 1 })`로 씁니다(자세히는 27편).

## if...else

`if...else`는 조건식의 결과에 따라 두 문 중 하나를 실행하는 분기문입니다.

```js
const n = -3
if (n > 0) {
  console.log('positive')
} else if (n < 0) {
  console.log('negative') // 'negative'
} else {
  console.log('zero')
}
```

- 조건식의 결과는 불리언으로 변환해 판단합니다. falsy 값은 `false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN` 여덟 가지이고 나머지는 모두 truthy입니다(자세히는 08편).
- 빈 배열 `[]`, 빈 객체, 문자열 `'0'`과 `'false'`는 truthy입니다.
- `else if`는 별도 문법이 아닙니다. `else` 뒤에 `if` 문 하나가 온 것입니다.
- 체인은 위에서 아래로 검사해 처음 참인 분기만 실행하고 나머지 조건식은 평가하지 않습니다. 따라서 좁은 조건을 앞에 둡니다.

```js
const score = 95
if (score >= 60) console.log('pass')     // 'pass'
else if (score >= 90) console.log('top') // 도달하지 못한다
```

- 본문이 문 하나이면 중괄호를 생략할 수 있지만, 들여쓰기는 문법에 영향을 주지 않습니다.

```js
const ok = false
if (ok)
  console.log('a')
  console.log('b') // 'b' 출력. if의 본문은 첫 문장뿐이다
```

- `else`는 가장 가까운 `if`에 붙습니다(dangling else).

```js
const a = true, b = false
if (a)
  if (b) console.log('b')
else console.log('else') // 'else' (if (b)의 else)
```

- `let`, `const`, `class` 선언은 단독 문 자리에 올 수 없습니다. `if (ok) let x = 1`은 `SyntaxError`이므로 블록으로 감쌉니다.
- 조건을 만족하지 않을 때를 먼저 처리하고 `return`하는 방식(가드 절)을 쓰면 중첩이 줄어듭니다.

```js
function area(r) {
  if (typeof r !== 'number') return NaN
  if (r < 0) return NaN
  return Math.PI * r * r
}
```

흔한 실수는 다음과 같습니다.

- `if (x = 5)`: 대입식의 값 `5`가 조건이 되어 항상 참입니다. 비교는 `===`로 씁니다.
- `if (x == 1 || 2)`: `(x == 1) || 2`로 묶여 항상 참입니다. `x === 1 || x === 2`로 씁니다.
- `if (arr)`로 빈 배열을 검사: 빈 배열도 truthy입니다. `arr.length`를 검사합니다.

## switch와 폴스루

`switch`는 하나의 값을 여러 `case` 값과 비교해 일치하는 위치부터 실행하는 분기문입니다.

```js
const day = 3
switch (day) {
  case 1:
    console.log('Mon')
    break
  case 3:
    console.log('Wed') // 'Wed'
    break
  default:
    console.log('other')
}
```

실행 규칙은 다음과 같습니다.

1. `switch` 뒤의 식을 한 번 평가합니다.
2. `case`의 식을 위에서 아래로 평가하며 `===`로 비교합니다. 처음 일치한 `case`에서 멈추고, 이후 `case`의 식은 평가하지 않습니다.
3. 일치한 `case`의 본문부터 실행합니다.
4. `break`를 만나거나 `switch`가 끝날 때까지 아래로 계속 실행합니다.
5. 일치하는 `case`가 없으면 `default`부터 실행합니다.

4번이 폴스루(fallthrough)입니다. `break`가 없으면 다음 `case`의 조건을 검사하지 않고 본문을 이어서 실행합니다.

```js
switch (2) {
  case 1: console.log('one')
  case 2: console.log('two')   // 'two'
  case 3: console.log('three') // 'three' (검사 없이 이어짐)
  case 4: break
  default: console.log('d')    // 실행되지 않는다
}
```

여러 값에 같은 본문을 쓰려고 `case`를 연달아 적는 것이 의도된 폴스루의 대표 용례입니다.

```js
const month = 1
switch (month) {
  case 12:
  case 1:
  case 2:
    console.log('winter') // 'winter'
    break
}
```

- `default`는 마지막에 두는 것이 관례이지만 어디에 있어도 됩니다. 모든 `case`를 먼저 검사해 일치가 없을 때만 `default`부터 실행하고, 그 뒤의 `case` 본문으로 폴스루합니다.

```js
switch (x) {
  case 1: console.log('1')
  default: console.log('d')
  case 2: console.log('2'); break
  case 3: console.log('3')
}
// x=1 → 1 d 2   x=2 → 2
// x=3 → 3       x=9 → d 2
```

- `case`에는 상수뿐 아니라 임의의 식을 쓸 수 있습니다. `switch (true)`에 불리언 식을 `case`로 두면 범위 조건을 분기할 수 있습니다.

```js
const score = 85
switch (true) {
  case score >= 90: console.log('A'); break
  case score >= 80: console.log('B'); break // 'B'
  default: console.log('C')
}
```

이 패턴은 `true === (score >= 90)`처럼 비교하므로 불리언 값만 일치합니다. `1`이나 `'a'`처럼 truthy이지만 `true`가 아닌 값을 내는 식은 일치하지 않습니다.

- 마지막 절의 `break`는 생략해도 동작이 같습니다.
- 함수 안에서는 `break` 대신 `return`으로 빠져나갈 수 있습니다.
- `switch`는 문이라 값을 반환하지 않습니다. 값 매핑이 목적이면 객체 조회나 조건 연산자가 간결합니다.
- 의도한 폴스루에는 `// falls through` 주석을 남깁니다. ESLint의 `no-fallthrough` 규칙은 이 주석이 있으면 의도한 것으로 봅니다.

흔한 실수는 `break` 누락입니다. 일치한 뒤 아래 `case` 본문이 모두 실행되어도 에러가 나지 않으므로 발견하기 어렵습니다.

## switch의 일치 비교와 블록 스코프 함정

### 일치 비교

`case`는 `===`(엄격 일치)로 비교하므로 타입 변환이 일어나지 않습니다(자세히는 06편).

| 상황 | 결과 | 이유 |
|------|------|------|
| `switch ('1')`에 `case 1` | 불일치 | 문자열과 숫자는 타입이 다르다 |
| `switch (NaN)`에 `case NaN` | 불일치, `default`로 | `NaN === NaN`이 거짓 |
| `switch (-0)`에 `case 0` | 일치 | `===`는 `+0`과 `-0`을 구분하지 않는다 |
| `case {}`나 `case []` | 일치하는 값이 없다 | 객체는 같은 참조여야 일치 |
| `switch (null)`에 `case undefined` | 불일치 | `===`는 둘을 구분한다 |

`NaN`을 분기하려면 `switch (true)`에 `case Number.isNaN(x)`를 쓰거나 `if`로 먼저 걸러냅니다(자세히는 30편).

### 블록 스코프 함정

`switch` 뒤의 중괄호 전체가 블록 하나입니다. 모든 `case`와 `default`가 같은 스코프를 공유하므로 두 가지 문제가 생깁니다.

첫째, 서로 다른 `case`에서 같은 이름을 `let`·`const`로 선언하면 `SyntaxError`입니다.

```js
switch (kind) {
  case 'a':
    const msg = 'A'
    break
  case 'b':
    const msg = 'B' // SyntaxError (msg 중복 선언)
}
```

둘째, 실행되지 않은 `case`에서 선언한 변수에 접근하면 `ReferenceError`입니다. 바인딩은 블록에 들어가는 시점에 만들어지지만, 초기화는 그 선언 줄을 실행해야 이루어지기 때문입니다.

```js
switch (2) {
  case 1:
    let a = 1
    break
  case 2:
    console.log(a) // ReferenceError: Cannot access 'a' ...
}
```

해결은 각 `case` 본문을 자신의 블록으로 감싸는 것입니다. ESLint의 `no-case-declarations` 규칙이 이 문제를 잡습니다.

```js
switch (kind) {
  case 'a': {
    const msg = 'A'
    break
  }
  case 'b': {
    const msg = 'B' // 별개의 스코프라 충돌하지 않는다
    break
  }
}
```

`class` 선언도 같은 규칙을 따릅니다. `var`는 충돌하지 않지만 함수 전체에서 공유됩니다.

## for

`for`는 초기화, 조건, 증감 세 부분으로 반복을 제어하는 문입니다. 반복 횟수를 미리 알 때 씁니다.

```js
for (let i = 0; i < 3; i++) {
  console.log(i)
}
// 0
// 1
// 2
```

실행 순서는 다음과 같습니다.

1. 초기화 식을 한 번 실행합니다.
2. 조건식을 평가합니다. 거짓이면 종료합니다.
3. 본문을 실행합니다.
4. 증감식을 실행합니다.
5. 2번으로 돌아갑니다.

규칙은 다음과 같습니다.

- 세 부분은 모두 생략할 수 있습니다. 조건을 생략하면 참으로 취급하므로 `for (;;)`는 무한 루프입니다.
- 초기화에서 변수를 여러 개 선언하거나 증감식에서 쉼표 연산자로 여러 식을 실행할 수 있습니다(자세히는 06편).

```js
for (let i = 0, j = 5; i < j; i++, j--) console.log(i, j)
// 0 5
// 1 4
// 2 3
```

- 초기화에 `let`을 쓰면 반복마다 새 바인딩이 만들어져 이전 값이 복사됩니다(ES2015). `var`는 반복 전체가 변수 하나를 공유합니다. 클로저가 값을 붙잡을 때 차이가 드러납니다(자세히는 23편).

```js
const a = [], b = []
for (var i = 0; i < 3; i++) a.push(() => i)
for (let j = 0; j < 3; j++) b.push(() => j)
console.log(a.map(f => f())) // [3, 3, 3]
console.log(b.map(f => f())) // [0, 1, 2]
```

- 초기화의 `const`는 첫 증감식에서 `TypeError: Assignment to constant variable.`을 일으킵니다. 증감식 없이 한 번만 도는 경우에만 쓸 수 있습니다.
- `let` 변수는 루프가 끝나면 접근할 수 없습니다. 초기화에서 `var`를 쓰거나 기존 변수를 재사용하면 루프가 끝난 뒤에도 변수가 남습니다.
- 증감식은 `i += 2`나 `i--`처럼 어떤 식이든 됩니다. 역순 순회는 `for (let i = n - 1; i >= 0; i--)`입니다.
- 조건식은 매 반복마다 평가됩니다. `i < arr.length`는 반복 중 배열의 길이가 바뀌면 그 값을 따릅니다.
- 본문 안에서 반복 변수를 바꾸면 증감식과 겹쳐 반복 횟수를 읽기 어려워집니다.

흔한 실수는 경계값입니다. 길이 3인 배열에 `i <= arr.length`를 쓰면 `arr[3]`이 `undefined`인 반복이 한 번 더 돕니다. 소수 카운터도 위험합니다. `0.1`을 열 번 더하면 `0.9999999999999999`이므로 `x !== 1`을 종료 조건으로 쓴 루프는 끝나지 않습니다.

## 중첩 for

중첩 `for`는 `for`의 본문에 또 다른 `for`를 둔 구조입니다. 바깥 루프가 한 번 돌 때마다 안쪽 루프가 처음부터 끝까지 실행됩니다.

```js
for (let i = 1; i <= 3; i++) {
  let row = ''
  for (let j = 1; j <= i; j++) row += '*'
  console.log(row)
}
// *
// **
// ***
```

- 안쪽 본문의 실행 횟수는 바깥 횟수 곱하기 안쪽 횟수입니다. 구구단 2단부터 9단까지는 8 × 9 = 72회입니다. 안쪽 횟수가 위 예제처럼 `i`에 따라 달라지면 곱이 아니라 합(1 + 2 + 3 = 6)입니다.
- 각 단계가 n회이면 2중은 n², 3중은 n³회입니다. n이 1000이면 3중 루프는 10억 회입니다.
- 관례적으로 바깥부터 `i`, `j`, `k`를 씁니다.
- 안쪽에서 `let i`를 다시 선언하면 바깥 `i`를 가려 동작은 하지만 안쪽에서 바깥 값을 읽을 수 없습니다. `var`로 같은 이름을 쓰면 변수 하나를 공유하므로 안쪽 루프가 끝난 값에서 바깥 증감이 이어져 바깥 루프가 한 번만 돕니다.
- 안쪽 루프에서 쓴 `break`는 안쪽 루프만 끝냅니다. 바깥까지 빠져나가려면 레이블(아래 레이블 문 절)을 쓰거나, 루프를 함수로 분리해 `return`합니다.
- 안쪽 루프에서 매번 같은 값을 계산하면 바깥 루프로 올립니다.

## while과 do...while

`while`은 조건을 먼저 검사한 뒤 본문을 실행하고, `do...while`은 본문을 먼저 실행한 뒤 조건을 검사하는 반복문입니다. `do...while`의 본문은 최소 한 번 실행됩니다.

```js
let a = 10, b = 10
while (a < 5) a++     // 조건이 처음부터 거짓: 0회
do b++; while (b < 5) // 본문 먼저: 1회
console.log(a, b)     // 10 11
```

- 반복 횟수를 모를 때 `while`을 씁니다. 종료 조건에 쓰는 값을 본문 안에서 직접 바꿔야 합니다.

```js
let n = 1234, digits = 0
while (n > 0) {
  n = Math.floor(n / 10)
  digits++
}
console.log(digits) // 4
```

- `do...while`은 닫는 괄호 뒤의 세미콜론을 생략해도 자동 세미콜론 삽입이 보충하므로 같은 줄에 다음 문이 와도 됩니다. 그래도 세미콜론을 붙이는 편이 읽기 쉽습니다.
- 본문에서 `let`·`const`로 선언한 변수는 조건식에서 보이지 않습니다. 본문 블록과 조건식은 별개의 스코프입니다.

```js
do { let x = 1 } while (x < 3)
// ReferenceError: x is not defined
```

- 조건에 증감식을 넣은 `while (i--)`는 감소 전의 값으로 조건을 판단합니다. 값이 `0`이 되면 거짓이 되어 끝납니다.

```js
let i = 3
while (i--) console.log(i) // 2, 1, 0
console.log(i)             // -1
```

- 주사위가 6이 나올 때까지 굴리는 것처럼 최소 한 번은 실행해야 하는 경우에 `do...while`이 맞습니다.

```js
let roll
do {
  roll = Math.floor(Math.random() * 6) + 1
} while (roll !== 6)
```

## 무한 루프

무한 루프는 종료 조건이 끝내 거짓이 되지 않아 끝나지 않는 반복입니다. 의도해서 만들기도 하고 실수로 생기기도 합니다.

의도한 무한 루프는 `while (true)`나 `for (;;)`로 쓰고 본문 안에서 `break`, `return`, `throw`로 빠져나옵니다.

```js
let n = 0
while (true) {
  n++
  if (n * n > 50) break
}
console.log(n) // 8
```

의도하지 않은 무한 루프의 원인은 다음과 같습니다.

| 원인 | 예 |
|------|----|
| 갱신 누락 | `while (i < 3) {}`에서 `i`를 바꾸지 않음 |
| 갱신 방향 오류 | `for (let i = 0; i >= 0; i++)` |
| `continue`가 갱신을 건너뜀 | 아래 break·continue 절 |
| 부동소수점 | `x !== 1`을 조건으로 0.1씩 증가 |
| `NaN` 비교 | `i !== NaN`은 항상 참 |
| 반복 중 컬렉션 증가 | `i < arr.length`인데 본문에서 `arr.push` |

- 자바스크립트는 코드를 한 번에 하나씩 실행하므로, 동기 무한 루프가 도는 동안 같은 스레드의 타이머, 이벤트 핸들러, 화면 갱신이 모두 멈춥니다. 브라우저에서는 탭이 응답하지 않고 Node.js에서는 프로세스가 CPU를 계속 쓰며 끝나지 않습니다(자세히는 40편).
- 에러가 아니므로 `try...catch`로 막을 수 없습니다.
- 어떤 값이 바뀌기를 기다리며 `while (!done) {}`로 도는 방식은 값을 바꿀 타이머 콜백이 실행될 기회가 없어 영원히 끝나지 않습니다. 기다림은 비동기로 처리합니다(자세히는 40편).

```js
let done = false
setTimeout(() => { done = true }, 100)
while (!done) {} // 타이머가 실행되지 못해 끝나지 않음
```

예방책은 다음과 같습니다.

- 조건에 쓰는 변수가 본문에서 실제로 바뀌는지 확인합니다.
- 소수 카운터는 `!==` 대신 `<`로 비교하거나 정수 카운터를 씁니다.
- 재시도 같은 반복에는 최대 횟수 카운터를 두고 초과하면 빠져나옵니다.

## break와 continue

`break`는 가장 안쪽 반복문이나 `switch`를 즉시 끝내고 그 다음 문으로 넘어갑니다. `continue`는 현재 반복의 남은 본문을 건너뛰고 다음 반복으로 넘어갑니다.

```js
for (let i = 0; i < 5; i++) {
  if (i === 1) continue
  if (i === 3) break
  console.log(i)
}
// 0
// 2
```

`continue` 뒤의 흐름은 반복문마다 다릅니다.

| 반복문 | `continue` 후 이동 위치 |
|--------|------------------------|
| `for` | 증감식 실행 → 조건 검사 |
| `while`, `do...while` | 바로 조건 검사 |

`while`에서 증감을 본문 끝에 두었다면 `continue`가 증감을 건너뛰어 무한 루프가 됩니다.

```js
let i = 0
while (i < 5) {
  if (i === 2) continue // i++를 건너뛰어 i는 계속 2
  i++
}
```

- `for` 안에 있는 `switch`에서 `break`는 `switch`만 끝냅니다. 루프까지 끝내려면 레이블이나 `return`이 필요합니다.
- `continue`는 `switch` 안에서 써도 바깥 반복문의 다음 반복으로 넘어갑니다. 반복문 밖의 `switch`에서 쓰면 `SyntaxError`입니다.
- `break`는 반복문, `switch`, 레이블 문 안에서만 쓸 수 있고 `continue`는 반복문 안에서만 쓸 수 있습니다. 밖에서 쓰면 `SyntaxError`입니다.
- 함수 경계를 넘을 수 없습니다. `forEach` 콜백 안의 `break`와 `continue`는 `SyntaxError`입니다. 콜백의 `return`은 그 호출만 끝내므로 `continue`처럼 동작하고 반복 전체를 끝낼 수는 없습니다. 중간에 끝내려면 `for...of`나 `some`, `every`를 씁니다(자세히는 29편).

## 레이블 문

레이블 문은 문 앞에 `식별자:`를 붙여 이름을 준 문입니다. `break 레이블`과 `continue 레이블`이 바깥 루프나 블록을 직접 가리키게 하려고 씁니다.

```js
outer: for (let i = 0; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    if (j === 1) continue outer // 바깥 루프의 다음 반복으로
    if (i === 2) break outer    // 바깥 루프 종료
    console.log(i, j)
  }
}
// 0 0
// 1 0
```

- `break 레이블`은 반복문이 아닌 블록에도 붙일 수 있습니다. 블록을 중간에서 빠져나오는 용도입니다.

```js
const ok = false
found: {
  console.log('start') // 'start'
  if (!ok) break found
  console.log('skipped') // 실행되지 않는다
}
```

- `continue 레이블`은 반복문의 레이블만 가리킬 수 있습니다. 반복문이 아닌 레이블이면 `SyntaxError`입니다.
- 레이블은 그 레이블 문의 내부에 있고 같은 함수 안인 `break`·`continue`만 가리킬 수 있습니다. 정의되지 않은 레이블은 `SyntaxError`입니다.
- 중첩된 문에 같은 레이블을 다시 쓸 수 없습니다.
- 레이블은 변수와 별개의 이름 공간이라 같은 이름의 변수와 충돌하지 않지만, 혼동을 피하려고 다른 이름을 씁니다.
- `break`나 `continue`와 레이블 사이에 줄바꿈을 넣으면 안 됩니다. 줄바꿈이 있으면 자동 세미콜론 삽입으로 레이블 없는 `break`가 됩니다.
- 레이블은 가독성을 떨어뜨리므로 드물게 씁니다. 루프를 함수로 분리해 `return`하는 방식이 대안입니다.

## for...in과 for...of 개요

`for...in`은 객체의 키를 순회하고 `for...of`는 이터러블이 내놓는 값을 순회하는 반복문입니다.

```js
const obj = { a: 1, b: 2 }
for (const key in obj) console.log(key, obj[key])
// a 1
// b 2
for (const ch of 'hi') console.log(ch)
// h
// i
```

| 구분 | `for...in` | `for...of` |
|------|-----------|-----------|
| 도입 | ES1 | ES2015 |
| 순회 대상 | 객체의 열거 가능한 문자열 키 | 이터러블이 내놓는 값 |
| 배열에서 | 인덱스(문자열) | 요소 |
| 일반 객체 | 순회 가능 | `TypeError` |
| `null`, `undefined` | 0회, 에러 없음 | `TypeError` |
| 상속된 프로퍼티 | 포함 | 해당 없음 |

### for...in

- 열거 가능한 문자열 키를 순회합니다. 열거 불가 프로퍼티와 심벌 키는 제외하고, 프로토타입 체인의 열거 가능 프로퍼티는 포함합니다.
- 순서는 정수 형태의 키가 오름차순으로 먼저 오고, 나머지 문자열 키는 생성 순서입니다. 자기 프로퍼티를 먼저, 그다음 프로토타입의 프로퍼티를 방문하며 같은 이름은 한 번만 방문합니다(자세히는 18편).

```js
const o = { b: 1, 2: 'x', a: 2, 1: 'y' }
for (const k in o) console.log(k) // 1, 2, b, a
```

- 상속 프로퍼티까지 나오므로 자기 프로퍼티만 필요하면 걸러내야 합니다(자세히는 18편).
- 순회 중 프로퍼티를 추가하거나 삭제하면 그 프로퍼티의 방문 여부에 기대지 않습니다. 순회 중에는 객체를 수정하지 않습니다.
- 배열에 쓰면 인덱스가 숫자가 아닌 문자열로 나오고, 배열에 붙은 일반 프로퍼티나 `Array.prototype`에 추가된 열거 가능 프로퍼티도 함께 나옵니다. 배열에는 쓰지 않습니다.

```js
for (const k in ['x', 'y']) console.log(typeof k)
// 'string' 'string'
```

- 구멍이 있는 배열 `[, 1]`에서 `for...in`은 존재하는 인덱스 `'1'`만 방문합니다. `for...of`는 구멍을 `undefined`로 방문해 두 번 돕니다.

### for...of

- `Symbol.iterator` 메서드를 가진 객체(이터러블)를 순회합니다. 배열, 문자열, `Map`, `Set`, `arguments`, 제너레이터가 이터러블입니다(자세히는 35편).
- 일반 객체는 이터러블이 아니어서 `for (const x of { a: 1 })`은 `TypeError`입니다. 객체의 키와 값은 `Object.entries`로 배열을 만들어 순회합니다.

```js
for (const [k, v] of Object.entries({ p: 1, q: 2 })) {
  console.log(k, v)
}
// p 1
// q 2
```

- 문자열은 UTF-16 코드 단위가 아니라 코드 포인트 단위로 순회합니다. `'😀'.length`는 `2`이지만 `for...of`는 한 번만 돕니다(자세히는 33편).
- `break`, `continue`, `return`을 쓸 수 있습니다. `forEach`와 달리 중간에 끝낼 수 있습니다. 중간에 빠져나가면 이터레이터의 `return` 메서드가 호출되어 정리 동작이 실행됩니다.
- `Map`의 `[key, value]` 쌍처럼 구조 분해로 바로 받을 수 있습니다(자세히는 37편).
- 비동기 이터러블은 `for await...of`(ES2018)로 순회하고, `async` 함수나 모듈 최상위에서만 쓸 수 있습니다(자세히는 43편).

### 공통 규칙

- 변수를 `const`로 선언해도 됩니다. 반복마다 새 바인딩이 만들어지기 때문입니다. 증감식이 있는 일반 `for`에서 `const`가 `TypeError`를 일으키는 것과 다릅니다.
- 배열 순회는 `for...of`, 객체 순회는 `Object.keys`·`Object.entries`와 `for...of`의 조합이 기본 선택입니다.

## 빈 문

빈 문은 세미콜론 하나만 있는 문입니다. 아무 일도 하지 않지만 문법상 문이 필요한 자리를 채웁니다.

```js
let i = 0
for (; i * i < 10; i++); // 본문이 빈 문
console.log(i)           // 4
```

- 블록 뒤에 세미콜론을 붙이면 그 세미콜론이 별도의 빈 문입니다. 에러는 아닙니다.
- 빈 문 `;`과 빈 블록 `{}`은 다릅니다. 블록은 스코프를 만드는 복합 문이고, 빈 문은 아무것도 아닌 문입니다.
- 의도한 빈 본문은 `{}`나 주석으로 표시해야 읽는 사람이 실수와 구분할 수 있습니다.

흔한 실수는 `if`나 `for`의 닫는 괄호 뒤에 세미콜론을 붙이는 것입니다. 세미콜론이 본문이 되어, 뒤의 블록은 조건·반복과 무관한 별개의 블록이 됩니다.

```js
const ok = false
if (ok); { console.log('항상 실행') } // ok와 무관하게 출력
for (let i = 0; i < 3; i++); { console.log('once') } // 1회
```

## 핵심 정리

- 블록 `{}`는 문 여럿을 하나로 묶고 `let`·`const`의 스코프를 만듭니다. 문 자리의 `{`는 객체가 아니라 블록입니다.
- `switch`는 `===`로 비교하고, 일치한 `case`부터 `break`를 만날 때까지 실행합니다. 모든 `case`가 블록 하나를 공유하므로 본문을 `{}`로 감쌉니다.
- `for`는 초기화 → 조건 → 본문 → 증감 순으로 돌고, `let`은 반복마다 새 바인딩을 만듭니다. `do...while`만 본문을 최소 한 번 실행합니다.
- `break`는 가장 안쪽 반복문·`switch`만 끝내고, 바깥으로 나가려면 레이블이나 `return`이 필요합니다. `while`의 `continue`는 갱신을 건너뛸 수 있습니다.
- `for...in`은 객체의 열거 가능한 문자열 키(상속 포함), `for...of`는 이터러블의 값을 순회합니다. 배열에는 `for...of`를 씁니다.
- `if`·`for` 괄호 뒤의 세미콜론은 빈 본문이 됩니다.
