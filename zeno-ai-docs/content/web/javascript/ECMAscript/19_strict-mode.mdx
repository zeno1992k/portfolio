## 개념과 적용

strict mode(엄격 모드)는 ES5(2009)에서 도입된, 일부 동작을 더 엄격하게 바꾸는 선택 사항입니다. 켜지 않은 코드는 비엄격 모드(sloppy mode)로 실행됩니다. 명세 용어로는 비엄격 코드(non-strict code)입니다.

바꾸는 내용은 세 갈래입니다.

- 조용히 무시되던 실수를 에러로 바꿉니다.
- 이름이 가리키는 대상을 실행 전에 정할 수 있게 합니다. `with`를 금지하고, `eval`이 호출한 스코프에 변수를 추가하지 못하게 합니다.
- 앞으로 문법이 될 단어를 예약합니다. `let`, `static`, `yield` 등이 실제로 ES2015에서 문법이 됐습니다.

켜는 방법은 지시어(directive)입니다. 스크립트나 함수 본문의 맨 앞에 문자열 문장 `'use strict'`를 둡니다.

```js
'use strict'        // 스크립트 전체

function f() {
  'use strict'      // 이 함수 본문과 안에 중첩된 함수
}
```

ES5 이전 엔진은 이 문장을 효과 없는 문자열 식으로 무시합니다. 하위 호환을 해치지 않고 strict mode를 요청하려는 설계입니다.

### 지시어로 인정되는 형태

지시어는 스크립트·함수 본문의 첫머리에 이어지는 "문자열 리터럴만으로 된 문장" 구간(지시어 서문) 안에 있어야 합니다. 그 안에 글자 그대로 `use strict`가 있으면 켜집니다.

| 형태 | 결과 | 이유 |
|------|------|------|
| `'use strict'` 또는 `"use strict"` | 인정 | 따옴표 종류는 무관 |
| 주석 뒤의 지시어 | 인정 | 주석은 문장이 아님 |
| `'abc'; 'use strict'` | 인정 | 앞의 문자열 문장도 지시어 서문에 속함 |
| `var a = 1; 'use strict'` | 무시 | 앞에 일반 문장이 있음 |
| `('use strict')` | 무시 | 괄호로 감싼 식 |
| 백틱으로 감싼 문자열 | 무시 | 템플릿 리터럴은 문자열 리터럴이 아님 |
| `'use stric\x74'` | 무시 | 이스케이프 시퀀스(`\x74` 등) 포함 |
| `'Use Strict'`, `'use  strict'` | 무시 | 대소문자·공백이 다름 |
| `{ 'use strict' }` | 무시 | 블록 안은 서문이 아님 |

무시된 지시어는 에러도 경고도 내지 않습니다. 값 없는 문자열 문장으로 실행될 뿐입니다.

### 적용 단위와 상속

- 스크립트 첫머리의 지시어는 그 스크립트 전체에 적용됩니다.
- 함수 첫머리의 지시어는 그 함수와 안에 중첩된 모든 함수에 적용됩니다. 형제 함수나 바깥 코드에는 영향이 없습니다.
- 한번 켜진 strict mode는 안쪽에서 끌 수 없습니다. 끄는 지시어는 없습니다.
- strict 여부는 코드가 적힌 위치로 정해집니다. 호출하는 쪽의 모드와는 무관합니다.

```js
function sloppy() { return this === globalThis }

function strictCaller() {
  'use strict'
  return sloppy()
}
strictCaller()   // true — 호출자가 strict여도 sloppy는 비엄격
```

## 전역·함수 단위 적용의 문제점

지시어는 스크립트 단위와 함수 단위로만 쓸 수 있어서 두 방식 모두 단위 경계에서 문제가 생깁니다.

### 스크립트 단위

- 파일 전체가 strict가 되므로, 그 안에 옛 코드(`with`, 8진 리터럴, 선언 없는 대입 등)가 하나라도 있으면 SyntaxError로 스크립트가 실행되지 않거나 실행 중 ReferenceError·TypeError가 납니다.
- 파일을 단순히 이어 붙이면 맨 앞 파일의 지시어만 의미가 있습니다.

| 합친 순서 | 결과 |
|-----------|------|
| strict 파일 → 비엄격 파일 | 지시어가 맨 앞이라 전체가 strict. 뒤 파일의 옛 코드가 에러 |
| 비엄격 파일 → strict 파일 | 지시어가 맨 앞이 아니라 무시. strict 파일이 비엄격으로 실행되고 에러도 없음 |

- 별개의 `<script>` 요소와 Node.js의 CommonJS 파일은 각각 따로 컴파일되므로, 지시어가 그 파일에만 적용됩니다.

### 함수 단위

- 함수마다 지시어를 반복해야 하고, 빠뜨린 함수는 비엄격입니다. 모듈 이전에는 파일 전체를 즉시 실행 함수로 감싸 함수 단위로 적용했습니다.

```js
(function () {
  'use strict'
  // 파일의 모든 코드
})()
```

- 비단순 매개변수(기본값, 나머지, 구조 분해)를 가진 함수의 본문에는 지시어를 쓸 수 없습니다(ES2016부터). 바깥 코드에서 켜거나 모듈·클래스를 씁니다(매개변수 문법은 27편).

```js
function f(a = 1) { 'use strict' }   // SyntaxError
```

- 본문 첫머리의 지시어는 함수 이름과 매개변수 목록까지 소급해서 검사합니다. 지시어를 추가한 것만으로 시그니처가 에러가 될 수 있습니다.

```js
function f(a, a) { 'use strict' }    // SyntaxError
```

- 식 본문 화살표 함수(`x => x * 2`)는 지시어를 쓸 자리가 없어 바깥 코드의 모드를 따릅니다.

### 공통 문제와 대응

- 지시어를 잘못된 위치에 두어도 에러가 없으므로 적용되지 않은 사실을 알기 어렵습니다. ESLint의 `strict` 규칙이 지시어를 파일 단위로 둘지 함수 단위로 둘지 강제하고, ES 모듈 안의 지시어는 금지합니다.
- 클래스와 ES 모듈은 지시어 없이 자동으로 strict이므로 새 코드는 모듈로 쓰는 것이 가장 단순합니다(아래 "클래스와 모듈의 자동 적용").
- 모듈이 아닌 파일은 파일 첫머리에 지시어를 하나 둡니다.

## strict mode가 발생시키는 에러

비엄격 모드에서 조용히 무시되거나 전역을 오염시키던 동작이 strict mode에서는 에러가 됩니다. 에러는 세 종류입니다(자세히는 44편).

| 에러 | 발생 시점 | 원인 |
|------|-----------|------|
| SyntaxError | 파싱 단계. 그 스크립트 전체가 실행되지 않는다 | 금지 문법(아래 "금지 문법 전체 표") |
| ReferenceError | 실행 중 | 선언 없는 이름에 대입 |
| TypeError | 실행 중 | 프로퍼티 대입·삭제 등이 거부됨 |

실행 중에 에러가 되는 동작은 다음과 같습니다.

| 동작 | 비엄격 모드 | strict mode |
|------|-------------|-------------|
| 선언 없는 이름에 대입 `x = 1` | 전역 프로퍼티 생성 | ReferenceError |
| `writable`이 false인 프로퍼티에 대입 | 무시 | TypeError |
| setter 없는 접근자 프로퍼티에 대입 | 무시 | TypeError |
| 확장 불가 객체에 새 프로퍼티 추가 | 무시 | TypeError |
| `configurable`이 false인 프로퍼티 삭제 | false 반환 | TypeError |
| 원시 값에 프로퍼티 대입 `(1).x = 1` | 무시 | TypeError |
| `undefined`·`NaN`·`Infinity`에 대입 | 무시 | TypeError |
| 문자열의 인덱스·`length`에 대입 | 무시 | TypeError |
| `arguments.callee` 읽기 | 현재 함수 반환 | TypeError |

```js
'use strict'
const user = Object.freeze({ name: 'Kim' })

user.name = 'Lee'    // TypeError (쓰기 불가)
user.age = 20        // TypeError (확장 불가)
delete user.name     // TypeError (삭제 불가)
count = 1            // ReferenceError (선언 없는 대입)
```

- 프로퍼티 대입·삭제가 거부되어 내부적으로 false를 돌려줄 때, 비엄격 코드는 그 false를 무시하고 strict 코드는 TypeError로 바꿉니다(어트리뷰트는 14편).
- strict 여부는 대입·삭제를 실행하는 코드의 모드로 정해집니다. 객체를 동결한 코드의 모드는 상관없습니다.
- 선언 없는 이름은 읽기만 해도 모드와 상관없이 ReferenceError입니다. strict mode가 바꾸는 것은 대입입니다. `typeof undeclared`는 두 모드 모두 `'undefined'`를 돌려줍니다(암묵적 전역은 20편).
- 모드와 상관없이 항상 에러인 것도 있습니다. `Object.defineProperty`의 거부와 동결된 배열에 대한 `push` 같은 내장 메서드는 항상 TypeError이고, `Reflect.set`은 에러 대신 false를 돌려줍니다(자세히는 47편).

흔한 실수는 비엄격 코드를 strict로 바꾼 직후 나는 에러를 새 버그로 여기는 것입니다. 그 줄은 원래 아무 일도 하지 않거나 의도하지 않은 전역을 만들던 코드입니다.

```js
let total = 0
totl = total + 1   // 비엄격: 전역 totl 생성 (오타가 숨는다)
                   // strict: ReferenceError
```

## strict mode의 this와 arguments

### this

strict mode는 호출할 때 넘어온 값을 `this`로 그대로 씁니다. 비엄격 모드는 `undefined`·`null`을 전역 객체로 바꾸고 원시 값을 래퍼 객체로 감쌉니다(래퍼 객체는 20편).

```js
function sloppy() { return this }
function strict() { 'use strict'; return this }

sloppy() === globalThis   // true
strict()                  // undefined
typeof sloppy.call(1)     // 'object' (Number 래퍼)
typeof strict.call(1)     // 'number'
strict.call(null)         // null
```

- 이 규칙은 `call`·`apply`·`bind`와 `thisArg`를 받는 배열 메서드(`map(fn, thisArg)`)에 모두 같습니다. `f.call(1)` 안에서 `this === 1`은 비엄격에서 false, strict에서 true입니다.
- 일반 함수 안의 `this.x = 1`은 비엄격에서 전역 프로퍼티를 만들고, strict에서는 `this`가 `undefined`라서 TypeError입니다. 생성자를 `new` 없이 호출한 실수가 이렇게 드러납니다(15편).
- 전역 코드 최상위의 `this`는 strict 여부와 무관하게 전역 객체입니다. 모듈 최상위의 `this`는 `undefined`입니다(46편).
- 화살표 함수는 자체 `this`가 없어 바깥의 `this`를 쓰므로 호출 방식으로 바뀌지 않습니다(자세히는 21편, 27편).

객체에서 꺼낸 메서드는 일반 함수 호출이 되어 `this`를 잃습니다. 이때 두 모드의 차이가 에러 여부로 갈립니다.

```js
const obj = { name: 'Kim', hi() { return this.name } }
const hi = obj.hi
hi()   // 비엄격: globalThis.name을 읽음 (조용히 엉뚱한 값)
       // strict: TypeError (undefined의 프로퍼티 읽기)
```

현재 코드가 strict인지는 일반 함수 안의 `this`로 확인합니다. 화살표 함수로는 확인할 수 없습니다.

```js
const isStrict = (function () {
  return this === undefined
})()
```

### arguments

`arguments` 객체 자체는 16편에서 다루고, 여기서는 두 모드의 차이만 정리합니다.

| 항목 | 비엄격 모드 | strict mode |
|------|-------------|-------------|
| 매개변수와 `arguments[i]` | 서로 연동 | 연동 없음 |
| `arguments.callee` | 실행 중인 함수 | TypeError |
| `fn.caller`, `fn.arguments` | 엔진이 제공하는 비표준 확장 | TypeError |
| `arguments`라는 이름의 선언·대입 | 가능 | SyntaxError |

```js
function sloppy(a) {
  arguments[0] = 99
  return a
}
function strict(a) {
  'use strict'
  arguments[0] = 99
  return a
}

sloppy(1)   // 99 (a와 arguments[0]이 연동)
strict(1)   // 1  (호출 시점의 값만 복사)
```

- 비엄격 모드의 연동은 양방향입니다. `a = 99`로 매개변수를 바꾸면 `arguments[0]`도 99가 됩니다. strict에서는 둘 다 독립입니다.
- 비엄격에서도 연동은 조건부입니다. 매개변수 목록이 단순하고(기본값·나머지·구조 분해가 없고) 실제로 전달된 인수에만 연동됩니다. `sloppy()`처럼 인수를 안 넘긴 매개변수는 연동되지 않습니다.
- `arguments.callee`는 익명 함수의 재귀 호출에 쓰였습니다. strict에서는 이름 붙인 함수 표현식으로 대체합니다.

```js
// ❌ strict: TypeError
(function (n) {
  return n <= 1 ? 1 : n * arguments.callee(n - 1)
})(5)

// ✅ 이름 붙인 함수 표현식
const fact = function f(n) {
  return n <= 1 ? 1 : n * f(n - 1)
}
```

- 연동이 없는 대안으로 나머지 매개변수 `...args`가 있습니다. `arguments`와 달리 진짜 배열입니다(자세히는 27편).

## 클래스와 모듈의 자동 적용

### 클래스

클래스 선언과 클래스 표현식의 모든 부분은 지시어 없이 항상 strict입니다. 메서드 본문, 필드 초기자, `static` 블록, 계산된 키, `extends` 뒤의 식까지 포함하고, 해제할 수 없습니다(클래스 문법은 24편).

```js
class User {
  save() { undeclared = 1 }   // 호출하면 ReferenceError
  static pick() { return this }
}
const pick = User.pick
pick()   // undefined (전역 객체가 아님)
```

- 클래스 바깥 코드에는 영향이 없습니다. 같은 파일의 클래스 밖 함수는 비엄격 그대로입니다.
- 클래스 안에 `with`나 8진 리터럴을 쓰면 SyntaxError입니다. `extends (010, Object)`처럼 상속 식에 써도 마찬가지입니다.

### 모듈

ES 모듈은 파일 전체가 항상 strict입니다. 파일이 모듈로 로드되는 조건은 브라우저의 `<script type="module">`, Node.js의 `.mjs` 확장자나 package.json의 `"type": "module"`입니다(자세히는 45편, 46편).

- 모듈에서는 `'use strict'`가 필요 없습니다.
- 모듈 최상위 `this`는 `undefined`이고, 선언 없는 대입은 ReferenceError, 직접 eval의 `var`는 바깥에 나오지 않습니다.

### 자동으로 적용되지 않는 것

ES6 이후 문법을 쓴다고 strict가 되지 않습니다. 화살표 함수, async 함수, 제너레이터, 객체 리터럴의 메서드, `let`·`const`를 쓴 코드도 클래스 밖·모듈 밖이면 비엄격입니다. 이 기능들은 바깥 코드의 모드를 따릅니다.

| 코드 | strict 여부 |
|------|-------------|
| 스크립트(`<script>`, CommonJS 파일) | 첫머리에 지시어가 있을 때 |
| ES 모듈 | 항상 |
| 클래스(선언·표현식 전체) | 항상 |
| 함수 | 바깥 코드가 strict이거나 본문 첫머리에 지시어가 있을 때 |
| 직접 eval | 호출한 코드의 모드를 이어받음. 문자열 첫머리에 지시어를 써도 됨 |
| 간접 eval, `new Function` | 이어받지 않음. 문자열(본문) 첫머리에 지시어가 있을 때만 |

## 금지 문법 전체 표

strict mode에서 SyntaxError가 되는 문법입니다. 모두 파싱 단계에서 발견되므로 해당 스크립트가 한 줄도 실행되지 않습니다. `eval`과 `new Function`에 들어간 코드는 그 호출에서 SyntaxError가 납니다.

| 금지 문법 | 예 | 비엄격 모드 |
|-----------|----|-------------|
| `with` 문 | `with (obj) { a }` | 객체의 프로퍼티를 스코프처럼 사용(12편) |
| 앞이 0인 8진 리터럴 | `010`, `07` | 8진수로 해석 (`010`은 8) |
| 앞이 0이고 8·9가 든 정수 | `08`, `09.5` | 10진수로 해석 |
| 8진 이스케이프 | `'\101'` | 문자 `A` |
| `\8`, `\9` 이스케이프 | `'\8'` | 문자 `8` |
| 중복 매개변수 | `function f(a, a) {}` | 허용. 뒤의 값이 앞을 덮음 |
| 식별자에 `delete` | `delete x` | 허용. `var` 변수는 지워지지 않고 false |
| `eval`·`arguments`를 선언 이름으로 | `var eval`, `function arguments() {}` | 허용 |
| `eval`·`arguments`에 대입·증감 | `eval = 1`, `arguments++` | 허용 |
| 예약어를 식별자로 | `var public` | 허용 |
| 비단순 매개변수 함수의 지시어 | `function f(a = 1) { 'use strict' }` | 지시어를 쓰지 않으면 허용 |
| 문 자리의 함수 선언 | `if (x) function f() {}` | 허용(웹 호환 예외) |

- `eval`·`arguments`는 변수·함수 이름뿐 아니라 매개변수 이름, `catch` 매개변수, 함수 표현식 이름에도 쓸 수 없습니다.
- 8진 이스케이프에서 `\0`은 뒤에 숫자가 오지 않으면 허용됩니다(널 문자). `\00`, `\01`, `\08`은 에러입니다.
- 예약되는 단어는 `implements`, `interface`, `let`, `package`, `private`, `protected`, `public`, `static`, `yield`입니다. `enum`은 모드와 무관하게 항상 예약어이고, `await`는 모듈에서 예약됩니다.
- `label: function f() {}`도 `if` 뒤의 함수 선언과 같은 이유로 막힙니다.
- 지시어가 있는 함수는 본문뿐 아니라 이름과 매개변수 목록도 strict로 검사합니다. `function public() { 'use strict' }`는 SyntaxError입니다.
- strict 함수 안에 중첩된 함수도 같은 규칙을 따릅니다. 바깥에 지시어가 있으면 안쪽 함수에 `with`를 쓸 수 없습니다.
- 화살표 함수, 메서드, 비단순 매개변수 함수에서는 중복 매개변수가 비엄격에서도 SyntaxError입니다.

한때 금지였다가 풀린 규칙이 있습니다.

| 규칙 | ES5 strict | ES2015 이후 |
|------|------------|-------------|
| 객체 리터럴의 중복 프로퍼티 이름 | SyntaxError | 허용. 계산된 키 때문에 실행 중에야 중복이 드러날 수 있어서 삭제됨 |
| 블록 안의 함수 선언 | 금지 | 허용. 그 블록 스코프에 속함(자세히는 11편) |

흔한 실수는 숫자 앞에 0을 붙이는 것입니다. `new Date(2024, 08, 15)`는 strict에서 SyntaxError입니다. 비엄격에서는 `new Date(2024, 010, 1)`이 에러 없이 8진수 `010`(값 8)로 해석되어 11월이 아닌 9월(월 인덱스 8)이 됩니다. 앞자리 0을 붙이지 않고, 8진수는 `0o10`으로 씁니다(ES2015).

## eval의 스코프 변화

`eval(문자열)`은 문자열을 코드로 해석해 실행하고 마지막 문의 값을 돌려주는 전역 함수입니다(자세히는 20편).

```js
eval('1; 2; 3')   // 3
```

### 직접 eval과 간접 eval

호출식의 대상이 식별자 `eval` 그대로이면 직접 eval이고, 호출한 곳의 스코프에서 실행됩니다. 그 밖의 호출은 간접 eval이고, 전역 스코프에서 실행됩니다.

```js
function f() {
  const x = 2
  const a = eval('x')           // 2 (직접)
  const b = (0, eval)('x')      // ReferenceError (간접)
}
```

간접 eval이 되는 형태: `(0, eval)(s)`, `const e = eval; e(s)`, `globalThis.eval(s)`, `eval?.(s)`.

### var와 함수 선언의 처리

| 선언 | eval 코드가 비엄격 | eval 코드가 strict |
|------|-------------------|--------------------|
| 직접 eval의 `var`·함수 선언 | 호출한 함수(또는 전역)의 변수 환경(22편)에 추가 | eval 코드 안에만 존재 |
| 간접 eval의 `var`·함수 선언 | 전역 변수(전역 객체의 프로퍼티)가 됨 | eval 코드 안에만 존재 |
| `let`·`const`·`class` | eval 코드 안에만 존재 | eval 코드 안에만 존재 |

```js
function sloppy() {
  eval('var a = 1')
  return typeof a
}
function strict() {
  'use strict'
  eval('var a = 1')
  return typeof a
}

sloppy()   // 'number'    (a가 호출한 함수에 생김)
strict()   // 'undefined' (a는 eval 안에서만 존재)
```

- eval 코드가 strict가 되는 경로는 두 가지입니다. 직접 eval을 strict 코드 안에서 호출하거나, eval할 문자열이 지시어로 시작하는 경우입니다. 후자는 호출한 함수가 비엄격이어도 격리됩니다. 간접 eval은 전자의 경로가 없으므로 문자열 지시어가 있을 때만 격리됩니다.

```js
function directive() {
  eval('"use strict"; var a = 1')
  return typeof a   // 'undefined'
}
```

- 격리되는 것은 선언뿐입니다. strict mode의 직접 eval도 바깥의 기존 변수를 읽고 대입할 수 있습니다.

```js
function g() {
  'use strict'
  let n = 1
  eval('n = n + 1; var inner = 5')
  return [n, typeof inner]   // [2, 'undefined']
}
```

- 간접 eval은 호출한 코드가 strict여도 이어받지 않으므로 문자열에 지시어가 없으면 `var`가 전역에 생깁니다. `new Function`으로 만든 함수도 전역 스코프에서 만들어지고, 본문에 지시어가 없으면 비엄격입니다.
- 비엄격 직접 eval은 실행해 보기 전에는 어떤 이름이 새로 생길지 알 수 없어서, 엔진이 이름을 미리 해석하지 못하게 합니다. strict mode는 선언을 eval 안에 가둬 이 문제를 없앴습니다(스코프의 예외는 12편).
- strict mode에서는 `eval`이라는 이름을 식별자로 선언하거나 대입하는 것도 금지입니다(위 "금지 문법 전체 표").

흔한 실수는 두 가지입니다. 하나는 strict 파일에서 간접 eval을 쓰면 안전하다고 믿는 것입니다. 간접 eval은 전역 변수를 만듭니다. 다른 하나는 eval이 만든 변수를 뒤에서 쓰는 것입니다. strict 코드에서는 ReferenceError입니다.

```js
'use strict'
eval('var v = 1')
console.log(v)   // ReferenceError
```

eval은 문자열을 호출한 쪽의 권한으로 실행하므로 외부 입력을 넣으면 코드 주입 위험이 있습니다. 데이터를 읽는 용도는 `JSON.parse`로 대체합니다(자세히는 39편).

## 핵심 정리

- strict mode는 스크립트·함수 첫머리의 `'use strict'`로 켜고, 클래스 전체와 ES 모듈은 지시어 없이 항상 strict입니다. 켜진 모드는 안쪽에서 끌 수 없고, 호출 위치가 아니라 코드가 적힌 위치로 정해집니다.
- 지시어는 첫머리에 글자 그대로 있어야 하고, 잘못 두면 에러 없이 무시됩니다. 파일을 이어 붙이면 맨 앞 지시어만 의미가 있습니다.
- 비엄격에서 조용히 실패하던 대입·삭제는 TypeError, 선언 없는 대입은 ReferenceError가 되고, `with`·8진 리터럴·중복 매개변수·식별자 `delete`·`eval`/`arguments` 이름 사용 등은 SyntaxError입니다.
- strict의 `this`는 넘어온 값 그대로(`undefined`·`null`·원시 값)이고, `arguments`는 매개변수와 연동되지 않으며 `callee`는 TypeError입니다.
- strict의 직접 eval은 `var`와 함수 선언을 호출한 스코프에 만들지 않습니다. 간접 eval과 `new Function`은 strict를 이어받지 않습니다.
