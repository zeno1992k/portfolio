## 개념

정규 표현식(regular expression)은 문자열에서 규칙에 맞는 부분을 찾는 패턴 표기입니다. JavaScript에서는 `RegExp` 객체로 표현하며 검색, 검증, 추출, 치환에 씁니다.

```js
const re = /\d{3}-\d{4}/
re.test('call 555-1234') // true
re.test('call 5551234')  // false
```

정규식은 패턴과 플래그로 이루어집니다. 패턴은 일반 문자와 특별한 의미를 가진 메타 문자의 나열이고, 플래그는 탐색 방식을 바꾸는 옵션입니다. 메타 문자는 다음과 같습니다.

```text
\ ^ $ . | ? * + ( ) [ ] { }
```

메타 문자를 글자 그대로 찾으려면 앞에 `\`를 붙입니다. `/\./`는 마침표, `/\$/`는 달러 기호, `/\(/`는 여는 괄호와 일치합니다.

엔진의 탐색 규칙은 세 가지입니다.

- 문자열을 왼쪽부터 훑어, 패턴이 성립하는 가장 왼쪽 위치에서 매치를 만듭니다.
- 같은 위치에서는 패턴에 적힌 순서대로 시도하고, 뒤쪽이 실패하면 앞쪽의 선택을 바꿔 다시 시도합니다. 이것이 백트래킹입니다(마지막 절).
- `|`는 가장 긴 대안이 아니라 먼저 성공하는 대안을 고릅니다. 수량자는 기본적으로 가능한 한 많이 매치합니다.

```js
/b+/.exec('abbbc')[0] // 'bbb'
/a|ab/.exec('abc')[0] // 'a'  (먼저 성공한 대안)
```

정규식을 받는 메서드는 다음과 같습니다.

| 메서드 | 반환값 |
|--------|--------|
| `re.test(str)` | 불리언 |
| `re.exec(str)` | 매치 배열 또는 `null` |
| `str.match(re)` | 매치 배열 또는 `null` |
| `str.matchAll(re)` | 매치 반복자 |
| `str.replace(re, 대체)`, `str.replaceAll(re, 대체)` | 새 문자열 |
| `str.split(re)` | 배열 |
| `str.search(re)` | 인덱스 또는 `-1` |

고정 문자열만 찾는다면 정규식 대신 `includes`·`startsWith`·`replaceAll`(문자열 인수)이 단순합니다(자세히는 33편). String 메서드는 내부에서 정규식의 `Symbol.match`·`Symbol.replace` 같은 메서드를 호출합니다(자세히는 34편).

## 리터럴과 RegExp 생성자

정규식을 만드는 방법은 두 가지입니다. 리터럴은 슬래시로 패턴을 감싸고, 생성자는 문자열로 패턴을 받습니다.

```js
const a = /ab+c/gi                 // 리터럴
const b = new RegExp('ab+c', 'gi') // 생성자
a.source  // 'ab+c'
a.flags   // 'gi'
String(a) // '/ab+c/gi'
```

| 항목 | 리터럴 | 생성자 |
|------|--------|--------|
| 패턴 | 코드에 고정 | 문자열이라 변수로 조립 가능 |
| 문법 오류 | 스크립트를 파싱할 때 SyntaxError, 파일 전체가 실행되지 않음 | 그 줄을 실행할 때 SyntaxError |
| 백슬래시 | `\d` | 문자열이라 `\\d` |
| 슬래시 | `\/`로 이스케이프 | 이스케이프 불필요 |

- 리터럴은 평가할 때마다 새 객체를 만듭니다. 함수 안의 리터럴은 호출마다 새 `RegExp`이고 `lastIndex`는 0입니다. 모듈 최상단에 `const`로 둔 정규식은 한 객체를 계속 공유합니다.
- 문자 클래스 안에서는 `/`를 이스케이프하지 않아도 됩니다(`/[/]/`).
- `//`는 주석이므로 빈 리터럴을 쓸 수 없습니다. 빈 패턴의 `source`는 `'(?:)'`입니다.
- 첫 인수가 정규식이면 패턴을 복사합니다. 둘째 인수가 없으면 플래그도 복사하고, 있으면 그 값으로 바꿉니다.

```js
new RegExp(/a/g).flags      // 'g'
new RegExp(/a/g, 'i').flags // 'i'
```

- 변수 값을 패턴에 넣을 때는 생성자를 씁니다. 사용자 입력은 먼저 이스케이프해야 합니다(`RegExp.escape`는 ES2025 절).
- `source`, `flags`, `global` 등은 읽기 전용입니다. 쓸 수 있는 프로퍼티는 `lastIndex`뿐입니다.

생성자에 넘기는 문자열에서는 문자열 이스케이프가 먼저 처리되므로 백슬래시를 두 번 쓰는 것을 잊기 쉽습니다.

```js
new RegExp('\d+').source           // 'd+'   ❌
new RegExp('\\d+').source          // '\\d+' ✅
new RegExp(String.raw`\d+`).source // '\\d+' ✅
```

## 플래그

플래그는 정규식의 탐색 방식을 바꾸는 옵션으로, 리터럴은 닫는 슬래시 뒤에, 생성자는 둘째 인수에 적습니다.

| 플래그 | 프로퍼티 | 의미 | 도입 |
|--------|----------|------|------|
| `d` | `hasIndices` | 매치와 그룹의 위치 정보를 만든다 | ES2022 |
| `g` | `global` | 모든 매치를 대상으로 한다 | ES3 |
| `i` | `ignoreCase` | 대소문자를 구분하지 않는다 | ES3 |
| `m` | `multiline` | `^`와 `$`가 줄 단위로 동작한다 | ES3 |
| `s` | `dotAll` | `.`이 줄바꿈도 일치한다 | ES2018 |
| `u` | `unicode` | 코드 포인트 단위로 처리하고 유니코드 문법을 켠다 | ES2015 |
| `v` | `unicodeSets` | `u`를 확장한 집합 표기 | ES2024 |
| `y` | `sticky` | `lastIndex` 위치에서만 일치한다 | ES2015 |

```js
/abc/i.test('ABC')     // true
/^b/.test('a\nb')      // false
/^b/m.test('a\nb')     // true
/a.b/.test('a\nb')     // false
/a.b/s.test('a\nb')    // true
```

- `flags` 프로퍼티는 지정한 순서와 상관없이 `dgimsuvy` 순서로 돌려줍니다(`new RegExp('a', 'ysmuigd').flags`는 `'dgimsuy'`).
- 플래그는 만든 뒤 바꿀 수 없습니다. 바꾸려면 `new RegExp(re, '새 플래그')`로 새로 만듭니다.
- 같은 플래그를 두 번 쓰거나, 모르는 플래그를 쓰거나, `u`와 `v`를 함께 쓰면 SyntaxError입니다.
- `i`는 대소문자 구분이 없는 한글 등에는 영향이 없습니다. `u`·`v`와 함께 쓰면 유니코드 대소문자 규칙(case folding)을 따릅니다. 켈빈 기호 `K`는 `/K/i.test('k')`가 `false`, `/K/iu.test('k')`가 `true`입니다.
- `g`와 `y`는 정규식 객체에 탐색 상태(`lastIndex`)를 만듭니다(lastIndex 절).

## test·exec

`test`는 일치 여부를 불리언으로, `exec`는 첫 매치의 상세 정보를 배열로 돌려줍니다. 둘 다 정규식 객체의 메서드입니다.

```js
const re = /(\d{4})-(\d{2})/
re.test('date: 2026-10') // true
const m = re.exec('date: 2026-10')
m[0]     // '2026-10'  전체 매치
m[1]     // '2026'     1번 캡처
m[2]     // '10'       2번 캡처
m.index  // 6          매치 시작 위치
m.input  // 'date: 2026-10'
m.groups // undefined  (이름 있는 그룹 없음)
re.exec('none') // null
```

- `exec` 결과는 배열이면서 `index`, `input`, `groups` 프로퍼티를 가집니다. `d` 플래그가 있으면 `indices`도 가집니다.
- 매치가 없으면 `null`이므로 `m[1]`은 TypeError입니다. 매치 여부가 불확실하면 `m?.[1]`로 읽습니다.
- `g`·`y`가 없으면 항상 처음부터 찾아 같은 결과를 줍니다. 있으면 `lastIndex`부터 찾고 호출 후 `lastIndex`를 갱신하므로, 반복 호출로 모든 매치를 순회할 수 있습니다.

```js
const re = /\d+/g
let m
while ((m = re.exec('a1b22c333')) !== null) {
  console.log(m[0], m.index)
}
// 1 1, 22 3, 333 6
```

- 인수가 문자열이 아니면 문자열로 변환합니다. `/undefined/.test()`와 `/null/.test(null)`은 모두 `true`입니다.
- 일치 여부만 필요하면 `test`, 위치나 캡처가 필요하면 `exec`를 씁니다.

## match·matchAll

`match`는 문자열 쪽에서 호출하는 메서드로, `g` 플래그 유무에 따라 반환 형태가 다릅니다.

```js
const s = 'a1b22c333'
s.match(/\d+/)   // ['1', index: 1, ...]  exec와 같은 결과
s.match(/\d+/g)  // ['1', '22', '333']    문자열 배열
s.match(/x/g)    // null
```

| 호출 | 반환값 |
|------|--------|
| `s.match(re)`, `g` 없음 | `exec`와 같은 첫 매치 배열 |
| `s.match(re)`, `g` 있음 | 매치된 문자열만 담은 배열, 없으면 `null` |
| `s.matchAll(re)` | 매치마다 `exec` 결과를 내는 반복자, `g` 필수 |

- `g`가 있는 `match`는 캡처 그룹과 `index` 정보를 버립니다. 그 정보가 필요하면 `matchAll`을 씁니다.
- `match`에 문자열을 넘기면 `new RegExp(문자열)`로 바뀌므로 메타 문자가 해석됩니다. `'a.b'.match('.')`의 결과는 `'a'`입니다.
- 매치가 없을 때 `null`이므로 `s.match(/x/g).length`는 TypeError입니다. `s.match(/x/g) ?? []`로 받습니다.

`matchAll`(ES2020)은 `g`가 없으면 TypeError를 던집니다. 문자열을 넘기면 `new RegExp(문자열, 'g')`로 바뀝니다.

```js
const re = /(?<k>\w+)=(?<v>\d+)/g
for (const m of 'a=1,b=22'.matchAll(re)) {
  console.log(m.groups.k, m.groups.v) // a 1, b 22
}
[...'a=1,b=22'.matchAll(/\d+/g)].map(m => m[0]) // ['1', '22']
```

- 반환값은 반복자이므로 `for...of`, 스프레드, `Array.from`으로 소비합니다(자세히는 35·36편).
- 내부에서 정규식을 복제해 쓰므로 원본의 `lastIndex`는 바뀌지 않습니다. 다만 복제본은 원본의 현재 `lastIndex`에서 시작합니다.

## replace와 정규식

`replace`는 일치한 부분을 바꾼 새 문자열을 돌려주고 원본은 바꾸지 않습니다. 첫 인수가 정규식이면 `g`가 없을 때 첫 매치만, 있을 때 모든 매치를 바꿉니다. 첫 인수가 문자열이면 글자 그대로 찾아 첫 일치만 바꿉니다. `replaceAll`(ES2021)은 문자열이면 모두 바꾸고, 정규식이면 `g`를 요구합니다.

```js
'a-b-c'.replace('-', '+')     // 'a+b-c'
'a-b-c'.replace(/-/, '+')     // 'a+b-c'
'a-b-c'.replace(/-/g, '+')    // 'a+b+c'
'a-b-c'.replaceAll('-', '+')  // 'a+b+c'
'a-b-c'.replaceAll(/-/, '+')  // TypeError
```

대체 문자열 안의 특수 패턴은 다음과 같습니다.

| 패턴 | 삽입되는 값 |
|------|-------------|
| `$$` | 달러 기호 `$` |
| `$&` | 매치된 전체 문자열 |
| `$1`–`$99` | 해당 번호의 캡처 그룹 |
| `$<name>` | 이름 있는 캡처 그룹 |

매치의 앞뒤 문자열을 넣는 패턴은 `$` 뒤에 백틱과 작은따옴표를 붙인 두 가지입니다.

```text
$`   매치 앞의 문자열
$'   매치 뒤의 문자열
```

```js
'abc'.replace(/b/, "[$`|$']") // 'a[a|c]c'
```

```js
'2026-10-05'.replace(/(\d+)-(\d+)-(\d+)/, '$3/$2/$1')
// '05/10/2026'
'cat'.replace(/a/, '[$&]')   // 'c[a]t'
'price'.replace(/price/, '$$100') // '$100'
'John Smith'.replace(/(?<f>\w+) (?<l>\w+)/, '$<l>, $<f>')
// 'Smith, John'
```

- 그룹 수보다 큰 번호(`$2`가 1개 그룹뿐인 패턴에서)와 `$0`은 치환되지 않고 글자 그대로 남습니다. 그룹이 10개 미만일 때 `$10`은 `$1` 뒤에 `0`이 붙은 것으로 읽힙니다.
- 이름 있는 그룹이 있는 패턴에서 존재하지 않는 `$<y>`는 빈 문자열이 됩니다.
- 빈 문자열과도 일치하는 패턴은 모든 위치에서 매치합니다: `'abc'.replace(/x*/g, '-')`는 `'-a-b-c-'`입니다.

대체 값으로 함수를 넘기면 매치마다 호출되고 반환값이 삽입됩니다. 함수의 인수는 순서대로 다음과 같습니다.

- `match`: 매치된 문자열 전체
- `p1`…`pn`: 캡처 그룹 값(그룹이 없으면 생략)
- `offset`: 매치 시작 위치
- `string`: 원본 문자열
- `groups`: 이름 있는 그룹이 있을 때만 마지막에 추가되는 객체

```js
'a1b2'.replace(/\d/g, d => d * 2)
// 'a2b4'
'a1b2'.replace(/\d/g, (m, offset) => `[${offset}]`)
// 'a[1]b[3]'
```

사용자 입력을 대체 문자열로 직접 넘기면 `$&` 같은 패턴이 해석됩니다. 글자 그대로 넣으려면 함수로 감쌉니다. 함수의 반환값에서는 특수 패턴이 해석되지 않습니다.

```js
'x'.replace(/x/, '$&$&')       // 'xx'
'x'.replace(/x/, () => '$&$&') // '$&$&'
```

## 임의 문자와 반복

`.`은 줄 종결자를 제외한 문자 하나와 일치합니다. 줄 종결자는 `\n`, `\r`, ` `, ` ` 네 가지이며, `s` 플래그를 켜면 이것도 일치합니다. `u`·`v` 없이는 BMP 밖 문자를 한 글자로 보지 못합니다(Unicode 플래그 절).

```js
/a.c/.test('abc')   // true
/a.c/.test('a\nc')  // false
/a.c/s.test('a\nc') // true
/a\.c/.test('abc')  // false  (\. 는 마침표 자체)
```

수량자는 바로 앞 요소가 몇 번 반복되는지를 정합니다.

| 수량자 | 반복 횟수 |
|--------|-----------|
| `*` | 0회 이상 |
| `+` | 1회 이상 |
| `?` | 0회 또는 1회 |
| `{n}` | 정확히 n회 |
| `{n,}` | n회 이상 |
| `{n,m}` | n회 이상 m회 이하 |

```js
/^\d{2,4}$/.test('123')  // true
/^a{2}$/.test('aa')      // true
/ab+/.exec('abbb')[0]    // 'abbb'  (+ 는 b 에만 적용)
/(ab)+/.exec('ababx')[0] // 'abab'  (그룹 전체에 적용)
```

- 수량자는 바로 앞의 요소 하나(문자, 클래스, 그룹)에만 적용됩니다.
- `{n,m}` 안에 공백을 넣거나 `{,3}`처럼 쓰면 수량자가 아니라 글자 그대로 해석됩니다. `/a{1, 3}/.test('a{1, 3}')`은 `true`입니다. `u`·`v`에서는 SyntaxError입니다.
- 앞에 반복할 대상이 없는 수량자(`/*/`)와 수량자 위의 수량자(`/a**/`)는 SyntaxError입니다. `a+?`의 `?`는 예외로 게으른 수량자 표시입니다(다음 절).
- 줄바꿈을 포함한 모든 문자는 `[\s\S]`로 씁니다. `s` 플래그가 생기기 전의 관용구입니다.
- 흔한 실수: 마침표를 이스케이프하지 않는 것입니다. `/1.5/`는 `'125'`와도 일치합니다.

## 탐욕·게으른 수량자

수량자는 기본이 탐욕(greedy)입니다. 가능한 한 많이 매치하고, 뒤쪽이 실패하면 한 글자씩 내놓으며 다시 시도합니다. 수량자 뒤에 `?`를 붙이면 게으른(lazy) 수량자가 되어 가능한 한 적게 매치하고, 뒤쪽이 실패하면 한 글자씩 늘립니다.

| 탐욕 | 게으른 |
|------|--------|
| `*` | `*?` |
| `+` | `+?` |
| `?` | `??` |
| `{n,m}` | `{n,m}?` |

```js
const html = '<b>a</b><b>c</b>'
html.match(/<b>.*<\/b>/)[0]    // '<b>a</b><b>c</b>'  탐욕
html.match(/<b>.*?<\/b>/)[0]   // '<b>a</b>'          게으른
html.match(/<b>[^<]*<\/b>/)[0] // '<b>a</b>'          부정 클래스
```

- 게으른 수량자도 매치의 시작 위치는 가장 왼쪽입니다. 뒤쪽 패턴이 요구하면 늘어납니다. `/a+?/.exec('aaa')[0]`은 `'a'`이고 `/a+?$/.exec('aaa')[0]`은 `'aaa'`입니다.
- 구분자 사이의 내용은 게으른 수량자(`".*?"`)보다 부정 클래스(`"[^"]*"`)가 의도가 분명하고 되돌아가는 횟수도 적습니다.
- 흔한 실수: `"(.*)"`로 따옴표 안을 뽑으면 첫 따옴표부터 마지막 따옴표까지 삼킵니다. `'"a" "b"'.match(/"(.*)"/)[1]`은 `'a" "b'`입니다.

## OR와 문자 클래스

`|`는 여러 대안 중 하나와 일치합니다. 우선순위가 패턴에서 가장 낮아서, 묶지 않으면 패턴 전체가 대안으로 갈라집니다. 왼쪽 대안부터 시도해 먼저 성공한 것을 고릅니다.

```js
/cat|dog/.test('hotdog')      // true
'abc'.match(/a|ab/)[0]        // 'a'  (먼저 성공한 대안)
/^cat|dog$/.test('catfish')   // true  (^cat 또는 dog$)
/^(cat|dog)$/.test('catfish') // false
```

문자 클래스 `[...]`는 나열한 문자 중 하나와 일치합니다. `-`로 코드 포인트 범위를 지정합니다.

```js
/[aeiou]/.test('sky')   // false
/[a-z0-9_]/.test('_')   // true
/[가-힣]/.test('한')     // true
/[.*+?]/.test('.')      // true  (클래스 안의 . 은 문자 그대로)
/[a\-z]/.test('-')      // true  (\- 는 하이픈 자체)
/[a-]/.test('-')        // true  (끝의 하이픈은 문자 그대로)
```

- 클래스 안에서 특별한 문자는 `\`, `]`, `^`(맨 앞일 때), `-`(두 문자 사이일 때)뿐입니다. 나머지 메타 문자는 이스케이프할 필요가 없습니다.
- 클래스 안의 `\b`는 단어 경계가 아니라 백스페이스입니다.
- `i` 플래그는 클래스에도 적용됩니다. `/[a-z]/i.test('Q')`는 `true`입니다.

자주 쓰는 클래스에는 약어가 있습니다.

| 약어 | 일치 대상 |
|------|-----------|
| `\d` | `[0-9]` |
| `\w` | `[A-Za-z0-9_]` |
| `\s` | 공백, 탭, 줄 종결자, NBSP(` `), BOM(`﻿`), 전각 공백(`　`) 등 |
| `\D` `\W` `\S` | 각 약어의 여집합 |

- `\d`와 `\w`는 ASCII만 일치합니다. 한글, 악센트 문자, 아랍 숫자는 `\w`·`\d`와 일치하지 않습니다(`/\w/.test('한')`은 `false`).
- 제로폭 공백 `​`은 `\s`와 일치하지 않습니다.
- 글자 코드 이스케이프: `\t` `\n` `\r` `\v` `\f`(제어 문자), `\xHH`(2자리), `\uHHHH`(4자리), `\u{H…}`(코드 포인트, `u`·`v` 필요).
- `[가-힣]`은 완성형 음절(U+AC00–U+D7A3)만 포함합니다. 단독 자모는 `[ㄱ-ㅎㅏ-ㅣ]`를 추가해야 합니다.
- 분해형(NFD) 한글은 음절이 자모로 쪼개져 있어 `[가-힣]`과 일치하지 않습니다. `normalize('NFC')`로 합친 뒤 검사합니다(자세히는 33편).

## NOT

부정은 "이 중 하나가 아닌 문자 하나"를 뜻하는 `[^...]`가 기본이고, 약어와 단언에도 부정형이 있습니다.

| 부정 대상 | 문법 |
|-----------|------|
| 문자 집합 | `[^abc]` |
| 숫자·단어·공백 문자 | `\D` `\W` `\S` |
| 단어 경계 | `\B` |
| 유니코드 속성 | `\P{...}` |
| 뒤따르는 문자열 | `(?!...)` |
| 앞선 문자열 | `(?<!...)` |

```js
'a1b2'.replace(/[^0-9]/g, '') // '12'
'a b\tc'.replace(/\S/g, '*')  // '* *\t*'
/[^a]/.test('\n')             // true  (줄바꿈도 일치)
/a[^b]/.test('a')             // false (문자 하나가 필요)
/[^]/.test('\n')              // true  (모든 문자)
```

- `[^...]`는 줄바꿈을 포함해 나열하지 않은 모든 문자와 일치합니다.
- 반드시 문자 하나를 소비합니다. 문자열 끝에서는 일치하지 않습니다.
- `[^abc]`는 "abc가 아닌 글자 하나"이지 "abc라는 문자열이 아님"이 아닙니다. 문자열을 포함하지 않는다는 조건은 전방탐색으로 표현합니다.

```js
const noAdmin = /^(?!.*admin)/
noAdmin.test('user')       // true
noAdmin.test('superadmin') // false
```

- 빈 클래스 `[]`는 아무것과도 일치하지 않고, `[^]`는 모든 문자와 일치합니다.

## 시작·끝 위치

단언(assertion)은 문자를 소비하지 않고 위치만 검사하는 요소입니다.

| 단언 | 위치 |
|------|------|
| `^` | 입력의 시작. `m` 플래그에서는 각 줄의 시작 |
| `$` | 입력의 끝. `m` 플래그에서는 각 줄의 끝 |
| `\b` | 단어 문자(`\w`)와 비단어 문자 사이, 또는 입력 가장자리의 단어 문자 옆 |
| `\B` | `\b`가 아닌 위치 |

```js
/^abc/.test('xabc')  // false
/abc$/.test('abc\n') // false  ($ 는 끝의 줄바꿈 앞에서 일치하지 않음)
/^$/.test('')        // true   (빈 문자열 검사)
const text = 'a1\nb2'
text.match(/^\w/g)   // ['a']
text.match(/^\w/gm)  // ['a', 'b']
text.match(/\d$/gm)  // ['1', '2']
```

- `m` 플래그의 줄 구분은 `\n`, `\r`, ` `, ` `입니다.
- ECMAScript에는 `\A`, `\Z`가 없습니다. `m` 플래그를 켠 상태에서 입력의 맨 처음만 가리키려면 `(?<![\s\S])`를 씁니다.
- 검증 용도에서는 앵커를 양쪽에 붙여야 전체 일치를 검사합니다. 앵커가 없으면 부분 일치로 통과합니다.

```js
/\d{3}/.test('12345')   // true   (부분 일치)
/^\d{3}$/.test('12345') // false
```

`\b`는 `\w`를 기준으로 하므로 ASCII 글자·숫자·`_`만 단어로 칩니다.

```js
'cat concat'.match(/\bcat\b/g) // ['cat']
'cat concat'.match(/cat/g)     // ['cat', 'cat']
/\bfoo\b/.test('foo_bar')      // false  (_ 도 단어 문자)
'abc'.replace(/\B/g, '-')      // 'a-b-c'
```

- 한글은 `\w`가 아니므로 한글 양옆에서 `\b`는 성립하지 않습니다. `/\b한글\b/.test('한글')`은 `false`입니다. 전후방탐색으로 대신합니다: `/(?<![가-힣])한글(?![가-힣])/`.
- 흔한 실수: `/^a|b$/`는 `^a` 또는 `b$`입니다. 양쪽을 감싸려면 `/^(a|b)$/`로 씁니다.

## 그룹과 캡처

`(...)`는 두 가지 일을 합니다. 요소를 하나로 묶어 수량자나 `|`를 적용하게 하고, 일치한 문자열을 번호를 붙여 기억합니다(캡처). 기억이 필요 없고 묶기만 하려면 `(?:...)`를 씁니다.

```js
/(ab)+/.exec('ababab')   // ['ababab', 'ab']
/(?:ab)+/.exec('ababab') // ['ababab']
```

번호는 여는 괄호의 위치 기준으로, 왼쪽부터 바깥 그룹 먼저 1부터 매깁니다.

```js
const m = /((\d+)-(\d+))-(\w+)/.exec('10-20-xy')
m[1] // '10-20'  바깥 그룹
m[2] // '10'
m[3] // '20'
m[4] // 'xy'
```

- 일치하지 않은 그룹의 값은 `undefined`입니다: `/(a)|(b)/.exec('b')`는 `['b', undefined, 'b']`입니다. `(a)?`도 같습니다.
- 반복되는 그룹은 마지막 반복의 값만 남습니다: `/(\d)+/.exec('123')`은 `['123', '3']`입니다.
- 반복할 때마다 그룹 안의 캡처는 초기화됩니다. `/(?:(a)|(b))+/.exec('ab')`는 `['ab', undefined, 'b']`로, 앞 반복에서 잡은 `'a'`가 사라집니다.
- 결과 배열의 길이는 `1 + 캡처 그룹 수`입니다.
- 캡처한 값은 역참조(`\1`), 대체 문자열(`$1`), `split` 결과, 콜백 인수에서 다시 쓰입니다.
- 흔한 실수: 묶기만 필요한 곳에 `(...)`를 쓰면 번호가 밀려 뒤쪽 그룹 번호가 바뀝니다. 그룹이 늘수록 `(?:...)`로 구분하거나 이름을 붙입니다.

## Named Capture Group

이름 있는 캡처 그룹은 `(?<이름>...)`으로 쓰고(ES2018), 번호 대신 이름으로 값을 읽습니다. 이름 있는 그룹도 번호를 함께 가집니다.

```js
const re = /(?<year>\d{4})-(?<month>\d{2})/
const { groups } = re.exec('2026-10')
groups.year  // '2026'
groups.month // '10'
```

- 값은 결과의 `groups` 프로퍼티에 담깁니다. `groups`는 프로토타입이 `null`인 객체입니다.
- 패턴에 이름 있는 그룹이 하나도 없으면 `groups`는 `undefined`, 하나라도 있으면 객체입니다. 일치하지 않은 이름 있는 그룹은 키가 있고 값이 `undefined`입니다.
- 이름은 식별자 규칙을 따릅니다. 한글 이름(`(?<연도>\d{4})`)도 가능하고, 하이픈은 SyntaxError입니다.
- 같은 이름의 그룹을 한 패턴에 두 번 쓰면 SyntaxError입니다. 서로 다른 대안 안에서는 ES2025부터 허용됩니다(ES2025 절).
- 이름 참조는 세 곳에서 씁니다. 패턴 안은 `\k<이름>`, 대체 문자열은 `$<이름>`, 대체 함수는 마지막 인수 `groups`입니다.

```js
const re = /(?<y>\d{4})-(?<m>\d{2})/
'2026-10'.replace(re, '$<m>/$<y>') // '10/2026'
'2026-10'.replace(re, (...args) => {
  const g = args.at(-1)
  return `${g.m}/${g.y}`
}) // '10/2026'
```

- 흔한 실수: 매치가 없을 때 `exec`가 `null`이므로 `const { groups } = re.exec(s)`는 TypeError입니다. `re.exec(s)?.groups`로 읽습니다(구조 분해는 37편).

## 역참조

역참조(backreference)는 앞 그룹이 일치한 문자열과 같은 문자열에 일치하는 요소입니다. 패턴이 아니라 실제로 잡힌 글자를 다시 요구합니다. 번호는 `\1`, `\2`, 이름은 `\k<이름>`입니다.

```js
/(\w)\1/.test('hello')                 // true  ('ll')
/\b(\w+)\s+\1\b/.test('the the cat')   // true  (중복 단어)
/(?<q>['"]).*?\k<q>/.exec(`say "hi" 'x'`)[0] // '"hi"'
```

- 패턴 안에서는 `\1`, 대체 문자열에서는 `$1`입니다. 위치에 따라 문법이 다릅니다.
- `i` 플래그가 있으면 역참조도 대소문자를 구분하지 않고 비교합니다. `/(a)\1/i.test('aA')`는 `true`입니다.
- 일치하지 않았거나 아직 일치 전인 그룹의 역참조는 실패하지 않고 빈 문자열과 일치합니다. `/(a)?\1b/.test('b')`는 `true`입니다. 다른 언어와 다른 동작입니다.
- 그룹 수보다 큰 번호(`/\1/`, 그룹 없음)는 `u`·`v` 없이는 8진 이스케이프로 해석됩니다(`/\1/.test('\x01')`은 `true`). `u`·`v`에서는 SyntaxError입니다.

## split·search와 정규식

`split`은 정규식과 일치하는 부분을 구분자로 문자열을 나누고, `search`는 첫 매치의 위치를 돌려줍니다.

```js
'a, b;c'.split(/[,;]\s*/)  // ['a', 'b', 'c']
'a1b22c'.split(/\d+/)      // ['a', 'b', 'c']
'a1b22c'.split(/(\d+)/)    // ['a', '1', 'b', '22', 'c']
'a,b,c'.split(/,/, 2)      // ['a', 'b']
' a b'.split(/\s+/)        // ['', 'a', 'b']
'a1b'.split(/(x)?1/)       // ['a', undefined, 'b']
```

- 캡처 그룹이 있으면 그 값이 결과 배열 사이에 끼어듭니다. 일치하지 않은 그룹은 `undefined`로 들어갑니다.
- 둘째 인수는 결과 배열의 최대 길이입니다.
- `g` 플래그는 영향이 없고 항상 모두 나눕니다. 빈 문자열과 일치하는 패턴은 글자 단위로 나눕니다(`'abc'.split(/(?:)/)`은 `['a', 'b', 'c']`).
- 문자열 맨 앞이나 맨 뒤에서 일치하면 빈 문자열이 생깁니다. 앞뒤 공백이 있으면 `trim()`을 먼저 호출합니다(자세히는 33편).

```js
'abc123'.search(/\d/) // 3
'abc'.search(/\d/)    // -1
'ABC'.search(/b/i)    // 1
```

- `search`는 `g`와 `lastIndex`를 무시하고 항상 처음부터 찾습니다. 캡처 정보는 주지 않습니다.
- 문자열을 넘기면 `new RegExp(문자열)`로 바뀝니다.
- 흔한 실수: 일치 위치가 0이면 거짓으로 평가됩니다. `if (s.search(/a/))`는 맨 앞에서 일치할 때 거짓이고, 일치가 없을 때(`-1`)는 참입니다. 조건에는 `test`를 씁니다.

## lastIndex와 g·y 플래그 함정

`lastIndex`는 정규식 객체가 가진 쓰기 가능한 프로퍼티(초기값 0)로, `g`·`y` 정규식이 다음 탐색을 시작할 위치입니다. 두 플래그가 모두 없으면 `exec`·`test`는 이 값을 읽지도 바꾸지도 않습니다.

| 호출 | `lastIndex` 동작 |
|------|------------------|
| 성공한 `exec`·`test` | 매치의 끝으로 이동 |
| 실패한 `exec`·`test` | 0으로 초기화 |
| `match`(g), `replace`, `replaceAll` | 0에서 시작하고 끝나면 0 |
| `search`, `split` | 항상 처음부터 찾고 값을 바꾸지 않음 |
| `matchAll` | 복제본이 원본의 현재 값에서 시작, 원본은 변하지 않음 |

가장 흔한 함정은 `g` 정규식에 `test`를 반복 호출하는 것입니다. 같은 입력인데 결과가 번갈아 달라집니다.

```js
const re = /a/g
re.test('aa') // true   (lastIndex 1)
re.test('aa') // true   (lastIndex 2)
re.test('aa') // false  (lastIndex 0으로 초기화)
re.test('aa') // true
```

```js
const re = /a/g
['a', 'a', 'a'].filter(s => re.test(s)) // ['a', 'a']
```

- 해결책은 `test`용 정규식에서 `g`를 빼는 것입니다. 상태가 필요 없으면 `g`가 필요 없습니다.
- 공유하는 `g` 정규식을 쓴다면 호출 전에 `re.lastIndex = 0`으로 초기화하거나, 함수 안에서 리터럴을 새로 만듭니다.
- 모든 매치를 순회하는 목적이면 `exec` 루프보다 `matchAll`이 안전합니다. `exec` 루프에는 무한 루프 두 가지가 있습니다.

```js
// ❌ g가 없으면 매번 첫 매치를 돌려줘서 끝나지 않는다
while ((m = /a/.exec('a'))) {}
// ❌ 빈 문자열 매치는 lastIndex를 옮기지 않는다
/a*/g.exec('b') // [''], lastIndex는 그대로 0
```

`y`(sticky) 플래그는 매치가 `lastIndex` 위치에서 정확히 시작할 것을 요구합니다. 그 위치에서 일치하지 않으면 뒤로 가서 찾지 않고 실패합니다.

```js
const re = /\d+/y
re.lastIndex = 2
re.exec('ab12')  // ['12']
re.lastIndex     // 4
re.exec('ab12 ') // null  (4번 위치가 숫자가 아님)
re.lastIndex     // 0
```

- `y`의 용도는 토크나이저입니다. 앞 토큰이 끝난 자리에서 다음 토큰만 인식하게 합니다.

```js
const tok = /\s*(\d+|[+*])/y
const out = []
let m
while ((m = tok.exec('12 + 3'))) out.push(m[1])
out // ['12', '+', '3']
```

- `y`에서도 `^`는 `lastIndex`가 아니라 입력의 시작(`m` 플래그가 있으면 줄의 시작)을 뜻합니다. `/^b/y`에 `lastIndex = 1`로 `'ab'`를 검사하면 `false`입니다.

## Lookahead·Lookbehind

전후방탐색은 문자를 소비하지 않고 현재 위치의 앞이나 뒤가 조건에 맞는지만 검사하는 단언입니다. 조건에 쓰인 문자열은 매치 결과에 포함되지 않습니다.

| 문법 | 이름 | 뜻 |
|------|------|----|
| `X(?=Y)` | 긍정 전방탐색(lookahead) | X 뒤에 Y가 올 때 X |
| `X(?!Y)` | 부정 전방탐색 | X 뒤에 Y가 오지 않을 때 X |
| `(?<=Y)X` | 긍정 후방탐색(lookbehind) | X 앞에 Y가 있을 때 X |
| `(?<!Y)X` | 부정 후방탐색 | X 앞에 Y가 없을 때 X |

```js
'$10 20€'.match(/(?<=\$)\d+/)[0] // '10'
'$10 20€'.match(/\d+(?=€)/)[0]   // '20'
'a1 b2 a3'.match(/(?<!b)\d/g)    // ['1', '3']
'1a 2b 3a'.match(/\d(?!a)/g)     // ['2']
'abc'.replace(/(?=b)/, '-')      // 'a-bc'
```

- 전방탐색은 ES3부터, 후방탐색은 ES2018부터 있습니다. 후방탐색은 Safari 16.4부터 지원합니다.
- 한 위치에서 여러 조건을 동시에 만족해야 할 때 전방탐색을 겹쳐 씁니다.

```js
const strong = /^(?=.*[a-z])(?=.*\d).{8,}$/
strong.test('abcdefg1') // true
strong.test('abcdefgh') // false (숫자 없음)
```

- 후방탐색은 길이가 가변이어도 됩니다: `'$10.50'.match(/(?<=\$\d+\.)\d+/)[0]`은 `'50'`입니다.
- 긍정 탐색 안의 캡처는 결과에 남습니다(`/(?=(\d+))/.exec('12')`는 `['', '12']`). 부정 탐색 안의 캡처는 항상 `undefined`입니다.
- 후방탐색은 오른쪽에서 왼쪽으로 평가합니다. 그래서 안에 그룹이 여러 개면 캡처 결과가 직관과 다릅니다. `/(?<=(\d+)(\d+))$/.exec('1053')`은 `['', '1', '053']`입니다.
- 전방탐색은 한 번 성공하면 그 안으로 되돌아가 다른 길이를 시도하지 않습니다(원자적).

## Unicode 플래그

`u` 플래그(ES2015)가 없으면 정규식은 문자열을 UTF-16 코드 유닛 단위로 읽습니다. 코드 포인트가 U+FFFF를 넘는 문자(이모지 등)는 코드 유닛 2개라 글자 하나로 취급되지 않습니다.

```js
'😀'.length                // 2
/^.$/.test('😀')          // false  (코드 유닛 2개)
/^.$/u.test('😀')         // true
'😀'.match(/./g).length   // 2
'😀'.match(/./gu).length  // 1
```

`u`가 바꾸는 것은 다음과 같습니다.

- `.`, 문자 클래스, 수량자 대상이 코드 포인트 하나 단위가 됩니다.
- `\u{1F600}` 코드 포인트 이스케이프를 씁니다. `u` 없이 `/\u{3}/`는 `u`를 3번 반복하는 패턴입니다.
- `\p{...}`, `\P{...}` 속성 이스케이프(ES2018)를 씁니다. `u` 없이 `/\p{L}/`은 글자 그대로 `p{L}`과 일치합니다.
- 문법이 엄격해집니다. 의미 없는 이스케이프(`\a`), 짝 없는 `{`, 범위를 벗어난 역참조가 SyntaxError입니다. `u` 없이는 글자 그대로 해석하며 통과합니다.
- `i`와 함께 쓰면 유니코드 대소문자 규칙을 따릅니다.
- `\d`, `\w`, `\b`는 `u`에서도 ASCII 기준 그대로입니다.

속성 이스케이프는 유니코드 속성으로 문자를 고릅니다.

| 종류 | 문법 | 예 |
|------|------|----|
| 일반 범주 | `\p{L}` `\p{Lu}` `\p{N}` | 글자, 대문자, 숫자 |
| 스크립트 | `\p{Script=Hangul}` | 한글(음절과 자모 모두) |
| 스크립트 확장 | `\p{Script_Extensions=Hangul}` | 한글을 함께 쓰는 문자 포함 |
| 이진 속성 | `\p{Alphabetic}` `\p{Emoji}` `\p{White_Space}` | 속성이 참인 문자 |

```js
/\p{Script=Hangul}/u.test('한')   // true
/\p{L}/u.test('é')                // true
/^\p{Lu}/u.test('Éa')             // true
/\P{L}/u.test('1')                // true  (글자가 아님)
'abc한글12'.match(/\p{L}+/gu)     // ['abc한글']
'한글 문서'.match(/\p{Script=Hangul}+/gu) // ['한글', '문서']
```

- 속성 이름과 값은 대소문자를 구분하며 정확히 써야 합니다. `\p{Foo}`와 `\p{script=Hangul}`는 SyntaxError입니다.
- `\p{Emoji}`는 이모지로 쓰이는 문자 전부이므로 숫자 `0`–`9`와 `#`도 일치합니다. 그림으로 표시되는 이모지만 고르려면 `\p{Emoji_Presentation}`을 씁니다.
- `u`도 코드 포인트 단위일 뿐, 사용자가 보는 글자 단위가 아닙니다. 가족 이모지는 이모지 3개와 ZWJ 2개의 코드 포인트 5개이고, `é`를 분해한 형태(`e`와 결합 문자)는 2개입니다.

```js
'👨‍👩‍👧'.length              // 8  (코드 유닛)
'👨‍👩‍👧'.match(/./gu).length // 5  (코드 포인트)
```

- 글자 단위로 세려면 `Intl.Segmenter`(자세히는 31편)를 쓰거나 이모지 시퀀스에는 `v` 플래그의 `\p{RGI_Emoji}`를 씁니다.
- 새 코드는 `u`나 `v`를 항상 켜는 것이 안전합니다. 엄격한 문법이 오타를 SyntaxError로 알려 줍니다.

## d 플래그

`d` 플래그(ES2022)를 켜면 매치 배열에 `indices` 프로퍼티가 생겨서, 매치와 각 그룹의 위치를 `[시작, 끝]` 쌍으로 알려 줍니다. 끝 인덱스는 포함하지 않습니다.

```js
const m = /(?<n>\d+)/d.exec('ab12cd')
m.indices[0]        // [2, 4]  전체 매치
m.indices[1]        // [2, 4]  1번 그룹
m.indices.groups.n  // [2, 4]  이름 있는 그룹
'ab12cd'.slice(...m.indices[0]) // '12'
```

- `d`가 없으면 `indices`는 `undefined`입니다.
- 일치하지 않은 그룹의 `indices` 항목은 `undefined`입니다. `/(a)|(b)/d.exec('b').indices`는 `[[0, 1], undefined, [0, 1]]`입니다.
- 위치는 `u`·`v`가 있어도 UTF-16 코드 유닛 기준입니다. `'😀1'`에서 `1`의 인덱스는 `[2, 3]`입니다.
- `exec`, `g` 없는 `match`, `matchAll`의 결과에 들어갑니다. `g`가 있는 `match`는 문자열 배열만 주므로 `indices`가 없습니다.
- 위치 계산에 추가 비용이 들므로 하이라이트나 오류 위치 표시처럼 필요할 때만 씁니다. 지원: Chrome 90, Firefox 88, Safari 15부터입니다.

## v 플래그

`v` 플래그(ES2024)는 `u`를 확장한 모드로, 문자 클래스 안의 집합 연산과 문자열 속성을 추가합니다. 지원: Chrome 112, Firefox 116, Safari 17부터입니다.

```js
/[\p{L}--[a-z]]/v.test('a')  // false  차집합: 글자 중 a-z 제외
/[\p{L}--[a-z]]/v.test('é')  // true
/[\p{Script=Greek}&&\p{Lu}]/v.test('Σ') // true  교집합
/[[a-z]--[aeiou]]/v.test('b') // true  중첩 클래스: 자음
/^[\q{abc|d}]$/v.test('abc')  // true  문자열 리터럴
/^\p{RGI_Emoji}$/v.test('👨‍👩‍👧') // true  이모지 시퀀스
```

| 기능 | 문법 | 설명 |
|------|------|------|
| 차집합 | `[A--B]` | A에는 있고 B에는 없는 문자 |
| 교집합 | `[A&&B]` | A와 B 모두에 있는 문자 |
| 중첩 클래스 | `[[a-z][0-9]]` | 클래스 안의 클래스, 나란히 쓰면 합집합 |
| 문자열 리터럴 | `\q{abc\|d}` | 클래스 안에서 여러 글자 문자열을 하나의 원소로 |
| 문자열 속성 | `\p{RGI_Emoji}` | 여러 코드 포인트로 된 이모지 시퀀스 |

- 문자열 속성은 `RGI_Emoji`, `Basic_Emoji`, `Emoji_Keycap_Sequence`, `RGI_Emoji_Flag_Sequence`, `RGI_Emoji_Modifier_Sequence`, `RGI_Emoji_Tag_Sequence`, `RGI_Emoji_ZWJ_Sequence` 일곱 가지입니다. `u`에서는 SyntaxError이고, `\P{...}`와 `[^...]` 안에서도 쓸 수 없습니다.
- `u`와 `v`는 함께 쓸 수 없습니다. `v`는 `u`의 모든 기능을 포함합니다.
- 클래스 문법이 더 엄격합니다. 클래스 안에서 `(`, `)`, `[`, `]`, `{`, `}`, `/`, `-`, `\`, `|`는 이스케이프해야 합니다. `/[(]/v`와 `/[a-]/v`는 SyntaxError입니다. `&&`, `--` 같은 이중 구두점은 연산자로 예약되어 있어 `[a||b]` 같은 표기도 SyntaxError입니다.
- 합집합과 집합 연산을 같은 층에 섞을 수 없습니다. `[a-z&&b]`는 SyntaxError이고 `[[a-z]&&b]`로 씁니다.
- 지원되는 환경에서 새로 쓰는 정규식은 `u` 대신 `v`를 씁니다.

## 중복 명명 그룹·수정자·RegExp.escape

세 기능은 모두 ES2025에 포함됐습니다. 지원 환경이 아직 일정하지 않으므로 사용 전에 대상 환경을 확인합니다.

| 기능 | Chrome | Firefox | Safari |
|------|--------|---------|--------|
| 중복 명명 그룹 | 125 | 129 | 17 |
| 수정자 | 125 | 132 | 26 |
| `RegExp.escape` | 136 | 134 | 18.2 |

### 중복 명명 그룹

같은 이름의 그룹을 서로 다른 `|` 대안 안에 둘 수 있습니다. 같은 이름 그룹 중 많아야 하나만 일치에 참여할 수 있는 경우에만 허용됩니다.

```js
const re = /(?<d>\d{4})-\d\d|\d\d-(?<d>\d{4})/
re.exec('2026-10').groups.d // '2026'
re.exec('10-2026').groups.d // '2026'
```

- `groups.d`에는 일치에 참여한 쪽의 값이 들어가고, 어느 쪽도 참여하지 않으면 `undefined`입니다.
- `\k<d>`와 `$<d>`도 참여한 그룹을 가리킵니다.
- 같은 대안 안에서(`/(?<a>x)(?<a>y)/`)나 둘 다 참여할 수 있는 구조(`/(?:(?<a>x)|y)(?<a>z)/`)는 여전히 SyntaxError입니다.

### 수정자

수정자(modifiers)는 패턴의 일부에만 `i`, `m`, `s` 플래그를 켜거나 끕니다. 문법은 `(?플래그:패턴)`과 `(?플래그-플래그:패턴)`이며, 효과는 그 그룹 안에만 적용됩니다.

```js
/(?i:abc)def/.test('ABCdef')  // true
/(?i:abc)def/.test('ABCDEF')  // false
/(?-i:a)b/i.test('aB')        // true   a만 대소문자 구분
/(?s:a.b)c.d/.test('a\nbcxd') // true   앞 . 만 줄바꿈 허용
```

- 바꿀 수 있는 플래그는 `i`, `m`, `s`뿐입니다. `g`, `u`, `v`, `y`, `d`는 정규식 전체 단위라 `(?g:a)`는 SyntaxError입니다.
- 같은 플래그를 켜고 끄는 데 동시에 쓰거나(`(?i-i:a)`), 켜는 쪽과 끄는 쪽이 모두 비어 있거나(`(?-:a)`) 같은 플래그를 반복하면(`(?ii:a)`) SyntaxError입니다.
- 수정자 그룹은 캡처하지 않는 그룹입니다.

### RegExp.escape

`RegExp.escape(문자열)`은 문자열을 정규식 안에서 글자 그대로 일치하도록 이스케이프한 문자열을 돌려줍니다. 사용자 입력이나 변수 값으로 패턴을 조립할 때 씁니다.

```js
const word = 'a.b'
const re = new RegExp(RegExp.escape(word), 'g')
'a.b a-b'.match(re) // ['a.b']
RegExp.escape('.*') // '\\.\\*'
```

- 문자열이 아닌 값은 TypeError입니다.
- 구문 문자(`^ $ \ . * + ? ( ) [ ] { } | /`)는 앞에 `\`를 붙입니다.
- 첫 글자가 영문자나 숫자이면 `\x61`처럼 16진 이스케이프로 바꿉니다. `RegExp.escape('a.b*c')`는 `'\\x61\\.b\\*c'`입니다.
- 공백, `-` 같은 일부 구두점도 `\x20`, `\x2d`로 바꿉니다. 한글 등 일반 문자는 그대로 둡니다.
- 지원 이전 환경에서는 직접 만든 함수를 씁니다.

```js
const escapeRe = s =>
  s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')
escapeRe('a.b*c') // 'a\\.b\\*c'
```

- 검색어를 글자 그대로 바꾸는 목적이라면 정규식 없이 `replaceAll('검색어', '대체')`로 충분합니다.

## 자주 쓰는 패턴

각 패턴은 형식을 검사할 뿐 내용이 실제로 유효한지는 보장하지 않습니다. 검증용 패턴에는 `^`와 `$`를 양쪽에 붙입니다.

```js
const digits = /^\d+$/                    // 숫자만
const decimal = /^-?\d+(?:\.\d+)?$/       // 정수·소수
const hex = /^#(?:[0-9a-f]{3}){1,2}$/i    // #fff, #ffffff
const hangul = /^[가-힣]+$/               // 완성형 한글만
const phone = /^01[016789]-\d{3,4}-\d{4}$/ // 010-1234-5678
const email = /^[^\s@]+@[^\s@]+\.[^\s@]+$/ // 형식만 확인
```

```js
const ymd = /^\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$/
ymd.test('2026-10-05') // true
ymd.test('2026-13-01') // false
ymd.test('2026-02-31') // true  (월·일 범위만 보고 달력은 모름)
```

- 이메일은 완전한 규격을 정규식 하나로 표현할 수 없습니다. 위 패턴은 `@`와 `.`의 위치만 확인하고, 실제 주소는 확인 메일로 검증합니다.
- 날짜의 유효성은 `Date`로 확인합니다(자세히는 31편). URL은 정규식 대신 `URL` 생성자(호스트 API)로 파싱하고, HTML은 정규식이 아니라 DOM 파서로 읽습니다.

변환 용도의 패턴입니다.

```js
'a   b \t c'.replace(/\s+/g, ' ')           // 'a b c'

const withComma = n =>
  String(n).replace(/\B(?=(\d{3})+(?!\d))/g, ',')
withComma(1234567) // '1,234,567'
withComma(999)     // '999'

'backgroundColor'.replace(/[A-Z]/g, c => '-' + c.toLowerCase())
// 'background-color'
'user_name_id'.replace(/_(\w)/g, (_, c) => c.toUpperCase())
// 'userNameId'
```

- 천 단위 콤마 패턴은 숫자 사이(`\B`) 중에서 뒤에 숫자 3개 묶음이 끝까지 이어지는 위치(전방탐색)에만 콤마를 넣습니다. 지역 표기가 필요하면 `toLocaleString`이나 `Intl.NumberFormat`이 낫습니다(자세히는 31편).

비밀번호 규칙처럼 "여러 조건을 모두 만족"하는 검사는 앞의 전방탐색 겹쳐 쓰기를 씁니다: `/^(?=.*[a-z])(?=.*\d).{8,}$/`.

## 치명적 백트래킹

패턴의 뒤쪽이 실패하면 엔진은 앞쪽 수량자와 대안의 선택을 바꿔 가며 다시 시도합니다(백트래킹, backtracking). 시도할 조합이 입력 길이에 따라 폭발적으로 늘어나는 패턴은 실패하는 입력에서 몇 초에서 몇 시간 동안 스레드를 붙잡습니다. 이를 치명적 백트래킹이라고 하며, 공격에 쓰이면 ReDoS(정규식 서비스 거부)라고 부릅니다.

```js
const re = /^(a+)+$/
re.test('aaaa')               // true   즉시
re.test('a'.repeat(28) + '!') // false  Node 24에서 약 1초
re.test('a'.repeat(29) + '!') // 글자 하나마다 약 2배
```

`!`에서 실패하면 엔진은 `a` 28개를 `(a+)+`가 나누는 모든 방법을 시도한 뒤에야 포기합니다. ECMAScript에는 정규식 실행 제한 시간이 없어서 브라우저는 화면이 멈추고 서버는 요청 처리가 멈춥니다.

위험한 구조는 다음과 같습니다.

| 구조 | 예 | 시간 증가 |
|------|----|-----------|
| 중첩 수량자 | `(a+)+`, `(a*)*`, `(\w+\s?)*` | 지수 |
| 겹치는 대안의 반복 | `(a\|aa)+`, `(\w\|\d)+` | 지수 |
| 이웃한 겹치는 수량자 | `\d+\d+`, `.*.*` | 다항식 |

- 위험은 매치가 실패하는 입력에서 드러납니다. 성공하는 입력만 시험하면 발견하지 못합니다.
- 중첩 수량자를 하나로 합칩니다: `(a+)+`는 `a+`와 같은 문자열을 받습니다.
- 반복되는 부분이 서로 겹치지 않게 합니다: `(\w|\d)+`는 `\w+`로 충분합니다.
- `.*` 대신 부정 클래스를 써서 구분자를 넘지 못하게 합니다: `"[^"]*"`.
- 검사 전에 입력 길이를 제한합니다. 사용자 입력을 패턴으로 쓰는 것은 피하고, 써야 하면 `RegExp.escape`로 이스케이프합니다.
- ECMAScript에는 원자적 그룹과 소유 수량자가 없습니다. 전방탐색이 한 번 성공하면 되돌아가지 않는 성질과 역참조를 조합해 흉내 낼 수 있습니다.

```js
/a+ab/.test('aaab')         // true   a+ 가 한 글자를 내놓고 되돌아감
/(?=(a+))\1ab/.test('aaab') // false  a+ 가 세 글자로 고정됨
```

## 핵심 정리

- 정규식은 패턴과 플래그로 이루어집니다. 리터럴은 파싱 시점에 문법 오류를 내고, 생성자에 넘기는 문자열은 백슬래시를 두 번 써야 합니다.
- `g`·`y` 정규식은 `lastIndex`에 상태가 있어 `test`·`exec` 반복 호출 결과가 번갈아 달라집니다. `matchAll`과 정규식 `replaceAll`은 `g`가 필수입니다.
- `|`는 우선순위가 가장 낮고, 수량자는 기본이 탐욕이며, 검증에는 양쪽 앵커가 필요합니다. `\d`·`\w`·`\b`는 ASCII 기준이므로 한글에는 `u`와 `\p{...}`를 씁니다.
- 캡처는 번호나 이름으로 읽고, 전후방탐색은 문자를 소비하지 않고 주변만 검사합니다.
- `d`(ES2022), `v`(ES2024), 중복 명명 그룹·수정자·`RegExp.escape`(ES2025)는 지원 환경을 확인한 뒤 씁니다.
- 중첩 수량자와 겹치는 대안은 실패하는 입력에서 지수 시간이 걸리므로 구조를 고치고 입력 길이를 제한합니다.
