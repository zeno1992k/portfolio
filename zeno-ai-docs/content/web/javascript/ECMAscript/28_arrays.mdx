## 배열·요소·인덱스

배열(array)은 값을 순서대로 담는 객체입니다. 담긴 값을 요소(element), 요소의 순번을 인덱스(index)라고 하며 인덱스는 0부터 시작합니다.

```js
const fruits = ['apple', 'banana', 'cherry']
fruits[0]      // 'apple'
fruits[2]      // 'cherry'
fruits[3]      // undefined (에러가 아니다)
fruits.length  // 3
```

- 마지막 요소의 인덱스는 `length - 1`입니다.
- 없는 인덱스를 읽으면 에러 없이 `undefined`가 나옵니다. 요소 값이 `undefined`인 경우와 구분하려면 `in` 연산자를 씁니다(아래 length와 희소 배열).
- 요소의 타입은 섞여도 되고, 배열도 요소가 될 수 있습니다. 배열 안의 배열을 중첩 배열이라고 하며, 2차원 배열은 중첩 배열로 표현합니다.

```js
const mixed = [1, 'two', { three: 3 }, [4, 5]]
mixed[2].three  // 3
mixed[3][1]     // 5
```

- 인덱스 접근은 대괄호만 가능합니다. `arr.0`은 구문 오류입니다.

## JavaScript 배열의 특징

JavaScript의 배열은 `Array.prototype`을 상속하는 특수한 객체입니다. 인덱스 프로퍼티와 `length`가 서로 연동되는 것이 일반 객체와의 차이이고, 명세는 이런 객체를 Array exotic object라고 부릅니다.

| 항목 | C·Java의 배열 | JavaScript 배열 |
|------|---------------|-----------------|
| 크기 | 생성할 때 고정 | 언제든 변한다 |
| 요소 타입 | 하나로 통일 | 섞을 수 있다 |
| 빈 칸 | 모든 칸에 값이 있다 | 값이 없는 빈 슬롯을 가질 수 있다 |
| 메모리 | 연속된 공간 | 명세가 규정하지 않는다 |

- `typeof []`는 `'object'`입니다. 배열 판별은 `Array.isArray`로 합니다(아래 Array.isArray).
- 인덱스는 내부적으로 문자열 프로퍼티 키입니다. `arr[1]`과 `arr['1']`은 같은 요소를 가리킵니다.
- 배열 변수에 대입하면 참조가 복사됩니다. 두 변수가 같은 배열을 가리키므로 한쪽에서 바꾸면 다른 쪽도 바뀝니다(자세히는 10편).
- 배열은 이터러블이라 `for...of`, 스프레드, 디스트럭처링에 쓸 수 있습니다(자세히는 35·36·37편).
- `length`의 최댓값은 2^32 - 1(4294967295)이고, 가장 큰 인덱스는 2^32 - 2입니다.
- 배열에도 일반 프로퍼티를 붙일 수 있지만 `length`에 반영되지 않고 배열 메서드는 무시합니다.

```js
const arr = [1, 2, 3]
arr.note = 'extra'
arr.length        // 3
arr.map(x => x)   // [1, 2, 3]
Object.keys(arr)  // ['0', '1', '2', 'note']
```

엔진은 구현 수준에서 숫자만 담긴 배열 같은 경우를 연속된 메모리로 최적화합니다. 이것은 명세가 아니라 구현이므로 동작은 달라지지 않지만, 큰 인덱스로 건너뛰며 채우는 희소 배열은 이 최적화를 잃기 쉽습니다.

배열과 일반 객체의 차이는 다음과 같습니다.

| 항목 | 배열 | 일반 객체 |
|------|------|-----------|
| 리터럴 | `[]` | `{}` |
| 키 | 0부터 시작하는 정수 인덱스 | 문자열·심벌 |
| length | 인덱스에 맞춰 자동 갱신 | 없다 |
| 프로토타입 | `Array.prototype` | `Object.prototype` |

## length와 희소 배열

### length

`length`는 배열의 가장 큰 인덱스 + 1입니다. 읽고 쓸 수 있지만 열거와 삭제는 되지 않는 프로퍼티입니다(자세히는 14편). 희소 배열에서는 요소 개수와 다를 수 있습니다.

인덱스에 값을 쓰면 `length`가 자동으로 늘어납니다.

```js
const a = [1, 2]
a[5] = 'x'
a.length  // 6
a         // [1, 2, <3 empty items>, 'x']
```

`length`에 더 작은 값을 쓰면 뒤쪽 요소가 잘려 나가고 복구되지 않습니다. 더 큰 값을 쓰면 빈 슬롯이 생깁니다.

```js
const a = [1, 2, 3, 4, 5]
a.length = 2
a  // [1, 2]
a.length = 4
a  // [1, 2, <2 empty items>] (3, 4, 5는 돌아오지 않는다)
a.length = 0
a  // []
```

- 음수, 소수, 2^32 이상 같은 올바르지 않은 값을 쓰면 `RangeError: Invalid array length`가 납니다.
- `arr.length = 0`은 같은 배열 객체를 비웁니다. 같은 배열을 참조하는 다른 변수에도 반영됩니다. `arr = []`는 변수만 새 빈 배열로 바꾸므로 다른 참조는 그대로 남습니다.

### 희소 배열

희소 배열(sparse array)은 값이 없는 칸, 즉 빈 슬롯(empty slot)이 있는 배열입니다. 빈 슬롯은 프로퍼티 자체가 존재하지 않는 칸이고, 값이 `undefined`인 칸과 다릅니다.

빈 슬롯이 생기는 경우는 다섯 가지입니다.

- 리터럴에 연속된 쉼표를 쓴 경우: `[1, , 3]`
- `new Array(3)`처럼 길이만 지정한 경우
- `delete arr[i]`로 요소를 지운 경우
- `length`를 늘린 경우
- `length`보다 훨씬 큰 인덱스에 값을 쓴 경우

```js
const holey = [1, , 3]
const filled = [1, undefined, 3]
holey[1]            // undefined
filled[1]           // undefined
1 in holey          // false (프로퍼티가 없다)
1 in filled         // true
Object.keys(holey)  // ['0', '2']
```

- 콘솔은 빈 슬롯을 `<1 empty item>`처럼 따로 표시합니다. 표시 형식은 환경마다 다릅니다.
- 리터럴 끝의 쉼표는 하나만 무시됩니다. `[1, 2, ]`와 `[1, , ]`의 `length`는 둘 다 2입니다.
- 읽으면 `undefined`가 나오기 때문에 빈 슬롯인지 값이 `undefined`인지는 `in` 연산자나 `Object.hasOwn`으로만 구분됩니다(자세히는 18편).
- 메서드마다 빈 슬롯을 건너뛰기도 하고 `undefined`로 읽기도 합니다(아래 메서드별 빈 요소 처리). 희소 배열은 만들지 않는 편이 안전합니다.

## 배열 생성(리터럴·Array·of·from)

### 배열 리터럴

`[]`로 만드는 것이 기본입니다. 요소를 쉼표로 나열합니다.

```js
const empty = []
const nums = [1, 2, 3]
```

### Array 생성자

`Array(...)`와 `new Array(...)`는 같은 결과를 냅니다. 인수 개수와 타입에 따라 의미가 달라지는 것이 함정입니다.

```js
new Array(3)      // [<3 empty items>] (길이 3)
new Array(3, 4)   // [3, 4]
new Array('3')    // ['3']
Array(3)          // new 없이 불러도 같다
new Array(-1)     // RangeError: Invalid array length
```

- 인수가 하나이고 숫자이면 그 값이 `length`가 되고, 요소는 만들어지지 않습니다.
- 인수가 하나이고 숫자가 아니면 그 값이 유일한 요소입니다.
- 인수가 둘 이상이면 모두 요소입니다.
- 하나뿐인 숫자 인수가 0 이상 2^32 - 1 이하의 정수가 아니면 `RangeError`입니다.

### Array.of

`Array.of(...items)`(ES2015)는 인수를 개수와 타입에 상관없이 그대로 요소로 하는 배열을 만듭니다. `Array` 생성자의 인수 하나 예외를 피하는 용도입니다.

```js
Array.of(3)        // [3]
Array.of(1, 2, 3)  // [1, 2, 3]
```

### Array.from

`Array.from(items, mapFn, thisArg)`(ES2015)는 이터러블이나 유사 배열 객체를 새 배열로 바꿉니다.

```js
Array.from('abc')                // ['a', 'b', 'c']
Array.from(new Set([1, 1, 2]))   // [1, 2]
Array.from({ length: 2 })        // [undefined, undefined]
Array.from([1, 2, 3], x => x * 2)  // [2, 4, 6]
Array.from({ length: 3 }, (_, i) => i)  // [0, 1, 2]
```

- 두 번째 인수 `mapFn(value, index)`는 변환 함수입니다. `Array.from(x).map(fn)`과 결과가 같지만 중간 배열을 만들지 않습니다. `thisArg`는 `mapFn`의 `this`로 쓰입니다(자세히는 29편).
- 입력이 이터러블이면 이터레이터를 쓰고, 아니면 `length`와 인덱스를 씁니다. 둘 다 있으면 이터러블이 우선입니다.
- 문자열은 UTF-16 코드 유닛이 아니라 코드 포인트 단위로 나뉩니다. `Array.from('a😀b')`는 요소 3개입니다.
- 빈 슬롯은 `undefined`가 됩니다. `Array.from([1, , 3])`은 `[1, undefined, 3]`입니다.
- 이터러블도 유사 배열 객체도 아닌 값(숫자, 불리언)은 빈 배열이 되고, `null`과 `undefined`는 `TypeError`입니다.

### 초기화된 배열 만들기

```js
new Array(3).fill(0)                    // [0, 0, 0]
Array.from({ length: 3 }, () => 0)      // [0, 0, 0]
Array.from({ length: 3 }, (_, i) => i)  // [0, 1, 2]
Array.from(Array(3).keys())             // [0, 1, 2]
```

흔한 실수는 `new Array(3)`에 바로 `map`을 쓰는 것입니다. `map`은 빈 슬롯을 건너뛰므로 콜백이 한 번도 호출되지 않습니다.

```js
new Array(3).map((_, i) => i)         // ❌ 빈 슬롯 3개
new Array(3).fill().map((_, i) => i)  // ✅ [0, 1, 2]
```

그 밖의 생성 방법으로 스프레드 `[...iterable]`(36편), `'a,b'.split(',')`(33편), `Object.keys`·`Object.entries`(18편)가 있습니다.

## Array.fromAsync (ES2026)

`Array.fromAsync(items, mapFn, thisArg)`는 비동기 이터러블을 포함한 입력을 배열로 모으고, 그 배열로 이행하는 프로미스를 반환합니다(프로미스는 41편, `await`는 43편).

```js
async function* gen() { yield 1; yield 2 }
await Array.fromAsync(gen())                     // [1, 2]
await Array.fromAsync([Promise.resolve(1), 2])   // [1, 2]
await Array.fromAsync([1, 2], async x => x * 2)  // [2, 4]
```

- 입력은 비동기 이터러블, 동기 이터러블, 유사 배열 객체 순서로 판별합니다.
- 동기 이터러블과 유사 배열 객체의 요소는 프로미스여도 `await`된 값이 배열에 들어갑니다.
- `mapFn`의 반환값도 `await`됩니다. 비동기 이터러블이 입력이면 `mapFn`에 넘기는 값은 `await`하지 않고 그대로 넘깁니다.
- 요소를 하나씩 순서대로 처리합니다. 다음 요소는 앞 요소가 끝난 뒤에 처리합니다.
- 한 요소가 거부되면 반환된 프로미스도 그 이유로 거부됩니다.

`Promise.all`과의 차이는 실행 방식입니다.

| 비교 | `Array.fromAsync` | `Promise.all` |
|------|-------------------|---------------|
| 입력 | 비동기·동기 이터러블, 유사 배열 | 동기 이터러블 |
| 처리 | 하나씩 순서대로 | 전부 동시에 기다림 |
| 변환 함수 | `mapFn` 인수 | 없음 (`map`으로 미리 변환) |

각각 100ms가 걸리는 비동기 `mapFn` 세 개를 처리하면 `Array.fromAsync`는 약 300ms, `Promise.all(arr.map(fn))`은 약 100ms가 걸립니다.

ES2026에 포함된 기능입니다. 쓰기 전에 대상 환경의 지원 여부를 MDN에서 확인합니다. `await` 없이 호출하면 배열이 아니라 프로미스가 나오는 것이 흔한 실수입니다.

## 요소 참조·추가·갱신·삭제

| 동작 | 방법 | 비고 |
|------|------|------|
| 참조 | `arr[i]` | 범위 밖이면 `undefined` |
| 끝에 추가 | `arr.push(v)`, `arr[arr.length] = v` | |
| 앞·중간에 추가 | `unshift`, `splice` | |
| 갱신 | `arr[i] = v` | |
| 삭제 | `pop`, `shift`, `splice`, `length` 줄이기 | `delete`는 빈 슬롯만 남긴다 |

```js
const a = ['a', 'b', 'c']
a[1] = 'B'          // a: ['a', 'B', 'c']
a[a.length] = 'd'   // a: ['a', 'B', 'c', 'd']
a[10] = 'z'         // 중간이 빈 슬롯인 희소 배열
```

음수 인덱스는 뒤에서 세는 것이 아닙니다. `-1`은 그냥 문자열 키 `'-1'`이므로, 읽으면 `undefined`이고 쓰면 `length`는 그대로인 일반 프로퍼티가 생깁니다. 뒤에서 읽으려면 `at`을 씁니다(아래 at).

```js
const n = [1, 2, 3]
n[-1]          // undefined
n[-1] = 'x'
n.length       // 3 (늘어나지 않는다)
Object.keys(n) // ['0', '1', '2', '-1']
```

- 배열 인덱스로 인정되는 키는 0 이상 2^32 - 2 이하 정수의 정식 십진 문자열입니다. 숫자 `1.0`은 `'1'`로 변환되므로 `a[1.0]`은 `a[1]`과 같고, `a['01']`은 인덱스가 아닌 일반 프로퍼티입니다.
- `delete`는 요소를 지우지만 `length`와 뒤 요소의 위치는 그대로입니다.

```js
const a = ['a', 'b', 'c']
delete a[1]
a         // ['a', <1 empty item>, 'c']
a.length  // 3
```

- 요소를 지우고 뒤 요소를 당기려면 `splice`를 씁니다(아래 splice·slice). 조건으로 걸러 내려면 `filter`를 씁니다(자세히는 29편).
- `const`로 선언한 배열도 요소를 바꿀 수 있습니다. `const`는 변수 재할당만 막습니다(자세히는 3편).

## 원본 변경 메서드와 새 배열 반환 메서드

배열 메서드는 호출한 배열 자체를 바꾸는 것과 원본을 두고 새 값을 만드는 것으로 나뉩니다. 원본을 바꾸는 메서드는 9개입니다.

| 메서드 | 반환값 |
|--------|--------|
| `push`, `unshift` | 바뀐 뒤의 새 `length` |
| `pop`, `shift` | 제거한 요소 |
| `splice` | 제거한 요소들의 배열 |
| `sort`, `reverse`, `fill`, `copyWithin` | 원본 배열 자체 |

새 배열을 반환하는 메서드는 `concat`, `slice`, `flat`, `flatMap`, `map`, `filter`, `toSorted`, `toReversed`, `toSpliced`, `with`입니다. 나머지(`indexOf`, `includes`, `join`, `find` 등)는 원본을 바꾸지 않고 값을 반환합니다. 전체 표는 마지막 절에 있습니다.

`sort`·`reverse`·`fill`·`copyWithin`의 반환값은 새 배열이 아니라 원본과 같은 배열입니다.

```js
const a = [3, 1, 2]
const b = a.sort()
b === a             // true (같은 배열)
a                   // [1, 2, 3]
const c = a.toSorted()
c === a             // false (새 배열)
```

원본을 바꾸는 메서드는 그 배열을 참조하는 모든 곳에 영향을 줍니다. 함수 안에서 호출하면 호출한 쪽의 배열이 바뀝니다.

```js
function top3(scores) {
  return scores.sort((x, y) => y - x).slice(0, 3)
}
const list = [5, 9, 1, 7]
top3(list)  // [9, 7, 5]
list        // [9, 7, 5, 1] (원본이 정렬되어 버렸다)
```

- 정렬 전에 복사하거나(`[...scores].sort(...)`) ES2023의 `toSorted`를 쓰면 원본이 유지됩니다(`sort`는 29편).
- 상태를 새 배열로 교체하는 불변 갱신 방식에서는 새 배열을 반환하는 메서드만 씁니다(자세히는 50편).
- `Object.freeze`로 동결한 배열에 원본 변경 메서드를 쓰면 `TypeError`가 납니다(자세히는 14편).

새 배열을 반환해도 요소는 복사되지 않습니다. 요소가 객체이면 원본과 새 배열이 같은 객체를 공유합니다(자세히는 10편).

```js
const users = [{ name: 'kim' }]
const copy = users.slice()
copy[0].name = 'lee'
users[0].name   // 'lee'
copy === users  // false
```

## Array.isArray

`Array.isArray(value)`(ES5)는 값이 배열이면 `true`를 반환합니다.

```js
Array.isArray([])                 // true
Array.isArray({ length: 0 })      // false
Array.isArray('abc')              // false
Array.isArray(new Uint8Array(2))  // false
Array.isArray(new Proxy([], {}))  // true
```

- `typeof`는 배열에도 `'object'`를 반환하므로 배열 판별에 쓸 수 없습니다.
- `instanceof Array`는 다른 실행 영역(iframe, Node.js의 `vm` 컨텍스트 등)에서 만든 배열에 `false`를 반환합니다. 그 영역의 `Array.prototype`을 상속하기 때문입니다. `Array.isArray`는 실행 영역과 무관하게 `true`입니다.
- 유사 배열 객체와 Typed Array는 배열이 아니므로 `false`입니다(자세히는 48편).
- `Array.prototype` 자체도 배열이라서 `Array.isArray(Array.prototype)`은 `true`입니다.

## indexOf·includes

`indexOf(value, fromIndex)`는 처음 일치하는 인덱스를, `includes(value, fromIndex)`는 존재 여부를 반환합니다.

| 항목 | `indexOf` | `includes` |
|------|-----------|------------|
| 반환값 | 인덱스, 없으면 `-1` | `true` 또는 `false` |
| 비교 방식 | 엄격한 동등(`===`) | SameValueZero |
| `NaN` | 찾지 못한다 | 찾는다 |
| 빈 슬롯 | 건너뛴다 | `undefined`로 취급한다 |
| 도입 | ES5 | ES2016 |

SameValueZero는 `===`와 같지만 `NaN`을 `NaN`과 같다고 보는 비교입니다. `+0`과 `-0`은 같게 봅니다.

```js
const a = [1, 2, NaN, 2]
a.indexOf(2)       // 1
a.indexOf(2, 2)    // 3 (인덱스 2부터 검색)
a.indexOf(NaN)     // -1
a.includes(NaN)    // true
a.includes(9)      // false
```

`fromIndex`가 음수이면 `length`를 더한 위치에서 시작하고, 더해도 0보다 작으면 0으로 봅니다.

```js
const b = [1, 2, 3, 2]
b.indexOf(2, -2)   // 3 (4 + -2 = 2번 인덱스부터)
b.indexOf(1, -9)   // 0 (0 미만이므로 0부터)
```

- 요소가 객체이면 참조를 비교합니다. `[{ a: 1 }].includes({ a: 1 })`은 `false`입니다. 조건으로 찾으려면 `some`·`find`를 씁니다(자세히는 29편).
- 두 메서드는 빈 슬롯에서 갈립니다. `[,].includes(undefined)`는 `true`이고 `[,].indexOf(undefined)`는 `-1`입니다.

흔한 실수는 `indexOf`의 반환값을 조건식에 바로 쓰는 것입니다.

```js
const arr = ['a', 'b']
if (arr.indexOf('a')) {}   // ❌ 0은 falsy라서 있는데도 거짓
if (arr.indexOf('z')) {}   // ❌ -1은 truthy라서 없는데도 참
if (arr.indexOf('a') !== -1) {}  // ✅
if (arr.includes('a')) {}        // ✅ 존재 확인이면 이쪽
```

## lastIndexOf

`lastIndexOf(value, fromIndex)`는 `indexOf`와 같은 비교 방식으로 뒤에서 앞으로 검색해 마지막으로 일치하는 인덱스를 반환합니다. 없으면 `-1`입니다.

```js
const a = [1, 2, 3, 2]
a.lastIndexOf(2)       // 3
a.lastIndexOf(2, 2)    // 1 (인덱스 2부터 앞쪽으로 검색)
a.lastIndexOf(2, -2)   // 1 (4 + -2 = 2번부터 앞쪽으로)
```

- `fromIndex`의 기본값은 `length - 1`입니다. 음수이면 `length`를 더합니다.
- `NaN`을 찾지 못하고 빈 슬롯은 건너뜁니다. 뒤에서 찾는 `includes`는 없습니다.
- 값이 아니라 조건으로 뒤에서 찾으려면 `findLast`·`findLastIndex`를 씁니다(자세히는 29편).

## push·pop·unshift·shift

끝과 앞에서 요소를 추가하고 제거하는 메서드입니다. 모두 원본을 바꿉니다.

| 메서드 | 위치 | 동작 | 반환값 |
|--------|------|------|--------|
| `push(...items)` | 끝 | 추가 | 새 `length` |
| `pop()` | 끝 | 제거 | 제거한 요소 |
| `unshift(...items)` | 앞 | 추가 | 새 `length` |
| `shift()` | 앞 | 제거 | 제거한 요소 |

```js
const a = [1, 2]
a.push(3, 4)   // 4, a: [1, 2, 3, 4]
a.pop()        // 4, a: [1, 2, 3]
a.unshift(0)   // 4, a: [0, 1, 2, 3]
a.shift()      // 0, a: [1, 2, 3]
```

- 빈 배열에 `pop`·`shift`를 쓰면 `undefined`를 반환하고 `length`는 0 그대로입니다.
- 인수를 여러 개 주면 인수 순서대로 들어갑니다. `[3].unshift(1, 2)`의 결과는 `[1, 2, 3]`입니다.
- 인수로 배열을 주면 펼쳐지지 않고 요소 하나로 들어갑니다. `[1].push([2, 3])`은 `[1, [2, 3]]`이 됩니다. 펼쳐 넣으려면 `push(...other)`를 쓰는데(자세히는 36편), 배열이 매우 크면 엔진의 인수 개수 한계를 넘어 `RangeError`가 날 수 있습니다.
- `push`·`pop`은 스택, `push`·`shift`는 큐로 쓸 수 있습니다.
- `push`·`pop`은 끝에서만 일어나지만 `shift`·`unshift`는 나머지 요소의 인덱스를 모두 옮겨야 합니다. 엔진이 최적화하기도 하지만, 큰 배열에서 `shift`를 반복하면 느려질 수 있습니다.
- 흔한 실수는 반환값 혼동입니다. `push`와 `unshift`는 추가한 요소나 배열이 아니라 새 `length`를 반환합니다.

## concat

`concat(...values)`는 원본 뒤에 인수를 이어 붙인 새 배열을 반환합니다. 원본은 바뀌지 않습니다.

```js
const a = [1, 2]
a.concat([3, 4])      // [1, 2, 3, 4]
a.concat(3, [4, 5])   // [1, 2, 3, 4, 5]
a.concat([[6, 7]])    // [1, 2, [6, 7]]
a                     // [1, 2]
```

- 인수가 배열이면 요소를 한 단계만 펼쳐 붙이고, 배열이 아니면 값 하나로 붙입니다. 중첩 배열은 더 펼쳐지지 않습니다.
- 유사 배열 객체는 펼치지 않고 객체 하나로 붙습니다. 객체에 `Symbol.isConcatSpreadable`이 `true`이면 펼칩니다(자세히는 34편).
- 요소는 얕은 복사됩니다. 빈 슬롯은 빈 슬롯으로 유지됩니다.
- 인수 없이 `a.concat()`을 호출하면 얕은 복사본이 나옵니다.
- 스프레드 `[...a, ...b]`로 같은 결과를 얻을 수 있습니다. 스프레드는 빈 슬롯을 `undefined`로 채웁니다(자세히는 36편).
- 흔한 실수는 반환값을 받지 않는 것입니다. `a.concat(b)`만 호출하면 `a`는 그대로입니다.

## splice·slice

두 메서드는 이름이 비슷하지만 성격이 다릅니다.

| 항목 | `slice(start, end)` | `splice(start, deleteCount, ...items)` |
|------|---------------------|-----------------------------------------|
| 원본 | 바꾸지 않는다 | 바꾼다 |
| 반환값 | 선택한 구간의 새 배열 | 제거한 요소들의 배열 |
| 두 번째 인수 | 끝 인덱스(미포함) | 제거할 개수 |
| 용도 | 일부를 복사 | 삭제·삽입·교체 |

```js
const a = [0, 1, 2, 3, 4]
a.slice(1, 3)             // [1, 2]
a.slice(-2)               // [3, 4]
a.splice(1, 2)            // [1, 2], a: [0, 3, 4]
a.splice(1, 0, 'x')       // [], a: [0, 'x', 3, 4]
a.splice(1, 1, 'y', 'z')  // ['x'], a: [0, 'y', 'z', 3, 4]
```

`slice` 규칙은 다음과 같습니다.

- 구간은 `start` 이상 `end` 미만입니다. `end`를 생략하면 끝까지입니다.
- 음수는 `length`를 더해 계산합니다. 범위를 벗어나면 0 또는 `length`로 맞춥니다.
- `start`가 `end` 이상이면 빈 배열입니다.
- 인수 없이 `arr.slice()`를 호출하면 얕은 복사본입니다.

`splice` 규칙은 다음과 같습니다.

- `start`가 음수이면 `length`를 더하고(0 미만이면 0), `length`를 넘으면 `length`로 맞춥니다.
- `deleteCount`를 생략하면 `start`부터 끝까지 전부 제거합니다. 0 이하이면 제거하지 않고, 남은 개수보다 크면 남은 개수까지만 제거합니다.
- `deleteCount`에 `undefined`를 명시하면 생략과 달리 0으로 변환됩니다.
- 삽입할 요소는 `start` 위치에 들어가고, 뒤 요소는 밀립니다.

```js
const a = [1, 2, 3]
a.splice(1)             // [2, 3] (생략: 끝까지 제거)
const b = [1, 2, 3]
b.splice(1, undefined)  // [] (0개 제거)
b.splice()              // [] (아무것도 하지 않는다)
```

흔한 실수는 다음과 같습니다.

```js
const a = ['a', 'b', 'c']
a.splice(a.indexOf('z'), 1)  // ❌ -1이 마지막 요소를 가리킨다
a                            // ['a', 'b']
```

- `indexOf`가 `-1`을 반환하면 `splice(-1, 1)`이 되어 마지막 요소가 지워집니다. 인덱스가 `-1`인지 확인하고 호출해야 합니다.
- `slice`의 두 번째 인수를 개수로 착각하거나, `splice`의 두 번째 인수를 끝 인덱스로 착각하는 실수가 많습니다.
- 순회 중에 `splice`로 요소를 지우면 인덱스가 밀려 요소를 건너뜁니다(자세히는 29편).

## join·reverse·fill

### join

`join(separator)`는 요소를 문자열로 바꿔 구분자로 이은 문자열을 반환합니다. 구분자를 생략하면 쉼표입니다.

```js
const nums = [1, 2, 3]
nums.join()      // '1,2,3'
nums.join('-')   // '1-2-3'
nums.join('')    // '123'
```

- `null`, `undefined`, 빈 슬롯은 빈 문자열이 됩니다. `[1, null, undefined, 3].join('-')`은 `'1---3'`입니다.
- 중첩 배열은 안쪽에서 `toString`이 호출되어 쉼표로 이어집니다. `[1, [2, 3]].join('-')`은 `'1-2,3'`입니다.
- 빈 배열의 `join()`은 빈 문자열입니다.
- `Array.prototype.toString`은 `join()`을 호출합니다. 그래서 `String([1, 2])`는 `'1,2'`입니다. `toLocaleString`은 각 요소의 `toLocaleString` 결과를 쉼표로 이어 붙입니다.

### reverse

`reverse()`는 요소 순서를 뒤집습니다. 원본을 바꾸고 원본 배열 자체를 반환합니다. 빈 슬롯도 위치가 뒤집힌 채 유지됩니다.

```js
const a = [1, 2, 3]
a.reverse() === a  // true
a                  // [3, 2, 1]
```

- 원본을 유지하려면 `toReversed`를 씁니다(아래 toSorted·toReversed·toSpliced·with).
- 문자열을 뒤집으려면 `[...str].reverse().join('')`을 씁니다. `split('')`은 UTF-16 코드 유닛으로 쪼개서 이모지 같은 문자가 깨집니다(자세히는 33편).

### fill

`fill(value, start, end)`는 `start` 이상 `end` 미만 구간을 같은 값으로 채웁니다. 원본을 바꾸고 원본 배열 자체를 반환합니다(ES2015).

```js
new Array(3).fill(0)        // [0, 0, 0]
const a = [1, 2, 3, 4]
a.fill(0, 1, 3)             // [1, 0, 0, 4]
const b = [1, 2, 3]
b.fill(9, -1)               // [1, 2, 9]
```

- `start`는 기본 0, `end`는 기본 `length`이고, 음수는 `length`를 더합니다.
- 빈 슬롯도 값으로 채웁니다. 그래서 `new Array(n).fill(v)`가 초기화 배열을 만드는 관용구입니다.
- 인수 없이 `fill()`을 쓰면 `undefined`로 채워 빈 슬롯을 없앱니다.

## fill의 참조 공유

`fill`은 값 하나를 모든 칸에 넣습니다. 그 값이 객체이면 모든 칸이 같은 객체를 가리킵니다.

```js
const grid = Array(2).fill([])
grid[0].push(1)
grid                   // [[1], [1]]
grid[0] === grid[1]    // true

const ok = Array.from({ length: 2 }, () => [])
ok[0].push(1)
ok                     // [[1], []]
```

- `fill({ n: 0 })`도 같은 문제를 일으킵니다. 한 칸의 객체를 바꾸면 모든 칸이 바뀝니다.
- 칸마다 독립된 객체나 배열이 필요하면 `Array.from`의 `mapFn`으로 칸마다 새로 만듭니다.
- 숫자·문자열 같은 원시 값을 채우는 것은 안전합니다. 원시 값은 복사되기 때문입니다(자세히는 10편).

## copyWithin

`copyWithin(target, start, end)`(ES2015)는 배열 안의 `start` 이상 `end` 미만 구간을 같은 배열의 `target` 위치로 복사해 덮어씁니다. 원본을 바꾸고 원본 배열 자체를 반환합니다.

```js
const a = [1, 2, 3, 4, 5]
a.copyWithin(0, 3)      // [4, 5, 3, 4, 5]
const b = [1, 2, 3, 4, 5]
b.copyWithin(1, 0, 3)   // [1, 1, 2, 3, 5]
const c = [1, 2, 3, 4, 5]
c.copyWithin(-2, 0)     // [1, 2, 3, 1, 2]
```

- `length`는 바뀌지 않습니다. 복사 대상이 끝을 넘으면 넘는 부분은 버려집니다.
- 구간이 겹쳐도 복사 전의 값을 기준으로 복사합니다. `[1, 2, 3, 4, 5].copyWithin(2, 0)`은 `[1, 2, 1, 2, 3]`입니다.
- `start`는 기본 0, `end`는 기본 `length`이고 음수는 `length`를 더합니다.
- 빈 슬롯은 빈 슬롯인 채로 복사되어 대상 칸의 값을 지웁니다. `[1, , 3].copyWithin(0, 1)`은 `[<empty>, 3, 3]`입니다.
- 실무에서 쓰는 일은 드뭅니다.

## flat

`flat(depth)`(ES2019)는 중첩 배열을 `depth` 단계까지 펼친 새 배열을 반환합니다. `depth`의 기본값은 1입니다.

```js
const n = [1, [2, [3, [4]]]]
n.flat()           // [1, 2, [3, [4]]]
n.flat(2)          // [1, 2, 3, [4]]
n.flat(Infinity)   // [1, 2, 3, 4]
```

- 원본은 바뀌지 않습니다.
- 빈 슬롯은 결과에서 제거됩니다. `[1, , 3].flat()`은 `[1, 3]`입니다. `flat(0)`도 마찬가지로 빈 슬롯을 없앱니다.
- `depth`가 0 이하이면 펼치지 않고 얕은 복사본(빈 슬롯은 제거)을 반환합니다.
- 펼치는 대상은 배열뿐입니다. 유사 배열 객체는 펼치지 않습니다.
- 변환과 한 단계 펼치기를 한 번에 하는 `flatMap`은 29편에서 다룹니다.

## at

`at(index)`(ES2022)는 인덱스의 요소를 반환하되 음수 인덱스를 뒤에서부터 셉니다. 범위를 벗어나면 `undefined`입니다.

```js
const a = [10, 20, 30]
a.at(0)    // 10
a.at(-1)   // 30
a.at(5)    // undefined
a[-1]      // undefined (대괄호는 뒤에서 세지 않는다)
```

- 음수 `index`는 `length`를 더해 계산합니다. `length` 이상이거나 `-length`보다 작으면 `undefined`입니다.
- 인수는 정수로 변환됩니다. 소수는 0 방향으로 버립니다(`a.at(1.7)`은 20). 문자열 `'1'`은 숫자로 바뀌고(`a.at('1')`은 20), `NaN`과 생략은 0으로 봅니다(`a.at()`은 10).
- 마지막 요소는 `arr[arr.length - 1]`로도 읽지만, 배열이 변수가 아니라 함수 호출 결과일 때는 `getList().at(-1)`이 임시 변수 없이 쓸 수 있어 간결합니다.
- `String`과 Typed Array에도 `at`이 있습니다(자세히는 33·48편).

## toSorted·toReversed·toSpliced·with

ES2023에서 추가된 네 메서드는 원본을 바꾸는 `sort`, `reverse`, `splice`, 인덱스 대입에 각각 대응하며 원본은 두고 바뀐 새 배열을 반환합니다.

| 원본 변경 | 복사본 반환 |
|-----------|-------------|
| `sort(compareFn)` | `toSorted(compareFn)` |
| `reverse()` | `toReversed()` |
| `splice(start, deleteCount, ...items)` | `toSpliced(start, deleteCount, ...items)` |
| `arr[i] = value` | `with(i, value)` |

```js
const a = [3, 1, 2]
a.toSorted()            // [1, 2, 3]
a.toReversed()          // [2, 1, 3]
a.toSpliced(1, 1, 'x')  // [3, 'x', 2]
a.with(0, 9)            // [9, 1, 2]
a                       // [3, 1, 2] (원본은 그대로)
```

- `toSorted`의 비교 함수는 `sort`와 같습니다. 비교 함수를 생략하면 요소를 문자열로 바꿔 비교하므로 `[10, 9, 1].toSorted()`는 `[1, 10, 9]`입니다(자세히는 29편).
- `toSpliced`는 `splice`와 인수가 같지만 제거된 요소가 아니라 바뀐 새 배열을 반환합니다. 제거된 요소는 얻을 수 없습니다.
- `with(index, value)`는 음수 인덱스를 지원합니다. `[3, 1, 2].with(-1, 'z')`는 `[3, 1, 'z']`입니다.
- `with`는 범위를 벗어난 인덱스에 `RangeError`를 던집니다. 인덱스 대입처럼 배열을 늘리지 않습니다.
- 이 네 메서드는 빈 슬롯을 `undefined` 요소로 채운 배열을 반환합니다. 결과가 희소 배열이 되지 않습니다.

```js
const h = [1, , 3]
h.toReversed()      // [3, undefined, 1]
h.toSpliced(0, 0)   // [1, undefined, 3]
h.with(0, 9)        // [9, undefined, 3]
```

- `toSorted`는 `undefined`와 빈 슬롯을 비교 함수 없이 맨 끝으로 보냅니다.
- 이전 환경에서는 이 메서드들이 없으므로 `[...arr].sort()`나 `arr.slice().reverse()`로 대체합니다.

## keys·values·entries

`keys()`, `values()`, `entries()`는 배열을 순회하는 이터레이터(Array Iterator 객체)를 반환합니다(ES2015). 배열이 아니라 `for...of`나 스프레드로 소비하는 이터레이터입니다(자세히는 35편).

| 메서드 | 순회하는 값 |
|--------|-------------|
| `keys()` | 인덱스 |
| `values()` | 요소 |
| `entries()` | `[인덱스, 요소]` 쌍 |

```js
const k = ['a', 'b']
const ks = [...k.keys()]       // [0, 1]
const vs = [...k.values()]     // ['a', 'b']
const es = [...k.entries()]    // [[0, 'a'], [1, 'b']]
for (const [i, v] of k.entries()) console.log(i, v)
// 0 a
// 1 b
```

- `Array.prototype[Symbol.iterator]`는 `values`와 같은 함수입니다. `for...of`가 요소를 얻는 이유입니다.
- 이터레이터는 값을 한 번에 만들지 않고 요청할 때 읽습니다. 이터레이터를 만든 뒤 순회를 마치기 전에 배열에 요소를 추가하면 그 요소도 순회됩니다.
- 세 메서드 모두 빈 슬롯을 `undefined`로 방문합니다. `[...[, 'a'].keys()]`는 `[0, 1]`입니다. `Object.keys`는 빈 슬롯을 건너뜁니다.
- 인덱스와 요소를 함께 쓰고 싶을 때 `entries()`와 디스트럭처링 조합이 `for` 문의 인덱스 변수를 대체합니다.

## 유사 배열 객체

유사 배열 객체(array-like object)는 `length` 프로퍼티와 0부터 시작하는 인덱스 프로퍼티를 가졌지만 `Array.prototype`을 상속하지 않는 객체입니다. `arguments`, DOM의 `NodeList`·`HTMLCollection`, 문자열의 인덱스 접근이 대표적입니다.

```js
const arrayLike = { 0: 'a', 1: 'b', length: 2 }
arrayLike[0]               // 'a'
arrayLike.length           // 2
Array.isArray(arrayLike)   // false
arrayLike.push             // undefined (배열 메서드가 없다)
```

유사 배열 객체를 배열처럼 다루는 방법은 두 가지입니다.

- 배열로 변환합니다: `Array.from(arrayLike)`. 이터러블이면 `[...arrayLike]`도 됩니다.
- 배열 메서드를 빌려 씁니다. 많은 배열 메서드는 `this`가 유사 배열 객체여도 동작합니다(`call`은 21편).

```js
Array.prototype.slice.call(arrayLike)  // ['a', 'b']
Array.prototype.map.call('abc', c => c.toUpperCase())
// ['A', 'B', 'C']
```

- 이터러블과 유사 배열 객체는 다른 개념입니다. 이터러블은 `Symbol.iterator`를 가진 객체입니다. `arguments`, `NodeList`는 둘 다이고, 위의 `arrayLike`는 유사 배열 객체이지만 이터러블이 아니라서 `[...arrayLike]`는 `TypeError`입니다.
- `Array.from`은 둘 다 받습니다. `Symbol.iterator`가 있으면 이터러블로, 없으면 유사 배열 객체로 처리합니다.
- `length`가 없으면 길이 0으로 취급해 `Array.from({ 0: 'a' })`는 `[]`입니다.
- `Array.isArray(arguments)`는 `false`입니다. 화살표 함수에는 자기 `arguments`가 없고, 새 코드에서는 나머지 매개변수가 대체합니다(자세히는 11·27편).

## 메서드별 빈 요소 처리

같은 희소 배열이라도 메서드마다 빈 슬롯을 다르게 처리합니다. 처리 방식은 다음 여덟 가지로 나뉩니다.

| 처리 방식 | 메서드 |
|-----------|--------|
| 건너뜀 (콜백·비교를 하지 않음) | `forEach`, `map`, `filter`, `some`, `every`, `reduce`, `reduceRight`, `flatMap`, `indexOf`, `lastIndexOf` |
| `undefined`로 방문 | `find`, `findIndex`, `findLast`, `findLastIndex`, `includes`, `keys`·`values`·`entries`, `Array.from`, 스프레드, `for...of` |
| 빈 슬롯 그대로 유지 | `concat`, `slice`, `splice`(옮겨지는 요소), `reverse`, `copyWithin`, `map`의 결과 |
| 제거 | `flat` |
| 맨 끝으로 모음 | `sort`: `undefined` 뒤에 빈 슬롯, 비교 함수는 호출하지 않는다 |
| `undefined` 요소로 채워 반환 | `toSorted`, `toReversed`, `toSpliced`, `with` |
| 빈 문자열 | `join` |
| 값으로 채움 | `fill` |

```js
const h = [1, , 3]
h.forEach(x => console.log(x))      // 1, 3 (두 번만 호출)
h.map(x => x * 2)                   // [2, <1 empty>, 6]
h.filter(() => true)                // [1, 3]
h.findIndex(x => x === undefined)   // 1 (빈 슬롯도 방문)
h.includes(undefined)               // true
h.indexOf(undefined)                // -1
Array.from(h)                       // [1, undefined, 3]
```

- 열거 쪽도 갈립니다. `Object.keys`와 `for...in`은 빈 슬롯의 인덱스를 건너뜁니다(자세히는 18편). `JSON.stringify`는 `null`로 바꿉니다(자세히는 39편).
- 모든 요소가 `undefined`로 채워진 배열이 필요하면 `Array.from(arr)`이나 `fill`로 먼저 빈 슬롯을 없앤 뒤 씁니다.
- 건너뛰는 메서드에서는 빈 슬롯 때문에 콜백 호출 횟수가 `length`보다 적을 수 있습니다. `reduce`에 초기값이 없으면 빈 슬롯이 아닌 첫 요소가 초기값이 됩니다.

## 핵심 정리

- 배열은 `length`와 인덱스 프로퍼티가 연동되는 객체이며, 대입하면 참조가 복사됩니다. `length`를 줄이면 요소가 잘리고, 늘리면 빈 슬롯이 생깁니다.
- 빈 슬롯은 `undefined` 값이 아니라 프로퍼티가 없는 칸입니다. `forEach`·`map`·`filter` 등은 건너뛰고 `find`·`includes`·스프레드는 `undefined`로 읽으므로 희소 배열을 만들지 않습니다.
- 원본을 바꾸는 메서드는 `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`, `copyWithin` 9개이고 반환값이 제각각입니다. 원본이 필요하면 `toSorted`, `toReversed`, `toSpliced`, `with`나 `slice`·`concat`을 씁니다.
- `indexOf`는 `===`로 비교해 `NaN`을 못 찾고, `includes`는 SameValueZero라서 찾습니다. `splice(indexOf(x), 1)`은 `-1`일 때 마지막 요소를 지웁니다.
- `fill`은 같은 참조를 모든 칸에 넣으므로 객체 칸에는 `Array.from`의 `mapFn`을 씁니다. 배열 판별은 `Array.isArray`, 유사 배열 객체의 변환은 `Array.from`입니다.
