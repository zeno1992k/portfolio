## 핵심 먼저 보기

- 모듈은 자기 스코프를 갖고 항상 strict mode로 실행되며, 최상위 `this`는 `undefined`이고, 한 번만 평가됩니다.
- named export는 여러 개, default export는 하나이며 이름이 `default`인 named export입니다. `export *`는 default를 넘기지 않고, 이름이 충돌하면 그 이름을 재공개하지 않습니다.
- import한 이름은 값 복사가 아니라 읽기 전용 라이브 바인딩이고, `import` 선언은 호이스팅되어 의존 모듈이 본문보다 먼저 실행됩니다.
- `import()`는 namespace 객체로 이행되는 프로미스를 반환하고, `import.meta`는 호스트가 채우는 메타데이터 객체입니다.
- JSON 모듈은 `with { type: 'json' }`로 가져오며(ES2025) default export만 있습니다. import defer는 3단계 제안입니다.

## 모듈의 개념과 모듈 스코프

**모듈**은 자기만의 스코프를 갖고, export한 것만 다른 파일에 보여 주는 코드 단위입니다. ES2015가 "파일 하나가 모듈 하나"인 문법을 표준에 넣었습니다. 이 문서에서 모듈은 ES 모듈(ESM)을 뜻합니다.

```js
// 일반 스크립트 (브라우저)
var total = 0
console.log(window.total) // 0

// 모듈
var total = 0
console.log(globalThis.total) // undefined
```

| 구분 | 일반 스크립트 | 모듈 |
|------|---------------|------|
| 최상위 `var`·함수 선언 | 전역 객체의 프로퍼티(브라우저) | 모듈 스코프에 머문다 |
| strict mode | 선택 | 항상 켜짐 |
| 최상위 `this` | 전역 객체 | `undefined` |
| `import`·`export` 문 | SyntaxError | 사용 가능 |
| 최상위 `await` | 사용 불가 | 사용 가능(ES2022, 43편) |
| 평가 횟수 | 로드할 때마다 | 한 번 |

## CommonJS·AMD·ESM

ES2015 이전의 언어에는 모듈이 없었고, 서로 다른 해결책이 쓰였습니다.

```js
const counter = (function () {
  let n = 0 // 클로저로 감춘 상태
  return { inc: () => ++n }
})()
counter.inc() // 1
```

| 항목 | CommonJS | ESM |
|------|----------|-----|
| 정체 | Node.js의 구현 | ECMA-262 문법 |
| 가져오는 방식 | `require()` 호출 시점에 동기 실행 | 실행 전에 의존 관계를 정적으로 파악 |
| 위치 | 어디서나, 조건부 가능 | `import` 선언은 최상위만 |
| 가져오는 대상 | `module.exports` 값의 복사 | 바인딩 참조(라이브) |
| 최상위 `this` | `module.exports` | `undefined` |
| 기본 모드 | sloppy | strict |
| 전용 변수 | `require`, `module`, `__dirname` | 없음(`import.meta`) |

## export

**export**는 모듈 안의 바인딩에 이름을 붙여 외부에 공개하는 선언입니다. 모듈 최상위에서만 쓸 수 있습니다.

## import

**import**는 다른 모듈이 공개한 바인딩을 현재 모듈 스코프의 이름으로 들여오는 선언입니다.

| 형태 | 구문 | 가져오는 것 |
|------|------|-------------|
| named | `import { a, b } from './m.js'` | 이름이 `a`, `b`인 export |
| default | `import x from './m.js'` | default export(이름은 자유) |
| namespace | `import * as ns from './m.js'` | 모든 export를 담은 객체 |
| 부수 효과 | `import './m.js'` | 없음. 모듈 실행만 |
| 조합 | `import x, { a } from './m.js'` | default와 named |
| 조합 | `import x, * as ns from './m.js'` | default와 namespace |

## named·default export

| 구분 | named export | default export |
|------|--------------|----------------|
| 모듈당 개수 | 여러 개 | 하나 |
| 가져오는 이름 | 공개된 이름 그대로(`as`로 변경) | 가져오는 쪽이 자유롭게 정함 |
| import 구문 | 중괄호 필요 | 중괄호 없음 |
| 이름 오타 | 링크 단계에서 SyntaxError | 발견되지 않음 |

default export의 형태는 네 가지입니다.

## namespace·alias import

**namespace import**(`import * as ns`)는 모듈의 모든 export를 프로퍼티로 가진 module namespace 객체를 만듭니다. default export는 `ns.default`입니다.

| 항목 | 값 |
|------|----|
| 프로토타입 | `null` |
| 키 | export 이름, 코드 유닛 순으로 정렬 |
| `Symbol.toStringTag` | `'Module'`, 즉 `[object Module]` |
| 프로퍼티 속성 | writable `true`, enumerable `true`, configurable `false` |
| 확장 | 불가 |
| 존재하지 않는 이름 | `undefined` |

## re-export

**re-export**는 다른 모듈의 export를 가져와 내 모듈의 export로 곧바로 내보내는 문법입니다. 여러 파일의 공개 API를 한 파일로 모을 때 씁니다.

| 구문 | 효과 |
|------|------|
| `export { a, b } from './m.js'` | `a`, `b`를 그대로 재공개 |
| `export { a as x } from './m.js'` | 이름을 바꿔 재공개 |
| `export { default } from './m.js'` | m의 default를 내 default로 |
| `export { default as Foo } from './m.js'` | m의 default를 named `Foo`로 |
| `export * from './m.js'` | m의 named export 전부(default 제외) |
| `export * as ns from './m.js'` | m의 namespace 객체를 `ns`로(ES2020) |

## Dynamic import

**동적 import**는 `import(지정자)` 형태로 모듈을 실행 중에 비동기로 불러오는 구문입니다. 해당 모듈의 namespace 객체로 이행되는 프로미스를 반환합니다(ES2020).

| 구분 | `import` 선언 | `import()` |
|------|---------------|------------|
| 위치 | 최상위만 | 어디서나 |
| 지정자 | 문자열 리터럴 | 임의의 표현식 |
| 시점 | 모듈 실행 전 | 호출한 시점 |
| 결과 | 바인딩 | namespace로 이행되는 프로미스 |
| 사용할 수 있는 코드 | 모듈 | 모듈, 일반 스크립트, CJS 파일 |

## import.meta

**`import.meta`**는 현재 모듈의 메타데이터를 담은 객체를 가리키는 메타 프로퍼티입니다(ES2020). ECMAScript는 이 객체의 존재만 정하고, 어떤 프로퍼티를 넣을지는 호스트가 정합니다.

| 프로퍼티 | 의미 | 제공 |
|----------|------|------|
| `url` | 모듈의 절대 URL 문자열(쿼리·해시 포함) | 브라우저, Node.js |
| `resolve(지정자)` | 지정자를 현재 모듈 기준 절대 URL로 해석해 문자열로 반환 | 브라우저, Node.js(20.0.0부터 동기) |
| `dirname`, `filename` | 모듈 파일의 디렉터리와 전체 경로 | Node.js 20.11, 21.2부터 |

## import attributes와 JSON 모듈

**import attributes**는 `with { 키: '값' }` 형태로 모듈 요청에 정보를 덧붙이는 구문이고, **JSON 모듈**은 이 구문으로 `.json` 파일을 모듈로 가져오는 기능입니다. 둘 다 ES2025에 포함됐습니다.

## 라이브 바인딩

ESM import는 export 바인딩의 현재 값을 읽습니다. import한 이름 자체를 재할당할 수는 없지만, export한 객체의 변경까지 금지되는 것은 아닙니다. 순환 import에서 초기화 전 바인딩을 읽으면 TDZ 오류가 날 수 있습니다.

## import 호이스팅과 읽기 전용

**import 호이스팅**은 `import` 선언이 코드 위치와 관계없이 모듈 본문보다 먼저 처리된다는 규칙입니다.

## 모듈의 자동 strict와 최상위 this

모듈 코드는 `'use strict'`가 없어도 항상 strict mode로 실행되고, 끌 수 없습니다(strict mode는 19편).

| 항목 | 일반 스크립트(sloppy) | 모듈(strict) |
|------|-----------------------|--------------|
| 선언 없는 변수에 대입 | 전역 변수가 생긴다 | ReferenceError |
| 읽기 전용 프로퍼티에 대입 | 조용히 무시 | TypeError |
| `with` 문 | 허용 | SyntaxError |
| 중복된 매개변수 이름 | 허용 | SyntaxError |
| 일반 함수 호출의 `this` | 전역 객체 | `undefined` |
| 8진수 리터럴 `010` | 8 | SyntaxError |

## 부수 효과 import

**부수 효과 import**는 바인딩을 가져오지 않고 모듈을 실행하기 위해서만 쓰는 `import` 선언입니다.

## import defer 제안 상태

**import defer**는 모듈을 로드하되, 평가(최상위 코드 실행)는 그 모듈의 export에 처음 접근할 때까지 미루는 import 구문 제안입니다. TC39 3단계(Stage 3)이며 아직 ECMAScript 표준이 아닙니다.

| 구분 | 정적 import | `import defer` | `import()` |
|------|-------------|----------------|------------|
| 로드 | 시작 시 | 시작 시 | 호출 시 |
| 평가 | 시작 시 | 첫 접근 시 | 호출 시 |
| 사용하는 코드 | 동기 | 동기 | 비동기(`await`) |
