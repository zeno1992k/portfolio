## 핵심 먼저 보기

- 문법은 트랜스파일러가 빌드 때 변환하고, API는 폴리필이 런타임에 채웁니다. `Proxy`와 BigInt는 어느 쪽으로도 완전히 대체되지 않습니다.
- Browserslist 쿼리 하나가 Babel·webpack·SWC·Vite 플러그인의 공통 타깃입니다. `not dead`를 함께 쓰고 데이터베이스를 갱신합니다.
- Babel 7은 `useBuiltIns`(`usage`·`entry`)로 core-js를 주입하고, Babel 8은 이를 제거하고 `babel-plugin-polyfill-corejs3`를 씁니다. `corejs`는 소수 버전까지 적습니다.
- 번들러는 모듈 그래프를 묶고, 트리 셰이킹은 ESM에서 쓰지 않는 export를 지우며, 코드 스플리팅은 동적 `import()`로 청크를 나눕니다. 소스맵은 변환된 위치를 원본으로 되돌립니다.
- Vite는 개발에서 번들하지 않고, 빌드에서는 Vite 8 기준 Rolldown으로 묶으며 기본 `build.target`은 Baseline widely available입니다.
- 타깃이 높으면 구형 환경에서 파일 전체가 죽고, 낮으면 번들이 커집니다. 실제 사용자 통계와 Baseline으로 정합니다.

## 트랜스파일러·폴리필·번들러의 역할

트랜스파일러는 문법 변환, 폴리필은 없는 런타임 기능 보충, 번들러는 모듈 그래프를 배포 파일로 묶는 일을 합니다. 소스맵은 변환된 코드의 위치를 원본에 연결합니다. 이 역할들을 한 도구가 함께 수행하기도 합니다.

## 문법 변환과 폴리필의 차이

문법 변환은 구형 엔진이 파싱하지 못하는 **문법**을 파싱할 수 있는 문법으로 바꾸는 일이고, 폴리필은 구형 엔진에 없는 **API**를 코드로 채우는 일입니다.

| 구분 | 문법 변환 | 폴리필 |
|------|-----------|--------|
| 대상 | `?.` `??` `class` `#private` `async` 같은 문법 | `Promise` `includes` `Object.hasOwn` 같은 내장 객체·메서드 |
| 시점 | 빌드 때 소스를 바꾼다 | 실행 때 전역에 값을 채운다 |
| 하는 도구 | 트랜스파일러 | core-js 같은 라이브러리 |
| 안 하면 | 파싱 단계에서 SyntaxError, 파일 전체가 실행되지 않는다 | 해당 줄을 실행할 때 TypeError |

```js
// 입력
const a = (x) => x ?? 1

// 대상 IE 11로 변환한 결과 (문법 변환)
var a = function a(x) {
  return x !== null && x !== void 0 ? x : 1;
};
```

## Browserslist

Browserslist는 지원할 브라우저 목록을 쿼리 문자열로 적는 공용 설정입니다. 한 번 적어 두면 Babel의 preset-env, Autoprefixer, webpack, SWC, `@vitejs/plugin-legacy` 같은 도구가 같은 목록을 읽습니다.

```json
{
  "browserslist": [
    "> 0.5%",
    "last 2 versions",
    "not dead"
  ]
}
```

| 쿼리 | 뜻 |
|------|----|
| `> 0.5%` | 전 세계 사용률이 0.5퍼센트를 넘는 브라우저 버전 |
| `last 2 versions` | 브라우저마다 최근 2개 버전 |
| `last 2 chrome versions` | Chrome의 최근 2개 버전 |
| `Firefox ESR` | Firefox 장기 지원판 |
| `dead` | 공식 지원이 끝난 지 24개월 넘은 브라우저 |
| `fully supports es6-module` | 해당 기능을 완전히 지원하는 브라우저 |
| `baseline widely available` | Baseline 널리 사용 가능 기준 (뒤의 Baseline 절 참조) |
| `since 2015`, `last 2 years` | 기간 기준 |

## Babel과 preset-env

Babel은 JavaScript를 파싱해 AST로 만들고, 플러그인이 AST를 바꾼 뒤, 다시 코드로 출력하는 트랜스파일러입니다(AST는 01편 참조). 변환 하나가 플러그인 하나이고, 플러그인 묶음이 프리셋입니다.

| 옵션 | 기본값 | 뜻 |
|------|--------|----|
| `targets` | 지정 없으면 모든 ES2015+ 변환 | 대상 환경. 문자열(Browserslist 쿼리)·배열·객체 |
| `useBuiltIns` | `false` | 폴리필 주입 방식: `'usage'` `'entry'` `false` |
| `corejs` | `"3.0"` | 주입에 쓸 core-js 버전. 소수 버전까지 적는다 |
| `modules` | `"auto"` | ESM을 CommonJS 등으로 바꿀지. `false`면 유지 |
| `bugfixes` | `false` | 특정 엔진의 버그 때문에 변환하던 문법을 더 가까운 현대 문법으로 변환 |
| `shippedProposals` | `false` | 브라우저에 이미 출시된 3단계 이상 제안 문법 허용 |
| `browserslistEnv` | 없음 | 사용할 Browserslist 환경 이름 |

## 폴리필과 core-js

core-js는 ECMAScript 표준 라이브러리와 일부 웹 표준 API의 폴리필 모음입니다. 현재 3.x(npm 최신 3.50.0)입니다. Babel의 `useBuiltIns`와 `babel-plugin-polyfill-corejs3`가 주입하는 폴리필도 core-js입니다.

| 값 | 동작 |
|----|------|
| `false` | 폴리필을 넣지 않는다(기본) |
| `'entry'` | 진입점의 `import 'core-js/stable'` 한 줄을, 타깃에 필요한 개별 모듈 import로 치환한다 |
| `'usage'` | 파일에서 실제 사용한 기능 중 타깃에 필요한 것만 import로 추가한다 |

## Webpack과 babel-loader

webpack은 진입점(entry)에서 시작해 `import`·`require`를 따라 모듈 그래프를 만들고, 그래프를 청크(chunk) 단위로 묶어 출력하는 번들러입니다. 현재 주 버전은 5입니다.

## 소스맵

소스맵(source map)은 변환·번들·미니파이를 거친 코드의 위치를 원본 소스의 위치로 되돌려 주는 JSON 파일입니다. 이것이 없으면 디버거와 에러 스택에 번들 파일의 한 줄짜리 코드가 나옵니다.

| 필드 | 뜻 |
|------|----|
| `version` | 항상 `3` |
| `sources` | 원본 파일 목록 |
| `names` | 변환 중 이름이 바뀐 식별자의 원래 이름 목록 |
| `mappings` | 위치 대응 데이터를 인코딩한 문자열 |
| `file` | 이 맵이 설명하는 생성 파일 이름 (선택) |
| `sourceRoot` | 원본 경로의 기준 (선택) |
| `sourcesContent` | 원본 소스 내용 (선택) |
| `ignoreList` | 외부 코드로 취급할 파일의 인덱스 (선택) |

## 미니파이와 코드 스플리팅

미니파이는 동작을 유지하며 공백·이름·표현을 줄입니다. 코드 스플리팅은 필요한 코드를 나중에 받도록 청크를 나눕니다. 파일을 많이 나누기만 하면 요청·공유 의존성 비용이 늘 수 있으므로 실제 로딩 결과로 판단합니다.

## Vite와 네이티브 ESM

Vite는 개발 서버와 빌드 도구를 합친 프런트엔드 도구입니다. 개발 중에는 번들하지 않고 브라우저의 네이티브 ESM으로 파일을 제공하고, 배포 빌드는 번들러로 묶습니다. 현재 Vite 8(2026년 3월 12일 출시, 이 문서는 8.3 문서 기준)입니다.

| 옵션 | 기본값 | 뜻 |
|------|--------|----|
| `build.target` | `'baseline-widely-available'` | 문법 변환 기준. Chrome 111·Edge 111·Firefox 114·Safari 16.4 이상 |
| `build.minify` | `'oxc'` | `'terser'`·`'esbuild'`·`false`도 가능 |
| `build.cssMinify` | `'lightningcss'` | CSS 미니파이 |
| `build.sourcemap` | `false` | 소스맵 생성 여부 |
| `build.cssCodeSplit` | `true` | CSS도 청크별로 분리 |

## SWC·Oxc·Rolldown

Babel·webpack·Terser는 JavaScript로 작성되어 있어 느립니다. 같은 일을 Rust·Go로 다시 만든 도구가 이를 대체하고 있습니다.

| 도구 | 언어 | 역할 | 특징 |
|------|------|------|------|
| SWC | Rust | 변환·미니파이·번들 | `env.targets`로 타깃 지정. `mode`(`usage`·`entry`)와 `coreJs` 설정이 Babel의 `useBuiltIns`·`corejs`에 대응 |
| esbuild | Go | 변환·번들·미니파이 | 폴리필 없음. ES6+를 ES5로 변환하지 못함 |
| Oxc | Rust | 파서·변환기·미니파이어·리졸버·린터(Oxlint)·포매터(Oxfmt) | 문법을 ES2026에서 ES2015까지 낮춤. 변환 도우미는 `@oxc-project/runtime`에서 가져옴 |
| Rolldown | Rust | 번들러 | Rollup과 같은 플러그인 API. Vite 8의 번들러 |

## 번들러 비교

| 도구 | 구현 | 개발 방식 | 특징 |
|------|------|-----------|------|
| webpack | JavaScript | 전체 번들 후 제공 | 로더·플러그인 생태계가 가장 크다. 설정이 많다 |
| Rollup | JavaScript | 번들 | ESM 중심, 트리 셰이킹이 강하고 라이브러리 번들에 쓴다. Vite 플러그인 API의 기준 |
| esbuild | Go | 번들 | 매우 빠르다. 변환·미니파이 내장, 폴리필·ES5 변환 없음 |
| Vite | JavaScript(번들러는 Rolldown) | 비번들 네이티브 ESM | 빠른 시작과 HMR. 폴리필은 플러그인으로 |
| Rolldown | Rust | Vite 안에서 번들 | Rollup 호환 API와 esbuild급 속도를 목표 |
| Rspack | Rust | 전체 번들 후 제공 | webpack 설정·로더와 호환 |

선택 기준은 단순합니다.

## 타깃 선택과 Baseline

타깃은 "이 코드가 실행돼야 하는 가장 낮은 환경"입니다. 타깃이 정해지면 변환할 문법과 채울 폴리필이 정해집니다.

| 타깃이 | 결과 |
|--------|------|
| 너무 낮다 | 변환·폴리필이 늘어 번들이 커지고 실행이 느려진다 |
| 너무 높다 | 구형 엔진에서 SyntaxError로 파일 전체가 실행되지 않는다. API가 빠지면 호출 시점에 TypeError |
