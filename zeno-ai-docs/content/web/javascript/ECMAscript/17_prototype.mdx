## 객체지향과 상속

객체지향 프로그래밍(OOP)은 프로그램을 객체의 모음으로 보고, 상태(프로퍼티)와 그 상태를 다루는 동작(메서드)을 하나의 객체로 묶는 방식입니다. 대상에서 필요한 속성만 골라 객체로 나타내는 일을 추상화(abstraction)라고 합니다.

| 특성 | 뜻 | JavaScript의 구현 |
|------|----|-------------------|
| 추상화 | 필요한 속성과 동작만 골라 객체로 표현한다 | 객체 리터럴, 생성자 함수, 클래스 |
| 캡슐화 | 상태와 동작을 한 객체로 묶고 내부를 숨긴다 | 클로저(23편), private 필드(24편) |
| 상속 | 한 객체의 프로퍼티와 메서드를 다른 객체가 이어받는다 | 프로토타입 |
| 다형성 | 같은 이름의 메서드가 객체에 따라 다르게 동작한다 | 하위 객체의 메서드 오버라이딩 |

상속은 한 객체가 다른 객체의 프로퍼티와 메서드를 자기 것처럼 쓰는 관계이고, 목적은 코드 재사용입니다. JavaScript는 클래스가 아니라 객체가 객체를 직접 상속하는 프로토타입 기반 언어입니다.

| 구분 | 클래스 기반 (Java, C++) | 프로토타입 기반 (JavaScript) |
|------|------------------------|------------------------------|
| 상속 단위 | 클래스가 클래스를 상속 | 객체가 객체를 상속 |
| 객체 생성 | 클래스를 정의한 뒤 인스턴스화 | 리터럴로 바로 생성 가능 |
| 상속 관계 | 선언 시 고정 | 실행 중에 바꿀 수 있다 |

ES2015의 `class`는 프로토타입 상속을 클래스 문법으로 감싼 것이어서, 상속 구조는 이 편의 규칙을 그대로 따릅니다(자세히는 24편).

프로토타입이 필요한 이유는 생성자 함수 안에서 메서드를 만들어 보면 드러납니다.

```js
function Circle(radius) {
  this.radius = radius
  this.getArea = function () { // 인스턴스마다 새 함수
    return Math.PI * this.radius ** 2
  }
}
const a = new Circle(1)
const b = new Circle(2)
a.getArea === b.getArea // false
```

`new`를 호출할 때마다 함수 객체가 새로 만들어져 인스턴스 수만큼 메모리를 씁니다. 메서드를 프로토타입에 두면 하나를 모든 인스턴스가 공유합니다.

```js
function Circle(radius) { this.radius = radius }
Circle.prototype.getArea = function () {
  return Math.PI * this.radius ** 2
}
const a = new Circle(1)
const b = new Circle(2)
a.getArea === b.getArea // true
```

인스턴스마다 값이 달라지는 상태는 생성자에서 `this`에 만들고, 모든 인스턴스가 똑같이 쓰는 메서드는 프로토타입에 한 번만 만듭니다.

## `[[Prototype]]`과 `__proto__`

모든 객체는 내부 슬롯(internal slot) `[[Prototype]]`을 가집니다. 값은 객체 또는 `null`이고, 그 객체가 프로토타입, 곧 프로퍼티를 상속받는 대상입니다. 내부 슬롯은 명세 안에서만 존재하는 상태라서 `obj.[[Prototype]]`처럼 접근할 수 없고, 두 가지 방법으로 간접 접근합니다.

- `__proto__` 접근자 프로퍼티 (이 절)
- `Object.getPrototypeOf`·`Object.setPrototypeOf` (다음 절)

`__proto__`는 `Object.prototype`에 정의된 접근자 프로퍼티입니다. getter는 `[[Prototype]]`을 반환하고 setter는 `[[Prototype]]`을 바꿉니다.

```js
const obj = {}
obj.__proto__ === Object.prototype // true
Object.hasOwn(obj, '__proto__')    // false (상속)
```

모든 객체가 `__proto__`를 쓸 수 있는 것은 프로토타입 체인(뒤의 절)으로 `Object.prototype`을 상속하기 때문입니다. 이 접근자는 열거할 수 없고(`enumerable: false`) 재정의할 수 있습니다(`configurable: true`).

규칙은 다음과 같습니다.

- setter에 객체도 `null`도 아닌 값을 대입하면 아무 일도 일어나지 않습니다. 에러도 나지 않습니다.
- 순환이 생기면 TypeError(`Cyclic __proto__ value`)입니다. 체인 탐색이 끝나지 않기 때문입니다.
- 확장 불가 객체의 프로토타입은 바꿀 수 없습니다(자세히는 14편).

```js
const a = {}
a.__proto__ = 1   // 무시된다 (에러 없음)
const p = {}
const c = Object.create(p)
p.__proto__ = c   // TypeError: Cyclic __proto__ value
```

객체 리터럴 안의 `__proto__: 값`은 접근자 호출이 아니라 생성 시점에 `[[Prototype]]`을 정하는 문법입니다. 계산된 키 `['__proto__']`와 단축 프로퍼티 `{ __proto__ }`는 일반 프로퍼티를 만듭니다.

```js
const a = { __proto__: { hi: 1 } }
a.hi                           // 1 (프로토타입에서 상속)
const b = { ['__proto__']: 5 }
Object.hasOwn(b, '__proto__')  // true (일반 프로퍼티)
```

코드에서 `obj.__proto__`를 직접 읽고 쓰지 않는 이유는 두 가지입니다.

- 웹 호환을 위해 명세 부록 B(웹 브라우저를 위한 추가 기능)에 레거시로 정의된 기능이고, MDN은 deprecated로 표시합니다.
- `Object.create(null)`로 만든 객체는 `Object.prototype`을 상속하지 않아 `__proto__` 접근자가 없습니다. 이런 객체에 대입하면 프로토타입이 바뀌지 않고 일반 own 프로퍼티만 생깁니다.

프로토타입을 읽고 쓸 때는 다음 절의 메서드를 씁니다.

## `getPrototypeOf`·`setPrototypeOf`

`Object.getPrototypeOf(obj)`(ES5)는 `[[Prototype]]`을 반환하고, `Object.setPrototypeOf(obj, proto)`(ES2015)는 `[[Prototype]]`을 `proto`로 바꾼 뒤 `obj`를 반환합니다. 둘 다 명세 본문에 정의되어 있습니다.

```js
const parent = { hi() { return 'hi' } }
const child = {}
Object.setPrototypeOf(child, parent) // child를 반환
Object.getPrototypeOf(child) === parent // true
child.hi() // 'hi'
```

| 호출 | 결과 |
|------|------|
| `getPrototypeOf(원시 값)` | 래퍼 객체로 바꾼 뒤의 프로토타입. `getPrototypeOf(1) === Number.prototype` (ES5는 TypeError) |
| `getPrototypeOf(null)`, `getPrototypeOf(undefined)` | TypeError |
| `setPrototypeOf(obj, 객체 또는 null)` | 정상. `obj` 반환 |
| `setPrototypeOf(obj, 1)`, `setPrototypeOf(obj, undefined)` | TypeError. 두 번째 인수는 객체나 `null`뿐 |
| `setPrototypeOf(원시 값, proto)` | 아무 일도 없이 그 원시 값을 반환 |
| `setPrototypeOf(null, proto)` | TypeError |
| 확장 불가 객체에 다른 프로토타입 지정 | TypeError |
| 순환이 생기는 지정 | TypeError |
| `Object.prototype`에 `null`이 아닌 값 지정 | TypeError |

- `Object.prototype`은 프로토타입을 바꿀 수 없는 객체(immutable prototype exotic object)입니다. 지금과 같은 값(`null`)으로 지정하는 것만 통과합니다.
- 두 메서드는 `__proto__`와 달리 null 프로토타입 객체에도 동작하고 명세 본문에 있으므로, 코드에서는 이 메서드를 씁니다.
- `Reflect.getPrototypeOf`는 원시 값에 TypeError를 던지고, `Reflect.setPrototypeOf`는 TypeError 대신 `false`를 반환합니다(자세히는 47편).

## 함수 객체의 `prototype`

`prototype`은 함수 객체만 가지는 프로퍼티이고, 그 함수를 `new`로 호출해 만든 인스턴스의 `[[Prototype]]`이 될 객체를 가리킵니다. constructor만 가지며, 화살표 함수나 메서드 축약 표현 같은 non-constructor에는 없습니다(자세히는 15편).

```js
function Person() {}
const me = new Person()
Object.getPrototypeOf(me) === Person.prototype // true
me.__proto__ === Person.prototype              // true
const arrow = () => {}
arrow.prototype                                // undefined
```

`__proto__`와 `prototype`은 이름이 비슷하지만 다른 프로퍼티입니다.

| 구분 | `__proto__` | `prototype` |
|------|-------------|-------------|
| 가진 객체 | 모든 객체(상속한 접근자) | constructor인 함수 객체만 |
| 가리키는 것 | 그 객체 자신의 프로토타입 | `new`로 만들 인스턴스의 프로토타입 |
| 쓰는 주체 | 프로퍼티 탐색 시 엔진 | `new` 연산자 |
| 종류 | 접근자 프로퍼티 | 데이터 프로퍼티 |

- 일반 함수의 `prototype`은 `writable: true, enumerable: false, configurable: false`입니다. 클래스의 `prototype`은 `writable: false`라서 다른 객체로 교체할 수 없습니다.
- 함수도 객체이므로 함수 자신의 `__proto__`가 있고, 값은 `Function.prototype`입니다. `Person.__proto__`와 `Person.prototype`을 혼동하는 실수가 많습니다.

```js
function Person() {}
Person.__proto__ === Function.prototype // true
Person.prototype === Function.prototype // false
Person.prototype.__proto__ === Object.prototype // true
```

함수 객체의 다른 프로퍼티(`length`, `name` 등)는 16편에서 다룹니다.

## `constructor` 프로퍼티

`constructor`는 프로토타입 객체가 가진 프로퍼티이고, 그 프로토타입을 `prototype`으로 가진 생성자 함수를 가리킵니다. 함수가 만들어질 때 `prototype` 객체와 `constructor`가 함께 생기므로 둘은 서로를 가리키는 순환 구조입니다.

```js
function Person() {}
Person.prototype.constructor === Person // true
const me = new Person()
me.constructor === Person               // true (상속)
Object.hasOwn(me, 'constructor')        // false
```

- 어트리뷰트는 `writable: true, enumerable: false, configurable: true`입니다.
- 인스턴스에는 own `constructor`가 없습니다. 프로토타입에서 상속받은 값을 읽을 뿐입니다.
- 리터럴로 만든 값도 같은 방식으로 상속합니다.

| 값 | `constructor` |
|----|---------------|
| `{}` | `Object` |
| `[]` | `Array` |
| `function () {}` | `Function` |
| `/a/` | `RegExp` |
| `1` | `Number` (래퍼 객체를 거쳐 상속) |

- `Object.create(null)`로 만든 객체에는 `constructor`가 없습니다.
- `class`에서도 `Foo.prototype.constructor === Foo`입니다.

**흔한 실수:** `constructor`로 타입을 판별하는 것입니다. 일반 프로퍼티라서 덮어쓸 수 있고, 프로토타입을 교체하면 사라지며(뒤의 절), `constructor.name`은 번들러가 함수 이름을 줄이면 달라집니다. 판별에는 `instanceof`, `Array.isArray`를 씁니다.

## 프로토타입의 생성 시점

프로토타입은 생성자 함수와 함께 만들어집니다. 함수를 호출하거나 `new`를 쓰는 시점이 아니라 함수가 정의되는 시점입니다.

| 종류 | 프로토타입이 만들어지는 때 |
|------|----------------------------|
| 함수 선언문 | 스코프에 진입할 때 함수 객체와 함께 (코드 실행 전, 호이스팅) |
| 함수 표현식 | 표현식이 평가되어 함수 객체가 만들어질 때 |
| 클래스 | 클래스 정의가 평가될 때 |
| 빌트인 생성자 | 전역 객체가 만들어질 때, 곧 사용자 코드가 실행되기 전 |

```js
typeof Person.prototype // 'object' (선언 앞에서도 존재)
function Person() {}
```

- 함수 표현식은 변수에 할당하는 문장이 실행되어야 만들어지므로 그 앞에서는 쓸 수 없습니다.
- 빌트인 프로토타입(`Object.prototype`, `Array.prototype` 등)은 첫 줄이 실행될 때 이미 존재합니다. 체인의 종점인 `Object.prototype`의 `[[Prototype]]`은 `null`입니다.
- non-constructor는 `prototype` 객체를 만들지 않습니다. 화살표 함수의 `prototype`은 `undefined`입니다.
- 빌트인 프로토타입은 realm마다 따로 있습니다. realm은 전역 객체와 그에 딸린 빌트인 객체 집합이고, iframe이나 Node.js의 `vm` 컨텍스트가 각각 별도의 realm입니다(`instanceof` 절에서 영향을 다룹니다).

## 객체 생성 방식과 프로토타입 결정

객체를 만드는 방식마다 새 객체의 `[[Prototype]]`으로 들어가는 값이 정해져 있습니다.

| 생성 방식 | 새 객체의 `[[Prototype]]` |
|-----------|---------------------------|
| 객체 리터럴 `{}` | `Object.prototype` |
| `new Object()` | `Object.prototype` |
| 생성자 함수 `new F()` | `F.prototype` (정확히는 `new.target.prototype`) |
| `Object.create(proto)` | `proto` (직접 지정) |
| 클래스 `new C()` | `C.prototype` |
| 배열 리터럴, 정규식 리터럴 | `Array.prototype`, `RegExp.prototype` |
| 함수 (일반, 화살표) | `Function.prototype` |

```js
const getProto = Object.getPrototypeOf
function Person() {}
class C {}
const proto = { x: 1 }
getProto({}) === Object.prototype             // true
getProto(new Person()) === Person.prototype   // true
getProto(new C()) === C.prototype             // true
getProto(Object.create(proto)) === proto      // true
```

- async 함수는 `AsyncFunction.prototype`, 제너레이터 함수는 `GeneratorFunction.prototype`을 프로토타입으로 가집니다. 둘 다 체인을 따라가면 `Function.prototype`에 닿습니다.
- 생성자 함수의 `prototype`이 객체가 아니면 `Object.prototype`이 쓰입니다(자세히는 15편).

## 프로토타입 체인

프로토타입 체인(prototype chain)은 `[[Prototype]]`으로 이어진 객체의 연쇄입니다. 프로퍼티를 읽을 때 엔진은 이 연쇄를 따라 올라가며 찾습니다.

```js
function Person(name) { this.name = name }
Person.prototype.hi = function () {
  return 'hi ' + this.name
}
const me = new Person('Lee')
me.hi()       // 'hi Lee' (Person.prototype에서 발견)
me.toString() // '[object Object]' (Object.prototype)
me.nope       // undefined (끝까지 없음)
```

```text
me                 { name: 'Lee' }
  ↓ [[Prototype]]
Person.prototype   { constructor, hi }
  ↓ [[Prototype]]
Object.prototype   { toString, hasOwnProperty, ... }
  ↓ [[Prototype]]
null
```

프로퍼티를 읽는 규칙은 다음과 같습니다.

1. 객체 자신(own)에서 찾습니다. 있으면 그 값을 반환합니다(접근자면 getter를 호출).
2. 없으면 `[[Prototype]]`이 가리키는 객체에서 같은 과정을 반복합니다.
3. `null`에 도달하면 `undefined`를 반환합니다. 에러가 아닙니다.

- 존재하지 않는 프로퍼티를 읽으면 체인 전체를 끝까지 훑습니다.
- 상속한 메서드나 getter 안의 `this`는 프로토타입이 아니라 점 앞의 객체입니다(자세히는 21편).
- 읽기만 체인을 따라갑니다. 대입은 자기 객체에 합니다(다음 절).
- 프로퍼티 존재 확인(`in`, `Object.hasOwn`)과 열거(`for...in`)가 체인을 어떻게 다루는지는 18편에서 다룹니다.

체인의 종점은 보통 `Object.prototype`입니다. 모든 객체가 아래 프로퍼티를 쓸 수 있는 이유입니다.

| 프로퍼티 | 용도 |
|----------|------|
| `toString`, `toLocaleString`, `valueOf` | 문자열·원시 값 변환에 쓰임(자세히는 08편) |
| `hasOwnProperty`, `isPrototypeOf`, `propertyIsEnumerable` | 프로퍼티·체인 검사 |
| `constructor`, `__proto__` | 앞에서 다룬 두 프로퍼티 |
| `__defineGetter__`, `__defineSetter__`, `__lookupGetter__`, `__lookupSetter__` | 레거시. 쓰지 않는다 |

빌트인 값의 체인은 다음과 같습니다.

| 값 | 체인 |
|----|------|
| `[]` | `Array.prototype` → `Object.prototype` → `null` |
| `function () {}` | `Function.prototype` → `Object.prototype` → `null` |
| `new Date()` | `Date.prototype` → `Object.prototype` → `null` |
| 문자열 원시 값의 메서드 호출 (`'abc'.trim()`) | 임시 래퍼 객체 → `String.prototype` → `Object.prototype` (자세히는 20편) |

`Object`와 `Function`도 함수 객체이므로 `Function.prototype`을 상속하고, `Function.prototype`은 `Object.prototype`을 상속합니다. 그 결과 `Function`은 자기 자신의 인스턴스이기도 합니다.

```js
Object.__proto__ === Function.prototype   // true
Function.__proto__ === Function.prototype // true
Object instanceof Function                // true
Function instanceof Function              // true
Function instanceof Object                // true
```

프로퍼티 탐색에 쓰는 프로토타입 체인과 식별자(변수) 탐색에 쓰는 스코프 체인(자세히는 12편)은 별개입니다. `x`는 스코프 체인에서, `obj.x`의 `x`는 프로토타입 체인에서 찾고, 둘은 서로 영향을 주지 않습니다.

## 오버라이딩과 섀도잉

프로토타입에 있는 프로퍼티와 같은 이름의 프로퍼티를 인스턴스에 정의하면, 읽을 때 인스턴스의 것이 먼저 발견되어 프로토타입의 것을 가립니다. 이 현상이 섀도잉(shadowing)이고, 메서드를 이렇게 다시 정의하는 일이 오버라이딩(overriding)입니다. 가려진 프로토타입 프로퍼티는 지워지지 않고 그대로 남습니다.

```js
function Person(name) { this.name = name }
Person.prototype.hi = function () {
  return 'hi ' + this.name
}
const me = new Person('Lee')

me.hi = function () { return 'yo' } // me의 own 프로퍼티
me.hi()                // 'yo'
delete me.hi           // own 프로퍼티만 삭제
me.hi()                // 'hi Lee' (다시 보임)
```

- 대입은 체인을 따라가지 않고 객체 자신에 own 프로퍼티를 만들거나 갱신합니다.
- 하위 객체에서는 프로토타입의 프로퍼티를 바꾸거나 지울 수 없습니다. `delete me.hi`는 `me`의 own 프로퍼티만 지웁니다. 프로토타입 쪽을 바꾸려면 `Person.prototype.hi = ...`, `delete Person.prototype.hi`처럼 프로토타입을 직접 가리켜야 하고, 그 변경은 모든 인스턴스에 즉시 반영됩니다.
- `me.count++`처럼 읽고 쓰는 연산은 프로토타입의 값을 읽어 `me`에 own 프로퍼티로 씁니다. 프로토타입의 값은 그대로입니다.
- 예외: 체인에 읽기 전용 데이터 프로퍼티(`writable: false`)가 있으면 대입이 막힙니다. 비엄격 모드에서는 조용히 무시되고, 엄격 모드에서는 TypeError입니다. setter가 있는 접근자라면 own 프로퍼티를 만드는 대신 setter가 호출됩니다(자세히는 14편).

```js
const base = {}
Object.defineProperty(base, 'k', { value: 1 })
const child = Object.create(base)
child.k = 2
child.k // 1 (비엄격: 무시, 엄격: TypeError)
```

- 오버라이딩한 메서드 안에서 프로토타입의 원래 메서드를 부르려면 `Person.prototype.hi.call(this)`처럼 직접 호출합니다. 클래스에서는 `super`를 씁니다(자세히는 25편).

**흔한 실수:** 프로토타입에 배열이나 객체를 두는 것입니다. 읽기는 프로토타입의 값을 돌려주므로 한 인스턴스에서 바꾼 내용이 모든 인스턴스에 보입니다.

```js
Person.prototype.tags = []
const a = new Person('a')
const b = new Person('b')
a.tags.push('x') // 읽기 → 프로토타입의 배열을 변경
b.tags           // ['x'] (공유됨)
a.tags = ['own'] // 대입 → a에 own 프로퍼티 생성
b.tags           // ['x'] (프로토타입의 것)
```

이 섀도잉은 같은 이름의 변수가 바깥 스코프의 변수를 가리는 스코프 섀도잉(12편)과 이름만 같은 별개의 현상입니다.

## 프로토타입 교체

프로토타입은 실행 중에 다른 객체로 바꿀 수 있습니다. 바꾸는 곳은 두 군데입니다. 생성자 함수의 `prototype`에 새 객체를 대입하면 그 뒤에 만드는 인스턴스부터 영향을 받고, 인스턴스에 `Object.setPrototypeOf`를 쓰면 그 인스턴스만 영향을 받습니다.

### 생성자 함수의 `prototype` 교체

```js
function Person(name) { this.name = name }
Person.prototype = {
  hi() { return 'hi ' + this.name },
}
const me = new Person('Lee')
me.hi()                   // 'hi Lee'
me.constructor === Person // false
me.constructor === Object // true
```

교체한 객체 리터럴에는 `constructor`가 없어서, 탐색이 체인 위쪽의 `Object.prototype.constructor`까지 올라갑니다. 복구하려면 `constructor`를 직접 정의해야 합니다. 리터럴에 `constructor: Person`이라고 쓰면 열거 가능(`enumerable: true`)한 프로퍼티가 되어 `for...in`에 나타나므로, 원래 어트리뷰트대로 `defineProperty`를 씁니다.

```js
Object.defineProperty(Person.prototype, 'constructor', {
  value: Person,
  writable: true,
  configurable: true, // enumerable은 생략하면 false
})
```

교체 전에 만든 인스턴스는 옛 프로토타입에 연결된 채 남습니다. 같은 생성자로 만들었어도 서로 다른 프로토타입을 갖게 됩니다.

```js
const a = new Person('a')            // 교체 전
Person.prototype = { hi() {} }
const b = new Person('b')            // 교체 후
a instanceof Person // false (새 prototype이 a의 체인에 없음)
b instanceof Person // true
```

### 인스턴스의 프로토타입 교체

```js
const parent = { hi() { return 'parent' } }
Object.setPrototypeOf(me, parent)
me.hi()                   // 'parent'
me instanceof Person      // false
me.constructor === Person // false
```

`me`의 체인이 `parent` → `Object.prototype`으로 바뀌어 `Person.prototype`이 빠집니다. `Person`과 `Person.prototype`의 연결은 그대로이고 `me`와의 연결만 끊어진 상태입니다.

- 교체하지 않고 기존 `Person.prototype` 객체에 메서드를 추가하면 `constructor`가 유지되고 기존 인스턴스에도 반영됩니다.
- 인스턴스의 프로토타입을 나중에 바꾸는 방식은 성능 문제가 있습니다(뒤의 `setPrototypeOf` 성능 절).
- 상속 관계를 만들 때는 직접 상속(`Object.create`), 생성자 함수 상속 패턴, 클래스 `extends`를 씁니다.

## `instanceof`

`instanceof`는 `객체 instanceof 생성자` 형태로 쓰고, 우변의 `prototype`이 좌변의 프로토타입 체인 어딘가에 있으면 `true`입니다.

```js
function Person() {}
const me = new Person()
me instanceof Person // true
me instanceof Object // true (체인에 Object.prototype)
me instanceof Array  // false
```

`obj instanceof C`의 동작 순서입니다.

1. `C`가 객체가 아니면 TypeError입니다.
2. `C`에 `Symbol.hasInstance` 메서드가 있으면 `C[Symbol.hasInstance](obj)`를 호출하고, 결과를 불리언으로 바꿔 반환합니다. 모든 함수는 `Function.prototype`에서 기본 구현을 상속하므로 보통 3번으로 이어집니다. 메서드가 없으면 `C`는 호출 가능한 함수여야 하고, 아니면 TypeError입니다.
3. 기본 구현은 먼저 `C`가 바운드 함수인지 확인해 맞으면 원래 함수로 검사합니다. 좌변이 객체가 아니면 `false`입니다.
4. `C.prototype`이 객체가 아니면 TypeError입니다. 객체이면 좌변의 체인을 `null`까지 오르며 `C.prototype`과 같은 객체가 있는지 찾습니다.

기본 구현을 직접 쓰면 다음과 같습니다.

```js
function isInstanceOf(obj, ctor) {
  if (Object(obj) !== obj) return false // 원시 값
  let proto = Object.getPrototypeOf(obj)
  while (proto !== null) {
    if (proto === ctor.prototype) return true
    proto = Object.getPrototypeOf(proto)
  }
  return false
}
```

- 비교 대상은 우변의 `prototype` 프로퍼티입니다. `constructor` 프로퍼티는 보지 않습니다.
- 좌변이 원시 값이면 `false`입니다. `'a' instanceof String`은 `false`이고, `new String('a') instanceof String`은 `true`입니다.
- 우변 함수에 `prototype`이 없으면 TypeError입니다. 화살표 함수가 그 예입니다(V8의 메시지는 `Function has non-object prototype 'undefined' in instanceof check`).
- `Object.create(null)`로 만든 객체는 `instanceof Object`가 `false`입니다.
- 우변의 `prototype`을 교체하면 이미 만든 인스턴스의 결과가 바뀝니다(앞의 프로토타입 교체 절).
- 바운드 함수는 `prototype`이 없어서 원래 함수의 `prototype`으로 검사합니다. 함수 `Foo`가 있을 때 `new Foo() instanceof Foo.bind(null)`은 `true`입니다.

realm이 다르면 같은 이름의 빌트인도 다른 객체입니다. 다른 realm에서 온 배열은 이쪽의 `Array.prototype`을 상속하지 않습니다.

```js
const vm = require('node:vm')
const ctx = vm.createContext({})
const other = vm.runInContext('[]', ctx)
other instanceof Array // false (다른 realm)
Array.isArray(other)   // true
```

**흔한 실수:** `instanceof`를 "이 생성자로 만들었는가"로 읽는 것입니다. 실제로 묻는 것은 "체인에 `prototype`이 있는가"이므로 자식 클래스의 인스턴스는 부모 클래스에도 `true`입니다. 정확히 그 생성자의 인스턴스인지 확인하려면 `Object.getPrototypeOf(x) === F.prototype`을 씁니다.

## `Object.create`와 직접 상속

`Object.create(proto, descriptors)`는 `[[Prototype]]`이 `proto`인 새 객체를 만들어 반환합니다(ES5). 생성자 함수와 `new` 없이 객체가 객체를 직접 상속하게 만듭니다.

```js
const animal = { eat() { return 'eat' } }
const dog = Object.create(animal)
dog.eat()                    // 'eat'
animal.isPrototypeOf(dog)    // true
Object.keys(dog)             // [] (own 프로퍼티는 없다)
```

두 번째 인수는 `Object.defineProperties`와 같은 형식의 디스크립터 맵이고, 생략한 어트리뷰트는 `false`입니다(자세히는 14편).

```js
const dog = Object.create(animal, {
  name: { value: 'Rex', enumerable: true },
})
dog.name       // 'Rex'
dog.name = 'x' // 무시됨 (writable이 false)
```

직접 상속하는 방법은 세 가지입니다.

| 방법 | 코드 | 특징 |
|------|------|------|
| `Object.create` | `Object.create(animal)` | 만든 뒤 프로퍼티를 따로 추가 |
| 리터럴의 `__proto__` | `{ __proto__: animal, name: 'Rex' }` | 생성과 상속을 한 번에 (ES2015) |
| `setPrototypeOf` | `Object.setPrototypeOf(obj, animal)` | 이미 있는 객체에 적용. 느림 |

- `proto`는 객체 또는 `null`이어야 합니다. 인수를 생략하거나 원시 값을 넘기면 TypeError입니다.
- 생성자 함수를 호출하지 않고 프로토타입만 연결할 수 있어서, 생성자 함수 상속 패턴이 `Object.create(Parent.prototype)`을 씁니다(마지막 절).
- `null`을 넘겨 null 프로토타입 객체를 만드는 것도 `Object.create`입니다(뒤의 절).
- 연결이지 복사가 아닙니다. 나중에 `animal`에 추가한 프로퍼티도 `dog`에서 바로 보입니다.
- 상속받은 프로퍼티는 own이 아니라서 `Object.keys`, `JSON.stringify`, 스프레드 `{ ...dog }`에서 제외됩니다. `for...in`은 상속된 열거 가능 프로퍼티까지 순회합니다(자세히는 18편).
- `Object.create(Object.prototype)`은 `{}`와 같은 프로토타입을 가진 객체를 만듭니다.

## 정적 프로퍼티·메서드

정적(static) 프로퍼티·메서드는 생성자 함수 객체 자신에 붙은 프로퍼티와 메서드입니다. 인스턴스를 만들지 않고 `Person.isPerson()`처럼 호출합니다.

```js
function Person(name) { this.name = name }
Person.prototype.sayHi = function () { // 프로토타입 메서드
  return 'hi ' + this.name
}
Person.isPerson = function (v) {       // 정적 메서드
  return v instanceof Person
}
const me = new Person('Lee')
me.sayHi()          // 'hi Lee'
Person.isPerson(me) // true
me.isPerson         // undefined
```

인스턴스의 체인(`me` → `Person.prototype` → `Object.prototype`)에는 `Person` 함수 자신이 없으므로 정적 멤버는 인스턴스에서 접근할 수 없습니다. `me.isPerson()`은 TypeError입니다.

| 구분 | 프로토타입 메서드 | 정적 메서드 |
|------|-------------------|-------------|
| 정의 위치 | `Person.prototype` | `Person` 자체 |
| 호출 | `인스턴스.메서드()` | `생성자.메서드()` |
| `this` | 점 앞의 인스턴스 | 점 앞의 생성자 함수 |
| 용도 | 인스턴스의 상태를 다룬다 | 상태와 무관한 유틸리티, 팩토리 |
| 표기 관례 | `Person#sayHi` | `Person.isPerson` |

- 빌트인도 같은 구분입니다. `Object.keys`, `Array.isArray`, `Number.isNaN`, `Math.max`, `Date.now`, `Promise.all`은 정적 메서드이고, `Array.prototype.push`, `Object.prototype.hasOwnProperty`는 프로토타입 메서드입니다.
- 인스턴스 상태(`this`)를 쓰지 않는 메서드는 정적 메서드로 둘 수 있습니다.
- 생성자 함수 상속에서는 정적 멤버가 자동으로 상속되지 않습니다. 클래스의 `extends`는 자식 클래스의 `[[Prototype]]`을 부모 클래스로 연결해 정적 멤버도 상속합니다(자세히는 25편).
- `static` 키워드로 정의하는 클래스의 정적 멤버는 24편에서 다룹니다.

## null 프로토타입 객체

null 프로토타입 객체는 `[[Prototype]]`이 `null`이라서 `Object.prototype`을 포함한 어떤 프로퍼티도 상속하지 않는 객체입니다. 체인이 시작하자마자 끝납니다. 만드는 방법은 세 가지입니다.

```js
const a = Object.create(null)
const b = { __proto__: null }
const c = Object.setPrototypeOf({}, null) // 느림. 비권장
```

상속이 없어서 일반 객체와 다르게 동작하는 부분입니다.

```js
const a = Object.create(null)
a.toString          // undefined
'toString' in a     // false
a instanceof Object // false
typeof a            // 'object'
String(a)           // TypeError (변환 메서드가 없다)
a.hasOwnProperty('x') // TypeError (함수가 아님)
Object.hasOwn(a, 'x') // false
```

- `toString`, `valueOf`, `Symbol.toPrimitive`가 모두 없어서 문자열·숫자 변환이 TypeError입니다(자세히는 08편).
- `hasOwnProperty` 같은 메서드를 점 표기로 호출할 수 없으므로 `Object.hasOwn`을 씁니다.
- Node.js는 이런 객체를 `[Object: null prototype] { ... }`로 출력합니다.

용도는 키가 충돌하지 않는 사전(dictionary)입니다. 일반 객체에서는 `constructor`, `toString` 같은 키가 상속된 값을 돌려줍니다.

```js
const plain = {}
plain['constructor'] // [Function: Object] (상속된 값)
const dict = Object.create(null)
dict['constructor']  // undefined
dict['__proto__'] = 1 // 일반 own 프로퍼티
```

- 표준에도 쓰입니다. `Object.groupBy`(ES2024)의 반환값과 정규식 결과의 `groups`는 null 프로토타입 객체입니다(자세히는 18편, 32편).
- 키-값 저장소가 목적이라면 `Map`도 선택지입니다(자세히는 38편).
- 외부 라이브러리가 `obj.hasOwnProperty(...)`나 문자열 변환을 호출하면 에러가 나므로, 외부로 넘기는 객체에는 쓰지 않는 편이 안전합니다.

## `Symbol.hasInstance`

`Symbol.hasInstance`는 `instanceof`의 동작을 바꾸는 내장 심벌입니다(ES2015). `obj instanceof C`는 `C[Symbol.hasInstance](obj)`를 호출하고 결과를 불리언으로 바꿔 사용합니다. 심벌은 34편에서 다룹니다.

```js
class Even {
  static [Symbol.hasInstance](n) { return n % 2 === 0 }
}
2 instanceof Even // true
3 instanceof Even // false
```

프로토타입 체인과 무관하게 임의의 조건으로 판정할 수 있습니다. 구조가 같으면 인스턴스로 보는 덕 타이핑(duck typing) 검사가 대표적입니다.

```js
class Duck {
  static [Symbol.hasInstance](o) {
    return typeof o?.quack === 'function'
  }
}
({ quack() {} }) instanceof Duck // true
```

- 우변이 함수일 필요가 없습니다. `Symbol.hasInstance` 메서드를 가진 객체이면 됩니다. `5 instanceof { [Symbol.hasInstance]: () => true }`는 `true`입니다.
- 모든 함수는 `Function.prototype[Symbol.hasInstance]`를 상속합니다. 이 기본 구현은 프로토타입 체인 검사를 합니다. 어트리뷰트는 `writable`, `enumerable`, `configurable`이 모두 `false`입니다.
- 기본 구현이 읽기 전용이라 함수에 `F[Symbol.hasInstance] = ...`로 대입하면 비엄격 모드에서는 무시되고 엄격 모드에서는 TypeError입니다(자세히는 14편). 함수에는 `Object.defineProperty`를 쓰고, 클래스에는 `static` 메서드로 정의합니다.

```js
function F() {}
Object.defineProperty(F, Symbol.hasInstance, {
  value: (v) => typeof v === 'number',
})
1 instanceof F   // true
'a' instanceof F // false
```

## 프로토타입 오염

프로토타입 오염(prototype pollution)은 `Object.prototype` 같은 공유 프로토타입에 프로퍼티를 몰래 추가해, 그것을 상속하는 모든 객체에 영향을 주는 공격입니다.

```js
const obj = {}
obj.__proto__.isAdmin = true // Object.prototype에 추가
const other = {}
other.isAdmin                // true (모든 객체가 상속)
```

정상 코드는 이렇게 쓰지 않습니다. 공격자가 제어하는 문자열이 객체의 키로 들어갈 때 일어납니다. 대표적인 취약 패턴은 재귀 병합(deep merge), 경로 문자열로 값을 설정하는 함수(`set(obj, 'a.b', v)`), 파싱한 JSON이나 쿼리 문자열을 기존 객체에 합치는 코드입니다.

```js
function merge(target, source) {
  for (const key in source) {
    const value = source[key]
    if (value && typeof value === 'object') {
      merge(target[key] ??= {}, value)
    } else {
      target[key] = value
    }
  }
}
const evil = JSON.parse('{"__proto__":{"admin":true}}')
merge({}, evil)
const fresh = {}
fresh.admin // true
```

- `JSON.parse`는 `__proto__` 키를 접근자 호출 없이 일반 own 프로퍼티로 만듭니다(자세히는 39편). `for...in`이 그 키를 순회합니다.
- `target['__proto__']`는 상속받은 getter 때문에 `Object.prototype`을 반환하므로, 재귀 호출이 `Object.prototype`에 `admin`을 씁니다.
- `{"constructor":{"prototype":{...}}}`도 같은 결과입니다. `target['constructor']`는 `Object`이고 그 `prototype`이 `Object.prototype`이기 때문입니다.
- `Object.assign(target, parsed)`는 대입으로 복사하므로 `__proto__` 키가 setter를 호출해 `target` 하나의 프로토타입을 바꿉니다. `Object.prototype`은 오염되지 않습니다. 스프레드 `{ ...parsed }`는 own 프로퍼티로 복사하므로 프로토타입을 바꾸지 않습니다.

공격은 두 단계입니다. 프로토타입에 값을 넣는 오염 단계, 그리고 애플리케이션이 그 값을 읽는 코드(예: `if (user.isAdmin)`)에서 쓰이는 악용 단계입니다. 결과는 권한 검사 우회 같은 논리 오류나 XSS 같은 2차 공격입니다.

방어는 다음과 같습니다.

- 키 걸러내기: `__proto__`, `constructor`, `prototype`을 키로 받지 않습니다.
- own 프로퍼티만 사용하기: `Object.hasOwn(obj, key)`로 확인하고, 열거는 `for...in` 대신 `Object.keys`를 씁니다.
- 병합 대상과 사전을 null 프로토타입 객체나 `Map`으로 만들어 상속 자체를 없앱니다.
- 입력 스키마를 검증해 알 수 없는 키를 거부합니다.
- 내장 프로토타입 동결: `Object.freeze(Object.prototype)`. 동결하면 `Object.prototype`에 대한 쓰기가 막힙니다(비엄격 모드에서는 조용히 무시). 부작용으로 일반 객체에 `toString` 같은 상속된 이름으로 대입하는 것도 같은 방식으로 막힙니다(읽기 전용 상속 프로퍼티 규칙).
- Node.js의 `--disable-proto=delete` 또는 `throw`(v12.17.0, v13.12.0에서 추가): `Object.prototype.__proto__`를 없애거나 접근 시 에러를 던집니다. `constructor.prototype` 경로는 막지 못합니다.

**흔한 실수:** 오염의 원인을 `__proto__` 하나로만 알고 있는 것입니다. `constructor.prototype` 경로도 같은 결과를 만듭니다.

내장 프로토타입에 직접 메서드를 추가하는 것(`Array.prototype.myMethod = ...`)도 공유 객체를 바꾸는 일이라 비슷한 위험이 있습니다. 나중에 표준에 같은 이름의 메서드가 다른 동작으로 들어오면 충돌합니다. 새 기능을 구형 환경에 채우는 폴리필만 정당한 예외입니다.

## `setPrototypeOf`의 성능 비용

객체를 만든 뒤 `Object.setPrototypeOf`나 `__proto__` 대입으로 프로토타입을 바꾸면 느립니다. 엔진은 프로퍼티 접근을 객체의 구조와 프로토타입이 바뀌지 않는다는 가정 위에서 최적화하는데, 프로토타입을 바꾸면 그 가정에 기댄 최적화가 무효가 되어 코드가 재컴파일(역최적화)될 수 있기 때문입니다. 비용은 호출한 줄에서 끝나지 않고, 프로토타입이 바뀐 객체를 다루는 모든 코드로 퍼질 수 있습니다(MDN).

규칙은 프로토타입을 만드는 순간에 정하는 것입니다.

| 방법 | 예 |
|------|----|
| `Object.create` | `Object.create(proto)` |
| 리터럴 `__proto__` | `{ __proto__: proto }` |
| 생성자 함수 | `new F()` (`F.prototype`을 사용) |
| 클래스 | `class B extends A` |

- 정말 필요하면 객체를 만든 직후 한 번만 호출합니다.
- 정확한 비용은 엔진과 버전마다 다르므로, 수치로 단정하지 않고 필요할 때 측정합니다.
- 생성자 함수 상속 패턴은 인스턴스를 만들기 전에 프로토타입 연결을 끝냅니다(다음 절).

## 생성자 함수 상속 패턴

ES2015 이전에는 생성자 함수끼리의 상속을 아래 단계를 직접 조합해 구현했습니다. 자식 생성자 `Child`가 부모 생성자 `Parent`를 상속하는 방법입니다.

1. 인스턴스 프로퍼티 상속: 자식 생성자 안에서 `Parent.call(this, ...)`으로 부모 생성자를 자식 인스턴스에 적용합니다.
2. 프로토타입 연결: `Child.prototype = Object.create(Parent.prototype)`으로 체인을 잇습니다.
3. `constructor` 복구: 교체로 사라진 `constructor`를 다시 정의합니다.

```js
function Animal(name) { this.name = name }
Animal.prototype.speak = function () {
  return this.name + ' makes a sound'
}

function Dog(name) {
  Animal.call(this, name)                       // 1
}
Dog.prototype = Object.create(Animal.prototype) // 2
Object.defineProperty(Dog.prototype, 'constructor', {
  value: Dog, writable: true, configurable: true, // 3
})
```

```js
Dog.prototype.speak = function () { // 오버라이딩
  return Animal.prototype.speak.call(this) + ' (woof)'
}
const d = new Dog('Rex')
d.speak()             // 'Rex makes a sound (woof)'
d instanceof Animal   // true
d.constructor === Dog // true
```

```text
d
 → Dog.prototype
 → Animal.prototype
 → Object.prototype
 → null
```

2번과 3번 대신 기존 `Dog.prototype` 객체의 프로토타입만 바꾸는 방법도 있습니다. 교체가 아니므로 `constructor`가 유지됩니다. MDN이 권하는 방식이고, 인스턴스를 만들기 전에 한 번만 실행합니다.

```js
Object.setPrototypeOf(Dog.prototype, Animal.prototype)
Object.setPrototypeOf(Dog, Animal) // 정적 멤버 상속 (선택)
```

흔한 실수는 다음과 같습니다.

- `Dog.prototype = new Animal()`: 부모 생성자가 인수 없이 실행되어 `name: undefined`가 `Dog.prototype`의 own 프로퍼티로 남고 모든 자식이 이를 공유합니다. 부모 생성자에 부수 효과가 있으면 상속을 정의하는 시점에 실행됩니다.
- `Dog.prototype = Animal.prototype`: 두 함수가 같은 객체를 공유해, `Dog.prototype`에 추가한 메서드가 `Animal`의 인스턴스에도 생기고 `instanceof`로 둘을 구분할 수 없습니다.
- `constructor` 복구 누락: `new Dog('Rex').constructor`가 `Animal`을 가리킵니다.
- `Animal.call(this, name)` 누락: 부모의 인스턴스 프로퍼티(`name`)가 자식 인스턴스에 생기지 않습니다.

이 패턴은 `class`의 `extends`와 `super`가 대신해 줍니다.

| 단계 | 생성자 함수 패턴 | `class` |
|------|------------------|---------|
| 부모 초기화 | `Parent.call(this, ...)` | `super(...)` |
| 프로토타입 연결 | `Object.create(Parent.prototype)` | `extends`가 자동 처리 |
| `constructor` 복구 | `defineProperty`로 직접 | 자동 |
| 정적 멤버 상속 | `Object.setPrototypeOf(Child, Parent)` | 자동 |
| 부모 메서드 호출 | `Parent.prototype.m.call(this)` | `super.m()` |

빌트인 생성자는 이 패턴으로 상속할 수 없습니다. `Array.call(this)`는 `this`를 배열로 바꾸지 못하고 새 배열을 반환할 뿐이어서 `Array.isArray(인스턴스)`가 `false`입니다. 빌트인 확장은 `class extends`로 합니다(자세히는 25편). 객체 생성 방식 전체의 비교는 26편에서 다룹니다.

## 핵심 정리

- 모든 객체는 `[[Prototype]]`(접근은 `Object.getPrototypeOf`, 레거시 `__proto__`)으로 다른 객체나 `null`을 상속합니다. 프로퍼티 읽기는 체인을 따라 올라가고, 쓰기는 자기 객체에 합니다.
- constructor인 함수만 `prototype`을 가지며, 그 값이 `new`로 만든 인스턴스의 `[[Prototype]]`이 됩니다. `prototype.constructor`가 함수를 되가리키지만 `prototype`을 교체하면 사라집니다.
- 프로토타입은 생성자 함수가 정의될 때 함께 만들어지고, 빌트인은 코드 실행 전에 존재하며, 체인의 종점은 `Object.prototype`입니다.
- `instanceof`는 우변의 `prototype`이 좌변의 체인에 있는지 검사하고, `Symbol.hasInstance`로 판정을 바꿀 수 있습니다.
- 프로토타입은 생성 시점에 정합니다(`Object.create`, 리터럴 `__proto__`, `new`, `extends`). 생성 뒤 `setPrototypeOf`는 느립니다.
- `Object.create(null)` 객체는 상속이 없는 사전이고, 병합 코드로 들어오는 `__proto__`와 `constructor.prototype` 키는 프로토타입 오염 경로입니다.
