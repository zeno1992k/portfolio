## 핵심 먼저 보기

- Date는 에포크 이후 밀리초(시간 값) 하나를 담는 가변 객체이고, 월은 0부터, 일은 1부터, 요일은 0(일요일)부터 시작합니다.
- 오프셋 없는 문자열은 날짜만이면 UTC, 날짜+시간이면 지역 시각으로 해석합니다. ISO 형식 밖의 문자열은 엔진마다 다릅니다.
- 잘못된 날짜는 예외가 아니라 Invalid Date(시간 값 `NaN`)가 되므로 `Number.isNaN(d.getTime())`으로 검사하고, 날짜 계산은 서머타임을 고려해 setter나 UTC 기준으로 합니다.
- Intl 생성자는 로캘과 옵션으로 날짜·숫자·상대 시간·정렬·복수형·목록·분할·이름·기간을 만들며, 출력 문자열은 환경에 따라 달라질 수 있습니다.
- Temporal은 불변·1부터 시작하는 월·시간대 타입·나노초 정밀도를 갖춘 대체 API로, 2026년 3월 4단계에 올라 ES2027 예정이며 Safari는 아직 지원하지 않습니다.

## Date 객체와 시간 표현

Date는 한 시점을 나타내는 내장 객체이고, 내부에는 시간 값(time value) 하나만 들어 있습니다. 시간 값은 에포크(epoch), 즉 1970-01-01T00:00:00Z로부터 흐른 밀리초이며 윤초는 세지 않습니다.

```js
new Date(0).toISOString()
// '1970-01-01T00:00:00.000Z'
new Date(8.64e15).toISOString()
// '+275760-09-13T00:00:00.000Z'
new Date(8.64e15 + 1).getTime() // NaN
```

| 연산 | 동작 |
|------|------|
| `a - b` | 밀리초 차이(number) |
| `a + b`, `a + 1` | 문자열 연결 |
| `a < b`, `a >= b` | 시간 값 비교 |
| `a == b`, `a === b` | 참조 비교. 같은 객체일 때만 `true` |

## Date 생성자

Date 생성자는 인수의 개수와 타입으로 동작이 갈립니다.

| 호출 | 의미 |
|------|------|
| `new Date()` | 현재 시각 |
| `new Date(date)` | 복사 |
| `new Date(ms)` | 에포크 이후 밀리초 |
| `new Date(string)` | `Date.parse`와 같은 규칙으로 해석 |
| `new Date(y, m, d, h, mi, s, ms)` | 지역 시각의 구성요소 |

```js
new Date(2026, 9, 5, 14, 30).toString()
// 'Mon Oct 05 2026 14:30:00 GMT+0900 (한국 표준시)'
new Date(2026, 12, 1).getFullYear() // 2027 (월 12는 이월)
new Date(2026, 2, 0).getDate()      // 28 (3월 0일 = 2월 말일)
new Date(2026, 9, 5, 25).getDate()  // 6 (25시 = 다음 날 1시)
new Date(99, 0, 1).getFullYear()    // 1999
```

## Date.now·Date.parse·Date.UTC

세 정적 메서드는 모두 Date 객체가 아니라 시간 값(number)을 반환합니다.

| 메서드 | 동작 |
|--------|------|
| `Date.now()` | 현재 시간 값. `new Date().getTime()`과 같지만 객체를 만들지 않음 |
| `Date.parse(str)` | 문자열을 해석. 실패하면 `NaN`. `new Date(str)`과 같은 규칙 |
| `Date.UTC(y, m, ...)` | UTC 구성요소를 시간 값으로 변환 |

## getter와 setter

getter는 시간 값에서 구성요소를 꺼냅니다. 기본 이름은 지역 시각 기준이고, `getUTCFullYear`처럼 `UTC`가 들어간 짝이 UTC 기준입니다.

| 메서드 | 반환 | 범위 |
|--------|------|------|
| `getFullYear` | 연 | 네 자리 연도 |
| `getMonth` | 월 | 0–11 |
| `getDate` | 일 | 1–31 |
| `getDay` | 요일 | 0–6 (일요일이 0) |
| `getHours` | 시 | 0–23 |
| `getMinutes`·`getSeconds` | 분·초 | 0–59 |
| `getMilliseconds` | 밀리초 | 0–999 |
| `getTime`·`valueOf` | 시간 값 | 에포크 이후 ms |
| `getTimezoneOffset` | UTC와 지역 시각의 차 | 분 단위. UTC 짝 없음 |

## 월이 0부터 시작하는 함정

Date의 월은 0부터 시작하고, 일은 1부터 시작합니다. 요일도 0부터입니다. 세 값의 시작 기준이 서로 달라 혼동하기 쉽습니다.

| 값 | 시작 | 마지막 |
|----|------|--------|
| 월 (`getMonth`, 생성자 인수) | 0 = 1월 | 11 = 12월 |
| 일 (`getDate`) | 1 | 28–31 |
| 요일 (`getDay`) | 0 = 일요일 | 6 = 토요일 |

## 시간대와 UTC

UTC는 기준 시각이고, 시간대(time zone)는 UTC에 더하는 오프셋 규칙입니다. 서머타임(DST)처럼 날짜에 따라 오프셋이 바뀌는 규칙도 시간대에 포함됩니다. 시간 값은 시간대와 무관한 하나의 숫자이고, 같은 시간 값도 지역 시각으로 바꾸면 환경마다 다른 시·일이 나옵니다.

## 문자열 변환

| 메서드 | 기준 | 용도 |
|--------|------|------|
| `toString()` | 지역 | `Mon Oct 05 2026 14:30:15 GMT+0900 (한국 표준시)` 형태의 디버깅용 |
| `toDateString()`·`toTimeString()` | 지역 | `toString` 결과의 날짜 부분·시간 부분 |
| `toISOString()` | UTC | 항상 `YYYY-MM-DDTHH:mm:ss.sssZ`. 저장·전송용 |
| `toUTCString()` | UTC | HTTP 헤더·쿠키에 쓰는 날짜 형식 |
| `toJSON()` | UTC | `toISOString`과 같은 값. Invalid Date는 `null` |
| `toLocaleString()` 등 | 지역 | 로캘 형식. `Intl.DateTimeFormat`에 위임 |

흔한 실수는 `toISOString().slice(0, 10)`을 지역 날짜로 쓰는 것입니다. UTC 날짜가 나오므로 한국 시간 자정에서 전날이 됩니다.

## 날짜 문자열 파싱 함정

표준 날짜·시간 표기를 쓰고 필요한 시간대나 오프셋을 명시합니다. 날짜만 있는 ISO 문자열은 UTC 기준이지만 시간대 없는 날짜·시간 문자열은 지역 시간으로 해석됩니다. 비표준 문자열은 환경별 결과가 달라질 수 있습니다.

## Invalid Date

Invalid Date는 시간 값이 `NaN`인 Date 객체입니다. 예외를 던지지 않고 이 객체를 만들기 때문에 검사하지 않으면 `NaN`이 뒤로 번집니다.

| 연산 | 결과 |
|------|------|
| getter 전체 (`getTime`, `getFullYear` 등) | `NaN` |
| `toString()`, `toLocaleDateString()` | `'Invalid Date'` |
| `toJSON()` | `null` (`JSON.stringify`는 `null`로 직렬화) |
| `toISOString()` | `RangeError` |
| `Intl.DateTimeFormat`의 `format` | `RangeError` |

## 날짜 더하기와 차이 계산

두 Date를 빼면 밀리초 차이입니다. 24시간의 경과와 달력상의 하루는 일광 절약 시간 전환에서 다를 수 있습니다. 달력 날짜 변경에는 날짜 필드 연산을, 실제 경과 시간 계산에는 타임스탬프 차이를 사용합니다.

## Intl과 로캘

Intl은 ECMA-402가 정의하는 전역 객체로, 로캘(locale)에 따라 달라지는 포맷·비교·분할 기능을 모읍니다(ECMA-402는 01편). 생성자는 모두 `new Intl.X(locales, options)` 형태입니다.

## Intl.DateTimeFormat

`Intl.DateTimeFormat`은 로캘·시간대·옵션에 맞춰 날짜와 시각을 문자열로 만듭니다. `format`은 Date 또는 시간 값(number)을 받습니다. 인수가 없거나 `undefined`이면 현재 시각이고, Invalid Date는 `RangeError`입니다. `format`은 바인딩된 함수라서 `dates.map(fmt.format)`처럼 넘길 수 있습니다.

| 계열 | 옵션 | 값 |
|------|------|-----|
| 스타일 단축 | `dateStyle`, `timeStyle` | `full`, `long`, `medium`, `short` |
| 개별 필드 | `weekday`, `era`, `year`, `month`, `day`, `hour`, `minute`, `second` | 필드마다 `numeric`, `2-digit`, `long`, `short`, `narrow` 중 허용되는 값 |
| 보조 | `fractionalSecondDigits`, `dayPeriod`, `timeZoneName` | 1–3 / `long`·`short`·`narrow` / `short`·`long` 등 |

## Intl.NumberFormat

`Intl.NumberFormat`은 숫자를 로캘에 맞는 자릿수 구분·소수점·통화·단위·축약 표기로 만듭니다. `Number.prototype.toLocaleString`은 같은 규칙의 단축형입니다(자세히는 30편).

| style | 필요한 옵션 | 입력 → 결과 (en-US) |
|-------|-------------|---------------------|
| `decimal` (기본) | 없음 | `1234.5` → `1,234.5` |
| `currency` | `currency` | `1234.5` → `$1,234.50` |
| `percent` | 없음 | `0.256` → `26%` |
| `unit` | `unit` | `80` → `80 km/h` |

## Intl.RelativeTimeFormat

`Intl.RelativeTimeFormat`은 "3일 전", "내일"처럼 기준 시점에 상대적인 표현을 만듭니다. 두 시각의 차이를 계산해 주지 않으므로 값과 단위를 직접 넘깁니다.

## Intl.Collator

`Intl.Collator`는 로캘 규칙으로 두 문자열을 비교합니다. `compare(a, b)`는 음수·0·양수를 반환하고 바인딩된 함수라서 `sort`에 바로 넘길 수 있습니다.

| `sensitivity` | `a`와 `A` | `a`와 `á` | 구분하는 것 |
|---------------|-----------|-----------|-------------|
| `base` | 같음 | 같음 | 기본 문자 |
| `accent` | 같음 | 다름 | 기본 문자 + 악센트 |
| `case` | 다름 | 같음 | 기본 문자 + 대소문자 |
| `variant` | 다름 | 다름 | 전부 (`sort` 용도의 기본) |

## Intl.PluralRules

`Intl.PluralRules`는 수를 로캘의 복수형 범주로 분류합니다. `select(n)`이 범주 이름을 반환할 뿐 문구는 만들지 않으므로, 범주별 문구는 직접 매핑합니다.

| 로캘 | 사용하는 범주 |
|------|---------------|
| 한국어 (`ko`) | `other` |
| 영어 (`en`) | `one`, `other` |
| 러시아어 (`ru`) | `one`, `few`, `many`, `other` |
| 아랍어 (`ar`) | 여섯 개 전부 |

## Intl.ListFormat

`Intl.ListFormat`은 문자열 목록을 로캘에 맞는 접속사와 구분자로 연결합니다. `format`은 문자열의 이터러블을 받고, 문자열이 아닌 항목이 있으면 `TypeError`입니다.

## Intl.Segmenter

`Intl.Segmenter`는 문자열을 자소(grapheme)·단어·문장 경계로 나눕니다. `length`와 스프레드는 UTF-16 코드 유닛과 코드 포인트 단위여서 사용자가 보는 글자 수와 다를 수 있습니다(자세히는 33편).

## Intl.DisplayNames

`Intl.DisplayNames`는 지역·언어·통화 같은 코드를 지정한 로캘의 이름으로 바꿉니다. `type`은 필수이고 없으면 `TypeError`입니다. 변환은 `of(code)`로 합니다.

| type | 코드 형식 | 예 (영어 결과) |
|------|-----------|----------------|
| `region` | ISO 3166-1 두 글자, UN M.49 숫자 | `KR` → `South Korea` |
| `language` | BCP 47 | `ko` → `Korean` |
| `currency` | ISO 4217 | `USD` → `US Dollar` |
| `script` | ISO 15924 | `Hang` → `Hangul` |
| `calendar`, `dateTimeField` | 달력 이름, 필드 이름 | `gregory` → `Gregorian Calendar` |

## Intl.DurationFormat

`Intl.DurationFormat`은 시간 길이(기간)를 로캘에 맞는 문자열로 만듭니다. ECMA-402 2025년 판에 포함됐고 2025년 3월부터 주요 엔진이 모두 지원합니다(Chrome 129, Firefox 136, Node.js 23).

## Temporal

Temporal은 Date를 대체하기 위해 설계된 날짜·시간 API입니다. `Math`나 `Intl`처럼 클래스들을 담는 네임스페이스 객체이고 생성자가 아닙니다. `typeof Temporal`은 지원하는 환경에서 `'object'`이고, Node.js 24에서는 `'undefined'`입니다.

| Date의 문제 | Temporal의 해결 |
|-------------|-----------------|
| 가변 객체 | 모든 객체가 불변. `with`·`add`는 새 객체를 반환 |
| 월이 0부터 | 월은 1부터(`month`는 1–12) |
| UTC와 지역 시간대뿐 | `ZonedDateTime`이 IANA 시간대를 가짐 |
| 날짜만·시각만 표현할 수 없음 | `PlainDate`, `PlainTime` 등 별도 타입 |
| 밀리초 정밀도 | 나노초 정밀도(`epochNanoseconds`는 BigInt) |
| 문자열 파싱이 엔진마다 다름 | ISO 8601 확장 형식(RFC 9557)만 엄격하게 파싱 |
| 산술 API 없음 | `add`, `subtract`, `until`, `since`, `Duration` |
| 그레고리력 고정 | 다른 달력(히브리력, 일본력 등) 지원 |
