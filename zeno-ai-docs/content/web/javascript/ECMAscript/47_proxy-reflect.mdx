## Proxy 개념

**Proxy**(ES2015)는 다른 객체(target)를 감싸서 그 객체에 대한 기본 연산을 가로채 재정의하는 객체입니다. 기본 연산은 프로퍼티 읽기·쓰기·삭제, `in`, 열거, 함수 호출, `new` 같은 것들입니다.

```js
const target = { a: 1 }
const p = new Proxy(target, {})

p.b = 2
console.log(target.b) // 2 (빈 handler는 target으로 전달)
console.log(p === target) // false
```

명세는 객체의 동작을 내부 메서드로 정의합니다. 일반 객체에는 11개가 있고, 함수 객체에는 `[[Call]]`과 `[[Construct]]`가 더해져 13개입니다. Proxy는 이 내부 메서드를 handler의 함수(trap)로 바꿔 끼웁니다.

| 내부 메서드 | 대응하는 trap |
|-------------|----------------|
| `[[GetPrototypeOf]]`, `[[SetPrototypeOf]]` | `getPrototypeOf`, `setPrototypeOf` |
| `[[IsExtensible]]`, `[[PreventExtensions]]` | `isExtensible`, `preventExtensions` |
| `[[GetOwnProperty]]`, `[[DefineOwnProperty]]` | `getOwnPropertyDescriptor`, `defineProperty` |
| `[[HasProperty]]`, `[[Get]]`, `[[Set]]`, `[[Delete]]` | `has`, `get`, `set`, `deleteProperty` |
| `[[OwnPropertyKeys]]` | `ownKeys` |
| `[[Call]]`, `[[Construct]]` | `apply`, `construct` |

생성 규칙은 다음과 같습니다.

- target과 handler는 모두 객체여야 합니다. 함수도 객체이므로 허용됩니다. 원시 값이나 `null`이면 `TypeError`입니다.
- `new` 없이 `Proxy(...)`를 호출하면 `TypeError`입니다.
- `Proxy.prototype`은 `undefined`입니다. 프록시는 `Proxy`의 인스턴스가 아니라 target처럼 보이는 객체입니다.
- 프록시는 `typeof`·`Array.isArray`·`Object.prototype.toString`에서 target의 종류를 그대로 따릅니다.

```js
typeof new Proxy(() => {}, {}) // 'function'
typeof new Proxy({}, {}) // 'object'
Array.isArray(new Proxy([], {})) // true
```

- 프록시는 `p === target`이 `false`인 별개의 객체입니다.
- Proxy는 문법이 아니라 객체 동작 자체를 바꾸므로 트랜스파일러나 폴리필로 흉내 낼 수 없습니다.

getter/setter(`Object.defineProperty`)와 달리 프록시는 존재하지 않는 프로퍼티의 읽기, 새 프로퍼티 추가, 삭제, `in`, 배열 인덱스 대입까지 가로챕니다. 프로퍼티 어트리뷰트는 14편, 프로토타입은 17편에서 다룹니다.

## handler와 trap

**handler**는 trap 이름을 메서드로 가진 일반 객체이고, **trap**은 특정 연산을 가로채는 handler의 메서드입니다. handler에 없는 trap은 target에 대한 기본 동작으로 전달됩니다.

```js
const p = new Proxy({ x: 1 }, {
  get(target, key, receiver) {
    console.log('get', key)
    return Reflect.get(target, key, receiver)
  },
})
p.x // 로그: get x → 1
p.y // 로그: get y → undefined
```

규칙은 다음과 같습니다.

- trap 안의 `this`는 handler입니다.
- handler는 프록시를 만든 뒤에 바꿔도 즉시 반영됩니다. 프록시가 handler를 복사하지 않고 참조하기 때문입니다.
- trap 값이 `undefined`나 `null`이면 전달되고, 함수가 아닌 다른 값이면 해당 연산이 일어날 때 `TypeError`입니다.
- 명세가 정한 trap은 13종이고, 이름은 위 표의 내부 메서드와 같은 수입니다.

```js
const h = {}
const p = new Proxy({ x: 1 }, h)
p.x // 1
h.get = () => 99
p.x // 99
```

### trap 13종 전체 표

| trap | 가로채는 연산 | 반환 |
|------|---------------|------|
| `get(t, key, receiver)` | `p.x`, `p[k]`, 프로토타입 체인 조회 | 값 |
| `set(t, key, value, receiver)` | `p.x = v`, `p.x++` | 불리언 |
| `has(t, key)` | `key in p`, `with` | 불리언 |
| `deleteProperty(t, key)` | `delete p.x` | 불리언 |
| `ownKeys(t)` | `Object.keys`, `Reflect.ownKeys`, `for...in`, 스프레드 | 키 배열 |
| `getOwnPropertyDescriptor(t, key)` | `Object.getOwnPropertyDescriptor`, `Object.keys`의 열거 가능 검사 | 디스크립터 또는 `undefined` |
| `defineProperty(t, key, desc)` | `Object.defineProperty`, `Reflect.defineProperty` | 불리언 |
| `getPrototypeOf(t)` | `Object.getPrototypeOf`, `instanceof`, `for...in` | 객체 또는 `null` |
| `setPrototypeOf(t, proto)` | `Object.setPrototypeOf` | 불리언 |
| `isExtensible(t)` | `Object.isExtensible` | 불리언 |
| `preventExtensions(t)` | `Object.preventExtensions`, `freeze`, `seal` | 불리언 |
| `apply(t, thisArg, args)` | `p()`, `p.call()`, `p.apply()` | 임의 값 |
| `construct(t, args, newTarget)` | `new p()` | 객체 |

하나의 동작이 여러 trap을 거치는 경우가 있습니다(Node.js에서 실행한 결과).

| 동작 | 거치는 trap (순서대로) |
|------|-------------------------|
| `Object.keys(p)` | `ownKeys` → 키마다 `getOwnPropertyDescriptor` |
| `for (k in p)` | `ownKeys` → `getPrototypeOf` → 키마다 `getOwnPropertyDescriptor` |
| `JSON.stringify(p)` | `get`(`toJSON`) → `ownKeys` → 키마다 `getOwnPropertyDescriptor` → 키마다 `get` |
| `p.a++` | `get` → `set` |
| `Object.freeze(p)` | `preventExtensions` → `ownKeys` → 키마다 `getOwnPropertyDescriptor`, `defineProperty` |
| `p instanceof Object` | `getPrototypeOf` |

- trap이 없는 연산도 있습니다. `typeof p`와 `p === q`는 가로챌 수 없습니다. target을 직접 쥐고 있는 코드는 프록시를 우회합니다.
- 반환 타입을 어기면 `TypeError`입니다. `getPrototypeOf`가 객체나 `null`이 아닌 값을 돌려주는 경우가 그 예입니다.

열거와 `for...in`의 동작은 18편, `JSON.stringify`는 39편에서 다룹니다.

## get·set

**get trap**은 프로퍼티를 읽을 때 호출되고, 반환값이 읽은 값이 됩니다. 존재하지 않는 키에도 호출됩니다.

```js
const neg = (arr) => new Proxy(arr, {
  get(t, k, r) {
    const isNeg = typeof k === 'string' && /^-\d+$/.test(k)
    return Reflect.get(t, isNeg ? t.length + +k : k, r)
  },
})
neg([1, 2, 3])[-1] // 3
neg([1, 2, 3])[0] // 1
```

- `key`는 항상 문자열 또는 심볼입니다. `arr[0]`도 `'0'`으로 들어옵니다.
- 위 예에서 `typeof k === 'string'` 검사를 빼면, 심볼 키가 정규식에 들어가 `TypeError`가 납니다.
- 프로퍼티 읽기 외에도 엔진이 내부적으로 읽는 키(`Symbol.toPrimitive`, `toJSON`, `then`)에 대해서도 호출됩니다.

**set trap**은 프로퍼티에 값을 쓸 때 호출되고, 성공 여부를 불리언으로 반환해야 합니다.

```js
'use strict'
const p = new Proxy({}, { set() {} })
p.a = 1 // TypeError: 'set' on proxy: trap returned falsish
```

- 반환값이 거짓이면 엄격 모드에서는 `TypeError`, 느슨한 모드에서는 대입이 조용히 무시됩니다(strict mode는 19편).
- 반환값을 빠뜨리면 `undefined`이므로 거짓입니다. `set` trap의 가장 흔한 실수입니다. 성공했으면 `return true`를 씁니다.
- trap 안에서 `t[k] = v`로 직접 쓰는 대신 `Reflect.set(t, k, v, r)`을 쓰면 반환값과 receiver가 올바르게 처리됩니다.
- 배열 프록시에 `push`를 하면 `set`이 인덱스 키와 `length` 키에 대해 각각 호출됩니다. 실행 결과는 `set 0` → `defineProperty 0` → `set length` → `defineProperty length` 순서입니다.

## has·deleteProperty

**has trap**은 `in` 연산자와 `with` 문의 이름 조회를 가로챕니다.

```js
const hide = new Proxy({ _id: 1, name: 'a' }, {
  has: (t, k) => !String(k).startsWith('_') && k in t,
})
'name' in hide // true
'_id' in hide // false
```

- `has`는 `Object.hasOwn`과 `hasOwnProperty`를 가로채지 못합니다. 이 둘은 `getOwnPropertyDescriptor` trap을 거칩니다. 위 예에서 `Object.hasOwn(hide, '_id')`는 `true`입니다.
- `for...in`도 `has`를 호출하지 않습니다. 키 목록은 `ownKeys`에서 옵니다.
- 프록시를 다른 객체의 프로토타입으로 두면, 그 객체에 대한 `in`이 프로토타입 체인을 타고 프록시의 `has`까지 옵니다.
- 키를 숨기려면 `has`, `ownKeys`, `get`을 함께 처리해야 합니다. 하나만 막으면 다른 경로로 보입니다.

**deleteProperty trap**은 `delete` 연산자를 가로채고, 삭제 성공 여부를 불리언으로 반환합니다.

```js
const guard = new Proxy({ id: 1, tmp: 2 }, {
  deleteProperty(t, k) {
    if (k === 'id') return false
    return Reflect.deleteProperty(t, k)
  },
})
delete guard.tmp // true
delete guard.id // false (엄격 모드는 TypeError)
```

- `delete` 연산자의 결과가 곧 trap의 반환값(불리언으로 변환)입니다.
- 거짓을 반환하면 엄격 모드에서 `TypeError`입니다. `set`과 같은 규칙입니다.

## apply·construct

**apply trap**은 target이 함수일 때 호출을 가로챕니다. `p()`뿐 아니라 `p.call()`, `p.apply()`, `Reflect.apply(p, ...)`도 같은 trap을 거칩니다.

```js
const sum = (a, b) => a + b
const logged = new Proxy(sum, {
  apply(target, thisArg, args) {
    console.log('call', args)
    return Reflect.apply(target, thisArg, args)
  },
})
logged(1, 2) // 로그: call [1, 2] → 3
```

- 인수는 `(target, thisArg, argumentsList)`이고, argumentsList는 진짜 배열입니다.
- target이 호출할 수 없는 일반 객체이면 프록시도 호출할 수 없습니다. `apply` trap을 달아도 `p()`는 `TypeError`입니다.
- 클래스를 target으로 하면 프록시도 `new` 없이 호출할 수 있는 것으로 취급되어 `apply`가 먼저 실행됩니다. 그대로 `Reflect.apply`로 넘기면 클래스 규칙에 따라 `TypeError`입니다.

**construct trap**은 `new`를 가로챕니다. 인수는 `(target, argumentsList, newTarget)`이고, 반드시 객체를 반환해야 합니다.

```js
class Db {}
let inst
const Single = new Proxy(Db, {
  construct(t, args, newTarget) {
    return (inst ??= Reflect.construct(t, args, newTarget))
  },
})
new Single() === new Single() // true
```

- `newTarget`은 `new`에 쓰인 생성자입니다. `new p()`이면 프록시 자신이고, 프록시를 `extends`한 클래스가 `new`되면 그 클래스입니다. 새 객체의 프로토타입은 `newTarget.prototype`에서 결정됩니다(클래스 상속은 25편).
- 객체가 아닌 값을 반환하면 `TypeError`입니다.
- target에 `[[Construct]]`가 없으면 프록시에도 없습니다. 화살표 함수를 target으로 하면 `construct` trap이 있어도 `new p()`는 `TypeError`입니다.

## Reflect

**Reflect**(ES2015)는 객체의 내부 메서드를 함수로 노출하는 내장 객체입니다. `Math`처럼 정적 메서드만 가진 네임스페이스이고, 함수도 생성자도 아니므로 `new Reflect()`는 `TypeError`입니다.

메서드는 13개이고 Proxy trap과 이름·인수가 1대 1로 대응합니다. `Reflect.get`, `Reflect.set`, `Reflect.has`, `Reflect.deleteProperty`, `Reflect.ownKeys`, `Reflect.getOwnPropertyDescriptor`, `Reflect.defineProperty`, `Reflect.getPrototypeOf`, `Reflect.setPrototypeOf`, `Reflect.isExtensible`, `Reflect.preventExtensions`, `Reflect.apply`, `Reflect.construct`입니다.

기존 `Object` 메서드·연산자와 다른 점은 다음과 같습니다.

| 동작 | 기존 방식 | Reflect |
|------|-----------|---------|
| 정의 실패 | `Object.defineProperty`가 `TypeError` | `Reflect.defineProperty`가 `false` |
| 프로토타입 변경 실패 | `Object.setPrototypeOf`가 `TypeError` | `Reflect.setPrototypeOf`가 `false` |
| 대입·삭제 실패 | 엄격 모드에서 `TypeError` | `Reflect.set`·`Reflect.deleteProperty`가 `false` |
| 확장 금지 | `Object.preventExtensions`가 객체 반환 | `Reflect.preventExtensions`가 불리언 반환 |
| 원시 값 인수 | `Object.keys(1)`은 `[]`로 변환 처리 | `Reflect.ownKeys(1)`은 `TypeError` |
| 키 나열 | 문자열·심볼을 따로 조회 | `Reflect.ownKeys`가 비열거 키와 심볼까지 한 번에 |
| `in`·`delete`·`new` | 연산자 | `Reflect.has`·`Reflect.deleteProperty`·`Reflect.construct` 함수 |

`Reflect.ownKeys`의 순서는 정수형 키 오름차순, 문자열 키 생성 순, 심볼 순입니다. `{ b, [s], 2, a, 1 }`에 비열거 키 `hid`를 더하면 `['1', '2', 'b', 'a', 'hid', Symbol(s)]`입니다.

```js
Reflect.apply(Math.max, null, [1, 5, 3]) // 5
Reflect.has({ a: 1 }, 'a') // true
Reflect.defineProperty(Object.freeze({}), 'a', { value: 1 }) // false
```

`Reflect.construct(F, args, newTarget)`은 `F`의 생성자 로직을 실행하되 프로토타입은 `newTarget.prototype`으로 만듭니다.

```js
class A { constructor() { this.t = new.target.name } }
class B {}
const o = Reflect.construct(A, [], B)
o.t // 'B'
Object.getPrototypeOf(o) === B.prototype // true
o instanceof A // false
```

trap 안에서 Reflect를 쓰는 이유는 세 가지입니다.

- 기본 동작을 그대로 전달하는 가장 짧은 방법입니다.
- 반환값이 불리언이라 `set`·`defineProperty`·`deleteProperty` trap의 반환 규약과 맞습니다.
- receiver를 올바르게 넘길 수 있습니다(아래).

Reflect는 Proxy 없이도 쓸 수 있습니다. 호출 실패를 예외 대신 불리언으로 받고 싶을 때, `new`·`in`을 함수로 넘기고 싶을 때 씁니다.

## receiver

**receiver**는 `get`·`set` trap의 마지막 인수로, 그 연산이 원래 시작된 객체입니다. 보통은 프록시 자신이고, 프록시를 프로토타입으로 둔 객체에서 조회가 시작되면 그 객체입니다. getter·setter가 실행될 때의 `this`도 receiver입니다.

```js
const p = new Proxy({}, { get: (t, k, r) => r })
const child = Object.create(p)
p.x === p // true
child.x === child // true
```

getter 안의 `this`는 `Reflect.get`에 receiver를 넘기느냐로 달라집니다.

```js
const target = { _v: 1, get v() { return this._v } }
const log = []
const p = new Proxy(target, {
  get(t, k, r) { log.push(k); return Reflect.get(t, k, r) },
})
p.v // 1
log // ['v', '_v'] (this가 프록시라 _v도 trap을 거친다)
```

- `Reflect.get(t, k)`처럼 receiver를 빼면 getter의 `this`가 target이 되어 `log`는 `['v']`뿐입니다. 반응성 라이브러리에서는 getter 내부의 접근을 추적하지 못하는 버그가 됩니다.
- `t[k]`로 읽는 것도 receiver를 버리는 것과 같습니다.

`Reflect.set(t, k, v, receiver)`는 receiver가 target과 다르면 값을 target이 아니라 receiver에 씁니다.

```js
const t = {}
const r = {}
Reflect.set(t, 'a', 1, r) // true
t.a // undefined
r.a // 1
```

- receiver가 프록시 자신이면 `Reflect.set`이 프록시에 `getOwnPropertyDescriptor`와 `defineProperty`를 호출합니다. `set` trap 안에서 `Reflect.set(t, k, v, r)`을 부르면 실행 순서가 `set` → `getOwnPropertyDescriptor` → `defineProperty`가 됩니다.
- 프록시를 프로토타입으로 둔 객체에 `child.x = 1`을 하면 receiver는 `child`입니다. trap에서 `t[k] = v`로 쓰면 값이 target에 저장되고 `child`에는 생기지 않습니다. `Reflect.set(t, k, v, r)`을 쓰면 `child`에 저장됩니다.

## 불변식

**불변식**(invariant)은 trap의 결과가 target의 실제 상태와 모순되지 않도록 명세가 강제하는 조건입니다. 어기면 trap이 끝난 직후 `TypeError`가 납니다. 설정 불가·쓰기 불가로 고정된 프로퍼티와 확장 불가 객체에 대해 프록시가 거짓말을 하지 못하게 하는 장치입니다(configurable·writable은 14편).

| trap | `TypeError`가 나는 경우 |
|------|--------------------------|
| `get` | target의 쓰기 불가·설정 불가 데이터 프로퍼티와 다른 값을 반환 |
| `get` | target의 설정 불가 접근자 프로퍼티가 getter 없이 정의됐는데 `undefined` 외의 값을 반환 |
| `set` | target의 쓰기 불가·설정 불가 데이터 프로퍼티를 다른 값으로 바꿨다고 `true` 반환 |
| `has` | target의 설정 불가 own 프로퍼티를 없다고(`false`) 보고. 확장 불가 target의 own 프로퍼티도 마찬가지 |
| `deleteProperty` | target의 설정 불가 own 프로퍼티를 삭제했다고(`true`) 보고. 확장 불가 target의 own 프로퍼티도 마찬가지 |
| `ownKeys` | 결과에 중복이 있거나 문자열·심볼이 아닌 원소가 있음 |
| `ownKeys` | target의 설정 불가 own 키가 빠짐. 확장 불가 target이면 키 집합이 target과 정확히 같아야 함 |
| `getOwnPropertyDescriptor` | 객체나 `undefined`가 아닌 값 반환. 설정 불가 프로퍼티를 `undefined`로 보고 |
| `defineProperty` | 확장 불가 target에 새 프로퍼티를 추가했다고 `true` 반환 |
| `getPrototypeOf` | 객체나 `null`이 아닌 값 반환. 확장 불가 target이면 target의 실제 프로토타입과 달라도 안 됨 |
| `setPrototypeOf` | 확장 불가 target의 프로토타입을 바꿨다고 `true` 반환 |
| `isExtensible` | `Object.isExtensible(target)`과 다른 값 반환 |
| `preventExtensions` | target이 아직 확장 가능한데 `true` 반환 |
| `construct` | 객체가 아닌 값 반환 |

`apply`에는 불변식이 없습니다.

```js
const t = {}
Object.defineProperty(t, 'k', { value: 1 })
// writable: false, configurable: false
const p = new Proxy(t, { get: () => 2 })
p.k // TypeError: ... expected '1' but got '2'
```

- 같은 값(`get: () => 1`)을 돌려주면 통과합니다. 불변식은 값이 어긋날 때만 막습니다.
- 확장 불가 target을 감싸면 가능한 trap 동작이 크게 줄어듭니다. `Object.freeze`한 객체를 프록시로 감싸 값을 다르게 보이게 하는 일은 불가능합니다.
- 불변식은 trap 실행이 끝난 뒤에 검사하므로, 예외가 나기 전에 trap이 한 부작용은 남습니다.

## Proxy.revocable

**Proxy.revocable**(target, handler)은 `{ proxy, revoke }`를 반환하는 정적 메서드이고, `revoke()`를 호출하면 그 프록시를 영구히 무효화합니다.

```js
const { proxy, revoke } = Proxy.revocable({ a: 1 }, {})
proxy.a // 1
revoke()
proxy.a // TypeError: Cannot perform 'get' on a proxy that has been revoked
```

- 무효화된 프록시에 대한 모든 trap 대상 연산(`get`, `set`, `in`, `delete`, `Object.keys` 등)이 `TypeError`입니다. `Array.isArray`도 `TypeError`입니다.
- `typeof`는 계속 동작합니다. 객체 프록시는 `'object'`, 함수 프록시는 `'function'`입니다.
- `revoke()`는 몇 번 불러도 되고, 되돌릴 수 없습니다.
- 무효화하면 프록시가 target과 handler 참조를 버리므로 다른 참조가 없을 때 둘 다 가비지 컬렉션 대상이 됩니다(49편).
- `Proxy.revocable`은 `new` 없이 호출합니다. `new Proxy.revocable(...)`은 `TypeError`입니다.
- 용도는 외부 코드에 객체 접근 권한을 빌려 주었다가 회수하는 것입니다. 객체 자체를 넘기면 회수할 방법이 없지만, 프록시를 넘기면 `revoke`로 끊을 수 있습니다.

## 활용

**검증**은 `set` trap에서 값을 검사하는 가장 흔한 용도입니다.

```js
const user = new Proxy({}, {
  set(t, k, v, r) {
    if (k === 'age' && !Number.isInteger(v)) {
      throw new TypeError('age must be integer')
    }
    return Reflect.set(t, k, v, r)
  },
})
user.age = 20 // 통과
user.age = 'x' // TypeError: age must be integer
```

**반응성**은 `set`에서 값 변경을 알리는 방식입니다. Vue 3의 `reactive()`가 이 구조이고, Vue 2는 프로퍼티마다 getter·setter를 정의하는 방식이었습니다. 아래는 변경 알림만 보이는 최소형입니다.

```js
const effects = new Set()
const reactive = (obj) => new Proxy(obj, {
  set(t, k, v, r) {
    const ok = Reflect.set(t, k, v, r)
    effects.forEach((fn) => fn(k, v))
    return ok
  },
})
const state = reactive({ count: 0 })
effects.add((k, v) => console.log(k, v))
state.count = 1 // 로그: count 1
```

- 실제 라이브러리는 `get`에서 어떤 효과가 어떤 키를 읽는지 기록(추적)하고, `set`에서 그 키를 읽은 효과만 다시 실행합니다.
- 프록시는 얕습니다. `state.nested.x = 1`은 `nested`가 일반 객체이면 가로채지 못합니다. 중첩 객체는 `get`에서 읽는 시점에 프록시로 감싸 돌려줘야 합니다.

그 밖의 용도는 다음과 같습니다.

- **기본값·음수 인덱스**: 없는 키에 대해 기본값을 돌려주는 `get` (앞의 `neg` 예).
- **읽기 전용 뷰**: `set`, `deleteProperty`, `defineProperty`를 모두 막습니다. 하나라도 빠지면 그 경로로 변경됩니다. 얕은 보호만 필요하면 `Object.freeze`가 더 단순합니다.
- **로깅·디버깅·계측**: `get`·`apply`에서 호출 기록을 남기고 `Reflect`로 전달합니다.
- **동적 API**: `get`이 키 이름에 맞는 함수를 만들어 돌려주는 방식으로 `api.users.list()` 같은 호출을 구현합니다.
- **지연 생성**: 처음 읽을 때 값을 만들어 캐시합니다.

흔한 실수는 모르는 키에 예외를 던지는 `get` trap입니다. 엔진이 내부적으로 읽는 키까지 걸립니다.

```js
const strict = new Proxy({ a: 1 }, {
  get(t, k, r) {
    if (!(k in t)) throw new Error('no ' + String(k))
    return Reflect.get(t, k, r)
  },
})
JSON.stringify(strict) // Error: no toJSON
`${strict}` // Error: no Symbol(Symbol.toPrimitive)
await strict // Error: no then (프로미스가 거부됨)
```

## 한계

- **private 필드**: 프록시는 target의 `#private` 요소를 갖지 않습니다. 메서드가 `this`로 프록시를 받아 `this.#n`을 읽으면 `TypeError`입니다(private 필드는 24편).

```js
class Counter { #n = 0; inc() { return ++this.#n } }
const p = new Proxy(new Counter(), {})
p.inc() // TypeError: Cannot read private member #n ...
```

- **내부 슬롯**: `Map`, `Set`, `WeakMap`, `Date`, `Promise`, `RegExp`, 타입드 배열은 내부 슬롯에 데이터를 둡니다. 프록시는 내부 슬롯이 없으므로 이 객체들의 메서드를 프록시로 호출하면 `TypeError`입니다.

```js
new Proxy(new Map(), {}).set('a', 1) // TypeError
new Proxy(new Date(), {}).getTime() // TypeError
new Proxy(Promise.resolve(1), {}).then(() => {}) // TypeError
```

- 우회 방법은 `get`에서 함수를 target에 바인딩해 돌려주는 것입니다. 이러면 `this`가 target이 되므로, 그 메서드 내부의 접근은 프록시를 거치지 않습니다.

```js
const wrap = (o) => new Proxy(o, {
  get(t, k) {
    const v = Reflect.get(t, k, t)
    return typeof v === 'function' ? v.bind(t) : v
  },
})
wrap(new Map()).set('a', 1) // 동작
```

- 배열은 이 문제가 없습니다. `Array` 메서드는 내부 슬롯 없이 `length`와 인덱스만 읽는 범용 메서드이고, `Array.isArray`와 `JSON.stringify`도 프록시를 배열로 인식합니다.
- **동일성**: `p !== target`입니다. target을 키로 쓰는 `WeakMap`·`Set`·`Map`은 프록시로 조회하면 찾지 못하고, `===` 비교도 어긋납니다. target과 프록시를 섞어 쓰면 이 버그가 생깁니다.
- **성능**: 프록시를 거치는 모든 연산은 trap 함수 호출을 거칩니다. 엔진이 일반 프로퍼티 접근에 쓰는 최적화(인라인 캐싱 등)가 적용되기 어려워 직접 접근보다 느립니다. 반복이 많은 핵심 경로에는 측정한 뒤 씁니다.
- **우회 가능**: target 참조를 직접 가진 코드는 trap을 거치지 않습니다. 보호용으로 쓰려면 target을 외부에 노출하지 않아야 합니다.
- **지원 범위**: 폴리필이 불가능하므로 지원하지 않는 환경에서는 쓸 수 없습니다.

## 핵심 정리

- Proxy는 target의 기본 연산(내부 메서드 13종)을 handler의 trap으로 가로채고, trap이 없으면 target으로 전달합니다. Reflect는 같은 13종을 함수로 제공합니다.
- `set`·`deleteProperty`·`defineProperty` trap은 불리언을 반환해야 하며, 거짓이면 엄격 모드에서 `TypeError`입니다. `return true`를 빠뜨리지 않습니다.
- trap 안에서는 `Reflect.메서드(target, ..., receiver)`로 기본 동작을 전달합니다. receiver를 빼면 getter의 `this`와 상속된 객체의 대입이 어긋납니다.
- trap 결과가 target의 설정 불가·확장 불가 상태와 모순되면 불변식 위반으로 `TypeError`가 납니다.
- `Proxy.revocable`의 `revoke()`는 프록시를 영구히 무효화합니다.
- private 필드와 `Map`·`Date`·`Promise` 같은 내부 슬롯 객체는 프록시를 `this`로 받으면 `TypeError`입니다. 프록시는 target과 `===`가 아니고 직접 접근보다 느립니다.
