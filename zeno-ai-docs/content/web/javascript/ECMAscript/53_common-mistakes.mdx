## == 비교 함정

`==`(느슨한 동등)은 두 값의 타입이 다르면 변환한 뒤 비교합니다. `===`(엄격한 동등)은 변환하지 않고 타입과 값이 모두 같아야 `true`입니다(자세히는 06편, 08편).

```js
0 == ''           // true   ('' → 0)
0 == '0'          // true   ('0' → 0)
'' == '0'         // false  (둘 다 문자열, 변환 없음)
false == '0'      // true   (false → 0, '0' → 0)
null == undefined // true
null == 0         // false
[] == false       // true   ([] → '' → 0, false → 0)
[] == ![]         // true   (![] 는 false)
```

`==`의 변환 규칙은 다음 순서로 적용됩니다.

1. 타입이 같으면 `===`와 같은 결과입니다.
2. `null`과 `undefined`는 서로에게만 `true`이고 다른 값과는 `false`입니다.
3. 숫자와 문자열이면 문자열을 숫자로 바꿉니다.
4. 불리언이 한쪽에 있으면 불리언을 숫자(`true`는 1, `false`는 0)로 바꿉니다.
5. 객체와 원시 값이면 객체를 원시 값으로 바꿉니다(배열은 보통 문자열 `join` 결과).

`''`, `'0'`, `0`처럼 `a == b`와 `b == c`가 참인데 `a == c`는 거짓인 조합이 생기는 이유가 이 변환입니다. 관계 연산자도 `null`을 0으로 바꾸므로 `null >= 0`은 `true`, `null == 0`은 `false`입니다.

- 기본은 항상 `===`와 `!==`를 씁니다.
- 예외로 `x == null`은 `x`가 `null` 또는 `undefined`인지 한 번에 검사합니다. 팀 규칙으로 허용하는 경우가 많습니다.

### NaN과 -0의 비교

`NaN`은 자기 자신과도 같지 않습니다. `-0`은 `+0`과 같습니다. 두 값을 정확히 가리려면 `Object.is`를 씁니다.

| 식 | 결과 | 비고 |
|----|------|------|
| `NaN === NaN` | `false` | 어떤 비교 연산자로도 `NaN`을 찾을 수 없다 |
| `Object.is(NaN, NaN)` | `true` | 같은 값으로 취급 |
| `0 === -0` | `true` | |
| `Object.is(0, -0)` | `false` | 부호까지 구분 |
| `[NaN].indexOf(NaN)` | `-1` | `indexOf`는 `===` 방식 |
| `[NaN].includes(NaN)` | `true` | `includes`는 같은 값 방식 |

`NaN` 검사는 `Number.isNaN(x)`로 합니다. 전역 `isNaN('abc')`는 문자열을 숫자로 바꾼 뒤 검사하므로 `true`가 나옵니다. `Number.isNaN('abc')`는 `false`입니다.

## typeof null

`typeof null`은 `'object'`입니다. 1995년 초기 구현의 오류가 표준이 된 것이고, 기존 웹이 깨지므로 고치지 않습니다.

```js
typeof null       // 'object'
typeof []         // 'object'
typeof NaN        // 'number'
typeof function(){} // 'function'
typeof 10n        // 'bigint'
typeof undeclared // 'undefined' (에러 아님)
```

- `null` 확인은 `value === null`로 합니다.
- 객체 여부 확인은 `value !== null && typeof value === 'object'`로 합니다. 배열도 `'object'`이므로 배열 판별은 `Array.isArray(value)`입니다.
- 선언하지 않은 식별자에 `typeof`를 쓰면 에러 없이 `'undefined'`입니다. 단, 같은 스코프에서 나중에 `let`·`const`로 선언되는 이름(TDZ 구간)에 쓰면 `ReferenceError`입니다(자세히는 13편).
- 타입 판별 전반은 05편입니다.

## 부동소수점 비교

JavaScript의 `number`는 64비트 이진 부동소수점(IEEE 754 double)입니다. 0.1처럼 이진수로 딱 떨어지지 않는 소수는 근삿값으로 저장되어 연산 결과에 오차가 남습니다.

```js
0.1 + 0.2          // 0.30000000000000004
0.1 + 0.2 === 0.3  // false
19.99 * 100        // 1998.9999999999998
1.005.toFixed(2)   // '1.00' (1.01이 아님)
```

- 소수의 `===` 비교는 쓰지 않고 허용 오차로 비교합니다: `Math.abs(a - b) < Number.EPSILON`.
- `Number.EPSILON`(약 2.22e-16)은 1 근처 값에서만 맞는 오차입니다. 값이 커지면 오차도 커지므로 `1000000.1 + 0.2`와 `1000000.3`은 `EPSILON`으로 비교하면 `false`입니다. 큰 값에는 값에 비례한 오차(상대 오차)를 씁니다.
- 금액은 원·센트 같은 최소 단위의 정수로 계산합니다. `Math.round(19.99 * 100)`은 `1999`입니다.
- `toFixed`는 숫자가 아닌 문자열을 반환하고, 근삿값 기준으로 반올림하므로 사람이 기대하는 반올림과 다를 수 있습니다.
- 정수도 `Number.MAX_SAFE_INTEGER`(2^53 − 1, 9007199254740991)를 넘으면 정확하지 않습니다. `9007199254740992 === 9007199254740993`은 `true`입니다. 더 큰 정수는 BigInt를 씁니다(자세히는 05편).

## this 손실

메서드를 호출할 때 점 앞의 객체가 `this`가 됩니다. 메서드를 변수에 꺼내거나 콜백으로 넘기면 점이 사라져 `this`가 달라집니다(자세히는 21편).

```js
const user = { name: 'Kim', hello() { return this.name } }

user.hello()        // 'Kim'
const fn = user.hello
fn()                // 비엄격: 전역의 name, 엄격: TypeError
setTimeout(user.hello, 0)   // 같은 문제
const { hello } = user      // 같은 문제
```

- 일반 함수로 호출하면 비엄격 모드에서 `this`는 전역 객체, 엄격 모드(모듈과 클래스 본문 포함)에서는 `undefined`입니다. 비엄격 모드에서는 전역 객체의 `name`을 읽으므로 에러 없이 엉뚱한 값이 나옵니다(Node.js는 `undefined`, 브라우저의 `window.name`은 빈 문자열). 엄격 모드에서는 `undefined`의 프로퍼티를 읽게 되어 `TypeError`입니다.
- 일반 함수로 만든 콜백 안에서 `this`를 쓸 때도 같은 문제가 생깁니다.

해결 방법은 네 가지입니다.

| 방법 | 코드 |
|------|------|
| 바인딩 | `setTimeout(user.hello.bind(user), 0)` |
| 화살표 함수로 감싸기 | `setTimeout(() => user.hello(), 0)` |
| 클래스 필드 화살표 | `hello = () => this.name` |
| thisArg 전달 | `arr.forEach(user.hello, user)` |

## 클로저와 반복문

`var`는 함수당 바인딩이 하나입니다. 반복문 안에서 만든 콜백이 나중에 실행되면 모두 반복이 끝난 뒤의 같은 변수를 읽습니다(자세히는 23편).

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i))
}
// 3 3 3

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j))
}
// 0 1 2
```

- `for (let ...)`는 반복마다 새 바인딩을 만들기 때문에 각 콜백이 자기 반복의 값을 봅니다.
- `let`을 쓸 수 없던 시절에는 즉시 실행 함수(IIFE)로 반복마다 값을 인수로 복사했습니다.
- `let`이라도 반복문 밖에서 선언한 변수를 `while`로 증가시키면 바인딩이 하나이므로 `3 3 3`이 나옵니다.
- 이벤트 핸들러를 반복문으로 붙일 때도 같은 문제가 생깁니다.

## 참조 공유 버그

객체와 배열은 변수에 참조가 담깁니다. 대입이나 인수 전달은 객체를 복사하지 않고 참조만 복사하므로, 한쪽을 바꾸면 다른 쪽도 바뀝니다(자세히는 10편).

```js
const a = [1]
const b = a
b.push(2)
a                       // [1, 2]

const grid = new Array(3).fill([])
grid[0].push('x')
grid                    // [['x'], ['x'], ['x']]
```

`fill`은 같은 참조 하나를 모든 칸에 넣습니다. 칸마다 새 객체가 필요하면 생성 함수를 씁니다.

```js
const grid = Array.from({ length: 3 }, () => [])
grid[0].push('x')
grid                    // [['x'], [], []]
```

- 함수 인수로 받은 객체를 함수 안에서 바꾸면 호출한 쪽 객체가 바뀝니다. 바꾸지 않을 거라면 복사본을 만들어 작업합니다.
- 기본값 매개변수 `function f(list = [])`는 호출할 때마다 새로 평가되므로 공유되지 않습니다. 모듈 최상위에 둔 `const DEFAULTS = { tags: [] }`를 `{ ...DEFAULTS }`로 복사하면 `tags` 배열은 모든 복사본이 공유합니다(아래 얕은 복사).

## sort 기본 동작

`Array.prototype.sort()`는 비교 함수가 없으면 각 요소를 문자열로 바꿔 UTF-16 코드 단위 순서로 정렬합니다. 숫자 크기 순이 아닙니다(자세히는 28편).

```js
[10, 9, 1].sort()                // [1, 10, 9]
[10, 9, 1].sort((a, b) => a - b) // [1, 9, 10] 오름차순
[10, 9, 1].sort((a, b) => b - a) // [10, 9, 1] 내림차순
['b', 'a', 'B', 'A'].sort()      // ['A', 'B', 'a', 'b']
```

- 비교 함수는 음수, 0, 양수 중 하나를 반환해야 합니다. `(a, b) => a > b`는 `true`·`false`를 반환하는데 음수가 없으므로 결과가 보장되지 않습니다.
- `sort`는 원본 배열을 바꾸고 같은 배열을 반환합니다. `const sorted = arr.sort()`는 복사본이 아닙니다. 원본을 유지하려면 `[...arr].sort()` 또는 `arr.toSorted()`(ES2023)를 씁니다.
- `undefined`는 비교 함수를 거치지 않고 항상 맨 뒤로 가고, 빈 요소는 그 뒤에 놓입니다.
- 정렬은 안정 정렬입니다(ES2019부터 명세가 요구). 비교 결과가 같은 요소끼리는 원래 순서를 유지합니다.
- 문자열을 언어 규칙으로 정렬할 때는 `a.localeCompare(b)`나 `Intl.Collator`를 씁니다. 기본 정렬은 코드 단위 순서라 `'é'`가 `'z'` 뒤에 옵니다(자세히는 31편).

## forEach와 await

`forEach`는 콜백이 반환하는 값을 사용하지 않습니다. 콜백이 `async` 함수여도 반환된 프로미스를 기다리지 않고 다음 요소로 넘어가며, `forEach` 자체는 즉시 끝납니다(자세히는 29편, 43편).

```js
async function run() {
  [1, 2, 3].forEach(async (n) => {
    await sleep(100)
    console.log(n)
  })
  console.log('done')
}
// done → (약 100ms 뒤) 1 2 3
```

`done`이 먼저 출력되고, 세 콜백은 동시에 시작됩니다. 콜백 안에서 에러가 나면 호출한 쪽이 잡을 수 없는 처리되지 않은 거부가 됩니다.

| 원하는 동작 | 방법 | 실행 방식 |
|-------------|------|-----------|
| 하나씩 차례로 | `for (const n of arr) { await task(n) }` | 순차 |
| 전부 동시에 | `await Promise.all(arr.map(task))` | 병렬 |
| 결과 모으기 | `const rs = await Promise.all(arr.map(...))` | 병렬 |

- `map`에 `async` 콜백을 주면 값이 아닌 프로미스 배열이 나옵니다. `await Promise.all(...)`로 풀어야 합니다.
- `filter(async x => ...)`는 프로미스 객체가 항상 참으로 평가되어 아무것도 걸러지지 않습니다.
- 병렬 실행은 요청이 한꺼번에 나가므로 서버 부하나 호출 제한이 문제라면 동시 실행 수를 제한해야 합니다.

## 비동기 에러 누락

`try/catch`는 try 블록이 실행되는 동안 던져진 에러만 잡습니다. 나중에 실행되는 코드의 에러와 `await`하지 않은 프로미스의 거부는 잡지 못합니다(자세히는 44편).

```js
async function fail() { throw new Error('x') }

async function f1() {
  try { fail() } catch (e) { return 'caught' }  // ❌ 잡지 못함
  return 'no'
}
async function f2() {
  try { await fail() } catch (e) { return 'caught' }  // ✅
}
```

`f1()`은 `'no'`를 반환하고, 거부된 프로미스는 아무도 처리하지 않습니다. 세 가지 경우가 흔합니다.

- **await 누락**: 위 `f1`처럼 프로미스를 기다리지 않으면 거부가 try 밖으로 새어 나갑니다.
- **return 뒤 await 누락**: `try { return fail() } catch {}`는 프로미스를 그대로 반환할 뿐이므로 catch가 실행되지 않습니다. `return await fail()`이어야 catch가 잡습니다.
- **콜백 안 throw**: `try { setTimeout(() => { throw new Error() }) } catch {}`의 에러는 나중에 별도의 작업에서 발생하므로 catch가 잡지 못합니다. 프로미스로 감싸 거부로 바꾸거나 콜백 안에서 처리합니다.

프로미스 체인에서는 끝에 `.catch()`가 없으면 중간 거부가 처리되지 않습니다. `.then(onOk, onFail)`의 `onFail`은 앞 단계의 거부만 처리하고 같은 `.then`의 `onOk`에서 난 에러는 잡지 못합니다(자세히는 41편).

처리되지 않은 거부는 브라우저에서 `unhandledrejection` 이벤트와 콘솔 에러를 일으키고, Node.js 15 이상에서는 기본값으로 프로세스를 종료합니다.

## ASI

자동 세미콜론 삽입(ASI, Automatic Semicolon Insertion)은 파서가 줄바꿈을 보고 세미콜론을 보충하는 규칙입니다. 다음 줄이 앞 줄과 문법적으로 이어질 수 있으면 삽입하지 않습니다(자세히는 04편).

```js
const a = 1
[1, 2].forEach(console.log)
// TypeError: Cannot read properties of undefined
// (const a = 1[1, 2].forEach(...) 로 해석)

const b = 1
const c = b
(function () {})()
// TypeError: b is not a function
```

- 줄이 `(`, `[`, `` ` ``(템플릿), `+`, `-`, `/`로 시작하면 앞 줄에 이어붙을 위험이 있습니다. 세미콜론을 쓰지 않는 스타일에서는 이런 줄 앞에 `;`를 붙입니다.
- 줄바꿈이 허용되지 않는 자리(제한 생성)에서는 반대로 세미콜론이 삽입됩니다. 대상은 `return`, `break`, `continue`, `throw`, `yield`, 후위 `++`·`--`, 화살표 `=>` 앞입니다.

```js
function make() {
  return
  { ok: true }
}
make()  // undefined (return; 으로 해석)
```

- `return` 뒤에서는 반환할 값을 같은 줄에서 시작해야 합니다. 여는 괄호(`{`, `(`, `[`)를 `return`과 같은 줄에 둡니다.

## parseInt와 map

`['1', '2', '3'].map(parseInt)`는 `[1, 2, 3]`이 아니라 `[1, NaN, NaN]`입니다. `map`은 콜백에 `(요소, 인덱스, 배열)` 세 인수를 넘기는데, `parseInt(문자열, 진법)`의 둘째 인수가 진법이라서 인덱스가 진법으로 들어갑니다.

| 호출 | 결과 | 이유 |
|------|------|------|
| `parseInt('1', 0)` | `1` | 진법 0은 지정하지 않은 것으로 보고 10진법 |
| `parseInt('2', 1)` | `NaN` | 진법은 2에서 36까지만 유효 |
| `parseInt('3', 2)` | `NaN` | 2진법에 `3`은 없는 숫자 |

```js
['1', '2', '3'].map(parseInt)           // [1, NaN, NaN]
['1', '2', '3'].map(Number)             // [1, 2, 3]
['1', '2', '3'].map((s) => parseInt(s, 10)) // [1, 2, 3]
```

- 인수 개수가 다른 함수를 콜백으로 직접 넘기면 남는 인수가 의도하지 않은 매개변수로 들어갑니다. `['a', 'b'].map(console.log)`가 인덱스와 배열까지 출력하는 것도 같은 이유입니다.
- `parseInt`와 `Number`의 차이를 구분합니다.

| 입력 | `parseInt(x)` | `Number(x)` |
|------|---------------|-------------|
| `'12px'` | `12` | `NaN` |
| `''` | `NaN` | `0` |
| `'1e3'` | `1` | `1000` |

- `parseInt`는 숫자가 아닌 첫 문자 앞까지만 읽습니다. 숫자를 인수로 주면 먼저 문자열로 바꾸므로 `parseInt(0.0000005)`는 `'5e-7'`을 읽어 `5`입니다. 항상 문자열과 진법 10을 함께 씁니다(자세히는 30편).

## 배열 빈 요소

빈 요소(empty slot)가 있는 배열을 희소 배열이라고 합니다. 빈 요소는 값이 `undefined`인 요소와 다릅니다. 해당 인덱스에 프로퍼티 자체가 없습니다(자세히는 28편).

```js
const a = [1, , 3]        // 리터럴의 연속 쉼표
new Array(3)              // [ <3 empty items> ]
const b = [1, 2, 3]
delete b[1]               // [1, <1 empty item>, 3]
b.length = 5              // 끝에 빈 요소 추가
1 in a                    // false
```

메서드마다 빈 요소를 다루는 방식이 다릅니다.

| 방식 | 빈 요소 처리 |
|------|--------------|
| `forEach`, `map`, `filter`, `reduce`, `some`, `every` | 건너뜀 (`map`은 빈 요소를 유지) |
| `for...of`, 스프레드, `Array.from`, `find`, `includes`, `join` | `undefined`로 취급 |
| `indexOf` | 건너뜀 (`[,1].indexOf(undefined)`는 `-1`) |
| `Object.keys`, `in` | 존재하지 않는 인덱스로 처리 |
| `JSON.stringify` | `null` |

가장 흔한 실수는 `new Array(3).map((_, i) => i)`입니다. `map`이 빈 요소를 건너뛰어 길이 3의 빈 배열이 그대로 나옵니다.

```js
Array.from({ length: 3 }, (_, i) => i)  // [0, 1, 2]
[...Array(3).keys()]                    // [0, 1, 2]
Array(3).fill(0)                        // [0, 0, 0]
```

- `new Array(3)`은 길이 3의 빈 배열이고, `new Array('3')`은 `['3']`이며, `new Array(3, 4)`는 `[3, 4]`입니다. 요소 하나짜리 배열은 `Array.of(3)`으로 만듭니다.
- 요소를 지울 때 `delete arr[i]`가 아니라 `splice`를 씁니다.

## Date의 월

`Date` 생성자와 `getMonth`·`setMonth`의 월은 0부터 11입니다. 1월이 0, 12월이 11입니다. 일(`getDate`)은 1부터 31이지만, 요일(`getDay`)은 일요일이 0입니다(자세히는 31편).

```js
new Date(2026, 0, 1).getMonth()  // 0 (2026년 1월 1일)
new Date(2026, 12, 1).getFullYear() // 2027 (12월은 없음 → 다음 해)
new Date(2026, 1, 31).getMonth() // 2 (2월 31일 → 3월 3일)
new Date(2026, 3, 0).getDate()   // 31 (4월 0일 → 3월 31일)
```

- 범위를 넘는 값은 에러 없이 이월됩니다. 월 `m + 1`의 0일을 만들면 `m`월의 마지막 날을 구할 수 있는 것도 이 규칙입니다.
- 1월 31일에서 `setMonth(1)`을 하면 2월 31일이 이월되어 3월 3일이 됩니다.
- 연도 인수가 0에서 99 사이이면 1900을 더합니다. `new Date(26, 0, 1).getFullYear()`는 `1926`입니다. `getYear()`는 연도에서 1900을 뺀 값(`126`)을 반환하는 폐기된 메서드이므로 `getFullYear()`를 씁니다.
- `Date`는 가변 객체입니다. `setDate`·`setMonth` 등은 객체를 직접 바꿉니다.

문자열 해석도 함정입니다.

| 문자열 | 해석 기준 |
|--------|-----------|
| `'2026-01-01'` (날짜만) | UTC 자정 |
| `'2026-01-01T00:00:00'` (시간 있고 오프셋 없음) | 로컬 시간 |
| `'2026-1-5'` 같은 비표준 형식 | 엔진마다 다름 |

날짜만 있는 문자열은 UTC 자정이므로, UTC보다 시각이 이른 시간대(미국 동부 등, UTC−5)에서는 `getDate()`가 전날을 가리킵니다. `new Date('2026-01-01')`을 뉴욕 시간으로 보면 2025년 12월 31일 오후 7시입니다. 형식은 `YYYY-MM-DD`나 `YYYY-MM-DDTHH:mm:ssZ`처럼 표준 형식만 씁니다.

## const 객체 변경

`const`는 변수에 다시 대입하는 것을 막을 뿐, 변수가 가리키는 객체의 내용을 막지 않습니다(자세히는 03편).

```js
const list = []
list.push(1)       // [1] — 허용
list = [2]         // TypeError (상수에 재대입)

const cfg = { port: 80 }
cfg.port = 8080    // 허용
```

- 내용 변경을 막으려면 `Object.freeze(obj)`를 씁니다. 비엄격 모드에서는 쓰기가 조용히 무시되고, 엄격 모드에서는 `TypeError`입니다(자세히는 14편).
- `freeze`는 얕습니다. 최상위 프로퍼티만 막고, 중첩 객체는 그대로 바뀝니다. 중첩까지 막으려면 재귀로 `freeze`를 호출해야 합니다.
- `for (const i = 0; i < 3; i++)`는 `i++`에서 `TypeError`가 납니다. 값이 바뀌는 카운터는 `let`을 씁니다. `for (const x of arr)`는 반복마다 새 바인딩이므로 정상입니다.

## JSON 복사의 손실

`JSON.parse(JSON.stringify(obj))`는 JSON으로 표현할 수 있는 값만 남기므로 복사 과정에서 값이 바뀌거나 사라집니다(자세히는 39편).

```js
const src = { d: new Date(0), u: undefined, f() {},
  n: NaN, m: new Map([[1, 2]]), arr: [undefined] }

JSON.parse(JSON.stringify(src))
// { d: '1970-01-01T00:00:00.000Z', n: null,
//   m: {}, arr: [null] }
```

| 원본 값 | 복사 결과 |
|---------|-----------|
| `undefined`, 함수, Symbol | 객체 프로퍼티는 사라짐, 배열 요소는 `null` |
| `NaN`, `Infinity` | `null` |
| `-0` | `0` |
| `Date` | ISO 문자열 (Date 객체가 아님) |
| `Map`, `Set`, `RegExp` | `{}` |
| 클래스 인스턴스 | 프로토타입이 사라진 일반 객체 (메서드·getter 소실) |
| 순환 참조 | `TypeError` |
| `BigInt` | `TypeError` |

`structuredClone(obj)`는 이런 값을 대부분 보존하는 깊은 복사입니다. ECMAScript가 아니라 호스트 API(01편)이며, 현재 주요 브라우저와 Node.js 17 이상에서 쓸 수 있습니다.

- 보존: `Date`, `Map`, `Set`, `RegExp`, `undefined` 값, `NaN`, `BigInt`, `-0`, 순환 참조.
- 실패: 함수가 있으면 `DataCloneError`.
- 클래스 인스턴스는 프로토타입을 잃고 일반 객체가 됩니다. 인스턴스를 복사하려면 클래스에 복사 메서드를 직접 만듭니다.

## 화살표 함수 메서드

화살표 함수는 자기 `this`가 없고 정의된 자리의 `this`를 그대로 씁니다. 객체 리터럴의 메서드를 화살표 함수로 만들면 `this`가 객체가 아니라 바깥 스코프의 `this`입니다(자세히는 27편, 21편).

```js
const counter = {
  count: 0,
  inc: () => { this.count++ },   // ❌ this는 counter가 아님
  dec() { this.count-- },        // ✅
}
counter.inc()
counter.count  // 0 (변하지 않음)
```

모듈 최상위의 `this`는 실행 환경에 따라 다릅니다.

| 환경 | 최상위 `this` | `inc()` 결과 |
|------|---------------|--------------|
| Node.js CommonJS | `module.exports` | 에러 없이 엉뚱한 객체의 `count`가 `NaN`이 됨 |
| ES 모듈 | `undefined` | `TypeError` |
| 브라우저 일반 스크립트 | `window` | `window.count`가 `NaN`이 됨 |

화살표 함수가 맞지 않는 곳은 더 있습니다.

- `prototype`이 없고 `new`로 호출할 수 없습니다(`TypeError`). 생성자와 프로토타입 메서드는 일반 함수나 `class`를 씁니다.
- 자체 `arguments`가 없습니다. 나머지 매개변수 `...args`를 씁니다.
- `call`·`apply`·`bind`로 `this`를 바꿀 수 없습니다.
- 이벤트 핸들러에서 `this`로 이벤트 대상 요소를 쓰려는 경우에 맞지 않습니다.

화살표 함수가 필요한 곳은 메서드 안에서 `this`를 유지해야 하는 콜백입니다. 클래스 필드의 화살표(`f = () => this`)는 인스턴스를 고정하므로 꺼내 써도 `this`가 유지됩니다. 대신 인스턴스마다 함수가 새로 만들어지고 프로토타입으로 공유되지 않습니다.

## 얕은 복사

얕은 복사는 최상위 한 단계만 새로 만들고, 그 안의 객체는 참조를 그대로 가져옵니다(자세히는 10편, 36편).

```js
const a = { n: { x: 1 }, l: [1] }
const b = { ...a }
b.n.x = 2
b.l.push(2)
a   // { n: { x: 2 }, l: [1, 2] } — 원본도 바뀜
```

아래는 모두 얕은 복사입니다.

- 객체: `{ ...obj }`, `Object.assign({}, obj)`
- 배열: `[...arr]`, `arr.slice()`, `arr.concat()`, `Array.from(arr)`

객체 배열에서 `const copy = [...users]`로 복사해도 요소 객체는 같은 참조입니다. 요소를 바꾸려면 요소도 복사합니다.

```js
const copy = users.map((u) => ({ ...u }))
copy[0].n = 9    // users[0].n 은 그대로
```

중첩 구조는 세 가지 방법으로 다룹니다.

| 방법 | 특징 |
|------|------|
| `structuredClone(obj)` | 전체 깊은 복사 (함수 불가) |
| 변경 경로만 새로 만들기 | `{ ...s, n: { ...s.n, x: 2 } }` — 바꾸는 가지만 복사하고 나머지는 공유 |
| 라이브러리 | 불변 업데이트 도구 등 |

## 프로미스 반환 누락

`.then` 콜백이 값이나 프로미스를 반환해야 다음 `.then`이 그 결과를 받습니다. 반환하지 않으면 다음 단계는 기다리지 않고 `undefined`를 받습니다(자세히는 41편).

```js
getUser()
  .then((u) => { getPosts(u.id) })      // ❌ return 없음
  .then((posts) => console.log(posts))  // undefined

getUser()
  .then((u) => getPosts(u.id))          // ✅ 프로미스 반환
  .then((posts) => console.log(posts))  // ['post1']
```

- 화살표 함수에서 본문을 중괄호로 감싸면 `return`을 직접 써야 합니다. 중괄호 없이 식만 쓰면 그 값이 자동으로 반환됩니다.
- 반환하지 않은 프로미스가 거부되면 체인의 `.catch()`가 잡지 못하고 처리되지 않은 거부가 됩니다. 체인이 끊어지기 때문입니다.

`async` 함수를 호출하면서 `await`를 빠뜨리는 것도 같은 계열의 실수입니다(자세히는 43편). 결과가 값이 아니라 프로미스 객체입니다.

```js
const user = fetchUser()   // ❌ await 누락
user.name                  // undefined (프로미스에는 name이 없음)
if (user) { }              // 항상 참 (프로미스 객체)
user + 1                   // '[object Promise]1'
```

- `async` 함수 안에서 `return`을 쓰지 않으면 `undefined`로 이행하는 프로미스를 반환합니다.
- `await user`를 쓰면 값이 나오므로, 프로미스가 필요 없는 자리에는 `await`를 붙입니다.

## 핵심 정리

- `==`는 변환 규칙이 복잡해 `===`를 기본으로 쓰고, `NaN`은 `Number.isNaN`·`Object.is`로, `null`은 `=== null`로 검사합니다. 소수는 정수 단위나 허용 오차로 비교합니다.
- `this`는 호출 방식으로 결정되므로 메서드를 꺼내 넘기면 잃습니다. `bind`·화살표 래퍼로 고정하고, 객체 메서드를 화살표로 만들지 않습니다. `var`는 반복 콜백이 같은 변수를 공유하므로 `let`을 씁니다.
- 대입·`fill`·스프레드·`slice`는 객체를 공유합니다. 깊은 복사가 필요하면 `structuredClone`을 쓰고, `JSON` 복사는 `undefined`·함수·`Date`·`Map`을 잃습니다. `const`는 재대입만 막습니다.
- `sort()`는 문자열 순서이므로 비교 함수가 필요하고 원본을 바꿉니다. `map(parseInt)`는 인덱스가 진법이 되며, 빈 요소는 메서드마다 다르게 처리됩니다. `Date`의 월은 0부터입니다.
- `forEach`는 `async` 콜백을 기다리지 않고, `try/catch`는 `await`하지 않은 프로미스를 잡지 못합니다. `.then` 콜백은 `return`해야 체인이 이어집니다. 줄이 `(`·`[`로 시작하면 ASI가 삽입되지 않습니다.
