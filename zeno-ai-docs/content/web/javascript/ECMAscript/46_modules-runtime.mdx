## 핵심 먼저 보기

- 모듈은 구성(그래프 구축) → 인스턴스화(바인딩 연결) → 평가(본문 실행) 순서로 처리되고, 구문·연결 오류는 어떤 코드도 실행되기 전에 드러납니다.
- 모듈은 URL을 키로 한 번만 평가되고 결과가 공유됩니다. 순환에서는 `let`·`const`·`class`가 TDZ에 걸려 ReferenceError가 날 수 있습니다.
- Top-level await는 의존하는 모듈을 지연시키고 형제 모듈은 병렬로 진행합니다. 영원히 끝나지 않으면 Node.js가 종료 코드 13을 반환합니다.
- 정적 분석 덕분에 번들러가 트리 셰이킹을 하며, 배럴 파일은 `sideEffects` 선언이 없으면 불필요한 모듈을 로드하게 만듭니다.
- 브라우저는 `type="module"`과 임포트 맵, Node.js는 `.mjs`·`type: module`과 필수 확장자를 씁니다. CommonJS에서는 `require(esm)`이 동기 ESM에 한해 가능하고, `exports` 조건은 키 순서대로 평가됩니다.

## 모듈 로딩 3단계

ES 모듈은 구성(construction), 인스턴스화(instantiation), 평가(evaluation) 세 단계로 처리됩니다. 한 모듈의 본문은 세 단계를 모두 거친 뒤에야 실행되기 시작합니다.

| 단계 | 하는 일 | 코드 실행 |
|------|---------|-----------|
| 구성 | 지정자를 URL로 해석하고, 파일을 가져와 파싱하고, 그 안의 `import`를 찾아 의존 모듈을 재귀로 가져온다. 결과는 모듈 그래프 | 없음 |
| 인스턴스화 | 모듈마다 export 바인딩의 메모리 칸을 만들고, import 바인딩을 상대 모듈의 칸에 연결한다 | 없음 |
| 평가 | 본문을 실행해 칸에 값을 채운다 | 있음 |

```js
// o0.mjs
console.log('o0 start')
import './o1.mjs' // 본문: console.log('o1')
import './o2.mjs' // 본문: console.log('o2')
console.log('o0 end')
// 출력: o1, o2, o0 start, o0 end
```

## 단일 실행과 캐싱

한 모듈은 같은 환경에서 한 번만 평가되고, 모든 importer가 같은 인스턴스를 공유합니다. 로더가 모듈 맵(module map)에 해석된 URL을 키로 기록해 두고, 이미 있으면 다시 가져오지도 실행하지도 않습니다.

```js
// once.mjs
console.log('once evaluated')
export let n = 0
export const inc = () => { n++ }

// main.mjs
import './once.mjs'              // once evaluated
import { n, inc } from './once.mjs' // 실행 안 함
await import('./once.mjs')       // 실행 안 함
await import('./once.mjs?v=2')   // once evaluated (다른 URL)
```

## 순환 참조

순환 참조는 모듈 A가 B를 import하고 B가 다시 A를 import하는 관계입니다. ESM은 에러 없이 로드되지만, 평가 순서 때문에 아직 값이 채워지지 않은 바인딩을 읽을 수 있습니다.

| 선언 | 순환 중 B가 먼저 실행될 때 |
|------|----------------------------|
| `function` 선언 | 사용 가능 |
| `let`·`const`·`class` | TDZ. 읽으면 ReferenceError (`typeof`도 에러) |
| `var` | `export var`는 `undefined` |

## Top-level await와 모듈 그래프

Top-level await(ES2022)는 모듈 최상위에서 `await`를 쓰는 기능입니다. 사용한 모듈은 비동기 모듈이 되어, 그 모듈의 평가가 프로미스가 끝날 때까지 이어집니다.

## 정적 분석과 트리 셰이킹

트리 셰이킹은 정적 import·export 관계를 분석해 사용하지 않는 코드를 제거합니다. 부수 효과가 있는 최상위 코드는 남을 수 있습니다. ESM이라고 모든 미사용 코드가 자동 제거되는 것은 아니며 번들러 설정과 패키지의 부수 효과 표기도 영향을 줍니다.

## 배럴 파일의 비용

배럴 파일(barrel file)은 여러 모듈의 export를 한곳에서 다시 내보내는 `index.js`입니다.

| 대응 | 방법 |
|------|------|
| 직접 경로 import | `import { Button } from './components/Button.js'` |
| 라이브러리 배럴 | `sideEffects: false`를 선언해 번들러가 통째로 제거할 수 있게 한다 |
| 큰 아이콘·유틸 패키지 | Next.js는 `experimental.optimizePackageImports`로 쓰는 모듈만 로드하게 한다. lucide-react, date-fns, lodash-es 등은 기본 적용 (문서상 실험 기능) |
| 배럴을 쓸 곳 | 패키지의 공개 진입점으로만. 앱 내부 폴더에는 쓰지 않는 쪽이 안전 |

## 브라우저의 ESM

브라우저는 `<script type="module">`로 ES 모듈을 실행합니다. 클래식 스크립트와 다음이 다릅니다.

| 항목 | 모듈 스크립트 |
|------|---------------|
| 실행 시점 | 기본이 defer. HTML 파싱이 끝난 뒤 문서 순서대로 실행 (`defer` 속성은 무의미) |
| `async` 속성 | 의존 모듈까지 병렬로 가져와 준비되는 즉시 실행. 인라인 모듈에도 적용 |
| 같은 URL 중복 | 여러 번 써도 한 번만 실행 |
| 모드 | 항상 strict mode, 최상위 `this`는 `undefined` |
| 스코프 | 모듈 스코프. 최상위 `var`·함수가 `window` 프로퍼티가 되지 않음 |
| 교차 출처 | CORS 필수 |

## Node.js의 ESM

Node.js는 기본이 CommonJS이고, 다음 중 하나일 때 ESM으로 실행합니다.

| 조건 | 예 |
|------|----|
| 확장자 `.mjs` | `app.mjs` (항상 ESM) |
| package.json의 `"type": "module"` | 같은 패키지의 `.js`가 ESM |
| `--input-type=module` | 표준 입력·`-e` 코드 |
| 문법 감지 | `type` 없는 `.js`에 `import`·`export`가 있으면 ESM으로 판단 (최근 버전) |

## import.meta.dirname

`import.meta.dirname`은 현재 모듈 파일이 있는 디렉터리의 절대 경로이고, `import.meta.filename`은 파일 자체의 절대 경로입니다. CommonJS의 `__dirname`·`__filename`에 대응합니다.

## ESM과 CommonJS 상호 운용

두 시스템은 로드 방식, 값 전달, 캐시가 모두 다르지만 Node.js는 서로 불러오는 경로를 제공합니다.

| 구분 | CommonJS | ESM |
|------|----------|-----|
| 로드 | 동기 (`require`) | 비동기 가능 (최상위 `await`) |
| 값 전달 | `module.exports` 객체의 참조 | 라이브 바인딩 |
| 의존 파악 | 실행 중 | 실행 전 (정적) |
| 최상위 `this` | `module.exports` | `undefined` |
| strict mode | 선택 | 항상 |
| 캐시 | `require.cache` | URL 기반 별도 캐시 |

## require로 ESM 불러오기

`require()`는 ES 모듈 파일을 동기적으로 불러와 모듈 네임스페이스 객체를 반환할 수 있습니다. ESM 전용으로 배포된 패키지를 CommonJS 코드가 그대로 쓰게 해 줍니다.

| 조건 | 결과 |
|------|------|
| 그래프에 최상위 `await`가 있음 | `ERR_REQUIRE_ASYNC_MODULE` |
| `require`하는 ESM 사이에 순환이 있음 | `ERR_REQUIRE_CYCLE_MODULE` |

## package.json exports와 조건부 exports

`exports`는 패키지가 외부에 공개하는 진입점을 선언하는 package.json 필드입니다. `main`보다 우선하고, 선언하지 않은 경로는 접근할 수 없도록 패키지를 캡슐화합니다.

| 조건 | 뜻 |
|------|----|
| `import` | `import`·`import()`로 불러올 때 |
| `require` | `require()`로 불러올 때 |
| `node` | Node.js 환경 |
| `module-sync` | `import`와 `require` 양쪽에서 쓸 수 있는 동기 ESM |
| `types` | TypeScript가 읽는 타입 선언. 먼저 써야 한다 |
| `browser`, `development`, `production` | 번들러가 쓰는 관례. Node.js에서는 사용자 정의 조건 |
| `default` | 어느 조건도 맞지 않을 때의 대체. 항상 마지막 |
