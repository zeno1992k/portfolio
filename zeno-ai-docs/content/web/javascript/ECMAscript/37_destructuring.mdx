## 디스트럭처링 할당이란

디스트럭처링 할당(destructuring assignment, 구조 분해 할당)은 배열이나 객체에서 값을 꺼내 여러 변수에 한 번에 할당하는 문법입니다(ES2015). 꺼낼 값의 구조를 본뜬 패턴을 `=` 왼쪽에 쓰고, 오른쪽 값에서 패턴과 맞는 부분을 꺼냅니다.

```js
const [x, y] = [1, 2]
const { id, name } = { id: 7, name: 'Kim' }
// x = 1, y = 2
// id = 7, name = 'Kim'
```

패턴은 두 종류입니다.

| 구분 | 배열 패턴 `[a, b]` | 객체 패턴 `{a, b}` |
|------|-------------------|--------------------|
| 값을 찾는 기준 | 이터레이터가 내놓는 순서 | 프로퍼티 이름 |
| 오른쪽 값의 조건 | 이터러블 | null·undefined가 아닌 값 |
| 순서 | 중요 | 무관 |
| 대응하는 값이 없을 때 | undefined | undefined |

패턴을 쓸 수 있는 자리는 다섯 곳입니다.

| 자리 | 예 |
|------|----|
| 변수 선언 | `const { a } = obj` |
| 할당식 | `({ a } = obj)` |
| 함수 매개변수 | `function f({ a }, [b]) {}` |
| for-in·for-of의 머리 | `for (const [k, v] of entries) {}` |
| catch 매개변수 | `catch ({ message }) {}` |

선언과 매개변수 같은 자리의 패턴은 **바인딩 패턴**(새 변수를 만든다), 키워드 없는 할당식의 패턴은 **할당 패턴**(이미 있는 대상에 넣는다)입니다. 두 패턴은 문법이 거의 같지만 다음이 다릅니다.

| 구분 | 바인딩 패턴 | 할당 패턴 |
|------|-------------|-----------|
| 대상 | 새로 만들 식별자만 | 변수, 프로퍼티(`o.x`), 요소(`a[0]`) |
| 초기화 | 필수. `let [a];`는 SyntaxError (for-in·for-of 머리는 예외) | 해당 없음 |
| 같은 이름 두 번 | `let`·`const`는 SyntaxError, `var`는 허용 | 허용 |

- 꺼낸 값은 복사되지 않습니다. 값이 객체이면 원본과 같은 참조를 얻습니다(얕다).
- 패턴의 왼쪽 항목부터 차례로 꺼내고 바로 할당합니다. 할당 패턴에서 중간에 에러가 나면 앞쪽 대상에는 이미 값이 들어가 있습니다.
- `const`로 만든 바인딩에 할당 패턴으로 다시 넣으면 TypeError입니다.

## 배열 디스트럭처링

배열 패턴은 이터러블에서 값을 순서대로 꺼내 변수에 할당합니다. 배열뿐 아니라 이터러블이면 무엇이든 됩니다(이터러블은 35편).

```js
const [a, b] = [10, 20, 30]
// a = 10, b = 20 (30은 쓰이지 않는다)
const [c, d, e] = [1, 2]
// c = 1, d = 2, e = undefined
```

- 값이 변수보다 많으면 남는 값은 버려지고, 적으면 남는 변수는 undefined가 됩니다.
- 인덱스가 아니라 이터레이터로 꺼냅니다. `Symbol.iterator`를 호출해 이터레이터를 얻고, 패턴이 필요로 하는 횟수만큼 `next()`를 호출합니다.
- 문자열은 코드 포인트 단위로, Set은 삽입 순서로, Map은 `[키, 값]` 쌍 단위로 꺼냅니다(자세히는 35편, 38편).

```js
const [x, y] = 'hi'              // x = 'h', y = 'i'
const [e] = '😀a'                // e = '😀'
const [first] = new Set([5, 6])  // first = 5
const [[k, v]] = new Map([['a', 1]])
// k = 'a', v = 1
```

이터러블이 아닌 값은 TypeError입니다.

```js
const [p] = {}    // TypeError
const [q] = null  // TypeError
const [r] = 1     // TypeError
```

- 유사 배열(`{ 0: 'x', length: 1 }`)도 이터러블이 아니므로 TypeError입니다. 인덱스로 꺼내려면 객체 패턴을 씁니다: `const { 0: first, length } = arrayLike`.
- 빈 패턴 `const [] = iterable`은 값을 꺼내지 않지만, 오른쪽이 이터러블이어야 한다는 조건은 그대로입니다.

필요한 만큼만 꺼내므로 이터레이터가 끝나지 않았으면 패턴은 이터레이터를 닫습니다. 이터레이터의 `return()`을 호출하는 것이며, 제너레이터라면 `finally` 블록이 실행됩니다(자세히는 35편, 42편).

```js
function* gen() {
  try { yield 1; yield 2; yield 3 }
  finally { console.log('closed') }
}
const [a, b] = gen()
// 출력: closed
// a = 1, b = 2
```

변수가 값보다 많아 `next()`가 완료(`done: true`)를 돌려받으면 이터레이터가 이미 끝난 것이므로 `return()`을 호출하지 않습니다. 위 예에서 변수가 네 개이면 닫기 호출이 없습니다. Rest 요소도 이터레이터를 끝까지 소진하므로 닫지 않습니다.

## 기본값과 건너뛰기

건너뛰기는 쉼표로 자리를 비워 그 위치의 값을 무시하는 문법이고, 기본값은 `= 식`으로 값이 없을 때 쓸 값을 정하는 문법입니다.

### 건너뛰기

```js
const [, second] = [1, 2, 3]       // second = 2
const [one, , three] = [1, 2, 3]   // one = 1, three = 3
const [, ...rest] = [1, 2, 3]      // rest = [2, 3]
```

- 건너뛴 자리도 이터레이터에서 값을 하나 꺼내고 버립니다.
- 끝의 쉼표는 개수에 따라 다릅니다. `[a,]`의 쉼표는 후행 쉼표라 값을 하나만 꺼내고, `[a, ,]`는 건너뛰기가 하나 있어 둘을 꺼냅니다.

### 기본값

```js
const [a = 1, b = 2] = [undefined, null]
// a = 1 (undefined라서 기본값), b = null
const [x = 1, y = x + 1] = []
// x = 1, y = 2
```

- 기본값은 해당 자리의 값이 undefined일 때만 쓰입니다(규칙은 뒤의 "기본값은 undefined일 때만" 절).
- 기본값은 임의의 식이고, 필요할 때만 평가됩니다. 값이 있으면 식 자체가 실행되지 않습니다.

```js
const f = () => { console.log('f 호출'); return 9 }
const [p = f()] = [1]  // 출력 없음, p = 1
const [q = f()] = []   // 출력: f 호출, q = 9
```

- 기본값 식은 패턴에서 앞에 만들어진 변수를 쓸 수 있습니다(`y = x + 1`). 뒤에 오는 변수를 쓰면 아직 초기화 전이라 ReferenceError입니다(TDZ, 자세히는 13편).

```js
const [m = n, n = 1] = []  // ReferenceError
```

- 배열의 빈 슬롯(`[, 5]`)도 읽으면 undefined이므로 기본값이 적용됩니다.
- 익명 함수를 기본값으로 쓰면 변수 이름이 함수의 `name`이 됩니다. `const { cb = () => {} } = {}`에서 `cb.name`은 `'cb'`입니다(자세히는 16편).

## Rest 요소

Rest 요소는 배열 패턴 끝의 `...변수`로, 이터레이터의 남은 값을 모두 꺼내 새 배열에 담습니다.

```js
const [head, ...tail] = [1, 2, 3, 4]
// head = 1, tail = [2, 3, 4]
const [only, ...none] = [1]
// only = 1, none = []
```

- 남은 값이 없으면 빈 배열이 됩니다. 이터러블이 문자열이나 Set이어도 결과는 배열입니다.
- 패턴의 맨 마지막에만 쓸 수 있습니다. 뒤에 다른 항목이나 쉼표가 오면 SyntaxError입니다.
- 기본값을 붙일 수 없습니다(`[...r = []]`는 SyntaxError). 남은 값이 없어도 빈 배열이 만들어지므로 필요가 없습니다.
- 이터레이터를 끝까지 소진합니다. 끝이 없는 이터러블(무한 제너레이터)에 쓰면 종료되지 않습니다.
- 대상은 변수뿐 아니라 패턴도 될 수 있습니다.

```js
const [a, ...[b, c]] = [1, 2, 3, 4]
// a = 1, b = 2, c = 3
const [...{ length }] = 'hello'
// length = 5
```

- `const [...copy] = arr`은 배열의 얕은 복사입니다. 펼치는 스프레드와 방향이 반대이며(자세히는 36편), 함수 매개변수의 Rest(자세히는 27편)와 같은 모양의 문법입니다.

## 객체 디스트럭처링

객체 패턴은 이름이 같은 프로퍼티를 읽어 같은 이름의 변수에 할당합니다. `{ a }`는 `{ a: a }`의 단축 표기입니다.

```js
const { a, b } = { b: 2, a: 1 }
// a = 1, b = 2 (순서는 상관없다)
const { z } = { a: 1 }
// z = undefined
```

- 객체 리터럴의 단축 프로퍼티(09편)와 같은 모양이지만 방향이 반대입니다. 리터럴은 변수에서 프로퍼티를 만들고, 패턴은 프로퍼티에서 변수를 만듭니다.
- 프로퍼티를 일반 조회(`obj.a`)로 읽습니다. 프로토타입에서 상속한 프로퍼티도 읽히고, getter는 항목마다 한 번씩 호출됩니다.
- 읽는 순서는 객체의 프로퍼티 순서가 아니라 패턴의 왼쪽에서 오른쪽입니다.
- 없는 프로퍼티는 에러가 아니라 undefined입니다.
- 오른쪽이 원시값이면 객체로 변환해 읽습니다. null과 undefined만 예외입니다(마지막 절).

```js
const { length } = 'abc'   // length = 3
const { toFixed } = 1      // 숫자의 메서드 (함수)
const { toString } = {}    // 상속 프로퍼티 (함수)
const { a } = 1            // a = undefined
```

- 배열도 객체이므로 인덱스를 키로 꺼낼 수 있습니다: `const { 0: first, length } = ['x', 'y']`는 `first = 'x'`, `length = 2`입니다.
- 키가 예약어이면 단축 표기를 쓸 수 없어 SyntaxError입니다. 이름을 바꿔야 합니다(다음 절).
- 키가 식별자 형태가 아닌 경우(`'a-b'`, 숫자)에도 이름을 바꿔야 합니다.
- 함수가 여러 값을 돌려줄 때 객체로 반환하고 객체 패턴으로 받으면 순서에 의존하지 않고 필요한 값만 고를 수 있습니다. 배열로 반환하면 받는 쪽이 이름을 정하지만 순서를 알아야 합니다.

## 이름 변경과 기본값

`키: 변수`로 프로퍼티 이름과 다른 이름의 변수를 만들고, `= 식`으로 기본값을 줍니다. 두 가지는 함께 쓸 수 있습니다.

| 패턴 | 읽는 프로퍼티 | 만들어지는 변수 | 기본값 |
|------|---------------|-----------------|--------|
| `{ a }` | a | a | 없음 |
| `{ a: x }` | a | x | 없음 |
| `{ a = 1 }` | a | a | 1 |
| `{ a: x = 1 }` | a | x | 1 |

```js
const { a: x, b: y = 9 } = { a: 1 }
// x = 1, y = 9
typeof a  // 'undefined' — a는 변수가 아니다
```

- `:` 오른쪽은 값이 아니라 새로 만들어지는 변수 이름입니다. 객체 리터럴 `{ a: x }`와 모양이 같아 헷갈리지만 의미는 반대입니다.
- 기본값은 변수 이름 뒤에 붙입니다. `{ a = 1: x }`는 SyntaxError입니다.
- 예약어와 비식별자 키는 이름을 바꿔 받습니다.

```js
const { class: cls, default: d } = { class: 1, default: 2 }
// cls = 1, d = 2
const { 'a-b': ab, 0: zero } = { 'a-b': 1, 0: 'z' }
// ab = 1, zero = 'z'
```

- 같은 이름의 변수가 이미 있을 때 충돌을 피하는 용도로도 씁니다.
- `{ a = 1 }` 형태는 패턴에서만 허용됩니다. 값으로 쓰이는 객체 리터럴 `({ a = 1 })`은 SyntaxError입니다.

## 계산된 키

`[식]` 형태의 키는 식을 평가한 결과를 프로퍼티 키로 씁니다. 키를 실행 시점에 정할 때 필요합니다.

```js
const key = 'id'
const { [key]: value } = { id: 7 }
// value = 7
```

- 키 식의 결과가 심볼이면 심볼 키로, 그 밖의 값은 문자열로 변환해 읽습니다(`{ [1]: second }`는 키 `'1'`).
- 계산된 키는 변수 이름이 정해지지 않으므로 반드시 `: 변수`가 필요합니다. `const { [key] } = obj`는 SyntaxError입니다.
- 이름 변경 뒤에 기본값도 붙일 수 있습니다: `const { [key]: v = 0 } = {}`는 `v = 0`입니다.
- 심볼 키도 같은 방식입니다: `const { [Symbol.iterator]: iter } = []`는 `iter`에 배열의 `Symbol.iterator` 메서드를 담습니다.
- 키 식은 패턴의 왼쪽부터 평가되므로 앞에서 만든 변수를 뒤 키 식에서 쓸 수 있습니다.

```js
const { length, [length - 1]: last } = [1, 2, 3]
// length = 3, last = 3
```

## 기본값은 undefined일 때만

기본값은 꺼낸 값이 undefined일 때만 적용됩니다. 값이 없어서 undefined인 경우와, undefined가 직접 들어 있는 경우를 구분하지 않습니다.

| 꺼낸 값 | 기본값 적용 |
|---------|-------------|
| undefined (프로퍼티 없음, 요소 없음, 명시적 undefined) | 적용 |
| null | 적용 안 됨 |
| 0, 빈 문자열, false, NaN | 적용 안 됨 |

```js
const { a = 1, b = 2, c = 3, d = 4, e = 5 } =
  { a: undefined, b: null, c: 0, d: '', e: NaN }
// a = 1, b = null, c = 0, d = '', e = NaN
```

null까지 대체하려면 구조 분해 뒤에 `??`를 쓰고, falsy 값을 모두 대체하려면 `||`를 씁니다(자세히는 08편).

```js
const obj = { n: null }
const { n = 5 } = obj  // n = null
const m = obj.n ?? 5   // m = 5
const k = obj.n || 5   // k = 5
```

- 기본값 식은 구조 분해가 실행될 때마다 새로 평가됩니다. `{ list = [] } = {}`는 실행할 때마다 새 배열을 줍니다.
- 이 규칙은 배열 요소, 객체 프로퍼티, 매개변수 기본값에 모두 같습니다.

## 중첩

패턴 안에 패턴을 넣으면 깊은 구조에서 값을 한 번에 꺼냅니다. 배열 패턴과 객체 패턴을 섞어 쓸 수 있습니다.

```js
const user = {
  name: 'Kim',
  address: { city: 'Seoul' },
  tags: ['js', 'es']
}
const { address: { city }, tags: [firstTag] } = user
// city = 'Seoul', firstTag = 'js'
```

- `:` 오른쪽이 패턴이면 그 앞의 키 이름은 변수가 되지 않습니다. 위에서 `address`와 `tags`는 선언되지 않았습니다. 키 이름의 변수도 필요하면 같은 키를 한 번 더 씁니다.

```js
const { address, address: { city } } = user
// address = { city: 'Seoul' }, city = 'Seoul'
```

- 안쪽 패턴에도 이름 변경과 기본값을 쓸 수 있습니다: `const { a: { b: c = 3 } = {} } = {}`는 `c = 3`입니다.
- 꺼낸 안쪽 값이 객체이면 얕은 참조입니다. 복사되지 않습니다.
- 안쪽 값이 없으면 TypeError입니다. 안쪽 객체 패턴은 undefined나 null을 분해하게 되고, 안쪽 배열 패턴은 이터러블이 아닌 값을 받게 되기 때문입니다.

```js
const { a: { b } } = {}
// TypeError (안쪽 값이 undefined)
const { a: { c } = {} } = {}
// c = undefined (안쪽 기본값으로 막는다)
const { a: { d } = {} } = { a: null }
// TypeError (null은 기본값 대상이 아니다)
```

- 정규 표현식 결과처럼 구조가 정해진 값은 배열 패턴으로 바로 꺼냅니다.

```js
const [, year, month] = /(\d+)-(\d+)/.exec('2026-10')
// year = '2026', month = '10'
```

- 단계가 깊어질수록 패턴을 읽기 어렵습니다. 두 단계를 넘으면 한 단계씩 나눠 분해하는 편이 낫습니다.

## 매개변수 디스트럭처링

함수 매개변수 자리에 패턴을 쓰면 인수를 받는 즉시 분해합니다. 인수를 패턴에 `패턴 = 인수`로 대입하는 것과 같습니다.

```js
function area({ w, h }) { return w * h }
area({ w: 2, h: 3 })  // 6

const sum = ([a, b]) => a + b
sum([1, 2])  // 3
```

객체 하나로 옵션을 받는 형태에서 가장 많이 쓰입니다. 인수 순서를 외울 필요가 없고, 기본값을 정하고, 일부를 생략할 수 있습니다.

```js
function connect({ host = 'localhost', port = 80 } = {}) {
  return `${host}:${port}`
}
connect()                // 'localhost:80'
connect({ port: 8080 })  // 'localhost:8080'
```

- 바깥 기본값 `= {}`가 없으면 인수를 생략했을 때 undefined를 분해하게 되어 TypeError입니다. `area()`가 그렇습니다.
- 바깥 기본값도 undefined일 때만 쓰입니다. `connect(null)`은 null을 분해하므로 TypeError입니다.
- 기본값을 쓸 수 있는 자리가 두 곳이어서 헷갈립니다. 바깥 기본값은 인수 전체가 없을 때, 안쪽 기본값은 프로퍼티가 없을 때 적용됩니다.

```js
function f({ a } = { a: 1 }) { return a }
f()    // 1
f({})  // undefined (바깥 기본값은 인수가 없을 때만)
```

- 안쪽 기본값(`{ a = 1 } = {}`)이 `{}`를 넘긴 호출까지 처리하므로 보통 이쪽을 씁니다.
- 화살표 함수는 매개변수가 패턴 하나여도 괄호가 필요합니다: `({ id }) => id`. `{ id } => id`는 SyntaxError입니다.
- 매개변수마다 패턴을 따로 쓸 수 있고, 이름 변경도 됩니다: `function f({ id: userId }, [first]) {}`.
- 패턴 매개변수 하나는 매개변수 하나로 셉니다. 기본값이 붙은 매개변수부터는 함수의 `length`에서 빠집니다(자세히는 27편). Rest 매개변수에도 패턴을 쓸 수 있습니다(`(...[a, b])`).

### for-of와 catch의 패턴

for-in·for-of의 머리와 catch 매개변수에도 같은 패턴을 씁니다. 반복마다 꺼낸 값이 패턴에 대입됩니다.

```js
const obj = { x: 1, y: 2 }
for (const [key, value] of Object.entries(obj)) {
  // 1회차: key = 'x', value = 1
}
for (const { id } of [{ id: 1 }, { id: 2 }]) {}
try { null.x } catch ({ name }) {
  // name = 'TypeError'
}
```

- 선언 없이 기존 변수에 받을 수도 있습니다: `for ({ id } of list) {}`.
- 배열의 인덱스와 값은 `for (const [i, v] of arr.entries())`로 받습니다(자세히는 28편).

## Rest 프로퍼티

Rest 프로퍼티는 객체 패턴 끝의 `...변수`로, 앞에서 꺼내지 않은 프로퍼티를 새 객체에 담습니다(ES2018).

```js
const { a, ...rest } = { a: 1, b: 2, c: 3 }
// a = 1, rest = { b: 2, c: 3 }
```

- 담기는 대상은 객체 자신의 열거 가능한 프로퍼티이고, 문자열 키와 심볼 키를 모두 포함합니다. 상속 프로퍼티와 열거 불가 프로퍼티는 빠집니다. 스프레드와 같은 규칙입니다(자세히는 36편).
- 결과는 항상 `Object.prototype`을 상속하는 새 일반 객체입니다. 원본의 프로토타입은 이어지지 않습니다.
- 앞에서 꺼낸 키는 계산된 키로 꺼낸 것까지 제외됩니다.
- getter는 호출되고 값만 복사됩니다. 값이 객체이면 얕은 참조입니다.
- 마지막에만, 패턴당 하나만 쓸 수 있습니다. 뒤에 다른 항목이나 쉼표가 오면 SyntaxError입니다.
- 오른쪽이 원시값이면 객체로 변환합니다. `const { ...r } = 5`는 `r = {}`이고, 문자열은 인덱스 키를 얻습니다. null·undefined는 TypeError입니다.

```js
const { 0: first, ...r } = 'abc'
// first = 'a', r = { 1: 'b', 2: 'c' }
```

- 일부 프로퍼티를 뺀 복사본을 만드는 데 씁니다.

```js
const user = { id: 1, password: 'x', name: 'n' }
const { password, ...safe } = user
// safe = { id: 1, name: 'n' }
```

- 바인딩 패턴(선언·매개변수)에서 Rest 대상은 식별자뿐입니다. `const { ...{ a } } = obj`는 SyntaxError입니다. 할당 패턴에서는 `({ ...o.rest } = src)`처럼 프로퍼티 참조도 되지만, 패턴은 역시 안 됩니다.
- 배열에 객체 Rest를 쓰면 배열이 아니라 인덱스 키를 가진 객체가 됩니다. 남은 요소를 배열로 받으려면 배열 Rest를 씁니다.

| 구분 | Rest 요소(배열 패턴) | Rest 프로퍼티(객체 패턴) |
|------|---------------------|-------------------------|
| 결과 | 새 배열 | 새 일반 객체 |
| 담는 대상 | 이터레이터의 남은 값 | 자신의 열거 가능한 남은 프로퍼티 |
| 대상에 패턴 | 가능 (`...[b, c]`) | 불가 |
| 도입 | ES2015 | ES2018 |

## 변수 교환

임시 변수 없이 두 변수의 값을 바꾸는 데 할당 패턴을 씁니다.

```js
let a = 1, b = 2
;[a, b] = [b, a]
// a = 2, b = 1
```

- 오른쪽 `[b, a]`가 먼저 만들어져 현재 값이 담기고, 그 뒤 왼쪽 패턴이 할당합니다. 그래서 서로 덮어쓰지 않습니다.
- 변수가 아닌 대상끼리도 바꿀 수 있습니다. 할당 패턴은 요소와 프로퍼티도 대상으로 받기 때문입니다.

```js
const arr = [1, 2, 3]
;[arr[0], arr[2]] = [arr[2], arr[0]]
// arr = [3, 2, 1]
```

- 셋 이상의 순환도 같은 방식입니다: `[a, b, c] = [b, c, a]`.
- `const` 변수는 재할당이 안 되므로 교환할 수 없습니다. `let`이나 `var`로 선언합니다.

**흔한 실수:** 세미콜론을 생략하는 스타일에서 줄이 `[`로 시작하면 앞 줄의 식에 이어 붙습니다. 아래처럼 `;` 없이 쓰면 앞 두 줄이 `let b = 2[a, b] = [b, a]`로 읽히고, `b`가 아직 초기화 전이어서 ReferenceError가 납니다.

```js
let a = 1
let b = 2
[a, b] = [b, a]  // ReferenceError
```

## 선언 없는 할당의 괄호

이미 선언된 변수에 객체 패턴으로 할당하는 문장은 전체를 괄호로 감쌉니다.

```js
let a, b
{ a, b } = { a: 1, b: 2 }    // SyntaxError
({ a, b } = { a: 1, b: 2 })  // a = 1, b = 2
```

- 문장 맨 앞의 `{`는 객체 리터럴이 아니라 블록으로 해석되고, 블록 뒤의 `=`는 문법 오류입니다(문과 식의 구분은 04편). 괄호로 감싸면 식으로 해석됩니다.
- 괄호는 패턴이 아니라 할당식 전체를 감쌉니다. `({ a }) = obj`는 SyntaxError입니다.
- 배열 패턴은 `[`로 시작해 블록과 겹치지 않으므로 괄호가 필요 없습니다.
- 문장의 맨 앞이 아닌 자리에서는 괄호가 필요 없습니다. `for ({ a } of list) {}`가 그렇습니다.
- `const`·`let`·`var`로 시작하는 선언은 맨 앞이 키워드라 괄호가 필요 없습니다.
- 할당식의 값은 분해 결과가 아니라 오른쪽 값 그대로입니다.

```js
let a
const src = { a: 1, b: 2 }
const r = ({ a } = src)
// a = 1, r === src
```

- 세미콜론을 생략하는 스타일에서 `(`로 시작하는 줄은 앞 줄에 이어 붙으므로 그 앞에 `;`를 붙입니다. 앞 줄이 `foo`로 끝나면 `foo({ a } = obj)`라는 함수 호출로 읽힙니다.
- 할당 패턴의 대상은 변수에 한정되지 않습니다.

```js
const o = {}
;({ x: o.p, y: o.q } = { x: 1, y: 2 })
// o = { p: 1, q: 2 }
```

## null·undefined 대상 에러

null이나 undefined를 분해하면 TypeError입니다. 객체 패턴은 프로퍼티를 읽을 수 없고, 배열 패턴은 이터러블이 아니기 때문입니다. 패턴이 비어 있어도 에러입니다.

```js
const { a } = null       // TypeError
const { b } = undefined  // TypeError
const [c] = null         // TypeError
const {} = undefined     // TypeError (빈 패턴도)
const {} = 0             // 에러 없음 (원시값은 객체로 변환)
```

- 에러 메시지는 엔진마다 다릅니다. V8(Chrome, Node.js)은 `Cannot destructure property 'a' of 'null' as it is null.` 같은 문구를 씁니다. 메시지 문구에 의존하는 코드는 쓰지 않습니다.
- 원시값(숫자, 문자열, 불리언, 심볼, BigInt)은 객체 패턴에서 에러가 아닙니다. 배열 패턴은 이터러블인 문자열만 되고, 숫자와 불리언은 TypeError입니다.

값이 null·undefined가 되는 경로는 대체로 셋입니다.

| 경로 | 예 |
|------|----|
| 인수를 생략한 매개변수 | `function f({ a }) {}`를 `f()`로 호출 |
| 없는 중간 값 | `const { a: { b } } = {}` |
| 값이 없는 조회 결과 | 매치가 없는 `exec`의 null, 못 찾은 `find`의 undefined, 빠진 응답 필드 |

대응은 값이 어디서 비는지에 따라 다릅니다.

```js
const { x } = maybeNull ?? {}  // null·undefined 모두 대체
function f({ a } = {}) {}
// undefined만 대체. f(null)은 TypeError
const { p: { q } = {} } = obj  // 안쪽도 undefined만
const v = obj?.p?.q            // 분해 대신 옵셔널 체이닝
```

- 기본값 `= {}`는 undefined에만 적용되므로 null은 `?? {}`나 옵셔널 체이닝(`?.`)으로 막습니다(자세히는 08편).
- 옵셔널 체이닝은 값을 하나만 꺼낼 때 간단하고, 여러 값을 한 번에 꺼낼 때는 패턴이 낫습니다.

## 핵심 정리

- 배열 패턴은 이터레이터로 순서대로, 객체 패턴은 프로퍼티 이름으로 값을 꺼냅니다. 없는 값은 undefined입니다.
- 기본값은 undefined일 때만 적용됩니다. null, 0, 빈 문자열, false, NaN에는 적용되지 않습니다.
- `{ a: x }`는 프로퍼티 a를 변수 x로 받고, 계산된 키는 `{ [key]: x }`로 쓰며 변수 이름이 필요합니다.
- Rest는 패턴의 마지막에만 오고, 배열 Rest는 배열을, 객체 Rest는 열거 가능한 남은 자기 프로퍼티를 담은 새 객체를 만듭니다.
- 이미 선언된 변수에 객체 패턴으로 할당하려면 `({ a } = obj)`처럼 괄호로 감싸고, 변수 교환은 `[a, b] = [b, a]`입니다.
- null·undefined를 분해하면 TypeError이므로 매개변수에는 `= {}`, 값에는 `?? {}`로 막습니다.
