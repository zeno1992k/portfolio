## 콜백 인수와 thisArg

고차 함수는 함수를 인수로 받거나 함수를 반환하는 함수이고, 인수로 넘기는 함수를 콜백이라고 합니다(자세히는 11편). 배열 고차 함수는 요소마다 콜백을 호출하고 그 반환값을 목적에 맞게 모읍니다.

| 메서드 | 콜백 인수 | thisArg |
|--------|-----------|---------|
| forEach, map, filter, some, every, flatMap, find, findIndex, findLast, findLastIndex | `(element, index, array)` | 두 번째 인수 |
| reduce, reduceRight | `(accumulator, element, index, array)` | 없음 (두 번째 인수는 초기값) |
| sort | `(a, b)` | 없음 |
| Object.groupBy, Map.groupBy | `(item, index)` | 없음 |

- 콜백은 앞쪽 인수만 선언해도 됩니다. 선언하지 않은 인수는 무시됩니다.
- `array`는 메서드를 호출한 배열입니다. 체인 중간에서는 직전 단계가 만든 배열입니다.
- 콜백이 던진 예외는 메서드 밖으로 전파되고 남은 요소는 처리되지 않습니다.

함수를 그대로 넘기면 그 함수가 선언한 인수 수와 상관없이 모든 인수가 전달됩니다. 두 번째 인수를 다른 뜻으로 받는 함수에서 사고가 납니다.

```js
const s = ['1', '2', '3']
s.map(parseInt)               // [1, NaN, NaN]
// parseInt('1', 0), parseInt('2', 1), parseInt('3', 2)
s.map((v) => parseInt(v, 10)) // [1, 2, 3]
s.map(Number)                 // [1, 2, 3]
```

`parseInt`의 두 번째 인수는 진법입니다. 0은 기본값으로 처리되어 `1`이 되고, 1은 허용 범위 밖이라 `NaN`, 2진법에서 `'3'`은 숫자가 아니라 `NaN`입니다. `Number`는 첫 인수만 쓰므로 안전합니다.

thisArg는 콜백 안의 `this`를 정하는 선택 인수입니다.

```js
const counter = { step: 2 }
function mul(n) { return n * this.step }
const result = [1, 2].map(mul, counter)
// [2, 4]
```

- 생략하면 `undefined`가 전달되어 일반 함수 호출과 같은 규칙을 따릅니다(자세히는 21편).
- 화살표 함수는 자기 `this`가 없으므로 thisArg를 무시하고 선언된 위치의 `this`를 씁니다.
- 객체 메서드를 콜백으로 넘기면 `this`가 객체에서 분리됩니다. thisArg를 주거나 화살표 함수로 감싸야 합니다.

## sort와 비교 함수

sort는 배열을 제자리에서 정렬하고 같은 배열을 반환하는 메서드입니다. 새 배열을 만들지 않으므로 원본이 바뀝니다. 복사본을 정렬하는 `toSorted`는 28편에서 다룹니다.

```js
const nums = [3, 1, 2]
const sorted = nums.sort()
sorted === nums // true
nums            // [1, 2, 3]
```

### 기본 정렬 순서

비교 함수를 생략하면 요소를 문자열로 바꿔 UTF-16 코드 유닛 순서로 비교합니다. 숫자 배열도 예외가 아닙니다.

```js
const nums = [10, 9, 1].sort()       // [1, 10, 9]
const words = ['b', 'a', 'C'].sort() // ['C', 'a', 'b']
const neg = [-1, -2, 0, 1].sort()    // [-1, -2, 0, 1]
```

- `'10'`은 `'9'`보다 앞입니다. 첫 글자 `'1'`이 `'9'`보다 작기 때문입니다.
- 대문자(코드 65–90)는 소문자(97–122)보다 앞입니다.
- `undefined` 요소는 비교 함수를 호출하지 않고 끝으로 보냅니다. 빈 슬롯은 그 뒤, 맨 끝으로 갑니다.
- 비교 함수는 함수이거나 `undefined`여야 합니다. `sort(null)`은 TypeError입니다.

```js
const mixed = [3, undefined, , 1].sort()
// [1, 3, undefined, <빈 슬롯 1개>]
```

### 비교 함수

비교 함수 `(a, b)`는 두 요소의 순서를 숫자 부호로 알려 줍니다.

| 반환값 | 의미 |
|--------|------|
| 음수 | a를 b보다 앞에 둔다 |
| 양수 | a를 b보다 뒤에 둔다 |
| 0 또는 NaN | 같은 값으로 취급한다(상대 순서 유지) |

```js
const nums = [10, 9, 1]
nums.sort((a, b) => a - b) // [1, 9, 10] 오름차순
nums.sort((a, b) => b - a) // [10, 9, 1] 내림차순
```

숫자 비교는 뺄셈 하나로 충분합니다. 부호만 쓰기 때문에 값의 크기는 상관없습니다. 다음은 자주 틀리는 형태입니다.

```js
const v = [5, 1, 4]
v.sort((a, b) => a > b) // ❌ [5, 1, 4] (V8, 정렬 안 됨)
v.sort((a, b) => a - b) // ✅ [1, 4, 5]
```

`a > b`는 `true`와 `false`를 반환하고 이는 1과 0으로 바뀝니다. 음수가 나오지 않으므로 "a를 앞에 둔다"는 신호가 없습니다.

비교 함수는 일관되어야 합니다.

- 같은 두 요소에는 항상 같은 결과를 냅니다.
- `compare(a, b)`와 `compare(b, a)`의 부호가 반대입니다.
- `a`가 `b`보다 앞이고 `b`가 `c`보다 앞이면 `a`는 `c`보다 앞입니다.

일관되지 않으면 결과 순서는 명세가 정하지 않고 엔진마다 달라질 수 있습니다. 같은 이유로 `sort(() => Math.random() - 0.5)`는 섞기에 쓰지 않습니다. 균등한 섞기를 보장하지 않습니다.

`NaN` 요소가 섞인 배열에서 `a - b`는 `NaN`을 반환해 일관성이 깨집니다. 정렬 전에 `NaN`을 걸러 냅니다.

### 문자열 정렬

기본 정렬은 코드 유닛 순서라 대소문자, 악센트 문자, 한글의 사전 순서와 어긋납니다. 사전 순서가 필요하면 `localeCompare`나 `Intl.Collator`를 비교 함수로 씁니다.

```js
const words = ['b', 'a', 'C', 'é', 'z']
words.sort((a, b) => a.localeCompare(b))
// ['a', 'b', 'C', 'é', 'z']

const ko = ['다', '가', '나']
ko.sort((a, b) => a.localeCompare(b, 'ko'))
// ['가', '나', '다']
```

숫자가 섞인 이름은 `numeric` 옵션으로 숫자 크기를 비교합니다. 큰 배열에서는 `localeCompare`를 매번 호출하는 것보다 `Intl.Collator`를 한 번 만들어 재사용하는 편이 낫습니다(자세히는 31편).

```js
const opts = { numeric: true }
const collator = new Intl.Collator(undefined, opts)
const files = ['a10', 'a9', 'a1']
files.sort(collator.compare) // ['a1', 'a9', 'a10']
```

기본 정렬이면 `['a1', 'a10', 'a9']`입니다.

### 객체 배열과 여러 기준

객체 배열은 기준이 되는 프로퍼티를 비교합니다. 첫 기준의 결과가 0이면 다음 기준으로 넘기는 방식으로 여러 기준을 합칩니다. 0은 falsy이므로 `||`가 다음 기준을 평가합니다.

```js
const users = [
  { team: 'x', age: 30 }, { team: 'y', age: 25 },
  { team: 'x', age: 20 },
]
users.sort(
  (a, b) => a.team.localeCompare(b.team) || a.age - b.age
)
// x/20, x/30, y/25
```

- 날짜는 뺄셈이 밀리초 숫자로 바뀌므로 `(a, b) => a.date - b.date`가 동작합니다.
- 문자열 프로퍼티를 `a.name - b.name`으로 비교하면 `NaN`이 되어 아무것도 정렬되지 않습니다.
- 문자열 내림차순은 `b.localeCompare(a)`입니다.

## 안정 정렬(ES2019)

안정 정렬은 비교 결과가 같은 요소들이 원래의 상대 순서를 유지하는 정렬입니다. ES2019부터 명세가 `sort`에 안정 정렬을 요구합니다. 그 전 명세는 안정성을 보장하지 않았고, V8은 길이 10 미만은 삽입 정렬, 그 이상은 퀵 정렬을 써서 실제로 불안정했습니다. V8 7.0(Chrome 70)에서 TimSort로 바뀌며 안정해졌습니다.

```js
const people = [
  { name: 'A', age: 30 }, { name: 'B', age: 25 },
  { name: 'C', age: 30 }, { name: 'D', age: 25 },
]
people.sort((x, y) => x.age - y.age)
// B, D, A, C — 같은 나이끼리 원래 순서(B→D, A→C) 유지
```

안정 정렬이면 여러 기준을 정렬 여러 번으로 처리할 수 있습니다. 덜 중요한 기준으로 먼저 정렬하고, 가장 중요한 기준으로 마지막에 정렬합니다.

```js
users.sort((a, b) => a.age - b.age)               // 보조 기준
users.sort((a, b) => a.team.localeCompare(b.team)) // 주 기준
// team 순, 같은 team 안에서는 age 순
```

- 비교 함수가 항상 0이면 원래 순서가 그대로 유지됩니다.
- 안정성은 기준이 같은 요소의 순서만 보장합니다. 기본 정렬의 문자열 비교 결과가 달라지지는 않습니다.

## forEach

forEach는 각 요소에 콜백을 한 번씩 호출하고 `undefined`를 반환하는 메서드입니다. 결과값이 아니라 부수 효과(출력, 외부 변수 갱신)가 목적일 때 씁니다.

```js
const nums = [1, 2, 3]
let total = 0
nums.forEach((n) => { total += n })
total // 6
```

- 반환값이 `undefined`라 체이닝할 수 없습니다. `nums.forEach(f).map(g)`는 TypeError입니다.
- `break`와 `continue`를 쓸 수 없습니다. 콜백 안의 `break`는 SyntaxError입니다.
- 콜백의 `return`은 그 콜백만 끝냅니다. 반복문의 `continue`와 같은 효과입니다.
- 중간에 멈추려면 `for...of`, `some`, `every`, `find`를 쓰거나 예외를 던집니다. 예외는 흐름 제어로 권하지 않습니다.
- 빈 슬롯은 건너뜁니다. `[2, 5, , 9]`에서 콜백은 3번 호출됩니다.

비동기 콜백은 기다리지 않습니다. `forEach`는 콜백이 반환한 프로미스를 무시하므로, 반복이 끝난 시점에 비동기 작업은 끝나지 않은 상태입니다.

```js
const ids = [1, 2, 3]
ids.forEach(async (id) => { await save(id) })
console.log('done') // save가 끝나기 전에 출력된다
```

순서대로 기다리려면 `for...of` 안에서 `await`를 쓰고, 동시에 실행하고 기다리려면 `await Promise.all(ids.map(save))`를 씁니다(자세히는 43편).

## map

map은 각 요소에 콜백을 호출하고 반환값을 모아 같은 길이의 새 배열을 반환하는 메서드입니다. 원본 배열은 바뀌지 않습니다.

```js
const users = [
  { id: 1, name: 'Kim' }, { id: 2, name: 'Lee' },
]
users.map((u) => u.name)         // ['Kim', 'Lee']
users.map((u) => ({ id: u.id })) // [{ id: 1 }, { id: 2 }]
users.map((u) => { id: u.id })   // ❌ [undefined, undefined]
```

마지막 줄의 `{ id: u.id }`는 객체가 아니라 함수 본문(블록)입니다. 객체 리터럴을 바로 반환하려면 소괄호로 감쌉니다. 블록 본문에서 `return`을 빼먹으면 모든 요소가 `undefined`가 되는 것도 같은 원인입니다.

- 결과 길이는 호출 시점의 원본 길이와 같습니다. 콜백이 `undefined`를 반환해도 요소로 들어갑니다.
- 빈 슬롯은 콜백을 호출하지 않고 결과에서도 빈 슬롯으로 남습니다.
- 요소는 복사되지 않습니다. 객체 요소를 콜백에서 수정해 반환하면 원본 객체도 바뀝니다.
- `Array`를 상속한 클래스의 인스턴스에서 호출하면 결과도 그 클래스의 인스턴스입니다. `filter`와 `flatMap`도 같습니다.

```js
const sparse = [1, , 3].map((x) => x * 2)
// [2, <빈 슬롯 1개>, 6]

const older = users.map((u) => ({ ...u, age: 20 }))
// ✅ 새 객체를 만들어 원본 객체를 건드리지 않는다
```

결과를 쓰지 않고 부수 효과만 일으키려고 map을 쓰는 것은 흔한 실수입니다. 새 배열이 만들어졌다 버려지고, 읽는 사람은 결과가 쓰일 것이라고 기대합니다. 이 경우 forEach를 씁니다.

## filter

filter는 콜백이 truthy를 반환한 요소만 모아 새 배열로 반환하는 메서드입니다.

```js
const nums = [1, 2, 3, 4]
nums.filter((n) => n % 2 === 0) // [2, 4]
nums.filter((n) => n > 9)       // []
```

- 콜백 반환값은 불리언일 필요가 없습니다. truthy·falsy로 판정합니다(자세히는 08편).
- 결과는 원래 순서를 유지하고, 요소는 복사되지 않은 같은 참조입니다. 조건에 맞는 요소가 없으면 `undefined`가 아니라 빈 배열입니다.
- 빈 슬롯은 건너뛰므로 결과에는 빈 슬롯이 없습니다. 희소 배열을 압축하는 용도로도 씁니다.
- 첫 번째 일치 요소 하나만 필요하면 `find`를 씁니다. 전체를 순회하지 않습니다.

```js
const dense = [1, , 3].filter(() => true) // [1, 3]
const vals = [0, 1, '', 'a', null, NaN].filter(Boolean)
// [1, 'a']
```

`filter(Boolean)`은 falsy 값(`false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN`)을 전부 제거합니다. 의미 있는 `0`과 빈 문자열도 함께 사라지므로 `null`·`undefined`만 제거하려면 `(v) => v != null`을 씁니다.

중복 제거에 `filter`를 쓰면 다음 형태가 됩니다.

```js
const arr = [1, 2, 1]
arr.filter((v, i, a) => a.indexOf(v) === i) // [1, 2]
```

`indexOf`는 `NaN`을 찾지 못하므로 `NaN`이 통째로 사라지고, 요소마다 앞부분을 다시 훑어 느립니다. `[...new Set(arr)]`가 낫습니다(자세히는 38편).

흔한 실수는 비동기 콜백입니다. `async` 함수는 항상 프로미스를 반환하고 프로미스는 truthy이므로 모든 요소가 남습니다.

```js
const kept = [1, 2, 3].filter(async () => false)
// [1, 2, 3]
```

## reduce

reduce는 배열을 앞에서부터 순회하며 누적값(accumulator)에 콜백 반환값을 이어 넣어 하나의 값으로 만드는 메서드입니다. 결과는 숫자, 문자열, 배열, 객체 무엇이든 될 수 있습니다.

```js
const sum = [1, 2, 3].reduce((acc, cur) => acc + cur, 0)
// 6
```

| 호출 | acc | cur | index | 반환 |
|------|-----|-----|-------|------|
| 1 | 0 (초기값) | 1 | 0 | 1 |
| 2 | 1 | 2 | 1 | 3 |
| 3 | 3 | 3 | 2 | 6 |

콜백의 반환값이 다음 호출의 `acc`가 되고, 마지막 반환값이 `reduce`의 결과입니다. 블록 본문에서 `return`을 빼먹으면 다음 호출의 `acc`가 `undefined`가 됩니다.

초기값 유무에 따라 동작이 달라집니다.

| 상황 | 동작 |
|------|------|
| 초기값 있음 | 첫 `acc`는 초기값, index 0부터 순회 |
| 초기값 없음 | 첫 `acc`는 첫 번째 요소, index 1부터 순회 (호출 횟수는 길이 − 1) |
| 빈 배열 + 초기값 없음 | TypeError (Reduce of empty array with no initial value) |
| 빈 배열 + 초기값 있음 | 콜백 호출 없이 초기값 반환 |
| 요소 1개 + 초기값 없음 | 콜백 호출 없이 그 요소 반환 |

- 빈 슬롯은 건너뜁니다. 빈 슬롯만 있는 배열은 빈 배열과 같게 TypeError가 납니다.
- `undefined` 값은 건너뛰지 않습니다. `[1, 2, undefined, 4]`의 합은 `NaN`입니다.

초기값을 생략하면 첫 요소가 `acc`가 되므로, 요소와 결과의 타입이 다를 때 틀린 값이 나옵니다.

```js
const items = [{ price: 100 }, { price: 200 }]
items.reduce((a, c) => a + c.price)
// ❌ '[object Object]200'
items.reduce((a, c) => a + c.price, 0)
// ✅ 300
```

요소와 결과의 타입이 같고 빈 배열이 절대 들어오지 않는 경우가 아니면 초기값을 항상 씁니다.

## reduceRight

reduceRight는 reduce와 같지만 오른쪽 끝에서 왼쪽으로 순회하는 메서드입니다. 초기값이 없으면 마지막 요소가 첫 `acc`가 되고 첫 index는 `length - 2`입니다. 빈 배열과 빈 슬롯 규칙은 reduce와 같습니다.

```js
const r = ['a', 'b', 'c'].reduceRight((acc, c) => acc + c)
// 'cba'
const nested = [[0, 1], [2, 3]]
nested.reduceRight((acc, cur) => acc.concat(cur), [])
// [2, 3, 0, 1]
```

연산 순서가 결과를 바꾸는 경우(함수 합성, 오른쪽 결합 연산)에 씁니다. 순서가 상관없는 합계 같은 곳에서는 reduce를 씁니다.

## reduce 활용 패턴

### 합계·최댓값

합계는 앞 절의 형태입니다. 최댓값은 빈 배열을 고려해 초기값을 `-Infinity`로 둡니다.

```js
const nums = [3, 1, 2]
nums.reduce((m, n) => (n > m ? n : m), -Infinity) // 3
```

`Math.max(...nums)`도 같은 결과지만 배열을 인수로 펼치므로 아주 큰 배열에서는 RangeError가 날 수 있습니다(자세히는 30편).

### 개수 세기

```js
const words = ['a', 'b', 'a']
const count = words.reduce((acc, w) => {
  acc[w] = (acc[w] ?? 0) + 1
  return acc
}, {})
// { a: 2, b: 1 }
```

초기값 `{}`는 `Object.prototype`을 상속하므로 단어가 `'constructor'`이면 상속된 함수를 읽어 `'function Object() { [native code] }1'` 같은 문자열이 만들어집니다. 임의의 문자열을 키로 쓸 때는 `Object.create(null)`이나 `Map`을 초기값으로 씁니다.

### 배열을 객체로

```js
const users = [{ id: 1, n: 'a' }, { id: 2, n: 'b' }]
const byId = users.reduce((acc, u) => {
  acc[u.id] = u
  return acc
}, {})
// { 1: {id: 1, ...}, 2: {id: 2, ...} }
```

`Object.fromEntries(users.map((u) => [u.id, u]))`(ES2019)가 같은 결과를 더 짧게 만듭니다.

### 한 번의 순회로 filter와 map

```js
const nums = [1, 2, 3, 4, 5]
nums.reduce((acc, n) => {
  if (n % 2) acc.push(n * 10)
  return acc
}, [])
// [10, 30, 50]
```

`flatMap`으로도 같은 결과를 냅니다. 중간 배열이 하나도 안 생기지만 읽기는 `filter(...).map(...)`이 쉽습니다.

### 평탄화

`reduce((acc, cur) => acc.concat(cur), [])`는 한 단계 평탄화입니다. 반복마다 새 배열을 만들기 때문에 `flat`(28편)이나 `flatMap`을 쓰는 것이 낫습니다.

### 함수 파이프라인과 합성

reduce는 왼쪽에서 오른쪽으로, reduceRight는 오른쪽에서 왼쪽으로 함수를 적용합니다(자세히는 50편).

```js
const fns = [(x) => x + 1, (x) => x * 2, (x) => x - 3]
fns.reduce((v, f) => f(v), 5)      // 9  ((5+1)*2-3)
fns.reduceRight((v, f) => f(v), 5) // 5  ((5-3)*2+1)
```

프로미스를 순서대로 실행하는 데에도 같은 구조를 씁니다(자세히는 41편).

```js
tasks.reduce((p, t) => p.then(t), Promise.resolve())
```

### 주의할 점

누적 객체를 매 반복마다 스프레드로 복사하면 복사 비용이 쌓여 O(n²)이 됩니다.

```js
// ❌ 매 반복마다 acc 전체를 복사한다
users.reduce((acc, u) => ({ ...acc, [u.id]: u }), {})
```

그 반복에서 방금 만든 `acc`를 직접 수정(`acc[k] = v`)하는 것은 안전합니다. 단, 초기값은 호출마다 새로 만들어야 합니다. 바깥 상수로 빼 둔 객체를 초기값으로 쓰고 수정하면 호출 사이에 값이 남습니다.

```js
const DEFAULT = {}
const tally = (xs) => xs.reduce((acc, x) => {
  acc[x] = (acc[x] ?? 0) + 1
  return acc
}, DEFAULT)
tally(['a']) === tally(['b']) // true (같은 객체)
```

## some·every

some은 콜백이 truthy를 반환하는 요소가 하나라도 있는지, every는 모든 요소가 truthy인지를 불리언으로 반환하는 메서드입니다. 결과가 정해지는 즉시 순회를 멈춥니다.

```js
const nums = [1, 2, 3]
nums.some((n) => n > 2)  // true  (3에서 중단)
nums.every((n) => n > 0) // true
nums.every((n) => n > 1) // false (1에서 중단)
```

- some은 첫 truthy에서 `true`를 반환하고, every는 첫 falsy에서 `false`를 반환합니다. 그 뒤 요소는 콜백을 호출하지 않습니다.
- 빈 배열에서 `some`은 `false`, `every`는 `true`입니다. every의 `true`는 조건을 어기는 요소가 없다는 뜻입니다.
- 빈 슬롯은 건너뜁니다. `[ , 1].some((x) => x === undefined)`는 `false`, `[, ,].every(() => false)`는 `true`입니다.
- 반환값은 불리언뿐입니다. 해당 요소가 필요하면 `find`를 씁니다.
- 존재 여부만 알면 되는데 `filter(...).length > 0`을 쓰면 전체를 순회하고 새 배열도 만듭니다. `some`이 맞습니다.
- 순회를 중간에 끊어야 할 때 `some`(끊을 때 `true` 반환)이나 `every`(끊을 때 `false` 반환)가 forEach의 대안이 됩니다.

흔한 실수는 빈 배열 검증입니다. `items.every(isValid)`는 `items`가 비어 있어도 `true`이므로 비어 있는 경우를 따로 막아야 합니다.

```js
const ok = items.length > 0 && items.every(isValid)
```

## find·findIndex·findLast·findLastIndex

네 메서드는 콜백이 truthy를 반환하는 첫 요소 또는 그 위치를 찾습니다. findLast 계열은 뒤에서부터 찾습니다.

| 메서드 | 방향 | 찾으면 | 없으면 | 도입 |
|--------|------|--------|--------|------|
| find | 앞에서 뒤로 | 요소 | `undefined` | ES2015 |
| findIndex | 앞에서 뒤로 | 인덱스 | `-1` | ES2015 |
| findLast | 뒤에서 앞으로 | 요소 | `undefined` | ES2023 |
| findLastIndex | 뒤에서 앞으로 | 인덱스 | `-1` | ES2023 |

```js
const nums = [1, 2, 3, 4]
nums.find((n) => n % 2 === 1)          // 1
nums.findLast((n) => n % 2 === 1)      // 3
nums.findIndex((n) => n > 9)           // -1
nums.findLastIndex((n) => n % 2 === 1) // 2
```

- 첫 일치에서 순회를 멈춥니다.
- `findLastIndex`가 반환하는 인덱스도 앞에서부터 센 원래 위치입니다.
- `find`는 요소의 같은 참조를 반환합니다. 객체를 찾아 수정하면 배열 안의 객체가 바뀝니다.
- 못 찾으면 `undefined`이므로 결과의 프로퍼티를 바로 읽으면 TypeError입니다. `?.`를 씁니다(자세히는 06편).
- 배열 요소 자체가 `undefined`일 수 있으면 `find` 결과로 "못 찾음"과 구분되지 않습니다. `findIndex`의 `-1`로 판단합니다.
- 다른 순회 메서드와 달리 빈 슬롯도 방문하며 콜백에 `undefined`로 전달합니다.

```js
const sparse = [ , 1]
sparse.findIndex((x) => x === undefined) // 0
sparse.indexOf(undefined)                // -1
```

값을 직접 비교하는 `indexOf`·`includes`(28편)와의 차이는 비교 방식입니다. `indexOf`는 `===`라 `NaN`을 찾지 못하고, `includes`는 `NaN`도 찾습니다. 조건 함수가 필요하면 find 계열을 씁니다.

```js
const a = [NaN].indexOf(NaN)            // -1
const b = [NaN].findIndex(Number.isNaN) // 0
```

## flatMap

flatMap(ES2019)은 `map`을 호출한 뒤 결과를 한 단계만 평탄화(`flat(1)`)하는 메서드로, 순회 한 번에 처리합니다.

```js
const nums = [1, 2, 3]
nums.flatMap((n) => [n, n * 10]) // [1, 10, 2, 20, 3, 30]
nums.map((n) => [n, n * 10])
// [[1, 10], [2, 20], [3, 30]]
```

- 콜백이 배열을 반환하면 그 요소가 결과에 펼쳐져 들어갑니다. 배열이 아닌 값은 그대로 들어갑니다.
- 펼쳐지는 것은 진짜 배열뿐입니다. 문자열과 유사 배열 객체는 펼치지 않습니다.
- 깊이는 1로 고정입니다. 더 깊은 배열은 그대로 남습니다. 깊이를 정하려면 `map(...).flat(depth)`를 씁니다.
- 콜백 인수와 thisArg는 map과 같고, 원본의 빈 슬롯은 건너뜁니다. 콜백이 반환한 배열의 빈 슬롯은 제거됩니다.

```js
const a = [1, 2].flatMap(() => 'ab')      // ['ab', 'ab']
const b = [1, [2, [3]]].flatMap((x) => x) // [1, 2, [3]]
const c = [1, 2].flatMap((x) => [, x])    // [1, 2]
```

빈 배열을 반환하면 요소가 사라지고, 요소 하나짜리 배열을 반환하면 변환입니다. 이 성질로 filter와 map을 한 번에 처리합니다.

```js
const nums = [1, -2, 3]
nums.flatMap((n) => (n > 0 ? [n * 2] : []))
// [2, 6]
```

## Object.groupBy·Map.groupBy

Object.groupBy와 Map.groupBy(ES2024)는 이터러블의 요소를 콜백이 반환한 키별로 묶어 반환하는 정적 메서드입니다. 앞의 것은 객체를, 뒤의 것은 Map을 만듭니다.

```js
const items = [
  { name: 'apple', type: 'fruit' },
  { name: 'leek', type: 'veg' },
  { name: 'pear', type: 'fruit' },
]
Object.groupBy(items, (i) => i.type)
// fruit: [apple, pear], veg: [leek]
```

- 콜백은 `(item, index)`를 받고 반환값이 그룹 키입니다.
- 첫 번째 인수는 배열이 아니어도 이터러블이면 됩니다. 문자열과 Set도 받습니다.
- 그룹 안의 요소는 원래 순서를 유지하고, 그룹은 키가 처음 나온 순서로 만들어집니다. Object의 정수 형태 키는 프로퍼티 순서 규칙에 따라 앞으로 정렬됩니다(자세히는 18편).
- 원본은 바뀌지 않고 요소는 같은 참조입니다. 요소가 없는 키의 그룹은 만들지 않고, 빈 이터러블은 빈 결과를 돌려줍니다.

두 메서드는 키를 다루는 방식이 다릅니다.

| 구분 | Object.groupBy | Map.groupBy |
|------|----------------|-------------|
| 결과 | 프로토타입이 `null`인 객체 | Map |
| 키 변환 | 문자열·심볼로 변환 | 변환 없음 (SameValueZero 비교) |
| 객체 키 | `'[object Object]'` 하나로 합쳐짐 | 객체 자체가 키 |

```js
Object.groupBy([1, '1', 2], (x) => x)
// { 1: [1, '1'], 2: [2] }  (1과 '1'이 같은 키)
Map.groupBy([1, '1', 2, 1], (x) => x)
// Map(3) { 1 => [1, 1], '1' => ['1'], 2 => [2] }
```

- Object.groupBy의 결과는 프로토타입이 없어 `hasOwnProperty` 같은 메서드가 없습니다. `result.hasOwnProperty(k)`는 TypeError이고, `Object.hasOwn(result, k)`나 `k in result`를 씁니다.
- 프로토타입이 없으므로 `'constructor'` 같은 키와 상속 프로퍼티가 충돌하지 않습니다. 앞 절의 reduce 개수 세기 문제가 생기지 않습니다.
- 키가 문자열로 충분하면 Object.groupBy, 숫자·객체 같은 값 그대로 키가 필요하면 Map.groupBy입니다.
- 지원하지 않는 환경에서는 앞 절의 reduce 패턴으로 대신합니다.

## 순회 중 배열 변경

forEach, map, filter, some, every, flatMap, reduce는 호출 시점의 `length`를 한 번 읽고, 그 범위의 인덱스만 방문합니다. 각 인덱스는 방문하는 순간에 존재 여부와 값을 확인합니다.

| 순회 중 동작 | 결과 |
|--------------|------|
| 끝에 요소 추가 | 방문하지 않음 (범위가 고정) |
| 아직 방문 안 한 요소의 값 변경 | 콜백이 변경된 값을 받음 |
| 아직 방문 안 한 요소 삭제 | 건너뜀 (find 계열은 `undefined`로 방문) |
| 이미 방문한 요소 변경 | 순회에 영향 없음 |
| map 중 배열이 줄어듦 | 결과 길이는 그대로, 끝이 빈 슬롯 |

```js
const a = [1, 2]
let n = 0
a.forEach((x) => { a.push(x); n++ })
n // 2
a // [1, 2, 1, 2]
```

가장 흔한 사고는 순회하면서 요소를 지우는 것입니다. 삭제하면 뒤 요소가 앞으로 당겨지는데 인덱스는 계속 증가하므로 한 요소를 건너뜁니다.

```js
const c = [1, 2, 3, 4]
c.forEach((x, i) => { if (x < 3) c.splice(i, 1) })
c // [2, 3, 4] — 2가 남았다 (1을 지우자 2가 앞으로 이동)
```

- 조건에 맞는 요소를 남기려면 `filter`로 새 배열을 만듭니다.
- 제자리에서 지워야 하면 뒤에서부터 도는 `for` 루프를 씁니다.
- 복사본(`[...c]`)을 순회하면서 원본을 수정해도 안전합니다(자세히는 36편).

`for...of`는 규칙이 다릅니다. 배열 이터레이터가 매 단계마다 현재 `length`를 확인하므로 추가된 요소도 방문합니다(자세히는 35편).

```js
const b = [1]
for (const x of b) { if (b.length < 3) b.push(x + 1) }
b // [1, 2, 3] — 추가된 요소도 방문한다
```

find 계열은 삭제된 자리도 방문합니다. `find`로 순회하며 첫 반복에서 `pop()`하면 마지막 인덱스가 `undefined`로 콜백에 전달됩니다. forEach는 그 자리를 건너뜁니다.

## 빈 배열에서의 반환값

빈 배열에서는 콜백이 한 번도 호출되지 않으며 반환값은 메서드마다 정해진 기본값입니다.

| 호출 | 결과 |
|------|------|
| `[].forEach(f)` | `undefined` |
| `[].map(f)`, `[].filter(f)`, `[].flatMap(f)` | `[]` |
| `[].reduce(f, init)` | `init` |
| `[].reduce(f)` | TypeError |
| `[].some(f)` | `false` |
| `[].every(f)` | `true` |
| `[].find(f)`, `[].findLast(f)` | `undefined` |
| `[].findIndex(f)`, `[].findLastIndex(f)` | `-1` |
| `[].sort()` | `[]` (같은 배열) |
| `Object.groupBy([], f)` | 프로토타입이 `null`인 빈 객체 |
| `Map.groupBy([], f)` | 빈 Map |

빈 슬롯만 있는 배열은 빈 슬롯을 건너뛰는 메서드에서는 빈 배열과 같게 동작합니다. find 계열은 슬롯마다 콜백을 `undefined`로 호출하므로 다릅니다.

## 메서드 체이닝의 중간 배열

메서드 체이닝은 `map`, `filter` 등이 새 배열을 반환하는 성질을 이용해 메서드를 `.`으로 이어 쓰는 방식입니다. 각 단계는 입력 배열 전체를 순회하고, 결과로 중간 배열을 만듭니다.

```js
const result = [1, 2, 3, 4]
  .filter((n) => n % 2 === 0)
  .map((n) => n * 10)
// filter가 1, 2, 3, 4를 모두 검사한 뒤 map이 2, 4를 처리
// result: [20, 40]
```

- 단계는 요소별로 번갈아 실행되지 않습니다. 앞 단계가 전부 끝난 뒤 다음 단계가 시작됩니다.
- 콜백의 세 번째 인수 `array`와 `index`는 원본이 아니라 그 단계의 입력, 곧 직전 단계가 만든 중간 배열 기준입니다.
- 중간 배열의 객체 요소는 원본과 같은 참조입니다. 얕은 복사입니다.
- `forEach`는 `undefined`를 반환하고 `reduce`는 값 하나를 반환하므로 체인의 끝에만 올 수 있습니다.
- `sort`는 원본을 바꿉니다. `arr.sort().map(...)`은 원본을 정렬합니다. `arr.filter(...).sort()`는 `filter`가 만든 새 배열을 정렬하므로 원본이 안전합니다. 원본이 그대로여야 하면 `toSorted`나 `[...arr].sort()`를 씁니다.

단계가 k개이고 길이가 n이면 순회 k번과 임시 배열 k−1개가 생깁니다. 보통 크기에서는 문제가 되지 않으므로 성능이 측정으로 확인되기 전에는 읽기 쉬운 체인을 씁니다. 배열이 매우 크거나 앞부분 몇 개만 필요한데 전체를 처리하게 된다면 다음을 고려합니다.

- `for...of`로 한 번만 순회하고 `break`합니다.
- `reduce`나 `flatMap`으로 단계를 합칩니다.
- 이터레이터 헬퍼(ES2025)를 씁니다. 요소 하나가 모든 단계를 통과한 뒤 다음 요소로 넘어가고, 중간 배열이 없습니다(자세히는 35편).

```js
const firstTwo = [1, 2, 3, 4, 5].values()
  .filter((n) => n % 2 === 1)
  .map((n) => n * 10)
  .take(2)
  .toArray()
// [10, 30] — 4와 5는 검사조차 하지 않는다
```

## 고차 함수 비교

| 메서드 | 콜백 반환값의 용도 | 반환값 | 중단 |
|--------|--------------------|--------|------|
| forEach | 쓰지 않음 | `undefined` | 불가 |
| map | 새 요소 | 같은 길이의 새 배열 | 불가 |
| filter | truthy면 유지 | 일부 요소의 새 배열 | 불가 |
| reduce, reduceRight | 다음 `acc` | 누적값 하나 | 불가 |
| some | truthy면 종료 | 불리언 | 첫 truthy |
| every | falsy면 종료 | 불리언 | 첫 falsy |
| find, findLast | truthy면 종료 | 요소 또는 `undefined` | 첫 일치 |
| findIndex, findLastIndex | truthy면 종료 | 인덱스 또는 `-1` | 첫 일치 |
| flatMap | 배열이면 펼침 | 새 배열 | 불가 |
| sort | 순서(부호) | 같은 배열 | 불가 |

sort만 원본을 바꿉니다. 나머지는 원본을 바꾸지 않지만, 콜백이 요소 객체를 직접 수정하면 원본의 객체가 바뀝니다.

필요한 결과로 메서드를 고릅니다.

| 필요한 것 | 메서드 |
|-----------|--------|
| 요소마다 부수 효과 | forEach (중단이 필요하면 `for...of`) |
| 요소마다 변환 | map |
| 조건에 맞는 요소 모음 | filter |
| 하나의 값으로 합치기 | reduce |
| 조건 충족 여부 | some, every |
| 조건에 맞는 첫(마지막) 요소·위치 | find·findIndex, findLast·findLastIndex |
| 변환하면서 펼치기·제외하기 | flatMap |
| 키별로 묶기 | Object.groupBy, Map.groupBy |
| 순서 바꾸기 | sort (복사본은 `toSorted`) |

빈 슬롯 처리도 메서드 군마다 다릅니다.

| 처리 | 메서드 |
|------|--------|
| 콜백을 호출하지 않음 | forEach, map, filter, flatMap, reduce, reduceRight, some, every |
| `undefined`로 콜백을 호출 | find, findIndex, findLast, findLastIndex |
| 맨 끝으로 이동 | sort |

## 핵심 정리

- 기본 `sort()`는 요소를 문자열로 바꿔 코드 유닛 순으로 비교합니다. 숫자는 `(a, b) => a - b`를 쓰고, 정렬은 ES2019부터 안정이며 원본을 바꿉니다.
- `map`은 같은 길이의 새 배열, `filter`는 truthy인 요소의 새 배열, `forEach`는 `undefined`를 반환합니다. 콜백에 함수를 그대로 넘기면 index·array도 전달됩니다.
- `reduce`는 초기값을 항상 줍니다. 초기값이 없는 빈 배열은 TypeError이고, 요소가 하나면 콜백 없이 그 요소가 반환됩니다.
- 빈 배열에서 `some`은 `false`, `every`는 `true`입니다. `find` 계열은 못 찾으면 `undefined` 또는 `-1`이고 빈 슬롯을 방문합니다.
- 순회 범위는 시작 시점의 `length`로 고정됩니다. 순회 중 삭제는 요소를 건너뛰게 하므로 `filter`나 뒤에서부터의 `for`를 씁니다.
- `Object.groupBy`는 문자열 키의 프로토타입 없는 객체, `Map.groupBy`는 값 그대로의 키를 쓰는 Map을 반환합니다.
