## 핵심 먼저 보기

- async 함수는 항상 프로미스를 반환합니다. `return`은 이행, `throw`는 거부가 되고, 본문은 첫 `await` 전까지 동기로 실행됩니다.
- `await`는 그 함수만 멈추고 이행 값을 돌려주거나 거부 사유를 던집니다. 거부를 잡으려면 `await`하고 try...catch를 씁니다. try 안에서는 `return await`를 씁니다.
- 독립 작업은 먼저 시작해 `Promise.all`로 기다립니다. `forEach`·`filter` 콜백의 async는 기다려 주지 않으며, 개수 제한이 필요하면 작업자 풀을 씁니다.
- `await` 누락은 에러 없이 프로미스가 값 자리에 들어가는 실수입니다.
- 최상위 await는 모듈에서만 가능합니다(ES2022). `for await...of`와 `async function*`(ES2018)는 비동기 이터러블을 소비하고 만듭니다.
- 생성자는 async로 만들 수 없으므로 `static async` 팩토리를 씁니다.

## async 함수

async 함수(ES2017)는 `async` 키워드를 붙여 선언하며, 항상 프로미스를 반환하고 본문에서 `await`를 쓸 수 있는 함수입니다. 프로미스(자세히는 41편) 체인을 위에서 아래로 읽히는 코드로 쓰기 위해 도입됐습니다.

```js
async function a() {}          // 선언문
const b = async function () {} // 표현식
const c = async () => {}       // 화살표 함수
const obj = { async m() {} }   // 객체 메서드
class K {
  async m() {}                 // 클래스 메서드
  static async s() {}          // 정적 메서드
}
```

| 본문에서 | 반환된 프로미스 |
|----------|-----------------|
| `return 값` | 그 값으로 이행 |
| return 없이 끝남 | `undefined`로 이행 |
| `throw 값` | 그 값으로 거부 |

## 반환값의 프로미스 래핑

async 함수에서 `return`한 값은 무엇이든 프로미스 하나로 감싸집니다. 프로미스를 반환해도 `Promise<Promise<값>>`처럼 중첩되지 않습니다.

| return 하는 것 | 반환된 프로미스 |
|----------------|-----------------|
| 일반 값 | 그 값으로 이행 |
| 프로미스 | 그 프로미스의 결과를 따라간다 (이행이면 값, 거부면 사유) |
| thenable (`then` 메서드를 가진 객체) | `then`을 호출해 결과를 따라간다 |

```js
async function a() { return 1 }
async function b() { return Promise.resolve(2) }
async function c() { return Promise.reject(new Error('x')) }

a().then(v => console.log(v))          // 1
b().then(v => console.log(v))          // 2 (프로미스가 아니라 값)
c().catch(e => console.log(e.message)) // 'x'
```

## await

`await` 연산자는 프로미스가 확정될 때까지 async 함수의 실행을 멈추고, 이행되면 그 값을 식의 결과로, 거부되면 그 사유를 예외로 던집니다.

| 피연산자 | await의 결과 |
|----------|--------------|
| 이행되는 프로미스 | 이행 값 |
| 거부되는 프로미스 | 그 사유를 throw |
| thenable | `then`을 호출해 확정을 기다린 뒤 위와 같이 처리 |
| 그 외의 값 | 그 값 (단, 다음 줄은 마이크로태스크 뒤에 실행) |

## try...catch

`await`한 프로미스가 거부되면 그 자리에서 예외가 던져지므로 동기 코드처럼 `try...catch`로 잡습니다.

## return await와 return

async 함수에서 둘 다 최종 결과를 프로미스로 전달합니다. 다만 현재 함수의 `try...catch`로 거부를 잡거나 `finally` 정리 시점을 기다리려면 `return await`가 필요합니다.

## await 누락

`await`를 빠뜨리면 값 대신 프로미스를 받습니다. 에러 없이 틀린 값이 흘러가는 것이 문제입니다.

| 누락한 곳 | 증상 |
|-----------|------|
| 값을 읽을 때 | 프로미스 객체의 프로퍼티를 읽어 `undefined` |
| 조건식 | 프로미스는 항상 참이라 검증이 무시됨 |
| 연산·비교 | `p + 1`은 `'[object Promise]1'`, `p === 1`은 `false` |
| try 안 | 거부가 catch에 걸리지 않음 |
| 함수의 마지막 | 작업이 끝나기 전에 함수가 반환되고, 거부는 처리되지 않은 거부가 됨 |

## 순차와 병렬

`await`는 다음 줄을 멈추므로, 서로 독립인 작업을 `await`로 이어 쓰면 순차 실행이 되어 시간이 합산됩니다. 병렬은 프로미스를 모두 먼저 시작한 뒤 한꺼번에 기다리는 방식입니다. JavaScript는 싱글 스레드이므로 병렬은 계산이 아니라 입출력 대기 시간을 겹치는 것입니다.

| 방식 | 시작 시점 | 총 시간 | 하나가 실패하면 |
|------|-----------|---------|-----------------|
| 순차 `await` | 앞 작업이 끝난 뒤 | 합 | 뒤 작업은 시작도 안 함 |
| `Promise.all` | 전부 즉시 | 가장 긴 것 | 즉시 거부, 나머지는 계속 실행 |
| `Promise.allSettled` | 전부 즉시 | 가장 긴 것 | 전부 끝난 뒤 결과 배열 반환 |

## 반복문과 await

의존 작업은 `for...of` 안에서 `await`해 순차 실행합니다. 독립 작업은 `map`으로 프로미스를 만들고 `Promise.all`로 기다립니다. `forEach(async ...)`는 콜백의 프로미스를 기다리지 않습니다.

## 동시 실행 수 제한

`Promise.all`로 수천 개를 한꺼번에 시작하면 서버의 요청 제한, 소켓·파일 핸들 수, 메모리에 걸릴 수 있습니다. 진행 중인 작업 수를 일정 개수 이하로 유지하는 것을 동시 실행 수 제한이라고 합니다.

## Top-level await

최상위 await(ES2022)는 async 함수 밖, 모듈의 최상위에서 `await`를 쓰는 기능입니다. 모듈 전체가 async 함수 본문처럼 평가되어 비동기 초기화를 바로 적을 수 있습니다.

## for await...of

`for await...of`(ES2018)는 비동기 이터러블을 순회하며 매 반복에서 다음 값을 기다리는 반복문입니다. async 함수 안이나 모듈 최상위에서만 쓸 수 있습니다.

| 순서 | 대상에 있는 메서드 | 동작 |
|------|--------------------|------|
| 1 | `[Symbol.asyncIterator]` | 비동기 이터레이터로 순회 |
| 2 | `[Symbol.iterator]` | 일반 이터레이터로 순회하며 각 값을 `await` |
| 3 | 둘 다 없음 | TypeError (`5 is not async iterable`) |

## Async Iterator·Async Generator

비동기 이터레이터는 `next()`가 `{ value, done }` 객체를 프로미스로 감싸 반환하는 이터레이터입니다. 비동기 이터러블은 `[Symbol.asyncIterator]()` 메서드로 그 이터레이터를 돌려주는 객체입니다. `for await...of`가 이 프로토콜을 사용합니다(동기 이터레이터는 35편).

| 구분 | 제너레이터 | 비동기 제너레이터 |
|------|------------|-------------------|
| 선언 | `function*` | `async function*` |
| `next()` 반환 | `{ value, done }` | `{ value, done }`의 프로미스 |
| 프로토콜 심볼 | `Symbol.iterator` | `Symbol.asyncIterator` |
| 순회 | `for...of` | `for await...of` |
| 본문의 `await` | 불가 | 가능 |

## 생성자에 async를 못 쓰는 이유

생성자는 `new`가 만든 인스턴스를 돌려주는 함수이고, async 함수는 항상 프로미스를 돌려줍니다. 두 역할이 충돌하므로 명세는 클래스의 `constructor`에 `async`를 붙이는 것을 구문 오류로 정했습니다.

| 방법 | 형태 | 특징 |
|------|------|------|
| 정적 팩토리 | `static async create()` | 완성된 인스턴스만 얻는다. 가장 많이 쓴다 |
| 초기화 프로미스 보관 | `this.ready = this.#init()` | `new` 뒤에 `await obj.ready` |
| init 메서드 | `await obj.init()` | 초기화 전 인스턴스가 노출된다 |
