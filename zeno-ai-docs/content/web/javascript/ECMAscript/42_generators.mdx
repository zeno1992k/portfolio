## 핵심 먼저 보기

- 제너레이터 함수(`function*`)는 호출해도 본문이 실행되지 않고 제너레이터 객체를 반환하며, 화살표 함수로는 만들 수 없습니다.
- `next(v)`는 다음 `yield`까지 실행하고 `{ value, done }`을 돌려주며, `v`는 멈춰 있던 `yield`의 결과가 됩니다. 첫 `next`의 인수는 버려집니다.
- `return(v)`와 `throw(e)`는 멈춘 지점에서 종료·예외를 일으키고 `finally`를 실행합니다. `finally` 안의 `yield`는 종료를 미룹니다.
- `yield*`는 이터러블에 위임하며 `next`·`throw`·`return`을 전달하고, 위임 대상의 반환값이 표현식의 값이 됩니다.
- `*[Symbol.iterator]()`로 이터러블을 구현하고, 제너레이터는 필요할 때만 값을 계산하므로 무한 시퀀스와 지연 파이프라인, 상태 머신에 씁니다.
- 프로미스를 `yield`하는 실행기가 async/await의 원형이며, 지금의 비동기 흐름 제어는 async/await을 씁니다.

## 제너레이터의 개념

제너레이터(generator)는 실행을 중간에 멈췄다가 같은 지점부터 이어서 실행할 수 있는 함수입니다. ES2015에서 도입됐고, 멈추는 지점은 `yield`로 표시합니다.

| 항목 | 일반 함수 | 제너레이터 함수 |
|------|-----------|-----------------|
| 호출하면 | 본문을 실행하고 반환값을 돌려준다 | 본문을 실행하지 않고 제너레이터 객체를 돌려준다 |
| 값을 내는 횟수 | `return`으로 한 번 | `yield`로 여러 번, 마지막에 `return` |
| 중간에 멈춤 | 불가능 | `yield`에서 멈추고 재개 가능 |
| 실행 순서를 쥔 쪽 | 함수 | 호출자(`next()`를 부르는 쪽) |

## 제너레이터 함수

제너레이터 함수는 `function*`로 만든 함수입니다. 호출하면 본문을 실행하지 않고 제너레이터 객체를 반환합니다.

```js
function* a() { yield 1 }            // 선언문
const b = function* () { yield 1 }   // 표현식
const c = function* named() { yield 1 } // 이름 있는 표현식
```

## 제너레이터 메서드 표기

객체 리터럴과 클래스의 메서드도 이름 앞에 `*`를 붙여 제너레이터로 만들 수 있습니다.

| 위치 | 표기 |
|------|------|
| 객체 리터럴 | `*name() {}` |
| 클래스 인스턴스 메서드 | `*name() {}` |
| 클래스 정적 메서드 | `static *name() {}` |
| 계산된 키 | `*[Symbol.iterator]() {}` |
| 비동기(43편) | `async *name() {}` |

```js
const o = { *g() { yield 1 } }
class C {
  *g() { yield 1 }
  static *sg() { yield 2 }
  *[Symbol.iterator]() { yield 3 }
}
```

## 화살표 함수로 만들 수 없는 이유

제너레이터 화살표 함수는 존재하지 않습니다. ECMA-262 문법에 화살표 제너레이터를 만드는 규칙이 없어서, 어떻게 써도 SyntaxError입니다.

## 제너레이터 객체

제너레이터 객체는 제너레이터 함수를 호출한 결과로, 이터레이터이면서 이터러블입니다. `next`를 가지고 있고, `[Symbol.iterator]()`는 자기 자신을 반환합니다.

| 단계 | 내용 |
|------|------|
| 제너레이터 객체 | 호출마다 새로 만들어진다 |
| `gen.prototype` | 제너레이터 함수마다 하나씩 있는 객체 |
| `%GeneratorPrototype%` | `next`, `return`, `throw`, `Symbol.toStringTag`(`'Generator'`) |
| `Iterator.prototype` | `[Symbol.iterator]`와 이터레이터 헬퍼(ES2025, 자세히는 35편) |

## `yield`와 일시 중지·재개

`yield`는 제너레이터의 실행을 멈추고 피연산자 값을 호출자에게 내보내는 연산자입니다. 재개되면 `yield` 표현식은 `next()`에 넘긴 인수로 평가됩니다(아래 양방향 통신 절).

1. `next()`가 호출되면 멈춘 지점부터 다음 `yield`까지 실행합니다.
2. `yield` 값을 `{ value, done: false }`에 담아 호출자에게 돌려주고 멈춥니다.
3. 본문이 `return`을 만나거나 끝에 도달하면 `{ value: 반환값, done: true }`를 돌려주고 종료합니다. 반환값이 없으면 `value`는 `undefined`입니다.

## `next`·`return`·`throw`

제너레이터 객체는 실행을 조종하는 메서드 세 개를 가집니다. 세 메서드 모두 `{ value, done }` 객체를 반환합니다.

| 메서드 | 하는 일 |
|--------|---------|
| `next(v)` | 재개한다. 멈춰 있던 `yield` 표현식이 `v`로 평가된다 |
| `return(v)` | 멈춘 지점에서 `return v`를 실행한 것처럼 종료한다 |
| `throw(e)` | 멈춘 지점에서 `throw e`를 실행한 것처럼 예외를 일으킨다 |

## `yield*`

`yield*`는 다른 이터러블에 실행을 위임하는 연산자입니다. 위임 대상이 내는 값을 하나씩 그대로 내보내고, 대상이 끝나면 그 반환값이 `yield*` 표현식의 값이 됩니다.

## `next` 인수와 양방향 통신

`next(value)`의 인수는 멈춰 있던 `yield` 표현식의 결과가 됩니다. 첫 `next`는 아직 멈춘 `yield`가 없어서 인수가 버려집니다. `yield`로 내보내는 값과 `next`로 집어넣는 값을 구별합니다.

## 이터러블 구현

이터러블 프로토콜은 `[Symbol.iterator]()`가 `next()`를 가진 이터레이터를 반환하는 규칙입니다(자세히는 35편). 제너레이터를 쓰면 이터레이터 객체를 직접 만들지 않고 `yield`만으로 구현할 수 있습니다.

## 지연 평가 파이프라인

지연 평가(lazy evaluation)는 값이 실제로 필요해질 때까지 계산을 미루는 방식입니다. 제너레이터는 `next()`가 불릴 때만 다음 값을 계산하므로, 끝이 없는 시퀀스도 표현할 수 있고 여러 단계를 이어도 중간 배열이 생기지 않습니다.

| 방식 | 처리 순서 | 중간 결과 |
|------|-----------|-----------|
| 배열 메서드(즉시 평가) | `map`이 전체를 끝낸 뒤 `filter`가 전체를 처리 | 단계마다 새 배열 |
| 제너레이터(지연 평가) | 값 하나가 `map`에서 `filter`까지 통과한 뒤 다음 값 | 없음 |

## 상태 머신

상태 머신은 현재 상태와 입력(이벤트)에 따라 다음 상태가 정해지는 모델입니다. 제너레이터에서는 실행 위치 자체가 상태이므로, 상태 변수와 `switch` 없이 코드 순서로 상태를 표현할 수 있습니다.

- `yield state`가 현재 상태를 밖으로 내보내고, `next(event)`가 이벤트를 안으로 넣습니다.
- 정의되지 않은 (상태, 이벤트) 조합은 어느 `if`에도 걸리지 않으므로 상태가 유지됩니다.
- 제너레이터 객체는 복제하거나 되감을 수 없습니다. 상태를 저장하거나 이전 상태로 되돌려야 하면 상태 값을 보관하는 일반 객체나 함수가 낫습니다.
- 상태와 전이가 많으면 전이 표(객체)로 쓰는 편이 읽기 쉽습니다. 제너레이터는 "단계가 순서대로 이어지는 흐름"에 적합합니다.

## 비동기 처리

제너레이터는 `yield`에서 멈추므로 프로미스를 `yield`하고 이행되면 그 값으로 재개하는 실행기를 만들 수 있습니다. 이렇게 하면 비동기 코드를 위에서 아래로 읽히는 동기 코드처럼 쓸 수 있습니다. async/await 이전에 쓰던 방식이며, async/await은 이 구조를 언어 문법으로 흡수한 것입니다(자세히는 43편).

| 제너레이터 방식 | async/await |
|-----------------|-------------|
| `function*` | `async function` |
| `yield 프로미스` | `await 프로미스` |
| 직접 만든 실행기 `run` | 엔진이 내장 |
| 거부 시 `it.throw(e)` | 거부 시 `await` 자리에서 예외 |
| `run`이 프로미스를 반환 | async 함수가 프로미스를 반환 |
