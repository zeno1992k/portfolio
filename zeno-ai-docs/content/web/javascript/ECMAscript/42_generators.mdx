## 제너레이터의 개념

제너레이터(generator)는 실행을 중간에 멈췄다가 같은 지점부터 이어서 실행할 수 있는 함수입니다. ES2015에서 도입됐고, 멈추는 지점은 `yield`로 표시합니다.

일반 함수는 호출되면 `return`이나 예외로 끝날 때까지 멈추지 않습니다. 제너레이터는 `yield`에서 값을 내보내고 멈추며, 멈춰 있는 동안에도 지역 변수와 실행 위치가 보존됩니다.

| 항목 | 일반 함수 | 제너레이터 함수 |
|------|-----------|-----------------|
| 호출하면 | 본문을 실행하고 반환값을 돌려준다 | 본문을 실행하지 않고 제너레이터 객체를 돌려준다 |
| 값을 내는 횟수 | `return`으로 한 번 | `yield`로 여러 번, 마지막에 `return` |
| 중간에 멈춤 | 불가능 | `yield`에서 멈추고 재개 가능 |
| 실행 순서를 쥔 쪽 | 함수 | 호출자(`next()`를 부르는 쪽) |

- 제너레이터는 스레드가 아닙니다. 호출자가 `next()`를 부르는 동안 호출자는 멈추고 제너레이터만 실행되며, 다음 `yield`에서 호출자로 돌아옵니다. 두 쪽이 동시에 실행되는 순간은 없습니다.
- 값은 소비하는 쪽이 당겨 갑니다. `next()`가 불리기 전에는 다음 값을 계산하지 않습니다.
- 이런 방식으로 협력하는 실행 흐름을 코루틴(coroutine)이라고 부릅니다.

| 용도 | 제너레이터가 맞는 이유 | 절 |
|------|------------------------|-----|
| 이터러블 구현 | `yield`만으로 이터레이터를 만든다 | 이터러블 구현 |
| 지연 계산, 무한 시퀀스 | 요청받은 만큼만 계산한다 | 지연 평가 파이프라인 |
| 값을 주고받는 통신 | `yield`와 `next(값)`이 양방향 통로다 | next 인수와 양방향 통신 |
| 상태 머신 | 실행 위치가 곧 상태다 | 상태 머신 |
| 비동기 흐름 제어 | 프로미스를 기다리며 멈춘다 | 비동기 처리 |

## 제너레이터 함수

제너레이터 함수는 `function*`로 만든 함수입니다. 호출하면 본문을 실행하지 않고 제너레이터 객체를 반환합니다.

```js
function* a() { yield 1 }            // 선언문
const b = function* () { yield 1 }   // 표현식
const c = function* named() { yield 1 } // 이름 있는 표현식
```

- `*`의 위치는 `function* f`, `function *f`, `function*f` 모두 허용됩니다. 관례는 `function*`입니다.
- 선언문은 일반 함수 선언처럼 호이스팅되므로 선언 위쪽에서 호출할 수 있습니다.
- `this`와 `arguments`는 일반 함수처럼 호출 방식에 따라 정해집니다.
- 생성자로 쓸 수 없습니다. `new a()`는 TypeError입니다.
- `return` 값은 마지막 결과 객체의 `value`가 됩니다(자세히는 아래 `next`·`return`·`throw` 절).
- 비동기 제너레이터 `async function*`는 43편에서 다룹니다.

인수 바인딩과 매개변수 기본값 평가는 호출하는 순간에 일어나고, 본문은 첫 `next()`에서 시작합니다.

```js
function* g(a = console.log('default')) {
  console.log('body')
}
const it = g()  // 'default' 출력, 본문은 아직 실행 전
it.next()       // 'body' 출력
```

`GeneratorFunction` 생성자는 전역 이름이 아니며 `Object.getPrototypeOf(function* () {}).constructor`로 얻습니다. 문자열을 코드로 실행하는 `Function` 생성자와 같은 부류이므로 쓰지 않습니다.

## 제너레이터 메서드 표기

객체 리터럴과 클래스의 메서드도 이름 앞에 `*`를 붙여 제너레이터로 만들 수 있습니다.

| 위치 | 표기 |
|------|------|
| 객체 리터럴 | `*name() {}` |
| 클래스 인스턴스 메서드 | `*name() {}` |
| 클래스 정적 메서드 | `static *name() {}` |
| 계산된 키 | `*[Symbol.iterator]() {}` |
| 비동기(43편) | `async *name() {}` |

```js
const o = { *g() { yield 1 } }
class C {
  *g() { yield 1 }
  static *sg() { yield 2 }
  *[Symbol.iterator]() { yield 3 }
}
```

- `*`는 이름 앞에 둡니다. `g*() {}`는 SyntaxError입니다.
- 메서드 표기로 만든 제너레이터도 생성자가 아닙니다. `new o.g()`는 TypeError입니다.
- 접근자는 제너레이터가 될 수 없습니다. `get *x() {}`는 SyntaxError입니다.
- `*[Symbol.iterator]()`가 이터러블을 만드는 표준 관용구입니다(아래 이터러블 구현 절).

## 화살표 함수로 만들 수 없는 이유

제너레이터 화살표 함수는 존재하지 않습니다. ECMA-262 문법에 화살표 제너레이터를 만드는 규칙이 없어서, 어떻게 써도 SyntaxError입니다.

```js
const a = *() => {}        // SyntaxError
const b = async *() => {}  // SyntaxError
```

`yield`는 자신을 직접 감싼 제너레이터 함수의 실행을 멈추는 연산입니다. 화살표 함수와 콜백은 별개의 함수라서 바깥 제너레이터를 멈출 수 없고, 그 본문 안의 `yield`는 문법 오류가 됩니다. 제너레이터 안에서 화살표 함수를 쓰는 것 자체는 문제가 없고, 그 화살표 함수 안에서 `yield`를 쓰는 것이 문제입니다.

```js
function* outer() {
  [1, 2].forEach((x) => { yield x }) // ❌ SyntaxError
  for (const x of [1, 2]) yield x    // ✅
  yield* [1, 2]                      // ✅
}
```

대안은 다음과 같습니다.

- 제너레이터 함수 표현식이나 메서드 표기를 씁니다.
- 바깥 `this`가 필요하면 메서드 표기로 쓰거나, 제너레이터 함수 표현식에 `.bind(this)`를 붙입니다.
- 콜백 안에서 값을 내야 하면 `forEach`를 `for...of`로 바꿉니다.

## 제너레이터 객체

제너레이터 객체는 제너레이터 함수를 호출한 결과로, 이터레이터이면서 이터러블입니다. `next`를 가지고 있고, `[Symbol.iterator]()`는 자기 자신을 반환합니다.

```js
function* gen() {
  console.log('A')
  yield 1
  console.log('B')
  return 2
}
const g = gen()  // 출력 없음
g.next()         // 'A' 출력 → { value: 1, done: false }
g.next()         // 'B' 출력 → { value: 2, done: true }
g.next()         // { value: undefined, done: true }
g[Symbol.iterator]() === g  // true
```

프로토타입 체인은 다음 순서입니다.

| 단계 | 내용 |
|------|------|
| 제너레이터 객체 | 호출마다 새로 만들어진다 |
| `gen.prototype` | 제너레이터 함수마다 하나씩 있는 객체 |
| `%GeneratorPrototype%` | `next`, `return`, `throw`, `Symbol.toStringTag`(`'Generator'`) |
| `Iterator.prototype` | `[Symbol.iterator]`와 이터레이터 헬퍼(ES2025, 자세히는 35편) |

- `Object.prototype.toString.call(g)`는 `'[object Generator]'`입니다.
- 일반 함수의 `prototype`과 달리 `gen.prototype`은 생성자 역할을 하지 않습니다. 제너레이터 객체가 상속할 객체일 뿐입니다.
- 제너레이터 객체는 한 번 소비하면 끝입니다. 되감기나 복제 API가 없으므로 다시 순회하려면 제너레이터 함수를 다시 호출합니다.

```js
function* one() { yield 1 }
const once = one()
console.log([...once])  // [1]
console.log([...once])  // []
```

상태는 네 가지이며, 명세 용어로는 다음과 같습니다. 상태를 조회하는 공개 API는 없습니다.

| 상태 | 시점 |
|------|------|
| suspended-start | 생성 직후, 본문 첫 줄 실행 전 |
| suspended-yield | `yield`에서 멈춘 상태 |
| executing | 본문을 실행하는 중 |
| completed | `return`, 예외, 본문 끝으로 종료된 상태 |

executing 상태에서 `next()`를 다시 호출하면 TypeError입니다. 제너레이터 본문이 자기 자신의 `next()`를 호출하는 경우가 해당합니다.

흔한 실수는 제너레이터 함수 자체를 순회하려는 것입니다.

```js
for (const x of gen) {}    // ❌ TypeError: gen은 이터러블이 아니다
for (const x of gen()) {}  // ✅ 호출한 결과가 이터러블이다
```

## `yield`와 일시 중지·재개

`yield`는 제너레이터의 실행을 멈추고 피연산자 값을 호출자에게 내보내는 연산자입니다. 재개되면 `yield` 표현식은 `next()`에 넘긴 인수로 평가됩니다(아래 양방향 통신 절).

```js
function* counter() {
  let n = 0
  while (true) yield ++n
}
const c = counter()
c.next().value  // 1
c.next().value  // 2 — n이 보존되어 있다
```

실행 흐름은 다음과 같습니다.

1. `next()`가 호출되면 멈춘 지점부터 다음 `yield`까지 실행합니다.
2. `yield` 값을 `{ value, done: false }`에 담아 호출자에게 돌려주고 멈춥니다.
3. 본문이 `return`을 만나거나 끝에 도달하면 `{ value: 반환값, done: true }`를 돌려주고 종료합니다. 반환값이 없으면 `value`는 `undefined`입니다.

규칙은 다음과 같습니다.

- 피연산자가 없는 `yield`는 `undefined`를 내보냅니다. `yield` 뒤에서 줄바꿈하면 피연산자가 없는 것으로 처리됩니다.

```js
function* a() {
  yield
  1  // 별개의 식 문장이라 값이 되지 않는다
}
console.log([...a()])  // [undefined]
```

- `yield` 표현식은 우선순위가 대입 수준으로 낮습니다. `yield 1 + 2`는 `yield (1 + 2)`입니다. 이항 연산자의 피연산자 자리에는 괄호가 필요합니다.

```js
const x = yield 1 + 2      // ✅ 3을 내보낸다
const y = (yield 5) + 1    // ✅
const z = 1 + yield 2      // ❌ SyntaxError
Math.max(yield 1, yield 2) // ✅ 인수 자리는 괄호 없이 가능
```

- `yield`는 제너레이터 함수 본문 안에서 직접 써야 합니다. 안쪽의 일반 함수·화살표 함수·콜백 안에서는 SyntaxError입니다.
- `return`의 값은 `for...of`, 스프레드, 구조 분해에 나타나지 않습니다. `done: true`인 결과의 `value`는 순회 도구가 버립니다.

```js
function* f() { yield 1; return 2 }
console.log([...f()])  // [1] — 2는 나오지 않는다
```

- `yield` 앞의 코드는 이전 `next()` 호출 안에서, 뒤의 코드는 다음 `next()` 호출 안에서 실행됩니다. 본문의 `console.log`가 `next()` 호출 시점에 맞춰 찍힙니다.
- 제너레이터를 만들기만 하고 순회하지 않으면 본문은 한 줄도 실행되지 않습니다.

```js
function* noisy() { console.log('ran'); yield 1 }
const unused = noisy()  // 아무것도 출력되지 않는다
```

## `next`·`return`·`throw`

제너레이터 객체는 실행을 조종하는 메서드 세 개를 가집니다. 세 메서드 모두 `{ value, done }` 객체를 반환합니다.

| 메서드 | 하는 일 |
|--------|---------|
| `next(v)` | 재개한다. 멈춰 있던 `yield` 표현식이 `v`로 평가된다 |
| `return(v)` | 멈춘 지점에서 `return v`를 실행한 것처럼 종료한다 |
| `throw(e)` | 멈춘 지점에서 `throw e`를 실행한 것처럼 예외를 일으킨다 |

상태별 동작은 다음과 같습니다.

| 상태 | `next(v)` | `return(v)` | `throw(e)` |
|------|-----------|-------------|------------|
| suspended-start | 본문 시작 | 본문 없이 종료, value는 `v` | 본문 없이 종료, `e`를 던짐 |
| suspended-yield | 재개 | 멈춘 지점에서 return | 멈춘 지점에서 throw |
| completed | `undefined`, done `true` | value `v`, done `true` | `e`를 던짐 |
| executing | TypeError | TypeError | TypeError |

```js
function* g() { yield 1; yield 2; yield 3 }
let it = g()
it.next()          // { value: 1, done: false }
it.return(99)      // { value: 99, done: true }
it.next()          // { value: undefined, done: true }
it = g()           // 새 제너레이터, 아직 시작 전
it.return('early') // { value: 'early', done: true }
it.next()          // { value: undefined, done: true }
```

### `return`과 `finally`

`return(v)`는 멈춘 지점에서 `return`을 실행하는 것이므로 `try...finally`의 `finally`가 실행됩니다.

```js
function* g() {
  try { yield 1; yield 2 }
  finally { console.log('cleanup') }
}
const it = g()
it.next()       // { value: 1, done: false }
it.return('r')  // 'cleanup' 출력
                // → { value: 'r', done: true }
```

`finally` 안의 동작에 따라 결과가 달라집니다.

| `finally` 안의 코드 | `return('r')`의 결과 |
|---------------------|----------------------|
| 일반 코드만 있음 | `{ value: 'r', done: true }` |
| `yield 'step'`이 있음 | `{ value: 'step', done: false }`, 다음 `next()`에서 나머지를 실행한 뒤 `{ value: 'r', done: true }` |
| `return 'override'`가 있음 | `{ value: 'override', done: true }` |

`return()`이 항상 `done: true`를 돌려주는 것은 아닙니다. `finally` 안에서 `yield`하면 종료가 미뤄집니다.

### `throw`

`throw(e)`는 멈춘 `yield` 자리에서 `e`를 던집니다. 제너레이터 안에서 `try...catch`로 잡으면 실행이 이어지고, 잡지 못하면 호출자에게 전파되며 제너레이터는 종료됩니다.

```js
function* g() {
  while (true) {
    try { yield 'waiting' }
    catch (e) { console.log('inside', e) }
  }
}
const it = g()
it.next()       // { value: 'waiting', done: false }
it.throw('E1')  // 'inside E1' 출력
                // → { value: 'waiting', done: false }
```

- 잡았을 때의 반환값은 다음 `yield`가 내보낸 `{ value, done: false }`입니다.
- 잡지 못하면 `it.throw()` 호출 자리에서 예외가 나가고, 이후 `next()`는 `{ value: undefined, done: true }`입니다.
- 시작 전에 `throw(e)`를 호출하면 본문을 실행하지 않고 `e`가 던져진 채 종료됩니다.

### 소비 문법이 부르는 `return`

`for...of`를 `break`·`return`·예외로 빠져나가거나 구조 분해가 필요한 만큼만 값을 꺼내면, 엔진이 이터레이터의 `return()`을 자동으로 호출합니다. 제너레이터에서는 `finally`가 실행되므로 자원 정리 코드를 둘 수 있습니다(자세히는 35편).

```js
function* f() {
  try { yield 1; yield 2 } finally { console.log('closed') }
}
for (const x of f()) { break }  // 'closed' 출력
const [first] = f()             // 'closed' 출력
```

`for...of`가 끝까지 소진되면 `return()`은 호출되지 않습니다.

## `yield*`

`yield*`는 다른 이터러블에 실행을 위임하는 연산자입니다. 위임 대상이 내는 값을 하나씩 그대로 내보내고, 대상이 끝나면 그 반환값이 `yield*` 표현식의 값이 됩니다.

```js
function* inner() { yield 'a'; yield 'b'; return 'ret' }
function* outer() {
  yield 0
  const r = yield* inner()  // 'a', 'b'를 차례로 내보낸다
  console.log(r)            // 'ret'
  yield* [10, 20]           // 이터러블이면 무엇이든 위임 가능
}
console.log([...outer()])   // [0, 'a', 'b', 10, 20]
```

- `yield`와 달리 값 하나가 아니라 이터러블의 요소 전체를 내보냅니다.

```js
function* a1() { yield [1, 2] }
function* a2() { yield* [1, 2] }
console.log([...a1()])  // [[1, 2]]
console.log([...a2()])  // [1, 2]
```

- 위임 대상의 `return` 값은 순회 도구에는 나타나지 않고 `yield*` 표현식의 값으로만 받을 수 있습니다. 배열처럼 반환값이 없는 이터러블은 `undefined`입니다.
- 문자열도 이터러블이므로 `yield* 'hi'`는 `'h'`, `'i'`를 내보냅니다.

### 양방향 위임

위임 중에는 바깥 제너레이터에 대한 `next`·`throw`·`return` 호출이 안쪽 이터레이터로 그대로 전달됩니다.

```js
function* inner() {
  const x = yield 'a'
  console.log('inner got', x)
}
function* outer() { yield* inner() }
const it = outer()
it.next()     // { value: 'a', done: false }
it.next('X')  // 'inner got X' 출력
              // → { value: undefined, done: true }
```

- `throw(e)`는 안쪽의 `yield` 자리에서 던져지고, 안쪽이 잡으면 위임이 이어집니다.
- `return(v)`는 안쪽의 `finally`가 먼저 실행되고 이어서 바깥의 `finally`가 실행됩니다.
- 안쪽 이터레이터에 `throw` 메서드가 없으면 `return`이 있을 때 호출해 닫은 뒤 TypeError를 던집니다. 제너레이터에는 항상 `throw`가 있어서 해당하지 않고, 직접 만든 이터레이터에서 일어납니다.

### 재귀 위임

`yield*`에 자기 자신을 넣으면 트리 순회가 한 줄로 끝납니다.

```js
function* walk(node) {
  yield node.value
  for (const kid of node.kids) yield* walk(kid)
}
const tree = { value: 1, kids: [
  { value: 2, kids: [{ value: 3, kids: [] }] },
  { value: 4, kids: [] },
] }
console.log([...walk(tree)])  // [1, 2, 3, 4] — 깊이 우선
```

흔한 실수는 콜백 안에서 `yield*`를 쓰려는 것입니다. `yield`와 마찬가지로 제너레이터 본문 바로 안에서만 쓸 수 있습니다.

## `next` 인수와 양방향 통신

`next(v)`의 `v`는 멈춰 있던 `yield` 표현식의 결과가 됩니다. `yield`로 값을 내보내고 `next` 인수로 값을 받으므로 호출자와 제너레이터가 값을 주고받습니다.

```js
function* dialog() {
  const name = yield 'name?'
  const age = yield `hi ${name}, age?`
  return `${name}:${age}`
}
const d = dialog()
d.next()        // { value: 'name?', done: false }
d.next('Kim')   // { value: 'hi Kim, age?', done: false }
d.next(20)      // { value: 'Kim:20', done: true }
```

| 방향 | 통로 |
|------|------|
| 제너레이터 → 호출자 | `yield` 피연산자, 마지막 `return` 값 |
| 호출자 → 제너레이터 | `next(v)`의 `v`, `throw(e)`의 `e`, `return(v)`의 `v` |

규칙은 다음과 같습니다.

- 첫 `next()`의 인수는 버려집니다. 첫 호출은 본문을 시작시킬 뿐이고, 값을 받을 `yield`가 아직 없기 때문입니다.

```js
function* e() { const a = yield 'q1'; console.log(a) }
const it = e()
it.next('ignored')  // { value: 'q1', done: false }
it.next('A')        // 'A' 출력
                    // → { value: undefined, done: true }
```

- 인수와 반환값은 한 칸씩 어긋납니다. N번째 호출의 인수는 N-1번째 `yield`가 받고, N번째 호출의 반환값은 N번째 `yield`가 내보낸 값입니다.

```js
function* g() {
  const x = yield 1 + 2    // 1번째 호출의 반환값은 3
  const y = (yield 5) + 1  // 2번째 호출 인수가 x가 된다
  return [x, y]            // 3번째 호출 인수가 yield 5의 결과
}
const it = g()
it.next()      // { value: 3, done: false }
it.next('A')   // x = 'A' → { value: 5, done: false }
it.next(10)    // y = 11 → { value: ['A', 11], done: true }
```

실행 중인 누적 평균처럼, 호출자가 보낸 값으로 제너레이터 안의 상태를 갱신하는 데 씁니다.

```js
function* avg() {
  let sum = 0, n = 0, mean = null
  while (true) {
    const v = yield mean
    sum += v; n++; mean = sum / n
  }
}
const it = avg(); it.next()  // 첫 호출로 시작만 시킨다
it.next(10).value  // 10
it.next(20).value  // 15
it.next(60).value  // 30
```

흔한 실수는 첫 `next()`에 값을 넣고 받았다고 기대하는 것입니다. 이런 제너레이터는 먼저 `next()`를 한 번 불러 첫 `yield`까지 진행시켜 둬야 합니다.

## 이터러블 구현

이터러블 프로토콜은 `[Symbol.iterator]()`가 `next()`를 가진 이터레이터를 반환하는 규칙입니다(자세히는 35편). 제너레이터를 쓰면 이터레이터 객체를 직접 만들지 않고 `yield`만으로 구현할 수 있습니다.

직접 구현하면 순회 상태를 클로저 변수에 두고 결과 객체를 손으로 만들어야 합니다.

```js
const manual = {
  from: 1, to: 3,
  [Symbol.iterator]() {
    let i = this.from
    const to = this.to
    return {
      next: () => i <= to
        ? { value: i++, done: false }
        : { value: undefined, done: true },
    }
  },
}
```

제너레이터 메서드로 쓰면 같은 일을 순회 코드만으로 끝냅니다.

```js
class Range {
  constructor(from, to) { this.from = from; this.to = to }
  *[Symbol.iterator]() {
    for (let i = this.from; i <= this.to; i++) yield i
  }
}
const r = new Range(1, 3)
console.log([...r])  // [1, 2, 3]
console.log([...r])  // [1, 2, 3] — 호출마다 새 제너레이터
```

- `[Symbol.iterator]()`가 불릴 때마다 새 제너레이터 객체가 만들어지므로 여러 번 순회할 수 있습니다. 제너레이터 객체 자체를 이터러블로 넘기면 한 번만 순회됩니다.
- 이터러블을 받는 모든 문법과 API가 그대로 동작합니다: `for...of`, 스프레드, 구조 분해, `Array.from`, `new Set`, `new Map`, `Promise.all`, `Object.fromEntries`.
- 일반 객체에 나중에 붙일 수도 있습니다.

```js
const obj = { a: 1, b: 2 }
obj[Symbol.iterator] = function* () {
  yield* Object.entries(this)
}
console.log([...obj])  // [['a', 1], ['b', 2]]
```

- 다른 이터러블을 감싸 가공할 때는 `yield*`나 `for...of`와 `yield`를 조합합니다.
- 소비자가 중간에 멈추면 `return()`이 불려 `finally`가 실행됩니다(앞의 `return`과 `finally` 절).
- 제너레이터 객체는 `Iterator.prototype`을 상속하므로 ES2025 이터레이터 헬퍼(`map`, `filter`, `take`, `toArray` 등)를 그대로 쓸 수 있습니다(자세히는 35편).

## 지연 평가 파이프라인

지연 평가(lazy evaluation)는 값이 실제로 필요해질 때까지 계산을 미루는 방식입니다. 제너레이터는 `next()`가 불릴 때만 다음 값을 계산하므로, 끝이 없는 시퀀스도 표현할 수 있고 여러 단계를 이어도 중간 배열이 생기지 않습니다.

```js
function* naturals() {
  let n = 1
  while (true) yield n++  // 무한 시퀀스
}
function* map(it, fn) {
  for (const x of it) yield fn(x)
}
function* filter(it, ok) {
  for (const x of it) if (ok(x)) yield x
}
```

```js
function* take(it, n) {
  if (n <= 0) return
  for (const x of it) {
    yield x
    if (--n === 0) return  // n개를 내고 바로 멈춘다
  }
}
const squares = map(naturals(), (n) => n * n)
const odd = filter(squares, (n) => n % 2)
console.log([...take(odd, 3)])  // [1, 9, 25]
```

배열 메서드와 처리 순서가 다릅니다.

| 방식 | 처리 순서 | 중간 결과 |
|------|-----------|-----------|
| 배열 메서드(즉시 평가) | `map`이 전체를 끝낸 뒤 `filter`가 전체를 처리 | 단계마다 새 배열 |
| 제너레이터(지연 평가) | 값 하나가 `map`에서 `filter`까지 통과한 뒤 다음 값 | 없음 |

각 단계에 로그를 찍으면 배열 메서드는 `map` 호출이 모두 끝난 뒤 `filter` 호출이 시작되고, 제너레이터 파이프라인은 `map(1)`, `filter(1)`, `map(2)`, `filter(2)`처럼 번갈아 실행됩니다.

규칙은 다음과 같습니다.

- 파이프라인은 마지막 소비자(`for...of`, 스프레드, `next()`)가 값을 당길 때만 움직입니다. 만들기만 하고 소비하지 않으면 아무 일도 하지 않습니다.
- `take`가 `return`으로 빠져나오면 `for...of`가 상류 이터레이터를 차례로 닫습니다. `finally`가 모든 단계에서 실행되며, `take`가 없으면 무한 시퀀스에서 순회가 끝나지 않습니다.
- 한 번 소비한 파이프라인은 다시 쓸 수 없습니다. 다시 돌리려면 `naturals()`부터 새로 만듭니다.

흔한 실수는 `take`에서 값을 먼저 꺼낸 뒤 개수를 검사하는 것입니다.

```js
function* badTake(it, n) {
  for (const x of it) {
    if (n-- <= 0) return  // ❌ n+1번째 값을 이미 꺼냈다
    yield x
  }
}
```

`badTake(it, 3)`은 원본에서 4개를 꺼냅니다(`it`이 부수효과를 가지면 그 효과가 한 번 더 일어납니다). 앞의 `take`처럼 n개를 내보낸 직후에 멈춰야 3개만 꺼냅니다.

ES2025 이터레이터 헬퍼를 쓰면 같은 파이프라인을 메서드 체인으로 쓸 수 있습니다.

```js
naturals().map((n) => n * n).filter((n) => n % 2)
  .take(3).toArray()  // [1, 9, 25]
```

## 상태 머신

상태 머신은 현재 상태와 입력(이벤트)에 따라 다음 상태가 정해지는 모델입니다. 제너레이터에서는 실행 위치 자체가 상태이므로, 상태 변수와 `switch` 없이 코드 순서로 상태를 표현할 수 있습니다.

입력이 없는 순환 상태는 `yield` 순서가 곧 전이 순서입니다.

```js
function* light() {
  while (true) {
    yield 'green'
    yield 'yellow'
    yield 'red'
  }
}
const l = light()
l.next().value  // 'green'
l.next().value  // 'yellow'
l.next().value  // 'red'
l.next().value  // 'green'
```

입력에 따라 전이하는 경우에는 `next(이벤트)`로 이벤트를 받습니다.

```js
function* door() {
  let state = 'closed'
  while (true) {
    const event = yield state
    if (state === 'closed' && event === 'open') {
      state = 'opened'
    } else if (state === 'opened' && event === 'close') {
      state = 'closed'
    }
  }
}
```

```js
const d = door()
d.next().value         // 'closed'
d.next('open').value   // 'opened'
d.next('open').value   // 'opened' — 정의되지 않은 전이는 무시
d.next('close').value  // 'closed'
```

- `yield state`가 현재 상태를 밖으로 내보내고, `next(event)`가 이벤트를 안으로 넣습니다.
- 정의되지 않은 (상태, 이벤트) 조합은 어느 `if`에도 걸리지 않으므로 상태가 유지됩니다.
- 제너레이터 객체는 복제하거나 되감을 수 없습니다. 상태를 저장하거나 이전 상태로 되돌려야 하면 상태 값을 보관하는 일반 객체나 함수가 낫습니다.
- 상태와 전이가 많으면 전이 표(객체)로 쓰는 편이 읽기 쉽습니다. 제너레이터는 "단계가 순서대로 이어지는 흐름"에 적합합니다.

## 비동기 처리

제너레이터는 `yield`에서 멈추므로 프로미스를 `yield`하고 이행되면 그 값으로 재개하는 실행기를 만들 수 있습니다. 이렇게 하면 비동기 코드를 위에서 아래로 읽히는 동기 코드처럼 쓸 수 있습니다. async/await 이전에 쓰던 방식이며, async/await은 이 구조를 언어 문법으로 흡수한 것입니다(자세히는 43편).

실행기의 핵심은 두 가지입니다. 프로미스가 이행되면 `next(값)`으로 재개하고, 거부되면 `throw(에러)`로 재개합니다.

```js
function run(genFn) {
  const it = genFn()
  const step = (method, arg) => {
    const r = it[method](arg)
    if (r.done) return r.value
    return Promise.resolve(r.value).then(
      (v) => step('next', v),   // 이행 → next(값)
      (e) => step('throw', e),  // 거부 → throw(에러)
    )
  }
  return Promise.resolve().then(() => step('next'))
}
```

```js
run(function* () {
  const a = yield fetchA()  // 프로미스를 yield
  try { yield fetchB() }    // 거부되면 여기서 예외로 재개
  catch (e) { /* 처리 */ }
  return a
}).then((v) => console.log(v))
```

| 제너레이터 방식 | async/await |
|-----------------|-------------|
| `function*` | `async function` |
| `yield 프로미스` | `await 프로미스` |
| 직접 만든 실행기 `run` | 엔진이 내장 |
| 거부 시 `it.throw(e)` | 거부 시 `await` 자리에서 예외 |
| `run`이 프로미스를 반환 | async 함수가 프로미스를 반환 |

- `yield`된 값이 프로미스가 아니면 `Promise.resolve`가 이행된 프로미스로 감싸므로, 일반 값도 마이크로태스크로 곧바로 재개됩니다.
- 실행기가 필요하다는 점이 제너레이터 방식의 약점입니다. 직접 작성하거나 라이브러리를 써야 했고, 에러 처리와 동시 실행 같은 세부를 실행기가 책임졌습니다. 지금은 async/await을 씁니다.
- 비동기 값의 스트림을 `yield`로 내보내는 `async function*`와 `for await...of`는 43편에서 다룹니다.

## 핵심 정리

- 제너레이터 함수(`function*`)는 호출해도 본문이 실행되지 않고 제너레이터 객체를 반환하며, 화살표 함수로는 만들 수 없습니다.
- `next(v)`는 다음 `yield`까지 실행하고 `{ value, done }`을 돌려주며, `v`는 멈춰 있던 `yield`의 결과가 됩니다. 첫 `next`의 인수는 버려집니다.
- `return(v)`와 `throw(e)`는 멈춘 지점에서 종료·예외를 일으키고 `finally`를 실행합니다. `finally` 안의 `yield`는 종료를 미룹니다.
- `yield*`는 이터러블에 위임하며 `next`·`throw`·`return`을 전달하고, 위임 대상의 반환값이 표현식의 값이 됩니다.
- `*[Symbol.iterator]()`로 이터러블을 구현하고, 제너레이터는 필요할 때만 값을 계산하므로 무한 시퀀스와 지연 파이프라인, 상태 머신에 씁니다.
- 프로미스를 `yield`하는 실행기가 async/await의 원형이며, 지금의 비동기 흐름 제어는 async/await을 씁니다.
