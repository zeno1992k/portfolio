## ES6 이전 함수의 문제점

ES5까지는 `function` 하나가 일반 함수, 메서드, 생성자 역할을 모두 맡았습니다. 용도를 구분하는 문법이 없어서 생기던 문제를 ES6가 문법으로 하나씩 해결했습니다.

| 문제 | ES5의 우회 방법 | ES6의 해결 |
|------|-----------------|------------|
| 용도 구분이 없음 | 이름 관례(생성자는 대문자) | 메서드 축약 표현, 화살표 함수, class |
| 콜백의 `this` 손실 | `var self = this`, `bind(this)` | 화살표 함수 |
| 가변 인수 | `arguments`를 배열로 변환 | Rest 파라미터 |
| 기본값 | 단축 평가로 흉내 | 매개변수 기본값 |
| 부모 메서드 호출 | `Base.prototype.m.call(this)` | `super` |
| 장황한 콜백 | `function (x) { return x * 2 }` | `x => x * 2` |

모든 `function`은 호출 동작과 `new` 동작을 함께 가지고 `prototype` 프로퍼티도 가집니다. 메서드나 콜백으로 쓰려고 만든 함수에도 붙으므로, 실수로 `new`를 써도 에러가 나지 않습니다.

```js
var obj = { say: function () { return 'hi' } }
new obj.say() // say {}: 에러 없이 인스턴스가 만들어진다
```

중첩 함수와 콜백은 일반 함수로 호출되어 `this`가 바깥 메서드의 `this`와 달라집니다. 그래서 바깥 `this`를 변수에 보관했습니다.

```js
var counter = {
  sum: 0,
  items: [1, 2, 3],
  run: function () {
    var self = this // this를 변수에 보관
    this.items.forEach(function (n) { self.sum += n })
    return this.sum
  },
}
counter.run() // 6
```

가변 인수는 유사 배열인 `arguments`를 배열로 바꿔서 처리했습니다.

```js
function sum() {
  var args = Array.prototype.slice.call(arguments)
  return args.reduce(function (a, b) { return a + b }, 0)
}
sum(1, 2, 3) // 6
```

기본값은 단축 평가로 흉내 냈고, 이 방식은 거짓 값(falsy)을 모두 기본값으로 바꾸는 버그를 낳았습니다(자세히는 08편).

```js
function f(x) { x = x || 10; return x }
f(0) // 10: 0을 넘겼는데 기본값이 쓰인다
```

부모 객체의 같은 이름 메서드를 부르는 문법도 없었습니다. `Base.prototype.hi.call(this)`처럼 부모 이름과 `call`을 직접 적어야 했습니다.

## 일반 함수·메서드·화살표 함수 구분

ES6부터 함수는 만든 문법에 따라 일반 함수, 메서드, 화살표 함수로 나뉘고 종류마다 가진 능력이 다릅니다. 셋 다 `typeof`는 `'function'`이라 겉으로는 구별되지 않고, 차이는 함수 객체가 가진 내부 슬롯과 내부 메서드에 있습니다.

| 항목 | 일반 함수 | 메서드 | 화살표 함수 |
|------|-----------|--------|-------------|
| 만드는 문법 | 함수 선언문·표현식 | 메서드 축약 표현, getter·setter | `=>` |
| `new` 호출 | O | X (TypeError) | X (TypeError) |
| `prototype` 프로퍼티 | O | X | X |
| `super` 참조 | X (SyntaxError) | O | 바깥 메서드의 것 |
| 자체 `arguments` | O | O | X (바깥 함수의 것) |
| `this` | 호출 방식이 결정 | 호출 방식이 결정 | 바깥 스코프의 `this` |

- **일반 함수:** `function f() {}`, `const f = function () {}`, 그리고 `{ f: function () {} }`처럼 프로퍼티 값으로 쓴 함수 표현식입니다.
- **메서드:** 객체 리터럴의 `m() {}`, getter·setter, 클래스의 인스턴스 메서드와 `static` 메서드입니다. `async m() {}`와 `*m() {}`도 메서드 축약 표현이라서 `new` 불가와 `super` 사용 가능은 같습니다. 제너레이터 메서드만 예외적으로 `prototype` 프로퍼티를 가집니다(자세히는 42편).
- **화살표 함수:** `=>`로 만든 함수입니다.
- 프로퍼티에 담긴 함수를 모두 메서드라고 부르는 넓은 용법도 흔하지만, 이 문서에서 메서드는 축약 표현으로 만든 함수만 가리킵니다.
- 클래스, async 함수, 제너레이터 함수는 이 세 구분 밖의 종류이고 `new` 가능 여부는 15편의 표에 있습니다.

```js
const o = {
  a: function () {}, // 일반 함수
  b() {},            // 메서드
  c: () => {},       // 화살표 함수
}
new o.a()                       // 가능
new o.b()                       // TypeError
new o.c()                       // TypeError
Object.hasOwn(o.a, 'prototype') // true
Object.hasOwn(o.b, 'prototype') // false
```

## ES6 메서드와 `[[HomeObject]]`

`[[HomeObject]]`는 메서드가 가지는 내부 슬롯으로, 그 메서드를 정의한 객체(홈 객체)를 가리킵니다. `super.x`는 홈 객체의 `[[Prototype]]`에서 `x`를 찾습니다. 코드에서 직접 읽거나 바꿀 수 없고, 일반 함수와 화살표 함수에는 이 슬롯이 없습니다.

```js
const base = { hi() { return 'base' } }
const obj = {
  __proto__: base,
  hi() { return super.hi() + '+obj' },
}
obj.hi() // 'base+obj'
```

`super.x`는 아래 호출과 같은 동작입니다(자세히는 47편).

```js
Reflect.get(Object.getPrototypeOf(homeObject), 'x', this)
```

메서드가 어디에 정의됐느냐에 따라 홈 객체가 달라집니다.

| 메서드의 위치 | 홈 객체 | `super`가 보는 곳 |
|---------------|---------|-------------------|
| 객체 리터럴 | 그 객체 | 그 객체의 `[[Prototype]]` |
| 클래스의 인스턴스 메서드 | `Class.prototype` | 부모 클래스의 `prototype` |
| 클래스의 `static` 메서드 | 클래스 자신 | 부모 클래스 |

getter·setter, async 메서드, 제너레이터 메서드, 클래스의 `constructor`도 홈 객체를 가지므로 `super.x`를 쓸 수 있습니다.

규칙은 다음과 같습니다.

- 홈 객체는 정의되는 순간 고정됩니다. 메서드를 다른 객체에 복사해도 홈 객체는 바뀌지 않습니다. `this`는 호출할 때 정해지는 것과 대조됩니다.
- 홈 객체가 정해져 있어도 `super`의 조회는 호출할 때 일어납니다. 홈 객체의 `[[Prototype]]`을 나중에 바꾸면 바뀐 프로토타입을 봅니다.
- `super`로 찾은 메서드는 현재 `this`로 실행됩니다. 프로토타입 객체가 `this`가 되지 않습니다.
- `super.x = v`는 프로토타입이 아니라 현재 `this`에 씁니다. 프로토타입에 setter가 있으면 `this`를 대상으로 그 setter가 호출됩니다.
- `super.x`는 메서드 안에서만 쓸 수 있습니다. 일반 함수 표현식(`{ f: function () { super.x } }`)이나 메서드 밖의 화살표 함수는 SyntaxError입니다.
- 부모 생성자를 부르는 `super()`는 파생 클래스의 `constructor`에서만 쓸 수 있습니다. 객체 리터럴 메서드에서는 SyntaxError입니다(자세히는 25편).

```js
const src = {
  __proto__: base,
  hi() { return super.hi() + '!' },
}
const copy = Object.assign({}, src)
copy.hi() // 'base!': copy가 아니라 src의 프로토타입을 본다
```

**흔한 실수:** `super`를 쓰는 메서드를 `Object.assign` 같은 믹스인으로 다른 객체에 복사하고, 복사받은 객체의 프로토타입을 기준으로 동작할 것이라고 기대하는 경우입니다. 홈 객체가 고정이라 원래 객체의 프로토타입을 계속 봅니다.

## 화살표 함수 문법

화살표 함수는 `(매개변수) => 몸체` 형태로 쓰는 함수 표현식입니다. 매개변수 괄호는 단순한 이름 하나일 때만 생략할 수 있습니다.

```js
const a = () => 1                  // 매개변수 없음: 괄호 필수
const b = x => x * 2               // 단순 이름 하나: 생략 가능
const c = (x, y) => x + y          // 둘 이상: 괄호 필수
const d = (x = 1) => x             // 기본값: 괄호 필수
const e = (...xs) => xs            // Rest: 괄호 필수
const f = ({ id }, [first]) => id  // 구조 분해: 괄호 필수
```

몸체는 두 가지입니다.

```js
const sq1 = (x) => x * x          // 표현식 몸체: 값이 반환값
const sq2 = (x) => { x * x }      // 블록 몸체: return이 없다
const sq3 = (x) => { return x * x }
sq1(3) // 9
sq2(3) // undefined
sq3(3) // 9
```

- 표현식 몸체는 대입 표현식 하나입니다. 삼항 연산자, 대입, 다른 화살표 함수를 쓸 수 있습니다. `a => b => a + b`처럼 화살표 함수를 이어 쓰면 커링(인수를 하나씩 받는 함수 연쇄)이 됩니다.
- 표현식 몸체에서 쉼표 연산자를 쓰려면 괄호로 묶습니다: `x => (console.log(x), x * 2)`.
- `{`로 시작하는 몸체는 항상 블록입니다(다음 절). 블록 몸체에서 `return`을 빠뜨리면 `undefined`가 반환되고, `map`의 콜백에서 이 실수를 하면 `[undefined, ...]`가 됩니다.
- `=>` 앞에서 줄을 바꾸면 SyntaxError이고, 뒤에서는 바꿀 수 있습니다.
- 항상 표현식이고 선언문 형태가 없습니다. 변수에 담아야 이름이 추론됩니다(자세히는 11편).
- 호이스팅되지 않습니다. `const`에 담았다면 선언 전 호출은 ReferenceError, `var`면 TypeError입니다.
- 즉시 실행하려면 함수 전체를 괄호로 감쌉니다. `() => {}()`는 SyntaxError입니다.
- 다른 연산자의 피연산자로 쓰면 SyntaxError이므로 괄호가 필요합니다. 삼항 연산자의 두 분기에는 괄호가 필요 없습니다.
- `async x => x`, `async (x) => x`처럼 앞에 `async`를 붙일 수 있습니다(자세히는 43편). 제너레이터 화살표 함수는 없습니다.

```js
(() => 1)()                  // 1: 즉시 실행
const g = cb || (() => 1)    // ✅ 괄호로 감싼다
const h = cb || () => 1      // ❌ SyntaxError
const k = ok ? () => 1 : () => 2 // ✅ 삼항은 괄호 불필요
```

## 객체 리터럴 반환 시 괄호

화살표 함수의 몸체가 `{`로 시작하면 객체 리터럴이 아니라 블록으로 해석됩니다. 객체를 바로 반환하려면 객체 리터럴 전체를 괄호로 감싸 표현식으로 만듭니다.

| 코드 | 해석 | 결과 |
|------|------|------|
| `() => { a: 1 }` | 블록 안의 레이블 `a`와 식 `1` | `undefined` |
| `() => { a: 1, b: 2 }` | 블록 안의 문법 오류 | SyntaxError |
| `() => { a }` | 블록 안의 식 `a` | `undefined`(`a`가 없으면 호출 시 ReferenceError) |
| `() => ({ a: 1 })` | 괄호로 묶은 객체 리터럴 | `{ a: 1 }` |
| `() => { return { a: 1 } }` | 블록과 `return` | `{ a: 1 }` |

```js
const ids = [1, 2]
ids.map(n => { id: n })   // [undefined, undefined]
ids.map(n => ({ id: n })) // [{ id: 1 }, { id: 2 }]
```

- 표현식 몸체는 `{`로 시작할 수 없다는 것이 문법 규칙이라서, `=>` 뒤의 `{`는 항상 블록 몸체의 시작으로 해석됩니다. 괄호는 객체 리터럴의 일부가 아니라 그룹화 연산자이고, 괄호 안은 표현식 위치이므로 `{`가 객체 리터럴이 됩니다.
- `{ a: 1 }`이 에러 없이 `undefined`가 되는 이유는 `a:`가 레이블 문(자세히는 07편)으로 유효하기 때문입니다. 에러가 나지 않아 찾기 어려운 형태입니다.
- 삼항 연산자나 논리 연산자의 피연산자는 이미 표현식 위치이므로 괄호가 필요 없습니다: `x => x ? { a: 1 } : {}`.
- 스프레드를 쓰는 갱신 함수도 같은 규칙입니다: `state => ({ ...state, n: 1 })`.
- 빈 객체를 반환하는 `() => ({})`와 아무것도 하지 않는 `() => {}`는 다릅니다.
- 일반 함수의 몸체는 항상 블록이므로 `return { a: 1 }`을 그대로 쓸 수 있습니다.

## 일반 함수와의 차이

화살표 함수는 `this`, `arguments`, `super`, `new.target`을 자체적으로 가지지 않고 바깥 스코프에서 찾습니다. 또 `[[Construct]]`가 없어서 생성자가 될 수 없습니다. 아래 차이는 대부분 이 두 사실에서 나옵니다.

| 항목 | 일반 함수 | 화살표 함수 |
|------|-----------|-------------|
| `this` | 호출 방식이 결정 | 바깥 스코프의 `this`, `call`·`apply`·`bind`로 변경 불가 |
| `arguments` | 자체 객체 | 없음. 바깥 함수의 것을 참조 |
| `super` | 사용 불가 | 바깥 메서드의 것을 참조 |
| `new.target` | 호출 방식에 따라 `undefined` 또는 생성자 | 바깥 함수의 것을 참조 |
| `new` 호출 | 가능 | TypeError |
| `prototype` 프로퍼티 | 있음 | 없음 |
| 중복 매개변수 이름 | 비엄격 모드에서 허용 | 항상 SyntaxError |
| `yield` | 제너레이터 함수에서 사용 | 사용 불가 |
| 형태 | 선언문과 표현식 | 표현식만 |

```js
const Arrow = () => {}
new Arrow()     // TypeError: Arrow is not a constructor
Arrow.prototype // undefined
```

- 중복 매개변수 이름은 `function (a, a) {}`가 비엄격 모드에서 허용되고(마지막 인수가 값이 됩니다), `(a, a) => 1`은 비엄격 모드에서도 SyntaxError입니다.
- 같은 점도 많습니다. `typeof`가 `'function'`이고, `length`와 `name` 프로퍼티가 있으며, `call`·`apply`·`bind` 메서드를 쓸 수 있고, 클로저를 만들고, 기본값·Rest·구조 분해 매개변수를 쓸 수 있습니다.
- 화살표 함수 몸체에서 `yield 1`을 쓰면 SyntaxError입니다. 제너레이터 안에 화살표 함수를 중첩해도 바깥 제너레이터를 대신해 `yield`할 수 없습니다(자세히는 42편).

## 화살표 함수의 this

화살표 함수에는 `this` 바인딩이 없습니다. 몸체에서 `this`를 만나면 일반 변수처럼 스코프 체인을 따라 올라가 가장 가까운 바깥 함수(일반 함수 또는 메서드)의 `this`를 사용하고, 바깥 함수가 없으면 최상위의 `this`를 사용합니다. 이를 렉시컬 `this`라고 합니다. `this`는 호출 방식과 무관하게 화살표 함수가 만들어진 위치가 결정합니다(일반 함수의 `this`는 21편).

```js
const team = {
  name: 'A',
  list: ['x', 'y'],
  bad() {
    return this.list.map(function () { return this.name })
  },
  good() {
    return this.list.map(() => this.name)
  },
}
team.bad()  // TypeError (strict mode)
team.good() // ['A', 'A']
```

`bad`의 콜백은 일반 함수로 호출되어 `this`가 `undefined`(strict mode)나 전역 객체(비엄격 모드)가 됩니다. 비엄격 모드에서는 에러 없이 전역 객체의 `name`을 읽어서 엉뚱한 값이 나옵니다.

바깥 함수를 호출할 때마다 `this`가 달라질 수 있으므로, 화살표 함수의 `this`도 그 호출에서 만들어진 것을 따라갑니다.

```js
const o = {
  n: 'o',
  make() { return () => this.n },
}
o.make()()            // 'o'
const p = { n: 'p', make: o.make }
p.make()()            // 'p': make가 p로 호출되어 this가 p
```

규칙과 예외는 다음과 같습니다.

- `call`·`apply`·`bind`로 `this`를 바꿀 수 없습니다. 첫 인수는 에러 없이 무시되고 나머지 인수는 정상 전달됩니다.

```js
const add = (a, b) => a + b
add.call({}, 1, 2)   // 3: 첫 인수 {}는 무시, 나머지는 전달
add.bind(null, 1)(2) // 3
```

- 객체 리터럴은 스코프를 만들지 않습니다. 리터럴의 프로퍼티 값으로 쓴 화살표 함수의 `this`는 리터럴 바깥의 `this`입니다.
- 바깥에 함수가 없을 때의 최상위 `this`는 실행 환경에 따라 다릅니다.

| 실행 위치 | 최상위 `this` |
|-----------|---------------|
| ES 모듈 | `undefined` |
| 브라우저의 일반 스크립트 | `window`(전역 객체) |
| Node.js CommonJS | `module.exports` |

- 생성자 안에서 만든 화살표 함수는 그 인스턴스를 `this`로 가집니다. 클래스 필드에 화살표 함수를 대입해도 같습니다(아래 주의점 절, 자세히는 24편).
- 브라우저 이벤트 리스너를 일반 함수로 쓰면 `this`는 이벤트를 받은 요소입니다. 화살표 함수는 바깥 `this`를 쓰므로 요소가 필요하면 `event.currentTarget`을 사용합니다.

바깥 `this`를 콜백에서 쓰는 방법은 다음과 같습니다.

| 방법 | 형태 | 비고 |
|------|------|------|
| 화살표 함수 | `(m) => this.name + m` | 현재의 표준 방식 |
| `bind` | `function (m) { ... }.bind(this)` | ES5 방식 |
| 변수에 보관 | `var self = this` | ES5 방식 |
| `thisArg` 인수 | `list.map(fn, this)` | `map`·`forEach` 등 일부 메서드만 지원 |

## super·arguments

화살표 함수는 자체 `super`, `arguments`, `new.target`을 가지지 않고, `this`와 똑같이 바깥 함수의 것을 렉시컬하게 참조합니다.

```js
function outer() {
  const inner = () => arguments[0]
  return inner('b')
}
outer('a') // 'a': inner에 넘긴 'b'가 아니라 outer의 arguments
```

- 화살표 함수에 넘긴 인수는 `arguments`로 읽을 수 없습니다. 화살표 함수의 인수는 매개변수나 Rest 파라미터로 받습니다.
- 바깥 함수가 없는 최상위에서 `arguments`를 쓰면 ES 모듈과 브라우저에서는 ReferenceError입니다. Node.js의 CommonJS 파일에서는 모듈을 감싼 함수의 `arguments`(인수 5개: `exports`, `require`, `module`, `__filename`, `__dirname`)가 잡혀서 에러 없이 엉뚱한 값을 읽습니다.

`super`는 메서드 안에서 만든 화살표 함수에서 쓸 수 있습니다. 화살표 함수 자체는 홈 객체가 없고, 바깥 메서드의 홈 객체를 사용합니다.

```js
const child = {
  __proto__: { hi() { return 'parent' } },
  hi() {
    const f = () => super.hi()
    return f() + '>child'
  },
}
child.hi() // 'parent>child'
```

- 메서드 밖에서 만든 화살표 함수의 `super.x`는 SyntaxError입니다.
- 파생 클래스의 `constructor` 안에 있는 화살표 함수에서도 `super()`를 호출할 수 있습니다(자세히는 25편).
- `new.target`도 같은 방식으로 바깥 함수의 값을 참조합니다(자세히는 15편).

## 사용 시 주의점

화살표 함수는 일반 함수의 대체품이 아니라 자체 `this`가 필요 없는 함수를 위한 문법입니다. 아래 경우는 일반 함수나 메서드를 써야 합니다.

### 객체 메서드로 쓰지 않는다

```js
const user = {
  name: 'Kim',
  bad: () => this.name,         // ❌ this는 user가 아니다
  good() { return this.name },  // ✅
}
user.good() // 'Kim'
```

### 프로토타입 메서드와 생성자로 쓰지 않는다

```js
function Person(name) { this.name = name }
Person.prototype.hi = () => this.name // ❌ 바깥 this
const P = (name) => { this.name = name }
new P('Kim')                          // ❌ TypeError
```

### 호출하는 쪽이 this를 정하는 콜백

이벤트 리스너처럼 호출하는 쪽이 `this`를 정해 주는 API에서 그 `this`가 필요하면 일반 함수를 씁니다. 화살표 함수를 쓴다면 `event.currentTarget`으로 요소를 얻습니다.

### arguments가 필요한 함수

화살표 함수의 `arguments`는 바깥 함수의 것이므로 인수 목록 전체가 필요하면 Rest 파라미터를 씁니다.

### 클래스 필드의 화살표 함수

```js
class Counter {
  count = 0
  inc = () => { this.count++ }
}
const { inc } = new Counter()
inc() // 에러 없음: this가 인스턴스에 고정되어 있다
```

메서드를 분리해서 넘겨도 `this`가 유지되는 대신 비용이 있습니다.

- 인스턴스마다 새 함수 객체가 생깁니다. 프로토타입 메서드처럼 공유되지 않습니다.
- 필드는 인스턴스의 own 프로퍼티라서 프로토타입에 없습니다. 자식 클래스에서 `super.inc()`로 부를 수 없고 TypeError가 납니다(자세히는 24편).

### 이름이 필요한 경우

콜백 자리에 바로 쓴 화살표 함수는 `name`이 빈 문자열입니다. 변수에 대입해야 이름이 추론됩니다(자세히는 11편). 함수 이름으로 구별하는 코드나 도구에서는 구별되지 않습니다.

### 선택 기준

| 상황 | 쓸 함수 |
|------|---------|
| 콜백, 고차 함수 인수, 중첩 함수에서 바깥 `this` 유지 | 화살표 함수 |
| 객체와 클래스의 메서드 | 메서드 축약 표현 |
| 생성자, 제너레이터, `this`를 호출하는 쪽이 정하는 함수 | `function` |
| 선언 앞에서 호출해야 하는 함수 | 함수 선언문 |

## Rest 파라미터

Rest 파라미터는 매개변수 목록 마지막에 `...이름`으로 써서 남은 인수를 진짜 배열로 받는 문법입니다(ES2015).

```js
function sum(...nums) {
  return nums.reduce((a, b) => a + b, 0)
}
sum(1, 2, 3) // 6
sum()        // 0

const f = (first, ...rest) => rest
f(1, 2, 3) // [2, 3]
f(1)       // []: 남은 인수가 없으면 빈 배열
```

규칙은 다음과 같습니다.

- 매개변수 목록의 맨 마지막에 하나만 쓸 수 있습니다. 뒤에 매개변수나 후행 쉼표가 오면 SyntaxError입니다.
- 기본값을 지정할 수 없습니다. `...a = []`는 SyntaxError입니다.
- 남은 인수가 없으면 `undefined`가 아니라 빈 배열입니다.
- 일반 함수, 메서드, 화살표 함수 모두에서 쓸 수 있습니다. setter는 매개변수가 정확히 하나여야 하므로 Rest 파라미터를 쓸 수 없습니다.
- 이름 대신 구조 분해 패턴을 쓸 수 있습니다: `(...[a, ...others]) => a`(자세히는 37편).
- 함수의 `length`에 포함되지 않습니다.
- 몸체의 `'use strict'` 지시문은 SyntaxError가 됩니다(자세한 이유는 기본값 절).
- 매개변수 정의에서의 `...`는 인수를 모으고, 호출식과 배열 리터럴에서의 `...`(스프레드)는 펼칩니다. 모양은 같지만 반대 방향입니다(자세히는 36편).

```js
function pack(...args) { return args }
pack([1, 2])    // [[1, 2]]: 배열이 첫 인수 하나로 들어간다
pack(...[1, 2]) // [1, 2]: 스프레드로 펼쳐서 넘긴다
```

## arguments와 비교

`arguments`는 일반 함수와 메서드 안에서 쓸 수 있는 유사 배열 객체이고, 호출할 때 전달된 인수 전체를 담습니다. 길이와 인덱스가 있지만 `forEach`나 `map` 같은 배열 메서드는 없습니다.

| 항목 | `arguments` | Rest 파라미터 |
|------|-------------|---------------|
| 정체 | 유사 배열 객체 | 배열 |
| 배열 메서드 | 없음 | 있음 |
| 담기는 인수 | 전달된 인수 전체 | 이름 붙은 매개변수 뒤의 나머지 |
| 화살표 함수 | 자체 객체 없음 | 사용 가능 |
| 선언 | 암묵적 | 매개변수 목록에 명시 |
| 매개변수와 연동 | 비엄격 모드의 단순 매개변수에서만 | 연동 없음 |

```js
function show() {
  return [Array.isArray(arguments), typeof arguments.map]
}
show(1, 2) // [false, 'undefined']

function copy() { return [...arguments] }
copy(1, 2) // [1, 2]
```

`arguments`는 이터러블이라서 스프레드와 `Array.from`으로 배열로 바꿀 수 있습니다(자세히는 35편).

- `arguments.length`는 실제로 전달된 인수 개수이고, 함수의 `length`는 선언된 매개변수 개수입니다. 인수를 안 넘긴 것과 `undefined`를 넘긴 것은 `arguments.length`로 구별됩니다.

```js
function count(a) { return arguments.length }
count()          // 0
count(undefined) // 1
count(1, 2, 3)   // 3: 선언된 매개변수보다 많아도 센다
```

- 비엄격 모드이고 매개변수가 단순하면(기본값·Rest·구조 분해가 없으면) `arguments[i]`와 i번째 매개변수가 서로 연동됩니다. strict mode이거나 단순하지 않은 매개변수 목록이면 연동되지 않습니다. 인수를 넘기지 않은 매개변수는 비엄격 모드에서도 연동되지 않습니다.

```js
function f(a) { arguments[0] = 9; return a }
f(1) // 9: 비엄격 모드 (strict mode에서는 1)
```

- `arguments.callee`는 현재 실행 중인 함수를 가리키지만 strict mode에서 접근하면 TypeError입니다. 쓰지 않습니다(자세히는 16편).

`arguments` 사용 코드는 아래처럼 바꿉니다.

| 이전 | 이후 |
|------|------|
| `Array.prototype.slice.call(arguments)` | `function f(...args)`의 `args` |
| `fn.apply(this, arguments)` | `function f(...args)`에서 `fn.apply(this, args)` |
| `arguments[0]` | 첫 번째 매개변수의 이름 |

새 코드에서는 Rest 파라미터를 씁니다. `arguments`는 화살표 함수에서 쓸 수 없고 배열도 아니기 때문입니다.

## 매개변수 기본값

매개변수 기본값은 인수가 없거나 `undefined`일 때 쓰는 값을 매개변수에 지정하는 문법입니다(ES2015). 기본 동작과 `null`·`0`·`''`을 넘겼을 때의 차이, 단축 평가 방식과의 비교는 11편에서 다뤘습니다. 이 절은 평가 시점, 스코프, `length`와의 관계를 다룹니다.

### 기본값의 평가 시점

기본값 식은 함수를 호출할 때마다, 해당 인수가 `undefined`인 경우에만, 매개변수 목록의 왼쪽부터 오른쪽 순서로 평가됩니다. 몸체는 기본값이 모두 평가된 뒤에 실행됩니다.

```js
let n = 0
const next = () => ++n
function f(a = next()) { return a }
f()   // 1
f()   // 2: 호출마다 평가된다
f(10) // 10: 인수가 있으면 평가되지 않는다 (n은 그대로 2)
```

- 정의할 때가 아니라 호출할 때 평가되므로 바깥 변수는 호출 시점의 값을 읽습니다.

```js
let base = 1
function g(x = base) { return x }
g()      // 1
base = 2
g()      // 2
```

- 호출마다 평가되어 `[]`나 `{}` 기본값이 호출 사이에 공유되지 않습니다. 정의 시점에 한 번만 평가하는 언어와 다른 점입니다.
- 매개변수는 왼쪽부터 차례로 초기화됩니다. 자기 자신이나 오른쪽 매개변수를 기본값에서 읽으면 TDZ(자세히는 13편) 때문에 ReferenceError입니다. 해당 인수를 넘기면 기본값이 평가되지 않으므로 에러가 나지 않습니다.

```js
function h(a = b, b = 1) { return a }
h()  // ReferenceError: Cannot access 'b' ...
h(5) // 5
```

- 기본값 식 안에서 `this`와 `arguments`를 쓸 수 있습니다. 기본값이 있어도 `arguments.length`는 전달된 인수 개수 그대로입니다.
- 기본값 식에는 `yield`와 `await`를 쓸 수 없습니다.
- 객체 매개변수를 구조 분해할 때는 바깥 기본값 `= {}`가 없으면 인수를 생략했을 때 TypeError입니다(자세히는 37편).

```js
function p({ a = 1, b = 2 } = {}) { return [a, b] }
p()         // [1, 2]
p({ a: 9 }) // [9, 2]
// 바깥 = {}가 없으면 p()는 TypeError
```

### 기본값과 스코프

기본값 식이 하나라도 있으면(구조 분해 안의 기본값 포함) 매개변수용 스코프와 몸체 스코프가 분리됩니다. 기본값 식과 그 안에서 만든 함수는 몸체의 `var`, 함수 선언, `let`, `const`를 볼 수 없습니다.

```js
function f(a = () => typeof inner) {
  function inner() {}
  return a()
}
f() // 'undefined': 몸체의 함수 선언이 보이지 않는다
```

몸체에서 같은 이름을 `var`로 다시 선언하면 매개변수와 별개의 변수가 만들어지고, 그 초기값은 같은 이름의 매개변수 값입니다.

```js
function g(a, read = () => a) {
  var a = 2          // 몸체의 새 변수. 초기값은 매개변수 a의 값 1
  return [a, read()]
}
g(1) // [2, 1]: read는 매개변수 a를 본다
```

`var` 없이 `a = 2`로 쓰면 매개변수 자체를 바꾸므로 `read()`도 `2`를 반환합니다. 기본값 식이 없으면 매개변수와 몸체의 `var`는 같은 변수입니다(자세히는 12편).

- 몸체의 `let`·`const`·`class`가 같은 이름의 매개변수를 다시 선언하면 SyntaxError입니다. `var`만 허용됩니다.
- 기본값, Rest, 구조 분해가 있는 단순하지 않은 매개변수 목록에는 다음 제약이 붙습니다.
  - 몸체의 `'use strict'` 지시문이 SyntaxError입니다. 파일이나 바깥 함수 단위로 strict mode를 켭니다(자세히는 19편).
  - 중복된 매개변수 이름이 비엄격 모드에서도 SyntaxError입니다.
  - `arguments`가 매개변수와 연동되지 않습니다.

### 함수 length와 기본값·Rest

`length`는 함수가 기대하는 인수 개수이고, 첫 번째 기본값 매개변수와 Rest 파라미터 앞에서 멈춰 센 값입니다. 호출할 때 넘긴 인수 개수와는 무관합니다.

| 함수 | `length` | 이유 |
|------|----------|------|
| `(a, b) => {}` | 2 | 모두 센다 |
| `(a, b = 1, c) => {}` | 1 | 첫 기본값 앞까지만 센다. 뒤의 `c`는 기본값이 없어도 제외 |
| `(a, ...r) => {}` | 1 | Rest는 제외 |
| `(a = 1, b) => {}` | 0 | 첫 매개변수부터 기본값 |
| `({ a }, [b]) => {}` | 2 | 구조 분해 매개변수는 각각 하나로 센다 |
| `({ a } = {}, [b]) => {}` | 0 | 첫 매개변수에 기본값 |

- `length`는 쓰기 불가, 열거 불가, 설정 가능한 프로퍼티입니다(자세히는 14편).
- 인수를 `bind`로 미리 묶으면 묶은 만큼 줄어듭니다. `((a, b, c) => {}).bind(null, 1).length`는 `2`입니다.
- 인수 개수로 동작을 나누는 코드(커링 유틸 등)는 기본값이나 Rest가 있는 함수에서 기대와 다르게 동작합니다.
- 기본값 매개변수를 맨 뒤에 두면 `length`가 필수 인수 개수와 일치하고, 앞쪽 인수를 건너뛰려고 `undefined`를 넘길 일도 없습니다.

## 핵심 정리

- ES6는 함수를 일반 함수, 메서드, 화살표 함수로 나눴습니다. `new`와 `prototype`은 일반 함수만, `super`는 `[[HomeObject]]`를 가진 메서드만 쓸 수 있습니다.
- `[[HomeObject]]`는 정의할 때 고정되고, `super.x`는 그 객체의 현재 `[[Prototype]]`에서 호출 시점에 찾습니다. `this`는 호출할 때 정해집니다.
- 화살표 함수는 `this`, `arguments`, `super`, `new.target`을 바깥 스코프에서 렉시컬하게 가져오고, `call`·`apply`·`bind`로 `this`를 바꿀 수 없습니다. 객체 메서드, 프로토타입 메서드, 생성자에는 쓰지 않습니다.
- 화살표 함수 몸체의 `{`는 블록이므로 객체 리터럴은 `() => ({ ... })`로 감쌉니다.
- Rest 파라미터는 마지막 하나만 가능한 진짜 배열이고, `arguments`는 화살표 함수에 없는 유사 배열입니다.
- 기본값은 호출마다 평가되고, 기본값 식이 있으면 매개변수 스코프가 몸체와 분리됩니다. `length`는 첫 기본값 매개변수와 Rest 앞까지만 셉니다.
