## 선언형과 명령형

**명령형**(imperative) 코드는 결과를 얻는 절차를 한 단계씩 적고, **선언형**(declarative) 코드는 원하는 결과를 적고 절차는 함수에 맡깁니다.

```js
const nums = [1, 2, 3, 4, 5]

// 명령형: 반복, 조건, 누적을 직접 쓴다
const a = []
for (let i = 0; i < nums.length; i++) {
  if (nums[i] % 2 === 0) a.push(nums[i] * 10)
}

// 선언형: 무엇을 원하는지만 쓴다
const b = nums.filter(n => n % 2 === 0).map(n => n * 10)
// a, b 모두 [20, 40]
```

| 구분 | 명령형 | 선언형 |
|------|--------|--------|
| 코드가 말하는 것 | 어떻게 | 무엇을 |
| 상태 | 변수를 바꿔 가며 진행 | 값을 변환해 새 값을 만든다 |
| 반복 | `for`, `while` | `map`, `filter`, `reduce` |
| 흔한 위험 | 인덱스 오류, 누적 변수 오염 | 콜백 인수·반환값 오해 |

**함수형 프로그래밍**은 선언형 스타일의 하나로, 프로그램을 함수의 조합과 값의 변환으로 구성합니다. 핵심 규칙은 다음과 같습니다.

- 함수는 같은 입력에 같은 출력을 내고 바깥을 바꾸지 않는다(순수 함수).
- 데이터는 바꾸지 않고 새로 만든다(불변성).
- 함수는 값이므로 인수로 받고 반환한다(고차 함수).
- 작은 함수를 이어 붙여 큰 동작을 만든다(합성).

JavaScript는 함수형 전용 언어가 아닙니다. 함수를 값으로 다루는 일급 함수(자세히는 16편)와 클로저(자세히는 23편) 덕분에 함수형 기법을 선택해서 쓸 수 있을 뿐입니다. 명령형 코드가 더 읽기 쉬운 곳(복잡한 조기 종료, 성능이 중요한 반복)에서는 `for`를 써도 됩니다.

## 순수 함수

**순수 함수**(pure function)는 같은 인수에 항상 같은 값을 반환하고, 반환값을 만드는 것 외에 바깥에 영향을 주지 않는 함수입니다. 바깥에 영향을 주는 동작을 **부수 효과**(side effect)라고 합니다.

```js
const add = (a, b) => a + b // 순수: 인수만 사용, 바깥 변경 없음

let total = 0
const addToTotal = n => (total += n) // 불순: 외부 변수 변경
addToTotal(1) // 1
addToTotal(1) // 2 — 같은 입력, 다른 출력
```

| 순수성을 깨는 것 | 예 |
|------------------|----|
| 외부 변수 변경 | `total += n` |
| 인수로 받은 객체·배열 변경 | `cart.push(item)` |
| 입출력 | `console.log`, DOM 변경, 네트워크 요청, 저장소 쓰기 |
| 실행할 때마다 달라지는 값 읽기 | `Math.random()`, `Date.now()`, `new Date()` |
| 바뀔 수 있는 외부 값 읽기 | 나중에 재할당될 수 있는 변수 |

- 값이 바뀌지 않는 외부 상수(`const TAX = 0.1`)를 읽는 것은 결과를 흔들지 않으므로 순수로 취급합니다.
- 함수 안에서 만든 지역 배열에 `push`하는 것은 바깥에서 보이지 않으므로 순수성을 해치지 않습니다.
- `Math.max`, `String.prototype.toUpperCase`처럼 새 값을 반환하기만 하는 내장 함수는 순수합니다. `map`·`filter`는 콜백이 순수할 때만 순수합니다.

**참조 투명성**(referential transparency)은 호출 식을 그 결과 값으로 바꿔도 프로그램 동작이 같다는 성질입니다. 순수 함수는 이 성질을 가집니다.

```js
add(2, 3) // 5 로 바꿔 써도 프로그램은 같다
addToTotal(2) // 값만 대신 쓸 수 없다 — total이 바뀌는 효과가 사라진다
```

순수 함수의 이점은 다음과 같습니다.

- 입력만 정하면 결과가 정해지므로 테스트에 준비·정리 코드가 필요 없다.
- 호출 순서와 횟수가 결과에 영향을 주지 않는다.
- 결과를 저장해 재사용할 수 있다(메모이제이션, 아래 절).

흔한 실수는 인수를 직접 바꾸는 것입니다.

```js
const addItem = (cart, item) => {
  cart.push(item) // ❌ 호출한 쪽의 cart가 바뀐다
  return cart
}
const addItem2 = (cart, item) => [...cart, item] // ✅ 새 배열
```

`sort`, `reverse`, `splice`는 원본 배열을 바꿉니다. 인수에 대고 호출하면 불순해집니다. 대체 방법은 아래 불변 업데이트 절에 있습니다.

"반환값이 있으면 순수하다"는 오해도 흔합니다. 반환값이 있어도 `console.log`를 호출하거나 인수를 바꾸면 불순합니다.

## 부수 효과 격리

**부수 효과 격리**는 프로그램에서 부수 효과가 필요한 부분을 가장자리의 얇은 층으로 모으고, 나머지를 순수 함수로 두는 설계입니다. 입출력이 없는 프로그램은 쓸모가 없으므로 효과를 없애는 것이 아니라 위치를 정하는 것입니다.

```js
// 순수 핵심: 데이터를 받아 데이터를 반환
const makeReport = items =>
  items.map(i => `${i.name}: ${i.qty}`).join('\n')

// 명령형 껍질: 입출력은 여기서만
const items = [{ name: 'pen', qty: 3 }]
console.log(makeReport(items)) // pen: 3
```

실행할 때마다 달라지는 값은 인수로 받아 순수하게 만듭니다.

```js
// ❌ 시간과 난수를 함수 안에서 읽는다
const makeTokenBad = () => `${Date.now()}-${Math.random()}`

// ✅ 바깥에서 주입한다
const makeToken = (now, rand) =>
  `${now}-${Math.floor(rand * 1000)}`
makeToken(1700000000000, 0.5) // '1700000000000-500'
makeToken(Date.now(), Math.random()) // 경계에서 실제 값 주입
```

효과 자체를 값으로 만들어 실행을 미루는 방법도 있습니다. 함수는 "할 일"을 반환하고, 호출하는 쪽이 실행 시점을 정합니다.

```js
const logEffect = msg => () => console.log(msg) // 순수
const run = logEffect('hi') // 실행하지 않아 출력 없음
run() // hi
```

- 프로미스는 만들 때 이미 작업이 시작됩니다. `fetch(url)`을 호출하면 즉시 요청이 나갑니다. 실행을 미루려면 `() => fetch(url)`처럼 함수로 감쌉니다.
- 디버깅용 로그는 합성 도중에 `tap`(아래 pipe 절)으로 끼워 넣고, 확인이 끝나면 뺍니다.

흔한 실수는 `map` 콜백 안에서 바깥 배열에 `push`하거나, 결과를 쓰지 않으면서 `map`을 호출하는 것입니다. 효과만 필요하면 `forEach`나 `for...of`를, 새 배열이 필요하면 `map`을 씁니다.

## 불변성 유지

**불변성**(immutability)은 한번 만든 값을 바꾸지 않는 성질입니다. 값이 바뀌어야 하면 변경된 복사본을 새로 만듭니다.

이유는 세 가지입니다.

- 값을 공유해도 다른 코드가 몰래 바꿀 수 없어 추적이 쉽다.
- 이전 값이 남아 있으므로 되돌리기와 비교가 쉽다.
- 변경 여부를 내용 비교 없이 참조 비교(`===`)로 판단할 수 있다. 상태가 바뀌었는지 참조로 확인하는 라이브러리가 이 성질에 기대고 있습니다.

원시 값은 이미 불변입니다. 문자열의 한 글자를 바꾸는 시도는 소용이 없습니다.

```js
'use strict'
const s = 'abc'
s[0] = 'x' // TypeError (비엄격 모드에서는 조용히 무시)
s // 'abc'
```

변수에 다른 값을 넣는 재할당과 값 자체의 변경은 다릅니다. 객체는 값 자체를 바꿀 수 있습니다.

| 방법 | 막는 것 | 막지 못하는 것 |
|------|---------|----------------|
| `const` | 변수 재할당 | 객체 내용 변경 |
| `Object.freeze` | 그 객체의 프로퍼티 추가·삭제·변경 | 중첩 객체의 변경 |
| `Object.seal` | 프로퍼티 추가·삭제 | 기존 프로퍼티 값 변경 |

(`const`는 3편, `freeze`·`seal`은 14편에서 자세히 다룹니다.)

```js
'use strict'
const user = Object.freeze({ name: 'Kim', tags: ['a'] })
user.name = 'Lee'   // TypeError
user.age = 1        // TypeError
delete user.name    // TypeError
user.tags.push('b') // 허용: user.tags는 ['a', 'b']
```

- 비엄격 모드에서는 `freeze`된 객체에 대한 대입·삭제가 에러 없이 무시됩니다. 모듈과 클래스 본문은 항상 엄격 모드입니다(자세히는 19편).
- 얼린 배열에 `push`하면 모드와 관계없이 TypeError가 납니다.
- `Object.isFrozen(obj)`로 확인합니다. 원시 값은 항상 `true`입니다.

`freeze`는 얕습니다. 중첩 객체까지 얼리려면 재귀로 얼립니다.

```js
const deepFreeze = obj => {
  Object.freeze(obj)
  Object.values(obj).forEach(v => {
    const isObj = v !== null && typeof v === 'object'
    if (isObj && !Object.isFrozen(v)) deepFreeze(v)
  })
  return obj
}
```

- 먼저 얼린 뒤 재귀하고 `isFrozen`으로 걸러야 순환 참조에서 무한 재귀하지 않습니다.
- `Map`과 `Set`은 `freeze`해도 `set`·`add`가 막히지 않습니다. 데이터를 내부 슬롯에 저장하기 때문입니다.
- 요소가 있는 Typed Array에 `freeze`를 호출하면 TypeError입니다(자세히는 48편).
- `freeze`는 런타임 검사가 아니라 방어 수단입니다. 개발 중 실수를 드러내는 용도로 쓰고, 불변 업데이트 습관이 기본이어야 합니다.

변경하지 않은 부분은 복사하지 않고 이전 객체를 그대로 참조하는 방식을 구조 공유(structural sharing)라고 합니다. 아래 spread 복사가 이 방식입니다.

## 불변 업데이트 문법 모음

불변 업데이트는 원본을 두고 바뀐 부분만 다른 새 값을 만드는 작업입니다. 용도별 문법은 다음과 같습니다.

| 작업 | 문법 | 결과 |
|------|------|------|
| 객체 프로퍼티 변경·추가 | `{ ...obj, age: 31 }` | 새 객체 |
| 객체 프로퍼티 삭제 | `const { age, ...rest } = obj` | `rest`가 새 객체 |
| 배열 끝·앞에 추가 | `[...arr, x]`, `[x, ...arr]` | 새 배열 |
| 배열 요소 삭제 | `arr.filter(v => v !== x)` | 새 배열 |
| 배열 요소 교체 | `arr.map(v => v.id === id ? ... : v)` | 새 배열 |
| 인덱스로 교체 | `arr.with(i, v)` (ES2023) | 새 배열 |
| 정렬 | `arr.toSorted(cmp)` (ES2023) | 새 배열 |
| 뒤집기 | `arr.toReversed()` (ES2023) | 새 배열 |
| 중간 삽입·삭제 | `arr.toSpliced(i, n, ...items)` (ES2023) | 새 배열 |
| 합치기 | `arr.concat(other)`, `[...a, ...b]` | 새 배열 |
| Map 변경 | `new Map(m).set(k, v)` | 새 Map |
| Set 추가 | `new Set([...s, x])` | 새 Set |

원본을 바꾸는 메서드와 새 배열을 반환하는 대응 메서드를 구분합니다.

| 원본을 바꾼다 | 바꾸지 않는 대응 |
|---------------|------------------|
| `push`, `unshift` | spread, `concat` |
| `pop`, `shift` | `slice(0, -1)`, `slice(1)` |
| `splice` | `toSpliced` |
| `sort` | `toSorted` |
| `reverse` | `toReversed` |
| `arr[i] = v` | `with` |

```js
const arr = [3, 1, 2]
arr.toSorted()     // [1, 2, 3]
arr.toReversed()   // [2, 1, 3]
arr.with(0, 9)     // [9, 1, 2]
arr.toSpliced(1, 1) // [3, 2]
arr                // [3, 1, 2] — 원본 그대로
arr.with(5, 1)     // RangeError — 범위 밖 인덱스
```

- `toSorted`의 기본 정렬은 `sort`와 같아서 요소를 문자열로 바꿔 비교합니다. `[10, 5, 1].toSorted()`는 `[1, 10, 5]`이므로 숫자는 비교 함수를 넘깁니다. `toSorted((a, b) => a - b)`는 `[1, 5, 10]`입니다.
- `with`는 범위를 벗어난 인덱스에 RangeError를 던집니다. 대괄호 대입과 달리 배열을 늘리지 않습니다.

중첩 구조는 바뀌는 경로의 모든 층을 복사합니다.

```js
const state = { user: { name: 'Kim', age: 30 }, n: 1 }
const next = { ...state, user: { ...state.user, age: 31 } }
next.user.age        // 31
state.user.age       // 30
next.n === state.n   // true (값 공유)
```

```js
const todos = [
  { id: 1, done: false },
  { id: 2, done: false }
]
todos.map(t => (t.id === 2 ? { ...t, done: true } : t))
// [{ id: 1, done: false }, { id: 2, done: true }]
// id 1 객체는 복사하지 않고 같은 참조를 유지한다
```

객체 값을 변환할 때는 `Object.entries`와 `Object.fromEntries`(ES2019)를 씁니다.

```js
const price = { a: 1, b: 2 }
Object.fromEntries(
  Object.entries(price).map(([k, v]) => [k, v * 2])
) // { a: 2, b: 4 }
```

spread 복사의 규칙은 다음과 같습니다(자세히는 36편).

- 얕은 복사입니다. 중첩 객체는 같은 참조를 공유합니다. `({ ...s }).a === s.a`는 `true`입니다.
- 뒤에 오는 키가 앞의 키를 덮어씁니다. `{ a: 1, ...{ a: 2 } }`는 `{ a: 2 }`이고, `{ ...{ a: 2 }, a: 1 }`은 `{ a: 1 }`입니다.
- 자신의 열거 가능한 프로퍼티만 복사하고, 프로토타입은 복사하지 않습니다.

깊은 복사가 필요하면 `structuredClone`을 씁니다. ECMAScript가 아니라 호스트 API(브라우저·Node.js 등)입니다.

| 방법 | Date | Set·Map | undefined·함수 | 순환 참조 |
|------|------|---------|----------------|-----------|
| `JSON.parse(JSON.stringify(x))` | 문자열로 변환 | 빈 객체 | 프로퍼티 삭제 | TypeError |
| `structuredClone(x)` | 유지 | 유지 | 함수는 DataCloneError | 처리함 |

- `structuredClone`은 클래스 인스턴스를 복사하면 프로토타입을 잃고 일반 객체가 됩니다. 메서드와 `instanceof`가 사라집니다.
- 대부분의 경우 깊은 복사 대신 바뀌는 경로만 복사하는 위 방식이 더 가볍습니다. 중첩이 깊어 spread가 번거로우면 Immer 같은 라이브러리가 변경 코드를 불변 업데이트로 바꿔 줍니다.

흔한 실수는 `[...arr].sort()` 대신 `arr.sort()`를 상태에 대고 호출하는 것과, 중첩 객체를 한 층만 spread하고 안쪽을 직접 대입해 원본까지 바꾸는 것입니다.

## 고차 함수 활용

**고차 함수**(higher-order function)는 함수를 인수로 받거나 함수를 반환하는 함수입니다. 함수가 값이므로 가능합니다(자세히는 16편). `map`·`filter`·`reduce` 같은 배열 고차 함수는 29편에서 다루고, 여기서는 직접 만들어 쓰는 패턴을 다룹니다.

**동작을 인수로 전달**하면 같은 구조에 다른 판단을 끼울 수 있습니다.

```js
const sortBy = key => (a, b) => a[key] - b[key]
const rows = [{ n: 2 }, { n: 1 }]
rows.toSorted(sortBy('n')) // [{ n: 1 }, { n: 2 }]
```

**함수를 반환**하면 설정을 기억한 새 함수를 만드는 팩토리가 됩니다. 반환된 함수가 바깥 변수를 기억하는 것은 클로저 덕분입니다.

```js
const multiplyBy = n => x => x * n
const triple = multiplyBy(3)
triple(4) // 12
```

**함수를 감싸 동작을 덧붙이는** 래퍼(데코레이터)는 원본을 고치지 않고 기능을 더합니다.

```js
const not = fn => (...args) => !fn(...args)
const isEven = n => n % 2 === 0
const odds = [1, 2, 3, 4].filter(not(isEven)) // [1, 3]

const once = fn => {
  let done = false, result
  return (...args) =>
    done ? result : ((done = true), (result = fn(...args)))
}
const init = once(() => { console.log('init'); return 42 })
init() // init 출력 후 42
init() // 42 (출력 없음, 저장된 결과 반환)
```

고차 함수 자체의 규칙과 함정은 다음과 같습니다.

- **콜백이 받는 인수 개수**: 배열 메서드는 콜백에 `(요소, 인덱스, 배열)` 세 개를 넘깁니다. 인수를 여러 개 받을 수 있는 함수를 그대로 넘기면 의도하지 않은 값이 들어갑니다.

```js
const strs = ['1', '2', '3']
strs.map(parseInt)
// [1, NaN, NaN] — parseInt('2', 1), parseInt('3', 2)로 호출됨

const unary = fn => x => fn(x) // 첫 인수만 전달
strs.map(unary(parseInt)) // [1, 2, 3]
strs.map(Number)          // [1, 2, 3]
```

- **`this` 상실**: 메서드를 콜백으로 넘기면 호출한 객체와 분리되어 `this`가 사라집니다. `obj.method.bind(obj)`나 화살표 함수로 감쌉니다(자세히는 21편).
- **반환 함수 호출**: 함수를 반환하는 함수는 괄호가 한 번 더 필요합니다. `multiplyBy(3)(4)`처럼 씁니다.
- **래퍼의 인수와 `this` 전달**: 래퍼는 `...args`로 받은 인수를 그대로 넘겨야 원본의 호출 방식이 유지됩니다. 메서드를 감쌀 때는 `this`도 넘겨야 하므로 화살표 함수 대신 일반 함수와 `fn.apply(this, args)`를 씁니다.

## Currying

**커링**(currying)은 여러 인수를 받는 함수를 인수 하나씩 받는 함수의 연쇄로 바꾸는 기법입니다. `f(a, b, c)`를 `f(a)(b)(c)`로 호출하게 만듭니다.

```js
const add = a => b => c => a + b + c
add(1)(2)(3) // 6
add(1)(2)    // c => ... (아직 마지막 인수를 기다리는 함수)
```

JavaScript에는 커링 내장 기능이 없습니다. 위처럼 화살표 함수를 겹쳐 직접 쓰거나, 일반 함수를 변환하는 `curry`를 만듭니다.

```js
const curry = (fn, n = fn.length) =>
  function curried(...args) {
    return args.length >= n
      ? fn(...args)
      : (...more) => curried(...args, ...more)
  }

const add3 = curry((a, b, c) => a + b + c)
add3(1)(2)(3) // 6
add3(1, 2)(3) // 6
add3(1)(2, 3) // 6
```

동작 규칙은 다음과 같습니다.

- 인수가 `n`개 모이면 원본을 호출하고, 모자라면 나머지를 기다리는 함수를 반환합니다.
- 이 구현은 호출 한 번에 인수를 여러 개 받을 수 있습니다(느슨한 커링). 엄밀한 커링은 호출마다 정확히 인수 하나입니다.
- 기대 인수 개수는 `fn.length`입니다. 기본값이 있는 매개변수부터 뒤쪽과 나머지 매개변수는 `length`에서 빠집니다.

```js
((a, b) => 0).length         // 2
((a, b = 1, c) => 0).length  // 1
((...args) => 0).length      // 0
curry(Math.max, 3)(1)(5)(2)  // 5 — 인수 개수를 직접 지정
```

- `length`가 0인 함수는 `curry(fn)()` 호출 즉시 실행됩니다. 가변 인수 함수는 두 번째 인수로 `n`을 지정합니다.
- 초과 인수는 원본에 그대로 전달됩니다.

커링의 목적은 인수 순서를 설계해 함수를 재사용하는 것입니다. 변하지 않는 설정을 앞에, 처리할 데이터를 맨 뒤에 둡니다.

```js
const map = fn => arr => arr.map(fn)
const filter = fn => arr => arr.filter(fn)

const double = map(x => x * 2)
double([1, 2, 3]) // [2, 4, 6]
```

이렇게 만든 `double`은 인수가 하나인 함수라서 합성에 바로 쓸 수 있습니다(아래 합성 절).

흔한 실수는 다음과 같습니다.

- 엄밀한 커링 함수에 인수를 한꺼번에 넘기는 것: `const add = a => b => a + b`에서 `add(1, 2)`는 3이 아니라 함수 `b => ...`를 반환합니다(두 번째 인수는 무시).
- 데이터를 앞에 두는 것: `map(arr)(fn)` 순서로 만들면 `map(fn)`을 미리 만들어 재사용할 수 없습니다.
- 호출마다 클로저가 만들어지므로 성능이 중요한 반복문 안에서의 사용은 측정 후 판단합니다.

## 부분 적용

**부분 적용**(partial application)은 함수의 인수 일부를 미리 고정해, 나머지 인수만 받는 새 함수를 만드는 기법입니다.

```js
const greet = (greeting, name) => `${greeting}, ${name}`
const hello = greet.bind(null, 'Hello')
hello('Kim') // 'Hello, Kim'
```

`Function.prototype.bind`의 둘째 인수부터가 고정할 인수입니다. 첫째 인수는 `this`입니다. `this`가 필요 없으면 `null`을 넘깁니다.

- 바인드된 함수의 `name`은 `'bound greet'`이고, `length`는 원본 `length`에서 고정한 인수 개수를 뺀 값(0 미만이면 0)입니다. 위 `hello.length`는 1입니다.
- 화살표 함수에 `bind`해도 인수 고정은 동작하고, `this` 지정은 무시됩니다.
- `bind`는 앞쪽 인수만 고정합니다.

직접 만들면 앞·뒤 어느 쪽이든 고정할 수 있습니다.

```js
const partial = (fn, ...preset) =>
  (...rest) => fn(...preset, ...rest)
const partialRight = (fn, ...preset) =>
  (...rest) => fn(...rest, ...preset)

partial(greet, 'Hi')('Lee')      // 'Hi, Lee'
partialRight(greet, 'Park')('Yo') // 'Yo, Park'
Math.pow.bind(null, 2)(10)        // 1024
```

임의 위치를 고정하는 자리표시자 문법은 JavaScript에 없습니다. 필요하면 화살표 함수로 감쌉니다.

```js
const toDecimal = s => parseInt(s, 10) // 두 번째 인수 고정
const nums = ['1', '2', '3'].map(toDecimal) // [1, 2, 3]
```

커링과 부분 적용은 자주 혼동됩니다.

| 구분 | 커링 | 부분 적용 |
|------|------|-----------|
| 하는 일 | 함수의 모양을 1인수 연쇄로 변환 | 일부 인수를 고정한 새 함수 생성 |
| 인수 처리 | 인수가 모일 때까지 반복해서 받음 | 한 번 고정하고 나머지를 한꺼번에 받음 |
| 결과 함수의 인수 | 하나씩(엄밀) | 남은 인수 전부 |
| 원본 함수 | 변환된 함수로 대체 | 그대로 둠 |

커링한 함수에 인수 하나를 넘기는 것은 부분 적용과 같은 결과를 냅니다. 둘은 목적이 같고 인수를 받는 방식이 다릅니다.

## 함수 합성

**함수 합성**(function composition)은 한 함수의 출력을 다음 함수의 입력으로 이어 새 함수를 만드는 것입니다. 수학의 f∘g는 `x => f(g(x))`입니다.

```js
const inc = x => x + 1
const double = x => x * 2

const incThenDouble = x => double(inc(x))
incThenDouble(3) // 8  (3 → 4 → 8)
```

합성이 성립하려면 다음을 지킵니다.

- 앞 함수의 반환 값이 다음 함수가 기대하는 입력 타입이어야 합니다.
- 합성에 쓰는 함수는 인수가 하나(단항)여야 합니다. 맨 처음 함수만 인수가 여러 개여도 됩니다.
- 인수가 여러 개인 함수는 커링·부분 적용으로 단항으로 줄여 연결합니다.

```js
const add = a => b => a + b
const addTen = add(10) // 단항
double(addTen(1))      // 22
```

합성에는 두 가지 성질이 있습니다.

- **결합법칙**: `compose(f, compose(g, h))`와 `compose(compose(f, g), h)`는 결과가 같습니다. 묶는 순서를 바꿔도 되고, 중간에서 잘라 이름을 붙일 수 있습니다.
- **항등 함수**: `x => x`를 합성에 끼워도 결과가 바뀌지 않습니다. 함수 목록이 비었을 때의 기본값으로 쓰입니다.

메서드 체이닝(`arr.filter(...).map(...)`)도 합성의 한 형태지만 해당 객체의 메서드만 이을 수 있습니다. 함수 합성은 어떤 단항 함수든 이을 수 있고, 새 함수를 값으로 만들어 이름을 붙일 수 있다는 점이 다릅니다.

흔한 실수는 단항이 아닌 함수를 중간에 끼우는 것입니다. `map(parseInt)` 문제(고차 함수 절)와 같은 이유로 의도하지 않은 인수가 전달됩니다. `unary`로 감싸거나 인수를 고정해 단항으로 만듭니다.

## pipe·compose

`pipe`와 `compose`는 여러 함수를 합성하는 도우미입니다. 방향만 다릅니다.

```js
const pipe = (...fns) => x =>
  fns.reduce((acc, fn) => fn(acc), x)
const compose = (...fns) => x =>
  fns.reduceRight((acc, fn) => fn(acc), x)

pipe(inc, double)(3)    // 8  — inc 먼저: (3 + 1) * 2
compose(inc, double)(3) // 7  — double 먼저: (3 * 2) + 1
pipe()(5)               // 5  — 함수가 없으면 입력 그대로
```

| 구분 | `pipe` | `compose` |
|------|--------|-----------|
| 실행 순서 | 왼쪽에서 오른쪽 | 오른쪽에서 왼쪽 |
| 수학 표기와 | 다름 | 같음 `f(g(x))` |
| 읽는 흐름 | 쓴 순서 = 실행 순서 | 쓴 순서의 역순 |
| 구현 | `reduce` | `reduceRight` |

(`reduce`는 29편에서 다룹니다.) 실행 순서가 위에서 아래로 읽히는 `pipe`가 더 많이 쓰입니다. Lodash의 `flow`·`flowRight`, Ramda의 `pipe`·`compose`가 같은 역할입니다.

```js
const trim = s => s.trim()
const lower = s => s.toLowerCase()
const dash = s => s.replaceAll(' ', '-')
const slugify = pipe(trim, lower, dash)
slugify('  Hello World ') // 'hello-world'
```

**디버깅용 `tap`**은 값을 그대로 통과시키면서 부수 효과 하나를 실행합니다.

```js
const tap = fn => x => (fn(x), x)
pipe(inc, tap(console.log), double)(3)
// 4 출력, 반환 8
```

**첫 함수가 여러 인수를 받는** 변형은 첫 함수만 따로 받습니다.

```js
const pipeN = (first, ...rest) => (...args) =>
  rest.reduce((acc, fn) => fn(acc), first(...args))
pipeN((a, b) => a + b, double)(1, 2) // 6
```

- 이 변형은 함수를 하나도 넘기지 않으면 `first`가 `undefined`라서 호출 시 TypeError가 납니다.
- 중간 함수가 예외를 던지면 그 뒤 함수는 실행되지 않고 예외가 호출한 쪽으로 전파됩니다.
- 중간에 `null`·`undefined`가 나오면 다음 함수가 그대로 받으므로 TypeError가 날 수 있습니다. 필요한 곳에서 기본값을 채웁니다.

프로미스를 반환하는 함수를 이으려면 `then`으로 연결하는 비동기 버전을 씁니다(자세히는 41편).

```js
const pipeAsync = (...fns) => x =>
  fns.reduce((p, fn) => p.then(fn), Promise.resolve(x))
pipeAsync(inc, async x => x * 2)(1).then(console.log) // 4
```

`then`이 일반 값과 프로미스를 모두 받아 평탄화하므로 동기 함수와 비동기 함수를 섞어도 됩니다.

## Memoization

**메모이제이션**(memoization)은 함수의 결과를 인수별로 저장해 두고, 같은 인수로 다시 호출되면 계산하지 않고 저장된 값을 반환하는 기법입니다.

```js
const memoize = fn => {
  const cache = new Map()
  return arg => {
    if (cache.has(arg)) return cache.get(arg)
    const result = fn(arg)
    cache.set(arg, result)
    return result
  }
}

const fib = memoize(n =>
  n < 2 ? n : fib(n - 1) + fib(n - 2))
fib(50) // 12586269025 — 각 n을 한 번씩만 계산
```

- 순수 함수에만 적용합니다. 결과가 호출 시점에 따라 달라지는 함수는 오래된 값을 반환합니다.
- 재귀 호출이 메모이즈된 함수를 통해 이루어져야 효과가 있습니다. 위에서 `fib` 안쪽 호출이 `memoize`가 반환한 `fib`를 가리키는 것이 그 조건입니다. 메모이즈 전의 원본을 호출하면 재귀 내부는 캐시를 쓰지 못합니다.
- 캐시 확인은 `has`로 합니다. `cache[n] || ...`처럼 값의 참·거짓으로 판단하면 결과가 `0`, `''`, `false`인 호출을 매번 다시 계산합니다.
- `Map`은 키를 SameValueZero로 비교하므로 `NaN`도 같은 키로 취급하고, `0`과 `-0`은 같은 키입니다. 객체는 참조가 같아야 같은 키입니다(자세히는 38편).

인수가 여러 개이면 인수 목록을 하나의 키로 바꿔야 합니다. 흔한 방법은 `JSON.stringify(args)`입니다.

```js
const key = (...args) => JSON.stringify(args)
key(1, 'a')            // '[1,"a"]'
key(undefined, () => 1) // '[null,null]' — 서로 다른 값이 같은 키
key({ a: 1, b: 2 }) === key({ b: 2, a: 1 }) // false
```

- `undefined`·함수·`NaN`은 `null`로 바뀌어 다른 인수가 같은 키를 갖는 충돌이 생깁니다. BigInt는 TypeError를 던집니다.
- 같은 내용이어도 객체의 키 순서가 다르면 다른 키가 됩니다.
- 인수가 원시 값 하나뿐이면 키 변환 없이 `Map`을 직접 씁니다.

인수가 객체이면 `WeakMap`으로 참조별 캐시를 만들 수 있습니다. 객체가 다른 곳에서 쓰이지 않게 되면 캐시 항목도 회수됩니다(자세히는 38편, 49편).

```js
const memoizeByRef = fn => {
  const cache = new WeakMap()
  return obj => {
    if (!cache.has(obj)) cache.set(obj, fn(obj))
    return cache.get(obj)
  }
}
```

캐시 크기는 제한이 없습니다. 인수 종류가 계속 늘어나면 메모리가 계속 늘어납니다. `Map`이 삽입 순서를 기억하는 점을 이용해 가장 오래된 항목을 지울 수 있습니다.

```js
const MAX = 100
if (cache.size >= MAX) {
  cache.delete(cache.keys().next().value) // 가장 오래된 키
}
cache.set(arg, result)
```

비동기 함수는 결과가 아니라 프로미스를 저장합니다. 요청이 끝나기 전에 같은 호출이 오면 같은 프로미스를 공유하고, 실패한 프로미스는 캐시에서 지웁니다.

```js
const memoAsync = fn => {
  const cache = new Map()
  return key => {
    if (!cache.has(key)) {
      cache.set(key, fn(key).catch(e => {
        cache.delete(key) // 실패는 저장하지 않는다
        throw e
      }))
    }
    return cache.get(key)
  }
}
```

메모이제이션은 계산이 비싸고 같은 인수가 자주 반복될 때만 이득입니다. 호출이 대부분 새 인수이면 키 계산과 저장 비용만 늘어납니다.

## 지연 평가

**지연 평가**(lazy evaluation)는 값이 실제로 필요한 시점까지 계산을 미루는 방식입니다. JavaScript는 기본이 **즉시 평가**여서, 함수 호출 전에 인수를 모두 계산하고, `map`·`filter`는 배열 전체를 한 번에 처리해 중간 배열을 만듭니다. 지연 평가는 다음 도구로 부분적으로 얻습니다.

| 도구 | 미뤄지는 것 | 편 |
|------|-------------|----|
| 단축 평가(논리·nullish·조건 연산자) | 선택되지 않은 쪽의 식 | 08편 |
| 기본값 매개변수 | 인수가 `undefined`일 때만 식 평가 | 27편 |
| 썽크(thunk, 인수 없는 함수) | 함수 본문 전체 | 이 절 |
| 제너레이터 | 다음 값 계산 | 42편 |
| 이터레이터 헬퍼 | 요소 단위 변환 | 이 절 |

단축 평가와 기본값은 필요하지 않으면 식을 아예 실행하지 않습니다.

```js
const f = (a = (console.log('computed'), 1)) => a
f(5) // 5 (출력 없음)
f()  // 'computed' 출력 후 1
```

**썽크**는 계산을 함수로 감싸 호출 시점까지 미룹니다.

```js
const expensive = () => { console.log('run'); return 7 }
const lazyValue = () => expensive() // 정의만으로는 실행 안 됨
lazyValue() // run 출력 후 7
```

한 번만 계산하고 저장하고 싶으면 `once`(고차 함수 절)나 메모이제이션과 합칩니다. 접근 시 처음 한 번만 계산하는 게터도 같은 발상입니다.

```js
const config = {
  get big() {
    const v = [1, 2, 3] // 처음 접근 때만 계산
    Object.defineProperty(this, 'big', { value: v })
    return v
  }
}
config.big === config.big // true
```

**이터레이터 헬퍼**(ES2025)는 이터레이터에 `map`·`filter`·`take`·`drop`·`flatMap` 등을 제공해, 요소를 하나씩 끝까지 흘려보내며 처리합니다. 무한 시퀀스도 필요한 만큼만 꺼낼 수 있습니다.

```js
function* naturals() {
  let n = 1
  while (true) yield n++
}
naturals()
  .filter(n => n % 2 === 0)
  .map(n => n * n)
  .take(3)
  .toArray() // [4, 16, 36]
```

배열 체인과 평가 방식의 차이는 콜백이 실행되는 횟수에서 드러납니다.

```js
const log2 = x => { console.log(x); return x * 2 }

const r1 = [1, 2, 3].map(log2).slice(0, 1)
// 1, 2, 3 모두 출력 후 [2]

const r2 = [1, 2, 3].values().map(log2).take(1).toArray()
// 1만 출력 후 [2]
```

- 변환 메서드(`map`, `filter`, `take`, `drop`, `flatMap`)는 배열이 아닌 이터레이터를 반환하고, 최종 연산(`toArray`, `reduce`, `forEach`, `some`, `every`, `find`)이 호출될 때 비로소 실행됩니다.
- `Iterator.from(iterable)`로 이터러블이나 이터레이터 객체를 헬퍼 메서드를 가진 이터레이터로 바꿉니다.
- 이터레이터는 한 번 소비하면 비어 있습니다. 같은 이터레이터에 `toArray()`를 두 번 호출하면 두 번째는 `[]`입니다.
- 새 판의 기능이므로 대상 환경의 지원을 MDN에서 확인합니다. 지원하지 않는 환경에서는 제너레이터 함수로 `take`·`map`을 직접 만들어 씁니다.

지연 평가의 대가는 실행 순서와 시점을 추적하기 어려워지는 것입니다. 부수 효과가 있는 콜백을 지연 체인에 넣으면 효과가 언제 일어날지 읽기 어려우므로, 지연 평가는 순수한 콜백과 함께 씁니다.

## 파이프라인 연산자 제안 상태

**파이프라인 연산자**(`|>`)는 왼쪽 값을 오른쪽 식에 흘려 넣는 연산자를 추가하려는 TC39 제안입니다. 2026-10 기준 **2단계**(Stage 2)이며 표준이 아닙니다(단계의 의미는 01편).

채택 방식은 **Hack 파이프**이고, 직전 값을 가리키는 자리표시자로 `%`를 씁니다. 이 토큰은 최종 확정이 아닙니다.

```js
// 제안 문법 — 아직 표준이 아니다
'  Hello World '
  |> %.trim()
  |> %.toLowerCase()
  |> %.replaceAll(' ', '-') // 'hello-world'
```

```js
// 지금 쓰는 동일한 코드
pipe(trim, lower, dash)('  Hello World ')
```

규칙은 다음과 같습니다.

- 오른쪽 식은 `%`를 최소 한 번 사용해야 합니다. `value |> foo + 1`은 문법 오류입니다.
- 오른쪽에 임의의 식을 쓸 수 있으므로 `value |> foo(1, %)`, `value |> % + 1`, `value |> %.method()`처럼 인수가 여러 개인 함수나 메서드 호출을 별도 변환 없이 이을 수 있습니다.
- `value |> await %`처럼 `await`를, 제너레이터 안에서는 `yield`를 오른쪽 식에 쓸 수 있습니다. 함수 기반 `pipe`는 비동기 전용 버전이 따로 필요합니다.
- 우선순위는 화살표 함수·대입 연산자와 같은 수준으로, 쉼표 연산자보다만 높고 나머지 모든 연산자보다 낮습니다. 비슷한 우선순위의 연산자와 섞으면 괄호가 필요합니다.

경쟁하던 F# 방식(`x |> f`로 단항 함수를 바로 연결)은 채택되지 않았습니다. Hack 방식은 단항 함수 호출에만 `f(%)`처럼 문법 부담이 생깁니다. F# 방식은 단항이 아닌 모든 식(메서드 호출, 인수가 둘 이상인 호출, 연산식)에 부담이 생기고, 그런 식이 더 흔하다는 판단입니다.

실무 판단은 다음과 같습니다.

- 엔진이 지원하지 않으므로 그대로 실행되지 않습니다. Babel에는 구현돼 있습니다(7.15부터).
- 문법과 토큰이 바뀔 수 있어 프로덕션 코드에 쓰지 않습니다.
- 지금은 위 `pipe` 함수로 같은 구조를 만듭니다.

## 핵심 정리

- 순수 함수는 같은 입력에 같은 출력을 내고 바깥을 바꾸지 않습니다. 부수 효과는 가장자리로 모읍니다.
- `const`는 재할당만, `Object.freeze`는 한 층만 막습니다. 변경은 spread, `map`·`filter`, `toSorted`·`with` 같은 새 값 반환 문법으로 합니다.
- 커링은 함수를 1인수 연쇄로 바꾸고, 부분 적용은 일부 인수를 고정합니다. 둘 다 데이터를 마지막 인수로 두면 합성에 쓰기 좋습니다.
- `pipe`는 왼쪽에서 오른쪽, `compose`는 오른쪽에서 왼쪽으로 단항 함수를 잇습니다.
- 메모이제이션은 순수 함수의 결과를 키별로 저장하고, 지연 평가는 필요할 때까지 계산을 미룹니다.
- 파이프라인 연산자(`|>`, Hack 방식)는 2단계 제안이며 아직 사용할 수 없습니다.
