## 핵심 먼저 보기

- 변수는 선언문이 실행될 때가 아니라 스코프에 들어갈 때 생성되고, var는 즉시 `undefined`로 초기화되지만 let·const는 선언문 실행 시 초기화됩니다.
- 전역 변수는 이름 충돌과 암묵적 결합을 일으키므로 IIFE·네임스페이스·모듈 패턴으로 줄이고, 지금은 ES 모듈과 블록 스코프가 기본 해법입니다.
- var는 중복 선언, 함수 레벨 스코프, 선언 전 `undefined` 접근, 전역 객체 오염이 문제이고, let은 블록 스코프·중복 선언 금지·TDZ로 이를 막습니다.
- 일반 스크립트 최상위의 var·함수 선언은 전역 객체 프로퍼티가 되고, let·const·class는 선언적 환경 레코드에 저장되어 전역 객체에 나타나지 않습니다.
- const는 재할당만 막으므로 객체의 프로퍼티는 바뀔 수 있습니다. 기본은 const, 재할당이 필요하면 let, var는 쓰지 않습니다.
- `for (let ...)`는 반복마다 새 바인딩을 만들고, switch의 case는 별도 스코프가 아니며, TDZ 변수에는 `typeof`도 ReferenceError를 던집니다.

## 변수의 생명 주기

변수의 생명 주기(life cycle)는 변수가 생성되어 값을 담을 수 있게 된 시점부터 메모리가 회수되기까지의 기간입니다. 시작과 끝은 변수가 선언된 스코프가 정합니다(자세히는 12편).

| 변수 | 생성 | 회수 가능 시점 |
|------|------|----------------|
| 전역 변수 | 스크립트 실행 직전 | 전역 환경이 사라질 때. 브라우저는 페이지를 벗어날 때, Node.js는 프로세스가 끝날 때 |
| 함수 지역 변수 | 함수를 호출할 때마다 | 호출이 끝나고 아무도 참조하지 않을 때 |
| 블록 지역 변수 | 블록에 들어갈 때마다 | 블록이 끝나고 아무도 참조하지 않을 때 |

```js
function counter() {
  let n = 0 // 호출할 때마다 새로 생성된다
  n++
  return n
}
counter() // 1
counter() // 1 — 이전 호출의 n과 무관한 별개의 변수
```

## 전역 변수의 문제점

전역 변수는 일반 스크립트(모듈이 아닌 스크립트)의 최상위, 곧 어떤 함수나 블록에도 속하지 않는 위치에서 선언한 변수입니다. 같은 페이지의 모든 스크립트가 하나의 전역 스코프를 공유하고, 전역 스코프는 스코프 체인의 끝이라 어디서든 보입니다.

| 문제 | 내용 |
|------|------|
| 암묵적 결합 | 어느 코드에서나 읽고 바꿀 수 있어서, 값이 바뀐 원인을 찾으려면 모든 코드를 봐야 한다 |
| 긴 생명 주기 | 프로그램이 끝날 때까지 메모리를 차지하고, 남은 상태가 이후 동작에 영향을 준다 |
| 이름 충돌 | 같은 이름의 전역 변수는 하나뿐이라 다른 파일·라이브러리의 변수를 덮어쓴다 |
| 검색 경로 | 스코프 체인 맨 끝에 있어 검색할 환경이 가장 많다 |
| 테스트 | 전역 상태가 테스트 사이에 남아 서로 영향을 준다 |

```js
// a.js
var total = 10
// b.js — 같은 페이지에 함께 로드
var total = 'none' // a.js의 total을 덮어쓴다
// 이후 a.js의 코드에서
total + 5 // 'none5'
```

## 전역 변수 억제

전역 변수를 줄이는 원칙은 두 가지입니다. 변수의 스코프를 가능한 좁게 하고, 전역에 남겨야 하는 것은 하나로 묶습니다. 라이브러리가 전역에 소수의 이름만 노출하는 것이 이 방식입니다.

| 방법 | 전역에 남는 것 | 정보 은닉 | 한계 |
|------|----------------|-----------|------|
| IIFE | 없음 | 가능 | 결과를 밖에서 쓰려면 전역 변수에 대입해야 한다 |
| 네임스페이스 | 객체 1개 | 불가 | 모든 멤버가 공개되고 누구나 덮어쓸 수 있다 |
| 모듈 패턴 | 객체 1개 | 가능 | 의존 관계와 로드 순서를 직접 관리한다 |
| ES 모듈 | 없음 | 가능 | 모듈을 지원하는 환경이 필요하다 |

## var의 문제점

var는 ES5까지 유일한 변수 선언 키워드였습니다. let·const(ES2015)가 필요해진 이유가 다음 문제들입니다.

- 초기값이 없는 중복 선언은 기존 값을 유지합니다. `var x = 1; var x; x`는 `1`입니다. 함수 매개변수와 같은 이름의 `var a`도 값을 지우지 않습니다.
- 같은 이름을 실수로 다시 선언해도 에러가 없습니다. 중첩 루프에서 같은 카운터를 쓰면 안쪽 루프가 바깥 카운터를 망가뜨립니다.

## let과 블록 레벨 스코프

let(ES2015)은 재할당할 수 있는 블록 스코프 변수를 선언합니다. 블록 레벨 스코프는 `{ }`로 둘러싼 코드 블록이 스코프를 만든다는 뜻입니다. 함수 본문, if·for·while·switch 본문, try·catch·finally, 단독 블록이 모두 해당합니다.

## TDZ

`let`·`const`는 스코프 시작부터 선언이 인식되지만 초기화 전에는 접근할 수 없습니다. 이 구간이 TDZ이며 읽기·쓰기뿐 아니라 해당 바인딩의 `typeof`도 `ReferenceError`가 납니다.

## 전역 객체와 let

전역 객체(global object)는 실행 환경이 전역 스코프를 위해 만드는 객체입니다. 브라우저는 `window`, Node.js는 `global`, 어디서든 `globalThis`(ES2020)로 가리킵니다(자세히는 01편).

| 선언 | 저장 위치 | 전역 객체 프로퍼티 | delete |
|------|-----------|--------------------|--------|
| 최상위 var, 함수 선언 | 객체 레코드, `[[VarNames]]` | O (configurable: false) | 불가 |
| 최상위 let, const, class | 선언적 레코드 | X | 해당 없음 |
| 암묵적 전역, `globalThis.x = 1` | 객체 레코드 | O (configurable: true) | 가능 |

## const와 상수

const(ES2015)는 재할당할 수 없는 블록 스코프 변수를 선언합니다. 상수(constant)는 한 번 정한 뒤 바뀌지 않는 값에 붙인 이름입니다. 원시 값은 그 자체가 불변이라(자세히는 10편) 원시 값을 담은 const는 값까지 고정된 상수입니다.

## const와 객체 변경

`const`는 변수의 재할당을 막습니다. 객체의 프로퍼티나 배열 요소 변경까지 막지 않으므로 불변 객체가 필요하면 별도 규칙이나 동결을 사용합니다. `Object.freeze`도 기본적으로 얕게 동작합니다.

## 사용 기준

| 항목 | var | let | const |
|------|-----|-----|-------|
| 스코프 | 함수 | 블록 | 블록 |
| 같은 스코프 재선언 | 가능 | 불가 | 불가 |
| 재할당 | 가능 | 가능 | 불가 |
| 초기값 | 선택 | 선택 | 필수 |
| 선언 전 접근 | `undefined` | ReferenceError | ReferenceError |
| 최상위가 전역 객체 프로퍼티 | O | X | X |

선택 규칙은 세 줄입니다.
