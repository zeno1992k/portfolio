## 함수의 개념과 필요성

함수(function)는 여러 문을 하나로 묶어 이름이나 값으로 가리키고, 필요할 때 입력을 넘겨 실행하는 코드 단위입니다. 실행 결과는 반환값으로 돌려받습니다.

```js
function area(r) { return r * r * 3.14 }

area(3) // 28.26
area(5) // 78.5
```

함수가 없으면 같은 계산을 값만 바꿔 복사해야 합니다. 함수로 묶으면 세 가지가 달라집니다.

- 재사용: 한 번 정의하고 여러 번 호출합니다.
- 수정 범위: 계산 규칙이 바뀌면 함수 하나만 고칩니다.
- 가독성: 코드 덩어리에 의도를 드러내는 이름이 붙습니다.

| 용어 | 뜻 | `function add(x, y) { return x + y }`에서 |
|------|----|------|
| 함수 이름 | 함수를 가리키는 식별자 | `add` |
| 매개변수(parameter) | 받을 값에 붙인 이름. 함수 안에서만 쓰는 지역 변수 | `x`, `y` |
| 인수(argument) | 호출할 때 실제로 넘기는 값 | `add(1, 2)`의 `1`, `2` |
| 함수 몸체 | 중괄호 안의 문 | `return x + y` |
| 반환값 | 함수가 호출 지점에 돌려주는 값 | `3` |

ECMAScript에서 함수는 호출할 수 있는 객체입니다. 값이므로 변수에 담고, 인수로 넘기고, 반환할 수 있습니다(자세히는 16편). `typeof` 결과는 `'function'`입니다.

함수를 만드는 방법은 다음과 같습니다.

| 방법 | 형태 | 이 편의 절 |
|------|------|-----------|
| 함수 선언문 | `function f() {}` | 함수 선언문 |
| 함수 표현식 | `const f = function () {}` | 함수 표현식 |
| Function 생성자 | `new Function('return 1')` | Function 생성자 |
| 화살표 함수 | `const f = () => 1` | 화살표 함수 개요 |

메서드 축약 표기, 클래스, async 함수, 제너레이터는 각각 27편, 24편, 43편, 42편에서 다룹니다.

## 함수 리터럴

함수 리터럴(function literal)은 함수 객체를 만드는 표기입니다. 평가되는 순간 함수 객체가 생성되고 그 객체가 리터럴의 값이 됩니다. 객체 리터럴, 배열 리터럴과 같은 원리입니다.

```js
// function 키워드 + 이름(선택) + 매개변수 + 몸체
function add(x, y) { return x + y }
```

| 구성 요소 | 규칙 |
|-----------|------|
| `function` 키워드 | 필수 |
| 함수 이름 | 선택. 없으면 익명 함수(anonymous function), 있으면 기명 함수(named function) |
| 매개변수 목록 | 괄호 안에 쉼표로 구분. 없어도 빈 괄호는 필요 |
| 몸체 | 중괄호 필수. 내용은 비어 있어도 됨 |

같은 모양이 위치에 따라 다르게 해석됩니다. 문의 맨 앞에 `function`이 오면 선언문이고, 값이 오는 자리(할당 우변, 괄호 안, 인수, 반환식)에 오면 리터럴을 쓴 표현식입니다.

```js
function a() {}            // 선언문
const b = function () {}   // 표현식: 할당 우변
foo(function () {})        // 표현식: 인수 위치
const d = (function () {}) // 표현식: 괄호 안
```

리터럴은 평가될 때마다 새 함수 객체를 만듭니다. 같은 모양의 코드라도 평가가 두 번이면 서로 다른 객체입니다.

```js
const make = () => function () {}
make() === make() // false
```

## 함수 선언문

함수 선언문(function declaration)은 `function` 키워드로 시작하는 문입니다. 이름과 함수 객체를 함께 만들어 현재 스코프에 등록합니다.

```js
function add(x, y) { return x + y }
add(1, 2) // 3
```

- 이름이 필수입니다. 이름 없는 선언문은 SyntaxError입니다. `export default function () {}`만 예외입니다(45편).
- 문이므로 값이 아닙니다. `const f = function g() {}`처럼 값이 오는 자리에 쓰면 선언문이 아니라 표현식입니다.
- 끝에 세미콜론이 필요 없습니다. 붙여도 빈 문이 될 뿐 오류는 아닙니다.
- 함수 몸체 최상위에 쓴 선언문의 이름은 `var`처럼 그 함수 스코프에 등록됩니다. 이름은 재할당할 수 있습니다.

같은 이름을 다시 선언해도 오류가 아닙니다. 호이스팅 때문에 마지막 선언이 모든 호출에 적용됩니다.

```js
function add(x, y) { return x + y }
function add(x, y) { return x * y } // 오류 없음
add(2, 3) // 6
```

`let`·`const`와 같은 이름의 선언문을 같은 스코프에 쓰면 `SyntaxError: Identifier 'add' has already been declared`입니다.

## 함수 표현식

함수 표현식(function expression)은 함수 리터럴을 값이 오는 자리에 쓴 것입니다. 함수 객체가 값이 되므로 변수에 할당하고, 인수로 전달하고, 반환할 수 있습니다.

```js
const add = function (x, y) { return x + y }
add(1, 2) // 3
```

| 항목 | 선언문 | 표현식 |
|------|--------|--------|
| 문법 범주 | 문 | 표현식(값) |
| 함수 이름 | 필수 | 선택 |
| 함수 이름이 보이는 범위 | 둘러싼 스코프 | 함수 몸체 안 |
| 정의보다 앞에서 호출 | 가능 | 변수 규칙을 따름(불가) |
| 끝의 세미콜론 | 불필요 | 할당문이므로 붙이는 것이 관례 |

### 기명 함수 표현식의 스코프

기명 함수 표현식(named function expression)의 이름은 그 함수의 몸체 안에서만 보이는 식별자이고 함수 자신을 가리킵니다. 바깥 스코프에는 등록되지 않습니다.

```js
const fact = function f(n) {
  return n <= 1 ? 1 : n * f(n - 1) // 몸체 안에서 f 사용
}
fact(5)  // 120
typeof f // 'undefined': 바깥에서는 보이지 않는다
```

- 몸체 안에서 이 이름은 읽기 전용입니다. 재할당은 비엄격 모드에서 조용히 무시되고, strict mode에서는 TypeError입니다.
- 몸체 안에서 같은 이름의 매개변수나 `var`·`let`·`const`를 선언하면 그것이 이름을 가립니다.
- 쓰임새는 두 가지입니다. 변수 이름이 바뀌거나 함수를 다른 변수에 옮겨도 깨지지 않는 자기 재귀 호출, 그리고 `name` 프로퍼티가 정해져 디버거와 에러 스택에서 함수를 구분할 수 있다는 점입니다.

### 함수 이름 추론

ES2015부터 이름 없는 함수 리터럴(화살표 함수와 익명 클래스 포함)이 식별자에 직접 할당되면 엔진이 그 식별자를 함수의 `name`으로 정합니다. 명세 용어로는 NamedEvaluation입니다.

```js
const add = function () {}
add.name // 'add'

const o = { run: function () {} }
o.run.name // 'run'
```

추론되는 자리는 다음과 같습니다.

- 변수 선언과 식별자 대입: `const a = function () {}`, `a = () => {}`, `a ??= () => {}`
- 객체 리터럴의 프로퍼티 값
- 매개변수 기본값과 구조 분해 기본값
- 괄호로 감싼 리터럴 `const a = (function () {})`

추론되지 않는 자리에서는 `name`이 빈 문자열입니다.

```js
const obj = {}
obj.p = function () {}
obj.p.name // '': 프로퍼티 대입은 추론하지 않는다

const h = true ? function () {} : 1
h.name // '': 삼항·논리 연산자 안은 추론하지 않는다
```

- 배열 요소와 인수 위치에서 바로 넘긴 함수도 추론되지 않습니다.
- 이름을 직접 쓴 기명 함수 표현식은 그 이름이 우선합니다. `const a = function b() {}`의 `name`은 `'b'`입니다.
- `name`은 쓰기 불가이지만 재정의할 수 있습니다(자세히는 16편).

## 함수 호이스팅

함수 선언문은 스코프에 진입하는 시점, 즉 코드가 한 줄도 실행되기 전에 이름 등록과 함수 객체 초기화가 모두 끝납니다. 그래서 선언문보다 앞에서도 호출할 수 있습니다.

```js
add(1, 2) // 3: 선언문보다 앞에서 호출
function add(x, y) { return x + y }
```

변수는 이름만 앞당겨지고 값은 대입 시점에 들어가지만(03편), 선언문은 값까지 앞당겨집니다. 원리는 실행 컨텍스트의 생성 단계에 있습니다(22편).

함수 표현식과 화살표 함수는 변수 규칙을 따릅니다.

```js
sub(1, 2) // TypeError: sub is not a function
var sub = function (x, y) { return x - y }

mul(1, 2) // ReferenceError: Cannot access 'mul' ...
const mul = function (x, y) { return x * y }
```

| 정의 방식 | 호이스팅되는 것 | 정의 앞에서 호출 |
|-----------|----------------|-----------------|
| 함수 선언문 | 이름 + 함수 객체 | 가능 |
| `var` + 함수 표현식 | 이름(값은 `undefined`) | TypeError |
| `let`·`const` + 표현식·화살표 함수 | 이름(TDZ 상태) | ReferenceError |

TDZ(일시적 사각지대)는 13편에서 다룹니다.

`var` 변수와 이름이 같으면 선언문이 먼저 초기화되고, `var` 선언 자체는 값을 덮어쓰지 않습니다. 대입문이 실행된 뒤에야 값이 바뀝니다.

```js
function test() {
  console.log(typeof g) // 'function': 선언문이 먼저 초기화됨
  var g = 1             // 이 대입이 실행되면 덮어쓴다
  function g() {}
  console.log(typeof g) // 'number'
}
```

흔한 실수는 선언문을 `const` 표현식으로 바꾸면서 호출 위치를 그대로 두는 것입니다. 선언문일 때는 동작하던 코드가 ReferenceError로 바뀝니다.

### 블록 안 함수 선언

블록(`{}`, `if`·`for` 본문) 안의 함수 선언문은 ES2015부터 명세에 들어와 블록 스코프를 가집니다. 비엄격 모드에서는 웹 호환을 위한 Annex B 규칙이 추가로 적용되어 동작이 달라집니다.

| 항목 | strict mode | 비엄격 모드 |
|------|-------------|-------------|
| 블록 안에서 | 블록 시작으로 호이스팅 | 같음 |
| 블록 밖에서 | 보이지 않음 | 블록이 실행된 뒤 보임 |
| 블록 앞에서 | 보이지 않음 | 이름은 있고 값은 `undefined` |

비엄격 모드는 같은 이름의 `var` 변수가 바깥 함수 스코프에 따로 생기고, 블록 안의 선언문이 실행되는 시점에 그 변수에 함수가 대입되는 방식입니다. 바깥에 같은 이름의 `let`·`const`가 있어 `var`를 만들 수 없으면 이 규칙은 적용되지 않습니다.

```js
function run() {
  typeof f // 'undefined' (strict mode도 'undefined')
  { function f() {} }
  typeof f // 비엄격 'function', strict mode 'undefined'
}
```

- 블록이 실행되지 않으면(`if (false) { function k() {} }`) 비엄격 모드에서도 바깥의 `k`는 `undefined`입니다. 호출하면 TypeError입니다.
- `if (x) function f() {}`처럼 블록 없이 본문에 선언문을 쓰는 것은 비엄격 모드에서만 허용됩니다. strict mode에서는 SyntaxError입니다.
- 비엄격 모드의 세부 동작은 엔진마다 다를 수 있어 MDN도 블록 안 선언은 strict mode에서만 하라고 권고합니다. ES 모듈과 클래스 본문은 자동으로 strict mode입니다(19편).
- 블록 안에서는 선언문 대신 `const f = () => {}`를 쓰면 위 차이를 피할 수 있습니다.

## Function 생성자

`Function` 생성자는 문자열을 코드로 파싱해 함수 객체를 만듭니다. 마지막 인수가 몸체이고 앞의 인수가 매개변수 이름입니다.

```js
const add = new Function('a', 'b', 'return a + b')
add(1, 2) // 3
add.name  // 'anonymous'
```

- 매개변수를 `'a, b'`처럼 한 문자열에 쉼표로 적어도 됩니다.
- `new` 없이 `Function('a', 'return a')`로 호출해도 같은 결과입니다.
- 코드가 문자열이므로 SyntaxError는 생성하는 순간, 즉 실행 중에 발생합니다.
- 생성된 함수는 호출한 곳의 스코프가 아니라 전역 스코프에서 평가됩니다. 지역 변수가 보이지 않고 클로저가 만들어지지 않습니다.

```js
function outer() {
  const local = 1
  return new Function('return typeof local')()
}
outer() // 'undefined': 지역 변수에 접근하지 못한다
```

`eval`과 비교하면 다음과 같습니다.

| 항목 | `eval` | `Function` 생성자 |
|------|--------|-------------------|
| 입력 | 코드 문자열(문) | 매개변수 이름들 + 몸체 문자열 |
| 결과 | 마지막 문의 값 | 함수 객체(호출해야 실행) |
| 스코프 | 직접 호출이면 호출한 위치 | 전역 |

직접 호출은 `eval(...)`이라는 이름 그대로 부르는 경우입니다(strict mode와의 관계는 19편).

일반 코드에서 쓰지 않는 이유는 세 가지입니다.

- 보안: 외부 입력이 문자열에 섞이면 임의의 코드가 실행됩니다. 코드 주입 공격의 통로가 됩니다.
- 성능: 호출할 때마다 문자열을 파싱하므로 선언문·표현식보다 비효율적이고 엔진이 미리 분석하기도 어렵습니다.
- 환경 제약: 콘텐츠 보안 정책(CSP)으로 문자열 코드 실행을 막은 페이지에서는 거부됩니다.

선언문·표현식·화살표 함수로 만든 함수도 모두 `Function`의 인스턴스입니다. `(function () {}) instanceof Function`은 `true`입니다(17편).

## 화살표 함수 개요

화살표 함수(arrow function)는 ES2015에서 추가된 함수 표현식의 축약 표기입니다. `function` 키워드 대신 `=>`를 씁니다.

```js
const add = (x, y) => x + y
add(1, 2) // 3
```

| 매개변수 | 괄호 | 예 |
|----------|------|----|
| 없음 | 필요 | `() => 1` |
| 단순 이름 하나 | 생략 가능 | `x => x * 2` |
| 둘 이상 | 필요 | `(a, b) => a + b` |
| 기본값·나머지·구조 분해 | 필요 | `(a = 1) => a` |

- 몸체가 표현식 하나이면 중괄호를 생략하고, 그 값이 곧 반환값입니다.
- 중괄호를 쓰면 블록이므로 `return`을 직접 써야 합니다. 없으면 `undefined`를 반환합니다.
- 객체 리터럴을 바로 반환하려면 괄호로 감쌉니다. 감싸지 않으면 중괄호가 블록으로 해석됩니다.

```js
const f = () => { a: 1 }   // 블록 안의 라벨 문. 반환값 undefined
const g = () => ({ a: 1 }) // { a: 1 }
```

- `=>` 앞에서는 줄을 바꿀 수 없습니다. 바꾸면 SyntaxError입니다.
- 항상 표현식입니다. 선언문 형태가 없고 이름은 추론으로만 붙습니다.

일반 함수와 다른 점의 개요는 다음과 같습니다.

| 항목 | 일반 함수 | 화살표 함수 |
|------|-----------|-------------|
| `this` | 호출 방식에 따라 결정 | 바깥 스코프의 `this`를 그대로 사용 |
| `arguments` | 있음 | 없음(바깥 함수의 것을 참조) |
| `new`로 호출 | 가능 | TypeError |
| `prototype` 프로퍼티 | 있음 | 없음 |
| 매개변수 이름 중복 | 비엄격 모드에서 가능 | SyntaxError |

`this`는 21편, 생성자 호출은 15편, 화살표 함수의 세부 규칙과 사용 시 주의점은 27편에서 다룹니다.

## 함수 호출

함수 호출은 함수 값 뒤에 호출 연산자 `()`와 인수 목록을 붙여 몸체를 실행하는 것입니다. 호출식의 값은 반환값입니다.

```js
function greet() { return 'hi' }

greet   // 함수 객체 자체. 실행되지 않는다
greet() // 'hi'
```

호출은 다음 순서로 진행됩니다.

1. 호출할 함수 식을 평가합니다.
2. 인수를 왼쪽에서 오른쪽 순서로 평가합니다.
3. 함수 실행 컨텍스트를 만들어 호출 스택에 쌓고 몸체를 실행합니다(22편).
4. 반환값을 호출 지점에 돌려주고 컨텍스트를 스택에서 제거합니다.

호출할 수 없는 값에 `()`를 붙이면 TypeError입니다.

```js
const n = 1
n() // TypeError: n is not a function
```

호출 방식은 `this`를 결정합니다(자세히는 21편).

| 방식 | 예 | `this` |
|------|----|--------|
| 일반 함수 호출 | `f()` | 비엄격 모드는 전역 객체, strict mode는 `undefined` |
| 메서드 호출 | `obj.f()` | `obj` |
| 생성자 호출 | `new F()` | 새로 만든 인스턴스 |
| 간접 호출 | `f.call(x)`, `f.apply(x)` | `x` |

- 선택적 호출 `?.()`(ES2020)는 대상이 `null`이나 `undefined`이면 호출하지 않고 `undefined`를 반환합니다. 함수가 아닌 다른 값이면 여전히 TypeError입니다.
- 인수 목록과 매개변수 목록 끝의 후행 쉼표 `f(a, b,)`는 ES2017부터 허용됩니다.

```js
let cb
cb?.() // undefined: 에러 없음
```

## 매개변수와 인수

매개변수는 함수 정의에서 괄호 안에 적은 이름이고, 인수는 호출할 때 괄호 안에 넘기는 값입니다. 인수는 위치 순서대로 매개변수에 할당됩니다.

매개변수는 함수가 호출될 때마다 새로 만들어지는 지역 변수입니다. 몸체 밖에서는 보이지 않습니다.

```js
function add(x, y) { return x + y }
x // ReferenceError: x is not defined
```

인수와 매개변수의 개수가 달라도 에러가 아닙니다.

| 상황 | 결과 |
|------|------|
| 인수가 매개변수보다 적음 | 넘기지 않은 매개변수는 `undefined` |
| 인수가 매개변수보다 많음 | 초과 인수는 매개변수에 담기지 않음 |

```js
function pair(x, y) { return [x, y] }
pair(1)       // [1, undefined]
pair(1, 2, 3) // [1, 2]: 3은 어느 매개변수에도 담기지 않는다
```

- 초과 인수는 일반 함수 안의 유사 배열 객체 `arguments`로 읽거나, 나머지 매개변수 `...rest`로 배열에 받습니다(자세히는 16편, 27편).
- 매개변수 이름 중복은 비엄격 모드의 단순 매개변수 목록에서만 허용되고, 이때는 마지막 인수가 값이 됩니다. strict mode, 화살표 함수, 기본값·나머지·구조 분해가 있는 목록에서는 SyntaxError입니다.
- 매개변수에는 타입 선언이 없습니다. 어떤 타입의 인수든 들어옵니다(다음 절).
- 인수는 항상 값으로 전달됩니다. 객체를 넘길 때 무엇이 복사되는지는 "참조 전달과 외부 상태 변경"에서 다룹니다.
- 매개변수가 많으면 호출할 때 순서를 틀리기 쉽습니다. 객체 하나로 받아 구조 분해하는 방식을 씁니다(37편).

## 인수 확인과 기본값

JavaScript는 호출할 때 인수의 개수와 타입을 검사하지 않습니다. 인수가 빠지면 `undefined`가 들어가고, 이 값이 연산에 쓰이면 에러 없이 틀린 결과가 나옵니다.

```js
function add(x, y) { return x + y }
add(1)      // NaN: 1 + undefined
add(1, '2') // '12': 문자열 연결
```

### 인수 확인

함수 안에서 직접 검사하고, 잘못된 인수는 예외로 알립니다.

```js
function add(x, y) {
  if (typeof x !== 'number' || typeof y !== 'number') {
    throw new TypeError('숫자만 받습니다')
  }
  return x + y
}
add(1, '2') // TypeError
```

| 확인하려는 것 | 도구 |
|---------------|------|
| 원시 타입 | `typeof` (05편) |
| 유한한 숫자 | `Number.isFinite(x)`. `NaN`도 `typeof`는 `'number'`이므로 더 엄격함 |
| 배열 | `Array.isArray(x)` |
| 특정 생성자의 인스턴스 | `x instanceof C` (17편) |

### 기본 매개변수

기본 매개변수(default parameter, ES2015)는 인수가 없거나 `undefined`일 때 쓰는 값을 매개변수에 지정합니다.

```js
function f(x = 10) { return x }
f()          // 10
f(undefined) // 10
f(null)      // null: undefined가 아니므로 기본값 미사용
f(0)         // 0
f('')        // ''
```

- 단축 평가 방식 `x = x || 10`은 `0`, `''`, `false`, `null`까지 기본값으로 바꿉니다. `f(0)`이 `10`이 되는 버그의 원인입니다. `??`(ES2020)는 `null`과 `undefined`만 대체합니다(08편).
- 기본값 식은 호출할 때마다 평가됩니다. 인수가 주어지면 평가되지 않습니다.

```js
function f(list = []) { list.push(1); return list }
f() // [1]
f() // [1]: 호출마다 새 배열
```

- 앞쪽 매개변수는 뒤쪽 기본값 식에서 쓸 수 있습니다. 뒤쪽 매개변수를 앞쪽 기본값에서 쓰면 TDZ 때문에 ReferenceError입니다.

```js
function f(a, b = a * 2) { return [a, b] }
f(1) // [1, 2]

function g(a = b, b = 1) { return a }
g()  // ReferenceError: Cannot access 'b' ...
```

- 필수 인수는 기본값 자리에서 예외를 던지는 함수를 호출해 강제할 수 있습니다.

```js
const required = (n) => { throw new TypeError(`${n} 필요`) }
function f(x = required('x')) { return x }
f()  // TypeError: x 필요
f(5) // 5: 기본값 식이 평가되지 않음
```

- 기본값이 있는 매개변수 뒤에 기본값 없는 매개변수가 올 수 있지만, 앞 인수를 건너뛰려면 `undefined`를 명시해야 합니다. 기본값 매개변수는 맨 뒤에 두는 것이 관례입니다.
- "인수를 넘기지 않음"과 "`undefined`를 넘김"은 기본값만으로는 구별되지 않습니다. 둘 다 기본값이 쓰입니다.
- 기본값이나 나머지·구조 분해가 있는 함수의 몸체에는 `'use strict'` 지시문을 쓸 수 없습니다(SyntaxError). 매개변수 스코프와 `length`에 미치는 영향은 27편에서 다룹니다.

## 반환문

`return` 문은 함수 실행을 즉시 끝내고 값을 호출 지점으로 돌려줍니다. 그 뒤의 코드는 실행되지 않습니다.

```js
function f() {
  return 1
  console.log('x') // 실행되지 않는다
}
f() // 1
```

- `return` 뒤에 식이 없거나, `return` 문이 없거나, 실행되지 않고 끝나면 반환값은 `undefined`입니다.
- 반환값은 하나뿐입니다. 여러 값은 배열이나 객체로 묶어 반환합니다.
- `return`은 함수 몸체 안에서만 쓸 수 있습니다. 스크립트와 ES 모듈의 최상위에서는 SyntaxError입니다.
- 조건에 맞지 않는 경우를 먼저 `return`으로 빠져나가면 중첩이 줄어듭니다.

```js
function parse(s) {
  if (typeof s !== 'string') return null // 조기 반환
  return s.trim()
}
```

- 생성자 호출(`new`)에서 `return`이 객체를 반환하면 그 객체가 결과이고, 원시 값은 무시됩니다(자세히는 15편).
- 화살표 함수의 표현식 몸체는 `return` 없이 값을 반환합니다(화살표 함수 개요).

### return과 ASI

`return` 바로 뒤에서 줄을 바꾸면 세미콜론 자동 삽입(ASI)이 `return;`으로 해석합니다. 다음 줄의 식은 도달하지 않는 코드가 되고 함수는 `undefined`를 반환합니다. ASI의 일반 규칙은 04편에서 다룹니다.

```js
function f() {
  return
    1 + 2
}
f() // undefined: return; 으로 해석됨

function g() {
  return (
    1 + 2
  )
}
g() // 3: 여는 괄호가 같은 줄에 있어 이어진다
```

반환할 값은 `return`과 같은 줄에서 시작합니다. 객체 리터럴이면 여는 중괄호를, 여러 줄 식이면 여는 괄호를 같은 줄에 둡니다.

`return`처럼 줄바꿈을 허용하지 않는 지점(제한 생성)이 더 있습니다.

| 위치 | 줄을 바꾸면 |
|------|-------------|
| `return` 뒤 | `return;`으로 해석 |
| `break`·`continue` 뒤 | 라벨이 별개의 문으로 분리 |
| `throw` 뒤 | SyntaxError |
| `yield` 뒤 | 값 없는 `yield` 다음에 별개의 문 |
| 후위 `++`·`--` 앞 | 다음 줄의 전위 연산으로 해석 |
| 화살표 `=>` 앞 | SyntaxError |
| `async` 뒤 | 식별자 `async`와 별개의 문 |

## 참조 전달과 외부 상태 변경

인수는 항상 값으로 복사되어 전달됩니다. 객체의 경우 복사되는 값이 객체를 가리키는 참조여서, 호출자의 변수와 매개변수가 같은 객체를 가리킵니다(공유에 의한 전달). 값에 의한 전달과 참조에 의한 전달의 구분은 10편에서 다룹니다.

원시 값은 값이 복사되므로 함수 안의 변경이 호출자에게 닿지 않습니다.

```js
function inc(n) { n++; return n }
let a = 1
inc(a) // 2
a      // 1
```

객체는 프로퍼티를 바꾸면 호출자의 객체가 바뀝니다.

```js
function rename(user) { user.name = 'Kim' }
const u = { name: 'Lee' }
rename(u)
u.name // 'Kim': 외부 객체가 변경됨
```

매개변수에 새 값을 재할당하면 지역 변수가 가리키는 대상만 바뀌므로 호출자에게 영향이 없습니다.

```js
function reset(user) { user = { name: 'new' } }
reset(u)
u.name // 'Kim': 호출자의 변수는 그대로
```

| 동작 | 호출자에게 보임 |
|------|----------------|
| 원시 값 인수를 함수 안에서 수정 | 아니오 |
| 객체 인수의 프로퍼티·요소를 수정(변경) | 예 |
| 매개변수에 다른 값을 재할당 | 아니오 |

함수가 반환값 외에 바깥에 영향을 주는 것을 부수 효과(side effect)라고 합니다. 인수로 받은 객체의 변경, 외부 변수의 읽기·쓰기가 대표적입니다.

```js
let count = 0
function inc() { count++ } // 외부 변수를 변경
inc()
count // 1
```

부수 효과를 피하려면 인수를 바꾸지 않고 복사본을 만들어 반환합니다. 스프레드(36편)로 얕은 복사를 합니다.

```js
const rename = (user) => ({ ...user, name: 'Kim' })
const next = rename(u)
u.name    // 'Lee': 원본 그대로
next.name // 'Kim'
```

- 얕은 복사는 한 단계만 복사합니다. 중첩된 객체나 배열은 원본과 공유되므로 복사본에서 바꾸면 원본도 바뀝니다. 깊은 복사와 방어적 복사는 10편, 동결은 14편에서 다룹니다.
- `const`로 선언한 객체도 내부는 바꿀 수 있습니다. `const`는 재할당만 막습니다(13편).
- 배열의 `push`, `sort`, `reverse`, `splice`는 원본을 변경합니다(29편).

## IIFE

IIFE(Immediately Invoked Function Expression)는 정의하자마자 한 번 호출하는 함수 표현식입니다.

```js
(function () {})();   // 호출을 괄호 밖에
(function () {}());   // 호출을 괄호 안에
(() => {})();         // 화살표 함수
!function () {}();    // 단항 연산자로 표현식을 만든다
void function () {}() // 결과를 버린다
```

괄호가 필요한 이유는 문의 맨 앞에 오는 `function`이 선언문으로 파싱되기 때문입니다. 괄호는 그룹 연산자여서 안쪽이 항상 표현식으로 파싱되고, `!`·`void` 같은 단항 연산자도 같은 효과를 냅니다.

```js
function () {}()      // SyntaxError: 선언문에는 이름이 필수
function foo() {}()   // SyntaxError: 선언문 뒤의 빈 괄호
function foo() {}(1)  // 오류 없음: 선언문 뒤에 별개의 식 (1)
```

마지막 줄은 IIFE가 아닙니다. 선언문이 끝난 뒤 `(1)`이라는 독립된 식이 이어진 것이고, 함수는 호출되지 않습니다.

쓰임새는 세 가지입니다.

- 변수 격리: IIFE 안의 변수는 바깥에서 보이지 않아 전역 변수 오염을 막습니다(자세히는 13편).
- 초기화 결과를 `const`에 담기: 여러 줄이 필요한 계산을 한 식으로 만듭니다.
- async IIFE: 모듈이 아닌 스크립트(CommonJS 포함)에서는 최상위 `await`를 쓸 수 없으므로 `(async () => { ... })()`로 감쌉니다. 최상위 await는 ES2022부터 ES 모듈에서 가능합니다.

```js
const config = (() => {
  const env = 'prod'
  return { env }
})()
config.env // 'prod'
```

변수 격리 목적은 `let`·`const`의 블록 스코프와 ES 모듈(45편)이 대체했습니다. 임시 변수만 감추려면 `{ const tmp = 1 }` 블록으로 충분합니다.

흔한 실수는 앞 줄에 세미콜론이 없는 경우입니다. 괄호가 앞 줄의 식에 이어져 호출로 해석됩니다.

```js
const a = 1
(function () {})() // TypeError: 1 is not a function
```

이 코드는 `1(function () {})()`로 파싱됩니다. 앞 줄을 세미콜론으로 끝내거나 IIFE 앞에 `;`를 붙입니다.

## 재귀

재귀 함수(recursive function)는 자기 자신을 호출하는 함수입니다. 종료 조건과, 문제를 더 작게 줄여 자신을 호출하는 부분으로 구성됩니다.

```js
function factorial(n) {
  if (n <= 1) return 1        // 종료 조건
  return n * factorial(n - 1) // 더 작은 문제로 재귀 호출
}
factorial(3)
// 3 * factorial(2)
// 3 * (2 * factorial(1))
// 3 * (2 * 1) → 6
```

- 각 호출은 독립된 실행 컨텍스트와 지역 변수를 가집니다. 안쪽 호출이 반환되어야 바깥 호출이 계산을 이어 가므로, 호출 스택에 쌓였다가 거꾸로 풀립니다.
- 종료 조건이 없거나 도달하지 못하면 호출이 끝없이 쌓여 RangeError가 납니다(아래 절).
- 자기 자신을 가리키는 이름은 선언문이면 함수 이름, 함수 표현식이면 기명 함수 표현식의 이름이 안전합니다. 화살표 함수는 변수 이름을 씁니다. 호출 시점에는 변수가 이미 초기화되어 있어 동작합니다.
- 재귀는 트리, 중첩 배열처럼 구조 자체가 재귀적인 데이터에 자연스럽습니다.

```js
function depth(v) {
  if (!Array.isArray(v)) return 0
  return 1 + Math.max(0, ...v.map(depth))
}
depth([1, [2, [3]]]) // 3
```

같은 계산을 반복하는 재귀는 호출 수가 급증합니다. 피보나치 수의 단순 재귀가 대표적입니다.

```js
function fib(n) {
  return n < 2 ? n : fib(n - 1) + fib(n - 2)
}
fib(10) // 55: 호출 177번
fib(30) // 832040: 호출 2,692,537번
```

해결책은 계산 결과를 저장해 두는 메모이제이션(클로저를 활용, 23편)이나 반복문으로의 변환입니다.

### 재귀 깊이 한계

함수를 호출할 때마다 호출 스택에 프레임이 쌓이고 스택 크기는 유한합니다. 한도를 넘으면 RangeError가 발생합니다. V8의 메시지는 `Maximum call stack size exceeded`이고, 엔진마다 문구가 다릅니다.

- 한도는 명세가 정하지 않습니다. 엔진, 스택 크기 설정, 프레임 크기(인수와 지역 변수 수)에 따라 달라집니다.
- Node.js 24(V8)에서 직접 측정하면 인수 없는 단순 함수는 약 12,500번, 인수 5개를 받는 함수는 약 6,200번에서 멈췄습니다. 환경마다 값이 다르므로 기준으로 삼지 않습니다.
- 위의 `factorial(100000)`처럼 깊이가 10만인 재귀는 대부분의 환경에서 RangeError입니다.
- 스택 오버플로의 구조는 22편에서 다룹니다.

깊이가 큰 입력에는 반복문으로 바꿉니다.

```js
function factorial(n) {
  let result = 1
  for (let i = 2; i <= n; i++) result *= i
  return result
}
```

트리 탐색처럼 재귀 구조가 필요한 경우에는 배열을 명시적 스택으로 두고 반복문으로 처리합니다.

꼬리 호출은 함수의 마지막 동작이 다른 함수 호출이고 그 반환값을 그대로 돌려주는 호출입니다. `return n * factorial(n - 1)`은 호출 뒤에 곱셈이 남아 꼬리 호출이 아니고, `return fact(n - 1, acc * n)`은 꼬리 호출입니다. ES2015 명세는 strict mode에서 꼬리 위치의 호출이 스택을 쌓지 않도록(proper tail calls) 정의합니다. 그러나 주요 엔진 중 Safari의 JavaScriptCore만 구현했고, V8은 디버깅 정보가 사라진다는 이유로 기본 활성화하지 않았습니다. 꼬리 호출 형태로 바꿔도 다른 엔진에서는 깊이 한계가 그대로이므로 의존하지 않습니다.

## 중첩 함수

중첩 함수(nested function)는 다른 함수의 몸체 안에 정의된 함수입니다. 감싸는 함수를 외부 함수라고 합니다.

```js
function outer() {
  const msg = 'hi'
  function inner() { return msg } // 바깥 변수를 읽는다
  return inner()
}
outer() // 'hi'
inner() // ReferenceError: 바깥에서는 보이지 않는다
```

- 중첩 함수는 외부 함수의 변수와 매개변수를 읽고 쓸 수 있습니다. 반대로 외부 함수는 중첩 함수 안의 변수를 볼 수 없습니다. 이름을 찾는 규칙은 스코프 체인입니다(12편).
- 외부 함수가 호출될 때마다 중첩 함수는 새 객체로 만들어집니다.
- 외부 함수가 끝난 뒤에도 중첩 함수가 살아 있으면 외부 변수를 계속 참조합니다. 이것이 클로저입니다(23편).
- 중첩 함수를 일반 함수로 호출하면 `this`가 외부 메서드의 `this`와 달라집니다. 화살표 함수로 해결합니다(21편, 27편).
- 한 함수에서만 쓰는 보조 함수를 안에 두면 바깥에 노출되지 않고, 외부 변수를 인수 없이 공유할 수 있습니다.
- 몸체 최상위에 선언문으로 둔 중첩 함수는 호이스팅되어 호출이 앞에 있어도 됩니다. 블록 안 선언문은 함수 호이스팅의 "블록 안 함수 선언" 규칙을 따릅니다.

## 콜백과 고차 함수

콜백 함수(callback function)는 다른 함수의 인수로 전달되어 그 함수 안에서 호출되는 함수입니다. 고차 함수(higher-order function)는 함수를 인수로 받거나 함수를 반환하는 함수입니다.

```js
function repeat(n, fn) {
  for (let i = 0; i < n; i++) fn(i)
}
repeat(3, (i) => console.log(i)) // 0, 1, 2 순서로 출력
```

`repeat`가 고차 함수이고 화살표 함수가 콜백입니다. 함수가 값(일급 객체)이어서 가능한 구조입니다(16편).

| 종류 | 실행 시점 | 예 |
|------|-----------|----|
| 동기 콜백 | 고차 함수가 끝나기 전, 필요한 때마다 즉시 | `map`, `filter`, `forEach`, `sort` (29편) |
| 비동기 콜백 | 나중에 이벤트가 일어났을 때 | 타이머, 이벤트 핸들러 (40편) |

함수를 반환하는 고차 함수는 인수를 기억하는 새 함수를 만듭니다. 기억은 클로저가 합니다(23편).

```js
const multiplyBy = (n) => (x) => x * n
const double = multiplyBy(2)
double(5) // 10
```

콜백을 어떤 인수로 호출할지는 고차 함수가 정합니다. 배열의 `map`은 콜백에 요소, 인덱스, 배열을 넘기므로 콜백이 매개변수를 더 받으면 의도하지 않은 값이 들어옵니다.

```js
const s = ['1', '2', '3']
s.map(parseInt) // [1, NaN, NaN]
// parseInt('1', 0), parseInt('2', 1), parseInt('3', 2)
s.map(Number)   // [1, 2, 3]
```

`parseInt`의 두 번째 매개변수는 진법이어서 인덱스가 진법으로 쓰입니다. 진법 0은 기본값(10진법)으로 취급되어 `1`이 되고, 진법 1은 유효하지 않아 `NaN`이며, 진법 2에서는 숫자 `3`이 올 수 없어 `NaN`입니다.

콜백 이름 뒤에 괄호를 붙이면 콜백이 아니라 호출 결과를 넘깁니다.

```js
const inc = (n) => n + 1
const list = [1, 2]
list.map(inc)   // [2, 3]
list.map(inc()) // TypeError: inc()의 결과 NaN은 함수가 아님
```

- 함수가 아닌 값을 콜백으로 넘기면 고차 함수가 호출하는 시점에 TypeError입니다.
- 메서드를 콜백으로 넘기면 호출 방식이 바뀌어 `this`를 잃습니다(21편).
- 비동기 콜백을 중첩하면 코드가 깊어집니다. 프로미스가 해결책입니다(41편).
- 함수를 조합해 새 함수를 만드는 기법은 50편에서 다룹니다.

## 순수·비순수 함수

순수 함수(pure function)는 같은 인수에 항상 같은 값을 반환하고, 반환값 외에 바깥에 관찰되는 변화(부수 효과)를 일으키지 않는 함수입니다. 이 둘 중 하나라도 어기면 비순수 함수입니다.

```js
const add = (a, b) => a + b // 순수

let rate = 2
const scale = (n) => n * rate // 비순수: 외부 변수에 의존
scale(10) // 20
rate = 3
scale(10) // 30: 같은 인수인데 결과가 다름

const push = (arr) => arr.push(1) // 비순수: 인수를 변경
```

| 비순수의 원인 | 예 |
|---------------|----|
| 외부 변수의 읽기·쓰기 | `count++`, 위의 `rate` |
| 인수로 받은 객체의 변경 | `user.name = 'Kim'`, `arr.push(1)` |
| 입출력 | `console.log`, DOM, 네트워크, 파일 |
| 실행할 때마다 달라지는 값 | `Math.random()`, `Date.now()` |

순수 함수의 이점은 다음과 같습니다.

- 입력과 출력만 비교하면 되므로 테스트가 쉽습니다.
- 같은 인수의 결과를 저장해 재사용(메모이제이션)해도 안전합니다.
- 호출 순서와 횟수가 결과에 영향을 주지 않아 코드를 읽고 추론하기 쉽습니다.

입출력이 없는 프로그램은 없으므로 모든 함수를 순수하게 만들 수는 없습니다. 핵심 계산은 순수 함수로 두고 입출력은 바깥 가장자리에 모으는 방식을 씁니다(50편).

순수 함수를 만들려면 인수를 바꾸지 않고 새 값을 반환합니다. `sort`는 원본 배열을 변경하는 비순수 함수이고, ES2023의 `toSorted`는 정렬된 사본을 반환합니다(29편).

## 핵심 정리

- 함수 선언문은 스코프 진입 시 이름과 함수 객체가 모두 준비되어 정의 앞에서도 호출됩니다. 함수 표현식은 변수 규칙을 따라 `var`면 TypeError, `let`·`const`면 ReferenceError입니다.
- 매개변수와 인수의 개수·타입은 검사되지 않습니다. 기본값은 인수가 `undefined`일 때만 쓰입니다.
- 객체 인수는 참조가 복사되므로 프로퍼티 수정은 호출자에게 보이고, 매개변수 재할당은 보이지 않습니다.
- `return` 뒤에서 줄을 바꾸면 `return;`이 되어 `undefined`를 반환합니다.
- 재귀는 종료 조건이 필요하고 깊이는 호출 스택 크기로 제한됩니다. 꼬리 호출 최적화는 기대할 수 없습니다.
- 콜백은 인수로 넘기는 함수이고, 순수 함수는 같은 입력에 같은 출력을 내며 부수 효과가 없는 함수입니다.
