## 산술 연산자

산술 연산자는 피연산자(operand, 연산 대상 값) 두 개를 계산해 숫자를 돌려주는 이항(binary) 연산자입니다.

| 연산자 | 이름 | 예 | 결과 |
|--------|------|----|------|
| `+` | 덧셈 | `7 + 2` | `9` |
| `-` | 뺄셈 | `7 - 2` | `5` |
| `*` | 곱셈 | `7 * 2` | `14` |
| `/` | 나눗셈 | `7 / 2` | `3.5` |
| `%` | 나머지 | `7 % 2` | `1` |

거듭제곱 `**`은 아래 지수 연산자 절에서 다룹니다.

- 자바스크립트에는 정수 나눗셈이 없습니다. 정수 몫이 필요하면 `Math.trunc(7 / 2)`처럼 소수부를 버립니다(자세히는 30편).
- Number는 64비트 부동소수점이라 이진수로 정확히 표현할 수 없는 소수에 오차가 있습니다. `0.1 + 0.2`는 `0.30000000000000004`입니다(자세히는 05편).
- 0으로 나눠도 예외가 나지 않고 특수 값이 나옵니다.

```js
1 / 0                // Infinity
-1 / 0               // -Infinity
0 / 0                // NaN
Infinity - Infinity  // NaN
Infinity * 0         // NaN
```

피연산자에 `NaN`이 하나라도 있으면 결과는 `NaN`입니다.

### 피연산자의 숫자 변환

`-`, `*`, `/`, `%`, `**`와 단항 `+`·`-`는 피연산자를 먼저 숫자로 바꿉니다. 객체는 원시값으로 바꾼 뒤 숫자로 바꿉니다(자세히는 08편).

| 피연산자 | 숫자 변환 결과 |
|----------|----------------|
| `undefined`, `'12px'`, `{}`, `[1, 2]` | `NaN` |
| `null`, `false`, `''`, `[]` | `0` |
| `true` | `1` |
| `'12'`, `' 12 '`, `[12]` | `12` |
| `'0x10'`, `'1e3'`, `'Infinity'` | `16`, `1000`, `Infinity` |
| `Symbol()` | TypeError |

문자열은 앞뒤 공백을 지운 뒤 숫자 리터럴로 해석합니다. 빈 문자열은 `0`, 해석할 수 없으면 `NaN`입니다. 문자열 중간의 공백(`'1 2'`), 숫자 구분자(`'1_000'`), 단위(`'12px'`)가 있어도 `NaN`입니다.

```js
'6' / '2'      // 3
'a' * 2        // NaN
null * 5       // 0
undefined * 5  // NaN
```

### BigInt 연산

BigInt끼리의 산술 결과는 BigInt입니다. BigInt와 Number를 섞으면 TypeError이므로 한쪽을 명시적으로 변환해야 합니다(`BigInt(1)`, `Number(1n)`).

```js
7n / 2n    // 3n  (0 방향으로 버림)
-7n / 2n   // -3n
1n / 0n    // RangeError
1n + 1     // TypeError (BigInt와 Number 혼합)
```

### 나머지 연산의 부호

`%` 결과의 부호는 왼쪽 피연산자(피제수)를 따릅니다. 오른쪽 피연산자의 부호는 결과에 영향이 없습니다. 수학의 모듈로와 달리 음수가 나올 수 있습니다.

```js
 7 %  3   //  1
-7 %  3   // -1
 7 % -3   //  1
-7 % -3   // -1
```

$$
a \% b = a - \operatorname{trunc}(a / b) \times b
$$

- `a`: 피제수(왼쪽 값)
- `b`: 제수(오른쪽 값)
- `trunc`: 소수부를 0 방향으로 버리는 함수

`-7 % 3`은 `-7 - trunc(-7 / 3) * 3`이고, `trunc(-2.33...)`이 `-2`이므로 `-7 - (-6) = -1`입니다.

그 밖의 경계 조건입니다.

| 식 | 결과 | 이유 |
|----|------|------|
| `5 % 0` | `NaN` | 제수가 0 |
| `Infinity % 5` | `NaN` | 피제수가 무한대 |
| `5 % Infinity` | `5` | 제수가 무한대면 피제수 그대로 |
| `5.5 % 2` | `1.5` | 소수에도 적용 |
| `-4 % 2` | `-0` | 피제수가 음수이고 나머지가 0 |

BigInt의 `%`도 같은 부호 규칙을 따릅니다(`-7n % 3n`은 `-1n`).

음수에서도 0 이상의 나머지가 필요하면(배열 인덱스 순환 등) 제수를 더한 뒤 한 번 더 나눕니다.

```js
((-7 % 3) + 3) % 3   // 2
```

흔한 실수는 홀수 판별입니다. `-3 % 2`는 `-1`이므로 `n % 2 === 1`은 음의 홀수에서 거짓입니다. `n % 2 !== 0`을 씁니다.

## 단항 + 와 -

단항(unary) 연산자는 피연산자가 하나인 연산자입니다. 피연산자가 둘이면 이항, 셋이면 삼항이며 삼항 연산자는 `?:` 하나뿐입니다.

- 단항 `+x`는 `x`를 숫자로 변환합니다. 숫자로 바꾸는 가장 짧은 방법입니다.
- 단항 `-x`는 `x`를 숫자로 변환한 뒤 부호를 뒤집습니다.

```js
+'42'        // 42
+''          // 0
+'12px'      // NaN
+true        // 1
+null        // 0
+undefined   // NaN
+[]          // 0
+new Date()  // 현재 시각(밀리초 타임스탬프)
```

- `+x`는 `Number(x)`와 결과가 같지만 BigInt에서 갈립니다. `Number(1n)`은 `1`이고 `+1n`은 TypeError입니다. 반면 `-1n`은 `-1n`으로 정상 동작합니다.
- `-null`과 `0 * -1`처럼 결과가 0이 되는 음수 연산은 `-0`을 만듭니다(자세히는 아래 Object.is 절).

연속된 기호는 공백으로 구분해야 합니다. `++`와 `--`는 한 토큰이라 붙여 쓰면 증감 연산자로 읽힙니다.

```js
1 + + '2'   // 3   (이항 + 와 단항 +)
5 - -2      // 7
x+++y       // (x++) + y
--1         // SyntaxError (--는 감소 연산자)
```

## 증가·감소 연산자

`++`와 `--`는 피연산자를 숫자로 바꿔 1을 더하거나 뺀 값을 같은 변수에 저장하는 연산자입니다. 피연산자는 변수나 프로퍼티처럼 값을 저장할 수 있는 대상이어야 합니다.

| 형태 | 이름 | 식의 값 | 변수의 새 값 |
|------|------|---------|--------------|
| `++x` | 전위 | 증가한 새 값 | `x + 1` |
| `x++` | 후위 | 증가하기 전 값 | `x + 1` |

감소 `--`도 같은 방식입니다.

```js
let a = 1
a++   // 1  (a는 2)
++a   // 3  (a는 3)
a--   // 3  (a는 2)
--a   // 1  (a는 1)
```

- 후위가 돌려주는 값은 증가 전 값을 **숫자로 변환한 것**입니다.

```js
let s = '5'
const old = s++   // old는 숫자 5 (문자열 '5'가 아님)
// s는 6
```

- 변환 규칙은 단항 `+`와 같습니다. `null++`은 `1`을 저장하고, `undefined++`와 `'a'++`는 `NaN`을 저장합니다. BigInt는 BigInt로 유지됩니다(`1n`에 `++` 하면 `2n`).
- 프로퍼티와 요소에도 쓸 수 있습니다. 없는 프로퍼티에 쓰면 `undefined`가 `NaN`이 됩니다.

```js
const o = { n: 1 }
o.n++       // o.n은 2
const t = {}
t.count++   // t.count는 NaN
```

- 대상이 될 수 없는 피연산자는 오류입니다. `5++`는 SyntaxError, `const` 변수는 TypeError입니다.
- 독립된 문장에서는 전위와 후위의 결과가 같습니다. 식의 값을 쓸 때만 차이가 납니다.
- 후위 연산자는 피연산자와 같은 줄에 써야 합니다. 줄을 바꾸면 세미콜론이 자동으로 들어가 뒤의 식에 대한 전위 연산으로 읽힙니다.

```js
let a = 1, b = 5
a
++b   // a; ++b 로 해석 → a는 1, b는 6
```

흔한 실수는 같은 변수에 후위 증가와 대입을 함께 쓰는 것입니다.

```js
let i = 1
i = i++   // i는 1 (증가 결과를 증가 전 값이 덮어씀)
```

`i++`가 `i`를 2로 바꾸지만, 식의 값인 `1`이 다시 `i`에 대입되기 때문입니다. 한 식 안에서 같은 변수에 `++`를 여러 번 쓰는 것도 피합니다. `i`가 1일 때 `i++ + ++i`는 `1 + 3`으로 `4`이고 `i`는 3이 됩니다.

## 문자열 연결

`+`는 피연산자 중 하나라도 문자열이면 덧셈이 아니라 문자열 연결을 합니다. 다른 산술 연산자는 연결 기능이 없습니다.

`+`의 처리 순서는 다음과 같습니다.

1. 두 피연산자를 원시값으로 바꿉니다(객체는 `valueOf()`·`toString()`을 호출해 원시값이 됩니다. 자세히는 08편).
2. 한쪽이라도 문자열이면 다른 쪽도 문자열로 바꿔 이어 붙입니다.
3. 아니면 둘 다 숫자(BigInt)로 바꿔 더합니다.

```js
'1' + 2        // '12'
1 + '2'        // '12'
1 + 2 + '3'    // '33'   ((1 + 2) + '3')
'1' + 2 + 3    // '123'  (('1' + 2) + 3)
'3' - 1        // 2      (- 는 항상 숫자 연산)
```

`+`는 왼쪽 결합이라 왼쪽부터 하나씩 계산하므로, 문자열이 처음 나온 위치에 따라 결과가 달라집니다.

문자열로 바뀌는 방식은 값마다 다릅니다.

```js
'a' + null       // 'anull'
'a' + undefined  // 'aundefined'
'a' + [1, 2]     // 'a1,2'
'a' + {}         // 'a[object Object]'
'a' + 1n         // 'a1'
'a' + Symbol()   // TypeError
```

원시값으로 바꾼 결과에 문자열이 없으면 숫자 덧셈입니다.

```js
null + 1          // 1
undefined + 1     // NaN
true + true       // 2
```

문자열 여부는 객체가 원시값으로 바뀐 뒤에 판단합니다. 배열은 문자열로 바뀌므로 숫자끼리 더하는 것처럼 보여도 연결이 됩니다.

```js
[] + []           // ''      (둘 다 '' 로 바뀌어 연결)
[1, 2] + [3]      // '1,23'  ('1,2' + '3')
```

### Date와 변환 순서

Date 객체는 `+`에서 문자열로 변환되는 것이 기본입니다. 그래서 `new Date() + 1`은 날짜 문자열 뒤에 `1`이 붙은 문자열이고, `new Date() - 1`은 숫자입니다.

`valueOf()`와 `toString()`을 모두 가진 객체는 변환하는 곳에 따라 호출 순서가 다릅니다.

```js
const o = {
  valueOf() { return 1 },
  toString() { return 'S' },
}
o + ''     // '1'  (valueOf가 먼저)
`${o}`     // 'S'  (toString이 먼저)
String(o)  // 'S'
o * 2      // 2
```

### 흔한 실수

- 입력 필드 값처럼 외부에서 받은 값은 문자열인 경우가 많습니다. `'10' + 5`는 `'105'`입니다. 계산 전에 `Number()`로 바꿉니다.
- `s += 1`은 `s = s + 1`이므로 `s`가 문자열이면 연결입니다. `-=`는 항상 숫자 연산입니다(`'5'`에 `-= 1` 하면 `4`).
- 여러 값을 조합하는 문자열은 템플릿 리터럴(`${}`)이 `+` 연결보다 의도가 분명합니다.

## 할당 연산자

`=`는 오른쪽 값을 왼쪽 대상에 저장하며, 식 전체의 값은 저장한 값입니다. 오른쪽 결합이라 연쇄 대입이 가능합니다.

```js
let a, b, c
a = b = c = 0   // c = 0 → b = 0 → a = 0
console.log(a = 5)   // 5
```

- 왼쪽은 변수, 프로퍼티(`o.k`, `o[k]`), 구조 분해 패턴(자세히는 37편)이어야 합니다. `const` 변수에 대입하면 TypeError입니다.
- 객체를 대입하면 값이 복사되지 않고 참조가 복사됩니다(자세히는 10편).

### 복합 할당

`a op= b`는 연산 후 대입을 한 번에 하는 연산자입니다.

- 산술: `+=` `-=` `*=` `/=` `%=` `**=`
- 비트: `&=` `|=` `^=` `<<=` `>>=` `>>>=`
- 논리(ES2021): `&&=` `||=` `??=`

`a += b`는 `a = a + b`와 거의 같지만, 왼쪽 대상 식은 한 번만 평가됩니다.

```js
let i = 0
const arr = [10, 20]
arr[i++] += 1   // arr은 [11, 20], i는 1
```

`arr[i++] = arr[i++] + 1`로 풀어 쓰면 `i++`가 두 번 실행되어 결과가 달라집니다.

### 논리 할당

- `a &&= b`: `a`가 truthy일 때만 대입합니다.
- `a ||= b`: `a`가 falsy일 때만 대입합니다.
- `a ??= b`: `a`가 `null` 또는 `undefined`일 때만 대입합니다.

```js
let a = 0
a ||= 5   // 5  (0은 falsy)
let b = 0
b ??= 5   // 0  (0은 null이 아님)
let c = 1
c &&= 9   // 9
```

`a ||= b`는 `a || (a = b)`와 같습니다. `a = a || b`와 달리 대입이 필요 없으면 아예 대입하지 않으므로 오른쪽 식을 평가하지 않고 setter도 호출하지 않습니다. 대입이 일어나지 않으면 `const`에 써도 오류가 없습니다.

```js
const c = 1
c ||= 2    // 오류 없음 (대입이 일어나지 않음)
c &&= 2    // TypeError (대입이 일어남)
```

### 흔한 실수

- `let a = b = 0`은 `b`를 선언하지 않습니다. strict mode가 아닌 기본 모드(sloppy mode)에서는 전역 변수 `b`가 생기고, strict mode에서는 ReferenceError입니다(자세히는 19편).
- `if (x = 5)`는 비교가 아니라 대입이며, 대입된 값 `5`가 참이라 항상 실행됩니다. 비교는 `===`입니다.

## 동등 비교와 일치 비교

일치 비교(`===`, `!==`)는 타입 변환 없이 타입과 값이 모두 같은지 비교합니다. 동등 비교(`==`, `!=`)는 타입이 다르면 규칙에 따라 변환한 뒤 비교합니다. `!==`와 `!=`는 각각의 부정입니다.

### 일치 비교 규칙

타입이 다르면 `false`입니다. 타입이 같으면 다음 기준으로 비교합니다.

| 타입 | 같다고 보는 조건 |
|------|------------------|
| Number | 수학적으로 같은 값. `NaN`은 자기 자신과도 다르고, `+0`과 `-0`은 같음 |
| String | 코드 단위 열이 완전히 같음 |
| BigInt | 같은 정수 |
| Boolean | 같은 값 |
| `undefined`, `null` | 같은 타입이면 항상 같음 |
| Symbol, 객체 | 같은 참조 |

```js
1 === 1.0     // true  (정수와 실수 구분 없음)
NaN === NaN   // false
0 === -0      // true
1n === 1      // false (타입이 다름)
[] === []     // false (서로 다른 객체)
```

문자열은 눈에 같아 보여도 코드 단위가 다르면 다릅니다. `é`를 한 글자로 쓴 것과 `e`에 결합 악센트를 붙인 것이 그 예입니다(정규화는 33편).

```js
'\u00e9' === 'e\u0301'   // false
```

### 동등 비교 규칙

두 피연산자의 타입이 같으면 `==`는 `===`와 결과가 같습니다. 다르면 아래 표를 위에서부터 보고 처음 맞는 규칙을 적용한 뒤, 결과 값으로 다시 비교합니다.

| 순서 | 피연산자 | 처리 |
|------|----------|------|
| 1 | `null`과 `undefined` | 서로는 `true` |
| 2 | 숫자와 문자열 | 문자열을 숫자로 변환 |
| 3 | BigInt와 문자열 | 문자열을 BigInt로 변환(변환 실패는 `false`) |
| 4 | 불리언과 다른 타입 | 불리언을 숫자(`0`, `1`)로 변환 |
| 5 | 객체와 문자열·숫자·BigInt·심볼 | 객체를 원시값으로 변환 |
| 6 | BigInt와 숫자 | 수학적 값 비교(`1n == 1`은 `true`) |
| 7 | 그 밖 | `false` |

```js
null == undefined   // true
null == 0           // false (undefined 외에는 같지 않음)
'1' == 1            // true  ('1' → 1)
true == '1'         // true  (true → 1, '1' → 1)
false == 'false'    // false ('false' → NaN)
[] == false         // true  ([] → '' → 0, false → 0)
[1, 2] == '1,2'     // true  (배열 → '1,2')
```

- 불리언은 먼저 숫자로 바뀝니다. `true == 'true'`가 `false`인 이유입니다(`1 == 'true'` → `1 == NaN`).
- 양쪽이 같은 타입이면 변환이 없습니다. `'' == '0'`은 `false`, `[] == []`는 `false`(서로 다른 객체)입니다.
- `NaN`은 어떤 값과도 `==`로 같지 않습니다.
- 동등 비교는 추이성이 성립하지 않습니다. `'0' == 0`이고 `0 == ''`이지만 `'0' == ''`는 `false`입니다.
- `[] == ![]`는 `true`입니다. `![]`가 `false`가 되어 `0`으로, `[]`가 `''`를 거쳐 `0`으로 바뀌기 때문입니다.

비교 연산자는 객체의 내용을 비교하지 않습니다. `{} === {}`나 `[1] === [1]`은 항상 `false`입니다(자세히는 10편).

관례는 항상 `===`를 쓰는 것입니다. 예외는 `x == null`로, `x === null || x === undefined`와 같아서 널리 쓰입니다. `NaN` 검사는 `Number.isNaN(x)`(자세히는 30편)나 `x !== x`로 합니다.

## Object.is

`Object.is(a, b)`(ES2015)는 변환 없이 두 값이 같은 값인지 판정하는 함수입니다(명세의 SameValue). `===`와 다른 경우는 두 가지뿐입니다.

```js
Object.is(NaN, NaN)  // true   (=== 는 false)
Object.is(0, -0)     // false  (=== 는 true)
Object.is('1', 1)    // false  (변환 없음)
Object.is({}, {})    // false  (다른 참조)
```

| 비교 | `==` | `===` | `Object.is` |
|------|------|-------|-------------|
| `NaN`, `NaN` | false | false | true |
| `0`, `-0` | true | true | false |
| `'1'`, `1` | true | false | false |
| `null`, `undefined` | true | false | false |

변환 없이 값을 비교하는 같음 판정은 세 가지가 있고, 쓰이는 곳이 다릅니다.

| 알고리즘 | `NaN` | `+0`과 `-0` | 쓰이는 곳 |
|----------|-------|-------------|-----------|
| IsStrictlyEqual | 다름 | 같음 | `===`, `indexOf`, `switch`의 `case` |
| SameValueZero | 같음 | 같음 | `includes`, `Set`, `Map` 키 |
| SameValue | 같음 | 다름 | `Object.is` |

```js
[NaN].indexOf(NaN)    // -1   (=== 로 비교)
[NaN].includes(NaN)   // true (SameValueZero)
new Set([NaN, NaN]).size   // 1
```

`Set`과 `Map`은 `-0` 키를 `+0`으로 바꿔 저장합니다.

`-0`은 `-0` 리터럴, `0 * -1`, `-4 % 2`, `Math.round(-0.4)`에서 생깁니다. `String(-0)`은 `'0'`이라 문자열로는 구분할 수 없고, `Object.is(x, -0)`이나 `1 / x === -Infinity`로 판별합니다.

## 대소 비교 연산자

`<`, `>`, `<=`, `>=`는 항상 불리언을 돌려줍니다. 비교 순서는 다음과 같습니다.

1. 두 피연산자를 왼쪽부터 원시값으로 바꿉니다(객체는 숫자 우선 변환).
2. 둘 다 문자열이면 문자열 비교를 합니다(아래 절).
3. 아니면 둘 다 숫자(BigInt)로 바꿔 수를 비교합니다. 한쪽이 `NaN`이면 결과는 `false`입니다.
4. BigInt와 Number는 수학적 값으로, BigInt와 문자열은 문자열을 BigInt로 해석해 비교합니다(해석 실패는 `false`).

```js
'10' < 9     // false ('10' → 10)
'10' < '9'   // true  (둘 다 문자열 → '1' < '9')
'a' < 1      // false ('a' → NaN)
2n > 1       // true  (BigInt와 Number도 비교 가능)
[2] > 1      // true  ([2] → '2' → 2)
```

- `NaN`과의 비교는 모두 `false`입니다. `NaN <= NaN`도 `false`입니다.
- `undefined`는 `NaN`이 되므로 `undefined >= 0`도 `false`입니다.
- Symbol은 숫자로 바꿀 수 없어 TypeError입니다.
- `a <= b`는 `a < b || a == b`가 아닙니다. 내부적으로 `!(b < a)`로 계산되고(`NaN`일 때만 예외로 `false`), `==`의 변환 규칙은 쓰지 않습니다.

```js
null > 0    // false
null == 0   // false (== 은 null을 0으로 바꾸지 않음)
null >= 0   // true  (null → 0 이라 0 < 0 이 거짓 → 부정)
```

- 연쇄 비교는 없습니다. `1 < 3 < 2`는 `(1 < 3) < 2`이고 `true < 2`는 `1 < 2`라서 `true`입니다. 범위 검사는 `a < b && b < c`로 씁니다. `3 > 2 > 1`은 `1 > 1`이 되어 `false`입니다.
- Date는 숫자(밀리초)로 변환되므로 `<`, `<=`는 쓸 수 있지만 `==`, `===`는 참조 비교입니다.

```js
const a = new Date(0), b = new Date(0)
a < b        // false
a <= b       // true
a == b       // false (서로 다른 객체)
+a === +b    // true  (밀리초 숫자로 비교)
```

### 문자열 대소 비교 규칙

두 문자열을 앞에서부터 UTF-16 코드 단위(16비트 값) 하나씩 비교하고, 처음으로 다른 위치에서 값이 작은 쪽이 작은 문자열입니다. 한 문자열이 다른 문자열의 앞부분이면 짧은 쪽이 작습니다. 로케일이나 대소문자 규칙은 쓰지 않습니다.

```js
'a' < 'b'           // true  (97 < 98)
'apple' < 'apples'  // true  (앞부분이면 짧은 쪽이 작음)
'' < 'a'            // true
'Z' < 'a'           // true  (90 < 97)
'a' < 'B'           // false (97 < 66 은 거짓)
'9' < 'A'           // true  (57 < 65)
```

- 코드 값 순서는 숫자(`0`–`9`), 대문자(`A`–`Z`), 소문자(`a`–`z`) 순입니다. 대문자가 모두 소문자보다 앞입니다.
- 한글 완성형 음절(`가`부터 `힣`까지)은 코드 값 순서가 사전 순서와 같습니다. `'가' < '나'`는 `true`입니다.
- 이모지처럼 코드 단위 두 개로 이루어진 문자는 코드 단위별로 비교하므로 코드 포인트 순서와 다를 수 있습니다.

```js
'\u{1F600}' < '\uFF5E'   // true (앞 코드 단위 D83D < FF5E)
```

- 사전 순서(대소문자 무시, 언어별 정렬)가 필요하면 `localeCompare`나 `Intl.Collator`를 씁니다(자세히는 31편, 33편). `'a'.localeCompare('B')`는 `-1`입니다.
- 숫자 문자열을 비교하면 `'10' < '9'`가 `true`입니다. `[10, 9, 1].sort()`가 `[1, 10, 9]`가 되는 것도 같은 이유입니다(자세히는 28편).

## 삼항 조건 연산자

`조건 ? 값1 : 값2`는 조건이 참이면 `값1`, 거짓이면 `값2`를 평가한 결과를 돌려주는 연산자입니다. 자바스크립트의 유일한 삼항 연산자이며, 조건은 불리언으로 변환됩니다(자세히는 08편). 선택되지 않은 쪽은 평가되지 않습니다.

```js
const label = score >= 60 ? 'pass' : 'fail'
```

식이므로 변수 초기화, 인수, `return`, 템플릿 리터럴 안에 쓸 수 있습니다. 같은 일을 하는 `if` 문은 문이라서 값을 만들 수 없습니다(자세히는 04편).

- 오른쪽 결합이라 `a ? b : c ? d : e`는 `a ? b : (c ? d : e)`입니다. 조건이 늘어나는 분기에 씁니다.

```js
const grade = s >= 90 ? 'A' : s >= 80 ? 'B' : 'C'
// s가 85면 'B'
```

- 삼항은 `+`보다 우선순위가 낮아서 `+` 연결이 먼저 묶입니다. 문자열 연결과 함께 쓸 때는 삼항 부분을 괄호로 감쌉니다.

```js
const ok = false
'v: ' + ok ? 'yes' : 'no'     // 'yes' ('v: false'는 참)
'v: ' + (ok ? 'yes' : 'no')   // 'v: no'
```

- 결과 값이 필요 없는 부수 효과 호출에 쓰는 것(`c ? f() : g()`)은 문법상 가능하지만 `if`가 의도를 더 잘 드러냅니다.
- `?.` 뒤에 숫자가 오면 옵셔널 체이닝이 아니라 삼항으로 읽습니다. `true?.5:1`은 `0.5`입니다.

## 논리 연산자

`&&`(AND), `||`(OR), `??`(널 병합, ES2020)는 불리언이 아니라 **피연산자 중 하나를 그대로** 돌려줍니다. `!`(NOT)만 항상 불리언을 돌려줍니다.

- 거짓으로 취급되는 값(falsy)은 `false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN` 여덟 가지입니다. 그 밖의 값은 `'0'`, `'false'`, `[]`, `{}`까지 모두 참입니다(자세히는 08편).
- `a && b`: `a`가 falsy이면 `a`, 아니면 `b`.
- `a || b`: `a`가 truthy이면 `a`, 아니면 `b`.
- `a ?? b`: `a`가 `null`이나 `undefined`가 아니면 `a`, 아니면 `b`.
- `!a`: `a`를 불리언으로 바꿔 뒤집습니다.

```js
0 || 'x'     // 'x'
0 ?? 'x'     // 0
'' && 'x'    // ''
1 && 'x'     // 'x'
null ?? 0    // 0
NaN ?? 'n'   // NaN
```

여러 개를 이으면 `&&`는 처음 만나는 falsy 값을, `||`는 처음 만나는 truthy 값을 돌려주고, 없으면 마지막 피연산자를 돌려줍니다.

```js
1 && 2 && 3      // 3
1 && 0 && 3      // 0
0 || null || 'z' // 'z'
0 || '' || null  // null
```

### 단축 평가

왼쪽 값만으로 결과가 정해지면 오른쪽 식은 평가하지 않습니다. 오른쪽에 함수 호출이 있으면 호출도 일어나지 않습니다.

```js
user && user.save()   // user가 falsy면 save() 호출 안 됨
cache ?? load()       // cache가 null·undefined일 때만 호출
```

기본값 지정과 조건부 실행 같은 활용은 08편에서 다룹니다.

### 흔한 실수

- `||`로 기본값을 주면 유효한 `0`, `''`, `false`도 덮어씁니다. 값이 없을 때만 대체하려면 `??`를 씁니다.

```js
const count = 0
count || 10   // 10
count ?? 10   // 0
```

- `??`는 `||`, `&&`와 괄호 없이 한 식에 섞을 수 없습니다. `a ?? b || c`는 SyntaxError이고 `(a ?? b) || c`처럼 괄호로 묶어야 합니다.
- `x === 1 || 2`는 `(x === 1) || 2`라서 항상 참입니다. `x === 1 || x === 2`나 `[1, 2].includes(x)`로 씁니다.
- `!!x`는 `x`를 불리언으로 바꿉니다(`Boolean(x)`와 같음). `!![]`는 `true`, `!!'0'`은 `true`, `!!NaN`은 `false`입니다.

## 지수 연산자

`a ** b`(ES2016)는 `a`의 `b`제곱입니다. 숫자에서는 `Math.pow(a, b)`와 결과가 같습니다.

```js
2 ** 10   // 1024
2 ** -1   // 0.5
2 ** 0.5  // 1.4142135623730951
```

- 오른쪽 결합입니다. `2 ** 3 ** 2`는 `2 ** (3 ** 2)`로 `512`이고, `(2 ** 3) ** 2`는 `64`입니다.
- `+`, `-`, `!`, `~`, `typeof`, `void`, `delete`, `await` 같은 단항 연산자를 `**`의 왼쪽에 괄호 없이 쓰면 SyntaxError입니다. `-(2 ** 2)`인지 `(-2) ** 2`인지 모호하기 때문입니다.

```js
-2 ** 2      // SyntaxError
(-2) ** 2    // 4
-(2 ** 2)    // -4
2 ** -2      // 0.25 (오른쪽의 단항은 허용)
```

- 전위·후위 증감은 허용됩니다(`++x ** 2`, `x++ ** 2`).
- `**=`는 복합 할당입니다(`n **= 2`).

경계 값입니다.

```js
0 ** 0            // 1
NaN ** 0          // 1   (지수가 0이면 밑이 NaN이어도 1)
1 ** Infinity     // NaN (C의 pow와 다름)
(-8) ** (1 / 3)   // NaN (음수의 실수 거듭제곱근)
2 ** 1024         // Infinity
0 ** -1           // Infinity
```

BigInt에서는 정확한 큰 정수가 나옵니다. 지수가 음수이면 RangeError이고, Number와 섞으면 TypeError입니다.

```js
2n ** 64n    // 18446744073709551616n
2n ** -1n    // RangeError
2n ** 0.5    // TypeError
```

## 비트 연산자

비트 연산자는 Number 피연산자를 32비트 부호 있는 정수로 바꿔 비트 단위로 계산하고, 결과를 Number로 돌려줍니다. BigInt는 아래 별도 절에서 다룹니다.

- `&` (AND): 두 비트가 모두 1일 때 1
- `|` (OR): 하나라도 1이면 1
- `^` (XOR): 두 비트가 다를 때 1
- `~` (NOT): 모든 비트를 뒤집습니다. `~x`는 `-(x + 1)`과 같습니다.
- `<<` (왼쪽 시프트): 비트를 왼쪽으로 밀고 오른쪽을 0으로 채웁니다.
- `>>` (부호 유지 오른쪽 시프트): 오른쪽으로 밀고 왼쪽을 부호 비트로 채웁니다.
- `>>>` (부호 없는 오른쪽 시프트): 왼쪽을 0으로 채웁니다. 결과는 부호 없는 32비트 정수(0부터 4294967295)입니다.

```js
5 & 3       // 1   (101 & 011 = 001)
5 | 3       // 7   (101 | 011 = 111)
5 ^ 3       // 6   (101 ^ 011 = 110)
~5          // -6  (-(5 + 1))
5 << 1      // 10  (2를 곱한 효과)
-8 >> 1     // -4  (부호 유지)
-8 >>> 28   // 15  (-8은 32비트로 0xFFFFFFF8)
-1 >>> 0    // 4294967295
```

### 32비트 정수로의 변환

피연산자는 먼저 숫자로 바뀐 뒤 다음 순서로 32비트 정수가 됩니다.

1. `NaN`, `Infinity`, `-Infinity`는 `0`이 됩니다.
2. 소수부를 0 방향으로 버립니다.
3. 2의 32제곱으로 나눈 나머지를 구해 부호 있는 32비트 범위(`-2147483648`부터 `2147483647`)로 맞춥니다.

```js
3.9 | 0          // 3
-3.9 | 0         // -3
'12' | 0         // 12
NaN | 0          // 0
2147483648 | 0   // -2147483648 (범위를 넘어 한 바퀴 돎)
4294967296 | 0   // 0
```

- 시프트 횟수는 하위 5비트만 쓰므로 32로 나눈 나머지입니다. `1 << 32`는 `1`, `1 << 33`은 `2`입니다. `1 << 31`은 부호 비트가 켜져 `-2147483648`입니다.
- `x | 0`과 `~~x`는 소수부를 버리는 관용구이지만 32비트 범위 밖에서는 값이 틀어집니다. 범위를 넘을 수 있으면 `Math.trunc`를 씁니다(자세히는 30편).
- `~str.indexOf('b')`는 못 찾았을 때(`-1`)만 `0`이 되는 옛 관용구입니다. 지금은 `includes`가 읽기 쉽습니다.

### BigInt 비트 연산

BigInt는 임의 길이 정수로 비트 연산을 합니다. `>>>`는 부호 없는 폭이 정의되지 않아 TypeError이고, Number와 섞어도 TypeError입니다.

```js
1n << 64n   // 18446744073709551616n
~5n         // -6n
1n >>> 1n   // TypeError
1n & 1      // TypeError
```

### 쓰임과 흔한 실수

비트 연산은 하나의 정수에 여러 켜짐·꺼짐 값을 담는 플래그에 씁니다.

```js
const READ = 1, WRITE = 2, EXEC = 4
let perm = READ | WRITE                // 3 (켜기)
const canWrite = (perm & WRITE) !== 0  // true (확인)
perm &= ~WRITE                         // 1 (끄기)
perm ^= EXEC                           // 5 (뒤집기)
```

홀짝 판별 `n & 1`은 음수에서도 맞습니다(`-3 & 1`은 `1`). `%`와 다른 점입니다.

- `&`와 `&&`는 다릅니다. `1 & 2`는 `0`, `1 && 2`는 `2`입니다.
- `^`는 거듭제곱이 아니라 XOR입니다. `2 ^ 3`은 `1`입니다.
- `===`가 `&`보다 우선순위가 높아서 `x & 1 === 0`은 `x & (1 === 0)`이고 항상 `0`입니다. `(x & 1) === 0`으로 씁니다.

## typeof와 주의점

`typeof 피연산자`는 피연산자의 타입을 나타내는 문자열을 돌려주는 단항 연산자입니다. `typeof(x)`의 괄호는 함수 호출이 아니라 그룹 연산자입니다. 결과는 항상 문자열이라 `typeof typeof 1`은 `'string'`입니다.

### typeof 결과 전체 표

| 값 | 결과 |
|----|------|
| `undefined` | `'undefined'` |
| `null` | `'object'` |
| `true`, `false` | `'boolean'` |
| 숫자 (`NaN`, `Infinity` 포함) | `'number'` |
| BigInt | `'bigint'` |
| 문자열 | `'string'` |
| 심볼 | `'symbol'` |
| 호출할 수 있는 객체 (함수, 클래스, 화살표·async·제너레이터 함수, bind 결과) | `'function'` |
| 그 밖의 모든 객체 (배열, Date, RegExp, Map, Set, Promise, Error, 래퍼 객체, `Math`, `JSON`) | `'object'` |

브라우저의 `document.all`은 호환성을 위한 예외로 `'undefined'`를 돌려주는 호스트 객체입니다.

```js
typeof 'a'               // 'string'
typeof new String('a')   // 'object' (래퍼 객체)
```

### 주의점

- `typeof null`은 `'object'`입니다. 초기 구현에서 생긴 오류이며 기존 웹 페이지가 깨지므로 고치지 않습니다. `null` 검사는 `x === null`로 합니다.
- 배열·Date·정규식을 구분하지 못합니다. 배열은 `Array.isArray(x)`(자세히는 28편)로, 그 밖의 내장 객체는 `Object.prototype.toString.call(x)`로 구분합니다. 이 호출은 `'[object Array]'`, `'[object Null]'`, `'[object Date]'`처럼 내부 종류를 문자열로 돌려줍니다.
- 일반 객체 판별은 `typeof x === 'object' && x !== null`입니다. 함수는 `'function'`이라 이 식에서 빠집니다.
- 선언되지 않은 식별자에도 오류 없이 `'undefined'`를 돌려줍니다. 일반 참조는 ReferenceError입니다.

```js
typeof notDeclared             // 'undefined'
typeof window !== 'undefined'  // 브라우저인지 검사
```

- `let`, `const`, `class`로 선언한 변수는 선언문에 도달하기 전까지 접근할 수 없는 구간(TDZ)이 있고, 이 구간에서는 `typeof`도 ReferenceError입니다.

```js
typeof tdz   // ReferenceError
let tdz = 1
```

- `typeof`는 이항 연산자보다 우선순위가 높습니다. `typeof x + 1`은 `(typeof x) + 1`이라 `'number1'`이고, 피연산자 전체의 타입은 `typeof (x + 1)`로 씁니다.

## in 연산자

`키 in 객체`는 객체 자신이나 프로토타입 체인에 그 키가 있으면 `true`를 돌려줍니다. 왼쪽은 프로퍼티 키(문자열 또는 심볼로 변환), 오른쪽은 객체여야 하며 원시값·`null`·`undefined`이면 TypeError입니다.

```js
const o = { a: 1 }
'a' in o          // true
'toString' in o   // true  (프로토타입에서 상속)
'b' in o          // false
0 in [10, 20]     // true  (인덱스도 키)
'length' in []    // true
'a' in 'abc'      // TypeError (오른쪽이 문자열)
```

- 값이 `undefined`여도 키가 있으면 `true`입니다. `{ a: undefined }`에서 `'a' in o`는 `true`이고 `o.a !== undefined`는 `false`입니다.
- 배열의 빈 칸(구멍)은 키가 없습니다. `1 in [1, , 3]`은 `false`입니다.
- 자신의 프로퍼티만 확인하려면 `Object.hasOwn(o, 'a')`(ES2022)를 씁니다(자세히는 18편).
- 클래스 안에서 `#x in obj`(ES2022)는 `obj`에 비공개 필드 `#x`가 있는지 검사합니다(자세히는 24편).
- `for (const k in obj)`의 `in`은 연산자가 아니라 for...in 문의 일부입니다(자세히는 18편).
- Proxy의 `has` 트랩이 `in` 연산을 가로챕니다(자세히는 47편).

`in`은 관계 연산자와 같은 우선순위라서 `!`와 함께 쓸 때 괄호가 필요합니다.

```js
const o = { a: 1 }
!'b' in o      // false  ((!'b') → false → 키 'false' 검사)
!('b' in o)    // true
```

## instanceof 연산자

`객체 instanceof 생성자`는 생성자의 `prototype` 객체가 왼쪽 객체의 프로토타입 체인에 있으면 `true`를 돌려줍니다(자세히는 17편).

```js
class A {}
class B extends A {}
const b = new B()
b instanceof B        // true
b instanceof A        // true  (체인에 A.prototype이 있음)
b instanceof Object   // true
new A() instanceof B  // false
```

- 오른쪽이 호출할 수 있는 함수가 아니면 TypeError입니다.
- 왼쪽이 원시값이면 오류 없이 `false`입니다. `'a' instanceof String`은 `false`이고 `new String('a') instanceof String`은 `true`입니다.
- 프로토타입 체인에 `Object.prototype`이 없는 객체(`Object.create(null)`)는 `instanceof Object`가 `false`입니다.
- 생성자의 `prototype`을 나중에 바꾸면 이전에 만든 인스턴스는 `false`가 됩니다.

```js
function F() {}
const f = new F()
F.prototype = {}
f instanceof F   // false
```

- 화살표 함수는 `prototype`이 없어 오른쪽에 쓰면 TypeError입니다.
- 오른쪽에 `Symbol.hasInstance` 메서드가 있으면 `instanceof`는 그 메서드의 반환값(불리언으로 변환)을 씁니다. 함수의 기본 구현이 프로토타입 체인 탐색입니다.

```js
class Even {
  static [Symbol.hasInstance](n) { return n % 2 === 0 }
}
2 instanceof Even   // true
3 instanceof Even   // false
```

- iframe이나 `vm`처럼 실행 영역(realm)이 다른 곳에서 만든 배열은 `instanceof Array`가 `false`입니다. 배열은 `Array.isArray`로 판별합니다.
- 원시값 판별에는 `typeof`, 객체 종류 판별에는 `instanceof`를 씁니다.

## 쉼표·그룹·void·delete

### 쉼표 연산자

`a, b`는 `a`를 평가해 값을 버리고 `b`를 평가한 값을 돌려주는 연산자입니다. 우선순위가 모든 연산자 중 가장 낮습니다.

```js
const x = (1, 2, 3)        // 3
let n = 0
const y = (n++, n++, n)    // 2
```

쉼표는 연산자가 아닌 용도가 더 많습니다. 변수 선언 목록(`let a = 1, b = 2`), 인수, 배열·객체 리터럴의 쉼표는 구분자입니다. 이 자리에서 연산자로 쓰려면 괄호가 필요합니다. `f((1, 2))`는 인수 하나(`2`)를 넘기고, `const x = 1, 2`는 SyntaxError입니다.

연산자로 쓰는 대표적인 곳은 for 문의 초기식과 증감식입니다.

```js
for (let i = 0, j = 9; i < j; i++, j--) {
  // i와 j를 함께 갱신
}
```

`(0, obj.method)()` 형태로 쓰면 메서드 값만 꺼내 `this` 없이 호출합니다(자세히는 21편).

### 그룹 연산자

`( 식 )`은 괄호 안을 먼저 계산하고 그 값을 돌려주는 연산자입니다. 우선순위를 바꾸는 것 외에 값을 바꾸지 않습니다. `(1 + 2) * 3`은 `9`입니다.

- 문장 맨 앞의 중괄호는 블록으로 해석됩니다. 구조 분해 대입은 괄호로 감쌉니다(`({ a, b } = obj)`).
- 화살표 함수가 객체를 바로 반환하려면 `() => ({ a: 1 })`로 씁니다. 괄호가 없으면 `{ a: 1 }`이 함수 본문 블록이 되어 `undefined`를 반환합니다.
- 그룹은 값이 아니라 참조를 유지하므로 메서드 호출의 `this`를 바꾸지 않습니다. 쉼표는 값을 꺼내므로 `this`를 잃습니다.

```js
const obj = { f() { return this === obj } }
const r1 = obj.f()         // true
const r2 = (obj.f)()       // true  (그룹은 참조를 유지)
const r3 = (0, obj.f)()    // false (this가 obj가 아님)
```

### void

`void 식`은 식을 평가하고 항상 `undefined`를 돌려주는 단항 연산자입니다.

```js
void 0         // undefined
void (1 + 2)   // undefined
void 0 + 1     // NaN  ((void 0) + 1)
```

- `void 0`은 `undefined` 값을 얻는 표기입니다. 지역 변수 이름으로 `undefined`를 가릴 수 있어서 옛 코드와 압축된 코드에 남아 있습니다.
- 화살표 함수의 반환값을 버릴 때 씁니다(`() => void log.push(1)`).
- 의도적으로 결과를 기다리지 않는 프로미스 호출을 표시할 때 씁니다(`void fetchData()`).

### delete

`delete 객체.키`와 `delete 객체[키]`는 객체 자신의 프로퍼티를 삭제하고 불리언을 돌려주는 연산자입니다.

```js
const o = { a: 1 }
delete o.a        // true
o.a               // undefined
'a' in o          // false
delete o.zzz      // true  (없는 키도 true)
```

- 반환값은 삭제 후 그 프로퍼티가 없으면 `true`입니다. 삭제할 수 없는 프로퍼티(configurable이 `false`, 자세히는 14편)는 `false`이고, strict mode에서는 TypeError입니다.

```js
delete Math.PI    // false (strict mode면 TypeError)
const f = Object.freeze({ a: 1 })
delete f.a        // false
```

- 프로퍼티를 삭제하는 것과 `undefined`를 대입하는 것은 다릅니다. 삭제하면 `'a' in o`가 `false`가 되고, 대입하면 `true`로 남습니다.
- 프로토타입 체인은 건드리지 않습니다. 인스턴스가 상속받은 프로퍼티는 `delete`로 지울 수 없고, 자신의 프로퍼티가 가리고 있던 경우 삭제하면 프로토타입의 값이 다시 보입니다.
- 배열에 쓰면 요소가 빈 칸이 될 뿐 `length`와 다른 인덱스는 그대로입니다. 요소를 제거하려면 `splice`를 씁니다(자세히는 28편).

```js
const arr = [1, 2, 3]
delete arr[1]
arr          // [1, <1 empty item>, 3]
arr.length   // 3
```

- `var`·`let`·`const`로 선언한 변수는 삭제할 수 없습니다. strict mode가 아니면 `false`, strict mode에서는 `delete 식별자` 자체가 SyntaxError입니다(자세히는 19편).
- `delete`는 참조를 끊을 뿐 메모리를 직접 해제하지 않습니다. 값을 가리키는 참조가 모두 사라지면 가비지 컬렉션 대상이 됩니다(자세히는 49편).
- `Map`과 `Set`의 `delete()`는 이 연산자와 별개인 메서드입니다(자세히는 38편).

## 부수 효과

부수 효과(side effect)는 식이 값을 계산하는 것 외에 프로그램의 다른 상태를 바꾸거나 바깥에 영향을 주는 동작입니다. 값만 만들고 아무것도 바꾸지 않는 식은 순수한 식입니다.

| 부수 효과를 일으키는 것 | 바뀌는 것 |
|-------------------------|-----------|
| `=`, 복합 할당 | 변수·프로퍼티 값 |
| `++`, `--` | 피연산자 값 |
| `delete` | 프로퍼티 존재 여부 |
| 함수·메서드 호출, `new` | 함수 본문이 하는 모든 일(출력, 변경, 예외) |
| `await`, `yield` | 실행의 중단과 재개 |

산술·비교 연산자와 `typeof` 자체는 순수합니다. 그러나 피연산자가 객체이면 변환 과정에서 `valueOf()`·`toString()`이 호출되어 부수 효과가 생길 수 있습니다. getter가 있는 프로퍼티를 읽거나 Proxy 트랩이 걸린 객체를 다룰 때도 코드가 실행됩니다.

```js
const o = { valueOf() { console.log('called'); return 1 } }
o + 1   // 'called' 출력 후 2
```

### 평가 순서

피연산자는 우선순위와 관계없이 항상 왼쪽에서 오른쪽으로 평가됩니다. 우선순위는 어떤 연산이 어떤 값을 묶는지만 정합니다.

```js
const log = (v) => (console.log(v), v)
log(1) + log(2) * log(3)
// 1, 2, 3 순서로 출력된 뒤 2 * 3, 1 + 6 순으로 계산 → 7
```

- 함수 호출은 호출 대상 식을 먼저, 그다음 인수를 왼쪽부터 평가합니다. `i`가 0일 때 `f(i++, i++)`는 `f(0, 1)`입니다.
- 단축 평가(`a && f()`)와 삼항(`c ? f() : g()`)은 선택되지 않은 쪽을 평가하지 않으므로 그쪽의 부수 효과도 일어나지 않습니다.
- 같은 변수를 바꾸고 읽는 식도 순서는 정해져 있지만 읽기 어렵습니다.

```js
let a = 1
const b = a + (a = 5)   // 6  (왼쪽 a는 이미 1로 읽힘)
const c = (a = 5) + a   // 10 (대입 뒤의 a를 읽음)
```

### 작성 원칙

- 한 문장에 부수 효과를 하나만 둡니다.
- 값을 계산하는 식과 상태를 바꾸는 문장을 분리합니다.
- 값을 쓰지 않는 순수한 식 문장(`a + b;`)은 아무 일도 하지 않으므로 오타의 신호입니다.
- 부수 효과를 최소화하는 설계는 50편에서 다룹니다.

## 우선순위와 결합 순서

우선순위(precedence)는 여러 연산자가 섞인 식에서 어느 연산자가 피연산자를 먼저 묶는지의 순서입니다. 결합 순서(associativity)는 우선순위가 같은 연산자가 이어질 때 묶는 방향입니다. 왼쪽 결합이면 `a - b - c`가 `(a - b) - c`, 오른쪽 결합이면 `a = b = c`가 `a = (b = c)`입니다.

| 단계 | 연산자 | 결합 |
|------|--------|------|
| 18 | 그룹 `( )` | 해당 없음 |
| 17 | 멤버 접근 `.` `[]`, 호출 `f()`, 인수 있는 `new F()`, 옵셔널 체이닝 `?.` | 왼쪽 |
| 16 | 인수 없는 `new F` | 해당 없음 |
| 15 | 후위 `x++` `x--` | 해당 없음 |
| 14 | `!` `~` 단항 `+` `-`, 전위 `++` `--`, `typeof` `void` `delete` `await` | 해당 없음 |
| 13 | `**` | 오른쪽 |
| 12 | `*` `/` `%` | 왼쪽 |
| 11 | `+` `-` | 왼쪽 |
| 10 | `<<` `>>` `>>>` | 왼쪽 |
| 9 | `<` `<=` `>` `>=` `in` `instanceof` | 왼쪽 |
| 8 | `==` `!=` `===` `!==` | 왼쪽 |
| 7 | `&` | 왼쪽 |
| 6 | `^` | 왼쪽 |
| 5 | `\|` | 왼쪽 |
| 4 | `&&` | 왼쪽 |
| 3 | `\|\|` `??` | 왼쪽 |
| 2 | 대입(복합 포함), `?:`, `=>`, `yield` | 오른쪽 |
| 1 | 쉼표 | 왼쪽 |

`new`는 생성자 호출 연산자이고(자세히는 15편), `await`와 `yield`는 각각 43편과 42편에서 다룹니다.

```js
1 + 2 * 3 ** 2 - 4 / 2
// 1 + (2 * (3 ** 2)) - (4 / 2)
// 1 + 18 - 2 → 17

10 - 3 - 2          // 5   ((10 - 3) - 2)
2 ** 3 ** 2         // 512 (2 ** (3 ** 2))
x ? 1 : y ? 2 : 3   // x ? 1 : (y ? 2 : 3)
```

`&&`가 `||`보다 우선순위가 높아서 `a || b && c`는 `a || (b && c)`입니다. 다만 `??`는 같은 단계의 `||`와 달리 괄호 없이 섞는 것 자체가 금지입니다.

### 의도와 다르게 묶이는 식

| 식 | 실제 해석 | 의도한 형태 |
|----|-----------|-------------|
| `typeof x + 1` | `(typeof x) + 1` | `typeof (x + 1)` |
| `!a in o` | `(!a) in o` | `!(a in o)` |
| `!a instanceof B` | `(!a) instanceof B` | `!(a instanceof B)` |
| `x & 1 === 0` | `x & (1 === 0)` | `(x & 1) === 0` |
| `'v' + c ? 'p' : 'q'` | `('v' + c) ? 'p' : 'q'` | `'v' + (c ? 'p' : 'q')` |
| `a < b < c` | `(a < b) < c` | `a < b && b < c` |
| `-a ** 2` | SyntaxError | `(-a) ** 2` 또는 `-(a ** 2)` |
| `a ?? b \|\| c` | SyntaxError | `(a ?? b) \|\| c` |

`new`는 인수 목록 앞의 멤버 접근 전체를 생성자로 삼습니다. `new Foo.bar()`는 `new (Foo.bar)()`이고, 인수 목록 뒤의 멤버 접근은 만들어진 객체에 적용되어 `new Foo().bar`는 `(new Foo()).bar`입니다.

우선순위를 외워서 읽기보다, `&&`와 `||`, 비트와 비교, 삼항 안의 `+`처럼 서로 다른 계열이 섞이는 곳에는 괄호로 의도를 적습니다. 괄호는 실행 결과와 성능에 영향이 없습니다.

## 핵심 정리

- `+`는 한쪽이라도 문자열이면 연결이고, 그 밖의 산술 연산자는 피연산자를 항상 숫자(BigInt)로 바꿉니다. BigInt와 Number를 섞으면 TypeError입니다.
- `===`는 변환 없이 비교하고 `==`는 규칙 표에 따라 변환합니다. `Object.is`는 `NaN`과 `-0`에서만 `===`와 다릅니다.
- 대소 비교는 둘 다 문자열이면 코드 단위 순서, 아니면 숫자 비교입니다. `<=`는 `<`의 부정으로 계산되어 `null >= 0`이 `true`입니다.
- `&&`·`||`·`??`는 피연산자 중 하나를 돌려주며 오른쪽을 건너뛸 수 있고, `??`는 `||`·`&&`와 괄호 없이 섞을 수 없습니다.
- 피연산자는 항상 왼쪽부터 평가되고 우선순위는 묶는 방식만 정합니다. 섞이는 곳은 괄호로 의도를 적습니다.
- `%`의 부호는 왼쪽 값을 따르고, `**`는 오른쪽 결합이며 단항 연산자 바로 뒤에서는 SyntaxError이고, `typeof null`은 `'object'`입니다.
