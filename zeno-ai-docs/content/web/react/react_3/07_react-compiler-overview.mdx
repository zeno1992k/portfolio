## React Compiler

React Compiler는 컴포넌트와 Hook을 자동으로 메모이제이션해 불필요한 리렌더링과 중복 계산을 줄이는 빌드 시점 도구입니다. 개발자가 `React.memo`, `useMemo`, `useCallback`을 직접 쓰지 않아도 코드를 분석해 필요한 곳에 같은 효과를 적용합니다.

- 일반 JavaScript 코드를 받아 React의 규칙(Rules of React)을 이해하고 처리합니다. 코드를 다시 쓸 필요가 없습니다.
- React와 React Native 모두에서 동작합니다.
- 컴파일러는 Meta 등에서 프로덕션에 쓰이는 안정 도구입니다.

버전과 지원 범위는 다음과 같습니다.

| 항목 | 내용 |
|------|------|
| 1.0 정식 출시 | 2025-10-07 (React Compiler v1.0 발표) |
| npm 패키지 | `babel-plugin-react-compiler` (latest 태그 1.0.0, 2025-10-07 게시) |
| 지원 React 버전 | React 17 이상. 17과 18은 `target` 설정과 `react-compiler-runtime` 패키지 필요, 19는 설정 없이 동작 |
| 빌드 도구 | Babel, Vite, Metro, Rsbuild, Next.js 15.3.1 이상 |
| 새 프로젝트 | Expo SDK 54 이상은 기본 활성화, create-vite·create-next-app 템플릿에 선택지 포함 |

- 19.3 발표 글에는 컴파일러 변경이 없습니다. 컴파일러는 React 본체와 별도 패키지로 릴리스됩니다.
- 앞으로 일부 React 기능이 컴파일러를 필요로 할 수 있다고 공식 문서가 언급합니다.
- 설치와 설정은 08편에서 다룹니다.

## Build-time Optimization

컴파일러는 앱이 실행될 때가 아니라 빌드할 때 동작합니다. 소스 코드를 읽어 메모이제이션이 들어간 코드로 바꾼 결과가 번들에 담깁니다.

- 컴파일러는 Babel AST를 HIR(High-Level Intermediate Representation)이라는 중간 표현으로 바꾸고, 제어 흐름 그래프(CFG)를 기반으로 여러 단계의 분석을 합니다.
- 분석 대상은 데이터 흐름, 코드의 변경(mutation) 가능성, 렌더링 값 단위의 세밀한 메모이제이션 범위입니다.
- 런타임에서 코드를 감시하거나 추가 비용을 들이는 방식이 아닙니다. 사용자의 브라우저는 이미 최적화된 코드를 실행합니다.
- 빌드 도구에 플러그인으로 연결하므로 빌드 설정이 필요합니다(자세히는 08편).

## 자동 Memoization

메모이제이션(memoization)은 같은 입력에 대한 결과를 저장해 두고 재사용하는 최적화입니다. 컴파일러는 개발자가 `useMemo`나 `useCallback`을 쓰지 않은 값에도 이를 적용합니다.

```js
// 컴파일러 적용 전에 개발자가 직접 한 메모이제이션
const items = useMemo(() => filter(list, q), [list, q])
const onPick = useCallback((id) => select(id), [select])
```

```js
// 컴파일러가 있으면 일반 코드로 충분하다
const items = filter(list, q)
const onPick = (id) => select(id)
```

- 입력(props, state, 이전 값)이 바뀌지 않았으면 이전 결과를 재사용하고, 바뀌었을 때만 다시 계산합니다.
- 수동 메모이제이션이 못 하는 것도 합니다. 조건부 `return` 뒤에 있는 값도 메모이제이션할 수 있습니다. Hook은 조건문 뒤에서 호출할 수 없지만 컴파일러가 만든 메모이제이션에는 그 제약이 없습니다.
- 수동 방식은 의존성 배열을 직접 관리해야 하고 틀리면 버그가 납니다. 컴파일러는 코드를 분석해 이를 자동으로 처리합니다.

## 컴포넌트 최적화

컴파일러는 부모의 상태가 바뀔 때 자식이 쓸데없이 다시 렌더링되는 연쇄 리렌더링을 막습니다.

```js
function FriendList({ friends }) {
  const online = useFriendOnlineCount()
  return (
    <div>
      <span>{online} online</span>
      {friends.map((f) => <Card key={f.id} friend={f} />)}
      <MessageButton />
    </div>
  )
}
```

- `MessageButton`은 props가 없으므로 `friends`가 바뀌어도 다시 렌더링되지 않습니다. 수동으로는 `React.memo`로 감싸야 얻는 효과입니다.
- 렌더링 중 만들어지는 JSX 조각과 인라인 함수도 입력이 같으면 같은 참조를 유지해 자식의 `React.memo` 비교를 통과시킵니다.
- 인라인 화살표 함수가 매번 새 참조를 만들어 수동 `useCallback`을 무력화하는 문제도 컴파일러 안에서는 해소됩니다.
- 비용이 큰 계산 호출도 컴포넌트 안에서는 메모이제이션됩니다.

## Hook 최적화

컴파일러는 컴포넌트뿐 아니라 커스텀 Hook 안의 계산과 값도 같은 방식으로 최적화합니다.

```js
function useVisibleTodos(todos, filter) {
  return todos.filter((t) => matches(t, filter)) // 메모이제이션됨
}
```

- 커스텀 Hook 안의 비싼 계산도 입력이 같으면 다시 실행되지 않습니다.
- 컴포넌트와 Hook 밖에 있는 일반 함수는 메모이제이션 대상이 아닙니다. 컴포넌트나 Hook 안에서 호출될 때만 그 호출이 최적화됩니다.
- 여러 컴포넌트가 같은 계산을 공유하는 캐시는 만들어 주지 않습니다. 각 컴포넌트나 Hook이 자기 메모이제이션을 가집니다. 정말 비싼 계산은 React 밖에서 메모이제이션합니다.
- 렌더링 중 계산과 리렌더링이 대상입니다. Effect 안에서 하는 비싼 작업은 최적화하지 않습니다.

## Pure React 요구

컴파일러는 코드가 Rules of React를 지킨다는 전제에서 동작합니다. 규칙을 어긴 코드는 최적화가 틀릴 수 있어서 컴파일러가 해당 컴포넌트나 Hook을 건너뛸 수 있습니다.

Rules of React의 핵심은 세 가지입니다.

| 규칙 | 내용 |
|------|------|
| 순수해야 한다 | 컴포넌트와 Hook은 멱등하고, 부수 효과는 렌더링 밖에서 실행하며, props·state·Hook 인자와 반환값은 변경하지 않는다 |
| React가 호출한다 | 컴포넌트는 JSX로만 쓰고 직접 호출하지 않으며, Hook은 컴포넌트와 Hook 안에서만 호출한다 |
| Hook 규칙 | 최상위에서만 호출하고 React 함수에서만 호출한다 |

```js
function Counter({ list }) {
  list.push('x')      // ❌ props 변경
  const id = Math.random() // ❌ 렌더링마다 다른 결과
  return <p>{id}</p>
}
```

- 이 규칙은 `eslint-plugin-react-hooks`와 Strict Mode가 감지합니다.
- 규칙을 어기고도 지금까지 잘 동작하던 코드는 컴파일러가 감지하지 못하는 방식으로 깨질 수 있습니다. 컴파일러를 도입하기 전에 린트 경고를 먼저 정리하는 것이 안전합니다.
- 컴파일러의 버전이 바뀌면 메모이제이션의 세분화 정도가 달라질 수 있습니다. 규칙을 어긴 코드에서는 이것이 `useEffect`가 더 자주 또는 덜 실행되는 변화로 나타날 수 있어서, 공식 문서는 정확한 버전(예: `1.0.0`)으로 고정하고 수동으로 올리며 E2E 테스트를 갖추라고 권합니다.

**흔한 실수:** 컴파일러가 규칙 위반을 고쳐 준다고 기대하는 것입니다. 컴파일러는 규칙을 지키는 코드를 빠르게 만들 뿐 위반을 고치지 않습니다.

## React.memo와 관계

`React.memo`는 props가 같으면 컴포넌트의 리렌더링을 건너뛰게 하는 수동 API입니다(자세히는 중급 18편). 컴파일러는 같은 효과를 자동으로 얻게 하므로 새 코드에서는 `React.memo`를 쓸 필요가 줄어듭니다.

- 컴파일러 안에서는 부모 상태가 바뀌어도 입력이 같은 자식은 다시 렌더링되지 않습니다. 컴포넌트마다 `React.memo`를 붙이는 이유가 사라집니다.
- 이미 `React.memo`가 붙은 코드는 그대로 두어도 됩니다. 함께 동작하며, 컴파일러가 안정시킨 props 참조 덕에 `React.memo`의 비교가 더 자주 통과합니다.
- 공식 문서는 기존 메모이제이션을 지우면 컴파일 결과가 달라질 수 있다고 경고합니다.

## useMemo와 관계

`useMemo`는 계산 결과를 저장하는 수동 Hook입니다(자세히는 중급 19편). 컴파일러가 같은 일을 자동으로 하므로 새 코드에서는 기본적으로 쓰지 않습니다.

- 새 코드는 컴파일러에 맡기고, 정밀한 제어가 필요한 곳에만 `useMemo`를 씁니다. 대표적인 경우는 메모이제이션된 값을 Effect의 의존성으로 쓰면서 Effect가 반복 실행되지 않게 하려는 때입니다.
- 기존 코드의 `useMemo`는 그대로 두거나, 지우려면 지운 뒤 충분히 테스트합니다.
- 컴파일러는 컴포넌트와 Hook 안의 계산만 메모이제이션합니다. 계산 결과를 여러 컴포넌트가 공유해야 하면 별도의 캐시가 필요합니다.

## useCallback과 관계

`useCallback`은 함수 참조를 고정하는 수동 Hook입니다(자세히는 중급 19편). 컴파일러는 컴포넌트 안에서 만든 함수의 참조를 입력이 같은 동안 안정시킵니다.

```js
function List({ items, onSelect }) {
  // 컴파일러: onSelect가 같으면 이 함수 참조도 유지된다
  const pick = (item) => onSelect(item.id)
  return items.map((i) => (
    <Row key={i.id} onPick={() => pick(i)} />
  ))
}
```

- 수동 `useCallback`이 인라인 화살표 함수 때문에 무력해지던 문제는 컴파일러가 처리합니다.
- 함수가 Effect의 의존성이어서 참조 안정성이 의미가 있을 때는 `useCallback`을 탈출구로 계속 쓸 수 있습니다.
- 세 API의 정리는 다음과 같습니다.

| API | 컴파일러가 있을 때 |
|-----|--------------------|
| `React.memo` | 새 코드에서는 불필요. 기존 코드는 유지 가능 |
| `useMemo` | 새 코드에서는 불필요. Effect 의존성 같은 정밀 제어용으로만 |
| `useCallback` | 새 코드에서는 불필요. Effect 의존성 같은 정밀 제어용으로만 |

## 점진적 도입

기존 앱 전체에 한 번에 컴파일러를 켜지 않고 범위를 넓혀 가며 도입할 수 있습니다. 공식 문서가 다음 전략을 안내합니다(설정 방법은 08편).

| 전략 | 방법 |
|------|------|
| 디렉터리 단위 | Babel `overrides`로 특정 폴더에만 플러그인을 적용하고 점차 넓힌다 |
| 옵트인 | `compilationMode`를 `'annotation'`으로 두고 `"use memo"`가 있는 함수만 컴파일한다 |
| 런타임 게이팅 | `gating` 옵션으로 기능 플래그가 켜진 사용자에게만 컴파일된 코드를 쓴다(A/B 테스트) |
| 옵트아웃 | 문제가 생긴 컴포넌트에 `"use no memo"`를 붙여 임시로 제외한다 |

- 공식 문서의 권장 순서는 디렉터리 단위로 시작하고, 세밀한 제어는 옵트인으로, 점진적 출시는 게이팅으로 하는 것입니다.
- 도입 전에 린트로 규칙 위반을 확인하고, 도입 뒤에는 실제 성능과 동작을 측정해 확인합니다.
- Meta Quest Store 프로덕션에서의 결과로 공식 발표 글은 초기 로딩과 페이지 전환이 최대 12퍼센트 개선되고 일부 상호작용이 2.5배 빨라졌으며 메모리 사용은 변화가 없었다고 밝혔습니다. 앱마다 결과는 다릅니다.

## 핵심 정리

- React Compiler는 빌드 시점에 컴포넌트와 Hook에 자동으로 메모이제이션을 넣는 도구이며, 1.0은 2025-10-07에 정식 출시됐고 React 17 이상을 지원합니다.
- 연쇄 리렌더링과 컴포넌트·Hook 안의 계산을 최적화하고, 조건부 `return` 뒤의 값도 처리합니다. 컴포넌트·Hook 밖의 함수, 컴포넌트 간 공유 캐시, Effect 안의 작업은 대상이 아닙니다.
- Rules of React(순수성, React가 호출, Hook 규칙)를 지키는 코드를 전제로 하며, 어긴 컴포넌트는 건너뛸 수 있습니다.
- 새 코드에서는 `React.memo`, `useMemo`, `useCallback`을 기본으로 쓰지 않고, Effect 의존성 같은 정밀 제어에만 씁니다. 기존 메모이제이션은 지우지 않고 두는 것이 안전합니다.
- 디렉터리 단위, `annotation` 모드, 게이팅, `"use no memo"`로 점진적으로 도입하고 버전은 고정합니다.
