## Modal

Modal은 열리면 나머지 화면과의 상호작용을 막고 사용자의 응답을 요구하는 오버레이입니다. 모달이 성립하려면 다섯 가지가 필요합니다.

- 배경 비활성화: 배경은 클릭도 포커스도 받지 못하고 스크린 리더에서도 가려집니다.
- 포커스 가두기: Tab과 Shift+Tab이 모달 안에서만 순환합니다.
- 포커스 이동: 열릴 때 모달 안으로 포커스가 이동합니다.
- 포커스 복귀: 닫히면 열었던 요소로 포커스가 돌아갑니다.
- 닫기 수단: Esc와 눈에 보이는 닫기 버튼을 둡니다.

APG의 모달 Dialog 패턴이 정한 요건이며, `aria-modal="true"`는 실제로 배경 상호작용을 막고 시각적으로도 가릴 때만 설정합니다.

- 모달은 DOM 트리 맨 아래로 옮겨 렌더링해야 `overflow`와 `z-index`의 영향을 받지 않습니다(자세히는 중급 14편, Portal).
- 모달이 열려 있는 동안 배경 스크롤을 막는 처리도 필요합니다. 라이브러리가 대신 처리하는지 확인합니다.
- 모달은 흐름을 끊으므로 정말 응답이 필요한 때만 씁니다. 정보 표시나 단순 선택은 Popover가 낫습니다.

## Dialog

Dialog는 모달 또는 비모달로 열 수 있는 창이며, 구현 방법이 세 가지입니다.

| 방법 | 특징 |
|------|------|
| 브라우저 `dialog` 요소 | `showModal()`로 열면 배경이 inert가 되고 Esc로 닫히며 `::backdrop`으로 배경을 꾸밈. 2022-03부터 주요 브라우저 지원 |
| Radix Dialog 등 Headless | 포커스 가두기, 포털, `Title`·`Description` 연결을 대신 처리 |
| 직접 구현 | 위 요건을 모두 손으로 구현. 비추천 |

```js
dialog.showModal() // 모달: 배경 inert, Esc로 닫힘
dialog.show()      // 비모달: 배경 상호작용 가능
dialog.close('ok') // 닫기, returnValue는 'ok'
```

- `form`에 `method="dialog"`를 쓰면 제출 시 Dialog가 닫힙니다.
- 닫기 허용 범위는 `closedby` 속성으로 정합니다. `any`는 바깥 클릭·Esc·코드, `closerequest`는 Esc·코드, `none`은 코드만 허용합니다. 기본값은 `showModal()`일 때 `closerequest`입니다.
- Radix Dialog는 `Root`, `Trigger`, `Portal`, `Overlay`, `Content`, `Title`, `Description`, `Close`로 구성되고 `open`과 `onOpenChange`로 제어합니다. 기본이 모달이며 Esc로 닫힙니다.
- Radix는 `Title`과 `Description`을 요구합니다. 보이지 않게 하려면 `VisuallyHidden`을 씁니다.
- 파괴적 확인(삭제 등)은 `AlertDialog`를 씁니다. `alertdialog` 역할이며 열리면 Cancel에 포커스가 가고, 바깥을 클릭해도 닫히지 않습니다.

**흔한 실수:** Dialog에 제목과 설명을 연결하지 않아 스크린 리더가 무엇이 열렸는지 알리지 못하는 것입니다.

## Dropdown

Dropdown은 버튼을 누르면 동작 목록(메뉴)을 펼치는 패턴입니다. APG는 Menu Button 패턴으로 정의하며 `aria-haspopup="menu"`, `aria-expanded`, 메뉴 컨테이너 `role="menu"`를 요구합니다.

키보드 요건은 다음과 같습니다(Radix Dropdown Menu 기준).

| 키 | 동작 |
|----|------|
| Space·Enter (버튼) | 메뉴를 열고 첫 항목에 포커스 |
| 화살표 | 항목 사이 이동. 좌우는 하위 메뉴 열기·닫기 |
| 글자 입력 | 해당 글자로 시작하는 항목으로 이동(typeahead) |
| Esc | 닫고 버튼으로 포커스 복귀 |

- 항목 이동은 roving tabindex 방식이라 화살표 키로 움직이고, Tab으로 항목을 하나씩 지나가지 않습니다.
- Radix는 일반 항목, 체크박스 항목, 라디오 항목, 그룹, 구분선, 하위 메뉴를 제공하고 위치·충돌 처리를 맡습니다.
- 메뉴는 "동작"을 고르는 위젯입니다. 폼 값을 고르는 선택은 `select`나 Combobox를 씁니다.
- 어떤 내용이든 띄우는 비모달 패널이라면 브라우저의 Popover API가 대안입니다. `popover` 속성과 `popovertarget`으로 선언하고, `auto`는 바깥 클릭·Esc로 닫히며 상단 레이어에 그려집니다. 2025-01부터 최신 브라우저에서 사용 가능한 Baseline입니다.

## Tabs

Tabs는 여러 패널 중 하나만 보여 주는 패턴입니다. APG는 `tablist`, `tab`, `tabpanel` 역할과 `aria-selected`, `aria-controls`를 요구합니다.

```tsx
<Tabs.Root defaultValue="info">
  <Tabs.List aria-label="상품 정보">
    <Tabs.Trigger value="info">정보</Tabs.Trigger>
    <Tabs.Trigger value="review">후기</Tabs.Trigger>
  </Tabs.List>
  <Tabs.Content value="info">...</Tabs.Content>
  <Tabs.Content value="review">...</Tabs.Content>
</Tabs.Root>
```

- 키보드: 좌우 화살표로 탭 이동(세로 목록이면 상하), Home과 End로 처음·끝, Tab은 목록을 벗어나 패널로 이동합니다.
- 활성화 방식이 두 가지입니다. 자동은 포커스가 가면 바로 선택되고, 수동은 Space나 Enter를 눌러야 선택됩니다. 패널이 미리 로드되어 있으면 자동이 권장되며, Radix의 `activationMode` 기본값은 `automatic`입니다.
- 선택된 탭을 URL에 담으면 새로고침과 공유에서 상태가 유지됩니다(자세히는 중급 29편).
- 비활성 패널의 상태를 유지하고 싶으면 숨기는 방식(Activity)을 고려합니다(자세히는 중급 16편).
- 탭은 화면 내 전환이고 링크 이동이 아닙니다. 페이지가 바뀌는 메뉴는 탭이 아니라 내비게이션입니다.

## Accordion

Accordion은 제목을 눌러 해당 내용을 펼치고 접는 세로 목록입니다. APG는 제목 요소 안의 버튼, `aria-expanded`, `aria-controls`를 요구합니다. 버튼은 제목 요소의 유일한 자식이어야 합니다.

| 모드 | Radix 설정 | 동작 |
|------|------------|------|
| 하나만 열림 | `type="single"` | 하나를 열면 나머지가 닫힘 |
| 여럿 열림 | `type="multiple"` | 독립적으로 열고 닫음 |
| 전부 닫기 허용 | `collapsible` | single 모드에서 열린 항목을 다시 눌러 닫을 수 있음 |

- 키보드: Enter와 Space로 토글, Tab으로 이동합니다. Radix는 화살표와 Home·End 이동도 지원합니다.
- 애니메이션 높이는 Radix가 노출하는 CSS 변수 `--radix-accordion-content-height`로 처리합니다.
- 단순한 FAQ라면 브라우저 `details`와 `summary`로 충분합니다. 같은 `name`을 가진 `details`는 하나만 열리는 Accordion이 됩니다. JavaScript가 필요 없습니다.
- Tabs와의 구분은 동시에 여러 개를 볼 수 있는지입니다. Tabs는 하나만, Accordion은 설정에 따라 여럿입니다.

## Tooltip

Tooltip은 요소에 포커스가 가거나 마우스를 올렸을 때 보조 설명을 띄우는 작은 팝업입니다. APG는 `tooltip` 역할을 쓰고 트리거에서 `aria-describedby`로 연결하라고 합니다. Tooltip 자체는 포커스를 받지 않으며 Esc로 닫힙니다.

- Radix Tooltip의 `Provider`가 지연 시간을 정합니다. `delayDuration` 기본값은 700ms, 다른 Tooltip으로 옮겨 갈 때 줄어드는 `skipDelayDuration` 기본값은 300ms입니다.
- Radix 문서는 Tooltip이 터치 인터페이스용이 아니라고 명시합니다. 모바일에서 보이지 않아도 사용에 지장이 없어야 합니다.
- 필수 정보는 Tooltip에 넣지 않습니다. 입력 형식 안내, 에러 메시지처럼 꼭 읽어야 하는 내용은 화면에 항상 보이게 둡니다.
- 아이콘만 있는 버튼은 Tooltip이 아니라 `aria-label`로 이름을 먼저 붙입니다. Tooltip은 보조입니다.
- APG의 Tooltip 패턴은 아직 작업 중이며 합의가 완료되지 않았다고 문서에 명시되어 있습니다. 라이브러리마다 세부 동작이 다를 수 있습니다.

## Toast

Toast는 일시적으로 나타났다 사라지는 알림입니다. 동작이 끝났음을 알릴 때 쓰며, 사라지기 때문에 접근성에 주의가 필요합니다.

- 스크린 리더에는 라이브 영역(`aria-live`)으로 알립니다. `polite`는 다음 적당한 순간에, `assertive`는 즉시 알리므로 중요한 때만 씁니다.
- Radix Toast는 `Provider`, `Viewport`, `Root`, `Title`, `Description`, `Action`, `Close`로 구성됩니다. 사용자가 일으킨 알림은 `foreground`, 시스템 알림은 `background` 유형으로 구분해 알립니다.
- 기본 5초 뒤에 닫히고, 마우스를 올리거나 포커스가 있거나 창이 포커스를 잃으면 타이머가 멈춥니다. F8로 Viewport에 이동할 수 있고 스와이프로 닫을 수 있습니다.
- Toast 안에 동작 버튼을 둘 때는 `altText`로 대체 안내를 줍니다. 5초 안에 못 누르는 사용자가 있기 때문입니다.

```tsx
<Toast.Root duration={5000} type="foreground">
  <Toast.Title>저장했습니다</Toast.Title>
  <Toast.Close>닫기</Toast.Close>
</Toast.Root>
```

**흔한 실수:** 에러를 Toast로만 알려 사라지면 원인을 알 수 없게 만드는 것입니다. 폼 검증 오류는 필드 옆에, 복구가 필요한 오류는 화면에 남깁니다.

## Search

Search는 입력한 문자열로 결과를 보여 주는 패턴입니다. 어려운 부분은 입력할 때마다 결과를 다시 가져오는 비용입니다.

- 입력 값은 바로 반영하고, 결과 계산이나 요청은 늦춥니다. React의 `useDeferredValue`는 지연 값을 따로 만들어 입력은 즉시, 목록은 뒤에 갱신합니다. 고정 지연 시간이 없고 중단 가능해서 기기 성능에 맞춰집니다(자세히는 중급 10편).
- 네트워크 요청 횟수를 줄이는 것은 디바운싱의 영역입니다. 둘의 역할이 다릅니다. 지연 값은 렌더링을, 디바운싱은 요청을 줄입니다.
- 이전 요청 결과가 나중에 도착해 새 결과를 덮는 경쟁 조건에 주의합니다. 서버 상태 도구를 쓰면 쿼리 키 단위로 처리해 줍니다(자세히는 중급 27편).
- 검색어를 URL 쿼리에 담으면 공유와 뒤로 가기가 됩니다(자세히는 중급 29편).
- 로딩 중에는 이전 결과를 흐리게 보여 주고, 결과가 없으면 빈 상태 안내를 보여 줍니다(자세히는 중급 30편).

```tsx
const [query, setQuery] = useState('')
const deferred = useDeferredValue(query)
const stale = query !== deferred
// <Results query={deferred} dim={stale} />
```

## Filter

Filter는 조건(카테고리, 가격대, 상태)으로 목록을 좁히는 패턴입니다.

- 필터 값은 URL 쿼리에 담는 것이 기본입니다. 새로고침, 공유, 뒤로 가기에서 같은 목록을 보여 줍니다(자세히는 중급 29편).
- 필터가 바뀌면 페이지는 첫 페이지로 돌립니다. 3페이지에서 조건을 바꾸면 3페이지가 비어 있을 수 있습니다.
- 현재 적용된 필터를 칩 같은 요소로 화면에 보이고 개별 제거와 전체 초기화를 제공합니다.
- 조건이 확정되는 시점을 정합니다. 체크박스는 즉시 적용, 입력이 많은 필터는 "적용" 버튼으로 모아서 적용하는 방식이 흔합니다.
- 필터링을 어디서 하는지 정해야 합니다. 데이터가 작으면 클라이언트에서, 크거나 페이지로 나뉘어 있으면 서버에 조건을 보냅니다. 서버 필터는 쿼리 키에 조건을 포함시켜 캐시가 조건별로 분리되게 합니다.

## Pagination

Pagination은 긴 목록을 페이지로 나누는 패턴입니다. 방식이 두 가지입니다.

| 방식 | 요청 | 장단점 |
|------|------|--------|
| 오프셋 | 페이지 번호와 크기 | 임의 페이지로 이동 가능. 목록이 변하면 항목이 중복되거나 빠질 수 있음 |
| 커서 | 마지막 항목의 위치 값 | 변화에 안정적. 임의 페이지 이동 불가, 이전·다음 중심 |

- 접근성: 컨테이너를 `nav`로 하고 `aria-label`을 붙이며, 현재 페이지 링크에 `aria-current="page"`를 씁니다. 현재 항목은 하나만 표시합니다.
- 페이지를 URL에 담으면 링크로 공유됩니다.
- 이전 버튼은 첫 페이지에서, 다음 버튼은 마지막에서 비활성화합니다.
- 페이지를 넘기는 동안 이전 페이지 데이터를 보여 주면 화면이 깜빡이지 않습니다(자세히는 중급 28편).

**흔한 실수:** 페이지 번호를 전부 나열해서 수백 개가 되는 것입니다. 현재 주변과 처음·끝만 보입니다.

## Infinite Scroll

Infinite Scroll은 끝에 닿으면 다음 데이터를 이어 불러오는 패턴입니다. 구현은 두 부분입니다.

- 감지: 목록 끝에 보이지 않는 감시 요소를 두고 Intersection Observer로 화면에 들어왔는지 봅니다. `isIntersecting`이 `true`가 되면 다음 페이지를 요청합니다. `rootMargin`을 키우면 끝에 닿기 전에 미리 가져옵니다.
- 데이터: TanStack Query의 `useInfiniteQuery`가 필수 옵션 `initialPageParam`과 `getNextPageParam`을 받고, `data.pages`, `fetchNextPage`, `hasNextPage`, `isFetchingNextPage`를 돌려줍니다.

```tsx
const inView = useIntersecting(sentinelRef) // 직접 만든 Hook
useEffect(() => {
  if (inView && hasNextPage && !isFetchingNextPage) {
    fetchNextPage()
  }
}, [inView, hasNextPage, isFetchingNextPage])
```

- 공식 문서는 진행 중인 요청 위에 `fetchNextPage`를 호출하면 데이터 갱신을 덮어쓸 위험이 있다고 경고합니다. 위 코드처럼 `isFetchingNextPage`를 확인합니다.
- `maxPages` 옵션으로 메모리에 보관할 페이지 수를 제한할 수 있습니다.
- 항목이 수천 개로 쌓이면 DOM이 무거워지므로 가상화를 함께 씁니다(자세히는 중급 21편).
- 단점은 푸터에 닿지 못하고, 위치 복원이 어렵고, 키보드 사용자가 끝없이 Tab을 눌러야 한다는 점입니다. "더 보기" 버튼 방식이 더 안전한 대안이며, 두 방식을 섞기도 합니다.

## File Upload

File Upload는 사용자가 고른 파일을 서버로 보내는 패턴입니다. 기본은 `input type="file"`이며 `accept`, `multiple`, 모바일의 `capture` 속성을 받습니다.

```tsx
<input
  type="file"
  accept="image/png,image/jpeg"
  multiple
  onChange={(e) => setFiles([...e.target.files])}
/>
```

- 선택된 파일은 `files`(FileList)로 읽고, 각 `File`은 `name`, `size`, `type`, `lastModified`를 가집니다.
- `accept`는 파일 선택 창의 힌트일 뿐 검증이 아닙니다. 형식과 크기 검증은 서버가 반드시 다시 해야 합니다(자세히는 23편).
- 이미지 미리보기는 `URL.createObjectURL(file)`로 만듭니다. 이 URL은 해제하기 전까지 메모리를 차지하므로 언마운트나 파일 교체 시 `URL.revokeObjectURL`로 정리합니다.
- 전송은 `FormData`에 파일을 담아 보냅니다. 폼으로 직접 제출하려면 `enctype="multipart/form-data"`가 필요합니다.
- 드래그 앤 드롭 영역을 만들어도 `input type="file"` 경로를 함께 두어 키보드 사용자가 쓸 수 있게 합니다.
- 상태는 대기, 업로드 중, 성공, 실패를 파일별로 관리합니다. 실패한 파일만 다시 시도할 수 있게 합니다.

## Data Table

Data Table은 정렬, 필터, 페이지네이션, 선택 같은 기능이 붙은 표입니다. 로직은 TanStack Table 같은 Headless 엔진에 맡기고 마크업은 직접 씁니다(자세히는 13편).

- `useReactTable`에 `data`, `columns`, `getCoreRowModel`을 넘겨 표 모델을 얻고 `flexRender`로 셀을 그립니다.
- 표는 시맨틱 요소(`table`, `thead`, `th`, `tbody`, `td`)로 마크업하고 `caption`으로 표 제목을 둡니다.
- 정렬 가능한 열의 헤더는 버튼으로 만들고, 현재 정렬된 열의 `th`에만 `aria-sort`를 `ascending` 또는 `descending`으로 둡니다. 다른 열을 정렬하면 속성을 옮깁니다.
- 엔진은 내장 클라이언트 처리를 쓰거나, 서버가 처리한 행을 받아 렌더링하는 두 방식을 모두 지원합니다. 서버가 정렬·필터·페이지를 맡으면 클라이언트에서 같은 처리를 반복하지 않게 하며, 옵션 이름은 공식 문서에서 확인합니다.
- 행이 수천 개면 가상화가 필요합니다(자세히는 중급 21편).
- 좁은 화면(휴대폰)은 가로 스크롤, 열 숨김, 카드 형태 전환 중에서 고릅니다.

## Command Palette

Command Palette는 단축키로 열고 검색해 명령이나 페이지로 바로 이동하는 패턴입니다. 구조는 Dialog 안의 검색 입력과 필터링되는 목록입니다. 접근성은 APG의 Combobox 패턴을 따라 입력에 `role="combobox"`, `aria-expanded`, `aria-controls`, 선택 항목을 가리키는 `aria-activedescendant`를 둡니다.

cmdk는 명령 메뉴용 스타일 없는 React 컴포넌트입니다. 항목을 자동으로 필터링·정렬하고, `Command.Dialog`(내부는 Radix Dialog), `Command.Input`, `Command.List`, `Command.Item`, `Command.Group`, `Command.Empty`, `Command.Loading` 부분으로 조합합니다. shadcn/ui의 Command 컴포넌트가 이 cmdk 위에 만들어져 있습니다.

```tsx
useEffect(() => {
  const fn = (e: KeyboardEvent) => {
    if (e.key === 'k' && (e.metaKey || e.ctrlKey)) {
      e.preventDefault()
      setOpen((o) => !o)
    }
  }
  document.addEventListener('keydown', fn)
  return () => document.removeEventListener('keydown', fn)
}, [])
```

- 단축키는 macOS의 Command와 그 밖의 Ctrl을 모두 받습니다.
- cmdk는 가상화 없이 2,000–3,000개 항목까지 잘 동작한다고 문서가 밝힙니다. 더 많으면 `shouldFilter={false}`로 내장 필터를 끄고 직접 필터링합니다. 서버 검색 결과를 보여 줄 때도 같습니다.
- 항목에 `keywords`를 달면 이름 외의 단어로도 찾아집니다.
- 선택 후 실행할 동작은 항목의 `onSelect`에서 처리하고 Dialog를 닫습니다.
- 입력 필드에서 글자를 칠 때 단축키가 가로채이지 않도록, 열려 있을 때와 입력 중일 때의 동작을 분리합니다.

## 핵심 정리

- Modal은 배경 비활성화, 포커스 가두기·이동·복귀, 닫기 수단을 갖춰야 하며, 브라우저 `dialog` 요소나 Headless 라이브러리를 쓰는 것이 안전합니다.
- Dropdown, Tabs, Accordion, Tooltip은 APG 패턴에 정해진 역할과 키보드 동작이 있고, 단순한 경우 `details` 요소나 Popover API가 대안입니다.
- Toast와 Tooltip은 사라지거나 보이지 않을 수 있으므로 필수 정보를 넣지 않고 라이브 영역과 `aria-describedby`로 알립니다.
- Search와 Filter는 입력 반응과 요청 비용을 분리하고, 조건을 URL에 담아 공유와 복원이 되게 합니다.
- Pagination은 오프셋과 커서 방식을, Infinite Scroll은 감시 요소와 `useInfiniteQuery`를 쓰며 접근성과 가상화를 함께 고려합니다.
- File Upload는 클라이언트 검증이 힌트일 뿐이라 서버 검증이 필수이고, Data Table은 로직(TanStack Table)과 시맨틱 마크업을 나누며, Command Palette는 cmdk 같은 Combobox 기반 구성을 씁니다.
