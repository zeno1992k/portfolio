Web Components는 브라우저가 제공하는 컴포넌트 표준으로, Custom Elements, Shadow DOM, HTML Templates(`template`과 `slot`) 세 기술의 묶음입니다. React 없이 동작하는 표준이라서 React를 쓰지 않는 앱이나 다른 프레임워크와도 같은 컴포넌트를 공유할 수 있습니다. 이 편은 표준의 동작을 먼저 설명하고 React에서 쓰는 방법을 이어 갑니다. 중급 03편의 ref와 Fragment Ref를 알고 있다고 가정합니다.

## Custom Element

Custom Element는 개발자가 정의한 HTML 요소입니다. `HTMLElement`를 상속한 클래스를 만들고 `customElements.define()`으로 태그 이름과 연결합니다.

```js
class UserCard extends HTMLElement {
  connectedCallback() {
    this.textContent = this.getAttribute('name')
  }
}
customElements.define('user-card', UserCard)
// <user-card name="Kim"></user-card> → 텍스트 Kim
```

- 이름은 소문자로 시작하고 하이픈을 반드시 포함해야 합니다(`user-card`). 기존 HTML 요소와 이름이 겹치지 않게 하는 규칙입니다.
- 종류가 두 가지입니다. 자율 요소(autonomous)는 `HTMLElement`를 상속하고 `<user-card>`처럼 씁니다. 사용자 정의 내장 요소(customized built-in)는 `HTMLParagraphElement` 같은 내장 요소를 상속하고 `is="..."` 속성으로 씁니다. 후자는 Safari가 지원하지 않으므로 자율 요소를 씁니다.
- 라이프사이클 콜백은 다음과 같습니다.

| 콜백 | 호출 시점 |
|------|-----------|
| `connectedCallback` | 요소가 문서에 추가될 때 |
| `disconnectedCallback` | 요소가 문서에서 제거될 때 |
| `adoptedCallback` | 다른 문서로 옮겨질 때 |
| `attributeChangedCallback` | 관찰 중인 속성이 바뀔 때 |

- 생성자에서는 `super()`를 가장 먼저 호출하고, 속성이나 자식을 읽거나 추가하지 않습니다. 초기 렌더링 같은 작업은 `connectedCallback`에서 합니다.
- `connectedCallback`은 요소가 문서에 붙을 때마다 호출됩니다. 요소를 옮기면 여러 번 호출되므로 이벤트 리스너 등록은 `disconnectedCallback`에서 해제까지 짝을 맞춥니다.

**흔한 실수:** 생성자에서 `this.getAttribute()`로 속성을 읽는 것입니다. HTML 파서가 요소를 만드는 시점에 속성이 아직 없을 수 있습니다.

## Attribute

속성(attribute)은 마크업에 적히는 문자열 값입니다. HTML에서 `size="10"`으로 쓴 값이며 `getAttribute`/`setAttribute`로 읽고 씁니다. 값은 항상 문자열입니다.

요소가 속성의 변경에 반응하려면 `observedAttributes`에 이름을 등록합니다. 등록된 속성이 바뀌면 `attributeChangedCallback`이 호출됩니다.

```js
class UserCard extends HTMLElement {
  static observedAttributes = ['name']

  attributeChangedCallback(attr, oldValue, newValue) {
    if (attr === 'name') this.textContent = newValue
  }
}
```

- 등록하지 않은 속성은 바뀌어도 콜백이 호출되지 않습니다.
- 불리언 속성은 값이 아니라 있고 없음으로 표현합니다. `hasAttribute`로 확인합니다.
- 속성은 CSS 선택자(`user-card[open]`)로 상태를 표시하기에 좋습니다. 상태를 마크업에 드러내야 하는 값에 씁니다.

React는 속성을 어떻게 다루는지가 다음 절의 프로퍼티와 함께 핵심입니다(아래 "React 19 Custom Element 지원").

**흔한 실수:** 객체나 배열을 속성으로 넘기는 것입니다. 문자열로 변환되어 `[1,2,3]`이 `"1,2,3"`이 됩니다. 복잡한 값은 프로퍼티로 넘깁니다.

## Property

프로퍼티(property)는 요소 객체의 JS 필드입니다. 문자열이 아닌 임의의 값(객체, 배열, 함수)을 담을 수 있고 마크업에는 나타나지 않습니다.

```js
class ItemList extends HTMLElement {
  #items = []
  get items() { return this.#items }
  set items(value) {
    this.#items = value
    this.textContent = value.join(', ')
  }
}
// el.items = ['a', 'b'] → 텍스트 a, b
```

| 구분 | 속성(attribute) | 프로퍼티(property) |
|------|-----------------|---------------------|
| 위치 | 마크업(DOM 노드의 속성 목록) | 요소 객체의 필드 |
| 값 | 문자열 | 모든 JS 값 |
| 읽기·쓰기 | `getAttribute`, `setAttribute` | `el.items` |
| 변경 감지 | `attributeChangedCallback` | getter·setter |

- 속성과 프로퍼티는 자동으로 연결되지 않습니다. 둘을 동기화하려면 요소가 직접 구현합니다. 내장 요소의 `id`나 `value`처럼 반영(reflect)하는 쪽은 setter에서 `setAttribute`를 호출합니다.
- 원시 값이면 속성, 객체·배열·함수면 프로퍼티가 원칙입니다.

**흔한 실수:** 프로퍼티를 속성처럼 `setAttribute('items', JSON.stringify(x))`로 넘기고 요소에서 파싱하게 만드는 것입니다. 동작은 하지만 변환 비용이 들고 직렬화할 수 없는 값은 전달할 수 없습니다.

## Custom Event

Custom Element는 값을 위로 내보낼 때 이벤트를 발생시킵니다. `CustomEvent`를 만들어 `dispatchEvent`로 보냅니다. 부모는 `addEventListener`로 받습니다.

```js
this.dispatchEvent(
  new CustomEvent('item-select', {
    detail: { id: 7 },
    bubbles: true,
    composed: true,
  }),
)
// 리스너: e.detail.id → 7
```

- `detail`에 임의의 값을 실어 보냅니다. 기본은 `null`입니다.
- 이벤트 이름은 대소문자를 구분합니다. `item-select`와 `itemSelect`는 다른 이벤트입니다.
- `bubbles`는 DOM 위로 전파할지, `composed`는 Shadow DOM 경계를 넘을지를 정합니다. 둘 다 `Event`의 옵션이며 따로 지정해야 합니다.
- 이름 규칙은 요소마다 다릅니다. 하이픈 이름(`item-select`)이 일반적이며, 소문자 한 단어, camelCase 등이 쓰입니다. 소비하는 쪽은 정확한 이름을 문서에서 확인해야 합니다.
- 정보는 이벤트(위로)와 프로퍼티·속성(아래로)으로 흐릅니다. React의 단방향 흐름과 같은 구조입니다.

React에서 이 이벤트를 받는 법은 아래 "React 19 Custom Element 지원"에서 설명합니다.

**흔한 실수:** `bubbles`와 `composed`를 빼고 요소 바깥에서 이벤트를 받으려는 것입니다. 부모 요소에 건 리스너가 이벤트를 받지 못합니다.

## Ref 접근

React에서 Custom Element의 메서드를 호출하거나 프로퍼티를 직접 읽으려면 ref로 DOM 요소를 받습니다. ref는 요소 인스턴스를 가리키므로 요소가 노출한 메서드가 그대로 보입니다.

```tsx
function Player() {
  const ref = useRef<HTMLElement & { play(): void }>(null)
  return (
    <>
      <button onClick={() => ref.current?.play()}>
        재생
      </button>
      <media-player ref={ref} src="/a.mp4" />
    </>
  )
}
```

- 선언적으로 표현할 수 없는 동작(재생, 포커스, 열기·닫기)은 메서드 호출로 합니다. 상태로 표현할 수 있는 값은 props로 넘기는 것이 먼저입니다.
- 렌더 중에 `ref.current`를 읽지 않습니다. 이벤트 핸들러나 Effect 안에서만 읽습니다(자세히는 기초 19편).
- ref 콜백은 React 19부터 정리(cleanup) 함수를 반환할 수 있습니다. 표준 리스너를 직접 붙이고 해제하는 데 씁니다(자세히는 중급 03편).

```tsx
<my-element
  ref={(el) => {
    el?.addEventListener('Ready', onReady)
    return () => el?.removeEventListener('Ready', onReady)
  }}
/>
```

- 이 방식은 React가 이벤트 props로 지원하지 않던 시절의 우회였습니다. React 19에서는 `on` 접두사 props로 대부분 해결됩니다.
- TypeScript에서는 요소 타입을 직접 지정해야 메서드가 자동 완성됩니다.

**흔한 실수:** 요소 정의(`customElements.define`)가 끝나기 전에 ref로 메서드를 호출하는 것입니다. 정의 전에는 일반 `HTMLElement`일 뿐이라 메서드가 없습니다.

## Shadow DOM

Shadow DOM은 요소 안에 별도의 DOM 트리를 붙여 스타일과 DOM을 격리하는 기능입니다. 요소 자체가 shadow host이고, 그 안의 트리가 shadow tree이며, 경계가 shadow boundary입니다.

```js
class UserCard extends HTMLElement {
  constructor() {
    super()
    const root = this.attachShadow({ mode: 'open' })
    root.innerHTML =
      '<style>p { color: red }</style><p>Hi</p>'
  }
}
```

- `mode: 'open'`이면 `el.shadowRoot`로 접근할 수 있고, `'closed'`이면 `null`입니다. closed는 보안 장치가 아닙니다.
- 격리 규칙은 다음과 같습니다.

| 대상 | 경계 통과 |
|------|-----------|
| 페이지의 CSS | 안으로 들어가지 못함 |
| Shadow DOM의 CSS | 밖으로 새지 않음 |
| `document.querySelector` | 안쪽 요소를 못 찾음 |
| CSS 변수(`--color`) | 상속되어 통과함 |
| `composed`가 true인 이벤트 | 밖으로 나옴 |
| `id` | 트리 안에서 격리됨 |

- 바깥에서 스타일을 바꾸게 열어 두려면 CSS 변수나 `::part()`를 씁니다. 안쪽 요소에 `part="title"`을 달면 바깥에서 `my-el::part(title)`로 스타일할 수 있습니다.
- `slot`은 바깥(light DOM)의 자식을 shadow tree의 지정한 자리에 끼워 넣습니다. 이름 있는 슬롯은 `slot="title"` 속성으로 채우고, 이름 없는 슬롯은 나머지를 받습니다.
- `attachShadow({ delegatesFocus: true })`는 안쪽 첫 포커스 가능 요소로 포커스를 위임합니다.
- 한 요소에는 shadow root를 한 번만 붙일 수 있습니다.

React와 함께 쓸 때 영향이 큽니다.

- 페이지의 CSS(Tailwind 클래스, CSS Modules)는 shadow tree 안에 적용되지 않습니다. 안쪽 모양은 요소가 정하고 바깥은 CSS 변수와 `part`로만 조정합니다.
- `id`가 격리되므로 바깥 `label`의 `htmlFor`나 `aria-labelledby`가 안쪽 요소를 가리킬 수 없습니다(자세히는 20편).
- `document` 단위 쿼리는 shadow tree 안을 찾지 못하므로, 테스트에서는 `shadowRoot`를 직접 다뤄야 할 수 있습니다.

**흔한 실수:** React 쪽에서 `className`으로 Custom Element 안쪽을 꾸미려는 것입니다. 클래스는 shadow host에만 붙고 안쪽에는 영향을 주지 않습니다.

## React 19 Custom Element 지원

React 19(2024-12)는 Custom Element를 완전히 지원한다고 발표했고, Custom Elements Everywhere 테스트를 모두 통과합니다. 이 편의 규칙은 React 19 발표 글과 react.dev 레퍼런스를 기준으로 합니다. 이전 버전에서는 모르는 props를 모두 속성으로만 처리해서 객체를 넘기면 문자열로 바뀌었습니다.

React는 두 가지로 요소를 Custom Element로 인식합니다. 태그 이름에 하이픈이 있거나, 내장 요소에 `is` 속성이 있는 경우입니다.

props 처리 규칙은 렌더링 위치에 따라 다릅니다.

| 위치 | 규칙 |
|------|------|
| 클라이언트 | 요소 인스턴스에 같은 이름의 프로퍼티가 있으면 프로퍼티로 대입, 없으면 속성으로 대입 |
| 서버(SSR) | 문자열·숫자·`true`는 속성으로 출력. 객체·심벌·함수·`false`는 생략 |

```tsx
// items 프로퍼티가 정의된 요소라면 배열이 그대로 전달된다
<item-list items={['a', 'b']} />
// 프로퍼티가 없는 요소라면 속성이 된다(문자열로 변환)
```

- 판단 기준은 인스턴스에 프로퍼티가 정의되어 있는지입니다. 요소 정의가 렌더링보다 늦으면 프로퍼티가 없어서 속성으로 처리될 수 있으므로, 요소 정의를 앱 시작 시점에 먼저 등록합니다.
- 서버에서는 객체와 함수가 생략되므로, 그런 값에 의존하는 초기 화면은 서버 출력에 나타나지 않습니다. 클라이언트에서 프로퍼티로 대입된 뒤에 완성됩니다.

이벤트는 `on` 접두사 props로 연결합니다. React는 이름이 `on`으로 시작하는 함수 prop에 이벤트 리스너를 등록합니다.

```tsx
<my-element onspeak={(e) => log(e.detail.message)} />
<my-element onsay-hi={handleHi} />   {/* say-hi 이벤트 */}
<my-element onsayHi={handleSayHi} /> {/* sayHi 이벤트 */}
```

- 이벤트 이름은 대소문자를 구분하고 하이픈을 지원합니다. 요소가 발생시키는 이름 그대로 써야 합니다.
- `CustomEvent`의 `detail`은 `e.detail`로 읽습니다.
- 앞 절의 ref 콜백으로 직접 리스너를 붙이는 방식은 더 이상 필수가 아닙니다.
- 내장 요소의 이벤트는 기존처럼 `onClick` 같은 React 이벤트로 씁니다.

**흔한 실수:** 이벤트 이름의 대소문자를 바꿔 쓰는 것입니다. `onSayHi`는 `sayhi`가 아니라 `SayHi` 이벤트를 듣습니다. 요소가 발생시키는 이름과 정확히 일치해야 합니다.

## Design System 통합

Web Components로 만든 디자인 시스템은 React, Vue, 순수 HTML 어디서나 같은 요소를 쓰게 합니다. React 19에서는 별도 래퍼 없이 JSX로 직접 쓸 수 있습니다. 통합하는 쪽이 정해야 할 것은 다섯 가지입니다.

| 주제 | 방법 |
|------|------|
| 데이터 전달 | 원시 값은 속성, 객체·배열은 프로퍼티. React 19는 규칙으로 자동 판단 |
| 이벤트 | 요소의 이벤트 이름을 문서에서 확인해 `on` 접두사 props로 연결 |
| 스타일 | 디자인 토큰은 CSS 변수, 세부 변경은 `::part()` |
| 자식 콘텐츠 | React의 자식을 슬롯으로. `slot` 속성으로 위치 지정 |
| 폼 | `ElementInternals`로 폼 참여 |

```tsx
<ds-select
  value={sel}
  onds-change={(e) => setSel(e.detail)}
>
  <span slot="label">상태</span>
  <ds-option value="all">전체</ds-option>
</ds-select>
```

- 토큰: 색과 간격을 CSS 변수로 제공하면 shadow 경계를 통과해 앱의 테마와 맞출 수 있습니다. 앱 쪽 CSS 클래스는 안쪽에 닿지 않습니다.
- 폼: 일반 Custom Element는 `form`에 참여하지 않습니다. `static formAssociated = true`와 `attachInternals()`로 `setFormValue`, `setValidity`를 구현해야 값이 제출되고 검증됩니다. 이 요건을 지키는지 확인합니다.
- 접근성: 역할과 이름을 `ElementInternals`의 ARIA 프로퍼티로 선언할 수 있습니다. 안쪽 id 격리, 포커스 이동(`delegatesFocus`), 키보드 동작을 요소가 책임지는지 확인합니다(자세히는 13편, 20편).
- SSR: Declarative Shadow DOM(`template`에 `shadowrootmode`)으로 shadow tree를 서버 HTML에 포함시킬 수 있습니다. 다만 React의 서버 출력은 객체 props를 생략하므로(앞 절), 초기 화면이 그 값에 의존하면 불완전합니다(자세히는 01편, 03편).
- 타입: TypeScript에서는 요소 이름과 props를 JSX 타입에 선언해야 자동 완성과 검사가 됩니다.
- 선택 기준: 여러 프레임워크가 공존하는 조직이거나 장기간 유지할 공용 컴포넌트라면 Web Components가 맞습니다. React만 쓰는 팀은 React 컴포넌트 기반(Headless 포함)이 데이터 흐름과 테스트에서 더 자연스럽습니다(자세히는 13편, 22편).

**흔한 실수:** React 컴포넌트처럼 `style`과 `className`으로 안쪽을 조정할 수 있다고 가정하는 것입니다. 노출된 CSS 변수와 `part`가 전부입니다. 디자인 시스템을 설계하는 쪽이 어디를 열어 둘지 문서화해야 합니다.

## 핵심 정리

- Custom Element는 `HTMLElement`를 상속해 `customElements.define()`으로 등록하는 하이픈 포함 이름의 요소이며, 초기 작업은 생성자가 아니라 `connectedCallback`에서 합니다.
- 속성은 마크업의 문자열이고 `observedAttributes`와 `attributeChangedCallback`으로 반응하며, 프로퍼티는 임의의 값을 담는 객체 필드로 둘은 자동 동기화되지 않습니다.
- 값은 속성·프로퍼티로 내려가고 `CustomEvent`가 `detail`에 값을 실어 위로 올라오며, 경계를 넘으려면 `bubbles`와 `composed`가 필요합니다.
- Shadow DOM은 페이지 CSS와 `querySelector`를 차단하고 CSS 변수와 `composed` 이벤트만 통과시키므로, 바깥 스타일링은 CSS 변수와 `::part()`로 합니다.
- React 19는 클라이언트에서 인스턴스에 프로퍼티가 있으면 프로퍼티로, 없으면 속성으로 대입하고, 서버에서는 원시 값만 속성으로 출력하며, `on` 접두사 props로 이벤트 이름 그대로 리스너를 등록합니다.
- 디자인 시스템 통합은 토큰(CSS 변수), 이벤트 이름, 슬롯, 폼 참여(`ElementInternals`), 접근성과 SSR 제약을 확인합니다.
