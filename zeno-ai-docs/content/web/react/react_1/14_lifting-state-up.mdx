## Lifting State Up

State 끌어올리기(lifting state up)는 두 컴포넌트가 함께 쓰는 State를 각자에게서 빼서 가장 가까운 공통 부모로 옮기는 작업입니다. 부모가 State를 갖고 props로 내려보내며, 자식은 변경이 필요할 때 부모가 준 핸들러를 호출합니다.

패널 두 개 중 하나만 펼치고 싶다면 각 패널이 자기 `isActive`를 가져서는 안 됩니다. 세 단계로 옮깁니다.

**1단계. 자식에서 State를 제거하고 props로 받습니다.**

```jsx
// 전: Panel 안에 useState(false)로 isActive를 가짐
function Panel({ title, children, isActive, onShow }) {
  return (
    <section>
      <h3>{title}</h3>
      {isActive ? (
        <p>{children}</p>
      ) : (
        <button onClick={onShow}>Show</button>
      )}
    </section>
  );
}
```

**2단계. 공통 부모가 고정값을 넘겨 props의 모양을 확정합니다.**

```jsx
<Panel title="About" isActive={true}>...</Panel>
<Panel title="Etymology" isActive={true}>...</Panel>
```

**3단계. 부모에 State를 추가하고 변경 핸들러를 내려보냅니다.**

```jsx
function Accordion() {
  const [activeIndex, setActiveIndex] = useState(0);
  return (
    <>
      <Panel
        isActive={activeIndex === 0}
        onShow={() => setActiveIndex(0)}
      />
      <Panel
        isActive={activeIndex === 1}
        onShow={() => setActiveIndex(1)}
      />
    </>
  );
}
```

- 이제 한 패널의 Show를 누르면 부모의 `activeIndex`가 바뀌고, 다시 렌더된 두 패널이 새 `isActive`를 받아 서로 맞게 열리고 닫힙니다.
- 패널이 가진 정보 하나(`isActive`)가 두 개로 보이지 않고 부모의 숫자 하나로 정리된 점에 주목합니다. 불리언 두 개 대신 인덱스 하나를 둔 것이 State 구조 설계(12편)의 결과입니다.

## 공유 State

공유 State는 둘 이상의 컴포넌트가 읽거나 바꾸는 값입니다. 서로 다른 컴포넌트에서 같은 값이 필요하면 각자 State를 두지 말고 하나만 두고 나눠 씁니다.

- 컴포넌트끼리는 State를 직접 주고받을 수 없습니다. 값은 props로 내려가는 길만 있으므로, 공유하려면 공통 조상에 State를 둡니다.
- 공유할 값이 무엇인지 찾는 방법은 간단합니다. 어떤 값이 바뀔 때 화면의 두 곳 이상이 함께 바뀌어야 한다면 그 값이 공유 State입니다.
- 조상이 멀어 props를 여러 층 넘겨야 하면 Context(24편)나 상태 라이브러리를 검토합니다.

## Source of Truth

Source of Truth는 어떤 값의 기준이 되는 단 하나의 원본입니다. 각 State 조각마다 그것을 소유하는 컴포넌트가 하나 있고, 다른 컴포넌트는 그 값을 복사하지 않고 props로 받아 씁니다.

```jsx
// ❌ 같은 정보를 두 곳에 보관
const [items, setItems] = useState(initialItems);
const [selectedItem, setSelectedItem] = useState(items[0]);

// ✅ 원본은 items 하나, 선택은 id만 보관
const [selectedId, setSelectedId] = useState(0);
const selectedItem = items.find(i => i.id === selectedId);
```

- 같은 정보가 둘 이상의 State에 있으면 하나만 갱신했을 때 어긋납니다. 계산해서 얻을 수 있는 값은 State로 두지 않고 렌더 중에 구합니다(12편).
- 모든 State가 한 곳에 모여야 하는 것은 아닙니다. 조각마다 소유자가 하나이기만 하면 됩니다.

## 형제 공유

형제 컴포넌트가 같은 값을 쓰면 둘의 부모에 State를 둡니다. 한 형제는 값을 바꾸고 다른 형제는 그 값으로 표시합니다.

```jsx
function Catalog({ products }) {
  const [query, setQuery] = useState('');
  const shown = products.filter(p =>
    p.name.includes(query));
  return (
    <>
      <SearchBox query={query} onQueryChange={setQuery} />
      <ProductList products={shown} />
    </>
  );
}
```

- `SearchBox`와 `ProductList`는 서로를 모릅니다. 둘 다 부모와만 props로 연결되어 있습니다.
- `shown`은 State가 아니라 `products`와 `query`에서 렌더 중에 계산한 값입니다.
- 공통 부모가 마땅치 않으면 State를 담당하는 컴포넌트를 새로 만들어도 됩니다. 그 컴포넌트가 두 형제의 부모가 됩니다.

## Controlled Component

제어 컴포넌트(controlled component)는 자기 State가 아니라 props로 동작이 정해지는 컴포넌트입니다. 반대로 자기 State로 동작하고 부모가 관여할 수 없는 컴포넌트는 비제어 컴포넌트(uncontrolled component)입니다.

| 구분 | 값의 출처 | 부모 쪽 조정 |
|------|-----------|--------------|
| 제어 | props | 부모가 값과 동작을 완전히 정함 |
| 비제어 | 자기 State | 부모가 직접 바꿀 수 없음 |

- 위의 처음 `Panel`(자기 `isActive`를 가짐)은 비제어이고, 끌어올린 뒤의 `Panel`은 제어 컴포넌트입니다.
- 비제어는 쓰기 쉽습니다. 부모가 신경 쓸 것이 없습니다. 제어는 유연합니다. 여러 컴포넌트를 부모가 조율할 수 있지만 부모가 props를 모두 정해 주어야 합니다.
- 컴포넌트를 쓸 때는 어떤 정보를 props로 제어하고 어떤 정보를 자기 State로 둘지 정합니다. 나중에 바꾸는 리팩터링도 가능합니다.
- 폼의 `input`에도 같은 구분이 있습니다. `value`와 `onChange`로 State가 입력값을 정하면 제어이고, DOM이 값을 갖게 두면 비제어입니다(자세히는 15편).

## 동기화 State

동기화 State는 같은 정보를 두 곳에 두고 둘을 일치시키려고 만든 State입니다. 끌어올리기로 피해야 할 대상입니다. 가장 흔한 형태는 props를 State로 복사하는 것입니다.

```jsx
function Display({ value }) {
  // ❌ 첫 렌더의 value만 복사된다
  const [shown, setShown] = useState(value);
  return <p>{shown}</p>;
}
```

- `useState`의 초기값은 첫 렌더 이후에는 무시됩니다. 부모가 `value`를 바꿔도 `shown`은 그대로여서 두 값이 어긋납니다.
- 해결은 복사를 없애는 것입니다. props를 그대로 쓰거나, 계산한 값을 변수로 둡니다. 두 컴포넌트가 같은 값을 쓰면 State는 부모 한 곳에 두고 양쪽이 props로 받습니다.
- 값이 어긋나는 문제를 Effect로 맞추려는 코드(`useEffect`에서 `setShown`)도 같은 문제를 더 복잡하게 만듭니다. 대부분 State를 하나로 줄이면 해결됩니다(22편).
- 부모가 바꾼 prop에 맞춰 자식의 State를 비우고 싶을 때는 자식에 key를 줍니다(13편).

## State 소유권

State를 소유한다는 것은 그 State를 선언하고(`useState`) 값을 바꾸는 권한을 갖는 것입니다. 소유자만 값을 바꿀 수 있고 나머지는 부모가 내려준 핸들러를 호출해 변경을 요청합니다.

- 소유자는 값을 props로 내려보내고, 자식은 읽기만 합니다. props는 자식이 바꿀 수 없습니다(05편).
- 트리 아래쪽 컴포넌트는 입력 중인 글처럼 자기만 쓰는 State를 소유하는 경우가 많고, 위쪽 컴포넌트는 여러 곳이 함께 쓰는 State를 소유합니다.
- 소유자는 고정되지 않습니다. 앱이 커지며 필요한 곳이 바뀌면 State를 위나 아래로 옮깁니다.
- 소유자가 정해지면 변경을 일으키는 코드(핸들러)도 소유자가 갖습니다. 값은 내려가고 변경 요청은 올라갑니다(아래 "역방향 데이터 흐름").

## State 위치 선정

State의 위치는 그 State로 화면을 그리는 컴포넌트들의 가장 가까운 공통 부모에 둡니다. 순서는 세 단계입니다.

1. 그 State를 바탕으로 무언가를 렌더하는 컴포넌트를 모두 찾습니다.
2. 그 컴포넌트들의 가장 가까운 공통 부모를 찾습니다.
3. State를 둘 곳을 정합니다. 보통은 공통 부모에 두고, 필요하면 그 위 컴포넌트에 둡니다. 적당한 컴포넌트가 없으면 State만 담당하는 컴포넌트를 새로 만듭니다.

```jsx
function FilterableProductTable({ products }) {
  const [filterText, setFilterText] = useState('');
  // SearchBar와 ProductTable이 모두 filterText를 쓴다
  // -> 가장 가까운 공통 부모가 소유
}
```

- 필요 이상으로 높이 두지 않습니다. 위에 둘수록 State가 바뀔 때 다시 렌더되는 범위가 커지고 props를 넘겨야 하는 층이 늘어납니다.
- State를 바꾸는 쪽과 읽는 쪽이 모두 같은 부모 아래에 있는지가 판단의 핵심입니다.

## State 끌어내리기

State 끌어내리기(colocation)는 State를 그것을 쓰는 컴포넌트 가까이로 되돌리는 작업입니다. 끌어올렸지만 지금은 한 곳만 쓰거나, 처음부터 한 곳만 쓰는 State는 그 컴포넌트가 소유합니다.

```jsx
function App() {
  return (
    <>
      <SignupForm />   {/* firstName State를 여기서 소유 */}
      <PageContent />  {/* 키 입력마다 다시 렌더되지 않는다 */}
    </>
  );
}
```

- 입력 State를 `App`에 두면 글자를 칠 때마다 페이지 전체가 다시 렌더됩니다. `SignupForm` 안으로 내리면 그 폼만 다시 렌더됩니다.
- 끌어올림과 끌어내림은 반대 방향의 같은 판단입니다. 쓰는 컴포넌트가 늘면 올리고, 줄면 내립니다.

## 역방향 데이터 흐름

React의 데이터는 부모에서 자식으로만 내려갑니다(단방향 데이터 흐름). 자식이 부모의 State를 바꾸려면 부모가 setter나 핸들러를 props로 내려주고, 자식이 이벤트에서 그것을 호출합니다. 값은 아래로, 변경 요청은 위로 흐르는 것이 역방향 데이터 흐름입니다.

```jsx
<SearchBar
  filterText={filterText}
  onFilterTextChange={setFilterText}
/>

// SearchBar 안
<input
  value={filterText}
  onChange={(e) => onFilterTextChange(e.target.value)}
/>
```

- 핸들러 이름은 `onXxxChange`처럼 자식 입장에서 "무슨 일이 일어났는지"를 나타내는 이름을 쓰고, 부모가 `setXxx`를 연결합니다(08편).
- 자식은 부모가 State를 어떻게 바꾸는지 모릅니다. 부모는 핸들러에 어떤 검증이나 변환을 더해도 됩니다.
- 자식이 부모 State를 직접 바꾸는 경로는 없습니다. 반드시 핸들러를 거칩니다.

## 핵심 정리

- 두 컴포넌트가 같은 State를 쓰면 가장 가까운 공통 부모로 옮기고 props로 내려보냅니다. 방법은 자식 State 제거, 고정값 확인, 부모 State와 핸들러 추가의 세 단계입니다.
- 같은 정보는 한 곳에만 둡니다. 계산할 수 있는 값은 State로 두지 않고, props를 State로 복사하지 않습니다.
- 제어 컴포넌트는 props로, 비제어 컴포넌트는 자기 State로 동작이 정해집니다. 부모가 조율해야 하면 제어로 바꿉니다.
- State의 소유자는 그 State로 렌더하는 컴포넌트들의 가장 가까운 공통 부모이며, 한 곳만 쓰게 되면 그 컴포넌트로 내립니다.
- 값은 props로 내려가고 변경 요청은 부모가 준 핸들러를 호출해 올라갑니다.
