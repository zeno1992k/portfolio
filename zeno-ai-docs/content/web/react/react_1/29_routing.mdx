## Client-side Routing

클라이언트 사이드 라우팅은 페이지를 이동할 때 서버에 새 HTML을 요청하지 않고, 브라우저의 JavaScript가 주소(URL)를 바꾸고 그 주소에 맞는 컴포넌트를 렌더링하는 방식입니다. 싱글 페이지 앱(SPA)이 쓰는 방식입니다(자세히는 01편).

- 브라우저의 History API가 바탕입니다. `history.pushState()`와 `replaceState()`는 페이지를 다시 불러오지 않고 주소 표시줄과 방문 기록만 바꿉니다. 이 둘은 `popstate` 이벤트도 일으키지 않습니다.
- 뒤로 가기, 앞으로 가기를 누르면 `popstate` 이벤트가 발생합니다. 라우터가 이 이벤트를 듣고 현재 주소에 맞는 화면을 다시 그립니다.
- 라우터가 해 주는 일은 다음과 같습니다. 주소를 패턴과 비교해(매칭) 렌더링할 컴포넌트를 고르고, 링크 클릭을 가로채 `pushState`로 바꾸고, 주소의 값(경로 변수, 쿼리)을 컴포넌트에 전달합니다.
- 일반 `a` 링크와 달리 State가 유지되고 깜박임이 없습니다. 대신 앱을 처음 열 때 어느 주소로 들어와도 같은 `index.html`이 열려야 합니다. 서버나 호스팅이 모든 경로를 `index.html`로 보내도록 설정해야 하며, 설정이 없으면 새로고침이나 주소 직접 입력이 404가 됩니다.
- React 자체에는 라우팅이 없습니다. 라이브러리를 고르며, 이 문서는 React Router를 기준으로 합니다.

### React Router의 세 모드

React Router(패키지 `react-router`)의 현재 버전은 8.4.0입니다. 세 가지 모드를 제공하며, 모드는 아래로 갈수록 기능이 더해집니다.

| 모드 | 최상위 API | 더해지는 것 |
|------|-----------|-------------|
| Declarative | `BrowserRouter` | 주소와 컴포넌트 매칭, 이동. 기본 라우팅 |
| Data | `createBrowserRouter` + `RouterProvider` | `loader`, `action`, 대기 상태. 라우트 설정이 React 렌더링 밖으로 이동 |
| Framework | Vite 플러그인(`@react-router/dev/routes`) | 타입 안전성, 자동 코드 분할, SPA·SSR·정적 렌더링 선택 |

- Declarative: JSX로 `Routes`와 `Route`를 선언합니다. 기존 React 앱에 라우팅만 얹을 때 알맞습니다. 이 문서의 기본 예제입니다.
- Data: 라우트를 객체 배열로 정의하고 `RouterProvider`에 넘깁니다. 데이터 로딩을 라우트에 붙입니다.
- Framework: 프레임워크처럼 `app/routes.ts`에서 라우트를 설정하고 렌더링 전략까지 고릅니다. SSR은 이 과목 범위 밖입니다(고급 과목).
- 어느 모드든 `import`는 `react-router`에서 합니다. v8에서 `react-router-dom` 패키지가 제거되었습니다. 오래된 예제의 `react-router-dom` import는 `react-router`로 바꿔 읽습니다.
- v8의 최소 요구 사항은 React 19.2.7 이상, Node 22.22 이상입니다.
- 설치는 `npm i react-router`이고, Declarative 모드는 앱 루트를 `BrowserRouter`로 감쌉니다.

```jsx
import { BrowserRouter } from 'react-router'

createRoot(root).render(
  <BrowserRouter>
    <App />
  </BrowserRouter>,
)
```

## Route

Route는 URL 패턴과 그 패턴에서 보여 줄 컴포넌트의 짝입니다. `Routes` 안에 `Route`를 나열하면 현재 주소와 맞는 하나가 렌더링됩니다.

```jsx
import { Routes, Route } from 'react-router'

function App() {
  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/about" element={<About />} />
    </Routes>
  )
}
```

- `path`는 URL 경로 패턴이고, `element`는 렌더링할 요소입니다(컴포넌트 이름이 아니라 JSX 요소).
- 같은 레벨에 맞는 Route가 없으면 아무것도 렌더링되지 않습니다(아래 "404").
- Data 모드에서는 같은 설정을 객체로 씁니다. `element` 대신 `Component`에 컴포넌트를 넘깁니다.

```jsx
const router = createBrowserRouter([
  { path: '/', Component: Home },
  { path: '/about', Component: About },
])
// render(<RouterProvider router={router} />)
```

## Nested Route

중첩 라우트는 Route 안에 Route를 넣어 URL의 앞부분을 공유하는 화면을 부모와 자식으로 구성하는 것입니다. 부모 컴포넌트가 `Outlet`을 두면 그 자리에 자식 화면이 들어갑니다.

```jsx
<Routes>
  <Route path="dashboard" element={<Dashboard />}>
    <Route index element={<Overview />} />
    <Route path="settings" element={<Settings />} />
  </Route>
</Routes>
```

```jsx
function Dashboard() {
  return (
    <div>
      <h1>Dashboard</h1>
      <Outlet /> {/* Overview 또는 Settings */}
    </div>
  )
}
```

- `/dashboard`에서는 `Dashboard` 안에 `Overview`(index 라우트)가, `/dashboard/settings`에서는 `Settings`가 렌더링됩니다.
- `index`는 부모 주소와 정확히 같을 때 기본으로 보일 자식입니다. `path`는 없습니다.
- 자식의 `path`는 부모 기준 상대 경로라서 앞에 `/`를 붙이지 않습니다.
- `Outlet`은 맞는 자식이 있으면 그 요소를, 없으면 `null`을 렌더링합니다. 부모가 `Outlet`을 두지 않으면 자식이 보이지 않습니다.
- `Outlet`의 `context` Props로 부모가 자식 라우트에 값을 줄 수 있습니다. 자식은 `useOutletContext`로 읽습니다.
- 경로 접두사만 공유하고 부모 화면은 필요 없다면 `element` 없이 `path`만 둡니다.

```jsx
<Route path="projects">
  <Route index element={<ProjectList />} />
  <Route path=":pid" element={<Project />} />
</Route>
```

## Layout Route

레이아웃 라우트는 `path` 없이 `element`만 가진 Route입니다. URL을 늘리지 않고 여러 자식 라우트가 같은 틀(헤더, 사이드바)을 공유하게 합니다.

```jsx
<Route element={<MainLayout />}>
  <Route index element={<Home />} />
  <Route path="contact" element={<Contact />} />
</Route>
```

```jsx
function MainLayout() {
  return (
    <>
      <Header />
      <main><Outlet /></main>
    </>
  )
}
```

- 주소는 `/`와 `/contact`로 그대로입니다. 레이아웃은 주소에 영향 없이 감싸기만 합니다.
- 라우트 단위로 레이아웃이 다르면 이 구조로 나눕니다. 예를 들어 로그인 화면은 헤더가 없는 레이아웃, 나머지는 헤더가 있는 레이아웃입니다.
- 레이아웃 컴포넌트는 자식 라우트 사이를 이동해도 다시 마운트되지 않고 `Outlet`의 내용만 바뀝니다. 레이아웃 안의 State는 유지됩니다(자세히는 13편).
- Framework 모드에서는 `routes.ts`의 `layout()`이 같은 역할입니다.

## Dynamic Segment

동적 세그먼트는 경로의 일부를 변수로 만드는 패턴입니다. `:이름` 형태로 쓰고, 컴포넌트에서 `useParams()`로 값을 읽습니다.

```jsx
<Route path="posts/:postId" element={<Post />} />
```

```jsx
import { useParams } from 'react-router'

function Post() {
  const { postId } = useParams()
  return <h1>Post {postId}</h1> // /posts/42 이면 42
}
```

- 값은 항상 문자열(또는 `undefined`)입니다. 숫자가 필요하면 직접 변환합니다(`Number(postId)`).
- 세그먼트를 여러 개 둘 수 있습니다. `/c/:categoryId/p/:productId`는 `categoryId`, `productId` 두 값을 줍니다.
- 부모 라우트의 변수는 자식에서도 읽습니다.
- 변수 끝에 `?`를 붙이면 선택 세그먼트입니다. `:lang?/categories`는 `/categories`와 `/ko/categories` 모두 맞습니다.
- `*`는 나머지 경로 전체를 받는 스플랫(catch-all)입니다. `files/*`의 나머지는 `params['*']`로 읽습니다.

```jsx
const { '*': filePath } = useParams()
// /files/a/b.txt 이면 'a/b.txt'
```

- 같은 컴포넌트가 `/posts/1`에서 `/posts/2`로 바뀌면 컴포넌트는 새로 마운트되지 않고 Props와 params만 바뀝니다. 그래서 `postId`에 따라 데이터를 가져오는 Effect는 의존성에 `postId`를 넣어야 합니다(자세히는 21편). 화면 State를 초기화하려면 `key={postId}`를 씁니다(자세히는 13편).

**흔한 실수:** `useParams` 값을 `useState` 초기값으로 복사해 두는 것입니다. 주소가 바뀌어도 State는 처음 값 그대로입니다. params에서 바로 읽습니다.

## Search Params

Search Params는 URL의 `?` 뒤에 오는 쿼리 문자열(`?q=react&page=2`)입니다. React Router는 `useSearchParams`로 읽고 바꿉니다. State와 비슷하게 `[값, 세터]`를 돌려줍니다.

```jsx
import { useSearchParams } from 'react-router'

function Search() {
  const [searchParams, setSearchParams] = useSearchParams()
  const q = searchParams.get('q') ?? '' // 없으면 null
  const page = Number(searchParams.get('page') ?? 1)
  // ...
}
```

- `searchParams`는 표준 `URLSearchParams` 객체입니다. 값은 문자열이고 없으면 `null`입니다. 참조는 안정적이라 Effect의 의존성에 쓸 수 있습니다.
- `setSearchParams`는 URL을 바꾸는 이동(navigation)입니다. 기본적으로 방문 기록에 새 항목이 쌓입니다.

```jsx
setSearchParams({ q: 'react', page: '1' }) // 객체
setSearchParams((prev) => {
  prev.set('page', '2')
  return prev
}) // 함수로 기존 값에 덧붙이기
```

- 객체를 넘기면 기존 쿼리 전체를 교체합니다. 일부만 바꾸려면 함수형으로 기존 값에서 시작합니다.
- 같은 틱에 `setSearchParams`를 여러 번 불러도 `useState`의 업데이터 함수처럼 쌓이지 않습니다. 한 번에 모아서 부릅니다.
- `searchParams`를 직접 고치기만 하고 `setSearchParams`를 부르지 않으면 URL이 바뀌지 않습니다.
- 검색어, 필터, 정렬, 페이지 번호, 선택된 탭처럼 새로고침이나 링크 공유로 복원돼야 하는 상태는 URL이 단일 정보원이 됩니다. 이때 같은 값을 `useState`에 복제하지 않습니다(자세히는 12편의 State 구조 설계).
- 입력창과 연결하면 타이핑마다 방문 기록이 쌓이므로 검색 폼은 제출할 때 갱신하거나 디바운스합니다(자세히는 26편).

## Navigation

이동(navigation)은 주소를 바꾸고 해당 화면으로 전환하는 일입니다. 사용자가 누르는 링크는 `Link`, 코드로 이동할 때는 `useNavigate`를 씁니다.

| 상황 | 도구 |
|------|------|
| 사용자가 누르는 링크 | `Link`, `NavLink` |
| 이벤트 처리 뒤 이동(로그인 성공, 저장 완료) | `useNavigate` |
| 렌더링 결과로 이동(보호 라우트, 리다이렉트) | `Navigate` 컴포넌트 |
| Data·Framework 모드의 로더·액션 | `redirect()` |

```jsx
import { useNavigate } from 'react-router'

function LoginForm() {
  const navigate = useNavigate()
  async function handleSubmit() {
    await login()
    navigate('/dashboard')
  }
  // ...
}
```

- `navigate('/path')`는 새 항목을 쌓고 이동합니다. `{ replace: true }`를 주면 현재 항목을 교체해서 뒤로 가기로 돌아올 수 없습니다. 로그인 직후 로그인 화면으로 돌아오지 않게 할 때 씁니다.
- `navigate(-1)`은 한 단계 뒤로, `navigate(1)`은 앞으로 갑니다. 방문 기록에 해당 항목이 없을 수 있으므로 조심해서 씁니다.
- 옵션 `state`로 값을 넘길 수 있고 도착한 쪽에서 `useLocation().state`로 읽습니다. 새로고침해도 방문 기록에 남지만, URL 밖에 있는 값이라 공유되지 않습니다.
- `{ pathname, search, hash }` 객체로 목적지를 지정할 수도 있습니다.
- 공식 문서는 일반 이동에는 `Link`/`NavLink`를 쓰라고 합니다. 키보드, 접근성, 컨텍스트 메뉴 같은 브라우저 기능이 유지되기 때문입니다. `useNavigate`는 사용자의 클릭 없이 이동해야 할 때(폼 제출 뒤, 타이머)만 씁니다.
- `navigate`는 이벤트 핸들러나 Effect 안에서 호출합니다. 렌더링 중에 호출하지 않습니다.

## Link

`Link`는 클라이언트 이동을 하는 링크 컴포넌트입니다. 화면에는 일반 `a` 태그로 렌더링되고, 클릭을 가로채 페이지 새로고침 없이 이동합니다.

```jsx
import { Link, NavLink } from 'react-router'

<Link to="/dashboard">Dashboard</Link>
<Link to="/login" replace>Login</Link>
<Link to="?tab=one" preventScrollReset>Tab 1</Link>
```

- 앱 안의 이동에는 `a href` 대신 `Link`를 씁니다. `a`는 서버에 새 문서를 요청해 페이지 전체를 다시 불러오고 State를 잃습니다.
- `a` 태그라서 Ctrl 클릭(새 탭), 우클릭 메뉴, 스크린 리더 같은 표준 링크 기능이 그대로 동작합니다.
- 주요 Props는 다음과 같습니다.

| Props | 뜻 |
|-------|----|
| `to` | 목적지. 문자열 또는 `{ pathname, search, hash }` |
| `replace` | 방문 기록 항목을 쌓지 않고 교체 |
| `state` | 이동과 함께 전달할 값 |
| `reloadDocument` | 클라이언트 이동 대신 전체 페이지를 새로 불러옴 |
| `preventScrollReset` | 이동 시 스크롤을 맨 위로 되돌리지 않음 |

- `to`가 `/`로 시작하지 않으면 현재 라우트 기준 상대 경로입니다.
- 외부 사이트로 가는 링크는 일반 `a` 태그를 씁니다.

`NavLink`는 현재 주소와 맞을 때 활성 상태를 알려 주는 `Link`입니다. 메뉴처럼 현재 위치를 표시할 때 씁니다.

```jsx
<NavLink
  to="/messages"
  className={({ isActive }) => (isActive ? 'on' : 'off')}
>
  Messages
</NavLink>
```

- 활성일 때는 기본으로 `active` 클래스가 붙습니다. `className`, `style`, 자식(children)에 함수를 넘기면 `isActive`로 직접 정할 수 있습니다.
- `/` 같은 짧은 경로의 `NavLink`는 `/trending`에서도 활성이 되므로 `end` Props로 정확히 일치할 때만 활성으로 만듭니다.

```jsx
<NavLink to="/" end>Home</NavLink>
```

## 404

404 라우트는 어느 Route와도 맞지 않는 주소에서 보여 줄 화면입니다. `path="*"`(스플랫)로 마지막에 둡니다.

```jsx
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="*" element={<NotFound />} />
</Routes>
```

- `*`는 나머지 경로 전체를 받는 스플랫이라, 다른 Route가 맞지 않는 주소를 받아 줍니다. 읽기 쉽게 맨 아래에 둡니다.
- 레이아웃 라우트 안에 두면 404 화면에도 헤더와 사이드바가 유지됩니다.
- Data 모드는 객체로 `{ path: '*', Component: NotFound }`, Framework 모드는 `route('*', './not-found.tsx')`로 씁니다.
- 클라이언트 라우터가 보여 주는 404 화면은 서버의 HTTP 상태 코드와 무관합니다. 서버는 모든 경로에 `index.html`을 200으로 돌려주는 경우가 많습니다. 검색 엔진에 404를 알려야 하면 서버 렌더링 같은 별도 구성이 필요합니다(고급 과목).
- `/posts/9999`처럼 형태는 맞지만 데이터가 없는 경우는 라우트 매칭이 아니라 데이터 조회의 결과입니다. 컴포넌트에서 데이터가 없을 때 `NotFound`를 렌더링하는 식으로 따로 처리합니다.

## Redirect

리다이렉트는 사용자를 다른 주소로 자동 이동시키는 일입니다. 기본 경로를 다른 곳으로 보내거나, 로그인하지 않은 사용자를 로그인 화면으로 보낼 때 씁니다.

```jsx
<Route
  path="/old"
  element={<Navigate to="/new" replace />}
/>
```

- `Navigate`는 렌더링되면 `to`로 이동하는 컴포넌트입니다. `replace`를 주어 이전 주소가 방문 기록에 남지 않게 하는 것이 일반적입니다. 남기면 뒤로 가기가 다시 리다이렉트를 일으켜 갇힙니다.
- 공식 문서는 `Navigate`를 `useNavigate`의 컴포넌트 버전으로 설명하며 가능하면 `useNavigate`를 쓰라고 안내합니다. 보호 라우트나 옛 경로 이전처럼 렌더링 결과로 이동하는 경우에는 `Navigate`가 간단합니다.
- Data 모드와 Framework 모드에서는 로더나 액션에서 `redirect()`를 던지거나 반환합니다. 화면을 그리기 전에 이동하므로 잠깐 보였다 바뀌는 깜박임이 없습니다.

```jsx
async function protectedLoader() {
  if (!isLoggedIn()) throw redirect('/login')
  return null
}
```

- `redirect()`는 Declarative 모드에서는 쓸 수 없습니다. 기본 상태 코드는 302입니다.
- 사용자가 준 값(`?next=...`)으로 이동시키면 외부 사이트로 보내는 오픈 리다이렉트 취약점이 됩니다. 허용한 내부 경로인지 검증합니다.

## Route Code Splitting

라우트 코드 분할은 라우트별로 JavaScript를 나눠서 처음 열 때 필요한 화면의 코드만 내려받게 하는 것입니다. 첫 로딩에 받는 번들이 작아집니다.

Declarative 모드에서는 React의 `lazy`와 `Suspense`를 씁니다.

```jsx
import { lazy, Suspense } from 'react'

const Settings = lazy(() => import('./Settings'))

<Route
  path="settings"
  element={
    <Suspense fallback={<p>Loading...</p>}>
      <Settings />
    </Suspense>
  }
/>
```

- `lazy(load)`의 `load`는 `import()`로 모듈을 가져와 기본 내보내기(default export)에 컴포넌트가 있는 Promise를 반환해야 합니다.
- `lazy`는 컴포넌트 안이 아니라 모듈 최상위에서 선언합니다. 컴포넌트 안에 두면 렌더링마다 새 컴포넌트가 되어 State가 초기화됩니다.
- 로딩 중 보여 줄 화면은 `Suspense`의 `fallback`입니다. 로딩 실패는 가장 가까운 Error Boundary로 갑니다. 이 과목은 `lazy`와 `fallback`까지만 다루고 Suspense 전반은 중급 과목에서 다룹니다.
- Data 모드에서는 라우트 객체의 `lazy` 속성에 모듈을 동적으로 가져오는 함수를 줍니다.

```jsx
{
  path: 'app',
  lazy: async () => {
    const { Component, loader } = await import('./app')
    return { Component, loader }
  },
}
```

- Framework 모드는 라우트 모듈 단위로 자동 코드 분할을 합니다.
- 분할 기준은 화면 단위(라우트)가 가장 자연스럽습니다. 처음 보이는 홈 화면은 분할하지 않고, 자주 안 쓰는 설정이나 관리자 화면을 나눕니다.

## 보호 라우트

보호 라우트는 로그인 같은 조건을 만족해야만 들어갈 수 있는 라우트입니다. 조건을 확인하는 레이아웃 라우트를 만들어 조건을 만족하면 `Outlet`을, 아니면 `Navigate`를 렌더링합니다.

```jsx
function RequireAuth() {
  const { user } = useAuth() // Auth Context (24편)
  const location = useLocation()
  if (!user) {
    const from = { from: location }
    return <Navigate to="/login" state={from} replace />
  }
  return <Outlet />
}
```

```jsx
<Route element={<RequireAuth />}>
  <Route path="dashboard" element={<Dashboard />} />
  <Route path="settings" element={<Settings />} />
</Route>
```

- 보호할 라우트를 `RequireAuth` 레이아웃 아래에 묶으면 조건 확인 코드가 한 곳에만 있습니다.
- `state`에 원래 가려던 위치(`location`)를 실어 보내면 로그인 후 `useLocation().state.from`으로 되돌아갈 수 있습니다.
- 로그인 정보를 서버에서 확인하는 중(첫 로드)에는 `user`가 아직 없는 것과 로그인하지 않은 것을 구분해야 합니다. 로딩 상태에서 `Navigate`로 보내면 로그인한 사용자도 로그인 화면으로 튕깁니다. 로딩 중에는 로딩 화면을 렌더링합니다.
- 프런트엔드의 보호는 화면을 가릴 뿐입니다. 번들은 누구나 내려받으므로 코드를 읽을 수 있고 API 호출은 직접 보낼 수 있습니다. 실제 권한 검증은 반드시 서버 API가 합니다(권한별 화면 분기는 06편).
- Data 모드에서는 로더에서 `redirect('/login')`으로, 미들웨어에서 인증 검사로 처리할 수 있습니다.

## 스크롤 복원

스크롤 복원은 페이지를 이동하거나 뒤로 갈 때 스크롤 위치를 알맞게 되돌리는 동작입니다. 새 페이지로 이동하면 맨 위로, 뒤로 가기하면 떠났던 위치로 가는 것이 일반적인 기대입니다.

- 일반 웹 페이지는 브라우저가 처리합니다. SPA는 페이지를 새로 불러오지 않으므로 라우터가 이 동작을 대신해야 합니다.
- Data·Framework 모드에는 `ScrollRestoration` 컴포넌트가 있습니다. 루트 컴포넌트에 한 번 두면 방문한 위치별 스크롤을 `sessionStorage`에 저장하고, 뒤로·앞으로 가기나 다시 방문할 때 복원합니다. Declarative 모드에서는 쓸 수 없습니다.

```jsx
function Root() {
  return (
    <>
      <Outlet />
      <ScrollRestoration />
    </>
  )
}
```

- `getKey`로 복원 기준을 바꿉니다. 기본은 방문 항목마다 고유한 `location.key`이고, `location.pathname`을 쓰면 같은 경로를 다시 방문할 때 같은 위치로 갑니다.
- `Link`와 `navigate`의 `preventScrollReset` 옵션을 주면 이동해도 스크롤이 맨 위로 가지 않습니다. 탭을 쿼리로 바꿀 때 유용합니다.

```jsx
navigate('?tab=2', { preventScrollReset: true })
```

- Declarative 모드에서 맨 위로 이동시키는 동작이 필요하면 `useLocation`의 `pathname`이 바뀔 때 `window.scrollTo(0, 0)`을 호출하는 컴포넌트를 직접 만듭니다.

```jsx
function ScrollToTop() {
  const { pathname } = useLocation()
  useEffect(() => {
    window.scrollTo(0, 0)
  }, [pathname])
  return null
}
```

## 핵심 정리

- 클라이언트 사이드 라우팅은 JavaScript가 History API로 주소를 바꾸고 주소에 맞는 컴포넌트를 렌더링하며, 서버는 모든 경로에 `index.html`을 돌려줘야 합니다.
- React Router 8.4.0은 Declarative(`BrowserRouter`), Data(`createBrowserRouter`), Framework(Vite 플러그인) 세 모드이고, `react-router`에서 import합니다.
- `Route`는 `path`와 `element`의 짝이며, 자식 라우트는 부모의 `Outlet`에 들어가고, `path` 없는 레이아웃 라우트는 URL을 늘리지 않고 틀을 공유합니다.
- 동적 세그먼트는 `:id`와 `useParams`(값은 문자열), 쿼리는 `useSearchParams`로 읽고 URL을 바꿉니다. 공유와 복원이 필요한 상태는 URL에 둡니다.
- 사용자 이동은 `Link`/`NavLink`, 코드 이동은 `useNavigate`, 렌더링 결과 이동은 `Navigate`, 로더 이동은 `redirect()`이며, 404는 `path="*"`입니다.
- 코드 분할은 `lazy`+`Suspense`(또는 Data 모드의 `lazy` 속성), 보호 라우트는 `Outlet`/`Navigate` 레이아웃으로 만들고 실제 권한 검증은 서버가 합니다. 스크롤 복원은 `ScrollRestoration`(Declarative 제외)입니다.
