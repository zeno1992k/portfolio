## Global CSS

Global CSS는 일반 `.css` 파일을 만들어 앱 전체에 적용하는 방식입니다. React는 CSS를 추가하는 방법을 정해 두지 않으며, 컴포넌트에는 `className`으로 클래스를 붙이고 규칙은 CSS 파일에 씁니다.

```css
/* index.css */
.avatar {
  border-radius: 50%;
}
```

```jsx
import './index.css'

function Avatar() {
  return <img className="avatar" src="/me.png" alt="me" />
}
```

- Vite는 `.css` 파일을 `import`하면 `style` 태그로 페이지에 주입하고, 개발 중에는 저장하면 바로 반영(HMR)합니다. 비동기 청크가 쓰는 CSS는 별도 파일로 분리합니다.
- 규칙은 파일을 가져온 컴포넌트에만 적용되는 것이 아니라 페이지 전체에 적용됩니다. 어느 컴포넌트에서 `import`했는지와 무관합니다.
- 리셋, 기본 타이포그래피, `:root`의 CSS 변수처럼 앱 전체에 걸린 규칙을 두기에 알맞습니다.
- 클래스 이름이 전역이라 서로 다른 컴포넌트가 `.title`을 쓰면 충돌합니다. 우선순위(명시도)가 같으면 나중에 로드된 규칙이 이기므로 import 순서에 따라 결과가 달라집니다.
- 컴포넌트 단위 스타일에 쓰려면 이름 규칙(예: `.card-title`)으로 충돌을 피해야 하고, 규모가 커지면 관리가 어려워집니다. 그 한계를 푸는 것이 CSS Modules입니다.

## CSS Modules

CSS Modules는 CSS 파일의 클래스 이름을 그 파일 안으로 한정(지역 범위)하는 방식입니다. 파일 이름이 `.module.css`로 끝나면 Vite가 CSS Module로 처리합니다.

```css
/* Card.module.css */
.title {
  font-weight: 700;
}
```

```jsx
import styles from './Card.module.css'

function Card() {
  return <h2 className={styles.title}>Title</h2>
}
```

- `import`하면 클래스 이름을 키로 가진 객체가 돌아옵니다. 빌드가 이름을 고유하게 바꿔서 다른 파일의 `.title`과 충돌하지 않습니다.
- 클래스 이름을 객체 프로퍼티로 쓰기 때문에 존재하지 않는 이름은 `undefined`가 되어 오타를 찾기 쉽습니다.
- 하이픈이 있는 이름은 `styles['card-title']`로 접근합니다. 설정 `css.modules.localsConvention`을 camelCase로 바꾸면 `styles.cardTitle`처럼 쓸 수 있습니다.
- 일반 CSS 문법 그대로라서 `:hover`, 미디어 쿼리, 의사 요소를 모두 쓸 수 있습니다.
- Sass 같은 전처리기는 별도 패키지를 설치해야 쓸 수 있습니다.
- 클래스를 여러 개 합칠 때는 템플릿 문자열이나 `clsx`를 씁니다(아래 "조건부 클래스").

**흔한 실수:** 전역 규칙을 CSS Module에 쓰려는 것입니다. 지역 범위로 바뀌므로 `body`나 `:root` 같은 전역 규칙은 Global CSS 파일에 둡니다.

## Inline Style

Inline Style은 `style` 프로퍼티로 요소 하나에 직접 스타일을 지정하는 방식입니다. HTML의 문자열과 달리 JavaScript 객체를 넘기고, 프로퍼티는 camelCase로 씁니다.

```jsx
<img
  style={{
    width: user.imageSize,
    fontWeight: 700,
    backgroundColor: '#eee',
  }}
/>
```

- 숫자는 `px`로 해석됩니다(`width: 100`은 `100px`). 단위 없는 속성(`lineHeight`, `opacity` 등)은 그대로 둡니다. 다른 단위는 문자열로 씁니다(`width: '50%'`).
- 문자열을 넘기면 안 됩니다. `style="width: 100px"`는 오류이고 `style={{ width: '100px' }}`가 맞습니다.
- 공식 문서는 `style`을 동적 값(상태나 Props에 따라 바뀌는 값)에만 쓰고 정적 스타일은 `className`과 CSS 파일로 쓰라고 합니다.
- CSS 한계도 있습니다. `:hover` 같은 의사 클래스, 의사 요소, 미디어 쿼리를 쓸 수 없습니다. 인라인 스타일은 우선순위가 높아 클래스 규칙으로 덮어쓰기도 어렵습니다.
- CSS 변수를 값으로 넘기는 용도로 유용합니다(아래 "CSS Variables").

```jsx
<div style={{ '--progress': percent + '%' }} />
```

## CSS-in-JS

CSS-in-JS는 JavaScript 코드 안에서 스타일을 쓰고 컴포넌트에 연결하는 방식입니다. 대표 라이브러리가 styled-components와 Emotion입니다. styled-components는 템플릿 리터럴로 실제 CSS 문법을 쓰고, 스타일이 붙은 컴포넌트를 만듭니다.

```jsx
import styled from 'styled-components'

const Button = styled.button`
  padding: 8px 16px;
  background: ${(p) => (p.$primary ? 'blue' : 'gray')};
`
// <Button $primary>Save</Button>
```

- 컴포넌트와 스타일이 한 파일에 있고 Props로 값을 바꾸기 쉽습니다. 스타일 이름 충돌이 없습니다.
- 런타임 라이브러리입니다. 브라우저에서 JavaScript가 실행되며 스타일을 계산하고 `style` 태그로 주입합니다. 그만큼 번들 크기와 실행 비용이 듭니다.
- React는 CSS-in-JS 라이브러리 제작자를 위해 `useInsertionEffect`를 제공합니다. 레이아웃 계산 전에 스타일을 주입하기 위한 Hook이며, 라이브러리를 만드는 경우가 아니면 쓰지 않습니다.
- 이 과목에서는 개념과 위치만 다룹니다. 라이브러리별 문법은 각 문서를 따릅니다. 런타임 비용 없이 같은 목적을 이루려는 방식이 컴파일 타임에 CSS를 만드는 Tailwind입니다.
- 새 프로젝트를 시작할 때는 사용하려는 라이브러리가 쓰는 React 버전과 렌더링 방식(서버 렌더링 등)을 지원하는지 그 라이브러리의 문서에서 확인합니다.

## Tailwind CSS

Tailwind CSS는 `flex`, `p-4`, `text-center` 같은 작은 유틸리티 클래스를 `className`에 조합해 스타일을 쓰는 CSS 프레임워크입니다. 별도 CSS 파일을 만들지 않고 마크업 안에서 스타일이 끝납니다.

```jsx
function Card({ title }) {
  return (
    <div className="rounded-lg bg-white p-4 shadow">
      <h2 className="text-lg font-bold">{title}</h2>
    </div>
  )
}
```

- 현재 버전은 v4(문서 기준 4.3)입니다. Vite에서는 `tailwindcss`와 `@tailwindcss/vite`를 설치하고, `vite.config`의 `plugins`에 `tailwindcss()`를 추가하고, CSS 파일에 `@import "tailwindcss";`를 씁니다.
- 빌드할 때 소스 파일을 훑어 실제로 쓴 클래스 이름만 CSS로 만듭니다. 런타임 비용이 없는 컴파일 타임 방식입니다.
- 소스를 문자열 그대로 훑으므로 클래스 이름을 조각으로 조립하면 찾지 못합니다. 완성된 이름을 코드에 써야 합니다.

```jsx
// ❌ 조립한 이름
<p className={`text-${color}-500`} />
// ✅ 완성된 이름
const map = { red: 'text-red-500', blue: 'text-blue-500' }
<p className={map[color]} />
```

- `hover:`, `md:`, `dark:` 같은 접두사(variant)로 상태, 화면 크기, 다크 모드를 같은 클래스 안에서 처리합니다.
- 장점은 이름 짓기와 CSS 파일 이동이 없고 디자인 값이 일관된다는 점이고, 단점은 `className`이 길어지는 점입니다. 반복되는 조합은 컴포넌트로 묶어 재사용합니다.

## Design Token

Design Token은 색, 간격, 글자 크기, 모서리 반경 같은 디자인 결정에 이름을 붙여 둔 값입니다. 코드에서는 값을 직접 쓰지 않고 이름으로 가져다 씁니다.

| 종류 | 예 |
|------|----|
| 색상 | `--color-primary`, `--color-danger` |
| 간격 | `--space-2`, `--space-4` |
| 타이포그래피 | `--font-size-sm`, `--font-sans` |
| 모서리, 그림자 | `--radius-md`, `--shadow-card` |

- 값이 한 곳에 있으므로 브랜드 색이 바뀌어도 토큰 하나만 고치면 전체가 바뀝니다.
- 토큰은 두 단계로 나누는 것이 흔합니다. 원시 값(`--blue-600`)과 쓰임을 가리키는 의미 값(`--color-primary: var(--blue-600)`)입니다. 다크 모드처럼 쓰임은 같고 값만 바뀌는 상황에서 의미 값만 바꾸면 됩니다.
- 웹에서 토큰을 구현하는 기본 수단이 CSS 변수입니다(아래).
- Tailwind v4에서는 `@theme` 안에 `--color-*`, `--font-*`, `--breakpoint-*`, `--spacing-*`, `--radius-*`, `--shadow-*` 같은 이름으로 정의합니다. 이 변수는 `bg-mint-500`, `font-script` 같은 유틸리티 클래스를 만들고 `:root`의 CSS 변수로도 노출됩니다. 유틸리티 클래스가 필요 없는 일반 변수는 `:root`에 씁니다.

```css
@import "tailwindcss";

@theme {
  --color-brand: oklch(0.72 0.11 178);
}
/* bg-brand, text-brand 같은 클래스가 생긴다 */
```

## CSS Variables

CSS 변수(사용자 지정 속성)는 `--이름: 값`으로 선언하고 `var(--이름)`으로 읽는 CSS 기능입니다. 선언한 요소와 그 자손에게 상속되므로 `:root`에 쓰면 전역입니다.

```css
:root {
  --color-primary: teal;
}
.button {
  background: var(--color-primary, gray); /* 둘째 값은 대체값 */
}
.danger {
  --color-primary: crimson; /* 이 안에서만 덮어씀 */
}
```

- 이름은 대소문자를 구분합니다. `--my-color`와 `--My-color`는 다릅니다.
- 값 자리에서만 쓸 수 있고 미디어 쿼리 조건, 선택자, 프로퍼티 이름에는 쓸 수 없습니다.
- 런타임에 바꿀 수 있다는 점이 Sass 변수 같은 빌드 타임 변수와의 차이입니다. 다크 모드 전환, 사용자 테마 선택이 이를 이용합니다.
- React에서 값을 넘기려면 `style`에 변수 이름을 키로 씁니다. 스타일 규칙은 CSS에 두고 값만 State에서 받습니다.

```jsx
<div className="bar" style={{ '--p': percent + '%' }} />
// .bar { width: var(--p); }
```

- JavaScript에서는 `element.style.setProperty('--name', value)`로 바꾸고 `getComputedStyle(element).getPropertyValue('--name')`으로 읽습니다.

## Responsive UI

반응형 UI는 화면 크기에 따라 레이아웃이 달라지는 UI입니다. 기본은 모바일 기준 스타일을 먼저 쓰고, 화면이 넓어질 때 `min-width` 미디어 쿼리로 덮어쓰는 모바일 우선(mobile-first) 방식입니다.

```css
.grid { display: grid; grid-template-columns: 1fr; }
@media (min-width: 768px) {
  .grid { grid-template-columns: 1fr 1fr; }
}
```

Tailwind는 접두사가 없는 클래스를 모든 화면에, 접두사가 붙은 클래스를 그 크기 이상에 적용합니다.

| 접두사 | 최소 너비 |
|--------|-----------|
| `sm` | 40rem (640px) |
| `md` | 48rem (768px) |
| `lg` | 64rem (1024px) |
| `xl` | 80rem (1280px) |
| `2xl` | 96rem (1536px) |

```jsx
<div className="text-center sm:text-left" />
// 모바일은 가운데, 640px 이상은 왼쪽 정렬
```

- `sm:text-center`만 쓰면 640px 이상에서만 가운데가 됩니다. 접두사 없는 클래스가 모바일 기준이라는 점을 놓치기 쉽습니다.
- 구간을 제한하려면 `max-lg:`처럼 `max-*` variant를 씁니다. `md:max-lg:flex`는 md 이상 lg 미만에서만 적용됩니다.
- 뷰포트가 아니라 부모 컨테이너의 크기에 반응하려면 컨테이너 쿼리를 씁니다. 부모에 `@container`를, 자식에 `@md:flex-row` 같은 variant를 붙입니다. 재사용 컴포넌트가 놓이는 자리에 따라 레이아웃이 달라져야 할 때 알맞습니다.
- 화면 크기에 따라 렌더링할 컴포넌트 자체가 달라질 때만 JavaScript로 판단합니다(`useMediaQuery`는 26편). 크기, 숨김 같은 변화는 CSS가 맡는 편이 간단합니다.

## Dark Mode

다크 모드는 어두운 색 테마로 전환하는 기능입니다. 기준은 두 가지입니다. 사용자의 운영체제·브라우저 설정과, 사이트 안에서 사용자가 직접 고른 선택입니다.

`prefers-color-scheme` 미디어 쿼리는 사용자가 라이트 또는 다크를 요청했는지 알려 줍니다. 값은 `light`와 `dark`이고, 선호가 없으면 `light`로 취급합니다.

```css
:root { --bg: white; --fg: black; }
@media (prefers-color-scheme: dark) {
  :root { --bg: #1a1a1a; --fg: #e0e0e0; }
}
body { background: var(--bg); color: var(--fg); }
```

- 색을 CSS 변수에 두고 다크일 때 변수 값만 바꾸는 구조입니다. 컴포넌트 CSS는 `var(--bg)`만 쓰므로 수정할 필요가 없습니다.
- 사용자가 사이트 안에서 직접 고르게 하려면 `html` 요소의 속성(`data-theme`)이나 클래스로 상태를 나타내고 그 선택자로 변수를 바꿉니다.

```css
:root[data-theme='dark'] {
  --bg: #1a1a1a;
  --fg: #e0e0e0;
}
```

```jsx
useEffect(() => {
  document.documentElement.dataset.theme = theme
}, [theme]) // theme: 'light' 또는 'dark' State
```

- 선택값은 `localStorage`에 저장하고(자세히는 26편의 Storage Hook), 값이 없으면 시스템 설정을 따릅니다.
- 페이지가 그려진 뒤에 React가 테마를 적용하면 먼저 밝은 화면이 번쩍이는 현상이 생깁니다. 저장된 테마를 읽어 `html`에 적용하는 짧은 스크립트를 `index.html`에서 먼저 실행해 막습니다.
- Tailwind의 `dark:` variant는 기본으로 `prefers-color-scheme`을 따릅니다. 토글 방식으로 바꾸려면 `@custom-variant dark`로 선택자를 지정합니다.

```css
@import "tailwindcss";
@custom-variant dark (&:where(.dark, .dark *));
```

```jsx
<div className="bg-white dark:bg-black" />
// html에 dark 클래스가 있을 때 검정 배경
```

## Conditional Class

조건부 클래스는 State나 Props에 따라 `className`에 들어갈 클래스를 바꾸는 것입니다. 가장 단순한 형태는 삼항 연산자나 템플릿 문자열입니다.

```jsx
<button className={isActive ? 'btn active' : 'btn'} />
<button className={`btn ${isActive ? 'active' : ''}`} />
```

- `` `btn ${isActive && 'active'}` ``처럼 `&&`를 쓰면 `isActive`가 `false`일 때 클래스에 문자열 `"false"`가 들어갑니다. 값이 `undefined`이면 `"undefined"`가 들어갑니다. 삼항 연산자로 빈 문자열을 명시합니다.
- 조건이 늘면 템플릿 문자열이 읽기 어렵습니다. 이때 `clsx`를 씁니다(아래 "clsx").
- CSS Modules에서는 `styles.active`처럼 객체의 키로 접근하는 값을 조건에 씁니다.

```jsx
className={isActive ? styles.active : styles.idle}
```

- 상태를 `data-` 속성으로 표시하고 CSS가 그 속성으로 스타일을 정하는 방법도 있습니다.

```jsx
<button data-state={isActive ? 'on' : 'off'} />
// button[data-state='on'] { ... }
```

## Style Boundary

스타일 경계는 한 컴포넌트의 스타일이 어디까지 영향을 주고 어디까지 바깥의 영향을 받는지 정한 범위입니다. 경계가 흐리면 한 곳을 고쳤을 때 다른 화면이 깨집니다.

- Global CSS는 경계가 없습니다. 어느 파일의 규칙이든 전체에 적용됩니다.
- CSS Modules는 클래스 이름이 파일 범위로 한정되어 한 컴포넌트의 규칙이 다른 컴포넌트에 새지 않습니다.
- 유틸리티 클래스와 CSS-in-JS는 스타일이 요소에 직접 붙어 경계가 요소 단위입니다.
- 컴포넌트 경계에서 지킬 규칙은 다음과 같습니다.
  - 부모는 자식 컴포넌트의 내부 클래스 이름을 CSS로 직접 선택하지 않는다.
  - 외부에서 조절해야 하는 부분만 `className` Props(필요하면 `style`)로 열어 둔다.
  - 레이아웃(위치, 바깥 여백)은 부모가, 모양(색, 안쪽 여백)은 컴포넌트가 정한다.
  - 전역 규칙은 요소 선택자와 CSS 변수 선언 정도로 한정한다.

```jsx
function Card({ className = '', children }) {
  const cls = 'card ' + className
  return <div className={cls}>{children}</div>
}
// <Card className="mt-4" /> : 부모가 바깥 여백만 지정
```

- 사용하는 쪽이 넘긴 `className`이 내부 클래스와 충돌하는 문제는 Tailwind에서 `tailwind-merge`로 풉니다(아래).
- 외부 스타일이 스며들거나 새는 것을 막으려면 CSS Modules처럼 범위가 한정되는 방식을 고르고, 경계를 넘는 값은 CSS 변수로 전달합니다. CSS 변수는 상속되므로 부모에서 정한 값을 자손이 읽을 수 있는 통로가 됩니다.

## clsx

`clsx`는 조건에 맞는 클래스 이름을 모아 하나의 문자열로 만들어 주는 작은 유틸리티입니다. 거짓 값(`false`, `null`, `undefined`, `0`, `''`)은 걸러 냅니다.

```jsx
import clsx from 'clsx'

clsx('foo', true && 'bar', 'baz')   // 'foo bar baz'
clsx({ foo: true, bar: false })     // 'foo'
clsx(['foo', 0, false, 'bar'])      // 'foo bar'
```

```jsx
<button className={clsx('btn', isActive && 'active', {
  disabled: isLoading,
})} />
```

- 문자열, 객체(키는 클래스, 값은 조건), 배열을 섞어 쓸 수 있습니다.
- 클래스 충돌은 해결하지 않습니다. `clsx('p-2', 'p-4')`는 두 클래스를 모두 남깁니다.

## tailwind-merge

`tailwind-merge`의 `twMerge`는 같은 속성을 건드리는 Tailwind 클래스가 여러 개이면 뒤에 쓴 것만 남겨 충돌을 없애 줍니다.

```jsx
import { twMerge } from 'tailwind-merge'

twMerge('px-2 py-1 bg-red', 'p-3 bg-[#B91C1C]')
// 'p-3 bg-[#B91C1C]'
```

- Tailwind에서 같은 속성의 클래스가 둘 이상이면 어느 것이 이길지는 CSS 안에서 정의된 순서로 정해지고, `className`에 쓴 순서가 아닙니다. 그래서 컴포넌트의 기본 클래스를 `className` Props로 덮어쓰려 할 때 결과가 어긋날 수 있습니다. `twMerge`가 그 결과를 안정적으로 만듭니다.
- Tailwind v4에는 tailwind-merge v3, Tailwind v3에는 v2.6.0을 씁니다.
- 흔한 조합은 `clsx`로 조건을 처리하고 `twMerge`로 충돌을 정리하는 `cn` 함수입니다.

```js
import { clsx } from 'clsx'
import { twMerge } from 'tailwind-merge'

export function cn(...inputs) {
  return twMerge(clsx(inputs))
}
// cn('p-2', isBig && 'p-4', className)
```

## cva

`cva`(class-variance-authority)는 Props 값에 따라 달라지는 클래스 조합(variant)을 선언적으로 정의하는 라이브러리입니다. 버튼의 `intent`, `size`처럼 변형이 정해진 컴포넌트에 씁니다.

```js
import { cva } from 'class-variance-authority'

const button = cva('rounded px-3 py-1', {
  variants: {
    intent: {
      primary: 'bg-blue-600 text-white',
      ghost: 'bg-transparent',
    },
    size: { sm: 'text-sm', lg: 'text-lg' },
  },
  defaultVariants: { intent: 'primary', size: 'sm' },
})
// button({ size: 'lg' }) : 기본 + intent primary + size lg
```

- 인수 두 개를 받습니다. 항상 적용할 기본 클래스(`base`)와 `variants`, `defaultVariants`, `compoundVariants`를 담은 옵션입니다.
- `compoundVariants`는 여러 variant가 동시에 특정 값일 때만 추가할 클래스를 지정합니다.
- `VariantProps` 타입 도우미로 TypeScript의 Props 타입을 만들 수 있습니다.
- 결과는 클래스 문자열이므로 `cn(button({ intent }), className)`처럼 `cn`과 함께 써서 바깥에서 오는 `className`을 합칩니다.
- 변형이 한두 개면 삼항 연산자와 `clsx`로 충분합니다. variant 조합이 많고 여러 컴포넌트에서 반복될 때 `cva`가 가치가 있습니다.

## shadcn/ui의 위치

shadcn/ui는 npm에서 설치하는 컴포넌트 라이브러리가 아니라, 컴포넌트 소스 코드를 CLI(`add` 명령)로 내 프로젝트에 복사해 넣는 방식입니다. 복사된 코드는 내 소유라서 직접 수정합니다.

| 층 | 역할 | 예 |
|----|------|----|
| 스타일 시스템 | 클래스와 토큰 | Tailwind CSS |
| 동작·접근성 | 키보드, 포커스, ARIA | Radix UI |
| 컴포넌트 소스 | 버튼, 다이얼로그 같은 완성 컴포넌트 | shadcn/ui |
| 유틸리티 | 클래스 병합 | `cn` (clsx + tailwind-merge) |

- 위 표에서 shadcn/ui는 Radix UI와 Tailwind CSS 위에 얹혀 있고 `cn` 유틸리티를 포함합니다.
- 일반 라이브러리와 달리 스타일을 덮어쓰려고 wrapper를 만들거나 라이브러리 Props 체계에 맞출 필요가 없습니다. 코드를 직접 고칩니다.
- 대신 업데이트를 자동으로 받지 못하고, 복사한 코드의 유지보수 책임이 프로젝트에 있습니다.
- 이 과목에서는 위치만 소개합니다. 구체적인 사용법은 UI Libraries 과목에서 다룹니다.

## 스타일 방식 선택 기준

| 방식 | 범위 | 런타임 비용 | 잘 맞는 경우 |
|------|------|-------------|--------------|
| Global CSS | 전역 | 없음 | 리셋, 기본 스타일, 토큰 선언 |
| CSS Modules | 파일 단위 | 없음 | 일반 CSS 문법으로 컴포넌트별 스타일 |
| Inline Style | 요소 단위 | 없음 | 동적 값 하나(변수 전달 포함) |
| CSS-in-JS | 컴포넌트 단위 | 있음 | 이미 쓰는 코드베이스, Props 기반 스타일 |
| Tailwind CSS | 요소 단위 | 없음(컴파일 타임) | 빠른 개발, 일관된 디자인 값 |

- 모든 방식은 함께 쓸 수 있습니다. 흔한 조합은 Global CSS(토큰·리셋) + Tailwind 또는 CSS Modules입니다.
- 판단 기준은 다음 순서로 둡니다. 기존 코드베이스와 팀의 방식이 있으면 따른다 → 디자인 시스템이나 shadcn/ui를 쓰면 Tailwind → CSS 문법에 익숙하고 컴포넌트별 분리가 필요하면 CSS Modules → 동적 값만 필요하면 CSS 변수와 `style`.
- 2026년 10월에 조사한 React 채용 공고에서 Tailwind CSS는 반복해서 나오는 요건이었습니다. CSS-in-JS는 기존 프로젝트를 유지보수하며 만날 가능성이 큽니다.
- 같은 요소에 여러 방식을 겹치면 우선순위 때문에 결과를 예측하기 어렵습니다. 한 요소는 한 방식으로 스타일링합니다.

## 핵심 정리

- React는 스타일 방식을 정하지 않습니다. `className`에 클래스를, 동적 값은 `style` 객체(camelCase)에 씁니다.
- Global CSS는 전역이라 충돌 위험이 있고, CSS Modules(`.module.css`)는 클래스 이름을 파일 범위로 한정하며, CSS-in-JS는 런타임 비용이 있고, Tailwind는 컴파일 타임에 쓴 클래스만 만듭니다.
- Design Token은 CSS 변수(Tailwind v4는 `@theme`)로 구현하며, 다크 모드는 변수 값을 `prefers-color-scheme` 또는 `data-theme`로 바꿔 처리합니다.
- 반응형은 모바일 우선입니다. Tailwind는 접두사 없는 클래스가 모바일, `sm:` 등이 그 너비 이상이고, 컴포넌트 기준은 컨테이너 쿼리입니다.
- 조건부 클래스는 `clsx`, 충돌하는 Tailwind 클래스는 `tailwind-merge`, variant 조합은 `cva`로 처리하고, 이 둘을 묶은 것이 `cn`입니다.
- shadcn/ui는 소스를 복사해 소유하는 컴포넌트 모음이며 Tailwind와 Radix UI 위에 있습니다.
