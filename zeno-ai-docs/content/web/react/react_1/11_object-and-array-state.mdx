## 객체 복사

객체 State는 안의 값을 고치지 않고, 복사한 새 객체를 만들어 Setter로 교체합니다. 이전 객체와 새 객체가 서로 다른 참조여야 React가 변경을 감지합니다(자세히는 09편).

```jsx
const [user, setUser] = useState({ name: 'Kim', age: 20 })

user.age = 21              // ❌ 직접 변경
setUser({ name: 'Kim', age: 21 }) // ✅ 새 객체로 교체
```

- 새 객체를 손으로 전부 쓰는 것은 프로퍼티가 늘면 실수하기 쉽습니다. 기존 객체를 복사하는 도구가 스프레드입니다(아래 "Spread").
- 방금 만든 새 객체를 State에 넣기 전에 고치는 것은 괜찮습니다. 이를 지역 변이라 하며 State에 넣은 뒤에만 금지입니다.
- 복사는 얕은 복사(shallow copy)입니다. 최상위 프로퍼티만 새로 만들고 안쪽 객체는 참조를 공유합니다.

```jsx
const next = {}
next.x = e.clientX // ✅ 새 객체는 고쳐도 된다
setPosition(next)
```

## Spread

객체 스프레드(`...`)는 객체의 자기 프로퍼티를 새 객체에 복사하는 문법입니다. 바꿀 프로퍼티를 뒤에 쓰면 같은 키를 덮어씁니다(자세히는 JavaScript 과목 ECMAscript의 36편).

```jsx
setUser({ ...user, age: 21 })
// { name: 'Kim', age: 21 }
setUser({ ...user, age: 21, city: 'Seoul' })
// 새 프로퍼티도 추가된다
```

- `...user`를 앞에 둡니다. 뒤에 두면 바꾼 값이 원본으로 덮입니다.
- Setter는 병합하지 않고 교체합니다. 스프레드 없이 `setUser({ age: 21 })`을 넘기면 `name`이 사라집니다.
- 이전 State에 의존하면 업데이터 함수 안에서 복사합니다.

```jsx
setUser((prev) => ({ ...prev, age: prev.age + 1 }))
```

- 입력 폼처럼 프로퍼티가 많을 때 한 번에 복사해 바꿀 값만 쓰는 방식이 가장 짧습니다.

**흔한 실수:** 스프레드를 빠뜨리고 일부 프로퍼티만 담은 객체를 넘기는 것입니다. 나머지 프로퍼티가 사라져 화면에 `undefined`가 나오는 식으로 드러납니다.

## 중첩 객체 업데이트

중첩된 객체의 안쪽 값을 바꾸려면 그 값에 이르는 경로의 모든 단계를 복사합니다. 스프레드는 한 단계만 복사하기 때문입니다.

```jsx
const [person, setPerson] = useState({
  name: 'Niki',
  artwork: { title: 'Blue Nana', city: 'Hamburg' },
})

setPerson({
  ...person,
  artwork: { ...person.artwork, city: 'New Delhi' },
})
```

- 바꾼 경로(`person`, `person.artwork`)만 새 객체가 됩니다. `name`처럼 바꾸지 않은 값은 그대로 이어받습니다.
- 안쪽 객체를 스프레드하지 않고 `artwork: { city: 'New Delhi' }`만 쓰면 `title`이 사라집니다.
- 객체는 실제로 중첩되어 있지 않습니다. `person.artwork`는 `person` 안에 놓인 것이 아니라 `person`이 그 객체를 가리키는 참조입니다. 그래서 두 객체가 같은 `artwork`를 가리키는 일이 가능합니다.

```jsx
const obj1 = { title: 'Blue Nana' }
const obj2 = { name: 'Niki', artwork: obj1 }
obj1.title = 'X' // obj2.artwork.title도 'X' (같은 객체)
```

- 중첩이 3단계를 넘으면 코드가 길어지고 실수가 늘어납니다. 구조를 평평하게 만드는 정규화(아래)나 Immer를 고려합니다.

## 동적 Property

계산된 프로퍼티 이름(computed property name)은 대괄호 안의 식으로 키를 정하는 문법입니다. 입력창마다 핸들러를 따로 만들지 않고 `name` 속성으로 한 핸들러가 여러 필드를 다룰 때 씁니다.

```jsx
function handleChange(e) {
  setPerson({
    ...person,
    [e.target.name]: e.target.value,
  })
}
// name이 'firstName'인 입력창이면 firstName을 바꾼다
```

- 대괄호 안의 식을 계산한 결과가 키가 됩니다. `[key]: value`에서 `key`가 `'city'`이면 `city: value`와 같습니다.
- 대괄호가 없으면 식이 아니라 글자 그대로의 키가 됩니다. `{ e.target.name: v }`는 문법 오류이고, `{ key: v }`는 `key`라는 이름의 키를 만듭니다.
- 중첩 객체에서는 경로를 단계마다 나눠 복사해야 하므로 필드가 평평한 객체에서만 간단합니다.
- 폼 전체는 15편에서 다룹니다.

```jsx
const key = 'city'
setPerson({ ...person, [key]: 'Seoul' })
```

## 참조 동일성

참조 동일성(referential equality)은 두 값이 메모리에서 같은 객체를 가리키는지 여부입니다. 객체와 배열은 `Object.is`와 `===`가 내용이 아니라 참조를 비교합니다.

```jsx
const a = { x: 1 }
const b = { x: 1 }
a === b          // false (내용은 같아도 다른 객체)
const c = a
a === c          // true (같은 객체)
```

React는 이 비교로 State가 바뀌었는지 판단합니다.

- 참조가 다르면 바뀌었다고 보고 렌더링합니다. 내용이 같아도 새 객체면 렌더링됩니다.
- 참조가 같으면 바뀌지 않았다고 보고 건너뜁니다. 내용을 고쳤어도 같은 객체면 렌더링되지 않습니다.
- 그래서 직접 변경은 화면에 반영되지 않고, 불필요하게 새 객체를 만들면 렌더링이 늘어납니다. 같은 값이면 `set`을 호출하지 않는 편이 좋습니다.
- 바뀌지 않은 부분의 참조를 그대로 유지하면 그 부분은 같은 객체로 남습니다. 이는 이전 값과 비교해 작업을 생략하는 최적화(`memo` 등)의 전제입니다. 성능 최적화는 중급 과목에서 다룹니다.

```jsx
const next = { ...person, name: 'Lee' }
next === person                  // false
next.artwork === person.artwork  // true (공유)
```

## 불변 업데이트

불변 업데이트(immutable update)는 기존 값을 고치지 않고 바뀐 부분만 새로 만들어 교체하는 방식입니다. 객체와 배열 State는 모두 이 방식으로 바꿉니다.

규칙은 세 가지입니다.

1. 기존 객체·배열의 프로퍼티, 요소를 직접 바꾸지 않는다.
2. 바꿀 경로의 모든 객체·배열을 복사해 새로 만든다.
3. 바꾸지 않은 부분은 복사하지 않고 참조를 그대로 공유한다.

```jsx
const next = {
  ...state,                          // 바꾸지 않은 값은 공유
  user: { ...state.user, age: 21 },  // 경로만 새로 만든다
}
```

- 이전 State가 그대로 남아서 변화 과정을 비교할 수 있고, 실행 취소를 구현하기 쉽습니다.
- 전체를 깊은 복사하지 않아도 되므로 비용이 작습니다. 바뀐 경로의 객체 수만큼만 복사합니다.
- 중첩이 깊을수록 코드가 길어집니다. 이것이 Immer 같은 도구의 존재 이유입니다.

## 배열 추가

배열에 요소를 더할 때는 `push`와 `unshift` 대신 스프레드로 새 배열을 만듭니다.

```jsx
setTodos([...todos, newTodo])      // 끝에 추가
setTodos([newTodo, ...todos])      // 앞에 추가
```

```jsx
const i = 1
setTodos([
  ...todos.slice(0, i), // 앞부분
  newTodo,              // 끼워 넣을 항목
  ...todos.slice(i),    // 뒷부분
])
```

- `concat`도 새 배열을 반환하므로 쓸 수 있습니다. `todos.concat(newTodo)`.
- 이전 State에 의존하면 업데이터 안에서 추가합니다. `setTodos((prev) => [...prev, newTodo])`.
- 새 항목의 `id`는 렌더링 중이 아니라 이벤트 핸들러에서 만듭니다(자세히는 07편).

**흔한 실수:**

```jsx
todos.push(newTodo)   // ❌ 직접 변경
setTodos(todos)       // ❌ 같은 참조: 렌더링되지 않음
```

## 배열 삭제

요소를 지울 때는 `pop`, `shift`, `splice` 대신 `filter`나 `slice`로 남길 요소만 모아 새 배열을 만듭니다. 가장 흔한 방법은 `filter`입니다.

```jsx
setTodos(todos.filter((t) => t.id !== id))
// id가 같은 항목만 빠진다
```

- 삭제 기준은 위치(index)보다 `id`가 안전합니다. 목록이 바뀌어도 같은 항목을 가리킵니다.
- 위치로 지울 때는 `filter`의 두 번째 인수나 `slice`를 씁니다.

```jsx
setTodos(todos.filter((_, i) => i !== index))
setTodos([...todos.slice(0, 1), ...todos.slice(2)])
// 둘 다 index 1 하나를 삭제
```

- `splice`는 원본을 바꾸므로 State 배열에 직접 호출하지 않습니다.

## 배열 수정

요소를 바꿀 때는 `arr[i] = x` 대신 `map`으로 바꿀 요소만 새 값으로 두고 나머지는 그대로인 새 배열을 만듭니다.

```jsx
setCounters(
  counters.map((c, i) => (i === index ? c + 1 : c)),
)
// index번째만 1 증가한 새 배열
```

- 요소가 원시값이면 위처럼 값을 바꿔 반환합니다.
- 요소가 객체이면 객체도 복사해야 합니다(아래 "id 기반 수정").
- 한 요소만 바꾸면서 같은 위치를 지정할 수 있다면 `with`도 쓸 수 있습니다(아래 "toSorted·toSpliced·with").

## map

`map`은 배열의 각 요소를 함수에 넣고 반환값으로 새 배열을 만드는 메서드입니다. 원본은 바뀌지 않으며 State 배열을 변환·수정할 때 기본이 됩니다.

```jsx
setPrices(prices.map((p) => p * 2))        // 모든 요소 변환
setItems(items.map((it) => ({ ...it, seen: false })))
```

- 콜백이 반환하는 값이 새 요소입니다. 바꾸지 않을 요소는 그대로 반환하면 같은 참조가 유지됩니다.
- 요소 수가 같은 새 배열이 만들어집니다. 개수를 줄이려면 `filter`를 씁니다.
- 렌더링에서 목록을 JSX로 바꿀 때 쓰는 `map`과 같은 메서드입니다(자세히는 07편).

## filter

`filter`는 조건을 만족하는 요소만 모아 새 배열을 만드는 메서드입니다. 삭제와 조건부 목록 만들기에 씁니다.

```jsx
setTodos(todos.filter((t) => !t.done)) // 완료되지 않은 것만 남김
```

- 콜백이 참인 요소만 남고, 요소 자체는 복사되지 않아 같은 참조입니다.
- 결과가 비어도 빈 배열 `[]`이 반환됩니다.
- 화면에만 필요한 필터 결과는 State에 저장하지 않고 렌더링 중에 계산합니다. 원본 목록만 State로 둡니다(자세히는 12편).

```jsx
const visible = todos.filter((t) => !t.done)
// State는 todos 하나. visible은 렌더링 때 계산
```

## slice

`slice`는 배열의 일부를 복사해 새 배열을 반환하는 메서드입니다. 원본은 바뀌지 않습니다. 이름이 비슷한 `splice`는 원본을 바꾸므로 State에는 `slice`만 씁니다.

```jsx
const a = [1, 2, 3, 4]
a.slice(1, 3) // [2, 3] (원본 a는 그대로)
a.slice()     // [1, 2, 3, 4] (전체 복사)
```

| 메서드 | 원본 | 반환 |
|--------|------|------|
| `slice` | 바꾸지 않음 | 복사한 새 배열 |
| `splice` | 직접 바꿈 | 삭제된 요소 배열 |

- 끝 인덱스는 포함하지 않습니다. `slice(1, 3)`은 인덱스 1과 2입니다.
- 삽입·삭제에서 앞부분과 뒷부분을 나눠 스프레드할 때 씁니다.

## sort 복사

`sort`는 원본 배열을 직접 정렬하는 메서드입니다. State 배열에 바로 쓰지 않고 먼저 복사한 뒤 정렬합니다.

```jsx
const next = [...items]        // 복사
next.sort((a, b) => a.price - b.price)
setItems(next)
```

- `setItems(items.sort(...))`는 원본을 정렬하고 같은 참조를 돌려주므로 렌더링되지 않습니다.
- 복사본은 State에 넣기 전의 새 배열이어서 고쳐도 됩니다(지역 변이).
- 기본 정렬은 문자열 비교입니다. 숫자는 비교 함수가 필요합니다(`[1, 10, 2].sort()`는 `[1, 10, 2]`). 숫자 오름차순은 `(a, b) => a - b`입니다.
- 화면에 정렬된 목록만 필요하면 State를 정렬하지 않고 렌더링 중에 복사해 정렬합니다.

```jsx
const sorted = [...items].sort((a, b) => a.price - b.price)
```

**흔한 실수:** `const sorted = items.sort()`로 받고 `sorted`만 바뀌었다고 생각하는 것입니다. `items`도 이미 정렬되어 State 원본이 변경됩니다.

## reverse 복사

`reverse`도 원본 배열을 직접 뒤집습니다. 정렬과 같은 방식으로 복사한 뒤 뒤집습니다.

```jsx
const next = [...list]
next.reverse()
setList(next)
```

- 렌더링에서만 거꾸로 보여 줄 때는 `[...list].reverse()`를 씁니다.
- `setList(list.reverse())`는 원본을 뒤집고 같은 참조를 넘겨 렌더링되지 않거나, 렌더링되어도 State가 변경된 상태가 됩니다.
- `toReversed()`는 복사하며 뒤집는 메서드입니다(아래 "toSorted·toSpliced·with").

## id 기반 수정

목록의 항목은 위치가 아니라 `id`로 찾아 수정합니다. 요소가 객체이면 `map`으로 대상 하나만 복사해 바꿉니다.

```jsx
setTodos(
  todos.map((t) =>
    t.id === id ? { ...t, done: !t.done } : t,
  ),
)
// id가 같은 항목만 새 객체, 나머지는 같은 참조
```

- 요소 객체를 복사하지 않고 고치면 배열을 복사했어도 State가 변경됩니다. 배열 복사는 얕은 복사이므로 요소 객체는 원래 배열과 같은 객체이기 때문입니다.

```jsx
const next = [...todos]
next[0].done = true // ❌ todos[0]도 같은 객체라 함께 바뀜
setTodos(next)
```

- 수정할 객체가 하나일 때 `id`를 쓰면 위치가 바뀌어도 올바른 항목이 바뀝니다.
- 이전 State에 의존하는 수정은 업데이터 안에서 `map`을 씁니다.

```jsx
setTodos((prev) =>
  prev.map((t) => (t.id === id ? { ...t, text } : t)),
)
```

## 정규화

정규화(normalization)는 중첩된 데이터를 `id`를 키로 하는 평평한 구조로 바꾸는 방법입니다. 중첩 객체를 깊이 복사하는 대신 바꿀 항목 하나와 그 항목을 가리키는 부모만 복사하게 해 줍니다. 구조 설계 관점은 12편에서 이어서 다룹니다.

```jsx
// 중첩: 깊은 항목을 바꾸려면 경로 전체를 복사
{ id: 0, children: [{ id: 1, children: [{ id: 2 }] }] }

// 정규화: id로 바로 접근
{
  0: { id: 0, title: 'Root', childIds: [1] },
  1: { id: 1, title: 'Earth', childIds: [2] },
  2: { id: 2, title: 'Africa', childIds: [] },
}
```

- 정규화된 객체에서 항목 하나를 바꾸는 것은 얕은 갱신이 됩니다.

```jsx
setPlaces({
  ...places,
  [id]: { ...places[id], title: 'Asia' },
})
```

- 삭제할 때는 항목과 그 항목을 가리키던 부모의 `childIds`에서 모두 지웁니다. 객체에서 키를 지울 때는 구조 분해의 Rest로 해당 키를 뺀 나머지를 만듭니다.

```jsx
const { [id]: removed, ...rest } = places
setPlaces(rest) // id 항목이 빠진 새 객체
```

- 같은 데이터가 여러 곳에 중복되면 한쪽만 고치고 다른 쪽을 놓칩니다. `id` 참조는 이 문제를 줄입니다.
- `id`로 바로 접근하므로 배열에서 `find`로 찾는 일이 줄어듭니다.

## Immer 개념

Immer는 변경하는 것처럼 쓴 코드를 불변 업데이트로 바꿔 주는 라이브러리입니다. 복사 코드를 직접 쓰지 않고, 임시 복사본인 draft(초안)를 고치면 Immer가 바뀐 부분만 새로 만든 결과를 돌려줍니다.

```jsx
import { produce } from 'immer'

const next = produce(state, (draft) => {
  draft.user.age = 21     // 변경하듯 쓴다
})
// state는 그대로, next는 바뀐 새 객체
```

- draft는 Proxy입니다. 변경을 기록해 두었다가 `produce`가 끝나면 그 기록으로 새 불변 객체를 만듭니다.
- 바뀌지 않은 부분은 이전 객체와 같은 참조를 유지합니다(구조 공유).
- 결과는 자동으로 얼려져(freeze) 실수로 직접 변경하면 에러가 납니다.
- 일반 JavaScript의 객체, 배열, Set, Map을 그대로 씁니다.
- 외부 의존성이 늘어납니다. State 구조를 평평하게 바꾸기 어렵고 중첩 스프레드가 길어질 때의 대안으로 씁니다.
- Immer는 React 전용이 아닙니다. React에서는 `use-immer`로 편하게 씁니다(아래).

## Immer와 배열

Immer에서는 draft 배열에 `push`, `splice`, 인덱스 대입 같은 변경 메서드를 그대로 쓸 수 있습니다. draft가 원본이 아니기 때문입니다.

```jsx
const next = produce(todos, (draft) => {
  draft.push({ id: 3, title: 'Tweet', done: false }) // 추가
  const t = draft.find((x) => x.id === 1)
  t.done = true                                       // 수정
  draft.splice(0, 1)                                  // 삭제
})
```

- 복사 방식에서는 `map`과 `filter`로 쓰던 것을 변경 메서드로 짧게 쓸 수 있고, 중첩된 요소도 `draft.find`로 찾아 바로 고칩니다.
- 이 변경 메서드는 draft에만 씁니다. State 변수에 직접 쓰면 여전히 금지입니다.
- 배열 위치가 바뀌는 코드(`splice`, `sort`)를 draft에 써도 결과는 새 배열입니다.

## use-immer

`use-immer`는 Immer를 `useState`처럼 쓰게 해 주는 React Hook 라이브러리입니다. `useImmer`는 State와 업데이트 함수 쌍을 반환합니다. 설치는 `npm install immer use-immer`입니다.

```jsx
import { useImmer } from 'use-immer'

const [person, updatePerson] = useImmer({
  name: 'Niki',
  artwork: { city: 'Hamburg' },
})

updatePerson((draft) => {
  draft.artwork.city = 'New Delhi'
})
```

- 업데이트 함수에 함수를 넘기면 draft를 변경하는 생산자로 처리하고, 값을 넘기면 `useState`의 Setter와 같게 동작합니다.
- 이름은 관례로 `updateX`를 씁니다.
- `useImmerReducer`는 `useReducer`의 Immer 버전입니다(자세히는 25편).
- 중첩이 얕고 간단하면 스프레드가 더 가볍습니다. 깊게 중첩되었거나 갱신 로직이 복잡할 때 이점이 큽니다.

## structuredClone

`structuredClone`은 값을 깊이 복사하는 표준 내장 함수(Web API)입니다. 중첩된 객체와 배열을 모두 새로 만듭니다. 2022년 3월부터 주요 브라우저에서 쓸 수 있습니다.

```jsx
const copy = structuredClone(state)
copy.user.address.city = 'Busan'  // state는 영향받지 않음
setState(copy)
```

- 순환 참조도 복제합니다.
- 함수가 있으면 `DataCloneError`가 납니다. DOM 노드도 복제할 수 없습니다.
- 클래스 인스턴스는 프로토타입을 잃고 일반 객체가 됩니다. 메서드가 사라집니다.
- 모든 것을 새로 만들므로 바뀌지 않은 부분의 참조도 달라집니다. 불변 업데이트의 "바뀌지 않은 부분은 공유" 원칙과 다르므로, 렌더링 비교에서 이점이 사라지고 비용이 큽니다.
- State 갱신에는 바뀐 경로만 복사하는 방식이 기본이고, `structuredClone`은 완전히 독립된 복사본이 필요할 때 씁니다.

## toSorted·toSpliced·with

`toSorted`, `toSpliced`, `with`, `toReversed`는 원본을 바꾸지 않고 바뀐 새 배열을 반환하는 복사형 배열 메서드입니다. 2023년 7월부터 주요 브라우저에서 쓸 수 있습니다. 복사 후 변경하던 코드를 한 줄로 줄입니다.

| 변경하는 메서드 | 복사형 메서드 |
|-----------------|---------------|
| `sort` | `toSorted` |
| `reverse` | `toReversed` |
| `splice` | `toSpliced` |
| `arr[i] = x` | `with` |

```jsx
setItems(items.toSorted((a, b) => a.price - b.price))
setList(list.toReversed())
setTodos(todos.toSpliced(1, 0, newTodo))  // 1번 위치에 삽입
setTodos(todos.toSpliced(1, 1))           // 1번 위치 삭제
setCounters(counters.with(2, 10))         // 2번 자리를 10으로
```

- `toSorted`도 비교 함수 없이는 문자열 비교로 정렬합니다. 숫자는 `(a, b) => a - b`를 넘깁니다.
- `with(index, value)`는 인덱스가 범위를 벗어나면 `RangeError`를 던집니다. 음수 인덱스는 끝에서부터 셉니다.
- 복사형 메서드도 얕은 복사입니다. 요소가 객체이면 요소는 같은 참조입니다.
- 실행 환경이 오래된 브라우저를 지원해야 하면 스프레드 방식이 안전합니다.

## 핵심 정리

- 객체와 배열 State는 직접 고치지 않고 복사한 새 값으로 교체하며, React는 `Object.is`로 참조가 달라졌는지 비교해 변경을 감지합니다.
- 객체는 스프레드로 복사하고 바꿀 값을 뒤에 쓰며, 중첩은 바꿀 경로의 모든 단계를 복사합니다. 동적 키는 대괄호로 씁니다.
- 배열은 추가는 스프레드, 삭제는 `filter`, 수정은 `map`을 쓰고 `push`·`splice`·`sort`·`reverse`는 State에 직접 호출하지 않습니다. 정렬과 뒤집기는 복사한 뒤 합니다.
- 배열 복사는 얕은 복사라서 요소 객체를 고치려면 `id`로 찾아 그 객체도 복사해야 합니다.
- 중첩이 깊으면 `id` 기반으로 정규화하거나 Immer(`use-immer`)로 변경하듯 쓸 수 있고, `structuredClone`은 완전한 깊은 복사가 필요할 때만 씁니다.
- `toSorted`·`toReversed`·`toSpliced`·`with`는 원본을 바꾸지 않는 복사형 메서드입니다.
