## Function Component

함수 컴포넌트(function component)는 JSX를 반환하는 JavaScript 함수입니다. 화면의 한 조각을 만드는 데 필요한 마크업, 스타일, 동작을 하나의 단위로 묶습니다.

```jsx
function Profile() {
  return <img src="/kim.png" alt="Kim" />
}
```

- 함수의 매개변수로 Props를 받고, 반환값이 화면에 그려질 내용입니다(Props는 05편).
- 반환할 JSX가 여러 줄이면 괄호로 감쌉니다. 루트는 하나여야 하며, 여러 요소는 `div`나 Fragment로 묶습니다(03편).
- 공식 문서는 컴포넌트가 무언가를 반환해야 한다고 설명합니다. 아무것도 그리지 않으려면 `null`을 반환합니다.
- 클래스 컴포넌트도 지원되지만, 공식 문서는 새 코드에는 함수 컴포넌트를 권합니다. 클래스의 `this.state`, 생명주기 메서드는 각각 `useState`, `useEffect`로 대응됩니다. 이 과목은 함수 컴포넌트만 다룹니다.
- 컴포넌트는 React가 호출합니다. 직접 호출하면 안 됩니다.

```jsx
// ✅ JSX로 사용
<Layout><Article /></Layout>
// ❌ 함수처럼 직접 호출
<Layout>{Article()}</Layout>
```

직접 호출하면 React가 State 같은 기능을 붙이거나 재조정 최적화를 적용할 기회를 잃습니다. 컴포넌트를 쓸 때는 항상 태그로 씁니다.

## 컴포넌트 이름 규칙

컴포넌트 이름은 대문자로 시작해야 합니다. 소문자로 시작하면 `div`, `span` 같은 내장 HTML 태그로 해석됩니다.

```jsx
function Profile() {}   // ✅ <Profile />
function profile() {}   // ❌ <profile />은 HTML 태그로 취급
```

- 관례는 PascalCase입니다(`UserCard`, `ProductList`). 첫 글자만 대문자로 쓰는 것이 필수 규칙이고, 나머지는 팀 관례입니다.
- 파일 이름은 그 안의 주 컴포넌트 이름과 맞추면 찾기 쉽습니다(`Profile.jsx`).
- 이름이 `use`로 시작하는 함수는 컴포넌트가 아니라 Hook입니다(자세히는 26편).

**흔한 실수:** 소문자로 컴포넌트 이름을 짓는 것입니다. `<profile />`은 존재하지 않는 HTML 태그로 해석되어 의도한 컴포넌트가 렌더되지 않습니다.

## 컴포넌트 분리

컴포넌트 분리는 큰 UI를 책임이 분명한 작은 컴포넌트로 나누는 일입니다. 나눌 기준은 공식 문서의 세 관점이 도움이 됩니다.

| 관점 | 질문 |
|------|------|
| 프로그래밍 | 새 함수나 객체를 만들 때처럼, 하나의 일만 하는가 |
| CSS | 클래스 선택자를 따로 붙일 영역인가 |
| 디자인 | 디자인 시안의 레이어 구조로 나뉘는가 |

```jsx
function Gallery() {
  return (
    <section>
      <Profile />
      <Profile />
    </section>
  )
}
```

- 목업의 영역에 박스를 그려 이름을 붙이고, 다른 영역 안에 보이는 것을 자식으로 둡니다.
- 잘 구성된 데이터(JSON)의 구조가 컴포넌트 구조와 대응하는 경우가 많습니다.
- 컴포넌트가 길어져 한 가지 이상의 일을 하면 분리합니다.
- 컴포넌트 안에 다른 컴포넌트를 정의하면 안 됩니다. 부모가 렌더링될 때마다 자식 함수가 새로 만들어져 React가 다른 컴포넌트로 취급하고, State가 초기화되며 성능도 나빠집니다. 항상 최상위에 정의하고 필요한 값은 Props로 넘깁니다(자세히는 13편).

```jsx
// ❌ 안에서 정의
function Gallery() {
  function Profile() {}
}
// ✅ 최상위에서 정의
function Profile() {}
function Gallery() {}
```

**흔한 실수:** 성급하게 잘게 쪼개는 것입니다. 한 곳에서만 쓰고 단순하면 분리의 이점이 작습니다. 책임이 둘 이상이거나 반복될 때 나눕니다.

## 컴포넌트 재사용

같은 컴포넌트를 여러 곳에서 쓰고, Props로 다른 내용을 보여 주는 것이 재사용입니다.

```jsx
function Avatar({ name, size }) {
  return <img alt={name} width={size} />
}

<Avatar name="Kim" size={40} />
<Avatar name="Lee" size={80} />
```

- 재사용은 모양과 동작은 같고 내용만 다른 곳에 쓰기 위한 것입니다. 달라지는 부분은 Props로 받습니다.
- 같은 컴포넌트를 여러 번 쓰면 인스턴스마다 자기 State를 따로 가집니다(자세히는 13편).
- Props가 너무 많아지거나 `if`로 모양을 계속 갈라야 하면 다른 컴포넌트로 나누거나 합성을 고려합니다.
- 컴포넌트는 `export`로 내보내고 `import`로 가져다 씁니다(아래 "default export와 named export").

## 컴포넌트 합성

합성(composition)은 컴포넌트가 다른 컴포넌트나 JSX를 감싸 조합하는 방식입니다. 태그 안에 넣은 내용은 `children`이라는 특별한 Prop으로 전달됩니다.

```jsx
function Card({ children }) {
  return <div className="card">{children}</div>
}

<Card>
  <Avatar name="Kim" size={100} />
</Card>
```

- `children`이 있는 컴포넌트는 부모가 임의의 JSX로 채울 수 있는 빈칸이 있는 것과 같습니다. `Card`는 안에 무엇이 들어올지 몰라도 됩니다.
- 패널, 그리드, 레이아웃 같은 시각적 감싸개에 자주 씁니다.
- 모양을 Props로 일일이 설정하는 대신, 안에 넣는 내용을 바꿔 끼우는 방식이라 유연합니다.
- `children`과 Props 전반은 05편에서 다룹니다.

## 컴포넌트 트리

컴포넌트 트리(렌더 트리)는 한 번의 렌더링에서 컴포넌트가 서로를 포함하는 관계를 나타낸 트리입니다. 컴포넌트만 노드이고 `div` 같은 HTML 태그는 노드가 아닙니다.

```text
App
├─ Header
└─ Gallery
   ├─ Profile
   └─ Profile
```

- 같은 컴포넌트가 트리의 여러 곳에 노드로 나타날 수 있습니다.
- 조건부 렌더링이나 Props 값에 따라 렌더링마다 트리의 모양이 달라질 수 있습니다.
- 모듈 의존성 트리(어느 파일이 어느 파일을 import하는가)와는 다릅니다. 모듈 트리는 정적이고 번들러가 쓰며, 컴포넌트가 children으로 받은 경우 렌더 트리에서는 자식이지만 import는 부모 쪽에서 합니다.
- 루트에 가까운 상위 컴포넌트는 모든 후손의 렌더링 성능에 영향을 주고, 맨 아래의 말단(leaf) 컴포넌트는 자주 다시 렌더링되지만 단순합니다.
- React가 트리를 어떻게 비교하고 갱신하는지는 17편에서 다룹니다.

## Root Component

루트 컴포넌트(root component)는 앱 전체 컴포넌트 트리의 맨 위에 있는 컴포넌트입니다. 처음 렌더링 때 React가 가장 먼저 호출하고, 그 안에서 반환한 컴포넌트를 재귀적으로 호출합니다.

```jsx
// main.jsx
createRoot(document.getElementById('root')).render(<App />)
```

- 관례로 `App`이라는 이름과 `App.jsx` 파일을 씁니다. 이름이 정해져 있는 것은 아닙니다.
- `createRoot`가 만든 루트에 `render`로 넘기는 컴포넌트가 루트 컴포넌트입니다(01편, 02편).
- 다른 컴포넌트는 루트에서 import하거나 루트 안에서 렌더링되는 방식으로 이어집니다.
- Next.js처럼 파일 기반 라우팅을 쓰는 프레임워크는 페이지마다 루트에 해당하는 컴포넌트가 다릅니다.
- 전역 설정(Provider, 레이아웃, StrictMode)은 보통 루트 근처에 둡니다.

## 컴포넌트 책임

컴포넌트의 책임은 그 컴포넌트가 맡는 일의 범위입니다. 공식 문서는 컴포넌트가 이상적으로 한 가지 일에 집중해야 한다는 단일 책임 원칙을 안내합니다.

| 책임 | 하는 일 | 예 |
|------|---------|----|
| 표시 | Props를 받아 화면을 그린다 | `ProductRow` |
| 조립 | 자식 컴포넌트를 배치한다 | `Gallery` |
| 상태 소유 | State를 갖고 자식에게 내려 준다 | `FilterableProductTable` |
| 레이아웃 | 감싸고 `children`을 배치한다 | `Card` |

- 한 컴포넌트가 데이터 가져오기, 상태 관리, 모양을 모두 맡으면 바꾸기 어렵습니다. 나눌수록 재사용하고 이해하기 쉬워집니다.
- State는 그것이 필요한 가장 낮은 공통 부모에 둡니다(자세히는 12편, 14편).
- 표시만 하는 컴포넌트는 Props만 알면 되므로 단독으로 이해하고 테스트하기 쉽습니다.

**흔한 실수:** 한 컴포넌트에 데이터 요청, 변환, 표시를 몽땅 넣는 것입니다. 길이가 아니라 이유가 둘 이상으로 바뀌는지가 분리 신호입니다.

## Pure Component

순수 컴포넌트는 같은 입력(Props, State, Context)이면 항상 같은 JSX를 반환하는 컴포넌트입니다. React는 모든 컴포넌트가 순수 함수라고 가정합니다.

순수 함수의 조건은 두 가지입니다.

- 자기 일만 한다: 호출되기 전에 있던 객체나 변수를 바꾸지 않는다.
- 같은 입력에는 같은 출력을 낸다.

```jsx
function Recipe({ drinkers }) {
  return <p>물 {drinkers}컵, 찻잎 {drinkers}스푼</p>
}
// drinkers가 2면 언제나 같은 결과
```

```jsx
let guest = 0
function Cup() {
  guest = guest + 1          // ❌ 바깥 변수를 바꿈
  return <h2>손님 {guest}번 컵</h2>
}
// 호출할 때마다 결과가 달라짐
```

- 렌더링 중에 방금 만든 지역 변수나 객체를 바꾸는 것(지역 변경, local mutation)은 괜찮습니다. 렌더링마다 새로 만들어지고 기억되지 않기 때문입니다.
- Props, State, Context는 바꾸지 않는 값으로 다룹니다. 바꾸려면 State의 setter를 씁니다(자세히는 09편).
- 렌더링은 같은 입력에 대해 몇 번을 호출해도 같은 결과가 나와야 합니다(멱등성, idempotent).
- 순수해야 하는 이유는 React가 렌더링을 미루거나, 중단하고 다시 시작하거나, 입력이 같으면 건너뛸 수 있도록 하기 위해서입니다. 서버 렌더링처럼 한 컴포넌트를 여러 사용자에게 쓰는 경우에도 안전합니다.
- 개발 중 StrictMode는 컴포넌트를 두 번 호출해서 순수하지 않은 코드를 드러냅니다(자세히는 18편).

```jsx
function Clock() {
  const time = new Date()   // ❌ 호출마다 값이 달라짐
  return <span>{time.toLocaleString()}</span>
}
```

시각처럼 변하는 값을 쓰려면 State와 Effect로 다룹니다(자세히는 20편).

## 렌더 중 Side Effect 금지

부수 효과(side effect)는 렌더링 계산 밖의 세계에 영향을 주는 일입니다. 화면 갱신, 데이터 변경, DOM 직접 수정, 타이머 등록, 네트워크 요청이 해당합니다. 렌더링 중에는 하지 않습니다.

```jsx
function ProductPage({ product }) {
  document.title = product.title   // ❌ 렌더 중 DOM 변경
  return <h1>{product.title}</h1>
}
```

React가 컴포넌트를 언제, 몇 번 호출할지 보장하지 않기 때문입니다. 부수 효과가 렌더링 안에 있으면 의도하지 않은 시점과 횟수로 실행됩니다.

부수 효과가 들어갈 자리는 두 곳입니다.

| 자리 | 용도 |
|------|------|
| 이벤트 핸들러 | 클릭, 입력 같은 사용자 동작에 대한 반응. 첫 번째 선택지 |
| Effect(`useEffect`) | 렌더링 후 외부 시스템과 동기화해야 할 때. 마지막 수단 |

```jsx
function ProductPage({ product }) {
  useEffect(() => {
    document.title = product.title   // ✅ 렌더 후 실행
  }, [product.title])
  return <h1>{product.title}</h1>
}
```

- 이벤트는 08편, Effect는 20편에서 다룹니다.
- StrictMode는 개발 중 컴포넌트를 두 번 호출하므로 렌더링 안의 `console.log`도 두 번 찍힐 수 있습니다.

**흔한 실수:** Props로 받은 배열을 렌더링 중에 `sort()`하는 것입니다. `sort()`는 원본 배열을 바꾸므로 Props를 바꾸는 셈입니다. 복사본(`[...items].sort()`)을 정렬합니다.

## default export와 named export

컴포넌트를 다른 파일에서 쓰려면 내보내야(export) 합니다. 내보내는 방식은 default와 named 두 가지입니다.

| 방식 | 내보내기 | 가져오기 |
|------|----------|----------|
| default | `export default function Button() {}` | `import Button from './Button'` |
| named | `export function Button() {}` | `import { Button } from './Button'` |

- 한 파일에 default export는 하나만, named export는 여러 개 가능합니다.
- default import는 이름을 마음대로 붙일 수 있습니다. named import는 내보낸 이름과 정확히 같아야 하고 중괄호가 필요합니다.
- 한 파일에 주 컴포넌트와 보조 컴포넌트가 있으면 주 컴포넌트는 default로, 나머지는 named로 내보내는 식으로 섞을 수 있습니다.
- 한 프로젝트에서 한 방식으로 통일하는 팀도 많습니다. 공식 문서는 팀에 맞게 고르라고 안내합니다.
- default export는 가져오는 쪽 이름이 제각각이 될 수 있습니다. named export는 이름이 고정되어 검색과 자동 완성에 유리합니다. 이 비교는 정해진 규칙이 아니라 선택 기준입니다.
- 파일 이름은 주 컴포넌트에 맞춥니다. 확장자는 번들러 설정에 따라 생략할 수 있습니다.

## 컴포넌트·엘리먼트·인스턴스 구분

세 용어는 서로 다른 것을 가리킵니다.

| 용어 | 정체 | 예 |
|------|------|----|
| 컴포넌트 | Props를 받아 엘리먼트를 반환하는 함수(또는 클래스) | `function Profile() {}` |
| 엘리먼트 | 화면에 무엇을 그릴지 설명하는 가벼운 일반 객체 | `<Profile />`이 만드는 객체 |
| 인스턴스 | 클래스 컴포넌트가 가지는 `this` 객체. 함수 컴포넌트에는 없음 | 클래스로 만든 컴포넌트 |

```jsx
const element = <Profile name="Kim" />
// element: { type: Profile, props: { name: 'Kim' }, ... }
```

- JSX `<Profile />`은 컴포넌트가 아니라 엘리먼트를 만듭니다. 엘리먼트는 `type`과 `props`를 담은 설명서입니다.
- 엘리먼트는 한 번 만들면 바꾸지 않는 값(불변)이고 만드는 비용이 작습니다.
- React가 엘리먼트 설명에 맞춰 실제 컴포넌트를 호출하고, 필요하면 DOM을 만들고 갱신합니다. 개발자가 인스턴스를 직접 만들거나 관리하지 않습니다.

**흔한 실수:** `Profile`과 `<Profile />`을 같은 것으로 보는 것입니다. 앞은 함수이고, 뒤는 그 함수를 쓰겠다는 엘리먼트입니다. `Profile()`로 직접 호출하면 React가 관리하는 컴포넌트로 쓰이지 않습니다.

## 핵심 정리

- 함수 컴포넌트는 JSX를 반환하는 함수이며 React가 호출하므로 `<Profile />`처럼 태그로 씁니다.
- 컴포넌트 이름은 대문자로 시작해야 하고, 소문자는 HTML 태그로 해석됩니다.
- 컴포넌트는 최상위에서 정의하고, 책임에 따라 분리하며, 재사용은 Props로, 조합은 `children` 합성으로 합니다.
- 컴포넌트 트리는 한 번의 렌더링에서 컴포넌트 간 포함 관계이며, 맨 위의 컴포넌트가 루트 컴포넌트입니다.
- 렌더링은 순수해야 하고(같은 입력은 같은 결과, Props·State를 바꾸지 않음), 부수 효과는 이벤트 핸들러나 Effect에 둡니다.
- 컴포넌트는 함수, 엘리먼트는 화면 설명 객체, 인스턴스는 클래스 컴포넌트의 `this`입니다.
