## JSX란

JSX는 JavaScript 파일 안에서 HTML과 비슷한 마크업을 쓰게 해 주는 문법 확장입니다. HTML이 아니라 JavaScript이며, 빌드할 때 일반 JavaScript 코드로 바뀝니다.

```jsx
const title = <h1 className="title">Hello</h1>
```

- JSX 명세는 XML과 비슷한 문법 확장이고 정해진 의미(semantics)가 없다고 설명합니다. 브라우저나 엔진이 직접 실행하는 것이 아니라 변환 도구(트랜스파일러)가 처리합니다.
- 변환 결과는 React 엘리먼트, 즉 화면에 무엇을 그릴지 설명하는 JavaScript 객체입니다. 문자열이 아닙니다.
- React가 JSX를 쓰도록 강제하는 것은 아닙니다. `createElement(type, props, ...children)`를 직접 호출해도 같은 엘리먼트가 나옵니다.

JSX를 쓸 때 지킬 규칙은 세 가지입니다.

| 규칙 | 틀린 예 | 맞는 예 |
|------|---------|---------|
| 루트 요소는 하나 | 형제 두 개를 그대로 반환 | `div` 또는 Fragment로 감싸 반환 |
| 모든 태그를 닫는다 | `<img src="a.png">`, `<li>항목` | `<img src="a.png" />`, `<li>항목</li>` |
| 속성은 대부분 camelCase | `class`, `stroke-width` | `className`, `strokeWidth` |

- 루트가 하나여야 하는 이유는 JSX가 객체로 변환되는데 함수는 객체 여러 개를 감싸지 않고 반환할 수 없기 때문입니다.
- 컴포넌트 이름은 대문자로 시작합니다. 소문자로 시작하는 이름은 `div`, `span` 같은 내장 HTML 태그로 해석됩니다(자세히는 04편).
- HTML을 JSX로 바꿀 때는 변환기(HTML to JSX 변환 도구)를 쓸 수 있습니다.

**흔한 실수:** 반환할 JSX가 여러 줄일 때 `return` 뒤에 줄을 바꿔 시작하는 것입니다. 괄호로 감싸 같은 문장으로 이어 줍니다.

```jsx
return (
  <div>
    <h1>Title</h1>
  </div>
)
```

## JavaScript 표현식

중괄호 `{}`는 JSX 안에서 JavaScript로 빠져나가는 문입니다. 안에는 표현식(값이 되는 식)만 넣을 수 있습니다.

```jsx
const name = 'Kim'
const today = new Date(2026, 9, 6)

<h1>{name}의 할 일</h1>             // Kim의 할 일
<p>{formatDate(today)}</p>          // 함수 호출 결과
<p>{1 + 2}</p>                      // 3
<img src={base + id + '.jpg'} />    // 문자열 결합
```

중괄호를 쓸 수 있는 자리는 두 곳입니다.

| 자리 | 예 | 쓸 수 있는가 |
|------|----|--------------|
| 태그 안의 내용 | `<h1>{name}</h1>` | 가능 |
| 속성 값 | `src={avatar}` | 가능 |
| 태그 이름 | `<{tag}>` | 불가 |
| 속성 이름 | `{attr}="x"` | 불가 |

- 변수, 산술식, 삼항식, 함수 호출, 객체·배열 리터럴이 표현식입니다.
- `if`, `for`, `switch` 같은 문(statement)은 넣을 수 없습니다. 조건과 반복은 JSX 밖에서 하거나 삼항식, `&&`, `map`으로 표현합니다.
- 문자열, 숫자는 그대로 출력됩니다. 일반 객체를 그대로 넣으면 에러입니다(`{person}`은 오류, `{person.name}`은 정상).
- 중괄호 한 쌍 안의 객체는 중괄호가 겹칩니다. `style={{ color: 'red' }}`의 바깥 쌍은 JSX 탈출, 안쪽 쌍은 객체 리터럴입니다. 겹중괄호라는 별도 문법이 있는 것이 아닙니다.

**흔한 실수:** 속성 값을 따옴표로 감싸서 변수를 읽으려는 것입니다. `src="{avatar}"`는 글자 그대로 `{avatar}`라는 문자열이 전달됩니다.

## JSX Attribute

속성(attribute)은 태그에 붙여 값을 전달하는 이름-값 쌍이고, 내장 태그에서는 DOM 요소의 속성이 되고 컴포넌트에서는 Props가 됩니다(Props는 05편).

```jsx
<img className="avatar" src={url} alt="Kim" />
<input disabled />
<input disabled={false} />
```

| 쓰는 방식 | 전달되는 값 |
|-----------|-------------|
| 따옴표 `"abc"` | 문자열 `'abc'` |
| 중괄호 `{expr}` | 표현식의 값(숫자, 불리언, 객체, 함수 등) |
| 값 생략 `disabled` | `true` |

- 한 속성에 따옴표와 중괄호를 같이 쓰지 않습니다.
- 문자열 속성은 HTML 엔티티가 해석됩니다. 객체나 숫자, 함수는 반드시 중괄호로 넘깁니다.
- 속성 이름은 camelCase입니다. 예외로 `aria-*`와 `data-*`는 하이픈을 그대로 씁니다.
- 직접 만든 속성은 소문자여야 하고 `on`으로 시작하면 안 됩니다. 값은 문자열로 변환되고, `null`이나 `undefined`를 주면 속성이 제거됩니다.
- 객체의 모든 필드를 속성으로 펼치는 스프레드도 쓸 수 있습니다.

```jsx
const props = { src: url, alt: 'Kim' }
<img {...props} className="avatar" />
```

스프레드 속성은 어떤 Props가 필요한지 가려서 읽기 어렵게 만들기 쉬우므로 절제해서 씁니다(자세히는 05편).

## HTML과 이름이 다른 속성

JSX 속성은 HTML 속성이 아니라 DOM 프로퍼티의 이름을 따릅니다. 그래서 camelCase이고, JavaScript 예약어와 겹치는 이름은 바뀝니다.

| HTML | JSX | 비고 |
|------|-----|------|
| `class` | `className` | 예약어 `class` 회피 |
| `for` | `htmlFor` | 예약어 `for` 회피. `label`, `output`에서 씀 |
| `tabindex` | `tabIndex` | camelCase |
| `onclick` | `onClick` | 이벤트는 camelCase(08편) |
| `stroke-width` | `strokeWidth` | SVG 속성도 camelCase |
| `xlink:href` | `xlinkHref` | 네임스페이스 속성은 콜론을 없애고 camelCase |
| `aria-label`, `data-id` | 그대로 | 하이픈 유지 |

```jsx
const id = useId()

<label htmlFor={id}>이름</label>
<input id={id} name="name" />
```

- `htmlFor`는 `label`을 `id`가 같은 입력 요소와 연결합니다. `useId`로 만든 고유 `id`를 쓰면 같은 컴포넌트를 여러 번 써도 충돌하지 않습니다.
- `defaultValue`, `defaultChecked`처럼 React가 따로 정한 속성도 있습니다(Form은 15편).

**흔한 실수:** `class`를 그대로 쓰는 것입니다. 개발 중 경고가 나오므로 `className`으로 바꿉니다.

## className

`className`은 요소에 CSS 클래스 이름을 지정하는 속성이고, HTML의 `class`에 해당합니다.

```jsx
<div className="card">...</div>
<div className="card active">...</div>
<div className={isActive ? 'card active' : 'card'}>...</div>
```

- 값은 문자열입니다. 클래스가 여러 개면 공백으로 구분한 문자열 하나로 만듭니다.
- 조건에 따라 바꿀 때는 삼항식이나 템플릿 문자열로 문자열을 만듭니다.
- 값은 문자열이어야 하므로 여러 조건을 조합할 때는 문자열을 직접 만들거나 도구(`clsx` 등)를 씁니다(28편).

**흔한 실수:** 조건이 거짓일 때 `undefined`가 문자열로 붙는 템플릿 문자열입니다. `` `card ${isActive && 'active'}` ``는 `false`일 때 `card false`가 됩니다. 삼항식으로 빈 문자열을 선택하는 편이 안전합니다.

## style

`style` 속성은 인라인 스타일을 문자열이 아니라 JavaScript 객체로 받습니다.

```jsx
<div style={{ backgroundColor: 'black', marginTop: 20 }}>
  내용
</div>
```

- 속성 이름은 하이픈 대신 camelCase입니다(`background-color`가 `backgroundColor`).
- 값은 문자열이나 숫자입니다. 숫자를 주면 단위 없는 속성(예: `opacity`)이 아닌 경우 `px`가 붙습니다. `marginTop: 20`은 `20px`입니다.
- 바깥 중괄호는 JSX 탈출이고 안쪽은 객체 리터럴이므로 `{{ }}`가 됩니다.
- 공식 문서는 `style`을 값이 JavaScript 변수에 따라 달라지는 동적 스타일에만 쓰라고 권합니다. 고정된 스타일은 클래스로 지정하는 편이 낫습니다(스타일링 전반은 28편).
- 의사 클래스(`:hover`)와 미디어 쿼리는 인라인 스타일에 쓸 수 없습니다.

**흔한 실수:** `style="color: red"`처럼 문자열을 주는 것입니다. 객체가 아니면 에러가 납니다.

## Fragment

Fragment는 DOM에 요소를 추가하지 않고 여러 요소를 묶는 컴포넌트입니다. 약식 문법은 빈 태그 `<>...</>`입니다.

```jsx
function Info() {
  return (
    <>
      <h1>Title</h1>
      <p>Content</p>
    </>
  )
}
```

- 결과 DOM에는 `h1`과 `p`만 형제로 나옵니다. 불필요한 `div`가 늘지 않아 CSS 레이아웃(`flex`, `grid`, 표 구조)이 깨지지 않습니다.
- 약식 문법에는 `key`나 `ref`를 줄 수 없습니다. 이럴 때는 `Fragment`를 `react`에서 가져와 `<Fragment key={id}>`로 씁니다. 리스트에서 key가 필요한 경우는 07편에서 다룹니다.
- 상태 보존은 한 단계 안에서만 유지됩니다. `<><Child /></>`에서 `<Child />`로 바꾸는 것은 같은 위치로 취급되어 State가 유지되지만, Fragment가 두 겹이면 초기화됩니다(자세히는 13편).
- `<Fragment ref>`로 묶인 요소 전체에 접근하는 Fragment Ref는 19.3 발표 글에서 안정 기능으로 표시되었습니다. 다만 같은 시점의 Fragment 레퍼런스 페이지는 Canary 기능으로 적혀 있어 문서마다 표기가 다르므로, 쓰기 전에 현재 문서에서 상태를 확인합니다. 이 과목의 범위 밖입니다.

## 조건식

JSX 안에서는 `if`를 쓸 수 없으므로 삼항 연산자와 `&&`로 조건을 표현합니다(자세히는 06편).

```jsx
<li>{isPacked ? name + ' ✅' : name}</li>
<li>{name} {isPacked && '✅'}</li>
```

- 삼항식은 두 값 중 하나를 고르고, `&&`는 조건이 참일 때만 오른쪽을 렌더합니다.
- 더 복잡하면 JSX 밖에서 `if`로 변수에 JSX를 담거나, 일찍 `return`합니다.

**흔한 실수:** `&&` 왼쪽에 숫자를 쓰는 것입니다. `count && <p>있음</p>`은 `count`가 0이면 `0`이 화면에 나옵니다. `count > 0 && ...`처럼 불리언으로 만듭니다(아래 "false·null·undefined·0의 렌더 결과").

## 함수 호출

중괄호 안에서 함수를 호출하면 반환값이 그 자리에 들어갑니다.

```jsx
<h1>{formatDate(today)}</h1>        // 호출 결과를 렌더
<button onClick={handleClick}>      // 함수 자체를 넘김
```

- 값을 만들어 출력하는 함수 호출은 렌더링 중에 실행됩니다. 컴포넌트가 다시 렌더링되면 다시 호출되므로, 부수 효과 없이 같은 입력에 같은 결과를 내는 순수한 함수여야 합니다(자세히는 04편).
- 호출 결과를 쓰는 곳은 `{fn()}`이고, 이벤트 핸들러처럼 나중에 React가 부르게 할 함수는 `{fn}`으로 참조만 넘깁니다. 이벤트는 08편에서 다룹니다.
- 호출이 JSX를 반환하면 그대로 화면에 그려집니다. 다만 그 함수는 컴포넌트가 아니므로 Hook을 쓰지 않고, 가능하면 컴포넌트로 분리합니다.

**흔한 실수:** 이벤트 속성에 `onClick={handleClick()}`을 쓰는 것입니다. 렌더링 때 바로 실행되고, 반환값이 핸들러가 됩니다.

## 배열 렌더링

배열을 JSX 안에 넣으면 각 요소가 순서대로 렌더링됩니다. 데이터 배열을 화면으로 바꿀 때는 `map`으로 JSX 배열을 만듭니다.

```jsx
const people = [
  { id: 1, name: 'Kim' },
  { id: 2, name: 'Lee' },
]

<ul>
  {people.map((p) => (
    <li key={p.id}>{p.name}</li>
  ))}
</ul>
```

- `map`의 화살표 함수는 괄호 `(...)`로 감싸면 값을 바로 반환하고, 중괄호 `{...}`로 감싸면 `return`을 직접 써야 합니다. 중괄호에 `return`을 빼먹으면 아무것도 렌더되지 않습니다.
- `map` 바로 안의 요소에는 `key`가 필요합니다. 데이터에서 온 안정적인 고유 값(예: id)을 씁니다.
- 일부만 보여 주려면 `filter`로 걸러 낸 뒤 `map`을 씁니다.
- key, 필터링, 추가·삭제·정렬은 07편에서 자세히 다룹니다.

## false·null·undefined·0의 렌더 결과

`false`, `true`, `null`, `undefined`는 렌더 결과에 아무것도 남기지 않습니다. 숫자 `0`은 텍스트 `0`으로 렌더됩니다.

| 값 | 화면 |
|----|------|
| `false`, `true` | 아무것도 없음 |
| `null`, `undefined` | 아무것도 없음 |
| `0` | `0` |
| 빈 문자열 `''` | 보이는 것이 없음 |
| 빈 배열 `[]` | 아무것도 없음 |
| 일반 객체 | 에러 |

```jsx
<p>{false}{null}{undefined}</p>   // 빈 p
<p>{0}</p>                        // 0
<p>{count && <b>있음</b>}</p>      // count가 0이면 0 출력
```

- React는 `false`, `null`, `undefined`를 JSX 트리의 빈칸(hole)으로 취급합니다.
- 컴포넌트가 아무것도 그리지 않으려면 `null`을 반환하는 것이 공식 권장 방식입니다(06편).
- `0`과 `NaN`은 숫자라서 텍스트로 나옵니다. 조건 렌더링에서 숫자를 조건으로 쓸 때는 불리언으로 바꿉니다.
- `true`가 렌더되지 않는다는 점을 이용해 `{isLoggedIn && <Menu />}`가 조건 렌더링으로 동작합니다.

**흔한 실수:** 디버깅하려고 불리언을 화면에 보려는 것입니다. `{isOpen}`은 아무것도 출력하지 않습니다. `{String(isOpen)}`로 문자열로 바꿔 출력합니다.

## JSX와 XSS

XSS(Cross-Site Scripting)는 공격자가 입력한 스크립트가 사용자의 브라우저에서 실행되는 취약점입니다. React DOM은 JSX에 포함한 값을 렌더하기 전에 기본적으로 이스케이프(escape, 특수 문자를 안전한 문자로 치환)합니다.

```jsx
const input = '<img src=x onerror=alert(1)>'

<div>{input}</div>
// 화면에 문자열 그대로 표시. 태그로 실행되지 않음
```

- 값은 텍스트로 취급되므로 문자열 안의 태그나 스크립트가 요소로 해석되지 않습니다. 공식 문서는 이 방식이 애플리케이션에 명시적으로 쓰지 않은 것은 주입할 수 없게 한다고 설명합니다.
- 방어는 중괄호로 넣는 값에만 적용됩니다. 아래 경우는 이스케이프를 우회하거나 별도 주의가 필요합니다.

| 위험한 경우 | 이유 |
|-------------|------|
| `dangerouslySetInnerHTML` | 문자열을 HTML로 그대로 삽입 |
| 사용자가 준 URL을 `href`나 `src`에 사용 | 위험한 URL 형태(스크립트 실행 스킴)를 이스케이프가 막지 못함 |

- 사용자 입력 URL은 렌더링 전에 허용한 프로토콜(`https:` 등)인지 직접 검사합니다.
- React 19.3은 브라우저의 Trusted Types API와 연동되도록 React가 Trusted Types 객체를 DOM API에 그대로 전달합니다. CSP로 `require-trusted-types-for`를 쓰는 환경을 위한 개선입니다.

**흔한 실수:** React가 자동으로 막아 주니 어떤 값을 넣어도 안전하다고 믿는 것입니다. 안전한 것은 텍스트 위치의 값뿐입니다.

## dangerouslySetInnerHTML

`dangerouslySetInnerHTML`은 요소의 내용을 문자열 HTML로 직접 지정하는 속성입니다. 이름에 위험하다는 뜻을 넣어 이스케이프 보호를 끄는 것임을 드러냅니다.

```jsx
const html = { __html: '<p>안전하게 정제한 HTML</p>' }

<div dangerouslySetInnerHTML={html} />
```

- 값은 `__html` 키를 가진 객체입니다. 문자열을 직접 넘기지 않습니다.
- `children`과 함께 쓸 수 없습니다. 둘을 같이 주면 에러입니다.
- 공식 문서는 신뢰할 수 있고 정제(sanitize)된 데이터에만 쓰라고 경고합니다. 사용자 입력을 그대로 넣으면 XSS 취약점이 됩니다.
- 객체는 HTML이 만들어지는 곳 가까이에서, 신뢰할 수 있는 출처(예: 정제를 거치는 마크다운 라이브러리)에서만 만듭니다.
- 쓸 일은 서버에서 받은 서식 있는 본문을 표시할 때처럼 제한적입니다. 대부분은 JSX로 충분합니다.

```jsx
// ❌ 사용자 입력을 그대로 삽입
<div dangerouslySetInnerHTML={{ __html: userComment }} />
// ✅ 일반 텍스트는 이스케이프되는 중괄호로
<div>{userComment}</div>
```

## JSX Transform

JSX Transform은 JSX를 일반 JavaScript 호출로 바꾸는 변환 단계입니다. Vite, Next.js 같은 도구가 자동으로 실행합니다.

```jsx
// 입력
<h1 className="title">Hello</h1>

// 구 방식(클래식): React가 스코프에 있어야 함
React.createElement('h1', { className: 'title' }, 'Hello')

// 새 방식(자동): 변환기가 jsx-runtime에서 자동 import
_jsx('h1', { className: 'title', children: 'Hello' })
```

- 구 방식은 JSX가 `React.createElement` 호출로 바뀌어서, JSX를 쓰는 모든 파일에서 `import React from 'react'`가 있어야 했습니다.
- 새 방식(React 17 이상)은 변환기가 `react/jsx-runtime`의 `_jsx` 같은 함수를 자동으로 가져옵니다. JSX만 쓰는 파일에서 React를 import하지 않아도 됩니다.
- 새 방식은 번들이 조금 작아지고, 구 방식도 계속 지원됩니다(React 팀은 제거 계획이 없다고 밝혔습니다).
- Babel은 `@babel/preset-react`의 `runtime: 'automatic'`, TypeScript는 `tsconfig.json`의 `jsx` 옵션을 `react-jsx`로 설정하면 새 방식을 씁니다. Vite의 React 플러그인은 자동 JSX 런타임을 설정해 둡니다(02편).
- 위 변환 결과는 개념을 보이기 위한 표기이고, 실제 출력 형태는 도구와 버전에 따라 다릅니다.
- 변환된 결과로 만들어지는 React 엘리먼트는 `type`, `props`, `key`, `ref`를 가진 객체이며, 만든 뒤에는 바꾸지 않는 값으로 다룹니다.

**흔한 실수:** 옛 자료를 따라 모든 파일 맨 위에 `import React from 'react'`를 넣는 것입니다. 새 방식에서는 필요하지 않습니다. 대신 `useState` 같은 Hook은 여전히 `react`에서 import해야 합니다.

## JSX 주석

JSX 안의 주석은 중괄호 안에 JavaScript 주석을 넣어 씁니다.

```jsx
<div>
  {/* 태그 안의 주석 */}
  <h1>Title</h1>
</div>
```

- `{/* ... */}`는 안에 표현식이 없는 중괄호라서 아무것도 렌더하지 않습니다.
- 태그 안의 내용 자리에 `//` 주석을 쓰면 화면에 글자로 출력됩니다. 반드시 `{/* */}`로 감쌉니다.

**흔한 실수:** HTML 주석 `<!-- -->`을 JSX에 쓰는 것입니다. 문법 오류가 납니다.

## 핵심 정리

- JSX는 HTML이 아니라 JavaScript로 변환되는 문법이며, 루트는 하나, 태그는 모두 닫고, 속성은 대부분 camelCase로 씁니다.
- 중괄호에는 표현식만 넣을 수 있고, 속성에서 따옴표는 문자열, 중괄호는 JavaScript 값입니다.
- `class`는 `className`, `for`는 `htmlFor`, `style`은 camelCase 객체이며, `aria-*`와 `data-*`만 하이픈을 유지합니다.
- `false`, `true`, `null`, `undefined`는 렌더되지 않고 `0`은 `0`으로 렌더됩니다.
- JSX에 넣은 값은 자동 이스케이프되어 XSS를 막지만, `dangerouslySetInnerHTML`과 사용자 입력 URL은 직접 정제·검증해야 합니다.
- React 17 이상의 JSX Transform은 `react/jsx-runtime`을 자동으로 가져와 `import React`가 필요 없습니다.
