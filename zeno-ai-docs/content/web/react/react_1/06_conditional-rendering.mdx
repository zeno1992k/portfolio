## if

React에는 조건부 렌더링 전용 문법이 없습니다. 컴포넌트는 JavaScript 함수이므로 `if` 문으로 조건을 나누고, 조건마다 다른 JSX를 반환하면 됩니다.

```jsx
function Item({ name, isPacked }) {
  if (isPacked) {
    return <li className="item">{name} ✅</li>
  }
  return <li className="item">{name}</li>
}
```

- 반환할 JSX가 완전히 다를 때 알맞습니다.
- 두 분기에서 대부분이 같고 일부만 다르면 같은 JSX가 중복됩니다. 그때는 아래의 삼항 연산자나 변수 할당을 씁니다.
- `if` 문은 JSX 안(중괄호 안)에 쓸 수 없습니다. 중괄호 안에는 값이 되는 표현식만 올 수 있어서, JSX 안에서는 삼항 연산자나 `&&`를 씁니다(자세히는 03편).

변수에 JSX를 담았다가 한 번에 반환하는 방식은 분기가 많거나 계산이 필요할 때 가장 유연합니다.

```jsx
function Item({ name, isPacked }) {
  let content = name
  if (isPacked) {
    content = <del>{name} ✅</del>
  }
  return <li className="item">{content}</li>
}
```

- `let`으로 선언한 변수에 기본 결과를 넣고, 조건에 맞을 때 덮어씁니다.
- 변수에 값을 다시 쓰는 것은 렌더링 중에 새로 만든 지역 변수이므로 괜찮습니다. props나 state를 바꾸는 것과 다릅니다(자세히는 05편).

## 삼항 연산자

`조건 ? 참일 때 : 거짓일 때`는 값이 되는 표현식이라서 JSX 안에서 쓸 수 있습니다. 두 가지 중 하나를 고를 때 씁니다.

```jsx
return (
  <li className="item">
    {isPacked ? name + ' ✅' : name}
  </li>
)
```

JSX가 길면 괄호로 감쌉니다.

```jsx
{isPacked ? (
  <del>{name} ✅</del>
) : (
  name
)}
```

- 두 분기 중 하나가 "아무것도 그리지 않음"이면 `null`을 씁니다. `cond ? <A /> : null`은 아래 `&&`와 같은 결과입니다.
- 두 분기의 타입이 같은 컴포넌트이면 React는 같은 위치로 보고 state를 보존합니다. 조건 분기가 state에 미치는 영향은 "조건별 컴포넌트"에서 다시 봅니다.

## && 렌더링

`조건 && <JSX />`는 조건이 참일 때만 JSX를 그리고, 거짓이면 아무것도 그리지 않습니다. 거짓일 때 보여 줄 것이 없을 때 씁니다.

```jsx
return (
  <li className="item">
    {name} {isPacked && '✅'}
  </li>
)
```

- `&&`는 왼쪽이 거짓이면 왼쪽 값을 그대로 반환하고, 참이면 오른쪽 값을 반환합니다. 그래서 왼쪽의 값이 그대로 렌더 결과가 될 수 있습니다.
- 렌더 결과가 없는 값은 `false`, `null`, `undefined`, `true`입니다. 빈 문자열 `''`도 화면에 아무것도 나타나지 않습니다.
- 숫자 `0`과 `NaN`은 값 그대로 그려집니다(아래 "&& 왼쪽의 0과 NaN 함정").

## && 왼쪽의 0과 NaN 함정

`&&`의 왼쪽에 숫자를 그대로 쓰면, 거짓인 `0`이 화면에 그려집니다.

```jsx
const count = 0
<div>{count && <p>새 메시지</p>}</div>
// 화면에 숫자 0이 나온다

<div>{count > 0 && <p>새 메시지</p>}</div>
// 아무것도 안 나온다 (false)
```

- 원인은 `0 && x`의 결과가 `0`이고, React가 숫자 `0`을 텍스트로 그리기 때문입니다.
- `NaN`도 같습니다. `NaN && x`는 `NaN`이어서 화면에 `NaN`이 나옵니다. 숫자 계산 결과가 `NaN`일 수 있는 값을 `&&` 왼쪽에 쓰면 이런 일이 생깁니다.
- 배열 길이도 마찬가지입니다. `items.length && <List />`는 빈 배열일 때 `0`을 그립니다.

해결은 왼쪽을 불리언으로 만드는 것입니다.

```jsx
{items.length > 0 && <List items={items} />}
{Boolean(count) && <p>새 메시지</p>}
{!!count && <p>새 메시지</p>}
{count ? <p>새 메시지</p> : null}
```

- 공식 문서는 `messageCount > 0 &&`처럼 비교식을 쓰라고 안내합니다.
- 삼항 연산자는 거짓 쪽을 `null`로 명시하므로 이 함정이 생기지 않습니다.
- 값이 문자열이면 `''`는 그려지지 않으므로 안전하지만, `' '`처럼 공백만 있는 문자열은 참으로 취급됩니다.

## early return

early return은 조건에 맞지 않거나 예외 상황이면 함수 앞부분에서 먼저 반환해 버리고, 나머지 코드는 정상 경우만 다루는 방식입니다.

```jsx
function Profile({ user }) {
  if (!user) {
    return <p>로그인이 필요합니다.</p>
  }
  return <h1>{user.name}</h1>
}
```

- `user`가 없을 때를 먼저 처리해서, 아래에서는 `user`가 항상 있다고 가정하고 쓸 수 있습니다. 중첩이 줄어 읽기 쉽습니다.
- Hook은 early return보다 위에서 호출해야 합니다. early return 뒤에 `useState`를 두면 렌더링마다 Hook 호출 순서가 달라질 수 있어 규칙 위반입니다(자세히는 26편).

```jsx
function Panel({ open }) {
  if (!open) return null
  const [value, setValue] = useState('') // ❌ 조건 뒤의 Hook
}
```

- 해결은 Hook을 맨 위에 두는 것입니다. 또는 `open` 조건을 부모로 옮겨 `Panel` 자체를 렌더링하지 않게 합니다.

## null 반환

컴포넌트가 `null`을 반환하면 그 컴포넌트는 아무것도 그리지 않습니다. 에러가 아니라 정상적인 "빈" 결과입니다.

```jsx
function Item({ name, isPacked }) {
  if (isPacked) {
    return null
  }
  return <li className="item">{name}</li>
}
```

- 렌더 결과가 없다는 뜻으로는 `null`을 씁니다. `false`도 아무것도 그리지 않지만 관례는 `null`입니다.
- `null`을 반환해도 그 컴포넌트의 함수는 실행되고 안의 Hook도 실행됩니다. DOM에 아무것도 만들지 않을 뿐입니다.
- 컴포넌트가 스스로 `null`을 반환하는 일은 흔하지 않습니다. 보통은 부모가 조건에 따라 컴포넌트를 포함하거나 빼는 편이 읽는 사람을 덜 놀라게 합니다.

```jsx
{!isPacked && <Item name={name} />} // 부모에서 조건을 판단
```

## 조건별 컴포넌트

분기마다 UI가 크게 다르면 조건 안에 JSX를 길게 쓰지 말고 컴포넌트로 나눕니다. 조건 하나가 컴포넌트 하나에 대응하게 됩니다.

```jsx
function Greeting({ isLoggedIn }) {
  return isLoggedIn ? <UserMenu /> : <LoginButton />
}
```

- 컴포넌트를 나누면 각 분기가 자기 state와 Hook을 가질 수 있습니다. 한 컴포넌트 안에서 분기하면 Hook을 조건 안에 못 넣어서 불편해집니다.
- 부모가 조건을 판단하고, 자식은 자기 역할만 합니다.

분기에 따라 state가 어떻게 되는지는 아래 규칙으로 정해집니다.

| 상황 | state |
|------|-------|
| 같은 위치에 같은 컴포넌트 타입 | 보존 |
| 같은 위치에 다른 컴포넌트 타입 | 초기화 |
| 조건이 거짓이 되어 트리에서 제거 | 파괴 |
| `key`가 바뀜 | 새로 만듦 |

```jsx
{isFancy ? <Counter isFancy /> : <Counter />}
// 같은 위치, 같은 타입이라서 state가 이어진다
{isFancy && <Counter isFancy />}
// isFancy가 false가 되면 Counter가 사라지고 state도 사라진다
```

- 분기를 컴포넌트 안에서 정의하는 실수가 있습니다. 컴포넌트 함수 안에 다른 컴포넌트를 선언하면 렌더링마다 새 함수가 만들어져, React가 매번 다른 타입으로 판단해 state가 초기화됩니다. 컴포넌트는 항상 최상위에서 선언합니다(자세히는 13편).

## 중첩 조건

조건 안에 조건이 들어가면 읽기 어려워집니다. 삼항 연산자를 중첩하면 특히 그렇습니다.

```jsx
// ❌ 읽기 어렵다
{a ? (b ? <X /> : <Y />) : <Z />}
```

중첩을 줄이는 방법은 네 가지입니다.

1. **early return**으로 예외를 먼저 걸러냅니다.
2. **변수로 빼냅니다.** 조건을 `let` 변수나 함수로 계산하고 JSX에는 결과만 둡니다.
3. **컴포넌트로 나눕니다.** 안쪽 분기를 별도 컴포넌트로 만듭니다.
4. **객체 맵으로 바꿉니다.** 분기가 한 값의 여러 경우라면 아래 "객체 맵으로 분기"를 씁니다.

```jsx
function Status({ a, b }) {
  if (!a) return <Z />
  return b ? <X /> : <Y />
}
```

- 삼항 중첩은 한 단계까지만 쓰고, 두 단계부터는 위 방법으로 풀어 쓰는 것이 읽기 쉽습니다.
- 조건식이 길면 이름을 붙인 변수로 뺍니다. `const canEdit = user && user.role === 'admin'`처럼 쓰면 JSX가 `{canEdit && <Editor />}`로 짧아집니다.

## 권한 기반 렌더링

사용자의 권한에 따라 다른 UI를 보여 주는 것도 조건부 렌더링입니다. 권한을 판단하는 값을 먼저 계산하고, 그 값으로 분기합니다.

```jsx
function Post({ post, user }) {
  const isOwner = user?.id === post.authorId
  const isAdmin = user?.role === 'admin'
  return (
    <article>
      <h2>{post.title}</h2>
      {(isOwner || isAdmin) && <button>삭제</button>}
    </article>
  )
}
```

- 로그인 전(`user`가 `null`)일 수 있으면 옵셔널 체이닝을 씁니다.
- 권한 판단이 여러 곳에서 반복되면 컴포넌트로 묶습니다.

```jsx
function RequireRole({ role, user, children }) {
  if (user?.role !== role) return null
  return children
}

<RequireRole role="admin" user={user}>
  <AdminMenu />
</RequireRole>
```

- **화면에서 숨기는 것은 보안이 아닙니다.** 브라우저에 내려온 JavaScript와 데이터는 사용자가 볼 수 있으므로, 권한 검사는 서버가 해야 합니다. 클라이언트의 조건부 렌더링은 사용자 경험을 위한 것입니다.
- 페이지 단위 접근 제어(로그인하지 않으면 다른 페이지로 보내기)는 라우팅에서 다룹니다(자세히는 29편).

## Loading, Error, Empty

데이터를 불러오는 화면은 거의 항상 네 가지 상태가 있습니다. 불러오는 중, 실패, 성공했지만 비어 있음, 성공해서 데이터가 있음입니다.

| 상태 | 보여 줄 것 |
|------|-----------|
| Loading | 스피너·스켈레톤 |
| Error | 실패 메시지와 다시 시도 버튼 |
| Empty | 비어 있다는 안내(할 일을 유도) |
| Success | 데이터 목록 |

early return으로 예외 상태를 먼저 처리하는 것이 가장 읽기 쉽습니다.

```jsx
function UserList({ users, isLoading, error }) {
  if (isLoading) return <Spinner />
  if (error) return <p>불러오지 못했습니다.</p>
  if (users.length === 0) return <p>사용자가 없습니다.</p>
  return <ul>{users.map(renderUser)}</ul>
}
```

- 순서가 중요합니다. 로딩 중에는 `users`가 아직 없을 수 있으므로, `users.length`를 확인하는 코드가 `isLoading` 확인보다 먼저 오면 에러가 납니다.
- 로딩 상태를 불리언 두세 개로 나누면 `isLoading`과 `error`가 동시에 참이 되는 모순이 생깁니다. 하나의 `status` 값(`'loading'`, `'error'`, `'success'`)으로 두면 한 번에 하나만 가능합니다(자세히는 12편).
- Empty와 Loading을 구분하지 않으면 로딩 중에 "비어 있음" 문구가 깜빡입니다. `data`가 아직 없는 상태와 빈 배열인 상태는 다릅니다.
- 데이터를 불러오는 방법은 23편, 27편에서 다룹니다.

React에는 이 상태를 선언적으로 다루는 도구도 있지만 이 과목의 범위 밖입니다.

- Suspense는 자식이 데이터나 코드를 불러오는 동안 `fallback`을 보여 줍니다. Effect나 이벤트 핸들러 안에서 불러오는 데이터는 감지하지 못합니다.
- Error Boundary는 자식의 렌더링 중 에러를 잡아 대체 UI를 보여 줍니다. 클래스 컴포넌트로만 만들 수 있고(함수 컴포넌트 대응물은 아직 없음), 이벤트 핸들러와 비동기 코드의 에러는 잡지 못합니다.

## 객체 맵으로 분기

한 값의 여러 경우마다 다른 UI를 보여 줄 때는 `if`나 삼항 연산자를 늘어놓는 대신 객체로 값과 UI를 대응시킵니다.

```jsx
const views = {
  loading: Spinner,
  error: ErrorMessage,
  success: Result,
}

function Screen({ status }) {
  const View = views[status] ?? NotFound
  return <View />
}
```

- 키로 컴포넌트 자체(함수)를 저장하고, 쓸 때 대문자로 시작하는 변수에 꺼내 담아 렌더링합니다. JSX 태그 이름이 소문자로 시작하면 HTML 태그로 해석되므로 `View`처럼 대문자로 씁니다.
- 없는 키를 조회하면 `undefined`이므로 `??`로 기본 컴포넌트를 둡니다. 기본값이 없으면 `undefined`를 렌더링하려다 에러가 납니다.
- JSX 엘리먼트 자체를 값으로 저장할 수도 있습니다(`loading: <Spinner />`). 이때는 객체를 만들 때 모든 엘리먼트가 한꺼번에 만들어집니다. 엘리먼트를 만드는 것만으로 컴포넌트가 실행되지는 않지만, 값을 계산하는 식을 포함하면 사용하지 않는 분기의 식도 실행됩니다.
- 분기마다 필요한 props가 다르면 컴포넌트 맵보다 `switch`나 `if`가 더 분명합니다.
- 맵은 컴포넌트 밖에 선언합니다. 안에 선언하면 렌더링마다 새로 만들어집니다.

간단한 값 대응은 함수 안의 `switch`도 가능합니다.

```jsx
function Icon({ type }) {
  switch (type) {
    case 'ok': return <CheckIcon />
    case 'fail': return <XIcon />
    default: return null
  }
}
```

## 핵심 정리

- 조건부 렌더링은 JavaScript의 `if`, 삼항 연산자, `&&`로 하며, JSX 중괄호 안에서는 표현식인 삼항과 `&&`만 쓸 수 있습니다.
- 분기가 완전히 다르면 `if`와 early return, 두 가지 중 하나면 삼항, 있거나 없거나이면 `&&`, 복잡하면 변수에 담습니다.
- `&&` 왼쪽이 `0`이나 `NaN`이면 그 값이 화면에 그려지므로 `count > 0 &&`처럼 비교식이나 불리언으로 바꿉니다.
- `null`을 반환하면 아무것도 그리지 않으며, Hook은 early return보다 위에서 호출합니다.
- 조건이 같은 위치의 같은 타입이면 state가 보존되고, 트리에서 제거되거나 타입이 바뀌면 초기화됩니다.
- Loading, Error, Empty는 early return으로 먼저 처리하고, 권한 분기는 보안이 아니라 UI 제어이므로 서버 검증이 따로 필요합니다.
