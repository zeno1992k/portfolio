## React Event

React에서는 JSX 엘리먼트에 `onClick` 같은 prop으로 핸들러 함수를 넘겨 이벤트를 처리합니다. 핸들러는 사용자 동작(클릭, 입력, 키 누름 등)이 일어났을 때 React가 호출하는 함수입니다.

```jsx
function Button() {
  function handleClick() {
    alert('clicked')
  }
  return <button onClick={handleClick}>Click</button>
}
```

- 이벤트 prop의 이름은 `on` + 이벤트 이름이고 camelCase입니다. HTML의 `onclick`이 아니라 `onClick`입니다.
- 핸들러에는 문자열이 아니라 **함수**를 넘깁니다. HTML의 `onclick="handle()"`과 다릅니다.
- 함수를 호출한 결과가 아니라 함수 자체를 넘겨야 합니다. 호출식을 쓰면 렌더링 중에 실행됩니다.

```jsx
<button onClick={handleClick()}>   // ❌ 렌더링 중에 즉시 실행
<button onClick={handleClick}>     // ✅ 클릭할 때 실행
<button onClick={() => alert('hi')}>  // ✅ 인라인 화살표 함수
```

- 인라인으로 쓸 때는 화살표 함수나 이름 없는 함수를 씁니다. `onClick={alert('hi')}`는 렌더링 중에 호출됩니다.
- 이벤트 핸들러는 렌더링과 달리 순수할 필요가 없습니다. 입력값 변경, 목록 갱신, State 변경 같은 부수 효과가 일어나는 알맞은 자리입니다.
- 이벤트 prop은 `<button>`, `<input>`, `<form>` 같은 내장 DOM 엘리먼트에서 동작합니다. 직접 만든 컴포넌트에 `onClick`을 쓰면 그것은 이름일 뿐이고, 컴포넌트가 그 prop을 받아 DOM 엘리먼트에 넘겨줘야 동작합니다.

```jsx
function MyButton({ onClick, children }) {
  return <button onClick={onClick}>{children}</button>
}
```

## onClick

`onClick`은 요소를 클릭(마우스 주 버튼, 터치, 키보드로 버튼 활성화)했을 때 호출됩니다. 가장 많이 쓰는 이벤트입니다.

```jsx
<button onClick={handleClick}>저장</button>
```

- 클릭할 수 있는 UI는 `<button>`을 씁니다. `div`에 `onClick`을 달면 마우스는 되지만 키보드와 스크린 리더로는 동작하지 않습니다. 접근성 있는 마크업은 `button`, `a`로 시작합니다.
- 링크 이동이 목적이 아니면 `<a onClick>` 대신 `<button>`을 씁니다.
- 핸들러는 클릭할 때마다 호출됩니다. 중복 실행을 막으려면 처리 중에 버튼을 `disabled`로 바꿉니다.
- 이벤트는 위로 전파(버블링)됩니다. 자식 버튼을 클릭하면 부모 `div`의 `onClick`도 호출됩니다(아래 "stopPropagation").

## onChange

`onChange`는 입력 요소(`input`, `textarea`, `select`)의 값이 바뀔 때 호출됩니다. 입력값을 State에 반영하는 데 쓰입니다.

```jsx
function Search() {
  const [text, setText] = useState('')
  return (
    <input
      value={text}
      onChange={(e) => setText(e.target.value)}
    />
  )
}
```

- React의 `onChange`는 브라우저의 `change` 이벤트(포커스를 벗어날 때 발생)와 달리 **키를 누를 때마다** 호출됩니다. 역사적 이유로 `onInput` 대신 `onChange`를 관용적으로 씁니다.
- 텍스트 입력은 `e.target.value`, 체크박스와 라디오는 `e.target.checked`를 읽습니다.
- `value`를 주었으면 `onChange`로 State를 바꾸는 것이 필수입니다. 빼면 읽기 전용 입력창이 됩니다.
- `onChange`에서 State 갱신을 `setTimeout` 같은 비동기로 미루면 커서 위치가 튀는 문제가 생깁니다. 동기적으로 바로 갱신합니다.
- 제어 컴포넌트와 비제어 컴포넌트, 여러 입력값 관리는 15편에서 다룹니다.

## onSubmit

`onSubmit`은 `<form>`이 제출될 때 호출됩니다. 제출 버튼을 클릭하거나 입력창에서 Enter를 눌러도 호출됩니다.

```jsx
function Signup() {
  function handleSubmit(e) {
    e.preventDefault() // 페이지 새로고침 방지
    const data = new FormData(e.target)
    console.log(data.get('email'))
  }
  return (
    <form onSubmit={handleSubmit}>
      <input name="email" />
      <button>Send</button>
    </form>
  )
}
```

- 브라우저는 폼을 제출하면 페이지를 새로 불러옵니다. 단일 페이지 앱에서는 보통 이를 막아야 하므로 `onSubmit` 안에서 `e.preventDefault()`를 호출합니다.
- 버튼의 `onClick`에서 처리하지 말고 `<form>`의 `onSubmit`에서 처리해야 Enter 키 제출도 동작합니다.
- 폼 안의 `<button>`은 `type`을 생략하면 제출 버튼입니다. 제출이 아닌 버튼은 `type="button"`을 씁니다.
- React 19에는 `<form action={함수}>` 방식도 있습니다. 함수를 `action`에 넘기면 제출이 Transition 안에서 실행되고 `e.preventDefault()`가 필요 없습니다. `onSubmit`은 모든 React 버전에서 동작하고 제출 이벤트 자체에 접근할 수 있습니다. 이 문서는 `onSubmit`을 기준으로 합니다.
- Form Actions는 이 과목의 범위 밖(중급)입니다. 폼 제출과 검증은 15편, 16편에서 다룹니다.

## onKeyDown

`onKeyDown`은 키를 눌렀을 때, `onKeyUp`은 뗐을 때 호출됩니다. 어떤 키인지는 이벤트 객체의 `key`로 확인합니다.

```jsx
function handleKeyDown(e) {
  if (e.key === 'Enter') {
    addTodo()
  }
  if (e.key === 'Escape') {
    close()
  }
}

<input onKeyDown={handleKeyDown} />
```

- `e.key`는 눌린 키를 나타내는 값입니다(`'Enter'`, `'Escape'`, `'a'` 등).
- 한글 같은 조합 입력(IME) 중에는 Enter가 글자 확정에 쓰이므로, 조합 중인지 확인하고 처리해야 합니다(자세히는 15편).
- 단축키는 `e.ctrlKey`, `e.shiftKey`, `e.metaKey`로 보조 키 상태를 함께 확인합니다.
- 텍스트를 입력하는 것이 목적이면 `onKeyDown`이 아니라 `onChange`를 씁니다. 붙여 넣기, 음성 입력, 자동 완성은 키 이벤트로 잡히지 않습니다.
- 입력 폼에서 Enter로 제출하려면 `onKeyDown`을 쓰지 말고 `<form onSubmit>`을 씁니다.

## onFocus와 onBlur

`onFocus`는 요소가 포커스를 얻었을 때, `onBlur`는 잃었을 때 호출됩니다. 입력 검증 시점(`blur`), 포커스 시 안내 표시 등에 씁니다.

```jsx
<input
  onFocus={() => setFocused(true)}
  onBlur={() => setFocused(false)}
/>
```

- 브라우저의 `focus`, `blur`는 버블링되지 않지만, **React의 `onFocus`와 `onBlur`는 버블링됩니다.** 그래서 부모 `div`에 달면 자식 입력 요소의 포커스 변화도 잡힙니다. React 17부터 내부적으로 `focusin`, `focusout` 이벤트를 쓰기 때문입니다.
- 부모에 달았을 때 포커스가 자식 사이를 옮겨 가는 경우에도 `onBlur`가 호출됩니다. 포커스가 영역 밖으로 나갔는지는 `e.relatedTarget`이 영역 안에 있는지로 확인합니다.

```jsx
<div
  onBlur={(e) => {
    if (!e.currentTarget.contains(e.relatedTarget)) {
      close() // 영역 밖으로 나갔을 때만
    }
  }}
>
```

- `onMouseEnter`, `onMouseLeave`는 버블링되지 않고 Capture 단계도 없습니다.
- 입력창의 검증 시점으로는 `onChange`(입력할 때마다), `onBlur`(벗어날 때), `onSubmit`(제출할 때)을 고릅니다(자세히는 16편).

## 이벤트 객체

핸들러의 첫 번째 인수로 이벤트 객체가 전달됩니다. 이벤트의 종류, 발생 위치, 입력된 값 같은 정보를 담고 있습니다.

```jsx
function handleClick(e) {
  console.log(e.type)           // 'click'
  console.log(e.target)         // 이벤트가 시작된 요소
  console.log(e.currentTarget)  // 핸들러가 달린 요소
  console.log(e.nativeEvent)    // 브라우저 원본 이벤트
}
```

| 속성·메서드 | 의미 |
|-------------|------|
| `type` | 이벤트 이름 |
| `target` | 이벤트가 처음 일어난 요소 |
| `currentTarget` | 지금 실행 중인 핸들러가 붙은 요소 |
| `nativeEvent` | 브라우저의 원본 이벤트 |
| `preventDefault()` | 브라우저의 기본 동작을 막음 |
| `stopPropagation()` | React 트리에서 이벤트 전파를 멈춤 |
| `bubbles`, `cancelable`, `defaultPrevented`, `eventPhase`, `isTrusted`, `timeStamp` | 이벤트 상태 정보 |

- `target`과 `currentTarget`은 다릅니다. 버튼 안의 `span`을 클릭하면 `target`은 `span`이고 `currentTarget`은 핸들러가 달린 `button`입니다.
- 이벤트의 종류마다 추가 속성이 있습니다. 마우스 이벤트는 `clientX`, `clientY`, `button`, 키보드 이벤트는 `key`, `code`, 입력 요소의 `onChange`는 `e.target.value`를 씁니다.
- React 16까지는 이벤트 객체가 재사용되어(이벤트 풀링) 핸들러가 끝나면 속성이 비워졌고, 비동기에서 쓰려면 `e.persist()`를 호출해야 했습니다. React 17부터 풀링이 없어져서 필요 없습니다. `persist()`는 React DOM에서 아무 일도 하지 않습니다.
- 핸들러 안에서 값이 필요하면 `const value = e.target.value`로 먼저 꺼내 쓰는 것이 읽기 쉽습니다.

## SyntheticEvent와 nativeEvent

React가 핸들러에 넘기는 이벤트 객체는 브라우저의 이벤트를 감싼 합성 이벤트(SyntheticEvent)입니다. 브라우저마다 다른 이벤트 동작을 같은 모양으로 맞추기 위한 래퍼입니다.

- 원본 브라우저 이벤트는 `e.nativeEvent`로 접근합니다. React가 제공하지 않는 속성(예: `isComposing`)이 필요할 때 씁니다.

```jsx
function handleKeyDown(e) {
  if (e.nativeEvent.isComposing) return // 조합 입력 중
}
```

- 합성 이벤트의 `target`, `currentTarget`, `eventPhase`, `type`은 React 코드가 기대하는 값을 반영합니다. React가 내부에서 이벤트를 루트에 붙이는 사실은 이벤트 객체에 드러나지 않습니다.
- 이벤트마다 같은 이름이라도 브라우저의 동작과 다른 것이 있습니다. `onChange`(키 입력마다 호출), `onFocus`와 `onBlur`(버블링)가 그렇습니다.
- `onBeforeInput`은 브라우저의 네이티브 `beforeinput`을 아직 쓰지 않고 다른 이벤트로 흉내 냅니다.
- `onScroll`은 버블링되지 않습니다.

## 이벤트 위임

React는 각 DOM 요소에 핸들러를 직접 붙이지 않고, 앱이 렌더링되는 **루트 DOM 컨테이너**에 이벤트 리스너를 붙여서 위임 방식으로 처리합니다. 이벤트가 위로 버블링되어 루트에 도달하면, React가 어느 요소에서 시작된 이벤트인지 보고 해당하는 핸들러들을 호출합니다.

- React 16까지는 `document`에 붙였고, React 17부터 루트 컨테이너에 붙입니다. 한 페이지에 여러 React 앱이나 여러 버전이 있어도 서로 전파가 간섭하지 않게 하기 위해서입니다.
- 이 구조 때문에 네이티브 이벤트 핸들러와 섞어 쓸 때 순서가 중요합니다. `document`에 직접 단 리스너(`addEventListener`)보다 React 핸들러가 먼저 실행됩니다. React 핸들러에서 `e.stopPropagation()`을 호출하면 `document` 리스너는 호출되지 않습니다. React 16에서는 `document`에 붙어 있었으므로 `document` 리스너도 호출되었습니다.
- 요소마다 리스너를 붙이지 않으므로 항목이 수천 개인 리스트도 부담이 적고, 요소가 추가·삭제되어도 리스너를 다시 붙일 필요가 없습니다.
- 위임이 적용되는 것은 React가 처리하는 이벤트 prop(`onClick` 등)입니다. `ref`로 DOM을 직접 잡아 `addEventListener`를 쓰면 일반 DOM 이벤트로 동작하고, 이 경우 제거(`removeEventListener`)는 직접 해야 합니다(자세히는 20편).

## preventDefault

`e.preventDefault()`는 이벤트의 브라우저 기본 동작을 막습니다. 이벤트 전파는 막지 않습니다.

```jsx
<form onSubmit={(e) => {
  e.preventDefault()  // 폼 제출로 인한 새로고침 방지
  save()
}}>
```

| 이벤트 | 막는 기본 동작 |
|--------|----------------|
| `submit` | 폼 제출과 페이지 이동·새로고침 |
| 링크 `click` | 링크 이동 |
| `keydown` | 문자 입력, 스크롤, 단축키 |
| `contextmenu` | 오른쪽 클릭 메뉴 |

- React에서는 핸들러에서 `false`를 반환해도 기본 동작이 막히지 않습니다. 반드시 `e.preventDefault()`를 호출합니다.
- 취소 가능한 이벤트(`cancelable`이 `true`)에서만 효과가 있고, 호출 후에는 `e.defaultPrevented`가 `true`가 됩니다.
- passive 리스너에서는 `preventDefault()`가 동작하지 않습니다(아래 "passive 이벤트").

## stopPropagation

`e.stopPropagation()`은 이벤트가 부모로 전파(버블링)되는 것을 멈춥니다. 브라우저의 기본 동작은 막지 않습니다.

```jsx
<div onClick={() => alert('div')}>
  <button onClick={(e) => {
    e.stopPropagation()
    alert('button')
  }}>
    Click
  </button>
</div>
// 클릭하면 'button'만 나온다 ('div'는 호출되지 않음)
```

- 이벤트는 요소에서 시작해 부모, 조상 순으로 올라갑니다. `onScroll`을 제외한 모든 이벤트가 전파됩니다. 그래서 자식의 클릭이 부모의 `onClick`을 호출하는 일이 생깁니다.
- 한 번 멈추면 그 위쪽 핸들러는 호출되지 않습니다. 위쪽의 분석, 모달 닫기 같은 코드가 동작하지 않는 버그의 원인이 되므로 남용하지 않습니다.
- `stopPropagation`은 React 트리에서의 전파를 멈춥니다. 같은 요소에 붙은 다른 핸들러는 계속 호출됩니다.
- 전파를 막는 대신, 부모 핸들러에서 `e.target`을 확인해 처리할 대상인지 걸러내는 방법도 있습니다.

| 메서드 | 막는 것 |
|--------|---------|
| `preventDefault()` | 브라우저의 기본 동작 |
| `stopPropagation()` | 부모 핸들러로의 전파 |

## 인자 전달

핸들러는 이벤트 객체만 받습니다. 추가 값(항목의 id 등)이 필요하면 인라인 화살표 함수로 감싸서 함수를 호출합니다.

```jsx
{items.map((item) => (
  <button
    key={item.id}
    onClick={() => handleDelete(item.id)}
  >
    삭제
  </button>
))}

function handleDelete(id) {
  setItems(items.filter((i) => i.id !== id))
}
```

- `onClick={handleDelete(item.id)}`는 렌더링 중에 호출되고 그 반환값이 넘어갑니다. 반드시 함수를 만들어 넘깁니다.
- 이벤트 객체도 함께 필요하면 화살표 함수가 이벤트를 받아 넘겨 줍니다.

```jsx
<button onClick={(e) => handleDelete(item.id, e)}>
```

- 함수를 반환하는 함수(커링)로도 쓸 수 있습니다.

```jsx
const handleDelete = (id) => () => {
  setItems(items.filter((i) => i.id !== id))
}
<button onClick={handleDelete(item.id)}>
```

- 반복되는 항목이 매우 많을 때 렌더링마다 함수가 새로 만들어지는 비용을 따지는 사람이 있지만, 대부분은 문제가 되지 않습니다. 측정하기 전에는 읽기 쉬운 인라인 방식을 씁니다.
- 부모 핸들러가 `e.target`의 `data-id` 속성을 읽어 어떤 항목인지 알아내는 방식도 가능하지만, 자식 요소를 클릭하면 `target`이 달라지므로 `currentTarget`을 씁니다.

## Capture

핸들러 이름 끝에 `Capture`를 붙이면 캡처 단계에서 실행됩니다. 이벤트는 세 단계로 진행됩니다. 루트에서 대상까지 내려가는 캡처 단계, 대상 요소, 대상에서 루트로 올라가는 버블 단계입니다.

```jsx
<div onClickCapture={() => console.log('1 capture')}>
  <button onClick={() => console.log('2 bubble')}>
    Click
  </button>
</div>
// 1 capture, 2 bubble 순서로 출력
```

- 일반 핸들러(`onClick`)는 버블 단계에서, `onClickCapture`는 캡처 단계에서 실행됩니다. 캡처가 항상 먼저입니다.
- 자식이 `e.stopPropagation()`으로 버블링을 막아도 부모의 `Capture` 핸들러는 이미 실행됐습니다. 자식에게 이벤트가 닿기 전에 가로채야 할 때 씁니다(예: 모든 클릭을 기록하는 분석 코드).
- 캡처 단계에서 `e.stopPropagation()`을 호출하면 대상까지 내려가지 않고 이벤트가 멈춥니다.
- 거의 모든 이벤트에 `onXxxCapture`가 있지만 `onMouseEnter`, `onMouseLeave`는 캡처 단계가 없습니다.
- 대부분의 앱에서는 쓸 일이 드뭅니다. 필요할 때만 씁니다.

## 이벤트와 State 갱신

이벤트 핸들러 안에서 `setState`를 호출하면 State가 바로 바뀌지 않습니다. 핸들러가 읽는 State 변수는 이번 렌더링 시점의 **스냅샷**이고, setter는 다음 렌더링을 예약합니다(자세히는 10편).

```jsx
const [count, setCount] = useState(0)

function handleClick() {
  setCount(count + 1)
  setCount(count + 1)
  setCount(count + 1)
  console.log(count) // 0 (핸들러 안에서는 계속 0)
}
// 클릭 후 count는 3이 아니라 1
```

- 세 번의 `setCount(count + 1)`은 모두 `setCount(0 + 1)`입니다. 같은 렌더링에서 `count`는 항상 0이기 때문입니다.
- 이전 값을 기준으로 이어서 바꾸려면 updater 함수를 씁니다.

```jsx
setCount((c) => c + 1)
setCount((c) => c + 1)
setCount((c) => c + 1)  // 클릭 후 count는 3
```

- 핸들러 안의 `setTimeout`이나 `await` 뒤에서도 State는 핸들러가 만들어진 렌더링의 값입니다. 3초 뒤의 `alert(count)`도 클릭했을 때의 값을 보여 줍니다.
- 한 핸들러 안의 여러 `setState`는 묶여서 한 번의 렌더링으로 처리됩니다(batching). React 18부터는 비동기 코드 안에서도 묶입니다(자세히는 10편).
- 핸들러가 끝난 뒤에 다음 렌더링이 일어나고, 새 State를 읽는 새 핸들러가 만들어집니다. 과거에 만들어진 핸들러는 만들어진 시점의 State를 계속 가지고 있습니다.
- 이벤트 핸들러는 순수하지 않아도 되는 자리이므로 서버 요청, 저장, 외부 라이브러리 호출 같은 부수 효과를 렌더링 중이 아니라 핸들러에서 합니다(자세히는 22편).

## 핸들러 이름 규칙

이름은 역할에 따라 두 가지를 구분합니다.

| 대상 | 규칙 | 예 |
|------|------|----|
| 이벤트를 받는 prop | `on` + 대문자 이벤트 이름 | `onClick`, `onSubmit`, `onSmash` |
| 컴포넌트 안에서 정의하는 핸들러 함수 | `handle` + 이벤트 이름 | `handleClick`, `handleSubmit` |

```jsx
function PlayButton({ movie, onPlay }) {
  function handleClick() {
    onPlay(movie)   // 부모가 준 on 함수를 호출
  }
  return <button onClick={handleClick}>Play</button>
}

<PlayButton movie="Up" onPlay={handlePlay} />
```

- 내장 엘리먼트의 prop 이름(`onClick`)은 고정입니다. 직접 만든 컴포넌트의 이벤트 prop은 이름을 자유롭게 정하되, 관례대로 `on`으로 시작합니다(`onPlayMovie`, `onUploadImage`).
- 핸들러 이름은 무슨 일이 일어났는지로 짓고, 함수가 하는 일(`saveAndClose`)이 아닙니다. 이름을 보고 어느 이벤트에 연결된 함수인지 알 수 있어야 합니다.
- `on`으로 시작하는 prop 이름은 자식 쪽에서 "일어난 일을 알린다"는 뜻이고, `handle`로 시작하는 함수는 부모(또는 같은 컴포넌트) 쪽에서 "일어난 일을 처리한다"는 뜻입니다.
- 이름 규칙은 React가 강제하지 않는 관례이고, 대신 팀의 코드를 읽을 때 prop과 함수를 한눈에 구분하게 해 줍니다.

## passive 이벤트

passive 리스너는 `preventDefault()`를 호출하지 않겠다고 브라우저에 약속하는 리스너입니다. 브라우저는 스크롤을 핸들러 실행 결과에 기다리지 않고 바로 처리해서 스크롤이 부드러워집니다.

- React 17부터 `onTouchStart`, `onTouchMove`, `onWheel`은 passive로 유지됩니다.
- passive 리스너에서 `e.preventDefault()`를 호출해도 효과가 없습니다. 스크롤을 막아야 하면 CSS의 `touch-action`, `overscroll-behavior`를 먼저 고려합니다.
- 그래도 `preventDefault()`가 필요하면 `ref`로 DOM 요소를 잡아 `addEventListener('wheel', fn, { passive: false })`로 직접 등록합니다(Effect 안에서 등록하고 정리하는 방법은 20편).

```jsx
useEffect(() => {
  const node = ref.current
  const onWheel = (e) => e.preventDefault()
  node.addEventListener('wheel', onWheel, {
    passive: false,
  })
  return () => node.removeEventListener('wheel', onWheel)
}, [])
```

- 일반적인 `onClick`, `onChange`, `onKeyDown`은 passive와 관계없습니다.
- `onScroll`은 스크롤을 막을 수 없는 이벤트라서 `preventDefault()`와 무관합니다.

## 핵심 정리

- 이벤트 핸들러는 `on` + 이벤트 이름 prop에 함수 자체를 넘기며, 호출식(`handle()`)을 넘기면 렌더링 중에 실행됩니다.
- `onChange`는 키 입력마다, `onFocus`와 `onBlur`는 버블링, `onSubmit`은 `preventDefault()`와 함께 쓰는 것이 React 이벤트의 차이점입니다.
- 이벤트 객체는 합성 이벤트이고 원본은 `nativeEvent`로 접근하며, React 17부터 루트 컨테이너에 위임되고 이벤트 풀링이 없습니다.
- `preventDefault()`는 기본 동작을, `stopPropagation()`은 부모로의 전파를 막고, `Capture` 접미사는 캡처 단계에서 실행됩니다.
- 인자는 `() => handle(id)` 형태로 감싸 전달하고, 핸들러 안의 State는 렌더링 시점의 스냅샷이라 연속 갱신에는 updater 함수를 씁니다.
- 이름은 prop이 `on`, 함수가 `handle`로 시작하며, `onTouchStart`·`onTouchMove`·`onWheel`은 passive라서 `preventDefault()`가 동작하지 않습니다.
