## input

`input`은 한 줄 값을 받는 기본 폼 요소이며 `type`에 따라 동작이 달라집니다(`text`, `email`, `number`, `checkbox`, `radio`, `file` 등). 사용자가 값을 바꾸면 `onChange`가 호출됩니다.

```jsx
function NameField() {
  const [name, setName] = useState('');
  return (
    <input
      value={name}
      onChange={e => setName(e.target.value)}
    />
  );
}
```

- `e.target`은 이벤트가 발생한 `input` DOM 요소이고, 그 `value`가 입력된 문자열입니다(이벤트 객체는 08편).
- React의 `onChange`는 브라우저의 `change`처럼 포커스를 잃을 때가 아니라 `input` 이벤트처럼 키를 누를 때마다 호출됩니다.
- `type="number"`여도 `e.target.value`는 문자열입니다. 숫자가 필요하면 직접 변환합니다.
- 레이블은 `label`로 감싸거나 `htmlFor`와 `id`를 짝지어 연결합니다. 여러 번 렌더되는 컴포넌트에서 `id`가 겹치지 않게 `useId`로 만듭니다.

```jsx
const ageId = useId();
<label htmlFor={ageId}>Age</label>
<input id={ageId} name="age" type="number" />
```

## textarea

`textarea`는 여러 줄 텍스트를 받으며 React에서는 `input`처럼 `value`와 `onChange`로 다룹니다. HTML과 달리 안쪽 내용(children)으로 값을 주지 않습니다.

```jsx
<textarea
  value={content}
  onChange={e => setContent(e.target.value)}
/>
<textarea defaultValue="초기 내용" rows={4} />
// ❌ <textarea>초기 내용</textarea> (children 금지)
```

- 초기값은 `defaultValue`, 제어는 `value`입니다.
- 크기는 `rows`(기본 2)와 `cols`(기본 20)로 정하고, 글자 수는 `maxLength`로 제한합니다.

## select

`select`는 목록에서 선택합니다. 선택값은 `option`이 아니라 `select`의 `value`로 정합니다.

```jsx
<select
  value={fruit}
  onChange={e => setFruit(e.target.value)}
>
  <option value="apple">Apple</option>
  <option value="banana">Banana</option>
</select>
// ❌ <option selected> 는 쓰지 않는다
```

- HTML의 `option`에 붙이는 `selected` 속성은 React에서 쓰지 않습니다. 제어는 `value`, 초기 선택은 `defaultValue`입니다.
- `multiple`이면 `value`와 `defaultValue`가 문자열 배열입니다. 선택된 값은 `e.target.selectedOptions`에서 읽습니다.

```jsx
<select
  multiple
  value={picked}
  onChange={e => setPicked(
    [...e.target.selectedOptions].map(o => o.value)
  )}
>
```

## checkbox

체크박스는 값이 아니라 켜짐 여부가 State입니다. `value`가 아니라 `checked`와 `e.target.checked`를 씁니다.

```jsx
const [agree, setAgree] = useState(false);

<input
  type="checkbox"
  checked={agree}
  onChange={e => setAgree(e.target.checked)}
/>
```

- 체크박스 여러 개에서 선택된 항목을 모으려면 State를 배열로 두고 추가·삭제합니다.

```jsx
function toggle(id) {
  setPicked(prev => prev.includes(id)
    ? prev.filter(x => x !== id)
    : [...prev, id]
  );
}
```

## radio

라디오는 같은 `name`을 가진 것 중 하나만 선택됩니다. State는 선택된 값 하나이고, 각 라디오의 `checked`는 그 값과 자기 `value`의 비교 결과입니다.

```jsx
<input
  type="radio"
  name="size"
  value="small"
  checked={size === 'small'}
  onChange={e => setSize(e.target.value)}
/>
```

- 같은 묶음의 라디오는 같은 `name`, 서로 다른 `value`를 가집니다.
- 초기 선택은 `defaultChecked`입니다.

## Controlled Component

제어 컴포넌트는 입력값을 React State가 정하는 폼 요소입니다. 값은 State가 갖고, 변경은 `onChange`에서 State를 바꾸는 방식으로만 일어납니다.

- 값 → 화면: `value`(또는 `checked`)에 State를 연결합니다.
- 화면 → 값: 입력이 일어나면 `onChange`가 State를 갱신하고, 다시 렌더되어 새 값이 화면에 반영됩니다.
- 입력값을 렌더 중에 읽을 수 있어 즉시 검증하거나 다른 UI에 보여 주거나 다른 입력과 연동하기 쉽습니다.
- 대가는 키 입력마다 State가 바뀌어 컴포넌트가 다시 렌더된다는 점입니다. 입력 State를 입력을 쓰는 작은 컴포넌트에 두면 영향이 줄어듭니다(14편).

## Uncontrolled Component

비제어 컴포넌트는 값을 DOM이 보관하는 폼 요소입니다. React는 초기값만 주고, 값은 필요할 때(보통 제출 시점에) 읽습니다.

```jsx
<input name="query" defaultValue="react" />
```

- 입력할 때마다 렌더되지 않아 코드가 짧습니다. 제출할 때만 값이 필요한 단순한 폼에 맞습니다.
- 입력 도중의 값을 화면에 반영하거나 검증하는 일은 어렵습니다.
- 요소는 수명 동안 제어에서 비제어로, 비제어에서 제어로 바뀔 수 없습니다. 하나를 정해서 씁니다.
- 파일 입력은 항상 비제어입니다(아래 "file input").

| 항목 | 제어 | 비제어 |
|------|------|--------|
| 값 보관 | React State | DOM |
| 값 지정 | `value`, `checked` | `defaultValue`, `defaultChecked` |
| 변경 감지 | `onChange`가 필수 | 필요할 때 읽음 |
| 입력 중 반응 | 쉽다 | 어렵다 |

## value와 onChange

`value`를 주면 입력은 그 값으로 고정되고, 바꾸려면 `onChange`에서 State를 갱신해야 합니다. 둘은 항상 한 쌍입니다.

```jsx
<input value={text} />
// ❌ onChange 없음: 입력할 수 없는 읽기 전용이 된다(경고)
<input value={text} readOnly />
// ✅ 일부러 읽기 전용이면 readOnly를 명시
```

- `onChange` 없이 `value`만 주면 입력이 막히고 경고가 납니다. 초기값만 주려면 `defaultValue`를 쓰거나, 읽기 전용이면 `readOnly`를 붙입니다.
- `value`가 `undefined`나 `null`이면 비제어로 취급되다가 값이 생기면 제어로 바뀌어 경고가 납니다. 서버에서 온 값은 `value={data.name ?? ''}`로 항상 문자열을 줍니다. 체크박스의 `checked`는 `?? false`로 항상 불리언을 줍니다.
- State에는 `e.target.value`를 동기적으로 그대로 넣습니다. 값을 변환해서 넣거나(`toUpperCase()`) `setTimeout`으로 늦게 넣으면 커서가 맨 앞으로 튑니다. 변환은 렌더 중에 표시할 때 합니다.

## defaultValue

`defaultValue`는 비제어 입력의 초기값입니다. 첫 렌더 이후에 바꿔도 입력은 영향을 받지 않습니다.

```jsx
<input name="title" defaultValue={post.title} />
<textarea name="body" defaultValue={post.body} />
<select name="status" defaultValue="draft">...</select>
```

- 한 요소에는 `value`와 `defaultValue` 중 하나만 씁니다.
- 다른 대상의 데이터로 바뀌어도 입력을 새 `defaultValue`로 다시 채우려면 `key`를 줍니다(13편).
- 체크박스와 라디오의 초기값은 `defaultChecked`입니다.

## checked

`checked`는 체크박스와 라디오의 선택 여부를 State로 제어하는 prop입니다. `value`가 아니라 `checked`를 쓰는 것이 텍스트 입력과의 차이입니다.

- 체크박스: `checked={불리언}`과 `onChange`에서 `e.target.checked`.
- 라디오: `checked={선택값 === 자기 value}`와 `onChange`에서 `e.target.value`.
- `checked`만 주고 `onChange`를 빼면 `value`와 같은 읽기 전용 경고가 납니다.
- 체크박스의 `value` 속성은 폼 제출 시 전송되는 값일 뿐 선택 여부와 무관합니다. 선택 여부는 `checked`입니다.

**흔한 실수:** 체크박스에서 `e.target.value`를 읽는 것입니다. 항상 같은 문자열이 나옵니다. `e.target.checked`를 읽어야 합니다.

## 여러 입력값

입력이 여러 개면 State를 객체 하나로 두고, 입력의 `name`을 키로 써서 핸들러 하나로 처리합니다.

```jsx
const initial = { email: '', agree: false };
const [form, setForm] = useState(initial);

function handleChange(e) {
  const { name, type, value, checked } = e.target;
  setForm(prev => ({
    ...prev,
    [name]: type === 'checkbox' ? checked : value,
  }));
}
// <input name="email" value={form.email}
//   onChange={handleChange} />
```

- `[name]`은 계산된 프로퍼티 이름이라서 `name` 속성의 값이 키가 됩니다. 입력의 `name`과 State 키를 같게 맞춥니다.
- 객체는 복사해 갱신합니다(11편). 이전 State를 기준으로 하므로 updater 함수(`prev =>`)를 씁니다(10편).
- 체크박스는 `value`가 아니라 `checked`를 저장하므로 타입으로 분기합니다.
- 입력마다 `useState`를 쓰는 방식도 틀리지 않습니다. 입력이 서로 독립적이고 적을 때 단순합니다.

## form 제출

`form`의 `onSubmit`에서 제출을 처리합니다. 브라우저의 기본 제출은 페이지를 새로고침하므로 `preventDefault()`로 막습니다.

```jsx
function handleSubmit(e) {
  e.preventDefault();
  console.log(form); // 제어: State를 그대로 사용
}

<form onSubmit={handleSubmit}>
  <input
    name="email"
    value={form.email}
    onChange={handleChange}
  />
  <button type="submit">Send</button>
</form>
```

- 제출 버튼은 `button type="submit"`이거나 `type`이 없는 `button`입니다. 입력창에서 Enter를 눌러도 제출됩니다.
- 제출에 쓸 값은 제어면 State, 비제어면 `FormData`(아래)로 얻습니다.
- 이벤트 핸들러는 `button`의 `onClick`이 아니라 `form`의 `onSubmit`에 두는 것이 Enter 제출까지 포함하는 올바른 위치입니다.
- `form`의 `action`에 함수를 넘기는 React 19의 방식은 별도 개념(Form Actions)이며 중급 과목에서 다룹니다. 이 편은 `onSubmit` 기준입니다.

## reset

reset은 폼을 초기 상태로 되돌리는 동작입니다. 비제어 입력은 `button type="reset"`을 쓰면 브라우저가 입력을 기본값(`defaultValue`, `defaultChecked`)으로 되돌립니다.

```jsx
<form>
  <input name="q" defaultValue="react" />
  <button type="reset">Reset</button>
</form>
```

- 제어 입력은 값이 State이므로 State를 초기값으로 되돌려야 합니다.

```jsx
const initial = { email: '', agree: false };
const [form, setForm] = useState(initial);

function handleReset() {
  setForm(initial);
}
```

- 여러 입력을 한 번에 비우려면 폼 컴포넌트에 `key`를 바꿔 새로 만드는 방법이 있습니다(13편).
- 제출이 성공한 뒤에 비울 때도 같은 방법을 씁니다.

## file input

`input type="file"`은 파일을 선택하는 요소이며 항상 비제어입니다. `value`로 값을 제어할 수 없습니다.

```jsx
function Upload() {
  const [file, setFile] = useState(null);
  return (
    <input
      type="file"
      accept="image/*"
      onChange={e => setFile(e.target.files[0] ?? null)}
    />
  );
}
```

- 선택한 파일은 `e.target.files`(`FileList`)에서 읽습니다. 각 항목은 `name`, `size`, `type`을 가진 `File` 객체입니다.
- 여러 파일은 `multiple` 속성을 줍니다. 허용 형식은 `accept`로 알립니다(`image/*`, `.pdf`). `accept`는 선택 창을 제한할 뿐 검증이 아니므로 서버에서도 확인합니다.
- `value`는 보안상 `C:\fakepath\파일이름` 형태로 나오고 비우는 것 말고는 코드로 설정할 수 없습니다.
- 선택한 파일 정보를 화면에 쓰려면 `onChange`에서 `files`를 State에 저장합니다. 입력 자체는 그대로 DOM이 보관합니다.
- `FormData`에서는 파일 입력이 `File` 객체로 들어갑니다.

## 한글 조합 입력

한글, 일본어, 중국어는 IME(입력기)가 키 입력을 모아 글자를 완성하는 조합(composition) 과정을 거칩니다. 조합 중에는 글자가 확정되지 않은 상태입니다.

- 조합은 `compositionstart`로 시작해 `compositionupdate`를 거쳐 `compositionend`로 끝납니다.
- 조합 중에 발생한 키보드 이벤트는 `isComposing`이 `true`입니다. 조합이 끝나면 `false`입니다.
- Enter로 전송하는 입력창에서 조합 중인 글자를 확정하려고 누른 Enter가 `keydown`을 일으켜 전송이 실행되는 문제가 대표적입니다. 조합 중이면 무시합니다.

```jsx
function handleKeyDown(e) {
  if (e.nativeEvent.isComposing) return; // 조합 중이면 무시
  if (e.key === 'Enter') send();
}
```

- React의 키보드 이벤트 객체에는 `isComposing`이 없습니다. 원래 브라우저 이벤트를 가리키는 `nativeEvent`로 접근합니다.
- 조합 시작·끝은 `onCompositionStart`와 `onCompositionEnd`로 직접 감지할 수도 있습니다.
- 영어만 입력하면 조합 과정이 없어서 이 문제가 드러나지 않고, 한글로 테스트할 때 발견됩니다.

## name 속성과 FormData

`FormData`는 `form`에서 제출될 값을 `이름 → 값` 쌍으로 모은 브라우저 객체입니다. 비제어 입력의 값을 한 번에 읽는 방법이며, 입력에 `name`이 있어야 포함됩니다.

```jsx
function handleSubmit(e) {
  e.preventDefault();
  const data = new FormData(e.currentTarget);
  data.get('email');    // 첫 번째 값(없으면 null)
  data.getAll('tag');   // 같은 이름의 모든 값 배열
  Object.fromEntries(data); // { email: '...', tag: '...' }
}
```

- `name`이 없는 입력, `disabled` 입력, 체크되지 않은 체크박스와 라디오는 포함되지 않습니다.
- 같은 이름이 여러 개면 `Object.fromEntries`는 마지막 값만 남깁니다. 모두 필요하면 `getAll`로 읽습니다.
- 파일 입력은 `File` 객체로 담깁니다. 값은 모두 문자열 또는 `File`이므로 숫자는 변환합니다.
- 제어 입력도 `name`을 주면 `FormData`로 읽을 수 있지만, 이미 State가 있으니 State를 쓰는 편이 자연스럽습니다.
- `name`은 위의 "여러 입력값"에서처럼 핸들러 하나로 처리할 때도 키 역할을 합니다.

## 핵심 정리

- `value`, `checked`는 제어, `defaultValue`, `defaultChecked`는 비제어입니다. 텍스트 계열은 `e.target.value`, 체크박스는 `e.target.checked`를 읽습니다.
- `value`와 `onChange`는 한 쌍이며, `value`에는 항상 문자열(또는 `checked`에 불리언)을 줍니다. `select`는 `option`이 아니라 `select`에 `value`를 줍니다.
- 입력이 여럿이면 `name`을 키로 한 객체 State와 핸들러 하나로 관리합니다.
- 제출은 `onSubmit`에서 `preventDefault()` 후 처리하고, 비제어 값은 `name`이 있는 입력만 `FormData`로 모읍니다.
- 파일 입력은 항상 비제어이며 `files`에서 읽습니다. 한글 입력창의 Enter는 `e.nativeEvent.isComposing`을 확인합니다.
