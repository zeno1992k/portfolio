## useRef

`useRef`는 렌더링 사이에 값을 기억하되 그 값이 바뀌어도 재렌더링을 일으키지 않는 Hook입니다. 초기값을 받아 ref 객체를 반환합니다.

```jsx
import { useRef } from 'react'

function Counter() {
  const ref = useRef(0)
  function handleClick() {
    ref.current = ref.current + 1
    alert('Clicked ' + ref.current + ' times')
  }
  return <button onClick={handleClick}>Click</button>
}
// 클릭 1회 → 1, 2회 → 2. 화면의 버튼 글자는 그대로다
```

- 호출은 `useRef(initialValue)` 형태이고 반환값은 `{ current: initialValue }` 객체입니다.
- 다른 Hook처럼 컴포넌트(또는 Custom Hook)의 최상위에서만 호출합니다(자세히는 26편).
- 값을 화면에 보여 줘야 하면 ref가 아니라 State를 씁니다(아래 "useRef와 useState").
- 개발 모드의 StrictMode는 컴포넌트를 두 번 호출하므로 ref 객체도 두 번 만들어지고 하나는 버려집니다(자세히는 18편).

## Ref Object

ref 객체는 `current` 프로퍼티 하나를 가진 평범한 JavaScript 객체입니다. React는 렌더링마다 같은 객체를 돌려줍니다.

```jsx
const a = useRef(0)
// 렌더링 1: a는 객체 X, 렌더링 2: a는 같은 객체 X
// 일반 변수 { current: 0 }은 렌더링마다 새 객체가 된다
```

- 같은 객체를 반환하므로 ref는 렌더링 사이에 유지됩니다. 일반 지역 변수는 렌더링마다 초기화됩니다(자세히는 17편).
- 컴포넌트 인스턴스마다 따로 있습니다. 같은 컴포넌트를 두 번 쓰면 ref도 둘입니다.
- 개념상 `useState({ current: initialValue })`의 첫 번째 값을 반환하는 것과 같습니다. 그 객체를 바꿔도 `set`을 호출하지 않으므로 재렌더링되지 않습니다.
- ref 객체는 JSX의 `ref` 속성에 넘길 수도 있습니다. 그러면 React가 `current`를 DOM 노드로 채웁니다(아래 "DOM 접근").

초기값이 만드는 비용이 큰 객체라면 첫 렌더링에서만 한 번 만드는 지연 초기화 패턴을 씁니다. 렌더 중 ref를 읽거나 쓰지 말라는 규칙의 예외입니다.

```jsx
function Video() {
  const playerRef = useRef(null)
  if (playerRef.current === null) {
    playerRef.current = new VideoPlayer() // 한 번만 생성
  }
}
// useRef(new VideoPlayer())는 결과가 첫 렌더링에서만 쓰이지만
// 생성자는 렌더링마다 호출된다
```

## current

`current`는 ref 객체가 값을 담는 프로퍼티이며 읽고 쓸 수 있습니다.

- 초기값은 `useRef`에 넘긴 값입니다.
- 마음대로 바꿀 수 있습니다. State와 달리 새 객체로 교체할 필요 없이 직접 대입합니다.
- 바꿔도 React는 알지 못하므로 재렌더링되지 않습니다. 다음 렌더링에서 읽으면 바뀐 값이 보이지만, 그 렌더링이 일어나는 시점은 다른 이유(State 변경 등)가 정합니다.
- `current`는 State처럼 렌더링마다 스냅샷으로 고정되지 않습니다. 읽는 시점의 최신 값입니다.

```jsx
const ref = useRef(0)
function handleClick() {
  ref.current = ref.current + 1 // ✅ 바로 반영
  console.log(ref.current)      // 방금 바꾼 값
}
```

- `current`는 이벤트 핸들러나 Effect 안에서 읽고 씁니다. 렌더링 중에는 읽지도 쓰지도 않습니다(아래 "렌더 중 ref 읽기·쓰기 금지").
- ref가 DOM 노드에 연결된 경우 `current`는 React가 설정하는 값이라 직접 대입하지 않습니다.

## DOM 접근

`useRef(null)`로 ref를 만들고 JSX 엘리먼트의 `ref` 속성에 넘기면 React가 그 엘리먼트의 DOM 노드를 `current`에 넣어 줍니다. 그러면 브라우저 DOM API를 직접 쓸 수 있습니다.

```jsx
function Box() {
  const boxRef = useRef(null)
  function handleClick() {
    boxRef.current.scrollIntoView({ behavior: 'smooth' })
  }
  return <div ref={boxRef} onClick={handleClick} />
}
```

- React는 렌더링이 끝나고 커밋 단계에서 `current`를 설정합니다. 그래서 첫 렌더링 중에는 `current`가 `null`이고, 재렌더링 중에는 이전 값입니다. DOM 노드는 이벤트 핸들러나 Effect에서 읽습니다.
- `ref`로 할 일은 DOM을 바꾸지 않는 작업이 안전합니다. 포커스, 스크롤, 크기 측정이 해당합니다.
- React가 관리하는 DOM 노드의 자식을 추가하거나 지우거나 내용을 바꾸지 않습니다. 이후 렌더링의 갱신과 어긋나서 화면이 깨지거나 에러가 납니다. React가 아무것도 그리지 않는 빈 `div` 같은 곳은 안전합니다.

### 자식 컴포넌트의 DOM 접근

React 19에서는 함수 컴포넌트가 `ref`를 일반 prop처럼 받을 수 있습니다. 받은 `ref`를 내부 DOM 엘리먼트에 넘기면 부모가 그 노드를 가집니다.

```jsx
function MyInput({ ref }) {
  return <input ref={ref} />
}
function Form() {
  const inputRef = useRef(null)
  return <MyInput ref={inputRef} />
}
```

- React 18 이하에서는 `forwardRef`로 감싸야 `ref`를 받을 수 있었습니다. React 19에서도 `forwardRef`는 동작합니다(자세히는 05편).
- 부모에게 노드 전체 대신 일부 메서드만 노출하려면 `useImperativeHandle`을 씁니다.
- 부모가 자식의 DOM을 직접 만지기보다 Props와 State로 제어할 수 있으면 그쪽을 먼저 고려합니다.

### 리스트와 ref

리스트의 개수는 렌더링 전에 알 수 없으므로 반복문 안에서 `useRef`를 호출할 수 없습니다. 이럴 때는 ref에 함수(ref 콜백)를 넘깁니다. 콜백은 DOM 노드를 받고, 정리 함수를 반환할 수 있습니다.

```jsx
<li
  key={cat.id}
  ref={(node) => {
    map.set(cat.id, node)
    return () => map.delete(cat.id)
  }}
/>
// map은 useRef로 만든 Map을 꺼낸 것이다
```

State를 바꾼 직후 그 결과가 반영된 DOM을 바로 읽어야 한다면 `flushSync`로 갱신을 즉시 반영할 수 있습니다. 대부분의 경우 필요 없습니다.

```jsx
import { flushSync } from 'react-dom'

flushSync(() => setTodos([...todos, newTodo]))
listRef.current.lastChild.scrollIntoView()
```

## focus

입력창에 포커스를 주는 것은 ref의 대표적인 용도입니다. 버튼을 눌렀을 때 `inputRef.current.focus()`를 호출합니다.

```jsx
function Form() {
  const inputRef = useRef(null)
  function handleClick() {
    inputRef.current.focus()
  }
  return (
    <>
      <input ref={inputRef} />
      <button onClick={handleClick}>Focus</button>
    </>
  )
}
```

- `focus()`는 DOM 메서드이고 React의 State나 Props로 표현하지 않습니다. 이런 명령형 동작이 ref가 필요한 대표적인 경우입니다.
- 마운트 직후 포커스가 필요하면 Effect 안에서 호출합니다. Effect는 커밋 뒤에 실행되어 `current`가 이미 채워져 있습니다(자세히는 20편).

```jsx
useEffect(() => {
  inputRef.current.focus()
}, [])
```

**흔한 실수:** 렌더링 중에 `inputRef.current.focus()`를 호출하는 것입니다. 첫 렌더링에서는 `current`가 `null`이라 에러가 납니다. 포커스는 이벤트 핸들러나 Effect에서 호출합니다.

## Timer ID

`setTimeout`과 `setInterval`이 돌려주는 ID는 화면에 보이지 않지만 나중에 `clearTimeout`, `clearInterval`로 취소할 때 필요합니다. 이 ID를 ref에 저장합니다.

```jsx
function Stopwatch() {
  const [now, setNow] = useState(null)
  const intervalRef = useRef(null)
  function handleStart() {
    intervalRef.current = setInterval(() => {
      setNow(Date.now())
    }, 10)
  }
  function handleStop() {
    clearInterval(intervalRef.current)
  }
}
```

- 시작 함수와 중지 함수는 서로 다른 이벤트 핸들러이므로 ID를 공유할 곳이 필요합니다. 렌더링 사이에 유지되면서 바꿔도 재렌더링이 필요 없는 ref가 맞습니다.
- 일반 지역 변수에 저장하면 재렌더링 때 초기화되어 중지 함수가 ID를 잃습니다.
- ID를 State에 저장하면 동작은 하지만 바뀔 때마다 불필요한 재렌더링이 일어납니다. 화면에 쓰이지 않기 때문입니다.
- 한 Effect 안에서 시작하고 그 Effect의 정리 함수에서 멈춘다면 ref 없이 Effect 안의 지역 변수로 충분합니다(자세히는 20편).
- 컴포넌트가 사라질 때 타이머가 남지 않도록 정리해야 합니다.

## 렌더에 필요 없는 값

화면 출력에 쓰이지 않는 값은 ref에 둡니다. 값이 바뀌어도 화면이 달라지지 않으므로 재렌더링이 필요 없습니다.

- 타임아웃, 인터벌 ID
- DOM 엘리먼트
- JSX를 계산하는 데 필요하지 않은 객체. 예를 들면 외부 라이브러리의 인스턴스(플레이어, 지도 객체), 웹소켓 연결 객체
- 이벤트 핸들러만 읽는 플래그나 카운터. 예를 들면 클릭 횟수를 세기만 하는 경우

판단 기준은 하나입니다. 이 값이 바뀔 때 화면도 바뀌어야 하는가입니다. 바뀌어야 하면 State이고, 아니면 ref입니다.

ref는 React 바깥의 시스템과 소통할 때 쓰는 탈출구(escape hatch)입니다. 애플리케이션 로직 대부분이 ref에 의존한다면 설계를 다시 살펴봅니다.

## Previous Value

이전 값을 기억하는 ref 패턴은 값을 매 렌더링이 끝난 뒤 Effect에서 ref에 저장하고, 다음 렌더링에서 그 ref를 읽는 것입니다.

```jsx
function usePrevious(value) {
  const ref = useRef(undefined)
  useEffect(() => {
    ref.current = value // 커밋 뒤에 저장
  })
  return ref.current // 이번 렌더링에서 읽으면 이전 값
}
// count가 0 → 1: 렌더링 중 prev는 0, 그 뒤 ref는 1로 갱신
```

- Effect는 렌더링이 끝난 뒤 실행되므로 렌더링 중 `ref.current`는 직전 렌더링의 값입니다. 의존성 배열이 없어서 매 렌더링 뒤에 갱신됩니다.
- 이 패턴은 렌더링 중에 `ref.current`를 읽습니다. 앞서 본 규칙과 어긋나므로 값이 화면 출력에 쓰이면 권장하지 않습니다. 이전 값에 따라 화면이 바뀌어야 하면 State로 이전 값을 저장하는 방식이 React 문서가 설명하는 방법입니다.

```jsx
function CountLabel({ count }) {
  const [prevCount, setPrevCount] = useState(count)
  const [trend, setTrend] = useState(null)
  if (prevCount !== count) {
    setPrevCount(count)
    setTrend(count > prevCount ? 'up' : 'down')
  }
  return <p>{count} {trend}</p>
}
```

- 렌더링 중에 `set`을 부를 때는 반드시 `prevCount !== count` 같은 조건 안에서 부르고, 조건 안에서 이전 값을 `setPrevCount(count)`로 갱신해야 합니다. 그렇지 않으면 무한히 재렌더링됩니다.
- 이렇게 렌더링 중에 `set`을 부를 수 있는 컴포넌트는 지금 렌더링 중인 컴포넌트뿐입니다. 다른 컴포넌트의 `set`을 렌더링 중에 부르면 에러입니다.
- 대부분은 이 패턴이 필요 없습니다. 현재 Props나 State로 계산할 수 있는 값은 State로 두지 말고 렌더링 중에 계산하고, 관련 State는 이벤트 핸들러 안에서 한꺼번에 갱신합니다(자세히는 12편).

## useRef와 useState

| 항목 | `useRef` | `useState` |
|------|----------|------------|
| 반환값 | `{ current: initialValue }` | `[value, setValue]` |
| 값을 바꾸면 재렌더링 | 일어나지 않음 | 일어남 |
| 바꾸는 방법 | `current`에 직접 대입 | `set` 함수 호출 |
| 렌더링 중 읽기 | 하지 않음 | 안전함 |
| 렌더링 사이 유지 | 됨 | 됨 |
| 용도 | 화면에 쓰이지 않는 값 | 화면에 쓰이는 값 |

선택 기준은 이렇습니다.

- 정보가 렌더링에 쓰이면 State에 둡니다.
- 이벤트 핸들러나 Effect에서만 쓰고 바뀌어도 재렌더링이 필요 없으면 ref가 더 효율적입니다.
- 둘이 섞인 예가 스톱워치입니다. 화면에 보이는 시작 시각과 현재 시각은 State이고, 인터벌 ID는 ref입니다.

```jsx
const [startTime, setStartTime] = useState(null) // 화면에 쓰임
const [now, setNow] = useState(null)             // 화면에 쓰임
const intervalRef = useRef(null)                 // ID만 보관
```

**흔한 실수:** 화면에 보이는 값을 ref에 두는 것입니다. 값은 바뀌는데 화면이 그대로여서 버그처럼 보입니다.

```jsx
const countRef = useRef(0)
countRef.current += 1
return <p>{countRef.current}</p> // ❌ 클릭해도 화면이 갱신되지 않음
```

## 렌더 중 ref 읽기·쓰기 금지

렌더링 중에는 `ref.current`를 읽지도 쓰지도 않습니다. React는 `current`가 언제 바뀌는지 알지 못하므로, 렌더링 중에 읽으면 컴포넌트 동작을 예측하기 어렵습니다. 렌더링은 순수해야 한다는 규칙의 연장입니다(자세히는 17편).

```jsx
function MyComponent() {
  myRef.current = 123              // ❌ 렌더 중 쓰기
  return <h1>{otherRef.current}</h1> // ❌ 렌더 중 읽기
}
```

읽고 쓰는 곳은 이벤트 핸들러와 Effect입니다.

```jsx
function MyComponent() {
  useEffect(() => {
    myRef.current = 123 // ✅
  })
  function handleClick() {
    doSomething(otherRef.current) // ✅
  }
}
```

- 유일한 예외는 앞서 본 지연 초기화입니다. `current`가 비었을 때만 한 번 채웁니다.
- DOM 노드를 담은 ref는 첫 렌더링 중에 `null`이고 이후 렌더링 중에는 갱신 전의 값입니다. 렌더링 중에 읽어도 믿을 수 있는 값이 아닙니다.
- 렌더링에 필요한 값이면 State나 Props로 바꿉니다. 렌더링 중 읽기가 필요하다는 것은 그 값이 State여야 한다는 신호입니다.

## 핵심 정리

- `useRef(initial)`은 `{ current: initial }` 객체를 반환하고 React는 렌더링마다 같은 객체를 돌려주므로 값이 렌더링 사이에 유지됩니다.
- `current`는 직접 대입하며 바꿔도 재렌더링되지 않습니다.
- JSX의 `ref` 속성에 넘기면 React가 커밋 때 `current`에 DOM 노드를 넣어 줍니다. 포커스, 스크롤, 크기 측정 같은 DOM을 바꾸지 않는 작업에만 씁니다.
- 타이머 ID, 외부 객체처럼 화면에 쓰이지 않는 값은 ref에, 화면에 보이는 값은 State에 둡니다.
- 렌더링 중에는 `ref.current`를 읽거나 쓰지 않고 이벤트 핸들러와 Effect에서만 다룹니다. 예외는 첫 렌더링의 지연 초기화입니다.
