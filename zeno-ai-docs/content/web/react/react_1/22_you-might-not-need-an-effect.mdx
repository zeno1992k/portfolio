<Callout type="info">
  **이번 문서의 목표:** 어떤 코드가 Effect에 있을 필요가 없는지 판단하고, 각 경우에 렌더 중 계산, key, 이벤트 핸들러, useSyncExternalStore 중 알맞은 대안으로 바꿀 수 있습니다.
</Callout>

Effect는 React 밖의 시스템(네트워크, 브라우저 DOM, 비 React 위젯)과 동기화하는 탈출구입니다. 외부 시스템이 없는데 props나 state가 바뀌어 state를 갱신하려는 코드라면 Effect가 필요 없습니다. Effect에 넣으면 렌더가 한 번 더 일어나고 코드가 복잡해집니다(Effect 기본은 20편, 의존성은 21편).

## Derived State

Derived State(파생 상태)는 다른 state나 props에서 계산할 수 있는 값입니다. 별도 state로 두지 않고 렌더 중에 계산합니다.

```jsx
// ❌ state + Effect: 렌더가 두 번 일어난다
const [fullName, setFullName] = useState('');
useEffect(() => {
  setFullName(firstName + ' ' + lastName);
}, [firstName, lastName]);

// ✅ 렌더 중에 계산
const fullName = firstName + ' ' + lastName;
```

- ❌ 방식은 `firstName`이 바뀌면 오래된 `fullName`으로 한 번 렌더하고, Effect가 `setFullName`을 호출해 다시 렌더합니다.
- ✅ 방식은 값이 항상 입력과 일치하며 렌더가 한 번입니다.
- 판단 기준은 그 값이 props나 기존 state만으로 계산되는지입니다. 그렇다면 state가 아닙니다(State 구조 설계는 12편).

## 데이터 변환

받은 데이터를 화면에 맞게 바꾸는 계산(정렬, 합계, 포맷)도 렌더 중에 합니다. 컴포넌트 최상위에서 변환하면 입력이 바뀔 때마다 결과가 자동으로 따라옵니다.

```jsx
function Cart({ items }) {
  const total = items.reduce((sum, i) => sum + i.price, 0);
  const labels = items.map((i) => i.name.toUpperCase());
  // items가 바뀌면 total, labels도 다음 렌더에 맞게 바뀐다
}
```

- 변환 결과를 state에 넣고 Effect로 동기화하는 방식은 매번 한 박자 늦은 화면을 한 번 그립니다.
- 렌더 중 계산은 순수해야 합니다. 요청 전송이나 DOM 조작 같은 부수 효과를 넣지 않습니다.

## 리스트 필터링

필터링한 목록도 파생 값입니다. 계산이 비싸면 `useMemo`로 결과를 캐시합니다.

```jsx
// ❌
const [visible, setVisible] = useState([]);
useEffect(() => {
  setVisible(getFilteredTodos(todos, filter));
}, [todos, filter]);

// ✅ 계산만 하거나, 비싸면 useMemo
const visible = useMemo(
  () => getFilteredTodos(todos, filter),
  [todos, filter],
);
```

- `useMemo`는 의존성이 바뀌지 않으면 이전 계산 결과를 재사용합니다. 렌더 중 계산을 그대로 두는 것이 기본이고, 비용이 클 때만 감쌉니다.
- 비싼지는 `console.time`과 `console.timeEnd`로 측정합니다. React 공식 문서의 기준은 기록된 시간이 1ms 이상일 때 메모이제이션을 고려하라는 것입니다.
- React Compiler를 쓰면 많은 경우 자동으로 메모이제이션됩니다(고급 과목).

## Props 변화 State Reset

props가 바뀔 때 State 전체를 초기화하려고 Effect에서 `set...('')`를 호출하는 방식은 잘못된 패턴입니다.

```jsx
// ❌ userId가 바뀌면 오래된 comment로 한 번 렌더한 뒤 비운다
function ProfilePage({ userId }) {
  const [comment, setComment] = useState('');
  useEffect(() => {
    setComment('');
  }, [userId]);
}
```

- 이전 사용자의 입력이 새 사용자 화면에 한 번 그려졌다가 지워집니다.
- 이 컴포넌트 안에 중첩된 자식들의 state도 각각 초기화해야 해서 빠뜨리기 쉽습니다.
- 올바른 방법은 다음 절의 key입니다.

## key로 Reset

React는 같은 위치의 같은 타입 컴포넌트를 같은 것으로 보고 State를 유지합니다. `key`를 바꾸면 다른 컴포넌트로 취급해 State를 버리고 새로 시작합니다(규칙은 13편).

```jsx
// ✅
export default function ProfilePage({ userId }) {
  return <Profile userId={userId} key={userId} />;
}

function Profile({ userId }) {
  const [comment, setComment] = useState('');
  // userId가 바뀌면 Profile이 새로 만들어져 comment는 ''
}
```

- 초기화하고 싶은 State를 가진 컴포넌트를 분리하고, 바깥에서 그 컴포넌트에 `key`를 줍니다. key는 그 컴포넌트를 렌더하는 바깥(부모)에서 줍니다.
- 자식 컴포넌트의 State까지 한 번에 초기화됩니다.
- key 변경은 컴포넌트와 DOM을 새로 만드는 비용이 있으므로 State를 버리고 싶을 때만 씁니다.

## Props 변화 State 조정

props가 바뀔 때 State의 일부만 조정해야 하는 경우입니다. 가장 좋은 방법은 조정이 필요 없도록 state 구조를 바꾸는 것입니다.

```jsx
// ❌ items가 바뀌면 selection을 Effect로 비운다
const [selection, setSelection] = useState(null);
useEffect(() => { setSelection(null); }, [items]);

// ✅ id만 저장하고 선택된 객체는 계산한다
const [selectedId, setSelectedId] = useState(null);
const selection =
  items.find((item) => item.id === selectedId) ?? null;
```

- 객체 전체 대신 id를 저장하면 `items`가 바뀌어 그 id가 없을 때 `selection`이 자동으로 `null`이 됩니다. 조정 코드가 필요 없습니다.
- 구조를 바꿀 수 없을 때는 렌더 중에 state를 직접 갱신할 수 있습니다. 이전 props를 state에 저장해 비교합니다.

```jsx
const [selection, setSelection] = useState(null);
const [prevItems, setPrevItems] = useState(items);
if (items !== prevItems) {
  setPrevItems(items);
  setSelection(null); // 렌더 중에 같은 컴포넌트의 state 갱신
}
```

- 렌더 중 갱신은 React가 반환한 JSX를 버리고 즉시 다시 렌더합니다. 같은 컴포넌트의 state만 갱신할 수 있고, 다른 컴포넌트의 state를 갱신하면 에러입니다.
- `items !== prevItems` 같은 조건이 없으면 루프가 됩니다.
- Effect 방식보다 낫지만 읽기 어려운 패턴이므로 계산이나 key로 해결되는지 먼저 확인합니다.

## 이벤트 반응

사용자의 특정 동작(클릭, 제출)에 반응하는 코드는 이벤트 핸들러에 둡니다. 코드를 Effect에 둘지 핸들러에 둘지는 왜 그 코드가 실행되어야 하는지로 정합니다.

| 실행 이유 | 둘 곳 |
|-----------|-------|
| 컴포넌트가 화면에 표시되었기 때문(분석 로그, 연결) | Effect |
| 사용자가 특정 동작을 했기 때문(구매, 제출, 알림) | 이벤트 핸들러 |

```jsx
// ❌ product가 장바구니에 있으면 알림: 새로고침해도 뜬다
useEffect(() => {
  if (product.isInCart) {
    showNotification(`Added ${product.name}!`);
  }
}, [product]);
```

- 이 Effect는 장바구니에 담긴 상품이 있는 페이지를 열거나 새로고침할 때마다 알림을 띄웁니다. 원했던 것은 "담기 버튼을 누른 순간"입니다.
- state를 "무슨 일이 일어났다"는 신호로 쓰고 Effect가 그것을 감지하게 만드는 패턴은 거의 항상 이벤트 핸들러에서 해결됩니다.

## Event Handler로 이동

여러 핸들러가 같은 로직을 공유해야 하면 함수로 뽑아서 각 핸들러가 호출합니다. 공유한다고 Effect에 넣지 않습니다.

```jsx
function ProductPage({ product, addToCart }) {
  function buyProduct() {
    addToCart(product);
    showNotification(`Added ${product.name}!`);
  }
  function handleBuyClick() { buyProduct(); }
  function handleCheckoutClick() {
    buyProduct();
    navigateTo('/checkout');
  }
}
```

POST 요청도 같은 기준입니다.

```jsx
// 화면에 표시되었기 때문에 보내는 로그 -> Effect
useEffect(() => {
  post('/analytics/event', { eventName: 'visit_form' });
}, []);

// 제출 버튼을 눌렀기 때문에 보내는 요청 -> 핸들러
function handleSubmit(e) {
  e.preventDefault();
  post('/api/register', { firstName, lastName });
}
```

- 제출 요청을 `jsonToSubmit` 같은 state에 담아 Effect가 보내게 하면 state와 Effect 쌍이 늘고, 의존성이 바뀔 때마다 의도치 않은 시점에 요청이 나갑니다.
- 핸들러는 사용자가 동작한 그 시점에만 한 번 실행되므로 개발 모드의 StrictMode 재실행에도 영향을 받지 않습니다.

## 연쇄 Effect

한 Effect가 state를 바꾸고 그 state를 의존성으로 가진 다른 Effect가 또 state를 바꾸는 연쇄는 피합니다.

```jsx
useEffect(() => {                       // ❌ 연쇄
  if (card?.gold) setGoldCount((c) => c + 1);
}, [card]);
useEffect(() => {
  if (goldCount > 3) {
    setRound((r) => r + 1);
    setGoldCount(0);
  }
}, [goldCount]);
```

- 연쇄는 단계마다 렌더를 일으켜서 느립니다. 또 데이터 흐름이 코드 곳곳에 흩어져서 한 값을 바꾸면 어디까지 영향이 가는지 추적하기 어렵습니다.
- 해결은 다음 값을 이벤트 핸들러에서 한 번에 계산해 한꺼번에 설정하는 것입니다. 렌더 중에 계산할 수 있는 값(`isGameOver = round > 5`)은 state로 두지 않습니다.

```jsx
function handlePlaceCard(nextCard) {
  setCard(nextCard);
  if (nextCard.gold) {
    if (goldCount < 3) setGoldCount(goldCount + 1);
    else { setGoldCount(0); setRound(round + 1); }
  }
}
```

- 연쇄가 맞는 경우도 있습니다. 앞 드롭다운의 선택값으로 네트워크에서 다음 드롭다운의 선택지를 가져오는 경우처럼 각 단계가 네트워크와의 동기화라면 Effect 연쇄가 적절합니다.

## 앱 초기화 코드

앱이 시작할 때 한 번만 실행해야 하는 코드(저장소 읽기, 토큰 확인)를 `useEffect(..., [])`에 두면 개발 모드에서 두 번 실행됩니다. StrictMode가 일부러 Effect를 재실행하기 때문입니다(자세히는 18편).

```jsx
let didInit = false;                   // 모듈 변수 플래그

function App() {
  useEffect(() => {
    if (!didInit) {
      didInit = true;
      loadDataFromLocalStorage();
      checkAuthToken();
    }
  }, []);
}
```

모듈 최상위에서 실행하는 방법도 있습니다.

```jsx
if (typeof window !== 'undefined') {   // 브라우저인지 확인
  checkAuthToken();
  loadDataFromLocalStorage();
}

function App() { /* ... */ }
```

- 모듈 최상위 코드는 컴포넌트가 import될 때 한 번 실행됩니다. 렌더되지 않아도 실행되므로 무거운 코드는 신중히 넣습니다.
- 플래그 방식은 마운트 이후에 실행되고, 모듈 최상위 방식은 앱이 렌더되기 전에 실행됩니다.
- 이 코드가 Effect에 있어야 하는 외부 동기화인지, 단순히 한 번 실행하면 되는 초기화인지 구분합니다. 후자는 Effect가 아닙니다.

## 부모에게 변경 알리기

자식의 state가 바뀔 때 부모의 `onChange`를 호출하려고 Effect를 쓰면 렌더가 불필요하게 늘어납니다.

```jsx
// ❌ 자식이 렌더되고, Effect가 부모를 호출하고, 부모가 또 렌더
useEffect(() => { onChange(isOn); }, [isOn, onChange]);
```

- 자식 state 갱신으로 화면이 한 번 그려진 뒤 Effect가 `onChange`를 호출하고, 부모의 state 갱신이 렌더를 한 번 더 일으킵니다.
- 해결은 state를 바꾸는 이벤트 핸들러에서 둘을 함께 호출하는 것입니다. React는 한 이벤트 안의 갱신을 한 번에 묶어 렌더합니다.

```jsx
function Toggle({ onChange }) {
  const [isOn, setIsOn] = useState(false);
  function updateToggle(nextIsOn) {
    setIsOn(nextIsOn);   // 내 state
    onChange(nextIsOn);  // 부모 state
  }
}
```

- 더 단순한 방법은 state를 부모로 끌어올려 `isOn`과 `onChange`를 props로 받는 제어 컴포넌트로 만드는 것입니다(자세히는 14편).
- 데이터를 부모에게 올려주는 경우도 같습니다. 자식이 데이터를 가져와 Effect로 부모에 전달하지 말고, 부모가 가져와 자식에게 props로 내려줍니다. 데이터 흐름은 부모에서 자식 방향이어야 추적이 쉽습니다.

## 외부 스토어 구독

React 밖에서 관리되는 데이터(브라우저 API, 서드파티 스토어)를 읽을 때, Effect와 state로 직접 동기화하지 말고 `useSyncExternalStore`를 씁니다.

```jsx
// ❌ state + Effect로 구독
const [isOnline, setIsOnline] = useState(true);
useEffect(() => {
  const update = () => setIsOnline(navigator.onLine);
  update();
  window.addEventListener('online', update);
  window.addEventListener('offline', update);
  return () => { /* 두 리스너 제거 */ };
}, []);
```

```jsx
// ✅
function subscribe(callback) {
  window.addEventListener('online', callback);
  window.addEventListener('offline', callback);
  return () => {
    window.removeEventListener('online', callback);
    window.removeEventListener('offline', callback);
  };
}
```

```jsx
function useOnlineStatus() {
  return useSyncExternalStore(
    subscribe,
    () => navigator.onLine, // 클라이언트 스냅샷
    () => true,             // 서버 스냅샷
  );
}
```

- 시그니처는 `useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot?)`이고 현재 스냅샷을 돌려줍니다. 세 번째 인자는 서버 렌더링 때 쓰는 값입니다.
- `subscribe`는 콜백을 받아 스토어에 등록하고 구독 해제 함수를 반환합니다. 컴포넌트 밖에서 선언해 렌더마다 다시 구독하지 않게 합니다.
- `getSnapshot`은 값이 바뀌지 않았다면 같은 참조를 반환해야 합니다. 호출할 때마다 새 객체를 만들어 반환하면 무한 렌더가 됩니다.
- `getSnapshot`과 `getServerSnapshot` 규칙은 Hook 레퍼런스에 있습니다.

## 핵심 정리

- 외부 시스템이 없는데 props나 state로 state를 맞추는 Effect는 필요 없고, 렌더 중 계산이나 key로 대체합니다.
- 파생 값, 데이터 변환, 필터링은 렌더 중에 계산하고 비쌀 때만 `useMemo`로 캐시합니다.
- props 변화에 따른 State 전체 초기화는 key를, 일부 조정은 state 구조 변경을 먼저 고려하고 마지막 수단으로 렌더 중 갱신을 씁니다.
- 사용자 동작에 대한 반응은 이벤트 핸들러에, 화면에 표시되었기 때문에 실행할 코드는 Effect에 둡니다.
- 연쇄 Effect는 이벤트 핸들러에서 한 번에 계산하고, 부모 알림도 핸들러에서 처리하거나 state를 끌어올립니다.
- 앱 초기화는 모듈 최상위나 플래그로 한 번만 실행하고, 외부 스토어 구독은 `useSyncExternalStore`를 씁니다.
