## Activity

`Activity`는 자식 UI를 언마운트하지 않고 숨기거나 되살리는 컴포넌트입니다. React 19.2에서 정식으로 추가되었습니다.

```jsx
import { Activity } from 'react'

<Activity mode={isShowing ? 'visible' : 'hidden'}>
  <Sidebar />
</Activity>
```

| prop | 값 | 기본값 |
|------|----|--------|
| `mode` | `'visible'` 또는 `'hidden'` | `'visible'` |
| `children` | 보이거나 숨길 UI | 없음 |

- 숨겨도 자식의 state와 DOM은 남고, 숨기는 동안 Effect는 정리됩니다.
- 19.2 발표 글은 앞으로 용도에 따라 모드를 더 추가할 계획이라고 밝혔습니다.

## 보이기 / 숨기기

`mode`가 `'visible'`이면 자식을 보이고 Effect를 마운트하며 업데이트를 평소대로 처리합니다. `'hidden'`이면 자식을 CSS `display: none`으로 숨깁니다.

```jsx
function App() {
  const [open, setOpen] = useState(true)
  return (
    <>
      <button onClick={() => setOpen(!open)}>토글</button>
      <Activity mode={open ? 'visible' : 'hidden'}>
        <Sidebar />
      </Activity>
    </>
  )
}
```

- 숨기는 방식은 DOM 요소에 `display: none`을 적용하는 것이라서, DOM 요소가 없는 자식은 숨길 대상이 없습니다. 텍스트만 렌더하는 숨겨진 Activity는 숨긴 텍스트가 아니라 아무것도 렌더하지 않습니다.
- `mode`를 다시 `'visible'`로 바꾸면 이전 state와 DOM을 복원하고 Effect를 다시 만듭니다.

## State 유지

숨겨진 동안에도 자식의 state는 보존됩니다. 입력 중인 텍스트, 접힌 상태, 스크롤 위치 같은 값이 그대로 돌아옵니다.

```jsx
function Draft() {
  const [text, setText] = useState('')
  return (
    <textarea
      value={text}
      onChange={(e) => setText(e.target.value)}
    />
  )
}
// <Activity>로 숨겼다 보이면 입력한 text가 남아 있음
```

- 공식 문서가 꼽는 효과는 두 가지입니다. 숨겨진 컴포넌트의 state 복원, 그리고 textarea 값이나 영상 재생 위치 같은 DOM 상태의 보존입니다.
- 조건부 렌더링으로 언마운트하면 같은 state가 사라집니다. 이를 막으려고 state를 부모로 끌어올리던 구조를 줄일 수 있습니다.
- 부모에서 내려 주는 props가 바뀌면 숨겨진 자식도 갱신됩니다. 다만 우선순위가 낮습니다(아래 절).

## Background Rendering

숨겨진 Activity의 자식은 보이는 화면을 방해하지 않는 낮은 우선순위로 렌더됩니다. 19.2 발표 글은 숨긴 상태에서 모든 업데이트를 React가 할 일이 없을 때까지 미룬다고 설명합니다.

```jsx
<Activity mode="hidden">
  <SlowPage /> {/* 보이기 전에 미리 렌더하고 데이터를 불러옴 */}
</Activity>
```

- 사용자가 다음에 갈 가능성이 큰 화면을 숨긴 채 미리 렌더하면(pre-render), 데이터·CSS·이미지를 백그라운드에서 불러와 이동이 빨라집니다.
- 처음부터 `mode="hidden"`으로 마운트해도 되고, 보이던 것을 숨겨도 됩니다.
- 미리 렌더하는 데이터는 Suspense를 지원하는 소스여야 불러옵니다(자세히는 11편).
- 숨겨진 트리의 렌더도 CPU를 쓰므로 무거운 화면을 여러 개 미리 렌더하면 비용이 쌓입니다.

## Hidden Tree

Hidden Tree는 `mode="hidden"`인 Activity 안의 컴포넌트 트리입니다. React 트리에서는 마운트된 상태로 남아 있고, DOM에서도 요소가 남은 채 `display: none`만 적용됩니다.

| 항목 | 숨겨진 트리에서의 상태 |
|------|------------------------|
| 컴포넌트 state | 유지 |
| DOM 요소 | 유지, `display: none` |
| ref | 유지 |
| Effect | 정리(cleanup)됨 |
| 렌더 | props가 바뀌면 낮은 우선순위로 진행 |

- DOM이 남아 있으므로 DOM 쪽 부수 효과는 계속됩니다. `video`, `audio`, `iframe`은 숨겨도 재생이 이어집니다.
- 다음 절의 방식으로 Effect 정리 시점에 직접 멈춰야 합니다.

## Effect 처리

숨기면 Effect의 정리 함수가 실행되고, 다시 보이면 Effect가 새로 실행됩니다. 구독, 타이머, 이벤트 리스너가 숨겨진 동안 풀립니다.

```jsx
useEffect(() => {
  const id = setInterval(tick, 1000)
  return () => clearInterval(id) // 숨길 때 실행됨
}, [])
```

- 마운트와 언마운트 때만 실행되는 줄 알았던 Effect가 숨김과 표시에도 맞춰 실행됩니다. 정리 함수가 올바르면 아무 문제가 없고, 정리 함수가 없는 Effect가 숨겨진 뒤에도 계속 도는 버그가 드러납니다.
- DOM 부수 효과(영상 재생)는 정리 함수로 멈춰야 합니다. 공식 문서는 `useLayoutEffect`의 정리 함수에서 `pause()`를 호출하라고 안내합니다.

```jsx
function Video() {
  const ref = useRef(null)
  useLayoutEffect(() => {
    const video = ref.current
    return () => video.pause() // 숨길 때 멈춤
  }, [])
  return <video ref={ref} controls src="/movie.mp4" />
}
```

- Effect 실행 순서는 04편, 정리 함수 규칙은 기초 과목의 Effect 편에서 다룹니다.

## 탭 UI

탭마다 Activity를 하나씩 두고, 선택된 탭만 `'visible'`로 합니다. 탭을 오가도 각 탭의 입력값과 스크롤이 유지됩니다.

```jsx
function Tabs({ tab }) {
  return (
    <>
      <Activity mode={tab === 'a' ? 'visible' : 'hidden'}>
        <TabA />
      </Activity>
      <Activity mode={tab === 'b' ? 'visible' : 'hidden'}>
        <TabB />
      </Activity>
    </>
  )
}
```

- 탭 수가 많고 각 탭이 무거우면 숨겨진 탭의 렌더 비용과 메모리가 누적됩니다. 방문한 탭만 Activity로 유지하거나, 자주 쓰는 탭에만 적용합니다.
- 숨긴 탭은 데이터를 미리 불러올 수 있어서 처음 열 때 대기가 줄어듭니다.

## Navigation UI

내비게이션에서는 떠난 화면을 숨겨 두었다가 뒤로 가기에서 그대로 복원할 수 있습니다. 목록의 스크롤 위치, 필터 입력값을 되돌리는 용도입니다.

```jsx
function Router({ page }) {
  const isList = page === 'list'
  return (
    <>
      <Activity mode={isList ? 'visible' : 'hidden'}>
        <ListPage />
      </Activity>
      {page === 'detail' && <DetailPage />}
    </>
  )
}
```

- 공식 발표 글이 꼽는 용도는 사용자가 이동할 가능성이 높은 화면을 미리 렌더하는 것과, 이동해 나간 화면의 state(입력 필드 등)를 저장해 뒤로 가기에서 유지하는 것입니다.
- 모든 화면을 유지하면 메모리가 늘어나므로 유지할 화면을 정해서 씁니다.
- 숨겨진 화면은 URL과 어긋날 수 있으므로 라우터와의 연동은 라우터 쪽 설계를 따릅니다.

## 조건부 렌더링과 차이

조건부 렌더링은 조건이 거짓이면 컴포넌트를 언마운트하고, `Activity`는 숨기기만 합니다.

| 항목 | `{cond && <X />}` | `<Activity mode="hidden">` |
|------|-------------------|----------------------------|
| 컴포넌트 | 언마운트 | 마운트 유지 |
| state | 사라짐 | 유지 |
| DOM | 제거 | 유지(`display: none`) |
| Effect | 정리됨 | 정리됨 |
| 숨긴 상태의 렌더 | 없음 | props 변경 시 낮은 우선순위로 진행 |
| 비용 | 낮음 | 메모리와 렌더 비용 발생 |
| 미리 렌더 | 불가 | 가능 |

- 다시 보였을 때 처음 상태로 시작해야 하면 조건부 렌더링이 맞습니다. 이전 상태를 이어 가야 하면 `Activity`가 맞습니다.
- 숨기는 동안 DOM이 남아 있으므로 `display: none` 때문에 의도하지 않은 스타일 충돌이 생기지 않는지 확인합니다.

## ViewTransition

`ViewTransition`은 요소가 나타나고, 사라지고, 이동하고, 크기가 바뀔 때 브라우저의 View Transition API로 애니메이션을 입히는 컴포넌트입니다.

```jsx
import { ViewTransition } from 'react'

{show && (
  <ViewTransition>
    <Panel />
  </ViewTransition>
)}
```

**릴리스 상태:** 19.3 발표 글(2026-09-09)이 View Transitions와 Fragment Refs가 정식(stable)이 되었다고 밝혔습니다. 2025년에는 실험 API였습니다. 2026-10-06에 확인한 `ViewTransition`, `Activity`, `addTransitionType` 레퍼런스 페이지에는 Canary 안내문이 없습니다. 다만 페이지 안 예제의 샌드박스는 19.3.0-canary 빌드를 가리키고 있으므로, 정식 버전(19.3 이상)에서 동작을 확인하고 씁니다.

- 기본 애니메이션은 부드러운 크로스 페이드입니다.
- DOM에서만 동작합니다. React Native 지원은 준비 중이라고 안내합니다.
- 기본값으로 `setState`만으로는 동작하지 않습니다. Transition 안의 업데이트에서만 발동합니다(아래 "Transition과 연결").
- `ViewTransition`은 DOM 노드보다 앞에 놓아야 합니다. 바깥에 `div`를 두고 그 안에 `ViewTransition`을 넣으면 enter와 exit가 동작하지 않습니다.

| prop | 의미 |
|------|------|
| `enter`, `exit`, `update`, `share` | 해당 발동 때 적용할 애니메이션 |
| `default` | 위 네 가지의 기본값 |
| `name` | 공유 요소 전환용 이름 |
| `onEnter`, `onExit`, `onUpdate`, `onShare` | JS 애니메이션 콜백 |

## View Transition API

View Transition API는 DOM 상태가 바뀔 때 이전과 이후를 스냅샷으로 떠서 그 사이를 브라우저가 애니메이션하는 브라우저 기능입니다. `ViewTransition` 컴포넌트가 이 API 위에서 동작합니다.

```js
document.startViewTransition(() => {
  updateDom() // 이전·이후 스냅샷 사이를 애니메이션
})
```

- 같은 문서 안의 전환은 `document.startViewTransition()`으로 시작합니다. 문서 간 전환(MPA)은 CSS의 `@view-transition` 규칙을 씁니다.
- 전환 중에는 `::view-transition` 아래에 `::view-transition-group`, `::view-transition-image-pair`, `::view-transition-old`, `::view-transition-new` 가상 요소가 만들어지고, CSS로 각각 꾸밉니다.
- 요소에 `view-transition-name`을 주면 그 요소가 별도 그룹으로 전환에 참여합니다.
- React에서는 `startViewTransition`을 직접 부르지 않습니다. React가 Transition 커밋 시점에 맞춰 호출하고, `ViewTransition`마다 이름을 자동으로 붙입니다.
- 직접 이름을 주는 `name` 대신 View Transition Class(`enter`, `exit`, `update`, `share` prop에 클래스 이름을 주는 방식)를 쓰기를 권합니다.

```css
::view-transition-group(.slide-in) { }
::view-transition-old(.slide-in) { }
::view-transition-new(.slide-in) { }
```

## enter, exit, update, share

React는 변경 내용을 보고 네 가지 중 어느 애니메이션을 낼지 정합니다.

| 종류 | 발동 조건 |
|------|-----------|
| enter | Transition 안에서 `ViewTransition`이 새로 삽입됨 |
| exit | Transition 안에서 `ViewTransition`이 제거됨 |
| update | 내부 DOM이 바뀌거나, 형제 때문에 크기·위치가 바뀜 |
| share | 같은 `name`의 `ViewTransition`이 한쪽에서 제거되고 다른 쪽에서 삽입됨 |

각 prop에는 `"auto"`(기본 크로스 페이드), `"none"`(애니메이션 없음), 클래스 이름 문자열, 전환 타입별 객체를 줄 수 있습니다.

```jsx
<ViewTransition
  default="none"
  enter="slide-up"
  exit="slide-down"
>
  <Panel />
</ViewTransition>
```

### enter

`ViewTransition`이 Transition 안에서 처음 삽입될 때 실행됩니다. 위 예에서는 `slide-up` 클래스가 입장 애니메이션을 정의합니다.

### exit

`ViewTransition`이 Transition 안에서 제거될 때 실행됩니다. 제거되는 DOM의 마지막 모습이 스냅샷으로 남아 애니메이션됩니다.

### update

`ViewTransition` 안쪽의 DOM이 바뀌었거나 형제 요소의 변화로 크기·위치가 달라졌을 때 실행됩니다. 일부만 애니메이션에서 빼려면 안쪽에 `update="none"`을 둔 `ViewTransition`을 중첩합니다.

```jsx
<ViewTransition>
  <div className={theme}>
    <ViewTransition update="none">
      {children}
    </ViewTransition>
  </div>
</ViewTransition>
```

### share

공유 요소 전환입니다. 한쪽 트리가 언마운트되고 다른 쪽이 마운트될 때, 같은 `name`을 가진 쌍이 있으면 언마운트되는 쪽에서 마운트되는 쪽으로 이어지는 애니메이션이 실행됩니다.

```jsx
<ViewTransition name={`thumb-${id}`}>
  <img src={src} alt="" />
</ViewTransition>
```

- `share`는 enter·exit보다 우선합니다.
- `name`은 같은 시점에 앱 안에서 유일해야 합니다. 같은 이름이 둘 이상 마운트되면 오류가 납니다. 항목 ID처럼 구분되는 값을 이름에 넣습니다.
- 쌍의 한쪽이 뷰포트 밖에 있으면 일반 enter·exit로 처리됩니다.
- 이름은 공유 요소에만 씁니다. 그 밖에는 React가 자동으로 붙이게 둡니다.
- JS로 직접 애니메이션하려면 `onEnter` 같은 콜백을 씁니다. `(instance, types)`를 받고, `instance.old`와 `instance.new`로 가상 요소에 접근하며, 정리 함수를 반환해야 합니다.

## Transition과 연결

`ViewTransition`은 Transition 안의 업데이트에서만 애니메이션합니다. `startTransition`, `Suspense`, `useDeferredValue`로 표시된 업데이트가 대상이고 일반 `setState`는 대상이 아닙니다(자세히는 09편, 10편).

```jsx
function show() {
  startTransition(() => setOpen(true)) // 애니메이션 발동
}
function showNow() {
  setOpen(true) // 애니메이션 없음
}
```

- 여러 업데이트는 하나의 애니메이션으로 묶여 처리됩니다.
- Suspense와 함께 쓰는 방식은 두 가지입니다.

```jsx
<ViewTransition>
  <Suspense fallback={<Spinner />}>
    <Content />
  </Suspense>
</ViewTransition>
```

- 위 구성은 Fallback에서 내용으로 바뀌는 순간 update 크로스 페이드가 납니다.
- `Suspense`의 Fallback과 내용에 각각 `ViewTransition`을 두면 Fallback은 exit, 내용은 enter로 따로 애니메이션합니다.
- 19.3 발표 글의 권장은 Fallback은 애니메이션 없이 즉시 나타내고, 내용이 Fallback을 대체할 때만 애니메이션하는 것입니다. `update="auto" default="none"`을 줍니다.
- 이미지와 폰트를 `Suspense` 안에 두면 로딩이 끝날 때까지 전환을 기다립니다.
- `Activity`와도 연동됩니다. `ViewTransition`이 `Activity` 안에 있고 `startTransition`으로 `mode`를 바꾸면 보일 때는 enter, 숨길 때는 exit가 발동합니다. 이때 state는 유지됩니다.

### addTransitionType

`addTransitionType(type)`은 `startTransition` 콜백 안에서 호출해, 그 전환의 원인을 문자열로 표시하는 함수입니다. `ViewTransition`의 prop에 객체를 주어 타입별로 다른 애니메이션을 고릅니다.

```jsx
startTransition(() => {
  addTransitionType('forward')
  setPage(next)
})
```

- 반환값은 없습니다. 한 전환에 여러 타입을 추가할 수 있고, 타입은 커밋이 끝나면 초기화됩니다.
- `addTransitionType`은 19.3 발표 글에서 View Transitions와 함께 정식 API로 소개됩니다.

## Navigation Animation

페이지 이동 방향에 따라 슬라이드 방향을 바꾸려면 이동 때 전환 타입을 붙이고, `ViewTransition`에서 타입별로 클래스를 매핑합니다.

```jsx
function go(next, type) {
  startTransition(() => {
    addTransitionType(type) // 'forward' 또는 'back'
    setPage(next)
  })
}
```

```jsx
<ViewTransition
  enter={{ forward: 'from-right', back: 'from-left' }}
  exit={{ forward: 'to-left', back: 'to-right' }}
  default="none"
>
  <Page key={page} />
</ViewTransition>
```

- 객체 prop은 전환 타입을 키로, 클래스 이름을 값으로 갖습니다. 타입이 없는 전환에는 `default` prop(또는 객체의 `default` 키)이 쓰입니다.
- 클래스 이름(`from-right` 등)은 직접 정의하는 CSS 이름입니다. `::view-transition-old(.to-left)` 같은 선택자로 키프레임을 연결합니다.
- 슬라이드 같은 페이지 이동 애니메이션에는 라우터가 Transition으로 이동을 처리해야 합니다. 라우터가 `startTransition` 없이 상태를 바꾸면 애니메이션이 나오지 않습니다.

## List Reorder

리스트 순서를 바꿀 때는 각 항목을 `ViewTransition`으로 감싸고, 항목마다 `key`를 줍니다. 순서만 바뀌어도 각 항목에서 update 애니메이션이 나와 제자리로 미끄러져 이동합니다.

```jsx
{items.map((item) => (
  <ViewTransition key={item.id}>
    <Row item={item} />
  </ViewTransition>
))}
```

- 순서 변경은 `startTransition` 안에서 합니다.
- `ViewTransition`은 DOM 노드 바깥에 있어야 합니다. 항목마다 `div` 래퍼를 두고 그 안쪽에 `ViewTransition`을 넣으면 항목이 개별로 움직이지 않고 래퍼가 하나로 움직입니다.

**흔한 실수:** `key`를 인덱스로 주는 것입니다. 순서가 바뀌면 같은 항목으로 인식되지 않아 이동 대신 내용 교체로 보입니다.

## Reduced Motion

`prefers-reduced-motion`은 사용자가 OS 설정에서 움직임 줄이기를 요청했는지 알려 주는 CSS 미디어 기능입니다. React는 이 설정에 따라 애니메이션을 자동으로 끄지 않습니다.

```css
@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*) {
    animation-duration: 0s;
  }
}
```

- 공식 문서는 `@media (prefers-reduced-motion)`으로 항상 애니메이션을 끄거나 줄이라고 권장합니다.
- 전환 종류를 슬라이드에서 페이드로 낮추는 방식도 있습니다.
- 접근성 전반은 32편에서 다룹니다.

## 핵심 정리

- `Activity`는 `mode`가 `'hidden'`이면 UI를 `display: none`으로 숨기고, state와 DOM은 유지하며, Effect는 정리하고, 렌더는 낮은 우선순위로 진행합니다. 19.2에서 정식이 되었습니다.
- 탭·내비게이션 상태 복원과 다음 화면 미리 렌더에 쓰고, 숨겨도 계속되는 `video` 같은 DOM 부수 효과는 정리 함수로 멈춥니다.
- 조건부 렌더링은 언마운트로 state를 버리고, `Activity`는 메모리와 렌더 비용을 치르는 대신 상태를 보존합니다.
- `ViewTransition`은 19.3부터 정식이며 enter, exit, update, share를 React가 변경 내용에 따라 고릅니다. `share`는 같은 `name`의 쌍에서 실행됩니다.
- `ViewTransition`은 `startTransition`, `Suspense`, `useDeferredValue`의 업데이트에서만 발동하고, 방향별 애니메이션은 `addTransitionType`으로 나눕니다.
- 리스트 항목은 `ViewTransition`을 래퍼 밖에 두고 `key`를 주며, `prefers-reduced-motion` 대응은 직접 CSS로 합니다.
