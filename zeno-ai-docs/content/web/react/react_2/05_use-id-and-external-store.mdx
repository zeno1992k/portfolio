## useId

`useId`는 컴포넌트 인스턴스마다 고유한 문자열 ID를 돌려주는 Hook입니다. 접근성 속성(`htmlFor`, `aria-describedby` 등)에 넘길 ID를 만들려고 존재합니다. 인자는 없습니다.

```jsx
import { useId } from 'react'

function Field() {
  const id = useId()
  // id는 이 컴포넌트의 이 호출에 대응하는 문자열
  return <input id={id} />
}
```

- 같은 컴포넌트를 여러 번 렌더링하면 인스턴스마다 다른 ID가 나옵니다.
- 같은 인스턴스에서 한 컴포넌트가 `useId`를 두 번 부르면 서로 다른 ID 두 개가 나옵니다.
- 컴포넌트 최상위나 Custom Hook에서만 호출합니다. 조건문·반복문 안에서는 부를 수 없습니다(Hook 규칙은 기초 26편).
- 현재는 async Server Component에서 쓸 수 없습니다.

## 접근성 ID

HTML 접근성 속성은 요소끼리 ID로 서로를 가리킵니다. ID는 문서 안에서 유일해야 하므로 컴포넌트에 ID 문자열을 직접 써 넣으면 같은 컴포넌트를 두 번 렌더링하는 순간 중복됩니다.

```jsx
function Bad() {
  // ❌ 두 번 렌더링하면 같은 id가 문서에 둘
  return <input id="email" />
}
```

중복 ID가 있으면 ID로 요소를 찾는 `label`과 ARIA 속성이 엉뚱한 요소를 가리킬 수 있습니다. `useId`로 만든 값을 쓰면 인스턴스마다 다른 ID가 보장됩니다.

### label과 input 연결

`label`의 `htmlFor`와 `input`의 `id`에 같은 값을 넣습니다. 연결되면 레이블을 눌러도 입력창에 포커스가 가고, 스크린 리더가 입력창의 이름을 레이블 문구로 읽습니다.

```jsx
function EmailField() {
  const id = useId()
  return (
    <>
      <label htmlFor={id}>이메일</label>
      <input id={id} type="email" />
    </>
  )
}
```

한 컴포넌트에서 ID가 여러 개 필요하면 `useId`를 한 번만 부르고 접미사를 붙입니다.

```jsx
function NameFields() {
  const id = useId()
  return (
    <>
      <label htmlFor={id + '-first'}>이름</label>
      <input id={id + '-first'} />
      <label htmlFor={id + '-last'}>성</label>
      <input id={id + '-last'} />
    </>
  )
}
```

### aria-describedby

`aria-describedby`는 요소를 설명하는 다른 요소의 ID를 가리킵니다. 입력창에 도움말이나 에러 문구를 붙일 때 씁니다.

```jsx
function PasswordField() {
  const hintId = useId()
  return (
    <>
      <input type="password" aria-describedby={hintId} />
      <p id={hintId}>8자 이상이어야 합니다.</p>
    </>
  )
}
```

## ID Prefix

한 페이지에 독립된 React 앱을 여럿 올리면 앱마다 같은 규칙으로 ID를 만들기 때문에 서로 충돌할 수 있습니다. `createRoot`나 `hydrateRoot`의 옵션 `identifierPrefix`로 앱마다 다른 접두사를 줍니다. 그 앱에서 `useId`가 만드는 모든 ID가 그 접두사로 시작합니다(Root API는 17편).

```jsx
const root1 = createRoot(el1, { identifierPrefix: 'app1-' })
const root2 = createRoot(el2, { identifierPrefix: 'app2-' })
root1.render(<App />)
root2.render(<App />)
```

서버 렌더링을 쓰면 서버의 `renderToPipeableStream` 옵션과 클라이언트의 `hydrateRoot` 옵션에 같은 `identifierPrefix`를 줘야 합니다. 다르면 하이드레이션이 실패합니다.

생성되는 ID의 기본 형태는 버전마다 달랐습니다. 19.0은 `:r:` 형태, 19.1은 `«r»` 형태, 19.2는 `_r_` 형태입니다. 앞의 두 형태는 CSS 선택자에 쓸 수 없고, View Transition 이름으로도 유효하지 않아서 19.2에서 바꿨습니다. 형태는 내부 구현이므로 ID 문자열을 파싱하거나 CSS 선택자에 직접 박지 않습니다.

## SSR 안정성

서버 렌더링에서는 서버가 만든 HTML과 클라이언트의 첫 렌더 결과가 같아야 하이드레이션이 됩니다(SSR과 하이드레이션 자체는 이 과목 범위 밖이며 Next.js 과목에서 다룹니다). ID도 그 대상이라서 서버 ID와 클라이언트 ID가 달라지면 불일치 경고가 나옵니다.

`useId`는 호출한 컴포넌트가 렌더 트리에서 놓인 부모 경로를 바탕으로 값을 만듭니다. 그래서 서버와 클라이언트의 트리 모양이 같으면 렌더링·하이드레이션 순서가 달라도 같은 ID가 나옵니다.

- 서버와 클라이언트가 같은 컴포넌트 트리를 렌더링해야 합니다. 트리가 다르면 ID도 다릅니다.
- 컴포넌트가 마운트된 동안에는 ID가 유지되지만, 렌더링 중에 바뀔 수 있습니다. 그래서 캐시 키로는 쓰지 않습니다.

## 랜덤 ID와의 차이

직접 ID를 만드는 흔한 방법은 둘입니다.

```jsx
let nextId = 0
function A() {
  const id = 'f-' + nextId++     // 전역 카운터
  return <input id={id} />
}
function B() {
  const id = 'f-' + Math.random() // 난수
  return <input id={id} />
}
```

| 방식 | 문제 |
|------|------|
| 전역 카운터 | 클라이언트 컴포넌트가 하이드레이션되는 순서가 서버가 HTML을 내보낸 순서와 다를 수 있어 값이 어긋난다 |
| 난수 | 서버와 클라이언트가 서로 다른 값을 만든다. 렌더마다 새 값이면 매번 DOM 속성도 바뀐다 |
| `useId` | 부모 경로 기반이라 순서와 무관하게 서버와 클라이언트가 같은 값을 만든다 |

렌더링 함수는 같은 입력에 같은 출력을 내야 하므로 렌더 중의 `Math.random()`은 그 자체로 순수성을 깹니다. 클라이언트 전용 앱이라도 `useId`를 쓰는 편이 안전합니다.

## key로 사용 금지

`useId`로 리스트의 `key`를 만들면 안 됩니다. `key`는 데이터에서 나와야 합니다. 항목의 정체성은 데이터가 정하는데 `useId`의 값은 렌더 트리 위치에서 나오기 때문입니다.

```jsx
function List({ items }) {
  const id = useId()
  return items.map((item, i) => (
    // ❌ 데이터와 무관한 값
    <li key={id + i}>{item.text}</li>
  ))
}
// ✅ <li key={item.id}>{item.text}</li>
```

- `useId`는 컴포넌트당 호출 한 번에 값 하나입니다. 반복 안에서 호출할 수도 없습니다.
- `use()`에 넘기는 Promise의 캐시 키로도 쓰지 않습니다.

## useSyncExternalStore

`useSyncExternalStore`는 React 바깥에 있는 데이터를 구독해서 컴포넌트에 읽어 오는 Hook입니다. 인자 세 개를 받습니다.

```js
const snapshot = useSyncExternalStore(
  subscribe,         // 구독 함수
  getSnapshot,       // 지금 값을 읽는 함수
  getServerSnapshot, // 선택. 서버·하이드레이션용
)
```

- 반환값은 현재 스냅샷입니다. 렌더링에서 그 값을 그대로 씁니다.
- 대상은 두 부류입니다. React 바깥에 상태를 두는 서드파티 라이브러리, 값이 바뀌고 변경 이벤트를 제공하는 브라우저 API입니다.
- 일반 상태는 `useState`와 `useReducer`를 씁니다. 이 Hook은 React 밖의 데이터를 연결할 때만 씁니다.

## 외부 스토어

외부 스토어는 React의 State 시스템 밖에서 값을 들고 있는 객체입니다. React는 그 값이 언제 바뀌었는지 모릅니다. 그래서 스토어가 스스로 "바뀌었다"를 알리는 구독 방법과 현재 값을 읽는 방법을 노출해야 하고, `useSyncExternalStore`가 이 두 가지로 연결합니다.

다음은 구독자 목록을 가진 최소한의 스토어입니다.

```js
let todos = []
const listeners = new Set()

export const todosStore = {
  subscribe(cb) {
    listeners.add(cb)
    return () => listeners.delete(cb)
  },
  getSnapshot: () => todos,
  add(text) {
    todos = [...todos, { id: Date.now(), text }]
    listeners.forEach((l) => l())
  },
}
```

컴포넌트에서는 두 함수를 그대로 넘깁니다.

```jsx
function TodoList() {
  const todos = useSyncExternalStore(
    todosStore.subscribe,
    todosStore.getSnapshot,
  )
  return todos.map((t) => <li key={t.id}>{t.text}</li>)
}
```

스토어를 바꿀 때 값을 제자리에서 수정하지 않고 새 배열로 교체한 점이 핵심입니다(아래 "Snapshot 안정성").

## subscribe

`subscribe`는 콜백 하나를 받아 스토어에 등록하고, 등록을 해제하는 함수를 반환하는 함수입니다. 스토어가 바뀌면 받은 콜백을 호출해야 합니다.

- 콜백이 호출되면 React가 `getSnapshot`을 다시 불러 값을 비교하고, 달라졌으면 컴포넌트를 다시 렌더링합니다.
- 반환하는 정리 함수는 컴포넌트가 사라지거나 `subscribe`가 바뀔 때 React가 호출합니다.
- `subscribe`는 컴포넌트 밖에서 선언합니다. 안에서 선언하면 렌더마다 새 함수가 되고, React는 다른 `subscribe`를 받으면 구독을 해제하고 다시 합니다.

```jsx
function Bad() {
  // ❌ 렌더마다 재구독
  function subscribe(cb) { /* ... */ }
  const v = useSyncExternalStore(subscribe, getSnapshot)
}
```

`subscribe`가 props에 의존하면 `useCallback`으로 감싸서 의존 값이 바뀔 때만 새 함수가 되게 합니다.

```jsx
function Room({ roomId }) {
  const subscribe = useCallback(
    (cb) => connect(roomId, cb),
    [roomId],
  )
  const msgs = useSyncExternalStore(subscribe, getSnapshot)
}
```

## getSnapshot

`getSnapshot`은 컴포넌트가 필요한 스토어 값의 스냅샷을 읽어 돌려주는 함수입니다. React는 렌더링 중에, 그리고 구독 콜백이 호출될 때 이 함수를 부릅니다.

- 스토어가 바뀌지 않았다면 몇 번을 불러도 같은 값을 돌려줘야 합니다.
- 값이 바뀌었는지는 `Object.is`로 비교합니다. 다르면 다시 렌더링합니다.
- 스냅샷은 불변이어야 합니다. 스토어가 가변 데이터라면 바뀔 때만 새 불변 스냅샷을 만들고, 그렇지 않으면 마지막 스냅샷을 그대로 돌려줍니다.
- Transition 안에서 스토어가 바뀌면 React는 그 업데이트를 non-blocking으로 처리하지 못하고 blocking 업데이트로 되돌립니다. 업데이트를 DOM에 반영하기 직전에 `getSnapshot`을 한 번 더 불러 값이 달라졌는지 확인하기 때문입니다(Transition은 09편).
- 이 Hook이 읽는 스토어 값으로 렌더를 Suspend시키는 것은 권하지 않습니다. 스토어 변경은 Transition으로 표시할 수 없어서 이미 보이던 화면이 fallback으로 바뀝니다(Suspense는 11편).

## getServerSnapshot

`getServerSnapshot`은 서버에서 HTML을 만들 때와, 클라이언트에서 그 HTML을 하이드레이션할 때만 쓰이는 초기 스냅샷 함수입니다. 세 번째 인자이고 선택입니다.

```js
function getServerSnapshot() {
  return true // 서버 HTML은 항상 온라인으로 그린다
}
```

- 서버에서 렌더링하는 컴포넌트가 이 Hook을 쓰는데 `getServerSnapshot`이 없으면 서버 렌더링이 에러를 던집니다.
- 서버 값과 클라이언트 첫 렌더 값이 같아야 합니다. 서버에서 미리 채운 스토어 내용을 돌려준다면 같은 내용을 클라이언트로 전달해 첫 렌더에서 똑같이 돌려줘야 합니다. 예를 들어 서버가 `script` 태그로 전역 변수에 내용을 심고 클라이언트가 그것을 읽습니다.
- 서버에서 의미 있는 초기 값이 없다면 인자를 생략해서 클라이언트에서만 렌더링하게 만듭니다(Suspense의 fallback 처리).

## Browser API 구독

브라우저가 제공하는 값 중에는 읽을 수 있고 변경 이벤트도 주는 것이 많습니다. 네트워크 상태, 화면 크기, 다크 모드 설정, 문서 가시성 등입니다. `subscribe`는 이벤트 리스너를 달고 정리 함수로 떼며, `getSnapshot`은 현재 값을 읽습니다.

```js
const query = '(prefers-color-scheme: dark)'

function subscribe(callback) {
  const mq = window.matchMedia(query)
  mq.addEventListener('change', callback)
  return () => mq.removeEventListener('change', callback)
}
function getSnapshot() {
  return window.matchMedia(query).matches
}
```

`matches`는 불리언이라 `Object.is`로 비교해도 안전한 원시 값입니다. 읽는 값이 원시 값이면 스냅샷 안정성 문제가 생기지 않습니다.

`useEffect`와 `useState`로 구독해도 동작은 합니다. 다만 첫 렌더에서는 기본값을 쓰고 Effect 이후에 값을 고치는 구조라서 한 번 틀린 화면이 보일 수 있습니다. `useSyncExternalStore`는 렌더 중에 현재 값을 바로 읽습니다.

## Online Status

공식 문서의 대표 예제입니다. `navigator.onLine`을 읽고 `online`·`offline` 이벤트를 구독해 Custom Hook으로 묶습니다.

```js
function subscribe(callback) {
  window.addEventListener('online', callback)
  window.addEventListener('offline', callback)
  return () => {
    window.removeEventListener('online', callback)
    window.removeEventListener('offline', callback)
  }
}
export function useOnlineStatus() {
  return useSyncExternalStore(
    subscribe,
    () => navigator.onLine,
    () => true, // 서버 HTML은 항상 온라인
  )
}
```

컴포넌트에서는 값만 씁니다.

```jsx
function StatusBar() {
  const isOnline = useOnlineStatus()
  return <h1>{isOnline ? '온라인' : '연결 끊김'}</h1>
}
```

Custom Hook으로 감싸면 구독 방식이 컴포넌트에서 가려져서, 나중에 구현을 바꿔도 사용하는 쪽은 그대로입니다(Custom Hook은 기초 26편).

## SSR

서버에는 `window`와 `navigator`가 없으므로 Browser API를 읽는 `getSnapshot`은 서버에서 호출할 수 없습니다. 서버와 하이드레이션 동안에는 `getServerSnapshot`이 대신 쓰입니다.

| 시점 | 호출되는 함수 |
|------|---------------|
| 서버에서 HTML 생성 | `getServerSnapshot` |
| 클라이언트 하이드레이션 | `getServerSnapshot` |
| 하이드레이션 이후 | `getSnapshot` |

- 그래서 서버 값은 "가장 흔한 값"이나 "안전한 기본값"을 고릅니다. 온라인 상태는 `true`를 씁니다.
- 서버 값과 클라이언트 첫 렌더 값이 다르면 하이드레이션 불일치가 납니다.

## Snapshot 안정성

`getSnapshot`이 호출될 때마다 새 객체를 만들면 React는 "스토어가 계속 바뀐다"고 판단합니다. 값이 `Object.is`로 같지 않아서 다시 렌더링하고, 불필요한 재렌더링이 반복되고, React는 "The result of getSnapshot should be cached" 에러 메시지로 이 실수를 알립니다.

```js
// ❌ 호출마다 새 객체
function getSnapshot() {
  return { todos: myStore.todos }
}
// ✅ 저장된 불변 값을 그대로 반환
function getSnapshot() {
  return myStore.todos
}
```

스토어가 가변이어서 새 객체를 만들 수밖에 없다면, 마지막으로 만든 스냅샷을 보관했다가 데이터가 바뀌지 않은 호출에서는 같은 것을 돌려줍니다.

```js
let cached = null
let cachedVersion = -1
function getSnapshot() {
  if (cachedVersion !== store.version) {
    cached = { todos: store.todos.slice() }
    cachedVersion = store.version
  }
  return cached
}
```

- 스토어를 불변으로 만들면(바뀔 때 새 값으로 교체) 별도 캐시가 필요 없습니다. 앞의 `todosStore`가 그 방식입니다.
- 스냅샷에서 값 일부만 고르는 로직(selector)을 넣고 싶다면 고른 결과가 같은 입력에 같은 참조여야 합니다.

## 상태 라이브러리가 이 훅을 쓰는 이유

Redux·Zustand 같은 상태 라이브러리는 상태를 React 밖에 둡니다. React 18의 동시성 렌더링은 렌더링을 중간에 멈췄다가 이어 갈 수 있어서, 렌더링 도중에 외부 값이 바뀌면 한 화면 안에서 어떤 컴포넌트는 이전 값을, 어떤 컴포넌트는 새 값을 그리게 될 수 있습니다. 이 현상을 tearing(찢어짐)이라고 합니다.

- tearing은 외부 가변 상태를 읽는 경우에만 생깁니다. props·State·Context만 읽는 컴포넌트에서는 생기지 않습니다.
- `useSyncExternalStore`는 렌더링 중에 스냅샷이 바뀌었는지 확인하고, 바뀌었으면 렌더링을 처음부터 blocking으로 다시 해서 화면 전체가 같은 버전의 값을 보여 주게 합니다.
- 그래서 라이브러리는 이 Hook으로 구독을 구현하고, 사용자는 동시성 기능과 함께 써도 일관된 화면을 얻습니다.
- 라이브러리의 구독 모델과 선택 기준은 23편, Zustand는 24편에서 다룹니다.

## 핵심 정리

- `useId`는 인스턴스마다 고유한 ID를 만들며, `htmlFor`·`aria-describedby` 같은 접근성 속성에 쓰고 여러 개가 필요하면 한 번만 호출해 접미사를 붙입니다.
- 서버와 클라이언트의 트리가 같으면 `useId` 값도 같으므로 하이드레이션이 맞고, 난수나 전역 카운터는 맞지 않습니다. 한 페이지의 여러 앱은 `identifierPrefix`로 구분합니다.
- `useId`는 리스트 `key`와 캐시 키로 쓰지 않습니다.
- `useSyncExternalStore`는 `subscribe`(안정된 함수, 해제 함수 반환), `getSnapshot`(변경이 없으면 같은 값), `getServerSnapshot`(서버·하이드레이션용)으로 React 밖의 데이터를 읽습니다.
- `getSnapshot`이 매번 새 객체를 만들면 불필요한 재렌더링과 에러가 생기므로 불변 값이나 캐시한 값을 돌려줍니다.
- 상태 라이브러리는 동시성 렌더링 중 외부 값이 바뀌어 화면이 어긋나는 tearing을 막으려고 이 Hook을 씁니다.
