## React.lazy

`lazy`는 컴포넌트 코드를 처음 렌더링될 때까지 불러오지 않고 미룹니다. 코드 분할(code splitting)은 앱 코드를 여러 파일(청크, chunk)로 나눠 필요한 것만 내려받게 하는 기법이고, `lazy`는 그 React 쪽 방법입니다.

```jsx
import { lazy, Suspense } from 'react'

const Preview = lazy(() => import('./Preview.js'))

<Suspense fallback={<Loading />}>
  <Preview />
</Suspense>
```

| 항목 | 내용 |
|------|------|
| 인수 | `load`: Promise(또는 thenable)를 돌려주는 함수 |
| Promise의 값 | `.default`에 유효한 컴포넌트가 있는 객체 |
| 반환 | 렌더링 중 중단되는 컴포넌트 |
| 호출 횟수 | `load`는 한 번만 호출되고, Promise와 결과 컴포넌트는 캐시됨 |

- 컴포넌트 타입은 함수 컴포넌트, `memo`, `forwardRef`가 될 수 있습니다.
- 로드되는 동안 컴포넌트가 중단되므로 `Suspense`가 필요합니다(자세히는 11편).
- 로드가 실패해 Promise가 거부되면 React는 그 거부를 가장 가까운 Error Boundary에 던집니다(자세히는 13편).

## Dynamic Import

`import()`는 모듈을 실행 중에 불러오는 문법입니다. 코드 분할의 지점이 됩니다. 빌드 도구는 `import()`를 만나면 그 모듈을 별도 청크로 분리합니다.

```js
const mod = await import('./chart.js')
mod.default // default export
mod.draw    // 이름 있는 export
```

- 반환값은 Promise이고, 모듈 네임스페이스 객체로 이행됩니다. 로드·링크·실행이 실패하면 거부됩니다.
- default export는 `default` 프로퍼티에 들어 있습니다. `lazy`가 `.default`를 요구하는 이유입니다.
- 같은 모듈 지정자는 한 번만 실행되고 결과가 캐시됩니다. 두 번째 `import()`는 즉시 같은 모듈을 돌려줍니다.
- 브라우저에서 널리 지원됩니다(2020년 1월부터).

`lazy`는 default export만 읽기 때문에 이름 있는 export를 쓰려면 변환합니다.

```jsx
const Chart = lazy(() =>
  import('./charts.js').then(m => ({ default: m.Chart })),
)
```

정적 `import`는 최초 의존성에 적합하고 트리 셰이킹에도 유리합니다. 동적 `import()`는 조건부·지연 로딩이 필요한 곳에만 씁니다.

## Route-level Splitting

라우트(페이지) 단위 분할은 효과가 가장 크고 안전한 기본 전략입니다. 사용자가 방문하지 않은 페이지의 코드를 내려받지 않습니다.

```jsx
const Home = lazy(() => import('./pages/Home.js'))
const Admin = lazy(() => import('./pages/Admin.js'))

<Suspense fallback={<PageSpinner />}>
  <Routes>{/* 경로별 컴포넌트 연결 */}</Routes>
</Suspense>
```

- 페이지마다 `lazy` 컴포넌트를 만들고, 라우터 바깥쪽에 `Suspense`를 한 번 둡니다.
- 페이지 이동은 Transition으로 감싸면 이전 화면을 유지한 채 새 코드를 기다립니다. Suspense와 연동된 라우터는 자동으로 감쌉니다(자세히는 09편).
- 라우터가 자체 지연 로딩을 제공하기도 합니다. 예를 들어 React Router는 라우트 객체의 `lazy` 속성으로 라우트 모듈(컴포넌트와 로더 등)을 지연 로드합니다. 이 방식은 렌더링 전에 모듈을 불러오므로 `React.lazy`와 다릅니다.
- 관리자 화면처럼 일부 사용자만 쓰는 페이지는 분할 효과가 특히 큽니다.

## Component-level Splitting

페이지 안에서도 무겁고 항상 쓰이지 않는 컴포넌트는 따로 분할합니다.

| 대상 | 예 |
|------|----|
| 조건부로 나타나는 UI | 모달, 드로어, 설정 패널 |
| 무거운 라이브러리를 쓰는 컴포넌트 | 차트, 코드 에디터, 마크다운 렌더러, 지도 |
| 첫 화면 밖의 영역 | 탭의 비활성 패널, 스크롤 아래 섹션 |

```jsx
const Editor = lazy(() => import('./Editor.js'))

function Post() {
  const [open, setOpen] = useState(false)
  return open ? (
    <Suspense fallback={<Loading />}>
      <Editor />
    </Suspense>
  ) : <button onClick={() => setOpen(true)}>편집</button>
}
```

- `open`이 `true`가 되는 순간에 코드를 요청합니다.
- 작은 컴포넌트는 분할 비용(추가 요청)이 이득보다 큽니다. 크기가 큰 것만 나눕니다.

## Suspense fallback

`lazy` 컴포넌트가 로드되는 동안 보이는 것이 `Suspense`의 `fallback`입니다.

- 가장 가까운 부모 경계의 fallback이 보입니다. 경계를 어디에 두느냐에 따라 화면 전체가 가려지거나 해당 영역만 가려집니다(자세히는 11편).
- 라우트 분할은 페이지 단위 스피너, 컴포넌트 분할은 해당 자리에서 크기가 비슷한 스켈레톤을 쓰면 레이아웃 이동이 적습니다.
- 이미 화면에 보이던 내용이 다시 중단되면 fallback이 내용을 가립니다. `startTransition`이나 `useDeferredValue`로 일으킨 업데이트는 이전 내용을 유지합니다.
- 로드가 매우 빠르면 fallback이 깜박일 수 있습니다. 경계를 넓게 잡거나 Transition을 씁니다.

## Chunk Error

청크 로드 에러는 `import()`가 거부되는 경우입니다. 네트워크가 끊기거나, 배포로 이전 청크 파일이 삭제되었는데 사용자가 옛 HTML을 들고 있을 때 일어납니다.

- `lazy`는 거부를 Error Boundary로 던지므로, 경계 바깥에서 에러 UI를 준비해야 합니다.
- `load`가 한 번만 호출되고 결과가 캐시되므로, 같은 `lazy` 컴포넌트를 다시 렌더링한다고 해서 새로 요청한다는 보장은 없습니다. 에러 UI에서 페이지 새로고침(reload)을 안내하는 방법이 가장 확실합니다.
- Vite는 동적 import가 실패하면 `vite:preloadError` 이벤트를 발생시킵니다. `event.preventDefault()`로 예외를 억제할 수 있습니다.

```js
window.addEventListener('vite:preloadError', () => {
  window.location.reload()
})
```

- 배포 후에 옛 청크가 사라지는 문제는 HTML에 `Cache-Control: no-cache`를 지정해 오래된 HTML이 캐시되지 않게 하면 줄어듭니다(Vite 공식 문서의 권장).
- Error Boundary와 재시도 UI의 구성은 13편에서 다룹니다.

## Lazy 선언 위치

`lazy`는 컴포넌트 **바깥**, 모듈 최상위에서 선언합니다. 컴포넌트 안에서 선언하면 렌더링마다 새 `lazy` 컴포넌트가 만들어져 state가 초기화됩니다.

```jsx
// ❌ 렌더링마다 새로 만들어져 state가 사라짐
function Editor() {
  const Preview = lazy(() => import('./Preview.js'))
  return <Preview />
}

// ✅ 모듈 최상위
const Preview = lazy(() => import('./Preview.js'))
function Editor() {
  return <Preview />
}
```

- 새 `lazy` 컴포넌트는 새 컴포넌트 타입이므로 React가 이전 것을 버리고 다시 마운트합니다. 로드 상태와 내부 state가 모두 초기화됩니다.
- 한 파일에 `lazy` 선언이 여러 개면 파일 상단에 모아 두면 관리하기 쉽습니다.

## 번들 전략

어디를 나누고 무엇을 미리 불러올지 정하는 기준은 다음과 같습니다.

- 첫 화면에 필요한 코드는 메인 번들에 둡니다. 첫 화면 컴포넌트까지 `lazy`로 만들면 요청이 한 단계 더 늘어납니다.
- 라우트 단위로 먼저 나누고, 그다음 무거운 컴포넌트를 나눕니다.
- 분할한 컴포넌트가 로드된 뒤에야 데이터를 요청하면 워터폴이 생깁니다. 코드와 데이터 요청을 함께 시작합니다(자세히는 11편).
- 클릭이나 호버처럼 곧 필요해질 신호가 있으면 미리 불러옵니다(아래 "preload 패턴").
- 나누기 전과 후에 번들 크기를 측정합니다(아래 "번들 분석 도구").

### preload 패턴

`lazy`의 `load` 함수를 변수로 빼 두면, 필요하기 전에 호출해 모듈을 미리 받아 둘 수 있습니다. 모듈은 한 번만 실행되고 캐시되므로 뒤이어 `lazy`가 부르면 즉시 끝납니다.

```jsx
const loadEditor = () => import('./Editor.js')
const Editor = lazy(loadEditor)

<button
  onMouseEnter={loadEditor} // 호버 시 미리 받음
  onClick={() => setOpen(true)}
>
  편집
</button>
```

- 호버·포커스·화면 진입 같은 신호에 맞춰 호출합니다.
- 미리 받는 것은 낭비일 수 있으므로 사용할 확률이 높은 것만 합니다.

### 번들 분석 도구

번들에서 무엇이 용량을 차지하는지 시각화해 분할 대상을 찾습니다.

| 도구 | 쓰는 곳 | 특징 |
|------|---------|------|
| rollup-plugin-visualizer | Vite·Rollup | 트리맵, 선버스트, 네트워크 등 여러 차트로 출력 |
| webpack-bundle-analyzer | webpack | 상호작용형 트리맵, 원본·최소화·gzip 크기 표시 |

```js
// vite.config.js
import { visualizer } from 'rollup-plugin-visualizer'

export default {
  plugins: [visualizer()],
}
```

- 큰 모듈이 여러 청크에 중복되어 있지 않은지, 한 번만 쓰는 무거운 라이브러리가 메인 번들에 들어 있지 않은지 확인합니다.
- 실제 빌드(프로덕션)로 측정합니다. 개발 서버의 크기는 기준이 되지 않습니다.

## 리소스 프리로딩 API

`react-dom`의 `preload`와 `preinit`은 리소스를 브라우저에 미리 알리는 함수입니다. 컴포넌트 렌더링 중, Effect, 이벤트 핸들러에서 호출할 수 있습니다. 같은 `href`로 여러 번 호출해도 한 번 호출한 것과 같습니다.

| 항목 | `preload(href, options)` | `preinit(href, options)` |
|------|--------------------------|--------------------------|
| 하는 일 | 내려받기만 함 | 내려받고 실행(스크립트) 또는 삽입(스타일) |
| `as` | `font`, `image`, `script`, `style` 등 | `script` 또는 `style` |
| 스타일 | 해당 없음 | `precedence` 필요 |
| 반환 | 없음 | 없음 |

```jsx
import { preload, preinit } from 'react-dom'

function AppRoot() {
  preload('/a.woff2', {
    as: 'font',
    crossOrigin: 'anonymous',
  })
  preinit('/a.css', { as: 'style', precedence: 'medium' })
  return <App />
}
```

- `preload`의 `as`는 필수입니다. 폰트처럼 CORS가 필요한 리소스에는 `crossOrigin`을 붙입니다.
- `preload`의 `fetchPriority`(`auto`, `high`, `low`)로 우선순위를 줄 수 있습니다.
- 서버 렌더링에서는 렌더링 중이거나 렌더링에서 시작된 비동기 맥락에서 호출될 때만 효과가 있습니다.
- ES 모듈에는 `preinit` 대신 `preinitModule`을 씁니다.

## 핵심 정리

- `lazy(load)`는 `.default`에 컴포넌트가 있는 모듈을 `import()`로 불러오며, `Suspense` 안에서 렌더링하고 로드는 한 번만 일어납니다.
- 동적 `import()`가 분할 지점이고, 이름 있는 export는 `default`로 변환해 감쌉니다.
- 라우트 단위 분할을 먼저 하고, 무겁고 조건부로 쓰이는 컴포넌트를 추가로 나눕니다.
- 로드 실패는 Error Boundary로 전달되며, 배포 후 사라진 청크에는 reload와 `Cache-Control: no-cache`가 대응책입니다.
- `lazy`는 모듈 최상위에 선언해야 하고, 컴포넌트 안에 선언하면 state가 초기화됩니다.
- `load` 함수를 먼저 호출하면 미리 받을 수 있고, 폰트·스타일·스크립트는 `preload`와 `preinit`으로 미리 불러옵니다.
