## useDeferredValue와 Deferred Value

`useDeferredValue`는 값 하나를 받아, 화면에 급하게 반영하지 않아도 되는 "지연된 값"(deferred value)을 돌려주는 Hook입니다.

```jsx
const deferredValue = useDeferredValue(value, initialValue?)
```

| 인수 | 설명 |
|------|------|
| `value` | 지연할 값. 어떤 타입이든 가능 |
| `initialValue` | 선택. 첫 렌더링에 쓸 값(React 19) |

동작은 두 단계입니다.

1. `value`가 바뀌면 React는 먼저 **이전 값**으로 렌더링합니다. 화면은 곧바로 응답합니다.
2. 그 직후 **새 값**으로 백그라운드 렌더링을 시작합니다. 끝나면 `deferredValue`가 새 값이 되고 화면이 갱신됩니다.

```jsx
function App() {
  const [text, setText] = useState('')
  const deferredText = useDeferredValue(text)
  // text: 입력창에 즉시 반영
  // deferredText: 한 박자 늦게 따라옴
}
```

- 처음 렌더링에는 비교할 이전 값이 없으므로 `deferredValue`는 `value`와 같습니다(`initialValue`를 주면 달라집니다).
- 변경 판단은 `Object.is`로 합니다.
- 백그라운드 렌더링은 중단할 수 있습니다. 빠르게 입력하면 진행 중이던 렌더링을 버리고 최신 값으로 다시 시작합니다.
- 고정된 지연 시간이 없습니다. 첫 렌더링이 끝나면 곧바로 백그라운드 렌더링이 시작되고, 기기가 빠르면 거의 즉시 따라잡습니다.
- 값은 문자열·숫자 같은 원시 값이거나 렌더링 밖에서 만든 객체여야 합니다. 렌더링 중에 매번 새 객체를 만들어 넘기면 필요 없는 백그라운드 렌더링이 계속 일어납니다.

## 느린 UI 지연

한 입력이 느린 컴포넌트에 연결되어 있으면, 입력이 그 컴포넌트의 렌더링을 기다리느라 끊깁니다. 느린 쪽에 지연된 값을 넘기면 입력은 즉시 반영되고 느린 UI는 뒤따라옵니다.

```jsx
function App() {
  const [text, setText] = useState('')
  const deferredText = useDeferredValue(text)
  return (
    <>
      <input
        value={text}
        onChange={e => setText(e.target.value)}
      />
      <SlowList text={deferredText} />
    </>
  )
}
```

이 코드만으로는 효과가 없는 경우가 많습니다. 아래 "Memoized Child"를 지켜야 합니다.

## 검색 입력

검색 입력은 `useDeferredValue`의 대표 사용처입니다. 입력창은 원래 state를, 결과는 지연된 값을 읽습니다.

```jsx
const [query, setQuery] = useState('')
const deferredQuery = useDeferredValue(query)
const isStale = query !== deferredQuery
```

- 사용자가 타이핑하는 동안 입력창은 즉시 갱신되고, 결과 목록은 직전 상태에 머물다가 새 값 렌더링이 끝나면 바뀝니다.
- 입력이 이어지는 동안은 백그라운드 렌더링이 계속 취소되므로 중간 단계의 결과는 화면에 나타나지 않을 수 있습니다.
- 입력용 state와 결과용 state를 따로 두지 않아도 state 하나로 구현됩니다.

## Stale Content

새 값에 대한 화면이 준비될 때까지 이전 결과가 남아 있는 상태가 Stale Content(낡은 내용)입니다. 사용자에게 낡았다는 사실을 알려 주려면 원래 값과 지연된 값을 비교합니다.

```jsx
const isStale = query !== deferredQuery

<div style={{ opacity: isStale ? 0.5 : 1 }}>
  <SearchResults query={deferredQuery} />
</div>
```

- `query !== deferredQuery`는 백그라운드 렌더링이 아직 끝나지 않았다는 뜻입니다.
- React 공식 예제는 투명도를 0.5로 줄이되 전환에 약간의 지연을 두어, 빠르게 끝나는 경우에는 깜박이지 않게 합니다.
- `useTransition`의 `isPending`처럼 별도 플래그가 없으므로 이 비교가 곧 stale 판단입니다.

## Suspense

지연된 값을 받는 컴포넌트가 새 값 때문에 중단(suspend)되면, 이미 보이던 내용은 fallback으로 바뀌지 않고 이전 지연 값의 화면이 유지됩니다(자세히는 11편).

```jsx
const deferredQuery = useDeferredValue(query)
// ...
<Suspense fallback={<h2>Loading...</h2>}>
  <SearchResults query={deferredQuery} />
</Suspense>
```

- 새 검색 결과 데이터가 오는 동안 `h2` fallback 대신 이전 결과가 남아 있습니다.
- 백그라운드 렌더링이 중단되는 동안 Effect는 실행되지 않습니다. Effect는 지연된 값이 화면에 반영된 뒤(커밋 이후)에 실행됩니다.
- 중단이 일어나려면 컴포넌트가 Suspense를 지원하는 방식으로 데이터를 읽어야 합니다. Effect 안에서 가져온 데이터는 중단되지 않습니다(자세히는 11편).

## Transition과 차이

둘 다 업데이트를 비긴급으로 만들지만 감싸는 대상이 다릅니다(자세히는 09편).

| 항목 | `useTransition` | `useDeferredValue` |
|------|-----------------|--------------------|
| 감싸는 대상 | state를 바꾸는 코드(`set` 호출) | 값 |
| 필요한 것 | `set` 함수 접근 권한 | 값만 있으면 됨 |
| 대기 표시 | `isPending` 제공 | 값 비교(`query !== deferredQuery`) |
| 비동기 Action | 지원 | 해당 없음 |
| 적합한 경우 | 이벤트 핸들러에서 state를 갱신하는 코드가 내 것일 때 | props나 커스텀 Hook이 준 값을 받아 쓸 때 |

- Transition 안에서 일어난 업데이트라면 `useDeferredValue`는 이미 지연된 것으로 보고 새 값을 곧바로 돌려줍니다. 별도의 백그라운드 렌더링을 만들지 않습니다.
- 값을 소유한 쪽에서는 Transition이, 값을 받기만 하는 쪽에서는 `useDeferredValue`가 자연스럽습니다.

## Memoized Child

지연된 값을 받는 자식은 `memo`로 감싸야 합니다.

```jsx
const SlowList = memo(function SlowList({ text }) {
  // 느린 렌더링
  return <ul>{/* 많은 항목 */}</ul>
})
```

- `text`가 바뀌어 부모가 다시 렌더링되더라도, 첫 단계에서는 `deferredText`가 이전 값이므로 `SlowList`의 props가 같습니다. `memo`가 있으면 이 렌더링을 건너뜁니다.
- `memo`가 없으면 첫 단계에서도 `SlowList`가 다시 렌더링되어 입력이 여전히 느려집니다. 지연이 효과를 내려면 "이전 값일 때는 건너뛰기"가 가능해야 합니다(자세히는 18편).
- 자식에게 인라인 객체나 함수를 따로 넘기면 매번 props가 달라져 `memo`가 무력해집니다(자세히는 19편).

## initialValue

React 19에서 추가된 두 번째 인수입니다. 첫 렌더링에서 `initialValue`를 돌려주고, 곧바로 `value`로 백그라운드 렌더링합니다.

```jsx
function Search({ deferredValue }) {
  const value = useDeferredValue(deferredValue, '')
  // 첫 렌더링: ''  →  이어서 백그라운드: deferredValue
}
```

- `initialValue`가 없으면 첫 렌더링에서는 지연하지 않고 `value`를 그대로 돌려줍니다.
- 무거운 컴포넌트가 처음 나타날 때 먼저 빈 상태(또는 가벼운 상태)로 그린 뒤 채우는 데 씁니다.

## 디바운스·스로틀과 비교

디바운스(debounce)는 입력이 멈춘 뒤 일정 시간이 지나야 실행하고, 스로틀(throttle)은 일정 시간마다 한 번만 실행합니다. 둘 다 고정된 시간을 기다립니다.

| 항목 | `useDeferredValue` | 디바운스·스로틀 |
|------|--------------------|-----------------|
| 지연 시간 | 고정값 없음, 기기 성능에 따라 달라짐 | 정해 둔 시간(예: 300ms) |
| 중단 | 새 입력이 오면 진행 중인 렌더링 취소 | 타이머가 끝날 때까지 대기 |
| 대상 | React 렌더링 | 모든 함수 호출 |
| 네트워크 요청 | 줄여 주지 않음 | 줄여 줌 |

- `useDeferredValue`는 요청 횟수를 줄이지 못합니다. 지연된 값이 바뀔 때마다 새 요청이 나갑니다.
- 렌더링이 아닌 작업을 줄일 때(API 호출 횟수 제한)는 디바운스·스로틀을 씁니다. 렌더링이 느릴 때는 `useDeferredValue`를 씁니다.
- 둘은 함께 쓸 수 있습니다. 디바운스로 요청 횟수를 줄이고, 결과 렌더링에는 `useDeferredValue`를 적용합니다.

## 핵심 정리

- `useDeferredValue`는 값을 받아 먼저 이전 값으로 렌더링하고, 백그라운드에서 새 값으로 다시 렌더링합니다.
- 입력은 즉시, 느린 UI는 뒤따라가게 하며, `query !== deferredQuery`로 낡은 내용을 표시합니다.
- 지연된 값을 받는 자식은 `memo`로 감싸야 효과가 있고, 렌더링 중 만든 새 객체를 넘기면 안 됩니다.
- 지연된 값이 중단되면 fallback 대신 이전 화면이 유지되고, Effect는 커밋 뒤에 실행됩니다.
- Transition은 `set` 호출을, `useDeferredValue`는 값을 감쌉니다. 요청 횟수를 줄이는 것은 디바운스의 몫입니다.
- React 19의 `initialValue`는 첫 렌더링에 쓸 값을 정합니다.
