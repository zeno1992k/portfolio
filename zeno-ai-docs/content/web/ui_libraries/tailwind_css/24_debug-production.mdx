## 핵심 먼저 보기

- CSS가 없음 → 감지·빌드·로딩 경로를 봅니다.
- CSS가 있는데 적용 안 됨 → 조건·캐스케이드·레이아웃을 봅니다.
- 개발 화면뿐 아니라 실제 빌드 결과를 확인합니다.

## 원인을 나누는 순서

1. 클래스가 완성된 문자열로 소스에 있는지 확인합니다.
2. 그 파일이 감지 범위에 포함되는지 확인합니다.
3. 생성된 CSS에 규칙이 있는지 확인합니다.
4. 페이지가 최신 CSS를 실제로 불러왔는지 확인합니다.
5. 개발자 도구에서 덮어쓴 규칙과 충족하지 않은 조건을 확인합니다.

클래스가 있는데도 `md:` 조건이 안 맞거나 부모의 폭·overflow·쌓임 맥락이 원인일 수 있습니다. CSS가 없는 문제와 레이아웃 계산 문제를 섞어 고치지 않습니다.

## 대표적인 실패

| 증상 | 먼저 볼 것 |
|---|---|
| 동적 색만 사라짐 | 완성 클래스 문자열·CSS 변수 |
| 특정 패키지 UI만 깨짐 | source 감지 경로 |
| 고정 헤더·sticky가 안 됨 | 조상 overflow·이동 공간 |
| 긴 내용이 화면을 밀어냄 | `min-w-0`·폭 제한·내부 스크롤 |
| 스타일이 덮어써짐 | 레이어·조건·선택자·충돌 클래스 |

## 배포 전 확인

프로덕션 빌드의 작은 화면·큰 화면, 밝게·어둡게, 키보드 포커스, 비활성·오류·로딩 상태를 봅니다. 감지 후보를 과도하게 늘려 CSS가 불필요하게 커지지 않았는지도 확인합니다. 접근성·로딩 성능·CSS 크기는 서로 다른 항목이므로 하나의 성공으로 나머지까지 통과했다고 판단하지 않습니다.
