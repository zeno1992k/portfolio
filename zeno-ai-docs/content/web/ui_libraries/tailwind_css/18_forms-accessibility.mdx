## 핵심 먼저 보기

- label·button·input 같은 의미 있는 HTML을 먼저 사용합니다.
- 포커스·오류·상태는 색만으로 전달하지 않습니다.
- 숨기는 목적에 맞게 hidden·sr-only를 구분합니다.

## 이름과 설명

입력에는 연결된 label이 필요합니다. placeholder는 입력 중 사라지므로 label을 대신하지 않습니다. 오류 설명은 텍스트로 쓰고 필요하면 `aria-describedby`로 입력과 연결합니다. 시각적 오류 스타일만 붙여도 보조 기술에 관계가 자동 생성되지는 않습니다.

```html
<label for="email">이메일</label>
<input id="email" type="email"
  aria-describedby="email-help"
  class="rounded border border-slate-300 p-2
  focus-visible:ring-2 focus-visible:ring-blue-600">
<p id="email-help">연락받을 주소를 적습니다.</p>
```

## 상태 스타일

`invalid:`·`required:`·`checked:`·`disabled:`는 실제 입력 상태를 봅니다. `accent-*`는 체크박스 등의 강조색, `appearance-none`은 기본 외형 제거에 사용합니다. 기본 외형을 지우면 포커스·선택 표시·강제 색상 모드에서도 구분되는지 확인해야 합니다.

## 보이는 것과 읽히는 것

`sr-only`는 시각적으로 숨기되 보조 기술용 이름을 제공할 때 쓸 수 있습니다. `hidden`은 일반적으로 접근성 트리에서도 제외됩니다. 아이콘 전용 버튼에는 접근 가능한 이름을 주고, 클릭만 가능한 div보다 네이티브 button을 우선합니다.
