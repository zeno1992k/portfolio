## 핵심 먼저 보기

- 필요한 기능만 확장하고 프로젝트 버전과 호환되는지 확인합니다.
- 플러그인은 스타일을 추가하며 앱의 기능을 대신하지 않습니다.
- 반복되는 선택 조건은 이름 있는 변형으로 표현할 수 있습니다.

## 플러그인 연결

v4에서는 설치한 JavaScript 플러그인을 CSS의 `@plugin`으로 읽을 수 있습니다. Typography는 외부 본문의 서식을 `prose` 계열로, Forms는 기본 폼 컨트롤 스타일 정돈을 돕습니다. 둘 다 핵심 패키지에 자동 포함된 것은 아닙니다.

```css
@import "tailwindcss";
@plugin "@tailwindcss/typography";
```

`prose`를 사용해도 코드 하이라이트·목차·보안 처리가 자동 완성되지는 않습니다. 앱의 UI 부분은 `not-prose`로 본문 스타일 범위에서 분리할 수 있습니다. Forms도 입력 검증 로직을 구현하지는 않습니다.

## 이름 있는 상태

```css
@custom-variant theme-ocean (
  &:where([data-theme="ocean"] *)
);
```

이 정의는 `theme-ocean:bg-blue-950`처럼 사용합니다. 실제 data 속성을 바꾸는 코드는 앱이 담당합니다. 토큰을 추가하는 `@theme`, 유틸리티를 만드는 `@utility`, 조건을 만드는 `@custom-variant`를 구분합니다.
