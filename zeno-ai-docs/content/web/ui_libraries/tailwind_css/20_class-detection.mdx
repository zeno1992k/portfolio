## 핵심 먼저 보기

- Tailwind는 코드를 실행하지 않고 소스의 클래스 후보를 읽습니다.
- 조건부 클래스도 완성된 이름이 소스에 있어야 합니다.
- 감지 범위를 넓히기 전에 빠진 파일의 위치부터 확인합니다.

## 문자열을 조립하면 빠지는 이유

`bg-${color}-600`은 완성된 클래스가 파일에 없으므로 필요한 CSS를 안정적으로 만들 수 없습니다. 상태별로 `bg-blue-600`·`bg-red-600`이라는 완성된 문자열을 매핑합니다. 조합 함수나 React 조건식 자체가 문제인 것은 아닙니다.

```js
const tones = {
  info: 'bg-blue-600 text-white',
  danger: 'bg-red-600 text-white',
}
// 선택한 값을 className에 사용한다.
```

## source 경로

v4는 소스를 자동 감지하지만 `.gitignore` 대상이나 `node_modules` 등은 기본 감지에서 빠질 수 있습니다. 외부 UI 패키지처럼 필요한 대상은 `@source`로 등록합니다. 모노레포에서는 빌드 작업 디렉터리와 기준 경로도 확인합니다.

```css
@import "tailwindcss";
@source "../node_modules/@acme/ui";
@source inline("bg-blue-600 text-white");
```

## 필요한 클래스만 생성

`@source inline()`은 소스에 없지만 확실히 필요한 클래스 후보를 명시합니다. 가능한 값 전체를 대량 생성하기보다 유한한 선택지는 완성 문자열, 연속적인 값은 CSS 변수로 나눕니다. 감지 대상에 파일을 추가하는 것과 그 파일의 CSS를 import하는 것은 다른 일입니다.
